## 總結：最值得抄的五樣
1. **Plan 9 proc(3) 的 ctl/status/note/wait 分工**：一檔一語意；ctl 是「動詞＋參數」純文字；同步動詞（waitstop，寫入會卡到達成）與非同步動詞（stop）分開；`wait` 用「讀會 block、檔案長度非 0 表示有東西」。跟你們的設計幾乎同構。
2. **Maildir 的「先寫 tmp、再原子 link/rename 進 new」＋ 唯一檔名＋ 讀者忽略 dot 檔、清過期 tmp**：信箱不需要鎖。
3. **cgroup v2 的檔案格式慣例**：一檔一值／flat keyed／nested keyed、寫入與讀出同格式、`cgroup.events` 只在值改變時產生 modified event（poll/inotify 可等）；mkdir 建物件、rmdir 刪物件。
4. **varlink 的線上格式**：一則 JSON＋NUL 結尾、回覆依序、錯誤是「完整名稱字串＋parameters」、內建 `org.varlink.service` 自述（GetInfo / GetInterfaceDescription）、`more`/`continues`/`oneway` 旗標。若堅持一行一則 JSON（JSON Lines），可借它的錯誤命名與自述介面。
5. **FUSE 防卡死三件套**：supervisor 定期讀 `/sys/fs/fuse/connections/<n>/waiting`，持續 >0 就寫 `abort`；啟動時掃 `/proc/self/mountinfo` 清殘留 fuse 掛載（`fusermount3 -uz`）；動態檔用 `direct_io`。**本機核心 6.6.114 沒有 FUSE request timeout（6.15 才有）**，所以只能自己做 watchdog。
- 附記：sd_notify 的「KEY=VALUE 換行分隔、未知鍵忽略、私有鍵加前綴」與 s6 的「寫一個換行＝ready」也值得抄，見第 4 節。

## 1. IPC 分類法
**出處狀況**：Stevens 書沒有網路原文，本節大多**憑記憶**。

### 它怎麼規定的
- （憑記憶）UNPv2（1999 第二版）把 IPC 分四塊：
  - Message passing：pipe、FIFO、POSIX/System V message queue。
  - Synchronization：mutex、condition variable、read-write lock、record locking、semaphore。
  - Shared memory。
  - RPC：Doors、Sun RPC。
- （憑記憶）「IPC 物件活多久」三級：
  - process persistence：行程結束就沒了（pipe、FIFO 裡的資料、mutex、condvar）。
  - kernel persistence：直到 reboot 或明確移除（System V msg/sem/shm、POSIX mq/sem/shm）。
  - filesystem persistence：直到 unlink，reboot 後還在（FIFO 的「名字」）。
- （憑記憶）另一常見軸：byte stream（pipe、FIFO、TCP）vs 有訊息邊界（message queue、UDP、SOCK_SEQPACKET）。
- 讀自原文（非 Stevens，是課程筆記）：POSIX 物件通常歸 kernel persistence，POSIX mutex/condvar 歸 process 級；有些實作用檔案實作而變 filesystem 級——分類會隨實作變。
  https://w3.cs.jmu.edu/kirkpams/OpenCSF/Books/csf/html/POSIXvSysV.html

### 值得抄
- 描述每個通道時固定回答兩個問題：①物件生命期靠什麼維持（行程／核心／檔案系統）②是 byte stream 還是有邊界的訊息。你們的 ctl（一行）、status（一檔）、信箱（一封一檔）、socket（一行一則）可以各填一格，看有沒有重複。

### 坑
- Linux 的 POSIX mq 掛在 /dev/mqueue 看起來像檔案，實際是 kernel persistence——「看得到檔名」不等於 filesystem persistence。FUSE 檔案則是「行程 persistence 假裝成 filesystem」，這正是你們的特殊處（行程死了，檔案就該消失／回錯誤）。

### 出處

## 2. 訊息建在「寫檔」上

### 2.1 Maildir
**規格（讀自原文：Debian 的 maildir(5) man 頁，內容即 Bernstein 規格的 man 版；cr.yp.to 原頁抓取失敗）**
- 三個子目錄 `tmp`、`new`、`cur`，必須在同一個 filesystem。
- `new`：新投遞、讀者還沒看過；`cur`：看過的。
- 檔名 `time.pid.host`（time=1970 起秒數、pid=投遞行程、host=主機名）。
- 投遞步驟：chdir 進 maildir → stat `tmp/time.pid.host`，若已存在，等約 2 秒、更新 time 再試（次數有限）→ 在 tmp 建檔 → 寫入（檢查每次 write 回傳位元組數、fsync、close）→ 用 hard link 連到 `new/` 同名檔；link 成功那刻就算投遞完成。
- 投遞者開始建 tmp 檔前先起 24 小時計時，過期就放棄。tmp 內 36 小時沒動的檔讀者可清掉。
- 讀者：讀 `new`，可顯示、刪除、或搬到 `cur` 加 info 後綴；`.` 開頭的檔名一律跳過；不要解析檔名。
- 為何不用鎖：不同投遞者永不寫同一檔；信一旦出現在 new 就是完整的、之後不改；讀者可在投遞進行中安全刪改已投遞的信。

**Dovecot 擴充（讀自原文）**：檔名 `<base>:2,<flags>`（S=seen、T=trashed、a–z keywords）；加 `,S=<size>`、`,W=<vsize>` 省 stat；控制檔 `dovecot-uidlist`、`dovecot-keywords`。

**值得抄**
- 「寫完才可見」：tmp 寫、rename/link 進 new。寫信者不需鎖，收信者永遠看不到半封。
- 檔名保證唯一（時間＋pid＋主機＋計數／隨機），碰撞就重試而不是覆蓋。
- 用目錄表達狀態（new/cur），收件者處理完搬走。
- 讀者忽略 dot 檔、定期清過期 tmp（寫到一半就死掉的寄件者會留下垃圾）。

**坑**
- NFS 下每台投遞機器 hostname 必須唯一（讀自搜尋摘要）。
- 投遞後信不可改；要改就寫新信刪舊信。
- link() 從 tmp 到 new 無法可靠偵測重複（信可能已被搬到 cur），Dovecot 結論是「永遠產生保證唯一的檔名」。
- 改 flag 用 rename：並行讀者會看到信暫時消失，也可能得到新 UID。
- procmail 用 MH 風格投到 `Maildir/new` 會產生 `msg.inode` 名，inode 重用讓舊信看起來又回來。
- 憑記憶：原規格 `time.pid.host` 在高頻下會撞名，後來實作加 microsecond／隨機數／計數器；沒讀到具體格式。

**出處**

- https://cr.yp.to/proto/maildir.html（抓取失敗，只在搜尋結果）

### 2.2 Plan 9 plumber
**plumb(6) 訊息格式（讀自原文）**：純文字，欄位以換行分隔、順序固定、缺的欄位是空行；只有 data 可含換行。
1. `src`（產生者）　2. `dst`（目的 port）　3. `wdir`（工作目錄）　4. `type`（目前只有 `text`）　5. `attr`（`name=value` 空白分隔；含空白／引號／`=` 的值要 quote，值不可含換行）　6. `ndata`（data 的位元組數，必須準確，可為 0）　7. `data`。

**plumber(4)（讀自原文）**：掛在 `/mnt/plumb`：
- `send`：程式寫入訊息。
- `rules`：讀出目前規則；append 是新增；用 OTRUNC 開啟會清空（所以可用編輯器動態改）。
- `ports/`：每個 `plumb to` 目的一個 port；慣例 sam 讀 `/mnt/plumb/edit`。port 不會被動態刪。
- 投遞：訊息複製給每個開著該 port 的 client。
- **寫入失敗**：沒 client 開著 port 時：規則有 `plumb client` → 執行指令並保留訊息、等 port 被開；有 `plumb start` → 執行指令、訊息丟棄；都沒有 → 訊息丟棄，**寫入者收到 write error**。沒有任何 rule set 命中也是丟棄＋write error（例外：`dst` 指向既有 port 時原樣送出）。
- 規則檔 `$HOME/lib/plumbing`：rule set 以空行分隔、`#` 註解、`include`；依序檢查，第一個全部 pattern 都符合的觸發。pattern 動詞 `add delete is isdir isfile matches set`；action 動詞 `to client start`；變數 `$0..$n $attr $data $dir $dst $file $type $src $wdir`。
- plumb(1)：`plumb [-p plumbfile] [-a attrs] [-s src] [-d dst] [-t type] [-w dir] -i | data...`，預設 src=plumb、type=text、plumbfile=/mnt/plumb/send。
- plumb(2) 函式庫：`plumbopen plumbsend plumbrecv plumbpack plumbunpack plumbunpackpartial`…；`plumbunpackpartial` 專門處理分段到達（資料不夠回 nil 並在 `*morep` 給還缺幾位元組）。

**值得抄**：固定欄位順序的純文字訊息＋ `ndata` 讓 data 可含換行；「寄件者不知道收件者，由規則決定」；「沒人處理就讓 write 失敗」（你們的 ctl 鎖住時別人寫會當場失敗是同一思路）；rules 檔可讀可 append。
**坑**：type 只有 text；port 不能刪；attr 值不可含換行；`ndata` 不準整則壞；man 頁沒寫規則語法錯誤等細節的錯誤字串；BUGS 欄寫固定 namespace 難處理新掛載。
**出處**
- https://9p.io/magic/man2html/6/plumb
- https://9p.io/magic/man2html/4/plumber
- https://9p.io/magic/man2html/1/plumb
- https://9p.io/magic/man2html/2/plumb

### 2.3 其他「檔案當介面」例子
**acme（讀自原文）** https://9p.io/magic/man2html/4/acme
- 頂層：`cons consctl label index new/ errors` 與以數字 ID 命名的 window 目錄。`index` 每 window 一行：五個 11 字元十進位數（id、tag 長、body 長、是否目錄、是否已改）＋ tag 文字。存取 `new/` 內任何檔就建立新 window。
- window 目錄：`addr body data xdata tag ctl event`。body/tag 寫入一律 append（忽略 offset）；`data` 依 addr 隨機存取。
- `ctl` 寫入字（每行一個，可一次多行）：`addr=dot dot=addr limit=addr clean dirty cleartag del delete get put mark nomark menu nomenu scroll noscroll show name <name> dump <cmd> dumpdir <dir>`；讀 ctl 得五個 index 欄位＋寬度、字型、tab 寬。
- `event` 格式 `origin type n1 n2 flag count [text]`；開著 event 就由程式接管事件；**把事件原樣寫回 event 就等於「我不處理，照原動作做」**（放行機制）；文字 ≥256 字元不附，要去 data 讀。
- 值得抄：event 的「接管／放回放行」；固定寬度數字欄位；`new/` 存取即建立。坑：body 寫入忽略 offset 與一般檔語意不同；開著 event 又不處理，使用者操作會沒反應。

**rio（讀自原文）** https://9p.io/magic/man2html/4/rio
- `/dev/wsys/<id>/`：`cons consctl cursor label mouse screen snarf text wctl wdir winid window`。
- `wctl`：**讀會 block 到狀態改變才回**（座標＋hidden/visible＋current/notcurrent）；寫入命令 `resize move new scroll noscroll set top bottom hide unhide current delete`，選項值要用空白隔開（`-dx 100`）。例：`echo new -dx 800 -dy 200 -cd /sys/src/cmd sam > /dev/wctl`。
- `consctl` 寫 `rawon rawoff holdon holdoff`，**關閉時自動重置**——值得抄（持有者消失就還原）。

**ii（讀自原文，內容很少）** https://tools.suckless.org/ii/
- 每個 server 一個目錄，內 `in`（FIFO）＋ `out`（一般檔）；每個 channel/nick 也各有目錄＋`in`/`out`，加入時自動建立。只確認 `/j` 一個命令（`echo "/j #chan" > in`）。其餘命令、out 時間戳格式沒讀到，**未驗證**。
- 抄：「FIFO 當輸入、普通檔當輸出（可 tail -f）」用 shell 就能驅動。

**wmii（讀自原文）** https://manpages.debian.org/jessie/wmii/wmii.1.en.html
- `/ctl /event /keys /rules /colrules`、`/client/*/{ctl,label,props,tags}`、`/tag/*/{ctl,index}`、`/lbar /rbar`。
- 根 ctl 字：`quit exec <prog> spawn <prog>`；client ctl：`allow activate floating fullscreen group kill pid slay tags urgent`；tag ctl：`select send swap grow nudge`。
- `/event` 永不 EOF，持續吐事件（`ClientClick`、`Key <string>`、`[Not]Urgent` …）。`rules` 標 PROVISIONAL。

## 3. 控制檔

### 3.1 Plan 9 proc(3)（讀自原文）https://9p.io/magic/man2html/3/proc
- `/proc/n/` 檔：`args ctl fd fpregs kregs mem note noteid notepg ns proc profile regs segment status text wait`（清單末有 "..."，不一定完整）。
- `ctl` 字：`stop start waitstop startstop hang nohang`、`close n`、`closefiles`、`noswap`、`kill`、`private`、`pri n`、`wired n`、`trace`、real-time 排程類（`period deadline cost sporadic yieldonblock admit`）、`event`。
- `status`：12 欄、每欄後一個空格：名稱(27 字元)、使用者(27)、狀態(11)、六個 11 字元數字（時間）、記憶體(KB)、base priority、目前 priority。
- `note`：寫入字串＝送 note（長度 < ERRLEN-1）；讀取（buffer ≥ ERRLEN）取出最舊的待處理 note 並阻止其送達。`notepg` 只寫、送整個 group。
- `wait`：讀它得到已結束 child 的記錄；沒有 child 時**讀會 block**；檔案長度非 0 表示有記錄可讀；讀者與該行程自己的 await 互斥。
- **寫 ctl 何時返回**：`stop`/`waitstop` 這類會 block 寫入者直到目標進入 Stopped 或已結束；有些訊息要求特定狀態否則回 error；`admit` 檢查失敗則寫入失敗，error 字串就是原因。其他字的 blocking 行為頁面沒寫。
- 值得抄：一檔一語意；同步／非同步動詞分開；寫入失敗用 error 字串說原因；wait 的「可讀性＝長度」。
- 坑：status 固定寬度會截斷長名（27 字元上限）；wait 同時只能一個讀者；wait 記錄欄位格式頁面沒給；各 ctl 字的錯誤字串沒列。
- 與你們的差異：`/proc` 是核心統一提供，不是各行程自己 serve；status 是單行定長，不是 `name: value`。

### 3.2 Plan 9 ip(3)（讀自原文）https://9p.io/magic/man2html/3/ip
- `/net/tcp/clone`、`stats`、數字連線目錄。**開 clone 即保留一條新連線，拿到的 fd 指向該連線的 ctl，讀它得連線編號**。
- 連線目錄檔：`ctl data status listen local remote err`。
- ctl 字：`connect ip!port[!r] [local]`、`announce X`（X 為 port 或 `*`；已 announce/connect 時失敗）、`bind X`（僅為 APE 相容）、`hangup`、`keepalive n`（毫秒，預設 30000）、`checksum n`、`ttl tos ignoreadvice addmulti remmulti`。
- `listen`：先 announce，再 open `listen`——open 會 block 到有人連入，回的 fd 指向**新連線的 ctl**。
- `data`：無邊界 byte stream。`err`：出錯或 EOF 後讀，內容是原因。
- 值得抄：「open clone＝建物件，fd 即 ctl，fd 關閉物件釋放」；「open listen＝accept」；失敗經 write error 回；`err` 檔留最後失敗原因。
- 坑：bind 與 announce 語意重疊；連線編號要讀 ctl 才得，要處理 clone fd 關閉後目錄消失的競爭；具體 error 字串沒有規格清單（頁面沒列）。

### 3.3 Linux cgroup v2 與 configfs（讀自原文；cgroup 頁只讀前 100000 字元，後 43188 字元沒讀）
https://docs.kernel.org/admin-guide/cgroup-v2.html　https://docs.kernel.org/filesystems/configfs.html
- Conventions：一個功能一個檔；預設時間單位 microseconds，別的單位必須帶後綴；root cgroup 不放資源控制檔；event 檔列 key-value，**發生可通知事件時要產生 file modified event**。
- 格式：①New-line separated values（一次只能寫一個值）②Space separated values ③Flat keyed `KEY0 VAL0\nKEY1 VAL1\n` ④Nested keyed `KEY0 SUB_KEY0=VAL00 SUB_KEY1=VAL01`。寫入通常與讀出同格式；keyed 檔一次只能寫一個 key。（我讀到的段落沒有獨立的「Single value」格式。）
- 壞寫入的 errno：**沒有通用規則**，只見個案：拓樸無效 `EOPNOTSUPP`、遷移被拒 `-EACCES`、namespace 內不可達 `-ENOENT`。`cgroup.subtree_control` 多項操作原子（全成功或全失敗）。
- `cgroup.events`：唯讀 flat-keyed，只在非 root 存在；`populated` 為 0/1；值改變時產生 file modified event，**poll 與 inotify 都會被觸發**。
- mkdir 建子 cgroup；rmdir 需無子 cgroup 且無活行程（只剩 zombie 算空）。
- configfs：mkdir 時由 `make_item()` 配置物件、屬性檔隨之出現；rmdir 呼叫 `drop_item()`（void，不能失敗）；有子項、被 symlink 引用的不能刪；`configfs_depend_item()` 保護的回 `-EBUSY`；一般屬性是小 ASCII 檔、最大一個 PAGE_SIZE、建議一檔一值；**寫入要一次整包寫**（讀整個、改、整個寫回）；binary 屬性錯誤到 `close(2)` 才浮現，必須檢查 close 回傳值。
- 值得抄：mkdir/rmdir 建刪物件；四種格式分類＋「讀寫同格式」；`cgroup.events` 的「只在值變時通知」；單位固定。
- 坑：cgroup 沒統一 errno，你們要自己訂一張表（建議：格式錯 EINVAL、忙 EBUSY、不認得的字 EINVAL、權限 EACCES）；configfs binary 屬性易漏檢 close；寫入分段會壞。

## 4. 串流（unix socket）上的訊息協定

### 4.1 varlink（讀自原文）https://varlink.org/　/Service　/Method-Call
- 所有訊息是 JSON object，**以單一 NUL (0x00) 結尾**。回覆順序等於請求順序，不 multiplex；client 可 pipeline。
- 請求 `{"method":"<完整名>","parameters":{...}}`；回覆 `{"parameters":{...}}`；錯誤 `{"error":"<完整名>","parameters":{...}}`。
- 旗標：`more`（可能多個回覆）、`continues`（回覆旗標，表示後面還有；沒帶的最後一則結束呼叫）、`oneway`（不回覆，伺服器必須遵守）、`upgrade`（確認回覆後轉為自訂協定）。client 不想收了可直接關連線。
- 自述介面 `org.varlink.service`：`GetInfo() -> (vendor, product, version, url, interfaces)`、`GetInterfaceDescription(interface)`；標準錯誤 `InterfaceNotFound MethodNotFound MethodNotImplemented InvalidParameter PermissionDenied ExpectedMore`。
- 抄：錯誤用名稱字串不用數字；內建 introspection；旗標在同一訊息格式內；回覆嚴格依序。坑：`more` 期間連線被占用；`upgrade` 後離開 varlink 管轄；NUL 分隔要求 payload 不含裸 NUL（JSON 字串內本會 escape）。

### 4.2 JSON-RPC 2.0（讀自原文）https://www.jsonrpc.org/specification
- Request：`jsonrpc:"2.0"`、`method`、`params`、`id`（String/Number/NULL）。沒有 id ＝ notification，伺服器不得回。Response 的 `result` 與 `error` 互斥、id 對應。error：`code`、`message`、`data`。
- 錯誤碼：-32700 Parse error、-32600 Invalid Request、-32601 Method not found、-32602 Invalid params、-32603 Internal error、-32000～-32099 實作定義。
- **規格本身不規定分框。** 坑：id 允許 NULL 是公認瑕疵。

### 4.3 LSP base protocol（讀自原文，前 100000 字元）
https://microsoft.github.io/language-server-protocol/specifications/lsp/3.17/specification/#baseProtocol
- header `Name: Value\r\n`，header 與內容間再一個 `\r\n`；`Content-Length`（必填，內容**位元組**數）、`Content-Type`（選填，預設 `application/vscode-jsonrpc; charset=utf-8`）。內容 UTF-8。
- `$/cancelRequest`：被取消的 request 仍必須回 response（建議 error `RequestCancelled` -32800）。
- 抄：payload 可含任何位元組（含換行）。坑：Content-Length 是位元組不是字元；長度錯了串流失步（憑記憶：沒有 resync 機制）。

### 4.4 JSON Lines / NDJSON（讀自原文）https://jsonlines.org/　https://github.com/ndjson/ndjson-spec
- JSON Lines：UTF-8 無 BOM；每行一個合法 JSON 值；不允許空行；`\n`（`\r\n` 也行）；`.jsonl`。
- NDJSON：每個 JSON text 後接 `\n`（前可有 `\r`）；解析失敗 SHOULD 報錯；空行可忽略但行為 MUST 被文件記載；MIME `application/x-ndjson`。
- 坑：兩者對空行處理不同；內容換行必須 escape；都沒有 schema、版本、request/response 對應——這些得自己補（建議加 `id`、`ok`、`error` 欄位，仿 JSON-RPC）。

### 4.5 D-Bus（讀自原文，約最後 7000 字元未讀）https://dbus.freedesktop.org/doc/dbus-specification.html
- 每連線一個 unique name，另可有 well-known name（至少含一個 `.`）。`RequestName` flags：`ALLOW_REPLACEMENT 0x1`、`REPLACE_EXISTING 0x2`、`DO_NOT_QUEUE 0x4`；回覆 1 primary owner、2 in queue、3 exists、4 already owner。`ReleaseName` 回 1/2/3。
- `NameOwnerChanged` 廣播（name, old owner, new owner，空字串＝無）；`NameHasOwner`。
- 按需啟動：method call 預設 auto-start，帶 `NO_AUTO_START` 可關；`StartServiceByName` 回 1（已啟動）/2（本來就在）；頁面指出有 TOCTOU 問題。`.service` 檔 `[D-BUS Service]`：`Name`、`Exec` 必填。
- 身分：`GetConnectionCredentials` 回 dict（`UnixUserID UnixGroupIDs ProcessID ProcessFD`…，不可判定的欄位省略）；認證用 SASL `EXTERNAL`（Unix 上＝數字 UID，開頭 nul byte 可帶憑證）。
- 沒驗證：spec 頁對 `SO_PEERCRED`/`SCM_CREDENTIALS` 怎麼寫（摘要沒出現）。（憑記憶：Linux 實作確實用 SO_PEERCRED。）
- 抄：名稱註冊的 queue/replace/do-not-queue 與回覆碼；owner 變動用廣播；啟動中訊息先 hold。坑：TOCTOU；憑證查詢可能缺欄位。

### 4.6 systemd sd_notify / socket activation（讀自原文）
https://www.freedesktop.org/software/systemd/man/latest/sd_notify.html　…/sd_listen_fds.html
- 傳輸：對 `$NOTIFY_SOCKET` 送一個 datagram，內容是換行分隔的 `KEY=VALUE`。
- 鍵：`READY=1`、`RELOADING=1`（完成後再送 `READY=1`，配 `MONOTONIC_USEC=`）、`STOPPING=1`、`STATUS=`（單行 UTF-8）、`ERRNO=`、`BUSERROR=`、`MAINPID=`、`WATCHDOG=1`（`WATCHDOG=trigger` 回報內部錯誤、`WATCHDOG_USEC=`）、`EXTEND_TIMEOUT_USEC=`、`FDSTORE=1`（`FDNAME=`）、`BARRIER=1`（單獨送並帶一 fd，關閉該 fd＝確認先前訊息已處理）。**未知鍵忽略，私有擴充用 `X_` 前綴。**
- 回傳：負 errno 失敗、0＝`$NOTIFY_SOCKET` 未設、正值＝已送出（只代表進 queue）。
- socket activation：`LISTEN_PID`（必須等於自己的 PID，否則忽略——防止 env 被 child 誤用）、`LISTEN_FDS`、`LISTEN_FDNAMES`（冒號分隔）；fd 從 3 起；對每個 fd 設 CLOEXEC；`unset_environment` 清 env。
- 抄：KEY=VALUE 格式與前向相容規則；`LISTEN_PID` 檢查；BARRIER 同步。坑：datagram 送出≠對方處理完。

### 4.7 s6（讀自原文）https://skarnet.org/software/s6/ （notifywhenup、s6-svc、fifodir、s6-ftrig-wait 各頁）
- 就緒通知：service 目錄放 `notification-fd` 檔（內容為 fd 號）；daemon 就緒後對該 fd **寫一個換行再關閉**（換行前的資料忽略）；s6-supervise 更新 `supervise/status` 並對訂閱者送 `U` 事件。不支援的 daemon 可用 `s6-notifyoncheck` 反覆跑檢查腳本代為通知。
- `s6-svc` 控制字：`-u` 起且死後重啟、`-d` 停（SIGTERM，可由 `./down-signal` 改，再 SIGCONT）、`-o` ＝ `-uO`、`-O` 只一次、`-r` 重啟、`-x` 令 supervisor 自己離開；訊號 `-t -a -h -q -i -k -p -c`；`-w` 加狀態後綴（d D u U r R）會 block 到達成，`-T` 毫秒逾時（逾時 exit 1，預設 0＝無限）。命令寫進 `<svcdir>/supervise/control`（FIFO）。
- fifodir：只是會合目錄；訂閱者原子地在目錄內建 named pipe 並讀它，取消訂閱就 unlink；通知者對目錄內每個 pipe 寫一個位元組。`s6-ftrig-listen1/listen` 先訂閱、再觸發某程式、再等事件，避免「通知先到、訂閱者還沒到」。公開 fifodir 權限 1733；限制型 3730。`s6-ftrig-wait`：pattern 是 ERE，比對收到的事件序列。
- 抄：「寫一個換行＝ready」；單 FIFO＋單字元命令；`-w`/`-T`「等到狀態才返回、有逾時」；先訂閱再觸發避開競爭。
- 坑：就緒只有一位元組資訊、沒有失敗通道；`-w` 不加 `-T` 可能永遠卡；fifodir 通知晚到的訂閱者收不到（無重播）；權限設錯會看不見或被刪。
- 沒讀到：libftrig 頁（404）、`-X` 意義、`s6-notifywhenup` 頁。

## 5. FUSE 實務（Linux）
本機：WSL2，核心 6.6.114。

### 5.1 伺服器卡住
- 讀自原文（https://docs.kernel.org/filesystems/fuse/fuse.html）：每個 connection 在 `/sys/fs/fuse/connections/<n>/` 有 `waiting`（等待送給 userspace 或處理中的 request 數）與 `abort`（寫任何內容即中止：所有等待中與之後的 request 都回 error）。沒有 FS 活動但 `waiting` 非 0＝卡住或死鎖。只有 mount owner 能存取。需 `mount -t fusectl none /sys/fs/fuse/connections`。文件列四種救法：殺 daemon、殺 daemon 加所有使用者、`umount -f`（lazy unmount 過就無效）、**abort（最強、一定有效）**。
- 讀的人會怎樣：read 卡在 D state，直到 daemon 回應或 abort（我的推論，文件沒直接寫）。
- **Request timeout**（讀自原文：kernel sysctl 文件、req_timeout.c）：`/proc/sys/fs/fuse/default_request_timeout`（server 沒指定時用，0＝不設）與 `max_request_timeout`（>0 時是上限；0＝無上限）；最大 65535 秒；default 大於 max 以 max 為準。實作：每 15 秒檢查一次每條 queue 最舊的 request，超時就 abort connection；非 0 值至少被拉高到 15 秒，所以實際可能多等一個週期。
- 版本：搜尋結果顯示 merge 在 `fuse-update-6.15`（mirror 的 merge commit，非正式 release notes）→ **Linux 6.15**。**本機 6.6.114 沒有。**開法：root 設 sysctl（`fs.fuse.default_request_timeout=30`，路徑讀自原文，`fs.fuse.xxx` 的寫法是推導）。沒查到 per-mount 設定介面。
- 抄：supervisor 定期讀 `waiting`，連續 N 秒 >0 就寫 `abort`；找 `<n>` 用 `/proc/self/mountinfo` 的 device 號 `0:NN`（憑記憶）；6.15+ 另設 `max_request_timeout` 當保險；各服務 handler 自設 deadline。
- 坑：abort 後掛載仍在，存取回 `ENOTCONN`，還要 `fusermount -u`；timeout 是全系統 sysctl 需 root。
- 出處：https://docs.kernel.org/filesystems/fuse/fuse.html　https://docs.kernel.org/admin-guide/sysctl/fs.html　https://android.googlesource.com/kernel/common/+/refs/heads/upstream-master/fs/fuse/req_timeout.c　https://tangled.org/tjh.dev/kernel/commit/9b17cb59a7db983a967c3658fe9a2f250f588bbd

### 5.2 auto_unmount 與殘留掛載
- 讀自原文（https://github.com/libfuse/libfuse/blob/master/doc/mount.fuse3.8）：`auto_unmount` 是 libfuse 專屬，FS 因任何原因結束都自動釋放 mountpoint；man 警告「危險」——crash 後 mountpoint 看起來是空目錄（會看到底下的空目錄）。
- 機制（讀自搜尋摘要／doxygen，未讀 fusermount.c）：libfuse 開 `fusermount3 --auto-unmount`，parent 關閉 fd 後該 helper 負責 unmount；helper 在獨立 mount namespace。
- 不作用的情況：libfuse issue #889（仍 open）——daemon 被 `kill -9` 時主 mount 會被清，但它的 **bind mount 清不掉**，留下 "Transport endpoint is not connected"；maintainer 說 device number 會重用，race 無法根除。https://github.com/libfuse/libfuse/issues/889
- **WSL2：沒找到任何原文證據說 auto_unmount 在 WSL2 失效，也沒找到說有效。** 必須在本機實測（kill -9 後看 mount 是否消失）。
- 清理：`fusermount3 -u <dir>`；`-z` lazy（MNT_DETACH），一般 unmount 回 "Device or resource busy" 時用（讀自 man 與 rclone issue 搜尋摘要）。
- 抄：supervisor 啟動時掃 `/proc/self/mountinfo` 中 fstype 為 `fuse*` 的項目，對應服務不在了就 `fusermount3 -uz`；即使用 auto_unmount 也要掃。
- 坑：對殘留掛載 `stat`/`ls` 會 ENOTCONN——清理程式別 stat 該路徑，改讀 mountinfo；非 owner 不能 fusermount -u；lazy 會留下被行程持有 cwd 的殘影。
- 出處另有：https://raw.githubusercontent.com/libfuse/libfuse/master/doc/fusermount3.1　https://github.com/rclone/rclone/issues/7766（僅摘要）

### 5.3 direct_io、size 0、poll、default_permissions、allow_other
- direct_io／size 0：（搜尋摘要）VFS 依 getattr 的 size 限制 read，size 為 0 讀不到；動態內容在 open 回 `FOPEN_DIRECT_IO`；direct-io 繞過 page cache（kernel fuse-io 文件）。Linux 上 `st_size=0`＋direct_io 時 cat 是否仍讀到 EOF，**資料來源不一致，且可能隨核心版本而變——必須在 6.6 實測**。保險：getattr 回「目前實際內容長度」。
- poll：libfuse low-level 有 `poll` op，收到 `fuse_pollhandle`；資料變化時呼叫 `fuse_lowlevel_notify_poll(ph)`（high-level 為 `fuse_notify_poll`）；`example/poll.c` 每檔保存一個 pollhandle，新 handle 到來時 destroy 舊的。`README.notifications`：非同步 notification **不可在處理其他 FUSE request 時執行，否則可能死鎖**（搜尋摘要）。
- `default_permissions`：讓核心依 inode 的 mode/uid/gid 檢查（讀自原文）。
- `allow_other`：解除「只有 mount owner 可存取」（含 root）；非 root 要用須在 `/etc/fuse.conf` 開 `user_allow_other`（讀自原文，man）。2018 起核心把 allow_other 的 FUSE 存取限制在掛載者的 user namespace 及子孫（lore 搜尋摘要）：在 unprivileged user namespace 內掛的，外面行程即使 allow_other 也進不去。
- 抄：status/ctl 回應用 direct_io＋getattr 回真長度；要讓讀者「等狀態變化」就實作 poll＋notify_poll（在獨立執行緒、非 request 處理中通知）；單一使用者不要開 allow_other。
- 坑：跨帳號（root supervisor 讀使用者的 mount）要 `user_allow_other` 或 root 掛；容器／userns 內掛的外面看不到。
- 出處：https://docs.kernel.org/6.9/filesystems/fuse-io.html　https://bugs.freebsd.org/bugzilla/show_bug.cgi?id=192701　https://sources.debian.org/src/fuse3/3.18.1-1/doc/README.notifications　https://sources.debian.org/data/main/f/fuse3/3.18.2-1/doc/html/example_2poll_8c_source.html　https://man7.org/linux/man-pages/man8/mount.fuse3.8.html　https://lore.kernel.org/all/20180308212430.7053-4-ebiederm@xmission.com/（均有部分僅搜尋摘要）

## 6. 整體最像的前例
你們的設計（下稱 X）：每個行程自己 serve FUSE 目錄（ctl＋status＋信箱）＋活著時走 unix socket＋ daemon 管 spawn/stop/reap。

- **Plan 9 /proc（讀自原文，見 3.1）**：每個 pid 一個目錄，`ctl`（文字命令）、`status`、`note`、`wait`，內容由核心即時產生、不在硬碟。**概念上與 X 最同構。**差異：核心統一提供而非各行程自己 serve；沒有信箱（訊息走 note）；status 是定長單行；沒有 spawn/reap daemon（核心就是 supervisor）。
- **Plan 9 /srv（憑記憶；man 頁抓取失敗）**：server 把已開啟的 9P channel 以名字 post 到 `/srv/<name>`，client 開檔後 mount。只負責「名字→連線」的註冊與發現，控制介面由各 server 自訂；server 退出後 post 的檔去留我不確定。差異：X 把 ctl/status/mailbox 的約定固定下來。
- **plan9port 9pserve／9pfuse（讀自原文）**：9pserve 在 Unix 上扮演核心角色，把多個 client 多工到單一 9P 對話；client 斷線時 flush pending 並 clunk fid，server 不必處理 client 突然消失。namespace 預設 `/tmp/ns.$USER.$DISPLAY`（搜尋摘要）。差異：只做多工與掛載；沒提 server 卡住怎麼辦。啟示：多個 reader 同開 `ctl` 的清理，X 要自己做。 https://9fans.github.io/plan9port/man/man4/9pserve.html
- **v9fs（讀自原文）**：Linux 核心內建 9P client，`trans=unix`（unix socket／named pipe）、`fd`、`tcp`；選項 `uname aname access cache(預設 none) version msize`。文件沒寫 server hang／timeout。啟示：若每個服務講 9P，可不經 FUSE、不需 fusermount——但**本機核心有沒有 9p 模組沒驗證**。 https://docs.kernel.org/filesystems/9p.html
- **Inferno（憑記憶，沒查原文）**：Styx/9P，`/prog/<pid>/{ctl,status}` 類似 Plan 9 /proc；只作待查方向。
- **AGFS／agent9**：見 5.4。AGFS 最像「agent 目錄＋ctl＋逾時移除」，但是單一 server 內以 plugin 提供多目錄，不是每個行程各自 serve，也沒有 supervisor spawn/reap。
- **沒找到**：以「supervisor＋每服務一個目錄＋ctl/status/mailbox」為明確設計文件的現成專案。Erlang/OTP supervisor、systemd D-Bus 介面等沒查，不列。

**整體結論**：ctl/status 的語意直接抄 Plan 9 proc(3)；信箱抄 Maildir；等狀態變化抄 cgroup.events＋FUSE poll；活行程間 socket 分框抄 varlink／JSON Lines 並補 id／error；supervisor 的 ready／等待／逾時抄 s6（`-w`/`-T`）與 sd_notify；FUSE 防卡死靠自建 waiting/abort watchdog 與 mountinfo 清掃。

### 請查的東西
每一項請找**原始文件或官方說明**（man 頁、規格、原作者的論文／網頁），整理「它具體怎麼規定的」——檔名、格式、字、錯誤怎麼回、踩過什麼坑——不要只給一句介紹。

1. **IPC 的分類法**：W. Richard Stevens《UNIX Network Programming, Vol. 2: Interprocess Communications》怎麼分類（訊息傳遞／同步／共享記憶體／RPC），以及它「IPC 物件活多久」那張表（process／kernel／filesystem persistence）。有沒有別的常被引用的分類（例：位元組流 vs 有邊界的訊息）。
2. **訊息建在「寫檔」上**：
   - Maildir 的正式規格（tmp/new/cur、檔名怎麼取、為什麼不用鎖、已知的坑）。
   - Plan 9 的 plumber（plumb(4)/plumb(6)/plumber(4)）：擺出哪些檔（send、rules、各 port）、訊息格式逐欄、寫 send 失敗怎麼回。
   - 其他「把訊息／指令做成檔案介面」的現成例子：Plan 9 的 acme（/mnt/acme/<id>/ctl、event）、rio（/dev/wsys）、`ii`（IRC 用 FIFO 與檔）、wmii；各自的檔案配置與 ctl 字。
3. **控制檔**：
   - Plan 9 proc(3)：`/proc/n/` 底下每個檔、`ctl` 收哪些字、`status` 的欄位、`note`、`wait`；寫 ctl 什麼時候回來。
   - Plan 9 ip(3) 的 `/net/tcp/clone`→`ctl`／`data`／`status`／`listen` 這個樣式（開 clone 拿到新連線目錄）。
   - Linux cgroup v2 的檔案介面慣例（kernel 文件 cgroup-v2 的 “Interface Files / Conventions” 一節：flat keyed、nested keyed、一行一值、寫入失敗回什麼 errno、`cgroup.events` 怎麼用 poll／inotify 通知變化）；configfs 的 mkdir 建物件。
4. **串流（unix socket）上的訊息協定**：
   - varlink（線上格式、怎麼切一則、錯誤、介面自述）。
   - JSON-RPC 2.0、LSP 的分框方式；JSON Lines／NDJSON。
   - D-Bus：名字表、有人找就起（activation）、怎麼拿對方的身分（SO_PEERCRED）。
   - systemd 的 sd_notify（READY=1 等字）、socket activation；s6 的 readiness notification、`s6-svc` 的控制字、fifodir（s6-ftrig）。
5. **FUSE 的實務**（Linux）：
   - 伺服器卡住時讀的人會怎樣、怎麼救：`/sys/fs/fuse/connections/<n>/abort`、`waiting`；較新的核心有沒有 FUSE 請求逾時（request timeout）的設定，哪一版加的、怎麼開。
   - `auto_unmount` 的行為與已知不作用的情況（尤其 WSL2）；伺服器被 kill -9 後 “Transport endpoint is not connected” 的殘留掛載一般怎麼清。
   - `direct_io` 與 size 報 0 的動態檔、FUSE 的 `poll` 支援（讓讀的人等狀態變化）、`default_permissions`、`allow_other` 與 user namespace／不同帳號的限制。
   - 有沒有現成專案是「每個行程／服務擺出自己的 FUSE 目錄當控制介面」的（例：lxcfs 不算；找更像的），它們怎麼處理上面這些。
6. **整體最像的前例**：有沒有系統就是「監督者＋每個服務一個目錄＋檔案當控制面」而且服務是活著當場回答的（不是落在硬碟的檔）？Plan 9 的 `/srv`、Inferno、9P 生態（plan9port 的 9pserve、v9fs）、近年的 agent／actor 框架都可以看。各一段：它怎麼做、跟我們要的差在哪。
