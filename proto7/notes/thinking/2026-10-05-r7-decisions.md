## 先決：loop7 與落地順序

- **要不要先開 loop7 修第一節 1～5 組（adapt 回歸 → subd 誤收 → kill／回收時序 → budget unknown → 其餘），再回到事件保存？** 預設：是，loop7 期間你看事件保存的題。
- **loop7 的測試（6）與文件（7）併進去還是下一輪？** 預設：視分線容量，不夠就下一輪。

## Q1　事件保存要保證什麼（[event-store §11](../../../proto7-2/notes/reviews/2026-10-05/event-store.md#11-需要使用者決定的題)）

- 第一版保到什麼程度：只存看見的、合作來源逐件、還是全部核心內部轉換？預設：合作來源逐件業務事件＋明示為取樣的核心觀測。
- 主要給人／LLM 回看，還是有任務必須逐件處理？預設：兩種用途分開宣告，必讀的在責任完成前不清。
- 先單 node 存，還是直接集中？預設：先單 node 驗契約。
- 空間滿了，工作要不要等？預設：必讀通道停收新責任，一般觀測繼續但明報缺口。
- 保存成功後抵抗哪種中斷？預設：第一版只承諾程序 SIGKILL 可接續，不承諾斷電。
- （llm-author 第 11 題同款）LLM 包的保存要承諾到什麼故障等級？預設：程序中斷；未結算／未確認消費的資料不清。

## Q2　「不知道」要不要跨包統一

- budget 的退出碼 3 要接上 step 的有限重送（改程式），還是只在文件寫明兩種 unknown 不同（改文件）？預設：報告沒給，是 loop7 第 4 組裡的語意選擇。
- （llm-author 第 9 題）候選有效、usage 未知，能不能交付？預設：可保存並顯示「候選有效、帳務待結」，預留額照留。
- （llm-author 第 8 題）遠端結果不明時，要成本確定還是自動前進？預設：保留預留額、不自動重送；要再生成就是另有記錄的明確政策。

## Q3　義務要不要落盤

- 啟動中的 run 被 kill 回成功、之後照樣跑起來（play7 A8-06）：kill 的意思是「當時沒程序」還是「終止整次 run」？預設：報告列為契約缺口，等你定；定了才知道歸 bug 還是歸文件。
- daemon 的回收義務（取消登記、node 替換）要不要持久化？預設：deep-play 建議持久化意圖；放核心還是放模組，報告沒說。

## Q4　LLM 當作者還是轉換器（[llm-author §十](../../../proto7-2/notes/reviews/2026-10-05/llm-author.md#十待決題與預設建議)）

- 先證明作者價值，還是跨 node 轉換價值？預設：先做 CSV 固定工具作者。
- 作者只能組合既有工具，還是可以寫任意程式？預設：第一刀只組合可信工具。
- 候選要不要自動發布？預設：先產生可審查候選；明確授權的固定試驗可自動。
- 要不要執行中替換舊工作？預設：第一版只新增獨立版本。
- adapt-llm 必須等於最新來源嗎？預設：非控制用途先試 `within_age`（可落後但標明），必須最新的用 `current_only`。
- 每個來源事件都處理，還是只要最新值？預設：明確分開；逐件需求接回 Q1。
- 第一個 token 計量單位與上界怎麼定？預設：一個端點、一種已確認計量；證明不了上界就標「軟預算」。
- adapt-llm 的語意驗收標準是什麼？預設：先列有限欄位、必要的否定／例外、獨立答案。
- 何時值得升級成完整 agent？預設：作者與單次呼叫的價值確認後再加多輪記憶與工具選擇。
- （packs-use 4.5）budget 示範資源的「次數」與 `--amount` 不一致：算次數還是加權成本？預設：報告沒給，二選一。

## Q5　kernel 任務包（[kernel-pack §10](../../../proto7-2/notes/reviews/2026-10-05/kernel-pack.md#10-待決題與預設建議)）

- 第一版先證明什麼？預設：決策骨架＋進度監督範例，只觀測與綁 run 的 kill。
- 規則用純函式還是外部程式？預設：純函式、JSON 型別邊界。
- 同一 run 恢復進度後，已提交的 kill 還要不要生效？預設：不自動撤回、釘原 run，狀態明示可能延後生效；不接受就第一版只觀測。
- 接續保證跨多大？預設：同部署、同 node、同槽；初始化與執行分開。
- 誰可以控制同一槽？預設：單一控制者，觀測權與控制權分開列。
- step／budget／adapt 要不要改成 kernel 插件？預設：保持獨立。
- aos7-pack 安裝器綁不綁第一版？預設：分開。
