# 第六輪思考綜合（落地）：骨架放進現有體系（10-04）

← [第四輪題目](2026-10-04-r4-topic.md)｜[第五輪綜合](2026-10-04-r5-synthesis.md)｜原報告：[Fable](2026-10-04-r6-fable.md)、[astra](2026-10-04-r6-astra.md)｜[設計原則](../principles.md)

**這輪從方向轉到「放在哪、先做哪一小塊」。** 兩份都以 proto7-2 HEAD（核心精簡進行中）為準，都沒動 repo。技術題照使用者「落地時才逐題定」，這輪列出並附建議，標 ★ 的是真的兩難、照原則 2 做成選項。

## 1. 一致的結論

1. **daemon／tick 核心零新增。** 落地要用的零件 HEAD 都有：`once`＋`slot`＋launch、`exit.json`＋`never_started`、`x` 透傳、`edit_json` 三態、`tock.json`、同槽 `state.json` 換 run 不清、`until_round`、帶 run 的 kill。r2 提的精確 `timing` 第一塊用不到，**不當既定核心需求**。
2. **分兩處放**：基礎設施擴充（工具、子 daemon、稽核、控制／重試／診斷）留 `modules/`；工作語意（步驟、帳、轉接、觀測）進**任務包**。
3. **還缺的四個新包**：`step`（步驟表直譯器）、`account`（grant／帳／預留結算）、`adapt`（固定依據、轉接、信箱、窗口）、九軸契約與檢查器（先附在 `step` 裡）。另外三樣只是慣例或欄位：**槽外結果檔**、**時間契約欄**（效期／耐性）、**依據 `basis`**。
4. **任務包分層**（原則 8）：
   - **kernel 核心任務**：等 tock、讀快照、接續自己的狀態、把決定寫成 tasks／控制／掛載請求；不帶資源種類與算法。
   - **通用包**：`step`、`account`、`adapt`、`observe`（含現有 history 用途、時間量測）、`supervise`／`schedule`。
   - **agent 包**：狀態機、角色名冊、記憶與工具協定、團隊部署模板。
   - **LLM 包**：端點／分配者、`adapt-llm`（摘要、候選驗證）、LLM 決策者。
   - astra 指出一處文件要對齊：[組件契約 §2.8](../../../proto7-2/notes/component-contracts.md) 把帳本、准入列為 kernel 核心任務的例子，[精簡方案 §10](../../../proto7-2/notes/core-slimming.md) 放通用包；建議採後者，讓不記帳的用途也能單獨用 `step`。
5. **第一小塊＝單 node 的 `step` 直譯器第一版＋槽外結果檔，跑一個非 LLM 的工作。**
   - 直譯器是一個 `keep` 任務（`max_live: 1`），每次只登記下一個子工作的 `once`；讀框架、查結果、推進 `pc`。
   - 子工作把結果寫到**槽外**（帶 run id），直譯器讀它；`exit.json` 只當旁證——這是第五輪「直譯器自己的洞」的修法。
   - 檢查器第一版只查第五輪留下的三條（等結束只等有限工作；重試要冪等或先查回條；時間值標哪條線）＋結構錯誤。
   - 不用 restart、retry_lost、wake、掛載、語言前端、安裝器——**不必等精簡收完**，可以並行準備；整合驗證放在精簡收尾的 commit 上。
6. **探針形狀**（兩份重疊的部分）：正常走通；直譯器被殺後接回同一嘗試、不多派；結果已寫、`pc` 未更新時中斷只推進一次；once 槽已清仍靠槽外結果繼續；產物寫了、結果沒寫時殺子工作，不誤報成功也不當沒做；跑很多回合檔案數不長；pause 時耐性不前進。
7. **後續順序**：
   1. `step` 單 node 切片與探針；
   2. 控制包收完後接 kill 子任務；接一個本地資源入口與 `account` 的最小 grant／預留（到這步「子工作對核心可見」才值錢）；
   3. 加一個鄰居，用 `adapt` 傳最新值與依據，驗不同流速下的效期與耐性；
   4. 有逐件需求再補事件保存與窗口；
   5. 最後接 agent／LLM 作者與 `adapt-llm`。

## 2. 兩份不同的地方

| 項目 | Fable | astra | 綜合傾向 |
|---|---|---|---|
| 範例工作 | 備份：dump→verify→rotate→notify；rotate 不冪等，順便驗保守檢查 | CSV 轉 JSON→統計報表；兩步都可重算、無外部副作用 | 先 astra 的（最乾淨，只驗主幹），第二個案例用 Fable 的備份驗非冪等 |
| 放哪 | `proto7-2/modules/step/` | `proto7-2/packs/step/`（`packs/` 還只是方案） | 照精簡方案：基礎設施在 `modules/`、任務包在 `packs/`；`step` 屬任務包 |
| 步驟種類 | `run`／`wait`／`count`／`end` | 兩步線性流程，先不做平行與前端 | 差不多；四種步夠用 |
| 證據不足時 | 冪等步預設重起，非冪等步停住（`park`） | 一律停在 `unknown`，不自動重送 | 第一版照 astra 保守停住；冪等重起當選項 |
| 識別 | 一步一槽 `<job>.<step>`，結果檔 `<node>/out/<job>/<step>.json` | 分 `job_id`／`step_id`／`request_id`／`attempt_id`／`slot#run`，結果 `jobs/<job>/results/<step>/<attempt>.json` | astra 的分法較完整（跨重送保持同一 request）；落地時定 |
| 價值怎麼驗 | 測試形狀直接驗骨架 | 另用同一案例對照手寫 Python：恢復要多少人工、重派幾次、能否直接讀檔找卡點 | 兩者都做；後者回答「這層值不值得存在」 |

astra 另外提醒三處要**收窄承諾**：
- 請求／回條不是可靠事件信箱（同名回條會覆寫）。
- `until_round` 擋的是**新啟動**，不是完成期限；已啟動的工作照跑。
- 「先讀 status」不代表所有原因都在 status 裡，必要時讀 `last-round.json.errors` 或之後的診斷工具。

## 3. 落地技術題（附建議；★＝做成選項）

| 題 | 建議 |
|---|---|
| ★ 加完 once 要不要立刻 `wake` | 選項 `wake: false|true`，預設 `false`（守固定節拍）。 |
| ★ 耐性到期做什麼 | 選項 `on_timeout: unknown|fail|kill`，預設 `unknown` 停住；逾時不等於對方沒做，不抹掉遲到結果。 |
| ★ `end` 之後 keep 怎麼辦 | 選項 `restart_on_end: false|true`；預設 `false`（看到 `pc=end` 立刻退出）；要停就改表項 `enabled: false` 或 `until_round`。 |
| ★ 未知時怎麼辦 | 預設停；可選查入口、交人工，或契約允許時重送。沒有無條件「未知就重試」。 |
| ★ 耐性用哪個鐘 | 第一版本地回合（pause 時不走）；要真實時間再加單調鐘。 |
| ★ 結果檔保留多久 | 第一版到工作明確結案才清；之後可選確認後清或容量上限。 |
| 結果檔路徑誰定 | 直譯器在 argv 裡展開路徑（沒有 per-item env）。 |
| 條件語言 | 只准 `exists`／`glob`／`result.ok`／單一數字比較，不開運算式。 |
| 框架壞掉 | 不前進、記錯、等人；不從結果檔反推 `pc`（原則 9）。 |
| 派工跨檔（框架與 tasks.json）要不要做交易 | 暫不做；先量未知有多常見。 |
| `x` 欄 | 每個包一個 key。 |
| 九軸宣告放哪 | 第一版內聯在步（`idempotent`）；包級契約檔等 `pack.json` 定稿。 |
| 換程式版本能否接舊框架 | 執行中工作固定版本；沒有遷移規則就不接。 |
| 要不要延長 once 槽保存 | 不需要；靠槽外結果。真實工作裡「永遠 unknown」太多再回頭看。 |

## 4. 跟改進循環怎麼接

- **可以並行**：`step` 的契約卡、範例工作、框架／結果格式、檢查器、離線探針——全落在新包，不碰核心。
- **要等精簡收完**：用到 restart／reload、retry 外移後的重試、監督包控制動作、依賴詳細 status 的診斷。
- 改進循環照原則 10：**先寫包的契約卡，再做探針，再按組件歸屬修**。`step` 重派是 `step` 的錯；包沒保存承諾的結果是包的錯；不往 tick 加保護。

## 5. 仍然不確定

1. 最小步驟語意能不能真的比手寫 Python 省事，還是把同樣的複雜度搬成更多 JSON（兩份都列）。
2. 派工窗口與「結果前被殺」造成的未知有多常見；保守停住的代價值不值得加包內恢復機制。
3. 真正接上的資源與外部工具能提供多少查詢、去重、期限控制——決定骨架能承諾到哪裡。
