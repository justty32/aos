# 受限 node 與必然的轉手：兩份思考報告的綜合（第三輪）

← [事實的傳遞與時間確定性](../2026-10-04-fact-propagation.md)｜原報告：[Fable](2026-10-04-r3-fable.md)、[astra](2026-10-04-r3-astra.md)｜上一輪：[第二輪綜合](2026-10-04-r2-synthesis.md)

題目接續[使用者對第二輪的駁斥](2026-10-04-r2-synthesis.md#使用者的回應與駁斥10-04)：很多 node 天生不能吃原始資訊，資訊給它必定被轉手；這會是 kernel 的一個任務包（事實轉接），**先記下、先不做**；時間也是原始資訊。兩份報告各自獨立寫成，都照[設計原則](../principles.md)寫（單一 node 視角、通用／agent／LLM 標記、核心精簡）。下文 F＝Fable、A＝astra。**這些都是提案，不是決定。**

## 結論

1. **受限是好設計，而且 repo 裡早就是常態**：daemon 的 ctl 只吃 `{"op","node","by"}`、`counter.py` 只吃 `tock.json`、namespace 的 reviewer 只認 `llm-submit.v1`。窄輸入＝原則 3 的「單元」：測得了、換得掉、複製得起。第二輪錯在把「搆得到」（掛載）當成「吃得下」（格式、詞彙）。
2. **轉手要分兩種**：確定性、可重算、損失列得出來的（選取、換算、聚合…，「精確有損」）；以及 LLM 摘要這類不可重算的（「模糊有損」）。失真是**相對於受限 node 的輸入契約**來算的，檢查只有一條：**被轉接合併掉的情況，不能包含這個 node 必須分辨的情況**。
3. **轉接包是 kernel 的通用任務包**（從 core-slimming 的 `relay` 擴出來），LLM 步驟另外分成子包。鏈從**固定版本的依據**直接算，只有一跳；模糊步驟最多一個、放在鏈尾、後面接驗證。node 自己不讀依據，也不必為失真負責。
4. **時間的轉接**：期限類**不換算**，每次回到來源的鐘讀「到了沒、還差幾個來源回合」；只有規劃類才換算成自己的回合，而且要標 `estimate`、附誤差界。`tock.json` 就是核心唯一內建的轉接器，也是轉接包的範本。
5. **對 daemon／tick 的新增是零**。第二輪已提的 `timing`（C4）理由變強了，但它不是本輪的新要求。現在只需要先在寫介面時保留幾條約定，不寫程式。

## 共識

| 主題 | 兩邊都同意的 | 出處 |
|---|---|---|
| 受限的種類 | 出處、格式、協議、詞彙、時間尺度、容量；一個 node 可以同時有好幾種（F 另列單位、身分、位置，後兩者核心已處理） | F §1.2；A §1 |
| 先定義 node 要分辨什麼 | 輸入契約先定，轉接才知道要保留什麼；F 說成四件事（`need`、schema、unknown 時怎麼做、時鐘來源），A 說成「必須得到不同反應的情況」 | F §1.3；A §1 |
| 確定性≠無損，出處≠正確 | 純程式也會丟東西（取整、多對一詞彙），但丟了什麼要能列出來；雜湊只證明內容身分，引文存在只證明字串存在 | F §2.1；A §2、§4 |
| 「每跳回原始」是轉接器的能力 | 不要求受限 node 直讀；轉接器重新投影原始依據，不投影上一跳的輸出 | F §3.3；A §4 |
| 證據放在 node 外 | node 只吃窄輸入；依據、規則版本、驗證結果另存，給驗證者和追查者讀 | F §4.2；A §3、§4 |
| 失真責任 | 跟著鏈的宣告走：規則選錯算規則作者的，執行錯算轉換器的，漏檢算驗證器的，送錯算交付者的；受限 node 不負責 | F §4.2；A §4 |
| 有效交付要一起量 | 不能用全部拒絕（或全部 unknown）換零錯誤 | F §7.3；A §2 |
| 期限不重新起算 | 相對期限只在原始起算點解讀一次；跨線只轉接「到了沒」，不用 interval 比例推算回合匯率（pause、wake 都會打破比例） | F §5.2；A §5 |
| 一條鏈一個程序 | 每步都能單獨測，但不必各開一個程序；`tasks.json` 的排列不保證前一個任務已完成，不能拿它當鏈的順序 | F §3.2；A §3 |
| 核心零新增 | 轉接任務是普通的 keep 任務，鏈的設定由包自己讀，核心不認識事實、摘要、詞彙或驗證政策 | F §6；A §6 |

## 分歧與頂層傾向

| 題目 | Fable | astra | 頂層傾向 |
|---|---|---|---|
| 「回原始」讀哪一版 | 每回合從來源（`latest.json`）重算，LLM 步驟用依據雜湊做快取 | **固定依據版本**；每跳讀 `latest` 會把不同時刻的事實混在一起；中間層新加的有效事實（上級的限制、正式核准）不能被洗掉；上一跳足夠時可以直接接 | **合用**：每次計算綁定一組固定版本（F 的 `about` 雜湊已經是這件事）；中間層的新事實算另一個來源；F 的「預設吃來源，宣告 `pipe` 才吃上一步」已經涵蓋 A 的「上一跳足夠就直接接」 |
| 誰持有鏈、擺在哪 | 預設擺在消費端：受限 node 自己的 node 裡一個 keep 任務，或程式內呼叫的函式庫 | 由合法的上級或介面持有者組裝，從上級既有的入口交付（較貼近使用者說的「只吃上級給的」） | **不必拍板，做成部署選項**：重點是鏈直接讀依據（只有一跳），不是誰持有；同一份鏈宣告，擺哪裡都能跑 |
| 輸入的交付形式 | **暫存器式**：覆寫 `in/<sense>.json`，信封帶 `state: ok／unknown／absent` | **件式**：每件一個檔＋回條；驗證不過就不交付（`withhold`），node 沒收到新件就不工作 | **兩種都要，看 node 怎麼吃**：暫存器式的輸入必須帶三態（否則不交付時 node 只看得到上一份，過期了也不知道）；件式的輸入可以用「不交付」表示未知。A 也提醒：會沿用舊值的 node 一定要有表達「未知」的方式 |
| 回合內的先後 | 任務模式下，轉接器和 node 都等同一個 `tock.json`，誰先醒沒有保證；解法是讓 node 改等 `in/clock.json`（時間也由轉接器交付） | 件式交付天然沒有這個問題 | 暫存器式採 F 的解法、件式不需要；都不改核心。F 自己也說這招在 pause／wake 下還沒驗過 |
| LLM 步驟的上限 | 硬規定：到一個受限 node 的整條路徑上最多一個模糊步驟，跨 node 也算；驗證器照 `via.fuzzy` 擋 | 不設跳數上限；組裝者依 node 用途決定准許多少損失，驗證責任要分清楚 | **要拍板**（題 1） |
| 鏈的設定放哪 | 包自己的檔 `<node>/adapt/<sense>.json`，或 `tasks.json` 的 `x.adapt` 透傳欄 | 包自己的檔，不依賴還在提案中的 `x` 透傳 | **偏 astra**：放包自己的檔就夠了，不必等 `x` 透傳 |

## 各自獨有、值得留的

**Fable**
- **收口分兩半：搆得到（reach）與吃得下（digest）**。第二輪只處理了前一半。
- **問題出在轉手的位置，不在次數**：轉手發生在組織鏈上（上級轉述給下級），才會累積誤差；搬到消費者門口，跳數就是 1，每次都能回來源重算。
- **讓 LLM 直接讀原始資訊，本身就是一次轉手，而且是最糟的那種**。比較好的標準是：確定性轉接器直讀來源，LLM 只吃轉接器給的窄格式。受限不是 LLM node 的缺陷，而是它的失真控制。
- 精確有損可以靠「每次從來源重算」自動歸零，所以失真控制只需要管模糊有損。
- **效應器就是同一個包反過來跑**：受限 node 的窄輸出要變成 ctl 檔、信、grant 請求，一樣要 reshape＋map＋validate＋stamp。感官提供行動的依據，閘門決定行動的許可。
- 每條鏈都宣告自己的失真預算（`max_age_rounds`、`fuzzy_hops`、`need_drop`），守不住就輸出 unknown，就像 RTOS 宣告 deadline。
- `in/`＝感官、`out/`＝事實、`inbox/`＝意圖，三個目錄成一組。

**astra**
- **必要區分檢查**：例如 node 只判斷有沒有到 80°C，交 `{"hot":true}` 就夠了。但「現在正常」和「期間曾經異常、現在已恢復」，對只看最新值的 node 是同一個輸入；需要分辨的話，就得給它事件或窗口。
- **小而可組合的表示**：平均不能再拿去平均，但保留 `sum` 和 `count` 就能精確合併。轉接包值得找的就是這類表示。
- **誤差界的傳遞**：倍率 `a` 的換算加上至多 `q` 的取整，誤差界＝`|a|×前一步誤差＋q`；遇到門檻判斷時，誤差區間如果跨過門檻，就不能硬交一個確定的答案。範例中 79.96°C 先四捨五入再比，就會判錯。
- **取整方向要看用途**：「不可提早喚醒」要無條件進位，「不可延長有效期」要無條件捨去；傳輸和排隊的時間也要算進去。
- **「還差 3 個來源回合」不等於「孩子還能跑 3 次」**：後者牽涉到工作機會和配額的分配。
- 「忠於指定版本」和「消費時是否仍有效」要分開評分；只給驗證過的證據，不證明交付的就是被驗證的那份（回條要綁定實際的輸出內容）。
- 跨子 daemon 時，由橋接任務交付到子空間的收件區；不能假設孩子用現有的 mounts 就讀得到空間根以外的父檔案。

## 轉接任務包草案（合併兩邊）

包名暫定 `adapt`（從 core-slimming §10.3 的 `relay` 擴出來；copier 也併進來），LLM 步驟分成子包 `adapt-llm`。標記：〔通用〕＝把 LLM 換成 cron、備份、CI 一樣用得到；〔LLM〕／〔agent〕＝沒有它們就沒有這個需求。

| 任務 | 一行契約（職責／前置條件 → 保證；明確不管） | 標記 |
|---|---|---|
| `fetch` 取據 | 經合法掛載取得依據，固定版本（雜湊），只放行允許的出處 → 後續每一步處理的都是同一份內容，缺了就明說；不管來源說的是不是真話 | 〔通用〕 |
| `select` 選取投影 | 照規則選欄位、記錄、範圍 → 選到的值原樣保留，列出 `omitted`；路徑指不到就回 unknown，不猜 | 〔通用〕 |
| `convert` 轉碼換算 | 格式、單位、固定詞彙表的轉換；匯率和字典都有版本 → 可以重算，附上誤差界；表裡查不到就回 unknown，不建領域字典 | 〔通用〕 |
| `window` 窗口聚合 | latest／hold／window＋sum／max／count → 精確可重算，寫明涵蓋範圍、分母、混疊計數；不補回沒取到的樣本 | 〔通用〕 |
| `time` 時間轉接 | 讀來源的鐘（`round.json`／`tock.json`）和截止點 → 輸出「到了沒、還差幾個來源回合」、`source_paused`；規劃用的換算標 `estimate`、附誤差界；不重設期限，也不保證工作準時完成 | 〔通用〕 |
| `validate` 驗證 | 檢查 schema、`need` 有沒有漏、失真預算、必要區分 → 明列哪些驗過、哪些失敗、哪些未知，不過就輸出 unknown；不把格式通過當成語意正確 | 〔通用〕 |
| `stamp` 附註 | 記錄依據、規則版本、驗證結果（`about`、`via`、`aoi`）→ 綁定實際輸出的內容；不替內容的真實性背書 | 〔通用〕 |
| `deliver` 交付 | 暫存器式（覆寫 `in/<sense>.json`，帶三態）或件式（每件一檔＋回條）→ 交出去的內容和驗過的那份一致；不管 node 之後怎麼決策 | 〔通用〕 |
| `summarize`／`translate`／`infer` | 輸入已經是窄格式、有端點使用權 → 產生候選，附上 claim＋quote，標記 `fuzzy`；不保證語意正確，也不自己核准交付 | 〔LLM〕 |
| `validate` 的語意外掛 | quote 是不是原文子字串、數字和專名有沒有在原文出現、LLM 評審 → 抓得到改寫、編造、過時，抓不到遺漏 | 〔LLM〕 |
| agent 接面 | 接 agent 的記憶、角色訊息、專用信箱協議（一般檔案信箱是〔通用〕的 `deliver`） | 〔agent〕，有需要才加 |

- **組合**：一條鏈＝一個感官＝一個程序依序跑（F 的 `aos7-adapt` 或 A 的 `relay` 都是一支程式）；鏈的宣告放在包自己的設定檔，不交給 tick 解讀。反方向（node 的窄輸出 → ctl 檔、信、請求）用同一套步驟，就是效應器。
- **跟 `tock.json` 的關係**：`tock.json` 是核心唯一內建的轉接器。它在消費端、每回合重新投影 `round.json`、照 run 過濾身分、用覆寫暫存器，轉的正是時間。包就照這個樣子做（覆寫暫存器，不做 log 管線）。**包不改 `tock.json`，也不加欄位**：`time` 任務以它和 `round.json` 為依據；暫存器式的 node 改等 `in/clock.json`，避開回合內的先後問題。

## 對 daemon／tick 的要求

照原則 7、9，本輪**沒有新的核心要求**。

| 項目 | 核心／模組 | 標記 | 說明 |
|---|---|---|---|
| `timing`（monotonic 量的 tick／tock 耗時，第二輪 C4） | 核心 | 〔通用〕 | 第二輪已提、spec 還沒收。本輪多了一個理由：時間的換算要附誤差界，需要 ms 數據（F §5.3）。**但期限類不換算，所以轉接包的第一版不需要它** |
| `x` 透傳欄（core-slimming 提案） | 核心 | 〔通用〕 | **不需要**：鏈的設定放包自己的檔 |
| 跨子 daemon 交付 | 模組（橋接任務） | 〔通用〕 | 交付到子空間的收件區；不改核心 |
| 刻意不做 | — | — | 核心不排回合內的任務先後；`tock.json` 不加欄位；核心不認識 `in/`；不加同步 hook；不保存完整證據（「只留上一次」不變，需要重新投影的版本由來源或包保存） |

## 「時機到了」的訊號與現在最便宜的準備

**訊號**（出現任一條，就針對那一個 node 做第一條鏈，不必等 node 變多）：
1. 第二個消費者要同一份來源的**不同形狀**，開始出現兩份手寫的投影程式（F）；或同一個轉換被兩個以上的 node 重寫（A）。
2. 第一個**非 Python、小模型或人**要站在某個格式後面（可替換性真的被用上了）。
3. 出現「來源正確、node 也照規格工作，結果卻錯了」的案例，要追到中間的轉換（A）；或是輸出端閘門擋下過時的輸入，像 hsched 的 `stale_envelope`（F）。
4. 第一個跨時間線的期限交接（父子 daemon、不同 interval）。
5. 某個 LLM node 讀原始資訊的 token 占成本一半以上，或又出現 R-2 那種視窗被塞爆的情況。

**現在最便宜的準備**（只寫約定，不寫程式）：
- 寫 node 的介面或[組件契約](../../../proto7-2/notes/component-contracts.md)時，多加兩欄：**`need`（必要欄位，或必須得到不同反應的情況）**、**沒有有效輸入時怎麼做**。
- 輸入要能交代四件事：**目的契約版本、依據的識別、證據關聯（放在 node 外）、時間的單位與起算點**（A §8）。
- 替第一個真實的受限 node 留幾組「必須得到不同反應」的案例，當作第一版的驗收材料。
- 在 spec 裡點名 `tock.json` 是「核心唯一內建的轉接器」。這句話不改任何行為，只是定下方向。

## 要使用者拍板的題目

先排除不必拍板的：**鏈擺在哪**（消費端、上級或中繼，部署選項）；**暫存器式還是件式**（看 node 怎麼吃，兩種都提供）；**三態**（暫存器式的輸入一律帶 `state`，這是核心三態原則的延伸，不是選項；F 的 Q1 就這樣解掉）；**期限換不換算**（兩邊共識：不換算，F 的 Q3）；**重新投影、證據保存期、摘要嚴格度、快取**（都做成設定）。

1. **LLM（模糊有損）轉手要不要設硬上限？** (a) 硬規定：到一個受限 node 的路徑上最多一個模糊步驟、放鏈尾、後面接驗證；控制類用途（支用、權限、否定條件、不可逆提交）不准有模糊步驟。驗證器照 `via.fuzzy` 和 `purpose` 機械地擋。(b) 不設上限，每條鏈自己宣告預算。(c) 不管。**推薦 (a)**：這是唯一能從結構上讓誤差不累積的規則，也延續了第二輪「摘要不當控制依據」。代價是：深層的邊緣 node 如果只掛得到已經做過摘要的 digest，就只能用精確步驟，或申請加掛原文。
2. **第一個要接轉接鏈的受限 node 選哪個？它絕不能把哪兩種情況做出相同反應？錯一次、漏一次、晚一次各有什麼後果？**（A 的兩題合併）這是業務定義，系統沒辦法從資料推出來，卻決定了轉接要保留什麼、有損處理的驗收門檻放在哪裡。候選：hsched 吃政策的 kernel、agent 的 prompt 輸入，或一個純程式的監看 node。
3. **「先記下、先不做」要做到哪一步？** (a) 只把上一節的準備寫進約定和組件契約（不寫程式），等訊號出現再做第一條鏈；(b) 先做兩個離線探針，拿數據；(c) 連約定都先不寫。**推薦 (a)**：幾乎零成本，以後包來了只是換掉手寫的那段；探針等題 2 有答案再跑，比較有對象。

## 不確定的事

- **選取和換算要不要有自己的表達式語言**：dotted path 加 `["sub", a, b]` 正是 jq、JSONPath 那類工具長成怪物的起點；改成「一步＝一個純函式」雖然簡單，卻會綁死 Python，LLM 光讀檔也比較難看懂（F #1）。
- **「模糊最多一跳」在深層組織裡守不守得住**：要看那個「非常多受限 node」的未來裡，掛載權限開放到什麼程度（F #2）。
- **最小輸入契約會不會漏掉跨時間的差異**：node 有記憶、會重試或用窗口之後，單份輸入可能不夠，要驗的是整段輸入歷程（A #1）。
- **可以重新投影的依據能縮到多小**：原文可能太大、保存很貴，或只有上級讀得到（A #2）。
- **把語意驗證放到 node 外，能不能真的獨立糾錯**：摘要者和驗證者如果有相同的誤解，只是把錯誤換個地方放（A #3）。
- **受限 node 到底需不需要「我來得及嗎」**：如果多數只要「到了沒」，換算那一整套都可以砍掉，包會更小；`in/clock.json` 在 pause／wake 下的行為也還沒驗過（F #3）。

## 建議的探針

全部離線，用假 LLM 後端。

**探針一 `adapt-loss`：投影上一跳 vs 每跳回原始**（F §7.3＋A 探針一）
- 擺法：一個來源（結構化真值，含數字、單位、否定、例外、門檻附近的值）；末端的受限 node 只吃一個小 schema。三組：(A) 鏈式，每跳吃上一跳的輸出，每跳一次假 LLM 摘要；(B) 每跳回到固定版本的原始依據，模糊步驟最多一個、放在鏈尾；(C) 純精確，即 B 拿掉模糊步驟。鏈長 1／2／4／8，5～20 個 seed。假 LLM 注入遺漏、否定翻轉、數值偏移，另外測「每跳都犯同一個錯」的共同偏誤，再加「中層新增有效限制」的案例。
- 量：決策錯誤率、`need` 遺漏率、無依據主張率、AoI、unknown 率、有效交付率、讀取量、假 LLM 呼叫數。
- 假設與標準：A 的錯誤率隨跳數大約照 1−(1−p)^h 增加，B 跟跳數無關（共同偏誤不一定改善）；B 錯誤率 ≤ C＋2 個百分點；中層限制不會被 B 洗掉；unknown 率 ≤ 5%（不能用拒絕換零錯誤）；不預設 B 一定贏。

**探針二 `adapt-time`：期限不換算 vs 換算**（F §7.4＋A 探針二）
- 擺法：父線 1000 ms 發 grant（`until_round` 用父回合計），子線 150 ms 掛一個只吃期限的受限 node。四組：(a) 用量到的 interval 換算成子回合；(b) 每個子回合重讀父的鐘，輸出「到了沒、還差幾個父回合」；另加兩個反例組：(c) 每跳都讀 `latest`；(d) 收到之後重新起算。注入：子線每 20 ms 被 wake 一次、父線 pause 3 秒、父 interval 中途改成 500 ms、轉接器放慢到 1200 ms、來源換版、拿錯證據、驗過後交付不同的內容。
- 量：過期後仍行動、還沒到期卻停手的次數；期限延長量；ms 誤差；混疊計數；unknown 率；「忠於版本」和「消費時仍有效」分開評分。
- 假設與標準：(b) 過期誤放是 0，(a)、(c)、(d) 在 wake、改 interval、換版的情況下會出錯；轉接器放慢時 (b) 會標出混疊，但期限判定不出錯；父線 pause 期間輸出 `source_paused`；合法的工作都能完成。ms 誤差界不穩定是允許的（那是 `timing` 的問題，不是轉接包的問題）。
