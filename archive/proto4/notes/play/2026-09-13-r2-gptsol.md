- 現象：唯一需要回頭翻第二次的是 daemon 啟動；短範例寫 `./aos-daemon &`，但非互動 shell 結束後它真的死了 → 我期待：照開機範例抄就能持續運作 → 建議：主範例直接用適合自動化環境的 `setsid -f ./aos-daemon …`，把單純 `&` 放互動終端說明。

- 現象：`aos-kernel-boot`、`aos-kernel add` 都會印出下一步指令 → 我期待：完成一步後知道下一步 → 建議：保留，這是很有效的導引。

## 3. 五組故障

- 現象：`nocwd.json` 沒寫 `cwd`，`aos-kernel add` 不但沒拒絕，還補成 inst 所在資料夾並成功執行 → 我期待：題目稱它為壞檔，而且 kernel 文件又說缺 cwd 會進 `bad/` → 建議：明講「經 `add` 可省略、手動塞進 `procs/` 才會被退件」，否則兩段規則像互相矛盾。
- 現象：`typo/inst.json` 沒有 `stderr`，執行 `aos-exec … --stderr -` 後直接看到 `unknown symbol misspelled-name`，退出 1 → 我期待：不用找內部狀態檔就能看到錯誤 → 建議：上一輪加入的 `--stderr -` 確實有效。
- 現象：錯字後 `--status` 顯示 `pc 0`、失敗 form 與 stacktrace；我知道修字後重跑同一格 → 我期待：錯誤不會偷偷跳過 → 建議：可以把內部 `src/step.janet:141` stacktrace 收折，第一行其實已足夠新手處理。
- 現象：跑完原本的 A 後，在 `prog.janet` 最前插入 NEW；下一格警告 pc 可能錯位，但實際再次跑 A，NEW 被跳過 → 我期待：改動後停住等我選擇，而不是帶著警告繼續 → 建議：提供 `--accept-change`，預設偵測到插刪 form 就停止；至少把「會跳過／重跑」寫得更直白。
- 現象：警告直接告訴我可用 `--reset`，所以我知道怎麼從新程式重來 → 我期待：錯位後有明確復原路徑 → 建議：這句保留。

## 4. 五個問題

1. **容易上手：4/5。** 系統開機是 `export AOS_DAEMON_HOME`、`cd proto4-3`、daemon、init、boot、ls，共 6 條；暫存家另加 `mkdir`。寫好 `prog.janet` 與 `worker/.aos/inst.json` 後，一條 `aos-step prog.janet` 就能跑第一格，但完整七格需重打七次。
2. **容易理解：3/5。** `pc` 在 `aos-step --status` 中很直觀，`boot` 也能由 `aos-kernel-boot K` 猜到；但「CPU」其實是 daemon 裡的一支 `aos-run` Linux process，不是實體核心，而「boot」又不負責上電或灌 `K/`，最容易想歪。
3. **複雜度有沒有藏好：3/5。** 一般成功路徑不用碰 `.aos-step/env.img` 或 `K/state.json`；但為了讓 shebang 找到 Janet，必須知道 daemon 繼承的 `PATH`，錯誤畫面也直接露出 `src/step.janet` 與 Janet image 的內部 stack。
4. **控制結構簡單但全面：4/5。** `aos-kernel-init`、`boot`、`add`、`ls` 已足以完成正常閉環，`aos-daemon-ctl stop` 也能乾淨關機；缺口是沒有 `aos-kernel rm/cancel`，而 `aos-daemon-ctl rm` 拔的是 CPU，不是取消 `duplicate` 這種行程，兩層很容易混用。
5. **要背的東西少：3/5。** 日常至少記 3 種檔名／位置：`prog.janet`、行程 `inst.json`、資料夾工具的 `.aos/inst.json`；常用旗標約 5 個：`--status`、`--reset`、`--stderr -`、`--name`、`--ncpu`；另有 `PATH` 與 `AOS_DAEMON_HOME` 兩個環境變數，還要保存兩個原型的絕對路徑。

## 前五名最該改的

1. 在主開機範例提供一條跨非互動 shell 也可靠的 daemon 常駐指令，並讓錯誤提示使用同一條。（小）
2. 增加 `aos-kernel rm/cancel`，讓誤排、永不完成或占住名字的行程能由公開介面撤回。（中）
3. 說清楚缺 `cwd` 的兩條規則：`add` 會補，只有繞過 `add` 手放 `procs/` 才會進 `bad/`。（小）
4. 讓 boot/add/ls 清楚呈現「還在等下一個 tick」，避免成功訊息與暫時的舊表互相打架。（小）
5. 把 README 的原始碼檔案職責移到開發文件，首頁只留一條完整的新手路徑與故障入口。（中）
