## 1. 只看 README 把東西架起來

**花約 4 分鐘、6 個指令，一次成功。** 沒卡死，但回頭翻了兩次。

- 現象：`proto4-3/README.md` 的「怎麼跑」給了 `aos-daemon &`／`aos-kernel-init K --ncpu 2`／`ctl add K/inst.json`，但完全沒提 `AOS_DAEMON_HOME`。我是從最下面「檔案」那段 `aos_home.py：家的優先序」才撿到的 → 我期待快速上手區就把「暫存家怎麼指」寫出來 → 建議：「怎麼跑」第一行加 `export AOS_DAEMON_HOME=…`，並把 docs/kernel.md 那句「用環境變數比 `--home` 保險」搬上來。
- 現象：`aos-kernel ls` 在 `/tmp/play-opus` 跑會回 `這裡不是 kernel 的家（沒有 config.json）`，得先 `cd K` → 我期待 `aos-kernel ls K` 或吃 `--home` → 建議：`ls` 收一個可選的路徑參數；不收也行，但 README「怎麼跑」的那行要寫成 `cd K && aos-kernel ls`（docs/kernel.md 有寫 `（cd K 再跑）`，README 沒有）。
- 現象：我一直在找「插 cpu」的指令，README 沒有這個字 → 實際上是 `ctl add K/inst.json` 之後 kernel 自己把 `cpus/0.json`、`cpus/1.json` 插上去，我等了 4 秒 `ls` 就從「沒插上」變「running」 → 建議：這個自動行為是整套最舒服的一段，值得在 README 明講一句「cpu 不用你插，kernel 上電後會自己補」。
- 好的地方：`aos-kernel-init` 跑完直接印下一步（`開機：aos-daemon & ； aos-daemon-ctl add /tmp/play-opus/K/inst.json`），這比讀文件有用。

## 2. 寫自己的逐步 lisp（6 個 form）

程式在 `/tmp/play-opus/p1/prog.janet`：`def city` → `defn tag` → `spit notes.txt` → `aos/call-dir "./weather"` 帶 `:read`＋`:json` → `def data` → `spit summary.txt`。被叫的資料夾 `p1/weather/` 裡放 `.aos/inst.json`，跑 `./gen.sh` 印一段 JSON 到 `out.json`。

**手動 6 格全綠、第 7 格回 100。丟進 `K/procs/3.json` 後 7 秒自動跑完、被收進 `procs/done/`，`summary.txt` 內容正確。**

- 現象：README「函式庫怎麼用」開頭寫 `(import ./src/aos :as aos)`，我照抄一定壞（`could not find module ./src/aos`，因為那是相對 proto4-4 的路徑）；實際上 **根本不用 import**，aos-step 每格都幫你重綁 `aos/*` → 我期待範例可以直接貼進我的 prog.janet → 建議：把那行 import 刪掉，改一句「`aos/*`、`here`、`pc` 已經幫你綁好，直接用」。這是我這輪唯一一個「照 README 做會壞」的地方。
- 現象：每跑一格，aos-step 會把那個 form 的值印到 stdout（我看到 `@{:code 0 :kind "child" :out "…" :value @{…}}`），README 只示範了 `--status` 的輸出 → 我期待 README 提一句 → 建議：一句話帶過就好，這個回顯在手動 debug 時很好用。
- 現象：進 kernel 跑完後 `out.txt` 是**空的**——因為 aos-exec 每格都截斷 stdout，最後那格（回 100）什麼都不印 → 我期待至少看得到最後一格的輸出 → 建議：這在「沒做什麼」有寫，但新手一定會踩；README 的 kernel 範例 inst.json 旁邊直接加註「這兩個檔每格會被清空，要留紀錄請自己 append」。
- 好的地方：`:read` ＋ `:json` 一次到位，`(aos/value r)` 直接拿到 `@{"city" "Tainan" "files" 3 "ok" true}`，這條路完全照 README 走通，沒有意外。

## 3. 故意弄壞三樣

**(a) inst.json 少寫 `cwd`**

- 現象：丟進 `K/procs/9.json` → kernel 3 秒內退件，log 寫 `退件 9.json（沒寫 cwd）`，檔案在 `procs/bad/9.json`。**這條滿分**，訊息直接告訴我錯在哪。
- 現象：但同一份用 `aos-exec` 直接跑，只得到 `exit=2`，**一個字都沒印**。因為我 inst.json 裡沒寫 `stderr`，錯誤訊息照規則進了 `/dev/null`。補上 `"stderr": "err.txt"` 才看到 `aos-step: 找不到程式：prog.janet` → 我期待 aos-exec 自己的失敗訊息不該被 inst.json 的串流設定吃掉 → 建議：aos-exec 加一個 `--stderr` 覆蓋旗標（README 已列為「沒做」），或至少讓 `aos-kernel-init` 產的範例 inst.json 預設帶 `stderr`。**這是新手最容易鬼打牆的一點：東西壞了，畫面上什麼都沒有。**

**(b) form 裡寫錯字**（`(strng b)`）

- 現象：`aos-step: form 2 失敗："unknown symbol strng"`，退出碼 1，`.aos-step/error` 有完整 stacktrace；改好後再跑一格就過了，`error` 檔自動消失 → 我期待看到**行號** → 建議：`form 2` 是 0-based 的頂層 form 索引，不是行號，我得自己數；訊息裡補一個 `(prog.janet:3)` 會省很多事。stacktrace 指的也是 `src/step.janet:108`，對使用者沒意義。

**(c) 跑一半在 prog.janet 前面插一個 form** ← **最嚴重**

- 現象：pc=3 時我在第一行插 `(def zzz 999)`，再跑一格：**回 0、沒有任何警告**，實際上重跑了 `spit "b.txt"`，`n` 從 4 變 5，整條錯位一格，插進去的 `zzz` 永遠不會被跑到 → 我期待至少一行警告 → 建議：`.aos-step/` 存一個「上次那份程式的 hash 或 form 數」，發現對不上就印一行 `程式改過了，pc 可能錯位，要 --reset 嗎？`（不用擋，印出來就好）。這條在「沒做什麼」有寫，但**做錯的代價是靜悄悄地跑錯**，值得升級成一個警告。
- 順手撞到的：`cp prog.janet other.janet` 之後 `aos-step other.janet --status` 直接回 `:done true`——兩支程式共用同一份 `.aos-step/`。文件有寫，但表現是「無聲地什麼都不做」。

**(d) 額外撞到一個沒在任務書上的大雷：`--done-exit` 和 kernel 的 `done_exit` 是兩套。**

- 現象：我把一支 proc 的 argv 寫成 `[… "prog.janet" "--done-exit" "0"]` 丟進 `procs/`。程式**做完了**（`x.txt` 有內容），但 kernel 的 `config.json` 認的是 100，所以永遠收不走：`aos-kernel ls` 顯示 `cpu0 上 11 running runs=27` 一直往上加，那顆 cpu 就這樣被佔死，佇列有人也不會換 → 我期待兩邊對不上時 kernel 或 init 出個聲 → 建議：`aos-kernel-init` 產的說明裡寫死「procs 裡的 aos-step 不要自己給 `--done-exit`」，或 kernel 排程時看到 proc argv 含 `--done-exit` 就記一行 log。

**(e) 收工訊息會說謊。**

- 現象：`aos-daemon-ctl stop` → `收工了（pid 124299）`，很好；但接著 `ls` 回 `沒有 state.json（daemon 沒起來過）` → 我期待「daemon 已收工」 → 建議：改個字就好；順帶 README 說「daemon 沒在跑時 `ls`／`get` 讀最後狀態」，正常 stop 之後其實讀不到，因為 `state.json` 被刪了。

## 4. 五個問題

**① 容易上手 — 4 分。** 從零到第一個程式在 kernel 上跑完：**6 個指令＋2 個檔**（`export PATH`、`export AOS_DAEMON_HOME`、`aos-daemon &`、`aos-kernel-init K --ncpu 2`、`aos-daemon-ctl add K/inst.json`、`cp proc1.json K/procs/3.json`，檔案是 `prog.janet` 和那份 inst.json）。扣分在兩處要回頭翻：`AOS_DAEMON_HOME` 在 README 最下面、`cd K` 才能 `ls` 只在 docs/kernel.md 有。

**② 容易理解 — 4 分。** 「daemon＝硬體、`ctl add` ＝插一顆 cpu、kernel＝第一個程序」這組比喻一講就懂，這是整份文件最好的一段。想歪的兩個詞：**`pc`**——我以為是行號，實際是 0-based 頂層 form 索引，錯誤訊息 `form 2 失敗` 也用這個數，害我數了三次；**`procs/<pid>.json` 的 pid**——那不是 OS 的 pid，是我自己隨便取的檔名（我取 3、9、11），叫 pid 會讓人去找對應的行程。

**③ 複雜的東西有沒有藏好 — 3 分。** 被迫知道的東西偏多：`argv[0]` 一定要絕對路徑、`cwd` 一定要寫死否則被搬到 `cpus/` 就跑錯地方、daemon 開的時候 PATH 裡要有 `janet`（不然 `#!/usr/bin/env janet` 找不到）、`--home` 不會傳給子孫所以要用環境變數、每格會截斷 stdout。`runs_at`、硬連結那招我沒被迫知道（`ls` 沒露出來），這點做得好。

**④ 控制結構簡單但全面 — 3 分。** `init`／`add`／`ls`／`step`／`tick` 這幾支分得很乾淨，沒有重疊。缺口三個：(a) 「把行程排進去」沒有指令，是 `cp` 進 `procs/` 並自己想一個檔名；(b) 排進去之後沒有 `rm`／`kill`／`ps <pid>`，要撤只能刪檔；(c) 開機三步沒人包（README 自己提過 `aos-kernel-boot`），我每次都得重打。另外 `aos-kernel` 現在只剩 `ls` 一個子命令，這支存在感很弱。

**⑤ 要背的東西少 — 3 分。** 檔名 6 個（`inst.json`、`.aos/inst.json`、`config.json`、`state.json`、`.aos-step/`、`kernel.log`）、環境變數 3 個（`PATH`、`AOS_DAEMON_HOME`、`AOS_EXEC`）、旗標日常只用到 3 個（`--ncpu`、`--interval-ms`、`--reset`）。可以合併的：`--done-exit` 應該只有 kernel 那一份說了算；`aos-kernel-init` 可以順手產一份 `procs/` 的範例 inst.json，這樣「argv 絕對路徑＋cwd 寫死＋stderr 要寫」三條規則就不用背。

## 前五名最該改的

1. **inst.json 沒寫 `stderr` 就完全看不到錯誤**——`aos-exec` 加 `--stderr` 覆蓋旗標，或 kernel 排程時對沒寫 stderr 的 proc 記一行 log。（**中**）
2. **改過的 prog.janet 靜悄悄錯位**——`.aos-step/` 記住上次的 form 數／hash，對不上就印一行警告。（**小**）
3. **README「函式庫怎麼用」那行 `(import ./src/aos :as aos)` 照抄必壞**——刪掉，改成「`aos/*` 已經綁好」。（**小**）
4. **`--done-exit` 兩套會讓 cpu 被佔死而且 `ls` 看不出來**——統一由 kernel `config.json` 說了算，或在 `ls` 標出「這位好像做完了但收不走」。（**中**）
5. **開機三步 ＋ 把行程排進佇列，都沒有指令**——補 `aos-kernel-boot` 和 `aos-kernel add <inst.json>`（自動配檔名、順手檢查 cwd／argv）。（**中**）

（第 6 名如果算的話：`aos-kernel ls` 收路徑參數，以及 `stop` 之後別再說「daemon 沒起來過」，兩個都是**小**。）

## 我實際跑過的指令（精簡）

```sh
export PATH="$HOME/.local/bin:$PATH"; export AOS_DAEMON_HOME=/tmp/play-opus/home
P3=…/proto4-3; STEP=…/proto4-4/aos-step

$P3/aos-daemon &                                   # 硬體上電
$P3/aos-kernel-init K --ncpu 2                     # 建家
$P3/aos-daemon-ctl add /tmp/play-opus/K/inst.json --interval-ms 1000
cd /tmp/play-opus/K && $P3/aos-kernel ls           # cpu 自己插上了
$P3/aos-daemon-ctl ls

cd /tmp/play-opus/p1
$STEP prog.janet                                   # ×7，第 7 次回 100
$STEP prog.janet --status                          # {:pc 6 :n 6 :done true}
$STEP prog.janet --reset
cp /tmp/play-opus/proc1.json /tmp/play-opus/K/procs/3.json   # 進佇列 → 7 秒後 done/

cp nocwd.json K/procs/9.json                       # → procs/bad/，log 寫「沒寫 cwd」
$P3/aos-exec /tmp/play-opus/p2/nocwd.json          # exit=2，零訊息
sed -i 's/string/strng/' p3/prog.janet; $STEP prog.janet     # form 2 失敗
sed -i '1i (def zzz 999)' p3/prog.janet; $STEP prog.janet    # 靜悄悄錯位
cat K/procs/../kernel.log | grep -v 沒事

$P3/aos-daemon-ctl stop                            # 收工，pgrep 確認無殘留
git -C …/aos status --porcelain                    # 空：repo 沒被動
```
