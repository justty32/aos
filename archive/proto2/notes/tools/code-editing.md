# code 工具包發想

## 1. 這包做什麼

一句話：`fs` 管通用讀寫，`code` 管看程式骨架、找程式、檢查修改、跑程式和反悔。

## 2. 工具清單

第一版只顧 Python。工具少一點，小模型比較不會叫錯。

### `code_outline`

參數：`path`，一個 Python 檔的路徑。
回傳：類別、函式、方法的名字和行號。巢狀項目會縮排。不回原文。
何時用：第一次碰一個檔，先看骨架。不要一開始就讀完整檔。

### `code_search`

參數：`query`、`path="."`、`context=2`、`limit=20`。
第一版只找原樣文字。不讓模型先煩惱特殊寫法。
回傳：檔名、行號、命中行，還有前後幾行。最多 50 筆。
何時用：看完骨架後，用名字或錯誤文字縮小範圍。範圍越小越好。

### 精準改一段：沿用 `fs` 的 `edit`

參數：`path`、`old`、`new`。
`old` 剛好出現一次才換。零次或多次都不改，並叫模型多抄幾行。
回傳：檔名、改動起始行、換掉幾個字。
建議不要在 `code` 再做一支。兩支同用途的工具只會讓小模型選錯。

### 整檔改寫：沿用 `fs` 的 `write`

只准用在新檔，或很短而且已經完整讀過的檔。
既有的大檔一律用 `edit` 分小段改。不要為了改幾行重送整份內容。

### 套 patch：第一版不提供

小模型常把 patch 的檔頭、空白或位置寫壞。失敗訊息也不容易救回來。
先用數次 `edit` 完成小修改。真的常遇到跨很多檔的大改，再補這支工具。

### 跑測試或程式：沿用 `fs` 的 `sh`

參數：`command`、`timeout=60`。最長只准 120 秒。
cwd 固定是專案根目錄。要進子資料夾，就在指令開頭寫 `cd 子資料夾 &&`。
回傳：退出碼、秒數、標準輸出最後 1500 字、錯誤輸出最後 1500 字。
何時用：跑一支程式或一小段測試。可能超過一分鐘就改用 `run_long`。
超時會停止，並叫模型把同一句改交給 `run_long`。`code` 不再做另一支執行工具。

### `code_check`

參數：`path`，一個 Python 檔。
內部跑 `python -m py_compile`。成功只回 `ok`，失敗回行號和短錯誤。
何時用：每完成一小次修改就叫一次，再跑相關測試。
建議不要每次寫檔自動跑。一次修改兩個檔時，中間狀態本來就可能不完整。

### `code_checkpoint`

參數：`paths`，準備修改的檔案清單。
它把原檔複製到 `<home>/.aos-undo/<編號>/`。不存在的路徑也會記下來。
回傳：編號、收了哪些檔、共幾個字。不要回檔案內容。
何時用：動手改之前叫一次。不要用 Git commit 當存檔點。

### `code_diff`

沒有參數。比較現在的檔案和最近一次 checkpoint。
回傳：有變的檔名、增減行數、短差異。沒變就只回 `no changes`。
何時用：改完後確認自己只動到預期的地方。

### `code_undo`

沒有參數。把最近一次 checkpoint 收下的檔案還原。
當時不存在的檔，撤銷時會移除。checkpoint 本身先保留，避免按錯一次就沒救。
回傳：還原和移除的檔名。只在改壞且無法小修時用。

## 3. 給小模型的預設 prompt 全文

```text
你正在改一個 Python 專案。
第一次碰檔案，先用 code_outline 看骨架。
再用 code_search 找名字、呼叫處或錯誤文字。
只讀真正需要的那幾行。
改之前，用 code_checkpoint 收下準備改的檔案。
一次只改一小段。
小修改用 edit，而且 old 要抄到只出現一次。
新檔或很短且已完整讀過的檔，才可以用 write 整份寫入。
不要整份重寫既有的大檔。
每完成一小次修改，就用 code_check 檢查 Python 語法。
再用 sh 跑最相關的小測試或程式。
可能超過一分鐘的工作改用 run_long，不要留在這一格等。
最後用 code_diff 看自己改了什麼。
如果工具說結果還有更多，縮小 path、query 或 context 再叫。
不要為了看更多而把上限調到最大。
改壞又救不回來時，才用 code_undo。
```

## 4. 工作區長什麼樣

建議 agent 的世界資料夾就是專案資料夾。
agent 自己的 home 放在專案內的 `.aos-agent/`，不要把專案塞到 home 隔壁。
這樣所有程式路徑都從專案根目錄算，模型比較不會迷路。
`sh` 的 cwd 就是專案根目錄。要跑子資料夾裡的東西，由指令自己先 `cd`。

## 5. 省 token 的規矩

每支工具的整包回傳最多 4000 字，並在完整一行結束處截斷。
`code_outline` 最多 200 項。`code_search` 預設 20 筆，最多 50 筆。
`code_diff` 從前面保留 4000 字。`code_check` 最多 2000 字。
`sh` 跑程式時只留兩邊最後 1500 字，因為錯誤通常在尾端。
checkpoint 和 undo 的回傳最多 1000 字，只列檔名，不帶內容。
被截斷時固定回 `truncated: true`、總字數、已顯示字數和縮小範圍的建議。
不要只寫「截斷」。要讓模型知道還有多少，以及下一次該縮哪個參數。

## 6. 跟現有東西怎麼接

新增 `proto2/packs/code.py`，內有 `TOOLS`、`PROMPT`、`run(name, args, ctx)`。
`code.py` 不再定義 `edit`、`write`、`sh`。這三支留給 `fs`。
agent 的 `tools.json` 在 `packs` 加上 `"code"`，並一起開 `"fs"` 和 `"jobs"`。
`Ctx` 加 `project_path(path)`，把相對路徑放到世界資料夾下，並擋掉往外走的路徑。
`Ctx` 再加 `undo_dir()`，固定回 `<home>/.aos-undo/`。
其他事情可直接用已有的 `ctx.world`、`ctx.home`、`ctx.truncate()`。

## 7. 現在故意不做的邊緣狀況

- Python 以外的骨架和語法檢查。
- 壞到讀不出骨架的 Python 檔。
- 圖片、二進位檔和不是 UTF-8 的檔案。
- 連結到專案外的檔案。
- 兩個 agent 同時改同一個檔。
- 超大專案的搜尋目錄和快取。
- 檔案改名、權限改變和子 Git 專案的差異。
- 需要鍵盤輸入或一直跑著的程式。
- 自動猜測該用哪套測試。
- 撤銷 shell 指令造成的外部變化。
- 自動清理舊的 `.aos-undo/`。

## 8. 要使用者拍板

- T-35 世界就直接是專案資料夾，home 用 `.aos-agent/`？建議：是，路徑最單純。
- T-36 精準修改和整檔寫入沿用 `fs`，`code` 不重做？建議：是，工具越少越好。
- T-37 第一版不提供套 patch，只用多次 `edit`？建議：是，小模型比較不會卡在格式。
- T-38 checkpoint 用 `.aos-undo/` 複製檔案，不碰專案 Git？建議：是，不污染原本歷史。
- T-39 Python 語法由模型每次小改後主動檢查，不在寫檔時自動跑？建議：是，回合比較清楚。
