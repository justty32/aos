# review 工具包——回頭看自己，改進下一次

一句話：這包讓 agent 定期回頭看自己做過什麼，找出做得差的地方，然後改自己的做法。

## 回顧看哪些材料

- `<home>/prompts.json`：看當時收到什麼、答了什麼、目標有沒有跑掉，也能看出同一件事是否重做。
- `<home>/ledger/<日期>.jsonl`：看工具叫了幾次、花多久、帶回多少字、吃多少 token、花多少錢。
- `<home>/thoughts/`：看深度思考的題目、短結論、花費，以及最後有沒有真的照結論做。
- `<home>/branches/`：如果分支工具有留下紀錄，就看各條路的結論、淘汰理由，以及最後選了哪條。
- `<home>/outbox/`：看最後真的回了什麼，不把心裡想過但沒說出口的內容算成成果。
- `<home>/inbox/`：看誰交代過什麼、哪些信已讀、哪些信一直沒處理、回話有沒有接上來意。
- 工具回的 `error`：看哪個工具常失敗、失敗前是否反覆用了相同叫法。
- `<home>/llm-result.json` 的 `error`：看模型請求失敗時，agent 有沒有停住、重做或換錯方向。
- 帳本與狀態裡的超時：看慢在哪一步，以及超時後有沒有重複送出同一件事。

帳本要多記 `ok`、短短的 `error_kind`，以及不含原文的參數記號。這樣才能算錯誤與打轉，又不把指令全文抄進帳本。

## 工具

### `review_recent(n_steps | since)`

- 參數：二選一。`n_steps` 是往回看幾格；`since` 是起始時間。
- 回：一段短摘要。只報工具次數、錯誤次數、總時間、總 token、總花費、繞遠路的步驟和最後結果。不回原文。
- 什麼時候用：剛做完一件事，或覺得剛才做得不順時。
- 繞遠路的判準：同一工具連叫、同一錯誤重現、做了又撤回、拿了很多內容卻沒用在回話裡。

### `review_patterns()`

- 參數：無。預設看最近 30 天，沒有那麼久就看全部。
- 回：最常出錯的工具、最貴的工具、最常連續呼叫的工具、反覆出現的錯誤種類，各列次數與最近發生時間。
- 什麼時候用：定期回顧，或同一件事卡了好幾次時。
- 同一種問題用「工具名加錯誤種類」判斷。第一版不讓模型猜題目分類。

### `review_thoughts(id?)`

- 參數：`id` 可不填。填了就看那一次；沒填就看最近幾次。
- 回：題目、最後結論、花費、後來有沒有採用。分支先看 `adopt` 紀錄，再看後續對話、工具動作與 outbox；看不出來就回「不知道」。
- 什麼時候用：想知道深度思考有沒有白花錢，或要重查某次分支選擇時。
- 只帶回短結論與採用結果，不把整段思考原文塞回記憶。

### `lesson_add(text)`

- 參數：`text`，只能是一行，格式是「情況 → 我做了什麼 → 下次改成什麼」。
- 回：新增後的那一行、目前條數，以及是否有舊教訓被歸檔。
- 什麼時候用：同一種錯誤重現，或這次確實找到一個下次能照做的改法時。
- 寫進 `<home>/memory/lessons.md`。這裡記「我學到什麼」，不跟記「我是誰」的 `memory/self-note.md` 混在一起。

### `lessons_list()`

- 參數：無。
- 回：最近 20 條教訓，一條一行，新的在前面。
- 什麼時候用：開始相似工作前，或準備新增教訓、怕重複時。

### `improve_prompt(pack, text)`

- 參數：`pack` 是工具包名字，`text` 是新的補充做法。
- 回：寫入的路徑、字數，以及下次走格才會生效的提醒。
- 什麼時候用：某個工具包的預設做法反覆害自己走錯，而且一句教訓不夠清楚時。
- 寫到 `<home>/prompt-overrides/<pack>.md`。只改自己的覆蓋，不動出廠的 `packs/`。
- 只准改自己已開啟的工具包。整份覆蓋檔一次換掉，先讀舊內容再改。

### 跟 `tool_add` 接起來

回顧若發現同一串 shell 已手打三次，就先確認輸入與輸出，再用 `tool_add` 做成自己的工具，接著用 `tool_try` 試一次。工具只加進自己的 `tools.json`。不要因為只用過一次就造工具。

## 什麼時候自動提醒

最小規則：連續 3 格 `idle`，而且上次回顧後至少新增 10 次工具呼叫，就往 `<home>/inbox/self/` 丟一封「該回顧了」的信。

`state.json` 記上次提醒與上次完成回顧的位置。同一批紀錄只提醒一次。自動的只有寄信；讀材料、下判斷、寫教訓仍由模型動手。不做背景 LLM 呼叫。

## 自我優化的邊界

agent 可以改自己的 `memory/lessons.md`、`prompt-overrides/`、`tools.json`、`memory/`。也只能改自己的 home。

agent 不能改 `system-prompt.json`、`llm.json`、`.aos/inst`、出廠的 `packs/`，也不能改別人的家。

覆蓋寫壞時，刪掉那個 `<home>/prompt-overrides/<pack>.md` 就回到原樣。`lessons.md` 最多留 100 條；超過時把最舊 20 條移到 `<home>/memory/lessons-archive/<日期>.md`。

## 給模型的預設 prompt

> 任務告一段落或收到回顧提醒時，先看最近摘要，再看長期規律。檢查目標有沒有完成、哪一步失敗、哪一步重複、哪個工具太貴、思考結論有沒有真的採用。只把會改變下次做法的事寫成教訓。格式固定為「情況 → 我做了什麼 → 下次改成什麼」，一條一行。偶發小事、措辭喜好、已經修好的單次錯誤，不要寫成教訓。先用教訓；只有某個工具包的做法反覆有問題，才改 prompt 覆蓋。只有同一串 shell 已手打三次，才造工具。

## 跟成本綁在一起

回顧的主軸就是錢跟時間。每個任務都算 token、錢、格數和秒數，再跟上次同類任務比，看是變貴還是變便宜。

「同類任務」第一版可以拿第一封任務信的前 N 字做粗略 key。也可以讓模型在 lesson 裡自己標 tag；有 tag 就優先用 tag。

除了原本的提醒規則，下面任何一條成立，也往 `<home>/inbox/self/` 丟一封「該回顧了」的信：

- 一天花費超過門檻。
- 單一任務花費超過同類任務平均的兩倍。
- 某個工具連續三次都超過它的成本門檻。

`review_patterns()` 改成按錢排：先列最貴的工具，再列最貴的任務，最後列最常重複叫卻沒有進展的工具。打轉就是燒錢，每項都附次數、錢、格數和秒數。

lesson 要帶數字，格式改成「同類任務／tag：原本平均 X 元／Y 格 → 改法 → 之後平均 Z 元／W 格」。下次回顧自動拿新紀錄比對這條教訓有沒有真的省到；錢和格數都沒下降，就標記「無效」。

token 依 `engines.json` 的 `price` 換成錢；沒寫單價就留 `null`，不猜。

LLM 世界從 `usage/<day>.json` 的 `by-requester` 分帳取每個 agent 的花費，再跟自己 ledger 裡的任務和工具對上。

- T-60a：回顧的成本門檻寫死，還是放 `llm.json`？建議放 `llm.json`，不同世界可以用不同預算。
- T-60b：無效教訓自動刪掉，還是留著標記？建議留著標「無效」，免得下次又試同一個沒用的改法。

## 現在故意不做的邊緣狀況

- 不判斷教訓彼此矛盾，也不自動合併相似教訓。
- 不保證能看出一個思考結論是否被採用；證據不足就說不知道。
- 不回顧已刪掉、已搬走或壞掉的紀錄。
- 不處理兩個進程同時寫 lessons、覆蓋檔或帳本。
- 不替很久以前的舊帳補成功、錯誤種類或參數記號。
- 不自動刪除工具、不自動改 prompt、不自動寫教訓。
- 不評分人格，不讓回顧結果蓋過使用者給的要求。
- 不跨 agent 合併紀錄，也不替父 agent 計算小孩的成敗。
- 不做圖表、網頁介面、搜尋索引或語意分類。
