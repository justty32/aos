# code 工具包試玩

## 做的時候的坑

- 公開的 `Ctx` 還沒有規格提到的 `project_path()` 與 `undo_dir()`。先在 code 包內用 `ctx.world` 與 `ctx.home` 做同一件事。
- `code_diff` 沒有參數，所以它只能看最近一次 checkpoint。一次不要存太多不相干的檔。
- 整包測試有其他並行修改造成的失敗。本輪自己的六條測試是 6/6。

## 玩的紀錄

- 我說：「找出哪裡定義了 add 函式，幫它加型別註記，檢查語法，給我 diff。」
- agent 用 `code_search` 找到 `calculator.py:1`，再讀三個小檔。
- agent 用 `code_checkpoint` 存 `calculator.py`，再用 fs 的 `edit` 加上 `int` 註記。
- `code_check` 回 `ok`。`python3 test_calculator.py && python3 main.py` 回 0，輸出 5。
- `code_diff` 顯示 `calculator.py：+1 -1`。最後回話說修改、語法與測試都成功。

## 玩的時候的坑

- 模型沒有照 prompt 先用 `code_outline`。它先用 fs 的 `ls`，再直接搜尋。這次仍找對檔案。
- 第一次搜尋把 `.aos-agent` 裡自己的對話也搜出來。已改成跳過 `.aos-agent`。
- 模型有叫 `code_diff`，但最後回話只說做完，沒有貼出差異內容。差異仍留在工具結果裡。

## 缺什麼接點

- 缺 `Ctx.project_path(path)`：統一把相對路徑放進世界，並擋掉跑到世界外面的路徑。
- 缺 `Ctx.undo_dir()`：統一取得 `<home>/.aos-undo/`。

## 介面簡不簡潔（我自己的評分與哪裡可以更簡）

- 8/10。六支工具各做一件事。`code_diff` 與 `code_undo` 都不用參數。
- checkpoint 還是要傳檔案清單。這是讓撤銷範圍看得見，先不再縮。

## 內部機理簡不簡單

- 8/10。只用 `ast`、字串搜尋、`py_compile`、複製檔案與 `difflib`。
- checkpoint 多一個 `checkpoint.json`，用來記哪些檔案原本不存在。

## 效能與邊緣狀況（留給使用者看）

- 搜尋每次都把範圍內的文字檔讀完。專案大了會慢。
- 差異會把 checkpoint 裡的檔和現在的檔整份讀進記憶體。大檔會吃記憶體。
- 不處理非 UTF-8、二進位檔、連結跳出專案、兩個 agent 同時改檔與檔案權限。
- 不會清理舊的 `.aos-undo/`。用久了會一直長大。
