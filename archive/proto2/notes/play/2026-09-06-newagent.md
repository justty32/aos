# newagent：開新 agent 與模板

## 做的時候的坑

- 原本的 `spawn()` 只會在父 agent 底下生小孩，不能建任意的頂層世界。
- `--prompts` 的名字看不出來它要的是 JSON 路徑。原始任務書有寫清楚，所以照路徑做。
- 開工時只有四個包；做到模板時，其他輪已放進 `fs`、`code`、`communication`。模板最後只用了當下真的存在的包。
- 本輪限制不能改 code map，所以沒有替新增模板與測試補 repo 的 code map。
- 本輪八條測試全綠；完整 `test.sh` 是 368/391，23 條 FAIL。失敗都在並行輪改動中的 LLM 帳本、舊工具清單、review/self-memory 與背景進程檢查。

## 玩的紀錄

- 建立：`aos-user new <scratchpad>/play-newagent/coder --template coder --engine deepseek-flash`。
- register 成功。daemon 每秒推一格。
- 人：「用 ls 看看資料夾」
- agent 先後叫了 `ls`、`read`、`self_who`、`sh`，最後又叫 `ls`。它最後回：「看過了。目前我在的工作資料夾有 `agent/`、`.aos/`、`.gitignore`；隔壁還有 `proto2/`。你接下來要我怎麼做？」
- outbox 落在 `0066.json`。玩完已 unregister，daemon 回「時鐘關掉了」。

## 玩的時候的坑

- `fs.ls` 回的是 `dir<TAB>agent...`。模型一開始把 `dir` 當成路徑，又去列和讀 `dir`，兩次都失敗。
- 模型後來自己改用 `sh` 的 `pwd && ls -la`，再用 `fs.ls path=agent`，有恢復並完成。
- 只叫它看一次資料夾，回話落在 step 66；收鐘時已到 step 80、busy 24。它叫了七次工具，小事花太多格。
- 最後說 `.aos` 是 undo 存檔，這不是它看到的內容，是自己猜的。

## 缺什麼接點

- `aos_agent.py` 缺一個「建立頂層世界」函式。現在 `new` 只好在 `aos-user` 自己寫一份。之後應搬進 `aos_agent.py`，再讓 `new` 和 `spawn` 共用。

## 介面簡不簡潔（我自己的評分與哪裡可以更簡）

- 8/10。平常用模板只要一條指令。新手也可以一路按 Enter。
- `--prompts` 若能叫 `--prompts-file` 會更直白，但規格已固定，所以文件特別說它是路徑。

## 內部機理簡不簡單

- 設定就是讀四個 JSON、用旗標改值、再寫回去。沒有新格式。
- 所有新功能留在 `aos-user` 一檔。代價是建世界的幾行跟 `spawn()` 重複。

## 效能與邊緣狀況（留給使用者看）

- `aos-user packs` 每次會載入所有包。包很多以後會變慢，現在數量少不用先做快取。
- coder 的 `ls` 實玩會繞路。`fs.ls` 的表格把類型放第一欄，小模型可能把 `dir` 當路徑；這個格式值得另輪觀察。
- 沒處理兩個人同時建同一路徑、建立到一半斷電、home 用 `../` 走出世界、模板 JSON 內容更細的驗證。
- 沒處理私有工具包。`new --packs` 只看內建包。
