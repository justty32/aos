# branch 工具包試玩

## 做的時候的坑

- `join` 沒有一個「立刻收這包旁線結果」的共用接點。包裡直接用 `llm_dir()` 看自己的結果檔。
- `adopt` 改完 `prompts.json` 後，共用 `act` 還會追加舊主線的工具結果。用 `on_system_prompt` 在下次問主線前清掉。
- 分岔當下的快照最後一則是 `fork` 工具呼叫。每條請求要先補上這次呼叫的工具結果，訊息串才是完整的。

## 玩的紀錄

- 我：「用三個不同方向想『週末怎麼安排』，然後選一個告訴我」
- agent 叫 `fork`：分成「零行程放電」「戶外冒險」「社交與體驗」三條。
- agent 第一次叫 `join`：「還差 1 條」，等下一輪再叫。
- agent 第二次叫 `join`：收到三段總結。
- agent 最後選「社交與體驗」：週六早午餐、看展、逛書店，週日上半天手作短課。

## 玩的時候的坑

- 共用 LLM 一次最多跑兩個 `deepseek-flash` 請求。第三條會自然排隊，所以第一次 `join` 還差一條。
- 模型看得懂「還差 1 條」，下一輪會自己重叫 `join`，沒有重複 `fork`。
- 這台引擎沒寫 `price`，所以預估與實際花費都是 `null`。三條實際合計 1817 token。

## 缺什麼接點

- 缺一個讓 `join` 當場收回指定旁線結果的接點。
- 缺一個讓 `adopt` 明確告訴共用 `act`「這次不要追加舊工具結果」的接點。

## 介面簡不簡潔（我自己的評分與哪裡可以更簡）

- 8/10。只有 `fork`、`join`、`adopt` 三個名字，用途好猜。
- `budget` 的三個鍵還是有點長。但是直接寫單位，比短名清楚。

## 內部機理簡不簡單

- 7/10。一個 Python 檔就做完。資料只用 JSON、Markdown 和現有 LLM 請求檔。
- 為了補 `join` 與 `adopt` 的接點，包內有兩小段繞路。

## 效能與邊緣狀況（留給使用者看）

- 每條都會抄一份完整記憶。記憶很大時，磁碟與輸入 token 會線性增加。
- 不上鎖。兩個進程同時改同一個 agent 可能互相蓋掉。
- 請求送到一半失敗、結果遲到、引擎回壞格式、id 碰撞與舊分支清理都沒做。
- 金額只是估算。已送出的請求不能取消。
