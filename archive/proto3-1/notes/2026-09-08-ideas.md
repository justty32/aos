### 4. list 當世界、求值走 eval（09-08 上午）

原話：「開 proto3-1，這次試試看把 list 作為世界，求值走 eval。同樣兩套都做。」「可以開 agent 去做。」

→ 我的理解與設計見 [design](2026-09-08-design.md)：世界＝list＋環境、跑一格＝eval、
  下一格要跑什麼用 `(next form)` 寫回（就是 proto2 inst 的寫法）、狀態機變成 form 改寫。
→ 做法：兩個 opus agent 各做一套（Janet／SBCL），規格同一份，各管各的目錄。

→ 結果（同日）：兩套都做完。Janet 51 條、CL 44 條測試全綠，範例與非同步都通。
  - 兩邊 agent 各自做了一個沒在規格裡的判斷：Janet 把等待的 until／then 當 closure 塞進 `(agent-wait …)`
    的 tuple；CL 改成純資料 `'(:llm-result 3)`＋函式名，由 `wait-check` 解讀——所以 CL 的 form 印出來
    就看得懂在等什麼。**CL 那個更合「list 是資料」的本意**，Janet 版之後可以照抄。
  - CL 的 kernel 把鐘的登記簿改成 list（順序固定），不然 observer 會漏看一格；Janet 用 hash 順序
    不定，觀察者只好開場先記一筆。順序要不要定，之後統一。
  - 沒有一等環境的代價 CL README 寫得很清楚：`*me*` 是全域動態綁定 → 非同步全部排隊跑；
    狀態只能 `(var 'x)`／`(setvar 'x v)` 手工演資料夾；form 裡的符號要顧套件。
