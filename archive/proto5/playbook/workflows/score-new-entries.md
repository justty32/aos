# 評新交件（品管部的四步）

← [workflows](README.md)｜來源：[notes/2026-09-25-arknights/qa/README.md](../../notes/2026-09-25-arknights/qa/README.md)｜評分器 [eval/README.md](../../notes/2026-09-25-arknights/eval/README.md)

**適合什麼活**：製造隊做出一批新的條目（詞條、證據、任何「要附出處」的產出），但這些條目**不在基準集裡**、沒有標準答案可比。評分器照舊用，程式一行不改。

## 四步

| 步 | 做什麼 | 叫模型？ | 注意 |
|---|---|---|---|
| 1 保住交件 | 列出每人交件在哪、還在不在；還在專案副本工作樹的，原樣複製到自己的暫存夾（只讀） | 不叫 | 副本會被下一次試跑退回基線；沒留住的寫「無資料」，不要猜 |
| 2 機械＋證據 | 對快照跑機械檢查、證據行號檢查；**草稿也跑一次證據檢查**當交件前對照 | 不叫 | 列裡沒有「」引文時，證據檢查只驗到行號沒超界，要在報告寫明 |
| 3 評審 | 每人叫一次（固定 `claude-opus-5`），「標準答案」那格換成草稿 | 每人 1 次 | 分數意思變成「比草稿好不好」，**不能跟基準集的分數直接比**；先設 `JUDGE_BUDGET`＝現有行數＋人數，多叫就會被擋 |
| 4 抽查 | 挑最低 3 個，每個寫「哪裡扣分、原文哪一行」，自己打開原文看兩三列 | 不叫 | 沒交件的排最前；評審的意見也要回原文核一次，可能是自己前處理弄出來的 |

照打（包裝腳本在 qa 夾，評分器本體不動）：

```bash
python3 proto5/notes/2026-09-25-arknights/qa/score_nongolden.py ~/tmp/arknights-try <快照夾> <批標籤> 名1 名2 …            # 不叫模型
JUDGE_BUDGET=<現有行數+人數> python3 …/score_nongolden.py ~/tmp/arknights-try <快照夾> <批標籤> 名1 名2 --judge --label qa-xxx
```

## 格式偏了怎麼辦

內容對、格式不合慣例（例如證據列用「A L155」代號、不寫檔名）時，機械分會掉到 0。**不要改評分器**：原樣分數當正式分數，另做一份「只修格式、不動內容」的版本再跑一次，兩個都報，並把格式要求回給製造隊。

## 量測怎麼切

多張單同時跑時，`aos-team score --task` 會把整隊的數算給每張單。每人的 token／秒要照「單子的 assignee＋他做這張單的那段時間」切 `usage.jsonl`；跳數用 `aos_hops.py report` 的「agent 一格」次數，那是每個成員的，不是每張單的。

## 哪裡可再用

- 別的專案：換掉 `score_nongolden.py` 裡的草稿路徑（`aos-drafts/<名>/`）就行；沒有草稿時可以不給參照，但評審的「覆蓋」那項就沒意義，要在報告寫明。
- 要能跟基準集比：挑基準集裡的人重跑製造，用評分器原本的 `eval.sh`。
