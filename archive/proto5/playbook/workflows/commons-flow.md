# 投稿 → 審 → 入庫 → 查閱：哪幾步是程式、哪一步才要模型

← [workflows 索引](README.md)｜規格 [spec/team/commons.md](../../spec/team/commons.md)｜來源 [notes/2026-09-25-commons §1、§2](../../notes/2026-09-25-commons/README.md)

**適合什麼活**：任何「很多人往一個共用的地方放東西、要有人把關」的事——共用知識庫、共用工具包、共用樣板。重點是把關的人（圖書館員）大部分時間不用想。

**哪裡可再用**：照 [`examples/commons/`](../../examples/commons/README.md) 三份名冊開隊；把關規則照抄 [`lib/aos_team_commons.py`](../../lib/aos_team_commons.py) 的 `check_fields`／`check_files`／`similar`。

| 步 | 誰做 | 程式還是模型 | 09-25 真跑 |
|---|---|---|---|
| 1. 決定要分享哪一條、寫成一段 | 投稿隊的成員 | **模型**（這步本來就要想） | astra 讀 notes.md，挑對了那條、跳過「便當」那條，4～5 次模型 |
| 2. 投稿（`commons_submit`） | 成員的工具 | 程式：只往自己 outbox 放一份申請 | — |
| 3. 附件抄進圖書館的收件格 | 投稿隊的郵差 | 程式：路徑、大小、符號連結 | 投稿後 1 輪（≤ 5 秒）到 |
| 4. 形狀檢查（必填、大小、路徑、執行位、完全重複） | 圖書館員隊的郵差 | 程式 | 兩次都過 |
| 5. 跟既有條目像不像 | 圖書館員隊的郵差 | 程式（關鍵字重疊） | r2 **漏判**一次（換說法），已改判法 |
| 6. 像的才判「收不收」 | 圖書館員 | **笨模型**，二選一＋一句理由 | 單跳實驗：deepseek 6 秒、3 次、6,370 token，判對 |
| 7. 入庫（寫檔、索引、人看的總表） | 圖書館員隊的郵差 | 程式 | 乾淨的投稿 0 次模型 |
| 8. 回信給投稿者 | 投稿隊的郵差 | 程式 | — |
| 9. 查閱（`commons_search`） | 需要的隊的成員 | 程式查、模型決定怎麼用 | 兩次 B 隊都查到並在成品裡引用條目 id |

形狀：**只有「寫」和「判重複」兩處用模型**；寫的用強模型（本來就要想），判重複用笨模型（題目窄、做不了壞事、判錯人一行修），其他全程式。
