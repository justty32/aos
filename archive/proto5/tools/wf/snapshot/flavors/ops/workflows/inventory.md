# inventory — 唯讀盤點 / 健康檢查

[WORKFLOWS](../WORKFLOWS.md)｜[INDEX](../INDEX.md)

跑一輪唯讀指令看服務現況，回一句總結。只看不改。

**何時用**：「盤點一下」「健康檢查」「服務還活著嗎」；heartbeat 包 routines 的「開工唯讀盤點」叫的就是本檔。
**何時不用**：已知壞了、要動手修 → [incident](incident.md)；要送新版本上線 → [deploy](deploy.md)。

## Done when

- 下表**每一列**的指令都跑過，且回了一句總結（全正常 / 哪幾列對不上）。
- 有列對不上「正常樣貌」→ 已轉 [incident](incident.md)，或（要等使用者）[WAIT_USER](../WAIT_USER.md) 一行。

## 流程

1. 依序跑下表指令，逐列比對「正常樣貌」。
2. 全對 → 回一句總結，結束，不留檔（活狀態不記已完成）。
3. 有對不上 → **原文貼出**該列輸出，走交接段。

## 盤點表

| 項目 | 指令 | 正常樣貌 |
|------|------|----------|
| 容器 / 行程 | `{{指令，如 docker ps}}` | `{{如：4 個容器都 Up}}` |
| 磁碟 | `{{指令，如 df -h /}}` | `{{如：使用率 < 80%}}` |
| 服務健康端點 | `{{指令，如 curl -fsS localhost:8080/healthz}}` | `{{如：回 200、body 為 ok}}` |
| `{{其他項目}}` | `{{指令}}` | `{{正常樣貌}}` |

> 〔模板說明〕一列一個可機械比對的檢查：指令必須唯讀，「正常樣貌」要寫成看得出對錯的具體字樣（✗「看起來正常」✓「使用率 < 80%」）。列多到需要分區時才升成資料夾型（照 [STRUCTURE](../STRUCTURE.md)）。

## 交接

- 有異常 → [incident](incident.md)。
- 需要使用者親自登入 / 授權才看得到的項目 → [WAIT_USER](../WAIT_USER.md) 一行。
