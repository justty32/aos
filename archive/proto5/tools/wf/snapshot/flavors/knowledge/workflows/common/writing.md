# writing — 寫作風格（產出給人讀的文字時共用）

[common/README](README.md)｜[INDEX](../../INDEX.md)

README、設計說明、commit 訊息、PR 描述、對外文案——動筆前過一遍這裡。管的是**怎麼寫**，不是**做什麼**。被動參考：寫散文才取用，不是 always-on。

> 〔模板說明〕本檔是文風骨架。參考聲音、AI 味表、標點條款都是**可替換的範例**，換成你自己欣賞的文風與語言慣例（參考聲音可以寫人名，也可以只寫特徵）。填完 `{{}}` 後刪除本段。

先判斷在寫哪一種模式，再照那組規則走。

## 模式一：敘事／概念

**何時用**：README 開頭、設計理念、回顧、任何要「讓人想讀下去」的段落。
**參考聲音**：{{你欣賞的散文寫法；寫不出人名就寫特徵，如 長短句交錯、少形容詞、不用結論式收尾}}
**語氣**：有想法但不故作高深；反思而不空泛；短句不堆砌。

## 模式二：技術

**何時用**：API 文件、規則說明、相容性表、實作註記、教學。
**參考聲音**：{{你讀過最好懂的說明文寫法；寫不出人名就寫特徵，如 平時簡潔直接，遇到容易搞混處先點破「你為什麼會混淆」，再用一個具體例子把讀者帶出來}}
**語氣**：一句一個資訊，先結論再理由。難點才多花力氣拆解，平時不囉嗦。

## 別寫成這樣（AI 味）

| 詞／句型 | 為什麼壞 | 替換 |
|---------|---------|------|
| 值得一提的是 / 眾所周知 / 隨著…的發展 | 開場套話，零資訊 | 刪掉，直接講那件事 |
| 總而言之 / 綜上所述 / 未來可期 | 收尾套話，讀者已經看完了 | 刪掉，或給一個具體下一步 |
| 不僅…更… / 它不只是 X，它是 Y | 拿排比灌情緒 | 拆成兩個直述句 |
| 每段都「首先、其次、最後」 | 三段式強迫症 | 真有先後才編號 |
| 賦能 / 打造 / 深耕 / 生態 / 閉環 / 抓手 / 顆粒度 / 對齊 | 商業黑話，指涉不明 | 用平常話說到底做了什麼 |
| 在一定程度上 / 某種意義上 / 可以說 | 過度 hedging，把話講糊 | 講實；不確定就說清楚不確定在哪 |
| 用破折號／冒號製造停頓感 | 標點當戲劇效果，最像 LLM | 一個句號或逗號就夠 |
| 每個名詞都粗體、整篇 bullet、灑 emoji | 格式雜訊，強調失效 | 省著用才有力 |

產文後自檢一行：

```
grep -nE '值得一提|眾所周知|總而言之|賦能|抓手|閉環' <檔>
```

## 別寫成這樣（AI 腔）

上面那張表抓詞，這張抓**句型**——換了詞照樣是 AI 腔：

| 句型 | 為什麼壞 | 替換 |
|------|---------|------|
| 「不是因為 A，是因為 B」／「不是 A……也不是 B……是 C」 | 鋪一輪否定當陪襯，逼讀者陪你繞到答案才出場 | 答案直接講，陪襯的否定句整句刪 |
| 無生命的東西當主詞做人的判斷，如「這份排程浮現出調整空間」 | 做判斷的人被動詞藏起來，責任跟著模糊 | 換成真正做這件事的人或系統當主詞 |
| 懸浮視角，如「沒有人特別規劃過」「一般來說大家會」 | 誰都不是，讀者抓不到你在跟誰說話 | 指名是誰，或直接對讀者講 |
| 段落收在「就是這樣」「僅此而已」式短句 | 用一句短話表演洞見，內容其實撐不起這句 | 刪掉，讓前一句自己收尾 |

## 量化自檢（收尾稿再做，草稿階段不用）

覺得整篇快 AI 味但抓不到哪裡，五項各打 1–10 分：**開門見山**（有沒有繞路才給重點）、**好讀不繞**（句子要不要重讀兩次才懂）、**例子具體**（換個名詞是不是照樣套用在任何主題）、**語氣克制**（有沒有硬凹金句或排比壯膽）、**沒有廢字**（刪掉那句意思會不會少一塊）。總分低於 30／50 就回頭改——照分數低的那幾項對症修，不是整篇重寫。

## 標點與節奏（中文）

- **句長要有變化**，長短交錯才有呼吸。
- **頓號（、）用於並列**，別用逗號代替。
- 中英文之間空不空格，全篇統一。
- 不要把英文 em-dash 的語感直接搬進中文。
- **清單別老是湊三項**：三個例子、三個步驟、三個理由是最容易被認出的固定節奏；該兩項就兩項，該五項就拆開講，別為了湊「三」硬加或硬砍。
