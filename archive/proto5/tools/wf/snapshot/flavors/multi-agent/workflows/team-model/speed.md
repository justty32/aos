# 執行速度、時程與逐模型指揮心得

本頁由 [`../team-model.md`](../team-model.md) 拆出。

## 一、執行速度＝三個因素相乘

使用者有時會要求「幾小時內完成」；排時程時要看**執行速度**，不是只看聰明度。三個因素要**相乘**看，**單看任何一項都會排錯**：

1. **token 產出速度**——通常越聰明產出越慢，但廠商類型也有影響，不能一概而論。
2. **聰明程度＝繞圈數**——笨的要多繞幾圈才完成，聰明的一下子搞定。所以「**產出慢但聰明**」的總時間未必比「產出快但笨」長。
3. **模型癖好**——例如每做一件小事就跑去驗證，硬生生把時間拉長一兩倍。

推論：**「聰明但有壞癖好」的便宜模型，在時程維度會被第 ③ 項吃掉一半優勢**——趕時間的活就改派強模型，或**多開幾條並行、每條範圍切小**。

## 二、逐模型指揮心得

指揮分兩類：**靜態**寫進交接書（範圍用排除法寫死、**驗收條數寫死**，見 [`../dispatch/driving-cli-agents.md`](../dispatch/driving-cli-agents.md)），**動態**是過程中反覆提醒。**交接書擋不住的過程漂移，只能靠動態拉回來。**
