# collide — 材料 × 自家構想的接點筆記

[WORKFLOWS](../WORKFLOWS.md)｜[INDEX](../INDEX.md)

把外部材料對到**自家的構想或另一個專案**：它打到哪一節、有何啟發、是佐證還是打臉。產物是接點筆記，**只留在本庫**。

**何時用**：使用者說「這篇對我的構想有什麼啟發」「拿這批碰撞一下設計」「掃最新的、看有沒有改變判斷的」。
**何時不用**：只要讀懂材料本身 → [source-intake](source-intake.md) 的摘要就夠。跨件找主題全景、不牽涉自家構想 → [survey](survey.md)。要據此拍板改設計 → 接 kernel 的 [planning](planning.md) / [decisions](decisions.md)。

## Done when

- `{{接點筆記目錄，如 collide/}}/<批次或主題>.md` 存在，frontmatter 有 `scope`（掃描範圍、時間窗）與 `note`（證據強度，例：僅摘要層快篩，未通讀全文）。
- 每則接點三件事都在：材料 `[[id]]`＋來源、打到**自家哪一節**、**原文事實與本檔推論分開標示**。
- `{{對照專案路徑}}` 底下沒有新增或修改的檔案（`git -C {{對照專案路徑}} status --porcelain` 無輸出）。

## 流程

1. **圈自家這一側**：是哪份構想的哪幾節（沒有編號就先給它編號），把要被打的點列出來。沒有這一側就不是 collide，是 [survey](survey.md)。
2. **圈材料這一側**：從 `index/` 或某一批 [backlog](backlog.md) 撈；只留**會實際改變既有判斷**的，不因為新就收。
3. **逐則寫接點**，固定三段：
   - **原文事實**：附 `[[id]]` 與來源，數字標「作者自報」。
   - **對本案的推論**：加「（本檔補註，非作者自陳）」——這段是本檔的意見，不是材料作者的。
   - **待實測 / 風險**：要拿什麼最小實驗去驗、作者的前提在本案不成立的地方。
4. **方向要寫全**：佐證、打臉、或補上原本缺的工程層。**打臉的一定要寫進去**，只留佐證等於自我確認。
5. 落檔；`index/` 相關列可補一句「已碰撞：<檔名>」，`logs/<當月>.md` 補一行。

## 產物只留本庫

為別的專案找的材料，**產物一律留在本庫**，不去那個 repo 新增或修改任何檔案。要把結論搬過去是那邊的事，由使用者決定（守鐵律 2：授權來源）。這條讓本庫可以放手掃、放手碰撞而不污染對方。

## 交接

- 碰撞出來的變更要拍板 → kernel 的 [planning](planning.md)（要不要做）／[decisions](decisions.md)（選了哪個、為什麼）。
- 缺的材料 → [backlog](backlog.md) 開一批補掃。
- 要對方 repo 真的改起來 → [WAIT_USER](../WAIT_USER.md) 一行，寫明搬哪幾條過去。
