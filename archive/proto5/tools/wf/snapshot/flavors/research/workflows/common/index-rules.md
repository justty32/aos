# index-rules — 索引真相層的維護規則

[common/README](README.md)

累積型的庫需要一層**索引真相層**：`index/`。「庫裡有什麼、每件做到哪」**只有這裡算數**；摘要、翻譯、綜述、網頁各有職責，但都不回答這個問題。

## 三層各管什麼

| 層 | 誰 | 規矩 |
|----|----|------|
| **索引真相層** | `index/`（＋入口 `index/README.md`）| 一件材料一列，狀態欄即處理進度 |
| **內容真相層** | 摘要 / 翻譯 / 筆記的 `.md` | 內容更新一律**先改這裡** |
| **衍生層** | 網頁、匯出檔、綜述呈現頁 | 由上兩層產生，**可後補**；要改樣式或版面**改產生器、不改產出**——下一次重建會蓋掉手改的檔 |

同一件事不要有兩個真相層：候選池的狀態在 ⬜ 歸零後就凍結，成果只登在 `index/`。

## 維護規則

- **一類一檔**：`index/` 按主題類別分檔，一個類別一個檔、一個職責。
- **每列一件**，欄位固定（例：`id | 題名 | 狀態 | 產物落點`）。不同型態的條目（沒有 id 的訪談、內部文件）**另開一檔**，否則「每列一件 X」這條不變式就破了。
- **狀態圖例全庫一套**，寫在 `index/README.md` 與各檔 frontmatter：`⬜ 待處理`／`🔶 部分完成`／`✅ 完成`。
- **不按 bytes 硬切**：單檔超過 8192 bytes 是「該檢視」的訊號、不是硬上限。類別本質不可分就留著；能按子主題再分才分（分出 `index/<類>/` 並加一個 README）。
- **新增一件加在所屬類別檔的表尾**，同步更新 `index/README.md` 的件數。
- 索引是**單一寫入者**的地盤：多線／多 agent 同時作業時，只有調度者能改 `index/`，其他線唯讀。
