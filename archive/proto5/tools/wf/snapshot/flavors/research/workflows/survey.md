# survey — 跨件主題綜述

[WORKFLOWS](../WORKFLOWS.md)｜[INDEX](../INDEX.md)

把庫裡同一主題的若干件材料整合成一張全景圖：誰佐證誰、誰打臉誰、共通難題與缺口在哪。產物是綜述檔，每個結論都能用 `[[id]]` 回到內容真相層。

**何時用**：庫裡某主題累到夠多，使用者說「做個跨篇綜述」「這個主題現在長怎樣」。
**何時不用**：只處理一件材料 → [source-intake](source-intake.md)。材料還沒入庫 → 先入庫再回來。要對到自家構想 → [collide](collide.md)。庫外的一次性材料讀完即止 → knowledge 包的 digest。

## Done when

- `{{綜述目錄，如 surveys/}}/<主題>.md` 存在，frontmatter 的 `covers:` 一件一行列出涵蓋範圍。
- 每個結論後面有 `[[id]]`，沒有無出處的斷言。
- `index/` 相關列已補上指向這份綜述。
- `logs/<當月>.md` 多一行。

## 流程

1. **圈範圍**：從 `index/` 撈相關篇目列成清單，寫進 `covers:`。範圍由主題決定，不由「順手讀到哪」決定。
2. **讀各件的摘要**；結論有疑義時回頭讀翻譯或原文。**不採信二手轉述**，原始來源與摘要衝突時以原始來源為準。
3. **找咬合與矛盾**：誰佐證誰、誰打臉誰、大家共同卡在哪、沒人做的是什麼。**這是綜述的價值，把每件摘要串接起來不算完成。**
4. **三類寫法分清楚**，每則都標明是哪一類：
   - **原文事實**：附 `[[id]]`，數字標「作者自報」。
   - **本檔推論**：加「（本檔補註，非作者自陳）」。
   - **尚待實測的假設**：明寫還沒驗證，別寫成結論。
5. 落檔，每個結論標 `[[id]]`；回頭在 `index/` 相關列補指向，`logs/` 補一句。

## 綜述是呈現層

內容真相層仍是各件的摘要與翻譯，綜述只做地圖（原則見 [common/index-rules](common/index-rules.md)）。所以綜述可以重寫、可以整份取代，不會弄丟事實。

## 分檔慣例

- 撐大了照 [STRUCTURE](../STRUCTURE.md) 按**章節語意**分檔：正文分進**同名資料夾** `<主題>/` 的 `01_….md`、`02_….md`，母檔保留原檔名當**章節目錄**。同名的 `.md` 與資料夾並存是正常型態，不是重複。
- **看正文結構、不看檔案大小**：母檔的 `covers:` 一件一行，覆蓋面廣時光這份清單就上萬 bytes，正文其實只有簡介＋章節連結。判斷該不該重整看正文，別看 bytes。

## 交接

- 綜述指出的缺口要去補材料 → [backlog](backlog.md) 開一批。
- 結論會改變自家構想 → [collide](collide.md)；要據此決定做不做 → kernel 的 [planning](planning.md) / [decisions](decisions.md)。
- 綜述寫到一半停手 → [SESSION-LOG](../SESSION-LOG.md) 一行寫清楚讀到哪幾件。
