**逐段操作與故障結果**

「照抄」僅依指定環境替換 PATH、工作目錄；背景 daemon 採 README 提供的 `setsid`，部分等待明寫 60 秒。

- **README 1：通過。** daemon boot／halt 正常，跨工具 shell 存活。
- **README 2：通過。** `init --target K --config FILE` 成功，初次 boot 印 `booted 4 cpus`。check 不帶 probe 明寫「未測模型連線」；帶 probe 確實連至 LiteLLM。
- **README 3：通過。** once 回音 code 0，stdout 在 `once.out`；count 最終 `done runs 3`。
- **README 4：通過。** init、check、start、say 與 date 工具問答完成。listen 預設／last、wait、follow 都測過；wait 無新回話退 101，follow 收到新回話。工具中途的 last 有「還在處理中」提示。
- **README 5：通過。** agent → kernel → daemon 正常停機。一次一般 halt 約 1.07 秒，返回時 daemon 孩子表為空；`--no-wait` 約 0.03 秒返回。
- **每天重開機：通過。** 測過先 stop agent，以及保留登記兩種情況；後者三個 start 都印 `already started`、退 0，重開後仍能聊天。
- **README 6：通過。** add 工具實際算出 5555；另寫 `list_folder`，模型實際呼叫並正確報出 `apple.txt`、`banana.csv`，共兩個檔案。
- **手動建家附錄：完成。** 原子投入 `input.json` 可運作。首次等待與我的斷線測試重疊，20 秒只見中間工具訊息；修復、continue 後完成，再次問時間亦成功。
- **`aos-llm call`：通過。** 設定 `AOS_LLM_CONFIG` 後取得 assistant JSON，退 0。

三個 init 生出的 agent 分別使用時間管家、系統老師、資料夾管理員人格，以及 date、uname、pwd 工具；修正一次工具重名後，完成輪流各三句，混用等待與不等待。記憶能回答使用者叫「小林」、慣用「文字檔」。

其他必測項目：

- daemon／kernel 的目前目錄、環境變數、明寫 target 三種來源，故意給壞家時，錯誤尾巴均標明家與來源。agent 全程明寫 target。
- 未 start 的 agent：普通 say 退 0；say --wait 立即退 101；兩句均在 input，之後 start 可處理。
- agent 家重複 init：拒絕、退 1。status 指到 kernel 家：清楚說不是 agent，退 1。
- **非空普通資料夾的 kernel init：不符合預期。** 帶 config 直接成功、退 0；原檔案仍在。加 `--force` 則報 unrecognized arguments、退 2。
- 壞 port 下 probe 立即 bad。用臨時 HTTP 模型清單製造缺少指定模型的情境，probe 只 warn、退 0。
- 兩個 agent 同時遇到壞 port：status 與 ls 觀察到 **重試 1/3 → 2/3 → 連敗暫停 → continue／continue --all → 已解除暫停，等下一次成功 → ok**；舊錯另標「已恢復」。
- 另測只失敗一次就改回 port，重試能自行回 ok。
- llm cpu 閒置、工作中各 kill -9 一次；兩次均看到「恢復中（llm cpu dead，daemon 重拉中）」後自行回 ok。工作中那次經過 Interrupted、重試，最終仍取得答案。
- 搬走 `K/requests/`：ls／status 指出缺目錄；say --wait 收件後立即退 101，明說不要重送。搬回後繼續處理。
- pause 中兩種 say 都收件並提示 continue 後處理；帶 wait 退 101。continue 後確實回出測試文字「紫色鳳梨」。

**卡住的地方**

1. **本輪指定的 kernel init／force 行為**：以為非空資料夾必須明確允許才初始化；實際直接成功，force 根本不被辨識。這是功能落差，不是等待問題。（調度者按：任務書把 `--force` 誤植給 `aos-kernel init`，實際規範與實作都只在 `aos-agent init`；kernel init 本來就沒有非空保護，不是這輪 fix-r5 沒做到。）
2. **README 第 4 段接 `spec/agent/info.md` 工具範例**：我新增 `base.json` 的 date，以為是設定該工具；實際 init 已有 `date.json`，資料夾合併後重名。錯誤很清楚，但需要先知道預設檔名。
3. **README 的 continue 恢復說明**：工具重名累積成 kernel bad 後，我試 continue，以為能恢復；實際回「沒有在暫停」，最後 stop／start 才恢復。這與模型連敗暫停是不同層次。
4. **README 手動附錄 `sleep 20`**：直覺上像能接著讀最終答案；實際固定等待不足以保證完成。這次另受我注入的故障影響，不能算單純效能失敗。
