# 市場層第一次真跑：兩家公司、同一張單、走一輪

2026-09-25 13:47～14:05，經理人辦公室的執行員。目的：市場層原本只用假帳本測過，這次兩家真的做同一張單，再照規則走一輪 `score → rank → bankrupt → grant → pool`；順便把研發部剛改的「一家一個 daemon」真開機驗一次。

實例全在 `~/tmp/company-market/`（留給董事看）：`c1/`、`c2/` 兩家，`cost/` 帳本與帳戶，`market.json` 市場，`runs/` 跑完存的紀錄（董事收件匣、各部門信、總機單、帳本分組、品質分的原始檔）。模型只走 LiteLLM `localhost:4000`。真的叫模型的單：**2 張**（一家一張，兩家同時跑）。

## 5. 發現的問題（只記；本輪沒改程式）

沒有一條是「不修就跑不完」，所以一行程式都沒改、全套測試不用跑。

| # | 類 | 問題 | 建議 |
|---|---|---|---|
| 1 | 規則 | **品質分讀不懂證據代號**：c1 的證據檔寫「行號依據 A 檔 `…奇石.md`」再用「A L30-L37」，evidence_check 找不到檔名，8 列全算壞，品質從 93.75 掉到 50。品管部 lessons 19 講過同一件事（格式一放鬆機械檢查就全瞎），市場層直接吃這個數就會賞罰顛倒 | 二選一：證據格式在寫手的工作流寫死「每列寫完整檔名」、驗收加一條機械檢查；或 evidence_check 認「X 檔」代號。在修好前，經理人 `score` 前先看 evidence_check 的 `by_status`，有「無檔名」就別直接用 |
| 2 | 規則 | **做壞的單照樣拿滿分品質**：c2 的總機單 failed、總裁報 FAILED，但品質是看檔案本身（檔案在、證據列對得上）＝100，排名分 60，撥到 42％。`min_quality` 擋不到，因為品質是 100 | 品質只算「這輪結案（done）」的交件；或加參數 `min_done`（這輪至少結一張單才撥）。這題要董事拍：失敗的公司這輪該拿 0，還是保底一點 |
| 3 | bug（規則） | **沒打分也照發**：撥完第 1 輪後，我什麼都沒做直接 `grant --dry-run`，第 2 輪照樣把 5000 萬整份照 58／42 分出去（兩家排名分都 0，同分照名字排，c1 永遠第一）。手滑多跑一次 `grant` 就多發一輪 | 這輪一家都沒 `score`（或排名分全 0）時 `grant` 拒絕；同分的平分，不照名字 |
| 4 | 規則 | **「快」量的不是董事等了多久**：它算這家公司總機單（部門之間每一跳）的平均。c1 董事實際等 401 秒，市場記 182 秒（兩張總機單平均）；製造那張 343 秒、品管那張 21 秒——多派一張短單反而把平均拉快 | 改成董事的單（`company.py order`）從下單到總裁結案信的秒數 |
| 5 | 規則 | **「省」在一家失敗時不比**：c1 花了 c2 的 6.6 倍 token，省＝100；因為 c2 沒結單＝0。這次這樣算沒錯（失敗的不該算省），但要注意這一輪的「省」其實沒比出什麼 | 不動；兩家都結單時才有意義 |
| 6 | 樣板 | 製造部門房「補人物 X（只寫詞條）」寫死「讀 `aos-drafts/X/` 的草稿」，事實欄也指那裡。這次草稿不在，兩家寫手照樣從原文寫，沒卡住；但總裁的結案信寫「已依草稿與證據寫成」，不是事實 | 門房規則加「草稿不在就從原文寫」；或拆兩條規則（已修，見 commit） |
| 7 | 小事 | `aos-team hr cap` 不帶 `AOS_KERNEL_HOME` 會說找不到 HR 家；公司的 README 沒寫 | README 補一行（已修，見 commit） |

## 6. 給經理人：這一輪要不要真的發額度

**建議先不要照這套規則發真的額度**，理由三條：

1. 品質分會顛倒（第 1 條）：不看一眼就用 `--eval` 的話，這輪會是「做壞的拿滿分」。
2. 失敗的公司也分到四成（第 2 條）：跟「做得好的多拿」的本意不合。
3. `grant` 多跑一次就多發一輪（第 3 條）：真錢的時候這是最容易出事的一條。

要發的話：每輪只由經理人手動 `score --quality`（先看 evidence_check 的 `by_status`），`grant` 前一定先 `--dry-run`，失敗的公司用 `--tokens c2=0` 覆寫成 0。等研發部修掉第 2、3 條再照公式發。
另外，一張「補人物」的成本兩家差 6.6 倍（595 萬 vs 90 萬 token），開辦費 2500 萬 token 對 deepseek 寫手大約是 4 張、對 gpt-5.5 寫手約 27 張；總量 `total` 還是等董事給數（報告第 2、14 題）。
