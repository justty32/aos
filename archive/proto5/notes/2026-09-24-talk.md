# 2026-09-24 talk：`aos-agent talk`（極簡來回對話）

← [notes 索引](README.md)｜規範：[aos-agent §1.8 cli-talk-repl.md](../spec/aos-agent/cli-talk-repl.md)｜實作：[lib/aos_agent_talk.py](../lib/aos_agent_talk.py)

使用者原話：「來一個 `aos-agent talk` 指令。這就只是來回 say/listen，類似 repl。……極簡版，ctrl+c 就退出那種。啊，要加一些 slash command，比如 /status、/context 之類，看著加上。相關 flag 你也自己看著辦。」

## 做了什麼

```
aos-agent talk [--target DIR] [--wait 秒] [--show-calls]
```

- 打一行 → 投進 `input` → 等**這一句**的回話 → 印出來 → 再打下一行。只用標準庫（`input()`，有 readline 就載入）。
- `--wait 秒`：每句最多等幾秒，預設 120（人坐在前面等，比 `say --wait` 的 300 短）；`0`＝送出就回提示符。
- `--show-calls`：多印工具的簡化行 `[呼叫 date]`、`[結果 ok 1 行]`（失敗是 `[結果 失敗 工具 date 失敗（exit 1）：…]`）。
- slash 指令（提示符打 `/` 開頭，**不送給模型**）：

| 指令 | 做什麼 |
|---|---|
| `/status [-v]` | 狀態一行；`-v` 印整段 status |
| `/context [N]` | 每次問模型送出的東西：模型代號、system 字數、記憶幾則幾字、工具幾個，加最近 N 則 |
| `/history [N]` | 記憶最後 N 則（預設 10） |
| `/tools` | 列出工具 |
| `/wait [秒]` | 上一句逾時了，再等一次 |
| `/pause`、`/continue` | 同 `aos-agent pause`／`continue` |
| `/help`、`/quit`（`/exit`） | 指令表；離開 |

  不認得的 `/xxx`＝「沒有這個指令，/help 看清單」，不送。要把 `/` 開頭的字送給模型就打兩個：`//status 是什麼`。
- Ctrl-C（任何時候）、Ctrl-D、`/quit` 都退 0。還有一句沒回的話，離開時提醒「回話會進記憶，之後 `listen --last` 看」。
- stdout 只有回話和 slash 指令的輸出；提示符、等待提示、逾時、卡住的原因都在 stderr（試玩 r5 的痛點：`say --wait` 失敗會把整段 status 混進 stdout，talk 不會）。

**`listen --wait` 那個坑怎麼避開**：talk 在**送出之前**記下記憶長度，等的是「那之後、而且含我這句的那一輪」走完。回話就算在開始等之前就寫進記憶了，也照樣算數、照樣印（測試 `test_reply_before_wait_starts_is_not_lost`）。
另外記一個「印到哪」的位置，新訊息到一則印一則，印過的不再印；逾時之後晚到的回話，下次按 Enter（或送下一句、或 `/wait`）時補印。
逾時訊息不叫人用 `listen --wait`（它會踩坑），改成「/wait 再等；按 Enter 看到了沒；離開後 `listen --last` 也看得到」。

**跟任務書不一樣的一處**：規範檔名。`spec/aos-agent/cli-talk.md` 早就是 §1.2 `say`／§1.5 `listen`，所以 talk 另開 `cli-talk-repl.md`（§1.8）。

## astra 唯讀審查

[任務書](2026-09-24-talk-review-task.md)、[審查](2026-09-24-talk-review-astra.md)。必修 12 條：**修了 11 條**，第 12 條不歸這一隊。

1. 同一句連送兩次，第一句的回話可能被當成第二句的；單一檔輸入被別人再投時會卡住 → 改成認「我投的那份」（inode），而且照 §8 的順序**先看檔、再讀 state、最後讀記憶**。
2. 投完了但還沒記下「在等」時按 Ctrl-C，不會提醒 → 投檔＋記下包成一組，Ctrl-C 等這組做完才生效。
3. 剛進入時（banner）按 Ctrl-C 會印 traceback → 整段都包進同一個 Ctrl-C 出口，退 0。
4. `/pause`、`/continue` 中途 Ctrl-C 會留半截 → 同樣包成一組做完。
5. 提示符寫進 stdout（`talk > 紀錄.txt` 會混進 `> `）；stdin 是管線但 stderr 是終端時還是印等待提示 → stdout 不是終端時提示符寫 stderr；等待提示要 stdin 與 stderr 都是終端。
6. 回話在打字時才到，離開時還說「還沒回」 → 離開前再看一次，先補印。
7. 記憶讀壞時停止原因也看不到，會乾等到逾時 → 兩件事分開看。
8. `/quit now`、`/pause x` 這種不驗參數 → 驗了，錯就 Usage、不執行。
9. 工具失敗可能被印成 `[結果 ok]`（名稱表只從印過的呼叫來）→ 只看字串開頭判失敗。
10. 幾個格式不照規範（`/context` 沒整行截、參數空白被折疊、失敗第一行被截、`/status` state 讀不到少欄位）→ 照規範改。
11. 記憶被改短之後，那一句永遠等不到 → 短到比送出時還短就放掉，並說「記憶被改短了，追不到剛才那句」。
12. **`proto5/README.md` 第 69、115、143、147 行還寫著 `aos-kernel check --agent`**（advice-r1 已把它改成用法錯 2）→ 這是 main 上本來就有的錯，不是這一輪改的；任務書說不碰 README，**交給正在拆 README 的那一隊**。

建議兩條（補測情境、每 200 ms 重讀多份檔）：補測挑了必修相關的 8 條；重讀的成本沒動（等回話時每 200 ms 讀一次 info＋記憶＋state，跟 `say --wait` 一樣）。

## 保證外（規範裡也寫了）

- 同一個家開兩個 talk、或 talk 開著時旁邊有人 `say`：「這句回完沒」的判法不受影響，但「印到哪」之後的回話都會印，所以可能看到別人那句的回話。
- 回話在你打字的時候到了，要等你按 Enter 才印（不打斷正在打的那行）。
