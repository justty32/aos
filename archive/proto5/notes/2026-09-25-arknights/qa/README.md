## 4. 結論

- **強模型寫出來的兩份，內容品質到了標準答案那級**：評審沒找到編造、邊界（未知、同名切割、「擋刀」沒有原文）都有交代。
- **但流程不穩**：四人裡兩人沒有可驗的交件（一個快照漏存、一個團隊停擺）。品質上限沒問題，問題在「跑完、存好」。
- **格式要管**：老薑那種「A/B/C 代號」讓機械檢查全瞎。done_when 應該加一條「每列都寫出處檔名」，或者寫手人格明講不准用代號。

## 5. 留下一輪

- **評分器的洞（沒改程式，只記下）**：
  1. 證據檢查器不認「表格上方先定義代號、列裡只寫代號」的寫法，全判「無檔名」；評審的原文摘錄也因此拿不到那幾列（`judge.source_excerpt` 靠同一個解析）。
  2. 檔名前面緊貼中文（沒有空白或反引號）時，檔名會連前面的字一起吃進去，判「檔不存在」。
  3. `eval_run.py` 只收 golden 裡的批號，評不了新人；這次用包裝腳本繞過。要評新人，評審的「參照」該怎麼定（草稿？不給？）要你拍。
  4. 證據列沒有「」引文時，只驗行號沒超界，等於沒驗內容（評分器 README §9 已提）。
- **量測的洞**：`aos-team score --task` 在多張單並行時照時間窗算，每張單都算成整隊；要照 assignee＋單子期間切才對。
- **批次停擺原因沒查**：11:34 起寫手、審查員都沒再叫模型；老木頭的審查單、老財的寫作單都停在 working。hops 裡每個成員都有 4～5 次「退 102 → 300 秒後再派」。
- 老財跑完、老木頭審完之後，照 [workflows/score-new-entries.md](../../../playbook/workflows/score-new-entries.md) 再評一次（每人 1 次評審）。
