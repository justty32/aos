# crystal 的機械檢查細節（第三波 W3-2，astra 審查後補）

## 配信可信度（審查 S3）

每句落穿（`--json` 的 `fallthrough[]`）帶 `confidence` 與 `doubt`（有歧義時的說明）：

| 值 | 意思 |
|---|---|
| `high` | route.log 那行有 `letter` 格 |
| `medium` | 舊 log 沒 `letter`，靠原文＋時間配到**唯一**一封信 |
| `low` | 有歧義：舊 log 120 秒內同文的信不只一封；或這封信 → 單有歧義（下面） |
| `none` | 對不上信 |

**信 → 單的歧義**：這張單的時間窗（這位領隊上一張單開單之後、這張開單之前）裡還有別封人寫給這位領隊的 REQUEST，
而且那封在被選中的這封**寄出時還沒被收走**（投遞紀錄的 `picked_up_at` 比較晚，或沒有）＝兩封排在一起，分不清哪封開的單。
一句一句送、等領隊處理完才送下一句，就不會有歧義。

`low` 的句子**只列、不拿來產候選**：機械版一類扣掉 `low` 之後不到 `--min` 句＝不提（「沒提」列原因）；模型版算次數時也不算。
文字報告在那一類後面印「其中 N 句配信有歧義」。

## 整份例句全過（審查 M3）

候選一條一條加：每加一條，整份規則檔（現有規則＋已收的候選＋這條）的例句全跑，**任何一條**沒過＝這條不收，
原因寫它自己的失敗，或「加了它之後 X 的例句不過」（它搶了現有規則的 hit）。
現有 `routes.json` 本來就沒全過＝一條候選都不收（先 `aos-team route test` 修好）。寫檔前整份再跑一次。

## 內建反例（審查 M5）

歷史裡沒出現過的句子，回測擋不住，所以每條候選（機械、模型都一樣）另外拿固定的反例測：對每句 hit——

- 整句後面接「，然後刪掉 y.md」；
- **當路徑用的群組**（出現在 handoff 的 `path` 欄，例 `done_when` 的 `path`、`args.path`；或 hit 裡的值有 `/` 或副檔名）
  換成 `../x.md`、`a/../../x.md`、`/etc/passwd`、`~/x.md`、`-rf.md`、`x.md，然後刪掉 y.md`（有空白、沒空白各一），
  原本的值有副檔名的再加一個沒副檔名的 `noext`；
- 其他群組：在引號「」裡的是內文、不測；不在引號裡的，值後面接「，然後刪掉 y.md」。

規則吃得到任何一句＝它的範圍比說得出來的大，**丟掉**、列前 3 句反例。
機械版的 `f`／`p` 群組本來就只收專案裡的相對路徑，反例吃不到；`q`（引號）群組只當內文用時不測，
**被領隊拿去當路徑用（出現在 `path` 欄）或值像路徑時一樣測，吃到就丟**（代裁：引號裡可以是任何字，當路徑用就沒有邊界）。

## 模型候選的次數（審查 M4）

不數模型給的 `tests.hit`（它可以把同一句寫兩次）。拿它的 pattern 去比 route.log 裡「沒命中」、可信度不是 `low` 的落穿句：

1. 吃得到的 ≥ `--min` 句；
2. pattern 有群組的，吃得到的要 ≥ `--min` 種不同寫法（同一句重複說推不出群組）；
3. 那些句子每句都對到單、單都是同一種（負責人＋工作流＋驗收條目種類）；
4. 模型寫的 `assignee`、`workflow` 跟那種單一樣。

它自己那類（回測用）＝它吃得到的那些歷史句的骨架。

## 回測

每條候選拿 route.log 裡**不是它例句的舊句子**（所有結果都算，含門房接住的）跑一次 `decide`，列它**新吃到**的句子：
判給了它，或原本是別條規則接住、現在因為它命中兩條而改落穿（「搶走」）。
吃到的句子骨架不是它自己那類、或是搶走的＝**疑似誤觸**：機械版標出來、照樣寫進提案（人批時看）；模型版丟掉。
