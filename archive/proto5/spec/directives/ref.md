## 3.2 `$ref` + `$at`：讀另一份 JSON 的某個位置

`$ref` 決定讀**哪份檔案**（或不讀檔案，就用目前這份），`$at` 決定要文件裡的**哪個位置**：

```json
{"$ref": "a.json"}                       整份 a.json
{"$ref": "a.json", "$at": "/x/y/0"}      a.json 裡的 /x/y/0（開頭 / ＝從那份文件的根算）
{"$ref": "",       "$at": "/envs/PATH"}  $ref 空字串＝「這個值所在的那份檔案」自己
{"$ref": "",       "$at": "./a", "a": true}   ./ ＝這個指示詞物件自己的位置 → 它的 key a → true
{"$ref": "",       "$at": "../GREET"}    ../ ＝往上一層（兄弟 key）
```

**`$ref`：找哪份檔案**

- `$ref` 的值一定是字串（不是 → `DirectiveValueTypeMismatch`）。
- 非空字串：當**檔名**看。相對路徑相對於**「中心路徑」**去找檔案；中心路徑是什麼由**宿主
  規範決定**（例如 inst 是解出來的 `cwd`，不是這份指示詞所在的檔案）。絕對路徑照字面用。
- **空字串 `""`**：特指「**目前正在解析的這份文件**」——可能是頂層 inst.json 本身，也可能是
  透過某個 `$ref` 取進來、這個值目前所在的那份檔（見「目前文件／目前位置」）。
- **`$ref` 字串也可以自己帶 `#位置`**，等同另外寫一個 `$at`：

  ```json
  {"$ref": "main.json#/a/b"}        ＝ {"$ref": "main.json", "$at": "/a/b"}
  {"$ref": "main.json#./a/b"}       別的檔的「目前位置」＝它的根，所以 ＝ /a/b
  {"$ref": "#../GREET"}             檔案空＝目前文件，從目前位置往上
  {"$ref": "", "$at": "../GREET"}   同上
  ```

  `$ref` 字串以**第一個 `#`** 切開：前面當檔案（空字串＝目前文件），後面當位置字串，語法
  跟 `$at` 完全一樣；沒有 `#` ＝整份文件。代價：檔名裡真的含 `#` 的檔沒辦法用 `$ref` 指到。
  `$at` key 跟字串裡的 `#位置` **同時出現時，`$at` 贏**，字串裡 `#` 後面那段整段忽略。

**`$at`：文件裡的哪個位置**

- `$at` 可省——省了＝整份文件；有寫必須是字串（不是 → `DirectiveValueTypeMismatch`）。
- 用 `/` 分段解讀：
  - 整個 `$at` 以 `/` 開頭 ＝**絕對**，從「`$ref` 指到的那份文件」的根算起（例如 `/x/y/0`）。
  - 整個 `$at` 第一段是 `.` 或 `..`（也就是以 `./` 或 `../` 開頭，或整串就是 `.`／`..`）＝
    **相對於「目前位置」**，不分 `$ref` 指的是目前文件還是別的檔，統一這樣算：
    - `$ref` 指**目前文件**（`$ref:""`）——目前位置＝這個指示詞物件自己在文件裡的位置；
    - `$ref` 指**別的檔**（非空字串）——目前位置＝那份檔的**根**（`/`）。
    所以 `x.json#./a` ＝ `/a`；`x.json#../a` 從根再往上爬，爬過根 → `ReferencePointerInvalid`。
  - 之後每一段：`.` 段＝略過（留在原地）、`..` 段＝往上一層（回到父層，也就是兄弟 key／元素
    那一層），爬過文件的根 → `ReferencePointerInvalid`。
  - 其餘段是實際要走的 key 或索引：`~1` 還原成 `/`、`~0` 還原成 `~`；物件用 key 對應、陣列用
    十進位索引；走不到 → `ReferencePointerInvalid`。
  - 不是以 `/`、`.`、`..` 開頭的 `$at`（例如 `"x/y"`）→ `ReferencePointerInvalid`。
  - 單獨一個 `.`（$at 整串就是 `"."`）＝目前位置本身，不移動——常拿來測循環，見第 5 節。

**目前文件／目前位置，以及取值後怎麼繼續解**

- 頂層 inst.json（或任何宿主文件）一開始，「目前文件」就是它自己、「目前位置」是根 `/`。
- **「位置」一律是原始 JSON 裡的實體路徑**，連 `$fmt`、`$val`、`$opt` 這些指示詞自己的 key
  都算一段，不會被跳過：`argv` 第一個元素是 `/argv/0`；`envs.PATH` 若是一般字串就是
  `/envs/PATH`，若是 `$fmt` 物件，變數 `p` 的位置是 `/envs/PATH/$fmt/p`、模板本身
  （`$val`）的位置是 `/envs/PATH/$fmt/$val`；一個選項物件的值位置是（例如）`/stdout/$val`。
  這樣 `$fmt` 的變數之間才能互相指來指去，例如 `"b": {"$ref": "", "$at": "../a"}` 從
  `/envs/PATH/$fmt/b` 往上一層就到 `/envs/PATH/$fmt/a`。
- `$at` 的空段（例如整段 `"/"`、或 `./` 結尾留下的那個空字串）照 RFC 6901 當 key `""`，
  不會被略過。
- 取回來的值**原樣**放進那一格——字串、陣列、物件都可能，型別由那一格自己驗（第 2 節）。
- 取回來的東西如果又是指示詞，繼續解時「目前文件」換成剛剛被 `$ref` 指到的那份檔、「目前
  位置」換成剛剛取到的位置。所以解析器要一路帶著「(目前文件的 realpath，目前文件的根物件，
  目前位置的 pointer)」這三樣往下傳，`$ref:""`／相對 `$at` 才有東西可以比對。
