# 共通踩坑（跨工作流）

[common/README](README.md)

不專屬任一工作流的坑記 / 查這裡；工作流專屬的坑記在該工作流自己的 `gotchas.md`（長出來後在下表加一列導流）。

**何時用**：使用者說「記個踩坑」「上次也是這樣」；或動手前要查這個現象以前撞過沒。
**何時不用**：坑專屬某個工作流、而那個工作流已有自己的 `gotchas.md` → 記在那裡；**只撞過一次**的意外 → 不記（門檻是第二次撞到）。

## Done when

- 下表對應的檔多一條坑（粗體標題＋一兩句現象與對策），或查到既有條目並照它處理。

## gapA3（chatgpt-gpt-6-sol-high）
- 下次寫唯讀 aos 工具前，先隔離既有寫入、復原與鎖路徑；輸入目錄可能唯讀，檔案位元組、權限和時間戳都不能變。
- 解析 jsonl 要用 b'\n' 切位元組：缺尾換行先判 torn；別用 splitlines 誤切 CR，也要拒絕 NaN、Infinity。
- Python 的 bool 是 int 子類；驗 seq、next_seq、acked_upto 要用 type(x) is int，不能靠 isinstance(x, int)。
- 壞紀錄不能進彙總；count 要包含重複紀錄，dup 列重複序號，unacked 則只數不同的有效序號。
- 狀態檔只讀必要欄位；整份無效才讓兩頻道狀態皆為 null，單頻道無效只影響自己，壞 state 只記一筆。
- CLI 要先守住錯路徑 exit 2 且 stdout 為空、成功恰一行 JSON；排序、null 和整數型別都是輸出契約。
- 驗收別只跑單元測試，還要做獨立唯讀核對：`python3 proto7-2/tests/run_all.py packs/evgap/tests`、`python3 check_answer.py <proto7-2> fixture`；以後交接書該點名的工具

## runsA3（chatgpt-gpt-6-sol-high）
- 下次寫 aos 工具前要知道：Python 3.11+ 的整數字串長度限制會讓合法的超長 last_code 在解析或輸出 JSON 時失敗；要測 4301 位數字仍能保留該列。
- 時區時間運算不能只看最終結果是否合法：先在原時區加秒數，或先轉 UTC，都可能在年份上下界溢位；要測中間越界、最終可表示的案例。
- 驗收 runs 工具要跑 `python3 proto7-2/tests/run_all.py packs/runs/tests` 和 `python3 check_answer.py <proto7-2> fixture`；以後交接書該點名的工具

## auditA3（chatgpt-gpt-6-sol-high）
- 下次寫 aos 工具前要先知道：只掃非點開頭信箱的 inbox/*.md 與 inbox/done/*.md；檔案也須是非點開頭、非符號連結的普通檔，不遞迴。
- 下次寫 aos 工具前要先知道：frontmatter 的界線必須是整行 ---，欄位只按第一個「: 」切開；值不去空白，重複鍵取最後一筆。
- 下次寫 aos 工具前要先知道：壞信件只記最先適用的原因，依序是 no_frontmatter、no_field、bad_name、dup_id；重複 id 由相對路徑字典序最前的有效信件取得。
- 下次寫 aos 工具前要先知道：REQUEST 是否未結案要跨所有有效信件查 re；只有 DONE、BLOCKED、NEEDS-USER、FAILED 能結案，PROGRESS 不能。
- 下次寫 aos 工具前要先知道：信箱即使沒有有效信件也要列入 boxes；done 計全部有效歸檔信件，inbox 只列實際出現的狀態。
- 下次寫 aos 工具前要先知道：資料裡無時區的 at 要套用 --now.tzinfo；分鐘差向下取整，未來時間可為負數，不能截成零。
- 下次寫 aos 工具前要先知道：驗收 mailtodo 除實質測試，還要跑 `python3 check_answer.py <proto7-2> fixture` 核對唯讀與固定答案；以後交接書該點名的工具。
