## 踩過的坑
- 候選 JSON 後面多出交付欄位 → 先確認最外層 JSON 結構恰好符合要求，避免把欄位放在錯誤層級或留下多餘文字。
- 僅憑測試程式碼推定測試會通過 → 執行指定 runner，依實際失敗輸出修正，再重跑確認。
- 測試只驗證一般情境 → 加入會區分排序、驗證優先序及重複資料處理的案例，並逐項核對預期結果。
- 入口檔超出行數限制或承載過多邏輯 → 入口保持精簡，將實作放在同包模組。
- 測試檔沒有被指定 runner 發現 → 依 runner 的 discover 規則放置測試，使用明確的匯入方式並實際執行。
- README 缺少指定章節 → 使用要求的章節標題，並提供可直接執行的示例。
- 索引列放進 `files` → 索引列使用頂層 `row` 欄位。
- report 缺少指定結尾 → 交付前確認必需的最後一節存在，且內容以該節結尾。
- 未執行獨立 checker 卻宣稱驗收完成 → 分別執行所有指定驗收命令；未執行的項目如實標示，不宣稱通過。
