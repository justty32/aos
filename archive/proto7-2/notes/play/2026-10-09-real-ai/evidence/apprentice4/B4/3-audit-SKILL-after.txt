## 踩過的坑

- 候選 JSON 多帶索引列、報告文字或外層 Markdown 圍欄，或字串跳脫、括號不合法 → 下次確認交付恰好是一個 JSON 物件，索引列與報告分別放在規定欄位。
- 索引列混進 files，造成範圍驗收失敗 → 下次只把交付檔案放進 files，索引列獨立放在 row。
- 依賴測試執行器的工作目錄匯入模組，導致測試找不到模組 → 下次在測試檔中明確加入包目錄至 `sys.path`，並用指定測試命令驗證 discover 與匯入。
- 測試資料路徑或預期狀態不一致，造成錯誤失敗或覆蓋不足 → 下次逐一核對目錄結構、相對路徑與資料內容，並涵蓋正常、壞資料、重複資料及輸入錯誤。
- 錯把未執行驗證寫成通過 → 下次實際執行指定測試與獨立 checker；無法執行時明確記錄限制，不宣稱驗收通過。
- 入口超出行數限制，或只檢查語法沒有按指定方式執行 → 下次保持入口精簡、計算行數，並實際執行驗收指定命令。
- 掃描超出允許的目錄或檔名，或將符號連結視為一般檔案 → 下次先列出允許路徑與檔案型別，只遍歷規定範圍，不遞迴到未指定位置。
- 唯讀工具改動輸入資料或其 metadata → 下次只讀取輸入，避開既有寫入、修復與鎖定路徑；驗證前後內容、型別、大小、權限及修改時間均未變。
- 缺欄、空字串、null 與錯誤格式被混為一談，或布林值誤當整數 → 下次依規格逐欄驗證，對型別使用精確判斷，並測試空值、缺值與錯誤值。
- 壞資料處理不完整，或一筆壞資料使整體彙總不符合規格 → 下次按規定順序驗證與分類，測試壞資料、重複資料、排序、退出碼及有效資料保留行為。
- README 缺少指定章節或無法照指令執行 → 下次包含用途、唯讀界線、指定標題、入口用法、成功與錯誤行為，以及測試命令。
- 報告未記錄實際驗證結果，或結尾缺少指定標題 → 下次逐項記錄命令與結果，並以規定的交接工具標題和命令清單收尾。
- 未守住修改範圍或件數上限 → 下次先確認允許的路徑與檔案數，只新增規定項目，不動既有資料或範圍外檔案。

## 驗過的骨架

入口：以 Python 執行時將包目錄加入模組搜尋路徑，再呼叫模組的 `main`；保持精簡並確認不超過行數限制。

```python
#!/usr/bin/env python3
import os, sys
sys.path.insert(0, os.path.dirname(os.path.dirname(os.path.abspath(__file__))))
from aos_tool import main
if __name__ == "__main__":
    raise SystemExit(main())
```

模組匯入：入口使用的模組放在包目錄，提供入口與測試可呼叫的函式。

```python
# packs/example/aos_tool.py
def summarize(folder):
    ...

def main(argv=None):
    ...
```

測試匯入與 discover：測試檔名採 `test_*.py`；若執行器未將包目錄加入搜尋路徑，測試須自行加入，並以指定命令確認案例被發現及執行。

```python
# packs/example/tests/test_tool.py
import os
import sys
import unittest

sys.path.insert(0, os.path.dirname(os.path.dirname(os.path.abspath(__file__))))
from aos_tool import summarize


class ToolTests(unittest.TestCase):
    def test_summary(self):
        self.assertEqual(summarize("fixture")["v"], 1)


if __name__ == "__main__":
    unittest.main()
```

README 必要章節：說明用途與唯讀界線，包含指定標題、入口用法、成功與錯誤行為及測試命令。

```markdown
# 工具名稱

簡述工具用途與唯讀界線。

## 第一次跑

```sh
python3 packs/example/bin/tool <folder> --now <ISO-with-timezone>
```

說明成功及輸入錯誤時的輸出與退出狀態，並列出指定測試命令。

```sh

```
```

索引列：只新增一列，路徑與 README 連結一致；交付時依格式規定放在 row 欄位，不混入 files。

```markdown
| `packs/example/` | 唯讀彙總資料 | [README](packs/example/README.md) |
```

report 結尾：記錄實際執行的驗證命令及結果；若未能執行，明確說明。最後使用指定標題並列出交接時必須點名的工具。

```markdown
# REPORT
