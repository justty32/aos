# Haiku 第 2 輪（節錄 B～E；A 段四項弄壞都拿到預期那一行：node 不在／層 who 缺出口 exit／練習腳本用完了／做完再跑印同一行）

B. 五題
1. AI 每次只看到一層：題目文字、編號選項、回法（「第一行 選：N」）。寫字的層另外有「格：」。它回一行 選：N，寫字的層再加 格： 接內容。
2. 照 practice.json 一句一句念的假模型，不連網、不花錢。範例第 2 句故意少了「格：」，所以要求它重回一次。
3. who 選回誰（不寫檔）；line 寫一句回覆存到 menu/hello/out/reply.txt；send 不問 AI，跑登記的工具 hello-send，結果存到 out/sent.txt。
4. README 叫「都不行，要人決定」，選了就停下來等人，status 會顯示停下原因。注意：範例 JSON 裡出口的文字是「缺少判斷先回誰的必要資訊，請人補充」，和 README 說法不一致。
5. rm -r WORK/menu/hello 再打同一個 run，或加 --run 新名字。已做完的再打同一個 run 只印同一行「做完」，不會重走、不問 AI（實測）。

C. 2 個指令。概念：README 點名 4 個＋選：／格：格式＋出口，約 6 個。

D. 容易上手 6（「裡面有 AGENTS.md 的那個」資料夾——不准讀 AGENTS.md，只能靠路徑猜）／容易理解 5（工作資料夾／node、選單／menu 兩個名字；出口有三種說法：README「都不行，要人決定」、範例「缺少判斷…請人補充」、缺出口錯誤訊息「都不是，要你決定」）／複雜的藏起來 6（menu.json 的 next、set、slot、do、ok、fail、max_rounds 沒解釋）／外層控制結構 6（停下、重走、做完再跑都有；缺 exit 訊息直接指出哪層、怎麼改是優點）／要背的少 5（重走兩種做法、出口三種說法）。總分 5.6。
其他：沒說 practice.json 從哪個檔讀（只說「選單旁邊」）；「到這裡就完成了」之後還列 ADVANCED、spec，有壓迫感；`run --help` 的選項沒有說明文字。

E. 基本流程不複雜（AI 只回一個編號，程式做其餘），但寫自己的選單時 JSON 欄位多、名稱不統一，會開始變複雜。
