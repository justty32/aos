# 第四輪思考綜合：時間流速 × 語言層 × 九軸（10-04）

← [第四輪題目](2026-10-04-r4-topic.md)｜原報告：[Fable](2026-10-04-r4-fable.md)、[astra](2026-10-04-r4-astra.md)｜[設計原則](../principles.md)

**只收方向，不列拍板題**（原則 11）。使用者要求這份寫完後**照原題再開第五輪反芻**，所以這裡也標出兩份報告的分歧與空白，給第五輪接著想。

## 1. 兩份一致的地方

1. **沒有「別人的現在」**。回合是每個 node 自己的時間，不是大家共用的座標；看到 B 在第 100 回合，只是一次觀察。要對齊的不是回合，是「依據了哪一版」。「下午兩點才第 5 回合」只有在 node 跟牆鐘有約時才算落後（aos 不補課）。
2. **一個 node 不只一種進度**。時間線的回合速率、任務完成的速率、觀察者取樣的速率各不相同；pause 只停新回合，已在跑的任務和外部世界照走。回合是時鐘，不是進度條。所以「等 B 三回合」至少有三種意思，語言不能都寫成 `wait(3)`。
3. **快慢之間先問「通道保留什麼」，再談換算**。三種交付：
   - **狀態／位準**：保留最新值，會漏中間變化；
   - **事件**：逐件保存到確認，要付積壓、去重、確認的成本；
   - **控制**：請求＋回條（握手），跟速率無關。
   Fable 用硬體跨時脈域（CDC）的三件套命名；astra 多了第三種輸入「窗口／摘要」。longrun 漏 tock、A3-01 重播，都是把事件塞進只留最新值的檔案。
4. **語言層的共同產物＝任務表＋步驟表＋（框架／契約）**，前端（Lisp、Python 函式庫、LLM、手寫 JSON）只是不同寫法，比對產出物就能驗。語言不進核心，編譯器、直譯器、檢查器都是任務包。
5. **九軸是語言的型別／效果檢查**。例如：非冪等步不准無條件自動重試；等「結束」只能等有限生命週期的工作；沒宣告的軸當未知，任務照跑，只是工具不替它自動重試、平行化、替換。
6. **第 9 軸拆開後各管一件事**：幾率性管「重做」（確定的重跑沒意義、可快取；隨機的重跑是新一次抽樣），可預測性管「把關」（有界的用機械驗證器，不可預測的要另一個主體）。可預測性只留定義、相對於觀察者，不深究。
7. **流速不是任務的第十軸**。它屬於環境與時間契約；真正可分配的是回合槽、CPU、處理名額、保留容量。
8. **對 daemon／tick-tock 核心的新要求：零。**

## 2. 各自帶來的新東西

**Fable**
- **編譯器＝async/await 的狀態機轉換**：在每個 await 處切開；await 之間合成一支程序（同一回合內免費），await 本身一定跨回合；跨段變數升到槽裡的 `state.json`（協程框架）。最重要的最佳化是合併基本塊、並行展開互不依賴的段。
- **三態是回傳型別**（`Ok | Absent | Unknown`），不是錯誤碼。
- **流速變化分兩類**：可預測的雜訊（抖動、負載，可附誤差界換算）與不可預測的控制事件（pause、wake、改 interval，只能回來源讀）。分界是准入門檻 U。這給第三輪「期限不換算、規劃才換算」更精確的理由。
- **時鐘域是單位型別**：「team-b 的第 160 回合」和「我的第 160 回合」不能直接相加；換算結果是 `estimate` 型。
- **等慢 node：pause 自己＋請對方 wake**（跨域的中斷線），不輪詢。
- **流速是時間線資源的補給率，daemon 是它的閘門**（只是認出來，不加東西）。
- **跨 node 程式＝編舞（choreography）**：寫一份全域舞步，投影成每個 node 自己的步驟表。自評把握最低。
- 其他軸也各藏兩件事（「它做什麼」vs「我們能對它說死什麼」），第 9 軸只是最明顯的一例。

**astra**
- **看到「有效」≠動手時仍有效**：觀察、准入回條、提交回條要分開。轉接再忠實，也可能在消費前過期；期限要接到實際的效果入口去核對。轉接可以縮小 node 看到的世界，不能放大證據允許的行動。
- **新鮮度有三個問題**：忠於哪個版本、距離哪次觀察多久、這份依據是否仍適用於眼前的動作；多跳轉接不能替資訊重新計齡。
- **逾時≠對方沒做**：我不等了，不代表 B 沒執行、可以退款；開始窗口、完成期限、接受遲到回條的期間是不同約束。
- **慢消費者在要資源**：「不漏件」就是要上游替它保管資料。有限緩衝、來源不等、消費者可永久暫停、不漏件四者不能同時成立。
- **接續的狀態不只 `pc`**：還要業務請求身分、依據版本、已預留什麼、等哪種回條、哪些效果未知；新的 run 不等於新的業務請求。可靠接續的結果由任務包存在槽外。
- **流速只是觀測**，要跟目標、保證、使用權分開。wake 加快回合，不會憑空增加算力。
- **九軸約束編譯器的最佳化**：合併兩步可能省掉重新取樣、授權核對、取消機會；所以產物要保留「在哪固定依據、在哪等、在哪重新核對、哪些中間結果可見」。
- **Python 前端的陷阱**：產生程式時的 `if` 已經做完選擇；要等未來回條才決定的 `if`，必須留在產物裡。

## 3. 分歧與空白（給第五輪）

1. **CDC 借多少**。Fable 認為三種原語就夠且 aos 全有；astra 說檔案原子覆寫不能代替「不漏件」和跨檔一致性的契約，也多了「窗口」這種輸入。Fable 自己也不確定「最近 10 回合最大值」算位準還是事件，可能要第三型。
2. **相對論類比的界線**。Fable 用固有時當核心比喻；astra 只借「看別人的鐘是一次觀察」，明說不建立換算公式。
3. **流速算不算資源**。Fable：時間線資源的補給率，daemon 是閘門；astra：流速是契約裡的性質，能分配的是服務機會。兩者可能只是說法不同，待釐清。
4. **步驟表的「框架」放什麼**。Fable 是 `pc`＋區域變數；astra 要的是「未履行的責任」（請求身分、預留、在途效果）。後者大很多，跟「框架要小」有張力。
5. **期限的最後一哩**。Fable 的兩個鐘（對方的效期、自己的耐性）沒處理「讀到有效到動手之間過期」；astra 的觀察／准入／提交補了這段，但把責任推到「效果入口」——入口是什麼、誰當，尚空白。
6. **編舞投影 vs 原則 3（拓撲自然長出來）**。投影要事先知道參與者；可能只適合團隊內部的固定舞步。
7. **這一層值不值得存在**（兩份都不確定）。如果多數人退回「一支 Python 自己管」，或步驟表只是把 Python 改寫成更多表格，語言層就沒有立足點。價值應該來自跨 node、重開、未知狀態下還能看懂並接續工作。

## 4. 不變的

- 核心零新增；語言、通道、轉接、型別檢查、對帳都在任務包。通用的進通用包，agent 狀態歸 agent 包，模型與摘要品質歸 LLM 包（原則 5、8）。
- 單一 node 視角（原則 3）：跨 node 的程式最後仍是每個 node 各自的步驟表。
