# 核心 spec：aos 時空架構

**這份只收使用者已經說定的核心概念。** 不加新方向；使用者說「之後再說」的列在最後一節，不算核心。條號 S-，之後的細部 spec、程式與測試都要合它、引用它。

## 原則

- **S-01 LLM 可讀。** 相關的操作和協議，盡量用 JSON 或文字，讓 LLM 讀得懂、好使用（第 9 行；使用者稱為這套體系的絕殺）。檢驗方式：一個 LLM 只靠讀寫檔案，就能看懂並操作這一層。

## 四層（由下往上，第 11～19 行）

- **S-02 四層。** daemon（運行層）→ aos 時空（檔案系統＋tick-tock）→ kernel → agent。上層只透過下層提供的時空做事。

## daemon：運行層

- **S-03 daemon 是 aos 與 Linux 之間的介面。** daemon 之上可以做脫離 Linux 的抽象世界；「脫離」是提供一個接口，硬要接回 Linux 也可以（第 13、34 行）。
- **S-04 用程序，不用 thread。** 每個動作是一次 POSIX 程序呼叫，保留任意程式語言的優勢（使用者 10-03 看完 thread 與程序的評估後定）。
- **S-05 多條時間線。** 一個 daemon 要能同時跑多條 tick-tock 時間線，每條負責一個資料夾（第 54 行）。
- **S-06 邊緣狀況歸 daemon。** tick-tock 的邊緣狀況默認都正常；出事是 daemon 的問題，不是 aos 時空的問題（第 36 行）。

## aos 時空

- **S-07 空間＝daemon 能訪問的資料夾。** 這是空間的邊界（第 33 行）。FUSE 跟 tick 能碰到的資料夾整合在一起，以 tick 能碰到的資料夾為正統；傾向整棵穿透，FUSE 掛在空間的根上（第 37～38 行）。
- **S-08 時間＝tick-tock 回合。** tick 動作結束是回合開始，tock 動作結束是回合結束（第 31～32 行）。回合數每條時間線各自數。tick、tock 不準時無妨，aos 本來就和現實時空脫鉤（第 45 行）。
- **S-09 tick 只是起頭。** tick 很快結束，之後很多任務在跑；任務跑完後 tock 進場，也可能提前進場（第 39 行）。
- **S-10 任務一律由 tick 啟動。** 用這點限制任務能碰的空間：任務理論上只碰 tick 給的資料夾，讀寫可以不經 FUSE（第 40～41 行）。tick 也負責把任務和 daemon 對接，所以任務才收得到 tick、tock、daemon 的訊息，也才能受管理（第 44 行）。
- **S-11 任務可以跨回合。** tock 不收掉任務，只告訴它「這個回合結束了、這是第幾回合」（第 42 行）。例子：第 3 回合啟動的任務 A，收到第三次 tock（第 6 回合結束）時自行結束（第 43 行）。
- **S-12 tick 形式無所謂。** tick 是程式還是 lib 都可以；用 inst JSON 當基底，是因為它在 Linux 上最通用（第 17 行）。

## node

- **S-13 node＝一條時間線服務的資料夾。** 主體性就是先前的 node（第 52～53 行）。
- **S-14 node id＝相對 daemon 空間根的資料夾路徑。** 符號連結、搬家改名等寫法細節隨意（第 56 行）。
- **S-15 重疊只管最基本的。** 巢狀資料夾、兩條時間線管同一個或部分重疊的資料夾，只處理最基本的情況（第 55 行）。

## kernel 與 agent：看任務性質認定

- **S-16 角色看任務性質。** kernel、agent 都是 tick 啟動的任務：做資源管理、排程的算 kernel；有 LLM 呼叫、工具使用的算 agent（第 51 行）。
- **S-17 kernel 管任務。** 單位是任務，時間單位是 tick-tock；在 tick-tock 時對跑著的任務做 kill、restart（第 66～67 行）。資源可以無限定義，排程算法隨意（第 35、68 行）。
- **S-18 kernel 管時間線靠 daemon ctl。** 能下 ctl 讓某條 tick-tock 時間線停止或繼續就夠了（第 69 行）。
- **S-19 agent 是狀態機任務。** 在 idle、think、act 之間變換，依託 tick-tock 換狀態（第 74～75 行）。

- **S-23 跨 node 通訊靠掛載。** 任務想跟別的 node 通訊時，把對方相關的收訊資料夾掛到自己看得到的地方；這樣仍合 S-10「任務只碰 tick 給的資料夾」（使用者 10-03 答 proto7-1 的 D-1）。任務執行中也可以請求加掛，由下一個 tick 決定給不給（答 M-6）。

## 同像性

- **S-20 時間線像一個大號的任務。** daemon 與 tick-tock、tick-tock 與任務之間有同像性；daemon 和 tick-tock 的位置仍然特殊，好處只在實作上共用，能共用的都可以（第 79～81 行）。
- **S-21 tick-tock 控制 daemon，兩條路都要。** 路一：時間線的 tick 生出一個任務，任務開一個 daemon，子 daemon 對父時間線就是普通任務，daemon 核心不知道從屬（從屬由子 daemon 自己寫在子根的 owner.json）。路二：寫別的 daemon 的控制檔，跟 S-18 是同一個動作，對象換成 daemon（第 83～84 行）。子 daemon 歸屬起它的 node；路二對子 daemon 的 stop，要那個 node 允許才有效（使用者 10-03 答 Q5）。
- **S-22 控制成環不管。** 使用者承擔風險（第 85 行）。

## 不在核心（使用者說之後再說）

- kill、restart 這些控制塊怎麼做；任務與 tick、tock、daemon 之間的訊息交流（第 46 行）。
- 權限：ctl 能不能下、別的 daemon 的控制檔能不能寫（第 69、84 行）。
- kernel 的管轄範圍（第 70 行）；agent 狀態機以外的細節（第 75、86 行）。
- daemon 與 tick-tock 的技術選型（第 61 行），例如跨 daemon 的 id、daemon 重開後回合數延不延續、tock 何時進場、FUSE 掛法、鎖的粒度、node 怎麼出生與消失、kernel 怎麼看見各 node 的任務、任務表誰能改、外部事件和人怎麼進來、失敗與結束碼怎麼被看見。
