# FINDINGS-team — 玩「指揮一隊」撞到的事

寫的日期：2026-09-05。劇本＝ideas 13「先玩清單」第二級：**一個主 agent（lead）派兩個子
agent，各住自己的資料夾、各自由 `aos run --register` 登記自己的鐘，做完把結果寫回主指定的
落點，主等兩邊都好了再合併寫總結**。全程用 LLM 世界的假後端 `echo:`，不打網路。

跑的東西：[`proto/play-team.sh`](../../play-team.sh)＋這個資料夾（[README](README.md)）。
**這份只記這一趟玩撞到的，不動 [`proto/FINDINGS.md`](../../FINDINGS.md)**（由使用者事後合併）。

怎麼讀一條：`- **情境**｜依據：哪一條｜**卡在哪**｜**怎麼繞**｜類別｜擋路程度`

類別照使用者定的三種量法，外加一種：**多餘的動作**／**看不見的狀態**／**錯誤不指路**／**spec 沒講**。
擋路程度：**擋路**／**煩**／**小**。

## 先看這三條（其餘按主題排在下面）

### T-01 daemon 起的每一支 run，看到的結束碼一律是 0——所有指令失敗都變成靜默成功
- **情境**｜依據：08 S-08-06（走時鐘＝daemon 替每塊地起一支 `aos run`）、S-08-31／10 S-10-30（agent **預設**就是這樣起）、05 I-04 第二頻道（沒宣告 `expect` 就看結束碼）
- **卡在哪**：`daemon._loop` 為了不留殭屍設了 `signal.signal(SIGCHLD, SIG_IGN)`。`SIG_IGN` 這個處置**會跨 exec 繼承下去**，所以 daemon 起的 `aos run` 一出生 SIGCHLD 就是 IGN；它再用 `subprocess` 跑地上的指令時，`waitpid` 拿到 ECHILD，CPython 就把 `returncode` 記成 **0**。於是 `.aos/ticks/<N>/results/<id>.json` 的 `exit_code` 永遠是 0，`instrun.semantic_ok` 永遠說「成功」，串照樣往下推。
- **實測**（最小重現，一步 `python3 -c "sys.exit(3)"`）：
  - 自己敲 `aos run <地> --until idle` → `exit_code: 3`、串 `failed`、停止原因 `failed`、退出碼 5。**對的**。
  - `aos daemon add <地> --steps 3` 讓 daemon 去起同一塊地 → `exit_code: 0`、串「推到 `end`」、停止原因 `idle`。**壞掉的東西完全看不見。**
  - 這一隊的實例：子 A 的 `prep` 步 `sys.exit(1)`（讀不到主派的檔）被當成成功 → 下一步 `aos deliver` 拿到不存在的 `state/req.json`、退出碼 2，也被當成成功 → 子卡在 `wait` 空等 73 格，主只能等到自己的 `await` 逾時。三層錯誤，一層都沒浮出來。
- **怎麼繞**：這一趟沒繞（不准改 `aosp/`）。要繞只有三條路：run 在起頭把 SIGCHLD 設回 `SIG_DFL`；或 daemon 不用 `SIG_IGN` 收屍、改成自己 `waitpid`；或每一步都宣告 `expect`，完全不靠結束碼。
- 類別：**看不見的狀態**｜擋路程度：**擋路**（spec 兩條分開看都對，合起來把第二頻道整個廢掉；正式實作要明訂「起子行程前必須把 SIGCHLD 還原成預設」）

### T-02 父分不出子「還沒好」「做完了」「壞掉了」——登記表的 `state`／`pid` 三種情況長得一樣
- **情境**｜依據：07 S-07-29／08 S-08-30（F-07：要知道子地的鐘還在不在走，**必須**查登記表那筆的 `state` 與 `pid`，禁止用別的方法猜）、07 S-07-14 三態
- **卡在哪**：子的 run 一結束就把自己那筆改成 `state:"stopped"`、`pid:null`。**做完了**、**串壞掉停了**、**被 SIGTERM 全停**、**被 kill -9 之後對帳改的**，這四種在登記表上一模一樣。真正的答案在子那塊地的 `.aos/stopped.json`（`idle` / `failed` / `signal`）——可是 F-07 明文禁止用別的方法查。
  實測：子 A 讀不到檔壞掉、子 B `await_timeout` 壞掉，兩次登記表都只寫 `stopped`，跟正常做完的子 A 那一趟一字不差。
- **怎麼繞**：只好讓子自己補：`worker.py` 在放棄時**自己**往 `<落點>.status.json` 寫一份 `failed`，主的 `await` 才看得到「壞了」而不是傻等。代價是——子被 SIGKILL、或子在 `prep` 就死了，這份檔沒人寫，主就只剩「等到 `max_ticks` 用完」這一條路。
- 類別：**看不見的狀態**｜擋路程度：**擋路**（F-07 該改寫：登記表只回答「鐘還在不在走」，「這件事做成沒做成」一律看落點三態；並補一條「誰替死掉的子寫狀態檔」——07 S-07-18 說 daemon 要寫，原型的 daemon 沒做）

### T-03 兩個子指到同一個落點，沒有任何一層擋，後寫的靜靜蓋掉先寫的
- **情境**｜依據：07b S-07-60～S-07-63（呼叫前三個檔都不得已存在＝退出碼 3；同一格裡所有落點必須兩兩相異，有重複整格拒跑）、S-07-78（`call` 步由 exec 查）
- **卡在哪**：`execute._do_call` 只查一件事——落點不准指進 `.aos/`（`bad_result_path`）。S-07-60～63 一條都沒實作。實測把主的兩個 `call` 步都寫成 `result: "out/shared.done.json"`：
  - 沒有退出碼 3、沒有拒跑，兩個子都被派出去；
  - 子 B 後寫，蓋掉子 A 的那份；
  - 主的 `wait_a` 與 `wait_b` 等的是同一個檔，兩步都立刻算「好了」；
  - 主替 `work/a.py` 貼上的是**子 B 想的 docstring**（實測檔頭：`"""子 B 寫的：work/b.py 提供 greet、shout。"""`）；
  - 主報告裡「誰先好」也錯（兩列的 mtime 是同一個檔）。**A 這個子做的事整份人間蒸發，全程零錯誤訊息。**
- **怎麼繞**：沒繞。這一隊正式的劇本靠「人自己把兩個落點取不同名」躲開。
- 類別：**看不見的狀態**｜擋路程度：**擋路**（S-07-63 那條非做不可，而且該在 `call` 步就查，不是等到寫檔）

## 落點與重跑

- **落點沒清就重跑，主會立刻撿到上一輪的舊結果**｜依據：07b S-07-60、S-07-61、S-07-62｜**卡在哪**：只清 `.aos/` 與 `state/`、留著 `lead/out/*.done.json` 再跑一次：主的 `wait_a`／`wait_b` **第 1 格就過**（實測 run 紀錄從第 1 格直接跳到 `prep_report`），拿上一輪的資料寫報告；兩個子這時才剛被派出去，稍後才把新結果蓋上去——主讀到的跟子寫的是兩回事。spec 說這種情況要退出碼 3 不准自動蓋，原型沒查。｜**怎麼繞**：`play-team.sh` 每次跑之前自己 `rm -rf lead/out`，並把 `work/` 從 `.pristine/` 還原。｜類別：**看不見的狀態**｜擋路程度：**擋路**
- **重跑要人清的東西有五處，沒有一條指令做這件事**｜依據：07b S-07-62（要重跑必須人先把舊檔清掉）｜**卡在哪**：一隊三塊地，重跑要清：三個 `.aos/`、`lead/out/`、三個 `state/`、`lead/report.md`、還要還原被主改過的 `work/*.py`。`aos reset <地>` 只清壞掉的串與停止原因檔，碰不到落點，也一次只能一塊地。｜**怎麼繞**：`play-team.sh` 第 0 節手寫這一串 `rm -rf`，並在第一次跑時把 `work/` 存一份到 `lead/.pristine/`。｜類別：**多餘的動作**｜擋路程度：煩
- **子改父地上的檔是「讀得到就改得到」，只有寫落點那條規矩是真的**｜依據：07b S-07-64、S-07-65（落點＝父開的明示寫入洞，只涵蓋那條路徑與兩個後綴檔）、07 S-07-08（子地看得到什麼只由父放進那個資料夾的東西決定）｜**卡在哪**：主要把材料交給子，能用的只有 `args`（變成 `AOS_ARG_*` 環境變數，**只能是字串**）。所以主只能交路徑：`AOS_ARG_FILE=work/a.py` ＋ `AOS_CALLER=<主地>`。子照著 `os.path.join` 就**直接讀到父地上的檔**，沒有任何一層擋——它要順手改掉、或去讀父地上別的檔，一樣沒人擋。這一隊的劇本是自律的（子只讀不寫、只寫 `$AOS_RESULT`），但那是 `worker.py` 自己有良心，不是機器保證的。｜**怎麼繞**：沒繞，寫進這裡。｜類別：**spec 沒講**｜擋路程度：**擋路**（S-07-08 要嘛給執行機制，要嘛降級成「慣例」；不然「一塊地只看得到自己地上的東西」在第一個真實劇本就是空話）

## 派活與等待

- **派 N 個子＝N 步 N 格，等 N 個子＝N 個 `await` 步，而且是排隊等**｜依據：05 接力棒（一條串線性推進）、07 S-07-07（脫節呼叫之後用 `await` 看落點）｜**卡在哪**：主的原稿只能寫成 `dispatch_a → dispatch_b → wait_a → wait_b`。兩個子已經是這樣，五個子就是十步。更糟的是**排隊等**：主停在 `wait_a` 的時候，子 B 就算已經把 `<落點>.status.json` 寫成 `failed`，主也看不到，要等 A 那步過了才輪到。實測子 A 壞掉時，主整整卡到自己的 `max_ticks` 用完才動，而 B 早就做完了。｜**怎麼繞**：把 `max_ticks` 調小當保險絲；主的 `lead.py` 在 `report` 那步自己再把兩個落點各查一次三態。｜類別：**spec 沒講**｜擋路程度：**擋路**（沒有「等這一組全好」「等最先好的那個」的步，指揮一隊就只能寫成序列）
- **`await` 的等待格數跨越「一次全停→重開」不歸零**｜依據：07 S-07-22（超過 `max_ticks` 算失敗）、10 S-10-33（一次全停之後重開必須接著走）｜**卡在哪**：`ext.awaits[步名]` 存在接力棒裡，停機期間格不走、計數也不減。實測：`slow:8000` 的假後端＋中間 `aos daemon stop` 停一次再重開，子 B 一重開就踩到 `max_ticks`（`await_timeout`）——**它被機器停機的那段時間算進了自己的耐心**。父完全分不出「子真的太慢」跟「中間停過機」。｜**怎麼繞**：沒繞。`max_ticks` 只好開得很大（這一隊的主用 400）。｜類別：**spec 沒講**｜擋路程度：**擋路**（`max_ticks` 要嘛只算「這支 run 這一趟」的格、要嘛重開時歸零、要嘛明講就是含停機時間）
- **主想照 F-07 查子的鐘，指令面沒有「查一塊地」這件事**｜依據：07 S-07-29／08 S-08-30（必須查登記表那一筆）、08 S-08-51（`aos daemon ls` 逐筆列出）｜**卡在哪**：`aos daemon ls` 只會把整張表印出來。`aos daemon ls <地>` **不報錯、也不過濾**（argparse 收下那個參數就丟掉了，退出碼 0）——照著敲的人會以為自己查的是那一塊地。主要在自己的原稿裡查一個子，只能跑 `aos daemon ls --json` 然後自己 parse 整張表比對路徑。｜**怎麼繞**：這一隊沒在原稿裡查，改成靠落點三態（也就是繞過 F-07）。｜類別：**錯誤不指路**｜擋路程度：煩（該補 `aos daemon ls <地>` 或 `aos state <地>`，並讓多餘的參數報錯）
- **子怎麼知道自己被派了什麼：只有環境變數，而且只有 daemon 起的那支 run 才有**｜依據：07 S-07-12、S-07-13（`AOS_RESULT`／`AOS_CALLER`／`AOS_ARG_*`）、08b（脫節子地由 daemon 起）｜**卡在哪**：這三個值由 `aos run` 從**登記表那筆**重建。人自己敲 `aos run workers/a --until idle` 想單獨試一個子，三個值全是空的，`worker.py` 只能自己失敗——機器不會講「這塊地要由主派活才跑得起來」。而且值只有字串，要傳一份材料只能傳路徑（見上面那條）。｜**怎麼繞**：`worker.py` 自己寫了指路訊息（少了哪個變數、該怎麼起）。｜類別：**錯誤不指路**｜擋路程度：煩

## 一次全停與重開

- **`aos daemon stop` 停得掉三塊地，但停不掉 LLM 世界**｜依據：08 S-08-84（`runner` 是 `llm-serve` 的那筆，daemon 起的必須是 `aos llm serve`）、09 F-02（LLM 世界是單獨一塊地）｜**卡在哪**：原型的登記表沒有 `runner` 欄，daemon 也只會起 `aos run`，所以 LLM 世界那支只能由**人自己**在背景起（`play-team.sh` 第 2 節）。實測 `aos daemon stop`：三塊地都乖乖在格尾停、各寫 `stopped.json`（`reason:"signal"`）、登記表三筆全 `stopped`——**但 `aos llm serve` 那支還活著**，得腳本自己補一刀。「一次全停」對這一隊來說是「停四樣裡的三樣」。｜**怎麼繞**：`play-team.sh` 記下 serve 的 pid，全停之後檢查、還活著就自己殺掉並印一行說明。｜類別：**看不見的狀態**｜擋路程度：**擋路**
- **全停之後把 daemon 開回來，三塊地一塊都不會動**｜依據：08 S-08-85（`resume` 欄）、10 S-10-33（重開接著走）｜**卡在哪**：全停把三筆都寫成 `stopped`，daemon 迴圈只撿 `pending`。實測只 `aos daemon start` 再等 5 秒：三塊地的游標動都不動（主停在 `wait_a`、兩個子停在 `wait`）。要接回去，得**一塊一塊** `aos daemon add` 重新登記；登記完確實會從游標接著走（主 `wait_a → wait_b`、子 A 走到 `end`），所以 S-10-33 本身是成立的，卡的是「怎麼把一隊接回去」。`resume` 這一欄原型沒有。｜**怎麼繞**：`for L in 主 子A 子B; do aos daemon add $L --every 300; done`。一隊 N 塊地就是 N 個指令。｜類別：**多餘的動作**｜擋路程度：**擋路**
- **看一隊的現況要敲 1+N 次指令**｜依據：12 指令面（看的只有 `status`）、08 S-08-51｜**卡在哪**：`aos daemon ls`（誰的鐘在走）＋每塊地一次 `aos status`（游標在哪）。而且兩邊都不講重點：`aos status` 只印「游標 `wait_a` 狀態 running」，**不講在等哪一個落點、等了幾格**——那句話只出現在 run 的輸出裡（daemon 起的話是 `.aos/daemon-run.log`，人自己起的話就只在終端機上，過了就沒了）。要知道主在等誰，得去翻 log。｜**怎麼繞**：`play-team.sh` 每 3 秒把 `daemon ls` ＋三塊地的 `status` 一起印，收尾時再自己讀三份 `series.json` 與 `stopped.json` 湊出一張表。｜類別：**看不見的狀態**｜擋路程度：**擋路**（該有 `aos ps`／`aos state <地>`，至少把 `await` 在等什麼放進 `aos status`）

## 其他（煩，但不擋路）

- **兩個子只差一個字母，程式卻得整份複製**｜依據：10 S-10-01（一個 agent 就是一個資料夾）、03（一塊地只看得到自己地上的東西）｜**卡在哪**：`workers/a` 與 `workers/b` 的 `main.aos.json`、`worker.py`、`system.md` 一模一樣，只有 `agent.json` 的 `who` 不同。沒有「模板一塊地」「同一支腦兩塊地共用」的東西，也不能 symlink 進去（那等於開了一個沒人管的洞）。改一行腦要改兩份。｜**怎麼繞**：`cp` 過去，`agent.json` 用 `sed` 改一個欄位。｜類別：**多餘的動作**｜擋路程度：煩
- **`aos daemon add` 是原型自己補的，spec 的 `aos agent init` 一個都還沒有**｜依據：08 S-08-86（`aos daemon add` 只登記成 `pending`）、10 S-10-07（`aos agent init` 必須一次產出四樣）｜**卡在哪**：起一隊要敲：`init` ×3 ＋ 手寫 `.aos/config.json` ×3（`path` 白名單不寫，地上的 `aos deliver` 就找不到 `aos`）＋ `llm init` ＋ 背景起 `llm serve` ＋ `daemon start` ＋ `daemon add` 主。**九個動作才開得了一隊**，其中三個是手寫 json。｜**怎麼繞**：全寫進 `play-team.sh`。｜類別：**多餘的動作**｜擋路程度：煩
- **`agent.json` 的欄位跟 spec 對不上，而且沒人讀它**｜依據：10 S-10-08（欄位是 `format_version`／`max_seconds`／`max_llm_calls`／`max_tokens`／`tier`／`system_prompt`／`ext`）、S-10-10（上限對 `.aos/usage.json` 判）｜**卡在哪**：機器完全不讀 `agent.json`，也不寫 `.aos/usage.json`；LLM 世界沒有寫 `<落點>.usage.json`（S-10-11），所以 `max_llm_calls`／`max_tokens` 在原型裡就是裝飾。這一隊真正在管圈數的是 `worker.py` 自己讀的 `max_rounds`——那個欄位 spec 裡沒有。｜**怎麼繞**：`agent.json` 照 spec 的欄位寫齊，另加自己要用的 `max_rounds`、`team`、`who`，並在這裡記一筆。｜類別：**spec 沒講**｜擋路程度：小
- **假後端 `echo:` 把 prompt 原樣回，所以「模型的答案」得由自己在 prompt 裡先種一行**｜依據：09（假後端）、原型 FINDINGS「加了假後端 `echo:`」｜**卡在哪**：不打網路就沒有真答案。子要拿到一句 docstring，只能在 prompt 裡放一行「想不到就照抄下面這行」的備用答案，回話回來之後挑**最後一行** `DOC:`。換成真後端，挑的就是模型自己那行——但這個「挑哪一行」的規矩是每個 agent 自己土法煉鋼寫的，11 的封套沒管到回話怎麼解析。｜**怎麼繞**：`worker.py` / `lead.py` 各自 `pick_doc()`／`pick_line()`，並濾掉格式示範那一行。｜類別：**spec 沒講**｜擋路程度：小

## 沒撞到問題的（記一下，免得下次重測）
