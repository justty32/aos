## proto5 的 agent（2026-09 版）

- **一個資料夾就是一個 agent**，叫「agent 家」；身分就是資料夾名。不常駐，kernel 定時派一格 `aos-agent tick`，每格只做一小步就退出。
- 一格：拿鎖 → 看 `paused` → 讀設定 → 看門 → 有批就收批，沒有就照 `state.json` 的 `idle`／`think`／`act` 往下走。
- **LLM 呼叫不直接打 HTTP**：think 寫一份 inst `aos-llm call`，丟給 kernel 的 llm 池跑；下一格回收結果。端點 OpenAI 相容（實際走 LiteLLM）。
- 工具＝OpenAI `tools` 陣列，每個多一格 `_meta`（就是一份 inst）。模型給的 arguments 進 stdin、stdout 原樣給模型看。每個 tool_call 是丟給 kernel 的一次性工作。
- 記憶：`prompts/history.json`（短期）、`notes/notes.json`（長期）。壓縮機械做、不叫模型（留最後 3 輪、更舊只留問答、再超就封存成 8 KB 摘要；上限 32000 token 是使用者裁的）。
- 訊息：單一 agent 用 `input/` 放檔；團隊用 outbox → 郵差 `aos-team post`（機械程式，驗寄件人、白名單）。
- 退出碼有特別意義：101 等、102 停車等叫醒、103 馬上再排一格。
- 權限：工具一律 bwrap 關牢，`access.json` 列掛載點；沒有 Linux 帳號。
- 試玩評語：「要背的東西太多」一直最低分；`say`／`listen` 不對稱；status 印內部檔名。使用者撤掉的：父子樹（一律平的）、多叫一次模型的功能預設關、不給模型「等」的工具、「每個 agent 一個 tick-daemon」。
- 09-28 新方向（沒做）：一 agent 一 Linux 使用者；工具沿用委託者權限、不逐工具 bwrap；cgroup v2 管資源；一台家用機放一萬個 agent，閒著的只佔磁碟。

出處：`proto5/spec/agent/`、`proto5/spec/aos-agent/`、`proto5/lib/aos_agent*.py`、`proto5/notes/play/README.md`、`proto5/advice.md`。

## 舊設計 spec（09-29～09-30，已封存）

- agent 與 kernel 都是「node 的角色」：node 是資料夾實體，任務表裝了什麼就是什麼。agent 平常不設週期，等 kernel 叫醒。
- 一輪：收件 → 收工具與 LLM 結果 → 組 context → 送請求（下一格收）→ 記用量、寫摘要。
- LLM 排程三檔：自己排（預設）、交給 endpoint、直連。token 預算先不做。
- 這整套 10-02 封存（`notes/archive/spec-2026-10-02/`），裡面的 `requests/`、once、`target_node`、summary 在現行程式都沒有落腳處。

## 被現行零件吸收的

| 舊 agent 功能 | 現在對應 |
|---|---|
| 收件、投件 | daemon 訊息模組：`aos-mq send／take／peek`，多扇門 |
| 叫醒 agent | `aos-ctl wake`；寄信也會合併叫醒 |
| 停車（退出碼 102） | 退出碼沒意義了（B-626）；改 `aos-ctl pause` 或擋板檔 |
| 每項一個 cgroup 框 | daemon 收屍模組 |
| 換帳號 | daemon 帳號模組（單位是 daemon 的一項） |
| git 提交／還原 | hooks ＋普通 git 指令 |
| 工具＝inst | inst 原樣搬進 proto6（`aos_inst.py`） |
| 一步一格、不常駐 | tick 核心 |

## 現行程式**沒有**的（要新造或靠組合）

LLM 呼叫、對話記憶、工具呼叫的接線、agent 身分、睡／醒的判斷、信的寄件人欄位、信落檔（信箱在記憶體，daemon 重開就丟）、任務逾時（tick 用 Popen 直接開任務、不經 aos-exec、沒逾時）。

## 程式核對出來的坑（規劃時要記得）

- **daemon 跑 daemon 沒測過**；內層 daemon 沒掛控制／訊息模組時，外層的 `AOS_DAEMON_CTL_SOCKET`、`AOS_DAEMON_MQ_*`、`AOS_DAEMON_INST` 會原樣漏給內層任務，內層的 `aos-ctl`／`aos-mq` 會打到外層。
- 信箱在記憶體、沒有寄件人、沒上限、不去重。
- `docs/mq.md` 還寫 `mq-get`／`mq-post`，程式是 `send`／`take`／`peek`；`docs/ctl.md` 少列 `kill`／`restart`。
