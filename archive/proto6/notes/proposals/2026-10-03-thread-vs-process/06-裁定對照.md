# 六、跟已有裁定的關係：哪個選項要翻什麼

← [入口](README.md)｜上一份：[其他路線](05-其他路線.md)｜下一份：[實驗](07-實驗.md)

只列會被碰到的。「翻」＝原文要改意思；「補」＝原文不動、加一句；「無關」＝不受影響。使用者 10-03 已講的六條方向（daemon 變 FUSE、框與帳號拉出去、互不從屬、不管子程序、tick 變 lib、一項是什麼待定）本身就會翻一批裁定，那部分不論選 A 或 B 都要翻，另列在最後。

## 隨選項而異的

| 裁定 | 原文位置 | A 全程序 | B tick 進 lib | C 混合 |
|---|---|---|---|---|
| T-07「tick 是一個定期被執行的程式」 | [terms.md](../../../spec/terms.md) | 不翻 | 翻：變成「一個函式，外面套一層 CLI」 | 補：兩種叫法都算 |
| T-11／B-640「daemon 只是定期叫 `aos-exec`、不認得工作資料夾、一項就是 inst 字面值」 | [terms.md](../../../spec/terms.md)、[07 最核心 daemon](../../verdicts/11-tick-as-unit/07-1001-最核心daemon.md) | 不翻（A′ 省掉 aos-exec 程序只是實作，語意同） | 翻：daemon 要認得工作資料夾、直接讀 `tasks.json` | 翻一半：一項可以是資料夾或 inst |
| B-627「經 daemon 跑的格跟人手、cron 直接跑沒有差別」 | [tick.md](../../../spec/tick.md) | 不翻 | 補：同一份 lib、兩個入口；測試要兩邊都打 | 同 B |
| B-602「鎖 fd 不傳給任務」 | [tick.md](../../../spec/tick.md)、[06 互斥](../../verdicts/11-tick-as-unit/06-1001-互斥-狀態資料夾-user.md) | 不翻 | 若要保住重開語意就要翻：鎖 fd 傳給任務、鎖跟著任務活 | 同 B |
| B-602「核心不清後代、不管逾時」 | 同上 | 不翻 | 不翻，但後果變重：卡住的任務卡住一條 daemon thread，永遠 | 同 B |
| C-10「tick 跑每一項前先把繼承來的 `AOS_TASK_*` 拿掉」「其他變數一路往下傳」 | [conventions.md](../../../spec/conventions.md) | 不翻 | 補：繼承來源從「tick 程序的環境」改成「daemon 給這一項的 env dict」 | 同 B |
| C-11「頂層 `cwd` 不改程式自己的工作目錄」 | 同上 | 不翻 | 要做徹底：tick 自己也不能 chdir（`aos_tick.py` 第 132 行） | 同 B |
| 第十九批 kill／restart 靠程序群組 | [21 第十九批](../../verdicts/11-tick-as-unit/21-1001-第十九批.md) | 使用者說「等等」；若留，A 現成 | 若留：kill 一格＝只能殺它正在等的任務 | 看哪一路 |
| 第十二批「daemon 有很多執行緒，fork 後跑 Python 不安全」 | [14 第十二批](../../verdicts/11-tick-as-unit/14-1001-第十二批.md) | 不翻 | 不翻 | 不翻；但 [05](05-其他路線.md) 的 fork server 路線要照它：先 fork 出 zygote 再開 thread |
| 第十四批「只用標準庫」 | [05-dependencies](../../verdicts/05-dependencies.md) | 無關 | 無關 | 無關；真正撞它的是 FUSE（Python 要 pyfuse3／fusepy），不分 A、B |
| C++11 改寫放最後、由使用者親手寫 | [plan README](../../../plan/README.md) | 不翻：tick 與 daemon 可一支一支改 | 補：兩支一起改，或 C++ daemon 嵌 Python 跑 tick lib | 同 A（argv 路留著就能分開改） |

## 不分選項、使用者六條方向本身就要翻的

| 裁定 | 原文位置 | 被哪一條方向翻 |
|---|---|---|
| 「FUSE 延後」「daemon 變 FUSE 樹留到 C++11 再評」 | [notes README](../../README.md) 規模目標段、[plan9 README](../2026-10-02-plan9/README.md) | 方向 1 |
| B-644 收屍／cgroup 模組、B-646 帳號模組、`aos-daemon-root` | [daemon/README.md](../../../spec/daemon/README.md) | 方向 2：搬暫緩區 |
| 第二十五批 socket 666、`AOS_DAEMON_CTL_SOCKET`、`AOS_DAEMON_MQ_*`、`AOS_DAEMON_INST` | [26 第二十五批](../../verdicts/11-tick-as-unit/26-1002-第二十五批.md) | 方向 1、5：socket 與三組變數被 FUSE 路徑取代 |
| B-641 控制模組的 kill／restart | [control.md](../../../spec/daemon/control.md) | 方向 6 待定 |
| 第二十一批「跨 daemon 用 socket 路徑當前綴」 | [23 第二十一批](../../verdicts/11-tick-as-unit/23-1001-第二十一批.md) | 方向 3：改成寫對方的樹 |
| 「daemon 死後孤兒程序不清」（第二十批進行順序：接受） | [01 方向與追答](../../verdicts/11-tick-as-unit/01-0930-方向與追答.md) | 方向 3「重開要管」：要不要翻，之後再說 |

## 一句話

A 一條裁定都不翻，連 spec 字面都不用動（省掉 aos-exec 程序是實作細節）。B 要翻 T-07、T-11／B-640、B-602 一句，補 B-627、C-10、C-11。真正的大翻（FUSE、框與帳號出走、socket 消失）來自使用者的六條方向，跟選 A 或 B 無關。
