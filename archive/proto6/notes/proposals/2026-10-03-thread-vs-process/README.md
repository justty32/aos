# 評估：daemon／tick 要不要從「每次動作一個 POSIX 程序」改成「thread＋lib」（2026-10-03）

← [筆記索引](../../README.md)｜使用者的分層：[aos 的分層](../../2026-10-03-aos-layering.md)｜現行 spec：[proto6/spec](../../../spec/README.md)｜程式：[proto6/src/py](../../../src/py/README.md)｜相關：[Plan 9 提案](../2026-10-02-plan9/README.md)、[astra 另想](../../reviews/2026-10-03-astra-alt/README.md)

**這是評估，不是裁定。** 不改程式、不改 spec。使用者 10-03 的六條減法方向（daemon 變 FUSE、框與帳號拉出去、daemon 互不從屬、核心不管子程序、tick 變 lib、一項是什麼待定）與同日的四層分層（daemon＝運行層 → aos 時空＝檔案系統＋tick → kernel → agent；tick 形式無所謂，inst JSON 只因在 Linux 上最通用）當前提。要回答的是使用者的原話：「每次動作都是一個 posix 呼叫，天然適配 process 機制。但現在換成 thread，整個都要大改動。這牽扯到另一個權衡：是否要捨棄 posix 的優勢，也就是任意程式語言。」

## 一段話結論

thread 只能取代四跳裡的一跳（daemon → tick）；tick → 任務在程式裡**本來就是函式邊界加一次 Popen**（`aos_tick_run.py` 第 75 行），所以任務層的任意語言三個選項都不受影響。照使用者的四層看，程序或 thread 是運行層的實作選擇，大多數取捨（啟動 17 ms／16 MB、GIL、ps、鎖的做法、tick 的語言）都**留在運行層**，上層感覺不到；會**漏到上層**的只有三類：daemon 被殺時時間會不會分叉（B 下格被攔腰切、鎖立刻放、下一格跟孤兒任務重疊）、空間會不會因一格卡住（B 下 tick lib 卡住或碰自己的 FUSE 樹會卡整棵樹）、kernel 能用的最小單位是什麼（B 下運行層只會跑格，掛不了下層 daemon 或常駐服務，多層時退回 C）。A 這三類靠程序邊界白得；B 前兩類要另外補、第三類要留程序路。thread 版「鎖比較好處理」「FUSE 比較好認身分」實測都不成立。現行鏈最浪費的是 aos-exec 那一跳（25 ms，比 tick 本身還貴），A′ 一條裁定都不翻就省掉它。

## 選項

| 選項 | 長相 | 運行層的單位 |
|---|---|---|
| **A 全程序**（A′＝省掉 aos-exec 程序） | daemon 一項一條 thread，thread 裡 Popen tick 程序、只 wait、不殺不收屍 | inst（tick 是其中一種） |
| **B tick 進 lib** | thread 裡呼叫 `run_tick(cwd)`；任務仍是 Popen | 資料夾 |
| **C 混合** | 一項是資料夾就走 lib，是 inst 就走程序 | 兩種 |

第四、第五條路（常駐 worker、fork server、極小 C++ tick、A′、rfork 式）見 [05](05-其他路線.md)。

## 建議（供拍板，不是裁定）

1. **先做 A′**：daemon thread 直接開 inst 的 argv，不經 aos-exec 程序。每格 42 → 17 ms，零裁定要翻，兩小時。
2. **B 等到量到需要**：訊號是「同時在跑的格長期上百」或「週期降到百毫秒級」。規模目標是一萬 agent、每小時活躍不到一百，離兩個訊號都遠。
3. **若要「daemon 不開程序」當原則**，那是 C 不是 B：多層一定要開程序。C 的代價是兩條路兩套測試。
4. **FUSE 與 `me` 連結照做**，跟 A／B 無關；但要寫一條規矩「daemon 自己的 thread 不碰自己掛的樹」。
5. **做 [07](07-實驗.md) 的 E1＋E2（一天）**再拍：B 的原型與 daemon 被殺時的行為，看過比讀過準。

## 問使用者的問題

| # | 題 | 選項與後果 | 建議 |
|---|---|---|---|
| 1 | 運行層要替時空守哪些契約？（[09](09-分層視角.md) 的 T1～T4） | a 四條都守 → A 白得，B 要補鎖 fd 傳任務＋樹隔離；b 只守 T2、T4，daemon 被殺時接受時間分叉 → B 可直接做 | a。kernel 的「給你 10 格」靠 T1 |
| 2 | 運行層的單位是什麼？ | a inst（任何程式，tick 是其一）→ A；b 資料夾（只跑格）→ B，但多層 daemon 沒地方放；c 兩種 → C | a 或 c。問題 1 選 a 時，b 就不可行 |
| 3 | 「核心不管子程序」的「不管」含不含「不開」？ | a 不殺不收屍但可以開並 wait → A；b 連開都不開 → B，多層時破例 → 實為 C | a。「只 wait」就是現狀，runit、s6、cron 都這樣 |
| 4 | tick 本身要不要可被換掉（別的語言、包一層 timeout／bwrap）？ | a 要 → A 或 C；b 不要，tick 永遠是 daemon 同語言的 lib → B 可行 | 使用者說形式無所謂，所以這題只影響 C++ 改寫能不能分段；a 比較省事 |
| 5 | 要不要現在就做 A′？ | a 做（兩小時，省 25 ms）；b 留著 aos-exec 這一跳 | a。aos-exec 程式還在、人手照用，只是 daemon 不再 exec 它 |
