# 七、建議的最小實驗（半天到兩天）

← [入口](README.md)｜上一份：[裁定對照](06-裁定對照.md)｜下一份：[外部先例](08-外部先例.md)

目的只有一個：**用結果而不是論述來區分 A、B、C**。每個實驗寫：做什麼、看什麼、能分出什麼。全在 scratchpad 做，不動 repo 的程式；[03](03-實測.md) 已做掉的不重做。

## 已經做掉的（03）

- 每格成本：Python aos-tick 17 ms、aos-exec 25 ms、lib 呼叫 0.3～0.7 ms、C 程式 0.07～0.43 ms。
- 同時 1000 格：程序版 1.8 s／27 s CPU，thread 版 67 ms／0.14 s CPU。
- 現行 `run_tick` 多 thread 會悄悄跑錯資料夾（chdir 競爭）。
- flock 在 thread 間互斥；鎖 fd 傳給任務後鎖跟著任務活。
- FUSE 拿到的是 tid，thread 分得出。
- thread 殺不掉。

這些已足夠回答「速度」「記憶體」「鎖」「認身分」四題。剩下的是語意題，要靠下面的實驗。

## E1：B 的最小原型（半天）

- **做**：在 scratchpad 複製 `aos_tick*.py`，把 `os.chdir` 與所有相對路徑改成帶 `cwd` 的絕對路徑（[04](04-改動清單.md) A 類第 1～4 項），`_env()` 改成吃傳進來的 env dict。寫一個 50 行的假 daemon：N 條 thread 各呼叫 `run_tick(dir_i, table_i, env_i)`。
- **看**：N＝100 時每格紀錄都在自己資料夾、沒有 `busy:`；現有 `tests/test_tick_*.py` 改成 import 呼叫後過幾條。
- **分出**：B 的改動量到底是「改幾十行」還是「重寫 tick」。順便得到 lib 版的真實數字（不是代理）。

## E2：daemon 死掉時的格（一小時）

- **做**：兩個版本各跑一格、格裡一項 `sleep 30`；格跑到一半 `kill -9` daemon。A 版＝現行 daemon；B 版＝E1 的假 daemon。然後立刻再開一個 daemon。
- **看**：A 版：tick 程序活著、鎖握著、新 daemon 的第一格印 `busy:`；30 秒後正常接上。B 版：tick thread 跟著死、鎖立刻放、`sleep 30` 變孤兒、新 daemon 的第一格**直接開跑**，跟孤兒重疊。再試 B＋「鎖 fd 傳給任務」看是否回到 A 的行為。
- **分出**：使用者方向 3「重開要管」在 B 下要多付什麼。

## E3：daemon 跑 daemon 在 B 下長什麼樣（半天）

- **做**：用 E1 的假 daemon，試把「一項」設成另一個 daemon。
- **看**：做不到——下層 daemon 要自己掛 FUSE、自己當身分，不能是 thread。所以 B 一定要留一條「一項是程序」的路。
- **分出**：B 是否自動退化成 C。這題其實不用跑就知道答案，但半天的原型能讓它變成「看到的」而不是「說的」。

## E4：A′（daemon 省掉 aos-exec）（兩小時）

- **做**：scratchpad 版 `aos_daemon_run.run_once()` 改成 import `aos_exec` 的函式直接開 inst 的 argv（不 Popen aos-exec）。
- **看**：每格從 42 ms 降到 17 ms；`tests/test_daemon_*.py` 哪幾條要改（預期只有看 `exec=` 輸出格式的不用改、看 stderr 標頭的要對一下）。
- **分出**：A 的「免費優化」是不是真的免費。

## E5：FUSE `me` 連結認身分（一天，可跟 plan9 實驗 B 併）

- **做**：用 03 的 60 行 C FUSE 擴成「`insts/<項>/ctl` 可寫、`status` 可讀」，每個工作資料夾放 `.aos/d` → 掛載點、`.aos/d/me` → 自己那項。任務用 `echo do > .aos/d/me/ctl`。A 版任務在 tick 程序底下、B 版任務在 thread 底下，各跑一次。
- **看**：daemon 從「被寫的是哪個檔」認出是哪一項，不看 pid；兩版行為相同。再故意讓 B 版 tick lib 自己去寫 `.aos/d/me/ctl`，看會不會自鎖。
- **分出**：使用者方向 5「環境變數在 FUSE 下有更好的方法」是否跟 A／B 無關；B 的「daemon thread 不能碰自己的樹」是不是真坑。

## E6：fork server（半天，只在考慮 E 路線時做）

- **做**：daemon 一開始、開 thread 之前 fork 出 zygote（import 好 `aos_tick`）；daemon 經 pipe 送 `tick <dir>`，zygote fork 孩子跑 `run_tick`、`_exit`。
- **看**：每格成本（預期 1 ms 以下）、`ps` 看得到每格、`kill` 得掉。
- **分出**：留在 Python 時，E 能不能用 1/20 的成本保住全部 POSIX 優勢。

## 建議順序

1. **E1＋E2**（一天）：直接回答「B 要付多少」與「B 的重開語意」。
2. **E4**（兩小時）：不管選哪個都划算。
3. **E5**（一天）：跟 plan9 那條的 FUSE 實驗合併做，不重複。
4. E3、E6 看前面結果再決定。

做完 1 與 2，使用者手上就有「B 原型跑起來的樣子」與「A′ 的數字」，可以憑感覺拍，不用憑這份報告。
