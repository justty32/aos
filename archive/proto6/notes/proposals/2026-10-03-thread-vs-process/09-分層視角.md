# 九、用使用者的四層重看：哪些取捨漏到上層，哪些留在運行層

← [入口](README.md)｜上一份：[外部先例](08-外部先例.md)｜使用者的分層原文：[aos 的分層](../../2026-10-03-aos-layering.md)

使用者 10-03 的分層：**daemon 是運行層**（aos 與 Linux 的介面）→ **aos 時空**（檔案系統＝空間、tick＝時間；tick 是一個動作，形式無所謂，inst JSON 只因為在 Linux 上最通用）→ **kernel**（排程與資源管理依託時空）→ **agent**。照這個分層，「程序或 thread」是運行層的實作選擇；要問的不再是「失去哪些 POSIX 優勢」，而是**哪些取捨會改變上層看得到的語意**。

## 時空對運行層的要求（上層看得到的契約）

從現行 spec 與裁定抽出來，tick 作為「時間」要成立，運行層至少要撐住四件事：

| 契約 | 出處 | 上層靠它做什麼 |
|---|---|---|
| T1 同一資料夾時間不分叉：一次一格、格與格不重疊 | B-602 | kernel 說「給你 10 格」、agent 讀 `last/` 當上一刻 |
| T2 一個動作要嘛完整（`ended:true`、`seq`＋1）、要嘛沒發生（busy、擋板，不佔號） | B-633、第十八批 | 以 `seq` 當時間軸；中途被殺看得出來 |
| T3 空間永遠讀得到：`.aos/` 與 FUSE 樹不因某一格出事而消失或卡住 | 方向 1 | kernel／agent 全靠讀檔與寫檔 |
| T4 誰都能推進時間（人手、cron、daemon 跑一格沒差別） | B-627 | 除錯、重播、不綁 daemon |

## 逐項：留在運行層，還是漏上去

| 取捨（[01](01-POSIX優勢拆解.md) 的編號） | A | B | 漏到哪一層 |
|---|---|---|---|
| 啟動 17～42 ms、16 MB（換到的） | 付 | 省 | **運行層**。只有週期降到百毫秒級時才變成時間粒度的下限，漏進時空 |
| spawn 機制、GIL、fd 表（8、14） | — | — | **運行層** |
| `ps`／`strace` 可觀察（9） | 留 | 半 | **運行層**。上層本來就該從 `current/record.json` 與 FUSE 樹看「在不在格裡」，不該看 ps |
| 鎖怎麼做（flock vs 程序內） | flock | flock 照用 | **運行層**。鎖檔本身是空間的一部分，兩案不變 |
| 認身分（pid／tid／`me`） | pid | tid | **不漏**。`me` 連結是空間的概念，兩案通用 |
| 環境變數 `AOS_DAEMON_*` | — | — | 本來就是 Linux 側的洩漏；FUSE 把它收回空間，跟 A／B 無關 |
| tick 可換語言（2、10、16） | 留 | 失 | **運行層**。使用者說形式無所謂；但 C++ 改寫的分段是運行層自己的工程題 |
| daemon 死後格照跑、鎖照握（13） | 留 | 失 | **漏到時空：破 T1、T2**。B 下 daemon 死＝格被攔腰切、鎖立刻放、任務成孤兒；新 daemon 下一格跟孤兒重疊（時間分叉）。補法：鎖 fd 傳給任務（[03](03-實測.md) 第三節實測可行） |
| tick 當掉不拖垮 daemon（3） | 留 | 失 | **漏到時空：破 T3**。B 下 tick lib 卡住或碰自己的 FUSE 樹會卡住整棵樹；A 下只壞那一格 |
| tick 可殺（4） | 留 | 失 | **半漏**。「一格卡住」在兩案都能靠殺任務解；A 多一個直接殺格的手段。kernel 要殺的是計算（任務），不是格（T-06） |
| 資源與帳號邊界（5、6） | 可包在 tick 外 | 只能包任務或整個 daemon | **漏到 kernel**：資源管理的最小單位。A 有「資料夾」這一級，B 只有「任務」與「daemon」兩級 |
| 一項是 inst 還是資料夾（15） | inst | 資料夾 | **漏到 kernel**：kernel 替成員登記的是什麼。inst 能登記任何程式（含下層 daemon、LLM 服務）；資料夾只能登記 tick |
| daemon 跑 daemon（[02](02-分層.md) 第四列） | 自然 | 要破例開程序 | **漏到 kernel**：多層 kernel（T-06）要靠上層把下層世界當一項跑；B 不留程序路就做不到多層 |
| 人手跑 tick 與 daemon 跑一樣（11） | 同一支程式 | 同一份 lib、兩個入口 | **碰到 T4**，但只要同一份 lib 就守得住；代價是兩條路兩套測試 |

## 讀法

- **留在運行層的**：速度、記憶體、GIL、觀察手段、鎖的實作、tick 的語言。這些使用者可以憑工程喜好選，上層感覺不到。「tick 是程式還是 lib 都可以」在這一欄完全成立。
- **漏到時空的**：daemon 被殺時格的完整性（T1、T2）與空間不卡（T3）。B 不是做不到，是要**另外做**：鎖 fd 傳任務、tick lib 嚴禁碰自己的樹、卡住的格要有人殺任務。A 靠程序邊界白得。
- **漏到 kernel 的**：資源邊界的粒度、一項能登記什麼、能不能多層。這三項決定 kernel 提案（[10-02 kernel](../2026-10-02-kernel/README.md)）的形狀，是真正要使用者拍的。

## 對「inst JSON 只是 Linux 上最通用」的回應

同意。所以 inst 的地位應該是**運行層的單位**，不是時空的單位。時空的單位是資料夾與格。這樣分之後，三個選項可以重寫成：

- A：運行層的單位是 inst，tick 是 inst 的一種。
- B：運行層的單位是資料夾，inst 只剩任務層在用。
- C：運行層兩種單位都收。

B 把運行層的單位收窄到資料夾，等於讓運行層只會「跑格」，不會「跑任何程式」；kernel 想在同一個 daemon 下掛一個不是格的東西（下層 daemon、常駐 LLM 服務）就沒有地方放。這是 B 漏到 kernel 的那條，也是為什麼它在多層時會退回 C。

## 一句話

照四層看，thread 與程序的差別大多留在運行層；會漏上去的只有三類：daemon 被殺時時間會不會分叉（時空）、空間會不會因一格卡住（時空）、kernel 能用的最小單位是什麼（kernel）。A 三類都白得；B 第一、二類要補做，第三類要留程序路才補得回來。
