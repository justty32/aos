# 五、第四、第五條路

← [入口](README.md)｜上一份：[改動清單](04-改動清單.md)｜下一份：[裁定對照](06-裁定對照.md)

A、B、C 之外還有幾條。每條講長相、好處、代價、什麼時候值得。外部先例與來源另見 [08-外部先例](08-外部先例.md)。

## D：常駐 tick worker（每個資料夾一條長命程序）

- **長相**：daemon 開一項時只開一次 `aos-tick --serve <dir>`，之後不再 exec。worker 自己迴圈：等叫醒（讀 FUSE 樹裡自己那項的 `wait` 檔、或 stdin 一行、或 SIGUSR1）→ 跑一格 → 再等。daemon 想叫它跑就寫它的 `do`。
- **好處**：程序邊界全留（[01](01-POSIX優勢拆解.md) 十六項全在），每格零啟動成本，鎖可以常握。
- **代價**：tick 從「被執行一次的程式」變成「有迴圈的服務」，翻 T-07 的意思；worker 死了誰重開（daemon 又要管程序）；N 個資料夾＝N 條常駐程序，記憶體從「同時幾格」變成「有幾項」，跟「idle 不常駐」的規模目標相反。
- **何時值得**：某幾個資料夾週期很短（秒級）時，只讓那幾個常駐。

## E：fork server／zygote

- **長相**：daemon 一開始、**還沒開任何 thread 之前**先 fork 出一條單執行緒的 zygote，裡面 import 好 `aos_tick`。之後 daemon 每格送一行 `tick <dir>` 給 zygote，zygote `fork()` 一個孩子，孩子 `chdir`、呼叫 `run_tick()`、`_exit(碼)`。孩子是真程序。Python 的 `multiprocessing` forkserver 就是這個形狀。
- **好處**：每格成本從「啟動直譯器＋import」（17 ms）降到「fork 一次」（未實測；fork 一支 16 MB 的 Python 程序估計 1 ms 以下），同時保住隔離、可殺、ps 可見、每程序 cwd／env。
- **代價**：多一條程序與一條管道協議；zygote 必須單執行緒（第十二批那句話）；tick 改版要重開 zygote；C++ 下用處小，因為 C++ 程序啟動本來就便宜。
- **何時值得**：留在 Python、而且量到每格 17 ms 真的礙事時。現在不是。

## F：讓程序成本趨近零——極小 C／C++ tick

- **長相**：不改架構，只把 `aos-tick` 換成 C++ 寫的。這本來就是 plan 第六段。
- **好處**：每格啟動約 0.3～1 ms（[實測](03-實測.md) 的 C 靜態／動態程式），thread 的速度優勢消失；全部 POSIX 優勢保留。
- **代價**：就是 C++ 改寫本身的工。JSON 讀寫、指示詞展開（`$ref`、`$fmt`、`$env`、`$opt`）要在 C++ 重做。
- **何時值得**：已排定要做；它讓「為了速度選 B」這個理由在 C++ 時代不存在。

## G：A′——daemon 省掉 aos-exec 那一跳

- **長相**：daemon thread 不再 `Popen([aos-exec, inst])`，改成 import `aos_exec_run` 的函式直接開 inst 的 argv。語意完全一樣（aos-exec 本來就只是「讀 inst、Popen、寫 exit」）。
- **好處**：每格少 25 ms（aos-exec 的啟動比 aos-tick 本身還貴，[實測](03-實測.md)）、少一個中間程序；一條裁定都不翻。
- **代價**：aos-exec 的「自己被訊號結束不轉送」那段變成 daemon 的事；daemon 多 import 幾個模組。
- **何時值得**：隨時。它是 A 的免費優化，也是 C 的程序路。

## H：rfork 式「選擇性共享」（只當思考工具）

Plan 9 的 `rfork` 可以逐項選要不要共享記憶體、fd 表、環境、namespace（憑記憶）。Linux 的 `clone()` 旗標也能選，但 Python 碰不到、glibc 不建議。它提醒我們：**thread vs process 不是二選一**，問題是「哪些東西要各自一份」。對 tick 來說要各自一份的是 cwd、env、fd 表、可殺性；要共享的只有程式碼。這正好是「程序」的定義，所以 Linux 上答案還是程序。

## I：FUSE 與程序模型的其他組合

| 組合 | 樣子 | 一句評語 |
|---|---|---|
| FUSE 樹 ＋ A | daemon 掛樹、thread 開 tick 程序；任務用 `me` 連結講話 | 最直接；tick 程序碰自己的 `d/` 沒有自鎖問題 |
| FUSE 樹 ＋ B | 同上但 tick 是 thread | 要守「daemon thread 不碰自己的樹」；tick 有 bug 會卡住 FUSE loop，整棵樹 hang |
| FUSE 樹 ＋ D | worker 用 `cat me/wait` 擋著等叫醒 | 最 Plan 9，但翻 T-07，且 blocking read 跟「一格」原則打架（[plan9 03](../2026-10-02-plan9/03-daemon變成檔案伺服器.md)） |
| 沒有 FUSE，只用普通目錄＋inotify | `echo do > .aos/d/tick` 是普通檔，daemon 用 inotify 盯 | [astra 03](../../reviews/2026-10-03-astra-alt/03-plan9-alt.md) 的路；零依賴，但讀 `status` 要 daemon 事先寫好，沒有「讀的那刻才算」 |

## 一句話

要「每格便宜」有 E、F 兩條都不必放棄程序；要「daemon 不開程序」只有 B，而 B 在 daemon 跑 daemon 時又站不住。最便宜且不翻裁定的一步是 G（A′）。
