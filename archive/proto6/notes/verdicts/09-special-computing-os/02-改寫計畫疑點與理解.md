## spec 改寫計畫的先定疑點（同日）

題號對應改寫計畫第七節。

- **Q1 正本：主規格是正本**（方案 A），行為規則寫在主規格，協議篇只留欄位、JSON、schema、範例與連結。
- **Q2 各 kernel 自訂：正式開放**。kernel 可以自己登記任務種類（kind）與資源名稱，schema 的列舉跟著放寬。
- **Q5 熱重載：只收 SIGHUP**，同帳號或 root 才發得了；不開 IPC。
- **Q7 牽涉 helper 的欄位**（其他帳號的額度、佈建權）**改了仍要重開**；其餘照即時改。
- **Q14 排空停機：用設定決定 SIGTERM／Ctrl-C 走排空還是立即停**，不開 stop IPC。
- **Q22 tick 系統性任務算基底的範圍：三者都算**——任務表的 `kind:system`、tick 自己做的事（回 -32601、投件、刪原件、鬧鐘、發布摘要、清 task 框）、aos-clean。範本裡的 kernel 設定檢查從 `kind:system` **改成 kernel 類**。〔已被第十九批取代：基底範圍縮到三件核心，其餘屬標準配備或掛載，見[第十九批](../10-tick-minimal-core.md)〕

其餘疑點（Q3、Q4、Q6、Q8～Q13、Q15～Q21、Q23～Q33）由記錄者依「最少改動、與已定方向一致」預填，使用者看過只改了 Q19，其餘照預填：

- **Q19 node 自己的逃生口（使用者改）**：做成**可調的設定，預設不管** node 自己開的子框——daemon 重啟、解除登記時都不殺；可設成要殺。
- Q3 父配額公開檔保留（子層要往下分）。Q4 通用外部資源池延後，隨外殼一起。Q26、Q29 屬 agent 機制，延後。
- Q6 能即時改的照套、其餘回報要重開。Q8 頂層額度縮小：下一格授權不過就停格並寫事項。Q9 前綴比名稱、排除 UID<1000、保留首次建立後綁定 UID。Q10 換父：被搬的那棵先暫停並全空，新舊兩父都要同意。〔已被第十九批取代：換父改寫成搬資料夾或覆蓋登記，管轄權跟資料夾，見[第十九批](../10-tick-minimal-core.md)〕Q11 pause 不加連子樹。Q12 頂層 roots 增刪只走熱重載。Q13 `disable` 即時改。
- Q15 排空時已登記 node 照常開格，只拒新 once 與新成員。Q16 到上限轉立即停、在途記 unknown，預設上限 10 分鐘，排空途中再按 Ctrl-C 改立即停。
- Q17 調低上限的紀錄寫在 kernel 自己的資源狀態檔。Q18 自建子樹總上限由部署者設在更上一層。Q20 空框在逐層重建完、仍沒人登記才刪，多帳號下由 helper 刪。Q21 helper 加「刪殘留框」，不加遞迴改群組與 chmod，群組名受前綴限制。
- Q23 看 `/proc/self/cgroup` 判斷、不在框回 2〔已被第十九批取代：拒跑已撤，見[第十九批](../10-tick-minimal-core.md)〕、只限 tick、「立刻跑一格」用 wake 加等格次序號。Q24 投件權即執行權**會傳遞**，key 只對整條鏈以外的帳號保護。Q25 主人帳號接件時記下，once 自己的 user 不算主人。Q27 壞件用同一 issue_id 記已報過，只算 `requests/`。Q28 補投回應從 git 歷史撈，本地動作 stdout 存 `.stdout` 檔。
- Q30 放寬持久檔與檔案 RPC、daemon IPC 維持嚴格，要「永遠禁止的鍵」清單，轉檔指令 `aos migrate`（含 daemon state 與設定）。Q31 每次呼叫 git 帶 `-c core.fsync=committed,reference`。Q32 容量與保留期都設（預設 1024 筆／24 小時），手動清除可整棵子樹。Q33 `aos work trace` 請求 ID 與 attempt ID 都收。
- 編輯決定：unregister 的 TERM→寬限→kill 改叫「收尾」，「排空」只留給停機。

## 記錄時的理解（不是使用者逐字裁定）

有疑問以使用者後續裁定為準。

- 第 3、4 條合起來的讀法：aos 本身只提供讓各 kernel 定義抽象／資源／隔離的框架，加上一個最小的「可排程計算」外殼（能被 Linux 啟動、限制、殺掉，結果交回檔案）；各 kernel 在外殼上定義自己的任務種類。
- 第 5 條的讀法：上層只用它自己認得的資源與規則管下層，不要求下層配合或知情；Linux 管的部分（cgroup、帳號）因為本身是巢狀的，天生不可能比上層寬，第 5 條的「可以更寬」指的是 kernel 自己定義、Linux 管不到的那部分。
- 第 6 條的「隨機性」要怎麼量、怎麼跟完成度與消耗權衡，本批沒定。
