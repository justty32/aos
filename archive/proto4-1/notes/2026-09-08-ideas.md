## 1. 使用者原話（依序）

> 把 proto4 的 kernel 改成直接執行 inst。我預期的行為是每次tick xxx，就是cd到xxx這個資料夾，然後執行./.aos/inst。錯誤碼、stdin/out/err、環境變數這些，可以看.aos/config.json
> 喔喔還有user等
> 反正執行inst的時候的各種設置都在.aos/config.json
> 然後config.json會有不同版本，也可以是空的。沒被設置的，daemon就默默吞掉，比如錯誤碼/stdin/out/err，環境變數則是繼承
> 趕快做好，這只是個小程式，放到proto4-1
> 直接用python吧
> 基本上就是參考proto2，但是吸取教訓

## 2. 我的理解與做法

- 這一版**不是**「資料夾模擬 lisp」的延續，是「kernel 對資料夾做的唯一一件事＝跑它的 `.aos/inst`」這條線的原型，語言換 Python 是因為要快。proto4 的 Janet 版留著不動。
- `.aos/config.json` 是**執行 inst 的全部設定**，集中一處：args、env、stdin/out/err、exit 對照、user、interval、timeout，加 `version`。設計原則是**沒設就吞掉**（stdio 丟 /dev/null、任何退出碼都不算錯），只有環境變數例外（一律繼承再加）。
- 直接執行的判準照 proto4 筆記第 6 節：執行位＋（`#!` 或 ELF）才直接 exec，否則退回 `/bin/sh`。
- daemon 照 proto2 的樣子（家、requests/done、state、start/stop/ls），教訓折進去的清單在 README。
- `exit` 裡的 `pause`／`unregister` 是 inst 對 kernel 講話的唯一管道：用退出碼說「把我暫停」「把我註銷」。這是新加的，C++ 版要不要留看使用者。

## 3. 給 C++ 版的備忘

- 單進程單 kernel，同步一格一格跑，`chdir` 在子進程裡做（posix_spawn 的 chdir 或 fork 後 chdir）。
- 檔案格式（config.json 欄位、state.json、procs.json、請求／回覆 JSON）照 README 那張表，C++ 版對齊就能用同一組測試資料夾。
- 沒解的：`user` 換身份要 root；SIGHUP；併發客戶端；inst 改寫自己的 inst 要「先寫暫存再 rename」（第 6 節講過，這版沒強制）。
