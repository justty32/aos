# 試玩報告 r2 — opus

**總評：** 上一輪那些會讓新手卡死的坑幾乎都補起來了，這次我從零到第一支自己寫的程式跑完、被 kernel 收走，中間沒有一次需要去翻原始碼。剩下的問題集中在「東西排錯了之後怎麼辦」——kernel 只能加不能刪，而且會安靜地讓一個永遠失敗的行程轉一輩子。

## 1. 只看 README 架起來

四個指令、不到一分鐘，一次過，沒回頭翻第二次：`aos-daemon &` → `aos-kernel-init K --ncpu 2` → `aos-kernel-boot K` → `aos-kernel ls K`。`init` 跑完直接印出「下一步是什麼」的三行提示，這招很有效。cpu 也真的自己掛上，我第一次 `ls` 看到「沒插上」以為壞了，等四秒就變 running 了。

- 現象：`aos-kernel-boot` 第一行印 `ok=True result={"pid": …}` 一整串。→ 我期待：只要看到第二行那句「開機了」。→ 建議：那串 raw dict 收到 `--verbose` 後面。
- 現象：README 教了怎麼上電，但從頭到尾沒提怎麼關機；`aos-daemon-ctl stop` 我是靠 `--help` 才找到的。→ 建議：`./aos-daemon-ctl stop # 關機` 補在 `./aos-daemon &` 旁邊。
- 現象：README 開頭五行全是 `../proto4/notes/…` 的規格連結。→ 建議：那段搬到最下面當「出處」。

## 2. 寫自己的逐步 lisp

寫了六個 form，手動七格跑完（第七格回 100），一次就對。`--reset` 後排進 kernel，兩秒被排上 cpu0，五回合跑完自己進 `procs/done/`。

- 現象：`:json true` 解出來的 key 是字串（`@{"count" 3 …}`），不是 keyword。→ 建議：`:json` 那段加「key 是字串」。
- 現象：`aos-step` 每格會把該 form 的回傳值印到 stdout。→ 建議：一句「每格會印出這個 form 的值」。
- 現象（相對路徑）：`cwd:"proc1"`、`argv[0]:"../../…/aos-step"` 被解成 `/tmp/home/lorkhan/…` 而失敗。cwd 跟 argv[0] 的基準不同。→ 建議：README 補「cwd 以 inst.json 所在資料夾為準，argv[0] 以 cwd 為準」。
- 現象：錯的時候訊息非常好——`argv[0] 指的檔不存在：…`，而且先檢查完才排。→ 純誇獎，別改。

## 3. 故意弄壞五樣

- (a) 少寫 `cwd`：`aos-exec` 直接跑回 rc=2、畫面全白；加 `--stderr -` 才看到。`aos-kernel add` 則安靜地幫我補成 inst.json 所在的資料夾。→ 建議：七欄那張表講清楚哪些可省、省了等於什麼。
- (b) 不寫 `stderr` ＋ 錯字：加 `--stderr -` 得到 `aos-step: 第 1 個 form（0 起算）失敗：…`——夠清楚。後來才發現 `--status` 的 `:error` 也有完整 stacktrace。→ 建議：proto4-4 加一行「卡住就 `--status`，錯誤全文在 `:error`」。
- (c) 跑到一半插一個 form：警告講了現象、原因、下一步，這條完美。
- (d) daemon 沒開／家沒灌：`aos-kernel-boot` 兩種都擋，直接把該打的指令印出來。但 `aos-kernel ls 不存在的家` 吐的是 `[Errno 2] No such file or directory`。→ 建議：把 boot 那句話共用到 `ls`／`add`。
- (e) 同名排兩次：`名字已經存在或正在 cpu 上：阿明`，rc=1。

**額外撞到的兩件（比上面五件都嚴重）：**
- `aos-kernel add` 的事前檢查不驗欄位。我排了一份含 `timeout_ms` 的 inst.json，add 說「排進去了」，結果 aos-exec 每回合都回 125（`不認得的欄位 'timeout_ms'`），跑了 256 次沒人管，`procs/bad/` 一直是空的。→ 建議：add 直接叫 aos-exec 的驗證器；125 應該算 bad 不算 running。
- 沒有辦法把一個行程從 kernel 上拿掉。最後是自己去手寫 `K/cpus/0.json` 塞一個 `exit 100` 才騙它收工——這完全是內臟。而且事後 `ls` 把我硬殺的那個當成「做完了」。→ 建議：補 `aos-kernel rm K 名字`（含正在 cpu 上的）。

## 4. 五個問題

- ① 5：四個指令上電，寫程式再兩個。從讀完 README 到 `report.txt` 出現大概五分鐘。
- ② 4：`aos-kernel ls` 的欄位叫 `PID` 但裝的是行程名字，隔壁 `aos-daemon-ctl ls` 的 `PID` 才是 OS pid。建議改叫 `PROC`。`procs/done/` 我以為是「成功做完」，實際只是「不再跑了」。
- ③ 3：正常路徑藏得乾淨。一出錯就漏光：要停一個行程得知道 `K/cpus/N.json`、done_exit=100 這個約定。`aos-kernel ls` 看不到 exit code，要去 `aos-daemon-ctl ls` 才看到 `LAST_EXIT 125`。
- ④ 3：六個字就夠日常。洞：沒有 rm；沒有「健不健康」的顯示；kernel 的 ls 跟 daemon 的 ls 兩張表欄位不一樣。
- ⑤ 4：真正要記的只有一句「看不到東西就加 `--stderr -`」。扣分是 done_exit=100 這個魔術數字沒有名字。

## 前五名最該改的

1. 加 `aos-kernel rm K 名字`（含正在 cpu 上的）。（中）
2. `add` 要用 aos-exec 的驗證器驗欄位；連續回 125 的行程要進 `procs/bad/`。（中）
3. `aos-kernel ls` 加一欄 LAST_EXIT。（小）
4. README 補三句話：怎麼關機、cwd 可以省略時預設哪裡、`cwd` 與 `argv[0]` 的相對基準不一樣。（小）
5. `PID` 欄改叫 `PROC`；proto4-4 補一行「卡住就 `--status` 看 `:error`」。（小）
