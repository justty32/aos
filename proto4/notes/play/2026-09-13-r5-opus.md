「故意弄壞」玩了五樣：永遠等不到檔（會讓出 cpu ✓）、Python 丟例外（訊息＋`job.py.error` ✓）、跑到一半插一格（會警告 ✓）、停 daemon 再丟 LLM 單（「已撤單」✓）、連續失敗 10 次進 `bad/`（✓，而且是我不小心撞到的）。

## 發現清單（改了對今晚的人幫助最大排前面）

1. **第 3 站重玩是死路**：`add` 說「名字已經存在」→ 照提示 `aos-kernel rm` 又說「找不到這個行程」→ 我是自己去翻 `$K/procs/done/` 手動 `rm` 才活過來。 **我期待**：README 的「玩法」那行就告訴我重玩要先清掉。 **建議**：`aos-kernel rm` 直接連 `done/`、`bad/` 一起清，或 README 玩法那行改成「`aos-kernel rm $K py-llm && rm -f $K/procs/done/py-llm.json`」。
2. **LLM 單撞名的行程 5 秒就被丟進 `bad/`**：錯誤訊息叫我 `aos-kernel llm rm`，但它每 0.5 秒重試一次、10 次就出局，我打字都來不及。 **我期待**：給我時間照它說的做。 **建議**：撞名這種「你要改設定」的錯不要算進 `bad_after`，或至少 README 先警告。
3. **`aos-user bob listen --once` 會秒回上一則舊回話**：說完新的一句馬上 listen，它把 outbox 從頭全印一次就退出（同一秒），看起來像 agent 在跳針。 **我期待**：只印還沒看過的，沒有就等一下。 **建議**：`--once` 加個「目前沒有新回話」的輸出，或只印新的。
4. **README 第 1 站的 `max_tokens` 那段是錯的**：我設 `max_tokens: 5` 問「用一句話說你是誰」，照樣吐了 329 個 token、`finish_reason` 是 `stop`——這個欄位根本沒被送出去。 **我期待**：文件說會空就要真的空。 **建議**：要嘛把 `max_tokens` 透傳，要嘛把那段改成「`max_tokens` 目前不支援」。
5. **daemon 停掉後 `aos-kernel ls` 亂猜原因**：印「找不到 daemon 的家：AOS_DAEMON_HOME 沒設？」，但我明明設了、資料夾也在，真正原因是它剛正常收工。 **我期待**：說「daemon 沒在跑」。 **建議**：分開判斷「沒設變數」和「沒在跑」。
6. **同一張表 `RUNS` 欄印出 `None`**：daemon 停掉那段時間看到裸的 Python `None`。 **我期待**：`-`。 **建議**：跟 idle 一樣印 `-`。
7. **`aos-kernel ls` 名字超過 4 個字就整排歪掉**：`json-wait 1.7s` 擠在一起，兩顆 cpu 的欄位對不齊，掃一眼很難看。 **我期待**：欄位對齊。 **建議**：PROC 欄寬度跟著最長名字走。
8. **`env.sh` 的開場橫幅沒展開變數**：印「kernel：$K   daemon 家：$AOS_DAEMON_HOME」。 **我期待**：印路徑。 **建議**：那行的單引號換雙引號。
9. **第 5 站退 101 差一次**：README 說「第四次開始等」，實際第四次還是退 0（那格是宣告要等），第五次才 101。 **我期待**：數字對得上。 **建議**：README 改成「第五次」。
10. **Python 例外的一行訊息指到 `def` 那行**：說「PROG 第 12 行」，但 `job.py.error` 的 traceback 指第 13 行才是真的出事那行。 **我期待**：兩邊同一個數字。 **建議**：一行訊息也用 traceback 的行號。
11. **第 6 站把 `max_steps_per_question` 改小之後救不回來**：`status` 一直 `stuck=yes`，再說話也是秒回「這題走了 2 格先停」。（答案是把數字改回 60 就好，但 README 沒寫。） **我期待**：README 告訴我怎麼解。 **建議**：玩壞那段補一句「改回去就好」。
12. **`aos-step-json` 跑成功完全不出聲**：連跑三次都是空白，不知道剛剛跑了第幾格、有沒有真的動。 **我期待**：一行「第 1 格 ok」。 **建議**：成功時印一行，或 README 提醒「沒消息就是好消息，用 `--status` 看」。
13. **README 說東西放 `~/aos-play/`，沒提可以換**：同一台機器兩個人同時玩會撞在一起。 **我期待**：知道有 `AOS_PLAY` 這個開關。 **建議**：開場那段補一句「想換位置就先 `export AOS_PLAY=...`」。

## 我實際跑過的指令（精簡）

```sh
export AOS_PLAY=/tmp/play5-opus && source playground/env.sh && playground/up.sh

# 1
cd $AOS_PLAY/stations/1-ask-once
aos-llm models endpoint.json
aos-llm call endpoint.json request.json result.json && jq -r .text result.json
sed -i 's|gemma-4-e4b|gemma-9-nope|' endpoint.json && aos-llm call endpoint.json request.json bad.json
echo '{"messages":[...],"max_tokens":5}' > s3.json && aos-llm call endpoint.json s3.json s3o.json   # 被忽略

# 2
cd $AOS_PLAY/stations/2-json-wait
aos-step-json prog.json; aos-step-json prog.json; echo $?     # 101
echo 開門 > go.txt; aos-step-json prog.json x3; aos-step-json prog.json --status
aos-step-json prog.json --reset && rm go.txt got.txt
aos-kernel add $K inst.json --name json-wait && aos-kernel ls $K

# 3
cd $AOS_PLAY/stations/3-py-llm
aos-kernel add $K inst.json --name py-llm && cat answer.txt
aos-step-py job.py --reset; sed -i 's/用一句話介紹你自己。/…/' job.py
aos-kernel add $K inst.json --name py-llm      # 撞名 → rm 也不行 → rm -f $K/procs/done/py-llm.json
aos-kernel llm ls $K; aos-kernel llm rm $K play-py-1
sed -i 's/…\["text"\]/1\/0/' job.py; cat job.py.error          # 例外訊息

# 4 / 5
cd $AOS_PLAY/stations/4-lua-b64 && aos-step-lua job.lua x3 && jq -c .state.blob job.state.json
cd $AOS_PLAY/stations/5-lisp && aos-step prog.janet x7 && jq -r .text answer.json

# 讓出 cpu：複製兩份 2-json-wait 排進去，json-wait 被踢回佇列
# 插一格：python3 塞一格進 prog.json → 「PROG 改過了（上次 3 個、現在 4 個）」

# 6
cd $AOS_PLAY/stations/6-agent && ./make.sh && aos-kernel add $K bob/inst.json --name bob
aos-user bob say "用 sh 工具看看你資料夾裡有什麼，然後告訴我"; aos-user bob listen --once
aos-user bob say "…隨便聊聊吧"; aos-user bob status
sed -i 's/60/2/' bob/agent.json && aos-user bob say "請一步一步做：…"   # → stuck=yes
aos-daemon-ctl stop && aos-user bob say "還在嗎" && aos-user bob status  # unread=1，沒偷跑
aos-step-py job.py            # 「kernel 沒回應；請求沒送出去，已撤單」
playground/up.sh              # 回來，bob 自己把積的信回完
playground/down.sh
```

補一句：第 6 站重複問同一句話**不會**撞名（單子叫 `bob-q1-s1`／`bob-q2-s1`…，按問題編號走），而且它第三次回答還會講「與上次相比，`messages.json` 變大了」——記憶是真的有接上，這站是六站裡最像「玩到東西」的一站。
