# 統一錯誤路徑：退出碼、一行訊息、「不確定」

使用者 10-09 16:10：錯誤路徑要統合。本文定全 aos 共用的一套；凍結的 llmcall 0～4、budget 0～3、核心 0／3／其他**都不用動**。退出碼表只放這裡與各包 ADVANCED.md（README 給第一次用的人，不出現退出碼）。

## 1. 現狀（各包各說各話）

逐包的退出碼 0～5 與訊息格式在 [blueprint-errors-items.json](blueprint-errors-items.json)（一包一列）。毛病四種：同一個數字意思不同（3 是 conflict／滿／不知道三種、4 有三種）；「你給錯」和「我做不到」混在一碼（三關的 2、mail 的 2）；「不知道」有的包沒有碼（wfnode、mail 把它算失敗、metrics 算成功）；訊息有的 stdout 有的 stderr、有的 JSON 有的純文字、前綴五種寫法。凍結的 llmcall 0～4、budget 0～3、核心 0／3／其他三家其實已經一致——統一表就是從它們抽出來的。

## 2. 統一退出碼表（全 aos 共用，只有五個）

| 碼 | 一句話 | 什麼時候 | 重跑？ |
|---|---|---|---|
| **0** | 做到了 | 要做的事確定完成（部分成功也算，細節寫在輸出） | 不用 |
| **1** | 做不到 | 確定沒做成，而且知道為什麼：終局失敗、被拒、滿了、撞名、同名不同內容、體檢沒過、前提不在（帳任務沒在跑） | 照訊息處理後再跑 |
| **2** | 你給的不對 | 參數、檔案形狀、用法錯；**什麼都沒動** | 改了再跑 |
| **3** | 不知道 | 沒法確定做到或沒做到：鎖忙、在途、讀寫故障、半路被殺、對方沒回；**該留的證據留著** | 照原樣再跑一次會接續 |
| **4** | 做到了但帳沒清 | 只給「交付」與「結帳」分兩步的包（現在只有 llmcall）：內容已交付、用量未知或超預留 | 不用重送；對帳 |

5 以上不用；127 留給「程式起不來」。argparse 的 2 正好是「你給的不對」。檢查型指令（`mail audit`、wfnode check）找到問題也用 1：沒過＝做不到。

## 3. 錯誤訊息：一行、白話、說怎麼辦

**人看的一行永遠在 stderr**，格式固定：

```text
<指令名>: <發生什麼，一句>。<怎麼辦，一句>
```

- `<指令名>` 用 `aos7-xxx`（半形冒號＋空格；拿掉全形冒號與「無法完成」）。
- 第一句說事實，不放代號、不放 spec 條號；第二句一定有，哪怕是「照原樣再跑一次」。例：`aos7-skills: 帳任務沒在跑。用 aos7-up 起的 node 才有帳；進階：aos7-budget ledger budget/llm`。
- 退出 2 的第二句要說「該給什麼」並附一個例子；退出 1 說「為什麼做不到」；退出 3 以「不確定：」開頭（見 §4）。
- **機器看的 JSON 照舊放 stdout**（既有欄位一個都不改，程式在讀）。規則只加一條：**有 JSON 也要有 stderr 那一行**；沒 JSON 的包（routines、skills、wfnode、metrics、mail）不必新加 JSON。
- 成功時 stderr 不印；`--help` 一屏、只列給人用的指令，退出 0。

## 4. 「不確定」怎麼表達

- 退出碼 **3**；stderr 一行以 `不確定：` 開頭，三件事說清：**沒確定什麼**、**留了什麼**（預留、請求、pending）、**怎麼接**（「照原樣再跑一次會接續」或「等心跳再試」）。例：`aos7-llmcall: 不確定：送出後沒等到回覆，預留留著、沒重送。照原樣再跑一次會接續；想放棄用 status 看證據`。
- JSON 裡維持各包既有欄位（`outcome:"unknown"`、`why:"unknown"`、`result:"not_yet"`）。
- 「不知道」**不能**降成 0 或升成 1：metrics 讀不了的檔仍算 0（它是量尺，行尾報缺口即可——唯一豁免）；wfnode 體檢「未完成」要退 3 不是 1；mail 的 OSError 要退 3 不是 2。
- 不確定時**不清證據、不重送、不猜**——這是核心 spec 既有原則，包照辦。

## 5. 各包要改什麼

只列不一致處，逐包在 [items json](blueprint-errors-items.json) 的 `change` 欄。要點：author（3→1、4→3、5→1）、author 三關（某關不過 2→1、分支衝突 3→1、4→3）、events（滿 3→1、4→3、加 `ack` 子命令）三家改數字，`why` 欄位不動；routines 用法 1→2；skills「帳沒在跑」3→1；wfnode 未完成 1→3；mail OSError 2→3；compact 未分類 1→3；budget `status` 沒帳退 1、`call` 與 llmcall 進門先看 `ledger.lock`、沒人持有退 1（不再無限等）；prompt、metrics 只補 stderr 人話與前綴；up 照本表，`ask` 逾時退 0 是藍圖代定。

## 6. 與凍結介面的關係

- llmcall 0～4、回條欄位、入口終局：**零衝突**，表 §2 就是它。
- budget 0～3：零衝突；只加 `status` 的 1 與 `call` 的「帳沒在跑」1（原本是等到天荒地老，不算改語意）。
- 核心 tick／tock 的「0／3／其他」：零衝突（其他＝1 或 2）。
- 唯一會破既有測試的是 author（3→1、4→3、5→1）與 events（3→1、4→3）：測試只改數字；`why` 欄位保留所以呼叫方（mail 讀 events 的 `why`、A5 學徒讀三關 JSON）不受影響——但 **A5 交件後**再改 author。

## 7. 不做

不做共用錯誤函式庫（每包幾行自己印）；不改 JSON 欄位名；不引進錯誤碼目錄；不把 warning 升成退出碼；不要求每包都出 JSON。驗收走 [分線](blueprint-simplify-teams.json) ER0 的一致性測試：每包 `--help` 退 0、壞參數退 2 且 stderr 一行含指令名與「。」、不確定案退 3 且以「不確定：」開頭。
