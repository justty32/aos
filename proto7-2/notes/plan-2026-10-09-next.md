## 1. 目標（一句話）

**一個真 AI 學徒，收到需求後自己寫候選、過三關、發布成 step 工作、跑完、檢查答案；每次呼叫都有帳、有事件；壞候選、模型超時、usage 缺、預算滿、程序被殺，都被系統擋下或接回，不雙跑、不偽裝成功。** 外加一條非控制用途的 adapt-llm 證明「慢答案仍有價值」。

## 2. 驗收長什麼樣（R2 逐條給燈號）

1. **全自動一整圈**：CSV 與 JSON 兩種題型各 ≥10 單，從 `send` 到 `close` 不用人按（`serve` 跑手，自動發布只給 grant 白名單）；記通過率、token、延遲。
2. **故障被擋下／接回**（真 AI 線路各 ×3）：壞 JSON 候選、白名單外工具、usage 缺（pending、退出 4）、U>R（overrun 記帳）、預算 denied／events must full（停在 waiting）、LiteLLM 逾時／5xx／遲到回覆（unknown 留 R、adopt 接回）、intent 後／發布前／step 子程序 SIGKILL（接回不重問不重發）。
3. **帳＝事件**：`aos7-events usage` 彙總與 budget 帳對得上，差額列成缺口。
4. **adapt-llm** 100 回合：過期拒收率、有效交付率、採用時來源年齡三個數字，消費端不凍結在過期 ok。
5. **核心不多跑**：回合身分三窗口 SIGKILL ×3 不多跑不少跑。
6. **全套 ×3 綠**、astra-8 回歸報告、ELI5 進度圖、消耗報告＋建議限制表（暫定、待使用者）。

## 5. 代定（頂層核）

- **真 AI 模型名**：LiteLLM 上只有 `chatgpt-gpt-6-sol`／`-astra`／`-luna`／`gpt-reserve`（**沒有 6.1-sol**；帶 `-high`／`-max` 調推理）；預設 `chatgpt-gpt-6-sol-high`，比較加 astra-high；不用 lm-*／ollama-*。上限拉滿，但每隊寫死呼叫次數 gate 免失控：A2 ≤20、A3 ≤100、D1 ≤100、R2 ≤200。一律走 llmcall（有帳有事件），不准直打 LiteLLM。
- adapt-llm 第 5／10 題照預設（within_age；有限欄位＋必要否定＋獨立答案）；call_id＝sense＋來源版本雜湊，同版本不再問。
- 事件第二段只做消耗事件＋usage 報告；多消費者 ack 不做。
- budget `on_overrun` 預設 `record`（今天實跑不擋）；`hold` 要人手 `reconcile`。
- 回合身分：daemon 世代＋登記世代＋回合號；C0 核過才開 C1。
- 學徒自動發布只給 grant 白名單（llm1 第 3 題不翻）；壞候選重問上限預設 1。
- 限制表只建議不生效；kernel 任務包、集中事件、多端點仍不排。

## 6. 規則與保護

- 交接書：開頭「可開 subagent 最多 4 條」；範圍＝json 領地、其餘不得寫（含 `proto7/user-advice.md`、`tests/_proc.py`、wf hub 檔、R1 的檔）；件數／容量 gate 照 json。工人不 commit；隊長 `git commit <路徑>`（`bin/` 要 `-f`）、交棒前 rebase；頂層 ff-merge＋push。
- 呼叫：寫碼 `codex exec -m gpt-6.1-sol -C ../aos-wt/<隊> -o <out.md> - < task.md`；審查／起草 `codex exec -m gpt-6-astra -c model_reasoning_effort="high" -s read-only -C <目錄> -o <out.md> - < task.md`。
- 測試容量：全套同時 ≤3 份（16 核的物理上限，額度充裕也一樣）；開發中只跑自己的測試檔，一律 `systemd-run --user --scope -q -p TasksMax=300 -p RuntimeMaxSec=1200`（全套 800）。真 AI 呼叫 deadline 600 秒。
- 鐵律：改碼同步 code map；方向性題不停線、回報頂層代定並記代定清單；R2 發現只記不修。
