# 學徒自我改進對照實驗 意圖卡（AP5）

← [intents](README.md)｜上一輪 [apprentice-4](apprentice-4.md)

**①解決什麼**：AP4 沒證明「學徒用上自己前面留下的技能、所以第 N 題做得更好」，原因兩個：弱模型一半的輪次卡在候選 JSON 括號手滑（不是知識，記不住），題目的坑又都寫在需求裡、強模型第 1 題就過（沒東西可記）。這輪把兩個原因各拆掉一個：
- 交件可以用「每個檔一段文字」（`=== 路徑 ===` 分隔），不必把整包程式碼塞進一個 JSON 字串。
- 新出 4 題，都讀**真的 aos mail 郵局資料夾**（用 `aos7-mail` 真寄真辦產生）。郵局有 3 條慣例**需求裡不寫**：辦結的信歸檔在 `<人>/inbox/done/`、`.` 開頭的檔與資料夾（如投遞到一半的 `.tmp/`）不是信、根目錄的 `teams/` 是團隊資料夾不是人。答案檢查器的錯誤訊息會講出是哪個情境答錯，所以只能從第 2 關的錯誤學到；4 題每題都會撞到同樣 3 條。
- A 組每題從零；B 組每題後 `learn --skill-into` 改寫技能書、下一題 `propose --skills` 帶進提示。先用 luna 與 sol-low 各試，挑差異清楚的那個加到每組 ≥5 次。題 1 兩組條件相同，兩組題 1 的差當雜訊；第 2～4 題的差要大於它才算證明。

**②必要的副作用**：暫存學徒 node 在 /tmp（budget 帳＋llmcall 紀錄，收尾刪）；真 AI 呼叫（學徒、審查 `chatgpt-gpt-6-astra-high`，全走 llmcall 記帳，token 上限用模型上限）；三關沙箱；證據存 `notes/play/2026-10-09-real-ai/evidence/apprentice5/`。

**③不做**：不發布 `apprentice/` 分支（「過」＝propose 三關含審查都過）；不給學徒答案檢查器原始碼；不改 skills 挑書規則；不改 LiteLLM；不把 3 條慣例寫進需求或工具卡。

**④對照現狀多出來的**：
- 三關收「每段一個檔」的文字候選：開頭不是 `{` 就照文字格式拆（`=== 路徑 ===` 是檔、`=== row ===`、`=== report ===` 是索引列與 REPORT；v／rid／kind／name 取自需求）。JSON 候選照舊，三關照舊 → **保留**。
- `propose --format text`：提示改說文字格式、候選存 `.txt`；不給時提示一個 byte 都不變 → **保留**。
- 4 題 mail 範例（`examples/aos-tool-mail*`）與 fixture 重造腳本 → **保留**（之後量自我改進可以重用）。
