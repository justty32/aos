# 抽屜（L1／L2）與信件分層 種子卡（待 Fable 發想）

← [intents](README.md)｜相關 [scaffold](scaffold.md)、[brain-memory](brain-memory.md)、[skills-local-pick](skills-local-pick.md)

使用者 10-10 凌晨提的想法，**還沒發想、沒定案**。明天交給 Fable 擬意圖卡與藍圖。

**① 信件就是 agent 之間的通道**：`ask` 等於寄一封信，跟 wf/inbox 的協議同類；真人也是一個 agent，只是權限最高。要回答的問題：
- 多 agent 合作是否都走信？同級之間能不能寄？還是只能上級寄給下級？
- 讀寫權限要怎麼管？現況：郵局裡誰都能寄給任何人，權限只靠檔案系統；mail 已經有團隊信箱和 `--up`。
- 先辦哪封信：現況只按時間先後（`fifo`）。以後能不能依寄件人、優先級排序？還是取信改成專用工具，讓各 agent 有自己的取信規則？

**② 抽屜整合**：技能目錄和記性目錄本質相同，都是「東西放旁邊、只給 AI 看目錄、AI 要哪個再拿出來」，可以統一成同一種抽屜，再分類：工具、過去的事、自訂（什麼都能放）。
- 類比快取：L1＝重要或最近的東西，直接放進提示（例如 STATE、最近幾則）；L2＝只放目錄，AI 要了才拿；其餘＝連目錄都沒有的一般儲存（例如 compact 封存箱）。
- 現況對照：L1＝STATE、前幾步軌跡；L2＝技能目錄、記性 INDEX（AI 可以回「要檔案：」）；最底層＝notes/done 原文、compact archive。差別在於：技能由程式在本機挑，記性則是程式挑加上 AI 自己要。

**給 Fable 的提醒**：要跟 [scaffold](scaffold.md)（選項少、專用工具、分層引導）一起想，例如「從哪個抽屜拿」是不是就是一層選單；ELI5 之後不能變複雜。
