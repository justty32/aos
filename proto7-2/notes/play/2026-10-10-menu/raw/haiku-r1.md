# Haiku 第 1 輪（Agent model=haiku 最終回覆，節錄 B～E；A 段的指令與輸出同 luna，差異寫在下面）

A 段差異：2b 用行號刪 exit 時留下尾逗號，拿到 `aos7-menu: …/my/menu.json 不在或 JSON 不合。給可讀的 JSON 檔，例如 hello/menu.json`（退 2），沒撞到「缺出口」那句；2c status 退 0、run 退 1。

B. 五題
1. AI 每次只看到一層：一題問題、附編號選項。它回一行「選：N」；要寫字的那層再加一行「格：……」。README 說最後一個編號是「都不行，要人決定」，但我沒有看到 AI 的提示內容，無法確認那個編號是哪個數字。
2. 「練習用的 AI」是照 practice.json 逐句念出預寫好回覆的假 AI，不連網、不花錢。第 2 句故意回成「選：1＋內容」，格式不對，所以被要求重回；第 3 句才是「選：1＋格：」，才通過。
3. who 讓 AI 選先回誰；line 讓 AI 寫一句回覆，寫到 out/reply.txt；send 呼叫登記好的小工具 hello-send，寫到 out/sent.txt。都在 WORK/menu/hello/out/ 底下。
4. README 說是「都不行，要人決定」，AI 選它就停下來等人。我沒有驗證這件事。
5. `rm -r WORK/menu/hello` 後再跑 run。對已做完的再打一次同一個 run，只印同一行「做完」，不會重走、不會再問 AI。

C. 2 個指令（run、status）。概念：README 明講四個（選單、層、練習用的 AI、工作資料夾），另數了編號選項、選：／格：、「都不行」選項、run／status、out/ 共約十個。

D. 容易上手 6（要 mkdir、要 cd 到專案根、路徑很長）／容易理解 5（「頂多再寫一句」「下一行再回格：」不清楚；「node」與「工作資料夾」名稱不一致）／複雜的藏起來 5（JSON 結構完全沒講；`--run`／`--llm`／`--reply` 沒說明）／外層控制結構 6（重走、中斷、錯誤碼說明分散）／要背的少 5。總分 5.4。
錯誤訊息扣分：2b「不在或 JSON 不合」——檔案明明在，也沒說哪一行錯；2c「換 --run 重走」——`--run` 要給什麼值沒說，README 也沒提。

E. 使用端很簡單（寫好選擇題，AI 只挑號碼，程式照做），但想自己改或寫選單時，JSON 結構和 `--run` 等選項沒有在 README 講清楚，這一塊相當複雜。
