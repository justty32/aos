# Haiku 第 3 輪（節錄）

A 段：第一次跑、2a（node 不在，退 2）、2d（做完再跑印同一行；rm -r menu/hello 後重走）、收掉都照做。**2b、2c 沒做**：它把「只能讀 README」解讀成連複本的 menu.json／practice.json 都不能打開，判「照 README 走，新手改不了選單」。

B. 五題
1. AI 每次只看到一題：題目文字（附上需要的上下文，例如兩封信）、編號選項、「回法」那一行。回一行 選：N；寫字的那層第二行寫 格： 後接內容。
2. 照 practice.json 一句一句念的替身，不連網、不花錢。範例第 2 句故意回錯格式，所以會被要求重回（這次只印一行「做完」，沒看到重回過程，照 README 得知）。
3. 第一層選先回誰（AI 選 1，小明）；第二層寫一句回覆；第三層不問 AI，由登記好的小工具「寄出」。寫在 WORK/menu/hello/out/ 的 reply.txt 與 sent.txt。
4. 每層最後一個編號是出口。第一層是 3「缺少判斷先回誰的必要資訊，請人補充」。AI 選了出口，選單就停下來等人。第二層選項 README 沒寫；第三層不問 AI，沒有出口。
5. rm -r WORK/menu/hello 再打同一個 run；或在 run 最後加 --run 新名字（紀錄在 menu/新名字/）。已做完的再打同一個 run 只印同一行「做完」，不重走、不問 AI。

C. 2 個指令（run、status）。概念：README 點名四個＋出口＋選：／格：格式。

D. 容易上手 8（mkdir 放在第一行的括號裡；`node 不在` 的 node 沒解釋）／容易理解 6（工作資料夾與 node 名字換來換去；出口要對照範例才懂；「登記好的小工具」沒說登記在哪）／複雜的藏起來 6（`run --help` 露出 --llm、--reply、--var、--brief 卻沒說明）／外層控制結構 7（做完、停下、沒跑成三種結局 status 都說得出；停下條件擠在一句）／要背的少 5（run 參數順序、選：／格：、出口、node、兩種重走）。總分 6.4。

E. 不算複雜：一次問一題、AI 只回一個編號（或一段字）、程式照做；門檻在看懂 node 與回法格式，以及要改 JSON 的事 README 沒教。
