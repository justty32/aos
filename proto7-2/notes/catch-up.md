## 1. 三分鐘版

**proto7-2 是什麼。** 一套用 Python 寫的原型，可以叫它「資料夾回合機」。有一個常駐程式（**daemon**，一直在背景跑的管理員）看著幾個登記好的資料夾（每個資料夾叫一個 **node**，可以想成一個工作站）。每隔固定時間，daemon 替每個 node 開一回合、關一回合。開回合的動作叫 **tick**，關回合的動作叫 **tock**，像時鐘的滴、答。回合裡，照 node 的任務表 `tasks.json` 把任務當子程序起來；關回合時，把「這回合發生什麼」寫成一份 JSON 檔。所有狀態與控制都是 JSON 檔：用 `cat` 看得懂，寫一個檔就能下指令。

**能做什麼。**

- 登記、取消登記 node；每個 node 有自己的節拍（interval，幾秒一回合）；暫停、喚醒、停止，都靠寫控制檔。
- 三種任務：`keep`（常駐，掛了就補起來）、`each`（每回合起一次）、`once`（起一次就從表上刪掉）。
- 每個任務在一個固定的資料夾裡跑，這個資料夾叫**槽**（`.aos/tasks/<名字>/`，同名就重用）。每次執行叫一個 **run**，有流水號。
- 核心承諾：同一個槽不會同時跑兩份；「不知道」不當「失敗」處理；只留「上一次」的結果，跑一年檔案也不會變多；任務或 daemon 被強制砍掉（kill -9）都能接回來。
- 核心之上長了**六個模組包**（可選的擴充，像外掛）和**三個任務包**（`step` 步驟表、`budget` 預算帳本、`adapt` 鄰居資料轉接）。三個任務包都是**核心一行沒改**做出來的。
- 376 項離線測試，約 200 秒跑完。

**還不能做什麼。** kernel 任務包（替任務做決策的那一層）、事件保存（一件都不漏的事件紀錄）、讓 LLM 當作者寫任務、包的安裝器、回到 C++。另外有一批 10-05 審查挖出的「兩個機制交接處」的缺陷在等你拍板（第 6 節）。

**一個具體小例子。** 空間根 `/tmp/sp`，裡面一個資料夾 `team` 當 node：

```sh
mkdir -p /tmp/sp/team/.aos
echo '{"tasks":[{"name":"hello","argv":["sh","-c","echo hi $AOS7_RUN"]}]}' > /tmp/sp/team/.aos/tasks.json
python3 proto7-2/bin/aos7-ctl daemon /tmp/sp register team   # 寫一個控制檔：請登記 team
python3 proto7-2/bin/aos7-daemon /tmp/sp &                   # daemon 只跑登記過的 node
```

daemon 起來後，一回合這樣走：

1. 時間到，daemon 起 `aos7-tick`。tick 拿鎖讀任務表，把回合數加一、標「開著」。`hello` 的槽是空的，所以 tick 先寫一份 `birth.json`（這次 run 的出生證明：槽名、run 號、回合、要跑的命令），再透過 `aos7-run`（任務的包裝程式）起子程序。`aos7-run` 寫 `pid.json`，程序結束時寫 `exit.json`。tick 不等任務，起完就退出。
2. 任務跑的時候，從環境變數知道自己在哪個 node、哪個槽、第幾個 run；想知道「回合關了沒」就看槽裡有沒有新的 `tock.json`。
3. interval 到，daemon 起 `aos7-tock`。tock 看每個槽：有這個 run 的 `exit.json` 就是結束；程序還在就是活；證據兜不起來，先做身分掃描再說是不是走失（lost）；檔案讀不到＝**不知道**，什麼都不動。然後把回合總結覆寫到 `last-round.json`（只留這一次），通知活著的任務，把名字已從表上拿掉的槽刪掉，回合標「關了」。
4. 下一回合 tick 看到 `hello` 上一個 run 已結束，就換一個 run 號重用同一個槽：清掉上次的基礎設施檔（birth、pid、exit、out.log），任務自己寫的檔（例如 `state.json`）留著給下一個 run 接。

想看狀態：`cat /tmp/sp/.aosd/status.json /tmp/sp/team/.aos/last-round.json`。收工：`aos7-ctl daemon /tmp/sp stop --kill`。

## 3. 系統長什麼樣

### 3.1 核心五支程式各管什麼

| 程式 | 管什麼 | 不管什麼 |
|---|---|---|
| `aos7-daemon` | 跟 Linux 的介面：讀登記清單 `.aosd/nodes.json`，每個 node 一條時間線照節拍起 tick、tock；處理控制檔（登記、取消登記、暫停、喚醒、停止），每件留一份回條；node 不見了就收掉程序、標 `missing`（失蹤）；寫 `status.json` | 任務在做什麼；重啟任務（移到控制包）；歷史 |
| `aos7-tick` | 開回合：回合數加一；執行槽裡的 kill 請求與加掛審核；照任務表在槽裡起 run；once 項起完刪掉。起完就退，不等任務 | 任務跑多久、結果對不對 |
| `aos7-tock` | 關回合：判每個槽（結束／活／走失／不知道）；寫 `last-round.json`；通知活任務；刪不要的槽 | 補漏掉的回合；更早的歷史 |
| `aos7-run` | 任務的包裝程式：子程序與檔案之間的交接者，寫 `pid.json`、`exit.json`、`out.log` | 任務內容 |
| `aos7-ctl` | 人或程式用的命令列：寫控制檔、加任務、等回條（本體在工具包） | — |

共用的程式庫：`aos7_fs`（讀檔，回答「不存在／讀到／不知道」三態）、`aos7_proc`（程序事實：不在／在／不知道）、`aos7_task`（槽的判定、身分掃描、kill）、`aos7_mount`（掛載，讓任務搆得到別的資料夾）。

### 3.2 誰依賴誰

```mermaid

    D[aos7-daemon<br/>登記、控制檔、status] --> T[aos7-tick 開回合]
    D --> K[aos7-tock 關回合]
    T --> R[aos7-run 起任務]
    T & K & D --> FS[aos7_fs / aos7_proc / aos7_task<br/>三態判定入口]

    CTRL[control 控制包<br/>restart／reload]

    AUD[audit 稽核包]
    DIAG[diag 診斷包<br/>唯讀＋恢復手冊]
    HIST[history.py 歷史 module<br/>每個 tock 抄一份「上一次」]
```

讀圖：核心不呼叫任何包、不知道它們存在。包只有三種接法——**當任務**（tick 起它）、**當包裝程式**（任務命令前面加它）、**當工具**（人或程式呼叫）。核心另給三個小出口：任務表的 `x` 欄原樣抄進 birth.json（模組放自己的資料用）、「從沒起來過」這個事實欄位、一個通用守門檔。總覽在 [modules/README.md](../modules/README.md)。

### 3.3 核心的幾條關鍵承諾

| 承諾 | 白話 | 為什麼 |
|---|---|---|
| **不雙開** | 同一個槽同時只有一份在跑；常駐任務重起前，舊的一定已收掉 | proto7-1 的壓力測試 20 次有 7 次起出兩份。做法：先寫證據（起動標記、birth.json）再起程序；懷疑走失時先做身分掃描 |
| **三態：不知道不等於失敗** | 推定「回合關了沒、任務活著沒、是不是同一個程序」只有是／否／不知道；不知道時不殺、不判走失、不起新 run | 讀不到 /proc、檔案寫到一半，都是常態。把不知道當「否」會誤殺，當「是」會雙開 |
| **錯誤四分支** | 每個錯先分類：不存在、不知道、輸入不合、中斷；同類只走一條路 | 瘦身前五十幾處 `except` 各判各的；現在讀檔只經一個入口、讀程序只經一個入口，bug 修在入口 |
| **只留上一次** | 每個 node 只留最近一回合總結、每個槽只留最近一次 run、回條同名蓋掉 | 你定的：「正常運行時這些就是垃圾」；不留就不用清 |
| **登記，不掃描** | daemon 只跑登記清單上的 node；看不到不等於不存在 | 你定的；掃描帶來的一堆規則全拿掉 |
| **先寫證據再動作** | 程序被砍不偵測；靠順序、靠重做是安全的、靠清掉死掉的人留下的暫存檔 | 各個時間點 kill -9 的測試靠這條成立 |
| **核心不長新功能** | 行數上限 2800，超過測試就紅；新功能一律當外掛 | 瘦身前 4501 行，一半是防誤用與只為 agent 的東西；三個任務包證明核心夠用 |
| **誤用不防** | 違反前置條件（寫不該寫的檔、不拿鎖）算誤用，寫進文件界線，不加檢查 | 防誤用的兩百多行刪掉後，行為沒變 |

### 4.2 10-04 中午：兩輪對抗測試，核心還是「厚」的

astra 是另一個 AI（codex）扮演的對抗測試員，專挑設計承諾去打。

- **第一輪**（[報告](play/2026-10-04-astra-1-infra.md)）找到 13 條，前五條是結構性的：「讀不到」在中途被某個讀函式吃成「沒有」、回合和槽的身分證據不夠、控制檔重播不安全。修法是把「讀不到＝不知道」貫穿每個讀點，並加 116 項故障注入測試（模擬 /proc 讀不到、檔案半寫等）。
