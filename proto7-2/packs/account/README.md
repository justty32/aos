## 契約卡（草稿）

**grant（使用權）**
- 職責：寫明「誰、在什麼範圍、用多少、在哪條鐘的哪段期間內」可以用某種資源；提供判斷函式（在不在範圍內、過期沒、可不可以再分）。
- 前置條件：grant 檔由發放者寫、持有者只讀；每份 grant 自己宣告用哪條鐘（v1 只有本地回合，同 step 的耐性）與 `[from, until)`。
- 保證：判斷只看 grant 檔本身與給的鐘值，讀不到＝不知道（不當「沒有限制」、也不當「已過期」）；過期只擋**新的**使用（同核心 `until_round` 擋新啟動，不是完成期限）。
- 明確不管：資源本身怎麼量（入口或任務的事）；惡意持有者（合作式，同核心 §11）。

**帳本（ledger）**
- 職責：記每一筆預留（reserve）與結算（settle），算出已用、在途、剩餘。
- 前置條件：帳本只有帳本任務一個寫者；請求方用請求檔送 reserve／settle，帶自己的請求 id（同 id 重送＝同一件）。
- 保證（暫定）：同一請求 id 只入帳一次；預留後子工作 `never_started` 或明確失敗＝退回；**在途未知**（子工作結果不明、step 停在 unknown）＝預留留著、不退也不結，記成在途未知等人或等證據；帳本讀不到＝不受理新預留（不當空帳）。
- 明確不管：把取樣的 `usage.json` 當精確帳（它只是下界，核心 spec §8 與 problems「kernel 用量以 run 為單位」）；跨 node 的一致性（v1 單 node）。

**入口（gateway）回條**
- 職責：資源入口在放行前核對 grant／預留，回一份回條（准／拒／不知道）。
- 保證（暫定）：不知道時不放行；回條帶請求 id，重送同 id 拿到同一個結論。
- 明確不管：入口後面的資源做了什麼（效果回條是效果擁有者的事）。

## 待定（下一輪藍圖要先答的）

1. grant 的檔案格式與型別（r6 Fable 提的五型別要不要第一版就全上）。
2. 帳本請求通道：沿用 step 的「槽外結果檔＋請求 id」慣例，還是另開 inbox 資料夾；回條保留多久（同核心「只留上一次」還是到結案）。
3. 在途未知怎麼收：等人、等 step 的 resume、或有期限自動退回（★ 可能是兩難，照原則 2 做成選項）。
4. step 的 `reserve→run→settle` 括號放 step 步驟表（新步種類）還是包成 `run` 步的包裝程式。
5. 第一個資源入口用什麼非 LLM 的本地資源驗（r6 §1 第 7 點第 2 步）。
