## 想法（依講述順序）

### 1. Janet 的資料就是檔案系統（09-08 09:2x）

原話：「我想要把 janet lisp 當作檔案系統，list 當作資料夾，執行資料夾就是對 list 求值。先來幫我做一個簡單的循環。」

→ 我的理解：proto2 是「資料夾＝世界、`.aos/inst`＝一句 shell」，proto3 把這層搬進語言裡——
  一個世界是一份 Janet 資料（list／struct／table），「跑一格」就是對這份資料求值。
  資料夾裡放什麼（子資料夾、指令）＝資料裡放什麼（子資料、函式）。
→ 第一版 `src/main.janet`（使用者先寫了偽碼，我補成能跑的）：
  `registereds` 登記簿、`dotick` 對一個世界求值（走元素、碰到 `:func-tick` 就叫它）、
  `tick-all-world-once`、`kernel/register`、`daemon` 每秒走一格；範例 `world-1`（印時間）與
  `agent-1`（idle→thinking→act 三態）。
→ 還沒碰的：怎麼存到磁碟（Janet 資料 ↔ 檔案）、和 proto2 的 Python 工具包怎麼接。

### 2. 先把基礎架構搞定（09-08 09:4x）

原話：「先不管 python 和存進磁碟。先繼續幫我把這一套完善，弄到世界／時鐘／agent 的架構都搭好。」
「後續的工具包、teams、agent 交流那些先不動。」「agent 的狀態機我之後會再變，所以那邊簡單勾勒一下就好。」

→ 做了：拆成 world／kernel／llm／agent 四個模組（見 README「檔案」）。
  - 世界：table；求值走元素；path 身分；`spawn` 小孩借鐘或自己鐘；`kill` 連子孫。
  - 鐘：一世界一鐘；同步 `step-all`（interval＝每幾格動一次）與非同步 `start`（一鐘一 fiber）。
  - LLM 世界：佇列、三態、結果寄信回去、按請求者算 usage；engine 是純函式，測試用劇本 engine。
  - agent：只勾輪廓。唯一算基礎設施的是 `wait-for`（時鐘是唯一喚醒者）。出錯先回 idle。
→ 我自己做的判斷（可推翻）：等待／喚醒用「登記條件、每格檢查」而不是回呼；
  LLM 結果走信箱而不是直接改 agent；小孩預設借父鐘。
