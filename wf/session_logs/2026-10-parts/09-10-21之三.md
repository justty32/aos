## 2026-10-21（續）

### 傍晚：設定檔是唯一的位置參數、run 陣列、daemon 經 aos-exec、`$path` 改字串拼接

- 使用者回來（「windows不管，反正就是要WSL」），原話與決定 H1～H8、頂層自定 9 點在 [ideas 10-21 § 9](../../../proto8/thinking/2026-10-21-ideas.md#9-設定檔是唯一的位置參數path-改字串拼接10-21-傍晚)；使用者把修飾欄 `$at` 撤掉，改成 `$path` 字串拼接（`$path: "#/loops/a"`），`$path` 與 `at` 日後可能統一。
- 結論：`aos-loop`／`aos-daemon`／`aos-fsm` 是 `程式 [旗標] 設定檔`（沒有 `--cfg`、沒有命令列 XXX；設定檔可寫 `檔#/指標`）；`run`／`val` 可以是 `[目標, 參數...]`；daemon 小格的 loop.json 蓋上 `_exec`、相對的 `run` 轉絕對，起 `aos-exec -- 小格/loop.json#/_exec`，子項名字不能帶 `#`；`$ref` 指到資料夾＝錯。
- 坑：路徑裡有 `#`（工作區、stack、設定檔所在資料夾）會在第一個 `#` 被切成指標；daemon 只擋子項名字帶 `#`。
- 坑：`aos-exec loop.json a b` 多給的 args 接在 `_exec` 後面＝usage 錯（設定檔只能一個），要帶參數寫進 `run` 陣列；`_exec` 裡 `{"$env": "AOS_CF"}` 解出來若以 `-` 開頭會被當旗標。
- daemon 只轉子項 `run` 目標的相對路徑，其他 key 不轉。

### 使用者不在時代定：aos-tick（計畫第 4 段，10-21 晚）

- （10-22 使用者：功用未定、先擱著不用管，可能之後刪掉）
- 規格是使用者 10-12「做吧」那份（[tasks-ticktock § 2](../../../proto8/thinking/2026-10-12-tasks-ticktock.md)）；使用者的條文只加註、不改原話，不另開 N- 條（時鐘規範是 N-01～N-03）。代定翻案就改 `proto8/bin/aos-tick` 與 bin README 那條。
- 代定 1：命令列 `aos-tick [旗標] FILE`，走 `aos_flags`、旗標表空、唯一位置參數是 FILE；`--` 結束旗標；沒給、多給、不認得的旗標＝usage 錯。
- 代定 2：FILE 照字面、`#` 不切指標。
- 代定 3：錯誤一行 `aos-tick: 原因`，原因開頭四種 `usage: aos-tick FILE（…）`、`時鐘檔讀不到：`、`時鐘檔壞：`、`時鐘檔寫不了：`；都退 1、FILE 不動。
- 代定 4：只收 `[0-9]+` 加可有可無的一個 `\n`，其他都算壞；前導零照收（`007` 寫回 `8`）；不設上限。
- 代定 5：暫存檔叫 `.名字`，寫失敗會清掉；不 fsync。
- 代定 6：FILE 的資料夾不在＝寫不了，不替人建。
- 代定 7：demo 時鐘檔放 `$AOS_STACK/tick`；loop.json 不加 `interval_ms`／`ctl`／`state`；`_exec` 用 shell 小殼。
- 代定 8：不另開 N- 條，實作對應寫在各檔開頭「實作」欄、bin README 與註。
- 坑：FILE 是捷徑時改名會把捷徑換成一般檔；剛寫完暫存還沒改名就被殺會留 `.名字`（N-05 讀的人不讀 `.` 開頭）；同一 FILE 兩人同時 tick 會掉一格（規格不管）。

### impls 對齊 bin 版 10-21（10-21 晚）

- impls 跟上 bin 10-21 一整天的改動（aos-exec 旗標、`.env`、入口順序、一路往下、`AOS_CO`；loop／fsm／daemon 的 `程式 [旗標] 設定檔`、`run`／`val` 陣列、daemon 經 aos-exec、`$path` 字串拼接）。aos-exec 公開 API 是 `run_cli`（等同命令列）＋`run_inst`＋`argv0`；設定檔讀取在 aos-util 的 `aos/cli.hpp`。impls 沒有 aos-tick（10-22 使用者定：C++ 先不用補。）
<a id="刻意沒對齊"></a>
- 刻意沒對齊（使用者 impls 原本的設計，保留）：(1) 沒有 `aos-inst` 命令列，inst 是 C lib、單子在 aos-exec 行程內跑；(2) 錯誤一行多一個代號（`aos-exec: EntryMissing 原因`、`aos-loop: Usage usage: …`）；(3) loop／fsm 每拍、daemon 起子 loop 不叫 PATH 上的 aos-exec，而是 fork 後在子行程呼叫 `run_cli`（效果等同；argv 陣列裡插的 aos-exec、daemon 要的 aos-loop 照樣照 PATH 找）；(4) 可執行檔入口的 argv[0] 是 `./檔名`；(5) fsm 的 trace／.state 寫不了是 `WriteFailed` 一行。寬鬆度差兩條：設定檔第一行 `#!` impls 跳過（bin 的 `load_cfg` 算錯）；`.env` 去前導空白 impls 只認 ASCII 空白（Python `lstrip` 也認 Unicode 空白）。
- 頂層代定（可翻案）1：impls daemon 照使用者「5.要」經 aos-exec、exec PATH 上的 aos-loop 起子 loop（`ps` 看到的子 loop 叫 aos-loop）。
- 頂層代定 2：`.env` 兩個代號 `EnvBad`（壞）、`EnvReadFailed`（讀不到），錯只印位置不印值；單子起不來的原因開頭「單子跑不起來：」、起不來的訊息「起不來：X（原因）」，跟 bin 字面一致。
- 頂層代定 3：旗標用錯一律 `Usage`（不用 `FlagUnknown`）。
