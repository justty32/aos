## agent-dan（試驗場 `~/code/try/agent-dan`）

```sh
cd ~/code/try/agent-dan && rm -rf ws-real && mkdir -p ws-real/new
echo '請用工具算 17*23，並用工具查現在 UTC 幾點，最後用一句話回答。' > ws-real/new/q1.txt
aos-exec --ws ws-real $R/demo/agent-dan; echo rc=$?
```

- 成功：`ws-real/out/q1.txt` 有 391；`.stack/history.jsonl` 有 role=tool 那幾行；trace `idle think act idle think act idle`。測試版：`python3 -m unittest discover -s proto8/tests -p test_dan.py -v`。
- 風險：低。think 120 秒、act 60 秒、loop 40 次。
- 打磨方向（[tool-calls](../../../../proto8/thinking/2026-10-23-tool-calls.md)）：history 沒上限、太長就 `BrainFailed`；腦叫不存在的工具或工具失敗時整隻停下等人（WAIT_USER 的三題之一）。改了 dan 記得更新 artifact（SESSION-LOG 那行）。

## agent-pip（試驗場 `~/code/try/pi-tools`，`seed/` 是改前的工作區）

```sh
cd ~/code/try/pi-tools && rm -rf ws-real stack-real && cp -r seed ws-real && mkdir -p stack-real
AOS_STACK=$PWD/stack-real/ aos-exec --ws ws-real $R/demo/agent-pip; echo rc=$?
```

- 成功：`ws-real/out/fix_mean.txt`；`cd ws-real && python3 test_stats.py` 全過；`stack-real/history.jsonl` 看 edit 失敗後有沒有自己重來。第二題（改 act 逾時）在 `explore/`，`explore/seed/new/` 是空的、要先放題目。
- 呼叫：5～15 次（loop 上限 200）。風險：bash 工具擋不住跑出工作區、刪檔、連網；read／bash 每次最多回 50KB，history 長得快；同一個錯重複只有 max 200 擋。
- 打磨方向（[pi-tools](../../../../proto8/thinking/2026-10-24-pi-tools.md)）：stack 放在工作區裡腦就改得到自己的對話（所以上面放外面）；edit 不做模糊比對，抄錯一字就 `TextMissing`；ls 會列出自己的 `new/`、`cur/`。

## aos-json 的 json_edit 兩步（`impls/aos-json/tools/json_edit`；沒有試驗場）

注意有兩支 json_edit：`lib/base/json_edit` 不問腦（pip 掛這支）；「兩步」是 aos-json 那支——先找 key、再給值，自己問腦。

```sh
mkdir -p ~/code/try/aos-json/ws && cp $R/demo/agent-dan/fsm.json ~/code/try/aos-json/ws/
cd $I/aos-json && echo '{"file": "fsm.json", "want": "把 think 那格的逾時改成 30 秒"}' | \
  AOS_WS=$HOME/code/try/aos-json/ws AOS_STACK=$HOME/code/try/aos-json/ws/ aos-exec tools/json_edit
```

- 成功：stdout 有 `看過：/ → /states → …`、`找到：/states/think/exec/timeout_ms`、`改：… = 30000`；`ws/fsm.json` 只動那一行、排版不變。
- 呼叫：第一步最多 12 輪（`JSON_EDIT_MAX_ROUNDS`），第二步每個指標一次、最多重給 3 次。風險：`--follow` 穿 `$ref` 可能改到工作區外。
- 打磨方向（[aos-json](../../../../proto8/thinking/2026-10-24-aos-json.md)）：被重寫那塊數字格式會變（`1e3`→`1000.0`）、有重複 key 的物件整份重排；第二步預定換 agent-gus 的 `thought.json`。

## agent-liv（工具＝函式庫；沒有試驗場，要建）

```sh
mkdir -p ~/code/try/tool-lib/ws/new ~/code/try/tool-lib/stack
echo '列出目前資料夾有幾個檔' > ~/code/try/tool-lib/ws/new/q1.txt
AOS_STACK=$HOME/code/try/tool-lib/stack/ aos-exec --ws ~/code/try/tool-lib/ws $R/demo/agent-liv; echo rc=$?
```

- 成功：`ws/out/q1.txt` 是真回答；trace 叫到庫裡的工具（ls 之類）。呼叫 2～4 次。
- 風險：庫裡有 write、edit、bash，bash 擋不住寫出工作區；liv 的工具一出錯就 `ToolFailed` 停下（沒跟 pip／gus 一樣回給腦）。
- 打磨方向（[tool-lib](../../../../proto8/thinking/2026-10-24-tool-lib.md)）：`cp -r` 或 aos-ai spawn 複製 agent 時捷徑會被解開、不再跟著庫；庫一改所有 agent 立刻跟著變（沒有版本釘）。

## kernel-llm（impls 的 aos-kernel-llm、aos-gate；demo/kernel-llm；沒有試驗場，要建）

**先改 daemon 的 `max`**：`demo/kernel-llm/daemon.json` 是 `"max": 25, "interval_ms": 200`（約 5 秒收工），三封信排隊跑真腦很可能超過——收工會把 agent 收掉、已在跑的腦照花錢（推的，沒實測）。`_entry` 寫死、加不了旗標，所以複製一份改大：

```sh
W=~/code/try/kernel-llm; rm -rf $W && mkdir -p $W && cp -r $R/demo/kernel-llm $W/demo
sed -i 's/"max": 25/"max": 600/' $W/demo/daemon.json
for a in a b c; do mkdir -p $W/ws/$a/new; echo "$a 問：2+2 等於多少？" > $W/ws/$a/new/q1.txt; done
cd $W/ws && AOS_BRAIN_MODEL=chatgpt-gpt-6-luna-low aos-exec $W/demo; echo rc=$?
```

- 成功：`ws/{a,b,c}/out/q1.txt` 是真回答；`ws/.stack/kernel/served.jsonl` 順序 c（high）→ b（宣告 `time_ms` 800）→ a，每行 `tokens` 是真 usage、`report_bad` false；`used.json` 的 calls 是 3。
- 必設 `AOS_BRAIN_MODEL`（agent-ivy 沒 `.env`）。think 逾時 120 秒含排隊。信裡帶整份環境（含 key），信箱要在自己的 stack 裡。
- 打磨方向（[llm-kernel](../../../../proto8/thinking/2026-10-24-llm-kernel.md)、[metainfo](../../../../proto8/thinking/2026-10-24-metainfo.md)）：token 回報是腦自願、kernel 不驗；閘門那格逾時時 kernel 那邊已在跑的不會停；`_metainfo` 宣告錯（說 1 秒跑 1 小時）不處罰、`llm_tokens` 只讀不用（預先擋沒做，代定 9）。其他 agent 要走 kernel 時再抄 agent-dan brain.py 寫 `AOS_KERNEL_REPORT` 那幾行（10-24 遷移時已抄進 eve、fay、hal 等）。
