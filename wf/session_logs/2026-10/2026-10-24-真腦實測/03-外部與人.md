## aos-ai（`proto8/ai_tools`，含 skill；試驗場 `~/code/try/aos-ai-tools`，沒有 README）

```sh
cd ~/code/try/aos-ai-tools && aos-ai doctor                       # brain.reachable 要是 true
aos-ai --root . spawn boss2 --tool ask_agent --tool agent_status \
 && aos-ai --root . ask boss2 '請叫 helper 算 17*23' && aos-ai --root . run boss2 --timeout 300
# skill（外部 Claude 用法，付費）：
claude -p --plugin-dir $R/ai_tools/claude_skill/aos --model sonnet --allowedTools "Bash(aos-ai *)" "用 aos-ai --root . 起一隻 helper2，問它 '17*23'，回答案"
```

- 成功：輸出 JSON `ok:true`、`answers` 是 391 不是 `FAKE ANSWER`；`agents/boss2/ws/agents/helper/` 長出來。
- 呼叫：spawn／ask 約 3 次；`claude -p` 每次約 0.08～0.14 美元。非互動會擋完整路徑與含 `$` 的指令、題目的 `*` 要加引號；`ask_agent` 上限 50 秒、act 60 秒；巢狀深度沒限制。
- 打磨方向（[ai-tools](../../../../proto8/thinking/2026-10-24-ai-tools.md)）：工具結果是整串原樣 JSON，真模型會不會自己摘要沒驗；子 agent 想換腦得 `--dotenv-override`，aos-ai 沒給這個旗標。

## say／listen／chat（`proto8/human`；親手）

照 [WAIT_USER](../../../WAIT_USER.md) 那行做（試驗場 `~/code/try/say-listen/ws`）。成功：真回答、`/status` 停在 idle、trace `idle think act idle think act idle`；腦壞時印 `BrainFailed`、題目留 `cur/`、`/run` 接著做。每句 1～3 次。

## agent-fay：claude／codex 當工具、attach（試驗場 `~/code/try/cli-tools`，有 env.sh；親手）

要在 **Claude Code 外面**的終端機、要 tmux。步驟照 [WAIT_USER](../../../WAIT_USER.md) 那行；想先讓 agent 自己叫一次，另開新 ws（舊 `ws/` 留著舊 session）：

```sh
. ~/code/try/cli-tools/env.sh && cd ~/code/try/cli-tools && rm -rf ws-real && mkdir -p ws-real/new
echo '列出這個資料夾的檔案並回一句話。' > ws-real/new/q1.txt && aos-exec --ws ws-real $FAY; echo rc=$?
cd ws-real && $FAY/attach claude          # Ctrl-\ 跳出
```

- 成功：`ws-real/out/q1.txt`、`.stack/claude/session.txt`、`turns.jsonl`。呼叫：腦 2～4 次＋CLI 1～2 次（付費：claude 非互動每次上限 0.5 美元，互動與 codex 沒上限）。act 15 分；hook 沒回要 10 分才報 `ReplyMissing`。CLI 目前唯讀。
- 打磨方向（[cli-tools](../../../../proto8/thinking/2026-10-24-cli-tools.md)）：人在畫面上講的話不進 agent 的 history；codex 沒有「正在跑」的鎖，人打到一半跳出、半句會跟 agent 送的字黏在一起；stack 疊深時 socket 路徑超過 108 字、tmux 開不起來。

## Janet 編譯物（`proto8/langs/janet`；試驗場 `~/code/try/janet-aos`）

```sh
cd ~/code/try/janet-aos && rm -rf ws-dan-real && mkdir -p ws-dan-real/new && echo '17*23 是多少？現在幾點？' > ws-dan-real/new/q1.txt
aos-exec --ws $PWD/ws-dan-real agent_dan; echo rc=$?     # 重編：aos-janet --force $R/langs/janet/examples/agent_dan.janet agent_dan
```

- 成功：`out/q1.txt` 有 391 與時間、trace 同 agent-dan（拿同一題跑 `$R/demo/agent-dan` 對照）。2～4 次、風險低。
- 打磨方向（[janet-compile](../../../../proto8/thinking/2026-10-24-janet-compile.md)）：重編蓋掉手改、拿掉的檔留在輸出、編到一半出錯留半份；par 不轉訊號、if 分不出「條件為假」與「條件那步壞掉」。

## Lua 編譯物與 nvim 外掛（`proto8/langs/lua`、`proto8/editors/nvim`；試驗場 `~/code/try/lua-aos`；nvim 親手）

```sh
cd ~/code/try/lua-aos && python3 try.py       # 自己放 PATH、重編 build/、重建 ws-dan、ws-dan-hand、ws-clocks
```

- 成功：編出來的 dan 與手寫的 dan 兩份都是真回答、trace 形狀一樣；clocks 的 tick 1、2、3。4～6 次。
- nvim 照 [WAIT_USER](../../../WAIT_USER.md) 那行（先 `export AOS_BRAIN_URL=…`，子行程繼承 nvim 的環境）。外掛沒有「停」指令；nvim 開著時外面別跑同一個工作區（會搶 `new/` 的題）。
- 打磨方向（[lua-nvim](../../../../proto8/thinking/2026-10-24-lua-nvim.md)）：`return aos.fsm{…}` 被當尾呼叫、錯誤丟掉原始檔行號；build 不清舊檔；nvim 從帶 `AOS_STACK` 的環境開時 `:AosTrace` 看的 stack 對不上。

## aos-grow（`proto8/grow`；試驗場 `~/code/try/grow`）

`run_compare.py` 會清掉 `AOS_*`、只在 `--brain-down` 設網址，**不能拿它跑真腦**，手動跑：

```sh
cd ~/code/try/grow && for a in dan-before dan-after; do rm -rf ws-$a; mkdir -p ws-$a/new; echo 幾點了？ > ws-$a/new/q0.txt; echo 現在時間 > ws-$a/new/q1.txt; aos-exec --ws $PWD/ws-$a $a; echo rc=$?; done
```

- 成功：兩份結束碼 0、trace 格序一樣、`out/q0.txt`、`q1.txt` 都有（真腦內容不會逐字一樣，只比形狀）。約 8 次、風險低。
- 打磨方向（[fn-grow](../../../../proto8/thinking/2026-10-24-fn-grow.md)）：程式自己讀 `AOS_CF`／`AOS_CD`／`AOS_CO` 的長大後值會變、用 `__file__` 找旁邊檔的會找不到；被逾時收掉時 trace 的 `signal` 從 15 變 null；daemon.json 的子項沒試過。

## 沙箱的 root 那層（不叫腦；親手）

照 [WAIT_USER](../../../WAIT_USER.md) 那行（`setup.sh` 乾跑 → `sudo … --apply` → `sudo -n /usr/local/bin/s6-setuidgid aos-run id`）。另驗：`sudo -n /usr/local/bin/s6-setuidgid aos-run cat ~/.bashrc` 要 Permission denied。不要 root 的半邊：`cd $R/tests && python3 -m unittest test_sandbox`（16 案）。

- 風險：改 `/usr/local/bin`、建帳號、開 `/srv/aos-run`、加 sudoers（腳本最後一行是拆除指令）；`sudo` 清環境，`PATH`、`AOS_*` 要另帶。
- 身分層目前配不上 self-improve：mkdtemp 的暫時資料夾是 700、aos-run 進不去，要改到 `/srv/aos-run` 底下。其他邊緣狀況（`procs` 算整個使用者、`mem_mb` 是虛擬記憶體、Go／Java／Node 可能起不來、`net: true` 在 resolv.conf 指 `/run` 的機器上解析不了）見 [sandbox](../../../../proto8/thinking/2026-10-24-sandbox.md)。
