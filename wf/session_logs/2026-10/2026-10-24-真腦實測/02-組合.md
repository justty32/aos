## agent-eve 叫 pyfix 子 agent（試驗場 `~/code/try/agent-as-tool`，有 README.txt）

```sh
cd ~/code/try/agent-as-tool && python3 setup_ws.py && aos-exec --ws ws $R/demo/agent-eve; echo rc=$?
```

- `setup_ws.py` 重建 `ws/`，題目是有兩個 bug 的 `proj/stats.py`。成功：`ws/out/q1.txt` 講出 mean、median 兩個錯；`cd ws/proj && python3 -m unittest test_stats` 全過且 `test_stats.py` 沒被改；`ws/.stack/pyfix/runs/001/` 有 history、`before/`、diff。
- 呼叫：十次左右。風險：逾時一層套一層（eve act 30 分；子 agent think 180 秒、act 300 秒、max 60）；子 agent 的 bash 不是沙箱；兩層打同一個 URL、看不出各花多少。
- 打磨方向（[agent-as-tool](../../../../proto8/thinking/2026-10-24-agent-as-tool.md)）：子 agent 每次從空的開始、同一份檔每次重讀（記憶）；要不要讓子 agent 換強模型。（失敗回給腦、轉接共用 `lib/agent/agent_tool.py` 10-24 下午做了。）

## agent-gus 小念頭（試驗場 `~/code/try/thoughts`，有 README.txt）

```sh
cd ~/code/try/thoughts && rm -rf ws-real && mkdir -p ws-real/new && cp question.txt ws-real/new/sort.txt
aos-exec --ws ws-real $R/demo/agent-gus; echo rc=$?; python3 measure.py ws-real/.stack
```

- 成功：`ws-real/out/sort.txt` 有三種排序的數字與建議；`.stack/thoughts/<id>/` 是念頭樹；`measure.py` 印 context 比例（假腦 19%）。
- 呼叫：幾十次（假腦 17 次、6 個小念頭；額度最多 10 個、深 2 層）。風險：每層同時 3 個、最多 9 棵行程樹打同一端點，被限流會一起 `BrainFailed`；一個小念頭 900 秒、fork 格 1 小時。
- 打磨方向（[thoughts](../../../../proto8/thinking/2026-10-24-thoughts.md)）：真模型拆得太碎或太粗、被 needs 的字帶偏；context 一層層轉手會失真；小念頭失敗停下等人、SIGKILL 可能留孤兒。

## agent-meg 記憶（試驗場 `~/code/try/memory`，有 README.txt）

```sh
cd ~/code/try/memory && python3 run.py
```

- **先看 log 第一行是「腦：…（LiteLLM）」**——連不上會靜靜改假腦。成功：`runs/<時間>/log.txt` 兩題結束碼 0、`.heap/` 存了 prefs、facts；第二題（全新 stack）答出「4 個空格、repo 根目錄、`cmake --build --preset default`」。測試版要 `AOS_REAL_MODEL=1` 跑 `test_meg.py`。

- 打磨方向（[memory](../../../../proto8/thinking/2026-10-24-memory.md)）：腦把猜的存成事實、之後每次自動附上且不記來源；不同標題講同一件事會一起附、可能互相矛盾。

## talk（三隻互寄信；試驗場 `~/code/try/agent-talk`，有 README.txt，`ws/` 要先建）

```sh
cd ~/code/try/agent-talk && python3 setup_ws.py && cd ws && aos-exec $R/demo/talk/team; echo rc=$?
```

- `setup_ws.py` 會刪舊 ws。成功：結束碼 0、`user/new/` 收到 ann 的公告且有 11985 元；各自 `sent/`、`out/`、`.stack/<名>/history.jsonl`（假腦 6 封信）。
- 呼叫：6～10 次。風險：daemon `max` 3600、輪詢 500 ms，真模型繞圈最多跑 30 分鐘；一個 member 的腦失敗整隊退 1。
- 打磨方向（[agent-talk](../../../../proto8/thinking/2026-10-24-agent-talk.md)）：ann 同時等兩封回信只靠 history 記，可能漏「兩封都到才整理」；自動回信剛好第 `max_hops` 手被擋，問的人永遠等不到。

## agent-kai 按意圖組 context（bench；輸出到 `~/code/try/intent-context/runs/`）

```sh
cd ~/repo/simple_tools/aos && python3 proto8/tests/bench_intent_context.py --upstream $U   # 可加 --model …、--only kai
```

- 成功：`results.json` 三隻的答對數（假腦 15/15/14）、用 `usage.prompt_tokens` 比 kai 比 dan 省多少；第 13 題 kai 要靠 recall 撿回。
- 呼叫：60～100 次（15 題 × 3 隻），最貴的一項之一；子行程逾時 900 秒、proxy 180 秒。bench 用 `--upstream`／`--model`，不轉送 key。
- 打磨方向（[intent-context](../../../../proto8/thinking/2026-10-24-intent-context.md)）：每次組的前綴不同、幾乎吃不到 prompt cache，帳單可能反而比 dan 貴（看 cached tokens）；字面比對對同義詞無力（「房間號碼」對「房號」）。

## self-improve（含 sandbox.json；試驗場 `~/code/try/self-improve`，有 README.txt）

**跑前先決定「self-improve 預設就關」**（入口殘項；sandbox 那份的翻案判準就是「拿真模型跑之前」）。

```sh
export PATH=$HOME/code/try/sandbox/s6-root/bin:$PATH        # s6-softlimit（sandbox.json 有 mem_mb）
cd ~/code/try/self-improve && python3 setup_ws.py ws && cp $R/sandbox/examples/self-improve.json ws/sandbox.json
aos-exec --ws $PWD/ws $R/demo/self-improve; echo rc=$?
```

- 成功：結束碼 0、`ws/out/result.json` 達成、`out/best/` 8/8；結束碼 2（`BudgetSpent`）＝預算用完沒達成。看 `ws/out/report.txt` 與各版 `ws/.stack/versions/vNNN/diff.txt`——**檢查有沒有把例子的答案寫死**。
- 呼叫：最多 5 輪、每輪 5～20 次，共 10～100 次；token 預算 50 萬（只算 improver）。逾時：improve 30 分、think 180 秒、run 15 分。腦連不上停在 improve、退 1。
- 打磨方向（[self-improve](../../../../proto8/thinking/2026-10-24-self-improve.md)）：沒有 `sandbox.json` 時被改的函數讀得到 `judge/cases.json`；improver 只看得到最好那版與分數、看不到改壞那版，同一種錯可能再犯。
