# 請求：用 fable 想一題頂層設計——aos 怎麼支援「反向傳播式自我改進」

## 題目
今天 arknights 知識庫這條線（`proto8/thinking/2026-11/07/arknights-kb/`）實際跑出一個模式：sol 先摸索 → 把走過的路固定成步驟工具／腳本 → 降級模型（sol→terra→luna→本機）看哪裡錯 → 錯的地方再工具化，並連帶優化被影響的子函數（使用者稱「反向傳播」，他說「這種改進行爲我會特別關注」）。
目前這套靠隊長人工在做。**請想：aos 本體（概念層與機制）要怎麼支援這種自我改進，讓它變成系統的一部分而不是靠人**。要涵蓋使用者今天的想法（原話在 `proto8/thinking/2026-11/07/kb-ideas/README.md`，想法 1～10，必讀）：
- 統一路徑 `a/b#/c/1`（檔案路徑＋JSON 路徑）、連結別濫用、tag；
- 函數 metainfo＝任意 JSON 值（可細化、可寫公式 `{"cal":"x*2"}`），分「自我宣稱」與「他者觀測」（呼叫過程自己統計）；成本含 token／calls／時間；
- 少上下文、嵌套分派、thought 隔離、重複任務長出專精 agent、llm kernel 可嵌套、agent 可以成千上萬（可 sleep）；
- 優化目標是「產出過程的成本」，格式檢查只是門檻。
