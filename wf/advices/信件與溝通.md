## mailbox_read 預設刪信，專區回信讀完就驗不了

- 主題：信件與溝通
- 哪裡：MCP `mailbox_read`（不帶 keep）＋ `aos-user verify`。
- 現象：用 `mailbox_read` 讀了兩封使用者專區回信，信夾就被刪掉，之後沒東西可驗。拿 `~/.aos/user/done/<月>/<原信>/reply.json` 去驗也不行：`aos-user: error: VerifyBad not a user-zone reply (no zone key or no in_reply_to)`。只能逐欄比對，少了 level 1 驗證；push、刪檔這類授權正是最需要驗的。
- 建議：擇一或都做。帶 `zone` 鍵的信 `mailbox_read` 預設 keep，或至少在輸出末行提醒「這是專區回信，要驗請 keep:true」；`aos-user verify` 也接受 done/ 底下的 reply.json，或接受信名自己去 done/ 找。
- 痛的程度：拖慢
- 提出者與日期：ok-pilot 2026-11-14
- 出處：wf/temp/ok-pilot/aos-advice/mailbox_read預設刪信讓專區回信驗不了.md；wf/temp/ok-pilot/notes.md「摩擦：專區回信讀了就沒了」
- 狀態：已排入（ok-misc）。lib/agent/mailbox_read/_entry 目前仍是預設讀完就刪。

## fyi 信的 status 規則不在 schema/letter.json 裡

- 主題：信件與溝通
- 哪裡：`~/.aos/user/schema/letter.json` 與 `aos-user send` 的檢查。
- 現象：照 schema 寫 fyi 信，status 用 NEEDS-USER（schema 的 enum 有），送出被退：`SchemaBad fyi status must be one of DONE, FAILED, BLOCKED`。照 schema 寫的檢查器抓不到這條。
- 建議：把「依 kind 限定 status」寫進 schema（if/then 或 oneOf 按 kind 分支）；或在 door.json 的 kind 說明列出各 kind 可用的 status；另給 `aos-user send` 加 `--dry-run`，只檢查不寄。
- 痛的程度：小不便
- 提出者與日期：ok-pilot 2026-11-14
- 出處：wf/temp/ok-pilot/aos-advice/fyi信status規則不在schema裡.md；wf/temp/ok-pilot/notes.md「摩擦：fyi 信的 status」

## MCP subagent ask／listen 有 60 秒硬上限，蓋過 timeout_s

- 主題：信件與溝通
- 哪裡：aos MCP 的 `subagent` 工具（op ask、listen）。
- 現象：`ask`／`listen` 帶 `timeout_s: 600`，60 秒就被砍：`aos-mcp: error: CommandFailed subagent timed out (60 s); its process group was killed`。工具說明寫預設 600，看不出 MCP 層另有上限。sol 的題目常要 1～5 分鐘，ask／listen 對真題幾乎等不到。繞法：say、結束這輪、clock_register 叫醒再 listen（timeout_s ≤ 50）；或背景看 history.jsonl（[wf/public/tools/waitdone](../public/tools/waitdone/README.md)）。
- 建議：MCP 層照 timeout_s，或在說明寫明上限；超過上限直接回 ArgumentsBad；逾時回「還沒答」（例 `AnswerPending`＋已等多久），不殺行程、不算錯，可以續等。
- 痛的程度：拖慢
- 提出者與日期：ok-pilot 2026-11-14；ok-llmk2 2026-11-14（listen，活樹上仍撞到）
- 出處：wf/temp/ok-pilot/aos-advice/MCP-subagent的60秒上限蓋過timeout_s.md；wf/temp/ok-pilot/notes.md 第二輪第 4 點；wf/temp/ok-llmk2/aos-advice/subagent-listen-60s.md
- 狀態：已解（252669c47：MCP 層 subagent／fork 不再被 60 秒砍，timeout 0＝不限時；後續測試修正 77a822e1c）。活樹待換樹（ok-llmk2 當天在活樹上還是撞到）。另外 MCP client 自己也有工具逾時（Claude Code 是 MCP_TOOL_TIMEOUT），超過還是會被 client 砍；「逾時回還沒答、可續等」那條沒做。

## aos-agent 沒有 ask，一問一答要拆成 say＋listen

- 主題：信件與溝通
- 哪裡：`aos-agent` 指令（proto8/cmd/aos-agent）。
- 現象：`aos-agent ask --target fsm_ann "現在幾點？"` 回 `CommandUnknown unknown subcommand ask`。agent 的 `subagent` 工具有 `op: ask`，人用的 aos-agent 沒有；腳本得寫 `aos-agent say … >/dev/null; aos-agent listen --target X --timeout-s N`。兩步之間若別人也對同一隻 say，listen 拿到的可能不是自己那句的回答。
- 建議：加 `aos-agent ask --target X [--timeout-s N] TEXT`：say 後只 listen 自己那封信的回答（用 say 印的信名配對），逾時退非 0；名稱、行為跟 subagent 工具的 ask 對齊。
- 痛的程度：小不便
- 提出者與日期：ok-kf 2026-11-14
- 出處：wf/temp/ok-kf/aos-advice/aos-agent-no-ask.md；proto8/thinking/2026-11/14/kernel-framework-1114.md 批 13、14
- 狀態：未處理
