在 ~/code/playground-arc-play 跑一棵 11 題的小樹：幾秒跑完、能停能暫停、能改旋鈕。下面每一步的輸出都是 11-08 實跑貼上的。

① 入門→ ② 詳解→ ③ 帶玩（本頁）

這棵小樹的引擎就是 arcagi 的 run_curve（r07／r08 的學習迴圈）；跟 r09 正在蓋的活樹 ~/code/playground-arc1/ 完全分開，玩壞了一鍵 reset。不用 LLM、nice -n 19、4 個 worker。

0遊樂場長怎樣

只有一個指令 play；你動的是 tree/，seed/ 是還原用的原版。

題組是哪 11 題

要學的 L（計分）8 題：68b16354、d10ecb37、1e0a9b12、beb8660c、a740d043、6f8cd79b、ce4f8723、995c5fa3（前四題在 r08 的 dec-g1 曲線解得出、後四題解不出）。只量不學的 H 3 題：44f52bb0、5bd6f4ac、ea32f347。全部出自 training。名詞見 題組。

3跑一輪

play run
[play r001 s0] pass 0: L=3 H=1 H24=None P=None/None lib=0 logcost=102.966 wall=0.2s
[play r001 s0] pass 1: L=4 H=1 H24=None P=None/None lib=0 logcost=101.551 wall=0.2s
[play r001 s0] pass 2: L=4 H=1 H24=None P=None/None lib=2 logcost=92.91 wall=0.2s
[play r001 s0] pass 3: L=4 H=1 H24=None P=None/None lib=2 logcost=92.976 wall=0.2s
[play r001 s0] pass 4: L=4 H=1 H24=None P=None/None lib=2 logcost=91.037 wall=0.2s
[play r001 s0] pass 5: L=4 H=1 H24=None P=None/None lib=1 logcost=91.124 wall=0.2s
done: AUC_L=20 (sum of solved_L over passes 1..5), delta=1; files in tree/runs/001/

代表：每行一個 pass（全部題目重試一遍，pass 之間故意等 3 秒）。L＝8 題學的題解出幾題：pass 0 解 3 題 → pass 1 變 4 題；lib＝這個 pass 能用的積木數；logcost 從 103 降到 91＝同樣的題找得更快。AUC_L＝pass 1～5 的 L 加總＝20。H24、P 是 r08 的欄位，這裡沒用，印 None。

為什麼 pass 1 就多解一題、lib 卻還是 0？

pass 0 解出的程式會更新「哪些原語常用」的排序（旋鈕 order=prior），pass 1 的枚舉先試常用的，beb8660c 就在預算 3 萬內找到了。pass 1 結束後 G1 才把 1e0a9b12 和 beb8660c 共有的片段收成積木，所以 pass 2 的 lib 才變 2。練習 4 會把這個排序關掉驗證。

練1把學習關掉，看差多少

play set pace_s 0      # 全速，不等 3 秒
play set learn false
play run
learn: True -> False (takes effect on the next play run)
[play r003 s0] pass 0: L=3 H=1 H24=None P=None/None lib=0 logcost=102.966 wall=0.2s
[play r003 s0] pass 1: L=3 H=1 H24=None P=None/None lib=0 logcost=102.966 wall=0.2s
…（pass 2～5 一模一樣）
done: AUC_L=15 (sum of solved_L over passes 1..5), delta=0; files in tree/runs/003/

代表：不學就原地踏步：AUC_L 15（開學習是 20）、logcost 一直 103。這就是「不學對照」，r08 的 pool-noG1 同一個意思。做完 play set learn true 改回來。

練2拿掉一個原語

play exclude sort
play run
play include sort      # 放回去
exclude = ['sort'] (takes effect on the next play run)
[play r004 s0] pass 0: L=2 H=1 H24=None P=None/None lib=0 logcost=104.974 wall=0.2s
[play r004 s0] pass 1: L=2 H=0 H24=None P=None/None lib=2 logcost=103.486 wall=0.2s
…
done: AUC_L=10 (sum of solved_L over passes 1..5), delta=0; files in tree/runs/004/

代表：沒有 sort，靠排序的 1e0a9b12、beb8660c 都解不出，L 掉到 2。這種「留一個原語看掉幾題」就是 r09 規劃的 sieve/exclude 掃描。全部原語 play prims。

練3預算加大

play set budget 100000
play run
budget: 30000 -> 100000 (takes effect on the next play run)
[play r007 s0] pass 0: L=4 H=1 H24=None P=None/None lib=0 logcost=114.635 wall=0.5s
[play r007 s0] pass 1: L=4 H=1 H24=None P=None/None lib=2 logcost=109.668 wall=1.0s
…
done: AUC_L=20 (sum of solved_L over passes 1..5), delta=0; files in tree/runs/007/

代表：預算 10 萬時 pass 0 就硬搜到 beb8660c（要 8.9 萬個），所以 delta 0；學習的好處變成「更快」（logcost 115→110），不是「多解」。預算小一點（例如 5000：L 只剩 2）就連起點都變差。改回 play set budget 30000。

練4關掉「常用先試」排序

play set knobs.order size
play run
play set knobs.order prior   # 改回來

[play r005 s0] pass 1: L=3 H=1 H24=None P=None/None lib=0 logcost=102.966 wall=0.2s

代表：只照大小排序時 beb8660c 一直找不到，第二支含「每列排序」的程式沒出現，G1 也就湊不出積木——小型的冷啟動。旋鈕一個個改、看曲線變不變，就是元優化在做的事。

還能改哪些旋鈕

play set 不帶參數會列出可改的鍵：passes（1～12）、budget（1000～200000）、workers（1～6）、pace_s（0～30）、learn、g4、knobs.decomp、knobs.m、knobs.k、knobs.max_holes、knobs.lib_cap、knobs.order、knobs.lam_depth。上面四個練習以外的組合沒實跑過，結果自己看。
