1一輪 r0x 的流程

一輪 = 簡報 → fable 規劃 → Argon 審 → 設計定稿 → 施工 → 評測 → 總結＋代定清單。

步誰做什麼（大白話）檔
01 簡報隊長（opus）把上一輪結果、你的新想法、硬限制整理成給 fable 的考卷，最後一節是「請 fable 回答」01-簡報.md
02 規劃fable逐題回答：做哪幾步、每步怎麼驗收、判準先寫死02-規劃-fable.md
02b 審Argon（經 aos 轉）唯讀挑錯＋提案；不用等它回才開工，採不採由隊長記代定02b-Argon審.md
03 設計隊長定稿：模組契約、分線（同時 ≤3 條，opus／sonnet）03-設計.md
施工子 agent寫程式、跑小測；共用檔只有隊長碰src/、scripts/
評測隊長跑學習曲線；收輪前跑一次 400 題 gatedreports/、artifacts/
04 總結隊長數字、判準過沒過、下一輪方向（§6）04-總結簡報.md、代定清單.md
收輪義務與硬限制
  • 論壇發帖：~/repo/simple_tools/aos/wf/tools/forum_post.sh arcagi '<標題>' <檔> --tag arcagi；精華 forum_admin.sh feature <id> --as arcagi。
  • 交棒總表：~/repo/arcagi/notes/rounds/README.md（冷啟動先讀它）。
  • 資源：子 agent ≤3；CPU 批次 nice -n 19；單批記憶體 ≤16G（systemd-run --user --scope -p MemoryMax=16G）；swap 只有 512MB；全機同時只跑一個全量評測。

2節點樹與一個 pass 怎麼跑

一個 pass：所有題目用目前的積木庫重搜一遍 → 過門的程式拿去 G1 壓縮 → 下個 pass 庫變大。

每個 pass 印一行（實際 log 格式）

[pool s0] pass 2: L=4 H=0 H24=2 P=15/13 lib=3 logcost=246.331 wall=5.0s

L＝L16 解出數、H＝H8 解出、H24＝H24 解出、P＝練習池「過 train 數／過門數」、lib＝這個 pass 用的積木數、logcost、wall＝秒。

樹有哪幾種（r08 的 --tree）
tree意思
dec-g1r07 對照：演繹分解＋G1、r07 規則
poolr08 主樹：分解＋G1＋主題練習池 P32＋留一門
pool-noG1同樣預算但不學（對照）
pool-rand32／pool-foot32練習池換成隨機 32 題／立足點主題 32 題
pool-halves多開 halves 拆法
pool-g4再加 G4 演化，每個 --seed 一條
meta／action元優化：改一個旋鈕或加一個拆法，用 CRN 判準決定留不留
r09 的 epoch（r09 施工中）

規劃稿 notes/rounds/r09/02-規劃-fable.md §5：① 主跑（只用 live 列）→ ② gate 節點 → ③ grow 造 comb（孵化中）→ ④ 影子跑（live＋孵化中）→ ⑤ stall／route（停滯判斷、UCB 選臂）→ ⑥ 判準決定誰升級 → ⑦ 寫 epochs/<n>/、live/。

H24 底線：升級在 epoch 邊界整批提交；下個 epoch H24 退步就整批回休眠、重跑。後端改 C++ arcbatch（目前 r08 曲線仍是 Python 後端）。

4重要檔案格式

看學習迴圈只要懂三個輸出：solutions.jsonl（每題答得怎樣）、curve.csv（每 pass 的分數）、blocks.json（學到什麼）。

程式長怎樣（program JSON）

["sort", ["blk", "g1_f72643d574", ["$in"]]]
#  原語呼叫 ["prim", 參數…]；["$in"]＝輸入格子；["$0"]／["$1"]＝lambda 參數
#  ["lam", n, body]＝lambda；["blk", 名字, 洞…]＝引用積木；整數＝常數

blocks.json（積木庫，一個 list）

[{"name": "g1_f72643d574", "body": ["map", ["lam", 1, ["sort", ["$0"]]], ["$h0"]],
  "sig": "…型別…", "src_tasks": ["1e0a9b12", "beb8660c"], "saving": …, "uses": 8,
  "born": 1, "holes": 1, "idle": 0}]

$h0＝洞（呼叫時填）；src_tasks＝從哪幾題抽出；born／holes／idle 是 grow 加的，讀取時忽略。上例取自遊樂場實跑。

solutions.jsonl 欄位 
{"pass": 0, "set": "L", "task_id": "68b16354", "program": ["reverse", ["$in"]],
 "source": "enum", "train_ok": true, "test_ok": true, "nodes": 23, "nodes_to_first": 23,
 "near_top": ["$in"], "seconds": 0.001, "gate_ok": true, "mdl_ok": true, "gate_nodes": 69}
  • set：L、H、H24、P。source：enum（枚舉）或 g4（演化）。
  • nodes_to_first：試到第幾個節點才找到；沒找到是 null。
  • near_top：最接近的失敗程式（冷啟動用）。gate_* 只有開留一門才有；練習池另有 synth_n／synth_ok。
curve.csv 欄位

pass, solved_L, solved_H, wall_s, nodes, llm_calls, lib_size, lib_bits, mean_prog_nodes, nodes_solved, solved_P, clean_P, budget_P, lib_from_P, logcost_L, solved_H24, nodes_total, false_pos, synth_ok

  • AUC_L 不存欄位，現算：pass 1～8 的 solved_L 加總；Δ＝最後 pass − pass 0。
  • curve_sha＝清掉 wall_s 後整檔 sha1，用來證明重跑逐位相同。
  • false_pos：過門但 test 錯的題數（要是 0）。
題目 JSON 與 taskset.json 
{"train": [{"input": [[0,1],[1,0]], "output": [[1,0],[0,1]]}, …],
 "test":  [{"input": […], "output": […]}]}      # 格子是 0～9 的整數；求解器拿不到 test output

data/r08/taskset.json：鍵 learn（L16）、holdout（H8）、holdout24、practice（P32）、rand32、pool_foot32，每題 {"task_id", "sha1", …}；另有 rule 寫產生規則。

eval 報告與 trace
  • 報告（arcagi-evaluation/1）：tasks_total、tasks_correct、task_accuracy、tests_*、tasks[]（每題 task_id、correct、tests[{prediction, expected}]、trace）。
  • --traces 每行一筆 arcagi-trace-record/1：task_id、correct、elapsed_seconds、trace（attempts[]、selected、metadata）。
  • 外部求解器協定：讀 request {"schema_version":"arcagi-solver-input/1","task_id","task":{train,test}}，寫 {"<task_id>": [每個 test 一張格子]}。說明在 docs/solvers.md、docs/traces.md。
帳本：aos/meta/ledger.jsonl、aos/pool/
  • aos/meta/ledger.jsonl：r06 產生器帳（run_id、layer、score_main、accepted…）與 r07／r08 元優化回合（kind、knob、before、after、auc_*_seeds、accepted、mean_drop、se）。路徑可用 ARCAGI_META 換。
  • aos/pool/：r01～r06 舊樹的 node-pool 帳（config.json、wallets.json、ledger.jsonl、epochs/<n>.json）；r07 起的空樹沒有記這本。
  • arcbatch configs 每行：{"name","lib":"blocks.json","budget":100000,"decomp":false,"lam_depth":2,"exclude":[…],"order":{…}}。
r09 的五檔（r09 施工中）
  • ops.jsonl：一列一招：id、kind（comb／decomp／rewrite／route／gate／sieve）、status（incubating／live／dormant）、payload、evidence、ttl、env_hash、by、born、blamed_by。
  • ledger.jsonl：kind（epoch／promote／rollback／layer2／say／foundry／stall）、before、after、judge、evals。
  • frozen.json（判準與盲測題號，寫死不搜）、每節點 _metainfo.json、_witness.jsonl。
  • live/_status.json、events.jsonl 的欄位規劃稿沒寫（待確認）。
{"id": "…", "kind": "gate", "status": "live", "payload": {"params": {"mdl_div": 1.0, "loo_frac": 0.25,
 "loo_min_pairs": 3, "lib_cap": 16, "retire_after": 2, "m": 3, "k": 2.0, "max_holes": 2}}, "by": "agent-r09", …}

名詞表

頁內虛線字會跳到這裡；帶玩頁的名詞也連回這裡。

aos
「資料夾＝程式」的 AI agent 體系；arcagi 借它的樹、節點、帳本的想法來組解題器。
樹
一套解題設定加它長出的積木，例如 pool、dec-g1；r09 起是真的一棵資料夾樹（hammer）。
節點
樹裡負責一件事的單位（解題、審查、改進…）；r09 每個節點一個資料夾，有 _metainfo.json 與信箱。
原語
最小的指令，空樹固定 32 個：add、map、sort、reverse、transpose、zipwith…（play prims 可列）。
積木
從解過的程式抽出來的共同片段，存進 blocks.json，之後當一個指令用（["blk", 名字, …]）。
枚舉
從小到大把原語與積木拼成程式、一支支試；型別不合的直接跳過。
預算
每題最多試幾個節點（程式）；r07／r08 預設 100,000。
pass／epoch
把所有題目用目前的庫重搜一遍算一個 pass；pass 0 是空庫起點。r09 改叫 epoch。
L16／H8／H24／P32
題組：L16 要學、計分；H8、H24 盲測只量不學；P32（r09 P48）練習池，只練不計分。全部出自 training。
過 train 答錯
程式把 train 例子全答對、test 卻錯——背了例子沒學到規則；守門就是要擋這種。
AUC_L
pass 1～8 的 L16 解題數加總；越大＝學得越快越多。r08 主樹 32。
logcost_L
每題找到答案花的節點數取 log2 加總（沒解記上限）；越小越省。
G1 壓縮
把已解程式的共同子樹挖出來做成積木；夠省位元才收。
反合一
兩支程式對齊，不同的地方挖成洞（$h0），留下共同骨架。
MDL
最短描述長度：積木要讓「庫＋所有程式」總長變短才划算。
門／留一門（LOO）
決定哪支程式能拿去學。r08：拿掉一個 train 例子重搜，還能找到同類程式才算數，不看 test 答案。
G4
演化：把差一點的程式突變、交配；r08 主樹預設關。
演繹分解
先猜大結構（例如「每列各自做一件事」），把整題拆成小題再搜；r07 起 C++ 有七個拆法。
冷啟動
一開始解不出題 → 沒料可壓縮 → 庫不長 → 還是解不出；r08 的主要卡點。
元優化（meta）
優化「學習迴圈本身」：改旋鈕、加拆法，再看曲線有沒有真的變好。
旋鈕（knobs）
m（每 pass 收幾個積木）、k（洞的懲罰）、max_holes、order（size 或 prior：照使用次數排序）、lib_cap、decomp…；存 data/r0x/knobs.json。
CRN
共同亂數：比較前後兩版時用同一批 seed，雜訊才不會蓋過差異。
gated（守門入口）
python -m arcagi.solvers.gated：跑完 C++ 混合求解，再用重驗與合成例子決定要不要交答案（不確定就棄答）。r07 起的正式 400 題入口。
影子跑
新東西先「只答不算」跑一陣，數據夠好才上線。
arcbatch
C++ 批次枚舉器（native/bin/arcbatch），跟 Python 逐題 0 差異、快 12～22 倍。
純度（purity）
空樹不准帶 ARC 專用字眼或 import 舊樹；scripts/r07_purity.sh 檢查。
fable
頂層規劃模型，每輪寫 02 規劃稿；它寫過的設計在看板「fable 的設計」。
Argon
Gemini 第二意見，經 aos 轉，唯讀審規劃稿（02b）。
代定
隊長替你先做的方向決定（編號 D-r9-3 這種），記在每輪 代定清單.md，你可翻案。
錘子（hammer）
r09 的新樹：使用者說「先造 lv1 錘子去打造 lv2 錘子」；錘子＝節點樹本身。
ops.jsonl／孵化三態
r09 的招式表，每列一招；狀態 incubating（孵化）→ live（上線）→ dormant（休眠），由樹的判準升降。
鑄模廠／蠟模
r09：卡死（stall=stop）時才讓 LLM 解一題，只留每步的輸入輸出軌跡（蠟模），程式銷毀；枚舉器再逐段擬合成招式。
stall／UCB
停滯判斷（餓死／飽和／stop）與多臂選擇法：卡住時決定下一步往哪種改進投資源。
H24 底線
r09 硬規則：每個 epoch 的 H24 盲測不准退步，退了整批升級回滾。
