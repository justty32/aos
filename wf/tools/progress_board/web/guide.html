aos × arcagi 入門

一句話：讓電腦自己長出一棵「解謎程式樹」，越解越快、越解越多，而且不靠神經網路。

① 入門（本頁）：圖＋結論→ ② 詳解：指令、格式、資料夾→ ③ 帶玩：在遊樂場親手跑一次

1在解什麼：看幾個例子，猜出規則

電腦要從少少幾個例子「寫出一支程式」，再拿去答新題；答案靠確定的程式，不靠猜。

細節
  • 只交一個答案（top-1），格子大小與每格顏色全對才算對。
  • LLM 只能幫忙找規則、寫程式、蒸餾；最後解題的是程式。神經網路盡量不用。
  • 可以暴力吃 CPU、可以寫 C++／CUDA。

2什麼是「aos 的樹」：資料夾＝程式

樹＝一包原語＋越長越多的積木＋幾個負責「解、審、改」的節點；全部是檔案，打開就看得懂。

細節
  • r07 起用「空樹」：只有 32 個通用原語（不准帶 ARC 專用知識），看它能自己學多快。程式在 src/arcagi/seed/。
  • 學到的積木存成 blocks.json（一個 list）。r01～r06 的舊手寫樹另在 repo 根的 aos/blocks/，是另一套。
  • r09 要把整個學習迴圈變成一棵「活樹」：節點是真的資料夾，有信箱，你能 cd 進去下指令（r09 施工中）。

3一個 pass：試 → 驗 → 抽積木 → 再試

一個 pass 就是「全部題目重試一遍」；學到的積木讓下一遍更快，有時多解一題。

細節
  • 枚舉有預算（試幾個節點就停，預設 10 萬）。
  • 壓縮＝把兩支已解程式的共同骨架挖出來（反合一），夠省位元（MDL）才收成積木。
  • r08 加了「留一門」：只看 train 例子決定能不能拿來學，不偷看 test 答案。
  • r09 把 pass 改叫 epoch，多了審查、停滯判斷、路由等步驟（r09 施工中）。

4怎麼算進步：學習曲線下的面積

r07 起主指標是「從空樹學解一小組題有多快」（AUC_L），不是 400 題拿幾分；400 題只偶爾量一次看泛化。

細節
  • 題組：L16＝要學的 16 題（計分）；H8／H24＝只量不學的盲測；P32／P48＝練習池（只練不計分）。
  • AUC_L＝pass 1～8 的 solved_L 加總；logcost_L＝每題花幾個節點才找到（取 log），越小越省。
  • 使用者說：成績上上下下正常，看多輪趨勢和方向。

5一輪（r0x）怎麼走

每輪固定七步，產物都在 ~/repo/arcagi/notes/rounds/r0x/；方向題不停線，隊長先「代定」，你之後可翻案。

細節
  • fable＝頂層規劃模型；Argon＝Gemini 第二意見，唯讀審規劃。
  • 代定清單：隊長替你先做的決定，每條寫了怎麼翻案。
  • 防當機：子 agent ≤3、nice -n 19、單批記憶體 ≤16G、全機同時只跑一個全量評測。
