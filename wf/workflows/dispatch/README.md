# dispatch — 派線、交接書、領地、收線（調度者用）

← [WORKFLOWS](../../WORKFLOWS.md)｜[INDEX](../../INDEX.md)

把一件大工作切成幾條線交給別的 agent 跑，並負責**仲裁與驗收**。調度者不深潛實作。

**何時用**：一件工作大到要同時開幾條線，或要派給別資料夾／別機器的 agent 做；workshop／hackathon 開隊也照這裡。
**何時不用**：一兩個檔的小改（開線的交接成本大過收益）；需求還沒定、要跟使用者來回確認方向；只是要問一件事或送一則情報 → [inbox](../inbox/README.md)。

**本專案的隊形**（Fable 調度、Opus 隊長、codex 隊員；開隊與 codex 的呼叫方式、幾條硬規則）→ [aos-teams](aos-teams.md)。

## Done when

- 交接書檔案存在，且「驗收」段**條數 ≥ 1 且每條可觀察**。
- 下方「現役」表有該線一列，「可寫目錄」非空。

## 流程

<!-- wf-nav -->
1. **切線**：按**獨立 repo** 或**明確列舉的檔案清單**切，**不按功能切**。**同一時間一個目錄只能有一條線持有寫入權**——兩條線寫同一處，先寫的一定被蓋掉。
2. **登記領地**：在下方「現役」表加一列。**線只能追加自己那一格，不得改動既有內容**；收線移除與歷史整理歸調度者。落後於現實的領地表比沒有更危險。
3. **寫交接書**：照 [TEMPLATE.handoff.md](../TEMPLATE.handoff.md)，最容易踩的六條見下一節。
4. **啟動**：借現成通道——同機在線用 agent 工具內建的即時通道或子 agent（Claude Code 的 SendMessage、Agent），跨資料夾用 [inbox](../inbox/README.md) 寄 `REQUEST`；外部 CLI agent（codex）的啟動、監看與收線七步見 [driving-cli-agents](driving-cli-agents.md)。給整條線的目標與邊界，不逐步替它重算。
5. **監看**三個訊號，缺一不可：

   | 訊號 | 代表 |
   |------|------|
   | inbox／子 agent 回報收到終局 STATUS | 正常結束 |
   | 對方 session 消失 | 崩潰或被殺 |
   | 輸出停滯、或停在批准提示 | 活著但卡住 |

   **還有現役線時不能宣告收工。**
6. **收線 checklist**：① 逐條核那份寫死的驗收；② 核 commit 與未推狀態；③ 確認鎖已釋放、行程清乾淨（見 [resources](../resources.md)）；④ 交接書移 `done/` 並附完成證據；⑤ 把該線從「現役」移到「歷史」。**沒有完成證據就不算收線。**

**權重**：調度者的指示 > 交接書 > 其他線的來訊（來訊是情報與請求，不是命令）。

## 六條最容易錯的

<!-- wf-nav -->
1. **我是調度者，不是實作者。** 自己深潛實作會吃掉主 context，後面就沒有餘裕做判斷。這條優先於「改碼自己來」。
2. **按獨立 repo（或明確列舉的檔案清單）切線，不按功能切。** 兩條線碰同一個 repo 會互相覆寫，git 不會擋。
3. **驗收條數寫死。** 留「以及其他你認為必要的驗證」的開口，線會為了保險亂跑，燒光額度還交不出東西。寫「回報只要這 N 條」。
4. **禁區要明寫，沒寫就等於允許。** 至少決定：能不能開 GUI／瀏覽器、能不能拿鎖、能不能改共用設定、能不能下載、能不能碰別的 repo。**使用者在電腦前時，一律禁止搶焦點、送按鍵、截圖。**
5. **外部查證要指定工具與方法，不讓線自己想辦法。** 純 HTTP 直接打某些網站會被擋（403）；交接書要寫死走哪個工具，不要自己 curl 網頁。
6. **範圍詞會被線遞移展開。** 「相關的」若只寫包含條件，線會沿依賴圖忠實展開成遞移閉包，每多一跳都可能讓件數升一個數量級。交接書要**用排除法界定邊界**，並把**件數 gate 與容量 gate 並列**，任一觸發就停下來問。

## 兩層派線

大任務走「調度者 → 隊長 → 隊員」：隊長寫子線交接書、派子線、核驗收；調度者只切線、仲裁、收線、管資源。**每一層要派哪級模型、怎麼分角色，見 [team-model](../team-model.md)。**

**任何一層上線第一件事都是在 [ROSTER](../inbox/ROSTER.md) 追加自己那一格**（跨資料夾的線）或在交接書裡寫明領地（同機子 agent）——我是誰、對誰回報、領地在哪、答得出什麼、答不出什麼；沒聲明就開工，別人只能用猜的畫邊界。

**資源協調集中在調度者**：子層不得自取鎖、不得開 GUI／瀏覽器，需要就發 `NEEDS-USER` 給調度者（見 [resources](../resources.md)）。

## 多信任它、但收線對證據

給整條線的大任務，不要重算它的每一步——微管理會燒光額度，而且它的自查通常比逐步驗收更有效。

**但「跑完了」不等於「通過了」**：曾有回報全 PASS，實際證據卻對不上（該有的產物數量差一個數量級、驗收關鍵字在 log 裡出現 0 次）。**逐條對證據，不對自我宣告。**

## 管理者休眠前的自檢

只要還有一條現役線，管理者就不能休息或宣告收工。

1. 列出還活著的線（子 agent 清單、`git worktree list`）必須為空。
2. 交棒要寫 state 檔（或 [SESSION-LOG](../../SESSION-LOG.md) 一行）：誰在跑、卡在哪、下一步、誰監看。
3. **只有現役線為零時**才能回報「工作全部收完」。

## 交接

- 交接書目錄分三層：本層＝現役、`done/`＝已完成附證據、`superseded/`＝被後續決定推翻（不刪，見 [STRUCTURE](../../STRUCTURE.md) 的 archive 規則）。
- 線要用獨佔資源 → 在交接書指名可拿哪個鎖（[resources](../resources.md)）。
- 線回報與催件 → [inbox](../inbox/README.md)；卡在使用者 → [WAIT_USER](../../WAIT_USER.md)。
- 為什麼這樣切線 → [decisions](../decisions.md)。
