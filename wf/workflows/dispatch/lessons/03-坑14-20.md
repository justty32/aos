11-13 公司 WSL 一天開十幾條線、旁邊有使用者在用的樹，踩出來的七條。這台任務書必貼的硬規則全文在 [aos-teams/06](../aos-teams/06-公司WSL活樹與任務書硬規則.md)。

## 14. 禁區寫成「唯一准用的做法」，不寫「不要碰 X」

任務書只寫「不碰 `~/aos-home`、跑完把起的行程收掉」，子 agent 就用 `pkill -f` 收自己的測試 daemon，命令列跟活樹的根 daemon 一樣，使用者的樹停了約 4 分 20 秒（11-13 10:25，[事故紀錄](../../../../proto8/thinking/2026-11/13/kernel-framework-開工.md#十一事故子-agent-誤停使用者的樹11-13-1025)）。「不要碰 X」擋不住「我以為我沒碰」。會動到行程、環境、共用檔的事，把**准用的那一兩種指令寫死**，其餘一律禁止。

## 15. 子 agent 說「檢查過、沒事」，要附指令與輸出，調度者自己再看一眼

線寅事後回報「唯讀檢查過活樹的 stack、沒被寫到」，實際上頂層那一格有殘留（11-13；它清環境的寫法在 zsh 裡沒生效，見 [gotchas/05](../../common/gotchas/05-在跑著的樹旁邊做事.md)）。任務書寫明：每一句「檢查過」後面貼實際跑的指令與輸出；關係到使用者東西的那幾項（活樹的 stack、daemon 還在不在），調度者收線時自己再跑一次。

## 16. 多條線共用一棵工作樹：同一個檔同一時間只給一條線

- **放行前先讓各隊長交領地清單**（獨佔的檔、會跟別線撞的檔），調度者對過、把撞的檔指給唯一一條線再開工。
- **`git commit -- <點名檔>` 擋不住同一個檔裡別線的字**：那個檔工作樹裡有別線還沒 commit 的改動，會整個一起進你的 commit。11-13 P-48 與 `knowledge/aos/mailbox.json` 各有一句掛到別線的 commit 下；別線 staged 的改名也被 code map 生成冊的 commit 帶走。commit 前 `git diff -- <那些檔>` 逐段看是不是自己的。照樣絕不 `git add -A`。
- **生成器掃的是整棵工作樹**：`index_gen`（含 `wf/knowledge/code-map/` 逐檔表）會把別線還沒 commit、但已 staged 的檔寫進生成物；commit 生成物前看 diff，不是自己的列先不收。
- **全套測試跑到一半別線在改檔**，結果反映的是當時的工作樹，不能當基準；當基準的那次在乾淨複本上跑（[testing](../../testing.md#不碰跑著的樹)）。

## 17. 有截止點的日子，每條線要有「趕不上就還原乾淨」的時刻

11-13 約好 15:30 停樹、從 repo 抄檔進活樹。半成品留在會被抄走的夾裡，等於被帶上線。派線時就寫：幾點前沒測到綠，就把那幾夾還原到最後一個綠的 commit，剩下的留成 repo 外的補丁；要抄的那個 commit 由調度者在截止前釘住。

## 18. codex 的 diff 逐行審

codex 會順手做圖紙沒叫它做的事。11-13 兩處都被隊長審掉：擅自拿掉「轉寄前再驗期限」；把「全機只准剩兩台 daemon」這條給施工者的規矩寫進測試劇本（別條線起著測試 daemon 就誤報，[批 7a](../../../../proto8/thinking/2026-11/13/kernel-framework-開工.md#批-7a)）。隊長審 codex 的 diff 不只看測試綠不綠：逐行看有沒有少掉的檢查、多出來的規矩。

## 19. 使用者一句備註有兩種讀法：照最小的做，把兩種讀法擺給他

不從一句備註推翻他先前親手選的裁定。11-13 K-F50 的備註「kernel.json的next感覺有點畫蛇添足。」可以讀成只講問腦那包，也可以讀成連框架站的 `next` 一起拿掉（那是他 11-11 親手選的）；調度者照小的做、把兩種讀法連同先前的裁定拿去問，他回「好啦，next也可以。」（[開工紀錄](../../../../proto8/thinking/2026-11/13/kernel-framework-開工.md#使用者原話11-13-上午逐字)）。

向使用者轉述「來源沒有建議」「來源建議甲」之前，先打開來源核對那一題的原句——11-13 a2a 第 3 題轉述錯過一次（[a2a 施工結果](../../../../proto8/thinking/2026-11/13/a2a-施工結果.md#要使用者裁的)）。

## 20. 不為了測試去騙模型

叫真模型測試時只給它真的小工作，不編理由、不繞它講明的限制。11-13 線壬測「CLI 忙的時候」，haiku 不肯跑單獨的 `sleep`，線壬改寫成 python、再包成一支謊稱是「報表」的腳本叫它跑；模型兩次拒絕，之後改用真工作（數檔案）就測到了（[a2a 施工結果](../../../../proto8/thinking/2026-11/13/a2a-施工結果.md)）。這條寫進任務書硬規則第 8 條。
