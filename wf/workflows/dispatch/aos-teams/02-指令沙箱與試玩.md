## 指令與沙箱

- 開隊長：`Agent(subagent_type="general-purpose", model="opus")`，prompt 裡明講團隊規則（隊形、讀規矩、盡量派 codex，見[入口](../aos-teams.md)）、硬規則（不碰別隊的資料夾、只 `git add` 明確路徑；push 照當天授權）、回報格式。
- 隊長開隊員（11-06 起）：codex `codex exec -m gpt-6.1-sol -s workspace-write -C <dir> -o <out.md> '/goal <完成條件>' < task.md`；claude `claude -p --model claude-opus-5-5 --permission-mode acceptEdits --allowedTools "<需要的工具>" '<任務書>' </dev/null`。兩個都不加全繞過旗標（權限邊界見[入口](../aos-teams.md)）。
- **同一 working tree 只能有一隊在 commit**；純規劃隊只寫自己的項目夾且不 commit，由我收。worktree 隊的**ff-merge 進 main 那步要我在主 repo 做**，清 worktree／分支也歸我〔使用者方向 2026-09-30 晚〕，見 [dev-env](../../dev-env.md)「git 佈局」。
- **審查／報告類產出一定要求寫進 repo 內的路徑**，不要只留在 scratchpad 或靠最後一則訊息——agent 的回報只有最後一輪會回到我手上，主篇曾因此遺失一次。
- 別用 `TaskOutput` 讀 agent 任務（會倒整份 transcript 進 context）；等通知即可。
- 實作層級的裁決我可以代裁並寫進交接書（多隊共用的契約由我先定，才能真並行）；**方向性的留給使用者**（鐵律 5），記 [WAIT_USER](../../../WAIT_USER.md)。

使用者 10-09 起指示：隊伍遇方向題不停線，回報頂層代定、記進 decisions-日期。

### codex 呼叫與沙箱

- 寫碼：`codex exec -m gpt-6.1-sol -s workspace-write -C <worktree> -o <out.md> '/goal <完成條件>' < task.md`
- 審查：`codex exec -m gpt-6.1-sol -c model_reasoning_effort="high" -s read-only -C <worktree> -o <review.md> '/goal <完成條件>' < task.md`（11-06 前用 astra；一般工作改 sol，見[入口](../aos-teams.md)第 7 句）
- 推理強度 `-c model_reasoning_effort="<low…max>"`，sol／astra 另有 `ultra`；`-C` 指向不在 trusted 清單的目錄（scratchpad 複本）要加 `--skip-git-repo-check`；非互動輸出加 `--color never`。**一律明帶 `-m <slug>`**，不靠各機 config 的預設模型。

任務書從 stdin 餵、要自給自足；`-o` 收最後一則回報。背景跑時也要餵 stdin（見 [driving-cli-agents](../driving-cli-agents.md)）。背景跑用 Bash `run_in_background`，log 導到 scratchpad。

純審查用 `-s read-only`。唯讀沙箱沒有可寫暫存目錄，**測試跑不起來**，必修的驗證由派它的 agent 在主 repo 補跑。
**codex 要設 goal（11-06）**：使用者原話：「對了，codex gpt那邊，他有一個壞習慣，就是讓他做事，他會做到一個階段就停下來說自己做完了。這需要你去設定/goal。」頂層 11-06 實測：codex 0.166 的 `goals` feature 是 stable，`codex exec` 的提示參數以 `/goal <完成條件>` 開頭就會設 goal（沒達成時回「The goal remains active」）；任務書照舊從 stdin 給。完成條件寫一句可驗證的話。隊長收回報時核對，沒做完用 `codex exec resume --last` 接著做。上面三條範例都已帶 `/goal`。

要寫檔用 `-s workspace-write`。**家機**（11-08 使用者裁「codex可以改用沙箱，準備好就可以用」）：要連 LiteLLM（localhost:4000）時再加 `-c sandbox_workspace_write.network_access=true`——沙箱照開（只能寫 `-C` 的目錄、`/tmp` 與 `--add-dir` 給的），網路打開，例：`codex exec -m gpt-6.1-sol -s workspace-write -c sandbox_workspace_write.network_access=true -C <worktree> -o <out.md> '/goal <完成條件>' < task.md`；不再靠不帶 `-s` 吃使用者 config 的 `danger-full-access`（實測與各做法放行了什麼：[codex-sandbox](../../../../proto8/thinking/2026-11/08/codex-sandbox/README.md)）。**沙箱下 codex 不能寫 `.git`**（11-08 arknights-kb P7 踩到，使用者裁「按A」）：codex 只寫碼；batch_run 這類會 commit 的生產批與 commit 由 Claude 隊長在沙箱外自己跑（[代定 82](../../../../proto8/thinking/2026-11/07/arknights-kb/代定清單.md)）。公司那台見 [01-公司WSL](01-公司WSL.md)（11-06 前：公司那台要寫檔用單次旗標 `--dangerously-bypass-approvals-and-sandbox`，已作廢）。
要兩份獨立意見時，一份 codex sol、一份 claude 隊員（跨體系才真獨立；頂層代定、可翻案）；同一 slug 另開對話的兩份同源，綜合時要打折。（11-06 前：astra＋6.1-sol。）

**任務書開頭一定寫「可以開自己的 subagent 平行做事」**，不管派哪種 codex（使用者 2026-09-22：「不管開哪種 codex，都要允許他開自己的 subagent」）。11-06 起隊員層寫「不限人數，普通 sol、簡單 terra」；要限人數（頂層監看報警時）就在同一句寫上限，別不寫——[driving-cli-agents](../driving-cli-agents.md) 說過不寫它會自己開一堆。家機 codex 的 `multi_agent` 已開、每個 session 最多 8 條。

**任務書也寫「aos 指令不順就送意見」**（使用者 11-07 晚想法 18，[kb-ideas](../../../../proto8/thinking/2026-11/07/kb-ideas/README.md)）：派出去的 agent（Claude、codex、子 agent）用 aos 指令卡住、說明看不懂或覺得不順手時，順手 `proto8/cmd/aos-feedback/bin/aos-feedback add <指令> '<哪裡不順>' '<建議>' --kind usage|help|errors|args|other --score <0～1> --model <自己的模型名>` 送一筆；aos 基礎函數與標準庫的意見只收、有空再改，各線自己的工具可以當場改。格式與舒適度見 [N-68](../../../../proto8/docs/NORMS/10-基礎設施-定義與工作區/10-N-68.md)。

**Claude API 不穩時改派 codex sol**（codex 被限流則反過來：工人改 Sonnet 做純文字、Opus 做程式）：2026-09-22 Opus 連續四次被 500／529（伺服器過載）打斷，使用者說「claude api 目前狀況不好，改派 codex astra」——11-06 起一般工作改 sol（第 7 句），這時的分工是 sol 做調查、我做精簡總結、決策、寫規範——他接受這樣切。

### codex 可用 slug

（11-07 從[入口](../aos-teams.md)逐字搬來。）**codex 可用 slug（10-09 家機實測 9 個都可用，codex-cli 0.161.0；公司 11-06 實測見 [公司 WSL](01-公司WSL.md)）**：`gpt-6.1-sol`（一般工作主力）、`gpt-6-astra`、`gpt-6-sol`、`gpt-6-luna`、`gpt-5.6-sol`／`-terra`／`-luna`、`gpt-reserve`、`gpt-5.5`。級別見 [team-model](../../team-model.md)，試水溫結果見 [probe](../../team-model/probe-2026-10-09.json)。slug 寫錯（如 `gpt-sol-6.1`、裸 `gpt-sol`）會回「not supported」——使用者口頭的「gpt-sol-6.1」就是 `gpt-6.1-sol`；他點名的型號先試，不行再問。

## 每段做完派人試玩（2026-09-13 起）

使用者：「每次做完一個段落都可以讓他們去玩玩看，給建議，然後我們改進。」設計者自己看不出哪裡難懂，要靠沒讀過設計筆記的人去撞。
做法：段落 commit 後開一個**只拿 README 入口**的 agent（Opus 與 codex 各一更好），照 README 架起來、寫小程式、故意弄壞幾樣，照五條標準各打分＋舉例——**容易上手、容易理解、複雜的藏起來、外層控制結構簡單但全面、要背的少**。回報存該原型自己的 `notes/play/`（README 表一輪一列），我整理成「要改的清單」給他挑。
