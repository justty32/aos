## 使用者原話

「我們在持續推進的同時，都是你跟我匯報進度。我覺得不如你開個agent，各線把進度都交給他，然後這個agent負責將進度丟到桌面html，實時更新(有需要的話可以用npm run dev這類技術棧)。你這邊仍負責接收我的指令和作爲頂層指揮。這樣可以避免污染你的context」

「那個agent也會把進度匯總並做總結，但不匯報給你。你這邊就是有需要的時候再去看那個agent的進度匯總就好」

## 各線什麼時候回報

各線隊長在**開線、每做完一批或一個地點、代定、卡住、交棒**時，各呼叫一次（codex 隊員也可以叫）：

```
wf/tools/progress_post.sh <線名> <start|progress|done|blocked|decision|handoff|ask> '<白話一句>' [連結或路徑...]
```

- 線名用 `arknights-kb`、`impl-plan` 這類短英文；新線名直接用，看板會自己長出卡片。白話那句用繁體中文、只講結論。
- 帶 `--round '第三輪'`／`--round '批 6'` 標明是哪一輪或哪一批，看板的「輪次」頁（照 aos-arknights 網站的版型）就照這個分；沒帶時從白話裡猜，猜錯會多出零碎的輪。
- `decision`＝代定（替使用者先做的決定），`blocked`＝卡住；同一條線之後再送別的狀態就算解除。
- **要使用者決定的事用 `ask` 放上看板的「待你裁」區**，然後照代定（推薦選項）往下走、不停線；使用者答了再照答案修正。題目可帶選項：`--option 'A：做法與後果' --option 'B：…' --recommend A`。讀回答：`wf/tools/progress_answers.sh [--since <時間>] [--line <線名>]`（`--open` 列還沒答的）。
  **一批 3 題以上、或要附背景原話才裁得了的**，改走 [decide-page](../../decide-page.md)：做成桌面互動頁，看板只放一題「這批在等你」，回覆可貼回對話或看板意見框。
  使用者原話（11-07 傍晚）：「等一下七點我要出門運動，八點回來。這段期間不可以問我問題。除此之外，有需要我決策或給意見的話，可以在那個npm run dev的網頁放東西，我有空會看。」
- **回報頂層只寫一兩句**，細節交給看板；頂層要看全貌時讀看板的匯總 `~/Desktop/aos-進度/summary/latest.md`。

## 看板與匯總者

- 頁面：`~/Desktop/aos-進度/`（開伺服器 http://127.0.0.1:8765/ 即時更新；不開伺服器直接開 `index.html` 看最後快照）。程式與設定在 [`wf/tools/progress_board/`](../../../tools/progress_board/README.md)，怎麼開關、加線看那份 README。
- 腳本定時收：兩個 repo 的 commit、各線交棒檔的更新時間、codex 程序數、負載與記憶體——不靠 LLM。
- 匯總者：有新進度且距上次超過最短間隔（預設 15 分鐘）才經 LiteLLM 叫 gpt 系寫一份白話總結，舊的留歷史；每次花的 token 與秒數記在 `summary/cost.jsonl`。它**不寄信、不 SendMessage**，只寫檔。
