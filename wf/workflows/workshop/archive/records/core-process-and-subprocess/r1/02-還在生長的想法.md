## 還在生長的想法

- 核心描述檔的名字：`kernel.json`（多數）vs `system.json`。
- **`.aos/procs/<id>`**：子行程各有 turn／status，結果投遞回主行程。
- **World 抽象帶 root fd、版本、能力**：回答規格第十二節「世界本身沒有抽象」；root fd 不像
  `chdir` 是行程共用的，更能支援多核。
- **外部處理器完成後**：ack、寫 receipt，還是投遞給另一顆 CPU（變成 pipeline 的一節）？
- **turn ID 與最小事件紀錄**：最痛的是副作用已發生但結果未落盤；值不值得那個複雜度不確定。

## 大家問出來的問題

1. **核心序言／尾聲失敗時，業務批次還跑不跑？** 尾聲失敗算不算「本回合未完成」（要不要留 `.runi`）？
2. 多核衝突誰裁決？兩核同改一個檔時誰定因果？
3. 子行程能不能直接寫世界？（funcs 隔離還是共用）
4. 子行程失敗後，主行程停住、隔離、重試，還是照常提交下一回合？誰有最終決定權？
5. 誰升級 kernel？核心序尾能不能被世界自己修改？（能的話，「恆常」又可被破壞）
6. 各核的寫入範圍由誰驗證？
7. 外部處理器完成後是 ack、寫 receipt，還是投遞另一顆 CPU？

## 明顯的坑

- **尾指令自我複製**：crash 遺失、重跑增殖、手改破壞。
- **`.runi` 給人「多核已經安全」的錯覺**：它只隔離取件，不隔離資料競爭。
- **`chdir` 擋住多核**：cwd 是行程共用的，一支 `aos exec` 只能推進一個世界（規格第十二節已記）。
  要多核就換 root fd，或一個世界一支行程。
- **`rename` 只保證可見性原子，不保證斷電耐久**。要不要承諾耐久未定，它會大幅改變協定重量。
- **funcs 走獨立 queue 可能協定過重**；不走就沒有隔離、重啟與公平性。一旦 func 需要暫停、重試
  與公平性，它就會從 job 長成 lane。
- **「不用 lib 也接得上」沒有 golden files 與 conformance 檢查就只是宣稱。**
