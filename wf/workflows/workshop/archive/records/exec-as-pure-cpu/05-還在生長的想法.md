### 還在生長的想法

- **規格得指定哪一份是正本**（架構師）。兩個入口＝兩份公開契約（函式／argv）且必須永遠同義；規格明寫 **argv 只是函式語意的投影，分歧時函式贏**，否則十年後有人靠上 argv 的副作用。
- **argv 入口只能是薄殼，錯誤路徑的測試留在函式那層**（資深工程師）。直接叫函式測又快又確定；用 CLI 測要造檔案系統狀態＋等子行程，慢且會 flake。
- **機制那幾筆不出現在人打開的 `inst.json` 裡**（資深工程師）。放進 `boot.json`，argv 寫在 `aos init --repair` 能重寫的檔裡，就不會變成改不掉的資料夾格式。
- **`.aos/version` 第一次有事做**（資深工程師）。boot.json／角色表一存在就有「舊版寫、新版讀」；過舊時不要 best-effort，印 `hint: aos init --repair .`。
- **退出碼碼表要共用，「無事可做」從 0 拆出來**（資深工程師）。aggregate 回 0 分不出「收了 5 份」和「inbox 是空的」，而 `--loop` 要靠這個決定睡不睡。與規格第八節衝突，要改規格。
- **`.aos` 長出執行紀錄區**（架構師）。跨 process 後只剩退出碼＋stderr，所以 `.aos/log/<verb>.err` 與黑客松要的 receipt 收斂成同一件事：機制的輸出寫進 `.aos`、不寫 stderr。仍不可攜，規格第十節「`.aos` 全部不進 git」不必改。
- **機制的參數會變成使用者資料**（架構師）。`<folder>` 本體會被 commit，寫著 `["aos","aggregate",...]` 的腳本會流進別人的 repo；那串字的相容壓力比 C ABI 大——函式庫有 soname 能並存，argv 沒有。
- **該問的是 driver 能不能被換掉**（架構師）。`aos exec` 若只剩「讀角色表 → 依序 execve aggregate、claim、跑批次、release」，它就是兩百行內讀得完的 core，其餘三支是政策：core 的定義從「哪些程式」改成「哪一份順序」。提出者承認這條畫不到原話「其他啥都不做」的位置。
- **aos 沒有持得住鎖的主體**（OS 研究者）。機制外放還活下來的系統都有常駐者握把柄：make jobserver 靠繼承的 pipe fd、init 靠 pid 1、systemd 靠 cgroup。aos 刻意沒有常駐 process，只持得住檔名；所以要嘛讓檔案系統自己維持不變式（`link()`＋`unlink()` 或 `renameat2(RENAME_NOREPLACE)`），要嘛別把鎖交出去。
- **`aos --list-core`**（OS 研究者，對照 `busybox --list`）：印這個 build 含哪些 applet，啟動時就查得出「彙整懂 v2、執行懂 v1」。
- **`aos exec --dry-run .` 與 `--explain .`**（開發者）：前者印這回合會跑哪幾筆（含機制）但不執行；後者印實際走了哪條路、有沒有 fork，讓「閒置留在行程內」看得見。
- **`aos init --from ./aos-boot.json`**（開發者）：`.aos/` 不進 git，boot／角色設定沒法交給隊友。
- **conformance 是 argv 契約的可執行版本**（架構師）：比文件硬；libOS 會變成事實上的核心，是因為沒人定義過「合格的替代品」。

### 大家問出來的問題

- boot 批次失敗回哪個碼、`--loop` 停不停？（資深工程師主張停，跟碼 3 同級）
- deliver 補上後，既有直接寫 `<pid>.json` 的腳本怎麼被發現？沒檢查就是靜默資料損毀。
- 角色表本身改壞了怎麼被發現？它不在批次裡，只能由 `aos exec` 驗；開機檢查與 `.aos/version` 誰先？
- 若 core ＝ 回合的順序，`aos exec` 還算不算「其他啥都不做」？讀表、決定順序本身就是在做事。
- 第一批 instruction 是誰放進去的？架構師的答案是 `aos deliver`——bootstrap 走投遞、不走特權入口，但要求 deliver 先落地。
- 這套協定的讀者到底是誰？若永遠只有 `aos` 自己呼叫，conformance 與凍結 ABI 都是替假想使用者付錢。
- `.runi` 鎖的是「那一批」還是「那個世界」？四份發言都預設了答案、沒一份講明；前者拆得開，後者拆不開。
- `.aos/` 不進 git，`kernel.json` 與 `boot.json` 怎麼跟著專案走？
- `aos world status` 撞到 `.runi` 該回 0 還是非零？
