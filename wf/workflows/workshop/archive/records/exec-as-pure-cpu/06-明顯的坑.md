### 明顯的坑

- **特權位置會變成靜默的無限迴圈**：boot 批次改壞時每回合失敗一次、退出碼仍 0（見 [04](04-第-2-輪.md)）。
- **把 header 包進 `.runi` 會毀掉「`cat` 一下就知道是哪批」**：receipt 要放旁邊。
- **git 走過這條路又走回來**：`git-commit.sh` 曾真的 fork `git-update-index`，後來收回成 C builtin。理由一半是 Windows fork 太貴（aos Linux-only，不成立），另一半是錯誤穿不過退出碼——這半成立。
- **退出碼裝不下狀態，前人兩條路都有代價**：systemd 改用 `$SERVICE_RESULT` 傳給 `ExecStopPost=`；fsck 壓成位元遮罩，代價是每套 init script 都有一段 `case $? in`。
- **介面開放不等於有人來寫**：Plan 9 任何語言都能寫服務，實際上幾乎全是 C、同一群人寫。
- **沒有測試套件的規格會分岔**：Maildir 只有一篇文章，Courier 與 Dovecot 解讀分歧至今。aos 是單人專案，分歧成本近乎零——除非真的要讓外人寫 CPU。
- **receipt 只能幫人判斷，不能自動 resume**：boot id 在容器與 WSL 裡共用宿主的值，pid 會重用。recover 可能養出「照著 resume」的習慣，繞過「現場留給人」。
- **exokernel／libOS 對照過重**：真正的限制不是 libOS 分裂，是單人專案養不起兩個實作。
- **成本數字仍沒人量**：全場唯一沒有證據的共同前提。
