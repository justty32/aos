## 第 2 輪

### 成形的方向

**四比零：deliver 外放、claim／release 留內，無人主張整包外放。** 全場最強的訊號。

**`.runi` 升級成一份租約**（資深工程師、架構師、OS 研究者，理由分別是診斷／身分／原子性）。記 pid、boot id、時間、筆數，一次解三件事：三種現場分得出來；release 驗身分才刪，擋掉「放錯位置的 release 在回合還在跑時開鎖、讓第二支 `aos exec` 進來」（今天結構上不可能）；recover 就是把它印給人看。**receipt 放旁邊、不包進 `.runi`**：`.runi` 的內容就是那批 JSON，`cat` 一下就知道卡哪批，包 header 會毀掉這點；所以寫成 `inst.json.runi.receipt`，**先寫 receipt、後 rename `.runi`**（孤兒 receipt 無害，反過來不成立）。

**開發者不否決 claim／release 留內，他要的是可見性、不是呼叫權**：另給唯讀的 `aos world status <folder>`，印 `.runi` 在不在、幾筆待彙整、幾個 `.bad`、上一回合何時結束。

**`--loop` 的停止條件搬回檔案系統**（架構師）。3 不是某支程式的碼，是世界的狀況；`--loop` 每回合開頭自己 `stat` 一次 `.runi`，不讀子程序退出碼。檔案系統狀態本來就是這個模型的唯一真源；claim 哪天外放，停止條件仍留在 `aos exec`。

**零工作的回合必須是零 fork**：回合開頭 stat `inst.json` 與 `inst.tempd`，兩邊都空就 return，有工作才 exec。

**bootstrap 的特權檔**，四種形狀：

- OS 研究者：FreeBSD 雙層——開機批次編進執行檔當內建預設，`.aos/boot.json` 只在存在時覆蓋；刪光照樣能開（單層 inittab 改壞就起不來）。
- 架構師：它該是**角色表**、不是指令表。一批 instruction 串在最前面仍跑在 claim 之後，彙整還是沒自舉；角色表（誰扮演 aggregate、誰扮演 deliver）由 `aos exec` 開頭讀、直接 execve、不經 `inst.json`，悖論才解掉。這張表就是 `kernel.json` 間接層，兩者合併。被凍結的東西從「`aos aggregate` 這個字串」換成一個隨 `.aos/version` 版本化的檔——字串收不回來，版本化的檔收得回來。
- 開發者：instruction 不寫程式名，`kernel.json` 寫 `"aggregate": "@self"`；不動照樣跑，要換打 `aos world kernel set aggregate ./my-aggregate.py`。
- 資深工程師：失敗語意。改壞 boot 批次是每回合失敗一次、退出碼仍 0（第八節：子行程非零不影響回合碼）；所以 boot 批次任一筆非零就中止本回合、不跑 payload、回專屬碼並停 `--loop`，否則特權位置會變成靜默無限迴圈。

**recover 得進規格**（架構師）。`aos world recover` 做的是規格沒定義的狀態轉移（把 `.runi` 搬回 `inst.json`），要在規格第六節明文成為第四步（連同棄置），否則它在規格外偷改世界。

**先做 deliver，其餘等 receipt 格式定下來**（開發者）。T5 agent loop 腳本是第一個外部使用者，現在得自己 `mktemp`＋`rename`，有 `aos deliver` 就縮成一行。
