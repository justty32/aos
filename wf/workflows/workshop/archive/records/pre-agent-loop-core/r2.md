# R2 結論（交鋒輪，補進原提案辯護人）

← [agent loop 之前要做哪些 core 小專案？](README.md)

## 結論

1. **唯一該在 T5 之前做的是投遞 API，它是 `core/inst` 的擴充，不是新小專案。** handoff 加一支
   `deliver(base, bytes)`（同目錄唯一暫檔 → `rename`），CLI 是 `aos enqueue <folder> [file|-]`，
   給腳本與其他語言的生產者用；**只保證「完整且可見」**，驗證與隔離留在彙整那一步；C ABI 等實證再說。
2. **`k/`（續體）與 `c/`（熱快取）是兩層，分開命名。** `{at, then}`、函數游標是續體，不可丟；
   **解析後的 forms／context 是可丟、可重建的熱快取**。`c/` 只放帶內容雜湊的可重建物，量到成本才定。
   使用者的 register／L1 直覺對應的是第二層；**持久狀態不可以叫 cache**。
3. **`wait`／`func` 是同一個「續體推進一步」機制的薄前端。** 版面：`k/w.json:{at,then}`、
   `k/f.json:{src,i}`，共用一筆 `k-step` 指令；`wait` 未到期就重投自己，`func` 投 `[form[i], step]`。
4. **`core/eval` 不在 T5 之前做。** 門檻：**出現第二種續體格式／第二個互讀者才抽 eval**。形狀備查：
   `["aos","eval",".aos/k/<id>.json"]`，讀一個 form、reduce 一步、投遞零到多筆 inst，未完狀態落盤。
   **eval 管 form 與續體的生命週期，inst 管 POSIX 批次的驗證、執行、彙整**——eval 延後這條線也成立。

## 停損線與升格門檻

- T5 原型必須跑完「模型→工具→模型」＋回合之間人可以介入＋`Ctrl-C` 後續跑。
- 出現第二個生產者要重寫 `temp→rename` → 補投遞 API；出現兩個實作者必須互讀彼此的續體 → 立續體契約／eval。
  沒命中就不升格。
- 續體格式只容許一個私有原型：沒有第二個讀者時統一格式就是在猜，現在進 core 會把第一版的偶然形狀永久化。
