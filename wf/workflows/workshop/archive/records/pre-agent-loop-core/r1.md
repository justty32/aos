# R1 結論

← [agent loop 之前要做哪些 core 小專案？](README.md)

使用者四個構想的判讀（R2、R3 之後仍成立的部分；總結見 [conclusion.md](conclusion.md)）：

1. **「cache／暫存器」的持久部分是 continuation（續體），不是 cache。** 它是「這件事做到哪了」的
   持久狀態，丟了就等於工作消失，所以不叫 cache。可丟、可重建的熱快取是另一層（見 [r2.md](r2.md)）。
2. **`wait` 與 `func` 是同一個原語的兩種狀態**：`wait` 是時間續體（條件是「到了某個時刻」），
   `func` 是序列續體（條件是「還有下一條 form」）。「func 每輪投遞兩筆」與「wait 每輪重投自己」是同一個機制。
3. **「取下一條指令」不需要新機制。** 現有投遞協定（`.aos/inst.tempd/`，見 `docs/aos-folder.md`）
   就是續體的傳遞方式；候選 (a) 最後放一筆取件指令、(b) 通用 lib 都是既有機制的用法。
4. **夠格當 T5 前置的只有原子投遞 API**——roadmap T2 已知的缺口（「投遞那一步只有協定沒有 API」）。
5. **命名**：續體區叫 `.aos/k/`（`k` 是 continuation 的慣用符號）。

## 坑與補充

- **`$ref`／`$env`／`$opt` 是晚綁定，不是 quote／unquote。** 已有的指示詞機制不能直接當 lisp 的
  quote；要 quote 得另立機制（例如 `["emit", ["quote", inst]]`）。
- **`wait` 每回合重投自己等於輪詢**：`--loop` 底下可接受，但「回合」同時承擔了計時器的角色。
- **回合中途死掉的洞**：工具已造成副作用、但續投遞之前 process 死了；重跑重複副作用，不跑就停機。
  裁決是**明確不做**（見 [r3.md](r3.md)）。
