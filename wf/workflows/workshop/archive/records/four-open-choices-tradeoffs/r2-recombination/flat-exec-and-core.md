張力：使用者先前已拍板「多核學 Linux，有一個核心最高 root 行程，由單一
`aos exec` 掌握至高權力」，這輪又說「`aos exec` 不知道啥是子行程」。兩句都保留的話，root 的

日後再用 OS 權限強制。

## 成形的方向
## `aos exec` 是扁平 CPU；知道樹的是 `aos core`

`aos exec` 永遠只知道「對這個 folder 走一步」，不讀 parent、不辨認自己是不是子行程；`aos core`
知道行程樹，擁有建立、排程、join、收割與 commit 的管理權。

| 層次 | 它知道什麼 | 它做什麼 |
|---|---|---|
| **`aos exec`** | 一個世界的 folder、自己的 kernel、queue 與本回合 `.runi` | 彙整、claim、執行一步、release；內層 `aos exec <child>` 對它只是普通指令 |
| **`aos core`** | 哪些世界是行程、它們的位置、ready／join／generation 狀態 | 建立與收割、選下一個世界、授予執行額度、收 receipt、承認 commit |
| **子世界** | 只知道自己的資料夾，不保存「我上面有父行程」 | 用自己的 kernel 與 queue 獨立走一回合 |

**「至高權力」不是 `exec` 認得的特殊身分，而是誰有權改管理資料（proc 表、queue、commit）與承認結果。**

**集中管理不等於集中在同一個 OS 行程裡執行**：core 保有唯一管理權，同時把每個子世界交給普通的
`aos exec <path>`；B 式的集中權力不必逼出 B 式的集中 lane。
