# 哪幾題其實是同一個決定

四題不是四個可任意排列的開關；下面幾組互相鎖住。

## B 集中 lane 與 `World` 幾乎是同一個實作決定

B 要在單一 root 行程內輪流推進多個世界，每次 I/O 都得明確指向哪個世界，這就要 `World`。選 B 不收
`World`，只能用「一 lane 一 OS 行程」或反覆切 cwd 補洞。

## C 與「路徑還是 UUID」不能一前一後地拖延

C 要先固定磁碟 ABI，而 identity 本身就是 ABI：receipt、capability、owner 與 `$ref` 指的是位置還是
身分不定，就沒有 A／B 共用的格式。C 可以暫緩第三題的「誰去推」，**不能暫緩第四題**。

## 分層 kernel 與親緣的表達方式是同一個政策來源決定

分層 kernel 的「父」是實體目錄祖先、`parent_id` 指的邏輯父，還是 proc-table 的 owner，取決於第四題。
用實體祖先找 kernel，搬家可能換政策；用 UUID 親緣找，registry 就要參與每回合的政策解析。

## A 與分層 kernel 會把升級成本沿樹深放大

A 讓每層都是完整世界，分層又讓每層的有效政策依賴祖先：升級要確認每一層當時繼承到哪一版，事故時
要保留整條來源鏈。兩者可以同選，但同選後「有效快照」與版本相容是必備功能，不是附加功能。

## 能力的綁定方式把 `World`、身分與搬移三題串在一起

能力綁 root fd／inode，要定重啟與搬移後怎麼續；綁 path，要定 rename 後怎麼續；綁 UUID，要定誰把
UUID 解析成目前位置並防止逃出 root。能力只是排程資料時問題較輕；是安全邊界時，第一題與第四題要
一起形成可驗證的契約。

## 最難反悔的不是 A 或 B，而是落盤的身分、政策現場與恢復契約

scheduler 是實作，共同 ABI 正確就能換。會迫使所有既有資料夾遷移的是：磁碟裡怎麼表示
identity／parent／location、哪一版 kernel 形成本回合、未完成的 claim／receipt 怎麼恢復。
