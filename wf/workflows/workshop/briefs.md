# workshop — 議題書與參與者任務書

← [workshop README](README.md)｜**書記／祕書那兩棒的任務書在 [staff.md](staff.md)**

本檔＝**開場與每一輪要發給參與者的兩份東西**：議題書（主持人寫的第一塊）與參與者任務書
（每輪、每人一份）。身份怎麼挑、一場怎麼跑，見 [README](README.md)。

## 議題書（我寫給參與者的第一塊）

```markdown
## 主題
<一句話。可以是開放的，不必是能被回答的問句>

## 背景
<現況、為什麼現在談這個。給足夠的事實，但不要暗示答案>

## 使用者自己說的
<原話的意思，盡量保留，不要幫他整理掉細節>

## 想聽到什麼
<例如：越多具體做法越好／想知道哪裡會痛／想知道用起來像什麼>

## 範圍外
<明確不談什麼，避免發散到別的題目>

## 可讀資料
<repo 內相關路徑，指路用；參與者可自行延伸>
```

## 參與者任務書（每輪、每人一份）

任務書＝議題書 ＋ 下面這幾塊，寫成一個檔丟 stdin：

```markdown
## 你的身份
<身份名>：<這個身份在意什麼、他會從哪裡看這件事>

## 目前的想法池
<前幾輪收攏後的內容，標明哪個身份提的；R1 時寫「本輪為第一輪，無前情」>

## 本輪任務
<R1：各自發想；R2：延伸／組合／變體，禁止評判；R3：收攏成方向>

## 硬規則
- 唯讀：可以讀這個 repo 的任何檔，**不要改任何檔、不要跑 build / ctest**。
- 繁體中文，**700 字以內**。超過會被截。
- **這是發想，不是辯論**。不要否決別人的想法；不同意就提出你自己的版本。
- **想法要具體**。「應該更模組化」不算想法，「把 X 拆成 Y 和 Z，因為……」才算。
- 照下面格式輸出，不要加開場白與收尾客套。

## 輸出格式
**我是誰**：<一句話，你這個身份看這件事的角度>
**想法**：<3–6 條，每條一句話講清楚，越具體越好。彼此不必一致>
**我最想接著長的**：<想法池裡別人的哪一條，你想怎麼把它往前推。R1 寫「無，首輪」>
**我會問的問題**：<你這個身份自然會問、但目前沒有答案的>
**我沒把握的**：<標記你不確定的地方。不是自我批判，是標不確定性>
**一句話**：<能直接被抄進紀錄的一句>
```

「我沒把握的」是**標不確定**，不是辯論式的自陳弱點——研討會裡沒有人需要防守。
