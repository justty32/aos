## 失敗的世界不要只剩一把鎖

資深工程師不想只看到 `.runi` 卡住。他想讓 kernel 尾聲選配「飛行紀錄器」：每回合發布
`turns/000042.d`，放 claimed batch、kernel hash、exit 與 next deliveries；`aos explain <world>`
不替人推理，只把資料排成可讀的因果鏈。

要接工具的開發者把它叫作 **Crash museum**：把當時批次、kernel、已寫檔案與未發布投遞渲染
出來，失敗 world 可以整包附進 bug report。他同時指出這個模型最醜的地方：

> **「資料夾變了」缺少來源，五回合後沒人知道哪條 instruction 改壞哪個檔。**

資深架構師的 `aos fsck` 從信箱修復看同一件事；研究人員的世代 world 則想讓 crash 前的 current
仍保持完整。四個方向沒有收成一項功能：飛行紀錄器重因果、fsck 重修復、Crash museum 重展示、
世代 world 重回復。但它們都拒絕把 `.runi` 只當一把該刪掉的鎖。

## 如果真的有一千個 agent，四位先怕的不是同一件事

這一群沒有撞成單一答案，反而像四個不同儀表板：

- **資深工程師**想先看一百個鄰居世界的生態圖。它是展示品，也是把公平、容量與 queue 衝突
  肉眼化的方法。
- **資深架構師**認為 POSIX rename 會先失去可攜性；到物件儲存時，核心可能換成 conditional put。
  真正要保留的不是路徑，而是「未完成內容不可見、發布只有一次狀態跳變」。
- **資深研究人員**先加配額：每世界每回合最多多少 bytes、指令、外呼費用與衍生世界。沒有
  背壓，系統會先被磁碟與帳單擊穿。
- **要接工具的開發者**先加觀測：每次 rename 旁生唯讀 `turn-start`／`delivery`／`turn-end` 事件，
  讓 SQLite 或網站建立可重建索引；磁碟仍是真源。

有意思的是，沒有人在這一題先回答「更大的 process tree」。一位想看行為、一位換提交媒介、
一位控制資源、一位補來源；四種答案都把 agent 數量當成世界模型的壓力，而不是 scheduler 的數字。

## 幾條讓它們單獨站著的想法

### 法律與運動不要混在同一個「不進 git」裡

資深工程師那句「`.aos` 分成法律與運動」沒有別人直接接到。`kernel.json`、版本是法律；queue、
`.runi`、temp 是運動。這個分法同時碰版本控制、fork 與可攜性；若要實作，會直接影響 `.aos`
哪些檔可複製／可進 git，但本輪不轉交。

### 一回合也許只需要一份不可變 manifest

資深研究人員獨自提出：彙整不一定要反覆重寫一個含全部 instruction 的 `inst.json`，也可以發布
一份 manifest 指向本批不可變檔案。這會讓 instruction 本身更像郵件；也會改變現行「一回合＝
一整批」的落盤形狀，所以暫時讓它作為一條孤立的靈感。

### `rename` 是世界跨過門檻的那一刻

資深工程師的一句話既像電路，也像故事：

> **`rename` 不只是在提交檔案；它可以是世界從「可能」跨進「已發生」的那一刻。**

資深架構師說 clock edge，研究人員說提交脈衝，三人其實各自給了這句話另一種版本。

## 可能真的該做的

四位各自挑「最想看到它變成真的那一條」時，**四位獨立地都選了分支世界**。不是四票投給同一
組 CLI，而是四種理由落在同一個根：資料夾既然是世界，複製它就該能複製一個未來。

| 誰 | 他最想看到的 | 他為什麼挑這條 |
|---|---|---|
| **資深工程師** | `aos fork SOURCE DEST --at-boundary` | 它把「世界就在資料夾裡」從實作細節變成使用者摸得到的能力，也逼系統誠實分開可複製狀態與不可複製的在途工作 |
| **資深架構師** | 回合快照與分支：`aos branch world@42 experiment-b/` | LLM 不具決定性，保存真實世界再從某回合分叉，比假裝可 replay 更誠實地回答「換一個提示會怎樣」 |
| **資深研究人員** | speculative worlds：`aos speculate -n 8 world` | 不先造分散式 scheduler，只用 reflink、普通 `aos exec`、評分腳本與一次 pointer rename，就能讓多條未來可觀看、比較、保留 |
| **要接工具的開發者** | 世界競技場：`arena/{claude,gpt,local}/` → `winner` | 它不新增抽象，只把世界在檔案系統、回合有邊界兌現成廉價分支、比較與重播 |

四位的收尾句也落在同一個地方：

> **`aos` 最有趣的未來，也許不是管理更多行程，而是讓「複製世界、試跑未來、提交其中一條」
> 像檔案操作一樣普通。** ——資深研究人員

> **aos 最有趣的未來，也許不是更像 OS，而是讓工作休眠、分岔、交給人或模型，再把整個現場
> 帶走。** ——要接工具的開發者
