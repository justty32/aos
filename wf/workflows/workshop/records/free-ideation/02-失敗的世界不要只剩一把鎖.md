## 失敗的世界不要只剩一把鎖

`.runi` 不只是一把該刪掉的鎖。四個方向，沒有收成一項功能：

- **飛行紀錄器**（重因果）：kernel 尾聲選配，每回合發布 `turns/000042.d`，放 claimed batch、kernel hash、
  exit 與 next deliveries；`aos explain <world>` 不替人推理，只把資料排成可讀的因果鏈。
- **Crash museum**（重展示）：把當時批次、kernel、已寫檔案與未發布投遞渲染出來，失敗 world 整包附進 bug report。
- **`aos fsck`**（重修復）：從信箱修復看同一件事。
- **世代 world**（重回復）：crash 前的 current 保持完整。

這個模型最醜的地方：

> **「資料夾變了」缺少來源，五回合後沒人知道哪條 instruction 改壞哪個檔。**

## 如果真的有一千個 agent，四位先怕的不是同一件事

agent 數量是世界模型的壓力，不是 scheduler 的數字；沒有人先答「更大的 process tree」：

- **看行為**：一百個鄰居世界的生態圖，把公平、容量與 queue 衝突肉眼化。
- **換提交媒介**：POSIX rename 會先失去可攜性，到物件儲存時核心可能換成 conditional put。要保留的是
  「未完成內容不可見、發布只有一次狀態跳變」，不是路徑。
- **控制資源**：每世界每回合最多多少 bytes、指令、外呼費用與衍生世界。沒有背壓，系統先被磁碟與帳單擊穿。
- **補來源**：每次 rename 旁生唯讀 `turn-start`／`delivery`／`turn-end` 事件，讓 SQLite 或網站建立可重建索引；
  磁碟仍是真源。

## 幾條讓它們單獨站著的想法

- **法律與運動不要混在同一個「不進 git」裡**：`kernel.json`、版本是法律；queue、`.runi`、temp 是運動。
  會影響 `.aos` 哪些檔可複製／可進 git；本輪不轉交。
- **一回合也許只需要一份不可變 manifest**：發布一份指向本批不可變檔案的 manifest，不反覆重寫 `inst.json`。
  會改變「一回合＝一整批」的落盤形狀，暫為孤立靈感。
- **`rename` 是世界跨過門檻的那一刻**：
  > **`rename` 不只是在提交檔案；它可以是世界從「可能」跨進「已發生」的那一刻。**

## 可能真的該做的

**分支世界**（四位都選）：資料夾既然是世界，複製它就該能複製一個未來。

| 形式 | 為什麼值得 |
|---|---|
| `aos fork SOURCE DEST --at-boundary` | 把「世界就在資料夾裡」變成使用者摸得到的能力，逼系統分開可複製狀態與不可複製的在途工作 |
| 回合快照與分支：`aos branch world@42 experiment-b/` | LLM 不具決定性，保存真實世界再從某回合分叉，比假裝可 replay 更誠實地回答「換一個提示會怎樣」 |
| speculative worlds：`aos speculate -n 8 world` | 不先造分散式 scheduler，只用 reflink、普通 `aos exec`、評分腳本與一次 pointer rename，就讓多條未來可觀看、比較、保留 |
| 世界競技場：`arena/{claude,gpt,local}/` → `winner` | 不新增抽象，只把世界在檔案系統、回合有邊界兌現成廉價分支、比較與重播 |

> **`aos` 最有趣的未來，也許不是管理更多行程，而是讓「複製世界、試跑未來、提交其中一條」
> 像檔案操作一樣普通。** ——資深研究人員

> **aos 最有趣的未來，也許不是更像 OS，而是讓工作休眠、分岔、交給人或模型，再把整個現場
> 帶走。** ——要接工具的開發者
