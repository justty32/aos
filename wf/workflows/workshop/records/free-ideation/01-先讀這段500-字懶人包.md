## 先讀這段（500 字懶人包）

最強的方向：**世界可以複製、分岔，再挑一條未來成為現在**（`aos fork`、回合快照、speculative
worlds、世界競技場；四位各自想到，挑「最想成真」時也都選它）。

另一個共同畫面是 Maildir：instruction 像郵件，CPU 像郵差，`.bad` 是死信，`.runi` 是沒簽收完的
掛號信。**Human CPU**：人、LLM、儀器甚至印表機，都能用同一個信箱接工作。

其他：睡半年再醒來的可攜世界；能附進 bug report 的 Crash museum；一百個只准向鄰居投信的小世界；
千 agent 先撞上的不是 process tree，而是帳單、磁碟與「到底哪條 instruction 改壞了檔案」。

## `aos` 也許是郵局，不是作業系統

生產者先寫 tmp，完整後搬進 ready／new，消費者再 claim；instruction 是信，CPU 是郵差，壞檔是死信。

> `aos` 其實更像郵局，不像 CPU：`tempd` 是投遞口、`inst.json` 是郵袋、`.bad` 是死信、
> `.runi` 是尚未簽收完的掛號信。

- **跨機 bridge**：不共享 NFS，像 UUCP／Maildir 一樣先完整搬運信封，到目的端才 rename。
- **偷 Maildir 的傷疤**：唯一檔名、離線 client、信箱修復、垃圾清理；`aos fsck` 可能比 scheduler 更有價值。
- **每回合原子發布一份 manifest**，只列本批不可變的 instruction 檔，不重寫整份 `inst.json`。會改到現有
  彙整協定；只是靈感，不是規格提案。

另一個比喻是同步數位電路：

> folder 是暫存器，instruction 是組合邏輯，rename 是 clock edge，`.runi` 是「時脈只走了一半」
> 的證據。不同 CPU 可視為 clock domain，只能經 mailbox 跨域。

郵局說的是交接，電路說的是哪一刻從未完成跨成已發生。

## 把世界停住、複製，然後看兩個未來

### `aos fork`：分開法律與在途工作

`.aos` 拆成兩種：`kernel.json`、版本是可攜的「法律」；queue、`.runi`、temp 是本機正在發生的「運動」。
不拆的話，「整個 `.aos` 不進 git」與「kernel 要版本化」會互撞。`aos fork SOURCE DEST --at-boundary`
只准在回合邊界執行：有 `.runi` 就拒絕；複製世界與 kernel，清空在途狀態，再把不同 prompt 塞進各分支。

### 回合快照：replay 不可信，就保存真現場

reflink／filesystem snapshot：`aos branch world@42 experiment-b/`，兩個 agent 從同一現場走不同未來，
再用 `aos diff-turn` 比較。LLM 不具決定性，普通 replay 常是假象；保存當時的完整世界再分叉，才是在比較
「如果那時換一個提示」。

> **資料夾若真的是世界，最迷人的能力不是讓它跑得更快，而是把它停住、複製，然後觀看兩個
> 未來。**

### speculative worlds：把推測執行字面化

`aos speculate -n 8 world`：reflink 複製八個候選世界，不同模型／提示各跑一回合，評分器挑一個；其他
分支留下來 diff 或刪除。世界本身也可以是世代：`versions/42.tmp/` 完成後 rename 成 `42/`，再原子切換
`current`，原子的就是整個世界版本。

> **`cp` 是 fork 宇宙，`diff` 是解釋兩條時間線，`rename` 是承認其中一條成為現在。**

### 世界競技場：分支擺在桌上

`arena/{claude,gpt,local}/` 各走五回合，judge CPU 只看 diff 與測試，把勝者 rename 成 `winner`。或父世界
一次繁殖十個子資料夾，改不同 prompt／kernel，只把評分與產物投回父世界。生態缸版本：一百個小世界各養
一個 agent，只能向相鄰世界投信，每回合畫出族群、語言與合作關係，把 queue 衝突、容量與公平性變成看得見的現象。

**落地要定的**：什麼算回合邊界、哪些 `.aos` 狀態可以複製、`.runi` 存在時是否一律拒絕、勝者如何原子成為 current。

## 人也可以是一顆 CPU

`.aos/insts/human.json`：TUI、網頁或文字編輯器 claim 一個「批准部署／補背景／選 A 或 B」的問題，人填
答案，完整後 rename 回結果。**人不再是協定外的例外**；LLM、人工核准、實驗儀器與印表機都是慢速或異質
CPU，會收信、做事、回信就能接進來。它也是外部處理器契約的試紙：Human CPU 不引用 aos lib、只照磁碟
契約就接得上，「外部處理器的構造會很簡單」才成立。不必先改 core。

## 等待也是 CPU；休眠不是故障

**等待**是一顆外部 CPU：world 完全睡著，calendar watcher 到 09:00 才投遞 instruction，長期 workflow
不必為每個世界養 daemon。world 可以半年沒有 process，壓成 tar 寄走，解開後再走一回合；這種產品先痛的
是絕對路徑、秘密與外部 effect 能不能一起搬。

> **沒有活主控者仍有世界。**

LLM 是高延遲、非決定性的協處理器：真正的 CPU 仍是 `aos exec`；模型是偶爾從 mailbox 回一包候選
instruction 的裝置。mailbox、timeout、結果快取比把模型描述成常駐 agent 更貼近它。
