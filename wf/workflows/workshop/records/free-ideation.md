## 先讀這段（500 字懶人包）

四位互相看不到，卻全部撞上同一幅畫：**世界可以複製、分岔，再挑一條未來成為現在。**名字分別
叫 `aos fork`、回合快照、speculative worlds、世界競技場。

另一個 4／4 撞題是 Maildir：instruction 像郵件，CPU 像郵差，`.bad` 是死信，`.runi` 是沒簽收完
的掛號信。三位又各自想到 **Human CPU**——人、LLM、儀器甚至印表機，都能用同一個信箱接工作。

還有幾幅很難忘：睡半年再醒來的可攜世界；能附進 bug report 的 Crash museum；一百個只准向鄰居
投信的小世界；千 agent 先撞上的不是 process tree，而是帳單、磁碟與「到底哪條 instruction 改壞
了檔案」。

---

使用者只給了四個字：

> **這次是隨意發想。**

所以本輪沒有議題書、沒有等著拍板的答案。上一輪逐條拆自己的提案，這輪反過來允許不實用、
不可行、互相矛盾；任務書給的起跳點「不是清單，不要照著填」。下面保留的是四個人在沒有互看
發言時，各自撞出的畫面與句子。

## `aos` 也許是郵局，不是作業系統

**四位獨立地都借了 Maildir／郵局來看 aos。**這不是四種背景相近所以都說「像 queue」而已；
四位連對應物都幾乎對上了：生產者先寫 tmp，完整後搬進 ready／new，消費者再 claim；instruction
是信，CPU 是郵差，壞檔是死信。

資深工程師把整套比喻原樣寫成：

> `aos` 其實更像郵局，不像 CPU：`tempd` 是投遞口、`inst.json` 是郵袋、`.bad` 是死信、
> `.runi` 是尚未簽收完的掛號信。

他順著這個形狀想到跨機 bridge：不共享 NFS，而像 UUCP／Maildir 一樣先完整搬運信封，到目的端
才 rename。資深架構師則想直接偷 Maildir 的「傷疤」：唯一檔名、離線 client、信箱修復、垃圾
清理；甚至覺得未來的 `aos fsck` 可能比 scheduler 更有價值。要接工具的開發者也用了同一句：

> **instruction 是郵件，CPU 是郵差。**

資深研究人員把這個類比推到批次格式：與其彙整時重寫整份 `inst.json`，也可以每回合原子發布一份
manifest，裡面只列本批不可變的 instruction 檔。這一條若要變成真的，會直接改到現有彙整協定；
本輪只記靈感，不當作規格提案。

郵局不是唯一比喻。資深架構師看見的是同步數位電路：

> folder 是暫存器，instruction 是組合邏輯，rename 是 clock edge，`.runi` 是「時脈只走了一半」
> 的證據。不同 CPU 可視為 clock domain，只能經 mailbox 跨域。

資深研究人員則稱它是「一台以目錄為記憶體、以 `rename` 為提交脈衝的奇怪電腦」。兩句與郵局
沒有互相取代：郵局說的是交接，電路說的是哪一刻從未完成跨成已發生。

## 把世界停住、複製，然後看兩個未來

這是本輪最強、也最意外的撞題：**四位互相看不到，卻四位獨立地都想到廉價分支世界；最後四人
挑「最想成真」時，又 4／4 選了這一家族。**

### `aos fork`：分開法律與在途工作

資深工程師先把 `.aos` 拆成兩種東西：`kernel.json`、版本是可攜的「法律」；queue、`.runi`、
temp 是本機正在發生的「運動」。不拆的話，「整個 `.aos` 不進 git」與「kernel 要版本化」早晚
會互撞。

他的 `aos fork SOURCE DEST --at-boundary` 只准在回合邊界執行：有 `.runi` 就拒絕；複製世界與
kernel，清空在途狀態，再把不同 prompt 塞進各分支。這不只是備份，而是讓「可複製什麼、不能
複製什麼」成為使用者摸得到的界線。

### 回合快照：replay 不可信，就保存真現場

資深架構師想到 reflink／filesystem snapshot：`aos branch world@42 experiment-b/`，兩個 agent
從同一現場走不同未來，再用 `aos diff-turn` 比較。理由不是 replay 比較方便，反而是 LLM 不具
決定性，普通 replay 常是假象；保存當時的完整世界再分叉，才是在比較「如果那時換一個提示」。

他最喜歡的講法是：

> **資料夾若真的是世界，最迷人的能力不是讓它跑得更快，而是把它停住、複製，然後觀看兩個
> 未來。**

### speculative worlds：把推測執行字面化

資深研究人員把同一件事做成 `aos speculate -n 8 world`：用 reflink 複製八個候選世界，不同
模型／提示各跑一回合，評分器挑一個；其他分支留下來 diff，或之後刪除。他甚至讓世界本身變成
世代：`versions/42.tmp/` 完成後 rename 成 `42/`，再原子切換 `current`。如此原子的就不只「取到
哪批指令」，而是整個世界版本。

他把可能的使用體驗縮成三個普通檔案動作：

> **`cp` 是 fork 宇宙，`diff` 是解釋兩條時間線，`rename` 是承認其中一條成為現在。**

### 世界競技場：分支不是藏在 scheduler 裡，而是擺在桌上

要接工具的開發者把分支放進 `arena/{claude,gpt,local}/`：各走五回合，judge CPU 只看 diff 與
測試，把勝者 rename 成 `winner`。資深架構師也獨立想到父世界一次繁殖十個子資料夾，改不同
prompt／kernel，最後只把評分與產物投回父世界。

資深工程師的好玩版本更像生態缸：一百個小世界各養一個 agent，只能向相鄰世界投信；每回合後
畫出族群、語言與合作關係。它不先解 queue 衝突、容量與公平性，反而把那些問題變成人眼看得見
的現象。

若這一家族真的落地，會碰到規格的地方很明確：什麼算回合邊界、哪些 `.aos` 狀態可以複製、
`.runi` 存在時是否一律拒絕、勝者如何原子成為 current。四位本輪只是在同一個形狀上各畫一幅
未來，沒有替這些問題拍板。

## 人也可以是一顆 CPU

**工程師、架構師、要接工具的開發者三位獨立地提出 Human CPU。**共同形狀是
`.aos/insts/human.json`：TUI、網頁或文字編輯器 claim 一個「批准部署／補背景／選 A 或 B」的
問題，人填答案，完整後 rename 回結果。

這個想法好玩的地方不是把人硬說成機器，而是**人不再是協定外的例外**。資深架構師沿著同一條
線，把 LLM、人工核准、實驗儀器與印表機都看成慢速或異質 CPU；每一種只要會收信、做事、回信，
就能接進來。

資深工程師還把它當成外部處理器契約的試紙：如果 Human CPU 不引用 aos lib，只照磁碟契約就能
接上，那句「外部處理器的構造會很簡單」才真的站得住。這一條若成真，會驗證現有協定，但不必
先改 core。

## 等待也是 CPU；休眠不是故障

資深架構師提出一顆什麼都不算的外部 CPU：**等待**。world 完全睡著，calendar watcher 到 09:00
才投遞 instruction。長期 workflow 因此不必為每個世界養 daemon。

要接工具的開發者從另一端撞到同一個形狀：world 可以半年沒有 process，壓成 tar 寄走，解開後
再走一回合。對這種產品，先痛的可能不是 CPU 數，而是絕對路徑、秘密與外部 effect 能不能一起
搬。

他說最漂亮的是：

> **沒有活主控者仍有世界。**

資深研究人員也把 LLM 從「CPU」降成高延遲、非決定性的協處理器：真正的 CPU 仍是 `aos exec`；
模型只是偶爾從 mailbox 回一包候選 instruction 的裝置。mailbox、timeout、結果快取，可能比把
模型描述成常駐 agent 更貼近它。

## 失敗的世界不要只剩一把鎖

資深工程師不想只看到 `.runi` 卡住。他想讓 kernel 尾聲選配「飛行紀錄器」：每回合發布
`turns/000042.d`，放 claimed batch、kernel hash、exit 與 next deliveries；`aos explain <world>`
不替人推理，只把資料排成可讀的因果鏈。

要接工具的開發者把它叫作 **Crash museum**：把當時批次、kernel、已寫檔案與未發布投遞渲染
出來，失敗 world 可以整包附進 bug report。他同時指出這個模型最醜的地方：

> **「資料夾變了」缺少來源，五回合後沒人知道哪條 instruction 改壞哪個檔。**

資深架構師的 `aos fsck` 從信箱修復看同一件事；研究人員的世代 world 則想讓 crash 前的 current
仍保持完整。四個方向沒有收成一項功能：飛行紀錄器重因果、fsck 重修復、Crash museum 重展示、
世代 world 重回復。但它們都拒絕把 `.runi` 只當一把該刪掉的鎖。

## 如果真的有一千個 agent，四位先怕的不是同一件事

這一群沒有撞成單一答案，反而像四個不同儀表板：

- **資深工程師**想先看一百個鄰居世界的生態圖。它是展示品，也是把公平、容量與 queue 衝突
  肉眼化的方法。
- **資深架構師**認為 POSIX rename 會先失去可攜性；到物件儲存時，核心可能換成 conditional put。
  真正要保留的不是路徑，而是「未完成內容不可見、發布只有一次狀態跳變」。
- **資深研究人員**先加配額：每世界每回合最多多少 bytes、指令、外呼費用與衍生世界。沒有
  背壓，系統會先被磁碟與帳單擊穿。
- **要接工具的開發者**先加觀測：每次 rename 旁生唯讀 `turn-start`／`delivery`／`turn-end` 事件，
  讓 SQLite 或網站建立可重建索引；磁碟仍是真源。

有意思的是，沒有人在這一題先回答「更大的 process tree」。一位想看行為、一位換提交媒介、
一位控制資源、一位補來源；四種答案都把 agent 數量當成世界模型的壓力，而不是 scheduler 的數字。

## 幾條讓它們單獨站著的想法

### 法律與運動不要混在同一個「不進 git」裡

資深工程師那句「`.aos` 分成法律與運動」沒有別人直接接到。`kernel.json`、版本是法律；queue、
`.runi`、temp 是運動。這個分法同時碰版本控制、fork 與可攜性；若要實作，會直接影響 `.aos`
哪些檔可複製／可進 git，但本輪不轉交。

### 一回合也許只需要一份不可變 manifest

資深研究人員獨自提出：彙整不一定要反覆重寫一個含全部 instruction 的 `inst.json`，也可以發布
一份 manifest 指向本批不可變檔案。這會讓 instruction 本身更像郵件；也會改變現行「一回合＝
一整批」的落盤形狀，所以暫時讓它作為一條孤立的靈感。

### `rename` 是世界跨過門檻的那一刻

資深工程師的一句話既像電路，也像故事：

> **`rename` 不只是在提交檔案；它可以是世界從「可能」跨進「已發生」的那一刻。**

資深架構師說 clock edge，研究人員說提交脈衝，三人其實各自給了這句話另一種版本。

## 可能真的該做的

四位各自挑「最想看到它變成真的那一條」時，**四位獨立地都選了分支世界**。不是四票投給同一
組 CLI，而是四種理由落在同一個根：資料夾既然是世界，複製它就該能複製一個未來。

| 誰 | 他最想看到的 | 他為什麼挑這條 |
|---|---|---|
| **資深工程師** | `aos fork SOURCE DEST --at-boundary` | 它把「世界就在資料夾裡」從實作細節變成使用者摸得到的能力，也逼系統誠實分開可複製狀態與不可複製的在途工作 |
| **資深架構師** | 回合快照與分支：`aos branch world@42 experiment-b/` | LLM 不具決定性，保存真實世界再從某回合分叉，比假裝可 replay 更誠實地回答「換一個提示會怎樣」 |
| **資深研究人員** | speculative worlds：`aos speculate -n 8 world` | 不先造分散式 scheduler，只用 reflink、普通 `aos exec`、評分腳本與一次 pointer rename，就能讓多條未來可觀看、比較、保留 |
| **要接工具的開發者** | 世界競技場：`arena/{claude,gpt,local}/` → `winner` | 它不新增抽象，只把世界在檔案系統、回合有邊界兌現成廉價分支、比較與重播 |

四位的收尾句也落在同一個地方：

> **`aos` 最有趣的未來，也許不是管理更多行程，而是讓「複製世界、試跑未來、提交其中一條」
> 像檔案操作一樣普通。** ——資深研究人員

> **aos 最有趣的未來，也許不是更像 OS，而是讓工作休眠、分岔、交給人或模型，再把整個現場
> 帶走。** ——要接工具的開發者
