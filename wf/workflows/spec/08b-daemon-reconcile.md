# 08b daemon 的對帳與清理
← [入口](README.md)

daemon 起來第一件事是拿登記表跟磁碟對帳：哪些鐘還在走、哪些行程死了、哪些地不見了。之後它一邊看管子行程一邊定期再對一次帳。這份檔接著 [08](08-daemon.md)，條款編號延續，講對帳、看管、清理、一次全停、搬家。

## 登記表的寫者有四方

- **S-08-98** 登記表必須容許四方寫：exec 登 `pending`、`aos run --register`、門房登出生、daemon 自己。四方一律先拿 `registry.lock` 再原子改名，[02](02-layout.md) 的「每條路徑恰一個 writer」對登記表的例外就明列在這裡，禁止再有第五方。〔主編補〕

## `aos daemon start`：先對帳

- **S-08-32** `aos daemon start` 必須先讀登記表逐筆對帳，對完才起子行程。〔主編補〕
- **S-08-33** 對帳必須同時看兩樣：那筆的行程還活著嗎、那筆的 `path` 還在嗎。〔主編補〕
- **S-08-68** 判活必須看 `pid` 與 `pid_start` 兩欄都吻合；只看 `pid` 會在系統重用編號時認錯人，甚至把 SIGKILL 打到無辜的第三方行程。〔主編補〕
- **S-08-34** 行程活著、路徑在＝鐘還在走，必須留著那筆 `running`，禁止重起一支。〔主編補〕
- **S-08-35** 行程死了、路徑在＝必須依 `clock` 決定：`every`／`until` 重起子行程，`steps`／`once` 標成 `stopped`。〔主編補〕
- **S-08-36** 路徑不在、行程還活著＝孤魂，必須先停掉那支行程，再刪那筆登記。〔裁決 2026-09-04〕
- **S-08-37** 路徑不在、行程也不在＝地死了，必須直接刪那筆登記。〔裁決 2026-09-04〕
- **S-08-71** daemon 禁止自動改登記的 `path`。路徑不見一律走孤魂流程判死，就算那支行程其實健康地在新位置跑；要搬只能用 `aos mv`。〔主編補〕
- **S-08-70** `pending` 而且沒有 `pid` 的那筆，重啟時必須一律當成沒起過並重起；不會變成兩支，正確性靠那塊地的 `.aos/lock`。〔主編補〕
- **S-08-88** `aos daemon start` 必須確認 LLM 世界那塊地（使用者層設定的 `llm_world`）有一筆登記；沒有就自動補一筆，`runner` 填 `llm-serve`。〔主編補〕
- **S-08-97** `llm_world` 指的路徑還沒有 `.aos/` 時，`aos daemon start` 必須先對它做一次 `aos init`（就是 `aos llm init` 那件事，見 [09](09-llm-world.md)），再登記那筆 `llm-serve`。〔主編補〕
- **S-08-89** 對帳完必須起兩種筆：`pending` 的，以及 `resume` 是 `true` 的；起完必須把 `resume` 清掉。〔主編補〕
- **S-08-38** 對帳完必須替每筆 `pending` 起子行程、改成 `running`。〔主編補〕
- **S-08-72** `aos daemon start` 必須印出這次接管了幾個孤兒時鐘、清掉了幾筆；靜靜接管等於沒人看得見。〔主編補〕

## 看管與巡邏

- **S-08-39** 起完之後必須進看管迴圈：子行程結束就更新 `state`，定期巡邏＝再做一次對帳。〔主編補〕
- **S-08-69** 不是自己親生子行程的那些登記（daemon 上次死掉、被 init 領養的），必須用輪詢判死，建議 5 秒一次；禁止只靠 `waitpid`，領養過的收不到。〔主編補〕
- **S-08-40** 巡邏必須是保底不是快路；禁止要求地在消失前先通知 daemon。〔裁決 2026-09-04〕
- **S-08-62** 門鈴（門房或 `aos deliver` 發的「某地有新投遞」）收件人必須是 daemon，禁止直接戳那塊地。〔主編補〕
- **S-08-63** daemon 收到門鈴、那塊地又沒有 `running` 的登記時，必須替它起一支 `--until idle` 的 run。〔主編補〕
- **S-08-90** daemon 必須替自己起的子行程收屍（忽略 `SIGCHLD` 或 `waitpid(WNOHANG)`）；殭屍禁止算成活著，不然那個 pid 還在、對帳永遠不會把它改成 `stopped`。〔主編補〕
- **S-08-73** `every` 的 run 因為沒新指令而正常退出時，那筆登記必須保留成 `stopped`；下次到期由 daemon 重起一支新的 run。〔主編補〕
- **S-08-74** `once` 的 run 跑完必須刪掉那筆登記；`steps` 與 `until` 跑完標成 `stopped`，禁止重起。〔主編補〕
- **S-08-91** `--until never` 的登記（伺服器型的地，例如 LLM 世界）必須照 `every` 那條辦：run 退出後保留登記，到期由 daemon 重起。〔主編補〕
- **S-08-95** 每筆必須收一個可選欄 `last_started_at`：daemon 起那支 run 時寫，run 自己 `--register` 時也寫；沒起過就沒有這欄。〔主編補〕
- **S-08-96** 「到期」必須這樣算：`last_started_at` 加上 `clock.every_ms` 已經過了就算到期。沒有 `last_started_at` 的 `every` 筆一律當成到期，立刻起一支。〔主編補〕

## 清理：只刪自己那塊，不碰父的檔

- **S-08-75** daemon 禁止刪父地上的任何東西：結果檔、狀態檔、用量檔都不准碰。它只看得到自己管的那塊地。〔主編補〕
- **S-08-41** 一塊脫節子地閒著、`stopped` 超過使用者層的 `reap_after_ms`（牆鐘），daemon 必須刪掉那塊地本身與它那筆登記。〔裁決 2026-09-05，數字之後可改〕
- **S-08-76** 刪之前必須看那筆的 `ext.result`：落點沒有結果檔就代寫 `<結果落點>.status.json`、`reason` 填 `reaped`，讓父看到的是「壞了」而不是「還沒好」。〔主編補〕
- **S-08-42** 暫態的地建議由開它的父讀完結果就刪；巡邏只當保底。〔裁決 2026-09-05〕

## `aos daemon stop`：一次全停

- **S-08-77** 每支 run 必須自成一個行程群組；停一顆鐘必須對整個群組送訊號，同步子孫才不會變成孤兒繼續改檔案。〔主編補〕
- **S-08-45** `aos daemon stop` 必須對每筆 `running` 的地投一則 `stop` 到它的 `.aos/control/`，等它自己停。〔預設 2026-09-05，L-05〕
- **S-08-46** 等超過 10 秒還沒停的，必須對那個行程群組送 SIGKILL，再改成 `stopped`。〔主編補〕
- **S-08-92** `aos daemon stop` 停掉的每一筆，除了改成 `stopped`，必須把 `resume` 設成 `true`；不設的話全停之後再 start，那些地就再也不會被接回去跑。〔主編補〕
- **S-08-47** daemon 不在時 `aos daemon stop` 必須先做一次完整對帳，再照上兩條全停。〔主編補〕
- **S-08-48** 全停時被 SIGKILL 殺掉的脫節子地寫不出結果，daemon 必須在那筆的 `ext.result` 指的落點旁補一份 `<結果落點>.status.json`，`reason` 寫 `killed`。〔主編補〕
- **S-08-49** 理由必須寫進文件：不補狀態檔，父的 `await` 會一直等一個永遠不會來的結果。〔主編補〕
- **S-08-78** `aos stop --kill <地>` 之後 daemon 必須做同樣的代寫；殺掉不是只送一個訊號就算完。〔主編補〕
- **S-08-93** `aos stop --kill <地>` 找 pid 必須有兩個來源：登記表那筆，以及那塊地 `.aos/lock` 裡的 `pid`；沒登記的 run 只有鎖檔查得到。〔主編補〕
- **S-08-94** 兩個來源都查不到活人時，`aos stop` 禁止投控制信，必須直接說「這塊地現在沒人在跑」並列出查過哪兩處；不然那封信會躺著等下一趟 run 開跑才把它停掉。〔主編補〕
- **S-08-79** 被殺那格的 `.aos/ticks/<N>/` 必須原封留著當現場，禁止 daemon 自己蓋掉重跑；現場怎麼收由 `aos fix` 處理，見 [12](12-cli.md)。〔主編補〕

## `aos mv`：唯一正確的搬法

- **S-08-52** 搬一塊地必須用 `aos mv <舊> <新>`：投 `stop` → 等它停 → `mv` 資料夾 → 那筆的 `path` 改成新的真實路徑 → 原本 `running` 的在新路徑重起。〔裁決 2026-09-05〕
- **S-08-80** `aos mv` 必須連 `.aos/` 一起搬，接力棒與游標保留；身分換了但跑到一半的工作接得下去。〔主編補〕
- **S-08-81** `aos mv` 必須把前身路徑寫進新地 `.aos/layout.json` 的 `ext.moved_from`。〔主編補〕
- **S-08-82** `aos mv` 必須是唯一准改登記表 `path` 的地方；別的路徑一律禁止改，只能刪了重登記。〔主編補〕
- **S-08-53** 文件必須把 `aos mv` 寫成唯一正確的搬法；語意仍是舊的死了、新的生一個，只有跑到一半的狀態是例外。〔裁決 2026-09-04〕
- **S-08-54** 在 shell 直接 `mv` 禁止被當成錯誤，後果必須由對帳兜底：舊路徑那筆被判死清掉，新路徑沒登記也沒鐘，跑到一半的狀態不保證接得下去。〔裁決 2026-09-05〕
- **S-08-55** 禁止做搬家通知，也禁止用 symlink 當第二個身分。〔裁決 2026-09-04〕

## 現況對照

今天沒有對帳這回事：每塊地各寫自己的 `.aos/run.pid`，沒有人在重啟後檢查那個編號還是不是同一支行程，也沒有孤兒接管。今天沒有巡邏、沒有到期清理，跑完的暫態資料夾會一直留著。搬家今天沒兜底，舊行程抓著舊路徑繼續跑；`aos stop` 只對單一 pid 送訊號，同步子孫收不到。
