# 05 接力棒 series.json
← [入口](README.md)

接力棒是 `.aos/series.json`。一塊地上「這一批有哪幾條串、各跑到哪」全記在這一個檔裡。兩格之間程式不存在，下一格全靠讀它接上。欄位正本是 [schemas/series.schema.json](schemas/series.schema.json)；暫存器怎麼替換、兩種壽命、這個檔誰能寫，在 [05b](05b-series-lifetimes.md)。

## 一、為什麼是一個檔

- **S-05-01** 接力棒必須是一個 json 檔，路徑 `.aos/series.json`：檔頭放批 id 與格式版本，內容是一個陣列、一條串一個物件。〔裁決 2026-09-05〕
- **S-05-02** 這一批的彙總狀態禁止另立欄位或另立檔案；要知道這批的狀況，必須看各串的 `status`。〔裁決 2026-09-05〕
- **S-05-03** 進度必須寫在這個檔裡，禁止只留在記憶體：一格做完 exec 就交回，兩格之間沒有任何程式活著。〔裁決 2026-09-01〕
- **S-05-04** exec 每一格必須先把整份接力棒讀進來，跑完再整份寫回。〔主編補〕
- **S-05-05** 控制流禁止只靠「指令做完自己投下一步」：投遞掉了整條串會無聲斷掉。〔裁決 2026-09-01〕

## 二、檔頭

- **S-05-06** `format_version` 必須是整數，這一版是 `1`。〔主編補〕
- **S-05-07** `batch_id` 必須在載入那一刻產生，值是 32 個小寫 hex 的隨機 id；這一批跑完之前禁止換。〔主編補〕
- **S-05-08** 重新載入（被 `aos reset` 清過，或再次被父點名打開）必須產一個新的 `batch_id`。〔主編補〕
- **S-05-09** `tick` 必須是最近一次寫回時剛跑完那一格的格號；載入那一刻寫 `0`。〔主編補〕
- **S-05-10** exec 讀到 `tick` 之後，這一格的格號必須是 `tick + 1`，檔開在 `.aos/ticks/<格號>/`；寫回時 `tick` 必須推成這個格號。〔主編補〕
- **S-05-46** `recent_ids` 必須有：一個字串陣列，記最近從收件匣取件過的投遞 id，最多 1000 個，滿了先進先出丟最舊的。〔主編補〕
- **S-05-47** exec 取件時，投遞 id 已經在 `recent_ids` 裡的必須拒收；控制收件匣的去重另外記，禁止共用這一欄。〔主編補〕
- **S-05-48** 跨重啟還認得舊 id，必須以 `.aos/` 是持久的為前提；`.aos/` 放在 tmpfs 上時，去重禁止被當成保證。〔主編補〕
- **S-05-58** 收件匣的投遞 id 去重必須只靠 `recent_ids`，禁止另外開一個去重檔或去重目錄。〔主編補〕

## 三、一條串記什麼

- **S-05-11** `id` 必須是這塊地上唯一的串 id，機器產，32 個小寫 hex。〔主編補〕
- **S-05-12** `template` 必須是這條串在跑的那個模板的名字，對應 `.aos/program/<模板名>.json`。〔主編補〕
- **S-05-13** `cursor` 必須寫步名，禁止寫成第幾步的數字：步會被插被刪，數字會指錯人。〔主編補〕
- **S-05-14** `regs` 是這條串的暫存器（符號表）：必須是一個物件，名字對字串值，只在這條串裡有效，禁止被別條串讀到。〔裁決 2026-09-01〕
- **S-05-16** `parent` 必須有，值是同一塊地上開出它的那條串的 id，或 `null`。遞迴＝很多條串共用一個 `template`、各有各的 `id`。〔主編補〕
- **S-05-17** `resources` 是可選的自我申報（`ticks`、`llm_calls`、`priority`）；排程只准拿它當參考，禁止當保證。〔裁決 2026-09-01〕
- **S-05-18** `fail_reason` 必須只在 `status` 是 `failed` 或 `stopped` 時出現，值是短代碼，跟狀態檔的 `reason` 用同一組。〔主編補〕
- **S-05-19** `ext` 是具名擴充區；除了它，接力棒出現不認得的欄位必須整份拒絕。〔裁決 2026-08-28〕
- **S-05-49** `fail_streak` 必須有：整數，記這條串停在同一步連續失敗幾次。那一步成功、或游標推到別的步，必須歸零。〔主編補〕
- **S-05-53** `calls` 是可選的物件，必須是步名對一個 call id：記這條串停在那一步時開過的那筆呼叫記錄。〔主編補〕
- **S-05-54** `await_ticks` 是可選的物件，必須是步名對一個整數：記這條串停在那一步已經等了幾格。〔主編補〕

## 四、狀態四值

- **S-05-20** `status` 必須是四個值之一：`running`（還在跑）、`done`（跑完了）、`failed`（哪一步壞了）、`stopped`（被人或被預算叫停）。〔裁決 2026-09-05〕
- **S-05-21** 串誕生時必須是 `running`；游標走到 `"end"` 時必須改 `done`。〔主編補〕
- **S-05-22** 一步失敗又沒地方跳時必須改 `failed`；收到停的指示時必須改 `stopped`。〔裁決 2026-09-05〕
- **S-05-23** `failed` 與 `stopped` 的串禁止自動變回 `running`：要它再動，只有 `aos reset` 清掉，或整塊地被父刪掉重來。〔裁決 2026-09-05〕
- **S-05-24** 不是 `running` 的串在下一格必須被跳過：不推游標、不產指令。〔主編補〕
- **S-05-50** 一條串必須算「在等」，如果它 `status` 是 `running`，而且游標停在 `await` 步、或停在 `mode` 是 `"sync"` 的 `call` 步而子還沒閒著。在等的串禁止被當成沒事做（怎麼用見 [06](06-exec-and-run.md)）。〔主編補〕

## 五、游標怎麼推

- **S-05-25** 成敗必須看檔案判，禁止拿結束碼當「做成沒做成」；結束碼只管跑沒跑起來。〔裁決 2026-09-05〕
- **S-05-26** `inst` 步：傳輸層失敗（沒跑起來、被訊號殺、逾時）必須算失敗。有 `expect` 時，那個檔在＝成功、`<expect>.status.json` 在＝失敗、兩個都不在＝失敗。沒 `expect` 才退而看結束碼，`0`＝成功。〔主編補〕
- **S-05-27** `call` 步：`sync` 時父每格對子做一次 `aos exec`，子沒閒著這一步必須停在原地、禁止算失敗，子閒著後照結果落點判。`async` 時登記完子的時鐘，這一步必須立刻算成功。〔裁決 2026-09-05〕
- **S-05-61** 同步 `call` 的子閒著了，結果落點沒檔、狀態檔也不在時，這一步必須算失敗、`fail_reason` 寫 `no_result`；禁止再對那塊子地點名，不然父會每格重新載入一塊已經閒著的地、永遠卡住。〔主編補〕
- **S-05-55** 呼叫記錄必須只在游標第一次走進那一步時寫一筆，call id 記進 `calls[步名]`；同一步停在原地的後面幾格，禁止再寫新的呼叫記錄，必須沿用 `calls[步名]` 那一筆。〔主編補〕
- **S-05-28** `await` 步：結果檔不在＝這一格串不動、禁止算失敗；結果檔在＝成功；`<result>.status.json` 在＝失敗。〔裁決 2026-09-05〕
- **S-05-56** `await` 步每一格必須把 `await_ticks[步名]` 加一；跟 `max_ticks` 比的就是這個數，超過必須算失敗，`fail_reason` 寫 `await_timeout`。〔主編補〕
- **S-05-57** 游標離開一步時，必須把 `calls` 與 `await_ticks` 裡那個步名的鍵刪掉；下次再走進同一步就是從頭算。〔主編補〕
- **S-05-29** 一步成功時 `cursor` 必須照那一步的 `then` 改；`then` 省略就走模板裡的下一步；`then` 是 `"end"` 就把 `cursor` 寫成 `"end"`、`status` 改 `done`。〔主編補〕
- **S-05-30** 那一步有 `select` 時，成功後必須改讀 `select` 指的那個檔的第一行當下一步名，蓋過 `then`。〔預設 2026-09-05，D-02〕
- **S-05-31** 一步失敗、那一步有 `on_fail` 時，必須照 `on_fail` 改 `cursor`，`status` 留在 `running`。〔裁決 2026-09-05〕
- **S-05-32** 一步失敗、那一步沒有 `on_fail` 時，必須停在原地：`cursor` 不動、`status` 改 `failed`、`fail_reason` 寫短代碼，並由 run 寫 `.aos/stopped.json`。系統禁止自己重試，也沒有例外機制。〔裁決 2026-09-05〕
- **S-05-51** `fail_streak` 加到 3 時，exec 必須把這條串改成 `stopped`、`fail_reason` 寫 `repeat_fail`，就算那一步有 `on_fail` 也一樣；父的腳本禁止關掉這條。〔主編補〕
- **S-05-52** `on_fail` 指到的那一步自己又失敗時，禁止再做一次處置：串必須直接改 `failed`，`fail_reason` 寫成 `<原始原因>;<處置原因>` 兩層。〔主編補〕

## 六、串怎麼生、怎麼清

- **S-05-33** 載入那一刻必須只開一條串：`template` 是 `main`、`cursor` 指 `main` 的第一步、`regs` 空、`parent` 是 `null`。〔主編補〕
- **S-05-34** `call` 步禁止在這塊地上開新串：它開的是一塊子地，子地有自己的接力棒。〔裁決 2026-09-05〕
- **S-05-35** 模板呼叫模板必須由編譯器在編譯期拆平進同一條串，禁止在跑的時候開子串；所以這一版所有串的 `parent` 都是 `null`，欄位先留著。〔主編補〕
- **S-05-36** `done` 的串必須留在陣列裡，禁止跑完就刪；要清只有 `aos reset` 或重新載入。〔預設 2026-09-05，E-05〕

## 七、什麼叫閒著

- **S-05-44** 一塊地必須在 `series` 是空陣列、或每一條串的 `status` 都是 `done` 時算閒著。〔主編補〕
- **S-05-45** 有 `failed` 或 `stopped` 的串時禁止算閒著：run 要以「因失敗停」收場，不是以「跑完」收場。〔主編補〕

## 八、範例

兩條串：一條停在 `await` 步在等（已經等了 3 格），一條已經跑完。

```json
{

  "batch_id": "9f2c1a4b7e0d43a6b8c5f1e2d3a49b70",
  "tick": 12,
  "recent_ids": ["a3f0091c2b7d4e5f8091a2b3c4d5e6f7"],
  "series": [
    {
      "id": "0a1b2c3d4e5f60718293a4b5c6d7e8f9",
      "template": "main",
      "cursor": "wait_report",
      "status": "running",
      "regs": { "who": "alice" },
      "parent": null,
      "fail_streak": 0,
      "calls": { "spawn_worker": "6d5c4b3a29180716f5e4d3c2b1a09876" },
      "await_ticks": { "wait_report": 3 },

      "fail_streak": 0,
      "ext": {}
    }
  ]
}
```

## 待使用者拍板

〔預設〕：S-05-30 有 `select` 就讀那個檔第一行當下一步名（D-02）；S-05-36 `done` 的串留著不當場刪（E-05）。

〔主編補〕：

- S-05-04 一格讀一次、寫一次整份。
- S-05-06 `format_version` 是整數 `1`。
- S-05-07／08 `batch_id` 載入時產，重新載入換新。
- S-05-09／10 `tick` 記剛跑完那格，這格是 `tick + 1`。
- S-05-11～13 串 id 是 32 hex；`template` 對應 `.aos/program/`；`cursor` 寫步名不寫數字。
- S-05-16 `parent` 語意；遞迴＝同模板多筆。
- S-05-18 `fail_reason` 與狀態檔共用短代碼。
- S-05-21／24 誕生是 `running`；非 `running` 跳過。
- S-05-26 沒 `expect` 才看結束碼（入口表矛盾 7）。
- S-05-29 `then` 省略＝走下一步。
- S-05-33 載入只開一條 `main`。
- S-05-35 模板呼叫模板走編譯期拆平。
- S-05-44／45 閒著的定義；壞掉的串不算閒著。
- S-05-46～48、58 `recent_ids` 去重，tmpfs 上不保證，禁止另開去重檔（B33／B34）。
- S-05-49／51 `fail_streak` 與連三次強制 `stopped`（B08）。
- S-05-50 「在等」的定義（B01）。
- S-05-52 處置那步再壞就不再處置，原因記兩層（S11）。
- S-05-53～57 `calls` 與 `await_ticks`：呼叫記錄只開一次、等待格數有地方數、離開那步就清鍵。
- S-05-61 同步子閒著卻沒結果也沒狀態檔＝失敗 `no_result`。

矛盾：ideas 05 說「函數呼叫＝開一條子串、掛上父串 id」，但三種步（`inst`／`call`／`await`）沒有一種會開串，`call` 開的是子地。我選編譯期拆平（S-05-35），因為加第四種步會動到 03 與 06；代價是 `parent` 這一版永遠是 `null`。要不要改成允許開子串，請使用者裁。

## 現況對照

今天沒有 `series.json`：控制流靠指令做完自己投下一條，投遞掉了整條線就斷。串、游標、暫存器、堆疊框都不存在，進度散在 `.aos/batch/<turn>/` 的目錄名裡。也沒有收過的投遞 id 表，同一筆重投會被當成新工作跑第二次。
