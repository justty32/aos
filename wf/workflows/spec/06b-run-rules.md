# 06b run 的停法與恢復
← [入口](README.md)

`aos run` 就是反覆叫 `aos exec`。一格裡面發生什麼在 [06](06-exec-and-run.md)；這份檔只管外面那一圈：怎麼走、什麼時候停、停了留下什麼、上次崩在半路這次怎麼接。兩份檔共用一套 `S-06-NN` 編號，不另起新號段。

## 三種走法

- **S-06-16** `aos run` 必須就是反覆叫 exec，禁止另有一套推進邏輯。〔裁決 2026-09-04〕
- **S-06-17** 三種走法必須對應三個旗標：`--steps N`（走固定 N 格）、`--every <ms>`（每隔這麼久走一格）、`--until idle`（走到閒著；不給旗標時的預設）。〔裁決 2026-09-04〕
- **S-06-54** `--until` 必須多收一個值 `never`：閒著也不停，只等投遞或控制信進來，給伺服器型的地用（`aos llm serve` 預設就是它）。`--until never` 沒給 `--every` 時必須用 `500` 毫秒。〔主編補〕
- **S-06-19** 禁止另立第三種「有變動才動」的走法；那件事用「沒新指令就停、有信進來就醒」加門鈴達成。〔預設 2026-09-05，F-03〕
- **S-06-20** 預算 `--budget N` 的單位必須是格數，由 run 自己數；走滿就停。〔預設 2026-09-05，E-03〕
- **S-06-46** run 期間禁止讀頂層原稿的任何一個位元組。〔主編補〕
- **S-06-47** 建議每格開頭 stat 一次自己的 `.aos/`；不在了就停，原因寫 `land_gone`。〔主編補〕

## 通用停法

- **S-06-18** 通用停法必須管住三種走法，而且要兩個條件同時成立才停：這次 exec 沒產出新指令，**而且**沒有任何串在等。「在等」＝游標停在 `await` 步，或停在同步 `call` 步而子還沒閒著（定義見 [05](05-series-format.md)）。〔主編補〕
- **S-06-58** run 每一格 exec 完必須先看這塊地閒著沒有：閒著就停，原因寫 `no_new_insts`。閒著必須贏過「這格游標動了」——最後一格把串推到 `done`，游標是動了，但地已經閒著，這時必須停。不這樣做的話下一格會重新載入、整批從頭再跑。〔主編補〕
- **S-06-36** 只剩在等的串時，run 必須在兩格之間睡 `--every` 那麼久再走下一格；沒給 `--every` 就睡 `500` 毫秒。`--steps N` 與 `--budget N` 照舊一格一格數。〔主編補〕
- **S-06-37** run 決定要停之後、放鎖之前，必須再掃一次 `.aos/inbox/`；有新投遞進來就不停，再走一格。〔主編補〕
- **S-06-57** 幾個停止條件同時成立時，寫進停止原因檔的必須照這個優先序挑：失敗 ＞ 控制信 ＞ 閒著 ＞ `--steps` 跑滿 ＞ `--budget` 用完。`--steps` 與 `--budget` 同時滿足必須報 `steps_done`。〔主編補〕

S-06-18 改寫了 M-01 升格的那條裁決（原話只有前半句「沒產出新指令就停」）。理由：不改的話，父投出一筆脫節呼叫的下一格就沒有新指令了，run 當場停掉，結果回來沒人收。

## 停與殺

- **S-06-21** run 的每一格之間必須看一次 `.aos/control/`，收到 `stop` 就在格邊界停；禁止打斷正在跑的一格。〔預設 2026-09-05，L-05〕
- **S-06-62** exec 也必須每格讀一次 `.aos/control/`（取件之後、湊指令之前）：收到 `stop` 就把所有 `running` 串改成 `stopped`、寫停止原因檔（`stop_requested`）、把信搬到 `.aos/control/done/`、寫回接力棒後放鎖並退出 `0`，這一格不跑任何指令。這條只為「父用 `call` 步 `mode:"sync"` 帶著走的子地」而存在——那種子地沒有自己的 run，控制信沒人收。agent 預設自己登記時鐘（[10](10-agent.md) 的 S-10-30），它的控制信由自己那支 run 讀。〔主編補〕
- **S-06-38** 控制收件匣必須在三個點讀：每格開頭、每筆指令逾時輪詢的每一輪、在等時的每次睡醒。所以「停」最壞要等一筆指令的 timeout 那麼久。〔主編補〕
- **S-06-39** run 必須 `setpgid` 讓自己自成一個行程群組，同步呼叫開出來的子子孫孫全在這個群組裡；停一顆鐘就是對這個群組送訊號。〔主編補〕
- **S-06-55** 處理過的控制信必須搬到 `.aos/control/done/`；run 開跑前必須把收件匣裡既有的控制信全搬到 `done/`，並印一行「清掉 N 封陳年控制信」。`op` 不認得的信也必須搬到 `done/` 並印一行。〔主編補〕
- **S-06-56** 建議把睡 `--every` 的時間切成不超過 `100` 毫秒的小段，每一段醒來看一次控制收件匣。〔主編補〕

## 停下來要留下原因

- **S-06-22** run 每一次停下來都必須寫 `.aos/stopped.json`，格式照 [stopped.schema.json](schemas/stopped.schema.json)；run 一開始必須先刪掉舊的那一份。〔預設 2026-09-05，E-03〕
- **S-06-23** 有串變成 `failed` 時，那條串必須停在原地，run 必須停下並寫 `reason` 為 `failed`；系統禁止自己重試。〔裁決 2026-09-05〕
- **S-06-53** `.aos/stopped.json` 必須只有三個寫者：exec（判串失敗那一刻寫）、run（開跑前刪掉舊的、停下時一定寫，收到 `SIGTERM` 也要寫）、daemon（`--kill` 之後代寫 `killed`）。run 寫的時候必須把 exec 那一份的 `detail` 帶進去。禁止第四個寫者。〔主編補〕
- **S-06-24** run 的退出碼必須這樣對：`no_new_insts`、`steps_done`、`stop_requested` 給 `0`；`failed`、`budget`、`timeout`、`repeat_fail`、`crashed`、`land_gone` 給 `5`；用法錯 `2`、解析拒絕 `3`、不是一塊地 `4`、鎖被佔 `75`。〔主編補〕

```json
{
  "format_version": 1,
  "reason": "no_new_insts",
  "tick": 12,
  "series": null,
  "step": null,
  "message": "沒有串在跑、也沒有串在等，再走一格也不會變。",
  "at": "2026-09-05T12:00:00.000Z",
  "ext": {"tick_ms": [83, 91, 77]}
}
```

## 崩了怎麼接

- **S-06-43** exec 在跑指令之前必須先寫一個空的 `.aos/ticks/<N>/started`，讓外面看得出這一格開跑過。〔主編補〕
- **S-06-44** exec 開頭發現上一格有 `started` 但接力棒的 `tick` 沒推（上次崩在半路）時：那一格的 `results/` 每筆都齊，就必須直接照這些結果判成敗、推游標，禁止重跑；只要有一筆不齊，就必須把那幾條串改成 `stopped`、原因寫 `crashed`。〔主編補〕

## 現況對照

今天的 `aos run` 沒有停止原因檔、沒有預算、沒有控制收件匣，停下來只留終端輸出；崩在半路沒有任何現場，重跑就是整批重來。今天也沒有「串在等」這個概念，所以沒有等結果時的睡法。
