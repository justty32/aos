# 04 指令格式
← [入口](README.md)

一筆指令（inst）是這台機器最底下、再也拆不開的一格。它就是「開一支程式、給它一組參數、等它結束」寫成 json。正本是 [`schemas/inst.schema.json`](schemas/inst.schema.json)；跑完寫出來的執行結果，正本是 [`schemas/result.schema.json`](schemas/result.schema.json)。

## 一筆指令是什麼

- **S-04-01** 一筆指令必須是一次 POSIX 呼叫的序列化，底下不再有更小的一格。〔裁決 2026-08-28〕
- **S-04-02** 步裡的 `inst` 物件與 `.aos/ticks/<N>/insts/<id>.json` 必須是同一個格式，用同一份 schema 驗。〔主編補〕
- **S-04-03** 指令必須有 `format_version`，第一版是整數 `1`。〔主編補〕

## 欄位

- **S-04-04** `argv` 必須是陣列且非空，禁止寫成一整條命令列字串；第 0 個元素是要跑的那支程式。〔裁決 2026-08-28〕
- **S-04-05** `id` 必填，同一格內必須唯一；同一格出現兩個一樣的 `id`，整格解析拒絕。〔主編補〕
- **S-04-06** `env` 是物件，鍵是變數名、值是字串；它必須蓋過繼承來的同名變數。〔主編補〕
- **S-04-07** `env_inherit` 是布林，格式裡必須有這個欄位（可省略，預設 `true`）；建議在原稿裡明寫 `false`，因為金鑰不該被自動帶進每一支子程式。〔預設 2026-09-05，I-07〕
- **S-04-08** `cwd` 省略時必須等於這塊地的根。〔主編補〕
- **S-04-09** `stdin`、`stdout`、`stderr` 必須是檔案路徑，禁止是管線；所以一格看得見、可重跑、崩了有現場。〔裁決 2026-08-28〕
- **S-04-10** 省略時的預設必須是：`stdin`＝`/dev/null`、`stdout`＝`.aos/ticks/<N>/results/<id>.stdout`、`stderr`＝`.aos/ticks/<N>/results/<id>.stderr`。〔主編補〕
- **S-04-11** exec 必須在開程式之前把這三個檔備好（父目錄不在就建）；備不出來必須算沒跑起來，寫進 `spawn_error`。〔主編補〕
- **S-04-12** `timeout_ms` 的預設由 run 那層給（`aos run --timeout`，預設 60000）；單筆只能寫得更短，寫得比 run 給的長必須整格解析拒絕，退出碼 `3`。〔預設 2026-09-05，F-06〕
- **S-04-13** 逾時禁止做在開程式那一層；必須由 run 那層剝掉、套在外面。〔裁決 2026-08-28〕
- **S-04-14** `footprint` 是 `{"reads":[…],"writes":[…]}`，兩個路徑陣列。第一版必須收下並存住，禁止拿它擋執行——宣告不強制。〔預設 2026-09-05，I-08〕
- **S-04-15** `exclusive` 是字串陣列；帶到同一個名字的兩筆指令禁止在同一格跑，後到的必須延到下一格。建議兩筆會寫同一個路徑的指令帶同一個名字。〔主編補〕
- **S-04-16** `ext` 是唯一可以放 spec 不認得的欄位的地方；`ext` 以外多一個欄位就必須拒絕，禁止默默忽略。〔裁決 2026-08-28〕
- **S-04-17** 格式禁止設任何上限（參數多長、環境變數幾個、吃多少記憶體）；資源界線用 `ulimit` 與 cgroup。〔裁決 2026-08-28〕
- **S-04-39** `footprint` 雖然不強制，但同一格裡兩筆指令**宣告的** `footprint.writes` 只要相交（同一條路徑，或一條是另一條的上層目錄），就必須整格解析拒絕，退出碼 `3`；沒宣告 `footprint` 的那筆，必須被當成只寫自己的 `AOS_TMP` 與 `stdout`／`stderr`。相交必須用正規化後的路徑比（相對路徑以這塊地的根為基準，`.` 與 `..` 先解掉；`{"b64":"…"}` 先解成位元組再比）。〔主編補〕

## 非 UTF-8 的逃生門

Linux 的檔名是位元組串，json 字串裝不下。所以有一個逃生門。

- **S-04-18** `argv` 的元素、`cwd`、`stdin`、`stdout`、`stderr`、`env` 的值，必須都可以寫成 `{"b64":"…"}`（base64 的原始位元組）。〔主編補〕
- **S-04-19** `{"b64":…}` 物件禁止有第二個鍵。〔主編補〕

## 四條白送的好處

argv 是陣列（S-04-04）、不認得就拒絕（S-04-16）、不設上限（S-04-17）、三條流是檔案（S-04-09）已經寫在上面。剩下四條也是規定。

- **S-04-20** 禁止為指令另外發明綁定層或介面描述語言；五十年的既有介面（argv、環境變數、三條流）白送，每種語言都已經會接。〔裁決 2026-08-28〕
- **S-04-21** 一筆指令崩掉必須只死它自己，禁止把 exec 或同一格其他指令帶走。〔裁決 2026-08-28〕
- **S-04-22** 一筆指令必須是一支真的行程，`ps`、`strace`、cgroup、訊號才現成可用。〔裁決 2026-08-28〕
- **S-04-23** 呼叫的邊界就是狀態的邊界：同一格裡的指令禁止看到彼此這一格的產出，要餵給下一步就得跨格。〔裁決 2026-09-01〕

## 嚴格解析、寬鬆執行

同一份東西，讀進來很嚴，跑起來很鬆。這是刻意的。

- **S-04-24** 讀：這一格要跑的全部指令必須一起驗，任一筆不合格整格都不跑，退出碼 `3`；訊息必須指出是哪一筆、哪個欄位。〔裁決 2026-08-28〕
- **S-04-25** 跑：某一筆結束碼非零、逾時、或找不到那支程式，禁止因此中止同一格其他指令。〔裁決 2026-08-28〕

## 三樣天生在界外

- **S-04-26** 這三樣禁止被寫成指令：共用記憶體、常駐服務、串流。開新程式會把記憶體整個換掉，所以「以呼叫者的記憶體為對象」的動作不可能是一筆指令。〔裁決 2026-08-28〕
- **S-04-27** 一次 LLM 呼叫禁止是一筆指令；要用 LLM 就投一筆請求給 LLM 世界（見 [09](09-llm-world.md)）。〔裁決 2026-09-05〕

## 兩個頻道

結束狀態拆成兩邊：跑沒跑起來，跟做成沒做成。

- **S-04-28** 執行結果檔必須只記傳輸層這四件事：沒跑起來（`spawn_error`）、被訊號殺（`signal`）、逾時（`timed_out`）、結束碼（`exit_code`）。〔裁決 2026-09-05〕
- **S-04-29** 執行結果檔禁止被當成「做成沒做成」的判定；那件事看步的 `expect` 檔或狀態檔，規則寫在 [05](05-series-format.md) 與 [06](06-exec-and-run.md)。〔裁決 2026-09-05〕

## 執行結果檔

- **S-04-30** 每筆指令必須寫一份 `.aos/ticks/<N>/results/<id>.json`，`id` 跟那筆指令一樣；必須在指令結束那一刻寫，且是原子寫（寫 `.tmp` → 刷檔 → 改名 → 刷目錄）。〔主編補〕
- **S-04-31** 根本沒跑起來的也必須寫一份：`exit_code` 與 `signal` 都是 `null`，`spawn_error` 寫原因。〔主編補〕
- **S-04-32** `exit_code` 與 `signal` 最多只准一個非 `null`；`timed_out` 是 `true` 時必須同時記下殺它的 `signal`。〔主編補〕
- **S-04-33** `stdout` 與 `stderr` 必須是路徑，禁止把輸出內容塞進結果檔。〔裁決 2026-08-28〕
- **S-04-34** `started_at` 與 `ended_at` 必須是 ISO 8601 UTC 含毫秒。〔主編補〕

## exec 給指令的環境變數

- **S-04-35** exec 必須給每筆指令這七個：`AOS_LAND`（這塊地的根）、`AOS_TICK`（格號）、`AOS_SERIES`（哪條串）、`AOS_FRAME`（堆疊框路徑）、`AOS_TMP`、`AOS_HOME`（家的路徑）、`AOS_LLM_WORLD`（LLM 世界的路徑，取自家的 `config.json` 的 `llm_world`，省略時＝`$AOS_HOME/.aos/llm`）。`env_inherit` 是 `false` 時指令一樣得知道家在哪，投給 LLM 世界也才有位址。〔裁決 2026-09-05〕
- **S-04-36** `AOS_TMP` 必須是 `.aos/ticks/<N>/tmp/<id>/`；指令跑完 exec 必須把它刪掉。〔主編補〕
- **S-04-37** 被呼叫的子地必須另外拿到 `AOS_RESULT`（父指定的結果落點）、`AOS_CALLER`（父地路徑），以及呼叫那步 `args` 展開出來的 `AOS_ARG_*`。〔主編補〕
- **S-04-38** 這幾個由 exec 最後套上；`env` 寫同名的鍵禁止蓋掉它們。〔主編補〕
- **S-04-41** 測試要切一個假家時，必須靠跑 `aos exec`／`aos run` 那支行程自己的 `$AOS_HOME`；指令的 `env` 禁止用來換家（S-04-38 已禁止蓋 `AOS_HOME`）。〔裁決 2026-09-05〕
- **S-04-40** 從收件匣直接跑、不屬於任何串的指令，`AOS_SERIES` 必須是空字串、`AOS_FRAME` 必須等於它的 `AOS_TMP`；這種指令禁止在 `.aos/frames/` 底下建任何東西。〔主編補〕

## 範例

一筆指令：

```json
{
  "format_version": 1,
  "id": "build-01",
  "argv": ["/usr/bin/make", "-C", "src", "all"],
  "env": { "CC": "clang" },
  "env_inherit": false,
  "cwd": ".",
  "stdout": "logs/build.log",
  "stderr": "logs/build.err",
  "timeout_ms": 30000,
  "footprint": { "reads": ["src"], "writes": ["logs"] },
  "exclusive": ["logs-build"],
  "ext": {}
}
```

它跑完的執行結果：

```json
{
  "format_version": 1,
  "id": "build-01",
  "started_at": "2026-09-05T12:00:00.000Z",
  "ended_at": "2026-09-05T12:00:03.250Z",
  "exit_code": 0,
  "signal": null,
  "timed_out": false,
  "spawn_error": null,
  "stdout": "logs/build.log",
  "stderr": "logs/build.err"
}
```

結束碼 `0` 只代表 make 跑起來也正常結束了。這次建置成不成，要看那一步的 `expect` 檔在不在。

## 待使用者拍板

〔預設〕三條：

- S-04-07〔I-07〕`env_inherit` 欄位一定要有，預設繼承，但建議關掉。
- S-04-12〔F-06〕`timeout_ms` 預設由 run 給，單筆只能更短，更長就解析拒絕。
- S-04-14〔I-08〕`footprint` 第一版只卡欄位，宣告不強制。

〔主編補〕條款：

- S-04-02 步裡的 `inst` 與落檔的指令同一格式。
- S-04-03 指令有 `format_version`。
- S-04-05 `id` 必填、同格唯一、撞了整格拒絕。
- S-04-06 `env` 蓋過繼承來的同名變數。
- S-04-08 `cwd` 省略＝這塊地的根。
- S-04-10 三條流省略時的預設路徑。
- S-04-11 三條流的檔備不出來算沒跑起來。
- S-04-15 `exclusive` 互斥組，後到的延到下一格。
- S-04-39 同格兩筆宣告的 `footprint.writes` 相交就整格拒跑；沒宣告的視為只寫自己的暫存與 `stdout`／`stderr`。
- S-04-18、S-04-19 非 UTF-8 的 `{"b64":"…"}` 逃生門與它的位置。
- S-04-30 執行結果檔的路徑、寫的時機、原子寫。
- S-04-31 沒跑起來也要寫一份結果檔。
- S-04-32 `exit_code` 與 `signal` 最多一個非 `null`。
- S-04-34 時間戳格式。
- S-04-36～S-04-38 `AOS_TMP` 跑完刪、`env` 蓋不掉它們。
- S-04-40 不屬於任何串的指令，`AOS_SERIES` 是空字串、`AOS_FRAME`＝`AOS_TMP`，不碰 `.aos/frames/`。

矛盾：ideas 09 章說「刻意不設任何上限」，同一章的檢查表又說收件匣要有背壓、指令要能宣告足跡。選了兩邊都留——S-04-17 只管指令格式本身不寫死常數，背壓與足跡是別的層的事（背壓在 [07](07-call-and-delivery.md)），因為「不設上限」講的是不要猜一個魔術數字，不是不准有邊界。

## 現況對照

今天的指令 json 有 `id`、`argv`、`env`、`cwd`、`stdin`、`timeout_ms`，但 `stdin` 裝的是內容不是檔案路徑，執行結果也把 stdout 與 stderr 的內容整段塞在 json 裡。今天沒有 `format_version`、`env_inherit`、`footprint`、`exclusive`、`ext`，環境變數一律繼承父行程。今天的結果檔只有 `exit` 與 `signal`，沒有 `timed_out` 與 `spawn_error`，所以「逾時」和「找不到程式」跟「跑了但回非零」混在一起，分不開兩個頻道。
