# 13 門房第一級
← [入口](README.md)

門房站在資料夾樹前面看檔案動靜。第一級只看不擋：收 Linux 的檔案變更通知（inotify），在本子記一筆，該更新登記表就更新，然後什麼都不做。

門房不是必要的。沒有它整套 aos 照常轉，只是發現一塊地死了要等 daemon 下一次對帳。

## 一、門房是什麼、住在哪

- **S-13-01** 門房必須是 aos 自己的一個子命令 `aos doorman`，不另外養一支程式。〔預設 2026-09-05，J-06〕
- **S-13-02** 禁止為門房引進第二種腳本語言，它的設定也禁止進任何一塊地的 `.aos/`。〔預設 2026-09-05，J-06〕
- **S-13-03** 門房底下必須是真正的目錄；門房只是蓋在真目錄上面看的一層。〔主編補〕
- **S-13-04** 門房掛掉禁止影響任何一塊地：所有地照樣被讀寫、時鐘照走、exec 照跑。〔主編補〕
- **S-13-05** 門房第一級必須用 inotify，禁止接管檔案系統。〔裁決 2026-09-04〕
- **S-13-06** 往下走的順序必須是 tmpfs → inotify → FUSE；FUSE 要做，但等真的需要「擋」才開工。〔裁決 2026-09-04〕
- **S-13-07** FUSE 建議不排進第一版；第一版只做本檔第二節那幾項。〔預設 2026-09-05，J-01〕

## 二、只記不做

門鈴歸門鈴，做菜歸做菜。門房被通知時只記一筆，`aos run` 照自己的節奏走。

- **S-13-08** 門房收到事件時必須只做兩件事：在本子記一筆、必要時更新登記表。〔預設 2026-09-05，J-03〕
- **S-13-09** 門房禁止推任何一塊地走一格、禁止跑指令、禁止改任何一塊地的 `.aos/`（登記表住在家，不算）。〔預設 2026-09-05，J-03〕
- **S-13-10** `aos run` 必須照自己的走法決定何時 exec，禁止被門房的事件直接推動。〔預設 2026-09-05，J-03〕
- **S-13-11** 門房的本子必須是 `$AOS_HOME/.aos/doorman.log`，一行一個 json（jsonl）。〔主編補〕
- **S-13-12** 本子每行必須過 [`doorman-log.schema.json`](schemas/doorman-log.schema.json)：`at`（ISO 8601 UTC 含毫秒）、`event`、`path`（真實路徑），加可選的 `ext`。〔主編補〕
- **S-13-13** `event` 必須用這幾個短代碼之一：`born`、`born_invalid`、`gone`、`write`、`inbox`、`fallback`。〔主編補〕

範例：`{"at":"2026-09-05T12:00:01.250Z","event":"write","path":"/home/u/work/plan/notes.md","ext":{"by_pid":4711}}`

## 三、第一級做哪幾項

- **S-13-14** 第一級必須先做偵測死亡與偵測出生，記帳第二個做。〔預設 2026-09-05，J-02〕
- **S-13-15** 門鈴叫醒與髒標記建議做，不做也合規。〔預設 2026-09-05，J-02〕

### 偵測死亡

- **S-13-16** 登記表裡某筆的 `path` 被刪或被搬走時，門房必須在本子記一筆 `gone`。〔裁決 2026-09-04〕
- **S-13-17** 路徑不在了但那筆的 `pid` 還活著時，必須先把那個行程停掉（孤魂補刀），再改登記表。〔裁決 2026-09-04〕
- **S-13-18** 停掉孤魂之後，必須把那筆的 `state` 改成 `"stopped"`、`pid` 改成 `null`，或整筆刪掉。〔主編補〕
- **S-13-19** 發現死亡必須有兩條路：門房通知是快路，daemon 定期對帳是保底；沒門房時只剩保底，也合規。〔裁決 2026-09-04〕
- **S-13-20** 禁止做「搬家通知」：搬走＝原地死掉、新位置生一個新的，門房看到一筆 `gone` 加一筆 `born`。〔裁決 2026-09-04〕

### 偵測出生

- **S-13-21** 新出現一塊地時，門房必須在本子記一筆 `born`。〔裁決 2026-09-04〕
- **S-13-22** 門房必須把新出生的地登記成 `state` 為 `"stopped"`，`pid`、`clock`、`parent` 都是 `null`。登成 `pending` 會被 daemon 起一支 run，跟父的同步呼叫撞成兩個時鐘。〔主編補〕
- **S-13-23** 門房禁止替新出生的地起時鐘；起時鐘仍然是父或使用者的動作。〔主編補〕
- **S-13-47** 門房必須只認一個出生事件：`.aos/layout.json` 以原子改名出現（inotify 的 `IN_MOVED_TO`）。〔主編補〕
- **S-13-48** 只建了 `.aos/` 目錄禁止當成出生；沒有那次改名就不是一塊地。〔主編補〕
- **S-13-49** `layout.json` 讀不到或不合它的 schema 時，門房禁止登記，必須在本子記一筆 `born_invalid`。〔主編補〕

### 記帳

- **S-13-24** 記帳必須記下誰、何時、寫了哪塊地的哪個檔，只寫進本子。〔預設 2026-09-05，J-02〕
- **S-13-25** 記帳禁止改變任何地的行為；它是資源計量的原始資料，不是控制訊號。〔預設 2026-09-05，J-03〕

### 門鈴（建議）

- **S-13-26** 建議在某塊地的 `.aos/inbox/` 出現新檔時，於本子記一筆 `inbox`。〔預設 2026-09-05，J-02〕
- **S-13-27** 建議讓 `aos run --every` 改成「本子有新事才做下一次 exec」，沒新事就繼續等。〔預設 2026-09-05，J-02〕
- **S-13-28** 通知必須先攢成一批，到下一格才一起處理；禁止一個通知推一次動作。〔預設 2026-09-05，J-03〕
- **S-13-50** 門鈴的收件人必須是 daemon，不是那塊地本身。門房記完本子就沒事了。〔主編補〕
- **S-13-51** 第一版 daemon 必須自己輪詢本子，建議 5 秒一次；門房禁止主動戳 daemon。〔主編補〕
- **S-13-52** daemon 從本子看到某地有 `inbox`、登記表那筆又不是 `running` 時，必須替它重起一支 run。〔主編補〕

### 髒標記（建議）

- **S-13-29** 建議在本子上標出這一段時間內有動過的地，讓 daemon 只推有動的地。〔預設 2026-09-05，J-02〕

## 四、監看範圍與上限

- **S-13-30** 門房必須監看登記表裡所有筆的 `path`，加上 `$AOS_HOME` 底下一層的子目錄（找新出生的地）。〔主編補〕
- **S-13-31** 門房禁止遞迴監看整棵樹；深處的地要被看見，必須先進登記表。〔主編補〕
- **S-13-32** 監看數量碰到系統上限時，門房必須記一筆 `fallback`，並退回定期巡邏。〔主編補〕
- **S-13-33** 退回巡邏時門房禁止直接結束；它必須繼續把生死結果寫進本子與登記表。〔主編補〕

## 五、門房與 daemon

- **S-13-34** 第一版的門房必須是獨立的子命令，不強迫跟 daemon 綁在同一支行程。〔主編補〕
- **S-13-35** daemon 要不要順手起一支門房，必須由旗標決定：`aos daemon start --doorman`。〔主編補〕
- **S-13-36** 沒有門房時，daemon 的定期對帳必須照樣清掉已死的登記。〔主編補〕
- **S-13-37** 門房與 daemon 都改登記表，兩邊必須走 `$AOS_HOME/.aos/registry.lock`，寫暫存 → 刷 → 改名。〔主編補〕

## 六、tmpfs

- **S-13-38** `.aos/` 放 tmpfs 必須只當實驗開關，預設仍然放在磁碟上。〔預設 2026-09-05，J-04〕
- **S-13-39** 開關必須是 `aos init --tmpfs`，開了就記在那塊地的 `.aos/layout.json` 的 `ext` 裡。〔主編補〕
- **S-13-40** 開這個開關的前提必須是載入器真的能從頂層原稿重建 `.aos/program/`；重建不回來就禁止開。〔預設 2026-09-05，J-04〕
- **S-13-41** 把接力棒這類動態狀態放 tmpfs 的人，必須接受「機器掛了這塊地從頭跑」。〔預設 2026-09-05，J-04〕
- **S-13-42** 頂層原稿禁止放 tmpfs；人寫的東西一律留在磁碟。〔主編補〕
- **S-13-53** 重開機後從原稿重建必須當成「從頭跑」：游標、收過的投遞 id、等中的呼叫全沒了，做過的副作用可能再做一次。〔主編補〕
- **S-13-54** `.aos/series.json`、`.aos/calls/`、`.aos/ticks/`、`.aos/frames/` 只要需要跨重開機活著，就禁止放 tmpfs。〔主編補〕

## 七、一格內凍結與自己人回寫

第一級不擋，現在沒有凍結。規則先寫著，做第二級時照用。

- **S-13-43** 第一級禁止延後或攔下任何寫入；一格之內凍結不在第一級。〔預設 2026-09-05，J-01〕
- **S-13-44** 將來做凍結時，正在被某個 `await` 步等的那個結果落點，寫進去必須直接落地，算自己人。〔預設 2026-09-05，J-05〕
- **S-13-45** 其餘所有寫入必須等到那一格結束才落地。〔預設 2026-09-05，J-05〕

## 八、第一塊要做的

- **S-13-46** 新實作的第一塊必須是門房第一級的偵測生死，加上成本帳的關口（帳簿那一關，見 [09](09-llm-world.md)）。〔預設 2026-09-05，M-03〕

## 九、以後

第二級是「擋」，那一級才要 FUSE：只有 aos 行程能寫 `.aos/`、一塊地真的看不到 `../`、一格之內凍結、配額、唯讀。前提是認得出敲門的是誰，FUSE 拿得到 pid 與 uid。

第三級是變出不存在的假檔案：虛擬檔現生、家的資料夾一 `ls` 就是登記表、LLM 世界變成寫進 prompt 就冒出回應的資料夾。

兩級都不寫成條款，開工再定。

## 現況對照

今天沒有門房，也沒有任何檔案事件通知；`run` 靠一遍遍翻磁碟發現變化。也沒有登記表，所以「發現一塊地死了」今天沒有人做。現有四個核心的 `.aos/` 暫存檔都在目標旁邊、改名不跨檔案系統，整棵放 tmpfs 是可行的。
