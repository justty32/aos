# 06 走一格與跑到底
← [入口](README.md)

`aos exec` 讓一塊地往前走一格就交回控制權。這份檔規定一格裡做哪些事、照什麼順序做，還有一格為什麼長不到哪裡去。`aos run` 怎麼走、怎麼停、崩了怎麼接在 [06b](06b-run-rules.md)；兩份檔共用一套 `S-06-NN` 編號。

## 一格是什麼

- **S-06-01** 一格必須恰好是一次 `aos exec`：走一步就交回，下一格要不要走由外面的時鐘決定。〔裁決 2026-09-04〕
- **S-06-02** 一格必須掃過這塊地上所有該動的串，禁止一格只推進一條串。〔裁決 2026-09-01〕
- **S-06-03** 同一格裡的指令之間禁止有資料流；前後銜接一律跨格。〔裁決 2026-09-01〕
- **S-06-04** 一筆指令禁止被切成兩格：預算必須只在原子邊界檢查，原子做完才收格。〔預設 2026-09-05，F-05〕

## 一格的精確順序

- **S-06-05** exec 必須照下面這十五步的順序做，禁止調換。〔主編補〕

1. **拿鎖**：以獨佔建檔（`O_EXCL`）建 `.aos/lock`，裡面寫自己的 `pid` 與 `pid_start`。檔已經在就先看持有者活著沒有：活著＝別人正在跑，退出 `75`；死了就收回鎖再拿；`.aos/` 這個目錄不在＝這裡不是一塊地，退出 `4`。
2. **接崩潰現場**：看上一格有沒有留下 `started`，處理法見 [06b](06b-run-rules.md) 的「崩了怎麼接」。
3. **讀接力棒** `.aos/series.json`。檔不在，或這支 run 的第一格而且這塊地閒著（所有串都是 `done`），才做一次**載入**：原稿編譯進 `.aos/program/`、依 `main` 模板開一條串、新產 `batch_id`、`tick` 從 `0` 起。跑到一半變閒著禁止重新載入。有 `failed`／`stopped` 的串不算閒著，等 `aos reset`。
4. **取件**：把 `.aos/inbox/` 裡已完成的投遞物一個個原子改名搬走。`inst` 併進這格；`mail` 搬到 `.aos/mail/`；`llm` 只有 LLM 世界收得。收不得的搬到 `.aos/inbox/rejected/`。
5. **讀控制收件匣**：看 `.aos/control/`。收到 `stop` 就把所有 `running` 串改成 `stopped`、寫停止原因檔（`stop_requested`）、信搬到 `done/`、寫回接力棒後放鎖，退出 `0`，這一格不跑指令。
6. **湊指令**：對每條 `running` 串取游標停的那一步，`inst` 步取出它的指令；在等的串在這裡看一次結果落點。同一個 `exclusive` 名下這格只留一筆。
7. **嚴格解析整格**：一筆欄位不合格、兩筆 `footprint.writes` 相交、落點撞在一起、或呼叫的落點三個檔已經有人在（見 [07b](07b-result-path.md)），整格都不跑，接力棒不改，退出 `3`。
8. **落檔**：指令寫進 `.aos/ticks/<N>/insts/<inst id>.json`，寫 `${…}` 替換完成後的樣子；同時寫一個空的 `.aos/ticks/<N>/started`。
9. **並行跑**：每筆指令起一個行程群組，建好它的 `.aos/ticks/<N>/tmp/<inst id>/`，套上 timeout。
10. **寫結果**：每筆寫一份 `.aos/ticks/<N>/results/<inst id>.json`。
11. **判成敗**：對每條串游標那一步，照 [05](05-series-format.md) 三種步各自的規則判成功、失敗、或這格不動。
12. **推游標**：成功走 `then`（或 `select` 讀出的步名），失敗走 `on_fail`；沒寫 `on_fail` 就 `status` 改 `failed`、停在原地。走到 `end` 改 `done`。
13. **呼叫步**：游標停在 `call` 步的串，第一次進入時寫一筆呼叫記錄。`sync` 在這一格內對子地做一次 `aos exec`，做完立刻判、該推就推；`async` 去登記表把子地登記成 `pending`，沒有 daemon 就這一步失敗、原因 `no_daemon`。
14. **收拾**：串跑完就刪它的 `.aos/frames/<串 id>/`，指令跑完就刪它的 `tmp/`；壞掉的兩樣都留著。
15. **收格**：`tick` 加一，接力棒寫暫存檔→刷→改名→刷目錄；刪 `.aos/lock`；交回。

- **S-06-06** 一塊地同時只准一支 exec 或 run；exec 正常結束、出錯結束都必須刪掉 `.aos/lock`。〔主編補〕
- **S-06-48** `.aos/lock` 的內容必須是 `{"pid":N,"pid_start":"…"}`。拿不到鎖時必須拿這兩個欄位檢查持有者還活著沒有：死了就收回鎖再拿，活著才退出 `75`。〔主編補〕
- **S-06-07** 載入必須只在接力棒不在或這塊地閒著時做；有 `running` 串時禁止重新載入。〔預設 2026-09-05，E-02〕
- **S-06-59** 載入必須只在「接力棒不在」或「這支 run 的第一格而且閒著」時做；一支 run 跑到一半變閒著，禁止因此重新載入，否則整批會從頭再跑一次。〔主編補〕
- **S-06-08** 取件必須用原子改名把投遞物搬出收件匣；`kind` 是 `"llm"` 的投遞物除了 LLM 世界以外，別的地必須當無效投遞。〔裁決 2026-09-05〕
- **S-06-09** 同一個 `exclusive` 名下的指令禁止在同一格跑，後到的必須延到下一格。〔主編補〕
- **S-06-52** 同一個 `exclusive` 名下誰先跑，必須照接力棒陣列裡串的順序決定；建議把上一格被延後的串排到陣列前面，免得餓死。〔主編補〕
- **S-06-10** 嚴格解析必須整格一起判：一筆不合格就整格不跑，禁止只跳過壞的那筆。〔主編補〕
- **S-06-41** 同一格裡兩筆指令宣告的 `footprint.writes` 相交時，必須整格拒跑並退出 `3`。〔主編補〕
- **S-06-61** 嚴格解析還必須查落點：同格所有落點（連 `.status.json`、`.usage.json`）兩兩相異，且這格要開的呼叫其三個檔都還不存在（見 [07b](07b-result-path.md) S-07-60～63）。違反任一項必須整格拒跑、退出 `3`。〔主編補〕
- **S-06-11** 落檔必須寫替換後的樣子，禁止把 `${…}` 原樣寫進 `.aos/ticks/<N>/insts/`。〔主編補〕
- **S-06-12** 推游標前判成敗必須看檔（結果落點在不在、狀態檔在不在），禁止拿結束碼當「做成沒做成」。〔裁決 2026-09-05〕
- **S-06-13** 只有那一步沒宣告 `expect` 時，才允許退而看結束碼 `0`／非 `0`；宣告了 `expect` 就禁止看結束碼。〔主編補〕
- **S-06-14** 串跑完的堆疊框與指令跑完的 `tmp/` 必須在推游標的同一步刪掉；壞掉的必須留著給人看。〔預設 2026-09-05，E-05〕
- **S-06-42** 在等的串的結果落點必須每格只在格頭取樣一次；格跑到一半才到的結果必須留到下一格才算數。〔主編補〕
- **S-06-50** 從收件匣直接跑、不屬於任何串的 `inst`，`AOS_SERIES` 必須是空字串、`AOS_FRAME` 必須等於它的 `AOS_TMP`；這種指令禁止在 `.aos/frames/` 底下建任何東西。〔主編補〕
- **S-06-40** 同一條串卡在同一步連續失敗三次，exec 必須把那條串改成 `stopped`、原因寫 `repeat_fail`；計數是串的 `fail_streak`（見 [05](05-series-format.md)），父的腳本禁止關掉這條。〔裁決 2026-09-05，數字之後可改〕
- **S-06-49** exec 判定一條串變成 `failed` 時，必須當場寫一份 `.aos/stopped.json`：`reason` 寫 `failed`，`series` 與 `step` 填那條串與那一步，細一點的代碼放 `detail`。〔主編補〕

## 這格有沒有產出新指令

- **S-06-15** 「這格產出了新指令」必須定義成兩件事的其中之一：這格湊出來的指令集合非空，或有任何一條串的游標動了。兩件都沒有就是沒產出。〔主編補〕
但這塊地已經閒著時，閒著贏過「游標動了」——見 [06b](06b-run-rules.md) 的 S-06-58。

## 一格的長度要有界

- **S-06-26** 讓一格有界的主方法必須是環境限制：`.aos/config.json` 的 `path` 陣列決定這塊地的指令能從哪裡找。〔裁決 2026-09-04〕
- **S-06-27** `path` 上找不到的指令必須寫成 `spawn_error` 落進執行結果檔，讓失敗看得見；禁止悄悄跳過。〔預設 2026-09-05，F-04〕
- **S-06-51** `env_inherit` 是 `false` 而且 `.aos/config.json` 的 `path` 是空的時候，PATH 必須保底給 `/usr/bin:/bin`，禁止交出一個空的 PATH。〔主編補〕
- **S-06-28** timeout 只能當保險絲，禁止當成主線：預設開，`--timeout` 預設 `60000` 毫秒，`.aos/config.json` 的 `inst_timeout_ms` 可以覆蓋，單筆指令的 `timeout_ms` 只能比它更短、不能更長。run 必須把算好的上限用 `aos exec --timeout <ms>` 交給 exec；直接打 `aos exec` 沒給旗標就用 `inst_timeout_ms`，再沒有就 `60000`。〔預設 2026-09-05，F-06〕
- **S-06-45** `--timeout` 禁止給 `0`，也禁止給「不限」。一格的最長時間必須算成這格各筆 timeout 裡最大的那一個（它們並行），不是全部加起來。〔主編補〕
- **S-06-29** 逾時必須殺掉那筆指令的整個行程群組，並把 `timed_out` 寫成真。〔主編補〕
- **S-06-30** 時間禁止進入世界語意：`--every <ms>` 只是走格的節奏，不是給程式讀的輸入。〔裁決 2026-08-26〕
- **S-06-25** 建議把每一格花了多少毫秒記進 `.aos/stopped.json` 的 `ext`；一格有多長的正本是 `.aos/ticks/<N>/results/` 裡每筆的 `started_at` 與 `ended_at`。〔主編補〕

## 子地：借鐘與自己有鐘

- **S-06-60** `call` 步的呼叫記錄必須只在第一次進入時寫一筆。`sync` 必須在同一格內對子地做一次 `aos exec` 並做一次三態判定（沒好就停原地）；`async` 必須去登記表把子地登記成 `pending`，沒有 daemon 時這一步必須失敗、原因寫 `no_daemon`。〔主編補〕
- **S-06-31** 同步呼叫必須是「父每一格對子地做一次 `aos exec`」：子還沒閒著，父的這一步就停在原地，而且不算失敗；子閒著之後才照三態判成敗。〔主編補〕
- **S-06-32** 同步子地的整棵樹裡禁止有 LLM 呼叫；要用 LLM 就投一筆請求給 LLM 世界，那條路一定是脫節的。〔裁決 2026-09-05〕
- **S-06-33** 脫節子地必須自己有一顆登記過的時鐘，父的那一格禁止等它；父每格看父自己指定的結果落點在不在。〔裁決 2026-09-04〕

## 原稿改了什麼時候算數

- **S-06-34** 一批跑到一半原稿被改，這一批必須不理它；下一次載入才重讀。〔裁決 2026-09-05〕
- **S-06-35** 要讓改過的原稿立刻生效，必須先 `aos reset` 讓這塊地回到閒著，再跑。〔裁決 2026-09-05〕

## 現況對照

今天沒有 `aos exec` 子命令，走一格最接近 `aos run --step 1`；沒有接力棒，一格跑什麼是每次從收件匣現湊的。也沒有 `.aos/lock`、沒有 `started` 這種崩潰現場、沒有依地限 `PATH`；timeout 已經是整個行程群組殺，但它是主線不是保險絲。
