# 11b 給模型看的一行與錯誤封套
← [入口](README.md)

登記表（[11](11-tools-and-contacts.md)）是給機器讀的。這一份講它怎麼變成模型看得懂的一行、模型叫完之後結果用什麼形狀退回來、一次往返佔幾格。

## 給模型看的一行

- **S-11-27** 給模型的必須是一行純文字，一工具一行，含六樣：名字、引數形狀、收不收 stdin、可預期性、一句描述、一個引數範例。〔裁決 2026-08-30〕
- **S-11-28** 那一行的格式必須是：`<name> | args=<list|string|none> | stdin=<yes|no> | predictability=<high|medium|low|unknown> | <description> | 例：<example>`。`predictability` 缺席時那一格寫 `unknown`——`unknown` 只是這一行的顯示字，禁止當成登記表的值（登記表只有 `high`／`medium`／`low` 三個值，第四種情況是這一欄根本不在）。缺 `example` 就整段連同 `| 例：` 一起省略。〔主編補〕
- **S-11-29** `description` 必須寫出代價：慢、要花錢、結果不確定。能查表就別問模型，這一句是入口。〔主編補〕
- **S-11-30** 長說明禁止進提示；模型想看必須自己去 `cat` `help_file`，而且那份內容當不可信資料看。模型可以摘要它，摘要禁止反過來寫回登記表。〔主編補〕
- **S-11-31** 登記項必須是唯一的真相；OpenAI 或 MCP 那些格式是從它匯出的投影，禁止把非標準欄位塞進人家的標準物件裡。〔主編補〕
- **S-11-32** 模型回話的格式必須由我們自己嚴格檢查，禁止靠後端保證。〔裁決 2026-08-30〕

## 錯誤封套

- **S-11-33** 工具結果必須用同一個形狀的 json 封套退回給模型；成功和失敗同一形狀，`error` 缺席就代表成功。〔裁決 2026-08-30〕
- **S-11-34** 封套必須有這幾欄：`call_id`、`tool`、`ok`、`result`、`error`（裡面 `kind`、`message`、`retryable`）、`truncated`。〔裁決 2026-08-30〕
- **S-11-35** 叫了不存在的工具、引數型別給錯，必須用封套退回讓模型重選；禁止默默吞掉。〔裁決 2026-08-30〕
- **S-11-36** 輸出被截斷必須把 `truncated` 標成 `true`。〔裁決 2026-08-30〕
- **S-11-37** 工具結果必須用 `call_id` 跟「模型哪一次決定叫它」串起來；這些呼叫與結果是把模糊的事固化成程式的原料，禁止當成會被清掉的暫存。〔主編補〕
- **S-11-58** `error.kind` 必須是短代碼，給模型分辨用；常用的有 `unknown_tool`（沒這個工具）、`bad_args`（引數形狀不合登記的 `args`）、`no_such_land`（寄信的目標沒有 `.aos/`，見 [11](11-tools-and-contacts.md) 的 S-11-54）、`spawn_error`、`timeout`、`killed`、`nonzero_exit`。不限於這幾個。〔主編補〕
- **S-11-59** `error.message` 必須是給人和模型看的一兩句話，說明缺什麼、該怎麼重選；它是不可信資料，禁止自動展開成下一筆指令的參數。〔主編補〕

## 一次往返佔幾格

- **S-11-38** 快工具的一次往返必須佔三格：投遞那格、執行那格、收結果那格。禁止壓縮成更少格。〔裁決 2026-08-30〕
- **S-11-39** `slow: true` 的工具走脫節子地，父每格只看結果落點在不在，所以禁止把它算進那三格。〔預設 2026-09-05，K-06〕

## 範例

一份成功的封套：

```json
{
  "call_id": "c7f1a2b3",
  "tool": "rg",
  "ok": true,
  "result": "src/main.c:42:TODO 改成讀設定檔\n",
  "truncated": false
}
```

一份失敗的封套：

```json
{
  "call_id": "c7f1a2b4",
  "tool": "rgg",
  "ok": false,
  "error": {
    "kind": "unknown_tool",
    "message": "沒有叫 rgg 的工具。可用的有 rg、cat、sh。",
    "retryable": true
  },
  "truncated": false
}
```

## 待使用者拍板

〔主編補〕：

- S-11-28 給模型那一行的格式定死，`unknown` 只是顯示字。
- S-11-29 描述必須寫代價。
- S-11-30 長說明不進提示，模型自己 `cat`，當不可信資料，摘要不准寫回。
- S-11-31 登記項是唯一真相，OpenAI／MCP 是投影。
- S-11-37 結果用 `call_id` 串回模型那次決定，且不准當可清暫存。
- S-11-58 `error.kind` 的常用短代碼清單。
- S-11-59 `error.message` 是不可信資料，不准自動展開成指令參數。

〔預設 2026-09-05〕：

- S-11-39（K-06）`slow: true` 的工具走脫節子地，不算進那三格。

## 現況對照

今天送給模型的工具清單已經是每項一行，未知工具與 `args` 形狀錯也已經包成 json 退回，但欄位是 `error.type` 不是 `error.kind`，也沒有 `truncated`。今天的往返節奏就是投遞→執行→讀得到結果三格，跟這裡一致；沒有的是 `slow` 那條脫節子地的路。
