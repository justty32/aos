# 11 工具登記表與通訊錄
← [入口](README.md)

模型要做事只有兩個對象：**程式**和**別的 agent**。程式那份名單叫工具登記表，agent 那份叫通訊錄，是分開的兩樣東西。這一份講這兩份名單怎麼寫、怎麼維護。怎麼講給模型聽、結果怎麼回來，見 [11b](11b-tool-envelope.md)；誰去跑、跑多久見 [06](06-exec-and-run.md) 與 [07](07-call-and-delivery.md)。

## 什麼算工具

- **S-11-01** 能用 POSIX 方式叫得動的程式（給一串引數、餵 stdin、看 stdout 和結束碼）必須都可以登記成工具。〔裁決 2026-08-30〕
- **S-11-02** 一個可執行檔必須算一個工具；命令列引數就是它的引數，stdin／stdout／stderr 是特殊引數，來往的東西全是文字。〔裁決 2026-08-06〕
- **S-11-03** 模型只准叫登記表裡有的工具；要跑沒登記的普通指令，必須經由已登記的 `sh` 這類工具。〔裁決 2026-08-06〕
- **S-11-04** 禁止掃系統 PATH 自動登記；登記必須是人的動作。〔主編補〕
- **S-11-05** 子 agent 禁止登記成工具；找 agent 走通訊錄。〔裁決 2026-08-30〕
- **S-11-53** 禁止把 `aos llm`、或任何自己直接打 LLM 後端的程式登記成工具；`aos tool add` 與 `aos check` 都必須擋下來。要用 LLM 一律投一筆請求給 LLM 世界（見 [09](09-llm-world.md)），繞過去就繞過了並行上限、處理單元表與帳簿。〔主編補〕

## 登記表

- **S-11-06** 一工具必須一個檔，路徑 `.aos/tools/<名>.json`，檔裡的 `name` 必須等於檔名。〔裁決 2026-08-30〕
- **S-11-07** 登記表必須住世界那一層，禁止放在單隻 agent 底下：工具是這塊地的，agent 只是使用者。〔裁決 2026-08-30〕
- **S-11-08** 必須填的只有三欄：`name`、`command`、`description`；其餘一律選填。〔裁決 2026-08-30〕
- **S-11-09** 其餘欄位必須平鋪在同一層，禁止分組巢狀；不認得的欄位一律拒絕，唯一放得下它們的地方是具名擴充區 `ext`。〔裁決 2026-08-30〕
- **S-11-10** `args` 必須三選一：`"list"`＝逐項接在 `command` 後面，空白與引號原樣保留、不經 shell；`"string"`＝整段當一個參數，只給 `sh` 這種；`"none"`＝不收引數。〔裁決 2026-08-30〕
- **S-11-11** 禁止做 `{名字}` 這種具名槽。〔裁決 2026-08-30〕
- **S-11-12** 禁止再有 agent 底下的工具白名單；只留世界層這一份登記表。〔預設 2026-09-05，K-01〕
- **S-11-13** `aos tool add` 必須用 `--metainfo` 去探自我介紹；只有登記的人明確開了，才准再用 `--metadata` 試一次。〔裁決 2026-08-30〕
- **S-11-14** 同一欄有多個來源時必須：人手填的贏自述、自述贏預設；每欄的來源記在 `filled_by`。〔主編補〕
- **S-11-15** 禁止把「沒自述」推論成「安全」。沒說就是不知道。〔主編補〕
- **S-11-16** 有狀態的工具，狀態必須放它自己的地方；禁止塞進 `.aos/`。〔主編補〕
- **S-11-17** `.aos/tools/` 與 `.aos/contacts.json` 必須留在 `.aos/` 裡、必須進 git；人禁止手改，只透過 `aos tool` 與 `aos contact` 寫。這兩樣是靜態設定，不是機器跑出來的狀態。〔主編補〕

## 可預期性

- **S-11-18** `predictability` 指的必須是「結果符不符合人的預期」，禁止讀成「同樣輸入給同樣輸出」。〔裁決 2026-08-30〕
- **S-11-19** 值只有 `"high"`／`"medium"`／`"low"` 三級；缺席＝不知道，禁止當成 `"high"`。〔裁決 2026-08-30〕
- **S-11-20** 禁止強制 LLM 類的工具標 `"low"`；填不填由登記的人決定。〔裁決 2026-08-30〕
- **S-11-21** 禁止做「發證、憑證才准進、可以撤照」那一層；那是另一本帳。〔主編補〕

## 誰讀哪幾欄

- **S-11-22** 第一版的圈唯一會讀的登記表欄位必須是 `slow`。`repeat_safe`、`leaves_trace`、`interruptible`、`output` 一律保留、無消費者，禁止拿它們改變任何行為。〔主編補〕
- **S-11-23** 這幾欄之後要拉起來用，第一個必須是 `repeat_safe`。〔預設 2026-09-05，K-02〕
- **S-11-24** `output` 這欄必須留著、先不用；等大輸出真的出現才拿它決定走內嵌還是走檔案。〔預設 2026-09-05，K-05〕
- **S-11-25** `slow` 必須由登記的人自己填；沒填當快的，跑到逾時再由人改登記。〔預設 2026-09-05，K-06〕
- **S-11-26** `slow: true` 的工具必須由 agent 開一塊脫節子地去跑（見 [10](10-agent.md)）。〔預設 2026-09-05，K-06〕

## 工作目錄

- **S-11-56** 工具跑起來的工作目錄預設必須是**呼叫它的那塊地的根**；禁止用家、也禁止用世界根。登記表住世界層，不代表工具就從世界根開始看東西；一塊地只看得到自己地上的東西。〔主編補〕
- **S-11-57** 登記表的 `cwd` 欄只能是那塊地之內的相對路徑；絕對路徑、或會跳出去的 `..`，`aos tool add` 與 `aos check` 都必須拒絕。〔主編補〕

## 危險工具

- **S-11-40** 危險工具的安全第一版必須不做：把 `sh` 登記給模型，就等於信任啟動這個圈的人。〔裁決 2026-08-30〕
- **S-11-41** 白名單禁止宣稱它提供安全。要交給非開發者用的那天，再加「投遞前先問人」那一層。〔主編補〕

## 通訊錄

通訊錄只回答一個問題：某某人住在哪個資料夾。它不是登記表、不是白名單、不是權限。

- **S-11-42** 通訊錄必須是 `.aos/contacts.json`，頂層就是一個陣列，每列三欄 `name`、`path`、`note`（`note` 選填）。〔預設 2026-09-05，K-03〕
- **S-11-43** 通訊錄必須手動維護；開一塊地時禁止動它。〔裁決 2026-08-30〕
- **S-11-44** `~` 那一格禁止落檔，讀的時候合成出來；它就是使用者，使用者也是一隻 agent。〔裁決 2026-08-30〕
- **S-11-45** 權威必須是對方那個資料夾自己存不存在；通訊錄只是省一趟路的快取，允許過期。〔主編補〕
- **S-11-46** 「寄信給某某」必須是登記表裡的一條工具，它做的事＝`aos deliver` 一封 `mail` 到那個資料夾的收件匣；通訊錄只回答他在哪。〔主編補〕
- **S-11-54** 這條工具禁止建目錄。目標資料夾不存在、或存在但裡面沒有 `.aos/`，必須直接失敗，封套的 `error.kind` 是 `"no_such_land"`。沒有 `.aos/` 的資料夾一律不是一塊地；`mkdir` 出來的假地會騙過門房的「偵測出生」。〔主編補〕
- **S-11-55** 這種失敗的 `error.message` 必須寫出是通訊錄裡的哪一列指到哪個路徑，並要求人用 `aos contact add` 更新；禁止靜默失敗。〔主編補〕
- **S-11-47** 處理單元的位址禁止進通訊錄；那是引擎設定，混進來會分不清對方是人還是一顆處理單元。〔主編補〕
- **S-11-48** 子 agent 必須用自己的設定，禁止繼承父的；否則通訊錄會偷偷變成權限與執行設定。〔主編補〕

## 兩支子命令

細表在 [12](12-cli.md)，這裡只講跟這兩份名單有關的行為。

- **S-11-49** `aos tool add <名> -- <argv…>` 必須先驗 `argv[0]` 叫得動（含 `/` 就查那個檔，否則搜 PATH），叫不動就不登記。旗標 `--description`、`--args`、`--stdin`、`--predictability`、`--slow`、`--example`、`--help-file`、`--cwd` 算人手填，在 `filled_by` 記 `"human"`；探到的記 `"probe"`；`--no-probe` 不探。〔主編補〕
- **S-11-50** `aos tool ls` 必須有給人看的表與 `--json`；`aos tool rm <名>` 刪那個檔；讀登記表遇到壞檔必須整次報錯，禁止安靜略過。〔主編補〕
- **S-11-51** `aos contact add <名> <資料夾> [--note …]`、`ls`、`rm <名>` 必須只改 `.aos/contacts.json`，同名視為取代，`ls` 把合成的 `~` 排最前面。〔主編補〕
- **S-11-52** 這兩支寫檔必須用寫暫存→刷→改名，跟其他寫者同一套。〔主編補〕

## 範例

一份工具檔 `.aos/tools/rg.json`：

```json
{
  "format_version": 1,
  "name": "rg",
  "command": ["rg", "--line-number", "--no-heading"],
  "description": "在這塊地裡搜字串，很快、不花錢、只讀不寫。",
  "args": "list",
  "stdin": false,
  "predictability": "high",
  "slow": false,
  "cwd": "src",
  "output": { "kind": "text" },
  "repeat_safe": true,
  "leaves_trace": false,
  "interruptible": true,
  "example": "TODO src/",
  "help_file": "docs/rg.txt",
  "filled_by": { "description": "human", "predictability": "human" }
}
```

一份通訊錄 `.aos/contacts.json`：

```json
[
  { "name": "planner", "path": "agents/planner", "note": "排工作的那隻" },
  { "name": "archivist", "path": "/srv/aos/archivist" }
]
```

## 待使用者拍板

〔主編補〕：

- S-11-04 不掃 PATH，登記是人的動作。
- S-11-14 多來源：人填贏自述、自述贏預設，記在 `filled_by`。
- S-11-15 沒自述不准推論成安全。
- S-11-16 工具的狀態不准塞 `.aos/`。
- S-11-17 兩份名單留 `.aos/`、進 git、只透過子命令寫（主編裁的矛盾 #1）。
- S-11-21 不做工具發證與撤照那一層。
- S-11-22 **改寫 K-02**：第一版的圈只讀 `slow`，其餘欄位保留、無消費者。原本 K-02 說「一欄都不讀」，那樣 K-06 的 `slow` 就是死的。
- S-11-41 白名單不准宣稱安全。
- S-11-45 權威是對方資料夾存不存在，通訊錄只是快取。
- S-11-46 寄信是登記表裡的一條工具，做的事＝`aos deliver` 一封 `mail`。
- S-11-47 處理單元位址不進通訊錄。
- S-11-48 子 agent 不繼承父的設定。
- S-11-49～52 兩支子命令的引數與寫檔行為。
- S-11-53 禁止登記 `aos llm` 或任何直接打 LLM 後端的程式，`aos tool add` 與 `aos check` 都擋。
- S-11-54、55 寄信絕不建目錄；目標沒 `.aos/` 就失敗 `no_such_land`，訊息要人去更新通訊錄。
- S-11-56、57 工具的工作目錄＝呼叫它的那塊地；登記表 `cwd` 只能是地內相對路徑。

〔預設 2026-09-05〕：

- S-11-12（K-01）拿掉 agent 底下的工具白名單。
- S-11-23（K-02）之後要讀，第一個是 `repeat_safe`。
- S-11-24（K-05）`output` 留欄先不用。
- S-11-25、26（K-06）`slow` 由登記者填，沒填當快，`slow: true` 走脫節子地。
- S-11-42（K-03）通訊錄頂層是陣列，每列三欄。

矛盾：通訊錄與封套沒有 `format_version`，跟「每份頂層文件都要有」那條打架。選了照 K-03 與封套的形狀走：通訊錄頂層是陣列放不下這一欄，封套又不落檔、只是塞進提示的一段文字。要換版本時通訊錄靠 `aos contact` 一次改寫全檔。
