# 12b 核心名冊與正本規範
← [入口](README.md)

從 [12 指令面](12-cli.md) 拆出來，編號接著同一串。這裡講：exec／run／daemon 三層、我們自己要寫哪幾支程式、規範以哪一份為準、版本欄與升級、`aos init` 與 `aos reset`、裁決怎麼回寫。

## 三層各一個名字

- **S-12-06** `aos exec` 必須是「讓一塊地走一步」，做完就交回。〔裁決 2026-09-03〕
- **S-12-07** `aos run` 必須是「反覆走到不再有新事可做」。〔裁決 2026-09-03〕
- **S-12-08** daemon 必須是最外面那圈常駐的，管所有正在走的地。〔裁決 2026-09-03〕
- **S-12-09** `aos exec` 是唯一入口，但這支程式裡禁止出現 LLM 的程式碼、金鑰或連線；行程邊界就是隔離邊界。〔裁決 2026-08-24〕
- **S-12-10** LLM 只准出現在 `aos llm` 與 LLM 世界（見 [09](09-llm-world.md)）；其他子命令要用 LLM 必須投一筆請求過去。〔裁決 2026-09-05〕

## 核心名冊六支

核心是我們自己要寫的那幾支小程式，要幾支從協定推出來、不憑感覺加。

- **S-12-24** 核心名冊必須恰好六支：執行（exec）、迴圈（run）、投遞（deliver）、看狀態（status）、修復（fix）、驗證（check）。〔預設 2026-09-05，L-02〕
- **S-12-25** 加第七支必須先過封閉判準：每個協定步驟一支、每種靜態狀態一看一修、每份規範一支驗證器。〔預設 2026-09-05，L-02〕
- **S-12-67** `migrate`、`publish`、`daemon add`、`llm serve`、`llm ask` 這些子命令必須歸指令面，不算核心名冊的第七支；名冊數的是核心要有的能力，不是子命令數。〔主編補〕
- **S-12-26** agent 那五支（`agent init`、`say`、`listen`、`talk`、`state`）必須歸指令面；禁止進核心。〔預設 2026-09-05，L-02〕
- **S-12-27** `say` 與 `listen` 必須能單獨用，`talk` 是這兩支合成出來的。〔裁決 2026-08-30〕
- **S-12-28** 核心必須切四圈：①執行單筆指令 ②反覆取指的迴圈 ③彙整（用注入的方式跟迴圈配合）④外面不再包一圈。〔裁決 2026-08-27〕
- **S-12-29** 逾時必須由迴圈那圈在核心讀到它之前先剝掉並自己套用；禁止放進最裡面那圈。〔裁決 2026-08-28〕
- **S-12-30** 六支與四圈必須當成兩份表：六支問「要寫哪幾支程式」，四圈問「程式碼怎麼分家」；`deliver` 在名冊上，但是普通程式、不占一圈。〔主編補〕

## 正本與版本欄

- **S-12-31** 這疊 spec 與 `schemas/` 必須是正本；parser、文件、給 LLM 的說明全部從它派生。〔預設 2026-09-05，L-03〕
- **S-12-32** `aos check` 必須是那支驗證器：驗 `.aos/` 版面對不對、每個 json 過不過它的 schema、版本欄認不認得。〔預設 2026-09-05，L-03〕
- **S-12-33** `aos check` 禁止寫任何檔；要動手修的是 `aos fix`。〔主編補〕
- **S-12-34** 版面版本必須放 `.aos/layout.json` 的 `layout_version`。〔預設 2026-09-05，L-04〕
- **S-12-35** 格式版本必須放各份 json 自己的 `format_version`；兩個版本欄是兩件事，禁止合成一個。〔預設 2026-09-05，L-04〕
- **S-12-36** 兩個版本欄必須都是整數、只往上加。〔預設 2026-09-05，L-04〕
- **S-12-37** 讀到不認得的 `layout_version` 或 `format_version` 必須退出 3，禁止猜著往下跑；升級的唯一途徑是 `aos migrate`（S-12-49、S-12-50）。〔預設 2026-09-05，L-04〕
- **S-12-49** `aos migrate <地>` 第一版必須只印一行「版面版本 X→Y 需要人工處理」並退出 0；禁止自動改任何檔。〔主編補〕
- **S-12-50** 除了 `aos migrate` 與 `aos check`，任何子命令讀到 `layout_version` 不是本版就必須拒跑並退出 3；禁止自動升級或忽略。〔主編補〕
- **S-12-38** `.aos/` 底下每條路徑必須有唯一一個 writer；有兩個 writer 的路徑就是損壞點。歸屬表在 [02](02-layout.md)。〔主編補〕

## `aos init`

- **S-12-11** `aos init` 必須建 `.aos/layout.json`、`.aos/config.json` 範本、`.gitignore` 片段。〔預設 2026-09-05，L-01〕
- **S-12-12** `aos init` 禁止建空的 `.aos/series.json`；接力棒由載入器在第一次被 exec 時才建。〔預設 2026-09-05，L-01〕
- **S-12-13** `pu` 禁止當子命令；「一個資料夾就是一顆處理單元」這個意思保留為概念，指令一律用 exec／run／daemon。〔預設 2026-09-05，L-01〕
- **S-12-14** `.gitignore` 片段的內容必須由這份 spec 定，地不能自己改。〔預設 2026-09-05，C-05〕

## `aos reset`

- **S-12-15** `aos reset <地>` 必須把接力棒裡 `failed` 與 `stopped` 的串清掉，`--all` 則整份接力棒刪掉；下一次 exec 重新載入原稿、開新的一批。〔主編補〕
- **S-12-16** `aos reset` 禁止動頂層的任何檔。〔主編補〕
- **S-12-17** `.aos/lock` 被佔著（有 exec 或 run 在跑）時 `aos reset` 必須拒絕並退出 75。〔主編補〕

## 回寫鐵律

- **S-12-39** 實作閉合必須在同一個 commit 回寫規範；只約束裁決與規範，一般實作細節不強制。〔預設 2026-09-05，L-06〕
- **S-12-40** 實作中被迫下的新裁決必須當成正式裁決回寫。〔裁決 2026-08-28〕
- **S-12-41** 方向性的裁決屬於使用者；禁止代裁，只能擺出選項與後果。〔裁決 2026-08-30〕
- **S-12-42** 新裁決進正本的做法必須是：改對應那份 spec 檔的條款、句尾標〔裁決 日期〕、跟實作同一個 commit。〔預設 2026-09-05，L-06〕
- **S-12-43** 「為什麼選 A 不選 B」必須寫進判例記錄，禁止另存一份表。〔裁決 2026-08-30〕

## 待使用者拍板

- S-12-24～26 核心六支、封閉判準、agent 五支不進核心。〔預設，L-02〕
- S-12-30 六支與四圈是兩份表，`deliver` 不占一圈。〔主編補〕
- S-12-67 `migrate`／`publish`／`daemon add`／`llm serve`／`llm ask` 屬指令面，不算第七支。〔主編補〕
- S-12-31～37 正本是這疊 spec 與 schemas、`check` 是驗證器、兩個版本欄、不認得退 3。〔預設，L-03／L-04〕
- S-12-33 `check` 只讀不寫。〔主編補〕
- S-12-38 每條路徑唯一 writer。〔主編補〕
- S-12-49～50 `aos migrate` 第一版只印訊息，版面版本不合一律退 3。〔主編補〕
- S-12-11～14 `init` 建哪幾樣、不建空接力棒、撤回 `pu`、`.gitignore` 由規範定。〔預設，L-01／C-05〕
- S-12-15～17 `reset` 的語意、不動頂層、鎖被佔退 75。〔主編補〕
- S-12-39、42 回寫鐵律與新裁決進正本的流程。〔預設，L-06〕
- 矛盾：2026-08-27 裁「`deliver` 除非很核心否則當普通指令做」，但封閉判準把「投遞」列成六支之一。選了兩邊都成立：進名冊、不進四圈（S-12-30），因為兩張表判準不同。

## 現況對照

今天核心底下有執行、迴圈、tick、wire、agent、llm、tool，沒有「彙整」那圈，agent 整套在核心裡；看狀態、修復、驗證三支都不存在。正本規範也不存在：規格、實作文件、手寫的 parser 三份真相各自漂移，兩個版本欄一個都沒有，也沒有 `aos migrate` 與 `aos reset`。
