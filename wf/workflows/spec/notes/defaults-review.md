## 我會挑出來請使用者改的（12 條）

- **E-04**：`_comment` 不是丟掉，而是**原樣抄進中間表示**——不然出事時看接力棒完全不知道這串在幹嘛（邊 L06）。
- **F-03**：除了門鈴，還得補一種「閒著也不停、掛著等信」的走法（`--until never`），LLM 世界正需要；門鈴的收件人要是 daemon 不是那塊地，否則信落地時 run 已經死了（F 原型 run 段、邊 B12）。
- **F-04**：慢不慢改成**登記工具的人自己標**，而且第一版就讀那一欄——原本說「後補的糖」，但 agent 要靠它決定原地跑還是開脫節子地（邊 S16）。
- **F-07**：「查登記表」只對地成立；**一筆 LLM 請求不是地**，查不到。要給請求一個看得到的狀態（排隊中／送出中／好了／壞了）（邊 B03）。
- **G-06**：並行上限**不再由 daemon 數**——LLM 已經是單獨一個世界，讓它自己數 in-flight；daemon 只保證那支 run 活著。兩邊都數會變成雙重限流或兩邊都不管（邊 S05）。
- **H-03**：三個上限留著，但**總時限改成格數**（父的鐘停三天，agent 一醒來就被牆鐘判死），**token 上限對 agent 自己地上的用量檔判**（token 數只有 LLM 世界知道，不改就等於沒設）（邊 L02、B19）。
- **I-07**：環境變數**預設改成不繼承**——原本「預設繼承、但文件建議關」等於預設就是不建議的那個，金鑰會被帶進每一支子程式；同時要明訂關掉之後的保底 PATH（FINDINGS 核心段）。
- **I-08**：足跡照樣不強制，但**同一格裡兩筆指令宣告要寫同一個檔就整格拒跑**——不然誰後寫誰贏，直接打到「可預測性最優先」（邊 S08）。
- **J-05**：脫節回寫可以隨時落地，但**父每格只在格頭看一次**——不然同一格前後看到兩個世界，「一格＝一筆交易」破功（邊 S09）。
- **K-02**：「第一版一欄都不讀」改成**只讀 `slow` 那一欄**，其餘保留無消費者——不改的話 K-06 那一欄是死的（邊 S16）。
- **K-04**：`aos llm` 四種退出碼保留，但**全歸「跑沒跑起來」**，「該不該重試」寫進狀態檔——不然退出碼跟 I-04 的兩頻道自相矛盾（邊 S18、FINDINGS LLM 段）。
- **L-03**：「先立薄的一份」已經被事實蓋過——**現在就是 757 條 spec＋schemas 當正本**，這條改成描述現況比較誠實（spec 現狀）。
