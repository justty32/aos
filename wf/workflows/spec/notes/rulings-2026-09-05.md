# 使用者 2026-09-05 拍板的 8 條（寫 spec 的最高依據）

來源：使用者當面回答，日期 2026-09-05。這 8 條蓋過 ideas 各章的「建議預設」。

| 編號 | 裁決 | 白話與後果 |
|---|---|---|
| M-01 | **2026-09-04 那批 13 條傾向整批升格為裁決** | ideas/13 章「該升格的傾向」表裡 13 條全部當成已拍板：一格＝exec、run＝反覆 exec（固定次數／隔一段時間／到條件）、run 通用停法＝沒產出新指令就停、同步子世界借父鐘、脫節子世界自己有鐘、父看固定路徑檔拿脫節結果（**但路徑由父指定，見 I-01**）、時間有界主方法是環境限制、所有時鐘由 daemon 走並登記在一處、一塊地只看得到自己地上的東西、路徑＝身分、刪資料夾＝死、一個 agent＝一個資料夾、agent 本質是一個 aos run、agent 停於 LLM 不再呼叫工具、prompt 組法留給工程、FUSE 要做且順序 tmpfs→inotify→FUSE。spec 裡這些寫成「必須」條款，不再標傾向。 |
| F-02 | **LLM 處理單元是單獨一個世界（一塊地）；其他世界要用 LLM，就是丟請求給它。** 使用者原話：「預期到時候 LLM cpu 會單獨一個世界，其他世界要用，那就是丟請求給他。」 | 後果：(1) 同步子世界裡不可能有 LLM 呼叫，因為 LLM 不是指令、是另一個世界，只能投遞；(2) 「一次 LLM 請求＝一塊脫節小地」這個講法改寫成「一筆投給 LLM 世界的請求」，請求怎麼投、結果回到哪，走 I-01／I-02 的呼叫記錄與狀態檔；(3) LLM 世界自己有鐘、由 daemon 登記與看管（G-01）；(4) 並行上限、排隊、tier、處理單元位址（G-05、G-06、07 章五條規則）都變成「LLM 世界自己的 .aos 怎麼寫」的問題，spec 要給 LLM 世界一章。 |
| G-01 | **daemon 走時鐘＝替每塊登記的地起一支 `aos run` 子行程，daemon 只當看管者** | daemon 掛了各地時鐘照走；代價是 daemon 不在時沒人能一次全停，只能重啟後對帳。spec 要明寫這個代價。 |
| E-01 | **接力棒是一個 json 檔：檔頭放批 id 與格式版本，內容是陣列、一條串一個物件（串 id、模板名、游標、狀態、可選資源自報）** | 多寫者撞寫用原子改名（寫暫存→刷→改名）。D-03 併入此處：批 id 與格式版本在檔頭、彙總狀態在各串物件的狀態欄。 |
| I-01 | **父從子拿回的結果，路徑由父在呼叫那筆記錄裡指定**（不是固定 out/） | 跟指令「輸出寫到哪」同一套。呼叫記錄格式要有「結果落點」欄；子跑完把結果寫到那裡。LLM 世界的請求同樣：請求裡寫結果要落到哪。 |
| I-02 | **子資料夾另寫一個狀態檔標明壞了** | 三態：結果檔不在＝還沒好；結果檔在＝好了；狀態檔說壞了＝壞了。狀態檔要能放錯誤原因。狀態檔放哪由主編定（建議：緊鄰結果檔、固定後綴，因為結果路徑已由父指定）。 |
| I-03 | **父對失敗的處置寫在父的 .aos 腳本裡；機器只保證「壞了看得見」** | 系統不內建重試、不內建例外。父沒寫處置時，預設行為由主編定一條最保守的（建議：該串停在原地、寫停止原因檔），且必須在 spec 明寫。 |
| I-04 | **結束狀態拆兩個頻道：結束碼只管「跑沒跑起來」（找不到程式、崩潰、逾時、被殺）；做成沒做成寫進檔案** | 接力棒推游標前看檔案判成敗，不看結束碼。「做成沒做成」寫在哪個檔、什麼格式，跟 I-02 的狀態檔合成一題。 |

## 其餘 63 條怎麼處理

使用者同意：其餘待決定全部照 ideas/README.md 待決定總表的「我建議的預設」寫進 spec，每條在 spec 裡標 **「預設（2026-09-05，未經使用者拍板）」**，之後他翻到不同意再改。spec 的入口要有一張表列出哪些條款來自使用者裁決、哪些只是預設。

## 跟 I-01 有關的連動

ideas 裡多處寫「父看子的 out/ 固定路徑」（06、07、09、13 章）。I-01 裁定後一律改成「父指定的路徑」。「固定路徑」這個講法在 spec 裡不再出現。
