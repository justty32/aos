# 07b 結果落點的規矩
← [入口](README.md)

「結果落點」是父在呼叫記錄或 LLM 請求裡指定的那一條路徑，子把結果寫到那裡。這份只講那條路徑：誰解析、能放哪、旁邊還有哪幾個檔、怎麼寫上去。三態怎麼讀、呼叫怎麼開在 [07](07-call-and-delivery.md)。條款編號跟 07 連號。

## 路徑誰解析

- **S-07-54** 父在 `call` 步或 LLM 請求裡寫的 `result` 必須以父那塊地的根為原點。〔主編補〕
- **S-07-55** exec 必須在寫呼叫記錄（或投出請求）那一刻，把 `result` 展開成絕對真實路徑，記錄與請求裡存的都是展開後的。〔主編補〕
- **S-07-56** 子地與 LLM 世界必須把 `AOS_RESULT` 當成一條不透明的絕對路徑直接拿去寫，禁止自己再解析、拼接或改寫。〔主編補〕

## 落點能放哪

- **S-07-57** 落點必須在父那塊地之內。〔主編補〕
- **S-07-58** 落點禁止落在任何一塊地的 `.aos/` 之內，子地自己的 `.aos/` 也不行。〔主編補〕
- **S-07-59** 落點禁止以 `.status.json` 或 `.usage.json` 結尾，這兩個後綴是保留給狀態檔與用量檔的。〔主編補〕

## 呼叫之前落點必須是空的

- **S-07-60** 開子地或投出請求之前，落點、`<落點>.status.json`、`<落點>.usage.json` 這三個檔必須都不存在。〔主編補〕
- **S-07-61** 這三個檔有任何一個已經在，必須當解析拒絕、退出碼 3；禁止自動刪掉或蓋過去。〔主編補〕
- **S-07-62** 要重跑同一個呼叫，必須人先把舊檔清掉，或父換一個落點。〔主編補〕
- **S-07-63** 同一格裡所有落點（連同它們的兩個後綴檔）必須兩兩相異；有重複必須整格拒跑、退出碼 3。〔主編補〕
- **S-07-78** 上面四條誰查必須講死：`call` 步由 exec 在嚴格解析那一步查；用 `aos deliver --llm` 投出去的 LLM 請求由 `aos deliver` 自己查，違反就退出碼 3、那筆不投。〔主編補〕

## 落點是一個明示的寫入洞

一塊地只看得到自己地上的東西，這是必須。落點是唯一的合法出口：父把路徑交出去，就是父自己開的洞。

- **S-07-64** 落點必須當成父對子地（或 LLM 世界）開的一個明示寫入洞：把這條路徑交出去這個動作本身就是授權。〔主編補〕
- **S-07-65** 這個洞必須只涵蓋那一條落點路徑與它的 `.status.json`、`.usage.json`；子往父地其他位置寫是禁止的。〔主編補〕

## 怎麼寫上去

- **S-07-66** 結果檔與狀態檔都必須這樣發布：暫存檔開在落點自己那個目錄 → fsync 這個檔 → 改名成正式名 → fsync 那個目錄。〔主編補〕
- **S-07-67** 暫存檔禁止開在別的目錄；禁止用複製代替改名。同目錄就是為了保證改名不跨檔案系統。〔主編補〕
- **S-07-68** 父只認正式名：看到正式名的檔就必須當它是完整的；被殺的指令留下的半成品禁止用正式名。〔主編補〕
- **S-07-69** 結果檔或狀態檔解析不開時必須判「壞了」，禁止重讀重試。〔主編補〕
- **S-07-70** 子地或 LLM 世界寫落點之前，必須先確認父那塊地的 `.aos/` 還在；不在就必須放棄寫，禁止建目錄。〔主編補〕
- **S-07-71** 放棄寫之後，必須在登記表自己那筆的 `ext` 留一筆 `result_orphaned`，讓人事後查得到這份工作白做了。〔主編補〕
- **S-07-72** LLM 世界處理完一筆請求，必須在落點旁另寫一份 `<結果落點>.usage.json`（欄位在 [09](09-llm-world.md)）。〔主編補〕
- **S-07-77** 同步子地已經閒著、落點卻沒檔也沒狀態檔時，那一步必須算失敗：父的 exec 代寫狀態檔、`reason` 寫 `no_result`，禁止繼續當它還沒好。〔主編補〕

## 狀態檔的 message 與 ext

- **S-07-73** 狀態檔的 `message` 最長 4096 bytes；超過必須截斷，並在 `ext` 寫 `"truncated": true`。〔主編補〕
- **S-07-74** `message` 必須當成不可信資料：裡面常常是別人的程式或模型吐出來的字。〔主編補〕
- **S-07-75** 禁止把 `message` 自動展開成任何指令的參數；要用它必須人或父的腳本明白處理過。〔主編補〕
- **S-07-76** 「這件事值不值得再試一次」必須寫在狀態檔的 `ext.retryable`（布林，LLM 世界填，欄位意思在 [09](09-llm-world.md)）；父只讀狀態檔，禁止改看退出碼。〔主編補〕

## 例子

父地是 `/home/u/work`，父寫 `"result": "notes/report.md"`，展開之後這三個位子被佔住：

- 結果檔 `/home/u/work/notes/report.md`
- 狀態檔 `/home/u/work/notes/report.md.status.json`
- 用量檔 `/home/u/work/notes/report.md.usage.json`

寫的時候是 `/home/u/work/notes/report.md.tmp.<隨機>` → fsync → 改名成 `report.md` → fsync `/home/u/work/notes`。

## 待使用者拍板

整份都是〔主編補〕，一條沒有使用者批過。

- S-07-54～S-07-56 落點以父地根為原點、由 exec 展開成絕對真實路徑、子不解析。
- S-07-57～S-07-59 落點必須在父地內、不得在任何 `.aos/` 內、不得用兩個保留後綴。
- S-07-60～S-07-63 呼叫前三個檔都不得已存在（存在＝退出碼 3，不自動刪）；同格落點兩兩相異。
- S-07-78 這四條誰查：`call` 步是 exec，`aos deliver --llm` 是 deliver 自己。
- S-07-64、S-07-65 落點＝明示寫入洞，只涵蓋那條路徑與它的兩個後綴檔。
- S-07-66～S-07-69 同目錄暫存→fsync→改名→fsync 目錄；禁止用複製；父只認正式名；解析不開就判壞。
- S-07-70、S-07-71 父地死了就放棄寫、禁止建目錄，在登記表 `ext` 留 `result_orphaned`。
- S-07-72 用量檔 `<結果落點>.usage.json`。
- S-07-77 同步子地閒著卻兩個檔都沒有＝失敗，父代寫 `no_result`。
- S-07-73～S-07-75 `message` 4096 bytes 上限與「不可信資料」。
- S-07-76 可不可重試寫在 `ext.retryable`，父只讀狀態檔。

沒發現新的矛盾。S-07-60 那條要注意：它讓「同一個落點重跑」變成必須人來清，比較囉唆，但靜默讀到上一輪的舊結果更糟。

## 現況對照

今天沒有結果落點這個概念，也沒有狀態檔、用量檔；輸出路徑由每筆指令自己寫，沒有人檢查它落在哪、會不會撞、會不會蓋掉別人的檔。今天的暫存檔位置也沒有規定，跨檔案系統改名會直接失敗。
