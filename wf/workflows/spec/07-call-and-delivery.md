# 07 呼叫、三態與投遞
← [入口](README.md)

這份講三件事：父怎麼開一塊子地、結果與失敗怎麼看得見、東西怎麼安全放進別人的收件匣。落點那條路徑自己的規矩另開一份：[07b](07b-result-path.md)。一格的順序在 [06](06-exec-and-run.md)。

## 開子地：等它＝呼叫，不等＝傳訊

- **S-07-01** `call` 步的 `mode` 必須是 `"sync"`（同步）或 `"async"`（脫節）兩者之一，沒有第三種。〔裁決 2026-09-04〕
- **S-07-02** 同步呼叫必須做成：父每走一格就對子地做一次 `aos exec`，父的這一步停在原地，直到子地閒著。〔主編補〕
- **S-07-03** 子地還沒閒著時，父的這一步禁止算失敗，也禁止推游標。〔主編補〕
- **S-07-04** 子地閒著之後，父必須照三態判這一步成不成。〔裁決 2026-09-05〕
- **S-07-05** 同步呼叫的整棵子樹裡禁止有 LLM 呼叫；要用 LLM 必須投一筆請求給 [LLM 世界](09-llm-world.md)。〔裁決 2026-09-05〕
- **S-07-06** 脫節呼叫必須拿 `call` 步的 `clock` 去登記表登記子地的時鐘；登記寫成功這一步就算成功，父不等它。〔裁決 2026-09-04〕
- **S-07-07** 脫節呼叫的結果必須之後用 `await` 步看結果落點，禁止在 `call` 步等。〔裁決 2026-09-04〕
- **S-07-08** 子地看得到什麼，必須只由父放進那個資料夾的東西決定。〔裁決 2026-09-04〕
- **S-07-47** exec 開子地時必須設環境變數 `AOS_CALL_CHAIN`：這條呼叫鏈上每一塊地的真實路徑，用冒號隔開，最後一個是子自己。〔主編補〕
- **S-07-48** 子地的真實路徑已經在 `AOS_CALL_CHAIN` 上時，這一步必須立刻失敗、`reason` 寫 `call_cycle`；禁止自動把那個環打斷。〔主編補〕
- **S-07-49** `AOS_CALL_CHAIN` 上超過 8 塊地時，這一步必須立刻失敗、`reason` 寫 `call_depth`。〔主編補〕
- **S-07-50** 點名一個沒有可載入原稿的資料夾，必須當場失敗並寫狀態檔、`reason` 寫 `no_source`，禁止靜靜算成功（見 [03](03-source-and-compile.md)）。〔主編補〕

## 呼叫記錄

- **S-07-09** 兩種 `mode` 都必須寫一筆呼叫記錄 `.aos/calls/<call id>.json`，欄位：`format_version`、`id`、`tick`、`series`、`step`、`child`、`mode`、`result`、`args`、`opened_at`；同步的只在第一次進那一步時寫，之後每格不重寫。〔裁決 2026-09-05〕
- **S-07-10** `child` 必須寫子地的真實路徑，禁止寫 symlink。〔主編補〕
- **S-07-11** `result` 是父指定的結果落點，必須由父寫在這筆記錄裡；禁止讓子地自己挑要寫哪。〔裁決 2026-09-05〕
- **S-07-12** exec 必須用 `AOS_RESULT` 把 `result`、用 `AOS_CALLER` 把父地路徑交給子地。〔裁決 2026-09-05〕
- **S-07-13** `args` 的每一對必須變成子地的環境變數 `AOS_ARG_<大寫名>`，值是字串。〔主編補〕

## 三態與狀態檔

- **S-07-14** 三態必須這樣讀：結果落點的檔不在＝還沒好；在＝好了；`<結果落點>.status.json` 在＝壞了。〔裁決 2026-09-05〕
- **S-07-15** 狀態檔的位置必須是結果落點加後綴 `.status.json`，禁止另立位置。〔主編補〕
- **S-07-16** 狀態檔欄位必須是 `format_version`、`state`（只有 `"failed"`）、`reason`、`message`、`at`、`ext`。〔裁決 2026-09-05〕
- **S-07-17** `reason` 必須是短代碼，例如 `spawn_error`、`timeout`、`killed`、`no_daemon`；常用的一整組列在 `schemas/status.schema.json`，不夠用可以自己加。〔主編補〕
- **S-07-18** 誰寫狀態檔：子地的 run 停在 `failed` 時必須寫；daemon 發現子地行程死了、被殺、逾時必須寫；LLM 世界處理請求出錯必須寫。〔主編補〕
- **S-07-19** 結果檔與狀態檔怎麼寫上去、落點能放哪、`message` 有多長，必須照 [07b](07b-result-path.md)。〔主編補〕
- **S-07-20** 結果檔與狀態檔同時在時，必須算壞了：狀態檔贏。〔主編補〕
- **S-07-21** 判「做成沒做成」必須看檔，禁止看結束碼；結束碼只管跑沒跑起來。兩個頻道的細節在 [05](05-series-format.md)。〔裁決 2026-09-05〕
- **S-07-22** `await` 步超過 `max_ticks` 還是三態的第一態，必須算失敗，`reason` 寫 `await_timeout`。〔裁決 2026-09-05〕
- **S-07-51** 建議每個 `await` 步都寫 `max_ticks`，沒寫就沒有等太久這個上限。〔主編補〕

## 失敗的處置歸父

- **S-07-23** 父對失敗要做什麼，必須寫在父原稿那一步的 `on_fail`。〔裁決 2026-09-05〕
- **S-07-24** 系統禁止內建重試、禁止內建例外；機器只保證壞了看得見。〔裁決 2026-09-05〕
- **S-07-25** 父沒寫 `on_fail` 時，預設必須是：那條串停在原地、狀態改 `failed`、寫停止原因檔 `.aos/stopped.json`。〔裁決 2026-09-05〕
- **S-07-26** 一條串停了，同一塊地上其他串必須照跑。〔主編補〕

## 脫節子地的一生

代價明寫：daemon 不在時新的脫節工作起不來，已經在走的照走。

- **S-07-27** 順序必須是：父寫呼叫記錄、把子地登記成 `pending` → daemon 起一支 `aos run <子> --register` → 子跑到閒著 → 結果落到父指定的落點 → 父的 `await` 步之後某一格讀到。〔主編補〕
- **S-07-28** 登記表的 `daemon_pid` 不在、或那支行程已經死了時，`call async` 必須立刻失敗：exec 代子寫狀態檔、`reason` 寫 `no_daemon`；禁止 exec 自己 detach 起一支 run。〔主編補〕
- **S-07-29** 父要知道子地的鐘還在不在走，必須查登記表那一筆的 `state` 與 `pid`，禁止用別的方法猜。〔預設 2026-09-05，F-07〕
- **S-07-30** 子地由父來刪：`call` 步可以帶 `cleanup: true`，父的 `await` 步讀到結果之後，exec 必須刪掉那塊子地；結果落點在父地上，不受影響。〔主編補〕
- **S-07-31** `cleanup` 省略時必須當 `false`，子地留著給人看。〔主編補〕
- **S-07-32** daemon 巡邏保底：一筆登記閒著超過 `reap_after_ms`（牆鐘），daemon 必須只刪那塊脫節子地本身，禁止碰父地上的結果檔與狀態檔；刪之前落點還沒有檔就代寫狀態檔、`reason` 寫 `reaped`。〔主編補〕

## 投遞協定

- **S-07-33** 投遞必須四步一氣呵成：寫 `.aos/inbox/<id>.json.temp` → fsync 這個檔 → 改名成 `<id>.json` → fsync 收件匣目錄。〔裁決 2026-08-28〕
- **S-07-34** 取件必須是：exec 把那個檔原子改名搬離收件匣之後，才可以執行它。〔裁決 2026-08-26〕
- **S-07-35** 投遞物的 `id` 必須是隨機名（32 個小寫 hex），禁止拿行程編號當名字。〔裁決 2026-08-28〕
- **S-07-36** 「正在跑」那種狀況檔禁止當鎖用；互斥必須用獨佔建檔的 `.aos/lock`，一塊地同時只准一支 exec 或 run。〔裁決 2026-08-28〕
- **S-07-37** 崩潰留下的半成品必須留在原地給人處理，禁止靜靜蓋掉重跑。〔裁決 2026-08-26〕
- **S-07-38** 投遞物必須有 `format_version`、`id`、`kind`（`"inst"`／`"mail"`／`"llm"`）、`from`、`at`，其餘欄位依 `kind`。〔主編補〕
- **S-07-39** 同一個 `id` 再投必須拒絕，並回報投遞者：`aos deliver` 印出原因、非 0 退出。〔預設 2026-09-05，I-05〕
- **S-07-40** 外面來的投遞必須在格與格之間被取走，禁止插進正在跑的那一格。〔預設 2026-09-05，I-05〕
- **S-07-41** 無效投遞（過不了 schema、`kind` 不認得）必須搬去 `.aos/inbox/rejected/<id>.json`，同格其他投遞照跑。〔預設 2026-09-05，I-06〕
- **S-07-42** 隔離之後必須往 `from` 的收件匣投一則 `mail`：`subject` 寫 `"rejected"`、`body` 寫原因。〔預設 2026-09-05，I-06〕
- **S-07-43** 投遞物壞到連 `from` 都讀不出來、或 `from` 那塊地投不進去時，必須在自己這塊地的 `.aos/errors.log` 追加一行 json（`at`、`file`、`error`），然後放棄回報。〔主編補〕
- **S-07-44** 收件匣裡還沒取走的檔數超過 `.aos/config.json` 的 `inbox_max`（預設 1000）就必須拒收，投遞者拿退出碼 75。〔預設 2026-09-05，I-06〕
- **S-07-52** 取件的去重必須只靠接力棒檔頭的 `recent_ids`（見 [05](05-series-format.md)）：id 在裡面就不再跑第二次，禁止另設一份去重檔（LLM 世界另走 `.aos/requests/`，見 [09](09-llm-world.md)）。〔主編補〕
- **S-07-53** 投遞禁止建立任何目錄；目標資料夾不在、或裡面沒有 `.aos/`，必須算投遞失敗，`aos deliver` 退出碼 4。〔主編補〕
- **S-07-45** `kind: "mail"` 的投遞物，exec 必須搬到 `.aos/mail/<id>.json` 就停手，禁止執行它。〔主編補〕
- **S-07-46** 誰讀信、讀完怎麼標記，必須照 [10](10-agent.md)。〔主編補〕

## 範例

一筆呼叫記錄 `.aos/calls/9f2c4a1b8d3e47f0a5b6c7d8e9f01234.json`：

```json
{
  "format_version": 1, "id": "9f2c4a1b8d3e47f0a5b6c7d8e9f01234",
  "tick": 12, "series": "s-main-01", "step": "fetch-report",
  "child": "/home/u/work/reporter", "mode": "async",
  "result": "/home/u/work/notes/report.md",
  "args": { "month": "2026-09" },
  "opened_at": "2026-09-05T12:00:00.000Z"
}
```

它的狀態檔 `/home/u/work/notes/report.md.status.json`（這個檔在就是壞了）：

```json
{
  "format_version": 1, "state": "failed", "reason": "timeout",
  "message": "子地跑了 40 格還沒閒著，被預算停掉。",
  "at": "2026-09-05T12:03:20.500Z"
}
```

三種投遞物各一段：

```json
{
  "format_version": 1, "id": "0a1b2c3d4e5f60718293a4b5c6d7e8f9", "kind": "inst",
  "from": "/home/u/work", "at": "2026-09-05T12:00:01.000Z",
  "inst": { "format_version": 1, "id": "mk-notes", "argv": ["mkdir", "-p", "notes"] }
}
```

```json
{
  "format_version": 1, "id": "11223344556677889900aabbccddeeff", "kind": "mail",
  "from": "/home/u/work/reporter", "at": "2026-09-05T12:00:02.000Z",
  "subject": "rejected", "body": "投遞物少了 kind 欄，已隔離。"
}
```

```json
{
  "format_version": 1, "id": "fedcba98765432100123456789abcdef", "kind": "llm",
  "from": "/home/u/work/reporter", "at": "2026-09-05T12:00:03.000Z",
  "prompt": ".aos/frames/s-main-01/prompt.txt", "tier": "smart",
  "result": "/home/u/work/notes/answer.txt",
  "priority": 10, "max_wait_ms": 60000
}
```

## 待使用者拍板

〔預設〕：S-07-29 查登記表知道子地的鐘還在不在（F-07）；S-07-39、S-07-40 同 id 再投＝拒絕並回報、外部插隊只在格邊界（I-05）；S-07-41、S-07-42、S-07-44 無效投遞隔離＋回一則信、收件匣滿了拒收（I-06）。

〔主編補〕（標〔裁決〕的不列）：

- S-07-02、S-07-03 同步＝父每格對子 exec 一次，那一步停在原地不算失敗（矛盾 #3）。
- S-07-10、S-07-13 呼叫記錄寫真實路徑；`args` 變 `AOS_ARG_<大寫名>`。
- S-07-15、S-07-17～S-07-20 狀態檔的位置、短代碼、誰寫、發布規矩指向 07b、兩檔都在時狀態檔贏。
- S-07-26 一條串停了其他串照跑；S-07-27 脫節子地的流程。
- S-07-28 沒有 daemon 時新的脫節工作直接失敗（取代矛盾 #6 原本的「exec 自己 detach 起 run」）。
- S-07-30、S-07-31 `cleanup: true` 才刪子地（C-01）；欄位要加進 [03](03-source-and-compile.md)。
- S-07-32 daemon 只刪子地、不碰父地上的檔，落點沒檔就代寫 `reaped`（取代 C-02 原本的「連結果一起清」）。
- S-07-38、S-07-43、S-07-45、S-07-46 投遞物共同欄位、寄件人讀不出來就寫 `.aos/errors.log`、信只搬不跑。
- S-07-47～S-07-50 呼叫鏈的環與深度上限；點名沒有原稿的資料夾當場失敗。
- S-07-51～S-07-53 建議 `await` 都給 `max_ticks`；去重靠 `recent_ids`；投遞不建目錄。
- [07b](07b-result-path.md) 整份都是〔主編補〕。

矛盾：C-01、C-02 預設「父讀完就刪」，但崩潰現場要留給人看。折衷：預設不刪，要刪就明寫 `cleanup: true`。

## 現況對照

今天沒有呼叫記錄、狀態檔、三態；`aos run <子>` 是阻塞子行程，只有同步一種。投遞不刷磁碟，壞投遞永久堆積且投的人不會知道，收件匣也沒有上限。
