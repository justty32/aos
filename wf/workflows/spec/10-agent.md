# 10 agent
← [入口](README.md)

agent 不是核心裡的零件。它就是一塊地，加上寫在原稿裡的一個圈：組 prompt → 投給 LLM 世界 → 等回話 → 跑工具 → 再組 prompt。這份檔規定那塊地有哪些檔、圈長什麼樣、什麼時候停。工具與封套見 [11](11-tools-and-contacts.md)。

## 一個 agent 就是一塊地

- **S-10-01** 一個 agent 必須是一個資料夾（一塊地）；生死沿用一塊地那套：開資料夾＝生，刪資料夾＝死。〔裁決 2026-09-04〕
- **S-10-02** agent 必須沒有第二套規則：用的是普通的地、普通的步、普通的指令。〔裁決 2026-09-04〕
- **S-10-03** agent 的圈禁止進核心；它必須由原稿裡的步拼出來，不是核心裡的一個功能。〔裁決 2026-09-04〕
- **S-10-04** agent 的本質必須是一個 `aos run`：反覆讓這塊地走一格。〔裁決 2026-09-04〕
- **S-10-05** agent 每格必須能從檔案讀出自己走到哪一步；圈的狀態禁止只放記憶體。〔主編補〕

## agent 資料夾裡有什麼

- **S-10-06** agent 資料夾必須有四樣：`main.aos.json`（它的圈）、`agent.json`（限制參數）、`system_prompt` 指到的檔、`.aos/`。〔主編補〕
- **S-10-07** `aos agent init` 必須一次產出這四樣，產出的 `main.aos.json` 必須能直接跑。〔主編補〕
- **S-10-08** `agent.json` 必須住頂層、進 git、由人寫；欄位 `format_version`、`max_seconds`、`max_llm_calls`、`max_tokens`、`tier`、`system_prompt`、`ext`，正本 [`agent.schema.json`](schemas/agent.schema.json)。〔預設 2026-09-05，H-03〕
- **S-10-09** `system_prompt` 必須是一條路徑，禁止把整段人格字串塞進 `agent.json`。〔主編補〕

## 限制參數：保底的強制停

自然停是通用停法（沒新事就停）。限制參數是保底的強制停，兩個都要有。

- **S-10-10** `max_llm_calls` 與 `max_tokens` 必須對這塊地自己的 `.aos/usage.json` 判；禁止讀家的帳簿，那是 LLM 世界那邊的帳。〔主編補〕
- **S-10-11** LLM 世界回結果時必須在落點旁多寫 `<結果落點>.usage.json`（`tokens_in`、`tokens_out`）；圈必須每圈把它累加進 `.aos/usage.json`，正本 [`usage-total.schema.json`](schemas/usage-total.schema.json)。〔主編補〕
- **S-10-12** 超過上限時必須往自己的 `.aos/control/` 投一則 `stop`，串記 `stopped`；那則 `stop` 由它自己那支 run 在格邊界讀到（例外：借父鐘的 agent 由父的 exec 讀，見 [06b](06b-run-rules.md) 的 S-06-62）。禁止直接殺行程。〔主編補〕
- **S-10-13** `max_seconds` 必須由外面兜：起 run 的人換算成格數，寫進 `aos run --budget N` 或登記表那筆的 `budget`。圈不看牆上的鐘。〔主編補〕
- **S-10-14** 三個上限缺席或填 0 必須當「不限」。〔主編補〕
- **S-10-43** 累加必須是 `await` 拿到結果檔之後的下一步，一筆自己的指令（骨架裡叫 `tally_usage`）：讀 `<結果落點>.usage.json` 累加進 `.aos/usage.json`。不准跟 `await` 擠同一格，一格裡的指令看不到彼此的結果。沒有用量檔（例如失敗）就只把 `llm_calls` 加一。〔主編補〕

## 每圈怎麼走

一圈是六種步接成一條串，走完回到第一步。中間夾多少空等的格，由 LLM 多慢與時鐘多密決定。

- **S-10-15** 一圈必須照這個順序：組 prompt → 投給 LLM 世界 → 等回話 → 解析成工具清單 → 跑工具 → 包成封套 → 回到組 prompt。〔裁決 2026-09-04〕
- **S-10-16** 組 prompt 的輸入必須只有三樣：上一圈的工具結果封套、等待期間搬進 `.aos/mail/` 的信、一份固定的地圖檔。禁止每圈全掃這塊地。〔預設 2026-09-05，H-04〕
- **S-10-17** 進了 prompt 的信必須在同一格裡用原子改名從 `.aos/mail/` 搬到 `.aos/mail/read/`；搬不成功的禁止放進 prompt，否則下圈再讀一次。〔主編補〕
- **S-10-18** prompt 的字串怎麼拼必須留給實作；這份 spec 只定輸入來源與順序，禁止規定字串模板。〔裁決 2026-09-04〕
- **S-10-19** 每圈第一筆指令必須先清掉上一圈留在堆疊框的結果檔、`.status.json` 與 `.usage.json`。不清，`await` 會撿到舊的，而且下一圈投請求會被 [07b](07b-result-path.md) 的「三個檔都不得已存在」擋掉。〔主編補〕
- **S-10-20** 投給 LLM 世界必須是一筆 `kind:"llm"` 的投遞：用一個 `inst` 步跑 `aos deliver`。禁止為每次請求另開一塊地。〔裁決 2026-09-05〕
- **S-10-21** 請求裡的 `result` 必須指到自己的堆疊框；`tier` 沒指定就照 `agent.json`；`tools` 清單必須從這塊地的 `.aos/tools/` 產生。〔主編補〕
- **S-10-44** LLM 世界的位置必須用內建暫存器 `${llm_world}` 拿、家用 `${home}` 拿（見 [05b](05b-series-lifetimes.md)）；agent 這塊地禁止自己去讀家的設定檔。〔主編補〕
- **S-10-22** 等回話必須是一個 `await` 步，等的就是上一步指定的那個結果落點。〔裁決 2026-09-04〕
- **S-10-23** 解析模型回話必須嚴格檢查格式，格式不合就算這步失敗；清單是空的也是合法結果，不算失敗。〔裁決 2026-08-30〕
- **S-10-24** 沒標 `slow` 的工具必須在這塊地用 `inst` 步跑完；`slow: true` 的必須開一塊脫節子地跑：`call` 步（`mode:"async"`）加一個 `await` 步。〔預設 2026-09-05，K-06〕
- **S-10-25** 工具結果必須包成 [11](11-tools-and-contacts.md) 的錯誤封套再進下一份 prompt；成敗同一個形狀。〔裁決 2026-08-30〕

模板骨架（一份能過 `program.schema.json` 的實體，照抄改）在 [10b](10b-agent-loop.md)。

## 什麼時候停

- **S-10-26** agent 的停止條件必須就是 run 的通用停法；「LLM 不再呼叫工具」只是它的白話。〔裁決 2026-09-04〕
- **S-10-27** 停在 `await` 步上的串必須算「在等」：run 禁止因為這格沒產出新指令就停，只剩在等的串時每格之間睡 `--every`（見 [06](06-exec-and-run.md)）。等 LLM 不會停掉 agent。〔主編補〕
- **S-10-28** 清單是空的時候，圈必須走到 `then:"end"`：串記 `done`、地閒著、run 停。〔裁決 2026-09-04〕
- **S-10-29** 停必須不是死：資料夾還在，下封信進來、下次 `aos run` 就重新載入原稿再開一圈。〔主編補〕

## 誰讓它動

- **S-10-30** agent 預設必須用 `aos run --register` 自己登記一顆鐘：daemon 起它、登記表看得到它那筆、`aos stop <地>` 停得到它。父停了它照走。〔裁決 2026-09-05〕
- **S-10-31** 借父的鐘（父用 `call` 步 `mode:"sync"` 帶，父走一格它走一格）必須是可選的做法、不是預設；兩種都合法，但借父鐘的 agent 沒有自己那支 run，登記表上也沒有它。〔裁決 2026-09-05〕
- **S-10-32** agent 這塊地上禁止跑時間由外面決定的指令；那種一律搬去 LLM 世界或脫節子地。〔裁決 2026-09-04〕

## 一次全停、重開、等待期間世界會變

- **S-10-33** 一次全停之後重開必須接著走：狀態全在檔案裡，重開就是從游標那一步繼續。〔主編補〕
- **S-10-34** 等 LLM 那步壞掉時必須看得到狀態檔：被訊號殺是 `reason:"killed"`，送出去了但不知道後端做完沒是 `reason:"result_unknown"`。〔裁決 2026-09-05〕
- **S-10-35** agent 禁止自行判斷重發 LLM 請求；看到 `killed` 或 `result_unknown` 要不要重投，必須是 `await` 步 `on_fail` 明寫的一步。沒寫＝串停在原地。〔主編補〕
- **S-10-36** 等待期間世界會變必須當正常：組 prompt 那格看到的地跟結果回來那格不同，不算錯。〔主編補〕
- **S-10-37** 等待期間搬進 `.aos/mail/` 的信必須進下一份 prompt，不然永遠慢一圈。〔主編補〕

## 工具、人、指令面

- **S-10-38** agent 底下禁止有自己的工具白名單；能用的就是這塊地 `.aos/tools/` 登記過的。〔預設 2026-09-05，K-01〕
- **S-10-39** 使用者必須也算一隻 agent，住 `~`；別的 agent 可以寄信到那裡。〔裁決 2026-08-30〕
- **S-10-40** 每封信必須帶 `from`，值是投遞者那塊地的路徑。〔裁決 2026-08-30〕
- **S-10-41** `aos say` 必須是往某個 agent 的收件匣投一封 `mail`，`aos listen` 是讀 agent 投到 `~` 的信，`aos state` 是看游標在哪一步。旗標在 [12](12-cli.md)。〔主編補〕
- **S-10-42** `aos state` 必須把游標翻成三態給人看：停在等回話那步＝等 LLM，停在跑工具那幾步＝等工具，其餘＝組 prompt。〔預設 2026-09-05，H-03〕

## 待使用者拍板

- S-10-05～07 圈的狀態一律落檔；資料夾必有四樣檔；`aos agent init` 一次產出。〔主編補〕
- S-10-08 `agent.json` 就是那七欄。〔預設，H-03〕｜S-10-09 `system_prompt` 只放路徑。〔主編補〕
- S-10-10、S-10-11、S-10-43 上限對 `.aos/usage.json` 判、不讀家的帳簿；用量由 `await` 之後的下一步累加，沒有用量檔就只加 `llm_calls`。〔主編補〕
- S-10-12～14 超過上限＝投 `stop` 記 `stopped`；`max_seconds` 換成格數；缺席或 0＝不限。〔主編補〕
- S-10-16 每圈 prompt 的三個輸入來源。〔預設，H-04〕｜S-10-24 慢工具開脫節子地跑。〔預設，K-06〕
- S-10-17 進 prompt 的信同格搬到 `.aos/mail/read/`，搬不成不進 prompt。〔主編補〕
- S-10-19 每圈開頭先清掉堆疊框上一圈的結果檔、狀態檔與用量檔。〔主編補〕
- S-10-21 `result` 落堆疊框、`tier` 取自 `agent.json`。〔主編補〕｜S-10-44 用 `${llm_world}`／`${home}`，不讀家的設定檔。〔主編補〕｜S-10-33 重開從游標繼續。〔主編補〕
- S-10-27 停在 `await` 的串算「在等」，run 不停、每格之間睡 `--every`。〔主編補〕｜S-10-29 停不是死。〔主編補〕
- S-10-35 禁止自行重發 LLM 請求，重不重發由 `on_fail` 明寫，沒寫＝串停。〔主編補〕
- S-10-36、S-10-37 等待期間世界會變算正常、信進下一份 prompt。〔主編補〕
- S-10-38 沒有 agent 層白名單。〔預設，K-01〕｜S-10-41、S-10-42 `say`／`listen`／`state` 語意與三態。〔主編補〕
- 矛盾：ideas 08 說「問 LLM 就開一塊脫節子地」，F-02 說 LLM 是單獨一個世界。選 F-02：投一筆請求，不另開地；rulings 蓋過 ideas。
- 矛盾：ideas 08 說 agent 停在「LLM 不再呼叫工具」，06 說停在「沒產出新指令」。併成一條（S-10-26），照 H-02 的建議預設。

## 現況對照

今天的 agent 住在 `.aos/agents/<名字>/`，是指令層的東西不是一塊地；沒有 `agent.json`、沒有限制參數與用量檔，一步同步等 HTTP 回來。工具往返佔三格，慢工具沒地方擺。agent 層那份白名單 `agents/<名字>/tools.json` 拿掉。
