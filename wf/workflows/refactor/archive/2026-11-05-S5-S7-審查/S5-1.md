## 要先修的

### 必修 1：沙箱裡的 Python 指令 import 不到 aos_flags

- 原因：`aos-sandbox` 綁進沙箱的是 `commands` 裡每支指令「所在的夾」。以前 `aos-tools` 和 `aos_flags.py` 一起放在 `proto8/bin/`，綁一個夾兩個都進得去。現在指令在 `cmd/aos-tools/bin/`，`aos_flags.py` 在 `proto8/py/`，後者沒被綁進去。
- 實測：拿 `examples/agent.json` 拿掉 `mem_mb`／`cpu_s` 兩欄（家機沒裝 s6），在沙箱裡跑 `aos-tools --help`：S5 版報 `ModuleNotFoundError: No module named 'aos_flags'`，main 版正常印出說明。agent-fsm 四格靠「aos-tools 的真位置推 `../../../py`」那條備援，在沙箱裡同樣會斷。
- 修法二選一：
  - (a) `aos-sandbox` 綁 `commands` 時，真位置符合 `…/cmd/<名>/bin/<名>` 的，連同 `…/py` 一起唯讀綁進去；
  - (b) 在 `agent.json` 的 `ro` 裡明寫 `proto8/py`。但 README 第 35 行寫「相對路徑從 cwd 算」，所以只能寫絕對路徑，範例就沒辦法照抄。

  傾向 (a)。改完把上面那次沙箱實測再跑一次，`aos-sandbox/README.md` 第 56 行補一句「一起綁 py/」。

### 應修 2：lib 的 claude、codex 工具複製出 repo 後找不到 cli_session

- 原因：`cli_session.py` 從 `lib/agent/` 搬到了 `proto8/py/`。`lib/agent/claude/_entry` 和 `lib/agent/codex/_entry` 的第 12 行只會往 `lib/../py` 找，沒有「從 PATH 上 aos-tools 的真位置找」那條備援。所以像試驗場那樣把整個 `lib/` 複製出 repo 之後就找不到。
- 實測：在 `pgB/lib/agent/claude/_entry` 跑一次，報 `ModuleNotFoundError: No module named 'cli_session'`。main 時期 cli_session 跟著 lib 一起被複製，不會壞。
- 修法：照 templates 那行，第 12 行後面補一行
  `sys.path.append(os.path.join(os.path.dirname(os.path.realpath(shutil.which("aos-tools") or "/")), "..", "..", "..", "py"))`。
- 試驗場的 `tools.json` 沒登記這兩支工具，所以最短路不受影響。
