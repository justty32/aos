## 發現

### 1. 判官開了排隊就改照 `sent_at` 排，跟關排隊時、跟設計稿都不一樣
- **類別**：程式現況｜**嚴重度**：品質（設計與程式不一致；已實測；實際影響目前小）
- **檔:行**：`proto8/lib/aos/judge/_entry:21,302-306`；設計 `proto8/thinking/2026-11/06/os-impl/03-判官排隊選項.md:15`；文件 `proto8/kernel/docs/02-kernel-modes.md:20`
- **commit／哪隊**：`b19f844cb`（11-06 晚家機，判官排隊第二步；os-impl 06 寫「codex 實跑＋隊長複跑」，排序那段 `git log -S` 指到這個 commit）
- **問題**：
  - 判官沒開排隊時，同一批信照 aos-post 的規矩：有序信全部在前。開了排隊，新信改照寄出時間 `sent_at` 排，有序信就跟無序信混在一起比時間。
  - 結果是「開不開排隊，誰先被放行不一樣」。實測同樣四封（無序 U1 → 有序 O1 → 無序 U2 → 有序 O2，依序寄），`max_running: 1`：關排隊放行 O1；開排隊放行 U1，`queue.json` 順序是 U1、O1、U2、O2。
  - 還有一個更細的：`sent_at` 是寄信程式**拿號之前**蓋的（`impls/aos-post/src/send/send.cpp:38-46,192`）。兩個人同時寄有序信，先蓋時間的不一定先拿到號，判官照時間排就可能跟序號顛倒。這點是讀碼推論，沒實測。
  - 設計稿 03 寫的是「取信順序照 aos-post：有序先、再名字」；N-16 也說處理順序「都用同一套」。判官檔頭註解自己寫了「照 sent_at／信名排序」，kernel/docs/02 只寫「先來先掛」，沒寫用什麼比。
  - 目前影響小：aos-agent 寄的都是無序信，無序信的名字本來就是時間開頭，照名字和照 `sent_at` 幾乎一樣。
- **使用者原話**：判官排隊只有「做成選項」（`os-impl/03-判官排隊選項.md:5`）；排序規則沒找到原話，是 agent 代定。有序投遞的原話是「另外設置一個檔案或資料夾，有鎖的，大家要投遞就去取鎖，取得順序」（`proto8/docs/NORMS/05-基礎設施-窗/05-N-16.md:11`）——意思是順序看拿號，不是看時間。
- **建議**：這是 agent 代定的細節，可以直接修，不用使用者裁。
  - A（推薦）：新信改用 `letter_key` 排（同 aos-post），刪掉 `sent_at` 那一層。跟設計稿、跟關排隊時一致，有序信也照號碼走。
  - B：保留 `sent_at`，把「排隊模式照寄出時間、有序信不優先」寫進 kernel/docs/02 和設計稿 03。

### 2. 有序信經判官轉寄後，回信對不上原信名
- **類別**：程式現況｜**嚴重度**：錯誤行為（已實測；目前沒有程式會寄有序信給判官，人手寄才會撞到）
- **檔:行**：`proto8/lib/aos/judge/_entry:15,174-187`
- **commit／哪隊**：`6d6428011`（11-05 kernel-daemon 步 5，claude；不是 sol）
- **問題**：
  - 判官轉寄有序信時用 `--ordered`，daemon 的 ctl 信箱會發一個**新號碼**。daemon 回信的 `in_reply_to` 寫的是新名字，原寄件人照舊名字等（`py/daemon_ctl/post.py:126`、`aos-llm` 同），對不上就一直等到逾時。
  - 實測：寄到判官的信名 `000000000003.…`，轉到 ctl 信箱變 `000000000002.…`，回信 `in_reply_to` 是 `000000000002.…`。
  - 同一個原因，判官「上一輪轉過了沒收完」的防重檢查（`_entry:184` 看 ctl 信箱有沒有同名）對有序信永遠不成立，判官在轉寄和收信之間當掉的話，有序信會被轉兩次。
  - 檔頭註解只寫了「有序信換了序號」，沒寫後果。
- **使用者原話**：N-16「`in_reply_to`（回信時寫原信的信件名稱）」（`05-N-16.md:6`）。沒找到針對判官轉有序信的原話，這是推論。
- **建議**：要使用者挑。
  - A（推薦）：文件寫明「經判官的信不要帶 `--ordered`，有序只保證到判官的收件箱為止」，判官收到有序信照轉成無序（不帶 `--ordered`、用尾名）。改動小，回信對得上；代價是有序保證在判官這裡斷掉。
  - B：判官記一張「新名字 → 原名字」對照表，由判官代回信。保住有序，但判官要多讀 ctl 信箱的回信，比較重。
  - C：維持現況，只在 kernel/docs/02 寫一句已知限制。
