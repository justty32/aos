## 四批之間打架

### 1. special-cases K3「設了但指不到照退路走」對 tick-time 使用者裁「當第 0 格、不改退路」
最該先修的一句；K 隊 `c56e53751` 寫的 K3 註直接跟 R 隊同檔下兩行、跟 tick-time 04 的裁定相反。細節見 [02 第 1 條](02-tick-time.md)，F 隊 [06 第 1 條](../06-special-cases抽核/01-發現.md) 從程式側也抓到。

### 2. C-52 的「現行清單」被三批各數各的
P5b 把 conventions 改成「剩兩處」→ J7 主檔寫「①③④」、conventions「三處」→ C-52 兩題後續檔「①③④⑤」、conventions「四類」→ special-cases 續檔改成判準＋八列表（⑧ 做完沒擦）。使用者已裁「判準＋現行表」就不該再數數字。見 [03 第 3 條](03-json-argv-J7.md)、[01 已核對](01-no-pid-P5b.md)。

### 3. N-28 `_tick`／daemon 型／`auto_restart` 疊成四層註
- **檔:行**：`proto8/docs/NORMS/04-基礎設施-loop與daemon/02-N-28.md:34-37`
- **commit／哪隊**：:36 P5b `85d9bc6d5`（規劃中「daemon 型才例外重起」）→ :37 P6 `cf250cef4`（已實作但不是 daemon 型、通用 `auto_restart`）；:34 T8 `a858fe1a0`（「`_tick` 照 daemon 型規則重起…已定」＋「已實作照 P6 改讀」）→ :35（改讀「沒有 daemon 型了」）
- **問題**：同一個事實（沒有 daemon 型；`_tick` 展開成寫了 `auto_restart: true` 的普通 proc）要讀四條互相指來指去的註才拼得出來；兩批（no-pid、tick）各自疊、沒合併。內容本身跟使用者「不要耦合」「通用 restart: true」一致，不是寫歪。
- **使用者原話**：「對於daemon來說，子daemon對他來說就只是一個普通的proc。不要耦合」（`no-pid/15-P6去耦合.md:7`）；N1「那兩題都按照推薦。」（tick-time 03:76）
- **建議**：雜活：四條合成一條「現況：`auto_restart` 通用布林，`_tick` 展開時寫 true；原句與歷程」。

### 4. 「唯一」兩個意思：P5b N-63「不寫唯一的路」對 K3「寫明唯一一條退路」
- **檔:行**：`01-N-63-三件事與跟實作對不上的.md:17`（P5b：環境變數不是唯一的路，argv／設定／信裡明給都算給）；`03-AOS_-變數的四種性質.md:22`（K3：沒設＝Missing 或唯一一條退路）
- **問題**：不衝突——前者講「怎麼給位置」（使用者原話撐），後者講「什麼都沒給時退哪」（使用者裁 K3）。但兩句相隔一檔都用「唯一」，讀快了會以為打架。品質；建議 K3 那句改「寫明一條退路（只能一條）」。

### 5. tick「兩個都給＝錯」對 json-argv「只吃想吃的、不報錯」——不是同一件事，但 `null` 的處理兩邊不一致
- `timeout_ticks` 跟 `timeout_s`／`timeout_ms` 擇一、兩個都給報錯，是 tick-time 03 §二代定（[02 第 5 條](02-tick-time.md)）；使用者「只吃想吃的」講的是多餘的 JSON 鍵忽略，兩個互斥鍵都給不在那句裡，所以沒打架。打架的是 `null`：inst 單子 `timeout_ticks: null`＝沒寫，thought／agents 收到 `null` 卻當「給了」報 `ArgumentsBad`；腦常填 `null`。跟 A 區 [01 第 3 條](../01-設定檔.md)（`tool_io` 對 `null`）同根。見 [02 第 8 條](02-tick-time.md)。
- 旗標映射：`timeout_ticks`（JSON 底線）↔ `--timeout-ticks`（argv 連字號）照 C-54／P-45，四處程式一致——沒打架。

### 6. 沒打架、核過的
- **P5b N-17「對 /proc 判活只剩 daemon」對 special-cases 題 1「不認身份、可認公開介面」**：讀 /proc 是 Linux 介面、不是認下層身份；使用者 11-06 晚「父daemon只看他有沒有活着」跟 C-52 續 :29「pid／訊號、公開 ctl／state 窗的回應」一致；lib 規則 11「不碰 pid」是工具層，P5b 說規則 11 不動是對的。
- **`_` 開頭保留**：tick-time 03 邊緣 8「`_` 留給 daemon 展開、撞名＝CfgBad」只在 thinking；special-cases 題 4 使用者「等撞名再說」→ 條文沒寫；daemon 只在 `tick.name` 真撞到既有 proc 時 `CfgBad`（`daemon.cpp:57-59`）。一致。
- **「近的贏」**：tick-time 03 代定 → daemon-board 題 2 使用者「設，近的贏」→ special-cases K4 推薦升格（沒問）→ tick-time 05 使用者「三個時鐘留著」。條文 N-28:73 寫已定對；K4 沒進條文；HANDOFF 說「T 隊又當方向題丟上來」指的是 05:37 建議拿掉領班的鐘，條文沒受影響。
- **special-cases K-2「daemon 不認 aos-loop 字句」對 N-43 續「有自己的 error 行＝自己錯」**：special-cases 自己盤出、改讀「看到 `RunFailed` 就是下層的碼」；K-2 後 loop 型 proc 的 `reason` 變成包裝行，這個後果在題 1 推薦項的後果欄寫了、使用者看過。
- **P5b「ctl 問詢改寄信等回信」對 tick T6「等待可寫 tick」**：`daemon_ctl.ask(timeout_ticks=)` 只加 keyword、預設仍 3 秒牆鐘；人打的 `--timeout-s` 照舊。一致。
