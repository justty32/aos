# 2026-11-07 sol 審查：11-06 起 codex sol 做的設定、條文、設計決定跟使用者原話對不對（總入口）

← [refactor](../../README.md)｜使用者 11-07：「不是審查source code，而是審查設定」，四類全審。對照基準一律是使用者原話（thinking 各題「原文／裁定」段、`proto8/user-advice/`）。只出報告、沒改任何其他檔。

## 白話總結

大方向沒有被偷換：消耦合、根 daemon 是普通 daemon、等多久由寄信者設、image 只留最新一份、鐘都留著，這些都有你的原話撐著，程式也照做了。引號裡的「使用者原話」絕大多數真的是逐字原話。

問題分三種。第一種是**真的會出錯的**，大多在邊上：寫時鐘的 `aos-tick` 不認空檔，整棵樹的 tick 期限會永遠不到期；LiteLLM 端點現在一定要 `LITELLM_KEY`，可是沒有任何地方設它；腦送 `null` 會被當成「給了壞值」；有序信經判官轉寄會換名字，回信永遠等不到；搬家食譜關了 gc 又不清，本機 `.git` 會一直長。第二種是**你裁了、但沒生效或寫反**：留格給高優先做了但範本沒開；搬家食譜教「只在樹根開 tick」，你選的是「三層各留」；hub 變數指不到你選「印 warning」，條文卻寫「照退路走」。第三種最多：**你點了「推薦」，agent 就把推薦旁邊的判準、自己補的理由、沒給你看過的例外，一起當成你裁過的寫進條文**——九個短名「表外不准開」、升格門檻的數字、K7 多出的例外、判官排隊「預設關」，都是這樣。

誰的鍋要分清：約一半問題其實落在 claude 隊長收稿或落地那一步（條文落地、裁定段多一句、刪授權句）；sol 本身引文準、搬檔逐字，毛病是把「推薦」寫成「一律」、順手多做沒攤出來。代定盤了 400 條，真正還在生效、沒給你看過的方向性只有 12 件，沒有一件是方向做錯，都是跳過「給你看」這一步。

## 最該先處理的五條

1. **時鐘會卡死**：`aos-tick` 遇到空檔就報錯不寫，daemon 重起三次後放棄，時鐘停在 0、所有 tick 期限永遠不到期。對齊成「空檔當第 0 格」就好 → [07 第 1 條](07-tick一致性實驗/02-發現.md#f1)。
2. **真腦必失敗**：三個 LiteLLM 端點現在一定要 `LITELLM_KEY`，試驗場、env.sh、systemd 範例都沒設 → [01 第 2 條](01-設定檔.md)。
3. **你裁了卻沒生效**：留格 `reserved` 範本沒寫、搬家食譜「只根開 tick」寫反、`/queue.json` 被擋掉等待時間歸零 → [04 第 3、4 條](04-設計規劃/05-no-pid-os-impl.md)、[01 第 4 條](01-設定檔.md)。
4. **判官排隊兩件**：「預設關」是頂層代定（你原話偏向排隊是常態）；一開排隊，取信順序就從「有序先」變成「照寄出時間」 → [05 § 1](05-代定盤點/01a-未裁逐條-1～6.md)、[08 第 1 條](08-信箱取件順序/02-發現.md)。
5. **推薦寫成已定**：P-44 九個短名「表外不准開」、升格門檻「第 3 次」、K7 多出的例外、N-28／N-16 把翻案包裝成改讀 → [02 § 1](02-條文-lift-to-norms/01a-要使用者裁的-1～3.md)、[04 第 5、6 條](04-設計規劃/01-special-cases.md)、[02a § 1-2](02-條文-lift-to-norms/02a-NORMS-1～5.md)。
