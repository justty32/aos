## 1. kernel 新的逐封帳 `ledger.jsonl`，等於把你 11-05 選的 `served.jsonl`「也刪」加回來

- **背景**：11-05 問你「每封信一行代號／模型／用量的紀錄要不要也拿掉」，你選了「也刪」（`proto8/thinking/2026-11/04/think-as-function/08-邊緣狀況實測.md:66`）。P2（`proto8/impls/aos-llm-kernel/src/serve/reply.cpp:100`）又加回一模一樣的東西，只記成代定 10（`arknights-kb/代定清單.md:16`）。引用你原話的文件行也被整行換掉了（`impls/aos-llm-kernel/docs/01-用法.md:41`）。
- **選項**：
  - **A★ 留著，算明說翻案**：寄件人不管是 agent、腳本還是人手 `ask`，都有逐封帳。代價是檔案會一直長（見[設計 8](03-設計問題.md)）。文件要補回「11-05 原裁也刪，11-07 翻」。
  - **B 照 11-05 拿掉**：逐封成本只靠 agent 的 `observed.jsonl`，不是 agent 的寄件人要自己記。
  - **C 留著，但只留最近 N 行**：多一套輪替機制。
- 不管選哪個，都要定 token 以哪份為準（[設計 6](03-設計問題.md)）。

## 2. `aos-daemon-ctl prune` 的自檢自己讀 `/proc` 比 pid，撞上 no-pid「只有 daemon 碰 pid」

- **檔:行**：`proto8/py/daemon_ctl/table.py:144-162`；`proto8/docs/NORMS/05-基礎設施-窗/06-N-17.md:5`。依據是你 11-05 晚的原話「所有牽涉到linux原生行程的機制，都以daemon爲界面」。
- 另外，這段用 Python 把 aos-util 的算法又寫了一份。你原本只說「自檢與清理」，要比 pid 是施工時自己代定的。
- **選項**：
  - **A★ 拿掉 pid 比對**，自檢只看檔案。代價：「表上 running 但行程已死」要等 daemon 自己發現。
  - **B 開明文例外**：no-pid 界線出現第一個缺口，兩份算法要一直同步。
  - **C 把比對移進 daemon**，寫進 `procs_state`：要改 C++，但界線守得住。你如果真想要這項檢查，選 C。

## 3. 對不讀 ctl 的程式下 stop，列會永遠停在 stopping，只剩 rm 一條路

- **檔:行**：`proto8/impls/aos-daemon/src/daemon/tend.cpp:113`；`proto8/py/daemon_ctl/ctl.py:26`、`:30`、`:33`（stopping 時 sleep 被 PhaseBad 擋下，提示還寫「stuck, or SIGSTOP」）
- B 之後任何東西都能 stop。一般腳本、伺服器收到 stop 只會一直等，`ls` 上也看不出來。rm 會連 launch 一起丟掉。
- **選項**：
  - **A★ stopping 的列准許 sleep**：改送 SIGTERM，退了留 stopped。這會改到你 11-05「嚴格分」的 PhaseBad，所以要問你。
  - **B 維持現狀**，只改提示和文件。
  - **C stop 加期限**，到期改送 SIGTERM：等於把 B 之前的退路加回來。

## 4. agents ask 的秒數上限是工具自己的寫法造成的，「比照 thought」照字面沒做到

- **檔:行**：`proto8/lib/agent/agents/_entry:42`、`:131`、`:466-467`；對照 `proto8/lib/agent/thought/_entry:133`（分段等，沒有上限）
- 同樣給 1e9 秒，thought 照等，agents 報 ArgumentsBad。
- **選項**：
  - **A★ agents 改用分段等**，拿掉上限：翻掉 E8 秒數那一半。
  - **B thought 也加上同樣的上限**。
  - **C 維持兩支不一致**。

## 5. #3「預設不帶有序」做出來後，有序信經判官的回信還是對不上

- **檔:行**：`proto8/kernel/docs/02-kernel-modes.md:22`（「要對上請寄一般信」，還掛著你的裁定標記）
- 頁面 3A 原本承諾「回信對得上」。
- **選項**：
  - **A★ 維持現況**，改標成落實代定：目前只有人手寄有序信才會撞到。
  - **B 判官轉寄時保住原信名**：要改判官。
  - **C 寄件端只比尾名**：信件格式多一條特例。

## 6. memory_write 的鎖用呼叫者自己的時鐘算租約，不同時鐘的 agent 共用知識庫時，鎖會失效

- **檔:行**：`proto8/lib/agent/memory_write/locking.py:99-106`。圖紙原本寫的是 10 秒牆鐘。
- D 實測：時鐘快的那一方 0.04 秒就收走對方還活著的鎖。同一個時鐘停住時，持有者被 kill -9 之後，鎖永遠不到期。
- **選項**：
  - **A★ 呼叫 aos-lock 時拿掉 `AOS_TICK`，改用牆鐘 10 秒**：精神上接近 N-65 ③「跨樹用毫秒」，改約 3 行。
  - **B 維持現狀**：跨樹共用由人保證大家用同一個時鐘。
  - **C aos-lock 加回 `--lease-ms`**。
