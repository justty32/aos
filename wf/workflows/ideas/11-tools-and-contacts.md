# 11 工具與通訊錄
← [入口](README.md)

模型要做事只有兩種對象：**程式**（工具）和**別的 agent**。兩種各有一份名單，而且是分開的兩份——工具那份叫登記表，agent 那份叫通訊錄。這章講這兩份名單怎麼寫、怎麼把工具講給模型聽、叫完之後結果怎麼回來。誰去跑、跑多久見 [呼叫與失敗](09-call-and-failure.md) 與 [時間](06-time-and-clocks.md)。

## 什麼東西算工具

門檻很低：能用一般方式（給一串參數、餵 stdin、看 stdout 和退出碼）叫得動的程式就是工具。

- 任何支援 POSIX 呼叫的程式都可以當工具；要有一份登記表，還要有一份給模型看的表述。〔裁決 2026-08-30〕
- 一個可執行檔就是一個工具；命令列參數天然就是它的引數；stdin／stdout／stderr 是特殊引數；來往的東西全是文字。〔裁決 2026-08-06〕
- 普通指令直接交給 shell，不用登記；只有指定資料夾底下的東西才登記成模型可用的工具。〔裁決 2026-08-06〕
- 不掃系統的 PATH 自動登記——登記是人的動作，不是掃描的結果。〔AI 觀察〕
- 子 agent 不是工具，不登記在這裡；它們走通訊錄。〔裁決 2026-08-30〕
- 登記表是一份**行為契約**：不只記怎麼叫得動，還記這程式大概會怎麼表現。`ls`、`cat` 永遠不會自我介紹，所以登記表要能替它代答；代填的欄位要標明來源是人填的。〔AI 觀察〕

## 登記表長什麼樣

一個工具一個檔，扁平的 json，沒有巢狀分層。

- 一工具一檔，路徑 `.aos/tools/<名字>.json`；多到爆再想怎麼拆，現在不考慮。〔裁決 2026-08-30〕
- 登記表住在**世界那一層**，不住在單隻 agent 底下——工具是這塊地的，agent 只是使用者。〔裁決 2026-08-30〕
- 必填只有三欄：名字、怎麼叫（固定的命令列開頭）、一句描述。〔裁決 2026-08-30〕
- 其餘欄位一律平鋪在同一層，不分組。〔裁決 2026-08-30〕
- 引數形狀三選一，登記時定：**逐項列表**（接在固定開頭後面，空白引號原樣保留、不經 shell）、**整串**（整段一個參數，只給 `sh` 這種）、**不收**。〔裁決 2026-08-30〕
- 不做 `{名字}` 這種具名槽——那條路的盡頭就是使用者判過失敗的那套綁定編譯層。〔裁決 2026-08-30〕
- 自我介紹用 `--metainfo` 這個旗標去探；第三方程式要明確開了才試 `--metadata`（怕撞到人家「寫入 metadata」的功能）。〔裁決 2026-08-30〕
- 同一欄有多個來源時，人手填的贏自述、自述贏預設；探不到就讀腳本檔頭註解，再不行要求人填。沒自述的不准推論成「安全」。〔AI 觀察〕
- 有狀態的工具，它的狀態放自己的地方，不要塞進 `.aos/`——那裡是機器的地盤。〔AI 觀察〕
- 除了必填三欄，還有一組描述行為的欄位（會不會留下痕跡、能不能安全地重跑、能不能中途砍掉之類），先存著不用；**誰第一個去讀它們沒定**。〔AI 觀察〕

## 「可預期性」是什麼意思

這個詞被特別重新定義過，容易誤讀，所以單獨講。

- 可預期性指的是**結果符不符合人的預期**，不是「同樣輸入給同樣輸出」。〔裁決 2026-08-30〕
- 值只有高、中、低三級；沒填就是「不知道」，不是「高」。〔裁決 2026-08-30〕
- LLM 類的工具不強制標低——欄位存在，但填不填由登記的人決定。〔裁決 2026-08-30〕
- 再上面那層（給工具發證、憑證才准進某個環節、可以撤照）是**刻意不做**，不是忘了；那是另一本帳，現在只做登記表。〔AI 觀察〕

## 給模型看的那一行

登記項是給機器讀的，模型看的是它的簡寫。

- 給模型的是一行純文字，一工具一行：名字、引數形狀、收不收 stdin、可預期性、一句描述、一個引數範例。模型回話的格式由我們自己嚴格檢查，不靠後端。〔裁決 2026-08-30〕
- 等到 `aos llm` 真的帶著工具清單對真後端打過一次，再升級成後端原生的工具呼叫。〔裁決 2026-08-30〕
- 描述裡要寫**代價**：慢、要花錢、結果不確定。這是「能查表就別問模型」的入口。〔AI 觀察〕
- 登記項是唯一的真相，OpenAI 或 MCP 那些格式都是從它匯出的投影，照一張固定的對照表產生；別把非標準欄位塞進人家的標準物件裡。〔AI 觀察〕
- 長說明和範例不進提示；模型想看就自己去 `cat` 說明檔，而且那份內容當**不可信資料**看。模型可以摘要它，但摘要不能反過來變成登記表的真相。〔AI 觀察〕

## 叫一次工具會發生什麼

- 一次工具往返固定佔三個回合（第一回合投遞、第二回合執行、第三回合收結果），**不壓縮**。〔裁決 2026-08-30〕
  - 新的時間模型下，慢工具改成生一塊自己走時鐘的小地去跑，主世界每一格只去看那塊地的結果檔在不在，所以「等很久」不再等於「卡住回合」。見 [agent](08-agent.md)。〔AI 觀察〕
- 結果用一個固定形狀的 json 封套退回給模型；成功和失敗同一個形狀，錯誤欄缺席就代表成功。〔裁決 2026-08-30〕
  - 封套裡有：呼叫 id、工具名、成不成功、結果、錯誤（種類＋訊息＋可不可重試）；輸出被截斷要標出來。〔裁決 2026-08-30〕
- 叫了不存在的工具、引數型別給錯，都要用結構化的訊息退回讓模型重選，**不能默默吞掉**。實測過：模型認得出缺口，但缺口不會自己變成動作。〔AI 觀察〕
- 危險工具的安全先不管。把 `sh` 登記給模型，就等於信任啟動這個迴圈的人。〔裁決 2026-08-30〕
  - 要交給非開發者用的那天，再加「投遞前先問人」這一層；白名單不該宣稱它提供安全。〔AI 觀察〕
- 外部的 coding agent 引擎會繞過帳本（它自己的工具動作不落在批次紀錄裡），這個洞先接受；之後用事件回填，把它每一對開始／結束補寫成一筆結果並標明來源。〔裁決 2026-08-30〕
- 大輸出不要整包塞進 json；登記表留一欄描述輸出形狀，之後大內容走檔案路徑。〔AI 觀察〕
- 工具結果要跟「哪一次模型決定叫它」用 id 串起來，否則事後追不回去。每回合留下的指令與結果是「把模糊的事固化成程式」的原料，別設計成會被清掉的暫存。〔AI 觀察〕

## `aos llm` 這支程式的形狀

- 它就是一支普通的 unix 過濾器：stdin 進、stdout 出。〔AI 觀察〕
- 退出碼要分流，不要全部 exit 1：跑成功、用法錯、後端或傳輸失敗（可重試）、被取消，各一種。〔AI 觀察〕
- 後端回的錯誤當**一等錯誤**處理，帶上狀態碼和回應片段，不要糊成一句話。〔AI 觀察〕
- 不要做 C 語言的二進位介面，也先不要為它單獨做常駐程式或限流器。〔AI 觀察〕

## 通訊錄

通訊錄回答的問題只有一個：**某某人住在哪個資料夾**。它不是登記表、不是白名單、不是權限。

- 通訊錄住世界那一層，檔名 `.aos/contacts.json`；手動維護，開一塊地時不碰它。〔裁決 2026-08-30〕
- 通訊錄跟工具登記表是兩份東西。〔裁決 2026-08-30〕
- 一個 agent 就是一個資料夾，所以每一列只要三樣：名字、資料夾、一句備註（備註選填）。不再有「那個世界裡的哪隻 agent」這一欄。〔傾向 2026-09-04〕
- 權威永遠是對方那個資料夾自己存不存在；通訊錄只是省一趟路的快取，可以過期。〔AI 觀察〕
- 使用者住在 `~`、也是一隻 agent（見 [agent](08-agent.md)），所以通訊錄天然有一格 `~`，不用落檔；訊息要帶「寄件人」欄。〔裁決 2026-08-30〕
- 對 agent 來說「寄信給某某」是登記表裡的一條工具；通訊錄只回答「他在哪」，投遞是工具做的。〔AI 觀察〕
- LLM 處理單元的地址不進通訊錄——那是引擎設定，跟 agent 混在同一張表會分不清對方是人還是一顆處理單元。等哪天所有端點都統一成「可以收指令的地址」再合併。〔AI 觀察〕
- 子 agent 用自己的引擎設定，不繼承父的；否則通訊錄會偷偷變成權限與執行設定。〔AI 觀察〕

## 我的意見

- **白名單大概可以直接拿掉。** 它原本是給「一個世界裡好幾隻 agent，各自能用哪幾樣工具」用的。既然一個 agent 就是一個資料夾，這個區分就沒對象了。留著只會讓人誤以為它是沙盒——它從來不是。

- **「代答」跟「宣告了就要做到」的界線要寫清楚，不然會被讀成兩條打架的規則。** 我的讀法是：代答的是人的**觀察與約定**（我看過 `ls`，它不改東西），標明來源是手填的；「宣告了就要做到」約束的是**程式自己吐出來的那份自述**。人可以補一句描述，但不能替一個沒宣告的欄位擅自填「安全」——沒說就是不知道。

- **那組描述行為的欄位現在是死的。** 名字定了、值也存了，但沒人定誰第一個讀。如果第一版迴圈一欄都不看，它們就只是註解，那不如老實承認是註解，等真要用時再一次拉起來，免得留下一堆看起來有效、其實沒人執行的宣告。

- **三回合往返跟互動體感打架，但答案可能不在這章。** 每叫一次工具延遲兩回合，聊天式互動會很鈍。舊補丁「同回合再跑一批尾巴」會破壞「一回合一批」這條乾淨規矩。新的時間模型給了另一條路——慢的搬去脫節小地，快工具照樣三回合、慢工具不佔回合。剩下要決定的只有：登記表要不要標「這工具算慢的」。

## 現況對照

- 今天的登記表已是 `.aos/tools/<名字>.json` 扁平 json，`aos tool add/ls/rm` 三支子命令，`add` 會去探自述。
- 今天的通訊錄是 `.aos/contacts.json` 頂層陣列，欄位還多一個「哪隻 agent」；`~` 是合成出來的一格，不落檔。
- 今天 agent 一回合只投一條工具指令，只認下一回合的產出，慢跑補跑的收不到；未知工具只寫一條註記，沒有結構化退回。
