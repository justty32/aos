# 第三輪：CPU 類比撐得住多少
← [call-format](README.md)｜[ideas](../README.md)｜[WORKFLOWS](../../../WORKFLOWS.md)

第一輪打格式、第二輪打原語，這一輪打**「更高層次的 CPU 指令」這個類比本身**——照真實
CPU 的標準去驗，缺了哪幾件。

> **使用者的總裁決**：**`aos core` 就是這一整套 CPU 類比（雖然不是完全類比）。**
> 缺件裡有三樣無解、認了，一樣有解、就是 loop。

## 三樣無解的缺件（已認）

**沒有原子性。** 真實指令要嘛退休、要嘛沒發生。一筆 inst 可以跑到一半 crash，留下寫了
一半的 `stdout`、沒寫的 `exit`——世界會停在 **state N.5**，不是 N 也不是 N+1。而整個
模型建立在「一份 inst 推進一回合」上。`.runi` 保留現場是**事後有屍體**，不是**轉移是
原子的**。

**指令集不是封閉的。** CPU 的 ISA 可窮舉、有版本、是契約。這裡的「指令集」是「這台
機器上恰好裝了什麼」——開放、無版本、隨環境漂移，同一份 `inst.json` 在兩台機器是兩套
ISA。這正是[「是機制不是約定」](universality.md)在 CPU 類比裡的對應面。

**沒有確定性。** 同樣的 state ＋ 同樣的 inst 不保證同樣結果（時鐘、網路、環境）。回合
制模型最想要的「可重播、可稽核一個回合」目前不成立。

**裁決：這三樣確實都沒辦法，這終究不是能完全類比 CPU 的。**

## 第四件缺件有解：控制流就是 loop（方向已定）

一批 inst 沒有 PC、沒有跳轉、沒有分支——「上一筆失敗就別跑下一筆」目前表達不了。
[exit status 要改](universality.md)之後會立刻撞上「那誰讀它、誰決定下一步」。

**裁決：控制流這塊 loop 確實會是重要一環**，所以 `aos core` 才是「這一整套 CPU 類比」
——`exec` 是指令、`exec_loop` 是取指與控制流，兩個合起來才是那顆 CPU。這也解釋了
[core-layering](../core-layering.md) 為什麼把 loop 放進 core 而不是外掛。

## daemon 讓世界外溢——答案是 GPU 模型（方向已定）

**問題**：模型第一句是「指定資料夾是被演化的世界／狀態容器」，但常駐 daemon 的 KV
cache、連線、對話歷史也是世界狀態，**而且不在資料夾裡**。把資料夾回滾到 state N 再跑
一次不會得到 state N+1，因為 daemon 記得上一次。

**裁決**：LLM CPU 就是常駐 daemon，而交流方式是——**把 LLM 工作要求透過特定指令投遞到
外部資料夾，好了之後它會寫回來，就類似 CPU 與 GPU 的交流。**

這是 mailbox／DMA 模型，順手決定了兩件事：

1. **它回答了 [decided-and-open](../turn-based-folder/decided-and-open.md) 那條開放
   問題**（抽象 CPU 的回合是同步跑完還是只做投遞）——答案是**投遞**。
2. **代價要講明白**：這條是**非同步**的，所以 LLM 的結果落在**未來某個回合**，不是發起
   它的那一回合。`aos exec` 那條「等所有 thread 跑完才算本回合結束」的邊界**對 LLM CPU
   不適用**。世界仍然外溢在 daemon 裡，只是交換點被收斂成一個資料夾——這讓它**可觀察**
   了，但沒讓它**可重播**。

## 權限：安全交給其他人

彙整把多個生產者併成一批（`inst.tempd/<pid>.json`），**pid 只是檔名，沒記誰投的**——
自己寫的 inst 和 LLM 生成的 inst 同批同路，上層想分級也沒有資訊可分。
**裁決：權限與安全這塊交給其他人，核心不管。** 同 [universality](universality.md)。

## 還開著的

- **外層契約會反噬基石**：一旦外層有了型別、回傳值、高階形式，有意思的工作都會搬上去，
  內層退化成啟動器（syscall → libc → framework、shell → make → CI DSL）。要問的是那個
  契約**還在 inst 之上嗎**——若它需要自己的執行器，「fork/exec 是基石」就變成
  「fork/exec 是最終落地方式」，從地基變後端。**裁決：還沒想好。**
- **plan 9 只解命名空間、不解執行**：9P 把遠端掛成檔案跟模型同構，但指令仍在本機跑，
  只有 I/O 走網路；要計算跑遠端得靠 plan 9 的 `cpu` 那類東西。**要標紅的是**：整套交接
  協定（投遞／彙整／取件）建立在「同目錄 rename 是原子的」之上，**跨 9P 的 rename 原子
  性與快取一致性不是白送的**，落地前要驗。
- **這顆 CPU 沒有停機**：沒有 halt、沒有終止狀態、沒有「已到達目標狀態」的表達方式，
  `--loop` 就是一直跑。而何時停下來是 agent 系統最難的問題。**裁決：之後在 loop 內再
  說。**
