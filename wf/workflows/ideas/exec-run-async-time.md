「限制慢指令」與「async 是什麼」的時間模型。

## 使用者原話（2026-09-04）

> 限制這塊，確實可以用timeout方式，但我更傾向於用環境變數去限制，也就是讓他可以用的指令，全都是很快就結束的。然後async:true這塊，在我們的模型裡，其實像是世界時序脫節：父資料夾是大世界、子資料夾是其中的一塊地，通常情況下一次tick(exec)，就是父世界動、子世界跟著動，全部動完才算tick結束；而async:true就是讓某個子世界的時間和父世界的時間脫節。

## 使用者傾向／使用者定義（未明說裁決）

- **使用者傾向**：限制同步工作的主方法是環境變數，讓它能用的指令全都很快結束；timeout 可以有，
  但不是首選。
- **使用者定義**：平常一個父 tick 會連子地塊一起推完；`async:true` 是讓某個子世界的時間跟父世界
  脫節。

## AI 觀察（非裁決，可否決）

### A. 環境限制 vs timeout

**timeout 是事後保險絲；環境限制是事前保證。** timeout 等程式已經跑太久才殺掉它；環境限制則在
開跑前就只給它一組時間有上限的東西。既然已裁**可預測性最優先**，主線應是事前保證，timeout
降級成最後一道保險絲。前篇 [§e](exec-run-async.md#e-沒辦法實際限制其實可以限制但那是另一顆-key)
把 timeout 接到 RTOS，現在應照這個位置重讀。

這也接上已裁的**資料夾＝環境**：一個資料夾能用哪些指令，由該資料夾的環境決定。實作上很可能
就是把該資料夾的 `PATH` 限到只指向一小組允許的東西。

但「快」不是指令本身永遠不變的性質。`cat` 遇到大檔也會慢，`curl` 更要看遠端什麼時候回話。
真正要分的是：

- **時間由自己決定**：輸入規模有界、最壞時間說得出來。
- **時間由外面決定**：網路、外部服務、等別人回覆；自己保證不了何時結束。

因此完整規則要兩條合起來：**同步世界只准放時間有上限的原子；時間看外面的一律搬去脫節子世界。**
一個 tick 只有有限個原子，而且每個原子都有上限，tick 長度就天生有上限。這才是 RTOS 主線要的
可預測性，而且不靠事後殺行程。原子這一層見 [top-to-bottom/04](top-to-bottom/04-atoms.md)。

直接後果是：今天 `aos agent` 一步裡同步等 `curl`，在這套規則下**不合法**。目前路徑是
`core/agent/src/step.cpp` 的 `step()` → `complete_locally()` → `aos::llm::complete()`；前篇已查過。
LLM 的時間由外面決定，所以 LLM 呼叫必定要成為 async 子世界。**這是模型與現有程式對不上的一條。**

### B. `async` ＝世界時序脫節

預設情況是：一次 tick，父世界動，所有子地塊跟著動，全部動完才算 tick 結束。這就是昨天
「**正常次序求值**」的時間版講法：父 `.aos` 點到子資料夾，才沿著唯一的橋
`aos run <child>` 去推它，而且父會等這次求值完成。

`async` 則是：**某塊地有自己的時鐘，父 tick 不等它。**

這跟頂層很對稱。頂層資料夾對使用者本來就是脫節的——使用者只偶爾來看一眼；async 子資料夾，
就是在世界裡再長出一塊「像頂層一樣」的地。**每個 `aos run` 就是一個時鐘；同步子世界借父的
時鐘，脫節子世界自己有一個。**

父要拿結果時，不必改前篇的答案：父在自己的 tick 看子的 `out/` 在不在；不在就當這回合還沒有，
在了才讀。這和前篇提的「固定路徑的檔」是同一件事。

這個說法立刻生出兩題，現在不答，放回玩的清單：

1. **誰讓子時鐘走？** 父 fork 一個 `aos run`，還是交給 daemon 接手？
2. **父死了，子時鐘要不要繼續？** 「脫節」表示可以繼續，這既是好處，也是孤兒風險；接
   [play-watchlist 第 4 條](play-watchlist.md#4-資料夾壽命)。

## 現有 aos 對照

| 模型裡的說法 | 今天程式裡的情況 | 對照 |
|---|---|---|
| 父 tick 等同步子世界全動完 | `aos run --step 1` 一回合＝`start_all()` ＋ `wait_all()` | **已有**：回合會等整批完成 |
| 子世界借父時鐘 | inst 裡跑 `aos run <child>` 是阻塞的子行程 | **已有**：父等子跑完才結束 |
| 脫節子世界有自己的時鐘 | 沒有直接對應物；最接近的是 `core/tick/src/tick.cpp` 的 `run_tick()` → `loop::deliver()` | **沒有**：tick 只投 inbox，不替子世界持續跑 |
| 用環境限制同步世界能做什麼 | 今天沒有依資料夾限制 `PATH` 或允許指令集合 | **沒有** |
