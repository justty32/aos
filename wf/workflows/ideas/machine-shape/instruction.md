# inst 作為 CPU 指令的地位
← [machine-shape](README.md)｜[ideas](../README.md)｜[WORKFLOWS](../../../WORKFLOWS.md)

> **貫穿三份的一條線**：`instruction` 第 1、2 條與 `loop` 第 6 條是**同一個決定**——
> **給「批」一個名字和一個 header**，它同時解決 ISA 版本、指令來源、與 loop 分支所需的旗標。

## 1. 被命名的那個東西，不是指令

已定案「**一回合＝一整批，不是一次一筆**」。那麼**真正的指令是「批」**——它才是造成一次
狀態轉移的單位；`inst_t` 比較接近 VLIW bundle 裡的一個 slot、或一條微指令。

但 `inst_t` 有名字、有 C++ 型別、有 C ABI、有序列化，而**「批」什麼都沒有**：匿名 JSON
陣列，沒有型別、沒有 id、沒有 header。於是所有屬於「一條指令」的東西都無處可放——批的
id、來源、版本、整體狀態、postcondition。

**想確立 ISA 地位，但被命名的那個東西不是那個地位的持有者。** 這不是缺陷清單的一項，是
**名字放錯層級**，而名字放錯會讓後面每個決定都往錯的層去。

## 2. ISA 是跨時間的契約，這個格式沒有版本

沒有版本欄位。目前策略是「未知 key 一律拒絕」＝舊執行檔遇新格式**硬失敗**（刻意的，
好）；但新執行檔遇舊格式**靜默接受**，也無法表達「這批需要 aos ≥ X」。對一個**要讓 LLM
生成、且格式一定會演化**的 ISA，這是很貴的省略——而它極便宜，批有 header 之後就有地方
放。

## 3. 有指令，但沒有「程式」

CPU 有指令也有程式：可命名、可重用、可參數化、可跳進去的一段。aos 只有前者，每回合都是
現場組出來的**直線碼**，沒有機制能說「跑那個叫 X 的批」。

而 `$ref` 已經很接近了——**它取的是值，不能取指令**。若 `$ref` 能引用一整筆或一整批
inst，立刻得到副程式：具名、可重用、LLM 可引用而不必每次重生成全文。**這是整串裡槓桿
最高的單一擴充**，不需要新機制，只是把指示詞的值域從「字串」擴到「指令」。

代價：`$ref` 會從「求值」變成「連結」，循環偵測的意義從資料環變成遞迴。但循環偵測本來
就有了。

## 4. 沒有架構狀態，只有檔案系統（建議正名）

沒有暫存器、沒有累加器、沒有旗標暫存器；指令 N 留東西給 N+1 只能寫檔。

**這是乾淨的設計，值得正名**：它是一台 **memory-to-memory 機器**，架構狀態就是資料夾。
好處是——一旦承認這點，[prior-work](../prior-work.md) 的 `/self/state`、`/self/round` 那套
projection 就不是「額外功能」，而是**這台機器的暫存器檔**，本來就該在規範裡有固定位置。

代價：**沒有便宜的暫存**，任何中間值都是一次 open/write/close/open/read。粒度地板因此比
fork/exec 本身還高一階。

## 5. von Neumann 且指令流可被指令改寫——這正是機制本身

`.aos/inst.json` 住在它所修改的世界裡，一筆 inst 可改寫下一回合的指令。真 CPU 也是 von
Neumann，但有 MMU、有 W^X；這裡沒有——**而且不該有**，因為「LLM 在回合之間寫下一回合的
指令」正是這台機器要幹的事。

所以問題不是要不要禁，而是：**要不要區分「經彙整祝福的指令」與「直接寫進去的指令」？**
目前兩者不可分（見 [feedback-and-failure](../call-format/feedback-and-failure.md) 第三條）。
要 ISA 有地位，這個區分大概是必要的——否則「指令從哪來」永遠答不出來。又回到第 1 條。

# 第九輪（實測）

## 18. 整批在任何一筆執行之前就全部 resolve 完 → **一個回合內不可能有資料流**

`run_batch.cpp:102` 的順序是死的：先跑完一整個迴圈把**每一筆**都 resolve（任一筆失敗就
`return 1`，整批不執行），**然後**才建 thread 執行。所以 **`$ref` 不可能引用同一批裡前一
筆產生的檔案**——那個檔案在 resolve 當下還不存在。

三件事疊起來：一回合＝一整批（已定）＋批內依賴邊執行器看不見＋批內 `$ref` 在執行前就求
值完畢。結論：**一個回合是純粹的並行構造，內部沒有任何資料流，所有鏈接都必須跨回合。**

這不是缺陷，是個乾淨的語意——但它**沒有被寫在任何地方**，而它是這個 ISA 最重要的約束
之一。

## 19. 這台機器已經有一條四階段管線，只是沒說出來

```text
claim（rename → .runi）     = fetch      取指
resolve（$env／$ref 求值）   = decode     解碼
fork/exec                   = execute    執行
exit 檔                     = writeback  寫回
```

這個框架直接切開了「loop 的職權」與「inst 的地位」：**loop 擁有 fetch 與 writeback，
exec 擁有 execute，decode 目前卡在錯的一層**（[core-layering](../core-layering.md) 把
resolve 留在最內圈；照這條線它屬於 decode，不屬於 execute）。

也修正了[第一輪的一個判斷](../call-format/format-gaps.md)：`$ref` 讀檔不是「求值語言汙染
最內圈」，而是**解碼階段本來就該做的事**——真正的問題只是它被放錯圈，不是它不該存在。

**四階段裡三個有名字，只有 writeback 沒有**：`exit` 只寫單筆，沒有整批的。那正是 loop
缺的旗標暫存器。
