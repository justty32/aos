## aos 是什麼

一個 agent loop（一顆 LLM、一組工具、一個反覆執行的迴圈）可以當成一顆 CPU。aos 是站在這顆 CPU 上面的作業系統。它的記憶體就是檔案系統：一個資料夾就是一支程式，也是這支程式正在跑的樣子。資料夾裡有一個 `.aos/` 目錄，那是機器的地盤；裡面有一段命令腳本，最底下是一次工具呼叫或一次 LLM 呼叫。`aos exec` 讓一個資料夾走一步，`aos run` 反覆走到沒有新事可做，daemon 管所有正在走的資料夾。子資料夾預設躺著不動，父資料夾點名才開。時間不進世界的語意，一切以回合算。要優化的不是速度，而是可預測性（最優先）、花的錢、人看不看得懂。這套構想講的就是這些：空間怎麼切、程式長什麼樣、時間怎麼走、agent 是什麼、東西怎麼呼叫怎麼失敗、還有哪些沒定。

## 怎麼讀

- 規定版（spec）在 [../spec/README.md](../spec/README.md)，要寫程式看那邊，這裡只留想法。
- **第一次讀**：01 → 02 → 04 → 06 → 08，這五章是骨幹，讀完就知道整套在講什麼。
- **要寫 spec**：全部都要，順序照編號；09 與 05 是格式最多空位的兩章，寫 spec 時先從那裡的待決定開始。
- **只想知道還缺什麼**：直接看 13，再回各章的「待決定」表。
- **可以跳的**：10（門房）與 11（工具）是相對獨立的兩塊，不影響理解主幹；12（指令面）給要動手的人。
- 每條細項句尾的標記：〔裁決〕＝使用者拍板；〔傾向〕＝使用者說了定義或偏好但沒拍板；〔AI 觀察〕＝AI 提的、沒被否決也沒被採納。09-04 那批幾乎全是〔傾向〕，要不要升格見 13 章。使用者回「的確會是這樣」的那一整套走法算〔傾向〕，走法之內個別 AI 推論仍是〔AI 觀察〕。
