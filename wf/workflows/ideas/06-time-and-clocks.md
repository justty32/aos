# 06 時間與時鐘
← [入口](README.md)

這章講 aos 裡的時間怎麼算。一次 `aos exec` 是一格，一個 `aos run` 是一個時鐘；子資料夾平常跟著父走，標了脫節的子資料夾自己有鐘。時間為什麼重要：可預測性是第一優先（見 [什麼與目標](01-what-and-goals.md)），而可預測性的根就是「一格多長」說得出來。空間的部分在 [一塊地](03-land-and-life.md)，時鐘由誰推在 [daemon](07-daemon.md)。

## 一格時間＝一次 `aos exec`
`exec` 不是把事做完，是讓世界往前一格就交回控制權。

- **一格＝一次 `exec`**：對資料夾就是讓它的 `.aos` 走一步；走完控制權交回，下一格要不要走由外面的鐘決定。〔傾向 2026-09-04〕
- **像遊戲引擎的一格**：每跑一次 `exec` 等於遊戲的 `_process()` 被叫一次——世界不是被一支長跑程式一直改，而是每格被叫醒一次、做完就返回。〔裁決 2026-09-01〕
- **一批就是一格**：一格掃所有該動的東西，不是一次只動一筆；要模仿的是遊戲引擎一格掃過所有東西，不是單發射的 CPU。〔裁決 2026-09-01〕
- **一格內沒有資料流**：一格裡的指令彼此不接管線，所有前後銜接都跨格（細節在 [`.aos` 裡面](04-inside-aos.md)）。〔裁決 2026-09-01〕

## 一個時鐘＝一個 `aos run`
`run` 就是反覆 `exec`，反覆的方式就是這個時鐘的規格。

- **三種走法**：跑固定次數、每隔一段時間跑一次、跑到某條件成立。〔傾向 2026-09-04〕
- **通用停法**：這次 `exec` 沒產出新指令就停。〔傾向 2026-09-04〕
- **白話解釋**：再 `exec` 一次資料夾也不會變了，就是到底了；但 LLM 不保證每次一樣，所以「到底」可能永遠不來，要有預算保底（預算單位放 [寫→編譯→執行](05-write-compile-run.md)）。〔AI 觀察〕
- **停的原因要看得見**：寫成檔案或步數，不藏在 daemon 記憶體裡；行程掛掉再起來，人要看得出為什麼停、接下來會怎樣。〔AI 觀察〕
- **時鐘由 daemon 推**：出生先登記、關機一次全停、父鐘掛了子鐘照走——這些歸 [daemon](07-daemon.md)，這章只說「每個 `run` 就是一顆要登記的鐘」。〔傾向 2026-09-04〕

## 時間不進世界語意
世界是回合制的，「經過了多久」不是輸入。

- **回合制**：不以「經過多少時間」當語意輸入；輪詢週期只是實作細節，不代表世界內的時間。〔裁決 2026-08-26〕
- **誠實版本**：回合的內容不含時間，但回合的觸發是時間驅動的（每隔多久跑一次是牆鐘）；改成檔案一到就叫醒才是真的事件驅動，這件事之後在 `run` 那層做。〔裁決 2026-08-28〕
- **借的是呼叫結構不是參數**：遊戲引擎比喻借的是「每格叫一次、自己在預算內返回」，不是 `delta` 那個參數；真實時間只用在節奏。〔AI 觀察〕

## 同步子世界借父的鐘
平常子資料夾沒有自己的時間。

- **父動子動**：父動一格，父 `.aos` 點到的子也跟著動一格；全部動完，父的這一格才算完。〔傾向 2026-09-04〕
- **這就是「父點名才開」的時間版**：父沿著 `aos run <子>` 那座橋推它，而且等它做完；同步子世界沒有另一顆鐘。〔AI 觀察〕
- **代價就是定義**：同步子世界慢，父這一格就慢；不想被拖就改成脫節。〔AI 觀察〕

## 脫節子世界自己走
「脫節」（`async`）不是偷開執行緒，是讓子世界的時間跟父世界脫節。

- **定義**：某塊地有自己的時鐘，父的那一格不等它。〔傾向 2026-09-04〕
- **父怎麼拿結果**：父在自己的那一格看子的 `out/` 在不在；不在就當這回合還沒有，在了才讀。〔傾向 2026-09-04〕
- **結果落在固定路徑一個檔**：這半句是提議，未裁，細節在 [呼叫與失敗](09-call-and-failure.md)。〔AI 觀察〕
- **不開執行緒，開子資料夾**：執行緒住記憶體，父掛了一起消失，磁碟上沒痕跡；子資料夾住磁碟，看得到、殺得掉、能重跑。〔AI 觀察〕
- **脫節與 timeout 是兩回事**：timeout 是「在這裡跑但不准超時」，脫節是「去別處跑，父不在這裡等」。〔AI 觀察〕
- **跟頂層對稱**：頂層資料夾對使用者本來就是脫節的（他只偶爾來看一眼）；脫節子資料夾就是在世界裡再長一塊像頂層的地。〔AI 觀察〕
- **兩種鐘**：父的鐘是週期性的；一次 LLM 請求那種小地的鐘只跳一下（跑一次、寫結果、結束）。〔AI 觀察〕

## 時間要有界
一格多長要說得出來，主方法是事前限制，不是事後殺。

- **主方法是環境限制**：讓這塊地能用的指令全都很快結束；timeout 可以有，但不是首選。〔傾向 2026-09-04〕
- **事前保證勝過事後保險絲**：timeout 是程式跑太久才殺，環境限制是開跑前就只給有上限的東西；可預測性最優先，主線該是前者。〔AI 觀察〕
- **「快」要分兩種**：時間由自己決定（輸入有界、最壞時間說得出）和時間由外面決定（網路、外部服務、等別人回覆）。同步世界只放前者，後者一律搬去脫節子世界。有限個有上限的原子，一格才天生有上限。〔AI 觀察〕
- **實作大概是限 `PATH`**：把該資料夾的 `PATH` 限到只指向一小組允許的指令，接上「資料夾＝環境」。〔AI 觀察〕
- **直接後果：LLM 永遠脫節**：同步等 LLM 回話不合法，LLM 呼叫一定是脫節子世界（要不要正式裁見 F-02）。〔AI 觀察〕
- **更早就有的靠山**：LLM 這類「抽象 CPU」走投遞式，工作投出去、好了寫回來，結果落在未來某個回合，像 CPU 對 GPU。〔裁決 2026-08-28〕
- **timeout 住在外圈**：真要有 timeout，由 `run` 那層管，不塞進最內圈的指令執行。〔裁決 2026-08-28〕

## 一格有預算
一格能做的事有上限，做不完的等下一格。

- **超預算就等下一格**：這次 `_process()` 超過預算，其他事等下一次再做。〔裁決 2026-09-01〕
- **一格內的四步**：觀察外界與自身、看自身目的、決策、行動（遊戲 AI 常用的 GOAP 那套）。〔裁決 2026-09-01〕
- **每格預算＝軟即時的期限**：不是硬保證，是「這格最多花這麼多」；引擎從不搶佔，靠每格自願返回。〔AI 觀察〕
- **執行到一半的動作怎麼記**：自願返回要求能中途封存意圖，半成品要能被下一格讀懂；這件事還沒形狀（見待決定 F-05）。〔AI 觀察〕

## 節奏差一個數量級不是缺陷
快世界慢世界並存，是設計特性。

- **一次跑十幾分鐘正常**：REPL 的節奏差一個數量級是特性不是缺陷；使用者可能同時跟多個慢 REPL 交流。〔裁決 2026-09-01〕
- **REPL 是非同步的**：送出、之後被通知，不是按 enter 等結果。〔AI 觀察〕
- **一致性視窗**：不同節奏的世界共享資料夾時，慢世界會整格拿著過期資料在跑；這跟「兩顆 CPU 共寫一份記憶體卻沒有記憶體模型」是同一筆帳。〔AI 觀察〕

## 我的意見
1. **同步子世界能不能再開子世界、還含 LLM？** 「借父的鐘、全動完才收格」乘上「一格要有上限」，只要同步子世界底下任何一層藏了一次 LLM 呼叫，上限就保不住。現在「LLM 永遠脫節」只是 AI 觀察加一句「的確會是這樣」，建議明寫成規則：同步子世界的整棵樹裡不得有 LLM 或網路。
2. **LLM 吐出的清單裡有慢指令，誰判定？** agent 所在的同步地不准跑 `curl`，可是 LLM 常會吐出 `curl`。靠 `PATH` 沒那個指令就直接失敗，是最誠實的事前保證，但失敗得回到 LLM 眼前它才學得會；讓清單自標「這條要脫節」是糖，得有人（載入器或 `run`）翻譯成開一塊小地。兩種可以並存，先定預設。
3. **父分不出「還沒好」與「永遠不會好」。** 這章只給「檔在不在」兩態；脫節子地被殺、逾時、關機一次全停，父看到的都是「不在」。這是失敗語意的一部分，放 [呼叫與失敗](09-call-and-failure.md) 處理，但時間模型至少要留一個「這顆鐘還在走嗎」的查法。
4. **「有變動才動」與「有 agent 的世界沒有空回合」是同一個痛點。** 每隔多久跑一次的鐘，在沒事時也在燒空格；「沒新指令就停、有信進來就醒」其實已經是第三種模式的雛形，差的只是叫醒的門鈴（見 [門房](10-doorman.md)）。建議不另立模式，把它寫成「條件模式」的一種條件。
5. **08-30 那套「同步等、佔住回合」的排程機制不進正文。** 它是對舊程式的裁決，跟 09-04 的時間模型直接衝突；保留的概念（並行上限、排隊、優先序）在 [daemon](07-daemon.md)。

## 現況對照
- 今天 `aos llm` 與 agent 的一步都同步等 HTTP 回來，模型判這條不合法（09-04 盤點）。
- 今天在指令裡跑 `aos run <子>` 是阻塞子行程，只有「同步借鐘」；「脫節子世界自己有鐘」沒有對應物。
- 今天指令有 `timeout_ms`、超時整組殺掉；沒有依資料夾限 `PATH` 的機制。
