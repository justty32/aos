# 第四輪：交接協定的實作缺陷，與世界／歷史／控制流的邊界
← [call-format](README.md)｜[ideas](../README.md)｜[WORKFLOWS](../../../WORKFLOWS.md)

前三輪打格式、原語、CPU 類比。這一輪打**交接協定**（投遞／彙整／取件）與**世界邊界**。
前三條是讀 `core/inst/src/handoff.cpp` **驗證過的實作缺陷**，不是推論；後五條是設計點。

> 實作缺陷的可查版本記在 [common/gotchas](../../common/gotchas.md)；這裡留的是它們對
> **設計**的意義。

## 一、`.runi` 不是一把鎖（實作缺陷，已認）

[layout-handoff](../turn-based-folder/layout-handoff.md) 寫「它固定名稱，所以**天生就是
一把鎖**」。實作（`core/inst/src/handoff.cpp:158-179`）是：

```text
lstat(runi)      → 存在就回 Busy
read_file(base)  ← 先把 inst.json 讀進來
rename(base, runi)
```

- **POSIX `rename()` 靜默覆蓋目的檔**——它原子，但**不互斥**。互斥全靠前面那個 `lstat`
  撐著，那是 check-then-act，中間有窗口。
- **`read_file` 在 `rename` 之前**。兩支同時進來的 `aos exec` 會**都讀到同一份
  `inst.json`**，然後都 rename。後果**不是**弄丟現場，是**同一個回合被執行兩次**。

對「一份 inst 推進一回合」的模型，同批跑兩次是最壞的失敗。rename 不是互斥原語；要互斥
得用 `link()`（目的存在即失敗，可攜）、`renameat2(RENAME_NOREPLACE)`（Linux only）或
獨立 lock 檔 `open(O_CREAT|O_EXCL)`。

## 二、沒有任何 `fsync`（實作缺陷，已認）

`core/inst/src/` 底下 grep 不到 `fsync`。`rename` 保證目錄項原子替換，**不保證內容已
落地**——崩潰後可以得到一個已改名、內容零長度的 `.runi`。而崩潰後的整套故事都押在
「`.runi` 保留現場等人處理」，**保留下來的可能是空的**。順序要是：寫檔 → `fsync(fd)`
→ `rename` → `fsync(dir_fd)`。

## 三、`<pid>.json` 不唯一（實作缺陷，已認）

投遞用 pid 當檔名，理由是「`rename` 原子但寫入不是，共用檔名會互相蓋寫」。但 **pid 會
回收、會 wrap，跨 namespace／容器直接撞**——對一個結構性問題，pid 只給統計上的保證。
`mkstemp` 或 pid＋亂數成本幾乎為零。

> **裁決（一～三）**：前三條的設計確實還要調整，**之後實作的時候自然會想到更好的
> 想法**。

## 四、世界沒有圍牆 → 用 git（方向已定）

一筆 inst 可以寫絕對路徑、覆寫 `cwd`、`rm -rf ~`。所以「資料夾＝世界」是一句**沒有機制
支撐的敘述**，回合的效果不被侷限在世界裡。代價是快照、回滾、複製去重跑、資料夾之間
演化獨立——這幾件「資料夾是世界」本來該白送的好處，一件都拿不到。

**裁決：沒關係，快照／回滾／複製這些都打算用 git 做。** 也就是版本邊界不由 aos 自己
發明，直接借既有工具。

## 五、沒有回合編號、沒有歷史、沒有 trace（要補，補在 loop）

`release_instruction` 的實作是 `unlink(runi)`（`handoff.cpp:191`）——**跑完就刪**。所以
N 個回合之後，系統裡沒有任何東西記得那 N 個回合：沒有回合計數器（模型寫 `state N`，
但 N 不存在於系統中）、沒有指令 trace、沒有結果歷史。

這打到核心價值「使用者可以在回合之間介入」——介入需要知道發生過什麼，人要知道，要決定
下一步的 LLM CPU 更要知道，而現在兩者都只看得到當下這一格。一顆 CPU 至少有 PC 和暫存器
可看，這裡連「現在第幾回合」都答不出來。

**裁決：這確實是實作上要添加的新東西，應該會在 loop。**

## 六、PC 不會自己前進（這就是要的）

loop 做的是彙整 → 取件 → 執行 → 再來一次，**它從不計算下一條指令，只是等別人投遞**。
真實 CPU 的 PC 自己會走（`PC += 4`），跳轉是改寫它；這裡的「PC」只有一個狀態：有沒有人
放東西進 `inst.tempd/`。沒人投遞，世界就空轉。

誠實的說法是：**`exec_loop` 是取指單元，但控制流不在系統裡**，它在投遞者手上（人、或
那顆 LLM CPU）。**裁決：這就是我想要的。**

> 與第五條合起來是這輪最尖的一句：**負責決定控制流的那一方，看不到執行歷史。** 第五條
> 補上歷史之後這句才解除。

## 七、嚴於解析、鬆於執行（刻意的）

`format.md`：「任何一筆失敗都不會執行其中任何指令」——整批驗證，全有全無。
`exec.md`：非零狀態、訊號終止、找不到命令、逾時，「不會中止後續的記錄」。
於是一個拼錯的 key 殺掉整個回合，一支把資料夾刪光的指令不影響下一筆。

**裁決：這是刻意的——序列化本來就要是嚴格的格式，而 `inst_t` 的實際執行那塊故意弄鬆。**

## 八、delta time 從 loop 走回來了（之後在 loop 處理）

模型第一句是「**不以經過時間作為語意輸入**」，但 `--loop <間隔>` 用牆鐘輪詢、
`timeout_ms` 是牆鐘。所以一個回合**什麼時候發生**取決於輪詢間隔——那就是 delta time
換了個位置。誠實的版本是「**回合的語意內容**不含時間，但**回合的觸發**是時間驅動的」；
改成 inotify 之後觸發才真的變事件驅動。**裁決：之後在 loop 去弄。**
