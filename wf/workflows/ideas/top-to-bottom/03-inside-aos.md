# 03 · `.aos` 裡面：一段命令腳本

← [top-to-bottom](README.md)｜上一層 [02-folders](02-folders.md)｜下一層 [04-atoms](04-atoms.md)

上一層講的是**資料夾之間**；這一層鑽進 `.aos` 裡面，看**一個資料夾自己怎麼一步一步走**。

## 本質：`.aos` 裡就是一段命令腳本

**裁決（2026-09-03）**——使用者原話：

> 你說的編譯器就是把資料夾壓成inst，我覺得這樣不太好，我會希望inst內部和外部資料夾兩者
> 互不相關。inst內部那套，本質上就是posix呼叫和aos run的搭配，他本質上提供的是一些好用的
> 命令，比如aos deliver之類，也就是語法糖。外部資料夾可以善用這些語法糖

**兩條**：

1. **兩層互不相關**——**資料夾不會被壓進 inst，inst 也不會長到資料夾層。**
2. **inst 層的本質＝POSIX 呼叫 ＋ `aos` 子命令**（`aos run`、`aos deliver`…）**的搭配**。
   那些子命令就是**包好的好用命令＝語法糖**；**資料夾層「使用」它們。**

**大白話**：`.aos` 看起來像一份 shell script，因為**它本來就是**。

> **裁決（2026-09-03）**：這段腳本**不是人直接寫進 `.aos/` 的**——人寫的原稿放**資料夾頂層**，
> 父層點名打開它的時候，loader 才把原稿讀進 `.aos/`。見 [02](02-folders.md)。

> **被否決的一條（只留痕跡，別再照它推）**：AI 曾提「編譯器判斷哪些子資料夾可以安全壓成
> inst 鏈」。**使用者當場否決**——他要的是兩層互不相關。

## 走一步 vs 算到底

**裁決（2026-09-03）**：

| 指令 | 大白話 | 學名 |
|---|---|---|
| `aos exec` | **走一步**——就地把這個資料夾往前推一格 | small-step 歸約 |
| `aos run` | **一路算到不再變**——推到這個資料夾不會再變為止 | eval（歸約到不動點） |

「**算到不再變**」就是「跑完了」的定義：**再 exec 一次，資料夾也不動了。**

**AI 觀察（非裁決，可否決）**：LLM 是不確定的，所以「穩態」**不能**定義成「每次算出來都
一樣」，只能定義成「**exec 不再改它**」；而且可能**永遠到不了**（來回震盪），所以要有
**預算**——超過就停。

**AI 觀察（非裁決，可否決）：`aos exec` 這四個字一詞三用，別混。** 它同時被拿來指
①**已裁的概念名「走一步」**（就是上表那格）、②口語裡順著用的一次、③**今天不存在的一支指令**。
**概念不改**；補一句實況：**今天要走一步就是下 `aos run --step 1`**，要不要真的加一支
`aos exec` 是**實作的事**，不是概念問題。

**AI 觀察（非裁決，可否決）：「算到底＝不再變」今天對不上。** 今天的 `aos run` 是**跑滿
`--step N`**，或被 `aos stop` 叫停。**有接力棒的時候**，「游標走到底」就是不再變；**沒有
接力棒的時候**只能靠 LLM 自己說停，**還沒實作**。所以這是**實作落後，不是概念矛盾**——
缺的正是下面那格「薄的 `.aos` 不存在」（`G14` 載入器）。

## 接力棒：`series.json`

**使用者口述（2026-09-01）**：**loop 必須另讀一份 `series.json`**，記**在跑哪些串**與
**跑到哪裡**，跑的時候自然去抓那條串的下一筆。排程也沿用它：一條串可以自己報未來幾回合要
花多少資源、建議什麼優先級。**格式等實作再說。**

**大白話**：`series.json` 就是**接力棒**——上面寫著「做到哪了、下一棒交給誰」。跑到一半
的狀態不能只活在記憶體裡，因為**每一步之間 loop 根本不存在**，所以進度必須寫在檔案裡。

**AI 觀察（非裁決，可否決）**：這件事有個學名叫 **continuation**（「接下來還要做什麼」
被寫成一份可以看、可以改、可以重播的資料）。跟 C 語言最大的不同就在這裡：**C 的執行堆疊
你看不到也改不了，這裡的接力棒是一份 json。**

**AI 觀察（非裁決，可否決）：接力棒只有一根。** 兩層唯一的橋是腳本裡 `aos run <子資料夾>`
那一行，**走過就記下「開過誰」**——所以 `series.json` **一根就夠**，住在 `.aos/` 內、由 loop
讀，跟「loop 另讀一份 `series.json`」是同一件事。[nested-eval-sugar](../nested-eval-sugar.md)
說「父層那條短的要留」**不是第二根**，就是這一根裡的那幾行。

## 中間值：`out/`

`f(g(x))` 這種一層包一層的算式，**在跑之前就被拆平了**——改寫成「先算 `g`、把結果存成一個
有名字的檔、再拿那個檔去算 `f`」。那些中間值就住在 **`out/`**。

**學名**：拆成這種「一步一個名字」的形式叫 **ANF**（A-normal form）；把「接下來要做什麼」
一律寫成資料帶著走，叫 **CPS**。

**裁決（2026-09-01）**：**這種複雜式另存成新的 json，由「我們的程式」確定性地拆平之後才進
series——LLM 在這一段不出場。** 所以整條線是三段：**寫（人／LLM，不確定）→ 編譯（確定）→
執行（確定）**。

**裁決（2026-09-01）**：**留著批**——一回合可以一次送出好幾條 inst，不退回「一次一條」。

## 這一整套是語法糖

**使用者觀察（2026-09-03）**：

> inst 攤平 接力棒 out/這些，在這種情況下，它就變成一種語法糖。因為複雜的邏輯可以直接
> 託付給子資料夾

**裁決（2026-09-03）**——使用者原話：

> 喔天啊，這套模型太棒了！你說的對，inst語法糖就是為了省成本而做的

**inst 鏈（攤平、接力棒、`out/` 中間值）是為了省成本而存在的語法糖，不是本體。**
本體只有兩樣：

1. **原子 inst**——工具呼叫、LLM 呼叫。**不是資料夾，無法再往下託付**（見 [04](04-atoms.md)）。
2. **開／讀／選**——開一個子資料夾、讀它的產出、決定下一個開誰。

其餘全部都可以改寫成「**每一步開一個子資料夾**」。對照 lisp：**special form 只有幾個，
其餘都是 macro 疊出來的糖。**

**那為什麼還要糖？** 因為**開一個子資料夾＝生一個行程**：至少多一輪、多花 token、多一分
不確定。`.aos` 裡連著寫一串 inst 是**內聯**。跟 C 的「函數呼叫 vs 內聯」一樣——**意思相同，
成本不同。兩種寫法都要留，依情況選。**

## 兩層之間唯一的橋

**AI 觀察（非裁決，可否決）**：

- **唯一的橋是 `.aos` 裡 `aos run <子資料夾>` 那一行命令**——它是腳本裡的**一行**，做的卻是
  **開外面一個資料夾**。而且**單向**：裡面可以開外面，外面**永遠不會**被折進裡面。
- 因此**攤平／ANF／CPS 那條 C 語言線全關在 `.aos` 內**，只講「這段腳本怎麼寫得順」，
  **永不碰資料夾層**。
- **父層那條資料夾層級的短接力棒要留**（記「開過誰、下一個開誰」）。誘人的省法是「看檔案
  系統就好，子資料夾有產出就是做完了」，但再走一步就變成「材料齊了就自動跑」＝Make 的
  模型＝applicative，跟剛裁的「父層點名才開」**相反**。

## `.aos` 會有兩種長相

**AI 觀察（非裁決，可否決）**：**薄的**（只做開／讀／選，複雜邏輯全託付給子資料夾）與
**厚的**（`.aos` 裡一整串 inst）。**今天的 aos 只有厚的，薄的不存在。**
