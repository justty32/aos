# 05 寫→編譯→執行
← [入口](README.md)

這章講 `.aos` 裡那段腳本怎麼從「人或 LLM 寫的東西」變成「機器一步一步照走的東西」。中間隔一道確定性的編譯，跑的時候靠一根叫接力棒的檔案記進度。整條線只在 `.aos` 裡面發生，不碰外面的資料夾樹（那是 [02](02-folders-as-lists.md) 與 [04](04-inside-aos.md) 的事）。為什麼重要：不確定的只有 LLM，把它關在最上游，後面兩段就能重播、能量。

## 一、三段式生產線：寫、編譯、執行

寫的人可以亂，編譯跟執行不能亂。

- **複雜式（像 `f(g(x))`）另存成一份新的 json，由我們自己的程式確定性地拆平，拆完才進接力棒；LLM 在這一段不出場。**〔裁決 2026-09-01〕
- 整條線三段：寫（人或 LLM，產一份新 json，不確定）→ 編譯（我們的程式拆平，確定）→ 執行（loop 照接力棒走，確定）。〔裁決 2026-09-01〕
- 型別與回傳值同樣由程式拆平，細節等一下想。〔裁決 2026-09-01〕
- 這條線全關在 `.aos` 內，不碰資料夾層；子資料夾永遠不會被壓進這條線。〔裁決 2026-09-03〕
- 不確定性只在最上游，所以留住最上游那份 json 就能重播後面兩段。〔AI 觀察〕
- 那份新 json 就是「程式」（靜態、有名字、可重用），接力棒就是「行程」；程式與行程的分界自然長出來，不用另外發明標記。〔AI 觀察〕
- 「拆平」白話：巢在一起的算式拆成一步一個名字、中間值各自存檔（學名 ANF）；「接下來做什麼」寫成資料帶著走（學名 CPS）。〔AI 觀察〕

## 二、全塔 json：從源碼到指令批一路同一種格式

記法統一，lisp 只留精神。

- 源碼 → 中間表示 → 接力棒 → 指令批，一路都是 json。〔裁決 2026-09-01〕
- 源碼與中間表示是兩個檔、兩站；源碼是給人舒服編輯的那份，中間表示是編譯器吐的那份。〔裁決 2026-09-01〕
- lisp 只保留為哲學（整套系統是一棵可改寫的樹），語法層不進場；哪天想手寫再加括號糖衣，括號樹與 json 樹來回轉換是機械且無損的。〔裁決 2026-09-01〕
- 一條語意線：程式歸求值（源碼、中間表示、宏），協定歸解析（接力棒、指令批、機器狀態）。前者是拿來算的，後者是拿來讀的資料，不會被當成程式跑。〔裁決 2026-09-01〕
- 最底層要接 POSIX C ABI。〔裁決 2026-09-01〕
- 界線畫在指令：指令往上全是樹；指令本身就是樹壓扁成 POSIX 叫法（argv 是一串字、env 是名值表）。編譯管線最後一站吐出來的「機器碼」就是指令批。〔AI 觀察〕
- 回程只有一個整數，回傳值得靠 `out/` 檔繞過；見 [09 呼叫與失敗](09-call-and-failure.md)。〔AI 觀察〕
- 全 json 賺三樣：agent 產得穩、格式驗證卡在編譯器門口、一套解析器吃全家。唯一實質損失是 json 沒有註解，源碼要自己想辦法（例如 `_comment` 欄）。〔AI 觀察〕

## 三、接力棒（`series.json`）：進度一定要寫在檔案裡

loop 每走一步就消失，所以「做到哪、下一棒給誰」不能放在記憶體。

- loop 必須另讀一份檔，記「在跑哪幾條串」與「各跑到哪」，跑的時候去抓那條串的下一筆。〔裁決 2026-09-01〕
- 為什麼不能只靠「做完自己投下一步」：投遞失敗整條串就無聲斷掉，接力棒是保險。〔裁決 2026-09-01〕
- 排程沿用這份檔：一條串可以自報未來幾回合要花多少資源（CPU、LLM…）、建議什麼優先級；格式等實作再說。〔裁決 2026-09-01〕
- 為什麼一定是檔：兩步之間 loop 根本不存在。〔AI 觀察〕
- 一份檔四種身分：行程表、游標（程式計數器）、排程輸入、可見窗口（能看見它接下來幾步要幹嘛）。〔AI 觀察〕
- 一根就夠：父層「開過哪個子資料夾、下一個開誰」也記在這根裡，不另立第二根。〔AI 觀察〕
- 接力棒有序，資料夾無序：正在跑的那部分需要順序、順序由接力棒的 json 陣列給；穩態的資料夾本身不需要順序（見 [02](02-folders-as-lists.md)）。〔AI 觀察〕
- 接力棒是明寫的「接下來還要做什麼」（學名 continuation）：可以看、可以跑到一半改、可以重播。C 的堆疊看不到改不了，這裡是一份 json——這是「程式與資料同一種形狀」撐住「自我改寫」的落地點。〔AI 觀察〕
- 資源是自我申報，排程器只能當參考。〔AI 觀察〕
- 這份檔會被好幾方同時寫（loop、串自己、外部中斷），怎麼防撞見 [09](09-call-and-failure.md)。〔AI 觀察〕
- 串的生滅沒定：新串怎麼誕生、跑完誰清；使用者沒答，見待決定 E-05 與 [一塊地](03-land-and-life.md)。〔AI 觀察〕

## 四、函數、代號、兩種壽命

往上一層看，這根接力棒可以有「函數」，而中間值有兩種活法。

- 函數＝有名字、可重用的串模板；呼叫＝開一條子串、掛上父串的 id；返回＝把結果寫到父串指定的位置、父串游標繼續走；遞迴＝同一個模板多筆實體。〔AI 觀察〕
- 模板＝程式，跑起來的串＝行程；程式／行程分界在這一層再出現一次。〔AI 觀察〕
- 串裡可以用代號指代東西，搭配串的狀態，能大幅減少重複。〔裁決 2026-09-01〕
- 代號白話就是「有名字的暫存器」；符號表是串的狀態，只在串內有效。〔AI 觀察〕
- 兩種壽命都要：一種只在單一指令執行中存在，其他指令、其他回合都看不到（暫存器壽命）；另一種跟著「串的一筆」生滅，開串時建、返回時丟（堆疊框壽命）。真 CPU 也兩個都有。格式未拍板。〔裁決 2026-09-01〕
- 硬碟就是較慢較大的記憶體，沒有本質區別；stack 與 heap 只差壽命、不差住處。〔裁決 2026-09-01〕
- 堆疊框＝這次呼叫用的臨時資料夾，結束就丟；heap＝活得比這次呼叫久的東西，寫進世界資料夾。〔AI 觀察〕
- 介面與身體可以分（像 `.h` 與 `.c`）：aos 有「分開編譯」——模板獨立拆平、開子串時才把代號解析到實際目標（那就是連結）。但介面不必是獨立檔，可以只是源碼 json 裡的一欄。〔AI 觀察〕

## 五、什麼叫跑完

要一個機器判得出來的「結束」。

- 停止條件：這次 exec 沒產出新的指令就停。〔傾向 2026-09-04〕
- 白話：再 exec 一次資料夾也不會變了，就是跑完了。〔AI 觀察 2026-09-03〕
- LLM 不確定，所以「穩態」不能定義成「每次結果一樣」，只能定義成「exec 不再改它」；而且可能永遠到不了（來回震盪），所以要有預算保底，超過就停。〔AI 觀察〕
- 有接力棒時判法很便宜：游標到底就是跑完，不用比對整個資料夾。純靠 LLM 的資料夾（像聊天）只能靠 LLM 自己說停——這就是可預測性的來源差；把工作從 LLM 搬到接力棒就是在買可預測性。〔AI 觀察〕
- 停止原因要看得見（檔案或步數），不藏在記憶體；歸 [06 時間](06-time-and-clocks.md)。〔AI 觀察〕

## 六、「一回合內沒有資料流」跟攤平不打架

- 一回合是純並行：同批指令之間沒有資料流，所有鏈接跨回合（見 [04](04-inside-aos.md)）。巢狀運算式被拆平成跨回合的多步、中間值放臨時檔，本來就不需要回合內資料流，所以那條規範不用改。〔AI 觀察〕

## 七、外層契約會不會反噬

- 一旦外層有了型別、回傳值、高階形式，指令可能退化成「只是啟動器」；使用者還沒想好，見 E-06。〔AI 觀察 2026-08-28〕
- 要問的其實是：那個契約還在指令之上嗎？只要契約住在源碼 json 與編譯器裡、指令批維持字串進整數出，指令就沒退化。〔AI 觀察〕
- `.h`／`.c` 的分法給這題留了車位：型別與回傳值＝函數簽名，放在源碼 json 的介面欄，由編譯器消化掉，不落到指令。〔AI 觀察〕

## 我的意見

- **裁決密度高，但沒有一條定格式。** 接力棒格式、臨時資料夾格式、源碼 json 格式全「等實作」。新實作第一份文件大概就得補這個，而且要先補接力棒——其他兩個都掛在它上面。
- **json 與 shell 兩種記法沒對過帳。** 這章說全塔 json；[04](04-inside-aos.md) 說 `.aos` 裡是一段命令腳本、本來就是 shell script。兩句都是 09 月的裁決。最不打架的讀法：人寫的是頂層原稿，載入器讀進 `.aos/` 之後才叫腳本；json 塔是腳本裡「厚的那一串」的內部格式；但誰包誰沒人明說。
- **批的名字、版本、彙總狀態要跟接力棒合成一題。** 「批沒有 header」被三條線同時需要（去重、輸入歷程、串歸屬）。接力棒本來就記串 id 與游標，批 id、格式版本、彙總狀態（全成功／部分失敗／逾時）最自然的落點就是這根檔；[04](04-inside-aos.md) 互指到這裡。
- **「執行段確定」只確定順序，不確定結果。** 原子指令裡有 LLM，跑出來的東西還是不確定；三段式只保證「照接力棒走」這件事確定。壞掉怎麼回來這章沒有，整題在 [09](09-call-and-failure.md)；接力棒推游標前得先判這一步成敗，被那邊的 exit 兩頻道擋著。
- **堆疊框誰丟沒說。** 「開串時建、返回時丟」講的是時機，沒講誰做——run 自己丟、還是留給 [03](03-land-and-life.md) 講的壽命清理。跟「串跑完誰清」是同一題。
- **預算沒有主人。** 「要有預算保底」是 AI 觀察，單位（步數還是 token）與誰執行（run 自己數、還是 daemon 在外面砍）都沒定。建議先用步數，因為 token 要接 LLM 處理單元才算得到。

## 現況對照

- 今天沒有拆平器，也沒有「送一份源碼 json → 拆平 → 進接力棒」這條路；`aos deliver` 送的是單筆指令，批是 loop 每回合從收件匣湊出來的。
- 今天沒有 `series.json`；控制流靠指令做完自己投下一條，投遞失敗鏈就斷。
