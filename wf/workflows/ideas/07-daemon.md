# 07 daemon：所有時鐘的總管、REPL 的桌子、LLM 處理單元的管家
← [入口](README.md)

daemon 是一支常駐程式，站在整棵資料夾樹的最上面。它做三件事：盯著桌子、桌上有東西就抓起來跑（互動視窗那種「讀一句、算一句、印結果、回去等」的迴圈，學名 REPL）；替每塊正在走的地登記時鐘、讓時鐘走、關機時一次全停；替慢得沒有上限的 LLM 呼叫當管家，不讓它們把世界拖住。時間模型（一格、一個時鐘、同步借鐘、脫節自走）在[時間](06-time-and-clocks.md)；agent 怎麼利用 daemon 在[agent](08-agent.md)；門房那層皮在[門房](10-doorman.md)。

## 三層各一個名字，daemon 是最外面那層
走一步、算到底、盯桌子，是三件不同的事，各佔一個名字，不再用「aos 的 loop」泛指。
- **daemon 是三層裡最外面那層**：走一步、算到底、盯桌子各佔一個名字（三名字見 [指令面](12-cli-and-layering.md)）；REPL 的落點是 daemon，不是資料夾自己那條 run，daemon 收到「去跑某個資料夾」的指令才跑。〔裁決 2026-09-03〕
- **頂層資料夾由使用者開，或由使用者開的 daemon 代開**；沒有資料夾會自己醒過來。〔裁決 2026-09-03〕
- **開 daemon 的是 shell**：手動 `aos daemon start`，systemd 先不做，風險略大。〔裁決 2026-08-30〕
- **`~` 是 daemon 的家、第一個目標**：開機後在 `~` 起 daemon，底下各地由它帶。〔傾向 2026-08-30〕

## 桌子：誰放東西、兩層桌子、印出只剩通知
lisp 的 REPL 只有人會往桌上放東西；aos 這張桌子收的東西更多，而且不當場回話。
- **桌子有兩層**：daemon 桌上排「哪個資料夾要推進」，資料夾自己的 run 排「這個資料夾下一批做什麼」；外層排資料夾、內層排批。〔AI 觀察〕
- **三種投件人**：人（在終端下指令）、資料夾自己（跑到一半自投下一步）、時鐘（到期的例行事務）；桌子要收得下三種。〔AI 觀察〕
- **這個 REPL 是非同步的**：送出指令、之後被通知；節奏為什麼可以差一個數量級見 [時間](06-time-and-clocks.md)。〔裁決 2026-09-01〕
- **「印出」只剩通知**：資料夾本身就是輸出，daemon 印的是事件——「到不動點了」「預算用完了」。〔AI 觀察〕
- **沒有 daemon 時，人就是那個迴圈**：人是桌邊的一個角色，不是站在系統外面的操作員。〔AI 觀察〕
- **缺一個一次性入口**：「去跑某資料夾一次」這一格，形狀像 `aos daemon exec <資料夾>`，或化約成往 daemon 桌上投一筆。〔AI 觀察〕

## 時鐘總管：登記、走、一次全停
每個 `aos run` 就是一個時鐘。時鐘不歸各自的父管，統一交給 daemon。
- **所有時鐘都由 daemon 走**；父自己 fork 子時鐘那條先不考慮。〔傾向 2026-09-04〕
- **父時鐘掛了，子時鐘還可以繼續走**。〔傾向 2026-09-04〕
- **所有時鐘登記在一處**，想關機、停下所有時鐘時，一次全停。〔傾向 2026-09-04〕
- **daemon 對時鐘只做三件事**：登記、走、一次全停。〔AI 觀察〕
- **登記處就是 daemon 自己的資料夾**：它是一個 list，每個元素指向一塊正在走時鐘的地；不另發明登記機制。〔AI 觀察〕
- **出生先登記再走**：順序反過來會留下總管看不見的時鐘，關機就漏掉。〔AI 觀察〕
- **兩種時鐘**：週期性的（父世界那種）與一次性的（跑一次、寫結果、結束）；登記簿兩種都要收。〔AI 觀察〕
- **daemon 自己掛了，時鐘照走**；重啟後拿總表逐筆對各地的 pid 對帳，清掉已死的登記。〔AI 觀察〕
- **判死與孤魂補刀**（pid 還在、路徑不在）的規則在[一塊地](03-land-and-life.md)；登記表落地永遠記真實路徑。〔AI 觀察〕
- **登記也可以由門房自動做**（見[門房](10-doorman.md)第一級）。〔AI 觀察〕
- **這跟 Unix 同形**：父死子繼像孤兒過繼給 PID 1，一次全停像 systemd 用 cgroup 收掉一組行程；走到同一個地方是沒走歪的訊號。〔AI 觀察〕
- **一筆登記至少有**：資料夾路徑、pid、時鐘規格（間隔／步數／條件／一次性）。細節留給玩。〔AI 觀察〕

## daemon 的形狀：一支常駐程式，也可以看成一個資料夾
- **daemon 是一支常駐程式**，它同時是所有時鐘的總管與 REPL 的桌子，不是某個 run 的附屬旗標。〔傾向 2026-09-04〕
- **它自己也可以看成一個資料夾**：它的 `.aos` 寫的是「盯著桌子、有東西就開」，桌上的資料夾就是它的引數，登記表就是它資料夾的內容；於是「父決定要不要開子」在整棵樹上一致成立，頂層不用開特例。〔AI 觀察〕
- **門房是它未來可以加的一層皮**：daemon 本身變成一支支援 FUSE 的行程、整棵樹寄生在裡面，是使用者續想，不排進第一塊。〔傾向 2026-09-03〕
- **「走時鐘」的動作**：替每塊登記的地起一支 `aos run` 子行程，daemon 只當看管者；這樣 daemon 掛了時鐘才真的照走。〔AI 觀察〕

## LLM 處理單元：daemon 是它的管家
LLM 慢、貴、時間看外面，所以它不能在同步世界裡被等；它是另一台機器，daemon 負責替它排隊。
- **LLM 不是被呼叫的函式，是另一台跑同一套協定的機器**；兩邊只靠投遞接觸，誰也不進誰的記憶體。〔裁決 2026-08-30〕
- **它天生是常駐服務**：幾十 GB 的權重不能每回合重載；工作投出去、好了寫回來，像 CPU 對 GPU 的信箱，結果落在未來某個回合。〔裁決 2026-08-28〕
- **一次 LLM 請求＝一塊脫節的小地**：把 prompt 寫進去，請 daemon 走它的一次性時鐘，父之後只看固定路徑的檔在不在（走法見[agent](08-agent.md)）。〔AI 觀察〕
- **daemon 對它的四條責任**：同時在用的 LLM 數不因資料夾變多就無上限；不讓某隻長期 agent 餓死別人；結果與錯誤準確歸回原資料夾；重啟後認得未處理／處理中的工作。〔AI 觀察〕
- **概念層保留的排程規則**（下面五條是對舊程式下的裁決，機制不沿用，只留規則）：
  - 並行上限兩層：使用者層是總上限、世界層只能再往下限。〔裁決 2026-08-30〕
  - 超上限就排隊，但帶等待上限，超過才退回；退回不算失敗，狀態寫「在等 LLM」。〔裁決 2026-08-30〕
  - 優先序用數字，登記時填。〔裁決 2026-08-30〕
  - agent 固定綁一顆 LLM 處理單元，可選「要多聰明」的分級，不指定哪一顆。〔裁決 2026-08-30〕
  - 處理單元掛了，只對還沒送出的改派同級；送出後斷線＝結果不明，不重送。〔裁決 2026-08-30〕
- **處理單元的位址不進通訊錄**，放引擎設定；通訊錄只放 agent。〔AI 觀察〕
- **參考數字**：本機模型一次思考 2～17 秒；雲端帳號的併發上限遠大於我們自己設的上限，端點不會替我們擋。〔AI 觀察〕
- **最漂亮也最重的形狀是「LLM 變成一個資料夾」**，那要門房第三級（見[門房](10-doorman.md)）。〔AI 觀察〕

## 我的意見
- **「走時鐘」的動作沒有人正面寫過。** 兩種可能：daemon 自己一支行程逐一走每塊地，或替每塊地起一支 `aos run` 子行程。前者 daemon 掛了時鐘就停，跟「時鐘照走」直接矛盾；後者才對得上，而「先不考慮 fork」講的是父地自己 fork 子時鐘，不是 daemon 起子行程。我照後者寫，但這是推論，要使用者點頭。
- **「一次 LLM 請求＝一塊小地」跟 08-30 的「請求檔排隊、一支工人逐件打端點」其實是同一件事，沒人對過。** 排隊的目錄就是 daemon 的登記表，工人就是 daemon 走一次性時鐘。差別只在誰數並行：小地模型裡沒人數，得由 daemon 走時鐘時去數「正在跑、要用同一顆 LLM 的小地」有幾塊。這個「數」的動作是四條責任的第一條，目前沒有落點。
- **daemon 的 `.aos` 就是用這套指令集寫的排程器。** 「排程是普通指令、用自己的指令集寫」與「所有時鐘交給 daemon」兩條可以合成一條：daemon 是唯一一個由 aos 之外（shell）推的 run，它的 `.aos` 做的事就是排程。合了以後，「daemon 專屬一格要不要加進缺口表」也自然有答案。
- **一次性時鐘跑完，登記誰清、地誰刪。** 結果還在 `out/` 等父來讀，資料夾不能馬上刪，有一段「時鐘停了、地還在」；這跟壽命是同一題，放在[一塊地](03-land-and-life.md)，這裡只提醒登記表要能表達「停了但沒死」。
- **「照走」與「一次全停」方向相反。** 子行程模型讓 daemon 掛了時鐘照走，代價是 daemon 不在時沒人能一次全停，只能靠重啟後對帳。可接受，但要明寫。

## 現況對照
- 今天每個資料夾各有 `.aos/run.pid`，`aos stop <資料夾>` 只停一個；沒有跨資料夾總表、沒有一次全停。
- `aos run --daemon` 是單一資料夾一直跑；多目標的 `aos daemon` 只規劃未做。
- 並行上限靠鎖檔槽（`<AOS_HOME>/slots/`）在使用者層擋，退回時 exit 75。
