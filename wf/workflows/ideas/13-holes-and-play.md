# 13 已知的洞、該升格的傾向、先玩清單
← [入口](README.md)

前面十二章把「要管什麼」講完了，這章收尾：哪些還沒定而且第一天就會撞到；哪些是使用者說過但沒拍板、該不該升格；哪些舊想法已被取代、別再撿回來；「先去玩」要玩什麼。這章沒有新主張。

## 最大的洞（動手第一週就會撞到）
每一條都有章在講，這裡只排優先序。

- **失敗語意整個是空的**：子資料夾跑壞、指令失敗、等太久，父怎麼知道、怎麼處置，沒討論過；它擋著「判定這一步成敗」，而成敗判定又擋著接力棒推游標與 `run` 的停止條件，三件事綁死。見 [呼叫與失敗](09-call-and-failure.md) I-02～I-04。〔AI 觀察〕
- **開子資料夾拿回什麼**：等不等已答（同步等、脫節不等），拿回什麼只有「固定路徑一個檔」的提議；父分不出「還沒好」與「永遠不會好」。見 [呼叫與失敗](09-call-and-failure.md) I-01、[時間](06-time-and-clocks.md) F-07。〔AI 觀察〕
- **daemon「走時鐘」的動作沒人寫**：自己逐一走，還是每塊地一支子行程；兩者對「daemon 掛了時鐘照走」答案相反。見 [daemon](07-daemon.md) G-01。〔AI 觀察〕
- **接力棒沒有格式，批的 id／版本／彙總狀態沒有落點**：整章裁決都是模型層，沒有一條定格式；源碼 json、臨時資料夾格式都掛在它上面。見 [寫→編譯→執行](05-write-compile-run.md) E-01。〔AI 觀察〕
- **壽命只講了生沒講死的執行者**：跑完的暫態資料夾、一次性小地誰刪、何時刪。見 [一塊地](03-land-and-life.md) C-01、C-02。〔AI 觀察〕
- **同步世界能不能藏 LLM**：「借父鐘、全動完才收格」乘上「一格要有上限」，只要同步樹裡任何一層有 LLM，上限就破；現在只是 AI 觀察加一句「的確會是這樣」。見 [時間](06-time-and-clocks.md) F-02。〔AI 觀察〕
- **成本帳與命名空間被判「拖了會鎖死」，但使用者裁先玩**：第一版要不要留插口。見 [什麼與目標](01-what-and-goals.md) A-03、[一塊地](03-land-and-life.md)。〔AI 觀察〕
- **控制介面升為必要卻一支沒設計**：看得見誰在跑、殺得掉、停得了。見 [指令面](12-cli-and-layering.md) L-05。〔AI 觀察〕
- **json 塔與 shell 腳本誰包誰**：沒對過帳。見 [寫→編譯→執行](05-write-compile-run.md) E-02、[`.aos` 裡面](04-inside-aos.md) D-04。〔AI 觀察〕

## 該升格的傾向（2026-09-04 那批）
這批是使用者說的定義與偏好，來源檔全自標「無裁決」；但使用者同日宣告「大體哲學已經擬定，接下來都是工程」。要嘛整批升格，要嘛逐條挑。本書的標法：使用者回「的確會是這樣」的那一整套走法算〔傾向〕，走法之內個別 AI 推論仍是〔AI 觀察〕。〔傾向 2026-09-04〕

| 傾向 | 在哪章 |
|---|---|
| `aos exec`＝走一步；`aos run`＝反覆 exec（固定次數／隔一段時間／到條件成立） | [06](06-time-and-clocks.md) |
| `run` 的通用停法：這次 exec 沒產出新指令就停 | [06](06-time-and-clocks.md)、[05](05-write-compile-run.md) |
| 同步子世界借父的鐘，全動完父這一格才算完；脫節子世界自己有鐘、父不等 | [06](06-time-and-clocks.md) |
| 父拿脫節子的結果＝看固定路徑的檔在不在 | [06](06-time-and-clocks.md)、[09](09-call-and-failure.md) |
| 時間要有界，主方法是環境限制（能用的指令都很快結束），timeout 不是首選 | [06](06-time-and-clocks.md) |
| 所有時鐘由 daemon 走、登記在一處、關機一次全停；父鐘掛了子鐘可續走；fork 先不考慮 | [07](07-daemon.md) |
| 一塊地只看得到自己地上的東西，要看外面只能掛載或 symlink | [03](03-land-and-life.md) |
| 路徑是一塊地的唯一標示；刪資料夾＝死；消失前通知 daemon 是快路、定期查是保底 | [03](03-land-and-life.md) |
| 一個 agent 就是一個資料夾 | [08](08-agent.md) |
| agent 的本質是「丟 LLM→叫工具→再丟」的循環，本質上就是一個 `aos run`；逐 tick 走法「的確會是這樣」 | [08](08-agent.md) |
| agent 跑到 LLM 不再呼叫工具（使用者語氣有保留） | [08](08-agent.md) |
| 每圈 prompt 怎麼組留給工程 | [08](08-agent.md) |
| FUSE 要做；順序 tmpfs → inotify → FUSE；何時做未定 | [10](10-doorman.md) |

同日已經是裁決的只有兩條：搬家不做通知（搬＝死＋生）；LLM 當假 CPU 的四個腳位是工程問題、不在概念層繼續談。〔裁決 2026-09-04〕

另外幾條不是 09-04 但同樣是傾向、值得一起問：三條傳話失真的對策方向（08-27）；資料夾就是活的 image（09-01）；`~` 是 daemon 的家與第一個目標（08-30）；「門房只記不做」是 AI 自升的硬規則（[10](10-doorman.md) J-03）。〔AI 觀察〕

## 被取代的東西（別再撿回來）
只列名字與一句「為什麼」，內容不重講。〔AI 觀察〕

- **08-30 的 LLM 排程機制**（鎖檔槽同步等、請求目錄＋工人）：與「同步世界只放有上限原子」衝突；五條規則保留在 [daemon](07-daemon.md)，機制不沿用。
- **`aos pu` 這個名字**：被 09-03「exec／run／daemon 三名字」蓋掉；意思（一個資料夾＝一顆處理單元）保留。
- **agent 住在 `.aos/agents/` 裡**：被「一個 agent＝一個資料夾」取代，正式成為現況缺口。
- **編譯器把子資料夾壓成指令鏈**：使用者當場否決，兩層互不相關。
- **用引用機制做副程式**：「程式」的落點已移到資料夾層（子資料夾就是副程式），舊提案自然失效。
- **daemon 只是 `run` 的一個旗標**：daemon 已是時鐘總管與桌子，是獨立的常駐程式。
- **「只有 lisp 承載得了」**：收回為偏好；全塔 json，lisp 只留哲學。
- **接力棒是資料夾的第一個元素**：第一個元素是整個 `.aos/` 目錄，接力棒只是裡面先被讀的檔。
- **依「金錢優先」推出的提案**（含「帳本當 OS 第一塊」）：可預測性最優先拍板後前提已變，須重推。
- **資料夾自宣告 init 起跑**：頂層由使用者或 daemon 開。
- **「觀察者」這個角色**：就是 daemon／門房，不另立。
- **同步等 LLM 佔住回合**：LLM 呼叫一律脫節。
- **通訊錄的「哪隻 agent」欄**：世界＝agent 之後多餘。
- **每回合把「下一回合的自己」投進收件匣**（自我複製投遞）：「agent 每回合都要在」得有檔案承載，不能靠上一回合投成功。
- **搬家通知（像 `git mv` 那樣）**：使用者裁不做。

## 先玩清單
使用者裁「到這裡只能知道要管什麼，怎麼管要玩過才知道」；重啟設計的人從玩出來的**阻礙**開始，不從觀察開始。〔裁決 2026-09-03〕

- 跑兩級順手劇本：單人 coding agent（全程只用 `aos …`，對照現成 coding agent）；指揮一隊（主 agent 派子 agent 各住一個資料夾）。第一級一定要驗「停掉隔天再來記憶還在不在」。〔裁決 2026-08-30〕
- 量法：不打分數，記三種東西——多餘的動作、看不見的狀態、錯誤不指路；每條附對照。〔裁決 2026-08-30〕
- 把 `.aos/` 放 tmpfs，看少碰磁碟有沒有差。〔AI 觀察〕
- 三支固定的串各跑五次，畫成本與結果的分布——這是可預測性今天就能量的兩把尺之一。〔AI 觀察〕
- 把現成的二十幾支最小重現腳本改讀成固定工作負載，當評估任務集的起點。〔AI 觀察〕
- 玩的時候順手記四條橋（父拿回什麼、子看不看得到父、失敗怎麼回、資料夾壽命）撞到的實例。〔AI 觀察〕
- 玩完回來第一件事：決定「OS 的第一塊」。候選（未裁）：門房第一級的偵測生死與出生；成本帳的薄關口；接力棒格式。〔AI 觀察〕

## 我的意見
- **這批傾向該整批升格，而不是逐條挑。** 它們彼此扣著：時鐘模型撐 daemon，daemon 撐一塊地的生死，生死撐 agent 的走法。挑掉任何一條，其他幾條就懸空。唯一該單獨問的是「LLM 一律脫節」——它不是使用者說的，是推出來的，但整個一格有界的論證押在它上面。
- **「先玩」與「動工」的界線要畫。** 概念層說收尾，可是這本書 68 條待決定裡至少三分之一是「不定就動不了工」的（接力棒格式、結果落哪、失敗三態、走時鐘的動作）。建議把玩的目標寫成「回來能裁這幾條」，不然玩完還是原地。
- **兩條「拖了會鎖死」的東西值得破例。** 成本帳與命名空間都是「第一版不留插口、之後要重寫所有呼叫點」的那種；破例可以很小：LLM 呼叫走同一個薄關口只記一行帳；父開子時遞進去的東西寫成明的清單。
- **接力棒與批 header 是同一題，該先答。** 三條線（去重、輸入歷程、串歸屬）同時壓在它上面，定了它其他格式才有依據。
