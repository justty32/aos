## 第四部分 · 我的觀察（主 session，不是裁決，使用者可否決）

### 十四、函數＝有名字、可重用的「串模板」

| C | 這台機器 |
|---|---|
| 函數定義 | 有名字、可重用的**串模板** |
| 呼叫 | 開一條**子串**，掛上父串的 id |
| 返回 | 把結果**寫到父串指定的地方**，父串游標繼續往下走 |
| 遞迴 | **同一個模板、多筆實體**（多條串各有各的狀態） |

值得注意的是：**程式／行程的分界在更高一層重現**——**模板＝程式，跑起來的串＝行程**。
`G07` 不是被繞過，是換一層再出現一次。

### 十五、堆疊框＝臨時資料夾，heap ＝活得比呼叫久的世界資料夾

- **堆疊框**＝這次呼叫用的**臨時資料夾**，呼叫結束就丟。
- **heap**＝**活得比這次呼叫久**的東西，寫進世界資料夾。

所以 **stack／heap 的差別只在壽命，不在住處**——兩者都是資料夾，分不同層。

> **使用者裁決（2026-09-01 重申舊裁決）**：**硬碟就是較慢較大的記憶體，無本質區別。**
> 上面那條「壽命而非住處」接的就是這一條。同時**判定 eeprom／flash 那個問題不是問題、
> 跳過**。

### 十六、運算式 `f(g(x))` 由編譯器拆平成串

C 有巢狀運算式，彙編沒有。編譯器把 `f(g(x))` 拆成「先算 `g(x)` 存到臨時值、再拿臨時值餵
`f`」——**臨時值就放臨時檔**。

所以 [verdicts B3](../verdicts.md)「**一個回合內沒有資料流**」那條規範**不用改**：巢狀被
拆平成跨回合的多步，本來就不需要回合內資料流。

### 十七、型別與回傳值＝函數簽名，正面壓上 `B5`

C 的函數有**型別與回傳值**，那就是**函數簽名**。而 [verdicts B5](../verdicts.md)
（**外層契約會反噬基石**：一旦外層有型別與回傳值，inst 可能退化成啟動器）**使用者還沒想好**
——這條 C 語言線**正面壓上它**，不是擦邊。

## 第五部分 · 使用者的裁決（2026-09-01）

### 十八、串中可用**代號**指代，搭配串的狀態

> 串裡可以用**代號**指代東西，搭配**串的狀態**，能**大幅減少重複**。

（我的觀察）這就是**暫存器有名字**；而**符號表是串的狀態、只在串內有效**。

### 十九、兩種壽命都要：暫存器與堆疊框

使用者先說：臨時資料夾**只在單一 inst 執行中存在，其他 inst 和其他回合都看不到**。

經主 session 指出「那樣它是**暫存器**壽命、不是堆疊框壽命」之後，**使用者確認**並補上：

> 另外需要一種跟著**「串的一筆」**生滅的——**開串時建、返回時丟**，那才是**堆疊框**。
> **兩種壽命都要，真 CPU 也兩個都有。**

**格式尚未拍板。**
