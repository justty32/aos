# 03 一塊地：看得到哪裡、身分是什麼、怎麼生怎麼死
← [入口](README.md)

上一章說一個資料夾就是一個 list。這章換個角度看同一個資料夾：當它真的在跑的時候，它是一塊「地」——有邊界、有身分、有出生和死亡。這章要回答三個問題：這塊地看得到哪裡、別人怎麼指認它、它什麼時候算活著什麼時候算死了。時鐘怎麼走見 [時間](06-time-and-clocks.md)，誰幫它走見 [daemon](07-daemon.md)。

## 什麼算一塊地

一塊地就是一個裡面有 `.aos/` 的資料夾。它同時是「一個程式」和「一個正在跑的東西的家」。

- 一塊地＝一個帶 `.aos/` 的資料夾；一個新的執行單位誕生，就是父層的 `.aos` 去開一個子資料夾。〔裁決 2026-09-03〕
- 這塊地能存取到的所有資料夾，就是它的世界；它自己所在的那個資料夾（cwd）就是它的本體，其他能碰到的是它的外在世界。〔裁決 2026-09-01〕
- 世界的大小不是設定出來的，是掛出來的：掛了什麼進來，它的世界就有多大。〔裁決 2026-09-01〕
- 一個 agent 也就是一塊地，不另立規則——生死照這章走。細節見 [agent](08-agent.md)。〔傾向 2026-09-04〕

## 看得到哪裡：預設只看自己，開洞要明講

這塊地的世界，就是它那個 list 裡有的東西。想看外面，得有人明白地把外面放進來。

- 一塊地只看得到自己地盤上的東西；要看 `../`，只能靠掛載或 symlink。〔傾向 2026-09-04〕
- symlink 不是另一套權限系統，它只是讓這個 list 多一個「指到外面」的元素；掛載是同一種明白開洞。〔AI 觀察〕
- 「子看得到什麼」是父開子的那一刻決定的，就是父決定往裡面放什麼。廚師拿到什麼食材，看上面遞了什麼。〔AI 觀察〕
- 方向是預設封閉、開洞要明講。〔AI 觀察〕
- 「看得到哪裡」不是安全機制，它是世界的定義：不掛任何東西進來，這塊地就沒有可觀察的世界，它連第一步都走不了。〔AI 觀察 2026-09-01〕
- 「准不准做」是另一件事，很後面才做。〔裁決 2026-09-03〕將來由 [門房](10-doorman.md) 那層擋。
- 每塊地各有自己看得到的範圍，這件事本身被裁為 OS 該做的、而且是必要的（因為要同時跑很多顆）。〔裁決 2026-09-02〕

## 身分就是路徑

沒有 id、沒有名字表，一塊地的身分就是它在檔案系統上的位置。

- 路徑是一塊地的唯一標示符。〔傾向 2026-09-04〕
- 資料夾被刪掉，就是這塊地死了。〔傾向 2026-09-04〕
- 一塊地搬到別的地方，等於原地死掉、新地方生一個新的；不做「搬家通知」這套（這條使用者當場拍板，跟同批其他條不同）。〔裁決 2026-09-04〕
- 不做通知的理由：加了通知，daemon 的表跟磁碟之間會多一段對不上的時間；而且有人直接在 shell 打 `mv`，通知照樣會漏，最後還是得靠定期查。保底一定要有，快路價值不高。〔AI 觀察〕
- git 自己也不記錄搬家，`git mv` 本質就是刪一個加一個，事後再比對推斷。〔AI 觀察〕
- symlink 適合當「轉寄地址」，不適合當第二個身分；登記表若要落地，永遠記實際路徑（realpath），不記 symlink。〔AI 觀察〕
- 真要搬，規矩是搬之前先把時鐘停掉，像拔硬碟之前先卸載；可以做一顆糖叫 `aos mv`＝停＋搬＋重新登記，但語意仍然是死了再生一個。〔AI 觀察〕

## 死了怎麼被發現

死亡本身很簡單（資料夾不見了），麻煩的是誰、什麼時候發現。

- 兩條路：消失之前主動通知 daemon 是快路，daemon 定期巡邏是保底。〔傾向 2026-09-04〕
- Linux 有個坑：資料夾被刪掉，裡面的行程不會跟著死，它可以帶著一個已經不存在的家繼續跑。〔AI 觀察〕
- 所以判死要同時看兩樣：行程還在不在、登記的路徑還在不在。路徑不在但行程還活著，那是孤魂，要先把它停掉再清登記。〔AI 觀察〕
- 「登記了才算活的（時鐘在走），沒登記就只是一堆資料」——這句就是程式跟行程的分界。〔AI 觀察〕
- 這條分界被裁為必要的，因為人要同時跑很多個程式，得分得出哪個在跑。〔裁決 2026-09-02〕

## 壽命還沒答完的部分

生講完了，死也定義了，但「誰來刪、什麼時候刪」還是空的。

- 一塊暫態的地跑到不再變之後，留著還是刪掉、由誰刪，沒有答案。〔AI 觀察〕見待決定 C-01。
- 一次性的小地（例如「問一次 LLM」開出來的那塊）更麻煩：它的時鐘停了，但結果還躺在它的 `out/` 裡等父來讀，所以不能馬上刪。這中間有一段「時鐘停了、地還在」的狀態。〔AI 觀察〕見待決定 C-02。
- 父怎麼知道那塊地是還沒好、好了、還是壞了，屬於失敗語意，見 [呼叫與失敗](09-call-and-failure.md)。〔AI 觀察〕

## 存檔與回滾：交給 git，不自己發明

這套東西不打算自己做版本控制。

- 快照、回滾、複製重跑全部用 git 做，版本邊界不由 aos 自己發明。〔裁決 2026-08-28〕
- 但不是資料夾裡的每個檔都該進 git。分兩種：機器自己用的暫存，跟世界真正的記憶。〔傾向 2026-09-01〕
- 判別式只有一句（全書只在這裡講一次）：把這個檔刪掉，世界的意思會不會變？只會變快變慢、變節奏＝機器自己的暫存（像 CPU 的 cache）；意思會變＝世界的記憶。〔AI 觀察 2026-09-01〕
- 舉例：行程編號檔、鎖檔、上次跑到哪的紀錄，都是暫存；定期事務的設定檔刪了就永遠不跑了，那是記憶。〔AI 觀察〕
- 機器自己的暫存永遠不進 git。理由很實際：把行程編號檔存進版本裡，之後回滾到那個版本，系統會以為有個早就不存在的行程還活著，直接卡死。〔AI 觀察〕
- 所以 `.gitignore` 不是個人習慣，它是規範的一部分：哪條路徑算世界的一部分，要寫下來。〔AI 觀察〕
- 這條線會隨著設計落地移動（例如「現在第幾回合」一旦變成程式的位置指標，就從暫存升格成記憶），所以記錄的時候要一併記「什麼落地之後會改」。〔AI 觀察〕

## 記憶就是地

這套系統最核心的一條需求，用一句話講完。

- 停掉、隔天再來，記憶還在不在——這是核心需求，不是加分項。〔裁決 2026-09-02〕
- 記憶不需要另外設計一個容器：記憶就是這塊地本身。地上有什麼，它就記得什麼。〔傾向 2026-09-04〕
- 因為狀態一定在檔案系統裡（本體不能無限膨脹），所以「還在不在」等於「資料夾還在不在」。見 [aos 是什麼](01-what-and-goals.md)。〔裁決 2026-09-02〕
- 剩下的是工程題：一塊地可以長多大、每一圈要把地上多少東西組進 prompt（整塊全給，還是只給上一圈的結果加一點），使用者說之後再說。〔傾向 2026-09-04〕
- 這題等於決定了一塊地的「可用記憶上限」，跟檔案系統能塞多少無關。〔AI 觀察〕

## 我的意見

- **「看得到哪裡」跟「准不准做」要分開講，分開了就不打架。** 一邊說權限交給上層、核心不管，另一邊說父開子時決定放什麼進去，看起來衝突，其實是兩件事：前者是「能不能做」（權限，很後面才做，見 [門房](10-doorman.md)），後者是「有沒有東西可看」（世界的定義，現在就在做）。建議正式把這兩個詞分開用，不要混叫「隔離」。

- **壽命這條是本章最大的洞。** 生有明確答案（父開子）、死有明確定義（刪資料夾），但中間「誰負責刪」完全空白。這個洞不填，一次性小地會越積越多，而且沒人知道該不該清。兩個候選：父讀完結果就刪（乾淨但父掛了就漏），或 daemon 巡邏清（保底但要有規則判斷「父還會不會來讀」）。我傾向前者當預設、後者當保底，跟死亡偵測的「快路＋保底」同一個形狀。

- **搬家＝死＋生很乾淨，但人不會照做。** 使用者在 shell 直接 `mv` 是常態，而不是例外。既然決定不做通知，那巡邏的頻率跟「發現路徑不見時到底做什麼」就要寫清楚，不然「搬家」在實務上會表現成「東西莫名其妙不動了」。`aos mv` 這顆糖的價值就在這裡——它不是省打字，是把正確流程變成預設。

- **「記憶就是地」是漂亮的答案，但它只回答了一半。** 它回答了「記憶住在哪」，沒回答「記憶歸 OS 管還是歸應用管」。一塊地上什麼算它該記得的、誰負責整理、超過上限誰來砍，這些現在沒有主人。這也是「多次使用」這條必要需求在整套設計裡唯一沒有掛靠點的地方。列為待決定 C-03。

- **`.gitignore` 政策該有一份，而且該是全域的。** 判別式（刪了會不會變意思）很好用，但如果每塊地自己寫自己的，遲早有人把行程編號檔存進去。既然 `.aos/` 是機器的地盤，那 `.aos/` 裡哪些檔進 git 就該由規範決定，不是由使用者決定。

## 現況對照

今天的程式是這樣，但不當事實。

- 地的路徑在記憶體裡是絕對路徑，但沒有存進任何檔案；搬完資料夾之後，還在跑的舊 loop 仍然抓舊路徑，可能在舊位置重建一份 `.aos/`，並在新位置留下沒人清的行程編號檔。
- 每個資料夾各自寫自己的行程編號檔，沒有跨資料夾的總登記表，也沒有一次全停；停一塊地要指名那塊地。
