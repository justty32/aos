# fuse-host-impl：實作面備忘——會不會麻煩、跟 tmpfs 差在哪

← [top-to-bottom/01-top](top-to-bottom/01-top.md)｜[fuse-host](fuse-host.md)｜[ideas](README.md)｜[WORKFLOWS](../../WORKFLOWS.md)

**本檔是 [fuse-host](fuse-host.md) 的續篇**——使用者說「都順便記下來吧」，接著問的兩題另開
一檔，免得 [fuse-host](fuse-host.md) 超過檔案大小上限。**本檔無裁決**，全部是 AI 觀察，
使用者可以否決；**不排進 OS 第一塊**，性質同上游。

## 節一：實作會不會麻煩、有沒有開源庫

**使用者原話（2026-09-03）**：

> 因為我們的aos吃檔案系統吃很重，讀寫增刪，後續還會有所謂權限、修改日期，實現這套會很
> 麻煩嗎？還是說有開源庫？

**AI 觀察（非裁決，可否決）**：

- **不麻煩，難的部分不用寫。** 跟核心講話、把系統呼叫翻成事件，這件事 **libfuse**（FUSE
  最主流的函式庫）已經做完了。要寫的是十幾個回呼函式（列目錄、讀、寫、建立、刪除、改名、
  改時間、改權限），每個都是同一個套路：**收到請求、做事、回答**。
- **門房最簡單的當法是 passthrough（穿透）**：底下擺一個真目錄，宿主收到什麼就原樣轉發
  給那個真目錄。libfuse 自帶穿透範例（C 版幾百行、Python 的 loopback 範例一百多行）。
  在範例上加兩件事——**每個請求記一筆**、**某些請求回答不行**——就是門房。權限與修改
  日期不用另外實作，穿透就是把底下真目錄的原樣狀態報上去。
- **庫對照**：C/C++ 用 **libfuse 3**（最正宗、自帶穿透範例、有 C++ 封裝）；Python 有
  `pyfuse3`、`fusepy`（也有 loopback 範例）；Rust 有 `fuser`；Go 有 `go-fuse`；Lua 的
  `luafuse` 老舊沒人維護，不建議。
- **AI 建議**（非裁決）：C++ 直接接 libfuse，門房可以是 aos 自己的一個子命令——aos 本來
  就是 C++23，不用為了這件事多養一個 Lua。
- **會咬人的地方**（是「要知道」不是「難寫」）：
  - **只有 Linux 有**——WSL2、Manjaro 可以，Windows 原生要另一套叫 WinFsp、介面不同；
    這跟既有裁決「aos 跑在 Linux 上」一致，不算新代價。
  - **宿主當掉，掛載點會卡住**——這時去讀那個資料夾的程式會 hang 住，要手動
    `fusermount -u` 解除掛載。所以底下**一定要是真目錄**（呼應 [fuse-host §d.2](fuse-host.md#d-三個提醒對應既定的三個目標指標)）。
  - **擋人要先認得敲門的是誰**——libfuse 能拿到敲門那個行程的 pid／uid，用 pid 去查是不是
    aos 自己，不算百分之百嚴密，但夠用。
  - **每個操作多繞一趟核心**——aos 一輪是秒到分鐘級，這趟繞路感覺不到。
- **更輕的替代**：如果只要「記錄」不要「擋」，Linux 內建的 **inotify**（檔案系統變更通知
  機制，只能「看」不能「擋」、不用掛載任何東西）就夠，幾十行就寫完；要「擋」或要「演出
  不存在的檔案」才真的需要 FUSE。inotify 可以當玩的時候的第一步。
- **規模估計**：穿透＋記錄＋擋人的門房，**C++ 幾百行、一兩天**。真正麻煩只出現在走
  [fuse-host-doorman](fuse-host-doorman.md) 裡「廚師」那條路線——樹根本不在磁碟上、全靠
  宿主演出來——那才是大工程，門房路線不是。

## 節二：跟 tmpfs 的差別

**使用者原話（2026-09-03）**：

> 那這跟/tmpfs的差別？

**AI 觀察（非裁決，可否決）**：

- **tmpfs＝用記憶體做的桌子。** 核心自己提供，用起來跟一般目錄一模一樣，東西放在 RAM
  裡、很快，關機就沒了（很多 Linux 發行版的 `/tmp` 本身就是 tmpfs）。**桌子上沒有程式在
  跑**：寫檔案就直接存進去，沒人知道、沒人擋、沒人記。
- **FUSE＝有門房的桌子。** 桌子本身可以是任何東西（真目錄、記憶體、演出來的），重點是
  **每一次讀寫都要先經過你自己寫的程式**。

| | tmpfs | FUSE 門房 |
|---|---|---|
| 誰在後面 | 核心，沒有程式 | 你寫的程式 |
| 東西放哪 | RAM | 你決定，通常是底下的真目錄 |
| 能不能記錄誰寫了什麼 | 不能 | 能 |
| 能不能擋人 | 只有一般 Unix 權限 | 能，按你自己的規則 |
| 能不能演出不存在的檔 | 不能 | 能 |
| 程式掛了會怎樣 | 沒有程式可掛，資料還在 | 掛載點卡住，底下真目錄的資料還在 |
| 重開機後 | 全沒了 | 看底下擺的是什麼 |
| 速度 | 最快 | 每次讀寫多繞一趟 |

- **兩者可以疊在一起**：門房底下的真目錄本身放在 tmpfs 上，就是「有門房的記憶體桌子」——
  快，但關機就沒。**對 aos 不建議**：[fuse-host §d.2](fuse-host.md#d-三個提醒對應既定的三個目標指標)
  已經提醒過，穩態要留得住，宿主不在時人才能隨時打開資料夾接手；放在 tmpfs 上等於自己
  把這個好處拿掉。
- **一句話**：**tmpfs 決定東西放在哪，FUSE 決定誰管著。** 使用者說「daemon 可以更漂亮」
  是「誰管著」的問題，跟東西放在哪（tmpfs）是兩件事，不衝突也不能互相取代。
