# 01 aos 是什麼、為什麼要有它、拿什麼尺量
← [入口](README.md)

這章講三件事：aos 底下那顆「CPU」是什麼、為什麼要在它上面蓋一層作業系統、以及蓋出來的東西要拿什麼尺量好壞。後面每一章的細節都可以回頭拿這章的尺去問「這讓人更方便寫、更方便跑、更方便管嗎」。這裡不講形狀，形狀從 [資料夾就是 list](02-folders-as-lists.md) 開始。

## 一個 agent loop 就是一顆 CPU

一顆能算任何東西的機器要同時有三樣本事，而一個 agent loop（LLM ＋ 工具 ＋ 迴圈）三樣都有，所以可以正名叫 CPU。

- **能算**：由 LLM 擔任。〔裁決 2026-09-01〕
- **能依外界改變行為**：工具是這台機器唯一看得到外界的器官，外面變了它才會變。〔裁決 2026-09-01〕
- **能重複執行自己**：本體不能無限膨脹——不能執行自己的話，一段長計算就得整段攤平寫進本體；由迴圈擔任。〔裁決 2026-09-01〕
- 三樣湊齊，agent loop 就可以當一顆 CPU，跟現代計算體系橫向對比。〔裁決 2026-09-01〕
- aos 的一句話目標：**一個以 agent loop 為計算單元的作業系統**，站的位置對應現代 OS 站在 CPU 之上的位置；「橫向對比」對的是位置，不是抄實作。〔裁決 2026-09-01〕

## 為什麼需要一層 OS

一顆 CPU、跑一支程式、一個人用、只跑一次——這種情況不需要作業系統，直接餵一串工作就好。是「多」把 OS 逼出來的。

- 四種「多」裡，**多程式、多次（跨時間）、多顆 CPU 要做；多人先不做**。〔裁決 2026-09-02〕
- 多程式逼出行程、程式與行程的分界、排程、載入器；多次逼出可存的狀態與記憶；多顆 CPU 逼出隔離、行程間通訊，以及傳話失真這條裂縫。〔裁決 2026-09-02〕
- **狀態必然落在檔案系統**：本體不能膨脹，狀態就得在迴圈之外，而迴圈的外面只有檔案系統。這條是推導出來的必然，不是選擇。〔裁決 2026-09-02〕
- 多人不做之後，「使用者是誰」塌成一句：**恰好一個使用者，而他也是一隻住在 `~` 的 agent**；授權整題消失，只剩「這句話是哪隻 agent 說的」這種來源標記。〔裁決 2026-08-30〕
- 整條推導收成一句：agent loop 是 CPU；人要多程式、多次、多顆地用它；狀態必然在檔案系統；所以要有一層管行程、記憶、隔離與中斷的東西——那層就是 aos。〔裁決 2026-09-02〕

## OS 的定義就是判準

使用者給作業系統下的定義只有一句「方便人使用」，往下拆成四條。這四條同時是判準：任何設計都拿它來問。

- 作業系統的核心概念就是**方便人使用**。〔裁決 2026-09-01〕
- 三件具體的事：**方便人寫程式、方便人寫的程式跑、方便人管理正在跑的程式**。〔裁決 2026-09-01〕
- 再加一層：**管理資源的使用**，例如 LLM 呼叫要排隊。〔裁決 2026-09-01〕
- 這是判準不是描述：**現代 OS 裡不服務這四條的部分，可以不要**。〔裁決 2026-09-01〕
- 前三件的主詞是人，第四件的主詞是資源；排隊是為了讓前三件在資源有限時仍成立，不是為了效率。〔AI 觀察〕

## 要優化的三樣，可預測性最優先

一般 OS 丟一堆計算任務下去、量花掉多少資源，主指標是時間。aos 的任務比較抽象，指標會多樣化，例如 token。

- **時間與空間只是粗淺的優化**；真正重要的三個是消耗的金錢（token）、可預測性、人類可理解性。〔裁決 2026-09-03〕
- 三個裡面**可預測性最優先**。〔裁決 2026-09-03〕
- 金錢與可理解性哪個在前，沒拍板，見 A-02。〔AI 觀察〕
- 資源的分配與管理包含計算資源與記憶體資源；**權限是很後面才做的事**，見[門房](10-doorman.md)。〔裁決 2026-09-03〕
- aos 早就定在 linux 上跑、善用 linux 機制，所以資源這塊不必想太多——linux 把硬體的邊緣狀況吸掉了，而且 aos 的時間粒度很粗、允許不規則。〔裁決 2026-09-03〕
- 可預測性有兩個現成量得到的落點：一條工作串自報要花多少 vs 實際花多少的差；同一件事跑很多次，結果的分布有多寬。不必等定義寫死就能先量。〔AI 觀察〕
- 現成 OS 家族裡唯一把可預測性當主指標的是即時系統（RTOS），那是對的親戚：它的期限對應「每格的預算」，它的優先序對應「串自報的優先級」，它的最壞執行時間對應「每回合最壞 token 數」。〔AI 觀察〕

## 一條要守的線：邊緣狀況只准從 LLM 來

- 邊緣狀況不會消失，只會搬家。aos 的邊緣狀況**只該來自 LLM**（不確定、傳話失真）；**不該來自機器**，機器來的就代表抽象漏了。〔AI 觀察 2026-09-03〕

## 傳話會失真，這是類比最深的一道裂縫

現代 OS 的行程間通訊是無損的，agent 之間不是。

- 大量 agent 合作時訊息層層轉手，每一手都可能失真；失真發生在**語意層**（用詞略偏、意思漂掉）不是位元層，**沒辦法用數學手段糾正**。一個小偏差會被下游當成前提，發散成錯誤風暴。〔裁決 2026-08-27〕
- 前提要正面承認：底下這顆計算單元本身的錯誤率就大於一，平均一個錯會引出不只一個下游錯，所以才會發散；不能假裝底層可靠只做上層邏輯。〔裁決 2026-08-27〕
- 三條對策方向：**關鍵節點插人類審核**；**同一件事多做幾份、多隻 agent 互審**（拿冗餘壓錯誤率，代價是大量算力花在驗證上）；**夠簡單夠穩的直接寫死成程式**。〔傾向 2026-08-27〕
- 第三條就是固化：把工作從 LLM 搬回確定性的指令。所以「哪些工作該固化」在 aos 裡等於「這段該由哪一顆 CPU 執行」。〔AI 觀察〕

## 從舊專案繼承的幾把尺

這幾條沒被拍板，但都是同一個方向：**縮小 LLM 的出場面積**。

- LLM 只該留在兩個介面：把人的意圖翻成結構化的動作，以及還沒固化的模糊前沿；其餘全是確定性程式。〔AI 觀察 2026-08-30〕
- 想讓 LLM 進某個環節要舉證——證明非它不可，而且測得夠穩。預設是零領地。〔AI 觀察 2026-08-30〕
- 大內容走路徑不走內嵌；測試不要只投影成功（要有髒回應、失敗回應的樣本）。〔AI 觀察 2026-08-30〕

## 什麼叫順手

「方便人」不能只當口號，要有可以驗的劇本。

- 目標一句話：**在 shell 打 `aos …` 就要有 coding agent 的效果**，使用情境類似，例如改某一段程式碼。〔裁決 2026-08-30〕
- 兩級劇本：**第一級是單人 coding agent**（待在程式碼資料夾裡、全程只用 `aos …`，拿現成 coding agent 做同一件事當對照）；**第二級是指揮一隊**（主 agent 派子 agent 各住一個資料夾、靠通訊錄互相投遞，使用者只跟主 agent 說話）。〔裁決 2026-08-30〕
- 第一級一定要驗的一條：**停掉、隔天再來，記憶還在不在**。〔裁決 2026-08-30〕
- 怎麼量：**不打分數**，只記三種東西——多餘的動作、看不見的狀態、錯誤訊息不指路；每條都附上拿現成工具做同一件事的對照。〔裁決 2026-08-30〕
- 第二級要先有通訊錄與派子 agent 的最小路徑，沒有就先記一條「做不到」當第一個發現。見[工具與通訊錄](11-tools-and-contacts.md)。〔AI 觀察 2026-08-30〕

## 現在的立場：先去玩

- 停在這裡：到目前為止只能大概知道**要管什麼**，**具體怎麼管**要有真的任務、真的使用經驗才知道，所以先去用現有的東西玩玩看。〔裁決 2026-09-03〕
- 後果：缺口表暫停往下設計，「OS 的第一塊」延後到玩過之後再選；要重啟設計的人，從玩的過程記下來的**阻礙**開始，不要從觀察開始。〔裁決 2026-09-03〕
- 概念層在這之後仍收了一輪尾，那批東西是定義與偏好，不是拍板。〔傾向 2026-09-04〕
- 跨機器這件事現在沒差，之後用 Plan 9。〔裁決 2026-08-28〕

## 我的意見

- **「分支由工具擔任」這句措辭該修**。工具只是感官與手腳，真正「看見之後決定要不要換做法」的是 LLM，而迴圈負責把決定接上控制流。在 09-03 之後的模型裡，分支實際落在兩個地方：`.aos` 裡的「選（決定下一個開哪個子資料夾）」，以及 `run` 的停止條件（這次沒產出新指令就停）。正文寫的是後者，但根基三要件那句還停在舊講法，兩邊沒對過帳。
- **「多次」被裁為必要，卻在 OS 帳上沒有掛靠點**。多次綁到兩樣東西：可存的執行狀態被判給迴圈自己的規格、記憶被判「屬 OS 還是應用未定」。結果是一個明確的必要需求，兩個承接點一個不在 OS、一個懸空。記憶那題放在[一塊地](03-land-and-life.md)。
- **成本帳與命名空間是唯二「拖了會鎖死」的兩條，但使用者裁了先去玩，兩件事沒有正面對撞過**。成本帳是量測儀，沒有它整層資源管理是盲飛，事後補等於重寫所有 LLM 呼叫點。建議：不做，但第一版留插口——LLM 呼叫都走同一個薄關口，關口先只記一行帳。
- **可預測性最優先拍板之後，指標那一整套推論只有一半被重看**。原本很多結論是照「金錢優先」推出來的，前提換了卻沒重推。目前能拿來當判準的只有「可預測性最優先」這一句，其他是空位。好消息是那兩個量法（自報 vs 實際、多次跑的分布寬度）今天就能量，不必等定義。
- **評估任務集還不存在**。量任何一條指標都要有一組固定的工作負載；現成最接近的是那批可重跑的最小重現腳本，改讀成固定工作負載是最省力的起點。

## 現況對照

- token 計費完全在體系外：沒有跨世界的計數，也沒有優先序。
- 一回合結束，系統唯一的產出是一個 8-bit 的離開碼；沒有「宣告了什麼／實際做了什麼／觀察到什麼」這三分。
- 順手判準已經試用過，發現記在一份表裡，另有二十幾支可重跑的最小重現腳本——那是現成的工作負載起點。
