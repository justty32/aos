# 02 一個資料夾就是一個 list
← [入口](README.md)

這章講 aos 上「程式」長什麼樣子：檔案是最小的東西，資料夾是把東西串起來的列表，程式就是那個資料夾。每個資料夾裡有一個叫 `.aos` 的東西，它是這串列表的第一個元素，決定其他東西怎麼被對待。這是整套模型的正中央——一塊地怎麼活（見 [土地與生死](03-land-and-life.md)）、`.aos` 裡面裝什麼（見 [`.aos` 裡面](04-inside-aos.md)）、時間怎麼走（見 [時間](06-time-and-clocks.md)）都掛在它上面。

## 檔案是最小單位，資料夾是可以巢狀的列表
lisp 的最小單位叫 atom、載體叫 list；aos 的最小單位是檔案、載體是資料夾。資料夾可以裝資料夾，就像 list 可以裝 list，巢狀這一格對得最準。

- **檔案＝最小單位、資料夾＝列表、程式就是那個資料夾。**〔裁決 2026-09-01〕
- **lisp 只是哲學參照，不是語法。** 使用者喜歡它簡潔，但 Python、Lua 也適合；不必真的寫括號。〔裁決 2026-09-01〕
- **「程式與資料同一種形狀」這件事落在資料夾樹本身**，不是落在 json。它撐的不是表達力，而是「自我改寫」：一個正在跑的資料夾能被另一隻 agent 讀進來、改一改、再放回去繼續跑。〔AI 觀察〕

## `.aos` 是第一個元素，其餘全是引數
一個資料夾寫成 list 就是 `(.aos 子資料夾… 檔案…)`。求值就是跑 `.aos`，資料夾裡其他東西都是跑它的材料。

- **求值＝跑 `.aos`，其餘內容是它的引數。**〔裁決 2026-09-03〕
- **引數靠檔名認，不靠位置。** 所以比較像具名引數，這也是順序不重要的原因。〔裁決 2026-09-03〕
- **資料夾裡東西的順序沒差，重點在求值。**〔裁決 2026-09-03〕 正在跑的那部分（接力棒）才有順序，見 [寫→編譯→執行](05-write-compile-run.md)。
- **資料夾沒有「位置上的第一個」，所以入口只能是約定的名字**，那個名字就是 `.aos`；這是資料夾與 list 在「入口」上唯一的差別。〔AI 觀察〕
- `.aos/` 是一個目錄，是機器的地盤；「`.aos` 是第一個元素」指的是這整個目錄。裡面裝什麼見 [`.aos` 裡面](04-inside-aos.md)。〔AI 觀察〕

## 穩態與暫態就是 quote
lisp 的 quote（加上引號＝「這只是資料，別拿去算」）在這裡就是「這份東西這次不會被動到」。

- **穩態＝求值幾次都不會變的東西**（你寫的程式、你放的資料）；**暫態＝這次求值會被改掉的東西**（進度、產物）。〔裁決 2026-09-03〕
- **寫程式＝開一個資料夾、放一堆東西進去，期望求值之後它變成我們想要的樣子。**〔裁決 2026-09-03〕
- **正在被求值的就是暫態那部分**：`aos exec` 就地推進它，穩態的留著不動。〔裁決 2026-09-03〕
- **資料夾同時是算式與結果暫存器。** lisp 的求值不改原式、回傳新值；aos 的求值是就地改資料夾，是「帶副作用的求值」。後果：想重跑，穩態那部分一定要留著。〔AI 觀察〕
- **一個資料夾裡有四種東西，寫程式只碰前兩種**：程式（模板，穩態）、資料（值，穩態）、接力棒（進度，暫態）、產出（暫態轉穩態）。後兩種是跑出來的，不是寫出來的。〔AI 觀察〕
- 什麼叫「跑完」見 [寫→編譯→執行](05-write-compile-run.md)。

## 資料夾拿到的是沒算過的原料
一般 lisp 的廚師收到的是切好的菜（引數先算完才進函數）；aos 的廚師收到的是整袋食材（原料原封不動送進去，`.aos` 自己決定怎麼辦）。這種「完全不幫你算、自己看著辦」的模型有個學名叫 operative（或 fexpr），使用者說「我要的就是這種」。

- **子資料夾跑不跑，完全由父資料夾的 `.aos` 決定。** 沒有自動求值，沒有預設順序；沒被點名的子資料夾就躺著。〔裁決 2026-09-03〕
- **`.aos` 收到的是沒被算過的原料，不是算完的值。**〔裁決 2026-09-03〕
- **拆平那套（把 f(g(x)) 攤成一步一步）是 `.aos` 內部的事，跟子資料夾求值無關。** `.aos` 內是機器層，`.aos` 外是資料夾樹。細節見 [`.aos` 裡面](04-inside-aos.md)。〔裁決 2026-09-03〕
- **「先跑子資料夾」不是做不到，是預設不做。** 想要的話在 `.aos` 開頭寫「先把所有子資料夾跑完再做我的事」，那就是一般 lisp 的先算引數，只是一種包裝。〔AI 觀察〕
- **環境就是資料夾本身。** 這種模型通常還要另外拿到「當時有哪些名字可用」；在 aos 裡 `.aos` 本來就站在資料夾裡，不必額外傳。〔AI 觀察〕

## `.aos` 對一個子資料夾恰有三種處置
全部都是「自己看著辦」。

- **當資料讀**（只讀內容，不跑）、**開它**（這時子的 `.aos` 才上場）、**轉手**（投遞給別人，自己不碰）。〔裁決 2026-09-03〕
- **分支就是「決定接下來開哪一個子」。** 因為子資料夾不會先被算掉，所以兩邊不會都先算一遍——這正是 lisp 裡 `if` 必須特別處理的同一個理由。〔AI 觀察〕
- **同時開兩個子＝並行；下一步同時讀兩邊的產出＝會合。**〔AI 觀察〕
- **一個資料夾的入口是一批，不是一個**：接力棒記的是「哪些串在跑」，是複數。〔AI 觀察〕
- 「開它」之後父要不要等、拿回什麼、壞了怎麼辦，見 [呼叫與失敗](09-call-and-failure.md)。

## 多個資料夾互相投遞，就是一群各管各的演員（actor）
同一台機器換角度看：一個資料夾看是求值、多個資料夾互投看是 actor、機器層看是 CPU，三個讀法不衝突。

- **多個資料夾互相投遞就是 actor**：各有收件匣、私有狀態、不共享記憶體、只能送訊息；投遞＝丟一則訊息過去。〔裁決 2026-09-03〕
- **留著批**：一個資料夾一回合可以同時推進好幾條線，不退回「一次只做一件事」；該模仿的是遊戲引擎一格掃過所有東西。〔裁決 2026-09-01〕
- **資料夾之內拆結構＝作用域**（像拆函數，改可讀性）；**資料夾之間拆＝actor 拓樸**（像拆成多個程式，改隔離與排程）。〔AI 觀察〕

## 人寫的原稿放頂層，`.aos/` 永遠是機器的
人放的東西與機器長的東西要分開住，不然等於在源碼目錄裡 build，人打開看不懂。

- **人寫的原稿放資料夾頂層。** 這個資料夾被父層點名打開時，載入器才把原稿讀進 `.aos/`，變成可以照著走的腳本；`.aos/` 一直是機器的，人不碰它。〔裁決 2026-09-03〕
- **「打開＝拿掉引號」的具體動作就是這一次讀入。** 讀入之前是穩態的程式，讀入之後就有了暫態的行程。〔裁決 2026-09-03〕
- 哪些檔算世界的一部分、哪些只是機器暫存，判別式在 [一塊地](03-land-and-life.md)。〔AI 觀察〕
- 版面歸屬表（每條路徑誰能寫）見 [指令面與分層](12-cli-and-layering.md)。

## 頂層資料夾誰開
沒有任何一個資料夾會自己醒過來，一定是外面有人去開它。

- **頂層資料夾由使用者在終端開，或由使用者開的 daemon 代開；資料夾不會自己宣告 init 然後自動起跑。**〔裁決 2026-09-03〕
- 把 daemon 也看成一個資料夾，「父決定要不要開子」就在整棵樹上一致成立、頂層不需要特例；細節見 [daemon](07-daemon.md)。〔AI 觀察〕

## 資料夾是活的：關掉再開，東西還在（image）
- **資料夾就是 image**（lisp／Smalltalk 那種活的、可持續變異的狀態，往裡面逐步加東西而不是重編一份新的）；「停掉、隔天再來，記憶還在不在」問的就是 image 活不活。〔傾向 2026-09-01〕
- 記憶怎麼放、地能長多大，見 [土地與生死](03-land-and-life.md)。

## 我的意見
1. **檔案更像「名字＋內容」，不像純值。** lisp 的 atom 只有值；檔案有檔名又有內容，像一個「名字綁著一個值」。使用者沒正面回答，穩態／暫態切的是另一刀（會不會被改），沒回答這條。我建議正面採納它的白話版：新增一個檔＝定義一個名字，規劃資料夾結構＝設計作用域與壽命。這跟「引數靠檔名認」是同一件事。
2. **「兩層互不相關」，但父「開過誰」記在機器層的檔案裡。** 資料夾層的狀態（點過哪個子、下一個開誰）住在 `.aos/` 的接力棒裡。可以接受，但要講清楚它是「資料夾層借住機器層的一根接力棒」，不是第二根。否則實作時很容易滑向「看檔案系統就好，子有產出就算做完」，那是 Make 的模型，跟「父點名才開」相反。
3. **資料夾是「本體」還是「表示」沒答。** 帶副作用的求值讓資料夾既是算式又是結果。載入器讀原稿進 `.aos/` 之後，原稿與腳本會分岔：行程跑到一半使用者改了原稿，算誰的？我建議「跑中不理原稿，下次被點名開才重讀」，改原稿等於換程式。
4. **「三種處置」裡的「開它」只有半座橋。** 開了之後等不等、拿回什麼、壞了怎麼知道，在 [呼叫與失敗](09-call-and-failure.md) 還是傾向與開放題。本章的裁決密度高，但沒有這一題，資料夾能不能當函數用還不能說死。
5. **同像性到底撐什麼有三種說法**（自我改寫、編譯每站同一棵樹、macro 與 eval 讀同一棵樹），全是 AI 提的。本章採「自我改寫」，前提是接力棒是明的資料（見第 05 章），不只是資料夾長得像 list。

## 現況對照
- 今天沒有載入器；`.aos/` 直接就是收件匣、批、常駐指令那些機器暫存，人寫的東西（agent 設定、工具表）也放在裡面，頂層與 `.aos/` 的分工沒做。
- 今天沒有「父點名才開子」的機制；要推進子資料夾得人手動下 `aos run <子>`。
