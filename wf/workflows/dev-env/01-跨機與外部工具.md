## 跨機 / 離線差異

兩台輪流開發：家裡 Manjaro Linux（repo 在 `~/repo/simple_tools/aos`）、公司 WSL2 Ubuntu（repo 在 `~/repo/simple_tools/aos`，見下方「公司那台」）。沒有 CI 差異，全部驗證都由 agent 跑。

**公司那台**：公司 WSL（Ubuntu），repo 在 `~/repo/simple_tools/aos`（試驗場 install.sh 的 symlink 指這份）；codex 直接叫 `codex`（`~/.local/bin/codex` 是指向新版原生執行檔的捷徑，見 [公司 WSL](../dispatch/aos-teams/01-公司WSL.md)），另有 `~/.local/bin/claude`（另一個帳號）。`~/projs/aos`（歷史改寫前的舊 clone）、`~/repo/aos-tools`（aos-mcp 的 mcp.json 寫死用它）**兩份都別用**。這台 codex／claude 程序數要少（見 [公司 WSL](../dispatch/aos-teams/01-公司WSL.md)）。兩台都可能是當下這台，所以**開場先確認在哪台、LLM 走哪個端點**。

**公司那台（Windows 側）補充**：

這台 Windows 上 repo 也在 `C:\code\mine\simple_tools\aos`（git bash `/c/code/mine/simple_tools/aos`）；在 WSL 建置就用 `/mnt/c/code/mine/simple_tools/aos`。git bash 的 `python3` 是假捷徑，跑 python／wf-lint 走 `wsl -e bash -lc 'cd /mnt/c/… && …'`。

codex 在 Windows 的登入已失效（WSL 重新 `codex login` 後同帳號 refresh token 輪替、Windows 那份被撤銷），**固定走 WSL 那份**，別兩邊輪流登入。寫法：`wsl -e bash -lc "cd /mnt/c/code/mine/simple_tools/aos && codex exec --approve-for-me -m <slug> - < '<提示檔的 /mnt/c 路徑>' > '<log>' 2>&1; echo EXIT=\$? >> '<log>'"`，提示寫成檔用 `-` 從 stdin 讀（slug 見 [aos-teams](../dispatch/aos-teams.md)）。

`--approve-for-me` 已含 workspace-write 沙盒，**不能**同時給 `-s`；沙盒預設不給網路，要 HTTP 加 `-c sandbox_workspace_write.network_access=true`。Bash 工具背景工作上限 10 分鐘，更久的在 WSL 內 `setsid nohup bash queue.sh &` 脫離，等 log 出現 `^EXIT=`。會改同幾個檔的多個 codex 任務**串成佇列**（下一個先 `until grep -q '^EXIT=' 前一個.log; do sleep 10; done`），不並行。最終報告在 log 最後一個 `^codex$` 行之後。

**公司這台的本機模型**：LM Studio 由使用者自己開（使用者 11-06：「本地lmstudio我開起來了，可以用」），開著時 WSL 直接連 `http://localhost:1234/v1`（WSL 是 mirrored 網路；server 用 `lms.exe`〔`/mnt/c/Users/WG-Guanyu/.lmstudio/bin/`〕`server start -p 1234`，不用 `--bind`）。**別長時間連跑**：這台跑模型推論時整台 Windows 當過機（先黑屏，疑似內顯被推論卡死）（[thinking 10-19 ideas § 6](../../../proto8/thinking/2026-10/19/ideas/README.md)）；用完關不關由使用者決定（`lms.exe server stop`、`unload --all`）。真腦驗收不用這台的小模型，走 eca，見 [02-模型端點](02-模型端點.md)「公司機只用 eca 驗真腦」。**不用區網 `192.168.1.146` 的 ollama**（使用者 10-15：「那就都用本地的就好，別碰146」）。
