## 跨機 / 離線差異

兩台輪流開發：家裡 Manjaro Linux、公司 WSL2 Ubuntu，repo 都在 `~/repo/aos`（家機使用者 11-13 晚「~/repo/aos」；公司那台見下方「公司那台」）。沒有 CI 差異，全部驗證都由 agent 跑。

**樹不跟著機器搬**（11-23 起）：aos 的樹的 stack 每台各有各的（家機是 repo 裡的 `~/repo/aos/.stack`，被 git 忽略；公司那台 11-24 起是 `~/aos-home/.stack/procs/repo-aos`），不跟著 git 搬（使用者 11-23「直接變成.stack，然後把它git ignore，就這樣。換機那一套就不用了。」）；llm kernel 也是各台自己跑。11-23 起每台一棵根在 `~/aos-home` 的樹，底下兩列：llm kernel（定義 `~/aos-home/llm`、stack `~/aos-home/.stack/procs/llm`）與 repo 那棵（子 daemon，stack 家機是 `~/repo/aos/.stack`，公司那台 11-24 起是 `~/aos-home/.stack/procs/repo-aos`）；公司那台已建好，家機還是 llm kernel 自己一台（stack `~/aos-home/.llm-stack`），要照說明書改。家機 11-22 起樹、公司那台 11-23 起樹（當時叫 `_stack`，之後改名）。每台要有什麼、殼設定檔怎麼寫、怎麼起樹，看[每台設定說明書](03-換機.md)。

**公司那台**：公司 WSL（Ubuntu），repo 在 `~/repo/aos`（`AOS_HOME` 指它的 `proto8`；11-13 起唯一一份；樹 11-23 起住 `~/repo/aos/.stack`，11-24 起搬進 `~/aos-home/.stack/procs/repo-aos`（公司那台 repo 裡已經沒有 `.stack`）；這台的 llm kernel 放 `~/aos-home/llm`，使用者 11-23「這台的llm kernel放~/aos-home/llm」；11-23 起 `~/aos-home` 是這台的樹根，llm kernel 與 repo 那棵是它底下兩列，repo 那列帶 `CLAUDE_CONFIG_DIR="$HOME/.claude-alt"`）；codex 直接叫 `codex`（`~/.local/bin/codex` 是指向新版原生執行檔的捷徑，見 [公司 WSL](../dispatch/aos-teams/01-公司WSL.md)），另有 `~/.local/bin/claude`（另一個帳號）。`~/projs/aos`（歷史改寫前的舊 clone）別用。這台 codex／claude 程序數要少（見 [公司 WSL](../dispatch/aos-teams/01-公司WSL.md)）。兩台都可能是當下這台，所以**開場先確認在哪台、LLM 走哪個端點**。

**公司那台（Windows 側）補充**：

這台 Windows 上 repo 也在 `C:\code\mine\simple_tools\aos`（git bash `/c/code/mine/simple_tools/aos`）；在 WSL 建置用 WSL 裡的 clone `~/repo/aos`，不要在 `/mnt/c` 底下跑（見[入口](../dev-env.md)）。git bash 的 `python3` 是假捷徑，跑 python 走 `wsl -e bash -lc 'cd ~/repo/aos && …'`。

codex 在 Windows 的登入已失效（WSL 重新 `codex login` 後同帳號 refresh token 輪替、Windows 那份被撤銷），**固定走 WSL 那份**，別兩邊輪流登入。寫法：`wsl -e bash -lc "cd /mnt/c/code/mine/simple_tools/aos && codex exec --approve-for-me -m <slug> - < '<提示檔的 /mnt/c 路徑>' > '<log>' 2>&1; echo EXIT=\$? >> '<log>'"`，提示寫成檔用 `-` 從 stdin 讀（slug 見 [aos-teams](../dispatch/aos-teams.md)）。

`--approve-for-me` 已含 workspace-write 沙盒，**不能**同時給 `-s`；沙盒預設不給網路，要 HTTP 加 `-c sandbox_workspace_write.network_access=true`。Bash 工具背景工作上限 10 分鐘，更久的在 WSL 內 `setsid nohup bash queue.sh &` 脫離，等 log 出現 `^EXIT=`。會改同幾個檔的多個 codex 任務**串成佇列**（下一個先 `until grep -q '^EXIT=' 前一個.log; do sleep 10; done`），不並行。最終報告在 log 最後一個 `^codex$` 行之後。

**公司這台的本機模型**：LM Studio 由使用者自己開（使用者 11-06：「本地lmstudio我開起來了，可以用」），開著時 WSL 直接連 `http://localhost:1234/v1`（WSL 是 mirrored 網路；server 用 `lms.exe`〔`/mnt/c/Users/WG-Guanyu/.lmstudio/bin/`〕`server start -p 1234`，不用 `--bind`）。mirrored 網路下，連 127.0.0.1 上沒人聽的 port 不會立刻被拒，要等到逾時（沒設逾時的程式約 127 秒；`::1` 會立刻拒）。aos 的 llm_http 連線逾時預設 10 秒，可在 llm kernel 每個端點包設 `connect_timeout_s`。litellm 11-24 開機慢就是它探 ollama 撞到這個。**別長時間連跑**：這台跑模型推論時整台 Windows 當過機（先黑屏，疑似內顯被推論卡死）（[thinking 10-19 ideas § 6](../../../proto8/thinking/2026-10/19/ideas/README.md)）；用完關不關由使用者決定（`lms.exe server stop`、`unload --all`）。真腦驗收不用這台的小模型，走 eca，見 [02-模型端點](02-模型端點.md)「公司機只用 eca 驗真腦」。**不用區網 `192.168.1.146` 的 ollama**（使用者 10-15：「那就都用本地的就好，別碰146」）。
