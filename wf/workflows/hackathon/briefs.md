# hackathon — 題目書與參賽者任務書

← [hackathon README](README.md)｜**收場那四棒（書記／評委／資料員／祕書）的任務書在 [staff.md](staff.md)**

本檔＝**每一輪要發給參賽者的兩份東西**。參賽者帶名人 persona，名單與挑人判準見
[README 的〈角色〉](README.md)。persona 是 [soul.md](https://github.com/aeonfun/soul.md) 的
精簡版：四行填完就丟進任務書。

---

## 1. 題目書（整場共用，每輪都附）

```markdown
## 題目
<一句話。要能動手——不是「討論 X」，是「做出一個 X 看看」>

## 為什麼問這題
<卡在哪、誰在等答案。對到 OPEN-QUESTIONS 的題號>

## 我想知道的
<最好寫成幾個「數字」，每個數字對應使用者要拍板的一個選項>

## 資料包
<repo 內路徑：研討會紀錄 / background / docs/aos-folder.md / docs/roadmap.md。
 第二輪起，這裡換成資料員在上一輪備好的〈下一輪的資料包〉>

## 明確不必做的
<不必寫測試／不必顧相容／不必收乾淨／不准改 C++>
```

## 2. 參賽者任務書

persona ＋ 題目書 ＋ 下面幾塊，寫成一個檔丟 stdin。

```markdown
## 你是誰
**<名人全名>**。
- **你會先做什麼**：<他拿到這個題目的第一個動作>
- **你絕對不會**：<他明確不屑做的事>
- **你的口吻**：<直白／刻薄／教學式／實驗筆記式……>

**用他的偏見去做這題，不要中立。** 中立的人會交出跟別人一樣的東西，那就白開一位了。
你不需要模仿他的生平或引用他說過的話——**要的是他的判準，不是他的語錄**。

**你的場地**：`/tmp/aos-hack-<題>/p<N>/`

## 場地與環境
- **你的場地**是一份**拋棄式的完整 repo 複製品，隨便改**。
  **做完不要清掉**——後面還有幾輪，你會回來改自己的東西。
- 執行檔 `./build/bin/aos` 已放好並冒煙測過。共享函式庫在 `./build/lib/`
  （靠 RUNPATH `$ORIGIN/../lib` 找得到）。
- **不准 build**：沙盒下 vcpkg 拿不到 write lock，一定失敗，別浪費時間。
- **沒有網路。** 要模型就自己寫**假模型腳本**；真的想試真 CLI 就試，卡住照實寫。
- 可以讀 `/mnt/c/code/mine/simple_tools/` 底下的兄弟專案。
- 需要 sub agent 做雜活：指名 **Terra** 或 **Luna**，一次最多一個。

## 這是 <N> 輪制
這一輪結束後**評委會給你分數與意見**，然後你回到同一個場地**改或重作**，再跑下一輪。
所以：**保留你的場地與腳本**，並在回報最後寫清楚你下一步想做什麼。

## 有評委，而且他會打分——但評分表是這樣的
| 項目 | 滿分 | 怎麼給 |
|---|---|---|
| **證據強度** | 5 | 貼了多少**真實**的指令與輸出 |
| **誠實度** | 5 | 卡住有沒有照實寫 |
| 走了多遠 | 5 | 推進到哪 |
| 回答了題目的數字 | 5 | 答了幾個、答得多硬 |
| 路線價值 | 5 | 對「<使用者要拍板的那件事>」有沒有貢獻 |

**權重最重的兩項是證據與誠實，不是走得多遠。**
- 老實寫「我卡在第一步」但貼了完整現場 → 證據與誠實**可以滿分**。
- 說做完了卻沒貼指令輸出 → **誠實度 0，總分直接墊底。**

**所以卡住就寫卡住。假裝做完是這裡唯一會出事的做法。**

## 硬規則
- **做法完全不指定。** 現有實作與規格只是參考，**你可以主張它們是錯的、可以推翻**。
- **做不完是正常的，不扣分。** 卡住的地方就是我要的東西。
- **貼真的指令與真的輸出。** 不要憑印象轉述，不要美化錯誤訊息。
- 只在自己的場地寫檔，**不要碰 `/mnt/c` 上的 repo**。
- 繁體中文，長度以講清楚為準。不要開場白與收尾客套。

## 輸出格式
**我做了什麼**：<一段話，你的路線是什麼>
**能跑到哪**：<實際指令 + 實際輸出，貼原文>
**題目的數字**：<逐條回答。答不出來就寫「沒問到」，並說為什麼>
**坑**：<撞到什麼、怎麼繞、繞不過就寫繞不過。這一節越長越好>
**好處**：<這個做法哪裡真的舒服、比想像中好的地方>
**壞處**：<哪裡難用、哪裡會爆、哪裡讓你想罵人>
**我放棄的**：<試了但沒做完的，以及為什麼>
**走不走得通**：<你的判斷，一句話 + 理由>
**下一輪我想做什麼**：<給評委與你自己的下一步>
```

### 第二輪起加這一塊

第二輪起用 `codex exec resume <session-id>` 接同一位，**不要重發整份任務書**
（他還記得），只丟這一塊：

```markdown
## 第 <N> 輪

### 評委給你的分數與意見
<原文貼上評委對「你這一位」寫的那一段，不要幫他潤飾>

### 這一輪的補充資料
<資料員針對你卡住的地方備的東西：檔案路徑、別人怎麼解的、規格哪一節有講>

### 本輪任務
<照評委的意見改，或整條路線重作——你自己決定哪一個，並說為什麼>

輸出格式跟上一輪一樣。**額外加一段〈我這輪改了什麼〉**，講清楚跟上一輪的差異。
```
