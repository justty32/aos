## 第 1 輪評分與意見

評委判題用的三個命題（第 2 輪沿用）：

- 成功＝整批輸入恰好變成一個可見的 ready delivery。
- 失敗＝沒有任何可見 delivery。
- `Already` 若存在，意思是「這個 key 曾經成功 publish」，不是「某個 process 曾開始嘗試」；volatile reservation 只證明 attempt。

評委指出的坑（仍成立）：

- **致命：無 ledger 卻公開冪等 `--key`。** aggregate 後，「K 從未 publish」與「K 曾 publish 但 delivery 已刪」的可觀測狀態可以完全相同，沒有程式能對兩段歷史都正確回答 `Already`。
- **會擋 C++ 方向：複製玩具 parser。** Deliver 與 canonical `read_all()` 對同一 batch 結果不同，「接受」就沒有單一意義。
- **隱藏成本：細分退出碼與「每個欄位都被讀到」。** 為實驗剛寫的 consumer 讀到某欄位，不證明真 caller 需要它；細分 exit 與 machine code 會變成兩份 taxonomy。
- **只是麻煩、可繞過：** 多寫 `-f` 或 `-`、相對路徑以 caller cwd 為基準、wrapper 擷取哪條 stream，都能用一句文法或單一 machine-output stream 消除。

拍板建議以第 2 輪為準，見 [12](12-第-2-輪評分與意見.md)〈如果現在就得拍板〉。
