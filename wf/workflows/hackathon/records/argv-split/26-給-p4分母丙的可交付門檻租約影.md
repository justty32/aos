#### 給 p4：分母、丙的可交付門檻、租約、影子世界

- **空回合的完整路徑（分母該包含什麼）**：`core/inst/src/run_exec.cpp` 第 95–155 行——`chdir` → `stat(".aos")` → `open`＋`read`＋`close` `.aos/version` 並比對 `"1\n"` → `aggregate_instructions`（內含一次 `lstat(inst.json)`，ENOENT 之後**再一次 `opendir(inst.tempd)`**）→ `claim_instruction`（一次 `lstat(inst.json.runi)`、一次 `read_file` 回 ENOENT）→ `return 0`。`did_work` 只有在 claim 回 `Ok` 之後才被設為 true（第 171 行）。**逐系統呼叫複本要對得上的就是這一串。**
- **`--loop` 那一層的成本**：`core/inst/src/run_loop.cpp` 第 64–82 行——`run_exec_once` → `if (result == 3) return 3` → 檢查 `g_stop_requested` → `!did_work && interval != 0` 才 `sleep_milliseconds`；`sleep_milliseconds` 是 `nanosleep`（第 51 行），**不是 fork**。`--loop 0` 被夾成 1 的規則與理由在 `docs/aos-folder.md`〈十二／已經被實作決定的〉前兩條。
- **丙那道門（規格已經替「只外放彙整」留好的門）有現成測試**：`core/inst/tests/test_handoff.cpp` 的 `TEST_CASE("handoff does not publish over an existing instruction")`（第 107 行）——`inst.json` 已存在時 `aggregate_instructions` 回 `Ok`、`result.published == false`、投遞留在 inbox、`inst.json` 內容不變。條文版在 `docs/aos-folder.md`〈六／彙整的規則〉的「**`inst.json` 已經有一份沒被讀走的批次時，這一輪不發布**，等下一輪再試。不覆蓋、不合併」。
- **丙要逐位元重現的其餘規則，全部在同一節**：〈六／彙整的規則〉五條——只收沒有狀況後綴的投遞、順序不保證（實作用字典序）、已有未取批次就不發布、無效投遞就地改名加 `.bad`、**發布成功之後才刪投遞**。實作對應：`core/inst/src/handoff_fs.cpp` 的 `is_delivery_name()`（第 98 行，用 `name.find('.')` 判斷第一個點之後是不是 `.json`——**不是 `endswith`**）、`core/inst/src/handoff.cpp` 的 `isolate_delivery()`（第 30 行）與 `remove_accepted_deliveries()`（第 37 行）。文件版在 `core/inst/docs/handoff.md`〈彙整規則〉與〈公開 API 與錯誤資料〉（`HandoffResult`／`HandoffIssue` 已有的 `published`、path、`InstState`、errno）。

- **孤兒／`setpgid`／租約，三個詞的現況已經有一份寫定的名詞表**：`wf/workflows/workshop/background/execution-and-turns/turn-boundary.md`〈孤兒行程（orphan）、process group 與 `setpgid`〉——「**已存在，而且是刻意的**……`timeout_ms` 那條路徑已經有對整個 process group 送 `SIGTERM`→`SIGKILL` 的處理，**缺的只有『parent 被外部信號砍掉』那一條路徑**」；同檔〈running marker（起跑標記）與租約（lease）〉——「**提案，目前不存在。** 它只能由 `aos exec` 本身寫……`exit` 欄位補不了這一半（`exit` 是 parent `wait` 完才寫的，而崩潰的定義就是沒走到那一步）」，並記了形狀限制（receipt 另放旁邊、先寫 receipt 後 rename、原子建立用 `renameat2(RENAME_NOREPLACE)` 或 `link`＋`unlink`）。

#### 給「aos 執行檔太胖」（提案 9）

- **胖在哪是連結決定，機制就在兩個檔裡**：`app/CMakeLists.txt` 最後一段 `target_link_libraries(aos_app PRIVATE ${aos_subcommand_libraries})`——**每一個登記過的子命令的 library 都連進同一支執行檔**；登記函式是 `cmake/AosSubproject.cmake` 的 `aos_add_subcommand()`（第 141 行起，含重名檢查與名稱字集限制）。
- **今天登記了誰**：`core/inst/CMakeLists.txt` 第 39 行（`exec`）與第 46 行（`init`）、`core/tooljson/CMakeLists.txt` 第 19 行（`tooljson`）、`core/llms/CMakeLists.txt` 第 44 行（`llms`）。**四支，就是 p3 說的那四個子命令**；`libaos_llms` 是被 `llms` 那一筆拉進來的。
- **場地那邊的連帶事實**：`wf/workflows/hackathon/gotchas.md`〈場地〉——「只複製 `build/bin/aos` 會跑不起來……執行檔的 RUNPATH 是 `$ORIGIN/../lib`，所以**要一起複製 `build/lib/*.so*`**」，並記了「原始碼 1.8 MB ＋ 執行檔與 .so 約 42 MB」。
