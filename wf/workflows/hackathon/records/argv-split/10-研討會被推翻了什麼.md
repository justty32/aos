## 研討會被推翻了什麼

**逐條對照。以下只陳述對照，不判斷誰對。**

### 三個好

| 研討會原本怎麼說 | 這輪實測到什麼 | 誰量的、哪一段輸出 |
|---|---|---|
| **好 1**：投遞外放是把唯一沒實作、安全性全押在上面的那一步補成真契約（四位獨立地都提、四位都排第一，開發者說是「唯一無爭議的淨賺」） | **四位獨立地都做出來了、都跑通了**；同時 **p4 一位推翻它的框架**：投遞根本不在 `aos exec` 裡，所以「把 deliver 外放」外放的是**零支**，`aos exec` 一行不動——研討會四位是「一致地推薦了那四支裡唯一一支本來就不在裡面的」 | p1（`aos-deliver` 端到端跑通，兩筆指令都執行）、p2（`hack/bin/aos-deliver`，走 stdin）、p3（`kit/aos-deliver` + 真 `aos exec`）、p4（**5 行 shell 全文**）。推翻的證據：p4 `grep -rn 'deliver' core/inst/src/run*.cpp app/src/main.cpp` → `exit=1 <- nothing` |
| **好 2**：介面從函式庫變成 argv 之後，shell 或 Python 一樣拿得到同一套協定（四位獨立地都提） | **四位獨立地都證實了**（p2 整包是 sh、p4 24 行 shell、p1 C/sh/py 三套、p3 sh+python）。**但價碼被兩位量出來了**，而且 p1 量到 python 版會讓毫秒輪詢直接失效 | p3：`python3 -c pass` **5.669 ms**／支 = `aos` 子命令的 6.5 倍、`/bin/sh` 的 13 倍，「要 Python 寫的第二顆 CPU，就是接受每回合多 15–20 ms」。p1：python 版 **10641 µs/回合** > 1 ms 輪詢間隔，實際回合率 **94/s** vs `--loop 1` 要求的 **944/s**。p3 另外標了現況：「今天 argv 那層**根本不存在**，`aos` 只有 `exec`/`init`/`tooljson`/`llms` 四個子命令」 |
| **好 3**：彙整政策從編譯期寫死變成換一支程式（四位獨立地都提） | **三位獨立地都正面驗到了**。**但 p4 一位指出它跟「零 fork 閒置閘門」互斥**，而研討會兩條都當成好處收下了 | p2 情境 1：配額版彙整「跟原版的差異就是一行 `head -n 2`」，`[{"argv":["/bin/echo","d1"]},{"argv":["/bin/echo","d2"]}]`，剩下兩份留在收件匣。p3 實驗 J：12 行 `sh` + `jq`，逆序＋每回合最多 2 份，`aos` 一行沒動、沒重編。p4：認為只有彙整有政策旋鈕，這是他推薦丙的唯一理由。互斥那條：p4〈壞處〉第一條 |

### 六個壞

| 研討會原本怎麼說 | 這輪實測到什麼 | 誰量的、哪一段輸出 |
|---|---|---|
| **壞 1（四位全中、四位都排第一）**：`.runi` 的崩潰不變式會降級成約定；三種死法在磁碟上會長得一模一樣 | **拆成三半：**（a）「三種死法一模一樣」**四位獨立地都證實**；（b）「唯一理由是同一個行程」**三位獨立地都推翻**——今天就已經分不出來了；（c）「一旦外放就分不出來」**三位獨立地都做出反例**。**p4 一位分歧**：他只推翻三分之一，並提出一個替代版本 | （a）p1 三個快照 sha256 全部 `e24be31a…`；p2 六個現場三個 diff 零差異＋「時間戳也救不了」（三個現場 ctime−mtime 都約 1 ms）；p3 gdb K1/K2/K3 → `f92bcff06f874b16…`；p4 `0a4278ce9cd0ca88` 三份一致。（b）p1 單體對照 P vs Q 逐位元相同（`a697f32d…`）；p2 單體 M1/M2/M3 三個 diff 零差異；p3 實驗 F 一筆 `rm .aos/inst.json.runi` 開鎖，`trace.txt` 證明兩批同時在跑。（c）p1 `flock`＋journal；p2 相位標記＋租約（碼 4/5/6）；p3 write-ahead sidecar（碼 11/12/13），今天的現場 → `UNCLASSIFIABLE` rc=1。分歧：p4「(b)(c) 分不出來的原因是孤兒執行器把整批跑完了——**鎖的壽命跟工作的壽命脫鉤了**，receipt header 解不掉」 |
| **壞 2（三位提）**：退出碼 3 會退化成「批次裡某一筆 exit=3」，`--loop` 失去唯一的停止條件 | **實測證實了（b）形狀；p3 一位指出它只在（b）成立**，在「driver 用 argv 叫」的形狀下退出碼 3 完整保留。**p4 一位另外測到一個沒人提過的路徑會把 3 弄丟**：照資深工程師的閘門原話字面實作 | 證實：p2 情境 3——`aos-claim` 那一筆自己回 3、**回合退出碼 = 0**。保留：p3 `p3-exec --loop rc=3`（與真 `aos exec --loop rc=3` 並排）。新路徑：p4 `AOS_GATE=1 ./bin/aos-round4 L` → **EXIT=10**，無閘門 → EXIT=3；「那句話要進規格得補上 `.runi`」 |
| **壞 3（兩位提）**：契約從編譯期的型別搬到執行期的退出碼與檔名 | **p2 一位加碼推翻它的嚴重性下限**：不是「半夜卡住」，是**整批資料無聲蒸發，連 `.bad` 都沒有**。p1 從另一面補了同一件事的形狀 | p2 第五節：外部 jq 彙整器 rc=0 放行拼錯 key 的投遞 → `aos exec` 在執行期 rc=1 → 規格第六節規定 `.runi` 照刪 → 那批消失；C++ 版會隔離成 `1.json.bad` 留在原地。p1：「今天這些狀態是 `HandoffState` 這個 enum，編譯器管；外放之後變成 **12 個整數**，沒有人管」 |
| **壞 4（一位提）**：`aos aggregate` 這種字串會變成 `.aos` 磁碟格式的一部分 | **沒有人正面測。p3 一位指出它跟〈壞 2〉一樣只在（b）形狀成立**——在（a）裡程式名寫在 driver 或角色表裡，`<folder>` 一個字都沒多 | p3 主張三末段。p2 明說沒碰；p4 明說 `kernel.json` 角色表「是設計題不是實作題」，不做 |
| **壞 5（三位獨立算到）**：最常走的路徑變成最貴的路徑；閒置回合外放後**至少**多一次 fork＋execve | **方向四位獨立地都證實，而且四位都說比研討會講的更嚴重**（因為沒人量過閒置回合有多便宜）。**但「至少多一次 fork」四位獨立地都推翻——零 fork 做得到。** p4 另外指出整個論證少了 `--loop` 週期這個決定性參數 | 倍率：p1 **18–57 倍**（8.6 µs → 158.6/490.6 µs）；p2 **CPU 125 倍**、每閒置回合 **7.4 次 fork**；p3 **wall 43×、CPU +327×**（外放三支 +2.58 ms）；p4 **70×–365×**（2.2 µs → 154/450/802 µs）。零 fork：p2 `/proc/stat` 交錯基準線 37 vs 32/53/77/34；p3 `ns_last_pid` 0.01/回合、gdb catchpoint 0 命中；p1 `mtimeguard` **1.11 µs / 0 fork**（比今天真 `aos exec` 的 8.6 µs 還便宜 7.7 倍）。週期：p4「`--loop 1` 時 802 µs 是災難，`--loop 100` 時是 0.8% 的雜訊——**把一個調參問題論證成了架構問題**」 |
| **壞 6（一位提）**：可呼叫的東西就會被呼叫，然後人把自己弄壞 | **沒有人碰。** p2、p3 都在回報裡明寫「沒碰」 | — |
