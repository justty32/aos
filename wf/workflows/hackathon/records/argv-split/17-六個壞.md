#### 六個壞

| 條目 | 裁決 | 依據 |
|---|---|---|
| **壞 1(a)**：三種死法在磁碟上長得一模一樣 | **證實了** | 四位、四種殺法、四種快照工具；最硬的是 p3 的 gdb（不靠 race）與 p2 的時間戳分析（mtime、ctime 都在回合開始前凍住） |
| **壞 1(b)**：「成立的唯一理由是同一個行程」 | **真的推翻了** | p1 的 P/Q 對照（現有二進位、逐位元相同批次，`kill -9` 與 EACCES 兩種崩潰 `.runi` 相同）；p3 實驗 F（一行 `rm` 開鎖、兩批同時跑）。**「同一個行程」買到的是偵測，從來沒買到診斷** |
| **壞 1(c)**：一旦釋放外放就分不出來 | **真的推翻了** | 三個獨立做法在 claim 與 release 分屬不同行程下做出判別：p1 `flock`＋journal、p2 相位標記＋租約（碼 4/5/6）、p3 write-ahead sidecar（碼 11/12/13，讀今天的現場 → `UNCLASSIFIABLE`） |
| **壞 1：p4 的分歧** | **換了命題的假推翻，但換出一個真發現** | 殺的是驅動器，執行器把整批跑完，他的 b 與 c 是同一個世界狀態。真發現：鎖的壽命跟工作的壽命脫鉤（單體 `exitfiles=1/2`）。「沒有便宜的解」被 p2 的 `flock` 租約推翻：孤兒跑完後核心自動放掉租約，判定翻成 `DEAD_MID_BATCH` |
| **壞 1：p4 的「取件完就死不需新格式就分得出來」** | **證據不足** | exit 檔落在 `B/.cpu/`，可能讀到鷹架痕跡。原理（exit 欄位當進度游標）合理也便宜，要重測 |
| **壞 2**：退出碼 3 退化成某一筆的 exit | **形狀 (b) 證實了；普遍性真的推翻了** | (b)：`aos-claim` 那筆回 3、回合回 0。(a)：`p3-exec --loop rc=3`。但 (a) 保留 3 是 driver 的設計決定，〈壞 2〉變形成「12 個整數沒有人管」 |
| **壞 2：p4 的新路徑**（照閘門原話字面實作會弄丟 3） | **真的（新發現）** | `AOS_GATE=1 → EXIT=10`／`AOS_GATE=0 → EXIT=3`。提案第 4 條進規格必須補 `.runi` 這個檔名 |
| **壞 3**：契約從編譯期型別搬到執行期退出碼與檔名 | **證實了，下限比研討會講的低** | 外部 jq 彙整器放行拼錯 key → 執行期 rc=1 → 規格第六節規定 `.runi` 照刪 → 那批消失，連 `.bad` 都沒有。不是「半夜卡住」，是資料蒸發 |
| **壞 4**：`aos aggregate` 字串變成 `.aos` 磁碟格式 | **證據不足**＋**只在形狀 (b) 成立**（分析） | 要等角色表（提案 7）拍板才有東西可測 |
| **壞 5**：最常走的路徑變成最貴的路徑 | **方向證實；量級兩頭都錯；「至少多一次 fork」真的推翻了——但推翻的代價是外放的定義被改小了** | 分子高估、分母（6–9 µs）沒人量過，兩個錯互相抵銷。零 fork 三位做到，都靠「把偵測留在裡面」；「exec 什麼都不知道還能零 fork」沒有人做到 |
| **壞 6**：可呼叫的東西就會被呼叫，人把自己弄壞 | **證據不足**（機制演出來了，傷害沒測） | p2 情境 3：手打一次 claim，世界卡在退出碼 3，今天沒有任何一支指令能救 |
