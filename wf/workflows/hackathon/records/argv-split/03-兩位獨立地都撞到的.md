#### 兩位獨立地都撞到的

**（八）影子世界會打壞規格第四節的相對路徑基準。**（p2、p4 實測）指令裡的相對路徑落到影子世界去：

```
（p2）指令：[{"argv":["/bin/sh","-c","pwd > out.txt"]}]
甲 aos exec        → out.txt: .../lab/sc-pathA/out.txt          內容: .../lab/sc-pathA
乙 exec-split      → out.txt: .../lab/sc-pathB/.aos/cpu.d/out.txt   內容: .../lab/sc-pathB/.aos/cpu.d
```

做乙就一定要影子世界，就一定動到 cwd 基準；研討會問的「helper 的 `cwd` 誰保證」——答案是沒人。

**（九）非互動 shell 會把背景 job 的 SIGINT／SIGQUIT 設成 `SIG_IGN`**（`/proc/<pid>/status` 的 `SigIgn: 0000000000000006`）。測 SIGINT 要用 `subprocess` 直接起（得到 `rc=-2`），或在有前景終端機的環境測。

#### 一位撞到、但值得單獨記的

- **`/bin/sleep` 自己就是一次 fork。**用 shell 寫輪詢迴圈要零 fork 閒置，改用 bash 內建 `read -t` 配一個沒人寫的 fifo。用 shell 寫 core helper 要注意這點。
- **`set -e` 會吃掉退出碼 3。**這個題目裡非零退出碼是正常結果，實驗腳本不能用 `set -e`。
- **`zsh` 的 `&&` 鏈會把 `pkill` 回 1 當失敗、整串靜靜中斷。**時序敏感的實驗寫成獨立 bash 腳本。`find` 被 alias 成 `bfs`、`ls` 會卡到逾時：用 `/usr/bin/find` 絕對路徑。
- **大陣列別開在 stack 上**：`char acc[4096][4096]` 直接 segfault（139），改 `static`。
- **並行 bug 要做歸因對照**：「事先彙整好、只搶 claim」0/30，才確定 race 在 aggregate 不在 claim。
- **影子世界自己會洩漏相位**：`.aos/cpu.d/` 底下 `aos` 自己的交接本身就是三個相位標記，快照比對時要排掉（`SNAP_EXCLUDE`）。任何真的 CPU 都得被告知要跑什麼，「被告知過」本身會在磁碟上留痕跡。
- **單體裡 race 不到「取件完就死」**（claim 到第一次 fork 只有幾十微秒）。用 gdb 斷點停在第一次 `fork`；手工 `mv` 構造的現場要標明「構造的，不是殺出來的」。
- **相位標記的寫入順序規則**：「**『給重跑許可』的標記寫在危險動作之前，『收回許可』的標記寫在之後。**」釋放時**先 unlink `.runi` 再清 sidecar**——孤兒 sidecar 無害，孤兒 `.runi` 有害。（這條是推理，窗口微秒級，沒實測。）
- **`.temp` 檔名共用**：規格第六節要投遞帶 pid「因為 `rename` 原子但寫入不是」，彙整卻用固定的 `inst.json.temp`；外放或多推進者之後是現成的資料損毀來源。
