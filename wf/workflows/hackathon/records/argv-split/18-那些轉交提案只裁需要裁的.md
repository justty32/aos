#### 那些轉交提案（只裁需要裁的）

| 提案 | 裁決 | 依據 |
|---|---|---|
| **第 11 條：去量那個數字** | **真的推翻了那個數字，而且更重要的是推翻了它的型別** | 見下一節。 |
| **第 5 條：`.runi` 鎖的是那一批還是那個世界** | **二分法本身錯了**（p2、p3 兩位獨立指出），見下面專節 | |
| **第 1 條：`aos world recover` 進規格第六節** | **真的推翻了它的字面版** | p3 實驗 A3：照「把 `.runi` 搬回 `inst.json`」寫，`DELIVERY-1` 被蓋掉、投遞檔已被 aggregate 刪除、**磁碟上再也沒有它**。我讀了 `aggregate_instructions`，它的守衛只有 `lstat(paths.base)`、完全不看 `.runi`，而 `run_exec_once` 把 aggregate 排在 claim 之前——**機制確認成立**。這是本輪最該立刻處理的一條，而且跟 argv 化毫無關係。 |
| **第 2 條：`.runi` 升級成租約、receipt 旁邊放** | **證實可行**（三個獨立實作）；**p4 的替代方案（exit 欄位就夠）被他自己的資料削弱** | p4 的 b/c 兩格 exit 檔都是 2/2，正因為孤兒把批次跑完了——exit 欄位在那個現場**不能**分辨。 |
| **第 4 條：`--loop` 停止條件改成回合開頭 `stat` 一次 `.runi`** | **真的推翻了字面版**（p4 的 `EXIT=10`），修法一個檔名 | |
| **第 9 條：「都算 core」＝同一支執行檔** | **證實了成本代價，但那是部署事實不是架構事實** | p2 0.79 ms／p3 0.877 ms vs `/bin/sh` 0.437 ms；`LD_DEBUG=statistics` 516041 cycles、80% 花在 4793 次 relocation。**但貴在一顆跟交接完全無關的 32 MB `libaos_llms`**——那是連結決定，拆得掉。**所以這條不該拿來反對提案 9 的原則**，它只說明「同一支執行檔」今天被實作成了一支胖執行檔。 |
| **第 15 條：argv 只是函式語意的投影** | **證據不足**（原則）＋**證實了捷徑不存在**（p3 坑 6） | 要投影就得有人在 C++ 裡寫薄殼，FFI 那條路是關的。 |
| **第 12 條：這套協定的讀者是誰** | **仍然無解，而且 p2 正確地指出主張三的「值不值得」直接卡在這題上** | 這是使用者的決定，量不出來。我同意。 |

#### 研討會沒說、這輪才撞出來的（裁決）

| 發現 | 裁決 |
|---|---|
| 規格第六節「不會有兩支 `aos exec` 同時跑同一個資料夾」是假的 | **真的推翻了**（p1 的並行實驗＋p3 的 A4／F，兩條獨立路徑；我從原始碼確認了機制，見下面專節） |
| `aggregate` 不看 `.runi`，退出碼 3 那條路徑上世界仍被改動 | **真的推翻了**（p3 A1；我在 `handoff.cpp:141` 一帶與 `run_exec.cpp` 的順序上確認） |
| 退出碼 3 一碼兩義（「有一回合沒跑完」vs「有一回合正在跑」） | **真的推翻了**（p3 A4）。真正成立的是 `R` ⟺ 有一回合沒跑完 **或** 有一回合正在跑——而少掉的那個析取項正是 `--loop` 用來決定停不停的那一項 |
| 彙整暫存檔名是固定的 `inst.json.temp`，而同一節替投遞規定要帶 pid | **證實了規格內部矛盾**（我讀了 `derive_paths`：`paths.temp = base + ".temp"`），**但實際傷害沒有人做出來**——見我給 p1 的第 1 項 |
| 使用者原話的字面版在邏輯上不可能（要跑「取件」這一筆，得先取件） | **證實了**（p2 情境 3），而且這解釋了為什麼形狀 (a)/(b) 必須分開 |
| 這個題目在今天的二進位上不可實驗 | **證實了**（四位獨立撞到，四種繞法全部留下可觀測的破口）。**這是本輪對路線最有價值的一條** |
