### 研討會沒說、這輪才撞出來的

| 這輪發現了什麼 | 誰量的、哪一段輸出 |
|---|---|
| **規格第六節「也不會有兩支 `aos exec` 同時跑同一個資料夾」是假的**——兩位獨立地都推翻，路徑不同 | p1：16 個並行真 `aos exec`，30 次試驗 **異常 23 次**（最糟一批被跑 3 次）；併發度掃描 N=2/4 乾淨、N=8 出現 2/30、N=16 是 14/30；歸因對照（事先彙整好只搶 claim）**0/30** → race 在 aggregate。p3：實驗 A4 兩支 `aos exec` 確實同時在跑（P2 rc=3 但**改了世界**）；實驗 F 一個 `rm` 之後兩批的 `trace.txt` 交錯 |
| **`aggregate` 不看 `.runi`，所以退出碼 3 那條路徑上世界還是被改了**——兩位獨立地都撞到（一位從 race、一位從狀態機） | p3 實驗 A1：`aos exec: refusing wA1: .aos/inst.json.runi already exists`／`rc=3`，但執行後 `.aos/inst.json` 出現了、投遞被吃掉，**同一個檔位上同時掛著兩批**（`B ∧ R` 規格沒有定義）。p1：同一件事的並行後果 |
| **退出碼 3 今天已經一碼兩義**：「有一回合沒跑完」與「有一回合正在跑」 | p3 實驗 A4：「今天在同一個世界上跑第二支 `aos exec --loop`，第二支會立刻自殺並印一行說世界壞了——**而世界好得很**。真正成立的不變式是：`R` ⟺ 有一回合沒跑完 **或** 有一回合正在跑」 |
| **規格第六節的彙整暫存檔名是固定的 `inst.json.temp`**，而同一節自己說投遞要帶 pid「因為 `rename` 原子但寫入不是」 | p1〈壞處〉。「行程內時只有一個彙整者所以看不到，外放（或多推進者）之後這是個現成的資料損毀來源。我的實作照抄了這個錯」 |
| **使用者原話的字面版在邏輯上不可能**（要跑「取件」這一筆 instruction，得先取件） | p2 情境 3 |
| **「零 fork 閒置閘門」與「彙整政策完全外包」互斥**，研討會兩條都收下了；三位對這個矛盾給了三種不同的處置 | p4〈壞處〉第一條（互斥，二選一）；p1 `mtimeguard`（把規格知識搬進**設定**，exec 不認識任何命名規則，1.11 µs / 0 fork）；p2「把彙整拆成**偵測**（留內）與**政策**（外放）」；p3 直接承認「閒置快速路徑本身就是一條寫死在核心裡的政策」 |
| **規格已經替「只外放彙整」留好了門**：`aggregate_instructions()` 在 `inst.json` 已存在時直接 `return Ok`，於是外部彙整先跑完，內建那支自動變成 no-op | p4〈好處〉。「這是我在這題裡最喜歡的一個發現：**四位沒有人提到**」 |
| **這個題目在今天的二進位上不可實驗**——四位獨立地都撞到（見第 2 節坑一） | p2 的講法：「四位在研討會上談了兩輪『該拆哪幾支』，**沒有一位發現這個題目在今天的二進位上不可實驗**。這就是唯讀研討會的極限」 |
| **量測工具本身在這台機器上不存在**，於是「量一個回合有多貴」變成前置工作 | p3 坑 2：「如果 roadmap 真要走成本路線，`aos exec --explain`（開發者提的）**不是加分項，是量測的前提**」 |
| **一條方法論上的話**（p1 一位提，直接對上研討會「四位獨立地都提」這個信心來源） | p1：「研討會 12 個好塌成 3 條、每條四位獨立地都提，被當成信心的來源。這一輪的證據顯示相反：四位獨立地都提的那個 1–3ms 是錯的，四位都排第一的〈壞 1〉因果是錯的，四位收攏的主張三方向是反的。**共識的寬度跟正確性沒有關係，因為四個人共享的是同一份沒被量過的前提。**」 |
| **一條規格層級的請求**（p3 一位提，他自己說「如果只能挑一件事帶走」） | p3：「規格第六節那句『所以這個不變式成立』要改——它今天是錯的，而且它錯的方式（`aggregate` 在鎖裡面改世界）會讓照它寫出來的 `aos world recover` 靜默吃掉使用者的一整批投遞。**這件事跟要不要 argv 化完全無關，現在就該修。**」 |
