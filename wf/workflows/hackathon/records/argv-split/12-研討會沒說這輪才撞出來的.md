### 研討會沒說、這輪才撞出來的

| 發現 | 證據 |
|---|---|
| **規格第六節「也不會有兩支 `aos exec` 同時跑同一個資料夾」是假的** | p1：16 並行 30 次異常 23 次，race 在 aggregate。p3：實驗 A4 兩支同時在跑（P2 rc=3 但改了世界）；實驗 F 一個 `rm` 後兩批交錯 |
| **`aggregate` 不看 `.runi`，退出碼 3 那條路徑上世界還是被改了** | p3 實驗 A1：`rc=3`，但 `.aos/inst.json` 出現、投遞被吃掉，同一檔位同時掛兩批（`B ∧ R`，規格沒定義） |
| **退出碼 3 今天一碼兩義**：「有一回合沒跑完」與「有一回合正在跑」 | p3 實驗 A4：第二支 `aos exec --loop` 會立刻退出並說世界壞了，而世界好得很。真正成立的是 `R` ⟺ 有一回合沒跑完 **或** 有一回合正在跑 |
| **彙整暫存檔名固定為 `inst.json.temp`**，同一節卻要投遞帶 pid「因為 `rename` 原子但寫入不是」 | p1：外放或多推進者後是現成的資料損毀來源 |
| **使用者原話的字面版在邏輯上不可能**（要跑「取件」這一筆 instruction，得先取件） | p2 情境 3 |
| **「零 fork 閒置閘門」與「彙整政策完全外包」衝突**，研討會兩條都收下了 | p4；三種處置見〈壞處〉 |
| **規格已經替「只外放彙整」留好了門**（`inst.json` 已存在時 `return Ok`） | p4 |
| **這個題目在今天的二進位上不可實驗** | 四位（坑一） |
| **量測工具不存在**，「量一個回合有多貴」是前置工作 | p3：`aos exec --explain` 是量測的前提 |
| **共識的寬度跟正確性沒有關係** | p1：四位都提的 1–3ms 是錯的、四位都排第一的〈壞 1〉因果是錯的、四位收攏的主張三方向是反的，「**因為四個人共享的是同一份沒被量過的前提。**」 |
| **規格第六節「所以這個不變式成立」要改** | p3：「它今天是錯的，而且它錯的方式（`aggregate` 在鎖裡面改世界）會讓照它寫出來的 `aos world recover` 靜默吃掉使用者的一整批投遞。**這件事跟要不要 argv 化完全無關，現在就該修。**」 |
