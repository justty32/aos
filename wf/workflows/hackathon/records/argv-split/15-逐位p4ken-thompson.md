**講評。** 你做了兩件別人都沒做的事，兩件都對。第一，你造了**丙**——只外放彙整一支——因為你發現題目問的「最少幾支」的答案不在甲乙之間。那是本輪唯一一個可以直接交給使用者去做的形狀，而且你找到了規格已經替它留好的門（`aggregate_instructions()` 在 `inst.json` 已存在時 `return Ok`；我讀了原始碼，第一個 `lstat(paths.base)` 就返回，**確認成立**）。第二，`--loop` 的週期：`--loop 1` 時 802 µs 是災難、`--loop 100` 時是 0.8% 的雜訊——**研討會把一個調參問題論證成了架構問題**，這句話是本輪對成本論證最有效的一擊，比任何一個微秒數字都有用。

**你要的那個回答：你的 `grep` 站得住，但它證實的不是你以為的那件事。** 我獨立跑了 `grep -rn 'deliver' core/inst/src/run*.cpp app/src/main.cpp`，`exit=1`，沒有結果；整個 `core`／`app` 底下 `deliver` 只以 `delivery`／`deliveries`（收件端的名詞）出現，沒有生產端。規格第十二節自己也寫著「**投遞那一步沒有實作**」。所以事實成立。**但研討會〈好 1〉自己就寫了這句話**：「投遞者本來就在世界外面——這是四支裡唯一一支『呼叫者本來就不在 `aos exec` 裡』的。」他們知道。**他們沒做的是把這個事實接到結論上**——一邊承認它不在裡面，一邊把它排進「該外放的四支」並列第一，然後拿這個去回答使用者「`aos exec` 只保持取指令執行指令」的問題。所以你的貢獻是真的，但它的名字是「**研討會自己寫下的事實，沒有人把它接到結論上**」，不是「研討會弄錯了一個事實」。這個區別會影響下一輪你怎麼寫它。

**扣證據分的地方，講清楚。** 你的 `round.c` 是「逐系統呼叫複製 `run_exec_once()` 空回合路徑」的**複本**，不是本體，你標明了——但你接著把它的 **2.2 µs** 當成整張 70×／205×／365× 表的分母。而你自己的交叉驗證（`--loop 1` 跑 5 秒、40 ms CPU、約 4700 回合）給的是 **8.5 µs**，差了將近四倍，你沒有調和這個差距。**那張表右邊每一個倍率都繼承了這個未解的四倍。** 另外：三處殺一次是 n=3、SIGINT 整欄沒有資料（你誠實寫了）、`aos-aggregate` 是 `jq` 玩具（你也誠實寫了）。誠實度給滿分，證據強度只能給 3。

**還有一個方法學上的破口你沒發現，而 p2 發現了。** p2 的坑六：**影子世界自己會洩漏相位**——`.cpu/.aos/` 底下 `aos` 會做它自己那一套交接，所以「批次寫進去了沒／claim 了沒／release 了沒」本身就是三個相位標記。他為此用 `SNAP_EXCLUDE` 把它排掉。你的 `aos-forensic` 判「取件完就死」靠的是 **exit 檔數 = 0**，而你自己的輸出顯示 `e1.txt`／`e2.txt` 落在 `B/.cpu/` 裡——**你可能在讀你自己的鷹架留下的痕跡，而不是乙的性質。** 這不是說你判錯了，是說這一格現在**證據不足**。

**下一輪你要做什麼（照這個順序）：**

1. **先把分母修好。** 用跟 p1／p3 同一個定義重量一次空回合（`--loop` 內部的邊際成本），把 2.2 µs 與 8.5 µs 之間那四倍解釋掉——是複本漏了什麼，還是 tick 解析度。**在那之前，你那張 70×–365× 的表不能拿去給使用者看。** 這是你這輪最大的技術債。
2. **把丙做成能交付的東西——這是你這輪唯一該優先的產物。** 你自己排的第 2 項就是它，我同意，但加兩個必要條件：（a）外部彙整器必須**逐位元重現**內建彙整的結果（同一批投遞、兩條路、比對磁碟），（b）**必須包含 `.bad` 隔離與 schema 驗證**——因為 p2 已經實測出來：不驗 schema 的外部彙整器會把「隔離一份壞投遞」變成「整批無聲蒸發，連 `.bad` 都沒有」。你的 `jq` 版今天就是那種。**丙的價值全部押在這一步上；沒有它，丙就是把使用者的資料交給一支玩具。**
3. **重測 forensic，先把影子世界的痕跡排掉**（照 p2 坑六的作法），再判一次「取件完就死」分不分得出來。
4. **「鎖的壽命跟工作的壽命脫鉤」這條你要繼續挖，但先去讀 p2 的 `lease-demo.sh`。** 你說這件事「沒有便宜的解——要嘛共命、要嘛長出一個 init」。p2 在同一輪用一把 `flock` 租約解掉了：孤兒跑完之後**核心自動放掉租約**，判定從 `RUNNING` 翻成 `DEAD_MID_BATCH`，沒有任何一行收尾程式碼跑過。**核心就是那個常駐的東西。** 你的發現是真的，你的「無解」不是。下一輪把租約接上你的乙，量它的代價——那才是你這條線的終點。
5. SIGINT 用 `script`／偽終端補齊，你自己排第一，我把它排到最後：它是空白，不是錯誤，而上面四項每一項都比補一欄空白值錢。
