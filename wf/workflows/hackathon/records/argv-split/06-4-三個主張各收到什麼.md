### 4. 三個主張各收到什麼

#### 主張一（成本）：四位都量了，四位都推翻了那個數字；驗收條件四位都做到了

**「一次 fork＋execve 約 1–3ms」——四位獨立地都量了，四位都推翻。**單位一律微秒（µs）或毫秒（ms），量法貼在各人回報裡。

| 被 exec 的那支 | p1（`spawn_bench.c`，`taskset -c 2`，n=2000） | p2（`forkexec.c`，n 見括號） | p3（`bench_fork.py` 線性回歸，30 次/點 × 9 點） | p4（`bench.c`，n=2000） |
|---|---|---|---|---|
| 純 `fork`＋`_exit` | p50 **27.1 µs**（mean 28.6） | p50 **35.7 µs** | — | — |
| 靜態小 C | p50 **71.9 µs** | p50 **84.0 µs** | — | — |
| 動態小 C／`/bin/true` | p50 **128.4 / 130.4 µs** | p50 **142.8 / 149.4 µs**（vfork 115.1） | 斜率 **0.222 ms/筆** | p50 **151.5 µs** |
| `/bin/sh -c :` | p50 **432.0 µs** | p50 **449.1 µs**（n=500） | 單支底價 **0.437 ms** | p50 **447.2 µs** |
| `aos`（同一支執行檔、busybox 式） | p50 **769.0 µs**（n=500） | p50 **789.2 µs**（n=1000） | 斜率 **0.861 ms/筆** | p50 **778.8 µs** |
| python3 腳本 | p50 **5487 µs**（5.49 ms） | p50 **5720.8 µs**（5.72 ms，n=200） | 單支底價 **5.669 ms** | — |

四位的結論措辭不同但方向一致：

- **p1**：「這個數字 90% 由『被叫的那支程式怎麼啟動』決定，跟 fork 幾乎無關。**四個人拿一個混淆了 primitive 與 callee 的數字論證了兩輪。**建議把它從所有論證裡刪掉，換成『一次外放 = 130 µs（binary）／430 µs（shell）／5.5 ms（python）』。」
- **p2**：「**這個數字不是一個常數，它是一個實作選擇**，跨度 68 倍。整個成本論證架在一個『它是常數』的假設上，那個假設才是真正錯的地方。」
- **p3**：「實測 0.861 ms，高估 1.2–3.5 倍。」那 0.639 ms 的差價花在動態連結（見〈壞處〉）。
- **p4**：「高估了 1.3× 到 20×……而且它偏保守。」

**空回合今天到底多便宜——四位獨立地都量了，四位都量到微秒級。**

| 量法 | 數字 |
|---|---|
| p1：`/proc/<pid>/io` 的 `rchar` 當回合計數器，60 秒 / **56667 個回合**，量化誤差 ±0.18 µs/回合 | CPU/回合 **8.6 µs**；wall/回合 1058.9 µs 減掉實測 nanosleep 1052.5 µs → **6.4 µs**。兩個獨立方法夾出「**空回合 ≈ 6–9 µs**」 |
| p2：兩點消去法，`aos exec 空世界` 減 `aos 無參數`（各 n=1000） | 邊際 **27.2 µs**（816.4 − 789.2） |
| p3：ctypes 掛 inotify 在 `.aos/inst.tempd` 上精確數回合（`--loop 1`，3776 回合 / 4000.9 ms） | wall **0.0596 ms**，CPU **7.9 µs/回合** |
| p4：`round.c` 逐系統呼叫複製 `run_exec_once()` 的空回合路徑（n=5000） | **2.2 µs**（他標明這是複本不是本體）；交叉驗證 `--loop 1` 跑 5 秒 40 ms CPU / 約 4700 回合 → **約 8.5 µs** |

**外放之後變多少：**

| 誰 | 情境 | 數字 |
|---|---|---|
| p1 | `split_driver` 五模式，n=20000（`full` 是 C 版工具） | inproc 2.30 µs / 0 fork；deliveronly **2.28 µs / 0 fork**；guarded 2.21 µs / 0 fork；mtimeguard **1.11 µs / 0 fork**；**full 158.55 µs / 1.00 fork**（self 17.30 + children 141.25）；full(sh) **490.63 µs**（n=5000）；full(py) **10641 µs**（n=500） |
| p2 | `loopcmp.py` 兩點消去法（T=3s vs 12s，`--loop 10`） | 甲 `aos exec --loop 10` **22.9 µs/回合**（0.229% 一顆核心）；乙天真版 **2852.1 µs/回合**（28.5%）；乙＋守門 **43.6 µs/回合**（0.436%） |
| p3 | 單支底價相加 | 外放 1 支 **+0.861 ms → wall 15×、CPU +108×**；外放 3 支 **+2.58 ms → wall 43×、CPU +327×** |
| p4 | `round.c` 外放彙整一支 | **154 / 450 / 802 µs**（`/bin/true` / `sh` / `aos`）＝ **70× / 205× / 365×** |

**驗收條件「零工作的回合必須是零 fork」——四位獨立地都做到 0 fork，證據的硬度不同。**

- **p2** 是唯一真的去數全系統 fork 的（`/proc/stat` 的 `processes` 欄，基準線與案例**交錯量**，每段 8 秒、輪詢 10 ms、約 800 個閒置回合）：

  ```
  基準（什麼都不跑）        32        甲 aos exec --loop 10        32     -> 每閒置回合 0 次 fork
  基準（什麼都不跑）        53        乙 split-loop 10（無守門）   5955   -> 每閒置回合 7.4 次 fork
  基準（什麼都不跑）        77        乙+守門 split-loop --gate    37     -> 落在噪音裡，0 次 fork
  基準（什麼都不跑）        34
  ```
- **p3** 用兩把獨立的儀器互相印證：`gdb` 的 `catch fork`（0 筆 instruction → 0 次命中；1 筆 → 1 次；3 筆 → 3 次），以及 `/proc/sys/kernel/ns_last_pid` 位移（N=100，扣掉 harness）：

  ```
  基準線：/bin/true                     → 0.00
  今天：aos exec（空 world）             → 0.00
  乙：p3-exec（空 world）                → 2.06
  乙：p3-exec --idle-fast（空 world）     → 0.01
  ```
  他的話：「**這條驗收條件不是外放的阻擋條件，是外放的必做項。**」
- **p1** 做了兩個守門變體並量了：`guarded` 2.21 µs / 0 fork、`mtimeguard` **1.11 µs / 0 fork**——「比今天真 `aos exec` 的 8.6 µs 還快 7.7 倍。所以成本這一題**不是外放的固有代價，是『每回合無條件 fork』的代價**。」
- **p4** 做到了，但量出一個沒人提過的代價：**照資深工程師的原話字面實作，退出碼 3 會消失。**

  ```
  $ AOS_GATE=1 ./bin/aos-round4 L     # 閘門只 stat inst.json 與 inst.tempd
    乙 WITH gate   EXIT=10   <-- 3 沒了
  $ AOS_GATE=0 ./bin/aos-round4 L
  aos-claim: refusing: L/.aos/inst.json.runi already exists
    乙 WITHOUT gate EXIT=3
  ```
  「那句話要進規格得補上 `.runi`。」

**p4 另外提出一個四位研討會參與者都沒提的參數：`--loop` 的週期。**「`run.cpp` 實測 `--loop 0` 會被夾成 1（`aos exec: warning: --loop 0 would busy-poll ... using 1 ms instead`），所以下限是 1 ms。`--loop 1`：多 802 µs 讓週期從 1.0 ms 變 1.8 ms，還吃掉近半顆核心——真的痛。`--loop 100`：0.8%——是雜訊。**整個成本論證只對 `--loop 1` 成立。研討會把一個週期參數的問題講成了架構問題。**」
