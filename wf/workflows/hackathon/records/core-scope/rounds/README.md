# core scope 黑客松 — 每輪紀錄（書記）

← [本場索引](../README.md)｜[hackathon](../../../README.md)

發生了什麼：各人做了什麼、坑的總表、三個數字收到什麼答案。不含判斷。

每輪紀錄都是固定六塊的一份報告，三份都超標，因此各自再按段落職責拆一層；輪次檔本身留在原路徑當導航。

| 輪次 | 導航 | 什麼時候會想看 | 分檔 |
|---|---|---|---|
| 第 1 輪 | [本輪索引](round-1/README.md) | 想看這場的起點：四位第一次把 loop 跑完，各自撞到什麼。 | [各人做了什麼](round-1/what-they-did.md)｜[坑的總表](round-1/pits.md)｜[好處／壞處](round-1/pros-cons.md)｜[結算](round-1/wrap-up.md) |
| 第 2 輪 | [本輪索引](round-2/README.md) | 想看第一次修正之後，哪些坑被解掉、哪些還在。 | [各人這輪改了什麼](round-2/what-they-did.md)｜[坑的總表](round-2/pits.md)｜[好處／壞處](round-2/pros-cons.md)｜[結算](round-2/wrap-up.md) |
| 第 3 輪 | [本輪索引](round-3/README.md) | 想看三輪跑完的最終現場數字，以及仍然留著的未知。 | [各人這輪改了什麼](round-3/what-they-did.md)｜[坑的總表](round-3/pits.md)｜[好處／壞處](round-3/pros-cons.md)｜[結算](round-3/wrap-up.md) |

四份分檔的職責（三輪一致）：

| 分檔 | 職責 |
|---|---|
| 各人做了什麼 | 這輪四位各自做了／改了什麼，逐人一段。 |
| 坑的總表 | 這輪撞到的坑，每條附四路的現場原文與錯誤訊息。**三輪都是份量最重的一份。** |
| 好處／壞處 | 書記對上面那批坑的正反兩面整理。與〈坑的總表〉講的是同一批坑，建議連著讀。 |
| 結算 | 題目那三個數字這輪收到什麼答案、評委上一輪交辦的事做到了沒（第 1 輪無此塊）、仍然不知道的。 |

> 想橫著比同一塊在三輪之間的變化（例如三輪的〈坑的總表〉），就照上表同一欄走。
>
> 原本是單檔 `rounds.md`，三輪寫到 51 KB，照 [DEV-GUIDE](../../../../../DEV-GUIDE.md) 的「膨脹即拆」按輪次拆成本資料夾；三個輪次檔隨後又各自超標，再按段落職責拆一層。舊路徑 `round-1.md`、`round-2.md`、`round-3.md` 仍在，只留導航。
