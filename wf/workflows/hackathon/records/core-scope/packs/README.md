# core scope 黑客松 — 資料包（資料員）

← [本場索引](../README.md)｜[hackathon](../../../README.md)

每輪之後針對卡住的地方找出的可參考資料，每條都有 repo 內路徑。

兩份資料包都超標，因此各自再按資料員的固定分塊拆一層；資料包檔本身留在原路徑當導航。

| 資料包 | 導航 | 什麼時候會想看 | 分檔 |
|---|---|---|---|
| 第 1 輪之後 | [本份索引](after-round-1/README.md) | 想知道第 2 輪開跑前，四位手上被塞了哪些現成材料。 | [卡住的清單](after-round-1/stuck.md)｜[repo 裡已經有答案的](after-round-1/in-repo.md)｜[兄弟專案裡可以抄的](after-round-1/from-siblings.md)｜[還是查不到的](after-round-1/not-found.md) |
| 第 2 輪之後 | [本份索引](after-round-2/README.md) | 想知道第 3 輪開跑前給了什麼料，以及上一份料實際被用掉多少。 | [卡住的清單](after-round-2/stuck.md)｜[上一輪給過的料，有沒有人真的用](after-round-2/was-it-used.md)｜[repo 裡已經有答案的](after-round-2/in-repo.md)｜[兄弟專案裡可以抄的](after-round-2/from-siblings.md)｜[還是查不到的](after-round-2/not-found.md) |

分檔的職責：

| 分檔 | 職責 |
|---|---|
| 卡住的清單 | 這輪四位各自卡在哪裡，每條附原始整理或現場檔案路徑。**先讀這份**，其餘三塊都是為了這些卡點而查的。 |
| 上一輪給過的料，有沒有人真的用 | 逐條回查上一份料有用／沒有用，沒用的再判斷是不是不相干。**只有第 2 輪之後那份有這一塊。** |
| repo 裡已經有答案的 | 卡點在本 repo 的文件、原始碼與既有實驗紀錄裡已經寫過的答案。 |
| 兄弟專案裡可以抄的 | repo 之外、同一批 simple_tools 兄弟專案裡可直接抄的實作與測例。 |
| 還是查不到的 | repo 與兄弟專案都翻過、確認沒有現成資料的那幾條。 |

> 第 3 輪之後沒有再備資料包，所以本資料夾只有兩份。
>
> 想橫著比同一塊在兩份之間的變化，就照上表同一欄走。
>
> 原本是單檔 `packs.md`，照 [DEV-GUIDE](../../../../../STRUCTURE.md) 的「膨脹即拆」按輪次拆成本資料夾；兩份資料包隨後又各自超標，再按分塊職責拆一層。舊路徑 `after-round-1.md`、`after-round-2.md` 仍在，只留導航。
