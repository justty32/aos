#### （3）`aos agent` 該收掉什麼的優先序

判準：**拿掉它會不會死。** 完整版在[評委的清單](13-二aos-agent-該收掉什麼.md)。

**最前面兩件（會花錢或會安靜掉資料）**

1. **崩潰現場看得出來、救得回來。** `aos exec` 派小孩出門前先寫條子（含行程編號），加一支只看不動的救援命令，攤開現場：小孩還活不活、收件匣其實已被搬走。重播要人明確要求；孤兒還活著就拒絕動作。這是 `aos exec` 的 C++，T5「loop 不含新 C++」對「跑」成立、對「救」不成立。
2. **送出去之前先驗一次。** 送出前擋下 → 錯誤餵回模型 → 模型改對；送出後才擋 → 丟一旁 → 回 0 → 循環安靜死掉。aos 目前沒有「只驗不跑」的入口。

**中間三件（四位都重寫過）**

3. 從外面分得出「做完了／沒事做／壞掉了／正在想」，並給 `--loop` 停止條件。
4. 「下一批要跑什麼」只寫一次；現有指示詞解不掉。
5. 三個輸出檔的路徑不要手打；大小取決於架構怎麼切。

**後面四件（繞得過或已半解決）**

6. 投遞——真正該收的是防撞號碼。
7. 工具登記表——`aos tooljson` 已存在但沒人讀過，讀之前不為這條開新規格。
8. 三支 CLI 各自的接線——收成一份契約加各家設定，不收成一支命令。
9. 組 prompt 與工具結果回程的型別——痛的是形狀不是錢，排最後。

**明確不要收**：不為 LLM 往指令格式加欄位；不為效能動 `aos exec`。

**如果今天就得拍板**：先做第 1 件（晚做的成本是已花掉的錢），並補規格漏洞——**退出碼 3 之前不要搬收件匣，或至少寫明它會搬。**

#### （4）這一輪會動到你手上哪些還沒拍板的決定

只列牽動關係，不做建議。

- **`aos agent` 為什麼存在**：從「讓 loop 好寫」變成「讓 loop 壞掉之後有救」。
- **T5 的驗收條件與 D6 的矛盾**（`docs/roadmap.md` T5 底下的警示區塊：「中途 Ctrl-C 之後能從斷點繼續」與 D6 矛盾，兩條擇一：改措辭承認續跑就是回合邊界／長出真正的復原路徑；拍板前不照這條驗收實作）。本輪的現場：批次層級可以續跑，指令層級不行。
- **golden slice 鎖哪一支 CLI（OPEN #6）**：三種答案的前提都有裂縫（主張 pi 的沒接 pi；主張 codex 的理由之一未查證；讓解析變簡單的旗標是廠商專屬）。三支都是 agent，沒把模型工作目錄指到空資料夾的量測，有一部分量到的是 CLI 的能力。
- **要不要先試 `aos llms`**：若它能直接當模型站，OPEN #6 的答案變成「不要用 CLI」，T5 與 T6 的邊界要重畫。
- **`.runi` 鎖的是那一批指令還是整個世界**：既有提案都預設了答案卻沒講明；孤兒現象讓這題不能再拖。
- **同時要兩個工具的形狀（`tool_call_id`）**：是協定不是實作，晚定形狀會很貴。
- **還不能拿去改規格的回報**：「pi 不吃 stdin」與「codex 的 session 資料夾是空的」，都沒有任何輸出。
