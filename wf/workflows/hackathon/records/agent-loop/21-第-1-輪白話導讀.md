## 第 1 輪白話導讀

> 給沒跟到現場的人看的翻譯。

### 一、這一輪到底發生了什麼

四個人各用一百多行小腳本，讓付費 AI 服務自己一步步把事做完（問它 → 它選工具 → 跑工具 → 結果給它看 → 直到它說做完），都成功了。也都撞到同一件事：中途關掉總管程式，被叫出去的付費服務不會停，它會做完、還排好下一步；總管回來卻不知道，只把門鎖上說「上次沒做完，人來處理」。人照直覺解鎖，會把已做完的成果無聲刪掉，再付一次錢重做。

### 二、冒出來的新詞

| 詞 | 白話 | 在 aos 裡 |
|---|---|---|
| 孤兒行程／`setpgid`／process group | 你叫小孩去跑腿然後先走了；小孩照樣跑完，只是沒人知道他回來過。`setpgid` 讓小孩自成一隊，Ctrl-C 誤傷不到，也叫不停 | 已存在且是刻意的（`docs/aos-folder.md` 第十二節）。本輪所有坑都從這裡長出來 |
| running marker／租約（lease） | 把「有人在裡面」的鎖換成一張條子：誰、幾點、做第幾件 | **提案，不存在。** `aos exec` 在派小孩出門前寫條子（含行程編號），正常結束再撕。評委列第一，只有 `aos exec` 做得到 |
| 短路／`"needs"` 欄位 | 接力第一棒摔倒，後面的人就不跑 | **提案，不存在。** 現在前一筆失敗後面照跑、整回合回 0，這是規格寫明的行為 |
| 結構化輸出（`--output-schema`） | 發一張表格給對方填 | codex 的旗標，不是 aos 的。廠商專屬，不能當「解析不是問題」的證據 |
| `aos recover`／`aos deliver`／`aos status --json`／`aos agent step` | 出事後攤開現場／安全放進收件匣／看是做完還是壞了／說出下一步 | **四支都是提案，不存在**，參賽者各自用 shell 寫 |
| `aos llms` | aos 內建、直接跟模型講話的命令 | **已存在**（`core/llms/`，`ask`／`models`）。沒人測，本輪最大的集體盲點 |
| `aos tooljson` | 工具名 → 實際命令的登記表，附參數檢查 | **存在一半**：`list`／`check` 有，`run` 沒有 |
| `thread_id`／rollout 檔 | 客服先給的案件編號，線斷了拿編號查得回來 | codex 給的，第一行就到、早於答案；本機紀錄在 `~/.codex/sessions/<年>/<月>/<日>/rollout-*.jsonl` |
| ARG_MAX | 一次能塞進命令列的字數上限，對話越長越危險 | 作業系統設的。「pi 只能塞參數」的論證在重測前不採用 |
| JSONL 與「`jq` 預設吃串流」 | 一行一則的紀錄檔；`jq` 會把 30 則各自處理、不抱怨 | 要檢查「剛好一則」寫 `jq -e -s 'length==1'` |
| markdown 圍籬 | 對方回話時自己加一圈框線，講明不要也加 | claude 的行為，要自己用 `sed` 剝，很脆 |
| sentinel 檔（`DONE`） | 桌上放一張「我做完了」紙條 | 參賽者自己發明的，`aos` 不認得，是「沒有停止條件」的補丁 |
