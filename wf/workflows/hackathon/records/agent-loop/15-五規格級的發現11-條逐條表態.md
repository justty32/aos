### 五、〈規格級的發現〉11 條，逐條表態

評委對照 `core/inst/src/run_exec.cpp`、`docs/aos-folder.md` 第五／六／七／八／十二節、`core/inst/docs/format.md`、`docs/inst-directives.md` 判定，分開「實作與規格對不上」「規格沒寫」「參賽者誤讀」。條目見[規格級的發現](09-規格級的發現.md)。

| # | 判定 | 一句話 |
|---|---|---|
| 一 | **真的（規格沒寫，後果嚴重）** | `aggregate` 確實在 `claim` 之前 |
| 二 | **真的** | 是第一條加上孤兒現象的必然結果 |
| 三 | **真的，而且是根因** | 規格自己的兩句話互相矛盾 |
| 四 | **真的** | 規格沒有指定恢復動作，該新增 |
| 五 | **真的（格式層）** | 要 per-attempt 路徑，不要 append |
| 六 | **真的，但提出的解法只夠一半** | 要 fork 前的 marker |
| 七 | **真的，但是設計錯配，不是實作 bug** | 規格前提是多個獨立生產者 |
| 八 | **不是對不上** | 實作與規格一致，這是功能請求 |
| 九 | **不是對不上** | 符合規格；該提的是新的展開指示詞 |
| 十 | **不是對不上，但規格那句話該改** | 「檔名帶 pid」改成「檔名必須唯一」 |
| 十一 | **真的，但規格自己已經寫了** | 新資訊是 counter，不是 temp+rename |
