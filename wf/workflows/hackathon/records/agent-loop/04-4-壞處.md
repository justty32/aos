### 4. 壞處

- **沒有停止條件。** `aos exec --loop` 不知道「做完了」；sentinel 檔要自己發明，終止條件只能放在世界外的行程裡。
- **退出碼對 agent loop 幾乎沒有資訊量。** `exit=0` 有四種意思（見[坑的總表](02-2-坑的總表/03-兩位獨立地都撞到.md)）。
- **批次不短路，而 agent loop 就是一條 pipeline。** 模型站掛了之後，後面各站只是把垃圾往下游推（等於沒有 `pipefail`）。
- **`.runi` 只知道「沒跑完」，不知道「做到哪」**，而後者才是復原需要的。它鎖的是佇列不是世界：上一批的子行程可能還在世界裡跑，任何「先 `mv` 回去再重跑」的復原都在跟看不見的孤兒賽跑。
- **`exit` 檔在最需要時一定不存在。** aos 在子行程 `wait` 完才寫 `exit`，崩潰就是沒走到那一步；缺 `exit` 檔分不出「沒跑」與「跑完了但 parent 死了」。
- **去程有型別，回程沒有。** 模型輸出可以用 schema 定型，工具結果回程只是自己截斷、手拼進 prompt 的純文字。
- **stage 檔名全靠手打。** 七站管線手打 `run/<站>.<out|err|exit>` 39 次，打錯不報錯（漏一次 `stderr` 就把診斷印到終端機）。次數取決於架構怎麼切，別的架構只有個位數。
- **冪等靠自律**，有一個工具忘了寫守衛，「重播是安全的」就破了，而且沒有訊號。
- **中間檔只保留最後一回合**，第 N 回合的現場回不去。
- **tool registry 不存在**，自己寫容易寫錯（見[坑的總表](02-2-坑的總表/03-兩位獨立地都撞到.md)）。
- **一個 agent 步驟要兩個 `aos exec` 回合。** 彙整在下一次 `aos exec` 開頭，模型回合與工具回合之間隔一個彙整（`--loop 200` 下每步多 200 ms）。回合數 ≠ agent 步驟數，規格講「第幾回合」要先講清楚是哪一種。
- **把 agent CLI 當 LLM 用，每回合付一份不屬於你的 system prompt**（codex 約 15.6k token／回合、claude 一次 "OK" $0.086）。
