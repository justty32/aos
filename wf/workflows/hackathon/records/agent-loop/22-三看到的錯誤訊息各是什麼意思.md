### 三、看到的錯誤訊息各是什麼意思

**aos 自己講的話**

| 你看到的 | 白話 |
|---|---|
| `aos exec: refusing w1: .aos/inst.json.runi already exists`／`exit=3` | 上一回合沒正常收尾，不敢開工。但說這句**之前**已經把收件匣搬空了。也是唯一會讓 `--loop` 停的碼 |
| `aos exec: warning: ...: UnknownKey` | 投進來的紙條有不認得的欄位。這張被跳過，整體仍 `exit=0` |
| `aos exec: warning: ...: FieldTypeMismatch`＋檔案變 `.bad` | 欄位型別錯。壞的那張被改名丟一旁，不擋別人，整體仍 `exit=0`；**模型永遠不知道被退件**（訊息去了 stderr） |
| `exit=0` | 四件事同一個碼：正常跑完／沒事做／模型說做完／模型參數寫錯導致下一步被丟 |
| `exit=1` | 回合本身出問題（子程式失敗仍算 0） |
| `exit=2` | 命令下錯了 |
| `model.exit=MISSING` | 那一筆的結果碼沒寫下來。**不代表沒跑完**——寫它的是總管，總管先死就沒人寫 |

**作業系統／殼層的話（不是 aos 的錯）**

| 你看到的 | 白話 |
|---|---|
| `exit=130` | 被 Ctrl-C（SIGINT）打斷 |
| `exit=137` | 被 SIGKILL 強制砍掉，沒有善後 |
| `exit=124` | `timeout` 自己動手砍的，代表被測的東西沒自己停 |
| `exit=127` | 找不到程式（這台機器沒有 `/usr/bin/time`） |
| 送了 SIGINT 卻 `codex_exit=0` | 背景工作預設忽略 Ctrl-C，信號沒打中 |
| `ls` 沒輸出或卡 2 分鐘 | 這台機器的 `ls` 是別名，會去掃整個 repo 的 git 狀態；改用 `find` |

**codex 的話**

| 你看到的 | 白話 |
|---|---|
| `ERROR rmcp::transport::worker: ... AuthRequired ...` | codex 自己的外掛服務連不上，每次都噴、無害。不能用有沒有紅字判斷成敗 |
| `error: unexpected argument '-s' found`／`exit=2` | 全域選項要放在 `resume` **前面** |
| `Not inside a trusted directory` | 要加 `--skip-git-repo-check` |
| 中途砍掉後 `-o` 的答案檔不存在、紀錄停在 `turn.started` | 開始了、沒完成；不會讀到半截答案，但本機看不出對方有沒有計費 |

**參賽者腳本印的話（不是 aos 的行為）**

| 你看到的 | 白話 |
|---|---|
| `mdl: connection refused`／`mdl = 7` | 故意換上必定失敗的假模型，驗證後面會不會照跑。會 |
| `inst: 沒有這支工具: nosuchtool`／`exit=3` | 腳本自己的退出碼，跟 aos 的 3 無關 |
| `put: 空批次，不投遞（迴圈到此結束）` | 沒有下一步了。模型講錯工具名與宣布完成印的都是這句 |
| `REJECT unknown tool: nuke_everything` | 送出前擋下並把錯誤餵回模型，下一回合模型改口。整輪唯一的自我修復 |
| `DIFFERENT -> DOUBLE BILLED` | 兩次呼叫的案件編號不同：同一件事付了兩次錢 |
| `kind=null`（× 33） | 把 30 幾行紀錄整包當成模型回答，每行都解讀失敗 |
