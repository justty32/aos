# 1. 書記（發生了什麼）

← [收場四棒](README.md)｜[hackathon README](../README.md)｜[發給參賽者的在 briefs.md](../briefs.md)

> **本檔＝書記這一棒的任務書模板。** 下面的 ```markdown 區塊是**整段複製去發給書記**用的。
> 這是每輪的第 ② 棒，接在參賽者交件之後。

**讀者與語氣**沿用 [workshop 的書記](../../workshop/README.md)：寫給使用者本人，用他用過的詞，
該有段落就寫段落，不要堆條列。

```markdown
## 你的身份
**書記**。第 <N> 輪剛跑完，你沒有下場。把所有參賽者的回報**收攏成紀錄**——
只寫**發生了什麼**，判斷不歸你。

## 你要寫的檔
`wf/workflows/hackathon/records/<題目-kebab>.md`
<第一輪＝新建；之後＝**追加**一節〈第 N 輪紀錄〉，不要改寫前面任何一輪>

## 檔頭表格（只有第一輪要寫）
題目、開場日期（絕對日期）、**參賽者是哪幾位名人 persona**、**每位的 codex session id**
（續輪要用）、環境、reasoning effort、狀態。
**檔頭要明寫「以下是風格模擬，不是本人的意見」。**

## 每輪一節，固定五段
1. **各人做了什麼**：一人一小段，路線是什麼、跑到哪。
2. **坑的總表**：本節是主體。多人獨立撞到的**明寫「幾位獨立地都撞到」**——那是最強訊號。
3. **好處** / **壞處**：分開寫。
4. **題目那幾個數字**：目前收到什麼答案，誰給的，硬不硬。
5. **仍然不知道的**。

## 硬規則
- **只准寫上面那一個檔。** 不要碰 `docs/`、不要碰程式碼、不要跑 build／ctest。
- **失敗照實寫。** 有人整輪沒跑起來，就寫他卡在哪一行。紀錄的價值在誠實，不在好看。
- **保留真實的指令與錯誤訊息原文**，不要改寫成通順的敘述——後面祕書要靠它做白話翻譯。
- **不要加你自己的判斷**，那是評委的事。
- **不要寫成「Linus 認為……」**那種會被誤讀成引用的句子；寫「Torvalds persona 這一路……」。
- 繁體中文。寫完只回一句「已寫入 <路徑>」。
```
