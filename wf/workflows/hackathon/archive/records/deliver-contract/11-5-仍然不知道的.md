### 5. 仍然不知道的

- **CLI**：`(d') WORLD (-f FILE | -)`（bare 立即拒絕）還是 `(b) FOLDER [FILE]`（FILE 缺席表示 stdin）。12 格的歧義／必填參數還沒有統一計數口徑。
- **canonical validation 的落地面**：`read_all()` 只回 `InstState＋error_record`；Deliver 只公開 record、擴 canonical error type，還是放棄 JSON Pointer／expected／actual，未定。正式 FFI 不存在。
- **輸出 schema**：`ok/code/location`、`error/where`、`result` tagged union、`ok/code/pointer` 四種；預期錯誤 JSON 全走 stdout 還是 success stdout／failure stderr；exit `2` 只代表 CLI usage，還是代表所有 caller 可修正的 rejection。
- **錯誤優先序**：world first 是否成為公開契約；第二筆同時多錯時 canonical parser 是否公開凍結欄位優先序。
- **同名競爭**：多輪競爭、非 Linux、NFS、orphan temp cleanup、cleanup 本身失敗回哪個錯、no-replace collision 該隨機名重試還是回 stable target conflict。
- **回覆遺失**：沒有安全重叫方案；若日後公開 key，要付哪組持久狀態成本（durable ledger、stable intent、consumer acknowledgment、retention、GC）。
- **durability**：file fsync、directory fsync、power loss 都沒測。
- **空 batch**：`read_all()` 接受為 `count=0`，公開 Deliver 應成功、拒絕還是 no-op 未定；ready bytes 是 caller 原始 bytes 還是何時 canonicalize 未定。
- **`delivery`／receipt**：沒有 query surface 時要不要保留；人類診斷放 optional message、stderr prose、另做 renderer，還是另設 machine/human mode。
