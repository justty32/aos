## 第 2 輪紀錄

### 1. 各人做了什麼

四位都照第 1 輪評委意見修正、沒有整條重作；都未改 C++、未 build。各路現在的立場：

- **Hickey persona**：`(d') WORLD (-f FILE | -)`；Linux `renameat2(RENAME_NOREPLACE)` 跑同名雙 producer；rename 後、stdout 前 SIGKILL；從 `libaos_inst.so` 直接叫 canonical `aos::read_all()`（ABI-local `ctypes` 只當證據 shim，不是產品方案）；輸出 `5/5`、exit `0/1/2`。
- **Cantrill persona**：`(d')`；外層 `published/rejected/failed` tagged union，預期結果全走 stdout JSON、stderr 只留給程式崩壞，exit 是 outer tag 的粗投影；實跑複合錯誤與只讀 `result` 的負向對照 caller。沒接 canonical parser。
- **Evans persona**：`(d')`；兩筆 batch 恰成一個 ready 並被真 `aos exec` 執行；真 `EACCES`；TTY 與關閉 fd 0 下 bare invocation 都立即 exit 2；移除 `message` 後 machine decision 不變。仍用 toy validator、普通 rename。
- **Pike persona**：key 答 `1/4`、位置用 `location:{kind,value}`、exit `0/1/2`；**保留 `(b) FOLDER [FILE]`、不採 `(d')`**，理由是來源規則（相對 FILE 取 caller cwd）已能消除歧義，多一個旗標不增加明確性。
