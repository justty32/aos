#### 那些轉交提案（只裁需要裁的）

| 提案 | 裁決 | 依據 |
|---|---|---|
| **第 11 條：去量那個數字** | **真的推翻了那個數字，更重要的是推翻了它的型別** | 見〈那個成本數字〉 |
| **第 5 條：`.runi` 鎖的是那一批還是那個世界** | **二分法本身錯了** | 見〈`.runi` 鎖的是「那一批」還是「那個世界」〉 |
| **第 1 條：`aos world recover` 進規格第六節** | **真的推翻了它的字面版** | 照「把 `.runi` 搬回 `inst.json`」寫，投遞被 aggregate 刪掉、磁碟上再也沒有它；aggregate 守衛只有 `lstat(paths.base)`、不看 `.runi`，且排在 claim 之前。**最該立刻處理，跟 argv 化無關** |
| **第 2 條：`.runi` 升級成租約、receipt 旁邊放** | **證實可行**（三個獨立實作）；p4 的「exit 欄位就夠」被他自己的資料削弱 | 孤兒把批次跑完時 exit 檔都是 2/2，exit 欄位分不出來 |
| **第 4 條：`--loop` 停止條件改成回合開頭 `stat` 一次 `.runi`** | **真的推翻了字面版**，修法是補一個檔名 | p4 `EXIT=10` |
| **第 9 條：「都算 core」＝同一支執行檔** | **證實了成本代價，但那是部署事實不是架構事實** | 貴在跟交接無關的 32 MB `libaos_llms`，是連結決定、拆得掉。不該拿來反對提案 9 的原則 |
| **第 15 條：argv 只是函式語意的投影** | **證據不足**（原則）＋**證實了捷徑不存在** | 要投影就得有人在 C++ 裡寫薄殼，FFI 那條路是關的 |
| **第 12 條：這套協定的讀者是誰** | **仍然無解**，主張三的「值不值得」直接卡在這題上 | 這是使用者的決定，量不出來 |

#### 研討會沒說、這輪才撞出來的（裁決）

| 發現 | 裁決 |
|---|---|
| 規格第六節「不會有兩支 `aos exec` 同時跑同一個資料夾」是假的 | **真的推翻了**（兩條獨立路徑，原始碼確認機制） |
| `aggregate` 不看 `.runi`，退出碼 3 那條路徑上世界仍被改動 | **真的推翻了** |
| 退出碼 3 一碼兩義 | **真的推翻了**。成立的是 `R` ⟺ 有一回合沒跑完 **或** 有一回合正在跑——少掉的析取項正是 `--loop` 用來決定停不停的那一項 |
| 彙整暫存檔名固定 `inst.json.temp`，同一節替投遞規定要帶 pid | **證實了規格內部矛盾**（`paths.temp = base + ".temp"`），實際傷害沒人做出來 |
| 使用者原話的字面版在邏輯上不可能（要跑「取件」這一筆，得先取件） | **證實了**，這解釋了形狀 (a)/(b) 必須分開 |
| 這個題目在今天的二進位上不可實驗 | **證實了**。**本輪對路線最有價值的一條** |
