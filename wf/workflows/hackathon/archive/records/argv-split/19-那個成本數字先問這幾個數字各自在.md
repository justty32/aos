### 那個成本數字：先問這幾個數字各自在測什麼

| 數字 | 它實際在測什麼 |
|---|---|
| **fork 27–36 µs** | primitive 的成本；外放一定要 execve，所以跟外放幾乎無關 |
| **動態執行檔 128–151 µs** | fork＋execve＋`ld.so` 載入小型動態執行檔＋waitpid，大頭在動態連結 |
| **`aos` 769–789 µs** | callee 映射 42 MB／7 顆 `.so`、4793 次 relocation，其中 32 MB 是跟交接無關的 `libaos_llms`——**一個連結決定，不是機制的成本** |
| **python 5.49–5.72 ms** | CPython 啟動時間——**語言選擇** |

**「一次 fork＋execve 約 1–3ms」錯在型別，不在數值**：它是「你決定去叫哪一支程式」的參數，跨度 68 倍，被當成機制常數用；對精瘦 binary 高估 8–23 倍，對 python 低估 2 倍。它大致是「胖的動態執行檔或輕量直譯腳本」的量級（`aos <verb>` 0.79 ms），特例被寫成了通則。

**分母採用 6–9 µs**（p1 兩法 6.4／8.6、p3 7.9）；p4 的 2.2 µs（複本，與自己的 8.5 µs 差四倍）與 p2 的 27.2 µs（含行程進入成本）不採用。

帶去改規格與 roadmap 的陳述：

> 一次外放的成本不是一個常數，是 **130 µs（精瘦 binary）／440 µs（`/bin/sh`）／790 µs（今天這支 `aos`）／5.5 ms（python）**。今天一個空回合是 **6–9 µs**。所以倍率是 **15×–600×**，取決於你叫誰。
> **而這個倍率有沒有關係，由 `--loop` 的週期決定**（p4）：`--loop 1`（下限，`--loop 0` 會被夾成 1）時 800 µs 讓週期從 1.0 ms 變 1.8 ms 並吃掉近半顆核心；`--loop 100` 時同一個 800 µs 是 0.8%，是雜訊。
> **而且倍率可以歸零**：閒置回合零 fork 三位獨立做到了（p2 `/proc/stat` 交錯基準線、p3 兩把儀器、p1 的 1.11 µs），代價是觸發判準必須留在裡面。

**結論：〈壞 5〉不該再被當成反對外放的理由。** 它真正說的是「不要每回合無條件 fork」和「不要用 python 寫機制」，兩件都是實作紀律，不是架構障礙。

### `.runi` 鎖的是「那一批」還是「那個世界」

這個問題欠定，要拆成三件事：

- **範圍（scope）**：這把鎖保護哪一個資源？
- **身分（identity）**：鎖上寫著哪一批佔用了它？
- **壽命（lifetime）**：它從什麼時候活到什麼時候、誰讓它結束？

四個答案不一樣，是因為各自答了不同的一件（p1／p3 答範圍，p2 指出缺身分，p4 答壽命）。

#### 有幾種可能的讀法

| 讀法 | 不變式 | 鎖名要帶什麼 | 拆得開嗎 |
|---|---|---|---|
| **L-batch（那一批）** | 對每一批 `b`，全世界最多一個執行者在跑 `b` | **批次身分** | 拆得開，多批可並行 |
| **L-slot（那個檔位）** | 對每個 instruction 檔位 `s`，最多一批在跑，且下一批不得在前一批結束前開始 | 檔位路徑 | 半拆得開 |
| **L-world（那個世界）** | `R` 成立時，`.aos` 的狀態不得被任何人改變 | 世界路徑 | 拆不開 |

#### 現在的實作實際上是哪一種

**是 L-slot，而且它連 L-slot 都沒守住。**

1. `derive_paths()` 只從 instruction 檔路徑推出鎖名（`paths.runi = base + ".runi"`），不帶批次身分 → **L-batch 不成立**。
2. `aggregate_instructions()` 的守衛只有 `lstat(paths.base)`、不看 `.runi`，且 `run_exec_once()` 把 aggregate 排在 claim 之前 → `R` 成立時世界照樣被改 → **L-world 不成立**。
3. A1 之後同一檔位 `B ∧ R` 同時成立——**規格沒有定義這個狀態。**

#### 規格散文寫的是哪一種

**規格第六節同時寫了兩種，自相矛盾。**「**`.runi` 已存在時拒絕啟動**……也不會有兩支 `aos exec` 同時跑同一個資料夾」是 L-world 的語言；「**每顆 CPU 各鎖各的**：`inst.json.runi` 只鎖核心 CPU，`insts/llm.json.runi` 只鎖 LLM 那顆」是 L-slot 的語言。所以「鎖的是那一批」（p1）不對：那句區分的是檔位不是批次；若真是 L-batch，recover 就能確認搬回去的是當初那一批，而實際上不能。

**給使用者的一句話：** 第 5 條要在規格裡定的不是「那一批 vs 那個世界」，是三件事各自寫一行——

> **範圍 = 檔位**（今天就是，寫下來即可）。**身分 = 目前沒有**（要補，內容雜湊就夠，否則 recover 只能賭）。**壽命 = 目前只綁在一個檔名上**（要不要升級成核心持有的租約，是提案 2 真正在問的問題）。
> 並且**刪掉或修正**「不會有兩支 `aos exec` 同時跑同一個資料夾」這句——它今天是假的。
