### 六、哪個坑是致命的、哪個只是麻煩

**致命的只有一個：孤兒＋`.runi` 的組合。** 它是唯一從世界內部繞不過去的：冪等守衛輸給 race、產出被靜默刪除、付了兩次錢、或沒有任何安全動作可做，四種架構都沒解決。它需要 `aos exec` 在 fork 前寫東西，也就是 C++。所以 `aos agent` 存在的理由不是讓 loop 好寫（一百行 shell 就夠），而是讓 loop 壞掉之後有救。

**只是麻煩、繞得過的（不拿去排 roadmap）**

| 坑 | 怎麼繞 |
|---|---|
| `--loop` 不會停 | driver 把 PID 寫進世界，世界裡的 `tools/stop` 送 SIGINT |
| 批次不短路 | `bin/gate` 不改 C++ 就做得到（待下一輪數字） |
| tool registry 不存在 | 具名 registry，順便讓模型自我修正 |
| claude 包 markdown 圍籬 | `sed` 剝殼 |
| codex 的 MCP stderr 噪音 | 不看 stderr，看 `-o` 檔在不在或退出碼 |
| codex 旗標順序／`resume` 要 `--skip-git-repo-check` | 寫進文件 |
| `jq` 預設吃串流 | `jq -e -s 'length==1'` |
| 手打 stage 路徑 | 一支十幾行的產生器 |
| `deliver` 的 counter | 12–13 行 |
| 中間檔只留最後一回合 | 自己 `cp` 快照 |

**中間地帶：`parallel: true`。** 現在不痛是因為任務都一次一個工具，而真模型常一次要兩個。tool_call_id 的形狀是協定不是實作，**現在就要決定**。

### 七、哪份回報不可信

沒有一份整體不可信。兩個斷言沒有任何輸出，**在重測前不能進規格**：

1. **「pi 只能塞 argv、不吃 stdin」**——兩份成功現場對一句無現場的斷言，而且已被拿來當 golden slice 選 codex 的第一條理由。優先處理。
2. **「`~/.codex/sessions/` 是空的、session 存在 sqlite」**——另外兩位各自貼了實際存在的 rollout 檔。

原則：可以寫「沒問到」「不知道」，不能寫一個沒看過的機制。

### 八、如果現在就得拍板：`aos agent` 第一版的三件事

**1. 崩潰之後的可判定性（先做這一件）。** 兩半都要：

- `aos exec` 在 fork 之前落盤 running marker，內容至少是「批次裡第幾筆」＋「子行程 pid」，回合正常結束時清掉。
- 一支唯讀的 `recover`：攤開 `.runi` 裡有哪幾筆、每筆的 `stdout`／`exit` 現況、marker 的 pid 還活不活（`kill -0`），並先告訴人 inbox 已被搬走。重播必須是明確要求的動作，不是預設；孤兒還活著就拒絕動作。

先做它，因為它有金額、四位都繞不過、晚做的成本是已花掉的錢。順帶補規格漏洞：**退出 3 之前不要彙整**，或至少在規格寫明它會。

**2. `aos agent step`——回合模板＋投遞＋投遞前驗證，一支。** 「下一批要跑什麼」只寫一次、temp+rename 投遞（含 counter）、rename 前驗一次並把錯誤字串回給呼叫者，讓型別錯誤變成模型下一回合自己改對。

**3. `aos status --json`。** 讓做完了／沒事做／壞掉了／正在想從外面分得出來，並給 `--loop` 一個終止條件。

**不做**：不為 LLM 往 instruction 加欄位。唯一值得考慮的新欄位是 `"needs"`（它跟 LLM 無關，是管線的最小表達），等 `bin/gate` 的輸出再決定。
