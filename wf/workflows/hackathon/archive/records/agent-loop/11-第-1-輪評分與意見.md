### p1（John Carmack persona）

**評語**：效能結論定案（aos 開銷 0.4 秒／22 秒），以後可擋掉「exec 太慢」的提案；`$1`／`$2` 佔位符撞名是全場最精準的工程觀察。扣分：建議 golden slice 鎖 pi，而 pi 是他唯一沒接進 loop 的那支。

**下一輪要做的。**
1. 把 pi 接進 loop 跑同一個任務，量每回合秒數、token、總美金，與 codex 並排，再確認或收回「鎖 pi」；順便在自己場地重測 pi 吃不吃 stdin。
2. 把「兩個 thread_id、31,316 token」的案例做成 `recover.sh` 的測試資料：讀 `.runi` 的批次、比對每一筆的 `stdout` 與 `exit`、印出「第 N 筆疑似已完成且已付費」。驗收：recover 之後模型呼叫從 4 次降回 3 次。
3. 不要再花時間在 `--loop` 的優雅收尾上。

### p2（Rob Pike persona）

**評語**：「`exit` 欄位就是 program counter」是不需要新機制的提案；`$ref` 三組現場是全場唯一的實測。撞到 `.runi` 後判定「沒有安全動作」是對的。扣分：閉環只轉了一次工具，任務規模較小。

**`aos exec --resume`（跳過 exit 檔存在且為 0 的那幾筆）救不了錢**：崩潰時缺的正是最貴那一站的 exit 檔（`mdl.exit=MISSING`），`--resume` 會重跑它。值得做，但不能當省錢方案。

**下一輪要做的。**
1. 做出 `bin/gate run/mdl.exit`，證明 `"needs"` 夠用。驗收：`mdl` 換成必定失敗那支，七站的 exit 表要看到 `last`／`note`／`act` 跳過、transcript 沒被空的「模型: 」汙染、inbox 空。
2. 補 `--resume` 的洞：`mdl` 前原子地建 `run/mdl.lease.<pid>`，跑完刪；重跑 SIGKILL 實驗，證明復原判斷變成「租約在不在＋持有者活不活（`kill -0`）」。
3. 試 `aos llms` 能不能直接當 `bin/mdl`。
