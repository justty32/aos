### 3. 好處

- **模型呼叫就是一支 CLI，換模型是換一個 symlink。** 假模型與真模型走同一份批次，閉環其他部分一行不動、回合數一樣。四位都驗到。
- **行數很少。** 一條 agent loop 是一份 `inst.json` 加約一百行腳本（p2 105 行、p4 144 行，每支不超過 21 行）。
- **`aos` 這一層的開銷在真模型下是雜訊。** 5 回合假模型共 152 ms；真模型（codex）共 22,067 ms，其中模型佔 97.9%，彙整＋取件＋fork＋wait＋膠水加輪詢間隔約 0.4 秒。不要為了效能動 `aos exec`。
- **現有 instruction 欄位剛好夠包一支 agent CLI。** prompt 從 `stdin` 進、最後一則從 `stdout` 出、`stderr`／`exit` 收尾、`timeout_ms: 300000` 當保險。三家 CLI 都不需要 schema 以外的欄位。
- **「一回合＝一整批」配上陣列，順序是免費的。** 工具回合 `[工具, tool-done.sh]` 放同一份投遞就保證順序；拆兩份投遞則不保證（aggregate 不保證順序）。
- **`argv` 是陣列直進 `execve`，沒有 shell，沒有引號問題**，帶空白的參數邊界完整保留。
- **codex 的 `--output-schema` 讓解析模型輸出縮成一行 `jq -r '.action'`。** 但它是 codex 專屬旗標，見[評委但書](14-三哪條路最值得繼續走.md)。
- **回合邊界是硬的，好 debug。** 沒有常駐行程，任兩回合之間能改 prompt、改 `tools.json`、手塞 transcript，下一回合就吃到；每回合的輸入輸出都是磁碟上的檔。
- **世界可以整包搬走。** `bin/`、`tools/`、`steps/` 都放進世界、路徑相對於 `<folder>`，`cp -r` 就是複製一個 agent。
- **「停止＝不投遞」不需要 halt 旗標或狀態機**（缺點是跟「壞掉」長一樣）。
- **`stderr: {"$opt":"merge"}` 好用**，debug 少開一個檔。
- **壞投遞隔離成 `.bad` 不擋其他人**，多生產者下是對的。彙整收任何沒有狀況後綴的檔名（`185452-0.json` 也收）。投遞前先用 `jq -e .` 驗一次，整場不會出現 `.bad`。
- **具名 registry 把錯誤餵回模型，模型會自我修正**（`REJECT unknown tool: nuke_everything` → 下一回合改口），是整個 loop 唯一的自癒機制。
- **codex 的 JSONL 逐事件 flush**，崩潰當下 `events.jsonl` 已有內容，`thread_id` 在第一行、早於答案。只實測過一次，不當成通例。
