**工具結果拆成 `.out`／`.err`／`.exit` 三個自己命名的檔，沒有 correlation id。** 只能用固定檔名關聯，同時只能有一個工具在飛；`parallel: true` 一開就會壞（推理，沒實測）。

**tool registry 不存在，自己寫很容易寫錯。** 只寫 `[ -x "tools/$tool" ]`，模型一句 `TOOL ../../../../../../../../usr/bin/id -un` 就能跑世界外面的執行檔。具名 registry（name → argv 的表）能擋下未知工具，並把錯誤寫成一則 `[tool]` 餵回模型，模型下一回合會改口。

**「做完了」和「壞掉了」從外面分不出來。** 模型講錯工具名與模型宣布完成，結果都是 inbox 空、`aos exec` 回 0、世界靜止。`exit=0` 同時代表回合跑完、沒工作可做、模型正常結束、模型參數型別錯誤導致投遞被丟掉。

**冪等守衛會跟孤兒賽跑。** 守衛 `test -f final.json` 檢查時孤兒還沒寫出結果，重播就又付一次錢；窗口等於一次模型呼叫的長度（好幾秒），結果由時機決定。

**冪等不能靠每個工具作者自己記得寫。** 只有模型那支有守衛、工具那支沒有時，在工具回合崩潰後重播會重跑 `write_file`。

**`jq -e .` 擋不住多份 JSON。** `jq` 預設吃 JSON 串流，30 個頂層物件不抱怨、`.kind` 每個都回 `null`。要求「剛好一份 JSON 文件」要寫 `jq -e -s 'length==1'`。pi 會吐 30 幾行 JSONL，要自己挑出最後一則。

**claude 即使被 system prompt 禁止，也會把輸出包在 ```` ```json ```` 圍籬裡。** 得自己用 `sed -e 's/^```json$//' -e 's/^```$//'` 剝，很脆。

**環境坑（跟 aos 無關）：**

- `ls` 是 `eza --icons --git` 的別名，在 repo 複製品裡會對整個 repo 跑 git status 而掛死；改用 `find -printf`。
- 機器上沒有 `/usr/bin/time`（exit 127）。
- 背景 job 繼承忽略 SIGINT，`kill -INT` 打不中；改用前景 `timeout --preserve-status -s INT`。

**codex 的旗標順序：`resume` 是 subcommand，global option 都要放在 `resume` 前面**，否則 `error: unexpected argument '-s' found`（exit 2）。`codex exec resume` 也要加 `--skip-git-repo-check`，否則 `Not inside a trusted directory`。

**codex session 落在 `~/.codex/sessions/<年>/<月>/<日>/rollout-*.jsonl`**（p1、p2 都貼了實際檔案）。「`~/.codex/sessions/` 是空的、session 存在 sqlite」這說法沒有證據，評委判為不可用。
