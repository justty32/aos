**投遞要自己寫 temp+rename 與防碰撞檔名。** 只用 PID 當檔名，同一個行程投第二次會互蓋，所以檔名要寫成 `$$-<counter>`：

```sh
d=".aos/inst.tempd"; n=0
while :; do base="$$-$n"; [ -e "$d/$base.json" ] || [ -e "$d/$base.json.temp" ] || break; n=$((n+1)); done
```

四位都重寫了一次（12–13 行）；躲得掉 counter 這個坑是因為讀過上一份實測。

**codex、claude、pi 不是模型端點，是 agent。** codex 每次呼叫固定吃 15.4k–15.8k input token（它自己的 system prompt）；claude 一次 15 token 的回覆 `total_cost_usd: 0.0886`；`pi --no-tools` 只吃 2,151 token、$0.011。codex 會偷跑（自己跳過一步工具）。**模型的 cwd 要指到空資料夾**，否則 codex 會用自己的 shell 直接讀工作區，整條 tool loop 變成裝飾品；不靠這招就只能靠 prompt 求它別當 agent。

**codex 每次呼叫都往 stderr 噴一段 `ERROR rmcp::transport::worker: ... AuthRequired ... api.githubcopilot.com ...`，無害**（codex 自己配置的 GitHub Copilot MCP server 沒 token）。不能用「stderr 有沒有東西」判斷模型呼叫成敗。

**`--loop` 沒有停止條件，答案出來後一直空轉。** sentinel 檔（`DONE`、`state/DONE`）`aos` 不認得。能讓它停的辦法：driver 先把自己的 PID 寫進世界（`run/driver.pid`），世界裡的 `tools/stop` 對它送 SIGINT，空轉歸零。不要用 `pkill -INT -f 'aos exec --loop'`，會連跑腳本的 shell 一起殺掉（它的命令列也含那串字）。終止條件現在只能放在世界外面的行程裡。

**`$ref` 幫不上 agent loop。** 它是參數替換，不是 include，取回的值只能是字串：

- 整筆 `{"$ref": ...}` 放進 batch → `UnknownKey`，被跳過。
- `"argv": {"$ref": ...}` 指到陣列 → `FieldTypeMismatch`，隔離成 `.bad`。
- argv 元素逐一 `$ref` 到字串 → 成功。

展開成多個 argv 元素是規格刻意否決的語意，而 agent loop 要的正是它。

**批次不短路：前一筆失敗，後面照跑，`aos exec` 回 0。** 把模型站換成必定失敗的程式，七站裡五站照跑，transcript 被附上一則空的「模型: 」回合，下一回合模型會看到不存在的空回合。p2 的提案是 instruction 加 `"needs": "run/mdl.exit"`：那個 exit 檔不存在或非 0 就跳過這一筆（不改退出碼語意）。
