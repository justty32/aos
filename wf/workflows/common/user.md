# user — 使用者偏好與確認邊界

← [common/README](README.md)

agent 不用重猜的事。always-on 鐵律在 [AGENTS.md](../../../AGENTS.md)，這裡是**這位使用者**的偏好——改了改這裡，不改鐵律。

| 項目 | 設定 |
|------|------|
| 語言 | 回覆與 `wf/`／`docs/` 一律繁體中文；程式碼沿用各檔既有語言；**程式的輸出（訊息、usage、寫進檔的文字、log）一律英文**（11-05「全都用英文吧」，細節 [conventions](conventions.md)） |
| 分支慣例 | **本地與遠端都只有一個 `main` 分支**（使用者 2026-11-03 晚：「我希望不管是遠端或本地，都只有一個main分支。寫進記憶吧」）：直接 commit `main`，不開分支、不開 worktree 分支、不 push 別的分支；做到一半要跨機器帶走的，收工前收斂成能進 main 的狀態，或只留在本機工作樹。push 見下方「push 授權」 |
| 直接做、不用問 | 改 `wf/` 文件、跑唯讀指令、build、開子 agent 隊、做原型讓他試 |
| commit 怎麼交 | **走 `wf/tools/commit-request`**（鐵律 3；11-14 專區「q1:fix」）：`claim`／`submit --line … --files … --msg-file …`，生成器由排隊跑，各線不自己跑 `index_gen`、不 `git add`（用法見 [aos-teams/07](../dispatch/aos-teams/07-預設流程與agent-fsm.md)）；沒有 commit-request 的機器才自己在 commit 前跑 `python3 wf/tools/index_gen.py --apply`。`wf/tools/index_check.py`、`wf/tools/check_anchors.py` **不是必跑**，工具留著，大量搬檔後想查再跑（使用者 2026-11-13 晚被問「commit 前的查錯檢查改成想跑才跑？」答「1.對。」） |
| 一定先問 | push、刪檔、開新工作（鐵律 2）；**方向性裁決**（鐵律 5）——我擺選項與後果，他拍板 |
| 回覆風格 | 先結論、短、**大白話**（見下方）；問「要不要」時附**可執行判準**（門檻數字）與後果。他說「不想看」時用實測取代拍板；**問他的題目寄進使用者專區（`aos-user send --kind decide`），會出現在全景頁上**（11-14 午：「問我的問題你直接放全景網頁，我現在大多在看那邊」），不只寫在終端。**稱呼不用比喻**：kernel、daemon 直接叫 kernel／daemon，不說「手」「門」；翻 handle 的「把手」改說「遙控器」（他後來說「操控器...還是用遙控器吧」）（11-20「拜託，手、門只是比喻，幫我乖乖用kernel/daemon稱呼好ㄇ」，對照表在 [user/01](user/01-說話授權與記憶.md#說話方式)） |
| 沒回答的邊緣狀況 | 視為天然差異或實作時自然可解，不追問、不列待辦（見表下）|
| 時區 | Asia/Taipei（推的；不對就改這格）|
| 工作模式 | 我當調度者、不親做內容；先講打算怎麼做再派；隊形見 [dispatch/aos-teams](../dispatch/aos-teams.md) |
| 定期 compact | 做到一個段落（一批交完、一次換樹完、收工）就提醒使用者打 `/compact`，不要等 context 滿了被自動壓（11-15 早：「感覺要定期，做到一個段落就來compact。」）；提醒前先把還開著的事寫進 `wf/progress.json` 或交接 |
| artifact／說明頁風格 | 使用者 2026-11-05：「拜託這幾個artifact都遵循"圖多、只講結論、細節摺疊、白話"」——每節先一張圖（inline SVG 或 mermaid），圖下一兩句白話結論＋最常用一行指令，完整用法、表格、錯誤代號、範例一律收進 `<details>`；不寫大段文字。**手機遠端頁（11-08）**：ELI5、圖少（必要時一張小圖）、只講結論、過程除非很重要不附、細節摺疊——原話「我人在外面耍，沒辦法把全部精力用在思考這塊。所以可以的話，細節折疊，然後盡量ELI5風格講述。圖不用多，因爲artifact承載力有限。盡量只講結論就好，中間過程除非很重要否則不用附。」 |
| 凍結中的線 | **arknights 凍結到至少 2026-12-14**（使用者 11-14 早：「arknights先不動，我要凍結到至少一個月後。」）：不開線、不拿它當試驗場、不碰 `~/code/playground-ak5`；到期也要使用者說了才解凍 |
| 舊版遷移 | 使用者 2026-11-05：「其實不用管舊版本遷移這件事，我們在proto8內，就是一律當成沒有舊版。畢竟是prototype-8」——proto8 改格式／改名／改結構時**不寫遷移、不做舊格式相容、不留舊名提示**；舊資料壞了就重建 |
| `wf/user`（使用者專屬區） | 使用者 11-22：「wf/user是我的地盤，裡面的東西無法保證穩定性。user advice可以搬進去。剩下都按照推薦」。**人的地盤**：agent 只讀、叫了才寫（「叫了」照鐵律 2 的授權鍊算），代寫標「（agent 代寫，使用者 MM-DD 口述）」。**裡面的檔不穩定**：使用者隨時會改名、改內容、刪掉，所以規矩、知識庫、程式碼都不寫死連到 wf/user 裡的某個檔（要指只指到夾）；引用他在那裡寫的話就抄原文，註明日期與當時的檔名。**正本**：一次性的交代只留在 wf/user；長期的規矩抄進本檔（或分檔），正本在這裡；判斷不了的當長期。**誰交**：他自己改的檔，eca-aos 收工或換台前 `git status --short -- wf/user` 有改動才用選項框問一次要不要交。開場與壓縮後怎麼掃、私人那格 `wf/user/private/`、舊的 `user-advice` 搬去哪，都寫在那個夾的 README。**沒有使用者專區（`~/.aos/user/`）的機器，要問他的題目放 `wf/user`**（使用者 11-23 在公司 WSL，eca-aos 報「這台沒有 `~/.aos/user/`」之後：「沒有~/.aos/user，那就放wf/user。」）；這算他叫 agent 寫，照代寫的標法標，有專區的機器照舊寄專區 |
| 子 agent 模型 | 使用者 2026-10-20：「事情都盡量交給agent，普通工作交給opus，簡單工作交給sonnet，需要高難度思考&規劃的交給fable(盡量少用)。你就負責和我交流。派agent時要讓他們通讀wf/規矩，除了幹雜活的」——普通工作派 opus、簡單工作與雜活派 sonnet、高難度思考與規劃才派 fable；頂層只負責跟使用者交流；派出去的 agent（雜活除外）提示裡要它先讀[規矩卡](rules-card.md)（使用者 11-17 待裁網頁 wf-6 選 a：「通讀 wf/ 規矩」改成讀這張 8 KB 內的濃縮卡，原文為準；碰程式再讀 conventions、當線隊長再讀 aos-teams）。派出去的 agent 也要先**大致掌握 aos 體系**：提示裡要它先讀知識庫 `$AOS_HOME/knowledge/aos/_description.md`，例外跟讀 wf/ 規矩同一套（使用者 11-13 晚「agent做事前也要大致掌握aos體系」「照預設走」；規劃的流程見 [aos-teams](../dispatch/aos-teams.md)）。**改寫使用者的概念／規範條文不算簡單工作**，不派 sonnet（使用者 2026-10-19：「竟然是開sonnet做事...不怕錯嗎」）。**現在的隊形**（使用者 11-14 專區「q2:update」）：蒐集和施工用 sol（agent-fsm），不走 codex、不用 terra；Claude 子 agent 補位（普通 opus、簡單 sonnet）；流程見 [aos-teams](../dispatch/aos-teams.md)。 |

> **他沒回答的邊緣狀況怎麼處理**（2026-09-01 他自己說的通則）：我挖出來的邊緣狀況他沒回應，
> 就代表**要麼只是比喻上的天然差異**（拿現成概念比喻 aos 時，比喻本來就不會處處貼合），
> **要麼實作的時候自然能解決**。兩種都不必再追問、也不列進待辦——留在原本記它的地方，
> 供實作時想得起來就好。
