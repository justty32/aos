# user — 使用者偏好與確認邊界

← [common/README](README.md)

agent 不用重猜的事。always-on 鐵律在 [AGENTS.md](../../../AGENTS.md)，這裡是**這位使用者**的偏好——改了改這裡，不改鐵律。

| 項目 | 設定 |
|------|------|
| 語言 | 回覆與 `wf/`／`docs/` 一律繁體中文；程式碼沿用各檔既有語言 |
| 分支慣例 | 直接 commit `main`；push 見下方「push 授權」。分支只用於凍結或實驗 |
| 直接做、不用問 | 改 `wf/` 文件、加測試、跑唯讀指令、build／ctest、開子 agent 隊、做原型讓他試 |
| 一定先問 | push、刪檔、開新工作（鐵律 2）；**方向性裁決**（鐵律 5）——我擺選項與後果，他拍板 |
| 回覆風格 | 先結論、短、**大白話**（見下方）；問「要不要」時附**可執行判準**（門檻數字）與後果。他說「不想看」時用實測取代拍板 |
| 沒回答的邊緣狀況 | 視為天然差異或實作時自然可解，不追問、不列待辦（見表下）|
| 時區 | Asia/Taipei（推的；不對就改這格）|
| 工作模式 | 我當調度者、不親做內容；先講打算怎麼做再派；隊形見 [dispatch/aos-teams](../dispatch/aos-teams.md) |
| 子 agent 模型 | 需要思考的（設計、提案、盤點、評估、拍板前的分析）派 **fable**；照決定實作、跑測試、查資料等用預設。原文（2026-10-15 夜）：「對了，需要思考的就交給fable」。**改寫使用者的概念／規範條文也算思考**（2026-10-19：proto8-2 併入時派 sonnet 改 CONCEPTS／NORMS，使用者「竟然是開sonnet做事...不怕錯嗎」；事後 fable 審出 9 處原話被刪改、2 條決定被丟）——搬檔、改程式可派預設，動條文派 fable，或派完一定再派 fable 審。2026-10-19 /goal 再收緊：「需要思考的事情交給fable，sonnet只能拿來做雜事或簡單工作，要做事的agent(除了sonnet)都要先讀過wf/規矩」——派非 sonnet 的做事 agent 時，提示裡要它先讀 AGENTS.md 與本檔。2026-10-19 晚 /goal 改成「事情盡量交給agent做，簡單工作和雜活交給sonnet。你就負責和我交流。可以隨意push」，並說「fable太貴了...」——**之後不再預設派 fable**：需要思考的（設計、改條文、審）改派預設模型（不指定 model，跟頂層同級），fable 只在使用者指名時用；sonnet 照舊只做雜事與簡單工作；做事的 agent（sonnet 除外）仍要先讀 AGENTS.md 與本檔。 2026-10-20 使用者再改：「事情都盡量交給agent，普通工作交給opus，簡單工作交給sonnet，需要高難度思考&規劃的交給fable(盡量少用)。你就負責和我交流。派agent時要讓他們通讀wf/規矩，除了幹雜活的」——**現行分工以此為準**：普通工作派 opus、簡單工作與雜活派 sonnet、高難度思考與規劃才派 fable（盡量少用）；頂層只負責跟使用者交流；派出去的 agent（幹雜活的除外）提示裡要它先通讀 wf/ 規矩（AGENTS.md、WORKFLOWS.md、common/user.md、common/conventions.md 等）。 |

> **他沒回答的邊緣狀況怎麼處理**（2026-09-01 他自己說的通則）：我挖出來的邊緣狀況他沒回應，
> 就代表**要麼只是比喻上的天然差異**（拿現成概念比喻 aos 時，比喻本來就不會處處貼合），
> **要麼實作的時候自然能解決**。兩種都不必再追問、也不列進待辦——留在原本記它的地方，
> 供實作時想得起來就好。
