### `proto8/extras/langs/janet`（Janet 寫 aos、編成資料夾）

`aos-janet`：跑一份 Janet 原始檔、拿它的 `program`，寫成資料夾＋JSON＋短腳本（跟手寫的一樣，照舊 `aos-exec` 跑）。說明在 [janet/README](../../../../../proto8/extras/langs/janet/README.md)；設計 [thinking 2026-10-24-janet-compile](../../../../../proto8/thinking/2026-10-24-janet-compile.md)。

| 哪裡 | 負責什麼 |
|---|---|
| `bin/aos-janet` | 命令列 `aos-janet [--force] 原始檔.janet 輸出資料夾`：子環境裡跑原始檔、拿 `program`、交給 emit；錯一行 `aos-janet: 代號 原因` |
| `aos.janet` | 寫法：JSON 的值（`obj`、`inst`、`env`、`ref`、`aos-loop`、`aos-fsm`…）與檔案節點（`dir`、`text`、`script`、`sh`、`copy`、`dotenv`、`tool`、`janet-main`） |
| `combine.janet` | `aos-seq`、`aos-par`、`aos-if`：各編成一個資料夾，入口是短 shell 腳本、每步一個小格 |
| `emit.janet` | 寫到磁碟；JSON 值裡碰到檔案節點就長成同層子資料夾、原地換成名字 |
| `json_write.janet` | Janet 的值 → 好讀的 JSON（key 固定順序、中文不跳脫、短的擠一行） |
| `code_write.janet` | Janet 程式碼 → 原始碼字串（`janet-main` 用，中文照原樣） |
| `examples/agent_dan.janet`、`count.janet`、`steps.janet` | agent-dan 的 Janet 版（編出來跟 demo/agent-dan 同形）、loop＋fsm 葉子用 Janet、seq／par／if 示範 |

測試：`proto8/tests/test_janet.py`（沒裝 janet 就 skip）。

### `proto8/extras/langs/lua`（Lua 寫 aos、編成資料夾）

`aos-lua`：一份 Lua 原始檔 `return` 一個 table，編成資料夾＋JSON；lua 5.x、luajit、`nvim -l` 都能跑、產物逐位元組一樣。說明在 [lua/README](../../../../../proto8/extras/langs/lua/README.md)；設計 [thinking 2026-10-24-lua-nvim](../../../../../proto8/thinking/2026-10-24-lua-nvim.md)。

| 哪裡 | 負責什麼 |
|---|---|
| `aos.lua` | 建構子（`dir`、`file`、`script`、`inst`、`loop`、`fsm`、`daemon`、`env`、`ref`…）＋JSON 編碼＋攤平成檔案清單 |
| `bin/aos-lua` | 命令列：`build`（寫出來）、`json`（印一個檔或 `#/指標`）、`ls`（列會寫哪些檔） |
| `examples/agent_ann.lua`、`agent_dan.lua`、`clocks.lua` | 全內嵌的 agent-ann、會用工具的 agent-dan（腦與工具程式讀 demo 那份）、daemon 顧三個時鐘 loop（`for` 產生子項） |

測試：`proto8/tests/test_lua_aos.py`（也叫下面 nvim 的 smoke）。

### `proto8/extras/editors/nvim`（nvim 外掛 aos_nvim）

在 nvim 裡跑 aos 程式、看 trace、丟題、跳到 `檔#/指標`、預覽 Lua 編出的 JSON。說明在 [editors/nvim/README](../../../../../proto8/extras/editors/nvim/README.md)；設計同 lua：[thinking 2026-10-24-lua-nvim](../../../../../proto8/thinking/2026-10-24-lua-nvim.md)。

| 哪裡 | 負責什麼 |
|---|---|
| `lua/aos_nvim/init.lua` | 指令（`:AosWs`、`:AosExec[!]`、`:AosTrace`、`:AosSay[!]`、`:AosGoto`、`:AosLuaPreview`、`:AosLuaBuild`）、面板 `aos://panel`、叫子行程（PATH 前面接 repo 的 `impls/*/bin` 等，nvim 自己的 PATH 不改） |
| `lua/aos_nvim/pointer.lua` | 在 JSON 原文裡找 `#/指標` 指到第幾行第幾欄（不 decode） |

| `tests/smoke.lua` | headless 把每個指令走一遍；`proto8/tests/test_lua_aos.py` 叫它 |

### `proto8/extras/sandbox`（把一個函數關起來跑）

`aos-sandbox`：照一份設定排好 `[s6-softlimit] [s6-setuidgid] bwrap … -- prog` 再 exec 走（不常駐，結束碼與串流原樣）。強制寫在叫的那一方的 argv。說明在 [sandbox/README](../../../../../proto8/extras/sandbox/README.md)；設計 [thinking 2026-10-24-sandbox](../../../../../proto8/thinking/2026-10-24-sandbox.md)。

| 哪裡 | 負責什麼 |
|---|---|
| `bin/aos-sandbox` | `aos-sandbox [--dry-run] [--] 設定檔 prog [args...]`（Python 純標準庫）：讀設定（白名單 `user`、`base`、`commands`、`ro`、`rw`、`net`、上限五個、`env`（環境白名單，10-24 補；沒寫＝`ENV_BASE`：PATH、語系、aos 的六個）；能不能用 kernel 不另設開關，信箱綁不綁進來、`env` 帶不帶 `AOS_KERNEL` 而已〔10-24 晚拿掉 `kernel` 開關，使用者「純靠linux」〕）；可寫 `檔#/指標`、只解 `$env`），排 chain-loading、exec；`--dry-run` 印 argv |
| `examples/self-improve.json` | 自我改進交辦工作區的 `sandbox.json`：run 格與 try_run 把被改的函數關起來：只寫得到 `$IMPROVE_RUN`（這次的暫時資料夾）、斷網、`env` 只帶 `PATH` 與語系、1 GB、60 秒 CPU（工作區沒放時 self-improve 用自己那份、不含上限） |
| `examples/bash-boxed/` | 庫的 bash 包一層：`_entry` 是 argv 陣列 `["aos-sandbox", "sandbox.json", "aos-exec", "inner"]`，`inner`、`tool.json` 是捷徑指到 `lib/base/bash`（10-24 遷移前指 demo/pi-tools/bash；參數 `timeout` 跟著改 `timeout_s`） |
| `examples/cli-tool.json`、`agent.json` | claude／codex CLI 當工具（要連網、寫自己的設定資料夾，`env` 另帶 `HOME`、`TERM`）；agent 當工具（斷網、`rw` 綁 `$AOS_KERNEL` 信箱、`env` 另帶 `AOS_KERNEL`、`AOS_BRAIN_URL`／`MODEL`；kernel 那邊要寫 `accept`，見 thinking S14、S18） |
| `root/setup.sh` | 要 root 的那半，預設乾跑：s6 四支進 `/usr/local/bin`、帳號 `aos-run`、`/srv/aos-run`、sudoers 只准換成 aos-run；`--mailbox 信箱`＝只做讓 aos-run 寫得到某個 kernel 信箱（擁有者自己、群組 aos-run、2770、四格預設 ACL；10-24 晚）；`--apply` 才做；`AOS_ME`、`AOS_RUNNER` 給測試在假 root 裡換數字 |

測試：`proto8/tests/test_sandbox.py`（沒有 bwrap 整檔跳過；s6 照 PATH 找，找不到看試驗場 `~/code/try/sandbox/s6-root/bin`，沒有就跳過那幾案）。
