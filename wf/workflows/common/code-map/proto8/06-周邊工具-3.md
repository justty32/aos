### `proto8/extras/cli_hub`（aos-hub：常駐 kernel 管所有 claude／codex 實例、代答 say／listen、close／stop，10-27 起、10-28 重寫、10-30 改走 queue）

說明在 [cli_hub/README](../../../../../proto8/extras/cli_hub/README.md)；設計 [thinking 2026-10-28-hub-adapter](../../../../../proto8/thinking/2026-10-28-hub-adapter.md)、[10-28 hub-kernel](../../../../../proto8/thinking/2026-10-28-hub-kernel.md)、[10-30 agent-lifecycle](../../../../../proto8/thinking/2026-10-30-agent-lifecycle.md)（第 6 步）、[10-27 claude-switch](../../../../../proto8/thinking/2026-10-27-claude-switch.md)。

| 哪裡 | 負責什麼 |
|---|---|
| `bin/aos-hub-kernel` | 常駐 kernel（python3）：`$AOS_HUB/kernel.sock` 一行 JSON 問答（`register`／`add`／`ls`／`open`／`close`／`stop`／`shutdown`；10-30 `pause` 改名 `close`），實例只記在記憶體；`add` 時 `aos-post init <stack>/queue`；serve 迴圈替「代答」實例收 `<資料夾>/.stack/queue/`（N-16 有順序信箱；`cur/` 有沒答完的先接、否則 `new/` 有信才 `aos-post claim`）、`aos-post check` 讀信（body 要是 `{"role": "user", "content": 字串}`，不是＝壞信：`aos-post finish` 丟掉、trace 記 `letter_warning`）、body 接進 `.stack/history.jsonl`（`append_history`：最後一行已是同一則不接兩次）、叫工具的 `_entry`、回答接成一則 assistant、才 `aos-post finish`；在 stack 的 `trace.jsonl` 接一行（`question`＝信號／`error`）、放 `server.txt`；`stop` 把小格搬到 `<stack>/hub_archive/`、`cli_session.freeze_transcripts` 把 symlink 換成複製；import cli_session（`open_cell`、`close`），把它的 `die` 換成丟例外；叫 `aos-post`（要在 PATH 上，起不來＝`PostMissing`） |
| `bin/aos-hub` | 命令列（python3），全部經 kernel：`ls`、`state`、`add`、`open [-d]`（還沒納管先 add；接＝`tmux -S <格>/tty.sock attach`）、`close [--idle 分]`、`stop`、`watch`（把 `live.jsonl` 新長的行印成人看的）；`state` 多一行「對話檔」、`ls` 在指不到時多一行、`--json` 多 `transcript`／`transcript_missing`（import cli_session 的 `transcript_note`） |
| `bin/hub_ipc.py` | 兩支共用：`$AOS_HUB`（沒設＝`HubMissing`）、`ask(請求)`（連不上＝`KernelMissing`） |
| `reap.json` | 自動收起：aos-loop 的 loop.json，每分鐘跑一次 `bin/aos-hub close --idle 30` |

測試：`proto8/tests/test_hub.py`（假 claude，借 test_fay 的、多寫一份 `$CLAUDE_CONFIG_DIR/projects/…/<id>.jsonl`；10-30 起 say／listen 先用 aos-post 投信＋讀 history，aos-say／listen 改走 queue 後換回）。
