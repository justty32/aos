### `proto8/demo/`

說明在 [proto8/demo/README.md](../../../../../proto8/demo/README.md)；`run.sh` 各建暫時工作區（題目 `new/` → `cur/` → `done/`、答案 `out/`）跑一遍並印整棵 stack 樹（`.stack/`）。

- `agent-bob/`（混合範本）：`_entry`＝`exec aos-loop loop.json`、`loop.json`＝`{"exec": "fsm.json", "max": 20}`；`fsm.json` 帶 `_entry`（本身是 aos-exec 入口，10-21）、idle／act 是子資料夾、think 是那格 `body` 裡的單子〔10-24 起單子直接寫在 `exec`〕；`act/tools/cathy/` 是另一隻完整 agent（同一套範本），她的 `act/tools/stamp/` 是最底層的工具——一次跑完四層巢狀。
- `agent-ann/`（全內嵌對照）：零子資料夾，`_entry`＝`exec aos-exec loop.json`（loop.json 帶 `_entry`），`fsm.json` 三格全是 `body` 裡的單子〔10-24 起直接寫在 `exec`，loop.json 的 `exec` 也是單子〕，各指 `idle.py`／`brain.py`／`act.py`。`.env`（10-22）是 demo 唯一的 `.env` 範例，全是註解（API key 與 `PATH=${AOS_CD}/bin:${PATH}` 的寫法；PATH 那行要最外層加 `--dotenv-override` 才生效、只多一份），不設任何東西。
- `agent-dan/`、`agent-dan-q/`：**11-02 晚刪了**（使用者 11-02 晚「4.都刪掉，過時了」；10-23 真腦＋工具範本、讀舊協議 `new/*.txt`，與 10-30 搬到 queue 的版本）。最後一版看 `git show 983a2632:proto8/demo/agent-dan/<檔>`（dan-q 同理）。別份 code map 表裡的「同 agent-dan」照 `agent-eve/` 讀（eve 是它的複本，只改錯誤訊息開頭與 act 逾時）；測試 `test_dan.py`、`test_dan_q.py` 一起刪，`test_dan.py` 的假 server 與劇本小幫手搬到 `tests/fake_brain.py`。
- `agent-eve/`（10-24，agent 當工具；[thinking](../../../../../proto8/thinking/2026-10-24-agent-as-tool.md)）：主 agent 照抄 agent-dan（11-02 晚刪了；`brain.py`、`act.py` 只改錯誤訊息開頭；act 逾時 30 分鐘），唯一的工具 `tools/pyfix/`：`_tooldef.json`（task、dir）、`_entry`（python3 轉接：開小格 `$AOS_STACK/runs/NNN/`、備份 `before/`、task 寫進子 agent 的 `ws/new/task.txt`、`aos-exec --dotenv-override --ws … agent`、印 `out/task.txt`＋實際 diff）、`agent/`（子 agent pyfix-agent，也是 agent-dan 範本：自己的 `system.txt`、`.env`、`loop.json` max 60；`tools/list_files`、`read_file`、`write_file`、`edit_file`、`run_python` 只碰 `$AOS_STACK/pyfix_dir.txt` 寫的資料夾，11-01 起取代環境變數）。
- `daemon/`（10-20）：`_entry`＝`exec aos-daemon daemon.json`、子項 `exec`＝`daemon.json#/loops/<名字>/body`（10-21；10-23 深夜改名，原 `run`）〔10-24 起子項 `exec` 直接是單子〕；一個 daemon 同時管 bob、ann 兩個子 loop（工作區 `$AOS_WS/bob`、`$AOS_WS/ann`，stack 在 daemon 的小格裡）。
- `llm-kernel/`（10-24，[thinking](../../../../../proto8/thinking/2026-10-24-llm-kernel.md)）：`_entry`（shell）設 `AOS_KERNEL=$AOS_STACK/mailbox` 並先建好、`exec aos-daemon "$@" daemon.json`（後面的參數原樣給 daemon，`--max` 改收工次數，10-24 真腦實測加）；`daemon.json` 管 kernel（`aos-llm-kernel kernel.json`，`interval_ms` 300）與 a、b、c 三個子項（各跑一次 `agent-ivy/`，環境變數 `AOS_IVY_BRAIN` 選腦的單子）；`kernel.json`＝`{"mailbox": {"$env": "AOS_KERNEL"}, "slots": 1, "budget": {…}}`（budget 10-24 下午 3fbcefcc 加）；`agent-ivy/`＝ann 式 agent（`idle.py`、`brain.py`〔假腦睡 1 秒〕、`act.py`），think 格 `exec` 是 `aos-llm-send $AOS_IVY_BRAIN`、stdout 導到 `plan.txt`；`agent-ivy/brains/` 三張腦的單子（`plain.json` normal、`quick.json` normal＋`_metainfo.time_ms` 800、`urgent.json` high＋5000）。
- `daemon-2/`（10-29，[medium-plan](../../../../../proto8/thinking/2026-10-29-medium-plan.md) 實作第 8 步）：信箱模式的 daemon。`_entry`＝`exec aos-daemon "$@" daemon.json`；`daemon.json` 寫 `loops_ctl_mailbox`（11-02 晚原 `loops_mailbox`；慣用名 `daemon_ctl.json`／`daemon_state.json`）、沒寫 `max`（`run.sh` 給 `--max 25`）、`loops` 只有 `sam`；`agent-sam/_entry`（shell，agent 格）：`$1`＝daemon 的信箱（daemon.json 給 `$AOS_STACK/../../loops_ctl_mailbox`：sam 的小格在 `loops/sam/`，11-02 改 `loops/<名字>/`，[thinking 11-02 stack-tools](../../../../../proto8/thinking/2026-11-02-stack-tools.md)），`aos-post send` 一封加子項 `tick`（每 300 毫秒 `aos-tick`）的信；`README.md`（怎麼起、人怎麼寄、怎麼看 loops_state、怎麼停）。自動測在 `impls/aos-daemon/tests/test_demo.py` 的 `run_daemon2`。
- `daemon-3/`（10-30，[agent-lifecycle](../../../../../proto8/thinking/2026-10-30-agent-lifecycle.md) 實作第 8 步）：一次性的東西掛 daemon 的兩種寫法。`_entry`＝`exec aos-daemon "$@" daemon.json`；`daemon.json`（`max` 10、`interval_ms` 200）同一支 `../tick` 掛兩次：`loops` 的 `tick_loop`＝`{"exec": "../tick", "max": 1}`（① 包成跑一次的子 loop）、`execs` 的 `tick_exec`＝`"../tick"`（② exec 型子項，直接 aos-exec 一次）；`README.md`（兩種寫法對照、怎麼跑、跑一次的 loops_state 兩張表、半路用 `aos-daemon-ctl add` 加一個；所以 daemon.json 也寫 `loops_ctl_mailbox`）。自動測在 `impls/aos-daemon/tests/test_demo.py` 的 `run_daemon3`。
- `tick/`（10-21 晚）：`_entry`＝`exec aos-loop loop.json`、`loop.json` 跑 5 次 `loop.json#/body`〔10-24 起單子直接寫在 `exec`〕（`aos-tick $AOS_STACK/tick.txt`），跑完時鐘檔是 5。
