### `proto8/extras/human`（給人用的 say／listen／chat）

人對一隻 agent 說話、看回答：10-30 起照 agent 對話協議（CONVENTION P-42；[agent-lifecycle](../../../../../proto8/thinking/2026-10-30-agent-lifecycle.md) 第 4 步）只碰 stack——說＝寄進 `<stack>/queue/`、回答＝`history.jsonl` 最新那則 assistant、狀態看 aos-loop 的 `state.json`（之前：題目放 `$AOS_WS/new/`、答案在 `out/`，舊協議的 fsm 範本不再認）。Python 純標準庫、只在 Linux。說明在 [human/README](../../../../../proto8/extras/human/README.md)；設計 [thinking 2026-10-24-say-listen](../../../../../proto8/thinking/2026-10-24-say-listen.md)。

| 哪裡 | 負責什麼 |
|---|---|
| `bin/aos-say` | 一句話（參數或 stdin）＝一則 user message，`aos-post send --ordered <stack>/queue`（沒有 queue 先 init），stdout 印信號；`--stack`；沒有 `--name` |
| `bin/aos-listen` | 等一封（信在 queue 的 new/ cur/ 就等、不見了印 history 最新的回答；`--timeout`；10-30 晚起信在 new/、沒人在跑、trace.jsonl 卻比信新＝`LetterUnclaimed` 直接退，多半是舊協議的 agent，`aos_human.unclaimed`）、跟著看 history（`--follow`、`--last N`，一段＝問的話＋回答）、`--status` 快照（誰在跑、aos-loop 的 `phase`、最後一格、queue 幾封；10-30 起 stack 有 `letter_warning.txt` 就多印一行最後一封壞信，`aos_human.status_lines`）；`--trace` 帶 trace 短行；`--stack` |
| `bin/aos-chat` | say＋listen 串起來一問一答（印 history 新長出來的回答、queue 還有沒答的就等）；給了 agent 資料夾就每句替你跑一次（帶 `AOS_STACK`）；`/status`、`/run`、`/trace`；`--stack` |
| `bin/aos_human.py` | 三支共用：`Where`（工作區與 stack：`--stack` ＞ `$AOS_STACK` ＞ `<ws>/.stack/`；10-30 拿掉「`.stack/new/` 在就改用」的特例）、讀 `/proc` 看誰在跑（`AOS_STACK`＝這個 stack，或沒設時 `AOS_WS`＝這個工作區；只靠 `/proc`——10-30 eca 第 7 步刪了 `declared`〔stack 的 `server.txt`〕；掛 daemon 的經工作區 `.stack` symlink 用 samefile 認）、`failure`／`stuck_hint`／`unclaimed`（信在 new/ 而 trace.jsonl 比它新＝跑過卻沒認領，10-30 晚）（trace 最後一行失敗＝停在 `unit`〔round〕或 `state`〔fsm〕那格）、trace 短行、快照（loop 的 `phase`）；寄信、看回答、讀 stack 那幾樣在 `proto8/lib/aos/aos_ws.py`（跟 aos-ai 共用） |

測試：`proto8/tests/test_human.py`（10-30 eca 第 7 步加 `External` 2 案：臨時組的外部範本〔aos-loop 包 `lib/eca/turn`，10-31 改叫 `bin/aos-eca-turn --on-empty`；假 claude〕直接跑與掛 daemon 時，say／listen 答得出、`--status` 認得服務者與 phase）。
