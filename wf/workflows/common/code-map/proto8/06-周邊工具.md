### `proto8/lib`（腦可以叫的工具庫）

agent 的 `tools/<名>` 用捷徑掛進來的標準工具（引用、不複製）；10-24 只收了底層 `base/` 七個。說明與工具契約在 [lib/README](../../../../../proto8/lib/README.md)；設計 [thinking 2026-10-24-tool-lib](../../../../../proto8/thinking/2026-10-24-tool-lib.md)。

| 哪裡 | 負責什麼 |
|---|---|
| `README.md` | 分層（base／aos／agent，後兩層還沒收）、工具契約十條（stdin 一份 JSON、stdout 是結果、錯一行同時印 stdout、只碰 `$AOS_WS`、逾時、原子寫檔…）、怎麼用捷徑引用、七個工具的索引 |
| `base/<名>/`（每個一樣三個檔） | `_entry`（python3 純標準庫，第二行是 NAME）、`tool.json`（給模型看，`description`＋`parameters`）、`_metainfo`（給 kernel 與人：`summary`、`time_ms`、`side_effect`…） |
| `base/read`、`write`、`edit`、`bash` | 讀檔（2000 行或 50KB 截）、整份寫、照字面替換（全有或全無）、在工作區跑一行 bash（`timeout_s` 30／300、整群收）；來源 demo/pi-tools |
| `base/ls`、`json_read`、`json_edit` | 列資料夾（分頁、回 JSON）、照指標看 JSON（大的摺起來）、照指標改 JSON（`set`／`del`，全有或全無）；新寫，Python 版、不叫 aos-json |

測試：`proto8/tests/test_lib.py`（形狀檢查跑過每個工具、各工具行為、demo/agent-liv 經捷徑跑一題）。

### `proto8/human`（給人用的 say／listen／chat）

人對一隻 fsm agent 丟題、看答案：題目放 `$AOS_WS/new/`、答案在 `out/`。Python 純標準庫、只在 Linux。說明在 [human/README](../../../../../proto8/human/README.md)；設計 [thinking 2026-10-24-say-listen](../../../../../proto8/thinking/2026-10-24-say-listen.md)。

| 哪裡 | 負責什麼 |
|---|---|
| `bin/aos-say` | 一句話（參數或 stdin）寫成 `new/<題名>`，stdout 印題名 |
| `bin/aos-listen` | 等一題的答案（`--timeout`）、跟著看（`--follow`、`--last N`）、`--status` 快照（誰在跑、停在哪格、各階段幾題）；`--trace` 帶 trace 短行 |
| `bin/aos-chat` | say＋listen 串起來一問一答；給了 agent 資料夾就每句替你跑一次；`/status`、`/run`、`/trace` |
| `bin/aos_human.py` | 三支共用：定工作區與 stack、放題、讀 `/proc` 看誰在跑、trace 短行、快照 |

測試：`proto8/tests/test_human.py`。

### `proto8/ai_tools`（給 AI 用的 aos 工具集）

`aos-ai`：起 agent、丟題、跑、背景顧、看狀態與錯誤、停，生成 JSON 與骨架、查概念；每次 stdout 一行 JSON。說明在 [ai_tools/README](../../../../../proto8/ai_tools/README.md)；設計 [thinking 2026-10-24-ai-tools](../../../../../proto8/thinking/2026-10-24-ai-tools.md)。

| 哪裡 | 負責什麼 |
|---|---|
| `bin/aos-ai` | 命令列本體：`templates`、`spawn`、`ask`、`run`、`status`／`answer`／`trace`／`history`、`start`／`stop`／`wait`（寫 daemon 的 ctl）、`daemon up｜down｜status`、`exec`、`edit`、`doctor`；只寫 root 底下、不刪東西；PATH 自己放 impls 各支（含 aos-json） |
| `bin/aos_ai_make.py` | `make`：生成 inst／loop／fsm／daemon／metainfo／tool_json（先驗形狀、`--out` 原子寫、有 aos-json 就跑 `check`），骨架 `make tool`／`cell`／`func`（改既有 fsm.json 交給 `aos-json set`） |
| `bin/aos_ai_explain.py` | `explain`：印 `concepts.md` 的一節；`--here` 模擬 aos-exec 會讀哪些 `.env`、挑哪個入口、六個變數的值 |
| `dan_tools/<名>/` | 給 agent-dan 掛的六個工具（`tool.json`＋`_entry`，都轉叫 aos-ai）：`spawn_agent`、`ask_agent`、`agent_status`、`make_json`、`make_tool`、`explain_aos`；aos-ai 的錯印成 JSON、退 0 |
| `claude_skill/aos/SKILL.md`、`.claude-plugin/plugin.json` | Claude Code 的 skill，同時是 plugin（`claude --plugin-dir` 或捷徑進 `~/.claude/skills/`；repo 根的 `.claude/` 沒動） |
| `claude_skill/aos/concepts.md` | aos 概念速成（每節白話、最小範例、常見錯、條號）；`aos-ai explain` 讀的就是它 |

測試：`proto8/tests/test_ai_tools.py`（不叫真模型、不叫 claude）。

### `proto8/grow`（函數長大／縮回）

`aos-grow`：把呼叫方一格的函數從內嵌單子長成 `NAME.json`、再長成 `NAME/` 資料夾（或縮回去），呼叫方跟著改、跑起來一樣。Python 純標準庫、不進 impls。說明在 [grow/README](../../../../../proto8/grow/README.md)；設計 [thinking 2026-10-24-fn-grow](../../../../../proto8/thinking/2026-10-24-fn-grow.md)。

| 哪裡 | 負責什麼 |
|---|---|
| `aos-grow` | `up 設定檔#/指標 --to file｜dir [--name] [--take 檔]...`、`down 設定檔#/指標`、`--dry-run`；補 `cwd`、改相對 `$ref` 與 `AOS_CD` 路徑讓行為不變；先寫新檔、最後改呼叫方（原子） |

測試：`proto8/tests/test_grow.py`。
