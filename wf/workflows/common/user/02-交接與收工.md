## compact 前先寫交接（2026-10-15 定）

他發現 compact 之後頂層會變笨——忘了規範、忘了這個 session 裡給過的授權和偏好。原文：「像這種comapct後變笨的狀況，有可以改善的方法嗎」「好，派人去設 hook」。

所以：**他說要 compact 前，頂層先把交接寫進 [wf/HANDOFF.md](../../../HANDOFF.md)**——session 內授權（push、在家／出門、模型分配）、正在討論的設計與已定／未定、當晚新定的規範條目編號。compact 後 repo 根 `.claude/settings.json` 的 SessionStart hook（matcher `compact`）會跑 [`wf/tools/compact_reload.sh`](../../../tools/compact_reload.sh)，把本檔全文和 HANDOFF 最新一條自動讀回來。

**什麼時候換手**（2026-10-25 定）：使用者看 `/context` 時說「差不多30%的時候就該換手了其實」，前一句是「注意context有沒有滿，可能的話抓個大斷落重開隊伍。你自己也是，跟我說一聲我就compact」。所以 context 用到約 **30%** 就換手：頂層先寫好 HANDOFF 再跟他說可以 compact；隊長與長工 agent 在最近的大段落寫交棒檔、收線，由頂層開新的接手。

## 「審」的範圍

他說「審」文件時，除了前後不一致、裁定有沒有落實、壞連結，**也要審設計原則**：冗餘（同一件事多處重寫、兩套機制做同一件事）、該考慮卻沒考慮到的狀況（規模、當機復原、權限、人工介入、版本演進）、跟自己宣稱的原則打架的弱點（2026-09-30 補）。仍然只攤問題給他裁定。審稿提示一開始就把設計問題列成獨立一類（報告分必修／設計問題／建議／要使用者裁定）。

領域詞彙以 `docs/aos-folder.md` 的定義為準；常猜錯再開 `glossary.md`（見 [common/README](../README.md)）。


## 日誌怎麼寫（2026-10-26 定）

使用者講 session_logs 與它的索引：「感覺這塊能優化...」；看完四個選項回「1+3+4」。

日誌（[`session_logs/`](../../../session_logs/README.md)）只記「哪天做了什麼」，**不是第二份知識庫**：

- **每日檔少寫**：`session_logs/<月>/<日期>.md` 每條一行「動了哪些檔／做了什麼」＋連到結論所在處。結論寫進它自己的文件（proto 的 thinking、NORMS、各工作流、本檔），日誌只連過去；只有沒有別的家可放的（代定清單、當天的交接）才寫在日誌裡。
- **總目錄**（[session_logs/README.md](../../../session_logs/README.md)）每天一列，寫一句「這天定下了什麼」（結論），不寫做了哪些事；連到該日檔，已收月摘要的連月摘要的該日段。
- **月摘要**：一個月結束後（下個月第一次動日誌時順手做），把該月每日檔濃縮成 `session_logs/<月>.md`：每天一段 `## <日期>`，只留結論（別處已有就連過去）與使用者原文（逐字；被後來推翻的可刪），判準與原文檢查照 [tidy 內容精簡](../../tidy/content-trim.md)，commit 訊息寫「內容精簡」。被連過的舊錨點在月摘要裡保留同名標題或 `<a id>`。每日原檔照 [STRUCTURE archive 規則](../../../STRUCTURE.md#archive-規則)封存到 `session_logs/archive/<月>/`，活文件裡指向它的連結改指月摘要同名段，`session_logs/archive/README.md` 只追加列。
