## 在跑著的樹旁邊做事（公司 WSL）

公司 WSL 的 `~/aos-home` 有一棵使用者整天在用的樹（下面叫「活樹」），頂層 session 自己就是樹裡的一隻 agent。現況與任務書必貼的硬規則在 [aos-teams/06](../../dispatch/aos-teams/06-公司WSL活樹與任務書硬規則.md)，測試怎麼跑在 [testing](../../testing.md#不碰跑著的樹)；這裡記坑。

- **收行程不按名字、不按命令列字串**：`pkill`、`killall`、`kill $(pgrep …)` 都不准。只准 `aos-daemon-ctl -d <自己暫存樹 stack 的絕對路徑> shutdown`（下之前 echo 路徑確認），或 kill 自己起的時候記下、且 `readlink /proc/<pid>/cwd` 核對在自己暫存夾裡的 pid；tmux 只動自己用 `-S <暫存夾內 socket>` 起的。收尾貼 `pgrep -u "$USER" -af aos-daemon`，確認活樹的 daemon 還在。
  11-13 10:25 子 agent 用 `pkill -INT -f "aos-daemon --enable-logs daemon.json"` 收自己暫存夾的測試 daemon，活樹根 daemon 的命令列一模一樣，兩台一起停了約 4 分 20 秒，使用者自己起回來（[事故紀錄](../../../../proto8/thinking/2026-11/13/kernel-framework-開工.md#十一事故子-agent-誤停使用者的樹11-13-1025)）。repo 裡的測試也不留 `pkill -f`：`cmd/aos-agent/tests/test_rm_keep.py` 原本那一行已改成收自己記的 pid（`88c571674`）。
- **agent 的 Bash 帶著活樹的 `AOS_STACK`／`AOS_DAEMON`／`AOS_HOME`／`AOS_WS`**（頂層是樹裡的 agent，子 agent 全部繼承）：不清掉就跑測試或 aos 指令，檔會寫進活的 stack、信會寄到活樹。起任何 aos 行程、跑任何測試前先清；跑完 `ls` 活樹裡頂層那一格 stack，對照開工前的清單。
  11-13 至少四條線中過：線庚、線寅、線申（兩行 `aos-agent ctl add` 帶著頂層的 `AOS_STACK`，回信箱開在頂層那格的 `daemon_reply/`，見 [eca-as-kernel](../../../../proto8/thinking/2026-11/13/eca-as-kernel.md)），另有一條線在 11:22～11:23 把 `daemon_reply/`、`interfaces.json`、`observed.jsonl` 三樣留在頂層的 stack 裡。
- **清環境的寫法在 zsh 裡會靜靜失效**（Bash 工具的殼是 zsh）：`env -u $VARS` 不會把變數拆成多個字，等於沒清（線寅）；在 zsh 裡 `source` 一份 bash 寫法的環境檔，清的那段不生效（線申）。清環境一律寫成一支 bash 腳本、用 `bash 腳本 指令…` 跑，腳本開頭「不是 bash 就拒絕」、清完「還有殘留就拒絕」（範例在 [testing](../../testing.md#不碰跑著的樹)）。
- **改 repo 的這三類檔，存檔當下活樹就在用**：`~/.local/bin` 的 `aos-*` 是連到 repo 的連結，所以 `proto8/cmd/`、`proto8/py/`、被指令直接 import 的 `proto8/lib/agent/*.py` 一存檔就生效。新碼先放新檔／新函式、測到綠，接到既有路徑的那一步放最後一個 commit、動手前回報調度者；改既有檔「先寫暫存檔再改名、存完立刻 import 驗一次」。
  11-13 線庚有一次存檔少一行，約一分鐘內「列了 stdio 外部 server 的 eca」會 `ModuleNotFoundError`，剛好沒人走到（[fixes 施工結果](../../../../proto8/thinking/2026-11/13/fixes-施工結果.md#各項要記的事)）。
- **活樹的 `lib`／`templates`／`knowledge`／`py` 是複本，改 repo 不會生效，重抄才生效**：結果檔的「生效表」要逐項寫「存檔即生效」還是「要重抄」；重抄是停樹時的事（做法在 [aos-teams/06](../../dispatch/aos-teams/06-公司WSL活樹與任務書硬規則.md#停樹換檔的做法)）。
- **在 repo 裡 build C++＝換掉活樹的執行檔**：CMake 把執行檔寫回原始碼夾的 `bin/`，`~/.local/bin/aos-daemon` 指的就是那個檔。要編就把原始碼抄到 repo 外的 build 夾編、測，停樹時只換檔。
- **在 agent 的 shell 裡起活樹，先清掉全部 `AOS_*`**：起樹前 `source` 的環境檔要清全部 `AOS_*`（正本 `proto8/extras/aos-home/env.sh`，活樹那份 11-13 15:35 已改），或用 `env -u` 逐一清乾淨再起；起完看根 daemon 的 cwd 與 stack 是不是 `~/aos-home` 那一格。
  11-13 15:24:54 `eca_main` 在自己的 shell 起樹，當時的 `env.sh` 只清 `AOS_DAEMON`／`AOS_KERNEL`／`AOS_CLOCK`、`AOS_STACK` 還在，root 把它那一格當成 root stack；約 35 秒真的領班與 9 個 agent 掛在錯的 root 底下、看到錯的鐘，它自己停掉、清乾淨重起（[11-13 日誌](../../../session_logs/2026-11/2026-11-13.md#停樹換檔與起樹事故15231529)）。
