**這篇講什麼**：agent 的「一輪」這一週怎麼一路變，四次轉彎各為什麼 | **幾分鐘**：5 分

「一輪」＝agent 收到一句話、想、動手、答完的一整趟。這一週它換了三種長相，最後那支指令被你裁掉。下面照時間走，每次轉彎都寫「先這樣 → 後來那樣 → 為什麼」。

---

## 10-28：什麼都要是資料夾程式，一輪也是

**你定的方向**：你說「各種單位都要跟aos函數對上，也就是aos-exec可以跑的單位目標。包括endpoint」。意思是收題、記對話、問腦、跑工具、還有流程上每個時間點的插座，全都做成一個資料夾一支程式。

**一輪放哪**：AI 原本代定「一輪留在零件庫，不升成一支正式指令」。你先講了一句「也可以用aos-round，讓他跑一整輪」，接著又改口：

> 喔不，還是零件庫吧。只是說，aos-round他是一個語法糖，沒有他，我們也可以用aos-loop加上一些東西去實現。

所以 10-28 的定案是：**一輪是零件庫裡的一支骨架、是方便用的捷徑（語法糖），不是正式指令**。

## 10-28 晚：第一版做出來

照這個方向做了第一版：零件庫裡有收題、記對話、問腦、跑工具四格，加上一支叫 round 的骨架把它們照順序叫一遍；流程上留了九個插座（一輪開始前、問腦前後、跑工具前後、出錯時、暫停……），沒插東西就當沒有。

**強度**：用假腦跑過（答一題、沒題、腦壞掉都驗了）；也讓 claude 經 MCP 問這隻 agent 一題、拿到假腦的答案。接真模型那題那晚這台連不上，沒跑。

## 10-30：你看地圖時問「round 是啥」

**先這樣**：round 是一支自己寫順序的骨架，等於把當初設計稿上的步驟一行行直接寫成程式。

**你的疑問**：你原以為它只是「開啟aos loop跑fsm，直到fsm停在idle且沒有新訊息的時候，就停掉aos loop」，看到實作後問：「他能否待在aos-loop/fsm的框架下去實現？」

**後來那樣**：你澄清——

> 裡面的迴圈那塊可以用loop/fsm實作，外部這塊各類用到的函數也可以用aos函數替代。整個框架則化作aos-round。整體看起來就像是包在aos loop/fsm agent上的一層薄殼

於是改成：一張流程表（交給「照流程表一格一格走的機器」去走）＋表上五個薄薄的小格（等題、想、動手、看還有沒有工具、交卷）＋一支叫 aos-round 的小指令負責挑表、開機。表怎麼走看每格的結束碼：想完有要動手就去動手、沒有就去交卷。你說「都照建議」，舊骨架當天就刪掉、不並存，10-30 晚做完。

**請留意**：10-28 定的是「不升成正式指令」，10-30 實際變成了一支正式指令 aos-round。兩次都有你的原話，中間沒有一句話明講「推翻 10-28」。

## 10-31：要不要整個收成一支程式

**起因**：你那天說，與其拼一堆小組合子，「不如直接整合成單檔案程式」，並確認「指 round」；又給了一把尺——拆成資料夾程式的好處是 git 能存進度、能和任何語言的程式串、agent 好用，值不值得拆就看這個。

**草圖**：一個唯讀 session 拿這把尺推了一份「重切」草圖：五個小格收回 aos-round 一支程式裡，只留問腦、插座、壓縮對話、工具在外面。

**fable 收斂的結論是不重切**，理由是五個小格其實有人單獨在用：外面問一題的工具一格一格叫它、畫面上顯示「停在想那格」、當掉後能從停的那格接著跑，大約三四十個測試靠著這個。收成一支程式，這些都要自己重做一遍。

## 11-01 早：你說「不重切，要深思」

你回：「3.先這樣，這塊之後我要深思。」也說何時該收不要死盯三條門檻，「反正就是我們這套技術棧的優點和缺點，大家比比看就好」。所以早上的狀態是**暫時不動、但沒結案**。

同一天早上另一件相關的事：管零件清單的那支指令（aos-parts，見第 3 篇）被整支刪掉，aos-round「沒題時停還是等」的設定也從牆上便條改成寫在命令列。

## 11-01 晚：「刪掉」

你問：

> aos round這東西還沒刪掉嗎

> 這應該整個都不需要吧

頂層說明它只有 62 行（挑表、在牆上貼一張「agent 在哪」的便條、交給流程表機器），用現有的東西就組得出來，並列了牽連範圍（外面問一題的工具、外部 coding agent 那條線、範本 agent、八個測試檔、條文十來處）。你回：「刪掉」。早上「要深思」那題，就此有了答案。

**要分清楚刪的是什麼**：刪的是 aos-round 這支開機的小指令。依來源寫的，流程表和五個小格留著；之後一輪靠 agent 自己的設定（`loop.json`）直接叫流程表機器跑那張表，五個小格從 aos-exec 給的位置知道 agent 在哪，不再靠那張便條。

## 現在的狀態

- **main 上**：aos-round 還在，是 10-30 那版（流程表＋五格＋開機指令），只改了早上那條「停還是等」的寫法。
- **另一個工作分支**：正在刪 aos-round，和「把四十多個牆上便條改成命令列或檔案」那批一起做，**還沒併進 main**，做完的對照文件也還沒開。
- **沒寫清楚的**：刪掉之後，「沒題時停還是等」改由誰挑表，來源只寫「用現有機制組合」，沒寫細節（不確定）。

## 回頭看這條線

一輪這一週的位置是：零件庫的捷徑 → 升成正式指令 → 差點收成一支大程式 → 指令刪掉、回到「用現成的外圈加流程表組出來」。最後的樣子其實很接近你 10-28 那句「沒有他，我們也可以用aos-loop加上一些東西去實現」。中間每一步都有你的原話撐著，但前後並不一致；這裡只把來回攤開，不判斷哪一步錯。
