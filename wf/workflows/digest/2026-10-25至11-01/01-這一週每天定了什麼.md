**這篇講什麼**：10-25 到 11-01 八天，每天定了什麼，加上哪幾條線先定後翻　|　**幾分鐘**：4 分

## 這一週的大方向

前半週在替「外部 coding agent（像 claude code、codex）」和 aos 自己的 agent 一路加零件：總管、登記表、信箱、一輪的流程表。後半週開始把零件收回來，到 11-01 晚你說「就是整體要瘦身」，範圍明天再定。

---

## 10-25：命名規則、換手時機

計數一律叫 `counter_<被數的東西>`、上限叫 `max_*`、時間點叫 `<發生了什麼>_at`。AI 的對話記憶剩約三成就換一個新的接手。

另外開了一個試驗：讓 AI 照「由上而下拆資料夾樹」的想法，自己把一個叫 galtxt 的題目拆成一層層資料夾。沒人評，也沒量完。

## 10-26：文件整理

主要是 wf 文件的收納規矩（條文收進 `docs/`、日誌每天一行一條）。同天做了第一個「叫 claude 做事的資料夾程式」，實跑一次通過。

## 10-27：很多個 claude 怎麼管

用一個總覽指令（aos-hub）把開著的 claude 列出來，cd 過去一個指令接上，閒 30 分自動收起，再接就叫回。外面的 claude 要用 aos 的程式，走一條新的轉接口（aos-mcp），不必給它開 shell。這些是代定、可以翻。

## 10-28：零件登記與「一輪」的設計（這天最多）

- 總管 aos-hub 裡面要跑一個常駐的管理程式，分「收起」和「結束」兩種停法。
- 工具改成每個 agent 資料夾一份登記表（aos-tools），當天做了第一版。
- agent 裡的每個單位（收話、問腦、用工具、一輪本身）都要是 aos 的資料夾程式。
- 一輪的細節照原則代定，你回「照新做法」全部定案；零件也要走一份登記表（parts.json）。

## 10-29：程式之間怎麼傳話

「投遞」（每封信都算）和「窗」（只看最新那張）並列，是程式之間交流的兩個基本做法。誰是誰，就看它的資料夾路徑；人也算一個。

試驗場先做了「agent 自己去看信箱」，看完方向就改了：你講的兩種用法（交代完就不管、交代完還要聽它回）都用不到 agent 自己看信箱。中途塞話、偷看它在幹嘛，統一用 aos-say／aos-listen。

## 10-30：agent 收話是排隊，總管改名

你照直覺定：agent 這層收話是一條排隊（queue），不叫信箱。外部 coding agent 當黑盒子，生死在外面管。看完現況地圖後，你又定不另做通用總管：現有的改名 aos-eca-hub，通用的那層就是 aos-daemon。

同天把「一輪」改成照流程表一格一格走的機器上的一層薄殼（aos-round），做完了。

## 10-31：零件表該放哪、便條改名

零件表一度定成放進「標準庫」那一層（跟流程表機器同等地位的基本零件）。你提了 aos-var 又自己收回，說 `$ref`、`$env`（設定檔裡「去別處拿值」的現成寫法）本來就有這功能。aos 的環境變數一次補上 `AOS_` 開頭，一輪不重切。

## 11-01：開始瘦身

- 早上：零件表降成 agent 自己這層的一個約定，管它的那支 aos-parts 刪掉了（做完）。
- 下午：你進試驗場，從最小的 agents/bob 做起，定了原則「環境變數像 Janet 的 `dyn`，只在必要時用」。
- 晚上：環境變數五題裁了三題，有一題你兩次沒聽懂、待重講，還有一題「到時候再說」。42 個旋鈕要改成參數或檔案；aos-round 整支刪掉；做出 agents/amy 原型（一個視窗開 claude 畫面，另一個視窗 say／listen），實跑過；aos-listen 的用法你又改了一次。
- **做完、已併入主線**：改旋鈕、刪 aos-round，11-01 晚已併入 main（`974ba4f2`）。aos-listen 新用法 11-02 晚也做完了（`aos-say 話 && aos-listen`）。
