**這篇講什麼**：agent 要用的零件（給腦用的工具、一輪裡的各格）去哪找、怎麼登記，這週怎麼來回 | **幾分鐘**：5 分

## 先講結論（11-01 早為止）

一隻 agent 找零件有兩條路，兩條同時有效：

- **通訊錄**：agent 資料夾裡的一份清單，寫「這個名字 → 在哪裡」。工具一份（`tools.json`），一輪的各格另一份（`parts.json`）。
- **門牌**：通訊錄沒寫，就照固定名字去 agent 資料夾裡找，例如門口掛著 `queue`、`history` 的那個資料夾或捷徑。

通訊錄有寫的優先，沒寫的看門牌，再沒有就當沒裝。

## 一、工具：從「挨家挨戶敲門」到通訊錄（10-28）

**後來**：你說：

> 像現在這樣掃tool.json，實在太土太粗暴，不夠靈活

於是提了 aos-tools：維護一份工具通訊錄，用 `add／rm／ls／get` 增刪查。登記的東西可以是資料夾、JSON 檔或可執行檔，各自要交出一份「工具說明」；不合格就報錯、不猜。

**當天做了第一版、跑過測試**：通訊錄每個 agent 資料夾一份 `tools.json`、裡面存絕對路徑；舊的 `tool.json` 全改名 `_tooldef.json`（58 份）；工具撞名報錯、加 `--override` 才蓋。aos 自己的 agent 直接讀這份，外部 coding agent 經 aos-mcp 讀同一份。

一輪（收到一句話、想、動手、答完）由好幾格組成：收題、記對話、問腦、跑工具……多半是共用的標準件。

> 註冊檔案中沒寫的，那就是走固定名字

所以格也有一本通訊錄（`parts.json`），另做一支管它的指令 aos-parts；捷徑降成「門牌」那條路的一種放法。查找順序就此定下：通訊錄 → 門牌 → 沒裝。
