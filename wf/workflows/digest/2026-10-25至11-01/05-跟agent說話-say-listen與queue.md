**這篇講什麼**：人怎麼對一個跑著的 agent 說一句話、拿回答；這一週那條「說話的管道」轉了幾個彎 | **幾分鐘**：5 分

一句話版：說話＝在 agent 門口**排一張留言條**（aos-say），聽＝**等它的回條**（aos-listen）。這一週改的是「留言條放哪、怎麼排、回條怎麼認」，最後一個改法你 11-01 晚剛定、**還沒做**。

---

## 起點（10-24）：題目一張、答案一張

做了三支指令：aos-say 放一題、aos-listen 等答案、aos-chat 一問一答。題目寫成工作區 `new/` 裡的一張紙，答案出現在 `out/` 裡同名的一張。

say 會印出那張紙的名字，listen 拿這個名字去等它的回條，寫成 `aos-listen 題名`。這種用法是當時隊長代定的，你那天說「都按建議做」，整批點頭。當時只用假腦跑過。

---

## 轉彎一（10-28）：它其實就是一條排隊

你說：「aos-say/listen，其實就是stdin那個queue的push，和stdout pop」。也就是：說＝把留言條排到隊尾，聽＝從另一頭拿回條。

你又說：「aos-say/listen是面對aos agent的，或許可以提取出相關協議，然後讓hub實作」。意思是這套排留言條的規矩要寫清楚，讓 aos-hub（替 claude code 這種外部 coding agent 開畫面、轉話的常駐程式）也照著做，這樣 say/listen 也能對 claude 說話。這天做成了，在 WSL 實跑過。

同一天問「留言條要放 claude 的工作資料夾，還是別處」，你答：「放Stack比較好。」於是信箱改放進那個資料夾底下的 `.stack/`（每次執行自己的抽屜），不再長在你的專案裡。

---

## 轉彎二（10-29）：讓 agent 自己去看信箱？解錯題

試驗場試了另一個方向：給 agent 一個「看信箱」的工具，在 prompt 裡叫它答完順便看看。haiku 跑 16 次，只有 9 次記得去看，看了也不一定照做。

你看完覺得不對，然後講了兩個使用場景：

- **射後不理**：發一個 agent 出去就不管它，跑完自己結束。要它做什麼，事先寫在它的定義裡、放在工作區裡，途中誰都不碰它。
- **射後有理**：發出去以後，它跑著的時候你還能塞話給它、偷看它說了什麼，必要時暫停它。

兩個場景都用不到「agent 自己去翻信箱」：前一個根本沒有途中的話，後一個塞的話直接排進它的對話。所以那個看信箱的工具解錯題，擱下了。

你接著補：「給予stdin/偷看stdout的動作，我希望有一個通用接口，也就是aos-say/listen」。射後有理那種「途中塞話、偷看」，就統一用 say/listen。

---

## 轉彎三（10-30）：不叫信箱，叫 queue

你說「信箱這個概念不該在這一層出現，這一層更接近訊息的queue概念」。於是定：

- agent 這一層的輸入叫 **queue**，就是一排**有先後順序的留言條**，放在 `.stack/queue/`。「信箱」這個詞留給 agent 之間互相寄的請求。
- aos-say 改成往 queue 排一張留言條；回條不再是 `out/` 裡的另一張紙，而是 agent 對話紀錄裡**最新那句回答**。
- 10-24 那套「題目放 `new/`、答案放 `out/`」退場，只留給舊的範本用，say/listen 不再認它。

這次照計畫改完了程式。10-30 晚頂層用真模型（GPT）代跑過：say 一句、listen 拿到「17 乘 23 是 391。」，aos-chat 一問一答也通；但舊範本 agent-dan 還照老規矩讀 `new/`，say 給它不會報錯、只會一直等。

## 實跑（11-01 晚）：amy，兩個視窗

你想要：視窗一跑 amy，直接進平常那種 claude code 畫面、你照常用；視窗二打 `aos-say "現在狀況" && aos-listen` 跟它說話。你說「你幫我想」、「做出來讓我試」。

隊長用現成零件組出原型（repo 程式沒動，在試驗場）。實跑過，用 haiku：

- 畫面開著、你人在畫面上時，視窗二 say 之後 2.5 秒拿到回答，畫面上也看得到那句。
- 隊長代定：你在畫面上的時候，留言條也照樣貼進畫面答（不先讓給你）。不這樣的話，你人在畫面上它就一直讓，視窗二永遠等不到。可翻案，改一個字。
- 邊角：你自己在畫面上打的話不會進對話紀錄；你打字打到一半時，留言條會接在你的字後面。

## 轉彎四（11-01 晚）：`aos-listen 題名` 翻案

原型的說明裡寫成 `N=$(aos-say …); aos-listen "$N"`（先記下留言條的號碼，再拿號碼等回條）。這種寫法要記號碼，是因為現在的 listen 不帶參數時會一直跟著看、不會結束。你看到後說：

> aos-listen "..."這種使用方式是誰定的，我不喜歡。aos-say "..." && aos-listen才是正規用法。

追下去，是 10-24 隊長代定、你整批點頭的那條。現在定成：

- 正規用法只有 `aos-say 話 && aos-listen`。listen 不帶參數＝等**最新那張留言條**的回條，拿到就印出來、結束。
- 帶號碼的那種用法拿掉。
- 原本「不帶參數＝一直跟著看」改成要明寫 `--follow`。

**這條還沒實作。** 排在另一個工作分支（刪 aos-round、改旋鈕那批）併進 main 之後，免得兩邊同時改 aos-listen。
