**這篇講什麼**：claude code、codex 這種別家的 AI 程式怎麼接進 aos，「管它活著的那一層」怎麼長出來、又怎麼縮回去 | **幾分鐘**：5 分

## 一句話

這一週先替它們蓋了一個專屬管理處（aos-hub，裡面還有自己的常駐程式），10-30 你看地圖後把它拆掉：通用的那半交給本來就有的管家 aos-daemon，只留「畫面」這種別家程式才有的事，改名 aos-eca-hub。eca＝external coding agent，外部 coding agent 的縮寫。

## 10-26～27：先叫得動，再讓它用 aos 的工具

- **10-26**：試驗場第一個節點只做一件事：叫 `claude -p`（一問一答、答完就退的用法）。進門那張紙一行，Python 十幾行。實跑過，3.6 秒。

## 10-27：很多個 claude 同時跑，誰來看？

你說「我不可能每個都開一個shell視窗去看」，又要閒著的先關掉、下次叫回來。於是有了 aos-hub：列出全部、`cd` 到哪個資料夾一個指令就接進那裡的畫面、閒了收起、用 claude 自己的 `--resume` 叫回同一段對話。實跑過（haiku，不到 1 美分）。

## 10-28：先加厚——hub 裡跑一個常駐的管理程式

**先這樣**：10-27 的 hub 每次都當場翻檔看狀態。

**後來那樣**：你 10-27 晚的筆記說，用一張便條（環境變數 `AOS_HUB`）指到一個資料夾，裡面常駐一個 aos-kernel 記帳。你 10-28 說：「其實應該還是要aos-hub。因為不只claude code cli，可能也要包括pi coding agent, codex之類。」「應該要有pause和stop兩種。」

**定了的**：狀態以常駐程式記的為準；它掛了指令就報錯；`AOS_HUB` 沒設也報錯；pause＝關畫面、對話留著，stop＝歸檔、不再叫回。

當天照此重寫，還做了「每種程式一張適配表」：claude、codex 兩欄實測過，pi 這台沒裝、只照文件填。

## 10-29：兩隻 bob，撞到 hub 的邊

bob-1 射後不理（跑完就結束），bob-2 射後有理（跑著時能塞話、看回覆）。兩隻都實跑過。

## 10-30 早：你照直覺定——它是黑盒子，外面包

你說：「其他coding agent時，他們內部是黑盒子。」生命週期在外面包，掛到管家 aos-daemon 底下；「沒有的話也沒關係，linux本身的proc管理就夠，aos體系就是用ps aux+kill去管理」，又補「包成max:1也是可以」（讓管家只跑它一次、不重起）。

## 10-30 看地圖：再翻一次，hub 縮回去

**先這樣**：claude 被當成 aos agent 裡的「腦」。

**後來那樣**：你說「兩者是平級的關係，但你要把它當成aos agent brain...有點....」——外部 coding agent 是整隻 agent，跟 aos agent 平起平坐。

接著你說 aos-hub 應該很通用；頂層回：摘出通用那層，其實就是管家 aos-daemon。你：「aos-hub既然摘出來就是daemon，那就不做aos-hub，而是aos-eca-hub。aos-hub這個名字保留到以後使用」。

**為什麼這樣收**：記帳、列清單、閒了關掉，管家本來就會；只有開畫面、接回對話、保存它自己的對話檔，是別家程式才需要的。所以規劃（你「都照建議」）把 hub 自己的常駐程式刪掉、`AOS_HUB` 退場改用管家的 `AOS_DAEMON`，10-28 的「以常駐程式為準」改讀成「以管家的帳為準」。stop 的歸檔也從工作區搬到管家那邊（你回「A」）。

**當晚做完**，先用假的 claude／codex 跑過；當晚頂層又在家機用真的 claude（haiku）和 GPT 跑過**不開畫面的部分**，都過。信任提問、進畫面、Ctrl-] 跳出這些要人坐在畫面前，留給你。

## 11-01：試驗場 bob 與 amy

- **bob**：兩個檔、沒有程式碼，進門那張紙直接寫好 `claude -p` 的參數。實跑過，檔案寫進工作區、結束碼 0。
