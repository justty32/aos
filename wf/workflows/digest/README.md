## 這個工作流怎麼運作

**觸發**：你說「把這些東西濃縮給我看」「我只有半小時」「寫個我看得懂的版本」。

**做法**：主辦人（我）把來源指派給幾個 agent，一人寫一篇，全部照同一份寫作規範。**agent 只讀不寫來源**——digest 不修改任何既有的紀錄。

### 寫作規範（每一篇都要守）

1. **不准用讀者看不懂的名詞。** 判準：一個詞如果需要先懂另一個專案內部概念才看得懂，就不要用，或當場用一句白話解掉。
2. **拿他已經懂的東西打比方**，而且一篇之內比喻要一致。
3. **段落短**（手機上看，一段不超過四行），多用小標題，讓被打斷之後找得回位置。
4. **講事實不推銷。** 不確定的要標明不確定；「三個人獨立量到」跟「有一個人說」強度不同，要寫出來。
5. **每篇開頭固定一行**：`**這篇講什麼**：… | **幾分鐘**：…`
6. **不幫他做決定。** 攤開選項與代價就好。
7. **單檔上限 8192 bytes，目標 4000–6000。寧可短。**

### 什麼時候該再開一批

**紀錄長到你自己不想打開的時候。** 這批的觸發點是：一天之內產出三十幾萬字，而使用者明講「你讓我去啃那一大堆結論，我也是很頭痛」。

**每批一個資料夾、一個 README。** 這批直接放在本層是因為它是第一批；**再開第二批時，把這批收進 `2026-08-26/`，本檔退回只做導航**（照 [STRUCTURE](../../STRUCTURE.md) 的「膨脹即拆」）。
