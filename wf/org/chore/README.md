# 打雜工 `chore`

使用者 11-23：「fsm gpt則會是打雜工」「蒐集算打雜，但施工這塊，如果是重要的部分，那確實還是得用claude」「尤其是寫程式」。同天答七題「都按照推薦。…」（原話在 [org 入口](../README.md#哪些是使用者說的)）：第 4 題寫程式一律 Claude、不必判斷的機械式施工可以給 fsm gpt；第 5 題蒐集與雜活先給 fsm gpt，掛不起來才由 sonnet 的 Claude 子 agent 補位。沒註出處、標〔提案〕的是 fable 11-23 的切法。

用到才掛、做完就收；不佔位子，沒有地盤與筆記。

**現況：公司 WSL 11-23 下午第一次掛起來、做完一張蒐集單。** `eca-aos` 掛了 `eca-aos-sol-1`（agent-fsm 範本蓋上 wf 配給包 `gather`，腦 `sol` 加 `reasoning_effort: high`），派它盤點三組檔裡的「部長」：15:45 送任務書、15:55 回 DONE，24 處、11 個檔，跟 eca-aos 自己數的一樣。細節在 [eca-aos 筆記](../../ws/eca-aos/notes.md)。

之前卡的四關現在的樣子：

1. 真模型端點：通（核心程式位子 11-23 實測 4000 埠有在聽、gpt 有回話）。
2. 端點包的名字：配給包改成 `sol` 加 `reasoning_effort`（`e66a68095`），跟 llm kernel 範本一致。
3. `AOS_LLM_KERNEL`：不用抄配給包的 `.env`，由掛的人那邊（上層 daemon 那一列）傳下來。
4. 掛的人要有 `subagent`、`agent_def` 兩支工具：`eca-aos` 用 `self_tools add` 自己加了（`{"$env":"AOS_HOME","$path":"/lib/tools/agent/subagent"}`，`agent_def` 同理）。

實際掛一次學到的：

- 一張小蒐集單約 10 分鐘（高強度的 gpt 每問一次腦一到三分鐘），比 sonnet 的 Claude 子 agent 慢；適合不急、可以放著跑的單。
- 任務書要寫知識庫的絕對路徑（配給包的 system 只說「任務書給的知識庫」）。
- 它佔掛的人一個 `max_subagents` 名額；位子睡著也佔名額，四格滿了要先 `rm` 一隻。
- 工作區放 `wf/ws/eca-aos/temp/<agent 名>/`（不進 git）可行；定義放 `wf/ws/eca-aos/temp/defs/`。

## 職責

- **可以派**
  - **蒐集事實**（使用者 11-23「蒐集算打雜」；配給包的蒐集員）：查找、盤點、讀檔整理，每條附出處；不設計、不建議、不改它看的東西。
  - **逐條核對**（配給包的審稿員）：拿任務書或圖紙一條一條對，只指出、不修。
  - **不必判斷的機械式施工**（第 4 題：照對照表改名、搬檔、套格式）：現在沒有現成的包（kits 只做了「看」包，沒有寫的工具），要派得先配包。
- **不能派**
  - **寫程式**（第 4 題一律 Claude，不分重不重要），與其他要判斷的施工（使用者 11-23「施工這塊，如果是重要的部分，那確實還是得用claude」）。
  - 設計、架構、判斷對錯（使用者 11-07「gpt 系不做設計決策」，長期，見 [aos-teams](../../workflows/dispatch/aos-teams.md)「誰做什麼」）。
  - 改寫使用者的概念／規範條文（[user.md](../../workflows/common/user.md)：不算簡單工作）。
  - 交件、push、刪檔、問使用者、往下再掛人：題目與產物都交給掛它的人。
  - 要跑指令才知道的事：「看」包沒有 shell，掛的人自己跑好，把輸出給它。
- **分界**（第 4 題）：看「要不要判斷」——照一張對照表就做得完的給它；要讀懂程式、選做法、判斷對錯的，就是 Claude 的活。分不清的當成要判斷〔提案〕。
- **Done when**：`out/answer.md` 或 `out/review.md` 交出來，掛的人逐條對過證據；機械式施工交回改好的檔，掛的人對過 diff 再交件〔提案〕。

## 讀寫範圍

約定，沒有強制力（[places「寫入範圍只是約定」](../places.md#寫入範圍只是約定)）。

- **可以讀**：任務書點名的路徑、知識庫。
- **可以寫**：只有自己的工作區。這條只靠配給包的 system 文字，沒有 hook 擋（kits「已知限制」）；包裡關掉了改自己的工具，但那仍不是牆。
- **工作區放哪**〔提案，11-23 試過可行〕：放掛的人地盤的 `temp/<agent 名>/`（不進 git），要留的結果由掛的人搬出來。
- 活樹、git、刪檔的禁令在配給包的站台層 `site.txt`。

## 交接

| 誰 | 給它什麼 | 它交回什麼 | 之後 |
|---|---|---|---|
| 掛它的人（負責人或任何位子） | 一張單只做一件事：唯一目標、可讀可寫的路徑、交付物、完成條件 | `out/answer.md`、`out/review.md`，或全文放在最後一則回答 | 掛的人逐條對證據、不重跑；要進 repo 的由掛的人整理後交件；`subagent rm` |

- **誰掛誰驗收、誰負責**：它的結果不直接給使用者，也不直接給別的位子。
- 等它不要卡在同一回合（[aos-teams](../../workflows/dispatch/aos-teams.md)第 4 件）。
- 額度用光它不會來信（「看」包沒掛 `brain_notify`），掛的人自己看。
- 任務書不用附必讀清單：配給包只讓它讀知識庫入口加站台層。

## 模型

- **腦**：gpt 的 sol（包名見上面第 2 關）；不用 terra、不走 codex（使用者 11-14）。
- **同時幾隻**：一張單一隻，用到才掛；上限是掛的人的 `max_subagents`（預設 4）。名字 `<掛的人>-sol-<編號>`（aos-teams「命名」）。
- **掛不起來時**：蒐集與雜活由 sonnet 的 Claude 子 agent 補位（第 5 題）；機械式施工也改由 Claude 子 agent 做〔提案〕。
