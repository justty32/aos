# wf/org：工作室的分工（誰負責什麼、做完交給誰）

← [AGENTS.md](../../AGENTS.md)｜[WORKFLOWS](../WORKFLOWS.md)｜隊形短卡 [aos-teams](../workflows/dispatch/aos-teams.md)｜地盤 [wf/ws](../ws/README.md)

`wf/workflows/` 講「一類事怎麼做」，`wf/ws/` 放每個 agent 自己的東西，這裡只講**這件事歸誰、做完交給誰**。鐵律、使用者偏好、交件、活樹硬規則、地盤規矩都在原檔，這裡不重抄。

**何時用**：要決定一件事派給誰、要開或收一個位子、要掛打雜工、要改交接方式。
**何時不用**：指令怎麼下 → aos-teams；選哪級模型 → [team-model](../workflows/team-model.md)；某類事的做法 → WORKFLOWS。

> 然後你也可以開claude subagent fable，去規劃你這邊自己的團隊組織架構

> 蒐集算打雜，但施工這塊，如果是重要的部分，那確實還是得用claude

> 尤其是寫程式

使用者定的只有上面這四句。**本夾標〔提案〕的＝提案（fable 規劃，11-23，等使用者定）**，不是既定事實。舊文件（aos-teams、team-model、規矩卡）跟這幾句對不上的地方還沒改。

## 工作室的樣子〔提案〕

- **人少、位子固定**：一位負責人加少數專職位子，全是 eca claude。不設部長，不照生產線分部門。
- **位子不等於一直開著的行程**：位子＝一張角色卡（本夾）加一格地盤與筆記（`wf/ws/`）。有活才掛；沒掛時由負責人派 Claude 子 agent 代班：先讀角色卡與那個位子的 `notes.md`，收工前把學到的寫回去。記憶在筆記，不在某一段對話裡。
- **eca 自己開的 Claude 子 agent 是它的手，不算成員**：誰開的誰負責、誰驗收；模型照 [user.md「子 agent 模型」](../workflows/common/user.md)。
- **fsm gpt 只打雜**：用到才掛、做完就收，不佔位子、沒有地盤。
- **沒有位子的工作**（`proto8/py`、`proto8/cpp` 的程式，條文，wf 整理，環境）由負責人按件派，不預先開位子。

「位子」「負責人」「代班」這些叫法是〔提案〕。

**以後才開**〔提案〕：

- **前端位子**：使用者定了 `aos-eca-frontend` 的職責，或前端大修（progress `overview-page`）開工時，才寫角色卡。
- **核心程式位子**：同一塊程式的規矩與踩過的坑多到每次派工都要重講時才開；在那之前按件派。
- **設計、審查、測試、整合不開**：驗收是派工的人的事（要第二雙眼睛就按件派一隻），交件口是 commit-request 的排隊。
- **開位子的條件**：有固定的寫入範圍，而且有要跨件留下來的規矩。開＝寫角色卡、建地盤、成員表加一列；要使用者點頭（鐵律 2「開新工作」）。

## 標準流程〔提案〕

```
使用者 → eca-aos（聽懂、先講打算）
   ├─ 落在某個位子的範圍 → 那個位子（掛著：寄信；沒掛：派代班）
   ├─ 不屬於任何位子     → 按件派 Claude 子 agent（要規劃的派 fable）
   └─ 過程裡的蒐集與雜活 → 做的人自己掛打雜工、自己驗收
→ 做的人自己驗 → 交件（commit-request）→ 回 eca-aos 終局狀態
→ eca-aos 逐條對證據 → 回報使用者
```

- **沒有部長**：aos-teams、規矩卡、kits/card 寫「寄部長」「部長放行」的地方，在這裡都是 eca-aos。
- **誰交件**：照任務書。沒寫就是：掛著的位子在自己的範圍內自己交、回報附雜湊；Claude 子 agent 與打雜工不交，產物給派它的人。跨出範圍、帶 `--rm`、要跑 `install.py`、會動到活樹的先問 eca-aos；push、刪檔照鐵律 2。
- **小事怎麼跳**：照 [WORKFLOWS「可以跳流程」](../WORKFLOWS.md)。另有三條短路：純查詢，eca-aos 自己答或派一隻唯讀的；活狀態與抄使用者原話進規矩，eca-aos 自己寫；位子範圍內一兩句的修正，直接給那個位子或代班，不寫正式任務書，照樣回終局狀態。
- **位子之間可以直接寄信**請對方做它範圍內的事（先例：規矩卡「回報怎麼寫」第 4 條）；接的人照樣回終局狀態，給 eca-aos 的回報裡提一句。
- **方向題**：誰碰到都回 `NEEDS-USER` 給 eca-aos，由它問使用者；沒有人替他選（鐵律 5）。
- **要規劃的大事**：照 [aos-teams「要規劃就走正統流程」](../workflows/dispatch/aos-teams.md)；需求不清先發想。

## 打雜工能做與不能做

- **能做**：蒐集（使用者 11-23「蒐集算打雜」）、照任務書逐條核對、不必判斷的雜活。
- **不能做**：重要的施工，尤其寫程式（使用者 11-23，用 Claude）；設計與架構判斷（使用者 11-07，長期）；交件、問使用者。
- **還沒定**：不重要的施工歸誰、怎麼分重要不重要。細節與掛法在[角色卡](chore/README.md)。

## 東西放哪裡、能寫哪裡

問答表、寫入範圍、定義怎麼寫 → [places](places.md)。一句話版：位子自己的東西放它的地盤 `wf/ws/<上層>/<名>/`，暫存放地盤的 `temp/`，討論與報告寫當天的 `proto8/thinking/`，`wf/org/` 只放入口與角色卡；角色卡列的寫入範圍是**約定、沒有強制力**。

## 交接與信件

已有的規矩在原檔：信的格式、STATUS、接了事一定回終局狀態 → [inbox.json](../workflows/inbox.json) 的 `local/letter_format`；回報怎麼寫 → [規矩卡](../workflows/common/rules-card.md)；任務書 → [派線與任務書](../public/派線與任務書.md)；派 Claude 子 agent → [claude子agent](../public/claude子agent.md)。

工作室多要求兩件〔提案〕（學自另一個專案第一輪的回顧）：

1. **任務書寫明**：能寫哪些檔、這段期間還有誰在改哪些檔、自己驗到哪裡、做到哪一步算完；只寫跟角色卡不一樣的地方。
2. **回信要短**：狀態、改了什麼、雜湊、卡在哪、產物路徑；細節另存成檔附路徑；沒跑的、不能跑的、不適用的分開寫。

## Done when

- 職責或現況變了，成員表與角色卡一起改。
