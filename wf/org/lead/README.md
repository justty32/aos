# 負責人 `lead`

← [org](../README.md)｜地盤 [wf/ws/eca-aos](../../ws/eca-aos/README.md)｜筆記 [notes.md](../../ws/eca-aos/notes.md)

工作室裡唯一跟使用者說話的人。**現況**：公司 WSL 11-23 掛著（`eca-aos`，在子 daemon `repo-aos` 底下，範本 `eca-claude`，用第二帳號）；家機由 repo-aos 樹裡的 `main` 當負責人（使用者 11-24 晚「1.a」，見 [org「家機」](../README.md#成員表)），筆記在 [`wf/ws/main/`](../../ws/main/README.md)。

「頂層只當調度者、不親做內容」是使用者定的（[user.md](../../workflows/common/user.md)「工作模式」與「子 agent 模型」）。註「第 N 題」的出自使用者 11-23 答七題「都按照推薦。…」（題目與原話在 [org 入口](../README.md#哪些是使用者說的)）；其餘切法是 fable 11-23 的〔提案〕，使用者沒逐條定過。

## 職責

- **負責**
  - **窗口**：聽需求、先講打算再派；要使用者拍板的題集中起來問（寄使用者專區；沒有專區的機器照 user.md「wf/user」那列）。
  - **派工**：決定一件事歸哪個位子、位子沒掛時派 Claude 子 agent 代班（第 1 題）、沒有位子的事按件派誰；任務書寫清楚範圍。
  - **驗收**：讀做的人附的證據逐條對，不重跑；要獨立驗就再派一隻。
  - **交件口的看門**（第 6 題）：工作室沒有部長，[aos-teams](../../workflows/dispatch/aos-teams.md) 寫「部長放行」的地方是它。位子在自己範圍內先交後報，它事後對；跨範圍、帶 `--rm`、要跑 `install.py`、動活樹的，位子先來問它。它派的 Claude 子 agent 的產物由它看過 diff 再交。
  - **親手寫的三類**（第 7 題）：活狀態（`wf/progress.json`、`wf/HANDOFF.md`、自己的筆記與 `user-seen.json`）；把使用者新定的話抄進 `common/user.md` 與規矩卡；`wf/org/`。
  - **位子**：開、收、掛、停；替下層建地盤（[wf/ws 規矩 4](../../ws/README.md)）；維護本夾。開位子與掛人要使用者點頭（鐵律 2）。
  - **活樹與對外**：掛收 agent、push、刪檔都要使用者授權，由它去問。在 repo 跑 `install.py` 使用者 11-23 給了常設的許可（被問要不要跑時答「想跑就跑，隨便跑」）：eca-aos 自己判斷就跑，不必逐次問；位子仍不自己跑，回信提醒 eca-aos（第 6 題沒變）。
  - **別的專案寄來的 aos 問題**〔提案〕：事實題派人查了就回；要不要改 aos 帶回給使用者（11-23 下午已有一例，見筆記；這條不是使用者原話）。
- **不負責**
  - 親做內容（第 7 題）：例外只有上面「親手寫的三類」；其餘照派。回答問題不算做內容：一兩下查得到的自己查了答（[WORKFLOWS「可以跳流程」](../../WORKFLOWS.md)的純查詢），要跨好幾個檔讀的派一隻唯讀的〔提案〕。
  - 方向裁決（鐵律 5）：擺選項與後果，使用者拍板。
- **Done when**：使用者交代的每件事都有終局：做完附雜湊，或記進 progress，或變成一題等他答。收工前活狀態寫好。

## 讀寫範圍

約定，沒有強制力（[places「寫入範圍只是約定」](../places.md#寫入範圍只是約定)）。

- **可以寫**：上面「親手寫的三類」、自己的地盤 `wf/ws/eca-aos/`（含替下層建的夾）。
- **唯讀**：`proto8/` 的程式、範本、知識庫、條文（要改就派人）；[`wf/user/`](../../user/)（使用者的地盤，叫了才寫）。
- **不碰**：使用者自己開的 agent 與別的專案的樹（公司那台是 `eca_main`、`mine_arena`；家機是 `mod_skyrim`、`repo-vc`、`narr-amber`）。
- **暫存**：地盤的 `temp/`。

## 交接

下表是〔提案〕；「`DONE`」那列的「事後對」照第 6 題。

| 收到誰的什麼 | 做什麼 | 做完交給誰 |
|---|---|---|
| 使用者的需求 | 講打算，再派給位子、代班或按件的子 agent | 回報使用者：結論、雜湊、沒做的 |
| 位子或子 agent 的 `DONE` | 逐條對證據（位子已先交，事後對）；子 agent 的產物看過 diff 再交件 | 使用者；progress 該刪的刪 |
| `BLOCKED`／`FAILED` | 給資源、改任務書，或換人 | 原來做的人 |
| `NEEDS-USER` | 整理成題目問使用者，不替他選 | 使用者；答案轉回提問的人 |
| 別的專案的來信 | 事實題派人唯讀查證後回；方向題等使用者 | 寄件人（終局狀態） |
| 寄給知識庫位子的故障回報（位子沒掛時） | 記進 progress；派代班補，或等位子掛上再轉 | [kb](../kb/README.md) |
| 位子先問的事：跨範圍、`--rm`、`install.py`、動活樹（第 6 題） | 自己能放行的回覆；要使用者授權的去問他 | 提問的位子 |
