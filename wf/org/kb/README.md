# 知識庫 `kb`

← [org](../README.md)｜地盤 [wf/ws/eca-aos/eca-aos-kb](../../ws/eca-aos/eca-aos-kb/README.md)｜筆記 [notes.md](../../ws/eca-aos/eca-aos-kb/notes.md)

**現況**：公司 WSL 11-23 沒掛；地盤與筆記在（11-22 在家機做過知識庫跟上範本瘦身、拿掉日期標記、回饋四題的提案）。沒掛時由負責人派代班，代班先讀這張卡與筆記，收工前把學到的寫回筆記。

## 職責

- **負責**
  - `proto8/knowledge/` 的內容。寫法照筆記裡使用者交代的五條（不寫日期註記、原話例外、改的句子不標記、中文映照版不碰、回饋的改法）；**規矩的正本在筆記**，這裡不重抄。
  - 範本或程式改了，知識庫跟上（步驟在筆記「範本改了，知識庫跟上」）。
  - `aos/troubleshooting.md` 的新條目：別人查出的故障寄來，查證過才寫（[規矩卡「回報怎麼寫」](../../workflows/common/rules-card.md)第 4 條）。
  - `aos/packs.md` 的每包字數表（量法在筆記）。
- **不負責**
  - 中文映照版 `proto8/knowledge-zh-md/`（使用者 11-22「kb-zn不用管」）。
  - 範本、程式、`wf/` 寫錯：回報負責人，不自己改。
  - 跑 `install.py`；對活的 daemon 下指令。
  - 要先問方向的改動：只出提案（放地盤的 `proposals/`、`drafts/`），不改知識庫。
- **Done when**：改的頁只寫核對過的事；交件有雜湊；回報列出改了哪頁哪句、拿不準沒改的、替使用者做的選擇。

## 讀寫範圍

約定，沒有強制力（[org「寫入範圍只是約定」](../README.md)）。

- **可以寫**：`proto8/knowledge/`（含那裡手寫的 `_index.json`）、自己的地盤。
- **唯讀**：`proto8/templates/`、`proto8/py/`、`proto8/lib/`、`proto8/docs/`（對事實用）；`wf/` 其他地方。
- **存檔就生效**：知識庫存檔當下活樹就在用（規矩卡「活樹旁九條硬規則」第 5 條），一頁一次寫完整。
- **暫存**：地盤的 `temp/`；commit 訊息檔放 repo 外。

## 交接

| 收到誰的什麼 | 做什麼 | 做完回給誰、信裡要有什麼 |
|---|---|---|
| 負責人的 `REQUEST`：哪個 commit 或哪幾頁 | 照筆記的步驟改，自己交件 | `DONE` 給負責人：雜湊、哪頁哪句、拿不準的 |
| [範本位子](../templates/README.md)的通知：範本交件了（附雜湊） | 對 `tools.json`、`cli.json` 的 diff，知識庫跟上 | `DONE` 給負責人，並告訴範本位子 |
| 任何人寄來的故障（症狀、原因、怎麼查、依據） | 查證後補進 troubleshooting；查不了的不寫 | `DONE` 或 `BLOCKED` 給寄件人 |
| 改之前要先問方向的題 | 出提案 | `NEEDS-USER` 給負責人，附提案路徑 |

發現範本、程式、`wf/` 的錯，寫在回報裡給負責人。

## 模型

- **身**：eca claude（範本 `eca-claude`）。級別：知識庫是所有 agent 讀的正本，不當簡單工作派 sonnet（提案）；11-22 在家機開的是哪一級沒查到。
- **同時幾個**：1 個（同一頁不能兩個人寫）。
- 蒐集與雜活可以自己開 Claude 子 agent，或掛[打雜工](../chore/README.md)。
