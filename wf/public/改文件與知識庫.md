# wf/public/改文件與知識庫 — 改寫必讀規矩檔、請新人照索引走、知識庫頁對程式

## 改寫必讀規矩檔：草稿夾、對照表、請沒看過表的人來對、一口氣換上

把舊條文改寫成「只寫現行做法」，或一次動好幾份全場必讀的規矩檔時，會撞三個坑：`wf/` 存檔當下全場就在讀，直接改現役檔會有一段時間是改到一半的版本；改寫的人自己做的「舊條文→新位置」表會漏（整條掉了、意思被改、照舊 HEAD 寫的草稿蓋掉別線剛加的條、把 AI 的轉述當成使用者原話）；草稿寫好到換上去之間，現役檔又被別線改了。

1. 子 agent 一律寫草稿夾（自己地盤裡的 `wf/ws/<上層>/<名>/temp/draft/`，不進 git），任務書寫明不准碰現役檔。
2. 改寫前全文先原樣抄進 `archive/`，用程式逐行比對跟 HEAD 一樣。
3. 做一張「舊條文→新位置」表，再請一隻**沒看過這張表**的審稿員自己從舊檔抓規矩句到草稿裡找。
4. 使用者原話用程式比對：把舊檔每個「」字串拿去新檔找，找不到的逐個看。只剩封存副本才有的原話，收進一節「已被取代的原話（留底）」。
5. 換上去當下：逐檔 `git log`（有新 commit 先併、封存副本重抄）→ 逐檔「cp 到暫存檔再 mv」一口氣換完 → `check_anchors.py` → 一個 commit。
6. 換完當成新來的 agent 照新文件實做一次（例：照短卡的字跑 claim、乾跑、交件）。

- **小改**（只動幾句）：python 小腳本 `str.replace` 精確舊句、`assert count == 1`、寫暫存檔再 mv；每批跑 check_anchors。審稿方一眼看得出只動了字。
- **偏好檔、鐵律**：先給 eca-aos 逐字看 diff 再交（抓到過使用者原話「不可以問我問題」被寫成「不追著問」）。

## 換全場共用的工具（commit_queue）：確認沒人持有、換完立刻三筆 dry-run

改 `wf/tools/commit_queue.py` 這種壞了大家都交不了件、存檔就生效的檔：確認 `holder.json` 是 `{}`；原檔與測試檔備份；寫暫存檔再 `mv`；換完立刻 import 並實測函式；用新佇列跑三筆 dry-run（一個該擋的、一個該收的、一個普通檔）。驗不過就換回備份。

## 文件對不對，請新人照索引走一遍來量

想知道「agent 進來查不查得到、要讀多少」：定十來個常見問題；請一隻沒看過這條線的 agent 從 `AGENTS.md` 與知識庫入口出發，只跟連結與索引走；每個開過的檔算整檔 bytes、每題獨立計；記走不走得到、有沒有互相衝突的答案。改完再請另一隻走一次比。

- 兩次要同樣的起點與量法，寫明讀的是 repo 那份還是活樹複本。
- 換模型（sol 對 Claude）挑的路不一樣，bytes 只能看大方向。
- 量「讀多少」和量「有沒有衝突」是兩種走法，分開做：只走到答案就停的那次看不出衝突，要把相關的檔全跟到才找得到。
- 沒有依據的數字目標不要訂（例：訂了 20 KB，入口三份必讀檔本身就超過）。

## 知識庫頁對程式：先分「會撞到的」和「只是沒寫的」

把知識庫（或任何說明頁）逐頁對程式時：

1. 蒐集時每條標種類（跟程式對不上／過時／漏寫／太長／重複）與把握（確定／猜），附程式的檔與行。
2. 「對不上、確定」的直接改，每條改前再回現在的程式核對一次（別線同時也在改程式，改完可能就又過時）。
3. 「漏寫」的不要全補：只補 agent 照頁做會撞到的（查不到的錯誤代號、會用錯的預設與互斥、會改結果的旗標）；純短名、`-j` 這類留一句「More flags: run X --help」。
4. 沒頁的工具不另寫頁：在索引加指標列，鍵寫成到那一段的路徑（例 `../mailbox.json#/tools`），`index_check.py` 會檢查解不解得到。
5. 交完請 eca-aos 派獨立審稿員抽核（見 [審查與實測](審查與實測.md)）。

## 改文件時的小坑

- **`check_anchors.py wf` 會掃到 `wf/temp/` 與各地盤 `wf/ws/…/temp/` 裡別線的草稿**：別線草稿有壞錨點時整個退 1。看輸出裡的路徑，不是自己的檔就照交、在回報寫一句。
- **知識頁有位元組上限**：補句子前先看頁還剩多少，補完超了就得縮同頁別的句子。
- **一行字串的 JSON 知識頁被兩線同時改，`git apply` 會失敗**：用 python 讀出字串，只換自己的段落再寫回，兩邊的字都保住。
- **wf 版和產品版有數字不同時，兩份都寫明差在哪**（例：看包 wf 版跟產品版工具數不同），不寫讀的人會以為有一份寫錯。
- **量數字要量對樹**：量測腳本的 `AOS_HOME` 寫死成暫存樹，量到的是暫存樹的舊說明。數字寫進文件前先確認量的是哪一棵。
- **批次改文件用非貪婪正則可能吃掉整段**：`.*?` 配上 `re.DOTALL`，如果終止字串在檔案更後面又出現一次，會從起點一路吃到那裡，整段被砍掉還被 commit。批次改完一定要看行數與章節數，`grep` 只能證明某段不在，不能證明別的還在。
- **`\b` 邊界在 `-Iinst/include` 這種字串上不成立**：`inst` 前面是 `I`（word 字元），所以 `\binst/` 匹配不到。批次替換路徑之後，`grep` 一次確認沒有漏網的。
- **`fix_moved_links.py` 同一份 moves.tsv 不能跑第二次**：檔已經在新位置時，它仍把「被搬的檔」的連結當舊位置解析，把對的連結改壞。rebase 之後別重跑整份；上游新進來的檔有舊連結，就只拿那幾個檔另做一份 moves 或手改。
- 搬檔、拆檔、資料檔的坑另見 [整理與拆檔](整理與拆檔.md)。
- **`scan.py` 印的「in N files」是有命中的檔數**，不是掃了幾檔；「0 files」不是沒掃到（工具見 [tools/scan](tools/scan/README.md)）。
