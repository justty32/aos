## 哪些改動活樹當下就吃到：實際查，不能用推的

結論寫在 [06「現況」](../workflows/dispatch/aos-teams/06-公司WSL活樹與任務書硬規則.md#現況)：11-18 S3 起活樹只跑 `$AOS_HOME/bin`、`$AOS_HOME/lib`（`install.py` 從 `py/`、`cpp/` 產的），改 `py/`、`cpp/` 存檔不會動到它，**在那份 proto8 跑 `install.py` 才換**；不經 install.py、活樹直接讀的是 `knowledge/`、`frontend/`；`templates/` 要重抄進樹。這幾類很容易搞反。要回答或放行某個改動屬於哪類時，別用推的：`command -v <指令>` 應該是 `$AOS_HOME/bin/<指令>`，Python 指令的入口是 `install.py` 生的幾行、插的是 `<家>/lib`（不是 `py/`）；`~/.local/bin` 還有舊連結的機器，`readlink -f` 看它指去哪。這屬於看活樹，**先請部長點名再查**（見下面「唯讀查看」）。

11-17 起不抄樹：樹裡的程式直接指 repo，換版本＝停 daemon、pull、`install.py`、重抄過時的範本抄本、重起（[06「停樹換檔的做法」](../workflows/dispatch/aos-teams/06-公司WSL活樹與任務書硬規則.md#停樹換檔的做法)）。「活樹的 `lib`／`templates`／`knowledge` 是複本、重抄才生效」、結果檔逐項寫「存檔即生效／要重抄」的生效表、`copy_tree.py` 留的 `.aos-source.json`，都是之前的舊做法（腳本封存在 [proto8/archive/aos-home](../../proto8/archive/aos-home/README.md)）。

## 在 repo 裡跑 install.py＝換掉活樹的執行檔與程式：要跑先回報，只試裝就抄到暫存夾

`python3 install.py` 把 C++ 執行檔與 Python 指令入口寫進 repo 的 `proto8/bin/`、把 `py/` 抄成 `proto8/lib/`（都先清空再填），`source $AOS_HOME/env.sh` 後 PATH 上的、活樹的工具與 agent 的格 import 的就是那份；清空到填好之間那幾秒，活樹叫到的指令與工具都不在。樹在跑時這樣做可以，風險使用者承擔（使用者 11-15「樹還在跑的時候不能在repo裏面編，我希望可以，這就是使用者自己承擔風險。或是編譯的時候走腳本，腳本會稍微檢查一下」）；動手前先回報調度者（06 第 5 條）。換樹不再換 C++，C++ 一律平常這樣換（使用者 11-15「好，就這樣改。」）；當時配的 `build.sh`（編在 repo 外、九支都編成功才用 rename 換進去、會警告哪些正在跑）11-17 封存在 [proto8/archive/tree-swap](../../proto8/archive/tree-swap/README.md)。只想編來測、不換：把原始碼抄到 `~/.aos/scratch/<線名-日期>/`，在那份的 proto8 跑 `python3 install.py`（只寫那份自己的 `bin/ lib/ include/`；使用者 11-15 裁「4.a」，不放 `~/code`；只重編幾支見 [pitfalls](pitfalls.md#暫存樹編-cpp-的-cmake-目標要用-_main)）。

## 換活樹直接讀的檔：備份、暫存檔改名、被 import 的先換、每換一檔就 import

11-18 S3 起改 `py/` 不會即時生效，這段只剩活樹直接讀的 `proto8/knowledge`、`proto8/frontend` 的既有檔（以前是 `proto8/cmd`、`lib` 的 `*.py`）：改到一半的檔會被正在跑的 agent 讀到；多檔之間順序一反，中間那一刻整支指令 import 不起來，而且是活的。

1. `git diff --quiet <base> -- 檔`，確認 repo 的檔還跟暫存樹的基準一樣；claim。
2. 原檔備份到 repo 外。
3. `cp --preserve=mode` 到同夾的暫存檔，再 `mv -f`，用 `cmp` 核對。
4. **多檔：順序寫死在腳本裡，被 import 的先換**（例 `entry.py → __init__.py → common.py → who.py → add.py → 測試 → 文件`）。每換一檔就跑：import 該模組、import 用到它的模組、`aos-agent --help`，一件失敗就停。整套先在 `git archive` 的乾淨複本上照同樣順序演一遍，輸出附在交件信。
5. 經 clean.sh 跑定向測試：從 HEAD archive 一份、把這幾檔的實際內容疊上去跑。能的話在暫存樹起自己的 daemon 實跑一次，看 stderr 是空的。
6. 新碼先放成新函式；接上舊路徑另外找部長放行（06 第 5 條）。

放行的人：自己把新檔跟 repo 現行檔 diff 一次，看檔頭 import 的名字在被 import 的檔裡有沒有；放行條件寫成「被 import 的先換、驗過名字都在，才換 import 它的」。審 diff 的人要問換檔順序。

## 唯讀查看活樹也要任務書點名；寫的界線照字面讀

為了查「哪份碼在跑」「有沒有人在用某變數」「新提示會不會誤報」想看活樹時，很容易順手越線：讀活樹 daemon 的 `/proc/<pid>/environ`（只列名字也算）、grep 活樹（`.stack`、`wf/tree/`、`~/aos-home`）的 `.env` 與 `daemon.json`、看活樹頂層與 `lib/` 清單、讀自己程序鏈的 `AOS_*`。06 第 1 條：唯讀查看只限任務書點名的。

- 要活樹的事實：開查前把要看的路徑一條條列給部長，點了名才看，或寄一句請頂層代查。查不到就寫「沒查到」，不要為了答完整再多看一處。06 第 9 條要的 pgrep 不算在內，照跑。
- 授權別人看活樹的檔，**路徑寫到檔**（點名「xiaosi/ 底下的 live.jsonl」，實際在 `xiaosi/claude/live.jsonl`，線照「點名位置沒有就不往別處找」回報，只好再補點名）。要寫進授權範圍的路徑先 grep 程式確認。
- 寫的界線比想像的寬：一行 CSS 也算寫活樹。授權範圍照字面讀：「准裝 v2.0」不含 v1 的修正。
- 暫存腳本開頭一律先清 `AOS_*`、PATH 拿掉 `~/.local/bin`，否則測試可能悄悄用到活樹在跑的執行檔。

## 查祕密有沒有擴散：值不落地、只印檔名和變數名

查 API key 這類值有沒有被寫進檔、log，或要看某個行程的環境時：

- 不要為了 `grep -F -f` 把值寫進 `/dev/shm` 這類檔：等於又複製一份，還得另外請使用者授權刪（授權只蓋題目寫到的那個檔，見 [user-zone-mail](user-zone-mail.md)）。也不把整份 env 傾印成檔，會帶出 API key。
- 在行程內比對只印檔名，或只比雜湊；`grep -l`，或 `sed` 只取等號左邊；看環境檔先濾掉含 KEY、TOKEN、SECRET 的行，只印變數名；再用 `git ls-files` 濾掉 repo 抄本，雜訊少很多。
- 不把整份環境變數寫進檔、log 或信（aos-teams 第 5 件）。

## 換樹當晚：pin 是 main 的一個 commit，不能跳過中間某一筆

當晚要把 main 換進活樹時：

- 「這個 commit 有問題就從今晚拿掉」做不到。只有兩條路：收件截止前修好或 revert；或把 pin 往前釘（之後的 commit 今晚都不換）。所以「要不要隨今晚進活樹」在 submit 之前決定，不想進就等 pin 釘完再交；收件前先跟各部講清楚。
- 一個 commit 同時改 C++ 和 `proto8/knowledge/`：換樹後活樹的知識庫會寫著執行檔還沒有的功能。跟管換樹的線講定那支執行檔同時換上（C++ 與 Python 都在 repo 的 proto8 重跑 `python3 install.py` 換；`build.sh` 11-17 已封存；見 [06「停樹換檔的做法」](../workflows/dispatch/aos-teams/06-公司WSL活樹與任務書硬規則.md#停樹換檔的做法)），或等 pin 釘完才 submit。
- 線比估的早交時，立刻想「它會不會被今晚的 pin 帶到」，馬上通知換樹的線加預演和換後驗。
- 管換樹的線：定一個最後收件時刻，往回推全套測試、預演、送審要的時間。換法照 06「停樹換檔的做法」：11-17 起不抄樹、換版本＝停 daemon、pull、`install.py`、重抄過時的抄本、重起；舊腳本封存在 [proto8/archive/tree-swap](../../proto8/archive/tree-swap/README.md)。
