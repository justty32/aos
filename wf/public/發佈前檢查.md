## 照字實跑文件：從頁面本身抽指令來測，不另寫測試腳本

- **適用**：寫給外人照著打的文件（開始用、README Quickstart、教學），要確定照抄就會通。
- **做法**：
  1. 用 [tools/doc-run](tools/doc-run/README.md) 的 `run-doc.py PAGE.md REPO_URL OUT.sh`，把頁面裡的 ```` ```bash ````／```` ```sh ```` 區塊依序抽成一支腳本；`<REPO_URL>` 換成本機鏡像（`file://…`）。測的就是讀者會打的那幾行。
  2. 在乾淨複本裡跑，清掉所有 `AOS_*`（用 bash 逐一 unset，同 [patch-and-commit「環境沒清會假綠」](patch-and-commit.md)），`HOME` 指到暫存夾裡的空資料夾。
  3. 跑完看三件事：輸出和頁面上寫的「預期」一致；暫存夾裡沒有留下行程（掃 `/proc/*/cwd`）；`HOME` 底下多了什麼，拿來對頁面上「會寫哪裡」那句。
  4. 給讀者看的預期輸出放 ```` ```text ```` 區塊，不會被抽到，指令和預期輸出可以放一起。只想展示、不想被執行的指令不要放進 bash 區塊。
  5. 同一段指令抄在好幾頁（README、宣傳頁）時，指定照字實跑的那頁當正本，用 `check-cmds.py 正本.md 抄本…` 檢查抄本每一行指令都在正本裡。
- **實跑抓到的**：
  - 頁面寫「不寫家目錄」，實跑發現建置時 vcpkg 寫了 `~/.cache/vcpkg`。
  - 「再玩一次」要跑第二輪才知道得換示範夾。
  - 疑難排解裡「找殘留行程」的 `/proc` 迴圈，站在示範夾裡跑會列出自己的 shell，讀者會以為有殘留；要先 `cd ~`。
  - 一條準備投的意見（「停樹後表上還寫 running」）跑了才發現前提錯（其實是 sleeping），沒投出去。
  - check-cmds 第一次跑就抓到 README 多了 `sleep 2`、宣傳頁少了 `nohup`。
- **驗過**：ok-release 11-14。「開始用」v1 跑兩輪、v2 一輪，README 兩輪，安全頁、疑難排解各一段，抓出 4 個文件錯。
- **出處**：`proto8/thinking/2026-11/14/release-1114/08-批0實測.md`；原始工具 `wf/temp/ok-release/bin/run-doc.py`、`wf/temp/ok-release/drafts/tools/check-cmds.py`
- **投稿**：ok-release（`照字實跑文件.md`，附 check-cmds.py）

## 無頭瀏覽器截圖看頁：有動畫的頁面要給虛擬時間

- **適用**：agent 寫了 HTML 頁（宣傳頁、草稿站），要自己先看一眼再交人。
- **做法**：
  ```
  google-chrome-stable --headless=new --screenshot=out.png --window-size=1280,2400 --virtual-time-budget=3000 file:///<頁面的絕對路徑>
  ```
  - 一定要加 `--virtual-time-budget`。不加的話，有淡入動畫的頁面會截到動畫開頭，整頁看起來褪色，容易誤判成配色有問題。
  - `--window-size` 的高度設長一點才看得到整頁；看手機版把寬度改成 390。
  - 截圖放暫存夾或紀錄夾，交人時附路徑。圖片要公開的話也要過下一條的掃描（看 metadata）。
- **驗過**：ok-release 11-14，兩版宣傳頁各截過圖；宣傳頁 B 第一次沒加虛擬時間，截到褪色的樣子。
- **出處**：`proto8/thinking/2026-11/14/release-1114/06-草稿/v1/*.png`
- **投稿**：ok-release（`無頭瀏覽器截圖看頁.md`）

## 掃個人值（帳號名、主機名、email）要比字邊界

- **適用**：發佈前掃要公開的檔案，看有沒有帳號名、主機名、email、金鑰。
- **做法**：
  - 用 [tools/scan](tools/scan/README.md)：`python3 -I scan.py --private 個人值清單.txt 要公開的檔或夾…`，沒命中退 0、有命中退 1、參數錯退 2。它照下面幾點做好了。注意它每筆會印出命中的那一行，輸出本身就含個人值，不要貼進報告。
  - 帳號名、主機名這種短字串，用「不分大小寫＋字邊界」比，另外也比 URL 編碼後的樣子。只比子字串的話，短主機名會命中一般英文字中間的同樣字母，幾百筆誤報，真的反而看不到。
  - 個人值清單放在 git 不收的地方（例如 `wf/temp/<線>/`，`.gitignore` 已排除 `wf/temp/`），不 commit，也不抄進報告。報告只寫「命中幾筆、在哪個檔」。
  - 判斷二進位檔用「不是 UTF-8 或含 NUL」，不要看副檔名，不然 `.cpp` 之類會被跳過或誤判。圖片另外看 metadata（PNG 的 text 區塊、JPEG 的 EXIF、SVG 編輯器留下的欄位）。
- **驗過**：ok-release 11-14，全倉掃描。scan 工具另由頂層整理時在暫存夾用假檔實跑（各規則都命中、字邊界有效、退出碼 0／1／2 對），沒測過的寫在工具 README。
- **出處**：工具收在 [tools/scan](tools/scan/README.md)（原檔 `wf/temp/ok-release/drafts/tools/scan.py`）；`proto8/thinking/2026-11/14/release-1114/09-掃描報告-1.md`
- **投稿**：ok-release（`個人值掃描要比字邊界.md`；第五批補投 scan 工具夾）
