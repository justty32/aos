## eca 定義關掉 Claude Code 的自動記憶

用 eca-claude 範本開的 eca，工作區放在某個 git repo 底下（尤其是別隊的 repo、或 repo 裡的 `tmp/…`）時：Claude Code 的記憶夾照工作區的 `git rev-parse --show-toplevel` 算，eca 會載入那個 repo 的記憶，系統提示也會叫它寫進去：讀到別隊的舊記憶，還可能寫髒它（工作區在 submodule 根時則另起一份空的）。

- **做法**：在定義的 `cli.json` 加 `"settings": {"autoMemoryEnabled": false}`。aos 會把它併進自己那個 `--settings`（Claude 命令列上兩個 `--settings` 只有最後一個算，所以不要在 flags 裡自己寫 `--settings`，cli.json 也會擋）。
- **驗法**：開一個新 session，在它的 transcript 裡 `grep -c "persistent file-based memory"`，要是 0（沒關的對照組是 3）。

## 換定義用 `ctl set-def`，不要 rm 再 add

一隻 agent 已經在表上，要換它的定義（system、工具、腦），又想留住它的 history、queue、mailbox 時：`aos-agent ctl set-def NAME DEF`。stack（history、queue、mailbox）、工作區、limits、auto_restart 都照舊，只換定義。

- 不帶 `--restart`：daemon 下一次起它才用新定義；在跑的話照跑舊的，會印一行提醒。agent 也可以對自己下（不帶 `--restart`）。
- 帶 `--restart`：關畫面、這一輪結束後停、用新定義起來。不能用在自己身上。
- stack 裡有它自己的工具檔（`aos-agent tools add`／`rm` 做的）的話，那份照舊蓋過定義的，set-def 會提醒；用 `aos-agent tools ls` 看、`aos-agent tools reset` 清。

坑：

- 用 `--envs` 加進來的 agent 不能 set-def（ArgumentsBad），而 `subagent add` 掛的子一律帶 envs，所以 subagent 掛的子都不能 set-def；只能 `ctl rm` 之後 `ctl add --envs … --stack <它原本的 stack> DEF`，stack 照樣留著。
- set 了還沒起、daemon 自己先重啟，表上會回到舊定義。換完就 start 它，或用 `--restart`。

## 用 agent_def new 複製定義後，把 README 重寫短

用 `agent_def {"op": "new", "template": …}` 或 `{"from": …}` 把範本、別人的定義複製到自己的地方時：new 是整夾照抄，README 裡指向原處旁邊檔案的相對連結複製過去全斷。複製完把 README 縮成幾行（這份定義做什麼、從哪裡抄來、跟來源差在哪），再跑 `agent_def {"op": "check", "path": …}`，要回 `{"problems": []}`。check 不查 README 的連結，連結要用自己的連結檢查跑一次。
