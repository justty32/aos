# wf/public/交件與放行 — 先交小修、放回 repo、部長放行、共用計數、封存搬檔

← [wf/public](README.md)｜commit-request 的正式用法在 [07「commit」](../workflows/dispatch/aos-teams/07-預設流程與agent-fsm.md#commit)；claim、DescMissing、搬補丁、驗收全套見 [patch-and-commit](patch-and-commit.md)

## 工作樹有未交的改動，又要先交一個小修

同一個檔上有還不能交的工作版，但有一行小修要先進 main（什麼都不刪）：把工作版存到暫存夾 → 用「HEAD 版加小修」蓋上去，只交這一檔 → 再蓋回「工作版加小修」。交完用 `git show` 確認只有那幾行。

## 把檔複製進 repo：暫存名再改名，交前確認底之後沒人動

- `cp S/f f.<線>-tmp && mv f.<線>-tmp f && cmp S/f f`。
- 交前 `git log <底>..HEAD -- 檔`，或逐檔跟 HEAD 比對、不一樣就擋（別人的 commit 會讓暫存樹落後）。施工複本落後時單檔可用 `git merge-file -p <我的> <當時的 base> <現在的 HEAD>`（base 用 `git show <archive 的 commit>:檔`）；整批的做法見 [patch-and-commit](patch-and-commit.md)。
- 跟別線先講好「你的檔／我的檔」；同時要動同一檔就講好誰先交、誰後疊，不混進同一個 commit。
- 會即時生效的檔（`proto8/cmd`、`py`、`lib/agent`）另有備份與順序的規矩，見 [活樹旁邊](活樹旁邊.md)。

## 放行 commit：看三樣；放行的是看過的那一版

部長（或任何有放行權的人）收到「請放行」時：

1. 不只讀信裡的摘要，自己看三樣：`git diff --no-index -- <repo 檔> <暫存複本的檔>` 看實際差異；`grep -E '^(Ran|OK|FAILED|FAIL:|ERROR:)' <log>` 看測試結果行；改到即時生效的檔再 `diff <(git show HEAD:檔) 備份` 確認備份等於 HEAD。
2. 放行信寫明版本（哪個暫存夾的哪一份），並寫三樣：我看過什麼、沒看過什麼、交完要回我什麼（hash、備份路徑、輸出尾段）。hash 回來自己 `git show --stat` 核一次再記帳。
3. 偏好檔、鐵律的改動，部長逐字看 diff 再上交頂層，不自己放。

線這邊：放行後還要改，先回一句、把差異再給放行的人看。已經交了就對那個 commit 的 `git archive` 乾淨複本補跑全套。

## 兩線同時改同一份計數：後交的以交件當下的 HEAD 重算

有合計數字的共用檔（例：`wf/advices/README.md`）：先 claim，被佔著就 `clock_register +10m` 叫醒自己再試。拿到後看 `git log -3 -- <那夾>`，數字照各檔實數重算，不照寄信時預先算好的數。放行的人事先講明「先 claim 的先交，後交的以當下 HEAD 重算」。

## 封存或搬檔：預設留指標頁，不帶 `--rm`

真的 `mv` 走之後，交件要把舊路徑列進 `commit-request submit --rm`；帶 `--rm` 的指令 agent 的權限模式會整條擋下，只能請使用者親手跑，這段時間工作樹是半套狀態、別線也動不了那些檔。所以：

1. **預設留指標頁、不帶 `--rm`**：全文抄成 `archive/` 底下的新檔，原路徑改成幾行的指標頁；交件只有 `--files`，自己就交得進去，也合使用者「不刪」的偏好。
2. **只有使用者明說要移除舊路徑**才真的搬走：動手前先跟部長講、預先排好請使用者親手跑；交之前逐一確認每個舊路徑在 `archive/` 都有對應的檔。
