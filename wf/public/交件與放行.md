## claim 的幾個坑

- **適用**：用 `commit-request claim`／`submit`。
- **坑與做法**：
  - **claim 檔案本身，不要 claim 資料夾**：claim 資料夾 submit 照樣成功，但會出 `not claimed` 警告。submit 後 claim 就用掉了，同一個檔下一批要重新 claim。
  - **中文路徑別從 `git status` 直接抄**：抄到的是轉義過的字串，claim 存成那串、蓋不到真檔。用 `git -c core.quotepath=off status`；claim 後看一眼 `commit-request claims`。
  - **設計階段不要先 claim 程式檔**：任務書寫「施工開始才 claim」。設計階段 claim 會擋住同一批檔上正在施工的線（ok-pilot 照派工信 claim 了 `idle.py` 等四檔，ok-fsm 正要改，只好請它釋放）。
  - **用完沒改就放掉**：`proto8/knowledge/aos/_index.json` 被 claim 三個多小時、其實沒改動，別線的一格因此晚交。
  - **「會動某檔」不等於「claim 了某檔」**：轉述給別部或使用者之前，自己跑 `commit-request claims` 看；回別部時直接貼線報的 claim 清單（head-tools 把一句「會動 llm_rules.py」當成 claim 寫進專區信，事後向三方更正）。
  - **檔名叫 `_index.json` 的**：知識庫以外的是生成物，不收、由排隊重生；知識庫手寫的 `_index.json` 從 f446f3d86 起才交得進去。日索引的 README 是共用檔，不能放 `--files`，用 `--op day_upsert`（否則 `RequestBad`）。
- **驗過**：ok-llmk2（`28c401e57` 那次出警告）、ok-kf、head-tools（信 01794634073536789037.2905115.2265918、01794636957639168513.470906.2554328）、head-front、head-comm、ok-onboard，都是 11-14。
- **出處**：`wf/temp/{ok-llmk2,ok-kf,head-tools,head-front,head-comm,ok-onboard}/wrapup-1114/經驗.md`；中文路徑那條另見 [advices 指令與工具](../advices/指令與工具.md)

## 工作樹有未交的改動，又要先交一個小修

- **適用**：同一個檔上有還不能交的工作版，但有一行小修要先進 main。
- **做法**（什麼都不刪）：把工作版存到暫存夾 → 用「HEAD 版加小修」蓋上去，只交這一檔 → 再蓋回「工作版加小修」。交完用 `git show` 確認只有那幾行。
- **驗過**：ok-onboard 11-14，bddfbcb9d。
- **出處**：`wf/temp/ok-onboard/wrapup-1114/經驗.md`

## 把檔複製進 repo：暫存名再改名，交前確認底之後沒人動

- **適用**：把暫存樹做好的檔放回 `~/repo/aos`。
- **做法**：`cp S/f f.<線>-tmp && mv f.<線>-tmp f && cmp S/f f`；交前 `git log <底>..HEAD -- 檔`，或逐檔跟 HEAD 比對、不一樣就擋（別人的 commit 會讓暫存樹落後，例 246d4aa49 改了 add.py）。施工複本落後時單檔可用 `git merge-file -p <我的> <當時的 base> <現在的 HEAD>`（base 用 `git show <archive 的 commit>:檔`）；整批的做法見 [patch-and-commit](patch-and-commit.md)。跟別線先講好「你的檔／我的檔」，同時要動同一檔就講好誰先交、誰後疊，不混進同一個 commit。
- **會即時生效的檔**（`proto8/cmd`、`py`、`lib/agent`）另有備份與順序的規矩，見 [活樹旁邊](活樹旁邊.md)。
- **驗過**：ok-astra、ok-limits（`ws/phase1/land2.sh`）、ok-kmsg（`wait.py` 同一小時三條線改，都沒衝突）11-14。
- **出處**：`wf/temp/{ok-astra,ok-limits,ok-kmsg}/wrapup-1114/經驗.md`

## 放行 commit：看三樣；放行的是看過的那一版

- **適用**：部長（或任何有放行權的人）收到「請放行」；線在收到放行之後。
- **做法（放行的人）**：
  1. 不只讀信裡的摘要，自己看三樣：`git diff --no-index -- <repo 檔> <暫存複本的檔>` 看實際差異；`grep -E '^(Ran|OK|FAILED|FAIL:|ERROR:)' <log>` 看測試結果行；改到即時生效的檔再 `diff <(git show HEAD:檔) 備份` 確認備份等於 HEAD。
  2. 放行信寫明版本（哪個暫存夾的哪一份），並寫三樣：我看過什麼、沒看過什麼、交完要回我什麼（hash、備份路徑、輸出尾段）。hash 回來自己 `git show --stat` 核一次再記帳。
  3. 偏好檔、鐵律的改動，部長逐字看 diff 再上交頂層，不自己放。
- **做法（線）**：放行後還要改，先回一句、把差異再給放行的人看。已經交了就對那個 commit 的 `git archive` 乾淨複本補跑全套。
- **驗過**：head-tools 11-14 七次放行（兩次因此多問一句才放；38271da3b 比審的多了兩處，補跑 lib/tests 與 agent-fsm 兩整夾）；head-core 14 個 commit 都核，其中一筆 25dd03d86 是線沒先問就交的，靠核帳才對上；head-front 逐字看抓到一次力道被改輕（879cee23e）；ok-fsm 之後三個 commit 都照做。
- **出處**：`wf/temp/{head-tools,head-core,head-front,ok-fsm}/wrapup-1114/經驗.md`；信 01794635908970994674.4071130.2449462；7ce38e7cf、3b02a41c4

## 兩線同時改同一份計數：後交的以交件當下的 HEAD 重算

- **適用**：`wf/advices/README.md` 這類有合計數字的共用檔。
- **做法**：先 claim，被佔著就 `clock_register +10m` 叫醒自己再試。拿到後看 `git log -3 -- <那夾>`，數字照各檔實數重算，不照寄信時預先算好的數。放行的人事先講明「先 claim 的先交，後交的以當下 HEAD 重算」。
- **驗過**：ok-limits 0ee233df4 與 ok-sec 714aba179 同時改同一列，沒有算錯（寄信時的底是 22/4，交件時已變成 16/7）。

## 封存或搬檔：預設留指標頁，不帶 `--rm`

- **適用**：要把一批現役檔封存進 `archive/`（或任何搬檔），再用 commit-request 交。
- **坑**：真的 `mv` 走之後，交件要把舊路徑列進 `commit-request submit --rm`。帶 `--rm` 的指令，agent 的權限模式會整條擋下（Claude Code 的 don't ask 模式；11-14 線庫 ok-kb 和頂層 repo-aos 都被擋），只能請使用者親手跑。檔已經搬了、還交不進去的這段時間，工作樹是半套狀態，別線也動不了那些檔。
- **做法**（頂層 11-14 定，寫在 [STRUCTURE「archive 規則」](../STRUCTURE.md#archive-規則)）：
  1. **預設：留指標頁，不帶 `--rm`**。全文抄成 `archive/` 底下的新檔（第一行加封存檔頭），原路徑改成幾行的指標頁：為什麼停用、現在怎麼做、全文在哪。別處連進來的錨點在指標頁補 `<a id="…">`。交件只有 `--files`，自己就交得進去，也合使用者「不刪」的偏好。代價是夾裡多一份短檔。
  2. **只有使用者明說要移除舊路徑**，才照 97cda3435、10a75ac53 真的搬走：`mv` 之後 `--files` 列新路徑、`--rm` 列舊路徑，git 會認成改名。這種交件 agent 跑不了，動手前先跟部長講，預先排好請使用者親手跑；交之前逐一確認每個舊路徑在 `archive/` 都有對應的檔。
- **驗過**：ok-kb 11-14。做法 1：c913897a6 把 `dispatch/aos-teams/04-進度回報.md` 改成指標頁、改寫前全文抄進 `dispatch/archive/`，只帶 `--files` 交成。做法 2：10a75ac53（封存 hackathon、workshop）卡在 `--rm`，最後由使用者親跑交成。
- **出處**：`proto8/thinking/2026-11/14/kb-1114.md`；698fa6d94（STRUCTURE 的 archive 規則）；`wf/temp/head-front/wrapup-1114/經驗.md`
- **投稿**：ok-kb（`wf/temp/ok-kb/to-top/05-封存搬檔的兩種做法與public-README的返回連結.md` 第一節）
