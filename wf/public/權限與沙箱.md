# wf/public/權限與沙箱 — 換 uid、sudo 身分層、cgroup 的測法與坑

← [wf/public](README.md)｜跑測試前清環境的規矩見 [06 第 2 條](../workflows/dispatch/aos-teams/06-公司WSL活樹與任務書硬規則.md)

三條共通的一點：**要給別的 uid 用的暫存夾放 `/tmp`，不要放家目錄**。家目錄通常是 0700，換過去的 uid 連走都走不進去，結果全是 Permission denied，量不到你要量的東西。

## 免 root 做跨 uid 實測（subuid）

要驗「換成別的 uid 之後，碰不碰得到某個檔、殺不殺得到某個行程」，又不想用 sudo、不想建帳號時：

1. 先確認機器有 subuid：`grep $USER /etc/subuid /etc/subgid` 要有一行（形如 `<你>:100000:65536`），另外要有 `newuidmap`、`setfacl`。
2. 換成一個 subuid 跑一條指令：`$AOS_HOME/bin/aos-asuser [--group sub:G] sub:N -- 程式`。真號＝起點＋N－1，例如 sub:5＝100004。要先在那份 proto8 跑過 `install.py`（指令入口在 `bin/`）。
3. 要當「內圈 root」改 subuid 的檔（chown 給它、設 ACL 讓自己能寫）：`unshare --map-users=1:100000:65536 --map-groups=1:100000:65536 --map-root-user bash -c '…'`。ns 裡的 0 就是你自己，1..65536 是 subuid。
4. 起任何東西都經一支 bash 腳本，先清掉 AOS_*（06 第 2 條）。背景行程記下 pid，用 SIGTERM 收；kill 之前先 `readlink /proc/<pid>/cwd` 確認是自己起的。

坑：

- 在 ns 裡 `id -u` 印的是 N，不是真號；在 ns 裡 stat 別人的檔會看到 65534。要比對真號，從外面看。
- `pwd.getpwuid()`、`getpass.getuser()` 在 subuid 裡會丟 KeyError（/etc/passwd 沒有那個號）。
- 用 mkstemp 建的 0600 檔會把 ACL 的 mask 壓成 `---`，使用者的 ACL 等於失效。要救就跑 `aos-asuser --fix --recursive 路徑`。

## sudo 身分層的三個坑（NOPASSWD 換成低權限帳號）

用 sudo NOPASSWD 規則換成某個低權限帳號跑東西（例如 aos-sandbox 的 aos-run 身分層），或在那個帳號共用的資料夾底下建檔時：

- **坑一：`sudo -n -l 指令` 判斷不了「免密碼准不准」**。它只看准不准，不看要不要密碼；只要你另外有一條要密碼的 `(ALL) ALL`，查「換成 root」也回 0。要知道准不准，就真的跑一次無害的指令：`sudo -n -k /usr/local/bin/s6-setuidgid aos-run /usr/bin/true`。退 0 才是准；不准的話 stderr 印 `sudo: a password is required`、退 1。
- **坑二：一律帶 `-k`**。`sudo -n` 遇到還沒過期的憑證（剛打過密碼）會直接放行，這時參數若被換成 `root` 就成了提權。`-k` 跟指令一起用時不看快取、也不更新快取，只剩 NOPASSWD 規則能放行。再加一道：換身分前先 `pwd.getpwnam` 查帳號，uid 或 gid 為 0 的一律拒絕；帳號名先過格式檢查，免得 `--`、`-x`、換行混進 argv。
- **坑三：共用資料夾的 setgid 會被自己的 chmod 清掉**。例：`/srv/aos-run` 是「我:aos-run 2770」，但我不在 aos-run 群組。群組外的人對目錄 chmod，kernel 會清掉 setgid，之後新建的檔變成我自己的群組，aos-run 讀不到；我也 chgrp 不到自己不在的群組。做法：底下只 mkdir、不 chmod，讓子目錄沿用 setgid 帶下來的群組；umask 022 建出來是 2755，要給對方寫的那層再 `chmod g+w`。根治：把自己加進那個群組（`usermod -aG`，重新登入才生效）。
- **小點**：sudo 會把 PATH 換成 secure_path、清掉環境，鏈上每一支都寫絕對路徑。換過去的帳號走不進 0700 的家目錄，連「設定檔所在的資料夾」也算；測試要真的換身分，暫存夾放 `/tmp`、權限 0755。

## 用 transient scope 測 cgroup v2

在家機（systemd user session）測 cgroup v2 的程式（記憶體、pids 上限、cgroup.kill、委派），又不想留下永久 unit、不想改 user slice 時（範例：`proto8/cpp/aos-daemon/tests/test_cgroup.py`）：

- **起法**：`systemd-run --user --scope --collect -p Delegate=yes -p TimeoutStopSec=2s --unit=<前綴>-<隨機> -- <程式>`。屬性名寫 `TimeoutStopSec`（`TimeoutStopUSec` 是 D-Bus 的名字，命令列上報 `Unknown assignment`）；`--collect` 讓失敗的也收掉，不留 failed unit。
- **收尾**（包成一個 helper 放進 addCleanup）：停掉程式 → 對 scope 的 `cgroup.kill` 寫 1 → `systemctl --user stop <unit>` → `systemctl --user reset-failed <unit>`（沒有也不算錯）→ 確認 `list-units --all` 裡已沒有它。
- **家機上的事實**：
  - 有 swap 時只設 `memory.max` 不會 OOM，要一起寫 `memory.swap.max=0`。
  - cgroup v2 不准內部行程：要開 subtree_control，自己得先搬進子格，不然 EBUSY。控制器要逐層開。
  - `cgroup.kill` 是非同步的，rmdir 前先等 `cgroup.events` 出現 `populated 0`。
  - 不帶 Delegate 的 scope 在家機上一樣可寫，拿它測「做不到」不會失敗。要造出一定失敗的前提：先搬進沒開控制器的子格；或在 scope 裡先留一支 `sleep &`，讓開 subtree_control 時 EBUSY。
- **fork 炸彈類測試**：用 python 的 `os.fork()` 迴圈接 `BlockingIOError`。不要用 bash 開背景行程：bash 遇到 EAGAIN 會退避 1+2+4+8 秒，測試會卡住。
- **要從 daemon 表上讀結果的例子**：主行程要以非 0 結束（例如退 3）或被訊號停掉；退 0 的列可能被直接收掉，讀不到。
