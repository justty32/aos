# wf/public/建置與相依 — 把 C++ 庫匯出給外部用時的三個坑：私有相依、vcpkg 補洞、漏標 AOS_API

← [wf/public](README.md)｜暫存樹編 impls 的 make 目標、乾淨複本怎麼跑見 [pitfalls](pitfalls.md)

## 私有相依會偷偷變成使用者的義務：手寫匯出的 target 要剝掉 `$<LINK_ONLY:dep>`

`target_link_libraries(x PRIVATE dep)` 會在 `INTERFACE_LINK_LIBRARIES` 留下 `$<LINK_ONLY:dep>`，匯出之後使用者的 `find_package(aos)` 就得先找得到 `dep`——即使它是 header-only、即使符號全被 hidden 蓋掉。症狀是使用者在沒有 vcpkg 的環境 configure 直接失敗。手寫 target 時要記得剝掉。

## 外部消費測試沒有 `env -u VCPKG_ROOT` 等於白測

有 vcpkg 在的話，本來會失敗的相依問題會被它悄悄補上，問題留到使用者手上才爆（上一節那個坑就是這樣被漏掉的）。外部消費測試一律 `env -u VCPKG_ROOT` 跑。

## 公開標頭漏標 `AOS_API`：編譯期不會爆，連結時才找不到符號

編譯過、`#include` 也過，連結時才找不到符號，而且通常是外部使用者先撞到；自己在 repo 裡跑測試不一定會發現（測試若連的是 OBJECT library 就繞過了可見度）。改公開標頭時逐一看新函式有沒有標 `AOS_API`。
