# wf/public/整理與拆檔 — 封存搬檔、拆檔、資料檔、多 repo 連結檢查的坑

← [wf/public](README.md)｜規矩在 [tidy](../workflows/tidy/README.md)、[data-files](../workflows/common/data-files.md)、[STRUCTURE「archive 規則」](../STRUCTURE.md#archive-規則)；封存預設留指標頁見 [patch-and-commit](patch-and-commit.md)；批次改字的正則坑見 [改文件與知識庫「改文件時的小坑」](改文件與知識庫.md#改文件時的小坑)；派工人的坑見 [派線與任務書](派線與任務書.md)

## 拆檔前先 grep 誰錨定它：被錨定的標題原文留在入口

拆檔最常見的破壞是**別處的 `#錨點`**。拆前先 `grep -rn '<檔名>#'`，被錨定的標題原文保留在入口；拆完跑 `check_anchors.py`。

## 目錄改名會留正文引註殘留：另外 grep 舊目錄名

`x.md:48` 這種正文引註連結檢查抓不到，目錄改名後要另外 grep 舊目錄名。

## 改寫器與檢查都要跳過 code fence

` ```markdown ` 圍籬內可能刻意放「壞」連結當測試字串；連結改寫器與檢查都要跳過 code fence。

## archive 准動什麼，交接書要明說

線會把「archive 不維護內部連結」讀成「archive 不能動」而卡住。交接書寫明：archive 內只准動指向現役檔的「取代者」連結，且 `archive/README.md` 只准**追加**列（規矩在 [STRUCTURE「archive 規則」](../STRUCTURE.md#archive-規則)）。

## 名冊、領地登記這種表格類活檔：規則段留在活檔、只搬歷史；狀態欄不可信

表格裡的「狀態」欄不可信，判準改用 `wf/progress.json` 或明確給出的現役清單作證據；交接書要直接給出證據，否則線會「不敢猜」留一半。

## 「不搬現役目錄」跟「清指向 archive 的連結」會在同一批檔上打架：驗收只擋 rename／delete

驗收命令只擋 rename／delete，不擋 modify：`git diff --cached --name-status -M <dir>/ | grep -v '^M'`。

## 資料夾大小、檔數用 `ls -A` 看

資料夾可能有 `.` 開頭的隱藏檔；用 `ls -A`，否則大小統計也可能漏掉。

## 線報告裡的「需要裁示」要寄使用者專區，不能只留在回報裡

寄法 `aos-user send`（規矩在 [common/user.md](../workflows/common/user.md)，寄信的坑見 [user-zone-mail](user-zone-mail.md)；進度記在 [progress.json](../progress.json)、標「等使用者」）。

## 入口壓在 8192 邊緣：改字前先 `wc -c`，找超標的用 `find -size +8192c`

入口壓在 8192 邊緣時再改一個字就爆；改字前先 `wc -c`。`wc -c … | awk '$1>8192'` 會被 total 行騙，用 `find -size +8192c`。

## `link_columns` 只列整格是相對路徑或單一 md 連結的欄

把散文欄（`body`、`理由`、`機制`）或機外路徑欄列進 `link_columns`，`tabledb.py check` 查斷鏈時會把整格當路徑驗、報大量假斷鏈；散文裡的 md 連結所有欄本來就會掃，不必標。

## 給人讀的總覽表不抽 json

README 能力表、tools 說明表這類給人讀的總覽表不是記錄表，不抽 json；判準是「一列一個要去的地方／要知道的事」對上「一列一筆同構記錄」（契約在 [data-files](../workflows/common/data-files.md)）。

## 用空行把清單切塊躲 `find_big_lists.py` 的門檻不算解

它會把單一空行分隔的塊併起來。導航清單加 `<!-- wf-nav -->`，同質記錄抽資料檔。

## `grep -c` 接在不存在的腳本後面會印 `0` 假通過

驗收命令要在腳本所在 repo 根跑，或先 `test -f`。

## 多 repo 的專案：連結檢查與檢查工具各掃各的

這幾條是 aos 還是 `simple_tools` 的 submodule 時踩的；aos 現在是獨立 clone、沒有子 repo（[dev-env](../workflows/dev-env.md)），整理多 repo 的專案時才用得上。

- 母 repo 的全庫連結檢查工具可能吃**檔案**路徑不吃目錄、且只掃母 repo 追蹤的檔；子 repo 內部用它自己的檢查，全庫檢查由調度者在母 repo 根跑。
- 子 repo 自己的檢查不抓跨 repo 的錨點，母 repo 根的全庫檢查才抓。
- 母 repo 的檢查工具用 `.` 會遞迴掃進所有子 repo，數字會隨別條線在動；母 repo 自己只掃自己那一份。
