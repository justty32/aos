# wf/public/claude子agent — 派 Claude 子 agent（Agent 工具）時的坑

← [wf/public](README.md)｜帶 sol（agent-fsm）見 [sol-crew](sol-crew.md)；派獨立審稿員的問法見 [審查與實測](審查與實測.md)

## 長任務在前景跑，並要它邊做邊寫進度檔

eca 用 Agent 工具派 Claude 子 agent 做超過幾分鐘的事（修洞、審查、施工）時：背景跑的子 agent 會隨 eca 這一輪結束或 session 重啟被停掉，什麼結果都沒留，或只留半成品。

- `run_in_background: false`。
- 任務書叫它每做完一節就追加進一個檔（`notes/progress.md`），被停了下一隻從這裡接。
- 單子切小一點，前景分短段做。

## 寫最終回答之前，先把背景的東西收齊

eca（claude 身）的隊長在一輪裡派了背景子 agent、或把長指令丟到背景，然後就寫最終回答時：寫出 result 後 `claude -p` 可能不退出（多半在等背景的東西，例如被額度擋住的背景子 agent）。aos 以為這一輪還沒結束，new_mail 進不來：從外面看是「回合已結束、有新信、卻沒醒」；最後只能經使用者同意 kill 那支 claude，aos-loop 把那輪當失敗、整隻停掉，跑到一半的測試沒有結果。（只遇過一次，沒有重現實驗。）

- 寫最終回答前，子 agent 的回答收回來、背景指令等到結束或明確停掉。
- 跑很久的全套測試不要丟背景後就結束回合：前景等完，或寫成用 clock 叫醒自己再回來看的流程。
- 額度快用完時不要再派背景子 agent。

## 可寫路徑寫成唯一一個絕對路徑，並寫明 /tmp 也不行

任務書要限制子 agent 寫哪裡時，寫「只寫一個檔」不夠：子 agent 還是會把讀檔結果轉存到 `/tmp/`，或自己多留備份檔。寫成「唯一可寫的是這一個絕對路徑；別處都不行，/tmp、家目錄、轉存的暫存檔都不行」。驗收時看它的報告和實際動作，越界照實報。

## 被權限擋住會乾等；Read／Write 常被拒

子 agent 在 don't ask 模式下遇到 Read 或指令被權限擋，有的不回報、就停在那裡；Read／Write 被拒時它們會改用 `cat`、heredoc，所以「請把結果寫成檔」不一定寫得出來。任務書寫明「一件事用 bash 腳本走完、不要用 Read 讀暫存樹」；要結果的寫「最後一則回答裡放全文」；配上面的進度檔。

## 子 agent 寫的日期、hash、行號要回原檔核

收子 agent 交回的稿時：它會補出沒看到的事實（把封存日寫成別的日子），也會把一句 AI 的轉述當成使用者原話。日期、hash、行號、引號裡的原話，都回原檔核一次才採用。

## subagent 的 system set 是整份取代

用 `subagent` 的 system set 給掛上的隊員（含 eca 類隊員）加一段 system 時：set 是整份取代定義的 system，不是附加。要保留定義原有的，就先 get 再接上自己的字。
