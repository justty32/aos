## 四、proto6 帳號模組真 root 驗收：先修手冊

[手冊](../../proto6/notes/2026-10-01-account-manual.md)照 `6583f565` 寫；之後 `52870cbd`（10-02 第二十五批）改了 mq 與控制 socket 介面，手冊沒跟上（只在 `c15aee6f` 改過連結）。已核對現行 [aos_mq.py](../../proto6/src/py/lib/aos_mq.py)、[aos_ctl.py](../../proto6/src/py/lib/aos_ctl.py)、[aos_daemon_mq.py](../../proto6/src/py/lib/aos_daemon_mq.py)，具體落差：

1. **第 2 節 `daemon.json`（手冊第 61 行）**：`"mq": {"socket": "./mq.sock"}` 是舊格式。現行 `modules.mq` 是「門名 → socket 路徑」，例如 `{"door": "./mq.sock"}`，門名只能英數底線。
2. **第 2 節 insts（手冊第 62～72 行）**：現行每一項要用 `"mq": ["<門名>"]` 訂門才收得到信；手冊的 insts 沒寫，c.json 會永遠取不到信。
3. **b.json 寄信（手冊第 47 行）**：`aos-mq send c.json '{"hi":1}'` 的第一個參數不再是收件 inst，而是門的 socket 路徑；任務內該寫 `aos-mq send "$AOS_DAEMON_MQ_<門名>" '{"hi":1}'`（daemon 每項會給每扇門一個該環境變數）。
4. **c.json 取信（手冊第 48 行）**：現行 `aos-mq take <socket 路徑>`，要給路徑參數。
5. **第 3.4 節（手冊第 134、136 行）**：環境變數 `AOS_DAEMON_SOCKET` 現行是 `AOS_DAEMON_CTL_SOCKET`；順帶，現行 `aos-ctl --socket` 必須明寫 `<inst>`，任務內的 `aos-ctl status` 不受影響。
6. **第 3.5 節（手冊第 150 行）預期輸出**：`got.c` 應是 `{"from":"b.json","msg":{"hi":1}}`；現行信是寄的 JSON 原樣，也就是 `{"hi":1}`，不再有 `from`／`msg` 包裝，並且寄件人若有訂門也會收到自己的。
7. 手冊其他提到 `mq.sock` 的段落（如 3.4 的 ls 清單、後段關 root 端後 socket 被刪的預期）要一併核對路徑名稱，是否沿用新設定的門路徑。

修完手冊後才請你在可丟棄機器上照跑；這一步（我先修手冊）等你一句話。驗完照手冊第 5 節回報。我沒有執行真 root 驗收，以上是靜態對照。
