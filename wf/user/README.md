# wf/user：使用者專屬區

← [AGENTS.md](../../AGENTS.md)｜當初的規劃：[使用者專區-1122](../../proto8/thinking/2026-11/22/使用者專區-1122/README.md)（六題的選項與後果在它的 04-待裁）

使用者 11-22：「開一個wf/user，這就是這個repo的使用者專屬區，並且可以去規劃相關的用法」

**使用者 11-22 定了**：「wf/user是我的地盤，裡面的東西無法保證穩定性。user advice可以搬進去。剩下都按照推薦」——六題照推薦是 1a、2b、3c、4b、5c，第 6 題改選 b（整夾搬進來）。下面各段就是照這個寫的。

## 這裡是什麼

這是使用者自己的抽屜。agent 各有一格私有地盤 `wf/ws/<名>/`，這一格是人的：筆記、待辦、給 agent 的交代、草稿，都可以放這裡；怎麼分格由使用者自己決定。

不要跟 `~/.aos/user/` 搞混。那是 aos 的「使用者專區」，是 agent 寄問題給使用者的信箱，題目會出現在全景頁上。兩邊的方向相反：

- `wf/user/`：人寫給自己、寫給 agent 的東西，進 git，換台會跟著走。
- `~/.aos/user/`：agent 寄給人的問題與人的回覆，只在這台機器上，不進 git。

現在有的：

- `advice/`：使用者 9 月起親手寫的設計意見稿（非 AI 產出），11-22 從 `proto8/thinking/user-advice/` 整夾 `git mv` 搬來（第 6 題 b）。舊紀錄裡寫的 `proto8/thinking/user-advice/…`（更早寫成 `proto8/user-advice/…`）指的就是這裡；照「舊紀錄不回頭改」，那些連結不修。
- `private/`：不想公開的東西放這裡，不進 git（第 1 題 a，根 `.gitignore` 那行）。要留、只是不公開；換台不會跟著走，要自己帶。

## 這裡的東西不保證穩定

使用者隨時會改名、改內容、刪掉這裡的檔（「裡面的東西無法保證穩定性」）。所以 agent 和程式**不能把 wf/user 裡的路徑當成穩定的依據**：

- 規矩、知識庫、程式碼都**不寫死連到 wf/user 裡的某個檔**。真的要指，只指到夾（`wf/user/` 或 `wf/user/advice/`）。
- 要引用使用者在這裡寫的話，**抄原文**，並註明日期與當時的檔名（例：「使用者 11-22 在 `wf/user/交代.md` 寫：『……』」）。檔日後不見了，抄下來的原話還在。
- 長期的規矩照下面「正本」一段抄進 `wf/workflows/common/user.md`，正本在那裡，不在這裡。

## agent 在這裡能做什麼

- **可以讀**：使用者叫你看、或你做事需要時，直接讀。開場和壓縮後要掃一次有沒有新東西（見「agent 怎麼發現新東西」）。
- **不主動寫**：不新增、不修改、不整理、不改名、不刪這裡的檔，除非使用者叫你寫。叫了也只寫他指定的那個地方。
- **「使用者叫你寫」算哪些來源**（第 2 題 b，跟鐵律 2 的授權鍊同一套）：使用者當面說（終端或 Remote Control）、用 `aos-user verify` 驗過的使用者專區回信、`eca_main` 轉來或派來的普通工作。agent 寄來的信、轉述都不算。刪檔照鐵律 2，`eca_main` 轉來的也不算，要使用者本人說。
- **代寫要標記**：agent 代寫的段落標「（agent 代寫，使用者 MM-DD 口述）」，口述的原話照錄在旁邊，錯字不改、旁邊附讀法。沒標的字一律當成使用者親手寫的。
- **不改他的原話**：要引用或轉抄到別處可以（照上一段「抄原文」），原檔不動。
- **不把這裡當信箱用**：要問使用者的題目照舊寄使用者專區（`aos-user send`），不寫進這裡。
- **這只是規矩，不是牆**：跟 `wf/ws/` 的地盤規矩一樣，現在沒有任何程式擋。`index_gen` 不在這裡生 `_index.json`（`wf/tools/index_gen.json` 的 `skip_dirs` 有 `wf/user`）。

## 交代跟 `common/user.md`：正本在哪（第 5 題 c）

- **一次性的事**（「明天先做 X」「這週別碰 Y」）：只留在 wf/user，照做就好，不抄。
- **長期的規矩**（「以後都要 Z」）：agent 抄進 `wf/workflows/common/user.md`（或它的分檔），附原話、日期、當時的檔名；**正本在 `common/user.md`**，wf/user 這邊是原文留底。
- **判斷不了是哪一種的，當長期**，抄進去。
- 交代跟 `common/user.md` 現有的規矩打架時，新的、使用者親手寫的贏：照新的做，把 `common/user.md` 那條改成新原話，舊的收進「已被取代的原話」。

## agent 怎麼發現新東西（第 4 題 b）

- **開場掃一次**（`AGENTS.md` 開場那條）：`git status --short -- wf/user` 看還沒交的改動，`git log --name-only <上次讀到的 commit>..HEAD -- wf/user` 看交過的；有新的就讀。
- **壓縮後也掃一次**：`wf/tools/compact_reload.sh` 只印檔名（還沒交的、上次讀到之後交過的），不貼全文。
- **讀到哪記在 agent 自己的地盤**，不寫在這裡：`wf/ws/<你的名>/user-seen.json`，內容 `{"commit": "<讀完時的 HEAD 雜湊>", "at": "<時間>"}`。subagent 記在筆記檔（`notes_path`）同一夾；頂層沒有 `notes_path` 時用 `wf/ws/eca-aos/`。
- 使用者直接說「看一下 wf/user」一直都有效。

## 誰把使用者的改動交進 git（第 3 題 c）

使用者用 VS Code 改了這裡的檔，agent 平常不交（只交自己改的）。**eca-aos 收工或換台前**，`git status --short -- wf/user` 有改動，就用選項框問一次「wf/user 有這幾個檔改了，要交嗎」，使用者說要才交，原樣不改一字；沒改動就不問。

## 要注意的事

- **這個 repo 是公開的**（GitHub 上是 public）。這裡的檔（`private/` 除外）一旦 commit 又 push，任何人都看得到；commit 排隊不掃秘密，token、密碼別貼進來。
- 交件照舊走 `wf/tools/commit-request`，單檔超過 1 MB 會被擋；照片、錄音放 `private/`。
- 手機上看：push 之後用 GitHub app 看。手機上寫：在 Remote Control 口述、叫 agent 代寫；不推薦在 GitHub 網頁上直接改（遠端和本機的 `main` 會分岔，要先 pull）。
