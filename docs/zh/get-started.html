開始用：不用任何模型，跑起第一棵樹

一句話：建好程式、起兩個資料夾、掛一隻叫 ann 的 agent、跟它說一句話——然後打開資料夾，看它剛剛做了什麼。全程不用模型帳號；aos 除了 ~/aos 和 ~/aos-demo 兩個資料夾，不寫你家目錄的任何地方（建置時 vcpkg 會在 ~/.cache/vcpkg 放下載快取）。

這頁用內建的「假腦」代替模型，不用任何 API 金鑰（安裝分級裡叫 L0）。假腦會照固定格式回話，但它走的路跟真腦一模一樣：收信、叫工具、寫紀錄、回信。

開始前：Linux（或 WSL2）、git、bash、Python 3.11 以上、CMake 3.21 以上、支援 C++20 的編譯器、vcpkg。細節看需求。請開一個新的 bash。新開的 bash 還是會繼承外面已經設好的變數，所以先確認沒有舊的 AOS_*：

env | grep '^AOS_'

什麼都沒印才對。有印出東西（例如你以前裝過 aos），先把它們清掉再開始：

unset $(env | grep -o '^AOS_[A-Za-z0-9_]*')

agent 會用你的帳號執行程式。第一次玩，建議在拋棄式帳號或容器裡試——見安全說明。

1. 抓原始碼、建置

git clone https://github.com/justty32/aos ~/aos
# vcpkg 不在 ~/dev/vcpkg 的話，先：export VCPKG_ROOT=<vcpkg 的位置>
cd ~/aos/proto8/cpp && cmake -B build && cmake --build build -j

建置會用 vcpkg 抓 C++ 需要的 JSON 函式庫。vcpkg 裝在 ~/dev/vcpkg 就什麼都不用設；裝在別處，照區塊裡的註解先設 VCPKG_ROOT。

不想用 vcpkg？（待驗）

沒給 vcpkg 時，CMake 會改找系統裝的 nlohmann-json。這條路我們還沒在乾淨環境實測過，裝了發行版的 nlohmann-json 套件理論上就能建。卡住請看疑難排解。

2. 讓這個殼找得到指令

export AOS_HOME=~/aos/proto8
export PATH=$(ls -d $AOS_HOME/cpp/*/bin $AOS_HOME/cmd/*/bin | tr '\n' ':')$PATH
export PYTHONPATH=$AOS_HOME/py:$AOS_HOME/lib

只改這個殼，關掉就沒了。想長期裝，看安裝的 install.sh。

3. 起兩個資料夾：腦，和你的樹

mkdir -p ~/aos-demo/llms ~/aos-demo/tree

cd ~/aos-demo/llms
cp -r $AOS_HOME/kernel/llm-kernel def
nohup aos-exec --stack stacks/llm def > llm.log 2>&1 &

cd ~/aos-demo/tree
cp -r $AOS_HOME/templates/daemons/daemon-root defs
cp -r $AOS_HOME/templates/agents/agent-fsm defs/ann
nohup aos-exec --stack stacks/root defs > root.log 2>&1 &
~/aos-demo/
  llms/   def/ 是 llm kernel 的定義，stacks/llm/ 是它跑起來的狀態（這裡是假腦）
  tree/   defs/ 是樹的定義，defs/ann/ 是 agent 的定義，stacks/root/ 是樹跑起來的狀態

def 和 defs 是定義（像程式碼），stacks/ 是跑起來之後的一切（像記憶體）。兩個並排放，樹就會自己找到旁邊的腦。

4. 掛上 ann，先看一眼它的資料夾

aos-agent -d stacks/root ctl add -w . defs/ann
aos-daemon-ctl -d stacks/root ls
ls stacks/root/procs/ann/
ann	running	1293838	-	~/aos-demo/tree	-
# daemon: running (pid 1293334)

hooks  queue  stage.txt  state_flux.json  state.json  stderr.txt

ann 現在是一個在跑的行程，而它的一切都在 stacks/root/procs/ann/ 這個資料夾裡。還沒有對話紀錄。

表上另外兩行 _clock、_sweeper 是什麼

樹自帶的兩個小幫手：_clock 數拍子，_sweeper 收拾停掉的行程。它們也是 proc，跟 ann 一樣在 procs/ 底下有自己的資料夾。

5. 跟 ann 說一句話

aos-agent -d stacks/root -t ann say "hello, who are you?"
timeout 60 aos-agent -d stacks/root -t ann listen
FAKE ANSWER to: hello, who are you? (tool said: 2026-11-14T04:33:40Z)

假腦的回答很呆，但看括號：它先叫了一個工具（問現在幾點），才回話。

6. 再看一次資料夾

ls stacks/root/procs/ann/
tail -n 3 stacks/root/procs/ann/history.jsonl
history.jsonl  hooks  interfaces.json  observed.jsonl  queue  stage.txt  state_flux.json  state.json  stderr.txt  think

{"role": "assistant", "content": null, "tool_calls": [{"id": "call_fake_2", "type": "function", "function": {"name": "peek_now_time", "arguments": "{}"}}]}
{"role": "tool", "tool_call_id": "call_fake_2", "content": "2026-11-14T04:33:40Z\n"}
{"role": "assistant", "content": "FAKE ANSWER to: hello, who are you? (tool said: 2026-11-14T04:33:40Z)"}

跟第 4 步比，多了 history.jsonl（整段對話）和 think/（它想的過程）。最後三行就是剛才那一來一回：叫工具 → 工具回答 → 最後的答案。沒有藏起來的狀態——想知道 agent 在做什麼，打開資料夾就好。

7. 工具也是資料夾：自己叫一次

第 6 步裡 ann 叫了 peek_now_time。這個工具不是藏在程式裡的函數，它就是一個資料夾：

ls $AOS_HOME/lib/base/peek_now_time/
echo '{}' | aos-exec $AOS_HOME/lib/base/peek_now_time
echo '{"expr": "17*23"}' | aos-exec $AOS_HOME/lib/base/math
_entry  _metainfo.json  tests  _tooldef.json
2026-11-14T04:48:07Z
391

資料夾裡放一支叫 _entry 的可執行檔，它就能被呼叫：輸入從 stdin 進，結果從 stdout 出。旁邊的 _tooldef.json 告訴模型這個工具怎麼用，_metainfo.json 記它的性質（會不會改東西、多久跑完）。這就是「資料夾，就是函數」。

自己做一個，用什麼語言寫都行：

mkdir -p ~/aos-demo/greet
cat > ~/aos-demo/greet/_entry <<'EOF'
#!/usr/bin/env bash
read -r input
echo "hello from a folder; you sent: $input"
EOF
chmod +x ~/aos-demo/greet/_entry
echo '{"name": "ann"}' | aos-exec ~/aos-demo/greet
hello from a folder; you sent: {"name": "ann"}

要讓 agent 也能叫它，還要補 _tooldef.json 並掛進 agent 的工具表——下一批的教學會講。

8. 停掉，確認都停了

aos-daemon-ctl -d ~/aos-demo/tree/stacks/root shutdown
aos-daemon-ctl -d ~/aos-demo/llms/stacks/llm shutdown
aos-daemon-ctl -d ~/aos-demo/tree/stacks/root ls
daemon at ~/aos-demo/tree/stacks/root stopped (ctl seq 1); 3 procs asleep, they wake when it starts again
daemon at ~/aos-demo/llms/stacks/llm stopped (ctl seq 1); 1 procs asleep, they wake when it starts again
_clock	sleeping	-	143	-	-
_sweeper	sleeping	-	143	-	-
ann	sleeping	-	143	~/aos-demo/tree	-
# daemon: not running (pid 1509266 is gone); the table above is what it left

每列都是 sleeping、最後一行是 not running，就是停乾淨了。ann 只是「睡著」：資料夾都還在，下次起樹它會接著醒來。

想從頭再玩一次：先照上面停掉，再換一個新的示範夾（例如 ~/aos-demo2），從第 3 步照做，但第 3 步以後每一個 ~/aos-demo 都要換成新的名字（包括第 8 步停掉的那兩行），不然你操作的還是舊的那棵樹。
