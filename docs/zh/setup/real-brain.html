接真腦：把 ann 換成真的模型

「開始用」裡的 ann 用的是假腦。這頁把它換成真的模型：先加一個你自己的端點，讓模型回一個字；再讓 ann 用它叫工具、回答。

原型 · demo 版

先決條件：

  • 你已經照開始用做完第 8 步，~/aos-demo/llms 和 ~/aos-demo/tree 都在，而且都停著。
  • 你還在同一個殼（終端機視窗）裡，第 2 步的三個環境變數都還在。
  • 你有一個 OpenAI 相容端點：網址（以 /v1 結尾）、模型名；端點要的話，還有金鑰（API key）。

要花錢： 下面每叫一次真模型，端點那邊就照它的價錢算。這頁總共叫三次左右。

1. 做一個端點函數

端點也是一個函數資料夾。它的 _entry 只說一件事：叫 aos 內建的 llm_http，金鑰從環境變數 MY_API_KEY 讀。

mkdir -p ~/aos-demo/llms/def/endpoints/mine
cat > ~/aos-demo/llms/def/endpoints/mine/_entry <<'EOF'
{"description": "my OpenAI-compatible endpoint; the key comes from MY_API_KEY",
 "argv": ["aos-exec", {"$env": "AOS_HOME", "$path": "/lib/base/llm_http"}, "--key-env", "MY_API_KEY"]}
EOF

金鑰不寫進 aos 的任何設定檔，只放在環境變數裡。MY_API_KEY 沒設或是空的，請求就不帶金鑰送出。本機不用金鑰的代理，可以這樣用。

2. 把它登記成一個腦

在腦的設定 ~/aos-demo/llms/def/kernel.json 裡，加一個叫 mine 的端點。先把下面前兩行改成你的端點網址和模型名：

export MY_URL=http://localhost:4000/v1
export MY_MODEL=<你的模型名>
python3 - <<'EOF'
import json, os
p = os.path.expanduser('~/aos-demo/llms/def/kernel.json')
k = json.load(open(p))
k['endpoints']['mine'] = {"exec": "endpoints/mine", "url": os.environ['MY_URL'],
                          "model": os.environ['MY_MODEL'], "summary": "my own endpoint"}
json.dump(k, open(p, 'w'), indent=1, ensure_ascii=False)
EOF

出廠的 kernel.json 裡還有好幾個別的端點。那些是作者本機代理上的名字，你用不到，留著也不影響。

3. 啟動腦，先讓它回一個字

金鑰要在啟動腦之前，在同一個殼裡設好。腦只讀它啟動那一刻的環境變數，之後再設它看不到。第一行會等你貼上金鑰（畫面上不顯示），端點不用金鑰就直接按 Enter；這樣金鑰也不會留在 shell 的指令歷史裡。

read -rsp 'API key (just Enter = none): ' MY_API_KEY; echo
export MY_API_KEY
cd ~/aos-demo/llms
nohup aos-exec --stack stacks/llm def > llm.log 2>&1 &
export AOS_LLM_KERNEL=~/aos-demo/llms/stacks/llm
aos-llm ls | grep mine
echo '{"endpoint": "mine", "request": {"messages": [{"role": "user", "content": "Reply with exactly: pong"}]}}' | timeout 120 aos-llm ask

剛啟動腦就打 aos-llm ls，可能先看到一行 llm daemon is not running 的 warning：那是腦還在啟動，等一兩秒再打就好，後面的 ask 不受影響。

應該看到下面兩行。第一行的 - 是 mine 沒填的欄位，這頁用不到。

mine	normal	-	-	-	-	my own endpoint
{"role": "assistant", "content": "pong"}

沒回 pong 的話先看 ~/aos-demo/llms/llm.log。看到 401 或 403，通常是啟動腦之前沒設好金鑰。連不上的話，檢查網址。

4. 讓 ann 換腦

把樹重新啟動（ann 會自己醒來）。只改 ann 一隻的腦，再跟它說一句要用到工具的話：

cd ~/aos-demo/tree
nohup aos-exec --stack stacks/root defs > root.log 2>&1 &
aos-agent -d stacks/root -t ann llm set model=mine
aos-agent -d stacks/root -t ann say "What time is it? Use your tool, then answer in one short sentence."
timeout 120 aos-agent -d stacks/root -t ann listen
tail -n 3 stacks/root/procs/ann/history.jsonl

llm set 會在 ann 的資料夾裡多寫一個 llm.json，裡面只記你改的那一個鍵。

模型每次回答的字不一樣。history.jsonl 最後三行大概像這樣，id 和時間會不同：

{"role": "assistant", "content": null, "tool_calls": [{"id": "call_…", "type": "function", "function": {"arguments": "{}", "name": "peek_now_time"}}]}
{"role": "tool", "tool_call_id": "call_…", "content": "2026-11-14T05:09:00Z\n"}
{"role": "assistant", "content": "It’s 05:09 UTC on November 14, 2026."}

跟假腦那次一樣是三行：叫工具、工具回、回答。差別是這次決定叫工具、寫回答的是真的模型。

想換回假腦：aos-agent -d stacks/root -t ann llm rm model。改過的鍵都拿掉後，ann 資料夾裡那個 llm.json 也會跟著消失，回到出廠設定（假腦）。

5. 停掉

aos-daemon-ctl -d ~/aos-demo/tree/stacks/root shutdown
aos-daemon-ctl -d ~/aos-demo/llms/stacks/llm shutdown

這頁沒驗到的

  • 只經本機代理照字跑過。帶金鑰的設定也照字走過：測試用的金鑰確實以 Bearer 送出，但那個代理不驗金鑰。連到雲端服務、用真金鑰的那條路還沒驗。
  • 別的模型會不會照樣叫工具，要看那個模型本身支不支援 tool calls。
