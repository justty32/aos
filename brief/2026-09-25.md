## 1. 一句話結論

董事說的「用 aos 體系蓋公司架構」，今天做出來了：**公司＝一組 aos 團隊，`company.py` 一支程式管開工、下單、看狀態、收工**，可以同時開好幾家、彼此不干擾，市場層也把「打分→排名→撥額度→倒閉→合併」整套走過一輪。**排名公式真跑後修好了**：做壞的單拿 0、沒打分不准撥、快改看董事等多久，經理人可以照公式發額度（打分後看一眼說明與註記再撥）。

## 2. 公司長什麼樣（對照董事的話）

董事原話：「這個公司架構，arknights 只是一個工具目標」「用我們現有的 aos 體系去建立這個公司架構」「初期新創不超過 10 人、不超過 20 個 cpu 和 5 個 llm cpu」「準備五個小公司，誰做得更好更快就給額度……剩兩家就合併」「可以每公司一個 daemon 和 kernel」。今天照這些話蓋出來的東西：

| 董事說的 | 現在是什麼 |
|---|---|
| 用 aos 體系蓋公司 | 部門＝真的 aos 團隊資料夾：總裁辦 hq、製造 mfg、品管 qa、研發 rd、圖書館 lib；業務、HR 併在總裁辦（總裁兼）；財務部沒有模型員工，只有一本帳＋一支指令 |
| 董事＝human | `company.py order／mail／answer` 就是董事下單、收信、拍板；董事的信箱在 `team/human/` |
| 部門之間怎麼通話 | 總機（`company.py relay`）每 5 秒轉一次信，**不叫模型**，只是照信第一行的〔給 部門〕搬信、開單 |
| 每公司一個 daemon 和 kernel | 已做：`<公司>/D/` 各自一份，今天真開機驗過兩家同時跑互不干擾 |
| 新創不超過 10 人、20 cpu、5 llm cpu | 現在編制：**正式 7 人／10、cpu 12／20（不含 llm）、llm cpu 5／5** |
| 正式／臨時工 | 名冊上每個人有 `employment` 欄：人手寫的員工是「正式」（算人頭，記憶留著）；程式臨時生出來的（`spawn`）是「臨時工」（不算人頭，一次性） |

**董事怎麼玩**（從公司樣板 README 抄的最短路徑）：

```sh
python3 company.py new    -C ~/tmp/company-run/c1 --prefix c1- --project ~/tmp/company-run/c1/proj
python3 company.py up     -C ~/tmp/company-run/c1
python3 company.py order  -C ~/tmp/company-run/c1 "補人物 老財"
python3 company.py status -C ~/tmp/company-run/c1
python3 company.py down   -C ~/tmp/company-run/c1
```

## 6. 要董事拍的題（最重要 8 題，其餘見 [WAIT_USER](../wf/WAIT_USER.md) 第 40～73 題）

1. **五家一起開，llm cpu 名額合計 25 超過機器上限 20**——每家新創上限 5，五家滿編就超賣。現在做法是五家同跑時每家降到 4。這樣可以嗎？
2. **claude「一週額度 10%」換算成具體多少**——是給美元數字、還是 token 數？財務部只看得到經 aos 的 claude 呼叫，訂閱本身的額度數字要董事給。
3. **開辦費調成 2500 萬 token、每輪總額 5000 萬，對不對**——原本 200 萬一張單就倒閉，試玩一張單就花了 451 萬。已先調高，要董事點頭或給別的數字。
4. **失敗的單要不要算分**——已修好，預設不算（做壞的單／沒結案，品質、快、省、總分全 0，撥 0）。董事只需否決，不否決就照這樣做。
5. **排名權重可以嗎**——現在品質 0.6、快 0.25、省 0.15，要不要改。
6. **cpu 的算法要統一成一種**——現在「cpu 20 顆」算不算 llm 那 5 顆，不同地方算法不一致（`status` 算不含 llm，`new` 一度算含 llm，已改對齊但董事沒正式拍板要用哪一種）。
7. **commons（跨部門經驗庫）預設要不要開**——現在預設每個成員都看得到、都能投稿，這樣對嗎，還是要名冊特別打開才有？
8. **製造部的寫手要不要現在就換成 deepseek**——HR 試用只跑過 1 次就通過，HR 部自己建議跑滿 10 次再換，不要現在就換。
