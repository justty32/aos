## aos-mcp

`bin/aos-mcp [--ws WS] [--stack DIR] [--timeout-s N] [--enable-logs [--logs-path FILE]] [--memory NAME] [--hooks DEF] [REGISTRY...]`：把**給的登記檔**（[aos-tools](../aos-tools/README.md) 的工具註冊檔，檔名不限，例 `aos-tools.json`）登記的工具當 MCP tools 給外部 agent（Claude Code、pi coding agent 等）叫，stdio JSON-RPC、只用標準庫。決定 [thinking 10-28 aos-tools](../../thinking/2026-10/28/aos-tools/README.md)（使用者「aos-mcp 是一個小包裝，跑在 aos-tools 上」）。

- **位置參數＝登記檔的路徑**（使用者 11-02「我希望能改成aos-mcp tools.json，也就是改成指定檔案，這樣我們可以改名為aos-mcp aos-tools.json，這樣能解放一些名稱」，[thinking 11-02 試驗場 cathy](../../thinking/2026-11/02/playground-cathy/README.md)）：相對路徑從啟動時的 cwd 算；給資料夾或不存在的檔＝`ToolMissing`。登記用 `aos-tools --file aos-tools.json add …`。一份都沒給＝讀啟動時 cwd 的 `./tools.json`（不存在＝`ToolMissing`），跟 aos-tools 沒給 `--file` 時一致，兩邊都不帶檔名就用同一份（使用者 11-02「兩邊的json格式是一樣的嗎？是同一份嗎？是的話，那就全部改回預設tools.json。」，[thinking 11-02 stack-tools](../../thinking/2026-11/02/stack-tools/README.md)）。
- **清單**：每份 REGISTRY 跑 `aos-tools --file REGISTRY ls --json`；名字＝登記名、`description`／`inputSchema`＝工具定義的 `description`／`parameters`（沒寫 parameters 給空物件 schema）。`_metainfo`（資料夾的 `_metainfo.json` 檔、JSON 檔的 `_metainfo` key；可執行檔沒有）搬成 annotations：`side_effect`→`readOnlyHint`（反）、`idempotent`→`idempotentHint`、`resource` 含 llm／net→`openWorldHint`。好幾份登記檔的工具合在一起，撞名＝`ToolsBad`。**每次 `tools/list`、`tools/call` 都重讀**：登記檔改了，下次列就看得到（不主動送 listChanged 通知；代定）。
- **叫一次**：`AOS_WS=WS AOS_STACK=<stack>/ aos-tools --file REGISTRY call 名`（aos-tools、aos-exec、有指示詞時 aos-json 都從 PATH 找），arguments 進 stdin、stdout 整段回 text、退非 0＝`isError`（stdout 空就回 `aos-mcp: error: CommandFailed <名> exited N with empty stdout`；逾時則回 `aos-mcp: error: CommandFailed <名> timed out (N s); its process group was killed`）；**失敗時（退非 0 或逾時）另附第二段 text：那次 stderr 的最後 2 KB**（工具自己寫的、aos-tools／aos-exec 說的「入口壞」等都在裡面；成功時不附），stderr 也照樣轉印到 aos-mcp 自己的 stderr（MCP 用戶端的 log）——使用者 11-05 選「附 stderr 尾巴（推薦）」（[edge-basics 題 1](../../thinking/2026-11/04/edge-basics/README.md#題-1工具失敗時外部-agentclaude-code-等看不到原因)；C-52「不偷讀下層 stderr」的例外，見 [CONCEPTS C-52](../../docs/CONCEPTS/01-設計理念/03-最高原則與兩條總原則.md#兩條總原則10-15-使用者定原文10-15-深夜加嚴)）；aos-mcp 只傳它定好的 stack，由 aos-tools call 統一算出每個工具的小格 `<stack>/tools/<名>/`（使用者選 B「tools/<name>」）；逾時＝`_metainfo` 的 `timeout_ms`，沒寫用 `--timeout-s`（預設 60），整群 TERM、2 秒後 KILL。呼叫紀錄預設不記（使用者 11-02「aos-mcp留下的calls.jsonl，這好像也是固定的。我希望能改一下，改成可以透過aos-mcp的argv來切換是否要留紀錄，默認不留」）；給 `--enable-logs`＝每次叫完在 `<stack>/aos-mcp-logs.jsonl` 記一行（`name`、`arguments`、`code`、`elapsed_ms`、`called_at`），再加 `--logs-path FILE`＝記在 FILE（相對路徑從啟動時的 cwd 算）；只給 `--logs-path` 沒給 `--enable-logs`＝`ArgumentsBad`（使用者 11-02「所以要兩個旗標」「還是logs好」，旗標名照他 11-02 的「--enable-logs」「--logs-path」）。
- **這隻自己加減的工具**（11-10 [aos-tools-cli](../../thinking/2026-11/10/aos-tools-cli/README.md) 步 4；11-05 起的 `--overlay O` 拿掉了）：REGISTRY 給 stack 裡這隻自己那份就好——它的 `"$override"` 指回定義那份，疊法歸 aos-tools（見 [aos-agent docs/03](../aos-agent/docs/03-tools覆蓋層.md#tools-覆蓋層)）；eca 經 cli_session 自動照這條選。
- **`--memory NAME`**（11-05 晚 [agent-knowledge K4](../../thinking/2026-11/05/agent-knowledge/03-接進agent與工具說明.md)）：`initialize` 時叫一次登記名 NAME 的工具 `{"op": "read"}`，印出來的知識庫根放進回應的 `instructions`（MCP 用戶端放進自己的 system prompt）。叫的是 `tools/list` 給出去的同一支，外部 agent 看到的根跟它自己查的一樣；清單沒有 NAME 或叫失敗＝不給 `instructions`、stderr 一行 `aos-mcp: warning: …`（不讓連線起不來）。eca 用 `cli.json` 的 `tools_flags` 帶（templates/eca-claude）。
- **`--hooks DEF`**（11-10 晚 [hook 圖紙 § 6](../../thinking/2026-11/10/self-family/hook/01-圖紙.md#6-eca-縮水版)）：DEF＝agent 的定義資料夾（interfaces.json 宣告 `hooks`），清單＝定義那份疊 stack 那份（`lib/agent/hooks.py`）。`tools/call` 跑之前 `before_tool`（可改 arguments；攔下＝不跑、結果文字＝hook stdout，空就 `(tool NAME blocked by hook HOOK)`，不算 isError），跑完 `after_tool`（可改結果文字）；hook 停下＝那次回 isError、文字是 `aos-mcp: error: HookFailed …`，櫃台不死。沒給＝沒有 hook；eca 由 cli_session 自動帶。
- 工作區＝`--ws` ＞ `$AOS_WS`；stack＝`--stack` ＞ `$AOS_STACK` ＞ `$WS/.stack/`。短名 `-w`＝`--ws`、`-s`＝`--stack`、`-h`＝`--help`。旗標都寫在 REGISTRY 前面（11-04 起照 [CONVENTION P-44](../../docs/CONVENTION/02-題目stack停錯腦/07-P-44.md)，用 `proto8/py/aos_flags.py`）。自己的錯 stderr 一行 `aos-mcp: error: 代號 原因` 退 1（`ArgumentsBad`、`FlagUnknown`〔不認得的旗標，11-04 前是 `ArgumentsBad`〕、`WsMissing`、`ToolMissing`〔REGISTRY 不是檔〕、`ToolsBad`〔啟動時 aos-tools ls 失敗，aos-tools 自己那行在前面〕）；跑起來之後登記檔壞了＝那一則回 JSON-RPC 錯誤（-32603）、不退，錯誤訊息附 aos-tools 那次 stderr 的最後一段（11-05，同上）。
- 只做 `initialize`、`ping`、`tools/list`、`tools/call`；沒有 progress、resources、prompts、HTTP。
- 掛法（Claude Code，WSL 裡）：`--mcp-config` 一份 `{"mcpServers": {"aos": {"command": ".../proto8/cmd/aos-mcp/bin/aos-mcp", "args": ["--ws", WS, "<登記檔>"], "env": {"PATH": "proto8/cmd/aos-tools/bin、impls 的 aos-exec／aos-json 的 bin:…"}}}}`，`--allowedTools mcp__aos__<名>`（**eca 不用手寫**：eca 資料夾放一份 `tools.json`，cli_session 自己接上 aos-mcp、工作區與 stack 跟著那隻實例，見 [templates/eca-claude](../../templates/docs/01-eca-claude.md)）；例子在試驗場 `~/code/playground/agents/bob-cathy/mcp.json`（不在 git；`"args": ["--enable-logs"]`——不帶登記檔＝cwd 的 `./tools.json`、`--enable-logs` 記呼叫紀錄到 `<stack>/aos-mcp-logs.jsonl`；cwd＝那隻 agent 的資料夾，工作區與 stack 從 aos-exec 給的 `AOS_WS`／`AOS_STACK` 繼承）。
