## aos-daemon-ctl

**`aos-daemon-ctl - 把 proc 掛到一個 aos-daemon 上、起停、暫停（往它的信箱投 procs_added／procs_removed／procs_stopped／procs_started／procs_slept／procs_woken）`**（使用者「我們現在跑aos-exec XXX，等同於把這個proc掛到linux這個原生proc管理器上。假如我們想要掛在daemon上呢？或許是aos-daemon-ctl add XXX這樣，然後會自動識別XXX是否為loop，不是的話就max:1這樣？」；[thinking 10-30 agent-lifecycle](../../thinking/2026-10/30/agent-lifecycle/README.md)、[thinking 11-03 procs](../../thinking/2026-11/03/procs/README.md)；例子 demo/daemon-3 11-04 隨 demo 刪了）

`aos-exec XXX`＝掛到 Linux 的 proc 管理；`aos-daemon-ctl add XXX`＝掛到 daemon 上。本質是 N-54 的管轄手把：往 daemon 的信箱（信箱模式，N-28 的 10-29 補）投信。設計與代定見 agent-lifecycle 的實作第 7 步的補、11-03 procs（loops／execs 統稱 procs）與 [cmd/README](../README.md)。

用法 `aos-daemon-ctl [-d D] add [--reply-to BOX] [--timeout-s S] [-n N] [-w WS] [-s S] [--def DEF] [--limits JSON] XXX [-- ARGS...]｜rm|stop|start|sleep|wake [--reply-to BOX] [--timeout-s S] NAME｜pause [--timeout-s S] NAME｜resume [--timeout-s S] NAME｜ls [-j]｜where --stack NAME｜ping [--timeout-s S]｜poke [--ctl|--mail|--all]`。短名照 [human-cli H4](../../thinking/2026-11/06/human-cli/03-慣例草案.md#h4-旗標命名) 的常用預設：`-d`＝`--daemon`、`-n`＝`--name`、`-w`＝`--ws`、`-s`＝`--stack`（只在 add；`where --stack` 不給短名）、`-j`＝`--json`、`-h`＝`--help`。`aos-daemon-ctl --help` 印頂層一份、`aos-daemon-ctl 子命令 --help` 印那個子命令的一份（英文，到 stdout、退 0）；中文說明與沿革在本檔與 [04](04-aos-daemon-ctl續.md)。名詞照 [procs § 0](../../thinking/2026-11/03/procs/03-規劃-fable-照原則定的細節-可翻案.md#0-名詞表代定)：add／rm＝插拔、start／stop＝起停（stack 留著）、sleep／wake＝睡醒（stack 留著；11-05 開放）、pause／resume＝暫停。表上的 `phase` 只有 `running`、`stopping`（收的途中）、`stopped`（daemon 下的 stop：行程不在、表上還在）、`sleeping`（11-03 procs § 8：daemon 收工〔ctl 的 stop、Ctrl+C〕時所有還活著的 proc，行程不在、表上還在；11-05 起也能 `sleep 名字` 手動睡；再開自動 wake，見 [aos-daemon](../../impls/aos-daemon/README.md)）；暫停中是子 loop 自己 state.json 的事，表上不轉述。沒有 `--kind`（11-02 拿掉，給了＝`FlagUnknown`）；舊說法「ls 只看得到還在跑的」已翻：已知非 0 留 stopped＋reason，stop／sleep 留列；退 0 才下表（使用者「把--kind刪掉，XXX後面可以接-- ... 也就是附加argv參數。改成子項結束後不留名單」）。

- **哪個 daemon**（N-63 hub 型變數）：`--daemon` ＞ `$AOS_DAEMON` ＞ **呼叫當下 cwd 的 `./.stack`**（11-05 [portable-flow 題 3](../../thinking/2026-11/05/portable-flow/05-衝突與方向題.md)，使用者選「沒設找 `./.stack`」：在 ws 裡起的 daemon，stack 就是 `ws/.stack`，`cd ws` 之後不設變數也找得到；不往上層找、不是資料夾＝`DaemonMissing`）。三種來源找到的 D 一律轉成真實路徑（realpath，捷徑解開）再用（11-06 [no-pid](../../thinking/2026-11/05/no-pid/README.md) P3）（使用者 11-04 晚「AOS_DAEMON_STACK實在太醜，還是直接簡化成AOS_DAEMON就好了」），值＝那個 daemon 的 `$AOS_STACK`（它的窗都在這：`procs_state.json` 用預設名字；警告讀 `state_flux.json`（D 裡有 `daemon.json` 則照它的 `state_flux`，讀不到設定用預設，`null`＝不讀）；信箱與 proc 的 stack 裡 `loop.json` 的名字照 daemon 在 `procs_state.json` 頂層回報的 `procs_ctl_mailbox`、`procs_loop`，11-04 起，沒回報＝預設 `procs_ctl_mailbox/`、`loop.json`）；都沒有或不是資料夾＝`DaemonMissing`；子 proc 照常繼承。`AOS_DAEMON` 要給絕對路徑，相對路徑 cd 之後就對不上（從別的資料夾叫＝`DaemonMissing`；使用者「3」：維持、只寫清楚）。掛在 daemon 底下的子項不用自己設：daemon 起它時就把 `AOS_DAEMON` 設成自己的 stack（[aos-daemon「子項的 AOS_DAEMON」](../../impls/aos-daemon/docs/05-信箱.md#子項的-aos_daemon_stack11-02thinking-11-02-resident-bob-衝突-2)），子項裡叫 aos-daemon-ctl 直接接到它的 daemon。
- **掛信寄哪：一律直寄這台 daemon，不看 `AOS_KERNEL`**（使用者 11-07 選項框「aos-daemon-ctl 永遠直寄」，[os-impl 08](../../thinking/2026-11/06/os-impl/08-aos-daemon-ctl永遠直寄實作結果.md)）：`add`／`rm`／`stop`／`start`／`sleep`／`wake` 的 `procs_*` 信與 `ping`，一律寄進 D 的 ctl 信箱（`procs_state.json` 頂層回報的 `procs_ctl_mailbox`）；設了 `$AOS_KERNEL` 也不讀、不印提醒。分工：**aos-daemon-ctl＝人直接敲板子**（像 C-83「人是最後保底」），**aos-agent＝經作業系統（判官）**——要判官管控就用 `aos-agent ctl`，它照 `$AOS_KERNEL` 寄（[aos-agent README](../aos-agent/README.md)）。判官本身睡著或停著：這是設計系統的人要管的風險，手動 `aos-daemon-ctl wake 名字`（停著用 `start`）叫醒；程式不另做自動叫醒或繞過。daemon 的 ctl 信箱沒有 `new/`＝`MailboxMissing`。直寄＝繞過判官的白名單與 `max_running`，判官管不到；要真的擋，照 [kernel/docs/02](../../kernel/docs/02-kernel-modes.md)「Linux 權限」那級讓 ctl 信箱只給判官的帳號寫。
- **`--reply-to BOX`**（11-05 [edge-agent 題 2](../../thinking/2026-11/05/edge-agent/README.md)，使用者選「加 --reply-to 等回信」）：寄信的六個子命令（`add`／`rm`／`stop`／`start`／`sleep`／`wake`）都收；原樣交給 `aos-post send --reply-to`（BOX 從 cwd 轉絕對；信封裡存相對收信信箱的根，照 aos-post 11-05 起的慣例；BOX 不是信箱＝aos-post 的 `MailboxMissing`／`MailboxBad`、這支 `SendFailed`；給空的＝`ArgumentsBad`）。回信：daemon 套了＝`{"applied": true}`（`in_reply_to`＝印出來的信件名稱；壞信不回，原因在 state_flux 的 `mailbox_warning`）。`--timeout-s` 與 `--reply-to` 互斥（並給＝`ArgumentsBad`）；給了 `--reply-to` 這支**只寄、不等**（等回信是呼叫者的事，例：aos-agent `ctl` 每封都帶共用回信信箱，下條）。實測：`aos-daemon-ctl add --reply-to /tmp/rb --name c1 a1` → `/tmp/rb/new/` 一封 `applied: true`。
- **沒給 `--reply-to`＝寄出後看 `--timeout-s S` 秒（預設 3）**（11-06 [no-pid](../../thinking/2026-11/05/no-pid/README.md) P3）：寄信的六個子命令印完信件名稱，看 S 秒那封信還在不在收信信箱的 `new/`（daemon 認領了就不在）；還在＝stderr 一行提醒 `aos-daemon-ctl: warning: the letter LETTER is still in BOX after 3 s (the daemon is busy, paused or not running); it is applied when taken`，照樣退 0——信留著，對方認領時照套。不判 daemon 活不活、不碰 pid（daemon 可能忙、暫停、沒有運行）；信被領走也不表示已套用；要確定套了沒就 `--reply-to` 自己等，或 `ping`。
- **ping**（11-06 no-pid P3；daemon 那半在 P2）：寄一封 `{"ping": true}` 進 D 的 ctl 信箱、等回信，`--timeout-s S` 預設 3 秒（S 必須是大於零的數字）。收到＝stdout `replied in N ms`、退 0；沒回＝`aos-daemon-ctl: error: DaemonFailed no reply from the daemon at D within 3 s (busy, paused or not running; what its supervisor sees: aos-daemon-ctl ls, last line)`、退 1。不分它是忙、暫停（paused 那圈不認領信）、還是掛了——**寄信不回＝這次呼叫失敗**；想知道原因看 `ls` 最後一行（上一層 daemon 的看法，見 [04](04-aos-daemon-ctl續.md)）。
- **poke**（11-09，[thinking daemon-interrupt](../../thinking/2026-11/09/daemon-interrupt/README.md)）：`aos-daemon-ctl [--daemon D] poke [--ctl|--mail|--all]`＝按門鈴，叫 daemon 不等下一圈、立刻看一次檔。鈴不帶內容：**先寫檔再 poke**（用別的子命令或自己寫 ctl.json／procs_ctl.json、寄信），連 poke 幾下合併成最強的一種做一次。三種模式互斥、不給＝`--ctl`：`--ctl`＝立刻跑一圈讀 ctl、procs_ctl、對表、寫窗（不認領信箱、不跑身體）；`--mail`＝再加信箱（仍不跑身體）；`--all`＝提前一整圈，含身體（不管 `interval_ms` 到了沒，`max` 照算）。身體跑到一半不打斷，跑完立刻補看。成功不印、退 0。
  - **護欄**：讀 D 的 state 窗（daemon.json 的 `state`，預設 `state.json`）的 `pid`、`started_at_ticks`、`boot_id` 與 daemon 宣告的 `poke` 欄（三個訊號號碼，本機是 `{"ctl": 35, "mail": 36, "all": 37}`）；先開 pidfd、比 `/proc/sys/kernel/random/boot_id` 與 `/proc/<pid>/stat` 的 starttime，三者都對上才用 pidfd 送（比完到送之間 pid 被重用的空窗關掉）。這是「其他人不碰 pid」的唯一例外，pid 重用的殘餘風險由使用者承擔；送得出去不代表叫得動，不拿它判死活（[N-17 的 11-09 例外](../../docs/NORMS/05-基礎設施-窗/06-N-17.md)）。
  - **錯**（都退 1）：模式給兩個以上或多給參數＝`ArgumentsBad poke takes at most one of --ctl, --mail, --all and no arguments (usage: aos-daemon-ctl [--daemon D] poke [--ctl|--mail|--all])`；state 窗設成 `null`＝`StateMissing`；沒 state.json＝`DaemonMissing no aos-daemon running at D (no state.json)`；pid 不在、starttime 或 boot_id 對不上＝`DaemonMissing`（例 `… (pid 265480 is now another process)`）；state 讀不了或不是物件＝`StateBad`；state 沒宣告 `poke`＝`PokeFailed the state window at D declares no poke signals (not an aos-daemon, or one too old to poke)`；跨帳號／沙箱送不出去＝`PokeFailed cannot signal the daemon (pid N): permission denied`，不改走別的路。
  - 例：`echo '{"cmd": "pause", "seq": 7}' > "$AOS_DAEMON/ctl.json" && aos-daemon-ctl poke`（daemon 立刻暫停）、`aos-daemon-ctl add --reply-to box ../agents/bob && aos-daemon-ctl poke --mail`（信立刻被認領；不帶 `--reply-to` 的 add 會先等 3 秒看認領、poke 就晚了）、`aos-daemon-ctl poke --all`（提前跑 daemon 自己的身體一次）。`pause`／`resume NAME` 寫的是子項自己的 ctl，poke 叫不到子項。
- **Python 呼叫者的時鐘期限**：共用 `daemon_ctl.ask`／`ping` 可指定 keyword-only `timeout_cycles=N`，與 `timeout_s` 擇一；兩者都省略仍為 3 秒。這是套件 API；本指令的 `ping --timeout-s` 與其他人用等待不變。兩鐘、參數檢查與錯誤詳見 [py/README](../../py/README.md)。
- **回信信箱（共用）**：`ping` 與 aos-agent 等回信都用同一個共用信箱、靠回信的 `in_reply_to` 認自己那封：呼叫者有 `$AOS_STACK`＝`$AOS_STACK/daemon_reply/`；沒有（人殼）＝`<D>/<ctl 信箱>/reply/`（預設 `<D>/procs_ctl_mailbox/reply/`）。只認 `in_reply_to` 是自己的，領了就 done；沒人領的回信超過 10 分鐘（照 `sent_at` 算）由下一個來拿信箱的人收掉（垃圾回收，不是判死活）。共用實作在 [`py/daemon_ctl/`](../../py/README.md)（寄信、回信信箱、ping 在 `py/daemon_ctl/post.py`）。
- **add／rm＝投信**（信箱模式，N-28、N-54）：信箱名照 daemon 在 `procs_state.json` 回報的 `procs_ctl_mailbox`（11-04 起 daemon.json 沒寫也開、預設 `procs_ctl_mailbox`；回報 `null`＝沒開＝`MailboxMissing`），沒有 `new/`＝`MailboxMissing`（daemon 還沒起）；stdout 印 aos-post 的信件名稱；daemon 下一圈才套，結果看 ls（壞信在 state_flux 的 `mailbox_warning`）。rm＝`{"procs_removed": [名字]}`；先停再拿掉，stack 不清。
- **做完的同名再 add＝重新起**：信箱模式下子項做完（done）daemon 就從期望表拿掉（11-02），再投一封同名的 add 就再跑一次，不用先 rm。出錯結束（任意 proc 退非 0）的不拿掉、留 `stopped`＋`reason`，同名 add 不會把它拉起來，要 `start`（11-05）。
- **自動識別**（11-04 改，使用者「拿掉，不應該看特定檔案。add這塊，就是看最終指向的json的內部結構。」，[four-elements 08 步 7](../../thinking/2026-11/04/four-elements/08-實作步驟-等aos-agent後.md)）：照 aos-exec 的找法（N-61／N-62 的子集）走到入口（資料夾＝`XXX/$AOS_ENTRY`，預設 `_entry`、沒有再找 `.json`；可執行檔＝exec 型；JSON 陣列一律原樣當 aos-exec 目標，不辨認 aos-loop；字串＝轉向再走；有 `argv` 的物件＝單子＝exec 型；沒 `argv`、有 `exec` 的物件＝loop 設定；沒 `argv` 沒 `exec`＝取 `js[$AOS_ENTRY]` 再走），走到 loop 設定＝loop 子項，其他＝exec 型（XXX 的絕對路徑，跑一次）；不看檔名（「有沒有 loop.json」不再算），繞圈＝`EntryBad`，XXX 的 `.env` 不讀（只判型、不是真的跑；`.env` 改了 `AOS_ENTRY` 這裡看不到）、指示詞（`$ref`／`$env`）不解。loop 子項的設定＝那份 loop 設定（去掉 `_entry`；相對 exec 照它的資料夾轉絕對；exec 是內嵌單子＝換成 `<那份檔>#<指標>/exec`，例 `<XXX>/loop.json#/exec`，子 loop 每次 aos-exec 指回原檔那張單子，`AOS_CD`、相對的 cwd／argv 照原地算，跟直接 aos-exec XXX 一樣；11-01 刪 aos-round 時改——eca 定義的 `aos-eca-turn … {"$env": "AOS_CD"}` 靠這條掛得上 daemon）；**11-04 起不補 `ctl`／`state`／`state_flux`**（aos-loop 沒寫＝`ctl.json`／`state.json`／`state_flux.json`；寫了就原樣，相對 `$AOS_STACK`、落在它的 stack）；設定只有 `exec`＝補 `"interval_ms": 0`（aos-loop 的預設本來是 0；daemon 看寫法決定怎麼起〔N-28 型別判法〕，只有 `{"exec": …}` 的物件＝跑一次，補了才不會被當成跑一次）。名字＝`--name` ＞ XXX 的資料夾名（`#` 前面那段的 basename）；名字合不合格由 daemon 驗（壞信記在 `state_flux.json` 的 `mailbox_warning`）。
- **給 agent 定義資料夾＝跑它的 `_entry`**（11-07 [os-impl 09](../../thinking/2026-11/06/os-impl/09-直掛agent不上表.md)；先選 A 只補文件，後由裁定 B 翻「失敗也下表」）：agent 的 `_entry` 是「把自己掛上 daemon」，直掛時可能跟自己撞名（InstanceExists、退非 0）；現在列留 stopped＋reason、stderr.txt 留原錯誤。要掛 agent 用 aos-agent ctl add（或 aos-exec 定義資料夾）；直掛身體用 `aos-daemon-ctl add -n bob --def bob bob/body.json`。`applied: true` 仍只表示信已套進名單，不保證那隻成功運行。
- **`-- 參數...`**（11-02）：`--` 之後全當附加 argv，原樣不轉路徑；exec 型＝`procs_added {名字: [XXX 絕對路徑, 參數...]}`（daemon 起它＝`aos-exec XXX 參數...`；沒參數是字串，`XXX --` 後面沒東西＝沒參數；`檔#/指標` 只轉 `#` 前面），實際送的是物件 `{"exec": [XXX, 參數...], "def": XXX, "ws"?: WS, "stack"?: S}`（`def` 見下）。**loop 型帶參數＝`ArgumentsBad`**（11-02 代定：參數沒地方放，要參數寫進 loop.json 的 `exec`）。XXX 後面接的不是 `--`＝`ArgumentsBad`（add 只收一個 XXX）。例：`aos-daemon-ctl add ./hello.sh -- world`（`hello.sh` 是可執行檔＝exec 型，daemon 起它＝`aos-exec <絕對路徑>/hello.sh world`；agent 定義資料夾不要這樣掛，見上條）。
- **`--ws WS`**（10-30 eca 第 2 步、thinking 2026-10-30-eca 衝突 1、3；使用者「都照建議」）：這一隻的工作區。WS 從呼叫當下的 cwd 轉絕對（不是資料夾＝`PathMissing`、空＝`ArgumentsBad`），寫進子項物件的 `ws`（loop＝子項設定多一個 `ws`；exec＝`{"exec": XXX 或 [XXX, 參數...], "ws": WS}`），daemon 起它時設 `AOS_WS`（沒給＝繼承 daemon 的；[aos-daemon「子項的工作區 ws」](../../impls/aos-daemon/README.md)）。
- **`--stack S`**（11-03 procs § 2b，使用者「那就記錄在名單上。我是希望盡量不要用捷徑啦。然後S裡面有別的東西的話，使用者要自己承擔風險。」）：這一隻的 stack，沒給＝daemon 預設的 proc 的 stack `<D>/procs/<名字>/`。S 從呼叫當下的 cwd 轉絕對（同 `--ws`）、**不驗在不在**（daemon 起它時 `mkdir -p`）；空（`--stack ""`、`--stack=`）＝`ArgumentsBad`；寫進子項物件的 `stack`（loop 型多一個 key、exec 型寫成 `{"exec", "stack"}`）。
- **不碰 `<WS>/.stack`**（使用者「那其實.stack根本不需要放到ws那邊」，[thinking 11-03 stack-where](../../thinking/2026-11/03/stack-where.md)）：11-03 起 add／rm 不建也不拆指到 proc 的 stack 的 symlink；daemon＝硬體、子項的 stack＝暫存器，歸 daemon 管，`AOS_WS` 只是一個位址。工作區原本有什麼都不動、不說話。要對它說話：`aos-agent say --target 名字 你好 && aos-agent listen --target 名字`（[aos-agent](../aos-agent/README.md)，11-04 起取代 aos-say／aos-listen；它掛 agent 也是叫本程式）。
- **stop／start**（11-03 procs § 2c）：`stop 名字`＝`{"procs_stopped": [名字]}`（所有 proc 都寫公開 ctl 並等自行退、不送 SIGTERM；列留成 `stopped`、stack 留著、where 照找得到）；`start 名字`＝`{"procs_started": [名字]}`（stopped 的用列上的 stack 再起；起來是跑還是暫停看它自己的 state.json）；stdout 印信件名稱。
- **sleep／wake**（11-05 [portable-flow 衝突 1](../../thinking/2026-11/05/portable-flow/05-衝突與方向題.md)，使用者選「嚴格分」）：`sleep 名字`＝`{"procs_slept": [名字]}`（daemon **現在就**對它 SIGTERM〔10 秒 KILL〕、列留成 `sleeping`、stack 留著；daemon 開門自己醒，或 `wake` 叫醒）；`wake 名字`＝`{"procs_woken": [名字]}`（sleeping 的用列上的 stack 再起）；stdout 印信件名稱。一句話分：**stop 等它做完這輪、要人 start 才回來；sleep 現在就睡、daemon 開門自己醒**。搬家前先 sleep（或直接 Ctrl-C daemon）再複製。
- **用錯 phase＝`PhaseBad`**（11-05 嚴格分；照表檢查、退 1、不送信，daemon 再驗一次）：`stop` 只收 `running`；`sleep` 收 `running`／`stopping`（stop 中改送 SIGTERM，退後仍留 `stopped`、用 `start` 再起）；`start` 只收 `stopped`；`wake` 只收 `sleeping`。提示照表上的 phase 給下一步，例 sleeping 的 `start`＝`X is sleeping; use wake (start only starts stopped ones)`、sleeping 的 `stop`＝`X is sleeping (no need to stop it); wake it first, then stop, or just rm`、stopped 的 `wake`＝`X is stopped; use start (wake only wakes sleeping ones)`。11-05 前 `start` 也收 sleeping，收回了。daemon 沒在跑時 `wake`／`start`／`rm` 照樣寄（daemon 再開先套信：rm＝拿掉；sleeping 的列本來就會醒，wake 信等於沒事；`--timeout-s S` 秒沒人認領印上面那行提醒（預設 3））。
- **pause／resume 只收 `running` 的列**（11-05 第二輪：這是命令列的 phase 限制，stopped 要先 start、sleeping 要先 wake，再 pause／resume；維持 `PhaseBad`。11-07 loop 改為起來第一拍套用未回音的 ctl，這項限制照舊）。**pause／resume**（11-03 procs § 2c 第 4 條、[ctl-commands § 5](../../thinking/2026-11/03/ctl-commands/README.md)）：不經 daemon，直接往它的 ctl（stack 裡 daemon 寫的 `loop.json` 的 `ctl` 那格，慣用 `ctl.json`）寫一道 `{"cmd": "pause"|"resume", "seq": N}`（先寫 `.ctl.json` 暫存再改名，N-05；N＝ctl 裡現有的 `seq`＋1，沒有＝1，內容一定跟上一道不同），寫完**等它 state_flux.json 的 `ctl_seq` 追上 N 才印 N**（最多 `--timeout-s S` 秒，預設 5，程式裡的 `APPLY_S`、`wait_applied`；11-05 晚 [listen paused bug](../../thinking/2026-11/05/portable-flow/07-listen-paused-bug.md)：ctl 只有一格，沒等就接著 stop／sleep，daemon 寫的 stop 會把還沒讀的 resume 蓋掉或丟掉〔暫停中的 loop 每秒才讀一次 ctl〕＝停下時 paused 還是 true、start 起來又暫停）；S 秒內沒套用（身體一步很久，loop 只在步與步之間讀 ctl）＝提醒行 `aos-daemon-ctl: warning: X has not applied pause (seq N) within 5 s …`、照樣退 0；子 loop 沒開 state_flux 窗＝不等。誰都不清 ctl（指令留在檔裡，loop 起來第一拍比上一份 state_flux 的 ctl_seq：相同不重做、不同或沒有就照做）。要看暫停了沒：看它 stack 裡的 `state.json`（`cat $(aos-daemon-ctl where --stack 名字)/state.json`，`phase` 是 `paused`）。
- **表上的路徑存相對、印絕對**（11-05 [portable-flow 03](../../thinking/2026-11/05/portable-flow/03-絕對路徑盤點.md)，使用者「可以用daemon作為相對路徑的一個基準點」）：daemon 寫 `procs_state.json` 時每列的 `stack`／`ws`／`exec`／`def` 存成**相對 daemon 的 stack**（＝D；例 `procs/bob`、`..`、`../../agents/bob/loop.json#/exec`），整份 `ws/` 搬走或 git pull 到別台照樣對得上。本程式讀表時一律 `normpath(join(D, 值))`（`exec` 的 `#` 片段照留；D 先解開捷徑——daemon 的基準點是 stack 的真實路徑，11-05 B 線——值照字面），**ls、ls --json、where 印的都是絕對**。add 送給 daemon 的照舊是絕對（「只改存的格式，不改給的格式」）。
- **`ls --json`**（11-04 晚）：列照 procs_state 原樣（路徑欄拼回絕對，上條），每列多一欄 `exec`＝daemon 記的起它時的目標（絕對；loop 型多是 `<XXX>/loop.json#/exec`、exec 型是 XXX；內嵌單子＝`null`；[aos-daemon](../../impls/aos-daemon/docs/02-看寫法決定怎麼起.md)），再一欄 `def`＝add 送的定義資料夾（下條）；文字的 ls 不加欄。
- **`def`**（11-04，使用者 11-04「那就b。」，[aos-agent 05/03 第 2 條](../../thinking/2026-11/04/aos-agent/05-實作步驟/03-實作時改的設計.md#實作時改的設計)）：add 的子項物件一律多帶 `"def"`＝XXX 的絕對路徑（`#` 後面不帶；11-05 起 `--def DEF` 可另給，aos-agent 的定義宣告了 `entry`、XXX 是定義裡那個入口時用），loop 型、exec 型都送——所以 exec 型一律送物件 `{"exec": XXX 或 [XXX, 參數...], "def": XXX, "ws"?, "stack"?}`，不再送裸字串；daemon 只記進表的 `def` 欄，aos-agent 靠它找定義（不再從 exec 欄倒推）。`--def DEF` 從 cwd 轉絕對、要是資料夾，不是＝`PathMissing`；沒給＝XXX（`#` 前面）。
- **`--limits JSON`**（11-05 [feat-proto 件 5](../../thinking/2026-11/05/feat-proto/05-資源份額.md)，使用者「會想要限制特定aos proc所占用的資源」）：這個子項的份額，原樣寫進子項物件的 `limits`（`mem_mb`／`cpu_s`／`procs`／`file_mb`／`files` 正整數、`user` 字串；`'{}'`＝不限、蓋過 daemon.json 頂層的預設）；不是 JSON、key 不認、值不對＝`ArgumentsBad`、不送信（daemon 再驗一次）。daemon 在子行程 setrlimit／換帳號（等同 s6-softlimit／s6-setuidgid，[aos-daemon docs/09](../../impls/aos-daemon/docs/09-份額.md)）；做不到（比 daemon 自己的 hard limit 寬、給 `user` 但 daemon 沒有 root）＝子項起不來、proc 的 stack 的 `stderr.txt` 一行 `LimitBad`、列 `stopped`＋`reason`。`ls --json` 每列帶生效的 `limits`（不限＝沒這欄）。
- **11-07 裁定 B：任何起法都能控制**。stop／sleep 只檢查 phase，daemon 不再因 exec 寫法拒信或不採用 procs_ctl；start／wake 同樣只看 phase。pause／resume 直接寫公開 ctl：小格父寫的 loop 設定有非空 ctl 才用它，否則 ctl.json；誰讀誰照做。寫不了是 WriteFailed，沒有 CtlMissing 的型別限制。sleep 送 SIGTERM、不寫 ctl（協定沒有 sleep）。
