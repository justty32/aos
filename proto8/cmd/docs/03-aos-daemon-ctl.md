## aos-daemon-ctl

**`aos-daemon-ctl - 把 proc 掛到一個 aos-daemon 上、起停、暫停（往它的信箱投 procs_added／procs_removed／procs_stopped／procs_started／procs_slept／procs_woken）`**（使用者「我們現在跑aos-exec XXX，等同於把這個proc掛到linux這個原生proc管理器上。假如我們想要掛在daemon上呢？或許是aos-daemon-ctl add XXX這樣，然後會自動識別XXX是否為loop，不是的話就max:1這樣？」；[thinking 10-30 agent-lifecycle](../../thinking/2026-10/30/agent-lifecycle/README.md)、[thinking 11-03 procs](../../thinking/2026-11/03/procs/README.md)；例子 demo/daemon-3 11-04 隨 demo 刪了）

`aos-exec XXX`＝掛到 Linux 的 proc 管理；`aos-daemon-ctl add XXX`＝掛到 daemon 上。本質是 N-54 的管轄手把：往 daemon 的信箱（信箱模式，N-28 的 10-29 補）投信。設計與代定見 agent-lifecycle 的實作第 7 步的補、11-03 procs（loops／execs 統稱 procs）與 [cmd/README](../README.md)。

用法 `aos-daemon-ctl [-d D] add [--reply-to BOX] [--timeout-s S] [-n N] [-w WS] [-s S] [--def DEF] [--limits JSON] [--auto-restart] XXX [-- ARGS...]｜rm|stop|start|sleep|wake [--reply-to BOX] [--timeout-s S] NAME｜pause [--timeout-s S] NAME｜resume [--timeout-s S] NAME｜ls [-j]｜where --stack NAME｜ping [--timeout-s S]｜poke [--ctl|--mail|--all]｜shutdown [--timeout-s S]`。短名照 [human-cli H4](../../thinking/2026-11/06/human-cli/03-慣例草案.md#h4-旗標命名) 的常用預設：`-d`＝`--daemon`、`-n`＝`--name`、`-w`＝`--ws`、`-s`＝`--stack`（只在 add；`where --stack` 不給短名）、`-j`＝`--json`、`-h`＝`--help`。`aos-daemon-ctl --help` 印頂層一份（11-10 晚 cli-sweep Q6／甲8，使用者裁 A＝不動行為：第一屏先一張「三對停與起」表——stop／start、sleep／wake、pause／resume 各怎麼停、之後表上是什麼、怎麼再起、daemon 重開時怎樣，外加 rm、shutdown 兩列；`aos-agent ctl --help` 同一張、rm 那列註明 stack 留著除非 `--purge`）、`aos-daemon-ctl 子命令 --help` 印那個子命令的一份（英文，到 stdout、退 0）；中文說明與沿革在本檔與 [04](04-aos-daemon-ctl續.md)。名詞照 [procs § 0](../../thinking/2026-11/03/procs/03-規劃-fable-照原則定的細節-可翻案.md#0-名詞表代定)：add／rm＝插拔、start／stop＝起停（stack 留著）、sleep／wake＝睡醒（stack 留著；11-05 開放）、pause／resume＝暫停。表上的 `phase` 只有 `running`、`stopping`（收的途中）、`stopped`（daemon 下的 stop：行程不在、表上還在）、`sleeping`（11-03 procs § 8：daemon 收工〔ctl 的 stop、Ctrl+C〕時所有還活著的 proc，行程不在、表上還在；11-05 起也能 `sleep 名字` 手動睡；再開自動 wake，見 [aos-daemon](../../impls/aos-daemon/README.md)）；暫停中是子 loop 自己 state.json 的事，表上不轉述。沒有 `--kind`（11-02 拿掉，給了＝`FlagUnknown`）；舊說法「ls 只看得到還在跑的」已翻：已知非 0 留 stopped＋reason，stop／sleep 留列；退 0 才下表（使用者「把--kind刪掉，XXX後面可以接-- ... 也就是附加argv參數。改成子項結束後不留名單」）。

- **哪個 daemon**（N-63 hub 型變數）：`--daemon` ＞ `$AOS_DAEMON` ＞ **呼叫當下 cwd 的 `./.stack`**（11-05 [portable-flow 題 3](../../thinking/2026-11/05/portable-flow/05-衝突與方向題.md)，使用者選「沒設找 `./.stack`」：在 ws 裡起的 daemon，stack 就是 `ws/.stack`，`cd ws` 之後不設變數也找得到；不往上層找、不是資料夾＝`DaemonMissing`；11-11 曾議改成沒設就報錯，11-12 使用者：「只是猜.stack感覺可以留著?」，未定案、照現行）。三種來源找到的 D 一律轉成真實路徑（realpath，捷徑解開）再用（11-06 [no-pid](../../thinking/2026-11/05/no-pid/README.md) P3）（使用者 11-04 晚「AOS_DAEMON_STACK實在太醜，還是直接簡化成AOS_DAEMON就好了」），值＝那個 daemon 的 `$AOS_STACK`（它的窗都在這：`procs_state.json` 用預設名字；警告讀 `state_flux.json`（D 裡有 `daemon.json` 則照它的 `state_flux`，讀不到設定用預設，`null`＝不讀）；信箱與 proc 的 stack 裡 `loop.json` 的名字照 daemon 在 `procs_state.json` 頂層回報的 `procs_requests`、`procs_loop`，11-04 起，沒回報＝預設 `procs_requests/`、`loop.json`）；都沒有或不是資料夾＝`DaemonMissing`；子 proc 照常繼承。`AOS_DAEMON` 要給絕對路徑，相對路徑 cd 之後就對不上（從別的資料夾叫＝`DaemonMissing`；使用者「3」：維持、只寫清楚）。掛在 daemon 底下的子項不用自己設：daemon 起它時就把 `AOS_DAEMON` 設成自己的 stack（[aos-daemon「子項的 AOS_DAEMON」](../../impls/aos-daemon/docs/05-信箱.md#子項的-aos_daemon_stack11-02thinking-11-02-resident-bob-衝突-2)），子項裡叫 aos-daemon-ctl 直接接到它的 daemon。
- **掛信寄哪：一律直寄這台 daemon，不看 `AOS_KERNEL`**（使用者 11-07 選項框「aos-daemon-ctl 永遠直寄」，[os-impl 08](../../thinking/2026-11/06/os-impl/08-aos-daemon-ctl永遠直寄實作結果.md)）：`add`／`rm`／`stop`／`start`／`sleep`／`wake` 的 `procs_*` 信與 `ping`，一律寄進 D 的 ctl 信箱（`procs_state.json` 頂層回報的 `procs_requests`）；設了 `$AOS_KERNEL` 也不讀、不印提醒。分工：**aos-daemon-ctl＝指名要碰某台 daemon 的工具**（有 Linux 權限就能用；使用者 11-11 選項框「維持直寄，它就是『指名 daemon』的工具」，[C-47](../../docs/CONCEPTS/04-kernel.md)），**aos-agent＝經 kernel**——人平常用 `aos-agent ctl`，它照 `$AOS_KERNEL` 寄（[aos-agent README](../aos-agent/README.md)）。判官本身睡著或停著：這是設計系統的人要管的風險，手動 `aos-daemon-ctl wake 名字`（停著用 `start`）叫醒；程式不另做自動叫醒或繞過。daemon 的 ctl 信箱沒有 `new/`＝`MailboxMissing`。直寄＝繞過判官的白名單與 `max_running`，判官管不到；要真的擋，照 [kernel/docs/02](../../kernel/docs/02-kernel-modes.md)「誰能繞過 kernel：靠 Linux 權限」讓 ctl 信箱只給判官的帳號寫。
- **`--reply-to BOX`**（11-05 [edge-agent 題 2](../../thinking/2026-11/05/edge-agent/README.md)，使用者選「加 --reply-to 等回信」）：寄信的六個子命令（`add`／`rm`／`stop`／`start`／`sleep`／`wake`）都收；原樣交給 `aos-post send --reply-to`（BOX 從 cwd 轉絕對；信封裡存相對收信信箱的根，照 aos-post 11-05 起的慣例；BOX 不是信箱＝aos-post 的 `MailboxMissing`／`MailboxBad`、這支 `SendFailed`；給空的＝`ArgumentsBad`）。回信：daemon 套了＝`{"applied": true}`（`in_reply_to`＝印出來的信件名稱；壞信不回，原因在 state_flux 的 `mailbox_warning`）。`--timeout-s` 與 `--reply-to` 互斥（並給＝`ArgumentsBad`）；給了 `--reply-to` 這支**只寄、不等**（等回信是呼叫者的事，例：aos-agent `ctl` 每封都帶共用回信信箱，下條）。實測：`aos-daemon-ctl add --reply-to /tmp/rb --name c1 a1` → `/tmp/rb/new/` 一封 `applied: true`。
- **沒給 `--reply-to`＝寄出後看 `--timeout-s S` 秒（預設 3）**（11-06 [no-pid](../../thinking/2026-11/05/no-pid/README.md) P3）：寄信的六個子命令印完信件名稱，看 S 秒那封信還在不在收信信箱的 `new/`（daemon 認領了就不在）；還在＝stderr 一行提醒 `aos-daemon-ctl: warning: the letter LETTER is still in BOX after 3 s (the daemon is busy, paused or not running); it is applied when taken`，照樣退 0——信留著，對方認領時照套。不判 daemon 活不活、不碰 pid（daemon 可能忙、暫停、沒有運行）；信被領走也不表示已套用；要確定套了沒就 `--reply-to` 自己等，或 `ping`。
- **ping**（11-06 no-pid P3；daemon 那半在 P2）：寄一封 `{"ping": true}` 進 D 的 ctl 信箱、等回信，`--timeout-s S` 預設 3 秒（S 必須是大於零的數字）。收到＝stdout `replied in N ms`、退 0；沒回＝`aos-daemon-ctl: error: DaemonFailed no reply from the daemon at D within 3 s (busy, paused or not running; what its supervisor sees: aos-daemon-ctl ls, last line)`、退 1。不分它是忙、暫停（paused 那圈不認領信）、還是掛了——**寄信不回＝這次呼叫失敗**；想知道原因看 `ls` 最後一行（上一層 daemon 的看法，見 [04](04-aos-daemon-ctl續.md)）。
- **poke**（11-09，[thinking daemon-interrupt](../../thinking/2026-11/09/daemon-interrupt/README.md)）：`aos-daemon-ctl [--daemon D] poke [--ctl|--mail|--all]`＝按門鈴，叫 daemon 不等下一圈、立刻看一次檔。鈴不帶內容：**先寫檔再 poke**（用別的子命令或自己寫 ctl.json／procs_ctl.json、寄信），連 poke 幾下合併成最強的一種做一次。三種模式互斥、不給＝`--ctl`：`--ctl`＝立刻跑一圈讀 ctl、procs_ctl、對表、寫窗（不認領信箱、不跑身體）；`--mail`＝再加信箱（仍不跑身體）；`--all`＝提前一整圈，含身體（不管 `interval_ms` 到了沒，`max` 照算）。身體跑到一半不打斷，跑完立刻補看。成功不印、退 0。
  - **護欄**：讀 D 的 state 窗（daemon.json 的 `state`，預設 `state.json`）的 `pid`、`started_at_ticks`、`boot_id` 與 daemon 宣告的 `poke` 欄（三個訊號號碼，本機是 `{"ctl": 35, "mail": 36, "all": 37}`）；先開 pidfd、比 `/proc/sys/kernel/random/boot_id` 與 `/proc/<pid>/stat` 的 starttime，三者都對上才用 pidfd 送（比完到送之間 pid 被重用的空窗關掉）。這是「其他人不碰 pid」的唯一例外，pid 重用的殘餘風險由使用者承擔；送得出去不代表叫得動，不拿它判死活（[N-17 的 11-09 例外](../../docs/NORMS/05-基礎設施-窗/06-N-17.md)）。
  - **錯**（都退 1）：模式給兩個以上或多給參數＝`ArgumentsBad poke takes at most one of --ctl, --mail, --all and no arguments (usage: aos-daemon-ctl [--daemon D] poke [--ctl|--mail|--all])`；state 窗設成 `null`＝`StateMissing`；沒 state.json＝`DaemonMissing no aos-daemon running at D (no state.json)`；pid 不在、starttime 或 boot_id 對不上＝`DaemonMissing`（例 `… (pid 265480 is now another process)`）；state 讀不了或不是物件＝`StateBad`；state 沒宣告 `poke`＝`PokeFailed the state window at D declares no poke signals (not an aos-daemon, or one too old to poke)`；跨帳號／沙箱送不出去＝`PokeFailed cannot signal the daemon (pid N): permission denied`，不改走別的路。
  - 例：`echo '{"cmd": "pause", "seq": 7}' > "$AOS_DAEMON/ctl.json" && aos-daemon-ctl poke`（daemon 立刻暫停）、`aos-daemon-ctl add --reply-to box ../agents/bob && aos-daemon-ctl poke --mail`（信立刻被認領；不帶 `--reply-to` 的 add 會先等 3 秒看認領、poke 就晚了）、`aos-daemon-ctl poke --all`（提前跑 daemon 自己的身體一次）。`pause`／`resume NAME` 寫的是子項自己的 ctl，poke 叫不到子項。
- **起根前清掉 `AOS_DAEMON`**（11-10 cli-sweep Q5，使用者裁不修、文件提醒：「喔沒關係，root這東西本來使用者就要多注意一點。」）：`AOS_DAEMON` 對人是「對哪台說話」、對 daemon 起動時是「我的上司」；為了少打 `-d` 而 export 它，再起另一台根，那台會以為自己是下屬。起根的殼先 `unset AOS_DAEMON`（範本 `.env` 清不掉，外層贏）。
- **shutdown**（11-10 open-11：原本沒有停 daemon 本身的指令）：`aos-daemon-ctl [--daemon D] shutdown [--timeout-s S]`＝停 D 這台 daemon 自己。先照 poke 的護欄確認它活著（state 窗的 `pid`、`started_at_ticks`、`boot_id` 對得上 /proc；不在＝`DaemonMissing`，**什麼都不寫**——不然下次起來第一拍就照做那道 stop），再往它自己的 ctl（D/daemon.json 的 `ctl`，預設 `ctl.json`；設成 `null`＝`CtlMissing`）寫 `{"cmd": "stop", "seq": N}`（N 照 pause 的規則：ctl 的 `seq`＋1 與 D 的 state_flux `ctl_seq`＋1 取大；暫存 `.ctl.json.<pid>.tmp` 再改名），`poke --ctl` 叫它立刻讀，然後等行程退出（最多 `--timeout-s S` 秒，預設 15：收工時還活著的子項 SIGTERM、10 秒後 SIGKILL），印 N、退 0。S 秒內還沒退＝錯誤行 `aos-daemon-ctl: error: StillRunning the daemon at D (pid P) is still running after S s, so it is not safe to commit or copy yet (…)`、退 1（stop 留在 ctl，下一圈套用；再跑一次 shutdown 會再等。11-10 two-machines 改：原本是提醒行退 0，會讓人以為停乾淨、可以 push 了）。收工照 daemon 自己 ctl 的 stop 那套：表上還活著的子項留 `sleeping`、state.json `phase: stopped`、`code: 0`；再起 daemon 時第一拍比 state_flux 的 `ctl_seq`，同一道 stop 不重做，睡著的列開門自己醒。D 自己是別台 daemon 的 proc（state.json 的 `daemon` 不是 null）時另印提醒行：退 0 會從上一層的表拿掉，要留列就改用上一層的 `aos-daemon-ctl --daemon UP stop 名字`。
  - 實跑（11-10，假腦小樹）：`aos-daemon-ctl shutdown` 印 `1`、退 0；`ls` 變 `bob	sleeping	-	143	…`；再下一次＝`aos-daemon-ctl: error: DaemonMissing no aos-daemon running at D (pid 49020 is gone)`；重起 daemon 後 bob 自己醒、daemon 照跑，第二次 shutdown 印 `2`。
- **sweep**（11-10 清道夫，[thinking sweeper](../../thinking/2026-11/10/sweeper/README.md)）：`aos-daemon-ctl [--daemon D] sweep [--purge [-y]] [--dry-run] [--retention-days N|none] [--min-bytes N] [--stop-grace-s S] [--timeout-s S] [-j]`＝在這個指令裡立刻跑一輪清道夫（跟常駐列 `_sweeper` 的 `aos-sweeper` 同一套 `py/aos_sweep.py`，`D/.sweeper.lock` 的 flock 錯開；常駐列 pause、stopped、沒掛都照跑）。只管 D 這台：表上各列與預設小格 `D/procs/*/`，不往子 daemon 底下走。
  - 一輪：表上各列 ≥ `--min-bytes`（預設 1 MiB）的 stderr 封存成 `<stack>/stderr_archives/<UTC>.txt.gz` 再截 0；表外、證明活著且是這台生的子 loop 先寫 ctl stop，之後的輪、離寫 stop ≥ `--stop-grace-s`（預設 300）還在才 SIGTERM／10 秒後 SIGKILL；zombie 與認不出的只報；daemon 不在不碰行程。**保留期只有明帶 `--retention-days` 才刪**（常駐列預設 7 天；人叫一次不照預設偷刪，代定）。
  - `--purge`：刪這台所有清道夫寫的封存（不管保留期），終端上先問 `[y/N]`、`-y` 不問；不封存、不碰 stderr 與行程。`--dry-run` 只印、什麼都不動。
  - 輸出一事一行（`NAME: archived …`、`archives: N file(s), M bytes`、`bad files: N`、`procs/NAME: pid P: …`）；`-j` 印整份 JSON。錯：`ArgumentsBad`（多給參數、`--purge` 配 `--min-bytes` 等、`--yes` 沒配 `--purge`、`--retention-days 0`）、`SweepBusy`（等 `--timeout-s`，預設 30 秒，拿不到鎖）、`StateMissing`／`StateBad`（表讀不了）、`DaemonMissing`。
  - 跟 `prune` 不同：prune 下表久沒動的列、不碰檔；sweep 管 stderr 封存與表外行程、不改表。prune 原樣保留（清道夫沒覆蓋它）。
- **Python 呼叫者的時鐘期限**：共用 `daemon_ctl.ask`／`ping` 可指定 keyword-only `timeout_cycles=N`，與 `timeout_s` 擇一；兩者都省略仍為 3 秒。這是套件 API；本指令的 `ping --timeout-s` 與其他人用等待不變。兩鐘、參數檢查與錯誤詳見 [py/README](../../py/README.md)。
- **回信信箱（共用）**：`ping` 與 aos-agent 等回信都用同一個共用信箱、靠回信的 `in_reply_to` 認自己那封：呼叫者有 `$AOS_STACK`＝`$AOS_STACK/daemon_reply/`；沒有（人殼）＝`<D>/<ctl 信箱>/reply/`（預設 `<D>/procs_requests/reply/`）。只認 `in_reply_to` 是自己的，領了就 done；沒人領的回信超過 10 分鐘（照 `sent_at` 算）由下一個來拿信箱的人收掉（垃圾回收，不是判死活）。共用實作在 [`py/daemon_ctl/`](../../py/README.md)（寄信、回信信箱、ping 在 `py/daemon_ctl/post.py`）。
- **add／rm＝投信**（信箱模式，N-28、N-54）：信箱名照 daemon 在 `procs_state.json` 回報的 `procs_requests`（11-04 起 daemon.json 沒寫也開、預設 `procs_requests`；回報 `null`＝沒開＝`MailboxMissing`），沒有 `new/`＝`MailboxMissing`（daemon 還沒起）；stdout 印 aos-post 的信件名稱；daemon 下一圈才套，結果看 ls（壞信在 state_flux 的 `mailbox_warning`）。rm＝`{"procs_removed": [名字]}`；先停再拿掉，stack 不清。
- **做完的同名再 add＝重新起**：信箱模式下子項做完（done）daemon 就從期望表拿掉（11-02），再投一封同名的 add 就再跑一次，不用先 rm。出錯結束（任意 proc 退非 0）的不拿掉、留 `stopped`＋`reason`，同名 add 不會把它拉起來，要 `start`（11-05）。
