## 逐支說明

> **分層（[C-74](../../docs/CONCEPTS/01-設計理念/02-C-51.md#分層10-22-使用者定)）**：`aos-clock` 擱置中、不歸層。（基礎層、標準庫那幾支只有 C++ 版，見 [impls](../../impls/README.md)。）

- **`aos-tools - 一個 agent 資料夾一份工具註冊檔（tools.json），登記這隻 agent 能叫哪些工具`**（決定與代定 [thinking 10-28 aos-tools](../../thinking/2026-10/28/aos-tools/README.md)）
  用法 `aos-tools [--file F] add [--replace] [-n N] [--no-cache] [--env-file FILE] [--envs K=V]... XXX｜rm XXX｜ls [-l｜-j]｜get XXX｜call NAME [ARGS_JSON]｜override BASE...`（`--file` 子命令前後都收）（短名照 [human-cli H4](../../thinking/2026-11/06/human-cli/03-慣例草案.md#h4-旗標命名) 的常用預設：`-n`＝`--name`、`-j`＝`--json`、`-h`＝`--help`；`--file` 不給短名），註冊檔＝`--file`＞`./tools.json`（沒有＝沒登記任何工具）。`aos-tools --help` 印頂層一份、`aos-tools 子命令 --help` 印那個子命令的一份（英文，到 stdout、退 0）；`aos-tools --help 子命令` 印的是頂層。
  **印什麼**（human-cli H8）：`add` 成功印一行 `added NAME -> PATH`（PATH 是從 cwd 算出的絕對路徑；存法保留使用者寫法，見下「存法」）；`rm` 每拿掉一個名字印一行 `removed NAME`；`ls` 一行一個 `名字 TAB 說明第一句`（11-10 深夜使用者「默認是給出短板，然後用-l才是給長版」）、`-l` 一行 `名字 TAB 種類 TAB 路徑 TAB FROM TAB STORED TAB ENV`、`-j` 一行 JSON 陣列；`get` 每個工具一行 JSON。JSON 裡保留完整 tooldef；brain／aos-mcp 給模型時只取 `description`／`parameters`，`env`／`errors` 等不進模型的工具定義。
  **登記格的 `env`**（11-05 晚 [agent-knowledge R1](../../thinking/2026-11/05/agent-knowledge/03-接進agent與工具說明.md#給新功能隊的請求本輪沒動他們的檔)）：`{"名": {"path": …, "env": {"AOS_KNOWLEDGE": "/x/knowledge/aos"}}}`，`call` 時合進那次呼叫的環境（蓋過外面同名的）；值照字面、不當路徑解；鍵 `[A-Za-z_][A-Za-z0-9_]*`、值字串，別的＝`RegistryBad`。`add --env-file FILE` **只記位置**（11-10 [aos-tools-cli](../../thinking/2026-11/10/aos-tools-cli/README.md) 步 3，使用者 Q1）：登記格選填 `env_file`（寫法同 XXX：絕對存絕對、相對存相對寫進的那份檔；手寫可用指示詞），內容不進登記檔；add 當下檔在就讀一次只為驗格式與 hub 提醒，不在＝warning 照登記；每次 `call` 才讀（`${VAR}` 照那次呼叫的環境展開），不在＝`PathMissing` 不跑（使用者 N4「報錯不跑」）、壞＝`DotenvBad`，訊息帶工具名與 `檔#/tools/名/env_file`。`--envs K=V` 可重複、同鍵最後一個贏、V 可空，存進 `env`（寫進 F）；`--replace` 整項重寫、不保留舊 env／env_file。優先順序（後面的贏）＝繼承環境 ＜ env_file ＜ env；`AOS_STACK` 另照下面的小格規則。`ls`／`get` 不印登記格 env 的值。工具定義的 `env` 列出所需 hub；add 時當下環境與這次 file／envs 都沒有的名稱合成一行 `aos-tools: warning: …`，仍登記、退 0。用途：覆蓋層也能替一隻換知識庫。
  **`$override`**（11-10 [aos-tools-cli](../../thinking/2026-11/10/aos-tools-cli/README.md) 步 4；使用者 N1（11-10 改口「null就是null，我們不做rm功能」「寫成 null，讀的人當它不是工具」）、K1「現在就寫 $override」、「$override希望能支援array…跟$ref一樣」）：F＝`{"$override": BASE, "tools": {名: 登記, 不要的: null}}`——BASE 是路徑字串（相對從 F 的資料夾算、絕對）、指示詞物件（每次用到才解）或它們的陣列（空陣列＝沒有底檔）；疊法＝**照順序疊，後面蓋前面**（使用者 11-10「都按你的建議」）：每個底檔先展開成它自己的序列，照陣列順序接起來，最後接這份自己的，一份一份補丁式往下合（物件逐 key 合，其餘整個蓋過去）。**合併沒有刪除，`null` 只是值**（11-10 改口：「等等，null表示拿掉...不用，null就是null，我們不做rm功能」「寫成 null，讀的人當它不是工具」）：讀的時候值是 `null` 的工具格不算工具，工具格裡值是 `null` 的欄位＝當沒設。底檔可以再 `$override`；菱形＝序列裡出現兩次、照樣疊；環以真實路徑判＝`RegistryBad`，指不到＝`PathMissing`；`add`／`rm` 只寫 F（`rm` 底檔也有的名字＝寫 `"名": null`、只有 F 記的＝刪 key）；`override BASE...` 子命令寫這一行（F 不在就建、已有就改指標、F 有自己的工具卻沒有 `$override`＝`RegistryBad`）。aos-agent `tools` 與 agent-fsm 的身體用它，說明在 [aos-agent docs/03](../aos-agent/docs/03-tools覆蓋層.md#tools-覆蓋層)。11-10 前的 `--overlay O`／`{"add","rm"}` 拿掉了，舊檔 `RegistryBad`、要重建。
  **三種登記對象**（種類照 aos-exec 的認法，N-61）：資料夾（裡面 `_tooldef.json`、有 `_metainfo.json` 一起給；11-04 起不帶副檔名的 `_tooldef`／`_metainfo` 不認）、沒 `+x` 的 JSON 檔（頂層 `_tooldef` key）、有 `+x` 的 python／可執行檔（`XXX --tooldef` 在 stdout 吐定義，結果依檔的 mtime＋大小快取在 `$AOS_STACK/tooldef_cache.json`（11-10 aos-tools-cli 步 2；不符重跑並寫回、檔壞重建、沒設 `AOS_STACK` 不快取；登記檔不再存快取、登記格 `cache` 只收 `false`，樣板 `stack.gitignore` 擋它）；`add --no-cache` 那一項記 `"cache": false`、不讀不寫快取檔，之後 ls／get 每次重跑 `--tooldef`，手寫或 `aos-json set …#/tools/名/cache false` 也行；`--replace` 沒帶 `--no-cache`＝回到有快取；dir／json 給 `--no-cache`＝`ArgumentsBad`、手寫 `false`＝`RegistryBad`，[thinking § 11-03](../../thinking/2026-10/28/aos-tools/04-11-03-no-cache.md)）；不符合就報錯。工具定義＝OpenAI function 物件去掉 `name`。工具名＝`--name`＞檔名去副檔名（資料夾名），只收 `[A-Za-z0-9_-]`；撞名 `ToolExists`，`--replace` 蓋掉（11-10 N3 改名）。
  **存法**：`{"tools": {名: {"path": 絕對路徑, "cache"?: false}}}`；add 的相對路徑從 cwd 算；存的保留使用者的寫法（11-10 午 TC）：給絕對存絕對、給相對存相對「寫進的那份檔（覆蓋層或註冊檔）的資料夾」、`--path-json JSON` 原樣存（字串或指示詞，例 `{"$env": "AOS_HOME", "$path": "/…"}`）；手寫的相對路徑從註冊檔的資料夾算（範本用這個，搬家不斷）。有 `$ref`／`$env` 就交給 aos-json 解與改（`$ref` 陣列＝拆成好幾份，add 寫進最後一份）。
  **叫**：`call 名`——資料夾、JSON、可執行檔都用 `aos-exec 路徑`，arguments 原樣從 stdin 進（P-41）。有父 `AOS_STACK` 就由 call 設工具的小格 `$AOS_STACK/tools/<登記名>/`；登記格 env 不能蓋掉它。父沒設時也不採登記格的 `AOS_STACK`，交 aos-exec 給預設。brain／act／aos-mcp 只傳各自的 stack，不自己再拼工具名。結束碼是工具的（被訊號殺＝128＋N）。**退非 0 時 stderr 有 `aos-tools: error:` 這行＝我錯；沒有＝下層（工具）的碼**（11-05 stdio-unify R8）。
  **錯**：stderr 一行 `aos-tools: error: 代號 原因`、退 1（`ArgumentsBad`、`FlagUnknown`、`CommandUnknown`、`RegistryBad`、`PathMissing`、`ToolDefMissing`、`ToolDefBad`、`NameBad`、`ToolExists`、`ToolMissing`、`DotenvBad`、`DirectiveBad`、`CommandMissing`、`WriteFailed`）；ls／get 碰到登記了但壞掉的工具也報錯。原因後面的括號只指那一層的路（human-cli H10）：不給子命令＝`ArgumentsBad missing subcommand (add, rm, ls, get, call; see aos-tools --help)`、不認得的子命令＝`CommandUnknown` 同一個括號；子命令層缺參數、多給參數、開關帶值＝括號是那個子命令的 usage（例 `add needs one XXX (usage: aos-tools [--file F] add …)`）；子命令前不認得的旗標＝`FlagUnknown` 不附括號；子命令後不認得的旗標＝`(see aos-tools 子命令 --help)`。要 PATH 上有 aos-exec、aos-json。

- **`aos-round` 不在了**（使用者「aos round這東西還沒刪掉嗎」「刪掉」）：agent 的 `loop.json` 直接叫 aos-fsm；它跑的 `lib/agent/round/` 那套格 11-03 也刪了（概念在 proto8/archive/agent-round-concepts/）。

- **`aos-eca-turn - 外部 coding agent（claude／codex）的一輪：從 stack 的 queue 認領一批、交給 CLI 就收信、回答接進 history`**（使用者「aos eca turn」、C-54 R13 `aos-<領域>-<功能>`；設計 [thinking 10-30 eca](../../thinking/2026-10/30/eca/README.md)）
  用法 `aos-eca-turn [--one] [--on-empty stop|idle] [--on-busy yield|answer] [--prompt FILE] DEF_DIR`（DEF_DIR＝定義資料夾的絕對路徑）（旗標寫在 DEF_DIR 前後都收，11-11 P-44 續）。定義＝`templates/eca-claude` 那種（頂層 `cli.json`、選填 `tools.json`〔aos-tools 登記檔，`cli.json` 的 `tools` 可改指；cli_session 接上 aos-mcp，`--ws $AOS_WS --stack $AOS_STACK`〕），定義不被寫、寫的都在 `$AOS_STACK`。一次答一批（使用者 11-03「每次aos-eca-turn就是把所有信一起丟進去(當然，是有順序的)」「一批幾封無上限」）：`queue/cur/` 與 `new/` 的信全部、照處理順序（`new/` 用 `aos-post take-all`，沒有上限；跑的期間才來的留給下一輪；順序照 `proto8/py/aos_ws.py` 的 `letter_key`：有序在前照名字、無序在後照名字，11-03 aos-post 改版起名字不是有序的也照樣答）→ 各封 content 用一個空行接成一段，經 `proto8/lib/agent/cli_session.py` 的 `ask` 交給 CLI（畫面開著貼字、沒開 `--resume`）→ **交出去那一刻**每封一則 user 接進 `history.jsonl`、收信（使用者「對於eca來說，他收到信後，丟給claude之類的，然後這封信就算是完成了」，[eca 20](../../thinking/2026-10/30/eca/20-11-03-交出去就收.md)）→ 答完 assistant 接進 history；CLI 中途掛掉＝邊緣狀況，那批不自動重答（要重答再 say）；turn 死了外部 CLI 跟著收（11-10 坑-52，Linux：非互動起的 CLI 設 `PR_SET_PDEATHSIG`＝SIGTERM，turn 被 `kill -9`／OOM 時 CLI 收 SIGTERM；tmux 畫面裡的 CLI 不在此列，見 [aos-eca](../aos-eca/README.md)），沒有 `current.txt`；讀信 `aos-post see`、收信 `aos-post done`；壞信丟掉、記進 `$AOS_STACK/mailbox_warning.txt`；11-04 起不寫 `$AOS_STACK/eca.json`（沒人讀了，aos-agent 從 daemon 表找定義）。
  **`--on-empty`**：queue 空時 `stop`（沒給；退 10＝loop 收工）｜`idle`（退 0＝loop 隔 `interval_ms` 再來）；壞值、跟 `--one` 一起給＝`ArgumentsBad`；不讀環境變數。**`--on-busy`**：`yield`（沒給）＝lock 拿不到、有人接在 tmux 畫面上、`busy.txt` 在＝還沒交出去：這輪退 0、信留 `cur/`、history 不動（`--one` 照錯退 1）｜`answer`＝照常答不退讓（lock 等、有人接著照樣貼、`busy.txt` 等它消失，共用 `timeout_ms` 期限，逾時 `ReplyMissing`）。`--one`＝工具形（stdin `{"prompt"}` → stdout，對話在 `$AOS_STACK` 這格本身；走 `agent.cli_session.call_main`，輸出共用 `lib/tool_io.py`，現在只剩它在用）：**要有效的 `$AOS_WS`**，沒設或不是資料夾＝`WsMissing`（不再當成 `.`）；`--one` 的錯照 lib 工具契約，stderr 與 stdout 各一行 `<定義資料夾名>: error: 代號 原因`、退 1。lib 的 `claude`／`codex` 不走 `call_main`，走 `lib/agent/agent_tool.py` 的 `ask_cli`，兩邊共用 `cli_session.ask`（11-06 json-argv J2）。**`--prompt FILE`**＝開場白檔（history 與 queue 都空時當第一則 user 投進 queue）：相對路徑從定義資料夾算；給了但不是檔＝`PromptMissing`、空字串或跟 `--one` 一起給＝`ArgumentsBad`；**沒給＝沒有開場白**（不找 `prompt.txt`；`cli.json` 寫了 `prompt` 不看）。使用者 11-04「不該在json中指定檔案名稱，應該改成用旗標指定」，[eca 21 § 翻案](../../thinking/2026-10/30/eca/21-11-04-開場白檔可指定.md#11-04-翻案開場白改成-aos-eca-turn-的旗標)。定義的 `loop.json` 這樣叫：`{"exec": {"argv": ["aos-eca-turn", "--on-empty", "idle", "--on-busy", "yield", {"$env": "AOS_CD"}], "timeout_ms": 900000}}`。
  **錯**：stderr 一行 `aos-eca-turn: error: 代號 原因`、退 1（`ArgumentsBad`、`FlagUnknown`、`AgentBad`、`StackMissing`、`PromptMissing`〔`--prompt` 給的開場白檔不在〕、`HistoryBad`、`PostFailed`、`WriteFailed`，加 cli_session 的 `WsMissing`〔只有 `--one`〕、`CfgMissing`、`CfgBad`、`ToolsMissing`、`CliMissing`〔含 aos-mcp 不在 PATH〕、`CliFailed`、`ReplyMissing`、`TrustMissing`〔11-10 深夜：畫面開著而 claude 停在「信不信任這個資料夾」選單＝不貼題目、信留著；人 attach 自己選，或在那個資料夾手動開一次 `claude` 選信任〕）。aos-post 的 stderr 原樣透出、不拿它當原因（11-05 stdio-unify R10），這支只多寫自己那行 `PostFailed aos-post X exited N`。要 PATH 上有 aos-post（接了工具還要 aos-mcp、aos-tools）。
  **history 被改過＝開新對話**（11-10 [self-family](../../thinking/2026-11/10/self-family/README.md) ⑩，解 10-30 eca 09「停著時改 history 再繼續」縮水版）：每輪 assistant 接進 history 後，把整份 history 的 sha256 寫進小格的 `.history_sum`；下一輪交出去前算出來不一樣（人用 `aos-agent history` 或直接改了）＝`drop_session`、開新的 claude 對話，題目前面照換台那套帶改過的 user／assistant 紀錄（上限 `reseed_bytes`），stderr 一行 `warning: history.jsonl was changed since the last turn; starting a new claude conversation that carries the changed record`。這一輪中間被改（claude 叫 `self_history`）＝`.history_sum` 寫 `edited`、下一輪照樣開新的。畫面開著時不換、只 warning。
