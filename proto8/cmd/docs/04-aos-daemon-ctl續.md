- **where --stack 名字**（11-03）：印這個子項的 stack＝procs_state 那一列的 `stack`（預設 `<D>/procs/<名字>`、或 add `--stack` 給的；表上存相對 daemon stack、這裡拼回絕對印一行、結尾不帶 `/`；拿 stack 只在 `cell_of` 一處）。**只認 daemon 表上的**（`running`、`stopping`、`stopped`、`sleeping` 都算；使用者「一個proc在daemon中的狀態，包括運行中、暫停中，除此之外就是不存在於daemon了」「拿下名單後，對於daemon來說他就不存在了，自然找不到」）：表上沒有＝`ProcMissing`、退 1，它的 stack 資料夾還在也一樣。`procs_state.json` 不在＝`StateMissing`；只讀表，不寄 ping、不判 daemon 活不活，照表印。只收 `--stack`（沒給、多給位置參數＝`ArgumentsBad`）。
- **ls**：讀 `procs_state.json` 的一張表 `procs`（切檔的 `$ref` 合回來；11-03 起沒有種類欄），一行「名字 TAB phase TAB pid TAB code TAB ws TAB reason」（reason 裡的控制字元——TAB、換行、CR、ESC——換成空白，11-05 第二輪）（pid、code、ws、reason 沒有＝`-`，stopped、sleeping 的 pid 是 `-`；ws 印絕對），表後多一行上一層的看法（下條）；`--json`＝一行 `{"procs": 表, "daemon": 上一層 或 null, "supervisor": {"phase", "reason", "note"} 或 null}`（`procs` 列照 procs_state 原樣：`pid`、`started_at_ticks`、`phase`、`code`、`signal`、`stack`、有給 ws 的帶 `ws`、`exec`、`def`、`reason`；路徑欄拼回絕對）。**`reason`**（11-05）＝出錯結束（loop 型退非 0，含被訊號打掉；例搬家沒帶定義、身體報錯）留成 `stopped` 的列，daemon 寫的原因（英文：wake／start 後 3 秒內＝`failed to start: …`、其他＝`failed while running: …`，接 proc 的 stack 裡 stderr 最後一行），`null`＝沒有；修好用 `start` 起、不要了 `rm`。**做完的不在表上**（表上是 `running`、收的途中 `stopping`、daemon 停掉或出錯結束的 `stopped`、收工時還在跑的 `sleeping`）：子項退 0（`done`、別人直接寫它 ctl 的 stop）、exec 型、接回的結束了 daemon 就拿掉（11-02），**結束碼看 daemon 的 log**（`aos-daemon --enable-logs` 時 stdout 每個子項起來一行、結束一行 JSON，`{"at","name","phase","pid","code","signal"(,"ws")}`），所以 code 那欄平常是 `-`（daemon 停掉的 `stopped` 是 0；出錯結束留下的 `stopped` 列有碼）。
- **ls 最後一行＝上一層 daemon 的看法**（11-06 [no-pid](../../thinking/2026-11/05/no-pid/README.md) P3，使用者「想想看，假如你平常打API呼叫某個saas服務，他沒回代表啥？」「詢問daemon也是一個正統管道」）：ls 不判這台 daemon 活不活、不碰 pid／`/proc`、不寄信，只讀檔——讀 `procs_state.json` 頂層的 `daemon` 欄（管這台的上一層；P2 起 daemon 寫），再讀**上一層**的 `procs_state.json` 裡這台那列，stdout 印一行 `# ` 開頭的：
  - 根（`daemon` 是 null）＝`# root daemon (no supervisor)`；
  - 有上一層＝`# supervisor UP: PHASE`（那列的 phase；有 reason 接 ` (REASON)`）；
  - 看不到＝`# supervisor UP: NOTE`，NOTE 三種：`relative path as the daemon inherited it; cannot tell where it is`（根從人殼繼承了相對路徑）、`no readable procs_state.json there`、`this daemon is not on its table`。

  `--json` 的 `daemon`＝UP（根＝null），`supervisor`＝`{"phase", "reason", "note"}`（看得到時 `note` 是 null，看不到時 `phase`／`reason` 是 null；根＝整個 null）。表空也印這行；`--json` 沒有這行文字。拿文字 ls 當資料的，跳過 `#` 開頭那行。要問這台此刻有沒有在回信：`aos-daemon-ctl ping`（[03](03-aos-daemon-ctl.md)）。
- **錯**（11-05 stdio-unify R1）：stderr 一行 `aos-daemon-ctl: error: 代號 原因`、退 1；提醒行 `aos-daemon-ctl: warning: 句子` 可以退 0。代號：`ArgumentsBad`（不給子命令也是）、`FlagUnknown`、`CommandUnknown`、`DaemonMissing`（找不到 D）、`DaemonFailed`（`ping` 時限內沒回信）、`MailboxMissing`、`PathMissing`、`EntryBad`（add 走入口時：讀不懂、指不到、繞圈）、`LoopBad`（loop 設定讀不了或不是物件）、`StateMissing`（`procs_state.json` 不在）、`StateBad`、`ProcMissing`（表上沒有）、`CtlMissing`（stop／sleep／pause／resume：沒有 ctl＝exec 型）、`PhaseBad`（stop／start／sleep／wake 用在不對的 phase，11-05）、`WriteFailed`（pause／resume 寫不了 ctl）、`CommandMissing`（PATH 沒 aos-post）、`SendFailed`（aos-post 退非 0，它的 stderr 照轉）。原因後面的括號只指那一層的路（human-cli [H10](../../thinking/2026-11/06/human-cli/03-慣例草案-續.md#h10-錯誤訊息與結束碼接三扇門)）：不給子命令＝`ArgumentsBad missing subcommand (add, rm, stop, start, sleep, wake, pause, resume, ls, where, ping; see aos-daemon-ctl --help)`、不認得的子命令＝`CommandUnknown` 同一個括號；子命令層缺參數、多給參數、開關帶值、`--ws`／`--stack`／`--reply-to` 給空的＝括號是那個子命令的 usage（例 `rm needs one name (usage: aos-daemon-ctl [--daemon D] rm [--reply-to BOX] NAME)`）；子命令前不認得的旗標＝`FlagUnknown` 不附括號；子命令後不認得的旗標＝`(see aos-daemon-ctl 子命令 --help)`。不再把全部子命令的 usage 塞進一行。要 PATH 上有 aos-post。`--help`（R3）印英文說明到 stdout、退 0：子命令前印頂層、子命令後印那個子命令的；Ctrl-C＝退 130。

例：`aos-daemon-ctl add --stack /tmp/c --name c ../agents/clock`、`aos-daemon-ctl pause c`、`cat /tmp/c/state.json`、`aos-daemon-ctl resume c`、`aos-daemon-ctl stop c`（`ls` 見 `c TAB stopped TAB - TAB 0 TAB -`）、`aos-daemon-ctl start c`、`aos-daemon-ctl sleep c`（`ls` 見 `c TAB sleeping …`）、`aos-daemon-ctl start c`（`PhaseBad c is sleeping; use wake (start only starts stopped ones)`）、`aos-daemon-ctl wake c`、`aos-daemon-ctl rm c`（`/tmp/c` 留著）、`aos-daemon-ctl ping`（`replied in 120 ms`）。

自帶時鐘的 daemon 在 `ls` 中會有普通 proc `_tick`（或 `tick.name`）；`pause _tick`／`resume _tick` 可停走時間，其他工作照跑。`procs_state.json` 頂層另有 `tick` 觀察值（含繼承的時鐘；壞檔為 null、沒設 `AOS_TICK` 則省略），它不是 `ls --json` 的額外欄位。改時鐘設定先 sleep 整台、再改、再 wake／重開；詳見 [daemon 時鐘](../../impls/aos-daemon/docs/02-看寫法決定怎麼起.md#自帶時鐘-tick選填)。
