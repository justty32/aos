- **`aos-clock - 把時鐘檔的回合數往前走一格`**（NAME，C-54 R1）
  用法 `aos-clock [FLAGS] FILE`（Python）：時鐘往前走一格（C-44：只是時鐘，不包任務、不保證什麼）。FILE 裡是回合數（十進位＋換行），讀出 n、寫回 n＋1 就退 0；FILE 不在或空＝0（第一次寫 1）；寫進 n＋1＝第 n 回合結束、第 n＋1 回合開始，mtime＝這回合從什麼時候開始。先寫同資料夾的 `.名字.pid` 再改名蓋過去（N-05），不 fsync，stdout 不吐東西。**命令列**：唯一的位置參數就是 FILE（必給、只能一個、相對路徑從 cwd 算）；FILE 照字面用，`#` 不切指標（它是時鐘檔不是設定檔）；目前沒有旗標（旗標表是空的、走 `aos_flags`，`--` 結束旗標）。**自己的錯**退 1、stderr 一行 `aos-clock: error: 代號 原因`、FILE 不動：`ArgumentsBad 原因 (usage: aos-clock [FLAGS] FILE)`（11-05 stdio-unify R5：原因在前；沒給、多給；不認得的旗標是 `FlagUnknown unknown flag … (usage: …)`）、`ClockBad cannot read clock file FILE: …`（例：它是資料夾）、`ClockBad clock file FILE is bad: …`（去掉前後空白後不是 `[0-9]+`、或已到 signed 64-bit 上限；負號、全形數字算壞。**11-07 sol 審查 #9** 起讀法跟讀時鐘的人同一套：前後空白、`\r\n` 不算壞，空檔＝0、寫 1——原本空檔報 `ClockBad`，daemon 的 `_clock` 重起三次就停、整棵樹時鐘卡在 0）、`WriteFailed cannot write clock file FILE: …`（資料夾不在或沒寫入權限；不替人建資料夾，暫存檔會清掉）。節奏、停、只走 N 回合交給 loop（`max`、`interval_ms`、ctl 的 `pause`）；同一個 FILE 兩個人同時叫 aos-clock 不管。**通常是根 daemon 的鐘列在叫它**（11-09 clock-decouple 起 daemon 程式不認它，鐘只是範本裡一列普通 proc）：根 daemon.json `procs` 寫 `"_clock": {"exec": {"argv": ["aos-clock", {"$env": "AOS_DAEMON", "$path": "clock"}]}, "interval_ms": 1000, "auto_restart": true, "stuck_after_ms": 10000}`，根定義資料夾 `.env` 寫 `AOS_CLOCK=${AOS_STACK}/clock`，大家讀的就是它寫的這個檔；寫法的坑見 [aos-daemon docs/02](../../impls/aos-daemon/docs/02-看寫法決定怎麼起.md#時鐘普通一列)。

- `aos_flags.py`（在 [proto8/py](../../py/README.md)）：命令列旗標解析 `parse(argv, 旗標表)` 回 `(opts, [XXX, args...])`（`--x V`／`--x=V`、重複給最後一個算、`--` 結束旗標、第一個不是旗標的參數起原樣；不認得＝`FlagUnknown`、缺值＝`ArgumentsBad`）。cmd 的 Python 支都用。11-06 [json-argv](../../thinking/2026-11/05/json-argv/06-實作步驟.md) J5：切 token 那段改包 `lib/tool_io.py` 的 `tokenize_flags`（跟 lib 工具同一份），`parse` 自己只管旗標表、短名、`--help`；行為不變。
  11-05 [stdio-unify](../../thinking/2026-11/05/stdio-unify/README.md) 加三扇門的共用小函式：`aos_flags.HELP`＝英文說明，設了 `parse` 在旗標的位置（子命令後再 parse 也算）看到 `--help` 就印到 stdout、退 0（R3）；`die(程式, 代號, 原因)`＝stderr 一行 `程式: error: 代號 原因`、退 1（`also_stdout=True` 兩邊各一行，給腦用的工具形）；`warn(程式, 句子)`＝提醒行 `程式: warning: 句子`（R1）；`error_line` 只組那一行；`run(main)`＝Ctrl-C 不吐 traceback、退 130（R12）；11-06 J5 加：讀的人先關了 stdout（`| head -1`）＝不吐 traceback、退 141（接 `BrokenPipeError`、stdout 換成 /dev/null；不把 SIGPIPE 設回預設，免得寫子行程 stdin 的支在子行程先退時被無聲打死）。
  11-06 [human-cli](../../thinking/2026-11/06/human-cli/03-慣例草案.md) 加兩樣：**短名**（H4）——常用預設表 `aos_flags.SHORT`（`-h -j -t -d -n -w -s -f -y`），各支用 `parse(…, short=("-t",))` 挑自己有的，或傳自己的短名對照表（每支各自定、可不同義；11-07 使用者裁定 sol 審查 #22）；`-h` 內建（認 `--help` 處都認，所以 `aos-clock -h` 也印說明）；不黏值、不併、不帶 `=`（`-tann`／`-jf`／`-t=x`＝`FlagUnknown`）。**確認**（[H11](../../thinking/2026-11/06/human-cli/03-慣例草案-續.md)）——`confirm(程式, 問句, yes)`：`yes` 或 stdin 不是終端＝照做不問；終端＝stderr 問 `程式: 問句 [y/N] `，只有 `y`／`yes` 算答應；答 No 呼叫者印 `warning: nothing done`、退 0。

執行中狀態（`stage.txt`、`plan.txt`、`current.txt`）在 `$AOS_STACK`（預設 `$AOS_WS/.stack/`）；工作區只放交辦的東西與成果（題目 `new/` → 認領 `cur/` → `done/`，答案 `out/`）；定義資料夾不被寫，所以同一個 agent 可同時被兩個工作區跑。結果＝工作區內容；沒有別的結果通道。
