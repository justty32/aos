## aos-eca-screen - eca 的 screen 子介面身體（11-04）

`templates/eca-claude/screen/_entry`＝`["aos-eca-screen", "--eca", ".."]` 叫它，ECA_DIR＝`..`（eca 資料夾，入口的 cwd 是它自己的資料夾）。aos-agent 照子介面規格叫入口 `動作 [--detach]`，aos-exec 把它接在入口 argv 的最後面，所以 ECA_DIR 是寫在前面的旗標（11-05 隊長代定 D6：aos-exec 把呼叫者的參數接在入口 argv 最後面，ECA_DIR 改成子命令前的旗標 `--eca`，入口寫死的部分才放得進去）。人不直接打，經 `aos-agent open／close／watch`；介面規格在 [thinking aos-agent 03/02](../../thinking/2026-11/04/aos-agent/03-種類與契約/02-子介面規格.md)。

- `aos-eca-screen --eca ECA_DIR open [--detach]｜close｜watch`（11-05 [stdio-unify](../../thinking/2026-11/05/stdio-unify/README.md) R6：照 P-44 `程式 [旗標] 子命令 [旗標]`、用 `aos_flags.parse`；原本是 `<eca dir> open [-d]`，R6 先改成 `open [--detach] ECA_DIR`，D6 再把 ECA_DIR 搬成旗標）：吃 `AOS_STACK`（那隻的 stack）、`AOS_WS`；open／close／watch 的身體 11-04 從 aos-eca 原樣搬來（畫面＝tmux，Ctrl-] 跳出；socket 11-10 起不在 `<stack>/<kind>/` 裡，在 `${XDG_RUNTIME_DIR:-/tmp}/aos-tty-<uid>/<小格 realpath 雜湊>.sock`，由 `cli_cell.tty_socket` 算，`open --detach` 印的就是它）。錯：stderr 一行 `aos-eca-screen: error: 代號 原因`——`ArgumentsBad`（沒給 `--eca`、多給位置參數、不是 eca 資料夾）、`FlagUnknown`、`CommandUnknown`、`StackMissing`、`SessionBad`（正在答題時 close），加 cli_session 的。`attaching…`、`watching…` 是提醒行 `aos-eca-screen: warning: …`（R1、D5）。`aos-eca-screen --help` 印頂層一份、`aos-eca-screen 子命令 --help` 印那個子命令的一份（英文；`-h` 同 `--help`）。原因後面的括號只指那一層的路（human-cli [H10](../../thinking/2026-11/06/human-cli/03-慣例草案-續.md#h10-錯誤訊息與結束碼接三扇門)）：不給子命令＝`ArgumentsBad missing subcommand (open, close, watch; see aos-eca-screen --help)`、不認得的子命令＝`CommandUnknown` 同一個括號；子命令層的 `ArgumentsBad`（多給參數、沒給 `--eca`、不是 eca 資料夾）＝括號是那個子命令的 usage（例 `missing --eca ECA_DIR (usage: aos-eca-screen --eca ECA_DIR open [--detach])`）；子命令前不認得的旗標＝`FlagUnknown` 不附括號；子命令後的＝`(see aos-eca-screen 子命令 --help)`。
- **watch 遇 loop 不在了就走**（11-05）：watch 跟到一次回答結束才走；這一拍沒新的整行時看 daemon 表上 `stack` 是這隻的那列（11-06 [no-pid](../../thinking/2026-11/05/no-pid/README.md) P3，經 `py/daemon_ctl/table.py` 讀表、不碰 pid）——不在表上、或 phase 不是 `running`（例：答到一半被 `ctl sleep`／`ctl stop`／`ctl rm`），stderr 印提醒行 `aos-eca-screen: warning: watch stopped waiting, …` 後退 0（那半截回答不會再完）。閒著的 `running` 照舊等下一次回答；找不到 daemon、表讀不到＝看不出來、照等。
- **aos-eca-llm 11-04 晚刪了**（連同 `demo/eca-claude/llm/`）：使用者 11-04 晚「aos llm,tool這兩個，我希望他們的定位是跟aos post一樣，作為基礎工具」——eca 的模型改放定義的 `llm.json`（`{"model": "sonnet"}`），`proto8/lib/agent/cli_cfg.py` 每題讀定義 `llm.json` 疊 `$AOS_STACK/llm.json` 補 `--model`；看／改副本＝`aos-agent llm show／set model=haiku／reset`（aos-json 的語法糖），改定義＝人直接 `aos-json set <定義>/llm.json#/model x`。見 [thinking think-as-function 03 § 2、§ 4](../../thinking/2026-11/04/think-as-function/03-呼叫端.md)。
