# aos-eca — 外部 coding agent（claude／codex）的兩支指令

← [cmd](../README.md)｜範本：[templates/eca-claude](../../templates/docs/01-eca-claude.md)

- `bin/aos-eca-turn`：答一輪——從 stack 的 queue 認領一批、交給 CLI 就收信、回答接進 history。說明在 [cmd/docs/01](../docs/01-逐支說明.md#逐支說明)。
  **畫面開著的 claude 身改走收件口**（[eca-a2a-notify](../../thinking/2026-11/13/eca-a2a-notify.md)，使用者 11-13「1.a2a這個按照建議。馬上送，eca他會自己處理。say/chat被當成不是使用者打的，我覺得可以，真的有要的話，就自己open進去說。」）：一批信不貼字，改往 Claude Code 這個 session 自己的收件口（cross-session messaging 的 Unix socket）寫，一封一個署名信封，畫面顯示「› Message from @名字: …」、CLI 自己告訴模型這則不是它的使用者打的。署名＝信 body 的 `name`（`aos-agent say`／`chat` 對 eca 寄時填，見 [aos-agent](../aos-agent/README.md)），沒有＝`aos通知中心`（新信通知、時鐘信、goal 提醒、開場白、換台前情提要）；`name` 不接進 history。這條路不看 `--on-busy`：有人接在畫面上、正在跑一輪都照投（CLI 手上那步工具做完就讀到）；等回答時 queue 又來信也一封一封馬上投（`aos_eca/midturn.py`，slash 指令、hook 或 aos-post 出錯、投不出去、冷卻剛到那輪除外，那封留到下一輪）。socket 位置與有沒有收到靠畫面 hook 記在小格的 `a2a.json`、`a2a_acks.jsonl`（`lib/agent/cli_a2a.py`）；沒記到、投不出去、投了 30 秒沒回執＝退回貼字（後者這個畫面之後都貼，到下一次 SessionStart）。接線前開的畫面要關掉重開才換新路。關掉：定義的 `cli.json` 寫 `"a2a": false`。畫面沒開、codex 身、slash 指令、工具形照舊。
  **history 被改過＝下一輪開新 claude 對話**（self-family ⑩）：靠小格的 `.history_sum` 認出來，帶改過的紀錄過去；畫面開著不換。細節同上。
  **turn 死了外部 CLI 跟著收**（坑-52，Linux）：非互動起的 claude／codex 設了 `PR_SET_PDEATHSIG`＝SIGTERM，aos-eca-turn 被 `kill -9`／OOM（或它的 aos-loop 被殺、經 aos-inst 的 PDEATHSIG 連帶）時 CLI 收 SIGTERM，不留孤兒跟下一輪的 `--resume` 寫同一段對話；tmux 畫面裡的 CLI 不在此列（`cli_print.parent_death_term`）。
  **hook（eca 縮水版）**（[hook 圖紙 § 6](../../thinking/2026-11/10/self-family/hook/01-圖紙.md#6-eca-縮水版)）：定義的 interfaces.json 宣告 `hooks` 時，這支跑 `before_queue`／`after_queue`／`brain_failed`／`tool_added`，`before_tool`／`after_tool` 在 aos-mcp；有哪些、沒有哪些見 [templates/docs/01](../../templates/docs/01-eca-claude.md)。
  **slash 指令**（[eca-slash](../../thinking/2026-11/12/eca-slash.md)，⑭）：`aos-agent say／chat` 送一封剛好是 `/clear`、`/compact`、`/status`、`/usage`、`/exit` 的信＝aos 這層做（claude -p 認得的 `/compact`、`/usage` 交給 claude），回一則 `[aos] slash: …`，listen 照拿；`/clear` 連 history 一起清、claude 的 `/compact` 把 history 換成它的摘要（原文都搬到 `history_removed.jsonl`）；畫面開著時這兩個打進畫面。`/goal …`（以它開頭就算，含 `/goal clear`）是 CLI 自己的 goal：畫面開著打進去、沒開交給 claude（codex 回一句請開畫面），跟 aos 的 goal.json 不同步；codex 已有 goal 時跳的「Replace goal?」aos 自動選 1（Replace current goal），認不得就不按。畫面上打的由畫面 hook 跟上（`cli_hook.follow_session`／`clear_history`／`compact_history`；codex 換到剛開的 thread＝清、同一段 thread 被壓過＝history 換成它壓縮後留下的對話）。沒畫面時交給 claude 的 `/goal …`、`/compact` 跟一般一輪一樣：交出去就收信、user 接進 history，claude 失敗＝這封掉了、fire `brain_failed`、記冷卻。
  **外部 MCP server**（[external-mcp](../../thinking/2026-11/12/external-mcp/README.md)）：定義的 `cli.json` 列 `mcp_servers`（server 檔路徑），cli_session 起 CLI 時讓 claude／codex 自己接（http 帶 Bearer 與自簽 CA、stdio 經 `aos-mcp-launch`）；金鑰檔起 CLI 那一刻才讀、只進 CLI（或 server）行程。寫法見 [templates/docs/01](../../templates/docs/01-eca-claude.md#接外部-mcp-server11-12-external-mcp)。另一條路是同一份 server 檔先用 [aos-mcp-import](../aos-mcp-import/README.md) 凍結、疊進 `tools.json`，經 aos-mcp 給 CLI（`mcp__aos__<server>_<工具>`，`before_tool` hook 攔得到）；一台選一條，差別表在同一節。
  **子 agent 與 skill**（[eca-task-subagent](../../thinking/2026-11/12/eca-task-subagent.md)）：claude 身的範本開 CLI 自己的 `Agent`（子 agent）與 `Skill`；`cli.json` 的 `tools_sub`＝子 agent 那台 aos 登記檔（內建 general-purpose 子 agent 只拿到 `mcp__aos_sub__*`，其他類型叫 `mcp__aos__*` 會被擋）。寫法見 [templates/docs/01](../../templates/docs/01-eca-claude.md#子-agent-與-skill11-12-晚-eca-task-subagent)。
  **程式放哪**：`bin/aos-eca-turn` 只留說明（檔頭中文 docstring）與找模組的入口，本體在旁邊的 `aos_eca/` 套件（一輪的流程、交給 CLI 的前後（handoff，一般一輪與 slash 共用）、history、hook、認領信、等回答時又來的信（midturn）、slash、開場白各一檔，逐檔一句話見 code map）；照 `aos-agent` 的寫法，install.sh 裝的 symlink 經 realpath 找得到它。
- `bin/aos-eca-screen`：eca 的 screen 子介面身體（open／close／watch），人經 `aos-agent` 叫。說明在 [cmd/docs/05](../docs/05-aos-llm與eca入口.md)。
