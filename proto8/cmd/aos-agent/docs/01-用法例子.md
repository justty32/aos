## 用法例子

`ctl add` 的工作區依序取 `--ws WS`、非空的 `$AOS_WS`、呼叫當下的 cwd，並轉絕對路徑。選到的路徑不是資料夾＝`WsMissing`，不送信、不退回 cwd；例如 `AOS_WS=/work aos-agent ctl add ../agents/bob` 使用 `/work`，加 `--ws /other` 就用 `/other`。

11-04 在 WSL 逐條跑過（11-05 輸出改英文、主要幾條重跑過；11-05 stdio-unify 起錯誤行是 `aos-agent: error: 代號 原因`、提醒行是 `aos-agent: warning: 句子`、`ctl ls` 用 TAB 分欄；11-05 起掛上與管理收進 `ctl`，下面照新寫法；信箱模式 daemon、`templates/agent-fsm` 複製一份到 `../agents/bob` 加 `interfaces.json`、假腦；路徑縮短成 `…`）：

```
$ export AOS_DAEMON=…/d                       # daemon 的 $AOS_STACK（絕對路徑）
$ aos-agent ctl add --name bob ../agents/bob
…/d/procs/bob
$ aos-agent ctl add -n ann ../agents/bob          # 同一份定義再掛一隻（-n＝--name，11-06 短名）
$ aos-agent ctl ls                               # TAB 分欄：名字、狀態、工作區、queue 幾封、reason（沒有＝-；11-05 R15）
bob	running	…/ws	0	-
ann	running	…/ws	0	-
$ export AOS_AGENT=bob                        # 或 source proto8/cmd/aos-agent/using-aos-agent.sh bob，之後直接 say／listen
$ aos-agent say 現在幾點 && aos-agent listen --timeout-s 30
000000000001.0179…
FAKE ANSWER to: 現在幾點 (tool said: 2026-11-04T06:09:02Z)
$ aos-agent ctl state
name    bob
state   running (daemon phase running)
ws      …/ws
stack   …/d/procs/bob
def     …/agents/bob
queue   0 queued
answer  FAKE ANSWER to: 現在幾點 (tool said: 2026-11-04T06:09:02Z)
$ printf '你好\n再一句\n' | aos-agent chat    # 提示符與開場在 stderr，stdout 只有回答
FAKE ANSWER to: 你好 (…)
FAKE ANSWER to: 再一句 (…)
$ aos-agent listen --last 1
== #4
> 按掉前
FAKE ANSWER to: 按掉前 (…)
$ aos-agent tools add clock2 …/lib/base/clock     # 11-05 起：只記差異（覆蓋層），見 03-tools覆蓋層
added clock2 -> …/lib/base/clock
aos-agent: warning: created overlay …/d/procs/bob/tools.json (it records only what this agent added or removed; later changes to the definition still show through; tools reset deletes it)
aos-agent: warning: this definition (…/agents/bob) is also used by ann; only bob's own copy (in its stack) changed, theirs did not (to change them all, edit the definition: aos-tools / aos-json)
$ aos-agent ctl state | grep '^tools'              # 11-05 feat-proto：有覆蓋層才多這行
tools   overlay: 1 added, 0 removed (+clock2)
$ AOS_STACK=…/d/procs/bob/tools/x/ aos-agent ctl who   # 11-05 feat-proto：這個 stack（或它底下的工具小格）是哪隻的
bob
$ aos-agent ctl who --stack …/d/procs/bob -j      # -j＝--json
{"name": "bob", "stack": "…/d/procs/bob", "ws": "…/ws", "def": "…/agents/bob"}
$ AOS_STACK=/tmp/elsewhere/ aos-agent ctl who
aos-agent: error: InstanceMissing /tmp/elsewhere is not inside the stack of any proc on the daemon table …/d
$ aos-agent tools reset                           # 11-06 起在終端裡會先問 [y/N]，見下面「短名與確認」
deleted overlay …/d/procs/bob/tools.json; back to the definition's …/agents/bob/tools.json only
$ aos-agent open
aos-agent: error: ScreenMissing bob does not declare the screen sub-interface (no screen); follow answers with aos-agent listen --follow --target bob
$ aos-agent ctl stop
stopped, stack kept (…/d/procs/bob); say still queues letters meanwhile, aos-agent ctl start --target bob to carry on
$ aos-agent say 停著時寄的
000000000005.0179…
aos-agent: warning: queued in …/d/procs/bob/queue/new/; nothing is running bob now; it is stopped on the daemon table (bob is stopped); start it: aos-agent ctl start --target bob
$ aos-agent ctl start && aos-agent listen --timeout-s 30
started (same stack); 1 queued letter(s) will be answered next
FAKE ANSWER to: 停著時寄的 (…)
$ aos-agent ctl sleep                             # 11-05 加（11-05 隊長實跑過）
asleep, stack kept (…/d/procs/bob); say still queues letters meanwhile, aos-agent ctl wake --target bob wakes it (it also wakes when the daemon restarts)
$ aos-agent ctl start
aos-agent: error: PhaseBad bob is sleeping; use wake (start only starts stopped ones)
$ aos-agent ctl wake
awake (same stack); 0 queued letter(s) will be answered next
$ aos-agent ctl rm -y bob                         # 11-06 起終端裡不加 -y 會先問一句
removed bob (deleted stack …/d/procs/bob)
$ aos-agent ctl state
aos-agent: error: InstanceMissing bob is not on the daemon table (removed with rm, or it exited 0 and left the table; the stack may still be there: aos-agent ctl add with the same name to pick it up again)
```

### stdin 與 stdout（11-05）

使用者 11-05「aos-say,aos-listen，我希望能支援stdin/out。」；WSL 假腦實測（`/tmp/feat-say-*`）：

```
$ echo '現在幾點' | aos-agent say && aos-agent listen --timeout-s 30 > ans.txt
000000000001.0179…
$ cat ans.txt                                     # 只有回答本文
FAKE ANSWER to: 現在幾點 (tool said: 2026-11-05T06:41:06Z)
$ printf '第一行\n\n第三行 *md*\n' > long.md
$ cat long.md | aos-agent say > /dev/null && aos-agent listen --timeout-s 30 2> err.txt
FAKE ANSWER to: 第一行

第三行 *md* (tool said: …)
$ wc -c < err.txt                                 # 沒有提醒時 stderr 是空的
0
$ echo 'dash 版' | aos-agent say -                # - 也是讀 stdin
$ aos-agent say                                   # 在終端裡直接打、沒接 stdin
aos-agent: error: ArgumentsBad no message: give WORDS or pipe it into stdin (stdin is a terminal; usage: aos-agent say [--target NAME] [WORDS...|-])
$ printf '\xff\xfe\n' | aos-agent say
aos-agent: error: ArgumentsBad the message is not UTF-8
$ aos-agent listen --last 2 | cat                 # 多則：== #序號、> 問、回答（代定照現行）
== #3
> dash 版
FAKE ANSWER to: dash 版 (…)
== #4
> 有 話 參數
FAKE ANSWER to: 有 話 參數 (…)
```

history 裡那則 user 的 content 是 `'第一行\n\n第三行 *md*'`（中間的空行留著、尾端換行去掉）。`kill -TERM`／`kill -HUP` 正在等回信的 `ctl stop`：退 143／129。

`chat` 等答案時按 Ctrl-C：退 130、stderr 一行 `(that message was sent; read the answer later with aos-agent listen --target bob)`，agent 照答（測試第 8 案；上面 `listen --last 1` 的「按掉前」就是這樣寄出、之後才答的）。

### 短名與確認（11-06）

規則在 [README](../README.md) 用法段下的「短名與確認」那條（[human-cli](../../../thinking/2026-11/06/human-cli/README.md) H4、H11）。下面 11-06 在 /tmp 試驗場複本（假腦）跑過，問句、提醒行、錯誤行照實際輸出（第一段裡 `-n`、`-j`、`-y` 那幾行是從長旗標改寫的，行為同長旗標）：

```
$ aos-agent ctl rm bob                            # 終端裡：問句在 stderr，答案從 stdin 讀
aos-agent: remove bob and delete its stack …/d/procs/bob? [y/N] n
aos-agent: warning: nothing done                  # 退 0；空行、Ctrl-D 也一樣
$ aos-agent ctl rm --yes bob                      # 或 -y：不問
removed bob (deleted stack …/d/procs/bob)
$ aos-agent ctl rm bob < /dev/null                # stdin 不是終端（管線、腳本、agent）：不問、照做
$ aos-agent -d …/d ctl ls -j                      # -d＝--daemon、-j＝--json
$ aos-agent listen -t bob --last 3 -f             # -t＝--target、-f＝--follow
$ aos-agent ctl ls -jf                            # 不併
aos-agent: error: FlagUnknown unknown flag -jf (see aos-agent ctl ls --help)
$ aos-agent ctl rm                                # 缺參數：括號裡是 ctl rm 自己的 usage 行
aos-agent: error: ArgumentsBad … (usage: aos-agent [--daemon D] ctl rm [-y] NAME)
```

`tools reset`／`llm reset` 同樣問、同樣 `-y`；這隻沒有覆蓋層（沒東西可刪）時不問。設了 `AOS_KERNEL` 的 ctl 信，寄出時 stderr 多一行 `aos-agent: warning: routing via AOS_KERNEL=…`。


## 判官排隊與叫醒收件者（11-06）

```sh
aos-agent ctl add --name kid --timeout-s 15 --on-queued fail ../agents/kid
aos-agent ctl add --name later --timeout-s 2 --on-queued ok ../agents/kid
# ok 到期且判官窗仍列該封時：queued later at position N (letter L; applied when a slot frees)
AOS_KERNEL= aos-agent ctl wake --target procs-kernel
```

fail 是預設，信帶從寄出起算的排隊期限；ok 成功只表示仍在判官的 FIFO 隊列，尚未掛上。最後一行由呼叫者明寫這次直接寄 daemon，避免把收件者自己的 wake 也寄進睡著的信箱。詳細判法與無法撤回已轉寄信的競態見 [README](../README.md) 與 [限制](02-已知限制.md)。
