## 已知限制（併自 extras/eca）

- **`AOS_DAEMON` 要給絕對路徑**，相對路徑 cd 之後就對不上（使用者 11-02 晚選「3」：維持、只寫清楚）。11-05 起沒設時找 cwd 的 `./.stack`（轉絕對），所以 `cd ws` 再下指令也行；cd 到別處就找不到（或找到別的 daemon），那時照樣設 `AOS_DAEMON`。11-11 曾議改成 `AOS_KERNEL`、`AOS_DAEMON` 都沒設就報錯、不再猜；11-12 使用者：「只是猜.stack感覺可以留著?」，未定案，照現行。
- **短時間多封信＝一批**（eca）：aos-eca-turn 一次把 queue 的信全部、照順序丟進一次 CLI；人接在畫面上時信排著等人跳出；`listen` 等的是最新那封，前面的要 `--last N` 看。
- **執行 aos-agent 的 PATH**：一定要找得到 `aos-post`、`aos-exec`；`llm set` 另要 `aos-json`。叫不到＝`CommandMissing`。`tools` 不看 PATH：照 aos-agent 自己的位置找同一份 repo 的 `proto8/cmd/aos-tools/bin/aos-tools`，用跑 aos-agent 的那個 Python（`sys.executable`）跑它（11-10 坑-65 對源碼改）。
- **daemon 的 PATH**：子 loop 用 daemon 啟動時的環境叫 claude／codex、aos-eca-turn、aos-post、aos-exec；接了工具還要 `proto8/cmd/aos-mcp/bin`（aos-mcp）與 `proto8/cmd/aos-tools/bin`（aos-tools）。
- **新資料夾第一次開畫面，claude 會先問「信任這個資料夾嗎」**：`open` 接進去，用方向鍵移到「Yes」再按 Enter（直接 Enter 是「No, exit」）。
- **出錯結束的（CLI 出錯、fsm 腦失敗，任意 proc 退非 0）留在表上 `stopped`＋`reason`**（11-05 使用者裁「留表標 stopped (Recommended)」）：`ctl ls` 最後一欄 reason、`ctl state` 多一行 `reason`；修好後 `aos-agent llm reset`／`tools reset`（或直接改 stack 裡那份）再 `aos-agent ctl start`；不要了 `ctl rm`。**做完的（退 0：跑滿、身體退 10、直接寫它 `ctl.json` 的 stop）在 daemon 表上沒有**：`ctl ls` 不列、`ctl state`／`ctl rm`＝`InstanceMissing`；stack 留著（自己 `rm -r`），要接著用就同名再 `ctl add`（用自訂 `--stack` 的要記得當初給的 S）。
- **回信信箱要讓 daemon、判官寫得進去**（11-05 edge-agent 題 2；11-06 [no-pid](../../../thinking/2026-11/05/no-pid/README.md) P3 改共用信箱）：回信寄到 `$AOS_STACK/daemon_reply/`（人殼＝`<daemon stack>/procs_requests/reply/`）。照 [kernel/docs/02](../../../kernel/docs/02-kernel-modes.md)「Linux 權限」那級把 daemon／判官放別的帳號時，它們寫不進去＝回信寄不出去（判官 stderr 一行 `ReplyFailed`），aos-agent 等滿 `--timeout-s S`（預設 30 秒）一封都沒收到＝`DaemonFailed no reply …`，就算表上其實已經變了；這種佈置要讓那個信箱給 daemon／判官的帳號寫。沙箱裡的 aos-agent 也一樣：回信信箱在自己的 stack，要綁 rw。
- **逾時不等於保證取消**：逾時失敗會盡力用 `aos-post regret` 撤原收信箱 `new/` 裡的信；成功撤掉才不會晚套。`--on-queued fail` 的信帶 `queue_wait_ms`，判官領進 cur 的也按 `sent_at` 牆鐘期限到期拒絕，包含睡醒後首次見到的過期信。但信已轉寄進 daemon ctl、或已被 daemon 領走進 cur 就撤不回；可能失敗後仍掛上，需查表處理。`--on-queued ok` 成功排隊會保留請求，之後有格照掛；它的成功只表示排隊。晚到回信留共用信箱，10 分鐘後由下一個開箱者收掉。`kill -9` 等待者不能保證跑撤信；直接 ctl／繞過判官也不能靠判官期限擋晚套。
- **收件者睡著**：`AOS_KERNEL` 只是信箱路由，不辨識 kernel 身份或預判其狀態；判官睡著是設計系統的人要管的風險（使用者 11-07）：手動 `aos-daemon-ctl wake NAME`（一律直寄 daemon、不看 `AOS_KERNEL`）叫醒，否則信照樣留它的箱裡等它回來；程式不自動叫醒、不自動繞過。
- **信交給 CLI 就算答了，中途掛掉的那批不重答**（eca 20）：要重答就再 `say` 一次。`ctl sleep` 剛好在答的時候也一樣（daemon SIGTERM 掉 CLI，wake 之後那句不會有回答；11-05 edge-agent 實測，`ctl sleep` 會先提醒一聲）；`ctl stop` 會等這輪答完，不會丟。
- **`limits` 已生效**（11-05 feat-proto 件 5；daemon 那半 E1／E2 11-05 晚做好）：`ctl add` 驗過就轉給 `aos-daemon-ctl add --limits`，daemon 在子行程 setrlimit／換帳號。是**每個行程各自**的上限（rlimit），不從 daemon 的總額扣；比 daemon 自己的 hard 寬不會自動夾、那隻起不來（`LimitBad`）。
- `watch` 只讀非互動那條路的 `live.jsonl`；收起畫面＝`tmux kill-server`，人打到一半沒送出的字會丟。
- `llm` 改過的鍵不跟定義（只放改過的鍵，其他照定義；`llm ls -l` 列哪些是改過的），要回去就 `reset`。`tools` 11-05 起是覆蓋層、定義改了照疊（[03](03-tools覆蓋層.md)）。
