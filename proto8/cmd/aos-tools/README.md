# aos-tools — 一個 agent 資料夾一份工具註冊檔

← [cmd](../README.md)

`bin/aos-tools`（Python）管 tools.json：登記這隻 agent 能叫哪些工具、`call` 叫它們。`add` 成功印一行 `added NAME -> 絕對路徑 (寫進的檔: 存的原樣值)`（原樣值是 JSON，指示詞就印那段）、`rm` 每拿掉一個印一行 `removed NAME (寫進的檔)`；`aos-tools --help` 印頂層、`aos-tools 子命令 --help` 印那個子命令的英文說明。說明在 [cmd/docs/01](../docs/01-逐支說明.md#逐支說明)；覆蓋（`$override`）見下段與 [aos-agent docs/03](../aos-agent/docs/03-tools覆蓋層.md)。

**一段白話**（C-85）：aos-tools 管「工具通訊錄」（一份 JSON 檔）。`add 路徑` 記一個工具進去，`ls`／`get` 看有哪些，`rm` 拿掉，`call 名字 [JSON]` 叫一次。通訊錄可以寫一行 `"$override"` 指向另一份（或一串），意思是「以那份為底，照順序疊，後面蓋前面，我這份只記差異；值是 null 的那格不算工具」——每隻 agent 自己加減的工具就是這樣一份。工具要的環境變數可以直接記值（`--envs`），也可以記一個 env 檔的位置（`--env-file`），每次叫工具才去讀。

**`$override`**（aos-tools-cli 步 4；使用者 Q4「"override":"../another_tools.json"」、N1「跟一般清單同形狀。想要rm的話，就是指定的key : null」、N3「旗標改叫 --replace」、K1「現在就寫 $override」、「$override希望能支援array…跟$ref一樣」）：`{"$override": BASE, "tools": {名: 登記, 不要的: null}}`。BASE＝路徑字串（相對從這份檔的資料夾算、絕對）、指示詞物件（每次用到才解）或它們的陣列（空陣列＝沒有底檔）。疊法＝**照順序疊，後面蓋前面**（使用者 11-10「都按你的建議」）：每個底檔先展開成它自己的序列，照陣列順序接起來，最後接這份自己的，一份一份補丁式往下合（物件逐 key 合，其餘整個蓋過去）。**合併沒有刪除，`null` 只是值**（使用者 11-10：「等等，null表示拿掉...不用，null就是null，我們不做rm功能」「寫成 null，讀的人當它不是工具」）：讀的時候值是 `null` 的工具格不算工具，工具格裡值是 `null` 的欄位＝當沒設。（只寫 `{"env": …}` 的同名格沿用底檔的 `path`；`add --replace` 要整格換時用 `null` 蓋過底檔有、這次沒給的欄位；被 `null` 蓋過的格之後再給物件＝從空的開始、不跟更早的合）。底檔可以再 `$override`；同一份經兩條路被引到（菱形）＝序列裡出現兩次、照樣疊、不算環；環以真實路徑判、只看往上那幾層＝`RegistryBad … chain loops: A -> B -> A`；底檔指不到＝`PathMissing 檔#/$override[/i]: 路徑 does not exist`、不是 JSON 物件＝`RegistryBad …（from 檔#/$override）`、頂層有 `add`／`rm`＝`RegistryBad`。`tools` 那格先照 lv0 解 `$ref`／`$env`，再做合併；寫入只寫 F（`aos-json set／del --follow`）；`rm` 只有 F 自己記的名字＝刪那個 key（`removed 名 (F: key deleted)`），底檔也有的＝在 F 寫 `"名": null`（`removed 名 (F: set to null over 底檔)`）；底檔位元組不動。`override (BASE... | --path-json JSON)`：F 不在＝新建 `{"$override": …, "tools": {}}`；F 已有 `$override`＝改指標（`tools` 照留）；F 有自己的工具卻沒有 `$override`＝`RegistryBad`；寫之前先照新指標讀一次（指不到、環、壞檔先報、不寫）。跟 `$ref` 陣列的差別（使用者 11-10「都按你的建議」）：`$ref` 只合一層，這裡一路往下合——同名工具格要能只改一個欄位（例如只換 `env`）而沿用底檔的 `path`，只合一層做不到；順序與後蓋前跟 `$ref` 陣列一致。`ls -l` 的 FROM＝寫那個 `path` 的那份檔。測試 `tests/test_override.py`。

**命令列小修**（[aos-tools-cli](../../thinking/2026-11/10/aos-tools-cli/README.md) 步 1）：`--file F` 子命令前後都收（前後都給且指到不同檔＝`ArgumentsBad`）；旗標寫在 XXX／NAME 前後都收（[cli-sweep 10d](../../thinking/2026-11/10/cli-sweep/10d-施工結果-Q1旗標位置.md)）；沒給 `--file` 而 `./tools.json` 不在時，`ls`／`get`／`call`／`rm` 先印 `aos-tools: warning: ./tools.json not found; no tools (use --file F)`；`ls` 預設是短版（使用者 11-10 深夜「self_tools ls，應該默認是給出短板，然後用-l才是給長版」）：一行一支 `名 TAB 說明第一句`（description 第一行、到第一個「句點＋空白＋大寫」為止，`e.g.` 不切；沒說明＝`-`），細項用 `get`；`ls -l`（`--long`）＝長版，一行 `名 TAB 種類 TAB 絕對路徑 TAB FROM TAB STORED TAB ENV`：`FROM`（`檔#/tools/名`）、`STORED`（存的原樣值，JSON）、`ENV`（只印變數名，沒有＝`-`），跟 `--json` 同給＝`ArgumentsBad`；`ls -l` 也列（使用者「3.顯示」）疊完仍是 `null` 的名字：`名 TAB null TAB 它蓋掉的那支的絕對路徑（底檔沒有＝-） TAB 寫 null 的那份#/tools/名 TAB null TAB -`，照名字跟其他列一起排，短版／`--json` 不列；`call NAME ARGS_JSON` 把 ARGS_JSON 原樣（不驗）當工具的 stdin，沒給就讀 stdin；登記檔的指示詞解不開時，訊息說出是哪個工具（`tool 名 (檔#/tools/名)`）。測試 `tests/test_cli.py`。

**一支壞掉不擋 `ls`**（[tool-path-broken](../../thinking/2026-11/12/tool-path-broken.md)；比照使用者 11-12 對 index_view 的裁定「_metainfo.json 壞掉時，index_view 對那個資料夾不該直接報錯。」）：登記了但這一支自己壞掉（路徑不在、`_tooldef` 缺或壞、`cache: false` 給了非可執行檔）時，`ls` 略過它、stderr 一行 `aos-tools: warning: tool 名 skipped: 代號 (白話原因); correct its path or take it off the list with rm 名 (get 名 shows the full error)`（不帶絕對路徑），其他照列、**退 0**；短版那一列印 `名 TAB broken: 代號 (…)…`、`-l` 的 KIND＝`broken`（其餘欄照登記格）、`--json` 不列（給 aos-mcp、brain／act 的清單只有叫得到的）。`get 名`／`call 名` 對壞的那支報原錯（`PathMissing` 等）；`add`／`rm`／`call 別支` 本來就不讀工具內容，不受影響——所以搬了工具資料夾，先 `rm` 舊的、搬完再 `add` 新路徑（不 rm 就搬，`ls` 會標 broken，照樣 `rm` 就好）。登記檔本身壞（不是 JSON、形狀不對、`$override` 指不到、指示詞解不開＝`DirectiveBad`）與 `CommandMissing`（aos-json 起不來）整份報錯。測試 `tests/test_broken_entry.py`。

**可執行檔的定義快取在 stack**（aos-tools-cli 步 2，使用者 Q2「快取搬到 stack 裡」）：`$AOS_STACK/tooldef_cache.json`，`{絕對路徑: {"stamp": "mtime奈秒-大小", "tooldef": …}}`；stamp 相符就用、不符重跑 `--tooldef` 並寫回（暫存檔＋改名）；檔壞＝當沒有、整份重寫；`AOS_STACK` 沒設或不是資料夾＝不快取、不寫也不建任何檔。登記檔不存快取，登記格 `cache` 只收 `false`（`add --no-cache` 寫的，那支不讀不寫快取檔）；物件＝`RegistryBad`。[`stack.gitignore`](../aos-agent/stack.gitignore) 擋 `**/tooldef_cache.json`。測試 `tests/test_cache.py`。

`add XXX` 的相對路徑從當下 cwd 算，成功行的 PATH 一律印絕對路徑。**存法保留使用者的寫法**（TC，使用者「使用者自己準備。要用相對位置、絕對位置、環境變數指定都可」）：給絕對＝存絕對；給相對＝存成相對「寫進的那份檔」（F）所在資料夾的相對；`--path-json JSON`＝原樣存（字串或指示詞，例 `--path-json '{"$env":"AOS_HOME","$path":"/lib/base/shell"}'`；add 當下解一次只為了驗與取名，解出的值不寫回，之後每次用到才解）。`aos-agent tools add` 照使用者給的寫法轉交（同一個 cwd）。**登記檔都解指示詞**（`path`、`env`、`env_file` 都收，同一套 `aos-json get --follow --resolve`）；路徑指不到＝`PathMissing`，訊息帶工具名、解出的路徑與它來自哪份檔的哪一格（`檔#/tools/名/path`，檔＝寫那個 path 的那份）。讀取時，相對路徑從記錄它的那份檔所在資料夾算。資料夾工具只認 `_tooldef.json` 與選填的 `_metainfo.json`；不帶副檔名的檔不讀，JSON 檔裡讀 `_tooldef`／`_metainfo` key。**tooldef 也可以寫在 `_metainfo` 裡**（[metainfo](../../thinking/2026-11/12/metainfo/README.md)，[N-69](../../docs/NORMS/10-基礎設施-定義與工作區/11-N-69.md) 的推薦讀法）：資料夾看 `_metainfo.json` 的 `tooldef` 鍵、JSON 物件看 `_metainfo.tooldef`，先讀它、再讀獨立的 `_tooldef.json`／`_tooldef`，頂層鍵淺合併、同名整鍵以獨立那份為準（`parameters` 整鍵換）；兩處都沒有才 `ToolDefMissing`，`_metainfo` 那處壞了（讀不了、`tooldef` 不是物件）而獨立那份可用＝印一行 `aos-tools: warning:`、略過裡面照用外面（比照使用者 11-12 對 index_view 的裁定）；拿不到可用的那處形狀不對＝`ToolDefBad`（句子指明哪一處）；`get` 的 `metainfo` 欄照原樣給（含 `tooldef`）。測試 `tests/test_metainfo_tooldef.py`。**也收 `檔.json#/指標`**（[tools-def](../../thinking/2026-11/10/tools-def/README.md)，使用者「2.收」）：那個物件要有 `_tooldef` 鍵（`_metainfo` 選填），種類算 `json`，叫＝`aos-exec 檔#/指標`（cwd＝JSON 檔的資料夾，`_entry` 裡的 `python3 mul.py` 從那裡算）；只有 `#` 前面那段算相對／絕對，`#/` 後面原樣存；預設名字＝指標最後一段（`~1`、`~0` 解開）。測試 `tests/test_pointer.py`。

三種工具（資料夾、JSON、可執行檔）都經 `aos-exec`、arguments 原樣從 stdin 進。`call` 統一把父 `AOS_STACK` 換成 `tools/<登記名>/` 小格；呼叫者只傳自己的 stack，登記格 env 不能蓋掉小格。父沒設時交 aos-exec 給預設。

**小格不先建**（使用者「我確實想改成工具真的寫東西時才建資料夾」，[tool-cells-lazy](../../thinking/2026-11/11/tool-cells-lazy.md)）：`call` 只設 `AOS_STACK=<父 stack>/tools/<名>/`、叫 `aos-exec --stack-lazy`，不建資料夾；工具真的要寫才自己 `mkdir -p`（shell、run_python 的記帳、subagent 的帳、claude／codex 的對話等），只讀的工具不留空資料夾。

`add` 可用可重複的 `--envs K=V` 補 hub 變數（存進登記格 `env`，值照打的存——不放金鑰）；`--env-file FILE` **只記位置**（aos-tools-cli 步 3，使用者 Q1）：存進登記格 `env_file`，寫法同 XXX，內容不進登記檔；add 當下檔在就讀一次只為驗格式與 hub 提醒、不在＝warning 照登記；每次 `call` 才讀，檔裡的 `${…}` 照那次呼叫的環境展開，不在＝`PathMissing` 不跑（N4「報錯不跑」）。call 時後面的贏：工具自己的 `.env`（只補沒設的）＜ 呼叫者環境 ＜ `env_file` ＜ `env` ＜ `AOS_STACK` 小格。`ls -l` 的 ENV 欄印 `env` 的名字與 `@"存的 env_file"`，不印值。測試 `tests/test_env_file.py`。`--replace` 整項重寫。工具定義 `env` 列的名稱若當下環境與這次設定都沒有，印一行 warning，仍登記、退 0。`ls --json` 保留完整 tooldef；brain／aos-mcp 給模型時只取 description／parameters，不傳 hub 值。
