## 一、aos 保證的（不是慣例，是底）

aos 保證的底——六個環境變數（`AOS_ENTRY`、`AOS_WS`、`AOS_STACK`、`AOS_CF`、`AOS_CD`、`AOS_CO`；原三個，§ 19 加兩個，10-21 晚加 `AOS_CO`）、`aos-exec [旗標...] XXX [args...]`（原 `aos-exec DIR`，§ 15；10-21 改收旗標、目前只有 `--ws`，原 `aos-exec XXX [WS [args...]]`）、aos-exec 只做那幾件事、WS 不存在或入口缺／壞時退 1、找入口的規則與 `#/` 尋址——已升成規範，見 NORMS：**P-01＝[N-57](../NORMS/10-基礎設施-定義與工作區.md)、P-02＝N-58、P-03＝N-59、P-04＝N-60**；10-19 下班前新的 N-61（找入口與種類判斷）、N-62（`#/`）沒有對應的 P 號。這裡不重複正文，條號 P-01～P-04 只留給別處的引用。慣例（P-05 起）建立在這個底上。

## 二、佈局（每檔一句）

混合寫法（§ 10 使用者「好主意」）：狀態表一律寫在 `fsm.json`；一行講完的格內嵌單子；有真邏輯的格 `val` 寫子資料夾名；留 `trace.jsonl`。程式已照這張做完（第二輪，見第十節）。

```
agent-bob/                 一個 agent＝一個資料夾程式（§ 1）
  _exec                    入口（預設 $AOS_ENTRY；10-19 晚改，原 .aos/exec），兩行：#!/bin/sh、exec aos-loop loop.json（§ 4、P-05；10-21 下午加 --cfg、傍晚拿掉）
  loop.json                {"val": "fsm.json", "max": 20}：每拍 aos-exec fsm.json（拍一次 fsm）、最多幾拍（P-06；10-21 run 只收字串〔10-23 改名 val〕）
  fsm.json                 整張狀態表（P-07、P-27）：_exec＝["aos-fsm", {"$env": "AOS_CF"}]（所以它本身就是 aos-exec 的入口；10-21 傍晚改）；
                           idle→"idle"（資料夾）、think→"fsm.json#/states/think/body"（單子放那格的 body）、act→"act"（資料夾）
  idle/_exec               格：inbox 有題→0 往下走；沒題→10 請 loop 停（P-19）
  brain.py                 think 格的身體（單子 python3 brain.py，stdout 導到 $AOS_STACK/plan、逾時 120 秒）：
                           取一題（P-12）、題名寫 stack 的 current、問腦（假腦或 OpenAI 相容端點，P-23），答案印 stdout
  act/_exec                格：把 plan 當題目交給 tools/cathy，拿她的答案寫 $AOS_WS/out/、題目搬 done/（P-24、P-32）
  act/tools/cathy/         act 的工具＝另一隻完整 agent，同一套範本（_exec、loop.json、fsm.json、idle/、brain.py、act/）；
                           act 裡寫 aos-exec tools/cathy（P-33）
  act/tools/cathy/act/tools/stamp/   cathy 的 act 的工具：stdin 前面加一行時間戳印出來、自己 stack 裡 runs 計次

workspace/                 ＝$AOS_WS，使用者的（§ 2）
  inbox/<題名>             題目：純文字、一題一檔（拍板點 2）
  out/<題名>               答案：跟題目同名
  done/<題名>              做完的題目搬來這
  .aos/                    預設 $AOS_STACK（§ 2）＝bob 的 stack：state、current、plan、trace.jsonl（P-16）
  .aos/cathy/              cathy 的小格＝她的 stack（P-32）：state、current、plan、trace.jsonl
  .aos/cathy/ws/           cathy 的工作區（bob 備好題目、拿答案的地方）：inbox/ out/ done/
  .aos/cathy/stamp/runs    stamp 的小格（P-17）
```

stack 樹就是呼叫樹：`.aos/cathy/stamp/` 一眼看出「bob 叫了 cathy、cathy 叫了 stamp」（P-38）。

## 三、入口、loop、fsm

- **P-05** 入口 `_exec`（預設 `$AOS_ENTRY`；10-19 晚改，原 `.aos/exec`，使用者「換。AOS_ENTRY 預設改成 _exec，工作區的 .aos/ stack 照舊」，[ideas § 13](../thinking/2026-10-19-ideas.md)）一定帶 shebang（`#!/bin/sh`），下一行 `exec aos-loop loop.json`（10-21 下午加 `--cfg`：aos-loop 改收旗標，位置參數是要跑的目標；**10-21 傍晚拿掉 `--cfg`**：設定檔是唯一的位置參數，N-11、[ideas 10-21 § 9](../thinking/2026-10-21-ideas.md#9-設定檔是唯一的位置參數path-改字串拼接10-21-傍晚)）。也可以讓 loop.json 帶 `_exec`、入口寫 `exec aos-exec loop.json`（demo 的 agent-ann）。（§ 4 原話「#usr/bin/sh aos-loop loop.json」。沒有 `#!` 的檔 Linux 本身跑不起來，aos-exec 與單子遇到會改用 `/bin/sh` 跑（§ 22 使用者「乙」，N-59 第 5 件），範本仍寫 shebang、不靠那條退路；`exec` 少一層行程、訊號直達 loop——本稿定。**10-19 下班前補**：帶 shebang 的是**可執行檔入口**這一種；§ 14 之後入口也可以是沒 `+x` 的 JSON（單子、argv 陣列、`js[$AOS_ENTRY]`，C-73），那種入口由 aos-exec 讀、**不寫 shebang、不設 `+x`**（寫法見 P-40）。範本 agent-bob 的 `_exec` 仍是 shebang 小殼，這條不變）
- **P-06** `loop.json` 的欄位（**10-22 照程式改**，原寫「只有兩個欄位」；aos-loop 認的 key 照 `proto8/bin/aos_loop.py` 共五個：`val`、`max`，加選填的 `interval_ms`〔上一拍結束到下一拍開始至少隔幾毫秒，沒寫＝0，N-32〕、`ctl`、`state`〔窗的檔名，在 `$AOS_STACK` 底下〕；其他 key 如 `body`、`_exec` loop 不看，是給 aos-exec 用的；[ideas 10-22 § 5](../thinking/2026-10-22-ideas.md#5-loop10-22)）：`val`＝每拍 `aos-exec` 誰（字串，aos-exec 的目標：子資料夾、檔、`檔#/指標`；每拍 `aos-exec -- <val>`）、`max`＝最多幾拍（沒寫＝不限）。**10-21 下午改**（使用者「你說的這兩個可以刪的，確實跟我想的一樣，都可以做。」，[ideas 10-21 § 8](../thinking/2026-10-21-ideas.md#8-aos-loop10-21-下午)）：`val` 不再收物件（原本物件＝每拍行程內跑一張單子）；要內嵌單子就寫 `"val": "loop.json#/body"`、單子放在同一份的 `body`（aos-exec 從 loop.json 的資料夾跑它）；`max` 沒寫原本＝10；`val` 的相對路徑照 cwd 算、loop 不轉（慣例下 cwd＝loop.json 所在的資料夾）；選填 `interval_ms`、`ctl`、`state` 10-20 已長出來；`val` 也可以是陣列 `[目標, 參數...]`（每拍 `aos-exec -- 目標 參數...`，10-21 傍晚）；loop.json 帶 `"_exec": ["aos-loop", {"$env": "AOS_CF"}]`（10-21 傍晚改，原 `["aos-loop", "--cfg", "loop.json"]`；放在大 JSON 裡就寫 `{"$env": "AOS_CF", "$path": "#/loops/a"}`，N-45）時，`aos-exec loop.json` 就能把 loop 跑起來（沒 `argv` 的物件當資料夾，N-61）。loop 每拍起一次 `val`，看它的結束碼決定下一步（P-19）。（§ 1；拍板點 1；欄位名為原型自訂，10-19 晚使用者定 daemon／窗的條文也統一用這兩個名字，[ideas § 22](../thinking/2026-10-19-ideas.md)、N-28；〔10-23 統合改名：10-19 晚定的是 `run`／`max`，`run` 10-23 改 `val`，[thinking](../thinking/2026-10-23-naming.md)〕）
- **P-07** fsm 一拍只跑一格：讀 `$AOS_STACK/state`（沒有＝`start`），跑那格；那格 0 才寫下一個狀態、退 0；非 0 就不換狀態、以原碼退。每拍之間狀態都落在 stack，人看得到。**標準＝`bin/aos-fsm fsm.json`**（§ 10；10-21 下午加 `--cfg`、沒有位置參數，[計畫 10-21](../thinking/2026-10-21-plan.md) F1；10-21 傍晚拿掉 `--cfg`，設定檔是唯一的位置參數、`val` 也可以是陣列，[ideas 10-21 § 9](../thinking/2026-10-21-ideas.md#9-設定檔是唯一的位置參數path-改字串拼接10-21-傍晚)）：表長 `{"start","states":{名:{"val","next"}}}`，`val` 只收字串＝`aos-exec -- 它`（子資料夾、檔、`檔#/指標`；相對 cwd＝agent 資料夾）；要內嵌單子寫 `"val": "fsm.json#/states/<名>/body"`、單子放在同一格的 `body`（10-21 F2：原本物件＝單子、fsm 行程內跑；現在物件＝表壞）；fsm.json 可帶 `"_exec": ["aos-fsm", {"$env": "AOS_CF"}]`（10-21 傍晚改），`aos-exec fsm.json` 就是一拍（F6）；每拍在 `$AOS_STACK/trace.jsonl` 追加一行 `{"at","state","code","signal","elapsed_ms"}`（`at`＝這拍開始的 UTC 時間，ISO 8601 到毫秒〔10-23 統合：原 `ms`、`at` 到秒，[thinking](../thinking/2026-10-23-naming.md)〕，第二輪加，P-38；10-21 拿掉 `timed_out`，F4）。shell 版 fsm（自己讀 state、`case` 換狀態，原 `agent-bob/fsm/.aos/exec`）是對照寫法，state 檔同一個檔、同一格式，兩種可互換；原檔靠 git 歷史。（C-62、N-53 agent 是被外面 loop 一拍一拍驅動的狀態機；N-36 一拍一格、表一定明寫）
- **P-08** 標準三態 `idle → think → act → idle`。要加狀態＝`fsm.json` 加一格（資料夾格就再加一個子資料夾）；表一定明寫、不靠慣例檔名。`idle` 既是起點也是終點：inbox 空了退 10 時 state 停在 `idle`，所以跑完的 agent 再被叫一次是從頭開始（P-34 靠這點）。（拍板點 1；N-36 表一定明寫）
- **P-09** 每一格都是資料夾程式（10-21 起 `val` 只收 aos-exec 的目標：內嵌在 `fsm.json` 的單子格也是經 aos-exec 跑的一個入口，P-07）。fsm 只看格的結束碼，不讀格的 stderr、不管格裡面怎麼做（同步等腦、或丟請求下一拍再看，都行）。（C-52、N-38、N-41）
- **P-10** 格之間要傳的東西寫成 stack 裡的檔（agent-bob：`current`＝正在做哪題、`plan`＝腦的草稿），不走 stdout。（N-36 `next` 只在表上、格之間要傳的東西由格自己寫成檔；§ 2）
