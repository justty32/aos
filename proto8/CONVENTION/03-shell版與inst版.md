## 八、shell 版與 inst 版

- **P-27** 標準範本＝**混合寫法**，就是第二節 agent-bob 的樣子：入口 `#!/bin/sh`＋`exec aos-loop --cfg loop.json`；`loop.json` 內嵌單子拍 `aos-fsm fsm.json`（10-21 起寫成 `{"run": "loop.json#/body", "body": {"argv": ["aos-fsm", "fsm.json"]}}`，loop 的 `run` 只收字串，P-06）；**狀態表一律寫在 `fsm.json`**；一行講完的格（think：跑哪支程式、輸出導去哪、多久逾時）內嵌單子；有真邏輯的格（idle 看 inbox、act 叫工具搬檔）`val` 寫子資料夾名、裡面是 shell；留 `trace.jsonl`。要頻繁改的東西（流程、逾時、誰接誰）全在一份 `fsm.json` 裡；要寫邏輯就開資料夾、用 shell，不用把 shell 塞進 JSON。（§ 10 使用者「好主意」；拍板點 1；§ 7「想要簡單直接，那就上 shell 指令」「單子是資料……在不希望資料夾佈局太複雜的時候很好用」。改掉 10-19 早上的「標準＝shell 版 fsm」）
- **P-28** inst 單子（`{"argv", "cwd", "stdin", "stdout", "timeout_ms", …}`，key 表見 [bin/README 的 aos-inst](../bin/README.md)）是可選的升級，四種用法都行、可以在同一個 agent 裡混用：(1) `_exec` 是 shebang 小殼、讀旁邊的 `_exec.json`；(2) loop／fsm 的設定裡直接內嵌單子（**已做**，`aos-loop`／`bin/aos-fsm`、`demo/agent-ann`；10-21 下午起 loop 改成 `run` 指到 `loop.json#/body`、單子放 `body`，由 aos-exec 跑，不再在 loop 行程內跑；fsm 的 `val` 照舊可內嵌）；(A) `_exec` 第一行 `#!/usr/bin/env aos-inst`、後面接 JSON（**已做**，`bin/aos-inst`）；(B) aos-exec 認 `_exec.json`（`$AOS_ENTRY.json`），入口＝可執行檔或單子（**已做**；(1) 小殼＝`#!/bin/sh`＋`exec aos-inst _exec.json "$@"`，也已有測試）。（檔名 10-19 晚隨預設入口改，原 `.aos/exec`／`.aos/exec.json`）（§ 7「1 跟 2 都要」「接法 3 感覺也是 OK 的」「AB 都可以」；四種都做完了）**10-19 下班前～晚補（§ 14、§ 17、§ 20、§ 21）**：上面「已做」指的是 `proto8/bin` 版。**impls 線沒有 `aos-inst` 命令列**（使用者：「aos-inst可以不用，inst和inst json格式，他就是一個C lib，也不提供cli」），所以 (1) 小殼 `exec aos-inst _exec.json` 與 (A) `#!/usr/bin/env aos-inst` 在 impls 跑不起來——**只有 `proto8/bin` 版有**；(2) 內嵌兩版都有（impls 的 loop／fsm 10-19 晚照 § 23 重寫／新做，連 aos-exec 的公開 API `run_inst`）；(B) 在 § 14 之後擴成「**任何沒 `+x` 的 JSON 檔**都能當入口」：`_exec.json`、`aos-exec tool.json`、`aos-exec tool`（補找 `tool.json`，N-61）、`cfg.json#/tools/stamp`（N-62）、JSON 裡的 `js[$AOS_ENTRY]`（單子、argv 陣列、字串路徑，C-73），同一個 (A) 檔拿掉 `+x` 就是 (B)（第一行 `#!` 會被跳過）——**(B) 兩版 aos-exec 都認**（bin 版 10-19 晚照 § 21 改完，單子在行程內 `aos_inst.run()`、不再 exec aos-inst）。單子的 key 表兩版一樣是 bin/README 那 10 個，其他 key 一律忽略（impls 假日版多出的 `stderr_merge`、`cwd_mkdir` 等在 aos-exec 的單子裡**不認、不報錯**，§ 20 預設）。`+x` 但沒 `#!` 的檔，單子裡的 `argv[0]`、aos-exec 的可執行檔入口、argv 陣列入口三處一致，都改用 `/bin/sh` 跑（§ 21 使用者「不擋」只放了單子那處；§ 22 使用者選「乙」三處都放，N-59 第 5 件；兩版都照做）。
- **P-29** 範本給的是 (2)：`fsm.json` 裡內嵌單子（think 那格），範本就是 `demo/agent-bob/fsm.json`（見下面範例）。(A)、(1)、(B) 仍都能用——一個資料夾格自己想要逾時、想用單子寫入口時用 (A)（`_exec` 第一行 `#!/usr/bin/env aos-inst`；**只有 `proto8/bin` 版能用**）或 (B)（把單子寫成沒 `+x` 的 `_exec.json`，兩版 aos-exec 都認，impls 線只能用這種，P-40）——但不是範本。資料夾格要逾時，更直接的寫法是在 `fsm.json` 把那格寫成 `{"argv": ["aos-exec", "act"], "timeout_ms": 600000}`（P-36）。（§ 10；§ 7「AB 都可以」。改掉 10-19 早上的「範本先給 (A)」；這是原討論稿拍板點 5 的答案）
- **P-30** 用 inst 換到的是四樣：argv 是陣列、不靠 sh 拼字串；`timeout_ms` 逾時收尾、不留孫程式；結果是結構化的（結束碼、訊號、有沒有逾時、毫秒）；單子是資料、可內嵌進別的 JSON。「不走 sh 更快」實測不成立：單獨起一個 aos-inst（Python）比一層 sh 慢 5～6 倍，agent-bob 一圈殼的開銷對一輪 LLM 不到千分之二；省得到的只有 loop／fsm 在行程內直接 `run()` 那種（10-21 下午起 loop 不再行程內跑單子，`loop.json#/body` 每圈經一個 aos-exec 子程式，只剩 fsm 那種）。（§ 7 使用者「都還好。主要是單子是資料這塊……結果是結構化的這塊也很舒服」；10-19 在 WSL 實量的結論）兩版的差別只在那層殼的重量：impls 的 aos-exec 是 C++、單子在行程內交給 C lib 跑，沒有「另起一個 Python 直譯器」那層；bin 版的 aos-exec 10-19 晚從 sh 改寫成 Python（§ 21）後，單子同樣在行程內 `run()`，但每層 aos-exec 多一次 Python 啟動——65 個舊測試約 5.9 秒變 6.7 秒，仍是對一輪 LLM 不到千分之幾的量；上面「慢 5～6 倍」那個數字是對單獨起 aos-inst 命令列（P-28 的 (A)、(1) 寫法）量的，impls 版沒量過。
- **P-31** 單子要指到 stack 或工作區底下的檔，寫 `{"$env": "AOS_STACK", "$path": "plan"}`：意思是「那個環境變數指的資料夾底下的 `plan`」，照 `os.path.join` 接（`AOS_STACK` 結尾有 `/`、`AOS_WS` 沒有，兩種都對；`$path` 寫絕對路徑就是絕對路徑）。不帶 `$path` 就是整個變數值。（10-20 改：原寫 `path`，使用者「我希望那個path可以換成$path，然後添加$prefix」，舊的 `path` 不再有作用；`$prefix` 接在結果前面，`{"$env": "AOS_WS", "$path": "a.txt", "$prefix": "--file="}` → `--file=/ws/a.txt`；`$env`、`$ref` 都能帶，換出來不是字串就靜默不作用；指示詞的寫法寬容、不報錯，見 N-45、[ideas](../thinking/2026-10-20-ideas.md) D9～D15）**範本只用 `$env`**；規範另有 `$ref`（`{"$ref": "檔"}`＝換成那份檔的整份內容，語意在 N-45），但單子本來就能內嵌、不必拆檔（`$ref` 10-20 起 bin 版也解得開、impls 10-21 對齊，第十節），所以範本與 demo 不寫 `$ref`。（10-20 改：bin 版已補上 `$ref`、還能取檔內位置 `{"$ref": "x.json#/a"}`／`{"$ref": "x.json", "at": "/a"}`，argv 陣列裡也能放 `$env`、`$ref`；impls 10-21 也對齊了——範本與 demo 照舊只用 `$env`，理由剩「單子本來就能內嵌、不必拆檔」；10-20 使用者，見 [ideas](../thinking/2026-10-20-ideas.md) D1、D2、D7、D8）變數沒設＝解單子那一層自己的錯、退 1（bin 版的 aos-inst 命令列、或兩版的 aos-exec 行程內跑單子時）。`$env` 在六個環境變數（10-21 晚加 `AOS_CO`）設好之後才解，所以單子裡也讀得到 `AOS_CF`、`AOS_CD`（N-45）。不用字串內插（`"$AOS_STACK/plan"`）：那是把規則埋進字串的暗規則。（本稿定；當時 PLAN 的決定 3，見 git 歷史 8d69bcb4 的 proto8-2/PLAN.md；C-48／C-55 值長成物件、同層加屬性；C-56 寫什麼就做什麼；N-45 `$env` 是正式機制；`$ref` 保留＝使用者 10-19 晚「impls這塊，指示詞是OK的」，[ideas § 22](../thinking/2026-10-19-ideas.md)）
