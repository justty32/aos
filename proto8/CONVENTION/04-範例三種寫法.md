### 範例：同一隻 agent 的三種寫法

**混合（標準範本，`demo/agent-bob/fsm.json`、cathy 同款）**——表一份、think 是單子、idle／act 是資料夾：

```json
{"_entry": ["aos-fsm", {"$env": "AOS_CF"}],
 "start": "idle",
 "states": {
   "idle":  {"val": "idle", "next": "think"},
   "think": {"val": "fsm.json#/states/think/body",
             "body": {"argv": ["python3", "brain.py"],
                      "stdout": {"$env": "AOS_STACK", "$path": "plan.txt"},
                      "timeout_ms": 120000},
             "next": "act"},
   "act":   {"val": "act", "next": "idle"}}}
```

格寫成 `{"val", "next"}` 照 N-36；10-21 起 `val` 只收 aos-exec 的目標，think 的單子放在同一格的 `body`、`val` 指到它（P-07）。`_entry` 讓 fsm.json 本身成為 aos-exec 的入口，所以 `loop.json` 寫 `{"run": "fsm.json", "max": 20}` 就好（fsm 讀表時不理 `_entry`、`body`，C-48）。挑題、認領（`new/` → `cur/`）、寫 `current.txt`、問腦這種動態的事由 `brain.py` 做，單子是靜態資料，只負責「跑誰、輸出導去哪、多久逾時」。act 的身體（`act/_entry`，bob 的）示範叫一隻 agent 當工具（P-32、P-35）：

```sh
#!/bin/sh
# act：把 plan.txt 當題目交給 tools/cathy（另一隻 agent），拿她的答案寫 $AOS_WS/out/<題名>，題目從 cur/ 搬 done/
[ -n "$AOS_STACK" ] || { echo "agent-bob: 沒設定 AOS_STACK" >&2; exit 1; }
name=$(cat "$AOS_STACK/current.txt") || { echo "agent-bob act: 讀不到 current.txt" >&2; exit 1; }
sub=$AOS_STACK/cathy/                          # cathy 的小格＝她的 stack；她的工作區＝$sub/ws/
mkdir -p "$sub/ws/new" "$AOS_WS/out" "$AOS_WS/done"
cp "$AOS_STACK/plan.txt" "$sub/ws/new/$name"     # 照 cathy 的說明備題：new/ 一題一檔
AOS_STACK=$sub aos-exec --ws "$sub/ws" tools/cathy || { echo "agent-bob act: cathy 失敗" >&2; exit 1; }
cp "$sub/ws/out/$name" "$AOS_WS/out/$name" || exit 1   # 答案從她的 out/ 拿
mv "$AOS_WS/cur/$name" "$AOS_WS/done/$name"
```

**全內嵌（對照，`demo/agent-ann`）**——零子資料夾、零 `aos-exec` 層：三格都是單子，各指一支小腳本（`idle.py`：`new/` 空退 10；`brain.py`：挑題、認領到 `cur/`；`act.py`：plan.txt 寫 out、題目從 cur 搬 done）。資料夾裡只有 `_entry`、`loop.json`、`fsm.json` 和三支 `.py`。適合「格全是一行、不叫工具」的小 agent；一旦某格要叫工具、要用 sh 搬檔，就回到混合寫法開資料夾。

```json
{"start": "idle",
 "states": {
   "idle":  {"val": "fsm.json#/states/idle/body", "body": {"argv": ["python3", "idle.py"]}, "next": "think"},
   "think": {"val": "fsm.json#/states/think/body",
             "body": {"argv": ["python3", "brain.py"],
                      "stdout": {"$env": "AOS_STACK", "$path": "plan.txt"},
                      "timeout_ms": 120000},
             "next": "act"},
   "act":   {"val": "fsm.json#/states/act/body", "body": {"argv": ["python3", "act.py"]}, "next": "idle"}}}
```

（ann 的 `loop.json` 留 `{"_entry": ["aos-loop", {"$env": "AOS_CF"}], "run": "loop.json#/body", "body": {"argv": ["aos-fsm", "fsm.json"]}, "max": 20}` 當對照（入口 `exec aos-exec loop.json`；10-21 傍晚拿掉 `--cfg`），fsm.json 不帶 `_entry`。10-21 起每格都經一個 aos-exec 子程式，「零 `aos-exec` 層」指的是沒有子資料夾那層。）

**全 shell（對照，10-19 早上的 agent-bob，原檔靠 git 歷史）**——`loop.json` 是 `{"run": "fsm", "max": 20}`〔現行也叫 `run`（10-23 統合一度改名 `val`，同晚使用者改回），[thinking](../thinking/2026-10-23-naming.md)〕，`fsm/.aos/exec` 自己讀 state、`aos-exec "$state"`、`case` 換狀態，每格是 `fsm/<格>/.aos/exec`。沒有逾時、沒有 `trace.jsonl`（只有自己 `echo` 的 `trace.log`）；表藏在 `case` 裡。想完全不碰 JSON 時可以這樣寫，state 檔同格式、跟 aos-fsm 可互換（P-07；下面節錄的 state 檔名照 10-23 改成 `state.txt`，原檔是 `state`）。

```sh
#!/bin/sh
# fsm/.aos/exec（節錄）
state=$(cat "$AOS_STACK/state.txt" 2>/dev/null || echo idle)
aos-exec "$state" || exit $?
case $state in idle) next=think;; think) next=act;; *) next=idle;; esac
echo $next > "$AOS_STACK/state.txt"
```

三種的 stack 長相一樣（`state.txt`、`current.txt`、`plan.txt`），人看的地方不變。demo 之間重複的小檔（`brain.py`、`idle/`）是 demo 的代價，不跨 agent 互指（P-33）。
