## 搬家（11-05）：整份 cp 或 git 到別處接著跑

依據 [thinking 11-05 portable-flow](../../../thinking/2026-11/05/portable-flow/README.md)（使用者「把daemon的stack、我做事的資料夾(ws)，一起直接複製到另一個地方。實現無痛遷移」「乃至於透過git管理，我到另一台電腦做git pull」）；哪些要改設計、哪些寫進說明在 [04 跨電腦與 git](../../../thinking/2026-11/05/portable-flow/04-跨電腦與git.md)。daemon 那邊怎麼存相對路徑見 [aos-daemon docs/03](../../../impls/aos-daemon/docs/03-起-停-暫停.md#11-05-搬家相關)。

**做法**（daemon 在 ws 裡起、stack＝`ws/.stack/`）：

1. **先讓它睡著再存**：daemon 那個視窗 Ctrl-C（還在跑的列改 `sleeping`、表寫完才退）。跑著時 cp 或 commit＝一張撕一半的照片（信箱 `tmp/` 的半封信、`cur/` 認領了沒收完的、`.名.tmp` 暫存）。只想讓某一隻先停手可以 `aos-agent ctl sleep`，但存之前 daemon 本身也要退。
2. **整份帶走、相對位置不變**：`ws/`（連 `.stack`）和定義資料夾（daemon、kernel、agents，加上定義自帶的工具 `lib/`）一起 `cp -r`，或放進同一個 git repo 推上去、另一台 `git clone`／`git pull`。表與小格存的是相對 daemon stack 的路徑，所以只要彼此的相對位置不變就對得上。
3. **新位置照常起**：`cd 新位置/ws && aos-exec ../daemon`，睡著的列自己醒、接著同一個 stack 答。要人設的環境變數（`AOS_LLM_KERNEL`）是絕對路徑，到新位置要重設（試驗場的 `env.sh` 從自己的位置算，source 新位置那份就對）。
4. **定義沒一起搬**：醒不來的那隻留在表上 `stopped`、行尾「原因 wake／start 後 3 秒內就退了…」（`aos-agent ctl ls`／`ctl state` 看得到）；把定義放回原本的相對位置，`aos-agent ctl start --target 名字`。

**別信、別帶的**：

- 表與 state 窗的 `pid`、`started_at_ticks`、`boot_id` 是上一台（上一次）的；新 daemon 對不上就當「沒在跑」，照起、照醒。
- eca（claude／codex 當 agent）的對話本體在那台的 `~/.claude/projects/…`，image 裡只有 `session.txt` 的 id；換一台 `--resume` 找不到就從頭開（`history.jsonl` 還在、看得到以前聊什麼）。`transcripts/` 的 symlink 到別台是斷的，無害。畫面的 `tty.sock` 是死的，醒來 `aos-agent open` 重開。
- git 不收空資料夾（信箱的 `tmp/ new/ cur/`、工具小格）：第一圈 daemon、aos-post、aos-tools 會自己建回，不用管。
- **只在 Linux 檔案系統 checkout**：Windows 端 checkout 會丟 `+x`（定義裡的 `_entry`）、`core.autocrlf` 會在 `stage.txt`、`_entry` 尾巴加 `\r`；`/mnt/c` 底下又每個檔都 `+x`（aos-exec 會把 JSON 當執行檔）。真的要過 Windows，pull 完 `chmod +x` 那幾個 `_entry`，並放下面的 `.gitattributes`。
- 同一份 image 一次只在一台醒著：pull 前先 Ctrl-C；同一個 stack 已有 daemon 在跑，再 `aos-exec ../daemon` 會 `DaemonRunning` 退 1。

**範本**（這個資料夾裡）：

| 檔 | 放哪 | 做什麼 |
|---|---|---|
| [`stack.gitignore`](../stack.gitignore) | `cp stack.gitignore ws/.stack/.gitignore` | 擋 `**/tmp/`（半封信）、`**/.*`（`.名.tmp`、`.flock`；不擋 `.stack` 本身與 `.gitignore`／`.gitattributes`）、`**/stderr.txt`、`**/*.sock`、`**/lock`；**不擋** `state.json`（`paused` 要帶著醒）、`procs_state.json`、`history.jsonl`、`queue/`、`stage.txt`、`think/`、`used.json`、`llm.json`、`tools.json`、`session.txt` |
| [`stack.gitattributes`](../stack.gitattributes) | `cp stack.gitattributes <git repo 根>/.gitattributes` | `* -text`：一律不轉換行（放根＝定義的 `_entry` 也管到） |

`.gitignore` 放 `.stack` 裡而不是 ws 根：放 ws 根也擋得對 image，但 `**/tmp/`、`**/.*` 會連你 ws 裡自己的 `tmp/`、`.env` 一起擋。

11-05 WSL 實測（試驗場）：Ctrl-C → `cp -a` 整份到 `/tmp` 另一處 → 新位置 `aos-exec ../daemon`：三列都在新位置醒、fsm_ann 接著答，舊位置的檔沒被碰；拿走定義再起＝那列 `stopped`＋原因、放回去 `start` 就回來；放兩份範本 `git init`＋commit＋`git clone` 到第三處再起：同樣醒、接著答。git 擋掉的只有三份 `stderr.txt` 和 kernel 信箱（裡面只剩 `.flock` 與空資料夾）。
