## 已知限制（併自 extras/eca）

- **`AOS_DAEMON` 要給絕對路徑**，相對路徑 cd 之後就對不上（使用者 11-02 晚選「3」：維持、只寫清楚）。11-05 起沒設時找 cwd 的 `./.stack`（轉絕對），所以 `cd ws` 再下指令也行；cd 到別處就找不到（或找到別的 daemon），那時照樣設 `AOS_DAEMON`。
- **短時間多封信＝一批**（eca）：aos-eca-turn 一次把 queue 的信全部、照順序丟進一次 CLI；人接在畫面上時信排著等人跳出；`listen` 等的是最新那封，前面的要 `--last N` 看。
- **daemon 的 PATH**：子 loop 用 daemon 啟動時的環境叫 claude／codex、aos-eca-turn、aos-post、aos-exec；接了工具還要 `proto8/extras/ai_tools/bin`（aos-mcp）與 `proto8/bin`（aos-tools）。
- **新資料夾第一次開畫面，claude 會先問「信任這個資料夾嗎」**：`open` 接進去，用方向鍵移到「Yes」再按 Enter（直接 Enter 是「No, exit」）。
- **出錯結束的（CLI 出錯、fsm 腦失敗，loop 退非 0）留在表上 `stopped`＋`reason`**（11-05 使用者裁「留表標 stopped (Recommended)」）：`ctl ls` 行尾 `reason …`、`ctl state` 多一行 `reason`；修好後 `aos-agent llm reset`／`tools reset`（或直接改 stack 裡那份）再 `aos-agent ctl start`；不要了 `ctl rm`。**做完的（退 0：跑滿、身體退 10、直接寫它 `ctl.json` 的 stop）在 daemon 表上沒有**：`ctl ls` 不列、`ctl state`／`ctl rm`＝`InstanceMissing`；stack 留著（自己 `rm -r`），要接著用就同名再 `ctl add`（用自訂 `--stack` 的要記得當初給的 S）。
- **暫時回信信箱在系統暫存資料夾**（11-05 edge-agent 題 2）：判官、daemon 要寫得進去才收得到回信。照 [demo/docs/04](../../../demo/docs/04-kernel-modes.md)「Linux 權限」那級把 daemon／判官放別的帳號時，它們寫不進 aos-agent 開的暫時信箱（`mkdtemp` 只給自己）＝回信寄不出去（判官 stderr 一行 `ReplyFailed`），aos-agent 退回舊的等法：表上變了就成功、判官不掛就等滿 30 秒 `WaitFailed`。kernel 睡著時立刻 `WaitFailed` 的那封，信留在它信箱、醒來才判，那時暫時信箱已刪＝一樣 `ReplyFailed`、不影響判的結果。
- **信交給 CLI 就算答了，中途掛掉的那批不重答**（eca 20）：要重答就再 `say` 一次。`ctl sleep` 剛好在答的時候也一樣（daemon SIGTERM 掉 CLI，wake 之後那句不會有回答；11-05 edge-agent 實測，`ctl sleep` 會先提醒一聲）；`ctl stop` 會等這輪答完，不會丟。
- **`limits` 現在不生效**（11-05 feat-proto 件 5）：`ctl add` 只驗宣告／`--limits` 的格式、不送給 daemon（aos-daemon-ctl 還沒有 `--limits`），stderr 提醒一行；daemon 那半（E1／E2）做好後才真的擋。生效後也是**每個行程各自**的上限（rlimit），不從 daemon 的總額扣。
- `watch` 只讀非互動那條路的 `live.jsonl`；收起畫面＝`tmux kill-server`，人打到一半沒送出的字會丟。
- `llm` 改過的鍵不跟定義（只放改過的鍵，其他照定義；`llm show` 的 stderr 列哪些是改過的），要回去就 `reset`。`tools` 11-05 起是覆蓋層、定義改了照疊（[03](03-tools覆蓋層.md)）。
