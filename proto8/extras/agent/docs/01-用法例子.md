$ export AOS_DAEMON=…/d                       # daemon 的 $AOS_STACK（絕對路徑）

### stdin 與 stdout（11-05）

使用者 11-05「aos-say,aos-listen，我希望能支援stdin/out。」；WSL 假腦實測（`/tmp/feat-say-*`）：

```
$ echo '現在幾點' | aos-agent say && aos-agent listen --timeout-s 30 > ans.txt
000000000001.0179…
$ cat ans.txt                                     # 只有回答本文
FAKE ANSWER to: 現在幾點 (tool said: 2026-11-05T06:41:06Z)
$ printf '第一行\n\n第三行 *md*\n' > long.md
$ cat long.md | aos-agent say > /dev/null && aos-agent listen --timeout-s 30 2> err.txt
FAKE ANSWER to: 第一行

第三行 *md* (tool said: …)
$ wc -c < err.txt                                 # 沒有提醒時 stderr 是空的
0
$ echo 'dash 版' | aos-agent say -                # - 也是讀 stdin
$ aos-agent say                                   # 在終端裡直接打、沒接 stdin
aos-agent: error: ArgumentsBad no message: give WORDS or pipe it into stdin (stdin is a terminal; usage: aos-agent say [--target NAME] [WORDS...|-])
$ printf '\xff\xfe\n' | aos-agent say
aos-agent: error: ArgumentsBad the message is not UTF-8
$ aos-agent listen --last 2 | cat                 # 多則：== #序號、> 問、回答（代定照現行）
== #3
> dash 版
FAKE ANSWER to: dash 版 (…)
== #4
> 有 話 參數
FAKE ANSWER to: 有 話 參數 (…)
```

history 裡那則 user 的 content 是 `'第一行\n\n第三行 *md*'`（中間的空行留著、尾端換行去掉）。`kill -TERM`／`kill -HUP` 正在等回信的 `ctl stop`：退 143／129，`$TMPDIR` 裡的 `aos-agent-reply-*` 不在；`kill -9` 的那個留著，下一次 `aos-agent ctl ls` 就清掉，同時在等的另一個 aos-agent 的信箱沒被動到。

`chat` 等答案時按 Ctrl-C：退 130、stderr 一行 `(that message was sent; read the answer later with aos-agent listen --target bob)`，agent 照答（測試第 8 案；上面 `listen --last 1` 的「按掉前」就是這樣寄出、之後才答的）。
