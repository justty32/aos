## 當機復原與已知限制（11-05 第二輪）

使用者 11-05 午：「你繼續多測試一些邊緣狀況吧。」第二輪實測（跨元件、時間軸、壓力）修的與只寫一句的，見 [edge-round2](../../../thinking/2026-11/05/edge-round2/README.md)。

### daemon 沒走收工就死了（kill -9、斷電、`wsl --shutdown`、OOM）

- **表上 running、行程已不在**：adopt 拿不到結束碼，不分起法、照自然結束下表；auto_restart 照舊重起。表上已有 stopped／sleeping 的照接回；重開仍依 daemon.json 名單起缺項。
- **表上 stopping**：依表內 `stop_mode` 接著收：stop 重新寫 ctl 並等自行退，sleep／remove 送 SIGTERM；sleep 退後留 sleeping、stop 留 stopped、remove 下表。收工時 running 的睡下（sleeping），stop 途中的留 stopped，sleep 途中的睡下，rm 途中的拿掉；收工途中被 kill -9，重開時照表上的 `stop_mode` 做，結果一樣。
- **起任何 proc 前看公開 state 窗**：proc 的 stack 裡子 loop 自己的 state 窗記的 pid＋`started_at_ticks` 對得上一支活著的＝接回、不再起一份（上一個 daemon「fork 了、表還沒寫」就死的那種；原本同一格兩支 aos-loop）。接回的拿不到結束碼，退了照舊下表（同 adopt）。
- **重開機過**（11-06 no-pid P1）：上次的表頂層 `boot_id` 跟這次開機不同（或沒寫）＝表上的行程都當不在了，不比 pid＋ticks（重開機後可能撞上別的行程）；這台讀不到 boot_id＝照舊只比 pid＋ticks。公開 state 的 boot_id 也比對（11-06 P9）。
- **resume 那一圈先寫 state**（`paused: false`、新的 `ctl_seq`）再套信對表：原本對完一大批信才寫，這中間死掉再起＝照舊 state「起來先暫停」、舊實作又把 ctl 裡那道 resume 當基準線＝一直停著。11-07 起，未套用的 resume 第一拍也會照做；這裡仍先寫 state，讓對外狀態先反映已套用的指令。
- **`state.json` 被刪或寫壞**：要先手動清掉 `ctl.json` 再起 daemon，否則它會照 `ctl.json` 裡的舊 stop，一起來就停；放在 systemd 之類自動重起底下，就會變成起了又停的迴圈（11-07 使用者裁定：維持現狀、文件寫明）。
- **`procs_state.json` 寫不了**（stack 唯讀、磁碟滿）：（11-05 起，[edge-round2 題 1](../../../thinking/2026-11/05/edge-round2/README.md) 裁定）不再退 1——stderr 一行、下一圈再寫、proc 照顧著（[06](06-結束碼等.md#結束碼)）。這段期間 daemon 被 kill -9＝磁碟上是最後寫成的那份，再起時照上面幾條接回；之後才加、信已收掉的那幾個不會回來（信還在 `cur/` 的會重套）。

### 一個 proc 的 stack、信箱出問題時不再整台停

- **daemon 的 stop 寫不了子 loop 的 ctl**（proc 的 stack 唯讀）：原本整台退 1、全部 proc 收掉；現在 stderr 一行 提醒行 `aos-daemon: warning: cannot stop X through its ctl (…); waiting for it to exit`，那一列留 `stopping` 等自行退，退了留 `stopped`；不因寫不了就改送 SIGTERM。
- **信箱認領不了**（`new/` 唯讀）：原本整台退 1；現在記進 `mailbox_warning`（`cannot take letters: …`）、下一圈再試。
- **收工途中又起一台**：`DaemonExists the daemon on this stack (…) is shutting down; start again after it exits`（原本叫人「沿用」它；11-06 起不印 pid，只看 `state.json` 的 `phase`）。

### reason 的細節（接 [03](03-起-停-暫停.md)「出錯結束一律留」）

- 只看**這一支起來之後**寫進 `stderr.txt` 的（原本整份檔的最後一行，會引到前幾輩子的話）；`stderr.txt` 被截短過（copytruncate）就看整份。
- 只取最後非空行，不依程式名或錯誤字句跳過任何行（11-06 K-2，移除 `is_wrap`）。控制字元（CR、ESC 色碼、TAB…）換成空白；切 300 位元組時不切在 UTF-8 字中間，長行也照這個上限處理。
- **add 剛起的也算「起來」**：3 秒內退＝`failed to start: exited within 3s of wake/start…`（原本寫成 `failed while running`）。3 秒從 daemon「看到它退了」那一刻算，最多晚一個 `interval_ms`。

### 已知限制（風險自擔，沒改）

- **proc 的 stack `stderr.txt` 沒有上限、不輪替**：子項每 10 毫秒印一行約每秒 3 KB、一天約 277 MB。要截就 `truncate -s 0`（copytruncate；daemon 用附加寫，截了從 0 接著寫、不留空洞）。
- **表很大時每拍的 CPU 跟列數成正比**（每拍組一次整張表比有沒有變）：4300 列、`interval_ms` 10＝閒著 82%；200 個 running、`interval_ms` 200＝0.4%。表大就把 `interval_ms` 調大；**`interval_ms: 0` 會吃滿一顆 CPU**，身體又一直失敗時每秒重跑約 500 次。
- **身體一直失敗**：「碼變了才印」只管 daemon 自己那行；身體自己的 stderr、aos-exec 的錯（例 `EntryMissing`）每圈照印；碼在兩個值之間交替＝每圈都印。
- **INT／TERM／HUP 以外的訊號**（USR1、USR2…）＝照系統預設直接死、不收工，同 `kill -9`（再起照上面接回）。
- **daemon 的 stop 沒有時間上限**（等子 loop 跑完這一次）：子 loop 被 SIGSTOP、身體卡死＝列一直 `stopping`，這時可下 `sleep` 改送 TERM、10 秒後仍在就 SIGKILL，退後保留 `stopped`、stack 與 launch，用 `start` 再起；`stop`／`start` 仍是 `PhaseBad`，`rm` 也會送 TERM、10 秒 SIGKILL，但拿掉列。
- **procs_ctl.json 是宣告、蓋過信**：它的 `procs_added` 裡有的名字，寄 `procs_removed`（`aos-daemon-ctl rm`）照收信、退 0，但下一圈又被疊回來、照跑（沒有 warning）。**刪掉 procs_ctl.json＝什麼都沒宣告＝回初始值**（11-05 第二輪修：原本沿用最後一份好的，跟 N-06 不符；前一份的 `ctl_warning` 也一起清掉）。
- 起一大批時 `procs_state.json` 最多每 200 毫秒寫一次（原本每起一列寫一次整張表：表上千列、一批上千封信＝平方慢，1500 封要 20 幾秒、Ctrl-C 要 30 秒才理）；切檔的舊分檔退役後留 2 秒才刪（daemon 一秒寫好幾次表時，讀的人剛讀到的主檔可能已是兩次以前的）。
