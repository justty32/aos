## 用法

```
aos-daemon [--max N] [--interval-ms N] [--ctl FILE] [--state FILE] [--state-flux FILE] [--enable-logs] [--enable-counters] daemon.json [-- ARGS...]
```

命令列同 [aos-loop](../../aos-loop/README.md)（共用 `loop_cli`）：唯一的位置參數＝設定檔（必給、只能一個；可寫 `檔#/指標`）；旗標放前面；起跑時 旗標 ＞ daemon.json ＞ 預設；
`procs`、`adopt`、`procs_ctl`、`procs_state`、`procs_requests`、`procs_loop`、`procs_exec`、`procs_stderr` 只在 daemon.json（沒有旗標）。usage 錯一行 `aos-daemon: error: ArgumentsBad reason (usage: aos-daemon [--max N] [--interval-ms N] [--ctl FILE] [--state FILE] [--state-flux FILE] [--enable-logs] [--enable-counters] daemon.json [-- ARGS...])`；`--help`＝英文說明印 stdout、退 0。
`--enable-logs`（不帶值的開關）＝印 log（見下「log」）。`--enable-counters`（不帶值的開關，11-09，全家同名）＝有 state 窗時，每一圈開跑時把「這個行程起來後跑到第幾圈」寫進 state 窗同資料夾的 `counter_runs.txt`（同 aos-loop 的次數，沒有身體也照數；不是 log 行裡身體跑了幾次）（見 [04](04-兩個手把-兩扇狀態窗.md)）；預設不寫。`daemon.json -- 參數...`：附加參數**只接在 daemon 自己的 `exec` 後面**（每次都帶），不影響 proc；沒有 `exec` 卻給了＝`ArgumentsBad`。

daemon.json＝loop.json 的超集（N-28）：

| key | 型別 | 沒寫 | 意思 |
|---|---|---|---|
| `exec` | 字串、`[目標, 參數...]` 或單子物件 | 不跑 | 自己每次的身體（同 aos-loop）；純監工不寫 |
| `max` | 非負整數 | 不限 | 跑幾次就收工（寫 `null` 不行） |
| `interval_ms` | 非負整數 | 200 | 兩次之間至少隔幾毫秒 |
| `ctl`、`state`、`state_flux` | 檔名或 `null` | `ctl.json`、`state.json`、`state_flux.json` | loop 面向的三扇窗，在 `$AOS_STACK` 底下（同 aos-loop；11-04 起沒寫＝預設名、`null`＝不開） |
| `procs_ctl`、`procs_state` | 檔名或 `null` | `procs_ctl.json`、`procs_state.json` | 管轄（名單）的手把與狀態窗，在 `$AOS_STACK` 底下；寫 `null`＝不開 |
| `procs_requests` | 路徑或 `null` | `procs_requests` | 信箱：名單的增減也可以一封封信投進來（在 `$AOS_STACK` 底下；11-04 起沒寫＝開在預設名、`null`＝不開）；跟 `procs_ctl` 可以同時開，都不開＝名單只看 daemon.json。見下「信箱」 |
| `procs` | `{名字: proc}` | `{}` | 名單；每項怎麼起看寫法（下「看寫法決定怎麼起」）；物件可多寫 `ws`、`stack`、`def`（定義資料夾，只記進表；見[看寫法決定怎麼起](02-看寫法決定怎麼起.md)）、`limits`（份額，[09](09-份額.md)）。拆成好幾份檔寫 `{"$ref": ["procs-1.json", "procs-2.json"]}`（下「指示詞與切檔」） |
| `procs_loop`、`procs_exec`、`procs_stderr` | 檔名 | `loop.json`、`exec.json`、`stderr.txt` | proc 的 stack 裡 daemon 自己寫的三個檔（loop 型的設定、exec 型的內嵌單子、兩型的 stderr；暫存檔＝`.`＋名字）。要是檔名（非空、不含 `/`、不以 `.` 開頭），不收 `null`，壞＝`CfgBad`。daemon 在 `procs_state.json` 頂層回報同名欄（還有 `procs_requests`，沒開＝`null`），讀 proc 的 stack 的人（aos-daemon-ctl、aos-agent、adopt）從窗拿、不寫死（11-04，使用者題 6「是否能在json中設置？但默認用這些名」） |
| `limits` | 物件或 `null` | 不限 | 沒寫 `limits` 的列用的預設份額（11-05；key 與規則見 [09-份額](09-份額.md)）；壞＝`CfgBad` |
| `adopt` | 布林 | true | 起來時讀自己上次的 procs_state，把還活著的接回、不重起；`stopped` 的列接成 `stopped`、`sleeping` 的列接回後自動 wake |

- 要 `$AOS_STACK`（沒設＝`StackMissing`）。名字不能當資料夾名或會被 aos-exec 誤認（空、含 `/`、含 `#`、以 `.` 開頭）＝`CfgBad``procs: name … cannot be a directory name`。跟自己的窗同名不擋（proc 的 stack 在 `procs/<名字>/`，撞不到 stack 頂層的窗）。
- **每次**（Loop 讀完 ctl 之後）：讀 procs_ctl →（開了信箱：套信、改底）→ 期望表＝procs_ctl 的 `procs`（有寫）或底，＋`procs_added`－`procs_removed`；stopped 集合＝底＋`procs_stopped`－`procs_started` →
  表上多出來的送 SIGTERM（`phase: stopping`）就往下走、**不等**，之後每次看一眼：退了印 log、從表上拿掉（proc 的 stack 留著），滿 10 秒還在就 SIGKILL 整群（子 loop 那群，加上它底下自成一群的——inst 起的單子）→
  在 stopped 集合裡、還在跑的＝daemon 的 stop（下「起、停、暫停」）→ 看誰自己結束了（`phase: done`，記 `code`／`signal`，印 log、拿掉、本次執行不再起）→
  起表上少掉的（在 stopped 集合裡的＝直接一列 `stopped`、不起；收的途中的同名項還在表上，等它退了下一次才起；本次執行已自己結束的不起）、`stopped` 的列拿出集合了＝start →
  跑 `exec`（有寫才跑）→ 寫 state、接著寫 procs_state（有變才寫）。ctl 是 `stop` 或 `pause` 的那圈不調表（下「兩個手把、兩扇狀態窗」）。
  被 `aos-daemon-ctl poke` 叫醒的那圈（11-09）：`--ctl` 跳過信箱與身體、`--mail` 跳過身體、`--all` 照上面整圈、身體不管 `interval_ms` 提前跑（[04 poke 門鈴](04-兩個手把-兩扇狀態窗.md#poke-門鈴11-09)）。
- **同名改寫法**（例：loop 型改成 exec 型、改了 `ws`）＝設定變了，已在跑的**不重起**（N-54「名字已在表上的不看設定變了沒」）；等它退了被拿掉／被 rm 再放回、或 stop 再 start 才照新寫法。
- **自然退 0 才下表，非 0 留 stopped**（11-07 B；auto_restart 照舊）（使用者「改成子項結束後不留名單」、「照舊拿掉」）：跑滿 `max`、身體退 10、訊號、別人直接往子 loop 的 ctl 寫 `{"cmd": "stop"}`——
  除了 stop／sleep 與 auto_restart 的路徑，退 0 才印 log 並從表上拿掉（＝對 daemon 不存在），proc 的 stack 照留。**11-07 裁定 B**：任何 proc 退非 0（含被訊號打掉）不拿掉、留 `stopped`＋`reason`（[03](03-起-停-暫停.md)「出錯結束一律留」）。自己結束（`done`）的**本次執行不再起**：記進 `ended_`（名字），期望表扣掉它；某一圈的期望表裡沒有它了才從 `ended_` 拿掉（之後名單再有它就照常起）。
  開了信箱再從底拿掉，而且下一圈套信之前，不是 procs_ctl 疊上去的就從 `ended_` 放掉（之後再有信同名 `procs_added`＝重新起）。daemon 重起時 `ended_` 是空的（照 daemon.json 再起）。
- **adopt**：讀上次的 procs_state（沒開 procs_state 窗＝沒東西可接；舊的 `loops_state.json` 不讀），每列的 `launch`、`phase`、`stop_mode` 都從表讀。`phase` 是 `running`、pid＋`started_at_ticks`（/proc 第 22 欄）對得上的放回表上、不重起（log 也印一行 `running`；接回的 `stack` 照列上的）。
  `phase` 是 `stopped` 的列接成 `stopped`（不起、不判活）、名字進底的 stopped 集合；`phase` 是 `sleeping` 的列接成 `sleeping`、**不**進 stopped 集合＝第一圈 wake（下「收工與開門」）；`stopping` 的列也接回，依 `stop_mode` 繼續 stop／sleep／rm。細節見 [08 當機復原](08-當機復原與已知限制.md)。接回的不是自己的子行程，之後看 /proc 判斷活不活，結束那行 `code`／`signal` 是 null。
- **子 loop 被 SIGKILL 時**它 proc 的 stack 裡的 `state.json` 停在最後那份（多半 `running`），daemon 不替它改（N-09）；看死活照 N-17。daemon 的 log 那一行是準的（`stopped`、`signal` 9、`code` 137）。
- 效能（使用者「都修都處理」，[thinking](../../../thinking/2026-10/23/daemon-bench.md)）：收子項不原地等；表＝「照加入順序的串列＋名字→那一列的雜湊表」；
  沒有 `exec` 時一圈只讀一次 ctl、只對一次表、最多寫一份 state（`waiting`；有變才寫，沒其他變動時 state、procs_state 都不動）；對表時起子項之前先寫一份 procs_state、之後每起一個寫一次（有變才寫）。
