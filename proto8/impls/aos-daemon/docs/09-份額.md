## 份額 limits（11-05）

使用者 11-05 午：「啊，還有，會想要限制特定aos proc所占用的資源。以及daemon/kernel自己本身被限制占用資源，並且會分配份額給proc」；方向：「讓daemon偷偷給底下的proc包s6」。規劃與代定：[feat-proto 05](../../../thinking/2026-11/05/feat-proto/05-資源份額.md)（E1～E3）。

```json
{"limits": {"files": 256},
 "procs": {"bob": {"exec": "../agents/bob/fsm.json", "interval_ms": 0, "limits": {"mem_mb": 1024, "cpu_s": 3600}},
           "tick": "../tick"}}
```

- **寫在 daemon 的表上，proc 自己不知道**（「偷偷」，C-52）：proc 物件選填 **`limits`**；daemon.json 頂層選填 **`limits`**＝沒寫 `limits` 的列用的預設（沒寫＝不限）。列寫 `{}`＝不限（蓋過預設）、`null`＝當沒寫（用預設）。字串／陣列寫法沒地方放，要份額就寫成 `{"exec": 它, "limits": …}`（仍是 exec 型）。指示詞照解。`limits` 不寫進小格的 `loop.json`。
- **key**（同 [aos-sandbox](../../../extras/sandbox/README.md) 那套）：`mem_mb`→`RLIMIT_AS`＋`RLIMIT_DATA`（不碰 `RLIMIT_STACK`）、`cpu_s`→`RLIMIT_CPU`、`procs`→`RLIMIT_NPROC`、`file_mb`→`RLIMIT_FSIZE`、`files`→`RLIMIT_NOFILE`，都是正整數、soft＝hard＝寫的值；`user`＝帳號名（字串），換成那個帳號（附加群組、主群組、uid）。
- **怎麼做：等同 s6-softlimit／s6-setuidgid**——daemon 在 fork 出的子行程裡（`setsid`、接好 stderr 之後、`run_cli` 之前）自己呼叫那幾個系統呼叫，**不 exec s6、不依賴 PATH**（代定 1；要「真的是 s6 那支」是[題 6](../../../thinking/2026-11/05/feat-proto/README.md) 的翻案）。之後 aos-exec、aos-loop、身體與它們起的一切都繼承。
- **寫壞**（不是物件、key 不認、值不是正整數、`user` 不是非空字串）＝跟 `stack` 同三條：daemon.json `CfgBad` 退 1、procs_ctl 整份不採用（`ctl_warning`）、信壞信（`mailbox_warning`）。
- **做不到**＝那一支起不來：小格 `stderr.txt` 一行、子行程退 1——比 daemon 自己的 hard limit 寬：`aos-daemon: LimitBad mem_mb 4096 exceeds the daemon's own hard limit`（**不自動夾成 daemon 的**，寫什麼就做什麼，C-56）；`user` 但 daemon 不是 root：`aos-daemon: LimitBad user bob: Operation not permitted (switching users needs the daemon to run as root)`；帳號不在：`LimitBad user bob: no such user`。loop 型照「出錯結束一律留」＝列 `stopped`＋`reason`（`failed to start: … LimitBad …`）；exec 型照舊下表、原因只在 `stderr.txt`。
- **超額＝rlimit 的天然行為**，不加新的錯誤路徑：記憶體到頂＝配置失敗（Python `MemoryError`，多半退非 0）；`cpu_s` 到頂＝SIGXCPU；`files` 到頂＝open 失敗；`file_mb` 到頂＝SIGXFSZ。對 daemon 來說都是「loop 型退非 0＝留 `stopped`＋`reason`」。
- **表上看得到**：`procs_state` 每列多 **`limits`**＝生效的那份（列的，或 daemon 的預設；不限＝不印這欄）；adopt、wake、start 照列上的帶著（同 `ws`：起的那一刻的值，名單後來改了也不變；信箱接回只留名的列再起時用它）。`aos-daemon-ctl ls --json` 原樣帶出、`aos-daemon-ctl add --limits JSON` 寫進那列；aos-agent 的 `ctl add` 送宣告的份額、`ctl state` 多一行 `limits`。
- **天然差異（照實寫）**：rlimit 是**每個行程各自**的上限，**不從 daemon 的總額扣**——三列各寫 `mem_mb: 1024` 加起來可以超過 daemon 自己的 1024；`procs` 數的是那個帳號的全部行程（Linux 的 `RLIMIT_NPROC` 本來如此）。要真共享總額＝cgroup v2（要 root 或 systemd 委派），未來選項、沒做。
- **daemon 自己被限＝起它的人包**（`prlimit`／`ulimit -H`／`aos-sandbox`）：rlimit 繼承，子項天生超不過 daemon 的 hard；子 daemon 再包它的子項只能更緊。
- **`user` 的帳號只認本機 `/etc/passwd`、`/etc/group`**（不經 NSS：aos-daemon 是靜態連結的，`getpwnam` 查不到名字時實測整台 SIGSEGV）。換了帳號的子項要能寫它的小格（`stderr.txt` 已由 daemon 開好、照寫；`loop.json`、`state.json` 要那個帳號寫得進去）——權限是使用者的事（C-64），daemon 不改擁有者。
