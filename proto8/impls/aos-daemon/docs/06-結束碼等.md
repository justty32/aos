### 結束碼

| 怎麼結束 | 結束碼 | stderr |
|---|---|---|
| 跑滿 `max`、ctl `stop`、身體退 10 | 0 | 不寫 |
| 收到 SIGINT／SIGTERM／SIGHUP | 128＋N | 不寫 |
| 自己的錯（設定壞、沒 AOS_STACK、子項起不來、state／procs_state 寫不了、信箱建不了、沒有 exec 卻給了 `-- 參數`） | 1 | 一行 `aos-daemon: 代號 原因` |

不論哪一種，都先收掉所有活著的 proc（全部送 SIGTERM，等它們退；等的這段 state 寫一份 `phase` `stopping`、之後每退一批寫一次 procs_state；滿 10 秒還在的 SIGKILL 整群，連底下自成一群的單子）、寫好 state 再結束（P-36）：
收掉的 log 記 `stopped`、從表上拿掉——還在跑的 loop 型例外：log 記 `sleeping`、列留成 `sleeping`，下次開門自動 wake（上「收工與開門」）；最後一次之後才自己結束的記 `done`、`code`；daemon 停掉的（`stopped` 的列、等它自己退的那些）留在最後一份 procs_state 上。子項的結束碼不影響 daemon 的。

**身體失敗＝記一行、下一圈再跑，不收工**（11-05 晚，使用者裁 [edge-daemon 題 1](../../../thinking/2026-11/05/edge-daemon/README.md)「記一行、下一圈再跑 (Recommended)」；之前同 aos-loop「那次非 0＝退」〔P-20〕，`judge.json` 打錯一字、身體的執行檔剛好在重建〔`LaunchFailed`〕就整台停）：
身體（判官、llm kernel）退 10 以外的非 0、或起不來＝stderr 一行 `aos-daemon: body <誰> failed (code N), retrying next round`（起不來是 `failed (代號 原因)`），**碼或錯變了才印**，好了印一行 `aos-daemon: body <誰> ok again`；`state.json` 多一欄 **`body_code`**（身體最後一次的結束碼，起不來記 1；還沒跑過＝null；沒身體的 daemon 沒這欄）；`interval_ms` 後再跑，proc 照顧著。
身體自己的 stderr 照它自己印（例：kernel.json 壞時 aos-llm-kernel 每圈一行，daemon 不管）。要整台停用 daemon 的 ctl `{"cmd": "stop"}` 或 Ctrl-C。aos-loop 本身不變（身體非 0 照退）。

## 實作注意

- **繼承 aos-loop 的 `Loop`**：daemon.json 是 loop.json 的超集，每次讀 ctl、睡 interval、寫 state、轉訊號都一樣；daemon 用 tend／finish／write_more／info 四個掛鉤（ctl 的檢查用 Loop 預設的）。**身體 daemon 自己跑**（11-05 晚，aos-loop 不改）：建構子把 Loop 的 `exec_` 收成 `body_`、讓 Loop 當沒有身體，`tend` 對完表最後呼叫 `run_body`——到時間才跑（Loop 一輪可能 tend 好幾次）、`max` 照算、跑前跑後各寫一份 `running`（`body_code` 變了照 Loop 有身體時的 phase 寫）；退 10＝`stopping_`（同 ctl stop：phase `stopped`、碼 0，原本 Loop 是 `done`）；跑的期間收到訊號＝`kill` 排回自己，Loop 下次取到就 128＋N 收工。ctl 的 stop／pause 由 Loop 照做完放在 `stopping_`／`paused_`，`tend` 看這兩格決定調不調表。
- **子 loop 經 aos-exec 起**（使用者「5.要」）：子 loop 跟別的程式一樣是「一個資料夾程式」——小格就是它的資料夾、`loop.json` 的 `_entry` 就是入口，所以小格裡放 `.env` 也有作用。
  fork 後在子行程裡呼叫 aos-exec 的 `run_cli`（不必在 PATH 上找 aos-exec），它最後 exec 成 PATH 上的 aos-loop，所以 `ps` 看到的子 loop 叫 `aos-loop`。
  fork 時 daemon 只有一條執行緒，子行程裡 C++ 配置、setenv 安全；三個訊號 daemon 一開始就擋著，子行程 exec 之前解開。
- **相對的 exec 照 daemon 的 cwd 轉絕對**：子 loop 經 aos-exec 起之後 cwd 是小格，不轉的話 `"exec": "../agents/bob"` 會從小格算。只轉字串與陣列的第一個元素，其他不動、不驗。
- **stop 的 seq**：daemon 寫子 loop 的 ctl 前讀它現有的 `seq`、取「自己數的＋1」與「現有的＋1」大的那個（遞增，內容一定跟上一道不一樣）——daemon 重起後計數從 0 開始，不這樣的話可能寫出跟子 loop 基準線一樣的內容、被當成同一道。
