### 看寫法決定怎麼起

| 寫法 | 型 | daemon 怎麼起 | proc 的 stack 裡 |
|---|---|---|---|
| 字串、`[目標, 參數...]`（非空字串陣列） | exec 型 | `aos-exec -- 目標 參數...` 一次，不包 aos-loop（`spawn_exec`） | `stderr.txt`、程式自己的檔 |
| 物件，key 只有 `exec`（＋`ws`、`stack`、`def`、`limits`、`auto_restart`、`restart_on_stuck`、`stuck_after_ticks`）；`exec` 是目標或內嵌單子 | exec 型 | 同上；單子＝寫成 proc 的 stack 的 `exec.json` `{"exec": 單子}`，`aos-exec -- proc 的 stack/exec.json#/exec` 跑一次 | 同上（單子多一份 `exec.json`） |
| 其他物件（多了任何一個 key：`max`、`interval_ms`、`ctl`、`state`、`body`、`envs`……；沒有 `exec` 也算） | loop 型 | 寫 proc 的 stack 的 `loop.json`、經 aos-exec 起一支子 aos-loop（`spawn`） | `loop.json`、`state.json`（子 loop 的窗）、`stderr.txt`、程式自己的檔 |

- **怎麼判（白話，11-04 使用者題 3「不動，文件寫清楚」）**：字串或陣列＝跑一次；物件只有 `exec`（可加 `ws`、`stack`、`def`、`limits`、`auto_restart`、`restart_on_stuck`、`stuck_after_ticks`）＝跑一次；物件多任何一個 loop 的 key（`max`、`interval_ms`、`ctl`、`state`）＝一直跑的 loop。**要一直跑，最少寫 `"interval_ms": 0`**（aos-loop 的預設本來就是 0，行為不變）。三個例子：
  `"a": "../job"`＝跑 `../job` 一次；`"b": {"exec": "fsm.json", "ws": "/w"}`＝跑 `fsm.json` 一次；`"c": {"exec": "fsm.json", "interval_ms": 0}`＝子 aos-loop 一直跑 `fsm.json`。aos-daemon-ctl add 的 loop.json 只有 `exec` 時替它補 `"interval_ms": 0` 就是為了這條。
- **不標哪種**：要分看 proc 的 stack 有沒有 `loop.json`（daemon 寫的；名字照 `procs_loop`，下同）。`Child::once` 只在記憶體裡（起的時候判、adopt 看 `loop.json`）。
- **通用布林 `auto_restart`、`restart_on_stuck`**（11-06 no-pid P6，使用者「不要耦合」後選的通用選項，[no-pid 15](../../../thinking/2026-11/05/no-pid/15-P6去耦合.md)）：任何物件寫法都能加（exec 型加了仍是 exec 型；loop 型不寫進 `loop.json`）；`null`＝沒寫，其他型別＝`CfgBad`。`auto_restart: true`＝常駐、退了照表重起（[03](03-起-停-暫停.md#auto_restart常駐11-06)）；`restart_on_stuck: true`＝判卡住時收掉再起（P7，[04](04-兩個手把-兩扇狀態窗.md#判卡住-stuck11-06-p7)）。字串／陣列寫法放不下，要用就寫成 `{"exec": …, "auto_restart": true}`。
- **`stuck_after_ticks`**（11-06 P7）：任何物件寫法可加的正整數，沒寫＝10；`null`、0、負數與其他型別＝`CfgBad`。exec 型加了仍是 exec 型，loop 型不傳給子 loop；表上記同名欄（不是 10 才寫），adopt 接回照用、沒這欄＝10。期限走 aos-util `deadline_after` 兩鐘規則：有 `AOS_TICK` 比 tick，沒設才用 `AOS_TICK_INTERVAL`（預設 1000 毫秒）換成牆鐘；有設但檔不在或空＝第 0 格，時鐘不走就不到期。
- **掛子 daemon**＝普通 proc（使用者 11-06「對於daemon來說，子daemon對他來說就只是一個普通的proc。不要耦合」）：`"sub": {"exec": "../sub", "auto_restart": true}`（`../sub/_entry`＝`["aos-daemon", "daemon.json"]`），父不知道它是 daemon。os-impl A7 的對照改讀：exec 型＝s6-rc 的 oneshot、loop 型＝longrun、`auto_restart`＝s6-supervise 那種「掛了再拉起」；bundle（整棵子樹）不是父的寫法，是子 daemon 自己管它那棵。
- exec 型物件的 `exec` 不是目標也不是物件（例 `3`、`null`）＝`CfgBad`；loop 型物件 daemon 只解自己認的格（`exec`、`max`、`interval_ms`、`ctl`、`state`、`ws`、`stack`、`def`、`limits`、`auto_restart`、`restart_on_stuck`、`stuck_after_ticks`），其他原樣交給子 loop、不驗（寫錯了子 loop 自己退 1，沒有 `exec`＝「沒有東西可跑」退 1）。
- **起子 loop**（經 aos-exec）：proc 的 stack mkdir；設定不補 `ctl`／`state`（11-04 起 aos-loop 沒寫＝`ctl.json`／`state.json`）、拿掉 `ws`、`stack`、`def`、`limits`、`auto_restart`、`restart_on_stuck`、`stuck_after_ticks`（daemon 的 key，不寫進 `loop.json`），
  **一律蓋上 `"_entry": ["aos-loop", {"$env": "AOS_CF"}]`**，相對的 `exec`（字串，或陣列的第一個元素）照 daemon 的 cwd 轉成絕對路徑（子 loop 的 cwd 會是 proc 的 stack）；`exec` 是內嵌單子＝沒寫 `cwd` 補上 daemon 的 cwd、相對的接在後面（指示詞不動），單子裡相對的 `$ref` 檔名照它來自的檔轉成絕對（`abs_refs`，不解）；
  先寫 `.loop.json` 再改名成 `loop.json`；fork 一個子行程：`setsid` 自成 session、stdin／stdout 接 `/dev/null`、stderr 附加到 proc 的 stack 的 `stderr.txt`、`AOS_STACK=proc 的 stack/`、`AOS_DAEMON=daemon 的 stack`、（寫了 `ws`）`AOS_WS`、
  解開三個訊號、cd 到 daemon 的 cwd，呼叫 aos-exec 的 `run_cli({"--", "proc 的 stack/loop.json#/_entry"})`——它 cd 進 proc 的 stack、讀 proc 的 stack 的 `.env`（若有）、設好 `AOS_CF`＝proc 的 stack 的 loop.json，再 **exec 成 PATH 上的 aos-loop**（pid 不變）。
  所以 **PATH 上要有 aos-loop 和 aos-exec**；沒有＝子 loop 以 1 結束、原因寫在 proc 的 stack 的 `stderr.txt`。
- **起 exec 型**：proc 的 stack、`stderr.txt`、setsid、`/dev/null`、`AOS_STACK`、`AOS_DAEMON`、`AOS_WS`、cd 到 daemon 的 cwd 都同上，**只是不包 aos-loop、不寫 `loop.json`**：子行程直接 `run_cli({"--", 目標, 參數...})`，表上的 pid 就是那支程式；相對路徑從 daemon 的 cwd 算（不轉）。
  退了＝`done`、不重起（同 loop 型）；**exec 型只有跑和拔**（使用者「他停下來就是沒了，新開的就是新的 CPU 了」）：`procs_stopped`／`procs_started` 裡有它＝procs_ctl 整份不採用／壞信（下「起、停、暫停」）。要一次性的東西能停，寫成 `max: 1` 的 loop。

### 自帶時鐘 `tick`（選填）

```json
{"tick": true, "procs": {}}
{"tick": {"file": "clock", "interval_ms": 200, "name": "_clock"}, "procs": {}}
```

- `true` 或物件＝開時鐘；不寫、`null`、`false`＝不展開，環境照繼承。物件只認 `file`、`interval_ms`、`name`；`file` 預設 `tick`（相對 daemon 的 stack，亦可絕對路徑）、`interval_ms` 預設讀 `AOS_TICK_INTERVAL`（沒設＝1000 毫秒）、`name` 預設 `_tick`。路徑和名字須為非空字串，名字須能當 proc 名，間隔須為正整數；錯型別、未知 key 或撞到 `procs` 名字＝`CfgBad`。
- daemon 在名單最前面插入普通 **loop 型** proc：`{"exec": {"argv": ["aos-tick", "時鐘檔絕對路徑"]}, "interval_ms": N, "auto_restart": true}`；stack 預設 `procs/<name>`。PATH 要有 `aos-tick`、`aos-loop`。用內嵌 inst 的 `argv` 從 PATH 找 `aos-tick`（普通 exec 陣列是 aos-exec 目標，不能拿來找 PATH）。每次身體只加一格，重起、stop／start、sleep／wake 都走一般 proc 規則，沒有時鐘專屬的監管規則。
- **起任何身體或子項前**先設定自己行程的 `AOS_TICK`＝時鐘檔絕對路徑，底下照繼承；子 daemon 自帶 `tick` 就覆蓋成自己的，**近的贏**。只有物件**明寫** `interval_ms` 且不等於 1000 時，才連 `AOS_TICK_INTERVAL` 一起設；其餘保留原環境。
- daemon 的自帶時鐘展開不等時鐘；P7 的卡住期限透過共用 `deadline_after`／`expired` 判，頂層狀態窗的 `tick` 是觀察值（見 [04](04-兩個手把-兩扇狀態窗.md)）。`pause _tick` 會停時鐘、工作照跑；daemon 自己 pause 不停子項，時鐘照走。時間過舊不退牆鐘、不 warning；忘了 resume，tick 期限就不會到。
- **不要讓兩台 daemon 指向同一個絕對時鐘檔**，否則會加倍計數。改 `tick` 前先 sleep 整台 daemon、等它收完，再改定義、wake／重開；活著直接改會讓接回的 proc 寫舊檔、環境卻指新檔。

### 每個 proc 自己的 stack

```json
{"procs": {"c": {"exec": "../clock", "interval_ms": 1000, "stack": "/tmp/c"}, "j": {"exec": "../job", "stack": "jobs/j"}}}
```

- **`stack`**（物件選填）：非空字串；`null`＝當沒寫；其他型別、空字串＝寫壞（daemon.json `CfgBad`、procs_ctl 不採用、信壞信）。字串／陣列寫法沒地方放，要指定就寫成 `{"exec": 它, "stack": S}`。指示詞照解（`resolve_keys` 有 `stack`）。
- **相對路徑從 daemon 的 cwd 算**（同 `ws`、子項 `exec`），讀進來就轉絕對（`abspath`：`.`、`..` 收掉、捷徑不解、結尾不帶 `/`）。
- **用法**：`AOS_STACK=<S>/`（取代預設 proc 的 stack）；loop 型的 `loop.json`／`ctl.json`／`state.json`、單子的 `exec.json`、`stderr.txt` 都寫進 S；**S 不在就建**（`mkdir -p`，同 `aos-exec --stack`）；建不了＝`MkdirFailed`。
  沒寫＝預設 proc 的 stack `$AOS_STACK/procs/<名字>/`（只建 `procs/` 與 proc 的 stack 兩層；`$AOS_STACK` 不在＝開了 state 或 procs_state 窗就 `WriteFailed`、兩扇都沒開才 `MkdirFailed`，都退 1——建 daemon 的 stack 只在 aos-exec 做，N-59 第 1 件）。寫了 `stack` 的 `procs/<名字>/` 根本不建。
- **不查、不擋**（C-52、N-28）：S 裡有別的東西、兩個 proc 同一個 S、S 指到 daemon 自己的 stack、S 是捷徑——都不管，使用者自己承擔。`rm` 不清 S。
- **`procs_state` 每列一律有 `stack`**（相對 daemon 的 stack；預設為 `procs/<名字>`）：adopt 與 start 照列上的，`aos-daemon-ctl where` 也靠它。
- **`procs_state` 每列一律有 `exec`**（11-04 晚，使用者「daemon表多一欄記下來」，[aos-agent 06/02](../../../thinking/2026-11/04/aos-agent/06-衝突與方向題/02-新題-11-04-晚.md#使用者裁定11-04-晚選項原文) 方向題 1）：每列多一欄 `exec`＝起它時的目標（字串目標、陣列的第一個、物件的 `exec`，先照 daemon 的 cwd 轉絕對，再存成相對 daemon 的 stack，`檔#/…` 片段照留；內嵌單子＝`null`），adopt 接回的照舊表帶過來（信箱接回只留名的列沒有設定，exec 欄只能從舊表來）；名單後來改了也不變（同 `ws`）。aos-daemon-ctl add 給的是 `<XXX>/loop.json#/exec`（loop 型、內嵌單子）、loop.json 的 exec 轉絕對、或 XXX（exec 型）。
- **物件多一個選填 key `def`、`procs_state` 每列一律有 `def`**（11-04，使用者 11-04「那就b。」，[aos-agent 05/03 第 2 條](../../../thinking/2026-11/04/aos-agent/05-實作步驟/03-實作時改的設計.md#實作時改的設計)）：`def`＝這隻的定義資料夾；規則同 `ws`（非空字串、`null`＝當沒寫、其他型別＝寫壞；指示詞照解；從 daemon 的 cwd 轉絕對），**不驗在不在、不碰它**，不寫進 `loop.json`、不進子行程環境，只記進列的 `def` 欄（沒給＝`null`）；adopt、start、wake 照列上的帶著（同 `exec`）。exec 型物件多了 `def` 仍是 exec 型。aos-daemon-ctl add 一律送 `def`＝XXX 的絕對路徑；aos-agent 靠這欄找定義（不再從 `exec` 欄推）。
- **物件多一個選填 key `limits`（份額，11-05）**：daemon 在子行程 setrlimit／換帳號（等同 s6-softlimit／s6-setuidgid），列上多 `limits` 欄；exec 型物件多了它仍是 exec 型。規則、錯誤、天然差異見 [09-份額](09-份額.md)。
