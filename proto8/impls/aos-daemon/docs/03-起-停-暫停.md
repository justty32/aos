### 起、停、暫停

四態：**running**（表上、活著）、**stopping**（收的途中）、**stopped**（表上、**行程不在**、stack 留著）、**表上沒有**（＝對 daemon 不存在）；另有收工留下的 `sleeping`（下「收工與開門」）。動作：`add`／`rm`＝`procs_added`／`procs_removed`、`stop`／`start`＝`procs_stopped`／`procs_started`、`pause`／`resume`＝不是 daemon 的事（直接寫子 loop 的 ctl）。

`ctl`／`state`／`state_flux` 的預設名、欄位與指令值引用 aos-loop 公開標頭 `aos/loop.hpp` 的 `CtlWindow`／`StateWindow`／`StateFluxWindow`，daemon 不另定義一份（11-06 K-2）。

- **stop（所有 proc；11-07 裁定 B）**：往該列 stack 的公開 ctl 寫 `{"cmd":"stop","seq":N}`，列進 `stopping`，等它自己退；退了留 `stopped`。小格有父寫的 loop.json 且 ctl 是非空字串才用它，否則用 `ctl.json`。不改送 SIGTERM，沒人讀就等程式自己結束；寫不了只印一行 warning、照樣等，沒有時間上限。
- 名字在 stopped 集合、行程還沒等到 daemon 寫 ctl 就自己退了＝一樣留成 `stopped`。等它自己退的途中被拿掉（不在期望表了）＝改送 SIGTERM，退了照樣拿掉。
- **同一封信（或同一份 procs_ctl）add＋stop**＝列直接 `stopped`（`pid`、`code` 都是 null）、不起、**stack 先不建**。
- **start**：從 stopped 集合拿掉→下一圈用**列上的 `stack`** 再起（loop 型重寫同一格的 `loop.json`；**不清 ctl**：子 loop 起來第一拍比上一份 state_flux 的 `ctl_seq`；同 seq 已套用過就不重做，所以正常 stop 後 start 不會被同一道 stop 再停。不同或沒有回音的指令照做）。起來是跑還是暫停看它自己 `state.json` 的 `paused`（暫停中被停的，起來先暫停；代定）。
  設定照期望表上的（同名 add 換過就是新的）；信箱接回的列沒有設定（null）＝照表上 `launch` 重放入口與完整參數。
- **只有指令叫起**：信來、procs_ctl 別的 key 變、`procs_added` 同名都不會把 `stopped` 的拉起來（同名 add＝設定換掉、停照停）。procs_ctl 拿掉 `procs_stopped` 的名字＝回初始值＝起（N-06）；要一直停就一直寫。底的 stopped 集合是 adopt 接回的 `stopped` 列＋信改過的——**重起 daemon 後**，procs_ctl 拿掉名字不會起它（初始就是停的），要 `procs_started`（代定）。
- **任何起法都採用**：procs_ctl 與信箱的 stop／start／sleep／wake 不再因起法拒絕。不在期望表的名字仍忽略；CLI 真正的 phase 用錯仍是 `PhaseBad`。
- **stopped 的被 rm**：列與集合都拿掉、stack 不碰；它 ctl 裡的 `{"cmd": "stop"}` 留著沒事。
- **繞過 daemon 自己往子 loop 的 ctl 寫 `{"cmd": "stop"}`**：子 loop 退 0，daemon 看到的是「退了」→從表上拿掉（＝拔掉，不是 stop；使用者「照舊拿掉」）。子 loop **退非 0** 的不拿掉、留 `stopped`＋`reason`（11-05 晚，下「11-05 搬家相關」最後兩條）。掛在 daemon 下要停就走 daemon。
- **pause／resume**：不是 daemon 的事——寫子 loop 自己的 ctl `{"cmd": "pause"}`／`{"cmd": "resume"}`（`aos-daemon-ctl pause`／`resume` 就是這樣做）；daemon 不轉述 paused（不讀子項的 state，C-52），要看讀它的 `state.json`。
- **daemon 自己暫停中**：起停也等解除（不寫子 loop 的 ctl）；daemon 收工＝收掉活著的（所有仍活著的列送 SIGTERM，退了依下一段留 `sleeping`／`stopped` 或拿掉）、`stopped` 的列照寫進最後一份 procs_state；再起 adopt 接回 `stopped` 的、wake `sleeping` 的、照名單起其他的。

### 收工與開門：sleep／wake

使用者「改寫成休息中」「我們有start/stop, sleep/wake, pause/resume，我們缺了sleep/wake」（[procs § 8](../../../thinking/2026-11/03/procs/10-實作時代定-11-03-實作者照原則定的.md#8-收工時改寫成休息中sleepwake11-03-晚)）：daemon 收工時還在跑的不從表上擦掉，改寫成 **`sleeping`**（表上、行程不在、stack 留著），daemon 再開時**自動 wake**。

- **sleep**：daemon 收工（自己 ctl 的 `{"cmd": "stop"}`、SIGTERM／SIGINT／SIGHUP，或出錯退出——都走 `finish`）時，所有還活著的 **proc**照舊 SIGTERM（10 秒 SIGKILL）。
  收工時 running 的睡下（sleeping），stop 途中的留 stopped，sleep 途中的睡下，rm 途中的拿掉；收工途中被 kill -9，重開時照表上的 `stop_mode` 做，結果一樣。收工前已是 `stopped`／`sleeping` 的保留；睡下的列留成 `{"pid": null, "started_at_ticks": null, "phase": "sleeping", "code", "signal", "stack", "ws"?}`，log 一行 `sleeping`。
- **wake**：daemon 再開 adopt 時，`sleeping` 的列接回、不進 stopped 集合；第一圈 reconcile 跟 start 走同一條：**用列上的 `stack`** 再起（設定照期望表；信箱接回的沒有設定＝照表上 `launch` 重放入口與完整參數、`ws` 照列上記的），log 一行 `running`。
  收工時本來暫停中的：子 loop 被 SIGTERM 時最後一份 `state.json` 記著 `paused: true`，用同一個 stack 起來照它自己的 state 先暫停（代定），`resume` 才接著跑。
- **睡著時收到的指令**（daemon 沒在跑時 `aos-daemon-ctl` 寄的信，開門後先套信再對表）：`procs_stopped`＝改成 `stopped`、不 wake（要 `start`）；`procs_removed`＝列拿掉；名單（daemon.json／procs_ctl）上已經沒有它＝列拿掉。
- daemon 開門時自己是暫停中（它的 state.json 記著 `paused`）＝跟起停一樣等解除才 wake。`adopt: false`＝不讀舊表，`sleeping` 的列就不認了（照 daemon.json 重新起）。
- **`kill -9` 的 daemon**沒走收工：子項還活著＝照舊 adopt 接回；子項也死了、或列正在 `stopping`＝見 [08 當機復原](08-當機復原與已知限制.md)（11-05 第二輪）；`sleep`／`wake` 也是 `aos-daemon-ctl` 的子命令（11-05 起可手動睡／醒，見下「11-05 搬家相關」）。
- **整棵樹 sleep／wake**（11-06 no-pid P6；os-impl A15）：子 daemon 掛成普通 proc，父照上面收工送 SIGTERM；子 daemon 收到就自己收工、把它的 procs 留 `sleeping` 才退——所以**葉先睡、根最後**，是每層自己做的，父不排順序。開門反過來：父先起、照名單或 `sleeping` 列起子，子從自己的 stack 叫醒它的 procs。父等每支子項照舊 10 秒（子 daemon 自己收子項是並行的，通常 1 秒內退完；孫子不理 SIGTERM 才會撞到 10 秒、被父整棵 SIGKILL）。在飛的問腦：子收工時收掉、列 `sleeping`、醒來重問（可能多花一次腦）；「凍前等在飛問腦收完」還沒做。

### auto_restart：常駐（11-06）

使用者 11-06 選項框選「通用 restart: true (Recommended)」、名字定 `auto_restart`（「因為單restart，你不知道他想表達的意思。」），[no-pid 15](../../../thinking/2026-11/05/no-pid/15-P6去耦合.md)。任何 proc（exec 型、loop 型）寫 `"auto_restart": true`：

- **自己退了＝同一拍照表重起**：退 0、非 0、被訊號打掉、接回來的拿不到碼都算。列先留 `sleeping`（log 那行記 `done`），對表第二段用同一個 stack 再起；這時 daemon 剛好被 `kill -9`，重開也會 wake 它。
- **連 3 次都在起來 3 秒內就退**＝列留 `stopped`＋`reason`（`…; restarted 3 times in a row, each exited within 3s; not restarting again`）、要人 `start`（計數歸 0）；中間有一次撐過 3 秒就重算。計數只在記憶體，daemon 重開歸 0。
- **auto_restart 只管自己退後重起**：stop／sleep 與收工睡醒適用所有 proc，不再需要靠此旗標放行；重開以 `launch` 保留入口與參數。
- 人下的 `stop`／`sleep`／`rm` 不重起；daemon 暫停或收工中看到它退＝留 `sleeping`，等解除／下次開門。
- 沒寫＝原本的行為，一點不變（N-28「子項結束後不自動重起」；11-06 起這句的例外就是 `auto_restart`）。

### log

使用者「daemon和loop他們就是把log輸出到stdout」，「應該要改成默認不印」：`--enable-logs` 才印到 **stdout**（同 aos-loop；不寫 log 檔）。一行一個 JSON：

- **行程起來一行、結束一行**：`{"at": ISO 8601 UTC 毫秒, "name": 名字, "phase": "running"|"done"|"stopped"|"sleeping", "pid", "code", "signal"}`，起它時給了 `ws` 的多一欄 `"ws"`（最後一欄）。起來那行 `code`／`signal` 是 null；adopt 接回的也印一行 `running`；
  daemon 停掉的退了也是 `stopped` 那一行（列留在表上）；收工時收掉的 proc是 `sleeping` 那一行（列留在表上）、wake 起來印 `running`；`stopped` 的列被 rm、add＋stop 直接成的 `stopped` 列沒有行程起落，不印。
- daemon 自己有 `exec`（身體）時同 aos-loop 每跑完一次一行 `{"started_at", "counter_runs", "code", "signal", "elapsed_ms"}`（11-05 晚起身體由 daemon 自己跑，行照印、`counter_runs`＝身體跑了幾次）；沒有身體不印每圈的行。
- 子項的 stdout 接 `/dev/null`（N-28），不會混進來；daemon 自己的身體繼承 daemon 的 stdout，會跟 log 交錯。印不了（關掉的管子）＝之後不印、照跑。

### 11-05 搬家相關：sleep／wake 指令、相對路徑、留 stopped＋原因、有就沿用

依據 [thinking 11-05 portable-flow](../../../thinking/2026-11/05/portable-flow/README.md)（使用者「我希望整套系統是方便的……一起直接複製到另一個地方。實現無痛遷移」）。

- **sleep／wake 是指令**（衝突 1，使用者選「嚴格分」）：信或 `procs_ctl.json` 的 `procs_slept`（名字陣列）＝**現在就睡**：對那一隻做收工那套（SIGTERM、10 秒還在就 SIGKILL 整群、列留 `sleeping`、stack 留著）；`procs_woken`＝叫醒（用列上的 stack 再起）。手動睡的**這一班不會自己醒**，要 wake；daemon 收工再開時 slept 集合是空的＝睡著的列**開門自己醒**（跟收工時順手睡的一樣）。跟 stop 的差別一句：**stop 等它做完這輪、要人 start；sleep 現在就睡、wake 或開門就醒**。任何起法都能 sleep／wake。sleep 不寫 ctl，因公開協定沒有 sleep 指令。「用錯就 PhaseBad」（sleep 收 running／stopping（stop 中改送 SIGTERM、退後仍 stopped，用 start 再起）、wake 只收 sleeping、start 只收 stopped、stop 只收 running）由 [aos-daemon-ctl](../../../cmd/docs/03-aos-daemon-ctl.md) 照表擋；daemon 本身對錯的組合不報錯（例：睡著的列又收到 sleep＝照睡）。add＋sleep 同時＝直接一列 `sleeping`、不起。
- **表上的路徑相對 daemon 的 stack**（使用者「可以用daemon作為相對路徑的一個基準點」，題 1 選「daemon 的 stack」）：`procs_state.json` 每列 `stack`、`ws`、`exec`、`def` 存成相對 `AOS_DAEMON`（daemon 自己的 stack）的路徑；基準點 `AOS_DAEMON` 取 stack 的**真實路徑**（解開捷徑；11-05 B 線：`ws/.stack` 是捷徑時字面算的 `../..` 被 OS 照實體走到別處，proc 的 stack 起不來），目標照字面（例 `procs/bob`、`..`、`../../agents/bob/fsm.json`、`../../kernel/loop.json#/exec`）；adopt 讀的時候從**新的** stack 拼回絕對（舊表是絕對的照用）。proc 的 stack `loop.json` 的 `exec` 寫成 `{"$env": "AOS_DAEMON", "$path": 相對}`（aos-loop 解指示詞拼回）；內嵌單子的 `cwd` 同、裡面的 `$ref` 改成相對 proc 的 stack。運行時的環境變數（`AOS_DAEMON`、`AOS_STACK`、`AOS_WS`）照舊絕對、每次開門重算。所以 Ctrl-C 之後把整個 `ws/`（連 `.stack`）跟定義保持相對位置一起 `cp -r` 或 git 來回，在新位置 `aos-exec ../daemon` 就在新位置醒（11-05 實測）。指到 daemon 外面的路徑照寫、解不開照各自的錯（自擔）。
- **寫成指示詞的路徑每次起再解**（11-10 two-machines，使用者「兩台各自設一次...不要限制只設一次」）：信（`procs_added`）或設定裡 proc 的 `ws`、`stack`、`def`、目標（`exec`，或 `exec` 陣列的第一個）寫成 `{"$env": …}`／`{"$ref": …}` 時，列多一欄 `as_written`＝那幾格的原形（`$ref` 的檔名存相對 daemon 的 stack）；`ws`、`stack`、`exec`、`def` 欄照舊是解好的值（給讀表的人）。信箱接回只留名的列再起（wake／start／auto_restart）時照 daemon **當下**的環境再解：改了環境變數、重起樹＝照新值走（子 loop 的入口是小格的 `loop.json`＝改寫它的 `exec`）；解不開（變數沒設）＝留 `stopped`＋`reason`（`failed to start: DirectiveBad …`），不退回舊值。daemon.json 的 procs 本來每次開門就重讀、重解。`as_written` 是 daemon 自己的 key，寫在設定裡的不算。
- **寫的人要求原樣存的絕對路徑**（11-10 晚 two-machines B01 後半，使用者選「絕對路徑原樣存」）：proc 物件可以帶 `"as_written": {"ws"?, "stack"?, "def"?, "exec"?}`，值只收絕對路徑字串（`檔#/…` 的 `#` 前面絕對）；daemon 把它併進列的 `as_written`（同一格寫成指示詞的以指示詞為準），表上照存、每次起照它，不換算成相對 daemon 的 stack。別的寫法（相對路徑、非字串、多的 key）＝`CfgBad`（信被拒，原因進 `mailbox_warning`）。`aos-daemon-ctl add`／`aos-agent ctl add` 在使用者把路徑打成絕對時替他寫這格。
- **stop 之後 sleep 再 start 不會馬上又停**（11-10，prefix-fixes 沒修的那條，使用者裁現在修）：`stop` 寫進小格 ctl 的 `{"cmd": "stop", "seq": N}` 子 loop 還沒回應就被 `sleep` 打掉時，那道 stop 留在 ctl 裡；從 `stopped`／`sleeping` 再起之前 daemon 把它的 `cmd` 拿掉（`seq` 照留），新起的子 loop 就不會照做。ctl 裡別的指令（pause 等）不動。
- **wake／start 起不來的留 `stopped`＋原因**（衝突 3，使用者「留成stopped，並寫原因」）：從 `stopped`／`sleeping` 的列再起的那一支，3 秒內就退了（定義沒一起搬、exec 的檔不在…）＝**不下表**，列留成 `stopped`、`code` 記結束碼、欄 `reason`；`aos-daemon-ctl ls`、`aos-agent ctl state` 看得到；修好路徑 `start` 就回來。每列一律寫 `reason`（`null` 或字串）。11-05 晚起擴大成下一條「出錯結束一律留表」，3 秒只用來分原因字樣。
- **出錯結束一律留 `stopped`＋原因**（11-05 晚，使用者裁 [edge-agent 題 1](../../../thinking/2026-11/05/edge-agent/README.md)「留表標 stopped (Recommended)」、[edge-daemon 題 2](../../../thinking/2026-11/05/edge-daemon/README.md)「一起改成留表 (Recommended)」）：**所有 proc**的行程自己退了、結束碼非 0（含被訊號打掉的 128＋N）＝不下表，列留成 `stopped`、進 stopped 集合（要 `start` 才再起；新 add 的第一圈也一樣），`reason`（英文）：
  wake／start 後 3 秒內退＝`failed to start: exited within 3s of wake/start (code N)`，其他＝`failed while running: exited with code N`；被訊號打掉多寫 `, signal S`；後面接 proc 的 stack `stderr.txt` 最後非空行（`: …`，最多 300 位元組）；不認下層程式名或錯誤字句、不跳過包裝行（11-06 K-2）。
  修好之後 `aos-daemon-ctl start`（或 aos-agent 的 `llm reset`／`tools reset` 再 `ctl start`）就用同一個 stack 回來；不要了 `rm`。**照舊下表的**：退 0（做完：跑滿、身體退 10、繞過 daemon 往它的 ctl 寫 stop）——3 秒內退 0 也下表（11-05 晚前是留 `stopped`）；**adopt 接回的**（不是 daemon 生的，拿不到結束碼；代定）。
  11-05 第二輪：reason 只看這一支起來之後寫的 stderr、控制字元換空白、add 剛起的也算「起來」——見 [08](08-當機復原與已知限制.md#reason-的細節接-03出錯結束一律留)。
- **有就沿用：`DaemonExists`**（旅程步 2「沒有才起」，代定可翻案）：daemon 起來先對自己的 stack 資料夾 `flock`（不多建檔；一直鎖到行程結束，`kill -9` 也會放），鎖不到＝已有 daemon 在跑＝退 1、stderr `aos-daemon: DaemonExists a daemon is already running on this stack (…); to reuse it, just aos-daemon-ctl add / aos-agent ctl add`（11-05 使用者「全都用英文吧」）（11-06 no-pid P1：不再對 /proc 印 pid，只看 `state.json` 的 `phase` 分「收工途中」）。daemon fork 出來的子行程一律先關掉這把鎖（11-06 P1；原本不 exec 的子——exec 型 proc 或身體是 inst 單子——一直帶著，`kill -9` daemon 後要等它跑完才起得來）。睡著的、別台搬來的、重開機過＝沒人鎖＝照舊起＋wake。11-05 B 線前是比 `state.json` 的 `pid`＋`started_at_ticks`＋`boot_id`：兩個同時起都過關（實測同一個 stack 跑兩個），改用鎖。要故意兩個就給不同 `--stack`。
