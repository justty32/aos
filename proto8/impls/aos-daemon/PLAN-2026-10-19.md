## 一、要使用者看的（衝突 3 條、方向問題 1 條；沒列的原則都推得出）

### 衝突 1：子項結束後要不要自動重起（策略格）

- **哪條**：N-28 的 `policies.child_exit`（10-14 候選 g、10-15 暫定 f 使用者「全定」）：子項結束時跑一張 inst 單子，stdin 餵 `{id, code, exits, last_state}`，**讀它的 stdout** `{action: restart|leave|remove, after_ms}` 決定重起、放著或移除；`exits ≥ 5` 強制放著。
- **衝突在哪**：(1) 10-19 起「結束碼是唯一訊號」——N-37 作廢、N-36／P-09 不讀格的 stdout、C-52 不偷看下層；策略格靠 stdout JSON 回話，正是被拿掉的那條路。(2) 拍板點 3「失敗就停、人來看」、P-20「不自動重試、不數連錯」、N-53「重試幾次由人或外面決定」——策略格就是自動重試＋數連錯。
- **各自後果**：**做**＝得另開一條「下層回話」通道（改成看結束碼：0＝重起、10＝放著、其他＝移除之類的暗規則，違反 C-56「寫什麼就做什麼」），daemon 多約 60 行、多一種檔（`policy.in.json`）；崩潰迴圈要上限。**不做**＝子項結束就停在表上（`phase: exited`、`last_code`），人看 daemon 的 state 窗知道誰停了；要重來＝改 daemon 的 ctl（`children` 拿掉那個 id、再放回）或重起 daemon（`adopt` 只接活著的、其餘重新起）。
- **例子**：daemon 顧 bob、ann、clock。bob 的腦連不上，bob 的 loop 以 1 結束。不做策略格：state 窗 `children.bob = {phase: "exited", last_code: 1}`，clock、ann 照跑；人修好後把 ctl 的 `children` 裡 bob 拿掉再放回，daemon 重起 bob。做策略格：daemon 每隔 after_ms 重起 bob 直到第 5 次，期間 bob 的 stderr 檔一直長。
- **預設**：**不做策略格、不自動重起**；`policies` 這個 key 不收（寫了被忽略）。N-28 那段改字。

### 衝突 2：`children` 的形狀

- **哪條**：N-28：`children` 是**陣列**，每項是「路徑或內嵌物件」（路徑＝一份 loop.json 檔），id 來自項目的 `id` key、沒寫＝`daemon 的 id#/children/i`；「沒 `run` 有 `argv` 就包成跑一次（`max` 1）」「是資料夾程式就包成 `{"run": 它}`」。
- **衝突在哪**：(1) C-71 資料夾＝table、fsm.json 的 `states` 已是 `{名: {…}}`——同族格式（C-48）該用物件、key 就是 id，不需要 `id` key 也不需要 `#/children/i`。(2) 「路徑＝一份 loop.json 檔」在新做法下沒有位置：loop.json 的 `run` 相對路徑從 cwd 算，daemon 得替它猜 cwd；要跑「bob 的 loop」就寫 `{"run": "../agent-bob"}`（aos-exec 它，它自己的入口就是它的 loop），不需要第二種寫法。(3) 「包成跑一次」「包成 `{run: 它}`」是把規則藏在值裡（C-56「寫什麼就做什麼」）。
- **各自後果**：照 N-28 原樣＝daemon 多四種判斷（陣列、`id`、路徑、兩種包裝）、小格名字難看（`#/children/0` 不能當資料夾名）。照新做法＝`children` 是物件 `{id: loop 設定}`，值只收 loop 設定物件（`run` 必填、其餘 key 跟 loop.json 一樣、daemon 不驗裡面），id＝小格名 `$AOS_STACK/<id>/`；要跑一次就寫 `"max": 1`、要一直跑就寫 `"max": null`，字面上看得出來。
- **例子**：`"children": {"bob": {"run": "../agent-bob", "max": null, "interval_ms": 1000}, "clock": {"run": "clock", "max": null, "interval_ms": 1000}}`。
- **預設**：照新做法（物件、只收 loop 設定物件、不包裝）。N-28 那段改字。

### 衝突 3：心跳 1 秒 vs 一拍會卡住的 loop

- **哪條**：N-17／N-32（10-14、10-15「全定」）：state 窗內容沒變也每 1 秒碰一下 `beat`，超過 3 倍間隔沒動靜算疑似死亡。
- **衝突在哪**：10-19 的 loop 一拍是阻塞的（`run_beat` 等那拍跑完才回來，bob 的 think 可能 120 秒），期間沒人能寫 state；要在拍中間維持心跳就得開執行緒（impls 的 run_folder 靠「fork 時只有一條執行緒」，加執行緒會踩到這條）或把 run_beat 拆成非阻塞兩步（兩版 loop／fsm 都要重寫）。
- **各自後果**：維持 N-17 原意＝兩版 loop 改成非阻塞拍（約各 80 行，fsm 也受影響）。照預設＝心跳只在拍與拍之間、睡 interval 的時候跳；拍跑著的時候 state 停在 `running`、`beat` 是進拍的那一刻；「3 倍沒動靜＝疑似死亡」只對 `waiting`／`paused` 成立，活不活一律看 pid＋啟動時間（N-15，daemon 本來就這樣看子項）。
- **預設**：心跳只在拍外跳；N-17 加一句限制。

### 方向問題：rewrite-order 第 5 題的兩條舊帳（NORMS/08），daemon 動工時順手結

- **「argv[0] 程式不自己 setsid」**：建議**結案、刪**——N-41 已寫「格自己不 setsid、群組由叫的人給」，daemon 照同一條：子 loop 的新 session 由 daemon 給，子 loop 自己不開；跟 P-36 不衝突。
- **「ctl `seq`／state `ctl_seq` 回音」**：建議**維持、結案**——daemon 寫子 loop 的 ctl 時 `seq` 加一（N-33）、每個開 ctl 窗的程式在 state 回報 `ctl_seq`，各一行程式。

其他（窗要不要做、放哪、adopt、收工、結束碼、兩版分工）原則都推得出，結論在下面。

## 二、一段話結論

**daemon＝一個開了窗的 loop，外加一張子 loop 的表。** `aos-daemon daemon.json`：daemon.json 是 loop.json 的嚴格超集（N-28 不變）：`run`（選填，自己每拍串行跑一次的身體）、`max`（預設 `null`＝不限）、`interval_ms`（預設 200）、`ctl`／`state`（布林，預設 `true`）、`children`（`{id: loop 設定}`）、`adopt`（預設 `true`）、`grace_ms`（預設 10000）。它需要 `$AOS_STACK`（沒設退 1，同 fsm）：自己的兩扇窗固定叫 `$AOS_STACK/ctl.json`、`$AOS_STACK/state.json`（N-13：窗落在 stack、名字程式自訂）；每個子項一個小格 `$AOS_STACK/<id>/`（P-17），daemon 把合好的 loop.json 寫進小格、以 `AOS_STACK=小格` 起一支子 loop（自成 session、stdout 丟掉、stderr 附加到小格的 `stderr`）。每拍：讀 ctl → 對表（起少掉的、收多出來的）→ 收屍 → 跑身體 → 寫 state（含 `children` 表＋心跳）。子項結束就停在表上，不自動重起（衝突 1 預設）。收工三條路：ctl `stop`／跑滿 `max`／身體退 10 ＝ 優雅（替每個子 loop 的 ctl 寫 `stop`、等它們結束）退 0；身體退其他非 0 ＝ 同樣先優雅收子項、以那個碼結束；收到 SIGINT／SIGTERM／SIGHUP ＝ 對每個子項整群 SIGTERM、等 `grace_ms`、整群 SIGKILL，寫好 state，以 128＋N 結束（P-36）。當機復原＝`adopt`：重起時讀自己上次的 state 窗，pid＋啟動時間對得上的子 loop 認領回來不重起，其餘照 `children` 重新起。**aos-loop 跟著長**：`max: null`、`interval_ms`、`ctl`／`state`（布林）四個選填 key，agent-bob 一個字不改。兩版（`proto8/bin` Python、`impls` C++）行為一致，都是「小庫＋薄命令列」：bin 多 `aos_window.py`、`aos_loop.py`，`aos-loop`／`aos-daemon` 是薄殼；impls 的 aos-loop 庫長出 `Engine`（拍引擎＋窗）與 `main_loop()`，aos-daemon 連它、fork 出子 loop、不走 PATH。

## 三、daemon 是什麼、做什麼、不做什麼

### 做什麼

| 事 | 怎麼做 | 依據 |
|---|---|---|
| 起子 loop | 小格 `$AOS_STACK/<id>/` mkdir -p；合好的 loop 設定（子項那份＋沒寫的 `ctl: true`、`state: true`）先寫 `.loop.json.tmp` 再改名成 `loop.json`；起 `aos-loop <小格>/loop.json`：cwd＝daemon 的 cwd（`run` 的相對路徑從這裡算）、`AOS_STACK=<小格>/`（其餘環境原樣，含 `AOS_WS`、PATH）、stdin／stdout＝`/dev/null`、stderr 附加到 `<小格>/stderr`、自成 session。先寫表（`phase: starting`）再起、起好改 `running`、記 pid＋啟動時間 | N-28、N-54、P-17、N-05、N-41、N-57、C-67 |
| 顧 | 每拍 `waitpid(WNOHANG)` 收屍；結束＝`phase: exited`、`last_code`＝結束碼（被訊號停掉 128＋N）；認領來的（非親生）看 `/proc/<pid>/stat` 的啟動時間還對不對，沒了＝`exited`、`last_code: null` | N-15、N-17 |
| 對表（每拍） | 期望表＝ctl 的 `children`（有寫）或 daemon.json 的 `children`；表上沒有的 id → 起；表上有、期望沒有的 id → 收掉（優雅：寫它的 ctl `stop: true`、`seq` 加一；它沒開 ctl 窗就整群 SIGTERM）、結束後從表上拿掉（小格留著，P-34）；已在表上的（含 `exited`）不動 | N-54、N-06、N-33、P-34 |
| 身體 | 有 `run` 就每拍跑一次（同 loop：字串＝aos-exec 它、物件＝單子行程內跑），結束碼照 loop 的規則：0 下一拍、10 收工（退 0）、其他非 0＝失敗（收工、以那個碼結束） | N-28、P-19、N-43 |
| 窗 | 讀 `$AOS_STACK/ctl.json`、寫 `$AOS_STACK/state.json`（見第四節） | N-06～N-09、N-11、N-13、N-32、N-33 |
| 收工 | 見第六節 | P-36、N-43 |
| 復原 | `adopt`（見第五節） | N-28、N-17 |

### 不做什麼

- 不讀子項的 state 窗、不轉述子項的 stderr（C-52）；daemon 的 state 表只記 pid、啟動時間、phase、last_code。
- 不自動重起、沒有策略格、沒有退避、不數連錯（衝突 1 預設；拍板點 3）。
- 不驗子項設定裡面（N-28「只看它自己需要的」）：只驗「值是物件、有 `run`」與 id 能當資料夾名（非空、不含 `/`、不以 `.` 開頭）；其餘 key 原樣灌給子 loop，寫錯子 loop 自己退 1、錯在它的 `stderr` 檔。
- 不收旗標、不讀 stdin 設定（N-11）；不動 PATH（§ 24）；不替子項發明工作區（`AOS_WS` 原樣繼承；要給子 agent 自己的工作區，在子項的 `run` 單子裡明給，見 demo）。
- 不做鎖、信箱、公告（N-14 其餘的窗，kernel 時再說）；不做 FUSE。
- 子項的 stdout／stderr 不輪替、不設上限（N-28「基礎實作」）。
- 不收 `work_dir`、`id`、`policies`、`table`、`load`、`ctl_dir`（舊 key；寫了一律忽略，同 P-28「其他 key 一律忽略」）。

### daemon.json

```jsonc
{
  "run": "body",            // 選填：自己每拍的身體（字串＝aos-exec 它；物件＝單子）。沒寫＝純監工
  "max": null,              // 跑幾拍就收工；null＝不限（預設）；loop 沒寫＝10（N-28：同名同義、預設值可不同）
  "interval_ms": 200,       // 拍與拍之間睡多久（預設 200；loop 預設 0）
  "ctl": true, "state": true,   // 開不開 $AOS_STACK/ctl.json、state.json（預設 true；loop 預設 false）
  "adopt": true,            // 重起時接回活著的子 loop（預設 true）
  "grace_ms": 10000,        // 收到訊號收工：SIGTERM 子項後等多久再 SIGKILL（預設 10000）
  "children": {             // {id: loop 設定}；id＝小格名
    "clock": {"run": "clock", "max": null, "interval_ms": 1000},
    "bob":   {"run": {"argv": ["aos-exec", "../agent-bob", {"$env": "AOS_STACK", "path": "ws"}]},
              "max": null, "interval_ms": 1000}
  }
}
```

一份合法的 loop.json 直接丟給 aos-daemon 也能跑（N-28）：就是一個開了窗、`max` 不限、每拍隔 200 ms 的 loop。

### aos-loop 跟著長的四個選填 key（兩版）

| key | 型別 | 沒寫 | 意思 |
|---|---|---|---|
| `max` | 非負整數或 `null` | 10 | `null`＝不限（原本只收整數） |
| `interval_ms` | 非負整數 | 0 | 一拍結束到下一拍開始之間睡多久；睡的期間看 ctl、收訊號（拍外收到＝直接 128＋N） |
| `ctl` | 布林 | false | true＝讀 `$AOS_STACK/ctl.json`（沒設 `AOS_STACK` 退 1） |
| `state` | 布林 | false | true＝寫 `$AOS_STACK/state.json`（同上） |

為什麼是布林不是路徑：N-13（10-19 改）窗落在 `$AOS_STACK`、名字由程式自訂——loop 自訂成 `ctl.json`／`state.json`，要放別處＝換 `AOS_STACK`（C-67），不另開路徑 key；路徑 key 又要定「相對於誰」，是多出來的規則。四個 key 都沒寫＝現在的 aos-loop 一模一樣，agent-bob、ann 不動。

## 四、窗（這次做：ctl、state；不做：鎖、信箱、公告）

位置固定：`$AOS_STACK/ctl.json`、`$AOS_STACK/state.json`。loop、daemon 共用同一段程式。

**ctl.json**（N-06～N-08、N-33；誰都可以寫，程式只讀）：

```jsonc
{"paused": false, "stop": false, "max": 3, "interval_ms": 500, "seq": 7,
 "children": {…}}   // children 只有 daemon 認（N-54）
```

- 整份是期望：沒寫的 key＝回設定檔的初始值；`stop` 壓過 `paused`；`stop` 讀到一次就算數。
- `paused`＝不起下一拍（daemon：也不對表、不起子項；收屍與 state 照寫）；`stop`＝收工（優雅那條）。
- 讀的時機：每拍之間、睡 interval 時每 50 ms 看一次；內容跟上次相同就不重驗。
- 壞 JSON／不是物件／型別不對／檔不見了＝整份不採用、維持上一次，`state.last_warning` 記「代號: 原因」（例 `CtlBad: …`、`CtlMissing: …`）；讀到好的清回 `null`；從沒出現過＝初始值。不寫 stderr（N-08、N-43）。
- `seq`：寫的人自己帶，非負整數；state 回報 `ctl_seq`。

**state.json**（N-09、N-17、N-32、N-33；只有自己寫；先寫 `.state.json.tmp` 再改名）：

```jsonc
{"state": "waiting",            // waiting／running／paused／stopping／done／stopped（N-17 七態取子集；starting 用不到）
 "pid": 123, "started": 1050011, "boot_id": "45db…",   // 心跳：pid＋/proc 啟動時間＋開機 id（N-32）
 "beat": 1791985930.186,        // 寫的那一刻（epoch 秒）；拍外每 1 秒碰一次（衝突 3 預設）
 "runs": 12, "max": null, "interval_ms": 200,          // 生效中的值（ctl 蓋過設定檔之後）
 "last_code": 0,                // 身體上次的結束碼；沒身體／還沒跑＝null
 "last_warning": null, "ctl_seq": 7,
 "children": {                  // daemon 才有（表就是 save 檔，N-28）
   "clock": {"pid": 124, "started": 1050020, "phase": "running", "last_code": null},
   "bob":   {"pid": null, "started": null, "phase": "exited", "last_code": 1}}}
```

- 內容有變就寫；沒變每 1 秒碰一次 `beat`；寫不了＝窗壞了：收工（優雅）、stderr 一行、退 1（state 是 daemon 的 save 檔，寫不了不能裝沒事）。
- `phase`（子項，N-17 六態取子集）：`starting`（表已寫、還沒起）→ `running` → `stopping`（已寫 stop／已送訊號）→ `exited`；`backoff`、`removed` 用不到（沒有重起；移除＝從表上消失）。
- 不記 `last_error`（loop 自己的錯＝退 1 結束，沒有「出錯還繼續跑」的情況）、不記 `id`（檔在哪就是誰）、不記 `signal`（結束碼就是訊號）。

## 五、狀態與當機復原（`adopt`）

- daemon 起來時：`adopt: true` 且 `$AOS_STACK/state.json` 存在 → 先看那份的 `pid`＋`started` 是不是還活著（活著＝另一個 daemon 還在跑同一個 stack，`Conflict`、退 1；C-53 入口檢查，一行）；再逐個看 `children` 列的 pid＋`started`：對得上＝認領（`phase: running`、記成「非親生」：之後靠 /proc 看它在不在、結束時 `last_code: null`）；對不上＝丟掉那列。然後照期望表起表上沒有的。`adopt: false`＝舊 state 不看，全部重新起（舊的子 loop 若還活著就變孤兒，人自己收）。
- 為什麼能接回：子 loop 自成 session，daemon 被 SIGKILL 時它們不跟著死（這也是 N-15／N-17 用 pid＋啟動時間的理由）。
- 要收乾淨就對 daemon 送 SIGTERM、不要 SIGKILL（舊版 README 同一句）。

## 六、訊號、收工、錯誤與結束碼

| 怎麼結束 | 收子項 | 結束碼 | stderr |
|---|---|---|---|
| ctl `stop`／跑滿 `max`／身體退 10 | 優雅：每個子項寫 ctl `stop: true`（沒開 ctl 窗的整群 SIGTERM）、等全部結束（期間 state 照寫、`stopping`；等多久都等——人不耐煩就對 daemon 送 SIGTERM 轉下面那條） | **0** | 不寫（N-43） |
| 身體退其他非 0 | 同上優雅 | **那個碼** | 一行 `aos-daemon: 第 N 拍 誰 失敗，結束碼 C`（同 loop） |
| 收到 SIGINT／SIGTERM／SIGHUP（拍中或拍外） | 拍中：先轉給身體那拍、等它收好（同 loop，P-36）。然後每個子項**整群** SIGTERM → 等 `grace_ms` → 還在的整群 SIGKILL → 收屍、記 `last_code` | **128＋N** | 不寫 |
| 自己的錯（沒設 `AOS_STACK`、daemon.json 讀不到／不是 JSON／型別不對、id 不能當資料夾名、小格建不了、state 窗寫不了、另一個 daemon 還在跑、子 loop 起不來） | 已起的子項走優雅那條 | **1** | 一行 `aos-daemon: 原因`（impls `aos-daemon: 代號 原因`：`StackMissing`、`ReadFailed`、`JsonSyntax`、`FieldType`、`MkdirFailed`、`WriteFailed`、`Conflict`、`LaunchFailed`、`Internal`） |

子項的結束碼不影響 daemon 的結束碼（C-52「每層只說自己」）。整支程式的壽命擋著三個訊號（同兩版 loop）。子 loop 拿到 SIGTERM 之後照 P-36 自己往下轉、收完以 128＋N 結束，daemon 記下。

舊帳順手結（第一節方向問題）：子 loop 的 session 由 daemon 開（N-41 同一條規則）；`seq` 回音照 N-33。

## 七、跟 aos-exec／aos-loop 公開 API 的關係（impls 做成小庫＋薄 CLI）

### impls/aos-loop 長出來的（公開標頭 `aos/loop.hpp` 加）

```cpp
namespace aos::loop {
struct Config { Json run; std::optional<long> max; long interval_ms = 0; bool ctl = false; bool state = false; };
Config read_config(const Json& doc);                 // 驗 run／max／interval_ms／ctl／state；其他 key 忽略
int wait_signal(int ms);                             // 睡 ms 毫秒，排著的三個訊號之一來了就回它（0＝沒有）；sigtimedwait

class Ctl    { public: explicit Ctl(std::string path); void poll(); const Json& good() const; std::optional<long> seq() const; std::optional<std::string> warning() const; };
class State  { public: explicit State(std::string path); bool write(const Json& doc); /* 有變就寫、沒變 1 秒碰；寫不了回 false */ };
Json state_skeleton(…);                              // pid、started、boot_id、runs、max、interval_ms、last_code、last_warning、ctl_seq

class Engine {                                       // 拍引擎：ctl → 拍 → state，loop 直接用、daemon 繼承
public:
    Engine(Config cfg, std::string stack_dir);       // stack_dir 空字串＝沒開窗也不用 AOS_STACK
    int serve();                                     // 回結束碼（0／身體的碼／128＋N）；自己的錯丟 Error
protected:
    virtual void tick(bool paused) {}                // 每拍、跑身體之前（daemon：對表、收屍）
    virtual void extra(Json& state) {}               // state 多的欄位（daemon：children）
    virtual void finish(bool signaled, int sig) {}   // 收工前（daemon：收子項）
    // 給子類用：runs()、want()（生效中的 max／interval_ms／paused／stop）、ctl 原文（daemon 讀 children）
};
int main_loop(const std::string& path);              // 命令列的身體：讀檔、read_config、Engine::serve；自己的錯印「aos-loop: 代號 原因」回 1
}
```

`block_signals`、`take_signal`、`run_beat` 照舊。`aos-loop` 的 `main.cpp` 變成 `return main_loop(argv[1])`。

### impls/aos-daemon（重寫；沒有公開標頭，同 aos-fsm）

```
 main ──▶ block_signals ──▶ 要 AOS_STACK ──▶ read_daemon_config ──▶ Daemon(Engine)::serve
   Daemon::tick      ──▶ Table::reap ──▶ Table::reconcile(期望表)（起：寫 loop.json、fork 子 loop；收：寫 ctl stop／SIGTERM）
   Daemon::extra     ──▶ children 表
   Daemon::finish    ──▶ Table::shutdown(優雅｜訊號, grace_ms)
   起子 loop（child/spawn.cpp）：fork → 子行程：關掉繼承的 fd、setsid、stdin/stdout←/dev/null、stderr←小格/stderr 附加、
                                 setenv AOS_STACK、呼叫 aos::loop::main_loop(小格/loop.json)、_exit(rc)
```

- 連 `aos-loop` target（它帶進 aos-exec、inst、aos-util、aos-directive）。子 loop 不走 PATH、不找兄弟執行檔：fork 之後在子行程裡跑 aos-loop 庫的 `main_loop`，跟 aos-loop 跑字串 run 用 aos-exec 公開 API 同一個做法（§ 20「隨意使用 aos-exec 的公開 api」）。代價：`ps` 看到的子 loop 叫 `aos-daemon`（同一支執行檔的分身），對 pid 要看 state 窗的 `children`；README 寫明。
- fork 前 daemon 是單執行緒（身體單子的工人執行緒在 run_inst 回來前已 join），子行程裡 setenv、C++ 配置安全（同 run_folder 的理由）。子行程要把 daemon 的 signalfd／eventfd 之類的 fd 關掉（沒有 exec，CLOEXEC 不會生效）。
- `src/`：`config/`（欄位表：daemon 的 key＋預設；children 物件與 id 檢查）、`table/`（`Table`：reap、reconcile、shutdown、adopt）、`child/`（一個子項：spawn、alive、stop、row）、`common/`、`main.cpp`。約 400 行。
- aos-util 現成能用的：`write_json`（原子）、`proc_started`、`boot_id`、`signal_group`、`reap`、`has_exited`。`spawn`（posix_spawn）這次不用（fork 走庫）。
