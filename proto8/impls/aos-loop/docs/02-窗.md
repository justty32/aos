### 窗（`ctl`、`state`）

語意照 [NORMS/05 窗](../../../docs/NORMS/05-基礎設施-窗.md)（N-06～N-09、N-17、N-32）；下面是這支的具體行為。
公開 C++ 協議在 `aos/loop.hpp` 的 `CtlWindow`／`StateWindow`：預設檔名、配置 key、ctl 的 `cmd`／`seq` 與三個動詞、state 的 `phase`／`done` 與行程身份欄位。其他程式（含 daemon）照這份宣告讀寫，不各存一份字串。

`"ctl": "ctl.json"`、`"state": "state.json"`＝兩扇窗的檔名，放在 `$AOS_STACK` 底下。**11-04 起沒寫＝預設名 `ctl.json`／`state.json`、寫 `null`＝不開、不提醒**（使用者題 5「留 key、沒寫時預設就是這兩個名」）；要開（沒寫或寫了檔名）卻沒設 `AOS_STACK`＝`StackMissing`——所以不經 aos-exec 直接跑 aos-loop，要自己設 `AOS_STACK` 或兩格寫 `null`。

- **ctl**（誰都能寫、loop 只讀；每跑一次讀一次、暫停中每秒讀一次）：**一道指令**（使用者「還是用指令吧，不然大家不好理解。但是loop就不要用mailbox那套，就是誰能寫ctl.json就能控制。」，[thinking 11-03 ctl-commands](../../../thinking/2026-11/03/ctl-commands/README.md)）：
  `{"cmd": "pause"／"resume"／"stop", "max", "interval_ms", "seq"}`，都選填。`pause`＝這次跑完不起下一次、phase `paused`；`resume`＝解除；`stop`＝這次跑完以 0 結束、phase `stopped`（壓過同一道裡的其他東西）；
  `max`／`interval_ms` 寫了＝從現在起用它、寫 `null`＝回旗標／loop.json 的值、沒寫＝不動；`seq` 只回音（state 的 `ctl_seq`＝最後一道照做的指令的 `seq`）。三個動詞冪等。其他 key 忽略（`paused`／`stopped` 也是）。
  **新舊比內容**：解完的那份跟上一次讀到的一樣＝同一道、不再做；不一樣才照做一次。所以檔留著沒事、loop 不刪不改它；兩個人先後寫、loop 還沒讀＝後寫的算、前一道就沒了。
  **手寫 ctl 每次換 `seq`**（11-06 晚，no-pid P7）：同內容再寫一次＝同一道、loop 不回應、`responded_at` 不動；上一層 daemon 看到 ctl 比 `responded_at` 新卻等不到回應，會把這列標 `stuck`（[aos-daemon docs/04](../../aos-daemon/docs/04-兩個手把-兩扇狀態窗.md#判卡住-stuck11-06-p7)）。`aos-daemon-ctl` 自帶遞增 `seq`。
  **起來第一次讀到的當基準線、不執行**——殘留的 `{"cmd": "stop"}` 不會讓新起的馬上退，不用誰去清；代價是起來之前寫好的指令不算（要一起來就暫停見下面 state）。檔不見了＝沒有新指令，之後再寫的一律算新的（實作時代定）。
  讀到新的壞的（讀不了、不是 JSON 物件、型別不對、`cmd` 不認得、指示詞解不開）整份不採用、維持原狀、原因寫進 state 的 `ctl_warning`；照做了一道好的才清回 null。基準線那份壞的不提醒（實作時代定）。
- **state**（只有自己寫；先寫 `.state.json` 再改名，N-05）：只在兩次之間寫，**而且有變才寫**（[thinking 11-02 state 窗](../../../thinking/2026-11/02/state-window/README.md)）：
  `{"phase": running／waiting／paused／done／stopped, "counter_runs", "max", "interval_ms", "paused", "ctl_seq", "ctl_warning", "pid", "started_at_ticks", "boot_id", "responded_at", "updated_at"}`，
  `counter_runs`＝跑過幾次（寫那一刻的快照）、`started_at_ticks`＝/proc/<pid>/stat 第 22 欄、`updated_at`＝這份寫出去的那一刻（ISO 8601 UTC 到毫秒，例 `2026-10-23T01:58:45.123+00:00`；最後一欄）（使用者 10-25「計數這塊，幫我改成counter_*」）。
  **`responded_at`＝最近一次有反應的時間**（11-06 no-pid P2，[thinking no-pid](../../../thinking/2026-11/05/no-pid/README.md)；格式同 `updated_at`，起來時 `null`）：只在有反應時更新——**讀到新的一道 ctl 並處理了**（照做的好指令，和整份不採用、寫進 `ctl_warning` 的壞指令都算：有回應、只是不採用；起來第一次讀到的基準線不算、檔不見了不算），以及**有身體時每跑完一次**（不論碼）。之後給上一層 daemon 判 `stuck` 用：有刺激（ctl 有新指令）卻過了 N 秒 `responded_at` 沒跟上才算卡住，沒刺激不判（判 stuck 還沒做）。
  **有變才寫**：每次要寫先組好一份（不含 `updated_at`），跟上一份寫出去的比，**`counter_runs` 不算變動**（比的時候排除；使用者 11-02「對」），**`phase` 在 running／waiting 之間換也不算**（11-02 晚使用者「running/waiting確實不該算變動」；寫出去的照帶當下的）——一樣就不碰檔，不一樣才加 `updated_at` 寫。
  啟動後第一份、結束那份（帶 `code`）一定寫。會變的：進出 paused／stopped／done（有身體的 loop 跑著睡著來回時窗停在第一份）、讀到新的 ctl（`ctl_seq`、`max`、`interval_ms`、`paused`）、`ctl_warning` 變、`responded_at` 變（11-06 no-pid P2：它算進比較，所以**有身體的 loop 每跑完一次會寫一份**；睡著——沒指令、沒身體或在等 interval、paused——時 `responded_at` 不動、窗照樣不動）。
  **沒有心跳**（11-02 使用者「心跳這塊就直接看pid就好」）：睡著時窗不動；判活著看 `pid`＋`started_at_ticks`＋`boot_id`（N-17），不看檔案的更新時間。nap 最多睡 1 秒是為了讀 ctl、不是心跳。`responded_at` 也不是心跳（11-06 no-pid P2）：沒事做就不動，只在有反應時才變，N-09「有變才寫」沒破。
  沒有 `exec`（只有 aos-daemon 會這樣）時一輪只讀一次 ctl、只 tend 一次、最多寫一份 `waiting`（不寫 `running`），睡著的 daemon 窗不動（使用者「都修都處理」，[thinking](../../../thinking/2026-10/23/daemon-bench.md)）。
  **起來先暫停**（代定，使用者四態「休眠但是可以隨時叫醒繼續跑指令或繼續暫停」）：開了 state 窗、`$AOS_STACK` 裡已有一份舊的 state.json 而且它的 `paused` 是 `true`＝起來先暫停（第一份 state 就是 `paused`，等 `{"cmd": "resume"}`）；其他欄位不接（`counter_runs` 從 0、`max`／`interval_ms` 回設定）。
  `$AOS_STACK` 資料夾不在＝state 寫不了＝`WriteFailed`、退 1、那次沒跑，**不自己建**（建 stack 只在 aos-exec 做，N-59 第 1 件；經 aos-exec 跑時它已經建好）。
  結束時多 `code`（`done`＝自己跑完或失敗、`stopped`＝ctl 的 `stop`、收到訊號或自己的錯）；`max` 不限時是 `null`。

### 結束碼

| 情況 | 結束碼 | stderr |
|---|---|---|
| 那次退 0 | 下一次 | — |
| 那次退 10 | **0** | 不寫 |
| 那次退其他非 0（含被訊號停掉 128＋N、單子逾時被收掉＝143） | **那個碼** | 錯誤行 `aos-loop: error: RunFailed run N: 誰 failed with exit code C`（11-05 stdio-unify D4；碼是身體的，不是 1）（誰＝exec 的目標字串：字串 exec 原樣、陣列＝第一個元素；例 `loop.json#/body`；單子＝「設定檔名#指標」，例 `loop.json#/exec`） |
| 跑滿 `max` | 0 | 不寫（N-43） |
| 收到 SIGINT／SIGTERM／SIGHUP | **128＋N**（等那次結束之後） | 不寫 |
| 其他訊號（SIGUSR1、SIGUSR2、SIGKILL…） | 照系統預設（多半直接死，例 138） | 不收工、state 留著最後一份（同 `kill -9`；11-05 第二輪） |
| 自己的錯（含 exec 的單子壞、起不來） | 1 | 一行 `aos-loop: error: 代號 原因` |

那次找不到入口、單子壞等（那一層 aos-exec 的錯）：stderr 先有一行 `aos-exec: error: 代號 原因`，那次的碼是 1，接著是 loop 那行「aos-loop: error: RunFailed run N: … failed with exit code 1」——每層只說自己的（P-21）。所以字串目標指到的單子壞不是 loop 自己的錯，每次都會照跑一次 aos-exec、各自報。

### 訊號

整支程式的壽命都擋著 SIGINT／SIGTERM／SIGHUP（P-36「先收好自己起的子程式、寫好狀態再結束，結束碼非 0」）：

- **跑到一半收到**：轉給那次——`kill` 給那個子行程（那次的 aos-exec；它跟 aos-loop 同一個行程群組；不另設 SIGKILL 期限）；
  那次是單子時由那次的 aos-exec（監工）再轉給整群、過 `grace_ms` 還沒結束就 SIGKILL 整群。等那次結束，**不起下一次**，以 128＋第一個收到的訊號結束。
- **兩次之間收到**（含睡 interval、paused 的時候）：不起下一次，直接 128＋N（有開 state 窗就寫 `stopped`、`code`）。
- 在終端機按 Ctrl-C：那次的子行程跟 aos-loop 同群組，會直接收到一次、再收到 aos-loop 轉的一次（兩次）；單子的子程式自成群組，只收到那次的 aos-exec 轉的。
