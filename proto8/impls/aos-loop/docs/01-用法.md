## 用法

```
aos-loop [--max N] [--interval-ms N] [--ctl FILE] [--state FILE] [--state-flux FILE] [--enable-logs] [--enable-counters] CONFIG.json [-- ARGS...]
```

- **命令列**（`loop_cli`，aos-daemon 共用）：**唯一的位置參數就是設定檔**——必給、只能一個；可寫 `檔#/指標`＝讀那份檔裡那個位置的物件（aos-util 的 `load_cfg`）。
  旗標放設定檔前面、規則同 aos-exec（`--x V`／`--x=V`、重複給最後一個算、`--` 結束旗標；aos-util 的 `parse_cli`）；旗標名＝loop.json 的 key 名底線換連字號。
  不認得的旗標（含 `--cfg`）＝`FlagUnknown`；沒給、多給設定檔、旗標缺值＝`ArgumentsBad`（原因 `reason (usage: aos-loop [--max N] [--interval-ms N] [--ctl FILE] [--state FILE] [--state-flux FILE] [--enable-logs] [--enable-counters] CONFIG.json [-- ARGS...])`）；`--help`＝英文說明印 stdout、退 0；
  `--max`／`--interval-ms` 要是非負整數（只收 `[0-9]+`），不是＝`ArgumentsBad`（命令列用錯）。
  `--enable-logs` 是不帶值的開關（寫 `--enable-logs=V`＝`ArgumentsBad`）：印 log（見下面「log」）。`--enable-counters` 也是不帶值的開關（全家同名，[N-09「計數器」](../../../docs/NORMS/05-基礎設施-窗/02-N-09～N-11.md)）：有 state 窗時每跑一次寫 `counter_runs.txt`（見 [02 窗](02-窗.md)）；沒開 state 窗就什麼都不寫。
- **`設定檔 -- 參數...`**（使用者「aos-XXX ... ... -- ...，第一個...就是aos-XXX本身的旗標……第二個...就是目標檔案……後面就是純參數」）：
  設定檔之後接 `--`＝後面全是附加參數（那個 `--` 剝掉），**每次**接在 exec 後面：字串目標＝`[目標, 參數...]`、陣列＝接在最後、內嵌單子＝接在單子 `argv` 的最後
  （`argv` 要直接寫成陣列；是指示詞或沒寫＝`CfgBad`）；ctl 改不了它們。設定檔之後接的不是 `--`＝`ArgumentsBad`；設定檔之前的 `--` 是「旗標結束」（`aos-loop -- -odd.json -- 參數`）。
  跟 aos-exec 的差異：`aos-exec XXX args...` 的 XXX 後面全部原樣交給入口（`--` 也原樣、不剝）；所以 `aos-exec <loop 資料夾> -- 題` 會變成 `aos-loop <AOS_CF> -- 題`，aos-loop 在這裡剝掉 `--`、把「題」接到身體。
- **起跑時 旗標 ＞ 設定檔 ＞ 預設**（ctl 窗在跑的途中還能再蓋，見下面「窗」）。
- **loop.json**：`{"exec": aos-exec 的目標, "max": 最多幾次}`（使用者「exec，loop／daemon 的 run 也一起改 exec」，跟 fsm 格同名），選填 `interval_ms`、`ctl`、`state`、`state_flux`（下面「窗」），其他 key 忽略（`body`、`_entry`…）。
  - `exec`（`parse_target`）＝**字串**（每次 `aos-exec -- <exec>`；`--` 讓 `-` 開頭的目標不被當旗標）或**陣列 `[目標, 參數...]`**（每次 `aos-exec -- 目標 參數...`；元素都要是字串、不能空）。
    相對路徑照 cwd 算、loop 不 cd 不轉；loop 不驗目標存不存在，那是那次 aos-exec 的錯。WS、`AOS_STACK` 由那次的 aos-exec 照它的規則定（沿用 `$AOS_WS`，沒設用 cwd）。每次重找入口，入口換了下一次就生效。
  - `exec` 寫成**物件＝單子**：每次在 aos-loop 自己行程內交給 aos-exec 的 `run_inst`（同 aos-exec 跑單子：先解指示詞、驗 17 個 key、aos-inst 起、`timeout_ms`／`timeout_cycles` 擇一與 `grace_ms`、訊號轉給整群）。`timeout_cycles` 有時鐘比格數，沒時鐘以 `AOS_CLOCK_INTERVAL` 毫秒換算（預設 1000）；時鐘停了就不到期。
    跑的期間 `AOS_CF`＝設定檔的實際路徑、`AOS_CD`＝它的資料夾、`AOS_CO`＝`/exec`（設定檔寫 `檔#/指標` 時＝那個指標＋`/exec`），跑完還原；相對路徑（`cwd`、串流、`argv[0]`）從設定檔的資料夾算，
    單子裡的 `$ref` 從 `exec` 那格來自的檔的資料夾算；`AOS_WS`／`AOS_STACK` 照 loop 自己的，相對路徑以 loop 的 cwd 轉成絕對（`AOS_STACK` 結尾補 `/`，同 aos-exec；跑完還原；不驗、不建），不讀 `.env`。單子壞＝自己的錯一行（`EntryBad`／`DirectiveBad`／`LaunchFailed`，原因開頭 `inst cannot run: `）、退 1。
    被逾時收掉＝那次 143（失敗那行的「誰」＝`loop.json#/exec`）。`{"exec": "loop.json#/body", "body": 單子}` 照樣能用（字串目標，由那次的 aos-exec 跑）。沒有 `exec`＝`CfgBad`「nothing to run」。
  - `max` 非負整數，**沒寫＝不限**；0＝一次都不跑、退 0（負的、`null`＝`CfgBad`）。
  - `interval_ms` 非負整數，沒寫＝0：一次結束到下一次開始至少隔幾毫秒。
- **`on_start`／`on_stop`**（選填，寫法同 `exec`；`null`＝沒有）：`on_start` 在讀完舊 state、第一次之前跑一次；`on_stop` 在要退的那一刻跑一次（`finish` 之後、最後一份 state 之前），不論為什麼退：stop、跑滿、身體 10、身體失敗、訊號、自己的錯（設定讀不了的那種在 loop 起來之前，兩格都不跑）。SIGKILL 跑不到。
  - `on_stop` 的環境多 `AOS_LOOP_CODE`＝loop 要退的碼、`AOS_LOOP_SIGNAL`＝收到的訊號號碼（SIGTERM＝`15`；沒有＝空字串），跑完還原。
  - 期限 `on_timeout_ms`（正整數，沒寫＝5000；0、負的、非整數＝`CfgBad`）：目標（字串、陣列）自成一個行程群組，到時間 SIGTERM 整群、1 秒後還在就 SIGKILL；單子自己沒寫 `timeout_ms`／`timeout_cycles` 就補上這個值。跑的期間收到的訊號轉給它（整群），之後照常收工。
  - 退非 0、逾時、起不來＝stderr 一行 `aos-loop: warning: on_stop <誰> exited N`（或 `did not finish in N ms and was killed`、`cannot run: 代號 原因`），loop 的結束碼不變、`on_start` 失敗照樣開跑。
  - 單子的 `AOS_CO`＝`/on_start`、`/on_stop`。aos-daemon 繼承 Loop，daemon.json 寫了也照跑。
  - 被 daemon 接回（daemon 被 kill -9 後 adopt）的 loop 沒有重起，`on_start` 不會再跑；auto_restart 重起、開門 wake 是新的一支，會再跑。
- loop.json 帶 `"_entry": ["aos-loop", {"$env": "AOS_CF"}]` 時，`aos-exec loop.json` 就把 loop 跑起來（PATH 上要有 aos-loop 與 aos-exec；`_entry` 裡也可以放旗標）。
- 不讀 stdin；stdout 只印 log（下面「log」，沒給 `--enable-logs` 就不寫 stdout）。那次的 stdin／stdout／stderr 接 aos-loop 的。逾時交給單子的 `timeout_ms` 或 `timeout_cycles`（擇一），由共用 `run_inst` 判。

### log

使用者 11-02「daemon和loop他們就是把log輸出到stdout」「要給argv讓使用者選擇是否要印出」，11-02 晚「aos-loop和aos-daemon他們印出的log感覺都沒啥用，應該要改成默認不印」（[thinking 11-02 state 窗](../../../thinking/2026-11/02/state-window/README.md)）：

- **每跑完一次在 stdout 印一行 JSON**（不論那次怎麼結束：0、10、失敗、被訊號停掉）：`{"started_at": 這次開始（ISO 8601 UTC 到毫秒）, "counter_runs": 第幾次, "code": 結束碼, "signal": 訊號或 null, "elapsed_ms": 毫秒}`。結束不另印；`exec` 起不來（單子壞、fork 失敗）那次沒有結果、不印。沒有 `exec`（aos-daemon 純監工）不印每圈的行。
- **預設不印，`--enable-logs` 才印**。不寫任何 log 檔（loop.json 沒有 `log` key）；要存檔就在外面接（`aos-loop loop.json >> log.jsonl`）。
- 身體的 stdout 跟 log 同一條（那次繼承 aos-loop 的 stdout）；混在一起由使用者自己處理（11-02 晚使用者「stdin/out/err都可以任意指定」）。
- 一行一次 `write`（不經 stdio 緩衝）。印不了（stdout 是關掉的管子 EPIPE…）＝之後都不印、照跑、不退出：寫的那一下用 `pthread_sigmask` 擋著 SIGPIPE，寫失敗就把排著的 SIGPIPE 吃掉（零逾時的 `sigtimedwait`）再還原遮罩——**不改 SIGPIPE 的處置**（改成忽略會被 exec 的那次繼承，改了身體的行為）。stdout 是滿了的管子（讀的人不讀）時會卡在那一下，同一般程式寫 stdout。

### 指示詞

使用者「aos 讀的 JSON 全部支援」（N-45）：loop.json 與 ctl 裡也能寫 `$ref`／`$env`（寫法同 [aos-directive](../../aos-directive/README.md)）。**只解 loop 自己讀的格**（C-52；`resolve_keys`）：

- loop.json：整份先換一層（整份是 `{"$ref": "real.json"}` 也行），再把 `exec`、`max`、`interval_ms`、`ctl`、`state`、`state_flux` 整個解（`exec` 換一層後是物件＝單子，裡面不解，留到每次跑的時候 `run_inst` 解，`resolve_exec`）；相對 `$ref` 從設定檔所在的資料夾算（整份換過的從那份檔的；設定檔是捷徑＝實際的資料夾，同 aos-exec 與內嵌單子的 `AOS_CD`，`config_file`）。
  其他 key（`body`、`_entry`…）不碰：`loop.json#/body` 由那次的 aos-exec 自己解，body 裡的 `$env` 沒設是那次的錯。
- ctl：整份先換一層，再把 `cmd`、`max`、`interval_ms`、`seq` 整個解；相對 `$ref` 從 ctl 所在的資料夾算。
- 解不開（變數沒設、讀不到、指不到、繞圈）：設定檔＝自己的錯 `DirectiveBad`、退 1；ctl＝整份不採用、原因進 state_flux 的 `ctl_warning`。

```json
{"exec": [{"$env": "AGENT"}, "題"], "max": {"$ref": "common.json#/max"}, "state": "state.json"}
```
