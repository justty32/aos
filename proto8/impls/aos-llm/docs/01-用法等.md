## 用法

```
aos-llm send [--priority P] --reply-to BOX < body.json
aos-llm recv [--full] [--quiet] BOX 信件名稱
aos-llm ask [--priority P] [--full] < body.json
aos-llm regret 信件名稱
aos-llm ls [--json]
```

- **命令列**：子命令在最前面，子命令的旗標寫在它的位置參數前後都收（P-44 續 11-11；aos-util 的 `parse_cli`）；帶值的旗標寫 `--x V` 或 `--x=V`。不認得的子命令＝`CommandUnknown`、不認得的旗標＝`FlagUnknown`、位置參數沒給或多給＝`ArgumentsBad`。
- **`AOS_LLM_KERNEL`**（`send`、`ask`、`regret`、`ls` 要）：llm kernel 的 **stack**（例 `~/llm_kernel`，那台 llm daemon 的 stack）；信寄進固定位置 **`$AOS_LLM_KERNEL/requests/`**（[aos-llm-kernel](../../aos-llm-kernel/docs/01-用法.md)）。沒設、空的、不是資料夾＝`LlmKernelMissing`（馬上退、不寄；N-63 ②）。**相對路徑的基準點**（11-05，照 [portable-flow](../../../thinking/2026-11/05/portable-flow/03-絕對路徑盤點.md)「基準點＝管我的 daemon 的 stack」）：有 `AOS_DAEMON`（被 daemon 管著跑；人殼 export 了也算）＝相對 `$AOS_DAEMON`，例 agent daemon 的 stack 在 `ws/.stack/`、llm daemon 的在 `ws/../k`＝`AOS_LLM_KERNEL=../../k`；沒有＝相對 cwd（人直接在殼裡打）。格的 cwd（定義資料夾）不當基準點。由人設（daemon 不代設；要給某台 daemon 的子項都拿到，export 了再起那台 daemon，或寫進那台定義的 `.env`）；信箱缺 `tmp/`、`new/` 自己建。`send`、`ask` 寄之前看一眼 `$AOS_LLM_KERNEL/state.json`（daemon 自己寫的窗）：不在、`phase` 不是 running／waiting／stopping（waiting＝兩圈之間，11-10 補；原本漏了會誤報）、或 `pid` 不在＝stderr 印一行 `aos-llm: warning: <stack>: …; letter <信件名稱> was written anyway to <stack>/requests/new/<信件名稱>, the reply comes once it runs (if AOS_LLM_KERNEL points to the wrong place, fix it and delete that letter)`（11-10 晚 two-machines B10：寄完才印、說出信寫到哪，指錯時知道去哪刪；判斷還是寄之前看的），照樣寄、照樣等（11-05 使用者裁 edge-llm 題 1「按照推薦」；daemon 在別的 pid namespace 裡會誤報，只是提醒）。`send`、`ask` 先驗 stdin 的 body 與 `--priority`，驗過才看 `AOS_LLM_KERNEL`、印這行 warning（11-10 坑-100）：body 壞＝只報 `RequestBad`／`PriorityBad`，不先印「letter sent anyway」。`recv` 不看它（只看 BOX）。
- **終端不讀 body**：`send`／`ask` 要從管線或檔案給內容，stdin 是終端就立刻 `ArgumentsBad`。`-h` 顯示該層說明；`ls -j` 等同 `ls --json`。
- **stdin＝整份 body**（`send`、`ask`；一份 JSON，aos-util 的 `read_stdin`）：`{"endpoint"?: 代號字串, "request": {"messages": [...], ...}, "priority"?}`。
  不是物件、沒有 `request`、`request` 不是物件、`messages` 不是陣列、`endpoint` 不是字串＝`RequestBad`（不寄）。`request` 裡其他東西（`tools`、`model`、`temperature`…）不看、原樣寄；`stream` 寫真由 kernel 回 `RequestBad`。
  **`--priority P`** 有給就蓋 `body.priority`：`P` 讀得成 JSON 就用它（`1`、`{"level":"high","deadline":"…"}`），不然當字串（`high`）。priority 先驗（形狀見 [aos-llm-kernel](../../aos-llm-kernel/docs/01-用法.md)），壞＝`PriorityBad`、不寄。
- **`--full`**（`ask`／`recv`）：成功時 stdout 印整個回覆 `body` 一行 JSON（`message`、原有的 `usage`／`model` 與其他欄位），加頂層 `letter`＝寄去 kernel 的原請求信名（`ask` 剛寄的那封、`recv` 參數給的那封）；其他缺的欄位不補。錯誤回信時 stdout 印完整錯誤 body 一行 JSON，保留 `error` 裡的其他鍵，不加 `letter`；stderr 仍印原本的一行、退 1。不給 `--full` 時成功只印 `body.message`，失敗 stdout 不印、stderr 與退出碼照舊。
- **`send`**（非同步）：`--reply-to BOX` 必給（沒給＝`ArgumentsBad`；C-56 寫什麼就做什麼，不猜預設）。BOX 沒有就建成 N-16 信箱（aos-post 的 `init`：`tmp/`、`new/`、`cur/`；建不了 `MkdirFailed`），再交給 aos-post 的庫寄一封信進 `$AOS_LLM_KERNEL/requests/`：
  信封 `sender`（aos-util 的 `aos::identity()`）、`sent_at`、`reply_to`＝BOX（aos-post 存成相對 kernel 信箱根，例 `../../bob/think/reply`；連第一層都不同才存絕對，11-05），`body`＝stdin 那份。**不建 `sender.flock`**：kernel 看不到檔＝不判寄信人在不在、照跑（[think-as-function 衝突 2 (a)](../../../thinking/2026-11/04/think-as-function/05-衝突與方向題.md)）。stdout 印信件名稱（aos-post 預設名，時間開頭）一行、退 0。
- **`recv BOX 信件名稱`**：到 BOX 的 `new/` 找 `letter.json` 的 `in_reply_to`＝那個名字的回信（別人的不碰）。BOX 不是資料夾＝`MailboxMissing`；名字含 `/`、`.` 開頭、空＝`ArgumentsBad`。
  沒到＝退 **10**（什麼都不印）。到了＝認領（`new/` → `cur/`）、讀 `body`、**收掉**（aos-post 的 `done`：刪），然後：
  - `{"message": 物件, …}`＝stdout 印一行 `body.message` 的 JSON、退 0；
  - `{"error": {"code", "msg"}}`＝stderr 一行 `aos-llm: error: 代號 原因`、退 1；
  - 讀不懂＝`ReplyBad`、退 1。
- **`ask`**（同步語法糖＝以前的 aos-llm-send 的等法）：回信信箱＝`$AOS_LLM_KERNEL/requests/reply/`（沒有就建）。透過 aos-post 的 `send_prepared` 把完整信封寫進 `tmp/.<信件名稱>/`；寫信前的 callback 先建 `sender.flock`、flock 住（拿到行程結束：kernel 靠它認寄信的人還在、不看 pid，沙箱裡也行），寫好 `letter.json` 才改名進 `new/`。
  然後每 20 毫秒看一次回信信箱的 `new/`（中間收到訊號馬上醒），回信到了照 `recv` 那三種交回。原信在 `new/`、`cur/` 都找不到、也沒有回信＝`LetterMissing`（kernel 先寄回信才刪信，不會誤判；回信寄不進回信信箱時就是這個；回信信箱本身被刪了，訊息會直說 `reply mailbox ... is gone`）。
  **等多久不歸 aos-llm 管**：kernel.json 的 `timeout_ms`、priority 的 `deadline`，或包它那格的 `timeout_ms`；kernel 不在＝信堆在 `new/`、一直等。
  **訊號**（SIGINT／SIGTERM／SIGHUP）：撤信——`new/<信件名稱>` 改名回 `tmp/` 再刪；已經在 `cur/`（kernel 已經掛去問腦）就讓它跑完、回信到了就收掉，還沒到的由 kernel 寄回信時撤回（寄信的人不在了）。以 128＋N 結束。
- **`ls [--json]`**（11-05 feat-proto，S4）：列 kernel 的能力包。讀 `$AOS_LLM_KERNEL` 的 stack 底下的窗 `endpoints.json`（kernel 每次跑寫的屬性表，形狀 `{代號: {"speed", "cost"?, "context"?, "slots"?, "backend"?, "summary"?}}`，[aos-llm-kernel](../../aos-llm-kernel/docs/01-用法.md)）。預設一行一包 `代號 speed cost context slots backend summary`（欄位用 TAB 隔開，缺的印 `-`，summary 在最後；壞掉的包 `{"error": ...}` 印 `代號<TAB>error:<TAB>原因`）；`-j`／`--json` 印整份窗為一行 JSON。窗不在、讀不懂＝`EndpointsMissing`（kernel 沒跑過，或還沒寫窗）。只讀窗，不看 daemon 在不在。
- **`regret 信件名稱`**：撤回還在 `$AOS_LLM_KERNEL/requests/new/` 的信（aos-post 的 `regret`：改名進 `tmp/` 再刪），退 0；不在 `new/`（kernel 已經認領，或本來就沒有）＝`RegretFailed`、退 1。已經在跑的撤不了，回信到了照樣進 BOX。

## 元素

```
 main ──▶ block_signals ──▶ 子命令 ──▶ parse_cli ──┬─ send：kernel → read_body → send（aos-post init／send）→ 印名字
                                                   ├─ recv：recv（find_reply → aos-post take → deliver）
                                                   ├─ ask：kernel → read_body → send_held（aos-post send_prepared＋sender.flock）→ ask_wait（輪詢、withdraw、deliver）
                                                   └─ regret：kernel → regret（aos-post regret）
```

逐檔「哪個檔負責什麼」從檔頭一句話生成，在 code map 的 [proto8 生成冊](../../../../wf/workflows/common/code-map/proto8/README.md)（`impls` 冊的 `aos-llm/` 段）；改說明去改檔頭。

## 錯誤代號

stderr 一行 **`aos-llm: error: 代號 原因`**、退 1（N-60）。`recv` 回信還沒到＝退 10（不是錯）。

| 代號 | 什麼時候 |
|---|---|
| `ArgumentsBad`、`FlagUnknown`、`CommandUnknown`（共用） | 沒給子命令、不認得的子命令或旗標、位置參數沒給或多給、`send` 沒給 `--reply-to`、信件名稱不是單純的名字 |
| `LlmKernelMissing` | 沒設 `AOS_LLM_KERNEL`、空的、不是資料夾（相對的照上面的基準點解完再看；訊息印解完的路徑） |
| `MailboxMissing`（共用） | `recv` 的 BOX 不是資料夾；`regret` 時 `$AOS_LLM_KERNEL/requests/` 不在 |
| `RequestBad` | stdin 不是物件、沒有 `request`、`request` 不是物件、`messages` 不是陣列、`endpoint` 不是字串（kernel 也會回：`stream` 真） |
| `PriorityBad` | priority 寫壞（沒寄） |
| `MkdirFailed`、`WriteFailed`、`MailboxBad`（共用） | 信寫不了、改名不了；回信信箱建不了；信箱對自己不可寫 |
| `LetterMissing` | `ask`：信在信箱裡不見了（也沒有回信） |
| `RegretFailed` | `regret`：信不在 `new/` |
| `EndpointsMissing` | `ls`：`$AOS_LLM_KERNEL/endpoints.json` 不在或讀不懂 |
| `ReplyBad` | 回信的 `body` 讀不懂（kernel 也會回：endpoint 函數的 stdout 讀不懂） |
| kernel 回的：`EndpointMissing`、`EndpointUnknown`、`EndpointFailed`、`LetterBad`、`DeadlineBad`、`BudgetMissing`、`LaunchFailed`、`DirectiveBad`、`CfgBad`… | 見 [aos-llm-kernel](../../aos-llm-kernel/docs/03-元素等.md#錯誤代號) |

## 已知限制

- `ask` 輪詢 20 毫秒（N-14「輪詢保底、inotify 加速」，目前只有輪詢）；`recv` 一次只看一眼，要等就由呼叫端（loop 的下一拍）再叫。
- **`AOS_LLM_KERNEL` 指錯資料夾不報錯**（11-04 夜使用者「自己要承擔的風險」）：只要是個資料夾就照寄，在那裡建出 `requests/`，沒有 kernel 收、寄信的一直等。常見三種指錯：指到定義資料夾（`~/llm_kernel/def`，還會在原始碼裡多出一個 `requests/`）、llm daemon 起的時候漏了 `--stack .`（stack 變成 `~/llm_kernel/.stack`）、指到跑 agent 的那台、相對路徑寫成從定義資料夾或人殼 cwd 算（有 `AOS_DAEMON` 時是從它算）。11-05 起這幾種與「llm daemon 停了」寄的時候都會印一行 warning（見上 `AOS_LLM_KERNEL`），但照樣寄、照樣等。
- `ask` 被 SIGKILL 來不及撤信：信留在 `new/`，鎖跟著行程放掉，kernel 下一次看寄信的人不在了會丟掉、不跑。`send` 寄的信沒有鎖：寄完的人不在了照跑，回信寄不進就印在 kernel 的 stderr；排隊中要省就 `regret`。
- 回信信箱裡每封沒看過的信都要讀 `letter.json` 才知道是不是回自己；`ask` 的共用回信信箱（`$AOS_LLM_KERNEL/requests/reply/`）量大時會慢。非同步用自己的 BOX 就沒這題。
- 回信到了才知道是不是 error；kernel 不在、或寄不進 BOX（權限）時 `recv` 一直退 10。11-10（坑-102）起有設 `AOS_LLM_KERNEL` 時多印一行 warning 說是哪一種：信還在 kernel 的 `new/`／`cur/` 而 kernel 沒在跑＝`no reply for L yet: …: llm daemon is not running …`；照權限位 kernel（它 stack 的 `state.json` 的主人）寫不進 BOX 的 `tmp/`、`new/`＝`no reply for L: the llm kernel cannot deliver into BOX (… is mode 555, owner uid …, kernel uid …)`（只看主群組，補充群組看不到）。正常等待中照舊不印；信已不在 kernel、BOX 也沒有的不報（回信已經收過一次也長這樣，分不出來）。每拍輪詢的呼叫者（fsm 的 wait）帶 `--quiet` 就不印這行（11-10：kernel 沒跑時每拍一行，一隻 agent 每小時約 2.7 MB）；人手打的 recv 預設照印。細節照舊看 kernel 的 stderr。
- 回信信箱是 aos-llm 用自己的 umask 建的；跨帳號（kernel 與寄信人不同帳號）要先照 [root/setup.sh](../../../cmd/aos-sandbox/root/setup.sh) `--mailbox` 建好、給權限，不然 kernel 寄不進回信。
