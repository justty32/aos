## 元素

```
 main ──▶ block_signals ──▶ parse_cli ──▶ 要 AOS_STACK ──▶ read_table ──▶ make_stack（11-11）──▶ read_state ──▶ pick ──▶ run_once（aos-loop）──▶ next_for ──▶ write_state（查到才寫）
```

跑一格借 aos-loop 的 `run_once`（格的 `exec` 跟 loop.json 的 `exec` 是同一個東西，訊號轉送也一樣）；fsm 不知道格是什麼（C-52）：`run_once` 只回碼、訊號、毫秒（沒有逾時）。沒有公開標頭（沒有別的專案要用 fsm 的庫）。

逐檔「哪個檔負責什麼」從檔頭一句話生成，在 code map 的 [proto8 生成冊](../../../../wf/workflows/common/code-map/proto8/README.md)（`impls` 冊的 `aos-fsm/` 段）；改說明去改檔頭。

訊號的阻擋與非等待取出直接使用 aos-util `block_signals`／`take_signal`；跑格仍使用 aos-loop `run_once`。

## 錯誤代號

自己出錯：stderr 一行 **`aos-fsm: error: 代號 原因`**、退 1（N-38、N-60）。跑格時才發現的錯，原因開頭是「state X: 」。

| 代號 | 什麼時候 |
|---|---|
| `ArgumentsBad`（共用） | 沒給、多給設定檔 |
| `FlagUnknown`（共用） | 不認得的旗標（含 `--cfg`） |
| `StackMissing` | 沒設 `AOS_STACK`（或空的） |
| `DirectiveBad`（共用） | fsm.json 裡 fsm 讀的格（整份、`start`、`states`、每一格、`exec`、`next`）的指示詞解不開；那格的單子裡的指示詞跑的時候解不開 |
| `CfgMissing`（共用） | 設定檔不在；`#/` 指標指不到 |
| `CfgBad`（共用） | 設定檔讀不了、不是 JSON；`#` 後面不是 `/`；不是 `{"start": 字串, "states": 物件}`；開跑時查整張表不合：`start` 不在表上、某格不是 `{"exec", "next": 字串或物件}`、`next`（或物件 `next` 的值）不在表上／空字串／頭尾有空白／有換行／不是字串、物件 `next` 的 key 不是 `"0"`～`"255"` 或 `"*"`、物件 `next` 沒有 `"0"` 也沒有 `"*"`、`exec` 不是字串、非空字串陣列或物件 |
| `EntryBad`（共用） | 那格的單子形狀不對（原因開頭「state X: inst cannot run: 」） |
| `StateBad` | `$AOS_STACK/stage.txt` 在但讀不了（沒權限、是資料夾、不是 UTF-8） |
| `StateUnknown` | state 檔裡的狀態不在表上 |
| `WriteFailed`（共用） | `.stage.txt` 寫不了、改名不了（例跑那格的途中 `AOS_STACK` 資料夾被刪掉） |
| `MkdirFailed`（共用） | 起來時 `$AOS_STACK` 有設但不在、又建不了（11-11：表查過之後、跑格之前先 `mkdir -p`，aos-loop 的 `make_stack`） |
| `LaunchFailed`、`Internal`（共用） | 跑格時 fork 失敗、準備轉送訊號失敗、那格的單子起不來（原因開頭「state X: 」） |

單子格壞、`$env` 沒設、起不來都是那格 aos-exec 的錯（它印一行、碼 1），fsm 只當那格非 0。
