## 錯誤代號

自己出錯：stderr 一行 **`aos-exec: 代號 原因`**、退 1（例 `aos-exec: EntryMissing entry not found: nope`）。照 N-60／P-21「程式名: 原因」，代號放開頭給測試認；
代號後面的原因開頭固定（`workspace does not exist`、`entry not found`、`bad entry`、`cannot start: X (原因)`、`inst cannot run: `、`cannot read .env`、`bad .env`、`cannot create AOS_STACK`、`usage: …`）。

| 代號 | 什麼時候 |
|---|---|
| `ArgumentsBad`（共用） | 沒給 XXX、XXX 是空字串、旗標缺值、不帶值的旗標帶了值（原因 `usage: aos-exec [--ws WS] [--stack S] [--dotenv-override] XXX [args...] (原因)`） |
| `FlagUnknown`（共用） | 不認得的旗標 |
| `WsMissing` | WS 不是資料夾 |
| `EntryMissing` | 資料夾／檔／`.json` 補找都沒有；多段 `$AOS_ENTRY` 中間某段不是資料夾；`#/` 指標指不到 |
| `EntryBad` | 既不可執行也不是 JSON；JSON 種類不對（沒 argv 的物件裡沒有 `[$AOS_ENTRY]`、數字、空陣列…）；`#` 後面不是 `/`；資料夾或可執行檔帶 `#/`；字串轉向繞圈、轉向的路徑是空字串；資料夾繞圈；argv 陣列的指示詞解不開或解完不是全字串；inst 單子欄位型別不對 |
| `DotenvBad` | `.env` 在但讀不到（權限、是資料夾、壞掉的捷徑）；`.env` 壞：沒有 `=`、名字不合、`${` 寫法不對、`${名字}` 沒設、值有 NUL、不是 UTF-8（含 BOM）；JSON `.env` key 的指示詞解不開、名字不合、`${名字}` 沒設。只印位置、不印值 |
| `DirectiveBad`（aos-directive 透傳） | 單子裡的指示詞解不開：`$env` 沒設、`$ref` 讀不到／不是 JSON、指不到、繞圈（寫法不合不算錯，物件原封不動，之後照欄位規則判） |
| `MkdirFailed`（共用） | AOS_STACK 建不了（`--stack` 給的也一樣）；單子的 `cwd_mkdir`／`stdout_mkdir`／`stderr_mkdir` 建不了（原因前面加「inst cannot run: 」） |
| `LaunchFailed`（共用） | exec 失敗（ENOENT、EACCES…；原因 `cannot start: X (原因)`）；inst 單子 libaos 起不來（原因 `inst cannot run: ` 接 libaos 的名字） |
| `Internal`（共用） | 照理不會發生的例外；inst 單子收不到結果（libaos 的 `WaitFailed`／`KillFailed`）、準備轉訊號失敗 |

入口跑起來之後的結束碼不是 aos-exec 的錯：可執行檔與 argv 陣列是 exec（碼就是入口的）；inst 單子是子程式的碼（被訊號停掉 128＋N）。
所以入口自己退 1 跟 aos-exec 出錯分不出來時，看 stderr 那行有沒有 `aos-exec: ` 開頭。

## 跟規範／慣例的已知差異

- 沒有 `aos-inst` 命令列：P-28 的 (A)「`_entry` 第一行 `#!/usr/bin/env aos-inst`」與 (1)「小殼 `exec aos-inst _entry.json`」跑不起來；
  同一個檔拿掉 `+x` 就能用（第一行 `#!` 跳過、當單子跑）。
- 新建的空 stack 只在 aos-exec 回來時收（N-59 第 1 件只說建）：可執行檔／argv 陣列入口 exec 成功就不回來，新建的空 stack 會留著；inst 單子把子程式丟到背景、子程式之後才寫 stack 的，回來那一刻是空的會被收掉（子程式要用就自己 mkdir -p）。
