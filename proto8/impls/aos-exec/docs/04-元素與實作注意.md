## 元素

```
 main ──▶ run_cli（解旗標）──▶ hop（check_ws → locate → setup_stack → enter：cd、load_env → 挑入口 → classify → 重設 CF／CD／CO）──▶ launch（exec／run_inst）
                                  ▲                                                                                       │
                                  └──────────────────── 字串轉向＝全新的一跳（旗標不帶、args 照接、同一條 Chain）◀────────────┘
```

逐檔「哪個檔負責什麼」從檔頭一句話生成，在 code map 的 [逐檔表 impls.json](../../../../wf/knowledge/code-map/proto8/impls.json)（`#/tree/aos-exec`）；改說明去改檔頭。

## 實作注意

- **`run_cli` 會動行程全域狀態（chdir、setenv）**：`.env` 要在挑入口之前讀、挑入口又要看讀完之後的 `$AOS_ENTRY`、每走進一層都要 cd 和 setenv，
  拆不成「先純計算、最後才動全域」的幾步，所以 `check_ws`／`setup_stack`／`hop`／`launch` 都是內部函數、只公開 `run_cli`。
  所以長命的呼叫者不在自己的行程裡叫它：aos-loop、aos-fsm 的每一次、aos-daemon 的子 loop 都是 **fork 出來的子行程**裡呼叫 `run_cli`，
  效果等同起一支 `aos-exec -- 目標 參數...`，父行程的 cwd 與環境不受影響。
- **AOS_STACK 在 chdir 之前算**：`--stack` 與有設的 `$AOS_STACK` 的相對路徑要從呼叫當下的 cwd 算。WS 的檢查在認出 XXX 之前、建 stack 在認出 XXX 之後（錯誤先後照這個順序），所以拆成 `check_ws`、`setup_stack` 兩個。
- **字串轉向是全新的一跳**：C-52「每層只管自己」——下一層自己定工作區、cd、讀 `.env`；這一層的旗標不帶過去。唯一的例外是繞圈偵測沿用同一條鏈，當安全網。
- **`.env` 的錯不印值**：`.env` 常放 API key，錯誤訊息只說哪個檔第幾行、什麼原因。
- **可執行檔、argv 陣列都用 glibc 的 `execvp`**：`+x` 沒 `#!`（ENOEXEC）由它改用 `/bin/sh` 跑，三種入口（含 inst 單子的 `argv[0]`）一致。
  aos-exec 自己沒有 fork，不必守「fork 後只能呼叫 async-signal-safe」那條（loop／fsm／daemon 在 fork 後呼叫 `run_cli`，是 exec 的替身：子行程是單執行緒的，且本來就要做完 `.env`、cd 再 exec）。
- **inst 單子留在行程裡**：單子的逾時、整群收掉、轉訊號總得有人做，而 aos-inst 只是 C lib、沒有自己的命令列，所以 aos-exec 當監工；
  可執行檔與 argv 陣列沒有這些欄位，直接 exec、少一層行程。
- **單子 JSON 的解析放這裡、不進 C 庫**（使用者定）：aos-inst 維持純 C、不讀 JSON、零 malloc、給 FFI。
- **`$env` 在 setenv、讀完 `.env` 之後解**：單子要讀得到 aos-exec 剛設的 `AOS_STACK`／`AOS_CD` 與 `.env` 設的值（`.env` 一直有效到真正開跑）。
- **`run_inst` 進出擋／還原訊號遮罩**：單執行緒的 CLI 不用另外做事；多執行緒的呼叫者要在開執行緒前自己把三個訊號擋好。
  轉送用 `killpg`（沒有 pidfd 可以代表一整群）；工人收完屍就停止轉送，避免群組號被別人重用時送錯。

- **行程邊界不是整棵樹的清單**：inst 的 `setsid`＋`killpg` 只管理自己起的子行程群；自行換 session 的後代會逃出該群。daemon 表只列它直接管的 proc，不列 inst 起的孫行程；跨機器搬 image 不會搬走 Linux 行程、session 或群組，醒來照自己的 stack 與重新啟動規則處理。
