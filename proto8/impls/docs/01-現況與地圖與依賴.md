## 現況

impls 是唯一實作；Python 版只剩 `proto8/cmd/aos-tick`。各支的 `bin/` 要先照下面「建置」建好。對外提供十支命令列；`aos-inst` 是 C 函式庫、沒有命令列（inst 單子的 JSON 解析在 aos-exec 的 `src/inst/`，沒有 `aos-inst` 命令列）；`aos-util` 是函式庫；`aos-directive` 同時提供函式庫與命令列，`lib/aos/judge/_entry` 靠 PATH 呼叫它，使用判官時必須放進 PATH（`install.sh` 會安裝連結）（aos-schema 11-06 封存到 `proto8/archive/aos-schema`）。每個專案是一個獨立的 CMake 專案（照 [dcap](../../../../dcap/README.md) 的慣例）。

| 專案 | 做什麼 | 產物 | 現況 | 去哪讀 |
|---|---|---|---|---|
| aos-exec | `aos-exec [--ws WS] [--stack S] [--dotenv-override] XXX [ARGS...]`：在工作區執行一個資料夾程式（走進去、讀 `.env`、挑入口、開跑；inst 單子在行程內跑）；公開 API `run_cli`、`run_inst`、`argv0` | `lib/libaos-exec.a`、`bin/aos-exec` | **提供** | [aos-exec](../aos-exec/README.md) |
| aos-loop | `aos-loop [FLAGS] loop.json`：一次次跑 `exec`，有 `interval_ms`、ctl／state 窗；公開 API（跑一次 `run_once`、骨架 `Loop`、`loop_cli`） | `lib/libaos-loop.a`、`bin/aos-loop` | **提供** | [aos-loop](../aos-loop/README.md) |
| aos-fsm | `aos-fsm fsm.json`：一次跑一格、照 `next` 換狀態 | `lib/libaos-fsm.a`、`bin/aos-fsm` | **提供** | [aos-fsm](../aos-fsm/README.md) |
| aos-daemon | `aos-daemon [FLAGS] daemon.json`：顧一群 proc（子 loop 或 aos-exec 一次），`procs_ctl` 增減、`procs_state` 表 | `lib/libaos-daemon.a`、`bin/aos-daemon` | **提供** | [aos-daemon](../aos-daemon/README.md) |
| aos-llm-kernel | `aos-llm-kernel [FLAGS] kernel.json`：LLM kernel 跑一次（收成品回信、挑信、請 daemon 掛成問腦 proc 跑自己的 endpoint 函數）；公開標頭 `aos/llm_kernel.hpp`（信箱與信） | `lib/libaos-llm-kernel.a`、`bin/aos-llm-kernel` | **提供** | [aos-llm-kernel](../aos-llm-kernel/README.md) |
| aos-llm | `aos-llm send`／`recv`／`ask`／`regret`：寄請求信進 kernel 的信箱、收回信（11-04 由 aos-llm-send 改名） | `lib/libaos-llm.a`、`bin/aos-llm` | **提供** | [aos-llm](../aos-llm/README.md) |
| aos-json | `aos-json 子命令 [FLAGS...] 檔#/指標 [值]`：讀、改 aos 的 JSON 設定（認得 `$ref`／`$env`）；給腦掛的工具在 lib：[`aos_json`](../../lib/aos/aos_json/)、[`json_rewrite`](../../lib/agent/json_rewrite/)；庫沒有公開標頭 | `lib/libaos-json.a`、`bin/aos-json` | **提供**（嘗試） | [aos-json](../aos-json/README.md) |
| aos-post | `aos-post 子命令 [FLAGS...] 信箱 [信件名稱]`：N-16 投遞（IPC 的語法糖；有序、無序同箱）；公開標頭 `aos/post.hpp` | `lib/libaos-post.a`、`bin/aos-post` | **提供** | [aos-post](../aos-post/README.md) |
| aos-lock | `aos-lock 子命令 [FLAGS...] 目標`：N-15 的鎖（flock 判庫持有者死活、租約數 tick）；公開標頭 `aos/lock.hpp` | `lib/libaos-lock.a`、`bin/aos-lock` | **提供** | [aos-lock](../aos-lock/README.md) |
| aos-inst | C 函式庫 aos-inst：起一個程式、等它結束、告訴你結果 | `lib/libaos-inst.so`（FFI）、`lib/libaos-inst.a` | 庫（不讀 JSON、沒有命令列） | [aos-inst](../aos-inst/README.md) |
| aos-util | 全家共用的 C++ 函式庫 | `lib/libaos-util.a` | 庫 | [aos-util](../aos-util/README.md) |
| aos-directive | 指示詞 `$ref`／`$env`（可帶 `$path`（字串拼接）、`$prefix`） | `lib/libaos-directive.a`、`bin/aos-directive` | 庫＋命令列（判官從 PATH 呼叫） | [aos-directive](../aos-directive/README.md) |

使用者看得到的名字照 [C-54 命名方法](../../docs/CONCEPTS/01-設計理念/C-54-命名方法.md) 與 [NORMS 前言「命名」](../../docs/NORMS.md)；時間值一律 ISO 8601 UTC 到毫秒（例 `2026-10-23T01:58:45.123+00:00`）。庫裡的內部變數、結構欄位不一定跟著改名（例 `runs_`）。

## 地圖與依賴

誰連誰（從各 `CMakeLists.txt` 的 `target_link_libraries` 生成）與每個檔負責什麼（從檔頭一句話生成），都在 code map 的 [proto8 生成冊](../../../wf/workflows/common/code-map/proto8/README.md)：`impls` 冊開頭是依賴表，後面一個專案一段。由下往上一句話：`aos-inst`（C）→ `aos-exec` → `aos-loop` → `aos-fsm`／`aos-daemon`；`aos-llm` 連 `aos-llm-kernel` 的信件協定 API；`aos-util` 全家共用；`aos-post`（連 `aos-lock`）是信箱，aos-daemon、aos-llm-kernel、aos-llm 連它；`aos-directive` 給 aos-exec、aos-loop、aos-json、aos-llm-kernel 解 `$ref`／`$env`。各專案的行為看它自己的 README。
