### 命令列：設定、旗標、三扇門、指示詞

> **aos-exec、aos-loop、aos-fsm、aos-daemon 的命令列不照這一節**：不讀 stdin 設定，設定只認設定檔（loop.json、fsm.json、daemon.json 是唯一的位置參數，可寫 `檔#/指標`），
> 不寫結果 JSON（結果＝結束碼），錯誤一行「程式名: 代號 原因」。**旗標**：旗標寫在位置參數前後都收（11-11 P-44 續；位置參數後像負數或含空白的字照舊當位置參數），`--x V` 或 `--x=V`、重複給最後一個算、`--` 結束旗標（在位置參數後＝連它原樣交出）、
> 呼叫者給 `keep`＝第 N 個位置參數起原樣（子命令程式的頂層、aos-exec 的 XXX、aos-json set／append／merge 給 1＝舊規則）；不認得＝`FlagUnknown`、缺值＝`ArgumentsBad`。規則在 aos-util 的 `aos/util/cli.hpp`（`parse_cli`、`load_cfg`）：
> aos-exec 有 `--ws`、`--stack` 與不帶值的 `--dotenv-override`；aos-loop、aos-daemon 有 `--max`、`--interval-ms`、`--ctl`、`--state`、`--state-flux`（11-09，[N-09 的 11-09 補](../../docs/NORMS/05-基礎設施-窗/02-N-09～N-11.md)：回音窗 `state_flux.json` 的位置，鏡射設定 key `state_flux`）與不帶值的 `--enable-logs`、`--enable-counters`（旗標 ＞ 設定檔 ＞ 預設）；aos-llm-kernel 只有 `--enable-counters`；aos-fsm 沒有旗標。**`--enable-counters` 是全家同名的開關**（11-09，[N-09 的 11-09 補](../../docs/NORMS/05-基礎設施-窗/02-N-09～N-11.md)）：只因時間或每跑一次就變、又沒別的程式讀的計數器，一個一個 `.txt`（例 `counter_runs.txt`）放在這個旗標後面，**預設不寫**；新程式有這類計數器就用同一個名字，走 `parse_cli`／`aos_flags`，不各自取名。
> 下面是較早那代（aos-directive 的 bin；aos-schema 11-06 封存）的規矩。

- **設定只從 stdin 讀一份 JSON**（`aos::read_stdin`）：空的＝`{}`、多份＝`InputBad`、解不出來＝`InputBad`、壞掉的尾巴丟掉。
  沒有 TARGET、沒有 `-`：任何位置參數＝`ArgumentsBad`。
- **旗標**：較早那代的 `aos::parse_flags`（旗標＝key 原名）沒人叫，11-04 已刪；現行旗標一律走 `aos/util/cli.hpp` 的 `parse_cli`。
- **指示詞**（aos-directive）：stdin 與每個旗標值裡的 `{"$ref": 檔}`、`{"$env": 變數}` 先解開再驗欄位。語意見 [N-45](../../docs/NORMS/06-基礎設施-命令列與指示詞.md)。
- **結果 stdout 一行 JSON、退出 0**（`aos::emit`，排版同 Python `json.dumps`，key 照原順序）；**出錯 stderr 一行、退出 1**。
  子程式回非 0 不算錯（那是結果）。

### 目錄（照 dcap，三處偏離）

```
<專案>/
  CMakeLists.txt    include(../cmake/settings.cmake) → project() → 兄弟專案 → 函式庫 → if(PROJECT_IS_TOP_LEVEL OR AOS_IMPLS_ALL) 執行檔
  vcpkg.json        nlohmann-json
  include/aos/...   公開標頭（有要給別人用的才有）
  src/              除 main.cpp 全進函式庫；一個元素一個資料夾
  bin/ lib/ build/  產物與建置目錄（不進 git）
```

跟 dcap 不同的三點（使用者拍板）：函式庫 **STATIC**（不是 SHARED）、執行檔 **`-static-pie` 全靜態**（啟動不必動態載入 libstdc++；代價是執行檔較大、glibc 有安全更新要重建）、**兄弟專案用 `add_subdirectory` 一起編**
（它們的 `lib/*.a` 會輸出到各自的資料夾，所以建 aos-fsm 也會更新 `../aos-loop/lib/`、`../aos-exec/lib/`——可接受）。

### 建置

**一次建全家（平常用這個）**：在 `impls/` 頂層一次 configure、一次 build，出所有專案的 bin（11 支：aos-util、aos-inst 只有庫）：

```sh
cd proto8/impls && cmake -B build && cmake --build build
```

**單獨建一個專案**（只改一個、或拿出 repo 用）：進那個專案的資料夾，同一行：

```sh
cd aos-exec && cmake -B build && cmake --build build
```

- **兩種建法擇一、不要同時跑**：產物都寫回各專案自己的 `<專案>/bin`、`<專案>/lib`，兩個 build 同時跑會互蓋（`build/` 各自分開、都不進 git）。
- 頂層 [`CMakeLists.txt`](../CMakeLists.txt) 照依賴序 `add_subdirectory` 每個專案、`option(AOS_IMPLS_ALL ON)`；各專案的執行檔條件是 `if(PROJECT_IS_TOP_LEVEL OR AOS_IMPLS_ALL)`，所以從頂層建也出 bin。新專案要加進頂層那張表。

- 共通的 CMake 設定在 [`cmake/settings.cmake`](../cmake/settings.cmake)（vcpkg toolchain 的找法、Release、`compile_commands.json`、PIC、
  `-static-pie` 與 sanitizer 例外），各專案 `project()` 之前 `include` 它。只有 `set()`，沒有函數、沒有巨集。
- nlohmann-json 走 vcpkg（toolchain 自動找 `~/dev/vcpkg`，或設 `VCPKG_ROOT`）；vcpkg 只看最上層那份 manifest：頂層建看 [`impls/vcpkg.json`](../vcpkg.json)（全家相依合併），單獨建看各專案自己的 `vcpkg.json`。專案加了相依，兩份都要加。
- C++ 標準全家一個：`settings.cmake` 定 C++20、`CMAKE_CXX_EXTENSIONS OFF`（`-std=c++20`）；aos-inst 是 C11，也 include `settings.cmake`。
- 要用兄弟專案就 `add_subdirectory`，包在 `if(NOT TARGET ...)` 裡（同一個 build 裡好幾個專案都要它，只 add 一次）：
  ```cmake
  if(NOT TARGET aos-util)
    add_subdirectory(../aos-util aos-util-build)
  endif()
  target_link_libraries(你的target PRIVATE aos-util)
  ```
- 依賴順序：aos-inst → aos-util → aos-directive → aos-exec → aos-loop → aos-fsm、aos-daemon、aos-llm-kernel → aos-llm；aos-json 連 aos-util、aos-directive，排在 aos-exec 後面；aos-lock 只連 aos-util、aos-post 連 aos-lock、aos-daemon 連 aos-post（信箱模式），所以 aos-lock、aos-post 排在 aos-daemon 前面。
  頂層 `CMakeLists.txt` 就照這個順序 add。
- Sanitizer：`cmake -B build-asan -DCMAKE_CXX_FLAGS="-fsanitize=address,undefined"`（`settings.cmake` 看到 `-fsanitize` 就不加 `-static-pie`）。
  帶 sanitizer 的 `.a` 會蓋掉共用的 `lib/`，建完記得重建正常版。
- clangd 看 `build/compile_commands.json`（會自己去 `build/` 找）。

## 新專案照這張清單

1. 資料夾 `aos-<短名>`；`CMakeLists.txt` 照 [aos-directive 的](../aos-directive/CMakeLists.txt)（最短的一份）改名字；`vcpkg.json` 抄一份改 name／description。
2. namespace `aos::<短名>`；`src/common/common.hpp` 放 `using aos::Error; using aos::Json;` 與自己的 `code`（`using namespace aos::code;` ＋獨有的）。
3. 先用一句話說清楚這支程式是什麼，從那句話裡的元素拆 `src/<元素>/`，每個元素一個同名 `.hpp` 列「幾塊 → 哪個檔」；跨元素共用的進 `common/`；
   全家都要的進 aos-util。`main.cpp` 只串。
4. 命令列：`aos::parse_cli` ＋ `aos::read_stdin` ＋ `aos::resolve` ＋ 欄位表；結果 `aos::emit`、錯誤 `aos::fail(程式名, e)`（錯誤行 `程式: error: 代號 原因`）、提醒 `aos::warn`；`parse_cli` 最後一個參數給英文 `--help` 說明。
5. README 照上面的章節順序；只講自己，共通的連回這一頁，規範的語意連回 [NORMS](../../docs/NORMS.md)。
6. 每個檔開頭一段白話（哪個元素的哪一塊）；寫法照「寫法（不要太難）」。
