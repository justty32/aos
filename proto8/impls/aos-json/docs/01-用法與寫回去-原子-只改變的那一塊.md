## 用法

`aos-json 子命令 [FLAGS...] 檔#/指標 [值]`——旗標寫在 `檔#/指標` 前後都收（aos-util 的 `parse_cli`，11-11 P-44 續）；**`set`、`append`、`merge`、`add` 照舊放在 `檔#/指標` 前面**：它們的值什麼字都可以（`--str` 時 `-x`、`--check` 也是合法值），`檔#/指標` 起原樣收。
`檔#/指標` 同 N-62：第一個 `#` 就切、`#` 後一定要 `/`、指標照 RFC 6901（`~1`＝`/`、`~0`＝`~`、陣列索引不收前導 0）；沒 `#`＝整份。
值：有給參數就用參數，沒給讀 stdin 整份（終端 stdin 立即 `ArgumentsBad`，請用管線或檔案）；當 JSON 解（解不開＝`ValueBad`，要寫字串加 `--str`）。負數值直接寫在 `檔#/指標` 後面就行（第一個位置參數之後都不當旗標）；值裡有空白要整個加引號，不然會被當成多的參數（`ArgumentsBad`）。`檔#/指標` 後面再寫 `--` 會被當成值。

| 子命令 | 做什麼 | 旗標 |
|---|---|---|
| `get` | 印那個值（一行 JSON） | `--follow` 路上的 `$ref` 穿過去；`--resolve` 把值裡的指示詞解開（aos-directive）；`--str` 字串印字面 |
| `ls` | 第一行這一格的型別與長度（`object, 4 keys`、`array, 12 items (index 0..11)`、`string, 5 chars`、純值 `number 20`）；之後一行一個孩子（key 照 RFC 6901 跳脫，可直接接在指標後面）；沒列完最後一行 `[more] A to B of N shown; next: --offset X`（退 0）。取值同 `get` | `--follow`、`--resolve`（同 `get`）；`--long` 每項多 TAB 欄：型別、大小（`N keys`／`N items`／`N chars`〔code point 數〕，純值是緊湊 JSON）、容器與字串再加 `N bytes`（緊湊 JSON 的 UTF-8 bytes）；`--depth N`（預設 1；>1＝N 層內的子孫照前序都列，每行是相對那一格的指標段 `states/think/next`，只往物件／陣列裡走）、`--offset N`（預設 0）、`--limit N`（預設全列；兩者算在攤平後的行上） |
| `search` | 找 key／value：往下＝那一格以下每個成員（前序、照檔裡順序）；`--up`＝父層一路到根、每層只看自己的成員、近的先。一行一筆 `檔#/指標 TAB 型別 TAB 大小…`（同 `ls --long` 的欄，檔照命令列字面）；沒中＝`[no match]`、超過 limit＝`[more] 0 to N-1 of M shown; narrow the path or give a bigger --limit`（都退 0） | `--key K`、`--value JSON`（至少一個；JSON 全等且型別一致，`1`≠`"1"`、`1`＝`1.0`；只給 value 時陣列元素也算）、`--contains`（key 與字串值改成「包含」）、`--up`、`--limit N`；`--follow`／`--resolve`＝從穿過／解開後那格往下找（不配 `--up`） |
| `peek` | 漸進展開：第一行位置＋形狀，之後每個孩子一行 `key: 摘要`（字串超過 80 位元組截斷、物件 `{N} 前六個 key`、陣列 `[N]`、指示詞 `$ref "…"`）；指到純值＝整個印 | `--follow`（指到的 `$ref`／`$ref` 陣列照 aos-directive 合好展開）、`--depth N`（預設 1） |
| `where` | 一路穿過 `$ref`，每站一行 `檔#/指標`，最後一站＝值實際寫的地方；最後是 `$env` 多印 `$env 名字` | |
| `set` | 換掉那個值（單值或整棵子樹）；物件裡沒這個 key＝接在最後；陣列只換已有的索引；整份（沒 `#`）時檔可以還不在＝建新檔 | `--follow` 或 `--raw`、`--parents`（路上沒有的物件 key 建空物件）、`--str`、`--check` |
| `add` | 加一項新的：父層是物件＝新 key（已有＝`KeyExists`，提示用 `set`；已有的是陣列再提示寫 `/-`）；父層是陣列＝`/N` 插在第 N 項前面（0..長度）、`/-` 接尾巴，超出或前導 0＝`PointerMissing`；整份（沒 `#`）＝檔已在 `KeyExists`、不在建新檔。成功 stdout 印實際寫到的位置（照給的字面，`-` 換成真索引） | 同 `set`：`--follow` 或 `--raw`、`--parents`、`--str`、`--check` |
| `batch` | stdin `{"/指標": 值, …}` 照順序一個個 set，**全部成功才寫**（每份檔一次原子寫入） | `--follow`、`--parents`、`--check` |
| `del` | 刪 key／元素（不刪整份） | `--follow`（`$ref` 陣列合起來的 key：每一份有的都刪）或 `--raw` |
| `append` | 陣列尾巴加一個 | `--follow` 或 `--raw`、`--str`、`--check` |
| `merge` | 物件淺層合 key（同 `$ref` 陣列：後蓋前、不往下合；`null` 照字面放） | `--follow`、`--check` |
| `env` | 換成 `{"$env": 名字}` | `--path`、`--prefix`、`--parents` |
| `ref` | 換成 `{"$ref": 目標}`（目標從這份檔的資料夾算） | `--move`：先把原本的值搬到目標（整份檔＝檔不能已在；`檔#/指標`＝那裡要還沒有），裡面的相對 `$ref` 跟著改；`--parents` |
| `check` | 驗：`$ref` 指得到（一路驗進被參照的檔）、繞圈、`$ref` 陣列合得起來、指示詞寫法不合、`exec` 形狀（最上層 `exec`、`states/<名>/exec`、`procs/<名>/exec`：非空字串、非空陣列、單子要有非空 `argv`）。問題每個一行 `位置: 代號 原因` 印 stdout、**退 10**（stderr 空；11-05 stdio-unify D1：查完了、結果否定，同「沒東西」；原退 1）；沒問題退 0 | `--env`：`$env` 現在沒設也報 |

**`--follow` 的規則**：沒加時，寫入的路上經過指示詞＝`FollowMissing`（往指示詞物件裡加 key，aos 不會看，是陷阱）；直接指著指示詞改＝原地換掉它。
加了＝穿過 `$ref` 改被參照的檔；`$ref` 陣列（幾份合成一份）：物件看「最後一份有這個 key 的」（生效的就是它），都沒有＝寫進最後一份；陣列照索引換算是哪一份；
`set --follow` 不能整個換掉合起來的值（`TargetBad`）；`$env` 穿不過去（`PointerMissing`）。`get`、`peek` 不加 `--follow` 時照原文走（跟 aos 讀設定檔一樣：`#/指標` 取原文）。

**`--raw`**（`set`、`append`、`del`、`add`；11-12 給 json 工具簡單組用，[json-tools](../../../thinking/2026-11/12/json-tools/README.md)）：路上的 `$ref`／`$env` 物件當普通物件，不擋也不穿過——`aos-json set --raw c.json#/r/k 1`（`r` 是 `{"$ref": "lib.json"}`）把 `k` 加在那個物件裡、變成 `{"$ref": "lib.json", "k": 1}`，沒加 `--raw` 是 `FollowMissing`。跟 `--follow` 一起給＝`ArgumentsBad --raw and --follow cannot be used together`。

**`--check`**：寫之前把整份檔（含被 `$ref` 的）用 check 驗一次改完的樣子，**比原本多出問題**才擋（`CheckFailed`，一個都不寫）；原本就有的問題不擋。

**錯**：stderr 一行 `aos-json: error: 代號 原因`、退 1（同 aos-exec，N-60）。代號：`ArgumentsBad`、`FlagUnknown`、`CommandUnknown`、`FileMissing`、`FileBad`（讀不了、資料夾、不是 JSON）、
`SpecBad`、`PointerMissing`、`ValueMissing`、`ValueBad`、`TargetBad`（這個位置不能這樣改）、`KeyExists`（`add`：已有）、`FollowMissing`、`CheckFailed`、`DirectiveBad`（`$ref` 讀不到、指不到、繞圈、合不起來；`--resolve` 的 `$env` 沒設）、`WriteFailed`、`Internal`。
check 印的問題代號：`DirectiveBad`、`DirectiveFormBad`（帶 `$ref`／`$env` 但寫法不合，aos 會原封不動留著）、`ExecBad`。

## 寫回去：原子、只改變的那一塊

- **原子**（N-05）：同資料夾先寫 `.名字.<pid>.tmp`、設回原本的權限、fsync、再 rename 蓋過去；失敗清掉暫存檔。值沒變＝不寫（mtime 不動）。
- **捷徑**：寫到它指的那份檔，捷徑本身留著。**第一行 `#!`** 整行留著。
- **只重寫有變的那一塊**（`src/doc/splice.cpp`）：從根往下找到「只有一個孩子變了」的最深那一層；加一個 key／元素（接在最後，或 `add` 插在陣列中間）或少一個＝只插入或拿掉那一個成員；其他＝只換那一個值的原文。
  原本在一行裡的寫一行（`", "`、`": "`），跨行的照檔的縮排展開（看第一個有縮排的行猜每層幾格）。其他地方一個字都不動，所以 git diff 只有那幾行。
  做不到（變的是整份、物件裡有重複的 key、檔裡有奇怪的寫法）＝整份照猜到的縮排重排。

取捨：新寫進去的那塊是 nlohmann 的排版（多行時每個陣列元素一行）；數字照 nlohmann 印（`1e3` 會變 `1000.0`）、字串裡的 `é` 這種跳脫會變成原字——只發生在被重寫的那一塊。
沒保留：檔的擁有者（rename 換成新檔、擁有者是跑的人）、硬連結（rename 後斷開）。兩個人同時改同一份檔＝後寫的蓋掉先寫的（沒有鎖）。

**好幾個人同時改同一份檔要配 aos-lock**（11-05 第二輪實測：20 個 `aos-json set c.json#/k$i` 同時跑，每輪只剩 1 個 key）：`aos-lock acquire --wait-ms 10000 c.json && aos-json set 'c.json#/k' 1; aos-lock release c.json`，20 個全在。
