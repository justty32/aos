## 給腦用的工具（在 lib）

給腦掛的工具都在 lib，照 lib 的契約走（`tool_io`、`_tooldef.json`、沒設 `AOS_WS`＝`WsMissing`）；它們叫 PATH 上的 `aos-json`。說明在 lib 的索引：

- **json 工具一族**（[thinking json-tools](../../../thinking/2026-11/12/json-tools/README.md)）：程式一份 [`lib/aos_json.py`](../../../lib/aos_json.py)（一次多格的兩支在 [`aos_json_multi.py`](../../../lib/aos_json_multi.py)），十四個資料夾只是殼；路徑一律一整串 `檔#/指標`。
  - 簡單組 `lib/base/json_get`、`json_ls`、`json_search`、`json_len`、`json_set`、`json_add`、`json_del`，加 `json_multi_get`、`json_multi_set`（逐格做、一格一行、不回滾；包 `lib/packs/json.json`）：值照字面；讀叫 `aos-json get／ls／search`，寫叫 `aos-json set／append／add／del --raw`（路上的 `$ref`／`$env` 當普通物件）；ls／search／add 的邏輯在 aos-json 裡，Python 只管參數、上限與把訊息說成參數名。說明在 [lib/docs/02 索引：base](../../../lib/docs/02-索引-base與索引-aos.md#索引base)。
  - 複雜組 `lib/aos/jsonx_get`、`jsonx_ls`、`jsonx_search`、`jsonx_set`、`jsonx_add`、`jsonx_del`，加 `jsonx_multi_get`、`jsonx_multi_set`（包 `lib/packs/jsonx.json`，agent-fsm、eca-claude 範本都掛）：腦明講才帶 `--follow`、`--resolve`、`--check`，值可從 `text`（當 JSON 解）或 `from`（另一格）來。說明在 [lib/docs/02 索引：aos](../../../lib/docs/02-索引-base與索引-aos.md#索引aos)。
  - aos-json 退 1 時接它錯誤行的代號與原因（C-52 例外 ⑤），例 `json_set: error: PointerMissing no such pointer: cfg.json#/a/b (the root has no a; give "parents": true to create objects along the way)`。

## 跟 aos-directive 的分工

`get --resolve` 與 `peek --follow` 指到的 `$ref` 直接交給 aos-directive（`resolve`、`resolve_shallow`），跟 aos-loop、aos-fsm 讀設定檔同一套；最外層的相對 `$ref` 從給的檔所在的資料夾算（沒解開捷徑，同 aos-loop 的 `load_cfg`），`#/…` 取的是值所在的那份檔（交給它 `RefBase{資料夾, 檔}`）。
但改檔要的是「這個值在哪份檔的哪個位置」，aos-directive 的 `resolve` 只回值，所以 `src/follow/` 自己往下走（語意見 [NORMS 指示詞 N-45](../../../docs/NORMS/06-基礎設施-命令列與指示詞.md)）：`$ref` 的字串→位置交給 aos-directive 的 `aos::ref_spot`（`#/…` 沒檔名＝寫著它的那份檔、`#./`、`#../` 都在裡面）；讀檔跳 `#!`、指標取原文、繞圈＝同一個檔＋指標又出現、陣列同名後蓋前仍在 `src/follow/kind.cpp`、`locate.cpp`，aos-directive 改了這幾樣要跟著改。

## 元素

逐檔「哪個檔負責什麼」從檔頭一句話生成，在 code map 的 [逐檔表 impls.json](../../../../wf/knowledge/code-map/proto8/impls.json)（`#/tree/aos-json`）；改說明去改檔頭。

寫入值在 `src/cmd/write.cpp`，`env`／`ref` 在 `src/cmd/ref.cpp`；兩邊共用的編輯狀態與 helper 在 `src/cmd/edit.hpp`、`src/cmd/edit.cpp`。

## 建置與測試

```sh
cmake -B build && cmake --build build
```

依賴 aos-util、aos-directive（`add_subdirectory` 一起編）。
**共用建置**：`aos-json` 列在頂層 `impls/CMakeLists.txt` 的專案清單裡（放在 aos-exec 後面），一次建全部的寫法見 `wf/workflows/testing.md`。
