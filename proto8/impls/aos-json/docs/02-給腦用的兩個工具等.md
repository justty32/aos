## 給腦用的兩個工具（在 lib）

給腦掛的兩個工具 11-06 搬到 lib，照 lib 的契約走（`tool_io`、`_tooldef.json`、沒設 `AOS_WS`＝`WsMissing`）；它們叫 PATH 上的 `aos-json`。說明在 lib 的索引：

- [`lib/aos/aos_json`](../../../lib/aos/aos_json/)：一次一個 aos-json 子命令（peek、get、where、set、batch、del、append、merge、check），寫入帶 `--check --follow`（del 只 `--follow`）。說明在 [lib/docs/02 索引：aos](../../../lib/docs/02-索引-base與索引-aos.md#索引aos)。
- [`lib/agent/json_rewrite`](../../../lib/agent/json_rewrite/)：「小念頭」式兩步改（腦先 peek 找位置、再每個位置給一個新值），腦靠 `AOS_LLM_KERNEL`。說明在 [lib/docs/03 索引：agent](../../../lib/docs/03-索引-agent等.md#索引agent)。

跑一次 json_rewrite（先起 [kernel/llm-kernel](../../../kernel/docs/01-llm-kernel.md)、`AOS_LLM_KERNEL` 指到它的 stack，例 `~/llm_kernel`；`AOS_WS` 一定要設）：
```sh
cd proto8/impls/aos-json && mkdir -p /tmp/ws && cp ../../templates/agent-fsm/fsm.json /tmp/ws/
echo '{"file": "fsm.json", "want": "把 act 那格的逾時改成 30 秒"}' | \
  PATH=$PWD/bin:$PWD/../aos-exec/bin:$PWD/../aos-llm/bin:$PATH AOS_WS=/tmp/ws AOS_STACK=/tmp/ws/ AOS_LLM_KERNEL=~/llm_kernel aos-exec ../../lib/agent/json_rewrite
```

## 跟 aos-directive 的分工

`get --resolve` 與 `peek --follow` 指到的 `$ref` 直接交給 aos-directive（`resolve`、`resolve_shallow`），跟 aos-loop、aos-fsm 讀設定檔同一套；最外層的相對 `$ref` 從給的檔所在的資料夾算（沒解開捷徑，同 aos-loop 的 `load_cfg`）。
但改檔要的是「這個值在哪份檔的哪個位置」，aos-directive 的公開介面只回值，所以 `src/follow/` 照它的規則（語意見 [NORMS 指示詞 N-45](../../../docs/NORMS/06-基礎設施-命令列與指示詞.md)）自己走一遍（寫法寬容、相對路徑從那份檔解開捷徑後的資料夾算、讀檔跳 `#!`、指標取原文、繞圈＝同一個檔＋指標又出現、陣列同名後蓋前）。
**兩份規則要一起改**：aos-directive 改了寫法或語意，`src/follow/kind.cpp`、`locate.cpp` 要跟著改。以後若 aos-directive 公開「取一份 `$ref` 的位置」（例如把 `fetch_ref` 的位置版開出來），這裡就能改用它。

## 元素

逐檔「哪個檔負責什麼」從檔頭一句話生成，在 code map 的 [proto8 生成冊](../../../../wf/workflows/common/code-map/proto8/README.md)（`impls` 冊的 `aos-json/` 段）；改說明去改檔頭。

寫入值在 `src/cmd/write.cpp`，`env`／`ref` 在 `src/cmd/ref.cpp`；兩邊共用的編輯狀態與 helper 在 `src/cmd/edit.hpp`、`src/cmd/edit.cpp`。
