## 用法

### 指示詞

解 JSON 時找出所有帶 `$ref` 或 `$env` 的物件，**整個物件換成它指到的值**；物件裡其餘東西不管。同一物件兩個都寫只看 `$ref`。

| 寫法 | 換成 |
|---|---|
| `{"$ref": "file.json"}` | 那份 JSON 檔的整份內容（第一行 `#!` 跳過），換進來的值接著解 |
| `{"$ref": "file.json#/a/b"}` | 檔內那個位置（JSON pointer，`~1`＝`/`、`~0`＝`~`）；指標取的是檔的原文，取到的值再接著解 |
| `{"$ref": "#/a/b"}` | **寫著這個 `$ref` 的那份檔自己**裡的 `/a/b`（11-12 使用者「話說ref應該支援#/開頭吧」）：那份檔＝相對檔名起點的那份（被 `$ref` 進來的檔裡＝那份檔自己；最外層＝呼叫者給的 `RefBase::file`，命令列＝`--file`）；取原文、接著解、繞圈與指不到同上一列。不知道是哪份檔（`file` 空：stdin 沒給 `--file`、信、行程內的 JSON）＝原封不動留著 |
| `{"$ref": "#/a/b"}`、`{"$ref": "#./b"}`、`{"$ref": "#../c"}`、`{"$ref": "y.json#"}` | **`#` 左邊一律檔案系統、右邊一律 json 內部**（11-13 晚使用者「#作爲json內部尋址的標示」「$ref和index路徑的規則要相同」）：左邊從寫著它的那份檔所在的資料夾算（`./`、`../`、絕對路徑照用）；右邊 `#/a/b`＝本檔根起算（RFC 6901，`..` 不特別、是 key 名）、`#./b`＝所在物件起算、`#../c`＝所在物件上一層起算（可連用，超出根＝`DirectiveBad`）、`#` 與 `#/`＝整份；`y.json#/k`、`y.json#`、`y.json#/` 可。所在物件＝這個 `$ref` 物件所佔的那一格的上一層（`{"a": {"b": {"$ref": "#./x"}}}` 的 `#./x`＝`/a/x`；整份檔就是一個指示詞＝沒有所在物件，`#./`、`#../` 報錯）。`#aaa`、`y.json#aaa`、`y.json#./b`、`y.json#../b`＝`DirectiveBad`；算出來是資料夾＝`DirectiveBad`（讀不到）。「字串→位置」只在 `aos::ref_spot`（aos-json 的 `--follow` 也叫它；index 路徑的 Python 那份 `aos_refpath.spot` 照同一套、跑同一張對照表 `lib/tests/ref_path_cases.json`） |
| `{"$ref": ["a.json", "b.json#/c/d"]}` | **陣列＝幾份照順序合成一份**（10-23 使用者「"$ref":["a.json", "b.json#/c/d]"」）：都是物件＝合 key，同名 key **後面的蓋前面的**（淺層，不往下層合；位置留在第一次出現的地方）；都是陣列＝接起來；種類混在一起＝`DirectiveBad`。每個元素寫法同上幾列（`檔`、`檔#/…`、`#/…`；各自從這一層算相對路徑、各自接著解、各自用 `#/` 指位置）；只有一份＝它本身（不限種類）；兩份以上都是字串、數字…＝合不起來，`DirectiveBad` |
| `{"$env": "NAME"}` | 環境變數的值 |
| 加 `"$path": "子路徑"` | 換出來是字串時**照字串接上去**：子路徑 `#` 開頭＝直接接（`x.json` ＋ `#/a`＝`x.json#/a`）；空字串＝不接；其他＝去掉值結尾的 `/` 與子路徑開頭的 `/`，中間剛好一個 `/`（子路徑是絕對路徑也是接上去：`/s` ＋ `/abs/p`＝`/s/abs/p`） |
| 加 `"$prefix": "--file="` | 換出來是字串時接在前面；先接 `$path` 再加 `$prefix` |

- 換出來不是字串（`$ref` 取到數字、物件…）：`$path`／`$prefix` 靜默不作用。寫 `"path"`（不帶 `$`）是普通 key、不作用。
- 相對檔名：最外層的 `$ref` 從呼叫者給的起點（`RefBase::dir`；命令列＝cwd，給了 `--file` 就是那份檔的資料夾）算；被 `$ref` 進來的檔裡的 `$ref`，從**那個檔解開捷徑後所在的資料夾**算（使用者 2026-10-17 定）。檔名部分可以寫 `./`、`../`（接上起點後整理）；`#` 右邊見上表。
- **錯分兩類**：
  - **真的解不開＝`DirectiveBad`**：環境變數沒設、`$ref` 的檔讀不到（含不是 JSON；**指到資料夾也算讀不到**，不走進去找入口，使用者「維持報錯」）、指標指不到、繞圈（同一個檔＋指標又出現）。
  - **寫法寬容、不報錯**：不認得的 `$xxx`（含 `$fmt`）與其餘 key 不管；`$path`、`$prefix` 不是字串＝當沒寫；
    `$ref`／`$env` 的值不是非空字串、只有 `#/…` 卻不知道是哪份檔＝換不了，**整個物件原封不動留著**（裡面也不解）。`$ref` 的 `#` 右邊寫法不合（`#aaa`、`y.json#./b` 等）＝`DirectiveBad`。
    `$ref` 陣列：空陣列、或有一個元素是上面這些（不是字串、空字串、`#/…` 卻不知道是哪份檔）＝整個物件原封不動（不會只合其中幾份）。
  - `$ref` 陣列的錯：有一份讀不到、指不到＝`DirectiveBad`；繞圈看的是「往上那幾層」——同一個陣列裡寫兩次同一份不算繞圈（物件合起來一樣、陣列接兩次）。
  - `$path`、`$prefix` 作用在合好的那一份：是字串（只會是只有一份時）才接，不是字串靜默不作用（同上）。

### 命令列

```
aos-directive [--file 檔] < 一份 JSON
```

stdin 一份 JSON（規則同全家：空的＝`{}`、多份＝`InputBad`、解不出來＝`InputBad`），以呼叫者的 cwd 為基準解開所有指示詞；
`--file 檔`＝這份 JSON 是從那份檔讀的：相對 `$ref` 從它的資料夾算、`{"$ref": "#/…"}` 取它（沒給＝`#/…` 原封不動），
stdout 印一行解好的 JSON、退出 0；出錯 stderr 一行 `aos-directive: error: 代號 原因`、退出 1（照 [CONVENTION P-44](../../../docs/CONVENTION/02-題目stack停錯腦/07-P-44.md)）。不收位置參數（給了＝`ArgumentsBad`；不認得的 `-` 開頭＝`FlagUnknown`）。

## 公開介面

```cpp
namespace aos {
namespace code { inline constexpr const char* DirectiveBad = "DirectiveBad"; }
// 字串→位置（只看字面、不讀檔）：std::optional<RefSpot{file, pointer}> ref_spot(const std::string& spec, const RefBase& base);
// 相對 $ref 的起點：dir＝相對檔名從哪算；file＝寫著它的那份檔（`#/…` 取它；空＝不知道，`#/…` 原封不動）。
// 字串、路徑可以直接當 RefBase（＝只給資料夾）；轉回字串＝dir。
struct RefBase { std::string dir; std::string file; /* RefBase(dir, file = "")、operator const std::string&() */ };
Json resolve(const Json& doc, const RefBase& base);
}
```

```cpp
namespace aos {
struct Resolved {
    Json value;
    RefBase base_dir;
    std::unordered_map<std::string, RefBase> key_dirs;   // $ref 陣列合物件：key → 它來自的那份檔的起點
    std::vector<RefBase> item_dirs;                      // $ref 陣列接陣列：第 i 個元素 → 它來自的那份檔的起點
    const RefBase& dir_of(const std::string& key) const;   // 沒記＝base_dir
    const RefBase& dir_of(size_t i) const;
};
Resolved resolve_shallow(const Json& v, const RefBase& base);
Resolved resolve_keys(const Json& doc, const RefBase& base, const std::vector<std::string>& keys);
}
```

`Json`、`Error` 來自 [aos-util](../../aos-util/README.md)。`base`＝doc 裡相對 `$ref` 的起點；知道 doc 是從哪份檔讀的就連檔一起給（`RefBase{資料夾, 檔}`），`#/…` 才換得了。
現在給了檔的呼叫者：aos-exec（入口檔、argv 陣列、JSON `.env`）、aos-loop（設定檔、ctl、內嵌單子）、aos-fsm（fsm.json）、aos-daemon（daemon.json、procs_ctl；內嵌單子寫進小格前 `#/…` 補成 `daemon.json#/…`，`abs_refs`）、aos-llm-kernel（kernel.json）。信、stdin 不給。

`resolve_shallow`＝**只換這一格**：`v` 本身是指示詞就換成它指到的值（換來的又是指示詞就再換），**不往物件、陣列裡面走**；回換好的值與「它裡面相對 `$ref` 的起點」
（換過 `$ref`＝最後那份檔解開捷徑後的資料夾與那份檔；沒換或換的是 `$env`＝給的 `base`）。給「只解自己讀的格」的程式用：讀到哪一層就對那一層呼叫一次，讀的 key 的值再交給 `resolve`。
錯與寬容同 `resolve`。`$ref` 陣列合出來的值，每個 key／元素各自來自不同的檔，**往下解某一格時用 `dir_of(key)`／`dir_of(i)` 拿它的起點**（不是 `base_dir`）。

`resolve_keys`＝整份先用 `resolve_shallow` 換一層，再完整解析 `keys` 中有寫的欄位，解析起點用各欄位的 `dir_of(key)`；其他欄位原封不動。回 `Resolved`，保留各欄位的相對路徑起點。

## 建置與測試

```sh
cmake -B build && cmake --build build
python3 -m unittest discover -s tests   # 定向測試（`$ref` 路徑規則＝對照表 `lib/tests/ref_path_cases.json`）
```
