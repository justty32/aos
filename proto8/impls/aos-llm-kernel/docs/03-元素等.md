## 做法

- **一次跑完就結束、不常駐**：節奏、暫停、收工交給拍它的 loop／daemon 的 ctl／state（C-47、C-38「它只是一個排程」）。
- **每封 fork 一個子行程**（`run_inst` 一次只跑一張、會卡住）；環境就是 kernel 自己的（11-04 起不再帶寄信人的環境：金鑰不隨信走、只在 kernel.json）。
- **kernel 不懂腦**：端點、模型、金鑰是 `endpoints` 裡的資料，原樣交給 endpoint 函數；kernel 只看結束碼與回信形狀（C-52）。要換家（Anthropic 原生、llama.cpp）＝再寫一個 endpoint 函數、`exec` 換指。
- **信箱用改名認領、flock 擋第二個 kernel**（N-14：只靠 rename、mkdir、flock）。寄信的撤信（`new/` → `tmp/`）跟 kernel 認領（`new/` → `cur/`）只有一個改得成。

## 錯誤代號

自己出錯：stderr 一行 **`aos-llm-kernel: 代號 原因`**、退 1（N-60）。**一封信的錯不是 kernel 的錯**：寫進那封的回信，aos-llm 印成它自己的一行。

| 代號 | 誰 | 什麼時候 |
|---|---|---|
| `ArgumentsBad`、`FlagUnknown`（共用） | kernel | 沒給／多給設定檔、不認得的旗標 |
| `StackMissing`（共用） | kernel | 沒設 `AOS_STACK` |
| `CfgMissing`、`CfgBad`、`DirectiveBad`（共用） | kernel | kernel.json 不在、指不到；不是物件、`mailbox` 不是非空字串、`slots` 不是正整數、`budget` 形狀不對、`exec` 沒寫或不是非空字串、`endpoints` 沒寫或不是非空物件、`endpoint` 不在表裡、`timeout_ms` 不是非負整數；指示詞解不開 |
| `MkdirFailed`、`WriteFailed`（共用） | kernel | 信箱四格建不了；`queue.json`、回信寫不了、改名不了 |
| `LockFailed` | kernel | 信箱被另一個 kernel 鎖著 |
| `QueueBad` | kernel | `queue.json` 在但讀不懂 |
| `UsedBad` | kernel | `used.json` 在但讀不懂 |
| `LetterBad` | 回信 | `letter.json` 讀不懂、`body` 不是物件、沒有 `body.request`（含頂層 `inst`／`env` 的舊信）、`body.endpoint` 不是字串、priority 壞 |
| `RequestBad` | 回信 | `body.request` 不是物件、`messages` 不是陣列、`stream` 寫真 |
| `EndpointMissing` | 回信 | 信沒寫 `endpoint`、kernel.json 也沒寫預設 |
| `EndpointUnknown` | 回信 | 信寫的代號不在 `endpoints` 表裡 |
| `DirectiveBad`、`CfgBad` | 回信 | 那組的指示詞解不開（環境變數沒設、檔讀不到）；那組不是物件、那組的 `exec` 不是非空字串 |
| `DeadlineMissed` | 回信 | 輪到之前時限已過，沒跑 |
| `BudgetMissing` | 回信 | 這一窗的額度用完了（`spent` 是 `refuse`），沒跑 |
| `EndpointFailed` | 回信 | endpoint 函數退非 0（含逾時、訊號；msg 帶它 stderr 的第一行）、或起不來 |
| `ReplyBad` | 回信 | endpoint 函數退 0 但 stdout 不是 `{"message": 物件, …}` |
| `RunFailed` | 回信 | 上一次 kernel 跑到一半死了、沒回信；跑信的子行程沒寫回信就結束了 |
| `Internal` | 回信 | 照理不會發生的例外 |
