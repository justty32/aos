## 元素

```
 main ──▶ block_signals ──▶ parse_cli ──▶ 要 AOS_STACK ──▶ read_cfg ──▶ serve：建信箱 → find_host → lock → read_used → read_table → 寫窗 endpoints.json → collect（settle：收成品／重掛）→ sweep → scan（pick：查代號、解那組、讀包、擋撞到 fixed 的）→ order → （spent？回錯／停）認領＋寫 request.json＋mount（寄掛信、寫 proc.json）→ write_queue
                                                                                                      finish：寫 reply.json、post_reply、regret_reply、add_used、整封刪
```

每輪骨架在 `src/serve/serve.cpp`，設定解析在 `config.cpp`，回信在 `reply.cpp`，問腦 proc 的掛載與收尾在 `proc.cpp`，排隊信件檢查在 `scan.cpp`；共用的 `Server` 宣告與分工入口在 [`src/serve/serve.hpp`](../src/serve/serve.hpp)。

逐檔「哪個檔負責什麼」從檔頭一句話生成，在 code map 的 [proto8 生成冊](../../../../wf/workflows/common/code-map/proto8/README.md)（`impls` 冊的 `aos-llm-kernel/` 段）；改說明去改檔頭。

## 做法

- **一次跑完就結束、不常駐**：節奏、暫停、收工交給拍它的 daemon（C-47、C-38「它只是一個排程」）；一般就是那台 daemon 的身體（[kernel/llm-kernel](../../../kernel/docs/01-llm-kernel.md)）。
- **問腦請 daemon 掛、kernel 不等**（11-05 使用者「問腦，他本身也可以包裝成一個aos函數，掛成proc去跑」「能包盡量包啦」）：一封＝一列 `llm_<信件名稱>`，`aos-daemon-ctl ls` 看得到；kernel 只寄信、讀窗（C-52）。
- **kernel 不懂腦**：端點、模型、金鑰是 `endpoints` 裡的資料，原樣交給 endpoint 函數；kernel 只看結束碼與回信形狀（C-52）。要換家（Anthropic 原生、llama.cpp）＝再寫一個 endpoint 函數、`exec` 換指。
- **信箱用改名認領、flock 擋第二個 kernel**（N-14：只靠 rename、mkdir、flock）。寄信的撤信（`new/` → `tmp/`）跟 kernel 認領（`new/` → `cur/`）只有一個改得成。

## 錯誤代號

自己出錯：stderr 一行 **`aos-llm-kernel: error: 代號 原因`**、退 1（N-60）。**一封信的錯不是 kernel 的錯**：寫進那封的回信，aos-llm 印成它自己的一行。

| 代號 | 誰 | 什麼時候 |
|---|---|---|
| `ArgumentsBad`、`FlagUnknown`（共用） | kernel | 沒給／多給設定檔、不認得的旗標 |
| `StackMissing`（共用） | kernel | 沒設 `AOS_STACK` |
| `DaemonMissing` | kernel | 沒設 `AOS_DAEMON`、指的不是資料夾（kernel 要住在 daemon 底下） |
| `MailboxMissing`（共用） | kernel | 沒設 `AOS_KERNEL`、而 `$AOS_DAEMON` 那台沒開 ctl 信箱（`procs_ctl_mailbox` 是 null） |
| `CfgMissing`、`CfgBad`、`DirectiveBad`（共用） | kernel | kernel.json 不在、指不到；不是物件、`slots`／`aging_ticks` 不是正整數、`budget` 形狀不對（含 `senders` 不是物件、一格不是 `{"max_calls", "max_tokens"}`、兩個 key 算出同一個寄件人）、`exec` 沒寫或不是非空字串、`endpoints` 沒寫或不是非空物件、`endpoint` 不在表裡、`timeout_ms` 不是非負整數；指示詞解不開 |
| `MkdirFailed`、`WriteFailed`（共用） | kernel | 信箱三格建不了；`queue.json`、`endpoints.json`、回信寫不了、改名不了 |
| `LockFailed` | kernel | 信箱被另一個 kernel 鎖著 |
| `QueueBad` | kernel | `queue.json` 在但讀不懂 |
| `UsedBad` | kernel | `used.json` 在但讀不懂 |
| `LetterBad` | 回信 | `letter.json` 讀不懂、`body` 不是物件、沒有 `body.request`、`body.endpoint` 不是字串、priority 壞 |
| `RequestBad` | 回信 | `body.request` 不是物件、`messages` 不是陣列、`stream` 寫真；request 寫了那組 `fixed` 裡的 key、或那組有 `model` 而 request 寫了 `model`（`temperature is fixed by endpoint smart-high …`） |
| `EndpointMissing` | 回信 | 信沒寫 `endpoint`、kernel.json 也沒寫預設 |
| `EndpointUnknown` | 回信 | 信寫的代號不在 `endpoints` 表裡 |
| `DirectiveBad`、`CfgBad` | 回信 | 那組的指示詞解不開（環境變數沒設、檔讀不到）；那組不是物件、那組的 `exec` 不是非空字串、`slots` 不是正整數、`budget` 不是 `{"max_calls", "max_tokens"}`（寫了 `window`／`spent` 也算）、`speed` 不是 `fast`／`normal`／`slow`、`fixed` 不是物件 |
| `DeadlineBad` | 回信 | 輪到之前時限已過，沒跑 |
| `BudgetMissing` | 回信 | 這一窗的額度用完了（`spent` 是 `refuse`），沒跑；那包的 `budget` 到頂＝msg 開頭 `endpoint <代號>: max_calls N reached …`（不降級換包）；寄件人的到頂＝`sender <寄件人>: max_calls N reached …` |
| `LaunchFailed`（共用） | 回信 | 掛不上 daemon：掛信寄不進（含重掛時）、或 daemon 的 `mailbox_warning` 說不收這封掛信 |
| `EndpointFailed` | 回信 | endpoint 函數退非 0（msg 帶 `reply.json` 或 `stderr.txt` 的第一行）、逾時、問腦跑了兩次都沒結果（被收掉或死在半路） |
| `ReplyBad` | 回信 | endpoint 函數退 0 但 stdout 不是 `{"message": 物件, …}` |
| `Internal` | 回信 | 照理不會發生的例外 |
