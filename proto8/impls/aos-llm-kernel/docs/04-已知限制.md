## 已知限制

- **token 靠 endpoint 函數照實寫 `usage`**：沒寫（或寫錯）就只算次數，`max_tokens` 額度看不到它；數字 kernel 不驗。
- **token 額度事後才知道**：跑之前不知道這封會吃多少，所以會超過一點（見 [02](02-token-回報與額度.md)「到頂怎麼判」）。
- **窗用本地時間**：kernel 的 `TZ` 換了、或日光節約，`since` 會變＝當成換窗歸零一次。`wait` 配 `window: "all"`＝到頂後永遠等（直到有人改 kernel.json 或刪 `used.json`）。
- 一次裡不補位：`slots` 2、一封 1 秒一封 10 秒，那一格空等 9 秒；新來的高優先信也要等這一次結束。
- kernel 整群被 SIGKILL：跑信的子行程跟著死，但 endpoint 函數自成行程群組、可能還在跑；下一次回 `RunFailed`（`reply.json` 還沒寫完整時），函數實際跑了一半或跑完沒人收。
- **endpoint 函數的 stdout 就寫在 `reply.json`**：函數退 0 寫好了、子行程還沒驗完 kernel 就死，下一次接手照那份當回信（讀得懂才算）。
- **信處理完就刪、kernel 這邊不留紀錄**（11-04 夜使用者「舊信根本不用留，就是刪」，[think-as-function 08 題 3](../../../thinking/2026-11/04/think-as-function/08-邊緣狀況實測.md#留給你的題白話推薦放第一)）：事後要查請求原文看 agent 自己的 history；11-05 起連每封一行的 `served.jsonl` 也不寫（使用者選「也刪」），kernel 這邊只剩 `used.json` 的總數。寄完被刪掉的 agent 那封照跑、回信寄不進（kernel 的 stderr 印一行），信照刪，[think-as-function 04 #6](../../../thinking/2026-11/04/think-as-function/04-邊緣狀況.md)。
- 寄回信跟刪信之間 kernel 死掉（`reply_letter.txt` 還沒寫成）：下一次接手會再寄一封，收信的只拿第一封，第二封留在回信信箱的 `new/`。
- `ask` 被打斷、而 kernel 寄回信前一刻它還沒走完（`sender.flock` 還鎖著）：那封回信沒人撤、留在 `$AOS_LLM_KERNEL/reply/new/`（窄縫，以前靠 `done/` 事後撤）。
- **`request.json` 跑的期間含金鑰**（那組的 `key` 解好了）：跑完就刪，但跑的期間讀得到信箱的人看得到——信箱放 kernel 自己的 stack 裡、照 Linux 權限管。
- **寄信的人是誰 kernel 不驗**：`sender.flock` 只說「人還在」、不是身分，信封的 `sender` 也不看；寫得到信箱的程式就能用 kernel 的額度問 kernel 登記過的腦（但改不了 url／key、也不能叫 kernel 跑別的程式）。
- **共用信箱看得到別人的信**：寫得到信箱就讀得到別封信（請求內容）與回信；要分開就分信箱、分群組（Linux 權限）。kernel 自己建的信箱照 umask（多半 755），跨帳號用照 `setup.sh --mailbox` 先建好。
- 沒有每個寄件人的配額（10-15「濫用：先信任」）；`class` 不看。
