## 用法

```
aos-llm-kernel [FLAGS] kernel.json
```

- **命令列**：唯一的位置參數＝設定檔（可寫 `檔#/指標`，aos-util 的 `load_cfg`）；目前沒有旗標（不認得＝`FlagUnknown`、沒給或多給＝`ArgumentsBad`）。
- **kernel.json**（[thinking 11-04 think-as-function 02 § 3](../../../thinking/2026-11/04/think-as-function/02-設計-信與kernel.md)、[11-05 kernel-daemon 03 § 6](../../../thinking/2026-11/05/kernel-daemon/03-問腦改掛daemon.md)）：
  - `slots`：同時**在飛**幾封（掛出去還沒收的，跨次計數），正整數；沒寫＝1。`budget`：額度（見 [02](02-token-回報與額度.md)「token 與額度」）；沒寫＝不限、只記帳。
  - **`exec`**（必填）：預設的 endpoint 函數＝aos-exec 的目標（資料夾、檔、`檔#/指標`）。相對路徑從 **kernel 定義資料夾**（kernel.json 所在；aos-exec 跑 kernel 時＝kernel 的 cwd，N-59）算，kernel 轉成絕對再寫進掛信（問腦 proc 在信的資料夾裡跑）。整份定義 `cp` 到別處時，相對路徑要跟著對（範本的 `../../lib/base/…` 只在 repo 裡對）。
  - **`endpoints`**（必填、非空物件）：**代號 → 一組 llm 設定＝一個能力包**（11-05 使用者「把endpoint打包成smart-high, stupid-fast, ...這類，並且附上各種屬性(各種temperature也固定)」，[feat-proto 02](../../../thinking/2026-11/05/feat-proto/02-endpoint-packs.md)）。代號就是能力名（`smart-high`、`stupid-fast`…），信只寫代號。一組＝一層物件，全選填（除了 endpoint 函數要的 `url`＋`model`，或 `exec`）：
    ```json
    {"url": "...", "model": "...", "key": {"$env": "..."}, "exec": "...",
     "fixed": {"temperature": 0.2, "top_p": 1, "max_tokens": 4096},
     "slots": 1, "budget": {"max_calls": 200, "max_tokens": 2000000},
     "speed": "fast", "cost": "high", "context": 200000, "summary": "one line for people and brains"}
    ```
    - **kernel 看的四個**（拿掉後才交給 endpoint 函數）：`exec`（這組改用別的 endpoint 函數，相對路徑同上）、`slots`（這包同時幾封在飛，正整數；沒寫＝只受 kernel 總 `slots` 限）、`budget`（這包每窗上限 `{"max_calls", "max_tokens"}`，非負整數；窗與 `spent` 用 kernel 的 `budget`，這裡寫 `window`／`spent`＝`CfgBad`）、`speed`（`"fast"`／`"normal"`／`"slow"`，排序用；沒寫＝`normal`）。排程怎麼用它們見 [02](02-token-回報與額度.md)「一次」。形狀不對＝那組的信回 `CfgBad`。
    - **交給函數的**：其他鍵（`url`／`model`／`key`／`fixed`／`cost`／`context`／`summary`／`script`…）**整個原樣**放進 `request.json` 的 `endpoint`。`fixed`＝包**釘死**的請求參數（要是物件，不然 `CfgBad`）；怎麼蓋上請求是函數的事（`llm_http`：request 先、`fixed` 蓋上、`model` 用包的）。`cost`／`context`／`summary` 函數不看，只進窗 `endpoints.json`。
    - **釘死的不給信蓋**（C-56 寫什麼就做什麼）：信的 `request` 寫了 `fixed` 裡有的 key、或那組有 `model` 而 `request` 寫了 `model`＝那封回 `RequestBad`（`temperature is fixed by endpoint smart-high (remove it from the request; to change it pick another endpoint name)`）。換參數、換模型＝換代號。沒 `fixed`、沒 `model` 的組（`fake`）照舊全收。
    整張表可以 `{"$ref": "endpoints.json"}` 拆出去，一組也可以 `"smart-high": {"$ref": "packs/smart-high.json"}`（整份檔＝不寫指標；`#/` 是 RFC 6901 的「key 為空字串」、不是整份）；每組裡的指示詞（`{"$env": "LITELLM_KEY"}`＝kernel 自己殼裡的變數、`{"$ref": "/home/me/.secrets/llm.json#/key"}`）**用到那組時才解**，解不開＝那封信回 `DirectiveBad`、kernel 照跑別封。
  - `endpoint`（選填）：預設代號（信沒寫 `endpoint` 時用）；寫了但表裡沒有＝`CfgBad`。
  - `timeout_ms`（選填，非負整數）：問腦的上限（寫進問腦單子的 `timeout_ms`，逾時 daemon 那邊整群收）；沒寫＝不限。
  - 其他 key 忽略（`_entry`…）。
  - 指示詞：`slots`、`budget`、`exec`、`endpoint`、`timeout_ms` 整格先解，`endpoints` 先換一層；解不開 `DirectiveBad`。
- **環境**（kernel 要住在 daemon 底下：問腦是請 daemon 掛 proc）：
  - **`AOS_DAEMON`**（必要）：哪台 daemon 掛問腦 proc＝那台的 stack。kernel 當 daemon 的身體或子項時 daemon 會自己設好（[aos-daemon docs/05](../../aos-daemon/docs/05-信箱.md)）；沒設、不是資料夾＝`DaemonMissing`、退 1。
  - `AOS_KERNEL`（選填，N-63）：有設＝掛信寄這個信箱；沒設＝寄 `$AOS_DAEMON` 的 ctl 信箱（`procs_state.json` 回報的 `procs_ctl_mailbox`；那台沒開 ctl 信箱＝`MailboxMissing`、退 1）。
- **`$AOS_STACK`**（必要）：kernel 自己的檔（計數的 key 一律 `counter_*`）——
  - `mailbox/`：信箱，**位置固定**（寄信的人手上只有 stack：`AOS_LLM_KERNEL`＝kernel 的 stack、信箱＝`$AOS_LLM_KERNEL/mailbox/`，[kernel-daemon 07 § 2](../../../thinking/2026-11/05/kernel-daemon/07-llm-daemon佈局.md)）。
  - `queue.json`：`{"counter_runs": kernel 跑過幾次, "seen_at_runs": {信件名稱: 第一次看到它是第幾次}}`（只留還在排的；先寫暫存再改名）。在但讀不懂＝`QueueBad`（刪掉就從頭算）。
  - `used.json`：用量帳（見 [02](02-token-回報與額度.md)；含每包的 `packs`）。在但讀不懂＝`UsedBad`（刪掉就從 0 算）。
  - **`endpoints.json`**（窗，11-05 feat-proto）：包的屬性表，給人與 `aos-llm ls` 挑代號。每次跑都照 kernel.json 算一份，跟現有的不同才寫（暫存改名，N-05）。形狀＝`{代號: {"speed", "cost"?, "context"?, "slots"?, "summary"?}}`——`speed` 一定有（沒寫＝`"normal"`），其他四個照 kernel.json 有寫才有、值原樣；**不含** `url`／`key`／`fixed`／`exec`／`budget`。那組解不開或壞了＝`{代號: {"error": "代號 原因"}}`（例：`{"error": "CfgBad kernel.json endpoints.x.speed must be \"fast\", \"normal\" or \"slow\", got \"warp\""}`）。只解這幾格的指示詞（`key` 的 `$env` 沒設不影響窗）。
  - 不寫每封信的紀錄（使用者 11-04 夜「舊信根本不用留，就是刪」、11-05 選「也刪」，[think-as-function 08 題 3](../../../thinking/2026-11/04/think-as-function/08-邊緣狀況實測.md#留給你的題白話推薦放第一)）。
- **信箱**（N-16 資料夾式）：`tmp/`、`new/`、`cur/` 三格，一封信＝一個資料夾 `<信件名稱>/`（`new/`、`cur/` 裡混進來的一般檔不理，11-05）；kernel 每次先建好三格（建不了 `MkdirFailed`），`.flock` 用 flock 鎖住整次（另一個 kernel 鎖著＝`LockFailed`）。`aos-llm ask` 的共用回信信箱在 `mailbox/reply/`。
  信件名稱＝aos-post 的預設名 `<UTC 奈秒 20 位>.<pid>.<started_at_ticks>`：字典序＝寄的先後。
  `cur/<信件名稱>/`＝認領了、請 daemon 掛成問腦 proc：裡面有 `request.json`、`proc.json`（kernel 寫）、`loop.json`／`state.json`／`stderr.txt`（daemon 寫）、`reply.json`（endpoint 函數寫）。
  **寄信的人還在不在＝信裡的 `sender.flock` 有沒有人鎖著**（[thinking sandbox S15](../../../thinking/2026-10/24/sandbox/README.md)）：只有 `aos-llm ask`（同步）會建、拿到行程結束；kernel 試著拿共享鎖（不等），拿得到、開不了＝人不在。
  **沒有 `sender.flock` 的信（`aos-llm send`、`aos-post send` 寄的非同步信）不判存活、照跑**（[think-as-function 衝突 2 (a)](../../../thinking/2026-11/04/think-as-function/05-衝突與方向題.md)）。
- **信**（`letter.json`，N-16 的信，aos-post／aos-llm 寫）：信封 `sender`、`sent_at`、`reply_to`（kernel 不檢查也不擋；沒寫 `reply_to`＝回信沒人收得到，信照刪），`body`＝
  `{"endpoint"?: 代號, "request": OpenAI chat completions 的 body 去掉端點, "priority"?}`。
  - `request`：`messages` 必有（陣列）；`tools`、`temperature`… 選填、原樣交給 endpoint 函數；撞到那組釘死的（`fixed` 裡的 key、那組有 `model` 時的 `model`）＝`RequestBad`；`stream` 寫真＝`RequestBad`（串流不做）。
  - `endpoint`：代號字串；沒寫＝kernel.json 的 `endpoint`；兩邊都沒寫＝`EndpointMissing`；表裡沒有＝`EndpointUnknown`。信改不了 `url`／`key`（只能選代號）。
  - **priority**：沒寫＝normal；`"low"`／`"normal"`／`"high"`；數字看正負；物件 `{"level", "deadline", 其他 key 照帶不管}`；`deadline`＝帶時區的 ISO 8601 或 epoch 秒（沒時區不猜＝壞）。排隊依據只從 `priority_of` 讀。
  - 沒有 `body.request`＝`LetterBad`。其他不認得的 key 忽略（C-48）。
- **回信**（`reply.json`）：endpoint 函數 stdout 那份 `{"message": {...}, "usage"?, "model"?}`，或 `{"error": {"code", "msg"}}`（沒跑、掛不上 daemon、函數退非 0 或逾時、stdout 讀不懂）。
  信封寫了 `reply_to`：另把同一份當 `body`、照 [N-16](../../../docs/NORMS/05-基礎設施-窗/05-N-16.md) 寄一封回信進那個信箱（aos-post 的庫；相對的 `reply_to` 從 kernel 信箱的根拼回、絕對的照用，見 [aos-post](../../aos-post/docs/01-用法與元素.md)；`in_reply_to`＝原信的信件名稱、`sender`＝kernel 自己的身分；不附檔），寄出的信件名稱記在 `<信>/reply_letter.txt`（已經有＝寄過了、不寄第二封）。**寄完就整封刪掉**（`cur/<信件名稱>/` 整個資料夾；沒有 `done/`）（11-04 夜使用者「舊信根本不用留，就是刪」）。
  寄不出去（信箱不在、寫不進）不是 kernel 的錯：kernel 的 stderr 印一行 `aos-llm-kernel: <代號> <原因> (cannot send the reply to letter <信件名稱>; letter deleted anyway)`、不退，信照刪（寄信的人自己承擔）。有 `sender.flock` 而寄完回信時寄信的人已經不在了（`ask` 被打斷）：那封回信還在對方 `new/`（沒人拿）就馬上撤回。
