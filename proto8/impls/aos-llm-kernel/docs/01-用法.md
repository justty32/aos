## 用法

```
aos-llm-kernel [旗標] kernel.json
```

- **命令列**：唯一的位置參數＝設定檔（可寫 `檔#/指標`，aos-util 的 `load_cfg`）；目前沒有旗標（不認得＝`FlagUnknown`、沒給或多給＝`ArgumentsBad`）。
- **kernel.json**（[thinking 11-04 think-as-function 02 § 3](../../../thinking/2026-11/04/think-as-function/02-設計-信與kernel.md)）：
  - `mailbox`：信箱資料夾；相對的從 `$AOS_STACK` 算（N-14 窗落在 `$AOS_STACK` 底下）；沒寫＝`mailbox`。
  - `slots`：同時跑幾封，正整數；沒寫＝1。`budget`：額度（見 [02](02-token-回報與額度.md)「token 與額度」）；沒寫＝不限、只記帳。
  - **`exec`**（必填）：預設的 endpoint 函數＝aos-exec 的目標（資料夾、檔、`檔#/指標`）。相對路徑從 **kernel 定義資料夾**（kernel.json 所在；aos-exec 跑 kernel 時＝kernel 的 cwd，N-59）算，kernel 轉成絕對再交給 aos-exec（aos-exec 是在信的資料夾裡跑的）。
  - **`endpoints`**（必填、非空物件）：**代號 → 一組 llm 設定**。一組＝一層物件，kernel 只認裡面的 `exec`（選填：這組改用別的 endpoint 函數，相對路徑同上），其他鍵（`url`／`model`／`key`／`body`…，是 endpoint 函數認的）**整個原樣**交給 endpoint 函數。
    整張表可以 `{"$ref": "endpoints.json#/"}` 拆出去；每組裡的指示詞（`{"$env": "LITELLM_KEY"}`＝kernel 自己殼裡的變數、`{"$ref": "/home/me/.secrets/llm.json#/key"}`）**用到那組時才解**，解不開＝那封信回 `DirectiveBad`、kernel 照跑別封。
  - `endpoint`（選填）：預設代號（信沒寫 `endpoint` 時用）；寫了但表裡沒有＝`CfgBad`。
  - `timeout_ms`（選填，非負整數）：跑 endpoint 函數的上限（寫進那張單子的 `timeout_ms`，逾時整群收）；沒寫＝不限。
  - 其他 key 忽略（`_entry`…）。11-04 起 **`accept` 拿掉**（它擋的是「別人塞單子」，信裡沒單子就沒這題；寫了也不管）。
  - 指示詞：`mailbox`、`slots`、`budget`、`exec`、`endpoint`、`timeout_ms` 整格先解，`endpoints` 先換一層；解不開 `DirectiveBad`。
- **`$AOS_STACK`**（必要）：kernel 自己的兩個檔（計數的 key 一律 `counter_*`）——
  - `queue.json`：`{"counter_runs": kernel 跑過幾次, "seen_at_runs": {信件名稱: 第一次看到它是第幾次}}`（只留還在排的；先寫暫存再改名）。在但讀不懂＝`QueueBad`（刪掉就從頭算）。
  - 11-05 起**不寫 `served.jsonl`**（原本每封信一行代號／模型／用量；使用者 11-05 選「也刪」，延續「舊信根本不用留，就是刪」，[think-as-function 08 題 3](../../../thinking/2026-11/04/think-as-function/08-邊緣狀況實測.md#留給你的題白話推薦放第一)）。舊 kernel 留下的 `served.jsonl` 不讀、不刪，要清自己刪。
  - `used.json`：用量帳（見 [02](02-token-回報與額度.md)）。在但讀不懂＝`UsedBad`（刪掉就從 0 算）。
- **信箱**（N-16 資料夾式）：`tmp/`、`new/`、`cur/` 三格，一封信＝一個資料夾 `<信件名稱>/`；kernel 每次先建好三格（建不了 `MkdirFailed`），`.flock` 用 flock 鎖住整次（另一個 kernel 鎖著＝`LockFailed`）。
  信件名稱＝aos-post 的預設名 `<UTC 奈秒 20 位>.<pid>.<started_at_ticks>`：字典序＝寄的先後。
  **寄信的人還在不在＝信裡的 `sender.flock` 有沒有人鎖著**（[thinking sandbox S15](../../../thinking/2026-10/24/sandbox/README.md)）：只有 `aos-llm ask`（同步）會建、拿到行程結束；kernel 試著拿共享鎖（不等），拿得到、開不了＝人不在。
  **沒有 `sender.flock` 的信（`aos-llm send`、`aos-post send` 寄的非同步信）不判存活、照跑**（[think-as-function 衝突 2 (a)](../../../thinking/2026-11/04/think-as-function/05-衝突與方向題.md)）。
- **信**（`letter.json`，N-16 的信，aos-post／aos-llm 寫）：信封 `sender`、`sent_at`、`reply_to`（kernel 不檢查也不擋；沒寫 `reply_to`＝回信沒人收得到，信照刪），`body`＝
  `{"endpoint"?: 代號, "request": OpenAI chat completions 的 body 去掉端點, "priority"?}`。
  - `request`：`messages` 必有（陣列）；`tools`、`temperature`、`model`… 選填、原樣交給 endpoint 函數（怎麼疊那組的預設是它的事）；`stream` 寫真＝`RequestBad`（串流不做）。
  - `endpoint`：代號字串；沒寫＝kernel.json 的 `endpoint`；兩邊都沒寫＝`EndpointMissing`；表裡沒有＝`EndpointUnknown`。信改不了 `url`／`key`（只能選代號）。
  - **priority**：沒寫＝normal；`"low"`／`"normal"`／`"high"`；數字看正負；物件 `{"level", "deadline", 其他 key 照帶不管}`；`deadline`＝帶時區的 ISO 8601 或 epoch 秒（沒時區不猜＝壞）。排隊依據只從 `priority_of` 讀（11-04 起 `_metainfo` 的兩個依據拿掉：信裡沒單子）。
  - 頂層 `inst`／`env` 的舊閘門信不再認＝`LetterBad`（不留兩種信，[04 #20](../../../thinking/2026-11/04/think-as-function/04-邊緣狀況.md)）。其他不認得的 key 忽略（C-48）。
- **回信**（`reply.json`）：endpoint 函數 stdout 那份 `{"message": {...}, "usage"?, "model"?}`，或 `{"error": {"code", "msg"}}`（沒跑、跑不起來、函數退非 0、stdout 讀不懂）。
  信封寫了 `reply_to`：另把同一份當 `body`、照 [N-16](../../../docs/NORMS/05-基礎設施-窗/05-N-16.md) 寄一封回信進那個信箱（aos-post 的庫；相對的 `reply_to` 從 kernel 信箱的根拼回、絕對的照用，見 [aos-post](../../aos-post/docs/01-用法與元素.md)；`in_reply_to`＝原信的信件名稱、`sender`＝kernel 自己的身分；不附檔），寄出的信件名稱記在 `<信>/reply_letter.txt`（已經有＝寄過了、不寄第二封）。**寄完就整封刪掉**（`cur/<信件名稱>/` 連 `reply.json`、`stderr.txt`；沒有 `done/`，舊 kernel 留下的 `done/` 下一次整個刪）（11-04 夜使用者「舊信根本不用留，就是刪」，[think-as-function 08 題 3](../../../thinking/2026-11/04/think-as-function/08-邊緣狀況實測.md#留給你的題白話推薦放第一)）。
  寄不出去（信箱不在、寫不進）不是 kernel 的錯：kernel 的 stderr 印一行 `aos-llm-kernel: 代號 原因（信 <信件名稱> 的回信寄不出去，信照刪）`、不退（11-05 前記在 served 的 `reply_error`），信照刪（寄信的人自己承擔）。有 `sender.flock` 而寄完回信時寄信的人已經不在了（`ask` 被打斷）：那封回信還在對方 `new/`（沒人拿）就馬上撤回。
