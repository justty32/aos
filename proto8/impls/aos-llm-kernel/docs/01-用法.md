## 用法

```
aos-llm-kernel [FLAGS] kernel.json
```

- **命令列**：唯一的位置參數＝設定檔（可寫 `檔#/指標`，aos-util 的 `load_cfg`）；目前沒有旗標（不認得＝`FlagUnknown`、沒給或多給＝`ArgumentsBad`）。
- **kernel.json**（[thinking 11-04 think-as-function 02 § 3](../../../thinking/2026-11/04/think-as-function/02-設計-信與kernel.md)、[11-05 kernel-daemon 03 § 6](../../../thinking/2026-11/05/kernel-daemon/03-問腦改掛daemon.md)）：
  - `slots`：同時**在飛**幾封（掛出去還沒收的，跨次計數），正整數；沒寫＝1。`budget`：額度（見 [02](02-token-回報與額度.md)「token 與額度」；含每個寄件人的 `senders`）；沒寫＝不限、只記帳。
  - `reserved`（頂層選填）：`{"high": N}` 留 N 格給宣告優先序達 high 的信；只認 `high`，N 必須是非負整數且小於頂層 `slots`，否則 `CfgBad`。沒寫、`{}`、`{"high": 0}` 都不保留；`slots: 1` 只能保留 0 格。這是 kernel 總格數的保留，不放在端點包內。低於 `priority_of` 的 high level 的信，只在總在飛數小於 `slots-N` 時補位；判定看宣告 level，不含 aging，等久升級也不能佔保留格。遇到這種信先跳過，後面的 high 仍可補位。
  - `aging_ticks`（選填，正整數，預設 3）：排隊每等這麼多格升一級，不封頂；不是正整數＝`CfgBad`。有 `AOS_TICK` 數 kernel 自己樹的時鐘格，沒有則用 `AOS_TICK_INTERVAL`（正整數毫秒，沒設或空字串＝1000）換牆鐘；凍住時鐘＝不升級。
  - **`exec`**（必填）：預設的 endpoint 函數＝aos-exec 的目標（資料夾、檔、`檔#/指標`）。相對路徑從 **kernel 定義資料夾**（kernel.json 所在；aos-exec 跑 kernel 時＝kernel 的 cwd，N-59）算，kernel 轉成絕對再寫進掛信（問腦 proc 在信的資料夾裡跑）。整份定義 `cp` 到別處時，相對路徑要跟著對（範本的 `../../lib/base/…` 只在 repo 裡對）。
  - **`endpoints`**（必填、非空物件）：**代號 → 一組 llm 設定＝一個能力包**（11-05 使用者「把endpoint打包成smart-high, stupid-fast, ...這類，並且附上各種屬性(各種temperature也固定)」，[feat-proto 02](../../../thinking/2026-11/05/feat-proto/02-endpoint-packs.md)）。代號就是能力名（`smart-high`、`stupid-fast`…），信只寫代號。一組＝一層物件，全選填（除了 endpoint 函數要的 `url`＋`model`，或 `exec`）：
    ```json
    {"url": "...", "model": "...", "exec": "endpoints/litellm",
     "fixed": {"temperature": 0.2, "top_p": 1, "max_tokens": 4096},
     "slots": 1, "budget": {"max_calls": 200, "max_tokens": 2000000},
     "speed": "fast", "cost": "high", "context": 200000, "summary": "one line for people and brains"}
    ```
    - **kernel 看的四個**（拿掉後才交給 endpoint 函數）：`exec`（這組改用別的 endpoint 函數，相對路徑同上）、`slots`（這包同時幾封在飛，正整數；沒寫＝只受 kernel 總 `slots` 限）、`budget`（這包每窗上限 `{"max_calls", "max_tokens"}`，非負整數；窗與 `spent` 用 kernel 的 `budget`，這裡寫 `window`／`spent`＝`CfgBad`）、`speed`（`"fast"`／`"normal"`／`"slow"`，排序用；沒寫＝`normal`）。排程怎麼用它們見 [02](02-token-回報與額度.md)「一次」。形狀不對＝那組的信回 `CfgBad`。
    - **交給函數的**：其他鍵（`url`／`model`／`fixed`／`cost`／`context`／`summary`／`script`…）**整個原樣**放進 `request.json` 的 `endpoint`。`fixed`＝包**釘死**的請求參數（要是物件，不然 `CfgBad`）；怎麼蓋上請求是函數的事（`llm_http`：request 先、`fixed` 蓋上、`model` 用包的）。`cost`／`context`／`summary` 函數不看，只進窗 `endpoints.json`。
    - **金鑰歸 endpoint 小 proc**：包裡不放金鑰，只用 `exec` 指端點自己的小定義；範本三個 LiteLLM 包指 `endpoints/litellm`，其 `_entry` 寫 `{"argv": ["aos-exec", "../../../../lib/base/llm_http", "--key-env", "LITELLM_KEY"]}`。變數名在小定義裡，值由小 proc 從自己的環境讀，kernel 不讀、不寫、不轉交；`url`、`model` 留在包裡。`llm_http` 沒設指定變數＝`EndpointFailed`，stdin 的 `endpoint` 帶 `key`＝`ArgumentsBad`；沒給 `--key-env` 就不帶 Authorization。
    - **釘死的不給信蓋**（C-56 寫什麼就做什麼）：信的 `request` 寫了 `fixed` 裡有的 key、或那組有 `model` 而 `request` 寫了 `model`＝那封回 `RequestBad`（`temperature is fixed by endpoint smart-high (remove it from the request; to change it pick another endpoint name)`）。換參數、換模型＝換代號。沒 `fixed`、沒 `model` 的組（`fake`）照舊全收。
    整張表可以 `{"$ref": "endpoints.json"}` 拆出去，一組也可以 `"smart-high": {"$ref": "packs/smart-high.json"}`（整份檔＝不寫指標；`#/` 是 RFC 6901 的「key 為空字串」、不是整份）；每組非金鑰設定裡的指示詞**用到那組時才解**，解不開＝那封信回 `DirectiveBad`、kernel 照跑別封。
  - `endpoint`（選填）：預設代號（信沒寫 `endpoint` 時用）；寫了但表裡沒有＝`CfgBad`。
  - `timeout_ms`（選填，非負整數）：問腦的上限（寫進問腦單子的 `timeout_ms`，逾時 daemon 那邊整群收）；沒寫＝不限。
  - 其他 key 忽略（`_entry`…）。
  - 指示詞：`slots`、`reserved`、`aging_ticks`、`budget`、`exec`、`endpoint`、`timeout_ms` 整格先解，`endpoints` 先換一層；解不開 `DirectiveBad`。
- **環境**（kernel 要住在 daemon 底下：問腦是請 daemon 掛 proc）：
  - **`AOS_DAEMON`**（必要）：哪台 daemon 掛問腦 proc＝那台的 stack。kernel 當 daemon 的身體或子項時 daemon 會自己設好（[aos-daemon docs/05](../../aos-daemon/docs/05-信箱.md)）；沒設、不是資料夾＝`DaemonMissing`、退 1。
  - `AOS_TICK`（選填）：kernel 自己樹的時鐘檔，內容為非負十進位整數；沒設或空字串＝退牆鐘，設了但檔不在或內容空白＝第 0 格，內容壞或讀不了＝`TickBad`、退 1。`AOS_TICK_INTERVAL` 供退牆鐘換算，設了但不是正整數＝`TickBad`。
  - `AOS_KERNEL`（選填，N-63）：非空＝掛信寄這個信箱；若 `<path>/new` 不是資料夾，每行程每路徑印一次英文 warning，仍用原路徑、不改退路、不因此報錯；後續掛 proc 失敗照舊回 `LaunchFailed`。沒設或空字串＝寄 `$AOS_DAEMON` 的 ctl 信箱（`procs_state.json` 回報的 `procs_ctl_mailbox`；那台沒開 ctl 信箱＝`MailboxMissing`、退 1）。
  - **端點金鑰**：起 llm daemon 的 root 殼先 export 各 `endpoints/*/_entry` 的 `--key-env` 指定的名字（範本是 `LITELLM_KEY`），daemon 子項會繼承；小定義的 `.env` 不寫值。若端點包在 sandbox，sandbox 的 `env` 陣列要明列該名字。搬家後由新機器的 root 殼重給。
- **`$AOS_STACK`**（必要）：kernel 自己的檔（計數的 key 一律 `counter_*`）——
  - `requests/`：信箱，**位置固定**（寄信的人手上只有 stack：`AOS_LLM_KERNEL`＝kernel 的 stack、信箱＝`$AOS_LLM_KERNEL/requests/`，[kernel-daemon 07 § 2](../../../thinking/2026-11/05/kernel-daemon/07-llm-daemon佈局.md)）。
  - `queue.json`：`{"counter_runs": kernel 跑過幾次, "seen_at_ms": {信件名稱: 第一次看到它的 UTC epoch 毫秒}, "seen_at_ticks"?: {信件名稱: 那時的 tick}}`（只留還在排的；`seen_at_ms` 一律寫，`seen_at_ticks` 有 `AOS_TICK` 才寫，沒有就整格省略；先寫暫存再改名）。讀取時 `counter_runs` 必填、兩個 `seen_at_*` 物件選填，不認得的 key 忽略；信沒有記錄＝從現在開始等。在但讀不懂＝`QueueBad`（刪掉就從頭算）。排法＝優先序（級數＋aging → deadline → 包的 speed → 等得久 → 先寄），不是先來先處理（C-54 R14，使用者 11-06）。
  - `used.json`：用量帳（見 [02](02-token-回報與額度.md)；含每包的 `packs`、每個寄件人的 `senders`）。在但讀不懂＝`UsedBad`（刪掉就從 0 算）。
  - **`endpoints.json`**（窗，11-05 feat-proto）：包的屬性表，給人與 `aos-llm ls` 挑代號。每次跑都照 kernel.json 算一份，跟現有的不同才寫（暫存改名，N-05）。形狀＝`{代號: {"speed", "cost"?, "context"?, "slots"?, "summary"?}}`——`speed` 一定有（沒寫＝`"normal"`），其他四個照 kernel.json 有寫才有、值原樣；**不含** `url`／`fixed`／`exec`／`budget`。那組解不開或壞了＝`{代號: {"error": "代號 原因"}}`（例：`{"error": "CfgBad kernel.json endpoints.x.speed must be \"fast\", \"normal\" or \"slow\", got \"warp\""}`）。只解這幾格的指示詞，端點金鑰沒設不影響窗。
  - `ledger.jsonl`：跑過的每封信收尾時追加的成本與時間觀測帳；不存請求原文，欄位與失敗行為見 [02](02-token-回報與額度.md)（11-07 使用者裁定：翻 11-05 的 served.jsonl「也刪」，ledger 留；各層都記 usage、加總只加一層。見 [kernel-nest](../../../thinking/2026-11/07/kernel-nest/README.md)）。
- **信箱**（N-16 資料夾式）：`tmp/`、`new/`、`cur/` 三格，一封信＝一個資料夾 `<信件名稱>/`（`new/`、`cur/` 裡混進來的一般檔不理，11-05）；kernel 每次先建好三格（建不了 `MkdirFailed`），`.flock` 用 flock 鎖住整次（另一個 kernel 鎖著＝`LockFailed`）。`aos-llm ask` 的共用回信信箱在 `requests/reply/`。
  信件名稱＝aos-post 的預設名 `<UTC 奈秒 20 位>.<pid>.<started_at_ticks>`：字典序＝寄的先後。
  `cur/<信件名稱>/`＝認領了、請 daemon 掛成問腦 proc：裡面有 `request.json`、`proc.json`（kernel 寫）、`loop.json`／`state.json`／`stderr.txt`（daemon 寫）、`reply.json`（endpoint 函數寫）。
  **寄信的人還在不在＝信裡的 `sender.flock` 有沒有人鎖著**（[thinking sandbox S15](../../../thinking/2026-10/24/sandbox/README.md)）：只有 `aos-llm ask`（同步）會建、拿到行程結束；kernel 試著拿共享鎖（不等），拿得到、開不了＝人不在。
  **沒有 `sender.flock` 的信（`aos-llm send`、`aos-post send` 寄的非同步信）不判存活、照跑**（[think-as-function 衝突 2 (a)](../../../thinking/2026-11/04/think-as-function/05-衝突與方向題.md)）。
- **信**（`letter.json`，N-16 的信，aos-post／aos-llm 寫）：信封 `sender`、`sent_at`、選填 `sent_at_ticks`（只在同一時鐘下可比，跨樹看 `sent_at`）、`reply_to`（kernel 不檢查也不擋；沒寫 `reply_to`＝回信沒人收得到，信照刪），`body`＝
  `{"endpoint"?: 代號, "request": OpenAI chat completions 的 body 去掉端點, "priority"?}`。
  - `request`：`messages` 必有（陣列）；`tools`、`temperature`… 選填、原樣交給 endpoint 函數；撞到那組釘死的（`fixed` 裡的 key、那組有 `model` 時的 `model`）＝`RequestBad`；`stream` 寫真＝`RequestBad`（串流不做）。
  - `endpoint`：代號字串；沒寫＝kernel.json 的 `endpoint`；兩邊都沒寫＝`EndpointMissing`；表裡沒有＝`EndpointUnknown`。信只能選代號，改不了包的 `url` 或端點小 proc 的金鑰。
  - **priority**：沒寫＝normal；`"low"`／`"normal"`／`"high"`；數字看正負；物件 `{"level", "deadline", 其他 key 照帶不管}`；`deadline`＝帶時區的 ISO 8601 或 epoch 秒（沒時區不猜＝壞）。跨樹信的期限＝牆鐘（N-65 ③），格式維持不變；kernel 自己的 aging 才用自己樹的鐘，不讀信裡任何 tick 欄。排隊依據只從 `priority_of` 讀。
  - 沒有 `body.request`＝`LetterBad`。其他不認得的 key 忽略（C-48）。
- **端點函數契約**：stdin 是 `request.json` 的 `{"endpoint": 能力包, "request": 原請求, "priority": {"level": 宣告級數, "deadline"?: epoch 秒}}`。`level` 照信原值、沒寫＝`"normal"`，不帶 aging；期限取信的 deadline 與首次 `mounted_at + timeout_ms / 1000` 較小者，兩者都沒寫就省略 `deadline`。`proc.json` 的 `seen_at` 從 queue 的 `seen_at_ms / 1000` 抄下，抄不到記 null；重掛沿用第一次的 request 與 seen_at，不重算期限。
  成功退 0、stdout 一行 `{"message": {...}, "usage"?, "model"?, "child"?}`；`child` 原值只記本層 ledger，回信拿掉，其他鍵原樣。退非 0 且非逾時時，stdout 若是單行 JSON、頂層只有 `error`，其中 `code`／`msg` 都是字串，整個錯誤物件原樣回（含 error 內其他鍵）；否則照舊 `EndpointFailed` 加第一行。退 0 卻印 error 仍是 `ReplyBad`。
- **回信**（`reply.json`）：endpoint 函數 stdout 那份 `{"message": {...}, "usage"?, "model"?}`，或 `{"error": {"code", "msg"}}`（沒跑、掛不上 daemon、函數退非 0 或逾時、stdout 讀不懂）。
  信封寫了 `reply_to`：另把拿掉 `child` 的那份當 `body`、照 [N-16](../../../docs/NORMS/05-基礎設施-窗/05-N-16.md) 寄一封回信進那個信箱（aos-post 的庫；相對的 `reply_to` 從 kernel 信箱的根拼回、絕對的照用，見 [aos-post](../../aos-post/docs/01-用法與元素.md)；`in_reply_to`＝原信的信件名稱、`sender`＝kernel 自己的身分；不附檔），寄出的信件名稱記在 `<信>/reply_letter.txt`（已經有＝寄過了、不寄第二封）。**寄完就整封刪掉**（`cur/<信件名稱>/` 整個資料夾；沒有 `done/`）（11-04 夜使用者「舊信根本不用留，就是刪」）。
  寄不出去（信箱不在、寫不進）不是 kernel 的錯：kernel 的 stderr 印一行 `aos-llm-kernel: <代號> <原因> (cannot send the reply to letter <信件名稱>; letter deleted anyway)`、不退，信照刪（寄信的人自己承擔）。有 `sender.flock` 而寄完回信時寄信的人已經不在了（`ask` 被打斷）：那封回信還在對方 `new/`（沒人拿）就馬上撤回。
