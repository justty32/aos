## 結論（跟 AI 討論後）

做了一支 C++ 命令列 `aos-json`（`proto8/impls/aos-json/`，連 aos-util、aos-directive）和兩個給腦掛的工具。說明與每個指令在 [README](../impls/aos-json/README.md)。

- **讀**：`get`（原文；`--resolve` 交給 aos-directive 解，跟 aos-loop／aos-fsm 讀設定檔同一套）、`where`（追 `$ref` 鏈，每站一行，最後一站＝值實際寫在哪）、
  `peek`（**漸進展開**：先只給頂層，每個 key 一行摘要、大的值摺起來，想看哪個 key 再 peek 那個指標）。
- **寫**兩種粒度：一次一個值（`set`、`append`、`merge`、`del`）、一次一大段（`set` 整棵子樹、`batch` 一次很多個指標，全部成功才寫）。
  寫入原子（N-05）、只重寫有變的那一塊（其他原文一個字都不動）、留 `#!` 與權限、捷徑留著。
- **指示詞**：路上經過 `$ref` 時，`--follow`＝改被參照的檔，不加＝擋下（`FollowMissing`）；直接指著指示詞改＝原地換。`env`、`ref` 把值包成指示詞，`ref --move` 把一塊拆成另一份檔（裡面的相對 `$ref` 跟著改）。
- **驗**：`check`（`$ref` 指得到、不繞圈、合得起來、寫法對、`exec` 形狀對）；寫入加 `--check`＝改完多出問題就不寫。
- **給腦**（照使用者的設計理由：AI 生成 JSON 幾乎不會錯、又只看想看的那層）：
  `tools/json/`＝一次一個動作，讀是 peek 一層層往下、寫是直接收腦生成的 JSON 值（單值或子樹），一律先驗再寫；
  `tools/json_edit/`＝**小念頭兩步**：一、「找到要修改的 key」——腦只看頂層、用 peek 往下、交出指標；二、「提供值」——每個指標各開一次新對話，只看那一處、只產出那個值；最後一次寫進去。

## 決定（代定，使用者 10-24「都按建議做」，照推薦定、可翻案）

1. 用 C++、放新資料夾 `proto8/impls/aos-json/`，連 aos-directive（`--resolve`、`peek --follow` 的展開直接用它）；改檔要的「值在哪個檔的哪個位置」它的公開介面沒有，`src/follow/` 照它的規則自己走一遍（兩份規則要一起改，README 有寫）。
2. 子命令放第一個、旗標放在 `檔#/指標` 前面（同 `parse_cli`）。值當 JSON 解，字串加 `--str`；沒給參數讀 stdin。
3. 寫入的路上經過指示詞沒加 `--follow`＝錯（`FollowMissing`），不默默寫進指示詞物件裡（aos 不會看那些 key）。
4. `$ref` 陣列（幾份合成一份）時 `--follow` 寫哪一份：物件看最後一份有這個 key 的（生效的就是它），都沒有寫進最後一份；`del --follow` 每一份有的都刪；不能整個換掉合起來的值。
5. 排版：只重寫有變的那一塊；做不到才整份照原縮排重排。不保留擁有者、硬連結；沒有鎖（兩人同時改＝後寫的蓋掉）。
6. `merge` 是淺層合、`null` 照字面放（同 `$ref` 陣列的合法，不照 RFC 7396「null＝刪」）。
7. `check` 只看 aos 設定檔裡的 `exec` 那幾格（最上層、`states/<名>/exec`、`loops/<名>/exec`，位置照 `$ref` 合好之後算）；`$env` 現在沒設預設不報（`AOS_*` 跑的時候才有），`--env` 才報；有問題退 1、印 stdout。
8. `--check` 只擋「改完多出來的問題」，原本就有的不擋。
9. 腦的工具：檔名只收工作區裡的相對路徑；aos-json 的錯（指不到、形狀不對）印 `錯：…`／`沒改：…`、退 0 讓腦重來，不算工具失敗（不會讓 act 格以 ToolFailed 停下）。
10. 小念頭兩步先用「兩次腦呼叫」做最小版（`tools/json_edit/` 自己問腦）。**之後接 agent-gus 的小念頭**（[thinking 小念頭](2026-10-24-thoughts.md)；`demo/agent-gus/thought.json`：`AOS_STACK=<小格> aos-exec <agent-gus>/thought.json < {"goal", "context"}` → 結論）：
    第二步「提供值」換成叫它一次，`goal`＝「給 檔#/指標 一個新值，只回 JSON」、`context`＝要做的事＋現在的值＋上一層的 peek，結論當 JSON 解；第一步也能換成一個小念頭，結論是指標清單。
11. 還沒接進共用建置（`wf/workflows/testing.md` 的建置迴圈、`proto8/tests`、`demo/run.sh` 都沒動）；接法寫在 README。agent-dan 範本也沒掛這兩個工具（要掛＝複製或捷徑到 `tools/`、`aos-json` 放進 PATH）。

## 邊緣狀況（實作時挖到的，照 README 處理）

- 負數值、`-` 開頭的字串：放在檔名後面會被當成多的參數；整個加引號（`'"-3"'` 是字串）或從 stdin 給。
- 物件裡有重複的 key：讀的時候 nlohmann 只留一個；寫回去 splice 會放棄、整份重排。
- 被重寫的那一塊：數字照 nlohmann 印（`1e3`→`1000.0`）、`é` 變原字。
- `check` 會報 `$ref` 陣列裡被後面那份蓋掉、根本不生效的格（例：a.json 的 think 被 b.json 的 think 整個蓋掉，a 那格的 exec 壞也照報）。
- `$ref` 陣列裡又有 `$ref` 陣列，`--follow` 先不支援（`TargetBad`）。
- `$ref` 帶 `$path`／`$prefix` 時 `--follow` 寫的是被參照的原值，實際生效的值還會再接上 `$path`／`$prefix`。
- `ref --move` 改相對 `$ref` 用的是字面路徑（不解捷徑）；搬到跨捷徑的資料夾可能算錯。
- 腦的工具：`--follow` 穿過的 `$ref` 可以指到工作區外面的檔，那邊照樣會被改。
- 真腦這次沒跑成：這台機器 10-24 下午 LiteLLM（localhost:4000）沒開；假腦測試證明了第一次只給頂層（看不到 `timeout_ms`）、之後照 peek 一層層往下、提供值那一步是只看那一處的新對話。指令在 README「真腦跑一次」。
