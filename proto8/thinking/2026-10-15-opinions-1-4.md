## 決定

**`end`（使用者改，兩次）**：使用者補充原文：「end那塊，如果表裏面沒有這個狀態也可以。通常來說，如果執行完某個state之後，他返回的狀態不在表裏，fsm會報錯，但如果不在表裏而在end裏，那就是退出。開始改吧」

- `end` 是陣列，可以多個名字；名字可以在表裡、也可以不在。
- 某格跑完回的 `next`：
  - (a) 在表裡、不在 end → 照常進入那個狀態。
  - (b) 在表裡、也在 end → 進入、跑完那格的 inst，然後這個 fsm 結束（巢狀時把那格的結果交給外層、自己回 `start`）。
  - (c) 不在表裡、在 end → 直接結束，交出去的結果＝剛跑完那格的結果。
  - (d) 不在表裡、也不在 end → 錯。
- (b) 是新補的（現行只有 (a)(c)(d)）；現行 demo 的寫法（`end` 放外層狀態名或表裡沒有的名字）照 (c) 仍然合法。

**frame 放哪由呼叫方決定（使用者改）**：
- 表達法：**frame＝被叫者跑的 cwd**，呼叫方用它跑那張 inst 時的 `cwd`（要新建就加 `cwd_mkdir: true`）指定——不新增任何 key。命令列直接叫＝`cd` 到那裡再跑。
- 預設（使用者可改）：**工具呼叫**沒寫 `cwd`＝呼叫者 `work/` 下一個新號碼資料夾（`work/<n>/`，mkdir 搶號，每次一個新的）；**直接呼叫**（命令列、程式、kernel）沒指定＝當下的 cwd。
- 指同一個 frame＝接著那裡的 history 繼續（同一段對話）；兩個呼叫同時指同一個 frame 不擋（Q13 拿掉 Busy，「卡死不防護」）。

**其餘 15 題照推薦**（使用者「剩下都按照推薦」）：

- **Q1 格出錯**：格非 0（或沒吐完整 JSON）＝phase 不動，fsm 把格的結果（N-30＋格 stderr 的錯）原樣往外報，fsm 結束碼非 0（後補，使用者：「結束碼不要太依賴，我已經決定規範中只定下：0就是通用正常，非0就是有錯，沒了。」→ N-43）；`error` 變成普通狀態名，要優雅處理就格自己接錯、回 `{"next": "error"}`。
- **Q2 stdin**：fsm 不給格 stdin，格照自己 inst 的 `stdin`；fsm 只另外接一份 stdout 看 `next`。
- **Q3 `data`**：拿掉，格之間用 frame 裡的檔傳。
- **Q4**：`step`／`max_steps` 交給拍它的 loop 的 `times`；`fails`／`max_fails`／`halted` 交給格自己（例 think 連錯 3 次回 `{"next": "halted"}`，halted 是表上普通狀態）；`running` 拿掉（被殺＝phase 沒變＝下一拍重跑，半成品由格自己認）。
- **Q5**：fsm 不開 ctl、lock，交給 loop；state 窗照必填，只剩 `phase`。
- **Q6**：`end` 保留（語意照上面改）；N-40「外層設定當預設」拿掉。
- **Q7 相對路徑**：格的名字從 fsm.json 所在資料夾算；窗與資料從 cwd 算。
- **Q8 葉子程式**：用指令名（`aos agent think`，在 PATH），不寫相對腳本路徑。
- **Q9 找名字**：先找 frame，找不到照 frame 裡 `env.json` 的 `parent` 往上找。
- **Q10 tools**：資料夾逐項合併＝追加＋同名蓋過；「整份取代」先不支援。
- **Q11 呼叫的串接**：`sh -c` 三步（寫 env.json → 跑被叫者的 loop → 讀 ret.json）。
- **Q12 回傳**：frame 的 `ret.json`（錯＝N-29 `{"error": …}`；沒有＝沒跑完）。
- **Q13**：TooDeep、Busy 都拿掉，深度靠各層 `timeout_ms`。
- **Q14**：agent 定義以資料夾為正本（單檔可互通，見意見 5）。
- **Q15**：先一次改規範（N-36～N-40、C-46）與 fsm.md、agent.md，再動程式。

## 結論

> **10-20 註**：結論當天採納；但下面例子裡的寫法後來被推翻，看的時候以後來的為準：`env.json` 先被[命名盤點](2026-10-15-naming/盤點.md) P2 改名 `frame.json`，再連同 `parent` 鏈在 [inst-exec 第四版](2026-10-15-inst-exec-v4.md)（未決 E）退場；`fsm-state.json` 被盤點 P3 改成 `fsm/state.json`；格裡的 `{"target": …}` 隨第三版、第四版「TARGET 全拿掉」改成直接寫一張 inst；工具叫 agent 的 `sh -c` 三步（寫 env.json → 跑 loop → 讀 ret.json）被第四版換掉（args.json／ret.json 那套 10-16 也不要了，見 [agent-inherit](2026-10-16-agent-inherit.md)）。

### 瘦身後的 fsm

設定只剩 `start`、`states`、`state`（窗）、選填 `end`；state 窗 `{"phase": "…"}`。一拍＝讀 phase → 跑那格（stdin／stdout 照那張 inst）→ 照 stdout 最後一份的 `next`＞表上靜態 next＞留原地 換 phase → 吐一行 `{"from", "to"}`＋格的 N-30 結果。結束照上面 end 的 (b)(c)：剛跑的是表裡的 end 狀態，或回的 next 是表外的 end 名字，就把那格結果交外層、phase 歸位 `start`。

從 fsm 移走的：給格的 stdin 與外層設定繼承（刪）、`data`／`running`／`fails`／`halted`（格自己）、`step`／ctl／lock（拍它的 loop）、error 格特例與 `error_from`／`last_error`（格自己接錯）。

### agent 的資料夾

```
agents/clerk/                    ← 定義（呼叫時不寫）
  fsm.json  loop.json
  cells/intake.json  cells/think.json  cells/route.json  cells/tool.json  cells/done.json
  brain.json  system.md  tools/clock.json
```

```jsonc
// agents/clerk/fsm.json
{"start": "intake", "state": "fsm-state.json", "end": ["done", "halted"],
 "states": {
   "intake":   {"target": "cells/intake.json", "next": "thinking"},   // args.json → history.json（已有 history 就不生）
   "thinking": {"target": "cells/think.json",  "next": "route"},
   "route":    "cells/route.json",                                     // 回 {"next": "tool"} 或 {"next": "done"}
   "tool":     {"target": "cells/tool.json",   "next": "thinking"},
   "done":     "cells/done.json",                                      // 寫 ret.json、ctl.json {"stop": true}
   "halted":   "cells/done.json"                                       // think 連錯自己跳來，ret.json 是錯
 }}

// agents/clerk/loop.json（ctl／state 從 cwd＝frame 算）
{"inst": {"argv": ["aos", "fsm", "/agents/clerk/fsm.json"]}, "times": 20, "ctl": "ctl.json", "state": "loop-state.json"}

// agents/clerk/cells/think.json
{"argv": ["aos", "agent", "think"], "timeout_ms": 200000}
```

agent.json 的私有 key（`brain`／`tools`／`system`／`history`／`work`）不再搭 fsm.json，各自是檔或資料夾；程式都在共用 lib。〔schema：定義資料夾布局、`env.json`、`args.json`（＝`_tool.parameters`）、`ret.json`、fsm 表——見[意見 5～7](2026-10-15-opinions-5-7.md)。〕

### call／binding（Lisp 式）

| Lisp | aos |
|---|---|
| 函數本體 | 定義資料夾 `agents/clerk/` |
| 呼叫時的環境（frame） | 呼叫方指定的資料夾＝被叫者的 cwd |
| 上一層環境 | frame 的 `env.json` `{"parent": "<定義資料夾>"}` |
| 綁定一個名字 | frame 裡放同名檔／資料夾 |
| 實引數／回傳值 | `args.json`／`ret.json` |
| 詞法 vs 動態 | 格的名字從 fsm.json 所在資料夾找；窗與資料從 cwd 找 |

求值規則：① 字串＝名字、物件＝內嵌值（C-48）；② 找名字＝frame → `env.json` parent 鏈（資料夾逐項找）；③ 呼叫＝在呼叫方給的 frame 寫 env.json、args.json、要蓋的綁定檔，跑被叫者的 loop.json；④ 被叫者走進 end 狀態（done）寫 ret.json 並 stop 自己的 loop，或 `times` 用完；⑤ 讀 ret.json。

例 1（A 把 clerk 當工具，frame 用預設 `work/<n>/`，tool 格把引數寫成那裡的 `args.json`）：

```jsonc
// agents/A/tools/clerk.json
{"argv": ["sh", "-c",
   "echo '{\"parent\": \"/agents/clerk\"}' > env.json && aos loop /agents/clerk/loop.json >/dev/null; cat ret.json"],
 "timeout_ms": 120000,
 "_tool": {"description": "問報時員（另一個 agent），它會查時間、回一句話。",
           "parameters": {"type": "object", "properties": {"question": {"type": "string"}}, "required": ["question"]}}}
```

例 2（直接叫，呼叫方指定 frame，順便綁 history、換腦、追加工具＝以前的 history、engine_args、tools_append）：

```
runs/judge-7/                    ← 呼叫方選的 frame
  env.json          {"parent": "/agents/clerk"}
  history.json      ← 綁 history
  brain.json        {"argv": ["aos", "brain", "openai", "--model", "qwen3-1.7b"]}   ← 蓋過預設的腦
  tools/weather.json                                                           ← 追加；clock 從 parent 找到
```

`cd runs/judge-7 && aos loop /agents/clerk/loop.json; cat ret.json`

### 要注意的邊緣（動工時處理）

- 葉子用相對腳本路徑在 cwd 換成 frame 後會壞，所以 Q8 是動工前提。
- 拿掉 `running` 後，各格要自己認得半成品（think 看 history 最後一則、tool 看 tool_calls 回了沒，現在已經這樣）。
- 沒接錯的格會每拍重跑到 loop `times` 用完。
- 表裡指回自己的遞迴 fsm 不擋，卡死不防護（後補，使用者「好」）。
- `env.json` 繞圈：lookup 記走過的 realpath，重複就停。
- 巢狀時內層 `timeout_ms` 要比外層短。
- ret.json 要先寫暫存再改名。
