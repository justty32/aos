## 原文（10-15 收工後，照記）

1. 「當現在是A狀態的時候，執行指定inst，就這樣，那個狀態內部、inst內部的東西，fsm不該管。」

## 一、現況對照：fsm 管了哪些「狀態→inst」以外的事

照意見 1，fsm 只該留三件：**讀現在狀態 → 查表跑那格 inst → 照那格說的換狀態**。下面是 [aos_fsm.py](../lib/aos_fsm.py) 現在多做的，逐項建議去處。

| 現在 fsm 做的 | 出處 | 建議去處 | 理由（一句） |
|---|---|---|---|
| 把**整份 fsm 設定＋`fsm_state`** 餵給格當 stdin | N-37 | **刪**：fsm 不碰格的 stdin，格要什麼自己的 inst 寫（inst 本來就有 `stdin` key） | 格的設定是格內部的事；agent 的 `brain`／`tools` 搭 fsm 設定的便車，正是 fsm.json 變胖的原因 |
| N-40 外層 cfg 當預設（內層繼承外層 key，`OWN` 例外清單、讀 stdin 一般檔的例外） | N-40 | **刪**（上一項刪了就沒意義） | 一條規則加兩個例外，全是為了傳設定 |
| `data`：上一格回的存進 state 窗、下一格再讀 | N-37、N-39 | **移到 inst**：格之間要傳的東西寫成 frame 裡的檔（history.json 已經這樣） | 這是「狀態內部」的資料 |
| `running`：起格前先寫、偵測被殺一半 | N-38、N-39 | **刪**：fsm 跑完格才寫 phase，被殺＝phase 沒變＝下一拍重跑同格；要不要撿半成品是格自己看自己的檔（think 已經會看 history 最後一則） | 重跑不保證冪等本來就是 N-20 |
| `step`／`max_steps`／`MaxSteps` | N-38 | **移到外層**：拍它的 loop 的 `times` 就是上限（agent call 的 max_ticks 也是這個） | 計數是「拍幾次」，屬於拍的人 |
| `fails`／`max_fails`／`halted`（連錯停住、人改窗接手） | N-38 | **移到 inst**：要停住的格自己數（例 think 連錯 3 次就回 `{"next": "halted"}`），`halted` 只是表上一個普通狀態 | 「腦錯每拍重叫」是 think 格的問題，不是所有狀態機的問題；也順便消掉 N-09 的例外 |
| `error` 格特例＋`error_from`＋`last_error`＋撿格 stderr 的 N-29 錯誤 | N-38 | **改成一條**：格非 0（或沒吐完整 JSON）＝phase 不動，fsm 把格的結果（N-30＋格 stderr 的錯）原樣往外報；想優雅處理的格自己接錯、回 `{"next": "error"}`，`error` 變成普通狀態名 | fsm 不懂錯誤內容，只轉交 |
| `ctl` 窗（paused／stop、`ctl_seq` 回音） | N-39 | **移到外層**：拍 fsm 的 loop 已有 ctl | fsm 壽命一拍，暫停是「要不要拍」的事 |
| `lock` 窗 | N-39 | **移到外層**：loop 串行拍就不會重疊；一次呼叫一個新 frame（mkdir 原子）也擋得住 | 同上 |
| 每拍 stdout 那行（N-30 欄位＋`step`、`from`、`to`） | fsm.md | **保留但瘦**：`{"from", "to"}`＋格的 N-30 結果；`step` 隨上面拿掉 | 給人看、給外層看，不影響行為 |
| `end` 出口名單＋走到 end 時把那份原樣吐出、phase 歸位 `start` | N-40 | **保留** | 這是「巢狀時換狀態」本身，不是格內部 |
| 表上靜態 `next`、stdout 的 `next` 優先 | N-36、N-37 | **保留** | 這就是「換狀態」 |
| 格的 TARGET 相對路徑從**呼叫者 cwd** 算 | fsm.md、N-36 | **改**：從 fsm.json 所在資料夾算（見三、規則 L） | 定義能被別人在別處叫，路徑才不會壞；也是 aos_agent_call「攤開」整段存在的理由 |

**瘦完的 fsm**：設定只剩 `start`、`states`、`state`（窗，N-19 照必填）、選填 `end`；state 窗只剩 `{"phase": "…"}`。一拍＝讀 phase → 跑格（stdin／stdout 照那張 inst 自己寫的，fsm 只另外接一份 stdout 來看 `next`）→ 寫 phase → 吐一行。

## 二、agent＝fsm＋inst 的最小布局

一個 agent **定義**＝一個資料夾（不寫）；一次**呼叫**＝一個 frame 資料夾（呼叫時新建，就是被叫者的 cwd）。程式全在共用 lib（`aos_agent_lib` 的幾格），資料夾與 JSON 只放「哪個狀態跑哪張 inst」與資料（意見 2）。

```
agents/clerk/                    ← 定義（函數本體，呼叫時不寫）
  fsm.json                       ← 只有表
  loop.json                      ← 怎麼拍它（上限＝times）
  cells/intake.json              ← 每格一張 inst，程式都在共用 lib
  cells/think.json
  cells/route.json
  cells/tool.json
  cells/done.json
  brain.json                     ← 預設的腦（可被 frame 蓋過）
  system.md
  tools/clock.json               ← 預設的工具（frame 可追加／蓋過）
```

```jsonc
// agents/clerk/fsm.json
{"start": "intake", "state": "fsm-state.json", "end": ["done"],
 "states": {
   "intake":   {"target": "cells/intake.json", "next": "thinking"},
   "thinking": {"target": "cells/think.json",  "next": "route"},
   "route":    "cells/route.json",                         // 回 {"next": "tool"} 或 {"next": "done"}
   "tool":     {"target": "cells/tool.json",   "next": "thinking"},
   "done":     "cells/done.json",                          // 寫 ret.json、寫 ctl.json {"stop": true}
   "halted":   "cells/done.json"                           // think 連錯自己跳來；同樣寫 ret.json（內容是錯）
 }}

// agents/clerk/loop.json（ctl／state 從 cwd＝frame 算）
{"inst": {"argv": ["aos", "fsm", "/agents/clerk/fsm.json"]}, "times": 20, "ctl": "ctl.json", "state": "loop-state.json"}

// agents/clerk/cells/think.json（leaf 用指令名，不寫相對腳本路徑，見問題 Q8）
{"argv": ["aos", "agent", "think"], "timeout_ms": 200000}

// agents/clerk/tools/clock.json（照舊，_tool.parameters 就是 args 的 schema）
{"argv": ["aos", "clock"], "timeout_ms": 5000,
 "_tool": {"description": "查現在的時間", "parameters": {"type": "object", "properties": {}}}}
```

跟現在比：agent.json 裡的 `brain`／`tools`／`system`／`history`／`work` 私有 key 不見了，各自是一個檔或資料夾；fsm.json 不再兼當 agent 設定。〔schema：「一個 agent 定義資料夾該有 fsm.json、可有 brain.json／tools/…」正好是意見 7 說的「用 schema 規範資料夾」，交給 opinions-5-7 那份。〕

## 三、call／binding 用 json＋資料夾＋inst（Lisp 式）

### 對應

| Lisp | aos |
|---|---|
| 函數本體（lambda） | 定義資料夾 `agents/clerk/` |
| 呼叫時的環境（frame／let） | 新建的 frame 資料夾（＝被叫者的 cwd） |
| 環境的上一層（parent env） | frame 裡的 `env.json` `{"parent": "<定義資料夾>"}` |
| 綁定一個名字 | frame 裡放一個同名的檔／資料夾 |
| 實引數 | `args.json`（stdin 那份物件，就是 `_tool.parameters` 描述的那份） |
| 回傳值 | frame 裡的 `ret.json`（錯＝N-29 `{"error": …}`） |
| 詞法作用域（找程式） vs 動態（放資料） | 格的名字從 fsm.json 所在資料夾找；窗與資料從 cwd（frame）找 |

### 求值規則（五條）

1. **值的雙形**（C-48）：字串＝名字，物件＝內嵌的值；名字要「找」，內嵌的直接用。
2. **找名字（規則 L）**：先看 frame（cwd）有沒有；沒有就照 `env.json` 的 `parent` 往上一層找，直到沒有 `parent`。名字是資料夾時**逐項找**：`tools/` ＝ 各層 `tools/*` 的聯集、同名以近的為準（＝現在的 `tools_append`＋蓋過）。fsm 表上的格名字例外，一律從 fsm.json 所在資料夾算（詞法）。這條由共用 lib 的一個 `lookup()` 做，格都用它，不是專用的 call 程式。
3. **呼叫 (f args)**：建新 frame（mkdir，原子）→ 寫 `env.json`（parent＝f）、`args.json`、要蓋的綁定檔 → 在 frame 裡跑 f 的 loop.json。
4. **結束**：f 自己的終點格寫 `ret.json`、並把 loop 的 `ctl.json` 寫成 `stop: true`；或 loop 的 `times` 用完。
5. **回傳**：讀 `ret.json`。沒有＝沒跑完（相當於現在的 MaxTicks；`history.json` 留在 frame 給人看）。

### 例 1：agent A 把 clerk 當工具叫（LLM 決定叫）

A 的 tool 格（共用 lib）只多守一條約定：**每次跑工具就在自己的 `work/` 下 mkdir 一個新號碼當工具的 cwd，並把引數寫成那裡的 `args.json`**（現在已經會寫 `work/N-call.json`，只是換成資料夾）。工具 inst 就是普通 inst：

```jsonc
// agents/A/tools/clerk.json
{"argv": ["sh", "-c",
   "echo '{\"parent\": \"/agents/clerk\"}' > env.json && aos loop /agents/clerk/loop.json >/dev/null; cat ret.json"],
 "timeout_ms": 120000,
 "_tool": {"description": "問報時員（另一個 agent），它會查時間、回一句話。",
           "parameters": {"type": "object", "properties": {"question": {"type": "string"}}, "required": ["question"]}}}
```

跑完的 frame（也就是 S 式 `(clerk :question "幾點？")` 攤在檔案系統上）：

```
agents/A-run/work/3/          ← A 第 3 次叫工具＝clerk 這次的 frame
  env.json        {"parent": "/agents/clerk"}
  args.json       {"question": "幾點？"}
  history.json    ← intake 從 args 生出來、think 一路累積
  fsm-state.json  {"phase": "intake"}        （done 走 end 後歸位）
  loop-state.json、ctl.json {"stop": true}
  work/1/         ← clerk 叫 clock 的 frame（一層層長下去）
  ret.json        {"reply": "現在 14:03:07"}
```

### 例 2：程式或 kernel 直接叫，順便綁腦與追加工具（＝現在的 engine_args、tools_append、history）

```
runs/judge-7/
  env.json          {"parent": "/agents/clerk"}
  history.json      [{"role": "user", "content": "…"}]    ← 給了 history＝綁 history（intake 看到已有就不從 args 生）
  brain.json        {"argv": ["aos", "brain", "openai", "--model", "qwen3-1.7b"]}   ← 蓋過 clerk/brain.json
  tools/weather.json                                      ← 追加；clock 照樣從 parent 找到
```

```
cd runs/judge-7 && aos loop /agents/clerk/loop.json; cat ret.json
```

綁定＝放檔，不放＝用定義的預設；沒有任何一行專門處理 `engine_args`／`tools`／`tools_append` 的程式。

### aos_agent_call.py 哪些可以拿掉

| 現在 [aos_agent_call.py](../lib/aos_agent_call.py) 做的 | 改成 |
|---|---|
| `_doc` 把定義「攤開」：格、brain、tools、system 讀成內嵌 inst、cwd 改成 bob/ | 規則 L（格從 fsm.json 所在資料夾算、資料走 lookup）＋leaf 用指令名 → **拿掉** |
| state／history／work 指進 frame | 這些本來就從 cwd 算，cwd＝frame → **拿掉** |
| `engine_args`（list 接 argv、dict 蓋 key）、`tools` 整份取代、`tools_append` | frame 放 `brain.json`、`tools/*` → **拿掉**（「整份取代」見 Q10） |
| `history` 給了就換、刪 state；沒給＝`NoHistory` | frame 放 `history.json`；intake 格看有沒有 → **拿掉** |
| `frame/lock/` 拿整趟＝`Busy` | 一次呼叫一個新 frame（mkdir 原子）→ **拿掉** |
| `_run` 一拍一拍敲 fsm、看 `next` 是否在 end、`MaxTicks`＋`partial` | loop 的 `times`＋終點格寫 ctl stop；沒有 ret.json＝沒跑完 → **拿掉** |
| `SubAgentFailed`（格錯或 halted） | 被叫者的 halted 狀態自己寫錯誤的 ret.json → **拿掉** |
| `AOS_ASK_DEPTH`／`TooDeep` | 各層工具的 `timeout_ms` 自然收；或照「卡死不防護」→ **拿掉**（見 Q13） |

剩下要寫的程式都在共用 lib：`lookup()`、intake／done 兩格、tool 格改成「新號碼資料夾＋args.json」。`aos_agent_call.py` 整支可以退場（`aos_agent_lib.py ask` 跟著退）。

## 四、挖到的邊緣狀況（給使用者判斷）

- **leaf 的相對腳本路徑**：現在 `["python3", "../tools/clock.py"]` 是照 cwd 算的，cwd 一換成 frame 就壞——這正是 aos_agent_call 把 cwd 改回 bob/ 的原因。瘦身方案要靠「leaf 用指令名」（`aos …` 在 PATH）才乾淨（Q8）。
- **被殺一半**：拿掉 `running` 後，fsm 只知道 phase 沒變；think 看 history 最後一則、tool 看 tool_calls 有沒有回，各格要自己認得半成品（現在其實已經這樣做）。
- **一直錯**：沒接錯的格（例 bug 直接崩）每拍重跑、loop 照拍直到 `times`；要停得靠格自己接錯跳 halted，或 loop 的 times。
- **`env.json` 繞圈**（parent 指回自己）：lookup 記走過的 realpath，重複就停（同 [同像性決定 3](2026-10-15-homoiconic.md)）。
- **遞迴太深**：每層一個 frame，往下長在 `work/N/work/M/…`；外層工具的 `timeout_ms` 會先收掉，但內層要比外層短，否則外層超時時內層還在寫（被 aos_inst 的群組收掉）。
- **ret.json 半份**：done 格要先寫暫存再改名（同 ctl／state 窗的寫法）。

## 五、待拍板（每題附推薦）

- **Q1 格出錯**：A 格非 0＝phase 不動、fsm 把格的結果往外報，`error` 變普通狀態名、要優雅就格自己接錯（**推薦**）／B 保留 `error` 格特例但拿掉 error_from／last_error／C 照現在。
- **Q2 fsm 給格的 stdin**：A 不給，格照自己 inst 的 `stdin`（**推薦**）／B 給上一格的 stdout（管線式）／C 照現在（設定＋`fsm_state`）。
- **Q3 `data`**：拿掉，格之間用 frame 的檔（**推薦**）／保留。
- **Q4 `step`／`max_steps`、`fails`／`max_fails`／`halted`、`running`**：全移出 fsm——上限給 loop `times`、連錯停住給格自己、`running` 拿掉（**推薦**）／只移一部分。
- **Q5 ctl、lock 窗**：fsm 不開，交給拍它的 loop（**推薦**）；state 窗照必填但只剩 `phase`。
- **Q6 巢狀**：`end` 保留、N-40「外層 cfg 當預設」拿掉（**推薦**）。
- **Q7 相對路徑**：格名字從 fsm.json 所在資料夾算、窗與資料從 cwd 算（**推薦**，接同像性決定 2）／照現在一律 cwd。
- **Q8 leaf 怎麼指程式**：用指令名（`aos agent think`，在 PATH）（**推薦**）／相對腳本＋給格一個環境變數指定義資料夾。
- **Q9 binding 的找法**：frame → `env.json` 的 `parent` 鏈（**推薦**）／frame 裡放 symlink 連回定義（零程式，但只限 POSIX）／照現在攤開。
- **Q10 tools 綁定**：資料夾逐項合併＝追加＋同名蓋過（**推薦**）；「整份取代」先不支援（**推薦**），真要再加一個標記。
- **Q11 呼叫的膠水**：`sh -c` 三步（**推薦**，原型最省）／把 proto8-1 的 `seq` 搬過來，寫成純 JSON／做一個通用 `aos eval`（不推薦：又變成專用程式）。
- **Q12 回傳值**：frame 的 `ret.json`（**推薦**）／被叫者 stdout 最後一份／history 最後一則。
- **Q13 TooDeep、Busy**：都拿掉，Busy 由新 frame mkdir 取代、深度靠 timeout（**推薦**，呼應「卡死不防護」）。
- **Q14 agent 定義的正本**：資料夾（**推薦**，綁定是逐檔蓋過）／單檔 agent.json（C-48 私有 key）；兩者可互通（意見 5）。
- **Q15 改規範的時機**：上面拍完一次改 N-36～N-40、C-46、fsm.md、agent.md，再動程式（**推薦**）。
