## 代定（可翻案）

1. **bob-1 多給 `Write`**（要寫 `result.md`）；兩隻都不接 MCP（`--strict-mcp-config` 不給 `--mcp-config`）。
2. **bob-1 的 history 記開場白與最後回答**兩則；中間讀檔、寫檔不進簿子（看 `.stack/claude.json`）。
3. **bob-2 的信箱用 P-11 的 `$AOS_WS/new cur out done`**——任務書原本寫 `aos-post init` 的 N-16 信箱＋`send --ordered`，使用者補「通用接口是 aos-say／listen」之後改用 say 認得的這個；不放 `.stack/`（那是 hub 代答實例的特例）。
4. **一題一答**：一次只認領一題、每題叫一次 `claude -p`（整本對話簿），不把幾題併成一次。
5. **開場白只在對話簿空的時候答**；答在簿子裡，沒有題名、不寫 `out/`。
6. **ctl.json 放 `$AOS_STACK/ctl.json`、形狀照 N-07**（只認布林 `paused`／`stopped`、`stopped` 壓過 `paused`）；每 0.3 秒看一次；壞的當沒寫，不記 `ctl_warning`。
7. **ctl.json 不會自己清**：寫著 `stopped` 就重開＝立刻退 0（實跑 0.03 秒）。照 N-06「ctl 寫的是期望」，要重開的人自己改掉。
8. **`server.txt`、每題一行 `trace.jsonl` 照 hub-adapter 代定 1**；另寫 `state.json`（`waiting`／`answering`／`paused`／`stopped`／`failed`），listen 現在不讀它。
9. **失敗＝題目留 `cur/`、退 1**（P-20）；重開先做 `cur/` 那題，user 那則不重複接。SIGTERM＝退 143、不收尾。
10. **對話簿沿用 A 的代定 3 放 `$AOS_WS/history.jsonl`**（結果 `listen --follow` 看不到，見下面衝突 1）。
11. hub 試法用自己的工具 `hub-bob`（`cli.json` 的 `kind` 寫 `bob`）；`add`、收題、`pause`、`stop` 都過，`open` 不過。

## 要帶給使用者的題

### 新做法跟既有原則的衝突

1. **對話簿放工作區 vs P-41／listen 放 stack**：A 的代定 3（輸入放工作區）沿用到 bob-1／bob-2；P-41 與 agent-round 放 `$AOS_STACK/history.jsonl`，`aos-listen --follow` 也只看 stack。**事實**：bob-2 跑著時 `listen --follow` 看不到它的對話。**後果**：放工作區＝外面一眼看得到、能手動接一句，但通用接口偷看不到；放 stack＝listen 原樣能偷看，跟 agent-dan 一致。**建議**：搬回 stack（照 P-41），A 的代定 3 翻案。
2. **「agent 這層沒有 ctl」**：NORMS 窗那份開頭寫「agent 這層沒有 ctl：停＝退 10 或送訊號（P-19）」。bob-2 是 agent，卻讀 ctl.json。**後果**：照字面，bob-2 只能用訊號停、沒有暫停；但使用者要的射後有理就是「跑著的時候能停一下」。**建議**：改成「**停著等的 agent**（自己不退的那種）也開 ctl 窗」——它其實就是「會反覆跑的東西」，跟 loop／daemon 同一類；一次跑完就退的 agent 照舊沒有。
3. **hub 的 pause ≠ N-07 的 paused**：hub-kernel 決定 5 的 pause＝關畫面、對話留著、**題照收**；N-07 的 paused＝不起新的一次。**事實**：`aos-hub pause` 之後 say 的題照答。**後果**：同一個詞兩個意思，用通用接口暫停時會猜錯。**建議**：hub 的那個改叫「收起」（10-27 的原名），`paused` 留給「不收新題」。
4. **兩種信箱**：任務書原本要用 N-16（aos-post），通用接口 say／listen 用的是 P-11 的題目信箱（10-29 加註：不算標準投遞）。**建議**：射後有理的塞話一律走 P-11（say 認得），N-16 留給 agent 之間的信；兩個不混。

### 原則推不出的方向題

1. **通用接口的契約定在哪一層**：say／listen 自己（程式說明）、agent 定義（每隻自己說信箱在哪）、還是介質條文（N-16／N-14）？**事實**：三方現在靠的是 P-11～P-14 加 hub 補的 `server.txt`、trace 兩樣（hub-adapter 代定 1：「沒升進 CONVENTION，用穩再說」）；bob-2 照這套一行沒改就接上了，缺的只有偷看（對話簿位置）與暫停（ctl）。**建議**：定在 CONVENTION 的 agent 對話協議（P-11～P-14 那節），把 `server.txt`、trace、stack 的 `history.jsonl`、`ctl.json` 四樣補進去；不放 N-16（那是標準投遞，信封不同）。
2. **外面管生命週期那層是誰**：aos-hub、aos-daemon，還是新東西？**事實**：hub kernel＋一題一答的工具已經做完 bob-2 的全部（等、收題、答、歸檔），不用自己寫循環；但它包不了自己會循環的程式、pause 意思不同、只會開 claude／codex 的畫面。**建議**：用 hub——它已經是「管停著的實例」的那層（hub-kernel 決定 9：hub 是 kernel 的一種）；補「一題一答的 aos agent 也能 add」（今天已經能跑）和讀 ctl.json 兩樣就夠，不另做新東西。
3. **bob-2 的「暫停」跟 aos-loop／aos-fsm 的 paused 是不是同一個**：**事實**：意思一樣（不起下一次、手上那次做完），差在「一次」多大——bob-2 是一題，loop 是一次 exec，fsm 是一格；使用者說的「暫停其狀態機、去修改更多東西」要停在格與格之間，bob-2 做不到（它沒有格）。**建議**：同一個詞、同一個意思（N-07），「一次」由各程式自己說；要停在格之間的，就是 aos-fsm agent 才有的細度。
4. **射後有理要「停著等的腦」自己寫循環，還是一律用 hub＋一題一答**：**事實**：兩種都跑通，延遲同級（3～6 秒，都是 claude 的時間）；自己寫的循環約 120 行，hub 那條只要 20 行的工具。**建議**：預設走 hub＋一題一答；只有腦本身就停著等（互動式 claude、pi 的 rpc 模式）才需要自己的循環——這正是使用者說的「寫死在定義裡」。
