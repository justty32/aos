## 頂層對八題的再想（10-29 晚；使用者「幫我多想想」後，未定）

> **頂層提法（10-29 晚，使用者還沒定，明天繼續想）**——不是決定。使用者原文見上面「使用者原文」一節。

**底層形狀：say／listen 就是「投遞＋窗」套在對話上。** `aos-say`＝把一句話**投遞**進 agent 的 queue，對話順序是意思的一部分，所以該用**有順序的投遞**（N-16 `--ordered`）；`aos-listen`＝看 agent 的**窗**（history，N-14）。通用接口不用發明新東西，是白天定的兩個基本概念的組合。

**第 4 題反對「兩種信箱並存」**：運行中塞話走 say／listen 的題目信箱（P-11 `new/`／`out/`）、agent 之間寄信走標準信箱（aos-post）＝兩套機制做同一件事（都是「有人把東西投進我的資料夾」）。題目信箱是 10-24 的老寫法、標準信箱是 10-29 才正規化的；既然 say 要當通用接口，它該走標準信箱且用 `--ordered`（隊長這次剛好沒用 `--ordered`，所以沒撞到）。順帶好處：**pending 信箱每輪開頭排進 history，兩個場景都適用**——場景一只是沒人投；對多回合的射後不理 agent，也能在回合之間插話，不必它停著等。

**第 2、6、7、8 題其實是一題：「停著等」由誰提供。** bob-2 是我們自己寫循環讓 `claude -p` 這種一答就退的腦看起來像停著等——這不是腦的本性，是裝的。使用者說「結不結束是腦的性子」對互動式 claude 成立（真的停著）；`claude -p` 的性子是退，要它停著一定有誰在外面繞圈。三個候選：

- 寫在 agent 裡（bob-2）：每個停著等的 agent 都要重做 paused／stopped／ctl 清理，隊長發現的兩個瑕疵（ctl 不清、status 看不出暫停）正是重做漏掉的。不建議。
- aos-hub：替有畫面的外部 CLI 做的（開畫面、Ctrl-]、接回舊對話），包 aos agent 多了用不到的、少了「先別動」。削足適履。
- aos-loop：10-28 定「aos-loop＝常駐＋暴露狀態＋控制手把的包裝」（medium 決定 2），paused／stopped、ctl 清理都有；一答就退的 agent 外面套 aos-loop 就是停著等。

建議：**agent 永遠是一個函數（一輪進、一輪出），停著等交給 aos-loop。** 於是第 2 題（agent 沒有 ctl）照舊不改規範；第 7 題暫停本來就是 aos-loop 的 paused；第 8 題不自己寫循環；aos-hub 只留給真的停著的外部 CLI。頂層自承：使用者先前說「這跟 aos-loop 沒關係」，那時頂層把 aos-loop 用在「退不退」上、用錯了；這次是另一題「一個會退的腦怎麼變成停著等」——對不對待使用者定。

**第 1、3、5 題同意隊長，補理由**：① history 放 `.stack/`——history 是這次執行的狀態、不是交給上層的成果（決定 26「紀錄 aos 不管」），暫停時要改的就是它；③ hub 的 pause 改名「收起」，同字兩義一定出事；⑤ 規則寫進 CONVENTION 的 agent 對話協議，但內容改成「agent 的 queue 信箱＝N-16 標準信箱的有順序實例、history＝N-14 的窗」，引用現有條文、不另定四樣新東西。

**還沒試到**：使用者的場景二「如果是 aos agent，還可以暫停其狀態機、去修改更多東西」——今晚兩個 bob 都是 `claude -p` agent、不是狀態機 agent；「停在格與格之間改東西」只有 aos-fsm agent 做得到，沒碰。下一輪試驗場值得拿一個 fsm agent 跑場景二。

**歸結成三題待使用者**：① say 改走標準信箱＋`--ordered`、題目信箱退場；② 停著等交給 aos-loop、agent 保持是函數；③ 其餘三題（1、3、5）照隊長建議。

## 決定（10-30）

使用者說「照直覺」回答，三條都可翻案；細節規劃交 fable（另一檔）。

- **決定 33**：say 可以改走標準的有順序投遞、題目信箱退場；但 **agent 這一層不用「信箱」這個詞，這層是訊息的 queue**。「請求的投遞」（agent 之間寄信）可以叫信箱、也可以叫 queue。
  - 頂層理解：queue 是概念名、有順序投遞是它底下的實作，條文與工具命名照這個分。
- **決定 34**：**aos-loop 是 aos agent 這支程式的內部組件**（停著等由它提供，agent 保持是函數）。其他 coding agent（claude code、codex）內部是黑盒子，要管它們的生命週期就在外面包東西、包括掛到 aos-daemon 底下；daemon 若管不了純 aos-exec 的東西，就擴充（aos-daemon-3 或 aos-hub 之類），總之要有一個東西能把純 aos-exec 的 proc 納管進 aos；沒有也行，Linux 的 `ps aux`＋`kill` 就夠。用現有 loop 規格把純 aos-exec 的 proc 包成 `max: 1` 掛到 aos-daemon 底下，可以。若做得到，daemon 原生能掛純 aos-exec 的子項更好（`max: 1` 是可接受的底線）。
- **決定 35**：其餘三題照隊長建議（對話簿放 stack、hub 的 pause 改名「收起」、規則寫進 CONVENTION 引用 N-16／N-14）；**另加：claude code cli 這類自己存 session 的，aos 體系要弄一份 symlink 或複製一份過來管理**。
- **決定 36**（10-30）：fable 規劃（[10-30 agent-lifecycle](../2026-10-30-agent-lifecycle.md)）的衝突六條與方向題三條都照建議（使用者「都照建議」）→ [agent-lifecycle § 決定（10-30）](../2026-10-30-agent-lifecycle/07-衝突.md#決定10-30)。
