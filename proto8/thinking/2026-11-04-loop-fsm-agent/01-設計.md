## 設計（fable 照原則定的細節，可翻案）

每條後面括號是依據。「跟 eca 一樣」＝照 [eca-claude](../../demo/README.md#eca-templates) 與 [aos-eca-turn](../../bin/README.md) 現行做法。

### 1. 範本資料夾：`proto8/demo/agent-fsm/`

- **是範本，不是程式**（使用者 10-23「範本」；C-50「資料夾布局和 json 那塊仍要保持單純」）：複製一份、改 `.env`／`system.txt`／`tools.json` 就是另一隻。跟 `demo/eca-claude` 並排、同形（P-43「包成跟 aos agent 範本同形的資料夾程式」反過來讀）。名字取使用者的話「loop fsm agent」；不叫 `aos-agent`——那個名字 11-03 留給以後的統一介面。
- 裡面的檔（每檔一句）：

```
agent-fsm/
  _entry       ["aos-loop", "loop.json"]（沒 +x 的 JSON 入口，P-40；不用 sh，10-15）
  loop.json    {"exec": "fsm.json", "interval_ms": 300, "ctl": "ctl.json", "state": "state.json"}
  fsm.json     三格表（§ 2）；帶 "_entry": ["aos-fsm", {"$env": "AOS_CF"}] 讓 aos-exec fsm.json 也能跑一次
  idle.py      收信格：queue → history（§ 3）
  brain.py     think 格：history＋system＋tools → 端點 → 接一則 assistant（§ 3、§ 4）
  act.py       act 格：照 tool_calls 跑工具、結果接回 history（§ 3、§ 5）
  system.txt   system 訊息（brain.py 的 --system 指到它；不要就拿掉旗標）
  tools.json   aos-tools 登記檔，範本只登記 clock（"../../lib/base/clock"；跟 eca-claude 同一份寫法）
  .env         AOS_BRAIN_MODEL=chatgpt-gpt-6-luna-low（P-23；不蓋外面已設的）
```

- **定義資料夾裡被程式「固定認」的名字只有 `_entry`**（aos-exec 的，N-61）：`loop.json` 由 `_entry` 指、`fsm.json` 由 `loop.json` 指、三支 `.py` 由 `fsm.json` 的 argv 指、`system.txt` 由 brain 的 `--system` 旗標指、`tools.json` 是 aos-tools 的預設名（`--tools` 可改指，同 eca 的 `tools`）。｜10-31「只有一個檔案固定，剩下的，則都由這個檔案指定」；11-04「不該在json中指定檔案名稱，應該改成用旗標指定」——跟 eca 的 `--prompt` 同一招，旗標寫在 `fsm.json` 的 argv 裡。
- 三支 `.py` 放在範本裡（複製）、不放 lib：這是 CONVENTION 的範本形（agent-eve 就是這樣）、也是 10-31「先做成單檔案，有需要再拆出來成 aos 函數」；拆的時機照 lib 規則 9「長到第三份一樣的大段再抽成共用庫」。有拉扯，寫在[方向題 1](04-衝突與方向題.md#方向題-1三格的程式放範本裡複製還是放-lib-掛捷徑)。
- **不帶**：`parts.json`、`hook/`、`trace.jsonl`、`current.txt`、`eca.json` 那種名片、任何 `AOS_*` 旋鈕（11-01、11-03 已刪或已否決的，一樣不回來）。

### 2. `loop.json` 與 `fsm.json`

`loop.json`（P-06 五個 key 用四個）：

```json
{"exec": "fsm.json", "interval_ms": 300, "ctl": "ctl.json", "state": "state.json"}
```

- `exec` 寫**字串** `fsm.json`、不寫單子：每次是一跳 `aos-exec -- fsm.json`，會 cd 進範本、讀 `.env`（`AOS_BRAIN_MODEL` 從這裡來；N-59）、設 `AOS_CF`／`AOS_CD`。直接跑時 cwd 就是範本（aos-exec 進去的）；掛 daemon 時 aos-daemon-ctl 把相對路徑轉絕對。｜agent-bob 同形。
- 沒有 `max`：常駐版靠 ctl `stop` 收工（跟 eca-claude 一樣沒 `max`）。要「跑幾次就停」自己加。
- `interval_ms` 300：queue 空時每 0.3 秒看一次，跟 eca-claude 同值；`paused`／`stopped` 的反應最慢一格加 0.3 秒。
- 開 `ctl`／`state`：P-42 的第三樣；也是 aos-daemon-ctl 認成 loop 型的條件（有 `loop.json` 就認；它一定補這兩個）。

`fsm.json`（N-36、N-38；物件 `next` 照結束碼分岔）：

```json
{"_entry": ["aos-fsm", {"$env": "AOS_CF"}],
 "start": "idle",
 "states": {
   "idle":  {"exec": {"argv": ["python3", "idle.py"]},
             "next": {"0": "think", "10": "idle"}},
   "think": {"exec": {"argv": ["python3", "brain.py", "--system", "system.txt"], "timeout_ms": 120000},
             "next": {"0": "act", "10": "idle"}},
   "act":   {"exec": {"argv": ["python3", "act.py"], "timeout_ms": 1800000},
             "next": "think"}}}
```

- **三態不變**（P-08；C-50「agent＝狀態機＋各狀態跑的 inst」）。格是行程內跑的單子（P-27 混合寫法；有邏輯但一行寫得完），cwd＝範本資料夾、相對路徑從這裡算、`timeout_ms` 守逾時（P-22）。
- **分岔讀法**：idle 退 0＝收到信→think；退 10＝queue 空→表上接住寫 state `idle`、fsm 退 0→loop 隔 `interval_ms` 再來（**停著等**，射後有理）。think 退 0＝腦要叫工具→act；退 10＝腦給了最後答案、沒事做了→idle。act 退 0→think（帶工具結果再問）。其他碼（1、128＋N）表上沒接＝state 不動、fsm 以那碼退、loop 以那碼結束＝**停下等人**（P-20 10-30 加註「表上沒接住時才是預設停」）。
- **射後不理**＝複製一份、把 idle 的 `next` 改成字串 `"think"`（10 到不了表上→fsm 退 10→loop 退 0 收工，P-19／P-35）、`loop.json` 拿掉 `interval_ms`、idle 加 `--prompt`（§ 3）。｜P-42「跑完要不要結束寫在定義裡」；eca 是 `--on-empty` 旗標、這裡是表——fsm 的格只能用結束碼說話，「queue 空要不要收工」正是「10 給誰接」，寫在表上最直接；做成旗標反而要 idle 吞掉 10、再多一條暗路（C-56 不藏暗規則）。差異記在 [02](02-跟-eca-對照.md)。
- 這張表跟被刪的 round 五格表長得像是因為同一條 N-36；不同的是沒有 more／finish 兩格、沒有 parts、沒有 hook、沒有 trace、兩種停法不開兩張表（改一行就是另一張）。

### 3. 三格各做什麼

三支都是 python3 純標準庫、不 import 隔壁（lib 規則 9）；錯一律 stderr 一行 `agent-fsm: 代號 原因`、退 1、history 不接（P-20、P-21）；要 `$AOS_STACK`（沒設＝`StackMissing`），`$AOS_WS` 沒設＝cwd。寫檔先寫 `.` 暫存再改名（N-05）。

**`idle.py [--prompt FILE]`**（收信格；eca 的 take_all＋opening 那半）

1. `$AOS_STACK/queue/` 缺 `tmp/`／`new/`／`cur/` 任一＝`aos-post init`（跟 aos-eca-turn、aos_ws.put 同一句）。
2. `cur/` 先（上次 take 了還沒接完的，P-12 精神），再 `aos-post take-all`（退 10 不算錯）。
3. 這批照 `aos_ws.letter_key` 的順序（有序在前照名字、無序在後）逐封：`aos-post see` → `body` 必須是 `{"role": "user", "content": 非空字串}`，不是＝壞信：`aos-post done` 丟掉、`$AOS_STACK/mailbox_warning.txt` 覆寫一行「信 <名> 不採用：<原因>」（跟 eca 一樣，N-16）；好信→接一則 user 進 `history.jsonl` → **立刻 `aos-post done`**（接進 history 就算收到，見[衝突 1](04-衝突與方向題.md#衝突-1信什麼時候收掉p-11-的-10-30-改口說答完才收)）。
4. 這批有好信＝退 0（→think）；一封好信都沒有（queue 空、或整批壞）＝看 `--prompt`：history 空且給了 `--prompt FILE`（相對路徑從範本資料夾算、不是檔＝`PromptMissing`、空白內容＝不投）→ 把檔內容 `aos-post send --ordered` 投進 queue 再從 2 走一次（開場白只投一次：history 非空就不投；跟 aos-eca-turn `opening` 同一條）；否則退 10。沒給 `--prompt`＝沒有開場白、不找 `prompt.txt`（eca 21 翻案）。
5. 一次收**全部**（「每次……把所有信一起丟進去(當然，是有順序的)」）：幾封就接幾則 user，think 一次答整批。

**`brain.py [--system FILE] [--tools FILE]`**（think 格；照 agent-eve 的 `brain.py` 改）

1. 讀 `history.jsonl`（壞行＝`HistoryBad`）。最後一則不是 user／tool（＝上一題答完、沒新信）＝沒事做、退 10（表接去 idle）。不會發生在正常流程（idle 退 0 才會進來），是給「人改了 history 再 resume」「重跑」用的自保（aos-round 衝突 4「每格對 state 與資料對不上要自保」）。
2. `--system FILE`：讀成一則 system 放最前面、不存進 history（P-41「system 每次從範本讀、不存」）；沒給＝沒有 system。
3. `--tools FILE`（預設同層 `tools.json`，有才接、沒有＝不給工具，同 eca 方向題 1 使用者答「如果cli.json沒有指定，那就去找默認的tools.json」）：`aos-tools --file FILE ls --json` 組 `tools` 陣列（失敗＝`ToolsBad`）。
4. 問腦（§ 4）；回覆接一則 assistant（只留 `role`／`content`／`tool_calls`，P-23）。有 `tool_calls` 退 0、沒有退 10。
5. `AOS_KERNEL_REPORT` 有設就把 `usage` 寫進去（照 eve；P-23）。

**`act.py [--tools FILE]`**（act 格；照 agent-eve 的 `act.py`）

1. 看 history 最後一則 assistant（沒有＝`HistoryBad`）。沒 `tool_calls`＝沒事做、退 10？——**不會**：表上 act 只從 think 退 0 來，一定有 `tool_calls`；真遇到（人改了 history）就退 1 `HistoryBad` 停下等人，不另開一條路。
2. 逐個（依序，不並行）`AOS_STACK=$AOS_STACK/tools/<名>/ aos-tools --file FILE call <名>`，`arguments` 原樣進 stdin，stdout 整段當 tool 訊息 `content`（P-41、P-17）。登記了沒有的工具（`ToolUnknown`）、`arguments` 不是 JSON（`ArgumentsBad`）、工具退非 0（含 10）＝接成 tool 訊息回給腦、不停（P-41 10-24 代定）；aos-tools 本身起不來＝`ToolFailed` 停。
3. 每個 tool 訊息各接一則；全部跑完退 0（→think）。

### 4. 腦怎麼叫（接 LLM 的那段）

- **照 P-23**：OpenAI 相容 `{AOS_BRAIN_URL}/chat/completions`，`AOS_BRAIN_MODEL`（範本 `.env`）、`AOS_BRAIN_KEY`（有才帶 Bearer）；`AOS_BRAIN_URL` 沒設＝**假腦**（eve 的 `fake()`：登記了 clock 就先假叫一次 clock、再答一句），測試靠它、不碰網路。只取 `content`／`tool_calls`，模型想的內容不收。
- **不經 kernel、不新加任何東西**：使用者 11-01「腦這東西未來會被統一管理……那塊就到時候再說」、10-28 決定 9「不考慮跟 kernel 的關係」。要排程或額度時，**不改 brain.py**，只把 think 格的單子換成閘門：`{"argv": ["aos-llm-send", {"$env": "AOS_CF", "$path": "#/states/think/brain"}], "timeout_ms": 120000}`＋同格一個 `brain` 單子（aos-llm-send README 現成寫法；`AOS_KERNEL` 指 kernel 信箱）。這是現有機制的組合，不是這次要做的。
- `AOS_BRAIN_*` 三個環境變數照舊（11-01 使用者「現在不動」）；掛 daemon 時由 daemon 的環境給 `AOS_BRAIN_URL`（子項繼承）或寫進範本 `.env`。

### 5. 工具怎麼接

- **`tools.json`＝aos-tools 登記檔**，跟 eca-claude **同一份格式、同一個預設名、同一條相對路徑規則**（從登記檔的資料夾算）；加工具＝`aos-tools --file tools.json add` 或手寫捷徑（lib/README「怎麼引用」）。
- **不經 aos-mcp**：aos-mcp 是給會講 MCP 的外部 CLI 用的包裝（10-27「aos-mcp 是一個小包裝，跑在 aos-tools 上」）；這隻的腦是我們自己的 brain.py，直接 `aos-tools ls --json`／`aos-tools call` 就是 P-41 的接法，少一層（C-56）。兩邊的工具箱可以是**同一份檔**——這是跟 eca 對齊最有價值的一點。
- 工具小格 `$AOS_STACK/tools/<名>/`（P-17 11-02 改）；工具的工作區＝`$AOS_WS`（lib 規則 4）。
- 腦看到的工具名＝登記名（eca 那邊是 `mcp__aos__<登記名>`，CLI 加的前綴，記在 02）。

### 6. queue、history 與對話紀錄

- **queue**＝`$AOS_STACK/queue/`，aos-post 信箱（`tmp/`、`new/`、`cur/`；`archive/` 不用），一封＝一則 OpenAI user message（P-11 10-30 改口、N-16）；有序無序同箱、有序先（11-04）。誰寄：aos-say、`aos-post send --ordered`、別的 agent 的 send_message 以後也可以。
- **history**＝`$AOS_STACK/history.jsonl`，一行一則 message、只附加（P-41）：user（idle 接）、assistant（brain 接，含 `tool_calls`）、tool（act 接）。**回答＝最新那則沒有 `tool_calls` 的 assistant**（aos-listen 現成的 `aos_ws.answers`）。**它就是全貌**：工具呼叫與結果都在裡面，不像 eca 要另外看 `transcripts/`。
- 沒有別的回答通道、不回信（eca 17「沒有回信」；P-11「回答就是 history 最新那則 assistant」）。檔案成品照舊落在工作區（工具寫的）。
- history 不設上限、沒有 compact（round 的 compact 格刪了）；要忘記＝換 stack（P-41）。
- 暫停時改 history 再繼續：`aos-daemon-ctl pause`（或寫 ctl）→ 停在格與格之間 → 改 `history.jsonl` → resume；brain 每次從頭讀，改了就生效。這是使用者 10-29「如果是aos agent，還可以暫停其狀態機，去修改更多東西」落地的樣子；eca 做不到（粒度一批信、對話在 CLI 自己手上）。

### 7. stack 佈局（`$AOS_STACK`；直接跑＝`<WS>/.stack/`、掛 daemon＝表上那列的 `stack`）

| 路徑 | 誰寫 | 誰讀 |
|---|---|---|
| `queue/`（`tmp/`、`new/`、`cur/`、`order.lock/`、`order.json`） | 寄信人 `aos-post send --ordered`；idle `init`／`take-all`／`done` | idle、aos-listen |
| `history.jsonl` | idle／brain／act 附加 | brain、act、aos-listen |
| `ctl.json` | 人、aos-daemon-ctl、daemon（`{"cmd": …}`，11-03） | aos-loop |
| `state.json` | aos-loop（有變才寫） | aos-daemon-ctl、人 |
| `state.txt` | aos-fsm（現在在哪一格；一行） | aos-fsm；人看 |
| `mailbox_warning.txt` | idle（壞信，只留最後一封） | 人 |
| `tools/<名>/` | act 叫工具時給的小格 | — |
| `loop.json`、`stderr.txt` | 只有掛 daemon 時 daemon 寫 | 人 |

沒有：`trace.jsonl`、`current.txt`、`plan.txt`（腦的決定就是 plan，P-24）、名片、log 檔（log 預設不印，N-11；要看加 `--enable-logs`）。

### 8. 跟 daemon、aos-say／aos-listen 怎麼接

- **直接跑**：`aos-exec --ws ~/proj proto8/demo/agent-fsm`（PATH 要有 impls 的 aos-exec／aos-loop／aos-fsm／aos-post、proto8/bin 的 aos-tools；跟 eca 少 aos-eca-turn／aos-mcp／claude）。stack `~/proj/.stack/`。
- **掛 daemon**：`aos-daemon-ctl add --ws ~/proj --name fsm1 proto8/demo/agent-fsm`——有 `loop.json` 就認成 loop 型，小格 `$AOS_DAEMON_STACK/procs/fsm1/`；`stop`／`start`／`pause`／`resume`／`rm`／`where --stack` 全部現成（11-03 procs、ctl-commands）；收工 `sleeping`、再開自動 wake、同一個 stack 接著對話。**零改動**。沒有 `aos-eca` 那種包一層的命令列：它多出來的事（畫面、session 檔、名片、`ls` 篩 eca）這隻一樣都沒有，直接用 aos-daemon-ctl 就是全部；以後的 aos-agent 再統一包。
- **aos-say／aos-listen 一字不改**（P-42 10-30 夜改口「aos-say／aos-listen 不分後面是誰」）：`aos-say --ws ~/proj 話 && aos-listen --ws ~/proj`；掛 daemon 的加 `--stack $(aos-daemon-ctl where --stack fsm1)`（跟 eca 一樣）。listen 的「信不見了→history 最後是 user→還在答」那條判法對這隻也成立（idle 收信就 done、brain 還沒答）。`run_hint` 沒人跑時印 `aos-daemon-ctl start 名字`（stack 裡沒 `eca.json` 就走這條）——已經對。
- **一次只能一個人在跑同一個 stack**（P-18）：aos-say 只寫 queue，不會撞；兩隻 agent 同一工作區要給不同 stack。

### 9. 失敗與邊緣狀況

| 狀況 | 怎麼辦（照哪條） |
|---|---|
| 腦連不上、HTTP 非 2xx、回覆形狀不對 | brain 退 1（`BrainFailed`／`ReplyBad`），history 不接、`state.txt` 停在 `think`；loop 退 1 停下等人（P-20）；掛 daemon 的從表上拿掉、stack 留（11-02）。修好後 `aos-exec` 或 `aos-daemon-ctl add` 同名同 stack 再起→fsm 從 `think` 接著問同一題 |
| 腦逾時 | think 單子 `timeout_ms` 120000 到＝整群 SIGTERM、碼 143、同上停下等人（P-22、P-36） |
| 工具退非 0、工具名不存在、arguments 壞 | 接成 tool 訊息回給腦、不停（P-41） |
| aos-tools／aos-post 不在 PATH、起不來 | `ToolFailed`／`PostFailed` 退 1 停下等人（C-53 入口默認正常） |
| 壞信（body 不是 user message、letter.json 壞） | done 丟掉＋`mailbox_warning.txt` 一行，其他封照答；整批壞＝當 queue 空（跟 eca 一樣） |
| idle 在 take-all 之後、接進 history 之前被殺 | 信留 `cur/`，下次 idle 先接 `cur/`（§ 3 第 2 步）；接了但 done 之前被殺＝下次會重接一則一樣的 user（兩步之間的窄窗，N-05 管單檔、不管兩檔；可接受的邊緣） |
| 思考中有新信進來 | 留在 `new/`，答完回 idle 才收（這批一起答）；要「打斷」見[方向題 2](04-衝突與方向題.md#方向題-2思考中來了新信等答完還是打斷) |
| 收到 `{"cmd": "pause"}` | loop 在這格跑完後暫停（粒度＝一格）；新信留 `new/`；resume 從下一格接 |
| 收到 `{"cmd": "stop"}`、daemon `stop` | 這格跑完 loop 退 0、phase `stopped`；`state.txt` 留在停的那格（可能是 think／act 中途），`start` 從那格接——對話不丟 |
| daemon 收工（Ctrl-C） | 子 loop SIGTERM→fsm 等這格跑完、寫好 state 再退 143、表上 `sleeping`；再開 daemon 自動 wake 同一 stack（11-03 § 8） |
| 人在暫停時改了 history（刪掉最後幾則） | brain 自保：最後一則不是 user／tool＝退 10 回 idle 等新信；act 遇到沒 `tool_calls`＝`HistoryBad` 停（§ 3） |
| history 第 N 行壞 JSON | `HistoryBad` 停下等人（P-41） |
| `--prompt` 指的不是檔、`--system` 指的不是檔、`--tools` 指的不是檔 | 入口就報 `PromptMissing`／`SystemMissing`／`ToolsMissing`、退 1（C-54 主題＋`Missing`；沒給旗標＝沒有，不是錯） |
| 同一工作區起第二隻 | 要給不同 `AOS_STACK`（P-18）；不擋 |
| 掛 daemon 卻沒給 `AOS_BRAIN_URL` | 假腦照跑（P-23 的設計）——daemon README 要提醒一句 |
