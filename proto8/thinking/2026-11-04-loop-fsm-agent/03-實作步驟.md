### 測試清單（`test_agent_fsm.py`；每案一句）

1. **範本形狀**：五個固定檔在、`_entry` 是 `["aos-loop", "loop.json"]`、`loop.json` 有 `ctl`／`state`、`fsm.json` 三格、`next` 形狀合 N-36、`tools.json` 列出 clock、沒有 `parts.json`／`prompt.txt`／`cli.json`。
2. **一問一答**（假腦）：起 agent → `aos_ws.put` 一封 → 等 history 出現沒 `tool_calls` 的 assistant → 四則順序對、`tools/clock/` 在、信已不在 `new/`／`cur/`、`state.txt` 回 `idle`、`mailbox_warning.txt` 不在。
3. **整批**：連寄三封再起 agent → history 前三則都是 user、只問腦一次（assistant 一則帶 tool_calls）。
4. **壞信**：body 是 `{"role": "assistant"}`、`{"role": "user", "content": ""}`、非物件各一封夾一封好信 → 壞的三封 done、`mailbox_warning.txt` 一行（最後一封）、好信照答。
5. **無序信排後面**：`aos-post send`（沒 `--ordered`）一封＋`--ordered` 一封 → history 裡有序那則在前。
6. **開場白**：`fsm.json` 的 idle 加 `--prompt prompt.txt`（相對範本）→ 不 say 也答；再起一次（history 非空）不重投；`--prompt` 指不到＝`PromptMissing` 退 1 不碰 queue；沒旗標、同層有 `prompt.txt` 也不投。
7. **停著等 vs 收工**：範本（表接 10）queue 空時 loop 不退、`state.json` phase 在 waiting／running 之間，寄一封就答；複製一份把 idle `next` 改 `"think"`＋拿掉 `interval_ms` → queue 空 loop 退 0。
8. **腦失敗停下等人**：`AOS_BRAIN_URL` 指到沒人聽的 port → brain 退 1 `BrainFailed`、loop 退 1、`state.txt`＝`think`、history 最後一則是 user；拿掉 URL 再起同一 stack → 從 think 接著答、history 不重複 user。
9. **工具錯回給腦**：`tools.json` 登記一個會退 1 的假工具、假腦先叫它 → tool 訊息尾巴有結束碼、agent 不停、最後有答案。
10. **`--system`／`--tools`**：`--system` 指的檔內容出現在送出的 request（假腦存 request 到 stack 給測試看，或用 `AOS_BRAIN_URL` 指到測試起的假 HTTP 端點）；`--tools` 指別的登記檔就用那份；指不到＝`SystemMissing`／`ToolsMissing`；沒 `tools.json` 也沒 `--tools`＝不給工具、照答。
11. **人改 history 再跑**：暫停後把最後一則 assistant 刪掉再 resume → brain 重問；把最後一則改成沒 `tool_calls` 的 assistant、`state.txt` 寫 `think` 再起 → brain 退 10 回 idle 等信。
12. **掛 daemon**（照 `test_eca_cmd.py` 起 daemon 的寫法）：`aos-daemon-ctl add` → 表上 running → `aos_ws.put` 到 `where --stack` → 答；`pause`→phase paused、新信留 `new/`；`resume` 答；`stop`→`stopped`、`start` 接著答；`rm` 下表。
13. **P-42 三樣以外不碰工作區**：跑完工作區只有工具寫的東西（clock 不寫）＝工作區空。
