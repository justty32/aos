## 結論（AI 整理；10-15 使用者照建議採納，第 5 條改法見「決定」）

### 一、資料夾⇄JSON 怎麼對

**對應規則**（一個資料夾＝一個 object）：

- 資料夾＝object；裡面每個項目的名字＝key。
- 子資料夾＝值是 object。
- `.json` 檔＝值是那份檔的內容（整份 JSON）。key **保留副檔名**（`agent.json`，不是 `agent`），這樣無損、也跟 N-35 的 `檔#/位置` 一致：`bob/agent.json#/states` 與「把 bob 當 object 後的 `/agent.json/states`」指的是同一塊。
- 其他檔（`.md`、`.py`、二進位）＝不展開，只放一個存根，例 `{"$file": "text"}`／`{"$file": "bin"}`（要的話帶 `size`、可執行位）。
- 反方向（object → 資料夾）只攤到「一個檔＝一份 JSON 文件」為止，不往下拆成一個值一個檔。

**細節差異**（意見 5 說的「細節有差異」具體在這幾處）：

| 差異 | JSON 這邊 | 資料夾這邊 | 後果 |
|---|---|---|---|
| 陣列 | 有，有順序 | 沒有；只能用 `0`、`1`… 當名字 | 分不出「陣列」和「key 剛好是數字的 object」；`10` 排在 `2` 前面；中間插一個要改一串名字 |
| 順序 | key 理論上沒順序，實作大多保留寫入順序 | 列目錄的順序看作業系統 | 來回轉一趟順序可能變；要固定就排序 |
| 名字能用的字 | 任何字串，含 `/`、空字串、`.`、`..`、很長的字 | 不能有 `/`、`\0`，不能是空、`.`、`..`，長度約 255 bytes；Windows 還不准 `:*?"<>|`、`CON` 這類名字 | 很多 key 攤不成檔名；JSON pointer 用 `~1` 寫 `/`，檔名沒有對應寫法（N-35 已說：空字串的 key 指不到、`#` 不支援） |
| 大小寫 | `A`、`a` 是兩個 key | macOS、Windows 預設不分大小寫；macOS 還會改 Unicode 的組合方式 | `{"A":1,"a":2}` 攤不出去 |
| 葉子的型別 | 字串、數字、true/false、null | 只有檔案（一串 bytes） | 一個檔寫著 `3`，是數字 3 還是字串 "3"？要另定規則；`1.0` 與 `1`、大整數精度也會跑掉 |
| 空 | `{}`、`[]`、`null` 三種 | 空資料夾、空檔、不存在 | git 不收空資料夾，`{}` 提交後就消失；`[]` 與 `null` 沒有自然對應 |
| 隱藏檔 | 沒這回事 | `.` 開頭的檔：N-05 的暫存檔、`.done`、`.git`、`.aos/` | 要定算不算；暫存檔算進去會讀到一半的東西 |
| 檔案自己的屬性 | 沒有 | 可執行位、symlink、時間、硬連結 | inst 的 argv[0] 要可執行位，JSON 表達不了 |
| 一次寫完 | 一份檔「寫暫存再改名」就整份換掉（N-05） | 好幾個檔不能一次換掉 | 改到一半有人讀，會讀到半新半舊——state／ctl 窗攤成資料夾就壞了 |
| 同名 | 不會 | `x` 和 `x.json` 可以同時在 | 去掉副檔名當 key 就撞名（所以上面規則保留副檔名） |
| `#` 的意思 | — | N-35 現在說「`資料夾#/位置`」是先找資料夾裡的 inst.json 再套位置 | 跟「資料夾＝object」的看法打架：`bob#/agent.json` 照 N-35 是 inst.json 裡的 key，不是 bob 底下的檔 |

**劃線**（「別濫用」建議停在這裡）：

- **可以互通**：拿來**看**（aos tree 印樹、inline、diff）、拿來**驗**（下面的 schema），以及**定義類**的樹（agent 定義、fsm 表、設定），而且名字守「安全子集」：非空、不以 `.` 開頭、只用英數與 `_-.`（中文也行）、同一層不靠大小寫區分。
- **別攤**：
  - 執行期的窗（state／ctl／lock）：要一個檔原子換掉，不攤成資料夾。
  - 陣列：整個留在一份 `.json` 裡，不攤成 `0/`、`1/`。
  - 單個純值：不做「一個值一個檔」，攤到一份 JSON 文件為止。
- **規範不動**：互通只當工具與思考方式（跟 aos_tree 一樣不入規範）；N-35 的 `#` 繼續當「檔案系統｜JSON」的分界，不讓它穿過資料夾。

### 二、JSON schema 在這套體系能用在哪

位置照同像性決定 6：inst 上的私有 key `_schema`（`{"stdin", "stdout"}`）。每條附一句評估：

1. **LLM 的回話**（判官 run／defer／reject、think 格吐的 tool_calls）：**最值得先做**。小模型常亂回（[judge-live](2026-10-15-judge-live.md) 4 次空了 2 次），驗不過就退回規則；OpenAI 相容的 `response_format: json_schema` 還能直接拿同一份 schema 約束模型輸出。
2. **工具參數 `_tool.parameters`**：已經在用，零成本。
3. **inst 的 stdin／stdout 簽名（`_schema`）**：值得寫，當「標頭檔」（C-42）；先在測試與工具裡驗，執行期不驗。
4. **fsm 表**（`start`／`states`／`end`、格的雙形用 `oneOf`）：值得做一份共用的，能抓打錯字；但「`next` 指到的格存在」schema 說不出來，要小程式補。
5. **agent 定義**（fsm 表＋`brain`／`tools`／`system`）：用 `allOf` 疊在 fsm 那份上就好；意見 1～4 若改 agent 結構，這份跟著改。
6. **binding／call 的型別檢查**：如果 binding＝「拿一棵樹填幾個 key」（同像性 8、意見 4），填完那棵過 callee 的 stdin schema 就等於型別檢查；細節歸意見 1～4 那份。
7. **閘門的信**（inst 族＋`priority` 雙形）：中等，信的形狀已穩定，可以補。
8. **窗族**（state／ctl、loop.json／daemon.json）：把規範條文配一份 schema 當附件，別人另寫實作時可以拿來對；中等，不急。
9. **lib 說明頁的「認得的 key」表**（C-48 要求列）：schema 本身就是那張表，可以反過來從 schema 產生；低成本、可順手做。
10. **agent 改自己的樹之前先驗**（同像性 5）：改完過 schema 才落檔，防改壞；等自我改進動工再說。

一個要注意的：C-48 說「只處理認得的 key、可以隨意加 key」，所以 schema **預設不寫 `additionalProperties: false`**；只有像判官回話這種封閉的 stdout 才關起來（judge.schema.json 已是這樣）。`_` 開頭的私有 key 一律放行。

### 三、意見 7：用 schema 規範資料夾——可行，但只管得到「形狀」

做法：先照第一節把資料夾轉成 JSON，再對那份 JSON 套 schema。拿 demo 的報時員 `demo/fsm/clerk/` 試過（10-15 用本機 jsonschema 4.26 跑過一次，通過）：

轉出來（`.json` 這裡為了簡短也只放存根；實際可以把內容放進去）：

```json
{"agent.json": {"$file": "json"}, "brain.json": {"$file": "json"},
 "clock.json": {"$file": "json"}, "system.md": {"$file": "text"}}
```

「一個 agent 定義資料夾」的 schema：

```json
{
  "type": "object",
  "required": ["agent.json"],
  "properties": {
    "agent.json": {"$ref": "agent.schema.json"},
    "system.md": {"properties": {"$file": {"const": "text"}}}
  },
  "patternProperties": {"\\.json$": {"type": "object"}},
  "additionalProperties": {"properties": {"$file": {"enum": ["text"]}}}
}
```

**表達得出來**：

- 必須有哪些檔（`required`）、某個名字一定是資料夾或檔。
- 某類檔名（`*.json`）的內容形狀——`.json` 展開成內容時，`agent.json` 就直接套 agent 那份 schema。
- 其他檔只准哪幾種（例：只准文字、不准二進位）、名字要符合什麼樣式（`patternProperties`、`propertyNames`）。
- 檔案大小上限、要不要可執行位——前提是存根有帶這些欄位。

**表達不出來**：

- **互相指的關係**：`agent.json` 的 `"brain": "brain.json"` 指的檔要存在、`next` 指的格要存在——schema 沒有「這個值要等於另一處的某個 key」。補法：先用 aos_tree `inline` 把路徑攤成物件（檔不在就攤失敗），再驗攤好的那份。
- **非 JSON 檔的內容**：`system.md` 寫得對不對、`.py` 能不能跑、二進位是什麼格式。
- 第一節那些細節：大小寫撞名、空資料夾被 git 吃掉、讀到一半的暫存檔——在轉成 JSON 之前就已經丟了或要先定規則。
- 順序（資料夾本來就沒有）。

**Python 原型怎麼做**：

- 轉換：一個 `dir_to_json(資料夾, 展開=True)` 約 30 行，放 aos_tree 當 `outline` 的反方向（aos_tree 本來就不入規範）。
- 驗證：本機有 jsonschema 4.26，但 proto8 lib 的慣例是純標準庫，判官測試也是手寫最小驗證器。建議**自寫最小子集** `aos_schema.py`（`type`、`properties`、`required`、`additionalProperties`、`patternProperties`、`items`、`enum`／`const`、`oneOf`／`allOf`、同檔與相對檔 `$ref`，約 100 行），import 得到 jsonschema 就改用它，測試兩邊各跑一次對照。
- 指令：`aos_schema.py check SCHEMA TARGET`，TARGET 是檔、`檔#/位置` 或資料夾（資料夾先轉）；錯照 N-29 形狀吐。

## 決定（10-15 使用者拍板）

使用者原文：「.aos這塊例外，我覺得可以用環境變數來定，也就是AOS_DIR。剩下就按照建議。」

1. **互通只當工具與思考方式**，不進規範（同 aos_tree）。
2. **攤到一個檔＝一份 JSON 文件為止**；陣列與 state／ctl 窗不攤。
3. **key 保留副檔名**（`agent.json`）。
4. **非 JSON 檔用存根** `{"$file": …}`，要內容另開選項。
5. **隱藏檔略過**（`.` 開頭一律不算）；例外的那個資料夾名字不寫死，**由環境變數 `AOS_DIRNAME` 決定**（資料夾名，語意同 proto7-1 的 `aos_dirname.py`：單一名字、不含 `/`、不是 `.`／`..`），沒設時預設 `.aos`。
6. **N-35 的 `資料夾#/位置` 維持**「先找 inst.json」，`#` 不穿過資料夾。
7. **schema 先用在 LLM 回話**（判官、think 吐的 tool_calls）和**一份 fsm 表 schema**，agent 定義用 `allOf` 疊上去；其他等需要。
8. **驗證時機**：測試與 `aos_schema check` 先用；執行期只在 LLM 回話驗（驗不過＝當錯，照現有退回規則）。
9. **驗證器自寫最小子集**，import 得到 jsonschema 就改用它（守純標準庫）。
10. **資料夾布局的 schema 放 lib 共用**（例 `lib/schema/agent-dir.schema.json`，驗證時指定），一類資料夾一份。
11. **`additionalProperties` 預設開**，只有封閉回話才關。
12. **變數名用 `AOS_DIRNAME`**（不用 `AOS_DIR`：proto4-2 用過 `AOS_DIR`，意思是資料夾的絕對路徑）。使用者原文：「那還是AOS_DIRNAME好了」
13. **aos_inst 找 inst.json 也跟 `AOS_DIRNAME` 走**（現在寫死 `.aos/inst.json`，改成 `$AOS_DIRNAME/inst.json`，沒設＝`.aos`）。使用者原文：「都AOS_DIRNAME」
