（同一晚稍早：「inst 這塊沒啥好說的，就那樣，從命令行，到 python 函數，就那樣。」所以題目是 run() 那幾個關鍵字參數要不要搬進 inst.json，不是改 inst 的形狀。）

看完第一版後：

結束碼那句的更正：

> inst 那塊錯了，我是說，就直接返回 inst 本身的結束碼就好，json 寫的那個呼叫的結束碼會自然輸出到 json 中定義的 exit 那邊。

拍板：「全部按照我說的改。寫。」「timeout、grace 都放 inst 內。」

## 2. 決定

**結束碼**
- 只有「0＝正常、非 0＝錯誤」是慣例；124、125～127、128＋N 這些細分只供參考，不設計、不當規矩（數字照舊留著）。
- **inst 只回自己的碼**：0＝inst 正常做完，非 0＝inst 本身有問題（讀不到、格式錯、起不來）。子程式的碼**不經由 inst 傳出**，照 json 的 `exit` 欄位寫進那個檔——子程式回非 0，inst 照樣回 0。
- exit 檔裡的數：子程式自己結束＝它的碼；被訊號停掉＝128＋N。json 沒寫 `exit` 就沒人記，是寫單子的人的選擇。
- 10-14 放寬：exit 檔照寫，aos-inst 的 stdout 結果也可以帶子程式的碼（[10-14 §2](2026-10-14-json-entry/03-決定未決.md)）。

**命令列與 run()**：照 10-14 D-1～D-4（[10-14 §4](2026-10-14-json-entry/04-argv與七題.md)）——命令列有鏡射旗標與 `--`；TARGET 與 stdin 二選一；`run()` 收路徑或 dict。

**timeout_ms、grace_ms 進 inst.json**

```jsonc
{
  "argv": ["sh", "-c", "date +%H:%M:%S"],
  "cwd": {"$env": "DEMO_OUT"},
  "stdout": "tick.out", "stdout_append": true,
  "exit":   "tick.exit", "exit_append": true,

  "timeout_ms": 5000,     // 正整數；沒寫＝不限時
  "grace_ms":   2000      // 非負整數；沒寫＝2000；0＝直接 SIGKILL
}
```

- `parse()` 多驗這兩格（型別錯＝`FieldType`，同現在），填進回傳的 dict。其他 key 一個都不加。
- 這兩格是單子的事，loop 外層和 ctl.json 都不放（見 [ctl 規範](2026-10-12-ctl-norms.md)）。

**不動的**：`find()`／`load()`／`parse()` 的路徑規矩；argv 一律陣列；指示詞。

## 4. 未決（待使用者確認，各附 AI 建議）

- **Q-A 原本四個監工參數（`stop`、`stop_poll_ms`、`forward_signals`、`new_session`）去哪？** 建議全拿掉：run() 在主執行緒時一律轉訊號；loop 改成起 `aos_inst.py TARGET` 當子程式（`start_new_session=True`），要停就整群送 SIGTERM、過 grace 整群 SIGKILL；`stop_poll_ms` 併進 loop 的 `ctl_poll_ms`；loop 的 `last_error` 從 aos_inst 的 stderr 那一行來。
- **Q-C 限時到了或被停止，算不算 inst 出錯？** 建議不算：inst 收掉它、寫 128＋N 進 exit 檔，自己回 0。
- **Q5 要不要防寫錯 key？** 建議不防：照 N-04 原樣，文件把 key 表列死、之後只加不改名。
