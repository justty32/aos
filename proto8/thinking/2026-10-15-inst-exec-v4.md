## 約束（本稿每一條都要過這幾關；依據的條號）

1. **指示詞不是機制**——C-48 原文：「指示詞（`$ref`／`$env`）是這招的一種用法，只是拆檔與讀環境變數的便利，設計不依賴它——設計對它的認知只要『自己的一些檔案可以透過指示詞拆成小檔』就好。」這次落成 **N-45**：設計一律假設沒有指示詞可用；JSON 大不是問題。**過關判準：把全稿的 `$ref` 手動展開、或完全不用，意思不變。** 本稿正文零 `$ref`，只在最後一段提一次。
2. **KISS 最高（C-56）**、**層徹底切割（C-52）**：agent 不知道工具內部；aos-exec 不知道 agent；aos-inst 不知道 aos-exec。
3. **N-12**：可呼叫的程式 stdin＝參數。aos-inst 只吃 stdin、命令列零引數（已定 3）。
4. **已定不重開**：`cwd`／`stdin`／`stdout`／`stderr` 從 aos-inst 的 cwd 算、沒寫 `cwd`＝在呼叫者站的地方跑（已定 2）；TARGET 從命令列與 JSON 裡全拿掉（已定 5）；不 `$abs_path`、不環境變數、aos-exec 不 cd、不寫檔（已定 6）；`$ref` 從所在檔算、不解 symlink（已定 1，只關拆檔）。
5. **少用 sh**（這次新定，記進 [user.md](../../wf/workflows/common/user.md#少用-sh2026-10-15-定)）。
6. **C-46**：frame＝被叫者跑的 cwd，`args.json` 進、`ret.json` 出，放同名檔＝綁定，呼叫方決定 frame 放哪；bob/ 裡的腦與工具只是預設值。**N-27**：子程式的參數走 `stdin`。**N-36／N-37**：格＝一張 inst，fsm 不碰格的 stdin。**N-28**：daemon children 可內嵌物件。**N-35**：`檔#/位置`、資料夾找 inst.json。

## 第三版錯在哪（兩句）

機制其實已經是「定義在 stdin 裡」，但整份稿用 `$ref` 畫圖、把 `$ref` 寫進機制說明（bob 的四個檔、工具 inst 的 `stdin: {"$ref"}`、判官「用 `$ref` 拆」），讀起來就是靠 `$ref` 在搬定義——違反 C-48。另外 `stdin` 偷偷收雙形（字串＝檔、物件＝內嵌）、agent 當工具靠 `sh -c`，兩樣使用者都打回。

## 核心（結論）

**一個 agent 的定義＝一張 inst（一份 JSON）。** 跑 bob＝把這張 inst 灌給 aos-inst；它跑在哪（cwd）就是 frame。定義不在資料夾裡、不在環境變數裡、不在任何路徑裡——它就在 stdin 那份 JSON 裡，所以在哪個 cwd 叫都一樣，什麼都不用找。資料夾形（bob/ 裡 loop.json、fsm.json、cells/…）只是這份 JSON 用指示詞拆開的樣子，拆不拆都一樣（N-45）。

```
cd /home/a/workspace
echo '{"question": "幾點？"}' > args.json     # 引數＝frame 的 args.json（C-46）
aos-exec ../agents/bob                         # 讀 bob/inst.json → 灌 aos-inst；cwd 仍是 workspace
cat ret.json
```

bob 一份 JSON 長這樣（零指示詞；`…` 是省略，不是語法）：

```jsonc
// /home/a/agents/bob/inst.json —— 整份就是一張 inst
{"argv": ["aos", "loop"], "stdin_inline": true, "stdin": {
  "times": 20, "stop_on_end": true, "ctl": "loop/ctl.json", "state": "loop/state.json",
  "inst": {"argv": ["aos", "fsm"], "stdin_inline": true, "stdin": {
    "start": "intake", "state": "fsm/state.json", "end": ["done", "halted"],
    "states": {
      "intake":   {"val": {"argv": ["aos", "agent", "intake"]}, "next": "thinking"},
      "thinking": {"val": {"argv": ["aos", "agent", "think"], "timeout_ms": 200000,
                           "stdin_inline": true, "stdin": {
                             "brain":  {"argv": ["aos", "brain", "openai"], "stdin_inline": true,
                                        "stdin": {"base_url": "http://localhost:4000/v1", "model": "…"}},
                             "system": "你是 bob，會報時。",
                             "tools":  {"clock": {"argv": ["aos-demo", "clock.py"], "stdin": "args.json", "stdout": "ret.json",
                                                  "_tool": {"description": "報現在時間", "parameters": {…}}}}}},
                   "next": "route"},
      "route":    {"argv": ["aos", "agent", "route"]},
      "tool":     {"val": {"argv": ["aos", "agent", "tool"], "stdin_inline": true, "stdin": {"tools": {…同上…}}},
                   "next": "thinking"},
      "done":     {"argv": ["aos", "agent", "done"]}}}}}}
```

- `loop/`、`fsm/` 窗、`history.json`、`work/`、`ret.json` 全落在 workspace（已定 2）。同一個 bob、兩個 workspace 同時叫互不相干。
- **綁定**照 C-46：workspace 放 `brain.json`／`system.md`／`tools/x.json` 就蓋過定義裡的同名東西（未決 F）。frame.json、`parent` 鏈都不需要（未決 E）。
- 只需要一件新東西：**inst 的 `stdin` 可以明說「我是內嵌的」**（未決 D，`stdin_inline`）。aos-inst 用管線把它餵給子程式，不落檔。

### aos-exec（第三版照抄，只改 A）

```
aos-exec TARGET [--key 值 ...] [-- argv...]      # TARGET 必填（A）
```

讀 TARGET（檔或資料夾：先 `<資料夾>/$AOS_DIRNAME/inst.json`、再 `<資料夾>/inst.json`，N-35 的找法搬到 aos-exec 名下；可接 `#/位置`）→ 旗標蓋 key、`--` 蓋 `argv`（N-22～N-24）→ 同行程交給 aos-inst 跑（B）。不 cd、不寫檔、不讀自己的 stdin 當設定、不認得 agent。它只是「`cat x.json | aos-inst` 再加旗標」。

### 工具（agent 當工具，零 sh）

C-46 說工具是函數、frame 是 stack；那工具的呼叫方式就只有一種——**frame**：

- tool 格對**每一張**工具 inst 做同一件事：開 `work/<n>/`、把模型給的 arguments 寫成那裡的 `args.json`、以 `cwd: work/<n>/` 跑那張 inst、跑完讀 `work/<n>/ret.json` 當結果（N-12 半份不算；沒有＝工具失敗）。**不碰工具 inst 的 `stdin`／`stdout`**，不接 `stdout.json`。agent 只知道「args.json 進、ret.json 出」，不知道工具裡面是什麼。
- 一般工具（clock）：inst 自己寫 `"stdin": "args.json", "stdout": "ret.json"`（兩個都是現成 key，從 work/<n>/ 算，已定 2）。
- agent 當工具（painter 叫 brush）：工具 inst＝brush 的那張 inst 加 `_tool`，argv 直接是 `aos loop`——brush 的 loop 跑在 work/<n>/，intake 讀 args.json、done 寫 ret.json，就是它自己的 frame。零 sh、零路徑、零環境變數（`AOS_DEMO` 退場）：

```jsonc
// painter 定義裡 tools 的 brush 那格
{"argv": ["aos", "loop"], "stdin_inline": true, "stdin": {…brush 整份 loop 設定，同上面 bob 的形狀…},
 "timeout_ms": 500000, "_tool": {"description": "叫畫筆備顏料", "parameters": {…}}}
```

這跟 [kiss/agent](2026-10-15-kiss/agent.md) 第 3 條（拿掉 `work/<n>/`、只用 stdin／stdout）相反：那條要 agent 當工具時用 `sh -c 'mktemp … && cat > args.json && …'`，使用者「少用 sh」之後走不通。本稿留 `work/<n>/`，但比現況更少：不再把 args.json 同時當 stdin、不再接 stdout.json。

### JSON 裡原本的 TARGET 字串（H）

原則一句：**凡是原本放「一個 TARGET 字串」的地方，現在放那份 JSON 本身**。這是資料形（N-45：JSON 大沒關係），不是為了 `$ref` 才這樣寫；要拆再拆，拆了也不改意思。

| 地方 | 現在放什麼 |
|---|---|
| loop `inst` | 一張 inst（本來就是） |
| daemon `children` 每項 | 一份 loop 設定；**`id` 必填**（缺＝`IdMissing`） |
| daemon `policies.child_exit` | 一張 inst |
| 閘門 `target`、kernel 的 gates／judges | 一張 inst（判官＝一個 agent＝一張大 inst，整份寫進去） |
| fsm 的格 | 一張 inst（純值形）或 `{"val": <inst>, "next"}`；N-36「格從表所在資料夾算」那句刪 |
| agent 設定的 `brain`、`tools` 每項 | 一張 inst |
| tasks seq／par／if／not 的 argv | 改從 stdin 收：seq／par＝一串 inst、if＝`{"cond", "then", "else"}`、not＝一張（[kiss/overview](2026-10-15-kiss/overview.md) 第 5 條若過＝四支刪掉，這列不用做） |

## 約束之間的矛盾（已定：(a)，10-15 深夜使用者「C-50 選 a」）

**只有一處：C-50「資料夾是正本（單檔可互通）」vs 本稿「一張 inst 是正本」。** 不靠指示詞、不靠環境變數、不靠 TARGET、aos-exec 不寫檔——這四條同時成立時，「bob 的資料夾在哪」這個資訊沒有任何通道能從 aos-exec 的命令列傳到跑起來的 loop／fsm／格手上，所以資料夾不能是機器認的正本。三條最小解法：

- (a) **JSON 是正本，資料夾＝拆檔**（本稿）：C-50 那句改成「定義＝一張 inst；拆成資料夾是指示詞的便利」。代價：bob 要一眼看全貌得看一份大 JSON（使用者已說「不用擔心 json 太大」）。**推薦。**
- (b) 資料夾是正本：那就必須有一條「資料夾在哪」的通道，只剩三條都被拿掉的路——TARGET 字串、環境變數、`$abs_path`。不選：要翻已定 5、6。
- (c) 兩者都正本、靠一支程式互轉（aos_tree 那種）：不選：兩套東西做一件事，aos_tree 已刪。

## 指示詞在這套裡剩下的角色（唯一提到 `$ref` 的一段）

把上面任何一份大 JSON 的某一塊換成 `{"$ref": "檔"}`，那塊就變成一個檔，基準＝這個指示詞所在的檔的資料夾（已定 1）。所以 bob/ 可以長成 inst.json＋loop.json＋fsm.json＋cells/＋brain.json＋tools/——那是同一張 inst 的拆檔版，aos-exec 讀的時候攤回來，跟手寫一整份沒有差別。設計、規範、lib 程式都不知道有人拆過。
