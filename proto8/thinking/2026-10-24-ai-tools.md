## 結論

**範圍**：只做「用 aos 指令與資料夾」這一層——起 agent（從範本產生資料夾）、丟題、`aos-exec` 跑一次、看 state／trace、經 daemon 的 ctl 加減子項、停、讀結果與錯誤一行。同日平行的嘗試（JSON 修改工具集、agent 當工具、claude／codex CLI 當工具、LLM kernel）不重做：JSON 編輯只留一個接口 `aos-ai edit`（交給 `$AOS_AI_JSON_EDITOR`）。

**兩種 AI、一個核心**：做一支命令列 `aos-ai`（Python、只用標準庫），每次 stdout 一行 JSON；兩種 AI 都轉叫它——

- ① 外部 coding agent（Claude Code、Codex）：一份 Claude Code **skill**（`ai_tools/claude_skill/aos/SKILL.md`，同資料夾帶 `.claude-plugin/plugin.json` 所以也是 plugin；`claude plugin validate` 過）。MCP server 這輪不做（理由：要多一層協定、多一個常駐行程；CLI＋skill 在 Claude Code 與 Codex 都能用，Codex 讀 SKILL.md 就是一份精簡說明）。
- ② 我們自己的 agent-dan 的腦：三個掛得上去的工具 `dan_tools/{spawn_agent, ask_agent, agent_status}`（P-41 的形狀：`tool.json`＋`_entry`，arguments 從 stdin 進、stdout 一行 JSON）。

## 決定（使用者 10-24「都按建議做」，照推薦定、可翻案）

1. **形狀**：核心是 CLI＋JSON 輸出；① 給 skill（也是 plugin），不做 MCP；② 給 agent-dan 三個工具。
2. **名字**：資料夾 `proto8/ai_tools/`（C-54 資料夾小寫底線），指令 `aos-ai`；子資料夾 `bin/`、`dan_tools/`、`claude_skill/aos/`；工具名照 OpenAI function 慣例用底線（`ask_agent`）。
3. **工作資料夾（root）**：`--root` ＞ `$AOS_AI_ROOT` ＞ cwd；只寫 root 底下，`--ws`、`edit` 的檔都檢查；名字只收 `[a-z0-9][a-z0-9_-]*`。不刪任何東西、不碰 git。
4. **root 的佈局**：`agents/<名>/agent/`（範本複本）、`agents/<名>/ws/`（工作區，stack 在 `ws/.stack/`）、`agents/<名>/runs.jsonl`（aos-ai 每次 run 一行）、`daemon/`（一個 root 一個 aos-daemon）。
5. **範本**：`--from` 收 `proto8/demo/` 底下的名字或路徑，預設 `agent-dan`；`spawn` 是整份複製（不是連結），之後改這隻不影響範本。
6. **前景 run**：`aos-exec --ws ws agent`，`AOS_STACK` 明寫成 `ws/.stack/`（被別的 aos 程式叫時外面的 `AOS_STACK` 不漏進來）；預設 300 秒逾時，到了 SIGTERM 整群、10 秒後 SIGKILL。
7. **結果與錯**：agent 跑失敗是資料（aos-ai 退 0、JSON `ok: false`、`code`、`errors`、`hint`）；aos-ai 自己的錯照 C-54：stderr 一行 `aos-ai: 代號 原因（下一步：…）`、退 1。下層的 `程式名: 代號 原因` 拆成 `{prog, code, reason}`。
8. **背景**：用 aos-daemon，一隻 agent＝一個子 loop，`exec` 是單子 `{"argv": ["aos-exec", "--ws", ws, agent], "envs": {"AOS_STACK": ws/.stack/}}`、`interval_ms` 預設 2000；加減寫 ctl 的 `loops_added`（N-54），每次 `seq`＋1、等 state 的 `ctl_seq` 回音才回。子 loop 結束（agent 失敗）不會自己重起，`start` 時看到表上是 done／stopped 就先拿掉、等它下表、再放回。`daemon up` 會拿掉上次留下的 `stopped`，`loops_added` 照留（上次在背景的照起）。
9. **② 的工具**：子 agent 放 `$AOS_AI_ROOT`（沒設＝老闆的 `$AOS_WS`）的 `agents/<名>/`；錯照 lib 契約 stderr＋stdout 一行、退 1（10-24 遷移）；讓腦看得到、自己改的是叫它的 agent——10-24 晚起 agent-dan 範本本身就把工具錯回給腦（[tool-calls 文末](2026-10-23-tool-calls.md#10-24-定叫工具與小念頭的失敗回給腦)，使用者 10-24「都隨意」），`aos-ai spawn` 原樣複製範本、`--tool-errors` 拿掉；`ask_agent` 前景跑、上限 50 秒（`$AOS_AI_ASK_TIMEOUT`，要小於 act 格的 60 秒）。
10. **skill 的裝法**：放在 repo 裡（`proto8/ai_tools/claude_skill/aos/`），不改 repo 根的 `.claude/`；要用時 `--plugin-dir`、或 symlink 到 `~/.claude/skills/aos`、或 repo 的 `.claude/skills/aos`。

## 生成與概念（10-24 補充後做的）

**結論**：aos-ai 多兩組命令，① skill 與 ② agent-dan 工具都跟上。

- `make`：生成 JSON——inst 單子、loop.json、fsm.json、daemon.json、`_metainfo`、tool.json——先驗形狀再輸出，`--out` 原子寫入；生成骨架——agent 的新工具（tool.json＋`_entry`，可加 `_metainfo`）、fsm 新格（可起格資料夾）、函數資料夾（`_entry`＋`_metainfo`）。
- `explain`：概念速成（`claude_skill/aos/concepts.md`，一份兩用：skill 讀它、`aos-ai explain` 印它；22 節，每節一句白話、最小範例、常見錯、條號，照 CONCEPTS／NORMS／CONVENTION 與 10-24 的 thinking 寫，沒有自創規則）；`explain --here` 照 N-58、N-59、N-61、N-62 模擬「現在 aos-exec 它」：讀了哪些 `.env`（哪幾個名字因為已設而跳過）、挑到哪個入口、哪一種、入口看到的六個變數。
- ② 加三個工具：`make_json`、`make_tool`、`explain_aos`。
- **實測**：
  - 生成的 loop＋fsm、單子、函數資料夾、daemon 都真的經 aos-exec／aos-loop／aos-fsm／aos-daemon 跑過；生成一個工具＋一個 fsm 格掛進 agent-dan，假 server 叫到那個工具、新格每輪都跑（測試 `test_make_tool_and_cell_end_to_end`）。
  - `explain --here` 跟真的 aos-exec 比（入口印 `printenv`）：資料夾一路往下＋`.env` 改 `AOS_ENTRY`、`檔#/指標`＋單子、JSON 物件的 `.env` key＋argv 陣列、找不到入口，四種都對得上；連「`.env` 預設不蓋已設的 `AOS_ENTRY`」這條也一致。
  - 沒讀過 NORMS 的 AI：`claude -p --model sonnet` 只給 skill，五題概念題（AOS_STACK 預設與沿用、結束碼 10、AOS_CO 在 `aos-exec fsm.json` 時的值與為何不能當「這一格」、`time_ms` 對 `timeout_ms`、工具小格）**五題全對**；它用 `aos-ai make` 生成 `gen/loop.json`＋`gen/fsm.json`，`aos-exec --ws . gen/loop.json` 跑通（hi 格寫 hello、stop 格退 10、loop 退 0）。7 回合、約 0.137 美元。
- 測試 13 個（原 7＋生成與概念 6），連跑三次全過。

## 決定（生成與概念；使用者 10-24「都按建議做」，照推薦定、可翻案）

11. **只生成、不改**：既有 JSON 的修改交給 aos-json（另一套「JSON 修改工具集」，`proto8/impls/aos-json`）。aos-ai 在 PATH 上找得到 aos-json 時：`--out` 寫完跑 `aos-json check`、`make cell` 用 `aos-json set` 改 fsm.json；找不到才自己讀－改－原子寫（只做簡單指標）。
12. **生成的形狀檢查只看 aos 讀的格**（exec 三種寫法、單子的 10 個 key、fsm 每格要有 `next` 且在表上、daemon 子項名字、`_metainfo` 通用 key 的型別、`priority` 不准放 `_metainfo`、tool.json 的 description／parameters）；其他 key 照 C-48 不管。
13. **loop／fsm／daemon 預設帶 `_entry`**（`["aos-loop"|"aos-fsm"|"aos-daemon", {"$env": "AOS_CF"}]`），生成的檔直接 `aos-exec` 得動；`--entry no` 不帶。
14. **fsm 的格**：`--cell 名=exec` 照順序，`next` 沒給＝下一格、最後一格回 `start`（接成環，同三態範本）；`--next 名=下一格` 改。
15. **欄位說明預設附上**（`notes`：每個欄位一句、指到 `explain` 的節），`--no-notes` 關掉。
16. **工具骨架預設 Python**（照 agent-dan 的 math；`--lang sh` 照 clock），骨架照 P-41：stdin 收 arguments、stdout 印結果、錯一行「工具名: 代號 原因」。
17. **函數資料夾的 `_metainfo` 是檔**（跟 `_entry` 並列，M1），內容照 M3 的通用 key。
18. **概念速成一份兩用**：放在 skill 資料夾（`concepts.md`），aos-ai 讀同一份，不另寫一份。
19. **`explain --here` 是模擬、不跑**：aos-exec 沒有試跑旗標，所以照條文重寫一遍判斷；輸出明寫「以 aos-exec 為準」，測試拿真的 aos-exec 對過。

## 邊緣狀況（實作時記下的）

- **背景的 agent 每 2 秒被叫一次**：沒題時 idle 退 10、子 loop 照 `interval_ms` 再叫，所以 `trace.jsonl` 每次多一行 idle（一天約 4 萬行）。要省就把 `--interval-ms` 調大；根本解是讓 loop 看 `new/` 有沒有東西再起（沒做）。
- **前景與背景的互斥只擋得住 aos-ai 自己**：有人直接 `aos-exec` 同一個工作區，兩邊一樣會互搶（use-aos 已知：loop 沒鎖）。
- **ctl 是宣告**：aos-ai 讀－改－寫整份，同時兩支 aos-ai 寫靠 `daemon/.ctl.lock`；人手改 ctl 同時 aos-ai 也在寫，後寫的蓋前寫的。
- **daemon 沒在跑時 `wait` 立刻失敗**（`WaitFailed`），不會白等。
- **`run` 收集答案看的是「這次多出來的 out/ 檔」**：題名跟舊答案同名時（人先刪了 done 又重丟）看不到，`ask` 擋重複題名就是為這個。
- **zsh 會把 `17*23` 當萬用字元**：題目要加引號（實測踩到一次）；SKILL.md 的例子加了引號。
- **工具結果是 aos-ai 的 JSON 原樣**：腦看到的是 `{"ok": true, "answer": …}` 整串，假腦直接轉述了 JSON；10-24 真腦（chatgpt-gpt-6-luna-low）會自己摘（`{"ok": true, "answer": "391\n"}` → 交「391」）。
- **② 子 agent 的腦跟老闆同一個**：`AOS_BRAIN_URL` 等環境變數一路傳下去；要不同的腦得在子 agent 的 `.env` 寫，但 `.env` 預設不蓋外面已設的（N-58），要 `--dotenv-override`——aos-ai 沒開這個旗標。
- **巢狀深度沒限制**：老闆的 helper 也掛 `ask_agent` 就能一直往下叫；每層前景跑，最外層 act 的 60 秒逾時會先到。
- **`ask` 的暫存檔被 agent 撿走**（測試抓到、已修）：原本先寫 `new/.q1.txt.tmp` 再改名（N-05），但 agent-dan 的 `brain.py` 用 `os.listdir` 撿題、連 `.` 開頭的也撿，背景跑時偶爾撿到暫存檔。改成暫存放在 `new/` 外面（工作區根）。agent-dan 那邊（撿題不濾 `.` 開頭）沒改，留給範本。
- **Claude Code 的 Bash 權限擋含 `$AOS_STACK` 的指令**：sonnet 生成 fsm 時第一次被擋（指令裡有 `$` 變數），第二次才過；非互動用時這類指令可能要另外允許。
- **`--argv` 給字串是照空白切**（`'sh -c "echo x"'` 會切壞），要精確就給 JSON 陣列；skill 的例子用 JSON。
- **`explain --here` 沒模擬的**：字串轉向後的下一跳、`$AOS_ENTRY` 多段路徑、捷徑、繞圈；`.env` 只粗讀（格式錯照 aos-exec 才報）。
- **不在 C-54 縮寫表的字**：`ai`（`aos-ai`、`AOS_AI_ROOT`）、`ws` 已在表上；`ai` 沒進表（頂層不改 CONCEPTS，留給整理時補）。

## 留給之後的選項（現在照推薦做了，要翻案時看這裡）

- 要不要另做 MCP server（把 aos-ai 的命令包成 MCP 工具，Claude Code 不用 Bash 權限也能叫）。
- 背景模式改成「有題才叫」（daemon 子項的 `exec` 先看 `new/`），省掉空轉的 trace。
- ② 的工具錯要不要改回停下等人：現在退 1 一行、叫它的 agent 回給腦（決定 9）。
- 子 agent 放老闆的工作區（現在）還是放老闆的 stack（P-17 小格的精神）。
- JSON 編輯：等「JSON 修改工具集」做好，把 `AOS_AI_JSON_EDITOR` 指過去（`make cell` 已經在用 aos-json 的 set／check）。
- 給 aos-exec 加一個「試跑」旗標（只算入口與變數、不跑），`explain --here` 就不必自己模擬。
- 讓 agent 的腦改自己（make_tool 給自己加工具）：現在只給 `agents/<名>/`（子 agent），不碰自己的定義資料夾（P-15）。
