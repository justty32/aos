## 決定（10-28）

1. **名字仍叫 aos-hub**，不叫 aos-ccc：管的不只 claude code，也包括 codex、pi coding agent 之類。
2. **環境變數用 `AOS_HUB`**（取代筆記裡的 `AOS_CLAUDE_CODE_CLI_HUB`）；`AOS_HUB` 指的資料夾裡跑一個**常駐的 aos-kernel**，管所有實例。（10-30 改口：aos-eca-hub 建在 daemon 上，見 [eca](../../30/eca/README.md)）
3. **kernel 掛了，依賴它的指令直接報錯**，不做自動接回或自動重開。（10-30 改口：aos-eca-hub 建在 daemon 上，見 [eca](../../30/eca/README.md)）
4. **限制實例數量：實作時再說。**
5. **要有 pause 和 stop 兩種**（頂層的解讀，使用者 10-28「你的解讀比較好」，定案）：
   - **pause**＝10-27 的「收起」：關掉程式，對話 id 留著，之後叫得回來。
   - **stop**＝結束這個實例：舊對話歸檔，不再叫回。
6. **舊對話歸檔**：放 daemon 小格那邊 `$AOS_DAEMON/eca_archive/`（10-30 使用者「A」，見 [eca § 決定](../../30/eca/09-方向題.md#決定10-30) 第 10 條），不放 `AOS_HUB` 路徑下（使用者 10-28「隨意，盡量不要與現有的衝突」）。
7. **Ctrl-]＝跳出畫面但不結束實例**（筆記本身的意思）。
8. **實例狀態以 kernel 記的為準**，不當場讀格裡的檔。（10-30 改口：aos-eca-hub 建在 daemon 上，見 [eca](../../30/eca/README.md)）
9. **hub 是 kernel 的一種**：kernel＝負責排隊和分配資源的程式，hub 在它上面多做事（列實例、接畫面、pause／stop）。所以不算撞名，跟 CONCEPTS 的 kernel（C-12 排序與資源分配）是同一個概念。（10-30 改口：aos-eca-hub 建在 daemon 上，見 [eca](../../30/eca/README.md)）
10. **`AOS_HUB` 沒設＝報錯**，不給預設路徑。
11. **筆記 pseudo code 裡的 prompt 參數＝stdin／stdout**，當成一條 queue：使用者的新話、模型的回覆都經它，迴圈裡 `queue.pop()`／`queue.push()`。
12. **現成 agent 程式（claude code 之類）跟 aos loop／fsm agent 的差別**：後者底層握在我們手上，每個階段都能是 aos 函數，所以控制得更細。
13. **插話時等這輪做完還是打斷：不訂死**，每個 aos agent 自己設定——這正是 aos agent 的靈活處。現成 agent 程式（claude code 之類）的 queue 不在我們手上，照它自己的。
14. **hub 的常駐 kernel 要不要照 C-47／N-42 建在 daemon 上、算不算第三種 kernel：實作時自由選**（照 daemon 做或不照都行），不列待辦——使用者「我也不確定。我覺得沒差」。
