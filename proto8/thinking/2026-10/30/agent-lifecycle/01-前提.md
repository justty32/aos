## 前提（引用哪些決定）

- **決定 33**（agent-bob）：say 改走標準的有順序投遞、題目信箱退場；**agent 這一層不用「信箱」這個詞，這層是訊息的 queue**；請求的投遞叫信箱或 queue 都可以。
- **決定 34**：**aos-loop 是 aos agent 這支程式的內部組件**（停著等由它提供，agent 保持是函數）；其他 coding agent 是黑盒子，生命週期在外面包、含掛到 aos-daemon 底下；daemon 管不了純 aos-exec 就擴充；沒有也行，`ps aux`＋`kill`。
  - 使用者 10-30 早補（逐字）：「**包成max:1也是可以**」——純 `aos-exec X` 用現有 loop 規格包成 `max: 1` 掛 daemon，他接受。
  - 再補（逐字）：「**不過可以的話，我也覺得讓daemon可以掛aos-exec，也是不錯的**」——daemon 原生就能掛一個純 `aos-exec X` 的子項更好。B 題兩條都做：② 原生、① `max: 1` 留作底層。
- **決定 35**：對話簿放 stack、hub 的 pause 改名「收起」、規則寫進 CONVENTION 引用 N-16／N-14；**claude code cli 這類自己存 session 的，aos 要弄一份 symlink 或複製一份過來管理**。
- 承接的：[10-28 medium](../../28/medium/README.md) 決定 1（納入管理透過介質、直接 aos-exec＝Linux 管）、2（aos-loop＝常駐＋狀態＋手把的包裝）、22（身分＝路徑）、25（人算 proc、`~/`）、26（紀錄 aos 不管、不進交流標準）、27（失敗不另外通知）、28（三種基本概念：投遞、窗、父子交代）、32（agent 的輸入是 queue）；[10-28 hub-kernel](../../28/hub-kernel/README.md) 決定 5（pause／stop）、9（hub 是 kernel 的一種）、11（prompt＝stdin／stdout 當 queue）、13（插話等或打斷不訂死）；[10-28 hub-adapter](../../28/hub-adapter/README.md) 使用者「放Stack比較好。」；[10-29 playground-queue](../../29/playground-queue/README.md) 結論 2（跑完結不結束寫死在定義裡）。
