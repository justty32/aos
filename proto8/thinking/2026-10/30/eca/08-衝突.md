## 衝突（跟既有原則、實作對不上的；寫給使用者看）

六條都照建議（使用者 10-30「都照建議」），定案見 [§ 決定（10-30）](09-方向題.md#決定10-30)。

1. **掛在 daemon 底下的 agent 拿不到自己的工作區**，使用者要的「cd 到專案、把 claude 掛上去」一定要每隻有自己的工作區（N-28、N-54 的子項只有 `exec`；代定 D-2「其他 key 忽略」）。**定：子項多一個 `ws` key**，daemon 起它時設 `AOS_WS`；aos-daemon-ctl 多 `--ws`。依據 N-55「工作區由呼叫方設」，daemon 是呼叫方。
2. **aos-eca-hub 沒有自己的常駐 kernel**，跟 10-28 hub-kernel 決定 2、8、9 字面相反。**定：三條改口**成「常駐的是 daemon、以 daemon 的表為準、eca-hub 建在 daemon 上」，kernel 與它的 socket 刪。三條的精神（有一個常駐的東西記著、指令只讀它、它掛了就報錯）不變，只是那個東西換成 daemon——使用者 10-30 說的「摘出來就是 daemon」。
3. **掛了 daemon 之後，「cd 到專案、直接 aos-say」找不到它的 queue**（stack 是 daemon 的小格，C-67；aos-say 預設找 `<專案>/.stack/`，N-57）。**定：`aos-eca-hub add` 在專案建一個 `.stack` symlink 指到小格**；專案本來就有 `.stack` 就不建、報一句，要人用 `--stack`。（11-03 起 `.stack` 捷徑拿掉，見 [11-03 stack-where](../../../2026-11/03/stack-where.md)。）
4. **`AOS_HUB` 退場**，N-63 拿掉這個實例；aos-eca-hub 用 `AOS_DAEMON`（同一個 daemon 不要兩個名字，C-54）；`aos-hub` 名字留給以後。
5. **外部 agent 包在 aos-loop 裡**，跟決定 34「aos-loop 是 aos agent 的內部組件」字面有點緊。**定：用 aos-loop 包 turn**（claude 仍是黑盒子：aos-loop 包的是 turn、不是 claude；medium 決定 2），決定 34 不改字。
6. **`server.txt` 與「只登記的實例」都刪**（跟 hub-adapter 代定 1、3 相反）：turn 在 aos-loop 下 `/proc` 就看得到；工具呼叫的格是那隻 agent 的事、不算實例，要看去看那隻 agent 的 trace（C-52）。
