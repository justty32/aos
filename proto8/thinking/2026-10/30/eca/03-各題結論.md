### B. 外部 agent 跟 aos agent 平級，怎麼落到佈局

1. **一隻外部 coding agent 的「定義」＝一個資料夾程式，形狀跟 aos agent 範本一樣**（map-review 第 3 點平級；C-68；N-53；P-15）。範本 `demo/eca-claude/`、`demo/eca-codex/`（範本名照 `aos-<領域>-<功能>` 的精神用 `eca-<CLI 名>`）：
   - `_entry`＝`["aos-loop", "loop.json"]`；`loop.json` 開 `ctl`、`state` 窗、`interval_ms` 300，每次叫一次 turn。停著等版 queue 空退 0，射後不理版 queue 空退 10。
   - 只有一格 **turn**（外部 agent 的「一輪」），沒有 think／act／endpoint：**腦不是 claude，整隻 agent 才是 claude**（第 3 點「不是腦」）。（10-31 起 turn 是 `bin/aos-eca-turn`、`loop.json` 直接叫它、`parts.json` 刪、停法改旗標 `--on-empty`，見 [13](13-實作時代定.md#實作時代定10-31隊長與工人照原則定的細節可翻案)。）
   - `cli.json`＝工具資料夾那份（`kind: claude|codex`、`flags`、`print_flags`、`timeout_ms`；[cli-tools 結論 3、6](../../24/cli-tools/README.md)），放在定義頂層；不另造 `agent.json`（C-56）。
   - 開場白（射後不理：history 空、queue 也空時，turn 把它當第一則 user 投進 queue 再答；playground-queue 結論 1「初始 prompt 寫在定義裡」）。（11-04 起由 `aos-eca-turn --prompt FILE` 給，見 [21](21-11-04-開場白檔可指定.md#11-04-翻案開場白改成-aos-eca-turn-的旗標)。）
   - **實例＝定義 × 工作區**（P-15、C-65）：`aos-exec --ws ~/code/myproj demo/eca-claude`；工作區＝claude 的 cwd；stack 預設 `~/code/myproj/.stack/`，裡面是 `queue/`、`history.jsonl`、`ctl.json`、`state.json` 與 cli_session 的小格 `claude/`（`session.txt`、`tty.sock`、`transcripts/`…）。這就是 P-42，不是 hub 的特例（10-28 使用者「放Stack比較好」）。
2. **turn 做的事**，照 queue 格與 round 的順序，「問腦」換成「叫 CLI」：① 認領信、接進 history；② `body` 不是 `{"role": "user", …}`＝壞信，丟掉、記一行；③ `content` 交給 cli_session（畫面開著＝貼進 pty 等 `Stop` hook；沒開＝`claude -p --resume <id>`，第一次 `--session-id <新 uuid>`）；④ 回答接成一則 assistant 進 history；⑤ queue 空：射後不理退 10、停著等退 0；⑥ 拿到 session id 就在小格建 `transcripts/<kind>-<id>.jsonl` → CLI 自己對話檔的 symlink（C-15～17）。**人在畫面上自己打的話不進 history**（方向題 2）；`SessionBad`（有人接在畫面上）＝這次退 0 不動、信留 `cur/`，下一次再試。（11-03 起一輪一批、交給 CLI 就收信，見 [17](17-11-03-批次-status.md)、[20](20-11-03-交出去就收.md)。）
3. **`aos-exec <外部定義>` 能跑**，這就是射後有理的開法；父子交代那層（C-75 第三種）跟 aos agent 一樣：argv、環境變數進，結束碼出。
4. **掛 daemon 用同一支 aos-daemon-ctl**：`aos-daemon-ctl add --ws ~/code/myproj --name myproj demo/eca-claude`——認成 loop 子項，daemon 的子 loop 直接跑 turn，只有一層 loop。子項要有自己的工作區（`--ws` → 子項的 `ws` key → daemon 起子項時設 `AOS_WS`），[衝突 1](08-衝突.md#衝突跟既有原則實作對不上的寫給使用者看)。掛上去之後 stack＝daemon 的小格，不在專案裡，10-27 筆記「cd 過去打指令就接上」就得有辦法找到它 → [衝突 3](08-衝突.md#衝突跟既有原則實作對不上的寫給使用者看)。
5. **「claude／codex 當 tool」（agent-fay）跟「當平級 agent」是同一份程式、兩種叫法**（C-52；10-24 agent-as-tool）：
   - **當平級**＝整個定義 `aos-exec`（`_entry` → aos-loop → turn），停著等、有 queue／history／ctl。
   - **當工具**＝只問一句的形：`lib/agent/claude`、`codex`（stdin `{"prompt"}` → stdout 回答，P-41），cli_session 共用。對話記在呼叫它那格的小格（`$AOS_STACK/<工具名>/session.txt`）；平級形的在定義自己的 stack；兩種都留 transcripts symlink（方向題 3）。
   - agent-fay、`attach` 不改；hub 的 `open` 跟 `attach` 共用 cli_session。
6. **queue 由 turn 收、history 由 turn 寫、paused 由包著 turn 的 aos-loop 認（＝不餵下一則）**。aos-say／listen／chat、`lib/aos/aos_ws.py`、ask_round 一行不改。
