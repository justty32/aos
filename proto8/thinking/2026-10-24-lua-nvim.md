## 決定與結論（照推薦定、可翻案；使用者 10-24「都按建議做」）

1. **編譯＝寫 table、輸出檔案**：一份 `.lua` `return` 一個節點，`aos-lua build` 寫成資料夾；編完只剩檔案，執行期跟 Lua 無關（aos 只訂環境變數與 aos-exec，C-69）。
2. **建構子只是有名字的 table**：`aos.loop{}` 編出來就是 loop.json 原樣的物件，不補 key、不改名（C-56「寫什麼就做什麼」）；建構子的用處是**寫的當下查形狀**，錯了指到原始檔那一行。
3. **名字照字面**：資料夾裡的 key 就是檔名，不自動補 `.json`、不自動加 `_entry`；要 JSON 自己當入口就寫 `_entry = aos.self_entry("aos-fsm")`。
4. **Lua 版本**：只用 5.1 子集，lua 5.5、luajit、`nvim -l` 都跑，編出來逐位元組一樣（測試比）。沒裝 lua 的機器用 `nvim -l aos-lua …`。
5. **命令列一支** `aos-lua`（C-54：檔名 `aos-lua`），三個子命令 `build`／`json`／`ls`；錯誤一行 `aos-lua: 代號 原因`、退 1。
6. **放哪**：`proto8/langs/lua/`（語言放 `langs/` 底下，Janet 那半可放 `langs/janet/`）、`proto8/editors/nvim/`（編輯器放 `editors/`）。
7. **nvim 外掛不進他的設定**：放 repo 裡，他要用時自己加一個 `lua/plugins/aos.lua`（寫法在 [editors/nvim/README](../editors/nvim/README.md)）；`init_min.lua` 給 `nvim --clean -u` 單獨試。模組名 `aos_nvim`（不叫 `aos`，免得跟 Lua 庫的 `require("aos")` 撞名）。
8. **外掛照他自己的樣子**：一個下方面板 `aos://panel` 重複用、按 q 關；指令 `:Aos…`；鍵不替他綁。
9. **叫 aos 的程式**：子行程的 PATH 前面接這個 repo 的 bin/，nvim 自己的 PATH 不動（同「aos 的程式都不動 PATH」）。丟題優先用 [human](../human/README.md) 的 `aos-say`／`aos-listen`，沒有就外掛自己寫 `new/`（暫存檔＋rename）、輪詢 `out/`。
10. **`:AosExec` 沒給目標＝往上找有 `_entry` 的資料夾**（跑整隻 agent）；`:AosExec!`＝跑目前這個檔本身（`fsm.json` 帶 `_entry`＝只走一格），兩種分開，不靠猜。

## Lua 寫法 ↔ 編出來的 JSON

| Lua | 編出來 |
|---|---|
| `aos.dir{名字 = 節點}` | 資料夾 |
| `aos.script("#!/bin/sh\n…")` | 可執行檔（755） |
| `aos.file("…")`、一般字串 | 純文字檔（644） |
| 一般 table、建構子 | JSON 檔（兩格縮排、短的寫一行、UTF-8 原樣） |
| `aos.inst{argv = {"python3", "brain.py"}, timeout_ms = 120000}` | `{"argv": ["python3", "brain.py"], "timeout_ms": 120000}` |
| `aos.loop{exec = "fsm.json", max = 40}` | `{"exec": "fsm.json", "max": 40}` |
| `aos.fsm{start = "idle", states = {{"idle", exec = "idle", next = "think"}, …}}` | `{"start": "idle", "states": {"idle": {"exec": "idle", "next": "think"}, …}}`（陣列寫法照順序） |
| `aos.daemon{max = 15, interval_ms = 100, loops = {…}}` | `{"max": 15, "interval_ms": 100, "loops": {…}}` |
| `aos.env("AOS_STACK", {path = "plan.txt"})` | `{"$env": "AOS_STACK", "$path": "plan.txt"}` |
| `aos.ref("x.json#/a", {prefix = "--"})` | `{"$ref": "x.json#/a", "$prefix": "--"}` |
| `aos.self_entry("aos-fsm")` | `["aos-fsm", {"$env": "AOS_CF"}]` |
| `_entry = {"aos-daemon", "daemon.json"}`（放在 dir 裡） | 檔 `_entry` 內容 `["aos-daemon", "daemon.json"]`（沒 +x＝aos-exec 當 argv 陣列，不用 sh） |
| `aos.array()`、`aos.object()`、`aos.null` | `[]`、`{}`、`null`（空 table 預設 `{}`） |
| `aos.obj{{"z", 1}, {"y", 2}}` | `{"z": 1, "y": 2}`（照寫的順序） |
| `aos.read("../x.py")` | 讀原始檔旁邊的檔（相對於 `.lua` 所在資料夾） |

查形狀（錯了 `aos-lua: SourceBad 原始檔:行: …`）：`inst` 要非空 `argv`；`loop` 要 `exec`；`fsm` 的 `start`、每格 `next` 要在表上、`next` 頭尾不能空白換行、`exec` 要是字串／陣列／單子／指示詞（同 N-36 開跑時查的）；`env`／`ref` 只收 `path`、`prefix`；dir 的名字不能含 `/`。

## 邊緣狀況

- **尾呼叫丟行號**：原始檔寫 `return aos.fsm{…}`（整份只回一個建構子）時，Lua 把它當尾呼叫、丟掉呼叫者那層，錯誤訊息沒有原始檔行號；包在 `aos.dir{}` 裡或先 `local x = …` 就有。
- **沒 lua 時 mkdir／chmod 走 sh**：純 Lua 沒有建資料夾、改權限的函數，`aos-lua` 在 lua／luajit 下用 `os.execute("mkdir -p …")`、`chmod`（引號照 sh 規則包）；在 `nvim -l` 下用 `vim.fn.mkdir`、`vim.uv.fs_chmod`，不經 sh。
- **輸出不清舊檔**：原始檔刪了一個檔，再 build 到同一個資料夾，舊檔還在；要乾淨就換新資料夾。
- **編出來的跟手寫的 JSON 排版不同**：語意一樣、文字不同（key 順序、換行），手寫的檔被 build 蓋過就變成 aos-lua 的排版。
- **Lua table 沒有順序**：一般 table 的 key 用「常用的在前、其餘字母序」排；fsm 的 states 用陣列寫法才保得住寫的順序。`{}` 分不出空物件與空陣列，預設物件。
- **數字**：Lua 5.3+ 的整數與 luajit 的浮點都輸出成整數字面；NaN、無限大＝錯。
- **`:AosExec` 跟 agent 用同一個工作區**：nvim 開著時外面也有人跑同一個工作區，兩邊會搶 `new/` 的題（同 human 的 say／listen）。
- **`:AosExec` 會擋住嗎**：不會，子行程背景跑、輸出一行行進面板；跑很久的 agent 要停得自己在終端機殺，外掛沒做「停」。
- **指令參數裡的 `#`**：nvim 的 `complete=file` 會把參數裡的 `#` 換成「上一個檔」，`檔#/指標` 就壞了——外掛的補全改用 Lua 函數避開。
- **nvim 從有 `AOS_STACK` 的環境開**：子行程會繼承那個 stack，`:AosTrace` 看的卻是 `工作區/.stack`；要對齊就 `setup{stack=}`。
- **`#/指標` 找位置只認標準 JSON**：有註解、尾逗號的檔找不到（aos 的 JSON 本來也不收）。
