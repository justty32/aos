# 2026-10-15 inst 只吃 stdin、aos-exec 當語法糖、`$ref` 從所在檔算

## 原文（10-15 晚，照貼）

**場景**：「我現在有個 /home/a/workspace/ 資料夾，然後有 /home/a/agents/bob/ 資料夾，然後我會 cd 到 workspace 資料夾，然後跑 `aos-inst ../agents/bob`」「也就是我想要在這個資料夾跑 bob 這個函數，讓他在這個 workspace 工作」「拿 ../agent/bob 作爲函數呼叫，讓他在 ./ 工作，然後我又不想碰環境變數」。

**規範重申**：「當初的規範定下來，就是說 stdin 作爲標準輸入，inst.json 的內容就是走 stdin 進去，這是標準使用，命令行是要空出來的」。

**流程**：「aos-inst 從 stdin 讀到一份 json 後，他就是先按照 aos-inst 自己的 cwd，去解指示詞（$ref/$env），然後是根據解出來的東西，同樣根據 aos-inst 自己的 cwd 去把 stdin/out 等檔案路徑定下來，然後要真正執行之前，再去將 cwd 切到指定的 cwd 路徑。」

**決定**：「首先 $ref 確實應該用該檔案所在的位置開始算」「從 stdin 來，其實更像是在 workspace 中創造一個叫做 inst.json 的檔案，然後將內容交給 aos-inst 這樣。然後 aos-inst TARGET 這樣的用法我覺得應該拿掉，就是完全從 stdin 來就好，要用 aos-exec TARGET 作爲語法糖。」「$ref 確實要改，改之前要派 agent 評估影響」。

**新指示詞**（AI 提 `$path`，使用者先改名再質疑）：「那應該改叫 $abs_path」「然後，其實 $abs_path 真的有必要嗎？我覺得不用吧，再想想」→ 移到未決 H。

## 決定

1. **`$ref` 的相對檔名，從那個指示詞所在的檔的資料夾算**。stdin 那份＝當成 aos-inst 的 cwd 裡放了一份 inst.json，所以它裡面的 `$ref` 基準是 cwd；`$ref` 取回來的東西裡再有 `$ref`，從被取的那份檔算。現況是「base_dir 整趟都用它，進了別的檔也不換」，要改。**影響評估另行進行，結果出來再補。**
2. **inst 的 `cwd`、`stdin`／`stdout`／`stderr`／`exit` 這些路徑，一律從 aos-inst 自己的 cwd 算**。`cwd` 這個 key 只決定子程式在哪跑，不影響別的路徑怎麼算。現況串流是「從解出來的 cwd 算」，要改。
3. **沒寫 `cwd`＝子程式在呼叫者站的地方跑**（現況如此，不變）。
4. **aos-inst 拿掉 TARGET，設定只從 stdin 來**（N-12 的標準用法；命令列空出來）。
5. **新增 `aos-exec TARGET`，給人用的語法糖**（細節見未決 A）。

### 用場景走一遍（照上面五條）

```
cd /home/a/workspace
aos-exec ../agents/bob            # ＝ echo '{"$ref": "../agents/bob"}' | aos-inst
```

- stdin 那份裡的 `$ref` 從 cwd（workspace）算 → 找到 `/home/a/agents/bob/.aos/inst.json`（沒有再找 `inst.json`，N-35）。
- bob/inst.json 裡再有 `$ref`，從 bob/ 算。
- bob/inst.json 沒寫 `cwd` → 子程式在 workspace 跑；寫了 `"stdout": "out.json"` → `workspace/out.json`（從 aos-inst 的 cwd 算，跟 bob 在哪無關）。
- 同一個 bob、兩個 workspace 同時叫，各自的輸出落在各自的 workspace，互不相干——這正是 [frame.md](../lib/frame.md)「frame 放哪由呼叫方定」的手感。
- bob 自己的 inst.json 怎麼指到 bob 自己的 loop.json（子程式要用的檔），見未決 H。

### 現況對照（事實，10-15 晚查）

- `aos_directives.resolve(doc, base_dir)`：一個 base_dir 用到底（決定 1 要改）。
- `aos_inst.parse()`：`cwd` 從基準算、三個串流與 exit 從解出來的 `cwd` 算（決定 2 要改）。
- `aos_cli.config()`：`[--key 值] [TARGET | -] [-- argv…]`，TARGET 與 `-` 二選一、都沒給＝`{}`（決定 4 要改）；loop／daemon／fsm／gate／tree 都共用這支。
- id：設定的 `id`＞TARGET 的 `realpath#/位置`＞null，stdin 來＝null（N-30；見未決 F）。
- `$ref` 之外，fsm 的格（N-36）、demo 的 `_schema`（私有 key）已經是「從所在檔的資料夾算」。
- 子程式拿到「定義在哪」的現況：agent 靠呼叫方寫的 `frame.json {"parent": "<絕對路徑>"}`（C-46）；demo 的工具 inst 用 `sh -c` 拼 `$AOS_DEMO`；frame.md 寫「不在 demo 裡就直接寫絕對路徑」。

## 未決（附推薦；使用者習慣「都按照推薦」）

### H. 要不要新指示詞 `$abs_path`（使用者質疑，放最前面）

**問題**：bob/inst.json 要起 `aos loop`，loop 要吃 bob 自己的 loop.json；但 bob 在 workspace 工作，cwd 不是 bob/。子程式只能從 argv、stdin、cwd、環境變數四條路拿到東西，環境變數不碰、cwd 要留給 workspace，所以剩 argv（要路徑字串）或 stdin（要內容）。原提案 `$abs_path`＝「從所在檔的資料夾算出絕對路徑字串」，餵 argv。沒有它，有這幾種走法：

- **H1 寫絕對路徑（現況做法，零新機制）**
  bob/inst.json：`{"argv": ["aos", "loop", "/home/a/agents/bob/loop.json"]}`（C 選甲後改成 `"argv": ["aos", "loop"], "stdin": "/home/a/agents/bob/loop.json"`）。
  通：bob 在 workspace 跑、結果落 workspace。卡：bob 搬家、複製一份給別人、放進 demo 都要改檔（demo 現在就是靠 `$AOS_DEMO` 拼）。
- **H2 `$ref` 嵌內容，走 stdin（同像性 inline）**
  bob/inst.json：`{"argv": ["aos", "loop"], "stdin": {"$ref": "loop.json"}}`。`$ref` 從 bob/ 算（決定 1），loop.json 的內容嵌進來；aos-inst 把它落成暫存檔當子程式的 stdin（loop 只吃 stdin，C 甲）。
  需要一個新功能但不是新指示詞：inst 的 `stdin` 收內嵌 JSON（字串＝路徑、物件／陣列＝內容，C-48 雙形）。
  通：`aos loop <路徑>` 這個需求整個消失，loop.json 裡 `{"inst": {"argv": ["aos", "agent", "fsm"]}}` 不帶路徑。卡：agent 找自己的 fsm.json／brain.json／tools 靠 `frame.json` 的 `parent`（絕對路徑），要有人先寫——**人直接叫**的場景本來就是人寫（frame.md 的「直接叫」第一步），所以 bob 例子長這樣、沒有新東西：
  ```
  cd /home/a/workspace
  echo '{"parent": "/home/a/agents/bob"}' > frame.json && echo '{"question": "…"}' > args.json
  aos-exec ../agents/bob            # bob/inst.json＝{"argv": ["aos", "loop"], "stdin": {"$ref": "loop.json"}}
  cat ret.json
  ```
  **工具叫**的場景（painter 叫 brush）還是卡：`painter/tools/brush.json` 那張 `sh -c` 要 printf 出 brush 的絕對路徑寫進 frame.json，它只知道「brush 在我旁邊 `../../brush`」。現況拼 `$AOS_DEMO`。
- **H3 靠 cwd**：aos-exec 先 cd 到 bob 再跑（＝未決 A 乙）。路徑全通，但 bob 不在 workspace 工作，被場景否掉。
- **H4 fsm 格的既有規矩**：fsm 的格從表所在資料夾算（N-36），能涵蓋「表指格」這一層，但 fsm 表本身是誰起的、brain／tools 在哪，仍是 frame.json 的事；涵蓋不到 inst 起子程式這一層。
- **H5 不開新指示詞，給 `$ref` 一個取法**：`{"$ref": "../brush", "$as": "path"}`＝要位置不要內容。效果等於 `$abs_path`，規矩（基準、`#` 不可用）跟 `$ref` 共用、少記一個名字；代價是 `$ref` 指到資料夾時「要內容＝找 inst.json、要位置＝資料夾本身」兩套。
- **H6 `$abs_path`（原提案）**：`{"$abs_path": "loop.json"}` 從所在檔算絕對路徑。細則若採用：指到不存在的檔不算錯（純字串運算，要不要存在是用的人的事，C-53）；不接 `#/位置`（結果是給 OS 用的字串）；stdin 那份裡的基準＝cwd；絕對路徑照回、`~` 不展開、abspath 不 realpath（定義資料夾可能是 symlink）；`abs`＝absolute 隨這條一起進 [abbr.json](../CONCEPTS/abbr.json)（實作時加）。

**推薦：現在不開 `$abs_path`。** 理由：使用者的場景（人叫）走 H2 就通——`$ref` 改成從所在檔算之後，bob 用 `$ref` 把 loop.json 嵌進 `stdin` 交給子程式，路徑問題自然消失；frame.json 的 parent 本來就是呼叫方寫的，不是新負擔。真正還缺「算絕對路徑」這個能力的只剩一處：**工具 inst 替被叫的 agent 寫 frame.json 的 parent**，現況靠 `$AOS_DEMO`／寫死絕對路徑，先照現況。等 `$ref` 影響評估與 H2 做完，demo 裡若還到處拼 `$AOS_DEMO`，再回頭在 H5／H6 之間挑一個；到時候若選 H6，名字照使用者改的 `$abs_path`。隨推薦要一起做的：inst 的 `stdin` 收內嵌 JSON（列進 G）。

### A. aos-exec 的確切行為

- **甲（推薦）**：`aos-exec TARGET` ＝ `echo '{"$ref": "TARGET"}' | aos-inst`。**不 cd**，所以沒寫 `cwd` 照樣在呼叫者站的地方跑、串流也落在那裡。實作上就是 `aos_inst.run({"$ref": TARGET})` 再把結果吐 stdout、錯誤透明轉交（aos-exec 自己只有「引數不對」這一種錯）。
- 乙：先 cd 到 TARGET 所在資料夾再跑。副作用三個：`cwd` 預設變成定義資料夾（bob 不在 workspace 工作了）、stdout 等串流落進定義資料夾、同一個 bob 被兩個 workspace 同時叫會互蓋。跟使用者的場景相反，不推。
- 附帶兩條規矩的歸屬（現在寫在 N-35「TARGET」底下）：**推薦搬到 `$ref`**——`$ref` 可接 `檔#/位置`（本來就可以）、`$ref` 指到資料夾＝找 `$AOS_DIRNAME/inst.json`、再 `inst.json`（新增；跟 C-51「資料夾的入口＝inst.json」一致）。aos-exec 只是把 TARGET 塞進 `$ref`，自然繼承，不用自己再寫一份；fsm 的格、daemon 的 children、gate 的 target 現在各自靠 `load_target`，改到 `$ref` 一處大家共用。
- 名字：使用者說 aos-exec，照用（`aos exec TARGET`；跟 C++ 那邊的 `core/exec` 子專案不相干，bin/aos 本來就是另一支）。
- Python 的 `run(x)`（N-25）：推薦**只收 dict**，路徑形改成 `run({"$ref": path})`，跟命令列一個手感；要保留路徑形也只是包一層。

### B. 旗標（`--timeout-ms` 等鏡射旗標）與 `--`

- 甲：留在 aos-inst（現況）。但使用者說「命令行是要空出來的」就是對 aos-inst 說的。
- **乙（推薦）**：**搬到 aos-exec**。aos-inst 命令列零引數（多給＝`ArgumentsBad`），旗標、`--` 本來就是「人手打」的方便（N-22 自己說「不是硬規則」），人用的那層才有。aos-exec 收 `[--key 值 …] TARGET [-- argv…]`：先解 `$ref`，再蓋旗標與 `--`（順序同今天的 `config()`；不能把旗標寫進同一個物件，因為 `$ref` 旁邊的 key 會被忽略）。daemon／loop 起子程序本來就走 stdin 不走旗標（N-22），不受影響。
- 丙：全拿掉。少一段程式，但 `aos-exec x.json -- sh -c '…'` 這種試東西的手感會沒掉，不推。
- 附：`-` 跟著 TARGET 一起退場（stdin 是唯一來源，不用再寫）；「都沒給＝從 `{}` 起」也退場（stdin 空＝`JsonSyntax` 錯）。N-21 整條改寫。

### C. aos-loop／aos-daemon（與 fsm、gate）的 TARGET

- **甲（推薦）**：**一致，全部拿掉 TARGET、只吃 stdin**，N-21 改成一句「設定只從 stdin 來」。人要從檔起 loop：`echo '{"$ref": "x.json"}' | aos loop`，或寫一張 inst 用 aos-exec 包它——`{"argv": ["aos", "loop"], "stdin": {"$ref": "loop.json"}}`（H2），N-27 本來就說「子程式的參數走 `stdin` 這個 key」。這樣「從檔案起任何東西」只剩一個入口 aos-exec，不另做 loop-exec／daemon-exec。
- 乙：只改 aos-inst，loop／daemon 留 TARGET（人常直接 `aos loop x.json`）。省工，但兩套規矩，違反 C-54「一次記住、全體系通用」。
- 丙：都拿掉，aos-exec 加旗標選程式（`aos-exec --prog loop x.json`）。多一個旗標，不推。
- 附（選甲時）：demo 六組 cells 的 argv 現在寫 `["aos", "loop", "/abs/…/loop.json"]`，改成 `["aos", "loop"]` ＋ `"stdin": {"$ref": "loop.json"}`；frame.md 的 `aos loop /abs/clerk/loop.json` 同改。

### D. inst 的 `stdin` 收內嵌 JSON（H2 的前提）

- **推薦做**：`stdin` 是字串＝檔路徑（現況，從 aos-inst 的 cwd 算）；是物件／陣列＝內容，aos-inst 落成暫存檔（N-05 的 `.` 開頭暫存、跑完刪，同 `aos_methods.run_cell` 的做法）灌給子程式；`null`／沒寫＝照舊。`stdin_inherit` 與它衝突照 N-26 報 Conflict。一份物件＝一份 JSON；要多份就給陣列（N-12 串流＝省略外層 `[]` 的陣列）——這裡有個歧義：陣列是「一份陣列」還是「多份」？推薦**一律當多份**（跟 N-12、N-35 把串流當陣列同一套），要傳一份陣列就包一層 `[[…]]`。

### E. `_schema` 的路徑基準與 `$ref` 一致性

- 現況：`_schema` 是私有 key（`_` 開頭，宿主程式忽略，C-48），demo 通用 kernel 的 `judges/rules.json` 與 test_tree 從所在檔的資料夾算（今晚已改）。
- **推薦**：不為 `_schema` 另開條文，改成一條通則寫進 N-35（或旁邊新一條）：**「定義裡指向別的定義的相對路徑，一律從所在檔的資料夾算」**——`$ref`、fsm 的格（N-36）、`_schema` 都是這條。**例外只有執行期的路徑**：inst 的 `cwd`、串流、`exit`，loop／daemon 的 `ctl`／`state` 窗，從跑的人的 cwd 算（決定 2）。

### F. 身分（id）在 stdin 來源時怎麼定

- 現況：id＝設定的 `id`＞TARGET 的 `realpath#/位置`＞null；stdin 來、沒寫 `id`＝null（N-30）。TARGET 一拿掉，daemon children、loop 的 id、kernel 信的 id 都是從 TARGET 來的，要有替代。
- 甲：stdin 來一律 null（寫 `id` 才有）。簡單，但 aos-exec 跑出來的結果 id 全 null，比今天退步。
- **乙（推薦）**：**stdin 那份的頂層整個就是一個 `$ref`（aos-exec 的形）→ id＝解到的那份檔的 `realpath#/位置`**，跟今天 `aos-inst TARGET` 的 id 一模一樣；頂層是寫死的物件→ null。先最小做：aos-exec 自己知道 TARGET、自己填 id；`echo '{"$ref": …}' | aos-inst` 要不要也拿得到來源（resolver 回報「這一格從哪份檔哪個位置來」），併進 `$ref` 的影響評估一起看。
- 丙：id＝`<cwd>/inst.json`（照「視為 cwd 裡一份 inst.json」的比喻）。那個檔不存在、同一 cwd 跑兩張不同 inst 會同 id，不推。
