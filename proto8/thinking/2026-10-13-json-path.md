# 2026-10-13 JSON 也是檔案系統：`檔#/位置`、loop.json 排法、單檔自指；`_metainfo`

## 0. 使用者原文（打字，去贅字）

1. proto8 這塊，我有些想法：我會覺得，json 本身也是一個檔案系統，他幾乎可以無縫銜接檔案路徑，比如 `inst.json#/argv/0` 這樣。考慮到 `#` 在檔案路徑中也是合法的（只是說在 shell 中可能不太友好），其實我們的 `aos-inst xxx`，那個 xxx 也是可以支援這套。所以 loop.json 的格式那塊，可以把 inst 放到頂層，然後 loop 相關的放到 `"loop"`。

6. 不要做，都先記下筆記。我們現在是討論環節。

## 1. 決定（2026-10-13）

- **D1 命令列 TARGET 支援 `檔#/位置`**（aos-inst／aos-loop 的 TARGET、`run(path)`、daemon 指令裡的 id）：跟指示詞 `$ref` 同一套寫法（`#` 後面是 JSON pointer）。使用者：「要，這個很便宜方便。」**還沒動工**，使用者說先記筆記。
- **D2 loop.json 排法不動**：維持 inst 包在 `"inst"` 格、節奏在外層。理由（使用者）：程式實作時資料結構現在這樣比較直觀。「inst 放頂層、節奏收進 `loop`」的提案收回。
- **D3 不做 `AOS_INST_SELF`**（aos-inst 塞「我正在跑的這份 inst 的路徑」環境變數）。使用者：「不要。」

## 2. 結論（討論後）

- **單檔自指是套娃**：inst 的 argv 寫成「aos-loop 自己」，aos-loop 讀到的 inst 又是「aos-loop 自己」，每層等下一層、沒有一層跑完第一次，程序鏈無限長。要讓單檔成立得拼出 `<自己>#/job` 這種字串，現在的指示詞沒有拼字串的（`$ref` 是取值不是給路徑，`$at` 要 `/` 開頭，指示詞不能巢狀），得發明新東西。最後定**兩個檔**：一份啟動單子 `{"argv":["aos-loop","loop.json"]}`、一份 loop 本體。這是 Unix 慣常的形狀，不用加任何新功能。
- **兩個檔的坑**：啟動單子裡的 `"loop.json"` 是相對路徑，照現有規矩從呼叫者的 cwd 算，不是從啟動單子所在的資料夾算。在別處 `aos-inst /x/start.json` 會找不到。解法：單子寫 `cwd` 或寫絕對路徑。**規矩不改**。
- **D1 實作時的預設**（AI 提出、使用者沒回應，照 [user.md](../../wf/workflows/common/user.md) 沒回答的邊緣狀況通則留著供實作時參考，不追問）：
  - 遇到第一個 `#` 就切，檔名含 `#` 的不支援。
  - 命令列的位置只認 `/` 開頭，空的＝整份。
  - id＝realpath 加 pointer；沒 pointer 或 `#/` 就是純 realpath（同一份檔兩個位置＝兩個 id）。
  - 指到的值不是物件就報錯。
  - 指到的那塊裡面的 `$ref` 可以用 `../` 往外摸到旁邊的東西（是視窗不是切下來），照留。
  - TARGET 是資料夾時，先照現有規矩找 inst.json 再套位置。
- **順帶**：有了 `檔#/位置`，一份 JSON 可以放好幾個 inst（如 `node.json#/clock`），要不要這樣用沒定。

## 3. `_metainfo`（10-13 第二段）

> 一樣只記筆記，沒動程式。

### 使用者原文（打字，照記）

1. 「路徑這塊就這樣。然後，我會希望添加一個 _metainfo key，在 inst 格式中。先前有提到說所謂的函數九軸，我們可以在這裡定義。也包括資源特性啥的。」
2. 「_metainfo 這塊，我的概念是，這是一個在 aos 體系中，被 aos inst 和相關標準實作所忽略的東西，它的作用是在後續 kernel 規劃時，提供參考。_metainfo 中所表述的，就是這個 inst 跑下去後的特性。我是覺得啦，我們的初衷之一，就是把 linux 檔案系統變成 lisp，而對一個 list 求值，我們就是統一用 aos inst。」
3. （AI 問後面是不是還有話）「沒，只是說，這是很適合用來作為 kernel 的參考。」

### 決定（D4）

- inst.json 加 `_metainfo` key。意思＝「關於這個 inst 跑下去會是什麼樣子」的描述：九軸（C-13：I/O 型態、生命週期、跨呼叫狀態、資源特性、可中斷性、執行保證、組合模式、環境模式、確定性）、資源特性、乃至其他特性。
- **aos inst 與所有標準實作一律當它不存在**（N-04 那個抽屜的固定名字）；它是給之後 kernel 做規劃時參考用的。
- **還沒動工**（使用者說先記筆記）。
- 跟 10-12 的關係：10-12 說「不做 _metainfo」指的是 proto7-2 那個「這份 inst 是哪種格式、第幾版」（`_type`／`_version`）的 `_metainfo`，那個仍然不做；10-13 的 `_metainfo` 是另一個意思。
- 來源：CONCEPTS C-13、C-14、C-42b；九軸逐軸套到 aos 的表在 [proto7 axes-astra](../../proto7/notes/thinking/2026-10-04-axes-astra.md)；ai_core 原文 `~/repo/ai_core/docs/kb/kb-ss/doc_05_axes_metadata.md` 在家機，公司機沒有。
