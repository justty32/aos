## 考古結論

- 「小念頭」「念頭」這兩個詞在整個 repo 與 git 歷史裡**以前沒出現過**（只有 09-03 fuse-host 一句「先記下這個念頭」，無關）。
- **proto7 的方法＝proto7-2 的 step 包（步驟表直譯器，[packs/step](../../proto7-2/packs/step/README.md)，10-04 第六輪）**，這次沿用它的精神：
  - 一張步驟表（`steps.json`：`start`、每步 `run`／`ok`／`fail`、`${req:<步>}` 引用前一步的結果）；直譯器一次推進一點、**每步派一個子工作**。
  - **子工作把結果寫到槽外的固定位置**（`results/<step>/<attempt>.json`），直譯器**只看結果檔推進**、不管子工作做了什麼；被殺後從框架（`frame.json` 的 `pc`）接回、已交的結果不重做；說不清的停住等人（`unknown`），不自動重送。
  - 9 月 ideas 的 [exec-run-async](../../wf/workflows/ideas/archive/exec-run-async.md)（AI 提議、未裁）：要「去別處跑」就開子資料夾、fork 一支 `aos run <子資料夾>`、**結果落固定路徑、父只讀那一個檔**——同一個形狀。
- proto8 自己的前例：10-15 的 `ask` 子 agent 有 `AOS_ASK_DEPTH` 超過 3＝`TooDeep`（f27163b5，10-19 隨舊 lib 刪）——遞迴要有深度上限，用環境變數往下帶。
- 對照：「agent 當工具」（[agent-eve](2026-10-24-agent-as-tool.md)）是**腦臨時決定**叫一個別的 agent；小念頭是**先規劃好整張步驟表**、每步 fork **自己**。兩者都「子的過程不回外層，只回一段文字」。

## 做了什麼（範本 [demo/agent-gus](../demo/README.md#agent-gus小念頭10-24)）

```
agent-gus/                      照抄 agent-dan（P-25 每隻一份），多兩格 plan、fork
  fsm.json                      idle → plan → fork → think → act → idle
  plan.py                       plan 格：認領題目、接進 history、請腦回 {"context", "steps": [{id, goal, needs}]}，寫 $AOS_STACK/steps.json
  fork.py                       fork 格：每步起一個小念頭（aos-exec 自己這個資料夾），needs 齊了才起、同時最多 N 個；
                                全部有結論後依規劃順序接進 history（一步一則）
  brain.py、act.py              think／act：同 agent-dan（brain 不認領題目；act 交答案時把 steps.json 收進 plans/）
  thought.json、thought.py      給別的程式叫「一個小念頭」的入口（stdin 一步 → stdout 結論）
  shared.py                     各格共用（C-50「程式可以擠在一坨，共用一些 lib」）
  tools/run_python/             工具：stdin {"code"} → 跑、印結束碼與輸出
  .env                          模型名＋小念頭的上限（THOUGHT_*）

$AOS_STACK/                     母體的 stack
  history.jsonl                 題目、「小念頭 sN 的結論（目標：…）：…」幾則、工具來回、回答
  steps.json                    這題的規劃與各步狀態／結論（答完收進 plans/<plan_id>.json）
  budgets/<plan_id>/            整棵念頭樹的額度（一個檔＝一個已算進去的小念頭）
  thoughts/<id>/                小格（P-17）：ws/{new,cur,done,out}/、stack/（小念頭自己的，可能又有 thoughts/）、log.txt
```

一題的流程：plan 請腦拆 → fork 把沒有 needs 的步同時起（每個小念頭是同一隻 agent-gus，工作區＝小格的 `ws/`、題目 `ws/new/<id>.txt`）→ 小念頭自己再 plan（可能再拆、再 fork）→ think／act 做完、答案寫進它的 `out/<id>.txt` → fork 讀那一段當結論、needs 等它的步接著起 → 全部到齊，結論一步一則接進母體 history → think 看著「題目＋結論」寫最後的回答 → act 交答案。不拆的題（腦回 `steps: []`）fork 直接過，就是 agent-dan。trace：`idle plan fork think act idle`（act 叫過工具就再繞一圈，plan、fork 這時什麼都不做）。

## 照推薦定的（使用者 10-24「都按建議做」，可翻案）

1. **fork＝再跑一次自己這個資料夾**：`aos-exec --ws <小格>/ws .`（cwd 是 agent 資料夾；`.` 不是 `..`，P-25 沒破）。小念頭就是同一隻 agent，所以它自己也能規劃、再 fork——使用者「fork出去的東西，又可以繼續steps」不用另寫東西。agent-eve 那份紀錄說「自己叫自己做不到」是指工具放在 `tools/` 底下的地址；fork 不經 `tools/`。
2. **fork 給的是摘要，不是母體的 history**：小念頭的題目＝plan 時腦寫的 `context`（給小念頭的背景摘要）＋它 needs 的那幾步的結論＋自己的 `goal`＋一句「做完只回結論，不寫過程，N 字以內」。小念頭的 history 從空的開始（像 eve 的「每次新的」）。
   - **選項（沒做）：複製母體 history**（像 Claude Code 的 fork 繼承 context）。token 差在：每個小念頭**每問一次腦**都要多送一份母體 history。母體 history 有 H 字、拆 k 步、每個小念頭平均問腦 c 次，就多送約 k×c×H。這次實跑母體 plan 時 history 只有題目（約 100 字），差別小；但母體是一段長對話（續聊、或 plan 前已用過工具）時，H 可能上萬字，k=4、c=3 就多送十幾萬字。好處是小念頭看得到前因後果、不靠腦寫摘要寫得好不好；有 prompt cache 的端點，同一段前綴可能便宜一些。
3. **回來只帶結論**：結論＝小念頭最後的答案（它 `out/` 裡那段），超過 `THOUGHT_MAX_CHARS`（預設 1500 字）截斷、註明全文在哪。過程（工具來回、讀到的東西、它自己的子念頭）全留在小格，不進母體 history。
4. **結論怎麼進母體 history**：全部到齊後依規劃順序一次接，一步一則 `{"role": "user", "content": "小念頭 sN 的結論（目標：…）：\n…"}`。腦的規劃回覆本身不進 history（只記在 steps.json），所以母體 history 只有「題目＋各步與結論＋回答」。用 user 而不是 tool 訊息：tool 訊息前面要有 assistant 的 tool_calls，規劃不是工具呼叫。
5. **步之間的依賴：`needs` 表＋「齊了就起」**：每步列出要先拿到哪幾步的結論；fork 一邊跑一邊看，某步的 needs 都有結論了、而且同時跑的不到 `THOUGHT_PARALLEL`（預設 3）個，就起它，它的題目帶上那幾步的結論。plan 時就擋掉 needs 指錯、繞圈。
   - 選項（沒做）：(甲) 全部獨立、只並行，要接力就靠母體最後彙整；(乙) 全部依序，每步都帶前面所有的結論（最簡單，但慢、題目越來越長）；(丙) 每跑完一批讓母體的腦重新規劃下一批（最有彈性，多花一次腦、規劃可能一直變）。
6. **並行：fork 格自己起多個行程**（不經 aos-daemon）：小念頭跟 fork 同生同死，fork 格的 `timeout_ms`（1 小時）一到整個收掉。每個小念頭自成一個行程群組，fork 被收（SIGTERM／Ctrl-C）時先把它們整群收掉再走。選項（沒做）：交給 aos-daemon 管，fork 格只登記、下一次再來收結論——小念頭能比 fork 格活得久，但要多一套「還在跑」的狀態。
7. **深度上限**：`THOUGHT_DEPTH`（fork 往下帶，母體 0）到了 `THOUGHT_MAX_DEPTH`（預設 2）就**不問腦、直接做**（省一次規劃）。
8. **整棵樹的額度**：`THOUGHT_MAX_TOTAL`（預設 10）＝一道題最多 fork 幾個小念頭（不含母體）。母體在 `$AOS_STACK/budgets/<plan_id>/` 開一份，`THOUGHT_BUDGET` 往下帶；plan 拿到規劃後拿鎖（flock）數一數，夠才佔（一步一個檔），**不夠就不拆、自己做**（不報錯）。剩不到 2 個時連問都不問。每道題一份額度、互不影響。
9. **一次規劃最多 `THOUGHT_MAX_STEPS`（預設 4）步**，跟剩下的額度取小的，寫在規劃提示裡；腦回的超過＝`PlanBad`。只拆一步＝當不拆（白 fork 一次）。
10. **錯一律照 P-20 停下等人**：規劃不是 JSON、超過步數、needs 指錯或繞圈＝`PlanBad`（steps.json 不寫，重跑再問一次腦，題目不重接）；小念頭退非 0、逾時（`THOUGHT_TIMEOUT_S`，預設 900 秒，整群 SIGTERM、5 秒後 SIGKILL）、沒交答案＝`ThoughtFailed`——**同一批其他的照樣跑完、結論記下**，母體停住；重跑時有結論的不重做，失敗的那個**在原本的小格裡接著跑**（它自己的 state 還在，像 proto7 step 包的「同一嘗試接回」）。其他代號同 agent-dan；`StepBad` 是 thought.json 的 stdin 不對。
11. **token 看得到了**：plan、think 問腦時，回覆的 `usage` 和送出的字數記一行在 `$AOS_STACK/usage.jsonl`（eve 那份說「看不到兩層各花多少 token」，這裡先補一個最小的）。
12. **名字**（C-54）：`agent-gus`（demo 用人名，接 dan、eve、fay 之後）；格 `plan`、`fork`（動詞、一看就懂）；`steps.json`、`thoughts/<id>/`（複數資料夾裝同類）、`plans/`、`budgets/`、`usage.jsonl`；環境變數 `THOUGHT_*`（主詞在前）；代號 `PlanBad`、`ThoughtFailed`、`StepBad`。

## 給別的程式叫：`thought.json`（一步進、結論出）

JSON 工具集那邊要用（使用者：拆成「找到要修改的 key」→「提供值」），所以小念頭另有一個能單獨叫的入口，形狀照 P-41（stdin 進、stdout 出）：

```sh
echo '{"goal": "找到要修改的 key", "context": "一份 xxx.json，要把逾時改成 30 秒",
       "needs": [{"id": "k0", "goal": "…", "conclusion": "…"}]}' \
  | AOS_STACK=<小格>/ aos-exec <repo>/proto8/demo/agent-gus/thought.json
# stdout：只有結論（例：/states/act/exec/timeout_ms）；退 0
# 失敗：stderr 一行「agent-gus: ThoughtFailed …」或「agent-gus: StepBad …」，退 1
```

- `goal` 必填；`context`、`needs` 選填（`needs` 每項要有 `goal`、`conclusion`，`id` 可省）。
- 每次呼叫開新的 `<小格>/runs/NNN/`（mkdir 搶號，同時被叫也不撞），過程留在那裡。小念頭的深度＝環境裡的 `THOUGHT_DEPTH`＋1、額度沿用 `THOUGHT_BUDGET`（沒有就那一格自己一份），所以它也可能再拆。
- 「找 key → 給值」兩步：叫兩次，第二次把第一次的結論放進 `needs`（就是 fork 格做的事）；或整題丟給 agent-gus 讓它自己規劃。
- 要給腦當工具：在那隻 agent 的 `tools/<名>/` 放一份 `tool.json`（參數就是上面三個）＋一個轉接 `_entry`，照 eve 的做法。

## 挖出的邊緣狀況

- **小念頭失敗**：現在停下等人（定 10）。另一條路是把「這步失敗：原因」當結論接回去、讓母體的腦自己決定（重拆、略過、照實說）；跟 10-23「叫了不存在的工具」、eve「子 agent 失敗」是同一題。
- **逾時是層層套的**：小念頭 900 秒、它裡面的 fork 格 1 小時——外層先到。外層 SIGTERM 小念頭整群時，它的 fork.py 會轉收孫念頭；但 5 秒後補的 SIGKILL 只打得到小念頭那一群，孫念頭（各自一群）可能變孤兒。沒有誰算「裡面最多跑多久」。
- **規劃爛掉**：不是 JSON、步數超過、needs 指錯／繞圈 → PlanBad 停。**擋不住的**：步之間其實重疊（兩步做同一件事）、步太碎（拆 4 步但一步就能做完）、`context` 寫得太短讓小念頭誤會題目、goal 沒說要帶回什麼。只拆一步當不拆。
- **步太多**：一次最多 4 步、整棵最多 10 個；超過額度就不拆、自己做。並行時兩個同層的小念頭可能**都先問了腦規劃**，搶額度時一個落空——那次規劃白問（測試看得到）。
- **遞迴**：深度上限 2（母體 0 → 小念頭 1 → 2 不再拆）；額度是整棵樹共用的檔，往下帶，所以不會爆炸。小念頭看不到母體的題目原文，只看 context，第二層看到的是第一層寫的 context，資訊會一層層失真（proto7 notes「多層轉手的延遲與失真」）。
- **並行的資源**：同時最多 3 個、每層各算（第 1 層 3 個、各自再 3 個 → 最多 9 個行程樹同時跑）；沒有全域的同時上限。**同時跑會互相干擾**：這次三個量時間的小念頭同時跑，量出來的數字會被彼此拖慢（要量準就設 `THOUGHT_PARALLEL=1`）。同時打同一個腦端點，限流時一起 `BrainFailed`。
- **fork 格自己被殺（SIGKILL）**：小念頭可能還在跑；重跑時 fork 會再起同一步——**同一個小格裡兩份同時跑**會互寫（沒有鎖、沒查 pid）。正常的 SIGTERM／逾時會先收掉小念頭，不會這樣。
- **結論接到一半被殺**：結論是一次寫完幾行；重跑時看 history 最後幾則是不是已經是這批結論，是就不重接。
- **結論被截斷**：超過 1500 字截掉，後面的資訊母體看不到（全文在小格）。小念頭沒照「只回結論」寫、整段過程貼回來，也只能靠截斷擋。
- **同一個 stack 續聊**：上一題的 history 照留（同 dan），新題重新規劃；但 plan 問腦時會帶整串舊 history（拆題要看前文），小念頭不帶。
- **假腦劇本的坑**：劇本一開始拿「題目全文」判斷要不要拆，s4 的題目裡帶了 s2 的 goal（needs 的結論），被當成 s2 又拆一次——真模型也可能被 needs 裡的文字帶偏，goal 要寫清楚。

## 留給使用者的選項（都已照推薦定，翻案時看這裡）

1. fork 給**摘要**（現在）還是**複製母體 history**（token 差見定 2）。
2. 依賴：**needs＋齊了就起**（現在）／全部獨立／全部依序／每批重規劃。
3. 小念頭失敗：**停下等人**（現在）還是**當結論回給母體的腦**。
4. 並行：**fork 格自己起**（現在）還是交給 aos-daemon。
5. 上限的預設值：一次 4 步、深 2 層、整棵 10 個、同時 3 個、每個 900 秒、結論 1500 字（都在 `.env`）。
6. 真模型還沒跑過——LiteLLM 開著時照試驗場 `README.txt` 跑一次，看 gpt 的規劃會不會拆得太碎或太粗。
