### 2c. 起、停、暫停（代定）

1. **手把與信多認 `procs_stopped`（要停的名字）、`procs_started`（要起的名字）**，名字的陣列（C-54 R4 狀態詞）。stopped 集合跟期望表同一套：底（記憶體；起來時＝adopt 接回的 stopped 列）由信改（`procs_stopped` 加、`procs_started` 減）；ctl 每圈疊上去（先加後減；同名兩邊都寫＝起）。N-06「沒寫＝回初始值」：ctl 拿掉名字＝起，要一直停就一直寫。寫壞＝整份不採用／壞信。
2. **stop（loop 型）**：名字在期望表又在 stopped 集合、行程活著 → daemon 往它的 `ctl.json` 寫 `{"cmd": "stop", "seq": N}`（[ctl-commands](../ctl-commands/README.md)；N-54「要暫停、停掉某個子 loop＝直接寫它的 ctl」），讓它**跑完這一次自己退 0**，不 SIGTERM、不殺半路的身體；等的這段列 `stopping`、沒有時間上限（N-28 ①）。退了之後**列留在表上**：`{"phase": "stopped", "pid": null, "started_at_ticks": null, "code": 0, "signal": null, "stack", "ws"?}`；stack 不碰。同一封信 add＋stop → 列直接 `stopped`、stack 先不建。
3. **start**：從 stopped 集合拿掉 → 下一圈「表上要有、沒在跑」用**列上的 `stack`** 再起（重寫 `loop.json` 同一格）；不用先清 ctl（起來第一次讀的 ctl 當基準線、不執行，[ctl-commands § 2](../ctl-commands/02-2-loop-怎麼知道這道是新的-沒有信.md#2-loop-怎麼知道這道是新的沒有信箱)）。起來是跑還是暫停看它自己 state.json 的 `paused`（[ctl-commands § 4](../ctl-commands/02-2-loop-怎麼知道這道是新的-沒有信.md#4-現在暫停中記在哪再起時怎麼辦代定)）。**只有指令叫起**：信來、ctl 別的 key 變、`procs_added` 同名都不會把 stopped 的拉起來（同名 add＝設定換掉、停照停）。
4. **pause／resume（loop 型）**：aos-daemon-ctl 不經 daemon，`where` 拿 stack、往它的 `ctl.json` 寫 `{"cmd": "pause"}`／`{"cmd": "resume"}`（N-05 暫存改名）。daemon 不轉述 paused（不讀子項 state，C-52）；要看讀它的 `state.json`。
5. **exec 型只有跑和拔**：`procs_stopped`／`procs_started` 裡的名字是 exec 型 → ctl 整份不採用、`ctl_warning`「exec 型 X 沒有 stop」；信＝壞信、`mailbox_warning` 同句、有 `reply_to` 回 `{"applied": false}`。aos-daemon-ctl 的 `start`／`stop`／`pause`／`resume` 先看 stack 有沒有 daemon 寫的 `loop.json`：沒有 → **`CtlMissing`** 退 1「X 沒有 ctl（exec 型只有跑和拔）」、不送信；有才動手（daemon 再驗一次）（11-04 已改：`loop.json` 這個名字從 `procs_state.json` 回報的 `procs_loop` 拿、ctl 的名字讀小格 `loop.json` 的 `ctl`，見 [four-elements 08 步 6](../../04/four-elements/08-實作步驟-等aos-agent後.md)）。要一次性的東西能停，寫成 `max: 1` 的 loop。
6. **stopped 的被 rm**：列與集合都拿掉；它 `ctl.json` 裡的 `{"cmd": "stop"}` 留著沒事（基準線）。**繞過 daemon 自己往子 loop 的 ctl 寫 `{"cmd": "stop"}`**：子 loop 退 0，daemon 照 11-02 從表上拿掉（＝拔掉，不是 stop；衝突 2 使用者「照舊拿掉」）；掛在 daemon 下要停就走 daemon。**不在期望表的名字出現在 `procs_stopped`／`procs_started`** → 不管。
7. **adopt**：`phase: stopped` 的列接回成 stopped（不起、不判活）、名字進底的集合；其他列照舊 pid＋`started_at_ticks` 對得上才接。持久化就是 state 窗（N-28「state 窗就是 save 檔」），不另開檔。
8. **aos-daemon-ctl 子命令**：`add`／`rm` 照舊送信；`stop NAME`／`start NAME` 送 `{"procs_stopped": [NAME]}`／`{"procs_started": [NAME]}`、印信號；`pause`／`resume` 直接寫（第 4 條）；`ls` 的 `phase` 是 daemon 看到的字。
9. **daemon 自己的 ctl `pause`／`stop`**：daemon 暫停時照 10-29 § 四 2 不調表（起停也等解除）；daemon 收工＝收掉活著的子項（P-36）、stopped 的列照寫進最後一份 state、退 0；再起 adopt 接回 stopped 的、照名單起其他的（11-03 晚已改：收工時還在跑的 loop 型記 `sleeping`、再開自己醒，見 [§ 8](10-實作時代定-11-03-實作者照原則定的.md#8-收工時改寫成休息中sleepwake11-03-晚)）。
