## 結論

1. **目標目錄**（[06a](06a-目標目錄.md)）：六個類別夾，範本自己的名字都不改；`kernel/` 改名 `kernels/`；`kits` 在 `agents/kits/`；`templates/tests/` 不跟著分。
2. **搬進 lib 的只有 `agent-fsm` 的九個檔**（[06b](06b-執行期的東西搬進lib.md)）：四支格、四支共用模組、一份 hook 點宣告。原始碼放 `py/aos/apps/agent_fsm/`，`install.py` 不用改就會裝到 `lib/aos/apps/agent_fsm/`。範本 `agent-fsm` 自己也改成動態連結，夾裡不再有 `.py`。`eca-claude` 沒有這種檔。
3. **要改的地方大多是換路徑字**，一支腳本照五條規則改得完；人要動腦的是程式六處、幾份 README、一張測試對照表、生成設定（[06c](06c-要改的每一處與分工.md)）。
4. **補丁在 repo 外的一份 clone 上做**，分「腳本可重跑的」與「人改的 commit」兩層；明早停樹後對齊一次 main，出一份補丁套回工作樹，再走 `commit-request` 交成一個 commit（[06d](06d-補丁怎麼做怎麼套.md)）。
5. **切換清單第 0～13 步，全部由使用者在樹外照著打**（[06e](06e-切換步驟.md)）；先交 commit 再起樹；每一步有退路。
6. **表上 13 列用「停著改檔」**（[06f](06f-改表的做法與家機.md)）：`set-def` 改不完（帶環境值的列它不收、agent 自己那份 `tools.json` 它不改）。這條路沒有先例，今晚要在暫存樹預演過才切。
7. **今晚備不齊六樣東西就不切**（06e 第一張表）。

## 替使用者做的小選擇（eca-aos 帶給他看）

1. 格程式的新家叫 `py/aos/apps/agent_fsm/`（照 eca 的 hook 宣告放 `aos/apps/eca/` 的先例），不另開 `lib/cells/`。
2. 範本 `agent-fsm` 不再帶八支 `.py`（跟 `start-api` 的 ann 一樣動態連結）；要整份靜態的人自己從 lib 抄九個檔，不做新工具。依據是他 11-20 看 ann 時的話，但那句講的是 ann，不是範本本身。
3. `hookeds.json`（出廠掛的 hook）留在範本，`std.hooks()` 編譯時去 `templates/agents/<名>/` 讀；`eca-claude` 的 `compact_hook` 不搬。
4. 類別夾裡的範本不改名（`starts/start-api` 這種名字有點重複）；類別夾不另寫 README。
5. `templates/tests/` 不跟著分；測格程式的那 27 支這次留在 `templates/tests/agent-fsm/`，不搬去 `py/tests`。
6. 表用「停著改檔」，不用 `set-def`。
7. 做補丁的地方是 `~/.aos/scratch/tri-split-1123/` 裡的一份 `git clone`（在它自己的 main 上 commit、永不 push）。
8. 兩支一次性的腳本（`switch.sh`、`stack_paths.py`）放規劃夾 `06-switch/`、跟著 git 到家機，不進 `proto8/`；我不把它們算成「遷移程式碼」。


另有一條給 eca-aos 的建議（不是使用者的事）：設一個整合的人，只有它在複本裡下 git。

## 還要問使用者的（三題）

1. **直接把範本夾當定義掛的 13 列，這次只改路徑，還是趁停樹改成各樹自己抄一份？**
   「以後範本怎麼搬都不動到活樹」對動態連結的定義從此成立；對這 13 列不成立，範本下次再搬，表還要再改一次。a 只改路徑（推薦：明早動得最少；之後哪一棵想換，隨時可以單獨換）；b 這次就各樹抄一份（它們從此不跟著範本更新）。
2. **別的專案的 6 份定義（arena_cheater 五份、ops-notes 一份）由切換腳本直接改檔可以嗎？** 只改各 5 處路徑字、留備份、不替它們 commit。a 可以（推薦）；b 不碰，那幾列起樹後會停著，等各專案的協調者自己改完再起。
3. **明早誰打指令？** a 他本人照 06e 的清單打；b 他開一個樹外的 Claude Code 視窗代打，每一步等他點頭。清單兩種都能用。

## 風險

- **停著改 daemon 的狀態檔沒有先例**。改壞主檔，daemon 會把它當壞檔丟開、從空表起。靠備份、改完解析驗一次、今晚預演來壓。
- **一個 commit 動三百個檔以上**。`commit-request` 對大量改名、對舊位置留下的生成檔會怎麼處理，沒試過；06d 排了一次在複本上的預演。
- **從現在到明早 main 還會動**。機械的部分重跑就好；人改的部分如果漂移剛好改到同一行，明早要有懂的人在場解衝突，而那時樹裡的 agent 都停了。
- **今晚的量不小**：程式六處、九個檔搬家、六十多個測試檔、兩支腳本、兩次預演。做不完就延後，不要帶著沒預演的東西切。
- **兩支工具的說明變了**（`agent_def`、`agents_ctl` 的例子路徑）：腦的提示快取會失效一次，知識庫的每包字數表要重量。
- **別的專案 repo 會留著沒交的改動**，要各自的協調者醒來後交。
- **家機**：push 之後才能 pull，而且要先停樹再 pull。
