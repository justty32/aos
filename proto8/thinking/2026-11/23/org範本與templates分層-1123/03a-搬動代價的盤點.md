## 先講結論

1. **範本的路徑不只是「抄的來源」，有一部分是執行期的位址。** `$AOS_HOME/templates/agent-fsm/` 底下的四支格程式與 hook 宣告，每一隻動態連結的 agent 每一格都從那裡跑；`$AOS_HOME/templates/eca-claude` 直接記在活樹的表上當定義。搬這兩夾，斷的是正在跑的東西。
2. **kernel 範本與其他幾夾只是抄的來源**（抄進樹裡就各自獨立），搬了只斷文件、測試與幾行工具設定。
3. 數字：提到 `templates/` 的地方，不算歷史紀錄 `thinking/` 與裝出來的 `lib/`，約 580 行；其中點名六個 agent 範本的 276 行、152 個檔，點名 `kernel` 的 95 行、51 個檔，點名其餘七夾的 79 行、49 個檔（其他是泛指 `templates/`、`templates/tests`、`templates/docs` 的）。

## 六、活樹與別的專案（搬了要人去動的）

1. **這個 repo 這棵樹**：我唯讀看了 `~/repo/aos/.stack/procs_state.json` 裡的定義路徑（只取路徑，沒看別的欄）。`eca-aos`、`eca-aos-kb`、`eca-aos-templates`、`eca-aos-core` 四列的定義都記成 `{"$env": "AOS_HOME", "$path": "/templates/eca-claude"}`，每次起都重新照這個找。`eca-claude` 一搬，這四隻下一次起就找不到定義；`eca-aos` 自己正跑在上面。
2. **arena_cheater 的定義**：`wf/aos/defs/` 底下 7 份定義（五個部門加兩個下屬）的 `fsm.json` 與 `interfaces.json`，共 14 個檔，都指 `$AOS_HOME/templates/agent-fsm/`（我讀了它 repo 裡的定義檔）。`agent-fsm` 一搬，這七隻下一格就跑不起來，要重做定義。
3. **paper_readings 的定義**：整份抄本，不指回範本，不會斷。
4. **別棵樹的表**（`~/aos-home` 根、`mine_arena`、`eca_main`、家機那棵）：**沒查**（任務規定不讀）。照範本 README 教的掛法（`aos-agent ctl add … $AOS_HOME/templates/eca-claude`），多半也是記這種路徑。
5. **`AOS_HOME` 是 proto8 的抄本的機器**：要重抄。

使用者的規矩是 proto8 一律當成沒有舊版：不寫遷移、不留舊名。所以搬了之後沒有過渡期，代價就是「每棵活樹停下來改表或重掛、每份動態連結的定義重做」。
