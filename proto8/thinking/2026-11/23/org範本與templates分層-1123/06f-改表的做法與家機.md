# 06f 改表的做法與家機

← [06 入口](06-三分的施工設計.md)｜清單在 [06e](06e-切換步驟.md)

## 結論

- **推薦停著改檔**：daemon 全停之後，用一支腳本把每台 daemon 的 stack 裡幾種固定的檔照 [06a 對照表](06a-目標目錄.md)換字，改之前留備份。
- 起來後用 `aos-agent ctl set-def` 改不完：帶環境值掛的列它不收，agent 自己那份 `tools.json` 它不改。它留著當**個別一列的備案**。
- 停著改 daemon 的狀態檔沒有先例，所以**今晚一定要在暫存樹預演過**（06e「今晚要備好的」第 3 項）。

## 表存在哪（不是猜的）

出處：`proto8/cpp/aos-daemon/src/daemon/adopt.cpp`、`reconcile.cpp`，`aos-daemon/docs/03`、`04`，知識庫 `aos/cli/agent.md`、`cli/daemon.md`；這棵樹的檔我唯讀看過（只看路徑欄，環境值沒看）。

- 表是 **`<daemon 的 stack>/procs_state.json` 的 `procs`**。daemon 起來時照它把每一列接回（`adopt()`）；列很多時主檔會寫成 `{"$ref": [分檔…]}`，這棵沒切。
- 一列裡定義路徑出現的地方：`exec`、`def`、`launch.exec`、`as_written.def`、`as_written.exec`。每次起一列，daemon 先照 `as_written` 記的原樣重算路徑（`refresh()`），再用 `launch`。算不出來，那一列變 `stopped`、原因寫 `failed to start: …`，其他列照起。
- 主檔讀不了或不是合法 JSON：daemon 把它改名成 `procs_state.json.bad-<時間>`，**從空表起**。所以改完一定要用 JSON 解析驗一次。
- 這棵樹看到的兩種列：

| 列 | 表上 | 表以外 |
|---|---|---|
| `eca-aos`（普通掛法） | `exec`、`def`＝`../proto8/templates/eca-claude`；`as_written`＝`{"$env": "AOS_HOME", "$path": "/templates/eca-claude"}` | `procs/eca-aos/tools.json`（它自己加過工具）的 `$override` 指 `$AOS_HOME/templates/eca-claude/tools.json` |
| `eca-aos-kb`、`-templates`、`-core`（subagent 生的，帶環境值） | `exec` 是 null；`def` 與 `as_written.def` 同上；`launch.exec` 指 `procs/<名>/exec.json#/exec` | **`procs/<名>/exec.json`** 的 `exec.argv` 裡寫 `{"$env": "AOS_DAEMON", "$path": "../proto8/templates/eca-claude"}` |

- 不用改、會自己換新的：`procs/*/claude/mcp.json`（每次起 CLI 重寫，`py/aos/agentlib/cli_mcp.py` 第 181 行）、`hookeds/*/event.json`、`claude/env.json`。不改的歷史：`history.jsonl`、`think/request.json`、信。
- 別棵樹的 stack 我沒讀。除了表與 `exec.json`，還有哪些檔記著舊路徑，以腳本「只列不改」的輸出為準。

## 兩種做法

| | 甲：停著改檔（推薦） | 乙：起來後下指令 |
|---|---|---|
| 怎麼做 | daemon 全停 → 腳本換字 → 起 | 起樹（那 13 列會 `failed to start` 停著）→ 樹外對每列 `aos-agent -d <stack> ctl set-def <名> <新定義>` |
| 帶環境值的列 | 一樣換字（`exec.json`） | `set-def` 不收（`ArgumentsBad`）；要 `ctl rm` 再 `ctl add --envs …`，環境值得重打一次 |
| 原本用 `$AOS_HOME` 指示詞掛的 | 指示詞原樣留著 | `set-def` 只收路徑，表上變成記相對路徑，指示詞沒了 |
| agent 自己那份 `tools.json` | 一樣換字 | `set-def` 只印一行提醒、不改；要 `tools reset` 再把工具加回去 |
| 樹起著時的狀態 | 每一列第一次起就是對的 | 有一段時間 13 列全停著；`rm` 到 `add` 中間那一列不在表上，subagent 的上層這時對它下指令，就會把它從自己的帳上忘掉 |
| 風險 | 手改 daemon 的狀態檔，文件沒教過；改壞主檔＝整張表被當壞檔丟開 | 舊定義夾已經不在時 `set-def` 走不走得完，沒試過 |
| 退回 | 備份蓋回去 | 逐列再改一次 |

甲的風險靠三件事壓：先備份、改完解析驗一次、今晚預演。

## 改表腳本 `stack_paths.py` 的規格

- **拒絕在樹起著時跑**：有任何 `aos-daemon` 行程就退出（`--defs` 不受限）。
- `--root <根 daemon 的 stack>`：讀它的表，哪一列的 stack 裡自己有 `procs_state.json` 就是一台子 daemon，再往下走。走到的每台都處理。
- **會改的檔（白名單）**：每台的 `procs_state.json` 與它 `$ref` 的分檔；每列 stack 裡的 `exec.json`、`loop.json`、`tools.json`、`llm.json`、`hookeds.json`、`subagents.json`（都只看 stack 第一層）。
- **只列不改**：stack 裡其他命中的小檔（列出路徑與行數，給人判斷）；`history*`、`mailbox/`、`queue/`、`think/`、`claude/` 連讀都不讀。
- 換字的規則＝06a 對照表（先檔後夾、長的先比、要有邊界）。只動字串裡那一段，其餘位元組不變。
- 預設只列：每台 daemon、每個檔、每一處「舊 → 新」。`--apply`：每個要改的檔先抄成 `<檔>.bak-trisplit-1124`、記進清冊（`out/manifest.tsv`），寫完重新解析一次 JSON，再數一次命中應為 0。
- `--defs <夾>…`：對定義夾底下的 `*.json` 做同一件事（給別的專案那 6 份用），一樣備份、進清冊。
- `--restore <清冊>`：把備份蓋回去。
- 不印、不存任何環境值；輸出只有路徑與被換的那一小段。

這支是一次性的工具，放規劃夾 `06-switch/`，不進 `proto8/`；它不是產品裡的遷移程式。不想用腳本也可以照「只列不改」的輸出手動改，這棵樹是 5 個檔。

## 個別一列的備案（起樹之後才發現某一列沒起來）

- **普通掛的列**：樹外打 `aos-agent -d <stack> ctl set-def <名> <新定義夾>`。不能由那隻 agent 自己打。
- **帶環境值的列**：`aos-agent -d <stack> ctl rm <名>`（不帶 `--purge`，stack 留著），再 `aos-agent -d <stack> ctl add -n <名> -s <它的 stack> -w <工作區> --envs … <新定義夾>`。環境值照備份的 `exec.json` 抄，不要貼到信或筆記裡。subagent 的上層只記孩子的名字與 stack，名字與 stack 不變就接得回去；中間別讓上層對這個孩子下指令。
- **格的路徑錯**（agent-fsm 的列一起就停）：看那份定義的 `fsm.json` 四格是不是指到 `lib/aos/apps/agent_fsm/`，改完 `ctl start`。

## 家機照做

家機現況沒查（有幾棵樹、掛了幾列範本、`~/aos-home` 改成新的一套了沒）。步驟一樣，數字以腳本的輸出為準。

1. **等公司這台 push 之後**再做。pull 之前家機照舊能跑。
2. **先停樹，再 pull**。pull 一進來範本夾就搬了，還在跑的樹當下就斷。家機若還是舊樣子（llm kernel 自己一台），兩台都停；[03-換機「家機照做」](../../../../../wf/workflows/dev-env/03-換機.md)那一節還沒做的話，趁這次停機一起做。
3. `git pull` → `python3 proto8/install.py` → 清掉舊範本夾留下的 `__pycache__` 與空夾。
4. `stack_paths.py --root <家機的根的 stack>`（舊樣子就每台各跑一次）：先只列、看過再 `--apply`。
5. 家機上別的專案 repo：協調者已經交了新定義的就 pull；還沒交的用 `--defs` 改。
6. 起樹，照 06e「每一列怎麼驗」驗。
7. 家機的 `~/aos-home/root`、`~/aos-home/llm` 是抄本，不受搬夾影響。範本 `llm-kernel/kernel.json` 裡示範用的假腦腳本寫著 `/templates/agent-fsm`（兩處），抄本如果還留著那一段，只有跑那個示範才用得到，可以順手換字。公司這台的 `~/aos-home/llm` 同理（兩台的 `~/aos-home` 我都沒讀，這一條是照範本推的）。
