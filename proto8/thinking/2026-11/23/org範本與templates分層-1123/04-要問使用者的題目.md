要使用者拍板的五題：templates 分層做到哪、org 範本的形狀、附不附 agent 定義、用什麼語言、現有的 org 要不要跟著改；每題有選項、後果與規劃員的推薦（推薦只是建議）。

# 04 要問使用者的題目

← [入口](README.md)｜依據：[01](01-四個樣本的總結.md)、[02](02-org範本的設計.md)、[03](03-templates分層.md)

第 1 題決定施工範圍，最要緊。第 2～4 題決定範本長怎樣，都照推薦的話 `draft/` 的初稿可以直接交給範本位子。第 5 題會碰到你別的專案。

## 第 1 題：templates 分層做到哪一步？

白話：你說的三類裡，`orgs` 是新的，`kernels` 其實已經有了（叫 `templates/kernel/`），`agents` 搬起來最貴，因為 `templates/agent-fsm`、`templates/eca-claude` 這兩個路徑是正在跑的 agent 每次都要去找的位址。

| 選項 | 做什麼 | 後果 |
|---|---|---|
| **甲（推薦）** | 只新增 `templates/orgs/`，其餘不動 | 什麼都不會斷；頂層還是 16 夾；`kernel` 單數、`orgs` 複數 |
| 乙 | 甲，再把 `kernel/` 改名 `kernels/` | 多改約 60 個檔的字與路徑；純改名；活樹照理不用動（別棵沒查） |
| 丙 | 照原話三分，agent 範本搬進 `templates/agents/` | 改 200 個以上的檔、含程式六處；這棵樹停下來改四列；arena_cheater 的七份定義重做；別棵樹與家機也要改；現有 14 個範本夾還有 7 個歸不進三類，要另外決定 |

推薦甲的理由：org 範本不必等分層；三類有兩類甲就到位；丙換來的是資料夾好看，付出的是每棵活樹停工。選甲又在意名字的話，新夾也可以叫 `org`（跟 `kernel` 一樣單數），不用改舊的。

## 第 2 題：org 範本做一副骨架，還是做兩套現成的？

白話：三個有 org 的專案，骨架一樣，不一樣的地方是九個各自獨立的選擇（誰 commit、成員常駐還是按需、要不要審查位子…）。paper_readings 既不是小型工作室也不是多部門。

| 選項 | 做什麼 | 後果 |
|---|---|---|
| **a（推薦）** | 一副骨架，加一份九題的選擇題 `CHOICES.md`，加幾樣選用件（打雜工的卡、改進紀錄、品質閘門） | 抄過去要自己答九題；只維護一套 |
| b | 兩套填好的：小型工作室版（照這個 repo）、多部門版（照 arena_cheater） | 抄了就能用、不用想；但兩套要一起維護，而且第三種形狀（像 paper_readings）兩套都不合 |

骨架夾的名字我先叫 `templates/orgs/basic`，你可以換。

## 第 3 題：範本要不要附現成的 agent 定義？

白話：定義＝一隻 agent 的設定夾。三個專案的定義身體、腦、抄法都不一樣，真正一樣的只有系統文字那一段（「你是哪個位子、先讀角色卡、衝突時照角色卡」）。

| 選項 | 做什麼 | 後果 |
|---|---|---|
| **a（推薦）** | 不附定義，只附那段系統文字與掛法的步驟 | 抄的人自己 `agent_def new` 再貼上文字，多一步；範本位子不用多顧一組抄本 |
| b | 附兩份定義夾（eca 位子一份、agent-fsm 位子一份） | 抄了改名字就能掛；但它們是 `eca-claude`、`agent-fsm` 的抄本，原範本每次改都要同步，還要加測試盯著 |

## 第 4 題：範本內容用英文還是中文？

白話：現有範本裡，給 agent 讀、會被整夾抄走的是英文（kits 的規矩是「檔案一律英文、中立」，知識庫是「內容語言英文」）；但你四個專案的角色卡全是繁中。

| 選項 | 做什麼 | 後果 |
|---|---|---|
| **a（推薦）** | 英文（初稿已經是） | 跟其他範本一致；你自己的專案抄過去，骨架句是英文、填的內容用中文，或邊填邊改成中文 |
| b | 繁中 | 你的專案抄了就合用；但它是 `proto8/templates/` 裡第一個給 agent 讀的中文範本，跟 kits 的規矩不一致 |
| c | 英文一份，另放一份繁中對照 | 兩邊都方便；兩份要一起改 |

## 第 5 題：現有的 org 要不要跟著範本改？

白話：範本是從這四個專案總結出來的，它們現在各自能用。回頭對齊，會動到你別的專案。

| 選項 | 做什麼 | 後果 |
|---|---|---|
| **a（推薦）** | 都不改。只在這個 repo 的 `wf/org` 入口加一行「範本在哪」；別的專案不動、不寄信，你想讓哪個專案用再說 | 沒有風險；範本先只服務新專案 |
| b | 這個 repo 的 `wf/org` 照範本對一遍（補上它沒有的，例：九個選擇各自選了什麼） | 順便拿自己當第一個試用者；`wf/org` 今天才定，又要動一次 |
| c | b，再由 eca-aos 寄一封短信給 arena_cheater、paper_readings 的 main，告知範本位置（不要求它們改） | 那邊知道有範本可以對照；arena_cheater 的 `aos-feedback.md` 記著你說過別一直寄信給 eca-aos，paper_readings 也照同樣的做法；這封是反方向的，要你點頭 |
