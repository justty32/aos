# kernel 是橋樑：對到現況——現在叫 kernel 的有哪些、根替底下橋了 linux 的哪些、子 daemon 從根拿到哪些（11-12 查程式的結果）

← [kernel-as-bridge](README.md)｜下一份 [02-整理法](02-整理法.md)

## 現在叫 kernel 的東西

| 東西 | 它實際做什麼 | 它碰不碰底下 |
|---|---|---|
| daemon（`impls/aos-daemon`） | 照表起 proc、看活著、退了照表重起、收掛 proc 的信、把狀態寫成公開檔 | **碰**：自己 `fork`、`waitpid`、送訊號 |
| 判官（`lib/aos/judge`；範本 `kernel/daemon-judge`、`kernel/procs-kernel`） | 看白名單與同時在跑上限，放行就把信轉寄給 daemon | 不碰，只轉信 |
| 問腦總機（`impls/aos-llm-kernel`；範本 `kernel/llm-kernel`） | 收問腦請求、排先後、看格數與額度、記帳；放行就**寄信請 daemon** 掛一個問腦 proc | 不碰；真正打 LLM 的是問腦 proc 裡的 endpoint 函數 |
| 隊 kernel（`kernel/llm-team`） | 把問腦請求轉交給下一台總機 | 不碰 |
| 通用 kernel 框架（[圖紙](../kernel-framework/README.md)，未施工） | 判官與總機共用的骨架與零件 | 不碰，「自己跑」零件也是寄信請 daemon 掛 |

所以現在只有 daemon 是真的把請求變成 linux 動作的那一個；其他叫 kernel 的都是「信到 daemon 之前的關卡」。

## 逐項：橋了沒

「根對 linux」＝根 daemon 有沒有替底下的東西把這件事包起來（底下的東西寄信或讀檔就好，不必自己碰 linux）。「子 daemon 對根」＝子 daemon 這件事是跟根拿，還是自己直接碰 linux。

| # | linux 的東西 | 根對 linux | 子 daemon 對根 |
|---|---|---|---|
| 1 | 起行程、停行程 | **已是橋**：寄信到 `procs_requests`，daemon 才 `fork`（先 `setsid`） | 子 daemon 自己被起、被停＝**跟根拿**；它底下的 proc＝**自己 fork，繞過根** |
| 2 | 退了重起 | **已是橋**：照表重起，連三次三秒內就退才停手 | 子 daemon 被重起＝**跟根拿**；它底下的 proc 它自己重起 |
| 3 | 訊號與 pid | **已是橋**：no-pid 定「只有上一層動 pid」，別人一律寄信 | 各層只對自己的孩子送訊號；子 daemon 對自己的孩子**直接碰 linux** |
| 4 | 活不活著 | **已是橋**：公開的表 `procs_state.json` | 問子 daemon 活不活＝讀根的表，**已是這樣** |
| 5 | 環境變數 | **已是橋**：`AOS_STACK`、`AOS_DAEMON`、`AOS_WS` 由 daemon 設，其餘由 `.env` 往下繼承 | **跟根拿**（繼承） |
| 6 | 時鐘（tick） | **已是橋**：根的表上一列 `_clock`，大家讀 `AOS_CLOCK` 那份鐘檔 | **跟根拿**（讀根的鐘檔） |
| 7 | 牆鐘 | 沒有橋：誰要誰自己問 linux | **直接碰 linux**；daemon 內部算逾時也直接用 linux 的鐘 |
| 8 | 檔案系統 | 只指派位置（小格、工作區），讀寫不經 daemon | 位置跟根拿，讀寫**直接碰 linux** |
| 9 | 信（proc 之間交流） | 不經 daemon：信是檔，寄件人直接寫進對方信箱 | **直接碰 linux**（檔案系統） |
| 10 | 單一行程的上限、換帳號 | **已是橋（小）**：`limits`（記憶體、CPU 秒、行程數、檔案、`user`）起 proc 時套，由 linux 執行 | 上限不能比上一層寬（linux 天生如此）＝唯一一處「上層給多少、下層最多這麼多」 |
| 11 | 總量上限（cgroup） | **沒有**（只在規劃） | 沒有 |
| 12 | 同時在跑幾個 | 不歸 daemon：判官的 `max_running`、總機的格數 | **沒有往下切**：根把子 daemon 算一格，裡面掛幾個根不知道 |
| 13 | 沙箱（bwrap） | 不自動套：要自己把 `aos-sandbox` 寫進要跑的指令 | 直接靠 linux |
| 14 | 網路 | **沒有** | **直接碰 linux**（問腦 proc 自己連出去） |
| 15 | LLM | 不歸 daemon：問腦總機（`AOS_LLM_KERNEL` 往下繼承） | 經總機，**已是橋**（另一座） |

**數一下**：根對 linux——已是橋 7 項（1～6、10）、只做一半或不歸它 5 項（8、9、12、13、15）、沒有 3 項（7、11、14）。子 daemon 對根——跟根拿 5 項（自己的起停、重起、活不活、環境變數、時鐘）、直接碰 linux 繞過根 7 項（底下 proc 的 fork／重起／訊號、牆鐘、檔案、信、網路、沙箱）、沒有 2 項（總量、格數往下切）。

## 兩種「下面」

對下來，aos 裡其實有兩種「下一層」，使用者那句話在兩種身上成立的程度不同：

**形一：監管樹上的子 daemon。** 根只給它三樣：電源（起、看活著、重起、收工時一層層睡醒）、時鐘、環境變數。其餘它都直接跟 linux 要。

```
        子 daemon 的 proc
              │ 寄信
          子 daemon ──────────┐
    電源／時鐘／環境 │          │ fork、檔案、牆鐘、網路
          根 daemon           │（直接碰，沒經過根）
              │               │
            linux ◄───────────┘
```

**形二：請求鏈上的站。** agent 的信一站一站往下轉，中間的站完全不碰 linux，最後一台 daemon 才動手。圖紙的 `next`（下一站）就是這條鏈的下一步。

```
   agent ─信→ 站 ─信→ 站 ─信→ daemon ─fork→ linux
              （中間的站只看得到下一站）
```

使用者那句話講的是形一。形一裡，**管你的事**（起、關、重起、時鐘、環境）走上一層，**你做的事**（開行程、讀寫檔）直通 linux。這不算打折——真的虛擬機也是這樣：裡面的系統跑一般指令時直接用真的 CPU，只有電源與特權的事才經過主機，沒有人因此說主機不是它的硬體（這一點是 Argon 指正的，同意，見 [04](04-Argon審查.md)）。

形二是另一種關係：C-47 的請求鏈，「我的請求寄給誰，誰就是我的 kernel」。問腦總機是形二的小例子：它自己是一台子 daemon 的身體，但問腦 proc 不是它 fork 的，是它寄信請 daemon 掛的。

**所以「下面」有兩個意思，在根身上重合，在子 daemon 身上分開：**

| | 誰起我、能關我（硬體） | 我的請求寄給誰（C-47 的 kernel） |
|---|---|---|
| 根 daemon | linux | linux |
| 子 daemon | 根 daemon | linux（它自己 fork） |
| 判官、總機（站） | 起它的那台 daemon | 下一站／daemon |
| 一般 agent | 起它的那台 daemon | `AOS_KERNEL` |

使用者這次的話是照左欄認硬體；C-47 是照右欄認 kernel。兩欄不必同一個東西。

## 「父只看活著」跟「上一層是硬體」合不合

合。真的硬體也不看作業系統裡面在做什麼；它只供電、給時鐘，當機了有看門狗把它重開。no-pid 的「子daemon管好自己，父daemon只看他有沒有活着，子daemon的其他東西父daemon別碰。盡量解耦合。」（使用者 11-06）正好是這個樣子：照表重起＝重新上電，`restart_on_stuck`＝看門狗。不合的是反方向——若要求子 daemon 每件事都經過根，根就得知道子底下掛了什麼，那才跟「父只看活著」打架（見 [03 § 嚴不嚴格](03-邊緣狀況.md#嚴不嚴格)）。
