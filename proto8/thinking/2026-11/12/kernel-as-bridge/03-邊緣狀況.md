## 嚴不嚴格

「上一層是硬體」可以嚴到三個程度：

| 程度 | 意思 | 現在是不是 | 後果 |
|---|---|---|---|
| ① 照現況 | 管你的事（電源、時鐘、環境）經上一層，你做的事直通 linux；不加任何規矩 | 是 | 什麼都不用做；總量上限沒有人擋 |
| ② 上層畫框、下層在框裡直接碰 linux | 上一層在起你的時候定好你的規格（環境、時鐘、上限、帳號、沙箱），之後你在框裡直接用 linux；像容器 | 一半：環境、時鐘、單一行程上限有；總量上限、沙箱自動套沒有 | 要補的是「起的時候多套幾樣」（cgroup、bwrap、帳號，[os-impl](../../06/os-impl/README.md) 都列在只規劃的那組）；不用改信怎麼走；「父只看活著」不受影響 |
| ③ 全部經上一層 | 子層要一個行程也得寄信跟上一層要，自己不 fork | 只有形二的站是（判官、總機） | 所有 proc 都掛在根的表上，根什麼都知道——跟「父只看活著……盡量解耦合」（使用者 11-06）相反；每多一層多等一拍；根一停，底下誰也起不了新行程 |

要點：

- **③ 現在就能當一種擺法做出來，不必當全體規矩。** 把子層做成站（不是一台自己掛 proc 的 daemon），它的 `next` 指向根，proc 就全掛在根的表上。要嚴格的地方這樣擺，不要的地方照形一。這跟 C-47「擺法只是範例」同一個精神。代價是那一層不再是 daemon、退成一個判官（Argon 也點了這個）。
- **嚴不嚴格 aos 自己說了不算，linux 說了才算。** 同一台機器上都是 linux 行程，沒設帳號與沙箱時，誰都能繞過上一層直接碰 linux（eca 的 Bash 擋不住就是這件事）。這時「上一層是硬體」是約定，跟 `AOS_DAEMON`「照傳，約定不用」同一種。使用者 11-11 的立場「保底的安全機制，就是linux本身」在這個看法下讀得通：真的硬體也是這樣——記憶體保護是晶片在擋，kernel 只負責設定；對應過來就是「擋是 linux 在擋，每一層 kernel 只負責起 proc 的時候把帳號、沙箱套上去」。
- 嚴格的話根要提供的「系統呼叫」＝現在的 ctl 信那一組（掛、拿掉、停、起、睡、醒、ping）加圖紙的狀態查詢信；現在沒有而會需要的是「我有多少額度」這種查規格的信。

- **跳層寄信**（Argon 補的，同意）：檔案系統是共用的，子 daemon 底下的 proc 可以直接寄信給根，請根掛一個 proc。後果不只是繞過子層的管制：那個 proc 掛在根的表上，子 daemon 收工或重起時不知道有它，子樹收不乾淨。現在靠約定（一般 proc 只寄 `AOS_KERNEL`）與 linux 權限擋。
- **往上偷看**（Argon 補的，同意）：根的表只看得到「子 daemon 一列」，看不到裡面——這合「父不碰子」。反過來沒設檔案權限時，子層裡的 proc 讀得到根的整張表。同樣靠 linux 權限；圖紙的狀態查詢信（中間站可以換成刪減版）是約定面的對應。

## 硬體壞了

- **根被 `kill -9`**：底下全部照跑（每個 proc 起的時候都自成一組，不跟著死），根再起來時把整棵樹接回去；實測約 0.02～0.04 秒、葉子的行程沒換過（[no-pid 19](../../05/no-pid/19-P9邊緣實測.md)）。**這裡比喻不貼**：真的硬體斷電，上面全滅；aos 是「板子沒了，程式還在跑」，因為真正供電的是 linux。屬天然差異，而且是好的那種。
- 根不在的那段時間：寄給根的信堆在信箱（信是檔），根回來再收；寄件人照自己設的逾時算失敗。鐘是根底下的一個 proc，根死了它還在走。
- **子 daemon 掛了**：對根就是「一個孩子退了」，照表重起；它底下的 proc 變孤兒繼續跑，子 daemon 回來接回。對上面的人，這像一個裝置重新上電。
- **卡住**：`restart_on_stuck` 就是看門狗；預設只標 `stuck` 等人，像亮故障燈。

## 資源往下怎麼切

- **形二（信一站站往下）天然成立**：下一層答應得再多，上一層不放行就是不放行；下層頂多「超賣」，然後收到拒信。隊 kernel 轉交給總機就是這樣，總機照寄件人記帳。
- **形一（子 daemon 直接碰 linux）現在不成立**：根的 `max_running` 把一台子 daemon 算一格，子底下掛一百個根也不知道。唯一天生往下收的是單一行程的 `limits`（子項設得比上一層寬會直接失敗）。要成立得靠 linux 的總量上限（cgroup）：上一層起你的時候把框定好，linux 代為執行——就是上表的 ②。
- 總機的保留格、寄件人額度現在全寫在最底那台總機的 `kernel.json`，沒有「上層給隊多少、隊再往下分」的層級；隊 kernel 自己再設一份額度的話，兩份帳各記各的，不保證加起來對得上（kernel-nest 已知）。
- 誰說了算：照這個看法就是**上一層**——硬體有多少就是多少，下層只能在裡面分。這句現在只有形二做得到。

## 時間

- 根的 `_clock`＝板載晶振，[板子比喻](../../../../docs/CONCEPTS/附錄1-續-板子比喻.md)已經這樣寫，新看法直接接上。
- 子層如果自己表上也帶一列 `_clock`、把 `AOS_CLOCK` 改指自己那份，它那棵子樹就有自己的時間（可以慢、可以停）——「上一層給的時鐘」變成可以換的。現在沒人這樣擺，但做得到。
- 牆鐘大家各自問 linux，沒有橋。根停著時 tick 不走、牆鐘照走，兩種時間會岔開（板子比喻的「牆鐘＝RTC」已記）。
- `on_clock` 讀的是鐘檔；鐘照登記表寄信叫人，像定時中斷——aos 沒有真的中斷，都是輪詢（已記的天然差異）。

## 身分與權限

- no-pid（別人不碰 pid、一律寄信）是「上面的東西不直接碰硬體」的約定面；真要擋住靠 linux 帳號。
- 沙箱歸誰：照橋的看法，**起 proc 的那一層**負責套（它是唯一知道要起什麼的）。現在 daemon 只套 `limits`（含換帳號），bwrap 要自己寫進指令。
- eca 的身體（claude、codex 的 CLI）自己有 Bash：它是一個不經 kernel 就能碰 linux 的 user space 程式。在 ① 之下這不算違規，只是風險自擔；要它守規矩只能靠 ②（把它關進框）。

## 跨機

現在沒有跨機實作（搬家是把 stack 整包搬過去再起根，不是連線）。照這個看法推：

- 兩台機器各一個根＝兩塊板子，各有各的 linux；之間只能靠信。
- 一個根「掛」遠端 daemon 做不到現在意義上的掛——看活著靠的是 linux 的父子行程，跨不了機器。遠端那台的硬體是它自己的 linux；對本機來說它比較像**外接設備**（C-29 的外部 PU），不是下一層。
- 順帶一個判準：**你的硬體＝起你、能關你的那一個。** 用它量，跨機與 LLM 供應商都落在「外接設備」，不落在層上。
- 形一的子 daemon 只跟根拿電源、時鐘、環境三樣，所以整棵子樹很好搬（換一塊板子插上去）；③ 越嚴格越難搬。

## 最下面與最上面

- **最下面**：根的硬體是 linux，linux 之下不管。但「地」不只 linux 一種（LLM 供應商、人），見 [02](02-整理法.md#問腦總機判官在新看法下算什麼)。
- **最上面的 agent 算不算一層 kernel**：不太算，比喻在這裡開始不貼。agent 開 subagent、fork 時，動手掛的是 daemon，不是 agent；subagent 的電源是 daemon。agent 對 subagent 是**交代工作的人**（在它上面），不是它的硬體（在它下面）。所以有兩棵方向相反的樹：daemon 樹是「誰供應誰」，agent 樹是「誰叫誰做事」；一層一層的硬體關係只沿 daemon 樹走。
- 例外：eca 的 claude 身用內建 `Agent` 工具開的子 agent 活在那個 CLI 行程裡，CLI 才是它們的硬體，aos 看不到也管不到。
- 照 C-47「從外面看」，agent 可以是別人的 kernel（工具把請求交給一隻專門的 agent 判）——那是做主那半，跟它是不是誰的硬體無關。

## 其他不貼的地方（列出，不解）

- 真的硬體不會變、不能熱換；aos 的上一層可以整個重起、表可以邊跑邊改。
- 真的 kernel 獨佔硬體；aos 的每一層都跟別人共用同一個 linux、同一個檔案系統、同一套行程編號。信、狀態檔、重起後接回孩子，全都直接踩在 linux 上，不經任何一層——上一層給的是開關與設定，真正的線路一直是 linux（Argon 的說法，同意）。
- 鏈每多一站多等那一站的一拍（例：判官範本 300 毫秒一拍）；真的系統呼叫沒有這種延遲。
- 硬體不會拒絕你；aos 的上一層可以拒信（它同時是做主的）。
