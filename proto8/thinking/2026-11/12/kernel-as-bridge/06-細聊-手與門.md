# kernel 細聊（11-12 晚，家機）：每一層的頂分「手」（daemon）與「門」（kernel）兩個角色，使用者定 kernel 是主觀的概念、daemon 也是概念；「資源排程別叫 kernel」收回、名字都不改

## 對話（依序）

1. 使用者：「來聊kernel吧」
2. 頂層整理現況：名字帶 kernel 的（`proto8/kernel/` 判官、`aos-llm-kernel` 問腦總機、`AOS_KERNEL`、kernel 框架圖紙）都屬「排程」那一半，真正當「橋」的 daemon 不叫 kernel；問是「以後 kernel 指 daemon、那四樣都改名」，還是輕一點。
3. 使用者：「你覺得呢？kernel這個意思到底應該定義爲啥...我其實沒啥想法，只是看到linux kernel做了那些就這樣想...」
4. 頂層的看法（頂層提的）：kernel 的定義是**「唯一的門」**——那個資源只有它碰得到，別人要用都得來問它。「橋」與「排程」都從這點長出來、有先後：先是唯一的門，才排得了程；什麼都不排的門仍是 kernel，繞得過去的排程者只是顧問。測法：把它拿掉，底下還碰不碰得到那個資源。照這個量：問腦總機很像 kernel（通往 LLM 的唯一的門，若金鑰只在它手上）；根 daemon 只有一半（只對「被起、被關」是唯一的門）；判官頂層沒把握。建議現在名字都不改。
5. 使用者：「Hmmm，其實早期，大約上個月吧，或者是更早之前的proto6,7之類(不用去翻)，我就是說有一個daemon，掌管aos proc的生死，而kernel則是他底下的一個特殊proc，是唯一具有權限能下daemon ctl的proc。後來發現除了root daemon需要處理linux相關的事物之外，其他daemon，其實本身就既是kernel也是daemon，因爲daemon本身是proc...整個很像，我混淆了，但同時我又覺得他們就是同種東西。」
6. 頂層的整理（頂層提的）：每一層的頂有兩個角色——**手**（真的動手起、關行程的，daemon）與**門**（唯一有資格叫那雙手做事的，kernel）。可以是同一個行程，也可以拆成兩個；從裡面看是兩個角色，從下面（被管的 proc）看永遠是一個東西。子 daemon 同時站兩個位置：對上一層是被管的 proc，對下一層就是「上面那個東西」。根 daemon 特別只在它上面沒有 aos 的東西、直接是 linux。「daemon 是手的名字，kernel 是門的名字」。
7. 使用者（結論）：「好，就是這樣。所以kernel仍會作爲一個概念存在，只要是符合這個概念的proc(或可發送請求的目標)，對於需要他的proc來說(在他心中)，那就是kernel，這是主觀的。而daemon，因爲有root daemon的存在所以比較難界定，但我覺得daemon也仍會作爲一個概念，只是root daemon爲了在linux上實現這個概念，所以做了比較多事情」
8. 頂層問（頂層提的）：照剛才的結論，「資源排程這塊還是別叫 kernel」可以收回——問腦總機、判官只要對某個 proc 來說是「請求要寄去的那道門」，在那個 proc 心中就是 kernel；它們叫 kernel 是因為是門、不是因為會排程。所以現有名字都不用改、那句收回，對嗎？
9. 使用者：「對，收回，名字都不用改。就是daemon這塊你能多說一些嗎？我要建立自己的心智模型」
10. 頂層講 daemon（頂層講的，照 [01-對到現況](01-對到現況.md) 查到的事實，濃縮）：daemon＝「一張表，加上一雙照表做事的手」，讓現實跟表一樣。它做的六件事：起／關行程（要寄信它才動手）、死了照表重起（連三次三秒內就死才停手）、送訊號（只有它對自己起的 proc 送）、公開「誰活著」的檔、給環境變數、給時鐘；另可在起 proc 時套上限（由 linux 執行）。它不管的：檔案讀寫、信、網路、現在幾點、「該不該起」（那是門的事）、proc 在裡面做什麼。性格：故意很笨，不做決定、只動手、只看生死（對應使用者 11-06「父 daemon 只看他有沒有活著…盡量解耦合」）。子 daemon＝表上某一列剛好自己也是 daemon：對上面是一個 proc（被起、被關、被重起、拿環境變數與時鐘這五樣跟上一層拿），對下面自己有表有手、底下的 proc 直接跟 linux 要、根不知道它裡面掛幾個。根 daemon 跟子 daemon 是同一支程式；差別只在它上面沒有人（沒人替它重起、鐘要掛在自己表上）、它是第一個碰到 linux 的——所以「不是根多做了事，而是別的 daemon 有上一層可以靠，它沒有」。每一層往下給的都是電源、時鐘、環境變數三樣；每一層自己做事都直接找 linux。
11. 使用者：「我覺得這樣就OK了」

## 決定（他明講或明確同意的）

- 「手／門」的整理同意（「好，就是這樣。」）：daemon 是手的名字，kernel 是門的名字；同一個行程可以兩者都是。
- kernel 是一個**概念**，而且是**主觀的**：凡是符合這個概念的 proc（或可以寄請求過去的目標），對需要它的那個 proc 來說（在它心中）就是 kernel。
- daemon 也是一個概念；根 daemon 只是為了在 linux 上實現這個概念，多做了比較多事。
- **「資源排程別叫 kernel」收回**（「對，收回，名字都不用改。」）：問腦總機、判官叫 kernel 是因為對寄件的 proc 來說是門，不是因為會排程。現有名字（`AOS_KERNEL`、`proto8/kernel/`、`aos-llm-kernel`、kernel 框架圖紙的名字）都不改；題 2（kernel 一詞留給誰）已結。
- **daemon 的心智模型（第 10 點）他認可**（「我覺得這樣就OK了」）。
