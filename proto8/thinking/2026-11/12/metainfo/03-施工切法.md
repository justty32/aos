# 03 施工切法：照使用者裁定重切成兩段——① 條文（必做）② 我們自己的工具各自小改支援（選做清單，使用者挑）

**11-12 下午使用者兩次裁定後整份重切**：原本的 S1～S4（搬 index、搬 description、搬 tooldef 並刪 72 檔、落條文）作廢。現在沒有內容搬家、沒有刪檔、沒有持久格式改動，**不用重建任何東西**；不動 C++；不做共用模組。待定 `_metainfo` 同日已照當天現況落成 [N-69](../../../../docs/NORMS/10-基礎設施-定義與工作區/11-N-69.md)（Q16），第一段是在 N-69 上補，不是新開一條。

照慣例：改到的說明同一個 commit 跟上、`codemap_gen.py --apply`、wf-lint broken 不超過基準、程式輸出一律英文。合併規則只有一條：**一層、同名整個換、外面贏**（[02 推薦讀法](02-設計.md#推薦讀法先裡面再外面合併外面贏)）。

## 第一段：條文（必做，小，約 6 處文字）

改寫條文不派 sonnet（使用者 10-19）。語氣一律是「約定＋推薦讀法」，不是強制。

- **A1 [N-69](../../../../docs/NORMS/10-基礎設施-定義與工作區/11-N-69.md)**（主體）補一段，內容：
  - 使用者 11-12 三句原話（「…蒐集那些同節點下散落的…各種_*」、tooldef 裡外都讀那段、「只活在概念與規範中…」）。
  - `_metainfo` 除了函數特性，也是口子：`tooldef`、`index`、`description` 三格可以寫在裡面（名字＝外面那個去掉 `_`），跟特性平鋪並排。
  - 推薦讀法：給一個節點，先看 `_metainfo` 有沒有、有就讀，再看獨立的那份、有就讀，兩者合併、獨立那份蓋過裡面；合併只有一層（tooldef 是頂層鍵、index 是逐項、description 是字串直接取代）。
  - 不做專門處理 `_metainfo` 的程式；各工具要不要支援看它自己；目前支援的名單（照第二段實際做了哪些填，沒做就寫「目前都還沒有」）。
  - `_entry`、`.env` 不進；裝不下的節點只有 index 延伸。
  - 「模型看不到」那句補：模型看到的只有 tooldef（支援的工具給的是合併後的）。
  - 最後一句「後續整合想法」的連結改指本夾。
  - index 的 `{名: {"description": …}}`、天然位置在上一層，至今在 proto8/docs 沒有條文（只寫在 `knowledge/docs`），順手在這段點到並連過去，不另開條。
- **A2 [P-41](../../../../docs/CONVENTION/02-題目stack停錯腦/06-P-41.md)**「資料夾裡只認 `_tooldef.json`、`_metainfo.json`…沒有 `_tooldef.json` 的資料夾登記不了」加一句 11-12 註指向 N-69：tooldef 也可以寫在 `_metainfo` 裡；aos-tools 認不認看第二段 B1 做了沒（沒做就寫現況「目前只認獨立那份」）。
- **A3 NORMS 的索引與條號表**：`10-基礎設施-定義與工作區.md` 入口、`附錄1-條號表.md`、`主題.md` 裡 N-69 的一句話標題跟上（如果標題變了）。
- **A4 `knowledge/docs/01-樹長怎樣與多庫.md`、`knowledge/README.md`**：index 與正文的位置各補一句「也可以寫在 `_metainfo` 裡，見 N-69」。
- **驗**：wf-lint broken 不超過基準；連結點得到；N-69 裡每句「程式會怎樣」都跟當下程式對得上（第二段沒做的不能寫成已支援）。

## 第二段：我們自己的工具各自支援（選做，使用者挑）

每項各自一個 commit、各自在自己的程式裡加幾行，不新增共用模組。測試都用暫存資料夾自己造，不動出廠工具夾與出廠內容。

| 項 | 改哪支 | 大小 | 做了之後多什麼 | 相依 |
|---|---|---|---|---|
| B1 | `aos-tools` 的 `inspect()` | 小（約 15 行＋9 支測試） | 只有 `_metainfo.json`（含 `tooldef`）的資料夾、只有 `_metainfo` 鍵的 json 物件，登記得了、腦叫得到 | 無 |
| B2 | `tool_io` 的 `load_tooldef()` | 很小（約 10 行＋4 支測試） | 這種工具自己啟動時也拿得到參數 schema（argv 旗標轉型、`--help`） | 單做沒意義，跟 B1 一起 |
| B3 | `tools_def` 的 `check`／`add_tooldef` | 很小（約 10 行＋2 支測試） | 檢查工具時把裡面的 tooldef 也算「有」；兩處都有時提醒 | 要先有 B1 |
| B4 | `index_view`（`lib/aos_index.py`） | 小（約 25 行＋8 支測試＋說明一句） | 寫在 `_metainfo` 裡的 index 看得到 | 無 |
| B5 | `defs/catalog.py` 的定義記號 | 很小（約 5 行＋1 支測試） | 只放了 index 的 `_metainfo.json` 不會被當成定義 | 無；**不管 B1～B4 做不做都建議做**，因為約定一定下來 agent 就可能這樣寫 |

規劃者的建議：B1＋B2＋B3 當一組（tooldef）、B4 一組（index）、B5 單獨；全做約半天，一名 opus 隊長帶一到兩名隊員，兩組不碰同一個檔可以同時做。只做條文、一支都不改也成立（那 N-69 就寫「目前都還沒有工具支援」）。

### B1：`cmd/aos-tools/bin/aos-tools` 的 `inspect()`

- `kind == "dir"` 分支：先讀 `_metainfo.json`（有就讀；整份讀不了照現行 `ToolDefBad`），取它的 `tooldef`（沒有這鍵＝當沒有；有但不是物件＝`ToolDefBad`，句子寫 `_metainfo.json#/tooldef`）；再讀 `_tooldef.json`（有就讀）；`{**inside, **outside}`；兩處都沒有才 `ToolDefMissing`，句子改成 `needs _tooldef.json inside, or a tooldef key in _metainfo.json`。合併後照舊過 `check_tooldef`。
- json 物件（`檔#/指標`）與整份 json 檔兩個分支：同樣規則，裡面＝`obj["_metainfo"]["tooldef"]`、外面＝`obj["_tooldef"]`。
- 可執行檔分支不動。輸出的 `metainfo` 欄照原樣（不拿掉 `tooldef`）。檔頭註解講「只認 `_tooldef.json`」的幾句跟上。
- 測試（`cmd/aos-tools/tests`）：資料夾與 json 物件兩種形狀各四支——只有外面、只有裡面、兩處都有（外面的 `description` 贏、裡面獨有的 `errors` 留著、`parameters` 整鍵換）、兩處都沒有＝`ToolDefMissing`；另一支裡面的 `tooldef` 是字串＝`ToolDefBad`。
- 驗：該夾測試全過；`aos-tools --file templates/<名>/tools.json ls` 三個範本支數跟施工前一樣；手造一個只有 `_entry`＋`_metainfo.json`（含 `tooldef`）的工具夾，`aos-tools add`／`get`／`call` 走得通；真腦一輪（eca haiku）：登記那支、腦叫得到、參數照 `parameters` 給。
- 說明跟上：`cmd/aos-tools/README.md`、`lib/docs/01-分層等/01-工具契約與規則1至5.md` 契約表那兩列。

### B2：`lib/tool_io.py` 的 `load_tooldef(folder)`

- 先讀 `folder/_metainfo.json` 的 `tooldef`（檔不在、沒有這鍵＝當沒有），再讀 `folder/_tooldef.json`，淺合併；兩處都沒有照舊回 `None`；壞檔照舊只提醒一次（提醒句指明哪個檔）。合併後才驗 `parameters` 是物件。
- 測試（`lib/tests` 的 `test_tool_io*`）：同樣四種。
- 驗：lib 測試全過；B1 手造的那支工具用 argv 旗標叫（`aos-exec 夾 --a 2 --b 3`）數字有轉型、`--help` 印得出參數。

### B3：`lib/agent/tools_def/_entry`

- `load_part(obj, base, "_tooldef")` 的「在不在」改成兩處任一處有、值給合併後的；`check` 的階段句與 `add_tooldef` 的 `PathExists` 判斷跟著對。兩處都有時 `check` 多印一行 `note  tooldef: both _metainfo.json#/tooldef and _tooldef.json; _tooldef.json wins on the same key`。`new`、`add_*` 寫的位置不變（照舊寫外面）。
- 測試（`lib/agent/tools_def/tests`）：只有 `_metainfo.json` 帶 `tooldef` 的夾 `check` 判成 3 of 3；兩處都有時有那行 note。
- 出廠內容 `knowledge/aos/tools_def.json` 補一句。

### B4：`lib/aos_index.py`（`index_view`）

- `spot(t)` 改成回兩個位置（裡面、外面）：資料夾＝`DIR/_metainfo.json#/index`、`DIR/_index.json`；json＝`F#/PTR/_metainfo/index`、`F#/PTR/_index`。
- `natural(path)`：兩處各讀一次，裡面那份為底、`dict.update` 疊上外面那份（逐項整項覆蓋）；兩處都沒有才回「沒有」；任一處不是物件＝`IndexBad` 並指明位置；節點是陣列／純量的提示句照舊。注意現有程式用「指標是空的」認出資料夾那份是整份檔，裡面那份帶指標，這個分支要拆成「讀檔→取鍵」兩段。
- `main()` 的標頭：只有一處有＝`[index] 那一處, N entries`（只有外面時跟現在逐字一樣）；兩處都有＝沿用既有句型 `[index] 裡面 + 外面 (on the same key 外面 wins), N entries`；再給 `index` 參數時三層照順序疊，標頭列出三個位置、最後一個贏。`[no index]` 的提示句不變（照舊教寫獨立那份）。
- `lib/base/index_view/_tooldef.json` 與 `_entry` 檔頭補一句；出廠內容 `knowledge/aos/tools/index_view.json`、`lib/packs/README.md` 各補一句。
- 測試（`lib/tests/test_index_view.py`）：資料夾與 json 物件各補——只有裡面、兩處都有（同名項外面贏、各自獨有的都在、順序裡面在前）、裡面不是物件＝`IndexBad`、三層。現有 8 支不該要改。
- 驗：lib 測試全過；對 `knowledge/aos`（只有外面那份）叫 `index_view` 輸出跟施工前逐字一樣；真腦一輪（eca haiku）：在一個臨時夾的 `_metainfo.json` 用 `json_set` 寫 `#/index/x`，`index_view` 看得到。

### B5：`lib/aos/defs/catalog.py`

- `definitions()` 現在看到 `interfaces.json` 或 `_metainfo.json` 就當成一個定義、不再往下。改成不會被「只有 `index`／`description`／`tooldef`、沒有 `_entry` 也沒有 `interfaces.json`」的 `_metainfo.json` 騙到；做法施工者定（建議：`_metainfo.json` 在而且同夾有 `_entry` 或 `interfaces.json` 才算）。
- 測試（`lib/aos/defs/tests/test_defs.py`）：defs 根底下一個只有 `_metainfo.json`（內容 `{"index": {...}}`）的普通夾，不出現在定義清單、不報「must contain a nonempty summary」，而且會繼續往它底下找定義。現有測試不該紅。

## 收尾

第二段做了哪幾項，回頭把 A1、A2 裡「目前支援的名單」那句填實；全套測試（proto8 底下所有 `tests/` 夾）跑一次，只紅既有 4 支。
