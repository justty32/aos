# 04 要使用者裁的兩題（a/b、後果、推薦）與代定 M1～M13

## 要使用者裁（兩題）

### 題一：`_tooldef` 這次搬不搬進 `_metainfo`

使用者 11-12 的話是猜測口氣：「搞不好_index,_tooldef也會被整合進metainfo」。跟它相碰的既有條文：

- P-41：「資料夾裡只認 `_tooldef.json`、`_metainfo.json`，不帶副檔名的不認；沒有 `_tooldef.json` 的資料夾登記不了」，出處是使用者 11-04 題 8「留 _、加 .json」。
- 10-24 M10（「都按建議做」定的）：tooldef 給模型看、`_metainfo` 給 kernel 與人看，兩者分開，理由是使用者 10-15「小模型注意力有限」。

| | a. 搬（推薦） | b. 這次不搬，只搬 index 與 description |
|---|---|---|
| 一個工具夾 | 剩 `_entry`＋`_metainfo.json` 兩個檔 | 照舊三個檔 |
| 規則 | 一句話講完：節點底下只有 `_entry` 與 `_metainfo` | 多一個例外：`_tooldef` 還在外面 |
| 模型看得到特性嗎 | 看不到。aos-tools 只把 `tooldef` 那格交給腦，M10 的用意照舊，只是不再分兩個檔 | 看不到 |
| 代價 | 72 個工具夾合併、程式約 8 檔、測試約 8 檔、說明約 15 檔，約一天；試驗場裡 agent 自己造的工具要重造；P-41 那句要改字 | 沒有 |
| AI 自己造工具 | 少寫一個檔；但 `tools_def` 重產 tooldef 時要小心別蓋掉同檔的其他格 | 照舊 |

推薦 a，排在第三步（index 先搬、跑順了再做）。選 b 的話前兩步照做，S3 整步不做。

### 題二：「要用不用都可以」是哪個意思

原話：「我們就是開了metainfo這個口子，要用不用都可以。json檔案也一樣。」兩種讀法：

| | a. 只認裡面一處（推薦） | b. 裡面外面都認 |
|---|---|---|
| 意思 | 「要用不用」＝節點可以完全沒有 `_metainfo`；但 index 要寫就寫在 `_metainfo` 裡，外面的 `_index.json`／`_index` 不再認 | 「要用不用」＝index 可以放 `_metainfo` 裡，也可以照舊放外面的 `_index.json`／`_index` |
| 後果 | 位置只有一個，`spot()` 還是一處；腦不用猜 | 兩處都有時要定誰贏；`index_view` 每次要看兩個地方；說明要教兩種寫法 |
| 跟既有原則 | 合 KISS、合「proto8 當沒有舊版、不留舊名」（11-05） | 等於留舊名相容 |

推薦 a。圖紙（[02](02-設計.md)、[03](03-施工切法.md)）照 a 寫；選 b 的話 S1 要加「兩處都看、裡面贏」的規則與測試。

## 代定 M1～M13（照原則定的小事，都可翻）

這裡的 M 是 11-12 這份的編號，跟 [10-24 `_metainfo`](../../../2026-10/24/metainfo/README.md) 的 M1～M10 無關；引用時寫「11-12 M幾」。

| 編號 | 代定 | 依據 |
|---|---|---|
| M1 | `_metainfo` 裡**平鋪**：既有特性 key 留在頂層，`index`、`tooldef`、`description` 跟它們並排，不另外包一層 | N-68 寫的是「頂層 `timeout_ms`」，不動它；KISS |
| M2 | 搬進去只去掉 `_`、其餘不改名；`summary`（一句話）與 `description`（正文）並存不合併 | 使用者「_index進去後就是index，去掉_」；`summary` 是 N-68／10-15 已定的 key |
| M3 | 裝不下的節點（陣列、別人的 json、可執行檔）：只有 `index` 延伸到最近裝得下的上層、鍵寫相對路徑；其他項目不延伸，沒寫＝沒說；可執行檔的 `--tooldef` 照舊 | 使用者 11-12「2,3的確如此」；10-24 M3「沒寫＝沒說」 |
| M4 | `ls`、`json_ls`、`json_search`、`stat` **不藏** `_metainfo`，也不設「底線開頭」的通則 | C-48「`_` 開頭沒有特別意思」；使用者「如果想要真正客觀，那就乖乖用shell ls或是aos json ls」 |
| M5 | index 表不列 `_metainfo`／`_metainfo.json` 自己（慣例，工具不檢查）；`_metainfo.json` 自己沒有 metainfo | 現行 `_index.json` 自己除外的做法 |
| M6 | `_description`（知識庫節點的正文）也搬，叫 `description`；排第二步、可單獨不做 | 使用者「蒐集那些同節點下散落的…各種_*」；沒有程式讀它，搬不搬都不影響程式 |
| M7 | 同一個檔多人寫照舊不上鎖；程式寫 `_metainfo` 一律讀出來、只換自己那幾格、再寫回 | 11-12 json 工具「同時寫不上鎖」 |
| M8 | `_metainfo` 照舊不強迫有；tooldef 搬進去後，要登記成腦的工具才需要 `tooldef` 那格，錯誤代號沿用 `ToolDefMissing`／`ToolDefBad` | N-68「不能假定永遠都有metainfo，而且我們也不該強迫」 |
| M9 | aos-tools 輸出的 `metainfo` 欄拿掉 `tooldef`（已經另有 `tooldef` 欄），其餘照給 | 不重複 |
| M10 | C++ 基礎層（aos-exec、aos-inst、loop、fsm、daemon）照舊不讀 `_metainfo`；10-13「標準實作一律當它不存在」的範圍寫明是基礎層，lib 的工具（aos-tools、act、`index_view`）會讀——這是 11-06 起的現況 | C-74 單向分層；現行程式 |
| M11 | `defs/catalog.py`「有 `_metainfo.json`＝一個定義」的記號，改成不會被只有 `index`／`description` 的檔騙到；做法施工者定 | 邊緣狀況，[02](02-設計.md#邊緣狀況) |
| M12 | 單子裡的 `_metainfo` 鍵（10-13 原本那處）照舊，不特別替它設計 `index`／`tooldef` 的用法 | 用不到就不做 |
| M13 | 「太大才補 index」的門檻、index 一項的格式、天然位置在上一層，全部照 11-12 已定的，不因為搬家而改 | [index](../index.md) 的決定 |

## 看起來像衝突、其實不衝突的（不用裁，記一筆）

- **C-48「`_` 開頭沒有特別意思」vs「`_metainfo` 蒐集各種 `_*`」**：`_metainfo` 是一個照字面認的名字，沒有恢復「底線開頭＝附註」的通則；工具也不因為底線開頭就藏（M4）。
- **10-13「`_metainfo` 給 kernel 參考、標準實作當它不存在」**：使用者 11-12 自己把它的意思放寬了（「天然的，蒐集…各種_*」）；基礎層不讀這一點保留（M10），S4 落條文時照新話寫。
- **「一兩個禮拜後」**：使用者 11-12 下午自己改口「感覺也可以開始先弄了」。
