# 02 設計：`_metainfo` 整合後的位置、形狀、搬進去的名字、留外面的判準、裝不下的節點、工具怎麼跟上、邊緣狀況

← [回入口](README.md)｜上一份：[01-盤點](01-盤點.md)｜下一份：[03-施工切法](03-施工切法.md)

proto8 一律當沒有舊版（使用者 11-05）：不設計遷移、不留舊名、不做相容。代定編號見 [04](04-題與代定.md)。

## 一句話

一個節點（資料夾，或 json 裡的一個物件）底下，aos 自己的東西只剩兩個名字：**`_entry`＝怎麼跑它**，**`_metainfo`＝其他一切關於它的說明與參考**。

## 位置（不變）

| 節點 | `_metainfo` 在哪 | 路徑寫法 |
|---|---|---|
| 資料夾 `DIR/` | 檔 `DIR/_metainfo.json` | `DIR/_metainfo.json#/index` |
| 整份 json 檔 `F.json`（頂層是物件） | 頂層鍵 `_metainfo` | `F.json#/_metainfo/index` |
| json 裡的物件 `F.json#/a/b` | 那個物件的鍵 `_metainfo` | `F.json#/a/b/_metainfo/index` |
| 單子（有 `argv`） | 單子的鍵 `_metainfo`（10-13 原本那處） | 同上 |

資料夾裡帶 `.json`、json 裡不帶，是 11-04 已定的（「留 _、加 .json」）。

## 形狀：一個物件、平鋪（代定 M1、M2）

原有的特性 key 原地不動（N-68 寫的是「頂層 `timeout_ms`」），新加三個通用 key 跟它們並排：

| key | 原本叫 | 值 | 給誰看 |
|---|---|---|---|
| `index` | `_index.json`／`_index` | `{名: {"description": …}}`，鍵是這個節點底下的東西 | agent（經 `index_view`） |
| `tooldef` | `_tooldef.json`／`_tooldef` | `{"description", "parameters", "positional"?, "errors"?, "env"?}`，內容一字不改 | 模型（經 aos-tools）、工具自己 |
| `description` | `_description.json`／`_description` | 字串，節點自己的正文 | agent 直接讀 |
| `summary`、`cost`、`timeout_ms`、`resource`、九軸、`sandbox`、`lineage`、`comfort`… | 不變 | 不變 | kernel、act、aos-mcp、審視者、人 |

- 全部選填（N-68「不強迫」、使用者「要用不用都可以」）。沒有 `_metainfo`＝什麼都沒說。
- 不認得的 key 照 C-48 忽略；人照 C-14 可以再加自己的 key（別跟上面的通用 key 撞名）。
- `summary` 與 `description` 並存：`summary` 是一句話（給 kernel、判官）、`description` 是正文（可以很長）。
- `index` 講的是「底下的東西」，其他 key 講的是「節點自己」；想了解某個節點，照舊去看它上一層的 `index`。

例一，工具資料夾 `lib/base/ls/`（現在三個檔 `_entry`、`_tooldef.json`、`_metainfo.json`，之後兩個）：

```json
{
  "summary": "List a folder one page at a time",
  "resource": "disk",
  "side_effect": false,
  "cost": {"time_ms": 30},
  "timeout_ms": 2000,
  "tooldef": {
    "description": "List a folder. ...",
    "parameters": {"type": "object", "properties": {"path": {"type": "string"}}},
    "errors": ["ArgumentsBad", "FileMissing"]
  }
}
```

例二，出廠內容夾 `knowledge/aos/`（現在 `_index.json`＋`_description.json` 兩個檔，之後一個 `_metainfo.json`）：

```json
{
  "description": "# aos in one page\n\n...",
  "index": {
    "rules.json": {"description": "House rules every agent follows."},
    "cli": {"description": "One file per command."}
  }
}
```

例三，json 檔內（`knowledge/aos/packs.json`）：

```json
{
  "_metainfo": {
    "description": "Tool packs: ...",
    "index": {"about": {"description": "How packs work."}, "look": {"description": "Pack look: read, ls, ..."}}
  },
  "about": "...",
  "look": {"...": "..."}
}
```

## 留在外面的，與判準

**判準：aos-exec 跑它的時候用不用得到。用得到的留外面，其餘進 `_metainfo`。**

- `_entry`、`_entry.json`：入口，aos-exec（C++）照 `AOS_ENTRY` 找；腳本入口本身要能執行，塞不進 json。
- `.env`：aos-exec 起跑前讀。
- 各程式自己的設定檔（`tools.json`、`loop.json`、`fsm.json`、`interfaces.json`…）：是程式本體，不是附屬資訊，本來也不是底線名。

換句話說：把 `_metainfo` 整個拿掉，東西照樣跑得起來——只是沒有說明、沒有視角、登記不成腦的工具、act 不設逾時。C++ 基礎層（aos-exec、aos-inst、loop、fsm、daemon）照舊永遠不開 `_metainfo`（代定 M10）。

## 裝不下的節點（代定 M3）

陣列塞不了鍵、別人的 json 不能亂加鍵、可執行檔沒地方放 json。

- **`index` 照既有規則延伸**（使用者 11-12「2,3的確如此」：放外面、鍵寫路徑）：寫在最近一個裝得下的上層節點的 `_metainfo` 的 `index` 裡，鍵寫從那個節點算起的相對路徑。
  - 陣列 `F.json#/list` 的各項：寫在 `F.json#/_metainfo/index`，鍵 `list/0`、`list/1`。
  - 別人的檔 `DIR/other.json` 的各鍵：寫在 `DIR/_metainfo.json#/index`，鍵 `other.json#/key`。
- **其他項目不延伸**：裝不下＝沒有，沒寫就是沒說。想替它留話，就寫在上層 `index` 那一項裡——那一項本來就是物件，可以放 `description` 以外的東西（使用者原話四「之所以用json obj，是因為obj裡面以後不只會有純文字description」）。
- 可執行檔工具的 `--tooldef` 照舊（P-41）。

## 工具怎麼跟上

| 誰 | 現在 | 之後 |
|---|---|---|
| `lib/aos_index.py` `spot()` | 資料夾 `DIR/_index.json` 整份；json `F#/PTR/_index` | 資料夾 `DIR/_metainfo.json#/index`；json `F#/PTR/_metainfo/index` |
| 同檔 `natural()` | 用「指標是空的」認出資料夾那份是整份檔 | 資料夾那份現在也帶指標，這個分支要改寫：檔不在、檔在但沒有 `index` 鍵，都印 `[no index]`；`index` 不是物件＝`IndexBad`。所以「只改 `spot()`」不夠，`natural()` 也要動 |
| `index_view` 的說明與 `[no index]` 提示 | 例子寫 `_index.json`／`_index` | 改成 `_metainfo.json#/index`／`_metainfo/index`；加一項的 json_set 例子跟著改 |
| `ls`、`json_ls`、`json_search`、`stat` | 照實列 | **照實列，不藏 `_metainfo`**（代定 M4）。index 才是視角，ls 是客觀（使用者「如果想要真正客觀，那就乖乖用shell ls或是aos json ls」）；`_` 開頭沒有特別意思（C-48）。`ls`／`stat` 的記號清單拿掉 `_tooldef.json` |
| `aos-tools` `inspect()` | 資料夾讀 `_tooldef.json`＋`_metainfo.json`；json 物件讀 `_tooldef`、`_metainfo` 兩鍵 | 只讀 `_metainfo`，取裡面的 `tooldef`；沒有那格＝`ToolDefMissing`、壞的＝`ToolDefBad`（代號沿用，M8）。輸出的 `metainfo` 欄拿掉 `tooldef`（M9） |
| `lib/tool_io.py` `load_tooldef()` | 讀自己夾的 `_tooldef.json` | 讀 `_metainfo.json` 的 `tooldef` |
| `lib/tool_spec.py` `write_defs()`、`tools_def` | 寫兩個檔／兩個鍵，整份覆蓋 | 寫一個檔／一個鍵；**先讀出來、只換自己那幾格再寫回**（裡面可能已經有別人寫的 `index`），M7。`add_metainfo`／`add_tooldef` 兩個動作照留，都寫進 `_metainfo`；階段照舊三段 |
| `lib/metainfo.py` `read()`、`timeout_ms()`、`eval_cost()` | 讀 `_metainfo.json`／`_metainfo` | 不用改（多出來的 key 它不看） |
| `lib/aos/defs/catalog.py` | 有 `interfaces.json` 或 `_metainfo.json`＝一個定義，且要有 `summary` | 別被只有 `index` 的 `_metainfo.json` 騙到（M11） |
| json 工具（`json_get`／`json_set`…） | — | 不用改；改 `index`、`description` 就是寫 `…/_metainfo.json#/index/x` 這種路徑 |
| C++（impls） | 只認 `_entry` | 不用改、不用重建 |

## 邊緣狀況

- **「這是一個定義」的記號失效**：`defs/catalog.py` 看到 `_metainfo.json` 就當定義、停止往下、還抱怨沒有 `summary`。defs 根底下的普通資料夾一旦放了 index，就會被誤判。第一步就要補測試擋住。
- **同一個檔多人寫**：以前 index、tooldef、特性各自一個檔，現在同一個。json 工具照 11-12 已定「同時寫不上鎖」；agent 在改 `index` 的同時 `tools_def` 重產 `tooldef`，後寫的會蓋掉先寫的那次修改。機率低，照舊不上鎖；程式端至少做到「讀出來改一格再寫回」，不整份覆蓋。
- **檔變大**：`description` 加 `index` 加 `tooldef` 都在，`json_get DIR/_metainfo.json` 可能超過預設上限（8000 bytes）只回型別與大小；agent 改讀 `#/index`、`#/description`，或用 `index_view`（本來就分頁）。act、aos-mcp 每次叫工具讀 `timeout_ms` 要多解析一些字，可以忽略。
- **index 表要不要列 `_metainfo.json` 自己**：不列（跟現在 `_index.json` 自己除外一樣，M5）；工具不檢查。
- **`_metainfo.json` 自己的 metainfo**：沒有。對 `DIR/_metainfo.json` 叫 `index_view` 會去找 `DIR/_metainfo.json#/_metainfo/index`，自然是 `[no index]`，不特別處理。
- **人加的自訂特性撞名**：C-14 讓人任意加 key，以後 `index`、`tooldef`、`description` 是通用 key，自訂的別用這三個名字。現有 74 份沒有撞到的。
- **工具夾沒有 `_metainfo.json`**：以前「沒有 `_tooldef.json` 登記不了」，之後是「沒有 `_metainfo.json` 或裡面沒有 `tooldef` 登記不了」。N-68 的「不強迫寫 metainfo」指的是特性那些 key，照舊不強迫。
- **模型看不看得到特性**（10-24 M10、使用者 10-15「小模型注意力有限」）：照舊看不到。同一個檔，但 aos-tools 只把 `tooldef` 那格交給腦。
- **一個資料夾又是工具又有很多子項**（子資料夾＝子動作，P-41 11-06 註）：父夾的 `_metainfo.json` 可以同時有 `tooldef`（自己）與 `index`（底下的子動作），不衝突。
- **`AOS_ENTRY` 換了入口名**：只影響 `_entry`；`_metainfo` 名字固定（10-24 M2：不開環境變數）。
