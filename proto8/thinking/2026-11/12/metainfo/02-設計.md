# 02 設計：`_metainfo` 是一條約定（不做專門程式）——裡外都認、外面蓋裡面、不搬家；形狀、合併粒度、留外面的判準、裝不下的節點、各工具若要支援怎麼做、邊緣狀況

**11-12 下午使用者兩次裁定後整份改寫**（原話在 [README](README.md#使用者原文)）：原本的「搬進去、只認裡面」作廢。代定編號見 [04](04-題與代定.md)。

## 一句話

`_metainfo` 只活在概念與規範裡，是一條**約定**：節點的 `tooldef`、`index`、`description` **可以**寫在它裡面，也可以照舊獨立放在外面（`_tooldef.json`、`_index.json`…）。我們推薦的讀法是兩處都看：**先讀裡面、再讀外面、合併，外面那份蓋過裡面**。

- 不做專門處理它的程式，也不做共用的讀取模組（使用者「我們目前是不做單一程式去處理的」）。
- 哪支工具要不要支援，是那支工具自己的事（「啊其他工具要不要支援，就看他們自己」）；要支援的就在自己的程式裡加幾行。
- 不強制（「這是不強制的啦，後續其他程式自己想怎麼做都可以，反正我們就是推薦這樣」）。
- 現有的檔一個都不搬、不刪。

## 位置（都不變）

| 節點 | `_metainfo`（裡面） | 獨立的（外面） |
|---|---|---|
| 資料夾 `DIR/` | 檔 `DIR/_metainfo.json` 的 `tooldef`／`index`／`description` 鍵 | 檔 `DIR/_tooldef.json`、`DIR/_index.json`、`DIR/_description.json` |
| json 物件（含整份 json 檔的頂層） | 物件的 `_metainfo` 鍵底下的 `tooldef`／`index`／`description` | 同一個物件的 `_tooldef`、`_index`、`_description` 鍵 |

## 形狀：一個物件、平鋪（M1、M2）

原有特性（`summary`、`cost`、`timeout_ms`、九軸、`sandbox`…，N-68、N-69）原地不動；三個格跟它們並排，名字是外面那個名字去掉 `_`（使用者「_index進去後就是index，去掉_」）：

| `_metainfo` 裡的格 | 外面獨立的名字 | 值 |
|---|---|---|
| `tooldef` | `_tooldef.json`／`_tooldef` | `{"description", "parameters", "positional"?, "errors"?, "env"?}`（P-41） |
| `index` | `_index.json`／`_index` | `{名: {"description": …}}` |
| `description` | `_description.json`／`_description` | 字串 |
| 特性各 key | 沒有外面的對應，只有這一處 | 照 N-68、N-69 |

全部選填；沒有 `_metainfo`＝什麼都沒說；不認得的 key 忽略（C-48）。

例，工具夾只有 `_entry` 與 `_metainfo.json`、沒有 `_tooldef.json`：

```json
{
  "summary": "Multiply two numbers",
  "timeout_ms": 2000,
  "tooldef": {"description": "Multiply a by b.", "parameters": {"type": "object", "properties": {"a": {"type": "number"}, "b": {"type": "number"}}}}
}
```

## 推薦讀法：先裡面、再外面、合併、外面贏

| 項目 | 合併粒度 | 例 |
|---|---|---|
| `tooldef` | **頂層鍵淺合併**：`{**裡面, **外面}`。同名的頂層鍵（`description`、`parameters`、`positional`、`errors`、`env`）整鍵以外面為準；只有一邊有的鍵留著（M14） | 裡面有 `description`＋`errors`，外面有 `description`＋`parameters` → 外面的 `description`、外面的 `parameters`、裡面的 `errors` |
| `index` | **逐項整項覆蓋**：同名的項整項以外面為準，不合併項裡的欄位；只有一邊有的項留著（M15，跟 `index_view` 既有 K1 同一條） | 裡面有 `a`、`b`，外面有 `b`、`c` → `a`（裡）、`b`（外）、`c`（外） |
| `description` | 字串，沒得合併：外面有就用外面的（M16） | — |

為什麼 tooldef 只合一層、不往下合：

- `parameters` 是一份 JSON Schema，往下合會出現「`properties` 一半來自裡面、`required` 來自外面」這種兩邊作者都沒寫過的 schema，腦照它給參數就會錯。整鍵換掉，結果一定是某一邊完整寫過的。
- 陣列（`errors`、`positional`、`required`）往下合沒有唯一合理的做法（接起來還是取代）。
- 跟 index 的 K1「同名的鍵整項覆蓋，不做欄位層級合併」同一個說法，整套只有一條合併規則：**一層、同名整個換**。沒有共用模組，每支工具自己寫，規則越短越不會各寫各的。

錯怎麼算（M18，給要支援的工具參考）：兩處都沒有＝照那支工具原本「沒有」的處理（aos-tools 是 `ToolDefMissing`、`index_view` 是 `[no index]`）；任一處有但形狀不對＝照原本「壞掉」的代號（`ToolDefBad`、`IndexBad`），句子指明是哪一處；合併之後再做原本的檢查。

寫的一方不變（M17）：`tool_spec`、`tools_def` 照舊寫獨立的 `_tooldef.json`／`_tooldef` 鍵；agent 改 index 用 json 工具，寫哪一處自己決定。

## 留在外面、不進 `_metainfo` 的

`_entry`（與 `_entry.json`）、`.env`：aos-exec 跑的時候要用（使用者「_entry確實不能搬進去」）。C++ 基礎層（aos-exec、aos-inst、loop、fsm、daemon）照舊不開 `_metainfo`（M10）。可執行檔工具只有 `--tooldef`（M19）。

## 裝不下的節點（M3）

陣列、別人的 json、可執行檔：只有 `index` 照既有規則延伸（使用者 11-12「2,3的確如此」）——寫在最近一個裝得下的上層節點的 index 裡（裡面或外面那份都行），鍵寫相對路徑（`list/0`、`other.json#/key`）。其他項目不延伸，沒寫＝沒說。

## 我們自己的工具若要支援，各自怎麼改

每支在自己的程式裡加幾行，不共用新模組（M23）。要不要做、做哪幾支由使用者挑，清單與大小在 [03](03-施工切法.md)。

| 誰 | 現在 | 支援之後 |
|---|---|---|
| `cmd/aos-tools/bin/aos-tools` `inspect()` | 資料夾讀 `_tooldef.json`（沒有＝`ToolDefMissing`）；json 物件／整份 json 檔讀 `_tooldef` 鍵 | 先取 `_metainfo` 的 `tooldef`、再取獨立的 `_tooldef`，淺合併；兩處都沒有才 `ToolDefMissing`。它本來就讀 `_metainfo`（帶出特性），不多開檔 |
| `lib/tool_io.py` `load_tooldef()` | 每支工具啟動時讀自己夾的 `_tooldef.json` | 先讀 `_metainfo.json` 的 `tooldef`、再讀 `_tooldef.json`，淺合併 |
| `lib/agent/tools_def/_entry` | 「有 tooldef」＝有 `_tooldef.json`／`_tooldef` 鍵 | 「有 tooldef」＝兩處任一處有（M20）；寫照舊寫外面 |
| `lib/aos_index.py`（`index_view`） | 天然那份＝`DIR/_index.json` 或 `F#/PTR/_index` | 天然那份＝`_metainfo` 裡的 `index` 為底、疊上獨立的 `_index`；再疊參數指定那份（三層，後面蓋前面） |
| `lib/aos/defs/catalog.py` | 有 `interfaces.json` 或 `_metainfo.json`＝一個定義，且要有 `summary` | 別被只放了 `index` 的 `_metainfo.json` 騙到（M11） |

不用動的：`lib/metainfo.py`（既有的、讀特性用的小函式，照舊；不把它擴成中央讀取層）、act、aos-mcp、`metainfo_check`、`tool_spec`、janet 輔助、`ls`／`stat`／`json_ls`（照實列，不藏 `_metainfo`，M4）、C++。

## 邊緣狀況

- **各工具支援程度不一**：這是約定不是強制，所以會有「aos-tools 認裡面的 tooldef、但工具自己啟動時（`tool_io`）不認」這種半套。後果見 [03 選做清單](03-施工切法.md)的相依欄；條文要寫明「支援與否看各工具」。
- **「這是一個定義」的記號**：`defs/catalog.py` 看到 `_metainfo.json` 就當定義、停止往下、抱怨沒有 `summary`。約定一定下來，agent 就可能在普通資料夾放只有 `index` 的 `_metainfo.json`；在 defs 根底下會被誤判。
- **兩處寫得不一樣、人只改了裡面**：外面贏，所以改裡面看起來「沒生效」。支援的工具在兩處都有時要讓人看得出來（`index_view` 的標頭、`tools_def check` 多一行 note，M21、M22）。
- **外面那份是空物件 `{}`**：淺合併下它什麼都不蓋，等於只用裡面的；不特別處理。
- **外面只寫了一半**（只有 `description`、沒有 `parameters`）：`parameters` 用裡面的。這是使用者要的「合併」，但也表示外面那份不再保證自己完整——要看合併後的（`aos-tools get`）。
- **模型看不看得到特性**（N-69「模型看不到」）：照舊看不到，aos-tools 只把合併後的 tooldef 交給腦。
- **自訂特性撞名**：C-14 讓人任意加 key，以後 `index`、`tooldef`、`description` 在 `_metainfo` 裡有約定的意思；現有 74 份實查沒有撞到的。
- **`_metainfo.json` 自己的 index**：沒有（M5）。
