# linux user 初步調查之三：五個念頭各自的讀法、看得到的走法、後果與邊緣狀況（不替使用者選）

← [linux-user](../linux-user.md)｜上一份 [02-對到aos現況](02-對到aos現況.md)

## a.「linux user 不管背後是人還是 agent，都是一個可以互動的對象」

讀法只有一種：互動的單位是 linux 帳號，帳號背後是誰不必問。

這句現在對「人」已經成立（人的信箱在家目錄、`from` 預設 `$USER`），對「agent」還不成立——agent 現在不是 linux 帳號，是某個帳號底下的一個資料夾。

互動＝寄信的話，要定的是這幾件：

- **地址是什麼**。走法一：家目錄下的固定路徑（現在）；寄件人要知道對方的家在哪，而且家目錄 700 時別的帳號寄不進來。走法二：公共位置按帳號名（像傳統 unix 信的 `/var/spool/mail/<名字>`，或沙箱那條線的 `/srv/…`）；地址就是名字，但那個位置要 root 先開好。走法三：帳號名經一張表查到路徑（像 `/etc/passwd` 查家目錄）；多一張表要顧。
- **跨帳號的權限怎麼開**。現成的只有 `setup.sh --mailbox` 那一套（擁有者＋群組＋2770＋預設 ACL），是給問腦信箱寫的；每多一對「誰能寄給誰」就多一個群組或一條 ACL。另一種形是傳統 unix 信的「任何人都能投、只有本人能讀」（資料夾開成只能放、不能看），aos-post 的 `tmp/`→`new/` 搬法在這種權限下能不能用沒驗。
- **寄件人需不需要知道對方是人還是 agent**。照他的話是不需要。實際差在速度與規矩：人幾小時才回、agent 幾秒；mailbox 協議的「卡住超過 10 分鐘先回 BLOCKED」對人不適用；[wf-to-aos 02](../wf-to-aos/02-寄信給人與主session.md) 的兩個洞（讀了就從清單消失、人不會被通知）都是人這邊才有的。
- **人不在線時信放哪**。信是檔，躺在信箱裡就好，這點天生沒問題；缺的只有通知（傳統 unix 信是登入時提醒一句）。
- **一個帳號底下有很多 agent 時，「寄給這個 user」是寄給誰**。現況是寄到 `~/.aos/stack/mailbox`，那是人的信箱，底下的 agent 不會看到。這題跟念頭 e 是同一題。

## b.「root daemon 本身掛在一個使用者底下」

兩種讀法：

- 讀成「以這個使用者的身分跑」：現在就是，沒有別的可能（每個行程一定帶著某個 uid）。
- 讀成「在行程樹上掛在代表這個使用者的那個行程底下」：家機現在是碰巧成立——用 `setsid nohup` 起的樹會被 `systemd --user` 收養，但它不照顧；要它照顧得登記成服務。

後果：root daemon 能做的事，上限就是這個使用者能做的事。它不能換身分、不能動別的使用者的東西；它底下的一切也都是這個使用者。使用者登出時它活不活，看 linger 開了沒（家機開著）；公司 WSL 有沒有 `systemd --user`、開沒開 linger 這次沒查。

## c.「一個 linux user，從 linux 看過去就是一個 proc；它跟 root daemon 是平級的」

**跟 linux 事實的出入**：linux 眼中 user 不是一個 proc，是貼在很多 proc 身上的一個號碼（[01](01-linux這邊的事實.md)）。linux 不會把「這個使用者」當成一個可以起、可以停、可以寄東西過去的單位。

這句話有四種讀法，後果不同（讀法四是 Argon 提的，隊長認為它最貼原話的語氣，一起列）：

| 讀法 | 意思 | 「平級」成不成立 |
|---|---|---|
| 四：user＝人自己開的那些行程（殼、Claude Code 主 session） | 這些行程沒有被任何 aos daemon 起、也不在任何 daemon 表上，是直接踩在 linux 上的；root daemon 也是直接踩在 linux 上（頭上沒有 daemon） | 在「誰的硬體是 linux」這一層上平級：兩者都沒有 aos 的上一層。行程樹上仍是殼起了 root daemon。主 session 報 `DaemonMissing` 就是這個位置的症狀——aos 裡沒有 daemon 罩的東西用不了信箱工具與 self 類工具 |
| 一：user＝`systemd --user` 那隻行程 | 一個 uid 一隻、是這個 user 所有行程的最上層、沒登入也能在——最像他說的「那個 proc」 | 行程樹上不平級：root daemon 是它的子孫。角色上是**同型**：兩個都是「一棵監管樹的根」，一個管這個 user 的 linux 行程、一個管 aos 的東西 |
| 二：user＝一個身分（號碼），不是行程 | 照 linux 原樣 | 不能比：root daemon 是「以這個身分跑的一個行程」，身分與行程不同類。要比的話是「root daemon 屬於這個 user」 |
| 三：user＝aos 眼中的一個對象（不管 linux 怎麼看） | 從 aos 這邊看，人（一個 user）跟一隻 agent 一樣是能收信的對象 | 成立，但平級的是「人」與「agent」，不是 user 與 root daemon |

照讀法四，念頭 e 就是接著來的下一步：人的行程在樹外、沒有 daemon 罩，要在 aos 裡當一個完整的對象，就會想到「找一台 daemon 代表我」。

他話裡「掛在底下」（b）與「平級」（c）同時出現。照讀法一，兩句可以同時對：**行程樹上是底下，角色上是同型**。照「一個 agent 一個帳號」的遠期說法則是另一種同時對：每個 user 各有自己的東西，user 與 user 之間平級，root daemon 只是其中一個 user 的東西。

還有一個看得到的走法是把 b 與 c 併起來：**讓 root daemon 直接當 `systemd --user` 的一個服務**，那它就是「代表這個 user 的那個行程」的第一層孩子，由它起、由它重起、開機自動在、可以在這一層設整棵樹的總量上限（cgroup）。這正是 no-pid 定的「使用者保證根 daemon 正常跑（自己交 systemd／s6）」的其中一種交法，不需要 root。

## d.「假如是 root user 的 root daemon 呢？」

以 root 身分跑的 daemon 能做三件別人做不到的事：把底下每個 proc 換成不同帳號（`limits.user`，機制已寫好）、設任何一格的總量上限、管任何人的行程。有了第一件，「一個 agent 一個帳號」就成立：agent 之間寫不到彼此的檔、殺不了彼此、冒用不了身分，全由 linux 擋，不靠自律。

代價與風險：

- **daemon 出一個錯就是整台機器**。daemon 照表上寫的起東西、收信就掛 proc（名詞表說它「來者不拒」）；它是 root 時，任何寫得進它信箱或表的人就等於拿到 root。現在這些檔是同 uid 誰都能寫。
- **跟現有規矩相撞**：現在的做法是 agent 不加繞過權限的旗標、root 的事由使用者親手做（`setup.sh` 預設乾跑、`--apply` 才動、sudoers 只准換成 `aos-run` 一個帳號）。整台 root daemon 是把 root 長期交出去。
- **帳號要先有**：換帳號不會自動建帳號。每隻 agent 一個帳號＝每加一隻就要建一個（要 root）、家目錄或工作區放哪、刪 agent 時帳號收不收。
- **機器限制**：公司 WSL 給不給 root、能不能建帳號，這次沒查。
- **檔案全變難**：現在整套靠「大家同一個 uid 所以都讀寫得到」在跑（共用的 lib、工作區、daemon 的表、彼此的信箱）。分帳號之後每一樣都要決定擁有者與群組；`setup.sh --mailbox` 光一個信箱就要七個資料夾＋ACL。

看得到的走法（由輕到重）：

1. 不放 root：帳號由使用者親手建好，daemon 仍是普通使用者，只能起同帳號的東西（現況）。
2. root 只放在一支小程式：daemon 是普通使用者，要換帳號時叫那支（sudoers 只准換成名單上的帳號）。這是他 11-05 說的「搭配一隻有root權限的小程式」，也是沙箱線現成的形（`sudo -n s6-setuidgid aos-run …`）。
3. 一台很小的 root daemon 只管「換帳號起下一層」，下面每個帳號各有自己的普通 daemon。這時每個帳號的那台 daemon 就很像念頭 e 的「代表這個 user」。
4. 整棵樹的根就是 root。

走法 3 從層次看（Argon 提、隊長同意這是一種看得到的形）：每個普通帳號各有一台自己的 root daemon，root 帳號的那台就是它們的上一層——管所有 linux user 的那一台。監管樹往上多接一層：linux → root 帳號的 daemon → 各帳號的 daemon → 各自的 agent。這時要回答的是「一個帳號」對應一隻 agent、還是一整棵樹（他 11-05 兩句話各說了一種：「一個agent一個賬號」與「這個linux user有一個root daemon」）。

另一種完全不用 root 的隔離是沙箱那層（bwrap：讓行程只看得到指定的資料夾）——擋得住讀寫，但 linux 眼中仍是同一個 uid，不是「另一個對象」。

## e.「一個 linux user 搞不好會說某個 root daemon 那個 proc，就代表他？」

「代表」至少有三種意思，可以只要其中一兩種：

| 代表的意思 | 成立之後 | 現在 |
|---|---|---|
| 收信：寄給這個 user 的信到這台 daemon（或它指定的信箱） | user 的地址＝它的 root daemon；底下哪隻 agent 來辦由它分 | 寄給 user 是寄到 `~/.aos/stack/mailbox`，跟任何 daemon 無關 |
| 額度：這個 user 的資源由它往下分 | 接上 kernel 的「資源分配」；整棵樹的總量上限設在它那一格 | 沒有總量上限；一個 user 幾棵樹互不知道 |
| 身分：它說的話、做的事算這個 user 的 | 它寄的信 `from` 就是 user 名 | 同 uid 下本來就分不出來 |

邊緣狀況：

- **一個 user 現在可以有很多棵樹**（家機：試驗場一棵＋測試臨時起的好幾棵，以後還有正式的）。要「代表」就得有辦法指定是哪一棵。走法：固定位置說了算（像 `~/.aos/` 底下放一個指向它的東西；`systemd --user` 是靠「一個 uid 只起一隻」）；或用鎖保證一個 user 只有一台自稱代表；或不指定行程、讓 `~/.aos/stack` 這個資料夾本身當代表（那就是現況，行程來來去去、資料夾一直在）。
- **代表掛了的時候**：信躺在信箱沒事（資料夾還在）；額度那種意思就沒人分了。這跟 no-pid 的「根 daemon 由使用者保證」是同一件事。
- **測試怎麼辦**：測試每次起一棵臨時的樹，它不該自稱代表，也不該被算進代表的額度裡——或者該算？
- **人自己登入時跟它的關係**有三種擺法：人在它上面（人起它、停它、改它的表——現況）；人在它旁邊（都是這個 uid 的行程，人只是另一個寄信收信的）；人在它底下（人是它表上的一列、一個收信的對象，「等使用者」就是寄給那一列）。今晚 D4「把人類這個linux user作爲agent」偏第三種的說法，但第一種的事實（人能停它）不會消失——所以人大概同時是兩種身分，這在同 uid 下沒有衝突，分 uid 之後要決定人用哪個帳號。
- **主 session 算什麼**：它現在以人的 uid 做事、用人的信箱，實際上是「人的代理」。如果某台 root daemon 代表這個 user，主 session 是它底下的一隻、還是跟它平行的另一個代表，沒定（[wf-to-aos 02](../wf-to-aos/02-寄信給人與主session.md)「主 session 的身分」是同一題）。

## 人與 agent 同等對待之後

- **收信**：今晚的兩個洞（讀了就消失、不會被通知）是人這邊的；傳統 unix 信用「登入時提醒」解第二個。
- **人的「工具」**：agent 的工具是登記檔裡那幾支；人的工具是整個殼。同等對待只在「收信寄信」這一面成立，能力上人大得多。
- **權限誰大**：同 uid 下一樣大——agent 能做人能做的一切（讀人的 ssh 金鑰、改人的殼設定、停掉根 daemon），靠的是自律與沙箱。分 uid 後人（或 root）才真的比較大。
- **冒用**：同 uid 下，任何 agent 都能往人的信箱放一封 `from` 寫別人名字的信，也能替人回信（`from` 只是字串、`sender` 路徑也是自己填的）；linux 看不出來。不同 uid 下，信檔的擁有者是 linux 蓋的章、偽造不了（沙箱紀錄已記：「身分只有 Linux 的 uid」）——但要有人去看那個章，現在 aos-mailbox 不看。

## Argon 補的邊緣狀況與提案（11-12 晚；標明同不同意）

- **人會多開**：一隻 agent 一個 stack 通常只有一個在收信的，但一個人同時開好幾個終端機、好幾個 Claude Code，全都讀同一個 `~/.aos/stack/mailbox`；誰先 `read` 誰拿走，別的視窗就沒看到。隊長同意，這是「人當 agent」獨有的；今晚幾位隊長同時開著就是這個情形。
- **代表掛了、人還在**：身分綁在一隻活著的行程上，它崩了人在 aos 眼中就失聯，雖然人坐在鍵盤前、資料夾也在；這會削掉「資料夾＝程式、不怕行程死」的好處。隊長同意，所以上面把「讓資料夾當代表」列成一種走法。
- **跨帳號寄信後檔案是寄件人的**：別的帳號放進來的信檔擁有者是他，收件人要搬動、刪除時可能被擋。隊長：`setup.sh --mailbox` 用預設 ACL 處理的就是這件事，但只在問腦信箱那個形設計過，aos-mailbox 的 `read`（搬到 `cur/`、刪掉或搬進 `archive/`）跨帳號沒驗過。
- **提案一：`~/.aos/stack` 當這個 user 唯一的「本家」，要代表就在那裡常駐一台 daemon**，人開的 Claude Code 都用本家的身分；試驗場與測試的樹是旁邊的別棵。隊長：這是「指定哪一棵」的一種走法，順便解 `DaemonMissing`；代價是多一台要使用者保證活著的 daemon，以及主 session 多開時同一個身分好幾個腦。不替使用者選。
- **提案二：跨帳號寄信走一支有權限的「郵局小程式」**，由它以收件人的身分把信放進去，不去調資料夾權限。隊長：可行的一種形，跟 11-05「一隻有root權限的小程式」同一格；要注意這樣信檔的擁有者就變成收件人，「擁有者＝寄件人、偽造不了」那個章沒了，得由小程式自己把寄件人的 uid 記進信裡。
- **Argon 說「讀了就消失」不算人當 agent 的洞，是收信工具的做法**。隊長：分類同意（是 `aos-mailbox read` 預設讀完就刪的做法，不是架構）；但它說信會留在 `cur/` 不對——現在預設是刪，`--keep` 才進 `archive/`。

Argon 的全文在 scratchpad，沒進 repo；信的位置見入口。

## 跨機

uid 與帳號名只在一台機器裡有意義。家機與公司機的同名帳號對 linux 是兩個不相干的號碼；信箱在本機檔案系統、不跨機。「兩台機器上的同一個人」是不是 aos 眼中的同一個對象，linux 幫不上忙，要 aos 自己定（現在跨機靠 git 與 wf/inbox 信，認的是人不是帳號）。反過來，一台機器上的兩個帳號可以是同一個人（人自己的帳號＋他建給 agent 的帳號）。
