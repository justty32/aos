## 結論二：「統一」有哪幾種

以 `kb/me.json` 為例：

```json
{"self_tools": {"$ref": "me/self_tools.json"},
 "defs": {"cmd": ["echo", "hi"]},
 "a": {"b": {"$ref": "x.json#/k"}, "c": {"$ref": "#/defs/cmd"}}}
```

**(a) 全同像**——`$ref` 的相對路徑照 index 的算法：從裝著它的容器算，物件當資料夾、`..` 往外層、根物件＝這個檔、再 `..`＝檔所在資料夾；`#/指標` 只能接在檔案系統那邊。

| 寫法 | 現在 | (a) 之後 |
|---|---|---|
| `/self_tools` 寫 `me/self_tools.json` | `kb/me/self_tools.json` | `kb/me.json#/me/self_tools.json`（沒這個 key＝解不開）；要改寫 `../me/self_tools.json` |
| `/a/b` 寫 `x.json#/k` | `kb/x.json#/k` | 不是路徑（物件裡直接寫 `#`，index 那邊使用者裁不收）；要改寫 `../../x.json#/k` |
| `/a/c` 寫 `#/defs/cmd` | 本檔 `/defs/cmd` | 一樣；另外多一種寫法 `../defs/cmd`（檔內相對，現在做不到） |
| 整份檔就是 `{"$ref": "x.json"}` | `kb/x.json` | 一樣（容器就是資料夾） |

**(b) 只統一寫法與解析器**——一支共用的「起點＋字串→檔＋指標」，`#/`、`./`、`../`、絕對路徑、跳脫、哪些不收，兩邊同一份；`$ref` 的起點照舊固定是檔所在資料夾，index 的起點是容器。上表「現在」那欄全部不變；現有檔一個字不用改、條文不用改。使用者看到的仍是兩條規則，只是不會再各寫各的。

**(c) index 改回照 `$ref`**（檔內 `_index` 也從檔所在資料夾算）：等於推翻今晚「用同像性去想」那句，只列出。

**(d) 用記號分開**——不帶 `#` 的照舊是檔名（從檔所在資料夾）；另收 `#../x`、`#./x`＝從所在容器算的檔內相對（「`#` 後不是 `/`」現在是不收的空位）。`/a/c` 可寫 `#../../defs/cmd`；現有寫法全不變。合使用者 11-11「json 檔內根是 `#/`、檔案系統是 `/`，兩者不同」，但跟 index 的讀法不一樣（index 沒有 `#./`），要真的統一就得回頭改 index。

**(e) (a) 再放寬「看到 `#` 就把前面當檔名」**——`/a/b` 的 `x.json#/k` 照舊能用，只有不帶 `#` 的整份檔參照變。使用者今晚對 index 已裁不放寬（「1. 甲。」），且現有 9 個全是整份檔參照，省不到。

## 結論三：邊緣狀況與後果

全同像 (a)：

1. **最常見的用法變囉嗦**：「指同資料夾另一份檔」幾乎一律要多寫 `../`，個數等於寫的深度；把一個 `$ref` 在檔內挪深一層，字面就得跟著改。換來的是檔內相對參照（一段子樹內部互指，整段搬走還對）。
2. **原本合法的寫法會悄悄失效**：寫在物件裡的 `x.json#/k` 變成「寫法不合」，照 N-45 寬容規則是**原封不動留著、不報錯**——漏改的不會報錯，只會留一個沒換掉的物件。漏加 `../` 的整份檔參照則會報指不到（這種抓得到）。
3. **起點有兩種讀法**（要使用者定，見下）：照 index 那句的字面是「寫著 `$ref` 這個 key 的物件」＝指示詞物件自己；照捷徑的類比是「裝著指示詞的那個容器」。前者連「整份檔就是一個指示詞」也要多寫 `../`，每個都比後者多一個。
4. **換進來的東西裡的相對路徑**：所在位置只能是「換進來之前」的（來源檔＋來源位置），同現行、也同檔案系統裡捷徑資料夾的 `..`。跟使用者 11-11「最後產出的檔就當作這是整份」並存的讀法是：那句管的是 `$ref` 以外的一般路徑值，`$ref` 自己在組裝當下就解完了。
5. **走路途中遇到指示詞不穿過**：`../x/y` 中 `x` 本身是 `{"$ref": …}` 時，照現行「指標取原文」是指不到。跟檔案系統穿過捷徑不同，屬於使用者說的「細節上有差異」。
6. **陣列也是容器**：argv 陣列元素的 `{"$ref": "cmd.json#/0"}`，入口檔根就是陣列時也得寫 `../cmd.json#/0`。
7. **不知道是哪份檔**（stdin、信、行程內給的 JSON）：檔內相對可以在手上那份裡走，走出根就只知道資料夾；現行 `#/` 在這情況是原封不動，兩者要定成一致。
8. **`$ref` 陣列淺層合併**：每個 key 現在記來源檔，要改記來源檔＋位置。
9. **搬動工具**（daemon 小格、aos-grow、`ref --move`）：現在只改檔名那段；之後檔內相對也要換算，最省事是一律改寫成「走出檔再 `檔#/指標`」。
10. **`$ref` 陣列本身不算一層容器**（Argon 補）：`{"a": {"$ref": ["x.json", "y.json"]}}` 的兩個字串跟寫成單個字串同一個起點，不然陣列寫法要多一個 `../`。合出來的物件裡，相鄰兩個 key 可能來自不同深度，各自裡面的 `$ref` 走出檔要的 `../` 個數不同。
11. **key 叫 `..`、`.` 或空字串**（Argon 補）：相對寫法走不到（`..` 一律當往外層、`.` 與空段略過），只能用 `#/` 開頭指；index 現在也是這樣。
12. **繞圈**：算出來仍是（檔, 指標），檢查不用改；`#` 後 JSON pointer 與 `..` 不混用（`..` 只在 `#` 前面那段），同 index L7、L8。
13. **語意差異留著**：`$ref` 取值並接著解、index 只顯示不跟。能統一的只有「字串怎麼算成位置」。

只統一解析器 (b)：沒有資料與條文後果；唯一要定的是共用碼放哪（C++ 庫＋命令列給 Python 叫，或各留一份、跑同一張對照表）。兩邊「不收」的細節要對齊一次（例：index 物件裡寫 `#` 不收，`$ref` 永遠在檔案系統那邊所以收）。

記號分開 (d)：`$ref` 無資料後果；index 要不要跟著收 `#./` 是另一題，不跟就仍是兩套讀法。

## 建議

- 最貼近「跟 index 統一」這句話字面的是 **(a)**，起點取「裝著指示詞的容器」；做得到，資料成本 9＋4 處，真正的成本與風險是 7 支程式約 110 處傳位置。
- 但 (a) 的日常代價不小（邊緣 1、2），而且 index 的路徑多半往容器裡面指、`$ref` 是被換掉的那一格、幾乎都往檔外指（Argon 的觀察，我同意）——同一套算法用在 `$ref` 上，最短的寫法給了最少用的情況。**我傾向 (b)**；想要檔內相對再加 (d)。要不要為了「只記一條規則」付 (a) 的代價，是使用者的方向題。
- **分步**：① 先做 (b)——共用的算法與對照表，行為不變，這步不論之後選什麼都用得上；② 庫介面改成值與位置綁在一起（漏改編譯不過），這步行為也還不變；③ 切換算法，同一個 commit 改 9 個資料、state 窗切檔與 `table.py`、測試；④ 三個搬動工具與 aos-json 那份；⑤ 條文與例子。①② 做完再看要不要走 ③。
- 沒動手，等使用者看完。

## 未定（要使用者定）

1. **選哪一種**：(a) 全同像／(b) 只共用寫法與解析器／(d) 記號分開／不動。
2. **選 (a) 的話起點是誰**：指示詞物件自己（字面同 index 那句）／裝著它的容器（建議；整份檔的指示詞不變、每個少寫一個 `../`）。
3. **選 (a) 的話，物件裡直接寫 `x.json#/k`**：照寬容規則悄悄不換／對這種改成報錯／放寬成 (e)。這是 N-45「寫法寬容」跟「漏改要抓得到」的衝突。
4. **界線**：只統一 `$ref`，還是所有寫在 JSON 裡的相對路徑值（`$override`、hooks 的 `handler`、`cli.json` 的 `tools`、`env_file`、stdio server 的 `command`…現在都從那份設定檔的資料夾算）也要跟。建議只 `$ref`（N-45：一般路徑值照讀它的程式的規則算）。
5. **C-51「互通只當工具與思考方式，不進規範」**：(a) 之後同像就寫進 N-45 本文，這句要不要改（今晚 index 那次裁不加註）。

## Argon

照 [aos-teams/05](../../../../wf/workflows/dispatch/aos-teams/05-同機session與Argon.md) 用 `agy`（Gemini 4 Argon High、plan 模式）送了原話＋上面的初步整理，當場有回。

Argon 的看法與我同不同意：

- **index 跟 `$ref` 的容器差一層**：`_index` 是物件 `p` 的屬性、描述 `p`，起點是 `p`；`{"$ref": …}` 是要換掉 `p` 的值，起點是 `p` 的上一層。實作時把「當前那一格的位置」直接當起點會全面多算一層。——同意，就是未定 2；也是介面要把值與位置綁在一起的理由。
- **深度 0 與深度 1 語意斷裂**：整份檔的指示詞寫 `tools.json` 是磁碟檔，挪進一層就變成本檔的 key。——同意（邊緣 1、3）。
- **Python 那幾處低估了**：呼叫的人手上多半只有「取出來的一段」和檔名，沒記它在原檔的位置，要改的是整條傳遞鏈、不是幾行呼叫。——同意方向，量沒逐處核對。
- **長期維護稅**：同檔內把一段設定包深一層，就得重數裡面每個 `$ref` 的 `../`。——同意（邊緣 1）。
- **「最後產出當整份」與邊走邊換**：7 支程式是一層一層換、不是先整份換完；工具把換到一半的子樹抽出來放到別層，綁深度的 `../` 就斷。——同意是 (a) 放大的風險（邊緣 9）；庫自己記來源位置的部分不受影響。
- **提案**：首推 (b)（它叫 g）或 (d)（它叫 f：不帶 `#`＝檔案系統、`#/`＝本檔根、`#../`＝所在容器，`#` 後不准走出檔根）；次推把 (d) 同時用在 index 與 `$ref`；使用者仍要 (a) 的話先定死四條（起點＝上一層容器、`$ref` 陣列不計深度、不穿過未換的 `$ref` 且繞圈看正規化後的位置、只改 `$ref` 與 index 其餘路徑欄不跟），再庫與搬動工具先行、最後資料測試文件一次切。——(b) 與分步我同意；「把 (d) 套回 index」等於改使用者今晚的裁示，只能由他提。
