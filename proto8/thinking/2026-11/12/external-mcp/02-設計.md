# 02 設計：一台外部 MCP server 一份 server 檔；寫進 cli.json 就是 CLI 自己接，疊進 tools.json 就是經 aos 接

← [external-mcp](README.md)｜上一份：[01 盤點](01-盤點.md)｜下一份：[03 施工切法](03-施工切法.md)

## 結論

1. **一台外部 server＝一份 server 檔**（例 `mcp/time.json`），寫這台怎麼起、要哪幾支工具、金鑰檔在哪。這就是 11-11 M2 裁的「寫在包檔裡」那份包檔，只是允許它先只有「怎麼起」那一段、還沒匯入工具。
2. **走哪條路看你把它寫在哪**（M8「每台伺服器自己選」的落地；使用者 11-12 裁，[題一](README.md#題一)）：
   - 寫進 `cli.json` 的 `mcp_servers`＝**原生掛**：cli_session 把它交給 claude／codex，由 CLI 自己連、自己列工具、自己叫。只有 eca 能用。
   - 疊進 `tools.json` 的 `$override`＝**經 aos**：先用 `aos-mcp-import` 把工具凍結進這份檔，每支外部工具變成一支 aos 工具。fsm 與 eca 都能用（eca 是經 aos-mcp 拿到）。這條就是 11-11 的 [03 設計稿](../../11/new-tools/03-mcp-client.md)，內容不變。
3. **eca 以原生掛為主**（使用者 11-12「eca本身就能接mcp」、11-11 晚「eca通常都有自己的基礎工具…更順手」）。**fsm 只有經 aos 這條**，照 03 做，排在回家那幾步。
4. 原生掛的外部工具在 aos 眼中**不算 aos 工具**，跟 claude 自帶的 Read、Bash 同一類；經 aos 的才算。

## server 檔

```json
{"description": "MCP server time: current time and timezone conversion (stdio, no key).",
 "mcp_server": {"name": "time",
                "transport": "stdio",
                "command": "uvx",
                "args": ["mcp-server-time"],
                "env": {"TZ": "Asia/Taipei"},
                "env_file": "/home/me/.config/aos/time.env",
                "only": ["get_current_time"]}}
```

| 鍵 | 意思 | 沒寫 |
|---|---|---|
| `description` | 這份檔一句話（JSON 檔的檔頭） | 該寫 |
| `mcp_server.name` | server 名。只收 `[a-z][a-z0-9_]*`、最多 32 字；`aos` 不能用（cli_session 自己那台叫這個） | 不行 |
| `transport` | 這一輪只收 `"stdio"`；`"http"` 排在後面的步驟 | 不行 |
| `command`、`args` | 怎麼起。`command` 不含 `/`＝從 `PATH` 找；含 `/` 的相對路徑從這份檔的資料夾算。兩個都可以寫指示詞（`$env`／`$path`），每次起才解 | `command` 不行；`args` 當 `[]` |
| `env` | 明文的環境變數，不放金鑰（同登記檔的 `env`） | 沒有 |
| `env_file` | 金鑰檔的位置，只記位置；每次起 server 才讀（M3） | 沒有 |
| `only`／`except` | 只要這幾支／不要這幾支（外部原名）；兩個都寫＝server 檔壞（M6「預設全收、可以挑」） | 全收 |

`aos-mcp-import` 匯入後，同一份檔多出 03 設計稿那幾段（`mcp_tools`、`tools`、`mcp_server.imported_at` 等），這時它同時是一個可以 `$override` 的包。只打算原生掛的人不用匯入。

server 檔放哪不規定（定義資料夾裡的 `mcp/`、或幾隻 agent 共用的地方都行），宣告的地方寫路徑指過去。

## eca 身：原生掛

### 定義裡怎麼寫

`cli.json` 多一個選填鍵 `mcp_servers`，值是 server 檔路徑的陣列（相對路徑從 `cli.json` 的資料夾算，也可以寫指示詞，規則同現有的 `tools` 鍵）：

```json
{"kind": "claude",
 "flags": ["--tools", "Read,Write,Edit,Glob,Grep,Bash", "--permission-mode", "dontAsk",
           "--allowedTools", "Write,Edit,Bash", "--strict-mcp-config"],
 "mcp_servers": ["mcp/time.json"],
 "print_flags": ["--max-budget-usd", "0.5"],
 "timeout_ms": 600000}
```

`--strict-mcp-config` 照留：這隻看得到的 server＝`aos` 加上這裡列的，使用者自己帳號底下設的 server 不會混進來。

### cli_session 怎麼交給 CLI

每次起 CLI 前（現有的 `mcp_argv` 那一步），對每份列出來的 server 檔：

| | claude | codex |
|---|---|---|
| 設定 | 小格那份 `mcp.json` 的 `mcpServers` 多一格：`"time": {"command": "aos-mcp-launch", "args": ["<server 檔絕對路徑>"]}`，跟 `aos` 那格並排 | `-c mcp_servers.time.command="aos-mcp-launch"`、`-c mcp_servers.time.args=["<絕對路徑>"]`、`-c mcp_servers.time.env={AOS_HOME=…}` |
| 放行 | `--allowedTools` 加 `mcp__time`；有 `only`＝改成逐支 `mcp__time__get_current_time`；有 `except`＝`mcp__time` 加 `--disallowedTools mcp__time__那支` | `-c mcp_servers.time.default_tools_approval_mode="approve"`；`only`／`except` 要用 codex 的逐支欄位，[01](01-盤點.md#codex-cli-01672) 標「沒查到」，施工時驗 |
| 腦看到的名字 | `mcp__time__get_current_time` | codex 自己的命名（server `time` 的 `get_current_time`） |

沒有 aos 登記檔、只有 `mcp_servers` 的定義也照接（`mcp.json` 裡就只有外部那幾台）。互動畫面（attach）走同一段，一樣接上。`lib/agent/claude`、`lib/agent/codex` 那兩支給腦叫的工具共用 cli_session，`cli.json` 寫了 `mcp_servers` 也會生效。

### `aos-mcp-launch`（新的小指令）

`aos-mcp-launch FILE`：讀 FILE 的 `mcp_server`、解指示詞、讀 `env_file`、把環境備好，然後 **exec** 那個 `command`（自己不留在行程裡，stdio 直接就是 server 的）。

- CLI 的設定與命令列裡只出現「`aos-mcp-launch` 加 server 檔路徑」：金鑰不進 `mcp.json`、不進 `-c`、不進 `ps` 看得到的命令列。
- claude 與 codex 用同一個寫法；codex 不帶環境的問題也在這裡補（它只要 `PATH`、`HOME` 與 `AOS_HOME`）。
- 之後 fsm 那條的 `mcp_tool` 起 server 用同一段程式（共用模組 `lib/mcp_server_file.py`：讀檔、驗形狀、組 argv 與環境）。
- 環境的先後：收到的環境 ＜ `env_file` ＜ `env`。`env_file` 寫了但檔不在＝報錯不起（同 aos-tools 的「報錯不跑」）。
- 錯：stderr 一行 `aos-mcp-launch: error: 代號 原因`、退 1。代號：`ArgumentsBad`、`FlagUnknown`、`PackMissing`、`PackBad`、`PathMissing`（`env_file` 不在）、`DotenvBad`、`LaunchFailed`（`command` 起不來）。

### 這條路有什麼、沒有什麼

| | 原生掛（`cli.json`） | 經 aos（`tools.json` 疊包） |
|---|---|---|
| 誰能用 | eca | fsm、eca |
| server 行程 | CLI 管：一次 CLI 執行期間常駐（非互動＝一輪；互動畫面＝畫面開著的期間） | 每叫一次起一台、叫完收掉（M4） |
| 有狀態的 server（瀏覽器之類） | 一輪之內可以；跨輪不行（下一輪是新的 CLI 行程、server 重起）；互動畫面可以 | 不行 |
| 進 `aos-tools ls`、`self_tools` 能加減 | 否 | 是 |
| `before_tool`／`after_tool` hook | 攔不到 | 攔得到 |
| 工具說明 | CLI 每次開場現問 server，**凍結不了**（使用者 11-12 裁接受，是 M7 在這條路上的例外，[題二](README.md#題二)） | 匯入時凍結，`sync` 才換（M7） |
| 要先匯入 | 不用 | 要 |
| 程式量 | 小（[03 步 1](03-施工切法.md)） | 03 設計稿的階段 1，2～3 天 |

同一台 server 兩邊都寫＝腦會看到兩組名字不同的同一批工具；不擋，文件寫明。

## fsm 身：經 aos（照 11-11 的 03，內容不重抄）

人跑一次 `aos-mcp-import` 連上 server、把工具清單凍結進 server 檔；每支外部工具的 `_entry` 是共用的 `mcp_tool`，每次呼叫起一台 server、叫完收掉；定義的 `tools.json` 疊上它：

```json
{"$override": [{"$env": "AOS_HOME", "$path": "/lib/packs/look.json"},
               "mcp/time.json"],
 "tools": {}}
```

腦看到的是 `time_get_current_time` 這樣一支普通的 aos 工具。aos-tools、brain、act、aos-mcp 都不用改。

這份圖紙對 03 只改四處，其餘照舊：

| 03 原本 | 改成 | 為什麼 |
|---|---|---|
| eca 原生掛排在階段 3 | 排最前面 | 使用者 11-12「eca本身就能接mcp」；公司只有 eca |
| 包檔一定是匯入產生的；檔已在＝`PackExists` | server 檔可以先手寫（只有 `mcp_server`）；匯入是「把工具凍結進這份檔」，檔裡已經有 `mcp_tools` 才 `PackExists` | 原生掛用不到凍結的工具表 |
| `--only`／`--except` 只是匯入時的旗標 | 記在 `mcp_server.only`／`except`，匯入與原生掛讀同一處；旗標照留、寫進檔裡 | 兩條路挑的是同一批 |
| `mcp_tool` 自己組怎麼起 server | 跟 `aos-mcp-launch` 共用 `lib/mcp_server_file.py` | 起法只寫一份 |

**fsm 不做原生掛的對應**（不在 fsm 的迴圈裡放常駐的 MCP 連線）：M4 已裁「先做每次呼叫起一台」，常駐留給他說的「專門的常駐aos proc」，另開設計。

## 外部工具算不算「工具」

| | 原生掛 | 經 aos |
|---|---|---|
| 算 aos 工具嗎 | 不算，是 CLI 自己的東西 | 算 |
| `aos-tools ls` | 沒有 | 有，一支一列 |
| tooldef 從哪來 | aos 不持有；CLI 現問 server | 匯入時寫進 server 檔，每支一個物件、獨立的 `_tooldef` 鍵（N-69 現行兩處都認、獨立那份為準；`_metainfo` 只放 `summary`、`side_effect`、`resource`、`timeout_ms`） |
| 名字 | `mcp__<server>__<工具>`，server 名不准叫 `aos`，所以不會撞 aos 那組 | `<server>_<工具>`（03 的轉名規則）；撞名＝匯入時 `NameBad` |

## 金鑰與環境變數

- 金鑰只放使用者自己的 env 檔，server 檔只記位置（M3「env 檔，只記位置」）。值只在 `aos-mcp-launch`／`mcp_tool` 起 server 的那一刻讀進 server 的環境。
- 不會出現金鑰的地方：定義資料夾、server 檔、`cli.json`、小格的 `mcp.json`、codex 的 `-c`、命令列、stack、history、`live.jsonl`、aos-mcp 的呼叫紀錄、任何錯誤行（錯誤行只講變數名與檔的位置，不講值）。
- 不把金鑰放進 CLI 自己的環境：claude 會把環境傳給它的 Bash 與每一台 server，腦一句 `echo` 就印進對話了。
- server 的回應裡如果帶出金鑰（它自己印的），aos 管不到，屬於那台 server 的行為。
- HTTP server 的金鑰（要放進標頭）這一輪不設計：stdio 以外的都排在後面，到時另出題。

## 權限與安全邊界

外部 server 是別人的程式，接上它＝讓那個指令用這隻 agent 的 Linux 身分在這台機器上跑。

- **誰決定接**：寫定義的人。`cli.json` 列了、或 `tools.json` 疊了，就是他點頭（03「人匯入那一步就是核准」的同一個意思）。範本預設一台都不掛（03 的 D9）。
- **claude**：照舊 `--permission-mode dontAsk` 加白名單。列出來的 server 才進 `--allowedTools`；沒列的 server 連不上（`--strict-mcp-config`）。不加任何全權限繞過的旗標。
- **codex**：只對列出來的那幾台設 `default_tools_approval_mode="approve"`，codex 自帶工具的核准與 `sandbox_mode` 不動。把免核准從 aos 那台擴到列出來的外部 server，使用者 11-12 裁「都按照推薦。」（[題三](README.md#題三)）。
- **沙箱**：CLI 的沙盒（codex 的 `sandbox_mode`）管的是腦下的指令，管不管得到 MCP server 沒查到，當作管不到。要關住外部 server，用 aos 既有的兩樣：Linux 帳號與檔案權限、把整隻 agent 包進 aos-sandbox（server 是 CLI 的子行程，一起在裡面）。這一輪不為外部 server 另做沙箱。
- **使用者自己承擔的**：選哪台 server、它拿到的金鑰能做什麼、它回來的文字（不可信，可能夾指令給腦看）、原生掛時它隨時可以改工具說明。比照 11-12「風險自己承擔」。
- **外部文字**：經 aos 那條照 03 加前綴 `[MCP server 名] `、限長、凍結。原生掛那條 aos 碰不到。

## 跟今天定的東西怎麼接

| 今天定的 | 這裡怎麼接 |
|---|---|
| `_metainfo` 裡的 tooldef（N-69） | 匯入寫的是獨立的 `_tooldef` 鍵，現行讀法照認；之後 `_tooldef` 整合進 `_metainfo` 時，改匯入程式寫的位置就好 |
| 一處壞了不擋別處（「_metainfo.json 壞掉時，index_view 對那個資料夾不該直接報錯。」；aos-tools 同日改成一條登記壞了只略過那支，[tool-path-broken](../tool-path-broken.md)） | `mcp_servers` 裡某一份 server 檔讀不了、形狀不對、名字重複或叫 `aos`＝印一行 `cli_session: warning:`、跳過那一台，其他台與 aos 那台照接，這一輪照問。`cli.json` 自己的 `mcp_servers` 不是陣列＝`CfgBad`（那是 `cli.json` 壞，照現行） |
| eca 以 CLI 為主、aos 盡量跟上 | 原生掛只做「把宣告翻成 CLI 認得的設定」；工具怎麼列、怎麼叫、行程怎麼管全交給 CLI，aos 不包一層 |
| kernel 框架的 hook（判決前、判決後、回信經過時） | 管的是站跟站之間的信。外部 server 是 CLI 或 `mcp_tool` 的子行程，不掛在 daemon 的表上、不經過 kernel，這三個時機碰不到它。之後做 M4 後半的常駐 proc 時，掛它的那封信才會經過框架站 |
| eca 不給 aos 的基礎檔案工具（11-12） | 同一個方向：CLI 自己能做的就讓它做 |

## 用到的既有機制、新增的東西

沿用：`cli.json`（多一個鍵）、登記檔的 `$override`、指示詞 `$env`／`$path`、`env_file` 只記位置、小格的 `mcp.json`、`--allowedTools` 白名單、codex 的 `-c`、`before_tool` hook（經 aos 那條）。

新增：server 檔的 `mcp_server` 段、`cli.json` 的 `mcp_servers` 鍵、指令 `aos-mcp-launch`、模組 `lib/mcp_server_file.py`；fsm 那條另有 03 列的 `aos-mcp-import`、`mcp_tool`、`mcp_client.py`。沒有新的環境變數，沒有靠檔名自動找的規則。
