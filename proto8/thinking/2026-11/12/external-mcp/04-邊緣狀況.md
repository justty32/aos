## 宣告與設定

1. **`mcp_servers` 列的檔不在、不是 JSON、沒有 `mcp_server`、形狀不對**：印 `cli_session: warning:` 一行（講哪一格、哪份檔），跳過那台，其他照接、這一輪照問。
2. **兩份 server 檔同名**：第一份算數，後面那份 warning 跳過。
3. **名字叫 `aos`**：warning 跳過（那是 cli_session 自己那台）。
4. **`cli.json` 的 `mcp_servers` 不是陣列、元素不是字串或指示詞**：`CfgBad`，照現行 `cli.json` 壞掉的處理。
5. **（作廢，11-12 下午）** ~~**`transport` 寫 `http`（步 4 之前）**：warning 跳過，句子說 only stdio is supported。~~
   作廢原因：[05](05-http-bearer試接.md) 實測 codex 不改程式就接得上 http＋bearer＋自簽憑證，server 檔改成收 `transport: "http"`（[02](02-設計.md#server-檔)），而且 http 排到最前面做（[03 步 1](03-施工切法.md)）。施工中途還沒做到的組合（步 1 做完時的 claude 身、stdio 的檔）一樣是 warning 跳過，寫在 03。
6. **`cli.json` 的 `flags` 自己又寫了 `--mcp-config`**：兩邊都交給 claude，合不合併看 claude（沒驗；cli_session 自己只寫一份，設計不靠它）；不特別擋，寫什麼就傳什麼。
7. **`flags` 拿掉了 `--strict-mcp-config`**：使用者帳號底下設的 server 也會進來，這是寫定義的人自己選的，aos 不補回去。
8. **codex 沒有 strict 的對應**：`~/.codex/config.toml` 裡的 server 本來就會被 codex 連上（現況就是這樣，這台那份檔裡沒有）。要隔開的人在 `flags` 加 `--ignore-user-config`（連帶不讀那份檔的其他設定）；範本不預設加。
9. **同一台 server 同時寫在 `cli.json` 與 `tools.json`**：腦看到兩組（`mcp__time__…` 與 `mcp__aos__time_…`），不擋，文件寫明。
10. **`aos-mcp-launch` 不在 `PATH`**：有 **stdio** 的外部 server 要接時 `CliMissing`（同現在 aos-mcp 不在 `PATH` 的處理）；只有 http server 的定義用不到它，不檢查。

## 行程與狀態

11. **server 起不來／連不上**（stdio：指令不存在、金鑰檔不在、第一次 `uvx` 下載太久；http：server 沒開、token 錯）：CLI 自己處理，那台的工具這一輪沒有、這一輪不因此失敗。claude 身由 cli_session 把「哪台沒起來」印成 warning（[03 步 3](03-施工切法.md)）；codex 身 aos 這邊沒有東西可攔，只有小格 `stderr.txt` 有 codex 的 ERROR 行（[05](05-http-bearer試接.md) 實測，token 錯是 `AuthRequired`，沒印出值）。
12. **非互動模式每一輪是新的 CLI 行程**：server 每輪重起；跨輪要記住狀態的 server（登入、開著的分頁）在非互動下記不住。互動畫面開著時記得住。要跨輪就等延後的常駐 proc。http server 在別處常駐，記不記得住看它自己。
13. **兩隻 eca 掛同一份 server 檔**：各自的 CLI 各起一台，互不相干；server 自己的檔案鎖由它負責。
14. **CLI 被收掉**（逾時、`PR_SET_PDEATHSIG`）：server 是 CLI 的子行程，由 CLI 收；CLI 被 `kill -9` 時 server 會不會留下來，看 CLI 與 server 自己（stdin 關了通常就退），aos 不追。
15. **server 的工作目錄**：就是 CLI 的 cwd（工作區）；`aos-mcp-launch` 不換資料夾。

## aos 這邊的機制碰到原生工具

16. **`before_tool`／`after_tool`**：攔不到（沒經過 aos-mcp）。要攔的改走經 aos 那條。
17. **goal 的「這輪有沒有進展」**：看的是 CLI 對話檔裡有沒有叫 `goal` 以外的工具，原生 MCP 工具算在內，不用改。
18. **`tool_added` hook、`self_tools`**：只看 aos 的登記檔，原生掛的 server 不在裡面；腦自己加減原生 server 這一輪不做（要動 `cli.json` 的 stack 副本，等有人要再說）。M5「不限制，有權限就能用。」由經 aos 那條滿足（給腦用的匯入，跟 fsm 那條一起延後）。
19. **`aos-agent tools`、`ls`**：看不到原生 server 的工具。`cli.json` 是定義的一部分，看定義就知道掛了哪幾台。
20. **換台、開新對話、`reseed`**：跟 MCP 無關，照舊；新的 CLI 行程照樣重接。

## 金鑰

21. **`env_file` 裡的值被 server 的工具回出來**：會進對話、`live.jsonl`、history；那是 server 的行為，aos 不濾。
22. **claude 把自己的環境傳給每台 server**：所以外部 server 看得到這隻 eca 行程環境裡的東西（`AOS_*` 那些路徑、使用者 shell 帶進來的變數）。aos 不洗環境（aos 工具拿到的也是這份）；不要把金鑰放在 agent 的環境裡，一律走 `env_file`。http 的 bearer 是例外：只能放在 CLI 行程的環境（見 23）。
23. **http 的 bearer 一定在 CLI 行程的環境裡**：codex 的 `bearer_token_env_var` 只認 codex 自己的環境。cli_session 起 codex 那一刻才讀 `env_file`、只放進那支行程（不往上到 aos-loop、hook），並自動補 `shell_environment_policy.exclude`，腦的 shell 拿不到（[05](05-http-bearer試接.md) 實測 exclude 有效）。codex 自己起的其他子行程（例如別台 stdio MCP server）拿不拿得到沒驗；11-11 實測 codex 不替 MCP server 帶父行程的環境，推測拿不到。
24. **`aos-agent ctl add --envs` 帶 token**：值明文寫進 stack 的 `procs/<名>/exec.json`（644）、也在那一下的命令列上（05 實測）。這一輪只在文件寫警告（[03 步 2](03-施工切法.md)）；秘密走 `env_file`。
25. **兩台 http server 的 `ca_file` 不一樣**：一支 CLI 行程只有一個 `SSL_CERT_FILE`。第一台的算數，後面 `ca_file` 不同的那台 warning 跳過；要同時接就把憑證合進同一份 bundle、兩份 server 檔指同一個檔。
26. **`flags` 裡自己也寫了 `shell_environment_policy.exclude`**：cli_session 還是會補自己那一條，兩條誰算數沒驗（[03 步 1](03-施工切法.md) 開工先驗）；驗完前文件寫明不要兩邊都寫。

## 升成題的三項（使用者 11-12「都按照推薦。」，都已裁）

- 宣告寫在哪 → 裁：`cli.json` 加 `mcp_servers` 鍵（[題一](README.md#題一)）
- 原生掛凍結不了工具說明 → 裁：接受，是 M7「默認用凍結的」在 CLI 自己接那條路上的例外，要凍結的走經 aos（[題二](README.md#題二)）
- 列了的 server 要不要整台免核准 → 裁：列了＝整台放行，11-11「只對 aos 那組工具關掉核准」擴到列出來的外部 server（[題三](README.md#題三)）
