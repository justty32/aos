# 03 施工切法：五步，每步各自能獨立合併——先 codex 身＋http server，再 `--envs` 的文件警告、claude 身、stdio＋`aos-mcp-launch`、範本與說明；fsm 那條延後

> 11-12 下午照 [05 試接](05-http-bearer試接.md#對圖紙的調整建議)重排。原本的「步 0 不改程式的實驗」codex＋http 那半 05 已經做掉；剩下沒驗的併進各步的「開工先驗」。原本的六步（0～5）作廢，以這張表為準。

## 結論

| 步 | 做什麼 | 多大 | 做完看得到什麼 |
|---|---|---|---|
| **1** | **codex 身＋http server**：`cli.json` 的 `mcp_servers` 鍵、`lib/mcp_server_file.py`、cli_session 翻成 codex 的 `-c`、備 codex 行程的環境、測試 | 半天～1 天 | 定義裡寫一行 `"mcp_servers": ["mcp/teamsite.json"]`，luna 叫到 http server 的工具；token 只在 codex 行程的環境 |
| **2** | **`--envs` 明文落地**：只做文件警告，不改程式 | 很小 | `aos-agent ctl add` 的說明寫明 `--envs` 不放秘密 |
| **3** | **claude 身**：同一份 server 檔翻成 `mcp.json` 與 `--allowedTools` | 半天 | haiku 叫到同一台 server 的工具 |
| **4** | **stdio server＋`aos-mcp-launch`**（兩身） | 半天～1 天 | 定義裡列一份 stdio 的 server 檔就接上；金鑰檔的值進得了 server、哪裡都不留 |
| **5** | **範本與說明**：文件、定義檢查、知識檔 | 半天 | 照文件抄得出一隻掛外部 server 的 eca |
| 延後 | fsm 那條（匯入成包、client、經 aos 的 http、常駐 proc） | 照 11-11 的 03 | — |

每一步做完都能單獨合併：還沒做到的組合（步 1 做完時的 claude 身、stdio 的 server 檔）＝印 `cli_session: warning:` 一行跳過那台，句子講哪種還沒支援；不報錯、不擋這一輪。

五步都只碰 eca，公司驗得完。使用者 11-12 上午說外部 MCP「等假日在家再來稿」；11-12 下午開工：「外部 MCP 開工吧，做不完就push上去，我回家繼續做」，進度看 [06 施工結果](06-施工結果.md)。

## 步 1：codex 身＋http server

| 動哪 | 做什麼 |
|---|---|
| 新 `proto8/lib/mcp_server_file.py` | 一個小模組：讀一份 server 檔、解指示詞、驗 `mcp_server` 形狀（[02 的表](02-設計.md#server-檔)，stdio 與 http 兩種都驗）；錯用 `tool_io.Error`（`PackMissing`、`PackBad`、`PathMissing`、`DotenvBad`） |
| 改 `proto8/lib/agent/cli_session.py`：`load_cfg` | `cli.json` 認 `mcp_servers` 鍵；不是陣列、元素不是字串或指示詞＝`CfgBad` |
| 同上：列出可用的外部 server | 逐份讀；某台 server 檔壞（檔不在、形狀不對、重名、叫 `aos`、`env_file`／`ca_file` 不在、`env_file` 裡沒有那個變數）＝warning 跳過那台，其他照接（X8） |
| 同上：`mcp_argv`（codex） | 每台翻成 `-c mcp_servers.<名>.url="…"`、`-c mcp_servers.<名>.bearer_token_env_var="<變數名>"`、`-c mcp_servers.<名>.default_tools_approval_mode="approve"`；有 `only`＝`-c mcp_servers.<名>.enabled_tools=[…]`；有 `except`＝`disabled_tools`（開工先驗，見下） |
| 同上：`run_cli` 加 `env=` | 起 codex 的那一刻讀 `env_file`，把 `bearer_token_env` 那個變數**只放進 codex 行程的環境**；`ca_file` 設成那份環境的 `SSL_CERT_FILE` 與 `CODEX_CA_CERTIFICATE` 兩個變數 |
| 同上：自動補 exclude | 有任何一台帶 `bearer_token_env`＝加一條 `-c shell_environment_policy.exclude=[所有這些變數名]` |
| 同上：畫面那條路 | 互動畫面（open／attach）起 codex 也帶同一組 `-c` 與同一份環境 |
| 新測試 | 假 http MCP server（標準庫，沿 [05](05-http-bearer試接.md#怎麼驗的) 那支的做法）；測組出來的 `-c`、環境、壞檔跳過、名字 `aos`、重名、`only`、token 值不出現在 argv 與任何寫出的檔 |

**開工先驗**（每項一句結果，寫進施工結果）：

| 要驗的 | 怎麼驗 | 驗不過怎麼辦 |
|---|---|---|
| `disabled_tools` 有沒有效 | 假 server 兩支工具，設 `disabled_tools=["echo"]`，看腦還看不看得到 `echo` | 寫了 `except` 的那台在 codex 底下不掛、印 warning（不默默整台放行） |
| `flags` 裡自己也寫了 `shell_environment_policy.exclude` 時誰算數 | `flags` 寫一條、cli_session 再補一條，腦的 shell `env` 看兩個變數 | 文件寫明不要兩邊都寫 |

**驗收**：單元測試；假 server＋自簽 CA（要「CA＋CA 簽的 leaf」，不能拿自簽憑證直接當 server 憑證，[05](05-http-bearer試接.md#怎麼驗的) 的坑）掛給 luna 一輪，定義用範本的 JSON `_entry`（不用 sh）；照 05 的掃法 grep 整棵樹、`~/.codex` 新動到的檔、所有行程的命令列都沒有假 token；`/proc/<pid>/environ` 只有 codex（與它的子行程）有，aos-loop、aos-eca-turn、cli_session 沒有；腦的 shell `env | grep` 找不到。

要重建什麼：不用。`cli.json` 多的是選填鍵，舊定義照跑。

## 步 2：`--envs` 明文落地，只做文件警告

[05](05-http-bearer試接.md#問題列給頂層沒改) 的 P1：`aos-agent ctl add --envs K=V` 的值明文寫進 `ws/.stack/procs/<名>/exec.json`（644），那一下也在 `ps` 命令列上。這一步**不改程式**，只在 `ctl add` 的說明文件與 `--help` 對應的文件段寫明：`--envs` 不放秘密；秘密走 server 檔的 `env_file`。（讓 `exec` 單子能指一份 env 檔是另一件事，這裡不做。）

## 步 3：claude 身

| 動哪 | 做什麼 |
|---|---|
| 改 cli_session 的 `mcp_argv`（claude） | 小格那份 `mcp.json` 的 `mcpServers` 多外部那幾格，跟 `aos` 那台並排，仍然只給一份 `--mcp-config`；`--strict-mcp-config` 照留（那是定義 `flags` 裡的，不動）；`--allowedTools` 加 `mcp__<名>`；`only`＝逐支 `mcp__<名>__<工具>`；`except`＝`mcp__<名>` 加 `--disallowedTools` |
| 同上 | 沒有 aos 登記檔、只有 `mcp_servers` 的定義也照接 |
| 同上 | claude 開場事件列出每台 server 的狀態（欄位開工時確認）：宣告了卻沒連上的印 `cli_session: warning: MCP server 名 did not start`。codex 沒有東西可攔（05 的 P3），不做 |
| 測試 | 組出來的 `mcp.json` 與旗標；token 值不出現在 `mcp.json`、argv |

**開工先驗**（claude 的 http 這半 05 沒碰）：

| 要驗的 | 驗不過怎麼辦 |
|---|---|
| `--mcp-config` 的 http 形狀（`{"type": "http", "url", "headers"}`）這版 claude 認不認 | 照實際認的形狀寫 |
| bearer 怎麼給才不落地：`headers` 會不會展開 `${VAR}` | 不展開＝帶 `bearer_token_env` 的 http server 在 claude 底下不掛、印 warning |
| token 在 claude 行程的環境時，腦的 Bash 看不看得到、有沒有擋的辦法 | 擋不住＝同上，不掛、印 warning（不把 token 交給腦的 Bash） |
| `ca_file` 對 claude 要設哪個變數 | 照查到的設；查不到＝文件寫明 claude 身不支援 `ca_file`，那台 warning 跳過 |
| server 沒開、token 錯時 claude 怎麼辦 | 記進文件 |

**驗收**：haiku 一輪叫到假 http server 的工具，`permission_denials` 是空的；不帶 bearer 的 http server 一定要通，帶 bearer 的照上表驗的結果。

## 步 4：stdio server＋`aos-mcp-launch`（兩身）

| 動哪 | 做什麼 |
|---|---|
| 新 `proto8/cmd/aos-mcp-launch/bin/aos-mcp-launch`、`README.md`、`tests/` | `aos-mcp-launch FILE`：用 `lib/mcp_server_file.py` 讀檔、讀 `env_file`、備環境、exec；`--help`、不給參數＝`ArgumentsBad`；http 的檔＝`PackBad` |
| 改 cli_session 的 `mcp_argv` | stdio 的 server 檔：claude＝`mcp.json` 多一格 `{"command": "aos-mcp-launch", "args": ["<絕對路徑>"]}`；codex＝`-c mcp_servers.<名>.command／args／env`（帶 `AOS_HOME`）。放行與挑工具同 http |
| 同上 | 有 stdio server 要接而 `aos-mcp-launch` 不在 `PATH`＝`CliMissing` |
| 測試 | 假 stdio server（標準庫，兩支工具）；`env_file` 的假值進得了 server、不出現在 argv、`mcp.json`、CLI 行程的環境 |

**驗證對象（不用下載、不用金鑰、本機就有）**：再起一台 aos-mcp，換個名字當成「外部 server」。它本來就是一支標準的 stdio MCP server，登記檔只放一支 `peek_now_time`（`lib/packs/gadgets.json` 裡那支，回 UTC 時間）。server 檔的 `command` 寫 `aos-mcp`、`args` 帶 `--ws`、`--stack` 與那份登記檔。haiku 與 luna 各一輪，看 `live.jsonl` 有一筆 `mcp__demo__peek_now_time`。

**開工先驗**：codex 的沙盒管不管 stdio MCP server——讓 demo 那支工具寫一個工作區外的檔，看寫不寫得進去（只記結果進文件，設計不靠它）。

**真的別人寫的 server**：通了之後可以換成 `uvx mcp-server-time`（MCP 官方的參考 server，PyPI 套件 `mcp-server-time`，stdio、不用金鑰）。這台已有 `uvx`，第一次執行會從 PyPI 下載套件到 `~/.cache/uv`；要不要在公司機下載由使用者點頭。
