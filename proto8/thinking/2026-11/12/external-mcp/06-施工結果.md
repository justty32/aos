## 代定（隊長定的，可翻案）

- **E1** claude 身 bearer 走 `headersHelper`（03 原本寫「驗不過就不掛」——驗過了，`headers` 的 `${VAR}` 會讓 Bash 看得到，所以改用 helper，值不進 claude 環境）。helper 指令裡只有 python、本檔路徑、env 檔路徑、變數名。
- **E2** bearer 寫了但沒寫 `env_file`：codex＝用 codex 行程本來繼承的那個變數；claude＝`headers` 寫 `Bearer ${變數}`（Bash 看得到，文件沒特別警告——要不要改成 warning 跳過，看使用者）。
- **E3** env 檔格式：`KEY=VALUE`、可有 `export `、`#` 註解、成對引號拿掉；認不得＝`DotenvBad`（句子只講第幾行）。沒用 aos-tools 的 `--env-file` 解析器（沒去找共用，KISS）。
- **E4** 每題 `load_cfg` 都重讀 server 檔＝壞的那台每題都 warning 一次。
- **E5** codex 的 `disabled_tools`（`except`）照翻，**沒實測**；`flags` 自己也寫 `shell_environment_policy.exclude` 時，cli_session 補的那條排在後面（誰贏沒驗）。
- **E6** codex 畫面那條路，codex 自己起的子行程（實測看到一支 Windows 剪貼簿 helper）會繼承 token——它是 codex 的子行程，跟非互動一樣，不另擋。
- **E7** `url` 只收 `http://`／`https://` 開頭；名字 `[a-z][a-z0-9_]*`、最多 32 字、`aos` 保留（照 02）。

## 搬一隻現有 Codex agent 進 aos 的照抄步驟（佔位符）

前提：那隻 agent 原本的 `start.sh` 是「讀 `~/.config/<agent>/<site>.env` 的 token、合成 CA bundle、`exec codex -c mcp_servers.<site>.url=… -c …bearer_token_env_var=<VAR>`」。

1. **token 檔**照原本的放法：`~/.config/<agent>/<site>.env`（`chmod 600`），一行 `<VAR>=<token>`。不放進定義、不放進工作區、不用 `ctl add --envs`。
2. **CA bundle**照 start.sh 合成一份：`cat /etc/ssl/certs/ca-certificates.crt <主機的憑證>.pem > ~/.config/<agent>/ca-bundle.pem`。
3. **定義**：`cp -r $AOS_HOME/templates/eca-claude <defs>/<agent>`。
   - `cli.json` 換成：

     ```json
     {"kind": "codex",
      "flags": ["-c", "sandbox_mode=\"workspace-write\"", "-c", "approval_policy=\"never\""],
      "mcp_servers": ["mcp/<site>.json"],
      "print_flags": [],
      "timeout_ms": 600000}
     ```

   - `llm.json`：`{"model": "<模型>"}`。
   - `_entry` **照範本不動**（`["aos-loop", "loop.json"]`；不用 05 那支 sh）。
   - 原本 agent 的指示（AGENTS.md 之類）留在它的工作區，codex 照讀；要給 aos 的 system 文字才寫 `system.txt`。
4. **server 檔** `<defs>/<agent>/mcp/<site>.json`：

   ```json
   {"description": "<site>: <一句話>",
    "mcp_server": {"name": "<site>", "transport": "http", "url": "https://<主機>:<埠>/mcp",
                   "bearer_token_env": "<VAR>",
                   "env_file": "/home/<你>/.config/<agent>/<site>.env",
                   "ca_file": "/home/<你>/.config/<agent>/ca-bundle.pem"}}
   ```

   只想開幾支工具：加 `"only": ["<工具>", …]`。
5. **起**（工作區直接用它原本的資料夾）：樹照平常起好後
   `aos-agent -d <daemon stack> ctl add --name <agent> --ws <它原本的資料夾> <defs>/<agent>`。
6. **確認接上**：`aos-agent say -t <agent> "list the tools of the <site> MCP server, then call one harmless one"`、`aos-agent listen -t <agent>`。
   - 看不到工具：`<stack>/tools/*/stderr.txt`（或 `ws/.stack/procs/<agent>/stderr.txt`）找 `cli_session: warning: external MCP server … skipped`（server 檔壞、env 檔沒那個變數）或 codex 的 `AuthRequired`／`http/request failed`（token 錯、CA 不對、主機不通）。
   - 確認 token 沒落地：`T=$(sed -n 's/^<VAR>=//p' ~/.config/<agent>/<site>.env)`（不要 echo），`grep -rlaF -- "$T" <defs> <ws>/.stack <daemon stack>` 應該沒東西。
7. 原本的 `start.sh` 不用了（要留著對照就留，別兩邊同時開同一個 token 的 thread）。
