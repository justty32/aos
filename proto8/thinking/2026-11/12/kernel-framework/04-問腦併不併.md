## 怎麼收（代定 K-F47，可翻案）

**用 Python 把問腦總機重寫成「骨架＋問腦專屬那一包」，刪掉 C++ 的 `impls/aos-llm-kernel`。**

| 做法 | 後果 |
|---|---|
| **Python 重寫（採用）** | 骨架真的只有一份；問腦自動有 hook 三時機。對外完全不變（`kernel.json`、stack 裡每個檔、信與回信、錯誤代號），所以現有 7 支測試是從外面打的黑箱測試，改指新程式就是驗收。代價：約 35 小時；每輪從 C++ 變成起一次 Python，信很多時一輪變慢 |
| C++ 留著，當框架底下的專屬程式（只在裡面加 hook 點） | 少寫很多；但收信、排隊、回信還是 C++、Python 各一份，骨架其實沒併，「在這個框架下擴充」只做到表面 |
| C++ 留著，前面串一站框架站（`next` 指到它） | 0 小時就有 hook；但信一轉寄寄件人就變成那一站，每個寄件人的額度失效、`aos-llm ask` 的「寄件人走了就收掉」失效、`aos-llm ls` 讀不到包的表 |

選第一種的理由：使用者要的是「骨架一份、在框架下擴充」，後兩種骨架都還是兩份；而黑箱測試現成，重寫的風險量得出來。

## 長什麼樣

```
lib/aos/kernel/          骨架 round()、收信／回信 letters.py、自己跑 runner.py、hook（lib/hook_run.py）
lib/aos/kernel_llm/      問腦專屬那一包
  _entry                 把問腦的五個口交給 round()；用法 aos-exec <這夾> <kernel.json>
  packs.py               能力包：查代號、惰性解指示詞、釘死的參數、窗 endpoints.json
  order.py               priority、aging、排序、後端黏著、窗 queue.json
  slots.py               總格、保留格、包格、後端格與同時幾種包
  budget.py              額度（總額、每包、每寄件人）、用量帳 used.json
  ledger.py              逐封帳 ledger.jsonl
  tests/                 從 impls/aos-llm-kernel/tests 搬來
impls/aos-llm-kernel/    刪掉（公開標頭 aos/llm_kernel.hpp＝信箱與信的格式，aos-llm 還要用，搬進 impls/aos-llm）
impls/aos-llm/           寄信那端（send／recv／ask／regret／ls）不動
lib/aos/llm_forward/     轉交函數不動（它是端點函數，不管總機用什麼寫）
```

怎麼掛：照舊是那台 llm daemon 的身體，只換 `daemon.json` 的 `exec`：

```json
{"exec": {"argv": ["aos-exec", {"$env": "AOS_HOME", "$path": "/lib/aos/kernel_llm"}, {"$env": "AOS_CD", "$path": "kernel.json"}]},
 "interval_ms": 300}
```

設定檔 `kernel.json` **現有的寫法全部照認**（`slots`、`reserved`、`aging_cycles`、`budget`、`exec`、`endpoint`、`endpoints`、`timeout_ms`、`backends`），只多三個選填的鍵，都是框架本來就有的：

```json
{"slots": 2, "reserved": {"high": 1}, "timeout_ms": 120000,
 "exec": {"$env": "AOS_HOME", "$path": "/lib/base/llm_http"}, "endpoint": "fake",
 "backends": {"lmstudio": {"slots": 1, "max_packs": 1}},
 "endpoints": {"smart-high": {"exec": "endpoints/litellm", "url": "http://localhost:4000/v1", "model": "claude-haiku", "slots": 4},
               "fake": {"exec": {"$env": "AOS_HOME", "$path": "/lib/base/llm_fake"}}},
 "budget": {"max_calls": 3000, "window": "day"},

 "hooks": {"audit":  {"event": "after_verdict", "handler": "hooks/audit", "async": true},
           "redact": {"event": "before_reply",  "handler": "hooks/redact"}},
 "next": "/srv/gate/requests",
 "count_daemon": "/srv/llm_daemon"}
```

| 新鍵 | 在問腦這包的意思 | 沒寫 |
|---|---|---|
| `hooks` | 三個時機都有；`before_reply` 不用開 `reply_via_me`（問腦本來就是自己回信） | 沒有 hook |
| `next` | 掛問腦 proc 的那封掛信寄去哪 | `$AOS_DAEMON` 的 ctl 信箱 |
| `count_daemon` | 去哪台 daemon 的表上看問腦 proc 跑完沒 | 沒寫 `next` 時＝`$AOS_DAEMON`；寫了 `next` 就要寫 |

`reply_via_me`、`keep_ordered`、`allowed`、`max_running`、`queue` 是掛 proc 那一包的鍵，問腦這包不認（C-48：不認得的不管）。

**掛信不再看 `AOS_KERNEL`**（K-F50）：現在的總機「有設 `AOS_KERNEL` 就把掛信寄那裡」，改成跟框架站一樣只看 `next`。總機自己就是 kernel，不是一般 proc；而且小修線實跑撞過——總機繼承到給一般 proc 用的 `AOS_KERNEL`，問腦 proc 的名字被那台的白名單擋掉。要讓掛信過另一站的，改成在 `kernel.json` 寫 `next`。

## 一輪的順序（問腦這包）

```
讀 kernel.json（頂層指示詞先解；壞＝CfgBad 退 1）；鎖 requests/.flock；讀 used.json、queue.json；寫窗 endpoints.json
1. 收成品 collect：cur/ 裡掛出去的每封，看 count_daemon 表上那列與信資料夾裡的 reply.json
     跑完了 → 解讀成回信（成功、合格錯誤物件原樣、EndpointFailed、ReplyBad）
               → 記 ledger、加 used（照端點函數原本的回話記）
               → before_reply hook（可改回信的 body；退 10＝改回 HookRejected）
               → 寄回信、寄件人已走就撤回、寄 procs_removed、整封刪
     被收掉或死在半路 → 重掛一次；第二次還是沒結果 → EndpointFailed
2. 收拾 sweep：new/ 裡有 sender.flock 而沒人鎖著的＝寄件人走了，刪信（不算判決、不跑 hook）
3. 看信 check：new/ 逐封
     第一次看到的：before_verdict hook（可改 body；退 10＝拒 HookRejected）
     驗信：LetterBad、RequestBad、EndpointMissing、EndpointUnknown、那包的 DirectiveBad／CfgBad → refuse
     記 seen_at（queue.json）
4. 排序 order：級數（含 aging）→ 期限 → 同後端黏著 → 包的速度 → 等得久 → 先寄
5. 逐封 admit：期限已過 → refuse DeadlineBad；額度到頂 → refuse BudgetMissing（或照 spent 設定整台停）；
               總格／保留格／包格／後端格／同時幾種包有空 → pass；沒空 → queue（留在 new/，跳過看下一封）
   after_verdict hook：第一次判完一次；排著的信離開隊（pass 或 refuse）再一次；繼續排的不跑
6. 去處 dispatch：pass 的 → 認領進 cur/、寫 request.json（能力包拿掉 kernel 看的五鍵＋原請求＋priority 與推得的期限）
               → runner 寄掛信 procs_added {llm_<信名>: {exec, max: 1, stack: 信資料夾, timeout_ms}} → 寫 proc.json
   refuse 的 → 回 {"error": {code, msg}}、整封刪
7. 寫 queue.json
退 0
```

- before_verdict 改過 body 而信還在排的，新 body 存 `bodies/<信名>.json`（同通用 kernel）。
- 拒信的形狀照問腦現有的 `{"error": {"code", "msg"}}`（不是掛 proc 那包的 `{"applied": false, "error": …}`）：回信的形狀是包的事，`aos-llm` 那端不用改。hook 攔下時填的也是這個形狀、代號 `HookRejected`。
- hook 的事件 JSON 跟通用 kernel 同一套欄位；`body` 就是問腦信的 body（`endpoint`、`request`、`priority`），`before_reply` 的 `body` 是要寄回去的那份（已拿掉 `child`）。

## 現有功能逐項對到哪

| `aos-llm-kernel` 現有的 | 收到哪 | 有沒有變 |
|---|---|---|
| 收件箱 `$AOS_STACK/requests/`、三格、一封一個資料夾 | 骨架：收信 | 不變 |
| `.flock` 擋第二個 kernel（`LockFailed`） | 骨架：鎖（掛 proc 那包也跟著有了） | 不變 |
| sweep：`sender.flock` 沒人鎖就刪信；沒有 `sender.flock` 的照跑 | 問腦包 `check` | 不變 |
| `queue.json`：`seen_at_ms`／`seen_at_cycles`、`backends` | 問腦包 `order.py` | 格式不變 |
| aging（`aging_cycles`，有 `AOS_CLOCK` 數格、沒有換牆鐘） | 問腦包 `order.py` | 不變 |
| 排序：級數＋aging → deadline → 同後端黏著 → speed → 等得久 → 先寄 | 問腦包 `order` 口 | 不變 |
| `slots`、`reserved.high`（只管補位不搶占）、包的 `slots` | 問腦包 `slots.py`（`admit` 口） | 不變 |
| `backends`：後端格數、`max_packs`、黏著、`switched`、`counter_switches` | 問腦包 `slots.py`＋`order.py` | 不變 |
| `budget`：總額、每包、每寄件人、窗、`spent`；`used.json` | 問腦包 `budget.py` | 格式不變 |
| `priority`（字串、數字、`{level, deadline}`）、`DeadlineBad` | 問腦包 `order.py`／`admit` | 不變（key 照舊 `level`） |
| `endpoints` 能力包：kernel 看的五鍵、其餘原樣給函數、`fixed` 不給信蓋、指示詞用到才解 | 問腦包 `packs.py` | 不變 |
| 窗 `endpoints.json` | 問腦包 `packs.py` | 格式不變 |
| 掛問腦 proc（`procs_added`、`max: 1`、`stack`＝信資料夾、argv 寫成相對 `AOS_DAEMON`）、跑完 `procs_removed` | 骨架新零件 `runner.py` | 掛信去處改看 `next`，不看 `AOS_KERNEL` |
| `timeout_ms`（daemon 逾時整群收） | `runner.py` | 不變 |
| 收成品、重掛一次、第二次沒結果＝`EndpointFailed`、睡著與停著的格怎麼算 | `runner.py` | 不變 |
| `LaunchFailed`（掛信寄不進、或 daemon 的 `mailbox_warning` 說不收） | `runner.py` | 先照搬（K-F55） |
| 端點函數契約：stdin `{endpoint, request, priority}`；stdout `{message, usage?, model?, child?}`；退非 0 的合格錯誤物件原樣回；`ReplyBad` | 問腦包 `collect` 口（`runner.py` 只交出結束碼、stdout、stderr 第一行） | 不變 |
| 回信：寄給 `reply_to`、`in_reply_to`、`reply_letter.txt` 防寄兩次、寄完整封刪、寄不出去照刪、寄件人已走就撤回 | 骨架：回信（撤回那段在問腦包） | 不變 |
| `ledger.jsonl`（`seen_at`、`mounted_at`、`finished_at`、`elapsed_ms`、`usage`、`code`、`child`、`switched`） | 問腦包 `ledger.py` | 格式不變 |
| `--enable-counters`、`counter_kernel_runs.txt` | 問腦包 `_entry` | 不變 |
| 自己的錯誤代號（`CfgBad`、`QueueBad`、`UsedBad`、`CounterBad`、`ClockBad`…）與回信代號（`LetterBad`、`RequestBad`、`Endpoint*`、`BudgetMissing`、`DeadlineBad`、`LaunchFailed`、`ReplyBad`…） | 各自所在的模組 | 代號不變；stderr 前綴 `aos-llm-kernel:` 變 `kernel_llm:` |
| 金鑰歸端點小 proc、kernel 不碰 | 不關總機的事 | 不變 |
| `llm_forward`、隊 kernel（`kernel/llm-team`） | 不動：轉交函數是端點函數，隊 kernel 就是一台 `exec` 指到它的問腦總機 | 只換 `daemon.json` 的 `exec` |
| 11-07 kernel-nest 已裁：期限往下帶（`request.json` 的 `priority`）、透明轉交錯誤、`child` 進帳不進回信、一隊一格、轉交 proc 半路死重掛一次、`level` | 問腦包＋`runner.py`，照搬 | 不變 |
| hook 三時機 | 骨架 | **新得到的** |
