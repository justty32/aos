# 問腦總機要不要收進框架：「先不併」「全併」「只補 hook」三種各畫出來，列成方向題

← [kernel-framework](README.md)｜上一份 [03-狀態查詢信](03-狀態查詢信.md)｜下一份 [05-施工步驟](05-施工步驟.md)

## 兩句互相頂到的話

- 使用者 10-16：「兩隻kernel不併成一支。」（[N-42](../../../../docs/NORMS/09-kernel.md) 開頭）
- 使用者 11-11：「在我的規劃中，我們會有一個通用的kernel框架，在這個框架下，我們去擴充更多功能如llm之類」

頂層 11-11 的理解是「骨架一份、問腦＝骨架＋問腦專屬那包、翻掉 10-16」；使用者沒有明確答「對」。所以這題由使用者拍板。不管選哪個，`AOS_LLM_KERNEL` 維持另一個變數（已裁）。

## 兩支現在長怎樣

| | 框架站（判官改的） | 問腦總機 `aos-llm-kernel` |
|---|---|---|
| 語言、大小 | Python，約 460 行（加零件後估 650） | C++，2343 行 |
| 中段在做什麼 | 判一下 → **轉寄**給下一站 → 下游回信 | 排序 → **掛一個問腦 proc 到自己那台 daemon** → 等它跑完收成品 → 自己回信 |
| 排隊 | 先來先掛 | 級數、期限、等久升級、包的速度、後端黏著 |
| 專屬的東西 | `procs_*` 規則 | 能力包、額度（總額與每寄件人）、逐封帳 `ledger.jsonl`、後端互斥、逾時重掛一次 |
| 鏈怎麼接 | 信原樣轉寄、回信二選一 | `llm_forward` 同步重問下一層、每層各記帳（11-07 已裁的做法） |
| 共通的 | 收 `$AOS_STACK/requests/`、`queue.json`、回信、寄件人期限 | 同左 |

兩支像的是頭尾（收信、回信、排隊窗），中段不同形：一個是「判＋轉寄」，一個是「排程＋自己跑」。

## 選項 A：先不併（推薦）

```
lib/aos/kernel/           框架：收信、規則＋hook、下一站、回信、排隊   ← 這次做
impls/aos-llm-kernel/     問腦總機：原樣不動
```

- 做法：這次只做框架、把判官收進去。問腦總機一行不改。N-42「兩支不併成一支」原句留著，註一句「先不做，等框架跑穩、而且問腦真的需要 hook 或鏈上轉寄時再議」。
- 後果：收信、排隊窗、回信在兩種語言裡各有一份；問腦沒有 hook 三時機；問腦的鏈照舊走 `llm_forward`。兩支對外的樣子本來就對齊（都收 `requests/`、都回 `{"error": {code, msg}}` 形的拒信）。
- 工作量：0 小時。
- 為什麼推薦：問腦總機是整棵樹每隻 agent 都靠的東西，現在跑得好、11-07 才剛定完嵌套；框架還沒做出來，不知道它要長出什麼口才裝得下問腦；併的好處（少一份骨架）現在換不回重寫的風險。之後要併，路還在。

## 選項 B：全併（骨架一份，問腦＝骨架＋專屬那包）

```
lib/aos/kernel/           骨架，多長兩個口：
                            ① 排序可換（先來先掛 → 包給的排序函數）
                            ② 去處可換（轉寄 → 掛在自己那台 daemon 上跑、收成品當回信）
lib/aos/kernel_llm/       問腦專屬那包（Python 重寫）：能力包、額度、帳、後端互斥、
                          級數／期限／aging 排序、掛問腦 proc、逾時重掛一次
impls/aos-llm-kernel/     刪掉
impls/aos-llm/            寄信那端不動
```

- 做法：骨架從「判＋轉寄」長成一個小排程器；問腦專屬的邏輯用 Python 重寫成一包；刪掉 C++ 那支與它的測試；範本 `kernel/llm-kernel`、`kernel/llm-team` 與試驗場的總機換身體。N-42 的「兩支不併」明寫翻案，N-42 (1) 兩份分檔跟著改寫。
- 後果：骨架只有一份，問腦自動有 hook 三時機與回信二選一。代價：骨架變大（估多 300 行），不再是「一包簡單零件」；問腦每輪從行程內的 C++ 變成起一次 Python 再叫好幾次 aos-post，信多時每輪變慢；重寫期間全樹的問腦都受影響；`ledger.jsonl`、`used.json`、`queue.json`、`endpoints.json` 的格式要逐欄對回，不然要重建。
- 工作量：約 45～60 小時（骨架兩個口 8、問腦包 25～35、測試搬移 8、範本與文件 6、整棵實跑 4）；要回家用 fsm 真腦驗。

## 選項 C：只補 hook（C++ 留著）

```
lib/aos/kernel/           框架（Python）
impls/aos-llm-kernel/     留著，加三個 hook 時機（排序前、決定掛之前後、回信前）
```

- 做法：問腦總機照舊是自己一支，只在 C++ 裡加上跟框架同名、同契約的三個 hook 點。回信二選一對它沒意義（它一定自己回），`next` 它已經有（`llm_forward`）。
- 後果：行為對齊、程式還是兩份；等於「替問腦加 hook」這個沒人提過的需求。
- 工作量：約 12 小時（C++ 的 hook 執行約 250 行＋測試）；公司可做。

## 方向題

**問腦總機要不要收進通用 kernel 框架？**

1. **A 先不併**（推薦）：框架先做、判官先收，問腦不動；等框架跑穩再議。0 小時。
2. B 全併：骨架長成排程器、問腦專屬那包用 Python 重寫、刪掉 C++ 那支；明寫翻掉 10-16。45～60 小時，要回家驗。
3. C 只補 hook：C++ 留著，加同契約的三個 hook 點。12 小時。
