## 1. 總覽

| 組 | 腦看到的工具 | 資料夾 | 包 | 誰拿到 |
|---|---|---|---|---|
| 簡單組 | `json_get`、`json_ls`、`json_search`、`json_set`、`json_add`、`json_del` | `lib/base/json_*/` | `lib/packs/json.json` | agent-fsm、eca-claude 範本；reviewer 範本直接列 `json_get`、`json_ls`、`json_set`、`json_del` |
| 複雜組 | `aos_json_get`、`aos_json_set`、`aos_json_add` | `lib/aos/aos_json_*/` | `lib/packs/aos_json.json` | 預設誰都不掛；要的 agent 在自己的 `tools.json` 的 `$override` 多一行 |

- 九個工具資料夾的 `_entry` 都是三行殼（照現有工具的開頭找 `lib/`），只叫 `aos_json.main("get", directives=False)` 這種；**全部邏輯在一支 `lib/aos_json.py`**（跟 `tool_io.py`、`directive_value.py` 同層）——這就是「做成一個 aos_json 工具」。
- `lib/aos_json.py` 自己不開檔：讀＝`aos-json get`，寫＝`aos-json set／append／del`（原子寫入、只重寫有變的那一塊照舊）。Python 只做：切路徑、量大小與摺疊、ls 排版、search 走訪、add 的判斷、值的來源。
- 簡單組把 JSON 當普通資料：不解、不穿、不擋 `$ref`／`$env`。複雜組＝同一批動作再加指示詞與值來源的選項；選項全不給時行為跟簡單組一樣。

## 2. 共通規則

**路徑 `path`**（每支唯一的定位參數，一整串）：`檔` 或 `檔#/指標`。第一個 `#` 就切；`#` 後一定要 `/`；指標照 RFC 6901（`~1`＝`/`、`~0`＝`~`）。**11-12 稍後改照標準（Q3 已裁）**：`x.json`、`x.json#` 是整份，`x.json#/` 是名字為空字串的那個 key，指標原樣交給 aos-json。檔的相對路徑從 `$AOS_WS` 算、絕對照用、不擋工作區外（`tool_io.ws_path`）。不剝引號、不替腦改路徑；`#` 後不是 `/` 時＝`PointerBad`，原因句照舊帶提示（例 `... has quotes around it; write the path as cfg.json#/n`）。

**值 `value`**：任意 JSON，照字面存。字串就是字串（`"{\"a\":1}"` 存成字串）。

**輸出**（給腦，英文、省 token）：
- 讀：`json_get` 印那個值本身（一行緊湊 JSON，不包殼）；`json_ls`／`json_search` 印文字、一行一項、欄位用 TAB。
- 寫：一行 `ok 路徑`（路徑是實際寫到的位置，`-` 換成真的索引，例 `ok cfg.json#/tags/3`）。
- 不是值的話一律用方括號開頭的一行（跟 `[exit code N]` 同款，不會跟 JSON 值混淆）：`[too big] …`、`[more] …`、`[no match]`。
- 錯：`工具名: error: 代號 原因` 兩邊印、退 1（lib 規則 3）。

**錯誤代號**：工具自己出的＋aos-json 最後一行的代號與原因原樣接過來（C-52 例外 ⑤，名單要更新，見 §8）。

| 代號 | 誰出 | 什麼時候 |
|---|---|---|
| `ArgumentsBad` | 工具 | 缺參數、型別不對、互斥的值來源給了兩個 |
| `PointerBad` | 工具 | `#` 後不是 `/`、檔名是空的 |
| `KeyExists` | 工具 | `json_add`：物件裡已有這個 key；或路徑指到的東西已在 |
| `TextBad` | 工具（複雜組） | `text` 不是 JSON |
| `WsMissing`、`LaunchFailed`、`CommandFailed` | 工具 | 沒工作區；aos-json 起不來；aos-json 退非 0 卻沒有錯誤行 |
| `FileMissing`、`FileBad`、`PointerMissing`、`TargetBad`、`ValueBad`、`WriteFailed`、`Internal` | aos-json 轉接 | 檔不在／不是 JSON／指不到／這個位置不能這樣改／寫失敗 |
| `FollowMissing`、`DirectiveBad`、`CheckFailed` | aos-json 轉接（只有複雜組會遇到） | 路上有指示詞沒開 `follow`；指示詞解不開；`check` 擋下 |

## 3. 簡單組六支

### json_get — 拿一格的值

| 參數 | 型別 | 預設 | 說明 |
|---|---|---|---|
| `path` | string | 必填 | `檔#/指標` |
| `max_bytes` | integer | `$AOS_JSON_MAX_BYTES`，沒設＝8000 | 值的緊湊 JSON 超過這麼多 bytes 就不印值 |
| `full` | boolean | false | true＝不管多大都印整個值 |

```
{"path": "cfg.json#/states/think"}      → {"exec":"think.py","next":"act"}
{"path": "cfg.json#/max"}               → 20
{"path": "big.json"}                    → [too big] object, 132 keys, 48213 bytes (max_bytes 8000). List it: json_ls big.json. Or json_get a deeper path, or "full": true.
```
大小＝這個值印成一行緊湊 JSON 的 UTF-8 bytes（不是檔案大小）；`[too big]` 行同時給型別與自然長度（物件 `N keys`、陣列 `N items`、字串 `N chars`）；退 0（這是結果不是錯）。

### json_ls — 列一格底下有什麼

| 參數 | 型別 | 預設 | 說明 |
|---|---|---|---|
| `path` | string | 必填 | |
| `long` | boolean | false | true＝每項多印型別與大小（像 `ls -l`） |
| `offset` | integer | 0 | 從第幾項開始 |
| `limit` | integer | `$AOS_JSON_MAX_ITEMS`，沒設＝200 | 最多列幾項 |

第一行一定是這一格自己的型別與長度（所以不另做 `json_len`）；之後一行一個孩子，印的是「可以直接接在路徑後面」的那一段（key 裡的 `/`、`~` 已跳脫）。
```
{"path": "cfg.json"}
object, 4 keys
name
max
states
tags

{"path": "cfg.json", "long": true}
object, 4 keys
name	string	5 chars	7 bytes
max	number	20
states	object	3 keys	1840 bytes
tags	array	12 items	96 bytes

{"path": "cfg.json#/tags"}                  → array, 12 items (index 0..11)
{"path": "cfg.json#/tags", "long": true}    → 第一行同上，之後每項一行 0<TAB>string<TAB>3 chars<TAB>5 bytes
{"path": "cfg.json#/name"}                  → string, 5 chars
```
`long` 的大小欄：物件、陣列、字串印長度＋bytes；number／boolean／null 直接印值。沒列完時最後一行 `[more] 200 of 1532 shown; next: "offset": 200`。

### json_search — 找 key／value，往下或往上

| 參數 | 型別 | 預設 | 說明 |
|---|---|---|---|
| `path` | string | 必填 | 從哪一格找起 |
| `key` | string | 沒給 | 要找的 key 名 |
| `value` | 任意 JSON | 沒給 | 要找的值 |
| `contains` | boolean | false | true＝key 與字串值改成「包含這段字」（分大小寫） |
| `up` | boolean | false | false＝往下找所有子孫；true＝往上找每一層祖先 |
| `limit` | integer | `$AOS_JSON_MAX_ITEMS`，沒設＝200 | 最多回幾筆 |

- `key`、`value` 至少給一個（都沒給＝`ArgumentsBad`）；兩個都給＝同一項的 key 與值都要中。
- 比對：key 整個相等；值照 JSON 相等、型別要一樣（`1` 不等於 `"1"`），物件與陣列也可以當 `value`（整個相等）。沒有 regex。只給 `value` 時陣列元素也算（它沒有 key）。
- 往下：`path` 那一格以下的每個物件成員與陣列元素，照檔裡的順序。
- 往上：從 `path` 那格的父層一路到根，每層只看那個物件自己的成員（不往旁支走）；近的先印。用途像「離我最近、哪一層有設 `timeout`」。
- 輸出一行一筆：`路徑<TAB>型別<TAB>大小或值`（同 `json_ls` 的 long 欄）；沒中＝`[no match]`、退 0；超過 `limit`＝最後一行 `[more] …`。
```
{"path": "cfg.json", "key": "next"}
cfg.json#/states/think/next	string	3 chars	5 bytes
cfg.json#/states/act/next	string	4 chars	6 bytes
```

### json_set — 把一格換成這個值

| 參數 | 型別 | 預設 | 說明 |
|---|---|---|---|
| `path` | string | 必填 | |
| `value` | 任意 JSON | 必填 | 照字面存 |
| `parents` | boolean | false | true＝路上沒有的物件層自動建（像 `mkdir -p`） |

- 物件裡沒這個 key＝新增在最後（最後一層不需要 `parents`）；中間層不在＝`PointerMissing`，原因句提示 `"parents": true`。
- 陣列：`/list/3` 換已有的那項；`/list/-` 接在尾巴；索引超出＝`PointerMissing`（提示用 `-`）。自動建的層一律是物件。
- 整份（`x.json`／`x.json#`；11-12 稍後 Q3 改照標準，`x.json#/` 是空字串 key）＝整份換掉；檔不在＝建新檔。帶指標而檔不在＝`FileMissing`（提示先 `json_set x.json {}`）；`parents` 只管檔裡面的層。
- 輸出 `ok cfg.json#/states/act/next`。

### json_add — 加一項新的（已有就報錯；陣列可插中間）

參數同 `json_set`（`path`、`value`、`parents`）。兩種行為由路徑最後一段落在什麼上面決定，不另設模式參數：
- 父層是物件：加一個新 key；已有＝`KeyExists`（要換值用 `json_set`）。
- 父層是陣列：`/list/2`＝插在第 2 項前面、後面的往後移（0 到長度都收，等於長度＝接尾巴）；`/list/-`＝接尾巴。
- 路徑指到一個已在的陣列本身（`x.json#/list`）＝`KeyExists`，原因句提示 `to add an item write x.json#/list/-`（小模型最常這樣寫）。
- 輸出 `ok cfg.json#/tags/2`。

### json_del — 刪一格

參數只有 `path`。那一格要在（不在＝`PointerMissing`）；刪陣列元素後面的往前移；整份檔不刪（`TargetBad`，提示用 `remove`／`trash`）。輸出 `ok cfg.json#/old_key`。

## 4. 複雜組三支（`aos_json_*`）

同名動作的簡單版參數全部照收，再加下面的選項；都不給＝跟簡單版同行為。說明文字第一句寫明「for aos config files that use `$ref`／`$env`; for plain data use json_*」。

| 工具 | 多的參數 | 做什麼 |
|---|---|---|
| `aos_json_get` | `follow`（boolean，預設 false） | 路上與指到的 `$ref` 穿過去（`aos-json get --follow`） |
| | `resolve`（boolean，預設 false） | 把拿到的值裡的 `$ref`／`$env` 解開再回（`--resolve`）；false＝回原樣 |
| `aos_json_set`、`aos_json_add` | 值的來源三選一：`value`（字面）／`text`（一段字，當 JSON 解析後存；解不開＝`TextBad`）／`from`（`a.json#/x`，把那一格的值複製過來） | 三個剛好給一個，否則 `ArgumentsBad` |
| | `resolve`（boolean，預設 false） | true＝值裡的指示詞先解開再存；false＝原樣存。`value`／`text` 的相對 `$ref` 從目標檔的資料夾算（`lib/directive_value.resolve(值, 目標檔資料夾)`）；`from` 的從來源檔算（`aos-json get --resolve 來源`） |
| | `follow`（boolean，預設 false） | true＝路上的 `$ref` 穿過去、改被參照的那份檔（`--follow`）；false＝路上有指示詞就 `FollowMissing`（aos 設定檔的保護，照 aos-json 原樣） |
| | `check`（boolean，預設 false） | true＝寫之前驗 aos 設定形狀，多出問題就不寫（`--check`，`CheckFailed`） |

`aos_json_add` 的插入與「已有就報錯」規則同 `json_add`。`ls`／`search`／`del` 今天沒有複雜版（讀 aos 設定用 `aos_json_get` 加 `follow`，或簡單組看原文）。

## 5. 上限設定怎麼落

只有兩個數字：`max_bytes`（json_get、aos_json_get）與 `limit`（json_ls、json_search）。由高到低：

1. **這次呼叫的參數**（`max_bytes`、`limit`；`full: true` 直接不限）。
2. **工具行程看到的環境變數** `AOS_JSON_MAX_BYTES`、`AOS_JSON_MAX_ITEMS`。這一層照 aos-tools 現行的順序合出來（後面的贏）：agent 行程的環境 ＜ `tools.json` 那支工具格的 `env`。**agent 的設定檔＝`tools.json` 工具格的 `env`**（範本或 agent 自己的覆蓋層都能寫，一支一格，例 `"json_get": {"env": {"AOS_JSON_MAX_BYTES": "20000"}}`）。
3. **工具定義的預設**：`_tooldef.json` 該 property 的 `default`（8000、200），程式裡同值的常數；模型與 `--help` 都看得到。

- 環境變數不是正整數＝提醒行一行（`tool_io.warn`）、用工具定義的預設照跑。
- 不用工具夾的 `.env`、不在包檔寫 `env`（預設只寫一個地方）。被讀的 json 檔不認任何保留鍵。
- 這兩個變數不列進 tooldef 的 `env` 欄（那欄是「沒設會提醒」的 hub 變數）。

## 7. 判斷：N-45 跟簡單組不衝突

N-45「aos 讀的 JSON 都解」同一條寫明「每支程式只解自己讀的那幾格」「指標取的是那份檔的原文」。json 工具不是在「讀設定來用」，是替腦搬運資料（同 `read`／`write`、`aos-json get` 不加旗標）；要解的人是之後讀那份設定的程式。所以簡單組回原文、照字面寫，不算違反 N-45；想看解開的樣子用複雜組。不必帶給使用者。

## 9. 代定清單

- **D1 腦看到多支 `json_*`，不是一支帶 `op`**：使用者兩天都用這些名字；每支參數少、沒有「某個 op 才有的參數」，小模型較不會叫錯；包可以只給讀的幾支。另一種見 Q1。
- **D2 一個程式 `lib/aos_json.py`，九個資料夾只是殼**：對上「做成一個 aos_json 工具」，改一處全好。
- **D3 讀寫一律經 aos-json**：指標規則、原子寫入、只改變的那一塊、指示詞行為只有一份實作；Python 不自己開檔。
- **D4 複雜組叫 `aos_json_get／set／add`**（**11-12 作廢**：Q2 使用者裁 `jsonx_*`）：`aos_` 表示「懂 aos 的指示詞」，簡單組是「普通 json」。候選見 Q2。
- **D5 複雜版只有 get、set、add**：加料全在「值怎麼來、路怎麼走」，ls／search／del 今天用不到。
- **D6 複雜組選項預設全關**：寫什麼做什麼（C-56）；要解開、要穿過去都由腦明講。
- **D7 `#/`＝整份，由工具先收掉**：使用者 11-11 已定；aos-json 本身今天不改（見 Q3）。**11-12 稍後作廢**：Q3 使用者裁照標準寫法，工具不再收 `#/`。
- **D8 `json_get` 輸出只有值本身，不包殼**：使用者「給路徑，然後拿到一個json value」，也最省 token。
- **D9 太大的判法＝緊湊 JSON 的 bytes，預設 8000**：一個數字管所有型別；約兩千 token。不設「0＝不限」這種暗值，另給 `full`。
- **D10 `json_ls` 預設短版、`long` 才附型別與大小**：照使用者 11-10「ls 默認給短版，-l 才是長版」。選項只有 `long`、`offset`、`limit`。
- **D11 不另做 `json_len`**：`json_ls` 第一行就是型別＋長度。
- **D12 `json_add` 的兩種行為看路徑落在物件還是陣列，不加模式參數**：跟 RFC 6902 的 add 對陣列的規則一樣，少一個要記的參數；指到已在的陣列本身＝報錯並提示寫 `/-`，不偷偷當成接尾巴。
- **D13 `json_set` 的 `parents` 預設關**：像 `mkdir` 不帶 `-p`；最後一層的新 key 不算（像在已有的資料夾裡寫新檔）。
- **D14 search 的比對**：key 全等、值 JSON 全等且型別一致；`contains` 一個開關管 key 與字串值；往上＝逐層祖先自己的成員、近的先。
- **D15 沒中、太大、沒列完都退 0，用方括號行說**：那是結果不是錯。
- **D16 簡單組寫入帶 `--raw`**：簡單組不碰 `$ref`／`$env`，路上有這種物件也當普通物件；「這是陷阱」的保護只留在複雜組。
- **D17 上限的層級**：呼叫參數 › 工具格 `env` › agent 行程環境 › tooldef `default`。**跟頂層告知使用者的「環境變數 › agent 設定」中間兩層對調**：aos-tools 現行就是工具格 `env` 蓋過行程環境（11-10 定的），兩者到工具手上是同一個變數、分不出來；不為這個改 aos-tools。請頂層轉告使用者一句。
- **D18 環境變數寫壞＝提醒行＋用預設**：腦自己修不了設定，不讓整支工具不能用。
- **D19 工具放 `lib/base/`（簡單）與 `lib/aos/`（複雜）**：照 lib 分層，懂指示詞的在 aos 層。
- **D20 包**：`json.json` 給 fsm、eca 兩個範本；`aos_json.json` 預設不掛。eca 的腦要動 aos 設定時可以直接下 `aos-json` 指令，少掛三支。
- **D21 reviewer 範本給 `json_get`、`json_ls`、`json_set`、`json_del`**：對上原本 `json_read`＋`json_write` 做得到的事。
- **D22 `json_rewrite` 今天不動**：沒有包掛它，不在這條線。
- **D23 今天不做 multi**：使用者「需要時」；先看真腦實測有沒有人需要。
- **D24 帶指標而檔不在＝`FileMissing`**：`parents` 只建檔裡面的層，不替腦建檔。
- **D30 `x.json#` 不收**（11-12 頂層代定；使用者未回應，照推薦 (a)，可翻案）：Q3 改照標準後工具曾把 `x.json#` 當整份，但 aos-json 與 N-62 規定 `#` 後一定接 `/`。兩個選項——(a) 工具也不收、整份只有 `x.json` 一種寫法；(b) 改 aos-json 與 N-62 也收——頂層推薦 (a)。做法：工具不剝 `#`，原樣交給 aos-json，照它報 `SpecBad x.json#: # must be followed by /`，後面補一句 `use FILE alone for the whole document: x.json`；九支 `path` 說明改成只講 `FILE alone = the whole document; FILE#/ is the key named ""`；`test_root_is_standard` 改驗九支都報錯、檔不變。

## 10. 待使用者裁

**Q1 腦看到的形狀**（代定 D1：多支；**11-12 已裁 (a) 維持多支**，使用者「1.那就維持多支。2.jsonx_*。」）
- (a) 多支 `json_get`…（代定）：工具清單多 6 支（fsm 淨增 4）；每支單純。
- (b) 一支 `json`（或 `aos_json`）帶 `op`：清單只多 1 支；但一份 schema 要裝所有動作的參數，小模型容易把 `value` 給錯動作或漏 `op`；不能只給「讀」的那幾個動作。
- 推薦 (a)。改成 (b) 只動九個殼與 tooldef，`lib/aos_json.py` 不用改。

**Q2 複雜組的名字**（代定 D4；**11-12 已裁 (b) `jsonx_*`**，使用者「1.那就維持多支。2.jsonx_*。」——`aos_json_get／set／add` 改名 `jsonx_get／set／add`，包 `aos_json` 改 `jsonx`，不留舊名；共用程式 `lib/aos_json.py` 與環境變數 `AOS_JSON_MAX_*` 不改）
- (a) `aos_json_get／set／add`（代定）：一看就知道是「aos 設定用的」。
- (b) `jsonx_get／set／add`：短，但 `x` 要人記。
- (c) `json_ref_get／set／add`：點出 `$ref`，但 `$env`、`text`、`from` 不在名字裡。

**Q3 `#/` 是根，跟 N-62「照 RFC 6901」不一致**（**11-12 已裁：照標準寫法**，見下方「裁定」）
- 衝突在哪：使用者 11-11「json 檔內的根是 `#/`」「`xxx.json#/` 也收」；N-62／N-45 與 aos-json、aos-directive、aos-exec 照 RFC 6901，`x.json#/` 指的是頂層名字是空字串的那個 key。今天的圖紙只讓腦的九支工具把 `#/` 當根。
- (a) 只有腦的工具這樣讀（今天的做法）：同一串 `x.json#/`，工具說是整份、`aos-json get` 與 `$ref` 說是空字串 key。
- (b) 全體系改成 `#/`＝根（改 N-62 條文、aos-json、aos-directive、aos-exec 的切法）：一致；代價是頂層空字串 key 再也指不到（實務上沒人用），要動三個基礎程式。
- 推薦：今天 (a)，之後排 (b)。
- **裁定（使用者 11-12）**：「原來$ref用的是標準寫法。那我們還是按照標準寫法好了。」——兩案都不取，改成第三種：腦的九支工具改回跟 aos-json／`$ref` 同一套 RFC 6901 讀法。
- **做法**：`lib/aos_json.py` 拿掉「`#/` 收成整份」那一行，指標原樣交給 aos-json 解（讀寫本來就經 aos-json，沒有第二套指標解析；Python 只切第一個 `#`、拆層給 search／add 走訪用）。整份＝`x.json` 或 `x.json#`（`#` 後空，工具交給 aos-json 時不帶 `#`；**11-12 稍後改**：`x.json#` 不收，見 D30）；`x.json#/`＝頂層名字是空字串的那個 key。九支 tooldef 的 `path` 說明、知識庫 `aos/tools/json_get.json#/path`、lib 索引跟上；測試 `test_root_is_standard` 釘住。N-62、aos-json、aos-directive、aos-exec 都不用動。
