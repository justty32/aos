## 做了什麼

- **一個程式 `lib/aos_json.py`、九個殼**：簡單組 `lib/base/json_get`、`json_ls`、`json_search`、`json_set`、`json_add`、`json_del`；複雜組 `lib/aos/aos_json_get`、`aos_json_set`、`aos_json_add`。行為照圖紙 §2～§5，D1～D24 全照代定做。
- **aos-json 只加一個旗標 `--raw`**（`set`、`append`、`del`）：路上的 `$ref`／`$env` 物件當普通物件往裡走；跟 `--follow` 同給＝`ArgumentsBad`。簡單組寫入一律帶它（D16）。
- **包與範本**：新包 `lib/packs/json.json`（簡單組六支）、`lib/packs/aos_json.json`（複雜組三支，範本都不掛）；look、change 兩包拿掉 json_read、json_write；agent-fsm、eca-claude 範本的 `$override` 各多一行 json 包（eca 原本單獨登記的 json_read／json_write 拿掉，照使用者「json_read/write之後會被我們的json替代」）；reviewer 範本換成 `json_get`、`json_ls`、`json_set`、`json_del`。範本支數：fsm 45、eca 24、reviewer 11。
- **刪舊**：`lib/base/json_read`、`lib/base/json_write`、`lib/aos/aos_json`（不留舊名）。`lib/agent/json_rewrite` 沒動（D22）。
- **知識庫**：`knowledge/aos/tools/` 九支各一個節點（舊兩個刪掉），packs、cli/parts/json、索引與交叉提及跟上；`knowledge_check` 出廠庫 0 錯誤。knowledge_* 工具本身沒動。
- **文件**：lib 索引與契約、packs README、C-52 例外名單（CONCEPTS 兩份＋conventions）、aos-json README 與 docs/01、02、impls/docs/01、範本 README。

## 施工時多定的（代定，接在圖紙 D24 後）

- **D25 `value` 不列進 schema 的 `required`**：lib 契約把 `null` 當「沒給」（tool_io 規則 9），列成必填的話腦寫 `"value": null` 會被擋；改由程式檢查「有沒有這個鍵」，說明文字開頭寫 `required:`。
- **D26 每支 description 尾巴帶 `Details: knowledge_read aos/tools/<名>.json.`**：knowledge_check 要求工具指到自己的節點。
- **D27 json_search 超過 `limit` 的 `[more]` 行**提示「縮小 path 或加大 limit」（它沒有 offset）。
- **D28 引號包著的指標照舊只給提示**：`q.json#"/n"` 報 `PointerBad`，原因句帶 `write q.json#/n`，不剝（11-11 退回剝引號）。
- **D29 `_` 開頭的鍵不特別處理**（頂層轉來 11-12 description／index 的預告）：照字面；json_ls 的 long 欄是 TAB 分隔，之後要加一欄 description 接在最後即可。
