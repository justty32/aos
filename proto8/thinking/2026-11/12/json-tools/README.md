> 「先說說檔案系統和json這塊，對於檔案系統的存取這沒啥好說的，aos和eca的基礎工具+shell就能夠包攬一切，而對於json，雖然也可以用shell，但我會想要在aos-json的基礎上(或是連同aos-json一起改)，去做一套讓agent方便存取json的東西。最基礎的就json_get/set，給予要存取的json檔案路徑，給予json檔案你想要存取的目標key/index，給予你想要設置的值。就這麼簡單...硬要說的話要給予設置的值，我在想要不要添加parse_text("{\"aaa\":true}")、$ref/$env解析、直接指定另一個路徑(aaa.json#/xxx/yyy)。更進一步就是因應一些基礎需求，提供更方便的工具，比如json_ls，列出指定object/array下的一些key/index，並且可以選擇要全部列出來還是啥...一個問題是列出來後沒辦法得到其values的一些屬性，比如檔案系統有size/權限啥的，我們這邊都沒有，就純列出key，這可能會在之後description/index兩個工具上有所改善。還有json_del/add，不用說。json_search key/value，可以往上也可以往下，value這塊搞不好還可以弄個類似regular expression的...最好不要，不如直接用mongoDB。」

> 「1.好，然後要類似shell ls那樣給選項，讓模型自己選擇要看啥。2.好功能，我希望是可選的、預設開(型別&大小上限可以透過環境變數、選項embedded in json之類設置)。3.這個確實模糊，所以還是不要加入這個功能吧，這畢竟是最底層。要不要解開...我覺得可以是可選...啊，那可以加入這個功能，可以選擇要不要解開或原樣存。這個工具可能要做兩套，一套簡單，一套稍微複雜。4.對，要給選項。6.都可選。6.不管」

> 「寫在agent的設定檔案(建議是工具定義內就有，agent可以自己override)」

## 決定

- **description／index 不在這條線**：之後做專屬工具、另談。knowledge 改回 memory **撤銷**；knowledge 工具日後可能整個拿掉，所以「json 工具跟 memory_*（knowledge_*）的關係」不用處理（11-11 待裁第 4 題消掉）。
- **工具名**：json_get／json_set（11-11 待裁第 1 題）；另有 json_ls、json_del、json_add、json_search。
- **json_ls**：附型別與大小，像 shell `ls` 那樣給選項、讓模型自己選要看什麼。
- **json_get 太大時**：只回型別＋大小、請改用 json_ls；可選、預設開。上限（型別與大小）可以由環境變數、選項等設定。
- **上限寫在哪**：寫在 agent 的設定檔，建議工具定義內就有預設、agent 可以自己 override；被讀的 json 檔自己不認任何保留鍵。優先順序（頂層代定，已告知使用者、未反對）：呼叫時的選項 › 環境變數 › agent 設定 › 工具定義預設。
- **`$ref`／`$env`／指另一個位置**：加，但可選擇解開或原樣存。
- **把文字當 json 解析**：要給選項（只在腦明講時才解析）。
- **json_add**：「已有就報錯」與「往 array 塞一項（含插中間）」兩種都做成可選。
- **同時寫同一檔**：不管、不上鎖。
- **兩套（A）**：兩組工具。簡單組只收路徑＋值，值照字面，不碰 `$ref`／`$env`／解析文字，小模型只給這組；複雜組另外取名，才有這些加料。
- **做成一個 aos_json 工具**，順便更新原本的 aos-json（帶問號，改到什麼程度由規劃定）。
- **json_search**：找 key／value，可以往上也可以往下；值不做 regular expression（「最好不要，不如直接用mongoDB」）。
- **11-11 已定仍有效**：路徑照 N-45 一整串 `檔#/位置`；一次一格、需要時 multi；不存在時自動建可選；認 `#/list/-`；整份檔 `xxx.json` 與 `xxx.json#/` 都收；值照字面；工具不替腦偷改值（剝引號已退回）。

## 頂層讀法與留給規劃的題（代定、可翻案）

- 「做成一個 aos_json 工具」讀成：這一族收在同一個程式／包（名字 aos_json），底下 get／set／ls／del／add／search；腦看到一支帶子指令的工具還是多支 `json_*`，由規劃照既有慣例定，另一種選項與後果列給使用者。
- 複雜組的名字、哪些動作需要複雜版（頂層看只有 set／get／add）由規劃擬，名字給使用者兩三個候選。
- 新工具建在 aos-json 上、需要時連 aos-json 一起改。
- 舊的 json 工具（json_write 等）被取代：不留舊名、不做相容；範本工具清單、知識庫節點、測試跟上。fsm 範本給簡單組；複雜組與 eca 範本給不給，規劃代定。
