## 決定

**起點 10-29，不再往前。** 依據（隊長自查）：docs 引 thinking 的日期最密的是 10-19（97 檔次）、10-23（90）、10-21（64），docs 就是那幾天長出來的；抽查 10-21～10-28 約 20 份，落差 0 項——沒寫進 docs 的全是後來刪掉的 demo／機制（agent-hal 的 compact、agent-kai、self-improve、agent-talk、topdown、claude 節點、aos-hub），其餘已在 P-41、P-11、C-64。往前拉到 10-19 會多約 600 KB／110 份，預估幾乎全是「不提取」。最弱的反而是 11-12（當天約 600 KB、docs 只引 10 次）與 11-10。

**備料→施工→對讀。** 先派 11 個子 agent 分批讀 thinking（B01～B11，10-29～11-12）、對 docs 條號，隊長合成總表並改判 13 處；再照 docs 分檔切成互不撞檔的施工批 W1～W9，每批 opus 施工、另一個 opus 逐句對讀（舊句→新句規則對照、原話 `LOST` 檢查 0 行）。

**寫法。** 條文只寫現在式結論；使用者原話逐字附在撐的那句旁、留一個 thinking 出處；被推翻的舊原話刪。**代定的標法**：AI 代定、使用者沒看過的，句尾標「（代定、可翻案，[出處]）」；使用者說過「都OK／照推薦／先這樣」的算照推薦、不標。整份圖紙級的代定（kernel-framework K-F、json-tools D、eca-slash S 這種幾十條）不進條文，只進程式 README。條號不重編、新條用下一個空號並登記條號表；不改 thinking。
