# 01 對標調查結論：現有 aos 東西對 wf/ 規矩，哪些能搬、差什麼、哪些對不上（11-12 晚，唯讀調查，main 226dc3c67 起）

← [回入口](../wf-to-aos.md)｜所在段落：[現有東西夠不夠對標 wf/ 規矩](../wf-to-aos.md#現有東西夠不夠對標-wf-規矩11-12-晚家機)｜下一份：[02-寄信給人與主session](02-寄信給人與主session.md)

> 11-13 回註：本檔講主 session 的前提（主 session 不在任何 daemon 表上、經外掛的 MCP 登記檔接 aos、always-on 要靠 `system.txt` 搬）在公司 WSL 已不成立——主 session 就是樹裡的一隻 eca `repo-aos`；以 [11-13 main-session-in-aos](../../13/main-session-in-aos.md) 的結論為準。

## 一句話結論

骨架與必須的都有了，沒有硬性缺的：導航、信件、等使用者、always-on 規矩、同質列表、權限都已經能搬；缺的是小輔助（人讀 json、「回了才消」、共享的 open 清單），或是使用者說之後自然會做的（檢查工具、always-on 的掛法）。明天主 session 先卡在 MCP 登記檔有兩格壞掉、0 支工具（11-12 晚已修，見 [02 第 1 點](02-寄信給人與主session.md#明天主-session-開始現在卡在三點)）。

## (a) 現在就能搬，aos 版不比 wf 差

- **分層導航**：資料夾＋json＋`_index`＋`index_view`。index 的格可以再帶 `index` 連到下一層，主觀 index 能疊上去。
- **信件**：`aos-mailbox`／`mailbox_*` 照 wf PROTOCOL 搬（STATUS 白名單、四段、`reply_to`），格式錯會擋（`StatusBad`）；`mail_notify`（on_clock 每 60 秒）有新信自動投進 queue，不用記得輪詢。
- **等使用者**：人＝`~/.aos/stack` 這隻 agent，`peek` 就是 open 清單（實跑通，見下）。
- **always-on 規矩**：定義的 `system.txt` 每輪附加（eca 用 `--append-system-prompt-file`），`/compact`、`--resume` 之後還在，比 wf 的 compact 重讀 hook 穩。
- **同質列表**（tabledb 那類）：json 工具增刪改查夠用。
- **權限**：agent-fsm 的 `before_tool` hook 能真的擋 `git push`（wf 只能靠自律）。

## (b) 差一點，補小東西就行

- **人讀 json**：一支把 json／`_index` 樹攤成人讀頁（md 或 HTML）的轉印器；`aos-json get` 印 JSON 字面、長字串的 `\n` 不展開。
- **等使用者的兩個洞**：見 [02](02-寄信給人與主session.md#等使用者寄信給人照抄指令與兩個洞)。
- **SESSION-LOG**：`todo` 是一隻 agent 私有、在 stack（不進 git）；共享的 open 清單＝一份放 repo 的 json＋「完成即刪」的規矩。
- **主 session**：見 [02](02-寄信給人與主session.md#明天主-session-開始現在卡在三點) 的三點。
- **長散文進 json**：沒有建議形狀（例如一節一物件：標題、內文、原話、出處），沒約定就各寫各的。
- **wake-policy 分層**：`mail_notify` 不看 STATUS、一律通知；要分層就換一支看 STATUS 的 handler（hook 可換）。

## (c) 目前對不上

- **內容樹的結構檢查**（壞路徑、過時 index、超標、codemap）：沒有 aos 版——使用者說先放著。
- **session 內授權的固定落點**（HANDOFF 第一條那種）：eca `/compact` 是 claude 自己摘要，「人給過什麼授權」留不留看摘要。
- **eca 擋不到 push**：eca 的 claude 自己的 Bash／Write 是 `--allowedTools` 不問就准，aos 的 `before_tool` 只看得到經 aos-mcp 的工具。
- **給人點選的頁**（decide-page、progress_board）：單題可以用回信取代，批次互動頁沒有。
- **跨機**：人的信箱與 agent stack 在家目錄，不跟 git（wf 的 WAIT_USER 跨機）。
- **wf/inbox 與 aos 信箱不互通**：`--box wf/inbox` 會 `MailboxBad`，只在兩套並存期間要緊。
