## 1. 總覽

| 項 | 結論 |
|---|---|
| 工具 | 只有一支 `index_view`：把某節點的 index（或指定的那份 index）一行一項印出來 |
| 資料夾 | `lib/base/index_view/`（`_entry` 三行殼、`_tooldef.json`、`_metainfo.json`：唯讀、無副作用） |
| 包 | 新增 `lib/packs/index.json`（只列這一支） |
| 範本 | agent-fsm 掛、eca-claude 掛（各 +1 支）；reviewer 不掛 |
| 程式 | 新開 `lib/aos_index.py`（約 80 行），import `aos_json` 的 `Target`／`read`／`limit`／`page` |
| 改 index | 不做工具，腦用 `json_set`／`json_add`／`json_del`（§5） |

- 不併進 `aos_json.py`：「index 放哪」要獨立成一個函數 `spot(node)`，搬進 `_metainfo` 時只改它；`aos_json.py` 也已 337 行、過 300 行門檻。
- **全系統只有 `spot()` 知道 `_index.json`／`_index` 這兩個名字**：輸出第一行與 `[no index]` 句子裡的位置都由它算出來，腦從輸出得知要改哪裡，指示詞不用寫死。

`spot(node)` 今天的規則：

| 節點 | 判法 | index 位置 | 搬家後（今天不做） |
|---|---|---|---|
| 資料夾 | 路徑沒 `#` 且是資料夾 | `DIR/_index.json` 整份 | `DIR/_metainfo.json#/index` |
| 整份 json 檔 | 路徑沒 `#`、不是資料夾 | `FILE#/_index` | `FILE#/_metainfo/index` |
| json 內的物件 | 路徑有 `#` | `FILE#/PTR/_index` | `FILE#/PTR/_metainfo/index` |

## 2. `index_view` 參數與行為

| 參數 | 型別 | 預設 | 說明 |
|---|---|---|---|
| `path` | string | 與 `index` 二選一 | 要看的節點（資料夾、`FILE`、`FILE#/POINTER`，寫法同 json 工具）；看它天然位置那份 index |
| `index` | string | 與 `path` 二選一 | 直接指定一份 index 表（`FILE` 或 `FILE#/POINTER`，指到表本身） |
| `key` | string | 沒給 | 只看這一項（跟 index 裡的鍵整個相等、照字面，不做 regex） |
| `offset` | integer | 0 | 從第幾項開始 |
| `limit` | integer | `$AOS_JSON_MAX_ITEMS`，沒設＝200 | 最多列幾項（沿用 json 工具的變數） |

- `path`、`index` 剛好給一個；都給或都沒給＝`ArgumentsBad`。
- 第一行一定是方括號行，說用的是哪份 index；之後一行一項 `鍵<TAB>description`。
- 鍵照 index 裡寫的字面印（不跳脫、不解析、不展開成完整路徑）。
- 那一項沒有字串 `description`（或值不是物件）＝只印鍵；description 裡的換行與 TAB 印成空白；其他欄今天不印。
- 工具只讀那一份 index，**不碰被描述的節點**：不查在不在、不附型別大小、不合併別份。
- 想了解節點 X 本身＝看它的上一層：`{"path": "X 的父節點", "key": "X 的名字"}`。

例子（名字與內容是示意）：

```
{"path": "knowledge/aos"}
[index] knowledge/aos/_index.json, 4 entries
cli	Command-line programs, one node per command
tools	Tools the brain can call, one node per tool
packs.json	Tool packs and which templates mount them
notes.json

{"path": "knowledge/aos/packs.json"}
[index] knowledge/aos/packs.json#/_index, 12 entries
json	json_get, json_ls, json_search, json_set, json_add, json_del
...

{"path": "knowledge/aos", "key": "tools"}
[index] knowledge/aos/_index.json, 4 entries
tools	Tools the brain can call, one node per tool

{"path": "d", "key": "data.json#/items/0"}
[index] d/_index.json, 3 entries
data.json#/items/0	First job; the scheduler reads only this one

{"index": "me/views.json#/aos"}
[index] me/views.json#/aos, 2 entries
tools	The only part I use; start at json_get

{"path": "knowledge/aos", "key": "nope"}
[index] knowledge/aos/_index.json, 4 entries
[no entry] nope

{"path": "work"}
[no index] work/_index.json does not exist. An index is a view, not a listing: use ls or json_ls to see what is really there.

{"path": "cfg.json#/tags"}
[no index] cfg.json#/tags is array, it cannot hold _index. Entries about its items may sit in a parent's index (keys like tags/0): try index_view cfg.json.
```

沒列完時最後一行 `[more] 0 to 199 of 512 shown; next: "offset": 200`（同 json_ls）。`[no index]`、`[no entry]`、`[more]` 都退 0。

tooldef description 要點（英文、短）：
- 第一句：`Show a node through its index: the notes agents keep about what is under it (KEY<TAB>description). It is a view, not the facts: entries can be missing or stale; for the real contents use ls or json_ls.`
- 一個例子。
- 鍵怎麼接回路徑：`folder: DIR/KEY; json: FILE#/KEY or FILE#/POINTER/KEY`。
- 怎麼改：`to change an index, edit the place shown on the [index] line with json_set / json_add / json_del`。

## 3. 錯誤代號

| 代號 | 誰出 | 什麼時候 |
|---|---|---|
| `ArgumentsBad` | 工具 | `path`／`index` 沒有剛好給一個；`key`、`offset`、`limit` 型別不對 |
| `PointerBad` | 工具（`Target`） | `#` 後不是 `/`、檔名空 |
| `IndexBad` | 工具 | 那份 index 在，但不是 JSON 物件 |
| `FileMissing`、`FileBad`、`PointerMissing` | aos-json 轉接 | `path` 的節點本身不在或不是 JSON；明講的 `index` 指不到（明講的那份不在＝錯，不是 `[no index]`） |
| `WsMissing`、`LaunchFailed`、`CommandFailed` | 工具 | 同 json 工具 |

## 4. 代定

- **I1 一支，叫 `index_view`，參數五個**：「主要做視角就好」、越少越好；C-54 主題在前；不叫 `index_ls`，免得被當成客觀的 ls。
- **I2 只回 index 寫的內容，不併存在與否、型別大小**：視角不是事實、客觀用 ls／json_ls；C-52 只管自己這層。
- **I3 鍵一律相對「這份 index 所描述的節點」**：天然那份就是它所在的資料夾或物件；指定的那份由寫它的 agent 自己知道在講誰。工具照字面印、不解析鍵，工具裡沒有「相對誰」的邏輯（C-56；主觀 index 放哪不規定）。建議慣例：主觀 index 的鍵寫法跟天然那份一樣。
- **I4 `path` 與 `index` 二選一**：指定了 index 後 `path` 沒事可做，留著就是給了不作用的參數（C-56）；「可指定用哪份」由 `index` 滿足。
- **I5 多處有 index 時只看一份、不合併**：`path`＝只讀該節點自己那份；要看別份就把 `path` 指到那個節點或用 `index`。不往上找、不疊加（KISS、C-52）。
- **I6 index 寫著但節點已不在：不管、不查、不標**：跟「沒列到的不管」同一把尺；查了就變第二個 ls；過時由改 index 的人負責。description 第一句已提醒可能過時。
- **I7 鍵可以跨層（只往下）**：「放外面、鍵寫路徑」本來就需要（`data.json#/items/0`、`sub/a.json#/k`）；工具不解析鍵，零成本。不訂 `..` 與絕對路徑的意思（已拆的 knowledge_fs 那套不搬回來）。
- **I8 資料夾與 json 內同一支**：一條路徑統一尋址；差別只在 `spot()` 三行。
- **I9 fs 還是 json 節點的判法**：有 `#`＝json 節點；沒 `#` 且是資料夾＝fs 節點；沒 `#` 不是資料夾＝整份 json 檔（不在就照轉 `FileMissing`）。
- **I10 「了解 X」＝看父節點加 `key`，工具不自動往上查**：天然位置的原話就是「去看其上方節點的index」；自動查會讓一次呼叫讀兩份、輸出兩種來源（KISS）。
- **I11 不接 `json_ls` 的 long 欄**：json_ls 是客觀那邊，接了等於讓它特別認 `_index`（違反 json-tools D29、C-48），也把視角混進事實；那個預留位置留著不用。
- **I12 天然那份不在＝`[no index]` 退 0；明講的 `index` 不在＝錯**：前者是「這裡沒人寫視角」的正常結果，後者是腦給的路徑指不到（同 json_get）。
- **I13 只印 `description`，其他欄今天不印、不加 `long`**：今天格式只有 description；不認得的欄忽略（C-48）。之後加欄就接在 TAB 後面。
- **I14 項目壞掉不報錯、只印鍵；整份 index 不是物件才 `IndexBad`**：C-48。
- **I15 上限沿用 `AOS_JSON_MAX_ITEMS`**，層級同 json 工具（呼叫參數 › 環境變數 › tooldef 預設）。
- **I16 自己的包 `index.json`，fsm、eca 掛、reviewer 不掛**：主題不是 json（資料夾也有）；eca 沒有 aos 檔案工具但有 json 包，看完正好能改；reviewer 不逛內容樹。
- **I17 `_index` 是這支工具的私有 key，別的工具照舊當普通 key**：C-48 私有 key；`json_ls` 照樣把 `_index` 列成普通孩子。
- **I18 C-52 例外 ⑤ 名單加 `index_view`**：它經 `aos_json` 轉接 aos-json 最後一行，照既有判準推得出來。
- **I19 aos 自己的設定檔子物件若會對不認得的 key 報錯（C-48 11-09 註：只有自己讀的子物件可以），那裡不放 `_index`、改放外面鍵寫路徑**（opus 補）：跟「別人的 json 檔」同一招，不另訂規則。

## 5. 怎麼用 json 工具改 index

| 情況 | 一行例子 |
|---|---|
| 資料夾的 `_index.json` | `json_set {"path": "knowledge/aos/_index.json#/packs.json", "value": {"description": "Tool packs"}}`（檔還不在時先 `json_set {"path": "knowledge/aos/_index.json", "value": {}}`） |
| json 內的 `_index` | `json_add {"path": "cfg.json#/_index/states", "value": {"description": "One entry per fsm state"}, "parents": true}` |
| 放外面、鍵寫路徑 | `json_set {"path": "d/_index.json#/data.json#~1items~10", "value": {"description": "First job"}}`（鍵是 `data.json#/items/0`；鍵裡的 `/` 寫 `~1`、`~` 寫 `~0`，第二個 `#` 照寫） |

- 刪一項＝`json_del` 同樣的路徑；只改 description＝`json_set …/description`。
- 要寫的位置照 `index_view` 第一行 `[index] …` 給的那串往後接。

opus 實測（11-12 公司 WSL，暫存樹，現行 main 的 json 工具）：

| 動作 | 結果 |
|---|---|
| `json_set d/_index.json#/a.json`，檔還不在（加不加 `parents` 都一樣） | `FileMissing`，提示 `create it first, e.g. json_set d/_index.json with value {}` |
| `json_set new/_index.json {}`，資料夾 `new/` 不在 | `WriteFailed cannot write …/new/._index.json.NNN.tmp: No such file or directory` |
| `json_set d/_index.json#/sub~1b.json#~1k` | ok，鍵存成 `sub/b.json#/k`（只切第一個 `#`） |
| `json_add d/c.json#/_index/a`＋`parents` | ok，自動建 `_index` 物件 |
| `json_ls d/_index.json` long | 鍵印成跳脫後的 `sub~1b.json#~1k`；大小欄 `1 keys` |

**json 工具小修建議（不在這條線施工）**

| # | 卡點 | 建議 |
|---|---|---|
| J1 | 新建 `_index.json` 要兩步 | 不改：`parents` 只管檔內的層照留，`FileMissing` 已提示確切的下一步 |
| J2 | 資料夾不在時 `WriteFailed` 看不懂 | 原因句補 `folder NAME does not exist; create it first`；不自動建資料夾 |
| J3 | 鍵是路徑時要自己跳脫 | `json_set`／`json_add`／`json_del` 的 `path` 說明補一句例子：`a key that contains / is written with ~1, e.g. idx.json#/sub~1b.json` |
| J4 | `1 keys` 單複數 | 改成 `1 key`／`1 item`／`1 char`，連測試；最低優先 |
