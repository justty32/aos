## 決定

- 圖紙的 I4「`path`／`index` 二選一」作廢，改成三種給法：只 `path`＝天然那份；只 `index`＝只看指定那份；兩個都給＝天然為底、疊上指定那份，指定那份有的鍵覆蓋天然那份。
- 照圖紙施工；json 小修 J2（資料夾不在的提示）、J3（`~1` 例子）、J4（`1 key` 單複數）一起做。

- 指定那份不在＝照轉 `FileMissing`／`PointerMissing`；在但不是物件＝`IndexBad`（兩個都給時也一樣，不默默略過）。
- json 小修：`json_set {"path": "nodir/_index.json", "value": {}}` 的錯尾巴多 `; folder nodir does not exist, create it first`（資料夾照腦給的字面印，不印絕對路徑；原因句前半的暫存檔路徑另一條線在改，這裡沒碰）；`json_set`／`json_add`／`json_del` 的 `path` 說明多「a key that contains / is written with ~1 (and ~ with ~0), e.g. idx.json#/sub~1b.json is the key "sub/b.json"」；`json_ls`／`json_search`／`json_get [too big]` 的大小改成 `1 key`、`1 item`、`1 char`（其他照舊複數）。
- 出廠內容：`knowledge/aos/tools/index_view.json` 一個節點、`knowledge/aos/tools/_index.json` 一項、`knowledge/aos/packs.json` 加 `index` 包與它的 `_index` 一項；拿真的 `knowledge/aos/tools`、`knowledge/aos/packs.json` 實跑過 `index_view`。

## 代定（施工時下的，可翻）

- **K1 同名的鍵整項覆蓋**：指定那份的 `{description…}` 整個換掉天然那份的，不做欄位層級合併（頂層讀法）。
- **K2 順序**：天然那份的鍵照原順序（被覆蓋的留在原位置），只在指定那份的接在後面；總數算疊完的。
- **K3 不標每項來自哪份**：一行一項 `鍵<TAB>description` 不變；只在第一行寫兩份的位置與「同名以指定那份為準」。圖紙沒有 long 選項（I13），不另開。
- **K4 天然那份沒有（不存在、或節點是陣列等裝不下）時兩個都給＝只看指定那份**，第一行括號說明天然那份為什麼沒有；`key` 沒中照舊 `[no entry]`。
- **K5 說明與提示補兩句**（haiku 第一次實測後）：tooldef 寫明「X 的說明在 X 上一層的 index，`{"path": "kb", "key": "app.json"}`、不是 path kb/app.json」與一項的形狀 `KEY: {"description": ...}`、一個 `json_set` 例子；`[no index]` 句子多一句「上一層的 index 怎麼看它」（只是提示，工具不自己往上找，I10 照舊）。
- **K6 單數**：`1 entry`／`N entries`，跟 json 工具 J4 同一套。
