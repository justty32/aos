## 決定

- index 是**視角**不是事實：天然位置那份＝各 agent 的通用視角；要真正客觀用 `ls`／`json_ls`。
- 工具**只做「透過視角看節點」**；改 index＝直接用 json 工具（`json_set`／`json_add`／`json_del`）。
- 改通用視角：有權限就能改、不用明講，風險自己承擔（落在 json 工具與檔案權限上）。
- 看的時候可以指定用哪份 index；沒指定＝通用視角（天然位置）。
- `path` 和 `index` 可以同時給：指定的那一份有的，覆蓋掉天然那份（圖紙原本的「二選一」作廢）。
- 照圖紙開工，json 工具小修 J2～J4 一起做。
- `_metainfo` 整合（index 搬進去、改名 `index`；`_entry` 搬不進去；開口子、用不用都可以，json 檔也一樣）：一兩週後，現在不做。
- 名字、格式、天然位置、陣列與別人的檔放外面、cache 不做、太大才補：照 [index](../index.md) 的決定。

## 結論

- **只有一支 `index_view`**（包 index，agent-fsm、eca-claude 都掛）：只給 `path`＝看節點天然那份；只給 `index`＝只看指定那份；兩個都給＝天然為底、疊上指定那份，同名的鍵整項以指定那份為準。一行一項 `鍵<TAB>description`，`key` 只看一項。不查節點在不在、不附型別大小、不往上找。
- 「index 放哪」只寫在 `lib/aos_index.py` 的 `spot()`，搬進 `_metainfo` 時只改它。
- 跟既有原則**沒有衝突**；代定 I1～I19（I4 已由使用者改）、施工代定 K1～K6。
- json 工具小修 J2～J4 已做（資料夾不在的提示、`~1` 例子、`1 key` 單複數），J1 不改。
