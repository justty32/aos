## 想法 20：拆分嵌套、節點池與錢財制度（11-08 早，使用者在床上想到，怕忘先說）

「我先說一說在床上想到的一些靈感，不然我怕我忘掉：隨着我們的整棵樹(不管是定義還是快照)愈來愈大，就算是聰明如fable也未必能完全掌握，改進的效率也會下降。所以我覺得要做拆分嵌套，也就是如同神經網路的訓練那樣，但將目光放到單個神經元的訓練上，對於單個神經元而言，他不知道後面神經元在幹嘛，他只知道自己要處理的梯度，還有要分配給後面神經元的梯度(當然，他是知道自己的子函數(後面神經元)有哪些的，只是不管他們怎麽訓練)。換算到我們這邊，就是一個節點，他有自己的審查與改進流程，這些都來自於上一級節點，而最上級節點就是第一線處理我們任務的，所面對的就是我們給的要改進的方向(梯度)。對於那種被多個節點引用參考的定義或節點，他的改進需要綜合這些節點給出的梯度，哪天這些節點覺得他的改進不合他意，那就是可以複製一個新的類似節點用於處理。所以預期會有一個節點池，儲存各種累積下來的定義與快照，這是資產，節點若有需要可以從中找到輪子，而非自己造。節點池會累積，所以要有機制去限制膨脹，我有個想法，那就是錢財制度，也就是每次的最上層改進epoch（也可以不用最上層），都會給最上層一筆錢，最上層把這筆錢截留一定比例給自己，剩下的分配給下層節點，沒被參考或引用的節點就沒被分配到，然後是扣生活費，所有節點依據其消耗的資源去扣錢，扣到0就刪掉。這比較複雜。然後對於單個節點而言，不管他是快照或定義，他的審查與改進流程，都可以是一個指標路徑，指向可用於改進自身的節點。」
