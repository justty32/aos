## 批 1：雜活清場（R2、R3、R4、R6、R7、E10）

各件的問題描述與推薦解法在晚審 [04](../../../../../wf/workflows/refactor/reports/2026-11-07-晚審/04-要使用者裁定.md) 第 2、3、4、6 題、[04b](../../../../../wf/workflows/refactor/reports/2026-11-07-晚審/04b-要使用者裁定-續.md) 第 7 題（使用者都選 A＝推薦）；改法摘要在 [06 末段](../../../../../wf/workflows/refactor/reports/2026-11-07-晚審/06-修正結果.md#11-07-傍晚裁定後的待辦)。

補充：

- **E10 只做單一 tag**（ks-5:B「memory find 加選填 tag……多 tag 交集仍在這條線」；02 批 1 寫的多 tag 交集不做，交集是試驗場 `kb_find` 的事）。介面：`find` 的 stdin 多一個選填 `tag`（字串）；`query` 與 `tag` 至少給一個，兩個都給＝兩條件都要符合；兩個都沒有＝`ArgumentsBad`。一個節點的 tag 來源：JSON 葉節點頂層的 `"tags"` 陣列；資料夾節點同層（節點資料夾內）的 `_tags.json` 的 `"tags"` 陣列。逐字比對、不分 facet。`_tags.json` 本身不算節點（memory 本來就不列 `_` 開頭檔）。壞的 `_tags.json`（不是 JSON、`tags` 不是字串陣列）＝當作沒 tag，不報錯（find 是搜尋，不是 lint）。
- **`read "a/b#/c/1"` 已實作**（`lib/agent/memory/tests/test_pointer.py`），E10 只在 `_tooldef.json` 的 `path` 說明補一句連結寫法：「a link value is a string `node/path#/json/pointer`; follow it with read」。
- R3 動到 `impls/aos-daemon` 時要 build 過（`cmake --build` 照 [dev-env](../../../../../wf/workflows/dev-env.md)）。

判準：照 02 批 1，其中多 tag 那句改成「兩個節點帶不同 tag，`find {"tag": X}` 只回帶 X 的；`{"tag": X, "query": Y}` 只回兩者都符合的」。
