## 判準逐條結果

1. **build 過、批 7 測試照過：通過。** 在副本 `proto8/impls` 跑 `cmake --build build -j8`，退出碼 0、建到 100%。批 7 的 16 個 kernel 測試與其餘既有套件全過；六組總共 83 個測試。
2. **兩層串帳與成功回覆：通過，真起兩台 daemon。** `test_batch8_live.py` 的 `test_unmodified_templates_two_daemons_success_error_and_missing_kernel` 用 `cp -a` 複製兩份範本成並排 stack 的 def，各自從 stack 跑 `aos-exec --stack . def`。先用未改的 kernel.json 寄 fake，驗上層 child.letter 等於下層 ledger 的 id，child.kernel 是包解完的原字串；兩層 usage 相同、上層回覆沒有 child。比較兩條 `ask --full` 成功 stdout 時，只刪除生成的 letter 成員，其他位元組完全一致；stderr 都空、退碼都 0。另驗下層 sender 是整隊 stack 一格。
3. **下層合格錯誤透明轉交：通過，同一組雙 daemon 真跑。** 完成未改範本驗證後，才在測試副本增加一個退 3、印單行合格 error（含額外 details）的端點。經上層與直連下層的 stdout 字串、stderr 最後一行與寄信方退出碼完全相同，error 內容也與端點相同。端點退 3，兩條路的 aos-llm 依其公開錯誤契約都退 1；不是宣稱 ask 會直接退端點的 3。llm_forward 自身另以 shim 驗下層 aos-llm 退 1／3／10／143 都同碼轉交，且 CRLF 與非 UTF-8 位元組也不改。
4. **本機互斥、批次與 switched：通過，真 daemon 慢包。** `test_live_local_packs_batch_once_and_switch_twice` 設 local slots 1／max_packs 1、頂層 slots 4，兩包交替各寄 3 封，第一封先用 gate 留在飛行中，確保其餘信全入列。真端點等 gate，再睡 0.08 秒交給本副本 lib/base/llm_fake。ledger 恰為 `AAABBB`，switched 恰為 `[true,false,false,true,false,false]`；queue.counter_switches 為 2，switched_at 等於 B 第一封 mounted_at。每次等候輪詢都檢查 cur 的包集合最多一種、真 daemon 表最多一封 llm proc 為 running。預備夾另驗後端 slots 總數含前輪與本輪、max_packs 1／2、不同包數而非信數、擋到跳過且別後端照跑。
5. **黏著不擋高級信：通過，真 daemon 與預備夾。** `test_live_urgent_b_runs_before_sticky_a` 在 A 還在飛時寄 normal A 與 high B，放行後 ledger 是 `ABA`，high B 先於等待的 A。預備夾補驗：同級同期限時 A 黏著勝過 B 的 fast；較高級數、較近 deadline、aging 升級都勝過黏著。另驗包格與 reserved 仍有效。
6. **照範本無額外 hub 設定嵌套：通過，與判準 2 同一組雙 daemon。** 啟動環境移除所有 AOS_ 變數，只把副本的 impls／cmd bin 加到 PATH。兩份 def 都 `cp -a`，啟動時不改 kernel.json、不另塞 AOS_LLM_KERNEL；寄信方只設它指向上層。範本的 `$env: AOS_STACK` 加 `$path: ../llm-kernel` 實際可解且寄得到。為保留 repo 內相對 exec 的原字串，在兩個暫存 stack 的共同上一層放 lib 捷徑指向本副本 proto8/lib；這是依賴佈局，不是改範本或設定 hub。兩份 interfaces.json 的 aos-ledger 宣告也核對通過。

## 小選擇

- 混合後端的排序不把「只在同 backend 比黏著」直接塞進 std::sort 比較器，因為可能與跨後端的 speed 比較形成循環。先照既有規則排，再在同有效級數、同 deadline 的區段中，只對各 backend 原本佔的位置做穩定分組；其他 backend 的位置留住。同後端的黏著插在 speed 前，priority／deadline 不動。預備夾包含混合後端案例。
- proc 額外記 backend，讓在飛數按首次掛的歸屬算；沒這欄的既有 proc（批 7 預備夾）按設定裡該 endpoint 的歸屬算。switched 只在首次成功寄掛信時決定，重掛與 ledger 沿用，沒 backend 的旗標為 false。
- `$path` 是字串拼接，會保留 `..`；llm_forward 不自行正規化包的 kernel，child 也保留原字串，測試另驗它解析後確實指到下層 stack。
- 隊範本 sender 額度沿用主範本的 `/tmp/aos-demo-sender` 當可替換範例；全隊每天 3000 次。四包 to 對上主範本現有的 fake／sol／luna／stupid-fast。
- llm-team 的 `_entry` 用帶 description 的 argv 物件，命令與主範本相同，讓新 JSON 檔有一句職責。interfaces.json 同樣帶 description，aos-ledger 的實際宣告仍是 file=ledger.jsonl。
- ls 文字欄位把 backend 加在 slots 後、summary 前，沒寫印 -；JSON 窗沒寫就省略 backend。
