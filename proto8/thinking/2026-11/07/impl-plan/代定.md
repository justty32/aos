# impl-plan 代定（可翻案）

← [impl-plan](README.md)

1. **本線只動 aos 本體**：五份設計落在試驗場 `~/code/playground-ak/` 的步驟（E17、T3、T8、T10、K11、A8、kb-scale 除第 6 步外、晚審 R9～R11）全交 arknights 線，本線不碰。
2. **kernel-nest 落地第 0 步取消**：使用者方向題 7 裁「程式不動，條文改成"推薦用val"」，priority 程式照舊用 `level`。
3. **evolve-design 第 6 步不做**：由 kernel-nest 第 5 步 `lib/aos/llm_forward` 取代（kernel-nest README 已寫）。
4. **照 fable 02 的 9 批與位置**（measure／promote／rollback／watch／metainfo_check／shell_report 放 `lib/aos/`，case 放 `proto8/cases/`，review／watch 紀錄放 `$AOS_WS/reviews/`，R8 改成審視者 `ladder.json#/promote_by`）；E15、E16、A6、T9 自動招這輪不做。
5. **E10 只做單一 tag**：fable 02 批 1 寫了多 tag 交集，跟 ks-5:B（交集留在 arknights 線）不合，照使用者裁定只做單一 tag。
6. **每批交棒不寫進 arknights-kb 的交棒檔**（02 §五 原寫要寫進去）：那是另一條線的檔，改寫在本夾 [交棒](交棒.md) 的「給 arknights」段。
7. **`wf/tools/metainfo_migrate.py` 進 repo 但只是一次性**：給 aos 本體與試驗場各跑一次；arknights 跑過後刪（使用者「不寫遷移」指的是不做相容，一次性改檔腳本照 N-68 用）。
8. **子帳位置用一次性 marker `.observed_child.json` 交接**（批 3 codex 的小選擇，隊長接受）：thought／agents 在自己小格寫這個檔告訴 act／`call()` 這次的 `child` 在哪，取用後刪。比「act 猜路徑」好；11-07 晚寫進 [N-68](../../../../docs/NORMS/10-基礎設施-定義與工作區/10-續-N-68.md)「他見的帳」段。
9. **想法 18 的落點（批 4b）**：收意見用新指令 `aos-feedback`（加 `lib/aos/feedback` 給 aos 內 agent），存 `proto8/feedback/<指令>.jsonl` 並進 git；舒適度 key 叫 `comfort`，拆 AI 角度四子項（usage 用法、help 說明、errors 錯誤訊息、args 參數）＋預留 `user`（現在 null、不排使用者評分）＋匯總 `val`；自稱寫 `_metainfo.json`、他見由 `aos-feedback score` 從意見的 AI 評分與帳裡的錯誤、重試算、不回寫；公式是起步值。
10. **舒適度按評分者細分**：每筆意見記 `rater`（模型名、家族、階位，自由字串）；只給模型名時查 `proto8/feedback/raters.json` 的子字串規則補家族與階位（起始：opus→claude/high、sonnet→claude/mid、sol→gpt/high、terra→gpt/mid、12b→local/low）；`score` 輸出 `ai`（全體）＋`ai_by.family`／`ai_by.tier` 分開看。
11. **裁判比對器叫 `templates/judge-llm/`**（02 寫 `templates/judge/`）：`lib/aos/judge` 已是 daemon 判官，同名會混（第二任隊長）。
12. **裁判比對器是一支同步函數、一次問腦，不是掛 daemon 的 agent**：比對器契約要同步回 `{score, diff, why}`，measure 經 `aos-exec` 叫；它自己寫一行 `think` 帳，measure 照樣把它算成 `agent` 節點、token 進 `check.cost`。要多步推理的裁判以後再做成 thought 包裝。
13. **審視者一輪的機械部分做成腳本 `lib/aos/review_round/`**：量、挑、試 downgrade、換上、開盯梢、retire 建議全是算術，照 C-22 與 11-07 檢討點 3 不交給 LLM；審視者 agent 只叫它、讀結果、對 fix／split 開處方。紀錄按輪放 `$AOS_WS/reviews/<ISO 時間>/`（02 寫的按定義名分夾不用，開輪時還不知道目標）。
14. **前版放 `<defs>/.prev/<target>/<時間>/`、可疊多份**（02 寫的 `<定義>/.prev/` 會被下次換上覆蓋）；判「正用著」走 `aos-daemon-ctl ls --json` 的 `def` 欄，`stopped` 的列不算。
15. **批 9 提到批 7 之前；批 7～8 的 C++ 在副本建、裝回要等 arknights 點頭**：試驗場四台 daemon 的 PATH 直接指 `proto8/impls/*/bin`，llm kernel 每圈重新執行二進位，一建就等於換掉正在跑的 kernel。所以 codex 只改原始碼，build 與測試在 `proto8/impls` 的暫存副本做；隊長在 arknights 線說可以（地點之間）時才在本體 `proto8/impls/build` 建一次裝上。批 9 純 Python、只加新工具，先做不卡。
16. **批 7：重掛沿用第一次的 `request.json`（含推得的期限）與 `seen_at`**（第三任隊長）：上層肯等多久從第一次掛上就定了，重掛不延長。
17. **批 8：backend 還沒記錄載著哪包時，第一封算換包（`switched: true`）**：kernel 不知道 LM Studio 實際載著什麼，保守當成要載入；判準因此寫「`switched: true` 恰兩行（第一封、換包那封）」。
18. **批 8：llm-team 範本的 `kernel` 用 `$AOS_STACK/../llm-kernel`（兩台 stack 並排）**，02 判準「用 aos-grow 長出來」改成「cp -a 兩份並排起來」：aos-grow 是函數成長工具，不管起 kernel。
