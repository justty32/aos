| 人用指令 | `aos-feedback add／ls／show／score`：add 一行送完、追加進 `<dir>/<key>.jsonl`（`key`＝被抱怨指令第一個詞的 basename、小寫）；`<dir>`＝`AOS_FEEDBACK`，沒設＝`proto8/feedback/`；只收與列，不判斷誰該改 | `proto8/cmd/aos-feedback/` |
| 評分者 | 每筆記 `rater {model, family, tier}`；只給模型名時查 `raters.json` 子字串規則（第一條命中，查不到＝`unknown`） | `proto8/feedback/raters.json` |
| 舒適度 | `score` 算他見的 `comfort`（`ai` 四子項 usage／help／errors／args、`ai_by.family`／`ai_by.tier`、預留 `user: null`、`val`），只印、不回寫 metainfo；`val`＝非 null 子項平均 × `calls/(calls+errors+retries)` | `cmd/aos-feedback/aos_feedback/comfort.py` |
| 腦用薄工具 | stdin JSON → 叫 `aos-feedback add`，`by` 沒給＝`aos-agent` | `proto8/lib/aos/feedback/` |

施工時的小選擇（現行行為）：

1. CLI 本體在指令自己的 `aos_feedback/` 套件，薄工具經公開 CLI 呼叫。
2. 旗標可放位置參數前後；支援 `--`、`--flag=value`；`--observed` 可重複給多份帳。
3. `add --json` 印新紀錄、`ls --json` 印 `[{key,feedback,latest}]`、`show --json` 印紀錄陣列；`score` 一律印物件。
4. 沒有 key 檔＝零筆，不建空檔；空的 `AOS_FEEDBACK` 報 `ArgumentsBad`；相對目錄從 cwd 算。
5. 模型子字串不分大小寫；缺 `raters.json`＝沒有規則；只覆寫 family 或 tier 時另一欄仍從規則補。
6. retries 按每檔依序的 tool 行判，`def` 有值以完整 def 認同一工具；各家族／階位的 `val` 共用全體行為因子（帳沒有評分者歸屬）。
7. 沒 score 的意見照樣分組計筆數；`other` 的 score 不進四子項；`user` 固定 null，不排使用者評分。
8. JSONL 讀寫對同檔加排他／共享鎖；壞資料 `FileBad`，指定的帳不存在 `FileMissing`。
9. 薄工具：下層 stderr 透傳；下層非 0 回 `CommandFailed`、起不來回 `LaunchFailed`。
10. 根 `.gitignore` 的 `bin/` 會藏住新入口，所以在 `cmd/aos-feedback/.gitignore` 解除。
