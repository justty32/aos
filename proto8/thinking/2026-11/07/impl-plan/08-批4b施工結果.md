## 圖紙沒寫死的小選擇

1. CLI 本體收在指令自己的 `aos_feedback/` 套件，入口只做載入；不把命令列實作放進 lib，薄工具經公開 CLI 呼叫。
2. 因圖紙範例把旗標放在位置參數後，CLI 支援前後旗標，各段仍交 `aos_flags.parse`。支援 `--` 保護任意文字、`--flag=value`，`--observed` 以重複旗標收多份帳。
3. `add --json` 印新紀錄物件；`ls --json` 印 `[{key,feedback,latest}]`；`show --json` 印紀錄陣列；score 有無 `--json` 都印圖紙的物件。
4. 沒有 key 檔視為零筆；show 空陣列、score 可僅從帳計算，不會建空檔。空的 `AOS_FEEDBACK` 明報 ArgumentsBad；相對目錄從當下 cwd 算。
5. 模型子字串不分大小寫；缺少 raters.json 視為沒有規則，不自動改寫／複製規則。只覆寫 family 或 tier 時，另一欄仍可從模型規則補足。
6. retries 以每檔依序的 tool 行判斷，`def` 有值時以完整 def 識別同一工具，沒有才用 name；其他 tool 切斷、非 tool 不切斷。各家族／階位的 val 使用同一個全局行為因子，因帳沒有評分者歸屬。
7. 無 score 的意見仍分組與計筆數；other 的 score 不混入四個指定子項。user 固定 null，不加任何等待評分的工作。
8. JSONL 寫入與讀取對同檔加排他／共享檔案鎖，寫完整行並 flush 後釋放；不加額外 lock 檔。壞 JSON／壞欄位報 FileBad，指定觀測帳不存在報 FileMissing。
9. 薄工具的 optional null 沿用 `tool_io` 共用規則，視為省略；未提供 by 仍明傳 aos-agent。下層 stderr 直接透傳，不解析；下層非 0 用 `tool_io` 回 CommandFailed，啟動失敗為 LaunchFailed。
10. 根 `.gitignore` 的 `bin/` 會藏住新入口，因此只在新指令夾加本地 `.gitignore` 解除；code map 新檔用暫存 index 生成，保留真實 git 狀態供隊長處理。
