## E7：執行、翻帳、成本與輸入大小

新增 [measure](../../../../lib/aos/measure/README.md) 的 `_entry`、`_tooldef.json`、`_metainfo.json`、`README.md`、`runner.py`、`ledger.py`，以及 `tests/test_ledger.py`、`tests/test_runner.py`、`tests/test_fake_agent.py`、`tests/test_acceptance.py`。

函數目標用 `observed.call()`，agent 目標用公開 add／say／listen／stop／rm。每次建立新工作區，翻帳只從 `interfaces.json#/aos-observed/file` 與帳上的 `stack`／`child` 前進；沒有宣告就當葉，不猜內部路徑。相同父帳下同一工具的多次呼叫合併，重疊的 child 抄本只讀一次。節點 token 只算自己的 think，輸出頂層 cost 加總整棵、逐次取中位數；tree 保留第一次。

測試指令與結果：

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s proto8/lib/aos/measure/tests -v
```

**24 tests，OK**（本指令也涵蓋下列 E8、T6 與 cases 判準）。翻帳部分驗公開宣告、父子抄帳去重、重複呼叫、cached／缺 usage、相對與絕對 def、父量時間及輸入大小；執行部分驗工作區隔離、既有 runs 保留、非零碼與 agent 移除失敗。

`test_fake_agent.py` 真起獨立 daemon 與 llm kernel，父呼叫 bash、thought，子再呼叫 bash，repeat 2。endpoint wrapper 仍執行真正 `lib/base/llm_fake`，只把 usage 換成每問 7 個 input、3 個 output tokens，避免全零讓加總檢查空過。每次 **5 筆 think（父 3、子 2），根 `cost.token.in = 35`**，等於所有公開可達 think 的 prompt_tokens 之和，也等於所有 tree 節點本地 token 之和。兩次都實際 stop／rm，最後公開 `ctl ls --json` 是 `[]`。另以獨立單步 LLM case 重跑三次，每次只問同一個 fake endpoint 一次，根 input token 為 7，consistency 為 `[1.0, 1.0]`，也完整清理。

小選擇：

- 單題暫存在自己的 `runs/<未使用整數>/`，重叫沿用小格時選下一個空號，不覆蓋前次資料。套題使用自己的 `cases/<題名>/runs/<未使用整數>/`。
- 原始 stdout 存在每次工作區的 `stdout.json`，讓不寫工作區的 math 也能考；內容保持原始 bytes，不假定一定是 JSON。
- 根為 script 且有子節點時，其時間用子時間加總以滿足批 4 判準；巢狀節點保留父量牆鐘，避免把父的外層時間改成孫成本。頂層總時間不重加各層牆鐘；token 才加總全樹。
- 節點另帶 `in_bytes`；重複工具呼叫合併時加總，目標根使用本次真實 stdin 長度，供 E14 公式評估。
- 同一本帳切換 endpoint 時，單一名稱仍是字串，多個名稱用去重陣列保留。agent 清理失敗由 measure 報 `MeasureFailed`，不把留下實例的結果當成功。

## E8：逐 byte 門、自訂比對器與獨立成本

新增 `measure/compare.py`、`tests/test_compare.py`；整合於 `runner.py` 與 `tests/test_acceptance.py`。

內建分數＝逐 byte 相同檔案數／expect 檔案數。自訂比對器也經 `observed.call()`，接收 expect／got／input 絕對路徑，回 score、diff、選填 why。所有次數都要達 `min_score`；目標或比對器非零也不能過。比對器的 token 與時間只進 `check.cost`。

測試使用上列 **24 tests，OK** 指令。實際命令列驗了：

- smoke repeat 3 全過；暫存副本把加法答案 `42\n` 改成 `43\n`，`check.pass = false`，`check.diff = ["addition/stdout.json"]`。
- 一支固定回 0.5 的比對器，門檻 0.6，三次都不過。它每次另記 5 個 input tokens，三次答案檢查加兩次自洽檢查，`check.cost.token.in = 25`、`check.cost.counter_calls = 5`，而目標 `cost.token.in = 0`、`cost.counter_calls = 0`。
- 比對器即使不自己記時間，仍有外量牆鐘；`check.cost.time_ms > 0`。比對器非零與輸出型別錯也有對應處理。

小選擇：空 expect 得 1 分；多出的 got 檔案不扣分，照圖紙分母只算 expect。未提供 expect 時，用第一次產出作參考。自洽比對同樣屬「量」的成本，併入 `check.cost`，每個 sample 仍保留自己的答案檢查成本。
