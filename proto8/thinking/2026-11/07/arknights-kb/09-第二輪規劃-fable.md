第二輪不比「做了幾個條目」，而是一個地點一個地點地把「存原文＋連結＋tag」這條流程每一步壓到最低成本、最低模型、最多工具；每做完一個地點就停下審視，把重複的事做成工具、連帶改被牽動的子函數，agent 從重複任務裡自然長出來。

## 一、方向

第一輪證明管線跑得通，但力氣花在「改寫」，而使用者已裁內文照原文存（README 裁定 1），第一輪的 writer 流程整個作廢（簡報 §4）。第二輪的對象換成**過程**：以一個地點為單位，把「取原文→存節點→找名字→建連結→貼 tag→檢查→commit」拆成明確步驟，每步標明現在是 LLM 做還是腳本做、用哪級模型、花多少 token；每做完一個地點跑一次固定的審視環節，能定死的定死、能降級的降級、重複出現的角色長成專精 agent，並把被牽動的定義一起改、一起量前後。條目是副產品，主產品是：步驟表上 LLM 的格子愈來愈少、成本曲線往下、帶說明與 metainfo 的定義愈來愈多。

## 二、對簡報 §9 八題的回答

**1. 第一個地點、換地點條件、換工具的訊號。** 第一個選**婆山鎮**：§3 已有它的逐字結構（1,067 bytes、提到夕／年／黎與活動代號、零連結），最小、已知，又剛好逼出「人名只是字串」和「目標節點還不存在」兩個問題。第二個選**切爾諾伯格**（§6：8 篇以它為題，關聯中等），第三個起才碰哥倫比亞、倫蒂尼姆這種十篇以上的。換下一個地點要三個條件都齊：已 commit 且 opus 抽查過（原文一字不差、連結指對）；審視紀錄寫完；審視點名要工具化的項目，不是做好就是寫明為何延後。某步該從 LLM 換成工具／函數的訊號：(a) 輸出由輸入完全決定（來源路徑、slug、名字比對，§4 已證腳本錯 0）；(b) 連續兩個地點做法一樣；(c) 降一級模型就錯、提示詞修一次仍錯——這就是想法 3「困難處先用聰明模型搞定，再定死」。降級階梯照隊長附註 sol → luna → 本機小模型；某步在某級連過兩個地點，下個地點就降一級。

**2. 關聯怎麼表示、怎麼跟原文並存。** 沿用 aos 已有的「檔案路徑 `#` JSON 路徑」寫法（§6），唯一要補的是讓知識庫工具認得它（見六）。原文葉**一個字不動**，關聯放同一節點的另一葉：哪個名字、在原文哪裡、指向哪個節點（或節點內哪段）。小函數分兩層：找目標／建立／解除／查懸空是通用的 aos 知識庫工具（跟 `#` 寫法同層）；「中文名→節點」比對表與別名是 arknights 這條線的定義。哪些提及值得成連結：先用規則（lore 1,490 個檔名精確比對，不用 LLM），LLM 只裁模稜兩可的；目標還沒進樹的記成「待接」，不丟掉也不硬造節點——細節交 opus。

**3. metainfo。** 「自我宣稱」的家就是現有 `_metainfo`（§7）。本輪所有**新**定義（工具、agent、kernel 設定）都要帶：至少一句白話、成本類數值用任意 JSON 值（可推估、可寫公式），單位用 token in／out／cached、calls、秒；美金算不出（§7），本輪不用錢。「他者觀測」由呼叫者記：agent 記每次工具呼叫的時間與結果，kernel 記每封請求的 token。現在只量得到每工作區的 calls 與總 token，量不到 in／out、逐封、逐 agent，因為 usage 在 `aos-llm ask` 與 kernel 收尾兩處被丟——所以修 usage 回傳與逐封留帳是**前提**（見六），#8 逐 agent 記帳排第二批。觀測值不當門檻，只在審視環節讀。

**4. tag 與連結。** tag 管「找得到」，連結管「從這裡走到哪」。第一個地點就帶 tag，但只帶能從語料既有結構**機械抽出**的（類別、INDEX 分組如國家／組織、events 的分類欄，§8），不讓 LLM 發明 tag。連結只給「以正名提到的實體」（人物、勢力、事件、活動），其餘不連；每節點連結數記下來、審視時看分布，不預設上限。別名／tag 集中索引會超過葉大小（#13），怎麼分片是 opus 的事。

**5. 上下文與審視環節。** 每個地點一棵任務樹：協調者只拿頂層簡介＋目錄，子任務（存原文、比名字、裁連結、貼 tag、檢查、commit）用 `thought` 或子 agent 分派，要查就用 memory 工具自己找；每個地點新實例（繞過 #12／#22，直到修好）。**審視環節固定五步，每個地點做完必做、沒紀錄就不算做完**：(1) 盤點——每步的 calls／token／秒、失敗、人工介入；(2) 找重複——跟前面地點一樣做法的步驟；(3) 工具化——交 codex 寫成工具／腳本／新 agent 定義，附 metainfo 與白話說明；(4) 反向傳播——列出呼叫它或被它呼叫的定義，重跑已完成地點確認仍過，改它們的 metainfo，能降級的降級；(5) 紀錄——一地點一篇：改了什麼、為什麼、牽動哪些子函數、前後數字、延後了什麼。前幾個地點由 opus 主持、gpt 施工；目標約第五個地點起由一個「審視 agent」照模板跑，opus 只審。

**6. 修 aos 本體。** 見六。

**7. 一百個不同質的 agent。** 長的地方：任務樹上每個重複出現的角色（存原文、比名字、裁連結、貼 tag、修 lint、commit、審視、記帳、問答、白話翻譯），再依類別或地區分化（人物專員、勢力專員、某國地點專員），加 kernel 層（隊伍 kernel、轉交 kernel）。「不同質」可檢查判準：跟任何既有 agent 比，下列至少兩項不同——工具集（至少一支對方沒有）、模型或 kernel 設定、自己的記憶子樹、在任務樹的位置（誰叫它）；只換 prompt 不算。避免湊數：只算**在真實地點工作裡被叫過至少一次、留有觀測紀錄**的；連三個地點沒被叫的合併或退役。用 `agents op:new` 當場長出的定義也過同一檢查，每批附白話說明（README 已定）。

**8. 結束與交付。** 見五、八。

## 三、優先序與階段

- **階段 0（前提）**：修 usage 回傳與逐封留帳、知識庫認 `#` 路徑；定審視紀錄模板與步驟表格式；用 sol 手動跑婆山鎮量基準。→ 婆山鎮 commit、每封請求的 in／out／秒都抓得到。
- **階段 1（地點 1～3，打通，sol 為主）**：照步驟表做、每地點審視；預期長出存原文、比名字、連結操作、填 tag 的腳本。→ 三篇紀錄齊、步驟表每步標明 LLM 或腳本、非 LLM 步驟錯誤 0。
- **階段 2（地點 4～8，降級與工具化）**：過關的步驟逐級降到 luna 再到本機小模型；history 控制修好；試審視 agent；agent 數開始長。→ 連三個地點沒叫 sol、步驟表 ≥70% 是腳本、每節點 token 比地點 1 少一半。
- **階段 3（收尾）**：拿地點 1 連出去的一個人物條目試結構能否原樣套到別的類別，只做一條；整理輪末交付。地點做到 8～10 個就收，不做滿 41。

## 四、要驗的假設

- H1 原文照存放得進一葉（≤8,000 bytes）。驗：量 places 41 檔。成立→不切；不成立→同節點多葉，仍逐字。
- H2 用 lore 檔名精確比對就抓到大多數提及、誤判少。驗：地點 1、2 人工對照。成立→名字比對全腳本；不成立→加別名表，仍錯才給 LLM 裁。
- H3 照原文存之後，一個節點的 LLM 呼叫只剩「裁連結」。驗：步驟表每步記 calls。不成立→還在用 LLM 的步驟進審視環節工具化。
- H4 每地點新實例能把單次請求壓在 15 KB 內。驗：抓請求大小。不成立→history 控制提前到階段 1。
- H5 `thought` 真的省上下文（§8b 沒測過）。驗：同一地點開／關各跑一次比 token。不成立→改子 agent 分派，記進不足清單。
- H6 luna 裁連結跟 sol 一樣準。驗：地點 2～3 兩級各跑一次比對。不成立→找出錯的題型做成規則或別名。
- H7 機械抽出的 tag 夠問答 agent 用。驗：10 題先用 tag 縮範圍再答。不成立→列缺的 tag 種類，再議要不要 LLM 貼。
- H8 第五個地點起審視能交給 gpt agent 照模板跑。驗：opus 審它的紀錄有沒有漏。不成立→opus 續做，記差在哪。
- H9 被提到的目標多半還沒進樹。驗：地點 1～3 數懸空比例。成立→「待接」機制必要；不成立→可省。

## 五、成功判準（本輪結束條件）

1. 地點 ≥8 個 commit，每個都有審視紀錄且含前後數字（100%）。
2. 每節點總 token：地點 5 時 ≤1.2 萬（參考 §4 新實例單題 1.04 萬），輪末 ≤0.6 萬；非裁量步驟 LLM 呼叫 0。
3. 步驟表 ≥70% 是腳本／工具；原文葉與規則連結重跑逐字一致 100%（LLM 裁的連結差異只記不擋）。
4. 最後三個地點零 sol 呼叫，至少一步跑在本機小模型。
5. opus 抽查：原文一字不差 100%、連結指對 ≥90%、懸空全標「待接」。
6. LLM 請求 ≥95% 抓得到 in／out／秒；新定義 100% 帶自我宣稱 metainfo，熱路徑定義有觀測紀錄。
7. 活躍且過不同質檢查的 agent 有清單、各有白話說明；零 prompt 複製品。
8. 機器負載 <80%（README）。

提前結束：某前提修補變成大改寫（估超過一個地點的工時），停下寫報告交使用者。

## 六、修 aos 本體的排序

- **前提（階段 0）**：`aos-llm ask` 回 usage、kernel 逐封留 in／out／時間（#3／#18 與 §7 丟 usage）；知識庫認「路徑 `#` JSON 路徑」並提供找目標／建立／解除／查懸空（想法 1）。
- **階段 1 內**：#19 每題工具呼叫上限（降到小模型前的保險）；#12／#22 history 不帶／截斷（成本主因，階段 2 前要好）。
- **階段 2 內**：#8 逐 agent 記帳（他者觀測要分得出誰）；#13 別名／tag 索引分片。
- **延後**：#4（slug 表已繞過）、#1／#2／#17（體驗問題）；kernel 文件「缺 usage 記 null」與實作記 0 不一致，順手改文件。

## 七、要帶給使用者的衝突／方向題

1. **一百個 agent vs. 有機長出。** 想法 8 要一百個，裁定 6 與想法 7 要自然長。照 8～10 個地點、早期每地點約 5～8 個新角色估，輪末可能只有 40～60 個過檢查的。建議只交真數字、不湊；請裁一百是硬目標還是方向。
2. **想法 1 的 JSON 路徑 vs. 裁定 1 的原文照存。** 原文是一整段文字，`#` 後的 JSON 路徑指不進文字中的某句；要能指到「原文第幾段」，得把原文存成逐段陣列（內容仍逐字，只是容器變結構）。請裁可不可以；不可以就只連到節點、不連到段。
3. **成本單位。** 無價目算不出美金，本輪 metainfo 用 token／calls／秒，日後接價目再換算。請確認。
4. **降級階梯。** 沒有 terra，用 sol → luna → 本機小模型（隊長附註）。請確認。

## 八、輪末要交給下一次總覽的東西

每地點審視紀錄（含前後數字）；步驟表終版（每步：LLM 或腳本、模型級、成本）；成本曲線（地點序 × token／calls／秒）；定義清冊（工具／agent／kernel，各帶 metainfo、白話說明、不同質檢查結果、被叫次數）；aos 修了什麼、延後什麼、新挖到的不足；九條假設的裁決；七節四題的使用者裁定；給下一輪的建議（下一類別從哪開始、哪些步驟還在 LLM）。
