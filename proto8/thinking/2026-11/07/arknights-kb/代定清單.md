# arknights-kb 代定清單（使用者 11-07 外出時隊長代定，每條可翻案）

← [arknights-kb](README.md)

每條：決定了什麼、為什麼、怎麼翻案。

1. **試驗場另開 `~/code/playground-ak/`**，不動使用者現有的 `~/code/playground`。為什麼：使用者的試驗場有他自己正在玩的狀態；這條線要大量亂試。翻案：說一聲就把成果搬回或刪掉該夾。
2. **arknights repo 唯讀**：只 `git -C` 讀，要實驗就 clone 到 playground-ak。為什麼：那是使用者自己的另一條專案。翻案：使用者說可以寫就改。
3. **演化出來的定義（工具、agent、kernel 設定）先放 `~/code/playground-ak/` 用 git 追蹤**，定稿值得進 repo 的再收進 proto8 適當位置；每批附白話說明，另維護一份定義總覽（可做成互動網頁，施工交 codex）。為什麼：使用者追加「期待看到你們自我演化出一大堆定義(原始碼)」；試驗場可以亂長、repo 只收穩的。翻案：要全部直接進 repo 就改收法。
4. **第一版設計（fable）照 opus 審查修七條必修**，寫在 [02-設計-修正](02-設計-修正.md)；三題＋補的三題要使用者裁的，使用者回來前先照推薦跑（全部可逆：語言／evidence 不進樹／lint 過就 commit／diff 只記數／每日 3000 calls／千級 agent 第三輪）。為什麼：使用者不在、不停線，且第一輪只在試驗場。翻案：裁了不同的，下一輪照改、已產的節點重跑。
5. **memory_write W1～W4 交 codex 照 K7 已裁圖紙先做**（原排在「大重構後」）。為什麼：這條線第二輪就要用，圖紙已裁定。翻案：結果有問題就 revert 那個 commit。
6. **第二輪先縮窄 LLM 的活、再擴範圍**：`sources:`、標題、段名、`[[…]]` 候選由腳本算好填入，LLM 只產本文；每節開乾淨上下文（新實例或每題清歷史，由下一位設計定哪種）；溫度 0。為什麼：第一輪四個數裡最差的（token／節點、重跑相同率、來源錯）都來自「LLM 做了腳本能做的事」與「歷史累積」，正是使用者「領域越是狹小，能夠變成工具的地方就越多」。翻案：要先擴範圍就照原 04 第二輪排。
7. **〔使用者 11-07 改裁：存成逐段陣列，見 [kb-ideas](../kb-ideas/README.md)；下面是原代定〕（第二輪）原文存成 `source.json` 的一個字串、連結用字元位置指進原文，不切逐段陣列**。為什麼：保證逐字、避開 memory_write「`.md` 第一行要 `# `」與原文 `###` 開頭的衝突，又能指到原文哪裡；fable 方向題 2 未裁。翻案：使用者要切段，就改成段陣列、`at` 換成 `#/paras/N`。見 [10](10-第二輪設計.md)。
8. **〔使用者 11-07 裁定同此：「方向，不湊數」〕（第二輪）一百個 agent 先不湊數**：只算被真實叫過且過「不同質」檢查的。為什麼：使用者想法 7、裁定 6 要自然長；fable 估本輪約 40～60。翻案：使用者說是硬目標，就在審視環節主動拆分角色補到一百。
9. **〔使用者 11-07 裁：成本單位同此；降級階梯改為 sol→terra→luna→本機小模型，terra 由頂層加進 LiteLLM、使用者重啟後才能用〕（第二輪）成本單位 token／calls／秒；降級階梯 sol→luna→本機小模型**（LiteLLM 沒有 terra、沒有價目）。翻案：接上價目或有 terra 再換。
10. **（第二輪）aos 本體 P1～P5 先修再跑**（`aos-llm --full`、kernel 逐封帳、memory 認 `#`、範本 history／工具上限選項、agent 自記觀測），預設行為不變。為什麼：不修就量不到成本，審視環節沒數字可比。翻案：revert 那個 commit。
11. **（第二輪，落實使用者改裁 7）逐段陣列的切法**：`source.json` 的 `paras` 是原文按換行 `\n` 切開的陣列（空行也是一個空字串元素），`"\n".join(paras)` 必須與原文逐 byte 相同；連結指 `節點/source#/paras/N`，要指到段內某處再加 `at: [起, 迄]`（段內字元位置）。為什麼：lore 詞條一行就是一段，換行切最簡單又可逆。翻案：改按空行切也行，只要可逆。
12. **（第二輪，落實使用者 11-07 傍晚）本機模型同一時間只載入一個**：同一時刻只讓一種 `lm-*` 模型在跑；換模型前等前一批全部結束；並行的本機級 agent 必須同一個模型。大小都可試（gemma-4 e4b／12b、qwen3.5-9b 等）。fable 規劃輪中也可開、次數不限（照「opus 匯總簡報→fable 一次性規劃→opus 加深架構」）。
