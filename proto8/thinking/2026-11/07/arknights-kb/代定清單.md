# arknights-kb 代定清單（使用者 11-07 外出時隊長代定，每條可翻案）

← [arknights-kb](README.md)

每條：決定了什麼、為什麼、怎麼翻案。

1. **試驗場另開 `~/code/playground-ak/`**，不動使用者現有的 `~/code/playground`。為什麼：使用者的試驗場有他自己正在玩的狀態；這條線要大量亂試。翻案：說一聲就把成果搬回或刪掉該夾。
2. **arknights repo 唯讀**：只 `git -C` 讀，要實驗就 clone 到 playground-ak。為什麼：那是使用者自己的另一條專案。翻案：使用者說可以寫就改。
3. **演化出來的定義（工具、agent、kernel 設定）先放 `~/code/playground-ak/` 用 git 追蹤**，定稿值得進 repo 的再收進 proto8 適當位置；每批附白話說明，另維護一份定義總覽（可做成互動網頁，施工交 codex）。為什麼：使用者追加「期待看到你們自我演化出一大堆定義(原始碼)」；試驗場可以亂長、repo 只收穩的。翻案：要全部直接進 repo 就改收法。
4. **第一版設計（fable）照 opus 審查修七條必修**，寫在 [02-設計-修正](02-設計-修正.md)；三題＋補的三題要使用者裁的，使用者回來前先照推薦跑（全部可逆：語言／evidence 不進樹／lint 過就 commit／diff 只記數／每日 3000 calls／千級 agent 第三輪）。為什麼：使用者不在、不停線，且第一輪只在試驗場。翻案：裁了不同的，下一輪照改、已產的節點重跑。
5. **memory_write W1～W4 交 codex 照 K7 已裁圖紙先做**（原排在「大重構後」）。為什麼：這條線第二輪就要用，圖紙已裁定。翻案：結果有問題就 revert 那個 commit。
6. **第二輪先縮窄 LLM 的活、再擴範圍**：`sources:`、標題、段名、`[[…]]` 候選由腳本算好填入，LLM 只產本文；每節開乾淨上下文（新實例或每題清歷史，由下一位設計定哪種）；溫度 0。為什麼：第一輪四個數裡最差的（token／節點、重跑相同率、來源錯）都來自「LLM 做了腳本能做的事」與「歷史累積」，正是使用者「領域越是狹小，能夠變成工具的地方就越多」。翻案：要先擴範圍就照原 04 第二輪排。
7. **〔使用者 11-07 改裁：存成逐段陣列，見 [kb-ideas](../kb-ideas/README.md)；下面是原代定〕（第二輪）原文存成 `source.json` 的一個字串、連結用字元位置指進原文，不切逐段陣列**。為什麼：保證逐字、避開 memory_write「`.md` 第一行要 `# `」與原文 `###` 開頭的衝突，又能指到原文哪裡；fable 方向題 2 未裁。翻案：使用者要切段，就改成段陣列、`at` 換成 `#/paras/N`。見 [10](10-第二輪設計.md)。
8. **〔使用者 11-07 裁定同此：「方向，不湊數」〕（第二輪）一百個 agent 先不湊數**：只算被真實叫過且過「不同質」檢查的。為什麼：使用者想法 7、裁定 6 要自然長；fable 估本輪約 40～60。翻案：使用者說是硬目標，就在審視環節主動拆分角色補到一百。
9. **〔使用者 11-07 裁：成本單位同此；降級階梯改為 sol→terra→luna→本機小模型，terra 由頂層加進 LiteLLM、使用者重啟後才能用〕（第二輪）成本單位 token／calls／秒；降級階梯 sol→luna→本機小模型**（LiteLLM 沒有 terra、沒有價目）。翻案：接上價目或有 terra 再換。
10. **（第二輪）aos 本體 P1～P5 先修再跑**（`aos-llm --full`、kernel 逐封帳、memory 認 `#`、範本 history／工具上限選項、agent 自記觀測），預設行為不變。為什麼：不修就量不到成本，審視環節沒數字可比。翻案：revert 那個 commit。
11. **（第二輪，落實使用者改裁 7）逐段陣列的切法**：`source.json` 的 `paras` 是原文按換行 `\n` 切開的陣列（空行也是一個空字串元素），`"\n".join(paras)` 必須與原文逐 byte 相同；連結指 `節點/source#/paras/N`，要指到段內某處再加 `at: [起, 迄]`（段內字元位置）。為什麼：lore 詞條一行就是一段，換行切最簡單又可逆。翻案：改按空行切也行，只要可逆。
12. **（第二輪，落實使用者 11-07 傍晚）本機模型同一時間只載入一個**：同一時刻只讓一種 `lm-*` 模型在跑；換模型前等前一批全部結束；並行的本機級 agent 必須同一個模型。大小都可試（gemma-4 e4b／12b、qwen3.5-9b 等）。fable 規劃輪中也可開、次數不限（照「opus 匯總簡報→fable 一次性規劃→opus 加深架構」）。
13. **（落實使用者 11-07 傍晚「將時間成本也算進去」，補代定 9）時間是成本的正式一維**：每一步、每個模型等級都記牆鐘秒數（含排隊與本機載入模型），降級比較一律同列 `{token:{in,out}, calls, time_s}`；本機模型省 token 但慢很多時，結果裡明寫取捨。翻案：使用者說時間只記不比，就退回只記。
14. **〔使用者 11-07 傍晚晚審第 9 題選 B 改裁：時間和 token 用同一個 1.2 倍門檻，取消本機 3 倍放寬；下面是原代定〕（第二輪，B3 審視後）降級選級規則**：同一份題目每級跑 3 次，三次一致率都 ≥90% 才合格；合格的較低一級，token 與秒數都不超過上一級的 1.2 倍才往下降；本機級不吃遠端額度，秒數放寬到 3 倍（取捨寫進結果）。為什麼：B3 照「級序便宜」選了 terra，實測 token 多 7%、秒數 2.3 倍，proxy 又沒價目，「便宜」沒有實測支撐；時間是正式一維（代定 13）。翻案：使用者給各級價目後改成按價格算。
15. 〔spans 部分已被代定 26 取代：一目標一條、只到段落〕**（第二輪，切爾諾伯格審視後）連結形狀與可連類別**：一個節點裡同一目標只一條連結，所有出現位置收進 `spans: [{in, at}, …]`（使用者想法 6「別濫用連結」）；places 加進可連類別（不連自己）；候選先按可連類別剪枝、跳過 `詳見：` 連結行，剪完只剩一個＝規則命中，同一名字一節只問 linker 一次。為什麼：切爾諾伯格 linker 裁的 22 題裡約四成是被丟掉或可規則化的白工。翻案：要逐處各一條就把 spans 展開回去。
16. 〔「本機秒數放寬 3 倍」已被使用者晚審第 9 題改掉，見代定 36〕**（第二輪，龍門審視後）降級階梯可跳過失敗級**：代定 14 的「合格的較低一級」指任何更低且合格的級，不要求相鄰級都合格；B4 照「遇失敗級就停」選了 terra，但本機 gemma-4-12b 三次全合格、token 2,152（terra 3,829）、秒 10.4（terra 8.5，本機放寬 3 倍內），照本條應選本機 12b。地點 4 起 linker 先用本機 12b，品質一次不合格就退回 terra，成本看三地平均（照 evolve-design「容忍短暫退步」）。為什麼：luna 失敗是輸出格式錯，跟本機級能不能用無關；不跳級會讓一個格式脆弱的中間級擋住整條階梯。翻案：改回「不跳級」就照 B4 選 terra。
17. **（同上）階梯試驗只在換題型或換模型時跑**，不每地點都跑；平常照選定級跑、靠抽查與 check 盯品質。為什麼：B4 階梯 47,038 token 是正式三地 12,647 的 3.7 倍。翻案：要每地點都量就恢復。
18. **（第二輪，隊長接手時的指示）價目未知**：繼續只比 token（in／out）、calls、秒，不換算金額。翻案：使用者給 LiteLLM 各級價目後改按錢算。
19. 〔已被代定 25 取代、使用者 ks-1 裁定：整詞連寫、撞名登記順序加序號〕**（後半，抽查第 3 條）節點名規則**：腳本照拼音規則算 slug（無聲調整詞連寫、通名後綴前加連字號、同類撞名改帶聲調數字再不行加序號），不用英譯；namer agent 因此出熱路徑、標 sleep。規則全文見 [13 §二.3](13-第二輪後半設計.md)。為什麼：抽查發現三種寫法混用、單字人名同音會撞；拼音規則可由腳本完全決定（使用者「能定死就定死」）。翻案：見方向題 E——要官方英文名就改成「官方英文名表優先、查無才拼音」。

23. 〔已被代定 26 取代：`to` 一律節點路徑，無 pending〕**（後半，抽查小事）pending 連結的 `to` 維持指 lore 原檔**，10 的 `ak/…` 寫法作廢；目標建好後由 `kb_backfill` 翻成 `ak/…`＋`ok`。為什麼：B3 改這樣才讓命名離開熱路徑。翻案：改回先命名再連。
24. **（B5 收，松心山谷審視）詞內表**：單字人名卡在普通詞裡（日後、當年、鋪陳）是 linker 白工與錯誤的主要來源（四地單字模稜 34 處、拒 18；Luna 唯一錯也是單字「年」）。改法：資料檔記「詞」，被表中詞蓋住的單字名由規則丟；linker 拒單字名時回報所在詞、腳本驗過寫表；種子 15 詞由隊長讀 18 次拒絕定。不選「後一律丟」（會誤殺真出場）。風險：名字在詞首的種子（年前、後續、東部）可能誤蓋「年前往」這類真出場——B6 四地重建比對與抽查盯。翻案：刪 `ak/index/inword.json` 即回原行為。
25. **（11-07 16:05，對照另一帳號 [kb-scale](../kb-scale/README.md)）命名改採 kb-scale**：整詞無聲調拼音連寫（`poshanzhen`，不再在通名前加連字號）、同類撞名照 lore 路徑排序登記加 `-2`／`-3`、登記即凍結、人可蓋過（`by: human`）、名字表按類別分檔且鑰匙＝lore 路徑；取代代定 19 的帶聲調數字與通名連字號。為什麼：兩帳號設計要收斂到一份；kb-scale 指出帶聲調仍會撞、終究要序號，多一套規則沒好處；凍結讓已引用的門牌不變。方向題 E 併入 kb-scale 方向題 1（推薦 A：拼音，幹員可取官方英文名）。翻案：回代定 19 只改 `kb_slug` 一處後重建。
26. **（同上）連結形狀改採 kb-scale**：`to` 一律指節點路徑（不分 pending／ok、不留 lore 指向、刪 retarget 與 13 B7 的 `kb_backfill`）；位置只到段落、記第一次出現的段，拿掉 `at` 與 `spans`；`by` 字串。取代代定 15 的 spans 與 23。為什麼：區間沒有讀者又兩次出錯；slug 可預算後 pending 只是多一個狀態（C-56 做減法）；正好落實使用者「別濫用連結」。內部 kb_mentions 仍用字元位置（詞內表要用）。翻案：`in` 改陣列或加回 `at`。
27. **（同上）同名跨五類固定優先序** characters→places→factions→events→operators，由規則定、不問 linker；節點記語料 `rev`（40 碼），lint 規則 1 比 `git show rev:from`。為什麼：烏薩斯這類「勢力／地點」二選一原本要問 LLM，固定序後可走零 LLM 路徑；rev 讓「過期」與「壞掉」分開。`kb_sync`、白話庫、`memory find` 認 tag 本批不做（後兩者等地點做完；tag 屬 evolve-design 的 aos 本體線）。翻案：優先序改由 linker 判。
28. **（B6 收）語料未提交的草稿不算身份**：節點釘語料 rev，`lore/characters/黎.md` 只在使用者語料工作樹、沒 commit，所以婆山鎮少一條「黎」。為什麼：rev 才可重現；試驗場不替使用者的語料 commit。翻案：使用者 commit 那檔後重跑婆山鎮即回來。
29. **（B6 收）本機 12B 答不了大題就退 terra、不硬修**：婆山鎮 16 題它兩次都給錯索引；其餘四地（1～2 題）一次過。為什麼：大題是少數、退回成本已入帳；照代定 16「一次不合格就退回」。翻案：要拆題給 12B，就讓 kb_link 每次最多送 N 題。
30. **（B6 收）B7 加 H4 校準**：reviewer v0 先在三個隊長已審過的 case（切爾諾伯格 B3、松心山谷 B5、伊比利亞之眼 B6）上盲跑、跟隊長處方比，再上地點 6。為什麼：審視交給系統前要先知道它看不看得出人看出的事；成本低（三個小 case）。翻案：直接上地點 6。
31. **（落實使用者 11-07 傍晚 kb-ideas 14）指標公式與模型下限**：原話「輸入和輸入的token數量」照上下文讀作輸入＋輸出，指標＝(token_in＋token_out) ÷ (所參照原文 bytes × 2)；「所參照原文」先取該步實際送進 LLM 的原文（地點節點＝該 lore 檔 bytes），**只在單個任務（一個地點／人物／事件）這一級算與畫線**（使用者補充適用範圍）；任務內部各步（linker、reviewer 等）用子指標（需 LLM 題數、模型等級、秒），表裡標明「子指標」。網站畫這條線取代單看 token 降幅。模型下限 10B：降級階梯改為 sol→terra→luna→本機 12B（e4b 等 <10B 除名）；複雜題（題多、同類多身份）照規則升到高階，不為省硬降。翻案：使用者若是指「輸入÷原文」就改分子。

33. **（B7 收）reviewer 處方駁回、word 改選擇題**：烏薩斯 reviewer 開「terra→luna」被隊長駁回（luna 已淘汰；真因是本機 12B 答不了 B7 新加的自由填 word，兩地退 terra、單任務指標約 0.9→2.0）。改成腳本列最多 3 個候選詞、linker 只回編號或 null。為什麼：選擇題 12B 答得了、驗證零成本；「學不到」不該讓整題失敗。翻案：回自由填＋重答。
34. **（B7 收）審視全自動延後**：H4 校準 0/3（reviewer v0 三案都開成「kb_link／split」，沒看出隊長看出的具體問題），改善花費是生產的 8.9 倍（177,818 對 19,925 token）。B8 改做「審視證據包」（腳本先把被拒單字的上下文、本機失敗原文、召回疑點、任務指標整理好），reviewer v1 只讀證據包、處方要引證據、單案封頂 1.5 萬 token；重跑四案 H4，**≥3/4 才談自動換模型**。為什麼：使用者「上下文最小化」；隊長自己找到問題靠的正是這幾樣證據。翻案：照 13 原排直接做全自動。
