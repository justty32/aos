## 2. 一個 pass（隊長在沙箱外跑，codex 不跑）

```
bin/pass_reset --scope pass
bin/batch_run --class places,events,characters --list R5/tasks.txt --workers 4 --batch <trial>-p<k>
  批末 hook：pool pay（v0 只記帳）；v1 加 distill compress --dry-run --suspect、distill essence（q1:B）
kb_truth → kb_rules stats --dedupe-qid → kb_rules promote → E3 重訓
review_round（v1 加梯度信）→ 隊長裁 open_human、批知識類處方、其餘寫 R5/<trial>/meta_todo.jsonl
bin/curve append <trial> <k>
```

停：達標（§5）或 5 pass。跑動中零人工；pass 間隊長動作記牆鐘（`curve` 的 `captain_s` 欄，隊長手填）。

## 3. 量具

**曲線** `R5/<trial>/curve.jsonl`（每 pass 一行，`bin/curve` 從 report.json、steps.json、ledger 算；隊長只填 captain_s）：

```json
{"trial":"v0a","pass":1,"t2_train":190,"t2_holdout":31,"zeroed_tasks":0,
 "prod_call_tok_median":4452,"ref_call_tok_total":106000,"prod_median":1.55,
 "wrong_blockable":0,"wrong_scattered":2,"live_rules":0,"holdout_cov":0.0,"holdout_purity":null,
 "score":{"prod":0,"ref":0,"review":0,"judge_qa":0,"improver":0,"captain_s":0},"meta_score":0}
```

`t2_*`＝送 LLM 的 T2 題數（訓練 18／驗證 4 分開）；`zeroed_tasks`＝該 pass 沒有生產呼叫的任務數；`score` 五欄照 `pool/config.json#/cost` 換分。另 `bin/curve show <trial>...` 印 markdown 表＋文字曲線（給收輪與網站）。

**meta 入帳**：`pool` 加 ledger kind `meta`（`pool meta --epoch <e> --tokens N --wall-s S --note '<包名>'`），只記、不分紅；codex 施工包的 token 隊長從 codex 回報手填。

**待元層** `R5/<trial>/meta_todo.jsonl`：`{pass, from: review_round|captain, target_def, say, kind: code|prompt|layout|threshold}`。

**升降 qid 去重**（P0d）：`kb_rules stats --dedupe-qid`——fires／right／wrong 以 `(task, mention_offset)` 為 qid，同 qid 只算一次、後一次覆蓋前一次判決。**預核**：`kb_rules precheck --batch T --dedupe-qid` 用 `PG` 第四輪的 rules.jsonl 與 T 批題目算：去重後幾條 candidate／shadow 過得了 22 §4（≥20 題、≥5 任務、T1∪T2 錯 0、整體 ≥95%）；≥3 條照舊，<3 條把 base-v0 的門檻改成 ≥8 題、≥3 任務（25c §4 預先寫死），結果寫進 `R5/precheck.md`，再打 tag。

## 4. 想法 21 的 LLM 歸納（使用者 q1:B）與格式（q2）

- `distill essence`：每 pass 收輪最多 **1 次** LLM 呼叫、輸入 ≤2k token（只送 form=literal 的 candidate／shadow 規則樣本，取觸發最多的前 N 條塞到 2k）；模型 `chatgpt-gpt-terra`（推不出就 sol，報告寫明）。
- 輸出存 `W5/distill/essence.jsonl`，每行：

```json
{"id":"ES-<hash>","form":"essence","status":"candidate","by":"llm:<model>",
 "say":"<自然語言描述本質，英文>","pattern":{"side":"left","text":"〈","tmpl":null},
 "verdict":"nolink","covers":["E3-…","E3-…"],"pass":2,"tokens":{"in":1800,"out":200}}
```

- `pattern` 可空：有 `pattern`（字面或 06 的三型模板）的本質進影子計分、照代定 74 升降（qid 去重）；**只有 `say` 的**只進收輪報告與元審視證據包，不作答。
- 呼叫記 ledger kind `improver`（不算生產）；06 量法 f 照「≤1 次／pass、≤2k token」。

## 5. 判準

**達標**（訓練 18、同一 pass 全成立，只用來算元2）：`t2_train ≤ 第 1 pass 的 70%`、Z1＝0、D3 不破。

**元指標**、**每 pass 健康判準**、**成本預估**照 25c §4、§7（元1～元5；Z1、Z2、Z3'、Z4'、Z5、S2；壓縮 a～g；節點池 P1～P4，退休兩項 N/A）。

**主要／周邊表**（固定指標，每 pass 一張、收輪一張總表）：

| | 步 | LLM 呼叫 | 模型 | token | 秒 | 子指標 |
|---|---|---|---|---|---|---|
| 主要（S4 連結裁定） | 1／任務 | 生產＋參考 | terra-low／sol-low | in／out | 中位、合計 | T2 題數、清零任務、每次生產呼叫 token |
| 周邊（門牌、存原文、找提及、tag、lint、check） | 5／任務 | 0 | — | 0 | 中位、合計 | — |
