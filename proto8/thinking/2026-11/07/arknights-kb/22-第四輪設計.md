## 1. W3 批次執行器：hold 檔與批報告欄位

`bin/batch_run --class places|characters --list <檔> --workers N --batch <名>`，產出全在 `R4/<批>/`。

- **worker**：每個 worker 是一個子程序跑 `place_run`（人物走同一入口、`--class characters`）、不帶 `--commit`；runner（主程序）收完成回呼後 `git commit --only <節點夾> <有變的 names 檔>`，一任務一 commit。commit 由 runner 單程序循序做，不需要另一把鎖。
- **任務狀態**只有三種：`accepted`、`hold`、`failed`（程式錯，非閘停下；記 stderr 末 40 行，不重試）。
- `R4/<批>/hold/<slug>.json`：`{slug, class, gate: "allreject|regression|reference|lint|other", reason, questions:[題 id…], run_dir, at}`。runner 寫完就跑下一個。
- `R4/<批>/tasks.jsonl` 每任務一行：`{slug, class, status, worker, start, end, wall_s, steps:{S1..S6 秒}, calls, token_in, token_out, prod_index, full_index, source_bytes, lock_wait_s, pending_n}`。帳從 kernel ledger 依 instance id 切。
- `R4/<批>/report.json`（加一份白話 `report.md`）：`{batch, workers, n, accepted, hold, failed, wall_h, throughput_per_h, step_wall_median, prod_median, full_median, throttle_events:[{at, from, to}], lock_wait_total_s, commits, missing_slugs, stale_locks, manual_touches}`。`manual_touches` 由 runner 記：跑動期間有人手動改 `K/` 的跡象（git 工作樹出現非 runner 的改動）就 +1。

## 2. W5／W6 逐題 pending 與 judge

`R4/<批>/pending.jsonl`、`R4/closed.jsonl`、`R4/open.jsonl`（跨批累積）每行一題：

```json
{"qid": "<slug>#q<n>", "slug": "...", "class": "...", "mention": "歲", "at": [s, e],
 "context": "前後 60 字", "prod": ["<目標>"] , "ref": [], "ref_model": "sol",
 "judge": null, "state": "pending|closed_nolink|open_human|closed_link",
 "why_forced": "single_char|family|adjacent_name|sampled", "batch": "A", "ts": {...}}
```

- 不同意的題**不寫進** `links.json`，節點照接受；同意的照寫。
- **強制參考**（不抽樣）：單字名提及、命中 `kind: family` 的、緊貼另一個已知名字的。其餘照舊抽樣。
- 批末 `kb_judge`：judge 說不連 → `closed_nolink`；說連 → `open_human`（留人，不自動連）。`kb_judge reopen --target <節點>` 把候選含該節點的 closed 件改回 pending、下批重裁。
- 人裁的件（隊長批間看 `open_human`）裁完追加進 T1 真值；連的走 rm→add 補連結（`by: captain`）——這是批後人工，記 `post_manual`。

## 3. W7 四條手寫 T0 規則

在 kb_link 的 T0 段、規則池之前，依序：

1. **嵌在更長的名字裡**：提及所在位置若被「已知名字表」裡更長的一個名字蓋住（最長匹配），丟掉這個提及、記 `dropped: embedded_in:<長名>`。已知名字表＝`K/index/names/*.json` 全部名字與別名 ∪ W8 的 `K/index/titles.json`（lore 全部詞條標題，去掉括號註）。
2. **修飾語後綴**：提及緊接後綴表裡的字，判不連、記 `rule: suffix`。後綴表放 `K/index/suffix.json`，起始：`語系、語、文、人、式、風、製、產、腔、裔`；隊長可加。只對地名／派系名類候選生效（人名後接「人」常見，例「拉特蘭人」仍判不連；「斯卡蒂的」不受影響，因為「的」不在表）。
3. **姓氏段**：命中的別名是 `kind: family` → 送 T2，強制參考（照 t0guard）。
4. **緊貼另一個已知名字**：提及前後 0 字距內有另一個已知名字（用 1 的名字表）→ 送 T2，強制參考。

## 4. W10 規則 schema 與升降

`W/distill/rules.jsonl` 每行：

```json
{"id": "r-0001", "kind": "pattern|lexicon|fragment|suffix", "predicate": {...},
 "verdict": "link|nolink", "scope": "general|corpus:arknights",
 "status": "candidate|shadow|live", "stats": {"fires": 0, "right": 0, "wrong": 0,
 "by_tier": {"T1": [r, w], "T2": [r, w], "T3": [r, w]}, "window50": []},
 "tasks_seen": 0, "provenance": ["題 id 或 lore 連結 id"], "ts": {"created": "", "promoted": "", "demoted": ""}}
```

- `predicate` 宣告式、引擎可直接算：`pattern` 用 `{left: "...", right: "...", term: "..."}`（E3 左右字）；`lexicon` 用 `{term, in_table}`；`fragment` 用 `{fragment_of}`（E6）；`suffix` 用 `{suffix}`。
- 升 live：shadow 答 ≥20 題、≥5 個任務、對 T1∪T2∪T3 ≥95%、對 T1∪T2 錯 0。降回 shadow：最近 50 次答題裡被抓錯 ≥2。批末 `kb_rules promote` 自動跑，事件寫 `W/distill/events.jsonl`。
- live 規則在 S4 的 T0 段（第 3 節四條之後）先答；答了的題不送 terra，**但照舊進參考抽樣**（才抓得到錯）。
- 引擎 `W/kb_rules/` 不含任何 arknights 字；arknights 的知識只在 `K/index/*` 與 `scope: corpus:arknights` 的規則。
