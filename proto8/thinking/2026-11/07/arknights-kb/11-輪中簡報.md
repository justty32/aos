## 0. 題目與規矩

**題目**：第二輪（把 arknights 敘事庫一個地點一個地點存進 aos 知識庫，每個地點做完停下審視、把重複的事工具化）已做完 3 個地點。請規劃**後半**（地點 4 起，目標總共 8～10 個地點收輪），回答 §6 的三個問題。

**規矩**：
- 大方向是使用者的；你在他已定的路上定細節、寫成結論。要帶給他的只有兩種：新想法跟既有原則的**衝突**（哪條、衝突在哪、各自後果）、原則推不出的**方向題**（選項＋後果＋推薦）。使用者在外到 16:30、不問問題，方向題暫照推薦。
- KISS 是最高原則也是最後原則；每層只管自己的結果與錯誤；proto8 不做舊版相容。
- 分工：fable（你）只做頂層規劃；opus 隊長據此補全成施工設計、主導審查；gpt（codex `gpt-6.1-sol`，同時最多一個）只照圖施工、寫文件、雜活，不做設計判斷。你**不派子 agent**、不改檔、不 commit。
- 成本三維：token（in／out）、calls、秒（含排隊與本機載入）。價目未知，**不換算金額**（隊長代定）。
- 本機 LM Studio 一次只能載入一個模型（使用者硬規矩）。
- 產出：一份 markdown，第一行一句話標題；含白話總結、對 §6 三題的回答、後半的階段與成功判準、要驗的假設、衝突與方向題。長度 8～12 KB。

## 4. 反向傳播式改進紀錄（使用者特別關注）

每次都是：審視時看數字或 LLM 原始回覆 → 找到浪費 → 改一個定義 → 把呼叫它／被它呼叫的定義一起改 → 已做地點重跑 `--check` → 比前後。

1. **B2→B3：namer 出熱路徑。**看到 namer 佔 1.02 萬 token，因為「還不存在的目標也要先取英文名」。改成 pending 連結指 lore 原檔、建節點時才命名。牽動 kb_link、kb_name、kb_lint2、place_run --check。婆山鎮 15,848→6,635。
2. **B2→B3：別名學習。**linker 把「煮傘居士」當新人物 → 加 `alias_of` 寫回別名表，下次變規則命中。
3. **B3→B4：候選剪枝與去重。**看 linker 原始回覆，22 題約四成白工（被類別白名單丟掉、按類別可定、同名重問）。改 kb_mentions 先剪枝、同名一問；連結改一目標一條＋spans；places 可連。牽動 kb_mentions、kb_link、linker 提示、kb_lint2、place_run --check。切爾諾伯格 8,134→3,797、19.96→7.52 秒。
4. **B3 選級規則改三維。**terra 一致率過但秒數 2.3 倍，「按級序選便宜的」沒實測支撐 → 每級跑 3 次、一致率 ≥90% 合格、token 與秒都 ≤1.2 倍才降（本機秒放寬 3 倍）。
5. **失敗也記**：B4 婆山鎮第一趟 linker 把已知別名又當新人物，被驗證擋下，4,370 token 白花，提示補一句後過。

現在這些全是**隊長人工**在做（看數字、找浪費、寫任務書給 codex、量前後）。

## 7. 同批頂層設計摘要（另一帳號 aos-b0 做的，已定或在跑）

**evolve-design（已完成，使用者已裁五題）**：
- 每個函數兩本帳：**自稱**（定義旁 `_metainfo.json`，估值，可寫公式）與**他見**（叫它的那層在自己 stack 記的 `observed.jsonl`，實測）。兩本不互寫；跑的時候誰都不改 `_metainfo.json`。
- 成本是任意 JSON，aos 只定三個通用 key：`token{in,out,cached}`、`counter_calls`、`time_ms`；可寫公式，以語言名當 key（`cal` 四則＋min/max 起步，`lua`／`py`／`aos` 以後接）。
- 帳沿呼叫樹往上收：每行「我叫了誰」寫明對方的帳在哪；子 agent 收掉前先抄帳；腳本用 `lib/observed.py` 記帳，不記就是葉。
- 工具：`measure`（跑 case 夾、量成本、過門＝比對器打分 ≥ min_score）、`promote`（換上／退回，正在用就拒）、`metainfo_check`（評估：實測／估值的落差比，0.8～1.25 算準）、裁判比對器（高階模型當語意裁判）。
- **審視者**是普通 agent：一輪七步——量、挑最貴的 agent 步、在整棵定義副本上依序試 downgrade→fix（輸出由輸入決定就寫成腳本）→split（腳本前處理＋更小 LLM 步）、整個 case 重量過門、寫 `review.json`、過門又變便宜就自動換上並開 watch 窗、建議。一輪只改一個函數。
- 使用者裁定：自動換、退步自動退回，但容忍短暫退步（品質一次不合格就退；成本看換上後三個地點平均，貴一成以上才退）；審視者前三個地點只開處方（fix／split 交 gpt 施工），之後放手自己寫程式；換模型第一天就全自動；語意錯先用高階模型當裁判、人抽查為輔；`_metainfo` 的估時與逾時拆開。
- 想法 12 的落點：審視者也是有兩本帳的函數，有「審視 case」（好答案取過去被轉正的 review），由第二隻審視者（同一份定義的另一實例）改它；只疊兩層。未裁暫照推薦：審視者在「最近 3 輪改進花的比省的多」時被審視。
- 落地 17 步（aos 本體＋試驗場改接最後一步），目前**無人施工**。

**tool-evolve（已完成，方向題未裁照推薦）**：shell 階段不寫欄位、從工具清單推（有任意執行工具＝開放；bash 關進沙箱＝謹慎；沒有＝專屬）；`thought`／`agents`／`self_tools` 也算任意執行，所以協調型 agent 永遠開放、只有窄領域專精 agent 到得了專屬工具期；bash 每次指令記一行帳，審視者看帳把重複用法做成專屬工具、只准往緊收；確定性用 measure 的重跑樣本分三層報（腳本步逐字、LLM 步自洽按模型分開記、整地點重跑幾檔相同），「自洽」與「跟聰明模型一致」分開。試驗場現況：bash 在第二輪只有基準用過，linker 只有 read。

**kb-scale、kernel-nest**：只有簡報、結論未到（全庫規模的命名衝突／版本／tag／連結節制／給人看那層；kernel 嵌套排程與跨層記帳）。**agent-diversity**（不同質 agent 設計）、**arknights-kb-audit**（第二輪資料抽查）已發任務書、未到。這幾題你只需寫「交給 X」帶過。
