## 1. 這個包第三輪的目標

一句話：**kb-kit 是試驗場活定義的「下游產物」，不是第二份原始碼**。活定義（`$AOS_WS/defs/`，ad-5）是唯一上游，所有改動都在上游做、在上游跑；kit 是把「這一段真的用到的定義」抽出來、把 arknights 專屬值搬進 `config.json`、附零模型證明與一頁說明的**打包結果**。使用者 ad-5 備註說的「定期將定義提取出來」就是這個節奏——「定期」在第三輪定為**主題 A 每段收尾（S0、S2 之後）各抽一次**，不在段中追著活定義跑；這跟使用者說「喘口氣＝各線收拾同步」是同一件事：kit 是收拾時順手產出的，不是另一條施工線。

怎麼避免兩份漂移：只有一條規則——**kit 裡的定義資料夾不准手改**。抽取是腳本，`kit.json` 記上游 commit 與每份定義的來源路徑；kit 要改什麼，回上游改、重抽。kit 自己擁有的只有「殼」：`kit.py`、`prove.py`、`prepare`、`config.json` 的欄位表、README、假語料。殼可以手改，但殼裡不准有建庫邏輯——有邏輯就是上游的東西跑錯地方了。ks-3「輪次邊界跑過期檢查」正好可以多查一項：kit 落後上游幾個 commit、哪幾份定義 diff 不為零。

跟 aos 本體（proto8）的關係：**第三輪不收進 proto8**，kit 留在試驗場 `export/`。方向是「有一天它變成 proto8 的範本／標準庫之一」（AGENTS.md 說 agent 範本是 Python／sh 放在 proto8），但條件要全達才談，不定日期：(a) 真的有第二個語料從 kit 跑過，不是假語料；(b) 殼連續兩次重抽都不用改 `config.json` 欄位表（代表欄位穩了）；(c) kit 只依賴 proto8 公開的工具與契約（aos-agent、memory、kernel），不依賴試驗場獨有的補丁；(d) 使用者裁定的 ltn-（lift-to-norms）若已定了「試驗場→proto8」的提升程序，照它走（假設 H4）。四條沒齊，kit 就只是試驗場的出口。

## 2. 泛化的邊界：第三輪拆什麼、留什麼

原則照 KISS：**只拆「第三輪自己會把它弄壞」的假設；沒有第二個語料就不猜第二個語料長什麼樣**。使用者說「拆另一個遊戲時可以運用」，意思是到時候拿得出來、改 config 就能跑，不是現在就把形狀抽象掉。

### 2.1 第三輪就拆

| # | 假設 | 為什麼現在拆 | 拆成什麼 |
|---|---|---|---|
| G1 | kit 是一次性複製的副本 | 主題 A 一開工活定義就變（路由表、三道閘、review.json 新欄位），副本第一天就過期 | 抽取腳本＋`kit.json` 記來源 commit；S0、S2 後各重抽一次；drift 檢查列進過期檢查 |
| G2 | 哪些定義該進 kit 沒有規則（46 份裡挑了 19 份，26 份第二輪呼叫數 0） | 沒規則就會手挑，手挑就會漂 | 選擇規則＝「這段呼叫數 > 0 的定義」＋它們引用到的閉包（用 te-2 的 observed 紀錄與 14b 的 77 條引用；假設 H2、H9）；呼叫數 0 的不進，這也是給想法 16「複雜性」的第一個實用：死枝不打包 |

### 2.2 留到真有第二個語料再拆

- 「語料根／類別／檔名.md」三層形狀：第二個語料若也是這形狀就永遠不用拆；拆了只是替想像中的語料付錢。
- 中文標題規則：第二個語料若也是中文遊戲敘事，一樣不用拆。`chinese_title_rules` 已在 config，夠了。
- 單一入口類別（`place_category`）：S2 做人物時上游若被迫改成多類別入口（主題 A 假設 A8），kit 重抽自然跟上；上游沒改，kit 就不改。
- 非 Git 語料、非 md 格式、英文語料、`names`／`compound_seeds` 種子表怎麼給：全部不碰。
- 模型供應商切換：config 已有別名與回傳前綴兩層，不再加。

### 2.3 第二個語料從哪來（方向題，推薦見 §5）

| 來源 | 能驗什麼 | 代價 | 看法 |
|---|---|---|---|
| 真的另一個遊戲語料 | 形狀、語言、類別全部真驗；這才是使用者說的用途 | 要使用者選語料、說明形狀、給路徑；不是隊長能決定的 | 第三輪不做，列成方向題 D1 給使用者；第四輪以後 |

| 合成語料 | 只能驗殼與接線，已經做過（三份假語料、換類別的第二份證明） | 再做一次什麼都不多證明 | 不再加 |

## 3. 驗收：第三輪對 kit 的判準

1. **抽取是腳本、重抽兩次都過**：從試驗場活定義一鍵重抽，`kit.json` 記上游 commit；S0 後與 S2 後各抽一次，每次 `prove.py` 的主證明與 `--alternate` 證明都零錯誤（是／否）。
2. **漂移 0**：收輪時 kit 定義資料夾對上游的 diff，除了 config 代入的標記之外為 0；kit 定義資料夾手改次數 0（看 git log，是／否）。
3. **自宿主 1 地**：用 kit `prepare` 的執行副本重跑地點 8，`--check` 逐字同、linker 輸出對試驗場接受快照 diff 0，整次 LLM token ≤ 第二輪蒼白海的 3,448 token 的 1.2 倍（數字）。
4. **專屬值 0 處**：`prove.py` 的 grep 清單（語料路徑、五個類別名、優先序、標題規則字面值）在定義資料夾命中 0 處；主題 A 新增的路由表與閘門檻都是 config 或資料檔，不在 prompt 裡（數字 0）。
5. **說明一頁、使用者看得懂**：README 保持一頁，「換語料改哪幾樣」一節列的項目數 ≤ 5；使用者看完能說出下一個遊戲要改哪三樣（他點頭才算過；te-5 備註說人類可理解性要他評）。

## 4. 成本與排程

插在主題 A 的段邊界，不佔段內時間：

| 時點 | 做什麼 | 成本 |
|---|---|---|
| S0 收尾 | 第一次重抽（抽取腳本寫好、G2 選擇規則、G3 grep 清單）；自宿主跑地點 8（S0 本來就要回放 8 地，拿它的接受快照來比） | 腳本工：gpt 系照圖施工、Claude 審，約半個工作段；LLM：一地份 ≈ 3,500 token、約 10 秒 |
| S1 第 16 地 check-in（主題 A 的提前收點） | 只跑 drift 檢查，不重抽；落後就記，不停 S1 | 0 LLM，一分鐘 |
| S2 收尾 | 第二次重抽（人物類讓上游改了什麼，kit 自然跟上）；跑 prove 兩條；更新 README「換語料改哪幾樣」 | 腳本工約四分之一工作段；0 LLM |

上限：整輪 kit 這條線 LLM token ≤ 第三輪生產帳的 2%、腳本工 ≤ 一個工作段；**永遠不擋 S1／S2**——kit 落後就寫進 review.json 下一段收尾補，不為它停主線。這跟主題 A 的試驗／正式比（判準 7 ≤ 3）相容：自宿主那一地算進 full，不進 prod。

## 5. 衝突、方向題、不做的事

### 5.1 衝突

- **C1 ad-5「定義樹放 `$AOS_WS/defs/`」vs kit 有自己的殼程式**。兩處有程式就會兩處改。推薦：殼只准做「複製、代入標記、跑證明」三件事，殼裡出現建庫邏輯就算判準 2 不過。
- **C2 使用者「拆另一個遊戲時可以運用」vs KISS 不預先通用化**。推薦：「可運用」定義為「改 config 跑得起、跑不起時知道要改上游哪份定義」，不是「任何形狀都吃」。形狀的泛化等第二個語料。
- **C3 主題 A 在段內快速改 linker（路由表、閘）vs kit 不想追移動靶**。推薦：只在段邊界抽（§4），段內漂移是正常的、不算失敗。
- **C4 想法 13「期待自我演化出一大堆定義」vs G2 只打包呼叫數 > 0 的**。演化出來但沒用到的定義仍留在上游、不刪；kit 不收而已。推薦：kit.json 另列「上游有、本段未用」的清單，讓使用者看得到演化出了什麼、哪些還沒派上用場。
- **C5 裁定「系統設計由 Claude 系、gpt 系照圖施工」**：抽取腳本與 grep 清單是施工，給 gpt 系；選擇規則與判準是設計，本檔定、Claude 審。不衝突，寫明分工。

### 5.2 方向題（附推薦）

- **D1 第二個語料**：真的另一個遊戲（第四輪以後，要使用者說哪個、什麼形狀、放哪、是不是 Git、是不是中文）／arknights 人物類（**推薦，第三輪免費帶到**）／合成（不再做）。給使用者的問法：「下一個遊戲心裡有人選了嗎？語料是不是也是一堆 md 按類別分夾？」沒答案前不動形狀。
- **D2 kit 放哪**：留試驗場 `export/`（**推薦**）／現在就搬進 aos repo。搬的條件見 §1 四條。
- **D3 模型路徑驗多深**：只驗接線（現狀）／自宿主一地（**推薦**，便宜）／自宿主整段。
- **D4 哪些定義進 kit**：全 46 份／呼叫數 > 0 加引用閉包（**推薦**）／手挑。
- **D5 要不要替 kit 開一隻 agent 維護它**：不要（**推薦**）。kit 是腳本產物，開 agent 是湊數（ad-1、「方向，不湊數」）。

### 5.3 不做

不搬進 proto8；不抽象三層形狀、不加格式外掛、不做英文或非 Git 語料；不自己找或合成第二個遊戲語料；不替 kit 寫第二套 linker 或 prompt；不在段內重抽；不驗 kit 的別名學習與審視者路徑的語意品質（上游主題 A 管）；不給 kit 專屬 agent；不把 `place_*` 改名成 `entity_*`，除非 S2 上游先改；不重寫殼。
