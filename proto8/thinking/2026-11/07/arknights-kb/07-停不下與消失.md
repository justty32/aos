## 根因

- **#15／#11**：`proto8/py/daemon_ctl/entry.py` 認身體種類時，只有**陣列** `["aos-loop", 設定]` 認成 loop；**帶 `argv` 的物件一律當一次性 exec**（約 100～102 行），即使 argv 就是 aos-loop。exec 型照 [N-54](../../../../docs/NORMS/04-基礎設施-loop與daemon/03-N-54.md)「exec 型只有跑和拔」，`daemon_ctl/ctl.py:21` 與 daemon `windows.cpp:125` 都擋 stop／sleep。`--limits` 無關（只加資料，不包殼），#11 當初以為是 limits 包成 exec，猜錯。
- **#16 列消失**：同一個原因的連帶結果。exec 型結束不論結束碼都下表（[N-28](../../../../docs/NORMS/04-基礎設施-loop與daemon/02-N-28.md) 第 68 行「exec 型…照舊下表」、`tend.cpp:172` 只對 loop 留失敗列）。陣列形的 agent 腦失敗會照 aos-agent 文件留 `stopped`＋reason。
- **#16 提示說退 0**：`proto8/cmd/aos-agent/aos_agent/hints.py` 的 `off_table` 只看「表上沒這列」，句子卻寫死 `its body exited 0`；`common.py` 的 `InstanceMissing` 也寫死 `it exited 0`。真正的結束碼 1 有記對（aos-loop `window.cpp:249`、daemon log）。

## 判斷

- **提示寫死退 0＝bug、不牽涉方向**：表上沒列推不出結束碼，句子講了它不知道的事。已修（下節）。
- **列消失＝照設計**：一次性 proc 結束下表是 N-28 明文；使用者 11-07 對類似題（os-impl 09）選過維持現狀。真正該問的是上游：為什麼這個 agent 被當成一次性。
- **物件形 body 被當 exec＝介面設計題，待裁**：同一個 argv 換個包法行為就不同，是坑；但「物件形要不要也認成 loop」是在改身體分類規則，照鐵律 5 交使用者。

## 使用者裁定與落實（11-07）

- **原話（逐字）**：「hmmm，果然不可以用陣列形或物件形來分，還是得去看關鍵的interval_ms，看有沒有這個key」→「等等，不過有個問題：argv:[aos-loop loop.json]，我用aos-exec執行，這等同於我變成了aos-loop，然後去跑loop.json設定。在變成loop之前，我確實就是一次性程式沒錯」→ 選 **B：daemon 不分類**。下表規則選項框選「失敗留表，照 opus 選的」，並同意翻 os-impl 09 A 與 N-54「exec就是只有執行中和拔掉」（**11-07 使用者確認翻案（B 落實時）**）。
- **為什麼不看 interval_ms**：daemon 看到的是一次性程式，它 exec 成 aos-loop 才變 loop；daemon 去翻 loop.json 就是上層認得下層（C-52）。
- **設計**：寫法只決定「怎麼起」，起來後所有列一視同仁。stop＝寫該列的公開 ctl（`<stack>/ctl.json`，小格有 daemon 寫的 loop.json 就照它的 `ctl` 名），等它自己退，沒人讀就等它自然結束，不送 SIGTERM；sleep＝送 SIGTERM 留 `sleeping`（ctl 沒有 sleep 指令）；任何列都能 start／wake。daemon_ctl 不再認 `["aos-loop", 設定]`。
- **下表規則**：退 0 下表；退非 0（含訊號、起不來）留 `stopped`＋`reason`；stop／sleep 途中退的留 stopped／sleeping；daemon 收工時還活著的留 `sleeping`、下次開門自動叫醒（一次性程式會重跑一次）；收工時正在 stop 的照 stop 留 `stopped`（隊長審 diff 時補：codex 版本會把它也變成 sleeping）。adopt 接回的拿不到結束碼，照舊下表。
- **改的檔**：daemon C++（tend、reconcile、adopt、stuck、windows、mailbox、procs、child）、daemon_ctl（entry、ctl）、aos-daemon-ctl help、aos-agent（hints、common、ctl/phase 與文件）、N-28／N-54／N-17、aos-daemon docs、cmd docs 03／04、aos-loop docs/02、knowledge；新增 `impls/aos-daemon/tests/`（test_ctl 7 項、test_lifecycle 17 項）。清單與 31 處 once 盤點見 [08](08-daemon不分類實作結果.md)。
- **實測**：四種身體（一次性腳本、陣列 aos-loop、物件 argv aos-loop、最小 fsm）× 四種情況（stop、sleep＋wake、自然退 0、出錯退 7）共 16 格全部符合：stop 留 stopped、sleep 留 sleeping 後 wake 回 running、退 0 下表、退 7 留 stopped＋reason。build 過，兩支測試全過（隊長修收工那處後重跑）。
- **代定**：sleep 不寫 ctl，照收工送 SIGTERM；表上多 `launch`（可重放的入口與參數，好讓 adopt 不必猜型別）與 stopping 時的 `stop_mode`；保留「直接寫 loop 設定只有 exec 時補 `interval_ms: 0`」（只影響起法）。
