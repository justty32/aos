## 一、隊長對 12 的補全與修正

1. **promote 用 git**（12 §1.2）：試驗場本來就一個 git。候選定義在 `reviews/<輪>/` 的工作副本裡跑（`git worktree` 不用——使用者定 repo 只有 main；試驗場也照此，副本＝複製 `defs/` 到 `reviews/<輪>/defs/`），過門後 codex 把副本內容拷回 `defs/` 並 commit，commit 訊息第一行寫 `promote <定義> <review id>`；退回＝`git revert` 那個 commit。不另寫 promote 工具。
2. **自稱 `_metainfo.json` 的 key 照 evolve-design 命名**：`cost.token.{in,out}`、`cost.counter_calls`、`cost.time_ms`（毫秒，不再用 `time_s`）、`timeout_ms` 另放。B4 已有的 `cost.calls`／`time_s` 這四個定義一起改（proto8 不做相容）。其他定義不動，收輪時再統一。
3. **他見不回寫定義夾**：現有 `defs/*/_observed.json`（meta_observe 寫的）搬到 `runs/2/observed/<定義>.json`，`defs/` 只留自稱（evolve-design 衝突 2）。
4. **review.json 格式**（地點 4 起每地點一份，`runs/2/places/<slug>/review.json`；`review.md` 改成由它生成，隊長只填「為什麼」）：

```json
{"schema": "ak_review/1", "place": "longmen", "reviewed_at": "2026-11-07T08:00:00.000Z",
 "by": "captain|reviewer:<run id>",
 "measured": {"steps": [{"step": "S4", "def": "linker", "model": "terra", "token": {"in": 4007, "out": 473}, "counter_calls": 1, "time_ms": 18023}],
              "total": {"token": {"in": 0, "out": 0}, "counter_calls": 1, "time_ms": 0},
              "vs_prev": {"place": "qieernuoboge-b4", "token_ratio": 1.18, "time_ratio": 2.34},
              "claim_check": [{"def": "linker", "key": "/cost/token/in", "claimed": 4007, "observed": 4007, "ratio": 1.0, "verdict": "close"}]},
 "target": {"def": "linker", "why": "only LLM step; 100% of tokens"},
 "move": "downgrade|fix|split|none",
 "prescription": "one paragraph",
 "dirty": ["kb_link", "kb_lint2"],
 "expected": {"token_ratio": 0.6},
 "decision": "approved|rejected|auto",
 "spent": {"token": {"in": 0, "out": 0}, "counter_calls": 0, "time_ms": 0},
 "after": null}
```

`after` 在下一個地點跑完後回填（實際省多少），`spent` 是這次審視本身花的（隊長人工那幾次填 null）。審視者自己的帳另追加 `runs/2/reviews.jsonl`，每行＝一份 review.json 的 `{by, spent, decision, expected, after}`——這就是「改進本身」的他見。

5. **階梯新規則**（12 C1、代定 16、17）：只在定義或模型改動後跑；現行級 1 次當對照、候選級 3 次；失敗級可跳；本機秒數欄一律寫 `time_ms_incl_load`（抽查指出 B4 表欄名易誤讀）。

## 二、抽查三條的處理（先修，B5 第一件）

1. **「博士」漏連（`kb_mentions` 146～200 行）**：名字清單不收 `lore/evidence/` 下的檔名；最長比對要在「可連類別」過濾**之後**做——被過濾掉的長命中不整段跳過，退回去試同位置較短的名字。修完三個已做地點 `place_run --check` 會有差（切爾諾伯格多出 [20,22]「博士」），照新工具重建三地點快照，差異逐條列進 B5 報告。這是一次反向傳播：牽動 kb_mentions → kb_link（題目變）→ linker（多一題或規則命中）→ kb_lint2 → place_run --check 基準。
2. **「煮傘居士」兩表不一致**：`kb_name` 先查別名表，名字是別人的別名就回那個實體、不給 slug；刪 `zhu-san-ju-shi`。加一條 lint：名字表裡任何名字都不能同時是別名表的別名。
3. **命名規則**（代定 19；方向題 E 帶回）：slug 由腳本照規則算，不再問 LLM——
   - 中文名轉**無聲調拼音、整詞連寫**（`longmen`、`qieernuoboge`）；地名的通名後綴（固定表：鎮、城、山、谷、郡、區、號、峰、港、島、灣、村）前加連字號（`poshan-zhen`）；名字含「／」的各段用底線接（`tala_shenchi`）；非漢字照原樣轉小寫、非 `[a-z0-9]` 換連字號。
   - **同類別內撞名**：撞到的每一個都改用帶聲調數字的拼音（黎 `li2`、礫 `li4`；令 `ling4`、澪 `ling2`）；仍撞就照 lore 檔名排序加 `-2`、`-3`。不同類別不算撞（路徑有類別）。
   - 不用英譯、不用官方英文名（那是方向題 E）。
   - 拼音用 `pypinyin`，裝在試驗場自己的 venv（`~/code/playground-ak/.venv`），不動系統 Python。
   - 已建三個節點照新規則重算（多半不變）；名字表的來源欄記 `rule:pinyin/1`。
   - **後果**：namer agent 出熱路徑、標 sleep（不刪定義）——這本身就是一次「fix」：輸出由輸入完全決定的 LLM 步換成腳本。agent 數暫時少一隻，由 §四補。
4. **小事**：別名表加「近衛局→龍門近衛局」「陳暉潔→陳」（最長比對會讓 span 蓋住整個「陳暉潔」）；`by` 統一成字串（`rule`／`llm:<級>`），混合來源用 `spans[].by`；pending 的 `to` **維持指 lore 原檔**（`lore:characters/夕.md`）——這是 B3 刻意改的（namer 出熱路徑），10 的寫法作廢，本檔取代；目標節點建好後由回填腳本翻成 `ak/…`＋`ok`（§三 B7）。
