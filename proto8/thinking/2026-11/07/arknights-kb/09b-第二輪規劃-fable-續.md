## 三、優先序與階段

- **階段 0（前提）**：修 usage 回傳與逐封留帳、知識庫認 `#` 路徑；定審視紀錄模板與步驟表格式；用 sol 手動跑婆山鎮量基準。→ 婆山鎮 commit、每封請求的 in／out／秒都抓得到。
- **階段 1（地點 1～3，打通，sol 為主）**：照步驟表做、每地點審視；預期長出存原文、比名字、連結操作、填 tag 的腳本。→ 三篇紀錄齊、步驟表每步標明 LLM 或腳本、非 LLM 步驟錯誤 0。
- **階段 2（地點 4～8，降級與工具化）**：過關的步驟逐級降到 luna 再到本機小模型；history 控制修好；試審視 agent；agent 數開始長。→ 連三個地點沒叫 sol、步驟表 ≥70% 是腳本、每節點 token 比地點 1 少一半。
- **階段 3（收尾）**：拿地點 1 連出去的一個人物條目試結構能否原樣套到別的類別，只做一條；整理輪末交付。地點做到 8～10 個就收，不做滿 41。

## 四、要驗的假設

- H1 原文照存放得進一葉（≤8,000 bytes）。驗：量 places 41 檔。成立→不切；不成立→同節點多葉，仍逐字。
- H2 用 lore 檔名精確比對就抓到大多數提及、誤判少。驗：地點 1、2 人工對照。成立→名字比對全腳本；不成立→加別名表，仍錯才給 LLM 裁。
- H3 照原文存之後，一個節點的 LLM 呼叫只剩「裁連結」。驗：步驟表每步記 calls。不成立→還在用 LLM 的步驟進審視環節工具化。
- H4 每地點新實例能把單次請求壓在 15 KB 內。驗：抓請求大小。不成立→history 控制提前到階段 1。
- H5 `thought` 真的省上下文（§8b 沒測過）。驗：同一地點開／關各跑一次比 token。不成立→改子 agent 分派，記進不足清單。
- H6 luna 裁連結跟 sol 一樣準。驗：地點 2～3 兩級各跑一次比對。不成立→找出錯的題型做成規則或別名。
- H7 機械抽出的 tag 夠問答 agent 用。驗：10 題先用 tag 縮範圍再答。不成立→列缺的 tag 種類，再議要不要 LLM 貼。
- H8 第五個地點起審視能交給 gpt agent 照模板跑。驗：opus 審它的紀錄有沒有漏。不成立→opus 續做，記差在哪。
- H9 被提到的目標多半還沒進樹。驗：地點 1～3 數懸空比例。成立→「待接」機制必要；不成立→可省。

## 五、成功判準（本輪結束條件）

1. 地點 ≥8 個 commit，每個都有審視紀錄且含前後數字（100%）。
2. 每節點總 token：地點 5 時 ≤1.2 萬（參考 §4 新實例單題 1.04 萬），輪末 ≤0.6 萬；非裁量步驟 LLM 呼叫 0。
3. 步驟表 ≥70% 是腳本／工具；原文葉與規則連結重跑逐字一致 100%（LLM 裁的連結差異只記不擋）。
4. 最後三個地點零 sol 呼叫，至少一步跑在本機小模型。
5. opus 抽查：原文一字不差 100%、連結指對 ≥90%、懸空全標「待接」。
6. LLM 請求 ≥95% 抓得到 in／out／秒；新定義 100% 帶自我宣稱 metainfo，熱路徑定義有觀測紀錄。
7. 活躍且過不同質檢查的 agent 有清單、各有白話說明；零 prompt 複製品。
8. 機器負載 <80%（README）。

提前結束：某前提修補變成大改寫（估超過一個地點的工時），停下寫報告交使用者。

## 六、修 aos 本體的排序

- **前提（階段 0）**：`aos-llm ask` 回 usage、kernel 逐封留 in／out／時間（#3／#18 與 §7 丟 usage）；知識庫認「路徑 `#` JSON 路徑」並提供找目標／建立／解除／查懸空（想法 1）。
- **階段 1 內**：#19 每題工具呼叫上限（降到小模型前的保險）；#12／#22 history 不帶／截斷（成本主因，階段 2 前要好）。
- **階段 2 內**：#8 逐 agent 記帳（他者觀測要分得出誰）；#13 別名／tag 索引分片。
- **延後**：#4（slug 表已繞過）、#1／#2／#17（體驗問題）；kernel 文件「缺 usage 記 null」與實作記 0 不一致，順手改文件。

## 七、要帶給使用者的衝突／方向題

1. **一百個 agent vs. 有機長出。** 想法 8 要一百個，裁定 6 與想法 7 要自然長。照 8～10 個地點、早期每地點約 5～8 個新角色估，輪末可能只有 40～60 個過檢查的。建議只交真數字、不湊；請裁一百是硬目標還是方向。
2. **想法 1 的 JSON 路徑 vs. 裁定 1 的原文照存。** 原文是一整段文字，`#` 後的 JSON 路徑指不進文字中的某句；要能指到「原文第幾段」，得把原文存成逐段陣列（內容仍逐字，只是容器變結構）。請裁可不可以；不可以就只連到節點、不連到段。
3. **成本單位。** 無價目算不出美金，本輪 metainfo 用 token／calls／秒，日後接價目再換算。請確認。
4. **降級階梯。** 沒有 terra，用 sol → luna → 本機小模型（隊長附註）。請確認。

## 八、輪末要交給下一次總覽的東西

每地點審視紀錄（含前後數字）；步驟表終版（每步：LLM 或腳本、模型級、成本）；成本曲線（地點序 × token／calls／秒）；定義清冊（工具／agent／kernel，各帶 metainfo、白話說明、不同質檢查結果、被叫次數）；aos 修了什麼、延後什麼、新挖到的不足；九條假設的裁決；七節四題的使用者裁定；給下一輪的建議（下一類別從哪開始、哪些步驟還在 LLM）。
