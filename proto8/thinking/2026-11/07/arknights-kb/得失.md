## 第 0 輪：開線與盤點（11-07 上午）

- **做了什麼**：收使用者原話開線；派 gpt 盤點語料、opus 盤點 aos 能力並架試驗場 `~/code/playground-ak/`。
- **得到什麼**：兩份盤點；試驗場三層樹起得來，gpt 腦（`gpt-luna-low`）叫 clock、查 memory 都答對；kernel 轉交用十來行的轉交函數就能接（1.8～3.3 秒）。
- **失去／踩到什麼**：第一次換 gpt 就停在 `stopped`（範本端點硬要 `LITELLM_KEY`，給假值才過）；轉交後上層 kernel 的 token 帳全是 0；中文詞條名不能當節點名；本機 clone 拿不到 `corpus/`；盤點兩份共吃掉不少 Claude 額度（aos 那份是 opus 跑的）。
- **下輪怎麼改**：盤點類雜活之後一律給 codex；先讓 codex 照已裁圖紙做 `memory_write`（W1～W4），同時 fable 出整體設計，第一輪實跑等兩者都好。

## 第 1 輪：places 40 檔兩趟（11-07 上午～中午，codex 施工＋實跑，gpt-luna-low）

- **做了什麼**：試驗場長出 16 個定義（`~/code/playground-ak/defs/`，總覽 `defs/INDEX.md`）：取路徑 `ak_slug`、驗格式 `kb_lint`、索引 `kb_index`、writer 定義、`bash_logged`、派工 `batch`、報告 `round_report`、三台 kernel／daemon 設定與轉交 `llm_forward` 等；places 兩趟各 40 節、8 個批次 commit（[04](04-第一輪實跑.md)）。
- **得到什麼**：整條「腳本派工 → gpt 寫一節 → lint 閘 → git commit」跑通，壞批不 commit、照 `git ls-files` 重派就自動補齊；lint 首次通過 96%；bash 一次都沒被叫（讀一篇寫一節用 read／write 就夠）。
- **失去／踩到什麼**：①**token 太貴**：每節約 4.7 萬 token，全庫一趟外推約 6800 萬——主因是 agent 每次請求都帶整份累積歷史，同樣 10 節第二批比第一批貴 2.24 倍；②**重跑逐字相同 0%**；③**LLM 寫來源路徑會錯**：已給逐字清單仍 3／10 寫錯，整批被擋重派；④kernel 只能按工作區記帳、`queue.json` 看不到在飛數、帶 limits 掛的 agent 不能 stop／sleep。不足 #8～#14。
- **下輪怎麼改**（隊長定，見代定 6）：把 LLM 的活再縮窄——**來源、標題、段名等能算的欄位全由腳本填**，LLM 只寫本文；**每節一個乾淨上下文**（不帶前面的歷史）；請求溫度設 0 再量一次重跑相同率；然後才擴到 factions／characters 與 memory_write。
