## 0. 一頁結論

- **骨架**：A0 建設（無 LLM）→ A 剩 20 地（前 8 循序當基準、後 12 並行 4）→ B 人物 205 人（每三人取一，並行 4）→ C 其餘 406 人（B 過閘才跑）；批末自動跑 judge、規則升降、E3 重訓、審視者，隊長只在批間看。

## 1. 零人工吞吐：定義與量法

**定義**：一批從 `bin/batch_run` 起跑到批報告寫完，隊長／使用者對庫內容或任務流向的動作數（`manual_touches`）＝0。啟動指令本身不算；批末看 hold／pending、抽查、開處方是「批後人工」，另計 `post_manual`（每百任務幾件），只記趨勢、不擋線。

| 第三輪隊長手動（brief §F） | 第四輪 | 擋不擋線 |
|---|---|---|
| 判停下對不對 | 閘停下→寫 `R4/hold/<slug>.json`（原因、證據、題紀錄），runner 跑下一個 | 不擋；批後隊長看，hold 率是指標 |
| 移錯連 | 參考閘逐題：生產與參考不同意→該連結進 `pending`、**不寫進 links.json**，節點照接受；批末 judge 自動收一半（§5） | 不擋；pending 待人件數是指標 |
| 開處方 | 仍是隊長，只在批間開；after 照舊腳本填 | 不擋 |
| 標 top1 | 機械：審視者疑點第一名命中「該任務的 hold／pending／規則降級事件」就算中；不再人標 | 不擋 |
| 抽查 | 批後 10 任務（系統抽，固定種子），結果寫 `post_manual` | 不擋 |
| agents new | 全自動（ad-3 前三地已過）；退休仍隊長按 | 不擋 |

**量法**：吞吐＝接受任務數÷批 wall 小時；hold 率＝hold÷任務；pending 待人率＝批末仍待人的 pending 題÷任務；品質用 qa（sol 抽 10 條接受連結／批）與批後抽查兩個數。數字門檻在 §7。

## 2. 提速與多 agent 同時寫庫

**並行數 4**：等於隊 kernel slots；S4 佔 wall 99%，多開只在 kernel 排隊。不動總機 6／隊 4、不動每日 3000、不動 watch（80% 砍半、不加回）；只在批報告記 throttle 次數與期間，若一批被砍半 >1 次下批再議。

**共用物處理**（照 20 §4 表）：

| 共用物 | 做法 |
|---|---|
| `K/index/names/<類>.json` | `kb_slug.write_names` 的讀→改→寫包進 aos-lock（鎖 `K/index/names/` 目錄，沿用 `memory_write/locking.py`）；格式不變，別名表不動 |
| 任務節點 `K/<類>/<slug>/` | S2 store、S4 links.json **改走 memory_write add／edit**，拆掉直接 write_text 那條路（不留雙軌）；這是本輪對 aos 原語的壓力測試，撞到 bug 記不足清單、當場修 |
| inword／別名新增 | 維持只讀（`persist_aliases=False`）；各任務 `aliases-added` 批末彙總成報告，不自動進表 |
| 知識庫 git | worker 不帶 `--commit`；runner 在任務完成回呼裡逐任務 `git commit --only <節點路徑> <names 檔>`，仍一任務一 commit（使用者裁定 3） |
| kernel 帳 | 已有鎖；每任務帳由 runner 依 instance id 從 ledger 切出 |
| 審視者帳、accounting、index-curve | runner 批末單程序寫，不變 |

**量法**：A 批前 8 地 `--workers 1` 得基準（任務／小時、各步 wall 中位、prod 中位），之後 `--workers 4` 比。提速＝吞吐 ≥3× 基準（A 只 12 地噪音大，看 ≥2.5×）；零丟失＝批末 `kb_slug check` 缺門牌 0、commit 數＝接受數、殘留 `.lock` 0；不變差＝並行 prod 中位在循序 ±10% 內、S4 wall 升幅 ≤20%（升多＝kernel 排隊，記下）。

## 3. 蒸餾（想法 17）本輪怎麼推

**關掉**：E2 剪候選（維持代定 57）、E5「整池對 sol ≥95%」門檻、E1 terra 抽事實擴面（別名召回 16%，facts 204 條留檔不增）。
**留**：E3 左右字模式（唯一碰到難題）、E6 單字固定判定（併入規則池當候選）。

**對誰算對——三層真值** `R4/distill/truth.jsonl`（累加、不刪）：T1 隊長機讀真值（6 題起，pending 待人件裁了就追加）；T2 語料作者連結（詞條內 `[X](../類/Y.md)` ⇒「X 在該段指 Y」，排除 ✓／詞條／證據／索引／詳見等版面 anchor）；T3 已接受連結（生產與參考同意的）。規則統計對 T1∪T2∪T3 算，另列對 T1∪T2 的數；**不再單對 sol 算**。

**逐條上線**（`kb_rules promote`，批末自動）：一條規則 live 的條件＝影子答 ≥20 題、跨 ≥5 任務、對 T1∪T2∪T3 ≥95%、對 T1∪T2 錯 0。live 規則在 S4 的 T0 段先答，答了就不送 terra。**降回影子**（不叫退休，ad-3 的退休是 agent）：live 後任 50 次滾動窗內錯 ≥2（參考抽樣、judge、qa 任一抓到）自動降，記事件。

**手寫 T0 規則 vs 蒸餾規則**：新失敗類型四種是隊長設計、直接進 T0（像 t0guard），不過影子：①只命中姓氏段（`kind: family`）→送 T2＋**強制參考**；②提及緊貼另一個已知名字→T2＋強制參考；③短名嵌在更長標題裡→用語料全標題詞典（§8 W8）最長匹配，被蓋住就丟提及、記錄；④「X語系／語／人／式／風／製」修飾語→T0 判不連、記錄（後綴表隊長可加）。單字名提及一律強制參考（不抽樣）。

**新教材**（§5 觀察，實查）：lore 8,067 條連結，anchor 1 字 157 條（扣 ✓ 45 約 110；望 13、陳 7、年／夕／令 各 6）、2 字 870 條（扣版面詞約 700）。單字正例約 110，比第三輪 89 道 LLM 題多一點、不是量級差；未連的出現**不算負例**（作者只連部分提及）。所以用法：T2 真值 ＋ E3 模式的正例擴充；負例仍來自題紀錄。D4 判準：E3 重訓後對留出的 C4＋C5 LLM 題覆蓋 ≥40/89（原 23）且純度 ≥95%，過就當正式教材，不過只留作真值。

**12B**：不回生產路徑（LM Studio 一次一模型、backend slots=1 會變瓶頸）。批末離線重放 T2 題，給二選一窄題「此處的『X』是普通字還是名字」＋前後 60 字；量對 T1∪T2∪T3 同意率。≥95%（≥100 題）才在第五輪考慮「live 規則與 12B 同票就跳過 terra」。

**資產形狀**（ad-5：定期抽出、換語料再用）：`W/distill/` 成一個定義，kit 可抽。`rules.jsonl` 每條：`id, kind(pattern|lexicon|fragment|suffix), predicate(宣告式：左右字、詞內、fragment_of、後綴), scope(general|corpus:arknights), status(candidate|shadow|live), stats{fires, wrong, by_tier, window50}, provenance(來源題／連結 id), ts{created,promoted,demoted}`；`truth.jsonl` 如上；引擎 `kb_rules` 不含語料知識，語料知識只在 `K/index/{names,inword,titles}` 與 scope 標 arknights 的規則。驗收：`kit-extract` 抽出引擎＋general 規則、不帶 arknights 詞典。

## 9. 要使用者裁

**1. 量（衝突）**：想法 3「一輪就做了40個條目？太多了……一個一個慢慢做」vs 第四輪主題「零人工吞吐、提速」。本規劃 B 批 205 人、C 批 406 人，跑動中沒有人看。
- a) A＋B＋C（631），C 只看 B 數字過閘就跑——**推薦**：吞吐與並行問題在 20 地量不出來，錯連有 pending 兜底、少連可重跑；後果：full 約 9M token、一天內跑完，錯誤若是系統性會一次影響數百節點（但節點重建便宜，使用者裁定「壞了就重建」）。
- b) 只跑 A＋B，C 留第五輪：風險減半，吞吐數字仍能量到；後果：蒸餾 D1／D2 樣本少一半，live 規則可能到不了 5 條。
- c) A＋B 的 B 縮到 100：最保守；後果：並行數字噪音大，D 系判準多半只能記錄。
- eli5：以前是一次做一個、做完看一眼；這輪要試「機器自己跑幾百個、人只事後看」。要不要一次放到六百多個，還是先放兩百個看看。

**2. 「歲」怎麼分類（方向題，使用者領域）**：巨獸本體「歲」在 factions，sol 參考與 judge 都不肯把巨獸的提及連到派系類節點，第三輪三題（歲獸、除歲、頡 q5）因此錯或懸著，本輪會被 judge 錯關。
- a) 不動節點，參考與 judge 提示寫明「巨獸本體歸派系類，提及巨獸就連它」——**推薦**：改一句提示、不動庫結構；後果：類別慣例靠提示維持，換模型可能再犯。
- b) 為巨獸本體另開人物類節點，派系類只放「歲的信徒／相關勢力」：結構正確；後果：要重建歲相關節點與已接受連結、知識庫五類的分法要補一條「同名實體跨類」。
