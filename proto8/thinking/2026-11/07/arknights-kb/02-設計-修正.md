## 必修七條的定法

1. **額度一隊一格**：kernel 以 `AOS_WS` 認寄件人，同一個 `ws/` 的 writer 就是一格；不寫每隻 writer 各一格。隊內誰用多少先不分（記進不足清單）。
2. **試驗場額度放寬**：隊 kernel 與總機的每日 `max_calls` 改 3000（第一輪兩趟約 240 次，留足餘裕；真正的煞車是 slots 與負載監看）。
3. **places 是 40 檔**：`INDEX.md` 不算詞條；第一輪不需要 `kb_split`。
4. **路徑一律相對 `$AOS_WS`**：信裡寫 `corpus/arknights/lore/places/X.md`、`kb-ak/ak/places/<slug>.md`；`sources:` 行寫相對 arknights repo 根（例 `lore/evidence/...`），`kb_lint` 拼上 `$AOS_WS/corpus/arknights/` 驗存在。
5. **`[[…]]` 只驗格式**：目標不存在只算 warning、計數進報告，不讓 lint 失敗（目標類別之後幾輪才有）。
6. **lint 只驗本批、做過＝已進 git**：`kb_lint` 接檔案清單；`batch.py` 以 `git ls-files` 判斷哪些做過，壞節點不 commit、下一批重派，順便解當機復原。
7. **T1 用 `mv` 不用 `git mv`**：clone 自帶 `.git`、在 `.gitignore` 裡，不進試驗場 git。

## 設計問題的定法

- **重跑 diff 率只記數、不卡關**：第一輪的驗收拿掉「≥ 80%」，報告照記；writer 的請求溫度若 kernel 支援就設 0，不支援就記不足。
- **指令統計不讀 history**（C-52）：改包一支 `bash_logged` 工具（`defs/bash_logged/`），自己把每次指令附加到 `work/bash.log`，統計腳本只讀這份。
- **中文 2 KB 太緊**：先照 2 KB（places 最大 1.3 KB 不受影響）；characters 輪再看拆節數量，必要時帶給使用者（併進裁題 1）。
- **規模、千級 agent、工具＝agent、全庫 token 總估**：第一輪不驗；記進 04 後續輪（第三輪排「千級 agent sleep／wake 與工具＝agent」專門一輪），全庫 token 總估由 round_report 依第一輪每節點 token 外推。
- **一層子節點過多**：第二輪 characters 起依首字母或陣營分一層，屆時由隊長定。

## 要使用者裁（02-設計三題之外補三題）

4. 重跑 diff 率要不要成為驗收門檻（推薦：先只記數，有基線後再定門檻）。
5. gpt 每日 token／金額上限要不要設（推薦：試驗場先設每日 calls 3000，金額不設，報告裡附當日 token 總數）。
6. 千級 agent 規模在第幾輪實測（推薦：第三輪，前兩輪先把流程與工具定下來）。
