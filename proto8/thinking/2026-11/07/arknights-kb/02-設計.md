## 白話總結

把 arknights 的 `lore/` 當**原料**，用便宜的 gpt 小腦（一類詞條一隻）**逐檔改寫成 aos 知識庫節點**（英文路徑、≤ 2 KB、標題＋一句摘要），證據不搬、用指標回指 clone。哪個檔→哪個路徑、合不合格、要不要拆、何時 commit，**全部由不用 LLM 的腳本決定**；LLM 只做「讀一篇、寫一節」這一件事。每輪跑完腳本出報告（失敗、重複的 bash 指令、要人工處），隊長據此提案新工具／定義，gpt 施工、opus 審、進試驗場 git，穩了再收進 proto8。第一輪只做 `places/` 41 檔、一隻 agent、跑兩次比 diff 量確定性。

```
隊長 opus（Claude Code，在 aos 外）── 看報告、提案、派 gpt 施工、交 opus 審
 │  腳本層（確定性，無 LLM）：batch.py 派工｜ak_slug 取路徑｜kb_lint 驗格式｜round_report.py 出報告｜git commit
 └─ aos 樹（~/code/playground-ak）
    ├─ root daemon
    │   ├─ 總機 llm_kernel ──→ LiteLLM（實打 API；slots 6、reserved high 1）
    │   ├─ 隊 kernel llm_team ──forward──→ 總機（隊的額度與帳在這層；slots 4）
    │   └─ 領班 daemon（判官 max_running 8）
    │        ├─ writer-places（gpt-luna-low）  讀 lore/places/X.md → 寫 kb-ak/ak/places/<slug>.md
    │        ├─ writer-factions（同上，第二輪）
    │        ├─ writer-characters（同上，第二輪，會拆子節點）
    │        └─ reviewer（gpt-sol-low，第二輪）  抽查 10% 對照原文、退件寫 work/
    └─ ws/kb-ak/（知識庫，git 追蹤）：README｜aos→（捷徑，唯讀）｜ak/{places,factions,characters,…}｜work/
```

## 八題結論（每題一段；細節在分檔）

1. **庫怎麼切**（[01-庫](02-設計/01-庫.md)）：三層但只有**詞條層進 memory 樹**——原文證據層＝arknights clone 原樣唯讀、不轉；詞條層＝`kb-ak/ak/<類>/<slug>` 從 `lore/` 各類逐檔轉格式（第一輪只轉、不重新歸納；第四輪起才把 characters＋deep_dive＋relationship_map 融成一節）；索引層＝`ak/index/*.json`（中文名→slug 對照，腳本生）。段名：有 ID 的用 ID（`char_002_amiya`、`act17mini`），沒 ID 的查對照表 `names.tsv`（第一次由 gpt 生拼音、進 git、之後純查表）；標題雙語 `# 伊比利亞之眼 (yibiliya-zhi-yan)` 所以中文 `find` 照樣命中。多庫照 K7：`kb-ak/` 根放 `aos ->` 捷徑。
2. **agent 分工樹**（[02-agent與工具](02-設計/02-agent與工具.md)）：一類詞條一隻 writer 定義（同一個範本、只差 system.txt 與輸出路徑），腦 `gpt-luna-low`；reviewer 一隻 `gpt-sol-low`；**沒有 foreman agent**——派工、拆批、合格判定、commit 都是腳本。本機小模型第三輪才拿來跟 luna 比確定性。
3. **工具樹與確定性演進**（同上分檔）：第一輪 writer 配 `read`／`write`／`memory`＋`bash`（開放但每批從 history 統計指令）；第二輪 bash 收成白名單、常用指令變專屬工具；第三輪拔 bash。量法四個數：**重跑 diff 率**（同輸入跑兩次）、**lint 首次通過率**、**人工次數**（退件＋手改）、**token／節點**。
4. **kernel 嵌套**（[03-kernel與git](02-設計/03-kernel與git.md)）：照試驗場 `llm_team/forward` 接；只補一個洞——`aos-llm ask --full` 印整封回信（含 `usage`）讓 forward 回 usage、上層帳不再是 0。下游 `senders` 只見隊一格**不改**（嵌套本意＝一隊一格）。並發三道閘：總機 `slots`、隊 `slots`＋`budget.senders`、判官 `max_running`；整樹包 `systemd-run --scope`。
5. **git**（同上分檔）：`kb-ak/` 跟定義都在 `~/code/playground-ak` 一個 git；**每批一 commit、lint 過才 commit、agent 不碰 git**；審查事後抽查、退件下批修（見裁題 3）。穩的定義再收進 proto8。
6. **第一輪**（[04-第一輪與施工](02-設計/04-第一輪與施工.md)）：`lore/places/` 41 檔→`ak/places/`，一隻 writer、跑兩次。過＝41 節全在、lint 0 錯、diff 率 ≥ 80%、隊 kernel `used.json` tokens > 0、一個 commit。第二輪 factions＋characters 前 50（拆子節點、3 隻並行、加 reviewer）；第三輪 operators 400＋本機模型對照；第四輪重新歸納。
7. **自我演化**（03 分檔）：每輪 `round_report.py` 出報告 → 隊長／fable 在 `defs/PROPOSALS.md` 提案（改哪個數字）→ gpt 在 `defs/<name>/` 施工附 `README.md` 白話 → opus 審 → commit；`defs/INDEX.md` 由檔頭一句生成（鐵律 3 的做法）。第三輪起讓 reviewer 用 `self_tools` 自己提案。
8. **要先補的程式**（04 分檔）：第一輪**不等任何 aos 改動**（kb 放 ws 內、用 `write`）；並行補 W1（find 跟捷徑）、W2＋W3（memory_write）、K1（`aos-llm --full`）；第二輪切到 memory_write。

## 要使用者裁（白話；推薦放第一）

1. **知識庫本文用什麼語言？** `knowledge/README` 寫「內容語言英文（AI 讀）」，但語料 361 萬漢字、專名與引文翻了就失真。
   - **段名英文、標題雙語、本文中文、引文保留簡體原文 (Recommended)**：零翻譯成本、`find` 中英都中；代價：`knowledge/README` 要加一句「語料庫例外」。
   - 全英文：跟 aos 庫一致，但 token 翻倍、專名對不回去。
2. **證據層（`lore/evidence/` 11.7 MB、3,845 檔）進不進 memory 樹？**
   - **不進，留在 clone、節點用 `sources:` 行回指 (Recommended)**：庫小、不重複；代價：agent 要看原文得用 `read`（第二輪收成 `ak_src` 專屬工具）。
   - 當第二個庫 `ak-evidence` 掛捷徑：全部可 `find`，但工作量 ×2、內容重複。
3. **commit 時機**：原話問「agent 的產出審過才 merge？」
   - **lint 過就 commit 到 main，reviewer 事後抽查、退件下批修 (Recommended)**：小模型大量產出先保存、git 歷史＝每批實況；代價：main 上會有短期錯節點。
   - 每批開 branch、審過才 merge：乾淨但多一套操作，第一輪沒 reviewer 等於白等。

## 代定（可翻案；每條：定了什麼／為什麼）

- 第一輪 kb 放 `ws/kb-ak/`、用現成 `write`／`read`，不等 memory_write／W1～W3 都沒做，先跑起來挖不足。
- arknights clone 搬進 `ws/corpus/`／`read` 只准 `$AOS_WS` 內；`corpus/processed`（2.8 MB）另 `cp` 一份唯讀，raw 不碰。
- 沒有 foreman agent、腳本派工／KISS，LLM 只做改寫這一步，確定性最高。
- 下游 kernel 的 `senders` 只見隊一格、不改／一隊一額度正是嵌套的用意；隊內帳在隊 kernel 自己的 `used.json`。
- 本機 lm-／ollama 模型第三輪才進來／先用 luna 建基線。
- 前兩輪提案只由隊長／fable 出，第三輪起 reviewer 可 `self_tools` 自提／先有數字再放手。
- `names.tsv` 用 gpt 生一次再凍結（機器沒 pypinyin）／裝了就改腳本生。
