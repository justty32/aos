# 第一輪範圍、驗收、施工步驟（結論）

## 第一輪：`lore/places/` 41 檔 → `ak/places/`

- 為什麼挑它：最小（43 KB）、格式單一（`### 地名`＋摘要＋「詳見 evidence」）、單檔最大 2.9 KB（只有幾檔要拆），一隻 writer 一個下午跑完兩次。
- 跑什麼：`batch.py places --size 10` ×5 批；每批 lint→commit；全部跑完換 `--out kb-ak-rerun` 再跑一次比 diff。
- 幾隻：`writer-places` 1 隻（第 3 批起掛第 2 隻看並發）；腦 gpt-luna-low；隊 kernel 經 forward。
- **過（全要）**：① `ak/places/` 41 節＋`index/aliases.json`；② `kb_lint` 0 錯；③ 重跑 diff 率 ≥ 80%；④ 隊 kernel `used.json` tokens > 0（K1 做完）或總機 `senders` 見 `../llm_team`；⑤ playground git 有 ≥ 5 個 batch commit；⑥ `runs/1/report.md` 四個數都有、得失第 1 輪填了；⑦ 全程 `watch.log` 無超 80%。
- 不足清單預期新增：bash 指令被濫用的樣子、luna 不照格式的樣子、`listen` 逾時行為、2 KB 邊界。
