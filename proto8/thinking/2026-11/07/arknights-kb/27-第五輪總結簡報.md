## 3. 新教練值不值

- **方法上值**：量尺第一次量出「改教練」的真效果（−9%，雜訊 0），並且指出真正的槓桿是**給教練的標準答案夠不夠**——元審視（sol 一次、約 6k token）比隊長草稿先看到這點（「556 題只有 129 題有真值」），照它改後已知答案 3.5 倍、候選規則才湊得到門檻。
- **錢上這輪不值**：省錢只發生在「整個任務不用問 AI」，三條都 0 個任務清零，所以生產呼叫一分沒省；參考全涵蓋多花的比省下的題多，改教練本身又花掉約一條試驗的分數。
- **要回本得怎樣**（事實，不是處方）：規則要能讓整個任務清零；參考從「全涵蓋」縮成「只補還沒有標準答案的題」；審視者只看有事的任務（v0a 元審視預測可省 100～180 分／pass，v1 沒試）。

## 5. 得失

**得**
1. 元優化的量法跑通：空基準 tag、pass 重置、兩條基準量雜訊、題數曲線、meta 帳分開記；改一處就看得出曲線差多少。
2. v1 錯連 0：參考全涵蓋把 v0 第 1 pass 那兩條錯連提前擋成待人題。
3. 單字名誤套根治：v0 第 3 pass 隊長要手補 5 題，v1 0 題。
4. 元審視（每份約 6k token）性價比高：三條疑點裡最有力的一條，比隊長草稿更打到主曲線。

**失**
1. 主目標 ≤130 三條都沒到；12 條 live 規則多半仍是標點型，驗證覆蓋一直 0——學到的是「謝拉格這批題的答案」，不是可帶走的規律。
2. 元處方①第一次只做了一半（參考跑了、答案沒進真值），作廢一次 v1 pass 1 才補上（代定 101）。
3. 基準 tag 兩次誤帶上一條學到的規則（pass 快照會 commit 進 `ws/defs`），都在開跑前抓到。
4. 梯度信自動寄沒接上（代定 99），想法 20 的錢在本輪對曲線 ≈0、退休訊號量不到。
5. 審視者一直是最貴的一塊，本輪沒動它。
