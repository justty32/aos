# 子題 3：多核／叢集概念 ↔ aos

狀態：**已經是這樣**／**差一點（差在哪）**／**天然差異**。

| 多核／叢集概念 | aos 現在有的 | 狀態 | 一句白話 |
|---|---|---|---|
| SMP vs AMP | daemon 不排誰先跑、每個 proc 自己的程式與 stack；Linux CFS 在底下分時 | 已經是這樣（aos 層是 AMP） | kernel 粗放式＝主核只管誰上電。 |
| 核數／oversubscription | `procs` 不限列；判官 `max_running` 數整台 running 列（含 0 號） | 天然差異（核數不是矽定的） | `max_running` 是唯一的「幾核」；超過實體核由 Linux 分時。 |
| `max_children`（每父配額） | `agents` 工具自己數小格 `children.json`；上限另有判官 `max_running` | 已經是這樣（兩層：子 cgroup `pids.max` vs 全板上限） | 父死計數跟著小格走、不歸零——自擔。 |
| 核間通訊：mailbox | aos-post（Maildir、有序先、認領靠 rename） | 已經是這樣 | RPMsg endpoint。 |
| 核間通訊：共享記憶體 | 檔／ws／共用 stack；N-05 暫存改名＝發布 | 已經是這樣 | 一個檔一次 rename＝一次 publish。 |
| 記憶體一致性（誰看到誰寫的） | 同機 POSIX 一致；窗「只看最新」（N-14）、一人寫（N-09）；跨檔沒有事務 | 已經是這樣（同機）／天然差異（跨檔、NFS） | 只有「一檔原子」，沒有 barrier 以外的東西。 |
| spinlock／mutex | aos-lock：`mkdir` 租約 `holder.json`（N-15；T2 改檔案鎖）；只有有序投遞 `order.lock/` 在用 | 差一點（共用 stack 時沒說要不要鎖） | [07 § 4](07-很多核-能借鑒.md) 一句條文。 |
| 無鎖／RCU／原子 | 暫存改名（N-05）＋單一寫者窗 | 已經是這樣 | 讀者永遠拿到完整的舊或新。 |
| per-CPU data | 每 proc 自己的 stack、小格 | 已經是這樣 | |
| CPU affinity／pinning | 沒有；Linux 決定；要釘就 `exec` 自己包 `taskset` | 差一點（一個 key 的距離）；推薦不加 | 核是 Linux 的，aos 不釘。 |
| `nice`／cpu shares | 沒有；所有 proc nice 0；priority 只在 llm kernel 的佇列 | 差一點；feat-proto 05 代定 7「不做 nice」 | CPU 先後交 Linux；腦的先後才是 aos 排。 |
| cgroup（整樹共享總額） | rlimit 各自上限；cgroup v2「要 root／委派」未做 | 天然差異（已裁，aos-daemon docs/09） | 整板 PSU 用 `systemd-run --user --scope` 包根 daemon（[07 § 3](07-很多核-能借鑒.md)）。 |
| `limits`（mem_mb／cpu_s／files…） | setrlimit 在子行程、繼承只能更緊、`user` 換帳號 | 已經是這樣 | 每核電源軌＋MPU；超了＝那顆核自己掛。 |
| `budget`（kernel／包／寄件人） | token／次數從總額扣、到頂 `BudgetMissing` | 已經是這樣 | aos 唯一「從總額扣」的資源＝加速器的電表。 |
| `slots`（kernel 總／包各自） | 在飛上限；包滿跳過讓別包補位 | 已經是這樣 | 加速器命令佇列深度／每顆引擎的佇列。 |
| `priority`（level＋aging→deadline→speed→等得久→先寄） | llm kernel 排隊 | 已經是這樣 | 加速器仲裁器，不是 CPU nice。 |
| 全域 vs 分區 run queue／work stealing | kernel 一條全域佇列＋按包分區（滿了跳過） | 已經是這樣 | 全域仲裁、分區佇列；Linux 自己的 work stealing 看不見。 |
| `interval_ms` | daemon 200＝主核輪詢週期；每 loop 型自己的＝各核除頻器；`0`＝吃滿一核（docs/08） | 已經是這樣 | 反應延遲下限＋每核節拍。 |
| big.LITTLE／異質核 | 能力包 `speed` fast／normal／slow、deadline 之後挑快的 | 已經是這樣（在 PU 層） | 大小核在加速器那邊，不在 proc。 |
| 熱插拔核 | `procs_added`／`removed` 跑中加減 | 已經是這樣（比板子強） | |
| NUMA／遠記憶體 | 一棵樹一台機器；跨樹只有信、沒有共享記憶體（11-06 已裁「外接」） | 天然差異 | 遠記憶體在 aos 是另一塊板。 |
| 跨 daemon 負載平衡／遷移 | 沒有；stack 路徑＝proc 的家；要搬＝整樹 image | 天然差異（kernel 粗放） | [07 § 6](07-很多核-能借鑒.md) 推薦不做。 |
| quiesce（停整機） | 監管樹整樹 sleep（P6）：父 TERM 子、子睡自己的 procs | 差一點（P6 未實作） | 葉先睡、根最後。 |
| live migration／CRIU | 睡著才 `cp -a`；在飛作廢重寄 | 天然差異（刻意：冷遷移） | 拔卡搬板，不是熱搬。 |
| 排程器也佔一核（C-12） | 0 號判官是表上一列、`max_running` 要算它；kernel 身體在 daemon 圈內 | 已經是這樣 | 排程器不是硬體，是一顆核。 |
| OTP supervisor／let-it-crash | daemon 型 crash 照表重起；stuck 預設只標；連 3 次失敗留 stopped | 差一點（P7 未實作） | |
| Plan 9 CPU server | `AOS_DAEMON`＝stack＝「那台機器」；跨樹寄信＝另一台 server | 已經是這樣（C-37） | 資料夾就是機器。 |

## 最有意思的三個對照

1. **aos 是 AMP，不是 SMP。** daemon 從不決定「誰先跑」，只決定「誰上電」，每個 proc 跑自己的韌體；Linux 的 SMP 排程在底下隱形。使用者說「kernel 粗放式、Linux 細粒度」，用多核語彙講就是：aos 的 kernel 是 AMP 主核，Linux 是 SMP 排程器——兩層各管一種「分配 cpu」，不打架。
2. **`max_running` 是核數、`budget` 是電表、`limits` 是每核電源軌。** 三個數字三種帳：`max_running` 數「幾顆核上電」（可超實體核，Linux 分時）；`limits` 每核各自上限、不從總額扣（天然差異，已裁）；`budget` 是 aos 唯一真的「從總額扣」的資源——因為腦是外部加速器，電表在它那邊。
3. **監管樹借的不是硬體、是 OTP。** 多核板子每核各自 WDT、互不管；aos 的「上一層 waitpid、crash 照表重起、stuck 只標」是 supervisor tree ＋ let-it-crash。比喻說成「每塊板是上一塊板的一顆核」就接回板子了，而且 11-06 已裁的「一棵樹一個 image」正好＝一個 OTP node。
