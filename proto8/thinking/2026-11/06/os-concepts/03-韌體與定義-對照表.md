# 子題 2：韌體概念 ↔「定義＝原始碼」

**一句話**：「定義＝原始碼」在韌體語彙裡是「原始碼＝image、沒有編譯這一步」（XIP：原地讀、不複製進板子）。所以韌體的「編譯期 vs 執行期」在 aos 變成「值住在哪一層」：**定義 JSON（ROM）→ `.env`／`AOS_*`（上電取樣腳）→ 覆蓋層（EEPROM，跟 image 走、`reset` 清掉）→ ctl 窗／信（揮發暫存器）**。八成已經是這樣；對不上的全是「沒有編譯步驟」的衍生，標天然差異（[08](08-天然差異.md)）。

銜接 [daemon-board 01](../daemon-board/01-對照表.md)（bootloader、`_entry`、`.env`、OTA、版本＝git）與 [portable-flow 02](../../05/portable-flow/02-image-模型.md)（定義＝source、stack＝記憶體）——那些列只引一句再往深挖。

| 韌體概念 | aos 現在有的 | 狀態 | 一句白話 |
|---|---|---|---|
| source → compile → image | 定義資料夾直接被讀；aos-directive 解 `$env`／`$ref`（N-45）算「連結」 | 天然差異 | 寫完就是成品；代價是沒有編譯期檢查，寫錯要跑到那格才知道。 |
| 編譯期設定（Kconfig、`#define`） | 定義裡的 JSON 鍵：`fsm.json` 表、`kernel.json` `slots`、`judge.json` `allowed`／`max_running`、`daemon.json` `limits`；呼叫時不變（C-46、C-68） | 已經是這樣 | 寫在定義裡＝「編進去的」，改了要重起才生效。 |

## 最有意思的三個對照

1. **沒有編譯步驟，所以「何時」變成「何處」。** 韌體問「這個值是編進去還是跑時讀」，aos 問「這個值住定義、`.env`、覆蓋層還是 ctl」。debug build、A/B 分區、image header、校正區全對不上，原因是同一個：它們都是 build 產物的概念，aos 沒有 build 產物。
2. **覆蓋層＝EEPROM，而且 EEPROM 跟 SD 卡走、ROM 不跟。** 定義（ROM）不動、實例參數寫 stack 覆蓋層（EEPROM）、`tools reset`＝清 EEPROM；image 搬家帶走 EEPROM 卻帶不走 ROM——這正是「定義沒搬＝`stopped`」的根源：aos 把 ROM 和 EEPROM 放在兩個資料夾。
3. **fsm.json 是自帶 history 的 HSM。** 韌體 HSM 要特別寫 history pseudo-state 才能「回到上次離開的子狀態」；aos 的狀態本來就在 `stage.txt` 裡，stop→start 天然接回那格，history 免費；entry／exit 不用加 key，因為格本身就是程式。
