# 子題 3：板子但很多核——比喻哪裡失效、換什麼

**一句話**：aos 這一層是 **AMP 不是 SMP**——daemon 是「主核」，只決定哪顆核上電（掛不掛）、不決定誰先跑；每個 proc 是一顆跑自己韌體的「遠端核」，自己的 stack＝自己的 SRAM，核間靠 mailbox（aos-post）與共享記憶體（檔、ws）；底下 Linux 的 SMP 排程（分時、親和性、工作竊取）aos 看不到也不管。使用者名詞表的「cpu＝kernel 開來跑某資料夾的一個執行單位」本來就是這種**虛擬核**，所以「板子很多核」＝「很多 cpu（使用者義）」；比喻只在一處真的失效：**核數不是矽定的**——proc 可以無限加、Linux 分時，aos 唯一說「這塊板有幾核」的地方是判官的 `max_running`。

## 板子比喻哪裡因多核失效

| 板子比喻的這一列 | 為什麼多核時不成立 | 改用什麼 |
|---|---|---|
| 「板子＝一顆 MCU 跑 super-loop」 | daemon 自己是 super-loop，但底下幾十個 proc 真的同時在幾顆實體核上跑；單核 MCU 沒有「同時」 | AMP 多核 SoC：daemon＝主核（remoteproc master），proc＝各跑自己韌體的遠端核 |
| 「核數＝板上有幾顆」 | `procs` 名單隨時 `procs_added`，列數遠超實體核，Linux 分時（oversubscription） | `max_running`＝這塊板「允許上電的核數」；實體核數是晶片商（Linux）的事，標天然差異 |
| 「每核綁自己的 SRAM」 | aos 的 stack 是檔，C-67 容許兩個 proc 共用一個 stack（P-18 同時跑互寫） | 共享記憶體區（shared SRAM）＋自己拿鎖（N-15）；[07 § 4](07-很多核-能借鑒.md) |
| 「mailbox 是固定的點對點硬體通道」 | aos-post 任何人對任何信箱，信箱數不限、跑中可開 | RPMsg／virtio 式的動態通道：信箱＝endpoint，誰知道路徑誰寄 |
| 「主核把韌體燒進遠端核再放開 reset」 | 對：fork→setsid→setrlimit→aos-exec 定義；但遠端核跑完會「自己退」，板子的核不會消失 | remoteproc 的 start／stop／crash-recovery；exec 型＝跑完就下電的核 |
| 「電源軌／限流＝limits」（daemon-board 01-續） | 多核時真板子所有核吃同一顆 PSU；rlimit 各核各自上限、沒有總額 | 每核電源軌照舊＝rlimit；**整板 PSU＝起根 daemon 的人用 cgroup scope 包**（[07 § 3](07-很多核-能借鑒.md)） |
| 「看門狗＝監管樹」（daemon-board 01-續） | 多核板子每核各自一顆 WDT、互不管；aos 是上一層管下一層、整棵樹 | 這一層借 OTP supervisor tree 的說法，不是硬體 |
| 「晶振一顆、全板共用」 | 成立——`_tick` 一棵樹一個；但每個 loop 型 proc 自己的 `interval_ms` 是各核自己的除頻器 | 一顆晶振＋每核各自 clock divider（`interval_ms`） |
| 「停整機＝按 reset」 | 多核停機要有順序：先停遠端核、主核最後；醒來反過來 | 監管樹 sleep 的「葉先睡、根最後；醒反序」（P6 已是這形狀，寫明即可） |

## 換比喻：五個候選

| 候選 | 好在哪 | 壞在哪 |
|---|---|---|
| **AMP 多核 SoC（remoteproc／RPMsg／OpenAMP）** | 留在使用者的嵌入式比喻裡；mailbox、共享記憶體、主核起遠端核、各核各自韌體與 SRAM，daemon-board 37 列全部接得上 | 核數矽定、不分時；核不會「自己退」；要把「核數不固定」標成天然差異 |
| 刀鋒機櫃 | 刀鋒可熱插拔＝`procs_added`／`removed`；機櫃管理控制器＝daemon；背板＝共享 fs；PSU＝總額 | 每片刀鋒是整台機器帶 OS，太重；mailbox、暫存器那層接不上 |
| 一棟樓的部門 | 帳號、額度（budget）、「誰能進誰的房間」直觀 | 不是技術比喻，tick／窗／信箱都沒對應 |
| Erlang／OTP node | 監管樹就是 supervisor tree、let-it-crash＝crash 照表重起、信箱＝mailbox、share-nothing、process ≫ scheduler | BEAM 自己排程（aos 交給 Linux）；BEAM process 不是 OS 行程；離開硬體語彙，偏離使用者的大方向 |
| k8s node | pod spec＝`procs`、requests/limits、restartPolicy、liveness probe＝stuck、namespace＝帳號 | 本體是叢集排程器與 YAML——跟「kernel 粗放式」「KISS」反向；會引來「要不要 requests 保留量」一堆 aos 沒要的題 |

**推薦：板子為主，「核」這一層換成 AMP 多核 SoC；監管樹那一層借 OTP supervisor 的說法（只借解釋、不改名）。** 跟子題 1 的三段式合起來：**板子（daemon＝主核＋BSP）＋薄 RTOS 核（kernel 身體）＋服務目錄（`procs` 表）；每個 proc 是一顆遠端核。**

## 用推薦的比喻重講七個名詞

- **daemon**＝主核的韌體：上電、起遠端核、收 mailbox 的 `procs_*` 指令，自己不算任務（C-47 最基礎 kernel＝remoteproc master）。
- **proc**＝一顆遠端核跑自己的韌體（定義）；exec 型＝跑完下電的核，loop 型＝常駐的核；核數不限、Linux 分時。
- **stack**＝那顆核的 SRAM（`procs/<名>/`）；共用 stack＝兩顆核映到同一塊 shared SRAM，自己拿鎖。
- **ws**＝板上的 DDR／外接 NAND：所有核都看得到、沒有誰擁有。
- **llm kernel**＝網路上一顆多板共用的 NPU 加速器，有自己的命令佇列（`slots`）、電表（`budget`）與仲裁（priority）；它自己也是一塊板（一台 daemon），上面每顆核是一次問腦。
- **監管樹**＝每塊板是上一塊板的一顆核；上一層 `waitpid`＝核的 fault 回報線，crash 照表重起＝OTP restart，stuck 只標＝WDT 不自動咬。
- **信箱**＝RPMsg endpoint：路徑就是地址，知道路徑就能寄；有序信＝有序通道。
