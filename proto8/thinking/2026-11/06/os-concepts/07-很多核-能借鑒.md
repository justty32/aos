# 子題 3 能借鑒的

全部零程式（名詞表一行、docs 一句、P8 食譜一行、慣例一句）；排程對照 [apply-ideas 02](../apply-ideas/02-排程.md)。

### 1. `max_running`＝這塊板的核數

- **白話**：aos 唯一定義「幾核」的地方。
- **選項**：① **名詞表「板子比喻」欄（已裁 ≤12 行）加一行「核數＝`max_running`；超過實體核由 Linux 分時」，`kernel/docs/02` 旁同一句**。② 不寫。
- **推薦 ①**。**落**：CONCEPTS 附錄1 板子欄、kernel/docs/02。**排**：T8 條文日。

### 2. affinity／`nice` 不進 `limits`

- **白話**：核是 Linux 的，aos 不釘核、不調權重。
- **選項**：① **不加 key；aos-daemon docs/09 一句「CPU 的分配是 Linux 的；要釘核或降權重，在那列的 `exec` 自己包 `taskset`／`nice`（寫什麼就做什麼；這是偏離『建議經 daemon』的例外，代價：表上看不到、核號是這台的，[09](09-Linux原生機制與可遷移性.md)）」**。② `limits` 加 `nice`（子行程 `setpriority`，約 1 h）。③ `cpuset`（要 cgroup，併 § 3）。
- **推薦 ①**（照 feat-proto 05 代定 7，只補判準）；判準：P9 壓測 100 個 running loop 時 daemon 一圈實測 >2×`interval_ms`（被餓）才做 ②。**落**：docs/09。**排**：條文 P8；程式之後另排。

### 3. 整樹總額（cgroup）不先做、先寫食譜 → README 方向題 3

- **白話**：「整塊板不超過 X」今天零程式就有：`systemd-run --user --scope -p MemoryMax=4G -p CPUQuota=200% aos-exec --stack . def` 包根 daemon，整棵樹（所有後代）共享那個總額，各列 `limits` 仍是每核上限。
- **選項**：① **P8 食譜一行＋docs/09「cgroup v2 列未來選項」旁補這句；`limits` 的 cgroup key 等「一個 agent 一個帳號」那支 root 小程式一起做（同樣要 root／委派，一次解）**。② 現在加 `cgroup` key——要 root，提早引權限問題，違 KISS。③ 不提——使用者想限整樹只能一列列寫、加起來還不守總額。
- **推薦 ①**；判準：使用者 user-session 有 systemd 委派（`/sys/fs/cgroup/user.slice/user-*/cgroup.controllers` 列出 memory、cpu）就寫進食譜；WSL 沒 systemd 時標「家機才有」。**落**：P8 食譜、docs/09。**排**：P8。

### 4. 共用 stack 的鎖一句

- **白話**：兩顆核映同一塊 SRAM，aos 不替你鎖。
- **選項**：① **CONVENTION P-18 旁一句「同時跑且共用 stack＝自己用 aos-lock（`<資料夾>/.lock/`，N-15）或各寫各檔；aos 不替你鎖、不擋」**。② daemon 拒絕兩列同 `stack`——違 C-67 自由度。③ 不寫。
- **推薦 ①**。**落**：P-18。**排**：條文日。

### 5. quiesce 順序寫明

- **白話**：停多核板要先停遠端核。
- **選項**：① **P6 文件寫「sleep：葉先、根最後；wake 反序；凍住前等在飛問腦收完（P8 已有）」**——P6 設計已是這形狀，只差一句。② 加「整樹 sleep 完成」窗欄——多一扇窗。
- **推薦 ①**。**落**：aos-daemon docs/03 省電模式表（daemon-board 代定 4：P6 後寫）。**排**：P6。

### 6. 多台 daemon 的負載平衡不做

- **白話**：proc 的家是它的 stack 路徑，不在板間漂。
- **選項**：① **不做自動；要把 proc 放到別棵樹＝人或 agent 把 `AOS_KERNEL` 指到那棵樹的判官信箱寄 `procs_added`（今天就行，手動 placement）；N-42 旁一句「kernel 不跨樹搬 proc」**。② 通用 kernel 把「哪台 daemon」也當資源排（C-11 容許）——要跨樹讀表、stack 得在共享 fs，跟 11-06「跨樹算外接」反向。
- **推薦 ①**。**落**：N-42。**排**：條文日。

### 7. 一致性的邊界一句

- **白話**：共享記憶體只保證「一個檔一次 rename」。
- **選項**：① **N-14 旁一句「proc 間經檔交資料，一致性只到單一檔的暫存改名；跨多檔要一致＝自己打包成一個檔或拿鎖」**。② 不寫。
- **推薦 ①**。**落**：N-14 旁。**排**：條文日。

## 方向題全文（README 題 3；另一候選不問）

**題 3：整樹總額要不要用 `systemd-run --user --scope` 當官方做法（寫進 P8 食譜），`limits` 的 cgroup key 等「一個 agent 一個帳號」的 root 小程式一起做？** 推薦：是（零程式、今天就有整板 PSU）。替代：(b) 現在加 `cgroup` key——要 root／委派，把權限題提前、違 KISS；(c) 不提——使用者想限整樹只能一列列寫、加起來還不守總額。

**不問、fable 代定（README 代定 4）：多台 daemon 之間要不要任何自動 placement？** 不做；手動＝`AOS_KERNEL` 指別棵樹的判官寄 `procs_added`（今天可行）。替代：通用 kernel 把「哪台 daemon」當資源排（C-11 容許）——要跨樹讀表與共享 fs，跟 11-06「跨樹算外接、一棵樹一個 image」反向。

## 跟既有原則／已裁的關係

沒有真衝突。兩處只是比喻貼不合、標天然差異即可：(i) 多核 SoC「每核綁自己的 SRAM」vs C-67「兩個 proc 可共用 stack」——不是衝突，是 aos 比板子自由，§ 4 補一句鎖的提醒就好；(ii) feat-proto 05 代定 7 已說「不做 `nice`」，§ 2 照它、只補判準，不翻案。
