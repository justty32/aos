# 天然差異與 fable 代定

## fable 代定（可翻案）

1. 三段式比喻（板子＋薄 RTOS 核＋服務目錄；核那層＝AMP 多核 SoC；監管樹借 OTP supervisor 的說法、只借解釋不改名）寫進 CONCEPTS 附錄1 那欄時仍守已裁的 ≤12 行：補「核數＝`max_running`」「kernel 身體＝scheduler task」「值住哪四層」各一行，超了就刪別的。
2. 依賴順序不給 daemon（`after` 不加）：要等誰 ready＝讀它 `state.json` 的 `counter_runs ≥ 1` 或寄 ping；避免再開 C-52 例外。
3. affinity／`nice` 不進 `limits`（照 feat-proto 05 代定 7）；要釘核在那列 `exec` 自己包 `taskset`／`nice`（偏離「建議經 daemon」、代價見 [09](09-Linux原生機制與可遷移性.md)）。
4. 多台 daemon 之間不做自動 placement；手動＝`AOS_KERNEL` 指別棵樹的判官寄 `procs_added`。
5. 試驗場與 `templates/` 的 daemon `_entry` 預設帶 `--enable-logs`（出廠 debug on），跟範本 `tick: true` 同 commit；正式用自己刪一個字。
6. 斷電安全不加 fsync、不加 CRC：食譜「全 sleep → daemon 退出 → `sync` → 再 cp／commit」；P9 `kill -9` ×50 出現壞 JSON ≥1 次才翻。
7. `slots`／`max_running` 不開 ctl：當編譯期常數、改＝凍住再醒（[04 § E](04-韌體與定義-能借鑒.md)）；一週內想跑中改 ≥1 次才開。
8. 改定義「什麼時候生效」不統一：各程式 README 一句、食譜兜底「改定義先 sleep」（[04 方向題全文](04-韌體與定義-能借鑒.md)；件 1「下一題生效」已定、C-56 一件事一個地方推得出）。
9. aos-sandbox 的命名空間先不改成 daemon 認 `sandbox` key（[09-續 方向題 B](09-續-偏離建議的地方與方向題.md)）；P5 只改範例 bind 相對 daemon。

## 天然差異（不追；09-01 通則：比喻貼不合處標出來就好）

## 子題 1：OS 概念 → kernel

1. 沒有時間片：一次身體跑多久它自己決定，排程粒度＝一次 exec，中途切不走。
2. daemon 這層沒有 ready 佇列：判官拒就是拒；排隊只在各 kernel 身體裡。
3. 在飛任務不會被升級或殺掉讓位（HTTP 一刀砍錢已花）。
4. 沒有阻塞原語：等＝輪詢，反應下限＝`interval_ms`；inotify 只是加速。
5. 信箱不會滿：訊息大小、數量只受磁碟限制，沒有 queue full 的 block／drop。
6. 沒有 OOM killer：撞上限的自己死，daemon 不挑受害者。
7. 排程演算法不是 OS 內建的一套而是可換的程式（C-15）：「用哪個演算法」不是 aos 的題，「哪個 kernel 身體」才是。
8. 參照物是回合與資料夾（C-38），量不到 CPU %：沒有 top 是結構使然。
9. `procs` 是集合（宣告式 N-06），不是有向依賴圖：runlevel 的「順序」語意本來就沒有。
10. capabilities 只有客體（名字）沒有主體（寄件人不驗）：使用者 11-05 裁的。

## 子題 2：韌體概念 →「定義＝原始碼」

11. 沒有編譯期檢查：JSON 寫錯要跑到那格才 `CfgBad`／`DirectiveBad`。
12. 定義沒有 image header：沒 magic、沒版本、沒 CRC、沒大小；`interfaces.json` 只宣告不驗。
13. 沒有第二個槽：A/B 分區與自動回滾不存在，git 就是另一個槽。
14. flash 可寫的 XIP：定義跑著時能被改、而且各程式生效時機不一（下一格 vs 重起）；真板子 XIP 時 flash 唯讀。
15. 校正參數（`endpoints`、`budget.senders`）跟 source 同一份檔，沒有獨立的 OTP 區。
16. 沒有 debug／release 二分：旗標是 source 裡的一個字。
17. 記憶體佈局不在 source 裡：stack 放哪由呼叫方給（C-67），source 不知道自己會被放在哪。
18. 沒有條件編譯：一份 JSON 被多支程式各讀各的 key，功能有沒有＝key 在不在。

## 子題 3：很多核

19. 核數不是矽定的：proc 無限加、Linux 分時；`max_running` 是唯一的上限。
20. aos 不知道、也不決定哪個 proc 在哪顆實體核（沒有 affinity）。
21. 沒有 IPI：叫醒另一顆核只能寫檔等它自己輪詢（`interval_ms`）。
22. 共享記憶體一致性只到「一個檔一次 rename」；跨檔沒有事務。
23. 遷移是冷的：睡著才搬，在飛的重做（11-06 已裁）。
24. 跨樹沒有共享記憶體、只有信；NUMA 的「遠記憶體」在 aos 是另一塊板。
25. 排程器自己佔一顆核：0 號判官是表上一列、`max_running` 要算它；硬體排程器不佔核。
26. 一個 proc＝一個 Linux 行程，比 BEAM process／thread 重幾個量級；daemon 一圈成本跟列數成正比（aos-daemon docs/08：4300 列、`interval_ms` 10＝閒著 82%）。
27. Linux 會把 proc 在實體核間搬來搬去（work stealing），aos 的 stack 不動——板子上核與 SRAM 綁死，aos 的「核」與「記憶體」是分開的。
