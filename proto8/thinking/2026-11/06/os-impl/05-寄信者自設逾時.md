# 寄信者自設逾時（11-06 使用者裁定後，opus 照原則定細節；可翻案）

## 使用者原文（11-06，選項框，逐字）

題目：「判官開了排隊後，寄信要格的人（例如 ctl add）等滿 30 秒還在排隊中，對它來說算什麼？」（三個選項見 [03 方向題](03-判官排隊選項.md#方向題原則推不出的推薦放第一)；使用者三個都沒選）

> 由寄信者自己設定。然後30秒？這不該是固定值，同樣該由寄信者自己設定。判官會輔助。

## 解讀（寫明判斷）

- **兩層都算寄信者的**：(a) **等多久**——「30秒？這不該是固定值……由寄信者自己設定」；(b) **等滿算什麼**——題目問「算什麼」，答「由寄信者自己設定」。「同樣」把兩句並列成兩件事，所以不是只講 (a)。
- **「判官會輔助」＝判官不替寄信者決定，只做兩件幫得上的事**：① 開一扇窗 `queue.json`，寫誰在排、排第幾（陣列順序）、什麼時候進隊；② 寄信者在信裡寫了「最多排多久」，判官代為執行——到期把信從隊裡拿掉、回一封拒信。兩件都不多寄信，守 [N-66](../../../../docs/NORMS/05-基礎設施-窗/08-N-66.md)「進度先不另定（讀窗）」與「一封信一封回信」（[body-protocol 03-續 #6](../body-protocol/03-邊緣與衝突-續.md)）。「判官先回一封排隊中通知」這種讀法跟 N-66 衝突，列在文末方向題。
- **跟原則的對照**：N-66「等不到回信＝這次呼叫失敗：寄信方自己算逾時」本來就把逾時交給寄信方，這次是把「寫死 30 秒」改成真的由寄信方給；llm kernel 已有同形先例：寄件人在 body 寫 `priority.deadline`，kernel 過期回 `DeadlineMissed`、不佔格（[llm-kernel docs/01](../../../../impls/aos-llm-kernel/docs/01-用法.md)）。

## 定下的（一句一條）

| 項 | 定法 | 為什麼 |
|---|---|---|
| 等多久（寄件人端） | `aos-agent ctl add／rm／stop／start／sleep／wake` 加 **`--timeout-s S`**，預設 **30**（現值）；S 要大於 0，不設上限、不給「無限」；此限制只管寄件人等待，`--on-queued ok` 例外是不帶 `queue_wait_ms`，信可能永遠排著。（11-07 使用者裁定 sol 審查 #4） | H4 單位後綴，跟 `listen --timeout-s`、`ping --timeout-s` 同名同義；「寄信不回＝失敗」需要一個期限 |
| 等滿算什麼（寄件人端） | 要格的三個（add／start／wake）再加 **`--on-queued fail｜ok`**，預設 **`fail`** | 照 `aos-eca-turn --on-empty／--on-busy` 先例；預設＝現況「沒等到＝失敗」 |
| 信裡帶的期限 | `fail` 時 aos-agent 在 body 加 **`queue_wait_ms`**＝S×1000；`ok` 時不加，信可能永遠排著。（11-07 使用者裁定 sol 審查 #4） | 一箱一函數：body＝判官的 stdin，期限不進信封（N-66）；信裡用毫秒（[N-65 ③](../../../../docs/NORMS/02-設計理念-時空.md)） |
| `queue_wait_ms` 的意思 | 從信封 `sent_at` 起算，最多在判官隊裡排幾毫秒；**非負整數**，`0`＝不排、沒格立刻 `SlotMissing`；不是整數＝`BodyBad` | 寫什麼做什麼（C-56）；0 讓寄件人單封不排隊 |
| 判官輔助 ①：窗 | `$AOS_STACK/queue.json`＝`{"queued": [{"letter", "names", "queued_at", "queued_at_ticks"?, "expires_at"?}]}`，**陣列順序＝排第幾**；`queued_at_ticks` 有 `AOS_TICK` 才寫，`expires_at` 信有 `queue_wait_ms` 才寫 | 03 的 `since_at` 照 C-54 R6 改叫 `queued_at`（細化 03 代定）；位置不另寫欄（KISS）（**11-06 註**：使用者 11-06 選項框「不算、檔頭寫明 (Recommended)」——實作時判官 `_entry` 檔頭註解與 kernel/docs/02 寫 queue.json 的那句要寫明排法＝先來先掛（C-54 R14），[mailbox-naming](../mailbox-naming/README.md)） |
| 判官輔助 ②：到期 | 每輪先看到期：`sent_at`＋`queue_wait_ms` 已過的排隊信**不轉**，回 `{"applied": false, "error": {"code": "SlotMissing", "msg": "queued N ms, no slot freed (queue_wait_ms M)"}}`、`done` 收掉、stderr 照舊一行提醒 | 一封信一封回信；「失敗」就真的不會之後被掛上（下面「等滿」表） |
| daemon 收到轉來的 `queue_wait_ms` | 忽略（`apply_letter`「其他 key 忽略」，C-48）；判官原樣轉、不刪欄 | 不多一個改 body 的地方 |
| 用哪個鐘 | 全用牆鐘：寄件人 `time.monotonic`、判官比 `sent_at`；凍住醒來首輪已過期的排隊信一起拒絕，要跨凍住用 `--on-queued ok`。（11-07 使用者裁定 sol 審查 #6） | N-65：毫秒寫的期限永遠牆鐘；不開 `--timeout-ticks` |
| 人殼 aos-daemon-ctl | add／start／wake 加 **`--queue-wait-s S`**（→ body `queue_wait_ms`；沒給＝不過期、照舊排）；「沒給 `--reply-to` 看 3 秒」與 pause／resume「等 5 秒」改成 **`--timeout-s S`**（預設 3／5 不變） | 人也是寄信者；人殼不等回信（`--reply-to` 時由呼叫者等），所以只開「信最多排多久」 |
| lib `agents` 工具 | 加選填 **`ctl_timeout_s`**（new／rm／stop／start／sleep／wake，預設 30、上限 1700）、**`on_queued`**（new／start／wake，`fail`／`ok`）；子行程保險＝`max(STEP_S, ctl_timeout_s+30)` | 腦是寄信者，要能設（例：agent 生第 5 個 agent、格滿）；`timeout_s` 保留給 ask，預設值不同所以另開一格 |
| `thought` 工具 | 不開；它掛子照 aos-agent 預設（`fail`、30 秒） | thought 是一次性呼叫、整次有 `timeout_s`；格滿＝失敗回給呼叫者最直接。判準：P9 出現「thought 因格滿失敗而想排」再開 `on_queued` |
| 錯誤代號 | 不加新的：到期＝`SlotMissing`（判官現有）；判官／daemon 都沒回＝`DaemonMissing`（現有）；訊息裡的「30 s」改印實際 S | no-pid 代定 7「不加新錯誤代號」 |

## 等滿 S 秒時怎麼算（aos-agent 那端）

| 情況（等滿當下） | `--on-queued fail`（預設） | `--on-queued ok` |
|---|---|---|
| 已收到回信 | 照回信（applied＝成功；`applied: false`＝那個代號） | 同左 |
| 信在判官 `queue.json` 裡（`$AOS_KERNEL` 的上一層） | 再等 `REPLY_GRACE`（1 秒）收判官的到期拒信，**以回信為準**：收到＝`SlotMissing`；沒收到＝`DaemonMissing`（判官這輪沒跑完，訊息說「可能之後仍被掛上」） | stdout 一行 `queued NAME at position N (letter L; applied when a slot frees)`、**退 0** |
| 都不是（判官沒收、daemon 沒套） | `DaemonMissing`（現況） | 同左 |

沒設 `$AOS_KERNEL`、或判官沒開 `queue`：沒有隊，兩個值行為一樣（沒格立刻 `SlotMissing`、沒人收＝`DaemonMissing`）。
