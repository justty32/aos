# 可遷移性檢查單六項對現行程式打勾

**一句話**：六項裡程式真的對不上的只剩兩小處（agents 工具存絕對路徑、不經 daemon 的程式 README 沒寫「搬不走什麼」），其餘不是已做就是已排在 T／P 線；檢驗法有食譜沒腳本。

## ① image 裡的位址一律相對 daemon 的 stack

- 看了：[child.cpp](../../../../impls/aos-daemon/src/child/child.cpp) `rel_spec`（341 `r["stack"] = rel_spec(c.stack, dstack)`、224 `inst["cwd"] = daemon_ref`、245 小格寫成 `{"$env":"AOS_DAEMON","$path":…}` 指示詞）；aos-post `reply_to` 存相對信箱根（[docs/01](../../../../impls/aos-post/docs/01-用法與元素.md) 31）；aos-tools 覆蓋層 `path` 相對覆蓋層所在夾（[aos-tools](../../../../cmd/aos-tools/bin/aos-tools) 458）。→ **勾**。
- 殘留：lib/agent/agents/_entry（`../../../../lib/agent/agents/_entry`） 312 `absolutize_tools` 把子定義的 `tools.json` `path` 改寫成 `realpath`；286 `children.json` 存 `ctl add` 回的絕對 `stack`。搬家後前者指到舊位置（指 lib 的還在就沒事、指 ws 內的斷）、後者對帳對不上＝把小孩忘掉、配額歸零（不壞、自擔）。→ **K1**。
- 不算叉：表頂層 `daemon` 欄存繼承的 `AOS_DAEMON` 絕對字串（[daemon.cpp](../../../../impls/aos-daemon/src/daemon/daemon.cpp) 390），每次起來重寫，是回顯不是真相；kernel.json `budget.senders` 鍵＝寄件人絕對路徑（[budget.cpp](../../../../impls/aos-llm-kernel/src/budget/budget.cpp) 76）與 `endpoints.url`＝跨樹「這台的」（os-concepts 08 天然差異 15、P8 食譜一句，已排）。

## ② 期限用 tick、跨樹用毫秒

- 看了：[queue.cpp](../../../../impls/aos-llm-kernel/src/queue/queue.cpp) 62～66 deadline 只比大小、單位毫秒；aging 數「拍」；[holder.cpp](../../../../impls/aos-lock/src/holder/holder.cpp) 51／63／148 `acquired_at`＋`lease_ms` 牆鐘；daemon 3 秒／10 秒牆鐘（Q5 已裁留牆鐘）。→ **叉**，但 T1（`deadline()`）、T2（aos-lock）、T4（kernel deadline＋aging 改 tick，見 [01](01-逐項分類.md)）、T5～T7 全蓋到；**不另開**。

## ③ 原生機制：表列由 daemon 套；直接用的寫明搬不走什麼

- 已做那半：[limits.cpp](../../../../impls/aos-daemon/src/child/limits.cpp) 在子行程 `setrlimit`／`setuid`，表欄回顯；[docs/09](../../../../impls/aos-daemon/docs/09-份額.md) 21 已寫「daemon 自己被限＝起它的人包」。→ 勾。
- 直接用的：lib 工具 10 處 `killpg` 自己的子，[lib/docs/01](../../../../lib/docs/01-分層等.md) 46「不碰行程」已寫只殺自己起的 → 勾。**沒寫的**：[aos-sandbox README](../../../../cmd/aos-sandbox/README.md)（s6-setuidgid 帳號、sudoers、`/usr/local/bin`、`/srv/aos-run`、bind 路徑全是這台的，一句沒提）；aos-exec／inst 的 `setsid`＋`killpg`（[signals.cpp](../../../../impls/aos-exec/src/inst/signals.cpp) 53）docs 沒說 daemon 看不到這些孫行程。→ **K2**。

## ④ 行程狀態不是真相

- 看了：daemon adopt 先比 `boot_id` 再比 pid＋`started_at_ticks`（daemon.cpp 522～568）；aos-loop 只寫自己的 pid／boot_id 給上一層看（[window.cpp](../../../../impls/aos-loop/src/engine/window.cpp) 55～66）；`py/daemon_ctl/`、`cmd/`、`kernel/` grep `/proc|kill -0|boot_id` 為 0。→ 勾。
- 殘留：holder.cpp 102 讀 `/proc/<pid>/stat`、139 `kill(pid,0)` → **T2 已排**；[send.cpp](../../../../impls/aos-llm/src/send/send.cpp) 50 `kill(pid,0)` → **P5 已排**；`cli_session.py` 289 `p.kill()` 是自己的子。**不另開**。

## ⑤ root 例外

- 看了：daemon 程式不讀 systemd／cgroup／帳號；「這台的」全在樹外——`export AOS_LLM_KERNEL`（[kernel/docs/01](../../../../kernel/docs/01-llm-kernel.md) 40）、試驗場 `env.sh`、[sandbox root/setup.sh](../../../../cmd/aos-sandbox/root/setup.sh)、kernel.json 的 localhost 端點；範本與 kernel 定義 grep `/home|~/|/srv` 為 0，judge daemon.json 用 `{"$env":"AOS_CD"}` 相對。→ **勾**；缺的只是重建四步食譜，**P8 已排**。
