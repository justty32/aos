## 驗收與輸出摘要

### 不再靠 aos-tools 找模組

```sh
git grep -n 'which("aos-tools")\|which(.aos-tools.)' -- proto8 ':!proto8/thinking' ':!proto8/archive'
```

無輸出，結束碼 1＝零符合。lib 的 Python AST 掃描沒有 import aos_flags、aos_ws、daemon_ctl 或 py；程式碼中沒有把 proto8/py 加進 sys.path。`git grep` 的 cli_session／agent_files 符合項都屬新 lib 共用模組。py 程式碼提到 tool_io 的檔案只剩 aos_flags；README 的模組名稱屬說明。

### 複製出 repo

用 `cp -r` 將 clock、claude 與 agent-fsm 複製到 `/tmp/aos-k5-root-uam2q_k6/copied/`。PATH 只放暫存 python3 捷徑，沒有 aos-tools；`python3 -S` 停用 site 載入。

```sh
env -u PYTHONPATH PATH="$TMP/bin" /usr/bin/python3 -S "$TMP/copied/clock/_entry" --help
env PYTHONPATH="$PROTO8/py:$PROTO8/lib" PATH="$TMP/bin" /usr/bin/python3 -S "$TMP/copied/clock/_entry" --help
```

六支的兩種情境共 12 案全過。無依賴時退 1、沒有 traceback、沒有印出 repo 真路徑，也不提 aos-tools；clock／claude 的 stdout 與 stderr 各一行相同錯誤，四支 FSM 只印 stderr 一行。範例：

```text

```

給指定 PYTHONPATH 後六支 help 全部退 0。另驗 judge 缺模組只印 stderr、本地共用模組優先、symlink 的 realpath、缺 agent 套件子模組、內部壞 import 不掩蓋，以及 cli_session 直接 hook 入口，均通過。
