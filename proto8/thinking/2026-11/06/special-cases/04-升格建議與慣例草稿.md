# 升格建議與慣例草稿

判準照使用者的話：「往後可能還會有更多，其好處超過壞處很多」。本稿 #23、#25 對應內容已照 11-07 使用者裁定更新；其他草稿與歷史推薦仍見 [05](05-衝突與方向題.md)。

**11-07 裁定更新（sol 審查 #23、#25）**：本文升格判準、每群表與 K2／K4／K5 已同步 sol 審查 #23、#25；K3、K7 的晚審補註見各段。現行升格改為同型再出現時問「往後會更多嗎、好處遠大於壞處嗎」；第 3 次、清單 5 項或 3 天 2 項只提醒。K2 只保留原件「終端問、非終端不問」，不升為人殼通則；K4「近的贏」只限 tick；K5 只保留各開關個案，不收為通則。公開介面只限標頭、schema、interfaces.json。

## 什麼時候升格、什麼時候消掉（11-07 裁定更新）

1. **認名型一律消掉，不看次數**：一個例外要成立，得讓 A 寫死認得 B 的程式名、內部檔名、格式或錯誤字句（[03](03-歸群.md) 的甲形狀）→ 第一次出現就改成「B 宣告、A 照宣告」或「任何人都能寫的通用欄位」。範本：P6 → `auto_restart`。
2. **同型特例再出現時問一次**：「往後會更多嗎、好處遠大於壞處嗎」；依這個判準決定是否升格成一條判準，取代逐項清單。次數本身不決定升格。（11-07 使用者裁定 sol 審查 #23）
3. **第 3 次只提醒重看**：特例寫在發生的地方，可以註明「同型第 N 次」；第 3 次提醒照第 2 條重看，不自動升格。（11-07 使用者裁定 sol 審查 #23）
4. **清單長太快也只提醒**：一份例外清單到 5 項，或 3 天內加了 2 項，提醒照第 2 條重看；決定升格後才改成「判準＋現行表」（現行表只列現在有效的，作廢的移到續檔）。（11-07 使用者裁定 sol 審查 #23）
5. **「先不做」要寫等什麼**：範圍限縮型的例外，寫一句「等 X 發生才動」；X 發生了就照 1～4 重審。

照這五條，15 群的推薦如下。

## 慣例草稿

一句規則＋什麼時候適用＋怎麼宣告。

- **K1 出口給看不到下層的讀者時，可以附下層最後的錯**
  - 規則：一層的出口讀者看不到下層的 stderr（外部 agent、腦、寄信方），這一層失敗時可以把下層錯誤行的「代號與原因」接進自己那一行，或附下層 stderr 最後 2 KB；成功時不附；下層 stderr 照樣原樣透出。
  - 適用：出口的讀者是外部 agent、腦，或回信的收件人。aos 內部上下層之間（讀者也是程式、看得到 stderr 檔）不適用。
  - 宣告：在該程式 README 寫一行「透出：哪一種（末行代號／尾 2 KB）、給誰」；C-52 例外表改成這條判準，下面附現行表。
- **K2 只限不可逆動作的互動確認原件**（11-07 使用者裁定 sol 審查 #25）
  - 規則：原件的不可逆動作需要確認時，stdin 是終端才問；非終端不問，照原件已裁的旗標與確認方式處理。
  - 適用：只限已裁的不可逆確認，不推成「人打與程式叫只能依終端分岔」的通則。
  - 宣告：該指令自己的 `--help` 寫明確認行為；不因此另立所有人殼的提示或輸出規則。
- **K3 hub 變數沒設：報 Missing，或寫明一條退路；設了指不到就印提醒**
  - 規則：N-63 ② 改成「沒設＝`<名字>Missing`，或在條文寫明唯一一條退路」；設了但指不到時，照退路走並印一行 `warning:`。（11-07 晚審註：sol 審查 #8 已裁 aos-agent 指不到判官時維持 `MailboxMissing`，不走退路、不能繞過判官。）
  - 適用：`AOS_` 開頭、值是資料夾的變數。
  - 宣告：退路寫在四種性質表那一列。「印提醒」那半使用者 11-06 已裁（[env-portability](../env-portability/README.md) Q5）。
- **K4 tick 的設定近的贏**（11-07 使用者裁定 sol 審查 #25）
  - 規則：tick 的設定，自己這層明給的值蓋過上一層傳下來的值；子 daemon 自帶時鐘就用自己的。
  - 適用：只限 `AOS_TICK_INTERVAL` 與子 daemon 自帶時鐘等 tick 原件，不推廣到 `.env` 或所有設定。
  - 宣告：照 tick 自己的條文與介面寫明；其他環境變數與登記格照各自已裁的規則。
- **K5 程式與範本預設逐件決定，不收通則**（11-07 使用者裁定 sol 審查 #25）
  - 規則：只保留已裁個案各自的程式預設與範本設定；不要求新行為一律程式預設關、範本開。
  - 適用：只限已裁的那幾件開關；其他開關依自己的用途與使用者裁定決定。
  - 宣告：各程式 README 分別寫明自己的預設值與範本設定，不作所有新增開關的共同規矩。
- **K6 `_` 開頭的名字是 aos 的**
  - 規則：daemon 表的 proc 名、定義資料夾裡的檔名、信件 body 的 key，`_` 開頭保留給 aos；使用者自己取的名字不准 `_` 開頭。
  - 適用：`_tick`、`_entry`、`_tooldef.json`；以後新的保留名都照這個取。`ping` 這類舊保留字列在同一張表。
  - 宣告：C-54 加一句，保留名一張表。
- **K7 別人的 stack：對方宣告了才寫**
  - 規則：A 不寫 B 的 stack，除非 B 在 `interfaces.json` 宣告了「這個檔可以由外面寫」（覆蓋層），或 A 是起 B 的那一方、而且 B 還沒開跑。開跑後的其他事一律經 B 的信箱或 ctl。（11-07 晚審註：sol 審查 #24 已拿掉「或 A 是起 B 的那一方、而且 B 還沒開跑」這個使用者沒裁的例外；只照對方宣告的介面寫。）
  - 適用：aos-agent `llm set`／`tools add`、thought、agents。
  - 宣告：覆蓋層的檔名只寫在 `interfaces.json` 一處，aos-agent 與身體都照它讀（現在 llm 照宣告、tools 寫死 `<stack>/tools.json`，P47）。
