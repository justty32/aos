## 凍住（fs-image）

1. **硬凍切到正在打外部 CLI 的 eca**（claude／codex，900 秒牆鐘）：子 loop 被 SIGTERM、CLI 子行程跟著收；醒來那題重跑，外部那邊可能已經記了一次（扣額度、留半個 session）。對外本來就是第②類，接受；寫進食譜「凍之前先看有沒有 eca 在飛」。
2. **凍住期間人手改 `procs_state.json`、小格 `ctl.json`**：醒來 adopt 照新表起。**11-07 #15-2 已解除原先「首份 ctl 當基準線、醒來 stop 落空」的限制**：子 loop 第一拍比上一份 state 的有效 ctl_seq，相同 seq 已套用過才略過；不同或缺回音則照做。凍住時可寫新 seq 的 pause／resume／stop，醒來第一拍生效；沒有 state 窗便無法跨啟動去重。
3. **凍住後搬到另一台機器醒**：`boot_id` 不同＝表上全當死（P1）→ 照名單重起，對；`sleeping` 列本來 pid 就是 null，wake 照舊。只有 `responded_at` 牆鐘跨機器有差→ P7 用 tick 就沒事。
4. **兩棵凍住的樹合成一棵**（把子樹搬進另一棵底下）：tick 值不同、`AOS_TICK` 指不同檔 → 子樹裡存的 `deadline_tick`、`acquired_tick` 全失去意義。規定一句（T8 寫進 N-04 旁）：併樹＝子樹換看父樹時鐘、舊期限作廢重算。
5. **有序寄信的 `order.lock/` 持有者被硬凍**：鎖只握到 rename 完、極短；SIGTERM 到時最多缺一號（aos-post 本來就說會缺號）。只有軟凍（SIGSTOP 式）才會讓牆鐘租約過期被搶→ T2 改 tick 就解。
6. **根 daemon 睡了、`AOS_TICK` 指的時鐘在樹外還在走**（另一棵樹的 aos-tick、人手 cron）：醒來期限全過。tick-time 02 #4 列過多時鐘；這裡補規矩候選：**一棵樹的時鐘要在這棵樹裡**（根 daemon 底下），搬家、凍住才跟著走。
7. **軟凍（D1 若裁要）公告第 N 回合、有 proc 不看時鐘**（C-37 可看可不看）：到了第 N 回合它還在跑→ 根 daemon 照硬凍收它。所以軟凍＝「先公告、到點硬凍」，不是「等大家都說好」。

## 時鐘（tick）

8. **沙箱裡的工具讀不到 `AOS_TICK` 指的檔**（沒綁）＝「沒設」＝期限永不到：`memory_write` 的鎖租約永不過期、thought 的 `timeout_ticks` 永不到。sandbox.json 要綁時鐘檔（ro）——寫進 P5 的 README 與 W 的沙箱段。
9. **lib 工具沒 `AOS_TICK` 每次呼叫都印 warning**：工具是短命行程，act 每叫一次就印一行→ stderr 洗版、aos-mcp 把 stderr 尾巴附給外部 agent（11-05 裁）會夾進去。→ [README 代定 5](README.md#fable-代定可翻案)：工具不印，長住的才印。
10. **`cp -a` 整包含時鐘檔**：兩份 image 各走各的 tick，之後互寄信的 `sent_tick` 對不上。規矩候選（T8）：跨樹的 tick 不能比，只在同一時鐘下比；跨樹看 `sent_at`。
11. **`AOS_TICK_INTERVAL` 的「默契」只在連續運行時成立**：凍 8 小時＝0 tick；日誌、人看的時間一律用 `sent_at`／`at`（牆鐘），不要拿 tick 換算成「幾點」。寫進 N-04 旁一句。
12. **`responded_at`（P2，牆鐘）與 `responded_tick`（P7）兩欄並存**：tick 欄只在有 `AOS_TICK` 時出現（不是寫 null）；N-09 有變才寫照舊。
13. **`AOS_TICK` 指到 image 外的檔**（例 `/tmp/clock`）：整包搬走時鐘沒跟，醒來讀不到＝當 0 → 期限全「未到」永不過期、沒人警告。T7 的 daemon 表 `tick` 欄顯示 0，人看得出；要不要 daemon 起來時 warning「tick file missing」——代定印。
14. **inst `timeout_ticks` 誰判**：aos-exec 是 C、本來只等 waitpid；加 poll `AOS_TICK` 等於多一個計時路徑。替代：aos-exec 不管、由 loop／daemon 這層判（它們本來就每拍看）。T5 實作時選——傾向後者（aos-exec 保持最小，C-74 核心層）。
15. **tick 檔被 aos-tick 寫、同時被 N 個 proc 讀**：寫法是 rename，讀永遠整份；但讀到的值可能比「現在」舊一格——期限比較只能「≥」不能「＝」，寫進 T1 的 `now_tick()` 說明。

## 非同步呼叫（只補 body-protocol 03 沒列的）

16. **body 裡的路徑**（函數 stdin 的 `path`、沙箱特例信箱的 inst `cwd`／`$ref`）是絕對路徑：image 搬家後斷。收信端把 body 存進信資料夾、以 `cur/<信名>/` 為基準解（kernel-daemon 08 代定 3 同法，body-protocol 選項 A 的 runner 已是這樣）；絕對路徑照寫、斷了自擔（portable-flow 已定「指外面自擔」）。
17. **人手 `aos-post send` 寄的信**：`sender`＝cwd；沒給 `--reply-to`＝notification、收信端不回→ 人看不到結果。文件寫「要看結果必給 `--reply-to`」。
18. **拿判官模式 1 當收信端入口**（body-protocol 02 選項 C 的一種做法）：判官 `allowed` 是 proc 名字白名單、不是函數白名單；要兼用得多認一種 key。五題裁了再說。
19. **寄信方在另一棵沒凍的樹**：收信樹凍住、寄信方的 tick 照走→ 逾時失敗→ 醒來變遲到回信（body-protocol 03 列的「收信者凍住」是同一棵樹的情況）；跨樹呼叫的逾時沒有共同時鐘可依，只能靠寄信方自己的。

## json-argv

20. **`--a.b x` 跟 stdin `{"a": {...}}` 合併**：03 代定「頂層鍵整個換、不深合併」會讓 `--a.b x` 蓋掉整個 `a` → J1 改成巢狀路徑只換那一葉（[README 代定 6](README.md#fable-代定可翻案)）。
21. **鍵本身含 `.`**（使用者說可接受）：旗標一律當巢狀，含 `.` 的鍵只能從 stdin 給；`--help` 的 input 行註明。
22. **J1 做完、J2 沒做的過渡期**：18 支 lib 工具還是手寫 `HELP`＋自己讀 stdin，`start()` 新回傳的 dict 沒人用——不是壞，但 `--help` 兩種版面並存一陣子；J2 排近一點就好。
