# 建議

**總原則一句**：環境變數照舊只放「位置」與「這台的東西」，但**從環境讀到的值不准落檔**；要記就記**名字**（`{"$env": X}`）或**相對 stack／定義的路徑**，到用的那一跳才從當下的環境解。

## 維持環境變數就好的

- aos-exec 的六個（`AOS_WS`、`AOS_STACK`、`AOS_CF`、`AOS_CD`、`AOS_CO`、`AOS_ENTRY`）：每跳重給，正是「醒來用這台的」。
- 樹內 hub `AOS_DAEMON`：daemon 每次醒來重設；表上已存相對或指示詞。
- 跨樹 hub `AOS_LLM_KERNEL`、`AOS_KERNEL`（指別棵樹時）、絕對的 `AOS_MEMORY`：維持 env，**但只准 root 層設**（人 export、`env.sh`）。
- `AOS_TICK`：T7 由 daemon 設給底下、每次醒來重設，不進 `.env`。
- 密鑰：只走環境；定義裡只准寫 `{"$env": X}` 或樹外 `$ref`。
- PATH、HOME、LANG、TZ：外部，照舊。
- **不建議**把 hub 改寫進檔：hub 的值本來就是「這台的位置」，寫進檔＝凍住舊機器，正好跟可遷移性相反。

## 搬家時要重設的（給 no-pid P8 食譜，接在 os-concepts 10 重建 root 四步的第 ③ 步）

**凍之前**
1. 等問腦收完再 sleep（`mailbox/cur/` 空了才凍）——R1、R6 做完前這條是唯一不讓金鑰與舊 exec 進 image 的辦法。
2. `grep -rIl "$HOME\|<舊根路徑>" <image>` 掃一次；有中的看是不是登記檔（P2）或 `.env`（P4）。

**新機器上、`aos-exec` 醒來之前（root 層，人做）**
3. 跑 repo 的 `proto8/install.sh`（PATH 上要有 aos 指令）。
4. `export` 跨樹 hub：`AOS_LLM_KERNEL`（新機器 llm kernel 的 stack）、要走判官才設 `AOS_KERNEL`、知識庫不在樹裡才設 `AOS_MEMORY`；用試驗場的 `env.sh` 就 `source` 新位置那份。
5. `export` 密鑰：各 `endpoints/*/_entry` 的 `--key-env` 列的名字（grep `key-env` 就是清單；E1 前是 kernel.json `{"$env": X}` 列的名字），export 在起 llm daemon 的那個殼。
6. **確認不該有的沒有**：起 llm daemon 的殼 `unset AOS_KERNEL`；`AOS_DAEMON` 不手設（讓 daemon 給）；`AOS_TICK` 不手設（T7 後由 daemon 給）。
7. 外部 CLI 的 session（`~/.claude`、`~/.codex`）要續接就另外搬，不搬＝那類 agent 從新對話開始。

**醒來之後**
8. 只搬了 agent 那棵（kernel 沒一起搬）：kernel.json `budget.senders` 的鍵改成新的相對位置。
9. **檢查各工具的登記檔**（定義的 `tools.json` 與 stack 裡的覆蓋層）：`aos-tools ls` 看 path 還在不在（絕對的會 `PathMissing`），`env` 裡存的路徑與值對不對這台；不對就重新 `aos-tools add --override`（登記檔照現況贏過外面的 export，使用者 11-06 選「C 照現況」，所以只 export 新值不夠）；eca 小格（R7 前）的 `ws.txt`／`stack.txt` 改成新位置。
