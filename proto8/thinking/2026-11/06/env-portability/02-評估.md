# 評估：環境變數對可遷移性的影響

判準（C-83／N-67）：一棵樹（定義＋stack）凍住，`cp -a` 到另一台 Linux、換路徑換帳號，`aos-exec` 醒來能不能接著跑、意思有沒有變。

**一句話**：環境變數**只活在行程裡**的時候都沒事——醒來時新機器重給一份，正好就是「搬家後用這台的值」。出事的都在**值被寫進檔**的那一刻：寫進去的是舊機器的絕對路徑或密鑰，跟著 image 走。

## 六個判準逐項看

已抽到 [02-判準.csv](02-判準.csv)（6 列）。欄位：`criterion`（判準）、`result`（結果）。

摘要：① 值幾乎都是絕對路徑，不落檔就沒關係；② **落檔四處**（kernel `request.json` 金鑰、aos-tools 登記檔、eca 小格、定義 `.env`），daemon 表與 agent stack 已乾淨；③ 換意思大多是故意的外接，危險的是沒設不報錯的 `AOS_KERNEL`／`AOS_TICK`；④ `.env` 外層贏對可遷移性是好事，aos-tools 登記格內層贏是反例；⑤ 密鑰會進 image；⑥ 跨樹 hub、PATH、HOME、密鑰只該在 root 層設。

## 有問題的四個（現在就會讓搬家壞掉或換意思）

### P1 金鑰落檔（kernel.json 的 key）
- 情境：kernel.json 某包 `"key": {"$env": "LITELLM_KEY"}`。問腦問到一半整樹 sleep、`cp -a` 帶走。
- 實測 X1（/tmp/envp）：在飛時 `grep -r sk-test-XYZ` 只中 `mailbox/cur/<信>/request.json`（`"key": "sk-test-XYZ"`，權限 644）；SIGINT 睡著後仍在；**醒來時故意不設變數，那封照樣用 image 裡的舊金鑰答完**；之後的新信才 `DirectiveBad`。答完信資料夾整個刪掉。
- 為什麼：[scan.cpp](../../../../impls/aos-llm-kernel/src/serve/scan.cpp) 整包 `resolve`，[serve.cpp](../../../../impls/aos-llm-kernel/src/serve/serve.cpp) 把解好的包寫進 `request.json` 再交 endpoint 函數。json-argv 04 說「金鑰走 JSON、不走 env 是現成範例」，只看了定義那層，沒看到中途落檔。

### P2 aos-tools add 把 env 與路徑凍進登記檔（使用者 11-06 選「C 照現況」：已知代價、不修）
- 情境：`aos-tools add --envs AOS_MEMORY=/abs/kb --env-file my.env 工具`，之後整樹搬家。
- 實測 X2：登記檔存 `"path": "/tmp/envp/x2/tools/memory"`（絕對）、`"env": {"AOS_MEMORY": "/tmp/envp/x2/old/kb", "MY_KEY": "sk-test-ABC"}`（明文）；env 檔的 `FOO=${HOME}/foo` 存成 `/home/guanyu/foo`（`$AOS_MEMORY/x` 沒大括號反而原樣存）。搬後 call＝`PathMissing`；放回舊位置再 call，**登記的舊 `AOS_MEMORY` 蓋過外面 export 的新值**。`--overlay` 時 path 存相對、搬後照樣能 call，但 env 一樣凍成明文。
- 這是「在 add 當下讀取並存下內容」的直接後果：存下的是那台機器、那一刻的值。
- **使用者 11-06 選「C 照現況」**（聽過 `DATA=${HOME}/data` 搬到別台會指錯、密鑰會落明文的例子後）：照舊存展開後的值、登記檔贏；搬家時靠食譜檢查登記檔、必要時重新 add（[03](03-建議與搬家食譜.md) 第 9 步）。

### P3 eca 小格記下絕對 ws／stack（程式判斷、未實測）
- 情境：claude／codex 型 agent 的小格寫 `ws.txt`、`stack.txt`（[cli_session](../../../../py/cli_session.py) `note_cell`），整樹搬家後「叫回畫面」。
- 程式：`open_cell` 讀回這兩個檔、照它開 `aos-mcp --ws … --stack …`＝指舊位置（舊樹不在就找不到、在就寫到舊樹）。`mcp.json` 每次重寫不算；`transcripts/` symlink 指 `~/.claude` 屬外接。
- 沒實測：要 tmux＋claude，留給 P8。

### （降級）寄件人絕對路徑當額度帳鍵
- 情境：kernel.json `budget.senders` 限某個 agent 一天 1 次；agent 的 ws 搬到別的路徑。
- 實測 X3：搬前第二封 `BudgetMissing`；搬後兩封都過——**上限悄悄失效**；`used.json` 同時有新舊兩個絕對路徑鍵。
- 現況：實測用的是舊執行檔；T 隊 b190e00c（T1＋T4）已把鍵改相對 kernel stack，所以**降成要注意**：agent 跟 kernel 在同一棵樹一起搬就對；分開搬（跨樹）仍會失效——寄件人身分本身是絕對路徑（[aos::identity](../../../../impls/aos-util/src/proc.cpp)）。

### P4 定義的 `.env` 寫絕對 hub 路徑（文件建議的寫法）
- 情境：照 [kernel docs/01](../../../../kernel/docs/01-llm-kernel.md)「或寫進那台定義的 `.env`，絕對路徑」，把 `AOS_LLM_KERNEL=/home/a/llm_kernel` 寫進 agent daemon 的定義。
- 實測 X4：搬到 B 後外面沒 export＝仍指 A（舊樹還在＝**悄悄寄到舊機器那套**；不在＝寄信失敗）；export 了＝外層贏、指 B；加 `--dotenv-override`＝又指回 A。另發現：寫 `AOS_LLM_KERNEL=${AOS_CD}/../llm_kernel` 會展開成新位置，**可搬**。

## 要注意的（不會壞，但要知道；完整見 01 兩份資料檔）

- **沒設不報錯的 `AOS_KERNEL`／`AOS_TICK`**：少設＝悄悄走退路；`AOS_TICK` 設了缺檔＝當成 0（aos-util `now_tick`），指舊位置＝tick 停在 0（Q5）。
- **kernel 在飛的 `proc.json`／`loop.json` 存 endpoint 函數絕對路徑**（程式判斷）：有問腦在飛＋搬家＝醒來指舊位置；外接已裁作廢重寄，影響小，併 P8 驗。
- **任意 `{"$env": X}`**：定義可以依賴任何變數卻不用宣告，搬家沒清單可查。
- **絕對路徑的回顯**：回信 `sender`、aos-lock `holder.json`（鎖不是真相，T2 改）。
- **外接**：HOME 底下的 CLI session（`~/.claude`、`~/.codex`）；起 llm daemon 的殼多帶 `AOS_KERNEL` 就掛錯台（K6）。

## 安全的

aos-exec 的 `AOS_STACK`／`AOS_CF`／`AOS_CD`／`AOS_CO`／`AOS_ENTRY`、樹內 hub `AOS_DAEMON`（daemon 每次醒來重設、表上存相對或指示詞）、`AOS_AGENT`、`_tooldef.json` 與 sandbox 的 `env` 陣列（只存名字）、試驗場 `env.sh`（從自己位置算，正是 root 例外該有的樣子）、LANG／TZ／TMUX 等外部變數。
