> 啊，我又有一個想法，還得再派一隊：之所以大多東西都要走json+檔案系統，這是為了可遷移性。而雖然我們有.env，但環境變數的濫用仍可能對可遷移性造成損害。請綜覽我們的現狀，給出評估，看看有哪裡需要注意。

## 一句話結論

環境變數**只活在行程裡**時都沒事——醒來時新機器重給一份，正好就是「搬家後用這台的值」；出事的是**值被寫進檔**的四處：kernel 把解開的**金鑰明文寫進信資料夾**、`aos-tools add` 把 **env 值與絕對路徑凍進登記檔**（而且蓋過新機器的）、claude／codex 型 agent 的小格**記下絕對 ws／stack**、叫回畫面時讀回（程式判斷）、文件建議把**絕對 hub 路徑寫進定義的 `.env`**。前兩個與最後一個在 /tmp 複本實測重現過；另一個實測重現的「寄件人絕對路徑當額度鍵、搬了上限悄悄失效」T 隊 b190e00c 已改相對、降成要注意。所以要加的規矩不是「少用環境變數」，而是「**從環境讀到的值不准落檔**」。

## 方向題（細節與後果見 [05](05-衝突與方向題.md)；推薦放第一）

1. **Q1 金鑰落檔怎麼修**：推薦 kernel 不解金鑰、`request.json` 存 `{"$env": X}` 原樣，由 endpoint 函數那一跳解｜kernel 解好走 pipe 不寫檔｜只在食譜寫「凍前等問腦收完」。
2. **Q2 aos-tools 登記格的 env 跟外面環境誰贏**：推薦外面有設的贏（跟 N-59 同向）｜照現況登記格贏。
3. **Q3 `--envs`／`--env-file` 存什麼**：推薦存原字串、call 時才展開 `${}`＋help 寫「密鑰別用 --envs」｜只准存名字指示詞｜照現況存展開後字面。
4. **Q4 N-67 加三項要不要交條文隊**：推薦要｜只寫進各程式 README。
5. **Q5 `AOS_KERNEL`／`AOS_TICK` 設了但指不到時**：推薦印 warning 行｜照現況悄悄退路。

不用問、照原則能直接做的：kernel docs/01 改建議（跨樹 hub 只在 root 層 export，或寫 `${AOS_CD}/..`）、kernel 在飛的 exec 存相對、eca 小格存相對、搬家九步併 P8。
