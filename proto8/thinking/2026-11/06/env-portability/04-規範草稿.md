# 規範草稿：N-67 加三項（只草稿，條號與落點由條文隊定）

**為什麼加在 N-67、不另開一條**：三項都是「一棵樹凍住能搬」的檢查項，跟 N-67 ①～⑥ 同一個問題；另開一條會跟 N-63（hub 怎麼命名、沒設報什麼）重疊。N-63 只管「hub 怎麼指」，不管「值能不能落檔」。

**使用者已有的原話可以當依據**：「aos體系下，唯一與json無關的，就是環境變數」（11-05，四種性質表註）——所以環境變數的**值**一旦寫進 JSON，就把唯一不是 JSON 的東西偷渡進了 image。

## 草稿

> ⑦ **環境變數的值不落檔**：程式不把從環境讀到的值（路徑、密鑰、任何字串）寫進 stack 或定義；要記就記**名字**（`{"$env": X}`）或**相對 stack／定義的路徑**，到用的那一跳才從當下的環境解。例外：每次起來都重寫、沒人讀回的**回顯**欄（例 daemon 表的 `daemon` 欄），寫的程式在自己文件標「回顯、不讀回」。
>
> ⑧ **密鑰只走環境、不落檔**：定義裡的密鑰只准寫成 `{"$env": X}` 或指向樹外的 `$ref`；解開的值只活在行程的記憶體與 pipe 裡，不寫進信、信資料夾、窗、登記檔。凍住的 image 裡不該 grep 得到任何密鑰。
>
> ⑨ **環境變數只指兩種地方**：樹內（daemon 或 aos-exec 每次醒來重設的，或從 `$AOS_CD` 算出來的）、或 root 層以上（人 export、root 的 `env.sh`）。定義的 `.env` 不寫絕對路徑；跨樹的 hub（`AOS_LLM_KERNEL` 等）只在 root 層設。

**檢驗法併 ⑥**：睡著 → `cp -a` 到別的路徑 → `grep -rIl` 舊根路徑與每個密鑰值，應為零（回顯欄除外）→ 醒來接著跑。

## 不建議加的

- **「樹裡不准存絕對路徑」一條獨立的禁令**：N-67 ① 已管「image 裡的位址一律相對」，⑦ 補上「從環境來的也算」就夠；再寫一條是同一件事兩處說（C-54 一詞一義的精神）。
- **「環境變數一律改成寫進檔」**：hub 的值就是「這台的位置」，寫進檔＝凍住舊機器，跟可遷移性相反（[03](03-建議與搬家食譜.md) 維持的那段）。
