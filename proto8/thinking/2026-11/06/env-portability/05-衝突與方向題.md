## 方向題（推薦放第一）

### Q1 金鑰落檔怎麼修
- **A（推薦）kernel 不解金鑰，交 endpoint 函數那一跳解**：`request.json` 存 `{"$env": "LITELLM_KEY"}` 原樣。後果：image 裡沒密鑰；醒在新機器用新機器的金鑰；沒設＝那封回錯。代價：endpoint 函數（`llm_http` 與以後的）要會解 `$env`（tool_io 共用一個函數就好）；「kernel 解指示詞、函數只吃平的 JSON」這個分工破一個口。
- B kernel 照解，但經 stdin pipe 交給函數、不寫 `request.json`：後果同 A 但醒來時要重解（行程沒了、pipe 沒了），kernel 跑法要改（現在是 daemon 照 loop.json 跑、stdin 讀檔），改動大。
- C 不改程式，食譜寫「凍前等問腦收完」：零改動，但靠人記得。

### Q2 aos-tools 登記格的 env 跟外面環境誰贏
- **A（推薦）外面有設的贏，登記格只補沒設的**：跟 N-59 同向；搬家後新機器 export 的新值生效。代價：想「強制蓋掉外面」的人沒辦法（目前沒有這種用例；要的話以後加 `--override` 類旗標）。
- B 照現況登記格贏：登記的人說了算；搬家要逐個重 add。

### Q3 `--envs`／`--env-file` 存什麼
- **A（推薦）存原字串、不展開 `${}`，call 時才展開**；help 加一句「密鑰別用 --envs，用 export」。後果：`FOO=${HOME}/foo` 跟著新機器的 HOME 走；改動小。
- B 只准存名字指示詞（`{"$env": X}`）或相對路徑：最乾淨，但 `--envs K=V` 的用法等於廢掉，json-argv（10～13）剛做的「add 當下讀取並存下內容」要翻。
- C 照現況存展開後字面。

### Q4 N-67 加三項（⑦ 值不落檔、⑧ 密鑰不落檔、⑨ 只指樹內或 root 層）要不要交條文隊
- **A（推薦）要**，照 [04](04-規範草稿.md) 草稿，條號與落點由條文隊定。
- B 只寫進各程式 README 當慣例，不進條文。

### Q5 `AOS_KERNEL`／`AOS_TICK` 設了但指不到時
- **A（推薦）印 warning 行**（不報錯、不改退路）：新機器少搬一個資料夾會被看見。現況 `AOS_TICK` 設了缺檔＝當成 0（b190e00c），比退牆鐘更隱形。
- B 照現況悄悄退路。
