## 草稿（暫稱 C-54 R14，接在 R13 後；照 R1～R2「先一句白話再取名」寫）

1. **「信箱」是機制名，不是用途名。** 凡是 N-16 那種資料夾（`tmp/`、`new/`、`cur/`、選用 `archive/`，信＝資料夾＋`letter.json`）都叫信箱；講機制的名字一律用 mailbox：aos-post 的型別與函式、錯誤代號 `MailboxMissing`／`MailboxBad`、壞信欄 `mailbox_warning`（使用者 11-02 定的通稱，不分這箱拿來做什麼）。
2. **資料夾、設定 key、窗裡回報箱名的欄位，照「這箱拿來做什麼」取名**（R2 的一句白話），分三種：
   - **queue**＝「寄的人全帶序號（`--ordered`）、一個讀者、照順序一封封消費，順序本身有意思」。四條都成立才叫 queue。現有唯一一個：agent 的 `$AOS_STACK/queue/`（N-16 10-30、P-11）。
   - **`<主題>_mailbox`／`mailbox`**＝收件箱：很多人寄、一封封各自獨立、可以要回信、讀的人可以整批拿；處理順序用 aos-post 預設（有序在前、無序照名字）或讀的人自己排（見 3）。例 `procs_ctl_mailbox/`、llm kernel 的 `mailbox/`。
   - **照內容取的名**＝收的東西有固定名字時直接用那個名詞的複數：`requests/`（判官收的掛子請求）、`reply/`、`daemon_reply/`（回信）。這也是收件箱，只是名字講裝什麼。
3. **讀的人另有排法（優先序、期限、配額），信箱名不叫 queue。** 排法寫在讀的程式的說明與 `order` 這類函式，不靠名字暗示。llm kernel 照級數＋aging 挑信，它的箱照舊叫 `mailbox/`。
4. **記錄排隊狀況的檔不是箱**（N-14：鎖、信箱都不算窗）：一個寫者、只看最新那份的叫窗，照 N-14 開；名字可以叫 `queue.json`（「現在誰在排、排第幾」），不受上面「四條都成立」的限制，但檔頭一句要寫明排法（先來先掛／優先序）。例：判官 `queue.json`（窗，先來先掛，未實作）、llm kernel `queue.json`（kernel 自己的排隊帳，N-13 身體自訂名）。
5. **「有序」只說信，不說箱。** 文件寫「有序的信」「帶序號寄」；要講箱就寫「當 queue 用的信箱」，不寫「有序信箱」——11-04 起箱沒有這個屬性（[02](02-有序是什麼.md)）。
6. **改名判準**（給以後新的箱）：寄的人程式裡全帶 `--ordered`、而且讀的人照順序消費、順序錯了結果就錯 → 叫 queue；其中任一條不成立 → 叫收件箱（照 2 的後兩種）。只因「順序有一點影響」（例 daemon 同一圈 add 又 rm）不升格成 queue。

## 跟既有條文對不對得上

| 條 | 對上嗎 | 說明 |
|---|---|---|
| N-16（10-30 queue 那點） | 對上 | 原文「agent 層把自己的輸入叫 queue……『信箱』這個詞留給 agent 之間的請求投遞（一封封獨立的信，可能要回信、可以不照順序）」——草稿 2 就是把這句一般化 |
| N-16（11-04 有序無序同箱） | 對上 | 草稿 5 補的是讀法：「它就是本條的有順序投遞」照「寄的都帶序號」讀 |
| N-14 | 對上 | 草稿 4：`queue.json` 是窗或身體自己的帳，不是箱 |
| N-66 一箱一函數 | 對上 | 箱名講用途（草稿 2）正好等於講「後面接哪個函數」 |
| C-54 R4 一詞一義 | **要使用者看** | queue 會有兩個用法：箱（嚴格 FIFO）與 `queue.json`（排隊狀況，llm kernel 是優先序）。草稿 4 把後者講成「排隊」這個意思的另一面；不接受就改窗名（方向題 2） |
| C-54 R7 例、命名.md | 對上 | `procs_ctl_mailbox` 是 11-03 定的例子，草稿不動它 |
| 名詞表板子比喻「信箱＝mailbox FIFO」 | **對不上** | 只有 queue 是 FIFO；一般信箱是收件箱、llm kernel 是優先序（方向題 3） |
| C-54 錯誤代號六種 | 對上 | 不新增代號 |
