## 結論一句

**「有序」是一封信的屬性，不是信箱的屬性。** 寄的人帶 `--ordered` 這封信才有序號；信箱本身沒有「我是有序箱」這個設定，也不擋無序的信。所以「這個 mailbox 是有序的」在程式裡不成立，能成立的只有「寄進這個箱子的程式，慣例上全都帶 `--ordered`」——全 repo 只有 agent 的 `queue/` 是這樣。

## 「有序」保證了什麼（[aos-post 標頭](../../../../impls/aos-post/include/aos/post.hpp)、`send.cpp`、`mailbox.cpp`）

| 層 | 有序的信（`--ordered`） | 無序的信（預設） |
|---|---|---|
| 投遞順序 | 拿 `order.lock/` → 讀 `order.json` 的 N → 寫 N+1 → rename 進 `new/<N+1 零填 12 位>.<尾名>` → 放鎖。鎖握到 rename 完，所以**到達 `new/` 的先後＝序號**，嚴格 FIFO | 不拿鎖，誰先 rename 誰先到 |
| 名字 | `000000000007.<尾名>` | 預設 `<UTC 奈秒 20 位>.<pid>.<started_at_ticks>`（寫信開始時取），或寄的人自己給的任意名 |
| 處理順序（`sort_letters`，`take`／`take-all`／`see`、`done` 預設、daemon 排殘骸都用它） | **全部排在無序的前面**，彼此照序號 | 排在後面，照名字字典序：預設名≈開始寫信的先後，不是到達的先後；自己給的名照字面 |
| 缺號 | 不等、直接拿下一號（寄的人死在寫計數與 rename 之間只缺號、不重號） | — |

所以「有序」同時做了兩件事：

1. **FIFO**：有序的信彼此嚴格照寄出（取號）順序處理。
2. **兩級優先**：有序整級排在無序前面；無序的被有序的一直插隊也接受（N-16 原文）。

它**不是**：

- 不是「處理順序之外的優先序」：沒有 `priority` 欄、沒有級數、沒有 aging。這些只有 llm kernel 自己有（下面）。
- 不是「一次一個讀者」：`take` 靠 rename 只保證一封信只有一個人拿到；兩個讀者同時拿，各自都照順序，但合起來的處理順序就沒保證。N-16 寫「一個信箱預設一個處理者」，是慣例、程式不擋。
- 不是「一次處理一封」：`take-all` 一次拿整批，讀的人怎麼用這批是它的事（eca 一次全接成一段、daemon 一封封套）。

## 各箱實際怎麼用（細目在 [01-盤點.csv](01-盤點.csv)）

| 箱 | 誰寄、帶不帶 `--ordered` | 誰讀、怎麼讀 | 順序對結果重不重要 | 實際是 |
|---|---|---|---|---|
| agent 的 `$AOS_STACK/queue/` | `aos-agent say`（`aos_ws.say`）、agent-fsm idle 與 aos-eca-turn 的開場白：**全帶** | 那隻 agent 一個：idle／eca-turn `take-all`，照順序接進 `history.jsonl`，接完 `done` 刪 | 重要（對話的先後） | **嚴格 FIFO、一個讀者、依序消費**＝queue |
| daemon 的 `procs_ctl_mailbox/` | `aos-daemon-ctl`（py/daemon_ctl）、llm kernel 掛信、判官轉寄：**不帶**（判官只在原信有序時照帶） | daemon 一個：每圈 `take-all`，照 `sort_letters` 一封封套進「底」，**後面的蓋前面的**，套完對一次表，`done` 刪 | 同一圈裡互相衝突的信（add X 又 rm X）才有差；平常無差 | 收件箱；順序是「名字≈時間」近似，不是 FIFO |
| 判官的 `$AOS_STACK/requests/` | 同上（經 `AOS_KERNEL` 改寄這裡）：不帶 | 判官一個：每輪 `take-all`，照處理順序逐封判，轉寄或回拒信，`done` 刪；排隊選項（os-impl 03／05，未實作）會讓等格的信留在 `cur/`、排隊順序寫在窗 `queue.json` | 有排隊選項後「先來先掛」才重要 | 收件箱（＋未來的等候區） |
| llm kernel 的 `$AOS_STACK/mailbox/` | `aos-llm send`／`ask`：不帶 | kernel 一個（flock 擋第二個）：**不用 `sort_letters`**，自己排：級數＋aging → deadline → 包的 speed → 等得久 → 信名；照 slots 補位，選到才 rename 進 `cur/`，在飛的留在 `cur/<信>/` 當問腦 proc 的 stack，回完整封刪 | 重要，但照**優先序**，不是先來後到 | 優先序排程的待辦池 |
| `<kernel>/mailbox/reply/`、py 的 `daemon_reply/`（或 `<ctl 信箱>/reply/`） | kernel／daemon 回信：不帶 | **很多個讀者共用**，每人只認 `in_reply_to` 是自己那封的（flock 擋同時收），十分鐘舊信清掉 | 不重要 | 共用回信信箱，挑著收 |
| `archive/`、`tmp/`、`cur/` 等格 | — | — | — | 箱裡的格，不是箱 |

## 11-04 改成「有序無序同箱」之後

- 改版前（10-29 起）有序信箱只收有序名，名字不是有序的算壞信；那時「這是有序信箱」是箱的屬性。11-04 aos-post 改版（使用者 11-03 晚「aos-post這塊都按照建議。」）起同箱都收，**箱的屬性就沒了**，只剩信的屬性。
- 所以每個箱子在程式上都「同時能裝兩種信」。實際裝了兩種的只有 `requests/` 與 `procs_ctl_mailbox/`（判官把有序原信照有序轉）；agent 的 `queue/` 實際只會收到有序的，除非有人直接 `aos-post send` 不帶旗標（照樣收、排最後）。
- 「有序」這個字因此有兩個讀法，文件要分清：**有序的信**（帶序號，程式事實）、**拿來當 queue 的信箱**（寄的人全帶序號、一個讀者依序消費，用法慣例）。N-16 的 10-30「agent 層把自己的輸入叫 queue，它就是本條的有順序投遞」講的是後者。
