# 慣例草案（續）：H9～H16（接 [03](03-慣例草案.md)）

## H9 stdin 與旗標並存、優先序

**給人用的指令 stdin 只放「內容」（say 的話、post／llm 的 body、json set 的值），不放參數；旗標 ＞ stdin ＞ 環境變數（使用者 11-05 晚）；需要內容但 stdin 是終端＝`ArgumentsBad stdin is a terminal`、不卡。** 不做「旗標 → stdin JSON 鍵」映射（json-argv Q1 推薦不做；使用者「依實際需要」——要做的那支自己做、不當通則）。C++ 吃 body 的子命令（`aos-post send／done`、`aos-llm send／ask`、`aos-json set／batch…`）現在碰終端會等 EOF（02 的 8 列）：照 lib 規則同一招，`isatty` 就當沒給＝`ArgumentsBad`（`aos-json set` 值可以從 argv 給、不受影響）。

## H10 錯誤訊息與結束碼（接三扇門）

**錯誤行 `程式: error: 代號 原因 (…)` 照 R1／R5；括號裡只放該層的指路：頂層缺子命令／不認得＝`(add, rm, ls, …; see 程式 --help)`；子命令層缺參數、位置參數不對、開關帶值＝`(usage: 那個子命令 help 的 usage 行)`；子命令前 FlagUnknown 不附（D9 照舊）；子命令後 FlagUnknown 附 `(see 程式 子命令 --help)`。** 不再把全部子命令的 usage 塞進一行（aos-daemon-ctl、aos-grow、aos-eca-screen 現況）。結束碼只有 0／1／10／128+N（N-43），人用不新增碼；轉交別人的碼照 R8 寫 README 一句。

## H11 互動確認與 `--yes`

**不做互動確認、沒有 `--yes`；唯一互動是明說互動的（`chat`，Ctrl-C 退 130、stdin 結束退 0）。** 不可逆靠 H5「對象明講」＋保護清單（rm 不刪蓋到工作區／定義／daemon／cwd／家目錄的 stack）。理由：unix `rm` 不問；agent 走 bash 會卡；多一條 tty 暗規則。選項見 [README 方向題 4](README.md#方向題原則推不出的推薦放第一)。

## H12 顏色與 tty 偵測

**不做顏色、不做進度條、stdout 格式不隨 tty 變；tty 偵測只用在一處——「要 stdin 內容卻是終端」→ `ArgumentsBad`。** 等待中的狀態句走 stderr 提醒行（D5 照舊）。理由：`ls` 那種「接管線就變單欄」是人人踩過的坑；要彩色 `| bat`。

## H13 環境變數只當逃生口

**只有兩類 env 進人用指令：人殼預設（`AOS_AGENT`、`AOS_DAEMON`→`./.stack`）與 hub 位置（`AOS_KERNEL`、`AOS_LLM_KERNEL`、`AOS_MEMORY`）；每個被 env 補值的旗標在 help 寫 `(default: $AOS_X)`；env 一設就改行為（`AOS_KERNEL` 轉寄判官）的印一行 `warning: routing via AOS_KERNEL=…`（json-argv E1／J6）；新旋鈕不走 env（N-63 ④）。** 理由：使用者「環境變數是唯一不走 JSON 的、別濫用」。

## H14 子命令與旗標的字彙

**動作字只用這張表，同義不新開：`add`／`rm`（登記或掛的東西）、`ls`（列全部）、`get`／`show`（看一個：`get` 印 JSON、`show` 印人看的）、`set`、`reset`、`where`（印路徑）、`who`（反查）、`start`／`stop`／`sleep`／`wake`／`pause`／`resume`、`open`／`close`／`watch`、`send`／`take`／`see`／`done`／`regret`（aos-post 的）、`init`、`check`、`call`、`ping`。** aos-json 的 `del`（刪 JSON 鍵）跟 `rm`（拿掉登記）是兩個東西、照留。新字先查這張表。

## H15 `--version`

**不做。** proto8 沒版本號、install.sh 是 symlink 進 repo，`git log` 就是版本；加了要維護一個常數。
