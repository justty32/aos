# 慣例草案（續）：H9～H16（接 [03](03-慣例草案.md)）

## H9 stdin 與旗標並存、優先序

**給人用的指令 stdin 只放「內容」（say 的話、post／llm 的 body、json set 的值），不放參數；旗標 ＞ stdin ＞ 環境變數（使用者 11-05 晚）；需要內容但 stdin 是終端＝`ArgumentsBad stdin is a terminal`、不卡。** 不做「旗標 → stdin JSON 鍵」映射（json-argv Q1 推薦不做；使用者「依實際需要」——要做的那支自己做、不當通則）。C++ 吃 body 的子命令（`aos-post send／done`、`aos-llm send／ask`、`aos-json set／batch…`）現在碰終端會等 EOF（02 的 8 列）：照 lib 規則同一招，`isatty` 就當沒給＝`ArgumentsBad`（`aos-json set` 值可以從 argv 給、不受影響）。

## H10 錯誤訊息與結束碼（接三扇門）

**錯誤行 `程式: error: 代號 原因 (…)` 照 R1／R5；括號裡只放該層的指路：頂層缺子命令／不認得＝`(add, rm, ls, …; see 程式 --help)`；子命令層缺參數、位置參數不對、開關帶值＝`(usage: 那個子命令 help 的 usage 行)`；子命令前 FlagUnknown 不附（D9 照舊）；子命令後 FlagUnknown 附 `(see 程式 子命令 --help)`。** 不再把全部子命令的 usage 塞進一行（aos-daemon-ctl、aos-grow、aos-eca-screen 現況）。結束碼只有 0／1／10／128+N（N-43），人用不新增碼；轉交別人的碼照 R8 寫 README 一句。

## H11 互動確認與 `--yes`（使用者 11-06 裁「終端問、非終端不問」＋「加上--yes跳過」）

**不可逆的子命令在 stdin 是終端時問一句、否則不問；`-y`／`--yes` 跳過；問句在 stderr、不算一行（像 chat 的 `> `，D5）；只有 `y`／`yes`（不分大小寫）算答應，其他字、空行、EOF 都是 No；問到一半 Ctrl-C 退 130。**

- **判 stdin、不判 stdout**：答案從 stdin 來；`ctl rm x > log` 人還在、照問；`echo | …`、agent 的 bash 工具、daemon 起的子行程 stdin 都不是終端＝不問、照做（使用者要的「程式或 agent 呼叫時不問」）。不看 `TERM`、不看 `CI` 之類的 env（H13）。
- **問句格式**（stderr、無換行）：`程式: 動作 對象 (後果)? [y/N] `，例 `aos-agent: remove fsm_ann and delete its stack /home/x/ws/.stack/procs/fsm_ann? [y/N] `。預設 No（大寫 N）。
- **答 No**：stderr 提醒行 `程式: warning: nothing done`、退 0——答 No 是正常路（N-43：正常退出不寫錯誤行）；腳本要分辨就加 `-y`、不要靠結束碼。
- **`--yes`／`-y`（使用者 11-06 補「幫我加上--yes跳過」）**：會問的子命令**一律提供**，終端裡也可用；stdin 不是終端時它是 no-op、不報錯（它只關掉問句，寫什麼就做什麼）。短名 `-y`（表內；推薦給，全 unix 同義、沒別的旗標搶）。
- **不可逆清單（會問的）**：`aos-agent ctl rm`（刪 stack）、`aos-agent tools reset`、`aos-agent llm reset`（刪這隻的覆蓋層副本）。**不問的**：`aos-daemon-ctl rm`（stack 留著）、`aos-tools rm`（登記可再 add）、`aos-post regret`／`done`（信件協議、程式叫）、`aos-json del`／`set`（改使用者自己的檔，像 `sed -i`）、`aos-grow down`（有 `--dry-run`、內容保留）。**判準：刪掉的東西別處沒有副本、而且沒有 `--dry-run`。** 新子命令要問就加進這張清單，並在它的 help 寫 `asks on a terminal; -y skips`。前兩題（含 `aos-tools rm`／`aos-json del` 嗎）見 [README 新方向題 1](README.md#新方向題裁完四題後冒出的推薦放第一)。
- 共用實作：`aos_flags.confirm(prog, question) -> bool`（`isatty(0)`、`-y` 旗標、讀一行、EOF＝False、Ctrl-C 交給 `run` 退 130）；C++ 目前沒有要問的子命令，`aos-util` 不加。
- 其他互動只有明說互動的 `chat`（Ctrl-C 退 130、stdin 結束退 0）。防呆仍靠 H5「對象明講」＋保護清單（rm 不刪蓋到工作區／定義／daemon／cwd／家目錄的 stack）；`tools reset`／`llm reset` 既然會問，`--target`／`$AOS_AGENT` 定對象照留（[05 衝突 9](05-邊緣與衝突.md)）。

## H12 顏色與 tty 偵測

**不做顏色、不做進度條、stdout 格式不隨 tty 變；tty 偵測只用在一處——「要 stdin 內容卻是終端」→ `ArgumentsBad`。** 等待中的狀態句走 stderr 提醒行（D5 照舊）。理由：`ls` 那種「接管線就變單欄」是人人踩過的坑；要彩色 `| bat`。

## H13 環境變數只當逃生口

**只有兩類 env 進人用指令：人殼預設（`AOS_AGENT`、`AOS_DAEMON`→`./.stack`）與 hub 位置（`AOS_KERNEL`、`AOS_LLM_KERNEL`、`AOS_MEMORY`）；每個被 env 補值的旗標在 help 寫 `(default: $AOS_X)`；env 一設就改行為（`AOS_KERNEL` 轉寄判官）的印一行 `warning: routing via AOS_KERNEL=…`（json-argv E1／J6）；新旋鈕不走 env（N-63 ④）。** 理由：使用者「環境變數是唯一不走 JSON 的、別濫用」。

## H14 子命令與旗標的字彙

**動作字只用這張表，同義不新開：`add`／`rm`（登記或掛的東西）、`ls`（列全部）、`get`／`show`（看一個：`get` 印 JSON、`show` 印人看的）、`set`、`reset`、`where`（印路徑）、`who`（反查）、`start`／`stop`／`sleep`／`wake`／`pause`／`resume`、`open`／`close`／`watch`、`send`／`take`／`see`／`done`／`regret`（aos-post 的）、`init`、`check`、`call`、`ping`。** aos-json 的 `del`（刪 JSON 鍵）跟 `rm`（拿掉登記）是兩個東西、照留。新字先查這張表。

## H15 `--version`

**不做。** proto8 沒版本號、install.sh 是 symlink 進 repo，`git log` 就是版本；加了要維護一個常數。
