# 慣例草案：給人（與用 shell 的 agent）操作的指令

適用：people 與 both 類的人面（[02](02-盤點.md) 的 `who` 欄）。純 aos 函數照 [json-argv 03](../../05/json-argv/03-旗標映射設計.md)（`_tooldef.json` 生旗標與 help），本檔不管。三扇門（錯誤行、提醒行、`--help` 必有、結束碼）照 [stdio-unify](../../05/stdio-unify/README.md) R1～R15 與 [P-44](../../../../docs/CONVENTION/02-題目stack停錯腦/07-P-44.md)，這裡只加「給人用」多出來的。

## H1 給誰用，設計之初寫下來

**每支程式 README 的 NAME 行底下一句 `for: people / aos functions / both`。** 判準（使用者 11-05 晚）：argv 裡有 stdin 不會出現的東西（子命令、位置參數、`--target`）＝偏人用。both（aos-exec、loop、daemon、post、json、lock、tools、sandbox、llm）：人面照本檔，被程式叫的那面照 P-44 現況不動。

## H2 子命令結構

**`程式 [全域旗標] 子命令 [子命令旗標] 位置參數`，最多兩層；群組名是名詞（`ctl`、`tools`、`llm`）、動作是動詞（`add`、`rm`、`ls`、`get`、`set`、`show`、`where`、`start`、`stop`）；一詞一義全體系（C-54）。** 全域旗標只放「選哪個容器」（`--daemon`、`--file`、`--overlay`、`--eca`）；動作的選項放子命令後。別名不新開（`state|status` 是使用者 11-04 定的，照留）。理由：P-44 R4 已是這形狀，只補「兩層」與「名詞／動詞」。

## H3 子資料夾＝子動作，落到 cmd 的檔案結構

**群組＝子資料夾（Python 套件），動作＝模組檔，每個模組頂端 `HELP` 字串＝那個子命令的 `--help`（第一行＝NAME 一句話），派發是一張顯式表 `SUBS = {…}`；小動作同主題合一檔。** 樣本 [01](01-樣本-aos-agent.md)。只有超 300 行的指令才拆套件（aos-agent）；其餘單檔、HELP 改成 dict（aos-daemon-ctl、aos-tools）。lib 工具那邊「子資料夾＝子 method」靠 aos-exec 照路徑找入口（json-argv Q2），cmd 這邊靠 import——字面不同、精神一樣：**一個動作一個地方、各自一份 help**。選項與後果在 [06 方向題 1](06-方向題.md)。

## H4 旗標命名

**長旗標為主、全小寫連字號、單位接後綴（`--timeout-s`、`--interval-ms`、`--lease-ms`）、開關不帶值（`--json`、`--follow`、`--dry-run`）、否定只在預設為真時用 `--no-x`（`--no-cache`）；可重複收的要在 help 寫 `(repeatable)`。** 理由：P-44 現行；全部現況已合（02 的 H4 gap 只 2 列）。

**短旗標（11-07 使用者裁定 sol 審查 #22）：每支指令各自定，同一短名在不同指令可不同義。** 共用模組的 `SHORT`／`kShort` 留作常用預設，各支可另傳自己的短名表；現有指令用法不變。短名只是別名，寫法 `-x V` 或 `-x`（開關），不黏值、不併、不帶 `=`；help 的旗標行寫 `-j, --json`。

## H5 位置參數

**只放這個子命令的主詞（對象）：一個、最多兩個（`aos-post send MAILBOX [LETTER]`）；有環境預設的改旗標（`--target NAME`、`--daemon D`）；不可逆動作的對象一律位置參數明講、不吃環境預設（`ctl rm NAME`，使用者 11-04 定）。** `WORDS...`（say）、`KEY=VALUE...`（llm set）、`FILE...`（json check）是「一串同類」、算一個位置參數。`-- ARGS...` 原樣透傳給下層（exec、loop、daemon-ctl add）不算本程式的位置參數。

## H6 `--help` 的形狀（英文；中文與長篇進 README）

**每支、每個子命令（含二層動作）各一份；頂層 ≤ 40 行一屏、子命令 ≤ 25 行、每行 ≤ 100 字；段序固定：NAME 一句 → `usage:`（含 `程式 子命令 --help` 那行）→ `subcommands:`／`actions:`（一行一個，一句話）→ `flags:`（每個旗標一行，讀 env 的寫 `(default: $AOS_X)`）→ 一段散文（≤ 5 行，只講「這支做什麼、結果去哪」）→ `exit codes:` → `more: <README 路徑>`。** `程式 --help 子命令` 印頂層（`--help` 在旗標位置就認，R3 照舊）。現在 `--help` 裡的長篇英文規則（aos-agent 的 Target／sleep／Replies／Interface 段、aos-daemon-ctl 的 15 段）搬 README（中文）；knowledge/aos 要給腦看的英文版另算（[05 邊緣 15](05-邊緣與衝突.md)）。理由：使用者「man/--help 要有、以人為主」；盤點 79 列的差距全在這條。

## H7 man

**`--help` 就是 man 的一屏版、README 是長版；不手寫 man 檔。** 真要 `man aos-x`，大重構後用小腳本從 `--help` 生 `cmd/<名>/man/`（help2man 式），零手寫。選項見 [06 方向題 3](06-方向題.md)。

## H8 人看的輸出 vs `--json`

**stdout 只放結果：清單＝一列一筆、TAB 分欄、無表頭（R15 照舊；表頭寫在 `--help` 的那一行）；單件＝一行可 `$(…)`（路徑、信名、seq）；動作成功＝一行結果句或信名（非同步動作要讓人知道信寄了）；會列資料的子命令（`ls`、`state`、`who`、`get`、`show`、`see`）都有 `--json`＝一行 JSON（不 pretty）；`#` 開頭＝註解行（`ls` 尾行的上層看法），`--json` 時變欄位不印行。** 清單空＝stdout 空、退 0；退 10 只給「查單件、沒有」（`take`、`see`、`recv`、`lock show`）。原本只印 JSON 的人用子命令（`aos-tools add／rm／get`、`aos-lock show`、`aos-post see`）：`get`／`show`／`see` 給腦與管線用的照舊一行 JSON、不另做人形（KISS，jq 就在旁邊）；`add`／`rm` 改印一行結果句或名字。`aos-llm ls` 改 TAB、`--json` 改一行（跟全家一致）。不做 `--quiet`／`--verbose`。
