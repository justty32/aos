# 這個比喻能帶來什麼（續）

### 5. 中斷線與遮罩：要分優先就多拉一條線（多開信箱），不加優先級

- **白話**：板子 IRQ 有優先序與遮罩；aos 現況＝有序信先收、`paused` 那圈整箱遮罩。ping 跟重活同箱時 ping 會被排後、3 秒逾時。
- **選項**：① **不改信封；規矩「要分優先＝多開信箱，一箱一函數」**（body-protocol 已裁「分權多開信箱」順勢延伸）——零程式。② 信封加 `priority`——違 11-06「不與 aos-post 耦合太深」與 aos-post 明寫不改的清單。
- **推薦 ①**；判準：某箱 ping 逾時率 >1% 時把 ping 分箱，不是加欄。
- **落**：N-16 旁協議段一句。
- **排**：併 A 條文日。

### 7. 多板互連沒有共同時基：跨樹的信期限只能用牆鐘

- **白話**：兩塊板各自晶振，CAN 匯流排上不比對方的週期數；aos 的 llm kernel 是另一棵樹（使用者 11-05「另起一台 daemon 共用 llm kernel」），agent 樹寄來的 tick 期限對 kernel 的時鐘沒意義（03 坑 3「跨樹不能比」），但 T4 要把 kernel deadline 改 tick。
- **選項**：① **信裡跨樹的期限一律毫秒（第②類「對外」）；kernel 自己內部計時（額度、每題上限）用自己樹的鐘；kernel 不讀信裡的 tick 欄**——T4 縮小成「寄件人額度相對 kernel」＋名字改，不改跨樹語意；kernel 樹凍住再醒，對外的毫秒期限會過期（接受：它本來就對外）。② 兩樹 export 同一個 `AOS_TICK`——違 apply-ideas 04 #6「一棵樹的時鐘要在這棵樹裡」、搬家斷。③ 信封加「時鐘身分」——aos-post 加欄。
- **推薦 ①**；判準：收信者的 `AOS_DAEMON` 樹 ≠ 寄信者的就算跨樹；同樹（判官、daemon ctl）照兩鐘規則。
- **落**：`proto8/impls/aos-llm-kernel`、N-04 旁一句。
- **排**：**T4 緊接 S9 那步做之前先定**（否則做兩次）；不插 S 步。→ README 方向題 1。

### 8. 沒有 timer 時怎麼寫程式：用「次」算、不假設一次多久

- **白話**：使用者原話「沒有timer可以參考，當然也還是可以寫啊，只是說你不確定每個函數、每個指令它具體的執行時間」。韌體靠指令週期估；aos 的對應是 `counter_runs`／回合數——沒 `AOS_TICK` 的 proc 照樣能用「跑了幾次」當時間、要真時間讀牆鐘（第③類）。另：`_tick` 自己也會慢（每格＝間隔＋跑一次，見 [03「要對上的」3](03-天然差異與要對上的.md)）。
- **選項**：① **N-04 兩鐘規則旁加一句慣例**：「沒時鐘＝用次數算、不假設一次多久；要實際時間讀牆鐘」；標稱頻率寫明「只會慢、是默契」——零程式。② aos-tick 自己睡到下一個整點（auto-reload，`interval_ms` 設 0）——aos-tick 改一輪、時鐘準，但多一個 Python 迴圈長期占著。③ aos-loop 加「固定週期」模式——改 N-32、動到所有 loop。
- **推薦 ①**；判準：P9 實測一小時偏差 >10%（Python 起一次約 50 ms／1000 ms ≈ 5%）才改 ②。
- **落**：N-04（T8）；②的話 `proto8/cmd/aos-tick/`。
- **排**：併 T8；② 若要，排 P9 之後。→ README 方向題 4。
