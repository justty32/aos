## 使用者原文（11-06，逐字；起點）

> 想想看，假如root daemon就是底下的那個硬體板子，在嵌入式中的那個內部晶振，應該也是板子附帶的，所以tick我希望能夠在daemon的設定中自帶(當然，不強制，不與daemon耦合)。沒設AOS_TICK=時間不走？這太粗暴了，在寫韌體的時候發現沒有timer可以參考，當然也還是可以寫啊，只是說你不確定每個函數、每個指令它具體的執行時間。而且我們還有一個逃生口：原生linux提供的實際時間函數。

11-05 已講過的同一比喻（逐字在 [kernel-daemon](../../05/kernel-daemon/README.md)、[portable-flow 02](../../05/portable-flow/02-image-模型.md)）：「daemon是硬體，他是比較特殊的存在，他的stack就是自己本身」「daemon就像是硬體，各stack就是各程序所佔據的記憶體空間。ws則是外置記憶體。各種定義資料夾則是類似source code，跑起來之後就是看其實例了(daemon下的stack)」。

**11-06 使用者回覆**（對「休眠不是 debug halt、SIGSTOP 可當軟凍候選」）：「好，關於暫停這塊我有話說：我知道linux有原生暫停，但我想要的是暫停後能遷移。」——暫停的目的＝凍住後整個資料夾能搬到別台機器再接著跑；逐字與「還綁在原機器的東西」在 [04](04-凍住後要能遷移.md)。

## 一句話結論（白話）

**root daemon 就是一塊沒有作業系統的「super-loop」板子：窗＝記憶體映射暫存器、信箱＝硬體 mailbox FIFO、`tick`＝板載晶振、Linux 牆鐘＝RTC（電池鐘）、監管樹＝只在有刺激時才咬的看門狗、sleep＝休眠到磁碟。** 對照下來八成「已經是這樣」，比喻帶得出來的新東西很少、也都小：T7 多傳一個 `AOS_TICK_INTERVAL`、T4 動工前先定「跨樹（llm kernel）的期限用牆鐘」、幾句條文與一張「省電模式表」——全排在既有的 T／P 序列裡，**不插大重構 S 步**。不貼的地方（沒有中斷、RAM 不揮發、晶振能被人停）是天然差異，標出來就好（[03](03-天然差異與要對上的.md)）。**暫停的目的是遷移**（使用者 11-06）：aos 的 sleep 對應板子的「休眠到磁碟＋可插拔存儲」（RAM 寫進 SD 卡、拔走插別塊板），不是 debug halt；SIGSTOP 行程與記憶體搬不走、不採。同一棵樹的 image 11-05 已經搬得動，剩下綁原機器的全在樹的邊界（跨樹回信地址、`AOS_LLM_KERNEL`、樹外時鐘、外部端點）＋P7 一個「醒來即 stuck」小坑（[04](04-凍住後要能遷移.md)）。

## fable 代定（可翻案）

1. 看門狗**不加餵狗**（心跳）：aos 的 stuck 是「有刺激沒反應」，睡著不會被咬，比真看門狗好；條文用比喻解釋，不翻 N-09／N-32。
2. 冷啟／熱啟不加 `boot` 欄：P8 食譜寫「`counter_runs` 繼續累加＋列從 `sleeping` 變 `running`＝熱啟成功」就夠（C-56）。
3. 中斷優先序不加信封欄位：「要分優先＝多開信箱，一箱一函數」（body-protocol 已裁「分權多開信箱」順勢延伸；aos-post 明寫不改）。
4. 省電模式表寫在 aos-daemon docs/03、不進 CONCEPTS；P6 做完（整樹睡成立）再寫。
