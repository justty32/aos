# 凍住後要能遷移：還有什麼把資料夾綁在原機器

## 使用者原文（11-06，逐字）

對「休眠不是 debug halt、SIGSTOP 可當軟凍候選」的回覆：

> 好，關於暫停這塊我有話說：我知道linux有原生暫停，但我想要的是暫停後能遷移。

## 定下的

- **暫停的目的＝凍住後整個資料夾能搬到別台機器再接著跑**（接 11-05「無痛遷移」「乃至於透過git管理，我到另一台電腦做git pull」）。
- **SIGSTOP／SIGCONT 不採**：行程與記憶體搬不走，不符合目標。板子比喻裡 aos 的 sleep 對應的是**「休眠到磁碟＋可插拔存儲」**（RAM 寫進 SD 卡、卡拔走插到另一塊板子），不是 debug halt。
- 「暫停時間」（tick 停）因此也是為了搬：時鐘檔在 image 裡，搬過去 tick 值接著數，期限不會因為搬家的牆鐘流逝而過期。

**一句話**：11-05 那波（相對 daemon、boot_id、不存副本、gitignore）把「同一棵樹的 image」綁原機器的東西都解掉了；剩下的全在**樹的邊界**——跨樹的回信地址與 `AOS_LLM_KERNEL`、樹外的時鐘、外部端點、牆鐘期限——加上 P7 一個「醒來即 stuck」的小坑。板子比喻說得通：SD 卡拔走插到別塊板子，板上的東西全對；接在匯流排上的別塊板、外接感測器、牆上的時鐘，本來就不在卡裡。

## 方向題（2 題；推薦放第一）

1. **搬家的單位是一棵樹（一個 image），還是整組樹（agent 樹＋llm kernel 樹）？** 推薦：**一棵樹一個 image**；跨樹的連線（`AOS_LLM_KERNEL`、在飛的問腦請求）算「外接」——搬家後重設變數、在飛的請求作廢重寄（食譜寫「凍之前先等問腦收完」，`aos-agent ctl state` 看 pending）。替代：把 llm kernel 樹塞進同一個 image 一起搬（回信地址同樹就對，但 llm 樹是多台共用的，搬一份就分叉）；或信封加「回信樹標識」（aos-post 加欄，違 11-06「不耦合太深」）。
2. **範本 daemon.json 要不要預設帶 `tick: true`（板子出廠就帶晶振）？** 推薦：**範本（試驗場、templates）帶 `tick: true`，程式預設仍不帶**（使用者「不強制、不耦合」）——沒 tick 的樹搬家一醒期限全過、#14 也只在沒 tick 時誤判；有 tick 這兩題都自然消失。替代：程式預設開（違「不強制」）；都不帶、靠食譜提醒（搬家第一次踩一回）。
