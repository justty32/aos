- 「現在討論好的這些，看你要不要派subagent去做架構規劃」

- 「可以的話我希望你能派一大堆subagent，建議都用claude subagent。」

- 「你這邊也可以散出一些fable max」「去幫你思考一些東西」
- 回報到第七份時：「婷婷婷」「停」，問他要哪種停，答「b」「讓他們收尾」；接著「fable limit要沒了」「馬上讓子agent都停」→ eca-aos 關掉自己的畫面，子 agent 一起停。
- 重開後：「收尾吧，先在這邊停頓」

## 最值得先看的（eca-aos 看過回報的部分）

- **16 衝突檢查**：真的衝突六處，其中四處使用者說新話時沒提舊裁定——別人不碰 pid（11-06 選「不放寬」，理由是 pid 搬不走）、image＝stack＋ws、不依賴 symlink（11-03、11-11）、一般 proc 只看得到 kernel；11-12 說過「聯絡得上就是 proc」後來自己收回，這次等於翻回來；舊條文有規定而新模型沒提的 24 項，最急的是死掉的 proc 去哪看。
- **06 路徑**：這台 PID 約七小時繞一圈，舊的 `/proc/<PID>/cwd` 會安靜指到別的行程；固定名字的連結當 `AOS_ROOT` 實測可行。
- **02 daemon**：換帳號起的子項讀 daemon 的 `/proc/<PID>/cwd` 是 Permission denied（實測）；表上 PID 四成是外殼不是 proc 本身。
- **01 aos-loop**：今天 ctl 的回音是「做了」不是「收到」；兩人同時寫 ctl 會丟一道且被誤報成功（現有毛病，實測）；ctl 直接換成 FIFO 會卡死。
- **04 eca**：eca 是 loop 加 Claude Code，畫面那棵不是 daemon 的子孫；11-25 接不上對話的第二個原因是人先開口就不補送前情。
