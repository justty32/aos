## 機器與專案事實（已查，不用重查）

- 公司 WSL2（Ubuntu）。repo `/home/guanyu/repo/aos`；`AOS_HOME=/home/guanyu/repo/aos/proto8`。原始碼在 `proto8/py/`、`proto8/cpp/`（C++20、g++、一份 Makefile；第三方只收單檔進 repo；不用 CMake、vcpkg），裝好的在 `proto8/bin/`、`proto8/lib/`。
- 活樹：根 daemon 的 stack 在 `~/aos-home/.stack`（定義 `~/aos-home/root`），底下 `procs/<名>/…`；repo-aos 這棵在 `~/aos-home/.stack/procs/repo-aos`。全部 agent 與使用者同一個 Linux 帳號。
- `/dev/fuse` 與 `fusermount3` 在；沒有 libfuse3 標頭、沒有 Python 的 fuse 套件。`/tmp` 是 tmpfs。`pid_max` 4194304；`yama ptrace_scope` 1。
- 已經確定、不用再爭的：Linux 的 `/proc/<PID>/` 底下使用者空間加不了東西（FUSE 也掛不進去）；`/proc/<PID>/cwd` 可以當入口（實測表在 `9p-proc-1125.md`）；今天 daemon 與 agent 行程站的是定義夾，不是自己的 stack。
