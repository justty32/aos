## 定了的

- **介面＝目錄的長相＋每個檔的內容格式規定**；硬碟、tmpfs、FUSE、真的講 9P 協議都只是實作，可以一個一個來，第一步用普通檔加 `/proc/<PID>/cwd` 就算數。
- **persist 在哪，以 proc 自己說的為準**：位置 proc 自己挑；daemon 起它之後從它的目錄讀（例如一個 `settings` 檔）得知路徑；proc 沒登記就死，daemon 就不知道，「那自然就是這樣」。daemon 可以給預設位置，在 `/tmp` 開一塊給它。
- **介面基於 9P，支援這套的就是 aos proc**；現有的 aos-loop／daemon 退成「普通實作」之一。
- **部分用 json**：9P 自己有的（stat 之類）照 9P 的；`ctl`、`status` 用純文字；`_metainfo` 照 aos 現有的（json）。
- **`ctl`**：吃純文字。寫回來＝**收到**，做完沒看 `status`。
- **`status`**：純文字，一行一個「名稱: 值」（像 Linux 的 `/proc/<PID>/status`，不像靠位置認欄位的 `stat`）。**目前只先給 `status` 一個檔**；以後可以多給別的檔（例如 token 用量）。
- **token 用量**：proc 自己的用量自己報、放在自己的目錄；kernel 發出去多少記在 kernel 自己的目錄；daemon 不管帳。
- **daemon**＝Linux 與 aos 之間的橋，本身是普通 Linux 行程，同時也是 aos proc（上層要能對它下 ctl、看 status）；特別處是多一個放各 aos proc 的資料夾，裡面每一項連到那個 proc 自己的目錄。
- **kernel**＝普通的 aos proc，只是帶了相關功能。
- **`proc` 與 `procs`** 兩個名字都留，在 aos 體系下指向同一個地方。
- **入口**：給根 daemon 的 PID，大家自己從 `/proc/<PID>` 進去；`AOS_ROOT` 指根，`AOS_DAEMON=$AOS_ROOT/procs/repo-aos`。Linux 的 `/proc/<PID>` 不加東西（實測見下：要多一個 `cwd`）。
- **stack 的意思換了**：`.stack` 這個夾以後沒有了；stack＝「一個活著的 proc 的身體所在」，現在的實作只是剛好把它放在硬碟上；直接用 Linux 這套時 `/proc/<PID>` 就是它的 stack，對應到它在記憶體裡的身體。
- **要留在硬碟上的東西**：各自處理；推薦的標準位置是 `procs/<名>/persist`。
- **送訊息兩條路**：proc 活著＝直接走 unix socket；掛了或睡了＝收不到，要送的人退一步去問它的 daemon 或某個 kernel「信箱在哪」，改走寄信（落檔、持續；放 tmpfs 的話以後再看）。
- **問信箱時要不要順手叫醒**：以後的實作細節；傾向做成 daemon 自己的可選設定。

## 實測：`/proc/<PID>/cwd`（eca-aos，公司 WSL，11-25）

Linux 的 `/proc/12321/procs` 不存在（`/proc` 是核心的，使用者空間加不了東西；FUSE 也掛不進去）。但核心本來就給每個行程一個 `cwd` 連結，指到它站著的資料夾，所以寫成 `AOS_ROOT=/proc/12321/cwd` 就照使用者說的走得通，Linux 那邊什麼都不用加。

模擬一台 daemon（站在自己的夾，夾裡 `procs/kid` 是指到 `/proc/<kid 的 PID>/cwd` 的 symlink）加一隻 proc（站在自己的夾，夾裡有 `status` 與一個 unix socket）：

| 測什麼 | 結果 |
|---|---|
| 從 `$AOS_ROOT/procs/kid/status` 讀（連穿兩層 `/proc` 連結） | 讀得到 |
| 從 `$AOS_ROOT/procs/kid/sock` 連 unix socket | 連得上、有回 |
| proc 的夾真實路徑 160 bytes，直接用真實路徑連 socket | 失敗 `AF_UNIX path too long`（上限 108） |
| 同一個 socket 走 `/proc/<PID>/cwd/procs/kid/sock`（32 bytes） | 連得上 |
| proc 被 `kill -9`、daemon 還沒收屍 | 那條路已經 `No such file or directory`（不用問任何人就知道死了） |
| 收屍之後 | 一樣讀不到；`procs/kid` 這個 symlink 檔自己還留在硬碟上（懸空） |
| 死掉的 proc 留下的 socket 檔，用真實路徑連 | `Connection refused` |

這台 `pid_max` 4194304、`yama ptrace_scope` 1（同帳號讀不受影響）。

沒測、照 Linux 規則說的：`/proc/<PID>/cwd` 要過 ptrace 讀權限檢查，**不同 Linux 帳號走不進去**（root 除外）；現在全部 agent 同帳號所以沒事，以後要用分帳號做權限時這條會被擋。

```python
import os, signal, socket, tempfile, time

base = tempfile.mkdtemp(prefix="proc-cwd-")
deep = os.path.join(base, *(["procs", "a-rather-long-daemon-name"] * 4), "procs", "kid")
os.makedirs(deep)
root = os.path.join(base, "rootdir")
os.makedirs(os.path.join(root, "procs"))
r, w = os.pipe()
kid = os.fork()
if kid == 0:                                    # 那隻 proc：站在自己的夾，給 status 與一個 socket
    os.chdir(deep)
    open("status", "w").write("phase: running\npid: %d\n" % os.getpid())
    s = socket.socket(socket.AF_UNIX, socket.SOCK_STREAM)
    s.bind("sock"); s.listen(4)                 # 相對名字：開的這邊沒有長度問題
    os.write(w, b"1")
    while True:
        c, _ = s.accept(); c.sendall(b"received: " + c.recv(100)); c.close()
os.read(r, 1)
os.chdir(root)                                  # daemon：站在自己的夾，顧 procs/<名> 連結
os.symlink("/proc/%d/cwd" % kid, os.path.join(root, "procs", "kid"))
via = "/proc/%d/cwd/procs/kid" % os.getpid()    # 別人拿到的路

def ask(path):
    c = socket.socket(socket.AF_UNIX, socket.SOCK_STREAM)
    try:
        c.connect(path); c.sendall(b"stop"); return c.recv(100).decode()
    except OSError as e:
        return "FAILED %s" % e

print(open(via + "/status").read(), ask(via + "/sock"), ask(os.path.join(deep, "sock")))
os.kill(kid, signal.SIGKILL); time.sleep(0.3)
print("zombie:", os.path.exists(via + "/status"), ask(via + "/sock"))
os.waitpid(kid, 0)
os.chdir(deep)
print("reaped:", os.path.exists(via + "/status"), ask("sock"))   # 留下的 socket 檔：Connection refused
```

## 跟現況對得上的地方

- 今天的版面已經是這個形狀：`~/aos-home/.stack/procs/repo-aos/procs/eca-aos`，daemon 的 stack 底下 `procs/<名>` 就是那個 proc 的目錄。要變的是「誰來回答」。
- 今天 daemon 與 agent 行程站的是**定義夾**，不是自己的目錄（例：根 daemon 的 cwd 是 `~/aos-home/root`）。要用 `cwd` 這招，每個 proc 得改成站在自己的身體裡。
- 「問 daemon 信箱在哪」今天就答得出來：daemon 的表（`procs_state.json`）每一列記著那個 proc 的 stack 位置。
- 今天的 `ctl.json` 帶 `seq`、靠 `state_flux` 跟上來判斷收到沒有。有回應的寫（9P 的 Rwrite／Rerror、或 unix socket 上一來一回）不需要 `seq`；落檔的實作檔案永遠寫得進去，才需要。
- 今天「stack」這個詞在程式、條文、知識庫裡指的是**硬碟上那個一直都在的夾**（`AOS_STACK`、`.stack`、history.jsonl 在裡面）。新的意思是活的身體；今天 stack 裡大部分的東西（history、queue、mailbox、session、自己改過的 tools）照新說法是 persist。規格那頁要把這個詞的新定義寫明。

## eca-aos 攤的邊緣（還沒有使用者的話）

- **外面的殼怎麼知道根的 PID**：PID 每次起樹都不同。可以是根起來時寫一個固定名字的連結指到自己的 `/proc/<PID>/cwd`。
- **跨機器沒有 `/proc`**：大家認的還是名字那條路（`procs/<名>`），`/proc/<PID>` 只是本機上連結指過去的地方。
- **不同 Linux 帳號**：見上面實測那節最後一段。
- **FUSE 時**：不需要 symlink 檔（伺服器當場回答 `procs/<名>`）是對的；但 FUSE 一樣掛不進 Linux 的 `/proc/12321/`，入口還是 `…/cwd`（daemon 站在自己的掛載點裡）或一個固定的掛載點。
- **`procs/arena/persist` 在 arena 死掉時走不到**：`procs/arena` 連到活的行程，行程一死這條路就斷。所以「問 daemon 信箱在哪」那一步是必要的，而且 **persist 的位置得在 proc 還活著時就讓 daemon 知道**（daemon 起它時給，像今天的 `AOS_STACK`；或它起來時自己登記）。
- **別人只需要 persist 裡的一樣東西：信箱**。其餘（歷史、佇列…）是 proc 自己的事。所以標準規範可以很小：位置 `persist`、裡面別人能投信的 `mailbox`。
- **重起＝新的身體接回舊的 persist**：讓它「還是同一隻」的東西都得在 persist。現有的落檔實作整個 stack 本來就都留著，要符合這條很便宜（例：stack 裡放一個指到自己的 `persist`）。
- **socket 那條不落檔**：收到了但還沒處理就死掉，那封就沒了。使用者 11-24 說過「持久性/單點故障沒差，我們可以定期保存」，先當作可接受。
- **兩條路的順序**：proc 掛著時信進了信箱，醒來後新訊息從 socket 進來；醒來要先清信箱，不然新的排到舊的前面。
- **兩個 `status`**：`/proc/<PID>/status` 是 Linux 自己的（講這個 Linux 行程），aos 的在 `/proc/<PID>/cwd/status`，只差一層、同名。
- **預設的 persist 放 `/tmp`**（第 7 段之後攤的）：
  - 公司這台的 `/tmp` 是 tmpfs（記憶體，`findmnt -T /tmp` 查的）：預設那塊過得了 proc 重起、過不了機器重開（WSL 一關就沒了）。等於三級：身體（跟行程一起沒）、預設的 persist（跟開機一起沒）、proc 自己挑的硬碟位置（一直在）。要緊的 proc 得自己挑。
  - 預設位置要用名字算、不用 PID 算，重起才接得回舊的那塊。
  - `/tmp` 大家都能寫，那塊要開成只有自己進得去。
- **daemon 什麼時候讀 `settings`**：行程剛起來還沒站好、檔還沒寫，這時讀不到。可以把「讀得到 `settings`／`status` 的那一刻起才算 aos proc」當成登記的定義。
- **同一招可以當「只登記、不起」的入口**：外來的行程把自己的 PID 告訴 daemon，daemon 一樣去讀 `/proc/<PID>/cwd/settings`，再把 `procs/<名>` 連過去。daemon 起的和自己來登記的，走同一條路。
- **`settings`、`_metainfo`、`status` 三個檔的分工**：我是什麼（`_metainfo`，定義帶來的）／我的東西放哪（`settings`）／我現在怎樣（`status`）。今天 `aos-agent ctl who` 印的 def、ws、stack、parent、notify_box 就是 `settings` 這一類。

### 這一輪定了的

- **`AOS_ROOT` 由人手動維護**：根重開後它提示自己的 PID，人自己 export；可以有方便的做法（例：用特殊指令起根，就順手把 `AOS_ROOT` 設好）。
- **proc 的身分字串**：用從根算的名字那條路，先這樣；名稱可以自己指定。
- **沙箱**：本來就是要關著，有需要再給它開口子。**換帳號**：比較麻煩，之後再想。
- **ctl 的字表不訂死**：只訂基礎且通用的，其餘大家想用什麼用什麼。
- **ctl 的回饋放 `status`，行名以 `aos_ctl_` 開頭**：這個開頭的是 aos 標準下的；規定它講的必須是最後一次 ctl。被拒的原因也放這裡。
- **ctl 要鎖**：一個人搶到之後，從他寫進指令到 proc 做完那個動作，都鎖住；另一個人會發現自己寫不進去。
- **daemon 這一側**：`procs_ctl`、`procs_status` 好；其餘（強制手段歸 daemon、想要的樣子與實際的樣子分開記、死因由 daemon 留、起了不登記的等到期限）照報告的推薦。
- **`settings` 用純文字**；json 格式另外給（他寫的是 `settings/json`、`ctl/json`、`status/json`），這些都可以之後再做。`status` 第一批收哪些行由 eca-aos 定。
- **socket 上送來的算 queue 還是 mailbox**：proc 自己決定，預設希望是 queue。
- **可遷移性**：現在不動；設計時先考慮著，遠期目標是 `cp AOS_ROOT` 就能把一切搬走。
- **落檔的實作不算 aos proc；直接起 proto9。**（第一輪「第一步用普通檔加 `/proc/<PID>/cwd` 就算數」那句被這條改掉；範圍 eca-aos 還在跟他確認，見下。）

### eca-aos 這一輪攤的（還沒有使用者的話）

- **「鎖住、另一個人寫不進去」只有當場回答的實作做得到**：普通檔擋不了第二個人寫。這條加上「落檔不算」，等於 proto9 的第一步就要選一種當場回答的做法（FUSE 掛載／proc 在 unix socket 上講 9P／其他）。這台的可行性那份報告（09）沒做出來。
- **鎖著的時候要強制停**：`stop` 可能要等很久（eca 是答完這輪才停），這段時間 ctl 寫不進去；強制手段走 daemon 的 `procs_ctl`，跟已定的一致。
- **因為忙而寫不進去的那一次，不該蓋掉 `aos_ctl_*`**：不然先搶到的人的回饋會被後來的人蓋掉；「忙」當場用寫入失敗告訴他。
- **`settings` 與 `settings/json` 不能同時存在**：一個名字不能既是檔又是夾（FUSE、9P 也一樣）。可以是 `settings.json`，或一個 `json/` 夾裡放 `settings`、`status`、`ctl`。
- **預設 queue 的話，活著與掛了意思不一樣**：活著時直接進對話，掛了改寄信是進信箱等它自己看。
- **手動 export 的 `AOS_ROOT` 過期後**：根死了、PID 被別的行程拿走，舊值會安靜地指到別人的夾；工具用之前可以先認一下那裡是不是根（例：讀它的 `status`）。樹裡的 proc 由 daemon 起，daemon 知道自己的 PID，可以直接給；要手動的只有樹外的殼。
- **`cp AOS_ROOT` 搬走一切**要先留的路：每隻 proc 要留的東西從它自己的目錄走得到（`persist`）；留下來的檔裡指別人用名字、不用絕對路徑與 PID。
