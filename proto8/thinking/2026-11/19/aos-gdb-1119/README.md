# 「aos 的 gdb 在哪」調查（11-19）：斷點＝條件成立就把 loop／fsm 停下來等人看；今天所有停得住的手段實測，以及 Python REPL＋aos-gdb 庫、程式邊跑邊長時怎麼停、怎麼看、怎麼續

← [2026-11-19](../README.md)

使用者 11-19 早問：「我們重新跟隨現代軟體技術棧去走……那，gdb在哪？」接著他補了想像中的樣子：「接近python repl + shell指令……用aos-gdb庫，下斷點……然後跑」。也說了新的開發範式：「先用agent作為萬能函數，然後逐步給他添加工具……在他的指令中央插入新指令」。看完第一輪結論後，他重新定義斷點：「特定條件發生時，暫停loop或fsm，停下來等待檢閱」，條件主要由 hook 承載，「能把他停下來的都可以」，並要我們「回去重新想想」。全文見 [00](00-使用者原話.md)，逐條對應見 [06](06-使用者回應.md)。

這條線是 `aos-gdb-1119`，只調查與發想：沒改程式，也沒排實作。實跑都在公司 WSL 的暫存樹，用假腦。

## 先講結論

1. **你定義的斷點，今天不改 aos 任何程式就湊得出來。** 四段分別是：
   - **條件**：一支普通程式，掛成 hook 或放在外面當觀察者。
   - **停**：`aos-agent ctl pause`。
   - **檢閱**：讀 stack 的檔。
   - **續**：`ctl resume`。

   四段都實測過，續了不丟東西。連「腦正在回答時按暫停」也不丟：答案先放在信箱，續了才收（[07](07-怎麼把它停下來.md)）。
2. **「發stop」建議用 pause 這一招。** hook 裡叫一行 `ctl pause --no-wait`，hook 機制一個字都不用動（實測）。停下時行程不死，停在兩格之間，信照收。不建議當斷點用的有三招：
   - **hook 故意失敗**：agent 會掛掉，被 daemon 連重起三次才放棄。
   - **`ctl stop`**：行程真的退出、換 pid。續得回來，但動靜大。
   - **Linux 的 SIGSTOP**：凍得住，但 aos 完全不知道它停了，表上照寫 running。

   kernel 的 hold 則停不了已經在跑的 agent。
3. **條件放哪，只差在準不準、碰不碰那隻 agent。**
   - **放在 agent 裡的 hook**：事情發生時就被叫，準，還能停在事前（例如工具要跑之前）。
   - **外面的觀察者 proc**：只能輪詢檔。實測約 2.5 秒內停住、晚一格，但完全不碰那隻 agent，還能看跨好幾格、跨好幾隻的事。

   今天沒有事件可等，外面只能輪詢。
4. **程式邊跑邊長，跟「C 與 .o」不衝突。** 跑起來之後加的工具、system、hook、llm 設定，都寫在這隻自己的 stack 疊層，下一輪生效，重生碰不到，就像程式跑起來後才載入的 lib。只有在 fsm 插一格、`agent_def` 這幾種會寫進定義夾（事實表在 [06](06-使用者回應.md)，實測在 [02-續](02-續-插入與Python.md)）。另外有一條限制：`loop.json` 只在起跑時讀一次。
5. **你說的「下一步看不到」是真的，斷點也就不綁位置。** fsm 的格與箭頭事前畫好了，但走哪條、腦點哪個工具要等腦決定（[02](02-aos現況.md) 第一節）。照你的定義，斷點本來就是「條件」不是「位置」，也不必對回原始碼。
6. **還缺的只有一件小事。** 停了之後表上只寫 `paused`，不說是誰、為了什麼條件停的（[04](04-邊緣狀況.md) 第 28 條）。發想裡各案都讓觸發器停的時候自己留一張字條。
7. **別人的作法**（[03](03-別人怎麼做.md)、[03-續](03-續-REPL與邊跑邊改.md)、[03-續二](03-續二-條件觸發.md)）：「條件與動作都在外面、目標不改」是很常見的分工，例如 gdb 的條件斷點加 `commands`、Erlang 的 trace 加 `sys:suspend`、DTrace 的 `stop()`、monit、混沌工程的中止條件。值得抄的有兩點：
   - **防誤報**：條件要「連續幾次才算」，單次就停容易誤停。
   - **能不能續**：停了能不能續要先講清楚。
8. **四個樣子**（[05](05-發想.md)、[05-續](05-續-兩個問號與要你先說的題.md)）：
   - **甲**：只用 shell 的對照組。
   - **乙**：條件放 agent 裡的 hook，由 aos-gdb 庫幫你裝。
   - **丙**：條件放外面的觀察者 proc。
   - **丁**：hook 當感應器、觀察者當裁判，收成一包現成的觸發器。這也對上你說的「選了之後就會添加一些除錯用的觸發器」。

   推薦（由你拍板）：先試乙，丙接著做，丁讓它從乙丙自然長出來。aos-gdb 做成薄殼：每個動作背後是一條 shell 指令或讀一個檔，所以不擋將來用 Lisp 整合。
9. **沒有要你先說的題。** 你這次已經把方向說完了。剩下四件（本體是檔還是 Python 物件、fsm 插格寫共用定義、停住時外面看不看得見、要不要重播），都可以先照推薦走、用到再說，理由在 05-續。
