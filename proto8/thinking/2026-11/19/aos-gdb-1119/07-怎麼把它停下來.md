# 怎麼把它停下來：今天所有停得住一支 agent 的手段（hook 自己發停、外面的 proc 來停、Linux 訊號），各停在哪、看得到改得到什麼、怎麼續（含 11-19 新實測）

← [README](README.md)｜上一份：[06-使用者回應](06-使用者回應.md)｜下一份：[05-發想](05-發想.md)（重寫後以本份為底）

使用者的新定義：斷點＝「特定條件發生時，暫停loop或fsm，停下來等待檢閱」，條件由 hook 或另一個 proc 判斷，「能把他停下來的都可以」（[06](06-使用者回應.md)）。這份把手段盤一遍。證據標三種：**新測**（11-19 第二輪，`~/.aos/scratch/aos-gdb-1119/13-stops2.sh`→`13.log`，`12.log` 只取 T6）、**沿用**（第一輪 log）、**讀程式**或**沒測**（寫理由）。假腦；實測用的慢腦 `fake-demo-slow`（每次答前等 3 秒）。

## 先講結論

1. **最乾淨的停法今天就有，而且 hook 和外面的 proc 用的是同一招**：叫 `aos-agent ctl pause`（寫控制窗 `ctl.json`）。loop 在**兩步（兩格）之間**停，行程不死、stack 全在、信照收；`ctl resume` 接著走，**實測不丟東西**——連「腦正在答的時候按暫停」也一樣：答案先放在信箱，續了才收。
2. **hook 發停 = hook 程式裡叫一行 `ctl pause --no-wait`**，hook 機制一個字都不用動（實測）。停在「這一格做完」：`before_tool` 裡發的，工具照跑、結果寫進 history，停在下一格（think）開頭。
3. **外面另開一個 proc 當觀察者也行**：實測一支 15 行的 bash 每 0.2 秒看 `observed.jsonl`，看到新的工具紀錄就發 pause，約 2.5 秒內停住。**今天沒有事件可等，只能輪詢**（aos 全輪詢；這台也沒有 `inotifywait`）。
4. **不建議當斷點用的三種**：hook 故意失敗（會讓 agent 掛掉、被 daemon 連重起三次才放棄）、`ctl stop`（行程真的退出、換 pid，但續得回來）、Linux 的 `SIGSTOP`（凍得住、續得回來，但 **aos 完全不知道它停了**，表上照寫 running）。kernel 的 hold 停不了跑著的 agent（只卡「起 proc」的信；問腦的 llm kernel 不支援 hold）。
5. **停住時人看得到、改得到的全在 stack 的檔**；缺的仍是「外面看得出它為什麼停」：pause 會在表上顯示 `paused`，但不知道是誰、因為什麼條件停的。

## 一、hook 自己發停（hook 機制不動）

一支 hook 今天能用的「讓 loop／fsm 停」的方式：

| 方式 | 會怎樣 | 停在哪 | 狀態寫什麼 | 怎麼續 | 證據 |
|---|---|---|---|---|---|
| hook 裡叫 `aos-agent ctl pause --no-wait <自己>` 再回 0 | 這次工具照跑；這一格做完就停 | 下一格開頭（實測 `stage.txt`＝`think`） | `state.json` `paused: true`；`ctl ls` 顯示 `paused`；daemon 表仍 `running`（行程活著） | `ctl resume` | **新測** T1（13.log）：hook 09:07:42 發、09:07:44 已停；resume 後答完 |
| hook 裡叫 `ctl stop --no-wait <自己>` | 這一輪做完，loop 退出 | 同上，之後行程沒了 | `state.json` `stopped`；表上 `stopped`、沒有 pid | `ctl start`：新 pid、history 與信箱都在 | **新測** T3：停後 `start` 回「0 queued letter(s) will be answered next」，接著答完 |
| hook 卡住不回（會等的 hook） | agent 停在 hook 裡 | 「腦已決定叫工具、工具還沒跑」 | **什麼都沒寫**：表與 `ctl state` 都是 running | hook 自己結束 | **沿用** 09.log |
| hook 回 10（擋） | 只擋這次工具，不停；腦收到「被擋」字樣繼續想 | 不停 | — | — | **沿用** 06.log |
| hook 回 JSON | 只能改 `arguments`（before_tool）或 `content`（before_queue、after_tool）；**沒有「停」這個鍵** | 不停 | — | — | **讀程式** `py/aos/agentlib/hooks.py` 第 44～52 行 |
| hook 失敗（退出碼非 0、非 10；`on_error` 預設 stop） | 那一格報 `HookFailed`，fsm 退 1，loop 以 `RunFailed` 結束；daemon 自動重起，**又撞同一個 hook**，連三次後「not restarting again」 | 掛掉 | 表上 `stopped`，LAST ERROR 寫原因；`state.json` `done` | 拿掉 hook 後 `ctl start`；實測從原地接著叫那個工具、答完 | **新測** T2：hook 在 0.7 秒內被叫了 4 次 |
| hook 直接寫 `ctl.json` | 等於 `ctl pause` 做的事 | 同 pause | 同 pause | 同 pause | **讀程式**（`py/aos/daemon_ctl/ctl.py` 的 `write_ctl`），沒另測 |
| hook 寄一封信 | 信寄給誰都不會讓這隻停；只能用來「通知人」 | 不停 | — | — | 推想 |

注意：**pause 型的 hook 每次條件成立都會再停**（第一輪實測：放行後下一個工具呼叫又停）。要「只停一次」得 hook 自己記、或停完就 `hook rm`。

## 三、「停下來等待檢閱」時看得到、改得到什麼

**看**（都在 [02](02-aos現況.md) 第二節的表）：`stage.txt`（停在哪格）、`state.json`、`history.jsonl`、`observed.jsonl`、`think/request.json`（最後一次問腦的整份）、`queue/new/`（堆著的信）、`hooks/<名>/event.json`、`stderr.txt`、llm kernel 的 `ledger.jsonl`；一句話版是 `aos-agent ctl state -t <名> all`。

**改**（停著時改，續了就用新的）：工具、system、hook、llm 的疊層（`aos-agent tools／system／hook／llm`，下一輪生效）；`stage.txt`（跳到別格）；定義夾的 `fsm.json`（下一格生效）；`history`（`aos-agent history rm／set`）。實測見 [02-續](02-續-插入與Python.md) 第一節。

**放行**：pause 型 → `ctl resume`；stop 型 → `ctl start`；會等的 hook → 讓 hook 結束；SIGSTOP → `SIGCONT`。

## 四、觀察者要「發現有問題」，今天有什麼可看

| 來源 | 內容 | 怎麼得知有新東西 |
|---|---|---|
| `observed.jsonl` | 每次想（端點、用量、耗時）、每次工具（名、路徑） | 輪詢行數（T7 用這個） |
| `history.jsonl` | 對話、工具呼叫與結果、答案 | 輪詢 |
| `stage.txt`、`state.json` | 現在哪格、phase | 輪詢 |
| `queue/new/`、`letters.json` | 進來的信、在途的信 | 輪詢目錄 |
| `cooldown.json`、`stderr.txt` | 腦失敗、錯誤行 | 檔出現／變大 |
| llm kernel `ledger.jsonl`、`used.json` | 每次問腦的帳與用量 | 輪詢 |
| `aos-agent ctl state`、`ctl ls -l` | 十一類、排隊數、重起數、最後錯誤 | 每次叫一次 |
| hook 本身 | 事件當下就在手上（工具名、參數、信的內容） | **事件驅動**：唯一不用輪詢的 |

白話：**在 agent 裡面的 hook 是「事情發生時被叫」；在外面的觀察者只能「隔一陣子看一眼」**。前者準（停在事件當下或下一格），後者晚一點（實測晚一格）但完全不碰那隻 agent。兩者可以合用：hook 只負責把事件記下或發停，判斷交給外面。aos 的 `on_clock` hook 是第三種：在 agent 裡、但定時被叫（每 N 格或每 N 毫秒）。
