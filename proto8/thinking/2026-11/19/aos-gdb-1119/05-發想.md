# 發想（上）：「Python REPL＋aos-gdb 庫」加上「程式邊跑邊長」可能長成的六個樣子

← [README](README.md)｜上一份：[04-邊緣狀況](04-邊緣狀況.md)｜續：[05-續-兩個問號與要你先說的題](05-續-兩個問號與要你先說的題.md)

照「需求不清時先發想」：這是頭腦風暴，不出施工圖、不排步驟、不定檔案格式。每案裡的 `>>>` 都是**示意，不是設計**，函式名隨手取的。兩個問號、一覽表、推薦、要你先說的題在[續篇](05-續-兩個問號與要你先說的題.md)。

## 先講結論

1. **你想像的流程，最陽春的版本今天就做得出來**：[02](02-aos現況.md) 第三節實測的「會等的 `before_tool` hook」就是斷點，加工具、換 system 都不用停（[02-續](02-續-插入與Python.md) 第一節）。差的是四件：外面看不出它停住、沒有正式的放行通道、斷點每次都停、停的地方對不回原始碼。
2. **六個樣子其實只有兩個大分岔**。第一個：斷點活在**檔案**裡（乙）還是活在 **Python 物件**裡（丙）——這決定 REPL 關掉會不會出事、也決定擋不擋 Lisp。第二個：主要靠**停下來**（乙丙丁戊）還是靠**錄下來**（己）。
3. **「下一步看不到」的解法是把三個詞重新定義**，六案共用：step＝走到下一個邊界（下一格、下一次工具呼叫、下一封信）；斷點位置＝事件名＋條件，不是行號；backtrace＝走過的邊界流水帳。事前看得到的是「可能去哪」（這格的箭頭、工具清單），看不到的是「這次走哪條」（[02](02-aos現況.md) 第一節）。
4. **斷點是不是 hook：工具呼叫和收信這兩層是，格這一層不是**——agent 的九個事件裡沒有「某一格開始前」。你昨晚說除錯「主要是loop那邊」，這裡有落差，列成題。
5. **debug 旗標三層不互斥**。跟庚的「C 與 .o」最合的是**執行時**（完全不碰定義夾）；**生成時**那份會跟著重生被蓋，而且跑到一半插進來的東西沒有出處；**插入時**記一筆是唯一能回答「當時程式長怎樣」的。
6. **有一處跟今天早上的裁定對不上，要你定**：插進定義夾 json 的新指令，下次從 `agent.py` 重生就無聲消失（[04](04-邊緣狀況.md) 第 16 條）。「程式持續增長」要長在哪裡，是續篇第 3、4 題。
7. **推薦（由你拍板）**：乙當底（斷點是檔），丁當 loop 層的第一個動作（REPL 手搖一格），戊做成乙上面的一種斷點；丙的「函式斷點」只當乙上的一層薄殼；己先只做「錄」、不做重播。

## 甲（對照組）：不做庫，shell 指令＋一支會等的 hook 腳本

```
$ aos-agent hook add -t ann --event before_tool --condition write ./bp.sh   # 下斷點
$ aos-agent say -t ann "整理 notes"       # 跑
$ cat .stack/procs/ann/hooks/bp/event.json   # 停住了：腦點了哪個工具、什麼參數
$ aos-agent tools add -t ann -n math2 ./tools/math2   # 插一個新工具
$ touch go                                 # 放行（bp.sh 在等這個檔）
```

- **怎麼停**：工具要跑前（`before_tool`）、信要進對話前（`before_queue`）；格的層級用 `ctl pause`。**怎麼插**：全用現成指令，工具、system、hook 寫在這隻自己的疊層（只記這隻改過什麼的那幾份檔），插一格只能改定義夾的 `fsm.json`。**怎麼續**：放行檔、`ctl resume`。
- **下一步看不到**：不處理，人自己去讀 `fsm.json` 和 `tools ls`。
- **好處**：今天就能用，[02](02-aos現況.md) 的 09.log 就是這一案；零新概念；昨天 D7 說的「第一個需要的人會自己寫」。
- **代價**：[04](04-邊緣狀況.md) 第 1、2 條原封不動（外面看不出停住、每次都停）；每個人各寫各的 `bp.sh`；「Python REPL」只是 `subprocess` 包 shell。
- **合不合／Lisp**：完全合，不擋。**自然長**：已經長出來了。

## 乙：「斷點是一個檔」——檔案約定當核心，Python 庫只是薄殼

```
>>> import aos_gdb as g
>>> p = g.attach("ann")                       # 只是記住它的 stack 在哪
>>> p.break_at(event="before_tool", name="write", once=True)   # 在 stack 放一張「斷點單」
>>> p.say("整理 notes"); p.wait_stop()        # 等「停住單」出現
>>> p.where()                                 # 現在哪一格、腦點了什麼、疊層現況
>>> p.add_tool("math2", "tools/math2")        # 就是 aos-agent tools add
>>> p.cont()                                  # 寫一張「放行單」
```

- **是什麼**：把甲的 `bp.sh` 收成一支大家共用的「會等的 hook」，它只認三種檔：**斷點單**（哪個事件、什麼條件、停一次還是每次）、**停住單**（它停下時自己寫，誰都看得到）、**放行單**。Python 庫的每個方法＝一條 shell 指令或讀寫一個檔。
- **怎麼停**：邊界同甲，多了「只停一次」和「外面看得見」。**怎麼插**：同甲，薄殼順手在 stack 記一筆「插了什麼」。**怎麼續**：寫放行單；REPL 關掉也沒事，別人 `ls` 得到停住單、用 shell 一樣能放行。
- **下一步看不到**：`p.arrows()` 讀 `fsm.json` 印這格每個結束碼走哪、`p.tools()` 印腦可能叫誰；`p.step()`＝放一張「下一個邊界停一次」的斷點單再放行。
- **好處**：檔案即狀態；agent 不知道自己被除錯，只是多一個 hook（C-52 上層不知道下層）；斷點單多寫的 key 別的程式不理（C-48）；shell 和 REPL 用同一套，正好是你說的「python repl + shell指令」。
- **代價**：三種單一旦有人用就難改；靠輪詢檔有延遲（實測的 `bp.sh` 是 0.2 秒看一次）；條件只能寫得出「事件名＋工具名」這種簡單的。
- **Lisp**：不擋，Lisp 再包一層薄殼就好。**自然長**：會，甲被第二個人用的時候就會收成這樣。

## 丙：「斷點是一個 Python 函式」——REPL 當駕駛座，hook 連回 REPL

```
>>> p = g.attach("ann")                       # REPL 開一個小門，等 hook 連回來
>>> @p.on("before_tool")
... def stop(ev):                             # 回 True 才停，像 gdb 的 Breakpoint.stop()
...     return ev["name"] == "write" and "secret" in str(ev["arguments"])
>>> p.run("整理 notes")                       # 停住時直接回到 >>>
>>> p.ev["arguments"]["path"] = "notes2.md"   # 改參數
>>> p.cont()
```

- **怎麼停**：邊界同乙，但停不停由 REPL 裡的函式當場決定，條件隨便寫，也能「不停、只記一筆」。**怎麼插**：同乙。**怎麼續**：REPL 直接回話給那支 hook。
- **下一步看不到**：同乙；另外函式可以寫「腦點了我沒料到的工具才停」。
- **好處**：最像 gdb 的 Python API 和 pdb；條件斷點、寫腳本自動除錯最強；不用輪詢。
- **代價**：**REPL 變成單點**——關掉或當掉，停住的 agent 全卡著（[04](04-邊緣狀況.md) 第 8 條）；斷點活在 Python 記憶體裡，別人和別隻 agent 看不到（不合檔案即狀態）；跨機器要開網路埠（[03-續](03-續-REPL與邊跑邊改.md) 每家都警告）；還要守 gdb 那條「決定停不停的函式裡只准看、不准改」。
- **Lisp**：**會擋**，斷點和狀態都是 Python 物件，換語言要重做。**自然長**：不會，要專門設計。
- **折衷**：把它疊在乙上——函式斷點＝REPL 裡有一小段程式盯著停住單、跑你的函式、不該停就自動放行。這樣好寫的條件還在，底下仍是檔，就不擋 Lisp；代價是多一次輪詢的延遲。

## 丁：REPL 當 loop——一格一格手搖

```
>>> p = g.take("ann")            # 先請 loop 停手（pause），之後由 REPL 來推
>>> p.stage                      # 'think'
>>> p.arrows()                   # 這格每個結束碼走哪（讀 fsm.json）
>>> p.step()                     # 跑一次 aos-exec fsm.json，回這格的結束碼
>>> p.step(until="act")          # 推到 act 格之前
>>> p.insert_state("note", after="act", run=["note.py"])   # 在指令中間插一格
>>> p.release()                  # 交還給 loop
```

- **怎麼停**：格與格之間，天生每一格都停。要看進 act 格裡面（腦點了哪個工具）得搭乙的工具斷點。**怎麼插**：格與格之間沒有東西在跑，是最安全的插入時機；插一格寫的是定義夾的 `fsm.json`，下一格就生效（[02-續](02-續-插入與Python.md) 實測）；改 `stage.txt` 就是跳到別格。**怎麼續**：再搖一格，或交還 loop。
- **下一步看不到**：這一層最看得到——格和箭頭事前都寫死，看不到的只有「這次的結束碼」。
- **好處**：最貼昨晚的裁定「主要是loop那邊」；不用新機制，手推一格實測可行（[02](02-aos現況.md) 第三節）；你說的「在他的指令中央插入新指令」在這裡最直白，而且插的是寫死的程式格，正是 C-22「能寫死的節點換成程式」。
- **代價**：手推要自己湊齊環境變數（實測 wait 格回 `LlmKernelMissing`）；沒先停 loop 會兩邊搶 `stage.txt`（[04](04-邊緣狀況.md) 第 12 條）；pause 要等這輪做完；**`fsm.json` 沒有疊層**，插一格是改共用的定義，而且下次重生就被蓋；eca 身沒有格，一步就是一整回合。
- **Lisp**：不擋，底下就是一條 shell 指令。**自然長**：會。

## 戊：出錯才停，列出「可以怎麼接下去」

```
>>> p = g.attach("ann"); p.catch("tool_error")    # 不預先下斷點
>>> p.run("把上個月的帳加總")
停在 after_tool：math: error: ArgBad ...          # 現場還在
可以怎麼接下去： 1 原樣交給腦   2 換一個結果再交給腦
                 3 先加一個工具、再告訴腦改用它   4 中止
>>> p.add_tool("sum_csv", "tools/sum_csv"); p.go(3)
```

- **怎麼停**：平常不停；工具回了錯誤行（`toolname: error: Code`）才在 `after_tool` 停，腦出錯可接 `brain_failed`。這對應你說的「把他停下來(或是不停)」。**怎麼插**：停下的那一刻，通常就是「發現萬能函數缺一個工具」的那一刻；加的工具寫疊層。**怎麼續**：從清單選一條。
- **下一步看不到**：這案乾脆不預測，不問「下一步是什麼」，只問「出事了沒」。
- **好處**：最貼你的新範式——每停一次，程式就多一個寫死的零件（C-22）；不用事前知道斷點該下在哪；它就是 Lisp 的 condition／restart（[03-續](03-續-REPL與邊跑邊改.md)），離你的遠景最近。
- **代價**：只抓得到「會報錯」的毛病，沒報錯但做錯的抓不到；`after_tool` **只能改結果、不能擋也不能重叫**（讀 `py/aos/agentlib/hooks.py` 的事件表），所以「改參數重叫一次」今天沒有門，只能用「換一段結果文字請腦自己重來」頂著；等人的 hook 要把逾時設成不限時。
- **Lisp**：不擋，反而是預演。**自然長**：半自然，它是乙上面的一種斷點單。

## 己（對照組二）：不停、全錄，事後翻帶子

```
>>> r = g.record("ann")          # 掛只記不擋的 hook，每拍順手記現在哪一格
>>> p.run("…")                   # 照常跑完，一次都不停
>>> r.steps()                    # 走過的每個邊界：格、工具、當時疊層是哪一版
>>> r.at(9).diff()               # 第 9 步之前，程式被插了什麼
>>> q = r.fork(9)                # 複製一棵暫存樹，照錄的答案重播到第 9 步
>>> q.add_tool(…); q.cont()      # 從這裡起才真的問腦
```

- **怎麼停**：不停。**怎麼插**：插在複製出來的那棵樹上。**怎麼續**：前半段拿錄好的腦答案，之後換真腦。
- **下一步看不到**：反過來變成「上一步全看得到」，補上今天沒有的兩樣：格的走法、每一步當時的程式是哪一版。
- **好處**：不打擾正在跑的東西，[04](04-邊緣狀況.md) 第一節那八條（佔資源、期限過、信堆著）全部不會發生；多隻並行也錄得了；接昨天的 D6。
- **代價**：重播要有人把 history 轉成劇本腦的劇本，今天沒人接（[02](02-aos現況.md) 第四節）；工具的副作用重播會再做一次，只能在暫存樹裡來；不能當場救；錄的東西會越積越多。
- **Lisp**：不擋，錄的都是檔。**自然長**：「錄」會，「重播」不會。
