← [README](README.md)｜上一份：[05-發想](05-發想.md)

甲～己六案在[上篇](05-發想.md)。這份只攤現況與選項，不替你定；推薦都標明是推薦。

## 問號 (a)：斷點是不是就用 hook？

**短答：工具呼叫和收信這兩層，是，而且今天就停得住；格（loop）這一層不是，hook 沒有那個掛點。**

agent 的九個事件（讀 `py/aos/agentlib/hooks.py` 第 42～52 行）：

| 事件 | 什麼時候 | 能擋下 | 能改什麼 | 當斷點 |
|---|---|---|---|---|
| `before_queue` | 信要進對話前 | 能 | 信的內容 | 可以 |
| `before_tool` | 腦點了工具、工具還沒跑 | 能 | 參數 | **可以，實測過** |
| `after_tool` | 工具跑完、結果還沒給腦 | 不能 | 結果 | 只能看與改結果 |
| `after_queue`、`brain_failed`、`tool_added`、`after_start`、`after_stop`、`on_clock` | 信進了對話、腦出錯、多了新工具、loop 起來、loop 要退、時鐘到了 | 不能 | 不能 | 適合拿來「記一筆」 |

kernel 的三個事件（`py/tools/aos/kernel/hooks.py`）：`before_verdict`（判決前，可改信的內容）、`after_verdict`（判決後，可改判決、可回「先留著」）、`before_reply`（回信前）。這三個攔的是「起停 proc、問腦」的信，本線沒實測。

- **能不能停住等人**：能。hook 沒回之前 agent 就等著，一支「會等的 hook」加上不限時就是斷點；[02](02-aos現況.md) 第三節實測停 0.5 秒到 20 多秒都照常接續。
- **停住時看得到什麼**：事件本身（工具名、參數）、整個 stack 的檔、`ctl state` 的十一類。**改得到什麼**：`before_tool` 回話改參數或擋掉；同時用現成指令加工具、換 system、加 hook，下一次問腦或下一個事件生效。
- **缺什麼**：外面看不出它停在斷點上（`ctl state` 照寫 running）；沒有正式的放行通道（實測是土法等一個檔）；斷點每次都停、沒有「只停一次」；**格與格之間沒有事件**；eca 身自己的工具攔不到（[04](04-邊緣狀況.md) 第 13 條）。

格這一層的選項：

| 選項 | 意思 | 後果 |
|---|---|---|
| a1 | 格層不用 hook，用 pause 或 REPL 手搖（丁） | 不動現有程式；「斷點」變成兩套說法（格用手搖、工具用 hook），由薄殼蓋成同一個 `step` |
| a2 | 替格的邊界新增 hook 事件 | 斷點統一成一套；要改 agent-fsm 那四格的程式，而且每格多起一次 hook |
| a3 | 再加 kernel 站當斷點（昨天的 D4） | 停得到「問腦送出前」，agent 完全不用動；只攔得到信 |

## 問號 (b)：debug flag 放哪一層？

你的兩句話剛好各指一層：「編譯時加debug flag，然後hook就有東西」是**生成時**；「插入新指令的時候就要放debug旗標」是**插入時**。再加一層你沒說、但今天最便宜的**執行時**。

| 層 | 長相（示意） | 代價 | 跟庚「C 與 .o」 | 跟「邊跑邊插」 |
|---|---|---|---|---|
| **生成時** | `agent.py` 重生時開一個開關，多生：①格與工具的出處對照（哪一格出自 `agent.py` 第幾行），②一組現成的除錯 hook——這就是「hook 就有東西」 | 行號很粗（一行 `FSM = …` 生出整份 `fsm.json`，[04](04-邊緣狀況.md) 第 21 條）；庚生 hook 排在第三刀；出處若寫進 json，每次改動都帶假的差異（[庚 11](../aos-compile-庚/11-跟除錯那條線的接點.md) 傾向現算、不寫進去） | **合，而且就像 `-g`**：開著重生一次是除錯版，關掉再重生蓋回乾淨版。但開關重生一樣會蓋掉手插的東西 | **有洞**：跑到一半插的格、agent 自己加的工具都沒有出處（[04](04-邊緣狀況.md) 第 18 條） |
| **插入時** | 每一次插入（加工具、換 system、加 hook、插格）順手在 stack 記一行：誰、何時、插了什麼、原本長怎樣 | 走指令與 aos-gdb 的才記得到，直接手改檔的記不到；要連 agent 的 `self_*` 也記，得動現有指令（工具這一項有現成的 `tool_added` 事件可以掛） | **不受影響**：記在 stack，重生碰不到。這本流水帳也正是「把插進去的東西收回 `agent.py`」的材料 | **正中**：唯一能回答「那時候程式長怎樣」的一層（Pharo 的 `.changes` 就是這個） |
| **執行時** | REPL 掛上去那一刻才裝 hook（寫這隻的疊層，下一個事件生效、不用重起也不用重生），每個邊界記一行；離開時拆掉 | 掛上之前的事沒記到；只對得回「json 的哪一格」，對不回 `agent.py` 的行 | **最合**：完全不碰定義夾 | **不需要出處**：記的是當下實況，插進來的照樣記到 |

三層可以疊：執行時負責「停」與「記走法」，插入時負責「程式的每一版」，生成時負責「對回原始碼行」。差別只在先做哪一層。

## 你的新想法跟已有裁定對不上的三處（照實列，不替你選）

1. **「程式持續增長」對上「C 與 .o」**：插進定義夾的格與工具，重生就無聲消失；插在疊層的（工具、system、hook）不受影響；但 `fsm.json` 沒有疊層，所以「在指令中央插一格」今天只有會被蓋的那條路。→ 第 3、4 題。
2. **「主要是loop那邊」對上「斷點用 hook？」**：hook 的掛點在工具與信，不在格。→ 第 1 題。
3. **「編譯時加 debug flag」對上「產出後就無關」**：不衝突，但生成時的旗標管不到之後插進來的東西。→ 第 5 題。

## 推薦（是推薦，由你拍板）

1. **乙當底**。你要的是「python repl + shell指令」兩個一起，只有「斷點是檔」能讓兩邊用同一套；它也是唯一同時解掉「外面看不出停住」「每次都停」「REPL 關掉怎麼辦」的一案，而且不擋 Lisp。
2. **丁當 loop 層的第一個動作**。它直接對上昨晚的裁定，零件實測過，而且「在指令中央插一格」在格與格之間做最安全。
3. **戊不另做一套，做成乙的一種斷點**（「工具報錯才停」的斷點單）。它最貼「先萬能函數、再逐步加工具」，今天做得到的是「停下、看、加工具、換結果」這幾條。
4. **丙只當乙上面的薄殼**，不讓斷點只活在 Python 記憶體裡。
5. **己先只做「錄」**（格的走法、每次插入記一筆），重播等真的需要那天。
6. **旗標先放執行時＋插入時**，生成時那層跟著庚的第三、四刀再說。理由：前兩層今天就不用改定義夾、不怕重生，也不會漏掉插進來的東西。

## 要你先說的題（七題）

**1. 斷點先顧哪一層？**
- a 格（loop 層）：照昨晚的裁定；用手搖（丁），不用新增 hook 事件，但看不進 act 格裡腦點了什麼。
- b 工具呼叫前：門現成、實測過；但那不是 loop 層。
- c 兩層都要，格用手搖、工具用 hook，薄殼蓋成同一個 `step`：不動現有程式，底下是兩套機制。
- d 兩層都要，而且替格新增 hook 事件：一套到底，要改 agent-fsm 的四格。
- 推薦 c。

**2. aos-gdb 的本體是「一組檔案與指令的約定」，還是「Python 物件」？**
- a 檔案約定，Python 是薄殼（乙）：shell 與 REPL 通用、REPL 關了沒事、Lisp 包一層就好；條件只能寫簡單的。
- b Python 物件（丙）：條件隨便寫、最像 gdb；REPL 是單點，Lisp 要重做。
- c a 當底、b 疊上去：兩邊好處都有，多一點延遲。
- 推薦 c，至少是 a。

**3. 跑到一半插進去的東西，要不要活過下一次重生？**
- a 不用：插入只是當場試，試完該留的由人寫回 `agent.py`。最貼「C 與 .o」；忘了寫回就沒了，沒有提醒。
- b 要，長在 json 上：`agent.py` 只是起手式，之後不再重生。最貼「程式持續增長」；`agent.py` 會越來越不是真的。
- c 要，長在 `agent.py` 上：每次插入都改 `agent.py` 再重生。兩邊一致；插入的工具得會改 Python，今天沒有。
- 推薦 a，配「插入時記一筆」，寫回時有帳可查。

**4. 「在指令中央插一格」今天只能改共用的定義夾（`fsm.json` 沒有這隻自己的疊層），怎麼看？**
- a 接受：插格就是改定義，同一份定義的 agent 一起變，重生會蓋。
- b 想要 fsm 也有疊層：只改這一隻、重生不蓋；要動 aos-fsm 那邊的程式，是一件不小的事。
- c 插格一律走 `agent.py`：要插就改原始碼再重生，「邊跑邊插」只限工具、system、hook。
- 推薦先 a，用到痛了再談 b。

**5. debug 旗標先做哪一層？**
- a 執行時（REPL 掛上才裝 hook）：不碰定義、今天就行；對不回 `agent.py` 的行。
- b 插入時（每次插入記一筆）：補上「當時是哪一版」；手改檔的記不到。
- c 生成時（重生時多生出處對照與除錯 hook）：對得回原始碼行；要等庚後面幾刀，管不到插進來的東西。
- 推薦 a＋b 先，c 之後補。

**6. 停在斷點時，要不要讓外面一眼看得見？**
- a 只有停住單：不動現有程式；`ctl state` 和全景頁照樣寫 running，別人可能以為它卡住而去停它。
- b `ctl state` 和全景頁也顯示「停在斷點」：不會誤會；要改現有程式。
- 推薦先 a，等有第二個人或 agent 會看到它時再做 b。

**7. 重播要不要拿錄好的腦答案（不花錢、每次一樣）？**
- a 先不做重播，只錄走法：便宜；想重來一次只能真的再問腦，答案可能不同。
- b 做「從 history 抽出劇本」：重播不花錢、可以反覆試同一步；副作用要在暫存樹裡處理。
- 推薦先 a。
