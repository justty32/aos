# 範圍切法：第一刀最小做到哪（能儘快試到原型）、之後四刀各是什麼、哪些明講不做

← [README](README.md)｜上一份：[07-邊緣狀況](07-邊緣狀況.md)｜下一份：[09-要使用者拍板的題](09-要使用者拍板的題.md)

只切範圍，不寫施工細節；細化成施工計劃是下一步交給 opus 的事。

## 先講結論

- **第一刀只加兩樣東西、不改任何現有程式**：一個 lib（`py/aos/agent_spec.py`）與一個骨架（`templates/agent-python/`）。做完使用者就能「空夾放一支 `agent.py` → 跑一次 → 掛上去」。
- 第二刀才去動 `agent_def` 與 `defs`，把打架規則接上。**第 1、2 題的答案只影響第二刀之後**；第一刀可以先開工。
- 每一刀都能單獨停下：停在哪一刀，前面做的都是完整可用的。

## 五刀

| 刀 | 做什麼 | 動到的現有程式 | 做完使用者能試什麼 |
|---|---|---|---|
| 一 | lib：`SYSTEM`／`TOOLS`／`LLM`／`FSM`／`DESCRIPTION`／`META`／`INTERFACES`、`ag.by_hand`、路徑小工具、生成前檢查（`SpecBad`）、記帳與四種狀況、`--write-defs`／`--force`／`--defs`／`--status`。骨架：一支 `agent.py`（就是 [04](04-agent-py-兩個例子.md) 的最小例子）＋它生出來的檔＋README | 無 | `agent_def new` 抄骨架（今天的 `new` 不用改就認得，因為骨架裡有 `interfaces.json`）→ 改 `agent.py` → `python3 agent.py --write-defs` → `aos-agent ctl add`，用假腦問一句 |
| 二 | 接進 `agent_def`：`check` 先重生再查、輸出多一格說寫了什麼；`tools`／`llm`／`system` 碰到生成檔的處理（照第 2 題）；`new` 抄到有 `agent.py` 的夾時改成在新位置重生。`defs check` 多兩句唯讀的問題（過時、被手改） | `agent_def/_entry`、`def_edit.py`、`defs/catalog.py`、兩支的 `_tooldef.json` 與測試 | 不必記 `--write-defs`，照今天的習慣打 `agent_def check` 就好；故意手改一份 json 看它怎麼講 |
| 三 | 補齊能宣告的東西：`HOOKS`（含「用範本那組」）、`FILES`（原樣吐）、不宣告 `FSM` 的部分接管（eca-claude、eca-pi 可用）。用它把 reviewer 重寫一遍當驗收：重生結果要跟今天手寫的等價 | lib 與骨架；範本要不要真的換掉看第 5 題 | [04](04-agent-py-兩個例子.md) 的 reviewer 例子與 eca 例子 |
| 四 | 除錯接點（使用者 11-18：「主要是loop那邊」）：`python3 agent.py --where` 印「狀態機的哪一格 ← `agent.py` 第幾行」；`ctl add`／`set-def` 碰到過時或被手改時印一行警告 | `ctl/add.py`、`ctl/set_def.py`（只加警告） | 手打 `aos-exec fsm.json` 走一格，對得回 `agent.py` 哪一行 |
| 五 | 收尾：寫進知識庫讓 agent 也會用（看第 4 題）；跟己（一頁總覽）接上——總覽直接吃 `--defs` 的輸出 | `knowledge/aos/`、`agent_def` 的說明 | agent 自己用 `agent.py` 做新定義 |

## 為什麼這樣切

1. **第一刀不改現有程式**，所以不會弄壞任何正在用的東西，改 `py/` 後要重跑的 `install.py` 也只是多抄一支 lib。這符合「快速做原型讓他試」，試了不喜歡整個拿掉也不留痕跡。
2. **記帳與四種狀況放在第一刀**，不留到第二刀。理由：它是 lib 寫檔那一段的一部分，量很小；而且少了它，第一刀的原型就會是「一律蓋」，使用者試到的手感會跟最後的不一樣。若第 1 題選 a（照工具版直接蓋），第一刀把這段拿掉即可，其他不受影響。
3. **eca 放第三刀**：它需要「部分接管」這個比較繞的模式，而第一、二刀先把最直接的一條路（有狀態機、整夾都生）走通。使用者若最常做的其實是 eca 版，可以把它提到第二刀前面，見第 3 題。
4. **行號對照不寫進生成檔**。11-18 的玩具在每份 json 加 `_from: "prog.py:13"`；真這樣做的話，`agent.py` 前面多加一行，後面每份 json 的行號都變，git 裡全是假的 diff、指紋也全變。改成要看的時候現算（`--where`），生成檔保持穩定。

## 明講不做的

| 不做 | 理由 |
|---|---|
| 從 json 反推回 `agent.py` | 11-18 調查：沒人做到全自動；`agent.py` 裡的迴圈、小函式推不回來 |
| 生 stack 裡的東西、daemon 表上的設定（limits、envs、kit、掛在誰底下） | 那是記憶體與部署，不是定義；做了就變成丙案或部署工具 |
| `agent.py` 直接當入口、掛的時候才生 | 那是丁案；庚的生成物是放在夾裡的普通檔 |
| 生成時把 `$env` 展開成絕對路徑 | 會綁死這台機器 |
| 生格的 Python | 肉不是骨架；借範本的或手寫 |
| 一次描述好幾隻 agent、整棵樹 | 那是丙案；庚一支 `agent.py` 對一個定義夾 |
| 舊格式相容、遷移 | proto8 一律當成沒有舊版 |
| 替生成檔加鎖、設唯讀 | 先看用起來會不會真的撞到 |
