# 範圍切法：第一刀的範圍說明（可直接交給 opus 細化施工）、之後幾刀各是什麼、哪些明講不做

只切範圍，不寫施工細節。使用者 11-19 六題裁定後重排過（[10](10-使用者裁定.md)）。

## 先講結論

- **第一刀只加一支 lib、一個骨架、一支測試，不改任何現有程式。** 裁定成「C 與 .o」之後，重生就是直接蓋，第一刀不含任何記帳或比對。
- **`agent_def`、`defs check` 幾乎不用動**：`tools`／`llm`／`system` 照常改 json、`new` 照常抄、`defs check` 照常查。原本剩的一小件「`agent_def check` 要不要順手重生」（第二刀），使用者 11-19 裁定劃掉，移到「明講不做」（[10](10-使用者裁定.md) 末節）。
- 所以實際上是：**第一刀 → 用一陣子 → 第三刀補 eca 與其他宣告**（第二刀已劃掉）。

## 第一刀的範圍說明

**目的**：使用者在一個空資料夾放一支二十來行的 `agent.py`，打一行指令，就得到一份掛得上去的 agent 定義。對應他的原話「讓我不必在那邊mkdir半天」。

**要加的檔**

| 檔 | 做什麼 |
|---|---|
| `proto8/py/aos/agent_spec.py` | lib，純標準庫，寫法與分層照同夾的 `tool_spec.py`。內容四塊：①宣告用的小函式（`pack`、`tool`、`no`、`home`、`env`、`fsm`、`state`、`stock_fsm`、`by_hand`）；②生成前檢查，寫錯報 `SpecBad`（查哪些見 [03](03-agent-py-長相.md)「生成前先驗」）；③「算出全部內容」的函式，回 `{"檔名": 內容}`，與「寫進某個夾」的函式（寫法見 [03](03-agent-py-長相.md)「重生時每份檔怎麼寫」與 [05](05-打架規則-總則.md)「寫檔的兩條保證」），兩個都能單獨被叫；④`main`：`--write-defs [資料夾]`、`--defs`、沒旗標印用法 |
| `proto8/templates/agent-python/agent.py` | 骨架本體，就是 [04](04-agent-py-兩個例子.md) 的最小例子：固定開頭（照 `templates/tool-python/tool.py` 那 20 行）＋ `DESCRIPTION`／`SYSTEM`／`TOOLS`／`LLM`／`FSM` ＋最後一行 |
| `proto8/templates/agent-python/` 下的 `_entry`、`body.json`、`loop.json`、`fsm.json`、`interfaces.json`、`tools.json`、`llm.json`、`system.txt`、`_metainfo.json` | 骨架那支 `agent.py` 生出來的結果，一起進 git（`agent_def new` 靠 `interfaces.json` 認範本；`tool-python` 也是把生成檔放進骨架） |
| `proto8/templates/agent-python/README.md` | 英文，給抄骨架的人看（對照 `tool-python/README.md`）：怎麼改、怎麼重生、怎麼掛；三句警語——重生會整份蓋掉宣告到的檔、直接改 json 的東西下次重生就沒了、改格名會讓停在舊格的 agent 停下 |
| `proto8/py/tests/test_agent_spec.py` | 測試（對照 `test_tool_spec.py`） |

另外順手改的只有說明文字：`templates/README.md`、`py/README.md` 的一覽各加一列。

**第一刀能宣告的**：`DESCRIPTION`、`SYSTEM`、`TOOLS`、`LLM`、`FSM`、`META`、`INTERFACES`、`ag.by_hand`。`ag.stock_fsm()` 是借 agent-fsm 範本的四格（使用者第 6 題）。`HOOKS`、`FILES`、不宣告 `FSM` 的模式都留給第三刀。

**明確不碰**：`agent_def`、`def_edit.py`、`defs`、`aos-agent ctl`、知識庫 `knowledge/aos/`（使用者第 4 題：先只給人用）、現有四個範本（第 5 題：不換）。夾裡不寫任何記號或帳。

**驗收看什麼**

1. 空夾放骨架那支 `agent.py`，`python3 agent.py --write-defs` 之後，`agent_def check` 對那個夾回 `{"problems": []}`。
2. `agent_def new` 用 `"template": "agent-python"` 抄得出來，抄出來的夾 check 也過，`lineage` 有寫。
3. 在暫存樹用假腦把它 `ctl add` 起來、問一句、有回、關乾淨（照活樹旁硬規則，在 `~/.aos/scratch/` 下做）。
4. 骨架裡進 git 的那幾份 json，跟骨架的 `agent.py` 當場重生的結果一字不差（測試守住，之後有人只改一邊會紅）。
5. 同一支 `agent.py` 連跑兩次，結果一字不差；輸出裡沒有時間、機器名、絕對路徑。
6. 三種寫錯各得到一行 `SpecBad`、夾裡一個字都沒變：狀態機的「下一格」不在表上、工具沒有路徑、`LLM` 的 `model` 不是字串。
7. 照裁定的行為：手改 `tools.json` 之後重生，被直接蓋回去、不報錯；`_metainfo.json` 裡別人的鍵（`lineage`）重生後還在；`README.md` 已經在就不動；`ag.by_hand` 的檔不動。

**做完使用者試的路徑**：`agent_def new` 抄骨架 → 改 `agent.py` → `python3 agent.py --write-defs` → `aos-agent ctl add`。改 `py/` 要重跑 `install.py` 才生效，在 repo 裡跑等於換掉使用中的那份，施工線要先回報。

## 之後幾刀

| 刀 | 做什麼 | 什麼時候做 |
|---|---|---|
| 二 | ~~`agent_def check` 順手重生~~ | **劃掉**（使用者 11-19：「第二刀劃掉吧」），移到下面「明講不做」（[10](10-使用者裁定.md) 末節） |
| 三 | 補齊能宣告的：`HOOKS`（含「用範本那組」）、`FILES`（原樣吐）、不宣告 `FSM` 的模式（eca-claude、eca-pi 可用；使用者第 3 題）。用它把 reviewer 重寫一遍當驗收，只比對、不換範本 | 第一刀用過之後 |
| 四 | 除錯接點（使用者 11-18：「主要是loop那邊」）：格 ↔ `agent.py` 行號的對照、生成時的除錯開關。要做什麼由除錯那條線的結論定（[11](11-跟除錯那條線的接點.md)） | 等 `aos-gdb-1119` 那條線 |
| 五 | 寫進知識庫讓 agent 也會用（使用者第 4 題：用順了再說）；跟己（一頁總覽）接上，總覽直接吃 `--defs` 的輸出 | 最後 |

第二刀已劃掉；第三刀本來就不靠它。每一刀都能單獨停下，前面做的都是完整可用的。

## 明講不做的

| 不做 | 理由 |
|---|---|
| 記指紋、對帳、偵測過時或手改、`--force`、`--status` | 使用者 11-19 裁定：產出後就跟 `agent.py` 沒關係 |
| `agent_def tools`／`llm`／`system` 碰到生成的 json 時擋下或標記 | 同上（第 2 題） |
| 從 json 反推回 `agent.py` | 11-18 調查：沒人做到全自動 |
| 生 stack 裡的東西、daemon 表上的設定 | 那是記憶體與部署，不是定義 |
| `agent.py` 直接當入口、掛的時候才生 | 那是丁案 |
| 生成時把 `$env` 展開成絕對路徑 | 會綁死這台機器 |
| 生格的 Python | 肉不是骨架；借範本的或手寫 |
| 一次描述好幾隻 agent、整棵樹 | 那是丙案；庚一支 `agent.py` 對一個定義夾 |
| 把現有範本換成 `agent.py` 寫 | 使用者第 5 題 |
| 舊格式相容、遷移 | proto8 一律當成沒有舊版 |
| `agent_def check` 順手重生（原第二刀） | 使用者 11-19 劃掉：`agent_def tools`／`llm`／`system` 照改 json，check 一順手重生就會蓋掉剛做的改動；檢查工具保持唯讀，重生只有 `--write-defs`（[10](10-使用者裁定.md) 末節） |
