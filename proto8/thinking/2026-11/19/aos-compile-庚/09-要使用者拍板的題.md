# 問使用者的六題：題目、選項、各自後果，與他選了哪個（11-19 早已全部答完）

← [README](README.md)｜上一份：[08-範圍切法](08-範圍切法.md)｜下一份：[10-使用者裁定](10-使用者裁定.md)

六題都已裁定，原話逐字在 [10](10-使用者裁定.md)。這份留著題目與各選項的後果，方便日後回頭看當時選的是什麼、放掉的是什麼。「✔」是他選的。

## 第 1 題：有人直接改了生成出來的 json，下次重生時怎麼辦

白話：`fsm.json` 是 `agent.py` 生的，但有人（或某隻 agent）直接打開 `fsm.json` 改了。之後再重生，要不要直接蓋掉？

| 選項 | 後果 |
|---|---|
| ✔ a. 直接蓋，不講（跟工具版一模一樣） | 最簡單，不用記任何帳。手改的內容無聲消失 |
| b. 停下來講一聲，加 `force` 才蓋 | 不會無聲弄丟東西。多一步；要在夾裡記每份生成檔的指紋 |
| c. 照蓋，但把被蓋掉的內容印在輸出裡 | 不卡人。輸出沒人看就還是丟了 |

## 第 2 題：`agent_def tools`／`llm`／`system` 碰到生成的檔，讓不讓它改

白話：今天要幫一份定義加工具，是叫 `agent_def tools add`，它直接改 `tools.json`。如果這份 `tools.json` 是 `agent.py` 生的呢？

| 選項 | 後果 |
|---|---|
| a. 擋下，告訴他去改 `agent.py` 的 `TOOLS` | 不會出現「改了又被蓋」。agent 要改一支 Python，比打一個工具呼叫難 |
| ✔ b. 照改 | 當下最順。配上第 1 題的 a：之後從 `agent.py` 重生，這次改的就無聲沒了 |
| c. 讓工具自己把改動寫回 `agent.py` | 只有很單純的寫法做得到 |

第 1、2 題合起來的後果，頂層當場再問了一次，他的回答就是「C 與 .o」那句（[10](10-使用者裁定.md)）。

## 第 3 題：eca 版（Claude Code、pi 當身體，沒有狀態機）排第幾刀

白話：你定的形狀是 SYSTEM／TOOLS／LLM／FSM 四樣。eca 版的 agent 沒有 FSM，要用另一種模式（`agent.py` 只寫 system、工具、腦設定三份，其他照舊抄範本）。這個模式要多早做？

| 選項 | 後果 |
|---|---|
| ✔ a. 第三刀 | 先把「有狀態機、整夾都生」這條最直接的路走通。eca 版要晚一點才能用 `agent.py` |
| b. 提到第二刀前面 | eca 版早點能用 |
| c. 不做 eca 版 | 最省。eca 版的定義永遠用手寫 |

## 第 4 題：要不要教 agent 自己寫 `agent.py`

白話：這個工具是只給你（人）用，還是也寫進知識庫、讓 agent 做新定義時也用它？

| 選項 | 後果 |
|---|---|
| ✔ a. 先只給人用，用順了再寫進知識庫 | agent 照舊用「抄範本、改 json」。知識庫暫時不變長 |
| b. 早早寫進知識庫 | agent 馬上會用。它們改 Python 比改 json 容易出錯；設計一變說明又要再改 |
| c. 永遠只給人用 | 最單純 |

## 第 5 題：現有的範本要不要改成用 `agent.py` 寫

白話：`templates/` 下的 agent-fsm、reviewer、eca-claude、eca-pi 現在都是手寫的 json。要不要把它們換成「一支 `agent.py`＋生成的 json」？

| 選項 | 後果 |
|---|---|
| ✔ a. 不換，只新增一個骨架 `templates/agent-python/` | 現有的東西一份都不動。reviewer 在第三刀會被重寫一遍當驗收，只拿來比對 |
| b. 只換 reviewer 一份當示範 | 多一個真的例子 |
| c. 全部換 | 範本最一致。等於變成預設做法 |

## 第 6 題：最小例子裡的那四格，是借範本的還是抄一份

白話：`ag.stock_fsm()` 生出來的 `fsm.json`，四格的程式要「指到 `$AOS_HOME/templates/agent-fsm/` 那幾支」（借），還是「把那幾支 Python 抄進你的定義夾」（抄）？

| 選項 | 後果 |
|---|---|
| ✔ a. 借 | 定義夾只有十來個小檔。範本的格更新時，所有借的 agent 一起跟著變 |
| b. 抄 | 定義夾自己就完整（多 105 KB、7 支 Python），範本怎麼改都不影響它 |

只決定預設值；想要另一種的人能在 `FSM` 裡自己寫路徑。

## 沒拿來問、設計者直接定的

| 事情 | 定的 | 依據 |
|---|---|---|
| 誰會重生 | 只有 `python3 agent.py --write-defs`；`agent_def check` 順手重生排成第二刀、先不做（11-19 使用者裁定劃掉，見 [10](10-使用者裁定.md) 末節） | 「C 與 .o」；後果見 [10](10-使用者裁定.md) 末節 |
| 查整棵樹的 `defs check` | 完全不動 | 它的說明寫「所有 op 只讀」；裁定後也沒有東西要它報 |
| `agent.py` 與 json 進不進 git | 都進 | json 是掛得上去、還會被改的定義本體；`tool-python`、`index_gen` 兩個先例 |
| 檔名、lib 名 | `agent.py`、`aos/agent_spec.py`（縮寫 `ag`） | 對照 `tool.py`、`tool_spec`（`ts`） |
| 刪掉 `agent.py` | 夾就是普通手寫定義，不需要任何動作 | C-45 給語法糖、不要求一定用 |
| `ctl add` | 不重生、不警告 | 生成物要不靠 lib 也能跑；自動重生是丁案 |
| kit、`self_*` | 不用處理 | 實讀程式：它們寫 stack、不改定義 |
| 出處行號 | 不寫進生成的 json | 寫進去的話 `agent.py` 多一行，後面每份 json 都變，全是假的 diff |
