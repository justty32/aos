# 跟除錯那條線（aos-gdb-1119）的接點：使用者兩句原話、庚這邊可能要預留什麼、一個要攤給他的邊緣狀況

← [README](README.md)｜上一份：[10-使用者裁定](10-使用者裁定.md)

另一條線今天在調查「aos 的 gdb」（[aos-gdb-1119](../aos-gdb-1119/00-使用者原話.md)）。這一份只記跟庚有關的兩句原話、標出庚可能要預留的口子，**不展開設計**；除錯怎麼做由那條線定。

## 使用者原話（11-19，頂層轉來）

第一句：

「我先用python產出一份粗定義，然後進入python repl，用aos-gdb庫，下斷點(hook？編譯時加debug flag，然後hook就有東西？)，然後跑。」

第二句：

「…執行途中，發現有問題，那就把他停下來(或是不停)，在他的指令中央插入新指令，我們的程式碼是持續在增長的…或許插入新指令的時候就要放debug旗標了？」

## 庚這邊可能要預留的

| 原話裡的哪一段 | 對到庚的什麼 | 可能要預留的口子 |
|---|---|---|
| 「先用python產出一份粗定義」 | 這就是庚：`agent.py` → 定義夾 | 無，本來就是 |
| 「然後進入python repl」 | 在互動環境（打一行跑一行的 `>>>`）裡用庚 | lib 的「算出全部內容」與「寫進某個夾」要能當一般函式直接叫，不能只藏在 `ag.main` 的旗標後面。已寫進 [03](03-agent-py-長相.md) 與第一刀（[08](08-範圍切法.md)），成本幾乎是零 |
| 「編譯時加debug flag，然後hook就有東西？」 | 重生時多一個開關，生出來的 json 多帶除錯用的東西 | 「算出全部內容」那個函式留一個開關的位置；開了之後要多生什麼（hook、記號、行號）由除錯那條線定，庚現在不做。「C 與 .o」在這裡剛好合用：開著重生一次是除錯版，關掉再重生就蓋回乾淨版，像 `-g` |
| 「下斷點(hook？)」 | 斷點掛在哪 | 庚第三刀才生 `hooks.json`。除錯那條線若決定斷點用 hook 做，第三刀的 `HOOKS` 要一起看 |
| 「這一步對到原始碼哪一行」（11-18 裁定時缺的兩樣之一） | 狀態機的格 ↔ `agent.py` 的行號 | `ag.state(…)` 被叫的當下可以記住自己在第幾行，要看的時候現算出一張對照表；不寫進 json（寫進去每次改動都帶假的 diff）。排在第四刀，等那條線說要什麼形狀 |

## 要攤給使用者的邊緣狀況（不替他解）

第二句說的是：agent 跑到一半，在它的指令中間插進新指令，程式持續長大。

在 aos 裡，「插進新指令」落到檔案上，就是去改定義夾的 json（例如在 `fsm.json` 多加一格、改某格的下一步）。而照今天的裁定（[10](10-使用者裁定.md)），json 是「.o」：

- **插進 json 的新東西，下次從 `agent.py` 重生就沒了，不提醒。**
- 如果那時有 agent 正停在插進去的那一格上，重生後那一格不存在，它下一拍會停下（[07](07-邊緣狀況.md) 第二節，照說明推的、沒實測）。
- 反過來，想讓插進去的東西留下來，就得把它也寫進 `agent.py`——這一步今天沒有工具幫忙，是人手做。

「持續增長的程式」與「產出後就無關」這兩件事放在一起，至少有三種走向，各自要的東西不一樣：

| 走向 | 意思 | 庚要配合什麼 |
|---|---|---|
| 長在 json 上 | 插進去的東西就留在夾裡；`agent.py` 只在一開始用一次，之後不再重生 | 不用配合。`agent.py` 變成「起手式」 |
| 長在 `agent.py` 上 | 每次插入都改 `agent.py` 再重生 | 插入的工具要會改 Python，或由人改 |
| 兩邊各長各的，要用時再併 | 插入先落在 json，之後有一個動作把它收回 `agent.py` | 就是「反推」，11-18 調查的結論是沒人做到全自動 |

哪一種是他要的，由他定。庚現在的設計三種都沒擋住。
