# 打架規則（逐條）：十種會打架的情況，各自有哪些處理方式、後果、我的推薦

← [README](README.md)｜上一份：[05-打架規則-總則](05-打架規則-總則.md)｜下一份：[07-邊緣狀況](07-邊緣狀況.md)

名詞照 [05](05-打架規則-總則.md)：「帳」＝`_metainfo.json` 的 `generated` 鍵；「生成檔」＝帳上列的檔。標「★問」的是要使用者拍板的，其餘是我照既有裁定與慣例定的。

## 1. 生成檔被人手改 ★問

人用編輯器、或 agent 用 `write`／`json_set` 直接改了 `fsm.json`。

| 做法 | 後果 |
|---|---|
| a. 照工具版，直接蓋 | 最簡單、不用記帳。手改的字無聲消失，check 還回「沒問題」；agent 會以為改成功了 |
| b. 停下來講，`force` 才蓋（推薦） | 不會弄丟東西；多一步、要記帳（[05](05-打架規則-總則.md)） |
| c. 照蓋，但把被蓋掉的內容印在 check 的輸出裡 | 不卡人；輸出沒人看就還是丟了，agent 的輸出尤其容易被截掉 |

推薦 b。這不是讓 json 贏——`agent.py` 還是唯一的原始碼——只是蓋之前確認一次。

## 2. 改了 `agent.py`，json 還沒重生（過時）

- `agent_def check`：重生，輸出多一格說寫了哪幾份。這是正路。
- `defs check`（整棵樹、唯讀）：列一條問題，退 1。夾裡的 json 其實跑得動，但「跟自己的原始碼不一致」值得讓巡樹的人看到。
- 沒人跑 check 就拿去掛：照舊的 json 跑。這跟工具版一樣（改了 `tool.py` 沒 check，模型看到的還是舊說明），不另外防；第四刀在 `ctl add` 加一行警告。

## 3. 兩邊都改了

指紋分不出「只有手改」和「手改＋`agent.py` 也改了」，也不需要分：都是「夾裡這份不是我生的」。照第 1 種處理。訊息要講清楚兩條路：把手改的內容搬進 `agent.py` 再 check，或 `force`。

## 4. 只有 json、沒有 `agent.py`

- **從來沒有**：就是今天的手寫定義。所有指令照舊，庚對它零影響（C-45：給語法糖、不要求一定用）。
- **本來有、後來刪了**：這就是「退出」。規則定成一句：**夾裡有 `agent.py` 才有生成檔這回事**；`agent.py` 不在，帳上寫什麼都不算數，所有檔都當手寫的，`agent_def tools` 等照常能改。帳留著沒清不算錯，`agent_def check` 印一行提醒就好。
- 這條同時保證「搬到別台只帶夾、不帶原始碼」照樣能用、能手改。

## 5. 本來手寫，後來才加 `agent.py`（收編）

夾裡已經有 `tools.json`，帳上沒有它。照 [05](05-打架規則-總則.md) 的表：內容跟 `agent.py` 要生的一樣＝一致，直接記進帳；不一樣＝當成被手改，停下、`force` 才蓋。所以「照著現有的 json 把 `agent.py` 寫出來，寫到 `--status` 全部一致為止」就是收編的做法，不需要另外的指令。

## 6. `agent_def tools`／`llm`／`system` 碰到生成檔 ★問

這三個動作今天是「改定義」的正規做法，知識庫也這樣教 agent。

| 做法 | 後果 |
|---|---|
| a. 擋下，報 `DefGenerated`，訊息指到 `agent.py` 的哪個常數（推薦） | 不會出現「改了又被蓋」。agent 得去改一支 Python 再 check，比打一個工具呼叫難，小模型可能改壞（改壞會得到 `SpecBad`，json 不動） |
| b. 照改，那份檔從此算被手改，下次 check 走第 1 種 | 當下最順。但每改一次就讓定義卡在「要 `force` 或要搬回 `agent.py`」，等於把麻煩往後推 |
| c. 工具幫忙把改動寫回 `agent.py` | 只有 `LLM = {…}` 這種單純字面值做得到；`TOOLS` 用迴圈拼的就寫不回去。11-18 調查的結論是反推沒人做到全自動，不推薦 |

推薦 a。先例：`tools_def add_tooldef` 碰到已有的生成檔也是擋下並說「change the script and run check」。唯讀的動作（`tools ls`、`llm ls`、`system get`）不擋。

## 7. `agent_def new` 抄一份有 `agent.py` 的定義

抄的時候 `new` 會做兩件改檔的事，都會跟生成檔撞：

- **寫 `lineage` 進 `_metainfo.json`**：不撞，因為 `_metainfo.json` 不整份重生、只動自己的鍵（[03](03-agent-py-長相.md)）。
- **把工具檔裡的相對路徑換算到新位置**：會撞。換算完的 `tools.json` 跟帳上的指紋不合，會被誤判成手改；而且 `agent.py` 裡寫的還是舊的相對路徑。

推薦：`new` 抄到的夾裡有 `agent.py` 時，**不換算生成檔，改成在新位置重生一次**；`agent.py` 裡若寫了會跑出定義夾外的相對路徑（`../…`），重生時列一條提醒請人改成 `ag.home(…)` 或 `ag.env("AOS_WS", …)`。骨架與例子一律不寫 `../`。單純 `cp -r` 的情況見 [07](07-邊緣狀況.md)。

## 8. kit、`self_*`

實讀 `ctl/kit.py` 與 `set-def --help`：kit 寫的是 stack 裡「自己那份」，說明原文「the definition is not changed」。`self_*` 同理。**它們跟生成檔不在同一個夾，打不到架。**

留意一點（今天就有、不是庚帶來的）：stack 裡的差異是對著舊定義寫的，`agent.py` 重生後定義變了，疊起來可能不對（例如那隻 agent 拿掉了一個工具，而新定義把它改名）。11-18 調查第 8 條已歸為天然差異，不處理。

## 9. `agent.py` 自己壞了

語法錯、宣告錯、丟例外、跑超過期限。一律 `SpecBad`（附行號與怎麼改），**夾裡現有的 json 一份都不動**，`agent_def check` 照樣把現有的 json 查完一起報。理由：正在跑的 agent 用的是夾裡那幾份，原始碼寫壞不該連累它們。

## 10. lib 說可以、`defs check` 說不行

聽 `defs check` 的（還有 aos-fsm、aos-tools 這些真正讀檔的程式）。它們是規範的一方，lib 只是代筆（C-45「規範比實作重要」）。這種情況代表 lib 的事先檢查漏了一條，照實把 `defs check` 的問題報出來，回頭補 lib。lib 不得為了自己方便發明只有它懂的 key 或格式。
