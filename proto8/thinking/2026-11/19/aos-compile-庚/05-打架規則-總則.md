# 打架規則（總則）：`agent.py` 與夾裡的 json 對不上時聽誰的、怎麼分辨「過時」與「被手改」、check 該報什麼

← [README](README.md)｜上一份：[04-agent-py-兩個例子](04-agent-py-兩個例子.md)｜下一份：[06-打架規則-逐條](06-打架規則-逐條.md)

## 先講結論

1. **永遠是 `agent.py` 贏。** 沒有任何一條路會讓 json 蓋回 `agent.py`，也不做合併、不做反推。這是 11-18 晚向使用者解釋過、他說「喔對的對的，這太方便了」的那條。
2. **但蓋掉之前要分得出兩種「對不上」**：一種是你改了 `agent.py`、json 還沒跟上（過時，放心蓋）；一種是有人直接改了 json（手改，蓋下去會弄丟東西）。工具版分不出來，一律蓋。
3. 我的推薦：**過時＝直接重生；手改＝先停下來講一聲，加 `force` 才蓋。** 這比 11-18 講的「一律重生」多一步，所以列為要你拍板的第 1 題（[09](09-要使用者拍板的題.md)）。
4. 分辨的方法：重生時把每份生成檔的指紋（雜湊，檔案內容算出來的一小串字，內容一變它就變）記在 `_metainfo.json` 的 `generated` 鍵。
5. `agent_def check`（查一份、本來就會轉叫別人）負責重生；`defs check`（查整棵樹、唯讀）只報不寫。

## 為什麼 agent 這格不能照抄「一律蓋」

| | 工具那格 | agent 這格 |
|---|---|---|
| 生成檔幾份 | 2 | 8 以上 |
| 有沒有正規指令會改生成檔 | 沒有 | **有**：`agent_def tools`／`llm`／`system` 就是設計來改這幾份的；`agent_def new` 抄完也會改寫 |
| 知識庫怎麼教 agent | 「改 `tool.py` 再 check」 | 「抄一份定義、改那份、再 check」（rules.json 第 1 條）——agent 會照做，直接改 json |
| 一律蓋的後果 | 幾乎沒人撞到 | agent 剛用 `agent_def tools add` 加的工具，下一次 check 無聲消失，而且 check 還回「沒問題」 |

最後一格是關鍵：**壞的不是「蓋掉」，是「蓋掉又不講」**。

## 記帳：`_metainfo.json` 的 `generated` 鍵

```json
{"summary": "…", "lineage": {"template": "agent-python"},
 "generated": {"by": "agent.py", "source": "sha256:…",
               "files": {"fsm.json": "sha256:…", "tools.json": "sha256:…", "system.txt": "sha256:…"}}}
```

- `files`：這次生了哪些檔、各自的指紋。**在這張表上的檔才算「生成物」**，其他都是手寫檔，重生永遠不碰。
- `source`：`agent.py` 自己的指紋。有了它，不必執行 `agent.py` 也看得出「原始碼改過、還沒重生」。
- 不記時間、不記機器名、不記絕對路徑：同一份 `agent.py` 在兩台機器生出來要一字不差。
- 放 `_metainfo.json` 而不另開一個檔的理由：`lineage`（從哪抄來）已經放這裡；N-69 說它「可以放任何東西來描述自己」「壞了當沒寫」——帳壞了就當沒帳，退回下面表格的「沒有帳」那一列，不會擋住 agent 跑。

## 每份生成檔的四種狀況

重生時對每一份要生的檔比三樣：**帳上記的**、**夾裡現在的**、**`agent.py` 現在會生的**。

| 狀況 | 怎麼認 | 做什麼 |
|---|---|---|
| 一致 | 夾裡的＝會生的 | 不寫檔（帳不對就補帳） |
| 過時 | 夾裡的＝帳上的，但≠會生的 | 重生 |
| 不在 | 夾裡沒有這份 | 生出來 |
| **被手改** | 夾裡的≠帳上的，也≠會生的（含「沒有帳」但檔已經在） | **停下**，報 `DefEdited`、列出是哪幾份；`force` 才蓋 |

四條補充：

- **先全部比完、再決定寫不寫**：只要有一份被手改而沒給 `force`，這次一份都不寫。不會出現「蓋了三份、卡在第四份」。
- **「夾裡的＝會生的」優先於「≠帳上的」**：這讓兩件事自動沒事——重生寫到一半當掉後再跑一次（已寫好的那幾份算一致），以及有人手改的內容恰好就是 `agent.py` 新版要生的。
- **只改排版不算手改**：json 檔的指紋算的是解讀後的內容，不是逐字（`system.txt` 逐字）。
- **不再宣告的檔不刪**：`agent.py` 拿掉了某個宣告，那份舊檔留在原地、從帳上除名、印一行提醒，要刪你自己刪。生成器不替人刪檔。

## 誰負責重生、誰只報

| 指令 | 會不會寫 | 碰到過時 | 碰到被手改 | `agent.py` 自己壞了 |
|---|---|---|---|---|
| `python3 agent.py --write-defs` | 會 | 重生，印 `made …` | 退 1，`DefEdited` | 退 1，`SpecBad`（講哪一行、怎麼改） |
| `agent_def check`（查一份） | 會：先叫上面那支，再照舊轉叫 `defs check` | 重生後才查 | 不重生，回 `DefEdited`；夾裡現有的照樣查完、問題一起列 | 回 `SpecBad`；夾裡現有的照樣查 |
| `defs check`（查整棵樹，唯讀） | **不會** | 列一條問題：`agent.py changed since … were generated (run agent_def check on this definition)` | 列一條問題：`fsm.json was edited by hand after it was generated from agent.py` | 看不出來（它不執行 `agent.py`） |
| `aos-agent ctl add`／`set-def` | 不會 | 第四刀起印一行警告，照樣掛 | 同左 | 不管 |

三點說明：

- **`agent_def check` 會寫檔，這跟工具版一致**（`tools_def check` 就是這樣），也是 11-18 向使用者講的樣子。`defs check` 維持唯讀，是因為它的說明白紙黑字寫「所有 op 只讀」，而且拿來一次查整棵樹——查一棵樹就改一堆定義太嚇人。
- **`defs check` 靠指紋就能報**，不必執行任何 `agent.py`：比 `source` 知道過時、比 `files` 知道手改。它看不出「`agent.py` 還引用了別的檔而那個檔變了」，這種只有 `agent_def check` 真的跑一次才知道。
- **`ctl add` 不擋、不自動重生**：生成物必須不靠 lib 也能跑（搬到別台只有夾沒有 `agent.py` 的情況，11-18 調查第 19 條）；自動重生等於掛 agent 時執行任意 Python，那是丁案。

## 新增的錯誤代號（建議名，施工時定）

| 代號 | 誰出 | 意思與訊息要講的 |
|---|---|---|
| `SpecBad` | `agent.py`、`agent_def check` | 宣告寫錯或 `agent.py` 跑不起來；講哪一行、怎麼改（沿用 tool_spec 的名字） |
| `DefEdited` | `agent.py --write-defs`、`agent_def check` | 生成檔被手改；列檔名；講兩條路：把改動搬進 `agent.py`，或加 `force` 丟掉 |
| `DefGenerated` | `agent_def tools`／`llm`／`system` | 這份檔是 `agent.py` 生的，要改去改 `agent.py` 的哪個常數（等使用者裁第 2 題） |

`defs check` 不加代號，照它的慣例只在 `problems` 多列句子，整體仍是 `DefBad`。
