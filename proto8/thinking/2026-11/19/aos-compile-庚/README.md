## 先講結論

1. **第一刀很小**：只加一支 lib（`py/aos/agent_spec.py`）、一個骨架（`templates/agent-python/`）、一支測試，不改任何現有程式。做完你就能「空夾放一支二十來行的 `agent.py` → 打一行 → 掛上去」，不用再抄 19 個檔去改三份。
2. **寫法整套照工具版 `tool.py`**：固定開頭、大寫常數（`DESCRIPTION`、`SYSTEM`、`TOOLS`、`LLM`、`FSM`）、最後一行 `ag.main(...)`。宣告了 `FSM` 就連骨架（`_entry`、`body.json`、`loop.json`、`interfaces.json`）一起生；格的 Python、`.env`、stack、daemon 表上的設定都不管。
3. **打架規則是「C 與 .o」**：方向只有 `agent.py` → json；重生就是直接蓋，不比對、不問、不講；產出後的 json 是普通定義檔，誰都能照常改（`agent_def tools`／`llm`／`system` 不擋），改過的東西下次重生就沒了。夾裡不留任何記號或帳。這跟工具版 `tool_spec` 今天的行為一樣。
4. **重生只有一個明講的動作**：`python3 agent.py --write-defs`。`agent_def`、`defs check`、`ctl` 第一刀都不動。「`agent_def check` 順手重生」有一個後果要你看過，先不做（[10](10-使用者裁定.md) 末節）。
5. **順便補了一個今天的洞**：`agent_def check` 現在完全不看 `fsm.json`，狀態機打錯格名要跑起來才知道；`agent.py` 生成前就會查，錯誤指回 `agent.py`。
6. **kit 與 `self_*` 打不到架**（實讀程式：它們寫 stack、不改定義）。
7. **最容易誤傷的一條**：在已經手寫好的夾裡放 `agent.py` 第一次重生，會把宣告到的那幾份整份蓋掉。先 `--defs` 看一眼，或不想被蓋的用 `ag.by_hand`。

## 還沒驗證的

- 「把狀態機的格改名後，停在舊格的 agent 會報 `StateUnknown` 並停下」是照 aos-fsm、aos-loop 的說明推的，沒有實測（[07](07-邊緣狀況.md) 第二節）。
- `loop.json` 只在起跑時讀一次，同樣只讀了說明。
- 兩個例子與所有函式名都是設計稿，沒有寫成程式跑過；「reviewer 重生結果跟手寫的等價」排在第三刀當驗收。
- 各份 json 帶 `description` 不會被哪支程式嫌棄，依據是 reviewer 範本今天每種檔都帶這個鍵。
