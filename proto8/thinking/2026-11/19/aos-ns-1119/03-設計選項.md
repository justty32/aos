## 先講結論

1. **推薦走向 B「路徑即命名空間」**：一個庫＝一個長相固定的資料夾，`std` 是隨 aos 發的那一個。全名就是路徑（`$AOS_HOME/lib/std/packs/look.json`）；`agent.py` 裡寫 `std.pack("look")`，**生成時把包展開成一支支工具寫進 `tools.json`**（工具的路徑仍是借的），json 裡只有全路徑。不加執行期的新機制，沒有搜尋路徑。（「展開」是 Argon 審後改的：照舊借包的話，撞名根本解不開，見 [06](06-Argon審與採納.md) A1。）
2. **有一件事四個走向都繞不開**：腦看到的工具名不能有 `.` `/` `:`。所以「東西屬於哪個庫」跟「腦看到叫什麼」是兩件事；後者只有三種選法，另列一題（[05](05-邊緣狀況與要拍板的題.md) 第 2 題）。
3. **今天真正的洞是「同名悄悄蓋」**（01 結論 2），不是名字太短。B、C 把它變成報錯；A 靠自律；D 把它變成規則。
4. **最小的第一刀**只改 `agent_spec`：`std`、`ag.lib`、生成時展開包、別的庫的工具自動加 `庫名_`、展開後查撞名，不搬任何檔。驗收用一個放在工作區、也有 `read` 的小庫：生成的 `tools.json` 裡同時有 `read` 與 `my_read`、各指各的。這樣第一刀就做到你要的「後者」的工具名那一半；std 本身要不要搬進 `lib/std/`（路徑上看得出是 std）是第二刀、第 4 題。
5. **這是方向題，由使用者拍板。** 另有兩處跟既有條文的用詞要你點頭（C-87 的「機制以後再說」、C-74 的「標準庫」）。今天裁的三件事（骨架不帶 hook、`stock_hooks` 是抄、check 不重生）四個走向都不推翻。

## 四個走向對照

| | A 前綴慣例（C 語言式） | B 路徑即命名空間（Python／Go 式） | C 定義檔裡寫全名（C++／Lisp 式） | D 搜尋路徑（`PATH` 式） |
|---|---|---|---|---|
| 一句話 | 名字自己帶 `std_`，沒有任何機制 | 庫是資料夾，全名是路徑 | 登記表的鍵就是全名 `std.read`，登記表負責翻成腦的名字 | 寫短名，照一串庫的順序找 |
| `agent.py` | `ag.pack("std_look")` | `std = ag.std`、`std.pack("look")`；別的庫 `my = ag.lib("my", 根)` | `ag.pack("std.look")` | `ag.pack("look")`（跟今天一樣） |
| json 定義檔 | `"std_read": {"path": …}` | 包展開成 `"tools": {"read": {"path": {"$env":"AOS_HOME","$path":"/lib/std/tools/base/read"}}, "my_read": {"path": …}}` | `"std.read": {"path": …, "as": "read"}` | 生成時解成路徑；手寫的 json 留短名 |
| shell | `aos-tools call std_read` | 照舊寫路徑；收短名的地方寫 `std/agent-fsm` | `aos-tools call std.read` | `AOS_LIBPATH=my:std` |
| 腦看到 | `std_read` | std 短名、別的庫 `庫名_名`（推薦，見 05 第 2 題） | `as` 那格 | 短名 |
| 落在哪層 | 名字字串 | 檔案路徑 | 定義檔欄位＋`aos-tools` | 環境變數＋解析程式 |
| 兩個來源同名 | 不會（前提是大家守規矩） | 生成時報 `SpecBad` | 全名不同，不會合在一起 | 前面的蓋後面的，不出聲 |
| 看名字知道是誰的 | 知道 | 看路徑知道 | 知道 | 不知道，要跑 `which` |

### A 前綴慣例

- **標準庫**：就是「名字以 `std_` 開頭的那一批」。18 個包的 62 個鍵改名，包名 `std_look`；別人的庫自己挑前綴，沒人發號。
- **合不合**：最貼 C-87 原話（「常見的名字加自己的前綴」）。跟「C 與 .o」無關（沒有解析這一步）。
- **代價**：腦每次問都多送 62 個 `std_`（C-92 小模型裝不下工具說明那條會更緊）；知識庫、各範本的 `system.txt`、測試裡所有工具名都要改。撞名仍然是「悄悄蓋」，只是比較不容易撞。
- **分刀**：沒得分，要嘛全改要嘛不改。

### B 路徑即命名空間（推薦）

**庫長這樣**（一個資料夾，像一個 Python 套件）：

```
<庫根>/_metainfo.json   一句話說明
       tools/<類>/<名>/  工具夾（std 留 base／agent／aos 三類）
       packs/<名>.json   工具包
       templates/<名>/   定義範本（含 kernel 範本、kits）
       hooks/<組>.json   hook 組（今天寄在範本名底下）
```

- **名字的寫法**：全名＝路徑。`agent.py` 裡庫是一個 Python 物件：`std.pack("look")`、`std.tool("base/read")`（不搬家時類夾是路徑的一段，不搜尋；搬家時可拍平成 `std.tool("read")`）、`std.hooks("agent-fsm")`、`std.fsm("agent-fsm")`。種類由你叫哪個函式決定，所以包 `look` 跟範本 `look` 不撞。收短名的少數地方（`agent_def new` 的 `template`）寫 `std/agent-fsm`，`/` 前是庫、後面原樣接在 `templates/` 底下——順便解掉今天 `kernel/llm-kernel` 叫不到的問題（01 第 5 類）。`agent_def new` 抄範本時沒有 `agent.py` 可查別的庫在哪，所以 05 第 6 題選 a 時它只收 `std/…`，別的庫的範本照舊用 `from` 給路徑。
- **怎麼解析**：`std` 的根固定是 `$AOS_HOME/lib/std`。別的庫的根**在用它的那支 `agent.py` 裡明寫**（`ag.lib("my", ag.env("AOS_WS", "/lib/my"))`；生成時一定要讀得到這個根，讀不到報 `SpecBad`，不靜默跳過），像 Python 的 `import x as y`：庫名只在這支檔裡有效，不進任何全域表。解析在生成時做完，json 裡只留指示詞路徑——正是「C 與 .o」。沒有「找不到往下一個找」。
- **包怎麼進 `tools.json`**：**生成時展開**——讀包檔，把裡面每支工具連同路徑寫進 `tools` 表，不再寫 `$override` 指包（`$override` 留給 stack 蓋定義用）。在 Python 裡整格處理，所以改名（`my.pack("net", rename={"ping": "net_ping"})`）、拿掉某個庫的某支（`exclude=["read"]`）、整支換成別的庫的（`ag.tool("read", my.tool("read"))`）都乾乾淨淨，沒有逐欄合併的殘渣。代價：包之後多加的工具，要重生才拿得到（跟「`stock_hooks` 是抄」同性質，05 第 7 題）。
- **腦看到的名字**：推薦 std 短名、別的庫預設加 `庫名_`（`my_read`，可用 `prefix=` 改）；展開完再查一次鍵，**還同名就報 `SpecBad`**（兩份解完的內容完全相同的菱形不算撞）。這跟 MCP 凍結的 `<server>_<tool>` 同一招。
- **標準庫是什麼**：18 包、三類工具夾（91 支）、`templates/` 底下全部（agent-fsm、agent-python、eca-*、reviewer、judge-llm、tool-python、daemon-root、kernel 四個、kits、start-*）、三組 hook、`stock_fsm` 四格的程式。**誰能出別的庫**：誰都能，放哪都行（工作區、另一個 repo）；aos 不發號、不登記。
- **合不合**：
  - 「資料夾＝程式」：庫也是資料夾，合。「重生是抄」「`stock_hooks` 是抄」「骨架不帶 hook」：只是 `ag.stock_hooks()` 改叫 `std.hooks()`，行為不變。
  - C-87：沒有隱性查找，合它的精神；但它說「契約或機制……以後的事情」，庫的固定長相算一種契約——**05 第 3 題**。
  - C-52：腦仍然只看到自己的工具清單，來源不外露，合。
  - 10-14「沒有搜尋路徑」：合。
  - C-74：**詞撞**。那裡的「標準庫」指 aos-fsm、tasks 那一層程式；這裡的 `std` 裝的是工具、包、範本，其中範本在 C-74 屬「最上層」。不處理的話同一個詞兩個意思——**05 第 5 題**。
- **要動的程式**：
  - 第一刀：`py/aos/agent_spec.py`、`agent_spec_parts.py`（加 `std`、`ag.lib`、生成時展開包、別的庫加前綴、展開後查撞名，粗估 200 行）、`templates/agent-python/agent.py` 的例子、一支測試（含工作區小庫的驗收）。`std` 的根先指今天的三個位置（`lib/tools`、`lib/packs`、`templates`，Argon A6：不搬時 std 不是一個夾，程式要特判），不搬檔。執行期程式一行不動。
  - 第二刀（搬家）：`py/tools/`、`py/packs/`、`templates/` 進 `std`；`install.py` 的 `copy_py`；18 包裡 62 條路徑；各範本的 `tools.json`、`hooks.json`、`fsm.json`；`agent_def` 找範本那段（`_entry` 92-98）；`STOCK_CELLS`；kits；`test_start.py`；知識庫 `aos/packs.json` 等；可順手拍平類夾、把 hook 組與 fsm 格程式從範本拆成 `hooks/<組>.json`、`fsm/<組>/`（範本自己的 `hooks.json` 改成跟庫那組同一份，免得兩份抄本）。純機械但很廣（上百條路徑字串），**活樹要重建**（stack 裡存著舊路徑）。
  - 第三刀：`defs check` 加「同一層的兩個包同名」的檢查（補手寫 json、kit、`tools_sub.json` 沒人查的洞）；`agent_def new` 收 `std/名`（第 6 題選 b、d 時也收別的庫）。
- **哪一刀最小可先試**：第一刀。試完覺得手感不對，丟掉也不留痕跡。

### C 定義檔裡寫全名

- **怎麼解析**：`tools.json` 的鍵改成 `std.read`，`$override` 照全名疊，所以 `std.read` 與 `my.read` 永遠是兩格。`aos-tools ls --json` 送腦前換成 `as` 那格，`call` 兩種都收。
- **標準庫**：內容同 B；`std.` 這個前綴誰能用，要多一條規矩（或像 Lisp 的 `cl` 一樣鎖住）。
- **合不合**：這是在 aos 本體加名字機制，離 C-87「機制以後再說」最遠。全名跟檔案位置無關，`std.read` 可以指到任何路徑（02 表裡 C++ 那格的包袱）。`as` 撞了還是要有規則。
- **要動**：`apps/tools/` 的 `registry.py`、`common.py`（名字規則）、`main.py`；`brain.py`、`act.py`；`apps/mcp/`；`self_tools`；18 包；全部範本；kits；`agent_spec_parts.py`。約是 B 第二刀的兩倍，而且動的是執行期。
- **分刀**：可先只讓登記表多收一個不影響行為的 `from` 欄位（記全名），其餘不動；但那樣沒解決撞名。

### D 搜尋路徑

- **怎麼解析**：`AOS_LIBPATH` 列一串庫根，短名照順序找，第一個中的贏。
- **合不合**：跟 10-14「沒有 extends、沒有搜尋路徑」、C-87「不做隱性操作」正面衝突；「到底用到哪一份」要看當時的環境變數。放在生成時做能減輕（json 裡是解完的路徑），但手寫的 json 沒有生成這一步。
- **結論**：不推薦。它想給的方便（少打字）B 已經用 `std = ag.std` 一行給了。

## 不只工具：哪些進命名空間、哪些不用動

| 東西 | 進不進庫 | 理由 |
|---|---|---|
| 工具、工具包、定義範本、kernel 範本、kits | **進** | 都是「別人做好、我拿來用」的東西，今天就是靠短名或路徑去拿 |
| hook 組 | **進**（第三刀後有自己的位置） | 今天借範本名當組名（01 第 3 類），不該綁在範本上 |
| `stock_fsm` 的四格程式 | **進**（跟著範本走） | 是借的，路徑裡帶庫名就夠 |
| 知識庫 | 已經是了 | 首段 `aos/`、`wf/` 本來就是路徑式命名空間 |
| hook 名、fsm 格名 | 不用動 | 範圍是「這一隻 agent 的那張表」；抄進來同名照現行「後面的贏」 |
| proc 名、endpoint 名 | 不用動 | 一台 daemon、一台 kernel 一張表，撞了本來就報錯或是刻意的（01 第 6、7 類） |
| 信、kernel、kit 的定址 | 不用動 | 本來就寫路徑 |
| 指令 `aos-`、變數 `AOS_` | 不用動 | 已是 A 式前綴（R8、R13） |

## 要你拍板的題

七題（走向、腦看到的名字、C-87、搬不搬、「標準庫」這個詞、別的庫的根、包是抄還是借）連同選項與後果整理在 [05](05-邊緣狀況與要拍板的題.md)，題號以 05 為準。

## 推薦與理由

**B，照「第一刀只改 `agent_spec`、不搬檔」起手；05 第 2 題選 b、第 6 題選 a、第 7 題選 a。**（Argon 審前推薦第 2 題選 a，審後改 b，理由見 [06](06-Argon審與採納.md)。）

- aos 本來就是「路徑即名字」（01 結論 1），B 只是讓僅剩的幾個短名也變成路徑的短寫，不另造名字表。
- 解析全在生成時做完，跟你定的「C 與 .o」是同一件事；json 仍是普通定義檔，刪掉 `agent.py` 照跑。
- 把今天「同名悄悄蓋」變成生成時的一行錯誤，這是實際會咬人的洞（[01](01-現況盤點.md) 實測）；別的庫自動帶前綴，對得上你說的「工具名本身就帶前綴」。
- 第一刀小、可丟；搬家（第二刀）等你試過手感再決定。

這是方向題。上面是設計者的推薦，不是決定；選哪個走向、05 的七題怎麼答，由使用者拍板。
