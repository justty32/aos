使用者 11-19 看到 `ag.stock_hooks()` 後說「我原本預期他會是類似C++那樣，有namespace、標準庫」，選了「連 aos 本身的東西都要分命名空間」那個意思，另要繼承「淺淺想一下」（原話全文 [00](00-使用者原話.md)）。線 `aos-ns-1119` 做：兩隻 opus 唯讀蒐集現況，fable 寫設計主體，隊長匯總細化、補一個實測（暫存夾 `~/.aos/scratch/aos-ns-1119/`，只用 repo 的 `bin/aos-tools`），送 Argon 審、寫採納表。**只出設計稿與發想，沒改程式**、沒跑 `install.py`、沒起 daemon、沒叫真模型。

## 先講結論

1. **aos 今天沒有全域名字表**：名字的範圍都靠路徑（哪個資料夾、哪台 daemon、哪台 kernel）限定。真正會撞、而且撞了不出聲的是**工具名**：幾個包疊在一起，同名就後面的悄悄蓋前面的。實測過：兩個包都有 `read`，`aos-tools ls` 只列一個、不警告，腦看到叫 `read`、實際跑的是另一支（[01](01-現況盤點.md)）。
2. **推薦走向 B「路徑即命名空間」**：一個庫＝一個長相固定的資料夾，`std` 是隨 aos 發的那一個。`agent.py` 寫 `std.pack("look")`、別的庫 `my = ag.lib("my", 路徑)`；生成時把包展開成一支支工具寫進 `tools.json`，json 裡只有全路徑；不加任何執行期機制、沒有搜尋路徑——解析在生成時做完，就是你說的「C 與 .o」（[03](03-設計選項.md)）。
3. **工具名：std 照舊短名（`read`），別的庫自動帶 `庫名_`（`my_read`），還撞就生成時報錯**。這對上你說的「工具名本身就帶前綴」；腦叫工具的名字只准英數、`_`、`-`，所以前綴用 `_` 接。
4. **最小一刀只改 `agent_spec`、不搬檔、可丟、執行期一行不動**：做完就能用一個放在工作區的小庫驗「兩個來源都有 `read`、各指各的、不撞」。std 本身要不要搬進 `lib/std/` 是下一刀、另一題。
5. **要你拍板七題**（[05](05-邊緣狀況與要拍板的題.md)）：走向、腦看到的名字、C-87（11-02「不做隱性的命名空間」「機制以後再說」）現在算不算以後、std 搬不搬、「標準庫」這個詞撞 C-74、別的庫放哪、包改成生成時抄還是照舊借。今天已裁的三件事（骨架不帶 hook、`stock_hooks` 是抄、check 不重生）都不推翻。
6. **繼承（淺）**：aos 沒有叫「繼承」的機制（10-14 明講不做），但像繼承的已有六種；有了 `agent.py`，「定義衍生定義」可以完全在生成時用 Python 的 import 做掉，json 裡不留上一層是誰。命名空間跟繼承搶同一個動作（「我要蓋你」對「碰巧同名」），要分得出這兩種才不打架（[04](04-繼承-淺想.md)）。
7. **Argon 審過**（[06](06-Argon審與採納.md)）：抓到一個真的死結——原稿照舊「借」包時，撞名根本解不開（改名只是多一格、拿掉會連 std 的一起拿掉）；因此 B 改成生成時展開包，推薦也從「腦看到短名」改成「別的庫帶前綴」。不採它「搬家時留舊路徑 symlink」的提案（proto8 不做相容）。
