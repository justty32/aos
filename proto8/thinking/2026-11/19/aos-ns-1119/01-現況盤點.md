# 現況盤點：aos 今天有名字、會被引用的東西，各自的名字從哪來、怎麼被找到、同名會怎樣

← [README](README.md)｜上一份：[00-使用者原話](00-使用者原話.md)｜下一份：[02-別人怎麼做](02-別人怎麼做.md)

讀 repo HEAD `2173a4ecc`（`~/repo/aos/proto8`），兩隻 opus 子 agent 唯讀蒐集、線隊長抽核。「讀程式」＝看程式碼推的；「看說明」＝看 docstring／README 推的。沒起 daemon、沒跑實測。

## 先講結論

1. **aos 今天沒有全域名字表**。每種名字的作用範圍都靠「在哪個資料夾、哪台 daemon、哪台 kernel」的**路徑**限定；真正被引用時寫的幾乎都是路徑（`{"$env":"AOS_HOME","$path":"/lib/tools/base/read"}`），短名字只出現在三處：**腦看到的工具名**、**`ag.pack("look")` 的包名**、**`agent_def new` 的範本名**（外加 daemon 表的 proc 名、llm kernel 的 endpoint 名，那兩個本來就是「一台一張表」）。
2. **最會撞、而且撞了不出聲的是工具名**：`tools.json` 是一張扁平的「名字 → 工具」表，幾個包用 `$override` 疊起來，同名就後面的**逐欄**蓋前面的，不報錯，前一份的欄位還可能殘留。腦看到的 function name 就是這張表的鍵，規則 `[A-Za-z0-9_-]{1,64}`——**不能有 `.` 和 `/`**。
3. **像前綴、像分類的東西已經有幾處，但都不是命名空間**：`lib/tools/{base,agent,aos}/` 三個類夾（只是放檔的地方，工具名裡沒有這層）、`aos-` 指令前綴與 `AOS_` 變數前綴（命名法 R8／R13）、`_` 開頭的系統 proc（慣例）、MCP 凍結進來的工具 `<server>_<tool>`（唯一真的帶前綴的工具名）、知識庫首段 `aos/`、`wf/`。
4. **疊層機制有四種**：工具表的 `$override`（可多層、菱形可、環才報錯）、stack 那份蓋定義那份（`tools.json`、`llm.json`、`hooks.json`）、`.env` 一跳一跳往下疊、llm-team 的 `to` 明寫轉交。**沒有搜尋路徑**（沒有像 `PATH` 那樣「找不到就往下一個地方找」的東西），唯一的例外是給人打指令的 `PATH`。
5. **已有條文明講「不做隱性命名空間」**：C-87「共用 stack 撞名，aos 不做隱性的命名空間：各自管好，常見的名字加自己的前綴，或自己開資料夾放」。它講的是 stack 裡的**檔名**，不是工具名；但這次要做的東西會碰到這條的精神，列在 [05](05-邊緣狀況與要拍板的題.md) 第一題。

## 逐類

### 1. 工具

| 項 | 現況 | 出處 |
|---|---|---|
| 放哪 | 原始碼 `py/tools/<類>/<名>/`（`_entry`、`_tooldef.json`、`_metainfo.json`），`install.py` 整份抄成 `lib/tools/<類>/<名>`；類只有 `base`（檔案、json、shell…32 支）、`agent`（agent 自己用的 38 支，含別線未交的 `gdb_trigger`）、`aos`（體系工具 21 支） | `install.py` `copy_py` 142-149 行 |
| 類夾算不算命名空間 | **不算**：工具名裡沒有類這層；三類之間目前沒有同名夾，但沒東西擋 | 讀程式 |
| 腦看到的名字從哪來 | `tools.json` 裡 `tools` 的**鍵名**；`brain.py` 送腦時 `{"name": t["name"]}`，`act.py` 只認登記過的名字 | `templates/agent-fsm/brain.py` 191-194、`act.py` 170 |
| 名字規則 | `[A-Za-z0-9_-]{1,64}`，不能 `/`、`.`（這是各家 LLM function name 的共同限制） | `apps/tools/common.py` 6、`agent_spec_parts.py` 14 |
| 誰取名 | `aos-tools add` 沒給 `--name` 就用夾名；`_tooldef.json` 不放名字；`tool_spec`（`tool.py`）用夾名只當錯誤行開頭，不是登記名 | `apps/tools/main.py` 65、165-172；`tool_spec.py` 253-256 |
| 同名 | `$override` 疊：後面的**逐欄合併**蓋前面的（物件欄位再合一層、其餘整個換），`null`＝拿掉；不報錯。只有 `aos-mcp` 合併多份登記檔時同名會報 `duplicate tool name` | `apps/tools/registry.py` 60-144；`apps/mcp/main.py` 173 |
| **實測** | 暫存夾 `~/.aos/scratch/aos-ns-1119/exp1`（經清 `AOS_*` 的 `run.sh`，只用 repo 的 `bin/aos-tools`，沒起 daemon）：包甲 `read`→`base/read`、包乙 `read`→`base/view`，`tools.json` 寫 `{"$override":["packA.json","packB.json"]}`。`aos-tools ls` 退 0、只列一個 `read`、沒有任何警告；`aos-tools get read` 指的是 `view`，說明也是 view 的。**腦會看到叫 `read`、實際是另一支的工具** | 本線實測 |

### 2. 工具包（pack）

- `ag.pack("look")` 生成 `$override` 的一項 `{"$env":"AOS_HOME","$path":"/lib/packs/look.json"}`；包名規則 `[a-z0-9][a-z0-9_-]*`，生成時查包檔在不在（`agent_spec_parts.py` 13、71-74、84）。
- 18 包：look、change、delete、shell、gadgets、todo、self、mailbox、goal、json、jsonx、index、events、subagent、def、kernel_gate、ws-write、comm（原始碼 `py/packs/`）。包內鍵名＝工具夾名，62 個名字各包之間沒有重複（蒐集員實數）。
- **包名就是「`$AOS_HOME/lib/packs/` 底下的檔名」**：只有一個地方找，沒有別的來源。
- 兩個包都有 `read`：後面那包悄悄蓋前面的；包跟單一工具撞名：單一工具（`tools` 自己那格最後疊）贏；`ag.no(x)` 寫成 `x: null`；同一包寫兩次報 `SpecBad`（`agent_spec_parts.py` 69、77、80）。

### 3. hook

- `hooks.json` 是 `{名: {event, handler, condition, on_error, …}}`；handler 多半指 `$AOS_HOME/lib/tools/agent/<x>`。名字非空、不含 `/`、不以 `.` 開頭，同時也是 `<stack>/hooks/<名>/` 小格的夾名（`py/aos/hook_run.py` 30、70-73）。
- 只有兩層：定義那份、stack 那份；同名整格蓋，`null`＝關掉。**沒有 `$override`**，`interfaces.json` 也只准指定義夾內的檔（`agentlib/hooks.py` 121-140、`declared_files.py` 22-28）。
- `ag.stock_hooks(template="agent-fsm")`：生成時讀 `$AOS_HOME/templates/<範本>/hooks.json`，整組**抄**進來（`agent_spec.py` 172-192）。三組：agent-fsm 四個（context_wrap、timer、brain_notify、mail_notify）、eca-claude 六個、eca-pi 兩個。**範本名在這裡兼當「hook 組的名字」**。

### 4. fsm 的格

- 格名是 `fsm.json` 裡的自由字串（只擋前後空白、換行），只在那一張表裡要唯一（`agent_spec.py` 112-113、143-163）。
- `ag.stock_fsm()`＝四格 idle／think／wait／act，argv 指 `$AOS_HOME/templates/agent-fsm/<prog>.py`，是**借**（指過去、不抄）（`agent_spec.py` 29-32、166-169）；reviewer 範本手寫同樣的借法。
- 指示詞 `$env`／`$path`／`$ref`／`$prefix` 每次用到才解、不寫回（`directive_value.py` 1-25、`refpath.py`）。

### 5. agent 定義夾與範本

- `templates/` 底下：agent-fsm、agent-python、eca-claude、eca-pi、reviewer、judge-llm、tool-python、daemon-root、kernel/{llm-kernel, daemon-kernel, procs-kernel, llm-team}、kits/{gather, review}、start-api、start-eca。
- `agent_def new {"template": 名}` 只收單層名字（不准 `/`、開頭 `.`），對到 `$AOS_HOME/templates/<名>`；找不到就列出有 `interfaces.json` 的夾；另有 `from` 收任意路徑或指示詞。**`kernel/llm-kernel` 這種兩層名用 `template` 叫不到**，只能走 `from`（讀程式推，`py/tools/agent/agent_def/_entry` 92-98、192-199）。
- `lineage`：出生時寫進 `_metainfo.json`（`{"template": 名}` 或 `{"from": 原樣}`），是「原始碼出處」，執行時沒人讀（C-89）；`agent.py` 不准設它（`agent_spec.py` 258-260）。
- 範本之間：reviewer 借 agent-fsm 四格；agent-python 用 `stock_fsm`＋三包；start-api、start-eca 是各範本的**逐字抄本**，靠 `templates/tests/test_start.py` 比對同步。

### 6. 腦（llm kernel 的 endpoint 名）

- agent 的 `llm.json` 寫 `model`（如 `luna`），`brain.py` 249 行填進問腦信的 `body.endpoint`——agent 這邊叫 model，kernel 那邊叫 endpoint。
- 對到**那台** llm kernel 的 `kernel.json#/endpoints`（扁平 `{名: 包}`，可 `$ref` 切檔），表上沒有報 `EndpointUnknown`；用哪台由 `$AOS_LLM_KERNEL` 決定（`templates/kernel/llm-kernel/kernel.json` 4-51、`packs.py` 85-103、286-306、`wait.py` 354）。**同一個名字在不同 kernel 可以指不同模型**——名字的範圍＝那台 kernel。
- 跨 kernel 只有 llm-team 的包用 `to`＋`kernel` 明寫轉交（`templates/kernel/llm-team/kernel.json` 11-27）。重複鍵 `json.loads` 靜默取後者。

### 7. daemon 表上的 proc 名

- 每台 daemon 一張表 `daemon.json#/procs`，proc 的 stack 預設 `<daemon stack>/procs/<名>/`；名字不能空、不含 `/`、`#`、不以 `.` 開頭（`cpp/aos-daemon/docs/01-用法.md` 23、31）。
- `--name` 沒給就取定義夾 basename；撞名報 `InstanceExists`（`apps/daemon_ctl/main.py` 487-492、`apps/agent/ctl/add.py` 162、182-186）；直接寫 `procs_added` 同名＝換設定。`subagent` 掛在同一張表、不加上層前綴；子 daemon 自己一張表。`_clock`、`_sweeper` 這種 `_` 開頭只是慣例。

### 8. 知識庫、指令、變數、信、MCP、kits

| 類 | 名字從哪來、怎麼找 | 像前綴的 |
|---|---|---|
| 知識庫 | 普通資料夾＋`.json`，路徑 `夾/檔.json#/指標`；`_index.json`／`_index` 鍵；沒有 `AOS_KNOWLEDGE`、沒有搜尋路徑；多庫＝多棵樹、不登記不疊（`knowledge/docs/01-樹長怎樣與多庫.md` 20-35） | 首段 `aos/`、`wf/` |
| 指令 | Python 的在 `py/entries.json`，強制 `aos-[a-z0-9-]+`；C++ 的 Makefile `addprefix aos-`；兩邊撞名 `install.py` 報 `EntriesBad`；`env.sh` 把 `$AOS_HOME/bin` 排 PATH 最前（`install.py` 159-181、`cpp/Makefile` 51-53、`env.sh` 21-27） | `aos-` |
| 環境變數 | 一律 `AOS_`，分四種性質；`.env` 每跳讀一層 | `AOS_` |
| 信、kernel | 全用路徑定址，沒有名字表；自己給的信名撞了報 `LetterExists`（`cpp/aos-post/docs/01-用法與元素.md` 23-30） | — |
| MCP | 凍結進 aos 的登記名 `<server>_<tool>`（小寫、64 字內、server 不准叫 `aos`）；eca 那邊 Claude 看到 `mcp__<server>__<tool>`（`mcp_freeze.py` 21-30、`mcp_server_file.py` 204-207） | **唯一帶前綴的工具名** |
| kits | `--kit` 吃夾路徑，不是名字；`templates/kits/kits.json` 只是索引（`apps/agent/ctl/kit.py` 41-42） | — |

## 今天就有的「疊層、覆蓋、抄、借」（繼承那節會用到）

| 機制 | 哪裡 | 誰蓋誰 |
|---|---|---|
| `$override` | 工具表（`tools.json`、`tools_sub.json`、pack） | 陣列照順序疊、自己最後；逐欄合併；`null` 拿掉；有環 `RegistryBad` |
| stack 蓋定義 | `tools.json`（`aos-agent tools add` 生 `{"$override": 定義那份, tools: 差異}`）、`llm.json`（鍵級）、`hooks.json`（格級） | stack 贏；定義不變（C-52「漂移只在 stack」） |
| kit | `ctl add --kit` 把 kit 的 `tools.json`、`system.txt` 直接蓋進 stack；kit 的 `$override` 直接指包、不經定義那份 | kit 贏，定義的工具不透上來 |
| 範本抄出 | `agent_def new`（整夾抄，寫 `lineage`）、`ag.stock_hooks()`（抄 hook 組） | 抄完各走各的 |
| 借 | `ag.stock_fsm()`、reviewer 的四格、所有 `$AOS_HOME/lib/...` 指示詞 | 被借的改了，借的人跟著變 |
| `.env` | aos-exec 每跳一層 | 預設不蓋已有的，`--dotenv-override` 才蓋（`cpp/aos-exec/docs/02-種類.md` 22 與 36 行字面有出入，沒查） |
