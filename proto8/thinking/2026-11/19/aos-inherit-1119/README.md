# 繼承深挖（線 aos-inherit-1119，11-19）：「繼承」在 aos 是哪幾件事、今天已有的機制實測、別人怎麼做、四條走向（推薦在 agent.py 重生時衍生、執行期不動）、跑著長出來的收不收回、四題要使用者拍板

← [日索引](../README.md)｜前一輪淺的那節：[aos-ns-1119/04](../aos-ns-1119/04-繼承-淺想.md)

使用者 11-19：「繼承那塊可以派深的去想了。」他沒說繼承要長怎樣，所以這份是**發想與選項**，不是施工計劃；方向由他拍板（[00](00-使用者原話.md)）。只寫文件，沒改程式。

## 先講結論

1. **「繼承」在 aos 真正算數的只有一個形狀：一份底＋一小份差異**。它有兩面：差異寫在 `agent.py`、重生時算完（定義衍生，例：`reviewer` 衍生出 `strict-reviewer`），和差異寫在 stack、執行時疊上去（這一隻跑著長出來的工具、hook）。庫衍生庫、範本衍生、換一格狀態機、除錯版都是前者的局部；C-87 的「變成」、`lineage` 只是長得像（[01](01-繼承是哪幾件事.md)）。
2. **今天的機制實測有五個意外**（[02](02-現況事實表.md)）：抄跟借常常一半一半（`agent_def new` 抄來的夾工具路徑指回來源）；`$override` 的菱形會悄悄把中間層的修改蓋回去；逐欄合併留殘渣、能讓工具壞掉；hook 同名整格換，`on_error: continue` 一起丟、回到「一失敗就停住」；一支 `agent.py` 直接 import 另一支，會把底那隻的定義寫進錯的夾、退出碼還是 0。
3. **推薦乙：衍生只在 `agent.py` 重生時做**，生出的 json 照舊整份、沒有上一層，執行期與 cpp 一行不動。Argon 審後只補**一個新函式** `ag.load("../reviewer")`（跑底那支，它最後一行的 `ag.main` 不寫檔、只交出欄位），其他是現有的 `TOOLS`／`HOOKS`／`ag.fsm` 多收「底」；「故意蓋 vs 碰巧同名」直接沿用命名空間第一刀：自己明寫的＝故意、兩個來源撞名又不同＝報錯，拿掉的留墓碑，所以菱形會報錯而不是悄悄蓋回或復活。**最小可試的一刀**只動 `agent_spec*`、骨架不用改，約 80 行、可丟（[04](04-設計選項.md)）。
4. **衍生做成「吃一份定義資料、吐一份定義資料」的函式，不做成 Python class**：這樣跟 Lisp 的 macro 同一邊（建置時展開），將來換成 Lisp 也只是換一層殼（[03](03-別人怎麼做.md)）。
5. **跑著長出來的東西要不要收回成新定義**：推薦現在只做一頁唯讀的「這隻跟定義差在哪」，倒成 `agent.py` 幾行等乙的零件有了、真要第二隻時再做。跟「C 與 .o」不打架：收回不是改那份 `.o`，是另寫一份新原始碼（[05](05-執行中長出來與定義衍生.md)）。
6. **跟舊裁定**：乙不違反 10-14「不做繼承：沒有 extends、沒有搜尋路徑」在 json 那層的字面（json 照樣整張、`ag.load` 只收明寫路徑），但同句後半「每個 agent 寫整張表……範本資料夾不是父類」在 `agent.py` 那層對不上，做完後寫 `agent.py` 的人做的事就是繼承，所以**列成題**、不自己推翻；執行期借（丁）跟 10-14 第 3 題、「hook 組是抄」正面衝突，不推薦。C-87 不衝突；C-89 的 `lineage` 不動，但出處因此分成兩套，**列成題**（[04 末節](04-設計選項.md#跟舊裁定的關係)）。
7. **要使用者拍板五題**：走向（甲／乙／丙／丁）、「繼承」進不進規範、長出來的收不收回、狀態機要不要「這一隻自己的」一層、衍生的出處記在哪（[06](06-邊緣狀況與要拍板的題.md) (d)）。Argon 審過（十點審查、四點提案；沒推翻方向，乙由四個小幫手縮成一個 `ag.load`，抓到菱形復活與相對路徑兩個真洞），採納表在 [07](07-Argon審與採納.md)。
