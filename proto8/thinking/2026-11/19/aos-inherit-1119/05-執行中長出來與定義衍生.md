# 跑著的 agent 長出工具與 hook 之後，要不要、能不能收回成一份新定義：它跟定義衍生是同一個形狀的兩面，差一座「倒出」的橋；五個選項，推薦現在只做「看得見」、橋等真的要第二隻時再搭

← [README](README.md)｜上一份：[04-設計選項](04-設計選項.md)｜下一份：[06-邊緣狀況與要拍板的題](06-邊緣狀況與要拍板的題.md)

## 先講結論

1. **這跟定義衍生是同一個形狀（底＋差異）的兩面**（[01](01-繼承是哪幾件事.md)）。stack 那幾份檔其實就是一份「沒有名字、只有一隻在用的衍生」。「收回」＝把這份沒名字的差異，改寫成有名字的：一個新定義夾，或 `agent.py` 裡的幾行。
2. **跟「C 與 .o」不打架，照使用者自己的比喻就講得通**：定義夾是 `.o`；跑起來後加的工具像執行中載入的 lib，掛在 stack，重生碰不到。「收回」不是回頭改那份 `.o`，而是**另寫一份新的原始碼**，內容是「跟那份一樣，再多載這幾個 lib」。
3. **lisp 的「存 image」今天已經有了**：stack 就是一個資料夾，整夾留著就是那一隻的完整樣子，`sleep`／`wake` 就是存下來再接著跑。缺的不是存，是**從那個樣子提煉出一份可以再開第二隻的定義**。
4. **推薦**：現在只做選項 1（一頁唯讀的「這隻跟它的定義差在哪」）；選項 3（倒出成 `agent.py` 的幾行）等 [04](04-設計選項.md) 乙的零件有了、而且他真的想要第二隻時再做。**要不要收回是方向題，由使用者拍板。**

## 今天長出來的東西落在哪（[事實表](02-現況事實表.md) D1～D6）

| 長出來的 | 落在哪 | 是「底＋差異」嗎 | 倒得出來嗎 |
|---|---|---|---|
| 工具（`self_tools`、`aos-agent tools add`） | stack 的 `tools.json`，`$override` 指回定義 | 是 | 是，差異就是那張表 |
| hook（`self_hook`、gdb 觸發器） | stack 的 `hooks.json` | 是，同名整格換 | 是；`gdb_` 開頭的是除錯器裝的，不該倒 |
| 腦設定 | stack 的 `llm.json` | 是，逐鍵 | 是 |
| system | stack 的 `system.txt` | **不是**：整份取代 | 只能整份倒，看不出改了哪幾句 |
| kit 帶來的工具 | stack 的 `tools.json`，**不**指回定義 | **不是**：定義的工具整份被換掉 | 只能整份列出 |
| 狀態機的格 | **定義夾**的 `fsm.json`（沒有 stack 那一層） | 不適用 | 這一隻沒有「自己的」狀態機差異可倒；改了就是改到用這份定義的每一隻，而且下次重生被蓋掉 |
| 記憶（`history.jsonl`） | stack | 不是定義的一部分 | 不倒；要連記憶一起＝複製整個 stack，那是「存 image」 |

另一個坑：`ctl set-def` 之後，stack 的工具還疊在**舊**定義上，其他三樣疊在新定義上。所以倒出時不能照 stack 檔裡寫的指標去找底，要**現算**：先算這隻此刻生效的整套，再跟它現在掛的那份定義比，差的才是差異。

## 五個選項

| | 做法 | 產出 | 好處 | 代價 |
|---|---|---|---|---|
| 0 不收回 | 什麼都不做 | — | 最貼「自然長出來，不特意規劃」（user/03，11-14） | 想要第二隻一樣的，只能照著 `tools ls -l` 手抄 |
| **1 只給人看（推薦現在做）** | 一個唯讀指令，印「這隻跟定義差在哪」：多的、關掉的、換掉的工具；增減改的 hook；改過的腦設定；system 換了沒；定義夾的 `fsm.json` 跟 `agent.py --defs` 算出來的對不對得上 | 一頁字（或一份 json） | 零風險；各欄的來源今天多半已經查得到（`tools ls -l` 的 FROM、`llm ls -l`、hook 的 `from`），只差湊成一頁 | 人看完要自己改 `agent.py` |
| 2 倒成 json 定義夾 | 把生效的整套寫成一個新定義夾（＝`agent_def new` 抄底，再把差異壓進去） | 一個掛得上去的夾，沒有 `agent.py` | agent 自己也做得到（它不寫 `agent.py`，庚第 4 題）；`lineage` 照 `agent_def new` 的規矩寫一次 | 是一份沒有原始碼的 `.o`：之後不能重生，底改了永遠不跟；等於一份加強版的 kit |
| 3 倒成 `agent.py` 的幾行 | 產一支新的 `agent.py`：`base = ag.load(底)`，再把差異寫成 `ag.tool`、`ag.no`、hook 表、腦設定幾行 | 一支短短的原始碼，人看得懂、改得動 | 底改了重生就跟；長出來的東西從此有名字、進 git | 要先有 04 乙的 `ag.load`；底沒有 `agent.py` 時要 `ag.from_folder`；system 只能整份貼 |
| 4 寫回原來那支 `agent.py` | 改上游的原始碼 | — | 不多一份定義 | 用那份定義的每一隻都跟著變；要程式去改別人手寫的 Python。不推薦 |

選項 3 產出的樣子（`bob` 是 `reviewer` 的一隻，自己加了 `git_log`、關了 `write`、腦換過）：

```python
base = ag.load("/ws/agents/reviewer")      # grown from the running agent bob, 2026-11-19

DESCRIPTION = base.DESCRIPTION
SYSTEM = base.SYSTEM
TOOLS = [base.TOOLS,
         ag.tool("git_log", ag.env("AOS_WS", "/tools/git_log")),
         ag.no("write")]
LLM = {**base.LLM, "model": "luna"}
HOOKS = base.HOOKS                          # 底的 hook 原樣帶著（漏了會連 loop.json 的 on_start／on_stop 一起沒，Argon A7）
FSM = base.FSM

ag.main(DESCRIPTION, SYSTEM, TOOLS, LLM, FSM, hooks=HOOKS)
```

（例子照 [04](04-設計選項.md) 修正版的寫法；Argon 審前的版本漏了最後一行 `ag.main` 與 `HOOKS`。）

這不是 11-18 調查說「沒人做到全自動」的那種反推。那種是從整份 json 猜回整支原始碼；這裡只倒**差異**，差異本身就是一格一格的結構。但有兩個前提（Argon A8）：

- **比對基準要跟倒出的底一致**：倒出的是 `ag.load(底的 agent.py)`（原始碼），差異就要拿生效的整套去減 `python3 底/agent.py --defs` 現算的那份，不是減定義夾裡現有的 json（`.o`）；兩者對不上（底改了沒重生、或有人手改過 json）就先報出來，不倒。
- **一格整格倒**：stack 的 tools 是 `$override` 逐欄合併（例如只替底的 `read` 補了一個 `env`），`agent.py` 的 `ag.tool` 是整格換；所以有差的那格要倒成**合完之後的整格**，而且取登記檔裡的原文（保留 `{"$env": …}` 指示詞），不取展開後的絕對路徑。

## 幾個要先想清楚的點

- **誰來倒**：人在 REPL 或 shell 下指令。agent 倒自己＝生一份新定義，C-89 說「生新定義不算函數改自己」，知識庫的規矩也允許它用 `agent_def` 做新定義；但它不寫 `agent.py`（庚第 4 題），所以 agent 自己只走得了選項 2。
- **倒出來的東西放哪**：C-89 ad-5 的備註原話是「演化出的定義樹放工作區……可以定期將定義提取出來。之後其他工作……可以運用。」——倒出這件事他說過要，位置是工作區。
- **倒完原來那一隻怎樣**：不動。它還是掛在舊定義上、stack 照舊。要讓它改掛新定義是 `ctl set-def`，那時腦設定、hook、system 的差異會**再疊一次**在已經含差異的新定義上（同一個值再設一次，結果相同）；但**工具那份不會**：stack 的 `tools.json` 還 `$override` 舊定義，工具照舊疊在舊定義上，之後新定義對工具的任何修改對這一隻都無效（Argon A8 指正，原稿寫「多半無害」是錯的）。所以「倒出再掛回」不是一個乾淨的動作，先當成兩件事；要掛回得先清掉 stack 的工具那份（`aos-agent tools` 的現成做法之外，沒有一鍵）。
- **狀態機長不出來**：這一隻想換一格，今天只能改定義夾，影響每一隻、重生就沒了。要讓狀態機也能「這一隻自己長」，得給它一層 stack 疊層，那是動執行期（`loop.json` 找 `fsm.json` 的方式）。gdb 線的原第 4 題問過同一件事、他還沒說。這裡不替他定，[06](06-邊緣狀況與要拍板的題.md) 列成題。
- **「長出來時怎麼看得見、接得住」**（user/03 那句的後半）：選項 1 是看得見；04 乙的 `ag.load`（與 `TOOLS`／`HOOKS` 收底）是接得住的零件——有了它，選項 3 只是一支把差異印成幾行 Python 的小工具，隨時可以補，不必現在設計管線。

## 「變成」這個詞有兩個意思，別混

| | C-87 的「變成」 | 這裡的「變成新的一種」 |
|---|---|---|
| 講的是 | 一次執行裡，一支程式接著跑下一支，共用同一個 stack | 一隻 agent 的配備跟它的定義越差越多，到了值得另起一個名字的程度 |
| 時間尺度 | 一拍之內 | 幾小時到幾天 |
| 有沒有新定義產生 | 沒有 | 有（如果收回） |
| 跟定義衍生的關係 | 只在「換格之後新舊格共用 stack」那一處相關 | 同一件事的執行時那一面 |
