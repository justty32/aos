# 「繼承」在 aos 可能指的十件事：真正算數的只有「一份底＋一小份差異」這一個形狀的兩面（宣告時寫在 agent.py、執行時寫在 stack），其餘是它的局部、兩面之間的橋、或只是長得像

← [README](README.md)｜上一份：[00-使用者原話](00-使用者原話.md)｜下一份：[02-現況事實表](02-現況事實表.md)

## 先講結論

1. **真正算「繼承」的只有一個形狀：一份底，加一小份差異。** 它有兩面：差異寫在 `agent.py`、生成時算完的，叫**定義衍生**；差異寫在這一隻的 stack、每次讀才疊的，叫**實例蓋定義**。後者今天已經完整存在，前者今天只能靠抄夾或手動 import。
2. **庫衍生、範本衍生、換一格、除錯版，都是定義衍生的局部或做法**，不是另外的事。把它們當成四件各做一套機制，就會做出四套。
3. **「跑著長出工具後變成新的一種」是兩面之間的橋**：把寫在 stack 的差異倒回成寫在 `agent.py` 的差異。今天沒有這座橋（[05](05-執行中長出來與定義衍生.md)）。
4. **C-87 的「變成」、`lineage`、C-52 的「不繼承」只是長得像**，各有各的事，新設計都不用動它們。

## 十件事

例子都用同一組人物：`reviewer`＝使用者自己用 `agent.py` 寫的審稿 agent；`bob`＝它跑起來的一隻。

| # | 哪件事 | 使用者實際會想寫的 | 今天怎麼做 | 歸到哪 |
|---|---|---|---|---|
| 1 | **定義衍生** | `strict-reviewer`＝`reviewer`，但 system 多三條規矩、拿掉 `write`、腦換成 `luna` | `agent_def new` 抄一夾再改；或 `agent.py` 互相 import（沒保護會悄悄寫錯夾，[事實表](02-現況事實表.md)結論 5） | **本體，宣告時那一面** |
| 2 | 庫衍生 | 「我的 look」＝std 的 `look` 包，但 `read` 換成會遮密碼的那支、`grep` 不要 | 第一刀已能寫：`[std.pack("look"), ag.tool("read", my.tool("read")), ag.no("grep")]`；想重複用就存成 Python 變數或自己庫裡的 `packs/look.json` | 第 1 件的「工具」那一欄 |
| 3 | 範本衍生 | 從 `agent-python` 骨架做一隻查帳的 | `agent_def new` 整夾抄、寫 `lineage`，之後各走各的 | 第 1 件的「抄」做法（只衍生一次） |
| 4 | 換一格 | 跟 agent-fsm 一樣四格，但 `think` 換成「先查快取、沒有才問腦」那支程式 | 自己把四格重寫一遍、改其中一格（`std.fsm()` 沒有逐格換） | 第 1 件的「狀態機」那一欄；10-14 起頭那句「class 函數可以被覆蓋」講的是這件 |
| 5 | 除錯版 | 同一隻 `reviewer`，但多掛三個「叫 `write` 前先停」的觸發器 | REPL 裡 `a.bp.add(...)` 掛在 stack；「生成時加個選項」還沒做 | 第 1 件的特例（多疊一層 hook），或第 6 件 |
| 6 | **實例蓋定義** | 跑著的 `bob` 發現要查 git，自己 `self_tools add git_log` | stack 那份疊在定義上（工具、腦設定、hook、system） | **本體，執行時那一面** |
| 7 | 長出來後變成新的一種 | `bob` 跑了三天，多了五支工具、system 改過兩次；想要第二隻一樣的 `carol`，或以後都從這個樣子起 | 沒有。kit 只能帶 system 與 tools，而且是整份換 | 第 6 件 → 第 1 件的**橋** |
| 8 | exec 鏈「變成」（C-87） | `_entry` → `aos-loop` → `aos-fsm` → `brain.py`，一路共用同一個 stack | 就是今天的執行方式 | 只是像 |
| 9 | 血緣紀錄 `lineage` | 想知道 `strict-reviewer` 是從誰抄來的 | `agent_def new` 出生時寫一次，只記一層 | 紀錄，不是機制 |
| 10 | 層與層（C-52） | 上層 agent 叫下層 agent 當工具 | 什麼都不往下傳 | 不是繼承，只是條文裡有「不繼承」三個字 |

## 同一個形狀的兩面：第 1 件與第 6 件

| | 定義衍生（宣告時） | 實例蓋定義（執行時） |
|---|---|---|
| 差異寫在哪 | `agent.py` 裡的幾行 | 這一隻的 stack（`tools.json`、`hooks.json`、`llm.json`、`system.txt`） |
| 誰寫 | 人（庚第 4 題：`agent.py` 先只給人用） | 人下指令，或 agent 自己用 `self_*` |
| 何時算 | 重生那一刻，算完寫成整份 json | 每想一次、每個事件現疊 |
| 底改了 | 重生才跟（抄） | 立刻跟（借） |
| 有幾隻受影響 | 用這份定義的每一隻 | 只有這一隻 |
| 有沒有名字 | 有，一個定義夾 | 沒有，就是「bob 現在的樣子」 |
| 狀態機 | 可以整張換 | 換不了（fsm 沒有 stack 疊層） |

所以淺想那節留的第四題（「變成」跟「衍生」是不是同一件事）要分兩個「變成」來答：

- **第 7 件的「變成新的一種」跟定義衍生是同一件事的兩面**，差在差異放哪、何時算。
- **第 8 件 C-87 的「變成」不是**。C-87 管的是「一次執行裡，前後幾支程式共住一個 stack，檔名別互踩」；定義衍生管的是「一份定義的內容從哪來」。兩者只在一處碰面：**衍生時換了某一格的程式（第 4 件），新格跟底留下的格執行時共用 stack，這時新格的作者要守 C-87**——看清楚底的格用了哪些檔名，避開或故意接手。使用者 11-02 那句「你要考慮你的 base class 做了啥、用了啥，並且斟酌決定是否要覆蓋，或是避開」放在這裡一字不改就適用。

## 只是長得像的三件，為什麼不算

- **C-87 exec 鏈**：沒有「底＋差異」。每一跳不蓋任何檔或設定，只有共用；使用者自己也說「在呼叫這塊，其實沒有 base class, deriative class 之分」。
- **`lineage`**：C-89 明講它是「原始碼的出處（像 git 的 fork 紀錄），不是執行時的上層」，沒有程式拿它做決定。
- **C-52**：講的是巢狀執行時上層不往下層傳東西，跟一份定義從哪來無關。

## 定義衍生今天各欄少了什麼（給 04 用）

| 哪一欄 | 今天少的那一小塊 |
|---|---|
| 工具（第 2 件） | 底如果已經自己明寫過 `ag.tool("read", …)` 或 `ag.no("grep")`，下游把兩串相加會撞「listed twice」。缺一個「把底那一整串當成一個包」的說法 |
| hook | 同名只能整格換，一換就把底那格的 `on_error`、`timeout_ms` 丟掉（事實表結論 4）。缺一個「拿底那格、只改這一欄」的寫法 |
| 狀態機（第 4 件） | 只能整張重寫。缺一個「拿底那張、換這一格」的寫法 |
| system、腦設定 | 不缺：字串相加、dict 合併，Python 本來就會 |
