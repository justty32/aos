# 定義衍生的四條走向（甲 純 Python、乙 一個 ag.load 加現有函式收「底」（Argon 審後由四個小幫手縮成）、丙 宣告物件、丁 執行期借）：各自怎麼寫、各欄怎麼蓋、跟舊裁定哪裡衝突；推薦乙、從甲那一刀起步，方向由使用者拍板

← [README](README.md)｜上一份：[03-別人怎麼做](03-別人怎麼做.md)｜下一份：[05-執行中長出來與定義衍生](05-執行中長出來與定義衍生.md)

這份是發想與選項，不是施工計劃（[00](00-使用者原話.md)）。函式名都是提案。例子：`strict-reviewer`＝`reviewer`＋system 多一條、拿掉 `write`、`read` 換成自己庫的、腦換 `luna`、`timer` 改成一分鐘、`think` 格換一支程式。

## 先講結論

1. **推薦乙**：衍生全部發生在 `agent.py` 重生的那一刻，生出來的 json 照舊是整份、沒有「上一層」。執行期與 cpp 一行不動。**Argon 審後（[07](07-Argon審與採納.md)）乙縮成「一個新函式 `ag.load`＋現有函式多收一種參數」**，見下面「乙（Argon 審後的修正版）」；原本四個小幫手那段留作對照。
2. **乙的第一刀就是甲**（修掉「import 另一支會悄悄寫錯夾」的坑），做了不會白做。
3. **「故意蓋」與「碰巧同名」沿用命名空間第一刀的分法，不新發明**：自己明寫的那一格蓋誰都算故意；兩個來源之間同名又不同＝報錯。底帶著「我是哪個來源」的標記進來，這條規則就自動套到衍生上；**拿掉的那一支要留一個墓碑**（像 Docker 的 whiteout），菱形裡「一邊拿掉、一邊留著」才抓得到。
4. **丁（執行期借）跟 10-14 第 3 題、今天裁的「hook 組是抄」正面衝突**，不推薦；它唯一買到的是「上游改了下游自動跟」。

## 甲：純 Python

修兩處就能用（兩處都算修 bug，設計者直接定，見 [06](06-邊緣狀況與要拍板的題.md)）：骨架最後一行改成 `if __name__ == "__main__": ag.main(...)`；`ag.main` 發現叫它的檔是被 import 的，就什麼都不做直接回（舊的 `agent.py` 沒加那行 `if` 也安全）。之後使用者照 Python 自己寫：

```python
import importlib.util                               # 兩支都叫 agent.py，不能直接 import agent
_s = importlib.util.spec_from_file_location("reviewer_agent", os.path.join(_d, "../reviewer/agent.py"))
base = importlib.util.module_from_spec(_s); _s.loader.exec_module(base)

SYSTEM = base.SYSTEM + "\nRefuse a change that has no test.\n"
LLM = {**base.LLM, "model": "luna"}
TOOLS = base.TOOLS + [ag.no("write")]               # 底自己寫過 ag.no("write") 就 SpecBad: listed twice
HOOKS = [std.hooks(), {"timer": {**std.hooks()["hooks"]["timer"], "every_ms": 60000}}]   # 伸手進內部形狀
```

夠用的：system、腦設定、「包＋加減幾支」。不夠的正是 [01](01-繼承是哪幾件事.md) 末節那三塊（底明寫過的工具再改會撞、hook 只改一欄要伸手進內部、狀態機只能整張重寫），外加載入那三行沒人背得起來。

## 乙（Argon 審後的修正版，推薦）：一個 `ag.load`，其他是現有函式多收一種東西

Argon 指出原版乙的六個洞（[07](07-Argon審與採納.md) A1～A7、A9、A10）：菱形裡被拿掉的會被另一邊悄悄復活；hook 的「底」跟「自己寫的」都是普通 dict、分不出來；`ag.load` 在模組最外層報錯會變 traceback；`sys.modules` 快取讓「還原 `sys.path`」沒用；底裡的相對路徑抄進衍生夾就指錯；底沒宣告 `HOOKS`／是 eca 版／某欄是 `by_hand` 時 `base.X` 直接炸。修正版照它的 B1～B3 收斂：

```python
base = ag.load("../reviewer")          # 跑那支 agent.py；它最後一行的 ag.main(...) 不寫檔、不退出，把九個欄位交出來

DESCRIPTION = "Review a change and refuse anything without a test."
SYSTEM = base.SYSTEM + "\nRefuse a change that has no test.\n"
LLM    = {**base.LLM, "model": "luna"}
TOOLS  = [base.TOOLS,                  # 底那一整串＝一個帶標記的來源；要改前綴：base.tools(prefix="r_", exclude=[...])
          ag.no("write"),
          ag.tool("read", my.tool("read"))]
HOOKS  = [base.HOOKS, {"timer": {**base.HOOKS["timer"], "every_ms": 60000}}]   # 底那組帶標記；自己寫的 dict 才是「故意蓋」
FSM    = ag.fsm(base.FSM, [ag.state("think", ["python3", "think_cached.py"])])  # 同名格只換有給的欄位，next 沿用底的

ag.main(DESCRIPTION, SYSTEM, TOOLS, LLM, FSM, hooks=HOOKS)   # 照舊一行；被別人 ag.load 時這行只交出欄位
```

| 改了什麼 | 怎麼做 | 修的是 |
|---|---|---|
| `ag.load(路徑)` | 照路徑跑那支 `agent.py`，在 `agent_spec` 裡記「正在載入」；它跑到 `ag.main(...)` 時不讀 argv、不寫檔、不退出，把九個欄位正規化成一份底交回（沒宣告的 `HOOKS`＝空組、eca 版 `FSM`＝None、`by_hand` 的欄位＝報一行 SpecBad 說「這一欄底是手寫檔，不能衍生」）。舊的 `agent.py` 一行不用改就能當底 | A3、A7；不必加 `if __name__` |
| 載入失敗 | 當下報一行 `SpecBad`（帶是哪一支、哪一行）並退 1；在 REPL 裡改成丟例外、不殺行程 | A3 |
| 隔離 | 底在自己的模組名下跑；載入期間新進 `sys.modules` 的非 aos 模組、加進 `sys.path` 的夾，載完都還原 | A4 |
| 相對路徑 | 底裡的相對路徑（工具 path、env_file、狀態格的 argv）載入時照底那夾換算成絕對路徑或指示詞，跟 `Lib._full` 同一套；換算不了＝SpecBad | A5 |
| `TOOLS` 收底 | `base.TOOLS` 是一個帶來源名的「包」；`base.tools(prefix=, rename=, exclude=)` 跟 `std.pack` 同一組參數 | A6 |
| 墓碑 | 底裡被 `ag.no` 拿掉的、`None` 拿掉的 hook，在來源表裡留成 `None`，到最後寫檔才濾掉；兩個來源一邊 `None` 一邊有＝SpecBad | A1 |
| `HOOKS` 收底 | `std.hooks()` 與 `base.HOOKS` 回一個帶來源標記的 dict（可以 `["timer"]` 取一格）；**兩個帶標記的來源同名又不同＝SpecBad，自己寫的普通 dict 才是故意蓋**；description 裡的出處去重 | A2；拿掉 `ag.change` |
| `FSM` 收底 | `ag.fsm(底, [ag.state…], drop=())`：同名格只換有給的欄位（沒給 `next`＝沿用底那格），新名的加上，`drop` 的拿掉，整張重驗 | A10；拿掉 `ag.refit` |
| 工具「只改一欄」 | **不提供**：工具一律整格換（`ag.tool`），不把殘渣請回來 | A9 第 3 點 |

不經 `ag.load`、直接 `import` 別支 `agent.py` 的，`ag.main` 發現叫它的模組不是 `__main__` 就什麼都不做（保險，免得 [02](02-現況事實表.md) 結論 5 又發生）。`ag.state` 在 `ag.fsm(底, …)` 裡可以只給要換的欄位，單獨用時照舊要給齊。新函式只剩 `ag.load` 一個；`ag.base`、`ag.change`、`ag.refit` 都不要了。原版（四個小幫手 `ag.load`、`ag.base`、`ag.change`、`ag.refit`）審後不留全文；Argon 對它指出的洞逐點見 [07](07-Argon審與採納.md)。

**為什麼逐欄只放在 Python 這邊**：「整格換」是今天唯一的疊法（工具第一刀、hook 生成時、stack 那份 hook 都是），維持它；「只改一欄」是 `agent.py` 裡明寫的一個動作，生成時算完，寫出來還是完整的一格。這樣不必把 `$override` 擴到 hooks，事實表結論 3 的殘渣、結論 4 的丟設定都不會悄悄發生。

**除錯版是同一招**：gdb 那邊的「編譯時加個選項、多生一些除錯用的觸發器」＝重生時在 HOOKS 最後多疊一層；選項放哪照 gdb 06 第 5 條不現在定。

**REPL**（`defs()`、`write_defs()` 本來就能當函式叫）：

```python
>>> from aos import agent_spec as ag
>>> r = ag.load("/ws/agents/reviewer")
>>> d = ag.defs(r.DESCRIPTION, r.SYSTEM + STRICT, [r.TOOLS, ag.no("write")], r.LLM, r.FSM, hooks=r.HOOKS)
>>> sorted(d["tools.json"]["tools"])                # 先看再寫
>>> ag.write_defs("/ws/agents/strict-reviewer", d)   # 夾要先 mkdir
```

收底的寫法都是「吃值、回新值」，不改底，REPL 裡試十種衍生互不汙染。注意：這樣寫出的夾**沒有 `agent.py`**，之後不能重生，是一份沒有原始碼的「.o」；要留就把那幾行存成 `agent.py`。

## 丙：宣告物件

```python
r = ag.derive("../reviewer")
r.system += "\nRefuse a change that has no test.\n"
r.tools.no("write"); r.tools.set("read", my.tool("read"))
r.llm["model"] = "luna"; r.hooks["timer"]["every_ms"] = 60000
if __name__ == "__main__": r.main()
```

最短、REPL 裡最順手，最像 lisp 拿一個物件邊看邊改。代價：`agent.py` 從此有兩種寫法；物件可以就地改，REPL 裡改了 `r` 再衍生第二隻，第一次的修改會跟過去；「故意蓋」散在各處的賦值裡，不再是清單上的一行。乙做完後，丙可以是包在乙上面的薄薄一層，不必現在選死。

## 丁：執行期借

定義夾裡寫 `{"$override": "../reviewer/hooks.json", "hooks": {"timer": {"every_ms": 60000}}}`，`fsm.json` 同理，`tools.json` 今天已經可以。好處：上游一改全部下游立刻跟；手寫 json 的人、不會寫 `agent.py` 的 agent 也能衍生。代價：事實表結論 2（菱形悄悄蓋回）、結論 3（殘渣）原樣帶進 hook 與狀態機；上游夾一刪下游全壞；`system.txt` 是純文字疊不了；要改 hook 機制與 cpp。

## 生出來的東西、出處、上游改了

- **json 與 shell 那邊什麼都不變**：`python3 agent.py --write-defs`，夾裡是整份 json、每格全路徑，沒有 `extends`、沒有 `$override`；`aos-agent ctl add 夾` 照舊。跑的時候不需要底那一夾還在。
- **出處不另外記**（設計者定）：原始碼那行 `ag.load("../reviewer")` 就是出處，像 `#include`；`tools.json` 的 description 有一句從哪抄的。`lineage` 不碰——C-89 說它出生時寫一次、之後不回寫，重生時改它就違反這句。
- **上游改了**：下游重生才跟，跟已裁的「hook 組是抄」同性質。重生時 Python 會把整條鏈的 `agent.py` 重跑一遍，所以衍生的是**原始碼**不是對方的 json：`reviewer` 改了但自己沒重生，`strict-reviewer` 重生後反而比 `reviewer` 的 json 新。
- **誰載了我**：`grep -r 'ag.load(' 定義樹`。原始碼就是答案，不做登記表。

## 跟別的裁定怎麼相處

| 裁定 | 相處方式 |
|---|---|
| 命名空間 B、第一刀 | 直接沿用：底＝一個包；別的庫的前綴在底那邊已經加好，衍生不再加 |
| 「C 與 .o」、重生直接蓋 | 衍生只是原始碼多了 `#include`；產出後照樣無關、照樣整份蓋 |
| 執行中增長（stack 疊層） | 互不相干：衍生只寫定義夾，stack 那份照舊疊在生出來的定義上。底拿掉了某支工具而某隻的 stack 還在改它，照今天 `$override` 的行為（多出一格） |
| gdb 觸發器 | 觸發器掛在 stack、名字 `gdb_…`，衍生碰不到；`agent.py` 裡的 hook 別取 `gdb_` 開頭（C-87：各自管好前綴） |
| 換格之後 | 新格與底的格共用 stack，守 C-87（[01](01-繼承是哪幾件事.md)） |

## 菱形與多個底

`d1`、`d2` 都衍生自 `base`，`d1` 把 `a` 換成另一支、拿掉 `write`。頂層寫 `[d1.TOOLS, d2.TOOLS]`（修正版；原版寫 `ag.base(...)`）：沒被改的工具兩邊完全相同，算同一支；`a` 兩邊不同＝SpecBad「comes from both … and they differ」，頂層得明寫 `ag.tool("a", …)` 選一支；`write` 一邊是墓碑、一邊還在＝同樣報錯，頂層明寫 `ag.no("write")` 或 `ag.tool("write", …)`（沒有墓碑時這一支會被 `d2` 悄悄復活，Argon A1）。對照 `$override` 的菱形是悄悄把 `d1` 的修改蓋回去。hook 組比照辦理：兩個帶標記的來源之間同名又不同＝報錯，自己寫的普通 dict 才是蓋（這會收緊第三刀「後面的同名蓋前面」的行為，只收緊「兩個來源互蓋」那一種；今天能寫出兩個來源的只有「兩次 `std.hooks()` 用不同範本」，設計者定）。

## 跟舊裁定的關係

| 舊裁定 | 甲乙丙 | 丁 |
|---|---|---|
| 10-14 第 3 題「沒有 extends、沒有搜尋路徑；每個 agent 寫整張表，想沿用就一格一格寫範本路徑或 `$ref`；範本資料夾不是父類」 | **json 那層不衝突**：生出來的 `fsm.json` 照樣整張。**但後半句在 `agent.py` 那層對不上**（Argon A9）：`ag.fsm(base.FSM, …)` 就是把另一夾當父類、不再一格一格寫——「繼承」進不進規範、這半句管不管 `agent.py`，**列成題**（[06](06-邊緣狀況與要拍板的題.md) 第 2 題） | **衝突**：整份 `fsm.json` 的 `$override` 就是 extends；只用原話允許的逐格 `$ref` 則不違背 |
| 同題的「沒有搜尋路徑」 | 要老實講：Python 的 `import` 本身就走搜尋路徑（`sys.path`）。骨架只往裡放兩處（自己那夾、`$AOS_HOME/lib`），而 `ag.load` 只收明寫的路徑、不搜尋，跟 `ag.lib("my", 路徑)` 同一招。所以**衍生另一支 agent 不經過任何搜尋**；同夾的普通模組 `import helper` 是 Python 的本分，不算 aos 的機制 | — |
| 10-16 C-56 補充「不要用這種方式添加規則……埋雷」 | 不衝突：每個蓋的動作都是清單上看得見的一行；沒有「沒寫就照底」以外的暗規則 | 逐欄合併的殘渣正是這種雷 |
| C-87 | 不衝突，換格時反而正好適用 | 同左 |
| C-89、`lineage` | 不衝突：不寫 `lineage` | 同左 |
| 庚 10「hook 組是抄」、命名空間第 7 題（暫定抄） | 一致 | **衝突**：改成借 |
| `$override` 原話（11-10） | 不動它 | 擴它的範圍，沒有原話支持 |
