## 先講結論：五個出乎意料的行為

1. **抄跟借常常一半一半**。`agent_def new` 整夾抄，但 tools.json 的相對路徑改寫成指回**來源那份**，抄過去的工具夾沒人用：來源的工具一改新夾跟著變、來源一刪新夾就壞〔測〕。`std.fsm()` 格子表是抄、格裡的程式是借〔測〕。`ctl set-def` 換定義後，stack 那份 tools 還是借**舊**定義〔測〕。
2. **`$override` 的菱形會悄悄把中間層的修改蓋回去**〔測〕：d1、d2 都疊 base，d1 把 `a.path` 改成 t3，頂層寫 `[d1, d2]`，疊的順序是 base→d1→base→d2→頂層，base 第二次又把 `a.path` 蓋回 t1，不報錯（`py/aos/apps/tools/registry.py` 第 110～127 行，註解明講「照樣疊」）。
3. **逐欄合併會留殘渣，殘渣能讓工具壞掉**〔測〕：下游只改 `path`，上游的 `env`、`env_file`、`cache:false` 都留著；殘留的 `cache:false` 碰上新的資料夾型 path ＝ RegistryBad、工具被跳過。手寫 `$override` 沒保護；`aos-tools add --replace` 會主動把底有、自己沒給的欄位寫成 `null` 防殘渣。命名空間第一刀起 `agent.py` 生成時整格換，沒有殘渣。
4. **hook 同名是整格換，定義那格的設定一起丟**〔測〕：stack 只寫 `timer` 的 `every_ms`，定義那格的 `on_error: continue`、`timeout_ms: 5000` 消失，回到預設 `stop`、`60000`——這個 hook 一失敗就會停住 agent。`agent.py` 裡 `[std.hooks(), {"timer": {…}}]` 也一樣整格換。
5. **一支 `agent.py` 直接 import 另一支，會悄悄產出錯的東西、退出碼還是 0**〔測〕：被 import 的那支最後一行 `ag.main(...)` 在 import 時就跑、`sys.exit(0)`，衍生那支根本沒跑到——`--defs` 印的是底那隻；`--write-defs` 沒給夾時寫進的是**底那隻自己的夾**；給了夾就把底那隻的定義寫進衍生的夾。兩支都叫 `agent.py` 時 `import agent` 先找到自己，`AttributeError: partially initialized module`。可行寫法見末節。

## 兩個小問題

**一支 `agent.py` 能不能 import 另一支？** 能，要加保護〔測〕：

- 骨架放進 `sys.path` 的：`agent.py` 自己的夾、`$AOS_HOME/lib`（`templates/agent-python/agent.py` 第 6～10 行）。
- `ag.main` 用 `sys._getframe(1)` 取「叫它的檔」當預設夾，被 import 時照跑、`sys.exit`（`py/aos/agent_spec.py` `main`）。所以直接 `from agent import TOOLS` 會出結論 5 那種事。
- 可行的三種寫法都退 0、產出正確：①底那支最後一行包成 `if __name__ == "__main__": ag.main(...)`，衍生用 `importlib` 照路徑載；②同樣加保護，`sys.path.insert(0, 底夾)` 再 `import agent`；③共用宣告放成同夾普通模組 `base_agent.py`，`from base_agent import TOOLS`。
- a 引 b、b 引 a＝Python 自己的 `ImportError … circular import`。

**生出來的 json 有沒有「上一層是誰」？** 沒有〔測〕：`_metainfo.json` 只有 `{"summary": …}`；唯一間接線索是 tools.json／hooks.json 的 description 寫「從哪些包／範本抄的」（說的是庫或範本，不是上一層 `agent.py`）。改底那支的 TOOLS，衍生的重生前 15 支、重生後 18 支——上游改了不會自己跟。
