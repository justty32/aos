邊緣狀況以 [04](04-設計選項.md) 的乙為準；〔今〕＝今天就會發生（[事實表](02-現況事實表.md)實測），〔乙〕＝做了乙之後的行為。照使用者偏好，邊緣狀況只攤出來，不逐條追問。

## (a) 邊緣狀況

**載入另一支 `agent.py`**

1. 〔今〕被 import 的那支最後一行是沒保護的 `ag.main(...)`：import 當下就跑完、退 0，衍生那支根本沒跑；`--write-defs` 沒給夾時寫進底自己的夾。〔乙〕`ag.main` 被 import 時不做事，骨架也改成 `if __name__ == "__main__":`。
2. 〔今〕兩支都叫 `agent.py`，`import agent` 找到自己，報 `partially initialized module`。〔乙〕`ag.load` 照路徑載、模組名不撞。
3. 〔乙〕a 載 b、b 載 a：`ag.load` 自己認得出來，報 SpecBad 說出那個圈。
4. 〔乙〕底那支在模組最外層做的事全部會跑（讀包、讀檔、`print`）。底用的庫根變數沒設，錯是記在底的 `TOOLS` 裡、等衍生那支 `defs()` 才報（Argon A3 第 3 點），訊息會叫人「fix the declaration in」衍生那支——`ag.load` 交回時要掃一遍底裡記著的錯，改寫成帶上是哪一支的。
5. 〔乙〕底那支 `import helper` 之後，`helper` 進了全域的 `sys.modules`；只還原 `sys.path` 沒用，衍生那支再 `import helper` 會直接拿到底那夾的（Argon A4）。`ag.load` 要連載入期間新進 `sys.modules` 的非 aos 模組一起還原。
6. 〔乙〕底沒宣告 `HOOKS`（骨架預設就沒有）、或是 eca 版沒有 `FSM`：修正版由 `ag.main` 交出九個正規化的欄位（沒宣告＝空組或 None），不會 `AttributeError`（Argon A7、B1）。eca 版的底衍生時仍要給已有骨架的夾（`defs(folder=)` 的規矩），REPL 對空夾寫會報 SpecBad。
7. 〔乙〕底的某一欄是 `ag.by_hand(...)`（`SYSTEM`／`TOOLS`／`LLM`／`FSM`／`HOOKS` 都可以）：沒東西可衍生，`ag.load` 交回時那一欄報一行 SpecBad，叫人改用 `ag.from_folder`（讀手寫夾那刀）或自己列（Argon A7 第 4 點：不擋的話 `{**base.LLM}` 會把 `{"kind": "by_hand"}` 混進腦設定）。
7b. 〔乙〕底裡寫的相對路徑（`ag.tool("t", "./my_tool")`、狀態格 `["python3", "x.py"]`）抄進衍生夾就從衍生夾算起、指錯（Argon A5）。`ag.load` 載入時照底那夾換算；換算不了報錯。衍生那支自己寫的相對路徑照舊從衍生夾算。
7c. 〔乙〕底的路徑不在或變數沒設時，連 `python3 agent.py --help` 都會在 `ag.load` 那行失敗（`--help` 在 `ag.main` 才處理）；可接受，錯誤訊息照樣一行。
8. 〔乙〕想當底的定義沒有 `agent.py`（`templates/reviewer`、agent 自己用 `agent_def` 做的）：`ag.load` 用不了，第四刀之前只能 `agent_def new` 抄。

**上游變動**

9. 上游改了：下游的 json 不變，重生才跟；沒有任何提醒。
10. 鏈 Z←Y←X：X 改了、Y 沒重生、Z 重生，Z 的 json 含 X 的新內容而 Y 的還是舊的——衍生的是原始碼，不是對方的 json。
11. 上游夾刪掉或搬走：已生出的下游照跑（json 是整份）；下游下次重生＝`ag.load` 找不到，SpecBad，夾裡不變。
12. 上游把某支工具拿掉，下游還寫著 `ag.no("那支")`：重生報「no pack in TOOLS has a tool」——上游少一支會讓下游重生失敗，這是故意的（不然 `ag.no` 寫錯字不會被發現）。
13. 〔今〕`agent_def new` 抄來的夾，工具路徑指回來源：來源一改就跟、一刪就壞（結論 1）。這是抄夾那條路自己的坑，走 `agent.py` 衍生沒有，不在這條線修。

**同名與蓋**

14. 菱形：兩個底都來自同一個祖先、其中一個改過某支工具＝SpecBad，頂層要明寫選哪支；沒改的算同一支。〔今〕`$override` 的菱形是悄悄蓋回（結論 2），手寫 json 與 stack 那邊照舊有。
15. 底的工具來自別的庫、已經叫 `my_read`；衍生那支自己也 `ag.lib("my", 另一個路徑)`：兩個 `my_read` 不同＝SpecBad。庫名只在各自那支檔裡有效，撞了由下游 `prefix=` 改。
16. 〔今〕hook 同名整格換，底那格的 `on_error: continue`、`timeout_ms` 一起丟，回到預設的「一失敗就停住 agent」（結論 4）。〔乙〕要只改一欄就寫 `{**base.HOOKS["timer"], "every_ms": 60000}`；整格換仍然合法，丟設定是寫的人看得見的選擇。
17. 工具不提供「只改一欄」（Argon A9 第 3 點：開了就把殘渣請回來，生成時也擋不住 `cache: false` 配資料夾型 path）；要改就 `ag.tool` 整格寫。
17b. 菱形裡一邊拿掉（`ag.no`、hook 設 `None`）、一邊留著：沒有墓碑時那一支會被另一邊悄悄復活（Argon A1）；修正版留墓碑、報 SpecBad。
18. 衍生的 hook 取名 `gdb_…`：除錯器掛在 stack 的同名觸發器會整格蓋掉它；倒出（[05](05-執行中長出來與定義衍生.md)）時也會被當成除錯器的而略過。照 C-87：`gdb_` 是除錯器的前綴，別人避開。
19. 〔乙〕`ag.fsm(base.FSM, [ag.state("think", …)])` 換掉 `think` 格（原版叫 `ag.refit`）：新程式與底的 `idle`、`wait`、`act` 共用 stack 的檔（`stage.txt`、`history.jsonl`…），要守 C-87；沒有東西幫忙檢查。
20. 〔今〕`std.fsm()` 的格程式是借的：aos 升級後四格的程式變了，所有衍生（含換過一格的）沒重生也立刻跟著變。

**環境與 REPL**

21. 跨機：`ag.load("../reviewer")` 相對路徑只要兩夾一起搬就沒事；寫絕對路徑或 `ag.env("AOS_WS", …)` 的，另一台路徑不同或變數沒設＝重生失敗。已生出的 json 不受影響（裡面沒有底的路徑）。
22. REPL 裡 `ag.write_defs` 寫出的夾沒有 `agent.py`，之後沒辦法重生；那幾行要自己存下來。
23. REPL 裡改了底那支檔再 `ag.load` 一次：要拿到新的（每次重載、不留快取）；舊的 `r` 還是舊值。
24. 〔丙才有〕物件可以就地改，改了 `r` 再衍生第二隻，第一次的修改會跟過去。乙的幫手都回新值，沒有這件事。

**執行中長出來的**

25. 〔今〕`ctl set-def` 後工具疊舊定義、其他疊新定義；kit 掛上後定義的工具整份被換掉。倒出時要現算差異，不能照指標找底。Argon B4 提議讓 stack 的工具那份改成「跟著現在掛的定義疊」——那是改執行期（`aos-agent tools`、`ctl set-def`），不在這條線，記在 [07](07-Argon審與採納.md) 當另開的題。
26. 〔今〕狀態機沒有 stack 那一層：一隻想換格只能改共用的定義夾，重生就被蓋。

## (b) 淺想那節留的四題

**一、用 Python 的 import 做夠不夠？被 import 的那支放哪、怎麼找？** 當骨幹夠，但少四小塊（載入的坑、底明寫過的工具再改會撞、hook 只改一欄、狀態機換一格），所以推薦乙。放哪：放哪都行，**由下游明寫路徑**（`ag.load("../reviewer")`），不搜尋，跟 `ag.lib("my", 路徑)` 同一招。Python 自己的搜尋路徑確實還在（`sys.path`），但衍生另一支 agent 不經過它；它只管「同夾的普通 Python 檔」與 aos 套件本身。

**二、`hooks.json` 要不要也有 `$override`？** 不要。今天裁的是「hook 組是抄」；借的話，菱形蓋回、逐欄殘渣、上游刪了就壞這三件會原樣搬進 hook。使用者真正缺的是「只改一欄不丟 `on_error`」，在 `agent.py` 明寫一行 `{**base.HOOKS["timer"], "every_ms": …}` 就有（Argon 審後不另設 `ag.change`），生出來的仍是完整一格。stack 那份 hook 照舊整格換，不動。

**三、上游改了，衍生的怎麼知道？** 不會自己知道，重生才跟——跟 `std.hooks()`、包同一條規矩。查誰用了我：`grep -r 'ag.load('`。查某個夾過時了沒：拿 `python3 agent.py --defs` 現算的跟夾裡的比（不記帳）；庚拿掉過 `--status`，這個先當點子、不排。`lineage` 不拿來做這件事。

**四、「變成」跟「衍生」是不是同一件事？** 分兩個「變成」（[01](01-繼承是哪幾件事.md)、[05](05-執行中長出來與定義衍生.md)）。「跑著長出工具後變成新的一種」跟定義衍生是同一個形狀的兩面，差一座倒出的橋。C-87 的「變成」不是，它管一次執行裡共用 stack 的檔名；只在「衍生時換了一格」那一處跟衍生碰面。

## (c) 設計者直接定的（原則推得出，不另問）

1. **衍生是抄、重生才跟**。依據：「C 與 .o」、已裁「hook 組是抄」、命名空間第 7 題暫定抄。
2. **`ag.main` 被 `ag.load` 載入時只交出九個欄位、被普通 import 時不做事；骨架不用改**（Argon B1；原稿是「骨架加 `if __name__`」）。這是修事實表結論 5 的 bug；舊的 `agent.py` 一行不改就能當底。
3. **底用明寫的路徑指**，不設固定位置、不設搜尋順序。依據：10-14「沒有搜尋路徑」、命名空間第 6 題暫定同款。
4. **故意蓋與碰巧同名照第一刀分**：自己明寫的那格＝故意；兩個來源之間同名又不同＝SpecBad。hook 組比照（收緊第三刀「後面蓋前面」裡「兩個來源互蓋」那一種；自己寫的表蓋來源照舊）。
5. **疊法只有整格換；只改一欄是 `agent.py` 裡明寫的 Python（hook、腦設定用 `{**底那格, 鍵: 值}`；工具不提供）**。`$override` 不擴到 hooks、fsm。依據：C-56 補充「埋雷」那句、事實表結論 2～4。
6. **不碰 `lineage`**。依據：C-89「出生時寫一次、之後不回寫」。但 Argon 指出這會讓「出處」分成兩套（`_metainfo.json` 的 `lineage` 與原始碼裡的 `ag.load`，用 `agent_def new` 從骨架抄出再改成衍生時 `lineage` 還寫著 `agent-python`），要不要另記一個鍵列成第 5 題。
7. **`gdb_` 前綴不在生成時擋**，只寫進說明。依據：C-87「各自管好自己的手」。

## (d) 要你拍板的五題

### 第 1 題：定義衍生放在哪裡做

比喻：照媽媽的食譜做菜，但鹽少一匙。可以把整份抄到自己的本子上再改（之後媽媽改食譜，你要重抄才知道）；也可以只在自己本子上寫「照媽媽那份，鹽少一匙」，每次煮都翻兩本（媽媽一改你就跟，她把本子丟了你就煮不了）。

| 選項 | 後果 |
|---|---|
| 甲 純 Python，只修載入的坑 | 最省；底明寫過的工具再改會撞、hook 只改一欄與換一格都要自己拼 |
| **乙 甲＋一個 `ag.load`，現有的 TOOLS／HOOKS／`ag.fsm` 多收「底」（推薦）** | 抄到自己本子那種。只動 `agent_spec`，分兩刀，第一刀含甲；執行期不動；json 那層跟舊裁定相容，`agent.py` 那層跟 10-14「範本資料夾不是父類」對不上（第 2 題） |
| 丙 一個可以邊看邊改的物件 | REPL 最順；`agent.py` 多一種寫法；可以之後包在乙上面 |
| 丁 執行期借（hooks、fsm 也能 `$override`） | 每次翻兩本那種。上游改了自動跟、手寫 json 也能用；**要推翻** 10-14 第 3 題（`fsm.json` 有了 extends）與今天裁的「hook 組是抄」，還要改 hook 機制與 cpp |

### 第 2 題：「繼承」這個詞現在進不進規範

衝突在哪：10-14 你說「『繼承』只是一種形容，還沒進規範，以後再說」，同日定「不做繼承：沒有 extends、沒有搜尋路徑；每個 agent 寫整張表，想沿用就一格一格寫範本路徑或 `$ref`；範本資料夾不是父類」。乙沒有違反 json 那層的字面（json 照樣整張、不搜尋），但在 `agent.py` 那層，`ag.fsm(base.FSM, …)` 就是把另一夾當父類、不再一格一格寫（Argon A9）；做完之後，寫 `agent.py` 的人做的事就是繼承。比喻：店裡規定「不賣酒」，現在廚房要用料理酒做菜——菜單上沒有酒，但要不要在規定裡補一句說清楚。

| 選項 | 後果 |
|---|---|
| **a 進，寫明只在生成時（推薦）** | 補一條：衍生只發生在 `agent.py` 重生時；定義夾的 json 永遠寫整份；10-14 第 3 題原封不動，註明它管的是 json 與執行時。以後有人提丁，有條文可擋 |
| b 不進，只當 `agent.py` 的寫法技巧 | 條文不動；「不做繼承」跟 README 裡教人衍生的例子並存，新來的讀到會困惑 |
| c 換個詞（例「衍生」），「繼承」留給 10-14 那個意思 | 兩個詞各管一件，條文最不會被誤讀；多一個詞要記 |

### 第 3 題：跑著的 agent 長出來的東西，要不要有辦法收回成一份新定義

比喻：廚師做了三天，邊做邊在圍裙口袋裡多放了五樣工具。要不要有人幫他把「口袋裡現在有什麼」列成一張清單，好讓下一位廚師一上工就帶齊。原則推不出來：你說過這種事「自然而然會發生，不用特意規劃」，也說過「可以定期將定義提取出來」。

| 選項 | 後果 |
|---|---|
| 0 不做 | 要第二隻一樣的就照著看、手抄 |
| **1 先只做一頁「這隻跟定義差在哪」（推薦）** | 唯讀、零風險；看得見了，再看要不要下一步 |
| 2 倒成一個 json 定義夾 | agent 自己也做得到；但那份之後不能重生、底改了不跟 |
| 3 倒成 `agent.py` 的幾行（衍生自底、多了這些） | 最完整；要先有乙的零件，等你真的想要第二隻時再做 |

### 第 4 題：狀態機要不要有「這一隻自己的」那一層

工具、hook、腦設定、system 都能只改這一隻（寫在 stack）；只有狀態機不行，要換一格就得改共用的定義夾，每一隻都變、重生就沒了。gdb 那輪的原第 4 題問過同一件事，你還沒說。比喻：每位廚師可以自己多帶工具，但「先切菜還是先燒水」的流程表貼在牆上、大家共用，沒有個人版。

| 選項 | 後果 |
|---|---|
| **a 先不做（推薦）** | 換格走定義衍生（乙的 `ag.fsm(底, …)`，生一份新定義再 `ctl set-def`）；執行期不動 |
| b 做：stack 裡有 `fsm.json` 就優先用 | 一隻可以邊跑邊長出新的格，最貼「在指令中央插入新指令」；要動執行期找狀態機的方式，並想清楚「正停在被換掉的那一格」怎麼辦 |

### 第 5 題：衍生出來的定義，「我從誰來」記在哪（Argon 審後加）

衝突在哪：C-89 說族譜是「資料夾樹＋出生時寫一次的血緣紀錄」、「它是原始碼的出處（像 git 的 fork 紀錄）」，`lineage` 由 `agent_def new` 寫、之後不回寫。走乙之後，真正的出處寫在 `agent.py` 的 `ag.load("../reviewer")`；而 `lineage` 可能寫著 `{"template": "agent-python"}`（從骨架抄出來再改成衍生），或根本沒有（`mkdir` 後直接 `--write-defs`）。定義目錄（`defs` 的 catalog）只讀 `lineage`，看不到衍生關係。比喻：戶口名簿寫「生於某醫院」，但真正的爸媽寫在日記裡。

| 選項 | 後果 |
|---|---|
| **a 只在原始碼（推薦）** | `lineage` 照 C-89 不動；查衍生關係用 `grep 'ag.load('`。兩套出處各說各的，目錄頁看不到衍生 |
| b 重生時另寫一個鍵（例 `_metainfo.json` 的 `derived_from`，不是 `lineage`） | 目錄看得到；但重生會改寫它，等於「`.o` 裡留了一點原始碼的痕跡」，要說清楚它跟 C-89「只寫一次」的 `lineage` 是兩件事 |
| c 讓 `lineage` 也記衍生 | 要改 C-89 第 4 點「出生時寫一次、之後不回寫」 |
