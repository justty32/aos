## 一、邊緣狀況

### 找套件、版本

1. **一般 `python3` 找不到 `aos`**：照推薦只有 `aos-gdb` 與自帶那四行開頭的腳本找得到。錯誤是 Python 原生的 `ModuleNotFoundError`，不是我們那種一行錯誤。攤著（第 4 題）。
2. **工作夾裡有一支叫 `aos.py` 的檔**：在那個夾開 `python3` 或跑腳本，`import aos` 抓到它，報 `'aos' is not a package`。`aos-gdb` 把 `lib/` 插在最前面所以不受影響；自己寫的腳本會中，**`agent.py` 骨架也會中**——它把自己的夾排在 `$AOS_HOME/lib` 前面（Argon A7）。已定：說明裡寫一句「不要把檔取名 aos.py」；骨架那兩處（排序、`except` 只認 `name == "aos"`）等有人動骨架時一起改（繼承線）。
3. **`lib/` 落後 `py/`**（01 第 4 節第 2 點）：改了 `py/aos/py/` 沒跑 `install.py`，REPL 用的還是舊的。這是既有的規矩（活樹只跑 `bin/`、`lib/`），不另做偵測。
4. **庫比指令新或舊**：薄殼不檢查版本。庫新、指令舊→多給的旗標指令回 `FlagUnknown`，一行錯誤看得懂；庫舊、指令新→新子指令代理照樣叫得到。這是代理比手寫包裝耐放的地方。
5. **兩個 aos 家**（`AOS_HOME` 指甲、`PATH` 上是乙的 `bin/`）：庫從甲的 `lib/` 載入，跑的指令是乙的。`env.sh` 已經會警告這種對不上；庫不另外查。攤著。
6. **`PATH` 上沒有 `aos-agent`**（沒 source `env.sh` 就開 REPL）：`Failed`，訊息提示 source（今天 `aos.gdb` 已經這樣做）。
7. **`from aos.py import ag` 需不需要 `PATH`**：不需要，寫定義那邊不跑任何指令；`std.pack(…)` 宣告當下要讀得到 `$AOS_HOME/lib/packs`（既有行為）。
8. **import 的成本**：`from aos.py import agent` 不該順便載入斷點庫、觀察者、寫定義那一整套。已定：子模組互不 import，`a.bp` 第一次用到才載。

### 搬家

9. **`install.py` 只加不刪**：`py/` 刪掉或改名的檔，每台機器的 `lib/` 裡還在，舊的 import 照樣成功——等於留了一個沒人知道的別名；第一刀不喜歡想刪掉時，`lib/aos/py/` 也清不掉。已定：第零刀改成「照抄之後刪孤兒」；**不**先整夾刪（Argon A7：活樹在中間那一刻會 import 不到）。
10. **正在跑的樹上已經下的斷點**：hook 本體 `lib/tools/agent/gdb_trigger` 會 import 斷點庫；重裝那一刻新舊交替，正扣著的那一次可能壞。採納後 `aos.gdb` 不搬、hook 本體不動，風險只剩一般重裝都有的那一下；在沒有扣著斷點時重裝，施工紀錄寫明。
11. **`aosgdb-api-1119` 寫稿時還沒交，收尾時已交（`822ee9228`）**：第一刀完全不碰 `py/aos/gdb/` 與 `apps/gdb`；第二刀接它時，它的 README、知識庫 `cli/gdb.json`、測試要再跟一次（預放名字換成新把手）。
12. **日後入口改名**（第 1 題反悔）：改一個夾名＋所有 `from aos.py` 的地方；不留舊名。越晚改越多行，所以第 1 題最好在第二刀之前答。

### 通用代理

13. **打錯名字不會當場報錯**（Argon A4 後只剩子層：把手頂層照 `aos-agent` 的子指令表擋，`a.tool`、`a.resume` 當場 `AttributeError`）：`a.ctl.stp()`、`agent.tool.add("x")`（模組層）會真的去跑 `aos-agent … tool add x`，由指令回「沒有這個子指令」。錯誤看得懂、沒有副作用，但要多等一次行程啟動（約 0.1～0.3 秒），tab 補全也補不出子指令名。可以讓代理認得一份子指令清單來補全與擋錯，但那份清單就是第二份真相、會過時。已定：第一刀不做清單；嫌煩再說（自然長出）。
14. **只是看一眼就跑指令**：今天在 REPL 打 `a.bp` 會跑外部指令（它的顯示走 `ls`）。已定：凡是「把物件印出來」一律不跑指令、不讀檔，只印它是什麼；要看內容自己打 `a.bp.ls()`。
15. **tab 補全、`hasattr`、`copy`、`pickle` 會去問底線開頭的名字**：代理對底線開頭的名字一律照 Python 平常的方式說沒有，不翻成指令。
16. **旗標名是 Python 保留字**（`--from`、`--async`）：後面加底線（`from_=`、`async_=`），名字結尾的 `_` 一律去掉一個；`id=`、`type=` 這類內建名本來就能當參數名，不用加（Argon A2）。`--json`：`json=True` 是通則裡唯一有特別意思的關鍵字（加 `--json` 並解開）。若哪天某支指令有個要帶值的 `--json X`，會跟這條撞；今天沒有。攤著。
17. **旗標放哪**：各支指令的「旗標可以放在位置參數後面嗎」不完全一樣。已定：代理一律「`--daemon`／`--target` → 子指令 → 旗標 → 位置參數」。
18. **位置參數長得像旗標**（`a.say("-h")`、`a.goal.set("- item")`）：會被指令當旗標。已定：代理統一處理，不只 `say`——有任何位置參數以 `-` 開頭就先放 `--`（Argon A2）。第一刀查 `aos.flags` 認不認 `--`，不認就補在 `aos.flags`（一處改、全部指令受惠）。
19. **指令印了一半才失敗**：薄殼丟 `Failed`，已經印到 stdout 的那一半丟掉不回。攤著（要的話 `e.stdout` 多一欄，等有人需要）。

### REPL 裡的等待與中斷

20. **REPL 關了，斷點還在**：觸發器掛在 agent 身上、觀察者掛在 daemon 表上，Ctrl-D 之後照樣會把 agent 停住，而表上寫的是 `running`（解耦合，刻意的）。隔天沒開 REPL 的人只會看到「它不動了」。已定：`aos-gdb` 離開時若還有斷點，印一行提醒（不自動清——你可能就是要它留著）。
21. **`a.listen(timeout_s=20)`、`a.bp.wait()` 卡著時按 Ctrl-C**：回到提示符，agent 不受影響（只是不等了）。對 `listen` 來說，Ctrl-C 會送到那條正在跑的 `aos-agent listen` 子行程——它被訊號收掉、庫這邊收到 `KeyboardInterrupt`，不轉成 `Failed`。
22. **`a.bp.resume()` 等不到 handler 收到放行**（今天上限 10 秒）：丟 `Timeout`，訊息說 agent 的狀態沒被庫改動、可以再打一次。
23. **`a.ctl.stop()` 在扣住斷點時會一直等**（第二版實測過）：REPL 看起來像當掉。已定：把手的 `repr` 與 `a.bp.why()` 之外不特別處理；`a.ctl.stop(no_wait=True)` 本來就有。說明寫一句。
24. **真模型很慢**：`a.ask(…)`、`a.listen(…)` 的逾時是指令自己的旗標，庫不另設上限；沒給就照指令的預設。
25. **echo 太吵**：斷點庫一個動作會跑好幾條；斷點庫內部的查詢今天已經用 `quiet` 不印。已定：延伸裡「為了查而跑」的不印、「會改東西」的印；整個關掉是 `aos.py.echo = False`。

### 兩隻、兩棵樹

26. **把手記的是絕對路徑**：`attach` 當下把 daemon 轉成絕對路徑，之後在 REPL 裡 `os.chdir` 不影響。但沒 `attach`、直接叫模組（`agent.ctl.ls()`）時，daemon 預設是指令在**當下的工作夾**找 `./.stack`——換了夾就換了樹，不會提醒。已定：說明寫明；要穩就 `d = daemon_ctl.attach(".stack")` 先綁好。
27. **那隻被 `rm` 再掛回來**：已定：把手不快取 stack 路徑，用到才問（Argon A6），所以照樣讀得到新夾；今天的 `aos.gdb` 是 attach 時就記，第二刀換掉。
28. **兩個 REPL 接同一隻**：斷點 id 以 agent 為範圍，兩邊看到同一批；一邊 `rm` 另一邊手上的 id 就失效，而且 id 刪了會重用（01 第 4 節第 10 點）。歸 `aosgdb-api-1119`。
29. **經 kernel 的 daemon**（`--kernel`）：把手今天只綁 `--daemon` 與 `--target`。要綁別的「指哪一個」旗標時，照通則在那個模組的三行設定裡加一個名字。

### 名字

30. **幾組長得像的名字**，說明裡各講一次：`ag`（寫定義的庫）／`agent`（`aos-agent` 的薄殼）／`a`（某一隻的把手）；`ag.tool`（宣告一支工具）／`a.tools`（指令）／斷點的 `tool=`（篩工具名）；`a.look`（讀 stack 的檔）／工具包 `look`（腦用來看工作區的那包）；`a.ctl.state()`（`ctl state`）／`ag.state`（狀態機的一格）；`breakpoint`（模組）／內建的 `breakpoint()`。「包」一詞三義、`lib` 三處（01 第 4 節第 5 點）這次不處理。
31. **把手上打「不對著某一隻」的動作**（`a.ctl.ls()`、`a.ctl.add(…)`、`a.ctl.rm()`）：`aos-agent ctl add／rm／ls／set-def／who` 前面給了 `--target` 會報 `ArgumentsBad`（`apps/agent/ctl/__init__.py:13,50`）。已定：錯誤原樣帶上來，說明寫「這幾個用模組層 `agent.ctl.*`」；庫不另記一份表（Argon A1）。
32. **`json=True` 遇到空輸出或一行一個 JSON**：空的回 `None`，JSONL 解成 list；預設就印 JSON 的指令補收 `--json`（Argon A3）。

## 二、要你拍板的五題

### 第 1 題：給人用的 Python 入口叫什麼？

> **已裁（11-19 選項框）：a `aos.py`**，見 [07](07-使用者裁定.md)。

像店面的招牌——東西都一樣，只是門口掛哪個名字，掛了之後換要重印所有名片。

| 選項 | 你會打 | 後果 |
|---|---|---|
| **a `aos.py`（推薦）** | `from aos.py import agent, ag, std` | 你的原話。毛病：看起來像檔名、原始碼路徑是 `py/aos/py/`、會引誘人把檔取名 `aos.py`（[03 第一節](03-版面設計.md#一入口叫什麼方向題-1)） |
| b `aos` 本身 | `import aos`、`aos.agent.attach("ann")` | 最像一般 Python 庫、沒有像檔名的毛病；但公開的名字跟三十幾支內部模組（`aos.json`、`aos.agentlib`、`aos.apps.agent`…）並排，哪些算公開只能靠文件講。（a 的「夾＝公開」其實也只是約定，內部模組照樣 import 得到，Argon 指出；差別在約定寫在夾名上還是文件裡） |
| c 你另外給一個名字 | `from aos.<名> import …` | 結構同 a。我想過的 `api`、`user`、`cmd`、`repl` 都撞到現有的詞 |

推薦 a。**可以照推薦先走**；反悔的代價是改一個夾名與所有 import，越早越便宜（第二刀之前最好）。

### 第 2 題：操作 agent 時，「是哪一隻」要寫在每一行上，還是先講一次之後都算它？

> **已裁（11-19 選項框）：甲 把手式**，見 [07](07-使用者裁定.md)。

像打電話：每次都撥號碼（不會打錯人），還是按「重撥」（快，但你得記得上一通打給誰）。

| 選項 | 你會打 | 後果 |
|---|---|---|
| **甲 把手式（推薦）** | `a = agent.attach("ann")`；`a.say("hi")`；`a.bp.resume()` | 每一行看得出對誰；兩隻、兩棵樹不會弄混。`from aos.py import a` 不成立（`aos-gdb ann` 進去時 `a` 已替你放好） |
| 乙「目前這隻」 | `from aos.py import a, bp`；`a.use("ann")`；`a.say("hi")`；`bp.resume()` | 你那三句 import 原樣成立、字最少、像真的 gdb；切錯對象不會報錯，會把話說給另一隻、把另一隻停住 |

推薦甲。**可以照推薦先走**：乙等於甲再加一個「目前這隻」，之後要加不會弄壞東西；反過來（先乙後甲）會。

（原稿這題還有第三個選項「寫定義的不搬」，Argon 指出它跟「是哪一隻」是兩件事、不該綁成單選；審後直接定成寫定義不搬、入口轉匯出，不再問。原第 3 題「斷點要不要有 shell 指令」也不再問：兩個選項今天都不動程式，記在 [03](03-版面設計.md) 第三節——要從 shell 或 Lisp 下斷點的那天，做獨立的 `aos-bp`，C-86 說它等同 `aos-agent breakpoint`，`aos-agent` 不用認得它。）

### 第 3 題：建一個斷點，寫法是哪一種？

> **已裁（11-19 選項框）：`a.bp.add.before_tool("x")`**，見 [07](07-使用者裁定.md)。頂層問的時候 b 改寫成 `a.bp.add.<事件>(…)`（不是下表的 `stop.before_tool()`），使用者選了它；「兩種都留」沒選，字串式 `add("before_tool", …)` 不留，第二刀改。觀察者與自訂事件怎麼寫留給施工線。

像點菜：是說「我要一份牛排」（`add("牛排")`，菜名當字串），還是菜單上每道菜各有一顆按鈕（`stop.牛排()`）。

你第一段例子是 `a.stop.before_tool()` 回 id；第二段改成「以斷點為核心增刪改查、`a.bp.stop()`／`a.bp.resume()`」，沒說建斷點叫什麼。另一條線 `aosgdb-api-1119` 照第二段做了、已交（`822ee9228`，`skip`、`wait_stopped` 它自己也標暫定名）。

| 選項 | 你會打 | 後果 |
|---|---|---|
| a `add(事件, …)`（那條線現在的） | `b = a.bp.add("before_tool", tool="write")`；`a.bp.stop()`＝現在就停 | 增刪改查四個字對得整齊（add／rm／set／get）；事件名是字串，打錯到執行才知道（會報一行錯），tab 補不出來 |
| b `stop.<事件>(…)` | `b = a.bp.stop.before_tool(tool="write")`；現在就停是 `a.bp.stop()` | 讀起來就是「在什麼時候停」、tab 補得出事件；但 `a.bp.stop` 同時是「現在停」與「建斷點」的分組，一個詞兩個意思 |
| c 兩種都留 | 兩種都能打 | 少想一次；同一件事兩種寫法，說明與測試要寫兩份 |

**不推薦哪一種**（這是你的手感）。**可以先照 a 走**：那條線已經做了，改成 b 是改名字、不動機制。
### 第 4 題：隨手開的 `python3` 要不要也 import 得到 aos？

> **暫照推薦 a（只靠入口），使用者未單獨裁、可再改**，見 [07](07-使用者裁定.md)。

像家裡的鑰匙：只有從正門（`aos-gdb`）進來的人有，還是在門口地墊下也放一把。

| 選項 | 後果 |
|---|---|
| **a 只靠入口（推薦，先這樣）** | 進 REPL 用 `aos-gdb`；自己的腳本開頭照 `agent.py` 那四行。不動 `env.sh`，跟你 11-15 拿掉 `.pth` 的方向一致。隨手 `python3` 還是 import 不到 |
| b `env.sh` 設 `PYTHONPATH=$AOS_HOME/lib` | 哪裡的 `python3` 都 import 得到，`agent.py` 開頭那段可以拿掉。它不像 `.pth` 會指到舊地方（跟著 `AOS_HOME`、只在 source 過的視窗）；daemon 底下的工具也會繼承，但它們本來就自己把 `lib/` 插在最前面，不受影響（Argon 更正）。差別是方向：11-15 是「入口自己負責」，這是「環境替大家設好」 |

推薦 a，第二刀再讓 `aos-gdb` 的 NAME 可省（不接 agent 也能進 REPL），補上「隨手開一個」的門。**可以照推薦先走**；用了覺得卡再開 b，那時是加一行。

### 第 5 題：讀 stack 檔的那幾支（`a.history(3)`、`a.where()`…）要不要收進 `a.look`？

> **已裁（11-19 選項框）：a 收進 `a.look`**，見 [07](07-使用者裁定.md)。

像抽屜貼標籤：把「不是指令、只是偷看檔案」的那幾支放進一個貼了 `look` 的抽屜，檯面上只留指令。

| 選項 | 你會打 | 後果 |
|---|---|---|
| **a 收進 `a.look`（推薦）** | `a.look.history(3)`、`a.look.where()`、`a.ctl.state()` | 「`a.xxx`＝`aos-agent xxx`」沒有例外的名字；`a.history.ls()` 就是 `aos-agent history ls`。代價：停下來看東西時每句多打 `look.` 五個字 |

不算衝突但要你知道的三點：

- **10-15「少用 sh」**：庫自己跑指令都是直接給 argv、不經 `sh -c`；`sh("…")` 是給人在 REPL 順手打 shell 的，今天 `aos.gdb` 就有，照留。
- **N-43「下層的錯不轉述」**：`Failed` 把指令的錯誤行原樣帶上來、另外拆成欄位，沒有改寫，算透明轉交。
- **10-14「不做繼承、沒有搜尋路徑」**：本線只留接點（`if __name__ == "__main__"`），「`agent.py` import 另一支 `agent.py`」會把 Python 的搜尋路徑帶進來，那是 `aos-inherit-1119` 的題。
