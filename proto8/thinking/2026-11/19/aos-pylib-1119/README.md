## 先講結論

1. **今天三塊各長各的**：寫定義是「函式＋小 dict、延遲報錯」，除錯是「物件＋當場丟 `Failed`、印出背後指令」，其他 Python 模組幾乎都只是指令的內部零件；一般 `python3` 連 `import aos` 都要自己插路徑（[01](01-現況盤點.md)）。
2. **一天裡真正需要進 Python 的只有四樣**：找得到套件的門、對活的 agent 下指令、斷點、讀 stack 的檔。起樹、抄樹留在 shell（前景行程）；寫定義的功能今天都有（[02](02-一天的流程.md)）。
3. **推薦版面：入口是一個夾 `aos.py`（`from aos.py import …`）＋走向甲「把手式」**：`a = agent.attach("ann")` 拿到一隻的把手，`a.say`、`a.ctl.stop()`、`a.tools.add(…)`、`a.bp.add(…)`。寫定義的 `ag`、`std` 與斷點的 `aos.gdb` **檔都不搬**，入口轉匯出、把手接上（[03](03-版面設計.md)）。
4. **一條通則做成程式**：`aos-agent --daemon D --target N X Y --flag v ARG` ↔ `agent.attach(N, daemon=D).X.Y(ARG, flag=v)`，用一個約四十行的「通用代理」實作，`aos-agent`、`aos-daemon-ctl` 現有與以後的子指令自動都有 Python 寫法；回傳 `json=True` 是解好的、否則是原樣文字、生出東西的回 id；活的那一邊只有一種例外 `Failed`；背後指令 REPL 裡印、腳本裡不印。**薄殼（一呼叫＝一條指令）是硬規則**，例外只有兩個有名字的延伸：`a.bp`（斷點）、`a.look`（讀 stack 的檔）；把手頂層打錯名字當場報錯。
5. **「只把必要的搞進來」**：第一批＝入口夾、`agent` 與 `daemon_ctl` 兩個代理、把手、接上斷點與讀檔；明講不做＝起樹與抄樹、寫定義與 `aos.gdb` 搬家、`aos-tools`／`aos-mailbox` 與其餘十幾支指令的模組、腦的工具、在庫裡拆 TSV、在庫裡展開工具包、執行中加的東西自動寫回 `agent.py`；之後「有人第二次遇到才加」，缺的優先加在指令上（Python 與將來的 Lisp 一起有）。工具包：寫定義時 `std.pack(…)` 寫進定義、執行時 `a.tools.add(路徑)` 寫進 stack；整包塞給活的那隻，要時做成 `aos-agent tools add --pack`。
6. **分三刀**：第零刀修 `install.py` 只加不刪（今天 `lib/` 就落後 `py/`）；第一刀新增 `py/aos/py/` 四個檔＋一支不起 daemon 的測試、現有檔不改、可丟；第二刀把手接 `a.bp`（`aosgdb-api-1119` 已交；建斷點的寫法已裁成 `a.bp.add.<事件>(…)`，第二刀順手改，見 [07](07-使用者裁定.md)）。開工要使用者說（鐵律 2）。
7. **五題使用者 11-19 已用選項框裁了四題**（[07](07-使用者裁定.md)，題目在 [05](05-邊緣狀況與要拍板的題.md)）：入口叫 `aos.py`、「是哪一隻」用把手式、建斷點寫成 **`a.bp.add.before_tool("x")`**（回 id；已交的字串式 `a.bp.add("before_tool", tool="x")` 不留、第二刀改，觀察者與自訂事件怎麼寫留給施工線）、讀檔收進 `a.look`；隨手 `python3` 那題沒單獨問，暫照推薦「只靠入口」、可再改。三刀都還沒開工，等使用者說。
8. **Argon 審過**（[06](06-Argon審與採納.md)）：十點審查、四點提案，大多採納。最要緊的兩條：原稿「整包加工具在代理裡展開」自己破了薄殼規則、會加到一半失敗——拿掉；原稿四刀要把今天剛交的寫定義和正在改的 `aos.gdb` 都搬家，跟「只把必要的搞進來」相反——改成都不搬。也抓到原稿替使用者定了斷點寫法，改成問。
