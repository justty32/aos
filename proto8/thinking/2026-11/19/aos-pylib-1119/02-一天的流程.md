# 使用者的一天，逐步對照「今天打什麼／理想上在 Python 打什麼／第一批進不進」——結論：必要的只有四樣，其餘靠一個「通用代理」自動就有

← [README](README.md)｜上一份：[01-現況盤點](01-現況盤點.md)｜下一份：[03-版面設計](03-版面設計.md)

線 `aos-pylib-1119` 設計稿（fable）。只是設計，沒有任何一行寫成程式跑過；「今天打什麼」照 [01](01-現況盤點.md) 與 `templates/start-api/README.md`，「理想上」用 [03](03-版面設計.md) 推薦的走向甲；隊長照 Argon 審改過第 2、9、15、18 步與結論（[06](06-Argon審與採納.md)）。

## 先講結論

1. 一天裡真的需要在 Python 裡做的事只有四樣：**找得到套件**（現在一般 `python3` 連 `import aos` 都不行）、**對一隻活的 agent 下指令**（說話、看、起停、加工具、加 hook）、**斷點**（今天已經有，搬個位置）、**讀它 stack 裡的檔**（今天已經有）。
2. 「對活的 agent 下指令」不用一支一支包。做一個**通用代理**（一個小零件，把 `a.tools.add("x")` 這種寫法照固定規則翻成 `aos-agent … tools add x` 去跑；像電話總機，你報分機它幫你轉，不必每個分機各請一個接線生），`aos-agent`、`aos-daemon-ctl` 現有與以後新增的子指令就全部自動有 Python 寫法。這就是「只把必要的搞進來」又不漏東西的做法。
3. **起樹、抄樹留在 shell**：那兩步是前景行程（佔住一個視窗、Ctrl-C 就整棵停），搬進 Python 等於要在 REPL 裡管背景行程的生死，不是薄殼做得了的事，也不是每天卡住你的地方。
4. 寫定義那邊（`ag`、`std`）功能今天都有，不動它、不搬檔，入口轉匯出就好。

## 逐步對照

假設樹在 `~/t1`，人站在樹根（`aos-agent`、`aos-daemon-ctl` 沒給 `-d` 時會用 `$AOS_DAEMON`，再沒有就用 `./.stack`，所以站在樹根可以省掉 `-d .stack`；下表「今天」那欄照 README 的寫法把它寫出來）。

| # | 這一步 | 今天要打什麼（shell） | 理想上在 Python 打什麼 | 第一批？ | 理由 |
|---|---|---|---|---|---|
| 1 | 抄一棵樹 | `cp -r $AOS_HOME/templates/start-api ~/t1`、`cd ~/t1 && source env.sh` | 不做；真要在 REPL 裡打就 `sh("cp -r …")` | 不進 | 一棵樹抄一次，不是每天的事；`source env.sh` 本來就得在 shell 做 |
| 2 | 寫粗定義 | `mkdir agents/bob`、抄 `templates/agent-python/agent.py` 進去改（開頭 `from aos import agent_spec as ag`、`std = ag.std`） | 同一支檔；入口轉匯出後也能寫 `from aos.py import ag, std`，今天的寫法照樣能用 | 不進（寫定義不搬） | 功能今天就有；骨架今天才交，先別動它 |
| 3 | 生成 | `python3 agents/bob/agent.py --write-defs` | 照舊在 shell 打；在 REPL 裡是 `sh("python3 agents/bob/agent.py --write-defs")`。不想先存檔的粗定義：`ag.write_defs("agents/bob", ag.defs(DESC, SYSTEM, [std.pack("look")], {}, std.fsm()))`（這兩個函式今天就有） | 不進（已經有） | 「C 與 .o」：編譯是一個明講的動作，不包進別的東西裡 |
| 4 | 起樹 | 視窗 A `aos-exec root`；視窗 B `cd llms && aos-exec --stack stacks/llm def`（都是前景） | 不做，留在 shell 的兩個視窗 | **明講不做** | 前景行程；見結論 3 |
| 5 | 掛 agent | `aos-agent -d .stack ctl add --auto-restart -w . agents/bob` | `agent.ctl.add("agents/bob", w=".", auto_restart=True)` | **進**（代理自動有） | 今天 Python 完全沒路（gdb 要先有一隻才接得上）；掛、試、拿掉、再掛是一天裡反覆做的事 |
| 6 | 進 REPL | `aos-gdb -d .stack bob` | 同一條指令；進去後已經放好 `agent`、`daemon_ctl`、`ag`、`std`、`sh`，以及 `a = agent.attach("bob")`、`bp = a.bp` | **進** | 這是「python repl + shell」的門；也順便解決「一般 python3 找不到套件」 |
| 7 | 看表上有誰 | `aos-daemon-ctl -d .stack ls` 或 `aos-agent -d .stack ctl ls` | `daemon_ctl.ls()`、`agent.ctl.ls()`（要結構就 `json=True`，回解好的 list） | **進**（代理自動有） | 每次起停後都會看 |
| 8 | 說話、看回話 | `aos-agent -d .stack --target bob say hello`、`… listen --timeout-s 20` | `a.say("hello")`（回那封信的名字）、`a.listen(timeout_s=20)`；一口氣問完等答：`a.ask("hello")` | **進**（`say`、`listen` 手寫，其餘代理） | `say` 要回信名給 `listen(letter=…)` 用，所以這兩支值得手寫 |
| 9 | 下斷點 | 沒有指令 | `b = a.bp.add("before_tool", tool="write")` → 回 `"before_tool_1"`（寫法待拍板，05 第 4 題） | **進**（已有，把手接上） | 今天的重點 |
| 10 | 等它停下來 | 沒有 | `a.bp.wait_stopped()`（等到它停在斷點或逾時；Ctrl-C 只是不等了，agent 不受影響） | **進**（已有；建議 `aosgdb-api-1119` 改短名 `wait`） | 不等的話下一句 `why()` 會撲空 |
| 11 | 看停在哪、發生了什麼 | `aos-agent ctl state`、自己 `cat .stack/procs/bob/…` | `a.bp.why()`、`a.look.where()`、`a.look.history(3)`、`a.look.observed()`、`a.ctl.state(json=True)` | **進**（已有；讀檔的收進 `a.look`） | 停下來就是為了看 |
| 12 | 續、跳過 | `aos-agent ctl resume`（只能續，不能跳過） | `a.bp.resume()`（不收參數）、`a.bp.skip()` | **進**（已有） | — |
| 13 | 查、改、拿掉斷點 | 沒有 | `a.bp.ls()`、`a.bp.get(b)`、`a.bp.set(b, enabled=False)`、`a.bp.rm(b)`、`a.bp.clear()` | **進**（已有） | 增刪改查，以 id 為準 |
| 14 | 執行中加一支工具 | `aos-agent -d .stack tools add --target bob lib/my/tools/grep` | `a.tools.add("lib/my/tools/grep")`；看：`a.tools.ls()` | **進**（代理自動有） | 使用者說的「執行途中給它加東西」 |
| 15 | 執行中整包加工具 | 沒有專門的指令 | 不在庫裡展開包；真要時給指令加 `aos-agent tools add --pack json`，代理就自動有 `a.tools.add(pack="json")` | 不進（第二次遇到再加在指令上） | 庫裡展開會加到一半失敗、又要懂寫定義的格式（Argon A6）；第一批先用第 14 步逐支加 |
| 16 | 執行中加 hook | `aos-agent -d .stack hook add --target bob --event after_tool …` | `a.hook.add(event="after_tool", …)`、`a.hook.ls()` | **進**（代理自動有） | 同 14 |
| 17 | 換 system、換腦 | `aos-agent system set FILE`、`aos-agent llm set model=luna` | `a.system.set("new.txt")`、`a.llm.set("model=luna")` | **進**（代理自動有） | 不常用，但不花成本 |
| 18 | 停、起、睡、醒、拿掉 | `aos-agent ctl stop／start／sleep／wake／rm bob` | `a.ctl.stop()`、`a.ctl.start()`…；拿掉用 `agent.ctl.rm("bob")`（`ctl rm` 不吃 `--target`） | **進**（代理自動有） | 改完定義要重掛時用 |
| 19 | 試好的東西留下來 | 手改 `agent.py`、重跑第 3 步 | 同左 | 不做 | 執行中加的東西寫在 stack 的疊層（活的那隻自己那份），定義不知道；要留就抄回 `agent.py`。這是「C 與 .o」，不自動 |
| 20 | 寄信、讀信 | `aos-mailbox send／peek／read` | 第一批先 `sh("aos-mailbox peek")`；第二次遇到再加 `mailbox` 模組（兩行），之後是 `mailbox.peek(json=True)` | 不進 | 一天裡用 `say`／`listen` 就夠 |
| 21 | 收工 | `aos-daemon-ctl -d .stack shutdown`、`aos-daemon-ctl -d llms/stacks/llm shutdown` | `a.bp.clear()`（斷點不清會留在 agent 身上）、`daemon_ctl.shutdown()`、`daemon_ctl.shutdown(daemon="llms/stacks/llm")`，再 Ctrl-D | **進**（代理自動有） | 每天都做 |

## 照這張表，「必要的」是哪些

**第一批（四樣）：**

1. **門**：`aos.py` 這個夾（給人用的 Python 入口）＋ `aos-gdb` 進去時把名字放好。解決「找不到套件」。
2. **通用代理**：`agent`（＝`aos-agent`）、`daemon_ctl`（＝`aos-daemon-ctl`）兩支。`tools`（＝`aos-tools`）、`mailbox`（＝`aos-mailbox`）同一個零件多寫兩行就有，但不預做，第二次遇到再加（Argon A10）。
3. **一隻 agent 的把手** `a = agent.attach("bob")`：把「哪台 daemon、哪一隻」記住，之後不用每句再講；`say`、`listen` 手寫（回傳要整形），其他全走代理。
4. **斷點 `a.bp` 與讀檔 `a.look`**：今天 `aos.gdb` 已經有的東西，檔不搬，把手接上它。

**明講不做：** 起樹與抄樹（第 1、4 步）、把執行中加的東西自動寫回 `agent.py`（第 19 步）、其餘十幾支指令（`aos-share`、`aos-sandbox`、`aos-clock-register`、`aos-comm`、`aos-feedback`、`aos-grow`、`aos-mcp-import`、`aos-json`、`aos-llm`…）的專門包裝——哪天在 REPL 裡真的用到，先用 `sh("…")` 打，第二次再照 [03](03-版面設計.md) 的規則加兩行。

**之後（等用過再說）：** 整包加工具（第 15 步，加在指令上）、`tools`／`mailbox` 模組、指令沒有 json 輸出的補上。寫定義那邊不搬（第 2 步）。
