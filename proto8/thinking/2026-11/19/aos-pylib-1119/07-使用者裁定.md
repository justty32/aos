## 第 2 題：「是哪一隻」怎麼講——裁：甲 把手式

- 選項框題目：「在 Python 裡「對哪一隻 agent 下指令」要怎麼講？」
- 使用者選：「把手式 (Recommended)」（`a = agent.attach("ann")`）
- 落到哪：照 [03 第二節](03-版面設計.md#二三種走向方向題-2)走向甲；「目前這隻」（乙）不做，之後要再加不會弄壞東西。

## 第 3 題：建斷點的寫法——裁：`a.bp.add.before_tool("x")`

- 選項框題目：「建斷點的寫法要哪一種？（這題線沒有推薦）」
- 使用者選：「a.bp.add.before_tool("x")」
- 選項說明：「按 tab 補得出有哪些事件，打錯當場知道。add 同時是動作又是一組名字。」
- **跟稿不同的地方**：05 這題的 b 原寫 `a.bp.stop.before_tool()`；頂層問的時候 b 改寫成 `a.bp.add.before_tool("x")`，使用者選的是這個。「兩種都留」沒選，所以字串式 `a.bp.add("before_tool", tool="x")` 不留。
- 結論：**建斷點＝`a.bp.add.<事件>(...)`，回 id 字串**；`a.bp.stop()` 照舊只是「現在就停」，`stop` 不再兼當分組，C-54 那處拉扯（05 第三節第 4 列）就沒了。
- 要改的程式：`aosgdb-api-1119` 已交（`822ee9228`）的 `a.bp.add("before_tool", tool="x")` 要改成新寫法，連同它的 README、知識庫 `cli/gdb.json`、測試；併進第二刀（把手接 `a.bp`）做。
- **待定細節，留給施工線定**：觀察者與自訂事件在這種寫法下怎麼寫（例如 `a.bp.add.watch(...)`、`a.bp.add.on("事件", ...)`）；`tool=` 是不是改成第一個位置參數（選項例子寫 `before_tool("x")`）；shell 提案（`aos-gdb bp add …`）跟著怎麼對。
- 已記在 [aos-gdb-lib-第二版](../aos-gdb-lib-第二版.md) 末節「暫定、待使用者挑的」。`skip`、`wait_stopped` 兩個名字仍是暫定。

## 第 4 題：隨手開的 `python3` 要不要 import 得到——暫照推薦 a，使用者未單獨裁

- 這題**沒有單獨問**。頂層跟使用者講的是：「建議照推薦『只靠入口』，因為另一種做法跟你 11-15 的一條裁定方向相反」。
- 所以記成：暫照推薦 a（只靠 `aos-gdb` 與腳本自帶的開頭，不動 `env.sh`），使用者未單獨裁、可再改。

## 第 5 題：讀 stack 檔的收不收進 `a.look`——裁：a 收進
