# 現況盤點：寫定義（ag）、除錯（aos.gdb）、其他 Python 模組、29 支指令——每個動作今天有沒有 Python 入口、三塊哪裡不一致

11-19 下午唯讀盤點（三隻 opus 蒐集，隊長匯總）。路徑都從 `proto8/` 算。`aos.gdb` 的介面當時另一條線 `aosgdb-api-1119` 正在改：下面「gdb 新版」指它工作樹裡那份（`a.xxx`＝`aos-agent xxx`、斷點全收在 `a.bp`）。本稿收尾時它已交（`822ee9228`），README、知識庫 `cli/gdb.json`、測試都跟上了；第 4 節第 10 點的小洞沒逐條核它修了沒。

## 1. 三塊各長什麼樣

| | 寫定義 | 除錯 | 其他 |
|---|---|---|---|
| 進口 | `from aos import agent_spec as ag`（`templates/agent-python/agent.py:12`） | `import aos.gdb as g`；`aos-gdb NAME` 開 REPL，預先放好 `g`、`a = g.attach(NAME)` | `aos.daemon_ctl`、`aos.ws`、`aos.clock_register`… 只有零星函式 |
| 找得到 `aos` 套件的方式 | agent.py 開頭自己把 `$AOS_HOME/lib` 插上 `sys.path`（`agent.py:6-10`） | `bin/aos-gdb` 用自己 realpath 的 `../lib`（`install.py:152-157`）；一般 python3 要自己插 | `env.sh` **不設** PYTHONPATH（只動 PATH）；使用者 11-15 裁過不寫 `.pth` |
| 風格 | 模組層純函式，回帶 `kind` 的小 dict（`{"kind":"tool",…}`）；`std`、`ag.lib(...)` 是物件 | 物件式：`a = g.attach(名)`，`a.bp` 子物件 | 大多是指令本體（`apps/*` 的 `cmd(argv)` 會 print、raise） |
| 要不要活樹 | **不要**：只要 `AOS_HOME`（`std.pack` 宣告當下就讀 `$AOS_HOME/lib/packs/`） | **要**：daemon（`daemon=` 或 `$AOS_DAEMON`）、PATH 上的 `aos-agent` | 看模組 |
| 背後 | 自己算、自己寫檔；唯一入口 `python3 agent.py --write-defs [夾]` | 薄殼：每個動作 shell 出去叫 `aos-agent …`／`aos-daemon-ctl …`，或直接讀寫 stack 的檔；預設先印 `$ 那條指令` | — |
| 錯誤 | 宣告時不丟，記成 `{"kind":"bad"}`，到 `defs()` 才丟 `SpecBad`；`main` 轉成一行 `名: error: Code reason` 退 1 | 一律 `Failed(RuntimeError)`，字串是一行英文；`wait_stopped` 逾時丟 `TimeoutError` | `flags.Error`、`tool_io.Error`、`ws.Error`、`daemon_ctl.Fail`、`apps.agent.common.Fail`… 各一套 |
| 回傳 | tagged dict；`write_defs` 回 `["wrote …"]` | `Text`（str 子類、repr 不加引號）、dict、list、id 字串混用 | 各自 |

**寫定義的公開名字**（`agent_spec.py`、`agent_spec_lib.py`）：`ag.home`、`ag.env`、`ag.tool`、`ag.no`、`ag.by_hand`、`ag.state`、`ag.fsm`、`ag.std`（`std.pack/tool/fsm/hooks`）、`ag.lib(名, 根)`（`.pack/.tool`，工具自動帶 `名_`）、`ag.defs`、`ag.write_defs`、`ag.main`；大寫的 `DESCRIPTION`、`TOOLS`、`FSM`… 只是慣例，靠 `main` 的參數傳。

**除錯的公開名字（gdb 新版）**：`g.attach`、`g.echo`、`g.sh`、`g.run`、`g.Failed`；`a.agent(*args)`（任意 `aos-agent` 子指令）、`a.say`、`a.listen`、`a.ctl(*args)`、`a.state`、讀 stack 的 `a.where/history/observed/request/queue/stderr/file/path`；`a.bp.add(on, tool=, sh=, py=, times=, once=, …)`→id 字串、`rm`、`set`、`ls`、`get`、`clear`、`stop`、`resume()`（不收參數）、`skip`、`held`、`stopped`、`wait_stopped`、`why`、`notes`。HEAD 版的 `a.stop_before_tool`、`a.resume(skip=)`、`a.wait_paused`、`g.watch/watchers/unwatch` 新版全拿掉了。

## 2. 命令行（29 支）裡跟「人在 Python 想做的事」有關的

C++ 9 支（`aos-exec`、`aos-loop`、`aos-fsm`、`aos-daemon`、`aos-directive`、`aos-json`、`aos-lock`、`aos-llm`、`aos-post`）多半是底層；Python 20 支是 `bin/` 裡 6 行入口跑 `aos.apps.<x>.main`。

| 指令 | 子指令 | 輸出 |
|---|---|---|
| `aos-agent` | `ctl`（add／rm／set-def／start／stop／sleep／wake／pause／resume／ls／state／where／who）、`say`、`listen`、`ask`、`chat`、`open`／`close`／`watch`／`peek`（畫面）、`tools`、`llm`、`hook`（ls／get／add／rm／reset）、`system`（get／set／reset）、`history`（ls／rm／summarize／set）、`goal` | TSV 為主，部分 `-j` |
| `aos-daemon-ctl` | add／rm／prune／stop／start／sleep／wake／pause／resume／ls／where／poke／ping／shutdown／sweep | TSV，`ls -j` |
| `aos-tools` | add／rm／ls／get／call／override | `get` 每支一行 JSON，`ls` TSV |
| `aos-mailbox` | where／peek／read／send | TSV，`-j` |
| `aos-exec` | 沒有子指令：`aos-exec [--ws][--stack] XXX`；**起樹就是 `aos-exec root`（前景）** | 被叫的程式自己的 |
| `aos-gdb` | 沒有子指令：`aos-gdb NAME` 開 REPL | — |
| 其他人打的 | `aos-share`（ACL）、`aos-clock-register`、`aos-comm`、`aos-feedback`、`aos-grow`、`aos-json`、`aos-json-view`、`aos-llm`、`aos-mcp-import`、`aos-asuser`、`aos-sandbox` | 各自 |

`agent_def`（new／check／tools／llm／system）、`tools_def` 不在 `bin/`，是**腦的工具**（`py/tools/agent/`）；`--write-defs` 是 `agent.py` 的旗標，不是 `agent_def` 的。

## 3. 每個動作今天有沒有 Python 入口

| 動作 | 今天打什麼（shell） | 今天的 Python 入口 |
|---|---|---|
| 寫定義、生成 | 寫 `agent.py`、`python3 agent.py --write-defs` | `ag.*`（庫）；生成只有 `ag.main`（會 `sys.exit`）或 `ag.defs`＋`ag.write_defs` |
| 抄一棵樹 | `cp -r $AOS_HOME/templates/start-api ~/樹` | 沒有 |
| 起樹（根、llm kernel） | 兩個視窗各跑 `aos-exec root`、`aos-exec --stack stacks/llm def`（前景） | 沒有 |
| 收樹 | `aos-daemon-ctl -d .stack shutdown`（llm kernel 另一句） | `daemon_ctl.shutdown(d)`（內部庫） |
| 列 agent | `aos-agent ctl ls`／`aos-daemon-ctl ls` | `daemon_ctl.rows(d)`（內部庫） |
| 掛 agent | `aos-agent -d .stack ctl add -w . agents/ann` | 沒有（`a.ctl("add",…)` 也不行：gdb 要先有一隻才能 attach） |
| 起停睡醒、拿掉 | `aos-agent ctl start/stop/sleep/wake/rm` | `a.ctl(...)`（gdb 新版，薄殼） |
| 說話、看回話 | `aos-agent say`、`listen`、`ask` | `a.say`、`a.listen`（`ask`、`chat` 沒有） |
| 看狀態 | `aos-agent ctl state` | `a.state()`、`a.where()` 等讀檔 |
| 下／看／拿斷點、續 | 沒有指令（斷點只在庫裡） | `a.bp.*` |
| 執行中加工具 | `aos-agent tools add`（寫 stack 的登記檔，定義不動） | 只有 `a.agent("tools","add",…)` 這種通用殼 |
| 執行中整包加工具 | 沒有專門的；只能 `aos-tools override` 或 `ctl set-def --kit` 整份蓋 | 沒有 |
| 執行中加 hook | `aos-agent hook add` | 只有通用殼（`a.bp` 內部也走這條） |
| 換 system、腦 | `aos-agent system set`、`llm set` | 只有通用殼 |
| 寄信、讀信 | `aos-mailbox send/read/peek` | 沒有 |

## 4. 三塊之間不一致的地方

1. **`aos` 套件今天要自己插 `sys.path` 才 import 得到**：agent.py 一套、`bin/` 入口一套、工具一套（沿 realpath 往上找）、範本格一套（`$AOS_HOME/lib`）；人在一般 `python3` 裡沒有現成的路。
2. **裝好的 `lib/` 會落後 `py/`**：盤點當下 `lib/aos/` 沒有 `agent_spec_lib.py`，骨架照 `$AOS_HOME/lib` 跑會 `ModuleNotFoundError` traceback（不是那行友善錯誤）；`install.py` 的 `copytree(dirs_exist_ok=True)` 只加不刪。測試走 `py/`，所以測試綠不代表裝好的能用。
3. **三種風格**：寫定義＝函式＋tagged dict、延遲報錯；gdb＝物件、當場丟 `Failed`、預設印指令；內部庫＝各自。
4. **例外六七套**：`SpecBad`、`DefBad(ValueError)`、`Failed(RuntimeError)`、`trigger.Bad(ValueError)`、`flags.Error`、`daemon_ctl.Fail`…
5. **同字不同意思**：`ag.state(名, argv, next)` 是 fsm 的格、`a.state()` 是 `ctl state`；`ag.tool` 宣告工具、`a.bp.add(tool=)` 是篩選工具名；「hook」在定義裡（`std.hooks`、hooks.json）和 stack 疊層（`aos-agent hook add`）各一個；「包」一詞三義（工具包 `py/packs`、mcp-import 凍結包、llm endpoint 包）；`lib` 三處（`ag.lib`、`$AOS_HOME/lib`、`aos.agentlib`）；`watch`（`aos-agent watch` 看畫面、`a.bp.add("watch")` 觀察者）。
6. **`a.xxx`＝`aos-agent xxx` 沒有完全成立**：`a.history(n)`、`a.where()` 是直接讀檔，名字跟 `aos-agent history`（ls／rm／summarize／set）、`ctl where` 撞但不同；`tools`、`llm`、`hook`、`system`、`goal` 在 `a` 上沒有方法；`a.state` 其實是 `ctl state` 不是頂層。
7. **同一動作兩條指令**：`aos-agent ctl` 跟 `aos-daemon-ctl` 都有 add／rm／start／stop…（前者經 kernel、有 `--purge`；後者直接寄）。
8. **指令輸出格式不一**：TSV 為主、`-j` 是選項；C++ 的 see／show／get 預設 JSON；指定對象有 `-t`、位置參數、`-s STACK`、`--kernel` 幾種。Python 薄殼若要「回傳解好的 json」，有些指令今天沒有 json 輸出可解。
9. **`ag.main` 在模組層呼叫且 `sys.exit`**：一支 agent.py 不能被另一支 import 來衍生（繼承那條想的 `from base_agent import TOOLS`），除非加 `if __name__ == "__main__"`。
10. **gdb 新版本身的小洞**（交給 aosgdb-api-1119，這裡只記會影響版面的）：斷點 id 刪了會重用；在 REPL 打 `a.bp` 就會跑外部指令（`__repr__` 走 `ls`）；觀察者 id 以 daemon 為範圍、觸發器以 agent 為範圍；`a.bp.stop.before_tool()` 這種寫法沒照使用者的例子做，現在是 `a.bp.add("before_tool")`。

## 5. 名字相關的事實

- `py/` 底下只有 `aos` 一個頂層套件；proto8 裡沒有 `aos.py` 檔、也沒有 `aos/py.py`。名叫 `py` 的資料夾只有原始碼夾 `proto8/py/` 本身。
- `aos.json` 已是 aos 的模組（腦的 json 工具共用碼），跟標準庫 `json` 同名，`from aos import json` 易混。
- `breakpoint` 是 Python 內建函式；`from … import breakpoint` 合法但會遮住內建。
- 若有人把 `lib/tools` 放上 `sys.path`，`lib/tools/aos/`（工具夾）會變成 namespace 套件搶名；今天沒人這樣做。
