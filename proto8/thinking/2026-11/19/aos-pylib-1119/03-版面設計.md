線 `aos-pylib-1119` 設計稿（fable 寫、隊長照 Argon 審改過，改了哪些逐條在 [06](06-Argon審與採納.md)：寫定義與 `aos.gdb` 都不搬、整包加工具從庫裡拿掉、`tools`／`mailbox` 不預做、分刀改成第零～二刀）。只設計；裡面的函式名、檔名都還沒寫成程式。事實來源是 [01](01-現況盤點.md) 與實讀 `py/aos/gdb/`、`py/aos/agent_spec*.py`、`py/aos/apps/agent/` 各支的 usage、`install.py`、`env.sh`。標「方向題」的由使用者拍板，題目在 [05](05-邊緣狀況與要拍板的題.md)。

## 先講結論

1. **入口是一個夾 `py/aos/py/`，import 寫 `from aos.py import …`**（照你的原話；方向題 1）。規矩只有一句：**這個夾裡的＝給人用的，夾外的 `aos.*`＝內部零件**。「哪些算公開」從此看資料夾就知道，跟命名空間 B「資料夾即命名空間」同一個想法。
2. **推薦走向甲「把手式」**：`a = agent.attach("ann")` 拿到一個把手（記住「哪台 daemon、哪一隻」的小物件，像電視遙控器先對好哪一台），之後 `a.say(…)`、`a.ctl.stop()`、`a.tools.add(…)`、`a.bp.resume()`。沒有藏起來的「目前這隻」。
3. **一條通則，而且是程式不是文件**：`aos-agent -d D --target N X Y --flag v ARG` ↔ `a.X.Y(ARG, flag=v)`。用一個四十行左右的**通用代理**實作，所以 `aos-agent`、`aos-daemon-ctl` 現有與以後新增的子指令**自動**有 Python 寫法，不用一支一支包、以後加指令不用再想 Python 那邊；別的指令（`aos-tools`、`aos-mailbox`…）要時加兩行就有，第二次遇到才加。
4. **三類東西分清楚**：編譯器（`ag`、`std`：寫定義，不需要活樹；**原地不搬**，入口只轉匯出）、薄殼（上面那些：一個呼叫＝一條指令）、延伸（`a.bp` 斷點、`a.look` 讀 stack 的檔：只在庫裡、沒有對應指令；**`aos.gdb` 原地不搬**，把手接它）。`a` 底下的名字，是 `aos-agent` 的子指令名就是薄殼，不是的只准是 `bp`、`look` 這兩個，其他名字當場報錯。
5. **最小第一刀只新增幾個檔、不改任何現有檔**：入口夾＋通用代理＋把手。之前先有一個第零刀修 `install.py`「只加不刪」，第一刀才真的「刪夾就還原」。`a.bp` 接上斷點是第二刀（`aosgdb-api-1119` 已交 `822ee9228`，剩等「建斷點的寫法」那題）。
6. 跟既有原則有六處衝突或拉扯（[05](05-邊緣狀況與要拍板的題.md) 末節），最要緊的四處：「斷點＝`aos-agent breakpoint`」的直覺對上「解耦合」、`.pth` 的舊裁定對上「一般 python3 也要 import 得到」、`aos.py` 這個名字對上 C-54、藏一個「目前這隻」對上 C-56。

## 一、入口叫什麼（方向題 1）

### `aos.py` 這個名字的實際狀況

做得到：`aos` 已經是套件，在裡面開一個子套件 `py/aos/py/__init__.py`，`from aos.py import agent` 就是合法 Python，不用任何花招。要照實講的毛病：

| 毛病 | 多嚴重 |
|---|---|
| **看起來像檔名**。文件裡寫「`aos.py`」，讀的人（與 AI）第一眼會當成一支叫 aos.py 的檔；我們已經有 `agent.py`、`tool.py`、`install.py` 都是真的檔 | 中。靠寫法壓住：文件一律寫成 import 句（`from aos.py import …`）或「`aos.py` 套件」 |
| **原始碼路徑變成 `proto8/py/aos/py/`**，兩個 `py` 意思不同（外面那個是「Python 原始碼夾」，裡面那個是「給人用的入口」） | 小，但 code map 與口頭溝通會繞 |
| **誰在工作夾裡存了一支真的 `aos.py`**（名字很順手），在那個夾開 `python3`，`import aos` 會抓到那支檔而不是套件，錯誤訊息是看不懂的 `'aos' is not a package` | 小但真的會發生；入口名取成 `aos.py` 等於在引誘人取這個檔名 |
| 名字把「Python」寫死。將來 Lisp 那邊會是另一個入口，不衝突 | 不是問題 |
| `from aos.py import a` 的 `a` 要是什麼，見第二節（走向甲裡它不存在） | 屬於走向的題 |

### 三個候選

| 候選 | 使用者打的 | 後果 |
|---|---|---|
| **① `aos.py`（推薦，你的原話）** | `from aos.py import agent, ag, std` | 上表的毛病；好處是「資料夾＝邊界」、一看就知道是「aos 的 Python 這一面」 |
| ② `aos` 本身 | `import aos`、`aos.agent.attach("ann")` | 最像一般 Python 庫，也沒有 `.py` 像檔名的毛病。但 `aos/` 底下已有三十幾支內部模組（`aos.json`、`aos.ws`、`aos.flags`…）跟公開的名字混在同一層，而且 `aos.agent` 這種名字要跟內部的 `aos.agentlib`、`aos.apps.agent` 並排。哪些算公開只能靠文件講。（Argon 指出：開了 `aos/py/` 夾，內部模組照樣 import 得到，所以 ① 的邊界其實也只是約定——差別只在「約定寫在夾名上」還是「寫在文件裡」，不是真的封住） |
| ③ 另一個短名的子套件 | `from aos.repl import …`、`aos.cmd`、`aos.api` 之類 | 結構同 ①、只換名。我試過的名字各自撞到現有的詞：`api`＝「API 版的腦」（`start-api`）、`user`＝使用者專區、`cmd`＝11-18 才收掉的舊夾名、`repl` 太窄（腳本也會用）。沒找到比 `aos.py` 明顯好的 |

推薦 ①。換名的代價是改一個夾名加幾十行 import，proto8 不留別名，所以**先照 ① 走、用了不順再換**是便宜的。

### `breakpoint` 這個名字

`breakpoint` 是 Python 內建函式（叫它會進 pdb）。模組檔叫 `aos/py/breakpoint/` **本身不遮任何東西**；遮的是「把它用原名 import 進來」那一刻：`from aos.py import breakpoint` 之後，同一個檔裡的 `breakpoint()` 就不是內建的了。你的例子本來就寫 `as bp`，所以：**模組叫 `breakpoint`，文件與 REPL 一律 `as bp`，平常用 `a.bp`**。`bp`、`ag` 兩個縮寫照 C-54 要進縮寫表 `docs/CONCEPTS/abbr.json`（今天表裡都沒有）。

## 二、三種走向（方向題 2）

三個走向底下的零件有九成一樣（都要通用代理、都要斷點庫），差在**使用者手上拿的是什麼**。

### 甲、把手式（推薦）

手上拿的是「把手」：`agent.attach("ann")` 回一個記住 daemon 與名字的物件。模組本身也能直接叫（沒對好哪一隻時用，例如掛新的、列全部）。

```python
# ── agents/ann/agent.py（寫定義；不需要活樹）──
from aos.py import ag, std                      # 入口轉匯出；今天的 from aos import agent_spec as ag 照樣能用（寫定義不搬）
DESCRIPTION = "Look things up and answer by mail."
SYSTEM = "You are ..."
TOOLS = [std.pack("look"), std.pack("mailbox")]
LLM = {"model": "fake"}
FSM = std.fsm()
if __name__ == "__main__":                       # 見第七節「繼承的接點」
    ag.main(DESCRIPTION, SYSTEM, TOOLS, LLM, FSM)
```

```
$ python3 agents/ann/agent.py --write-defs        # 生成（shell）
$ aos-gdb ann                                     # 進 REPL；下面的名字都已放好
```

```python
>>> agent.ctl.ls()                               # $ aos-agent ctl ls
>>> agent.ctl.add("agents/bob", w=".", auto_restart=True)   # 掛另一隻
>>> a                                            # <aos-agent --daemon /home/u/t1/.stack --target ann>（只印，不跑指令）
>>> a.say("hello")                               # $ aos-agent … say --target ann hello   回信名
>>> b = a.bp.add.before_tool("write")           # 回 "before_tool_1"（寫法依 07 第 3 題裁定）
>>> a.say("write a note"); a.bp.wait_stopped()   # 等到它停在斷點（名字歸 aosgdb-api-1119；建議短名 wait）
>>> a.bp.why(); a.look.history(3); a.ctl.state(json=True)
>>> a.tools.add("lib/my/tools/grep")             # 執行中加工具：$ aos-agent … tools add --target ann lib/my/tools/grep
>>> a.hook.ls()
>>> a.bp.resume()                                # 不收參數
>>> a.bp.rm(b); a.bp.ls()
>>> b2 = agent.attach("bob")                     # 第二隻，各拿各的把手，互不干擾
>>> daemon_ctl.shutdown()                        # $ aos-daemon-ctl shutdown
```

你的三句 import 在甲裡是：`from aos.py import agent`（再 `a = agent.attach("ann")`）、`from aos.py import breakpoint as bp`（`bp.attach("ann")` 回的東西跟 `a.bp` 是同一種）、`a.bp`。**第一句 `from aos.py import a` 在甲不成立**——`a` 是「某一隻」，import 那一刻還不知道是哪一隻；REPL 用 `aos-gdb ann` 進去時 `a` 已經替你放好，所以實際上很少要自己打那一行。

- 優點：沒有藏起來的狀態，畫面上寫 `a.say` 就是對 `a` 那一隻；兩隻 agent、兩棵樹同時操作不會打錯對象；腳本安全。
- 缺點：不在 REPL 預放名字的地方（自己寫的腳本）要多一行 `attach`。

### 乙、「目前這隻」式（最貼你那三句 import 的字面）

`a` 就是 `aos.py.agent` 這個模組的短名，模組裡記一個「目前這隻」；真的 gdb 也是這樣（它有「目前的行程」）。

```python
from aos.py import a, bp          # bp 就是 a.bp
a.use("ann")                      # 之後都是對 ann
a.say("hello")
b = bp.add.before_tool("write")   # 依 07 第 3 題（原寫 bp.stop.before_tool）
bp.wait(); bp.why(); bp.resume()
a.use("bob")                      # 換一隻
```

- 優點：你寫的三句 import 原樣成立；打字最少；對應到 Lisp 很自然（Lisp 有「動態變數」，就是這種「目前的某某」）。
- 缺點：`a.say(…)` 對的是誰，要看前面最後一次 `a.use` 在哪——畫面上那一行看不出來。同時顧兩隻 agent 要一直切；切錯了是把話說給另一隻、把另一隻停住，不會報錯。這正是 C-56 補充說的「埋雷」那一型（規則藏在看不見的值裡）。
- 跟甲的關係：**乙＝甲＋一個「目前這隻」的預設值**。先做甲，之後要乙只是加一個 `agent.use()`，不破壞任何寫好的東西；先做乙、之後想拿掉則會弄壞腳本。

### 丙、兩個世界各一個入口

寫定義的留在原地（`from aos import agent_spec as ag`，今天剛交的骨架一行不動），只替「活的那一邊」開 `aos.py`。理由是「C 與 .o」：編譯器（gcc）與除錯器（gdb）本來就是兩個工具。

- 優點：動得最少；骨架、庚的測試、繼承那條線都不受影響。
- 缺點：你要的是「整套一起規劃」；例外類別、import 路徑還是兩套。
- **Argon 審後採的是「甲＋丙的一半」**：活的那一邊用甲的把手；寫定義那邊檔案不搬（丙），但入口 `__init__` 多兩行轉匯出，`from aos.py import ag, std` 照樣成立，今天的 `agent.py` 一行不用改。第 2 題因此只問「是哪一隻」（[06](06-Argon審與採納.md) A9、B2）。

### 甲的子模組怎麼分

| 名字（`from aos.py import …`） | 是什麼 | 類別 | 要不要活樹 |
|---|---|---|---|
| `ag` | 寫定義：`ag.tool`、`ag.state`、`ag.fsm`、`ag.lib`、`ag.defs`、`ag.write_defs`、`ag.main`…（轉匯出 `aos.agent_spec`，檔不搬） | 編譯器 | 不要，只要 `AOS_HOME` |
| `std` | 隨 aos 發的庫：`std.pack`、`std.tool`、`std.fsm`、`std.hooks`（已裁，不動；＝`ag.std`） | 編譯器 | 不要 |
| `agent` | `aos-agent` 的薄殼；`agent.attach(名, daemon=None)` 回把手 `a` | 薄殼 | 要 |
| `daemon_ctl` | `aos-daemon-ctl` 的薄殼；`daemon_ctl.attach(D)` 回綁好 daemon 的把手 | 薄殼 | 要 |
| `breakpoint` | 斷點；轉匯出 `aos.gdb` 的斷點類別（檔不搬），`a.bp` 就是它 | 延伸 | 要 |
| （不預做）`tools`、`mailbox` | `aos-tools`、`aos-mailbox` 的薄殼：代理加兩行就有，第二次遇到才加（Argon A10、B1；也免得 `tools.add` 離線登記檔、`a.tools.add` 活的、`ag.tool` 宣告三個撞在一起） | 薄殼 | — |
| `sh`、`Failed`、`echo` | 順手打 shell、唯一的例外類別、要不要印指令 | 共用 | — |

把手 `a` 上面：`a.<aos-agent 的子指令>`（`say`、`listen`、`ask`、`ctl`、`tools`、`hook`、`system`、`llm`、`history`、`goal`…全走代理）、`a.bp`（延伸）、`a.look`（讀 stack 的檔：`where`、`history(n)`、`observed`、`request`、`queue`、`stderr`、`file(路徑)`）、`a.name`、`a.daemon`、`a.stack`（三個字串）。

**兩個世界要不要分**：同一個入口、分開的子模組、互不 import。`from aos.py import ag, std` 不會載入任何會跑指令的東西，也不需要 `PATH` 上有 `aos-agent`；`from aos.py import agent` 不會去讀 `$AOS_HOME/lib/packs`。交集只有兩個：共用一個例外類別、寫定義的宣告物件可以當活側指令的參數（第六節）。風格的差別留著並寫明是故意的：**宣告是延遲報錯（寫錯先記著，`defs()` 時一次講），動作是當場報錯**。

模組名的規則（以後加指令不用想）：**指令 `aos-X-Y` ↔ 模組 `aos.py.X_Y`**（去掉 `aos-`、連字號換底線）。所以是 `daemon_ctl` 不是 `daemon`；嫌長自己 `as d`。

## 三、命令行 ↔ Python 的通則

### 一句話

> `aos-agent --daemon D --target N  X Y  --flag v  ARG`  ↔  `agent.attach(N, daemon=D).X.Y(ARG, flag=v)`

「指**哪一個**」的旗標（`--daemon`、`--target`、`aos-mailbox` 的 `-s STACK`、`aos-tools` 的 `--file`）在 `attach` 時綁一次；其餘原樣照抄。沒 `attach` 直接叫模組也行，那幾個旗標就當關鍵字參數給：`agent.say("hi", target="ann", daemon=".stack")`。daemon 沒給時的預設**不由庫決定**，庫什麼都不加，交給指令自己（今天是 `$AOS_DAEMON`，再沒有就 `./.stack`）——庫不抄一份預設規則，免得兩邊對不上。

### 細則（實作者照這張表寫代理，寫一次）

| 這邊（Python） | 那邊（argv） | 例 |
|---|---|---|
| 「指哪一個」 | `--daemon D --target N` 一律放在**子指令前**（`aos-agent` 頂層就收，usage `apps/agent/__init__.py:12`） | `a.ctl.stop()` → `aos-agent --daemon D --target ann ctl stop` |
| 點下去的名字 | 子指令，一個字一段；底線換連字號；結尾的 `_` 去掉一個 | `a.ctl.set_def(…)` → `ctl set-def` |
| 位置參數 | 位置參數，放在旗標後面；不是字串的：數字轉字串，dict／list 轉 JSON；有任何一個以 `-` 開頭時，前面先放 `--`（第一刀查 `aos.flags` 認不認 `--`；不認就補在 `aos.flags`） | `a.say("-h")` → `say -- -h` |
| `名=True`／`False`／`None` | **先判布林**（Python 的 `True` 也是整數）：`True` 單字母 `-x`、多字母 `--名`；`False`、`None` 不加 | `auto_restart=True` → `--auto-restart`；`j=True` → `-j` |
| `名=值`（數字、字串） | `--名 值`；底線換連字號；單一字母是短旗標 | `timeout_s=20` → `--timeout-s 20`；`w="."` → `-w .` |
| `名=dict` | 值轉 JSON（跟位置參數同一條） | `path_json={"$env": "AOS_HOME", …}` → `--path-json '{…}'` |
| `名=[v1, v2]`、tuple | 旗標重複（要傳 JSON 陣列自己 `json.dumps`） | `envs=["A=1", "B=2"]` → `--envs A=1 --envs B=2` |
| 名字是 Python 保留字 | 後面加一個底線（只講保留字；`id=`、`type=` 這類內建名本來就能當參數名） | `from_="me"` → `--from me` |
| `json=True` | 加 `--json`，**回傳解好的** dict／list | `a.ctl.state(json=True)` |
| 點到底線開頭的名字 | 不翻、照 Python 平常的錯 | 防止 tab 補全、`hasattr` 亂觸發 |
| **把手頂層**點到不是 `aos-agent` 子指令、也不是 `bp`／`look` 的名字 | 當場 `AttributeError`；子指令表從 `aos.apps.agent` 那份讀（不另抄） | `a.resume` → AttributeError（你以前打過這個） |
| 只是把物件印出來（`repr`） | **不跑任何指令**，印出它會跑的那條 | `a.tools` → `<aos-agent --daemon … --target ann tools …>` |

代理同時就是「通用殼」：`a.tools("add", "--no-cache", "x")` 這樣把字串原樣丟過去也行；把手本身也能叫，`a("peek", "/status")`＝頂層通用殼。所以今天的 `a.agent(*args)`、`a.ctl(*args)` 兩支可以拿掉。

**`ctl add／rm／ls／set-def／who` 不吃 `--target`**（`apps/agent/ctl/__init__.py:13,50`，前面給了報 `ArgumentsBad`）：所以在把手上打 `a.ctl.ls()`、`a.ctl.rm()` 會被指令擋下、錯誤原樣帶上來；列表、掛、拿掉用模組層的 `agent.ctl.ls()`、`agent.ctl.add(…)`、`agent.ctl.rm("ann")`。庫不另記「哪些不收 target」的表（那就是第二份真相），說明寫一句。

要成立有一個**指令那邊的前提**：`json=True` 一律翻成 `--json`。隊長查過程式（不是 usage）：`aos-agent` 的 `ctl ls`、`ctl state`、`ctl who`、`tools ls`、`hook ls`、`history ls`、`system get`、`goal get`，`aos-daemon-ctl` 的 `ls`、`sweep`，旗標表裡都是 `--json` 長名、`-j` 只是短名（`apps/agent/ctl/ls.py:105`、`ctl/state.py:299`、`tools.py:173`、`hook.py:260`、`daemon_ctl/main.py:579`）；`aos-mailbox peek --json` 也收（`ctl/state.py:189` 自己就這樣叫）。其餘子指令第一刀再逐支查；真的只收 `-j` 的補上 `--json` 長名（改指令，不是在庫裡做對照表——對照表就是第二份真相）。

### 回傳值

| 情況 | 回什麼 |
|---|---|
| 給了 `json=True` | 解好的 dict／list；輸出是一行一個 JSON（JSONL）就解成 list；空的回 `None`。預設就印 JSON、沒有 `--json` 旗標的指令（如 `aos-tools get`）補收 `--json` 當無作用，規則仍只有一條 |
| 沒給 | 那條指令的 stdout 原樣，型別 `Text`（一種在 REPL 印出來不帶引號、不把換行印成 `\n` 的字串，看起來跟在 shell 打一樣） |
| stdout 是空的 | `None`（REPL 就不印東西） |
| 手寫的幾支、會「生出一個東西」的 | 那個東西的 id 字串：`a.say`→信名、`a.bp.add.<事件>(…)`（依 [07](07-使用者裁定.md) 第 3 題）→斷點 id |

**庫不解 TSV**。指令沒有 json 輸出、而你想要結構時：**先替那條指令加 `--json`，庫就自動回解好的**。理由：在庫裡拆 TSV＝格式有兩個地方知道，指令改欄位庫就悄悄錯；而且加在指令上，shell、將來的 Lisp 一起受惠。

### 錯誤

整個 `aos.py` 只有**一種例外 `Failed`**（今天 `aos.gdb` 的 `Failed` 搬過來加欄位）：

| 欄位 | 內容 |
|---|---|
| `str(e)` | 一行英文：那條指令自己的錯誤行原樣（長相例如 `aos-agent: error: TargetMissing …`），或庫自己拒絕的理由 |
| `e.program`、`e.code`、`e.reason` | 從 N-43 的錯誤行 `程式: error: 代號 原因` 拆出來的三段（拆不出來＝`None`） |
| `e.argv`、`e.exit` | 跑的那條指令、它的結束碼（不是指令失敗的＝`None`） |

等待逾時＝`Timeout(Failed, TimeoutError)`（`except TimeoutError` 也接得到）；`a.look.*` 讀不到檔、JSON 壞了也轉成 `Failed`（`code` 是 `FileMissing`／`JsonBad`，`argv`、`exit` 是 None）。所以活的那一邊 `except Failed` 一網接住，要細分看 `e.code`。寫定義的 `ag.SpecBad` 照舊（寫定義不搬，它本來就是延遲報錯、沒有 argv 可填）。錯誤行**原樣帶上來、不改寫**，這跟 N-43「下層的錯不轉述」是同一個意思（薄殼不是一層，是同一句話的另一種打法）。

### 要不要印背後那條指令（echo）

要，而且這是薄殼的另一半價值：你看得到每個 Python 寫法背後是哪條 shell，REPL 與 shell 可以混著用，將來寫 Lisp 版時那些 `$ …` 就是規格。定法：

- 庫的預設是**不印**（`echo = False`）；`aos-gdb` 這個 REPL 入口把它打開。腳本、被別的程式 import 時安靜，人坐在 REPL 前面時看得到。
- 印在 **stderr**（今天印在 stdout；腳本把結果接管線時不該混進去）。
- 讀檔的（`a.look.*`）印 `# read <路徑>`，一樣看得到它碰了哪個檔。

### 薄殼當硬規則，以及斷點怎麼對上

**硬規則**：`agent`、`daemon_ctl`（以及以後加的同類模組）裡**每個公開的呼叫＝剛好一條 aos 指令**，不多做、不自己記狀態、不解讀輸出（`json=True` 的解 JSON 除外）。違反的東西不准放進這些模組。兩個細節（Argon A6）：`attach` 只記名字與 daemon，stack 路徑**用到才問**、不快取（那隻被 `rm` 再掛回來也不會讀到舊夾）；手寫的 `say`／`listen` 模組層與把手上是**同一支函式**，`agent.say("hi", target="ann")` 跟 `a.say("hi")` 回的一樣。

**延伸**是明講的例外類別：一個功能需要「好幾條指令＋自己在 stack 裡放檔」才做得成、而且沒有對應指令，就放進**有自己名字的延伸**，不混進薄殼。今天有兩個：

- `a.bp`（`aos.py.breakpoint`）：下一個斷點＝寫幾個檔到 `<stack>/gdb/`＋一條 `aos-agent hook add`；它的每一步還是印得出來的指令或檔。
- `a.look`：只讀 stack 裡的檔，一次一個，不改。今天這幾支直接掛在 `a` 上（`a.history(3)`、`a.where()`），名字撞到 `aos-agent history`、`ctl where` 而意思不同（01 第 4 節第 6 點）；收進 `a.look` 之後，`a.history` 就能老實地是 `aos-agent history`。`a.state()` 同理改成 `a.ctl.state()`。

所以「`a.xxx`＝`aos-agent xxx`」的完整講法是：**`a` 底下的名字，是 `aos-agent` 的子指令就是那條指令；不是子指令的只有 `bp` 與 `look`，它們是庫的延伸。**

你說「斷點就是給他 `aos-agent breakpoint xxxx`」，又裁了「`aos-agent` 不知道 gdb」。這兩句照字面是衝突的，有一個兩邊都顧到的出口（原列為方向題，Argon 審後不再問：兩個選項今天都不動程式，記在這裡等那天）：**C-86 說連字號拆出去的獨立程式跟子指令視同一樣**——所以哪天真的要從 shell（或 Lisp）下斷點，做一支獨立的 `aos-bp`（`aos-bp --target ann add before_tool --tool write`），概念上它就是你說的 `aos-agent breakpoint`，程式上 `aos-agent` 一個字都不用認得它；到那時 `a.bp` 就從「延伸」變回普通薄殼。**現在不做**（只有 Python 在用、`py=` 的 lambda 條件過不了命令行），等 Lisp 整合或你想在 shell 下斷點時它自己會被需要。`aosgdb-api-1119` 交件時也寫了同一個意思的提案：做在 `aos-gdb` 自己這邊的 `aos-gdb bp add/rm/set/ls/get/stop/resume/skip/why …`（[第二版末節](../aos-gdb-lib-第二版.md)）——跟 `aos-bp` 只差名字，C-86 下兩者等同；到那天再挑名字。

`a.bp` 裡面的寫法（細部歸 `aosgdb-api-1119` 那條線，這裡只定版面要的）：

- 增：**已裁＝`a.bp.add.before_tool("x")`，回 id 字串**（使用者 11-19 選項框，[07](07-使用者裁定.md) 第 3 題；題目在 [05](05-邊緣狀況與要拍板的題.md) 第 3 題）。`add` 同時是動作與一組事件名，tab 補得出事件、打錯當場知道；`a.bp.stop` 只留「現在就停」、不兼分組。已交的字串式 `a.bp.add("before_tool", tool="x")` 不留，第二刀改；觀察者與自訂事件的寫法（例如 `a.bp.add.watch(…)`、`a.bp.add.on("事件", …)`）留給施工線定。以下是裁定前的原文，留作紀錄：你第一段例子是 `a.stop.before_tool()` 回 id，第二段改成「以斷點為核心增刪改查、`a.bp.stop()`／`a.bp.resume()`」，沒說建斷點叫什麼；`aosgdb-api-1119` 工作樹做成 `a.bp.add("before_tool", tool="write")`，`a.bp.stop()` 是「現在就停」。若改成 `a.bp.stop.before_tool(…)`，`a.bp.stop` 就同時是「現在停」的函式與「建斷點」的分組，一詞兩義（Argon A9）。本稿不替你定，版面兩種都放得下。
- `a.bp.stop()`＝現在就停、`a.bp.resume()` 不收參數、`a.bp.skip()`；刪改查 `rm`／`set`／`ls`／`get`／`clear` 照舊。
- `wait_paused`（現在叫 `wait_stopped`）你問過是啥：它是「**等到它停在斷點為止**」——`a.say(…)` 一送出去就回來了，agent 還在跑，緊接著打 `a.bp.why()` 多半還沒停。真的 gdb 沒有這一支，是因為它的 `continue` 自己會卡著等。建議改短名 `a.bp.wait()`，說明就寫上面那句。

## 四、「只把必要的搞進來」的線

**第一批**（照 [02](02-一天的流程.md)，Argon 審後縮小）：入口夾（轉匯出 `ag`、`std`）、通用代理（`agent`、`daemon_ctl` 兩個模組）、把手與 `say`／`listen`、把手接上 `aos.gdb` 的斷點與讀檔（不搬檔）。

**明講不做**：

- 起樹、抄樹（前景行程，留 shell）。
- 其餘十幾支指令的模組（`aos-share`、`aos-sandbox`、`aos-clock-register`、`aos-comm`、`aos-feedback`、`aos-grow`、`aos-mcp-import`、`aos-json`、`aos-llm`、`aos-asuser`…）。
- 腦的工具（`agent_def`、`tools_def`…）：那是給 agent 叫的，不是給人打的。
- 在庫裡拆 TSV、替指令補預設值、把執行中加的東西自動寫回 `agent.py`。
- 內部模組（`aos.flags`、`aos.daemon_ctl`、`aos.ws`…）不整理、不搬、不算公開。
- 寫定義（`agent_spec*`）與 `aos.gdb` 的檔不搬家（入口轉匯出／把手接它）；`aos-tools`、`aos-mailbox` 的模組不預做。
- 在庫裡把一個工具包展開成好幾條 `tools add`（要整包加，加在指令上）。

**之後怎麼加（自然長出來的規則）**：

1. **新指令、新子指令**：什麼都不用做，代理自動有。新的一支指令要有模組＝在 `aos/py/` 加一個三行的檔（指令名、哪幾個是「指哪一個」的旗標）。門檻：有人在 REPL 第二次用 `sh("aos-xxx …")` 打同一支。
2. **手寫一支包裝**（像 `say`）：只在「代理回的東西，有人第二次在 REPL 自己動手整理」時才寫，而且先問能不能改指令（加 `--json`、讓它印 id）而不是改庫。
3. **新的延伸**（像 `bp`）：只在「同一串好幾條指令，有人第二次照抄」時才開，而且要有自己的名字、不混進薄殼。
4. 加東西的人在 commit 訊息寫一句「第二次是在哪裡遇到的」。沒有第二次的不加。

## 五、跟已裁的幾件事的關係

- **命名空間 B**（`std`、`ag.lib`，不推翻）：檔不搬，`aos.py` 只轉匯出，名字不變；多的只是 `std` 也能直接 `from aos.py import std`（今天要 `std = ag.std`）。「資料夾即命名空間」這次往上套一層：`aos/py/` 這個夾就是「給人用的」那個命名空間。
- **解耦合**（`aos-agent`／daemon 不知道 gdb）：守住。`aos.py.agent` 這支薄殼模組本身不 import 斷點庫，`a.bp` 是第一次用到才載入的；`aos-agent` 的程式與 daemon 表一個字不動。庫這一層同時認得兩邊是可以的——你裁的是那兩支程式不認 gdb，不是 Python 庫不准把它們擺在一起。
- **C 與 .o**：`ag` 還是只有一個方向（`agent.py` → json）。活側加的工具、hook、斷點都寫在 stack（活的那隻自己那份），不寫回定義；重生不會蓋到它們（它們不在定義夾裡），但把那隻 `rm --purge` 再掛就沒了。這跟你說的「.o 也可以在運行途中給自己加 lib」一致。
- **將來 Lisp 整合**：薄殼＋一條通則的最大受益者就是它。Lisp 那邊要做的是同一張細則表寫成一個巨集（`(agent ann tools add "x" :no-cache t)` → 同一條 argv），不必翻譯任何 Python 邏輯；回傳靠 `--json`、錯誤靠 N-43 那一行，兩者都在指令那邊、跟語言無關。**唯一帶不過去的是延伸**（斷點庫是 Python 寫的）——這就是上面說「Lisp 整合時 `aos-bp` 會自己被需要」的原因。也因此「缺什麼先加在指令上」不只是潔癖：加在 Python 庫裡的聰明，Lisp 那邊都要重寫一遍。
- **繼承**（`aos-inherit-1119` 已交 `843c32566`，推薦乙：一個新函式 `ag.load("../reviewer")`，跑底那支、它最後一行的 `ag.main` 不寫檔只交出欄位，只動 `agent_spec`）：接得上。本線寫定義不搬、入口轉匯出整個 `ag`，所以那條線加的 `ag.load` 自動出現在 `from aos.py import ag` 裡，本線不用做事。原稿提的 `if __name__ == "__main__"` 守衛，那條線用「`ag.main` 被載入時不寫檔」解掉了同一個問題，這裡不再提；骨架與找路徑都歸那條線；它動骨架時順手修 Argon A7 抓到的兩處（`except` 只認 `name == "aos"`、骨架把自己的夾排在 `$AOS_HOME/lib` 前面，夾裡有支 `aos.py` 就會抓錯）。

## 六、工具包：寫定義時與執行時

| | 寫定義時（編譯器） | 執行時（薄殼） |
|---|---|---|
| 寫法 | `TOOLS = [std.pack("look"), my.pack("x"), ag.tool("grep", 路徑)]` | `a.tools.add(路徑)`、`a.tools.rm(名)`、`a.tools.ls()`、`a.tools.get(名)` |
| 寫到哪 | 定義夾的 `tools.json`（生成時把包展開成一支支） | 活的那隻 stack 裡的疊層（`aos-agent tools add`），定義不動 |
| 要不要活樹 | 不要 | 要 |

名字不撞的原因是**兩邊的東西不同種**：`std.pack(…)`、`ag.tool(…)` 回的是「宣告」（一張小單子，說有這麼一支工具、在哪），`a.tools.*` 是「動作」（對活的那隻做一件事）。`ag.tool`（單數，寫一張單子）對 `a.tools`（複數，指令名）這一對要在說明裡講一次。

**執行中整包加工具：不在庫裡做**（原稿想讓 `a.tools.add(std.pack("json"))` 在代理裡展開成一支一條 `tools add`；Argon A6 指出這會讓代理得懂寫定義的宣告格式、破了「一呼叫＝一條指令」，而且五支加到第三支失敗就留下半包）。真的要時，**加在指令上**——例如 `aos-agent tools add --pack json`（全有或全無由指令負責），Python 代理自動有 `a.tools.add(pack="json")`、Lisp 也同時有。第一批先逐支 `a.tools.add(路徑)`。hook 組同理。

不做：`aos-tools override`、`ctl set-def --kit` 的專門包裝（代理本來就叫得到）。

## 七、現有三塊要搬改多少、怎麼分刀

### `sys.path` 怎麼解

舊裁定的出處：`wf/workflows/dev-env.md` 第 27 行——「不再寫 Python user site 的 `aos-proto8.pth`（使用者 11-15 對自編規則盤點的裁定「6.拿掉。」…）；Python 指令的入口自己把 `lib/` 放上路徑」。那次拿掉的原因是 `.pth` 是整台機器、所有 Python 都吃的設定，repo 搬家後它還指著舊地方（11-13 公司機就踩過）。

| **a. 只靠入口（推薦，先這樣）** | `aos-gdb`（`bin/` 裡的入口本來就自己把 `../lib` 放上路徑）是進 REPL 的門；自己寫的腳本照 `agent.py` 開頭那四行。不動 `env.sh`、不違反 11-15。代價：隨手開的 `python3` 還是 import 不到 |

## 八、推薦（★＝方向題，你拍板；其餘是我照原則直接定的）

11-19 使用者已用選項框裁了入口名、是哪一隻、讀 stack 的檔（都照推薦）與建斷點的寫法；一般 python3 那題沒單獨問、暫照推薦。逐字見 [07](07-使用者裁定.md)。

| 項 | 推薦 |
|---|---|
| ★ 入口名 | `aos.py`（照你的原話；毛病見第一節） |
| ★ 是哪一隻 | 甲 把手式；乙的「目前這隻」之後想要再加 |
| ★ 一般 python3 找套件 | 先只靠入口（a）；不動 `env.sh` |
| ★ 讀 stack 的檔 | 收進 `a.look`；`a.history`、`a.ctl.state` 還給指令 |
| ★ 建斷點的寫法 | 已裁（[07](07-使用者裁定.md)）：`a.bp.add.before_tool("x")`；字串式 `a.bp.add("before_tool")` 第二刀改掉 |
| 斷點有沒有指令 | 不問：現在只在庫裡（延伸）；要從 shell／Lisp 下斷點那天做獨立的 `aos-bp`，不進 `aos-agent` |
| 寫定義、`aos.gdb` | 不搬；入口轉匯出／把手接它 |
| 通則 | 第三節那一句＋細則表；用通用代理實作；「指哪一個」放子指令前 |
| 回傳 | `json=True`→解好的（JSONL→list、空→None）；否則 `Text`；空的→`None`；生出東西的→id 字串；庫不拆 TSV |
| 錯誤 | 活的那一邊一種 `Failed`（`program`／`code`／`reason`／`argv`／`exit`），`Timeout(Failed, TimeoutError)`；寫定義的 `SpecBad` 照舊 |
| echo | 庫預設關、`aos-gdb` 打開、印 stderr |
| 薄殼 | 硬規則；例外只有具名的延伸（`bp`、`look`）；整包加工具加在指令上 |
| 模組名 | `aos-X-Y` ↔ `aos.py.X_Y`；第一批只有 `agent`、`daemon_ctl` |
| 分刀 | 第零刀（`install.py` 刪孤兒）→ 第一刀（新增 4 檔）→ 第二刀（接 `a.bp`＋改成 `a.bp.add.<事件>(…)`，第 3 題已裁，見 07） |
