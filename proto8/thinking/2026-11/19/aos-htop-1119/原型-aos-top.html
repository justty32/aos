aos-top 原型・假資料

像 htop，但每一欄都是 kernel 自己宣告「我記了什麼」。
只看：
設定欄位（像 htop 的 F2）：要看哪個 kernel 的哪些欄
欄位清單不是寫死的：是讀每個 kernel 的宣告（declares）排出來的。換一個自訂 kernel，這裡就會多出它的欄。勾選會記在這台瀏覽器。
會跑的指令 原型：只顯示指令，不執行 
（在任一列右邊的「下手」選一個動作，這裡會出現對應的指令）
會跑的指令 原型：只顯示指令，不執行 
（點卡片上的「建議動作」，這裡會出現對應的指令）
這頁是什麼
  • 欄位來自 kernel 宣告。每個 kernel（llm、procs、使用者自己寫的…）自己說「我替每隻 proc 記了哪些東西、單位是什麼」，這頁只照宣告排欄。記什麼、怎麼分配，都由 kernel 自己定，大家都能自訂 kernel。
  • 共通底是 daemon 那份表。每列一定有：name、phase、pid、reason、counter_restarts、stack、def，加上 agent 自己寫的 stage.txt（idle／think／wait／act）。
  • 全是假資料。名字、數字、金額都是編的，金額是「假價目」換算，不是帳單；沒有任何真的 key 或帳號。
  • 只顯示指令，不執行。「下手」選單與卡片上的建議動作，只把指令印在頁底的框。
  • 真的要接的話，資料應該從這些地方來：
    • llm kernel：ledger.jsonl（每次問腦一行）、used.json（今天額度用了多少）
    • daemon：procs_state.json（每隻的 phase、pid、重起次數…）
    • agent：stage.txt、observed.jsonl、history.jsonl（最後說的話、工具呼叫成敗、context 用量）
    • 不顯示「被 aos-gdb 扣住」：使用者定了「表上不要看得出來，兩者解耦合」；要看去 aos-gdb 用 a.bp.why()
  • 誰負責彙總：另一支讀檔的小工具（例如 aos-top 自己），不加在 daemon 身上——daemon 是板子，只管起停。
  • 欄頭可點來排序（同一層裡排，不打散樹）；點一列展開細節；▸／▾ 摺疊子樹。
