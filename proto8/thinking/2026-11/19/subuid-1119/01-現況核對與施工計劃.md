## 一、現況核對（施工前，讀程式）

| 哪裡 | 今天怎麼做 | 位置 |
|---|---|---|
| daemon 驗 `limits.user` | 只要是非空字串就收（`check_limits`），`sub:5` 也收 | `cpp/aos-daemon/src/child/limits.cpp` `check_limits` |
| daemon 備身分 | fork 前在 `/etc/passwd` 找同名帳號（不經 NSS）；`sub:5` 找不到＝`user_found=false` | 同檔 `prep_limits` |
| daemon 換身分 | 子行程 setrlimit 之後 `setgroups`＋`setgid`＋`setuid`；`sub:5` 在這裡印 `LimitBad user sub:5: no such user`、退 1（**這就是調查說的「回 LimitBad」**）；真帳號那條非 root 時 `EPERM … needs the daemon to run as root` | 同檔 `apply_limits`；`child.cpp` `run_child` 在 `run_cli` 前呼叫 |
| kernel 站 | `users` 表照 proc 名填 `limits.user`（可以是 `sub:N`），寄件人自帶的 `user`／`groups` 一律丟；README 寫「daemon 認之前不要填 `sub:N`」 | `py/tools/aos/kernel/limits_rule.py`、`kernel/README.md` |
| aos-asuser | Python：fork → 子 `unshare(CLONE_NEWUSER)` → 管子通知 → 父跑 `newuidmap PID 0 <uid> 1 N <起點+N-1> 1`、`newgidmap` → 子 `setgroups([])`、`setresgid`、`setresuid`、環境白名單、`HOME=/nonexistent`、`closerange(3…)` → exec | `py/aos/apps/asuser/main.py` |
| 這台的前提 | `/etc/subuid`、`/etc/subgid` 都有 `guanyu:100000:65536`；**`newuidmap`／`newgidmap` 沒有**；家目錄 `/home/guanyu` 是 **750**；ext4 吃 ACL（用 xattr 實寫一次成功） | 實查 |

## 二、規劃已定的（照做）

kernel-limits-plan（K1～K18 全裁）與 03、04、08：

- K4／03 第 4 點：無特權 user ns＋subuid；**每支 proc 自己一個 ns**，不是整棵樹進 ns；父子用一條通道對號碼，daemon 跑 `newuidmap`／`newgidmap`，換身分在 daemon 的子行程裡做（不 exec 另一支）。
- K6＋再裁、K18：一台 daemon 一個群組，daemon.json 寫 `group`（ns 60001～65536）；附屬群組清空。
- K16／G6：daemon 起 proc 前替 stack 設 ACL `u:<subuid>:rwx`＋預設 `u:<subuid>`、`u:<使用者>`；stack `700`。
- 03 第五節：換 uid 前 `close_range(3…)`、照白名單清環境（L5）；git 帶 `safe.directory=<工作區>`（G8）；起前檢查祖先走不走得到，走不到 `LimitBad user sub:N: cannot reach <路徑>`；沒有 newuidmap＝`LimitBad … newuidmap missing`。
- K7：eca 本體留 1000（這一刀不碰 eca）。K11：沒換 uid 寫 `procs` 才警告。
- 段 4 順序：進 cgroup 在換 uid 之前。

## 三、規劃沒講到、我自己定的實作細節

| # | 定了什麼 | 為什麼 |
|---|---|---|
| D1 | 通道用 `socketpair`＋`send(MSG_NOSIGNAL)`，不用兩條管子 | daemon 沒忽略 SIGPIPE，子行程先死時寫管子會把整台 daemon 打死 |
| D2 | 根 daemon 沒寫 `group`＝60001；daemon 的 `state.json` 多一欄 `group` | K18 只說「子 daemon 沒寫沿用父的」，沒說根的；60001 是段的第一號。沿用父的那半這刀沒做（見入口「沒做」） |
| D3 | 號碼段與帳號照讀 `/etc/subuid`、`/etc/subgid`、`/etc/passwd`（不經 NSS），helper 照 daemon 的 PATH 找 | 同 daemon 既有「靜態連結不用 getpwnam」；同 aos-asuser 的找法 |
| D4 | 環境白名單與 `HOME=/nonexistent` 照 aos-asuser 那份 | 規劃說「同 aos-sandbox 的 env」，但 daemon 的 proc 沒有 env 設定；asuser 是同一件事的現成做法 |
| D5 | 「走得到」在**換了身分之後**用 `access()` 查（小格 rwx、daemon 的 cwd x、工作區 x），不行再一層層找第一個走不進去的祖先 | 換身分後查才把 ACL、群組都算準；不用自己讀權限位 |
| D6 | ACL 直接寫 xattr（`system.posix_acl_access`／`_default`），不靠 `acl` 套件；每次起都重寫（冪等） | 公司 WSL 沒裝 `acl`；家機也不用多裝 |
| D7 | `setgroups` 被拒（`/proc/<pid>/setgroups` 是 deny）就不放行 | 放行的話 agent 會帶著使用者的附屬群組（sudo、docker…）跑 |
| D8 | helper 失敗：helper 自己的 stderr 與一行 `LimitBad user sub:N: <helper 路徑> exited N` 進小格 `stderr.txt`，子行程默默退 1 | 照 daemon 既有「子行程才失敗＝stderr.txt 一行、列 stopped＋reason」 |
| D9 | `sub:N` 的 N 1～60000、不收前導 0（`CfgBad`） | 同 aos-asuser；60001 起留給群組（08 號段） |

## 五、linux-as-hw 04 三十條裡這一刀撞到的

| 條 | 狀況 | 這一刀 |
|---|---|---|
| 1、2 | 家目錄 700／750、祖先走不到 | **偵測並點名**（`cannot reach /home/guanyu`），不替使用者改家目錄——怎麼開門是**拍板題 Q1**（入口） |
| 3 | agent 沒有家 | `HOME=/nonexistent`（D4）；eca 本體不換（K7），所以登入資料不用搬 |
| 4 | PATH 上的工具在家目錄裡 | 同第 1 條，開了門才走得到 |
| 5、6 | 使用者改不動 agent 的檔、agent 自己 chmod 鎖人 | 小格預設 ACL 把使用者加進去（5）；6 照舊用 `aos-asuser --fix` |
| 7 | git dubious ownership | 有 `ws` 就帶 `safe.directory=<ws>`；`ws` 在 repo 子夾時要指到 repo 根才有效——這刀不處理 |
| 8、22 | 搬家、兩台號碼 | 不處理（數字照 `/etc/subuid` 算，兩台都是 100000） |
| 9 | 刪不掉 agent 的檔 | 不處理（本線不刪；`rm` 照舊只 detach） |
| 10、11、13 | 信箱寫不進、投遞箱外洩、使用者專區 | **不處理**：換了身分的 agent 寫不進 daemon 與 kernel 的信箱（755、擁有者是使用者），要 `aos-share drop`（K16「共用夾用指令」）；所以這一刀能跑的是「不用寄信的 proc」 |
| 12 | 用信夾擁有者認寄件人（K9） | 不處理（丙，下一刀） |
| 15 | 附屬群組帶不進去 | 清空（`setgroups({})`），被拒就不放行（D7） |
| 17 | `ps` 看到數字 | 照舊；真 uid＝起點＋N－1 寫在 docs/09 |
| 18 | 公司 WSL 缺 `uidmap` | 報 `newuidmap not found on PATH (install the uidmap package)`；`acl` 不需要（D6） |
| 19 | 沒 systemd user | 跟 cgroup 一樣，與這刀無關 |
| 20 | `/mnt/c` 不吃 ACL | 設 ACL 失敗＝`LimitBad … cannot set the ACL`，那支起不來 |
| 23 | daemon 自己是誰 | 照舊是使用者；它是每個 ns 的擁有者，停得了、殺得了（**待真機補驗**） |
| 24 | 清道夫讀不到 environ | 不處理（清道夫認行程那條，下一刀） |
| 25 | 換身分前清環境、關 fd | 做了（D4、`close_range`） |
| 26、27 | eca 本體、tmux | 不處理（K7：eca 本體留 1000） |
| 28 | `procs` 份額 | 換了 uid 就只數自己（K11 的提醒不印）；**待真機補驗** |
| 14、16、21、29、30 | sudo、root、WSL 網路、prompt 注入、多人 | 與這刀無關或屬防賊／多人，照 06「先防呆」不做 |
