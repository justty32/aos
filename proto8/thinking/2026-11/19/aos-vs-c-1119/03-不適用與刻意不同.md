aos 在哪些地方本來就不該像 C：沒有同一個問題的（不適用），和有同一個問題但使用者選了不同解法的（刻意不同）。

## 不適用：aos 沒有 C 那個問題

| C 的東西 | C 為什麼需要 | aos 為什麼沒有這個問題 |
|---|---|---|
| 記憶體管理（malloc／free、指標、越界、use-after-free、ASan） | 程式直接摸位址 | agent 沒有位址；狀態全在檔裡（history、stack 的 json）。對應的「越界」是寫出工作區，那屬於同帳號邊界（已裁只寫明） |
| 未定義行為、`-O` 優化等級 | 編譯器為了快可以重排 | aos 的編譯只是把宣告展開成 json，沒有優化器；花費取決於腦，不取決於編譯 |
| ABI 的呼叫慣例、結構體排列、位元組序 | 兩邊二進位要對得上 | 工具之間傳的是 JSON，自帶鍵名；「ABI」只剩參數名與型別，那一半歸 G2／G4 |
| 前處理器的文字替換、header guard、`#pragma once` | C 沒有別的方式做條件編譯與重複 include | `agent.py` 是完整的 Python：`if`、函式、`os.environ` 就是條件編譯；`defs.load` 有防互相載入（SpecBad）；菱形載入同一個底會跑兩次，今天只是慢一點（02 G13）。沒有正式 `-D` 不痛，代價只是產物不記用了哪些環境變數 |
| 交叉編譯的指令集、目標三元組 | 不同 CPU 跑不同機器碼 | 兩台機器只差路徑與裝了什麼；`$env` 指示詞把路徑留到執行時解。編譯時要在本機讀得到庫，跟 C 要 `--sysroot` 一樣，不算缺（01 表，Argon A10） |
| linker script、section、重定位 | 決定東西放進記憶體哪裡 | 產物是一夾檔，放哪由檔名決定 |
| `sleep()` | 程式要主動等 | agent 沒事就停在 wait 格等信，本來就是睡；定時醒有 `clock_register` |
| 訊號處理函式的非同步安全 | handler 會插進任何一行中間 | aos 的「訊號」是 ctl 檔與格之間的邊界，格與格之間才看；收尾走 `after_stop` hook，是另一個行程 |
| errno 是全域變數、要馬上讀 | 只有一個 errno、會被下一次呼叫蓋掉 | 每支工具自己印一行錯誤、隨結果回給腦，不會被蓋 |
| 隨機數、排序、字串函式庫 | 程式自己不會做 | 大部分由腦做；真的要算準的（數學）才有工具。隨機與 uuid 今天沒看到需求 |
| 原始碼格式化（clang-format） | 多人改同一份 .c | `agent.py` 短、多半一人寫；產物格式已穩定（照宣告順序、`indent=2`），可重現就夠 |

## 刻意不同：有同一個問題，使用者選了不同解法

| 事 | C 怎麼做 | aos 怎麼做 | 依據 |
|---|---|---|---|
| 連結預設 | gcc 預設動態，`-static` 要明講 | 預設靜態，`--dynamic`／`link=` 要明講 | 使用者選「預設靜態 (Recommended)」（[aos-ns-1119/07](../aos-ns-1119/07-使用者裁定.md)） |
| 「靜態連結」抄了什麼 | 把庫的機器碼抄進執行檔 | 只抄「包裡有哪些工具」的名單；工具程式永遠執行時讀 | 不是裁出來的，是實作如此；跟 C 差最多的一處，見 [02 G2](02-缺口清單.md) |
| 編譯產物跟原始碼的關係 | `.o` 不知道自己從哪來 | 同：不記帳、這次宣告到的檔整份蓋、手改的下次就沒了。例外照骨架 README 寫明：`_metainfo.json` 合併、已有的 `README.md` 不寫、拿掉宣告後的舊檔不刪（Argon A3） | 「好比C語言和.o之間的關係。」（[aos-compile-庚/10](../aos-compile-庚/10-使用者裁定.md)） |
| 跑著的程式讀到新產物 | 執行檔載入後不變（換檔不影響已在跑的） | 跑著的 agent 每格／每次問腦都重讀定義夾 | 使用者：「我更願意稱其為"特性"」 |
| 除錯 | 斷點＝位址；`-g` 對回原始碼行 | 斷點＝條件成立就停 loop／fsm；不必對回原始碼 | [aos-gdb-1119/06](../aos-gdb-1119/06-使用者回應.md) |
| 命名空間 | C++ namespace 在編譯與連結時都在（符號改名） | 只在編譯時：資料夾即命名空間、別的庫工具帶 `庫名_`；執行期沒有 | [aos-ns-1119/07](../aos-ns-1119/07-使用者裁定.md)、C-87 加註 |
| 符號改名（name mangling） | 改出來的名字人不看 | `my_read` 這種前綴是**給腦看的**工具名，所以要短、要合法字元 | 同上第 2 題 |
| 找庫 | `-I`、`-L` 搜尋路徑 | 明寫路徑 `defs.lib("名", 路徑)` | 「先明寫，以後有需要再去弄-I。」 |
| `extern` | 宣告在這、定義在別的編譯單位 | 這份檔手寫、編譯不寫不蓋 | 使用者選「改 defs.extern」（[aos-pylib-1119/07](../aos-pylib-1119/07-使用者裁定.md)）；意思相近、不全同 |
| 繼承 | C 沒有；C++ 執行時有 vtable | 只在編譯時（`defs.load`），json 完整一份不記上一層 | N-70 |
| 檢查工具會不會順手編譯 | lint 不寫檔 | 同：`agent_def check` 唯讀、不重新編譯 | 第二刀劃掉 |
