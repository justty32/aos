## 先講結論

**aos 的「C 語言」骨架齊了，缺的是「連結器會罵人」那一半。** 打個比方：編譯器（`agent.py --compile`）會檢查文法、撞名、狀態機畫錯，也每次編出一模一樣的東西；但它不檢查「你叫的東西到底存不存在」，執行時找不到也只在角落記一行、程式照跑。C 的連結器最先擋的就是這種錯。

具體三件：

1. **寫錯一個工具路徑、格程式不在、LLM 值型別錯，編譯和 `agent_def check` 都說沒問題**；掛上以後工具從腦的清單無聲消失，或一起來就停。
2. **aos 的「靜態連結」只抄了工具名單，工具本身永遠在執行時從 `$AOS_HOME` 讀。** 所以 std 一改（升級），用它的 agent 會無聲換說明、少工具；拿掉一格時同一個 home 上的 agent 一次全倒；包、工具、aos 都沒有版本號可比。
3. **把一隻 agent 搬到別處（另一台機器、另一個工作區）時，依賴不跟著走、也不會說。**

其餘多半是「工具鏈還沒長出來」：沒有 make（改了庫或底，下游無聲跑舊的）、錯誤沒行號、沒有警告層、測試的劇本只能寫在共用 kernel、沒有 profiler 彙總。可重現、撞名、交叉編譯、訊號、退出碼、行程通訊、core dump、`nm`、範本與 `--help` 這些都對得上 C。

使用者今天已裁的十件（`-I`、執行期命名空間、跑著讀到新定義、單一 daemon 等）照標「已裁」，沒有再提。報告初稿送 Argon 審，18 點裡採納 16 點（改了幾處事實、排序與拍板題）、1 點只留底、1 點核過不採納，見 [04](04-Argon審與採納.md)。

## 要使用者拍板的題

每題都是「要不要補、補多少」，不牽涉今天已裁的方向。

### 第 1 題：編譯時要不要擋「叫的東西不存在、值型別錯」？（G1）

- **a 拆開：LLM 值型別在 `--compile` 直接擋；工具路徑、格檔在 `--compile` 只印 warning**。型別檢查不讀任何檔、對交叉編譯沒代價；路徑在別台機器上編時可能本來就不在，所以只警告。
- **b 三樣都在 `--compile` 擋成錯**：像 C 的連結器。代價：在一台缺東西的機器上就編不過。
- **c 只放進 `agent_def check`**：`--compile` 不變；要人記得跑 check。
- **d 不查**：只讓執行時的「skipped」更顯眼。
- 不論哪個：格程式只能查寫成指示詞或在本夾裡的（argv 分不出哪個字串是檔名）；model 名編譯時看不到 kernel，留給執行期。

### 第 2 題：std（`AOS_HOME`）升級後的保護要做哪些？（G2，可複選）

- **a 一支唯讀掃描**：列出表上每隻 agent 的定義裡解不開的路徑；升級前後各跑一次。不碰產物。
- **b `install.py` 在 `$AOS_HOME` 寫版本戳**：看得出兩台機器、兩個 home 是不是同一版。
- **c 真的靜態連結選項**：編譯時把用到的工具（或至少說明檔）、格程式抄進定義夾，std 怎麼改都不影響它，搬家也帶得走。代價：夾變大、std 的修正要重新編譯才到。
- **d 維持現狀**：算進「跑著讀到新定義」那個特性，風險自擔。
- 不列「把版本戳寫進 `_metainfo.json`」：會碰到「編譯產物不記帳」，也讓不同版上編出來不再一字不差。

### 第 3 題：搬家與分享要補到哪？（G3）

- **a 只加警告**：編譯時寫進本機絕對路徑（含 `defs.load("../底")` 的改寫）印一行。
- **b a＋庫的小清單檔**：庫根放一份（名字、要的 aos 版本、用到的 std 工具），`defs.lib` 編譯時讀它查。代價：庫的長相從「`packs/`＋`tools/`」多一份檔。
- **c 維持**：README 寫明「用指示詞寫、自己帶庫」。

### 第 4 題：要不要有 make 那種「哪夾過時」？（G7；`tool.py` 那條 G4 是同一件事在工具上）

- **a `agent.py --check`**：重新算一次、照 `--compile` 的保留規則跟夾裡比、不同退 1，不寫檔。
- **b `agent.py --deps`**：印出這次讀過哪些檔，交給 make 或人比。
- **c a＋b**。
- **d 不做**：靠 `--dry-run` 手比。注意：直接拿 `--dry-run` 輸出比，正常的夾也會因為 `README.md`、`_metainfo.json` 的保留規則顯示「不同」。
- 工具那半（G4）可另外選一個小的：aos-tools 讀工具時，夾裡有 `tool.py` 就比它算出的說明跟 `_tooldef.json`，不同就在 agent 的 stderr 印 warning。

### 第 5 題：`agent.py` 編譯器要不要加警告層（`-Wall`）？（G8）

候選警告（都是編譯時看得到的）：寫進本機絕對路徑、從起點走不到的狀態、沒用到的 `defs.lib`。

- **a 加警告，不加 `--werror`**。
- **b 加警告，也加 `--werror`**（警告當錯）。
- **c 只加絕對路徑那一個**。
- **d 不加**。
- 另外兩個不歸編譯器：動態包執行時撞名（G6）是執行期印 warning；工具描述過長（G13）歸 `tools_def check`。

### 第 6 題：agent 死了要不要留「死時是哪一份定義」？（G11，鄰近已裁「不做快照」）

- **a 死時記定義夾幾個檔的雜湊**：只保證「死時夾裡是什麼」；死前剛重新編譯過的話，不一定是出事那格讀到的。
- **b 不做**：算在「不做快照」裡。

### 第 7 題：工具鏈幾件小的要不要排？（G9、G10、G12，可複選）

- **a 重試迴圈提醒**（G9）：同名同參數連續失敗 N 次，給腦一則 `[aos]` 提醒。改的是執行期行為。
- **b 測試劇本跟著 agent**（G10）：`llm.json` 或夾裡一份劇本檔給假腦；外加一支把 history 抄成劇本的小指令。定義檔多一個欄位。
- **c `aos-agent stats`**（G12）：加總 `observed.jsonl` 的時間與 token。只讀。
- **d 都先不排**。

### 不用拍板、可以直接修的文件錯

- 骨架 README 兩處（開頭第三點「A change there shows up at the agent's next start」、「Linking tool packs」的「aos reads it every time the agent starts」「next start」）：實測與 `--compile` 自己印的話都是「每次問腦前讀」，不用重起。

## 沒查到、沒驗到

- 真的 `git pull`＋`install.py` 升級（用改名一格、搬走一支工具模擬）；真的跨兩台機器交叉編譯（用換 `AOS_HOME` 寫法、`AOS_WS` 沒設模擬）。
- eca 身體（Claude、pi）掛起來跑；只驗了它的 `agent.py` 編譯與 `llm_keys` 照目標檢查。
- subagent、fork、do_task、kernel 預算只讀文件；`aos-gdb` 只讀 `--help`。
- 腦真的去叫一支壞工具（假腦只叫字母序第一支）。
- 動態包換掉一支時「欄位不齊報 SpecBad」沒觸發（std 包條目只有 path）。
- Argon 指出的兩件只讀程式確認、沒實跑：底的格 `argv` 靠「檔存不存在」決定改不改寫（A7）、菱形載入的 `sys.modules` 卸載（A8）。
- 錯誤代碼 111 個是粗 grep。「system 文字跟工具不符」只證明沒有檢查。
