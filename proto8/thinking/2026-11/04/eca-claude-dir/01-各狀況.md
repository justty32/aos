入口檔「各狀況」的細節；每條：會發生什麼、嚴重度。使用者 11-04 定為自己承擔的風險、不改程式（見入口「決定」）。

## 各狀況

1. **畫面開在沒信任過的工作區＋有人 say＝claude 退出、信丟、這隻從 daemon 表掉下來**（高）。`aos-eca open -d` 的畫面停在「信任這個資料夾嗎」（游標在 No, exit），`cli_session.start` 只看畫面穩了就放行；`aos-say` 的字被貼進提問、Enter 選到 No → claude 退出 → `aos-eca-turn: CliFailed`。信在 Enter 時已收（history 只有 user 那則），子 loop 錯退後 `aos-eca ls` 看不到它、`aos-eca rm` 回 `InstanceMissing`，stack 留在原地。非互動 -p 不問信任、沒這問題。信任記在 `~/.claude.json` 的 `projects[<路徑>].hasTrustDialogAccepted`；git repo 以 repo 根為準，非 git 時信任上層會涵蓋下層。
2. **工作區自己的 hooks、CLAUDE.md、agents／commands／skills 都會進 eca**（中）。工作區＝aos repo 時：CLAUDE.md「去讀 AGENTS.md」會讓 eca 照 wf 規矩做事（掃 inbox、讀 SESSION-LOG…，多花錢、答非所問）；`/wf-lint` 會出現在它的指令清單；eca 一直 `--resume` 同一段對話、長了會自動 compact，那時 SessionStart（matcher `compact`）的 `compact_reload.sh` 會把 user.md 與 HANDOFF 塞進 eca 的對話。（aos repo 本身沒實跑，照 E1 的機制推的。）
3. **eca 自己不在工作區建檔**（低）。session、memory、信任都寫在 `~` 底下。會寫進工作區 `.claude/` 的只有三條路，寫了之後同 repo 的人與其他 eca 都會讀到：人在畫面上選「Yes, and don't ask again」→ `.claude/settings.local.json`、人打 `/init` → `CLAUDE.md`、cli.json 給了 Write／Bash 讓它自己寫。**daemon 在工作區起時 stack 就在 `ws/.stack/`**：`git status` 多一行 `?? .stack/`，裡面每隻 eca 的 history、mcp.json 都在 claude 用 Glob／Read 讀得到的地方（同工作區的兩隻能讀到彼此的 history）。
4. **同一工作區兩隻 eca（或一隻＋人）：session 不撞**（低）。都存在 `~/.claude/projects/<工作區路徑把非英數換成 ->/<id>.jsonl`；各自 uuid、各自 `--resume`。同一個 `--session-id` 再用會報 `Session ID … is already in use`（eca 只有第一次給新 uuid，不會撞）。`--resume <id>` 換了 cwd 也找得到、寫回原檔，所以同一個 stack 換了 `--ws` 前文還在、但 cwd 變了。人自己的 `claude --continue` 不挑 -p 的對話；畫面開的那段會不會出現在人的 `/resume` 清單沒驗。**auto memory**（`~/.claude/projects/<repo>/memory/`，以 git repo 為單位、預設開）是同 repo 的人與所有 eca 共用的；eca 只有 Read／Glob／Grep 時寫不進去，給了 Write 就會互相影響。
5. **環境變數**（中）。daemon 的環境一路傳到 claude，再加 `AOS_WS`、`AOS_STACK`、`AOS_DAEMON_STACK`、`AOS_CD`、`AOS_CF`、`AOS_CO`。`CLAUDECODE`、`CLAUDE_CODE_SESSION_ID`、`CLAUDE_CODE_ENTRYPOINT` 就算 daemon 是從 Claude Code 裡起的也會被 claude 自己蓋掉，`CLAUDECODE=1` 也不會讓 -p 拒跑。要留意 `AOS_STACK`＝**這隻 eca 自己的 stack**：cli.json 一給 Bash，claude 在裡面叫 aos 指令時沒給 `--stack` 就會用到它自己的 stack（例如寄信寄給自己）。畫面那條的 tmux 是 `aos-eca open` 那個人的 shell 起的，環境跟 daemon 起的 -p 不同（看程式推的，沒逐一比）。
6. **codex**（沒實跑成）：codex 讀 `~/.codex/config.toml`、`~/.codex/AGENTS.md`，加上從 git 根到 cwd 每層的 `AGENTS.md`；對話放在 `~/.codex/sessions/年/月/日/`、跟 cwd 無關；eca 帶 `--skip-git-repo-check`。WSL 的 `~/.codex/config.toml` 預設模型 `gpt-6.1-sol`，ChatGPT 帳號回 400 `model_not_found`——WSL 上掛 codex 的 eca 現在一定 `CliFailed`，cli.json 要自己帶 `-m`。
