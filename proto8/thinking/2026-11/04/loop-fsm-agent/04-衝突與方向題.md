## 要使用者看的

寫給不看 CS 術語的人。只有兩種：新設計跟既有條文打架的（衝突），和原則推不出答案的（方向題）。其餘細節都照原則定了，在 [01](01-設計.md)，可翻案。

### 衝突 1：信什麼時候收掉？P-11 的 10-30 改口說「答完才收」

- **哪條**：P-11 10-30 改口（agent-lifecycle 條文草稿，你「都照建議」）：「agent 認領……就把 `body` 接進 `history.jsonl`，**答完（assistant 那則已進 history）才把信收掉**」。P-12 跟著說「`cur/` 有沒做完的先接」。
- **衝突在哪**：這次設計讓 idle 把信**接進 history 的那一刻就收掉**（`aos-post done`），不等答完——跟你 11-03 替 eca 定的「他收到信後，丟給claude之類的，然後這封信就算是完成了」同一個精神：信的內容已經在 history 裡、不會丟，`cur/` 不用再留一份。這樣兩隻 agent 的收信行為一樣，統一介面不用分兩套。
- **各自後果**：
  - **(a) 接進 history 就收（fable 選的）**：queue 乾淨、兩邊一致；aos-listen 現在的判法（信不見了→看 history 最後一則是不是 user→還在答）兩邊都對。代價：P-11 那句要加註「走 fsm 的 agent 也是接進去就收」；腦失敗時「哪一題沒答」看 history 尾巴、不看 `cur/`。
  - **(b) 照 P-11 原字答完才收**：`cur/` 留到 assistant 進 history；人看 `cur/` 就知道「還有題沒答完」。代價：同一封信在 history 和 `cur/` 各一份、答完要再回去 done（多一步、多一個「答完但 done 沒成」的窄窗）；跟 eca 不一樣，統一介面要記兩種。
- **例子**：你 say 一句「現在幾點」。(a)：idle 收到 → history 多一則 user、信當場消失 → brain 問 → 答。腦掛了：history 尾巴是 user、`state.txt` 是 think，重起就接著問。(b)：信留在 `cur/` 直到答完才消失；腦掛了你看 `cur/` 有一封就知道沒答完。
- **建議 (a)**。

### 衝突 2：think 格也用結束碼 10？P-35 說「10 只有 idle 退」

- **哪條**：P-19「`10`＝正常停（idle 看 queue 空了）」、P-35「10 只有 idle 退（物件 `next` 接住的 10 到不了 loop）」、N-43「10＝沒東西」。
- **衝突在哪**：走 queue 之後，act 不能再「退 0 回 idle、idle 看題目還在 `cur/` 就再問腦」（信已收掉，idle 看不到題）。所以 act 要直接回 think，think 就得自己說「腦給了最後答案、沒事做了」——我用 **think 退 10、表上 `"10": "idle"` 接住**（N-36 分岔，10-30 你准的 round 表就是這麼寫：「think →0 act、10 finish」）。這跟 P-35「10 只有 idle 退」字面上打架，但 N-43 的本意「10＝沒東西」是對的：think 發現沒事可做。
- **各自後果**：
  - **(a) think 退 10、表接住（fable 選的）**：表三格、每格各一支程式、不多機制；P-19／P-35 加一句「物件 `next` 接住的 10 可以從別的格退，意思仍是『沒東西』」。
  - **(b) 堅守 10 只有 idle 退**：要另找辦法區分「腦叫了工具」跟「腦答完了」：要嘛 act 再多做判斷（有 `tool_calls` 退 0 回 think、沒有退 0 回 idle——但同一個碼 0 不能接兩個目的地，所以做不到）；要嘛 think 用別的碼（例如 11）——N-43 說結束碼只有 0／10／其他非 0，另造一個碼比加註更傷。
- **例子**：你問「現在幾點」。腦第一次說「叫 clock」→ think 退 0 → act 跑 clock → 回 think → 腦說「現在是 08:00」→ think 退 10 → 回 idle 等下一句。
- **建議 (a)**。

### 方向題 1：三格的程式放範本裡（複製）還是放 lib（掛捷徑）？

- **背景**：idle.py／brain.py／act.py 三支約各 60～120 行。你 10-23 說 aos-agent 是「範本」、CONVENTION 說「照抄的人不用想」，agent-eve 就是三支放在自己資料夾裡；但 lib/README 又說共用的東西「掛捷徑引用、不複製」，上一套 round 把格放在 `lib/agent/round/` 共用、11-03 連程式刪光。原則兩邊都有話說，推不出一個答案。
- **(a) 放範本裡、複製（fable 選的）**：每隻 agent 自己一份，想改腦的行為直接改自己那份，看一眼資料夾就全懂（C-50「布局單純」、10-31「先做成單檔案，有需要再拆」）。代價：第二個範本若要同樣的三支，就有兩份一樣的程式；到時照 lib 規則 9「第三份一樣再抽成共用庫」搬進 lib、範本改成捷徑。
- **(b) 放 `lib/agent/<名>/`、範本用捷徑指過去**：改一處全部生效。代價：跟 round 當年同一條路（lib 裡的格＋範本裡的捷徑）、Windows 沒捷徑、複製範本要 `cp -a`；而且現在只有一個範本，沒有「共用」可言。
- **建議 (a)**；有第二個範本時再搬。

### 方向題 2：思考中來了新信，等答完還是打斷？

- **背景**：你 10-28 說「插話時等這輪做完還是打斷：不訂死，每個 aos agent 自己設定」。範本總得有一個預設。eca 是「等這輪 CLI 答完、下一輪整批」。
- **(a) 等答完（fable 選的）**：新信留在 `new/`，act→think 幾圈到腦給最後答案、回 idle 才收，跟現在那批一起答。零機制。代價：長題目中途的話要等。
- **(b) 打斷**：act 每跑完一個工具（或 think 問腦前）看一眼 `new/`，有新信就先回 idle 收進 history 再問腦——腦下一次會同時看到工具結果和新話。代價：idle 以外的格也要看 queue（多一條路）、暫停粒度那段說明要改；而且「腦看到半途插進來的話」好不好要看場景。
- **例子**：你問「把 README 整理一下」，腦叫了 read、edit 兩個工具中間你又說「順便改標題」。(a)：等它答完 README 那題，下一句才處理「改標題」。(b)：edit 跑完回 think 前先收進「改標題」，腦一起處理。
- **建議 (a)**；要 (b) 的 agent 自己在 act.py 加那一眼。

## 決定（11-04，使用者）

四題都選建議，使用者逐字選的選項如下，並說「記完就實作」。

1. 衝突 1 選 (a)：「接進對話紀錄就收」——idle 把信接進 `history.jsonl` 那刻就 `aos-post done`；P-11 的 10-30 改口加 11-04 註。
2. 衝突 2 選 (a)：「think 也退 10，條文加註」——think 答完退 10、表上 `"10": "idle"` 接住；P-19、P-35 加 11-04 註。
3. 方向題 1 選 (a)：「放範本裡，每隻複製」——idle.py／brain.py／act.py 放在 `demo/agent-fsm/` 裡，有第三份一樣的再抽進 lib。
4. 方向題 2 選 (a)：「等答完回 idle 再收」——思考中來的信留在 `new/`，答完回 idle 才收、跟那批一起答。
