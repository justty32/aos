## 實作時代定（11-04，可翻案）

1. **aos-listen 放寬一個判斷**：判「信不見了但還在答」從「history 最後一則是 user」改為「最後一則不是回答」（`aos_ws.is_answer`）——這隻收信就 done、答的途中最後一則會是帶 `tool_calls` 的 assistant 或 tool；eca 行為一樣。
2. 假腦有工具時叫**第一個登記的工具**；答句是「FAKE ANSWER to: <最後一則 user>（tool said: …）」。
3. 旗標的相對路徑（`--prompt`／`--system`／`--tools`）從 `AOS_CD` 算（fsm 的內嵌格＝fsm.json 的資料夾＝範本），沒設＝cwd。旗標寫錯＝`ArgumentsBad`；開場白檔讀不了（不是不在）＝`PromptBad`。
4. idle 接進 history 的 user 只留 `role`／`content`（信 body 的其他 key 不帶）；brain 接的 assistant `role` 一律寫 `assistant`。
5. 暫停時改 history 要它**重答**：除了刪掉答案，`state.txt` 也要寫 `think` 再 resume（停在 idle 時 idle 看 queue 空就退 10，不會去問腦）。寫進 demo/README。
6. 寫 ctl 的例子都帶 `seq`（同一道指令內容不變時 loop 才認得是新的）。
7. 測試第 10 案用測試自己起的本機假 OpenAI 端點看送出的 request（system 在最前面、tools 是登記名、model 取範本 `.env`、回覆多的 key 不收）。
8. **實跑**：假腦直接跑、假 HTTP 端點掛 daemon（say／listen、pause／resume、stop／start、daemon 收工 `sleeping` 再 wake、rm）都照設計走；真腦 LM Studio（使用者 11-04「我已經打開本地lmstudio了，可以試試看。」；`AOS_BRAIN_URL=http://localhost:1234/v1`、`AOS_BRAIN_MODEL=qwen/qwen3-1.7b`）掛 daemon 能答、能叫到 clock（assistant 帶 `tool_calls` 時 `content` 是空字串）。
