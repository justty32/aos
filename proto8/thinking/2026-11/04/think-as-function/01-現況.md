## 現在問腦的三條路

1. **think 格直接打端點**（agent-fsm、pyfix、json_edit）：Python `urllib`，設定靠環境變數；逾時靠格的 `timeout_ms`；usage 寫 `AOS_KERNEL_REPORT`（經 kernel 跑時才有）。**同步、卡住 fsm 那一格**：120 秒內 loop 的 ctl（pause／stop）看不到、新信收不了。
2. **經閘門** `aos-llm-send 單子.json`（10-24 做的）：把「問腦那張單子」＋**寄信那一刻的整份環境**寫成信丟進 `$AOS_KERNEL/new/`，先 flock 住 `sender.flock`、**站著等**回信（`<信箱>/reply/`），再把 stdout／stderr／結束碼原樣交回——對那一格來說跟直接跑單子一樣（C-20）。kernel 跑的仍是 agent 自己的 brain.py，所以 `AOS_BRAIN_*` 要跟著信走。同步。
3. **eca**：腦是 claude／codex CLI，模型是 `cli.json` `flags` 裡的 `--model`；11-04 的 `aos-eca-llm` 子介面入口改它。不經 kernel。

## kernel／閘門／信箱做到哪（能直接長在上面的）

- **aos-llm-kernel**（C++，`impls/aos-llm-kernel/`）：一次跑完就結束，給 loop／daemon 拍（C-47）；`kernel.json`＝`mailbox`、`slots`、`budget`、`accept`；信箱 N-16 四格＋flock 擋第二個 kernel；排序六條（級數→deadline→`_metainfo.time_ms`→等得久→先寄）；每封 fork 一個子行程 `run_inst`、環境整份換成信裡的；`recover`（上次死在半路）、`sweep`（寄信人不在就丟）；回信：`reply_to` 有就照 N-16 寄一封（`in_reply_to`、`body`＝`{"code","signal"}` 或 `{"error"}`、附 `stdout.txt`／`stderr.txt`），`done/<信>/reply.json` 當紀錄；`served.jsonl`、`used.json`、額度 `BudgetMissing`；token 回報靠 `AOS_KERNEL_REPORT`。信的 `inst`／`env`／`priority` **過渡期在頂層、還沒包進 `body`**。
- **aos-llm-send**（C++，連 kernel 的公開標頭）：寄＋等＋交回；回信信箱固定 `<kernel 信箱>/reply/`（閘門共用，靠 `in_reply_to` 認自己的）；訊號＝撤信（`new/`→`tmp/`）；等多久由包它那格的 `timeout_ms` 守。
- **aos-post**（C++ lib＋CLI）：`send --reply-to`／`take`／`take-all`／`see`／`done --reply`／`regret`；`letter.json`＝`{"sender","sent_at","reply_to"?,"in_reply_to"?,"body"}`；有序投遞。daemon 的 `procs_ctl_mailbox` 走它、也會照 `reply_to` 回 `{"applied": true}`。
- **aos-daemon**：名單 `procs`、exec 型（跑一次）／loop 型（子 aos-loop）、每個 proc 自己的小格、`AOS_DAEMON` 設給子項、`aos-daemon-ctl add XXX`。所以「kernel 當 daemon 的一個 proc」現在就能做：`demo/llm-kernel` 的 `_entry`＝aos-loop，`aos-daemon-ctl add --name llm demo/llm-kernel`。
- **aos-loop／aos-fsm**：loop 每次跑 `exec`、看碼（0 下一次、10 停、其他錯）；fsm 一次一格、`next` 照結束碼分岔（N-36）。沒有「背景跑」的機制——非同步只能靠「寄了就退、下一格再收」。
- **`bin/aos-llm`**（11-04，Python）：現在是「改定義裡的腦設定」（找 `interfaces.json` 的 `llm` 入口、`def show／set`）；**`bin/aos-tools`**：登記檔 `add／rm／ls／get／call`，已經是不認 agent 的基礎工具。
- **aos-agent**（`extras/agent/bin/aos-agent`）：`llm`／`tools` 子命令改 stack 裡的副本（`$AOS_STACK/llm.json`、`tools.json`），`llm` 經宣告的入口程式（`aos-exec <定義>/llm stack …`）。

## 條文裡「函數」「工具」「腦」怎麼定

- **函數＝資料夾程式**（C-68 資料夾＝程式、入口 `_entry`；C-46 agent 當函數是概念上的、不另造 args.json／ret.json；呼叫＝`aos-exec [--ws] XXX [args]`，N-58；stack＝函數的環境、放哪由呼叫方決定，C-67／P-17）。aos 只訂環境變數＋一支 aos-exec（C-69）；巢狀由程式自己訂（C-70）。
- **工具＝被引用的函數**（C-42：體系每一樣都是 shell 指令、都是 agent 的工具；C-61／N-50 工具是資料夾程式、`tools.json` 登記、不靠 PATH；lib 契約：stdin 一份 JSON、stdout 整段是結果、錯 stderr 一行＋退 1、小格 `$AOS_STACK/tools/<名>/`）。
- **腦**：C-19 簽名的一部分；C-20「很多 agent 時誰先用腦」是 kernel 的核心題；P-23 腦＝OpenAI 相容端點＋三個環境變數（**要改的就是這條**）；N-42 (1) LLM kernel＝「把 brain 弄成一個請求，丟到某個地方，由 kernel 排隊跑」——使用者這次的話就是把 N-42 做到底：**信裡帶的是請求、不是單子**。
- **旋鈕不走環境變數**（N-63 ④、使用者 11-01）：url／model／key 要落在定義檔裡，而且落在**kernel 的**定義裡（使用者 11-04 晚）。
