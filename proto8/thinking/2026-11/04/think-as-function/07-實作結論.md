## 實作時代定（可翻案，一句一條）

1. `aos-llm send`／`ask` 的 stdin＝整份信 body（`{"endpoint"?, "request", "priority"?}`）；`--priority` 有給就蓋 body 的。
2. `loop.json` 的 exec 寫 `{"argv": ["aos-llm-kernel", "kernel.json"]}`（陣列形會被 aos-exec 當目標資料夾）。
3. 每組 endpoint 的指示詞用到那組才解，解不開只讓那封信回 `DirectiveBad`；範本的 LiteLLM 兩組不放金鑰（家機 LiteLLM 不用 key）。
4. 某組不是物件或 `exec` 不是字串＝那封信 `CfgBad`；組裡相對 `exec` 從 kernel.json 所在資料夾算。
5. 回信不附 `stdout.txt`／`stderr.txt`；沒有 `InstUnknown`。
6. kernel 不留舊信：寄完回信就整封刪掉（[08 題 3](08-邊緣狀況實測.md#留給你的題白話推薦放第一)）。
7. `aos-llm send` 在 `--reply-to` 的信箱不在時先建好。
8. agent-fsm 範本的 `llm.json`＝`{}`（kernel 預設 fake）：本機沒 LM Studio 時也跑得動；改法寫在 demo docs 02。
9. think 的 next 寫成 `{"0": "wait", "10": "idle"}`；brain.py 寫新請求時刪 `pending.txt`；wait 一 recv 有結果就先刪 pending，出錯停下後重跑＝重寄原本那份 request.json（停著時改了 `llm.json` 要把 `stage.txt` 寫回 `think` 才生效）。
10. `aos-agent llm set` 底下是 `aos-json set --str`；鍵名含 `/`、`~`＝`ArgumentsBad`；宣告值是資料夾、絕對路徑或含 `..`＝`LlmBad`。cli_session 讀的定義 `llm.json` 固定在 `cli.json` 同一層。
11. json_edit、pyfix 不寫 endpoint（用 kernel 預設）；pyfix 用 `aos-llm ask` 同步一刀。
12. 沙箱範例 `commands` 有 `aos-post`、`aos-tools`（agent-fsm 的 wait／act 要用）。
