## 實作時代定與改設計（可翻案，一句一條）

1. `aos-llm send`／`ask` 的 stdin＝**整份信 body**（`{"endpoint"?, "request", "priority"?}`），不是只有 request；think 寫的 `think/request.json` 就是這形狀。`--priority` 有給就蓋 body 的。
2. **`loop.json` 的 exec 要寫 `{"argv": ["aos-llm-kernel", "kernel.json"]}`**：設計（[02/01 § 6](02-設計-信與kernel/01-endpoint函數-aos-llm-kernel形態.md)、[06 步 3](06-實作步驟.md)）寫的陣列形會被 aos-exec 當目標資料夾（`EntryMissing`）。
3. 每組 endpoint 的指示詞**用到那組才解**，解不開只讓那封信回 `DirectiveBad`（沒設 `LITELLM_KEY` 不會讓整個 kernel 起不來）；範本的 LiteLLM 兩組乾脆不放金鑰（家機 LiteLLM 不用 key）。
4. 某組不是物件或 `exec` 不是字串＝那封信 `CfgBad`；組裡相對 `exec` 一律從 kernel.json 所在資料夾算。
5. 回信不再附 `stdout.txt`／`stderr.txt`（stderr 只留在 kernel 的 `done/`）；served 欄改 `endpoint`、`model`、`error`、`usage_bad`，拿掉 `code`／`signal`／`time_ms`／`metainfo_bad`／`report_bad`；`InstUnknown` 跟 `accept` 一起拿掉。
6. 沒 `sender.flock` 的信（非同步 send）在 `done/` 不收拾、會一直累積（kernel 已知限制）。
7. `aos-llm send` 在 `--reply-to` 的信箱不在時先建好。
8. agent-fsm 範本的 `llm.json`＝`{}`（不寫 endpoint＝kernel 預設 fake），不放設計寫的 `local-qwen`：本機沒 LM Studio 時也跑得動；改法寫在 demo docs 02。
9. think 的 next 寫成 `{"0": "wait", "10": "idle"}`（停著等）；brain.py 寫新請求時順手刪 `pending.txt`；wait 一 recv 有結果就先刪 pending，出錯停下後重跑＝重寄原本那份 request.json（停著時改了 `llm.json` 要把 `stage.txt` 寫回 `think` 才生效）。
10. `aos-agent llm set` 底下是 `aos-json set --str`；鍵名含 `/`、`~`＝`ArgumentsBad`；宣告值是資料夾、絕對路徑或含 `..`＝`LlmBad`。cli_session 讀的定義 `llm.json` 固定在 `cli.json` 同一層。
11. json_edit、pyfix 不寫 endpoint（用 kernel 預設）；pyfix 用 `aos-llm ask` 同步一刀，fsm.json 不動。
12. 沙箱範例 `commands` 補 `aos-post`、`aos-tools`（agent-fsm 的 wait／act 要用）。
13. 條文：換子 agent 的腦有兩種做法（給它的 stack 放 `llm.json` 副本換代號，或叫它那一行換 `AOS_KERNEL`），寫成代定。P-23 原有一句「這台電腦不跑本機模型。」照留（範本有 `local-qwen` 一組，刪不刪等使用者）。
