# 實作步驟表（fable 規劃，11-04 晚；只規劃、沒改程式）

**前提**：使用者看過 [05](05-衝突與方向題.md)（或說「照建議」）再動工。另一個 opus 在 tidy 條文（CONVENTION／NORMS／CONCEPTS），**條文只在步 7 動、排在它之後**；另一個 opus 在改 aos-agent `where`，步 5 碰 `extras/agent/bin/aos-agent` 前先 `git log` 確認它進了 main。每步一個 commit、訊息附使用者原話出處；驗證＝從 repo 根與 `proto8/impls` **build 得過**＋下面寫的手跑（11-04 起沒有測試）；改程式同步 code map（鐵律 3）。多個 agent 同工作樹用 `GIT_INDEX_FILE` 暫存 index。

## 步 0：endpoint 函數（純 Python，不碰 C++，可先做）

- 新 `lib/base/llm_http/`：`_entry`（python3 純標準庫；stdin `{"endpoint","request"}`→POST→stdout `{"message","usage","model"}`，`message` 只留 `role`／`content`／`tool_calls`；錯 `llm_http: 代號 原因` stderr＋stdout、退 1：`ArgumentsBad`、`EndpointFailed`、`ReplyBad`）、`_tooldef.json`、`_metainfo.json`（`resource: ["llm"]`、`parallel: true`）。程式碼從 `demo/agent-fsm/brain.py` 的 `ask()` 搬。
- 新 `lib/base/llm_fake/`：同契約的假腦（從 `brain.py` 的 `fake()` 搬）。
- lib README 索引 base 加兩列；code map 09-lib。
- 手跑：`echo '{"endpoint":{"url":"http://localhost:1234/v1","model":"qwen3-1.7b"},"request":{"messages":[{"role":"user","content":"hi"}]}}' | aos-exec --ws /tmp/w proto8/lib/base/llm_http` 印一行 message；`llm_fake` 同樣印 FAKE ANSWER；stdin 壞＝`ArgumentsBad` 退 1。

## 步 1：kernel 改跑 endpoint 函數（C++ `impls/aos-llm-kernel`）

- `read_cfg`：加 `exec`（必填，aos-exec 目標）、`endpoints`（必填、非空物件）、`endpoint`（選填預設代號，表裡要有）、`timeout_ms`；拿掉 `accept`。指示詞照 `resolve_keys` 解（`endpoints` 整棵）。
- 信：讀 `body.endpoint`（選填字串）、`body.request`（必填物件、`messages` 要是陣列、`stream` 真＝`RequestBad`）、`body.priority`；頂層 `inst`／`env` 不再認（有而沒 `body.request`＝`LetterBad`）。`priority_of` 拿掉 `_metainfo` 兩個依據。
- 跑一封：查代號（`EndpointMissing`／`EndpointUnknown` 回 error）、寫 `<信>/request.json`、fork `run_inst({"argv": ["aos-exec","--stack","<信>/", exec], "stdin": "request.json", "stdout": "reply.json", "stderr": "stderr.txt", "timeout_ms"})`，**環境用 kernel 自己的**（不再換成信裡的）；不設 `AOS_KERNEL_REPORT`。`finish`：讀 `reply.json`→回信 body（讀不懂＝`ReplyBad`、非 0＝`EndpointFailed`＋stderr 第一行）、`usage.total_tokens`→`counter_tokens`、`served.jsonl` 加 `model`、刪 `request.json`。`sweep`：沒有 `sender.flock` 的信不判存活。
- 公開標頭 `llm_kernel.hpp`：信的型別改（`request`／`endpoint` 取代 `inst`／`env`）、代號加 `EndpointMissing`／`EndpointUnknown`／`EndpointFailed`／`RequestBad`；aos-llm（步 2）連它。`budget.cpp` 的 `read_report` 改讀 `reply.json`。
- README 與 docs 01～04 改寫（信的形狀、kernel.json、已知限制那條「信裡帶整份環境」刪）；code map 01-impls-3。
- 手跑（kernel 單獨）：`AOS_STACK=/tmp/k/ aos-llm-kernel kernel.json`（`endpoints` 只有 `fake`）＋手寫一封信 `aos-post send --reply-to /tmp/r /tmp/k/mailbox <<< '{"request":{"messages":[…]}}'`→跑一次→`/tmp/r/new/` 有回信、body 有 `message`；代號寫錯→回信 `error.code`＝`EndpointUnknown`；`stream: true`→`RequestBad`。

## 步 2：`aos-llm` 基礎工具（`impls/aos-llm-send` → `impls/aos-llm`，C++）

- `git mv impls/aos-llm-send impls/aos-llm`；CMake target／`bin/aos-llm`；旗標在位置參數前（`parse_cli`）；子命令 `send [--priority P] --reply-to BOX`、`recv BOX 名`、`ask [--priority P]`、`regret 名`（[02/01 § 5](02-設計-信與kernel/01-endpoint函數-aos-llm-kernel形態.md)）。`post` 改寫：stdin 讀 request、body＝`{"endpoint"?,"request","priority"}`（`--endpoint 代號` 旗標？**不給**：代號寫在 stdin 那份 body 裡，跟 request 一起由呼叫端組；可翻案）；`send` 不建 `sender.flock`、`ask` 建；`recv`＝`find_reply`＋`take`＋印 `body.message`＋`done`；`regret` 包 aos-post。代號：`KernelMissing`、`RequestBad`、`ReplyBad`、`RegretFailed`＋kernel 回的。
- 刪 `proto8/bin/aos-llm`（Python，改定義那支；衝突 1 (a)）；bin README、bin/docs/01、code map 06 刪那列、01-impls-3 改名。`impls/README` 家族表改名。
- 手跑：kernel 開著（`demo/llm-kernel`，步 3）；`echo '{"request":{"messages":[{"role":"user","content":"hi"}]}}' | AOS_KERNEL=… aos-llm ask`→印 message、退 0；`… | aos-llm send --reply-to /tmp/r`→印名字；`aos-llm recv /tmp/r 名`→10（還沒）→0（到了）；`aos-llm regret 名`（剛寄、kernel 停著）→0；沒設 `AOS_KERNEL`→`KernelMissing`。

## 步 3：kernel 當資料夾程式 `demo/llm-kernel/`

- `_entry`＝`["aos-loop","loop.json"]`、`loop.json`＝`{"exec": ["aos-llm-kernel","kernel.json"], "interval_ms": 300}`、`kernel.json`（`endpoints`：`luna`／`sol`（LiteLLM）、`local-qwen`（LM Studio 1234）、`fake`；預設 `endpoint`＝`fake`，key 用 `{"$env": "LITELLM_KEY"}`）。`demo/README.md` 加一段；code map 13-demo。
- （11-04 晚實作時改：`loop.json` 的 exec 要寫 `{"argv": ["aos-llm-kernel", "kernel.json"]}`，陣列形會被 aos-exec 當目標，見 [07](07-實作結論.md) 第 2 條。）
- 手跑：`AOS_STACK=/tmp/k/ aos-exec --ws /tmp/w proto8/demo/llm-kernel &`，`export AOS_KERNEL=/tmp/k/mailbox`，步 2 的 `ask` 通；`aos-daemon-ctl add --name llm proto8/demo/llm-kernel`→`ls` 有、`where`＝stack、`AOS_KERNEL=<stack>/mailbox` 一樣通；`pause`／`stop` 生效。
