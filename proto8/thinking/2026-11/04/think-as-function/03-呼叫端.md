# 呼叫端怎麼接（fable 照原則定，可翻案）

## 1 agent-fsm：idle → think → wait → act

```json
{"start": "idle",
 "states": {
   "idle":  {"exec": {"argv": ["python3", "idle.py"]},                        "next": {"0": "think", "10": "idle"}},
   "think": {"exec": {"argv": ["python3", "brain.py", "--system", "system.txt"]}, "next": "wait"},
   "wait":  {"exec": {"argv": ["python3", "wait.py"]},                        "next": {"0": "act", "10": "wait"}},
   "act":   {"exec": {"argv": ["python3", "act.py"], "timeout_ms": 1800000},   "next": {"0": "think", "10": "idle"}}}}
```

- **think（`brain.py`）只組請求、不碰網路**：system（`--system`）＋`history.jsonl`＋工具清單（`aos-tools ls --json`，副本規則照舊）→ 寫 `$AOS_STACK/think/request.json`（信的 body：`{"endpoint": 代號, "request": {"messages","tools"}}`；代號與選填 `model` 來自定義 `llm.json` 疊 `$AOS_STACK/llm.json` 副本，見 § 4；都沒寫＝不寫 `endpoint`、kernel 用預設）→ 退 0。history 最後一則不是 user／tool＝沒事做、退 10（表上 think 的 `next` 是字串，10 到不了表→fsm 退 10→loop 收工；要「停著等」就把 think 的 next 也寫成物件、接 `"10": "idle"`——照 loop-fsm-agent 衝突 2 的裁法，實作時照範本現狀）。`timeout_ms` 從 think 拿掉（它一下就跑完）。
- **wait（`wait.py`，新）**：
  1. `$AOS_STACK/think/pending.txt` **不在**＝還沒寄：`aos-post init $AOS_STACK/think/reply`（沒有才建）、`aos-llm send --reply-to $AOS_STACK/think/reply < request.json`，信件名稱寫進 `pending.txt`（N-05 暫存改名）、退 10（下一拍再來看）。
  2. 在＝已寄：`aos-llm recv $AOS_STACK/think/reply <pending>`：退 10＝沒到→自己也退 10（loop 隔 `interval_ms` 再來，**loop 照跑、ctl 的 pause／stop 每拍都看得到**）；退 0＝到了→stdout 那則 `message` 接進 `history.jsonl`、刪 `pending.txt`、退 0（→act）；退 1＝kernel 回錯→刪 `pending.txt`、stderr 原樣、退 1（P-20 停下等人；人重跑＝wait 看到沒 pending、`request.json` 還在→**重寄**，這就是重試）。
  3. 沒 pending 也沒 `request.json`＝`RequestMissing`、退 1（人改了 stack）。
- **act（`act.py`）**：最後一則 assistant **沒有 `tool_calls`＝沒事做、退 10**（→idle）；有＝照舊逐個 `aos-tools call`、退 0（→think）。原本「沒 tool_calls＝`HistoryBad`」改掉——判斷「要不要叫工具」從 think 搬到 act，think 退 0／10 的分岔不需要了。
- **stack 佈局**（stack 是自己的地盤，C-70 使用者原話「AOS_STACK/think, /act」）：`think/request.json`、`think/pending.txt`、`think/reply/`（信箱三格）；`llm.json`、`tools.json` 副本照 aos-agent 原設計在 stack 根。
- `.env`、`llm/` 資料夾、`brain.py` 的 `urllib`、假腦分支全刪；`AOS_KERNEL` 沒設＝`aos-llm` 報 `KernelMissing`、wait 退 1。要跑 demo 先起 kernel（[02/01 § 6](02-設計-信與kernel/01-endpoint函數-aos-llm-kernel形態.md)）；試驗場的 daemon 掛一個 `llm` proc、`env.sh` export `AOS_KERNEL`。
- 「思考中來信等答完回 idle 再收」（使用者 11-04 裁）照舊：wait 不看 queue。

## 2 eca（claude／codex）

腦是 CLI，不經 kernel；**不改接**（它自己有額度、有對話）。只跟上 § 4：模型從 `cli.json` 的 `flags` 搬到定義裡的 `llm.json`（`{"model": "sonnet"}`），cli_session 組旗標時讀 `llm.json`（定義）＋`$AOS_STACK/llm.json`（副本）補 `--model`；`demo/eca-claude/llm/` 資料夾與 `bin/aos-eca-llm` 刪。

## 3 工具自己要腦（json_edit、pyfix 的子 agent）

- `impls/aos-json/tools/json_edit/_entry`：兩步問腦都改成 `aos-llm ask < request`（同步語法糖；工具本來就是一次跑完）；`AOS_BRAIN_*` 與 `BrainMissing` 拿掉，`AOS_KERNEL` 沒設由 aos-llm 報 `KernelMissing`。沙箱裡的工具一樣能用（信箱已是 `rw`）。
- `lib/agent/pyfix/agent/brain.py`、`.env`：同 agent-fsm 的改法（think 組請求、wait 收），或先用 `aos-llm ask` 同步一刀（pyfix 是工具形、一次跑完，同步就好；代定同步）。`.env` 刪。
- 遞迴（腦叫的工具又是 agent、它又問腦）：每層各寄各的信、各等各的；kernel 的 `slots` 決定幾封同時跑，深度 aos 不管（C-70）。叫自己＝使用者自己承擔（C-52）。

## 4 aos-agent 的 `llm`／`tools`：縮成語法糖，不再是「子介面入口程式」

使用者：aos-llm、aos-tools 是基礎工具，不是 aos-agent 的附屬。所以 aos-agent **只知道「那隻的 stack 與定義在哪」**（daemon 表的 `stack`／`def` 欄），底下叫基礎工具：

| 子命令 | 現在 | 改成 |
|---|---|---|
| `aos-agent tools --target bob …` | `aos-tools --file <stack>/tools.json …`（copy-on-write） | **不變** |
| `aos-agent llm --target bob show` | `aos-exec <def>/<llm 入口> stack show`（每隻一支入口程式） | 讀 `<def>/llm.json`（沒有＝`{}`）疊 `<stack>/llm.json`，印 `鍵=值`、stderr 一行列副本鍵；**沒有入口程式** |
| `aos-agent llm --target bob set model=qwen` | 入口程式寫 `<stack>/llm.json` | `aos-json set <stack>/llm.json#/model qwen`（檔不在就建；只放改過的鍵，不跟定義，照 11-04 裁） |
| `aos-agent llm --target bob reset` | 入口程式刪副本 | 刪 `<stack>/llm.json` |
| `aos-llm <def> show／set`（改定義） | `bin/aos-llm`（Python） | **刪**；改定義＝人直接 `aos-json set <def>/llm.json#/model x`（跟 aos-tools 改定義一樣是人的事，aos-agent 不包） |

- `interfaces.json` 的宣告：`"llm": "llm.json"`（**值＝定義裡那份腦設定檔的相對路徑**，跟 `"tools": "tools.json"` 同一種寫法；fsm、eca 都一樣）；副本＝stack 裡**同一個相對路徑**。沒宣告＝`LlmMissing`。`aos-agent/llm` 介面、`llm/` 資料夾、`llm.py`、`aos-eca-llm` 全退場；`screen` 照舊（它真的要一支程式）。
- `llm.json` 的鍵由那隻身體認（fsm：`endpoint`＝kernel 那邊的代號、`model`＝臨時覆寫；eca：`model`）；不認的鍵照 C-48 忽略，`KeyUnknown` 拿掉（aos-agent 不懂也不該懂鍵）。`show` 不遮罩——金鑰不在 agent 這邊了。
- 身體的承諾改成一句：**組請求時 `$AOS_STACK/llm.json` 有的鍵蓋過定義 `llm.json`**，每題重讀。

## 5 沙箱

`extras/sandbox/examples/agent.json`：`env` 名單拿掉 `AOS_BRAIN_URL`／`AOS_BRAIN_MODEL`；`commands` 的 `aos-llm-send` 改 `aos-llm`。斷網的 agent 只能經 `$AOS_KERNEL`（`rw`）問腦——本來就是這樣，現在 agent 連金鑰都看不到（金鑰在 kernel 那邊的 `kernel.json`、kernel 的環境或 `$ref` 的檔，沙箱 `ro` 的定義資料夾裡沒有）。跨帳號回信信箱權限那題（WAIT_USER 既有）不變：非同步時回信信箱在 agent 自己的 stack（`rw`），kernel 要寫得進去。
