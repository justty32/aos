# 呼叫端怎麼接（fable 照原則定，可翻案）

## 1 agent-fsm：idle → think → wait → act

```json
{"start": "idle",
 "states": {
   "idle":  {"exec": {"argv": ["python3", "idle.py"]},                        "next": {"0": "think", "10": "idle"}},
   "think": {"exec": {"argv": ["python3", "brain.py", "--system", "system.txt"]}, "next": {"0": "wait", "10": "idle"}},
   "wait":  {"exec": {"argv": ["python3", "wait.py"]},                        "next": {"0": "act", "10": "wait", "11": "think"}},
   "act":   {"exec": {"argv": ["python3", "act.py"], "timeout_ms": 1800000},   "next": {"0": "think", "10": "idle"}}}}
```

- **think（`brain.py`）只組請求、不碰網路**：system＋`history.jsonl`＋工具清單（`aos-tools ls --json`）→ 寫 `$AOS_STACK/think/request.json`（整份信 body：`{"endpoint": 代號, "request": {"messages","tools"}}`；代號與選填 `model` 來自定義 `llm.json` 疊 `$AOS_STACK/llm.json` 副本，見 § 4；都沒寫＝不寫 `endpoint`、kernel 用預設）、順手刪 `pending.txt`、退 0。history 最後一則不是 user／tool＝沒事做、退 10（→idle）。think 沒有 `timeout_ms`。
- **wait（`wait.py`）**：
  1. `$AOS_STACK/think/pending.txt` 不在＝還沒寄：`aos-llm send --reply-to $AOS_STACK/think/reply < request.json`，信件名稱寫進 `pending.txt`（N-05 暫存改名）、退 10。
  2. 在＝已寄：`aos-llm recv $AOS_STACK/think/reply <pending>`，一有結果就先刪 `pending.txt`：退 10＝沒到→自己也退 10（loop 隔 `interval_ms` 再來，ctl 的 pause／stop 每拍都看得到）；退 0＝到了→那則 `message` 接進 `history.jsonl`、退 0（→act）；退 1＝kernel 回錯→stderr 原樣、退 1（P-20 停下等人；人重跑＝重寄原本那份 `request.json`，這就是重試；停著時改了 `llm.json` 要把 `stage.txt` 寫回 `think` 才生效）。
  3. 沒 pending 也沒 `request.json`＝退 11 回 think，從 history＋目前定義／覆蓋層重組再寄；有 pending 時照第 2 步收原回信（11-06 git-image 裁定，image 不存可重建請求）。
- **act（`act.py`）**：最後一則 assistant 沒有 `tool_calls`＝沒事做、退 10（→idle）；有＝逐個 `aos-tools call`、退 0（→think）。
- **stack 佈局**（stack 是自己的地盤，C-70 使用者原話「AOS_STACK/think, /act」）：`think/request.json`、`think/pending.txt`、`think/reply/`（信箱）；`llm.json`、`tools.json` 副本在 stack 根。
- 範本沒有 `.env`、`llm/` 資料夾、`urllib`、假腦分支；範本的 `llm.json`＝`{}`（kernel 預設 `fake`，本機沒 LM Studio 也跑得動）。`AOS_KERNEL` 沒設＝`aos-llm` 報 `KernelMissing`、wait 退 1。要跑先起 kernel（[02/01 § 6](02-設計-信與kernel/01-endpoint函數-aos-llm-kernel形態.md)）。
- 「思考中來信等答完回 idle 再收」（使用者 11-04 裁）照舊：wait 不看 queue。

## 2 eca（claude／codex）

腦是 CLI，不經 kernel、不改接。模型在定義裡的 `llm.json`（`{"model": "sonnet"}`，跟 `cli.json` 同一層），cli_session 組旗標時讀定義 `llm.json`＋`$AOS_STACK/llm.json` 補 `--model`；沒有 `aos-eca-llm`、`llm/` 資料夾。

## 3 工具自己要腦（json_edit、pyfix）

- `impls/aos-json/tools/json_edit/_entry`：兩步問腦都用 `aos-llm ask`（同步；工具一次跑完）；沒有 `AOS_BRAIN_*`、`BrainMissing`；不寫 endpoint（用 kernel 預設）。
- `lib/agent/pyfix`：`aos-llm ask` 同步一刀、不寫 endpoint、沒有 `.env`。
- 遞迴（腦叫的工具又是 agent、它又問腦）：每層各寄各的信、各等各的；kernel 的 `slots` 決定幾封同時跑，深度 aos 不管（C-70）。叫自己＝使用者自己承擔（C-52）。

## 4 aos-agent 的 `llm`／`tools`：語法糖，沒有子介面入口程式

aos-llm、aos-tools 是基礎工具，aos-agent 只知道「那隻的 stack 與定義在哪」（daemon 表的 `stack`／`def` 欄），底下叫基礎工具：

| 子命令 | 做法 |
|---|---|
| `aos-agent tools --target bob …` | `aos-tools --file <stack>/tools.json …`（copy-on-write） |
| `aos-agent llm --target bob show` | 讀 `<def>/llm.json`（沒有＝`{}`）疊 `<stack>/llm.json`，印 `鍵=值`、stderr 一行列副本鍵 |
| `aos-agent llm --target bob set model=qwen` | `aos-json set --str <stack>/llm.json#/model qwen`（檔不在就建；只放改過的鍵，不跟定義） |
| `aos-agent llm --target bob reset` | 刪 `<stack>/llm.json` |
| 改定義 | 人直接 `aos-json set <def>/llm.json#/model x`，aos-agent 不包 |

- `interfaces.json` 的宣告：`"llm": "llm.json"`（值＝定義裡那份腦設定檔的相對路徑，跟 `"tools": "tools.json"` 同一種寫法；fsm、eca 都一樣）；副本＝stack 裡同一個相對路徑。沒宣告＝`LlmMissing`；宣告值是資料夾、絕對路徑或含 `..`＝`LlmBad`；鍵名含 `/`、`~`＝`ArgumentsBad`。`screen` 照舊（它真的要一支程式）。
- `llm.json` 的鍵由那隻身體認（fsm：`endpoint`＝kernel 那邊的代號、`model`＝臨時覆寫；eca：`model`）；不認的鍵照 C-48 忽略。`show` 不遮罩（金鑰不在 agent 這邊）。
- 身體的承諾：組請求時 `$AOS_STACK/llm.json` 有的鍵蓋過定義 `llm.json`，每題重讀。

## 5 沙箱

`extras/sandbox/examples/agent.json`：`env` 名單沒有 `AOS_BRAIN_*`；`commands` 有 `aos-llm`、`aos-post`、`aos-tools`。斷網的 agent 只能經 `$AOS_KERNEL`（`rw`）問腦，看不到金鑰。非同步時回信信箱在 agent 自己的 stack（`rw`），跨帳號時 kernel 要寫得進去（WAIT_USER 既有的那題）。
