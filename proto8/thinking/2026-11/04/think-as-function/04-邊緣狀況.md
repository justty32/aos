# 邊緣狀況（代定或現成機制，可翻案）

實測與使用者裁定見 [08](08-邊緣狀況實測.md)。

| # | 狀況 | 怎麼辦 |
|---|---|---|
| 1 | 端點連不上、HTTP 非 2xx、回覆不是 OpenAI 形狀 | endpoint 函數退 1 → 回信 `error: EndpointFailed／ReplyBad` → `aos-llm recv` 退 1 → fsm 停在 wait（P-20，不自動重試）；人重跑＝重寄。kernel 照跑下一封。 |
| 2 | kernel 額度用完 | 回信 `error: BudgetMissing`（或 kernel 設成等下一窗、信留著）；同上停在 wait。 |
| 3 | 端點跑太久 | kernel.json `timeout_ms` → 整群 TERM → `EndpointFailed 143`。wait 沒有自己的逾時；要上限寫 `priority.deadline`（`DeadlineMissed`）。 |
| 4 | kernel 不在 | 信堆在 `new/`、wait 每拍退 10 一直等；kernel 起來就接著跑。死在半路：`recover` 回 `RunFailed`。 |
| 5 | 寄完 agent 被 `stop`／`pause` | wait 一下就退，ctl 每拍生效；重 `start` 同一 stack：`pending.txt` 在→接著 `recv`，回信還在 agent 自己的信箱。 |
| 6 | 寄完 agent 被 `rm` | kernel 照跑、回信寄不進，浪費一次腦；要避免先 `aos-llm regret <pending>`（還在 `new/` 才撤得掉）。aos-agent `rm` 不順手撤。 |
| 7 | 取消 | 排隊中：`aos-llm regret 名`；跑了撤不了，回信留在 agent 自己信箱 `new/`、自己清。kernel 撤回沒人拿的回信只對有 `sender.flock` 的信做。 |
| 8 | 同時好幾封 | 一隻 fsm 一次一封；多隻 agent 各寄各的，`slots` 決定並行、`priority` 決定先後（C-20「誰先用腦」）。fan-out＝自己管好幾個 pending，aos 不另給機制。 |
| 9 | 共用回信信箱（`ask` 用 `$AOS_KERNEL/reply/`） | 照 `in_reply_to` 只拿自己的；非同步一律用自己 stack 的信箱。 |
| 10 | 舊信、舊回信 | `recv` 認名字，不是自己 pending 的不碰；`think/request.json` 每次 think 覆寫。 |
| 11 | 串流 | 不做；`stream: true`＝`RequestBad`。 |
| 12 | 成本 | kernel 從回信 `usage` 記 token；agent 自己不記。經 eca 的 CLI 不在這套裡。 |
| 13 | 金鑰 | 只在 kernel 的 `kernel.json`（`{"$env"}`／`{"$ref"}`，或直接寫——寫了就別把 kernel 定義 commit 進 repo）；不跟信走、不進 agent 的環境。跑信時的 `request.json` 含解好的金鑰→信箱要在 kernel 自己的 stack；kernel 處理完整封信刪掉。 |
| 14 | 請求太大 | 信沒有大小上限；端點回 4xx 就是第 1 條。 |
| 15 | 換模型、換端點 | 信寫代號 `endpoint`；臨時換同端點的模型＝`request.model`；不認的代號＝`EndpointUnknown`；信改不了 url／key。agent 平常用哪組＝它的 `llm.json`（副本可換，`aos-agent llm set endpoint=sol`）。要另一個額度才另起一個 kernel。 |
| 16 | 沙箱裡 | 斷網 agent 只有 `rw` 的 `$AOS_KERNEL`；跨帳號回信信箱權限照 WAIT_USER 既有的 `setup.sh --mailbox` 那題。 |
| 17 | `interval_ms` 太長 | 回信最多晚一拍收（兩邊各一拍）；要快就調小。「回信一到就醒」＝N-14 inotify，以後。 |
| 18 | eca 用 kernel？ | 不用：eca 的腦是 CLI、自己有對話狀態（使用者 11-01「大多」agent 經 kernel，不是全部）。 |
| 19 | `aos-llm ask` 被訊號打斷 | 撤信；已跑的跑完、回信由 kernel 撤回。 |
| 20 | 舊閘門的信 | 只有頂層 `inst`／`env`＝`LetterBad`；不留兩種信（C-54）。 |
