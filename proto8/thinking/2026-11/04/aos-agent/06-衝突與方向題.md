## 要使用者看的

寫給不看 CS 術語的人。只有兩種：新設計跟既有條文打架的（衝突），和原則推不出答案的（方向題）。其餘細節都照原則定了，在 [01](01-子命令.md)～[04](04-過渡與邊緣.md)，可翻案。

### 衝突 1：`.aos/agent.json` 寫進工作區，對上 C-65／P-42 與 11-03 工作區不放 stack

- **哪條**：C-65「工作區只放交辦的東西與成果」；P-42「三樣（queue、history、ctl／state）以外不碰工作區」；11-03 你定的「工作區不放子項的 stack」（拿掉 `.stack` 捷徑，aos-daemon-ctl「不碰 WS」）。
- **衝突在哪**：你 11-04 說的擴充——資料夾裡有 `.aos/agent.json` 就是被某隻 agent 佔了——是往使用者的資料夾放一個 aos 的檔。跟 11-03 剛拿掉的 `.stack` 捷徑長得像（都是「資料夾裡放一個指向 agent 的東西」）。
- **各自後果**：
  - **(a) 留著，當可選擴充（fable 選的）**：只在人下 `aos-agent occupy` 時才寫、內容只有名字＋daemon 位置兩行、agent 的身體從不寫它；`rm` 順手拿掉。好處：cd 進資料夾就能說，不用記名字、不用設環境變數（連「`AOS_DAEMON_STACK` 要絕對路徑」那條限制都避開了）。代價：C-65／P-42 要加一句註；工作區多一個隱藏資料夾 `.aos/`。
  - **(b) 不留，一律給名字**：工作區完全乾淨、條文不用動。代價：每次都要 `aos-agent say bob 話`，而且你 11-04 明說要這個擴充。
- **例子**：`cd ~/code/myproj && aos-agent say 把 README 整理一下 && aos-agent listen`——(a) 行得通（之前 `aos-agent occupy bob` 過）；(b) 要寫 `aos-agent say bob 把 README 整理一下`。
- **建議 (a)**，條文加註。

### 方向題 1：`.aos/agent.json` 誰寫、怎麼寫？

- **背景**：你 11-03 說「agent本身會在工作區建立.aos/agent/相關東西」，11-04 改說 agent 是 daemon 管的 proc、佔資料夾只是擴充、「agent通常是不需要佔據資料夾的」。誰負責寫這個檔，原則兩邊都有話：C-65／P-42 說 agent 的身體只碰 stack（所以不該是身體寫）；你 11-02 晚喜歡成對的指令（open/close、start/stop、add/rm）。
- **(a) 一對新子命令 `occupy`／`release`（fable 選的）**：`aos-agent add … && aos-agent occupy bob`；想換人佔就 `release` 再 `occupy`；`rm` 順手拿掉。好處：佔不佔是獨立一步、看得見、可以事後改，跟三對指令同一風格；身體不碰工作區。代價：多兩個子命令、常見流程多打一行。
- **(b) `add --occupy` 旗標**：掛的時候一起佔。少一行；代價：佔資料夾跟「掛到 daemon」綁在一起，事後要佔只能 rm 再 add；`rm` 的「順手拿掉」變成暗規則。
- **(c) agent 自己寫（11-03 原話）**：aos-eca-turn／idle.py 起來時寫 `<工作區>/.aos/agent.json`。代價：違反 P-42 三樣以外不碰工作區、兩種身體各寫一份同樣的事、「通常不需要佔」就得再加旗標關掉。
- **例子**：想讓 bob 替 `~/code/myproj` 幹活並且 cd 進去就能說。(a)：`aos-agent add --ws ~/code/myproj --name bob proto8/demo/eca-claude && cd ~/code/myproj && aos-agent occupy bob`。(b)：`aos-agent add --occupy --ws ~/code/myproj --name bob …`。(c)：add 完 bob 跑第一圈自己寫。
- **建議 (a)**。

### 方向題 2：`say` 的名字怎麼給？

- **背景**：其他子命令都是 `aos-agent 子命令 [名字|資料夾]`，名字是唯一的位置參數。`say` 後面還有「話」，而且你 11-04 要「cd 進佔了的資料夾、不給名字就能說」——那第一個字到底是名字還是話的開頭，程式分不出來。原則（C-54 好懂、C-56 不藏暗規則）推不出哪一種最順手。
- **(a) 第一個字是表上的名字就當名字，否則整串是話；撞到就放 `--`（fable 選的）**：`aos-agent say bob 現在幾點`、`aos-agent say 現在幾點`（佔了的資料夾）都行；話剛好以某隻名字開頭（例：你有隻叫「現在」的 agent）寫 `aos-agent say -- 現在幾點`。代價：有一條「查表決定」的規則要記；取名像常用字的 agent 會踩到。
- **(b) 名字一律用旗標 `--name N`**：`aos-agent say --name bob 現在幾點`；不給就看標記。沒有歧義；代價：跟其他子命令（位置參數）不一致、多打六個字。
- **(c) 名字一律要給，佔了的資料夾用 `.`**：`aos-agent say . 現在幾點`。沒有歧義、形式統一；代價：「cd 進去就能說」還是要多一個 `.`，跟你 11-04 說的「aos-say 會去找當前資料夾」差一點。
- **建議 (a)**；`listen` 同一條規則（它後面沒有話，所以沒歧義）。

### 方向題 3：舊指令怎麼退場？

- **背景**：aos-say、aos-listen、aos-eca 的事全部搬進 aos-agent 之後，三支舊指令與 `extras/human`、`extras/eca` 兩個資料夾怎麼辦。你 11-03 對 round 說「該刪的都刪光刪乾淨」、對 aos-chat 說「可以先封存」——兩種口味都有過，推不出。
- **(a) 做完、測試全綠就直接刪（fable 選的）**：`extras/human`、`extras/eca` 整個刪（`aos-eca-turn` 在 bin、不動），`test_human.py`／`test_eca_cmd.py` 的案子改寫成 `test_agent_cmd.py` 的；README、demo、bin 的例子全改 `aos-agent`。好處：一套指令、沒有兩個名字做同一件事（C-56）；thinking 的歷史紀錄留著就夠。代價：你手上若有用 `aos-say`／`aos-eca` 的 shell 歷史要改；刪了就沒有回頭路（git 有）。
- **(b) 留薄殼一輪**：`aos-say 話`＝`aos-agent say 話`、`aos-eca X`＝`aos-agent X`，各三行，下一次大整理再刪。代價：三個名字並存、README 要解釋兩套、測試兩套。
- **(c) 封存到 `proto8/archive/`**：像 aos-chat。代價：封存的程式沒人跑、很快就跟 lib 對不上。
- **例子**：你習慣打 `aos-say 現在幾點 && aos-listen`。(a) 改打 `aos-agent say 現在幾點 && aos-agent listen`（cd 在佔了的資料夾裡）；(b) 舊的照打、底下轉。
- **建議 (a)**；分開一個 commit 刪，要回頭 revert 那一個就好。

## 使用者回覆（11-04 晚，逐字）：介面細節

> --to，改成--target吧。這東西沒給的話就是吃AOS_AGENT。然後rm後面不用接--target，aos-agent rm xxx這樣就好。aos-agent add --name bob ../agents/bob這樣。然後我預期add這件事，他就是只吃指定介面，內部實現無所謂，你要是eca/fsm都可以。我就是不太喜歡要透過特定檔案去判斷是哪個這種。之後跟我說說這個介面長啥樣。加上一個status作為state的別名。然後幫我弄個aos-agent chat指令，ctrl-c退出。然後AOS_DAEMON_STACK實在太醜，還是直接簡化成AOS_DAEMON就好了，就跟剛剛那個AOS_AGENT一樣，原本我還想要用AOS_AGENT_TARGET的。

決定（11-04）：
- 指定對象的旗標是 **`--target 名字`**（取代 `--to`）；沒給＝環境變數 **`AOS_AGENT`**。

- `status` 是 `state` 的別名（原規劃已有，照舊）。
- 新增 **`aos-agent chat`**：互動對話，Ctrl-C 退出。
- 環境變數 **`AOS_DAEMON_STACK` 改名 `AOS_DAEMON`**（全 repo 一起改）。
