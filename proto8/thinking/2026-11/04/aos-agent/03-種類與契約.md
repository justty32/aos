## 種類怎麼認（不用旗標、不寫名片）

一隻 agent 的「種類」只決定四件事（下節契約）；其他子命令對所有種類一樣。認法靠**形狀**（C-53 入口默認正常、C-54 結構就是說明；11-03「kind 刪掉」所以沒有 `--kind`）：

- **從定義資料夾認**（`add` 時，XXX 在手上）：
  - 頂層有 `cli.json` → **eca**（跟 aos-eca `is_eca` 同一句）。
  - 有 `loop.json`、它的 `exec` 是**字串**、指到一個 fsm 表（那份 JSON 有 `states`）→ **fsm**（agent-fsm 範本：`{"exec": "fsm.json", …}`）。
  - 都不是 → `KindUnknown`，訊息說認得哪兩種、各看什麼檔。以後多一種就多一條。
- **從 stack 認**（`ls`／`state`／`stop`／`rm` 時，手上只有表那一列）：讀 daemon 起它時寫進 stack 的 **`loop.json`**（aos-daemon-ctl 把定義的 `loop.json` 相對路徑轉絕對後交給 daemon、daemon 寫在小格；loop-fsm 01 § 7「`loop.json`……只有掛 daemon 時 daemon 寫」）：它的 `exec` 是絕對路徑字串——fsm 的指到 `<定義>/fsm.json`、eca 的是 `<定義>/loop.json#/exec`（內嵌單子被換成指回原檔，bin/README「自動識別」那條）。**兩種都能從 `exec` 的路徑取回定義資料夾**，再照上面「從定義資料夾認」。**等實作確認**：daemon 寫的 `<stack>/loop.json` 的 `exec` 在兩種情況下長什麼樣（含 `#/exec` 那段怎麼切）。
- 所以**不另寫名片**：loop-fsm 02 對照表說「統一介面若要 `ls` 列出哪些是 agent，要一個共同名片」——不用，表上那列＋stack 裡 daemon 寫的 `loop.json` 就夠（零新檔，C-56）。eca 現有的 `eca.json`（aos-eca-turn 每圈寫 `kind`／`ws`／`template`）過渡期照認（只拿 CLI 種類 claude／codex 給 `ls` 印），aos-eca 退場後可以不寫（[04](04-過渡與邊緣.md)）。
- `ls` 的範圍＝表上**認得出種類**的列；認不出（exec 型、別的 loop）不列——不是 agent。`stack/loop.json` 還沒寫（剛 add、daemon 還沒跑下一圈）的那隻 `ls` 暫時看不到，`add` 等上表後才回所以人不會踩到；`state 名字` 這時說「剛掛上、等 daemon 起它」（跟 aos-eca「ls 要等子 loop 跑第一次」同性質，但只等一圈）。

## 種類要提供什麼（介面契約）

寫成一句：**種類＝「認、驗、收尾、多印幾行＋畫面」四組函數**；其他一律不歸種類。單檔 Python 裡兩個小 class（eca、fsm），長到第三種再拆檔（10-31「先做成單檔案」、lib 規則 9）。

| 契約 | eca | fsm | 誰叫 |
|---|---|---|---|
| `detect(定義)` 這是我的嗎 | 有 `cli.json` | `loop.json` 的 `exec` 是字串、指到有 `states` 的 JSON | add、從 stack 認 |
| `check(定義)` 掛之前驗（不送信） | 照 aos-eca 現行：`cli.json` 形狀、`tools` 指的檔、`loop.json` 的 `--prompt` 指的檔 | 讀 fsm 表：三格的 argv 第 2 個（`idle.py` 等）在不在、各格旗標 `--prompt`／`--system`／`--tools` 指的檔在不在（相對定義資料夾算；沒旗標＝不驗）、`tools.json` 若在是不是登記檔。**等實作確認**：旗標名與 argv 形狀照 `demo/agent-fsm/fsm.json` 定版 | add |
| `before_stop(列)`／`before_rm(列)` 收尾 | 關畫面（`SessionBad` 若正在答） | 沒事 | stop、rm |
| `state_lines(列)` 多印幾行 | 畫面 open／closed、session 前 8 碼、CLI 種類、工具箱 | 現在哪一格（stack 的 `state.txt`，aos-fsm 寫）、工具箱（`tools.json` 登記了幾個） | state、ls 那一欄 |
| `open／close／watch(列)` 畫面（選配） | cli_session 的 open_cell／kill-server／讀 `live.jsonl` | 沒有 → 介面層回 `ScreenMissing`，指去 `listen --follow` | open、close、watch |

**不歸種類的**（介面層自己做，只碰 stack 三樣與 daemon 表）：找 agent、add 的投信與等上表、rm 的刪 stack 與拿標記、start／stop／pause／resume／where 轉 aos-daemon-ctl、say／listen（aos_ws）、occupy／release、`state` 的共同幾行（phase、paused、種類、定義、工作區、stack、queue 排幾封）。種類**不准**改 history、不准寫工作區、不准自己起行程（除了 eca 的畫面，那是它存在的理由）。

**暫停粒度**不是契約：兩種都是寫同一個 ctl（`aos-daemon-ctl pause`），只是說明要寫清楚 eca 停在一批信之間、fsm 停在一格之間（可以改 history 再 resume）。

## eca 與 fsm：哪些統一、哪些保留

照 [loop-fsm 02 對照表](../loop-fsm-agent/02-跟-eca-對照.md)逐條：

| 差異 | 統一還是保留 | 怎麼做 |
|---|---|---|
| 一輪的身體（aos-eca-turn vs 三格） | **保留**，介面不碰 | — |
| queue 空要不要收工（`--on-empty` 旗標 vs 表上 idle 的 `next`） | **保留**（寫在各自定義裡，P-42「寫在定義裡」） | `state` 多印一行「queue 空時：停著等／收工」——eca 讀 loop.json 的 `--on-empty`、fsm 讀表上 idle `next` 的 `10` 有沒接。**等實作確認**。不做「add 時替人改」 |
| 暫停粒度 | **統一**成同一個子命令 `pause`／`resume`，粒度差只寫說明 | 轉 aos-daemon-ctl |
| 工具箱 | **已統一**：同一份 `tools.json` 登記檔、同一條相對路徑規則；腦看到的名字前綴（`mcp__aos__`）是 CLI 的事 | `state` 的「工具箱」一行兩邊同一段程式 |
| 腦 | **保留**，介面不管腦 | — |
| 對話全貌（history 只有一問一答 vs 全貌） | **統一**「看回答」＝`listen`（兩邊 history 都有）；eca 的 CLI 全貌是種類的事（`open`／`watch`） | — |
| 畫面、busy | **保留**在種類（`open`／`close`／`watch` 只有 eca 回應） | fsm＝`ScreenMissing` |
| 名片（`eca.json`） | **抹平**：種類從 stack 的 `loop.json` 認，不靠名片 | 過渡期照認 `eca.json` 的 CLI 種類 |
| 管理命令列（aos-eca 九個 vs 只有 aos-daemon-ctl） | **統一**成 aos-agent 一套（[01](01-子命令.md)） | aos-eca 退場見 [04](04-過渡與邊緣.md) |
| 入口檢查（aos-eca add 先驗 vs daemon add 不驗） | **統一**：兩種都在 `add` 先驗，驗什麼由種類 `check` 說 | fsm 的 check 是新寫的那塊 |
| 交出去後掛掉／中途來信 | **保留**各自語意（都是「邊緣不影響原意」） | `state` 看得出：eca＝history 停在 user、fsm＝`state.txt` 停在 think |
| 信什麼時候收 | **已統一**（接進去就收，11-04 衝突 1 裁定） | listen 的判法兩邊一樣 |
