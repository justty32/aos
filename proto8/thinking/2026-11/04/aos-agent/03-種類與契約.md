## 介面 `aos-agent`：裡面有什麼（fable 照原則定的，可翻案）

像 Go 的 interface：下面每一條是一個「方法」，遵守＝全做到。兩個範本今天的行為就全符合（P-42 本來就是這套），差的只是宣告（最後一節）。

| # | 項目 | 約定 | 依據 |
|---|---|---|---|
| 1 | 起法（argv） | 是資料夾程式：有 `_entry`（C-68、C-73），`aos-exec --ws WS XXX` 起得來、**不帶 args**（`add` 不收 `-- 參數`；旋鈕寫在自己定義裡）；掛 daemon 時 daemon 用同一句起（N-28） | C-69 |
| 2 | 環境變數 | 只吃 aos 給的：六個（N-57）與 hub 型 `AOS_DAEMON`（N-63）；自己的設定走定義的 `.env`。aos-agent 不另設變數給它 | C-69、11-01 |
| 3 | 常駐與窗 | 起來後不自己退（queue 空停著等；「射後不理」寫在定義裡，P-42）；`$AOS_STACK/ctl.json`／`state.json` 是 aos-loop 的窗（`{"cmd": "pause"\|"resume"\|"stop", "seq": N}`、`phase`）——實作上＝`_entry` 是 aos-loop、`loop.json` 開這兩扇 | P-42 ③、N-07、N-17 |
| 4 | 信箱 | `$AOS_STACK/queue/`＝aos-post 信箱（N-16）；一封 body＝`{"role": "user", "content": 非空字串}`；接進對話那一刻就 `aos-post done`；壞信丟掉、`$AOS_STACK/mailbox_warning.txt` 覆寫一行、不回信。寄信人可先 `aos-post init`（先說、再起） | P-42 ①、loop-fsm 衝突 1、eca 20 |
| 5 | 對話 | `$AOS_STACK/history.jsonl`，一行一則 OpenAI message、只附加；**回答＝最新那則沒 `tool_calls` 的 assistant** | P-42 ②、P-41 |
| 6 | stderr／結束碼 | 錯＝stderr 一行 `程式名: 代號 原因`、退 1（掛 daemon 時進小格 `stderr.txt`）；退了就下表、stack 留 | P-20、P-21、11-02 |
| 選配 | 子介面 `tools`／`llm` | 看／改工具箱、看／換腦（使用者 11-04 晚追加）：`tools` 宣告登記檔在哪、`llm` 宣告一個入口；細節、生效時機、改定義不改 stack 在 [03/01](03-種類與契約/01-tools-llm-與兩個範本要改什麼.md) | 同 `screen` |
| 選配 | 子介面 `screen` | 宣告裡給一個入口（相對定義資料夾）。aos-agent 用 `aos-exec --ws <它的 ws> --stack <它的 stack> <定義>/<入口> open [-d]`／`close`／`watch` 叫它，stdio 接呼叫者的（tmux attach 拿得到終端機）；退 0＝做了，非 0＝它自己 stderr 一行 | C-73、C-68 |

**不在介面裡的**（aos-agent 不知道、不問、不印）：腦是誰、工具箱（除非宣告了選配子介面 `llm`／`tools`，見 03/01）、暫停粒度（一批信或一格；都是經 aos-daemon-ctl 寫同一個 ctl，停在哪是身體的事，C-52）、queue 空收不收工、對話全貌在哪（eca 的 `transcripts/`）、定義裡還有哪些檔。沒有 `kind`（11-03）。

## agent 怎麼宣告：定義資料夾裡一份 `interfaces.json`

```json
{"aos-agent": {"tools": "tools.json", "llm": "llm"}}                      ← agent-fsm：遵守 aos-agent，選配 tools、llm
{"aos-agent": {"screen": "screen", "tools": "tools.json", "llm": "llm"}}  ← eca-claude：再加子介面 screen，入口是同層的 screen 檔
```

- **放哪**：定義資料夾頂層，固定名 `interfaces.json`（複數裝同類，C-54；一份宣告它遵守的所有介面，以後有別的介面也寫這裡）。key＝介面名；值＝那個介面的選配與參數（純值不夠就長成物件，C-55）；不認得的 key 忽略（C-48）。**為什麼不塞進 `_entry`**：兩個範本的 `_entry` 都是 argv 陣列，沒地方放 key。**為什麼是定義不是 stack**：宣告跟 class 定義放一起（Go 的 interface 是寫在型別那邊），`add` 掛之前就看得到；stack 是跑起來才有。固定名字第二個（`_entry` 之外）：C-51 10-31 加註「參與者少又穩定時固定就好」、11-01「註冊檔與固定名字可以共存」——這份就是註冊檔。
- **為什麼不算「靠特定檔案判斷是哪個」**：`cli.json`／`loop.json` 是實作的檔，看它們＝猜；`interfaces.json` 是 agent 自己說「我遵守什麼」，aos-agent 只讀這一句、不碰其他檔，裡面是 eca、fsm 或別的都一樣。
- **aos-agent 怎麼用**：`add` 讀 `<XXX>/interfaces.json`——不在、或沒有 `aos-agent` 這個 key＝`InterfaceMissing`「XXX 沒宣告遵守 aos-agent 介面」、不送信；讀不懂（不是 JSON 物件、值不是物件）＝`InterfaceBad`。只看宣告、**不驗內容**（C-53 (a) 入口默認正常、C-52 加嚴「不替下層驗」）：不看 `_entry` 是不是 aos-loop、不看 loop.json 有沒有開窗。這跟 aos-eca `add` 今天先驗 cli.json／tools／prompt 不同，見[衝突 2](06-衝突與方向題/02-新題-11-04-晚.md#衝突-2add-不再先驗對上-11-03-eca-tools入口先檢查不送信)。
- **宣告了卻沒做到**（照 C-53 各層只說自己的錯，aos-agent 不替它驗，後果在 [04 邊緣表](04-過渡與邊緣.md#失敗與邊緣狀況)）：不是 loop 型＝跑一次就下表，`pause`＝aos-daemon-ctl 的 `CtlMissing`；不收 queue＝`listen` 一直等、`state` 看得到排著幾封；history 不照格式＝`AnswerMissing`；`screen` 宣告的入口不在或退非 0＝`ScreenBad`（訊息帶它的 stderr 那一行）；沒宣告 `screen`＝`ScreenMissing`，訊息指去 `listen --follow`。
- **`open`／`close`／`watch` 時怎麼找回定義**：daemon 表那一列只有名字、phase、stack、ws，沒有定義路徑；要讀宣告得知道定義在哪。[方向題 1](06-衝突與方向題/02-新題-11-04-晚.md#方向題-1open-時怎麼知道定義在哪)使用者 11-04 晚裁「daemon 表多一欄記下來」：`procs_state.json` 每列多一欄 `exec`＝add 時的目標（絕對路徑），`open`／`tools`／`llm` 都從那欄找定義。
