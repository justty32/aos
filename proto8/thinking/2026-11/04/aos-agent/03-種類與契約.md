使用者 11-04 晚：「add這件事，他就是只吃指定介面，內部實現無所謂……我就是不太喜歡要透過特定檔案去判斷是哪個這種。」——aos-agent **沒有「種類」**，只有介面。同晚兩段原則（原文逐字在 [06](06-衝突與方向題.md#使用者原文11-04-晚逐字介面與-stack)）：**stack 是 proc 自己的地盤，放啥都行；對外介面四類——命令列參數、吃／設的環境變數、stdin／out／err／結束碼、信箱內容格式**（原文說「三類」、列了四樣，照四樣）；**去讀寫 agent stack 裡的檔沒問題，像 class 宣稱自己遵守某個 interface（golang interface）**。所以：介面＝一組約定（stack 裡有哪些東西、什麼格式，加上四類對外介面）；agent **自己宣告遵守**；aos-agent **只認宣告、不猜**。

## 介面 `aos-agent`：裡面有什麼（fable 照原則定的，可翻案）

像 Go 的 interface：每一條是一個「方法」，遵守＝全做到。兩個範本（eca-claude、agent-fsm）的行為全符合，各加一份宣告。

| # | 項目 | 約定 | 依據 |
|---|---|---|---|
| 1 | 起法（argv） | 是資料夾程式：有 `_entry`（C-68、C-73），`aos-exec --ws WS XXX` 起得來、**不帶 args**（`add` 不收 `-- 參數`；旋鈕寫在自己定義裡）；掛 daemon 時 daemon 用同一句起（N-28） | C-69 |
| 2 | 環境變數 | 只吃 aos 給的：六個（N-57）與 hub 型 `AOS_DAEMON`（N-63）；自己的設定走定義的 `.env`。aos-agent 不另設變數給它 | C-69、11-01 |
| 3 | 常駐與窗 | 起來後不自己退（queue 空停著等，P-42）；`$AOS_STACK/ctl.json`／`state.json` 是 aos-loop 的窗（`{"cmd": "pause"\|"resume"\|"stop", "seq": N}`、`phase`）——實作上＝`_entry` 是 aos-loop、`loop.json` 開這兩扇 | P-42 ③、N-07、N-17 |
| 4 | 信箱 | `$AOS_STACK/queue/`＝aos-post 信箱（N-16）；一封 body＝`{"role": "user", "content": 非空字串}`；接進對話那一刻就 `aos-post done`；壞信丟掉、`$AOS_STACK/mailbox_warning.txt` 覆寫一行、不回信。寄信人可先 `aos-post init`（先說、再起） | P-42 ①、loop-fsm 衝突 1、eca 20 |
| 5 | 對話 | `$AOS_STACK/history.jsonl`，一行一則 OpenAI message、只附加；**回答＝最新那則沒 `tool_calls` 的 assistant** | P-42 ②、P-41 |
| 6 | stderr／結束碼 | 錯＝stderr 一行 `程式名: 代號 原因`、退 1（掛 daemon 時進小格 `stderr.txt`）；退了就下表、stack 留 | P-20、P-21、11-02 |
| 選配 | 子介面 `tools`／`llm` | 看／改**正在跑的這一隻**的工具箱、腦：宣告定義裡的登記檔／腦設定檔在哪；改的是 stack 裡的副本，身體承諾「stack 有就用 stack 的」；改定義不經 aos-agent。細節 [03/01](03-種類與契約/01-tools-llm-與兩個範本要改什麼.md) | 使用者「改副本。改定義那塊用aos-tools」 |
| 選配 | 子介面 `screen` | 宣告裡給一個**資料夾程式**（相對定義資料夾；它自己宣告遵守介面 `aos-agent/screen`，規格 [03/02](03-種類與契約/02-子介面規格.md)）。aos-agent 用 `aos-exec --ws <它的 ws> --stack <它的 stack> <定義>/<入口> open [-d]`／`close`／`watch` 叫它，stdio 接呼叫者的；退 0＝做了，非 0＝它自己 stderr 一行 | C-73、C-68 |

**不在介面裡的**（aos-agent 不知道、不問、不印）：腦是誰、工具箱（除非宣告了選配子介面）、暫停粒度（停在哪是身體的事，C-52）、queue 空收不收工、對話全貌在哪（eca 的 `transcripts/`）、定義裡還有哪些檔。沒有 `kind`。

## agent 怎麼宣告：定義資料夾裡一份 `interfaces.json`

```json
{"aos-agent": {"tools": "tools.json", "llm": "llm.json"}}                      ← agent-fsm
{"aos-agent": {"screen": "screen", "tools": "tools.json", "llm": "llm.json"}}  ← eca-claude：再加子介面 screen
```

- **放哪**：定義資料夾頂層，固定名 `interfaces.json`（一份宣告它遵守的所有介面）。key＝介面名；值＝那個介面的選配與參數（C-55）；不認得的 key 忽略（C-48）。是 `_entry` 之外第二個固定名（C-51 註冊檔）。
- **aos-agent 怎麼用**：`add` 讀 `<XXX>/interfaces.json`——不在、或沒有 `aos-agent` 這個 key＝`InterfaceMissing`「XXX 沒宣告遵守 aos-agent 介面」、不送信；讀不懂（不是 JSON 物件、值不是物件）＝`InterfaceBad`。只看宣告、**不驗內容**（C-53 (a)、C-52；使用者裁「不驗，錯了第一圈看 stderr」，[06/02](06-衝突與方向題/02-新題-11-04-晚.md#使用者裁定11-04-晚選項原文)）。
- **宣告了卻沒做到**（C-53 各層只說自己的錯，後果在 [04 邊緣表](04-過渡與邊緣.md#失敗與邊緣狀況)）：不是 loop 型＝跑一次就下表，`pause`＝aos-daemon-ctl 的 `CtlMissing`；不收 queue＝`listen` 一直等、`state` 看得到排著幾封；history 不照格式＝`AnswerMissing`；`screen` 宣告的資料夾不在或沒宣告 `aos-agent/screen`＝`ScreenBad`；沒宣告 `screen`＝`ScreenMissing`，訊息指去 `listen --follow`。
- **`open`／`tools`／`llm` 怎麼找回定義**：daemon 表每列多一欄 `def`＝add 時 XXX 的絕對路徑（使用者裁「daemon 表多一欄記下來」，欄位定為 `def`：「那就b。」，[05/03](05-實作步驟/03-實作時改的設計.md#實作時改的設計) 2）；沒這欄＝`InterfaceMissing`。
