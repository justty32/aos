## 舊指令怎麼過渡

使用者 11-03：「aos_ws,aos-say/listen,aos-ai這些之後都會整合進aos-agent」（aos-ai 已刪）。四樣各自的去處：

| 現在 | 去處 | 說明 |
|---|---|---|
| `extras/human/bin/aos-say`、`aos-listen` | **併成 `aos-agent say`／`listen`**；程式邏輯搬進 aos-agent（`run_hint`／`stuck_hint` 那幾段原樣） | 介面差兩點：找對象改走 [02](02-找-agent.md)（名字或標記；`--stack` 留著）、不再猜 `<cwd>/.stack/`。`--ws` 旗標跟著消失（它只是用來拼 `.stack` 的）。退場方式見[方向題 3](06-衝突與方向題.md#方向題-3舊指令怎麼退場) |
| `extras/human/bin/aos_human.py` | 內容搬進 aos-agent（找 daemon 列、`/proc` 判誰在跑、提醒句） | 搬完刪 |
| `lib/aos/aos_ws.py` | **留在 lib/aos、不動**：它是「寄、等、讀 stack 三樣」的零件，aos-agent import 它；測試（`aos_ws.put`）也在用 | 使用者說的「整合」在它身上＝唯一的使用者變成 aos-agent，不是搬家 |
| `extras/eca/bin/aos-eca` | 九個子命令全部成為 aos-agent 的子命令（[01](01-子命令.md)）；eca 專屬的（畫面、session、`cli.json` 驗、`eca.json`）成為 eca 種類那個 class | 退場方式見方向題 3。`aos-eca-turn`（身體，在 bin）**不動** |
| `aos-daemon-ctl` | **不動**；aos-agent 是它上面一層，人要直接用它照舊可以 | aos-agent 只收 agent（認得種類的 loop 型）；別的 proc 還是找 aos-daemon-ctl |
| `aos_human.daemon_held` 的「eca＝stack 裡有 `eca.json`」、`run_hint` 印 `aos-eca start` | 改成「種類認法」（[03](03-種類與契約.md)）、提醒句一律印 `aos-agent start 名字` | — |

**跟 aos-eca 不一樣的三處**（整合時刻意改的，不是漏）：① 不「再比工作區」找 agent（[02](02-找-agent.md)）；② `open` 不替人 `add`（認不出就 `InstanceMissing`，要掛就 `add`）；③ 錯誤代號 `InstanceMissing` 的訊息不再提「open 建立」。

**`extras/human/README`、`extras/eca/README`** 的內容併進新的 `extras/agent/README.md`（對話協議 P-42 那段、eca 已知限制那段原樣搬）；兩個舊資料夾怎麼處置看方向題 3。

## 失敗與邊緣狀況

| 狀況 | 怎麼辦（照哪條） |
|---|---|
| 沒設 `AOS_DAEMON_STACK`、也沒標記、也沒 `--daemon-stack` | `DaemonMissing`，訊息三選一教法（同 aos-daemon-ctl） |
| `AOS_DAEMON_STACK` 是相對路徑、cd 之後對不上 | 照舊（11-02「3」維持只寫清楚）；標記存絕對路徑所以佔了的資料夾不受影響 |
| daemon 沒在跑 | 查表類照表印＋stderr 注意；動它的＝`DaemonMissing`；say 照寄＋提醒 |
| 名字不在表上 | `InstanceMissing`；訊息：rm 過或自己結束下了表、stack 資料夾可能還在、要接著用同名再 `add`（eca 現行那段） |
| 自己結束下了表（CLI 出錯、fsm 腦失敗退 1、別人直接寫它 ctl 的 stop） | 跟 aos-eca 一樣：`ls` 不列、`state`／`start`／`stop`／`rm` 都 `InstanceMissing`、stack 留著。標記若指著它＝舊標記，下次 `occupy` 覆寫 |
| `add` 認不出種類 | `KindUnknown`、不送信 |
| `add` 驗不過（檔不在、cli.json 壞） | 種類的代號（`PromptMissing` 等）、不送信——錯在掛之前看到，不用等第一格跑了看 `stderr.txt` |
| `add` 撞名 | `InstanceExists`（不論在跑或停著、不論是不是 agent）、不送信 |
| `add` 送了信、30 秒沒上表 | `Timeout`（aos-eca 現行）；信已送、daemon 下一圈可能還是會掛上——訊息說「用 `ls` 看」 |
| 剛 `add`、daemon 還沒寫 `<stack>/loop.json` | `ls` 暫時不列；`state 名字` 說「剛掛上、等 daemon 起它」 |
| stack 裡 `loop.json` 的 `exec` 指回的定義資料夾不在了（人搬走） | 種類認不出 → `ls` 不列、`state` 說「定義不在：路徑」；`stop`／`rm` 照做（它們不需要種類；收尾跳過） |
| `open`／`close`／`watch` 對 fsm | `ScreenMissing`，指去 `listen --follow` |
| `occupy` 遇到有效標記 | `WsOccupied`；舊標記覆寫；壞標記 `MarkerBad`（[02 表](02-找-agent.md)） |
| `release` 沒標記 | 說一句、退 0 |
| `rm` 的那隻佔著好幾個資料夾 | 只拿掉 cwd（或給的資料夾）那個；別處的變成舊標記、下次 `occupy` 覆寫（agent 那邊不記自己佔了哪些，C-56） |
| `say` 沒給名字、cwd 沒標記 | `InstanceMissing`，訊息教 `occupy` 或給名字 |
| `say` 的話以某隻的名字開頭 | 被當成名字；要當話就 `--`（[方向題 2](06-衝突與方向題.md#方向題-2say-的名字怎麼給)） |
| `say` 給 `--stack` 又給名字 | `ArgumentsBad`（兩條路只能走一條） |
| `start`／`stop`／`rm` 給 `--stack` | `ArgumentsBad`「這隻不在 daemon 上」 |
| `pause` 的那隻 `stopped`／`sleeping` | aos-daemon-ctl 照寫 ctl（起來時 `read_old_paused` 會先暫停）；aos-agent 不擋，`state` 看得出 |
| 兩隻 agent 同一工作區 | 允許（P-18 只管同一 stack）；找要靠名字或標記（標記只能指一隻） |
| 直接 `aos-exec` 跑的（沒掛 daemon） | 只有 `say`／`listen`／`state`／`pause`／`resume --stack S` 說得到；其他＝不在範圍（使用者「先暫時忽略」） |
| Windows | 跟 aos-say／aos-eca 一樣只在 Linux（讀 `/proc`、tmux） |

## 等實作確認（agent-fsm 做完後對一次）

1. daemon 寫進 stack 的 `loop.json`：fsm 的 `exec` 是不是 `<定義>/fsm.json` 絕對路徑字串；eca 的是不是 `<定義>/loop.json#/exec`——種類「從 stack 認」靠它（[03](03-種類與契約.md)）。
2. `demo/agent-fsm/fsm.json` 定版的三格 argv 與旗標名（`--prompt`／`--system`／`--tools`）——fsm 的 `check` 照它驗。
3. aos-fsm 寫的 `state.txt` 位置與格式（一行格名）——`state` 的「現在哪一格」。
4. `test_agent_fsm.py` 第 12 案（掛 daemon）跑出來的 phase 序列——aos-agent 的 `start`／`stop` 等待條件照它。
5. 「queue 空時停著等／收工」兩邊怎麼讀（eca `--on-empty`、fsm idle `next` 的 `10`）——`state` 那一行要不要做，看讀起來順不順。
