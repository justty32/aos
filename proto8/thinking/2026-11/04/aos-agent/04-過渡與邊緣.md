## 失敗與邊緣狀況

| 狀況 | 怎麼辦（照哪條） |
|---|---|
| 沒給 `--target`、沒設 `AOS_AGENT` | `TargetMissing`，訊息教兩句 |
| 沒設 `AOS_DAEMON`、沒 `--daemon` | `DaemonMissing`（N-63 ②） |
| `AOS_DAEMON` 相對路徑、cd 之後對不上 | 照舊（11-02「3」只寫清楚） |
| daemon 沒在跑 | 查表類照表印＋stderr 注意；動它的＝`DaemonMissing`；`say` 照寄＋提醒 |
| 名字不在表上 | `InstanceMissing`（rm 過、自己結束下了表；stack 可能還在；同名再 `add` 接著用） |
| 自己結束下了表（CLI 出錯、fsm 腦失敗退 1、別人寫它 ctl 的 stop） | `ls` 不列、`state`／`start`／`stop`／`rm`＝`InstanceMissing`、stack 留著 |
| `add` 的 XXX 沒 `interfaces.json`、或沒 `aos-agent` key | `InterfaceMissing`、不送信；訊息說怎麼宣告（一行 JSON） |
| `interfaces.json` 讀不懂 | `InterfaceBad`、不送信 |
| `add` 撞名 | `InstanceExists`（不論在跑或停著）、不送信 |
| `add` 送了信、30 秒沒上表 | `Timeout`；信已送、daemon 下一圈可能還是會掛上——「用 `ls` 看」 |
| 宣告了卻不是 loop 型（跑一次就下表） | `add` 回來時可能已經不在表上→`ls` 不列；`pause`＝aos-daemon-ctl `CtlMissing` 原樣轉述（C-53：下層的錯不轉述、只說一行） |
| 宣告了卻不收 queue | `listen` 一直等（提醒「沒人在跑」不會出現，因為它在跑）；`state` 看得到排著幾封不動——人自己判 |
| 宣告了卻 history 不照格式 | `listen`＝`AnswerMissing`；`state` 最新回答那行印不出來 |
| `open`／`close`／`watch` 對沒宣告 `screen` 的 | `ScreenMissing`，指去 `listen --follow` |
| 宣告的 `screen` 入口不在、退非 0 | `ScreenBad`，訊息帶它 stderr 最後一行 |
| `open` 時找不回定義 | 看[方向題 1](06-衝突與方向題/02-新題-11-04-晚.md#方向題-1open-時怎麼知道定義在哪)的裁定 |
| `rm`／`stop` 時畫面正在答 | `SessionBad`、不拔不停（同 aos-eca） |
| 給 `--stack` | `FlagUnknown`（11-04 晚方向題 2「不留」） |
| `tools`／`llm` 對沒宣告的 | `ToolsMissing`／`LlmMissing`，訊息說怎麼宣告 |
| `llm` 宣告的入口不在、退非 0；`tools` 宣告的登記檔不在 | `LlmBad`（帶它 stderr 一行）；aos-tools 自己的 `CfgMissing` 原樣轉 |
| `tools add`／`llm set` 時別隻也用同一份定義 | 照做，stderr 提醒「X、Y 也用這份定義」（表的 `exec` 欄相同） |
| `llm set url=…` 但 daemon 環境已設 `AOS_BRAIN_URL` | 改了沒用（`.env` 不蓋外面，N-59）；fsm 的 `show` 標 `(env 蓋住)` |
| `pause` 的那隻 `stopped`／`sleeping` | aos-daemon-ctl 照寫 ctl（起來時 `read_old_paused` 先暫停）；不擋，`state` 看得出 |
| `chat` 等答案時 Ctrl-C | 信照答、退 130、stderr 一行教 `listen`（[02](02-找-agent.md#chat-怎麼運作)） |
| `chat` 途中 agent 掛了 | 印 `AnswerMissing` 一行、回提示符，不退出 |
| `chat` 的 stdin 不是終端機 | 照跑：一行一句、stdout 只有回答；stdin 結束退 0 |
| 兩隻 agent 同一工作區 | 允許（P-18 只管同一 stack）；靠名字分 |
| 直接 `aos-exec` 跑的（沒掛 daemon） | aos-agent 不管；用 `aos-post send --ordered W/.stack/queue`＋看 `history.jsonl`（方向題 2 裁「不留」） |
| `using-aos-agent.sh` 的函數名撞到使用者自己的別名 | 使用者自己承擔；只定義四個名字 |
| Windows | 跟 aos-say／aos-eca 一樣只在 Linux（讀 `/proc`、tmux） |

## 等實作確認

1. `aos-exec --ws W --stack S <定義>/screen open`：args 接到入口 argv 後面、stdio 原樣透傳、tmux attach 在這條路上拿得到終端機（aos-exec 是 exec 還是 fork 等待——影響 `open` 要不要 `execvp`）。
2. `AOS_STACK` 給了絕對路徑時 aos-exec 不建、不改（S 是 daemon 的小格、已在）。
3. `test_agent_fsm.py` 第 12 案（掛 daemon）的 phase 序列——`start`／`stop` 的等待條件照它（aos-eca 現行 30 秒上限）。
4. `ls` 的 queue 排幾封：讀 `queue/new/`＋`cur/`；stack 沒 `queue/`（exec 型、別的 loop）印 `-`。
5. `tools`／`llm`：fsm 每輪 `aos-exec fsm.json` 確實重讀 `.env`（字串 exec）；eca 的 cli_session 每題重讀 `cli.json`——「下一題生效」靠這兩點。
6. chat 用 `input()` 還是 `sys.stdin.readline()`：Ctrl-C 在等答案的 `time.sleep` 迴圈與在 `readline` 兩處都要退 130、都要印那一行。
