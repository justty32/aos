## 舊指令怎麼退場

使用者 11-03：「aos_ws,aos-say/listen,aos-ai這些之後都會整合進aos-agent」（aos-ai 已刪）；11-04 選「測試全綠就直接刪」。11-04 已做完：

- `aos-say`／`aos-listen`／`aos_human.py` 併成 `aos-agent say`／`listen`（提醒句一律 `aos-agent start --target 名字`）；`extras/human/` 刪。
- `aos-eca` 的 `add`／`rm`／`start`／`stop`／`ls`／`state`／`status` 成為 aos-agent 的子命令；`open`／`close`／`watch` 的身體搬去 `bin/aos-eca-screen`（eca-claude 的 `screen` 入口叫它）；`extras/eca/` 刪。`aos-eca-turn`（身體）不動。
- `lib/aos/aos_ws.py` 留在 lib/aos、不動，aos-agent import 它（「整合」＝唯一的使用者變成 aos-agent）。
- `aos-daemon-ctl` 不動（改名除外）；aos-agent 是它上面一層，人要直接用照舊。
- human／eca 的 README 併進 `extras/agent/README.md`；刪資料夾單獨一個 commit。

**跟 aos-eca 刻意不一樣的**：① 不比工作區找 agent；② `open` 不替人 `add`；③ `add` 不驗 cli.json／tools／prompt；④ `ls` 列全表、不只列 eca；⑤ 錯誤訊息不提「open 建立」。

## 失敗與邊緣狀況

| 狀況 | 怎麼辦（照哪條） |
|---|---|
| 沒給 `--target`、沒設 `AOS_AGENT` | `TargetMissing`，訊息教兩句 |
| 沒設 `AOS_DAEMON`、沒 `--daemon` | `DaemonMissing`（N-63 ②） |
| `AOS_DAEMON` 相對路徑、cd 之後對不上 | 照舊（11-02「3」只寫清楚） |
| daemon 沒在跑 | 查表類照表印＋stderr 注意；動它的＝`DaemonMissing`；`say` 照寄＋提醒 |
| 名字不在表上 | `InstanceMissing`（rm 過、自己結束下了表；stack 可能還在；同名再 `add` 接著用） |
| 自己結束下了表（CLI 出錯、fsm 腦失敗退 1、別人寫它 ctl 的 stop） | `ls` 不列、`state`／`start`／`stop`／`rm`＝`InstanceMissing`、stack 留著 |
| `add` 的 XXX 沒 `interfaces.json`、或沒 `aos-agent` key | `InterfaceMissing`、不送信；訊息說怎麼宣告（一行 JSON） |
| `interfaces.json` 讀不懂 | `InterfaceBad`、不送信 |
| `add` 撞名 | `InstanceExists`（不論在跑或停著）、不送信 |
| `add` 送了信、30 秒沒上表 | `WaitFailed`；信已送、daemon 下一圈可能還是會掛上——「用 `ls` 看」 |
| 宣告了卻不是 loop 型（跑一次就下表） | `add` 回來時可能已經不在表上→`ls` 不列；`pause`＝aos-daemon-ctl `CtlMissing` 原樣轉述 |
| 宣告了卻不收 queue | `listen` 一直等；`state` 看得到排著幾封不動——人自己判 |
| 宣告了卻 history 不照格式 | `listen`＝`AnswerMissing`；`state` 最新回答那行印不出來 |
| `open`／`close`／`watch` 對沒宣告 `screen` 的 | `ScreenMissing`，指去 `listen --follow` |
| 宣告的 `screen` 資料夾不在、或沒宣告 `aos-agent/screen` | `ScreenBad`；入口自己退非 0＝它那行錯原樣轉、退 1 |
| `open` 時找不回定義（表上沒 `def` 欄） | `InterfaceMissing`，提示 rm／add 一次 |
| `rm`／`stop` 時畫面正在答 | `SessionBad`、不拔不停 |
| 給 `--stack` | `FlagUnknown`（使用者裁「不留」） |
| `tools`／`llm` 對沒宣告的 | `ToolsMissing`／`LlmMissing`，訊息說怎麼宣告 |
| `tools` 宣告的登記檔不在 | aos-tools 自己的 `CfgMissing` 原樣轉 |
| `tools add`／`llm set` 時別隻也用同一份定義 | 只改這隻的副本、別隻不動；stderr 提醒同定義的其他名字；要全部一起變＝改定義（有副本的那幾隻不跟） |
| 副本在、人又改了定義 | 不跟（使用者裁「不跟」）；stderr 說「用的是副本」；`reset` 回去 |
| `pause` 的那隻 `stopped`／`sleeping` | aos-daemon-ctl 照寫 ctl（起來時先暫停）；不擋，`state` 看得出 |
| `chat` 等答案時 Ctrl-C | 信照答、退 130、stderr 一行教 `listen`（[02](02-找-agent.md#chat-怎麼運作)） |
| `chat` 途中 agent 掛了 | 印 `AnswerMissing` 一行、回提示符，不退出 |
| `chat` 的 stdin 不是終端機 | 照跑：一行一句、stdout 只有回答；stdin 結束退 0 |
| 兩隻 agent 同一工作區 | 允許（P-18 只管同一 stack）；靠名字分 |
| 直接 `aos-exec` 跑的（沒掛 daemon） | aos-agent 不管；用 `aos-post send --ordered W/.stack/queue`＋看 `history.jsonl` |
| `using-aos-agent.sh` 的函數名撞到使用者自己的別名 | 使用者自己承擔；只定義四個名字 |
| Windows | 只在 Linux（讀 `/proc`、tmux） |
