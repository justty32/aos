## 11-04 晚改寫後的新題

### 衝突 1：`AOS_AGENT` 的值是名字、不是資料夾，對上 N-63 ①

- **哪條**：N-63「hub 用環境變數指：命名 `AOS_<名字>`，值是一個資料夾的路徑」；11-01 你說旋鈕「除非真的有必要，否則不要用」環境變數。
- **衝突在哪**：`AOS_AGENT` 長得像 hub 型變數（`AOS_` 開頭），值卻是 daemon 表上的名字（`bob`），不是路徑；而且它不是 hub（沒有大家共用的那個資料夾），是 aos-agent 這支指令給人殼用的「預設對象」。
- **(a) 照你說的做，N-63 加一句（fable 選的）**：N-63 只管 hub；`AOS_AGENT` 歸類成「給人殼設的預設」（像 `EDITOR`、`PAGER`），判準＝人在殼裡設、程式之間不靠它傳東西。代價：`AOS_` 開頭的變數有兩種性質，要在 N-63 說清楚。
- **(b) 值改成 stack 路徑**：就變成 hub 型（`AOS_AGENT=/…/procs/bob`）；代價：人要打路徑、`using-aos-agent.sh bob` 要先查表轉成路徑。
- **例子**：`export AOS_AGENT=bob; aos-agent say 你好`（a）vs `export AOS_AGENT=$(aos-agent where --target bob)`（b）。
- **建議 (a)**。

### 衝突 2：`add` 不再先驗，對上 11-03 eca-tools「入口先檢查、不送信」

- **哪條**：你 11-03 替 eca 定的「`add`／`open` 新建時先檢查：`tools` 指的檔不在＝`ToolsMissing`、cli.json 壞＝`CfgBad`，都不送信」、11-04「`--prompt` 指的不是檔＝`PromptMissing`、不送信」——理由是免得等 daemon 起子 loop、aos-eca-turn 退 1 才看到。
- **衝突在哪**：這些驗的都是 eca 實作的檔；你 11-04 晚說 `add` 只吃介面、不看特定檔案，C-52 加嚴也說「不替下層驗它的東西」。所以 aos-agent `add` 只看 `interfaces.json` 有沒有宣告，cli.json／tools／prompt 指錯要等第一圈才看到（小格 `stderr.txt` 一行、下表、`ls` 不列）。
- **(a) 不驗（fable 選的）**：aos-agent 乾淨；代價：掛錯要多等一圈、自己去看 `stderr.txt`；eca-tools、eca 21 那兩條決定加「11-04 晚起由 aos-eca-turn 第一圈報」的註。
- **(b) 介面多一條「自我檢查」**：宣告裡給一個入口 `check`，`add` 先 `aos-exec <定義>/<check>` 退 0 才投信；eca 的 check＝今天那段驗；fsm 的＝驗 `--system`／`--tools`。代價：每種 agent 多寫一支小程式、介面多一條。
- **例子**：`aos-agent add --name e1 eca-壞的` 之後——(a) `ls` 看不到 e1、`cat $(aos-agent where …)/stderr.txt` 看到 `aos-eca-turn: ToolsMissing …`；(b) `add` 當場印 `aos-agent: ToolsMissing …`。
- **建議 (a)**，等以後第三種 agent 出現、真的常掛錯再加 (b)。

### 方向題 1：`open` 時怎麼知道定義在哪？

- **背景**：`open`／`close`／`watch` 要讀宣告（`<定義>/interfaces.json`）、再 `aos-exec <定義>/<入口>`。但 aos-agent 手上只有 daemon 表那一列（名字、phase、stack、ws），表上沒有「這隻是從哪個資料夾 add 的」。原則推不出該由誰記。
- **(a) daemon 列多一欄 `exec`（fable 選的）**：`procs_state.json` 每列多記起它時的目標（add 的 XXX 絕對路徑；N-64「上一代記自己起了什麼」）；impls/aos-daemon 小改、N-28 列的欄位加一個。好處：一處、權威、任何工具都能用。代價：動 C++。
- **(b) 讀 daemon 寫在小格的 `loop.json`**：它的 `exec` 指進定義（eca＝`<定義>/loop.json#/exec`、fsm＝`<定義>/fsm.json`）、取資料夾。零改動；代價：靠實作檔的長相（exec 指到共用檔就錯）、正是你不喜歡的那種。
- **(c) 人自己給**：`aos-agent open --target bob ../agents/bob`。零改動；代價：每次要打路徑。
- **例子**：`aos-agent open --target e1`——(a) 讀表拿到 `/…/demo/eca-claude`、讀宣告、`aos-exec … /…/demo/eca-claude/screen open`；(c) 要多打一個參數。
- **建議 (a)**。

### 方向題 2：直接 `aos-exec` 跑的，要不要留 `--stack`？

- **背景**：你 11-04 說「先暫時忽略直接aos-exec出來的那些」；但 aos-say／aos-listen 刪了之後，`aos-exec --ws W demo/agent-fsm &` 這樣跑的 agent 就沒有指令能跟它說話（demo README、test_agent_fsm 的手跑例子都是這樣起的）。原則推不出要不要留。
- **(a) `say`／`listen`／`chat`／`state` 收 `--stack S`（fable 選的）**：直接指 stack、不查 daemon；其他子命令不收。代價：四個子命令多一個旗標、找 agent 有第二條（明講的）路。
- **(b) 不留**：直接跑的用 `aos-post send --ordered W/.stack/queue` 加 `tail -f W/.stack/history.jsonl`；demo README 改寫成這樣。代價：手跑不方便，測試還是用 `aos_ws.put` 無所謂。
- **例子**：`aos-exec --ws /tmp/w demo/agent-fsm & aos-agent say --stack /tmp/w/.stack 現在幾點 && aos-agent listen --stack /tmp/w/.stack`（a）。
- **建議 (a)**。
