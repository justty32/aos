## 實作時改的設計

使用者 11-04：「設計好就直接實作。實作途中如果發現問題可以回來改設計。」下面每條＝原本 → 改成 → 為什麼。沒有一條翻掉你的裁定。

### 改了做法的

1. **`aos-llm` 叫入口時的 stack**：原本「`aos-exec --ws <定義> <定義>/llm def …`，不給 `--stack`」→ 改成給一個**用完就刪的暫存資料夾**當 `--stack` → 因為 aos-exec 一定會建 stack，不給就建在 `<定義>/.stack`，等於寫進定義資料夾（P-15 不准）。入口的 `def` 對象本來就不看 stack，所以結果一樣。
2. **daemon 表的 `exec` 欄記什麼**：原本「add 時的目標（XXX）轉絕對」→ 改成 daemon **從那隻的設定推**：字串目標轉絕對、陣列取第一個、內嵌單子是 null；aos-daemon-ctl 對 loop 型本來就把內嵌單子改寫成 `<XXX>/loop.json#/exec`，所以兩個範本都推得回定義 → 因為 daemon 收到的是 loop.json 的內容，不是 XXX 這個字。**留著的邊緣**：loop.json 的 `exec` 若是陣列（例如直接寫 `["aos-eca-turn", …]`）或指到別的資料夾的檔，`exec` 欄就是那支程式，`aos-agent open／tools／llm` 找不回定義、報 `InterfaceMissing`。兩個範本沒這問題；要徹底解得讓 aos-daemon-ctl 把 XXX 也送給 daemon（多一個欄位），這算方向，留給你。**11-04 使用者選 (b)**，原文「那就b。」——已改成 `def` 欄：aos-daemon-ctl add 把 XXX 的絕對路徑當 `def` 送給 daemon（loop 型、exec 型都送），daemon 表每列多一欄 `def` 直接記，aos-agent 改讀 `def`、不再從 `exec` 推（沒 `def` 的舊列＝`InterfaceMissing`，提示 rm／add 一次）。
3. **入口自己的錯怎麼轉**：原本「screen／llm 入口退非 0 一律包成 `ScreenBad`／`LlmBad`」→ 改成**入口那行錯原樣轉、退 1**；`ScreenBad`／`LlmBad` 只用在「宣告的資料夾不在、沒宣告 `aos-agent/screen|llm`」→ 因為 C-53 各層只說自己的錯：`llm set zzz=1` 打錯鍵應該看到 `KeyUnknown`，不是「入口壞了」；rm／stop 遇到畫面正在答也才看得到 `SessionBad`。
4. **過渡期 aos-eca 不改叫 aos-eca-screen**：原本步 1「aos-eca 的 open／close／watch 改成叫 aos-eca-screen」→ 沒改，直接在步 7 整支刪 → 同一天就刪，改了只是多一輪測試。
5. **測試裡怎麼對直接跑的 agent 說話**：原本測試用 aos-say／aos-listen（`--stack`）→ 刪掉 extras/human 後改用新的測試小模組 `tests/stack_talk.py`（`aos_ws.put` 寄、看 history 等答案）→ aos-agent 只管 daemon 表上的（你裁「不留 `--stack`」），直接 `aos-exec` 跑的就照 02 那節寫信、讀 history。
6. **agent-fsm 的兩個新測試放哪**：原本加在 `test_agent_fsm.py` → 放進新的 `test_aos_llm.py` → 同一時間另一隊（four-elements）在改 test_agent_fsm，避免兩邊打架。
7. **eca `llm def set model=` 怎麼寫 cli.json**：只改 `"--model"` 後面那一格的字，cli.json 其他排版原樣；`set model=`（空值）＝`ArgumentsBad`。fsm 的 `.env` 也是只改那一行，沒有就加在最後。
8. **`tools add` 的細節**：`aos-agent tools add 名 路徑`＝`aos-tools add --name 名 <絕對路徑>`，不帶 `--override`（撞名照 aos-tools 報 `ToolExists`）；定義沒有登記檔時副本從空工具箱開始；登記檔裡的 `$ref` 沒處理。
9. **`aos-tools` 沒 `AOS_STACK`**：只有 `call` 一個可執行檔工具時才報 `StackMissing`；`--file` 的 ls／get／add／rm 與資料夾工具照舊能跑（aos-agent tools 要靠這個）。

### 補上規劃沒寫到的（小事）

- `--daemon` 只收在子命令前面（`aos-agent --daemon D ls`），跟 aos-daemon-ctl 一樣。
- `state` 多印一行「定義」（從 `exec` 欄算出來的資料夾）；`ls --json` 是陣列，每項 name、state、phase、ws、stack、queued。
- 沒人在跑的提醒句看這隻的 phase：stopped → `aos-agent start --target 名字`；sleeping 或 daemon 沒在跑 → 重開 daemon；其他 → 看 `<stack>/stderr.txt`。
- `open`／`close`／`watch` 的 stderr 先收起來、結束後一次印（才能原樣轉）；`open` 不帶 `-d` 時 stdio 全直通（tmux attach 拿得到終端機）。
- 只設舊名 `AOS_DAEMON_STACK` 時的 `DaemonMissing` 訊息會說「11-04 起改名，請改設 AOS_DAEMON」；給 `--daemon-stack`＝`FlagUnknown`。
- `using-aos-agent.sh` 的四個函數叫的是它旁邊那份 `bin/aos-agent`，不靠 PATH。
