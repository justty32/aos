## 實作時改的設計

使用者 11-04：「設計好就直接實作。實作途中如果發現問題可以回來改設計。」下面每條是實作時定的做法；沒有一條翻掉使用者的裁定。

### 做法

1. （`aos-llm` 改定義那支已隨 [think-as-function](../../think-as-function/README.md) 刪，本條不再適用。）
2. **daemon 表記定義在哪：`def` 欄**。使用者選 (b)，原文「那就b。」：aos-daemon-ctl add 把 XXX 的絕對路徑當 `def` 送給 daemon（loop 型、exec 型都送），daemon 表每列多一欄 `def` 直接記，aos-agent 讀 `def` 找定義；沒 `def` 的列＝`InterfaceMissing`，提示 rm／add 一次。
3. **入口自己的錯原樣轉、退 1**；`ScreenBad` 只用在「宣告的資料夾不在、沒宣告 `aos-agent/screen`」（C-53 各層只說自己的錯；rm／stop 遇到畫面正在答才看得到 `SessionBad`）。
4. aos-eca 沒有過渡期改叫 aos-eca-screen，步 7 整支刪。
5. **測試裡對直接跑的 agent 說話**：用測試小模組 `tests/stack_talk.py`（`aos_ws.put` 寄、看 history 等答案）。
6. （測試檔位置，已不適用。）
7. （eca `llm def set`，已隨 `aos-eca-llm` 刪除不適用。）
8. **`tools add` 的細節**：`aos-agent tools add 名 路徑`＝`aos-tools add --name 名 <絕對路徑>`，不帶 `--override`（撞名照 aos-tools 報 `ToolExists`）；定義沒有登記檔時副本從空工具箱開始；登記檔裡的 `$ref` 沒處理。
9. **`aos-tools` 沒 `AOS_STACK`**：只有 `call` 一個可執行檔工具時才報 `StackMissing`；`--file` 的 ls／get／add／rm 與資料夾工具照舊能跑（aos-agent tools 要靠這個）。

### 補上規劃沒寫到的（小事）

- `--daemon` 只收在子命令前面（`aos-agent --daemon D ls`），跟 aos-daemon-ctl 一樣。
- `state` 多印一行「定義」（`def` 欄）；`ls --json` 是陣列，每項 name、state、phase、ws、stack、queued。
- 沒人在跑的提醒句看這隻的 phase：stopped → `aos-agent start --target 名字`；sleeping 或 daemon 沒在跑 → 重開 daemon；其他 → 看 `<stack>/stderr.txt`。
- `open`／`close`／`watch` 的 stderr 先收起來、結束後一次印（才能原樣轉）；`open` 不帶 `-d` 時 stdio 全直通（tmux attach 拿得到終端機）。
- 只設舊名 `AOS_DAEMON_STACK` 時的 `DaemonMissing` 訊息說「請改設 AOS_DAEMON」；給 `--daemon-stack`＝`FlagUnknown`。
- `using-aos-agent.sh` 的四個函數叫的是它旁邊那份 `bin/aos-agent`，不靠 PATH。
