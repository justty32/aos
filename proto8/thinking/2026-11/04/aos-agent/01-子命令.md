## 子命令總表（fable 照原則定的，可翻案）

通則：**每個子命令只管一隻**（11-03；`ls` 暫留，跟 aos-eca 一樣以後歸 hub）；**`[名字|資料夾]` 都沒給＝當前資料夾**，找法在 [02](02-找-agent.md)；**介面層只碰 stack，不碰身體**（loop-fsm 02 對照表第一列）——所以沒有任何子命令會去改定義資料夾或 history 的內容。底下叫別的程式一律 argv 陣列（`aos-daemon-ctl …`、`aos-post …`），不經 sh（10-15）。名詞照 [procs § 0](../../03/procs/03-規劃-fable-照原則定的細節-可翻案.md#0-名詞表代定)：add／rm＝插拔、start／stop＝起停、pause／resume＝暫停、open／close＝畫面。

| 子命令 | 做什麼（一句話） | 從哪支整合來 | 底下是 |
|---|---|---|---|
| `add [--name N] [--ws WS] [--stack S] XXX` | 掛一隻：XXX＝agent 本身（eca 資料夾或 agent-fsm 那種範本的複本），認種類（[03](03-種類與契約.md)）→ 種類先驗（檔在不在、旗標指得到）→ 投信 → **等 daemon 把它放上表**才回、印 stack。撞名＝`InstanceExists`、不送信。不碰工作區 | aos-eca `add`（驗 cli.json／tools／prompt 那段原樣搬）；fsm 的驗是新寫 | `aos-daemon-ctl add --ws WS --name N [--stack S] XXX` |
| `rm [名字\|資料夾]` | 拔掉並刪乾淨：種類收尾（eca 關畫面）→ 下表 → **刪它的 stack**（不封存，11-02 晚）→ 工作區若有指著它的 `.aos/agent.json` 一起拿掉 | aos-eca `rm` | `aos-daemon-ctl rm 名字`，等下表，`rm -r` 列上的 stack |
| `start [名字\|資料夾]` | 停著的再起，同一個 stack、接著答排著的信；本來在跑＝說一句、退 0 | aos-eca `start` | `aos-daemon-ctl start 名字`，等列不再 `stopped` |
| `stop [名字\|資料夾]` | 答完手上這題就停，**還在表上**（`stopped`）、stack 留、`where` 找得到、信照收不答；種類收尾（eca 關畫面） | aos-eca `stop` | `aos-daemon-ctl stop 名字`，等列變 `stopped` |
| `pause` / `resume [名字\|資料夾]` | 暫停／接著跑（粒度看種類：eca＝一批信、fsm＝一格；暫停中可以改 fsm 的 history） | 新（aos-eca 沒包；以前要人直接叫 aos-daemon-ctl） | `aos-daemon-ctl pause／resume 名字` 直接轉 |
| `ls [--json]` | 列這個 daemon 上的 agent，一隻一行：名字、狀態、種類、工作區、種類多給的一欄（eca：畫面＋session 前 8 碼；fsm：現在哪一格） | aos-eca `ls` | `aos-daemon-ctl ls --json`，只留認得出種類的列（[03 § 認法](03-種類與契約.md)） |
| `state [名字\|資料夾]`（＝`status`） | 這隻的狀態幾行：狀態（phase／paused）、種類、定義、工作區、stack、queue 排幾封、工具箱；種類再多印幾行 | aos-eca `state`／`status` | 同一張表＋stack 裡的 `state.json`、`queue/` |
| `where [名字\|資料夾]` | 印它的 stack 一行（接 `$(…)` 用） | aos-daemon-ctl `where --stack` | `aos-daemon-ctl where --stack 名字` 直接轉 |
| `say [名字] 話…` | 對它說一句：寄進它 stack 的 queue（有序信、body＝user message）；印信件名稱。沒人在跑＝照 phase 提醒一句、信照寄 | aos-say（含 aos_human 的 `run_hint`） | `aos-post send --ordered <stack>/queue`（aos_ws.put） |
| `listen [名字] [--timeout 秒] [--last N] [--follow]` | 等最新那封的回答／看最後 N 段／跟著看 | aos-listen | aos_ws（history 最新那則沒 `tool_calls` 的 assistant） |
| `open [-d] [名字\|資料夾]` / `close` | 接進／收起畫面；只有有畫面的種類（eca）；其他種類＝`ScreenMissing`，訊息指去 `listen --follow` | aos-eca `open`／`close` | 種類提供（eca：cli_session） |
| `watch [名字\|資料夾]` | 跟著看一輪在做什麼；eca 讀 `live.jsonl`；fsm＝`ScreenMissing`（history 已是全貌，`listen --follow` 就是） | aos-eca `watch` | 種類提供 |
| `occupy 名字 [資料夾]` / `release [資料夾]` | 讓那隻佔這個資料夾（寫 `<資料夾>/.aos/agent.json`）／放掉；規則在 [02](02-找-agent.md)。是[方向題 1](06-衝突與方向題.md#方向題-1aosagentjson-誰寫怎麼寫)的建議案 | 新 | 只動那一個檔 |

**沒有的**：`--kind`（種類自動認，11-03「kind 刪掉」）；`sleep／wake`（daemon 自己的事，不開放，11-03 晚）；`history`／`transcripts`（看對話＝`listen --last N`；eca 的 CLI 全貌靠 `open`／`watch`）；`add` 的 `--occupy`（佔資料夾是另一個動作，見方向題 1）；批次操作（hub 的事）；aos-eca `open` 那條「認不出就先 add」的暗路——**`open` 只開已掛上的**（C-56 一條路；要掛就 `add`）。

## 旗標

- **哪個 daemon**：`--daemon-stack D` ＞ 當前資料夾 `.aos/agent.json` 的 `daemon_stack`（只在沒給名字時看）＞ `$AOS_DAEMON_STACK`；都沒有＝`DaemonMissing`。跟 aos-daemon-ctl 同一套（N-63），只多了標記那一層（它存絕對路徑，順手解掉「`AOS_DAEMON_STACK` 要絕對路徑、cd 之後對不上」那條已知限制）。
- **`--stack S`**（say／listen／state／pause／resume 收）：**直接指 stack、不查 daemon**——給「先暫時忽略」的直接 `aos-exec` 跑的那些留一條明路；給了就不找名字也不找標記。`$AOS_STACK` 同樣算（跟 aos-say 現行一樣）；**不再猜 `<cwd>/.stack/`**（N-57 的預設是 aos-exec 的事；aos-agent 的對象是 daemon 管的 proc）。
- `say` 的「名字還是話」怎麼切：第一個位置參數是表上的名字＝名字，否則整串是話、對象＝當前資料夾佔的那隻；話剛好以某隻的名字開頭就放 `--`（`aos-agent say -- bob 你好`）。見[方向題 2](06-衝突與方向題.md#方向題-2say-的名字怎麼給)。
- 其他：`add` 的 `--name`／`--ws`／`--stack` 語意同 aos-daemon-ctl（WS、S 從呼叫的 cwd 轉絕對；`--name` 預設 XXX 資料夾名、`--ws` 預設 cwd）；`ls --json`、`listen` 三個照舊；`open -d` 只開不接。

## 錯誤代號（C-54：主題＋Missing／Bad／Unknown／Failed／Exists）

stderr 一行 `aos-agent: 代號 原因`、退 1。沿用 aos-eca／aos-daemon-ctl 的：`ArgumentsBad`、`FlagUnknown`、`CommandUnknown`、`DaemonMissing`、`InstanceMissing`（表上沒有這隻）、`InstanceExists`、`PathMissing`、`PromptMissing`／`SystemMissing`／`ToolsMissing`、`CfgBad`、`SessionBad`、`Timeout`、`SendFailed`。新的：`KindUnknown`（XXX 認不出是哪種 agent）、`ScreenMissing`（這種沒畫面）、`WsOccupied`（資料夾已被別隻佔著，[02](02-找-agent.md)）、`MarkerBad`（`.aos/agent.json` 讀不懂）。aos-daemon-ctl 的 `ProcMissing` 進到 aos-agent 一律講成 `InstanceMissing`（對人而言是「這隻 agent 不在」）。
