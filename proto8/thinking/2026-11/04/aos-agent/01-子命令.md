## 子命令總表（fable 照原則與使用者 11-04 晚的決定定的，可翻案）

通則：**每個子命令只管一隻**（`ls` 暫留，以後歸 hub）；**對象＝`--target 名字`，沒給看 `$AOS_AGENT`**（`add`／`rm` 例外，見下）；**介面層只碰 daemon 表與那隻的 stack**（[03 介面](03-種類與契約.md)），定義裡只讀 `interfaces.json` 這一句宣告；底下叫別的程式一律 argv 陣列，不經 sh。名詞照 [procs § 0](../../03/procs/03-規劃-fable-照原則定的細節-可翻案.md#0-名詞表代定)：add／rm＝插拔、start／stop＝起停、pause／resume＝暫停、open／close＝畫面。

| 子命令 | 做什麼（一句話） | 底下是 |
|---|---|---|
| `add [--name N] [--ws WS] [--stack S] XXX` | 掛一隻：XXX＝宣告遵守 `aos-agent` 介面的資料夾。讀 `<XXX>/interfaces.json`（沒宣告＝`InterfaceMissing`、不送信）→ 撞名＝`InstanceExists`、不送信 → 投信 → **等 daemon 放上表**才回、印 stack。不驗內容、不碰工作區 | `aos-daemon-ctl add --ws WS --name N [--stack S] XXX` |
| `rm 名字` | 拔掉並刪乾淨：有畫面先關（正在答＝`SessionBad`、不拔）→ 下表 → **刪它的 stack**（不封存）。**位置參數、不吃 `AOS_AGENT`**（使用者 11-04 晚「rm後面不用接--target」） | `aos-daemon-ctl rm 名字`，等下表，`rm -r` 列上的 stack |
| `start`／`stop` | 停著的再起（同一個 stack、接著答排著的信）／答完手上這題就停（還在表上 `stopped`、stack 留、信照收不答；有畫面先關）。本來就是那個狀態＝說一句、退 0 | `aos-daemon-ctl start／stop 名字`，等 phase |
| `pause`／`resume` | 暫停／接著跑（停在哪是身體的事：eca 一批信、fsm 一格） | `aos-daemon-ctl pause／resume 名字` 直接轉 |
| `ls [--json]` | 列這個 daemon 表上**全部**的 proc，一隻一行：名字、狀態、工作區、queue 排幾封（stack 沒 `queue/`＝`-`）。不分哪些是 agent（C-52；要篩是 hub 的事） | `aos-daemon-ctl ls --json`＋每列 stack 的 `state.json`、`queue/` |
| `state`（＝`status`） | 這隻的狀態幾行：狀態、工作區、stack、queue 排幾封、最新一則回答的前 60 字、`mailbox_warning.txt` 那一行（有才印）。`status` 是別名 | 同一張表＋stack 的 `state.json`、`queue/`、`history.jsonl` |
| `where` | 印一行（接 `$(…)` 用）：不帶旗標＝`--stack`（印 stack）、`--ws` 印工作區（表上那列的 `ws`，沒記＝`WsMissing`）、兩個一起給＝`ArgumentsBad`（使用者 11-04 晚「aos agent的where，我希望默認是--stack，有需要再另外指定--ws。」） | `aos-daemon-ctl where --stack 名字` 直接轉 |
| `say 話…` | 寄進它 stack 的 queue（有序信、body＝user message）；stdout 印信件名稱。沒人在跑＝照 phase 提醒一句、信照寄 | `aos-post send --ordered <stack>/queue`（aos_ws.put） |
| `listen [--timeout-s 秒] [--last N] [--follow]` | 等最新那封的回答／看最後 N 段／跟著看 | aos_ws（history 最新那則沒 `tool_calls` 的 assistant） |
| `chat` | 互動對話：一行一句、等回答、再一行；**Ctrl-C 退出**。見 [02](02-找-agent.md#chat-怎麼運作) | say／listen 同一段程式 |
| `tools [ls\|get 名\|add 名 路徑\|rm 名\|reset]` | 看／改**正在跑的這一隻**的工具箱：宣告了子介面 `tools` 的才有；改的是 stack 裡的副本 `$AOS_STACK/tools.json`（第一次改才建、不跟定義、`reset` 刪掉回去跟）、下一題生效；改定義用 `aos-tools`；沒宣告＝`ToolsMissing`（使用者「改副本。改定義那塊用aos-tools」） | `aos-tools --file <stack>/tools.json …`（沒副本：`ls`／`get` 讀定義那份、`add`／`rm` 先複製） |
| `llm` | 看／換**正在跑的這一隻**的腦設定：宣告了子介面 `llm` 的才有；改的是 stack 裡的副本、下一題生效；沒宣告＝`LlmMissing`（「aos-agent llm改正在跑著的，aos-llm改定義」）。做法見 [think-as-function 03 § 4](../think-as-function/03-呼叫端.md) | 讀寫 `<stack>/llm.json` |
| `open [-d]`／`close`／`watch` | 接進／收起畫面／跟著看一輪；只有宣告了子介面 `screen` 的才有，其他＝`ScreenMissing`，訊息指去 `listen --follow` | `aos-exec --ws <ws> --stack <stack> <定義>/<screen 資料夾> open／close／watch`（[03/02](03-種類與契約/02-子介面規格.md)） |

**沒有的**：`--kind`（沒有種類）；`occupy`／`release` 與 `.aos/agent.json`（使用者 11-04「先不做擴充」）；`say [名字] 話` 那套「第一個字是名字還是話」（改成 `--target`，沒有歧義）；`sleep／wake`（daemon 自己的事）；`history`／`transcripts`（看對話＝`listen --last N`；eca 全貌靠 `open`／`watch`）；`add --occupy`；批次操作（hub）；`open` 替人先 `add`（`open` 只開已掛上的，C-56）。

## 旗標

- **對象 `--target 名字`**（除 `add`、`rm`、`ls` 以外每個子命令都收）：沒給＝`$AOS_AGENT`（裡面是表上的名字）；都沒有＝`TargetMissing`，訊息教兩句「`--target 名字`」「`export AOS_AGENT=名字`（或 `source using-aos-agent.sh 名字`）」。表上沒有這隻＝`InstanceMissing`。
- **哪個 daemon `--daemon D`**：`--daemon D` ＞ `$AOS_DAEMON`；都沒有＝`DaemonMissing`。跟 aos-daemon-ctl 同一套（N-63）。
- **沒有指對象用的 `--stack`**（使用者 11-04 晚[方向題 2](06-衝突與方向題/02-新題-11-04-晚.md#使用者裁定11-04-晚選項原文)選「不留」）：aos-agent 只管 daemon 上的；直接 `aos-exec` 跑的用 `aos-post send --ordered <WS>/.stack/queue` 寫信、看 `<WS>/.stack/history.jsonl`。`where` 的 `--stack`／`--ws` 是不帶值的旗標，只選印哪個（使用者 11-04 晚「aos agent的where，我希望默認是--stack，有需要再另外指定--ws。」）。
- `add` 的 `--name`／`--ws`／`--stack` 語意同 aos-daemon-ctl（WS、S 從呼叫的 cwd 轉絕對；`--name` 預設 XXX 資料夾名、`--ws` 預設 cwd）；`listen` 的逾時是 **`--timeout-s`**（C-54 R6 單位接後面）；`open -d` 只開不接。
