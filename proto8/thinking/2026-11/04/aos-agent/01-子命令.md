## 子命令總表（fable 照原則與使用者 11-04 晚的決定定的，可翻案）

通則：**每個子命令只管一隻**（11-03；`ls` 暫留，以後歸 hub）；**對象＝`--target 名字`，沒給看 `$AOS_AGENT`**（使用者 11-04 晚；`add`／`rm` 例外，見下）；**介面層只碰 daemon 表與那隻的 stack**（[03 介面](03-種類與契約.md)），不看定義裡的檔（只讀 `interfaces.json` 這一句宣告）；底下叫別的程式一律 argv 陣列（`aos-daemon-ctl …`、`aos-post …`、`aos-exec …`），不經 sh（10-15）。名詞照 [procs § 0](../../03/procs/03-規劃-fable-照原則定的細節-可翻案.md#0-名詞表代定)：add／rm＝插拔、start／stop＝起停、pause／resume＝暫停、open／close＝畫面。

| 子命令 | 做什麼（一句話） | 從哪支整合來 | 底下是 |
|---|---|---|---|
| `add [--name N] [--ws WS] [--stack S] XXX` | 掛一隻：XXX＝agent 本身（任何宣告遵守 `aos-agent` 介面的資料夾）。讀 `<XXX>/interfaces.json`（沒宣告＝`InterfaceMissing`、不送信）→ 撞名＝`InstanceExists`、不送信 → 投信 → **等 daemon 放上表**才回、印 stack。不驗內容、不碰工作區 | aos-eca `add`（去掉 cli.json／tools／prompt 那段驗） | `aos-daemon-ctl add --ws WS --name N [--stack S] XXX` |
| `rm 名字` | 拔掉並刪乾淨：有畫面先關（正在答＝`SessionBad`、不拔）→ 下表 → **刪它的 stack**（不封存，11-02 晚）。**位置參數、不吃 `AOS_AGENT`**（使用者 11-04 晚「rm後面不用接--target」；拔掉不可逆，名字要明講） | aos-eca `rm` | `aos-daemon-ctl rm 名字`，等下表，`rm -r` 列上的 stack |
| `start`／`stop` | 停著的再起（同一個 stack、接著答排著的信）／答完手上這題就停（還在表上 `stopped`、stack 留、信照收不答；有畫面先關）。本來就是那個狀態＝說一句、退 0 | aos-eca `start`／`stop` | `aos-daemon-ctl start／stop 名字`，等 phase |
| `pause`／`resume` | 暫停／接著跑（停在哪是身體的事：eca 一批信、fsm 一格；暫停中可以改 fsm 的 history） | 新（以前要直接叫 aos-daemon-ctl） | `aos-daemon-ctl pause／resume 名字` 直接轉 |
| `ls [--json]` | 列這個 daemon 表上**全部**的 proc，一隻一行：名字、狀態（`running`／`paused`／`stopping`／`stopped`／`sleeping`）、工作區、queue 排幾封（stack 沒 `queue/`＝`-`）。不分哪些是 agent（C-52：誰掛的都算；要篩是 hub 的事） | aos-eca `ls` | `aos-daemon-ctl ls --json`＋每列 stack 的 `state.json`、`queue/` |
| `state`（＝`status`） | 這隻的狀態幾行：狀態、工作區、stack、queue 排幾封、最新一則回答的前 60 字、`mailbox_warning.txt` 那一行（有才印）。`status` 是別名、行為一樣（使用者 11-04 晚） | aos-eca `state`／`status` | 同一張表＋stack 的 `state.json`、`queue/`、`history.jsonl` |
| `where` | 印它的 stack 一行（接 `$(…)` 用） | aos-daemon-ctl `where --stack` | `aos-daemon-ctl where --stack 名字` 直接轉 |
| `say 話…` | 對它說一句：寄進它 stack 的 queue（有序信、body＝user message）；stdout 印信件名稱。沒人在跑＝照 phase 提醒一句、信照寄 | aos-say（含 aos_human 的 `run_hint`） | `aos-post send --ordered <stack>/queue`（aos_ws.put） |
| `listen [--timeout 秒] [--last N] [--follow]` | 等最新那封的回答／看最後 N 段／跟著看 | aos-listen | aos_ws（history 最新那則沒 `tool_calls` 的 assistant） |
| `chat` | 互動對話：一行一句、等回答、再一行；**Ctrl-C 退出**（使用者 11-04 晚）。怎麼運作見 [02](02-找-agent.md#chat-怎麼運作) | 新（say＋listen 的迴圈；aos-chat 11-03 封存的那支不拉回來） | say／listen 同一段程式 |
| `open [-d]`／`close`／`watch` | 接進／收起畫面／跟著看一輪；只有宣告了子介面 `screen` 的才有，其他＝`ScreenMissing`，訊息指去 `listen --follow` | aos-eca `open`／`close`／`watch`（身體搬去 `bin/aos-eca-screen`） | `aos-exec --ws <ws> --stack <stack> <定義>/<宣告的入口> open／close／watch`（[03](03-種類與契約.md)） |

**沒有的**：`--kind`（沒有種類）；`occupy`／`release` 與 `.aos/agent.json`（使用者 11-04「先不做擴充」）；`say [名字] 話` 那套「第一個字是名字還是話」（改成 `--target`，沒有歧義）；`sleep／wake`（daemon 自己的事）；`history`／`transcripts`（看對話＝`listen --last N`；eca 全貌靠 `open`／`watch`）；`add --occupy`；批次操作（hub）；aos-eca `open` 那條「認不出就先 add」的暗路（`open` 只開已掛上的，C-56）。

## 旗標

- **對象 `--target 名字`**（除 `add`、`rm`、`ls` 以外每個子命令都收）：沒給＝`$AOS_AGENT`（裡面是表上的名字）；都沒有＝`TargetMissing`，訊息教兩句「`--target 名字`」「`export AOS_AGENT=名字`（或 `source using-aos-agent.sh 名字`）」。表上沒有這隻＝`InstanceMissing`。
- **哪個 daemon `--daemon D`**：`--daemon D` ＞ `$AOS_DAEMON`；都沒有＝`DaemonMissing`。跟 aos-daemon-ctl 同一套（N-63；改名見 [05](05-實作步驟.md#步-0aos_daemon_stack-改名-aos_daemon)）。
- **`--stack S`**（只 `say`／`listen`／`chat`／`state` 收）：直接指 stack、不查 daemon——給「先暫時忽略」的直接 `aos-exec` 跑的那些留一條明路（aos-say 刪掉後唯一的路，[方向題 2](06-衝突與方向題/02-新題-11-04-晚.md#方向題-2直接-aos-exec-跑的要不要留---stack)）。跟 `--target` 同時給＝`ArgumentsBad`；`$AOS_STACK` **不算**（它是跑在 agent 裡面才會有的變數，人殼裡通常沒有；要就明給）。
- `add` 的 `--name`／`--ws`／`--stack` 語意同 aos-daemon-ctl（WS、S 從呼叫的 cwd 轉絕對；`--name` 預設 XXX 資料夾名、`--ws` 預設 cwd）；`ls --json`、`listen` 三個照舊；`open -d` 只開不接。

## 錯誤代號（C-54：主題＋Missing／Bad／Unknown／Failed／Exists）

stderr 一行 `aos-agent: 代號 原因`、退 1（`chat` 被 Ctrl-C 退 130）。沿用 aos-eca／aos-daemon-ctl／aos-listen 的：`ArgumentsBad`、`FlagUnknown`、`CommandUnknown`、`DaemonMissing`、`InstanceMissing`（表上沒有這隻）、`InstanceExists`、`PathMissing`、`SessionBad`、`Timeout`、`SendFailed`、`PostFailed`、`QuestionUnknown`、`AnswerMissing`。新的：`TargetMissing`（沒給 `--target`、沒設 `AOS_AGENT`）、`InterfaceMissing`／`InterfaceBad`（XXX 沒宣告／宣告讀不懂）、`ScreenMissing`（沒宣告畫面）、`ScreenBad`（宣告的入口不在或退非 0）。aos-daemon-ctl 的 `ProcMissing` 進到 aos-agent 一律講成 `InstanceMissing`。拿掉的：`KindUnknown`、`WsOccupied`、`MarkerBad`、`PromptMissing`／`SystemMissing`／`ToolsMissing`／`CfgBad`（add 不再驗內容）。
