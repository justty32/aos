## 介面 `aos-agent/screen`

| # | 類 | 約定 |
|---|---|---|
| 1 | 起法 | 資料夾程式（`_entry`），`aos-exec --ws <那隻的 ws> --stack <那隻的 stack> <定義>/<宣告的資料夾> 動作`；**args 就是動作**：`open`、`open -d`、`close`、`watch` |
| 2 | 環境變數 | 吃 `AOS_STACK`（那隻的 stack）、`AOS_WS`（那隻的工作區）、`AOS_CD`（自己所在；eca 用 `..` 找 `cli.json`）；不設任何變數 |
| 3 | stdio／結束碼 | stdin／stdout／stderr **接呼叫者的**（`open` 要拿終端機 attach）；退 0＝做了；退 1＝stderr 一行 `程式名: 代號 原因`（`ArgumentsBad`、`SessionBad` 正在答、`ScreenFailed` 開不起來） |
| 4 | 信箱 | 不用 |
| 5 | 不管 | 畫面是 tmux 還是別的、session 檔在哪、`watch` 讀什麼——aos-agent 只透傳 |

## 介面 `aos-agent/llm`

| # | 類 | 約定 |
|---|---|---|
| 1 | 起法 | 資料夾程式；args＝`對象 動作 [鍵=值…]`：**對象** `stack`（正在跑的那一隻＝副本 `$AOS_STACK/llm.json`）或 `def`（定義裡的設定）；**動作** `show`、`set 鍵=值…`、`reset`（只有 `stack` 有：刪副本）。兩個都明寫、不猜（C-56「寫什麼就做什麼」） |
| 2 | 環境變數 | `stack` 對象要 `AOS_STACK`（沒設＝`StackMissing`）；`def` 對象不看它。`AOS_CD`＝自己所在（定義裡），用 `..` 找定義的設定檔。不設任何變數 |
| 3 | stdout | `show`→一行一個 `鍵=值`，順序固定、**至少有 `model`**；像 `key` 這類祕密印 `***`。`stack show`＝定義的值被副本蓋過後的結果；哪些鍵來自副本印在 **stderr** 一行「副本：model」。`set`→做完再印一次 show |
| 4 | 結束碼／錯 | 0＝做了；1＝stderr 一行 `程式名: 代號 原因`：`ArgumentsBad`（對象、動作、`鍵=值` 寫錯）、`KeyUnknown`（這隻不認的鍵；`show` 印得出來的鍵就是認的）、`StackMissing`、`CfgBad`（設定檔或 `llm.json` 讀不懂）、`WriteFailed` |
| 5 | 副本格式 | `$AOS_STACK/llm.json`＝一層物件 `{"鍵": "值"}`，只放改過的鍵；`reset`＝刪檔；N-05 先寫暫存再改名 |
| 6 | 身體的承諾 | agent 宣告 `llm` 子介面＝它的腦**讀設定時先看 `$AOS_STACK/llm.json`**（有的鍵蓋過定義／環境變數），每題重讀 |

鍵名：`model` 必有；其他由那隻定（fsm：`url`、`key`；eca：`kind` 只印不給改）。`show` 的輸出就是「這隻認哪些鍵」的宣告，不另列表。

## 子介面 `tools`：副本規則（不需要程式）

- 宣告 `"tools": "<登記檔相對定義>"`。**身體的承諾**：找登記檔時 **`$AOS_STACK/tools.json` 在就用它**，不在才用宣告的那份（旗標 `--tools`／cli.json `tools` 明給的仍優先，那是人寫在定義裡的）。
- `aos-agent tools --target bob [ls|get 名|add 名 路徑|rm 名|reset]`：`ls`／`get` 讀「副本在就副本、否則定義」那份（stderr 一行說用的是哪份）；`add`／`rm` 沒副本先建（複製宣告的登記檔到 `$AOS_STACK/tools.json`，每個 `path` 從登記檔所在資料夾解成**絕對路徑**），再 `aos-tools --file $AOS_STACK/tools.json add／rm …`（`add` 的路徑從呼叫 cwd 轉絕對再給）；`reset` 刪副本。沒宣告＝`ToolsMissing`。
- 改定義：人直接 `aos-tools --file <定義>/tools.json …`（現成；aos-agent 不包）。

## `aos-llm`：改定義裡的腦設定（新，`proto8/bin/aos-llm`，跟 aos-tools 並列）

使用者：「aos-agent llm改正在跑著的，aos-llm改定義」。**它不自己懂任何格式，就是叫那個 llm 入口、對象換成 `def`**：

```
aos-llm XXX [show|set 鍵=值…]        XXX＝agent 定義資料夾；沒給動作＝show
```

1. 讀 `<XXX>/interfaces.json`：沒有 `aos-agent` key 或沒宣告 `llm`＝`LlmMissing`；讀不懂＝`InterfaceBad`。
2. 讀 `<XXX>/<llm>/interfaces.json`：沒宣告 `aos-agent/llm`＝`LlmBad`。
3. `aos-exec --ws <XXX> <XXX>/<llm> def 動作 …`（不給 `--stack`、不設 `AOS_STACK`；`--ws` 給 XXX 只是 aos-exec 要一個工作區，入口不用它），stdio 透傳，結束碼照傳。
4. 錯：stderr 一行 `aos-llm: 代號 原因`、退 1：`ArgumentsBad`、`PathMissing`（XXX 不是資料夾）、`InterfaceMissing`／`InterfaceBad`／`LlmMissing`／`LlmBad`。Python 單檔、`aos_flags.parse`、純標準庫，跟 `aos-daemon-ctl` 同形。

對稱表：`aos-agent llm --target bob set model=x`＝`aos-exec --ws W --stack S <定義>/llm stack set model=x`；`aos-llm <定義> set model=x`＝`aos-exec --ws <定義> <定義>/llm def set model=x`。兩邊都是同一支入口程式，差在第一個 arg。`aos-agent tools` 與 `aos-tools` 同理，只是登記檔不需要入口程式。
