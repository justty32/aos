# 原則打架、沒寫清楚、必修

## 原則互相打架或沒寫清楚（7 處）

| # | 哪幾條 | 落點 |
|---|---|---|
| A | N-57「`AOS_STACK` 預設 `$AOS_WS/.stack/`」vs N-63 ②「hub 沒設＝報錯、不猜位置」 | 題 1：只有 aos-exec 給預設，其他一律 `StackMissing` |
| B | N-63 ①「值是資料夾」vs `AOS_AGENT`（名字）、`AOS_ROSTER`（檔）：`AOS_` 前綴底下四種性質，條文只寫兩種 | 題 2：N-63 加四種性質表 |
| C | C-69「aos 只訂六個環境變數」vs R8「格的旋鈕也要 `AOS_` 前綴」vs 11-01「旋鈕除非必要不用環境變數」 | 題 2 同一張表；R8 加註指過去 |
| D | N-63 ③「子程序繼承」vs P-39「`AOS_STACK` 叫別人時明給」 | 不衝突（繼承是預設、P-39 是慣例層做法），N-63 已有一句 |
| E | C-51「固定名字限縮、理想只一個」vs 11-04 晚「stack 是地盤、對外介面＝四類」vs P-42 三樣固定名 | 未裁：缺一張表分清「哪些固定名是定義的、哪些是介面的、哪些只是某支程式自己的」（使用者 10-31 也說「後續還有想法要追究」） |
| F | C-56「寫什麼就做什麼」vs 三個暗規則：daemon「物件多一個 key＝loop 型」、aos-tools「沒 stack 就暫存資料夾」、aos-eca「表上 ws 跟 cwd 相同就算」 | daemon 那條照題 3 不改、文件寫清楚；aos-tools 改 `StackMissing`；aos-eca 隨 aos-agent 拿掉 |
| G | NORMS 06「aos 的命令列只有 aos-exec」vs 二十多支命令列共用一套形狀、條文沒寫 | 題 7：形狀進 CONVENTION P-44 當慣例 |

## 必修（3 件，不用裁）

壞 symlink、刪沒人用的 `parse_flags`、aos-tools 沒 `AOS_STACK` 改報 `StackMissing`——都已做（07 步 0、08 步 5）。

## 還沒做的低項（列給將來 tidy）

- aos-post `see` 跟 lock `show` 同義：`see`→`show`。
- aos-lua 用 `os.execute` 拼字串跑 `mkdir`／`chmod`：改 Lua 檔案 API 或 argv 陣列（使用者 10-15 少用 sh）。
