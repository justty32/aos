# 要使用者裁的（10 題）

## 使用者裁定（11-04，選項原文或他的話，逐字）

1「只有 aos-exec 給 (Recommended)」　2「寫一張表 (Recommended)」　3「不動，文件寫清楚」　4「拿掉，不應該看特定檔案。add這塊，就是看最終指向的json的內部結構。」　5「留 key、沒寫時預設就是這兩個名 (Recommended)」　6 先問「這不是子項自己的定義中所寫的嗎？」（頂層解釋：stack 裡的 `loop.json`／`exec.json` 是 daemon 照自己名單生出來、包住子項入口的設定，不是子項定義資料夾那份；`stderr.txt` 是 daemon 接子項 stderr 的；三個都 daemon 寫）→「是否能在json中設置？但默認用這些名」　7「只進 CONVENTION 當慣例」　8「留 _、加 .json」　9「aos-exec 補認那 7 個」　10「fsm改名，嘗試用同義詞」

| 題 | 問什麼 | 決定 |
|---|---|---|
| 1 | `AOS_STACK` 沒設，誰可以給預設（打架 A） | aos-exec 以外一律 `StackMissing`；aos-tools 改 |
| 2 | `AOS_` 前綴底下的四種性質要不要寫成一張表（打架 B、C） | N-63 加四種性質表：執行環境／hub／人殼預設／旋鈕 |
| 3 | daemon 的 proc 型別怎麼認（打架 F；現況物件多寫任何 key 就變 loop 型） | 判法不改、文件寫清楚 |
| 4 | aos-daemon-ctl `add` 用 `XXX/loop.json` 在不在判 loop 型 | 不看 `loop.json` 在不在，改看 XXX 入口最終指到的 JSON 的內部結構 |
| 5 | `ctl.json`／`state.json` 是旋鈕還是固定名 | aos-loop 留 `ctl`／`state` key、沒寫＝`ctl.json`／`state.json`；`procs_ctl_mailbox` 同理給預設名 |
| 6 | daemon 寫進子項 stack 根的 `loop.json`／`exec.json`／`stderr.txt` | 三個名字可在 daemon.json 設、沒設＝現名 |
| 7 | 命令列統一形狀要不要升成規範（打架 G） | 進 CONVENTION 當慣例（不升規範） |
| 8 | `_tooldef`／`_metainfo` 這兩個名字 | `_tooldef.json`／`_metainfo.json`：`_` 留、副檔名加 |
| 9 | inst 單子 schema 列 17 個 key、aos-exec 只認 10 個 | aos-exec 補認那 7 個 |
| 10 | `state` 二義：`state.json`（loop 的窗）與 `state.txt`（fsm 的狀態名）同在 stack 根 | fsm 的 `state.txt` 換同義詞（挑了 `stage.txt`，見 [07](07-實作步驟.md)） |

實作步驟在 [07](07-實作步驟.md)、[08](08-實作步驟-等aos-agent後.md)。
