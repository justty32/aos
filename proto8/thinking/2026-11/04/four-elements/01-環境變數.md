# 環境變數：活的 15 個，分四種性質

條文依據：N-57（六個）、N-63（hub 型：`AOS_<名字>`、值是資料夾、沒設＝`<名字>Missing`、子程序繼承）、P-39（三類：繼承／每層覆寫／叫別人時明給）、R8（環境變數全大寫帶 `AOS_`）、使用者 11-01「除非真的有必要，否則不要用」。

## 盤點（誰讀誰設見程式；這裡只列判定）

| 性質 | 變數 | 誰設 → 誰讀 | 判定 |
|---|---|---|---|
| 執行環境（aos-exec 保證） | `AOS_WS`、`AOS_STACK`、`AOS_CF`、`AOS_CD` | aos-exec 每層設 → 全體 | 合 N-57。`AOS_STACK` 由 aos 設時結尾帶 `/`、`AOS_WS` 不帶（低，加註） |
| 執行環境 | `AOS_CO` | aos-exec 設 → **活程式沒人讀**（只有 aos-grow 拒搬、sandbox 照帶） | 合條文、無用途。低；不動（使用者 10-21 定的六個之一），條文可加一句「現無讀者」 |
| 執行環境（kernel 給腦） | `AOS_KERNEL_REPORT` | aos-llm-kernel 每封信設 → 三份 brain.py | **兩套**：值永遠是 `cur/<id>/report.json`，kernel 本來就照固定位置讀。中；建議改成 kernel 給腦的 `AOS_STACK`＝那封信的資料夾、腦寫 `$AOS_STACK/report.json`——用現有機制、少一個變數（11-01「現有機制組合一下就能搞定」） |
| hub | `AOS_KERNEL` | **活程式沒人設** → aos-llm-send | 代號 `MailboxMissing` 不合 N-63 ②（應 `KernelMissing`，N-63 已自記）。kernel 端讀 kernel.json 的 `mailbox`、不讀它＝同一個資料夾兩個入口。低；kernel 待重寫，加註 |
| hub | `AOS_DAEMON_STACK`（11-04 晚裁改名 `AOS_DAEMON`） | aos-daemon 起子項時設 → aos-daemon-ctl、aos-eca、aos_human | 合 N-63 三件。改名後 N-63「舊名退場：`AOS_DAEMON` 不留別名」整段反向，69 檔要改（aos-agent 05 已列）。aos_human 另外用「上層資料夾叫 `procs`」反推 daemon，是暗路（中；aos-agent 刪 extras/human 時消失） |
| 旋鈕（全樹繼承） | `AOS_ENTRY` | 人或 `.env` 設 → aos-exec、aos-grow | 使用者 11-01 裁「不拿掉」。**aos-mcp 主動 pop 掉它**（`aos-mcp:135`），違反 P-39「一路繼承」。低；問為什麼、加註或改 |
| 旋鈕（腦） | `AOS_BRAIN_URL`／`MODEL`／`KEY` | `.env` 設 → 四份 brain.py、json_edit | 使用者 11-01 裁「到時候再說、以後一個 `AOS_BRAIN` 指 kernel」。預設不一致：brain.py 是 `default`、json_edit 是 `chatgpt-gpt-6-luna-low`（低，改成同一個） |
| 旋鈕（hub 形） | `AOS_HEAP` | 沒人設 → lib/aos/memory | 不在 NORMS／CONVENTION；沒設退回 `$AOS_WS/.heap`，不合 N-63 ②。低；主人（agent-kai）已不在，瘦身候選 |
| 旋鈕 | `AOS_ROSTER` | 沒人設 → lib/aos/send_message | 不在條文；**值是檔不是資料夾**，不合 N-63 ①。低；主人（demo/talk）已不在，瘦身候選 |
| 退場 | `AOS_DAEMON` | 無 → 只為報錯提示 | 11-04 改名後反而變成正名；舊名變 `AOS_DAEMON_STACK` |
| 規劃中 | `AOS_AGENT` | 人殼 export → aos-agent | 值是名字、不是路徑；使用者 11-04 晚裁「N-63 加例外」 |

非 AOS 的：`PATH`（一律不動，合 N-59）、`HOME`／`CLAUDE_CONFIG_DIR`／`CODEX_HOME`（cli_session 找外部 CLI 的對話檔，條文沒寫、合理）、`TMUX`（aos-eca attach 前拿掉）。沒有 `OPENAI*`／`LITELLM*`。

## 兩套機制（同一件事既有環境變數又有旗標／檔）

| 事 | 環境變數 | 另一套 | 判定 |
|---|---|---|---|
| 工作區、stack | `AOS_WS`、`AOS_STACK` | `--ws`、`--stack`（aos-exec、aos-say、aos-mcp、daemon-ctl add、daemon procs 列的 `ws`／`stack`） | **不是濫用**：N-58 明定「旗標 ＞ 環境」，旗標是入口給值、環境是往下傳。但只有 aos-exec 該收旗標，其他程式從環境拿（C-69）——aos-say／aos-mcp 收 `--ws`／`--stack` 是因為它們是人殼指令、不經 aos-exec 起；aos-agent 規劃已裁「不留 `--stack`」，方向一致 |
| 哪個 daemon | `AOS_DAEMON_STACK` | `--daemon-stack` | 合 N-63（使用者 10-30「環境變數＋argv」） |
| kernel 信箱 | `AOS_KERNEL`（寄信端） | kernel.json `mailbox`（kernel 端） | 兩個入口指同一資料夾。低，kernel 重寫時合一 |
| 設環境變數的路 | `.env` 檔 | JSON `.env` key、inst `envs`、閘門信 `env`、sandbox `env`（放行名單） | 前兩條是同一條（C-72）；後三條各在自己那層，不算冗餘。**但 key 名三義**：`envs`＝要設的、`env`＝整份環境、`env`＝名單——違 R4 一詞一義。低；加註或 sandbox 改 `env_allow` |

## `AOS_STACK` 沒設時四種反應（原則打架，詳 [05](05-原則打架與方向題.md)）

aos-exec＝退回 `$AOS_WS/.stack/`（N-57）；loop／fsm／daemon／kernel／eca-turn＝`StackMissing`（N-63 ②）；**aos-tools＝偷用暫存資料夾**（`bin/aos-tools:311`）；aos-say／aos_ws／cli_session attach＝算 `ws/.stack`。前兩種 N-63 已自記不合；第三種是 N-63 ②明禁的「自己猜一個位置」，**中、必修**：改 `StackMissing`。第四種是人殼指令，跟 aos-exec 同一條（合）。

## 條文對不上

- 條文有、程式沒有：`AOS_CO` 沒讀者；`AOS_KERNEL` 沒設者；`AOS_ROUND_*` 在 7 份條文裡還當例子（已刪）；`AOS_DIRNAME` 只在附錄；`env-vars.json`（11-01 盤點）59 列已過期（沒有 `AOS_DAEMON_STACK`）。
- 程式有、條文沒有：`AOS_HEAP`、`AOS_ROSTER`；kernel 的 accept 模式「只疊 `AOS_` 開頭的」（`serve.cpp:485`）；aos-sandbox ENV_BASE 白名單（**漏了 hub 型 `AOS_DAEMON_STACK`、`AOS_KERNEL`**——沙箱裡的程式預設找不到 daemon，該考慮沒考慮，中）；`identity()` 順序 `WS＞STACK＞CF＞cwd` 只在程式註解（N-64 ③只講第一順位；低，加註）。

## 命名

- N-63 ①「值是資料夾」：`AOS_KERNEL`（無後綴）vs `AOS_DAEMON_STACK`（帶 `_STACK`）同是 hub、命法不同——11-04 改名後一致。`AOS_ROSTER` 值是檔。
- N-63 ②「`<名字>Missing`」：`MailboxMissing`（應 `KernelMissing`）、`DaemonMissing`（改名後剛好合）。
- 測試變數前綴不一（`AOS_FFI_KEEP` vs `FSM_SPY_LOG`、`FAKE_LOG`）：低，不動（測試自己的事）。
- 長得像環境變數的巨集／常數（`AOS_STATIC_PIE`、`AOS_API`、`AOS_INST_*`、`AOS_MARKS`、`AOS_LUA`）：grep 時會誤判，低，不動。
