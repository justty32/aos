# 資料夾結構：定義資料夾乾淨，stack 裡有人越界

條文依據：C-51 10-31 加註（固定名字可以、但限縮：理想只一個固定檔當入口、其餘由它指定）、C-65（工作區乾淨、執行中的放 stack）、C-70（子 stack 由程式自己訂）、N-05（`.` 開頭暫存）、N-16（信箱四格）、N-28（daemon 小格）、N-50（工具＝`<格>/tools/<名>/`）、P-17（小格 `tools/<名>/`）、P-42（stack 三樣）、使用者 11-04 晚「stack 是 proc 自己的地盤…頂多考慮繼承於你的傢伙會不會命名衝突」「不喜歡透過特定檔案去判斷是哪個」。

## 固定名字清單（程式寫死會去找的）

**定義資料夾**（人寫的，aos 去讀）：

| 名字 | 誰認 | 判定 |
|---|---|---|
| `_entry`（＋`.json`） | aos-exec | 唯一該固定的（C-68）；`AOS_ENTRY` 可改。合 |
| `.env` | aos-exec | N-59 定。合 |
| `cli.json` | aos-eca、cli_session | eca 的「第二個固定檔」；10-31 使用者裁「現階段維持固定」。aos-eca 用「有沒有它」判斷是不是 eca（`aos-eca:228`）——**用檔名認種類**。中；aos-agent 規劃改認 `interfaces.json` 宣告後消失 |
| `interfaces.json`（規劃） | aos-agent | 第二個固定名；合 C-51 加註「註冊檔與固定名字共存」。合 |
| `tools.json` | aos-tools（`--file` 預設）、brain／act（`--tools` 預設）、cli_session | 有旗標、只是預設值。合 |
| `loop.json` | aos-daemon-ctl add（有＝loop 型）、aos-eca | **用檔名認種類**（`daemon-ctl:232`）。中；[06 題 4](06-要使用者裁的題.md) |
| `system.txt` | fixture agent-eve **寫死**（相對 cwd）；demo/agent-fsm 已改 `--system` | 低；改 eve 跟 demo 一樣 |

**stack**（proc 自己的地盤；P-42 把三樣當對外介面）：

| 名字 | 誰寫死 | 判定 |
|---|---|---|
| `ctl.json`、`state.json` | aos-loop **沒預設名**（寫了 key 才開）；daemon、aos-daemon-ctl 替子項補這兩個名；P-42、aos_ws、aos-say 當協議 | **旋鈕被三方寫死成結構**。中；[06 題 5](06-要使用者裁的題.md)：要嘛規範定死這兩個名（aos-loop 去掉 key、`ctl: true` 就開），要嘛 aos-loop 自己給預設名 |
| `state.txt` | aos-fsm 寫死 | 跟 `state.json` 同層、`state` 二義（窗 vs fsm 狀態名）；有人把 loop 的 `state` 設成 `state.txt` 就互踩、程式不擋。中；[06 題 10](06-要使用者裁的題.md) |
| `procs/<名>/`、`procs_ctl.json`、`procs_state.json`、`procs_state_procs/` | daemon（後三個是 key 預設名） | 合 N-28／R7。但 aos-daemon-ctl、aos-eca、aos_human **寫死** `procs_state.json`、`procs_ctl_mailbox`——daemon 那邊可改名、甚至信箱預設不開。同上「旋鈕被寫死」。中 |
| `queue/`、`history.jsonl`、`mailbox_warning.txt` | idle.py、aos-eca-turn、aos-say／listen | P-42 定的介面，使用者 11-04 晚認可（像 Go interface）。合 |
| `eca.json`、`<kind>/` | aos-eca-turn 寫、aos-eca／aos_human 讀：**有它＝eca** | 用檔名認種類。規劃退場。 |
| `tools/<名>/`、`tool_call.json` | act.py、aos-mcp、aos-tools | 合 P-17／N-50。`tools/` 在定義裡＝工具定義、在 stack 裡＝小格，一詞二義（11-02 定，低、加註） |
| `loop.json`、`.loop.json`、`exec.json`、`stderr.txt`（daemon 寫進**子項 stack 的根**） | aos-daemon | **daemon 把自己的檔放進別人的地盤**：子項若自己寫 `loop.json`／`stderr.txt` 就撞——正是使用者 11-04 晚說的「要考慮繼承於你的傢伙會不會命名衝突」。現在沒撞只是因為 agent-fsm 不寫這些名字。中；[06 題 6](06-要使用者裁的題.md) |
| kernel：`queue.json`、`served.jsonl`、`used.json`、`mailbox/`（`done/`） | aos-llm-kernel | `queue` 跟 agent 的 `queue/` 同字不同義；歸檔格叫 `done/`、aos-post 11-04 改 `archive/`。低；kernel 重寫時對齊 |

## 用檔名認種類（使用者不喜歡的那種）5 處

1. aos-daemon-ctl add：`XXX/loop.json` 在＝loop 型。2. daemon adopt：小格有 `loop.json`＝loop 型（**這個可以**：那是 daemon 自己寫的檔、自己的地盤）。3. aos-eca：沒 `cli.json`＝`EcaBad`。4. aos-eca／aos_human：stack 有 `eca.json`＝eca。5. aos_human：上層資料夾叫 `procs`＝在 daemon 下。6.（JSON 版）daemon：proc 物件多一個 key＝loop 型。
3～5 隨 aos-agent 刪 extras/eca、extras/human 消失；1 與 6 留著，要裁。

## 三種信箱、四種鎖、三種暫存名

| 事 | 形狀 | 判定 |
|---|---|---|
| 信箱 | aos-post：`tmp/new/cur/archive/` 一封＝一資料夾；kernel：`tmp/new/cur/done/`＋`reply/`；**lib/aos/send_message：`new/<id>.json`＋`sent/`**；舊題目協議：工作區 `new/cur/out/done/`（fixtures 還在用） | 第三種沒活主人（demo/talk 已刪）——冗餘，瘦身候選；第四種是舊協議、fixtures 只為測試留，加註。kernel 的對齊等重寫。中 |
| 鎖 | `lock`（cli_session，無副檔名）、`.lock/`（aos-lock，資料夾）、`.flock`（kernel、heap）、`sender.flock` | 低；加註（aos-lock 是正規的，其他是各自 flock 的檔） |
| 暫存 | `.名`（loop、fsm、brain）、`.名.tmp`（idle.py、aos-lock）、`.名.<pid>`（aos-tools） | 合 N-05（都 `.` 開頭）；三種尾巴低、不動 |
| 「完成」格 | aos-post `archive/`、kernel `done/`、舊協議 `done/` | 低；kernel 重寫時改 |

## 資料夾＝table 對應得怎樣

對上的：`_entry`、`.env`、`$AOS_ENTRY` 一段段走＝key 一層層取、`#/`、沒 `argv` 的物件＝資料夾。沒對應也不必對應的：stack（執行中狀態，沒有 JSON 雙胞胎）、信箱四格（靠 rename 原子性，JSON 做不到）。**沒有發現「同一件事 JSON 一份、資料夾一份」的真正重複**——daemon 的 procs 表＋資料夾是名單＋預設位置，不算。C-51「別濫用」目前守住。
