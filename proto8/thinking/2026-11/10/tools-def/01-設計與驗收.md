## 寫一支工具長什麼樣

`tool.py` 下半段（上半段是找 `tool_spec.py` 的固定幾行：自己的資料夾 → 祖先的 `lib/` → `$AOS_HOME/lib` → 標準 `sys.path`）：

```python
DESCRIPTION = 'Add two numbers and return the sum. Example: {"a": 2, "b": 3} -> 5'

PARAMS = [
    ts.param("a", "number", "the first number"),
    ts.param("b", "number", "the second number"),
]

META = {"side_effect": False}


def run(args):
    return args["a"] + args["b"]


ts.main(run, DESCRIPTION, PARAMS, META)
```

`tool_spec` 做的事：

- 由宣告產 `_tooldef`（`description`、`parameters` 的 JSON Schema、`errors`＝`ArgumentsBad`＋原始碼裡寫到的 `ts.fail("代號", …)`＋`RunFailed`）與 `_metainfo`（`summary`＝說明第一句，其餘 N-68 通用 key 給保守預設，`META` 只寫不同的）。
- 落點＝**位置**：資料夾寫兩個檔（暫存檔＋改名）；JSON 檔或 `檔.json#/指標` 寫 `_tooldef`、`_metainfo` 兩個鍵（經 `aos-json set --parents`）。三條路各自可單獨用：`tooldef(…)`、`metainfo(…)`、`write_defs(位置, td, mi)`；入口的 `--tooldef`／`--metainfo` 印 JSON、`--write-defs [位置]` 寫。
- 執行時：`tool_io.start` 拿記憶體裡的定義（不讀磁碟上的 `_tooldef.json`，所以以 `tool.py` 為準），`tool_io.arguments` 驗型別、必填、不認得的鍵；`tool_spec` 再查 `enum`、補 `default`；`run` 回字串原樣印、其他印一行 JSON；`ts.fail`＝錯誤行；`run` 裡其他例外＝`RunFailed run() raised ZeroDivisionError: … (tool.py line N)`；宣告寫錯＝`SpecBad`（錯誤行，不吐 traceback）。
- 不引第三方套件；現有工具不必遷移；`tool_io.py` 沒動。

## tools_def

- `new {path, description?}`：骨架整夾複製（暫存夾＋改名、略過 `__pycache__`；已經在＝`PathExists`），`description` 填進 `DESCRIPTION`，叫 `tool.py --write-defs`。結果直接印出 `tool.py` 要改的那段（gemma 第 1 輪整份重寫 `tool.py` 之後加的）。
- `check {path, sample?}`：一行一項——`entry`（資料夾的 `_entry`／`_entry.json`，或物件的 `_entry` 鍵；argv 裡的 `.py` 在不在、編不編得過，壞了給行號）→ 用 `tool_spec` 的腳本先 `--write-defs 位置` 重產（`made`）；骨架抄出來的 `tool.py` 不再用 `tool_spec`＝bad → `metainfo` → `tooldef`（資料夾與 JSON 檔另經 `aos-tools` 暫存登記檔 `add`＋`get`；說明還是骨架那句＝bad）→ `example`：說明裡寫的 `Example: {…} -> 結果` 照跑比對（gemma 第 3 輪只改說明沒改程式之後加的）→ `try`：給了 `sample` 就 `aos-exec` 叫一次（成功但沒輸出＝bad）→ 最後一行 `stage N of 3 (entry, _metainfo, _tooldef)`＋缺什麼＋下一步（可以掛了就給 `self_tools add` 與「下一輪直接用名字叫」）。有 bad＝最後一行 `tools_def: error: ToolBad N problem(s) …`、退 1。
- 例：

```text
ok    entry: _entry.json runs ["python3", "tool.py"] (Python compiles)
made  _tooldef and _metainfo from tool.py
ok    metainfo: valid (Multiply two numbers and return their product)
ok    tooldef: valid, parameters: a, b
ok    example: {"a": 6, "b": 7} -> 42 (as the description says)
ok    try: {"a": 6, "b": 7} -> exit 0: 42
stage 3 of 3 (entry, _metainfo, _tooldef) - a tool: add it with self_tools {"op": "add", "path": "my_math/multiply"}; from your next turn call it directly by its name, like any other tool: multiply {"a": 6, "b": 7}
```

## 位置：現況支援到哪（11-10 深夜實測）

## 之後可加：分階段流程

使用者理想中的流程（原話 3、4）：①資料夾＋`_entry.json`＋小 Python ②補 `_metainfo` ③補 `_tooldef`。現在怎麼接：

- `check` 已經說出階段（`stage N of 3`）與缺什麼，對任何位置都行（不必是 `new` 起的；手寫工具如 `lib/base/math` 也過）。
- 「補 metainfo」「補 tooldef」的本體已在 lib：`tool_spec.metainfo(…)`、`tool_spec.tooldef(…)`、`tool_spec.write_defs(位置, …)`；之後加 op 只是薄薄一層，例如 `tools_def {"op": "add_tooldef", "path": 位置, "description": …, "params": [...]}`（params 用 `{name, type, description, default?, enum?}` 的 JSON，等於 `ts.param` 的參數）。
- 「補入口」：寫一份 `_entry.json`（或物件的 `_entry` 鍵）＝`["python3", "腳本.py"]`；之後的 op 可以把骨架的 `tool.py` 抄到旁邊。
- JSON 物件裡的工具：等 aos-tools 認 `#/` 才掛得上（上表）。 **11-12 使用者裁：「之後可加」結案**（[small-rulings](../../12/small-rulings.md)）

## 代定（可翻案）

1. lib 名字與位置 `proto8/lib/tool_spec.py`（跟 `tool_io.py` 同層）。
2. 骨架放 `proto8/templates/tool-python/`（名字照範本夾慣例用連字號；不是 agent 範本，`agent_def` 列範本只認有 `interfaces.json` 的，不會列到它）。
3. 骨架的形狀：`_entry.json`（inst 單子 `{"description", "argv": ["python3", "tool.py"]}`，用物件是為了帶 `description` 給 code map）＋`tool.py`；不用 `_entry` 可執行檔，好處是腦用 `write` 重寫 `tool.py` 也不會掉 `+x`。
4. `_tooldef.json`／`_metainfo.json` **落檔**（不走「執行檔答 `--tooldef`」）：資料夾工具照現行契約三個檔、aos-tools／metainfo／packs 都直接讀；`tool.py` 是真相、兩個檔是產物，`check` 每次重產（`check` 會寫檔——是「檢查並補齊產物」，名字沒另取）。
5. `errors` 自動收原始碼裡的 `ts.fail("代號"`，另加 `ArgumentsBad`、`RunFailed`；工具名預設＝`tool.py` 所在資料夾名。
6. `enum` 在 tool_spec 查（tool_io 刻意不查，留給有 `op` 的工具報 `OpUnknown`；tool_spec 的工具沒有這個需要）。
7. 錯誤代號新增 `RunFailed`（run 裡的例外）、`SpecBad`（宣告寫錯）、`ToolBad`（check 有 bad）、`PathExists`（new 的目的地已在）。
8. `check` 的 `example`：說明裡寫成 `Example: {JSON} -> 結果` 才跑；比對＝字面相同或兩邊都是相等的數字。
9. 不做成「人用的指令先有、工具包它」：aos-tools 沒有對應的子命令可包（`get` 只查已登記的），新做一支人用指令的好處不大；人直接 `cp -r` 骨架、`python3 tool.py --write-defs`。`check` 內部借 `aos-tools add＋get`（暫存登記檔）當現成檢查。
10. knowledge 節點新開 `knowledge/aos/tools.json`（`tools_def`、`tool_spec` 兩格）＋`aos/_index.json` 一格；沒動別隊正在改的 `agents.json`。
