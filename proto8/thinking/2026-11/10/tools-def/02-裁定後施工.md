## 1 eca 掛回基礎四包

- `templates/eca-claude/tools.json` 跟 agent-fsm 一樣疊十一包，34 支；經 aos-mcp `tools/list` 實測 34 支。範本 README、templates/docs、lib/packs、knowledge packs 節點、tool-packs 紀錄跟著改。

## 2 `檔.json#/指標` 當工具

- **aos-tools**（Python，沒動 C++）：`kind_of` 認 `#/`（種類算 `json`，`#` 前面的檔要在）；`inspect` 經 `aos-json get --follow --resolve 檔#/指標` 讀那個物件的 `_tooldef`／`_metainfo`；`call` 照交 `aos-exec 檔#/指標`。`get`／`rm` 用路徑也認。`aos-agent tools add`、`self_tools add` 原樣轉交，不用改。
- **lib/metainfo.read** 收 `檔#/指標`（自己走指標，`~1`、`~0` 照 RFC 6901）。
- **tools_def**：`check` 對指標也經 aos-tools 暫存登記檔 `add`＋`get` 驗；最後一行給 `self_tools add` 與名字。`new` 收 `檔.json#/指標`（或新的 `檔.json`）：物件寫 `_entry` 鍵 `["python3", "<名>.py"]`、骨架腳本放 JSON 檔旁邊、`--write-defs` 寫進物件；同一個 JSON 檔可以放好幾支。
- **分階段三個 op**（原話 3、4 的理想流程）：`add_entry`（寫入口，腳本不在就抄骨架的過去）→ `add_metainfo` → `add_tooldef`（腳本用 tool_spec 又沒給 `description`＝照腳本產；否則照 `description`／`meta`／`params` 產）。資料夾、JSON 檔、`檔#/指標` 都通；已經有＝`PathExists`；每步印 `stage N of 3` 與下一步。

代定（可翻案）：

1. 登記檔裡存法：只有 `#` 前面那段照原規則（給絕對存絕對、給相對存「相對登記檔資料夾」）；`#/` 後面原樣。
2. 預設工具名＝指標最後一段（`~1`、`~0` 解開，不合 `[A-Za-z0-9_-]` 就 `NameBad`、用 `--name`）；JSON 檔沒有指標＝檔名去 `.json`。
3. 旁邊小 Python 的相對路徑從 **JSON 檔的資料夾**算（照 aos-exec 對 `檔#/指標` 的 cwd）。
4. `ls -l` 的種類欄仍寫 `json`，路徑帶 `#/…`。
5. tool_spec 預設名：腳本叫 `tool.py`＝資料夾名，其他（`mul.py`）＝檔名去 `.py`，跟指標最後一段一致。
6. op 名字：`add_entry`、`add_metainfo`、`add_tooldef`；`add_entry` 的腳本預設＝資料夾 `tool.py`、物件 `<名>.py`，不在就抄骨架的（它本身就是能跑的加法）。
7. `add_tooldef` 的 `params`＝`ts.param` 的參數（`name, type, description, default?, enum?, items?, required?`）；`errors` 只有 `ArgumentsBad`＋`RunFailed`。

## 3 同一輪就生效

- **fsm**：每一步 brain 與 act 都是新起的行程、各自 `aos-tools ls --json` 重讀登記檔，所以是穩定行為、不是碰巧。精確說：加了之後**下一則回覆**（同一輪的下一次想）工具清單就有它、也叫得到；**同一則回覆裡**、排在 add 後面的呼叫＝`ToolUnknown`（act 開跑時讀一次清單）。測試 `templates/tests/agent-fsm/test_same_turn_tools.py` 釘住這三件事。
- **eca**：第一次重跑 haiku 時同一輪叫不到（Claude Code 回 `No such tool available`）。原因兩個：aos-mcp 沒通知清單變了；而且 session 開始時這隻自己那份登記檔（stack 裡）還不在，cli_session 交給 aos-mcp 的是定義那份，self_tools 第一次 add 才建出 stack 那份，aos-mcp 根本看不到。改法：aos-mcp initialize 宣告 `tools.listChanged`，`tools/call` 回完清單變了就送 `notifications/tools/list_changed`；新旗標 `--own FILE`（在＝用它、不在＝用 REGISTRY，每次重看），cli_session 起它時帶 stack 那份。重跑：haiku 同一輪 `self_tools add` 之後先叫錯名字 `multiply`（`No such tool available`），接著叫 `mcp__aos__multiply {"a":6,"b":7}` 得 42。測試 `cmd/aos-mcp/tests/test_list_changed.py`（2 支）。
- 說法統一成「works at once: from your next reply in this turn; call a new tool directly by its name, not in the reply that added it」：self_tools 的成功行、tooldef、help；knowledge `me.json#/self_tools`、`tools.json#/tools_def`；tools_def check 最後一行；骨架 README；agents_children 轉手時換成「kid's next reply」。

## 驗收

- 假腦（fsm，劇本 `td-ptr`）：一題裡 `tools_def new fns/box.json#/tools/mul`、`…#/tools/sub` → `edit` 兩支腳本 → 兩支 `check`（example 與 try 都 ok、stage 3 of 3）→ `self_tools add` 兩個指標 → **同一輪下一則**叫 `mul {"a":6,"b":7}`＝42、`sub {"a":10,"b":3}`＝7。另手動 `aos-tools add 'box.json#/tools/sub'` → `call`＝5、少參數＝`sub: error: ArgumentsBad missing b (required)`。
- eca haiku（十一包、題目「Make a tool that multiplies two numbers, then use it to compute 6×7.」，沒有手動補 edit）：第一次 `new` → `edit`（掛回的 change 包）→ `check` 42 → `self_tools add` → 同一輪叫不到（見上），答 42 是自己算的；修 aos-mcp／cli_session 後第二次：同一輪叫到 `mcp__aos__multiply` 得 42。
- gemma：這輪沒跑（裁定三題都不需要小模型才驗得到；假腦與 haiku 已驗）。
