# 逐支

## aos-loop（lv2）

> 白話：aos-loop 照一份設定檔，把一件事一圈一圈重複跑；那件事退 0 就再跑、退 10 就收工、其他就帶著那個碼停下。旁邊有三個檔可以遙控它（ctl：暫停／繼續／停）與看它（state、state_flux）。

裝不下（4）：一定要有 `AOS_STACK`（沒有旗標可給）；三個「窗」；`-- ARGS`；`--enable-logs`／`--enable-counters`。

```
$ aos-loop loop.json
aos-loop: error: StackMissing the ctl window needs AOS_STACK, which is not set (write null to turn it off)
$ aos-loop loop2.json --max 1
aos-loop: error: ArgumentsBad flag --max must come before the config file; when started via aos-exec, put flags in the definition's _entry …
```

- **O1（補說明）**：help 完全沒提 `AOS_STACK`（aos-fsm 的 help 有提）；錯誤訊息的「write null to turn it off」沒說寫在哪（是設定檔的 `"ctl": null`）。人想單獨試 aos-loop 一定先撞這個。改法：help 加一句「needs $AOS_STACK (run it through aos-exec, or set it yourself)」，訊息補「"ctl": null in CONFIG.json」。只動字，不動行為。
- 旗標寫在設定檔後面的訊息講得很對（這是今天 aos-tools 才補上的那種訊息，aos-loop 早就有）。

## aos-daemon（lv2）

> 白話：aos-daemon 照一份設定檔照顧一群行程：把它們起起來、照 ctl 說的重起或停掉、把狀況寫在 state 檔；自己也可以順便每圈跑一件事。

裝不下（5）：同樣要 `AOS_STACK`；poke 的三個訊號；stop／sleep 的差別；退 0 就下表；stuck 判定兩種單位。

- **O2（補說明）**：help 有 12 行在講生命週期規則（stop 不補 SIGTERM、退 0 下表、stuck 連三次…），是對的，但人要的「三對停與起」表在這裡也沒有；跟 [02](02-aos-daemon-ctl.md) B8 那張表合成一份、兩邊都指過去。
- help 沒有 `名字 - 一句話` 的首行（X10）。

## aos-fsm（lv3）

> 白話：aos-fsm 照一張狀態表走一步：看現在在哪個狀態（記在 stack 的 `stage.txt`），跑那個狀態的事一次，再照它的退出碼查下一個狀態。

裝不下（2）：`next` 的寫法（名字＝只認 0；物件＝照碼）；退出碼三種來源。

```
$ aos-fsm fsm.json                       → StackMissing AOS_STACK is not set
$ AOS_STACK=$PWD/fs aos-fsm fsm.json     → CfgBad state b: next must have "0" or "*" (exit code 0 must always match)
```

沒有怪點；訊息清楚。

## aos-json（lv3；跟 lv0 指示詞緊鄰）

> 白話：aos-json 讀寫 aos 的 JSON 檔裡的一格。位置寫成 `檔#/路徑`；`get`／`peek` 看、`set`／`append`／`merge`／`del` 改、`batch` 一次改多格、`check` 檢查；另外能寫入與追蹤兩種指示詞（`env`、`ref`、`where`）。

裝不下（4）：`--follow`（跟著 `$ref` 走）與 `--resolve`（把指示詞解開）是兩件事；`set` 的值要是 JSON、字串要加 `--str`；`--parents`；`--check`。

```
$ aos-json get 'j.json#/e'            → {"$env": "HOME"}
$ aos-json get --resolve 'j.json#/e'  → "/home/guanyu"
$ aos-json set j.json#/s hello        → ValueBad value is not JSON (add --str to write a string): hello
$ aos-json set j.json#/x/y 1          → PointerMissing … (… add --parents to create objects along the way)
```

- 訊息都會告訴你下一步，是全家寫得最好的一支。
- **O3（只是不熟）**：`where` 在這裡是「這個值是從哪個檔來的」，在 daemon-ctl／aos-agent 是「它的 stack 在哪」（[07](07-指令樹.md) T6）。
- **O4（補說明）**：`aos-json env`／`ref`（寫指示詞）跟 `aos-directive`（解指示詞）是一寫一解，兩支的 help 互相沒提。

## aos-directive（lv0）

> 白話：aos-directive 從 stdin 讀一份 JSON，把裡面所有指示詞（`$ref`、`$env`…）解開，印成一行。

```
$ echo '{"p":{"$env":"HOME","$path":"/x"}}' | aos-directive   → {"p": "/home/guanyu/x"}
$ aos-directive j.json   → ArgumentsBad takes no arguments, reads stdin; got extra j.json
$ aos-directive          （不給 stdin）→ 印 {}，退 0
```

- **O5（設計如此）**：只收 stdin、不收檔名（aos-json 收檔名）；相對路徑從現在站的地方算（aos-json 從檔的位置算）。lv0，不動；help 已寫「relative paths from the current directory」。

## aos-lock（lv3）

> 白話：aos-lock 在一個檔或資料夾旁邊放一把鎖：`acquire` 拿、`release` 放、`show` 看是誰拿著。拿不到退 10。

裝不下（2）：鎖放在哪（資料夾＝`目標/.lock/`、檔＝`目標.lock/`）；「我是誰」是從 `AOS_WS`／`AOS_STACK`／`AOS_CF` 或現在站的地方認的。

沒有怪點。已知：B14（同一工作區的兩方分不出誰是主）。

## aos-post（lv3）

> 白話：aos-post 是資料夾做的信箱：`init` 建一個、`send` 寄一封（內容從 stdin）、`take` 領下一封、`see` 看、`done` 結案（可順便回信）、`regret` 撤回還沒被領的。沒信退 10。

裝不下（2）：`--ordered`；領了沒結案的信留在 `cur/`。

- **O6（只是不熟）**：佔位名這裡叫 `MAILBOX`，旗標 `--reply-to BOX`、aos-llm 也叫 `BOX`（X10）。
- 使用者 11-10 的命名原則（「mailbox，他是底層的aos post機制…應該是用承載的機制作命名」）講的是上層別拿 mailbox 當名字；aos-post 自己就是那個底層，叫 mailbox 沒問題。

## aos-llm-kernel（lv4）

> 白話：aos-llm-kernel 跑「問腦總機」的一圈：把答完的收回來回信，再從排隊的請求裡挑幾封交給腦去答。平常是 daemon 每圈叫它，人不打。

沒有怪點。在[指令樹](07-指令樹.md)上它掛在 `aos llm` 底下，跟 `send／recv／ask` 同層，但性質不同（T2）。

## aos-sweeper（lv2 周邊）

> 白話：aos-sweeper 幫一台 daemon 打掃一輪：太大的 stderr 檔壓起來封存、太舊的封存刪掉、沒人管的殘留行程請它停、殘留的鎖夾清掉，最後寫一份報告。平常是 daemon 表上的 `_sweeper` 列每十分鐘跑一次。

裝不下（3）：copytruncate 可能掉最後幾行；殘留行程要「證明得了」才動；跟 `aos-daemon-ctl sweep` 是同一段程式、預設不同。

- **O7（補說明）**：同一件事兩個入口（`aos-sweeper` 與 `aos-daemon-ctl sweep`），保留期預設一個 7 天一個不刪；`--purge` 只有後者有。兩邊 help 都有寫對方。算清楚，但在樹上是同一功能掛兩處（T6）。
- `sweep --dry-run` 的輸出「bad files: 0」沒說 bad file 是什麼（help 裡有：`*.bad-*` 證據檔）。

## aos-clock（lv3）

> 白話：aos-clock 把一個「鐘檔」裡的數字加一。根 daemon 每秒叫它一次，別人讀這個檔就知道現在是第幾拍。

- **O8（只是不熟）**：名字讀起來像「看時間」，其實是「推一格」。help 第一句有講（「move a clock file one cycle forward」）。help 是牆型（X10）。

## aos-sandbox（lv5 周邊）

> 白話：aos-sandbox 照一份設定把一支程式關在沙箱裡跑：用哪個帳號、能用多少資源、看得到哪些路徑、能不能上網。`--dry-run` 只印它會怎麼跑。

```
$ aos-sandbox --dry-run j.json#/b echo hi
["/usr/bin/bwrap", "--unshare-all", "--die-with-parent", "--proc", "/proc", …]
```

- **O9（設計如此，留意）**：設定裡不認得的 key 一律忽略（help 有寫「unknown keys are ignored」）——打錯字的限制會安靜不生效。跟 B09（budget.senders 對不上安靜不生效）同型，留大修。
- help 牆型（X10）。沒在沙箱帳號下實跑（不 sudo）。

## aos-grow（lv6）

> 白話：aos-grow 把一段「要跑什麼」的寫法升一級或降一級：行內指令 ⇄ 一個檔 ⇄ 一個資料夾，並把呼叫它的那一格與相對路徑一起改好。

- `--dry-run` 只能寫在 `up／down` 前面（X3 同型）；`CALLER` 這個佔位名要讀兩行才懂（＝`設定檔#/路徑`）。沒實跑（只讀 help）。

## aos-feedback（lv6）

> 白話：aos-feedback 收集「哪支指令哪裡難用」的回饋：`add` 記一筆、`ls` 看哪支被抱怨最多、`show` 看全文、`score` 出一份舒適度報告。

- usage 寫成 `{add|ls|show|score}`（argparse 風，全家只有它）；`--json` 寫在前後都收（全家只有它與 aos-tools `--file`）；退出碼多一個 141。實跑 `ls`：欄位之間是兩個空白不是 TAB（別支是 TAB）。
- **O10（順帶）**：這支本來就是拿來記這類怪點的；這次掃出來的東西要不要也 `add` 進去，由使用者決定（沒代做）。
