## 逐項

### X1　指出「對哪個東西下指令」

| 指令 | 旗標 | 環境變數 | 都沒給 |
|---|---|---|---|
| aos-agent、aos-daemon-ctl、aos-sweeper | `-d／--daemon`（只能最前） | `AOS_DAEMON` | `./.stack` |
| aos-llm | 沒有 | `AOS_LLM_KERNEL` | 報 `LlmKernelMissing` |
| aos-tools | `--file`（前後都收） | 沒有 | `./tools.json`（不在會提醒） |
| aos-mcp | 位置參數 `REGISTRY…` | 沒有 | `./tools.json`（不在報 `ToolMissing`） |
| aos-eca-screen | `--eca`（定義）＋ | `AOS_STACK`（哪一隻） | 報錯 |
| aos-loop、aos-fsm、aos-llm-kernel | 沒有 | `AOS_STACK` | 報 `StackMissing` |
| aos-exec | `-s／--stack`、`-w／--ws` | `AOS_STACK`、`AOS_WS`（沿用外層） | `./.stack/`、現在站的地方（自己建） |
| aos-lock、aos-post、aos-json | 位置參數（檔／信箱） | — | 報錯 |

日常最常撞的是第一列：預設 `./.stack` 是 11-05「在 ws 裡起 daemon」那個用法留下的（`using-aos-agent.sh` 的註解：「AOS_DAEMON 沒設＝export 成 $PWD/.stack」），11-10 的日常用法根在 `stacks/root`（名字還不固定：「defs/, stacks/都只是舉例」），預設永遠不中。而補救辦法 `export AOS_DAEMON` 有 X12 的副作用。

### X2　指出「哪一個名字」

```
aos-daemon-ctl stop ann                 位置參數
aos-agent ctl stop -t ann               -t（位置參數報錯）
aos-agent ctl rm ann                    只收位置參數（-t 報錯）
aos-daemon-ctl where --stack ann        旗標的值
aos-agent ctl where --stack -t ann      --stack 是開關、名字給 -t
aos-agent tools -t ann add …            -t 要在動作前
aos-agent ctl state -t ann              -t 要在動作後
```

證據：[01](01-aos-agent.md) A1、A3，[02](02-aos-daemon-ctl.md) B4。

### X3　旗標能寫在哪

| 規矩 | 誰 |
|---|---|
| 「全域」旗標只能在子命令前 | aos-agent `-d`、aos-daemon-ctl `-d`、aos-eca-screen `--eca`、aos-grow `--dry-run` |
| 前後都收 | aos-tools `--file`（11-10 改）、aos-feedback `--json` |
| 子命令自己的旗標只能在位置參數前 | 全家（aos-daemon-ctl add、copy-out、aos-loop、aos-exec…）——這條是一致的家規，aos-exec／aos-loop 更是必須（後面的要原樣傳給程式） |
| 看子命令 | aos-agent `-t`（X2） |

寫錯位置時的訊息品質也不一：aos-loop 會說「flag --max must come before the config file」；copy-out 說「too many arguments」；aos-daemon-ctl add 說「add takes only one XXX; to pass arguments write XXX -- ARGS...」；`-d` 寫後面只說「unknown flag -d」。

### X4　`--stack` 四個意思

| 哪裡 | 意思 | 值 |
|---|---|---|
| `aos-exec --stack S`、`ctl add -s S`、`aos-mcp --stack DIR` | 「用這個資料夾當 stack」 | 路徑 |
| `aos-agent ctl where --stack` | 「印 stack（不是 ws）」 | 沒有值 |
| `aos-daemon-ctl where --stack NAME` | 「查這個名字的 stack」 | 名字 |
| `aos-agent ctl who --stack S` | 「這個 stack 是誰的」 | 路徑（要查的） |

另外 usage 裡的 `S` 一行出現兩次不同意思：`ctl add [-s S] … [--timeout-s S]`（一個是 stack、一個是秒）。

### X5　工作區沒給時

aos-exec＝現在站的地方；`aos-agent ctl add`＝`$AOS_WS`、沒有就現在站的地方；`aos-daemon-ctl add`＝daemon 的工作區；aos-mcp＝報 `WsMissing`。前三個各自合理，help 都有寫；差別只在「兩支 add 預設不同」沒有任何地方並排講。

### X6　成功時印什麼

| 指令 | 成功印 |
|---|---|
| `aos-agent ctl stop／start／sleep／wake／pause／resume` | 一句話（含下一步怎麼做） |
| `aos-agent ctl add` | stack 路徑 |
| `aos-agent say` | 信名 |
| `aos-daemon-ctl add／rm／stop／start／sleep／wake` | 信名 |
| `aos-daemon-ctl pause／resume／shutdown` | 一個數字（ctl 序號） |
| `aos-daemon-ctl poke`、aos-lock、aos-post init／done、aos-json set、aos-clock | 不印 |
| copy-out、aos-tools add／rm | 一句話 |

零件不印或印信名是對的（給程式接）；問題只在**人每天打的 `shutdown` 印一個 `1`**，以及 aos-daemon-ctl 那六個印信名卻不代表做成（[02](02-aos-daemon-ctl.md) B1、B2）。

### X7　列表長相

```
aos-daemon-ctl ls   NAME  PHASE  PID  CODE  WS  REASON          ＋尾行 "# …"
aos-agent ctl ls    NAME  STATE  WORKSPACE  QUEUED  REASON
aos-agent ctl ls -l …＋ QUEUE  RESTARTS  COOLDOWN  LAST ERROR   （九欄）
aos-llm ls          name speed cost context slots backend summary
aos-agent tools ls  NAME  KIND  PATH
aos-tools ls -l     （有 FROM、STORED、ENV）
```

全部沒有表頭行（欄名只在 help 裡）；`WS` 對 `WORKSPACE`、`PHASE` 對 `STATE`；JSON 版的 key 又是另一套（`aos-agent ctl ls -j` 同時有 `state` 與 `phase`、`queued` 與 `queue`）。`-j／--json` 的旗標名全家一致（好事；只有 `aos-agent tools ls` 的 help 動作列寫成 `ls [--json]`、旗標段寫 `-j, --json`）。

沒表頭是家規（「results on stdout only (one line per item, TAB-separated…)」，給程式切欄用），所以加表頭要小心別弄壞切欄的人——選項在 [08](08-改法與施工順序.md) 甲3。

### X8　同一種錯的代號

| 情況 | 代號 |
|---|---|
| 表上沒有這個名字 | aos-daemon-ctl `ProcMissing`；aos-agent `InstanceMissing`（`common.py:92` 明寫著把前者翻成後者） |
| daemon 沒在跑 | `shutdown`／`poke`：`DaemonMissing`（核 pid）；`ping`／`aos-agent ctl add`：`DaemonFailed`（等逾時）；`ls`：不算錯 |
| 找不到 daemon 資料夾 | `DaemonMissing`（跟上一列同代號、不同事） |
| 工具通訊錄檔不在 | aos-mcp `ToolMissing`；aos-tools 提醒後當空的；aos-agent `ToolsMissing` |
| 定義資料夾路徑不對 | aos-eca-turn `AgentBad`；aos-exec `EntryMissing`；copy-out `TemplateMissing` |
| 沒給工作區 | aos-mcp `WsMissing`（別支的 `WsMissing` 是「資料夾不存在」） |

代號是程式會比對的東西（屬「輸出」但接近介面），改名要連帶呼叫者；建議只補文件對照表，留大修統一。

### X9　「已經是那樣了」

aos-agent：「state already reached is a successful no-op」退 0；aos-daemon-ctl：`PhaseBad … is already stopped` 退 1（`py/daemon_ctl/ctl.py:32-37`）。同一個動作、同一台 daemon、同一個名字。腳本寫 `aos-daemon-ctl stop x && …` 會在第二次跑時斷掉。（[01](01-aos-agent.md) A5）

### X10　help 長相與佔位名

四型：

| 型 | 長相 | 誰 |
|---|---|---|
| 甲型（新 C++） | `名字 - 一句話`／`usage:`／`subcommands:`／`flags:`／`exit codes:`／`more:` | aos-json、aos-lock、aos-post、aos-llm |
| 乙型（舊 C++） | 第一行就是 `usage:`，沒有「名字 - 一句話」 | aos-exec、aos-loop、aos-daemon、aos-fsm、aos-directive、aos-llm-kernel |
| 丙型（Python 新） | 同甲型，多 `target:`／`output:` 段 | aos-agent、aos-daemon-ctl、aos-eca-screen、aos-grow、aos-sweeper、aos-feedback、aos-tools |
| 牆型（Python 舊） | 沒有 `usage:` 字樣、用法縮排四格、整段長行、結尾 `Errors: … Codes: …` | aos-eca-turn、aos-mcp、aos-clock、aos-sandbox、copy-out（半牆） |

- `more:` 的路徑三種寫法：`aos-llm/README.md`（相對誰？）、`proto8/cmd/aos-agent/README.md`、沒有。
- `help` 這個字全家都不收（`aos-agent help` → `CommandUnknown`、`aos-exec help` → `EntryMissing`、`copy-out help` → 真的抄一份到 `./help/`）；`--version` 全家都沒有。
- 佔位名：定義資料夾叫 `XXX`（aos-exec、兩支 add；使用者 10-28 用語、11-10 裁「留 XXX」）、`DEF_DIR`（aos-eca-turn）、`ECA_DIR`（aos-eca-screen）、`TEMPLATE`（copy-out）；設定檔叫 `CONFIG.json`／`daemon.json`／`kernel.json`／`CONFIG`；名字叫 `NAME`、`N`（`-n N`）；信箱叫 `MAILBOX`／`BOX`；`D`、`S`（X4）。「留 XXX」是裁過的，不動；其他只在重寫 help 時順手對齊，不值得單獨施工。

### X11　逾時

`--timeout-s` 名字全家一致（好事），但等的東西不同、預設不同：aos-daemon-ctl add／rm／stop…＝「信被拿走」3 秒；pause／resume＝「套用」5 秒；shutdown＝「行程退出」15 秒；ping＝3 秒；sweep＝搶鎖 30 秒；`aos-agent ctl …`＝「daemon 做完」30 秒；aos-mcp＝工具執行 60 秒。另有 `--timeout-cycles`（listen）、`--wait-ms`（aos-lock）、`--stop-grace-s`。沒有的：`aos-llm ask`、`aos-agent watch`。各自 help 都有寫等什麼，算清楚；只缺 `ask`。

### X12　同字不同義

| 字 | 意思一 | 意思二 | 會不會撞 |
|---|---|---|---|
| `AOS_DAEMON` | 人：我要對哪台 daemon 下指令 | aos-daemon 起動時：我的上司 | **會**（[02](02-aos-daemon-ctl.md) B6 實跑） |
| `ctl` | 子命令名（`aos-agent ctl`、`aos-daemon-ctl`） | 每支 loop 旁邊那個控制檔（`ctl.json`、「ctl window」）；help 裡還有「ctl mailbox」（已改名 `procs_requests`） | help 讀起來繞（「stop: write its public ctl…」） |
| `kernel` | `AOS_KERNEL`＝判官（管能不能加 agent） | `AOS_LLM_KERNEL`＝問腦總機 | 名字像同一個東西的兩個變數 |
| `queued`／`queue` | 在判官那邊排隊的名次 | 這隻 agent 信箱裡的信數 | `ctl ls -l` 同一行兩欄 |
| `where` | aos-json：值的來源檔 | ctl：stack／ws 的路徑 | 不撞，只是不同 |
| `warning:` | 真的要注意的事 | 正常結果的說明（[01](01-aos-agent.md) A13） | 會讓人以為出事 |
| `--reply-to` | aos-post／aos-llm：回信信箱 | aos-daemon-ctl：同上，但順帶「只寄不等」 | 不撞 |
| `rm` | aos-daemon-ctl：下表、留 stack | aos-agent ctl：下表、刪 stack | **會**（A4） |
| `stop` | 對一個列 | `shutdown` 才是對 daemon（分開了，好） | — |

### X13　功能重疊（細節在 [07](07-指令樹.md)）

1. `aos-agent ctl` 對 `aos-daemon-ctl`：十個動作同名（add、rm、ls、where、start、stop、sleep、wake、pause、resume），寫法與後果各自不同（X2、X6、X9、`rm`）。
2. `aos-agent tools` 對 `aos-tools`（[01](01-aos-agent.md) A9）。
3. `aos-agent open／close／watch` 對 `aos-eca-screen open／close／watch`（前者轉呼叫後者；乾淨）。
4. `aos-sweeper` 對 `aos-daemon-ctl sweep`（同一段程式、預設不同）。
5. `aos-agent listen --follow` 對 `watch` 對 `open` 對 `chat`（看回答的五條路）。

### X14　相對路徑

全家收相對路徑（相對現在站的地方），只有 aos-eca-turn 的 DEF_DIR 要絕對（[04](04-aos-llm-eca-mcp.md) T1）。「存進檔時怎麼存」是另一回事：B01（daemon 表存相對路徑、`ctl add` 收環境變數寫法）是明天第一項，不重報。

### X15　`--envs`

`aos-agent ctl add --envs K=V`、`aos-tools add --envs K=V` 有；`aos-daemon-ctl add` 沒有。補說明即可（要帶環境變數就用 aos-agent，或寫進定義的 `.env`）。

## 一致、做得好的（留著別動）

- 錯誤行的形狀全家一樣：`程式名: error: 代號 原因`，退 1。
- 退出碼 10＝「沒事可做／還沒有」（aos-loop 的身體、aos-post 沒信、aos-llm 還沒回、aos-lock 拿不到、aos-json check 有問題、aos-eca-turn 佇列空），而且 aos-loop 把 10 當「收工」——整套接得起來。
- `-j／--json`、`-h／--help`、`--timeout-s`、`--dry-run`、`-y／--yes` 的名字全家一致。
- `-w／--ws`、`-s／--stack`、`-n／--name`、`-d／--daemon`、`-t／--target` 短名一致。
- 會刪東西的都會先問（終端上）或要 `-y`／`--apply`。
