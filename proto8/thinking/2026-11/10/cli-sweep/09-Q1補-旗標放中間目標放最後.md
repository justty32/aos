## 二、照「`aos-yyy zzz [旗標…] XXX`」逐支對照

判讀時我用的讀法（**要他點頭的地方標★**）：

- 「旗標在中間」＝子命令之後、位置參數之前。
- 「目標在最後」＝最後一個位置參數是被操作的東西。
- ★ **目標後面還接東西的**（`aos-exec XXX ARGS`、`aos-daemon-ctl add XXX -- ARGS`、`aos-tools call NAME JSON`、`aos-json set 檔#/格 值`）：我讀成「目標之後只能接原樣交給它的內容」，算合（N-58 本來就這樣）；嚴格讀就是不合。
- ★ **沒有目標的子命令**（`ls`、`shutdown`、`ping`、`poke`、`sweep`）：目標其實是「這台 daemon」，由 `-d` 給；我讀成合。
- ★ **`-d`（哪台 daemon）、`--file`（哪份通訊錄）**：是「在哪裡做」不是「對誰做」，我讀成旗標；所以照他的形狀要能寫在中間。

| 指令 | 現在的形狀 | 合不合 | 不合在哪 |
|---|---|---|---|
| aos-exec | `[旗標] XXX [ARGS]` | 合（★） | — |
| aos-loop、aos-daemon | `[旗標] 設定檔 [-- ARGS]` | 合 | — |
| aos-fsm、aos-clock、aos-llm-kernel、aos-eca-turn、aos-directive | `[旗標] 一個位置參數`（directive 沒有） | 合 | — |
| aos-lock | `子命令 [旗標] TARGET` | 合 | — |
| aos-post | `子命令 [旗標] MAILBOX [LETTER]` | 合 | 兩個位置（信箱→信），由大到小，最後一個是目標 |
| aos-json | `子命令 [旗標] 檔#/格 [值]` | 合（★） | `set／append／merge／env／ref` 目標後面接值 |
| aos-llm | `子命令 [旗標] [BOX LETTER]` | 合 | — |
| aos-mcp、aos-sandbox、aos-sweeper | `[旗標] 位置…` | 合 | — |
| **aos-tools**（今天剛改） | `[--file F] 子命令 [旗標] XXX`；`--file` 子命令前後都收；旗標寫在 XXX 後＝`ArgumentsBad flags go before XXX`（實跑） | **合** | `call NAME [JSON]` 屬★；`override BASE…` 多個目標，可以 |
| **aos-daemon-ctl** | `[-d D] 子命令 [旗標] NAME` | 大致合 | ① `-d` 只能在子命令前、不能在中間；② `where --stack NAME`＝目標寫成旗標的值 |
| **aos-agent** | `[-d D] [-t N] 子命令 [動作] [旗標] …` | **不合最多** | ① `-d` 只能在最前；② 目標用 `-t`、不收最後位置（11-04 裁定，見上）；③ `tools／llm` 的 `-t` 要寫在動作**前**（`tools -t ann add`），寫在中間反而 `FlagUnknown`；④ `ctl -t ann state` 不收；⑤ `tools add 名 路徑` 兩個位置、名字不是旗標；⑥ `ctl who --stack S` 要查的東西寫成旗標；⑦ `ctl rm 名字`、`ctl add XXX`、`tools get／rm 名字` 是合的 |
| aos-eca-screen | `--eca 資料夾 子命令 [--detach]` | 不合 | 目標（定義資料夾）是子命令**前**的旗標；原因是 aos-exec 把動作接在入口 argv 最後（D6），純 JSON 入口排不出 `open … 資料夾` |
| aos-grow | `[--dry-run] up [旗標] CALLER` | 大致合 | `--dry-run` 只能在子命令前 |
| aos-feedback | `[--json] add COMMAND PAIN [SUGGEST]` | 不太合 | 三個位置、目標在最前；`--json` 前後都收 |
| copy-out | `[--proto8 MODE] [範本] 目的地` | 合 | 目的地在最後；「只給一個＝目的地」正是照這條規則長出來的（Q7 見下） |

**數一數**：22 支裡完全合的 15 支；要動的 5 支——aos-agent（六處）、aos-daemon-ctl（兩處）、aos-eca-screen（一處，有技術原因）、aos-grow（一處）、aos-feedback（lv6、不急）。

## 三、重擬的 Q1

把原本的「寫在哪都行」收窄成照 P-44：**旗標收在子命令之後、位置參數之前；位置參數之後的旗標照舊不收**（今天 aos-tools 就是這樣做的）。

**Q1（重擬）　照「`aos-yyy zzz [旗標…] XXX`」把不合的補齊，補到什麼程度？**

- **A（推薦）以這個形狀為主線、舊寫法並存。**
  - 旗標寫在中間一律收：`aos-daemon-ctl stop -d stacks/root ann`、`aos-agent ctl state -d stacks/root -t ann`、`aos-agent tools add -t ann …`、`aos-agent ctl -t ann state`、`aos-grow up --dry-run …`。子命令前的寫法照留（P-44 原文允許、aos-tools 今天也是兩邊都收）。
  - 目標放最後也收：`aos-daemon-ctl where ann`；`aos-agent ctl stop／start／sleep／wake／pause／resume／state／where` 最後一個位置當名字（`aos-agent ctl stop ann`）。`-t`／`$AOS_AGENT` 照留——`say／listen／chat／tools／llm` 還是靠它（11-04 你為 `say` 的歧義定的）。
  - aos-eca-screen 不動（人不直接打；技術原因在上表），只把 P-44 那句過時的條文改對。
  - 要改：aos-agent、aos-daemon-ctl、aos-grow 三支＋共用解析 `py/aos_flags.py`；**呼叫者零破壞**；約 1～1.5 天。
  - 後果：你記得的寫法每一支都通；同一件事仍有兩種寫法並存。
- **B　嚴格照做，只留這一種。**
  - 子命令前的旗標不再收（`-d`、`--file`、`--dry-run`、`-t` 都只能在中間）；`aos-agent ctl` 的八個動作只收最後位置、不收 `-t`；`tools -t ann add` 不收；`where --stack NAME` 拿掉；P-44 的 `程式 [旗標...] 子命令` 那半句刪掉。
  - 要改：aos-agent、aos-daemon-ctl、aos-tools（今天剛改完的 `--file` 子命令前寫法要拿掉）、aos-grow、aos-eca-screen（要先解決 aos-exec 把動作接在最後的問題，可能動到範本的 `screen/_entry` 寫法）共 5 支。
  - 連帶呼叫者（grep 下限，經 helper 組參數的抓不到）：程式裡把 `-d` 寫在子命令前的至少 6 檔 28 處、`--file` 寫在子命令前的至少 6 檔 114 處、`tools --target` 寫在動作前的 4 檔 13 處——含 lv6 的 `lib/agent/agents/_entry`、`self_tools/_entry`、`thought/_entry`；文件與知識庫裡 `aos-agent -d …`／`aos-daemon-ctl -d …` 至少 17 檔 37 處、`aos-tools --file …` 11 檔 22 處；`using-aos-agent.sh`、daemon-root README 的日常那兩行也要改寫。
  - 約 3～4 天；全家只剩一種寫法。
- **C　只修最小的：`-d`、`-t` 可寫在中間，其餘不動**（`ctl stop ann` 仍報錯、`where` 仍要 `--stack`）。約半天；「目標放最後」在 aos-agent 仍不成立。

推薦 A 的理由：B 會把今天下午才改好的 aos-tools 與一批 lv6 呼叫者再翻一次，跟「先讓 aos 體系能跑、能遷移」不合；A 之後要收成 B 隨時可以（只是拿掉舊寫法）。
