# 10d 施工結果：Q1 旗標寫在哪、Q2 名字放最後、Q3 之後停止解析（11-10 晚）

## 使用者原話

- 白天：「旗標也可以寫在子命令前面，但這樣就等同於aos-yyy zzz [flags] XXX [flags] QQQ。因為zzz有個意義：aos-yyy-zzz和aos-yyy zzz相等。所以其實都可以。」
- 頂層的讀法：指令每一層（程式、子命令、動作）是一個節點，屬於某一層的旗標，寫在那一層名字之後的任何位置都算（緊接著寫，或隔了下一層的名字、位置參數再寫）。頂層再問三點：1 位置參數後面的旗標收不收（例 `aos-tools add tools/clock --name now`，今天下午才做成報錯）；2 目標放最後要不要也收（`aos-agent ctl stop ann` 與 `-t ann` 都通；say／listen／tools／llm 維持只用 -t）；3 後面要原樣交給別人的那類位置參數（`aos-exec XXX args`、`aos-daemon-ctl add XXX -- args`）之後停止解析。
- 使用者答（逐字）：「1.收。2.收。3.好。」

## 結論

六支照新規則：aos-agent、aos-daemon-ctl、aos-grow、aos-tools、aos-mailbox、aos-clock-register。舊寫法全部照樣能用。今天下午加的「flags go before XXX」報錯和它的測試都拿掉了。下面四類位置參數之後不再解析旗標：`--` 之後、`aos-daemon-ctl add XXX -- ARGS`，以及（代定）訊息與內容。

## 怎麼做的

- **一層推一層**：程式入口 `parse(…, sub="root")`；中間派發的那層（aos-agent 的 `ctl`、`tools`、`llm`、`history`、`hook`）用 `sub=True`。這兩種都解到下一層的名字為止，再把自己的旗標表推進去。動作那層的 `parse` 會認出外層的旗標，值寫回外層那份 opts；位置參數後面的旗標也收。下層有同名旗標時算下層的。沒設 `sub="root"` 的程式行為不變。
- aos-agent 的頂層 `-d` 改成用的時候才讀（`common.TOP`），因為它可能寫在最後、到動作那層才解到。
- 切 token 仍只在 `tool_io.tokenize_flags` 一處（J5 去重不破）。

## 代定（可翻）

1. **訊息與內容也算「原樣交給別人」**，從它起不解析旗標：`aos-agent say` 的 WORDS、`history summarize` 的 TEXT、`history set` 的 JSON、`aos-mailbox send` 的 WHAT、`aos-clock-register add` 的 TEXT。理由有兩條。一是沒加引號的訊息裡若有 `-t`、`-h`，會被默默吃掉或改成印說明。二是 11-04 拿掉 `say [名字] 話`，本來就是為了這種歧義（[09](09-Q1補-旗標放中間目標放最後.md) 一節）。代價是 `aos-agent say hello -t ann` 會把 `-t ann` 當成話，然後報 `TargetMissing`。另一條路是全收，訊息裡要寫 `-x` 時就加 `--`。
2. **名字放最後**只收 `ctl start／stop／sleep／wake／pause／resume／where`。`ctl state` 的位置參數是 PART，所以不收。`ctl add／rm／ls／who` 後面寫 `-t`＝`FlagUnknown`；寫在前面照舊報「does not take --target」。
3. 位置參數後面像負數（`-3`、`-.5`）或含空白（`"- 一條摘要"`）的 `-` 開頭字，照舊當位置參數，其餘不認得的＝`FlagUnknown`。
4. 位置參數後的 `--` 連它本身一起交給呼叫者，`aos-daemon-ctl add` 才分得出 `XXX -- ARGS`。這跟舊行為一樣。
5. `--help` 寫在動作的位置參數後也印說明（舊規則不印）。
6. **還沒照新規則的**：aos-mcp、aos-sandbox、aos-clock、aos-sweeper、aos-feedback、aos-eca-turn／aos-eca-screen，以及 C++ 的 `aos::parse_cli`（aos-llm、aos-post、aos-json…）。任務單沒列，沒動，P-44 續裡寫明了。
