# 04 不認得的鍵＝ArgumentsBad（tool_io 集中做）

← [self-tools](README.md)

## 使用者原話

- 頂層列的怪處：tool_io 自動 help 寫「Keys the tool does not know are ignored」，self_tools／self_llm 卻會拒絕不認得的鍵。頂層推薦「改 help 那句、報錯對小模型較有幫助」，使用者：「那就報錯」。

## 做了

- `lib/tool_io.py` 的 `arguments()` 驗型別時一起擋：物件的 schema 有宣告 `properties`（或是最上層的 `parameters`）＝封閉，多出來的鍵＝`ArgumentsBad unknown key K (known: …)`，下層會帶位置（`in check`、`in items[0]`）。
- `--help` 那句跟著 schema 走：封閉＝「A key the tool does not know is ArgumentsBad」；寫了 `additionalProperties: true` 的＝「Keys the tool does not know are passed through」。
- 新測試 `lib/tests/test_tool_io_keys.py`（7 支）；`lib/docs/01` 規則那句改掉、tool_io 檔頭改掉。

## 盤點：lib 底下各工具原本怎麼做

| 工具 | 原本 | 現在 |
|---|---|---|
| self_tools、self_llm | 自己擋（`does not take X`） | 不屬於任何 op 的鍵先被 tool_io 擋；屬於別的 op 的鍵照舊自己擋 |
| 其他走 `tool_io.arguments()` 的工具（base 全部、agents、thought、claude、codex、json_rewrite、aos/* 等） | 忽略 | 報錯 |
| memory、memory_write、memory_export、memory_sync | 忽略 | 也走 tool_io，**沒改它們的檔、測試全過**，行為一起變成報錯（歸 json-memory 隊，口徑由頂層轉告） |
| llm_fake、llm_http（kernel 叫的 endpoint 函數） | 忽略 | kernel 送 `{endpoint, request, priority}`，`priority` 沒宣告；kernel 不動，所以 schema 加 `additionalProperties: true`＝照舊收 |
| llm_forward（kernel 端，自己讀 stdin，不走 `arguments()`） | 忽略 | 照舊；schema 加 `additionalProperties: true` 讓 help 說的跟做的一致 |
| judge | 不收 stdin JSON | 不變 |

## 順手修到的

- `review_round` 把整包 `config.watch`（含只有自己用的 `baseline_cases`）交給 `watch`，以前被忽略；現在會報錯，所以 review_round 先拿掉 `baseline_cases` 再交。

## 代定（可翻）

- 最上層的 `"description"` 照舊不算不認得：wf conventions 規則 2 說 JSON 檔用 `description` 當檔頭一句，`cases/box-probe`、`cases/smoke/*` 的 `stdin.json` 都帶。下層物件裡的 `description` 照樣報錯。
- 沒宣告 `properties` 的下層物件（例 `free: {"type": "object"}`、`additionalProperties: {type: string}` 的 `envs`／`settings`）＝自由物件，什麼鍵都收。
- `parameters.properties` 是空的（例 wall_clock）＝什麼鍵都不收。
