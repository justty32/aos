# 02 自我檢查與 -d（11-10 深夜第二批）

← [clock-letters](README.md)｜原話在 [tonight-rulings 第二批](../tonight-rulings/README.md#第二批11-10-深夜頂層用選項框問)

## 使用者原話

- 時鐘登記殘留（agent 走了、它登記的格寄不到每次 warning）：「時鐘本身會每隔一定的cycle檢查自身。」
- `aos-clock-register` 收 `-d D`：選「加 -d」。

## 1 時鐘自我檢查

- `aos-clock` 寫好新數字 n 後，`n % check_every == 0` 就檢查：箱子**資料夾已經不在**的格從登記表拿掉，各一行 `aos-clock: warning: clock register: removed entry NAME (added by BY): its box BOX no longer exists`；同一輪不再寄給它。
- 代定（可翻案）：
  1. 間隔＝登記表頂層鍵 `check_every`（正整數），沒寫或壞＝**100**（根的鐘 1 秒一格≈ 1 分 40 秒一次）。只能手改登記表設；`add`／`rm` 寫回時照留。
  2. 「不存在」＝box 解出來的路徑**不是資料夾**。資料夾還在、只是暫時寄不到（不是信箱、不可寫）的不算；指示詞解不開＝判不了、不動。
  3. 剛 `add` 的格若箱子資料夾還沒建，下一次檢查就會被拿掉（add 時已經 warning「not a mailbox yet」）。
  4. 寫回前重讀一次表、只拿掉那幾格（減少蓋掉別人剛加的）；寫不回＝一行 warning、時鐘照樣退 0。
- 測試：`test_self_check_removes_gone_boxes`（資料夾不在的拿掉、只有資料夾不是信箱的留著、`check_every` 照留）。

## 2 -d

- `aos-clock-register [-c CLOCK | -d D] …`：`-d D`＝時鐘檔 `D/clock`（daemon 的 stack，跟 aos-agent ctl 的 -d 同義）。誰當準：`-c` > `-d` > `$AOS_CLOCK`；`aos-clock register -d D …` 照樣轉過去。
- 代定（可翻案）：
  1. `-c` 和 `-d` 同給＝`ArgumentsBad`（不默默挑一個）。
  2. 工具 `clock_register` 只多 `daemon`（三個動作都收），不收 `clock`：agent 指名別人的鐘用 stack 就夠。
  3. `add` 時時鐘檔還不存在＝多一行 warning「no clock file … yet」（只有根的 daemon 有在跑的鐘），照樣寫進表。
- 測試：`test_daemon_flag`（-d 指到 D/clock、同給報錯）、工具 `test_daemon`。
