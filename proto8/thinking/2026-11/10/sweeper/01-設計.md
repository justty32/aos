# 01 設計定稿（規劃員草稿照使用者 11-10 裁定修訂）

← [README](README.md)

## 1. 形狀

- `aos-sweeper`（Python，跟 aos-clock 同類）跑一輪就退；常駐靠 daemon 表上一列 loop 型 `_sweeper`，節奏交給 aos-loop（`interval_ms` 是牆鐘，等待中每秒讀 ctl，pause／stop 一秒內生效；起來第一圈立刻跑）。
- 本體 `py/aos_sweep.py`（鎖、找列、封存、保留期、purge、報告）＋`py/aos_sweep_proc.py`（行程那半）；`aos-daemon-ctl sweep` import 同一份。讀表沿用 `daemon_ctl.table.state`／`names_of`、判 daemon 活沿用 `daemon_ctl.poke.read_state`／`check_alive`、寫 ctl 沿用 `daemon_ctl.ctl.next_seq`／`put_ctl`（只 import，不改）。
- 範本列（列上無機器位置；`aos-sweeper` 靠 PATH、報告靠 `$AOS_STACK`、daemon 靠繼承的 `AOS_DAEMON`）：

```json
"_sweeper": {"exec": {"argv": ["aos-sweeper", "--retention-days", "7", "--report", {"$env": "AOS_STACK", "$path": "sweeper_report.json"}]},
             "interval_ms": 600000, "auto_restart": true, "stuck_after_ms": 600000}
```

- 範圍＝**只有 D 自己這台**：D 表上各列的 stack、D 的預設小格 `D/procs/*/`。不往子 daemon 底下走（草稿「根掃整棵樹、看到子的鎖跳過」拿掉）。子 daemon 那列本身的 stderr 在 D 的表上，照封；子 daemon 表上的零件歸子 daemon 自己的清道夫。stack＝D 本身的列跳過（那份 stderr 歸 D 的上一層）。

## 2. 封存

- 對象：表上各列 stack 裡的 `procs_stderr`（從 `procs_state.json` 頂層讀，預設 `stderr.txt`），≥ `--min-bytes`（預設 1 MiB）。
- 位置：同 stack 的 `<去副檔名>_archives/<UTC 毫秒，冒號換 ->.<副檔名>.gz`；同毫秒撞名加 `-N`。
- 做法（copytruncate；daemon 用 O_APPEND 開、改名不行）：lstat 必須一般檔、連結數 1 → `O_RDWR|O_NOFOLLOW` 開、核 dev／ino 沒換 → gzip 串流到同夾 `.<名>.tmp` → 補抄增量到 < 64 KiB（最多 5 次）→ flush＋fsync → 改正式名 → 抄最後一點 → `ftruncate(0)` → 關檔。改名前任何一步失敗＝刪暫存、原檔不截、warning。改名後截不了＝warning（下輪重封，重複無害）。上一輪寫一半留下的自己的 `.tmp` 先刪（拿著鎖，不會有人正在寫）。
- 會掉的只有「最後一次 pread 到 ftruncate」之間寫進來的幾行（微秒級）。

## 3. 保留期與 purge

- `--retention-days N`（正整數，預設 7）／`none`＝永不自動刪；`0` 不收（照字面＝立刻全刪，那是 purge；KISS「給的值照字面用」）。看**檔名的 UTC 時間**，不看 mtime（git checkout、cp 會改 mtime，兩台時鐘也可能差；封存本來不進 git，這條只是保險）。
- 範圍＝表上各列＋表外預設小格的封存夾；只認自己寫的檔名樣式。
- **`aos-daemon-ctl sweep`（人叫一次）預設不做保留期刪除**，明帶 `--retention-days` 才做（代定：常駐列可能設了 `none`，人叫一次不該偷偷照預設 7 天刪）。
- `sweep --purge`：刪這台所有自己的封存檔與暫存（不管保留期），空了把夾也拿掉；夾裡有別人的檔＝留著、warning；不封存、不碰 stderr、不碰行程。

## 4. 行程（N-17 第二個例外）

**只收一類**，條件全部成立：
1. D 的 daemon 活著（`check_alive`：state 窗 pid＋started_at_ticks＋boot_id 對得上 /proc）。不在＝一個行程都不碰、只記一句。
2. 格在 `D/procs/<名>/`，表上沒有任何一列的 stack（realpath）是它；動手前重讀一次表。
3. 格裡父寫的 loop 設定指的 state 窗：pid＋started_at_ticks 對得上 /proc、不是 zombie、**boot_id 必須有且等於本機這次開機**（比 daemon 的 live_in_cell 嚴：stack 會經 git／cp 在兩台之間搬，別台的窗 pid 可能撞到本機無關的行程）。
4. `/proc/<pid>/environ`：`AOS_STACK`＝這格、`AOS_DAEMON`＝這台（daemon 起子項時設的）。讀不到（別帳號）＝只報。
5. 活了 ≥ 60 秒（剛 fork、還沒上表的窗）。

收法：第一次＝寫它的 ctl `{"cmd": "stop", "seq": next_seq}`、記進 `D/.sweeper_pending.json`（pid、ticks、stop_at、seq）。之後的某一輪、離 stop_at ≥ `--stop-grace-s`（預設 300 秒）、還是同一支＝pidfd 核身分 → SIGTERM 它的行程群（setsid 過，群組長是它）＋底下自成一群的（inst 起的單子）→ 10 秒後還在就 SIGKILL 同一批（照 daemon `settle`）。EPERM＝報「送不出去」，不改走別路。小格與檔一律不刪、不改表。

只報：daemon 與表上各列底下的真 zombie；活著但環境對不上的；別次開機／別台寫的窗而 pid 撞到本機活行程的；太年輕的。

不碰的（驗收清單）：表上的列、別台 daemon 的小格、不在 `D/procs/` 的、殼裡手起的 aos 指令、tmux server 與其中的 claude／codex（tmux 自己 daemonize，不是子 loop 的後代）。

## 5. 鎖、報告、結束碼

- `D/.sweeper.lock` flock（點開頭＝不進 image；不寫 pid）。常駐拿不到＝warning「skipped this round」、退 0；`aos-daemon-ctl sweep` 等 `--timeout-s`（預設 30）、等不到 `SweepBusy` 退 1。`--dry-run` 時鎖檔不在不建。
- 報告：stdout 一事一行；`--report FILE` 另寫 JSON（暫存再改名）。內容：at、daemon、table、archived、expired、purged、archives 總量、bad_files、processes（checked、note、orphans、zombies）、warnings。報告有 pid 與本機路徑，**不進 git**。
- aos-sweeper：0＝做完（含發現、warning、跳過、表讀不了）；1＝ArgumentsBad／FlagUnknown／DaemonMissing／WriteFailed。不退 10。

## 6. 不進 image

`stack.gitignore` 加 `**/stderr_archives/`、`**/sweeper_report.json`；`.sweeper.lock`、`.sweeper_pending.json`、`.…gz.tmp` 已被 `**/.*` 擋。`procs_stderr` 改名的人要自己加對應的 `**/<名>_archives/`。

## 7. 邊緣表（定稿）

| 狀況 | 處理 |
|---|---|
| 零件狂寫 | 補抄增量再截；實測每秒約 400 行、連封 9 次 0 行遺失 |
| 清道夫封到一半被殺 | 只留 `.tmp`、原檔沒截；下輪先刪舊 `.tmp` 再封 |
| 清道夫 pause／stop／沒掛 | 自動的停；人下的 `sweep` 照跑 |
| daemon 被 kill -9、沒人重起 | 清道夫（setsid）照封檔，認出 daemon 不在，不碰行程 |
| stack 經 git 搬到另一台 | 封存、報告、鎖、pending 都不進 git；舊機的 state 窗 boot_id 不同＝一定不是本機生的，pid 撞到本機活行程只報 |
| 兩列指同一個 stack | realpath 去重 |
| 子 daemon 也掛了清道夫 | 各管各的表，碰不到同一個檔（父封子 daemon 那列的 stderr，子封自己零件的） |
| 表讀不了 | 這輪什麼都不做、warning |
| symlink／硬連結 stderr | 跳過＋warning |
| 磁碟滿 | 封存寫不了＝刪暫存、不截、warning |
| 被收的是子 daemon | 寫它的 ctl stop＝它收工、把自己的子項睡下 |
| 剛 ctl add、還沒上表 | 60 秒門檻＋動手前重讀表 |
| 沙箱帳號 | stderr 是 daemon 開的（daemon 帳號），截得動；訊號到別帳號 EPERM＝只報；environ 讀不到＝只報 |
| `procs_stderr` 改名 | 封存夾跟著改名；gitignore 自己加 |
| eca 零件 | 位元組原樣封（含終端控制碼）；claude 在 tmux 畫面裡的輸出不走 stderr.txt |
| 截過後 daemon 讀 reason | 檔比 err_off 短＝看整份（正確）；新內容剛好跨過舊 err_off 時最後一行可能只拿到後半截（機率低；failure.cpp 退到行首的修法列之後可加） |

## 8. 只長不消、第一版不碰的（之後可加，給使用者一眼決定）

使用者原意是「對各種東西進行清理與封存」；這輪只做 stderr（使用者點名的那一樣）＋表外子 loop。下表是其餘只長不消的東西，第一版刻意不碰，理由寫在最後一欄；要加哪一樣，說一句就能照 stderr 同一套（封存夾＋保留期＋purge）接上。

| 東西 | 是什麼、誰寫 | 長多快 | 封存／清理的風險 | 第一版為什麼不碰 |
|---|---|---|---|---|
| `live.jsonl`、`turns.jsonl` | eca 的對話流水（lib/agent/cli_session） | 看對話量；大量用 eca、長時間做事時會是最大宗之一 | 只給人看、不進 image，封存安全；但 cli_session 可能開著檔在寫（要確認是 append 還是重寫，決定能不能 copytruncate） | 寫法沒逐一確認；使用者沒點名 |
| `aos-mcp-logs.jsonl` | aos-mcp 每次工具呼叫一行 | 看工具呼叫量 | 同上 | 同上 |
| `transcripts/` | eca 的逐輪紀錄資料夾 | 每輪一份 | 整檔封存（不用截），安全 | 資料夾型，要另一套「整檔搬進封存」的做法 |
| `history.jsonl` | agent-fsm 的對話歷史 | 每步一行 | **有人讀**：醒來要接著用；截了＝agent 失憶 | 持久檔，動它要先裁「歷史怎麼截短」（摘要？只留最後 N 輪？），是方向題 |
| `observed.jsonl`、`observed/` | lib/observed 的公開觀察帳 | 每步一行 | 有人讀（上一層看下一層的窗）；截了看不到過去 | 持久檔，同上 |
| kernel `ledger.jsonl` | aos-llm-kernel 每次問腦一行（額度帳） | 每次問腦一行 | 額度計算可能讀它；附錄 4 標「條文與 gitignore 對不上」 | 要先裁它進不進 image、誰讀 |
| `*.bad-<UTC>` 留證檔 | daemon、aos-loop 壞檔時留的證據 | 只有壞檔時一份 | 是證據 | 使用者 11-09「擋掉，不自動清」；只數份數 |

| 信箱 `tmp/` 半封信 | aos-post | 極少 | maildir 慣例 36 小時以上可刪 | 很少發生；要跟 aos-post 的人對一次 |

| `counter_*.txt`、`--enable-logs` | 計數器（覆寫）、log 印到 stdout（daemon 底下是 /dev/null） | 固定大小／不落檔 | — | 不用管 |
