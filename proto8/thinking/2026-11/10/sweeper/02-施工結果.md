## 怎麼驗

**單元測試**：`python3 proto8/cmd/aos-sweeper/tests/test_sweep.py -v` → 38 個全過（約 2 秒）。涵蓋：封存門檻、gzip 內容＝截前內容、截後原檔 0、O_APPEND 從 0 接著寫沒有空洞、`procs_stderr` 改名、symlink／硬連結不碰、保留期（含 `none`）與封存總量、`parse_retention`、purge（含外人檔留著）、`--dry-run` 整棵快照不變（含鎖檔不建）、flock（拿著時 Busy、等得到時成功、bin 拿不到退 0＋warning）、daemon 不在不碰行程、表外子 loop 先寫 stop → 寬限內不動 → 寬限後 SIGTERM（忽略 TERM 的 SIGKILL）、不該收的四種（表上的、別台環境、太年輕、不在 `D/procs/`）、表讀不了、只管自己（子 daemon 底下的不碰）、同 stack 兩列只封一次、stack＝D 的列跳過、命令列錯誤碼、跨機搬來的窗（boot_id 不同、pid 撞到本機活行程＝只報；pid 不存在＝不報）。

**測試會紅**（testing「綠燈不等於有檢查」）：故意弄壞 9 處（拿掉 boot_id 核對、dry-run 建鎖檔、保留期比較、硬連結檢查、60 秒門檻、寬限期、daemon 不在的分支、ftruncate、同 stack 去重）各跑一次，前 8 處都紅；同 stack 去重原本沒測到 → 補了一個測試。

**/tmp 假腦三層**（`cp -a ~/code/playground /tmp/pg-sweep`，三台各加 `_sweeper`：`interval_ms: 5000`、`--min-bytes 20000`、`--stop-grace-s 1`；根與領班各掛一支每毫秒寫一行 stderr 的零件）：

- 三台都跑、報告寫在各自 `_sweeper` 的 stack；假腦 fsm_ann 答 `FAKE ANSWER to: what time is it? (tool said: …)`。
- 狂寫的零件：連封 9 次、把所有封存 zcat 起來接上現在的 stderr，13322 行編號連續、0 行遺失、沒有半行。
- 只管自己：`pause` 領班的 `_sweeper` 12 秒，領班零件的 stderr 長到 1.2 MB 沒人封；根的報告只封根自己的列。手動 `aos-sweeper --daemon ws/.stack`（等同 `aos-daemon-ctl sweep`）照封。
- 表外子 loop：在領班上 add 三支（`ghost_polite`：body 0.5 秒；`ghost_stuck`：body sleep 100000；`ghost_hard`：body 忽略 SIGTERM），kill -9 領班、在根重起它之前把三列從表上拿掉 → 三支在表外活著。第 0 輪「younger than 60 s」只報；60 秒後 dry-run 只印「would write stop」、沒寫任何檔；第 1 輪三支都寫 `{"cmd": "stop", "seq": 1}`、記 pending；3 秒後第 2 輪：polite 已自己停（state 窗 code 0、報「exited after the stop」），stuck 與 hard 送 SIGTERM 收掉（code 143）；第 3 輪 pending 清空。
- 不會被動到：fsm_ann、兩支狂寫零件、別台（根、總機）的列、殼裡手起的 aos-loop（stack 放在 `ws/.stack/procs/hand_in`＝報「not started by this daemon」不碰；stack 在別處的完全不看）、tmux：表外子 loop 的 body 起了一個 tmux server（自己的 socket）裡跑 sleep，那支 loop 被 SIGTERM 收掉後 tmux server 與其中的 sleep 照活；殼裡帶著 agent 環境變數手起的 tmux session 也照活。
- 293 MB 的 stderr（重複度高的 warning 行）封一次 2.5 秒、壓到 24.9 MB。

**草稿「拿不準的」**：
- 內嵌單子 `{"argv": ["aos-sweeper", …]}` 不給 `--daemon`、靠繼承的 `AOS_DAEMON`：實跑可用；`{"$env": "AOS_STACK", "$path": "sweeper_report.json"}` 指令詞也可用。
- gzip 幾百 MB：見上，2.5 秒；`stuck_after_ms: 600000` 餘裕很大。
- 沙箱帳號（`limits.user`）：這台不能 sudo、沒有第二個帳號，**沒實跑**。照讀碼：stderr.txt 是 daemon 開的（daemon 帳號擁有）截得動；送訊號到別帳號＝EPERM＝報「cannot signal: permission denied」；`/proc/<pid>/environ` 讀不到＝報「cannot read its environment」不碰。

## 代定表（可翻案）

| # | 代定 | 誰定 |
|---|---|---|
| 1 | 範本 daemon 預設都帶一列 `_sweeper`（不要的人自己刪） | 頂層 |
| 2 | 保留期「永不自動刪」寫成 `--retention-days none`；`0` 不收（照字面＝立刻全刪，那是 `sweep --purge`） | 隊長 |
| 3 | `aos-daemon-ctl sweep`（人叫一次）預設**不**做保留期刪除，明帶 `--retention-days` 才做：常駐列可能設了 `none`，人叫一次不該照預設 7 天偷刪 | 隊長 |
| 4 | 報告檔靠列上的 `--report`（範本給 `$AOS_STACK/sweeper_report.json`），不給就只印 stdout；不偷寫進繼承來的 `AOS_STACK` | 隊長 |
| 5 | 「這台生的」第 4 道核對：`/proc/<pid>/environ` 的 `AOS_STACK`＝這格、`AOS_DAEMON`＝這台（子 loop 的 state 窗沒有「上一層 daemon」欄，草稿那句不成立） | 隊長 |
