# 01 拆法與命名

> 定名（使用者「拆分的名字，建議用agents_* 當前綴」）：下文的 `children`＝**`agents_children`**、`agent_add`＝**`agents_add`**、`defs` 加 `new`＝**`agents_defs`**（另開一支，只有 new 與 check；原本 `lib/aos/defs` 那支只讀的不動，理由見 [02](02-施工單.md)）。下面保留提案時的寫法。

← [agents-split](README.md)

## 一張表

| 塊 | 工具（主推名） | 一句話 | 包哪支指令 |
|---|---|---|---|
| 1a | `children` | 我生的子 agent：生、殺、停起、問話、出生後調它的東西；工具自己記帳、算配額 | `aos-agent ctl …`、`say`、`listen`，調東西轉給 self_* 一家 |
| 1b | `agent_add` | 把一隻 agent 掛上 daemon，掛完不管 | `aos-agent ctl add` |
| 2a | `defs`（現有那支加一個動作） | 定義：複製範本成新定義、檢查合不合格（原本的列、找重複、找引用照舊） | 沒有對應指令（複製＝`cp -r`＋相對路徑換算） |
| 2b | `self_tools`、`self_llm`、`self_history`、`self_hook` | 改自己（別隊在做，這裡不動） | `aos-agent tools／llm／history／hook` |

舊的 `agents` 整支拿掉，不留舊名。第三塊（agent 之間交流）不做。

## 名字備選

| 塊 | 主推 | 備選 | 理由 |
|---|---|---|---|
| 1a | `children` | `my_agents`、`child` | 「children」一看就知道只管自己生的；記帳檔本來就叫 `children.json`、錯誤代號本來就是 `ChildUnknown`、`ChildSlotMissing`。`my_agents` 也清楚，但跟 `agent_add` 掛的容易混 |
| 1b | `agent_add` | `ctl_add`、`attach` | 跟指令 `aos-agent ctl add` 對得上、主題放前面。`ctl_add` 更貼指令但腦看不出是掛 agent；`attach` 短，但指令裡沒這個字 |
| 2a | `defs` 加 `new` | 另開一支 `def_new`（`defs` 維持只讀） | 「定義」的事都在同一支，腦少記一個名字；`defs` 現在沒登記在範本裡，這次一起登記。備選的好處是 `defs` 仍保證不寫檔 |

## 每支的動作（每個動作一行例子）

### `children`（1a）

| 動作 | 例子 | 對應 |
|---|---|---|
| add | `{"op": "add", "name": "kid", "def": "defs/helper", "ws": "kid"}` | `ctl add -n kid -w kid defs/helper`；先對帳、滿了＝`ChildSlotMissing`、不寄信；成功記帳 |
| rm | `{"op": "rm", "name": "kid"}`（要連 stack 一起刪：加 `"purge": true`） | `ctl rm [--purge -y] kid` |
| stop／start | `{"op": "stop", "name": "kid"}` | `ctl stop -t kid`（做完這輪再停）／`ctl start` |
| sleep／wake | `{"op": "sleep", "name": "kid"}` | `ctl sleep`（馬上停）／`ctl wake` |
| pause／resume | `{"op": "pause", "name": "kid"}` | `ctl pause`（原地按住）／`ctl resume` |
| state | `{"op": "state", "name": "kid"}` | `ctl state -t kid` |
| ls | `{"op": "ls"}` | 我生的那幾列（`ctl ls --json` 篩過）＋ `max_children` |
| say | `{"op": "say", "name": "kid", "text": "hello"}` | `say -t kid`，馬上回 |
| listen | `{"op": "listen", "name": "kid", "timeout_s": 600}`（看最近幾則：`"last": 3`） | `listen -t kid --timeout-s 600`／`--last 3` |
| ask | `{"op": "ask", "name": "kid", "text": "what time is it?"}` | say 接 listen（唯一不是一對一的，留著省小模型一步） |
| tools | `{"op": "tools", "name": "kid", "args": {"op": "add", "path": "tools/math"}}` | `args` 跟 `self_tools` 收的一模一樣，目標換成 kid |
| llm | `{"op": "llm", "name": "kid", "args": {"op": "set", "settings": {"model": "fake"}}}` | `args` 同 `self_llm` |
| history | `{"op": "history", "name": "kid", "args": {"op": "ls"}}` | `args` 同 `self_history` |
| hook | `{"op": "hook", "name": "kid", "args": {…}}` | `args` 同 `self_hook`（那支 push 後自動接上；還沒有＝`ToolMissing`） |

名字不是我生的＝`ChildUnknown`；記過但已不在表上＝`ChildMissing`。add 的其餘參數跟 `ctl add` 一對一（`def_json`、`ws_json`、`stack`、`limits`、`envs`、`auto_restart`、`timeout_s`、`on_queued`）。不認得的鍵＝`ArgumentsBad`。

### `agent_add`（1b）

| 動作 | 例子 | 對應 |
|---|---|---|
| （只有一個，不用 op） | `{"def": "defs/helper", "name": "worker", "ws": "work"}` | `ctl add -n worker -w work defs/helper`；參數同 `children` 的 add；不記帳、不算配額，之後 `children` 碰不到它 |

### `defs`（2a）

| 動作 | 例子 | 說明 |
|---|---|---|
| new（新） | `{"op": "new", "from": {"$env": "AOS_HOME", "$path": "/templates/agent-fsm"}, "path": "defs/helper"}` | 整份複製；`path` 放哪都行（看權限），已經在＝`DefExists`；之後改內容用一般的檔案工具 |
| check | `{"op": "check", "root": "defs/helper"}` | 合不合格（root 可以是一整棵定義樹，也可以就是一份定義） |
| ls／dup／refs | `{"op": "ls", "root": "defs"}` | 照舊（只讀） |

## 1a 出生後怎麼調子 agent：選「`children` 裡四個轉手動作」

比過三種：

| 做法 | 腦要記的 | 問題 |
|---|---|---|
| **A（選這個）** `children` 加 `tools`／`llm`／`history`／`hook` 四個動作，`args` 原封不動就是 self_* 那支收的東西 | 不多一支工具；`args` 的寫法跟改自己時一樣，學一次 | 多一層 `args` |
| B self_* 各多收一個 `child` | 不多工具 | 名字叫 self 卻能改別人；大權散到四支別隊的工具裡，每支都要去讀帳 |
| C 另開 `child_tools`、`child_llm`… 一家 | 多四支工具、四份說明進腦的 context | 參數表重抄四份，self_* 一改要跟著改 |

選 A 的理由：使用者說「具備生殺大權的才能在出生後調整」——權力就放在記帳的那一支；小模型不用多認工具。做法是 `children` 驗過帳之後，用「子的身分」去跑旁邊的 `self_tools`（它本來就靠 `$AOS_STACK` 認自己是誰，換成子的 stack 就變成改子的），所以 self_* 一行都不用改，那邊加了動作這邊自動有。真腦（gemma-4-e4b）試叫，若它寫不好多一層 `args` 就改 tooldef 的例子，再不行退回 C。

## 代定清單（可翻案）

1. `children` 的 rm 預設留 stack、`purge: true` 才刪（跟人用的 `ctl rm` 一致；舊的一律 purge）。
2. `children` 的 add 不再順手收 `llm`／`tools`／`tools_rm`：出生後用 `tools`／`llm` 動作調（子剛掛上沒題目、不會先跑）。
3. `ask` 留著（say＋listen 合一）；另補 `listen`。
4. `children` 的 ls 只列我生的（舊的還附整張 daemon 表）。
5. 配額設定檔從 `agents.json` 改名 `children.json`（定義裡一份、stack 裡一份只放改過的鍵），預設 4 不變。
6. 舊 `new` 的 `files`／`llm`／`tools`／`tools_rm`／`reason`／`review` 都拿掉：`defs new` 只複製；「只能寫在工作區」的限制拿掉。
7. 血統：寫的那一半隨 `agents` 拿掉；`defs ls` 遇到定義裡已有的 `lineage` 照樣印（只讀、不接新的）。
8. 公開子帳（`children` 在 ask／listen／rm 時把子的觀測帳抄一份到自己 stack）留著，review_round 靠它追樹。
9. 三支都登記進 `agent-fsm`、`eca-claude` 範本（取代 `agents`）。
10. 「細的」動作（設 system prompt、設腦、加減工具寫進定義）與 `ctl where` 不做，列為之後可加。
