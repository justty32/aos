## 怪處清單

1. **（結構性，要你決定）小模型寫不出 `$` 鍵**：gemma 只能走「字串路徑」；但範本、math 這些在 `$AOS_HOME` 底下，腦不知道那個值。可選：工具收不帶 `$` 的寫法（例如 `"template": "agent-fsm"` 短名、或字串 `"$AOS_HOME/templates/agent-fsm"` 由工具展開）、或 system／知識庫告訴腦 AOS_HOME 的值、或接受小模型就是要人給絕對路徑。self_tools 的 `path_json`、self_hook 的 `path_json` 同一個問題。
2. **4096 context 裝不下全套工具**（見上表）；要嘛小模型的範本只登記少數工具，要嘛 tooldef 再瘦。
3. **還在教 CLI 旗標的句子**（隊員補點 3；腦會在結果或 stderr 尾巴看到）：
   - 成功句（agents_children／agents_ctl 原樣轉下層 stdout）：stop＝`… aos-agent ctl start --target k2 to carry on`、sleep＝`aos-agent ctl wake --target …`、pause＝`aos-agent ctl resume --target …`、rm 不 purge＝`kept (delete it with aos-agent ctl rm --purge, or by hand)`。最後這句對腦是死路：rm 完它已不在帳上也不在表上，兩支工具都刪不到那份 stack。
   - 錯誤句（`cmd/aos-agent/aos_agent`）：`InstanceMissing … the stack may still be there: ao…`（common.py:279）、`DaemonMissing … Start it first: aos-exec --stack …`（common.py:178）、`WsMissing … aos-agent ctl add / aos-daemon-ctl add --ws`（ctl/where.py:37）、`StackMissing no --stack and no AOS_STACK`（ctl/who.py:30）。
   - 經 tools 轉手的 self_tools：`ToolExists … add --replace to replace it`（gemma 照念「I should use `--replace`」）。
   - 撞名 InstanceExists 已換成工具寫法，但 stderr 尾巴仍附下層原句（act 格的 C-52 例外，非這兩支能管）；後半句「remove that agent first with {"op":"rm"}」對 agents_children 而言，不是自己生的那隻 rm 會 ChildUnknown。
4. **agent_def new 照 cp -r 連 `tests/` 一起抄**（隊員代定照舊、記一筆）：從 agent-fsm 抄出的定義 200 KB，其中 `tests/` 76 KB（test_batch3、test_cells、test_cooldown、test_hooks、test_integration、test_own_tools、test_selfheal 七支）；`__pycache__` 有濾掉。另：工作樹的 `templates/agent-fsm/` 本身現在有個 `__pycache__/`（有人跑測試留下的），agent_def 會濾、`cp -r` 不會。
5. **rm 不 purge 之後同名再 add＝接回舊 stack**（歷史接著；listen last 3 看得到前一輪兩題），算 ctl 的行為，但腦不知道會這樣。
6. **gemma 會謊報成功**（Copy 那題兩支都失敗還說做完了）——真腦常態，記著。
7. **假腦劇本裡的指示詞會被 kernel 先解開**：kernel.json 劇本寫 `def_json: {"$env": …}`，到工具手上已是字串路徑（history 裡看得到），所以 fake-demo-spawn 其實沒驗到「腦交指示詞物件」那條路；haiku 那題有驗到（物件原樣送達、agent_def 解得開）。
8. 子還在排隊（ChildQueued）、判官 queue 路線：本輪 kid4 走判官 `queue: true` 排 30 秒後才回 `SlotMissing`（不是 AddRejected），mama 那一拍卡了 30 秒；帳上沒留 kid4。
9. `self_history rm` 把子的歷史砍到只剩一則 user，ls 說那則是「step in progress」——子下一拍可能會去回它（self_history 的語意，不是這邊的）。
10. 媽轉手給子時 `AOS_WS` 仍是媽的：tools／hook 的相對路徑從媽的工作區算，存進子的覆蓋層時換成相對檔案的路徑（hook 實測 `../../../../hooks/logger`），子照樣找得到。和 tooldef「relative paths start at your workspace」一致，記一筆。

## 試驗場（~/code/playground）要刷新時注意什麼

（只寫、沒執行；那邊的 daemon 是使用者的，我沒碰。）照 [self-tools/02 的刷新段](../self-tools/02-試驗場怎麼玩三個工具.md)（最後一段） 做，另外：

- **舊 `agents` 登記要換**：試驗場定義裡的 `tools.json` 若還有 `"agents": …`（指到已刪的 `lib/agent/agents`）＝那支工具會 PathMissing。整份重抄範本最省事；只改登記的話換成 `agents_children`、`agents_ctl`、`agent_def` 三列（照範本 `{"$env": "AOS_HOME", "$path": "/lib/agent/…"}` 寫法）。stack 裡 `procs/<名>/tools.json`（aos-agent tools add 寫的覆蓋層）若點名過 `agents`，也要 `tools reset` 或刪掉那列。
- **`agents.json` 改名 `children.json`**：定義裡的 `agents.json` 不會再被讀到，配額回到預設 4；要改配額就寫 `children.json`（定義那份，或 `procs/<名>/children.json` 只放改過的鍵）。
- **舊帳不會被讀到**：舊 stack 的 `procs/<媽>/tools/agents/children.json`（誰是我生的）新工具不看——新工具的帳在 `tools/agents_children/children.json`。舊的子（例 `kid_fsm_ann`）對新工具是「不是我生的」（ChildUnknown），要嘛 `aos-agent ctl rm` 掉，要嘛整份 stack 重建；它們之前用的 `observed/` 子帳也在舊格裡。
- 範本工具清單一直在長（現在 15 支），若試驗場的小腦端點真的開 4096 context，要先決定只登記哪幾支（見怪處 2）。
- llm 腦設定鍵是 `model`（不是 `endpoint`），self-tools/02 已寫。

## 要你決定

1. 小模型寫不出 `$` 鍵：給工具一條不用 `$` 鍵就能指到範本／lib 的路嗎？（短名、`$AOS_HOME` 字串展開、或告訴腦 AOS_HOME 的值）
2. rm 不 purge 後留下的 stack，腦沒辦法再清——要不要給 agents_children 一條路（或 rm 的成功句不要提 `aos-agent ctl rm --purge`）？
3. 下層 ctl 的成功句／錯誤句裡的 CLI 寫法（怪處 3）要不要一起在 agents_cmd 的 TOOL_WORDS 換掉。

## 驗收後補的（隊長）

- 決定 1：`agent_def new` 加 `template`（內建範本短名）。直接打 LM Studio 的 gemma-4-e4b、帶三支新 tooldef（prompt 約 2380 tokens）：「Copy the agent-fsm template to defs/helper.」→ `{"op":"new","path":"defs/helper","template":"agent-fsm"}`；「Start a child agent named kid from the agent-fsm template.」→ 先叫 `agent_def new`（`defs/kid`）；「…from the eca-claude template and check it.」→ `template: "eca-claude"`。三題第一步都對。這三題只看第一個 tool call，沒在 daemon 上跑完整回合。
- 決定 2、3：rm 不 purge 的成功句、stop／sleep／pause 的成功句、`--replace` 那句，在 `agents_cmd.py` 換成工具參數的寫法（rm 那句改成「同名再 add 一次、再 rm 帶 purge」）。換字只有既有單元測試重跑過，沒有專屬測試、也沒在場子上重跑。
