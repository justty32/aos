# 收工與開工：新指令 `aos-image`

## 名字（你定；推薦放第一）

| 候選 | 說明 |
|---|---|
| **`aos-image freeze`／`aos-image thaw`**（推薦） | 新指令。image 是你 11-05 自己的用詞（lisp image），文件一直寫「凍住」；它跨好幾台 daemon 又碰 git，不屬於任何一支既有指令 |
| `aos-image save`／`load` | 更白話，但 `load` 聽不出「會起根」 |
| `aos-agent image …` | 少一支指令；但 aos-agent 管的是「一隻 agent」，這裡管的是整棵樹 |
| `aos-daemon-ctl freeze` | 不推薦：daemon-ctl 一次只對一台 daemon、也不該認得 git |

放 `proto8/cmd/aos-image/bin/aos-image`（Python），本體拆在 `proto8/py/aos_image_*.py`；`install.sh` 連進 PATH。輸出英文、錯誤一行 `aos-image: error: 代號 原因` 退 1、`--help`、旗標在位置參數前，全照既有慣例。

image 根怎麼找：`--image DIR` ＞ 從目前資料夾往上找到有 `image.json` 的那層。

| 現成的 | 用在哪 |
|---|---|
| `aos-daemon-ctl shutdown`（今天新加） | 停根 |
| `aos-daemon-ctl ping`、`ls --json` | 開工後逐台確認、收工後核表 |
| `copy-out --relink ROOT`（今天新加，待 commit） | 開工重指錨點 |
| `py/aos_sweep_proc.py` 認行程的那段（看 `/proc/*/environ` 的 `AOS_STACK`、核 pid＋起始時間） | 收工確認沒殘留行程 |
| `cli_session.close`（關 eca 畫面的 tmux） | 收工關畫面 |
| [04-搬家/02](../../../../cmd/aos-agent/docs/04-搬家/02-image保存與邊界.md) 的五行 git 食譜 | 收工打包、開工取回，原樣包進去 |
| `extras/image-move-check/check.py` | 不被 `aos-image` 呼叫；當施工驗收的底（它已會起三層、睡、搬、醒） |
| `aos-daemon-ctl sweep` | 不用叫：根停了清道夫那列跟著停；它寫的東西都不進 git |

## `aos-image freeze`（收工）

```
aos-image [--image DIR] freeze [--wait-s N] [--now] [--no-push] [--rescue] [--dry-run]
```

| 步 | 做什麼 | 失敗怎麼辦 |
|---|---|---|
| 1 找 image、讀 `image.json`、`local/machine.json` | 驗 git repo、有 `origin` | `ImageMissing`／`LocalMissing`，什麼都沒動 |
| 2 看標記 | `git fetch origin main`；遠端的 `image_info.json` 應該寫「這台在跑」 | 不是＝`OwnerMismatch`（別台接手過了），什麼都沒動；提示改用 `--rescue`（見 [04](04-防呆.md)）。抓不到遠端＝warning 照做，到推的那步再擋 |
| 3 等閒下來 | 掃每個 stack：eca 小格的 `lock` 被拿著或有 `busy.txt`（claude 正在答）、`stage.txt` 是 `act`（工具正在跑）、有 `think/pending.txt`（在等腦）、kernel 的 `requests/cur/` 有東西。全空且連兩次都空才算。每 2 秒看一次，最多等 `--wait-s`（預設 900），期間每 30 秒印一行還在等誰 | 到期還在忙＝`StillBusy` 列出是誰，**什麼都沒動、樹照跑**。`--now`＝不等這步直接往下（正在答的那輪 eca 白做、那批信照裁定 5 不重答；等腦的不受影響，信與回信都在樹裡、醒來接著收） |
| 4 關 eca 畫面 | 每個活著的 `tty.sock` 關掉（不關的話裡面的 claude 會在打包後繼續寫 ws） | 關不掉＝warning，交給步 6 |
| 5 停根 | `aos-daemon-ctl -d <根 stack> shutdown --timeout-s 60`。根沒在跑＝跳過 | 60 秒沒退＝`ShutdownFailed`，樹在半停狀態；再跑一次 freeze 會從這步接 |
| 6 確認沒殘留 | 等到沒有任何行程的 `AOS_STACK`／`AOS_DAEMON` 在這個 image 底下（最多 30 秒；子項收到 TERM 後 10 秒會被 KILL） | 還有＝`ProcsLeft` 列出 pid 與指令。不自動殺（N-17：只有 daemon 與清道夫碰 pid）；人處理後重跑 |
| 7 核表 | 每台 `procs_state.json` 沒有 `running`／`stopping` 的列 | 有＝`TableBad`。`stopped` 的列印出名字與原因當提醒（到另一台它還是 stopped） |
| 8 補規則 | 每個 daemon stack 的 `.gitignore` 跟現行 `stack.gitignore` 範本不同就換新；image 根的 `.gitignore` 缺行就補；`.gitattributes` 不在就放 | 寫不了＝`WriteFailed` |
| 9 寫標記 | `image_info.json`：代數加 1、`state: frozen`、這台的名字、時間、aos repo 的 commit、claude／codex 的版本號 | — |
| 10 打包 | `sync`；單檔超過 50 MB 印 warning、超過 95 MB＝`FileTooBig`（GitHub 單檔上限 100 MB）列出檔名、不 commit；然後照食譜：`git rm -r --cached`、`git add -A`、沒有父的 commit、指給 `main` | `FileTooBig` 時標記改回去；把那個檔加進 ws 的 `.gitignore` 或搬走再跑 |
| 11 推 | 先把標籤 `prev` 挪到遠端現在的 `main`、推標籤；再 `git push --force-with-lease=main:<步 2 看到的那個 commit> origin main`；成功後清舊版（`reflog expire`＋`gc --prune=now`） | 斷網、被拒＝`PushFailed`。**image 已經凍好、存在本機**，樹沒在跑；重跑 freeze 只會做這一步。被拒且遠端換人了＝`OwnerMismatch` |
| 12 印結果 | 一行 `frozen: generation N, <檔數> files, <大小>, pushed to origin/main` | — |

- **冪等**：每步先看「是不是已經這樣了」。根已停就不停、已凍沒推就只推、已推完再跑＝印 `already frozen and pushed (generation N)` 退 0。
- **`--dry-run`**：做步 1～3 的讀取與步 6～8、10 的檢查，印每步「會做什麼」（一行一步，開頭 `would`），不停任何東西、不寫任何檔、不 commit、不推。
- **`--no-push`**：做到步 10 為止。**`--rescue`**：步 2 不擋、步 9 不改標記、步 11 改成推到標籤 `rescue-<機器>-<UTC 時間>`，不碰 `main`。
- 退出碼：0 成功；1 任何錯（看代號）；130 被 Ctrl-C（不留半寫的檔：寫檔都先寫暫存再改名）。
- 錯誤代號：`ArgumentsBad`、`FlagUnknown`、`ImageMissing`、`LocalMissing`、`OwnerMismatch`、`StillBusy`、`ShutdownFailed`、`ProcsLeft`、`TableBad`、`WriteFailed`、`FileTooBig`、`GitFailed`（git 自己的話原樣透出）、`PushFailed`。

## `aos-image thaw`（開工）

```
aos-image [--image DIR] thaw [--takeover] [--discard-local] [--offline] [--no-start] [--foreground] [--dry-run]
```

| 步 | 做什麼 | 失敗怎麼辦 |
|---|---|---|
| 1 找 image、讀設定 | 同 freeze；`local/` 不在＝`LocalMissing`（提示 `cp -r local.example local`）；image 在 `/mnt/` 底下＝`ImageBad`（Windows 檔案系統會弄壞執行權限與換行） | 什麼都沒動 |
| 2 已經在跑？ | 根 daemon 活著（state 窗的 pid＋起始時間＋boot_id 對得上） | 是＝印 `already running on this machine` 接步 10 的 ping，退 0 |
| 3 拉 | `git fetch origin main`，照 [04 的判斷表](04-防呆.md#開工時的判斷表)決定：照拉、不拉直接起、或拒絕 | 拒絕＝`OwnerElsewhere`／`LocalNewer`／`LocalUnsaved`，什麼都沒動。斷網＝`FetchFailed`；`--offline`＝不拉、不推標記，用本機現有的（印一行明講沒有標記保護） |
| 4 換成遠端那份 | 先看工作樹：收工之後又被手改過（有沒 commit 的改動）＝`LocalUnsaved`，要先 `freeze` 補一代或加 `--discard-local`。乾淨才把本機現在的 `main` 記成本機標籤 `local-prev`（多一次後悔的機會），再 `git reset --hard origin/main` | `GitFailed` |
| 5 重指錨點 | `copy-out --relink <image 根>` | `AnchorBad`（那個位置有別的東西）原樣透出 |
| 6 清請求 | 刪每個 stack 的 `think/request.json`（只刪這個，11-07 裁定 20-3A） | — |
| 7 檢查這台 | ① `local/endpoints.json`、`keys.json` 是合法 JSON；② 端點單子要的金鑰名在 `keys.json` 或環境裡有；③ PATH 上有 `aos-daemon`、`aos-exec`、`aos-post`、`aos-llm`、`tmux`，有 eca 的話有 `claude`／`codex`、`aos-mcp`；④ `kb` 解得到一個資料夾；⑤ aos repo 的 commit 與 CLI 版本跟 `image_info.json` 記的比；⑥ 各定義與各 stack 的 `llm.json` 用到的端點代號，這台的端點表裡有沒有 | ①②③缺＝`LocalBad`／`KeyMissing`／`ToolMissing`，不起根。④⑤⑥不一樣或缺＝**只印 warning**（核心不依賴知識庫；程式版本差多少要不要緊只有人知道；缺代號只影響用到它的那隻） |
| 8 搶標記 | `image_info.json` 寫 `state: running`、這台名字、時間（代數不變）；沒有父的 commit、`push --force-with-lease`。**先搶到才起根** | 被拒＝`OwnerElsewhere`（剛好有人搶先），不起根 |
| 9 起根 | 設環境（`local/env`、`AOS_LLM_KERNEL`；拿掉殼裡的 `AOS_KERNEL`、`AOS_DAEMON`、`AOS_CLOCK`），在名叫 `aos-<image 資料夾名>` 的 tmux 裡跑 `[launch.json 的 wrap…] aos-exec --stack <根 stack> <根定義>`。`--foreground`＝不用 tmux、就在這個視窗前景跑；`--no-start`＝到步 8 為止 | tmux 那個名字已在＝`SessionExists` |
| 10 確認 | 逐台 `aos-daemon-ctl -d <stack> ping --timeout-s 30`（哪幾台從各表往下找）；印每台的表；`stopped` 的列連原因印出來 | 有一台沒回＝`PingFailed` 列出是哪台（根留著跑，讓人看） |
| 11 印結果 | `thawed: generation N on <機器>, <幾台> daemons up, <幾隻> agents; attach: tmux attach -t aos-img` | — |

- **eca 的對話不在這一步處理**：每隻 eca 下次收到信時自己判斷（[05](05-eca換台.md)）。開工只負責不把另一台的執行期殘留帶進來——那些本來就不進 git（F17、F21、F24～F30）。
- **冪等**：已在跑就只 ping；拉過了、錨點對了、標記已是這台，各步都是「已經這樣就跳過」。
- **`--dry-run`**：做步 1～3、7 的讀取與檢查，印會拉哪個 commit、會重指幾條錨點、會刪幾個請求、起根的完整指令；不寫任何東西。
- 錯誤代號（多的）：`ImageBad`、`OwnerElsewhere`、`LocalNewer`、`LocalUnsaved`、`FetchFailed`、`LocalBad`、`KeyMissing`、`ToolMissing`、`SessionExists`、`PingFailed`。

## `aos-image status`

不改任何東西，隨時可跑：

```
image ~/aos/img  generation 12  running on office since 2026-11-10T09:02Z  (origin/main: same)
daemon root      up    4 rows
daemon llm       up    kernel queue 0
daemon foreman   up    5 rows
NAME    PHASE    BUSY   QUEUE  RESTARTS  COOLDOWN         LAST ERROR
ann     running  think  0      0         -                -
bob     running  -      3      4         until 10:41 (4)  CliFailed claude exited 1: usage limit reached
```

`RESTARTS`、`COOLDOWN`、`LAST ERROR` 從 [06](06-長跑自動重起.md) 的 `cooldown.json` 讀；`QUEUE` 是 `queue/new/` 裡還沒收的信數。`-j` 印 JSON。

## `aos-image init DIR`

第一次建樹用：建 [01](01-整體圖像.md#image-根的佈局) 的佈局、三份定義（根帶 `_clock` 與 `_sweeper`、總機、領班；總機與領班在根表上 `auto_restart: true`）、`image.json`、`local.example/`、兩份 gitignore、`.gitattributes`、`git init -b main`、`gc.auto 0`。指回 repo 的路徑一律經 `.aos-proto8`。`DIR` 已存在＝`DestExists`。不設 `origin`、不 commit、不推——印出接下來三行要人自己打的指令。

agent 另外用 `copy-out <範本> agents/<名>` 抄、`aos-agent ctl add --auto-restart` 掛。

## 中途存檔

沒有另一支指令。`aos-image freeze && aos-image thaw`＝存一份、推上去、原地再起（午休、下班前各做一次，斷電時最多丟半天）。
