# 衝突與要裁的

## 要你裁的（3 題；沒回答的照推薦做）

<a id="題-1金鑰"></a>
### 題 1：金鑰

**白話**：現在金鑰是在起根的那個視窗裡 export 的，整棵樹每個行程都拿得到。有 bash 類工具的 agent 只要跑一次 `env`，輸出就進它的 `history.jsonl`，收工時推上 GitHub。你裁了不掃描，所以這條沒有東西擋。（另外三處——ws 裡的檔、定義的 `.env`、工具登記的 `env` 值——只能靠「不要寫在那裡」，見 [01 末段](01-整體圖像.md#不靠掃描也會把金鑰推上去的地方)。）

| 選項 | 做法 | 後果 |
|---|---|---|
| **A（推薦）金鑰只給端點那一支行程** | 金鑰寫在 `local/keys.json`（不進 git），端點單子用 `$ref` 讀進自己的環境（[02](02-機器專屬設定.md#金鑰)，/tmp 實測可行）。起根的視窗不 export | 其他行程的環境裡沒有金鑰，`env` 印不出來。agent 若刻意去讀 `../local/keys.json` 還是讀得到——擋的是「不小心」，不是「故意」。不用改程式，只改定義的寫法 |
| B 照舊在視窗 export | `local/env` 寫金鑰，thaw 起根前設好 | 最省事；`env` 一跑就進 history。靠 image repo 是私有的 |
| C 兩個都不要，回頭做掃描 | — | 翻你剛裁的 8 |

不管選哪個：image repo 一定要私有；一頁說明寫「金鑰只放 `local/`」。

<a id="題-2額度用完那幾個小時的信"></a>
### 題 2：額度用完那幾個小時的信

**白話**：你裁了「失敗就掉那一封、自動重起」。但 eca 是一次把信箱裡所有信一起交出去的（11-03「一批幾封無上限」），所以照字面做，額度用完那五個小時裡**進來幾封掉幾封**。

| 選項 | 做法 | 後果 |
|---|---|---|
| **A（推薦）失敗後冷卻；冷卻到了只拿一封去試** | [06](06-長跑自動重起.md#補的東西失敗後冷卻python兩個地方不動-daemon)：冷卻中不收信（信留在信箱）；30 秒起加倍到 30 分鐘；試成功才恢復整批收 | 五小時最壞掉十封左右，其餘留著等恢復。「一批無上限」只在剛失敗過的那一次暫時變成一封 |
| B 照字面 | 只接 `--auto-restart`，不加冷卻 | 最少改動；額度窗期間寄給 eca 的信全掉。fsm 那邊暫時性失敗會三次就判停 |
| C 試探失敗的那一封放回信箱 | A 再加：冷卻後的試探若失敗，不算收 | 一封都不掉；但等於在這個情況翻掉 11-03「交出去就算收了」與你剛裁的 5 |

### 題 3：新指令叫什麼

`aos-image freeze／thaw／status／init`（推薦）、或 `save／load`、或掛在 `aos-agent image` 底下。理由在 [03 開頭](03-收工與開工.md#名字你定推薦放第一)。這題只影響名字，不回答就用推薦的開工。

## 跟既有條文與裁定的衝突（逐條；除上面 3 題外都已代定）

| # | 哪條 | 衝突在哪 | 怎麼調和 |
|---|---|---|---|
| 1 | 11-03「交出去就算收了」（[eca 20](../../../2026-10/30/eca/20-11-03-交出去就收.md)）↔ 換台必失敗 | 照舊流程換台第一封必掉 | 不翻：把「這段對話在不在這台」的判斷移到交出去**之前**（[05](05-eca換台.md)）。交出去之後的失敗照舊掉 |
| 2 | 11-03「一批幾封無上限」↔ 冷卻後只拿一封 | 剛失敗過的那一次不是整批 | 題 2 |
| 3 | 11-06「image 只留最新一份」↔ 自動留 `prev` 標籤 | 遠端多留一份 | 代定：留。11-06 本來就寫「要留的版本先打 tag」；這裡自動做，不留歷史鏈 |
| 4 | 11-07 裁定 19A「image＝stack＋ws，定義是外部原始碼」↔ 定義放進 image repo | 定義跟 image 同一個 repo | 代定：同一個 repo、分開的資料夾。概念上定義仍是「原始碼」；但你會改它（persona、工具），兩台得一樣，而搬家文件的佈局本來就把定義放 image 根。缺點：定義也沒有歷史（只有 `prev`） |
| 5 | 11-07 裁定 20-3A「新機只清 `think/request.json`」 | 無衝突 | thaw 只刪這個；新加的 `cooldown.json`、`.session_home` 設計成「殘留也無害」，不用清 |
| 6 | N-17「只有 daemon 碰 pid」（清道夫是第二個例外） | freeze 要確認沒有殘留行程 | 只**看** `/proc`、不送任何訊號，不算碰；有殘留就報錯交給人 |
| 7 | 04-搬家/02「換一台 `--resume` 找不到就從頭開」 | 程式沒有這條路 | 文件改成新流程（[10 文件表](10-施工步驟.md#要更新的文件)） |
| 8 | 04-搬家/01 ③「搬完先改 `kernel.json` 的 url、model」、⑥「這台的值由 root 殼 export」 | 每天換台不能每次手改、手 export | 改成 `local/`＋`$ref`；⑥ 的精神（定義不寫這台的值）不變，只是從「殼」換成「不進 git 的檔」 |
| 9 | 04-搬家/03 的佈局（image 裡抄一份 `lib/`、`py/`，設 `PYTHONPATH`） | 有錨點後不需要 | 佈局名字沿用、拿掉那兩個資料夾與 `PYTHONPATH` |
| 10 | P-20「出錯停下等人」↔ 冷卻 | 冷卻看起來像「自己吞掉錯誤」 | 不衝突：失敗那次照樣退 1；沒開 `--auto-restart` 的照樣停著等人。冷卻只管「重起之後多久才再試」 |
| 11 | knowledge-write 代定 7「要歷史就把庫放 git」、agent-knowledge 的範本預設（庫在 repo 裡） | 新原則：aos 不假設知識庫是什麼 | 一致：那句本來就是「依託現成、aos 不做」。只把 `brain.py` 在庫讀不到時整隻停這一處解掉（[07](07-知識庫接點.md)） |
| 12 | lib 契約「工具自己那行錯誤、退 1」↔ `brain.py --memory` 改成 warning | 把一個錯降成提醒 | 代定：降。理由是你的「不要與其耦合」，而且 eca 那條路（aos-mcp）本來就是 warning，兩型行為現在不一致 |
| 13 | 「本地與遠端只有一個 main」 | image repo 用標籤（`prev`、`rescue-*`、本機 `local-prev`） | 那條是 aos 程式 repo 的規矩；image repo 也只有 `main` 一個分支，標籤不是分支 |
| 14 | 鐵律 2「未經確認不 push」 | `aos-image freeze` 會推 | 推的是 image repo、而且是你自己下的指令＝當場授權；`--no-push` 可以不推。aos 程式 repo 的 push 照舊要你點頭 |

| 16 | 10-30「停著時改 history 再繼續：之後再改」 | 這次順手做掉了一半 | 刪 `session.txt`＝用現在的 history 重開。沒做「自動偵測 history 被改過」 |

## 代定表（可翻案）

| 哪裡 | 代定 |
|---|---|
| repo 數量 | 一棵樹一個 image repo；定義放 image repo 裡 |
| 這台的值 | 放 image 根的 `local/`（不是家目錄）；端點用 `$ref` 陣列疊、不用 `$env` |
| 兩台的模型 | 用同一個代號、各自的 `local/endpoints.json` 指各自的模型 |
| 知識庫掛法 | image 根的 `kb` 掛點＋`_memory.json`；`AOS_MEMORY` 當備案 |
| 標記 | `image_info.json`，代數只在 freeze 加 1；程式與 CLI 版本不同只提醒不擋 |
| 沒收工就換台 | 預設拒絕；`--takeover` 明講才接；輸的一邊進 `rescue-*` 標籤 |
| 遠端多留一份 | 標籤 `prev`；本機 `local-prev` |
| 收工時還在忙 | 等 15 分鐘（`--wait-s`）、到期不動任何東西；`--now` 才硬收 |
| 收工關畫面 | 直接關 eca 的 tmux 畫面 |
| 開工起根 | 預設在 tmux 裡起、名字 `aos-<資料夾名>`；先搶到標記才起 |
| 開工檢查 | 缺金鑰、缺指令＝不起根；知識庫不在、版本不同、缺端點代號＝只提醒 |
| 大檔 | 50 MB 提醒、95 MB 不 commit |
| eca 判斷方式 | 記號檔 `.session_home`（比對話 id、工作區路徑、帳號資料夾），不讀 CLI 的檔 |
| 開場白 | 上限 48000 bytes（畫面開著時 8000）；第一則一定帶、其餘從新往舊；單則 6000 截中間；不帶工具輸出 |
| `session.txt` | 新對話交出去就寫；resume 失敗且這台找不到那段對話就刪 |
| 冷卻 | 30 秒起加倍、封頂 30 分鐘；牆上時鐘；檔名 `cooldown.json`、不進 git |
| `--auto-restart` | 布林旗標；兩支 add 都加；不提供「事後打開」，用 rm 再 add |
| `brain.py` 讀不到知識庫 | 降成 warning、照樣問腦 |
| W5 | 範本放好、不預先登記；W6 只先做最小一段 |
| `memory_sync` | 做成 lib 工具、可邊用邊補；衝突時留這台的、刪改相撞交給人 |
| `wait_warned.txt` | 不進 git |
