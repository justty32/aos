## 1～5：claude／codex 找不到對話時怎麼反應

| 步 | 指令 | 要看到 | 💬 |
|---|---|---|---|
| 1 | `cd /tmp && echo hi \| claude -p --resume 00000000-0000-4000-8000-000000000000; echo "exit=$?"` | 失敗、exit 不是 0（A02） | 0～1 句 |
| 2 | `cd /tmp && U=$(uuidgen) && echo "say ok" \| claude -p --session-id $U && ls ~/.claude/projects/*/$U.jsonl` | 列出一個檔（A03） | 1 句 |
| 3 | `mkdir -p /tmp/other && cd /tmp/other && echo "what did I just say" \| claude -p --resume $U; echo "exit=$?"` | 失敗（換資料夾就接不回） | 0～1 句 |
| 4 | `cd /tmp && CLAUDE_CONFIG_DIR=~/.claude-alt claude -p --resume $U <<< hi; echo "exit=$?"` | 失敗（換帳號資料夾就接不回）；沒有 alt 帳號就跳過 | 0～1 句 |
| 5 | `echo hi \| codex exec resume 00000000-0000-4000-8000-000000000000 -; echo "exit=$?"` | 失敗、沒有開出新 thread（A05）；沒用 codex 就跳過 | 0～1 句 |

第 2、3 步要在同一個視窗（用到 `$U`）。

## 6：eca 換台整條（在 /tmp 一個小專案）💬 約 3 句

```sh
mkdir -p /tmp/rv/something && cd /tmp/rv/something
copy-out daemon-root defs && copy-out eca-claude defs/bob
aos-exec --stack stacks/root defs        # 這個視窗留著；下面在另一個視窗打
```

```sh
cd /tmp/rv/something
aos-agent -d stacks/root ctl add --auto-restart -w . defs/bob
aos-agent -d stacks/root say -t bob "The password is kiwi. Reply ok."
aos-agent -d stacks/root listen -t bob
cat stacks/root/procs/bob/claude/session.txt
aos-daemon-ctl -d stacks/root shutdown
```

假裝換台：搬到新位置、拿掉這台的記號檔與舊對話，再起。

```sh
cp -a /tmp/rv /tmp/rv_b.2 && cd /tmp/rv_b.2/something
rm stacks/root/procs/bob/claude/.session_home     # 這台的記號檔不進 git，另一台本來就沒有
rm -rf ~/.claude/projects/-tmp-rv-something        # 另一台也沒有這段對話
aos-exec --stack stacks/root defs                  # 在第一個視窗打
```

```sh
cd /tmp/rv_b.2/something
aos-agent -d stacks/root say -t bob "What is the password?"
aos-agent -d stacks/root listen -t bob
cat stacks/root/procs/bob/claude/session.txt
aos-agent -d stacks/root listen -t bob --last 2
aos-daemon-ctl -d stacks/root shutdown
```

再看 claude 把這段對話存在哪：`ls -d ~/.claude/projects/*rv*`。

**要看到**：第二次答得出 kiwi（它是從 aos 記的紀錄知道的）；兩次印的 `session.txt` 不一樣；`--last 2` 兩題都在；`ls` 列出 `-tmp-rv-b-2-something`（底線和點都換成 `-`，A15）。名字不一樣的話照貼回來：那表示每輪都會開新對話。答不出來或卡住，貼 `stacks/root/procs/bob/stderr.txt` 的最後幾行。

**7（順手）**：第二次 say 時多問一句 `Do you have a memory tool? Use it once.`，看它有沒有去用 memory（aos-mcp 的說明有沒有被讀）。

## 9：兩台真的來回一次（公司↔家機）💬 約 3 句

用一個小專案、一個**私有** GitHub repo（你自己建）。stack 與定義都放在專案裡（放專案外、兩台相對位置不同會起不來，見 [13 B01](13-施工結果/03-不同之處與留給明天.md#b01-專案外的-stack定義換了相對位置)）。llms 也放進這個專案當子資料夾，就只要一個 repo。

**公司**：

```sh
cp -r $AOS_HOME/templates/start-api ~/code/rv    # ~/code/rv 要先不存在；樹裡有根、llms/def、agents/ann、env.sh
cd ~/code/rv && git init -b main
cp -r $AOS_HOME/templates/eca-claude agents/bob
mkdir -p .stack llms/stacks/llm
cp $AOS_HOME/lib/aos/apps/agent/stack.gitignore .stack/.gitignore
cp $AOS_HOME/lib/aos/apps/agent/stack.gitignore llms/stacks/llm/.gitignore
```

開兩個視窗（每個都先 `cd ~/code/rv && source env.sh`；`AOS_HOME` 已經設過，`AOS_LLM_KERNEL` 由樹裡的 `root/.env` 帶）：視窗一 `(cd llms && aos-exec --stack stacks/llm def)`，視窗二 `aos-exec root`。第三個視窗：

```sh
cd ~/code/rv && source env.sh
aos-agent -d .stack ctl add --auto-restart -w . agents/ann
aos-agent -d .stack ctl add --auto-restart -w . agents/bob
aos-agent -d .stack say -t ann "hello from office" && aos-agent -d .stack listen -t ann
aos-agent -d .stack say -t bob "The password is kiwi. Reply ok." && aos-agent -d .stack listen -t bob
aos-daemon-ctl -d .stack shutdown                # 兩句分開打，不要用 && 串
aos-daemon-ctl -d llms/stacks/llm shutdown
aos-agent -d .stack say -t ann "left in the mailbox"     # 睡著也收信
git add -A && git commit -m "rv day 1" && git remote add origin <你的私有 repo> && git push -u origin main
```

**家機**（先 `git -C ~/repo/aos pull`、`cd ~/repo/aos/proto8 && python3 install.py`；`AOS_HOME` 家機也要設過一次，指家機 `proto8` 的位置）：

```sh
git clone <你的私有 repo> ~/code/rv
```

同樣開兩個視窗（每個都先 `cd ~/code/rv && source env.sh`，`source` 會清掉殼裡別棵樹的 `AOS_*`）：視窗一起 llms、視窗二起根，指令跟公司一樣。第三個視窗：

```sh
cd ~/code/rv && source env.sh
aos-agent -d .stack listen -t ann --last 2                # 要有 left in the mailbox 的回答
aos-agent -d .stack say -t bob "What is the password?" && aos-agent -d .stack listen -t bob
aos-daemon-ctl -d .stack shutdown                         # 兩句分開打
aos-daemon-ctl -d llms/stacks/llm shutdown
git status --short                                         # 貼回來
git add -A && git commit -m "rv day 2" && git push
```

再回公司 `git pull`、起兩個視窗、`say -t ann "back at office"` 一次。兩台各打一次 `cat /etc/machine-id`，貼回來（應該不一樣，A16）。

**要看到**：家機不用跑任何「換台」指令就接著答；bob 答得出 kiwi；`git status` 只有 stack 裡的狀態檔（history、表、信箱這類），沒有 `stderr.txt`、`cooldown.json`、`.session_home`；回公司也照樣答。貼回來：家機的 `git status --short`、任何 `error:` 行、bob 的兩次回答。試完要刪就刪 `~/code/rv` 和那個 GitHub repo。

**第 6 步看到的**（全部對得上「要看到」那欄）：

- 樹 A 回 `ok`（listen 2.5 秒），`session.txt`＝`e0ddb713-…`，小格裡有 `.session_home`（帶 machine）。
- 樹 B 起來時 `ann` 自己醒（表上 `ws` 已是新路徑）。第二問答 `The password is **kiwi**, as you told me earlier in this conversation.`（listen 9 秒）。看 claude 的對話檔，第一則是 aos 的開場白 `[aos] session: this conversation continues in a new session (it moved to another machine or folder, or was restarted)…`＝kiwi 是從 aos 記的紀錄知道的。
- `session.txt` 換成 `447b71c2-…`（跟樹 A 不同），新的 `.session_home` 寫了新路徑；`--last 2` 兩題都在；stderr.txt 是空的。
- `ls -d ~/.claude/projects/*rv*` 列出 `-home-lorkhan--aos-scratch-t7-home-1118-rv-b-2-something`（底線、點都換成 `-`，**A15 過**）。第三問 `session.txt` 沒變、對話檔多一則 user＝這一輪是接回同一段，不是又開新的（`stored_here` 的資料夾名猜對了）。
- 限制：兩棵樹在同一台、同一個帳號資料夾，machine-id 一樣（`52cdbd89…`），換台是靠「工作區路徑不同」認出來的；machine-id 那道比對沒被考到（A16 仍等第 9 步）。

**第 7 步看到的**：eca-claude 範本沒有 aos 的 memory 工具；claude 用的是 **Claude Code 自己的自動記憶**——讀寫 `~/.claude/projects/<專案夾>/memory/MEMORY.md` 與一個 `memory-tool-check.md`（它自己說「我有檔案型的記憶，不是專用工具」，還刻意沒把密碼寫進去）。沒去叫 `mcp__aos__*`。

**坑**：

1. **claude 2.1.327 換資料夾也接得回對話**（第 3 步）：A03「換 cwd 就 resume 不到」在這版不成立（換帳號資料夾仍接不回）。aos 的 `stored_here`（`py/aos/agentlib/cli_cell.py`）要求工作區路徑也一樣才當「這台的」，所以比 claude 嚴：工作區換了一律開新對話、附開場白。後果只是保守（多一段開場白、記得的是大意），不會卡住、不會接錯；第 6 步正是靠這點認出「換台」。沒改程式。
2. **自動記憶留在樹外**（第 7 步）：claude 自己記的東西寫在 `~/.claude/projects/<依工作區路徑命名>/memory/`，不在 stack 也不在工作區，換台、換路徑都帶不走（樹 A 與樹 B 各一份），aos 也看不到。要不要在 eca-claude 範本關掉 Claude Code 的自動記憶、或改指到樹裡，等使用者裁（關掉用哪個設定鍵這次沒查證）。
3. 本頁的「開始前」（`~/repo/aos-tools`、cmake、`install.sh`、`AOS_PROTO8`）、`copy-out`、`stacks/root`、`cmd/aos-agent/stack.gitignore` 都是 11-10 的寫法，第 8、9 步照抄會失敗；公司機跑之前要先照現況改（本次沒改那兩步的內文）。
4. 跑法上的：zsh 不會把 `$R` 這種變數拆成多個字，包裝指令要寫進 bash 腳本；家機 tmux 開新伺服器會復原使用者存的 session，私人 tmux 一律 `-f /dev/null`。

收尾：兩棵樹都 `aos-daemon-ctl -d .stack shutdown` 停了，tmux 伺服器跟著沒了，沒有留下 claude 行程；暫存夾全留著沒刪。
