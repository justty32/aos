# 真機驗證：你親手試（約 30～40 分鐘）

**為什麼要做**：今天全部用假腦、假 claude 驗過；真 claude／codex 的幾個行為沒人試過（[assumptions.json](assumptions.json) 的 A01～A09、A15、A16）。下面每步都可以照抄，看「要看到」那欄，把輸出貼回來就好。

**燒額度**：只有標 💬 的步驟會叫真 claude／codex，每次一兩句話；其他用假腦，不花錢。

## 1～5：claude／codex 找不到對話時怎麼反應

| 步 | 指令 | 要看到 | 💬 |
|---|---|---|---|
| 1 | `cd /tmp && echo hi \| claude -p --resume 00000000-0000-4000-8000-000000000000; echo "exit=$?"` | 失敗、exit 不是 0（A02） | 0～1 句 |
| 2 | `cd /tmp && U=$(uuidgen) && echo "say ok" \| claude -p --session-id $U && ls ~/.claude/projects/*/$U.jsonl` | 列出一個檔（A03） | 1 句 |
| 3 | `mkdir -p /tmp/other && cd /tmp/other && echo "what did I just say" \| claude -p --resume $U; echo "exit=$?"` | 失敗（換資料夾就接不回） | 0～1 句 |
| 4 | `cd /tmp && CLAUDE_CONFIG_DIR=~/.claude-alt claude -p --resume $U <<< hi; echo "exit=$?"` | 失敗（換帳號資料夾就接不回）；沒有 alt 帳號就跳過 | 0～1 句 |
| 5 | `echo hi \| codex exec resume 00000000-0000-4000-8000-000000000000 -; echo "exit=$?"` | 失敗、沒有開出新 thread（A05）；沒用 codex 就跳過 | 0～1 句 |

第 2、3 步要在同一個視窗（用到 `$U`）。

## 6：eca 換台整條（在 /tmp 一個小專案）💬 約 3 句

```sh
mkdir -p /tmp/rv/something && cd /tmp/rv/something
copy-out daemon-root defs && copy-out eca-claude defs/bob
aos-exec --stack stacks/root defs        # 這個視窗留著；下面在另一個視窗打
```

```sh
cd /tmp/rv/something
aos-agent -d stacks/root ctl add --auto-restart -w . defs/bob
aos-agent -d stacks/root say -t bob "The password is kiwi. Reply ok."
aos-agent -d stacks/root listen -t bob
cat stacks/root/procs/bob/claude/session.txt
aos-daemon-ctl -d stacks/root shutdown
```

假裝換台：搬到新位置、拿掉這台的記號檔與舊對話，再起。

```sh
cp -a /tmp/rv /tmp/rv_b.2 && cd /tmp/rv_b.2/something
rm stacks/root/procs/bob/claude/.session_home     # 這台的記號檔不進 git，另一台本來就沒有
rm -rf ~/.claude/projects/-tmp-rv-something        # 另一台也沒有這段對話
aos-exec --stack stacks/root defs                  # 在第一個視窗打
```

```sh
cd /tmp/rv_b.2/something
aos-agent -d stacks/root say -t bob "What is the password?"
aos-agent -d stacks/root listen -t bob
cat stacks/root/procs/bob/claude/session.txt
aos-agent -d stacks/root listen -t bob --last 2
aos-daemon-ctl -d stacks/root shutdown
```

再看 claude 把這段對話存在哪：`ls -d ~/.claude/projects/*rv*`。

**要看到**：第二次答得出 kiwi（它是從 aos 記的紀錄知道的）；兩次印的 `session.txt` 不一樣；`--last 2` 兩題都在；`ls` 列出 `-tmp-rv-b-2-something`（底線和點都換成 `-`，A15）。名字不一樣的話照貼回來：那表示每輪都會開新對話。答不出來或卡住，貼 `stacks/root/procs/bob/stderr.txt` 的最後幾行。

**7（順手）**：第二次 say 時多問一句 `Do you have a memory tool? Use it once.`，看它有沒有去用 memory（aos-mcp 的說明有沒有被讀）。

## 8：在 /mnt/c 起一棵試一次（假腦，不花錢）

```sh
W=/mnt/c/Users/<你的 Windows 帳號>/AppData/Local/Temp/rv && mkdir -p $W/llms $W/something
cd $W/llms && copy-out kernel/llm-kernel def
aos-exec --stack stacks/kernel def           # 視窗一
```

```sh
W=/mnt/c/Users/<你的 Windows 帳號>/AppData/Local/Temp/rv
cd $W/something && copy-out daemon-root defs && copy-out agent-fsm defs/ann
export AOS_LLM_KERNEL=$W/llms/stacks/kernel
aos-exec --stack stacks/root defs            # 視窗二
```

```sh
W=/mnt/c/Users/<你的 Windows 帳號>/AppData/Local/Temp/rv && cd $W/something
aos-agent -d stacks/root ctl add --auto-restart -w . defs/ann
time aos-agent -d stacks/root say -t ann "hello"
time aos-agent -d stacks/root listen -t ann
aos-daemon-ctl -d stacks/root ls
aos-daemon-ctl -d stacks/root shutdown && aos-daemon-ctl -d $W/llms/stacks/kernel shutdown
```

**要看到**：`FAKE ANSWER to: hello …`；`ls` 每列都是 `running`；兩個視窗沒有 `error:` 行。把兩個 `time` 的數字貼回來（11-10 量到 fsm 一題約 8 秒）。試完 `rm -rf $W`。

## 9：兩台真的來回一次（公司↔家機）💬 約 3 句

用一個小專案、一個**私有** GitHub repo（你自己建）。stack 與定義都放在專案裡（放專案外、兩台相對位置不同會起不來，見 [13 B01](13-施工結果/03-不同之處與留給明天.md#b01-專案外的-stack定義換了相對位置)）。llms 也放進這個專案當子資料夾，就只要一個 repo。

**公司**：

```sh
mkdir -p ~/code/rv && cd ~/code/rv && git init -b main
mkdir llms && (cd llms && copy-out kernel/llm-kernel def)
copy-out daemon-root defs && copy-out agent-fsm defs/ann && copy-out eca-claude defs/bob
mkdir -p stacks llms/stacks
cp $AOS_PROTO8/cmd/aos-agent/stack.gitignore stacks/.gitignore
cp $AOS_PROTO8/cmd/aos-agent/stack.gitignore llms/stacks/.gitignore
```

開兩個視窗（每個都先 `cd ~/code/rv`、設好「開始前」的 export 與 `export AOS_LLM_KERNEL=$HOME/code/rv/llms/stacks/kernel`）：視窗一 `(cd llms && aos-exec --stack stacks/kernel def)`，視窗二 `aos-exec --stack stacks/root defs`。第三個視窗：

```sh
cd ~/code/rv
aos-agent -d stacks/root ctl add --auto-restart -w . defs/ann
aos-agent -d stacks/root ctl add --auto-restart -w . defs/bob
aos-agent -d stacks/root say -t ann "hello from office" && aos-agent -d stacks/root listen -t ann
aos-agent -d stacks/root say -t bob "The password is kiwi. Reply ok." && aos-agent -d stacks/root listen -t bob
aos-daemon-ctl -d stacks/root shutdown && aos-daemon-ctl -d llms/stacks/kernel shutdown
aos-agent -d stacks/root say -t ann "left in the mailbox"     # 睡著也收信
git add -A && git commit -m "rv day 1" && git remote add origin <你的私有 repo> && git push -u origin main
```

**家機**（先照「開始前」更新 aos、重建、install.sh）：

```sh
git clone <你的私有 repo> ~/code/rv
```

同樣開兩個視窗（每個都先 `cd ~/code/rv`、`export AOS_PROTO8=<家機 proto8 的位置>`、`export AOS_LLM_KERNEL=$HOME/code/rv/llms/stacks/kernel`、`unset AOS_CLOCK AOS_DAEMON AOS_STACK`）：視窗一起 llms、視窗二起根，指令跟公司一樣。第三個視窗：

```sh
cd ~/code/rv
aos-agent -d stacks/root listen -t ann --last 2           # 要有 left in the mailbox 的回答
aos-agent -d stacks/root say -t bob "What is the password?" && aos-agent -d stacks/root listen -t bob
aos-daemon-ctl -d stacks/root shutdown && aos-daemon-ctl -d llms/stacks/kernel shutdown
git status --short                                         # 貼回來
git add -A && git commit -m "rv day 2" && git push
```

再回公司 `git pull`、起兩個視窗、`say -t ann "back at office"` 一次。兩台各打一次 `cat /etc/machine-id`，貼回來（應該不一樣，A16）。

**要看到**：家機不用跑任何「換台」指令就接著答；bob 答得出 kiwi；`git status` 只有 stack 裡的狀態檔（history、表、信箱這類），沒有 `stderr.txt`、`cooldown.json`、`.session_home`；回公司也照樣答。貼回來：家機的 `git status --short`、任何 `error:` 行、bob 的兩次回答。試完要刪就刪 `~/code/rv` 和那個 GitHub repo。
