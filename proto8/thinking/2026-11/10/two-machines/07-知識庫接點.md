# 知識庫：只設計接點

原則（你 11-10 的三句，見 [README](README.md#使用者原文11-10逐字)）分兩層：

- **核心層不耦合**：daemon、loop、agent 範本的骨架、`aos-image`、清道夫、搬家流程，只把知識庫當「一個路徑上的資料夾」。不假設它是 git、不假設本地檔案系統、不替它 commit／pull／push、不看它的 git 狀態。
- **工具層可以假設**：`memory`、`memory_write`、新的 `memory_sync` 是可選的工具，可以假設 git、鎖、rename；**假設寫在工具自己的說明與錯誤裡**，前提不成立就清楚報錯。agent 裝不裝是它自己的事。

## 現行工具怎麼找知識庫（memory_fs.py（`../../../../lib/agent/memory_fs.py`） `memory_root`）

1. 工具資料夾（定義裡的 `tools/memory/`）有 `_memory.json` → 用它的 `base`（相對路徑從那個資料夾算）。
2. 沒有才看環境變數 `AOS_MEMORY`（相對路徑從 `$AOS_DAEMON` 算）。
3. 都沒有＝`MemoryMissing`。找到之後解開捷徑、確認是資料夾。

三支工具（`memory`、`memory_write`、`memory_export`）共用這一段；兩種指法都是現成的。

## 推薦的掛法：image 根的 `kb` 掛點

```text
<image 根>/kb  ->  這台的知識庫（捷徑、掛載點、或真的資料夾都行；不進 git）
<image 根>/agents/ann/tools/memory/_memory.json        {"base": "../../../../kb"}
<image 根>/agents/ann/tools/memory_write/_memory.json  -> ../memory/_memory.json（捷徑，兩支指同一個庫）
```

- 進 git 的只有 `"../../../../kb"` 這個字串，兩台一字不差；`kb` 後面是什麼 aos 不知道也不問。
- 跟 `.aos-proto8` 同一招，只是指的東西不同、而且**不由 `copy-out --relink` 管**（那是指 repo 的；`kb` 由人放一次）。
- 多庫照 11-05 的做法：`kb` 指到一個裡面放幾條捷徑的資料夾（例如一條指出廠的 `knowledge/aos`、一條指自己的筆記）。那個資料夾怎麼組也是知識庫那邊的事。
- 範本抄出來時 `_memory.json` 指的是出廠的 `knowledge/aos`（經錨點）。要用自己的庫就改這一行；`aos-image init` 建的樣板直接寫 `kb`。

**備案 `AOS_MEMORY`**：拿掉 `_memory.json`、在 `local/env` 寫 `AOS_MEMORY=/這台/的/路徑`。git 裡完全沒有知識庫的字樣，最乾淨；但它靠環境變數一路傳到每個工具行程（含 claude 起的 aos-mcp），中間任何一層清環境就斷，而且範本預設帶著 `_memory.json`（它優先）要記得刪。所以列備案。

## 那個路徑不在、掛不上、唯讀時

| 情況 | 現在的表現 | 設計 |
|---|---|---|
| 開工時 `kb` 不在或不是資料夾 | 沒人檢查 | `aos-image thaw` 印一行 warning：`kb does not resolve to a folder; agents that use memory will get MemoryMissing`。**不擋開工** |
| 跑著時讀不到（掛載斷了） | `memory`：`MemoryMissing`／`ReadFailed`，腦看到錯誤訊息，agent 照跑——好 | 不改 |
| 同上，**fsm 範本的 think 格** | `brain.py --memory` 每輪要先讀知識庫的根放進 system prompt，讀不到＝`MemoryFailed` 退 1＝**整隻 agent 停**（開了自動重起就是三次判停） | **要解（核心層）**：改成跟 aos-mcp 一樣——印一行 warning、system prompt 裡放一句 `Knowledge base is not available right now: <原因>`，照樣問腦。狀態不壞：`stage.txt`、history 都沒動 |
| 同上，eca | aos-mcp `--memory` 讀不到＝warning、不給說明、連線照起——好 | 不改 |
| 讀很慢（網路掛載） | `brain.py` 等 30 秒逾時＝同上停掉 | 同一個修法蓋到 |
| 唯讀 | `memory_write`：`WriteFailed … permission denied (this folder is read-only for you…)`——清楚 | 不改 |
| 檔案系統不支援 hard link／rename | `memory_write add`：`WriteFailed [Errno 95] Operation not supported`——看不懂 | 工具層：錯誤補一句前提 `(memory_write needs a file system with hard links and atomic rename)`，說明檔寫明 |

## 耦合清單

已抽到 [kb_coupling.json](kb_coupling.json)（24 列）。欄位：`id`、`where`（哪個檔／哪段）、`coupling`（耦合在哪）、`layer`（核心層／工具層／範本預設／文件）、`breaks`（知識庫是任意資料夾、可能不是本地檔案系統時會不會壞）、`fix`（解耦或講明前提要動什麼）、`before_start`（開工前必做嗎）。

統計：核心層 3 列（要解 1：`brain.py`；本來就沒耦合、列出來確認的 2：清道夫、stack 的 gitignore）、範本預設 3 列、工具層 15 列（都可以留，其中 4 列要把前提寫明或把錯誤講清楚）、文件 3 列。開工前必做 6 列。

工具層不為了 9P 重寫：`memory_write` 的鎖（`mkdir` 掛牌＋牆上時鐘 10 秒租約）、暫存檔＋rename、hard link，都留著，只在 `--help`、`_tooldef.json` 的說明與錯誤訊息寫明「需要支援 mkdir 原子性、rename、hard link 的檔案系統；多台同時寫同一個掛載時各台時鐘要對準」。

## W5／W6：我的判斷

| 項 | 判斷 | 理由 |
|---|---|---|
| **W5 範本接 `memory_write`**（fsm 與 eca 兩份都接） | **開工前必做** | 不接的話 agent 根本寫不了知識庫——而你要拿它做知識庫。照原則「不預先登記」：範本放好 `tools/memory_write/`，要寫的那隻自己 `aos-agent tools add memory_write tools/memory_write` |
| eca 那邊多一件 | 同上 | claude 的 `--tools Read,Glob,Grep` 不用動（`memory_write` 走 aos-mcp，不是 claude 的內建工具）；登記進去就能用 |
| **W6 教 agent 寫**（`knowledge/aos` 加 memory 一節） | **開工前做最小的一段**：何時寫、`LockFailed` 等一下再試一次、一個節點 ≤ 2 KB、寫前先 `find`；其餘邊用邊補 | 小模型撞鎖不重試就白寫。但這是「出廠庫的內容」，你用的若是自己的庫，就把這段放你自己庫的根 |
| 鎖等待 3 秒→10 秒 | 邊用邊補（一個數字） | 多隻寫同一層才會撞 |
| W7～W10、`edit` 加版本檢查 | 不做 | 已裁（裁定 7、「等大了」） |
| 坑-76（大寫、`.`、`_` 開頭的檔看不見卻沒提示） | 邊用邊補 | 你手放檔進知識庫時會中；`ls` 尾巴印一行「N files ignored」 |

## `memory_sync`（工具層、可選、不是開工前必做）

給「知識庫剛好是 git 資料夾」的人用的一支 lib 工具（`lib/agent/memory_sync/`），人或 agent 都能叫；`aos-image` 不叫它，文件只提一句「你的知識庫是 git 的話，收工前後可以跑這支」。

- 找庫的方式跟 `memory` 一樣。前提：那個資料夾是 git 工作樹、有 `origin`。不成立＝`NotGitRepo`／`RemoteMissing`。
- `{"op": "status"}`：有幾個檔沒 commit、領先落後幾個 commit。
- `{"op": "sync"}`：① `git add -A`＋commit（訊息帶機器名與時間）；② `git pull --no-rebase -X ours`——沒衝突的兩邊都留，同一段都改了的**留這台的**（這台是後同步的＝後寫的贏，裁定 7）；③ `git push`。
- 解不掉的衝突（一邊刪檔一邊改檔）＝`git merge --abort`、回 `SyncConflict` 列出檔名，交給人。不硬解。
- 會不會提交到寫一半的檔：`memory_write` 寫檔是暫存檔再改名，檔案層級沒有半寫；葉長成資料夾那種兩步動作被夾在中間時，會多提交一個過渡狀態，下次 sync 自己修正。前提是庫的 `.gitignore` 有 `.lock/`、`.tmp.*`、`.new.*`、`.rm.*`、`.lock.releasing.*`——工具起來先檢查，缺了回 `IgnoreMissing` 並印出該加的五行（不替人改）。
- 節奏不由 aos 定：手動、收工前後各一次、或你自己在某台 daemon 掛一列每 10 分鐘跑。

不做這支的話，你在知識庫資料夾裡手打 `git add -A && git commit -m x && git pull && git push` 效果一樣，所以排在「可邊用邊補」。
