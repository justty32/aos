# 防呆：一個跟著 git 走的小標記

兩台之間沒有真的鎖，唯一共用的東西是 GitHub 上那個 repo。所以標記就放在 repo 裡，**開工先搶、收工才還**。

## 標記檔 `image_info.json`（image 根、進 git、`aos-image` 寫）

```json
{"generation": 12, "state": "running", "machine": "office", "at": "2026-11-10T01:02:11Z",
 "aos_commit": "d47748408", "cli": {"claude": "2.1.30", "codex": "0.61.0"}}
```

- `generation`：第幾代。**只有 freeze 加 1**。兩邊比大小就知道誰新。
- `state`：`running`（有人開著）或 `frozen`（收好了）。`machine`：`local/machine.json` 的名字。
- `aos_commit`、`cli`：這一份是哪版程式、哪版 CLI 凍的；開工時比對、不一樣只提醒（順手補上大修清單的「image 不記版本」）。

推的時候一律 `--force-with-lease` 指定「我以為遠端是哪個 commit」，所以兩台同時搶，只會有一台成功。

## 開工時的判斷表

本機＝這台 clone 裡的 `image_info.json`；遠端＝剛 fetch 到的那份。

| 遠端寫的 | 本機的狀況 | thaw 怎麼做 |
|---|---|---|
| `frozen`，代數比本機大或相等 | 本機是 `frozen` | 正常：換成遠端那份、搶標記、起 |
| `frozen`，代數比本機**小** | 本機 `frozen`（上次這台收工沒推成） | `LocalNewer`：拒絕。提示先 `aos-image freeze`（只會補推）再 thaw |
| `running`，是**這台** | — | 這台上次沒收工就斷了（關機、WSL 被關）。本機就是最新的：**不拉**、直接起，印一行 warning |
| `running`，是**別台** | 本機 `frozen` | `OwnerElsewhere`：拒絕。確定那台不會再推了才用 `--takeover`（從遠端那份起，那台沒收工的部分不在裡面） |
| `frozen`，是別台、代數比本機大 | 本機還是 `running`（這台沒收工、另一台接手又收工了） | `LocalUnsaved`：拒絕。這台沒存的東西一拉就沒了；先 `aos-image freeze --rescue` 存成標籤，再 `thaw --discard-local` |
| 沒有這個檔（第一次） | — | 當作 `frozen`、第 0 代 |

收工時只看一件事：遠端是不是還寫著「這台在跑」。不是＝`OwnerMismatch`，不推 `main`。

## 四種誤操作各會怎樣

| 誤操作 | 會怎樣 | 丟什麼 |
|---|---|---|
| **A 沒收工就在 B 開** | B 的 thaw 看到遠端寫「A 在跑」→ 拒絕。你硬用 `--takeover`：B 從 A 上一次推的那份起。之後 A 再 freeze 會被擋（`OwnerMismatch`），用 `--rescue` 存成 `rescue-A-…` 標籤 | 不會無聲丟。A 那段與 B 那段變成兩份、合不起來，要人挑一份當主線；另一份在標籤裡可以翻出 ws 的檔 |
| **兩台同時開著** | 只可能來自 `--takeover` 或 `--offline`。兩邊各跑各的；先 freeze 的贏得 `main`，後 freeze 的被擋、進 rescue 標籤 | 同上。**知識庫不在 image 裡，兩邊寫進知識庫的不受這件事影響**（它自己怎麼同步是它的事） |
| **收工後忘了推**（斷網、`--no-push`） | freeze 自己會推，推不成退 1、訊息明講沒推成。人走了：B 看到遠端還寫「A 在跑」→ 拒絕。回到 A 再跑一次 freeze 只補推 | 不丟，只是 B 當下接不了；或 `--takeover` 接上一代 |
| **拉到比本機舊的** | 代數比一下就擋（`LocalNewer`）。真的換掉時，本機舊的那份先記成本機標籤 `local-prev` | 不丟（多一次後悔機會，下次 thaw 才被覆蓋） |

## 擋得住與擋不住

**擋得住**：忘了收工就換台、忘了推、拉到舊的、兩台同時推、同一台重複開（`DaemonExists` 本來就有）。

**擋不住**：
- `--offline`、`--takeover`、`--discard-local` 是你明講「我知道」，之後照上表收場。
- 不經 `aos-image`、手動 `git push --force` 或手動 `aos-exec` 起根。
- A 還開著、B 用 `--takeover` 接手之後，A **不會自己知道**——它不連 GitHub。它繼續跑到你去 freeze 才被擋。
- 知識庫的互蓋（裁定 7、9：那是知識庫那邊的事）。

## 只留最新一份＋強推：怎麼把損失壓到最小

不改「只留最新一份」的前提下，加三道便宜的保險，全都只用標籤、不開分支：

1. **遠端留「上一份」**：每次 freeze 推之前，把標籤 `prev` 挪到遠端當時的 `main`。一次壞的收工（例如 agent 把 ws 刪壞了才凍）還能退一代。代價：遠端大約兩份 image 的大小。（11-06 裁定本來就允許「要留的版本先打 tag」；這裡是自動留一份，[代定可翻案](09-衝突與要裁的.md#代定表可翻案)。）
2. **本機留「被換掉的那份」**：thaw 換掉本機之前記成本機標籤 `local-prev`，不推。
3. **輸的那邊進 `rescue-<機器>-<時間>` 標籤**：`freeze --rescue`。這些標籤不會自動刪，確定不要了自己 `git push origin :refs/tags/<名>`。

加上 [03 的中途存檔](03-收工與開工.md#中途存檔)：斷電、WSL 被關這種「來不及收工」的情況，丟的是最後一次 freeze 之後的 image 內容（對話紀錄、ws 的檔、信箱）。知識庫不在其內。
