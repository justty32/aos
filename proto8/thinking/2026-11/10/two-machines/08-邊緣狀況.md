# 邊緣狀況

目的：照「執行失敗、各種失敗、延遲」把兩台輪流跑會碰到的狀況挖一遍，每條一句會怎樣、一句怎麼處理。

已抽到 [edge_cases.json](edge_cases.json)（40 列）。欄位：`id`、`group`（哪一類）、`case`（狀況）、`what_happens`（會怎樣）、`design`（設計怎麼處理／不處理的理由）。

統計：斷電與關機 5、收工當下 7、GitHub 與網路 6、兩台的差異 7、搬動與手改 5、長跑 6、知識庫 4。

## 先看這幾條就好

- **來不及收工**（WSL 被關、斷電，E01、E03）：同一台再開是「恢復開機」，不拉、直接起；丟的只有當下正在答的那一輪 eca。到另一台接就只能接上一代（E05）。所以午休、下班各存一次。
- **收工時還在忙**（E06～E08）：預設等 15 分鐘；等腦的不怕砍，正在答的 eca 砍了會掉那一批信。
- **推不上去**（E13～E15）：image 已經凍在本機，補推就好；最可能的原因是 ws 裡有大檔。
- **兩台程式或 CLI 版本不一樣**（E20、E21）：只提醒、不擋。每天流程裡固定有「aos repo 也 pull、有改 C++ 就重建」這一步。
- **額度用完**（E31）：全部 eca 一起進冷卻，最多每 30 分鐘各掉一封；額度回來自己恢復。

## 這輪明講不處理的

| 編號 | 什麼 | 為什麼 |
|---|---|---|
| E03 | 斷電留下的半行 history 不自動修 | 自動刪 agent 的記憶比停下來等人危險 |
| E07 | 收工不做「先全體暫停」 | paused 會帶到另一台，醒來還要一隻隻 resume |
| E11 | 收工後殘留的行程不自動殺 | 只有 daemon 與清道夫碰 pid（N-17） |
| E30 | 手動對 image repo 下 git 指令 | 擋不住，寫文件 |
| E35 | 只長不消的檔 | 清道夫第二版或大修的題，不是換台才有 |
| E38～E40 | 知識庫的同步、互蓋、誤刪 | 知識庫那邊的事（裁定 9） |
