# 圖紙對照：保留／修改／作廢

**一句話**：作廢的是「image 那一整套」——`aos-image`、`image.json`、`image_info.json`、`prev`／`rescue` 標籤、`local/`、`local.example/`、`kb` 掛點、freeze／thaw。eca 換台、冷卻、`--auto-restart`、知識庫兩層原則都保留，照圖紙做了。

```mermaid
flowchart LR
    subgraph 作廢
      X1[aos-image 全部] --- X2[image.json／image_info.json] --- X3[prev／rescue 標籤]
      X4[local／local.example] --- X5[kb 掛點] --- X6[freeze／thaw]
    end
    subgraph 保留
      K1[eca 換台開新對話] --- K2[失敗後冷卻] --- K3[--auto-restart] --- K4[知識庫兩層]
    end
    subgraph 修改
      M1[路徑：錨點→三種寫法] --- M2[gitignore：樣板＋指南] --- M3[/mnt/c：從不能放到能放]
    end
```

作廢的根據：使用者「aos image...拿掉吧」、「換台還要特別跑東西...，我原本預期他就是cp過去，起daemon她就自動繼續了」（[README 午後方向改變](README.md#午後方向改變逐字)）。

## 01 整體圖像

| 部分 | 判定 | 現在的樣子 |
|---|---|---|
| 三樣東西三種同步 | 修改 | aos 程式 repo 照舊；image repo 改成**使用者自己的專案 repo**，定義與 stack 放哪、進不進 git 隨使用者；知識庫照舊是任意資料夾 |
| 一棵樹一個 image repo、只留最新一份、強推 | 作廢 | git 由使用者自己下，一般歷史 |

| `stack.gitignore` 加行 | 保留、擴充 | 加了 `cooldown.json`、`wait_warned.txt`、`sent.json`、`__pycache__/`、`endpoints.json`、巢狀 `.gitignore` 放行 |
| 不靠掃描也會推上金鑰的四處 | 保留 | 一頁說明寫「金鑰只放 llms 專案」 |

## 03 收工與開工、04 防呆

| 部分 | 判定 | 現在的樣子 |
|---|---|---|
| `aos-image freeze／thaw／status／init` 全部 | 作廢 | 收工＝`aos-daemon-ctl -d <stack> shutdown`；開工＝`aos-exec --stack <stack> <定義>` |
| `image_info.json`、判斷表、`--takeover`、`prev`／`rescue`／`local-prev` 標籤 | 作廢 | 兩台同時開、拉到舊的，由使用者自己的 git 流程管 |
| 開工清 `think/request.json` | 修改 | wait.py 自己認出舊請求、回去重組（`55bc1205b`） |
| 收工確認沒殘留、等閒下來 | 作廢 | `shutdown` 等子項全睡下；正在答的 eca 那輪會被打斷、那封不重答（裁定 5） |
| 防「同一份在兩處跑」 | 修改 | 只剩 `DaemonExists` 與 daemon 接回時比對是不是自己這棵樹（防副本接管） |
