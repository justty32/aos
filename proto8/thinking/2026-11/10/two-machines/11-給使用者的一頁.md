# 兩台輪流跑：一頁說明（照 11-10 實際做出來的）

下面的 `something`、`defs`、`stacks/root`、`ann` **都只是例子**，換成你自己的名字、放哪都行。每條指令 11-10 都在 `/tmp` 與 `/mnt/c` 用假腦實跑過。

## 每天

```sh
cd something && git pull                       # 或第一次 git clone
aos-exec --stack stacks/root defs              # 起根；睡下的 agent 自己醒、留在信箱的信照答
```

下班：

```sh
aos-daemon-ctl -d stacks/root shutdown         # 全部睡下；印一個數字（退 0）就是停乾淨了
                                               # 印 error: StillRunning（退 1）＝還沒停完，先別 commit，再跑一次 shutdown
git add -A && git commit -m "..." && git push  # git 你自己下，aos 不碰
```

llms（llm kernel）是另一個專案，自己起停：`cd llms && aos-exec --stack stacks/kernel def`，下班 `aos-daemon-ctl -d stacks/kernel shutdown`。

## 這台要備好什麼

之後想改隨時改，改完重起根就生效。都在**起根的那個殼**設：

```sh
export AOS_PROTO8=$HOME/repo/aos-tools/proto8          # 這台 proto8 在哪（或你選的寫法，見下）
export AOS_LLM_KERNEL=$HOME/code/llms/stacks/kernel    # llms 那邊的 stack
unset AOS_CLOCK AOS_DAEMON AOS_STACK
```

- **aos 指令在 PATH 上**：在 aos repo 跑一次 `proto8/install.sh`（repo 換位置要重跑）。
- **claude 登入**：有 eca（claude 當 agent）才要。
- **知識庫在哪**：寫進那隻 agent 的 `tools/memory/_memory.json`，例 `{"base": "../../../../knowledge"}`；相對、絕對、`{"$env": "MY_KB"}` 都可以。
- **`AOS_PROTO8` 的別種寫法**：`copy-out --proto8 absolute|relative` 抄出來的就不靠這個變數（絕對＝兩台 proto8 放同一個位置；相對＝兩台相對位置一樣）。

## 第一次建立

```sh
cd something
copy-out --template daemon-root defs                  # 根的定義（只帶時鐘與清道夫）
copy-out --template agent-fsm defs/ann                # 一隻 fsm agent
copy-out --template eca-claude defs/bob               # 一隻 claude agent（要的話）
cd ../llms && copy-out --template kernel/llm-kernel def   # kernel 放另一個專案；預設端點是假腦 fake
```

起來之後，另一個殼掛 agent（一次就好，之後記在表上、跟著 git 走）：

```sh
aos-agent -d stacks/root ctl add --auto-restart -w . defs/ann
aos-agent -d stacks/root say -t ann "hello"
aos-agent -d stacks/root listen -t ann     # 印出回答
```

`--auto-restart`＝退了就重起、失敗後冷卻（30 秒起、加倍到 30 分鐘）。真的模型與金鑰改 `llms/def/kernel.json` 的 `endpoints`。

## gitignore

要把 stack 放進 git，就照[指南](../../../../cmd/aos-agent/docs/05-gitignore指南.md)把樣板放到 stack 根（或只裝 stack 的那個資料夾）：

```sh
mkdir -p stacks && cp $AOS_PROTO8/cmd/aos-agent/stack.gitignore stacks/.gitignore
```

llms 那邊也放一份。不想帶 stack 就整個 `stacks/` 寫進你自己的 `.gitignore`。kernel 收件匣裡排隊的信會照帶：換台前讓 kernel 把它們答完最好，不然到另一台可能重寄一次、舊的回信可能沒人收。aos 不會自動改你的 `.gitignore`。

## 可以放哪

Linux 檔案系統（`~/…`）、`/mnt/c` 都可以，WSL 看得到的地方都行。

| | ext4（`~/…`、`/tmp`） | `/mnt/c` |
|---|---|---|
| fsm 問一題（假腦＋一次工具） | 約 4 秒 | 約 8 秒 |
| 每輪的小動作（ping、每拍） | 1× | 慢約 2～5 倍 |
| 閒置 CPU（整棵樹） | 約 1 % | 約 3 % |

畫面用的 unix socket 不能放 `/mnt/c`，已經改放 `/tmp`，你不用管。

## kernel 沒開時你會看到什麼

- **llms 還沒起過、或 daemon 沒開**：agent 照常收信，問題寄不出去或排在 llms 那邊，agent **原地等、不會停**（有沒有 `--auto-restart` 都一樣）。stderr 會有 warning，例 `agent-fsm: warning: aos-llm send exited 1 (its reason is above); the request stays and is sent again once AOS_LLM_KERNEL is a folder or the cooldown ends`。
- **你一開 kernel**：排隊的問題一題一題答完，agent 接著做。
- **something shutdown 再起幾次都沒關係**：同一題不會重寄、信不會越堆越多。
- **kernel 回錯**（端點壞、額度到頂）才算失敗：開了 `--auto-restart` 的冷卻後再試；沒開的停在表上等你。
- something 會進 git 的檔都不記 llms 的路徑；被引用的 another 也不會被寫。

## 什麼情況需要你動手

1. **沒開 `--auto-restart` 的 agent 停了**：先排除原因（端點、額度、定義被搬走），再 `aos-agent -d stacks/root ctl start --target ann`。
2. **定義被搬走或改名**：開了 `--auto-restart` 也是重試 3 次就停；放回去後同上 start。
3. **`daemon.json` 裡 `$ref` 的那個檔不見**：整台根起不來（`DirectiveBad … $ref cannot read <檔>`）。放回去再起。
4. **`AOS_LLM_KERNEL` 指錯地方**：會有 `no llm daemon here … letter sent anyway` 的 warning，信會寫進那個資料夾的 `requests/`。改好、刪掉多出來的 `requests/`、重起根。
5. **claude 登入過期**：eca 一直 `CliFailed`、反覆冷卻。重新登入就好。

## 要知道的坑

### 搬家與路徑

- **專案外的 stack 或定義、兩台相對位置不同**：掛 agent 時用環境變數寫法，表上就記指示詞、每次起照這台的環境再解，兩台各設自己的值就好，不用 rm 再 add（11-10 B01）：
  `aos-agent -d <stack> ctl add --auto-restart --ws-json '{"$env": "PROJ"}' --path-json '{"$env": "PROJ", "$path": "/defs/ann"}'`（`--stack-json` 同理）。
  一般的 `add xxx`（位置參數、`-w`、`-s`）會換算：相對路徑存成相對根 stack，所以樹外面的東西兩台相對位置要一樣。已經掛上的舊列不動，要改寫法就 `aos-daemon-ctl -d <stack> rm ann` 再 add（history 接著原來的）；**不要用 `aos-agent ctl rm`，它會刪 stack。**
- **在 `/mnt/c` 用 git 新加的腳本會掉 +x**（`core.filemode=false`），到另一台就跑不起來。新腳本 `git update-index --chmod=+x <檔>`。
- **金鑰只放 llms 專案**（端點單子讀不進 git 的金鑰檔）。agent 的 history、ws 都會進 git，沒有任何掃描在擋。

### eca（claude 當 agent）

- **換台＝新對話＋開場白**：它拿到 aos 記的「之前問過什麼、答過什麼」，記得大意、不是逐字；工具用過什麼不帶。換台本身不掉信。
- **shutdown 打斷它正在答的那輪＝那封不重答**（下一封照常答）。要那封有答，下班前先 `listen` 等它答完再 shutdown。
- **想讓它從頭開新對話**：刪那隻的 `stacks/root/procs/bob/claude/session.txt`，下一封就用 aos 記的紀錄重開。
- 兩台的 claude 盡量同版；`--max-budget-usd 0.5`、10 分鐘逾時是 eca 範本的保守值，長跑時自己調 `cli.json`。
- 多隻同時改同一個知識節點，後寫的贏。
