## 出錯時最常見的三種

1. **fsm_ann `stopped`、reason 是 `RunFailed … fsm.json failed with exit code 1`**（`listen` 會先提醒 `fsm_ann is not running now`）：舊格還在（它還在傳今天拿掉的 `--overlay`），第 4 步沒做或沒做完。重貼第 4 步，再 `aos-agent ctl start --target fsm_ann`。公司那份試驗場今天就是這樣壞的。
2. **`ToolsBad`／`RegistryBad top-level add / rm`**：stack 裡有舊形狀的工具覆蓋檔。`aos-agent tools -t fsm_ann reset --yes`，要的工具再 `aos-agent tools -t fsm_ann add …` 加回去。
3. **`_sweeper` 那列一直重起，或 `aos-sweeper: command not found`**：第 2b 步沒重跑。重跑 `proto8/install.sh`，再重起根。
   - 重建本身出錯（vcpkg、CMake 快取對不上）：`rm -rf proto8/impls/build` 再跑一次 2a（乾淨重建）。

要整個退回：停樹 → `rm -rf ~/code/playground && mv ~/code/playground.bak-1110home ~/code/playground`（舊程式就跑不動了，只是保底）。

## 今天改了什麼、你手感上會不一樣的

- `aos-daemon-ctl -d <stack> shutdown`：不用 Ctrl-C 也能整棵樹下班；印數字＝停乾淨，`error: StillRunning`＝還沒。
- `aos-agent ctl ls -l`：多欄（ws、queue、reason）一眼看誰停了、為什麼。
- 清道夫 `_sweeper`：每台 daemon 一列（要自己掛在 `daemon.json`，第 4 步已掛），每 10 分鐘封存 stderr、清殭屍，保留 7 天。手動：`aos-daemon-ctl -d <stack> sweep --dry-run`。
- daemon 設定的 key 改名 `procs_ctl_mailbox` → `procs_requests`（stack 裡也是 `procs_requests/` 資料夾）。
- kernel（總機）沒開或還沒起：agent **原地等、不會停**，stderr 有 warning；總機起來後排著的題照答（公司實測：先問、再起 kernel，答案照到）。kernel **回錯**（LM Studio 沒開→等滿 120 秒 `EndpointFailed`）才停。
- `aos-tools` 覆蓋檔改 `$override` 新格式；`--override` 改叫 `--replace`；`--overlay` 拿掉；`--env-file` 只記檔案位置、不抄內容；定義快取搬到 stack。試驗場 README 裡那行 `tools … add --override wall_clock …` 現在要寫 `--replace`。
- 範本 `cp -r` 抄出來的東西靠 `AOS_HOME` 找 repo（第 3 步；copy-out 11-10 晚刪了，裝過的 `~/.local/bin/copy-out` 是斷捷徑、刪掉就好）；`.aos-proto8` 錨點、`--relink`、`aos-image` 都拔了。
- `AOS_LLM_KERNEL`＝總機的 stack；試驗場 `env.sh` 已經設好，不用動。

## 想照新用法試（可選）

專案資料夾放定義與 stack、一行起；全文在 [11-給使用者的一頁](11-給使用者的一頁.md)。公司下午照下面這串走通（假腦、`/tmp`）：

```sh
mkdir -p ~/code/llms ~/code/something
cd ~/code/llms && cp -r $AOS_HOME/kernel/llm-kernel def
cd ~/code/something && cp -r $AOS_HOME/templates/daemon-root defs && cp -r $AOS_HOME/templates/agent-fsm defs/ann
export AOS_LLM_KERNEL=$HOME/code/llms/stacks/kernel
(cd ~/code/llms && aos-exec --stack stacks/kernel def)   # 視窗 A
(cd ~/code/something && aos-exec --stack stacks/root defs)   # 視窗 B（也要先 export 上面那行）
cd ~/code/something && aos-agent -d stacks/root ctl add --auto-restart -w . defs/ann   # 視窗 C，只要第一次
aos-agent -d stacks/root say -t ann "what time is it?" && aos-agent -d stacks/root listen -t ann --timeout-s 60
aos-daemon-ctl -d stacks/root shutdown; aos-daemon-ctl -d ~/code/llms/stacks/kernel shutdown
```

真腦：`~/code/llms/def/kernel.json` 預設端點是假腦；要 gemma 就照試驗場那份 `llm_kernel/def/kernel.json` 的 `stupid-fast` 抄過去。
