## B07 daemon.json 一列 `$ref` 壞

**以前**：`procs` 裡一列寫 `{"$ref": "another/x.json"}` 而那份檔不在，整台 daemon `DirectiveBad` 退 1，`_clock`、`_sweeper`、所有 agent 一起停。

**現在**（aos-daemon `procs.cpp` 的 `read_procs` 多一個選填參數收「壞列」，只有 daemon.json 的 procs 用；procs_ctl、信照舊整份不採用）：

```text
aos-daemon: warning: procs.broken in daemon.json: cannot resolve directives: $ref cannot read /…/another/x.json; leaving it stopped, the other procs start (fix it, then restart this daemon)
```

- 表上那列 `phase: stopped`、`reason: cannot resolve directives in the daemon config (procs.broken): $ref cannot read …; fix it, then restart this daemon`，其他列照起。
- 沒重起就 `start` 它＝照舊 `stopped`，reason 變 `failed to start: DirectiveBad …`（daemon.json 只在開門讀一次）。
- 改好檔、重起 daemon＝那列自己起來，不用再 `start`。
- 同名的列已經接回而且還活著＝照跑，不去停它。
- 解不開的範圍：那一列本身的 `$ref`，或它裡面 daemon 會解的格（`ws`、`exec` 的 `$env` 沒設等）。`procs` 本身那層壞（例 `"procs": {"$ref": [...]}` 其中一份不在）、列的形狀不對（`CfgBad`）照舊整台退 1。

**驗證**：aos-daemon `test_two_machines` 加兩支（一列壞其他照起、start 照舊停、改好重起自己起；`procs` 頂層壞照舊退 1），手跑一次看 warning 與表。aos-daemon 五支測試檔全過（ctl、lifecycle、poke、stale_stop、two_machines）。文件：aos-daemon [docs/05](../../../../impls/aos-daemon/docs/05-信箱.md)「指示詞與切檔」補例外。

## B08 `$ref` 進來那份檔的相對路徑、EntryMissing

**語意沒改**（見待裁 1）：`$ref` 的**檔名**從寫著它的那份檔算；那份檔**裡面**的 `exec`、`ws`、`stack`、`def` 照舊從 **daemon 的 cwd** 算（引用的那一邊）。施工時自己就寫錯一次（`another/x.json` 寫 `../body.py`，起不來），所以文件要寫清楚。

**做了**：aos-exec `find.cpp` 的 `locate`，相對路徑找不到時多印基準與絕對路徑；絕對路徑照字面。

```text
aos-exec: error: EntryMissing entry not found: agents/a (relative paths count from /home/me/root: /home/me/root/agents/a)
```

命令列打的從 cwd 算；字串轉向（`"_entry": "agents/a"`）從寫著它的那份檔所在的資料夾算。daemon 起的 exec 型 proc 是 cd 到 daemon 的 cwd 再交 aos-exec，所以小格 `stderr.txt` 裡會看到「從 daemon 的 cwd 算」。

**驗證**：新增 aos-exec `tests/test_entry_missing.py` 3 支（相對、轉向、絕對）；`test_classify` 照過。文件：aos-exec [docs/05](../../../../impls/aos-exec/docs/05-錯誤代號等.md)（例子與 `EntryMissing` 那列）、[docs/02](../../../../impls/aos-exec/docs/02-種類.md)（字串轉向那條指到 daemon 的例外）、aos-daemon docs/05。

## B09 `budget.senders` 的 key 對不上

**做了**：aos-llm-kernel `parse_budget` 把每個 key 解成絕對路徑後，不是資料夾就記一條提醒；`read_cfg` 印出來：

```text
aos-llm-kernel: warning: budget.senders key "agents/gone" is not a folder: /…/agents/gone (relative keys count from /…/llms/def, the kernel config's folder); this limit only applies to letters whose sender is exactly that path
```

kernel 是 daemon 的身體、每 300 ms 一個新行程，每拍都印會灌爆 stderr，所以印過的全文記在 `$AOS_STACK/budget_warned.txt`，一樣就不再印；沒有提醒就刪掉它（又壞了再印）。那格照收（agent 之後才建也行）。

**驗證**：aos-llm-kernel `test_two_machines` 加 `test_missing_sender_folder_warns_once`（第一拍印、第二拍不印、改對了檔消失、又壞再印）。aos-llm-kernel 七支測試檔全過（含兩支 live：batch8、nesting_live）。文件：aos-llm-kernel [docs/02](../../../../impls/aos-llm-kernel/docs/02-token-回報與額度.md)。
