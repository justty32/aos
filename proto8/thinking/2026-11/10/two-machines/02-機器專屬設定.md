# 機器專屬設定：全收在 image 根的 `local/`

**一句話：這台才有的東西只放 `local/`（不進 git），進 git 的定義用相對路徑指過去；指不到就起不來、錯誤講得出是哪個檔。**

`local/` 在 image 根裡面而不是家目錄，理由：定義到它的相對路徑兩台一樣，不需要另一條錨點；`git reset --hard` 不會動沒被追蹤的檔，所以拉新 image 不會洗掉它。

## `local/` 裡有什麼

| 檔 | 內容 | 誰讀 |
|---|---|---|
| `machine.json` | `{"name": "office"}`——這台在標記裡叫什麼（不用主機名：WSL 的主機名會變） | `aos-image` |
| `endpoints.json` | 這台的端點：整個端點物件（url、model、backend、slots、context、summary…） | aos-llm-kernel（經 `$ref`） |
| `keys.json` | `{"litellm": "sk-…"}` | 端點單子（經 `$ref`） |
| `launch.json` | 這台怎麼起根：`{"wrap": ["systemd-run", "--user", "--scope", "-p", "MemoryMax=4G"], "tmux": true}`；沒有這個檔＝直接用 tmux 起 | `aos-image thaw` |
| `env` | 其他這台才要的環境變數，一行一個 `名字=值`（不是 shell，不展開）；例 `DISABLE_AUTOUPDATER=1`、`CLAUDE_CONFIG_DIR=…` | `aos-image thaw` 起根前設好 |

`local.example/` 進 git，內容是同樣五個檔的假值版，新機器 `cp -r local.example local` 再改。

## 進 git 的定義怎麼指過去

### 端點的 url 與 model

`llm_def/kernel.json` 的 `endpoints` 改成「共用的一份疊上這台的一份」：

```json
"endpoints": {"$ref": ["endpoints.json", "../local/endpoints.json"]}
```

- `llm_def/endpoints.json`（進 git）：兩台都一樣的端點（假腦、經 litellm 的雲端模型）。
- `local/endpoints.json`（不進 git）：這台的本機模型。**同名的整個蓋掉**（只疊一層，不往裡面合），所以要寫完整的端點物件。

兩台用**同一個代號**指各自的模型，agent 的 `llm.json` 就不用跟著換台改：

```json
{"stupid-fast": {"backend": "lmstudio", "url": "http://localhost:1234/v1", "model": "google/gemma-3-4b",
                 "slots": 1, "speed": "fast", "cost": "free", "context": 4096,
                 "summary": "LM Studio on this machine"}}
```

公司那份同樣叫 `stupid-fast`，`model` 寫 `qwen3-1.7b`。

### 金鑰

端點單子 `llm_def/endpoints/litellm/_entry` 加一個 `envs`，金鑰只進這一支行程：

```json
{"argv": ["aos-exec", "../../.aos-proto8/lib/base/llm_http", "--key-env", "LITELLM_KEY"],
 "envs": {"LITELLM_KEY": {"$ref": "../../../local/keys.json#/litellm"}}}
```

（錨點放在 `llm_def/` 這一層；兩條相對路徑都從這份 `_entry` 所在的資料夾算。）這樣金鑰**不必在起根的殼裡 export**，整棵樹的其他行程看不到，agent 跑 `env` 也印不出來。要不要走這條、或照舊 export，是 [09 題 1](09-衝突與要裁的.md#題-1金鑰)。

### 為什麼選 `$ref` 本機檔、不選 `$env`

兩個都實測解得開（見下）。差別在缺的時候：

| 寫法 | 這台沒準備好時 | 評價 |
|---|---|---|
| `$ref` 指 `local/…` | kernel **起不來**，`aos-llm-kernel: error: DirectiveBad $ref cannot read …/local/endpoints.json` | 推薦：開工當下就知道、訊息指名哪個檔 |
| `{"$env": "X"}` | kernel 照起，**第一題才回錯**（坑-51 那種） | 備案 |

## 實測（WSL `/tmp`，假端點，11-10；已清）

1. `kernel.json` 寫 `"endpoints": {"$ref": ["endpoints.json", "../local/endpoints.json"]}`，本機檔覆蓋 `stupid-fast`：kernel 掛出去的請求檔 `requests/cur/<信>/request.json` 的 `endpoint` 是本機那份的 url／model／context；kernel 對外的 `endpoints.json` 窗也用本機的 `context`。
2. 端點值寫 `{"$env": "TM_URL"}`、`{"$env": "TM_MODEL"}`：請求檔裡是環境變數的值。
3. 把本機檔拿走：kernel 退 1、錯誤如上表。環境變數沒設：kernel 退 0 照跑，要等到用那個端點才回錯。
4. 單子的 `envs` 寫 `{"$ref": "../../local/keys.json#/litellm"}`：子程式環境裡拿得到值；檔不在＝`aos-exec` 報 `$ref cannot read`。

沒測的：真的 HTTP 端點、整棵樹經 daemon 起（只單跑了 kernel 一圈與 aos-exec 一次）。

## 兩台不同、但不放 `local/` 的

| 東西 | 怎麼辦 |
|---|---|
| aos repo 的位置 | 錨點 `.aos-proto8`；`thaw` 每次跑 `copy-out --relink` |
| 知識庫的位置 | image 根的 `kb` 掛點（[07](07-知識庫接點.md)） |
| 帳號名（`limits.user`） | 先不用；要用就兩台建同名帳號（寫進定義的值兩台得一樣） |
| claude／codex 的登入 | 各機各自登入；版本由 `image_info.json` 記、`thaw` 比對後提醒 |
| `AOS_LLM_KERNEL` | `thaw` 從 `image.json` 算出這台的絕對路徑再設，不存檔 |

## 第一次在新機器要準備什麼

1. clone aos 程式 repo、建 bin、`install.sh`；確認 `aos-daemon`、`aos-image`、`copy-out` 在 PATH。
2. `git clone <image repo 網址> ~/aos/img`（放 Linux 檔案系統）。
3. `cp -r local.example local`，改五個檔。
4. `ln -s <這台知識庫的位置> kb`。
5. claude、codex 各自登入；`local/env` 寫 `DISABLE_AUTOUPDATER=1`，兩台盡量同版。
6. `aos-image thaw`——它會重指錨點、檢查上面每一項，缺什麼講什麼。
