# self-family／hook（11-10 晚）：事件發生時跑指定的 aos 函數——hook 機制、`aos-agent hook`、`self_hook`

← [self-family](../README.md)｜[11-10](../../README.md)

## 使用者原話（逐字）

- 「還有self_hook，用於在有東西進到queue，或是一些事件發生，比如呼叫了某特定工具，比如brain呼叫失敗，或是新增了某些特定工具之類時，執行指定aos函數。」
- 通則（講 self_tools 時）：「我原本想說，這支工具就是aos-agent tools的包裝，只是目標改自己」
- 頂層問七題：1「aos 函數」＝任何 aos-exec 跑得動的東西（定義資料夾、JSON、執行檔），事件內容 JSON 從 stdin 餵；2 hook 能不能改變結果（攔下工具呼叫、改寫進 queue 的信）還是只順便跑；3 事件前或後觸發；4 等不等它跑完；5 hook 自己失敗時 agent 停不停；6 連鎖（hook 寄信給自己又觸發 hook）；7 eca 的腦在外面、有些事件攔不到，接受縮水版嗎。
- 使用者答：「1.讓規劃者回去看過去的定義，基本上就是你理解的這樣。2.可選。我是希望能改變結果啦，只是有些東西不能改，那就不用動。3.都要。4.可選，默認等他跑完。5.可選，默認跟着停。6.自行承擔。7.接受」

## 決定

- hook 的目標＝aos 函數＝aos-exec 跑得動的東西；事件內容是一份 JSON、從 stdin 進（既有定義的引文在[圖紙 § 1](01-圖紙.md#1-aos-函數的既有定義)）。
- 能不能改結果：每個 hook 自己選；改不了的事件就只是通知。
- 事件前、後都有觸發點。
- 等不等它跑完：每個 hook 自己選，預設等。
- hook 自己失敗：每個 hook 自己選，預設 agent 跟著停。
- 連鎖不檢測，使用者自行承擔。
- eca 給縮水版。
- 頂層的假設（使用者沒反對、沒明說同意）：人用 `aos-agent hook`、`self_hook` 純包裝它、清單存 agent 自己那份蓋在定義上。
