## 驗收（scratch 夾 `cp -r` 起一棵：llm kernel＋根＋fsm）

假腦劇本（`llm_fake` 的 `script`），hook 全用 `aos-agent hook add` 掛：

| 項目 | 結果 |
|---|---|
| `queue_before` 改寫 | 過：history 裡是 `hello one [edited by hook]` |
| `queue_before` 丟信（退 10） | 過：`mailbox_warning.txt` 寫 `letter … dropped by hook q_edit`，history 沒有那封 |
| `queue_after` 通知 | 過 |
| `tool_before` 通知（match wall_clock） | 過：事件 JSON 有 name、id、arguments |
| `tool_after` 改結果 | 過：腦看到 `HOOKED RESULT (was 21 bytes)` |
| `tool_added` | 過：掛上後第一題不觸發；`aos-agent tools add math` 後下一題觸發一次，帶 name、path |
| `tool_before` 改參數 | 過：腦叫 `1+1`，工具回 `5`（被改成 `2+3`） |
| `tool_before` 攔下 | 過：工具沒跑，腦收到 `blocked by acceptance hook` |
| 不等（`--no-wait`，hook 睡 6 秒） | 過：2 秒就答完，7 秒後 hook 的記號才出現 |
| 失敗不停（`--on-fail continue`） | 過：照樣答、agent 還在跑 |
| 失敗跟著停（預設） | 過：stderr `agent-fsm: error: HookFailed hook q_fail (event queue_after) failed: exited 3`，表上 `stopped`（有 `--auto-restart` 的那隻會被 daemon 重新起來） |
| `brain_failed` | 過：model 設成不存在的代號，hook 收到 `{"name": "BrainFailed", "reason": "aos-llm recv exited 1 …"}`，原本的冷卻與停下照舊 |

真腦（家機 LM Studio gemma-4-e4b）：一句「Use your self_hook tool to add a hook named mylog on the event queue_after that runs the program …/log.py」，它第一次就叫對 `{"op":"add","on":"queue_after","path":…,"name":"mylog"}`；下一句話進來，hook 觸發、記到事件。

**沒驗到的**：eca 用真 claude（haiku）對話那一段——跑指令時被權限系統擋下，沒有繞過去。eca 這邊只有假 CLI 的自動測試（18 支，全過）。照抄步驟在下面。

## eca 真對話照抄（會花 claude 額度）

```sh
# 根 daemon 起著、AOS_DAEMON 指到它的 stack、AOS_HOME 設好
aos-agent ctl add -w . defs/eca                    # defs/eca＝cp -r $AOS_HOME/templates/eca-claude
aos-agent llm --target eca set model=haiku
cat > /tmp/hk.py <<'PY'
#!/usr/bin/env python3
import json, sys
e = json.load(sys.stdin)
open("/tmp/hk-events.jsonl", "a").write(json.dumps(e) + "\n")
if e["event"] == "queue_before":
    print(json.dumps({"content": e["content"] + " (reply in one short sentence)"}))
PY
chmod +x /tmp/hk.py
aos-agent hook --target eca add --on queue_before --change -n qb /tmp/hk.py
aos-agent hook --target eca add --on queue_after -n qa /tmp/hk.py
aos-agent hook --target eca add --on tool_before --match wall_clock -n tb /tmp/hk.py
aos-agent hook --target eca add --on tool_after -n ta /tmp/hk.py
echo "What time is it? Use the wall_clock tool." | aos-agent say --target eca && aos-agent listen --target eca
```

算成功：`/tmp/hk-events.jsonl` 依序有 queue_before、queue_after、tool_before、tool_after；那隻 stack 的 `history.jsonl` 的 user 那則尾巴多了那句；小格 `claude/mcp.json` 的 args 有 `--hooks <定義>`。

## eca 攔得到／攔不到

- 攔得到：`queue_before`（改寫、丟信）、`queue_after`、`brain_failed`（交出去之後的 CliFailed／ReplyMissing）、`tool_added`、經 aos-mcp 叫的 aos 工具的 `tool_before`／`tool_after`。
- 攔不到：CLI 自帶的工具（Read、Bash…）、人在畫面上自己打的話、交出去之前的錯、aos-mcp 開場拿知識庫根那一次。

## 施工中多出來的代定（可翻案；圖紙那 11 條之外）

1. hook 名字不能空、不能有 `/`、不能 `.` 開頭（名字拿來當小格資料夾名）。
2. `hooks/<名>/` 小格歸成不進 git（跟 `tools/<名>/` 帶走不一樣）；hook 想留跨機的狀態要自己放工作區。
3. `tool_added` 的名單先記後跑：hook 停下的話，那個新工具下次不會再觸發。
4. `queue_after` 的 hook 讓 agent 停下時，那封信已經在 history 裡；fsm 重起後要等下一封信進來才會答到它（驗收時看到的）。eca 則是先讓 CLI 答完再報錯。
5. `brain_failed` 的 hook 自己失敗（on_fail stop）時不記冷卻、直接 HookFailed 退 1；`aos-llm` 根本起不來的那種 SendFailed 不觸發。
6. eca 的 `tool_added` 在「這輪有好信、交出去之前」比對，不是每 300 ms 一拍都比。
7. aos-mcp 的 `tool_after` 改了 content＝整個結果換成那一段文字，isError 照工具原本的結束碼。
8. `aos-agent hook add --match` 給一個存字串、多個存陣列；`ls -l` 與 `--json` 不能同時給。
9. `self_hook` 的相對 `path` 從工作區算，存進檔時變成相對 stack 那份檔的資料夾，所以 `ls` 印的路徑跟當初給的寫法不同。

## 留給使用者的

- 改結果預設關（`change` 要自己開）——他說「我是希望能改變結果啦」，如果想預設開，改 `hooks.py` 的 `DEFAULTS` 一格。
- 上面第 4 條（`queue_after` 停下後那封信晾著）要不要補：例如重起時 idle 看到 history 最後一則是 user 就直接去 think。
- 要不要把 hook 寫進 CONVENTION 條文。
- 可加的事件：`brain_before`、`brain_after`、`tool_removed`、`tool_failed`、`agent_start`／`agent_stop`、`clock`（每 N 個 cycle；頂層正在跟使用者確認）、agent 之間的「信進信箱」（mailbox 線的事）。事件清單是 `hooks.py` 裡一張表，加一個＝加一列＋一個觸發點。

## 持久格式要重建什麼

沒有。全是新增的檔（定義與 stack 的 `hooks.json`、`hooks/<名>/`、`hook_tools_seen.json`）；`interfaces.json` 的 `aos-agent` 多一個選填鍵 `hooks`，舊定義沒寫＝沒有 hook。
