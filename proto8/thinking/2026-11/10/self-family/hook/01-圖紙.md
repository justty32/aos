# hook 圖紙（11-10 晚）

← [hook](README.md)

> **11-10 深夜改名與改預設**（[tonight-rulings](../../tonight-rulings/README.md) 題 3）：使用者「3.幫我改成預設是開，選項名稱這塊，可以參考c#或java的hook那樣。」看過對照表後「hook這塊，主要走A, 但filter改condition。」——本圖紙以下照留當時的舊名，現行名字：`on`→`event`、`exec`→`handler`、`match`→`condition`、`change`→`intercept`（預設 true）、`wait`→`async`（預設 false，意思反過來）、`on_fail`→`on_error`、`timeout_ms` 不動；事件 `queue_before`→`before_queue`、`queue_after`→`after_queue`、`tool_before`→`before_tool`、`tool_after`→`after_tool`，`brain_failed`、`tool_added` 不動。現行說明在 [aos-agent docs/06](../../../../../cmd/aos-agent/docs/06-hook.md)。

一句話：**agent 的格在幾個固定的點上，照一份清單去跑指定的 aos 函數；事件內容用 JSON 從 stdin 餵進去，函數用結束碼和 stdout 回話。**

## 1. 「aos 函數」的既有定義

使用者過去的話（原樣）：

- 「一個函數是用_entry去跑。其特性我想要將其寫到_metainfo」（10-24，[NORMS 待定 metainfo](../../../../../docs/NORMS/08-待定/01-續-metainfo.md)）
- 「純粹把資料夾作為lisp的list或lua的table，然後有一個entry……」；使用＝`aos-exec [--ws WS] XXX [args...]`，XXX 可為資料夾、檔、`檔#/指標`（10-19，[C-68](../../../../../docs/CONCEPTS/01-設計理念/06-C-68～C-72.md)；入口四種見 C-73）
- 「我們aos函數他也是透過json去定義的，並且aos函數是aos體系的基石，和tool呼叫，兩者之間應該要是可以無痛轉換。」「這個method的實際input，在aos體系下通常都來自於stdin，output也是stdout/err。」「若是單純的aos函數……argv的旗標盡量不要濫用，大多東西都走要給stdin的json」（11-05，[C-82](../../../../../docs/CONCEPTS/05-agent/02-agent-的工具與agent-就是一台狀態機.md)）
- 非同步呼叫那邊同一個形：「body＝那函數的 stdin JSON」「成功的回信 body＝函數 stdout 原樣」（11-06，[N-66](../../../../../docs/NORMS/05-基礎設施-窗/08-N-66.md)）
- 「我們把json+資料夾當Lisp的list，這就是一個函數啊，何必再造一個體系？」（10-16，[C-46](../../../../../docs/CONCEPTS/05-agent/01-腦-工具-可預測性與agent函數binding.md)）

所以 hook 的目標照這個定義，不另造形式：

- **目標**＝任何 `aos-exec` 跑得動的東西（定義資料夾、JSON 檔、`檔#/指標`、執行檔）。lib 裡的工具夾直接能當 hook（C-82 無痛互轉）。
- **怎麼叫**：`aos-exec --stack $AOS_STACK/hooks/<hook 名>/ <目標>`，`AOS_WS` 等照樣往下傳；小格比照工具的 `tools/<名>/`（P-17）。
- **怎麼餵**：事件 JSON 一份，從 stdin 進（同時留一份在小格的 `event.json`，是最後一次的事件）。
- **怎麼回話**：結束碼＋stdout（§ 3）。stderr 不讀、原樣透出。

## 2. 事件清單

名字全小寫底線、主題在前（C-54）。「前」＝事情還沒發生、可以攔；「後」＝已經發生。

| 事件 | 觸發點（agent-fsm 的格） | 事件 JSON 多的欄位 | `match` 比什麼 | 能改 |
|---|---|---|---|---|
| `queue_before` | idle：一封好信從 queue 拿出來、接進 history 之前 | `letter`（信名）、`content` | —（不收 match） | 改寫 `content`、丟掉這封 |
| `queue_after` | idle：那封信接進 history 之後 | `letter`、`content`（實際接進去的） | — | 不能 |
| `tool_before` | act：一個工具呼叫要跑之前（已確認登記過、arguments 是 JSON） | `name`、`id`、`arguments`（解開的 JSON） | 工具名 | 改 `arguments`、攔下不跑 |
| `tool_after` | act：工具跑完（含失敗、逾時）、結果接進 history 之前；被攔下的不觸發 | `name`、`id`、`arguments`、`content`、`code`（逾時＝null）、`timed_out` | 工具名 | 改寫 `content`（腦看到的結果） |
| `brain_failed` | wait：BrainFailed（kernel 回錯）、SendFailed（寄不出去）、ReplyBad（回信不合）那一刻，照原本行為退出之前 | `name`（那個代號）、`reason` | 代號 | 不能 |
| `tool_added` | think（brain.py）：這一題的工具清單比上一次看到的多了名字，一個名字一次 | `name`、`path` | 工具名 | 不能 |

- 每份事件 JSON 都有：`event`、`hook`（這個 hook 的名字）、`stack`（agent 的 stack 絕對路徑）。
- `match`＝一個字串或字串陣列，跟上表那欄**完全相等**才觸發；沒寫＝全部。queue 兩個事件不收 `match`。
- `tool_added` 怎麼知道「多了」：有 `tool_added` hook 生效時，think 把這次的工具名單記在 `$AOS_STACK/hook_tools_seen.json`；第一次只記不觸發（不然一掛上去所有工具都算新增）；沒有這種 hook 時刪掉那份檔。不管工具是誰加的（self_tools、人、改定義）都抓得到。
- 同一事件多個 hook：照名字排序一個一個跑；前一個改過的東西，後一個看到的是改過的；被攔下就不往下跑。
- **可加、這次不做**：`brain_before`（請求組好、可改請求）、`brain_after`（腦回話了）、`tool_removed`、`tool_failed`、`agent_start`／`agent_stop`。

## 3. 回話協定與改變結果

結束碼分岔（N-36 的做法；10＝「不要」不是錯，N-43）：

| 結束碼 | 意思 |
|---|---|
| 0 | 放行。hook 設了 `change` 而且 stdout 非空＝stdout 必須是一個 JSON 物件，認得的鍵拿來改（下表）；不認得的鍵忽略（C-48）。stdout 空＝不改 |
| 10 | 攔下（只對「能攔」的事件、而且 hook 設了 `change`）：`tool_before`＝這個工具不跑，腦收到的結果＝hook 的 stdout（空就給一句 `(tool NAME blocked by hook HOOK)`）；`queue_before`＝這封信收掉、不進 history。其他情況的 10＝當 0 |
| 其他、逾時、起不來、該是 JSON 物件卻不是 | hook 自己失敗（§ 4） |

| 事件 | stdout 認得的鍵 |
|---|---|
| `queue_before` | `content`（非空字串） |
| `tool_before` | `arguments`（任何 JSON 值；交給工具前轉回字串） |
| `tool_after` | `content`（字串） |

- **改不改是每個 hook 自己選的**：`change: true` 才看它的 stdout 與 10；沒設＝純通知，stdout 不看。
- 不能改的：`queue_after`、`brain_failed`、`tool_added`（事情已經發生）；不等它跑完的 hook（`wait: false`）。對這些寫 `change: true`＝`aos-agent hook add` 直接說 ArgumentsBad。
- history 裡腦那則 assistant 訊息的 `tool_calls` 不動（改過的 arguments 只交給工具，不回頭改紀錄）。

## 4. 選項與預設

hook 清單裡一格的鍵：

| 鍵 | 意思 | 預設 |
|---|---|---|
| `on` | 事件名（必填） | — |
| `exec` | 目標：路徑字串或指示詞物件（`{"$env": "AOS_HOME", "$path": "/lib/…"}`）（必填）。相對路徑從寫它的那份檔的資料夾算 | — |
| `match` | 見 § 2 | 全部 |
| `change` | 看不看它的回話 | false |
| `wait` | 等不等它跑完 | true |
| `on_fail` | hook 自己失敗時：`stop`＝這格印 `agent-fsm: error: HookFailed …`、退 1（agent 停下等人，P-20）；`continue`＝印一行 warning、當沒這個 hook | `stop` |
| `timeout_ms` | 等它的上限；到了整群收掉、算失敗 | 60000 |

- `wait: false`：放出去就不管（自成一群、stdout 丟掉、stderr 照樣透出）；失敗、逾時都不知道，`on_fail`／`timeout_ms` 用不上。
- 連鎖不檢測（hook 寄信給自己又觸發 hook＝自行承擔）。
- 清單本身壞（不是 JSON、格的形狀不對）＝這格 `HooksBad` 退 1。

## 5. 存哪、怎麼管

- **宣告**：定義的 `interfaces.json` 的 `aos-agent` 多一個 `"hooks": "hooks.json"`（跟 `tools`、`llm` 並排）。沒宣告＝這隻沒有 hook 機制。
- **兩份檔、同一個形狀**：定義那份 `<定義>/hooks.json`、agent 自己那份 `<stack>/hooks.json`，都是 `{"hooks": {"名字": {…} 或 null}}`。讀法＝定義那份，疊上自己那份：同名的蓋過去、`null`＝關掉定義裡那一個。每格每次重讀＝改了下一個事件就生效。
- **`aos-agent hook`**（照 `aos-agent tools` 的慣例；只寫 stack 那份，定義不動）：
  - `ls [-l | --json]`：一行一個 `NAME TAB EVENT TAB EXEC`；`-l` 多 `MATCH WAIT ON_FAIL CHANGE TIMEOUT_MS FROM`，也列被設成 null 的。
  - `get NAME`：印那一格 JSON。
  - `add --on EVENT [--name N] [--match M]… [--change] [--no-wait] [--on-fail stop|continue] [--timeout-ms N] [--replace] (XXX | --path-json JSON)`：名字預設＝XXX 的檔名／夾名；撞名＝`HookExists`（加 `--replace`）；XXX 不存在＝`PathMissing`；相對路徑存成相對 stack 那份的資料夾、絕對存絕對（同 tools）。
  - `rm NAME`：定義裡有的＝寫 `null`；只在自己那份的＝刪那一格。沒有＝`HookMissing`。
  - `reset [-y]`：刪掉 stack 那份。
  - 不給動作＝`ls`；沒宣告＝`HooksMissing`。
- **`self_hook`**（`lib/agent/self_hook/`）：`aos-agent hook --target 自己` 的純包裝，op＝ls／get／add／rm／reset，參數一對一；樣板＝`lib/agent/self_tools/`。agent-fsm、eca-claude 範本預設登記。
- **共用模組** `lib/agent/hooks.py`：讀清單（疊兩份、驗形狀）、挑出符合事件的 hook、跑、解回話。四個格、aos-eca-turn、aos-mcp、aos-agent hook 都用它，不各自拼。
- stack 多出來的東西：`hooks.json`（持久，要跟著 agent 走）、`hooks/<名>/`（小格，執行中狀態）、`hook_tools_seen.json`（執行中狀態）。**要重建什麼**：沒有（新增的檔，舊 stack 不受影響）。

## 6. eca 縮水版

eca 的腦是外面的 CLI，aos 只看得到經過自己手的東西：

| 事件 | eca | 在哪 |
|---|---|---|
| `queue_before`／`queue_after` | 有 | aos-eca-turn 讀信、交給 CLI 之前／信接進 history 之後 |
| `tool_before`／`tool_after` | 只有經 aos-mcp 叫的 aos 工具 | aos-mcp 的 tools/call |
| `brain_failed` | 有（`name`＝`CliFailed`／`ReplyMissing`） | aos-eca-turn |
| `tool_added` | 有（看 aos 登記檔的名單） | aos-eca-turn 每輪開頭 |
| CLI 自帶工具（Read、Bash…）、人在畫面上自己打的話 | 沒有 | 沒經過 aos |

## 7. 岔路

沒有需要使用者現在裁的方向衝突。下面是照原則代定的，可翻案：

1. 指令叫 `aos-agent hook`（單數，照頂層的寫法）；檔名與鍵用複數 `hooks.json`／`"hooks"`（裝同類的用複數，C-54）。
2. 自己那份**不寫 `$override` 指標**：tools 需要指標是因為讀它的 aos-tools 只收一份檔；hook 的讀者一定同時知道定義與 stack，照 `llm.json` 的疊法（定義＋自己那份蓋上去、null 關掉）就夠。差異檔的精神一樣。
3. 改結果預設關（`change` 沒設＝純通知）：免得一個隨手印東西的函數被當成「改寫」。使用者說「可選」，這裡選的預設是不改。
4. 攔下用結束碼 10，不用 stdout 的旗標。
5. 逾時預設 60 秒（不設上限的話，一個卡住的 hook 會讓 agent 整隻卡住）。
6. `tool_added` 掛上去之後才開始算「新增」，掛之前已有的不補觸發。
7. `brain_failed` 包含 SendFailed、ReplyBad（都是「問腦沒成」），用 `match` 分。
8. `match` 只做完全相等，不做萬用字元／正規式。
9. 不等跑完的 hook 的 stdout 丟掉。
10. 多個 hook 照名字排序跑。
11. 不寫進 CONCEPTS／NORMS／CONVENTION 條文（條文是使用者的），只寫程式說明與 README；要不要升條文留給使用者。
