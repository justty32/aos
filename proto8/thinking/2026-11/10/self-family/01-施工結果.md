## 代定清單（照最保守能用的定的，可翻案）

1. 動作名 ls／rm／summarize／set；一段寫 `N`、`A-B`、`A-`；行號＝第幾則訊息（空行不算）；不給動作＝ls。
2. 摘要那則的 role 預設 `user`（`--role` 改），內容照字面、不自動加前綴。
3. 原文預設放 history 同資料夾的 `history_removed.jsonl`；`--keep` 相對目前資料夾（self_history 從工作區算）；`--no-keep` 才問、`-y` 跳過。
4. history 位置靠 `interfaces.json` 宣告；四個格的程式裡照舊寫死 `history.jsonl`。
5. 「這一步」的鎖只在 self_history 包裝層，人用的指令不擋。
6. 從外面改正在跑的：fsm 寄信前多看 mtime；已寄出去的不追、回信照接在改過的後面；act 正好 append 的空窗靠寫前比對、重做最多 3 次擋；建議先 `ctl pause`。
7. eca：雜湊對不上就開新對話，帶 user／assistant 文字紀錄（上限 `reseed_bytes`，預設 48000）；畫面開著不換。
8. 兩種範本都預設登記 self_history。

## 留給使用者的：eca 真對話驗收（會燒額度）

```
aos-agent ctl add --ws <ws> --name myproj proto8/templates/eca-claude
aos-agent say -t myproj "記住：我最愛的顏色是藍色" && aos-agent listen -t myproj
aos-agent history -t myproj ls
aos-agent history -t myproj rm 1-2          # 或 summarize 1-2 "…"
aos-agent say -t myproj "我最愛什麼顏色？" && aos-agent listen -t myproj
```

看 stderr（或 daemon log）有一行 `starting a new claude conversation`，而且 claude 只記得改過的內容。另一種：叫 claude 自己用 `mcp__aos__self_history` 改，改完下一輪也應該開新對話。

## 知識節點內容（給頂層轉 json-memory 隊；這條線不碰 `knowledge/aos`）

- **self_history 是什麼**：看、刪、摘要、改「叫我的 agent 自己」的對話紀錄。是 `aos-agent history --target 自己` 的包裝。
- **op 與例子**：
  - `{"op": "ls"}`、`{"op": "ls", "range": "5-", "json": true}`
  - `{"op": "rm", "range": "3-4"}`
  - `{"op": "summarize", "range": "1-6", "text": "User said their favorite color is blue."}`（`role` 預設 user）
  - `{"op": "set", "line": 2, "message": {"role": "user", "content": "…"}}`
  - 改的三個可加 `keep`（原文放哪）或 `no_keep: true`（不留）。
- **鎖**：正在進行的這一步（fsm＝叫 self_history 的那則 assistant 起；eca＝這一輪交進來的 user 起）動不了，碰到＝`RangeBad`；先 `ls` 看最後一行哪幾行鎖著。
- **原文不丟**：預設搬到 stack 裡 `history_removed.jsonl`。
- **何時生效**：下一輪起。eca（claude）改過就會開新對話、帶改過的紀錄過去（session 換掉、cache 沒了）。
- **人用**：`aos-agent history -t 名字 ls|rm|summarize|set`；改正在跑的先 `aos-agent ctl pause`。
