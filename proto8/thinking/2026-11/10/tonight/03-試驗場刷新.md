# 03 試驗場刷新：一段照抄就把 ~/code/playground 換成 repo 最新版（先備份、保留 gemma／haiku），已在複本上實跑過

← [2026-11-10](../README.md)｜底稿 [json-memory 07 最後一節](../json-memory/07-怎麼玩與刷新試驗場.md#試驗場-codeplayground-怎麼刷新照抄這次沒執行)

**結論**：下面那格整段貼進終端機（zsh、bash 都行）就刷新完。它會自己停掉試驗場的樹、整份備份成 `~/code/playground.bak-<月日-時分>`，再把四份複本、總機定義、四隻員工換成 repo 版，最後清掉三個 stack。**會清掉的是員工的對話紀錄、信箱、`llm set` 換過的腦設定、舊子 `kid_fsm_ann`**；你家機的 gemma（`stupid-fast`）、eca_bob 的 haiku 與 0.2 美金照留。這格在原件的完整複本上跑了三次（zsh 非互動、bash 帶「先停樹」、你自己的互動 zsh 設定），都過；原件沒動，也還沒對原件跑——誰跑、什麼時候跑由你決定。

## 照抄（刷新）

先等 fsm／eca 沒有題在答（不想等也行，停樹時在飛的題會作廢）。改第一行就能對別的試驗場跑。

```sh
PG=~/code/playground
( set -eu
R=$HOME/repo/simple_tools/aos/proto8                      # this machine's repo (not ~/repo/aos-tools)
BAK=$PG.bak-$(date +%m%d-%H%M)
[ -f "$PG/env.sh" ] && [ -f "$PG/root/daemon.json" ] || { echo "not a playground: $PG"; exit 1; }
n=1; while [ -e "$BAK" ]; do n=$((n+1)); BAK=$PG.bak-$(date +%m%d-%H%M)-$n; done   # never overwrite a backup
cd "$HOME"
# 0) stop the tree if its root is running (only the pid in $PG/.stack/state.json whose cwd is $PG/root)
mine() { for p in /proc/[0-9]*; do n=${p#/proc/}; [ "$n" != "$$" ] || continue
  case "$(command cat "$p/comm" 2>/dev/null)" in bash|zsh|sh|dash|fish) continue;; esac
  c=$(readlink "$p/cwd" 2>/dev/null || true); a=$(command cat "$p/cmdline" 2>/dev/null | tr '\0' ' ')
  case "$c/ $a" in "$PG"/*|*" $PG"/*|*"=$PG"/*) echo "$n $a";; esac; done; }
rp=$(sed -n 's/.*"pid": *\([0-9][0-9]*\).*/\1/p' "$PG/.stack/state.json" 2>/dev/null | head -n 1)
if [ -n "$rp" ] && [ "$(readlink "/proc/$rp/cwd" 2>/dev/null || true)" = "$PG/root" ]; then
  i=0; until aos-daemon-ctl -d "$PG/.stack" shutdown; do i=$((i+1)); [ $i -lt 30 ] || exit 1; sleep 2; done
fi
i=0; while [ -n "$(mine)" ]; do i=$((i+1)); [ $i -lt 30 ] || { echo "still running under $PG:"; mine; exit 1; }; sleep 1; done
# 1) back up the whole playground
cp -a "$PG" "$BAK" && echo "backup: $BAK"
cd "$PG"
# 2) the four copies (lib py templates knowledge) := the repo's; memory_read/memory_write use $AOS_HOME/knowledge = this copy
rm -rf lib py templates knowledge && cp -r "$R/lib" "$R/py" "$R/templates" "$R/knowledge" .
find lib py templates -name __pycache__ -prune -exec rm -rf {} +
rm -rf kb   # an older refresh's separate memory copy: not used any more
# 3) env.sh: AOS_HOME = the playground itself (definitions find lib/ templates/ knowledge/ through it)
grep -q '^export AOS_HOME=' env.sh || echo 'export AOS_HOME=$PG   # definitions use {"$env": "AOS_HOME", ...}: this playground' >> env.sh
# 4) llm kernel definition := the repo's, then put back this machine's stupid-fast model (gemma) from the backup
rm -rf llm_kernel/def && cp -r "$R/kernel/llm-kernel" llm_kernel/def
for k in model summary; do aos-json set "llm_kernel/def/kernel.json#/endpoints/stupid-fast/$k" "$(aos-json get "$BAK/llm_kernel/def/kernel.json#/endpoints/stupid-fast/$k")"; done
# 5) agents := fresh templates (eleven packs via $override; eca has no look/change/delete/shell packs); eca_bob back to haiku and 0.2 USD
for a in fsm_ann fsm_b fsm_c; do [ ! -d "agents/$a" ] || { rm -rf "agents/$a" && cp -r "$R/templates/agent-fsm" "agents/$a"; }; done
rm -rf agents/eca_bob && cp -r "$R/templates/eca-claude" agents/eca_bob
find agents -mindepth 2 -maxdepth 2 \( -name tests -o -name __pycache__ \) -exec rm -rf {} +
echo '{"model": "haiku"}' > agents/eca_bob/llm.json
aos-json set agents/eca_bob/cli.json#/print_flags/1 '"0.2"'
# 6) clear the images: the three stacks' runtime files (agents' history, mailboxes, brain settings set with llm set)
rm -rf .stack ws/.stack && find llm_kernel -mindepth 1 -maxdepth 1 ! -name def -exec rm -rf {} +
echo "refreshed: $PG (agents: $(command ls agents | tr '\n' ' '))"
)
```

刷新完起樹、問一題、停樹（照抄；起根放背景，不佔視窗）：

```sh
cd ~/code/playground && source env.sh && unset AOS_DAEMON
setsid nohup aos-exec root > root.log 2>&1 < /dev/null &                   # 起根（要前景看 log 就改成 aos-exec root、另開視窗二）
cd ws && aos-daemon-ctl -d "$PG/.stack" ping --timeout-s 30 && aos-daemon-ctl -d "$AOS_LLM_KERNEL" ping --timeout-s 30 && aos-daemon-ctl ping --timeout-s 30
aos-exec ../agents/fsm_ann && aos-agent ctl add --name eca_bob ../agents/eca_bob   # fsm_b、fsm_c 要的話照 fsm_ann
aos-agent llm --target fsm_ann set model=stupid-fast                         # 要 gemma 才打（定義照範本是假腦）
aos-agent say --target fsm_ann "what time is it?" && aos-agent listen --target fsm_ann --timeout-s 180
aos-agent tools --target fsm_ann ls -b                                       # 34 支；ls -l 的 FROM 欄＝哪一包
aos-daemon-ctl -d "$PG/.stack" shutdown                                      # 收工（不用 Ctrl-C）
```

## 每步在做什麼

| 步 | 做什麼 | 清掉／改掉什麼 |
|---|---|---|
| 開頭 | 認出是試驗場（有 `env.sh`、`root/daemon.json`）；備份名已存在就加 `-2`、`-3`，不覆蓋 | — |
| 0 停樹 | `.stack/state.json` 的 pid 還活著、而且它的 cwd 正是 `$PG/root`，才 `aos-daemon-ctl -d $PG/.stack shutdown`（`StillRunning` 會重試）；再等到沒有任何行程的 cwd 或參數在 `$PG/` 底下（殼不算），等 30 秒還有就印出來、停手 | 正在答的題作廢 |
| 1 備份 | `cp -a` 整份到 `~/code/playground.bak-<月日-時分>` | — |
| 2 四份複本 | `lib/ py/ templates/ knowledge/` 刪掉重抄 repo 版（從工作樹抄，含當下別隊還沒 commit 的改動）、清 `__pycache__`；舊版腳本建的 `kb/` 刪掉 | 舊 `knowledge/`（**記憶庫就是它**：memory_read／memory_write 指 `$AOS_HOME/knowledge`，員工寫進去的東西下次刷新會被換掉）、`kb/` |
| 3 env.sh | 沒有就加一行 `export AOS_HOME=$PG`（只加一次） | — |
| 4 總機 | `llm_kernel/def` 換 repo 的 `kernel/llm-kernel`，`stupid-fast` 的 `model`、`summary` 從備份抄回來（＝`google/gemma-4-e4b`） | 舊 kernel 定義 |
| 5 員工 | `fsm_ann fsm_b fsm_c`（在的才換）← `templates/agent-fsm`，`eca_bob` ← `templates/eca-claude`（工具照範本分包：`tools.json` 的 `$override` 一串 `lib/packs/*.json`；fsm 十一包 34 支、eca 不掛看／改／刪／殼四包 19 支）；eca_bob 改回 `{"model": "haiku"}`、`--max-budget-usd 0.2` | 舊定義（含舊 `agents` 登記、`agents.json`、`wall_clock`、`memory`） |
| 6 清 image | 刪 `.stack`、`ws/.stack`，`llm_kernel/` 只留 `def` | **全部員工的對話紀錄、信箱、覆蓋層（`llm set`、`tools add`）、子的帳、`kid_fsm_ann`、clock 登記表、總機帳本** |

要整個退回：停樹 → `rm -rf ~/code/playground && mv ~/code/playground.bak-<那次的名字> ~/code/playground`。

## 原件刷新（11-10 22:15，使用者「現在就刷新清空」）

刷新前先在一份新複本上照跑一次（過），再對原件跑。原件那時樹沒在跑（`state.json` 是 `stopped`，根 pid 17486 已不在；只有你的兩個 zsh 開在試驗場裡，腳本不碰殼）。

<details><summary>LM Studio context 不夠時的臨時作法（先關幾包來玩）</summary>

kernel 的 `stupid-fast` 寫 `context: 4096`，但真正算數的是 LM Studio 載入時設的長度（現在 71 936）。fsm 十一包的說明約 11 800 tokens，載入長度至少要開到 16k 左右才有空間放對話。使用者口徑是去調 LM Studio、不砍工具；想先用小 context 玩，就從這隻的定義拿掉幾包（例：只留小工具、自我管理、記憶三包，共 10 支；複本上實測 `aos-tools ls -b` 10 行）：

```sh
cd ~/code/playground && source env.sh
aos-json set agents/fsm_ann/tools.json#/\$override '[{"$env":"AOS_HOME","$path":"/lib/packs/gadgets.json"},{"$env":"AOS_HOME","$path":"/lib/packs/self.json"},{"$env":"AOS_HOME","$path":"/lib/packs/memory.json"}]'
```

下一題生效；要回全套就再刷新一次或照範本那串抄回來。

</details>

## 注意事項

- **名字以這台為準**：根表是 `llm_kernel`、`daemon`（[two-machines/15](../two-machines/15-回家那台開工.md) 寫的 `switchboard`／`foreman` 是公司那台）；根是 `root/`；員工 `fsm_ann fsm_b fsm_c eca_bob`；repo 在 `~/repo/simple_tools/aos`（不是 `~/repo/aos-tools`）。
- **`AOS_HOME` 兩種設法**：你的 `~/.zshrc` 設 repo 的 `proto8`；試驗場 `source env.sh` 後改成試驗場自己（用的是刷新那刻的複本，repo 施工中也不影響玩）。所以起根一定要先 `source env.sh`。
- **腦設定鍵是 `model`**：README 第 4 段的 `llm set endpoint=stupid-fast` 已過時，要打 `llm set model=stupid-fast`。刷新前四隻 stack 裡的 `{"endpoint": "stupid-fast"}` 會被清掉，要 gemma 就重打一次。
- **新工具都有**（第一版時）：範本 15 支（含 `self_state self_ctl mailbox_* clock_register agents_children agents_ctl agent_def`）＋這裡加的 `memory_write`；舊 `agents` 登記與 `agents.json` 隨定義換掉（現在是 `children.json`，預設配額 4）。gemma 帶 16 支工具照樣答得出來（kernel.json 寫 context 4096，這次沒撞到）。
- **記憶庫＝試驗場的 `knowledge/`**（tool-packs 起 memory_read／memory_write 指 `$AOS_HOME/knowledge`，節點路徑前面多一段 `aos/`）：員工寫的東西在這裡，**下次刷新會被換成 repo 版**；要留就先自己抄出來。第一版腳本的 `kb/` 不再用、刷新時刪掉。
- **試驗場 README 已跟上**（22:15 刷新時，改前那份在 backup 裡）：員工那段改成分包、第 0 段加一句指到本頁並註明舊相對路徑說法、第 4 段 `endpoint=`→`model=`、`wall_clock`→`peek_now_time`。

<details><summary>為什麼第 0 步要看 cwd，不直接 shutdown（複本的坑）</summary>

`cp -a` 一份正在跑的試驗場，複本的 `.stack/state.json` 帶著原件的 pid、`started_at_ticks`、`boot_id`，三樣跟 `/proc` 都對得上，`aos-daemon-ctl` 會把它當成活著的 daemon：對複本下 `ping`／`shutdown`，門鈴訊號其實送到原件那台（原件讀的是自己的 `ctl.json`，所以不會照做，但會被吵醒；複本那邊就一直等）。腳本只在 pid 的 cwd 正是 `$PG/root` 時才 shutdown，複本因此跳過；之後第 6 步把 stack 整份清掉，這些舊 pid 就沒了。跟 two-machines 的 B01（命令列絕對路徑原樣存表）是同一類：stack 是執行期的東西，搬或抄都要清。這次只記下來，沒改程式。

</details>

<details><summary>跟底稿比改了什麼</summary>

- 底稿 07 的 `echo '{"endpoint": "stupid-fast"}'` 過時（鍵改 `model`），這裡不寫進定義：fsm 定義照範本是假腦，要 gemma 用 `llm set`。
- 底稿 07 用 `--envs AOS_MEMORY=$PG/kb` 會把絕對路徑寫進 `tools.json`，搬家要重跑；這裡改寫指示詞 `{"$env": "AOS_HOME", "$path": "/kb"}`，搬家照樣對。
- 底稿每次 `rm -rf kb` 重抄，會把員工記下的東西清掉；這裡只在 `kb/` 不在時才抄。
- 加了：自己停樹（只認自己的根 pid）、等到沒有行程才動、備份名帶時分且不覆蓋、`fsm_b`、`fsm_c` 一起換、清範本帶來的 `tests/`、`__pycache__`。
- 照抄要能在互動 zsh 跑：全段包在 `( set -eu … )` 子殼裡（出錯只退子殼、不關你的終端機、`cd` 不帶出來），`cat`／`ls` 前面加 `command` 避開 `cat=bat`、`ls=eza` 的 alias，glob 只用一定對得到的。

</details>
