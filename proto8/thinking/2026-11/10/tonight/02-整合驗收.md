## 接縫

- **agents_children 轉手給子**：tools／llm／history／hook 四種都到子的覆蓋層；子的 hook（tool_before）真的收到 `wall_clock` 事件（`hooks/log.jsonl`）。
- **clock 叫醒**：ann（假腦）與 gemma 的 g4 都被叫醒；g4 每 5 格叫 wall_clock 答時間。
- **mailbox 互寄互讀**：ann↔bob（假腦）；ann（手叫 act）↔eb（haiku）：eb peek→read→`mailbox_send box=reply_to, in_reply_to` 回 DONE「6*7 = 42」，ann read 到。
- **agents_cmd 換字**：stop＝`{"op": "start", "name": "kid"} to carry on`、pause＝`{"op": "resume", …}`、sleep＝`{"op": "wake", …}`、rm 不 purge＝`to delete it: add it again under the same name, then rm with "purge": true`（照做一次：再 add 接回、rm purge 刪掉 stack，可行）、撞名＝`InstanceExists … give another "name", or remove that agent first with {"op": "rm", …}`，都觸發到。
- **act 附的 stderr 尾巴仍帶 CLI 寫法**（只記錄）：撞名那則 tool 結果後面照樣有 `aos-agent: error: InstanceExists …; pick another name (--name), or first aos-agent ctl rm bob`。
- **self_ctl 的句子**：`pause sent; ann pauses … until aos-agent ctl resume --target ann` 加 `(… someone runs aos-agent ctl resume …)`，講的是別人要做什麼，沒改。

## 沒修（列給隊長／使用者）

1. tooldef 總量 7.2k tokens，小模型 4096 context 裝不下；`self_tools ls` 一次 41 KB（每支附整份 tooldef）——要不要給 ls 一個不帶 tooldef 的短版，是方向題。
2. act 附給腦的 stderr 尾巴仍帶下層 CLI 句（C-52 例外，結構性）。
3. gemma 會抄 tooldef 例子的內容（mailbox_send 的 `what`），工具呼叫後常答空字串。
4. agents_children／agents_ctl 的 `ls` 一列約 400 字元 JSON（含 null 欄），小模型吃力。
5. 人刪掉 agent 時，它登記的 clock 項不會跟著消失（g4 刪了以後要人手 `aos-clock-register -c … rm`；clock-letters 已寫「不自動清」）。另：`aos-clock-register` 不收 `-d`（daemon），要給 `-c 時鐘檔`，跟 aos-agent／aos-mailbox 的習慣不同。
6. kernel 範本 `budget.senders` 有一格 `/tmp/aos-demo-sender`，每次起 kernel 印一行 warning。
