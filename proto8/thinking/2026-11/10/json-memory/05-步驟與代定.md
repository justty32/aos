| S3 | 最小可玩驗收：scratch `cp -r` 範本起一棵，fsm 假腦叫六個動作；gemma-4-e4b 真腦叫 read／find／add；eca 只驗登記與 aos-mcp 列得出、stdin 叫得動 | 結果寫進 06；小模型叫錯就改 `_tooldef.json` 的說明 | opus |
| S4 | 連帶：`memory_export`、`memory_sync`、文件、條文加註、附錄4、gitignore-check、其餘測試 | 相關測試過、wf-lint 不新增問題 | opus |

## 代定清單（可翻案）

| # | 代定 | 依據／翻案怎麼改 |
|---|---|---|
| D1 | 鎖整組拿掉 | 原話 4「不管，自行承擔風險」；要留＝從 git 找回 `locking.py` |
| D2 | 還是兩支工具（`memory` 唯讀、`memory_write` 寫），名字與 `{"op":"read"}`＝根 不變 | 範本、aos-mcp、eca 不用動；要合成一支＝改 tooldef 與登記 |
| D3 | 路徑帶副檔名（`rules.json`） | 原話 3 的寫法就是 `xxx/xxx.json#/…` |
| D4 | **使用者 11-10 翻案**：資料夾自己的簡介＝同資料夾的 `_description.json`；物件自己的簡介＝它的 `_description` key；`"."` 格不再有特別意思 | 原話 10「_index.json自己的簡介？那就是同資料夾下的_description.json啊」；S5 施工 |
| D5 | 表的格可帶 `$env`＝這格實際指到的路徑 | 規劃者補；原話 6 說 `$env` 可用，但 key 放不了指示詞 |
| D6 | **使用者 11-10 翻案**：讀寫都不限範圍，能不能寫看作業系統權限（不讓寫＝`WriteFailed`）；rm 庫的根仍是 `PathBad` | 原話 10「寫入這個沒差，想怎麽寫就怎麼寫，有權限就能動」；S5 施工 |
| D7 | 工具的 `path` 以 `/` 開頭＝檔案系統絕對路徑（單獨一個 `/` 仍是根） | 表裡指到庫外的東西才叫得到；小模型誤寫 `/me.json` 時錯誤訊息會提示改 `me.json` |
| D8 | 沒登記的檔／key：讀得到、ls 列在 `not in index:` | 原話沒答，最單純；`wf_kb` 這種 md 樹也因此還能用 |
| D9 | 陣列：只讀、不在裡面 add／rm、沒有表 | 原話沒答 |
| D10 | 拆檔後舊路徑：不轉址，要留路自己放 `$ref` | 原話沒答 |
| D11 | 非 JSON 枝葉 read 回原文；非 UTF-8 回一行大小 | 規劃者補 |
| D12 | 標籤從 `tags`／`_tags.json` 搬到表裡那格的 `tags` | 原話 4「其餘隨意」那格正好放；舊 `_tags.json` 不再認 |
| D13 | 小資料夾併成一份物件檔、`cli/` 留資料夾；單葉＝JSON 字串檔 | 兩種表（`_index.json`、`_index` key）都用到；要全資料夾或全單檔＝重跑轉換 |
| D14 | `edit` 改名 `set`；`TextBad`→`ValueBad`；`PointerMissing` 併進 `NodeMissing` | 跟 aos-json 用詞一致、代號更少 |
| D15 | aos-json 不加新子命令，`_index` 邏輯留 Python | 分層：下層不知道上層；也不跟另一隊搶 C++ build |
| D16 | `_description.json` 的內容是一個 JSON 字串 | 隊長代定：最單純；不是字串就當沒簡介、寫入給非字串＝`ValueBad` |
| D17 | 物件自己的簡介用 `_description` key（跟 `_index` 並排） | 頂層推論：使用者只講了資料夾那條，照它往物件推；只有 `_description` 沒 `_index` 的物件＝印簡介、空一行、其餘 key 的 JSON |
| D18 | 自己的簡介當普通路徑寫：`add`／`set`／`rm` 那條路徑，`value` 是字串、不帶 `description`（給了＝`ArgumentsBad`）、不進表；`add` 資料夾時的 `description` 照舊寫進上一層的表、不自動建 `_description.json` | 施工者代定：最單純，不多一個動作 |
| D19 | add 不給 value 時建空檔的旗標叫 `"create": true`；空內容：非 `.json` 檔＝空檔（0 byte），`.json` 檔與 `檔.json#/鍵`＝空字串 `""` | 施工者代定：最單純、read 印出來就是空的；要改成 `{}` 或 `null`＝改 `writing.no_value` |
| D20 | 不給 value、目標在、表裡**已經有**那格＝`NodeExists`（說用 set 換值或說明） | 施工者代定：跟「已存在＝NodeExists」一致；要改成「照樣成功、換說明」＝改 `writing.add` |
| D21 | 給了 value、目標已在（不論有沒有登記）＝`NodeExists` 照舊，訊息多一句「set 帶 description 也會補進表」 | 施工者代定：給了 value 就是要寫內容，不偷偷改成只補格；要改成「沒登記就照寫並補格」＝改 `writing.add` |
| D22 | `create` 跟 `value` 同給＝`ArgumentsBad`；`create` 不是 true／false＝`ArgumentsBad`；目標已在又帶 `create`＝只補指示牌（旗標沒作用）；開資料夾（`/` 結尾）與自己的簡介不看 `create`（簡介不給 value 仍是 `ValueBad`）；檔不在又沒帶旗標的錯誤代號用 `NodeMissing`，錯誤行附兩種補好的叫法（給 value、帶 `"create": true`） | 施工者代定；「檔不在＝報錯」本身是使用者原話 11「報錯」，不是代定 |

**11-12 使用者裁：D1～D22 結案（knowledge 將拿掉）**（[small-rulings](../../12/small-rulings.md)）
