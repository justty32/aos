使用者：「可以重新設計，可以用aos-json當基礎，配合檔案系統」（原話 7）、新增刪除工具一次做完兩處（原話 8「A」）。

## 兩支工具、名字不變

| 工具 | 動作 | 為什麼分兩支 |
|---|---|---|
| `lib/agent/memory` | `read`、`ls`、`find` | 範本只登記這支＝唯讀；`brain.py --memory`、`aos-mcp --memory` 開場叫 `{"op":"read"}` 拿根，這個約定不變，所以範本、aos-mcp、eca 都不用改 |
| `lib/agent/memory_write` | `add`、`set`、`rm` | 要寫的 agent 另外登記（照舊）；`edit` 改名 `set`（跟 aos-json 同一個詞） |

`path` 一律是 [02](02-格式規則.md) 的統一路徑，相對＝從庫的根算；空字串或 `/`＝根；`/` 開頭的其他寫法＝檔案系統絕對路徑。ls／find 印出來的每一行都是**可以直接貼回 `path` 的完整路徑**（小模型照抄就對）。

## 動作與例子

```text
{"op":"read"}                                  → 根：簡介（"." 那格）＋表
{"op":"read","path":"errors.json"}             → 有 _index 的物件：簡介＋表
{"op":"read","path":"errors.json#/codes"}      → 字串：原文照印（不加引號、\n 是真的換行）
{"op":"read","path":"cli/"}                    → 資料夾：簡介＋表
{"op":"ls","path":"cli/"}                      → 只印表
{"op":"find","query":"LockFailed"}             → 命中的路徑（最多 20 個）
{"op":"find","tag":"people","path":"notes/"}   → 表裡那格 tags 含 people 的

{"op":"add","path":"notes/amy.json","value":"Amy likes tea.","description":"Who Amy is"}
   → 寫 notes/amy.json，並在 notes/_index.json 加一格 "amy.json"
{"op":"add","path":"notes/amy.json#/phone","value":"0912","description":"Amy's phone"}
   → 在那個物件加 key phone，並在同一個物件的 _index 加一格（同一份檔、一次原子寫入）
{"op":"add","path":"notes/trips/","description":"Trips"}        → 開資料夾（帶空的 _index.json）
{"op":"set","path":"notes/amy.json","value":"Amy likes coffee."} → 換內容；可帶 description 一起換說明
{"op":"rm","path":"notes/amy.json"}            → 刪檔＋拔掉表裡那格
{"op":"rm","path":"notes/trips/","recursive":true}
```

read／ls 的輸出（純文字）：

```text
node: errors.json
How to read a failed call: the error line, warnings, exit codes.

children:
  errors.json#/codes  What each Code ending means.
  errors.json#/common  The Codes you meet most.
not in index:
  errors.json#/draft
```

- read 的值：字串＝原文；物件有 `_index`＝簡介＋表；物件沒 `_index`、陣列、數字等＝印 JSON；資料夾＝簡介＋表。超過 `max_bytes`（預設 8000）截斷並附 `[truncated: N more bytes]`。
- ls 只收枝幹（資料夾、物件、陣列）；對字串等＝`TargetBad`（說明裡寫「use read」）。
- find：`query`（不分大小寫的字串）比對路徑名、`_description`、字串內容；`tag` 比對表裡那格的 `tags` 字串陣列；兩個都給要同時符合。範圍＝`path` 底下的檔案樹＋表裡指到外面的格（照 02 規則 8 防繞圈）；不解內容裡的 `$ref`。
- add：位置已有東西＝`NodeExists`；上一層不在＝`NodeMissing`；`description` 必給（表才不會空）。`.json` 以外的副檔名＝`value` 要是字串、照原文寫。
- set：位置要已經在（否則 `NodeMissing`）。rm：資料夾不空要 `recursive: true`；根＝`PathBad`。
- **寫入只准寫在庫的根底下**（解開捷徑後）＝否則 `PathBad`；讀不限制。（規劃者補：原話「想指多遠就指多遠」講的是指示牌與逛；寫到庫外沒有原話依據，先保守。）

## 錯誤代號（C-54 結尾慣例，盡量沿用舊的）

`ArgumentsBad`、`OpUnknown`、`PathBad`（路徑或指標寫法不合、寫到庫外、rm 根）、`MemoryMissing`、`CfgBad`、`NodeMissing`（附上一層有哪些）、`NodeExists`、`ChildrenExist`（rm 不空的資料夾沒給 recursive）、`TargetBad`（對枝葉用 `#`／ls、在陣列裡 add／rm）、`FileBad`（`.json` 檔不是合法 JSON）、`ValueBad`（value 沒給、超過 8000 bytes、非 JSON 檔給了非字串；取代舊 `TextBad`）、`DirectiveBad`（`$ref` 讀不到、繞圈、`$env` 沒設；轉接 aos-json 的原因）、`ReadFailed`、`WriteFailed`、`LaunchFailed`（PATH 上沒有 aos-json）。拿掉：`LockFailed`、`TextBad`、`PointerMissing`（併進 `NodeMissing`：對腦來說都是「那裡沒東西」）。

## 同時寫：不加保護

使用者：「不管，自行承擔風險」（原話 4）。所以 **`memory_write` 的鎖整組拿掉**（`locking.py`、叫 `aos-lock`、`LockFailed`、`.lock/` 等 ignore 規則、「時鐘要同步」那些前提）。剩下的保證只有 aos-json 自己的：每份檔暫存後原子 rename，不會寫出半份檔。新增檔要動兩份檔（內容＋`_index.json`），中途死掉＝留下一個沒登記的檔，ls 的 `not in index:` 看得到。`aos-lock` 程式本身不動（別處還在用）。

## 哪些在 aos-json（C++）、哪些在 Python

- **用現成的 aos-json，不加新子命令**：讀一個位置（`get --follow --resolve`，`$ref`／`$env` 與繞圈都在這裡）、寫（`set`、同檔兩處用 `batch`、`del`）。理由：指標、指示詞、原子寫入、只改變的那一塊（git diff 小）它都做好了，這就是使用者說的「用aos-json當基礎」。
- **留在 Python（`lib/agent/memory_fs.py` 共用）**：統一路徑切開與跨檔案系統那一段、`_index`／`_description`／`"."` 的認法、兩處一起維護、find 逛樹、輸出排版與截斷。理由：`_index` 是記憶工具的慣例，aos-json 是下層、不該知道上層（單向分層）；find 一次要讀很多檔，逐檔起子行程太慢，所以 find 直接用 Python 讀 JSON（唯一例外）。
- 以後要下沉的候選（這輪不做）：「一條統一路徑跨多份檔走到底」做成 aos-json 的能力。
