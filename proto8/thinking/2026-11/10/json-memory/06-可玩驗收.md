# 06 可玩驗收（S3，11-10 晚家機）

← [json-memory](README.md)｜上一份 [05 步驟與代定](05-步驟與代定.md)

**一句話**：fsm（假腦、gemma-4-e4b 真腦）和 eca（haiku 真對話）上，memory 的 read／ls／find 和 memory_write 的 add／set／rm 都叫得動、結果對、磁碟上內容和 `_index` 兩邊都對。小模型最常卡在「add 沒給 description」和「資料夾還沒開」，這兩個改成錯誤訊息直接教它下一步怎麼叫，現在都能自己接回去。find 每筆後面多印命中的那一行，DaemonMissing 那題從「答得很籠統」變成每次都答對。

全部在 scratch 做（`AOS_HOME`＝這份 repo 的 proto8；llms／something／kb 都是 `cp -r` 出來的），沒碰 `~/code/playground*`。

## 1. fsm＋假腦（劇本）

- 起法：`cp -r` kernel/llm-kernel、daemon-root、agent-fsm，知識庫 `cp -r knowledge/aos kb`。定義的 `tools.json` 裡 memory 那格的 `AOS_MEMORY` 改成 kb 的絕對路徑，再加一格 memory_write（同一個 `AOS_MEMORY`）。kernel.json 加一包 `llm_fake`＋`script`，依序叫下面 12 個動作。
- 結果 **全過**：read 根、read `errors.json#/codes`、ls `cli/`、find `DaemonMissing`、add `notes/`、add `notes/amy.json`、add `notes/people.json`（值 `{}`）、add `notes/people.json#/bob`、set（連 description 一起換）、rm key、rm 檔、read `notes/`。history.jsonl 的 tool 訊息都是 `node: … / added|set|removed`；另外直接用 `aos-tools call` 一步一步看了磁碟：`notes/_index.json` 跟著加格、換說明、拔格，`people.json` 的 `_index.bob` 跟 key 一起進、一起出，`rm notes/ recursive` 之後根 `_index.json` 那格也拔掉了；出廠 `knowledge/aos` 沒被動到。
- 開場 system prompt：`think/request.json` 第一則 system 有 `Knowledge base root (from tool memory…)`、根的一頁簡介和 `children:` 表（加了 `notes/` 之後也列出來）。
- 給 agent 加 memory_write，三種做法都跑通：①手改定義的 `tools.json`；②`aos-agent -t 名 tools add [--replace] -n memory_write --envs AOS_MEMORY=… --path-json '{"$env":"AOS_HOME","$path":"/lib/agent/memory_write"}'`（寫進 stack 的覆蓋層；memory 那格同樣用 `--replace` 指到可寫的庫）；③腦自己叫 `self_tools {"op":"add","name":"memory_write","path":"…","envs":{"AOS_MEMORY":"…"}}`，下一步就能 add。

## 2. fsm＋真腦 gemma-4-e4b（LM Studio 開著）

每輪 3 次，每次一隻新 agent、一份新的庫。「Amy」是同一隻連問 5 句（記住、問、改成咖啡、忘掉、再問）。

| 題 | 改之前（B 輪） | 改之後（C 輪） | 再改之後（D 輪） |
|---|---|---|---|
| Missing 是什麼意思 | 3/3 | 3/3（find 一次就答） | 3/3 |
| DaemonMissing 是什麼 | find 3/3，但都去 read 籠統那頁，**答出確切意思 0/3** | **3/3** | 3/3 |
| 記住 Amy likes tea：最後存進去 | 3/3（花 8、5、6 次叫） | 3/3（4、4、6 次） | 3/3（6、4、5 次） |
| 　第一次就叫對 | 0/3（沒給 description，接著撞 `NodeMissing notes`） | 0/3 | 0/3 |
| 問 Amy／改咖啡／忘掉／再問 | 各 3/3 | 各 3/3 | 各 3/3 |

- 「第一次就叫對」一直是 0/9：gemma 第一下幾乎都照 schema 的 `required`（只有 op、path）叫，不給 description。錯誤訊息現在直接附「補好的那一次叫法」，它下一次就補上；接著 `NodeMissing` 教它先開 `notes/`，再一次就成。
- 其他看到的：資料夾帶 `"value": null` 或 `""`（B、D 各一次，現在當作沒給）；把 JSON 寫成字串（`"\"likes\": \"tea\""`，B 一次；說明加了「不要把 JSON 塞進字串」之後沒再看到）；多開一層沒用的 `notes/people/`（B 一次，無害）。
- 路徑都有帶副檔名，沒看到寫成 `notes/amy` 或 `/notes/...`。

## 3. eca

- **不燒額度那段，全過**：`cp -r` eca-claude，`aos-tools ls` 列得出 memory（解得開 `$env AOS_HOME`），`aos-tools call memory '{…}'` 和從 stdin 餵都回得來。`aos-mcp --memory memory tools.json` 手寫 JSON-RPC：`initialize` 的 `instructions` 有根（2977 字，含 `children:`）；`tools/list` 有 memory，schema 是 op（enum read／ls／find）、path、query、tag、max_bytes，`readOnlyHint: true`；`tools/call` read `cli/flags.json` 回內容、讀不在的回 `isError` 加那行錯誤。在定義裡用 `aos-tools add` 換成可寫的庫、加上 memory_write 後，`tools/call` add 資料夾、add 檔、read 都對。
- **真對話（haiku）**：一隻 eca，6 題各叫一次，**全部第一次就叫對**：read `cli/flags.json`、ls `cli/`、find `DaemonMissing`（答對確切意思）、記住 Amy（自己先 find、讀 `memory.json`，先開 `notes/` 再 add 檔，都帶 description）、改咖啡（先 read 再 set）、忘掉（rm）。磁碟上 `notes/_index.json` 最後是 `{}`，根表有 `notes/`。

## 改了什麼

| 檔 | 改了什麼 |
|---|---|
| `lib/agent/memory/_entry` | find 命中在內文時，那筆後面附 `[match: 命中那一行]`（最多 160 字） |
| `lib/agent/memory_fs.py` | `NodeMissing` 少寫 `.json` 時猜一個真的在的寫法：`me/self_tools` → `(did you mean me.json#/self_tools? …)` |
| `lib/agent/memory_write/_entry` | add 沒給 description：錯誤訊息附補好的那一次叫法 |
| `lib/agent/memory_write/writing.py` | add 時資料夾不在＝`NodeMissing` 後面教「先叫 `{"op":"add","path":"notes/","description":"…"}`」；add `檔.json#/key` 而檔不在＝教先用 `value {}` 開檔；資料夾的 `value` 是 null 或 `""` 當作沒給 |
| 兩支 `_tooldef.json` | memory_write：先講「add 一定要 path、value、description」，例子先開資料夾再加檔、不要把 JSON 塞進字串；memory：find 說明加 `[match: …]` 怎麼用 |
| `knowledge/aos/memory.json` | add 前面多一條「資料夾沒列出來就先開」的例子、純文字給字串 |
| `knowledge/aos/_index.json` | 根簡介最後加兩句：怎麼 find、寫之前先讀 `memory.json` |
| memory、memory_write 的 tests、memory/README | 跟著補（命中那行、猜副檔名、先開資料夾／檔、null 值） |

「`notes/` 不在就撞 `NodeMissing`」的解法：**不自動開資料夾**，讓錯誤訊息直接教下一步（最單純、不多藏行為）。
