## fsm 怎麼玩 memory（照抄）

```sh
export AOS_HOME=~/repo/simple_tools/aos/proto8
for v in $(env | grep -oE '^(CLAUDE[A-Z_]*|AI_AGENT)=' | tr -d =); do unset $v; done   # 起 eca 才需要，順手
mkdir -p ~/play && cd ~/play && mkdir -p llms something
cp -r $AOS_HOME/kernel/llm-kernel llms/def
aos-json set --str 'llms/def/kernel.json#/endpoints/stupid-fast/model' google/gemma-4-e4b   # 家機 LM Studio 的模型
cp -r $AOS_HOME/templates/daemon-root something/defs
cp -r $AOS_HOME/templates/agent-fsm something/defs/ann
cp -r $AOS_HOME/knowledge/aos kb                        # 可寫的庫（出廠那份不要寫）
KB=$PWD/kb
cd something/defs/ann
aos-tools add --replace -n memory --envs AOS_MEMORY=$KB --path-json '{"$env":"AOS_HOME","$path":"/lib/agent/memory"}'
aos-tools add -n memory_write --envs AOS_MEMORY=$KB --path-json '{"$env":"AOS_HOME","$path":"/lib/agent/memory_write"}'
echo '{"model": "stupid-fast"}' > llm.json              # 不寫＝假腦
cd ~/play
(cd llms && aos-exec --stack stacks/llm def &)
cd something && (aos-exec --stack stacks/root defs > ../root.log 2>&1 &)
aos-agent -d stacks/root ctl add -w . defs/ann
aos-agent -d stacks/root -t ann say "Remember that Amy likes tea." && aos-agent -d stacks/root -t ann listen
aos-agent -d stacks/root -t ann say "What do you know about Amy?" && aos-agent -d stacks/root -t ann listen
cat ~/play/kb/notes/_index.json ~/play/kb/notes/amy.json  # 磁碟上看結果；叫了什麼看 stacks/root/procs/ann/history.jsonl
# 收工
aos-daemon-ctl -d stacks/root shutdown && aos-daemon-ctl -d ../llms/stacks/llm shutdown
```

已經在跑的那隻不想動定義：把上面兩行 `aos-tools add` 換成 `aos-agent -d stacks/root -t ann tools add …`（同樣的旗標），寫進它 stack 的覆蓋層，下一題生效。

## eca 怎麼玩 memory（照抄，haiku）

接在上面那棵（根和 llms 開著；eca 的腦是 claude 自己、不走 llms）。**起根的那個殼要先拿掉 `CLAUDE*`**（上面第二行），不然 daemon 底下的 claude 會跟你自己的 Claude Code 混在一起。

```sh
cd ~/play/something && mkdir -p ecaws
cp -r $AOS_HOME/templates/eca-claude defs/eb
echo '{"model": "haiku"}' > defs/eb/llm.json
cd defs/eb
aos-tools add --replace -n memory --envs AOS_MEMORY=$KB --path-json '{"$env":"AOS_HOME","$path":"/lib/agent/memory"}'
aos-tools add -n memory_write --envs AOS_MEMORY=$KB --path-json '{"$env":"AOS_HOME","$path":"/lib/agent/memory_write"}'
cd ../..
aos-agent -d stacks/root ctl add -n eb -w ecaws defs/eb
aos-agent -d stacks/root -t eb say "Remember in the memory that Amy likes tea." && aos-agent -d stacks/root -t eb listen
aos-agent -d stacks/root -t eb say "Search the memory for DaemonMissing and tell me in one sentence what it means." && aos-agent -d stacks/root -t eb listen
# 叫了哪些工具：stacks/root/procs/eb/claude/live.jsonl 裡的 tool_use（名字是 mcp__aos__memory、mcp__aos__memory_write）
aos-agent -d stacks/root ctl rm eb
```

## 試驗場 `~/code/playground` 怎麼刷新（照抄；這次沒執行）

現況：`lib/`、`py/`、`templates/`、`knowledge/` 是 repo 的舊複本（`knowledge/aos` 還是 md 版），`llm_kernel/def` 是舊 kernel 範本，`agents/fsm_ann`、`eca_bob`（另有 `fsm_b`、`fsm_c`，README 沒寫）是舊範本、用 `../../lib` 相對路徑和 `tools/memory` 包裝夾；`env.sh` 沒有 `AOS_HOME`。新範本用 `$AOS_HOME/lib/…`、`$AOS_HOME/knowledge/aos` 找東西，所以讓 `AOS_HOME` 指試驗場自己，四份複本就照舊有用（repo 施工中也不影響你玩）。

```sh
# 0) 先在根視窗 Ctrl-C，等它退出（pgrep -af code/playground 沒有 aos- 行程再往下）
cd ~/code/playground
R=~/repo/simple_tools/aos/proto8
# 1) 四份複本換新
rm -rf lib py templates knowledge && cp -r $R/lib $R/py $R/templates $R/knowledge .
# 2) env.sh 加 AOS_HOME＝試驗場自己（加一次就好）
grep -q '^export AOS_HOME=' env.sh || echo 'export AOS_HOME=$PG' >> env.sh
# 3) 總機定義換新，stupid-fast 換成這台的模型
rm -rf llm_kernel/def && cp -r $R/kernel/llm-kernel llm_kernel/def
aos-json set --str 'llm_kernel/def/kernel.json#/endpoints/stupid-fast/model' google/gemma-4-e4b
# 4) 兩隻員工換新（fsm_b、fsm_c 要的話照 fsm_ann 那行）
rm -rf agents/fsm_ann agents/eca_bob
cp -r $R/templates/agent-fsm agents/fsm_ann && cp -r $R/templates/eca-claude agents/eca_bob && rm -rf agents/*/tests
echo '{"model": "haiku"}' > agents/eca_bob/llm.json
aos-json set --str 'agents/eca_bob/cli.json#/print_flags/1' 0.2
# 5) 可寫的庫，兩隻都換成讀寫它
rm -rf kb && cp -r $R/knowledge/aos kb
source env.sh
for a in fsm_ann eca_bob; do (cd agents/$a &&
  aos-tools add --replace -n memory --envs AOS_MEMORY=$PG/kb --path-json '{"$env":"AOS_HOME","$path":"/lib/agent/memory"}' &&
  aos-tools add -n memory_write --envs AOS_MEMORY=$PG/kb --path-json '{"$env":"AOS_HOME","$path":"/lib/agent/memory_write"}'); done
# 6) 清 image（舊員工的 stack 是舊程式寫的；會清掉對話，先自己備份）
rm -rf .stack ws/.stack && find llm_kernel -mindepth 1 -maxdepth 1 ! -name def -exec rm -rf {} +
# 之後照試驗場 README 第 1～3 段起樹、掛員工
```

注意：`$PG/kb` 在第 5 步就展開成絕對路徑寫進 `tools.json`，試驗場搬家後要重跑第 5 步的迴圈。試驗場 README 第 0 段（「定義用相對路徑 `../../lib`」那些）是舊說法，這次沒改它。
