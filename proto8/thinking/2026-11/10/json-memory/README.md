## 決定

- 記憶庫＝資料夾＋`.json`，整棵當一棵樹。統一路徑寫成 `資料夾/檔.json#/JSON Pointer`（RFC 6901；使用者說「我忘記啥標準了」指的就是它，名字是頂層補的）。`#` 這條界線讓 agent 看見。
- 枝幹都是 JSON；枝葉可以是任何東西（其他檔）。
- 資料夾的表＝`_index.json`，**整個檔就是表**：`{"rules.json": {...}, ...}`，path 以這個檔所在的資料夾為基準。JSON 內部的表＝`_index` 這個 key，value 是 object，path 以這個 key 所在的 object 為基準。例：`{"_index": {"motto": {"_description": "…"}}, "motto": "data of motto"}`。
- 表裡每一格是 `"path": xxx`，xxx 可以是任何東西；是 object 而且有 `_description` → 記憶工具就知道這個 path 在幹嘛。內容放在 path 指到的地方（跟指示詞 `$ref` 一樣的做法）；那格 object 裡可以隨意放別的東西，但通常不會。
- path 想指多遠就指多遠，只要有權限；指示詞 `$ref`、`$env` 都能用；嵌套迴圈由工具自己檢測。
- 同時寫互蓋：不管，自行承擔風險。
- agent 的記憶工具可以重新設計，以 aos-json 為基礎、配合檔案系統。
- `_index` 由工具維護：新增一次做完兩處（內容＋指示牌），刪除也一起拔指示牌。
- 出廠 `knowledge/aos` 直接轉成新形狀，不並存。
- 給人改的工具之後再做，現在只考慮 agent。`.md` 的文字只是字串，可以放進 JSON。
- add 的 `description` 必給，工具不自動補。
- 寫入不限範圍：想寫哪就寫哪，有權限就能動（翻掉代定 D6「寫入只准在庫的根底下」）。
- 資料夾自己的簡介＝同資料夾下的 `_description.json`（翻掉代定 D4 的 `"."` 格）。
- 就兩支工具（`memory`、`memory_write`）。
- add 可以不給 value（原話 11）：目標已在＝只補指示牌、內容不動；不在＝報錯、什麼都不寫；帶旗標才建空檔。旗標名與空內容等細節是代定 D19～D22（[05](05-步驟與代定.md#代定清單可翻案)）。

## 沒回答的

照使用者通則不追問、不列待辦，留在這裡，實作時想起來：

- 目錄印什麼（實際上 `_description` 已經涵蓋）。
- 陣列當路徑不穩。
- 資料夾裡有檔、但 `_index.json` 沒列它時，工具怎麼辦。
- 拆檔後舊路徑失效。
