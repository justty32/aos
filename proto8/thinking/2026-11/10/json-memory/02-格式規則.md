# 02 格式規則（圖紙）

每條後面括號標出處：「原話 N」＝ [README](README.md) 使用者原話第 N 條；**規劃者補**＝原話沒涵蓋、照最單純做法代定，可翻案（總表在 [05](05-步驟與代定.md#代定清單可翻案)）。

## 一棵樹長這樣

```text
knowledge/aos/                 ← 庫的根（AOS_MEMORY 指的資料夾）
├─ _index.json                 ← 這個資料夾的表（整個檔就是表）
├─ rules.json                  ← 一個檔＝一個 JSON 值（這份是一段文字）
├─ errors.json                 ← 一個物件，裡面自己有 _index 這個 key
└─ cli/
   ├─ _index.json
   └─ flags.json
```

```json
// knowledge/aos/_index.json
{".":           {"_description": "aos in one page …"},
 "rules.json":  {"_description": "Things you must never do."},
 "errors.json": {"_description": "How to read a failed call."},
 "cli/":        {"_description": "Commands for people and outside agents."}}

// knowledge/aos/errors.json
{"_index": {".":      {"_description": "How to read a failed call: …"},
            "codes":  {"_description": "What each Code ending means."},
            "common": {"_description": "The Codes you meet most."}},
 "codes":  "# Code endings\n\n…",
 "common": "# Common codes\n\n…"}
```

## 規則

1. **統一路徑**＝`資料夾/檔.json#/JSON Pointer`（RFC 6901：`/` 分段、`~1`＝`/`、`~0`＝`~`）。第一個 `#` 就切，`#` 後面一定是 `/`。檔名照磁碟上的寫、**帶副檔名**（`rules.json`，不是舊的 `rules`）。（原話 3、4「可以看見」）
2. **枝幹都是 JSON，枝葉可以是任何東西**：資料夾、`.json` 檔、JSON 裡的物件是枝幹，可以再往下走；字串、數字、陣列、其他副檔名的檔是枝葉。（原話 4）
3. **資料夾的表＝`_index.json`，整個檔就是表**：`{"rules.json": {...}}`，裡面的 path 從這個檔所在的資料夾算。（原話 4、5）
4. **JSON 裡的表＝`_index` 這個 key**，值是物件，裡面的 path 從這個 key 所在的那個物件算：`{"_index": {"motto": {"_description": "…"}}, "motto": "data of motto"}`。（原話 4、5）
5. **表裡每一格是 `"path": 任何東西`**；是物件而且有 `_description`（字串）→ 工具知道這個 path 在幹嘛、列目錄時印這句。格裡其餘 key 隨意，工具不管（唯一認的另一個是 `tags`，見 03 的 find）。內容放在 path 指到的地方，不放格裡。（原話 4、5）
6. **path 想指多遠就指多遠**：隔壁（`rules.json`、`codes`）、往下（`cli/flags.json#/x`）、`../`、絕對路徑（`/` 開頭＝檔案系統絕對路徑）都行；能不能讀看作業系統權限，工具不另外擋。（原話 6）
7. **指示詞照用**（原話 5、6）：
   - 內容那格寫 `{"$ref": "別的檔.json#/位置"}`＝讀的時候換成指到的值（跟 aos 其他 JSON 同一套，交給 aos-json 解）。
   - **規劃者補**：key 是字串、放不了 `$env`，所以「表的那一格」可以帶 `$env`（可加 `$path`）：`"team": {"_description": "…", "$env": "TEAM_KB", "$path": "/notes.json"}`＝這格實際指到解出來的那條路徑（字串，照規則 6 的寫法，相對就從表的基準算）；`_description` 從原文讀。
8. **迴圈**（原話 6「自己要檢測嵌套迴圈」）：`$ref` 繞圈由 aos-json 報 `DirectiveBad`。工具自己逛樹（find、export）時記「走過的（實體檔, 位置）」，再遇到就跳過、不報錯；`$env` 格只跳一次、不連跳。
9. **規劃者補｜`"."` 這格＝這個地方自己**：表裡 key 寫 `"."`，它的 `_description` 是這個資料夾／物件自己的簡介，read 這個枝幹時印在表前面。根的一頁簡介就放這裡（腦開場拿到的還是原本那一頁）。
10. **規劃者補｜枝葉不是 JSON 檔**（`.md`、`.txt`、圖…）：read 回原文（UTF-8 文字，超過 `max_bytes` 截斷）；不是 UTF-8 回一行 `binary file, N bytes`；對它用 `#`＝`TargetBad`。
11. **規劃者補｜沒登記的東西**（原話沒答）：資料夾裡有檔、物件裡有 key，但表沒列——照樣讀得到（路徑就是路徑）；ls 把它們列在表後面的 `not in index:` 一段，沒有說明。`.` 與 `_` 開頭的檔不列。
12. **規劃者補｜陣列**（原話沒答）：照 RFC 6901 用數字讀（`#/items/0`）；陣列沒有表、工具不在陣列裡新增／刪除（`TargetBad`），要穩定的名字就用物件。
13. **規劃者補｜拆檔後舊路徑失效**（原話沒答）：不做轉址；搬走的人要留路，就在原位放一格 `$ref` 指過去（規則 7）。

## 沿用不變的

- 庫怎麼指：`AOS_MEMORY`（範本寫在 `tools.json` 那格的 `env`）或工具夾的 `_memory.json`，照舊。
- 出廠庫內容語言英文、外部語料照原文、節點名英文（C-42 續），照舊。
- 「一個節點 ≤ 2 KB」改讀成「**一段文字（一個字串值）≤ 2 KB**，撐大就拆成物件的幾個 key 或幾個檔」；工具一次寫入上限仍是 8000 bytes。
