## 改完後的一段白話

> aos-tools 管「工具通訊錄」（一份 JSON 檔）。`add 路徑` 記一個工具進去，`ls`／`get` 看有哪些，`rm` 拿掉，`call 名字 [JSON]` 叫一次。通訊錄可以寫一行 `override` 指向另一份，意思是「以那份為底，我這份只記差異」——每隻 agent 自己加減的工具就是這樣一份。工具要的環境變數可以直接記值（`--envs`），也可以記一個 env 檔的位置（`--env-file`），每次叫工具才去讀。

**照 C-85 檢查，這段話還裝不下的**：

| 裝不下的 | 能不能藏／一句講完 |
|---|---|
| 相對路徑跟著通訊錄檔走 | 一句講完；`add` 成功行會印出存了什麼 |
| `--path-json`（環境變數留到用時才解） | 用你自己的那句話就講完：shell 當場展開的直接打；要留到用時才解的給 JSON |
| 定義快取 | 藏起來了：在 stack 裡、不進 git；只剩 `--no-cache` 一個旗標要解釋 |
| 環境變數誰蓋誰（五層，見下） | 要一張小表；規則是「越靠近這次登記的越贏」，平常不用知道 |
| **`override` 指標會過期**（新增的） | 新冒出來的：定義搬了位置，stack 那份的指標就指不到。現在基準是每次從 daemon 表算、不存檔，沒有這個問題。見「要你選的」N2 |
| **`add --override` 旗標跟 `override` 這個 key 同字不同義**（新增的） | 見 N3 |
| 旗標位置、靠 cwd 猜檔 | 甲級照做後消失（[02](02-改法.md) 甲1～甲3） |

比第一輪推薦少掉的：`--overlay` 旗標整個消失（命令列只剩 `--file`）、兩種檔拿錯的問題消失（給哪一份都能用）。

## 三種檔的最小長相

登記檔（通訊錄）：

```json
{"tools": {
  "clock":  {"path": "tools/clock"},
  "search": {"path": {"$env": "AOS_PROTO8", "$path": "/lib/base/search"},
             "env": {"AOS_MEMORY": "/data/kb"},
             "env_file": "secrets/search.env"},
  "up":     {"path": "tools/up.py", "cache": false}
}}
```

覆蓋檔（兩種候選，N1 選）：

```json
{"override": "../../defs/bob/tools.json", "add": {"math": {"path": "../lib/math"}}, "rm": ["clock"]}
```

```json
{"override": "../../defs/bob/tools.json", "tools": {"math": {"path": "../lib/math"}, "clock": null}}
```

快取（`$AOS_STACK/tooldef_cache.json`，不進 git）：

```json
{"/home/u/proj/defs/bob/tools/up.py": {"stamp": "1794291482385532340-254", "tooldef": {"description": "uppercase"}}}
```

## Q4：覆蓋檔自己指向被覆蓋的檔

### 命令列

- **`--overlay` 拿掉，只剩 `--file F`**。F 有 `override` 就順著讀下去再疊回來；沒有就是一般登記檔。
- **`add`／`rm` 只寫你給的那份 F**，不碰它指向的任何一份。`ls`／`get`／`call` 看疊好的結果。
- `ls -l` 的 FROM 欄印每個工具來自哪一份（鏈上哪個檔的哪一格）。
- 建立覆蓋檔：新增子命令 `aos-tools --file 新檔 override 底檔`（寫入 `{"override": …}`；新檔已是覆蓋檔＝改指標；已是一般登記檔＝`RegistryBad`）。底檔的寫法跟 `add` 的路徑同一套：絕對存絕對、相對（從 cwd 算）存成相對新檔所在資料夾、`override --path-json JSON` 原樣存。（代定；也可以手寫或 `aos-json set`。）

```
改前  aos-tools --file defs/bob/tools.json --overlay stack/bob/tools.json add --name math lib/math
改後  aos-tools --file stack/bob/tools.json override defs/bob/tools.json        ← 只做一次
      aos-tools --file stack/bob/tools.json add --name math lib/math
      aos-tools --file stack/bob/tools.json ls -l
```

### `override` 的值

三種都收、每次用到才解、不寫回（照你的路徑原則）：

| 寫法 | 例 | 怎麼解 |
|---|---|---|
| 相對 | `"../../defs/bob/tools.json"` | 從覆蓋檔自己所在的資料夾算 |
| 絕對 | `"/home/u/proj/defs/bob/tools.json"` | 照字面 |
| 指示詞 | `{"$env": "PROJ", "$path": "/defs/bob/tools.json"}` | 每次讀檔時交給 aos-json 解 |

後果：stack 在專案外、兩台相對位置不同時，相對指標換台就斷（跟今天 daemon 表的問題同型）；那種擺法要用指示詞或絕對。斷了的報法見下。

### 鏈的邊緣（代定的報法）

| 狀況 | 報法 |
|---|---|
| 環狀（A→B→A，以真實路徑判） | `RegistryBad override chain loops: A -> B -> A` |
| 指到不存在的檔 | `PathMissing A#/override: B does not exist`（**跟現況不同**：現在「有覆蓋層時定義那份可以不在」；改後明寫的指標指不到就是錯） |
| 指到的不是 JSON 物件 | `RegistryBad B (from A#/override) must be a JSON object` |
| 指到 `{}` 或沒有 `tools` 的物件 | 當空的登記檔（跟現況「沒有 tools＝沒工具」一致） |
| 同一份檔同時有 `override` 與另一型的格（S1：有 `tools`；S2：有 `add`／`rm`） | `RegistryBad` |
| 舊格式覆蓋檔（有 `add`／`rm`、沒有 `override`） | `RegistryBad A has add / rm but no override`（不當成空登記檔吞掉） |
| 指示詞解不開（變數沒設） | `DirectiveBad A#/override: …`（aos-json 自己那行照樣在前） |
| 鏈上某一份壞 | 整份報錯、訊息帶是哪一份（「不猜不跳過」照舊） |
| `rm` 一個只在底檔有的名字 | 記在你給的那份（S1：進 `rm` 陣列；S2：寫 `null`） |
| 覆蓋檔記了要拿掉、但底檔已經沒有的名字 | 忽略（照現況） |

### 其餘形狀：沿用還是趁機改（N1，要你選）

- **S1 沿用 `add`／`rm`**：`{"override": …, "add": {…}, "rm": […]}`。改動最小；仍是兩種形狀的檔。
- **S2 併成一種**：`{"override": …, "tools": {"math": {…}, "clock": null}}`——通訊錄只有一種形狀，多一行 `override` 就是「以那份為底」，值寫 `null` 就是「拿掉」。一段白話更好講；`add`／`rm` 的寫入路徑也只剩一條。代價：`null` 是新寫法，手寫的人要知道。

兩種的命令列完全一樣（[05](05-help草稿-改裁後.md) 不受影響）。兩種檔照舊可以同名（stack 裡那份的位置仍由 `interfaces.json` 宣告的相對路徑決定）；拿錯不再是問題，因為給哪一份都能讀——給底檔就是直接看、直接改定義那份。

### 誰建立、怎麼找到「這隻 agent 的那份」

現況：沒人存指標。`aos-agent tools`、`brain.py`／`act.py`、`cli_session.py`、`shell_report` 各自從「定義資料夾＋宣告的相對路徑」「stack＋同一個相對路徑」算出兩份，一起交給 `aos-tools --file … --overlay …`。

改後（代定）：

- **找法一條**：`<stack>/<宣告路徑>` 在就用它，不在就用 `<定義>/<宣告路徑>`；只交一個 `--file`。五個呼叫者都改成這條（`lib/tool_io.py` 不碰登記檔，不用改）。
- **建立時機**：照舊是第一次 `aos-agent tools add／rm` 才建（「沒改過＝沒有這份檔＝就是定義那份」不變）；建的時候由 aos-agent 叫 `aos-tools --file <stack 那份> override <定義那份>`。`tools reset`＝刪掉 stack 那份，照舊。
- 定義宣告了 tools 但那份檔不存在時：沒有東西可覆蓋，stack 那份建成一般登記檔（沒有 `override`）。
- copy-out、`agents` 工具（複製定義）不建覆蓋檔，不受影響。
- aos-mcp：拿掉 `--overlay`，照舊收 `REGISTRY`（給它 stack 那份或定義那份都行）。

**新冒出的後果（要你看，N2）**：定義的位置現在有兩處記著——daemon 表與 stack 裡這行 `override`。定義搬了、或整個 stack 被 cp 去配另一個定義，這行不會跟著變：指不到會報 `PathMissing`；**指得到但指的是舊的那份時不會報錯**，agent 會安靜地用舊定義的工具。代定的補救：`aos-agent tools` 與每次讀取時，aos-agent 這一層比對「指標解出來的檔」是不是 daemon 表上定義的那份，不是就印一行 warning。自動寫進去的指標用哪種寫法由 N2 決定。

### 通用機制的苗頭（只點出，不展開）

「一份檔寫 `override` 指向底檔、自己只記差異」跟 `llm.json` 在 stack 裡「只放改過的鍵」是同一個模式；登記檔既有的 `{"tools": {"$ref": [甲, 乙]}}`（拆成幾份再合）也只差「能拿掉」。之後可能收成 aos-json 層的一個通用疊法；這次只做 tools。

## Q1：env 只記檔案位置

- **登記格多一個選填 key `env_file`**：`{"path": …, "env": {…}, "env_file": "secrets/search.env"}`。一格一個檔。
- **`add --env-file FILE` 改成只記位置**：寫法跟 `path` 同一套——絕對存絕對；相對（從 cwd 算）存成相對「寫進的那份檔」的資料夾。要留到用時才解的指示詞，照你 Q3 的原則手寫（`aos-json set 檔#/tools/名/env_file '{"$env":…}'`），不另加旗標（代定）。
- **什麼時候讀**：只有 `call`。`ls`／`get` 不讀（所以 env 檔不在不會讓清單壞掉），照舊不印值；`ls -l` 的 ENV 欄印 `env` 的變數名與 env 檔的位置。
- **檔裡的 `${VAR}`**：改成 call 當下展開，看得到的是那次呼叫的環境（11-06 的「在命令列這個階段展開」是針對登記當下抄內容的做法；改成用時才讀之後，展開時點跟著移到用時）。
- **`add` 當下**：檔在就讀一次，只為了驗格式與做「工具宣告的變數有沒有著落」的提醒，不存內容；檔不在＝印 warning 照樣登記（另一台還沒放金鑰檔是常態；代定）。
- **`call` 時檔不在**：N4，要你選（報錯不跑／warning 照跑）。格式壞一律 `DotenvBad`、不跑。
- **誰蓋誰（後面的贏）**：

  | 順序 | 來源 |
  |---|---|
  | 1 | 工具資料夾自己的 `.env`（aos-exec 讀；只補沒設的，不蓋別人） |
  | 2 | 呼叫者的環境 |
  | 3 | `env_file` 的內容 |
  | 4 | `env`（`--envs K=V` 記的值） |
  | 5 | `AOS_STACK`（工具的小格，誰都蓋不掉） |

  3 蓋 2、4 蓋 3 是現況的延續（現在就是「檔案先、envs 後」「登記的蓋過外面同名的」）。
- 覆蓋檔裡的登記格同樣可以有 `env_file`，相對路徑從覆蓋檔自己的資料夾算。

## Q2：快取搬到 stack

- **位置與檔名**：`$AOS_STACK/tooldef_cache.json`（呼叫 aos-tools 的那一層的 stack：agent 的身體就是這隻的 stack；`aos-agent tools`、aos-mcp 本來就會設 `AOS_STACK`）。一個檔，key 是工具解出來的絕對路徑。不放進 `tools/<名>/`——那是工具自己的小格，不混主人。
- **失效判準**：照舊是檔案修改時間（奈秒）＋大小；不符就重跑 `--tooldef` **並寫回**（寫的是 stack，不是定義資料夾，P-15 沒問題；現況因為快取在登記檔裡所以不能寫回）。先寫暫存再改名。
- **沒設 `AOS_STACK`、或那個資料夾不存在**：不用快取、每次重跑、不寫任何檔、不建資料夾。
- **快取檔壞掉**：當作沒有，重跑後整份重寫（它本來就可重建）。
- **gitignore**：`cmd/aos-agent/stack.gitignore` 加一行 `**/tooldef_cache.json`（key 是這台的絕對路徑、stamp 是這台的修改時間，進 git 只有雜訊）；`05-gitignore指南` 同步。
- **`--no-cache` 留著**：它說的是「這個工具的定義不能只看檔案有沒有變」（11-03 的理由：定義是它 import 的別的檔算出來的），是工具的性質，仍記在登記格 `"cache": false`。登記格的 `cache` 從此只收 `false`。

## 加法還是破壞

| 項 | 性質 | 舊檔怎麼辦（proto8 不寫遷移） |
|---|---|---|
| 登記格加 `env_file` | **加法**：舊登記檔照樣能讀 | 以前用 `--env-file` 登記的，值還留在 `env` 裡、照樣生效；金鑰若已進 git 要自己重登記並處理歷史 |
| `add --env-file` 行為（抄內容→記位置） | 命令列行為改變 | 無檔要重建 |
| 登記格 `cache` 只收 `false` | **破壞**：有 `cache` 物件的登記檔＝`RegistryBad` | 對可執行檔 `add` 過的登記檔：刪掉那格（`aos-json del 檔#/tools/名/cache`）或 `add --override` 重登記 |
| 新檔 `tooldef_cache.json` | 加法（新的 stack 內檔，可重建，不進 git） | — |
| 覆蓋檔要有 `override` | **破壞**：stack 裡現有的覆蓋檔（`{"add","rm"}`）全部不能讀 | 每隻改過工具的 agent：`aos-agent tools reset` 後重新 add／rm（或手動補一行 `override`；選 S2 還要改形狀） |
| 拿掉 `--overlay`（aos-tools、aos-mcp） | 命令列破壞 | 自己寫的腳本若用了 `--overlay` 要改 |
| 新子命令 `override` | 加法 | — |

附錄 4（持久檔）要改三列：登記檔、覆蓋檔、新增快取檔。

## 要你再選的（四題，推薦排第一）

**N1　覆蓋檔除了 `override` 那行，其餘怎麼寫？**
- A（推薦）併成一種形狀：`{"override": …, "tools": {"math": {…}, "clock": null}}`，`null`＝拿掉。後果：通訊錄只有一種檔，一段話講得完；手寫時要知道 `null` 的意思。
- B　沿用現在的：`{"override": …, "add": {…}, "rm": […]}`。後果：改動最小；仍有兩種形狀要解釋。

**N2　aos-agent 自動幫某隻建覆蓋檔時，`override` 指標寫哪一種？**
- A（推薦）跟你當初 `ctl add` 給定義的寫法走：給絕對就寫絕對、給 `$env` 就寫指示詞、給相對就寫成相對覆蓋檔。後果：你怎麼擺專案它就怎麼跟；定義搬家仍要自己 `tools reset` 或改這一行（指錯時 aos-agent 會提醒）。
- B　一律寫相對覆蓋檔。後果：最簡單；stack 與定義一起搬沒事，分開擺、兩台相對位置不同就斷。
- C　一律寫 `{"$env": "AOS_CD", …}`（跑起來時 aos 設的「定義資料夾」）。後果：永遠跟著 daemon 表、不會過期；但手動 `aos-tools --file` 看這份時要自己設那個變數，eca 那條路每層的 `AOS_CD` 不同、要另外處理。

**N3　`add --override`（撞名時蓋掉）跟 `override` 這個 key（指向底檔）同字不同義，要不要分開？**
- A（推薦）旗標改叫 `--replace`，key 照你說的叫 `override`。後果：一個字一個意思；`--override` 是你 10-28 定的字，連帶改 `aos-agent tools add --override` 與文件。
- B　都不動。後果：不用改；說明裡同一個字要講兩次。
- C　旗標不動，key 換字（例 `"base"`）。後果：跟你這次給的例子不同字。

**N4　叫工具時，登記的 env 檔不在，怎麼辦？**
- A（推薦）報錯不跑（`PathMissing`，訊息說是哪個工具、哪個檔）。後果：另一台忘了放金鑰檔會馬上知道；那個工具在放好之前叫不動。
- B　印 warning 照跑。後果：工具自己缺金鑰時才失敗，錯誤訊息是工具的、比較難看懂。
