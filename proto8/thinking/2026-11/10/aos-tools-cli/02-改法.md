# 改法

取捨的主要判準：改完之後「一段白話裝不下的東西」有沒有變少（使用者 11-10：「我們能用一段白話就將他的功能描述個大概嗎」）。怪點編號指 [01](01-怪在哪.md)。工量以一名施工員計，含測試與文件。

共通：`tools.json`／覆蓋層的 JSON 形狀、環境變數、lib 介面在甲、乙兩級都不變。proto8 不寫遷移、不留舊名提示。

## 甲：不動對外格式，只改命令列長相、說明、預設、輸出（今明可做，合計約半天到一天）

| 編號 | 改什麼 | 解哪點 |
|---|---|---|
| 甲1 | `--file`／`--overlay` 子命令前後都收 | 5 |
| 甲2 | 旗標寫在路徑後：訊息講對；修 usage 截斷 bug | 4 |
| 甲3 | 沒給 `--file` 且 `./tools.json` 不在：印一行提醒 | 6 |
| 甲4 | `add`／`rm` 成功行說出「存了什麼、寫進哪份檔」 | 2 |
| 甲5 | `ls -l` 長格式：來源、原樣路徑、env 名 | 2、11 |
| 甲6 | `call NAME [ARGS_JSON]` | 12 |
| 甲7 | 登記檔與覆蓋層拿錯報 `RegistryBad` | 7 |
| 甲8 | 指示詞解不開時說出是哪個工具 | 14 |
| 甲9 | help 重寫（先講做什麼、給例子、存法縮成兩句） | 整體 |

### 甲1　`--file`／`--overlay` 前後都收

```
改前  aos-tools ls --file tools.json          → FlagUnknown
改後  aos-tools ls --file tools.json          → 照列
      aos-tools --file tools.json ls          → 照舊可用
```

做法：各子命令的旗標表加上這兩個，前後都給且不同＝`ArgumentsBad`（比照 aos-agent 的 `-t`）。後果：現有呼叫者（brain.py、act.py、aos-mcp、aos-agent、shell_report 都寫在前面）不受影響。連帶：`bin/aos-tools`、tests、README。工量：小（一小時內）。

### 甲2　旗標寫在路徑後的訊息、usage 截斷

```
改前  aos-tools add defs/tools/hello --name x9
      aos-tools: error: ArgumentsBad add needs one XXX (or --path-json JSON) (usage: … add [--override] [--name N] [--no-cache])
改後  aos-tools: error: ArgumentsBad flags go before PATH: --name (usage: aos-tools add [--name N] [--override] [--envs K=V]... PATH)
```

做法：位置參數超過一個且多出來的以 `-` 開頭時換這句；`usage()`（行 183-192）的續行判斷不要用 ` | ` 當停止條件。不放寬解析規則（「第一個非旗標後不再解析」是 aos_flags 全家規則，要改屬丙）。連帶：`bin/aos-tools`、tests。工量：小。

### 甲3　預設檔不在時提醒

```
改前  cd sub && aos-tools ls          →（空白，退 0）
改後  aos-tools: warning: ./tools.json not found; no tools (use --file F)        ← stderr，仍退 0
```

只在「沒給 `--file` 也沒給 `--overlay`」時印；程式呼叫者都明給 `--file`，不會多一行雜訊。`add` 在這種情況新開檔時，由甲4 的成功行說出來。連帶：`bin/aos-tools`、tests。工量：小。

### 甲4　成功行說出存了什麼

```
改前  added ov1 -> /tmp/…/proj/defs/tools/hello
改後  added ov1 -> /tmp/…/proj/defs/tools/hello (stack/tools.json: "../defs/tools/hello")
      removed hello (stack/tools.json)
```

第一段不變（`added NAME -> 絕對路徑`），後面加括號：寫進的檔與存進去的原樣值（指示詞就印那段 JSON）。後果：會看成功行的地方要核對——`lib/agent/self_tools/_entry`、`lib/agent/agents/_entry`、`cmd/aos-tools/tests/test_paths.py`（grep `added` 得到的三處；前兩個是轉印，預期只要改測試的比對）。工量：小到中。

### 甲5　`ls -l`

```
改後  $ aos-tools --file defs/tools.json --overlay stack/tools.json ls -l
      NAME   KIND  PATH                         FROM                         STORED                 ENV
      hello  dir   /…/proj/defs/tools/hello     defs/tools.json#/tools/hello "tools/hello"          -
      ov1    dir   /…/proj/defs/tools/hello     stack/tools.json#/add/ov1    "../defs/tools/hello"  AOS_MEMORY
```

`FROM` 用現成的 `field`（行 357）；`ENV` 只印變數名、不印值（維持「值不給腦看」）。不加進 `ls --json`（腦與 aos-mcp 吃那份，不動）。比照 `aos-agent ctl ls -l`。連帶：`bin/aos-tools`、tests、README。工量：小。

### 甲6　`call NAME [ARGS_JSON]`

```
改前  echo '{"who":"bob"}' | aos-tools call hello
改後  aos-tools call hello '{"who":"bob"}'        ← 多一種寫法；stdin 那種照舊
```

給了第二個參數就把它當成工具的 stdin 內容，原樣、不驗（跟 stdin 那條路一樣照字面）。沒給照舊讀 stdin。`.stack/` 留在 cwd 是 aos-exec 沒設 `AOS_STACK` 時的預設，不在這裡改，help 寫一句。連帶：`bin/aos-tools`（execve 前接一條 pipe 或暫存檔）、tests、README。工量：小。

### 甲7　兩種檔拿錯報錯

```
改前  aos-tools --file stack/tools.json ls        →（空白，退 0）
改後  aos-tools: error: RegistryBad stack/tools.json looks like an overlay (top-level add / rm); pass it with --overlay
      aos-tools: error: RegistryBad tools.json looks like a registry (top-level tools); pass it with --file      ← --overlay 給了登記檔
```

判法：`--file` 那份沒有 `tools`、卻有 `add` 或 `rm`；`--overlay` 那份有 `tools`。格式沒變，只是把本來安靜的錯說出來。連帶：`bin/aos-tools`、tests。工量：小。

### 甲8　指示詞解不開時說出工具名

```
改前  aos-tools: error: DirectiveBad tools.json#/tools: directives cannot be resolved (aos-json exited 1)
改後  aos-tools: error: DirectiveBad tool far3 (tools.json#/tools/far3/path): directives cannot be resolved …
```

做法：整格解失敗時，改成逐個工具解一次找出是誰（只在失敗路徑做）。仍然整份報錯（「不猜不跳過」不動）。工量：小。

### 甲9　help 重寫

草稿在 [03](03-help草稿.md)。原則：第一段講做什麼；給三四個照抄就能跑的例子；存法只留「相對路徑跟著通訊錄檔走」一句，細節指到 README；子命令 help 不再重列 `--file`／`--overlay` 的說明（只在 usage 行出現並指回頂層）；術語（registry、overlay、tooldef）在頂層各解釋一次。連帶：`bin/aos-tools`、`cmd/aos-tools/README.md`、`cmd/docs/01-逐支說明.md`、`knowledge/aos/cli/tools.md`。工量：中（文字為主）。

## 乙：動命令列相容性（改名、拿掉旗標），不動檔案格式（合計約半天到一天；Q1～Q4、Q6 選了才做）

### 乙1　拿掉 `add --env-file`（README Q1 選 A）

```
改前  aos-tools add --env-file hubs.env --envs AOS_MEMORY=/data/memory ../lib/base/read
改後  aos-tools add --envs AOS_MEMORY=/data/memory ../lib/base/read
      金鑰：寫在工具資料夾自己的 .env（每次 call 由 aos-exec 重讀；.gitignore 掉），或 export 在跑 agent 的環境
```

- 後果：金鑰不會再被抄進 `tools.json`；`.env` 改了下次 call 就生效；`read_env_file()`（行 449-517，約 70 行）整段可刪。`--envs K=V` 留著（全家寫法，11-05 已定），放位置類設定。登記檔的 `env` 格形狀不變。
- 這會翻掉 11-05「兩者並存」在 aos-tools 這一支的適用（aos-agent ctl add 等別支不受影響）與 11-07 #30「存內容」。
- 連帶：`bin/aos-tools`、tests、`cmd/aos-tools/README.md`、`cmd/docs/01-逐支說明.md`、`knowledge/aos/cli/tool_env.md`、`docs/CONVENTION/02-題目stack停錯腦/07-P-44.md` 第 13 行加註、`docs/NORMS/附錄4-持久檔.json`（提到 `--env-file` 的那列）。工量：小到中。
- 若選 Q1 的 B：不拿掉，`add` 用了 `--env-file` 時多印 `aos-tools: warning: copied N values from FILE into <檔> (KEYS…); do not commit secrets`，屬甲。

### 乙2　不再存快取、拿掉 `--no-cache`（README Q2 選 A）

```
改前  aos-tools add defs/tools/up.py        → tools.json 多一段 "cache": {"stamp": …, "tooldef": {…}}
      aos-tools add --no-cache defs/tools/up.py → "cache": false
改後  aos-tools add defs/tools/up.py        → {"path": "defs/tools/up.py"}，沒有 cache
```

- 後果：`tools.json` 每個工具只剩路徑（與 env）；兩台行為相同；`ls`／`get` 每次都跑各可執行檔的 `--tooldef`（每個多一次行程啟動，python 約幾十毫秒；逾時上限 10 秒照舊）。讀到舊檔裡的 `cache` 格：照「當沒有舊版」直接不認（或忽略），由施工員擇一並寫一句「要重建什麼」。
- 連帶：`bin/aos-tools`（`inspect()` 的快取分支、`stamp()`、行 565-566、581-582）、tests、`cmd/aos-agent/aos_agent/tools.py`（第 39、44、109、144 行的 `--no-cache`）、`cmd/aos-agent/README.md`、`cmd/docs/01-逐支說明.md`、`knowledge/aos/cli/tools.md`、`docs/NORMS/附錄4-持久檔`（登記檔那列）。工量：中。

### 乙3　`--path-env` 取代 `--path-json`（README Q3 選 A）

```
改前  aos-tools add --name bash --path-json '{"$env":"AOS_PROTO8","$path":"/lib/base/bash"}'
改後  aos-tools add --path-env AOS_PROTO8/lib/base/bash
      → 存 {"path": {"$env": "AOS_PROTO8", "$path": "/lib/base/bash"}}（跟現在一樣的形狀）
```

- 寫法：`VAR` 或 `VAR/子路徑`，第一個 `/` 前是變數名。名字照常從解出的路徑推，`--name` 可另取。
- 後果：不用打 JSON 與兩層引號；`$ref` 之類罕見寫法改用 `aos-json set 檔#/tools/名/path '…'` 手寫（登記檔本來就收）。
- 連帶：`bin/aos-tools`、`cmd/aos-tools/tests/test_paths.py`、`cmd/aos-tools/README.md`、`cmd/docs/01-逐支說明.md`、`cmd/aos-agent/docs/03-tools覆蓋層.md`、`cmd/aos-agent/docs/04-搬家/02-image保存與邊界.md`、`templates/docs/02-agent-fsm.md`、`knowledge/aos/cli/tools.md`。工量：小到中。

### 乙4　`aos-agent tools add` 跟 `aos-tools add` 同一種寫法、旗標補齊（README Q4 選 A）

```
改前  aos-agent tools -t bob add math ../lib/math
      （要 env／環境變數路徑：aos-tools --file <定義>/tools.json --overlay <stack>/tools.json add …）
改後  aos-agent tools -t bob add [--name math] [--override] [--envs K=V]... ../lib/math
      aos-agent tools -t bob add --path-env AOS_PROTO8/lib/base/bash
```

- 後果：人不用再知道定義與覆蓋層兩個路徑；`aos-tools --overlay` 只剩程式在用，help 一句帶過。
- 連帶：`cmd/aos-agent/aos_agent/tools.py`、`cmd/aos-agent/tests`、`lib/agent/self_tools/_entry`（給腦的工具：它的 JSON 參數 `name`＋`path` 可不變，內部改成 `--name`）、`lib/agent/agents/_entry`、`lib/agent/thought/_entry`（grep `tools add` 有中，需核對）、`cmd/aos-agent/docs/01、03、04-搬家/*`、`knowledge/aos/cli/{tool_env,flags}.md`、`templates/docs/01、02`、`docs/NORMS/…/09-N-67.md`、`docs/CONVENTION/…/07-P-44.md`。工量：中到大（文件多）。

### 乙5　佔位名（README Q6 選 A）

`add XXX` → `add PATH`；`rm XXX`／`get XXX` → `NAME_OR_PATH`。只動 help、錯誤訊息與文件用字。工量：小（併進甲9）。

## 丙：動檔案格式或概念，留大修

| 編號 | 題目 | 為什麼留 |
|---|---|---|
| 丙1 | 覆蓋層的檔名或形狀（跟登記檔同名不同形狀）；兩層要不要換成別的機制 | 動持久檔格式與 aos-agent、brain／act、cli_session 的讀法；甲7 先把拿錯變成報錯 |
| 丙2 | env「只記檔案位置、每次 call 才讀」（Q1 的 C） | 登記格要多一個 key |
| 丙3 | 快取搬到 stack（Q2 的 C） | 新的持久檔 |
| 丙4 | 通訊錄的預設來源（例：環境變數、往上層找） | 新環境變數或新找法，屬對外介面；甲3 先用提醒頂著 |
| 丙5 | 「旗標可以寫在位置參數後面」 | aos_flags／aos-util 全家規則（P-44） |
| 丙6 | 一個工具壞掉整份清單不能用（「不猜不跳過」）在兩台輪流下要不要鬆 | 你 10-28 定的原則；甲8 先讓訊息指出是誰 |
| 丙7 | 沒設 `AOS_STACK` 手動 `call` 會在 cwd 留 `.stack/` | aos-exec 的預設，不是 aos-tools 的事 |

## 建議的施工順序

1. 甲1～甲8（同一名施工員、同一個 commit 序列，只動 `cmd/aos-tools/`；等拔錨點那隊收工、或明確讓出 `bin/aos-tools` 之後再動，避免兩隊寫同一檔）。
2. 使用者答完六題後：乙1、乙2、乙3（都在 `bin/aos-tools`，一起做）→ 乙4（動 aos-agent 與一批文件）。
3. 甲9（help 與文件）最後寫，才能一次反映乙級的結果。
