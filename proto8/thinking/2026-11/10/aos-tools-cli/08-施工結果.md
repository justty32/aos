## 做成什麼樣（跟圖紙不同、或圖紙沒寫的）

1. **疊法＝照順序疊，後面蓋前面**：每個底檔先遞迴展開成它自己的序列，照 `$override` 陣列順序接起來，最後接本檔；一份一份補丁式往下合（物件逐 key 合，其餘整個蓋過去）。**合併沒有刪除，`null` 只是值**；讀的時候值是 `null` 的工具格不算工具、工具格裡 `null` 的欄位＝當沒設。被 `null` 蓋過的格之後再給物件＝從空的開始，不跟更早那份合（`null` 不是物件）。
2. **菱形**：同一份經兩條路被引到＝序列裡出現兩次、照樣疊（例 `[l, r]` 都 override `defs`＝序列 `defs, l, defs, r, 本檔`；第二次的 `defs` 會把 l 改過的同名欄位蓋回 defs 的值）。不算環。環以真實路徑判、只看往上那幾層（跟 `$ref` 同），訊息 `$override chain loops: A -> B -> A`。
3. **跟 `$ref` 陣列的差異**（已報、使用者照建議裁）：① `$ref` 只合一層，`$override` 一路往下合（同名工具格要能只改 `env` 而沿用底檔的 `path`）；② 空陣列：`$ref` 是「整個物件原封不動」，`$override: []`＝沒有底檔——對工具清單效果相同；③ 元素不是字串／指示詞：`$ref` 原封不動，這裡 `RegistryBad …#/$override/i must be a path…`（工具清單不猜不跳過）。
4. **`aos-json get --follow --resolve` 對含 `$override` 的檔**（06 第 6 條要的實測）：整份解時 `$override` 原封不動、但它裡面的 `{"$env": …}` 會被解掉；所以 aos-tools 只解 `#/tools` 那一格，`$override` 自己交 `aos-directive` 解。`aos-json set --follow` 會保留 `$override`。
5. **`rm`**：只有本檔記的名字＝刪 key（`removed 名 (F: key deleted)`）；底檔也有＝寫 `"名": null`（`removed 名 (F: set to null over 底檔)`）。`add --replace` 用 `null` 蓋過底檔那格有、這次沒給的欄位。
6. **`override` 子命令**：`override (BASE... | --path-json JSON)`；多個 BASE＝陣列；F 已有 `$override`＝只換指標（`tools` 照留）；F 有自己的工具卻沒有 `$override`＝`RegistryBad`；寫之前先照新指標讀一次（指不到、環、壞檔先報、不寫）。
7. **`ls -l` 的 FROM**＝寫那個 `path` 的那份檔（跟 STORED 一致）；ENV 欄＝`env` 的名字＋`@"存的 env_file"`。
8. **N2 指標**：daemon 表 `as_written.def` 是 `$env` 指示詞＝原樣接上宣告的 tools 路徑（`$path` 加 `/tools.json`）；`$ref`／`$prefix` 或只有字串＝相對 stack 那份。第一次 `tools add` 失敗時把剛建的那份收回（只有指標的檔不留）。
9. **ctl state 那行**：`own: N listed, M set to null (+名, null:名) over <$override 原樣值>`。
10. **預設檔不在的提醒**只在沒給 `--file` 時印；`add`／`override` 不印（成功行會說寫進哪份）。
11. 在含有解不開指示詞（變數沒設）的登記檔上 `add` 也會失敗（要先讀整份查撞名）——現行行為，沒改。
