## 第一輪結論（11-10 下午，答題前）

**現況的一段白話**（給不懂 aos 的人）：

> aos-tools 管一份「工具通訊錄」（`tools.json`）。`add 路徑` 把一個工具（資料夾、JSON 檔或可執行檔）記進去，`ls`／`get` 看有哪些，`rm` 拿掉，`call 名字` 叫一次（參數用 JSON 從 stdin 餵）。agent 每次要想事情前讀這份清單，要用工具時也經它叫。

**這段話裝不下、現在得另外解釋的東西（八樣，逐樣實測過，證據在 [01](01-怪在哪.md)）**：

1. **兩層**：通訊錄其實有「定義那份」＋「這隻自己加減的那份（覆蓋層）」，兩份都叫 `tools.json`、形狀不同、拿錯不報錯。
2. **路徑有三種長相**：你打的（相對 cwd）、存進檔的（相對「被寫的那份檔」）、印出來的（絕對）；要靠環境變數得手打一段 JSON（`--path-json`）。
3. **env 是登記當下抄一份**：`--env-file` 把檔案內容（含金鑰、已展開的 `${HOME}`）抄進 `tools.json`，之後改 `.env` 不生效。
4. **快取**：可執行檔的工具定義被塞進通訊錄（含檔案修改時間），另有 `--no-cache` 關掉它。
5. **旗標位置**：`--file`／`--overlay` 只能寫在子命令前；其他旗標只能寫在路徑前，寫後面報的錯還誤導。
6. **靠 cwd 猜通訊錄**：預設 `./tools.json`；站錯資料夾 `ls` 安靜印空白、`add` 安靜新開一份。
7. **`rm`／`get` 的參數「是名字、不然當路徑」**，`call` 又只收名字；按路徑 `rm` 會一次拿掉多筆。
8. **`call` 的周邊**：參數只能走 stdin、手動試一次會在 cwd 留 `.stack/`。

頂層猜的四個候選（兩層、相對於被寫的檔、env 固化、全域旗標在前）**都成立**；另外多出 4、6、7、8。真正讓 `add --help` 讀起來怪的是：**說明有一半在講「東西怎麼存」而不是「你要做什麼」**——10-28 的原設計是「站在 agent 資料夾裡、一份檔、存絕對路徑」，之後覆蓋層（11-05）、env（11-05）、`--no-cache`（11-03）、`--path-json`（11-10）各補一個旗標，每個都帶一條存法規則。

**照推薦做完之後的一段白話**：

> aos-tools 管一份「工具通訊錄」（`tools.json`）。`add 路徑` 記一個工具進去——路徑照你打的記，相對的就跟著通訊錄檔走，要靠環境變數就寫 `--path-env 變數/子路徑`；工具要的固定設定用 `--envs K=V` 記在旁邊。`ls`／`get` 看、`rm` 拿掉、`call 名字 [JSON]` 叫一次。agent 每次要想事情前讀這份清單。

**少掉的**：3（env 抄檔，拿掉 `--env-file`）、4（快取與 `--no-cache`）、5（`--file`／`--overlay` 前後都收、錯誤訊息講對）、6（預設檔不在會提醒、`add` 會說寫進哪份檔）、2 的大半（`add` 印出「存了什麼、存在哪」，環境變數不用手打 JSON）、8 的一半（`call` 可直接帶參數）。

**剩下、非留不可的**：

- **兩層**：是你 11-05 自己要的（「tools只存差異那塊可以先做，我直覺上這是好方法」），拿掉等於每隻 agent 抄一份定義。改後讓人只在 `aos-agent tools` 碰到它，`aos-tools` 的說明只留一句；兩份同名不同形狀改成拿錯會報錯。檔名／概念要不要合併留大修。
- **相對路徑跟著通訊錄檔走**：這是「git clone 到另一台、另一個位置還能跑」的根本，不能改成相對 cwd。但它能用一句話講完（上面那段已含）。
- **`rm`／`get` 收名字或路徑**：你 10-28 的原設計；留著，只把佔位名寫清楚。
- **`call` 從 stdin 收參數**：是工具契約（P-41），程式呼叫者都靠它；只多一個行內寫法給人用。

## 第一輪要使用者選的（六題；都已答，見上）

推薦都排第一個。Q1、Q2 是「新原則跟你先前裁定衝突」，一定要你看；其餘不選就照推薦。

**Q1　`--env-file` 把檔案內容抄進 tools.json（11-07 你裁過「存內容」），跟今天的「每次用到才解、不固化」「金鑰不該進 git」衝突，怎麼辦？**
實測：`.env` 裡的 `MY_KEY=sk-secret-123` 原樣進了 `tools.json`，`${HOME}/x` 變成 `/home/guanyu/x`。另實測：工具資料夾自己的 `.env` 本來就會在每次 `call` 時被 aos-exec 重讀，改了立刻生效。
- A（推薦）拿掉 `aos-tools add --env-file`，只留 `--envs K=V`（放不怕進 git 的位置設定）；金鑰放工具資料夾自己的 `.env`（gitignore）或行程環境。後果：少一個旗標、不會再把金鑰抄進 git；已用 `--env-file` 登記的要改放 `.env`。
- B　留著，但 `add` 當下印一行提醒「這些值已抄進 <檔>」，help 寫明別放金鑰。後果：不改行為，靠人注意。
- C　改成「只記檔案位置、每次 call 才讀」。後果：最貼近新原則，但要動登記檔格式，留大修。

**Q2　可執行檔工具的定義快取（10-28 你答「可以」、11-03 加 `--no-cache`）要不要拿掉？**
現況：快取連同檔案修改時間存在 `tools.json`；git clone 到另一台修改時間一定不同、又不寫回，所以快取只在登記那台有用，卻讓 `tools.json` 多一大段、多一個旗標。
- A（推薦）`add` 不再存快取、拿掉 `--no-cache`；每次列工具都跑一次各可執行檔的 `--tooldef`。後果：`tools.json` 每個工具只剩一行路徑、兩台行為一樣；代價是每次列清單每個可執行檔工具多幾十毫秒。
- B　維持現狀。後果：登記檔照舊含快取，help 照舊要解釋它。
- C　快取搬到 stack 裡。後果：兩邊都顧到，但要動格式，留大修。

**Q3　「路徑用環境變數」要怎麼打？**
- A（推薦）`aos-tools add --path-env AOS_PROTO8/lib/base/bash`，取代 `--path-json`。後果：不用手打 JSON 與引號；罕見的其他指示詞改用 `aos-json set` 手寫。
- B　直接認 `aos-tools add '$AOS_PROTO8/lib/base/bash'`。後果：最順手，但違反「給的值照字面用」（10-16），真有 `$` 開頭的路徑會被誤判。
- C　維持 `--path-json '{"$env":…}'`。

**Q4　「定義那份＋這隻自己的差異」這兩層，要讓人在哪裡碰到？**
- A（推薦）人只用 `aos-agent tools`（補上 `--name`／`--envs`／`--path-env`，`add` 的寫法改成跟 `aos-tools add` 一樣）；`aos-tools --overlay` 留給程式用，說明只留一句。後果：`aos-agent tools add 名 路徑` 改成 `aos-agent tools add [--name 名] 路徑`，連帶改 self_tools 等呼叫處。
- B　兩支都維持完整功能、寫法各自照舊。後果：設工具 env 仍得自己拼 `aos-tools --file <定義> --overlay <stack> add …`。
- C　大修時把覆蓋層改名或併進別的機制。後果：現在不動。

**Q5　乙級（改旗標）什麼時候做？**
- A（推薦）甲今明做完，乙緊接著做（拔錨點那隊收工後，約半天到一天）。後果：趁你還沒在兩台大量用之前把旗標定下來，之後不用改手感與腳本。
- B　只做甲，乙丙一起留大修。後果：風險最小；但 `--env-file` 抄金鑰的坑在這段期間還在（至少配 Q1 的 B 提醒）。

**Q6　說明裡的佔位名 `XXX`（你 10-28 的用語，aos-exec 也用）要不要換？**
- A（推薦）`add` 寫 `PATH`、`rm`／`get` 寫 `NAME_OR_PATH`（aos-agent tools 已經這樣寫）。後果：一眼看出三個子命令收的東西不一樣；跟 aos-exec 的 `XXX` 不同字。
- B　留 `XXX`。後果：跟 aos-exec 一致，但同一個 `XXX` 在 add 是路徑、在 rm／get 是名字或路徑。

## 我代定的（實作細節，可翻案）

`--file`／`--overlay` 子命令前後都收；預設 `./tools.json` 不在時印一行提醒；`add` 成功行加「存了什麼、寫進哪份檔」；`ls -l` 長格式（來源、原樣路徑、env 名）；`call NAME [JSON]`；登記檔與覆蓋層拿錯報 `RegistryBad`；旗標寫在路徑後的錯誤訊息講對、修 usage 被截斷的 bug。理由與細節在 [02](02-改法.md)。

- `aos-agent tools …` 只讀碼與 help，沒起 daemon 實跑。
- 「快取換台必失效」是從碼推的（stamp＝mtime_ns＋大小，行 244-246、318），沒在兩台實測。
- 「終端直接打 `aos-tools call 名` 會停著等輸入」是從碼推的（stdin 原樣交給工具，行 664），沒在真終端試。
- 工量是估的；乙級連帶檔清單來自 grep，文件類可能有漏。
- aos-mcp 沒實跑（只讀 help 與碼）。
