# 怪在哪（21 點，全部實跑過，除非標「推論」）

實跑環境：WSL、`/tmp/aos-tools-cli-review/proj/`（底下 `defs/tools/hello/`＝資料夾工具、`defs/tools/up.py`＝可執行檔工具、`stack/`、`../outside/ext/far/`＝專案外的工具）。行號指 `proto8/cmd/aos-tools/bin/aos-tools`（`2fe4245ee` 工作樹）。

## 一、真的問題（會踩坑，或跟你講過的原則衝突）

### 1. `--env-file` 把檔案內容抄進 tools.json（金鑰進 git、`${HOME}` 被寫死）

```
$ cat .env
MY_KEY=sk-secret-123
OTHER="${HOME}/x"
$ aos-tools add --override --env-file .env defs/tools/up.py
added up -> /tmp/aos-tools-cli-review/proj/defs/tools/up.py
$ cat tools.json
  "up": { "path": "defs/tools/up.py",
          "env": { "MY_KEY": "sk-secret-123", "OTHER": "/home/guanyu/x" }, …
```

- 跟 11-10「每次用到才解、不固化」「金鑰…不該進 git」衝突；`tools.json` 不論是定義那份還是 stack 裡的覆蓋層，照 two-machines 都會進 git。
- 這是你裁過的：`--env-file` 與 `--envs` 並存（11-05，[P-44](../../../../docs/CONVENTION/02-題目stack停錯腦/07-P-44.md) 第 13 行）、「`--env-file` 存內容（現況）」（11-07 sol 審查 #30）、`${HOME}` 在登記當下展開（11-06 env-portability）。所以是**新原則對舊裁定**，要你看（README Q1）。
- 其實不需要它：工具資料夾自己的 `.env` 每次 call 都會被 aos-exec 重讀——

```
$ echo "MY_KEY=from-tool-folder-env" > defs/tools/hello/.env; echo '{}' | aos-tools call hello
KEY=from-tool-folder-env …
$ echo "MY_KEY=changed-later" > defs/tools/hello/.env; echo '{}' | aos-tools call hello
KEY=changed-later …
$ echo '{}' | MY_KEY=from-shell aos-tools call hello        # 外面已設的贏
KEY=from-shell …
```

  可執行檔工具同樣讀它旁邊的 `.env`（實測 `defs/tools/.env` → `up.py` 拿到 `from-exe-dir-env`）。

### 2. 路徑有三種長相，`add` 不說它存了什麼、寫進哪份檔

```
$ aos-tools --overlay stack/tools.json add --name ov1 defs/tools/hello
added ov1 -> /tmp/aos-tools-cli-review/proj/defs/tools/hello      ← 印的：絕對
$ cat stack/tools.json
 "add": { "ov1": { "path": "../defs/tools/hello" } }               ← 存的：相對「被寫的那份檔」
                                                                    ← 打的：defs/tools/hello（相對 cwd）
```

第一次 `add` 會安靜新開 `./tools.json`，輸出也沒提。help 用七行解釋這條規則（行 93-98）。規則本身（存相對於檔）是對的、搬家需要；怪的是使用者看不到結果，只能 `cat`。

### 3. 「用環境變數指定」要手打 JSON，最自然的寫法反而失敗

```
$ aos-tools add --name far6 '$EXT/far'
aos-tools: error: PathMissing /tmp/aos-tools-cli-review/proj/$EXT/far does not exist …
$ aos-tools add --name far5 --path-json ../outside/ext/far
aos-tools: error: ArgumentsBad --path-json is not JSON: Expecting value: line 1 column 1 (char 0) …
$ EXT=…/outside/ext aos-tools add --name far3 --path-json '{"$env":"EXT","$path":"/far"}'
added far3 -> /tmp/aos-tools-cli-review/outside/ext/far
```

`--path-json` 這個名字講的是「形狀」（JSON），不是它承載的事（路徑由環境變數給）；純字串還得寫成 `'"../x"'`（JSON 字串外再包 shell 引號）。

### 4. 旗標寫在路徑後面：錯誤訊息誤導，而且印出來的 usage 被截斷（bug）

```
$ aos-tools add defs/tools/hello --name x9
aos-tools: error: ArgumentsBad add needs one XXX (or --path-json JSON) (usage: aos-tools [--file F] [--overlay O] add [--override] [--name N] [--no-cache])
```

明明給了 XXX，卻說「需要一個 XXX」；括號裡的 usage 少了 `[--env-file FILE] [--envs K=V]... (XXX | --path-json JSON)`——`usage()` 遇到含 ` | ` 的行就停（行 189），而 add 的第二行 usage 正好有 `(XXX | --path-json JSON)`。「第一個非旗標之後不再解析」是全家規則（aos_flags 第 16 行，為了 aos-exec 這種要原樣轉交參數的），但 aos-tools 沒有要轉交的參數。

### 5. `--file`／`--overlay` 只能寫在子命令前，而且沒有別的預設來源

```
$ aos-tools ls --file tools.json
aos-tools: error: FlagUnknown unknown flag --file (see aos-tools ls --help)
```

同樣的限制 aos-daemon-ctl 也有（`aos-daemon-ctl ls --daemon /tmp/x` 也是 FlagUnknown），但它有 `$AOS_DAEMON` 預設，平常不用打；aos-agent 的 `-t` 則明寫「may go before or after the subcommand」。aos-tools 兩頭都沒有，所以每行都得把 `--file F --overlay O` 寫在最前面。每個子命令的 help 還把這兩個旗標再列一次，寫成 `registry file before add`（「before add」是在講位置，讀起來不知所云）。

### 6. 靠 cwd 猜通訊錄：站錯資料夾不報錯

```
$ cd sub && aos-tools ls
[exit 0]                         ← 什麼都沒印
```

10-28 的前提是「每個agent資料夾一份」、人站在那個資料夾裡。現在的用法是專案資料夾裡定義與 stack「名字、數量、位置都不固定」，這個預設很少剛好對。「沒有這份檔＝沒有工具」對程式呼叫者是合理的，對手打的人是陷阱。

### 7. 登記檔與覆蓋層同名、不同形狀，拿錯不報錯

```
$ aos-tools --file stack/tools.json ls        ← 把覆蓋層當登記檔
[exit 0]                                      ← 空白
$ aos-tools --overlay tools.json ls           ← 把登記檔當覆蓋層
hello … up … x9 …                             ← 照常，覆蓋層等於沒作用
```

登記檔是 `{"tools": {…}}`、覆蓋層是 `{"add": {…}, "rm": […]}`，兩份通常都叫 `tools.json`（定義裡一份、stack 裡同相對路徑一份）。

### 8. 兩層對使用者外露，而包好的那支功能不齊

`aos-agent tools add` 只收 `[--override] [--no-cache] NAME PATH`（`cmd/aos-agent/aos_agent/tools.py` 第 39 行），沒有 `--env-file`／`--envs`／`--path-json`。要替某隻的工具設 env 或用環境變數路徑，文件教的是自己拼兩個路徑（`knowledge/aos/cli/tool_env.md`、`cmd/aos-agent/docs/03-tools覆蓋層.md`）：

```
aos-tools --file <定義>/tools.json --overlay <stack>/tools.json add --path-json '…'
```

（沒實跑 aos-agent，只讀碼與 help。）

### 9. 兩支的 `add` 寫法不同

```
aos-tools add [--name N] XXX
aos-agent tools add NAME PATH
```

佔位名也不同（`XXX` 對 `NAME_OR_PATH`／`NAME`／`PATH`）。同體系的 `aos-daemon-ctl add`、`aos-agent ctl add` 都是 `[-n N] XXX`。

### 10. 快取塞在通訊錄裡，還有一個旗標專門關它

```
$ aos-tools add defs/tools/up.py; cat tools.json
  "up": { "path": "defs/tools/up.py",
          "cache": { "stamp": "1794291482385532340-254",
                     "tooldef": { "description": "uppercase", "parameters": {…}, "env": ["MY_KEY"] } } }
```

- `stamp` 是檔案修改時間（奈秒）加大小（行 244-246）；git clone 後修改時間一定不同，快取不符就重跑、且不寫回（行 318-323）。**推論**：在另一台快取永遠用不到，只有登記那台有用；卻每次 add 都在 git 裡留一段機器專屬的東西。
- 沒有 `cache` 這格的登記，讀起來跟 `"cache": false` 行為相同（都重跑、都不寫）。所以 `--no-cache` 等於「別寫那一段」。
- 這是 10-28 你答的「4.可以」與 11-03 的 `--no-cache`，所以放 README Q2。

### 11. 存了 env，但 `ls`／`get` 都看不到

```
$ aos-tools get up
{"name": "up", "kind": "exe", "path": "…/up.py", "tooldef": {…}}      ← 沒有 env
```

「不印 env 值」是為了不把值給腦看（有道理），但人也因此沒有任何指令能確認「這個工具登記了哪些變數、來自哪份檔」，只能 `cat`。

### 12. `call` 手動試很彆扭

```
$ aos-tools call hello '{"who":"bob"}'
aos-tools: error: ArgumentsBad call needs one NAME, stdin = arguments …
$ echo not-json | aos-tools call hello            ← help 說 JSON，其實不驗
hello, stdin was: not-json
$ ls -a                                           ← 沒設 AOS_STACK 叫一次，cwd 多一個 .stack/
.  ..  .env  .stack  defs  stack  sub  tools.json
```

推論（沒在真終端試）：直接打 `aos-tools call hello` 會停著等你輸入到 Ctrl-D，沒有任何提示。stdin 收參數是工具契約（P-41），程式呼叫者（brain／act／aos-mcp）都靠它，不是問題；問題只在「人想試一下」這條路。

## 二、設計如此，但第一次看會愣一下（可用說明解決）

### 13. `rm`／`get` 的 XXX 是「名字，不然當路徑」；按路徑會一次動多筆

```
$ aos-tools rm ../outside/ext/far
removed far
removed far2
removed far3
removed far4
```

是 10-28 你的原設計（「add/rm/ls/get XXX，XXX是檔案或資料夾」）加上實作的「先當工具名」。同一個 `XXX` 在 add 是路徑、在 rm／get 是名字或路徑、call 又只收名字（`call defs/tools/hello` → ToolMissing）。`rm` 一次只收一個（`rm hello x9` → ArgumentsBad）。

### 14. 一個工具壞，整份清單都不能用，而且沒說是哪個

```
$ aos-tools ls            ← far3 用了 $EXT，這個 shell 沒設
aos-json: error: DirectiveBad environment variable EXT is not set
aos-tools: error: DirectiveBad tools.json#/tools: directives cannot be resolved (aos-json exited 1)
```

「不猜不跳過」是你 10-28 定的。但兩台輪流時，另一台忘了 export 一個變數＝這隻 agent 的工具全掛；訊息只說到 `#/tools`，沒說是 `far3`。

### 15. `ls` 會執行程式

`ls` 對每個可執行檔工具跑 `XXX --tooldef`（沒快取或快取不符時），所以「列清單」可能慢、可能有副作用。現況用快取遮住一部分（見 10）。

### 16. 名字推導

`up.py`、`up`、`up.json` 都推成 `up`（撞名）；`up.v2.py` → `NameBad 'up.v2'`；`my tool` → NameBad。訊息都有指路（`pick another with --name`），不用改。

### 17. `--envs` 的值照字面存

```
$ aos-tools add --override --envs 'MY_KEY=$HOME/x' --envs 'P=~/y' --envs REL=./rel defs/tools/up.py
{"MY_KEY": "$HOME/x", "P": "~/y", "REL": "./rel"}
```

照「給的值照字面用」（10-16）是對的；`--envs` 這個複數名與「不收 `--env`」是你 11-05 定的全家寫法（aos-agent ctl add、aos-daemon-ctl 都是）。help 寫的 `override file values` 在沒有 `--env-file` 時讀不懂，改一句說明即可。
