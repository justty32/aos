## 施工時順手確認的（04「沒實測或拿不準的」）

## 代定（裁定沒涵蓋、我選了保守做法）

- `.env` 必填檢查照 04 代定放在 daemon-root 加 kernel 全部四份（03 的表只寫 daemon-root、llm-kernel 兩份）。被 daemon 掛起來的 kernel 從上層繼承 `AOS_HOME`，多這一行不影響。
- `agents new` 保留「範本外的相對 tools 路徑換算成從新位置走回去」（11-06 就有的行為，`test_outside_template_through_symlink` 在驗），只拿掉 copy_def 那條；04 寫的「只留 copytree」我解讀成拿掉 repo 範本的改寫。

## 要重建什麼

- **用 copy-out 抄出去的舊副本**：照舊能跑（它們本來就是 `$env AOS_HOME` 寫法），不用重建；但它們裡面還有 `tools/memory/`（複本，不是捷徑），想跟新範本一致就重新 `cp -r` 一份。
- **裝過 install.sh 的機器**：`~/.local/bin/copy-out` 變成斷掉的捷徑，手動刪掉（`install.sh --uninstall` 也會清；重跑 install 不會清）。這次沒動 `~/.local/bin`。
- 範本的 `interfaces.json` 少了 `memory` 鍵、`tools.json` 形狀變了：從舊範本 `cp -r` 出來的定義不用改，照舊能跑；不寫遷移（11-05「當沒有舊版」）。

## 待使用者裁

- （無方向題。）defs 工具的「記憶」那一軸：範本不再宣告 `interfaces.json` 的 `memory`，庫改寫在 `tools.json` 裡 `memory` 那格的 `env.AOS_MEMORY`；defs dup 比工具時只看路徑、不看 `env`（原本就這樣設計），所以兩隻只差在知識庫的 agent 現在會被分成同一群。要不要讓 defs 改看 `memory` 那格的 `env.AOS_MEMORY`，留給使用者決定；現在不影響跑。
