# prefix-fixes 03：用的時候知道就好的坑（不修）

← [prefix-fixes](README.md)｜編號照桌面 aos-大修材料/40-問題清單

- **坑-36**：state_flux 被刪或壞了又要重起，先手動清 `ctl.json`，不然一起來就停。
- **坑-73**：線 2 的腳本做好之前，開新 agent 照 `templates/docs/02-agent-fsm.md` 第 8～15 行做。
- **坑-89、坑-90**：手動叫工具時設 `AOS_STACK`，不然 `.stack` 留在工作區。
- **設計-12**：手寫 ctl 每次換 seq。
- **設計-35**：stop 卡住改下 sleep（TERM、10 秒後 KILL）。
- **設計-40**：wake＝從頭重跑，問腦會多花一次錢。
- **設計-56**：別對 `llm_<信名>` 下 stop，會永遠佔一格。
- **坑-48**：起 llm daemon 的殼別設 `AOS_KERNEL`。
- **坑-37**：`interval_ms` 別寫 0，會吃滿一顆 CPU。
- **坑-91**：`bash`、`run_python` 碰得到工作區外面。
- **坑-93**：背景跑、stdin 沒關時工具會卡著等，記得接 `</dev/null`。
- **坑-84**：命令列 `aos-lock acquire` 要記得 release 或給租約。
- **設計-43**：JSON 入口別加 `+x` 又寫 `#!/usr/bin/env aos-exec`，會無限 exec。
- **坑-42**：沒有 aos-inst 指令，單子入口拿掉 `+x` 才跑得動。
- **坑-103**：大檔深層的 key，json_rewrite 可能走不到。
- **設計-63**：token 預檢會低估，不能當硬上限。
- **坑-24**：照跑用 WSL 那份建好、install.sh 裝的，不用 Windows 這份的 bin。
