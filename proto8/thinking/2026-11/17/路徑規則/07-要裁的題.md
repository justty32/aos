# 要你裁的題：每題選項、後果、推薦

先答題 1；選了規則一，題 2～6 才有意義。題 7、8 是八夾方案題 4 沒答完的部分。

## 題 1　走哪套規則

- A 規則一：只認一個家 `AOS_HOME`（推薦）。定義隨便放；樹不用抄；換版本＝關 daemon、換 commit、重開。改約 45 個程式檔，動一句條文（題 3）。
- B 規則二：`PATH`＋`PYTHONPATH`。程式碼最少（約 120 個檔刪掉找路徑的段落），但 aos 的 `lib` 會進到 agent 跑的每一支 Python 的搜尋路徑，要顧三個變數。
- C 規則三：最小修補。只改約 8 個檔，四格那顆雷修掉；樹照舊用抄的、換樹腳本照舊、其他往上找的寫法照舊。

## 題 2　樹裡那份程式怎麼來

- A `git worktree` 釘在一個 commit（推薦）：一行指令放進來，換版本一行 `checkout`，`git status`／`git log` 看得到版本與有沒有被改。C++ 只重編有改的。
- B 直接指 repo（`source ~/repo/aos/proto8/env.sh`）：零步驟，但 repo 一改樹就跟著變，agent 改到一半的東西會被跑著的樹用到。只適合開發時。
- C `git archive <commit> proto8 | tar -x`：解出來的是純檔案，沒有 git 連結，整包搬到別台最乾淨；版本要自己另記一個檔，每次換版本 C++ 全部重編，退回要自己留舊的那份。

## 題 3　抄出去的 Python 格怎麼找 `lib`（要不要動 N-63 表那句）

- A 格直接讀 `AOS_HOME`；N-63 四種性質表把 `AOS_HOME` 從「③ 人殼預設」改歸「② hub」（推薦）。改口草稿在 [04](04-規則草稿.md)。它實際上已經是 hub 的行為，只是表上寫「沒有程式直接讀它」。
- B 條文一字不動：程式不讀 `AOS_HOME`，改在定義的 `fsm.json` 每格單子加 `"envs": {"PYTHONPATH": {"$env": "AOS_HOME", "$path": "/lib"}}`（試過，跑得動）。代價：每份定義多四段一樣的字；`PYTHONPATH` 會傳給那格底下叫的所有 Python（工具、腦叫的腳本）。
- C 定義不帶格的程式，一律借家裡的格（`templates/reviewer` 的寫法）。定義變成純資料，最乾淨；但動到 P-27「各格的程式每隻 agent 複製一份自己改」，想改格的人要另外處理。

## 題 4　指令怎麼上 `PATH`

- A `env.sh` 把這個家的 `impls/*/bin`、`cmd/*/bin` 加進 `PATH`（推薦）：不往家目錄放任何東西；兩個家可以同時用（各 source 各的）；`PATH` 會多約 30 段；每個視窗要先 source（現在的習慣就是）。
- B `install.sh` 連進家裡的一個夾（例 `<家>/.bin`），`env.sh` 只加這一段：`PATH` 乾淨，但多一步，指令有增減要重跑。
- C 照舊連進 `~/.local/bin`：每個殼不用 source 就有指令；但一台只能指一個家，連結留在家目錄，repo 搬位置要重跑。

## 題 5　`py` 併進 `lib` 長什麼樣

- A 攤平放 `lib/` 頂層（推薦）：`import aos_flags` 一字不改，搜尋路徑只有一條。`lib/` 頂層的零散模組從 20 個變 27 個。
- B 收成 `lib/py/`：看得出哪些是「指令共用的」，但搜尋路徑還是兩條，每支找路徑的地方多留一行。

## 題 6　換樹腳本與 `copy_tree.py` 封存嗎

- A 封存（推薦）：`extras/tree-swap` 四支、`extras/aos-home/copy_tree.py` 進 `archive/`。換版本靠 [06](06-重建步驟單.md) 那四行。
- B 留著：給還想用「抄五夾」那種樹的人；但夾名表要跟著八夾改，等於多養一套。
- 題 2 選 C 的話，留一支最小的（解檔＋記版本）就好。

## 題 7　aos-view 何時搬進 `cmd/`

- A 等它改名那次一起搬（推薦，同八夾題 4）：在那之前 `extras` 只剩它，頂層是 9 夾。
- B 現在就搬成 `cmd/aos-view`：先到 8 夾，改名時再動一次。
- 不管哪個：它寫死了 `~/aos-home/ws/tools`（`aos-view:61`）與 unit 檔裡的 `%h/aos-home`、`%h/.local/bin`，重建樹後要跟著改或用它自己的 `VIEW_TOOLS` 指過去。這是它自己的事，不進路徑規則。

## 題 8　`langs`（Janet／Lua 的嘗試）封存可以嗎

- A 封存進 `proto8/archive/`（推薦）：10-24 之後沒動過。
- B 留在某處繼續當嘗試：那就進 `lib/` 或留一個 `extras`。

## 題 9　要不要做一個「根＋領班」的範本，讓搭樹少兩步（新工作）

- A 先不做（推薦）：照現在的三段手打，你看得到每個檔是什麼；等你重建一次、覺得煩再說。
- B 做：`templates/` 多一份可以 `cp -r` 的樹根（根 daemon＋領班＋空的 `agents/`、`ws/`），搭樹從九步變七步。要寫範本與測試，小工。

## 不用裁、但要你知道的

- 公司機 user site 那份 `aos-proto8.pth`、`~/.local/bin` 的 24 個連結都在你的家目錄，我們不會動；步驟單第 0 步請你自己清。
- 測試怎麼算「家在哪」（228 支各寫各的）這次不統一，只跟著夾名改。要統一是另一件事。
- `AOS_FEEDBACK`、`AOS_NOTIFY_BOX`、`AOS_USER_ZONE` 這幾個指「資料放哪」的變數不在這次範圍，照舊。
