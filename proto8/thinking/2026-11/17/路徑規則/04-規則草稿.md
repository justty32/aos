# 規則草稿（規則一；AI 寫的草稿，還沒裁，條號由你定）

暫時編號 路-1～路-8，只為了這份文件裡好指。「家」是這份草稿用的詞，進條文前要不要收這個詞也由你定（現有說法是「`AOS_HOME` 指的那個資料夾」）。

## 條文草稿

- **路-1　一個家。** `AOS_HOME`＝一個 proto8 資料夾的絕對路徑：repo 裡那個，或它在某個 commit 的另一份。aos 的程式（`impls cmd lib templates knowledge`）都在它底下。一棵樹只認一個家。
- **路-2　家裡的找家裡的：看自己的位置。** 家裡的程式要找家裡別的檔，從自己的真實位置照固定的相對位置算。不讀 `AOS_HOME`，不一層層往上找旁邊的夾。
- **路-3　家外的找家裡的：只經 `AOS_HOME`。** 定義、工作區裡的檔、抄出去的格或工具，要指進家裡只有這一條：JSON 寫 `{"$env": "AOS_HOME", "$path": …}`；Python 先看自己旁邊有沒有帶一份，沒有就用 `$AOS_HOME/lib`。
- **路-4　沒設就明講。** `AOS_HOME` 沒設或指不到要找的檔＝一行錯誤行 `程式: error: HomeMissing 原因`、退 1。不猜、不退到別的地方找。
- **路-5　指令照舊從 `PATH` 找。** `PATH` 由家裡的 `env.sh` 設成指進這個家；aos 的程式自己不動 `PATH`。
- **路-6　不往家外放程式。** 不往家目錄、Python user site、系統裡放 aos 的程式、連結或設定；`install.sh`（連進 `~/.local/bin`）只是選配。
- **路-7　沙箱。** 要讓沙箱裡的東西用 aos 的程式：唯讀綁 `AOS_HOME` 這一個夾、放行 `AOS_HOME` 這一個變數。
- **路-8　換版本。** 停 daemon、把家換到另一個 commit、起樹。沒有另外的換樹程式；新舊 stack 相不相容是那個 commit 自己要交代的。

## 題 3 選 A 時，N-63 表那一格的改口草稿

現在（③ 人殼預設）：「…每台設一次、改了值重起樹就生效；aos 的指令一律從 PATH 找、不經它；沒有程式直接讀它，只在定義檔寫成指示詞…時由解指示詞的那一層讀…」

改成（歸 ② hub）：「`AOS_HOME`（值＝一個 proto8 資料夾；沒設＝`HomeMissing`、沒有退路；來源＝人 source 家裡的 `env.sh`，底下照繼承；讀它的只有兩種：定義裡的指示詞 `{"$env": "AOS_HOME"}`，與離開家的程式找 `lib`；家裡的程式不讀它、指令照舊從 PATH 找）」。

理由：它現在的實際行為已經是 hub——根範本 `.env` 有必填檢查、整棵樹一路繼承、沒設就報錯（重現 2）。只是表上那句話沒跟上。

## 不寫進條文的（實作慣例，進 `lib/README` 就好）

- 會被抄出家的程式（範本的格、範本工具、kernel 假腦）找 `lib` 只留一種寫法：先看自己旁邊，再看 `$AOS_HOME/lib`，都沒有報 `HomeMissing`（`templates/tool-python/tool.py` 現在就是這樣）。
- 82 支 lib 工具現有的「往上找包住自己的 `lib/`」已經合路-2，這次不改。
