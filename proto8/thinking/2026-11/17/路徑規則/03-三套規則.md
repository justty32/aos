# 三套規則：同一組問題各自怎麼答

「家」＝`AOS_HOME` 指的那個夾（proto8 本身或它的一份）。

## 規則一：只認一個家（推薦）

一句話：**aos 的程式全部住在家裡；家裡的程式用自己的位置找鄰居，家外的東西只經 `AOS_HOME` 指進來。**

1. 怎麼知道程式在哪：家裡的檔（指令、lib 工具、範本原件）看自己在家裡的固定位置，不讀變數。家外的檔（抄出去的格、抄出去的工具）讀 `AOS_HOME`，沒設＝`HomeMissing`，不往上找、不猜。指令照舊從 `PATH` 找，`PATH` 由家裡的 `env.sh` 設成指進這個家。
2. 定義放哪都起得來：是。JSON 走 `{"$env": "AOS_HOME"}`（現在就是）；抄出去的 Python 格改成讀 `AOS_HOME` 找 `lib`。
3. repo 直接用跟樹：同一套。`source <某個 proto8>/env.sh` 就是用那一份；開發時指 repo，樹指一份釘在某個 commit 的 checkout。**不用抄樹**：家是一整個 proto8（含 `cmd`、`impls`），換版本＝停 daemon、`git checkout`、起樹。
4. 沙箱、子 agent、巢狀：`AOS_HOME` 一路繼承；沙箱綁 `AOS_HOME` 一個夾（唯讀）加放行這個變數，取代現在對 `py`、`tool_io.py` 的特判。子 agent 不用再帶 `PYTHONPATH`。
5. 往家目錄放東西：不用。`~/.local/bin` 的連結、`.pth` 都不需要（`install.sh` 留著當選配）。
6. 重建樹：9 步（[06](06-重建步驟單.md)），其中搭程式的只有 3 步（放一份 checkout、編 C++、source），沒有 aos 自己的腳本。
7. 改多少程式：第一類 19 處全換成同一個寫法；第二類隨 `py` 併進 `lib` 逐處改一行；第四類的連結與 `.pth` 不再需要；第五類整類消失（五支腳本封存）；第六類特判換成一條；第七類機械式改名。約 45 個程式檔＋55 支測試。

- 順著：C-51（只固定一個入口）、C-83 與 11-15 原話（關 daemon、重開就好）、C-78（設環境變數盡量少）、11-13「`AOS_HOME`＝proto8 本身或它的抄本」、N-63 ②（沒設＝報錯不猜）、P-31（指函式庫用 `AOS_HOME`）。
- **會動到**：N-63 四種性質表把 `AOS_HOME` 歸在「③ 人殼預設」，寫「沒有程式直接讀它」「aos 的指令一律從 PATH 找、不經它」。規則一讓家外的 Python 格直接讀它，等於把它改歸「② hub」。這要你裁（題 3；不想動條文有 B 走法）。P-27「各格的程式每隻 agent 複製一份」不動。

## 規則二：照 Unix 的標準做法（`PATH`＋`PYTHONPATH`）

一句話：**`env.sh` 設好 `PATH`、`PYTHONPATH`、`AOS_HOME` 三個，程式裡不再有任何找路徑的程式碼，直接 `import`。**

1. 怎麼知道：全靠環境。Python 靠 `PYTHONPATH`，指令靠 `PATH`，JSON 靠 `AOS_HOME`。
2. 定義放哪都起得來：是，只要環境有傳下來。
3. repo 與樹：同一套（source 哪份 `env.sh` 就用哪份），也可以不抄樹。
4. 沙箱、子 agent：三個變數都要放行、都要繼承；單子寫了 `envs_clear` 就斷。`PYTHONPATH` 會漏給 agent 跑的每一支 Python（使用者自己的腳本、`run_python` 工具）：`lib` 頂層有 `metainfo.py`、`observed.py`、`agent/` 這種常見名字，可能蓋到別人的模組。
5. 往家目錄放東西：不用。
6. 重建樹：9 步，同規則一。
7. 改多少程式：最多。82 支 lib 工具、22 支指令、6 支範本的找路徑段落全刪，約 120 個檔；刪完以後任何一支單獨拿出來跑都要先 source。

- 順著：C-07（用現成的 POSIX 做法）、C-56 KISS（程式碼最少）。
- 會動到：三個入口不是一個（C-51）；11-01「除非真的有必要，否則不要用（環境變數）」；N-63 的表要多一列 `PYTHONPATH`；程式沒環境時的錯變成 Python 的 traceback，不是一行錯誤行（N-43、P-21）。

## 規則三：最小修補（現在的找法留著，只補洞）

一句話：**哪裡壞補哪裡：四格找不到 `py` 時多看一眼 `AOS_HOME`；其餘不動，樹照舊用抄的。**

1. 怎麼知道：照舊三種混用（往上找、相對路徑、`AOS_HOME`），外加「找不到再看 `AOS_HOME`」。
2. 定義放哪都起得來：四格補了以後是。
3. repo 與樹：不同套照舊。指令在 repo、其餘抄進樹；抄樹、換樹腳本照舊要（夾名表跟著八夾改短）。
4. 沙箱、子 agent：特判照舊；子 agent 不用再帶 `PYTHONPATH`。
5. 往家目錄放東西：`~/.local/bin` 連結照舊。
6. 重建樹：現在的 ①～⑩ 加 `install.sh`，11 步；換樹照舊四步加三支腳本。
7. 改多少程式：最少，約 8 個檔。之後八夾第二步仍要改約 30 處路徑與 3 處夾名表。

- 順著：不動任何條文。
- 沒解決：「一棵樹三份程式」原樣；11-15 的「換樹要跑那堆腳本」原樣；往上找的寫法還在，「類似這樣的地雷」（11-16 原話）只少一顆。

## 推薦：規則一

- 你要的三件事它一次給：定義隨便放、換樹＝關 daemon 重開、重建樹看得懂（搭程式三步，都是你認得的 `git`、`cmake`、`source`）。
- 規則二程式碼最少，但把 aos 的 `lib` 塞進每支 Python 的搜尋路徑，還多兩個要顧的變數。
- 規則三最便宜，但你點名的兩件事（地雷、腳本）都還在。
- 規則一要付的：一條條文改口（題 3）、約 45 個程式檔，其中 30 個本來八夾第二步就要改。
