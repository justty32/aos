# 從零重建 `~/aos-home`：步驟單草稿（規則一、題 2 選 A、題 4 選 A）

**這是草稿**：施工單 S1～S6 做完才照得動；每一步的指令到時要在公司 WSL 真跑一遍再給你。`<commit>` 換成你要釘的那個。名字 `~/aos-home`、`src`、`eca_main` 都可以自己取。

## 搭完長這樣

```
~/aos-home/
  src/        一份 repo（git worktree，釘在某個 commit）。家＝src/proto8
  root/       根 daemon 的定義      daemon/  領班的定義
  agents/     你的 agent 定義        ws/      工作區
```

程式只有 `src/` 一夾，全部是 git 管的；其餘四夾是你自己的東西。

## 第 0 步：清掉以前裝在家目錄的（只做一次）

```sh
~/repo/aos/proto8/install.sh --uninstall
```
拿掉 `~/.local/bin` 裡指進 repo 的 `aos-*` 連結。

```sh
mv ~/.local/lib/python3.12/site-packages/aos-proto8.pth ~/aos-proto8.pth.old
```
移走舊的 `.pth`（公司機還在；它會讓壞掉的找法看起來沒壞）。舊的 `~/aos-home` 你自己決定搬去哪。

## 九步

1. 建四個夾。
```sh
mkdir -p ~/aos-home/root ~/aos-home/daemon ~/aos-home/agents ~/aos-home/ws
```

2. 放一份程式進來，釘在一個 commit。
```sh
git -C ~/repo/aos worktree add --detach ~/aos-home/src <commit>
```
之後 repo 怎麼改都不影響它；`git -C ~/aos-home/src log -1` 隨時看得到是哪一版。

3. 編 C++（全新編 9 支，公司 WSL 實測 4 分 2 秒；之後只編有改的）。
```sh
cd ~/aos-home/src/proto8/impls && cmake -B build -DCMAKE_BUILD_TYPE=Release && cmake --build build -j8
```

4. 進環境（**每開一個視窗都要做這一步**）。
```sh
source ~/aos-home/src/proto8/env.sh && echo $AOS_HOME && command -v aos-exec
```
它清掉殼裡的 `AOS_*`、把 `AOS_HOME` 設成這個家、把這個家的指令放進 `PATH`。要看到 `…/aos-home/src/proto8` 和 `…/src/proto8/impls/aos-exec/bin/aos-exec`。

5. 根 daemon 的定義：從範本抄，時鐘一行，加一格領班。
```sh
cd ~/aos-home && cp $AOS_HOME/templates/daemon-root/_entry $AOS_HOME/templates/daemon-root/daemon.json root/ && printf '%s\n' 'AOS_CLOCK=${AOS_STACK}/clock' > root/.env && aos-json set root/daemon.json#/procs/foreman '{"exec": "../daemon", "stack": "../ws/.stack", "ws": "../ws", "auto_restart": true}'
```

6. 領班的定義（兩個檔，內容照 [11-12 步驟 ⑤](../../12/ops-notes-to-aos.md#-領班管-agent-的那台)，沒變）。

7. 一隻 agent 的定義：從範本抄，寫模型。
```sh
cd ~/aos-home && cp -r $AOS_HOME/templates/eca-claude agents/eca_main && echo '{"model": "opus"}' > agents/eca_main/llm.json
```
知識庫在 `$AOS_HOME/knowledge`；`system.txt` 裡寫絕對路徑 `~/aos-home/src/proto8/knowledge`（照 11-12 步驟 ⑦）。

8. 起樹（前景跑，Ctrl-C＝整棵停）。
```sh
cd ~/aos-home && aos-tree-start root
```

9. 另一個視窗（先做第 4 步），把 agent 掛上。
```sh
cd ~/aos-home/ws && aos-agent ctl add ../agents/eca_main && aos-agent ctl ls
```

跟現在比：少了「跑 `install.sh`」「抄四夾再清快取」「抄 `env.sh`」三步；第 2、3、4 步都是 `git`、`cmake`、`source`，沒有 aos 自己的腳本。

## 之後換版本：關 daemon、換 commit、重開

```sh
aos-daemon-ctl -d ~/aos-home/.stack shutdown
git -C ~/aos-home/src checkout --detach <新 commit>
(cd ~/aos-home/src/proto8/impls && cmake --build build -j8)
cd ~/aos-home && aos-tree-start root
```

- 第三行只有 C++ 有改才真的編，沒改幾秒就過。
- 退回＝同樣四行，`<新 commit>` 換成舊的。
- 有沒有人在樹裡手改過程式：`git -C ~/aos-home/src status`。
- **仍然要人看的一件**：新 commit 有沒有改 stack 裡的帳的格式（[tree-swap README](../../../../extras/tree-swap/README.md)「釘 pin 時查帳的格式」那條）。這是 stack 相不相容的問題，換找法解決不了；commit 訊息要明寫。

## 開發時直接用 repo

```sh
source ~/repo/aos/proto8/env.sh
```
同一套找法，只是家指到 repo 本身。要同時開一棵釘住的樹和一個開發用的殼，就是兩個視窗 source 不同的 `env.sh`，互不干擾（現在 `~/.local/bin` 一台只能指一份，做不到）。

## 這份草稿還沒核的

- `git worktree` 的那份 checkout 裡 `impls/*/bin`、`build` 是 gitignore 的產物，`checkout` 換 commit 時留著不動——所以換版本後一定要跑第三行，不然 C++ 是舊的。
- 把 `~/aos-home` 整包搬到別台：`src/.git` 是指回 `~/repo/aos` 的一個小檔，搬過去檔都在、能跑，但 `git` 指令要那台也有 repo 才能用。要整包自帶就改用題 2 的 C（`git archive` 解一份）。
- 第 5、6 步現在要手打三段，是搭樹裡最囉嗦的；要不要做一個「根＋領班」的範本讓它變成一行 `cp -r`，見題 9。
