# 重現紀錄（11-17，公司 WSL，暫存夾 `~/.aos/scratch/paths-1117/`）

做法：repo 用 rsync 抄一份到 `src/`（不含 `.git`），實驗都在 `out1/` 裡；指令用這台 PATH 上現成的 `aos-*`。沒起 daemon、沒問腦（只跑 idle 格一拍）。每次都用 `env -i` 清乾淨環境，只給 `HOME`、`PATH` 與寫在下面的變數。暫存沒刪。

## 重現 1：定義放樹外，不給 `PYTHONPATH`

把 `templates/agent-fsm` 整夾抄到 `out1/defs/a1`，跑一拍：

```
env -i HOME=… PATH=… AOS_HOME=<src/proto8> aos-exec --ws ws --stack stackA/ defs/a1/fsm.json
```

- **第一次居然過了**（退 0）。查原因：這台 user site 還有 `aos-proto8.pth`，兩行指到 `~/repo/aos/proto8/py` 與 `lib`。
- 加 `PYTHONNOUSERSITE=1`（等於沒有那份 `.pth`，家機或新機器的情況）再跑：

```
agent-fsm: error: ModuleMissing required Python module aos_flags is unavailable
exit=1
```

- 照 11-16 的繞法加 `PYTHONPATH=<proto8>/py:<proto8>/lib`：退 0，`stage.txt` 正常。
- 同一份範本留在 proto8 裡原地跑（不抄出去）：退 0。

結論：雷是真的；公司機被舊 `.pth` 蓋住，而且蓋住時用的是 repo 工作樹的 `py`、`lib`，不是 `AOS_HOME` 那份。

## 重現 2：沒設 `AOS_HOME`

跑借格的範本 `templates/reviewer/fsm.json`（格寫成 `{"$env": "AOS_HOME", "$path": "/templates/agent-fsm/idle.py"}`）：

```
aos-fsm: error: DirectiveBad state idle: inst cannot run: environment variable AOS_HOME is not set
exit=1
```

結論：JSON 這條路沒設就明講，不猜。這是好的行為，新規則要讓 Python 那條路也一樣。

## 重現 3：指令用抄的、不用連結

`cp cmd/aos-tools/bin/aos-tools out1/bin/`，從 `/` 叫它（關掉 user site）：

```
Traceback (most recent call last):
  File "…/out1/bin/aos-tools", line 78, in <module>
    import aos_flags
ModuleNotFoundError: No module named 'aos_flags'
```

- 不抄、直接用原位的路徑從別的 cwd 叫：正常印 help。

結論：從哪個 cwd 叫沒差（都用真實位置算）；會壞的是「檔離開它的夾」。而且這裡連錯誤行都不是 aos 的格式，是 Python 的 traceback。

## 重現 4：單支工具抄出 lib、範本工具抄出去

`cp -r lib/base/read out1/defs/read1` 後叫它：

```
read1: error: ModuleMissing tool_io.py not in the tool folder, not in lib/, not on the Python path
```

`cp -r templates/tool-python out1/defs/t1`（沒設 `AOS_HOME`）：

```
t1: error: ModuleMissing tool_spec.py not found (set AOS_HOME, or copy it next to tool.py)
```

結論：`tool-python` 這支已經是「先看自己旁邊、再看 `AOS_HOME`、都沒有就明講」——推薦規則要的就是把這個寫法推到全部會被抄出去的程式。

## 重現 5：指令跟樹不是同一版

```
readlink -f $(command -v aos-tools)   → ~/repo/aos/proto8/cmd/aos-tools/bin/aos-tools
git -C ~/repo/aos rev-parse --short HEAD → ff7f74725
~/aos-home/{lib,py,templates,knowledge,kernel}/.aos-source.json → 都是 d5f47c890（11-17 08:47 抄）
```

結論：樹裡的工具是 `d5f47c890`，叫它們的指令（`aos-tools`、`aos-agent`…）與指令自己 import 的 `py`、`lib` 是 `ff7f74725` 加上工作樹裡還沒 commit 的改動。

## 重現 6：沙箱綁了什麼

`aos-sandbox --dry-run cmd/aos-sandbox/examples/agent.json`，綁進去的程式路徑：

```
--ro-bind ~/.local/bin
--ro-bind ~/repo/aos/proto8/cmd/aos-tools/bin
--ro-bind ~/repo/aos/proto8/impls/aos-{exec,fsm,llm,loop,post}/bin
--ro-bind ~/repo/aos/proto8/lib/tool_io.py
--ro-bind ~/repo/aos/proto8/py
```

結論：沙箱看到的是 repo 那份的指令與 `py`；`AOS_HOME` 沒綁、也不在環境白名單裡，樹的 `lib` 要設定檔自己列。

## 順手驗的一件（給規則用）

單子的 `envs` 裡可以寫指示詞：`{"argv": […], "envs": {"PYTHONPATH": {"$env": "AOS_HOME", "$path": "/lib"}}}`，跑出來子程式拿到 `<AOS_HOME>/lib`。所以「定義自己在 JSON 裡交代去哪找 lib」這條路現成就有（[要裁的題](07-要裁的題.md) 題 3 的 B 選項）。

## 沒重現的

- 子 agent 繼承環境、巢狀：沒起 daemon，只讀程式判斷（`envs` 是加上去、不清環境，除非寫 `envs_clear`）。
- 家機：沒看到。那邊有沒有殘留的 `.pth` 不知道。

## 順手驗的第二件：全新編一次、只靠家裡的 `PATH`

- 在暫存複本的 `impls/` 跑 `cmake -B build -DCMAKE_BUILD_TYPE=Release && cmake --build build -j8`：9 支都編出來，**4 分 2 秒**。
- 把這份複本的 `impls/*/bin`、`cmd/*/bin` 共 29 段放在 `PATH` 最前面（不含 `~/.local/bin`）、關掉 user site、`AOS_HOME` 指這份複本：`command -v aos-exec` 指進複本，範本原地跑一拍退 0。也就是「一個家自己就夠、不靠家目錄的連結」這件事現在就成立。
