## 你定的方向（原話九段全文在 [00](cpp-py-改名/00-使用者原話.md)）

- 「原始碼在 cpp/、py/，成品與入口另外放bin,lib,include」
- 「…git clone下來，跑個安裝腳本，編譯一下C++…python也稍微處理一下，然後bin/,lib/include就都會有東西，最後他只需要設個環境變數AOS_HOME就能開始了…」
- 「…git pull下來，重跑安裝腳本，然後就一切搞定…env.sh主要是補充。」
- 「安裝腳本...可以的話也用python寫？」「先不考慮pip，C++這塊也先不考慮vcpkg, cmake啥的」「cmd只留薄入口」

## 先講結論

- **推薦：執行期只認安裝產物。** `install.py` 編 C++ 進 `bin/`、`lib/`，把 `py/` 抄成 `lib/`，照一張表在 `bin/` 生出 Python 入口，標頭抄進 `include/`。跑起來只看 `bin/ lib/`（加 `templates/ knowledge/`），不看 `cpp/ py/`。三個產物夾整個不進 git。
- **有兩份 Python，但規則只有一句：改了原始碼，重跑 `install.py` 才生效**（C++ 與 Python 同一套）。代價是開發時每改一次要重裝（Python 那段約一秒）；好處是 pull 後不會新舊混搭、跑著的樹吃不到改到一半的程式。另一條路「入口直接用 `py/`」方便但 `lib/` 形同虛設——這是第一題（L-1）。
- **這個主案比「`lib` 改名 `py` 就地跑」便宜**：安裝後 Python 仍住在叫 `lib` 的夾，定義裡 223 處 `/lib/…` 指示詞最多只要插一段 `tools/`，選「工具照現在擺」的話一處都不用改。
- **分七步**，最大的兩步是「`lib` 從原始碼換手成產物」（約 400 檔內容、480 檔搬位置）與「`cmd` 的邏輯搬進 `py`」（21 支約 16,700 行、108 支測試，一支一支交）。
- **今天的 `env.sh` 跟你說的分工對不上**（它會清掉 `AOS_HOME` 再自己設），要改三處。
- **要你裁 15 題**；最要緊三題：L-1 執行期認哪一份、L-2 工具怎麼擺、L-3「不考慮 cmake」的讀法。

## 主案的樹

```
proto8/                 ＝ AOS_HOME（不變）
  install.py  env.sh
  cpp/        C++ 原始碼（原 impls；怎麼編照舊）            ┐
  py/         Python 原始碼                              │ 進 git
    aos/        一個套件：共用模組＋cmd 搬來的應用          │
    tools/      「資料夾＝程式」的工具 90 個               │
    packs/ schema/ tests/ docs/ entries.json             │
  templates/ knowledge/ docs/ thinking/ archive/         ┘
  bin/        9 支 C++ 執行檔＋21 支生出來的 Python 入口   ┐ install.py
  lib/        aos/ tools/ packs/ schema/（py/ 的抄本）＋.a │ 的產物，
  include/    aos/*.hpp（標頭的抄本）                     ┘ 不進 git
```

## 實測過的與沒測的（[09](cpp-py-改名/09-實測紀錄.md)）

| 實測過（WSL 暫存複本） | 沒測 |
|---|---|
| 夾改名＋成品改寫到同一夾，C++ 全部編得過 | `install.py` 沒寫、七步一步都沒做 |
| 純改名不修會全紅；機械替換後剩多少紅 | 抄 `py/`→`lib/` 後整套測試 |
| 套件 `aos` 與同名工具夾不會認錯；公司機舊 `.pth` 讓 `import aos` 拿到空殼 | 假腦起樹驗指示詞 |
| 公司 WSL 沒有 `pip`；這台 repo `core.symlinks=false` | 樹裡各檔「會不會過時」只照檔名分 |

## 沒把握的

- 數字是 grep 與子 agent 數的，量級可信、個位數不準；各步「改幾個檔」沒逐檔核。
- 推薦「只認安裝產物」是照你後面幾句話推的；它讓開發多一個重裝的動作，值不值得由你定（L-1）。
- 「不考慮 cmake」的讀法是猜的（L-3），而且外部依賴那條線可能改掉編法。
- `impl_cpp/` 沒看、沒納入。
