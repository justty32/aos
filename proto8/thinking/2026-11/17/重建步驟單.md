## 先講結論

- **程式只有一份：clone 下來的 `proto8/`。** `python3 install.py` 在它裡面填出 `bin/ lib/ include/`（不進 git），**執行期只認這三夾**；改了 `py/`、`cpp/` 或 `git pull` 之後，要重跑 `install.py` 才生效（11-18 S3 起，以前「改 repo＝改樹」的說法作廢）。
- **`AOS_HOME` 是你設的**：一台機器設一次，指那個 `proto8`（寫進 `~/.bashrc`；若用 zsh，寫進 `~/.zshrc`）。`env.sh` 不替你設，沒設就報一行錯、什麼都不改（11-17 L-7 C「沒設時：報錯」）。
- **樹＝你抄出去的定義＋跑出來的 stack**，`~/aos-home` 只放這些。一行 `cp -r` 抄起手範本（11-17 L-10 A）：API 版 `templates/start-api`（根＋掛在根上的 llm kernel＋一份選裝、預設不開的權限站＋一隻 agent-fsm），eca 版 `templates/start-eca`（根＋一隻 Claude Code agent）。
- **每開一個視窗：`cd ~/aos-home && source env.sh`**。樹裡那份是薄的，轉去 `$AOS_HOME/env.sh`：清掉別棵樹的 `AOS_*`（`AOS_HOME` 留著）、把 `$AOS_HOME/bin` 放到 PATH 最前（選配的網頁外掛在，就再加 `$AOS_HOME/frontend/bin`）。不往 `~/.local/bin` 放東西。
- 標 ✅ 的步驟，線 `s67-1118` 11-18 在 WSL 暫存夾從乾淨 `git clone` 實跑過（假 HOME、假腦、不接真模型、不碰你的樹）：install.py 全新約 1～1.5 分鐘（這次 71 秒，11-18 公司 WSL 重建 85.5 秒；同時有別的編譯在跑時會更久）、`bin/` 30 支（11-18 移除 `aos-kit`、`aos-tree-start` 後是 28 支：9 支 C++、19 支 Python）；第 6 步回 `FAKE ANSWER to: hello`（前面先印一行信件編號）；關樹兩台都停乾淨；更新五步後睡下的 `ann` 自己醒、再問一句照答。eca 版只試了抄、`source env.sh`、根起停（沒掛 agent，這台的測試環境沒有 `claude`）。

## 搭完長這樣

```
~/repo/aos/proto8/     程式（git 管）；bin/ lib/ include/ 是 install.py 填的。AOS_HOME＝這裡
~/aos-home/            從 templates/start-api 抄的
  env.sh               薄的：轉去 $AOS_HOME/env.sh；下面可以加這棵樹自己的 export
  root/                根 daemon 的定義（＝templates/daemon-root，.env 的 AOS_LLM_KERNEL 指 ${AOS_STACK}/procs/llm）
  llm/                 llm kernel 的定義（＝templates/kernel/llm-kernel），掛上根之後是表上一列 llm
  perm/                權限站的定義（＝templates/kernel/procs-kernel，kernel.json 是 {}）；選裝，出廠沒掛
  agents/ann/          一隻 agent 的定義（＝templates/agent-fsm，llm.json 是假腦；多一個 .env，只有一行註解掉的 AOS_KERNEL）
  .stack/              根的 stack（起的時候自己建）；llm kernel 的在 .stack/procs/llm/，ann 的在 .stack/procs/ann/
```

## 第 0 步：清掉以前裝在家目錄與 repo 裡的舊東西（只有你這兩台要做一次，新使用者沒有）

| 指令 | 說明 |
|---|---|
| `systemctl --user list-units --all \| grep aos`、`grep -rl aos-home ~/.config/systemd/user` | 先查有沒有常駐的東西指進舊樹或靠 `~/.local/bin/aos-*` 連結（沒有 systemd 的機器跳過）。家機 11-18 就有：全景頁 `aos-view.service`、`aos-user-tick.timer` 跑的是舊樹 `ws/tools/` 裡的程式（不在 repo），tick 還靠 `~/.local/bin/aos-post`（指進 `proto8/impls/`）；下面改名、刪連結、刪 `impls/` 都會讓它們壞。查到的話先想好怎麼處理（例：把那些工具抄進新樹，或改單元裡的路徑）再往下做 |
| 照你平常的關法把舊樹停掉，再 `mv ~/aos-home ~/aos-home.old` | 舊樹留著備查，要不要刪你自己決定 |
| `grep -n aos ~/.bashrc ~/.zshrc` | 看家目錄 rc 裡有沒有以前寫的 aos 行。若有自動 `source ~/aos-home/env.sh` 那種行（家機 `~/.zshrc` 有）：舊的 `env.sh` 會自己把 `AOS_HOME` 設成樹，新的不設，所以要在那行**前面**先 `export AOS_HOME=~/repo/aos/proto8`（第 3 步用 `>>` 接在檔尾會排在它後面，不夠）。改完要把所有開著的視窗都重開，含正在跑的 agent session（例 Claude Code）；沒重開的殼還帶舊的 `AOS_HOME`，`source` 會報 `EnvBad AOS_HOME=… is not an aos home` |
| `ls -l ~/.local/bin/aos-*` | 舊 `cmd/install.sh` 連進 repo 的捷徑（那支腳本 11-18 收掉了，`--uninstall` 也跟著沒了）。是指進 `repo/aos` 的連結，就自己拿掉：`find ~/.local/bin -maxdepth 1 -type l -name 'aos-*' -lname '*repo/aos*' -delete`（只刪連結）。不拿掉的話 PATH 上它排在前面時會跑到舊的 |
| `ls "$(python3 -m site --user-site)"/aos-proto8.pth` | 舊的 `.pth`（公司機 11-15 前裝的）。在的話直接刪：`rm "$(python3 -m site --user-site)/aos-proto8.pth"`（移到家目錄留著不算清乾淨）；它會讓壞掉的找法看起來沒壞 |
| `cd ~/repo/aos && git pull && git status --short --ignored proto8 \| head` | 拉新程式後看 `proto8/` 裡 git 不管的殘留：舊的 `proto8/impls/`、`proto8/cmd/`（只剩 `__pycache__`、舊 `bin/` 之類）可以整夾刪；`proto8/lib/` 不用管（`install.py` 會先清掉再填） |

## 安裝六步（新使用者從這裡開始）

| # | 指令 | 說明 | 實跑 |
|---|---|---|---|
| 1 | `git clone <repo> ~/repo/aos`（你的機器已有就 `git -C ~/repo/aos pull`） | 拿程式 | ✅ |
| 2 | `cd ~/repo/aos/proto8 && python3 install.py` | 先印必要／選配工具表（`-`＝沒裝，選配的缺了只是那項功能不能用；必要的缺了退 1），再清空 `bin/ lib/ include/`、用 `cpp/Makefile` 編 C++、把 `py/` 抄成 `lib/`、照 `py/entries.json` 生 19 支 Python 指令入口。最後兩行叫你設 `AOS_HOME`、抄起手範本 | ✅ |
| 3 | `echo 'export AOS_HOME=~/repo/aos/proto8' >> ~/.bashrc`，開新視窗 | 若用 zsh（家機），把 `~/.bashrc` 換成 `~/.zshrc`；rc 裡已有舊的自動 source 行，照第 0 步那格放在它前面。一台設一次。已經設過、指的是這裡，`install.py` 會說 `AOS_HOME already points at this home`；指到別的家會印一行 warning | ✅ |
| 4 | `cp -r $AOS_HOME/templates/start-api ~/aos-home` | 一行抄好整棵樹（eca 版換 `start-eca`）。**`~/aos-home` 要先不存在**：已經有的話 `cp -r` 不會覆蓋，會抄成 `~/aos-home/start-api`。要真模型就把 `agents/ann/llm.json` 的 `fake` 換成 `llm/kernel.json` 的 `endpoints` 裡的名字 | ✅ |
| 5 | `cd ~/aos-home && source env.sh && command -v aos-exec` | 進環境，**每開一個視窗都要做**。要看到 `…/repo/aos/proto8/bin/aos-exec`。`AOS_HOME` 沒設會看到 `env.sh: error: EnvBad AOS_HOME is not set …` | ✅ |
| 6 | 視窗 A：`aos-exec root`；視窗 B：`aos-daemon-ctl -d .stack add --auto-restart llm`、`aos-agent -d .stack ctl add --auto-restart -w . agents/ann`，再 `aos-daemon-ctl -d .stack ls`、`aos-agent -d .stack --target ann say hello && aos-agent -d .stack --target ann listen --timeout-s 20` | 起根（前景，Ctrl-C＝整棵停；殼裡別棵樹的 `AOS_*` 由第 5 步的 `source env.sh` 清掉，沒做那步就沒人擋）、把 llm kernel 掛上根（成為表上一列 `llm`；跟 agent 一樣只要第一次，之後關、再起都跟著根）、掛 agent、看表（`_clock`、`_sweeper`、`llm`、`ann` 都是 `running`）、問一句（假腦回 `FAKE ANSWER to: hello …`）。兩個視窗都先做第 5 步。**要真模型**：金鑰在視窗 A 起根之前 `export LITELLM_KEY=…`（llm kernel 從根繼承環境；根已經開著就先關、設好再起）。要它一直跑、不佔終端：在做過第 5 步的視窗打 `setsid bash -c 'cd ~/aos-home && source env.sh && exec aos-exec root' > ~/aos-home/root.log 2>&1 < /dev/null &`（只剩這一句：llm kernel 掛在根上，不用另起；11-20 實跑時它不往 `root.log` 印 `counter_runs`）；關法照下面「關」。權限站不在這幾步裡開，要開照 start-api README | ✅ 11-20 |
| 關 | `cd ~/aos-home && source env.sh && aos-daemon-ctl -d .stack shutdown` | 關樹：一句全關（子項睡下、記在表上，llm kernel 是根上一列、跟著睡下；它自己的表也記成 `sleeping`）。新視窗直接打會 command not found，所以先進環境。再起＝視窗 A：`cd ~/aos-home && source env.sh && aos-exec root`；睡下的（含 `llm`、`ann`）自己醒，不用再 `add` | ✅ 11-20 |

之後要加你的中心 agent（`eca_main`，Claude Code 那種）與領班：抄 `$AOS_HOME/templates/eca-claude` 到 `agents/<名>`，寫法照 [11-12 ops-notes ⑤⑦](../12/ops-notes-to-aos.md)；或整棵改用 `templates/start-eca`。這次沒試（不接真模型）。eca 版的殼裡 `command -v claude` 要找得到（常在 `~/.local/bin`；乾淨 PATH 或非互動殼裡跑 `install.py`，工具表上 `claude` 會是 `-`，那是表的事，起 eca 版的視窗 PATH 有它就好）。

## 要知道的

- **改了要 `install.py` 才生效**：樹跑的是 `$AOS_HOME/bin`、`$AOS_HOME/lib`。你在 repo 改 `py/`、`cpp/` 存檔、`git pull`，樹都還是舊的，直到跑 `python3 install.py`；反過來，樹跑著時在 repo 跑 `install.py`，它會先清再填，中間那幾秒樹叫到的指令與工具都不在（先停樹最穩）。不經 `install.py`、樹直接讀的是 `knowledge/`、`frontend/`，存檔就生效；`templates/` 要重抄進樹（更新第 4 步）。
- **stack 帳的格式**：新 commit 若改了 stack 裡的帳或名冊（例 `subagents.json`）的格式，換版本前要先收子或重建；commit 訊息要寫明。這跟找法無關，換版本時要人看一眼。
- **全景頁 aos-frontend**（選配的網頁外掛；11-17 從 `cmd/aos-view` 搬到 `proto8/frontend/`、改名 aos-frontend，舊名打不到了）：`install.py` 不管它；執行檔在 `$AOS_HOME/frontend/bin/aos-frontend`，`source env.sh` 之後直接打 `aos-frontend`。它的 systemd 範例是 `frontend/systemd/aos-frontend.service`，裡面寫 `~/repo/aos/proto8` 與 `~/aos-home`（11-18 起還多一行 `Environment=AOS_HOME=…`，因為 `env.sh` 不再替你設），跟你的位置不同就自己改；以前照舊範例裝過 `aos-view.service` 的，要換成新的檔名與指令。它的資料夾 `~/.aos/view` 沒改名，照舊用。v2 的 `dist/` 不在 git，要在有 Node 的機器照 `frontend/ui/v2/README.md` 建。
- 只是開發、不起樹：`export AOS_HOME=~/repo/aos/proto8`（已寫進 `~/.bashrc` 就不用）後 `source "$AOS_HOME/env.sh"`。**跑測試前也一定要先做這句**（例 `python3 -m unittest discover -s proto8/py/tests`）：測試要 `bin/` 在 PATH 上，沒 source 會冒一堆 `No such file or directory: 'aos-exec'`。在 agent 的殼裡要測一份暫存複本：先清掉 `AOS_*`、再 `export AOS_HOME=<複本的 proto8>`；直接 source 複本的 `env.sh` 而 `AOS_HOME` 還指活樹的家時，`env.sh` 照 `AOS_HOME` 走、另印一行 warning。
