# 11-17 從零重建 `~/aos-home`：步驟單（11-18 改寫成安裝六步＋更新五步）

← [路徑規則](路徑規則.md)｜流程的來由：[13-安裝腳本與新使用者流程](cpp-py-改名/13-安裝腳本與新使用者流程.md)、[14-更新與重新複製](cpp-py-改名/14-更新與重新複製.md)｜草稿原版：[06-重建步驟單](路徑規則/06-重建步驟單.md)（那份照 `git worktree` 寫，使用者裁「路徑-2 B」後作廢）

使用者原話（11-17）：「好，不用考慮活樹，因為我之後要重建~/aos-home，對，整個重來，我要掌握整個流程」。這份是給你照著做的；別的使用者照「安裝六步」也一樣（把 `~/repo/aos` 換成他 clone 的位置）。

## 先講結論

- **程式只有一份：clone 下來的 `proto8/`。** `python3 install.py` 在它裡面填出 `bin/ lib/ include/`（不進 git），**執行期只認這三夾**；改了 `py/`、`cpp/` 或 `git pull` 之後，要重跑 `install.py` 才生效（11-18 S3 起，以前「改 repo＝改樹」的說法作廢）。
- **`AOS_HOME` 是你設的**：一台機器設一次，指那個 `proto8`（寫進 `~/.bashrc`）。`env.sh` 不替你設，沒設就報一行錯、什麼都不改（11-17 L-7 C「沒設時：報錯」）。
- **樹＝你抄出去的定義＋跑出來的 stack**，`~/aos-home` 只放這些。一行 `cp -r` 抄起手範本（11-17 L-10 A）：API 版 `templates/start-api`（根＋llm kernel＋一隻 agent-fsm），eca 版 `templates/start-eca`（根＋一隻 Claude Code agent）。
- **每開一個視窗：`cd ~/aos-home && source env.sh`**。樹裡那份是薄的，轉去 `$AOS_HOME/env.sh`：清掉別棵樹的 `AOS_*`（`AOS_HOME` 留著）、把 `$AOS_HOME/bin` 放到 PATH 最前（選配的網頁外掛在，就再加 `$AOS_HOME/frontend/bin`）。不往 `~/.local/bin` 放東西。
- 標 ✅ 的步驟，線 `s67-1118` 11-18 在 WSL 暫存夾從乾淨 `git clone` 實跑過（假 HOME、假腦、不接真模型、不碰你的樹）：install.py 全新約 1～1.5 分鐘（這次 71 秒，11-18 公司 WSL 重建 85.5 秒；同時有別的編譯在跑時會更久）、`bin/` 30 支；第 6 步回 `FAKE ANSWER to: hello`（前面先印一行信件編號）；關樹兩台都停乾淨；更新五步後睡下的 `ann` 自己醒、再問一句照答。eca 版只試了抄、`source env.sh`、根起停（沒掛 agent，這台的測試環境沒有 `claude`）。
- 11-18 獨立驗證線在 HEAD `96b3e2e8c` 的乾淨 clone＋假 HOME＋假腦，照安裝六步與更新五步各走一遍，每步對得上；`install.py` 全新 71.7 秒、更新時 1.2 秒；「再起」這次有試（只跑兩個視窗、不再 add，`ann` 自己醒、照答）；沒驗：第 0 步、start-eca、真模型。
- 11-18 晚照 [公司 WSL 重建試跑紀錄](../18/公司WSL-重建試跑紀錄.md) 文末的卡點補了六處：再起時視窗 B 的 `cd llms`、關樹兩句分開打、`~/aos-home` 要先不存在、舊 `.pth` 直接 `rm`、install 耗時、跑測試前先 `source`。

## 搭完長這樣

```
~/repo/aos/proto8/     程式（git 管）；bin/ lib/ include/ 是 install.py 填的。AOS_HOME＝這裡
~/aos-home/            從 templates/start-api 抄的
  env.sh               薄的：轉去 $AOS_HOME/env.sh；下面可以加這棵樹自己的 export
  root/                根 daemon 的定義（＝templates/daemon-root，.env 的 AOS_LLM_KERNEL 指樹裡的 llms）
  llms/def/            llm kernel 的定義（＝templates/kernel/llm-kernel）
  llms/stacks/llm/     llm kernel 的 stack（起的時候自己建）
  agents/ann/          一隻 agent 的定義（＝templates/agent-fsm，llm.json 是假腦）
  .stack/              根的 stack（起的時候自己建）
```

## 第 0 步：清掉以前裝在家目錄與 repo 裡的舊東西（只有你這兩台要做一次，新使用者沒有）

| 指令 | 說明 |
|---|---|
| 照你平常的關法把舊樹停掉，再 `mv ~/aos-home ~/aos-home.old` | 舊樹留著備查，要不要刪你自己決定 |
| `ls -l ~/.local/bin/aos-*` | 舊 `cmd/install.sh` 連進 repo 的捷徑（那支腳本 11-18 收掉了，`--uninstall` 也跟著沒了）。是指進 `repo/aos` 的連結，就自己拿掉：`find ~/.local/bin -maxdepth 1 -type l -name 'aos-*' -lname '*repo/aos*' -delete`（只刪連結）。不拿掉的話 PATH 上它排在前面時會跑到舊的 |
| `ls "$(python3 -m site --user-site)"/aos-proto8.pth` | 舊的 `.pth`（公司機 11-15 前裝的）。在的話直接刪：`rm "$(python3 -m site --user-site)/aos-proto8.pth"`（移到家目錄留著不算清乾淨）；它會讓壞掉的找法看起來沒壞 |
| `cd ~/repo/aos && git pull && git status --short --ignored proto8 \| head` | 拉新程式後看 `proto8/` 裡 git 不管的殘留：舊的 `proto8/impls/`、`proto8/cmd/`（只剩 `__pycache__`、舊 `bin/` 之類）可以整夾刪；`proto8/lib/` 不用管（`install.py` 會先清掉再填） |

## 安裝六步（新使用者從這裡開始）

| # | 指令 | 說明 | 實跑 |
|---|---|---|---|
| 1 | `git clone <repo> ~/repo/aos`（你的機器已有就 `git -C ~/repo/aos pull`） | 拿程式 | ✅ |
| 2 | `cd ~/repo/aos/proto8 && python3 install.py` | 先印必要／選配工具表（`-`＝沒裝，選配的缺了只是那項功能不能用；必要的缺了退 1），再清空 `bin/ lib/ include/`、用 `cpp/Makefile` 編 C++、把 `py/` 抄成 `lib/`、照 `py/entries.json` 生 21 支 Python 指令入口。最後兩行叫你設 `AOS_HOME`、抄起手範本 | ✅ |
| 3 | `echo 'export AOS_HOME=~/repo/aos/proto8' >> ~/.bashrc`，開新視窗 | 一台設一次。已經設過、指的是這裡，`install.py` 會說 `AOS_HOME already points at this home`；指到別的家會印一行 warning | ✅ |
| 4 | `cp -r $AOS_HOME/templates/start-api ~/aos-home` | 一行抄好整棵樹（eca 版換 `start-eca`）。**`~/aos-home` 要先不存在**：已經有的話 `cp -r` 不會覆蓋，會抄成 `~/aos-home/start-api`。要真模型就把 `agents/ann/llm.json` 的 `fake` 換成 `llms/def/kernel.json` 的 `endpoints` 裡的名字 | ✅ |
| 5 | `cd ~/aos-home && source env.sh && command -v aos-exec` | 進環境，**每開一個視窗都要做**。要看到 `…/repo/aos/proto8/bin/aos-exec`。`AOS_HOME` 沒設會看到 `env.sh: error: EnvBad AOS_HOME is not set …` | ✅ |
| 6 | 視窗 A：`aos-exec root`；視窗 B：`cd llms && aos-exec --stack stacks/llm def`；視窗 C：`aos-agent -d .stack ctl add --auto-restart -w . agents/ann`，再 `aos-daemon-ctl -d .stack ls`、`aos-agent -d .stack --target ann say hello && aos-agent -d .stack --target ann listen --timeout-s 20` | 起根（前景，Ctrl-C＝整棵停；殼裡別棵樹的 `AOS_*` 由第 5 步的 `source env.sh` 清掉，沒做那步就沒人擋）、起 llm kernel、掛 agent、看表（`_clock`、`_sweeper`、`ann` 都是 `running`）、問一句（假腦回 `FAKE ANSWER to: hello …`）。三個視窗都先做第 5 步 | ✅ |
| 關 | `cd ~/aos-home && source env.sh`，再分兩句打：`aos-daemon-ctl -d .stack shutdown`、`aos-daemon-ctl -d llms/stacks/llm shutdown` | 關樹（子項睡下、記在表上；新視窗直接打會 command not found，所以先進環境）。兩句不要用 `&&` 串：根已經停了時第一句報 `DaemonMissing`、退 1，`&&` 後面的 llm kernel 那句就不跑。再起＝視窗 A：`cd ~/aos-home && source env.sh && aos-exec root`；視窗 B：`cd ~/aos-home && source env.sh && cd llms && aos-exec --stack stacks/llm def`（新開的視窗也能照抄；新視窗沒進環境會找不到 `aos-exec`。還在原來那個視窗 B、已經在 `llms/` 裡，只打 `aos-exec --stack stacks/llm def` 就好）；睡下的自己醒 | ✅ |

之後要加你的中心 agent（`eca_main`，Claude Code 那種）與領班：抄 `$AOS_HOME/templates/eca-claude` 到 `agents/<名>`，寫法照 [11-12 ops-notes ⑤⑦](../12/ops-notes-to-aos.md)；或整棵改用 `templates/start-eca`。這次沒試（不接真模型）。

## 要知道的

- **改了要 `install.py` 才生效**：樹跑的是 `$AOS_HOME/bin`、`$AOS_HOME/lib`。你在 repo 改 `py/`、`cpp/` 存檔、`git pull`，樹都還是舊的，直到跑 `python3 install.py`；反過來，樹跑著時在 repo 跑 `install.py`，它會先清再填，中間那幾秒樹叫到的指令與工具都不在（先停樹最穩）。不經 `install.py`、樹直接讀的是 `knowledge/`、`frontend/`，存檔就生效；`templates/` 要重抄進樹（更新第 4 步）。
- **stack 帳的格式**：新 commit 若改了 stack 裡的帳或名冊（例 `subagents.json`）的格式，換版本前要先收子或重建；commit 訊息要寫明。這跟找法無關，換版本時要人看一眼。
- **全景頁 aos-frontend**（選配的網頁外掛；11-17 從 `cmd/aos-view` 搬到 `proto8/frontend/`、改名 aos-frontend，舊名打不到了）：`install.py` 不管它；執行檔在 `$AOS_HOME/frontend/bin/aos-frontend`，`source env.sh` 之後直接打 `aos-frontend`。它的 systemd 範例是 `frontend/systemd/aos-frontend.service`，裡面寫 `~/repo/aos/proto8` 與 `~/aos-home`（11-18 起還多一行 `Environment=AOS_HOME=…`，因為 `env.sh` 不再替你設），跟你的位置不同就自己改；以前照舊範例裝過 `aos-view.service` 的，要換成新的檔名與指令。它的資料夾 `~/.aos/view` 沒改名，照舊用。v2 的 `dist/` 不在 git，要在有 Node 的機器照 `frontend/ui/v2/README.md` 建。
- 只是開發、不起樹：`export AOS_HOME=~/repo/aos/proto8`（已寫進 `~/.bashrc` 就不用）後 `source "$AOS_HOME/env.sh"`。**跑測試前也一定要先做這句**（例 `python3 -m unittest discover -s proto8/py/tests`）：測試要 `bin/` 在 PATH 上，沒 source 會冒一堆 `No such file or directory: 'aos-exec'`。在 agent 的殼裡要測一份暫存複本：先清掉 `AOS_*`、再 `export AOS_HOME=<複本的 proto8>`；直接 source 複本的 `env.sh` 而 `AOS_HOME` 還指活樹的家時，`env.sh` 照 `AOS_HOME` 走、另印一行 warning。
