# 11-17 從零重建 `~/aos-home`：步驟單（路徑規則一、樹裡的程式直接指 repo）

← [路徑規則](路徑規則.md)｜草稿原版：[06-重建步驟單](路徑規則/06-重建步驟單.md)（那份照 `git worktree` 寫，使用者裁「路徑-2 B」後作廢，以這份為準）

使用者原話（11-17）：「好，不用考慮活樹，因為我之後要重建~/aos-home，對，整個重來，我要掌握整個流程」。這份是給你照著做的。

## 先講結論

- **程式只有一份：`~/repo/aos/proto8`。** `AOS_HOME` 就指它；樹裡不抄 lib、templates、knowledge，也沒有 `git worktree`（你裁的路徑-2 B）。樹跑的就是 repo 當下的程式。
- **`~/aos-home` 只放你自己的東西**：根的定義、llm kernel 的定義、agent 的定義、stack。
- **每開一個視窗先 `source ~/repo/aos/proto8/env.sh`**，它清掉 `AOS_*`、設 `AOS_HOME`、把 repo 的指令放到 PATH 最前；不用再往 `~/.local/bin` 連東西。
- 標 ✅ 的步驟，線 `path-1117` 在 WSL 暫存夾實跑過（`AOS_HOME` 指暫存複本、假腦、不接真模型），到「`aos-daemon-ctl ls` 有東西、agent 回 `FAKE ANSWER`、用 shutdown 關掉」為止。沒標的沒跑。

## 搭完長這樣

```
~/repo/aos/proto8/     程式（git 管）。AOS_HOME＝這裡
~/aos-home/
  root/                根 daemon 的定義（從 templates/daemon-root 抄）
  llms/def/            llm kernel 的定義（從 templates/kernel/llm-kernel 抄）
  llms/stacks/llm/     llm kernel 的 stack（起的時候自己建）
  agents/ann/          一隻 agent 的定義（從 templates/agent-fsm 抄）
  .stack/              根的 stack（起的時候自己建）
```

## 第 0 步：清掉以前裝在家目錄的（只做一次，沒實跑）

| 指令 | 說明 |
|---|---|
| 照你平常的關法把舊樹停掉，再 `mv ~/aos-home ~/aos-home.old` | 舊樹留著備查，要不要刪你自己決定 |
| `cd ~/repo/aos && git pull` | 先拿到這次改好的程式（`install.sh` 搬到 `cmd/` 了） |
| `~/repo/aos/proto8/cmd/install.sh --uninstall` | 拿掉 `~/.local/bin` 裡指進 repo 的 `aos-*` 連結（只拿連結，別的不碰） |
| `mv "$(python3 -m site --user-site)/aos-proto8.pth" ~/aos-proto8.pth.old` | 移走舊的 `.pth`（公司機還在；它會讓壞掉的找法看起來沒壞）。沒有這個檔就跳過 |

## 搭樹（照順序）

| # | 指令 | 說明 | 實跑 |
|---|---|---|---|
| 1 | `cd ~/repo/aos/proto8/impls && cmake -B build -DCMAKE_BUILD_TYPE=Release && cmake --build build -j8` | 編 C++（全新編約 4 分鐘；之後只編有改的）。執行檔出在 `impls/*/bin/` | ✅（在暫存複本裡編） |
| 2 | `source ~/repo/aos/proto8/env.sh && echo $AOS_HOME && command -v aos-exec` | 進環境。**每開一個視窗都要做**。要看到 `…/repo/aos/proto8` 和 `…/proto8/impls/aos-exec/bin/aos-exec` | ✅ |
| 3 | `mkdir -p ~/aos-home/agents ~/aos-home/llms && cd ~/aos-home` | 建夾 | ✅ |
| 4 | `cp -r $AOS_HOME/templates/daemon-root root && echo 'AOS_LLM_KERNEL=${AOS_WS}/llms/stacks/llm' >> root/.env` | 根的定義：時鐘＋清道夫；多一行告訴大家 llm kernel 的 stack 在 `~/aos-home/llms/stacks/llm` | ✅ |
| 5 | `cp -r $AOS_HOME/templates/kernel/llm-kernel llms/def` | llm kernel（問腦的那台）的定義 | ✅ |
| 6 | `cp -r $AOS_HOME/templates/agent-fsm agents/ann && echo '{"model": "fake"}' > agents/ann/llm.json` | 一隻 agent，先接假腦試流程。要真模型就把 `fake` 換成 `llms/def/kernel.json` 的 `endpoints` 裡的名字 | ✅ |
| 7 | 視窗 A：`cd ~/aos-home && aos-tree-start root` | 起根（前景跑，Ctrl-C＝整棵停）。殼裡帶著別棵樹的 `AOS_*` 會被擋下，先做第 2 步 | ✅（放背景跑） |
| 8 | 視窗 B：`cd ~/aos-home/llms && aos-exec --stack stacks/llm def` | 起 llm kernel（另一台 daemon，前景跑） | ✅（放背景跑） |
| 9 | 視窗 C：`cd ~/aos-home && aos-agent -d .stack ctl add --auto-restart -w . agents/ann` | 把 agent 掛到根上；印出它的 stack 位置 | ✅ |
| 10 | `aos-daemon-ctl -d .stack ls` | 看表：`_clock`、`_sweeper`、`ann` 都是 `running` | ✅ |
| 11 | `aos-agent -d .stack --target ann say hello && aos-agent -d .stack --target ann listen --timeout-s 20` | 問一句、等答案；假腦回 `FAKE ANSWER to: hello …` | ✅ |
| 12 | `aos-daemon-ctl -d ~/aos-home/.stack shutdown && aos-daemon-ctl -d ~/aos-home/llms/stacks/llm shutdown` | 關樹（子項睡下、記在表上）；再起＝第 7、8 步，睡下的自己醒 | ✅ 關；再起沒試 |

之後要加你的中心 agent（`eca_main`，Claude Code 那種）與領班：抄 `$AOS_HOME/templates/eca-claude`，寫法照 [11-12 ops-notes ⑤⑦](../12/ops-notes-to-aos.md)；這次沒試（不接真模型）。「根＋領班」一行抄好的範本你裁了先不做（路徑-9 A）。

## 之後換版本：關、拉、編、開（沒實跑）

| 指令 | 說明 |
|---|---|
| 第 12 步那兩行 | 先關樹 |
| `git -C ~/repo/aos pull`（或 `checkout <commit>`） | 換程式；退回就 checkout 舊的 |
| `(cd ~/repo/aos/proto8/impls && cmake --build build -j8)` | 只有 C++ 有改才真的編，沒改幾秒就過 |
| 第 7、8 步 | 再起 |

## 要知道的

- **改 repo＝改樹**：樹跑的就是 repo 那份，你在 repo 存檔、`git pull`、`cmake --build`，下一次被叫到就是新的。想讓樹停在某一版，就別在樹跑著時改 repo（這是你選路徑-2 B 的代價；要釘版就回頭用 worktree）。
- **stack 帳的格式**：新 commit 若改了 stack 裡的帳或名冊（例 `subagents.json`）的格式，換版本前要先收子或重建；commit 訊息要寫明。這跟找法無關，換版本時要人看一眼。
- **全景頁 aos-frontend**（選配的網頁外掛；11-17 從 `cmd/aos-view` 搬到 `proto8/frontend/`、改名 aos-frontend，舊名打不到了）：執行檔在 `$AOS_HOME/frontend/bin/aos-frontend`，`source env.sh` 之後直接打 `aos-frontend`。它的 systemd 範例是 `frontend/systemd/aos-frontend.service`，裡面寫 `~/repo/aos/proto8` 與 `~/aos-home`，跟你的位置不同就自己改；以前照舊範例裝過 `aos-view.service` 的，要換成新的檔名與指令。它的資料夾 `~/.aos/view` 沒改名，照舊用。v2 的 `dist/` 不在 git，要在有 Node 的機器照 `frontend/ui/v2/README.md` 建。
- 只是開發、不起樹：同樣 `source ~/repo/aos/proto8/env.sh` 就好。
