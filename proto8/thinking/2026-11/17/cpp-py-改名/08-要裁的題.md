# 要你裁的題（15 題）

已經定的（不再問）：原始碼在 `cpp/`、`py/`；成品與入口在 `bin/ lib/ include/`，由 Python 寫的安裝腳本在 repo 裡原地產生；更新＝停、pull、重裝、重新複製、重開；`cmd` 只留薄入口；不考慮 pip；`AOS_HOME` 指固定的家、`env.sh` 是補充。

## L-1　執行期認哪一份（最要緊）

- **A 只認安裝產物（推薦）**：`install.py` 把 `py/` 抄成 `lib/`；跑的只看 `bin/ lib/`。規則一句話沒有例外、pull 後不會新舊混搭、跑著的樹吃不到改到一半的程式；開發時每改一次要重裝，有兩份。
- B 入口直接用 `py/`：存檔即生效、只有一份；`lib/` 只剩 C++ 的 `.a`、形同虛設，pull 後到重裝前 Python 新 C++ 舊。
- C `lib/` 放連結指回 `py/`：看起來滿、其實一份；同 B，外加兩種路徑算位置的層數不同。

## L-2　「資料夾＝程式」的工具怎麼擺

- **A 收一層：`py/tools/{base,aos,agent}`（推薦）**：指示詞 `/lib/tools/base/read`；模組與工具一眼分開；約 190 處指示詞插一段。
- B 照現在：`py/base`、`py/aos`、`py/agent`：指示詞 `/lib/base/read` 一字不改（223 處全省）；工具群 `aos/` 與套件 `aos/` 同層同名，要有一個改名。
- C 頂層 `tools/`：指示詞最短；頂層多一個夾，跟「原始碼在 `py/`」不合。

## L-3　「C++這塊也先不考慮vcpkg, cmake啥的」怎麼讀

- **A 照舊用 cmake＋vcpkg 編，10 份 CMakeLists 各改一行「成品寫到哪」（推薦）**：成品只有一處；不做 presets、`install()`、套件化。
- B CMake 一行都不動：成品照舊寫在各專案的 `bin/`、`lib/`，`install.py` 再抄到頂層。零風險；`cpp/` 裡留著一份執行檔，測試可能誤吃到它。
- C 你的意思是要換掉 cmake：要另開規劃，這份沒涵蓋。

## L-4　頂層 `include/`

- **A `install.py` 抄各專案的公開標頭（推薦）**：跟 `lib/` 同一個道理；現在沒有人用這份。
- B 標頭直接搬到頂層（進 git）：`include/` 不再是產物；標頭與實作分兩棵樹、11 份 CMakeLists 要改。
- C 先不設：你說的三個夾缺一個。

## L-5　`cmd/` 夾留不留

- **A 收掉（推薦）**：邏輯在 `py/aos/apps/`，入口由 `install.py` 照 `py/entries.json` 生進 `bin/`；頂層進 git 的剩 7 夾。
- B 留 `cmd/` 放手寫的薄入口（進 git），`install.py` 抄到 `bin/`：對上你最早說的七塊裡有 `cmd/`；21 支幾乎一樣的 5 行檔要人顧。

## L-6　`cmd` 裡不是程式的東西（aos-view 的 `ui/ web/ systemd/ aide-def/`、各支 README、aos-sandbox 的 `examples/`）

- **A 跟著應用進 `py/aos/apps/<名>/`（推薦）**：一個應用的東西在一起；執行期要用的跟著抄進 `lib/`。
- B 另開 `share/`（原始碼在 `py/share/<名>`，裝到頂層 `share/`）：最像安裝包；多一個產物夾、一個應用分兩處。

## L-7　`env.sh` 放哪、`AOS_HOME` 沒設怎麼辦

- A 只在家裡：`source $AOS_HOME/env.sh`；樹裡不放。跟「cd過去source env.sh」對不上。
- B 隨範本抄完整一份到樹裡：對上你的話；程式更新後樹裡那份是舊抄本，要重新複製。
- **C 樹裡一份三四行的，轉去 `source "$AOS_HOME/env.sh"`（推薦）**：對上你的話；真正內容在家裡，樹裡那份幾乎不過時。
- 三個選項共同的小題：`AOS_HOME` 沒設時——**報一行錯、不猜（推薦，照 N-63）**，或家裡的 `env.sh` 用自己的位置補上（方便只開發不起樹的人）。

## L-8　`templates`、`knowledge`、`docs`、`thinking`、`archive`

- **A 全留頂層（推薦）**：它們不用編、原地就是成品；`$AOS_HOME/templates`（31 處）、`$AOS_HOME/knowledge` 都不用改。
- B `templates`、`knowledge` 進 `share/`：最像 `/usr/share`；路徑全部要改，沒有功能上的收益。

## L-9　Python 被 import 的模組收成一個 `aos` 套件嗎

- **A 收：`from aos import flags`（推薦）**：對外只露一個名字；改 483 行 import。
- B 不收：模組平鋪，`import aos_flags` 照舊；`cmd` 搬來的應用也平鋪，一層六七十個名字。
- C 收，但套件叫別的名字（例如 `aoslib`）：避開跟工具群 `aos`、跟公司機舊 `.pth` 那個空殼同名；L-2 選 B 時必選這個。

## L-10　「起手範本」（一包抄好：根＋樹裡的 `env.sh`＋一隻 agent）

- **A 做（推薦）**：新使用者第 4 步變一行 `cp -r`；eca 版、API 版各一包給你的教學用。你今天裁過「根＋領班範本先不做」（路徑-9 A），這是因為有了別的使用者而重開。
- B 不做：教學裡寫四行 `cp -r` 與兩行設定（今天步驟單的第 3～6 步）。

## L-11　更新後怎麼讓人知道樹裡哪些過時（選項細節在 [14](14-更新與重新複製.md)）

- **A 人自己 `diff -r` 範本與樹＋動到範本的 commit 訊息寫明要重抄哪些（推薦）**：都是現成的；靠紀律。
- B 定義少帶程式（格借家裡的）：過時的東西直接變少；動到 P-27，是條文的事。
- C 之後另做一支檢查工具：這份不設計。

## X-1　分幾步

- **A 七步（推薦）**：[07](07-施工單.md)；每步單獨交、單獨驗。
- B 兩大步：S1～S3 一包、S4～S6 一包。
- C 只做 S1～S3 就停。

## X-2　文字跟到哪

- A 全跟（條文、wf、README）：連結不斷；多動約 380 個檔，條文你說以後要大修。
- B 只改程式與定義：最省；agent 讀知識庫與 README 會照舊路徑打錯。
- **C 只跟 agent 會照著做的（推薦）**：知識庫、各夾 README、`AGENTS.md`、規矩卡、`dev-env`、重建步驟單；條文內文與其他 wf 文件先放。

## X-3　小夾各去哪（選項見 [06 第 5 點](06-卡點.md)）

- **全選 a（推薦）**：`lib/schema`→`py/schema`、`lib/docs`→`py/docs`、`lib/tests`→`py/tests`（工具的測試留在各工具夾）、`impls/docs`→`cpp/docs`、`impls/cmake`→`cpp/cmake`、`cmd/docs`→`py/docs`。跟著自己的程式走，連結重算最少。
- b 三個 `docs` 併進頂層 `docs/`：說明集中一處；連結約 100 處重算。

## X-4　兩件記一筆的

- **A 舊的 `cmd/install.sh`（連進 `~/.local/bin`）收掉、由 `install.py` 取代；`directive json fsm llm` 四個不算 Linux 機制的 C++ 專案不動（推薦）**。刪檔要你說。
- B 舊腳本留著當選配：`PATH` 只剩一夾後幾乎沒用處，多一支要顧。
- C 把 `json`、`llm` 排進「之後改寫成 Python」：對上你說的「C++ 放與 linux 機制牽扯的」；是另一件工，這份沒估。
