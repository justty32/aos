# 安裝腳本與新使用者流程

你的原話（11-17 下午，逐字）：

- 「我目前來說所謂的安裝，我預期其他使用者，他們就是git clone下來，跑個安裝腳本，編譯一下C++(可能會需要vcpkg, cmake, gcc等)，python也稍微處理一下，然後bin/,lib/include就都會有東西，最後他只需要設個環境變數AOS_HOME就能開始了。也就是從template中複製一些東西到指定地點，然後cd過去source env.sh，他就能開始玩了，到時候我會準備一些eca版、API版的教學」
- 「啊至於以後git repo有更新的話，那就是git pull下來，重跑安裝腳本，然後就一切搞定。頂多跟他們說要先把正在跑的東西停掉，弄好後有些東西要重新複製過去，然後再重開就好。env.sh主要是一些要附加到PATH之類的東西，而AOS_HOME則是指向一些固定的東西，env.sh主要是補充。」
- 「安裝腳本...可以的話也用python寫？」

## 新使用者六步（主案做完後的樣子；草稿，沒實跑）

| # | 指令 | 說明 |
|---|---|---|
| 1 | `git clone <repo> ~/aos && cd ~/aos/proto8` | 拿程式 |
| 2 | `python3 install.py` | 查相依 → 編 C++ → 填 `bin/ lib/ include/`。全新約 3～4 分鐘 |
| 3 | `echo 'export AOS_HOME=~/aos/proto8' >> ~/.bashrc`，開新視窗 | 一台機器設一次；`install.py` 最後會印出這一行 |
| 4 | `cp -r $AOS_HOME/templates/<起手範本> ~/my-tree` | 抄一棵樹的定義到你要的地方（現在沒有一包抄好的範本，見 [14](14-更新與重新複製.md)） |
| 5 | `cd ~/my-tree && source env.sh` | 把 `$AOS_HOME/bin` 放上 `PATH` 等補充設定 |
| 6 | `aos-tree-start root`，另一個視窗掛 agent、說話 | 同今天步驟單第 7～11 步 |

教學的兩條路各從哪個範本起（你之後自己寫）：**eca 版**＝`templates/eca-claude`；**API 版**＝`templates/agent-fsm`＋`templates/kernel/llm-kernel`。

## 安裝腳本 `install.py`

| 問 | 答 |
|---|---|
| 叫什麼、放哪 | `proto8/install.py`，跟 `env.sh` 並排在家的頂層 |
| 用什麼寫 | Python，只用標準庫。第一件事是查 Python 版本，不夠就一行 `install.py: error: DepMissing python >= 3.10 (found 3.8)`、退 1。為了讓舊版 Python 也能印出這行，腳本本身只用很舊就有的語法 |
| 最低 Python | **3.10**（`lib/metainfo.py` 用了 `dict \| None`，3.9 會在 import 時就壞）；跑測試要 3.11（測試用 `tomllib`）。公司 WSL 是 3.12.3 |
| 做哪幾件 | ① 查相依，缺什麼一行英文講（查哪些見文末「外部依賴」） ② 先清掉 `bin/ lib/ include/` ③ 叫 `cmake` 編 `cpp/`，執行檔進 `bin/`、`.a`／`.so` 進 `lib/` ④ 抄各專案公開標頭到 `include/aos/` ⑤ 抄 `py/` 的 `aos/ tools/ packs/ schema/` 到 `lib/`（不抄 `tests`、`docs`、`__pycache__`） ⑥ 照 `py/entries.json` 在 `bin/` 產生 Python 入口 ⑦ 印下一步（英文） |
| 可不可以重跑 | 可以，而且**重跑的結果跟全新安裝一樣**：第 ② 步先清，所以表上拿掉的指令、原始碼刪掉的檔不會殘留。C++ 的中間檔在 `cpp/build/`，不清，所以只重編有改的（沒改的話重新連結幾秒） |
| 失敗怎麼講 | 一行 `install.py: error: 代號 原因`、退 1。例：`BuildFailed cmake --build exited 2, see cpp/build/build.log` |
| 失敗時 | 因為先清再裝，失敗＝`bin/` 是空的或不完整，不能用，但不會新舊混搭。另一種做法是「蓋上去、失敗留舊的」——能繼續用舊版，但可能一半新一半舊。更新前本來就要先停樹，所以推薦先清 |
| 動不動 repo 外面 | 不動。只寫 `proto8/bin lib include` 與 `cpp/build` |
| 要不要測試 | 要，一支就夠：在暫存夾放一個迷你的 `py/` 與假的 `cmake`，跑 `install.py`，檢查 `bin/ lib/` 的內容、重跑結果一樣、缺相依時的錯誤行。放 `py/tests/test_install.py` |
| 還是得用 shell 的 | 只有 `env.sh`：它要改「你現在這個視窗」的 `PATH`，一定得被 `source`，Python 做不到 |
| 跟現在的 `cmd/install.sh` | 那支是「把指令連進 `~/.local/bin`」，今天已改成選配；`PATH` 只剩一夾之後沒有用處。`install.py` 取代它，舊的收掉要你說（題 X-4） |

沒有「不適合用 Python」的理由：它做的事（查版本、叫 `cmake`、抄檔、寫小檔）標準庫都有；Python 本來就是 aos 的必要相依。

## `AOS_HOME` 與 `env.sh` 的分工

你講的分工：`AOS_HOME` 指向固定的東西（裝好的那個家），人設一次；`env.sh` 是補充，主要是加 `PATH`。

**今天的 `proto8/env.sh` 對不上這個分工**，三處：

| 今天的 `env.sh` | 照你的分工 |
|---|---|
| 清掉**所有** `AOS_*`（含 `AOS_HOME`），再從自己的位置設 `AOS_HOME` | `AOS_HOME` 是人設的，`env.sh` 不決定它；清 `AOS_*` 時要跳過 `AOS_HOME`（清其他的仍要留：11-13 那次事故就是殼裡帶著別棵樹的 `AOS_STACK`） |
| 掃 `cmd/*/bin`、`impls/*/bin` 加 30 段 `PATH` | 加一段 `$AOS_HOME/bin` |
| 檢查 `impls/aos-exec/bin/aos-exec` 在不在，不在就提示 `cmake` 指令 | 檢查 `$AOS_HOME/bin/aos-exec`，不在就提示 `python3 install.py` |

`AOS_HOME` 沒設時 `env.sh` 怎麼辦，與 `env.sh` 放哪，合成一題（L-7）：

| | A：只在家裡 | B：隨範本抄到樹裡（完整一份） | C：樹裡一份薄的，轉去家裡那份（推薦） |
|---|---|---|---|
| 人打的 | `source $AOS_HOME/env.sh` | `cd 樹 && source env.sh` | `cd 樹 && source env.sh` |
| 樹裡的 `env.sh` | 沒有 | 完整：清別棵樹的 `AOS_*`、加 `PATH` | 三四行：`AOS_HOME` 沒設就報錯；`source "$AOS_HOME/env.sh"`；這棵樹自己的補充 |
| 對上「cd過去source env.sh」 | 對不上 | 對上 | 對上 |
| 程式更新後 | 沒事 | 樹裡那份是舊抄本，屬於「要重新複製」的東西 | 真正的內容在家裡，樹裡那份幾乎不會過時 |
| `AOS_HOME` 沒設 | 報錯一行，不猜（照 N-63「沒設就明講」） | 同左 | 同左 |

另一個小選項：`AOS_HOME` 沒設時，家裡的 `env.sh` 要不要「用自己的位置補上」。補＝少設一次、只開發不起樹的人方便；不補＝完全照你的分工、行為只有一種。

## 外部依賴（另一條線在盤）

你的原話（11-17 下午，逐字）：「對了，我想了一下我們的外部依賴，我記得主要就幾個：1. nlohmann json，這是硬性的，不用多說，之所以需要vcpkg主要多虧了他，之後可以看看是否有方法把它直接弄進來，不管是submodule還是啥，讓我們脫離vcpkg。2.cmake，這個也可以考慮看看，或許可以直接走makefile？反正我們C++這塊也沒多少東西。3.cgroup,s6，這些是可選的，主要提供權限、限制相關的東西。4.各種python module，這沒啥好說的，提供requirement.txt就完事了。」

外部依賴的實況與選項（nlohmann json 怎麼脫離 vcpkg、CMake 換不換 Makefile、cgroup／s6、Python 模組與 `requirements.txt`）由線 `deps-1117` 另外規劃，見 [外部依賴](../外部依賴.md)；這份不重複。

對這份的影響只有兩點：

- `install.py` 的第 ① 步「查相依、缺什麼用一行英文講」查哪些、怎麼講，以那一份為準。這條線盤到的現況只有：C++20（公司 WSL 的 g++ 13.3 編得過，實測）、CMake ≥ 3.21（每份 CMakeLists 第一行）、nlohmann-json 是唯一的外部 C++ 函式庫且現在經 vcpkg 拿、Python 最低 3.10、第三方 Python 模組只看到選用的 `jsonschema`、公司 WSL 沒有 `pip`。
- 如果那邊定了「不用 CMake」，[04](04-主案-安裝包形狀.md) 的題 L-3 與 [07](07-施工單.md) S2「10 份 CMakeLists 各改一行」跟著換成那邊的編法；`install.py` 的其他步驟不變。
