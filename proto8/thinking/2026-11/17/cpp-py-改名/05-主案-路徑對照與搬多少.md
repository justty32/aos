# 主案：路徑對照與搬多少

照 [04](04-主案-安裝包形狀.md) 的推薦（甲：執行期只認安裝產物；工具收一層 `tools/`）寫。proto8 當沒有舊版：一次全換、不留舊名、不留相容連結；已經抄出去的舊定義重抄。

## 寫死的 `$AOS_HOME/…` 改成什麼

| 現在的寫法 | 處數 | 改成 |
|---|---|---|
| 指示詞 `"$path":"/lib/base/…"`、`/lib/aos/…`、`/lib/agent/…` | 約 190 | `/lib/tools/base/…`、`/lib/tools/aos/…`、`/lib/tools/agent/…`（插一段 `tools/`） |
| 指示詞 `"$path":"/lib/packs/…"` | 35 | **不用改** |
| 純文字 `$AOS_HOME/lib/base/read` 這類（知識庫教 agent 打的、README） | 約 20 | `$AOS_HOME/lib/tools/base/read` |
| 當 Python 路徑用的 `$AOS_HOME/lib`、`os.environ["AOS_HOME"], "lib"` | 8＋6 | **不用改**（`lib/` 底下就是 `aos` 套件） |
| `$AOS_HOME/impls/aos-exec/bin/aos-exec`（`env.sh`） | 5 | `$AOS_HOME/bin/aos-exec` |
| `$AOS_HOME/cmd/aos-view/bin/aos-view` | 3 | `$AOS_HOME/bin/aos-view`（或裸名字，`PATH` 上有） |
| `$AOS_HOME/cmd/aos-view/ui/v2/dist/`、`$AOS_HOME/cmd/aos-agent/stack.gitignore` | 2 | `$AOS_HOME/lib/aos/apps/view/ui/v2/dist/`、`$AOS_HOME/lib/aos/apps/agent/stack.gitignore` |
| `$AOS_HOME/templates/…`（31）、`$AOS_HOME/knowledge/…`（4） | 35 | **不用改** |

`impls`、`cmd`、`templates`、`knowledge` 都沒有指示詞形（0 處），只有純文字。因為安裝後 Python 還是住在叫 `lib` 的夾，**這個主案比「`lib` 改名 `py` 且就地跑」便宜**：定義與範本裡的 `lib` 字樣大半不用動。工具如果不收進 `tools/` 一層（題 L-2 的 b），223 處指示詞一處都不用改。

**一定要跟、漏了會出事的三處**（不是文字替換能自動對的）：

| 哪裡 | 現在 | 要變成 | 漏了會怎樣 |
|---|---|---|---|
| `lib/agent/guard/scope.py` 的禁區表 | `("lib","cmd","templates","knowledge","impls")` | `("bin","lib","include","cpp","py","templates","knowledge")` | agent 可以寫進家裡的新夾 |
| aos-sandbox 的唯讀掛載 | 自己拼 `<家>/lib` | 整個家唯讀（今天交接已記「規劃是整個家」），至少 `bin`＋`lib` | 沙箱裡沒有工具或指令 |
| `wf/tools/index_gen.json` 夾名表、`index_gen_desc.json` 的 191 個鍵 | `proto8/lib`、`proto8/impls` | `proto8/py`、`proto8/cpp`；`bin lib include` 是產物，不掃 | 生成器掃不到、報缺描述 |

## `py/` 裡怎麼不再混成一鍋

```
py/
  aos/             ← 唯一被 import 的：一個套件
    flags.py ws.py tool_io.py observed.py …    原 lib 頂層 27 支（aos_ 前綴拿掉）
    daemon_ctl/  agentlib/  comm/
    apps/agent/ apps/eca/ apps/view/ …          cmd 搬來的 21 支
  tools/           ← 被當程式跑的：base/（32） aos/（21） agent/（37），各帶自己的 tests/
  packs/           ← 純資料：18 份工具包清單
  schema/          ← 純資料：comm/1
  tests/           ← aos 套件的測試（原 lib/tests 25 支＋apps/ 底下 108 支）
  docs/  README.md  entries.json
```

| 性質 | 以前 | 以後 | 怎麼分辨 |
|---|---|---|---|
| 被 import | `lib/*.py`、`lib/agent/*.py`、`cmd/*/aos_x/` 三處 | `py/aos/` 一處 | `from aos import …` |
| 被當程式跑 | `lib/base` `lib/aos` `lib/agent`（跟模組混） | `py/tools/` | 有 `_entry` |
| 資料 | `lib/packs` `lib/schema` | `py/packs` `py/schema` | 只有 JSON |

三個小地方要注意：

- 套件 `aos` 與工具群 `tools/aos/` 同名但不同層，不會認錯（實測：有 `__init__.py` 的一定贏）。公司機那個舊 `.pth` 現在會讓 `import aos` 拿到一個空殼（實測），重建樹時要先移走、測試帶 `PYTHONNOUSERSITE=1`。
- `lib/` 放上 Python 路徑後，`tools`、`packs` 這兩個夾名理論上也 import 得到（空殼）。沒有程式會去 import 它們。
- 「先不考慮 pip」：`pyproject.toml` 不放。哪天要，加一個檔就好，不用再搬。

## `cmd` 的邏輯搬進 `py`：要動多少

| 指令 | 程式行 | 現在的形狀 | 搬的工 |
|---|---|---|---|
| aos-agent | 4,505 | 已是套件（27 支） | 整包移到 `py/aos/apps/agent/`，改 import |
| aos-eca | 1,941 | 已是套件（12 支），兩個入口 | 同上 |
| aos-kit、aos-comm、aos-feedback、aos-mailbox | 570、506、399、428 | 已是套件 | 同上 |
| aos-view | 3,107 | `bin` 單檔＋`ui/ web/ systemd/ aide-def/` | 單檔改成模組；`viewbin-1117` 交完才能動 |
| aos-tools、aos-daemon-ctl | 1,163、753 | `bin` 單檔 | 單檔改成模組 |
| 其餘 12 支 | 合計約 3,300 | `bin` 單檔 | 同上（各是一支小檔） |
| **合計** | **約 16,700** | 6 個套件＋15 個單檔 | 約 80 個程式檔、108 支測試、約 150 個其他檔搬家；套件內部 import 約 300 行（估）；測試裡算路徑的約 108 處 |

入口不再手寫：`py/entries.json` 一行一支（指令名 → 模組），`install.py` 生出這樣的檔放進 `bin/`：

```python
#!/usr/bin/env python3
# aos-agent - generated by install.py; the logic is in lib/aos/apps/agent.
import os, sys
sys.path.insert(0, os.path.join(os.path.dirname(os.path.dirname(os.path.realpath(__file__))), "lib"))
from aos.apps.agent.main import main
main()
```

15 個單檔搬的時候要逐支看一件事：測試多半是「把指令當子行程跑」，不受影響；少數直接 import 單檔內部函式的要改 import。
