# 施工單草稿（AI 寫的，題目裁完才準；沒有動手）

照的答案：L-1 甲（執行期只認安裝產物）、L-2 a（工具收一層 `tools/`）、L-7 C（樹裡一份薄的 `env.sh`）。你選別的，對應那步要改寫，其餘步不受影響。

## 一張表：七步

每一步是一個（S5 是一串）可單獨交的 commit；驗收都是「在乾淨複本上 `install.py` 之後，紅的清單不比 S0 多」。

## 每一步都要跟的四樣（漏了會壞）

1. `wf/tools/index_gen.json` 的夾名表與 `index_gen_desc.json` 的鍵（191 個帶 `proto8/impls`、`proto8/lib`）：路徑變了鍵要跟；`bin lib include` 是產物，不列進去。
2. `guard/scope.py` 的禁區表：S1 加 `cpp`、S2 加 `bin include`、S3 加 `py`、S5 拿掉 `cmd`。
3. aos-sandbox 的唯讀掛載（現在自己拼 `<家>/lib`）。
4. 知識庫裡教 agent 打的路徑與 `proto8/README.md`、該夾 README：跟那一步一起改。

## 逐步

### S0　基準

- 在 `git archive` 抄出的乾淨複本上編（實測約 3 分鐘、4 核），逐夾 `PYTHONNOUSERSITE=1 python3 -m unittest discover -s <tests 夾>`，記下跑了幾支、哪幾支本來就紅。這次抽樣的基準在 [09](09-實測紀錄.md)。
- 公司機舊的 `.pth` 要先移走（或一律帶 `PYTHONNOUSERSITE=1`），不然壞了也會綠。
- 從這步起定一條：**測試一律「抄出來→裝→測」**，S2 之後「裝」就是 `install.py`。

### S1　`impls` → `cpp`

- 動：`git mv proto8/impls proto8/cpp`；`env.sh`（4 處）、`cmd/install.sh`（7 處）；約 60 支測試裡的 `"impls"`；兩處錯誤訊息；CMake 的註解與選項名 `AOS_IMPLS_ALL`；四樣必跟的。C++ 原始碼與 CMake 邏輯零改。
- 驗：重編（等於全新編）；全部測試。

### S2　`install.py` 第一版＋C++ 成品進頂層

- 新增 `proto8/install.py`（做法見 [13](13-安裝腳本與新使用者流程.md)）與它的一支測試。這版只管 C++：查相依、清 `bin/ include/`、叫 `cmake`、抄標頭。
- 10 份 CMakeLists 各一行：執行檔從 `<專案>/bin` 改寫到頂層 `bin/`。`.a` 這步先留在各專案（頂層 `lib/` 還被 Python 原始碼佔著），S3 再搬。
- `.gitignore` 加 `/proto8/bin/`、`/proto8/include/`；`env.sh` 的 `PATH` 加 `$AOS_HOME/bin`、拿掉 `cpp/*/bin`；19＋6 支吃 `<專案>/bin` 的測試改從 `PATH` 找。
- `cmd/install.sh` 這步先不動（題 X-4 裁了再收）。
- 驗：刪掉各專案舊的 `bin/` 後 `install.py`，`ls bin` 有 9 支；全部測試。

### S3　換手：`lib` 從原始碼變產物

- `git mv`：27 支模組＋`daemon_ctl/`＋`agent/` 的 22 支模組到 `py/`（先平鋪，`import` 一行不改）；`base/ aos/ agent/` 到 `py/tools/`；`packs/ schema/ tests/ docs/` 到 `py/`。
- `install.py` 加：抄 `py/`（不含 `tests docs`）成 `lib/`；`.a`／`.so` 的輸出位置改到頂層 `lib/`；`.gitignore` 加 `/proto8/lib/`。
- 82 個工具的找法：從「往上找名字叫 `lib` 且有 `tool_io.py` 的夾」改成「往上找有共用模組的那一層」（在 `py/` 與 `lib/` 都要成立）；77 處錯誤字串；約 190 處指示詞插 `tools/`；22 個 `cmd` 入口改找 `lib/`（產物）；約 260 支測試裡的路徑。
- 做法建議：先寫一支一次性的替換腳本，在暫存複本上跑到測試不比基準紅，再對 repo 跑同一支（腳本不進 repo）。機械替換能走多遠，[09](09-實測紀錄.md) 有試。
- 驗：全部測試；另用假腦起一棵暫存樹走一遍（指示詞只有真的起樹才驗得到）；故意改一支 `py/` 的工具不重裝，確認跑到的是舊的、重裝後是新的。

### S4　收成套件 `py/aos/`

- 49 支平鋪模組移進 `py/aos/`（`aos_flags.py`→`aos/flags.py`；`agent` 的進 `aos/agentlib/`）；483 行 import 改成 `from aos import …`（`cmd` 129、工具 217、互引 43、測試 53、範本 41）；找法只剩「加一層」。
- `templates/tool-python` 的「旁邊帶一份 `tool_io.py`」慣例要定新說法（旁邊帶 `aos/` 夾，或一律走 `$AOS_HOME/lib`）。
- 驗：全部測試；`PYTHONNOUSERSITE=1 python3 -c "import aos"` 在家外要失敗（沒有東西偷偷把它放上路徑）。

### S5　`cmd` 的邏輯逐支搬

- 順序：先小的單檔試水（aos-clock 104 行、aos-mcp-launch 45 行），再 6 個已是套件的，再大的單檔（aos-tools、aos-daemon-ctl），**aos-view 最後**（等 `viewbin-1117` 交完）。
- 每支：邏輯到 `py/aos/apps/<名>/`、測試到 `py/tests/apps/<名>/`、README 與非程式的東西跟著；`py/entries.json` 加一行；`cmd/<名>/` 拿掉。`env.sh` 在過渡期同時掃 `bin/` 與剩下的 `cmd/*/bin`。
- 最後一支搬完：`cmd/` 剩的 `docs/`、README、`install.sh` 照題 X-3、X-4 處理；測試裡拼 `cmd/<名>/bin/<名>` 的（`lib` 測試 32 支等）改從 `PATH` 找；aos-view 的 systemd 單元路徑；禁區表拿掉 `cmd`。
- 驗：每支交之前跑那一支的測試＋全部測試。

### S6　`env.sh` 的分工

- 家裡的 `env.sh`：清 `AOS_*` 時跳過 `AOS_HOME`、不再自己設它（沒設時報錯或用自己位置補，看題 L-7）；`PATH` 只加 `$AOS_HOME/bin`；`bin/aos-exec` 不在就提示 `python3 install.py`。
- 樹裡那份薄 `env.sh` 放進範本；要「起手範本」的話（題 L-10）這步做。
- 驗：新開一個乾淨的殼照 [13 的六步](13-安裝腳本與新使用者流程.md) 走一遍；`echo $PATH` 只多一段。

### S7　收尾

- 文字照題 X-2 的範圍跟；[重建步驟單](../重建步驟單.md) 改寫成六步＋更新五步；`wf/workflows/dev-env`、規矩卡硬規則第 5 條（「改 repo＝改活樹」要改口成「`install.py` 之後才生效」）。
- 最後在全新的乾淨複本上從 `git clone` 那一步照步驟單走完。

## 會撞到的線與時機

- `viewbin-1117` 正在動 `cmd/aos-view/`：等它交完再開 S1，或 S1～S4 先跳過 aos-view 的檔、S5 再補。
- 你要重建 `~/aos-home`：等 S3（指示詞定了）之後最省，等 S6（`env.sh` 與起手範本定了）之後最完整；太早重建，抄出去的定義要重抄。
- S3 之後公司機那條「改 repo＝改活樹」不再成立，活樹旁的硬規則第 5 條要跟著改口。
