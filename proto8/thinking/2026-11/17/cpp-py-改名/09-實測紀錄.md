# 實測紀錄

都在公司 WSL 的 `~/.aos/scratch/cpppy-1117/`（`git archive HEAD` 抄出的乾淨複本；Python 3.12.3、g++ 13.3、cmake 3.28）。repo、`~/aos-home`、`~/repo/aos`、系統的 Python 環境都沒碰；沒起任何使用者的 daemon；暫存沒刪。測試一律帶 `PYTHONNOUSERSITE=1`。

## 一張表：試了什麼、結果

| # | 試什麼 | 結果 | 對規劃的意義 |
|---|---|---|---|
| 1 | 基準：原樣編、跑一批測試 | 編得過；跑 968 個測試，3 敗 2 錯（`aos-daemon` 2 錯、`aos-tools` 1 敗、`aos-agent` 2 敗）；`templates/tests/agent-fsm` 超過 5 分鐘被我切掉、沒結果 | S0 的基準長這樣：本來就有幾個紅的 |
| 2 | `impls`→`cpp`、`lib`→`py` 兩個夾改名，同時 10 份 CMakeLists 的成品位置用一行 `sed` 改到同一個夾 | C++ 全部編得過，9 支執行檔都在同一個夾 | 「成品寫到哪」真的只是一行；改名不影響 C++ |
| 3 | 改名後什麼都不修，跑 Python 那邊的測試 | 幾乎全紅：`py/tests` 跑不出結果；9 個工具的測試 103 個裡 81 敗 105 錯（基準是 364 個全綠） | 82 個工具靠「找名字叫 `lib` 的夾」，夾一改名就全部找不到 |
| 4 | 再用一支約 10 條規則的 `sed` 機械替換（525 個檔） | Python 那邊回到 364 個裡只剩 1 敗；C++ 專案的測試大片紅（它們吃 `<專案>/bin`，我把成品搬走了）；`aos-tools` 7 敗（基準 1 敗）、`aos-agent` 4 敗 2 錯（基準 2 敗） | 機械替換能救回大部分，但有三類救不到：吃自己專案 `bin/` 的測試、少數特殊寫法、要真的起樹才驗得到的指示詞 |
| 5 | 套件 `aos`（有 `__init__.py`）與同名工具夾 `aos/`（沒有）同時在路徑上，工具夾排前面 | `import aos` 拿到的是套件 | 兩個同名不會認錯 |
| 6 | 系統的 `python3 -c "import aos"`（不帶 `PYTHONNOUSERSITE`） | **成功**，拿到一個空殼，指到 `~/repo/aos/proto8/lib/aos` | 公司機舊的 `.pth` 還在作用；測試不帶那個變數會被它騙 |
| 7 | `python3 -m pip`、`import ensurepip` | 都沒有 | 公司 WSL 現在不能 `pip install`、不能建完整的 venv |
| 8 | 這台 Windows repo 的 `git config core.symlinks` | `false`（repo 裡已有 4 個連結檔） | 進 git 的連結在 Windows 工作樹是文字檔，所以不推薦用連結 |
| 9 | 暫存 git 倉試 `bin/` 混放的兩種 `.gitignore` 寫法 | 都可行（逐名列；整夾忽略＋`git add -f`） | 定案後 `bin/` 整夾不進 git，這題不存在了，留作紀錄 |
| 10 | 抄整個 `lib/`（559 檔、4.8 MB）花多久；C++ 沒改時重編花多久 | 0.09 秒；0.34 秒 | 「改了要重裝」的那一步，C++ 沒動時不到一秒 |
| 11 | 全新編 C++ 花多久 | 兩份複本各約 3 分鐘（4 核，同時在跑別的） | `install.py` 第一次約 3～4 分鐘 |

## 沒測的

| 沒測 | 為什麼 |
|---|---|
| `install.py` 本身 | 沒寫（只規劃） |
| 「抄 `py/`→`lib/` 之後整套跑得起來」 | 需要先做完換手那步；現在的 `lib/` 抄到別處能跑是今天以前「抄樹」就在做的事，但新擺法（`aos/`、`tools/`）沒試 |
| 成品寫到**頂層** `bin/`（實驗寫的是 `cpp/build/bin`） | 同一行的不同值，沒另外編一次 |
| 安裝時抄標頭到 `include/` | 沒寫 |
| 收成套件 `aos` 後的 483 行 import | 只用 4 支模組試了「放進套件能不能 import」（`tool_io` 可以） |
| 薄入口＋`aos/apps/` | 沒拿真的指令試 |
| 用假腦起樹驗指示詞 | 時間不夠；今天 `path-1117` 那條線的步驟單有現成做法 |
| 不經 vcpkg 編 | 歸 `deps-1117` |
| 家機 | 沒看到 |

## 子 agent 盤點的抽核

三個子 agent（兩個 opus、一個 sonnet）唯讀盤 `impls/`、`lib/`＋`cmd/`、寫死路徑的處數。我核過的：執行檔是 9 支不是 10 支（`util`、`inst` 沒有）、`PATH` 30 段、30 個指令名沒有重複、`$AOS_HOME/cmd|templates|knowledge` 的處數、`lib/base/read/_entry` 與 `cmd/aos-agent/bin/aos-agent` 的找法原文。其餘數字沒逐項核，量級可信。
