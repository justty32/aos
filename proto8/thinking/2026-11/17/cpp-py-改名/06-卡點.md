# 六個卡點（方向題：只攤選項與後果）

你已經定的：原始碼在 `cpp/`、`py/`；成品與入口在 `bin/`、`lib/`、`include/`，由一支安裝腳本（Python 寫）在 clone 下來的 repo 裡原地產生；更新＝停、`git pull`、重跑安裝、重新複製、重開；`cmd` 只留薄入口；不考慮 pip、vcpkg／cmake 的標準形式；`AOS_HOME` 指固定的家、`env.sh` 是補充。

|---|---|---|---|
| 1 | 執行期認哪一份 | 只認安裝產物（乾淨、改了要重裝）還是入口直接用 `py/`（方便、`lib/` 形同虛設） | L-1 |
| 2 | 工具資料夾怎麼擺 | 收一層 `tools/` 還是照現在（指示詞一字不改） | L-2 |

| 4 | 寫進定義的路徑 | 一次全換、不留相容 | （不是題，見下） |

原任務書的六個卡點裡，「`cmd` 的大塊邏輯搬不搬」你已經答了（只留薄入口）；「規則一 vs 可安裝的 Python 套件」因為不考慮 pip，變成上面的第 1、3 點。

## 1　執行期認哪一份（最要緊）

完整對照表在 [04](04-主案-安裝包形狀.md)。濃縮：

| 選項 | 改了 `py/` 何時生效 | 一支程式幾份 | `lib/` | 主要代價 |
|---|---|---|---|---|
| 甲 只認安裝產物（`install.py` 抄 `py/`→`lib/`） | 重跑安裝之後 | 2 | 滿的 | 開發時每改一次要重裝；沒重裝就跑測試會一半新一半舊；有人改到 `lib/` 的抄本會被下次安裝蓋掉 |
| 乙 入口直接用 `py/` | 存檔就生效 | 1 | 只有 C++ 的 `.a` | `lib/` 形同虛設；`git pull` 後到重裝前 Python 新、C++ 舊，會混搭；跑著的樹吃得到改到一半的程式 |
| 丙 `lib/` 放連結指回 `py/` | 存檔就生效 | 1（兩個路徑名） | 看起來滿 | 同乙，外加程式算位置時兩種路徑層數不同 |

## 2　工具資料夾怎麼擺

原始碼在 `py/`，`lib/` 照抄，所以擺法決定定義裡指示詞的長相。

| 選項 | 指示詞 | 後果 |
|---|---|---|
| a 收一層：`py/tools/{base,aos,agent}` | `/lib/tools/base/read` | 被 import 的（`aos/`）與被當程式跑的（`tools/`）一眼分開；約 190 處指示詞插一段 `tools/` |
| b 照現在：`py/base`、`py/aos`、`py/agent` | `/lib/base/read`（**跟現在一樣**） | 223 處指示詞、知識庫教的路徑全部不用改。但工具群 `aos/` 與 Python 套件 `aos/` 同層同名，必須有一個改名 |
| c 提到頂層 `tools/`（原始碼也是產物，像 `templates`） | `/tools/base/read` | 最短；工具裡的 Python 要回 `lib/` 找套件；頂層多一個夾，而且跟「原始碼在 `py/`」不合 |

## 3　規則一要改口的地方

今天的規則草稿（還沒進條文）：路-1「aos 的程式（`impls cmd lib templates knowledge`）都在它底下」、路-2「家裡的找家裡的：看自己的位置」、路-3「沒有就用 `$AOS_HOME/lib`」、路-6「不往家外放程式」。

| 句 | 主案下 | 要不要改口 |
|---|---|---|
| 路-1 | 夾名變成 `bin lib include`（產物）＋`cpp py`（原始碼）＋`templates knowledge` | 改夾名；補一句「執行期只認產物」 |
| 路-2 | 仍成立，而且因為 `lib/` 與 `py/` 擺法一樣，同一支程式在哪邊都找得到鄰居 | 不用 |
| 路-3 | `$AOS_HOME/lib` 這個寫法照舊有效 | 不用 |
| 路-6 | `install.py` 只寫家裡，不碰家目錄 | 不用 |
| 來源 | 草稿寫「`AOS_HOME` 來源＝人 source 家裡的 `env.sh`」；你現在說「`AOS_HOME` 指向固定的東西、`env.sh` 是補充」 | 改成「人設一次」——這跟 N-63 表原本的寫法（人殼預設、每台設一次）反而一致，條文那格不用動 |

文字要跟到哪（條文、wf、README）是題 X-2。

## 6　分幾步做

`lib/` 這個名字現在是進 git 的 Python 原始碼，做完是不進 git 的安裝產物。換手的那一步（`lib`→`py` 同時 `install.py` 開始產生新的 `lib/`）是整件事最大的一步。

| 選項 | 後果 |
|---|---|
| a 七步（[07](07-施工單.md)） | 每步可單獨交、單獨驗；換手那步約 400 檔內容、480 檔搬位置；中間幾天頂層是過渡的樣子 |
| b 兩大步：先「夾名、安裝腳本、成品位置」（S1～S3），再「套件與 `cmd`」（S4～S6） | commit 少；出事時要在更大的一包裡找 |
| c 只做 S1～S3 就停 | 很快看到 `bin lib include cpp py` 與 `install.py`；`cmd/` 還在、模組還平鋪 |

換手那一步不建議再拆成「先純改名、再分夾」：同一批行（82 個工具的找法、約 190 處指示詞）會改兩次。
