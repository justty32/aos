# 更新流程與「要重新複製的東西」

你的原話（11-17 下午，逐字）：「啊至於以後git repo有更新的話，那就是git pull下來，重跑安裝腳本，然後就一切搞定。頂多跟他們說要先把正在跑的東西停掉，弄好後有些東西要重新複製過去，然後再重開就好。」

## 更新五步（草稿，沒實跑）

| # | 指令 | 說明 |
|---|---|---|
| 1 | `aos-daemon-ctl -d ~/my-tree/.stack shutdown`（有 llm kernel 的再關那台） | 先停。子項睡下、記在表上 |
| 2 | `git -C ~/aos pull` | 拿新程式。這時 `bin/ lib/` 還是舊的完整一版，不會新舊混搭 |
| 3 | `cd ~/aos/proto8 && python3 install.py` | 先清再裝，結果跟全新安裝一樣；C++ 只重編有改的 |
| 4 | 把樹裡過時的東西重新複製（下面兩節） | 這一步現在沒有工具幫忙，是手動的 |
| 5 | `cd ~/my-tree && source env.sh && aos-tree-start root` | 重開；睡下的自己醒 |

跟今天步驟單「換版本：關、拉、編、開」比：第 3 步從 `cmake --build` 變成 `install.py`；多了第 4 步——它其實今天就存在（範本改了，樹裡的抄本不會自己變），只是步驟單沒寫出來。

## 樹裡有哪些東西、哪些會過時

「樹」＝你從範本抄出去的那個地點（今天的 `~/aos-home`）。裡面沒有 aos 的程式，但有從範本抄來的定義，其中一部分是程式性質的。**下表是照檔名分的，沒有逐檔核。**

| 類 | 例（`templates/agent-fsm`、`eca-claude`、`daemon-root`、`kernel/llm-kernel`） | 更新後 | 能不能直接蓋 |
|---|---|---|---|
| 抄出去的程式 | `_entry`、各格的 `act.py brain.py compact.py idle.py wait.py cell_common.py atomic_file.py llm_settings.py`、eca 的 `compact_hook`、`screen`、kernel 的 `fake_slow` | **會過時**：新版的套件或指令改了，舊的格可能壞或行為舊 | 沒改過的可以；P-27 說「各格的程式每隻 agent 複製一份自己改」，改過的蓋了就沒了 |
| 接線（指到家裡的路徑與結構） | `fsm.json`、`loop.json`、`hooks.json`、`interfaces.json`、`_metainfo.json`、`daemon.json`、`cli.json`、`body.json` | **可能過時**：家裡的工具搬家、指示詞路徑變了、結構加了欄位 | 多半可以；有人會在這裡加自己的 hook 或狀態 |
| 預設值＋自己改的混在同一檔 | `tools.json`、`tools_sub.json`（範本給的工具清單，你會增刪）、`kernel.json`（模型端點） | **可能過時**，而且最麻煩 | **不能直接蓋**，要比對後手動合 |
| 你自己的 | `llm.json`（選哪個模型）、`system.txt`、`.env`、`subagents.json`（名冊）、疊上去的角色文字 | 不過時 | **不能蓋** |
| 跑出來的 | 各個 stack（對話、帳、信箱、時鐘） | 不重新複製；但新版若改了帳或名冊的格式要先收子或重建（今天步驟單已有這句） | **不能蓋** |
| 樹裡的 `env.sh` | 隨範本抄的那份 | 薄的那種幾乎不過時；完整一份的會 | 可以 |

這次改名本身就是一次「全部過時」：指示詞從 `/lib/base/…` 變了，所有已經抄出去的定義都要重抄。你要整個重建 `~/aos-home`，所以這次不成問題。

## 怎麼讓使用者知道哪些過時了（選項；都是現有的東西，沒有新機制）

| 選項 | 做法 | 後果 |
|---|---|---|
| a 人自己比 | `diff -r $AOS_HOME/templates/agent-fsm ~/my-tree/agents/ann` | 零成本。會把你自己改的也列出來，要人眼分；樹裡 agent 多就很累 |
| b 寫在更新說明裡 | 每次動到範本的 commit，訊息寫明「這版要重抄哪幾個檔」（今天步驟單對 stack 格式已經這樣要求） | 靠紀律；漏寫就沒人知道 |
| c 定義少帶程式 | 格的程式不抄、借家裡的（`templates/reviewer` 現在的寫法；路徑規劃題 3 的 C） | 會過時的東西直接變少，更新幾乎只剩 `install.py`。但動到 P-27，想改格的人要另外處理——這是條文的事，你說條文以後大修 |
| d 用現有的檢查指令 | `aos-kit check KIT` 已經會查「疊上去的角色文字是不是最新」；範本本體沒有對應的檢查 | 只涵蓋角色套件那一類 |
| e 定義裡的血統紀錄 | `agent_def` 造新定義時會記血統（從哪來）；能不能拿來比「抄的時候是哪一版」**沒細看** | 不確定夠不夠用 |

這些可以併用（例如 a＋b）。要不要為這件事做新工具，是之後的題，這份不設計。

## 「從template中複製一些東西到指定地點」現在是什麼

| 要抄的 | 從哪 | 現在用什麼 |
|---|---|---|
| 根的定義 | `templates/daemon-root` | `cp -r`，再往 `.env` 補一行 |
| llm kernel 的定義（API 版要） | `templates/kernel/llm-kernel` | `cp -r` |
| 一隻 agent | `templates/agent-fsm`（API 版）或 `templates/eca-claude`（eca 版） | `cp -r`，再寫 `llm.json` |
| 角色套件（選配） | `templates/kits` | `aos-kit add KIT DEF` |

- 現有指令對不對得上：`aos-tree-start` 是**起**樹的（順便擋殼裡別棵樹的 `AOS_*`），不抄東西；`aos-kit` 只管疊角色；`agent_def` 是腦在樹裡造新 agent 定義用的工具，不是給人起手用的。**「抄」現在就是幾行 `cp -r`。**
- 要讓它真的是一行，需要一個「起手範本」（一包：根＋樹裡那份 `env.sh`＋一隻 agent）。你今天裁過「根＋領班」範本先不做（路徑-9 A）；現在因為 `env.sh` 要隨範本走、又要給別的使用者照著做，等於重開這題（L-10）。
- 抄出去的東西回家裡拿什麼：指令（`PATH` 上的 `bin/`）、工具與工具包（指示詞 `$AOS_HOME/lib/tools/…`、`/lib/packs/…`）、Python 的格 import 的 `aos` 套件（`$AOS_HOME/lib`）、知識庫（`$AOS_HOME/knowledge`）。

## 跟今天的[重建步驟單](../重建步驟單.md)對照

| 今天的步驟單 | 新流程 | 多還是少 |
|---|---|---|
| 第 0 步：清舊連結與 `.pth` | 新使用者沒有；你這台重建時仍要做一次 | — |
| 第 1 步：`cd impls && cmake -B build … && cmake --build …` | `python3 install.py` | 同一步；多了查相依、抄 Python、產生入口、抄標頭 |
| 第 2 步：每個視窗 `source ~/repo/aos/proto8/env.sh` | 一次性設 `AOS_HOME`；每個視窗 `cd 樹 && source env.sh` | 多一個一次性的步驟；每次打的字變短 |
| 第 3～6 步：建夾、三次 `cp -r`、補兩行設定 | 有起手範本＝一行；沒有＝照舊四步 | 少三步（要先做起手範本） |
| 第 7～12 步：起根、起 kernel、掛 agent、看表、說話、關樹 | 一樣 | 不變 |
| 換版本四行 | 上面的更新五步 | 多寫出「重新複製」那一步 |
| 「改 repo＝改樹」那段提醒 | 改成「改了要 `install.py` 才生效」 | 提醒的方向反過來 |
