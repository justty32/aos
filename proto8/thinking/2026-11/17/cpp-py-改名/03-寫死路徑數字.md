# 寫死 `impls`／`lib` 的地方：數字與分類

## `$AOS_HOME/lib` 這個寫法有幾種

| 寫法 | 處數（非排除區） | 在哪 |
|---|---|---|
| JSON 指示詞 `{"$env":"AOS_HOME","$path":"/lib/…"}` | 223／79 檔 | `lib` 81、`templates` 79、`cmd` 37、`docs` 2… |
| 　其中 `/lib/packs` | 35 | 範本與知識庫 |
| 　其中 `/lib/agent` | 21 | |
| 　其中 `/lib/base` | 16 | |
| 　其中 `/lib/aos` | 13 | |
| 純文字 `$AOS_HOME/lib…` | 34 | 知識庫 10、範本 8、`lib` 6、`cmd` 4… |
| Python `os.environ["AOS_HOME"], "lib"` | 6 | 範本的格 |
| 純文字 `$AOS_HOME/impls…` | 5 | `env.sh` 等 |

`impls` 沒有指示詞形（0 處）：C++ 執行檔一律從 `PATH` 找，定義不指它。**所以 `impls` 改名便宜、`lib` 改名貴，貴約五倍。**

## 不能閉著眼睛替換的

| 東西 | 為什麼 |
|---|---|
| 82 個工具的「往上找名字叫 `lib` 的夾」 | 是程式邏輯不是路徑字串；改名後要一起換成新名字，而且如果工具搬到 `py/tools/…`、模組搬到 `py/src/…`，「往上找」就要改找法 |
| `lib/agent/guard/scope.py` 的 `HOME_PARTS = ("lib","cmd","templates","knowledge","impls")` | 守門工具的禁區表，漏改＝agent 可以寫進新夾 |
| aos-sandbox 的 `<家>/lib` 唯讀掛載 | 漏改＝沙箱裡沒有工具 |
| 各 C++ 專案自己的 `lib/`（放 `.a`） | 不是頂層 `lib`，不該被替換到 |
| `/usr/lib`、`/lib/x86_64…` 這類系統路徑 | 同上（`cmd` 測試裡有 41 處「不確定」多半是這種） |
| `.gitignore` | 沒有任何一份寫死頂層 `impls`／`lib`，不用動；但根的 `bin/`、`build/` 忽略規則會影響新位置（`cpp/build/` 自動被忽略，合用） |
| `wf/tools/index_gen_desc.json` | 191 個鍵是路徑，改名要整批改鍵，否則 `index_gen` 會報缺描述 |

機械替換實際能走多遠，在暫存複本上試了，結果見 [09-實測紀錄](09-實測紀錄.md)。
