# Python 方案：`lib/` → `py/`

## 「標準 Python 專案」指的是哪幾件事

| 件 | 白話 | 現在 |
|---|---|---|
| `pyproject.toml` | 一個檔寫明：叫什麼、要哪版 Python、相依誰、測試怎麼跑 | 沒有 |
| 一個有名字的套件（`import aos.xxx`） | 所有模組住在一個名字底下，不會跟別人的模組撞 | 49 支模組平鋪，`import aos_flags`、`import hooks` |
| src layout（`src/aos/`） | 被 import 的程式放 `src/`，跟測試、資料、工具分開 | 模組、工具、資料、測試全在 `lib/` 同一層 |
| `tests/` 一處 | 一行指令跑全部 | 頂層 25 支＋每個工具夾自己的 99 支＋每支指令自己的 108 支 |
| 可以 `pip install -e .` | 裝一次，任何地方都 import 得到 | 靠每支程式自己算位置 |
| console scripts | 指令由安裝程序生出來 | `cmd/*/bin/*` 手寫入口 |

後兩件跟今天定的規則一會打架（裝了就不在家裡），細節在 [06-卡點](06-卡點.md) 第 3 點。**「資料夾＝程式」的工具（90 個）在 Python 的標準裡沒有對應的位子**：它們不是套件也不是模組，是一堆各自獨立的小程式。

## 三個方案對照

| | P-小：只改名 | P-中：標準骨架＋一個套件（推薦） | P-大：`cmd` 的應用也搬進來 |
|---|---|---|---|
| 被 import 的模組 | `py/*.py` 平鋪 | `py/src/aos/…`，`from aos import flags` | 同中 |
| 工具資料夾 | `py/base` `py/aos` `py/agent` | `py/tools/base` `tools/aos` `tools/agent` | 同中 |
| `pyproject.toml` | 無 | 有（宣告用；不要求安裝） | 有 |
| `cmd/` 各夾的邏輯 | 不動 | 不動（只改 import） | 搬進 `py/src/aos/apps/`，`cmd/*/bin` 剩 4 行 |
| 指示詞 | `/lib/base/read` → `/py/base/read` | → `/py/tools/base/read` | 同中 |
| 改內容的檔（不含純文字） | 約 350 | 約 400 | 約 500 |
| 搬位置的檔 | 0（整夾改名） | 約 560 | 約 560＋約 190 |
| import 行 | 0 | 483 | 483＋`cmd` 套件內部約 300（估） |
| 風險 | 低～中 | 中 | 中～高 |

三個方案都另有「只是文字」的約 880 處／210 檔（條文、wf、README）要不要跟（題 X-2）。

## P-小：只改名

```
py/
  aos_flags.py tool_io.py observed.py …（27 支）  daemon_ctl/
  base/  aos/  agent/        工具（agent/ 裡混著 22 支共用模組）
  packs/  schema/  docs/  tests/  README.md
```

- 動：82 個工具與 22 個入口的「找叫 `lib` 的夾」、223 處指示詞、範本的格、約 260 支測試裡的 `"lib"`、`scope.py` 禁區表、沙箱掛載、`index_gen` 夾名表與 93 個描述鍵。
- 好處：一次機械替換；`import` 一行不改。
- 代價：`py/` 裡還是五種東西混一層，跟你說的「py 程式庫」對不上的地方（工具不是程式庫）原樣留著。

## P-中：標準骨架＋一個套件（推薦）

```
py/
  pyproject.toml        名字 aos、Python ≥ 3.11、選用相依 jsonschema、測試設定
  README.md  docs/
  src/aos/              被 import 的，一個套件
    __init__.py
    flags.py  ws.py  tool_io.py  observed.py  metainfo.py …（原頂層 27 支；aos_ 前綴拿掉）
    daemon_ctl/         原樣搬
    agentlib/           原 lib/agent 的 22 支共用模組（hooks、cli_*、cooldown…）
    comm/               原 lib/aos/comm 的庫
  tools/                「資料夾＝程式」的工具：被 aos-exec 跑，不是套件
    base/（32）  aos/（21）  agent/（37）   每個工具照舊帶自己的 tests/
  packs/                18 份 JSON 工具包清單
  schema/               comm/1 的 schema 與樣本
  tests/                套件的測試（原 lib/tests 25 支）
```

- 找法只剩一種：家裡的程式從自己的位置往上找到 `py/src`，加進 `sys.path`，`from aos import …`；抄出家的格與工具用 `$AOS_HOME/py/src`（規則一的路-2、路-3 原樣適用）。**不安裝、不進 site-packages。**
- `pyproject.toml` 的用處：寫明版本與相依；編輯器與 `python -m unittest`／`pytest` 認得專案根；哪天想 `pip install -e py` 也行（選配，跟 `install.sh` 一樣的地位）。
- 好處：`py/` 一眼分得出「被 import 的」「被當程式跑的」「資料」「測試」；對外只露一個名字 `aos`，`hooks`、`runner` 這種泛名不會再跟誰撞；49 支模組三種 import 寫法收成一種。
- 代價：483 行 import 要改（機械的）；模組改名（`aos_flags` → `aos.flags`）之後 `git log` 要 `--follow`。
- 風險：
  - 工具夾 `tools/aos/` 與套件 `aos` 同名。實測：有 `__init__.py` 的套件一定贏過沒有的資料夾，不會認錯；但**公司機那個舊 `.pth` 現在就讓 `import aos` 成功**（拿到一個空殼，指到 `~/repo/aos/proto8/lib/aos`），測試一律要帶 `PYTHONNOUSERSITE=1`，重建樹時那個檔要先移走。不想冒這個險可以把套件叫別的名字（題 P-3）。
  - 抄出去的工具「旁邊帶一份 `tool_io.py`」的慣例（`templates/tool-python`）要改成「旁邊帶一個 `aos/` 夾」或一律走 `AOS_HOME`。
  - `aos-comm` 現在靠把 `lib/aos` 放上路徑再 `from comm import`，要重寫成 `from aos.comm import`。
- 這個方案內部可以切兩個 commit：先「分夾」（模組仍平鋪在 `py/src/`，import 不改），再「收成套件」（改 483 行）。只做前半也是一個可停的點。

## P-大：`cmd` 的應用也搬進來

```
py/src/aos/
  …（同 P-中）
  apps/
    agent/      原 cmd/aos-agent/aos_agent（27 支，4,505 行）
    eca/        原 cmd/aos-eca/aos_eca
    view.py  tools_cli.py  daemon_ctl_cli.py  kit/  comm_cli/ …
py/tests/apps/…  原 cmd/*/tests（108 支）
cmd/
  aos-agent/bin/aos-agent    4 行：算出 py/src、from aos.apps.agent import main、main()
  aos-view/                  bin 入口＋ui/ web/ systemd/ aide-def/（非 Python 的留著）
  …
```

- 多動：21 支指令約 16,700 行、108 支測試搬家；15 支「`bin` 單檔」要拆成「模組＋薄入口」；`cmd` 各夾的 README 與 `docs/` 連結。
- 好處：完全對上你說的「py 程式庫（大多應用都放在這裡）」「cmd（可以跑的命令行程式，會用到 cpp/、py/ 中的東西）」；一行跑全部 Python 測試；應用之間要共用程式不必再先搬去 lib。
- 代價：一支指令的程式、測試、說明現在在同一夾（改一支只看一處），搬完分在 `cmd/x/`、`py/src/aos/apps/x/`、`py/tests/apps/x/` 三處。`viewbin-1117` 正在動 aos-view，要等它交完。
- console scripts（讓安裝程序生出 `aos-agent` 這些指令）不建議：生出來的指令在 venv 的 `bin/`，不在家裡，違反規則一「不往家外放程式」；薄入口留在 `cmd/*/bin` 就好。

## 推薦：P-中，P-大留給你裁

- P-中把「標準形式」裡不跟規則一打架的四件都做了（`pyproject.toml`、一個套件、src layout、資料與工具分開），而且把今天早上 `py` 併進 `lib` 留下的「兩種東西混一夾」解開。
- 不推薦只做 P-小再回頭做 P-中：`lib` 的 223 處指示詞與 82 個找法，改名改一次、分夾又要再改一次，同一行動兩遍（細節在 [06](06-卡點.md) 第 6 點）。
- P-大是方向題（[06](06-卡點.md) 第 2 點）：你的原話指向它，但它把「一支指令一個夾」的現況打散，值不值得由你定；P-中做完隨時可以接著做，不會白工。
