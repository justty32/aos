## 使用者原話（11-17，逐字）

「對了，我想了一下我們的外部依賴，我記得主要就幾個：1. nlohmann json，這是硬性的，不用多說，之所以需要vcpkg主要多虧了他，之後可以看看是否有方法把它直接弄進來，不管是submodule還是啥，讓我們脫離vcpkg。2.cmake，這個也可以考慮看看，或許可以直接走makefile？反正我們C++這塊也沒多少東西。3.cgroup,s6，這些是可選的，主要提供權限、限制相關的東西。4.各種python module，這沒啥好說的，提供requirement.txt就完事了。」

## 結論

- **真正「沒有就編不起來／跑不起來」的只有四樣**：g++（C++20，連靜態 libc 與 libstdc++）、nlohmann json、建置工具（現在是 CMake ≥ 3.21）、Python ≥ 3.10。其餘全是選配。
- **vcpkg 只為了 nlohmann json 一個**，拿掉很容易：把官方 release 的單一標頭 `json.hpp`（3.12.0，953 KB）加授權檔收進 repo，實測 11 個專案全部編過、0 個警告、不用 vcpkg 也不用 `find_package`。
- **換 Makefile 做得到**：手寫 26 行就編出 `aos-util`＋`aos-lock` 的庫與執行檔，增量編譯、平行、改標頭重編都正常。全家估 100 行上下。
- **Python 其實沒有必需的第三方模組**：唯一的外部模組是 `jsonschema`，而且是選用（沒有就改用內建的檢查）。
- **s6 核心沒在用**：C++ daemon 是自己用系統呼叫模仿 s6 的兩個小工具；真的會叫 s6 的只有選配指令 `aos-sandbox`。cgroup 只有 `aos-daemon` 用、只認 cgroup v2、預設關。

## 跟你記憶對不上的地方

| 你說的 | 實際 | 差多少 |
|---|---|---|
| 1. nlohmann json 硬性、vcpkg 是為了它 | 對。C++ 沒有第二個外部函式庫（其餘全是標準庫與 Linux 系統標頭） | 吻合 |
| 2. cmake | 對。補充：最低 3.21（用到 `PROJECT_IS_TOP_LEVEL`）；測試不走 ctest，是 Python 測試去 `impls/*/bin` 找執行檔 | 吻合 |
| 3. cgroup、s6 選配、管權限與限制 | cgroup：對，只有 `aos-daemon` 的兩個上限鍵與「整格收掉」用。**s6：核心不用**，只有 `aos-sandbox` 換身分／軟上限時叫 | s6 比你記得的更邊緣 |
| 4. 各種 python module，給 requirements.txt | **沒有必需的**，只有選用的 `jsonschema`；repo 裡也還沒有任何 requirements 檔 | 比你記得的少 |
| （沒提到） | 選配系統工具還有一串：`bwrap`、`setfacl`、`sudo`、`newuidmap`、`tmux`、`git`、`claude`／`codex`／`eca`、`node`；還有 `-static-pie` 要的靜態 `libc.a` | 要補進檢查表 |

## 推薦一覽（細節與後果在各分檔）

| 類 | 推薦 | 為什麼一句話 | 分檔 |
|---|---|---|---|
| nlohmann json | 單檔 `json.hpp`＋`LICENSE.MIT` 收進 repo（例 `cpp/third_party/nlohmann/`），記版本與 sha256 | 離線可裝、零工具、更新＝換一個檔；實測過 | [02](外部依賴/02-nlohmann-json.md) |
| 建置 | 換一份頂層 Makefile，安裝腳本叫 `make -j` | 82 個原始檔、11 個專案同一個形狀，Makefile 夠用；少一個要裝的東西 | [03](外部依賴/03-cmake-或-makefile.md) |
| cgroup、s6 等 | 安裝腳本只「查並印一張表」，少了不擋 | 全是選配，少了只會少某幾個功能 | [04](外部依賴/04-cgroup-s6-系統工具.md) |
| Python 模組 | 放一份 `requirements-optional.txt`（只有 `jsonschema`），安裝腳本只檢查、不自己 pip | 必需的一個都沒有；很多發行版的系統 Python 不給 pip 裝 | [05](外部依賴/05-python-模組.md) |

## 實測了什麼、沒測什麼

- **測了**（公司 WSL，Ubuntu 24.04、g++ 13.3、CMake 3.28、GNU Make 4.3；在 `~/.aos/scratch/deps-1117/` 用 `git archive HEAD` 的複本）：單檔 `json.hpp` 不靠 vcpkg 編全家；手寫 Makefile 編兩個專案。
- **沒測**：其他發行版（Manjaro 家機）、clang、比 g++ 13 舊的編譯器；venv 與 pip（公司 WSL 的 Python 沒有 pip 也沒有 venv 模組）；全家版 Makefile（只寫了兩個專案）；cgroup 與 s6 實跑（只讀程式）。
- 跟 `cpp-py-改名` 的關係：那邊的題 L-3（「不考慮 cmake」怎麼讀）與施工單 S2 會被這裡的建置選項影響；兩邊的施工單要一起排。
