## D-1　nlohmann json 怎麼進來

- **A 把官方 release 的 `json.hpp`＋`LICENSE.MIT` 收進 `cpp/third_party/nlohmann/`（推薦）**：repo 多 0.95 MB；離線能裝；更新＝換一個檔。實測編過。
- B git submodule：repo 不變大；使用者要 `--recursive`，忘了就編不過；更新流程多一步。
- C 安裝腳本下載：repo 不變；第一次安裝一定要網路，公司防火牆或 GitHub 出事就裝不了。
- D 用系統套件：要 sudo 裝；每台機器版本不同。

## D-2　建置工具

- A 留 CMake，只拿掉 vcpkg：零風險、已實測；使用者仍要裝 CMake ≥ 3.21，12 份 CMake 檔照舊。
- **B 換一份頂層 Makefile，安裝腳本叫 `make -j`（推薦）**：少裝一個工具、一份約 100 行看得完；clangd 的 `compile_commands.json` 要另產、改旗標要 `make clean`、IDE 的 CMake 整合沒了。兩個專案實測過，全家版沒寫。
- C 安裝腳本直接叫 g++：只剩 g++；增量、平行、依賴追蹤都要自己寫（估 150～200 行），開發時每次都要叫安裝腳本才能編。

## D-3　`compile_commands.json`（D-2 選 B 或 C 才要答）

- **A 安裝腳本照 Makefile 同一套旗標寫一份（推薦）**：約 20 行 Python，不用多裝東西；旗標改了兩邊要一起改（可讓 Makefile 印旗標、腳本讀，避免抄兩份）。
- B 不產：clangd 找不到標頭，編輯器會滿是紅線。
- C 用 `bear -- make`：一行；要多裝 `bear`。

## D-4　Python 選用模組怎麼交代

- **A 放 `py/requirements-optional.txt`（只有 `jsonschema>=4.18`），安裝腳本只檢查、提示怎麼裝（推薦）**：不碰使用者的 Python 環境；外部管理的系統 Python 也沒問題。
- B 檔名用 `requirements.txt`：照你原話；但會讓人以為不裝不能跑。
- C 安裝腳本自建 venv 並 pip 裝：要 `python3-venv`（公司 WSL 沒有，會直接失敗）、要網路、所有入口改用 venv 的 Python。
- D 不放清單：使用者不知道有這個選用功能。

## D-5　Python 最低版本

- **A 宣告 3.11（推薦）**：執行與測試一致（測試用到 `tomllib`）；Ubuntu 24.04、Debian 12 都夠。
- B 宣告 3.10：執行夠，但兩支測試在 3.10 跑不了。

## D-6　選配系統工具的檢查

- **A 安裝腳本查一遍，印「有／缺／缺了少什麼功能／裝哪個套件」的表，缺了不擋（推薦）**；另有 `--check` 單獨重查。
- B 嚴格：缺任何一個就停。cgroup、s6、setfacl 在很多機器上本來就沒有，會變成誰都裝不起來。
- C 不檢查：等用到才看到 `CommandMissing`。

## 不列成題、照實記著的邊緣狀況

- `cmd/aos-sandbox/root/setup.sh` 的 s6 預設來源指向 11-15 已刪的自編版；`test_acceptance.py` 也引用那個路徑。真要用 `aos-sandbox` 的 `user` 功能時才會撞到。
- 公司 WSL 沒有 `setfacl`，`aos-share` 在這台不能用。
