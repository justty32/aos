## 2. 已停用或封存、入口還佔位置

- `wf/workflows/` 26 個東西裡 8 個是死入口：`hackathon/`、`workshop/`、`digest/`、`experiments/`、`investigations/`、`ideas/`、`spec/`、`decide-page.md`。其中 `investigations/` 連說明頁都沒有，夾裡只剩 `archive/`。
- `wf/WORKFLOWS.md` 派發表：兩張表 25 列裡 8 列指向「已封存」「已停用」「舊入口已封存、現行落點在別處」（ideas、spec、roadmap、workshop、hackathon、experiments、digest、decide-page），約佔這個檔 2.5 KB。
- `wf/salvage/`：頂層一個夾，只剩 604 B 的封存說明加 `archive/`。
- `wf/tools/progress_board/`（59 檔 586 KB）、`wf/tools/decide_page/`（9 檔 66 KB）：看板與離線待裁頁 11-14 都停用了，程式還在。
- `wf/workflows/resources.md`、`TEMPLATE.workflow.md`：11-13 的規劃就列在丟棄候選。
- 為什麼會留：11-14 定了「封存預設留指標頁、不移除舊路徑」，原因是 agent 的權限不讓跑帶 `--rm` 的交件，要使用者親手跑。所以每封存一個，入口數不會變少。

## 3. 活狀態檔太大

- 檔尾「各工作流 session-log」「不屬任何工作流的進度」兩段是空殼。

## 6. 名字不好懂、或一個詞好幾個意思（照 C-54「名字要好懂、一詞一義」看）

| 名字 | 問題 |
|---|---|
| `SESSION-LOG.md` 對 `session_logs/` | 名字只差大小寫、底線與 s，一個是「還沒做完的進度」、一個是「每日日誌」。而且 SESSION-LOG 根本不是 log |
| `WAIT_USER.md` 對 `wait-user/` | 同一件事，一個大寫底線、一個小寫連字號 |
| `INDEX.md` 對 `_index.json` | INDEX 是「repo 地圖」，`_index.json` 才是 aos 講的 index |
| `inbox/` 對 `workflows/inbox.json` | 一個是放信的夾，一個是收發信的規矩 |
| `investigation.md` 對 `investigations/` | 一個是工作流，一個是它的舊報告夾（已封存） |
| `wf/knowledge/` | 裡面只有 code map；同時還有 `proto8/knowledge/`（出廠知識庫）、`proto8/knowledge/wf/knowledge/`（通用版）、`~/aos-home/knowledge/`（活樹） |
| `common/` 對 `public/` | 都是「大家共用的」。`common` 放使用者偏好與慣例（規矩），`public` 放做法與坑（經驗），從名字看不出差別 |
| `tools/` 對 `public/tools/` | 兩個工具夾 |
| gotchas、lessons、pitfalls | 三個英文詞講同一種東西：踩過的坑 |
| `WORKFLOWS-parts/` | 是為了躲 `WORKFLOWS/` 跟 `workflows/` 在不分大小寫的檔案系統撞名才這樣取 |
| `advices`、`salvage` | `salvage` 要讀說明才知道是 8 月的打撈包 |
