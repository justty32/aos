# 03 寫死的路徑與連結量

量法：`git grep`。「活文件」不算 `archive/`、`reports/`、`session_logs/`、`inbox/`、`proto8/thinking`；「紀錄類」就是這幾種。數的是「有幾個檔提到」，不是逐條連結。

## 程式與設定裡寫死的（搬了會壞）

| 在哪 | 寫死什麼 | 哪個動作會踩到 |
|---|---|---|
| `CLAUDE.md` | `AGENTS.md` | 不動就沒事 |
| `.claude/settings.json` | SessionStart（matcher 只有 `compact`）跑 `wf/tools/compact_reload.sh` | 搬 `wf/tools` |
| `wf/tools/compact_reload.sh` | `wf/workflows/common/user.md` 與 `user/*.md`、`wf/HANDOFF.md`、`wf/SESSION-LOG.md` 的「## 最新進度」段 | 進度轉 json、user 轉 json、搬 HANDOFF |
| `wf/tools/commit_queue.py`（`commit-request` 的本體） | `SESSION_LOG = "wf/SESSION-LOG.md"`；`log_upsert`／`log_delete` 兩個 op 靠「行首等於 `- **open｜主題`」找那一行；`GEN_PREFIX = "wf/knowledge/code-map/"`；呼叫 `wf/tools/index_gen.py` | 進度轉 json 一定要同一個 commit 改它；它的測試 `tests/test_commit_queue.sh` 有 20 處 |
| `wf/tools/index_gen.json` | 範圍 `wf`（連底下每一層）、不建 index 的夾 `wf/inbox`、code map 輸出 `wf/knowledge/code-map/proto8` | 搬 `inbox/`、`knowledge/` |
| `wf/tools/index_gen.py` | `GEN_BY = "wf/tools/index_gen.py"`（寫進每份生成物） | 搬 `wf/tools` |
| `wf/tools/tabledb_fmt_vars.py` | 找 repo 根底下的 `wf/tools/fmt-vars.json` | 搬 `wf/tools` |
| `wf/tools/progress_board/collect.py` | 靠自己的位置往上三層推 repo 根 | 搬看板（搬去封存就不用管） |
| `wf/tools/index_gen_desc.json` | 以路徑當鍵的說明表，夾改名要跟著改鍵 | 任何搬夾 |
| `.gitignore` | `wf/temp/`、`wf/inbox/.inbox-send.*`、`wf/workflows/dispatch/trial/archive/sandbox/…` 五行 | 搬 `temp/`、`inbox/`、`dispatch/` |
| `proto8/install.sh` | 註解與一句英文錯誤訊息裡寫 `wf/workflows/testing.md` | testing 轉 json 或搬 |
| `proto8/extras/tree-swap/common.sh` | 註解寫 `wf/workflows/dispatch/aos-teams/06` | aos-teams 進知識庫時 |
| `proto8/extras/aos-view/aide-def/system.txt` | 提示裡寫 `~/repo/aos/AGENTS.md…` 當必讀 | 改「讀規矩」那句時要跟著改 |
| `proto8/templates/eca-claude/compact_hook` | 註解提 `wf/tools/compact_reload.sh` | 只是註解 |
| 程式註解裡的出處 | `proto8/cmd/aos-agent/aos_agent/ctl/add.py`、`impls/aos-loop/include/aos/loop.hpp` 提「wf/advices」；`lib/base/llm_http/_entry` 提 `wf/temp/ok-…`（不進 git 的路徑） | 只是註解 |
| 知識庫 `proto8/knowledge/aos/` | 只有 `definition.json` 一處拿 `~/repo/aos/wf/tools` 當 PATH 的例子 | 搬 `wf/tools` |
| 通用版 `proto8/knowledge/wf/` | 講的是「任何工作區的 `wf/…`」，其中 `live-lists.json` 提 `wf/SESSION-LOG`、`wf/WAIT_USER` 的寫法 | 進度轉 json 時對照一下 |
| 配給包 `dispatch/kits/` 的提示檔 | 沒有寫 `wf/`（`proto8/templates/tests/kits/test_kits.py` 還把 `wf/` 列為禁字） | 不受影響 |

沒查到的：活樹 `~/aos-home/agents/` 底下現役定義（`opus-kernel`、`fable-kernel` 等）的提示有沒有寫死 wf 路徑。我對 WSL 多個路徑的查詢被擋了，只讀到知識庫入口那一檔；上表是照 repo 裡的來源查的。

## 紀錄類的舊連結怎麼辦

跟 proto8 那份方案（[proto8-八夾](../proto8-八夾.md) 題 11）用同一套：**舊紀錄不改**，在 `proto8/thinking/README.md` 的改名表加一段「wf 哪個路徑搬去哪」。活文件的連結用 `wf/tools/fix_moved_links.py` 改（先 dry-run）。
