> **停在這裡**：使用者同日稍後說 goal 的設計到這邊就好（原話見下 6）。不排施工、不再追問待裁；[01](01-設計.md) 留著當日後施工的起點。

## 使用者原話（照時間）

背景：接在 [new-tools 02 todo](../new-tools/02-todo.md) 的 T1 裁定之後——他裁了 todo 清單「不帶，腦自己查」（不每輪自動帶進 prompt），然後說自動給 agent 看的東西改由 goal 來做。

1. 「然後自動給agent看的，可能要做goal工具。預期是當agent自己停下來時(在沒有新user prompt的情況下，自己不再呼叫工具)，自動丟goal給他，」
2. 停下來是在等人回覆時，使用者自己寫的：「agent可以用goal_pause，宣告說自己因為一些原因所以暫時不做goal，還有goal_resume。」
3. 收尾時：「對，我知道這很靠agent自覺。但這就夠了，沒有自覺的agent你再怎麼催他他也不會做。goal的設計也到這邊就好，不用繼續推進。」

## 裁定（頂層用選項框問的；引號內是選項文字或他自己寫的）

| 題 | 裁定 |
|---|---|
| 怎麼算結束 | 「agent 自己宣告完成」：agent 叫 goal 工具說完成或放棄並附一句理由，之後不再丟 |
| 次數上限 | 「有，預設十次可調」：連續丟到上限就停，留一則記錄說到上限了；設 goal 時可改數字 |
| 停下來是在等人回覆時 | 使用者自己寫的（上面原話 2）：`goal_pause`／`goal_resume`。頂層當時的選項還有「有新信進來就自動恢復」，他沒選、改寫成這句——新信會不會自動 resume **沒裁** |
| 誰可以設、改、清 | 「agent 自己和外面都行」：agent 用工具；人和父 agent 用指令（像 `aos-agent system` 那樣） |

頂層已告訴使用者、他沒反對的兩點：有新信時信優先，信箱空了才丟 goal；每丟一次 history 多一則，內容要很短（目標一句加一行提示）。

## 白話結論（草稿到哪）

- **「自己停下來」在 fsm 範本裡＝act 格看到最後一則 assistant 沒有 tool_calls、退 10 回 idle，而 idle 又收不到信的那一刻**。現有 hook 事件沒有這一刻，要嘛新事件、要嘛直接做在 idle 格。
- 推薦的形狀（未裁）：狀態一份檔放 agent stack 的固定位置（工具和 `aos-agent goal` 兩邊都拿得到），idle 收不到信又是「腦停下來」時，把 `[aos] goal: …` 一則接進 history 再去 think；計數放同一份檔。
- eca 那邊對應的點在 aos-eca-turn 一輪開頭 queue 空的地方（`one_turn` 裡 `batch` 空那段）；沒再深查。
- 工具形狀、存哪、計數歸零規則等都列在 01 的「日後施工時再裁」，不做成選項題。
