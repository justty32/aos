# 01 goal 設計草稿（停在這裡，日後施工的起點）

← [goal](README.md)

只寫到 11-11 查到的程度；使用者說到這邊就好，沒寫的不補。

## 一、「自己停下來」是哪一刻

**fsm 範本**（`templates/agent-fsm/fsm.json`：idle → think → wait → act → think…）：

- act 格看最後一則 assistant：沒有 `tool_calls`＝腦給了最後答案，退 10 回 idle（`act.py` 的 `sys.exit(10)`）。
- idle 收信：有好信退 0 去 think；沒信退 10 留在 idle（每 300 ms 一拍）。
- 所以「沒有新 user prompt、自己不再叫工具」＝**history 最後一則是沒有 tool_calls 的 assistant，而且 idle 這拍收不到信**。這正好也滿足「信優先」：idle 先收信，收到就照常走，收不到才輪到 goal。

**現有 hook 事件夠不夠**：不夠。現有的是 before_queue／after_queue／before_tool／after_tool／brain_failed／tool_added／after_start／after_stop／on_clock，沒有一個落在「腦停下來、信箱空」這刻。而且 hook 的 handler 預設不進 history（要叫腦得自己往 queue 寄信），寄信會繞一圈 before_queue 並被當成「新信」，跟計數、跟「新信會不會自動 resume」纏在一起。

**草稿推薦**：直接做在 idle 格（同 on_clock 掛在格開頭的作法）——idle 收不到信時，看 history 最後一則是不是「停下來」、goal 檔是不是 active 且沒到上限；是就把一則 user 接進 history、計數加一、退 0 去 think。不寄信、不走 queue，所以不會被當成新信，history 只多那一則。

## 二、丟進去的那則（草稿）

用既有 `[aos] 種類: 內容` 風格（要在 `py/aos_flags.py` 的 `NOTE_KINDS` 登記 `goal`）：

```
[aos] goal: <目標一句> (reminder 3 of 10; call goal_done when finished, goal_pause if you are waiting for someone)
```

到上限那一次（只留一則、之後不再丟）：

```
[aos] goal: reminder limit 10 reached; goal paused. <目標一句>
```

## 三、eca（claude／codex）

- 一輪＝aos-eca-turn 一次（CLI 自己在裡面叫多支工具），答完就是「停下來」。對應點在 `cmd/aos-eca/bin/aos-eca-turn` 的 `one_turn`：認領信之後 `batch` 空（queue 空）那段，現在退 `empty_code`。在這裡看 goal 檔、把同一則文字當這輪的題目交給 CLI、接進 history。
- 差異：fsm 是「接一則再 think」，eca 是「把那則當題目問一次 CLI」；eca 的一輪比 fsm 一格貴很多，上限更要緊。沒再深查（使用者收尾）。

## 四、狀態與外面的指令（草稿）

- 一份檔放 agent stack 固定位置（例 `<stack>/goal.json`）而不是工具小格：`aos-agent goal …`、idle 格、aos-eca-turn 都要讀寫，固定位置三邊都拿得到（同 `cooldown.json` 的作法）。
- 欄位：`text`、`status`（active／paused／done／abandoned）、`reason`、`reminded`（已丟次數）、`limit`（預設 10）、`set_by`（agent／外面）、`updated_at`。
- 外面：`aos-agent goal get|set|clear|pause|resume`，照 `aos-agent system`（`cmd/aos-agent/aos_agent/system.py`）的寫法；父 agent 替子設 goal 走同一條（子的 stack 各自一份，天生獨立）。
- history summarize 後 goal 還在（在檔裡，不在 history）。

## 五、日後施工時再裁（岔路，不做成選項題）

- 工具形狀：照使用者講的名字做一家多支（`goal_set`／`goal_show`／`goal_done`／`goal_pause`／`goal_resume`，像 `mailbox_*`，工具表多 5 支）還是一支 `goal` 分 op（多 1 支）；放哪個包（self 包或新 `goal` 包）。
- 放棄要不要另一支（`goal_done` 帶 `abandoned`，或另開 `goal_abandon`）。
- 「連續」怎麼算、何時歸零：腦叫了工具就歸零？收到新信歸零？還是只有人／agent 重設 goal 才歸零。
- 新信進來會不會自動 resume（使用者沒選那個選項，沒裁）。
- 到上限後怎麼再啟動（`goal_resume` 是否同時歸零計數）。
- 做在 idle 格裡，還是加一個新 hook 事件（例 `on_idle`）讓預設 hook 做——前者省、後者通用但要解決 handler 進 history 的問題。
- agent 睡著／被停時不丟（loop 不跑就不會到 idle），醒來後要不要先丟一次。
- 跟 do_task／subagent：子的 goal 獨立；do_task 一次性小幫手要不要帶父的 goal。
- 跟線 C 的衝突點：包檔（`lib/packs/`、兩範本 tools.json）、知識庫每支工具要有節點、`children`→`subagent` 改名；施工要等線 C 進 main 再動。
