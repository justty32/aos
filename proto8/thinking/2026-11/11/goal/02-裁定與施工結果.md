## 施工結果（白話）

- **狀態一份檔** `<agent stack>/goal.json`：`{text, status, reason, reminded, limit, set_by, updated_by, updated_at}`；status＝active／paused／done／abandoned，reminded＝連續沒進展被丟了幾次。讀寫、提醒文字、上限判斷全在 `lib/agent/goal_state.py`（四邊共用）。暫存檔＋改名。登記進 NORMS 附錄 4（持久、進 image、新檔不用重建）。
- **外面** `aos-agent goal get|set|done|pause|resume|clear`（照 `aos-agent system`）：`set [--limit N] TEXT... | -`（預設 10）、`done [--abandoned] [REASON...]`、`pause [REASON...]`、`resume`（計數歸零）、`clear [-y]`；沒 goal 時 get 印 `no goal` 退 0。父 agent 替子設＝同一條（`-t 子`）。
- **工具** `lib/agent/goal`（新包 `lib/packs/goal.json`，一支）：op get／set／done／pause／resume，純包 `aos-agent goal`（先 `ctl who` 認自己，同 self_system）；done 收 `status`（done／abandoned）＋必給 `reason`，pause 必給 `reason`。
- **fsm**（`templates/agent-fsm/idle.py`）：收不到信、history 最後一則是沒有 tool_calls 的 assistant、goal active＝接一則 user `[aos] goal: <目標> (reminder N of LIMIT. Keep working on it; when it is finished call the goal tool with op done; if you are waiting for someone, op pause.)` 進 history、退 0 去 think；不走 queue。到上限那次接 `[aos] goal: reminder limit N reached; goal paused (op resume to go on). Goal: <目標>`、goal 改 paused、照樣去 think（腦看得到這則）。
- **eca**（`cmd/aos-eca/bin/aos-eca-turn` 的 `one_turn`，⑬）：認領後沒好信（queue 空）、history 最後一則是 assistant、goal active＝這輪題目換成同一則文字；交出去那刻（handed）先寫 goal.json 再接進 history。冷卻中照舊不做；退讓（SessionBad）什麼都不寫。
- **歸零**：fsm 在 idle 判——最近一則 `[aos] goal:` 之後有 assistant 叫了 `goal` 以外的工具＝這次先歸零再數。eca 在每輪成功答完後判——CLI 自己的對話檔（transcripts）這輪長出來的那段有 `tool_use`／`function_call`／`custom_tool_call`／`local_shell_call`／`mcp_tool_call` 且名字最後一段不是 `goal`＝歸零。
- `py/aos_flags.py` 的 NOTE_KINDS 加 `goal`。

## 代定（每條可翻案）

1. op 名字：讀狀態跟 self_system 用 `get`（不是 show）；工具五個動作 get／set／done／pause／resume。`aos-agent goal` 多一個 `clear`，工具不給（agent 收尾用 done）。
2. 叫 goal 工具本身算不算進展：get 不算；set 重設（計數 0、active）；done／pause 結束或暫停；resume 歸零。歸零時判「goal 以外的工具」，所以叫 goal 不會讓計數歸零。
3. 到上限：丟第 LIMIT＋1 次時改送 limit 那則、status 改 paused、reason `reminder limit N reached without progress`、updated_by `aos`；這則也進 history 並問腦一次（腦知道自己被暫停了；eca 不能只寫 history 不問 CLI，否則 ⑩ 會當成 history 被改、開新對話）。resume 歸零重來。
4. 「找不到最近一則提醒」（還沒丟過、被 summarize 掉）＝不歸零（保守：寧可早停不要無限丟）。
5. history 空（agent 還沒答過任何一輪）＝不丟：照「最後一則是沒有 tool_calls 的 assistant」字面。
6. eca 的「有叫工具」看 CLI 自己的對話檔；找不到檔（`--no-session-persistence`、還沒建）＝不歸零。名字比對：最後一段（以 `__` 或 `.` 分）是 `goal`。
7. eca 射後不理版（`--on-empty stop`）有 active 的 goal 時，queue 空也不退 10、改丟 goal（直到 done／pause／上限）。
8. 誰改的：`aos-agent goal` 看自己的 `$AOS_STACK` 在目標 stack 裡＝`agent`，否則 `outside`；身體自動暫停＝`aos`。提醒本身不改 updated_*。
9. goal.json 壞了：`aos-agent goal get/done/pause/resume` 報 `GoalBad`；set、clear 照蓋；idle 與 aos-eca-turn 安靜當沒有（idle 每 300 ms 一拍，不洗 log）。
10. 目標文字上限 1000 字（每次提醒都帶）；limit 1～1000。
11. 提醒不走 queue、不觸發 before_queue／after_queue hook（它不是信）。
12. 新錯誤代號：`GoalMissing`（沒 goal）、`GoalEnded`（done／abandoned 不能 pause／resume，要 set 新的）、`GoalBad`。
13. `pause` 已暫停又沒給新理由＝印一句「already paused」退 0；`resume` 已 active＝同（11-10 cli-sweep Q4 慣例）。
14. 包：新包 `lib/packs/goal.json`（不塞 self 包）——self 包是「看自己、改自己的設定」，goal 是做事的節奏，分開讓定義可以單獨不帶。
15. 寫檔次序：fsm 先寫 goal.json 再接 history（寫不成＝warning、這次不丟，免得無限丟）；eca 在 handed 才寫（交出去才算丟過一次）。
16. NORMS 附錄 4：持久、進 image（跟 history 一起走）。
17. 外面與 agent 同時改 goal.json 不加鎖，後寫的贏（fsm 的 act 與 idle 不同時跑）。

### 做法

- **goal-2**：`goal_state.due(history)`＝history 空、或最後一則是沒有 tool_calls 的 assistant。fsm（`idle.py`，沒有 history.jsonl 也算空）與 eca（`aos-eca-turn` 的 `goal_prompt`）都改用它：還沒答過任何一輪、queue 空、goal active＝第一則就是 `[aos] goal: … (reminder 1 of LIMIT …)`，計數照樣加一。開場白（`--prompt`）照舊先投、先答，goal 下一輪才丟。eca 那邊 queue 空、沒有上一輪答案時：題目就是那則提醒，`session.txt` 不在＝開新對話，`reseed` 對空 history 給空字串（不附紀錄）；`--on-empty stop` 也一樣丟（同原代定 7）。
- **do-5**：goal 不認識 do_task、do_task 不通知 goal——fsm 本來就只看 history（`progressed_fsm`，改名 `goal_state.progressed`），沒有別的耦合；do_task 的 start／end 是「goal 以外的工具」，照原規則就算進展。改的是「上次提醒找不到」那條（見代定 18）。
- **eca 照現況、不改成只看 aos history**：eca 的 history.jsonl 只有題目（user）與 CLI 最後的答案（assistant），工具來回在 CLI 自己的對話裡，aos 的 history 根本沒有「叫了工具」這種行；eca 也不給 do_task。所以 eca 仍看 CLI 自己的對話檔（transcripts）判有沒有叫工具；理由寫進 `aos-eca-turn` ⑬。
- **goal set**：`aos_agent/goal.py` 的 set 那層 `parse(..., keep=1)`（同 `say` 的 `keep=1`、`history summarize/set` 的 `keep=2`）：旗標寫在文字前面，從第一個字起原樣收（`set Read --help first.` 的 `--help` 是文字；外層的 `--target`／`--daemon` 寫在文字後面也是文字）。其他動作（done、pause 的理由）照舊旗標前後都收。help 加一句；`knowledge/aos/cli/goal.json`、`aos/cli/flags.json#/text` 的清單、aos-agent README 跟著改。工具 `lib/agent/goal` 本來就把 `--limit` 放前面、文字走 stdin，不用改。

### 代定（接上面 1～17 的編號，每條可翻案）

18. **提醒找不到時以 `[aos] summary:` 為界**（取代代定 4 的說法）：從最後一則往回找，碰到 assistant 叫了 goal 以外的工具＝進展；停在最近一則 `[aos] goal:` 提醒。history 裡一則提醒都找不到時（do_task end 預設連別人的訊息一起摺、把提醒也摺掉；summarize；手改）＝停在最近一則 `[aos] summary:`——history 在那裡被改寫過，提醒多半在被摺掉的那段裡；do_task 摺完留下的 end 那則在總結後面，照樣算到。提醒和 summary 都沒有＝不歸零（保守，同代定 4 的精神）。**順手修正**：原程式在找不到提醒時其實會一路往回看到最舊（有更早的工具呼叫就歸零），跟代定 4「不歸零」的字面不符；現在照字面。
19. summary 那則本身不算進展（可能是外面 summarize 的，不是 agent 做事）；界線之後要有 assistant 叫了工具才算。summary 的認法：content 開頭 `[aos] summary:`，角色不管（`aos-agent history summarize --role` 可改角色）。
20. history 空時丟的那則也算一次提醒（`reminded` 從 1 起）；跟停下來時丟的同一句話，不另寫開場版。
21. mail-1 的兩條代定（全新起來只記不提醒、`notified.json` 每次都寫）見 backlog-rulings。
