# 02 施工結果、實測、代定、要重建什麼

← [self-system](README.md)

## 做了什麼

- `lib/agent/agent_files.py` 認 `system` 宣告（定義內相對檔名）。
- 人用：`aos-agent system get [-l|--json] | set [檔|-] | reset [-y]`（`cmd/aos-agent/aos_agent/system.py`，用法 [aos-agent docs/07](../../../../cmd/aos-agent/docs/07-system.md)）。沒宣告＝`SystemMissing`、宣告壞＝`SystemBad`。
- 給腦：`lib/agent/self_system/`（`aos-agent system --target 自己` 的純包裝；下層的提醒行也印進 stdout），進 `lib/packs/self.json`，兩範本 35 支。
- agent-fsm、reviewer：`interfaces.json` 宣告 `"system": "system.txt"`，`fsm.json` 拿掉 `--system system.txt`；`brain.py` 照宣告先找 stack 那份。eca-claude 宣告了、不帶檔。
- eca（`lib/agent/cli_session.py`，只動起 CLI 的 argv）：claude＝`--append-system-prompt-file`＋`--system-prompt-snapshot off`；codex＝`-c developer_instructions=…`。非互動與畫面兩條路都接。
- 對應關係補齊：`subagent` 多 `op: system`（轉 `self_system`）；`aos-agent ctl state`／`self_state` 多一類 `system`（來源、幾 byte、第一行）；`lib/aos/defs` check 驗 `system` 宣告的形狀。
- `llm set system=…`（含 `self_llm`）照存、提醒改用 `aos-agent system`／`self_system`。（**11-11 使用者翻案，見 [backlog-rulings](../backlog-rulings.md)**：改成 `ArgumentsBad`、不存、錯誤行指路。）

## 實測（11-11，公司機）

- 假腦：fsm 劇本 get → set → 下一格 think 送的 system 換成新的整份 → 空字串＝不送 system → reset 回定義（`templates/tests/agent-fsm/test_own_system.py`）。
- **eca claude haiku（非互動）**：同一段對話（session id 沒變）裡——人 `set`「句尾加 [~]」→ 下一輪有 [~]；換成「句尾加 [#]、不用 [~]」→ 下一輪 [#]；`reset` → 下一輪沒有記號。claude 自己經 aos-mcp 叫 `self_system` set「[%]」→ 檔寫進 stack、下一輪 [%]；再叫 reset → 檔刪掉、下一輪沒有記號。`--resume` 續接也跟著變，靠 `--system-prompt-snapshot off`（claude 2.1.322 的 help 寫明預設會把第一輪的 system 記下來、續接時照舊送）。
- **eca codex gpt-6-luna（非互動）**：新對話會吃 `developer_instructions`；**同一段對話 `codex exec resume` 帶新的不生效**（直接用 codex 驗過：resume 時給 [#]，回答仍是開頭的 [~]）。刪掉 session.txt 開新對話後，新文字就生效。所以 codex 底下 `aos-agent system set／reset` 多一行提醒（`self_system` 也轉給腦）。
- **codex 由腦自己叫 self_system**：第一次卡在兩件跟 self_system 無關的事（① codex 起 MCP server 不帶父程序的環境變數，aos-mcp 少了 `AOS_HOME` 起不來、腦看不到任何 aos 工具；② MCP 呼叫要核准、`approval_policy=never` 下一律被拒），使用者裁定後修了（下面「已裁」）。修完重驗（gpt-6-luna，經 aos-eca-turn）：看得到 aos 工具 35 支、叫 `peek_now_time` 通；codex 自己叫 `self_system` set → 檔寫進 stack → 開新對話後那段文字成了 developer 訊息（transcript 裡看得到）、回答帶記號；再叫 reset → 檔刪掉 → 開新對話沒有那則 developer 訊息、回答沒記號。
- 畫面那條路只驗提醒：開著畫面時 `set`／`reset` 印「要關掉再開才生效」（用假 tmux 畫面驗）。
- fsm 真腦沒驗（公司只有小模型），回家測。

## 代定（可翻案）

1. eca 畫面開著時改 system＝只印提醒、等重開才生效（頂層照調查員推薦代定）。11-11 使用者選維持現狀（[backlog-rulings](../backlog-rulings.md)）。
2. `self_llm`／`aos-agent llm set` 收到 `system` 鍵＝照存、提醒指到 `self_system`／`aos-agent system`（頂層代定）。**11-11 使用者翻案，見 [backlog-rulings](../backlog-rulings.md)**：選「報錯並指路」。
3. 不做 `ls`／`rm`：system 是一整段文字，`get` 就是看、`reset` 就是拿掉；家族裡 `ls` 是列多項、`rm` 是拿掉其中幾項，這裡沒有多項。
4. 空字串照收：fsm＝不送 system 訊息（知識庫根照接），eca＝什麼都不附加；不會退回定義那份（要回定義用 reset）。11-11 使用者選維持現狀（[backlog-rulings](../backlog-rulings.md)）。
5. 定義那份檔不在＝空文字（同 llm 定義那份不在＝`{}`）；defs check 只驗宣告的形狀、不要求檔在。
6. eca-claude 範本宣告 `system` 但不帶檔（預設什麼都不附加，`self_system` 一開始就能用）。
7. （11-11 使用者選維持現狀「claude 每輪重讀 system」，[backlog-rulings](../backlog-rulings.md)）claude 宣告了 system 就一律加 `--system-prompt-snapshot off`（不管有沒有自己那份）：這樣 reset 也是下一輪就回去。代價是 claude 自己 system 裡會變的段落（日期等）變了也會讓快取失效。
8. ~~代定~~ **已裁**（使用者 11-11 選項框 「codex 底下改了 system prompt 要開新對話才生效。改完之後 aos 要不要自動替它開新對話？」→「只提醒、不自動」）：codex 只提醒「下一段新對話才生效」，不替它自動開新對話。
9. brain.py 有給 `--system` 就照它、不看 stack 那份（同 `--tools`）。
10. `aos-agent ctl state` 的 system 類細節最多印 2000 字，全文用 `system get`。

## 已裁（使用者 11-11 選項框）

- 「codex 底下的腦現在看不到任何 aos 工具（codex 啟動工具時不帶環境變數，aos 工具起不來）。要不要修？」→「修」：`lib/agent/cli_session.py` 起 codex 時用 `-c mcp_servers.aos.env={…}` 明寫帶 aos-mcp 與工具實際讀的 `AOS_*`（`AOS_HOME`、`AOS_DAEMON`、`AOS_CLOCK`、`AOS_CLOCK_INTERVAL`、`AOS_KNOWLEDGE`、`AOS_LLM_KERNEL`、`AOS_KERNEL`、`AOS_THOUGHT_DEPTH`、`AOS_THOUGHT_FROM`、`AOS_LINUX_USER_STACK` 有設的，加上這次的 `AOS_WS`、`AOS_STACK`），不整個環境照倒。
- 「codex 每次叫 aos 工具都會停下來等人核准。要不要讓 aos 工具在 codex 底下免核准？」→「aos 工具免核准」，選項說明原文：「eca 範本起 codex 時，只對 aos 那組工具關掉核准（跟 claude 那邊已經允許 aos 工具是同一個意思）。codex 自帶的工具照舊要核准。」：同一處加 `-c mcp_servers.aos.default_tools_approval_mode="approve"`——codex 0.167 的 MCP server 設定有這個鍵（值 `auto`／`prompt`／`writes`／`approve`），只管名為 aos 的那個 server；`approval_policy`、沙箱、codex 自帶的工具都沒動，`~/.codex/config.toml` 沒動。
- 「codex 底下改了 system prompt 要開新對話才生效。改完之後 aos 要不要自動替它開新對話？」→「只提醒、不自動」：維持代定 8。

## 要重建什麼

- 新宣告、新檔（定義與 stack 的 `system.txt`），不用重建。
- 舊定義的 `fsm.json` 還寫 `--system system.txt` 的照舊能跑，但看不到 stack 那份（`self_system` 改了沒效）：把那兩個字拿掉、在 `interfaces.json` 補 `"system": "system.txt"`。
- 舊的 eca 定義沒宣告 `system`＝`self_system` 回 `SystemMissing`：要用就補宣告。
