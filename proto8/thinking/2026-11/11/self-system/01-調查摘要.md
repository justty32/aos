# 01 調查摘要：system 怎麼開放給 agent

← [self-system](README.md)

調查的結論（使用者照它在選項框裁了四題，見 [README](README.md)）：

- **不整合進 self_history**：history 是對話紀錄（只附加），system 每次從檔讀、不存進 history（P-41），放進去就要在 history 裡造一種特殊訊息，兩個機制做同一件事。
- **不做大的 self_settings**：能調的設定已經各有一支（工具 `self_tools`、腦 `self_llm`、hook `self_hook`、對話 `self_history`），再做一支「什麼都能改」的會跟它們重疊；system 照家族的模子單獨一支最省事。
- **模子照抄 self_llm／self_hook**：定義宣告相對檔名、stack 同路徑放這隻自己的；人用的 `aos-agent` 子命令是本體，給腦的是純包裝（`ctl who` 認自己）。差別只有一個：system 是一整段文字，**自己那份在就整份用**，不像 llm 只存改過的鍵。
- **兩種身體的用法不同**：fsm 自己組請求，system 訊息就是那份文字（取代）；eca 的 CLI 有自己的 system prompt，只能附加。
- **快取**：system 在請求最前面，換一次會讓 prompt cache 失效一次；寫進 tooldef，請腦別每輪換。
