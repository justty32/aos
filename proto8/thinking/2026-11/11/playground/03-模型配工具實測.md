# 03 — 模型配工具實測（家機 11-11 晚）

← [playground README](README.md)

使用者 11-11 晚：「我在顧火，大約十五分鐘後回來，幫我多試試看各種模型配各種工具。目標...就用我們現有的知識庫吧」。

**結論**：11 個模型讀知識庫、grep、todo、fork、self_system 這些都會用，答案也都對。**全軍覆沒的是「寫知識庫」**：試驗場沒給 agent 自己的知識庫，所以 knowledge_write 一律報 KnowledgeMissing。有的模型停下來問，有的自己在 ws 亂開一個知識庫，三種位置都出現了。另外有兩件值得討論：do_task 摺疊之後模型看不到自己讀過，就重做一次；eca 開的 subagent 沒設腦，答出 FAKE ANSWER。

## 怎麼跑

- 每個模型各掛一隻臨時 agent，名字照模型取：fsm 系的 fg／fl／ft／fs 從 `agents/fsm_ann` 掛，codex 系的 cl／ct／cs 從 `agents/eca_cody` 掛，claude 系的 bh／bs／bo／bf 從 `agents/eca_bob` 掛。
- 換模型用 `aos-agent llm set model=…`。11 隻同時跑，各自依序 `say` 再 `listen`，並記下秒數。
- terra／sol 走臨時 4001 proxy，因為 4000 還沒有 6.1 的名字。試驗場 kernel 的 url 暫時指向 4001，跑完已改回 4000、4001 也關了。
- 題目：
  - **T1**：查 goal 提醒上限的預設值。答案是 10，在 `aos/tools/goal.json#/rules`。
  - **T2**：用 grep 或 glob 找出 `proj/calc.py` 裡的函式，答案是 add、mul。
  - **T3**：todo 加兩項、勾掉一項。
  - **T4**：knowledge_write 寫到 `playground/notes/<名>`，不准寫進 aos/，寫完讀回來。
  - **T5**：do_task start → knowledge_read → end，只有 fsm 跑。
  - **T6**：交給 subagent 或 fork 去查 math 工具做什麼。
  - **T7**：self_system get，念出第一句。
- 貴的三個（sonnet、opus、fable）只跑 T1 和 T4。

## 發現（只記錄、沒修）

1. **試驗場沒有可寫的知識庫，T4 全倒。** knowledge_write 回的錯誤提示是「給 root（一個你能寫的資料夾）」，結果各模型自己挑位置：luna 選 `ws/`，在 ws 根留下 `_index.json` 和 `playground/`；haiku 選 `ws/kb/`；opus 和 fable 選 `ws/knowledge/`。同一個 ws 裡現在有三個知識庫。要討論的是：試驗場（或 agent 定義）要不要預設給一個自己的知識庫，例如 `AOS_KNOWLEDGE` 或定義裡的 root？錯誤訊息是否該直接建議一個固定位置？
2. **knowledge_read 不收 root。** 自己寫進去的知識讀不回來，luna 帶 root 被回 ArgumentsBad。所有寫成功的模型最後都改用 read 讀檔。寫和讀不對稱。
3. **do_task 摺疊把「讀過」的證據也收掉了。** 摺疊後歷史只剩 start、摘要、end。terra 在 end 之後重讀一次，又重做整個任務；sol 在 end 之後又讀一次。原文確實有 knowledge_read（`history_removed.jsonl` 對過），所以不是幻覺，是模型不相信自己做過。另外摘要那則 user 訊息排在 end 呼叫的前面，順序也有點怪。
4. **eca 開的 subagent 沒設腦，就是假腦。** haiku 叫 subagent `kb-reader`（`ws/defs/kb-reader`，`llm.json` 是 `{}`），收到的回答是「FAKE ANSWER」。haiku 有發現並自己補讀，但子 agent 留著沒收，是我後來 purge 掉的。fsm 用 fork 就沒這問題，因為 fork 繼承自己的腦。
5. **gemma 在 knowledge_write 漏 description**（ArgumentsBad），錯誤訊息講得很清楚，它下一輪就補上了。說明錯誤訊息有用。
6. **codex 系的 self_system 行為不一。** eca 沒有 system.txt，所以 get 拿到的是空的。luna 照實說空，terra 和 sol 卻當成「隱藏指令不能念」而拒絕。不算工具的錯，但 eca 的 self_system 拿到空值時，模型容易誤會。
7. **sol 的 T4 只講了打算就收尾。** 它說「我會用本地 knowledge/」之後沒有任何工具呼叫，這一輪就結束了。listen 拿到的是半截話。這是模型行為，aos 這邊沒錯。
8. **秒數**：同時跑時，fsm 單題 25～45 秒；第二輪單獨問時 luna 才 8 秒。慢的部分應該是 4001 proxy、LM Studio 和 fsm 輪詢一起擠出來的，這輪沒有拆開量。
