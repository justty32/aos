## grep／glob

- 兩支 base 工具 `lib/base/grep`、`lib/base/glob`，純 Python 標準庫，共用 `lib/base/file_walk.py`（走樹：深度優先、每層照名字排；隱藏名；gitignore＝先問 `git rev-parse --is-inside-work-tree`，成立再叫 `git ls-files -z -o -i --exclude-standard --directory` 拿被擋的清單、走樹時跳過；資料夾捷徑列出但不進；只讀一般檔〔fifo 等不讀，免得卡住〕；預算 20 秒或 2 萬項，模組常數、測試直接改，不加環境變數）。
- 進第 1 包「看」（`lib/packs/look.json`），兩範本 36 → 38 支；`shell` 說明原句「Use it to search (grep, find)」改成「to search, prefer grep (file contents) and glob (file names)」，知識節點 `shell.json`、`ls.json` 叫人用 shell 搜的句子改指新工具。
- 輸出、上限、翻頁、尾巴行、錯誤代號（新 `PatternBad`）照設計稿 D1～D8。知識節點 `aos/tools/grep.json`、`glob.json`（範例是實跑輸出）。
- 測試：grep 12、glob 7、`lib/tests` 32 全綠；`aos-tools call` 實跑通、stack 沒建工具小格；預算實測 `grep path:/usr` 20 秒收手、`glob path:/` 2 萬項停（0.3 秒）。
- 沙箱：aos-sandbox 只替 `cmd/*/bin` 自動綁 `tool_io.py`；lib 工具要綁什麼寫在各例子的 `ro` 清單，將來把 grep／glob 裝進沙箱，`ro` 要多列 `lib/base/file_walk.py`（這次沒動 aos-sandbox）。

### 代定（設計稿以外，可翻案）

- E1 在 git 工作樹裡 `.git` 一律跳過，`hidden: true` 也不進；只有樣式明寫那一段才進。
- E2 排序照路徑一段一段比（深度優先、每層照名字排，`src/deep/util.py` 在 `src/main.py` 前）；預算算看過的名字數（被跳過的也算），停時寫 `20000 entries` 或 `20 s`。
- E3 grep 的 `path` 是單一檔＝只搜它，`glob`／`hidden`／`gitignore` 不看（明指）；`path` 指進被擋的資料夾照搜（明指）。
- E4 只有 git 不在 PATH、`ls-files` 失敗或逾時才印 warning；`rev-parse` 失敗一律當不在 git 裡（不讀下層 stderr），所以 safe.directory 擋住時也安靜地不擋。
- E5 `path` 不是一般檔也不是資料夾（fifo、裝置）＝`ReadFailed`。
- E6 glob `type: file` 只算一般檔（含連到檔的捷徑）；fifo 等只在 `any` 列；連到資料夾的捷徑以 `dir/` 列出、不進去。
- E7 樣式 `/` 開頭＝`PatternBad`（「put the folder in path」）；grep 的 `glob` 參數壞＝`PatternBad glob: …`。
- E8 尾巴行：`... next_offset N (M matches in K files in all)`、預算用完括號換 `at least …`；files 模式 `(K files in all)`；offset 超過總數 `... no matches from offset N (…)`；skipped 三類 `binary file(s)`、`file(s) over 8MB`、`N unreadable`。
- E9 context 裡有中、但落在這頁以外的行印成 `-`（前後文），一頁的筆數不超過 `max_matches`。
- E10 `type`、`sort` 的 enum tool_io 不驗，`_entry` 自己驗、不合＝`ArgumentsBad`。
