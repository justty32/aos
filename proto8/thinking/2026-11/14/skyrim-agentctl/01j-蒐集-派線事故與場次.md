## 一、場次生命週期：用途、上限與刪除

### 三種記錄各管一件事

- **場次夾**：`home-<日期>/` 與當場一次性代號目錄，內放逐線交接及產物；一份交接書對應一條線、一個獨立 repo 或明確檔案範圍。來源：`S/agentctl/handoffs/README.md` 開頭。
- **STATE.md**：每天最新的場次現況，只寫本場、不抄前場，每場 ≤8 KB；不是下次續行清單。來源：`S/agentctl/handoffs/README.md`「現役」「保留期」。
- **NEXT-SESSION.md**：下次開場與現役續行入口，≤4 KB、不複製前場段落；精簡時舊段直接刪、不留快照。根層 SESSION-LOG 另限 ≤2 KB，只列 open，凍結事項一句加連結。來源：`S/agentctl/handoffs/README.md`「保留期」。

### 過時刪除的原句與保留期

指定 README 沒有一整句恰好叫「過時即刪、不建 done/history」；對應原文是：

「已完成、被推翻、到期的交接書與場次夾**直接 `git rm`**，追溯靠 `git log --all -- agentctl/handoffs/<路徑>`；`done/`、`history/`、`superseded/` 已廢除（2026-11-05），不再建。」來源：`S/agentctl/handoffs/README.md:5`。

到期條款另寫：「**場次夾**保留 **30 天或最近 5 場**（取較多）；到期由收線線整夾 `git rm`，不搬 `done/`。」刪前把仍被活文件引用的結論吸收進該活文件，使用者原句照抄，其餘連結降純文字，commit 訊息寫「刪除：<理由>」。來源：`S/agentctl/handoffs/README.md:14`。與保留期重疊時的優先序未載。

安排是結論留活文件、歷史用 git 找，更深動機未寫。刪／搬會斷鏈，刪後從 agentctl 根跑全庫 `python3 ../tools/check_markdown_links.py`，不帶 paths。來源：`S/agentctl/handoffs/README.md`「保留期」「刪場次夾後一定要跑連結檢查」。

落實工具的**文件說法**：`tools/hygiene_audit.py --older-than 30 --emit-script` 掃到期；`wf/tools/wf-lint-local.sh` 對 mtime >30 天的 home-* 報 `STALE-SESSION`，大小超標報 `HUB-OVERSIZE`。本次未讀實作。來源：`S/agentctl/handoffs/README.md:14` 與「保留期」末句。

### 什麼可進版控

2026-09-25 政策准進 md；tsv/csv/json 單檔 ≤1 MB；py/sh/toml/ini/txt ≤512 KB；`work/backup/**` 可留純文字 profile 備份。任何單檔 >1 MB 不准；每場非 md 合計 ≤2 MB，超量放 `~/notes/projects/modding/skyrim/handoffs-data/<場次>/`，REPORT 記路徑。gitignore 不能按大小排除，大檔不 git add，需保留時 gzip 後仍須 ≤1 MB。來源：`S/agentctl/handoffs/README.md`「保留期」「什麼能進版控」。

不准的副檔名原列：`.ess .skse .esp .esm .esl .bsa .dds .nif .png .jpg .jpeg .gif .dll .pdb .exe .zip .7z .rar .jsonl .pex .hkx .wav .xwm .fuz .log`；不准目錄原列：`work/ trash/ tmp/ preserved-*/ artifact/ offline/ mirror/ before/ after/ bin/ obj/ .housecarl-work/`，backup 例外同上。只 add 明確檔案，不做目錄級 add。來源：`S/agentctl/handoffs/README.md`「什麼能進版控」。

## 三、外部線怎麼判讀、多久看一次

### 同時看三訊號，不只看終局信

`S/agentctl/docs/driving-codex/monitoring.md`「四、監看」要求同時覆蓋：inbox 終局訊息、tmux session 消失、畫面 hash 停滯／批准提示。三者分別代表正常結束的回報、可能崩潰或被殺、仍活著但可能卡住；不能只憑一項宣告完成。

- **在等批准**：畫面命中 `Would you like to run`、`Press enter to confirm`、`Yes, proceed (y)` 就立刻通知。監看用 persistent，跟著有無現役線開關；timeout 到期不能假裝還在看。來源：同頁「四、監看」。
- **已退出或卡住**：capture-pane 之外查 pane_pid 子行程樹；Working 可能是復原的死 scrollback，沒有子行程表示原 agent 已退出。大量 ERROR 也不等於任務已死，還要查最終輸出／交付物。來源：`S/wf/lessons/dispatch-cli-agents.md`「tmux-working-text-is-not-liveness」。
- **已做完**：終局信是入口，再逐條對可查證來源與驗收；有矛盾、缺證據或高風險才補算／獨立覆核。結構量測通過也不保證內容正確，監看頁列中文翻譯結構通過、另一源內容檢測仍抓到殘缺譯文的例子。來源：`S/wf/lessons/dispatch-handoffs.md`「dont-trust-subordinate-self-report-verify-yourself」；`S/agentctl/docs/driving-codex/monitoring.md`「其他護欄」。
- **交棒時**：交棒書列每條線確切狀態、下一步；交棒前逐線 capture 確認指令真送出、不是停在輸入框，接手第一件事也是巡線。畫面不取代行程樹與交付。來源：`S/agentctl/docs/driving-codex/monitoring.md` 的「領導交棒時，線會空轉」「codex 長訊息要送兩次 Enter」及上述判活條目。

### 節奏與 context

`S/agentctl/docs/driving-codex/monitoring.md` 開頭記 notify_watch 每 20 秒看 new 與 tmux 孤兒；但不替線讀 orders／mail／topics。該頁末條明寫領導要 `inbox_poll.sh <自己> --wait`，因工人回報會路由到領導 mail。本次只讀這份文件，不宣稱監看器已在跑。

人／agent 的巡檢週期另有現行明文：每完成一步且至少每 20 分鐘發 PROGRESS，頂層 ≤20 分鐘巡檢。來源：`S/wf/lessons/dispatch-cli-agents.md` 開頭、`S/wf/lessons/dispatch-delegation.md`「trust-gpt-sol-more」。送鍵後的 4～5 秒確認是開工檢查，不是要求每幾秒完整巡線；後者在 delegation 條目被列為浪費模式。

context 是另一個換手訊號：`S/wf/lessons/dispatch-roles.md`「fable-top-opus-middle-management」寫大題切換或 context 過半就 compact，上級管下級；`dispatch-leads-and-line-discipline.md`「leads-manage-subordinate-context」要求大輸出落檔、Sonnet 單一任務做完即收、回報 ≤10 行。這是規則，未另列事故。
