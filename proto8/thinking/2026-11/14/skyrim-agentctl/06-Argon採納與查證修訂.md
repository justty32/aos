## 二、查證推翻或修正的「aos 現況」

三隻 sol 各查一塊，靜態讀 `proto8/` 程式、附行號，沒有實跑。

| 02 第一版怎麼說 | 查證結果 | 改成 |
|---|---|---|
| 隊員有 owner、`AOS_KERNEL` 指向上面的 gate，可以從這些推出上游 | **不成立**：只有掛的人那邊記了「我掛了誰」，隊員的 stack 與 daemon 表都沒有 owner；`AOS_KERNEL` 是控制請求入口，可繼承或明傳，不保證指向掛它的人 | 第二類第 1 條現況與方向重寫 |
| `subagent add` 不經門 | **相反**：它轉叫 `aos-agent ctl add`，環境有 `AOS_KERNEL` 就經門。我這隻沒設才直達 daemon | 第二類第 4 條、03 兩處改掉 |
| 腦的預算照寄件 stack 各算各的 | **說過頭**：llm kernel 同時有全站、每個 endpoint、每個寄件 stack 三層額度與 slots | 第二類第 4 條 |
| `agents_ctl ls` 完全看不出隊員在幹嘛 | **說過頭**：`ls` 的 JSON 有 `busy`（等腦／act／cli）；但空值不等於停下等話，也沒有一支指令把各種訊號合起來 | 第二類第 3 條 |
| `pause`、`sleep` 都可以真的停 | **一半**：`pause` 不打斷正在跑的那一格；`sleep` 才送終止訊號 | 第二類第 7 條、recipes |
| `mailbox_read` 讀了預設就刪，沒有「接了還沒辦完」 | 成立；補一句：控制請求與 kernel 轉寄那層有用 `in_reply_to` 對回信，但不是工作信 | 第二類第 2 條 |
| `max_subagents` 每隻各一份，三層 4×4×4 | 大致成立；精確說是每隻只算自己直屬掛的、不扣祖先額度，64 是第三代的數量 | 第二類第 4 條 |
| 獨佔資源完全沒有體系內的表示 | **說過頭**：slots=1 加上記錄誰在用，已能表達一格與佔用者；缺的是通用的取得／釋放約定 | 第二類第 5 條 |
| `subagent listen` 超過 60 秒被砍 | 成立，原因查到了：MCP 那層的預設逾時；repo 當天已修（252669c47），活樹複本還是舊的 | 第二類第 3 條、03 |

## 三、給頂層的兩件小事（都不是待裁題）

- 知識庫講 `say`／`pause`／`sleep` 的那頁值得補一句「say 不是剎車、pause 不打斷正在跑的那一格、要立刻停用 sleep」。知識庫我不動。
- 「掛在頂層 gate 底下」的 eca 如果環境沒有 `AOS_KERNEL`，它 `subagent add` 的請求不會經過頂層的 gate。我這隻就是這樣。要不要在掛 eca 時帶上，是頂層隊形的事。
