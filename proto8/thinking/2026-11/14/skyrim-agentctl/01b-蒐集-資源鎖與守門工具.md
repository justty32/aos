### 1.2 `lock.sh` 完整介面與實際硬度

來源：`C/tools/lock.sh:25`、`:103`、`:136`、`:181`。

```text
lock.sh acquire desktop|game --owner <無空白線名> [--note '<用途與時長>'] [--strict]
lock.sh release desktop|game --owner <無空白線名> [--force]
lock.sh status [desktop|game]
lock.sh --help     # 也接受 -h、help
```

- 預設路徑由 `$HOME` 與腳本位置推導；`LOCK_DESKTOP_DIR`／`LOCK_GAME_DIR` 可覆蓋完整鎖目錄，文件定位是測試用（`:22`）。
- acquire 先建立父目錄，再用原子的 `mkdir <lock>` 決勝；成功寫 `owner` 第一行：`<date -Is> <owner> <note...>`，並印 `ACQUIRED <資源> <路徑>`。任何 mkdir 失敗都走 `BUSY`＋owner、回 1，不分競爭、權限或壞檔型（`:124`）。
- owner 取該行第二個空白分隔欄位，不是子字串比對；`--owner` 非空且不得有空白（`:76`、`:231`）。
- acquire game 發現 desktop 不在或 owner 不同，預設 `WARNING` 仍取 game；加 `--strict` 才 `REFUSED` 且不建立。原始註解解釋：「保留預設放行是因為有不佔螢幕、但要 game.lock 的 profile 施工情境。」（`:37`）
- release 要 owner 完全相同才 `rm -rf`；不符回 1。`--force` 能跳過 owner 限制並警告，工具沒有另外驗證上游授權；歷史交付報告明說沒頂層明示不得用 force（`C@e6be53b4:handoffs/home-2026-10-23/improve/lock/REPORT.md:122`）。
- release desktop 若 game 還由同一線持有，只警告反序錯誤，仍會放；沒有 release 的 strict gate。
- release 目標不是目錄，直接 `NOT_HELD`、0；status 也只用 `-d` 決定 HELD／FREE。這包括「不存在」與「普通檔佔住鎖路徑」，不能把 FREE 當成路徑型態正常的保證。
- status 不要 owner；省略資源就印兩把。HELD 帶完整 owner 行與 `age=<秒>`，年齡取 owner 檔 mtime，沒有 owner 就取目錄 mtime（`:83`），不是解析 ISO 欄位。

| 回傳碼 | 意義 |
|---|---|
| 0 | 成功、help、鎖已不在，或 status 全部 FREE |
| 1 | BUSY、owner 不符、strict 拒絕等 |
| 2 | 用法錯誤，例如未知資源、漏 owner、owner 有空白 |
| 10 | status 查到至少一把 HELD |

### 2.2 `toolindex_check.py` 到底檢查什麼

來源 `C/tools/toolindex_check.py:32`、`:54`、`:84`、`:103`。

```text
toolindex_check.py [--index PATH] [--root PATH]
```

1. 解析表頭名「必用工具」；無該表頭的分隔列 fallback 第二欄，處理 `\|`，不把跳脫 pipe 當分欄。
2. 對工具欄的**每個反引號 span**取第一個含 `/` 的路徑 token；略過 python／bash／sudo 等前綴、旗標與 `<…>`；`python3 -m 模組` 跳過；裸檔名無 `/` 也跳過。
3. 路徑不存在印 `MISSING <索引行號> <path>`；只要有 missing 就 exit 1。
4. 路徑存在，工具所在目錄直接有任一 `test_*.py` 就算有測試，不要求同名、不 import、不執行測試。
5. 沒有直接測試則 `NO-TEST` warning；若只在子目錄或上一層同名測試有找到，額外提示 discover 層級落差，但仍不算失敗。
6. 索引讀取錯誤 exit 2；否則 exit 0／1，最後印解析條數、MISSING、NO-TEST。

**回答「工具沒登記就擋？」：不會。** 它只從表向路徑核對，未掃整個 tools 反向找漏登，也沒有執行白名單。現行 pre-commit 沒接這支；tool-index 寫「收工跑」（`:51`），wrap 原碼也沒有自動叫它。`test_toolindex_check.py:118` 的真索引測試連 exit 1 都接受，只驗能跑完出摘要，不證明真表無漂移。

## 3. wrap：收工一鍵的順序與停下方式

### 3.1 介面與 repo 順序

`C/tools/wrap.sh:4` 只 exec `python3 wrap.py`；git 輔助拆在 `wrap_git.py`，2026-10-26 commit `40091522` 拆檔註明行為不變。原型是 09-18 `hygiene/push-evening.sh`，10-03 kitB 正式化（`wrap.py:2`、git `97ca5af2`）。

```text
wrap.sh [-c REPO:PATH ...] [-f 清單檔 ...] [-m REPO:MSG ...]
        [--no-pin] [--pin-note 文字] [--push] [--apply]
```

- `-c` 可重複，只收各 repo 內明確檔案，絕對路徑、`..`、目錄、gitlink 都拒絕。`-f` 每行一筆 REPO:PATH，空行及 # 註解忽略。
- `-m` 是 REPO:MSG，未給的預設「收工（wrap 月-日）」；`--no-pin` 關自動 pin。
- 隱藏選項 `--root`、`--no-hygiene` 存在，原碼 `:194`；自動推導根會驗腳本是否真的位於 `<root>/agentctl/tools`，standalone agentctl checkout 不成立就回 2（`:31`）。
- 沒 `--apply` 不 commit／pin／push，**但 `--push` 即使 dry-run 仍會 fetch**；hygiene 也照跑，所以不是完全零狀態的唯讀指令。

repo 由內而外固定順序（`wrap.py:40`）：`profiles(instance/profiles)` → `agentctl` → `modpack-design` → `mod-library` → `instance` → `parent`。不存在的 repo 顯示跳過；明確指定要 commit 但 repo 不在則停。

### 3.2 一鍵實際做的 6 步

1. **印收工前表**：每 repo branch、tracked dirty 數、untracked 數、upstream ahead／無上游（`:60`）。它是觀測，不把整棵樹 dirty 一律判成失敗。
2. **按順序 commit 指定路徑**：`guard_index` 確認 active index 沒有其他 staged 路徑，否則停，不替別線 commit（`wrap_git.py:47`）。支援已 `git rm --cached` 且磁碟還在的路徑，不重新 add；最後是整個已核範圍的 index commit，不是 pathspec commit，避免吞回 untrack（`wrap.py:83`、`:110`）。沒差異就跳過。
3. **跑 agentctl `hygiene_check.py tracked`**：非 0 就停，訊息「有違規；不 pin、不 push」（`:241`）。注意這步在指定檔 commit 之後，不是事前交易檢查；commit hook 另有 staged gate。
4. **pin gitlink**：先 instance 的 profiles，再 parent 的 agentctl／modpack-design／mod-library／instance；只比 child HEAD 與 parent HEAD 記錄，不把 child dirty 內容拿來 commit（`:116`）。非 REPOS 名單的 changed gitlink 只提示不 pin，交子專案自己的隊；dry-run 會模擬本輪將移動的 HEAD。
5. **有 `--push` 才做 push**：先為全部 present repo 找 upstream、fetch、算 `HEAD..@{u}`；任一 behind 就停，該 push 階段一個都還沒推，不自動 merge／rebase。預檢全過再依 REPOS 內→外推 ahead 的 repo（`:147`）。parent push 前列 `push.recurseSubmodules` 與 on-demand 可能額外推的未列名 submodule；工具本身 pin 清單有限，不代表 git on-demand 推送範圍也有限。
6. **印收工後 unpushed 表**；成功 0。自定 Stop（含 git 失敗）印原因與現況表、回 1；CLI／根路徑錯誤回 2（`:255`）。

**失敗不做 rollback。** commit／pin 可能在前一步成功；push 預檢可做到「一個都沒推」，但真正 push 迴圈若後一本失敗，前面已推的也不還原。檔案清單讀取等非 Stop 類 I/O 錯誤沒有同樣的現況表保證。wrap 不自動收信、釋鎖、關行程、復原 profile、產交接或跑 wf-lint／toolindex／code-map；11-07 收工報告把這些額外程序另外列出。

## 5. precommit_gate＋policies：逐條規則與 hook 接線

### 5.1 判定流程與例外語意

`C/tools/repo_hooks/precommit_gate.py` 讀 `policies.json`，`--repo` 預設 cwd，`--policy` 不給時以工作樹 basename 推定；aliases 把 `skyrim`、`modding_skyrim` → `mother`。另有 `--policies PATH`、`--list-policies`、`--resolve-policy`。未知政策／壞設定回 2，不默默放行。

1. 只讀作用中 index 的 staged ACMR；刪除不查。
2. mode `160000` 是 gitlink，直接靜默跳過，不對 commit 物件猜 blob 大小。

## 6. 母 repo 另兩種守門：pin 與 Markdown links

### 6.1 submodule pin pre-push

`S/tools/hooks/pre-push:2` exec `tools/check_submodule_pins.py`。入口收 git stdin 的四欄 `local_ref local_sha remote_ref remote_sha`，也可 `--repo`、`--remote`、重複 `--update`；真正判定拆在 `S/tools/submodule_pins/{pins,branches,guard}.py`。

- 刪 ref 不查；一般 update diff 舊／新 SHA 的 gitlink；新分支先以 remote HEAD 為基準，沒有就走 remote 尚未有的 commits 內 gitlink（`pins.py:140`）。
- submodule 未初始化或該 commit 本地沒有 → WARN 放行；已被任一 remote ref 包含就 OK，必要時提示只掛側分支的持久性風險（`guard.py:52`）。
- 不可達時會 **fetch** 對應 sub remote 再查，不是純唯讀；仍不可達原則 block 1，錯誤 2（本次沒執行）。
- 但 `push.recurseSubmodules=on-demand` 或 `only` 會由 git 自己發布子 commit，所以 hook 放行，避免「pre-push 在遞迴 push 前先擋住修法」（`guard.py:15`、`:91`）。本次讀到母 repo 實際設定 `on-demand`。

### 7.2 CLI、掃描範圍與每個檢查項

```text
wf-lint.sh [--strict] [--quiet|-q] <dir>...
wf-lint.sh --self     # 模板 repo 自檢，不是一般專案模式
```

沒 dir 預設 `.`。一般模式 list_owned_files 排除 `.git`、node_modules、venv／.venv、__pycache__、archive／reference／references／vendor／done／superseded、放信用 inbox；`workflows/inbox` 是文件仍掃；不下鑽 `.gitmodules` 宣告 submodule，gitignored 也排除，tracked 不因 ignore 被漏掉（`S/wf/tools/wf-lint-checks.sh:39`）。因此一次掃 S 不等於同時掃 C，需另傳 C。

逐條一句，依實作：

1. **BROKEN 檔案連結**：剔 fenced／inline code 後抓 `](...)`，跳 http／https／mailto／純錨點／尖括號起始，去 fragment、嘗試 percent decode，再驗路徑存在（checks `:5`、`:21`）。
2. **BROKEN-ANCHOR**：有 python3 才呼叫 `check_anchors.py <root>`，驗 Markdown 內的本地錨點，計入 broken（`:105`）。
3. **OVERSIZE**：一般模式只查路徑含 `/workflows/` 的 md，單檔 >8192 bytes 印訊號，不是所有程式／文件 300 行政策都由此檢查（`:113`）。
4. **BIGLIST**：有 python3 才呼叫 find_big_lists，查 ≥1024 bytes 的表格／清單，跳 skills，AGENTS／WORKFLOWS／INDEX 檔名豁免；每列都有連結的區塊另標 BIGLIST-LINKS（`:121`）。
5. **資料檔 BROKEN**：CSV 及文字含精確 `"contract": "wf-table/` 的 JSON 呼叫 tabledb check，抽出輸出 `target` 問題，計入 broken；不是任意 JSON schema／語法全檢（`:143`）。
6. **QUERYCMD**：在非 wf／archive／tidy／skills 範圍的 md，除少數入口檔外，找散落的 `python3 ... tabledb.py` 或 `tools/tabledb.py` 查詢指令，提示資料檔查法不應到處複製（`:158`）。
7. **local hook**：只有傳入 `<dir>/wf/tools/wf-lint-local.sh` 真存在才呼叫，傳 dir 與 strict；非 0 算該 root 的 local=1，而不是把每一筆 finding 都相加（entry `:30`、checks `:167`）。
8. **模板殘留 residue**：逐一計數 `{{`、`〔模板說明〕`、`〔導入判斷〕`；實作是 literal 掃整份 md，不另外剔 code（checks `:169`）。
9. **inbox_pending**：計 `<root>/inbox` 第一層 `.md` 數，只放摘要，不因還有信就失敗（`:172`）。
10. **--self 額外檢查**：模板根入口連結、整包 >8192 bytes 檔案、template／skills／examples、各 flavor 及全 flavor 的一般／non-invasive 初始化成品；會建 temp、跑 wf-init 再刪，不是唯讀自檢，本次未執行（entry `:40`）。

平常只有 total_broken>0 exit 1；`--strict` 再把 residue、oversize、**BIGLIST（不含 BIGLIST-LINKS）**、querycmd、local 累計進失敗。inbox_pending 永遠不硬擋。缺 python3 時警告後略過 anchors／biglist／data，不會自動把缺檢查視為失敗；缺共用 checks 腳本則 FATAL 2（entry `:21`、`:27`、`:84`）。

**scope 差異會影響 retention。** 傳 S 根或 C 根，才找得到 `<root>/wf/tools/wf-lint-local.sh`；傳 `S/wf` 通常會找 `S/wf/wf/tools/...` 而不跑該 repo 外掛。11-07 報告跑 `wf-lint.sh wf` 只證明那個 scope 的 broken，不等於根層 retention 已過。

### 7.3 retention 如何機械化

文字規則：`S/wf/STRUCTURE.md:74` 與 C 同段，2026-11-05 起「過時即刪」，取代 kernel archive 但原文留著標示不照做；刪前把被引用結論吸收進活文件、連結降純文字，git commit 說明刪除理由，歷史用 git log 追。保留期原文（`:76`）：

> 「場次夾 30 天或最近 5 場（取較多）；SESSION-LOG.md ≤ 2 KB、NEXT-SESSION.md ≤ 4 KB、STATE.md ≤ 8 KB；信件 ack 後、結案項即刪；wf/user/ 頁用畢 30 天刪、HTML 不進版控；qa/reports/、tidy/reports/ 留最近 2 批。」

`wf-lint-retention.sh <dir>` 的實際演算法只有三類：

1. **ARCHIVE-DIR**：git repo 用 ls-files；非 repo 才 find 實體檔。看每條已列檔路徑中的目錄 component，一遇 archive／done／superseded／history，就輸出第一次那層的路徑，sort -u；`l10n/mods/`、`plugins/` 前綴豁免。不是找空目錄，也不是全磁碟所有 ignored archive（retention `:14`）。
2. **STALE-SESSION**：列磁碟 `handoffs/home-*/`，從 basename 抽 YYYY-MM-DD，排序；最新五個不報過期，其他日期若嚴格早於 GNU date 算的「30 days ago」就報。**以名稱日期，不以 mtime；最新五個即使很舊也保留**。第六個起只要仍在 30 天內亦保留（`:26`）。
3. **HUB-OVERSIZE**：root 的 `SESSION-LOG.md >2048`、`handoffs/NEXT-SESSION.md >4096`；場次 `STATE.md >8192` 只對名稱日期 ≥2026-11-05，且該場沒先命中 STALE-SESSION 才查（因為是 elif），舊場不追溯（`:39`、`:46`）。

每筆 finding 計 n，印 `SUMMARY retention: findings=N`；0 件 exit 0，有件 exit 1。local 外掛再交 kernel 決定是否 strict 硬擋。**腳本不 git rm、不刪資料、不排程自動清理**；它讓違規可數、可回傳，真正清理由授權收線執行。

文字政策與機械範圍的邊界：

- `C/handoffs/README.md:14` 說 wf-lint-local 按 mtime 查 home-*，與源碼「basename 日期」不符；audit --older-than 才按 mtime。
- hash／manifest 釘住檔案在 STRUCTURE 是例外，retention 只寫死成品兩個前綴，**沒有讀 manifest 判例外**。
- 用畢 wf/user 頁 30 天、HTML 不版控、QA／tidy 最近兩批、信 ack 後刪、場次 non-md 合計 2MB，**不在這支 retention 檢查中**；沒有把文字規則全機械化。
- audit 的 --older-than 只列「違反衛生政策」的老檔；合法 md 住在過期場次不會因此被 audit 列出，所以不是完整場次到期刪除器。
- 程式的 GNU date 若不可用，cutoff fallback `0000-00-00`，場次過期訊號會實際停用；這是原碼分支，不是本次跨平台實測。

### 7.4 agentctl local 外掛額外查什麼

C 外掛先跑 retention，保留回傳，再 find 現役 `handoffs/**/BRIEF*.md`（跳 done／superseded／templates）跑 **非 strict** brief_lint。它不是只看 staged，而是現役磁碟全掃；輸出每個 finding 加 `BRIEF` 前綴，統計檔數與 finding。brief_lint 自己預設 warning 回 0，所以外掛另依輸出行數判有 finding，回 1；讀檔錯回 2。缺 brief_lint 或 python3 印 WARN，但沿用 retention 結果，可能 0（`C/wf/tools/wf-lint-local.sh:21`、`:37`）。真正 commit 硬擋在前節的 staged BRIEF strict gate，不是每次普通 wf-lint 都硬擋。
