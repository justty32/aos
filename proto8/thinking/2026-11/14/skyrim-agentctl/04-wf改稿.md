## A. 往上轉信的三條規矩

**為什麼**：skyrim 的領導把工人的信往頂層轉時，規定三件事（`~/repo/moddings/skyrim/agentctl/tools/agent_inbox/PROTOCOL/wake-policy.md`「領導轉發的三條規矩」）。aos 現在每隻 ok-* 都是一條線的領導，信先到 xiaosi、xiaosi 依標題與 status 判輕重。xiaosi 是分流的，不會替寄信人補判斷，所以判斷要在寄的那一刻寫好。

### A-1 改 `wf/workflows/dispatch/aos-teams/07-預設流程與agent-fsm.md`

**位置**：「**頂層的雜務自動化**」那條底下，第一小點「小廝 `xiaosi`（sonnet eca，…）收所有 ok-* 的回報：…定時叫它。」的**後面**，插入一個新的小點（同一層縮排）。原有文字不動。

**改成（插入）**：

```markdown
  - **寄給 xiaosi 的信怎麼寫**（各 ok-* 與它們底下的隊長都適用；出處 skyrim 的「領導轉發三條規矩」，見 `proto8/thinking/2026-11/14/skyrim-agentctl/02-借鑑清單.md`）：
    1. **標題寫你的判斷，不轉貼隊員原話**：「線 X 做完，Y 已 commit（雜湊）」「線 X 卡在 Z，已試過 A、B」；不寫「完成」「報告」「sol 回報如下」。
    2. **標題或第一句標明你要什麼**：要使用者裁（status `NEEDS-USER`）、要頂層給資源或放行（`BLOCKED`）、只是報備（`PROGRESS`／`DONE`）。xiaosi 只看 status 與標題分輕重，寫錯就會被排進 20 分鐘彙整或被誤當急件。
    3. **正文先寫你已經排除的可能**：卡住或出錯的信，第一段列「試過什麼、為什麼不是那個」，頂層才不用重跑一次你做過的判斷。
```

**原文**：

```markdown
- 標題要是自足的一句結論，不可只寫「完成」「報告」。正文照四段格式。
```

**改成**：

```markdown
- 標題要是自足的一句結論，不可只寫「完成」「報告」。正文照四段格式。把隊員的信往上轉時照[三條規矩](dispatch/aos-teams/07-預設流程與agent-fsm.md)：標題寫你的判斷、標明你要什麼、正文先列已排除的可能。
```

## B. 交接書多四欄

**為什麼**：skyrim 的任務書範本（`~/repo/moddings/skyrim/agentctl/templates/BRIEF.md`、`agentctl/docs/driving-codex/handoff-contract.md`）有四樣 aos 範本沒有。其中「失敗分兩路」最實用：aos 的線現在回 `BLOCKED` 還是 `FAILED`、要不要自己還原，全靠各自理解。

全部改在 `wf/workflows/TEMPLATE.handoff.md`，四處，原有文字都不刪。

### B-1 子 agent 上限（硬性限制段）

**位置**：「## 硬性限制」清單，最後一行「- <其他：不得動的設定檔、不得啟動的程式、額度上限…>」的**前面**插入一行。

**改成（插入）**：

```markdown
- **子 agent 上限**：`<這條線總共最多再掛幾隻（含它們再往下掛的）；填數字、0 或「不限」>`。往下派時把這個數字寫進子任務書。
```

說明：`aos-teams.md` 那句隊員「無上限派子 agent」是使用者 11-06 原話，不動；這一欄只是讓每張任務書把數字講出來，填「不限」也算填。skyrim 那句「分配並傳遞總配額、不逐層倍增」沒有抄進來——體系目前沒有整棵樹共用的名額（借鑑清單第二類第 4 條），寫了也沒人擋得住。

### B-2 報告末尾回填工具（交付段）

（改稿 C 沒收的話，最後一句「調度者收線時…」拿掉即可。）

### B-3 失敗分兩路、錯誤來源分流（驗收段後新增一節）

**位置**：「**就這 N 條，不要做「其他你認為必要的驗證」**——…」那一行的**後面**、「## 完成／阻塞回報（必做）」的前面，插入一節。

**改成（插入）**：

```markdown
## 失敗怎麼收

- **跑了、結果是壞的**（有新的輸出證明它錯）→ 把本線動過的東西照 `<還原方式：git checkout -- 檔／還原備份／不用還原>` 收回，回 `FAILED`，附那次的輸出。
- **沒跑成、沒有證據**（工具壞、環境缺、權限不夠）→ **不還原**、保持現狀，回 `BLOCKED`，寫「什麼條件滿足了就能繼續」。不拿舊的 log 當這次的證據。

- **禁區是「你不可以寫 X」，不是「X 必須乾淨」**：別條線動了禁區裡的檔，不是你的收線條件，照實寫進報告就好。
```

說明：前三點是 skyrim BRIEF 範本「失敗處置」與「錯誤來源」兩格；第四點是它 `driving-codex/monitoring.md` 的教訓（三條線把禁區讀成結案條件），Argon 建議跟這次一起放進範本。

## C. 任務類型 → 怎麼做 的表

**為什麼**：skyrim 的 `agentctl/docs/tool-index.md` 開頭一句是「沒被交接書點名的工具就沒人用」。aos 今天六七條 ok-* 線各自摸索同一批事（怎麼掛 gpt 的 agent-fsm、怎麼設上限、怎麼等隊員），摸出來的東西散在各線的 thinking 檔與 `wf/temp/*/notes.md`。

**放哪裡，為什麼選 `wf/public/`**：

- 知識庫（`~/aos-home/knowledge/aos/`）是照工具排、而且各線不准動；`wf/knowledge/code-map` 是照檔排。兩邊都不是「我要做某件事」的入口。
- `wf/public/` 是使用者 11-14 才開的公用區，本來就是「大家摸出來的好東西放這裡」、由頂層管、各線可投稿、只追加。這張表的性質一模一樣，只是放的是做法不是程式。
- 為了不跟知識庫各養一份（Argon 的提醒）：表裡**只寫一行做法＋指到知識庫或 07 的哪一節**，不重抄用法；知識庫之後補了對應條目，那一列就改成純指標。
