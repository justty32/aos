# 審查：aos 公開 demo 發佈版草稿 v1（fable）

**總結論**：誠實度是這版最大的優點，可以當第一版給使用者看。最大的問題是主標「資料夾，就是函數」在整套草稿裡沒有任何一處讓讀者親手做到；送出前建議至少先修第 1、2、3 條。

審查範圍：兩份宣傳頁我只讀了抽出的文字和 SVG 標籤，沒有看實際排版。中文 README、status、faq 全讀，get-started 與教學 01 讀了前半，其餘頁只看標題。英文 README 沒讀。

## 一、定位

1. **【高】主標沒有被示範。** 首頁和 README 的示範都是「對 ann 說話、看 history.jsonl」，證明的是「agent 的狀態是檔案」。A 版圖裡的 `summarize({"text":…})` 是畫出來的，沒有一頁教人放一個 `_entry` 然後呼叫它。陌生人會記住主標，卻找不到對應的東西。
   - 修法：補一段約十行的實跑示範（建一個資料夾、放 `_entry`、用 `aos-exec` 呼叫、看輸出），放在首頁第二屏和教學裡。
   - 若這輪來不及，首頁的圖下面老實標「教學下一批」。

2. **【高】「為什麼要用」沒講出痛點。** 六張卡都在說 aos 是什麼樣子，沒有一句說它解決什麼。這版真正能兌現的好處是「看得見」：agent 做了什麼，用 `ls`、`tail` 就能看到。建議把這個意思提到副標或第一張卡。這是方向選擇，由使用者決定。

3. **【高】有三處講過頭。**
   - C5 標成 built，但 status.md 自己寫「把 Claude Code 掛進樹（L2，未實跑）」，兩邊矛盾。
   - status.md「今天能做」那欄混進三格沒跑過的：多隻 agent 互寄信、Claude Code、搬樹。未實跑的應移到獨立的「有、但這版沒驗」欄。A 版首頁的「今天能做」清單是乾淨的，以它為準。
   - README「教學 01：資料夾當函數」寫錯，教學 01 實際是「第一棵樹」，內容沒有函數呼叫。

4. **【中】副標 H2「不靠硬體，靠任意資源」陌生人看不懂。** 「任意資源」需要先懂 kernel 才有意義。建議改用 H2b「把 unix 哲學帶進 agent 時代」，它同樣是使用者原話，一眼能懂。

5. **【中】六張卡太多，建議收成四張。** 留 C1、C2、C4、C5（改寫後）。C3 和 C6 目前都只做到一部分，降到「怎麼組起來」那塊當說明。A 版的「哪些已完成、哪些還在實驗」那塊要保留。

6. **【低】示範的結果是 `FAKE ANSWER`，沒什麼驚喜。** 亮點其實是 history.jsonl 那三行（叫工具、工具回、答案），B 版有把它秀出來，A 版沒有。

## 二、A、B 兩版

**推薦以 A 為骨架，換上 B 的第一屏。**

| 區塊 | 用哪版 | 理由 |
|---|---|---|
| 第一屏示範 | B | 終端加上前後資料夾對照，一眼就懂「說一句話，多出 history.jsonl」，是兩版裡最好的一塊 |
| history.jsonl 三行 | B | 接在第一屏下面 |
| 主標、副標、一句話介紹 | A | B 版把副標丟了 |
| 資料夾＝函數圖 | A | 等第 1 條的實跑示範補上後才成立 |
| 特色卡 | A，收成四張 | B 只有兩張，太少 |
| 完成／實驗對照、今天與願景 | A | B 的願景只有兩句，沒有「今天能做」清單 |
| 下一步三張卡、範例、已實測環境 | A | B 完全沒有出口 |
| 安全提醒 | B 的位置 | 放在示範旁邊，比放頁尾有效 |

- **A 的弱點【中】**：九塊偏長；「六件事」的第一張卡和上面那張圖的說明是同一句，重複；「副標另一個候選」「備註」是審稿用的，上線前要拿掉。
- **B 的弱點【中】**：首頁塞了三十行 SETUP，應該只留四行輸入，其餘連到開始用；標籤全是英文（TERMINAL / INPUT、01 / NOW），和中文頁不搭。

## 三、文案表

**最好的三句**
- **P1**：有主詞、有動詞、有可驗證的東西（ls、讀、設權限），全表最紮實的一句。
- **V2**「從一隻 agent 開始，最後換成一支程式。」：願景裡唯一一聽就懂、又和別家不同的。
- **SEC**：直說風險、給出做法，陌生人會因此信任其他句子。

**最該改的三句**（改寫句是我寫的，不是使用者原話，要他點頭）

- **H2【高】**：改用 H2b，或用新句：
  - 中：「agent 做的每件事，都是你 ls 得到的檔案。」
  - 英：Everything your agent does is a file you can ls.

- **C5【高】**：把沒實跑的拆出去。
  - 中：「腦自己帶。先用假腦試，再換成任何 OpenAI 相容端點。」
  - 英：Bring your own brain. Start with a fake one, then point it at any OpenAI-compatible endpoint.
  - Claude Code 那半句移到「下一批」，實跑過再升回來。

- **C2【中】**：「不用另學一套框架」分不清是誰不用學，而且 aos 自己也有八個詞要學。
  - 中：「模型本來就會。讀檔、寫檔、列資料夾是模型最熟的動作，aos 就拿這些當介面。」
  - 英：Models already know how. Reading, writing and listing files is what they do best, so that is the interface.

## 四、文件骨架

1. **【高】缺「概念一頁」，這是最傷的缺口。** 設計稿裡有 `concepts/`，草稿裡沒有。現在讀者跑完開始用，沒有地方看「資料夾＝函數、樹、kernel 與信」這四件事。它和第一條的缺口是同一個，補上這一頁加一段實跑，主標才站得住。

2. **【高】第二傷的是「接真腦」。** 假腦跑完只有一句 FAKE ANSWER，讀者下一步一定想接真的。status 頁說端點實測過，但要讀者「自己加一包 endpoint 設定」，等於沒有路。建議排在下一批第一順位，早於 Claude Code 當身。

3. **【中】同一段指令抄了四份。** 首頁 A、首頁 B、README、開始用各有一份，已經出現小差異（有沒有 `nohup`、`timeout 60`）。多輪修改後一定會漂。建議以實跑腳本 `ref/get-started.sh` 為唯一正本，其他三處由它生成或加檢查。

4. **【中】先把空位留好。** 現在只有 install、tutorials、manual 三夾。建議這輪就建 `concepts/`、`examples/`、`reference/` 三個空夾，各放一頁寫「下一批」的索引；之後加頁不用動結構，首頁的三張「之後的批次」卡也有地方連。

5. **【低】教學檔名帶編號（`01-first-tree`），之後插頁要改網址。** 建議檔名不帶號，順序交給索引頁。

6. **【低】整體撐得住。** 每頁開頭一句結論、來源註記、「待驗」標示都有，文案表加 `copy:ID` 的做法能支撐多輪修改。
