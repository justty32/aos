### 1. 讀完第一屏（標題、副標、四個優勢）：這是什麼？它想讓我做什麼？

* **這是什麼東西：**
  老實說，只讀標題「新時代的軟體技術棧」跟副標「讓 unix 哲學再次偉大」，我**完全不知道這是什麼**——這兩句話套在作業系統、編譯器、容器工具或 Web 框架上都可以。
  我是讀完底下「四個優勢」裡出現的零碎關鍵字（「對話接著走」、「100 隻 agent 排隊共用 2 個模型位子」、「自己做一個工具、自己接一個模型端點」），才拼湊出來：**這是一個把所有狀態跟設定都存在資料夾（檔案系統）裡的輕量級 LLM Agent 執行框架與 API 排程器（Queue）。**
* **它想讓我做什麼：**
  它想讓我點「開始用」去下載這套系統，在上面跑多隻 AI Agent、掛自己的工具（Tool），並用它的排程機制去共用少數幾個 LLM API 端點。但讀完第一屏，我還不知道**為什麼我需要換掉現有的寫法來用它**（它解決了我什麼具體的痛點？）。

### 2. 逐段讀下去，哪裡卡住了、要回頭重讀、或不懂它在說什麼？

#### 卡點一：謎語式的數字
> **原文：**「核心三支程式，約 7500 行；八個詞講完整套概念。」
* **卡在哪：** 哪三支程式？哪八個詞？讀到這裡以為後面會列出「這八個詞是：……」，結果整篇讀完我也數不出是哪八個詞、哪三支程式。

#### 卡點二：「CPU／板子／硬體／作業系統」的類比自己打架
> **原文：**「一隻 agent，說穿了是一個一直在跑的迴圈：問模型、用工具、再問模型。這跟 CPU 做的事很像，所以我們乾脆把它當成一顆 CPU。CPU 一多，就要有地方插，於是有一支專門管它們的程式，那就是板子。而整套東西底下的硬體，就是 Linux……有了 CPU 和板子，下一步，就是作業系統了。……aos 的核心 kernel 做的是同一件事，只是它底下的『硬體』不是一台電腦，而是 Linux，加上 agent 要用到的各種東西。」
* **卡在哪：** 這兩段我來回重讀了三次還是混亂：
  1. 在真實電腦裡，主機板（板子）是硬體，不是「一支專門管 CPU 的程式」；負責排程與管資源的那支程式明明就是作業系統（kernel）。那在 aos 裡，**「板子」跟「kernel」到底是同一支程式，還是兩支不同的程式？**
  2. 前面說「Linux 是硬體、Agent 是 CPU」，結果下一段「可以嵌套」又寫：**「kernel 上面分兩塊，一塊是做事的 agent，一塊是另一個 kernel」**。在電腦裡，是 kernel 跑在 CPU 上，怎麼一轉眼變成 CPU（Agent）跑在 kernel 上面了？比喻前後顛倒，腦袋要一直重新對齊。

#### 卡點三：不明白為什麼要「kernel 套 kernel」
> **原文：**「可以嵌套。 還有一點：這一層可以再套一層。kernel 上面分兩塊，一塊是做事的 agent，一塊是另一個 kernel；那個 kernel 上面，又可以再分一次。」
* **卡在哪：** 完全沒講**為什麼**要這樣做。在什麼實際開發場景下，我需要在一個排程器上面再跑一個排程器？只講了「可以這樣套」，沒講「這樣套有什麼用」。

#### 卡點四：拿 `a=1+2` 的可讀性跟變數撞名當成本，結果 kernel 根本不管這個
> **原文：**「一行 a=1+2。……那除此之外呢？人看懂它要多久？原始碼佔多少地方？a 這個名字會不會蓋掉別人的？這些其實都是成本。……aos 的 kernel 就是為剩下的那些成本設計的：每個請求都先經過它，要優化什麼，由你來定。」
* **卡在哪：** 讀到這句我直接卡住：一個負責「讓每個請求先經過它、幫模型排隊」的 runtime kernel，怎麼可能管得到「人看懂程式碼要多久」跟「變數 `a` 會不會撞名（Scope 污染）」？那是程式語言設計、Linter 和 Code Review 的事。
  更讓人傻眼的是，往下讀兩行看到「今天做到哪」寫：**「看懂要多久、名字會不會撞這類成本，還沒有 kernel 在管。」**——既然沒在管（甚至架構上就不該由請求排程器管），為什麼前面要花兩大段拿 `a=1+2` 當引子？

#### 卡點五：為什麼「加一個資料夾」就等於「寫了一段程式」？又怎麼把語意理解換成普通程式？
> **原文：**「叫它改自己：『照類型分』不需要模型，它替自己寫了一段程式來做。改自己，就是在自己的資料夾裡加一個資料夾。……最後剩『判斷內容在講什麼』：這一步最難，是 aos 要去的方向。換掉以後，這個函數不再問模型，它是一支程式。」
* **卡在哪：**
  1. 資料夾只是目錄，為什麼「加一個資料夾」就能取代原本問模型的那一步？裡面的腳本怎麼被串進流程裡？中間跳過太多運作機制。
  2. **「判斷內容在講什麼」如果換掉不再問模型，變成一支普通程式，那它到底怎麼判斷一篇未知文章在講什麼？** 叫 Agent 自己手寫一個傳統 NLP 分類器嗎？這在技術直覺上說不通。

### 3. 哪兩段之間接不起來？

1. **從「02 重造計算模型（可以嵌套）」跳到「以往沒考慮過的成本（一行 a=1+2）」：**
   前面還在講 Linux、CPU、處理單元（PU）、Kernel 嵌套；下一段突然跳去講 `a=1+2` 的變數名稱衝突和可讀性。雖然開頭硬寫了一句「有了這個計算模型，再回頭看一行最普通的程式：a=1+2」，但前面那個計算模型跟 `a=1+2` 的可讀性**毫無邏輯關聯**。
2. **在「以往沒考慮過的成本」裡面，從「可讀性／名字相撞／畫家一週畫幾張」跳到「100 隻 agent 搶模型怎麼排隊」：**
   前面鋪陳了很玄的「以往沒考慮過的軟體成本」，結果最後端出來的解法是「API 請求排隊（Queue）與每日呼叫次數限制（Rate Limiting）」。併發排隊與限流明明是軟體工程最傳統、最常見的東西，怎麼會接在「以往沒考慮過的成本」後面？
3. **從「以往沒考慮過的成本」跳到「新的軟體開發範式（Lisp／把 Agent 一步步換成程式）」：**
   上一段講的是「多 Agent 共用模型端點的排程器」，下一段突然變成「Lisp 程式寫程式、把問模型的步驟一個個換成普通程式讓 token 歸零」。這兩件事（排程器 vs. Agent 自我重構成腳本）是兩個獨立的題目，中間沒有轉折就把讀者甩過去了。

### 4. 哪些詞沒有解釋就出現了？

1. **「核心三支程式」／「八個詞」**（01 精簡）：提了數字，但整頁沒公布答案。
2. **「板子」**（02 重造計算模型）：只說「專門管 CPU 的程式就是板子」，但沒解釋它在 aos 裡對應什麼元件、跟後面馬上出現的 `kernel` 差在哪。
3. **「照字跑過」**（02 起出現四次）：這是作者自己的口頭禪或內部黑話。第一次讀到時會愣住，要猜它是「照著文件上的步驟一字不差地實測過」還是「只跑過純文字 mock」。
4. **「每個寄件人一天最多幾次」的「寄件人」**（02 以往沒考慮過的成本）：前面都在講 Agent 呼叫模型，為什麼突然冒出「寄件人」？aos 內部是用寄信（Mail / Message Queue）溝通的嗎？前面沒交代。
5. **「這扇門」／「門」**（02「這扇門今天管過的是模型呼叫」、03「一扇會學的門」）：02 正文都在講 `kernel`，到了「今天做到哪」突然冒出「這扇門」三個字，沒解釋「門」跟 `kernel` 是不是同一個東西。
6. **「可以一直按」**（03 示意演示兩處 6/7）：猜測是網頁互動元件的提示字，但混在步驟敘述裡莫名其妙。
7. **「起一棵樹」／「同一棵樹」／「一棵樹住一台機器」**（04 NOW）：整篇 01～03 都在講「資料夾」、「CPU」、「板子」、「kernel」、「門」，結果到了 04 突然全部改口叫**「一棵樹」**！前面從頭到尾沒定義過什麼是「樹」（是指一個 aos 根目錄實例嗎？）。
8. **「假腦」／「真腦」**（04 NOW）：02 叫它「假模型」，04 突然改叫「假腦」、「真腦」，名詞不統一。

### 5. 哪些話你不相信，或覺得說得太滿？

這頁給我的強烈感受是：**標題跟概念吹得像發明了新世代作業系統，但每段底下的「今天做到哪」又誠實到讓我發現它目前只是個剛寫好的原型腳本。**

1. **「超高可併發：已實測（100 隻）100 隻 agent 排隊共用 2 個模型位子，全部答完，沒有掉一個請求。」**
   * **這句最扣分。** 對任何後端或系統工程師來說，100 個請求排隊共用 2 個 worker slot（Concurrency = 2）而且不掉請求，用 Python 的 `asyncio.Semaphore(2)` 或 Go channel 只要 15 行程式碼就寫完了，而且到了 02 才補充這 100 隻測的是「假模型」。把「100 個請求排隊進 2 個假端點」稱為**「超高可併發」**，會讓工程師覺得作者對高併發完全沒概念。
2. **「新時代的軟體技術棧」／「讓 unix 哲學再次偉大」**
   * 說得太滿。對照 04 現況，它目前能做的就是「建目錄、跑迴圈調用 OpenAI API、過一個 queue 排隊」。這是一個有趣的「目錄式 Agent 實驗框架」，稱不上「軟體技術棧」。
3. **「aos 的 kernel 就是為剩下的那些成本設計的（人看懂要多久、原始碼大小、名字相撞）」**
   * 完全不信。一個攔截並排程請求的機制，在原理上就不可能解決「人類看懂程式碼要多久」或「變數名稱衝突」。
4. **「一個資料夾就是一個函數，裡面用什麼語言寫都行，權限直接用 Linux 的，出了問題打開來看就知道。」**
   * 把問題講得太簡單了。為什麼大家不把每個函數都做成一個資料夾？因為跨行程與檔案系統的參數傳遞、型別檢查、錯誤堆疊（Stack trace）、還有多 Agent 同時讀寫資料夾時的 Race Condition，除錯起來比一般程式痛苦得多，「打開來看就知道」只在 Hello World 等級成立。
5. **「最後剩『判斷內容在講什麼』……換掉以後，這個函數不再問模型，它是一支程式。」**
   * 不相信。把「讀檔名、按副檔名分類、改名」換成普通腳本非常合理；但連「判斷未知文件內容在講什麼」這種語意理解任務都宣稱能換成不問模型的普通程式，這已經脫離現實了。

### 6. 讀完之後，你會不會想照著試？如果不會，差在哪？

**不會想照著試。** 差在四個致命傷：

1. **整頁沒有半行目錄結構或指令範例（零具象畫面）：**
   你從頭到尾強調「整套都是資料夾」、「一個資料夾就是一個函數」，結果整頁連一個 5 行的 `tree` 目錄長怎樣、裡面放什麼檔案、怎麼下指令跑起來都沒給我看。對工程師來說，看一個真實的資料夾結構範例，勝過前面兩千字的 CPU／板子哲學。
2. **真正吸引人的功能全部寫「還沒做」，現在能跑的功能我 10 分鐘就能自己寫出來：**
   整頁最亮眼的點子是「先讓 Agent 把事做到，再讓 Agent 把步驟一塊一塊換成普通程式（省 Token）」，但 03 明白寫著後半段「還沒做」。而 04 列出「今天 clone 下來就能做的」（對假模型說話、把資料夾當函數叫、接 OpenAI API 叫工具），我用幾十行 Python 就能做到，沒有為了這幾個基礎功能去學一套新框架的動力。
3. **安裝與安全成本跟「精簡、可遷移」自相矛盾：**
   第一屏說「整套都是資料夾，複製就能走」，結果最後一段警告我：**「只在一台 Manjaro 機器上跑過、建置走 vcpkg、會在你帳號下裸跑所以請準備虛擬機或容器」**。為了試一個只有基礎功能的早期原型，我要準備 C++ `vcpkg` 編譯環境還要開 VM？直接勸退。
4. **自創詞彙太多，閱讀心智負擔太重：**
   明明是「Agent 迴圈、目錄結構、API Queue、Mock LLM、Instance」，卻要包裝成「CPU、板子、kernel、處理單元、門、樹、假腦、照字跑過」，讀完覺得很累。

### 7. 如果只能改三個地方，你改哪三個？（附具體改法）

#### 第一改：第一屏（標題、副標、「超高可併發」）
**拿掉空泛的大口號與誇大的「超高可併發」，第一眼就讓工程師看懂它是什麼、長什麼樣。**

* **原本：**
  > `# 新時代的軟體技術棧`
  > `讓unix哲學再次偉大。`
  > `### 超高可併發`
  > `很多 agent 排隊，共用少少幾個模型端點。已實測（100 隻）100 隻 agent 排隊共用 2 個模型位子，全部答完，沒有掉一個請求。`
* **改寫為：**
  > `# aos：建在 Linux 檔案系統上的 Agent 執行環境`
  > `萬物皆資料夾：一個資料夾就是一隻 Agent 或一個函數。狀態直接存成檔案、隨時打包搬走，目標是讓 Agent 把重複的工作一步步改寫成普通程式。`
  > `### 統一的模型排程與限流`
  > `所有 Agent 的模型呼叫都經過統一的閘道（Kernel）排隊與配額管理。已實測 100 隻 Agent 同時發起請求、共用 2 個模型併發名額，依序跑完不掉單。`

#### 第二改：「02 介紹」的前兩節（重造計算模型 ＋ 以往沒考慮過的成本）
**砍掉混亂的「板子」與「`a=1+2` 變數撞名／可讀性」，直接講清楚「資料夾、處理單元、Kernel」三者的關係，並附上一個真實目錄結構。**

* **原本：**
  > `以 Linux 做硬體。 一隻 agent，說穿了是一個一直在跑的迴圈……那就是板子。……`
  > `一行 a=1+2。 有了這個計算模型，再回頭看一行最普通的程式：a=1+2。……人看懂它要多久？原始碼佔多少地方？a 這個名字會不會蓋掉別人的？這些其實都是成本。`
* **改寫為：**
  > `### 核心設計：站在 Linux 檔案系統上的三種角色`
  > `aos 不重新造輪子，檔案、行程、權限直接用 Linux 的，只在上面定義三件事：`
  > `1. **資料夾即函數（也是 Agent）**：一個資料夾就是一個可呼叫的函數，裡面放執行檔、狀態檔與子資料夾（工具）。如果它裡面跑的是「問模型 → 用工具」的迴圈，它就是一隻 Agent。`
  > `2. **處理單元（PU）**：不管是本地程式、外部 LLM API、甚至是需要等回信的人，只要包成「收輸入 → 等處理 → 寫輸出」的資料夾介面，對 aos 來說都是同一種處理單元。`
  > `3. **Kernel（排程閘道）**：一般作業系統管的是 CPU 和記憶體；aos 的 Kernel 管的是 Agent 時代的稀缺資源——API 併發上限、Token 額度、每個呼叫者一天的配額，以及誰先誰後的排隊規則。`

#### 第三改：「03 示意演示（7/7）」與「04 NOW」
**把不切實際的「完全不用模型判斷內容」講準確，並消滅最後才冒出來的黑話（起一棵樹、假腦、真腦、照字跑過）。**

* **原本：**
  > `03 (7/7)：最後剩「判斷內容在講什麼」：這一步最難，是 aos 要去的方向。換掉以後，這個函數不再問模型，它是一支程式。`
  > `04 NOW：不用模型起一棵樹，對假腦的 agent 說話，看對話檔與資料夾。……接一個支援工具呼叫的 OpenAI 相容端點，讓 agent 用真模型叫工具（接真腦）。`
* **改寫為：**
  > `03 (7/7)：最後只剩真正需要語意理解的「判斷內容在講什麼」才問模型（若文件格式固定，也能進一步換成關鍵字規則）。原本五步都要花 Token 的流程，現在絕大部分都固化成了可預測、零 Token 成本的普通程式。`
  > `04 NOW（今天 clone 下來就能跑通的四件事）：`
  > `- **不接 API 跑通流程（Mock 模式）**：啟動一個 aos 工作目錄，跟測試用 Agent 對話，直接打開資料夾觀察對話檔與狀態怎麼變化。`
  > `- **多 Agent 運作**：在同一個工作目錄下掛兩隻 Agent，各自對話（含教學）。`
  > `- **資料夾當函數呼叫**：實測把一個資料夾當成函數傳遞輸入並取得結果。`
  > `- **串接真實 LLM**：接上支援 Tool Calling 的 OpenAI 相容端點，讓 Agent 用真實模型呼叫資料夾裡的工具。`
