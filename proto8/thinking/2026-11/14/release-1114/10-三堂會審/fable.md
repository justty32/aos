下面照七題順序回答。引號裡是頁上原文。

## 1. 第一屏讀完：這是什麼、要我做什麼

我拼出來的理解：一個跑 LLM agent 的執行環境。agent、它的狀態、工具都存成資料夾，所以整包可以複製搬走；中間有個排隊的機制，讓一堆 agent 共用少數模型 API；工具、接哪個模型、排程規則可以自己改。它要我往下看演示，然後去 GitHub clone 下來跑。

但這是從四個優勢欄「拼」出來的，標題和副標本身零資訊：

- 「新時代的軟體技術棧」——「技術棧」我理解成語言＋框架＋資料庫那類組合，這裡顯然不是；「新時代」是形容詞不是內容。
- 「讓unix哲學再次偉大」——口號。整頁後面再沒出現 unix 兩個字，我不知道它跟 unix 哲學的連結在哪。
- 第一屏沒出現「LLM」「語言模型」，「agent」也沒定義。我是靠「模型端點」「對話」兩個詞猜出來這是 LLM 相關。
- 「核心三支程式，約 7500 行；八個詞講完整套概念」——哪三支？哪八個詞？整頁都沒列。

## 2. 卡住的句子（按閱讀順序）

(1) 「aos 把 Linux 當成硬體，在上面重新分一次：誰是 CPU、誰是板子、什麼可以拿來算。」
「板子」是什麼？主機板？往下讀才知道是「管 CPU 的程式」。主機板在真實電腦裡是硬體不是程式，比喻在這裡就歪了。

(2) 「一隻 agent，說穿了是一個一直在跑的迴圈：問模型、用工具、再問模型。這跟 CPU 做的事很像，所以我們乾脆把它當成一顆 CPU。」
「很像」在哪裡？agent 是一個會呼叫外部服務的行程，對我來說它像 process 不像 CPU。「說穿了」「乾脆」是在要我別追問。把它當 CPU 之後得到什麼，沒說。

(3) 「CPU 一多，就要有地方插，於是有一支專門管它們的程式，那就是板子。」接著「有了 CPU 和板子，下一步，就是作業系統了……排程其他程式、分配資源、管權限。」
板子已經在「管」CPU，kernel 又來「排程、分配、管權限」。這是一支程式還是兩支？「板子」這個詞之後整頁再沒出現，我猜是同一個東西換了名字，但不確定。另外「權限最高的那支程式」——後面「現況」說 agent 用我的帳號跑，那 kernel 也就是我帳號下的普通行程，哪裡權限最高？

(4) 「他對 aos 來說就是一個處理單元（PU），跟一張 GPU、一個外部的模型服務是同一類，照樣排程。」
前面 agent 是 CPU；這裡畫家、GPU、模型服務是 PU。CPU 是 PU 的一種？同義詞？更麻煩的是：agent 要「問模型」，而模型服務也是 PU——那 kernel 是排 agent、排模型呼叫、還是把 agent 排到模型上？讀到這裡我腦內的模型斷了。

(5) 「kernel 上面分兩塊，一塊是做事的 agent，一塊是另一個 kernel；那個 kernel 上面，又可以再分一次。」
「上面」是指它的子行程？為什麼要套一層？沒有動機。後面「現況」說「一棵樹住一台機器」，我才回頭猜「樹」就是這個嵌套。

(6) 「一層套一層，照字跑過」
「照字跑過」第一次看不懂，看到第三次才推斷是「照文件一步步做，有做出來」。這個詞出現七八次。

(7) 「有了這個計算模型，再回頭看一行最普通的程式：a=1+2。」
前一節在講嵌套 kernel，突然跳到一行程式的「看懂要多久」「名字會不會蓋掉別人」。這跟「agent 是 CPU」有什麼關係？往回讀一次還是接不上。

(8) 「aos 的 kernel 就是為剩下的那些成本設計的」→ 三行後「看懂要多久、名字會不會撞這類成本，還沒有 kernel 在管。」
一整節鋪陳 kernel 是為這些成本設計的，結果今天管的是「模型呼叫排隊＋每人一天幾次」。那是一個有配額的 rate limiter。整節到最後是落空的。

(9) 「這扇門今天管過的是模型呼叫……每個寄件人一天最多幾次」
「門」是什麼？要到第二個演示才出現「一扇會學的門」。「寄件人」是誰——agent？使用者？

(10) 「那為什麼大家不用？不好除錯，也碰不到底層。」
我不同意這句（見第 5 題），而且它跟後面的論點無關——後面講的是「改程式的可以是模型」，跟除錯、底層都沒關係。

(11) 「一個資料夾就是一個函數，裡面用什麼語言寫都行，權限直接用 Linux 的，出了問題打開來看就知道。」
這是整頁最核心的機制，卻只有一句。怎麼呼叫？輸入從哪進、輸出從哪出？資料夾裡要有什麼檔案？進入點叫什麼？一個字都沒有。

(12) 「跟它說『這個資料夾就是你，替自己加一個新工具』，它在自己的資料夾裡加一個資料夾就行了。」
「加一個工具」和「把某一步換成程式」是同一件事嗎？加了工具，模型還是得決定要不要叫它、傳什麼參數——那一步還是在問模型。演示 7／7 說「這個函數不再問模型」，那五步的先後順序是誰控制的？如果還是 agent，就不可能「不再問模型」；如果是寫死的流程，那頁上沒說什麼時候、由誰把流程寫死。

(13) 「模型也只是一種處理單元，換掉它，就是換一個處理單元。」
把「寫出能取代 LLM 判斷的程式」說成「換一個處理單元」，講得像換插座。

(14) 演示裡反覆出現的「用了多少模型長度只是示意，沒有量過」
我猜是圖表標籤跟註解黏在一起了，但純文字裡連出現六七次，像壞掉的輸出。「可以一直按。」——按什麼？另外「圖 2」出現在「圖 1」前面、而且出現兩次。

(15) 「4／7結果不太滿意。打開來看：它其實是五個小步驟」
打開什麼？對話檔？資料夾？「五個小步驟」是誰切的？真實 agent 跑完的 trace 通常不會這麼整齊。

(16) 「4／7這種話很難用公式算。設計上，讓門自己也是一隻 agent，由它讀了決定誰先。」
排程器本身要呼叫模型，而模型容量就是它要分配的稀缺資源——拿瓶頸資源做排程決策，每個決策多一次 LLM 延遲。還有：第一屏說今天的實測是「改一行排程規則」，演示講的是 agent 門。兩套講法，哪個是今天的？要看「今天能跑／還沒做」標籤才分得出來。

(17) 「不用模型起一棵樹，對假腦的 agent 說話」
「樹」「假腦」都第一次出現。「假腦」能猜（mock 模型），「樹」要回頭對照才猜到。

## 3. 接不起來的兩處

(a) 「可以嵌套」→「以往沒考慮過的成本」。前面是 kernel 套 kernel，下一節開頭「有了這個計算模型，再回頭看一行最普通的程式：a=1+2」。嵌套跟 a=1+2 的可讀性成本之間沒有橋。

(b) 「以往沒考慮過的成本」→「新的軟體開發範式」。前一節結論是 kernel 管模型呼叫排隊；下一節第一句「工具有了，下一步，是拿它怎麼寫軟體。」然後開始講 Lisp。「工具」指 kernel？指 aos？從 rate limiter 跳到 Lisp 的「程式即資料」，中間沒有過渡。

次要的：第一屏四個優勢（搬資料夾、排隊、改規則）是實際的工程功能，一進「介紹」卻變成「把 Linux 當硬體」的哲學，兩邊互不引用。「介紹」講 kernel，演示講「門」，應該是同一個東西，但沒有一句話說「門就是 kernel」。

## 4. 沒解釋就出現的詞

- agent（第一屏就用，第二節才用「迴圈」帶過）
- 模型／模型端點／模型位子——第一屏自己混用：「共用少少幾個模型端點……共用 2 個模型位子」。位子是一個端點，還是一個端點上的並發 slot？
- 板子
- 處理單元（PU）與 CPU 的關係
- kernel／核心——「核心三支程式」的「核心」跟「核心 kernel」是同一個意思嗎？
- 門
- 寄件人
- 樹／起一棵樹
- 假腦／真腦／接真腦
- 照字跑過
- 排程規則（寫在哪、什麼格式、「改一行」改的是什麼檔）
- 工具／工具呼叫（假定讀者懂 function calling；對目標讀者可能 OK，但沒說）

- unix 哲學（只在副標出現）

## 5. 不信、或說太滿

- 「新時代的軟體技術棧」「讓unix哲學再次偉大」——整頁沒有任何內容支撐這兩句。
- 「完全可遷移」vs 同一欄的「換一台機器還沒驗」。同一台機器搬資料夾叫「完全」太滿；頁尾還說「樹和樹之間現在還不會互相連線」。
- 「超高可併發」——100 隻 agent 排隊等 2 個位子，吞吐量就是 2。這是限流排隊，不是高併發。而且是「假模型」，沒有真實延遲、timeout、retry、429。假模型上「沒有掉一個請求」不代表什麼。
- 「八個詞講完整套概念」——我在頁上數出十幾個自創詞，沒有一處列出那八個。
- 「以往沒考慮過的成本」——可讀性、原始碼大小、命名衝突是幾十年的老問題；token 成本也到處有人算。
- 「aos 的 kernel 就是為剩下的那些成本設計的」——同節末尾自己承認沒管。
- 「作業系統是硬體上權限最高的那支程式」「權限直接用 Linux 的」——「現況」說 agent 用我的帳號跑、換資料夾不能隔離、請在拋棄式帳號或 VM 裡試。所以「權限用 Linux 的」實際意思是「沒有權限控制」。介紹當優點，現況當警告。
- 「最好的寫程式方式，Lisp 早就示範過……那為什麼大家不用？不好除錯，也碰不到底層。」——Lisp 有 REPL 和 condition system，除錯反而是強項；FFI、原生編譯都有，「碰不到底層」不成立。而且「資料夾裡放任何語言的腳本」跟 Lisp 的「程式即資料」距離很遠：資料夾能被讀寫，但程式碼不是結構化資料，agent 改它靠的是字串編輯。
- 「讓 token 一路往零走」＋演示 7／7「判斷內容在講什麼……換掉以後，這個函數不再問模型」——「判斷一份文件在講什麼」是語意分類，沒有模型要怎麼變程式？頁上只說「這一步最難，是 aos 要去的方向」。這是整個範式的終點，卻沒有任何機制描述。另外，如果終點就是一支普通程式，為什麼不一開始就寫？「用 LLM 當腳手架找出程式結構」是一個能講的論點，但頁上沒講，也沒說哪種任務適用、哪種不會收斂。
- 「一扇會學的門」——「看看它排得怎樣」怎麼看？沒有指標。「每個呼叫附上一句，說自己在做什麼」——agent 寫「緊急」就能插隊；用 LLM 讀自然語言決定優先序，等於開了 prompt injection 的入口。
- 「agent 替自己加工具，程式裡有，這版還沒驗」——「新範式」的核心動作，狀態是沒驗。演示 1 的 4～7 步、演示 2 的 3～7 步全是「還沒做」。兩個演示各七步，實際跑過的分別是 2.5 步和 1 步。
- 「精簡：核心三支程式，約 7500 行」——7500 行不大，但「精簡」是結論不是證據；不知道三支程式各做什麼，分不出是精簡還是功能少。

## 6. 會不會照著試

會 clone 下來看一眼，因為「今天 clone 下來就能做的」四條夠具體，第一條不用 API key。但不會照著「新範式」去試。差在：

- 我真正想試的動作（agent 改自己、把一步換成程式）全標「還沒做」或「還沒驗」。
- 到最後我還是不知道「一個資料夾當函數」長什麼樣：沒看到任何目錄結構、檔名、指令。
- 兩個演示都是「照設計畫的」，沒有一段真實對話紀錄。
- 它要我在 VM 裡跑，但沒說清楚為什麼值得開一台 VM——我看不出它今天能做的事，哪一件是一支 Python 腳本加一個 semaphore 做不到的。
- 不知道三支程式是什麼、怎麼起、互相怎麼溝通。
- 每一節結尾都把我推去「完整說明：為什麼做 aos ↗」，出現五次。這頁自己沒把話講完。

要翻轉我只需要兩樣東西：一個真實資料夾的 `ls -R` 輸出，和一段真實跑過的對話檔。

## 7. 只改三處

**(1) 第一屏的標題和副標。**
現在：「# 新時代的軟體技術棧 / 讓unix哲學再次偉大。」
改成：

> # aos：把 agent 存成資料夾來跑的 Linux 執行環境
> 每隻 agent、每個工具、每段對話都是一個資料夾；中間一個 kernel 讓很多 agent 排隊共用少數模型端點。原型，Linux only。

同一屏「完全可遷移」改「整包就是資料夾，複製就搬家」，「超高可併發」改「多 agent 排隊共用端點」。「完全」「超高」拿掉，欄裡的實測內容本來就夠。

**(2) 「以往沒考慮過的成本」整節刪掉，換一段講 kernel 現在實際做什麼；同時把「板子」「門」統一成 kernel。**
改成：

> ### kernel 現在做的事
> 每個模型呼叫都先經過 kernel 排隊，再送去端點。規則寫在 `＜檔名＞`，一行一條，例如：同時最多 2 個呼叫在跑；每隻 agent 一天最多 N 次。實測：100 隻 agent、2 個位子、假模型，全部答完。之後想讓它排的不只模型呼叫（人、GPU、token 預算），今天還沒有。

a=1+2、看懂要多久、名字相撞，今天沒有任何程式在管，放在這裡只會讓人以為有。

**(3) 「一個資料夾就是一個函數」那句後面，直接貼一個真實例子。**
現在：「一個資料夾就是一個函數，裡面用什麼語言寫都行，權限直接用 Linux 的，出了問題打開來看就知道。」
後面加（真實約定我不知道，以下是假的，要照實際的填）：

```
sort_by_type/
  run          # 可執行檔，任何語言
  README.md    # 一句話說它做什麼，agent 讀這個決定要不要用
```
> 呼叫：`aos call sort_by_type < in.json > out.json`。agent 自己也是這樣一個資料夾，多一個 `tools/` 子資料夾；「替自己加工具」就是往 `tools/` 裡再放一個這樣的資料夾。

這段放進去，第 2 題的 (11)(12)(13) 三個卡點和第 6 題一半的疑慮會消失。
