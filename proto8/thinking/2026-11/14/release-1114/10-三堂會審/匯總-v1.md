## 先講結論

1. **使用者的感覺是對的，而且不只是句子不順。** 三位各自獨立，卡在幾乎同樣的地方。最大的三個：第一屏看不出這是什麼；介紹用比喻解釋比喻（CPU、板子、kernel、PU、門、樹）；整頁沒有一樣看得見的實物（一個資料夾長什麼樣、一行指令、一段對話）。
2. **三位都說：頁上講的比做到的大。** 每段結尾的「今天做到哪」他們都讀到了，也都因此相信頁面是老實的；但結果是「前面鋪陳很大，段尾自己說沒做」，讀起來像落空。astra 的話：「比較像讀完一份未來設計提案，不是找到一個今天想裝來解決問題的工具。」
3. **會不會想試**：fable「會 clone 下來看一眼」，Argon、astra「不會」。三位給的理由相同：想試的（agent 改自己、把步驟換成程式）都還沒做；今天能做的又沒有一個看得見的例子。fable：「要翻轉我只需要兩樣東西：一個真實資料夾的 `ls -R` 輸出，和一段真實跑過的對話檔。」
4. 這次他們看的是純文字，看不到圖與互動演示。有幾條是抽字造成的（下面標「抽字」），不算頁面的問題。

## 五、我的建議

### A 我認為這輪就該改的（都是我或隊上寫出來的毛病，不動使用者定的方向；仍等使用者看過這份再動）

1. **T5 Lisp 那句改回第一人稱**。現在：「那為什麼大家不用？不好除錯，也碰不到底層。」改：「我們自己沒用它，是卡在兩件事：不好除錯，也碰不到底層。」這樣是經驗不是斷言，也貼回 user-advice 原話。
2. **T5「出了問題打開來看就知道」**改成「每一步留下的東西都是看得到的檔案」。
3. **T5「硬體上權限最高的那支程式」**：講的是一般作業系統，沒錯；但緊接著說 aos 的 kernel「做的是同一件事」，讀者會以為它有系統權限。補半句：「在 aos 這一層裡，由它說了算」。「權限直接用 Linux 的」後面連到現況的安全提醒。
4. **T1 板子與 kernel**：加一句分清楚。草擬：「板子只負責讓這些 agent 一直跑著；誰先跑、誰能用多少，是 kernel 在決定。」（對得上 user-advice：daemon 是板子，kernel 是上面的一號行程。）
5. **T4 用詞統一**：「門」第一次出現寫「kernel（下面叫它門）」或全頁只用一個；「假腦／真腦」改「假模型／真模型」；「照字跑過」改「照文件一步步跑過」；「寄件人」改「發出呼叫的 agent」；「模型位子」第一次出現說明是「同時能跑幾個呼叫」；「起一棵樹」第一次出現加半句「（一個 kernel 加上它底下的 agent，我們叫一棵樹）」。
6. **T4「八個詞」「三支程式」**：要嘛列出來，要嘛拿掉。三支可以直接寫出各做什麼（跑一步／反覆跑／讓很多個一直跑）。八個詞宣傳頁列不下的話，改成「概念只有八個詞，[列表在這]」並連過去。
7. **T3 兩句接詞**。草擬：
   - 嵌套→成本：「計算模型換了，要算的帳也跟著換。」
   - 成本→範式：「要省下這些成本，光靠排隊不夠，還得換一種寫程式的方式。」
8. **抽字那幾項**請 web 看一眼實際頁面。

### B 要使用者決定的（牽涉他定的字或方向；我只列選項與後果）

1. **第一屏加不加一句「這是什麼」**（#1）。標題、副標不動，在副標下加一行，例如：「aos 是一套在 Linux 上跑 AI agent 的原型：agent、工具、對話都是資料夾，很多 agent 排隊共用少數模型端點。」不加的後果：三位讀者都要讀完四張卡才猜得出來。我推薦加。（v3 那版原本有這樣一行，後來拿掉了。）
2. **頁上要不要放回一小塊真的東西**（S2）。使用者 14:31 定了「真正的 start 放 wiki」，頁上因此沒有任何指令和實跑輸出。三位都點名要看實物。選項：(a) 維持現狀；(b) 在「一個資料夾就是一個函數」旁放回一小格：一個真實資料夾的列表、一行呼叫指令、三行對話檔（這些都照字跑過，材料現成）。我推薦 (b)，只放一格，不放完整步驟。
3. **「成本」那一大段的順序**（#4、S3）。內容是使用者要的（a=1+2、kernel 設計來優化這些）。選項：(a) 維持；(b) 內容不變、順序倒過來：先說 kernel 今天實際在做的事（排隊、限次），再說「它是為了更大的一類成本設計的」，用 a=1+2 說明那一類是什麼。後果：(b) 讀者先拿到真的，再聽方向，不會覺得落空。我推薦 (b)。
4. **強字**（#9）。使用者 14:11 說過照寫。這次三位都不接受「超高可併發」，Argon 說會讓工程師覺得作者不懂高併發。選項：(a) 維持；(b) 詞不動，卡片的說明換角度，不講「100 隻排 2 個位子」的量，講它獨特的地方：很多 agent 共用很少端點、一個不掉、排法可以自己改；(c) 換詞（例如「少量端點，大量 agent」）。我推薦至少做 (b)。「完全可遷移」同理：詞旁已經寫「換一台機器還沒驗」，但讀者看到的是矛盾。
5. **演示最後一步**（#8、S4）。「token 往零走」是使用者的方向，我不改方向。選項：(a) 維持；(b) 兩套演示的最後一步改成不寫完成式：停在「還剩這一塊在問模型；能不能換掉，是我們要去的方向」，並在演示開頭補上 fable 說的那個論點：「先用 agent 把事做到，是為了找出這件事的結構；結構找到了，才一塊一塊換成程式。」我推薦 (b)。
6. **比喻要不要減**（#2、astra、Argon 都建議拿掉 CPU／板子）。這套類比是使用者的計算模型，我不建議拿掉；A-4 那一句若仍不夠，再談。

### C 這輪不建議動的

- 三位各自改寫的標題（「aos：把 agent 存成資料夾來跑的 Linux 執行環境」等）：標題副標是使用者定的，只呈報。
- Argon、fable 建議整段刪掉 a=1+2：是使用者 14:35、14:59 特別要的，不刪；用 B-3 的順序處理。
- 安裝成本（vcpkg、只驗過 Manjaro）：是事實，頁上照實寫是對的；等 docker 那條。
