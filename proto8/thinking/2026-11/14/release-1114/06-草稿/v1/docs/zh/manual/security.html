安全說明

agent 會用你的帳號執行程式。請在拋棄式帳號、容器，或丟了也不心疼的資料夾裡試。沙箱是實驗功能。

為什麼

事實意思
agent 是一般的 Linux 行程它能做你的帳號能做的事
agent-fsm 範本預設開了很多工具包：看、改、刪、殼（shell、run_python）等它可以讀寫刪檔、跑指令
這些檔案工具不擋工作區外的路徑（相對路徑從工作區算、絕對路徑照用）能不能動，只看 Linux 檔案權限
同一個帳號下的 agent 彼此沒有隔離一隻 agent 能碰到同帳號的其他檔案與行程

假腦（L0）不會真的亂做事，但範本的工具與權限是一樣的；接上真腦（L1 以上）才是實際風險所在。

建議的做法

  1. 拋棄式帳號：另開一個沒有重要資料的 Linux 使用者來試。
  2. 容器：放進容器裡跑（Docker 映像本版沒有提供；未實跑）。
  3. 丟了不心疼的資料夾：至少把示範夾放在 repo 外（例如 ~/aos-demo），不要把工作區設成放重要東西的地方。
  4. 收緊工具：從定義的 tools.json 的 $override 拿掉不要的包（例如拿掉 4「殼」與 3「刪」）；或只關一隻的某幾支：aos-agent tools rm shell、aos-agent tools rm run_python。

沙箱是 L3 實驗

專案裡有沙箱與限額相關的零件（aos-sandbox、aos-asuser；需要 bubblewrap 等外部工具），屬於實驗功能，本稿沒有實跑，不是安全保證。demo 版明講沒有「安全隔離保證」。
