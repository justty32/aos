## 2. 安裝現在長什麼樣（sol-2）

- **建置**：`cd proto8/impls && cmake -B build && cmake --build build`；CMake ≥ 3.21、C++20（aos-inst 是 C11）、vcpkg 只要 `nlohmann-json`、Threads；執行檔 `-static-pie`。vcpkg 找法：`CMAKE_TOOLCHAIN_FILE` → `VCPKG_ROOT` → `~/dev/vcpkg`。產物寫回各專案 `bin/`（不進 git）。**沒有預編發佈包。**
- **install.sh**：只做兩件事——把 `impls/*/bin/*`、`cmd/*/bin/*` symlink 進 `~/.local/bin`，在 Python user site 寫 `aos-proto8.pth`（指 repo 的 py、lib）。不裝依賴、不建 aos-home、不改 shell rc、不起 daemon；有 `--dry-run`、`--uninstall`。
- **Python**：只要 `python3` 標準庫，**沒有第三方套件**（HTTP 用 http.client）；最低版本沒明文，`aos-asuser` 要 3.12。
- **外部軟體（必需／可選）**：
  - 必需：Linux、bash、python3、CMake、C++20 編譯器、vcpkg（或自備 nlohmann-json）。
  - 選用，依路線：LiteLLM proxy 或任何 OpenAI 相容端點（FSM 真腦）、claude CLI＋tmux（eca-claude 路線與互動畫面）、codex CLI、LM Studio、bubblewrap／s6（aos-sandbox）、newuidmap（aos-asuser）、setfacl（aos-share）、systemd／s6-supervise（監管根 daemon，未驗）。
  - 內部工作流用、不是產品依賴：agy（Argon）。
- **起一棵樹**（文件有，但散在三處：`templates/daemon-root/README.md`、`kernel/docs/01-llm-kernel.md`、`templates/docs/02-agent-fsm.md`；另一條 eca-claude 的 17 步在 `thinking/2026-11/12/ops-notes-to-aos.md`，有版本落差）：
  1. 建置＋install.sh；2. 定 `AOS_HOME`（可直接指 proto8，或用 `extras/aos-home` 的 copy_tree 抄五夾）；3. 起 llm-kernel（預設 endpoint pack 是 `fake`，**不需要任何模型**；要真腦就用 `sol` 這類 pack 指向 `http://localhost:4000/v1`，金鑰走 `LITELLM_KEY` 環境變數）；4. 複製 `daemon-root` 與 `agent-fsm`；5. `aos-tree-start -- --stack stacks/root defs`；6. `aos-agent -d stacks/root ctl add --auto-restart -w . defs/ann`；7. `say/listen/chat`；8. `aos-daemon-ctl --daemon <stack> shutdown`。
- **推論**：「fake 腦＋FSM」這條完全不靠外部服務，是最適合當「clone 下來五分鐘跑得動」的第一條路；換真腦只是改一個 pack。eca-claude 路線最有看頭但要 claude CLI 帳號。
- 文件缺：LiteLLM 本身怎麼裝與寫 litellm.yaml、vcpkg 初次 bootstrap、從零到第一次成功的一條龍、預期輸出、疑難排解。

## 3. 隱私與安全（sol-1 指定七處＋opus 補掃全 repo）

- **產品本體七處**（proto8 的 README、docs、templates、lib、cmd、install.sh、knowledge）：`/home/<使用者>`、帳號名、email、`.zshrc` **零命中**；`sk-`／`token`／`api_key` 命中都是名稱、子字串、測試輸入，沒有看到真金鑰（文字掃描，二進位跳過）。
- **全 repo 追蹤檔**（opus `git grep`）：含 `/home/<使用者>` 的檔約 700 個，集中在 `archive/proto7-2`（391）、`wf/workflows`（100+）、`wf/inbox`（76）、`archive/proto5`、`proto8/thinking`（48）；email 字樣出現在 2 份 `wf/session_logs`。
- **git 歷史**：4,443 個 commit 的 author 是使用者的 GitHub 帳號＋個人 email（另有 2 個 `aos-apprentice`）。repo 本來就公開，這些已經在外面；改不改歷史只能由使用者決定（任務書：不自己改歷史）。
- `.vscode/settings.json` 有個人路徑，但**沒有被追蹤**（也沒被 ignore）。
- user-advice 是使用者原話；引用進文案前要列出用哪幾句讓他確認。

## 5. 同類專案怎麼做（web-research）

- README 趨勢是**短**（Letta 38 行、goose 63 行、LangGraph 82 行），細節交給文件站；長的（CrewAI 741 行、AIOS 459 行）讀起來累。
- 骨架：logo、標語、少量 badge、一句話、截圖／終端錄影、安裝 1～3 行、Quickstart、特色、架構圖、文件連結、授權。
- 安裝重的降門檻：預編二進位＋一行腳本（goose）、**按門檻分級**（OpenHands：無沙箱→Docker→原始碼）。最像我們的 AIOS 把架構圖放最前。smolagents 有「How smol」（用行數講規模）與獨立 Security 節。
- 文件目錄常見：Get started／Tutorials／Concepts／Examples／Reference／Changelog。
- 產生器：Jekyll（Pages 原生、可直接用 `/docs` 夾、不用 workflow，多語言自理）；MkDocs Material（Actions、多語言要每語一子專案，i18n 外掛已凍結）；VitePress／Docusaurus（內建多語言，要 Node）。

## 6. 限制與已知的事

- push、開 Pages、改 git 歷史、刪檔：使用者本人點頭才做。commit 走 commit-request、要頂層同意。
- 這條線原則上**不改程式**；安裝腳本要小修先報備。
- 給人看的頁照使用者風格：圖多、只講結論、細節摺疊、白話（wf/common/user.md）。
- 程式輸出一律英文；對外文件語言（英文／中文／雙語）是方向題，要問使用者、附推薦。
- proto8 是 prototype：沒有版本相容、格式會常改 → 文件要能跟著程式改，不宜手寫大量會過時的細節。
- 要能長期多次修改：草稿分版（v1、v2…）、採納表記每輪意見。
- 驗「陌生人 clone 下來照手冊能不能用」要在 `git archive` 乾淨複本＋`~/code/release-1114/` 暫存樹做。
