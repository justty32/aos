## 0. 結論

1. **骨架照 fable 稿**：同一個 repo 發，新增頂層 `README.md`＋`README.zh-TW.md`、`docs/`（Pages 站，Jekyll 從 `main` 的 `/docs` 原生發、不用 workflow）、`LICENSE`；產品本體還是 `proto8/`；另寫一份**公開清單**把「主打什麼」寫死。
2. **這個 repo 現在就是公開的**（`gh repo view`：PUBLIC）。內部紀錄（`user-advice/`、`thinking/`、`wf/`）與整段歷史早就看得到；發佈不會讓任何檔「新曝光」，只會讓更多人來看。所以掃描要掃**全倉**，不是只掃公開清單。
3. **安裝四級**：L0 假腦（零模型、零帳號）→ L1 任何 OpenAI 相容端點 → L2 Claude Code 當身 → L3 沙箱與限額（實驗）。首頁與 README 只推 L0。
4. **批 0 已驗**：L0 一條龍 6.4 秒（不含建置）、不跑 `install.sh` 只設三個變數就能用、Python 3.11／3.14 都通、vcpkg 路線建置 28 秒、L1 接 OpenAI 相容端點通。**沒驗到**：沒 vcpkg 的建置、多發行版、Jekyll 渲染、GCC／CMake 下限——都要 docker 服務（要 sudo）或 Ruby。
5. **第一印象**：Get started 主角是「打開資料夾看見 agent、信、狀態在變」，每做一步就看一個資料夾，並對照信送到前後的差異。
6. **宣傳頁手寫單檔 HTML**，草稿＝成品；**文案只有一個正本**（文案表），每句記依據原話、已實作／願景、使用者點頭沒。
7. **接下來**：等使用者答 ★ 題（★1 語言、★3 範圍最急）；有答案就開批 1 草稿 v1（只在本紀錄夾與暫存夾，不碰發佈檔）。

## 2. 發佈範圍（★3）

**先講白**：repo 已公開，GitHub 上每個被追蹤的檔、每個 commit 都看得到。下表的「不主打」只是**網站與 README 不連、不介紹**，不是「看不到」。

| 類 | 路徑 | 處理 |
|---|---|---|
| 對外主打（進公開清單） | `README.md`、`README.zh-TW.md`、`LICENSE`、`docs/`、`proto8/{impls,cmd,py,lib,kernel,templates,knowledge,cases}`、`proto8/install.sh`、之後的 `proto8/quickstart.sh`、`proto8/examples/` | 掃描 2B 加嚴必過；文件只連這些 |
| 看得到、標「設計筆記（中文、可能過時）」 | `proto8/docs`（CONCEPTS／NORMS／CONVENTION）、`proto8/README.md` | wiki 頁放一個連結並註明 |
| 看得到、不主打、不連 | `wf/`、`proto8/{thinking,user-advice,notes,feedback,extras,archive}`、`archive/`、`impl_cpp/`、`AGENTS.md`、`CLAUDE.md`、`.claude/` | 原地不動；README 最後一句交代「development history and working notes, not part of the product」；掃描 2A 全倉照掃，命中列給使用者決定 |
| demo 版明講沒有 | 兩台同時連線、版本相容、Windows／macOS 原生、套件管理器安裝、穩定 API、安全隔離保證 | status 頁三欄＋README Status 節 |

- **三案**（★3）：
  - **乙（推薦）同 repo**：最省事、長期改最便宜；外人看得到全部（本來就是）。
  - **甲 白名單匯出乾淨公開 repo**（astra）：外人只看到約 1,200 檔、6 MB 的產品；但舊 repo 仍公開（除非使用者改成私有），每版多一步同步。
  - **丙 從 HEAD 移走內部夾**（Argon）：門面變乾淨，但歷史裡還在、內部工具（wf）路徑全要改，**不推薦**。
- **體積**：`--depth 1` 仍 152 MB（`archive/` 83 MB）。乙案 README 教 sparse clone 只抓產品夾；上線後在 GitHub 上實測再寫數字。
- **公開清單**：`docs/_data/public-surface.json`，每條路徑＋一句理由；用途：掃描 2B 範圍、日後打包或匯出、給人審界線。
- **user-advice**：網站與 README 不連；宣傳頁只用使用者在文案表上點過頭的句子。
- 附帶問（★3 附題）：要不要正面講「這個專案是 aos 自己的 agent 團隊做的，過程都在 repo 裡」——repo 已公開，這反而是可以講的特色。

## 3. 軟體包與安裝分級

| 級 | 必需 | 得到什麼 | 首頁說法 |
|---|---|---|---|
| L0 | Linux（含 WSL2）、git、bash、Python 3.11 以上、CMake ≥ 3.21、C++20 編譯器、nlohmann-json（vcpkg 或系統套件） | 一棵樹、一隻 agent-fsm、假腦回話；「資料夾＝函數」小實驗 | 「不用任何模型」；「幾分鐘」的數字**等乾淨環境含建置量過才寫** |
| L1 | ＋任一 OpenAI 相容端點與它的金鑰（環境變數） | 同一隻 agent 換真腦、會叫工具 | 「換一個設定接上你的模型」 |
| L2 | ＋claude CLI（已登入）、tmux | Claude Code 成為樹裡的一隻 agent | 「把你在用的 Claude Code 納進來」 |
| L3（實驗） | 依功能：bubblewrap、s6、newuidmap、setfacl、systemd／s6-supervise；`aos-asuser` 要 Python 3.12 | 隔離、限額、分享、監管 | 只在手冊出現、標實驗 |

- 安裝頁第一屏講白：**Python 零第三方套件**、沒有 pip、沒有 venv。
- Get started 走 **`env.sh` 路線**（只設 `AOS_HOME`、`PATH`、`PYTHONPATH`，不寫家目錄；批 0 已驗）；`install.sh` 改成「想長期裝才跑」，文件講白它寫哪兩處、附 `--uninstall`。
- 建置兩條都寫：vcpkg 路線（標「已實測」）、系統套件路線（標「待驗」，docker 驗過才拿掉）。
- 預編檔、Docker 映像、Release：不在批 1；判準照 fable 3.3。Dockerfile 先只當我們自己的乾淨測試機。

## 4. 使用手冊、安裝手冊、範例、教學

### 4.1 站台目錄

```
docs/
  _config.yml               Jekyll 設定（minima 或自帶 _layouts/default.html；不用 remote_theme）
  _layouts/default.html     共用外框；內含 mermaid 前端啟動 JS
  index.html                宣傳頁（英文）   zh/index.html  宣傳頁（繁中）
  assets/                   圖、終端畫面、樣式、mermaid.min.js（本地一份，不靠 CDN）
  _data/public-surface.json 公開清單        _data/copy.json  文案表（正本）
  _tools/                   build-draft.py（Markdown→HTML，純標準庫）、抽指令實跑、隱私掃描（底線開頭不發佈）
  en/ 與 zh/（同結構；reference 只有英文）
    get-started.md
    install/   index requirements real-brain claude-code optional uninstall
    tutorials/ 01-first-tree 02-real-brain 03-two-agents 04-write-a-tool 05-claude-code-body 06-a-kernel-that-says-no
    examples/  index ＋每例一頁（由 proto8/examples/<名>/README 生成）
    concepts/  in-one-page folder-as-function tree kernel-and-letters bodies-and-brains vision
    manual/    run-a-tree agents mail brains limits-and-sandbox home-layout troubleshooting security
    reference/ cli tools errors env files glossary   ← 生成
    faq.md  status.md  wiki/index.md
```

- `build-draft.py`：把 `docs/` 的 Markdown 套 `_layouts/default.html` 輸出成靜態 HTML，給（1）使用者雙擊審稿、（2）掃描步 3／4。只支援我們用到的 Markdown 子集（標題、段落、清單、表格、程式塊、`<details>`、連結），用到新語法再加。它不取代 Jekyll：上線後以 Pages 實站為準，兩邊差異在批 1.5 push 後對一次。
- `manual/security.md`：agent 在你的帳號下執行程式；同帳號沒有隔離；建議在拋棄式帳號／容器／工作夾裡試；沙箱是 L3 實驗。README 的 Security 節連過來。
- `manual/troubleshooting.md` 第一條：**停樹與清殘留**（行程、lock、`stacks/`）；再來 `command not found`（PATH）、找不到 nlohmann-json、static 連結失敗、殼裡殘留 `AOS_*`、Pages 上 mermaid 不出圖。每條「症狀 → 為什麼 → 一行解法」。
- `get-started.md` 節奏：每一步後面接「看一下」（`ls stacks/root/procs/ann/`、history 裡「叫工具→工具回→答案」三行、信箱裡那封信）；**信送到前後各 `ls` 一次對照**；結尾固定「停樹＋確認沒有殘留行程」；示範夾放 repo 外（例如 `~/aos-demo`）。

## 11. 隊形

- **opus（ok-release）**：帶隊、定文案與每頁要寫什麼、審、commit 申請、所有對外動作的 NEEDS-USER。
- **sol**（agent-fsm，LiteLLM sol-high，`ok-release-sol-<n>`，limits `{"mem_mb":1024,"files":256}`）：實跑抄錄、照目錄寫文件初稿、HTML 施工、`build-draft.py` 與掃描腳本。要寫檔時只給限 `wf/temp/ok-release/` 與 `~/code/release-1114/` 的寫工具，或由它回文字、opus 落檔。**文案定稿與「這句能不能說」不交給 sol**。
- **astra**（同上，astra-high）：第二版宣傳頁視覺；每輪可再出一版對照。
- **fable**：使用者意見牽涉定位或範圍時再叫。
- **Argon**：批 1 草稿出來審一次；之後每輪一兩次。
