## 1. 現有 llm kernel 有什麼（repo 實作 `proto8/lib/aos/kernel_llm/`）

- **一站＝一個 proc**（活樹的 `llm-gpt` 是 ws daemon 上一個 300 ms 一輪的 looping proc）。agent 用 `AOS_LLM_KERNEL=<站 stack>` 寄信到 `requests/`；信體 `{"endpoint": pack, "request": {...}, "priority": ...}`。每封放行的信另掛成 `llm_<信名>` proc 去打端點。
- **endpoint pack**：`url`、`model`、`slots`、`cost`（只是標籤 free/high…，不是價錢）、`summary`、`budget`，選填 `exec`、`fixed`、`speed`、`backend`、`context`。活樹 llm-gpt：astra-high（slots 1、max_calls 500）、sol-high（slots 2、max_calls 1000）、fake；總 slots 3。
- **並行**：總 `slots`、pack `slots`、`backends.<名>.slots`、`max_packs`；`reserved: {"high": N}` 只保留給宣告 high 的信。
- **優先序**：只有三級 low/normal/high（數字只取正負）＋ deadline；排序＝宣告級＋`waited_cycles // aging_cycles`（預設 3）→ deadline → 同後端黏著 → speed → 等得久。不搶在飛的。
- **額度**：同時記三份帳——站總量、每個 pack、每個 sender（＝寄件 agent 的 stack 路徑）；單位是**次數與 token**（`usage.total_tokens`），不是錢；`window` hour/day/all（pack 與 sender 共用頂層的 window）；`spent: refuse`（回 BudgetMissing）或 `wait`（留在隊裡）。token 不預扣。
- **帳本**：站 stack 的 `ledger.jsonl`（每封收尾一行：id、endpoint、sender、model、時間、elapsed_ms、usage、code、child、switched）、`used.json`（當窗與累計，分 packs／senders）；agent 那邊 `observed.jsonl` 也記每次 think 的 usage。ledger 不輪替、可能有壞行重行，按 id 去重。
- **多層已經能串**：`llm_forward`——pack 寫 `{"kernel": "<下一站 stack>", "to": "<下一站 pack>"}`，信往下一站轉；**下一站看到的 sender 是上一站（不是原 agent）**，成功時 ledger 記 child 串帳。11-14 暫存樹做過 sol → llm-t1 → llm-gpt 兩層，「第一層按 stack 分額度」成立。
- **超額時 agent 怎麼辦（AK17）**：agent-fsm 收到 BudgetMissing → 冷卻重試 30 秒、1、2、4、8、15、30 分，之後每 30 分；不停機。`brain_notify` hook 寄一封 BLOCKED 給 `AOS_NOTIFY_BOX`（subagent add 預設＝父 agent 信箱），去重，只通知不加額度。
- **跟 kernel_gate 的關係**：gate（`AOS_KERNEL`）管「起／改 proc」的請求；llm kernel（`AOS_LLM_KERNEL`）管問腦。兩者共用框架零件、規則包不同、**互不連動**。唯一交會：llm kernel 掛 `llm_*` proc 時也寄自己的 `AOS_KERNEL`。頂層 gate → ok-* → sol 是派工／掛載關係，**沒有自動帶出 llm 額度或優先級**。

## 2. 現有 llm kernel 沒有的（缺口）

1. **優先級沒人填**：stock agent-fsm 的 `brain.py` 不寫 priority、`llm.json` 也不收，所以實際全是 normal。priority 由寄信者自填，沒有權限檢查。
2. **sender 不驗真**、沒列名的 sender 沒有預設額度（只受站總量與 pack 限）；活樹 llm-gpt 的 senders 還是舊名（gpt-lead2、sol-T03、sol-T04），現在的 ok-*-sol-N 都沒列。
3. **沒有部門／樹狀的額度**：沒有「父額度往下分」「子額度加總檢查」「借用／歸還」「保底」；嵌套只能靠 forward 串站，而且下一站只看得到上一站這個整體。
4. **沒有錢**：只有次數、token、秒；`cost` 只是標籤。
5. **不自動降級**：額度用完不會換便宜 pack；agent 只會冷卻重試。
6. **知識庫舊**：brain 頁沒寫 AK17；AK17 的 template／lib 屬換樹項目，活樹 agent 是否都套用沒核過。

## 3. 最大的盲區：多數 llm 呼叫根本不經 llm kernel

- 經過 llm kernel 的只有 **agent-fsm 身**（目前＝gpt 系 sol／astra，走 LiteLLM）。
- **eca 身**（Claude Code：repo-aos、各 ok-* opus、xiaosi sonnet；fable 子 agent；Codex CLI）直接用自己的 CLI 與訂閱，**不寄 llm kernel**。Argon（agy／Gemini）也不經。
- 但真正緊的額度正是 Claude：使用者有 Claude、GPT 各一個 200 美元方案（`wf/workflows/team-model/plans.md`）；Claude 有**週上限**（11-07 撞過）；額度緊時改 `.claude-alt` 帳號、99% 時各線暫停寫 HANDOFF（user/01「額度緊時」）。fable 最貴、只做頂層規劃。
- GPT 方案：LiteLLM 沒有這些 chatgpt 模型的價目，只能量 token（in／out／cached）、calls、秒；分級表：sol＝A 級能力、C 級消耗，astra 約 sol 的 3 倍。
- 所以：「誰燒了多少」現在只看得到 gpt 那一小塊；Claude 的用量要從別的地方來（目前不知道有沒有可讀的來源）。

## 4. LiteLLM proxy（家機 127.0.0.1:4000）

- 設定在 `~/repo/llm_proxy/litellm.yaml`（include deepseek、ollama、lmstudio、chatgpt、claude 五份）。有 chatgpt 系（astra、sol、luna、terra 各帶 low…max、nothink 後綴）、claude 系（opus-5-5、sonnet-5、fable-5-1…，經 callback 用登入憑證）、deepseek、本地 lm／ollama（wf 規定不用）。
- **沒有**設 budget、RPM／TPM、spend log；只有重試 2 次、timeout 600 秒。
- 也就是說：理論上 Claude 模型也能經 LiteLLM → llm kernel 走（agent-fsm 腦接 claude-*），但現在 eca 不這樣走。

## 5. 資源限制線（CPU／記憶體）可借的概念

- daemon `limits`：每 proc 的 rlimit（mem_mb、files、cpu_s、procs、file_mb）。`daemon.json` 頂層 `limits`＝預設；列上 `{}`／沒寫＝用預設；列上非空＝**整份取代**預設的數字鍵（使用者 11-14 選 a）。
- `limits_max`＝天花板：daemon 超過就**拒絕**（LimitBad），kernel 的 `limits.max` 是**夾值**（clamp，記 `limits_clamped`）；kernel 另有 `limits.default` ＋ `limits.by_sender[sender]`。
- rlimit 只繼承天花板、**不從父池扣帳**（三列各 1024 可以超過父的 1024）；cgroup（B5 計劃）才是**父格圈住所有子孫**、子 daemon 可再往下分（`mem_total_mb`、`procs_total`）。
- 事後標記：`limit_hit`（確定撞到）、`limit_suspect`（猜的）。
- 可以共用的形狀：預設／按人覆蓋／天花板（拒或夾）／事後標記；「每人各自上限」與「父池圈子孫」兩種模型並存。

## 6. 全景（ok-view）那邊已經留好的口

- **部門＝有孩子的任何節點**，不另設型別；主管＝節點本人；可無限嵌套；`self`（本人）與 `rollup`（含所有後代）分開；`tags` 只上色。父子判定：`config.parents` → subagent 紀錄 → 名字前綴 → `parent_rules`。**組織歸屬 ≠ 請求路由**（有的 ok-* 沒 AOS_KERNEL）。
- **董事長指令**：`POST /api/order {kind, target, what, ...}` → 一封 REQUEST 信（標題 `[董事長指令:<kind>] <target>：<what>`，`from: user`、`via: aos-view`、body 帶 `order`），**頁面不自己動手，接單的部門走 gate**。三種：`expand`（擴充；`budget?`）、`hire`（HR；`role/model/count`）、`power`（「電力：llm 額度」；接單者＝「之後的 llm kernel 上層，沒設就寄 repo-aos」；欄位 `target`、`priority`、`quota?`，理由放 `what`）。`priority` 目前是自由文字（提示「高／中／低」），欄位截 200 字。0.5 期已上線送單入口。
- 機房區預留「電力」卡：各部門用量＋調整申請；**沒有正式讀取介面就顯示 `not recorded`**（使用者選只走正式介面，頁面不自己翻 stack）。
- 新 UI（ok-view 這輪）要放部門視角、2D 縮放、嵌套、三種指令。
