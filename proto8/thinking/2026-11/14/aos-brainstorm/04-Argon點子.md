### 1. 重點題點子：人是外部計算單元、好不好懂、管人的 Kernel（#1 ～ #12）

* **#1【反直覺】「好不好懂」不用人打分數，看他怎麼「偷懶」就知道了**
  直接問人「這段好不好懂請評分」反而最耗注意力；管人的 kernel 只要偷看人的行為副作用——秒選推薦代表好懂、點開細節又關掉留 `?` 代表太繞、整批放置不理代表密度太高——就能反推出「好不好懂」這個值。

* **#2【反直覺】「不想看」和「全照推薦」不是敷衍，是高價值的壓縮訊號**
  當人回一句「都看過了照推薦」或直接跳過整批題，代表這塊領域在他心裡已經「不值得動腦」或「信任度夠了」；kernel 可以把這種敷衍當成「允許這塊邏輯粗化、以後別再拿這種細枝末節來煩我」的綠燈。

* **#3 人類也有「快取（腦容量）」，排程要湊「同個腦袋狀態」而不是照先來後到**
  人最慢的地方不是按按鈕，而是「切換話題重新進入狀況」；管人的 kernel 不應該照時間順序塞題，而是把同一個資料夾、同一種氣氛的問題扣著湊成一小包，讓人開機一次腦袋就順手刷完。

* **#4 先丟一題「探針」測人醒著沒，醒著才順手遞下一張牌**
  一次丟一百題過去只會讓人直接關視窗；kernel 平常只放一題極短的「探針題」在門口，只有偵測到人剛秒回了一題（代表人現在手在鍵盤上、正在等載入或發呆），才趁熱再遞兩三題過去。

* **#5【反直覺】問題會自己「過期發臭」，扣著不問反而自己就解決了**
  很多 agent 以為非問人不可的問題，其實放著別寄出去，過兩小時 agent 自己換條路走就繞過去了；管人的 kernel 可以故意替所有非不可逆的問題設一段「冷靜扣留期」，活過這段時間還沒消失的問題才配消耗人的注意力。

* **#6 把「問問題的額度」跟「以前寫得好不好懂」綁在一起**
  如果某隻 agent 寄出去的信老是被人類留 `?`（看不懂跳過）或退件，管人的 kernel 就直接砍掉這隻 agent 的「人類注意力配額」，逼它先去找別的 agent 幫它把話翻譯成大白話，才准再次排隊見人。

* **#7 人類在回信備註裡隨手抱怨的一句話，比選 A 或 B 值錢十倍**
  人懶得逐題點選、卻願意打字寫一句「這種檢查是阻礙開發的」，那是人類這個計算單元吐出的高純度「原則」；kernel 應該把這種抱怨截下來當成門口的擋箭牌，以後類似問題直接在門口拿這句話砸回去，不用再吵醒人。

* **#8【反直覺】把「中斷通知」反過來，變成人的「無聊抽卡池」**
  人很懶又討厭被打斷（連桌面通知都關掉），所以與其讓 agent 主動寄信催人，不如讓管人的 kernel 準備幾個按耗腦程度分類的牌堆（「三秒無腦二選一」「純看畫面試玩」「燒腦大方向」），人打遊戲讀取畫面無聊時自己抽一張來玩。

* **#9 投機執行（代定先行）就是把人類當成「事後對答案的慢速驗證器」**
  既然人類這個計算單元延遲高達幾小時，所有非不可逆的決定都該像 CPU 猜分支一樣先照推薦直接往下跑；人回信只負責「抓錯」，猜對了就零等待，猜錯了（人選了 `*`）才退回分叉點重跑。

* **#10 根據人類當下的「疲勞度／清醒度」動態粗化問題**
  當人類在外面用手機或邊打遊戲邊回時，kernel 自動把五題細節題壓縮粗化成一題大方向（「這整塊你放手嗎？」）；只有看人連答好幾題還附長備註（代表精神正好），才放行需要細看的題目。

* **#11 養一隻「影子臭宅分身」在門口先替真人踩雷**
  在管人的 kernel 前面放一個專門模仿使用者口味的小代理，拿過去答過的題目與備註當基準，先幫真人預判「這題真人八成會嫌太囉嗦」或「這題他一定選推薦」，只有分身自己也拿不準的題目才真正穿透給真人。

* **#12 定期抽檢資料夾的「人類一眼看懂度」，防止系統自己長成天書**
  就算 agent 之間跑得再順，只要整個資料夾長得讓人類點開三秒內看不出在幹嘛，那塊就等於脫離掌控了；kernel 可以偶爾在人有空時抽一個新長出來的資料夾丟給人看一眼，人皺眉或跳過，就派 agent 去幫那個資料夾減肥改名。

### 2. 其餘點子：粗化細化、`_metainfo` 公開與私有、稀疏激活、未曾想過的軟體（#13 ～ #22）

* **#13 平常只看 `_index` 的粗字，撞牆了才翻 `_metainfo` 細看（「原本以為是那樣，發現不是那樣」的動態對焦）**
  Agent 平常調用工具或看資源時，預設只讀最粗的一句話或一個總分（省腦力、省上下文）；只有當結果不如預期、報錯或花費暴衝時（「發現不是那樣」），才去翻 `_metainfo` 和下層 `_index` 把細節展開來抓蟲。

* **#14 跑熟了就自動「粗化封箱」，把一串囉嗦的 `_metainfo` 壓扁收進上一層 `_index`**
  反過來，當某個資料夾底下的細節連續跑了好幾十次都沒出過意外，就代表沒必要再盯著細項看了；它的複雜資源描述可以自動被粗化成上一層 `_index` 裡冷冰冰的一句話，直到哪天又出事才重新拆箱。

* **#15 `_metainfo` 是店家自己貼的廣告傳單，信不信由每個顧客（Agent / Kernel）自己算**
  工具在 `_metainfo` 裡宣告「我很省 token、傲嬌度 0.8」只是公開喊價；窮鬼 kernel 只抓裡面的 token 欄乘以十倍看，趕時間的 agent 只看速度欄，而在這工具上跌倒過的 agent 則在自己家裡（stack）記一筆「這傢伙吹牛，少用」。

* **#16 資源 JSON 亂長也沒關係，因為每個讀的人都自帶一副「偏光鏡」**
  不用規定全系統統一的資源格式，誰愛往 `_metainfo` 塞什麼新屬性都可以；每個 kernel 或 agent 讀的時候只挑自己認得的那幾個字，或者用幾行小轉換把一坨看不懂的複雜 JSON 壓成自己只在乎的一個數字（「對我有多麻煩」）。

* **#17 一萬隻睡在硬碟裡的 Agent，就是一顆平時不耗電的稀疏大腦**
  把一萬個小專長（比如專管某角色口癖、專管某種檔案格式）做成一萬個靜態資料夾躺著，平時完全不吃資源；只有當一封信順著 `_index` 一路敲門找過去時，才瞬間點亮路上那三五隻 agent 起來辦事，辦完立刻原地睡死。

* **#18 常一起被叫醒的兩隻 Agent，會在彼此的 `_index` 裡踩出一條「捷徑」**
  就像大腦裡常一起放電的神經元會連在一起，當兩隻原本隔很遠的 agent 老是在同一個任務裡前後腳被叫醒，它們可以直接在對方的 `_index` 留個直通門牌，下次不用再繞大圈問路，甚至中間直接長出一段固定腳本代勞。

* **#19【以前沒想過的軟體】像珊瑚礁一樣「邊活著邊鈣化」的軟體胚胎**
  以前寫軟體是人先想好全部邏輯再寫死；在 aos 裡，新軟體剛出生時是一團全靠 LLM 硬撐的糊塗蟲（什麼都能接，但貴又不穩），隨著每天被用，常走的路徑一點一點自然硬化成零 token 的死板程式，最後只剩沒見過的怪事才會驚動裡面的 AI。

* **#20【以前沒想過的軟體】把「人類心智負擔／命名污染」當成記憶體配額來管的自潔專案**
  傳統作業系統只在硬碟滿了才報錯，aos 卻能把「變數取名會不會撞車」「資料夾是不是嵌太深讓人眼花」當成資源上限；當一個模組的「難懂度」超標，kernel 直接拒絕寫入新功能，逼著裡面的 agent 先把舊東西整理乾淨才准動工。

* **#21【以前沒想過的軟體】以「人設崩壞度」與「情緒張力」當排程資源的活體劇本／Galgame 引擎**
  在寫故事或遊戲對話時，把「傲嬌濃度」「世界觀衝突風險」「讀者審美疲勞」當成系統資源來調度；日常背景描寫直接退化成查固定表，只有當「戲劇張力」資源見底或角色快要講出不符合人設的話時，才激活專門的守門與潤色 agent 救場。

* **#22 資料夾結構本身就是攤開在陽光下的 Lisp 語法樹**
  不用急著把整個系統改寫成 Lisp，因為「資料夾包資料夾＋`_entry`＋JSON」本來就是一棵活的語法樹；等以後哪天想用 Lisp 或 Lua，也不過是把某幾個嫌檔案太多太慢的子資料夾「壓縮打包」成一個腳本檔，外面看起來還是一模一樣的資料夾。

### 3. 極小、可丟棄、用現有東西就能玩的小實驗（4 個）

> 全都用現有的檔案、歷史紀錄或現成工具隨手試，看完感覺就能丟，不設任何硬門檻。

1. **拿現有的待裁歷史（`decide_20261113_*.json` 與 `.reply.txt`）玩「盲猜人類會不會跳過」**
   * **怎麼玩**：把 11-13 那幾批已經答完的題目（含那批 128 題只答 19 題、以及有留 `?` 與 `*` 的題）餵給一隻臨時小 agent，先遮住使用者的真實回覆，只讓它看題目的字數、`eli5` 寫法、選項長相，叫它猜「哪幾題人類會懶得看（`?`）、哪幾題會照推薦、哪幾題會反對（`*`）」。
   * **玩完看什麼**：對照真實回覆，看 AI 猜不猜得中人類「看到什麼長相的題目就會瞬間失去耐心」，順便看那些被跳過的題目是不是長得特別像。

2. **把同一批問題拆成「大雜燴」跟「同主題小包」丟進專區試水溫**
   * **怎麼玩**：下次手邊剛好有五六題想問使用者時，不用改程式，人工或讓傳話 agent 試兩種寄法：一次是東一題西一題湊一封信寄進 `aos-user`，另一次是只挑同一個話題的兩三題寄一封，看 `~/.aos/user/log.jsonl` 裡的 `seen` 到 `answered` 時間差與備註字數。
   * **玩完看什麼**：看同主題小包是不是真的讓人秒回、甚至多打兩句真心話，還是其實人根本沒感覺。

3. **故意寫一個「假裝很好懂、其實藏雷」的假工具，看 Agent 怎麼在 `_index` 與 `_metainfo` 之間切換**
   * **怎麼玩**：隨手建一個測試小工具資料夾，在上一層 `_index.json` 寫一句超單純的話（例如「把文字變漂亮」），但在工具裡面的 `_metainfo` 寫一句怪癖（例如「遇到英文會故意漏字」），讓一隻 agent 去用它完成小任務。
   * **玩完看什麼**：觀察 agent 是不是一開始只信 `_index` 直接呼叫，等發現印出來的東西怪怪的（「原本以為是那樣，發現不是那樣」），才會自己摸去讀 `_metainfo` 發現真相。

4. **用使用者寫過的幾句「原則式抱怨」當臨時守門員，攔截舊題目**
   * **怎麼玩**：把使用者在 11-13 留下的幾句真實備註（像是「check/lint 是阻礙開發的」「推薦都用 json，不遵守也沒差」）貼給一隻小 agent，再把過去問過他的幾十道題目重新排隊過這隻小 agent，問它：「光靠這幾句話，哪些題目根本不用去煩本人就能直接擋掉或代答？」
   * **玩完看什麼**：看光憑寥寥幾句人類隨手寫的備註，能替人類省下多少比例的無聊追問，以及會不會誤傷真正該問的大事。

### 4. 點子之間的「彼此矛盾」與「互相成就」

#### ⚡ 彼此矛盾（有趣的張力，不用現在二選一，看場合自然消長）

1. **「先斬後奏代定先行（#9）」 vs. 「扣著等湊成同主題一包再問（#3）與問題自然腐敗（#5）」**
   * 如果所有事情都照推薦「先斬後奏」直接往下跑了（#9），那問題在跑的當下就已經發生作用，根本沒辦法扣在手裡慢慢等湊成一包（#3）或等它自己消失（#5）；反過來，如果要扣著等湊批，還沒跑的線就得先忍住不動，或者要能承受事後翻盤重來的代價。
2. **「看人類偷懶照推薦就當成好懂（#1、#2）」 vs. 「定期抽檢防止系統長成天書（#12）」**
   * 人類一直按「全照推薦」或跳過不看，按 #1、#2 的邏輯系統會覺得「太棒了，這塊好懂又穩定，以後不用煩他」；但久而久之，這塊區域可能已經在底下悄悄長成沒人看得懂的怪物，跟 #12 想要維持人類隨時能看懂的目標正好拉扯。
3. **「影子分身幫真人擋題（#7、#11）」 vs. 「真人偶爾跳出框架的直覺（外部計算單元的真正價值）」**
   * 影子分身和舊原則（#7、#11）越盡責幫人類擋掉問題，人類就越輕鬆；但如果擋得太準太死，系統就只會順著人類「過去的習慣」走，反而少掉了人類看到怪問題時突然靈光一閃、推翻舊想法（像今早突然推翻太早規劃那樣）的驚喜。
4. **「跑熟了就粗化封箱不看細節（#14）」 vs. 「資源 JSON 自由亂長、各自解讀（#15、#16）」**
   * 粗化封箱（#14）希望把底層細節藏起來變成單一指標，省大家的腦力；但各 agent 私有看法（#15、#16）又希望保留奇奇怪怪的原始細節，好讓不同口味的 kernel 挑自己要的欄位看——壓得太扁，挑剔的 kernel 就沒材料看了。

#### 🤝 互相成就（湊在一起會自己轉起來的飛輪）

1. **「行為副作用測好懂度（#1）」＋「問題難度配額（#6）」＋「難懂度當資源上限（#20）」**
   * 不用人動手打分，光靠人在專區裡跳過或秒回的痕跡（#1），就能算出哪隻 agent 講話最難懂；難懂的 agent 被扣減問人額度（#6），同時它寫出來的資料夾也因為難懂度超標被限制擴張（#20），自然逼著全系統往「對人類好懂」的方向演化。
2. **「平時看 `_index`、撞牆才翻 `_metainfo`（#13）」＋「千萬 Agent 稀疏激活（#17）」＋「常一起醒就踩出捷徑（#18）」**
   * 一萬隻 agent 之所以不會把上下文塞爆，正是因為平常大家只看最粗的 `_index` 一句話來找路（#13），只叫醒極少數相關的 agent（#17）；而常走通的路又在 `_index` 裡留下捷徑、甚至粗化封箱（#14、#18），讓整顆大腦越用越快、越用越省 token。
3. **「人類抱怨變原則（#7）」＋「珊瑚礁式自我鈣化（#19）」**
   * 人類每次因為嫌煩而丟下一句大原則（#7），再加上各路 agent 常走的 `_index` 捷徑（#18），這兩股力量合在一起，就是讓原本靠 LLM 瞎摸的模糊地帶，一塊一塊鈣化成固定規則與純程式碼（#19）的催化劑。
4. **「探針測人醒著沒（#4）」＋「按疲勞度動態粗化（#10）」＋「無聊抽卡池（#8）」**
   * 人類不管什麼時候打開抽卡池（#8）或回了一題探針（#4），kernel 就能立刻從他回這一下的速度和字數，判斷他現在是「剛睡醒想動腦」還是「邊打遊戲邊敷衍」，當場決定下一張牌要遞給他粗的還是細的（#10）。
