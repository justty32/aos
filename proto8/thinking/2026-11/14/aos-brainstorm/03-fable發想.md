# fable 發想（11-14，頭腦風暴，不是規劃）：人這顆計算單元最稀缺的不是時間而是「願意看」，所以管人的 kernel 的成績是「人少答了多少題、事情還是對的」；另附六軸點子與十個玩完就丟的小實驗

← [README](README.md)｜備料 [02](02-給fable的備料.md)｜原話 [00](00-原話.md)

這份只有點子和小實驗。沒有計劃、沒有階段、沒有要你裁的題。點子之間很多互相打架，我故意不收斂，打架的地方在最後一節列出來。記號：「↔ 人3」＝跟人3 矛盾；「＋人3」＝跟人3 互相成就。

一個先講的事實限制：專區 `~/.aos/user/` 目前只有三封測試信，**沒有任何真人回信的時間資料**。下面凡是講「人回得多慢、哪時段快」的點子，現在都沒有東西可以對；手上唯一的真人痕跡是 11-13 那四批待裁頁的回覆檔（7、24、17、43 題）和「128 題只答了 19 題」這件事。

## 一、人是外部計算單元（重點）

### A. 這顆計算單元長什麼樣

- **人1　人就是一個端點包。** agent 問腦是寄信給 llm kernel，問人是寄信給「人 kernel」，形狀一樣，只是慢了五個數量級。llm 包上標的 `speed`／`cost`／`context`／`slots`，人也都有：很慢、很貴、一次裝不了幾題、同時只有一格。
- **人2　人的指令集其實已經存在，而且很小。** 待裁頁的 `*`（不照推薦）、`?`（沒看）、`U`（先不選）、備註、再加一句「都按照推薦」，這五個就是這顆 cpu 目前的全部 opcode。可以想的是：還缺哪幾個鍵？例如「看不懂」「這題不該問」「這類以後都你決定」。
- **人3　人有模式，像換包。** 打遊戲時（只按得了一個鍵）、專心時（能答長題）、在外面用手機時（只看 ELI5、不准問）。`door.json` 的 `normal`／`away` 是最粗的版本。＋人12
- **人4　人的 context 也會滿、也會被清掉。** 睡一覺，昨天那批題的背景就沒了。所以每題要自帶「你上次說過…」的原話（待裁頁的 `quotes` 已經在做），不能指望他還記得。
- **人5　人有快取命中。** 他剛聊完某個主題的那幾分鐘，問那個主題的題最便宜；隔天再問同一題，等於冷啟動。＋人22
- **人6　人有背景線程。** 「邊打遊戲邊想」就是。題丟給他之後，答案可能幾天後變成一篇深夜長文冒出來，而且不對應任何題號（20261113.md 就是這樣來的）。↔ 人20（到期就撤回）
- **人7　人有兩種時間：反應時間和思考時間。** 點一下屬於前者，可以被排隊、被批次；想方向屬於後者，不能催也不該打擾。把兩種混在同一頁上，前者會被後者拖死。
- **人8　人是唯一會否定題目本身的計算單元。** 今早那句「你們太早就開始規劃了」一次回掉十六題，而且沒有一題是照選項回的。這種「題目問錯了」的回答比任何選項值錢，格式上要留得住它。
- **人9　人算的不是「選 A 還是 B」，而是「感覺」。** 20261106 講過主觀屬性的基準就是人的主觀認知（傲嬌 0.4）。很多 A／B 其實 AI 自己判得了；只有「怪怪的」「不爽」「這樣可以」是只有人算得出來的值。值可以是一個字串，不必逼成數字。↔ 人30
- **人10　人的輸出常是原則，不是點。** 「推薦都用 json…不遵守也沒差」這一句能答掉一整類題。＋人27、人28
- **人11　人同時是被管的資源，也是定目標的主人。** 這在別的資源上不會發生。管人的 kernel 在優化「人的注意力」，但「什麼對人重要」只有人能說，所以人隨口一句要能蓋掉 kernel 的所有排序。

### B. 人 kernel 可以是什麼樣子

- **人12　人 kernel 的成績是讓人更懶。** 不看「人答了幾題」，看「人少答了幾題、事情還是對的」。最好的狀態是信箱空的。↔ 人13
- **人13　反過來：人 kernel 讓答題變爽。** 一次一題、一個鍵、答完馬上看到「這一答消掉了十二題，以後這類不問你了」。懶人最愛看題目變少。↔ 人12（一個減少題，一個讓題好玩）
- **人14　借 llm kernel 的整套：格子、優先、額度、保留格。** 每隻 agent 每天能佔人幾題，用完就回一個像 `BudgetMissing` 的拒絕，agent 自己想辦法。這會讓 agent 開始珍惜問題。
- **人15　題目競標。** agent 拿自己的額度出價，價碼是「這題不答我會卡多久」或「代定錯了重做多貴」。人只看到得標的。↔ 人11（出價是 agent 說的，重不重要是人說的）
- **人16　等越久越重要（借 llm kernel 的「等久自動升級」）。** 不會有題餓死。↔ 人17
- **人17　等越久越不重要，會自己爛掉。** 一題擺了三天事情都沒壞，答案多半就是「不用問」。使用者自己 09-01 說過：沒回應的邊緣狀況就是「天然差異或實作時自然解決」。↔ 人16
- **人18　人前面可以串好幾站，便宜的先擋。** 規則站（以前答過同類的直接回）→ 原則站（拿他講過的原則推）→ 替身站（一隻模仿他看法的 agent 先答，標明是替身答的）→ 真人。這就是現成的「kernel 可以串站」。＋人10
- **人19　替身的答對率就是「人的可預測性」。** 人對系統越可預測，就越少被問。有點像把「打擾」這件事沉澱掉。↔ 人8（替身只會照舊題的樣子答，不會說「題目問錯了」）
- **人20　題目有保存期限，過期自己撤回。** `deadline` 現在只用來催；它也可以表示「過了這時間這題就沒意義了」。撤回是對人的禮貌。↔ 人6
- **人21　不推、只等他來拉。** kernel 站只在 clock 週期跑；人的 clock 就是「他打開頁面」或「他開口說話」的那一刻，不規則。那一刻才算一格開著。
- **人22　搭便車。** 人主動開口的那一刻，他腦裡正熱著某個主題，把攢著的同主題的題掛在回覆尾巴最便宜。↔ 人23
- **人23　搭便車的反面：每次回覆都拖一串題很煩。** 人來講一件事，結果被塞三件別的事。
- **人24　kernel 管的是債的總量，不是題的流量。** 人不在時的「代定清單」是欠他的注意力債。128 題那次就是破產。破產時排隊沒有用，要丟：自動把最不要緊的那幾十題改成「已代定、不再問、出事再說」。
- **人25　人 kernel 的主要工作可能不是排題，是把事情變得能改回來。** 越容易改回來的事越不該問。問題數量降不下來的時候，回頭看是不是可逆性沒做好。
- **人26　人 kernel 自己不能變成人的負擔。** 管人的東西又要人設定，就違反了懶。它的設定只能從痕跡長出來，人只在不爽時說一句。
- **人27　最值得問的題是「能生出原則的題」。** 一題的價值＝它答完能消掉幾題別的題。從一百題裡挑一題代表題去問，比照順序問划算。
- **人28　收集的是原則，不是答案。** 人答一題，kernel 記的是「他為什麼這樣答」，然後拿去答剩下的，並標明「這是照你那句話推的」。
- **人29　最小的人 kernel 可能只是一張排好的清單，加一句「今天只要看前三個」。**

### C. 題目怎麼最好答

- **人30　把題降階。** 開放題 → 多選 → 二選一 → 是非 → 「我打算這樣做，不行才回」。最後一種人什麼都不用做就完成了，`default_if_silent` 已經是這個形狀。↔ 人9（感覺沒辦法降成是非）
- **人31　做完給他看，比做前問他好答。** 一個做好的東西是最好答的題（專區的 `trial` 信）。他對成品的反應是很便宜的取樣。使用者本來就偏好「做原型讓他試」。
- **人32　只報差異。** 照他預期進行的事一律不報，只給他看「跟你想的不一樣的地方」。這樣可預測性和好不好懂碰在一起：系統越照他預期走，他要讀的越少。
- **人33　新名詞是最貴的東西。** 每題的讀取成本可以粗估：幾個字、要點開幾個連結、幾個他沒見過的詞。使用者「理論強、術語弱」，所以第三項最貴。
- **人34　每個人有一張「已經認得的詞」表。** 這張表是對這個人的私有看法之一。題目用到表外的詞，就先換掉或附一句。＋看9
- **人35　位置是稀缺資源。** 128 題答 19 題，被答的大半是另外挑出來放在精選頁的那 17 題。排在前面、被挑出來，本身就是在分配注意力。
- **人36　「都按照推薦」是人的批次指令。** 可以把題排成讓這句話安全：會被它掃到的題，推薦錯了都改得回來；改不回來的另外放一疊，那句話掃不到。
- **人37　「看過」是一種很輕的簽核。** 「喔喔，我都看過了，應該算就按照推薦」把七題從沒看翻成照推薦。看過而不反對＝同意。危險是把「滑過去」誤算成「看過」。
- **人38　每個裁定帶一格「怎麼來的」。** 人親手選的、被批次那句掃到的、沉默照預設的、替身代答的、從原則推的。以後要翻案，先翻來源最弱的。
- **人39　一個「看不懂」鍵，不必說哪裡不懂。** 按下去這題就退回寄件人重寫（退信機制已有），同時留下一筆「不好懂」的樣本。這可能是最便宜的好不好懂量具。＋人44

### D. 沉默、懶、慢

- **人40　沉默至少有五種意思。** 沒看到、看了懶得回、看了覺得都行、看了看不懂、看了不同意但懶得講。再加今早出現的第六種：「現在沒需求，我也沒頭緒」。`seen` 時戳、有沒有點開，能分出前面幾種。
- **人41　沉默的答案可以由寄件人事先寫好。** 每題帶一句「你不回我就當成 ___」。人懶，預設值就是他的回答。
- **人42　人慢，所以代定就是分支預測。** 猜他會照推薦、先跑、猜錯再退。回覆裡的 `*` 就是預測失誤（但 01a 註明沒推薦的題也會帶 `*`，不能直接當失誤率）。不同題型失誤的多寡看起來差很多，猜不準的題型不該先跑。
- **人43　人重複講同一件事是系統的錯誤計數器。** 每次他說「我先前應該說過」，就是一次快取沒命中。把這句話當訊號記下來。user-advice 資料夾就是為了讓他只講一次。
- **人44　「退回來要重講」是最貴的失誤。** 一次退回等於整份白寫。它也是好不好懂最硬的訊號。＋人39
- **人45　人的回答常常是回給氛圍，不是回給題號。** 需要有人做對帳：「這段話回掉了哪幾題舊題」。今早的原話對到上一輪 D14、D15 就是手工對出來的。
- **人46　人的反感是硬門。** 「這種 check 啦，lint 啦…是阻礙開發的」這種話比任何分數都強。門規可以從他的反感長出來。

### E. 「好不好懂」這個值怎麼從人身上取

- **人47　不要問「幾分」，看行為。** 回覆花多久、有沒有退回重講、有沒有點開摺疊、備註是不是在問「這是啥」、沒看的比例。128 題答 19 題本身就是一筆量測值，量的是「好不好答」。
- **人48　一筆分數是一次世界線取樣。** 同一份文、同一個人，早上和深夜讀出來不一樣；今天懂、下週忘。所以分數要帶「什麼時候、什麼狀態下取的」，而且合理的值是一把散開的樣本，不是一個數。
- **人49　好不好懂一定有「對誰」。** 對使用者好懂、對 opus 好懂、對小模型好懂是三個不同的值。AI 讀者可以便宜大量取樣（讀完複述、再比對），人是貴的校準點。↔ 人50
- **人50　AI 覺得好懂跟人覺得好懂可能根本不相關。** 人卡在術語和密度，AI 不卡這些。拿 AI 當代理量具可能量到完全不同的東西。↔ 人49
- **人51　複述測驗。** 好懂＝讀的人能用自己的話講回來而且沒講錯。叫人複述太累，改成給他看「agent 猜你會怎麼講」，他只按對或不對。
- **人52　事後看：他讀完下的裁定後來有沒有翻案。** 翻得多，表示當時沒懂。這個量很慢，但不用額外問他。
- **人53　很多東西人根本不必懂。** 使用者原話「複雜到人類難以處理，反正是 ai 看」。好不好懂是資源，花在刀口上就好，不是越高越好。先分「人要懂的」和「人不必懂的」，後者隨便。↔ 人32（只報差異的前提是他懂基線）
- **人54　理解是會被花掉的。** 一份新概念很多的文件花掉他很多；同一天第二份就讀不動了。這是使用者說的「一次只能處理一些事」的另一個面。

### F. 人的 `_metainfo`、人是不是 proc、很多個人

- **人55　`user.md` 就是人的 `_metainfo`，只是寫成散文。** 「讀不動高密度」「要白話」「出門時不准問」都是宣告。
- **人56　人的 `_metainfo` 誰寫？人懶得寫，所以從回覆痕跡長出來。** 人只在看到寫錯時說一句「不是這樣」。這正好是那句「原本以為是那樣，發現不是」用在人身上。＋粗3
- **人57　daemon 的表裡有一列是人。** 名字 user，phase 是睡、玩、忙、在，reason 一句話。agent 看表就知道現在能不能問。
- **人58　人不是被管的 proc，人是最頂的那個 kernel。** `kernel_gate` 的留著等表態、放行、拒絕，對人和對 agent 是同一個形狀。「管人的 kernel」和「人自己當 kernel」是兩回事，可以串起來：agent → 人前面那站 → 人。↔ 人57
- **人59　對子節點來說，父節點就是它的人。** 使用者自己寫過這句。所以上面每一條都能先在 agent 問上級這件事上便宜地玩，玩出感覺再搬到真人。＋E5
- **人60　很多個人時，問誰是一個路由題。** 每人一區、一份宣告、專長不同。兩個人意見不同就是兩份私有看法，不必合成一個答案。＋稀7
- **人61　agent 們對使用者各有一份私有看法，而且彼此不一樣。** 人可以偷看「你們各自覺得我是怎樣的人」，哪份講錯了就糾正那一份。有用，也有趣。＋看9、E6
- **人62　人也是一顆神經元，門檻最高、亮得最稀疏。** ＋稀1

## 二、任意資源 OS 能長出什麼以前沒想過的軟體

- **軟1　先能用、後變便宜的軟體。** 一開始整個是 agent 硬做的，用多了自己變成程式。開發順序跟一般軟體相反。
- **軟2　小說的資源表。** 讀者的注意力、伏筆債（埋了還沒收）、角色出場額度、某種味道的預算（傲嬌）。排程問題變成「下一段該還哪一筆伏筆」。
- **軟3　遊戲裡玩家的無聊是資源。** 上千個 NPC 平常是睡著的資料夾，只有玩家附近的醒。＋稀4
- **軟4　一個人的一天是一台 daemon。** 待辦是 proc，精力和心情是資源，「今天精力只有三格」就只放行三件。這跟人 kernel 是同一個東西反過來用。＋人14
- **軟5　學習軟體：系統反過來訓練人。** 知識點是資料夾，「懂了沒」是每個節點的主觀屬性，什麼時候複習是 kernel 的一種政策。
- **軟6　名字是資源。** `a=1+2` 的 `a` 佔了一個名字。一個專案的自創名詞有容量，新造一個就得退一個，否則人記不住。＋人33
- **軟7　程式碼庫的戰爭迷霧。** 每個檔記著「上次有人真的看懂它是什麼時候」，太久沒人懂的區域蓋上霧。「人看得懂的面積」是一個可以管的量。
- **軟8　承諾是資源。** 說出去的話、答應別人的事都是要還的債，一個人的公司最缺的可能是這個。
- **軟9　世界線瀏覽器。** 同一個任務放開跑幾次，把分岔攤開給人挑喜歡的那一條。寫作和設計很適合。＋人48
- **軟10　會自己對不同讀者講不同粗細的軟體。** 同一個資料夾，對人吐一句話，對 AI 吐全部。＋粗8
- **軟11　替 AI 做的工學軟體。** `_metainfo` 裡已有 `comfort`（AI 用起來舒不舒服）。以前沒人為「工具給 AI 用舒不舒服」做過軟體。
- **軟12　討論當成 OS。** 發言權是資源，議題是 proc，離題是記憶體洩漏。

## 三、千萬 agent 像 LLM 的稀疏激活

- **稀1　門檻。** 神經元有激活門檻；agent 的門檻是「這件事夠不夠格叫醒我」。人的門檻最高。
- **稀2　路由就是 index 那一句話。** `index_view` 一行一項，寫得好的那句讓對的 agent 被找到。那句話是 agent 的「接受域」。＋粗1
- **稀3　權重是什麼？** 候選：誰常寄信給誰、index 那句話怎麼寫、kernel 給誰優先、各 agent 對彼此的私有看法。「訓練」就是這些被改掉。＋看4
- **稀4　睡著的 agent 應該只是一個資料夾。** 這是意象。實況是每隻閒著的 agent 也在輪詢（01b 第 7 節）。意象和實況的落差本身值得看。
- **稀5　殘差。** 子 agent 不重寫整份，只回「跟上面想的差在哪」。workspace 像殘差流：大家往同一塊加增量。
- **稀6　MoE。** kernel 是路由器、agent 是專家。可以一次叫 k 隻取最好的；也有「別讓某一隻被叫爆」這個平衡問題。
- **稀7　反向傳播＝責任往下分。** 使用者三點五回合寫的「主節點把責任交給應該負責的節點」就是。難的地方跟神經網路一樣：到底該怪誰。
- **稀8　死神經元。** 從來沒被叫過的 agent、從來沒被讀過的 index 項。看得見就能剪。
- **稀9　關掉幾隻看看。** 隨機讓幾隻 agent 不回應，看整體還行不行。
- **稀10　激活圖。** 把一件任務期間哪些 agent 亮過畫出來。人看這張圖就大概懂系統在幹嘛，這也是一種好不好懂。＋人32
- **稀11　稀疏的原因不同。** LLM 的稀疏是學出來的；aos 的稀疏是端點只有十幾格逼出來的。被逼出來的稀疏也可能逼出好分工。
- **稀12　蒸餾＝沉澱。** 大 agent 的行為教給小函數。
- **稀13　這個類比會誤導的地方。** 神經元彼此長得一樣、沒有名字、同步一起算、睡著不花錢；agent 各不相同、有名字、非同步、會回信（不是單向一層層往前）。「層」這個詞最不能照搬，aos 是會繞回來的圖。

## 四、粗化細化 ↔ `_metainfo`／`_index`

- **粗1　四層：名字 → `_index` 一句話 → `_metainfo` → 本體。** 名字是最粗的粗化，命名就是在做粗化。
- **粗2　往下鑽的觸發是「驚訝」。** 照那一句話去用，結果不對，才看 `_metainfo`；還不對，才看本體。沒驚訝就不鑽。
- **粗3　鑽下去的人最有資格改上面那句。** 但 index 是視角不是事實，所以他改的是自己疊上去的那份。很多人都疊了同樣的修正時，公家那句才該換。＋看1
- **粗4　每句話有「被騙次數」。** 用了幾次、其中幾次讓人發現不是那樣。這是那句話的準度，也是一種資源帳。
- **粗5　比本體更細的是它跑過的軌跡。** 本體說「應該」，軌跡說「實際」。「原本是那樣，發現不是那樣」的「發現」多半來自軌跡，不是來自再讀一次本體。
- **粗6　`cost:7` 的鑽法和文字的鑽法是同一個動作。** 7 不對 → 看 `{token,time}` → 不對 → 看 `{in,out}` → 不對 → 看實測。值的粗細和描述的粗細是同一件事的兩個面。
- **粗7　粗的那句可以自己說它省略了什麼類的東西。** 例如「這句沒講副作用」。讀的人就知道什麼時候該鑽。
- **粗8　不同讀者停在不同層。** 人停在一句話，AI 讀到本體。一個人「需要鑽幾層才夠」可以當他的好不好懂。＋人47
- **粗9　kernel 也是懶讀的。** 排隊時只看粗的，碰到邊界才細讀。粗細是省力氣的手段。
- **粗10　兩個方向會打架。** `index_gen` 是從本體往上重生那一句；用的人是從使用經驗往上改那一句。重生會把人改的洗掉。↔ 粗3
- **粗11　小的東西不粗化。** 使用者原話「如果夠小…直接讀就是了」。粗化本身有成本。

## 五、公開宣告 vs 私有看法

- **看1　私有看法的機制已經在了。** 「`_metainfo` 裡的 < 獨立那份 < 讀者指定的」這條疊法，最上面那層「讀者指定的」就是私有看法。看法住在讀者自己的 stack 裡。
- **看2　宣告是廣告，看法是評論。** 寫宣告的人有動機寫得好看。
- **看3　宣告和看法的差，就是這個函數誠不誠實，或宣告過期了沒。**
- **看4　別人對你的看法加起來是你的信譽。** 自稱花 100、大家私下都記 300，以後大家排它就排後面。看法因此是一種資源。
- **看5　看法會傳染。** A 把看法寫在信的 `why` 裡，B 讀了就染上。像 eca_main 這種轉信的中心是超級傳播者。↔ 看6
- **看6　沒有誰的看法贏。** kernel 的看法只在它那一站有效。兩個 kernel 對同一個資源一個擋、一個只記，這是特色。統一了就殺掉使用者說的那份自由。
- **看7　新 agent 天真、老 agent 世故。** 沒有看法時照宣告，有了自己的經驗就蓋掉。一隻 agent 的「經驗」可能就是它攢下的看法。
- **看8　看法能不能遺傳？** 子 agent 繼承父 agent 的看法就省得重學，但偏見也一起繼承。
- **看9　對人的看法也是看法。** 「他認得哪些詞」「他對這類題都照推薦」。人的宣告是 `user.md`，agent 們的看法各自不同。＋人34、人61
- **看10　看法也會過期，也要帶誰看的、替誰看的、什麼時候看的。**
- **看11　agent 之間的八卦頻道。** 「你覺得那個工具怎樣」。集體看法就是一套評價系統，不需要中央登記。↔ 看5（傳染太快就沒有獨立的看法了）

## 六、檔案系統／json／程式三處的佔比

- **佔1　其實是五處。** 還有 prompt 裡和人腦裡（沒寫下來的）。沉澱大致是人腦 → prompt → json → 程式這個方向，但也有逆流：程式太硬，退回 prompt。
- **佔2　誰要讀它，決定它住哪。** 人要 `ls` 就看到的住資料夾；AI 要一次讀完的住 json；沒人要讀、只要跑的住程式。
- **佔3　溫度。** 常改的留 json（AI 改 json 最穩），定型的進程式。N-68 的 `cal`→`lua`→`py`→`aos` 是目前唯一寫下來的搬家路線。
- **佔4　搬家夠便宜，就不必事先選對。** 資料夾和 json 同像，搬來搬去若是一個動作，「放哪裡」就不用規則。
- **佔5　三種痛各自把東西往別處推。** 資料夾太多 `ls` 看不完、json 太大讀到 `[too big]`、程式沒人敢改。現在的門檻（幾項以上才放 index）就是痛的早期形式。
- **佔6　讓它自己漂的前提只有「看得見」。** 每樣東西被讀幾次、被改幾次、被跑幾次，比例會自己說它該住哪。
- **佔7　同一樣東西可以同時住三處，粗細不同。** 資料夾是骨架、json 是參數、程式是肉。

## 七、lisp／lua（遠期，只留幾條）

- **L1** 一段 lua table 展開成資料夾，當「人用寫程式的方式規劃 aos」的入口；本機有 fennel，所以 lisp 語法 → lua → table → 資料夾是一條現成的鏈。
- **L2** 反過來：把活著的資料夾樹印成一段 lua／lisp 給人讀，當作一種粗化視圖。
- **L3** 對照表：quote＝`_entry` 指定哪些算元素、eval＝aos-exec、image＝資料夾停住。
- **L4** 最小的落腳處是 N-68 公式格的 `lua` key，其他等 kernel 穩。

## 小實驗（玩完整個丟）

全部唯讀 repo 與知識庫，產物只放丟棄用的暫存夾；不寄信給使用者、不動 `~/aos-home`、不改程式。沒有通過條件，只寫玩完看什麼。

- **E1　把四批回覆當成人的執行紀錄來看。**
  怎麼玩：用 json 工具讀 `proto8/thinking/2026-11/13/decide_20261113_*.json` 和四個 `.reply.txt`，每題排成一列：在頁上的位置、題面與 `eli5` 字數、有沒有推薦、選項幾個、回覆記號、有沒有備註。大檔 128 題另標「有被挑進精選頁／沒有」。
  玩完看：被答的和沒答的、`*` 和備註集中的地方，肉眼看不看得出樣子（位置？長度？題型？）。
- **E2　原則回收。**
  怎麼玩：從四個回覆檔的備註和 user-advice 抽出像原則的句子，叫一隻 agent 只憑這些句子去答大檔裡沒被答的 109 題，每題標「推得出／推不出／推出來但跟推薦相反」。
  玩完看：一句原則能消掉幾題；推不出的那些題面長什麼樣。結果只留在暫存夾，不當裁定。
- **E3　替身猜答。**
  怎麼玩：一隻 agent 只讀 `wf/workflows/common/user.md` 和 user-advice，蓋住回覆，猜 wu-r2 那 43 題他會怎麼回，再跟真的回覆對。同一隻跑兩三次。
  玩完看：哪種題猜得中、哪種猜不中；替身自己幾次之間穩不穩（替身也是世界線取樣）。
- **E4　`eli5` 複述。**
  怎麼玩：挑十來題，只把 `eli5` 兩句給一隻小模型，叫它講「這題在問什麼、選了會怎樣」，再跟題目全文比。同樣的題換一個大模型再做一次。
  玩完看：`eli5` 失真是哪一種失真；兩種模型覺得好懂的是不是同一批題（好不好懂的「對誰」）。
- **E5　拿排法重放 11-13 那天。**
  怎麼玩：把那天四批題當作到達流，用本機 lua 寫幾十行，照幾種排法各排一次：先到先看、等久升級、等久爛掉、「答完能消最多題的先」（用 E2 的結果）。假設人每次只看排在最前面的幾題。
  玩完看：每種排法下，他實際答過的那些題排在哪；哪種排法會把他根本沒答的題頂到最前面。
- **E6　三份對人的看法。**
  怎麼玩：三隻不同模型的 agent 各自只讀 `user.md`，各寫一份「這位使用者當計算單元的 `_metainfo`」（json，欄位自己定）。同模型再跑一次。
  玩完看：三份的欄位名和值差在哪、哪些欄位每份都有（可能是真的宣告）、哪些只有一份有（私有看法）。
- **E7　index 那句話騙不騙人。**
  怎麼玩：對知識庫 `aos` 夾跑 `index_view`，一隻 agent 只看每項那一句，寫下「我猜這裡回答得了哪三個問題」；再 `json_get` 本體核對。
  玩完看：哪幾句「原本以為是那樣、發現不是」；被騙的時候它是去看哪裡才發現的。
- **E8　沉默分類。**
  怎麼玩：把 `wf/WAIT_USER.md` 的 open 條目加上大檔沒答的題，由 agent 逐條猜是哪一種沉默（沒看到／懶得回／都行／看不懂／不同意／現在沒需求），再對照今早原話「現在沒有需求…沒個頭緒」。
  玩完看：「現在沒需求」那類的題面有沒有共同的樣子，能不能在寄出前就認出來。
- **E9　json 和資料夾來回搬一次。**
  怎麼玩：挑知識庫裡一節小 json，用本機 lua 在暫存夾把它展成資料夾樹（物件變夾、純值變檔），再收回 json，比前後。再挑一節形狀彆扭的（陣列多、key 帶斜線）做一次。
  玩完看：哪種形狀搬起來順、哪種彆扭；展成資料夾後，人 `ls` 一眼看到的比 json 多還是少。
- **E10　git 歷史當人的時鐘。**
  怎麼玩：`git log` 取 user-advice、`user.md`、各回覆檔相關 commit 的時間，排在一天二十四小時上。大多數 commit 是 agent 代做的，只能當粗訊號。
  玩完看：人「開口」的時刻聚在哪；回覆檔的落地時間有沒有能用的；還是說這條路什麼都看不出來，要等專區有真人信。

## 彼此矛盾／互相成就

矛盾（我沒有偏向任何一邊）：

- **人12 ↔ 人13**：讓人更懶（題越少越好）對上讓答題更爽（題好玩就多答）。
- **人16 ↔ 人17**：等越久越重要對上等越久越該爛掉。同一封信兩種老化方向。
- **人6 ↔ 人20**：人的背景線程幾天後才冒答案，對上題目到期就撤回。
- **人19 ↔ 人8**：替身讓人少被問，但替身永遠不會說「題目問錯了」，而那是人最值錢的輸出。
- **人22 ↔ 人23**：趁他開口搭便車最便宜，對上每次開口都被塞題很煩。
- **人15 ↔ 人11**：agent 出價決定誰先問，對上「重不重要只有人能說」。
- **人30 ↔ 人9**：把題降成是非最好答，對上人真正獨有的輸出是降不了階的「感覺」。
- **人49 ↔ 人50**：拿 AI 當便宜的好懂量具，對上 AI 的好懂跟人的好懂可能不相關。
- **人32 ↔ 人53**：只報差異需要人先懂基線，對上很多東西人根本不必懂。
- **人57 ↔ 人58**：人是 daemon 表裡的一列，對上人是最頂的 kernel。
- **粗3 ↔ 粗10**：用的人往上改那句話，對上生成器從本體重生把它洗掉。
- **看5 ↔ 看6／看11**：看法會傳染（越傳越像），對上看法各不相同才有價值。
- **稀4 意象 ↔ 實況**：睡著的 agent 是一個不花錢的資料夾，對上現在每隻閒著也在輪詢。

互相成就：

- **人10＋人27＋人28＋人18**：人愛給原則 → 挑能生原則的題問 → 記原則 → 原則站替他擋掉後面的題。E2 是這一串的最小試玩。
- **人39＋人44＋人47**：「看不懂」鍵、退回重講、行為訊號，三個都是不用問「幾分」就拿到的好不好懂樣本。
- **人56＋粗3＋看1**：人的 `_metainfo` 從痕跡長出、人只說「不是這樣」；跟「被騙了才往上改那句話」和「讀者指定的那層就是私有看法」是同一個機制用在三個地方。
- **人59＋稀7**：父節點是子節點的人，所以人 kernel 的點子能先在 agent 之間玩；責任往下分也是同一條線。
- **人34＋軟6＋人33**：認得的詞表、名字是資源、新名詞最貴，三條講的是同一筆帳。
- **人48＋軟9**：分數是世界線取樣，世界線瀏覽器把取樣攤開給人挑。
- **人32＋稀10**：只報差異和激活圖都在讓人「不用讀也知道系統在幹嘛」。
- **粗6＋佔4**：值的粗細、描述的粗細、住處的搬遷，如果都是便宜的來回動作，就都不必事先定規則，符合「自然長出來」。
- **人42＋人25＋人36**：代定是分支預測、把事情變可逆、讓「都按照推薦」安全，三條都靠同一件事：猜錯了改得回來。
