## 1. 記什麼

### history 列

只加一個鍵 `aos`，值是物件。原始碼目前沒有任何 history 列用到 `aos` 這個鍵（11-14 grep 過）。mailbox 的 `in_reply_to` 不改，也不借用這個名字。

- **信的 user 列**：`"aos":{"letter":"<信名>"}`
  - 寫的人：fsm 的 `idle.take()`（`templates/agent-fsm/idle.py:166-167`）；eca 的 `Handoff.handed()` 和 `extra()`（`cmd/aos-eca/aos_eca/handoff.py:23-24、39`）。
  - 時機照舊：先附加 history，再 `done`。
  - 寫入時**覆蓋**信 body 原本的 `aos` 鍵，免得寄信的人偽造。eca 會保留 body 裡除了 `name` 以外的鍵。
- **最終回答列**：`"aos":{"answer_to":["<信名>",…]}`
  - 最終回答＝assistant、沒有 `tool_calls`。
  - 值是清單：一則回答可能同時回好幾封信。
  - 沒信可回時不加這個鍵。
  - fsm 附加端點回覆之前，先把回覆裡原本的 `aos` 拿掉，再寫我們的。

### `<stack>/letters.json`（新持久檔）

格式：`{"pending":[信名…],"dropped":[{"letter","reason","at"}…]}`

- 寫法：先寫暫存檔，再 `os.replace`。
- `dropped` 只留最近 50 筆。
- `reason` 只有三種：
  - `bad`：壞信
  - `blocked`：被 before_queue hook 擋掉
  - `failed`：交給 CLI 之後失敗

**誰改它、什麼時候改：**

| 時機 | fsm | eca |
|---|---|---|
| 收到好信 | `idle.take()`：附加 history 之後、`done` 之前，加進 `pending` | `handed()`、`extra()`：附加 history 之後、`done` 之前，加進 `pending` |
| 丟掉壞信或被擋的信 | `done` 之前記進 `dropped` | 同左（`turn.py:50`、`midturn.py`、`hook.py:24`） |
| 寫最終回答 | `wait.py`：`answer_to = pending` 後清空 | `turn.py:84`：`answer_to = pending`（等於 `hand.good`）後清空；slash 回答照樣處理，施工時核 `slash.py:275、287` 不跟 `turn.py:84` 重複 |
| 交出去之後失敗 | brain 失敗後會重試，`pending` 不動。下一則最終回答把它們一起算進去，這是有意的：模型看得到那些信 | `CliFailed`／`ReplyMissing`（`handoff.py:57-62`）：把 `hand.good` 從 `pending` 移到 `dropped`，`reason` 記 `failed` |

**為什麼要這個檔**（Argon A6、A7）：

- 從 history 現算會出錯：本輪的 user 列可能被 do_task 折疊、summarize 或 self_history 改掉；上一則最終回答被刪掉時，已經答過的信又會被算進來。
- `pending` 不管 history 怎麼改，都只會記到「還沒被最終回答蓋到」的信。
- 有 `dropped`，被丟的信可以立刻報錯，不用乾等到逾時，也不會像 `mailbox_warning.txt` 那樣只留最後一封。

## 2. 讀的一方

### `aos_ws.answer_for(stack, name)`

回傳 `(狀態, 文字或原因)`。**查的順序固定，照信件流動的方向，從上游往下游查**（Argon A1、A2）：

1. `queue/new/` → `queue/cur/`：在裡面就是 `waiting`。
2. `history.jsonl`：
   - 有最終回答的 `answer_to` 含它 → `answered`，取第一則。
   - 有 user 列的 `aos.letter` 是它 → 記一筆「已交出」，往下查。
3. `history_removed.jsonl`（路徑照 interfaces 宣告）：
   - 改寫 history 的兩條路，都是先寫這份、再換 history（`lib/agent/cli_hook.py:58、103`；`cmd/aos-agent/aos_agent/history.py:220-253`）。所以先讀 history、再讀這份，不會有空窗。
   - 有 `message.aos.answer_to` 含它 → `answered`，stderr 加一句「這則回答已移出 history」。
   - 有 `message.aos.letter` 是它 → 記一筆「已交出」。
4. `letters.json`：
   - `dropped` 裡有它 → `dropped`，帶它自己那筆的 reason。
   - `pending` 裡有它，或第 2、3 步記過「已交出」 → `handed`。
5. 以上都沒有 → `unknown`。呼叫的人照樣等，不馬上報錯；等到逾時就報 `AnswerMissing`。新讀舊寫的情況也落在這裡，見 §5。

### 各指令

- **`ask`**：
  - 發信前記下 `before_rows`（history 有幾列）、`before_answers`（有幾則回答）。
  - 用 `sender.put` 回傳的信名去輪詢 `answer_for`。
  - 結果是 `dropped` → 報 `LetterDropped`，帶原因，退 1。
  - 逾時 → 報 `AnswerMissing`，帶信名和最後看到的狀態。
  - `--help` 裡「不配對」那句限制刪掉。
- **`chat`**：每句話用自己的信名，做法同 `ask`。
- **`listen`**：
  - 新增 `--letter NAME`，`say` 本來就會印信名。
  - 不給信名時（Argon A13）：
    - queue 裡有信 → 等最新那封（`listen.py:32`）。
    - queue 空、`pending` 有信 → 等 `pending` 最後那封。
    - 都沒有 → 照現行：`handed_unanswered` 就等新回答，不然印最後一則回答。
  - `--last`／`--follow` 不動。
  - ok-kmsg 加的提示呼叫點保留在原位。
- **subagent 的 op ask**（`lib/agent/subagent/_entry:228`）：改成呼叫 `aos-agent ask`，原本 say 和 listen 之間的空窗就沒了。op listen 加選填參數 `letter`。
- **一則回答回好幾封信**：每個問的人都拿到同一則全文。
