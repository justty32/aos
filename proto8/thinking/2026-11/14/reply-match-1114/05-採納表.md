# 回答配對 05：Argon 意見採納表（審 03 v1）

← [reply-match-1114](../reply-match-1114.md)

依據：[04 Argon 原文](04-Argon原文.md)。標「已核」的，是 ok-pilot 11-14 回原始碼對過。結果已改進 [03 v2](03-計劃.md)。

| # | Argon 意見 | 判定 | 理由／改法 |
|---|---|---|---|
| A1 | 掃 queue 的順序沒規定，信在 `new→cur` 搬移時會誤判成「不在」 | **採** | 固定先掃 `new/`、再掃 `cur/`、再看 history。`take` 是 rename，信不是在 new 就是在 cur。寫的一方先附加 history 才 `done`，所以從上游往下游查不會漏 |
| A2-1 | removed 檔只找 `answer_to`，沒找 `letter`；本輪的 user 列被折疊後，會誤報被丟 | **採** | removed 檔裡 `aos.letter` 是它的，算 `handed`，繼續等 |
| A2-2 | 改寫 history 和寫 removed 檔交錯時，兩邊都讀不到 | **不採（已核）** | `cli_hook.replace_history`（`lib/agent/cli_hook.py:58、103`）和 `aos_agent/history.py`（`:220-253`）都是先寫 removed 檔，再 `os.replace` 換 history。只要固定先讀 history、再讀 removed 檔，就沒有空窗。03 v2 把讀的順序寫明 |
| A2-3 | self_history、do_task 折疊時會不會寫 removed 檔，沒核實 | **採（施工時核）** | self_history 走 `aos-agent history`（同上，會寫）。do_task 也是經 history `set`／`summarize` 搬（sol-8 §2）。施工時補一條測試確認 |
| A3 | `mailbox_warning.txt` 只留最後一封，直接附上去會張冠李戴 | **採** | 改由 `letters.json` 的 `dropped` 逐封記原因（見 A5～A7 那列），不再附 `mailbox_warning.txt` |
| A4 | eca 中途信的 `done` 順序沒核實 | **不採（已核）** | `midturn.More.take` 只把信從 new 認領到 cur（`midturn.py:33`）。交出去之後由 `Handoff.extra` 先 `append_history`、再 `done`（`handoff.py:39-41`）。順序跟開頭那批一樣 |
| A5 | fsm 上一輪在 tool 迴圈中途失敗、沒有最終回答，下一輪（含 goal 輪）會把上一輪的信 L1 也算進 `answer_to` | **部分採** | fsm 失敗後，L1 還留在對話裡，下一則最終回答的模型看得到它，算成「回 L1」是對的（同 `aos_ws.exchanges` 現行語意）。03 v2 寫明這是有意的。但「現算」確實有 A6、A7 的洞，所以改用 pending 檔，見下一列 |
| A6、A7 | fsm 現算 `answer_to` 時：本輪 user 列被 do_task 折疊或 summarize 掉，就會漏記；上一則最終回答被刪掉，已答過的信又會被算進新回答 | **採：改回 02 的 `letters.json`** | 03 v1 拿掉 pending 檔是錯的。改成 `<stack>/letters.json`：`{"pending":[信名…],"dropped":[{letter,reason,at}…最多 50 筆]}`。收信時加進 pending，寫最終回答時 `answer_to = pending` 再清空。history 怎麼改都不影響。這樣 A5 的語意也自然成立 |
| A8 | 剝鍵要回傳拷貝；端點回的 message 也可能自帶 `aos` 鍵 | **採** | `for_endpoint(m)` 回傳新 dict。`wait.py` 附加端點回覆前，先去掉回覆裡的 `aos` 鍵，再寫我們的 |
| A9 | 寬容退路用「整份 history 沒有 `aos.letter`」判斷：已升級的 agent 剛開機或剛 summarize 完，也會誤觸發 | **採** | 改用發信前的快照判斷，見 A11 那列 |
| A10 | 半新半舊的 agent（history 裡有過 `aos` 鍵，但現在跑的是舊身體）每封信都會報被丟 | **採** | 同上 |
| A11 | 拿掉 `before` 計數之後，退回舊邏輯會直接拿到發信前的舊回答 | **採** | ask 發信前記下 `before_rows`、`before_answers`。信離開 queue 之後，若 `history[before_rows:]` 有不帶 `aos` 的一般 user 列，就判定收這封信的是舊身體，改走舊的等法：`handed_unanswered` 為假，且回答數大於 `before_answers`。同時加上 A16 的落地順序 |
| A12 | eca 交出去之後 CLI 失敗，ask 要白等到逾時 | **採** | `handoff.py` 遇到 `CliFailed`／`ReplyMissing` 時，把 `hand.good` 從 pending 移進 dropped，`reason` 記 `failed`。ask 立刻報 `LetterDropped`，帶原因 |
| A13 | `listen` 不給信名、queue 又是空的時候，退路會拿到舊回答或卡在死信上 | **採（改寫規則）** | queue 有信：等最新那封。queue 空、pending 有：等 pending 最後一封。都沒有：照現行，`handed_unanswered` 就等，不然印最後一則回答 |
| A14 | slash 回答和 `turn.py:84` 的 `hand.good` 會不會重疊 | **採（施工時核）** | 施工時核 `slash.py:275、287` 走不走到 `turn.py:84`。原則：一封信只進一則回答的 `answer_to` |
| A15 | 測試和文件清單漏列 | **採** | 03 v2 §4 補齊：02 §4 的測試，加上 `附錄4` 那兩列、`P-11`、知識庫 `cli/history.json` |
| 創見 1 | 改 self_history、do_task 的鎖，保護還沒回答的信列 | **不採** | 這會改動別的工具的語意。pending 檔已經讓配對不怕 history 被改，不需要這個 |
| 創見 2 | 被丟的信、失敗的信寫進 `history_removed.jsonl` | **不採** | removed 檔的語意是「從 history 移出的列」，混進丟信紀錄會讓 `aos-agent history` 那邊難懂。改記在 `letters.json` 的 `dropped`，效果一樣 |
| 創見 3 | 用發信前快照判斷新讀舊寫 | **採** | 見 A11 那列 |
| 方向 5 | 讀寫同一個 commit，再加快照退路 | **採（改寫）** | 再加一條 A16：**寫的一方先落地，讀的一方等換樹確認後再進 main**。寫的一方多一個鍵，舊的讀者照樣能用（sol-8 §2）；讀的一方的 `cmd/`、`py/` 一進 main 就生效。快照退路留著，給沒跟著換樹的 agent 用 |
