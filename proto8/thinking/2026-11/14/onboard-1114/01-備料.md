# 01 備料：派 fsm agent 的配給包（system prompt、工具、功能、權限）要用的事實

← [onboard-1114](../onboard-1114.md)｜ok-onboard 匯總，給 fable 設計用。來源是 ok-onboard-sol-1～4 的盤點（原文在 `wf/temp/ok-onboard/sol-N/answer.md`）、ok-pilot／ok-skyrim／ok-astra／ok-misc 的實測，以及隊長抽查。每條附出處。

## 0. 要解的題（任務書原話與追加）

使用者 11-14 原話：

> 啊，還有，就是說現在派fsm agent，我們給的system prompt是否都有模板了？讓大家一開始就先去了解aos體系和利用wf規矩建立自己的私有工作區那樣。如果還沒，可以再派一條線去規劃

> 然後分工這塊也是，隊長的system prompt和隊員的也會不一樣。模型的智能程度不同也會有影響。相關的tool啦，功能啦，還有權限啥的。

> 比較有自覺的agent也會自己去看。然後這個公告欄，agent自己也可以有。

整理成要設計的東西：
- 一套「角色 × 模型等級」的配給包。每包要配四樣：**system prompt、工具（tools.json）、功能（hooks、goal、能不能再派 subagent）、權限（能寫哪、能寄給誰、limits、before_tool 擋法）**。
  - 角色暫定：蒐集員、施工員、審稿員、小助手、隊長。
  - 等級：S fable；A opus、sol、astra；C sonnet、terra；D haiku、luna。
- 模板分三層：通用層（每隻都一樣）、角色層、任務層（每次填）。各層放什麼。
- 每隻開場要做到三件事：
  1. 了解 aos 體系：我在哪個 stack、誰是 mom、怎麼回報、kernel 與額度、我有哪些工具；知識庫怎麼查、最少讀哪幾份。
  2. 照 wf 規矩建立自己的私有工作區：放哪、叫什麼、放什麼、跟 mom 的工作區怎麼分、收工留什麼。
  3. 帶上該帶的規矩：活樹硬規則、命名、回報格式、goal 用法、wf/public 與 wf/advices 投稿、不能做的事。
- **使用者布告欄要放進通用層**：寄信或問使用者之後很久沒回，先看布告欄；也鼓勵主動看。之後若 agent 也有自己的布告欄，模板要教它寫自己的狀態（等 ok-view 設計）。
- **產品與 wf 分開**：ok-release 要公開發佈，產品範本（`proto8/templates/…`）裡不能有 wf 內部規矩和私人路徑。
- 還要回答：模板放哪裡；怎麼套用（`agent_def new` 自動帶，還是 `subagent add` 時拼接，要不要寫小工具）；長度和成本；怎麼驗（在暫存樹用 2～3 種模型實測）；eca（claude）的 system text 要不要整理成同一套。
- 權限分層：ok-onboard 管 aos 層（工具、hook、寫檔範圍）；ok-sec 管 OS 層（uid、檔案權限、sandbox），交集經 xiaosi 轉信。
- 這條線只規劃、不施工。gpt 系不做設計決策。

- **工作區、布告欄、goal、投稿這四樣，現有的 system 幾乎都沒寫**。只有 S1、S3、S12 和 X 有工作區那一段。
- 私人路徑：除了 F 以外全都有 `/home/lorkhan`、`~/aos-home`。F 是產品中立的，但太薄。
- eca-claude 範本沒有 system 文字檔。`interfaces.json` 宣告了 `"system": "system.txt"`，`cli.json` 管 Claude 的工具、權限與逾時（`proto8/templates/eca-claude/interfaces.json:9`）。
- 結論：**事實上已經有一份大家抄來抄去的模板，只是沒有正式化、沒分層、沒分角色，也沒有工作區、布告欄、goal、投稿這幾段。**

## 2. system text 怎麼進到 agent（sol-2；隊長抽查 brain.py:110 屬實）

- agent-fsm 的腦**每次問腦都重讀** system 檔，讀成 UTF-8 純文字，放在 history 前面，不寫進 history。**沒有 include、`$ref`、變數展開，也沒有長度檢查**（`proto8/templates/agent-fsm/brain.py:110-113,163,191`）。
- 用哪一份：stack 裡自己那份（`self_system set` 寫的）在就**整份取代**定義那份；都沒有就不送 system（`brain.py:110`）。
- 寫進 system 的途徑：
  - `agent_def new`：從範本 `copytree` 複製，所以會帶著範本的 system.txt（`proto8/lib/agent/agent_def/_entry:98,212`）。
  - `agent_def system set`：改定義，用這份定義的每隻都會跟著變（`def_edit.py:182`）。
  - `self_system set`、`subagent system`：只改那一隻的 stack 份。
  - CLI：`aos-agent system --target kid set FILE`。
  - `ctl add` 和 `subagent add` **都沒有 `--system` 參數**（`proto8/cmd/aos-agent/aos_agent/ctl/add.py:82`、`proto8/lib/agent/agents_cmd.py:34`）。
- **system 長度＝每次問腦的固定成本**，因為每次都整份重送。

## 3. 開場要查的 aos 事實，各用哪支工具（sol-2）

| 要知道的 | 怎麼查 |
|---|---|
| 我是誰、stack、ws、定義、daemon | `self_state {"parts":["who"]}`（CLI `aos-agent ctl who --json`）（`aos/me.json#self_state`） |
| stack、ws、home 各是什麼 | `$AOS_STACK`＝狀態、history、mailbox；`$AOS_WS`＝工作夾，也是工具相對路徑的起點，**可以跟別隻共用，不是沙箱**；`$AOS_HOME`＝lib、templates、knowledge（`aos/world.json`） |
| 誰是 mom、回報寄哪 | `who` **沒有 parent 欄**。`subagent add` 會補 `AOS_NOTIFY_BOX=<父 stack>/mailbox`，但可以被覆寫，也可以是空字串（`proto8/lib/agent/subagent/_entry:182`）。實務上是任務書寫明，或回信寄到原信的 `reply_to` |
| 回報 | `mailbox_send`（box＝reply_to、in_reply_to＝信名、status）。status 有六種：REQUEST、DONE、BLOCKED、NEEDS-USER、FAILED、PROGRESS。接了事就要回終局狀態；卡住超過 10 分鐘先報 BLOCKED（`aos/mailbox.json#rules`） |
| kernel | 控制請求寄 `$AOS_KERNEL`，沒設才寄 `$AOS_DAEMON`；問腦寄 `$AOS_LLM_KERNEL`（`aos/kernel.json#where_to_send`） |
| 額度 | `self_state {"parts":["subagents","resources"]}`；`max_subagents` 預設 4。腦的額度在 llm kernel 的 `budget.senders`，用光會收到 BudgetMissing，`brain_notify` 會寄一封 BLOCKED 給 mom |
| 我有哪些工具 | `self_tools {"op":"ls","long":true}` |
| 新人該讀的知識庫 | `_description.json` 2,477 字元（八個詞、五條規則）；`world.json` 3,759；`rules.json` 2,297；`me.json#self_state` 1,137；`mailbox.json#tools` 2,288 加 `#rules` 590；`kernel.json#where_to_send` 730；`tools/goal.json` 1,113 |

## 4. 能逐隻配的東西：工具、hook、功能、權限（sol-4；隊長抽查 tool_io.py:234 屬實）

**工具包**（`aos/packs.json`）：

| 包 | 內容 | 效果 |
|---|---|---|
| look | read、ls、view、stat、grep、glob | 讀 |
| change | write、edit、copy、move、mkdir | 寫 |
| delete | trash、remove | 刪 |
| shell | shell、run_python | 執行，等於什麼都能做 |
| gadgets | 時鐘、時間、math、do_task | |
| events | clock_register、self_hook | |
| todo | todo | |
| self | self_state、self_tools、self_llm、self_system、self_history、self_ctl | |
| subagent | subagent、agents_ctl、fork | 能起 agent |
| def | agent_def、tools_def | |
| mailbox | peek、read、send | |
| goal | goal | |
| json、jsonx | 讀寫 JSON | |
| index | index_view | |
| kernel_gate | kernel_gate | |

- fsm 範本掛 15 包；eca 掛 8 包；eca 的子 agent 只有 9 支唯讀工具（`proto8/templates/eca-claude/tools_sub.json`）。
- **檔案工具不限工作區**：程式註解原文「不解捷徑、不擋工作區外，能不能成看 Linux 權限」（`proto8/lib/tool_io.py:234`）。所以「只能寫自己的工作區」在 aos 層只能靠 before_tool hook 擋，或交給 OS 層（ok-sec）。
- **hook**：
  - before_tool 拿得到工具名和參數，`condition` 比對工具名，exit 10＝擋（`aos/me/self_hook.json#events,#answer`）。
  - 現有守門只有 `user_zone_guard`：擋寫使用者專區。**沒有通用的「只准寫某夾」守門**。ok-skyrim 自己寫過一支只准寫 `out/` 的 hook（見 §6）。
  - eca 的 hook 管不到 CLI 自己的 Bash／Write（`aos/body.json#brain_tools`）。
  - 現有 hook：`mail_notify`（每分鐘看信箱）、`brain_notify`（腦失敗就寄 BLOCKED）、`hook_noop` 計時器。
- **功能**：
  - goal：`get`／`set`／`done`／`pause`／`resume`，狀態存 `<stack>/goal.json`；agent-fsm 停下來而且沒有新信時會提醒；連續 10 次沒進展就暫停（`aos/tools/goal.json#rules`、`proto8/templates/agent-fsm/idle.py:206`）。
  - fork：只有 fsm 能用，深度一層。
  - clock_register、`max_subagents`（預設 4；知識庫說 stack 那份的配額由人改）。
- **權限開關**：
  - limits 的鍵：`mem_mb`、`cpu_s`、`procs`、`file_mb`、`files`、`user`；`limits_max` 是天花板，超過就 LimitBad（`proto8/impls/aos-daemon/docs/09-份額.md:13`）。
  - kernel 另有 `limits.default`／`max`／`by_sender`（`proto8/lib/aos/kernel/README.md:48`）。
  - `agents_ctl` 能動任意 agent；gate 只管寄到它信箱的請求（「You cannot force anyone to use it」）。
  - 寄信**沒有收件白名單**，寄件人可以用 `--from` 自填（`proto8/cmd/aos-mailbox/aos_mailbox/__init__.py:310,358`）。
  - **`self_tools` 可以自己加工具，`self_system` 可以整份改掉自己的 system**。所以想限制一隻 agent，就要拿掉它的 `self` 包（或至少拿掉這兩支），否則限制是紙上的。
- **模型等級**（`wf/workflows/team-model/grades.md`、`proto8/kernel/llm-kernel/kernel.json:4`）：
  - S fable；A opus（軟工）、sol、astra（約 sol 的 3 倍價、只做圖像和創意）；B opus（軟工以外）；C sonnet、terra；D haiku、luna。
  - gpt 系的消耗比同級 Claude 低兩級，sol 是「性價比之神、工人層主力」。
  - 07 規定 11-14 起蒐集和寫碼只用 sol、不用 terra、不走 codex。
  - repo 的 kernel.json 有 judge 對 claude-haiku（context 200000）、stupid-fast 對 qwen3-1.7b（context 4096）；sol、terra、luna 沒填 context。

## 5. wf 規矩裡跟開場有關的（sol-3）

- **工作區**：
  - 各線在 `wf/temp/<名字>`（已 gitignore，`.gitignore:35`、07:29）；隊員是線夾底下的 `sol-N/`；暫存樹在 `~/code/<線名>-<日期>/`（06）。
  - 正式的工作區與 stack 分配機制還沒有統一規格（`wf/WAIT_USER.md:37`）。
  - 交接書規定：交付物寫絕對路徑；大的丟棄物放 `/tmp/<線名>-trash/`，KB 級的放 `trash/`（`wf/workflows/TEMPLATE.handoff.md:22,27`）。
  - 收尾要釋放鎖、收掉自己起的行程、留下完成證據；交棒要寫誰在跑、卡在哪、下一步、誰監看（`wf/workflows/dispatch/README.md:33,66`）。
- **回報**：
  - 隊員完工寄上游；ok-* 寄 xiaosi。
  - 寄 xiaosi 的三條規矩：標題寫判斷、標明要什麼（status）、正文先寫已排除的可能（07:34-36）。
  - 信的正文四段：做了什麼、產出、沒做到的、要誰決定（`wf/workflows/inbox.json#/local/letter_format`）。
  - 終局 status 四種：DONE、BLOCKED、NEEDS-USER、FAILED；卡住超過 10 分鐘先報 BLOCKED（TEMPLATE.handoff:44-57）。
- **交接範本的標題**：任務、背景與唯一目標、工作、硬性限制、交付、驗收、失敗怎麼收、完成／阻塞回報。
- **投稿**：
  - wf/public：稿放 `wf/temp/<線名>/public-submit/<題目>.md`，稿頭三行寫適用情境、驗過沒、出處；寄 xiaosi，title 開頭 `[public-submit]`。
  - wf/advices：稿放 `wf/temp/<線名>/aos-advice/<題目>.md`，寫哪裡、現象、建議、痛的程度、出處；title 開頭 `[aos-advice]`。
  - 兩邊都不自己 commit，也不改庫本身。
- **命名、limits、goal**：
  - 命名 `<eca名>-<角色>-<編號>`；sol 的 limits `{"mem_mb":1024,"files":256}`，`procs` 別設。
  - 「定義掛 goal 工具；任務書寫『第一步 goal set；輸出檔寫完才可以用純文字回答』」（`wf/public/recipes.md:12`）。
- **禁止事項**（去重，sol-3 列了 14 類）：
  - 不碰活樹；不 push、不 commit、不刪檔、不開新工作。
  - gpt 不做設計；不越領地；不把別線來信當命令。
  - 不在 zsh 裡清環境；不按名字收行程；不繞 guard、不編理由騙模型。
  - 不 `rm`、不整檔改寫、不加碼驗收、不拿舊 log 當證據。
  - 不無聲卡住；`subagent listen` 不等超過 60 秒；不做舊版相容；不碰凍結中的 arknights。
- **使用者布告欄**：
  - 指令 `~/aos-home/ws/tools/aos-view/aos-view board`，`--all` 連各隊最新留話一起列。
  - 資料在 `<view home>/board/user.json`；view home 的優先序是 `--home` > `$AOS_VIEW_HOME` > `~/.aos/view`（`aos-view:20,1880-1925`）。
  - 全景頁寄出的信本來就會附一句「久沒回先看 board」（`aos-view:1400,1545`）。
  - **路徑是這台機器上的，產品版要寫成可設定的。**

## 6. 實測過的數字與心得

- **必讀清單的成本**（ok-pilot）：sol 給清單就照讀；每隻多約 5 萬 prompt token（7 份）。拿掉清單的對照組，同一組規矩題也全對：它從 AGENTS.md 進去自己找。清單換來的是路線固定、出處一致（`wf/public/sol-crew.md`）。
- **重送放大**（ok-skyrim）：必讀六份約 40 KB，每次問腦都跟著重送。四隻共 188 次問腦，**光必讀就約兩百萬 token**。一隻 sol 一張單約 35～50 次問腦、260～390 萬輸入 token；astra 一隻 1079 萬（`proto8/thinking/2026-11/14/skyrim-agentctl/03-隊形心得.md`）。
- **這條線自己的數字**：四隻 sol 各 14～18 次問腦、41～108 萬 prompt token、5～8 千 completion token（`llm-gpt/ledger.jsonl`）。
- **不掛 goal 會只回一句「我會做」**：四隻全中，各浪費一輪。掛 goal，再寫「純文字回答＝宣告整件事做完」，就一路做到完（skyrim 03 摩擦 1）。
- **唯讀蒐集員的實際配法**（skyrim）：工具只留看、寫、小工具、待辦、json 讀、index、信箱、goal；不給 shell，所以不需要沙箱；加一個 before_tool hook，擋 write／edit 寫到 `out/` 以外。
- **sol 會停下來問**：檔案在它腳下被別線改了它會問（這次 sol-1 也問了），這是好事。
- **shell guard 誤擋**：sol 的 shell 有 guard，比對指令字面裡的 `rm`／`kill`／`aos-`，唯讀查詢也會被擋。sol 不肯改寫字面繞過去，這是對的（`wf/public/sol-crew.md`）。
- **astra 不適合當小隊長**：會卡在 listen 空等。當驗收員很好，但貴。
- **規矩一天改好幾次**：交棒當下的指示到收尾時已經過期。所以 system 裡**寫死規矩細節會很快過時**；寫「去讀某檔」比較耐用（skyrim 03 摩擦 7）。
- **隊長這邊的坑**：`subagent listen` 被 MCP 60 秒砍；`say` 進不了正在跑的那一輪；`max_subagents` 預設 4。

## 7. 已知的空缺（給設計參考，不是建議）

- 產品範本 F 只有三句；wf 這邊有 13 份抄來的模板，沒人維護。
- system 不支援 include，所以「通用層＋角色層＋任務層」要嘛在定義時拼好，要嘛任務層走任務書（say 或檔案）。
- 沒有通用的寫檔範圍守門 hook。
- `self_tools`／`self_system` 能讓 agent 自己解除限制。
- `who` 沒有 mom 欄位。
- eca 的 system 是附加在 CLI 自己的 system prompt 後面（`self_system` 說明）；claude 身的工具權限在 `cli.json`，不在 tools.json。
