# commit 排隊：Argon 意見採納表

← [commit-queue-1114](../commit-queue-1114.md)｜涵蓋：Argon (A) 11 條、(B) 4 條逐條採納與否、理由、落在程式哪裡

| # | Argon 說 | 採納 | 理由／怎麼做 |
|---|---|---|---|
| A1 高 | 日誌在 update-ref 前寫，復原沒驗 NEW 進了 main；main 已超過 NEW 時補寫會蓋掉後來的 | 採納 | CAS 失敗當場刪日誌；`repair` 先 `merge-base --is-ancestor NEW main`，不是就刪日誌不補；main 已超過 NEW 時只補 main 上跟 NEW 同 blob 的路徑 |
| A2 高 | `read-tree --reset -u` 不會蓋回快取樹裡被改髒的檔 | 已有 | 初稿程式就是 `read-tree --reset -u` → `update-index --refresh` → `diff-files` 找髒的 → `checkout-index -f` 只蓋那些 → `clean -fdxq`；比整樹 `checkout-index -a` 快，效果相同 |
| A3 高 | `--cacheinfo` 不填 stat、先寫 index 後寫工作樹；逐檔搶 index.lock | 採納 | `finish` 改成先寫工作樹、再一次 `update-index -z --index-info`、再 `update-index -q --refresh -- 路徑` 填回 stat |
| A4 高 | symlink 會被當成目標檔 | 已有 | `blob_of_file` 認 `islink`、`readlink` 算 blob、mode 120000；`write_file` 用 `os.symlink` |
| A5 中 | 步驟 3、5 兩次讀工作樹，中間可能被改 | 已有 | 只讀一次：`hash-object -w` 進物件庫，之後快取樹的內容一律從那個 blob 取（`cat-file`），不再讀工作樹 |
| A6 中 | 新的一天允許日索引放 `--files`，換日時又會混寫 | 採納 | 日索引、月索引、SESSION-LOG 一律不准出現在 `--files`；`day_upsert` 遇到那天還沒有日索引時用範本開（標題、導航行、規矩句、表頭） |
| A7 中 | 工作樹那份 ≠ OLD 時只重套本次 ops，工作樹若落後 OLD 會少前人的列；建議 `merge-file --union` | 部分採納 | 改成三方合併 `git merge-file -p 工作樹 OLD NEW`，合併乾淨就用合併結果（再套一次冪等 ops）、有衝突才退回「在工作樹那份上重套 ops」並警告。不用 `--union`：工作樹若是有人刻意刪掉某列，union 會把它加回來；三方合併忠實保留工作樹上的改動（含刪除），HEAD 那份不受影響 |
| A8 中 | `month_bump` 子字串判斷會吞短段；`day_upsert` 以 `[name](link)` 認列，改名會重複 | 採納 | 摘要以「；」切段、整段相等才算有；`day_upsert` 改以連結 `](link)` 認列（T10 測改名不重複） |
| A9 中 | 補完時漏了放 claim | 採納 | update-ref 一成功就 `after_ref`：放 claim、寫 `log.jsonl`，並在日誌記 `released`；`repair` 也會先跑它（冪等） |
| A10 低 | 只改 +x 會被當沒改；只有 ops 要允許；刪光夾後舊 `_index.json` 去留 | 採納／已有 | 改動比 (mode, blob)（T10 測只改權限）；只有 ops 本來就允許（T10）；生成器刪掉的生成物照 `status` 的 D 收進 commit、工作樹跟著刪（`index_gen` 自己會刪範圍內不再對應的份） |
| A11 低 | GIT_* 變數污染 | 已有 | 兩組環境都先去掉所有 `GIT_*`，快取那組只經 `env=` 傳給子行程；路徑都是 realpath |
| B1 | 以 `diff-tree OLD NEW` 當寫回的唯一依據 | 採納 | `commit-tree` 之後用 `diff-tree -r -z` 得到真正變的路徑與新 mode/blob，存進日誌，`finish` 只照它做；冪等 op 沒改到的共用檔自然不在裡面 |
| B2 | 等鎖前先拍快照，拿到鎖再比，等鎖期間被改就擋 | 採納 | `submit` 進鎖前 `hash-object -w` 一次，`build` 再比；不同回 BLOCKED `ChangedWhileWaiting`（T10 測） |
| B3 | 同一條 submit 重送要冪等 | 採納 | 檔全等於 HEAD、沒有 rm／ops、HEAD 訊息等於這次訊息 → DONE `AlreadyCommitted`、附 HEAD 雜湊（T10 測） |
| B4 | claim 過期警示 | 採納 | 擋下時附 claim 了幾分鐘；超過 120 分鐘標 `stale` 並提示頂層可 `release --force` |

另外：測試時發現 HEAD（`750735dc1` 之後）在**乾淨的複本**上跑 `index_gen` 會失敗——`index_gen_desc.json` 有 `wf/temp` 一句，而 `wf/temp` 被 gitignore、只在共用工作樹存在。排隊機制的快取樹就是乾淨複本，所以順手修了 `index_gen.py`：手寫一句話的路徑若不存在但被 `.gitignore` 涵蓋，不算 `DescMissing`。只放寬、不影響其他輸出（真 repo 上 rc=0、生成物不變）。
