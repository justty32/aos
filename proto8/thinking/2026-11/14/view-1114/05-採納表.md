| # | Argon 意見 | 處理 | 理由／怎麼改 |
|---|---|---|---|
| A1 [高] | 組樹只查 running 的隊長、靠前綴，11-14 的 ok-skyrim（成員叫 `sky-sol-*`）會歸錯、紅燈驗收失效 | **採納** | 我查過，確實是這樣：前綴規矩是 11-14 才定的，sky-* 是之前起的。改成**所有 agent 都查** `ctl state … subagents`，停掉的查一次就快取。歸屬優先序：`aide.json`／信裡的 `team` → subagent 紀錄（含停掉的隊長）→ 前綴（最後才用）。第 0 期驗收改成「用 11-14 的 ok-skyrim 這種形狀重現」 |
| A2 [高] | 收隊後小助手不停就變殭屍，停了又變假紅燈 | **採納** | 燈號加一條：隊長與成員都停了，而且最後一封是 `DONE` 或沒有待決事項 → 灰，不看小助手心跳。小助手的 hook 看到 `done` 筆記、全隊停了、outbox 清空 → 寄最後一封 `DONE`，然後自己 `ctl stop`。隊長是**當掉**的（code 143、沒寫 done）時小助手不停，照紅燈報，這正是要看的情況 |
| A3 [高] | `history rm` 會跟正在跑的模型搶；hook 與 `view_report` 之間沒有交接 | **採納** | (1) 叫模型前先看自己在 daemon 表上的 `busy`／`queued`，忙就這次跳過。(2) 交接檔 `<小助手 stack>/hooks/aide_tick/pending_report.json`（facts、snapshot_sha256、requested_at）；`view_report` 讀它組信、寄出後刪檔；下一輪 hook 看到檔還在、自己又不忙 → 當成模型失敗，用 `summary_by:"none"` 寄出。(3) `seq` 由一支加 `flock` 的小函式發號，hook 與 `view_report` 共用 |
| A4 [高] | 「≥40 字的 base64 樣字串」會把 sha256、commit hash 全遮掉，還會弄壞決策單 | **採納** | 拿掉那條。只遮有明確前綴的（`sk-`、`ghp_`、`AIza`、`xox[baprs]-`、`Bearer `）和 `*KEY=`／`*TOKEN=`／`*SECRET=`／`*PASSWORD=` 賦值；`*_sha256`、`origin` 欄位與純 hex 不掃。**`payload_text` 一律不改字**：`view_decide` 建單時先掃，掃到就拒絕建單（`SecretInPayload`） |
| A5 [中] | body 加了 `origin` 就不是逐位元組相同；`view_match` 靠可重建的 `state/` 收據不夠；送專區寫死 `--kind decide` | **部分採納** | (1) 驗收的說法改成「專區那封信的題目欄位與隊長原檔一樣」，hash 算在**題目欄位的 canonical JSON**（鍵排序、無多餘空白；欄位：`kind title what questions done_when risk urgent deadline default_if_silent dedupe_key`），不算專區自己加的欄位。(2) `view_match` 改成先過 `user_verify`，再讀專區留底的原信 `~/.aos/user/done/<月>/<in_reply_to>/letter.json`（就是 `aos-user verify` 對照的那一份；不用 `aos-user show`，它會把信從 new 搬到 cur），重算 canonical hash，跟隊長自己的 `sent.jsonl` 比；`state/passed/` 收據只拿來在網頁上顯示。(3) `kind` 從單子讀，五種都送。**不採納的部分**：Argon 提到「除 `via` 以外先定好」，`via` 是回信欄位、不在單子裡，不用處理 |
| A6 [中] | 每小時 8 封的排隊會壓過 `deadline`；先 `done` 再排隊會丟信；`cur/` 裡的信會被忘掉 | **採納** | 排隊順序：`urgent` → 有 `deadline` 的（近的先）→ 一般 decide/verify → chore/fyi；離 deadline 不到 30 分鐘的可以用專區上限剩下的 2 封額度先送。還沒送進專區的 `pass` 信**留在中轉信箱 `cur/`**，送成功、寫好收據才 `done --keep`。每次 tick 先處理 `cur/`，再 `take` `new/` |
| A7 [中] | `<隊長 ws>/view/` 會讓 git 工作樹出現多餘的檔 | **部分採納** | 不去改 `.git/info/exclude`（那是動別人的 repo 設定）。改成隊伍的筆記、待送單、留底都放 `~/.aos/view/teams/<隊>/{notes.jsonl,outbox/,sent.jsonl,aide.json}`，隊伍工作區一個檔都不加。同一個 Linux 帳號，信任程度沒有變 |
| A8 [低] | (1) 擴充欄位沒實測 (2) 燈號優先序 (3) state 讀寫會撞 (4) 小助手同時醒來搶 slot | **採納** | (1) **已實測**：在 /tmp 乾淨環境 `aos-post init`＋`send`，body 裡的 `zone kind facts payload_text` 原樣保留。(2) 燈號優先序：紅 → 藍 → 黃 → 綠 → 灰（A2 那條灰優先於「小助手沒聲音」）；有決策單在等時，暫停「60 分鐘沒進度」的黃燈計時。(3) 所有 `state/*.json` 先寫 `.tmp` 再 `os.replace`。(4) 15 分鐘門檻加依隊名算的固定偏移（0～180 秒） |
