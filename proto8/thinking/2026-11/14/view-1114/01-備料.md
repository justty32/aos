# 01 備料：讓使用者看一頁就掌握全景，現有零件盤點

← [view-1114](../view-1114.md)｜蒐集：ok-view-sol-1／2／3（agent-fsm，sol-high，唯讀），ok-view 抽查與補查｜11-14

## 使用者原話（11-14，一字不改）

> 對了，再派一條線去幫我規劃，關於如何讓我掌握全景。就是說，現在雖然我可以cd到各ws和子ws，利用say/listen跟他們溝通。但這麼多，其實有點麻煩。我想了一個餿主意，就是每個工作團隊(有隊長的，或是自己本身就兼任隊長的)，都跟他們說，請他們盡量聘請一個小助手，可以用sonnet,haiku,terra,luna這種便宜的，根據隊伍工作複雜性而定，讓小助手定期搜集隊伍進度和狀況，包括需要使用者決策的(不要讓便宜模型寫對於使用者的決策請求單，要讓隊伍先準備好，便宜模型就負責傳遞)，統一丟到一個信箱，不是直接丟到使用者信箱，而是一個中轉信箱，然後一個固定程序負責從中轉信箱收取這些，拿去present到網頁上，這樣使用者就看網頁和操作網頁就好。

骨架（不改）：每隊盡量聘一個便宜小助手 → 定期蒐集進度與狀況（含要使用者決策的）→ 決策單由隊伍先寫好、小助手只傳 → 中轉信箱（不是使用者信箱）→ 固定程序收 → 網頁呈現與操作。

## 結論先講

1. **零件幾乎都有，缺的是「接線」**。現在有四塊互不相連的東西：使用者專區（收決策、網頁回答、回信回到提問者、可驗證）、桌面進度看板（逐線卡片、總結、待你裁）、claude.ai 手機遠端看板（只能靠帶 Artifact 工具的 Claude 推拉）、小廝 xiaosi（一隻 sonnet 收全部 ok-* 的信，自由文字）。中轉信箱、每隊一個的小助手、從信箱到網頁的固定程序，這三樣都還沒有。
2. **現行規矩有一條擋路**：專區 `door.json` 明文「不要把進度寄來，進度去看板」。所以中轉信箱不能是專區信箱（跟使用者原話一致），進度和決策要在中轉信箱之後分流。
3. **外出手機今天只有一條路**：claude.ai artifact，而且要 Claude 手動推拉。本機兩個網頁都只綁 127.0.0.1；機器上沒有 tailscale、cloudflared、ngrok。
4. **便宜模型的 pack 還沒裝**：活樹的 llm kernel `llm-gpt` 只有 `sol-high`、`astra-high`、`fake`；LiteLLM 上 terra、luna、haiku、sonnet、本機模型（lm-gemma、qwen）都有，但要用就得在 llm kernel 加 pack。這算改活樹。
5. **親子樹查不全**：`subagent` 有歸屬紀錄（可以逐層 `state` 的 subagents 部分查），`agents_ctl add` 沒有；沒有全域 parent 欄位。daemon 表上看得到「隊長停了、底下的 sol 還在跑」（11-14 實況：ok-astra、ok-kf、ok-skyrim、ok-misc 停在 code 143，sky-sol-a/b/c、sky-astra-d 照跑）。

## A. 使用者專區 `~/.aos/user/`（11-13 建，[user-zone-plan](../../13/user-zone-plan.md)）

- 是使用者自己的 stack，`mailbox/` 是標準 aos 信箱（new/cur/tmp）；另有 `done/<月>/`（原信＋reply.json）、`rejected/`、`drafts/`、`door.json`（公告，`mode=normal`）、`config.json`（`port=8766`、`notify=false`）、`schema/letter.json`、`web/token`（0600）、`log.jsonl`（`at`、`ev`…）。現況：待辦 0 封、done 3 封（試用留下的）。
- 工具 `~/aos-home/ws/tools/aos-user/`：`aos-user`（入口）、`zone.py`（邏輯）、`web.py`（網頁）。指令 `init where send ls show answer reply ok door verify notify tick serve`。systemd user timer 每分鐘跑 `tick`（檢查新信、退件、到期提醒）。
- 信的種類：`decide`（1～7 題；每題 id、question、eli5、≥2 options{key,label,consequence?}、recommend；可附 why/details/source_path）、`verify`、`trial`、`chore`、`fyi`。選填 `urgent`、`deadline`、`default_if_silent`（要有 deadline，不可配 `risk: irreversible`）、`risk`、`dedupe_key`（同 key 合成一列，答一次寄給全部寄件人）、`origin`（轉交時原樣貼上，程式只驗字串）。每寄件人每小時 10 封（`max_per_hour`），違規退 FAILED。
- 網頁：`aos-user serve` 前景跑，`ThreadingHTTPServer` 綁 `127.0.0.1:8766`；不是 daemon proc，沒有常駐設定，**現在沒在跑**。Host 只收 127.0.0.1/localhost；POST 要 cookie＋表單 token 都對，有 Origin 要是本機。頁面：`/` 待辦卡片、`/l/<信>` 逐題回答（可選 other＋備註、存草稿、正常風險可「全部照推薦」，不可逆沒有這顆鈕）、`/done`、`/door`（在家／出門）、`/api/ls`。**沒有讀進度看板，也不會自己輪詢更新。**
- 回答怎麼回去：送出 → `aos-post send --in-reply-to <原信> <原信 reply_to>`；dedupe 群組每人一封；回信 `from=user`、`status=DONE`、`answers`、`answer_line`、`via=web|cli`、hash 等；寄成功才搬進 done。收信方用 `aos-user verify` 或 `user_verify` 對照專區副本與 log；**驗過的回信算使用者本人的話，含 push、刪檔**（AGENTS.md 鐵律 2，11-13 晚）。同帳號、刻意兩邊一起造假的 agent 擋不住。
- 11-13 使用者對專區的裁定（原話）：「先不考慮手機。…網頁和看板...先做網頁就好。就先只考慮家裏這臺。」

## D. aos 機制（小助手與固定程序可用的）

- **看別人的狀態，不碰對方 stack**：`agents_ctl ls --json`／`aos-agent ctl ls --json`（NAME STATE WS QUEUED REASON，long 加健康欄）、`agents_ctl state`／`aos-agent ctl state -t NAME state history subagents`、`aos-agent listen -t NAME --last N`（不等新回答）、`aos-agent history -t NAME ls`（最後 20 則、每則 200 字；`-l` 全文、`-j` JSON）。這些不會讓對方多想一輪；`say`／`ask` 會進對方 queue、會花對方一輪。eca 的 history 只有 queue 訊息和每輪最終回答，沒有 CLI 內部的工具呼叫。`ls --json` 的確切欄位沒文件（實測有 name state phase ws stack queued reason auto_restart queue cooldown busy）。
- **親子**：`subagent add` 的孩子記在呼叫者 stack 的 `tools/subagent/`（不該直接讀），可經 `subagent ls` 或 `state` 的 subagents 部分逐層查；`agents_ctl add` 沒有歸屬；`ctl who` 的 owner 是 stack 屬於哪個 agent，不是父；kernel_gate 是請求路由，不是親子；沒有全域 parent 欄位。
- **定時**：clock letter（每次一個 brain turn）、`on_clock` hook 跑固定程式（零 turn）、hook 先查、有新東西才寫進 queue（只在有事時花 turn；範例 `mail_notify`、`self_hook.json#/daily`）。eca 每個 turn 都花錢，知識庫建議後兩種。睡著不跑；錯過多次只補一次；`every_ms` 向上取整成 cycle。
- **agent-fsm 的工具包**：讀檔 `look`、JSON `json`/`jsonx`、索引 `index`、daemon 表與自己的孩子 `subagent`（含 agents_ctl）、寄信 `mailbox`、定時 `events`、跑 CLI（`aos-agent listen/history`）要 `shell`。stock 的 `mailbox_peek/read` 只讀自己的信箱；`mailbox_read` 讀了就刪（keep 則搬 archive）；固定程式可用 `aos-post see BOX NAME` 看信、`take` 會把 new 搬到 cur。
- **中轉信箱可行**：`mailbox_send {"box": "/abs/relay", ...}`／`aos-mailbox send --box`，目標要是 `aos-post init BOX` 建的信箱（tmp/new/cur），否則 `MailboxMissing`/`MailboxBad`。信＝資料夾＋`letter.json`（信封 `sender sent_at reply_to body`；body 有 `from status title what outputs not_done decide in_reply_to`）。status 只有六個字。單封大小上限沒文件。
- **llm kernel**：`~/aos-home/kernels/llm-gpt/kernel.json`：pack `sol-high`（`chatgpt-gpt-6.1-sol-high`，slots 2，max_calls 1000/日）、`astra-high`（500/日）、`fake`；總 slots 3；`budget.window=day`、`spent=refuse`；sender 以 stack 路徑計；超額不會自動換便宜 pack。pack 怎麼新增知識庫沒寫完整（07「待補」也記著）。
- **LiteLLM `127.0.0.1:4000`（實際監聽 0.0.0.0:4000）上的模型**（ok-view 查 `/v1/models`）：`chatgpt-gpt-5.6-terra*`、`chatgpt-gpt-6.1-terra*`、`chatgpt-gpt-6-luna*`、`chatgpt-gpt-luna*`、`chatgpt-gpt-6.1-sol*`、`claude-haiku-4.5*`、`claude-sonnet-4-6*`/`-5*`、本機 `lm-gemma-4-12b`、`lm-gemma-4-e4b`、`lm-qwen3.5-9b`、`ollama-qwen2.5-14b` 等。`chatgpt-*` 走訂閱額度，不是按 token 計價；單價沒有資料。

## F. 跟現行規矩的對照（帶給 fable 的限制）

- 07「不用 terra，只用 sol」講的是蒐集與施工；使用者這次點名小助手可以用 terra／luna／haiku／sonnet。兩條不衝突，小助手只傳遞，不寫碼、不蒐資料做設計。
- 鐵律 5：骨架是使用者的，不換成別的大方向（例如「乾脆全部改成固定程式」不能拿來取代小助手；可以寫「哪些步驟本來就不需要模型」讓他看）。
- user/03「需求不清時先發想」：這題骨架與要的東西已經清楚，走正統規劃；但有些地方（手機外連、頁面要長怎樣）還是要問使用者，不要先替他定死。
- 授權：網頁的回答要能算「使用者本人的話」，就得沿用專區的驗證鏈；看板的 `/api/answer` 沒有這層。
- 安全：兩個網頁都只綁本機、同帳號 agent 都碰得到；LiteLLM 開在 0.0.0.0（旁支，記給使用者）。`~/.zshrc` 的 key 不能進任何頁面或信。
- 樹的層次：隊長底下有 sol／astra 孫代，隊長倒了孫代可能還活著；小助手是隊長的 subagent，隊長停了它不會跟著停（daemon 才是父程序）。
