## 2. 我對 fable 稿的改動

1. **`payload.json` → `payload_text`**（見上）。收據與 `view_match` 都比 `sha256(payload_text 的 UTF-8)`。
2. **燈號門檻的起算點**：fable 寫「35 分鐘沒信標紅」。小助手的 `beat` 是 15 分鐘一封，所以 35 分鐘＝漏了兩封，照採；但固定程序剛起來（或 `resumed`）的頭 35 分鐘不判「小助手沒聲音」，只顯示 `warming up`，免得一開頁全紅。
3. **第 0 期的決策卡**：fable 說第 0 期在全景頁直接答題。我改成第 0 期只**顯示**專區待辦，按鈕連到專區自己的頁 `127.0.0.1:8766/l/<信>`（要使用者開著 `aos-user serve`）；全景頁內答題（呼叫專區的回答程式）放第 1 期。理由：第 0 期就能驗「一頁看全景」，又不用先碰專區的回答邏輯；第 1 期再用 import `zone.py` 的函式做，一行都不重寫。
4. **小助手的工具也給兩種身體**：fable 寫小助手是 agent-fsm。隊長多半是 opus eca，聘 agent-fsm 的小助手沒問題（`subagent add` 已實測）。小助手的定義做成範本 `proto8/templates/aide/`（從 agent-fsm 複製），隊長用 `agent_def new from` 拿去用。

### 第 1 期：中轉信箱＋只送事實的小助手（不用模型）

1. `aos-view init` 補 `mailbox/`（`aos-post init`）、`done/ rejected/ poke/ schema/letter.json`。
2. 信的 body 定案（英文欄位）：
   - 共用：`zone:"view/1"`、`kind`（`report|beat|pass|post`）、`team`、`parent`、`seq`、`from`、`status`、`title`、`what`。
   - `report`：`said{now,next,blocked}`（第 1 期空）、`summary_by`（第 1 期一律 `"none"`）、`snapshot_sha256`、`facts{leader,members,notes,pending_pass}`。
   - `pass`：`payload_id`（`<隊>/<id>`）、`payload_text`（隊長原檔全文）、`payload_sha256`、`written_by`、`reply_to_team`（隊長信箱絕對路徑）。
   - status 對法照 02 §2。
3. `aos-view tick` 加收信：`aos-post take-all` → 驗 schema → 分流：
   - `report/beat/post` → `state/teams/<隊>.json`；
   - `pass` → 重算 hash（不對：`rejected/`＋`PayloadHashBad`）→ `payload_id`＋hash 查重 → 解出 `payload_text` 用專區 schema 驗 → 排隊（每小時 ≤8 封，`urgent` 先）→ `AOS_STACK=~/.aos/view aos-user send --kind decide --reply-to <reply_to_team>`，body 加 `origin:"<隊>/<id> sha256:<hex> via <小助手>"` → 收據 `state/passed/<隊>/<id>.json`（專區信名、hash、時間）；
   - 處理完 `aos-post done --keep` 進 `done/<月>/`。
   - 每隊每小時 >12 封：多的進 `rejected/`、那隊標 `too many letters`。
   - 遮 key：掃 `sk-[A-Za-z0-9]{20,}`、`[A-Z_]*KEY=\S+`、長度 ≥40 的 base64 樣字串，換成 `[masked]`、log 記 `SecretMasked`。
4. 隊長的工具：
   - `view_note <start|progress|done|blocked|decision|handoff|ask> '一句'` → 追加 `<ws>/view/notes.jsonl`（`ts status text`）。
   - `view_decide <檔>` → 用專區 schema 驗 → 存 `view/outbox/<id>.json` → 記 `view/sent.jsonl`（id、sha256）。id 不重用。
   - `view_match <專區回信資料夾>` → 先跑 `user_verify` 邏輯 → 讀回信的 `in_reply_to` → 查 `~/.aos/view/state/passed/` 收據 → 比 `view/sent.jsonl` 的 hash → 印 `ok: match` 或 `error: PayloadMismatch`。
5. 小助手範本 `aide`（hook 那一半）：`aide.json` 給 team、parent、隊長名、隊長 ws；hook 照第 3 節。決策單寄成功才從 `outbox/` 搬到 `outbox/sent/`；連三次寄失敗寫 `view/send_failed`。
6. 全景頁加 POST（cookie＋表單 token，有 Origin 要本機）：答決策（import 專區 `zone.py` 的回答函式；`via` 照它的規矩填）、收起、叫某隊現在回報（寫 `poke/<隊>`）、靜音某隊 N 小時、切在家／出門（呼叫專區 `door`）。
7. 燈號補齊 02 §5 那張表；加 `warming up`（第 2 節改動 2）。

驗收：照 fable 第 1 期五條，另加：
- 全景頁答一題 → 隊長收到回信 → `user_verify` 過、`view_match` 印 `ok: match`。

- 一封信塞一個假 key（`sk-` 開頭 30 碼）：`done/` 裡的副本與頁面都是 `[masked]`。

## 8. 依 Argon 修訂（定稿）

逐條理由在 [05 採納表](05-採納表.md)。這裡只寫改過之後的樣子。

**組樹與燈號**
- 每個 tick 對**所有** agent（停掉的也要）跑 `ctl state -t NAME subagents`；停掉的查一次就快取在 `state/subagents/<名>.json`；跑著的每個 tick 最多查 30 個，輪著查。
- 歸屬看三個來源，排前面的優先：`~/.aos/view/teams/<隊>/aide.json` 或信裡的 `team` → subagent 紀錄（停掉的隊長也算）→ 名字前綴。第 0 期驗收拿 11-14 的 ok-skyrim 形狀來測：隊長 143、成員叫 `sky-sol-*`，頁面要把成員歸給 ok-skyrim，那隊亮紅燈。
- 燈號優先序是紅 → 藍 → 黃 → 綠 → 灰，但有一個例外：隊長和成員全停了，而且最後一封是 `DONE` 或沒有待決事項，就直接亮灰，不看小助手的心跳。有決策單在等時，「60 分鐘沒進度」的黃燈暫停計時。第 2 期加黃燈 `looping?`：最近 5 則訊息裡重複 3 則以上。
- `state/*.json` 一律先寫 `.tmp`，再用 `os.replace` 換上去。

**隊伍的檔放哪**（取代 §3 的 `<隊長 ws>/view/`）
- 放 `~/.aos/view/teams/<隊>/`，底下有 `aide.json`、`notes.jsonl`、`outbox/`、`outbox/sent/`、`sent.jsonl`、`send_failed`。隊伍的工作區一個檔都不加。

**小助手**
- 模型那一半改做「助手觀察」：看成員的 history 和狀態，寫一句「隊員在忙什麼」。`view_report` 的參數是 `observed`（一句，最多 120 字）和 `blocked`（可空）。網頁每隊並排兩行：**隊長留話**照抄 `notes.jsonl` 最新一筆，**助手觀察**是模型寫的那句，標上是哪個 pack 寫的。
- hook 叫模型之前，先看自己在 daemon 表上是不是 `busy`、`queued>0`；忙就這輪跳過。不忙才清掉自己的歷史，寫好交接檔 `<自己 stack>/hooks/aide_tick/pending_report.json`（內容 `facts`、`snapshot_sha256`、`requested_at`），再寫 queue。
- `view_report` 讀交接檔，組好信寄出，然後刪掉交接檔。下一輪 hook 看到交接檔還在、自己也不忙，就當作模型失敗，改寄 `summary_by:"none"`。
- `seq` 由一支加 `flock` 的函式發號，hook 和 `view_report` 共用。
- 15 分鐘門檻加一個依隊名算出來的固定偏移（0～180 秒），各隊不會同時去搶 slot。
- 收隊：hook 看到三件事都成立——有 `done` 筆記、全隊都停了、outbox 是空的——就寄最後一封 `DONE`，然後 `aos-agent ctl stop` 停掉自己。隊長是當掉的（沒有寫 `done` 筆記）就不停，繼續照紅燈回報。

**決策單**
- hash 改算在題目欄位的 canonical JSON 上（鍵排序、`separators=(",",":")`、`ensure_ascii=False`），欄位有 `kind title what questions done_when risk urgent deadline default_if_silent dedupe_key`。`view_decide` 把結果記進 `sent.jsonl`；信裡的 `payload_text` 一個字都不改。
- `view_decide` 建單時先掃 key（只認明確前綴與 `*KEY=`、`*TOKEN=`、`*SECRET=`、`*PASSWORD=` 賦值），掃到就拒絕建單，回 `SecretInPayload`。固定程序遮 key 時跳過 `payload_text`、`*_sha256`、`origin` 和純 hex 字串。
- 送進專區的 `kind` 從單子裡讀，五種都可以。
- 排隊順序：`urgent` → 有 `deadline` 的（近的先）→ 一般的 decide／verify → chore／fyi。每小時最多 8 封；離 deadline 不到 30 分鐘的，可以用剩下的 2 封額度先送。
- 還沒送進專區的 `pass` 信留在中轉信箱的 `cur/`；送成功、寫好收據後才 `aos-post done --keep`。每個 tick 先處理 `cur/`，再 take `new/`。
- `view_match`：先跑 `user_verify`，再讀 `~/.aos/user/done/<月>/<in_reply_to>/letter.json`（就是 verify 對照的那一份），重算 canonical hash，跟 `sent.jsonl` 比。結果印 `ok: match` 或 `error: PayloadMismatch`。`state/passed/` 的收據只給網頁顯示用。
- 第 1 期的驗收改成：「專區那封信的題目欄位和隊長的原檔一樣（canonical hash 相同）」。

**網頁**
- 撤回 §2 的改動 3：第 0 期就開答題。後端呼叫 `subprocess.run(["aos-user", "answer", N, "q1:a", …])`，不 import `zone.py`、不改專區。回信的 `via` 是 `cli`，照實寫。

**已實測**

| `expand`（擴充部門） | 該部門主管（target 本人） | `target`、`what`（要多做什麼）、`budget?` | 部門卡上的「擴充」按鈕 → 表單 |

| `power`（電力：llm 額度） | 電力部門（之後的 llm kernel 上層；沒設就寄給 repo-aos） | `target`、`priority`、`quota?`、`why` | 機房區的「電力」卡：各部門用量（有正式介面才顯示，否則 `not recorded`）＋調整申請 |

後端只要加 `POST /api/order`（重用 `do_mail`）和 config 裡的 `orders` 表；前端每個 kind 一個小表單模組。部門用 `tags` 上色、篩選（第 6 題 a），`config.tags` 已經留好了。
