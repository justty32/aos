## 使用者原話（11-14 中午，頂層轉，一字不改）

> 然後目前的全景已經很好用了。希望能把版本獨立成一套。然後接下來的公司部門那個概念，可以的話需要重新規劃一整套UI，後端邏輯倒是應該還好。

> 對，就是前端的使用者體驗這塊

頂層的轉述：規劃重點是董事長怎麼一眼掌握全局、怎麼一層層往下看、怎麼下指令和說話，操作要順手；後端只補缺的 API，不重寫；技術棧隨意，可以用框架；新 UI 另開 8768，和 v1 並存可切換。

今天從頁面上來的回饋（sol-9 逐字整理）：
- 布告欄：睡覺前留話，agent 等不到回信時會來看。
- 「要你決定」送出後卡片賴著不走，捲動亂跳。使用者自己提了三種做法：折疊丟到底部、隱藏後另有按鈕看已送出的、能修改重送。
- 「我寄了信怎麼沒回」：要看得到送出後的狀態。
- 「先不用手機」。

## 1. v1 現在有什麼（sol-6）

v1 已經凍結在 `ui/v1/`，總共四個檔：`index.html`、`app.js`（約 760 行）、`map.js`（約 440 行）、`style.css`。原生 JS，沒有框架、沒有 build。

- **畫面**：
  - 頁首有幾個大數字：要你決定、出事、要留意、在跑。
  - 主體由上往下是：布告欄 → 要你決定 → 部門樹（清單）或地圖 → 機房 → 隊伍回覆。
  - 右側面板開單一 agent，分三頁：現在、往來、對話紀錄。說話、寄信、董事長指令都塞在面板底部，要點開才看得到。
- **地圖**：
  - 世界座標排版一次算好，用 CSS transform 縮放。
  - 每個框看自己在螢幕上多寬來決定畫多少：<24px 是色點，24–120 有燈號和名字，120–320 加兩行話，≥320 展開。
  - 點房間會飛進去，Esc 退一層，滾輪縮放、拖曳移動。
- **更新**：每 15 秒輪詢 tree、asks、relay、board，整區重畫。保護方式有 `busy()`（正在打字就不重畫）和記住捲動的 Y 值。

**摩擦 53 條裡最傷體驗的**（編號照 sol-6）：
1. **找東西靠捲**（F01、F03、F08、F09）：區塊是直排的，沒有搜尋；切到地圖就看不到清單、機房、回覆。
2. **說話、寄信、下指令都要先打開某個 agent，再點開摺疊**（F04、F05）：至少三下才開始打字；也不能一次對多隊說。
3. **頁首的數字點不進去**（F02、F34）：紅燈 2 個是哪兩個，要自己找。
4. **草稿會丟**（F21、F22、F23）：重新整理、關面板、換指令種類，打的字就沒了；Esc 會在打字時關掉面板。
5. **面板不會自己更新**（F12、F13）：往來、送達狀態、現在狀態，都要手動重開才會刷新。
6. **地圖的位置不留**（F39、F40、F41、F42）：重新整理回到全覽；手動縮放後麵包屑不跟著變；樹變了相機不跟。
7. **地圖上很多東西點不了**（F37、F38、F44、F46）：藍色圖釘只是數字，點房間不會開主管；proc、外部服務沒有詳情卡。
8. **一頁多個捲軸**（F10、F52、F53）：面板在窄螢幕會蓋掉整個畫面。
9. **新鮮度不誠實**（F11、F17、F19）：「N 秒前更新」只代表樹；fetch 沒有逾時，一個卡住就整輪停。

## 2. 後端有什麼、缺什麼（sol-8）

**已經有，不能當成缺口**：
- 部門與員工樹：燈號、rollup、tags、主管留話、小助手心跳。
- bot 卡的「現在」，以及 mailbox 和 history（含用過的工具名）。
- expand、hire、power 三種指令；說話、寄信、往來、送達狀態。
- 布告欄、asks、已回答清單、寄更正。
- 外部服務的健康檢查。

**圖紙答應過、但後端還沒有**：
- `/api/node?id=`、`/api/bot?id=`。
- rev 和 304、`X-Last-Tick`。
- 固定座位（slot 持久化）。
- 普通 proc 的資源詳情。
- commit 和 claims 統計。
- bot 卡完整的「做過、說過」契約，加上 30 秒快取和 `Semaphore(2)`。

**推播**：完全沒有 SSE。collector 不是每 20 秒準時跑：一輪 = 跑完的時間 + `poll_s`。一輪要叫 1 + N 次 CLI（N = 非 llm 的列數，每列 1 次 `ctl state`）。

如果加 SSE，只轉送 collector 已有的快照：
- 省得掉：瀏覽器重複 GET，以及「採樣完成到下一次 GET」之間的等待。
- 省不掉：採樣本身的成本，也不會讓採樣變快。

要先定契約的：
- SSE 的事件粒度和重連。
- 指令（order）的執行狀態：被 gate 放行了沒、做完了沒。
- 送達狀態是推定的，還是要正式 receipt。
- 更正要不要有結構化的關聯。

## 4. 給 fable 的題目

設計一整套「公司部門」前端。重點是使用者體驗，不是後端：
1. **一眼掌握全局**：董事長打開第一眼看到什麼；哪些事要主動推到他眼前（要決定的、出事的、回了話的、卡住的）。
2. **一層層往下看**：從公司 → 部門 → 子部門 → 員工 → bot 卡，怎麼走、怎麼回來、位置怎麼留；2D 縮放和清單要不要並存、怎麼切換。
3. **下指令和說話**：對任何人、任何部門說話、寄信、下三種指令，怎麼做到兩下就開始打字；送出之後狀態怎麼一路看到「已回」；草稿不丟。
4. **v1 摩擦的解法**：上面 1–9 條逐條給答案。
5. **技術棧**：要不要用框架、用哪個；build 和離線 vendor 怎麼做。
6. **後端要補的 API**：只列真的缺的。
7. **分期**：最小可用的第一版是什麼，後面怎麼長。
