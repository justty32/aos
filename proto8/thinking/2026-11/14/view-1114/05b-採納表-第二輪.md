# 05b 採納表（第二輪）：Argon 意見逐條處理（view-1114）

← [view-1114](../view-1114.md)｜對 [04b-Argon原文-第二輪](04b-Argon原文-第二輪.md) 逐條處理；採納的寫進 [03-計劃](03-計劃.md) §10｜ok-view，11-14

**結論**：21 條全部採納，其中 2 條部分採納（A7、A9）。骨架和第一輪定稿都沒動。改得最多的是前端：卡片改用 HTML，只有箭頭與圖釘用 SVG，還是零依賴；每個框只看自己在螢幕上多寬。

| # | Argon 意見 | 處理 | 理由／怎麼改 |
|---|---|---|---|
| A1 [高] | `ctl ls` 沒有 `code`，紅燈、灰燈分不出來 | **採納** | 我又查了一次：`ctl ls --json` 和 `ctl state … state -j` 都**沒有結束碼欄位**，只有 `state phase reason queued`。今天表上沒有停掉的列，`reason` 字串長什麼樣查不到。改成：施工第一件先在暫存樹停一隻、殺一隻，看 `reason`。分法：`reason` 空的、或者寫正常結束 → 灰；有錯誤字樣、被訊號殺掉、`cooldown` 有失敗次數 → 紅；認不出來 → 黃 `stopped, reason unknown`，不猜。節點第一次變成 stopped 時查一次 `ctl state` 存進 `state/stopped/<名>.json`，之後不再重查 |
| A2 [高] | 主管既是房間又是第一張桌，燈號會互相污染 | **採納** | `self.light` 只看主管本人（跟葉子同一套規則）。「隊長倒了底下還在跑」「小助手沒聲音」「60 分鐘沒進度」改算在 `rollup.worst`／`rollup.why`。房間展開時第 0 格固定是主管桌（Lead Desk），點它就開主管本人的 bot 卡。`rollup.nodes` 照舊算節點數，主管桌不另外算 |
| A3 [中] | 小助手放進 `children` 會佔座位，收隊時會誤觸紅燈 | **採納** | 小助手只放在部門節點的 `aide` 欄位：不進 `children`、不發 `slot`，也不算「底下還在跑」。畫成房間標題列右上角的徽章（02b §1 本來就這樣說，§3.1 的範例寫錯了） |
| A4 [中] | `llm_<id>` 先當節點再收起來，會灌爆座位表、讓 `rev` 一直跳 | **採納** | 讀完 `ctl ls` 第一步就把 `^llm_` 的列攔下來，只記個數，收成 `machine` 區的一個固定節點 `llm-workers`（`active: N`）。不進 `layout.json`。個數變了不加 `rev`，只更新 `X-Last-Tick` 那一類的 header（見 A6） |
| A5 [高] | 每輪最多查 30 個 subagents，新的子節點會先掉進 `unassigned` 再跳回來 | **採納** | (1) `state/subagents/<名>.json` 在重查之前一直沿用。(2) 這輪有新名字、而且按前綴歸不到哪一隊時，先把所有 running 主管排到這輪 30 個額度的最前面。(3) 還是歸不到的，先標 `pending` 不發座位，最多等 3 輪才放進 `unassigned` |
| A6 [高] | 304 沒有 body，前端拿不到 `last tick`，3 分鐘後會誤報斷線 | **採納** | 樹裡的時間一律存絕對時間（例如 `claimed_at`，不存 `age_s`），「幾分鐘前」由前端算。`rev` 算在扣掉 `generated_at`／`seen_at` 以後的內容上。200 和 304 都帶 header `X-Last-Tick`、`X-Ask-Count` |
| A7 [中] | `log.jsonl` 的線名跟節點名對不上；today 要用哪個時區 | **部分採納** | 我查了帳本：`line` 有 `ok-astra ok-limits ok-misc ok-skyrim repo-aos cq-1114`，大多數就是 agent 名，直接相等就對得上。對不上的（例如 `cq-1114`）由 `aide.json` 的 `line` 指定；沒指定的放 `unattributed`。**不採納**「去掉前綴字根做模糊比對」：猜錯會把 commit 算到別的部門，寧可不歸。today 用本機時區的 00:00，從檔尾往前讀 |
| A8 [中] | 子 daemon 的 id 有 `/`，會弄壞 `/api/node/<id>` | **採納** | API 改成 `/api/node?id=<id>`、`/api/bot?id=<id>`，id 在 JSON 裡保持原樣 |
| A9 [中] | `--on` 的對象拼錯、不在畫面上、互等 | **部分採納** | 對象縮在還沒展開的房間裡 → 箭頭接到畫面上看得到的那個祖先框；對象不在樹上 → 不畫箭頭，寫 `waiting on <名> (missing)`。互等成環 → 兩邊加 `waiting on each other` 籤。**不採納**用 `deadlock!` 這個字：這只是兩邊各寫了一句，不一定真的卡住；頁面只照寫的呈現，不下判斷（02b §4 只呈現協調、不做協調） |
| A10 [高] | 純 SVG 的 `<text>` 不會換行，卡片很容易爆框 | **採納** | 世界層改用 `<div>`，外面一層用 CSS `transform` 縮放與平移；房間和卡片都是一般 HTML（Grid、換行、省略號）。上面蓋一張透明 SVG，只畫箭頭和固定大小的圖釘。仍然零依賴，`export` 單檔照常可用 |
| A11 [高] | 「父框 > 360px 才展開孩子」在孩子多或少時都不對，還會讓框跳大小 | **採納** | 世界座標裡每個框的大小和位置在排版時一次算定，縮放時不改。展不展開看**每個框自己在螢幕上的寬度**，每一層都用同一張表：`<24` 圓點、`24–120` 燈號＋名字、`120–320` 兩行句子＋孩子的色點、`≥320` 展開（有孩子）或 Now 詳情（葉子）。這比 02b §5.3 更合「每一層同一套畫法」 |
| A12 [中] | 拉近或拖過員工桌時會一次打很多 bot 請求 | **採納** | 縮放、拖動時只顯示 `tree.json` 裡現成的 Now；Did／Said 要**點那張卡**才拉，一次只拉選中的那張，離開就停 |
| A13 [高] | bot API 在 handler 裡跑 CLI，會卡住伺服器或一次開太多子程序 | **採納** | `ThreadingHTTPServer`，所有 CLI 呼叫共用一把 `Semaphore(2)`，`timeout=5s`，超時回 504。id 先比對記憶體裡的樹，要是 `kind == "agent"` 才放行；argv 用 list，不經過 shell。結果在記憶體快取 30 秒，不落地 |
| A14 [中] | 第 7 題選 b 去讀 `live.jsonl` 的風險 | **採納（當作推薦的理由）** | 跟 02b 推薦一樣是 a；要看 eca 用過哪些工具，就走 c（補正式指令）。題目照樣問使用者，這條的理由會寫進題目 |
| A15 [低] | 「一天查一次 `ss`」要有地方記上次什麼時候查的 | **採納** | 結果和 `checked_at` 存進 `state/externals.json`，超過 86400 秒才重查 |
