# 02d fable 設計稿（第四輪）：全景前端大型重新規劃

← [view-1114](../view-1114.md)｜依據 [01d](01d-備料-UX重規劃.md)、astra 報告（`wf/temp/ok-view/ux-1114/astra/astra-報告.md`）｜fable，11-14

只規劃、不施工。後端照舊，只補缺的。v2 的資料層（pulse／rev、ui-state、草稿、`keys.ts`）全部留用，畫面重排。
下面的尺寸都是**設計預算**，還沒量過；要量的列在 §9。

## 0. 結論先講

1. **一格只放一樣東西。** 右欄不再把「決定單＋人卡＋打字框」疊三層。決定單變成右欄的**一個分頁**，跟「現在／往來／做過・說過」並排。這樣就沒有東西能蓋住別的東西。
2. **打字框平常只有一行（44 px），最高 240 px。** 寄信、指令的欄位都在這 240 px 裡，放不下就在框內捲。指令不可能再佔半個畫面。
3. **地圖重做成「名牌地圖」，不用縮放。** 整間公司照視窗大小排版，每個人是一塊寫得下全名的名牌（最小 104×28 px，字 13 px）。放不下時整張圖降一級密度，不把字縮小、不截名字。地圖在 1366 寬時佔 918×688 px（視窗的 60%；v1 是 21%）。
4. **左右兩欄都能收。** 左欄收成 48 px 的數字條，右欄沒選人時收掉。要看全局就收，要做事就開。
5. **v2 取代 v1。** v1 只修「Esc 丟草稿」一條，其他不修。第一期上線後使用者改看 8768。
6. **第一期就含地圖。** 使用者點名的兩件（指令佔版面、地圖太小）都在第一期解決。

右欄高度帳（視窗高 768，扣頁首剩 724）：

| 塊 | 高度 | 性質 |
|---|---:|---|
| 名條 | 56 | 固定 |
| 分頁列 | 32 | 固定，永遠在內容**上面** |
| 內容 | 最少 240 | 唯一會伸縮、會捲的一塊 |
| 打字框 | 44～240 | 釘在底；上限 `min(240, 右欄高×33%)` |
| 合計最壞情況 | 56＋32＋240＋240＝568 ≤ 724 | 還剩 156 給內容 |

視窗矮到 650（筆電開著書籤列）時：724 變 606，568 仍放得下。

### 1.2 誰固定、誰可收、誰可捲

| 區 | 寬 | 可收 | 捲動 |
|---|---:|---|---|
| 頁首 | 全寬×44 | 不收 | 不捲 |
| 左欄 | 300 ↔ 48 | 按 `[` 或欄頂的箭頭；收起時只剩五個數字 | 自己捲 |
| 中欄 | 剩下的 | 不收 | 地圖不捲；部門牆自己捲 |
| 右欄 | 400 ↔ 0 | 按 `]`；沒選任何人且在地圖時自動收 | 只有「內容」那塊捲 |
| 打字框 | 右欄內 | 沒在打字時收成一行 | 超過上限時框內捲 |

中欄寬度四種情況：666（都開）、918（收左）、1066（收右）、1318（都收）。

寬螢幕：≥1600 時右欄 460、左欄 320；其餘都給中欄。

### 1.3 不准互相蓋住：寫成規則

- 三欄和欄內各塊都用 CSS grid 的列來分，**不用 absolute／fixed 疊兄弟**。
- 右欄：`grid-template-rows: 56px 32px minmax(240px,1fr) auto`，第四列 `max-height` 照上表。
- 會蓋住別人的只有三種彈出物：找人（Ctrl+K）、我的公告、鍵盤說明。它們有暗底、Esc 可關，一次只開一個。
- 驗收（給 astra，§9 A1）：每個可點的東西，取中心點做命中測試，命中的必須是它自己。任兩個兄弟區塊的矩形不相交。

### 1.4 決定單和打字框同時開著

決定單是右欄的第一個分頁，不是另外疊上去的一塊。

```
│ ● ok-view   要你決定 1                                  │ 名條 56
│ [決定 1/2 ‹ ›] [現在] [往來] [做過・說過]                 │ 分頁 32
│────────────────────────────────────────────────────────│
│ 地圖要用 SVG 還是 canvas          期限 12-31｜3 分前      │ ┐
│ q1. SVG 還是 canvas？                                   │ │ 內容：自己捲
│  (a) SVG  推薦      後果：…                             │ │ 至少 240
│  (b) canvas         後果：…                             │ │ 沒在打字時 548
│ q2. 要不要動畫？ …                                      │ ┘
│ [全照推薦]  [送出（還有 1 題）]  先跳過                   │ 送出列 44，釘在內容底
│────────────────────────────────────────────────────────│
│ 對 ok-view 說…（按 / 開始打字）                          │ 打字框收起 44
└────────────────────────────────────────────────────────┘
```

- 兩題的決定單在 v2 量到 480 px 高。內容區有 548−44＝504，**不用捲就看完**。
- 回答時想看它的往來：點旁邊的分頁。答到一半的選項和備註本來就存著，切回來還在。
- 這時去打字：打字框長到最多 240，決定單內容縮到 264，自己捲。兩塊都還在、都點得到。
- 點左欄的藍色待辦＝選中出題的人＋右欄開在「決定」分頁。出題的人不在樹上（已收隊）也一樣開，名條寫「已收隊」。
- 很長的決定單（第三期）：分頁上有「放大」，蓋住中欄來讀。這是使用者自己按的，Esc 回來。

## 2. 地圖（第 2 題）

### 2.1 定位

**地圖和部門牆是中欄的兩種看法，同一個位置、同一個選取、同一套按鍵。**

| | 地圖 | 部門牆 |
|---|---|---|
| 回答的問題 | 全公司現在怎樣、誰在哪 | 這個部門每個人在做什麼 |
| 畫幾層 | 全部（放得下的話） | 一層 |
| 每人多少字 | 名字＋燈（有空間再加一行） | 名字、狀態、公告或最後一句 |
| 捲動 | 不捲，永遠剛好一屏 | 自己捲 |
| 預設用在 | 公司層（首頁） | 進了某個部門之後 |

`m`／`w` 隨時互換；使用者換過，就照他換的記住（存 ui-state 的 `prefs`）。

### 2.2 為什麼 v1 的地圖小

astra 量到：字一直是 13 px，但整張圖先排在一張大平面上、再整體縮到 0.13 倍，框只剩 24×15 px，名字的容器沒空間。再加上左邊空的布告欄吃 560 px。

所以不是把畫布拉大就好。**要改的是排法：照螢幕有多少像素來排，不是排好再縮。**

### 2.3 名牌地圖怎麼排

一個純函式：`layoutMap(樹, 所在部門, 寬, 高) → 每個節點的矩形和密度`。HTML 方塊定位，不用 canvas、不用 transform 縮放。

**四級密度**（整張圖用同一級，從最高試起，放得下就用）：

| 級 | 每人一塊 | 內容 |
|---|---:|---|
| D3 卡片 | 210×76 | 名字、狀態一行、公告或最後一句一行 |
| D2 兩行牌 | 150×44 | 名字、狀態一行 |
| D1 名牌 | 104×28 | 燈＋名字 |
| D0 點 | 14×14 | 只有燈；房間標題寫「共 N 人」 |

規則：

1. **名字不截。** 房間裡的人去掉跟房間相同的開頭：在 `ok-board` 裡，`ok-board-sol-26` 寫成 `·sol-26`。還是寫不下才用省略號，滑過去有全名。
2. **有事的人至少是名牌。** 出事、要你決定、公告寫等你的，就算整張圖降到 D0 也照樣畫成 D1，排在房間最前面。
3. **房間＝一個框**：標題列 26 px（部門名、人數、圖釘），裡面是主管桌和成員。子部門是框裡的框，最多畫到所在位置往下兩層；再深的用「▸ N 人」表示，進去才展開。
4. **排法**：房間照座位表的順序，一列一列往右排，排滿換列（shelf）。每個房間的寬＝它需要幾欄名牌。總高超過舞台就降一級密度重排。
5. **座位固定**：順序用已有的 `seats`（03 §12.1 第 5 件）。人走了留空位，別人不補位。

**現在的公司放不放得下（估算，待 astra 量）**：活樹約 33 隻 agent。D1 每塊連間距 108×32。918 寬一列放 8 塊，33 塊只要 5 列＝160 px，加房間標題不到 300 px。舞台有 688 px 高，所以多半能升到 D2，甚至部分 D3。666 寬（左右都開）一列 6 塊，同樣放得下。估計 D1 要到 100 人上下才會不夠。

### 2.5 操作

- 點名牌＝選（右欄開）。點房間標題、雙擊、Enter＝進那個部門：那個房間長成整個舞台，密度自動升高。
- 滾輪往前＝進游標下的房間；往後＝回上一層。**沒有自由縮放、沒有拖曳**，因為永遠剛好一屏（這條要問使用者，§10 U4）。
- 圖釘可點：🔵 開那個人的決定分頁，🔴 選中出事的人。
- 頁首數字被點時，地圖把相關的名牌標亮、其他變淡。
- 視窗變大小、收合左右欄＝重排一次（函式重跑）。
- v1 的 `map.js` 不搬。它的縮放門檻、transform 都用不上；只沿用「HTML 方塊」這個做法和燈的顏色。

### 2.6 部門牆也收緊

中欄 666 時三欄卡片（210 寬），每張 76 px 高（v2 現在約 140）。688 px 高可放 8 列＝24 張。repo-aos 現在 19 格，**不用捲**（v2 現在 19 張只看得到 8 張）。卡片三行：名字和圖釘／中文狀態／公告或最後一句（各一行，全文在右欄）。

## 3. 一眼掌握全局（第 3 題）

### 3.1 左欄：五組，每組標題都在首屏

| 順序 | 組名（頁首數字用同一個詞） | 內容 | 首屏先列 |
|---|---|---|---:|
| 1 | 🔵 要你決定 | 專區在等的信 | 3 張 |
| 2 | 🔴 出事 | 亮紅燈的人，**寫名字和原因** | 3 張 |
| 3 | ⏳ 等你 | 公告欄寫「等使用者」的 agent | 3 張 |
| 4 | ✉ 新回覆 | 還沒看過的回信 | 3 張 |
| 5 | 🕓 等很久沒回 | 你送出去、過了門檻沒動靜的 | 2 張 |

- 每組超過就寫「還有 N 則 ▾」，點了才展開。活樹現在 17 則回信會把別的擠到底下，收起來後五組標題都在 724 px 內。
- 高度帳：左欄 724，扣分頁列 36，剩 688。組標題 24×5＝120。「要你決定」「新回覆」每張兩行 48 px，其餘三組每張一行 32 px。所以表裡的「要你決定」先列 3 張（不是 4）：120＋3×48＋3×32＋3×32＋3×48＋2×32＝664 ≤ 688。
- 實作不寫死張數：照剩餘高度分配，每組至少 1 張，空的組不佔位、多出來的高度先給「要你決定」。
- v2 現在把「公告寫等你」放在「等很久」裡。分開：**「等你」是它在等你；「等很久沒回」是你在等它。**
- 黃燈不進左欄，照舊只在頁首「留意」。

### 3.2 數字一律點得到人

- 頁首五個數字＝左欄五組的張數＋留意。點數字：左欄只剩那組、展開全部；中欄標亮那些人。再點取消。
- 中欄工具列的「33 人：29 在做、2 閒、1 停、1 出事」每一段都能點，效果同上。
- 部門卡、房間標題上的 🔴1 🔵1 都能點，直接選中那個人。
- 左欄收成 48 px 時，五個數字直排，點了就展開左欄並篩那組。
- 分頁標題 `(3) 全景` 照舊（要你決定＋出事）。

### 3.3 沒選人時的右欄

- 在部門牆：右欄顯示所在部門的部門卡（照舊）。
- 在地圖：右欄收掉，地圖拿全寬。

## 4. 指令與說話（第 4 題）

### 4.1 打字框的四個高度

| 狀態 | 高 | 內容 |
|---|---:|---|
| 收起 | 44 | 一行：「對 ok-view 說…」＋有草稿時顯示「草稿」 |
| 說話 | 132 起，隨字長到 240 | 對象列 28＋文字框＋送出列 32 |
| 寄信 | 同上＋一行 24 | 多一行「標題：（第一行）」 |
| 指令 | 204 | 對象列 28＋句子列 32＋文字框 72＋說明一行 24＋送出列 32＋間距 |

```
│ 對 [ok-view ×] ＋        (說) 信  指令        收起 Esc │ 28
│ 加人：[ 2 ] 個 [sol ▾] 當 [測試員      ]            │ 32  ← 指令才有這列
│ ┌────────────────────────────────────────────────┐ │
│ │ 要什麼、為什麼…                                  │ │ 72
│ └────────────────────────────────────────────────┘ │
│ 會寄給 repo-aos 代辦；寄出不等於已加人                 │ 24
│ [下指令]                              草稿已存 10:31 │ 32
```

- 指令三種（擴充、加人、電力）是句子列最前面的一個選單，不是三顆鈕再展開一塊。
- 欄位**記住上次的值**（人數、模型）。第一次的預設：1 個、模型不指定。
- 寄信：不另外有標題格。文字框第一行就是標題，下面那行「標題：…」即時顯示會寄出的標題，可點了改。狀態預設 REQUEST，寫成「請求 ▾」，平常不用動。

### 4.2 找人框兼做「下命令」

Ctrl+K 的框認得開頭的動詞：

| 打什麼 | Enter 之後 |
|---|---|
| `board` | 選中 ok-board，游標在打字框（說話） |
| `信 board` | 同上，打字框是寄信 |
| `加人 view`、`擴充 view`、`電力 view` | 同上，打字框是那種指令，游標在第一個要填的格 |
| `決定` | 開下一張決定單 |

打字框有字時另有 Alt+S／Alt+M／Alt+O 換說話／寄信／指令（字不丟）。

### 4.3 步數目標（astra 的算法：一次點擊或一組按鍵算 1，打字不算）

| 工作 | v1 | v2 現在 | 目標 | 怎麼走 |
|---|---:|---:|---:|---|
| 說話 | 3 | 3 | 3 | Ctrl+K → Enter → Ctrl+Enter |
| 寄信 | 6 | 6 | **3** | Ctrl+K「信 名字」→ Enter → Ctrl+Enter |
| 加人 | 10 | 8 | **5** | Ctrl+K「加人 名字」→ Enter →（填角色）Tab →（填原因）Tab → Enter 按下「下指令」 |
| 回決定單 | 1 | 3 | 2 | 點待辦 → 送出（已全照推薦預選時）；不可逆的單照舊不預選 |
| 對已選的人說話 | — | 2 | 2 | `/` → Ctrl+Enter |

指令照 03 §12.8 不給 Ctrl+Enter，所以最後一步是 Tab 到按鈕再 Enter。

### 4.4 送出之後

狀態用字固定這幾個，**看得見的字就寫出是不是推定**：

| 顯示 | 意思 | 圖示 |
|---|---|---|
| 已送出 | 後端收下了 | ● |
| 排隊中（前面 N 則） | 還在對方信箱 | ● |
| 推定已讀 | 信離開了信箱，沒有回條 | ◐（半滿）|
| 已回 | 有 `in_reply_to` 對得上的回信 | ● |
| 之後有來信 | 說話之後它寄過信，不保證是回這句 | ◐ |
| 狀態不明 | 讀不到 | ○ |
| 等很久 | 過了門檻（門檻照 02c §2） | ⏳ |

- 半滿的圖示＝推定。圖例放在追蹤頁最上面一行。
- 追蹤和往來裡，說話顯示**原句的前 40 個字**，不再是「(說話)」。資料在 `sent.jsonl`；後端 `/api/outbox` 若沒帶原文，補一個欄位（唯一可能要補的後端）。
- 指令送出後寫「已寄給 repo-aos 代辦（還沒加人）」。對方回信的狀態變成結果：辦好了／卡住了／做不了／要你出面。
- 送出成功的那一行出現在打字框上方 5 秒，並有「看追蹤」的連結。

## 5. 名稱與文字（第 5 題）

### 5.1 一件東西一個名字

| 東西 | 統一叫 | 不再用 |
|---|---|---|
| 使用者自己貼的話 | **我的公告** | 布告欄、留話、📌 留話 |
| agent 貼的話 | **公告**（「ok-board 的公告」） | 布告、board、主管留話 |
| 專區在等的信 | **要你決定** | 要決定、等你的信 |
| 公告寫等使用者 | **等你** | 在等人、等很久 |
| 沒看過的回信 | **新回覆** | 回了話、等回音 |
| 你送出沒動靜 | **等很久沒回** | 等很久 |
| 送出物的清單 | **追蹤** | 寄件匣 |
| 部門的頭 | **主管** | 隊長、主管桌（桌只用在座位） |

「公告欄」是使用者自己的說法（「或許我也可以看到agent的公告欄？」），所以選它。

### 5.2 狀態字全中文

前端加一個檔 `model/words.ts`，**用結構化欄位組句子，不去解析後端的英文 `why`**（03 §12.1 第 4 件已確認 `why` 都能由 `light`、`state`、`busy`、`queued`、`reason`、`active_at` 推出）。

| 後端 | 畫面 |
|---|---|
| running，不在一輪裡，信箱空 | 在跑・信箱空 |
| in a turn，N queued | 正在做一輪・排著 N 封（這輪做完才讀） |
| asleep | 睡著 |
| stopped normally | 正常停了 |
| crashed: exited with code 1 | 當掉（結束碼 1） |
| last activity N min ago／not recorded | N 分前有動靜／沒有動靜紀錄 |
| unknown | 不明 |
| REQUEST／PROGRESS／DONE／BLOCKED／FAILED／NEEDS-USER | 請求／進行中／做完了／卡住／失敗／要你出面 |
| agent／proc／external | 員工／程序／外部服務 |

- 認不得的詞照原文畫，加灰底，不藏、不猜。
- 原文放滑鼠提示，供對照 log。
- agent 自己寫的話（公告內容、最後一句、信件標題）是原文，一字不改，英文就英文。
- 相對時間只有一種寫法：剛剛、N 分前、N 小時前、昨天 HH:MM。

### 5.3 門檻（比 astra 用的再嚴一點）

| 項目 | 門檻 |
|---|---|
| 最小字 | 12 px。正文 14，次要 13，標籤 12。不再有 10、11 |
| 可點的東西 | 最小 28×28 px；主要按鈕高 32；相鄰兩個之間至少 4 px |
| 文字對比 | ≥ 4.5:1，包含淡色字、選中狀態上的字 |
| 圖示、框線、焦點框 | ≥ 3:1；焦點框 2 px |
| 顏色不單獨傳意思 | 燈旁邊一定有字或形狀（出事有「!」、推定是半滿）|

- 文字顏色只准三個 token（主、次、淡），底色四個（頁、欄、卡、選中）。3×4＝12 組對比寫成一條單元測試，不過就不能 build。
- 上一張／下一張的箭頭（現在 4×16）改成 28×28 的按鈕。模式鈕（現在 40×20）改 28 高。

## 6. 鍵盤（第 6 題）

1. **選取永遠在畫面內。** 選取一變，就在一個地方（store 的選取訂閱）對那個元素做 `scrollIntoView({block:'nearest'})`。左欄、部門牆、右欄名單都走這一條，不各寫各的。地圖不捲，本來就在畫面內。
2. **地圖能用鍵盤走。** 每塊名牌和房間標題都是按鈕。整張地圖只佔一個 Tab 位（roving tabindex）。方向鍵＝往那個方向最近的一塊（用矩形算，純函式、可測）；Enter 進房間；Backspace 回上一層。
3. **Tab 換區**：左欄 → 中欄 → 右欄內容 → 打字框。每區一個 Tab 位，區內用方向鍵或 j／k。
4. **點卡片上任何地方都算選**，包括公告小籤（astra C3）。小籤不另外接點擊。
5. 新增的鍵：`[` `]` 收左右欄；`?` 鍵盤說明；Alt+S／M／O 換打字模式；Ctrl+K 的動詞。其餘照 02c §4.8 和 03 §12.8 第 4 條，不變。
6. Esc 的順序照舊：彈出物 → 打字框（有字只離開、不清）→ 取消選取。**任何時候 Esc 都不丟字。**

## 7. v1 的去留（第 7 題）

- **v1 只修一條**：說話框有字時按 Esc，只離開輸入框、不關側欄；關側欄時把字按對象存在 sessionStorage，再開還在。約十行。
- **其他都不修**（地圖窄、看不到公告、名字要捲）。這些是版型問題，修＝重做，而重做就是 v2。
- v1 頁首加一行：「新版在 8768」。
- 第一期上線、使用者用過說可以之後，建議對調：8767 給新版，舊版搬到 8769 留一週再收（要問，§10 U3）。

## 11. 給 opus 深化時要注意的

1. `layoutMap` 是第一期風險最大的一塊。先寫純函式和測試（放得下、不重疊、有事的人不低於 D1、同樣的輸入同樣的輸出），再接畫面。等 B1～B3 的數字回來再定四級的尺寸。
2. 右欄 grid 那四列是第一期最便宜、最有感的一步，可以先做先上。
3. `words.ts` 需要 tree 節點帶齊結構化欄位。先查 `/api/tree` 是不是每個欄位都有；缺的才補後端。

5. 決定單變分頁後，`dismissed`（先跳過）和「背景更新不換題」（03 §12.8 第 13 條的 8、9）兩條驗收要重跑。
6. 中欄寬度會變四種，牆的欄數用容器寬算（container query 或 ResizeObserver），不用視窗寬。
7. 本稿沒有動的：網址記位置、草稿、seen、輪詢、CSRF、只聽 127.0.0.1、沒有 stop／rm／push 的按鈕、字串當純文字畫。
