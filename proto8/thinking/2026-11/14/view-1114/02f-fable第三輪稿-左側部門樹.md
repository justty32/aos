## 1. 待辦清單放哪

### 1.1 決定

**左欄＝樹（上，會伸縮）＋「等你處理」（下，釘住，最多 4 列）。完整清單開在中欄。**

理由：

1. 使用者要的是「左邊一棵樹」。樹要常駐才像 NERDTree；跟清單共用分頁就變成一次只能看一個。
2. 待辦的標題在窄欄本來就讀不完（340 寬仍有 29% 被截，300 寬 82%，astra B7 量過）。搬到中欄（≥686 寬）一行寫得完。
3. 作答本來就在中欄（02e §2）。「清單 → 點一張 → 作答 → 送出回清單」都在同一塊，眼睛不用左右跑。
4. 首屏不能看不到急事，所以左下留「等你處理」；另外樹上每一列都有燈和數字（§2.2），頁首五個數字照舊。同一件事有三個地方看得到。

沒採用：

- **左欄兩個分頁「樹｜待辦」**：看樹時待辦不見，首屏看不到決定單的標題（A6 不過）。當第 9 題的選項 b。
- **左欄上下各半**：650 高時各剩 285，五組清單起手就要 452（02e §1.4），放不下。當選項 c。
- **清單放右欄**：選了人右欄就被佔走，清單又不見。

### 1.2 中欄的「待辦」檢視

- 工具列多一顆 `[待辦 7]`，跟 `[地圖]` `[牆]` 並排。現有的 `inbox/Inbox.tsx` 整個搬過來畫，三個分頁（待辦／追蹤／已處理）、五組、順序都不變；每張一行，寬的地方多出來的寫寄件人和時間。
- 進來的路：左下「全部 ▸」、頁首任何一個數字（只留那一組）、收起的窄條上的數字。
- 點藍色的那張＝進作答；點其他張＝選中那個人（右欄開他、樹上亮他），中欄不換。
- 首頁預設仍是地圖（02e 第 4 題不動）。

### 1.3 「等你處理」那一小塊

- 標題列 28：「等你處理 N　全部 ▸」。每張一列 32：圖示＋去掉開頭的名字＋標題，一行，尾巴省略。
- 列數上限：左欄高 ≥ 700 時 **4** 列，否則 **3** 列。事情比上限少就只佔那麼多；一件都沒有就只剩標題列，寫「沒有等你的事」。
- 列哪幾張（純函式）：先給「要你決定」「出事」「等你」這三組裡不空的各 1 張，剩下的列數照「要你決定 → 出事 → 等你 → 新回覆 → 等很久沒回」的順序補。
- 280 寬下標題多半會被截（算的，要量，B16）。接受：這塊是指路牌，全文在中欄清單和作答。

## 2. 樹

### 2.1 一列長什麼樣

列高 **28**（A7 的可點門檻就是 28）。一層縮 **14**。由左到右：

`縮排 14×層 ｜ 箭頭 16 ｜ 燈 14 ｜ 空 6 ｜ 名字（唯一會伸縮的）｜ 人數 ｜ 空 8 ｜ 數字章（靠右）`

- **部門列**＝這個部門的主管。箭頭 ▸／▾；名字粗體；後面灰字寫整個部門幾個人。
- **人的列**：箭頭的位置空著（名字才對得齊）。
- **名字去開頭**：同 02e §3.1 的第 1、2 條（照上一層的部門去開頭，換成 `·`；最上層寫全名）。放不下才在中間省略，滑過去有全名。
- **數字章**最多三顆，順序固定：🔵 要你決定、🔴 出事、✉ 新回覆。一顆 28 寬（圖示＋最多兩位數），是 0 就不畫。「等你」不另做章，用燈的樣子表示（同地圖的圖釘）。
- **收著的部門**：燈＝整個部門裡最糟的那盞；數字章＝整個部門加總。**打開的部門**：只算主管自己的，底下的人各自有。這樣收起來不會藏住壞消息。
- 點數字章＝把路徑打開、選中裡面第一個那種人。
- 選中的那列整列底色加左邊一條 3 px 的色條；滑過去淡底色。不畫 TUI 的豎線和 `+ |` 那種符號。

寬度的帳（算的）：固定的部分＝36＋14×層；三顆章＝3×28＋2×4＋空 8＝100。名字能用的寬＝258−36−14×層−100：

| 層 | 名字能用 | 夠不夠 |
|---:|---:|---|
| 0（最上層） | 122（部門再扣人數 24＝98） | 最上層全名最長 80.21（量過）→ 夠 |
| 1 | 108（部門 84） | 人最長 85.84 → 夠；今天的小組名（`·pilot` 等）遠短於 84 |
| 2 | 94 | 85.84 → 夠，餘 8 |
| 3 以上 | 80 以下 | 三顆章全亮時會省略；今天的樹沒有第 3 層 |

也就是今天的樹，就算每列三顆章都亮，被截的名字是 0 個。

### 2.2 順序、預設開合

- 一個部門裡：**小組在前、人在後**（各自照座位表）。這跟地圖相反（地圖是先人後房，為了排得密）；樹上小組是用來點的把手，埋在 15 個人下面就沒用了。
- 最上層：部門 → 散人 → 「機房 N」（一列，預設收著）。
- 欄頂的「全公司 41」不是樹的一列，是固定的：點它＝中欄回全公司地圖、取消選取。⊟＝全部收起。
- **第一次來**：最上層的部門都收著。**最上層只有一個部門時，它預設打開**（不然一打開只看到一列）。之後照使用者自己開合的，記在 `prefs`。
- 新出現的部門預設收著；不見了的從記錄裡拿掉。
- 純函式 `treeRows(樹, 打開的集合) → 每列（層、名字、燈、三個數字、是不是部門）`，可測。「有事」的三個布林值跟 `layoutMap` 用同一份（02e §8 第 8 條）。

### 2.3 點了會怎樣

| 動作 | 結果 |
|---|---|
| 點人的列 | 選中他；中欄換到**他所在的部門**（牆，卡片亮起並捲到看得見）；右欄開他（除非右欄被你收了） |
| 點部門的列 | 選中主管；中欄換到**這個部門**；右欄開主管。不改開合 |
| 點箭頭、或雙擊部門列 | 只開合，不改選取 |
| 在地圖或牆上點人 | 選中他；中欄不換；**樹把他上面的部門都打開、捲到看得見** |
| 中欄正在作答或看待辦清單時點樹 | 只選取、開右欄；中欄不換（答到一半不被搶走）。按 Esc 或 ✕ 回去後才是那個部門 |

- 「選取永遠在畫面內」照 02d §6 第 1 條那一個地方做，樹也走它。背景更新不動樹的捲動位置，除非選中的那列被擠出去。
- 為了讓選中的人看得見而打開的部門，也算使用者開的，照樣記住。

### 2.4 鍵盤（焦點不在打字框、不在作答時）

| 鍵 | 做什麼 |
|---|---|
| `j` `↓`／`k` `↑` | 樹上看得到的下一列／上一列（選取跟著走；中欄 150 ms 沒再按才換，連按不會閃） |
| `l` `→` | 收著的部門：打開。開著的部門：到第一個孩子。人：同 Enter |
| `h` `←` | 開著的部門：收起。其他：跳到上一層的部門 |
| `Enter` | 部門：開合。人：打開右欄（收著的話）並把游標放進打字框 |
| `[`／`]` | 收／開左欄、右欄（§4） |

`j` `k` 以後只有這一種順序（樹上看得到的列）。牆上的卡片跟著亮，不另外有一套順序。地圖的方向鍵照舊是第二期。

## 3. 右欄

內容不變（02e §1.3）。只改什麼時候出現：**有選人、而且使用者沒把它收起來**才顯示。使用者收起後，再選別人不會自己彈開；按 `]`、按 Enter、或按中欄工具列右端的「‹ 某某」才開。
