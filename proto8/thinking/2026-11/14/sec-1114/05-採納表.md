## (A) 審查

| # | Argon 說 | 採納 | 怎麼處理／理由 |
|---|---|---|---|
| A1 | Q9-1 在家目錄給 `--x`，等於讓所有 subuid 透過 other 位讀到家目錄裡所有 644 的檔（`.claude.json`、`.gitconfig`、repo…）；`~/aos-home` 底下也一樣，而 daemon 新建的檔還是 umask 022 | **採** | Q9 拿掉選項 1。改推「私有 mount ns 綁定」（E10 實測過），退路是「樹搬到家目錄外」。安全模式下 daemon 與 aos 工具一律 `umask 077`，再加上整棵樹 `o-rwx`，寫進第 3 期 |
| A2 | 預設 ACL 擋不住 `0600`、`chmod`：mask 被壓成 `---`，使用者會被鎖在外面；寄件人能做出刪不掉的毒信 | **採（改說法）** | E7 證實會被鎖、毒信成立；但內圈用 `aos-asuser --fix` 救得回，不是「永久」。處理：(1) 計劃不再寫「預設 ACL 保證使用者照樣能改」，改成「保證刪得掉、救得回」；(2) 信箱改成單檔投遞，或 daemon 遇到 `EACCES` 的壞信自動 `--fix` 後隔離（見 B1）；(3) 加一支 `aos-share repair`（用 `--fix` 之類的方式重鋪） |
| A3 | 「信夾的 Linux 擁有者＝真寄件人」不成立：收件人能原地改寫、`st_uid` 不變；ns 裡看別人是 65534；轉寄後只代表上一站；中圈讀不到專區 `done/` 也就跑不了 L1 verify | **採** | Q4 改寫：只有在「收件人對信沒有 `w`」（B1 單檔＋唯讀預設 ACL）時，st_uid 才算數，而且只能在內圈（主 ns）讀；它只代表「最後一站」。專區假回信的洞照 P7 等 L2 簽章，不拿 st_uid 頂替。中圈要驗專區回信＝等 L2 |
| A4 | (1) `sub:N` 裡跑的 sandbox 不能帶 `user`，巢狀 bwrap 也不行；(2) `uid_range` 從 1 開始，在 ns 裡會撞到 `/etc/passwd` 的系統帳號或找不到 | **(1) 部分採、(2) 採** | (1) E8：不帶 `user` 的 bwrap 可行（巢狀 user ns 沒問題）；帶 `user` 的確不行。規則改成：中圈裡叫 sandbox 時 `user` 欄必須空著，有寫就拒起；要換 uid 由最外層的 daemon 一次換好。(2) 號段改到避開系統帳號（預設從 10001 起），並且 aos-asuser／daemon 換 uid 時一定要給 `HOME`、`USER`、`LOGNAME`；`getpwuid` 找不到的程式（`getpass`、`ssh`）在第 0 期列一張清單 |
| A5 | (1) 第 1 期對 `~/aos-home` 做 `o-rwx` 會弄壞 aos-run（B6）；(2) `.env` 收成 600 排在換 uid 之前，換了 uid 的 agent 會讀不到 `.env`、一啟動就壞 | **(1) 不採、(2) 採** | (1) 家目錄本來就是 700，aos-run 本來就進不了 `~/aos-home`（ok-limits 11:10 驗收時就是因此把檔放 `/srv/aos-run`）；`o-rwx` 不改變它。(2) 對：`.env` 是 aos-exec 在換 uid 之後讀的。改法：第 1 期只收緊「確定只有內圈會讀」的秘密（使用者專區 token、MCP token、`exec.json`）；定義夾的 `.env` 跟「這隻改走內圈 LLM kernel、不拿 key」綁在同一期（第 2 期）、同一隻 agent 一起做 |
| A6 | pid＋啟動時間只修得到 adopt，修不到 sweeper（孤兒孫行程不在表上） | **採** | sweeper 改看 `/proc/<pid>/status` 的 `Uid`／`Gid`（人人可讀、`env -i` 洗不掉），對到 daemon 的號段或群組才清。第 1 期 1d 改寫 |
| A7 | 換了 uid 的 eca 若由使用者的 tmux server 開格子，格子裡的行程是 tmux server 的子行程，不歸 daemon 管（rlimit、cgroup、訊號都管不到）；另一種接法 `cli_cell.py` 的 uid 檢查與 tmux 的連線檢查都會擋 | **採** | E3 只證明「畫面能用」，沒處理「歸誰管」。第 5 期改成：daemon 在那隻 agent 的 uid／cgroup 裡起它自己的 tmux server，使用者用 `aos-agent attach` 接（內部 `aos-asuser sub:N -- tmux -S … attach`）；這要在第 5 期前再試一次（E3b） |

## (B) 提案

| # | Argon 提 | 採納 | 怎麼處理／理由 |
|---|---|---|---|
| B1 | 信改成單一檔案投遞，信箱預設 ACL 只給收件人與使用者 `r--`：毒信刪得掉、st_uid 不能改、不用跨 ns chown | **採為推薦，要使用者拍板；與使用者 11-14「不要修改到aos-post這個基礎程式」衝突，待定** | 刪單檔只看父夾權限，這是對的；也一次解掉 A2、A3、D3。但這會改 aos-post 的信件格式（信夾→信檔），而且有附件的信要另外想辦法。列成新題 Q10，施工歸 aos-post 那條線，排在第 2 期前 |
| B2 | `sub:N` 開私有 mount ns 綁定樹的路徑，家目錄不打洞；給每隻 agent 一個 `<stack>/home` 當 `HOME`，加上 `XDG_*`、git 設定 | **採** | E10 實測成立。另外要解決「路徑跟外面不一樣」的問題：用 bwrap 那種做法，在 ns 裡把 `/home/<使用者>` 蓋成只放樹的 tmpfs，路徑就能跟外面一樣（E11，待試）。`<stack>/home` 也一起解掉 A4 第 2 點的 HOME 問題 |
| B3 | LLM kernel 不必一人一個投遞口，直接讀請求信的 st_uid 記帳 | **採（有條件）** | 寄件人建的信夾或信檔，st_uid 就是寄件人，它自己改不了；LLM kernel 在內圈、看得到真號。前提是收件那頭沒有別人有 `w`（kernel 信箱只有內圈收）。03 原本的 D7 改成這個，比一人一口簡單 |
| B4 | adopt 用 pid＋啟動時間＋Uid；sweeper 用 Uid／Gid；停一隻 agent 時用 `aos-asuser sub:N -- kill -9 -1` 一次殺光 | **採** | `kill -1` 是用那個 uid 殺它名下所有行程，一隻一個 uid 時正好等於「這隻全殺」，沒開 cgroup 也做得到；但同一個真號只能有一隻（A9 的號段登記要先做）。第 2 期 |
| B5 | 第 0 期補 E3-full、E7、E8、E9 | **E7、E8 已做；E3b 採；E9 不採** | E9 第 1 項在 A5 已經用事實排除（家目錄 700）；第 2 項已經改成跟第 2 期綁在一起。E3b 放到第 5 期前 |
| B6 | 分期重切：第 1 期底座、第 2 期換 uid 連同環境與金鑰、第 3 期整台開並合併額度、第 4 期 L2 簽章與 eca | **大致採** | 03 第四節照這個重排，差別有兩處：(1) 第 1 期「write／edit 擋跨界 symlink」轉給 ok-onboard，不放本線；(2) 「sandbox 設定壞掉拒起」要先問使用者（Q11） |
