## 四、現況備料（sol 原文，未改寫）

### 4.1 limits、沙箱、asuser／share、sbroot、setgid 坑、施工中（ok-sec-sol-1）

A. limits 與 limits_max

- 五個數字鍵：`mem_mb`＝AS＋DATA、`cpu_s`＝CPU 秒、`procs`＝整個 uid 的行程數、`file_mb`＝單檔大小、`files`＝開檔數；`user` 是本機帳號名，切換附屬群組、主群組與 uid。來源：`proto8/impls/aos-daemon/docs/09-份額.md:14`
- 定義宣告的 `limits` 由 `aos-agent ctl add` 讀取；`--limits JSON` 整份覆蓋宣告；daemon.json 頂層另設預設。列上 `{}`／null 用預設，非空數字份額整份取代；預設 user 是例外，列沒寫就補上。來源：`proto8/cmd/aos-agent/aos_agent/ctl/add.py:108`、`proto8/impls/aos-daemon/docs/09-份額.md:13`、`proto8/impls/aos-daemon/docs/09-份額.md:15`
- daemon 在 fork 子行程內直接 `setrlimit`，不執行 s6；CPU hard 通常為 soft＋1。sandbox 才執行 `s6-softlimit`；限制 daemon 本身則由啟動方包 `prlimit`／`ulimit`／sandbox。來源：`proto8/impls/aos-daemon/docs/09-份額.md:14`、`proto8/impls/aos-daemon/docs/09-份額.md:17`、`proto8/impls/aos-daemon/docs/09-份額.md:36`
- daemon 的 `limits_max` 只收數字鍵：超過或缺鍵就拒起該列；kernel 站的 `limits.{default,max,by_sender}` 則先補預設、夾上限，並依 `users`／`groups` 填身分。來源：`proto8/impls/aos-daemon/docs/09-份額.md:16`、`proto8/lib/aos/kernel/README.md:81`

B. aos-sandbox

- 使用 bubblewrap：`--unshare-all --die-with-parent`，預設斷網；系統底唯讀，ro／rw 深層綁定優先，根目錄唯讀，另建 `/proc`、`/dev`、空白可寫 `/tmp`。`/home` 未列入綁定就不可見，但不是禁止明列。來源：`proto8/cmd/aos-sandbox/bin/aos-sandbox:249`、`proto8/cmd/aos-sandbox/README.md:27`、`proto8/cmd/aos-sandbox/README.md:39`
- 接在呼叫方 argv：`["aos-sandbox","sandbox.json","aos-exec","inner"]`；不是函數自行宣告就受到強制。agent 範例開放工作區、自己的 stack、LLM requests 信箱。來源：`proto8/cmd/aos-sandbox/README.md:52`、`proto8/cmd/aos-sandbox/examples/agent.json#/rw`
- 預設清環境後只帶白名單，含 AOS 路徑字串、不含 API key；設定所在整個資料夾會自動可見，預設 `/etc` 也唯讀可見。來源：`proto8/cmd/aos-sandbox/README.md:27`、`proto8/cmd/aos-sandbox/README.md:33`、`proto8/cmd/aos-sandbox/README.md:41`

C. aos-asuser 與 aos-share

- `aos-asuser [--group sub:G] sub:N -- PROG ARGS...`：子行程開 user namespace，父行程執行 newuidmap／newgidmap；清附屬群組後換身分。N＝1～60000、G＝1～65536，預設 G＝N；真 uid/gid＝目前使用者 subid 起點＋N/G－1。來源：`proto8/cmd/aos-asuser/README.md:5`、`proto8/cmd/aos-asuser/README.md:12`
- `aos-asuser --fix [--recursive] PATH...` 救回 subuid 檔案所有權及擁有者讀寫權；不跟符號連結。sandbox 的 `user:"sub:5"` 會接 `aos-asuser --env-all sub:5 --`，驗收寫出真擁有者 `100004:100004`。來源：`proto8/cmd/aos-asuser/README.md:19`、`proto8/cmd/aos-sandbox/README.md:26`、`proto8/thinking/2026-11/14/kernel-limits-1114.md:149`
- `aos-share KIND PATH (--group G|--uid U)...` 設 ACL、不切 uid；team/read/work/drop 用群組，key/stack 用 uid。六種命令形狀為 `aos-share team|read|work|drop PATH --group sub:G`、`aos-share key|stack PATH --uid sub:U`；read/key 可重複旗標，純數字直接當真號。來源：`proto8/cmd/aos-share/README.md:5`、`proto8/cmd/aos-share/README.md:11`、`proto8/cmd/aos-share/README.md:15`

### 4.2 kernel 樹與 kernel_gate（誰能對誰下指令、寄信）（ok-sec-sol-2）

結論：kernel 樹是請求路由與排程鏈，不是寄件人身分驗證邊界；能否繞過 gate，現有規則明定靠 Linux 檔案權限。來源：proto8/kernel/docs/02-kernel-modes.md:47

A. kernel 樹與控制流程

- daemon 啟動子 proc 時設定 AOS_STACK 與 AOS_DAEMON；巢狀 daemon 從繼承的 AOS_DAEMON 記錄上一層，再把自己的位置交給子項。這是 daemon 父子關係；kernel 請求鏈則由收件路徑決定。來源：proto8/impls/aos-daemon/src/child/child.cpp:62；proto8/impls/aos-daemon/src/daemon/daemon.cpp:180；/home/lorkhan/aos-home/knowledge/aos/kernel.json#what
- 掛載、移除、起停、睡醒請求由 aos-agent ctl 寄到 AOS_KERNEL；未設時寄 daemon ctl 箱。站放行後依 next → 自己環境的 AOS_KERNEL（指到本站則跳過）→ AOS_DAEMON 的 ctl 箱轉寄。來源：proto8/py/daemon_ctl/post.py:28；proto8/lib/aos/kernel/procs_rules.py:87
- kernel_gate 在 agent 的 hooks/kernel_gate/ 建站，以 on_clock 執行；預設先套規則，通過者 hold，agent 寫 pass／refuse，由站轉寄或拒信。來源：proto8/lib/agent/kernel_gate/_entry:5；proto8/lib/agent/kernel_gate/_entry:45；proto8/lib/agent/kernel_gate/_entry:109

B. 誰驗寄件人、能否繞過

- daemon 不驗呼叫者是否為目標 proc 的父親或 kernel；收信的關鍵程式是「bad = c.ok ? apply_letter(c.letter["body"]) ...」，apply_letter 只收 body、驗形狀並修改名單。來源：proto8/impls/aos-daemon/src/daemon/mailbox.cpp:90；proto8/impls/aos-daemon/src/daemon/mailbox.cpp:109
- 信封驗證只要求 sender、sent_at 是字串等結構條件，沒有比對 uid、檔案擁有者或實際寄件程序；gate 畫面的 from 也是直接取「letter.get("sender")」，不是驗過的身分。來源：proto8/impls/aos-post/src/take/take.cpp:69；proto8/lib/agent/kernel_gate/gate_lib.py:120
- 可直寫 daemon ctl 箱者能跳過 gate；aos-daemon-ctl 的實作直接呼叫「dc.send(d, body, box, direct=True)」。文件明說同帳號且未另設權限擋不住，也不設 daemon 寄件人白名單。來源：proto8/cmd/aos-daemon-ctl/bin/aos-daemon-ctl:449；proto8/kernel/docs/02-kernel-modes.md:52

C. 誰能寄給誰

- mailbox_send 固定包裝層的 from 為自己的名稱，但可指定 agent 名稱、另一台 daemon，或直接指定 box；底層 aos-mailbox 的 --from 本來就是可填字串。寄送流程驗收件位置、status、title、what，未見收件人授權清單或寄信配額。來源：proto8/lib/agent/mailbox_send/_entry:44；proto8/cmd/aos-mailbox/aos_mailbox/__init__.py:310；proto8/cmd/aos-mailbox/aos_mailbox/__init__.py:337
- aos-post 寄送檢查 tmp/、new/ 存在且「access(p.c_str(), W_OK | X_OK)」通過，然後寫 letter.json、rename 進 new/；此流程沒有寄件人白名單或數量配額。來源：proto8/impls/aos-post/src/send/send.cpp:120；proto8/impls/aos-post/src/send/send.cpp:193

D. procs_state_path

- 請求為 {"procs_state_path": true}；daemon 回自己公開表的絕對路徑，未開該窗則回 null；這條 daemon 路徑未按寄件人篩選資料。來源：proto8/impls/aos-daemon/src/daemon/mailbox.cpp:184
- 設 AOS_KERNEL 且未明給 --daemon 時，工具先問路徑再讀表；逾時報 KernelFailed、不退回讀 AOS_DAEMON。明給 --daemon 則直接讀指定 daemon 的表。來源：proto8/py/daemon_ctl/state_path.py:59；proto8/py/daemon_ctl/state_path.py:87

## 五、opus 補的重點（從上面四份抽出、給設計者先看）

1. **今天所有東西都在同一個 uid（lorkhan）**：stack、信箱、工作區、knowledge、repo、使用者專區都是 umask 022 建的（多半 755／644）；信箱目錄甚至 `mkdir 0777`（再被 umask 收）。同 uid 下，任何會開 shell 的 agent 都能寫任何人的信箱、daemon ctl 箱、別人的 stack（含 tools.json、hooks.json、history），讀所有 `.env`、token 檔，也能 kill 任何 aos 行程。
2. **程式裡的「權限」全是約定**：kernel_gate、`allowed`、`max_running`、`max_subagents`、`budget.senders` 都是站內程式檢查，信封 `sender` 不驗；直寫 ctl 箱或 `aos-daemon-ctl` 就繞過（P1 已承認）。
3. **工具清單不是沙箱**：檔案工具接受工作區外的絕對路徑；shell 工具 `bash -c`、不濾環境；eca-claude 範本 dontAsk＋預先允許 Write/Edit/Bash、沒沙箱旗標。agent 的能力上限＝它所在 uid 的能力。
4. **換 uid 的路已經有三條，但還沒接成體系**：(a) daemon `limits.user`＝真帳號，要 root daemon；(b) `sub:N`＝subuid＋user ns，免 root，aos-asuser 有了，daemon 端（段 3）還沒做；(c) aos-sandbox `user: aos-run`＝sudo 一條 NOPASSWD 規則（B6 施工中）。stack ACL 自動化（G6）還沒做。
5. **跨 uid 的接點**：信是「寄件人在收件夾 `tmp/` 建子夾、寫 `letter.json`、rename 到 `new/`」，收件人 `new→cur`。跨 uid 後要靠收件夾的群組／ACL（aos-share `drop` 樣板：1730＋預設 ACL）；讀信要內容可讀。adopt 讀 `/proc/<pid>/environ`，讀不到竟回 true（`adopt.cpp:54`）；daemon 按 pid／程序群組送訊號；tmux socket 檢查 `st_uid == getuid()`。
6. **eca 身保持 1000**（段 3 驗收第 6 條「eca 身保持 1000，畫面照開得起來」）——也就是最強的那類 agent（Claude Code，有自己的 Bash）恰好沒被隔離。
7. **秘密**：API key 走環境變數（llm_http 拒 `endpoint.key`）；`.env` 在定義夾；ctl add `--envs` 會明文寫進 `exec.json`；MCP token 檔「兩條路都不檢查權限」。
