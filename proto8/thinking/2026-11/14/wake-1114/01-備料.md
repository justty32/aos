## 程式路徑（sol-1）

- **一輪怎麼跑**：aos-loop 叫 `aos-eca-turn`（`templates/eca-claude/loop.json`）。
  - 它認領整批信，跑 before_queue，再呼叫 `cli_ask.ask`。
  - 畫面沒開時走 `print_claude`：`claude -p --output-format stream-json --verbose … (--resume SID | --session-id 新的)`。
  - 純文字題目寫進 stdin 後**就關掉 stdin**，接著只讀 stdout，等它結束（`lib/agent/cli_print.py:70`、`:113`）。
- **「沒畫面」怎麼判斷**：看 `tmux has-session` 有沒有那個 session，不看有沒有人接著。所以 detached 的畫面也算畫面（`lib/agent/cli_cell.py:135`）。
- **一輪在跑時**：沒畫面那條路完全不再讀 queue。`more` 雖然傳進了 `ask`，卻沒有傳給 `print_claude`（`cli_ask.py:177`）。
  - 只有畫面那條路（`live_a2a`，每 0.2 秒一圈）會中途叫 `midturn.More.take()`。
  - 而且要等第一批信拿到回執之後才開始叫。
- **節奏**：
  - 300 ms 是「上一輪做完到下一輪開始」的間隔。
  - CLI 逾時 600 秒（cli.json，從題目交出去之後才開始算）；整輪 exec 逾時 900 秒。
  - 冷卻依序是 30、60、120、240、480、900、1800 秒，之後固定 1800 秒（`lib/agent/cooldown.py:19`）。
  - 冷卻中，這一輪不認領信，直接退 0；但 on_clock hook 會先跑。冷卻剛到期那一輪只試一封信，那一輪也不給 More（`turn.py:27`、`:79`）。
- **交出去就算收信**：題目一寫進 stdin，每封信各接一行 user 進 history，然後 `aos-post done`。之後才失敗的話，信不會重送（`handoff.py:17`、`:57`）。
  - 失敗會寫冷卻，再退 1，aos-loop 就停了。冷卻是等重起之後才起作用（`__init__.py:109`、aos-loop docs 02-窗:30）。
- **回答**：取最後一個帶 result 的事件，只接一行 assistant 進 history（`cli_print.py:134`）。
- **Claude Code 的 hook**：
  - 沒畫面時，aos 只掛一個 PreToolUse 的 guard（擋 CLI 子 agent 叫主 agent 的 aos 工具）。
  - 畫面開著時才另外掛 SessionStart、UserPromptSubmit、Stop，並加上 crossSessionInbound accept（`cli_screen.py:62`）。
- **screen_linger**：只在 loop 起和停的時候觸發，只處理已經開著的畫面，預設 600 秒後關。不會替沒畫面的 eca 留住 socket（`lib/agent/cli_linger.py:105`）。
