# 多庫設計：假裝頂層還是一個庫（fable 代定，可翻案；方案 A／B 是 [README 題 1](README.md#要使用者裁的白話推薦放第一)）

使用者：「後續可以修改這個memory工具，讓他可以接多個庫，只是假裝頂層還是一個庫」「資料夾、子資料夾、檔案，本來就是一種資料庫、記憶庫」「隨意複製，隨意修改，隨意給agent指定、隨意拆卸增添」。

## 方案 A（推薦）：掛載表就是一個放捷徑的資料夾

```
~/kb/                         ← 這隻 agent 的「一個庫」：_memory.json 的 base 或 AOS_MEMORY 指這裡
├─ README.md                  ← 人寫：一行標題、一句摘要、「children 各是一個庫」
├─ aos -> /…/proto8/knowledge/aos        （出廠知識，唯讀：不配 memory_write 或 chmod）
├─ proj -> /…/myproj/kb                   （專案知識，共享）
└─ notes/                                （這隻自己寫的；真資料夾）
```

- **根**＝那個資料夾；**路徑第一段＝庫名**＝捷徑或資料夾的名字（照 `[a-z0-9_-]`）；`read /` 印人寫的 README＋目錄（每庫一行、摘要取各庫 README 第二句）——跟現在一字不改。
- **掛／卸**＝`ln -s`／`rm 捷徑`；**複製整套**＝`cp -a`（留捷徑）；**改名**＝改捷徑名；**不登記、沒有格式**。相對捷徑（`aos -> ../repo/proto8/knowledge/aos`）搬家一起搬就不斷。
- 要改的只有兩處（[05 W1](05-實作步驟草稿.md)）：
  1. `find`：`grep -r` → `grep -R`（跟捷徑；grep 碰到迴圈會警告並跳過，警告走 stderr、R10 原樣透出），命中檔的節點路徑**用 grep 印的路徑**（經捷徑的那條）對根算，不先 `realpath`——現在 `realpath` 後對根算會變 `../…` 被擋掉。
  2. `memory_export` 同一條（它已會判「捷徑繞回上層」）。
- **寫入**（memory_write）：路徑 `notes/x` 經定址落到真資料夾、暫存檔寫在真資料夾裡、鎖也 mkdir 在真資料夾（`aos-lock` 收到的是 `~/kb/notes/`，解開後就是那裡）。`add aos/...` 落到 `knowledge/aos`——沒配工具或沒權限就 `WriteFailed`，這就是「出廠庫唯讀」。
- **根層不能寫**：`add x`（在 `~/kb/` 直接建葉）要不要擋？不擋——根層的葉就是「這隻 agent 的散記」，跟 `notes/` 同級，沒必要多一條規則（C-56）。但 `rm aos`（拆捷徑）要擋嗎？`rm` 葉只 `unlink`、不跟捷徑，拆的是捷徑不是庫；資料夾節點沒有子節點才能刪、經捷徑的庫一定有子節點＝`ChildrenExist`，`recursive: true` 會進去刪**別人的庫**——所以 **`rm` 遇到捷徑一律只拆捷徑、不進去**（實作：`os.path.islink` 先判）。
- 同一節點兩個庫都有？不會：第一段就選了庫，庫內互不可見。兩個捷徑指同一個庫＝find 命中印兩次（兩個路徑都對）、自擔。

## 方案 B（可選、等 A 不夠時）：`_memory.json` 命名多根

`{"base": {"aos": "../../../../knowledge/aos", "proj": "/abs/kb", "notes": "notes"}}`（字串＝一個根照舊；物件＝多根，鍵名照 `[a-z0-9_-]`；不留舊格式相容也不需要——字串形狀本來就留著）。工具合成虛擬根：文＝固定一句英文「This knowledge base has N parts. Each child is one part.」＋目錄；第一段選庫；`find` 沒給 `path` 就逐庫跑再合併排序（上限 20 共用）；`ls /` 列庫名與各庫 README 摘要。寫入：`add`／`rm`／`edit` 在虛擬根層＝`PathBad`（掛載是設定、不是節點）。多約 60 行、全部在 `memory_fs.py`，三支工具不動。`AOS_MEMORY` **維持單一路徑**（冒號串會撞路徑裡的冒號、又得發明名字）。

**什麼時候才要 B**：定義要在 repo 裡寫死「這隻接哪幾庫」、又不想在定義裡放一個捷徑資料夾——其實 `tools/memory/` 包裝資料夾旁放一個 `kb/` 捷徑資料夾、`_memory.json` 指 `../kb` 就做到了。所以推薦先不做。

## 方案 A 與 B 的共同規則

- 一支 memory ＝ 一個根維持；要幾套就幾支（照舊）。
- 腦不能挑庫（參數沒有 `base`），只能用路徑第一段選（C-52）。
- memory、memory_write、memory_export 三支看同一個根（包裝資料夾的 `_memory.json` 各一份，`memory_write/_memory.json` 可以是指 `../memory/_memory.json` 的捷徑——兩個包裝資料夾同深度、相對路徑算出來一樣）。
- 根進 system prompt 的那段也是 `read /`，所以多庫目錄自動出現在每隻 agent 眼前，不另接線。
