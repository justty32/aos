# 寫入設計：工具 `memory_write`（fable 代定，可翻案）

## 一句話

**`memory_write` 跟 `memory` 同一套找根與定址，多三個會改檔的 op；每個 op 底下就是一個 Linux 動作（寫暫存再 rename、mkdir、rm），動作前後各一次 aos-lock。** 使用者：「依託檔案系統……ls/grep……包成 aos 函數」「上鎖，就是跟大家說，這個資料夾我正在修改。檔案的話就 rename 原子修改」。

放 `proto8/lib/agent/memory_write/`（三件套＋`--help`，lib 契約）。找根、定址、列子節點、讀標題摘要跟 memory 一字不差（共用模組 `memory_fs.py`，[05 W2](05-實作步驟草稿.md)）。

## 三個 op（stdin 一份 JSON）

| op | 參數 | 做什麼（磁碟動作） | 先決條件（不成立＝錯） |
|---|---|---|---|
| `add` | `path`、`text` | 在 `path` 建一個**葉**節點 `<父>/<名>.md`，內容＝`text`。父節點是葉（`父.md`）時先升級成資料夾：`mkdir 父/`、`rename 父.md → 父/README.md`（wf 四級成長：單檔長大變資料夾） | 父節點要在（`NodeMissing`，訊息附父的子節點名，跟 read 同句）；`path` 還沒有東西（資料夾、`.md`、`.json` 任一在＝`NodeExists`）；不能是根（`PathBad`）；`text` 合規（下節） |
| `edit` | `path`、`text` | 整段換掉節點的文：資料夾節點寫 `README.md`（沒有就建）、葉寫那個檔（`.json` 葉照 `.json` 寫） | 節點要在；不能是根（`PathBad root is read-only; a human edits it`）；`text` 合規 |
| `rm` | `path`、`recursive?`（預設 false） | 葉：`unlink`（捷徑只拆捷徑、不跟）。資料夾節點：沒有子節點＝整個資料夾（含 README）刪；有子節點＝`ChildrenExist`，`recursive: true` 才連子樹刪。刪資料夾＝先 `rename` 成同層 `.rm.<獨一無二>` 再 `rmtree`（讀的人看到的是「整個不見」，不是刪一半） | 節點要在；不能是根 |

- **為什麼只有整段 `edit`、沒有 append／patch**：一節 ≤ 2 KB，腦 `read` 完整段重寫最不會錯（json_edit 的經驗：局部改要先找位置，是小念頭的事）。要 append 的腦自己 read＋拼＋edit。
- **為什麼不做 `mv`**：改名＝`rm`＋`add`；資料夾改名會把子樹一起搬、跨捷徑／跨檔案系統不原子，第一刀不做，要時加一個 op（[05 W10](05-實作步驟草稿.md)）。
- **`add` 一律建 `.md`**：`.json` 葉是人寫的或 JSON 後端的事；要讓腦寫 `.json` 加 `kind: "json"`（等題 4）。
- **父節點要在、一次只長一層**：不 `mkdir -p`，打錯字不會長出一串空資料夾（`rules` 的「smallest change」）。

## `text` 的規矩（`TextBad`）

1. 是字串、UTF-8、≤ 8000 bytes（＝memory `read` 預設印的上限；超過＝「split into child nodes」）。
2. 第一行 `# 標題`（memory 的 `ls` 靠它印目錄）。摘要那行不強制，description 裡教。
3. 結尾補一個換行；CRLF 照寫（不替腦改字）。
4. `.json` 葉的 `edit`：`json.loads` 得過。

## 原子寫法（N-05、lib 規則 6；細節照 [04-續 實測](04-邊緣狀況-續.md#11-05-夜實測opus-邊緣員只在-scratchpad沒改-repo測的是-usrbingrep-gnu-312)改過）

- **寫檔**：目標先 `realpath`（葉是捷徑＝寫進真檔、暫存放真資料夾；不然 `os.replace` 會把捷徑換成一般檔），同一個資料夾裡 `mkstemp` 成 `.tmp.<亂數>`（**不帶節點名**，免得 255 上限撞到），目標已在就 `os.fchmod` 成原權限（`os.replace` 不保留、會變 0600），`fsync` 不做（跟 aos-tick 同級）。
  - `edit`＝`os.replace` 蓋過去（同一檔案系統內原子；讀的人看到整份舊或整份新，實測 40 萬次讀 0 次半截）。
  - `add`＝`os.link(暫存, 目標)` 再 unlink 暫存——**目標已在就 `FileExistsError`＝`NodeExists`**，連鎖都失效時也不會默默蓋掉別人剛建的同名節點。
- **升級葉→資料夾**（順序實測過，沒有空窗）：建 `.new.<亂數>/`、把 `父.md` 的內容寫成裡面的 `README.md`、新子節點也寫進去 → `rename .new.<亂數> → 父/` → `unlink 父.md`。rename 之後 `父/` 與 `父.md` 短暫並存、定址先找資料夾、內容已完整；反過來先 `mkdir 父/` 會讓空資料夾蓋住 `父.md`、中途當掉內容就永遠看不到。
- **刪資料夾節點**：先判 `islink`（捷徑只 `unlink`，`rmtree` 本來就拒絕捷徑）；真資料夾 `rename → .rm.<亂數>` 再 `rmtree`。
- **被 TERM／Ctrl-C**：先刪自己的 `.tmp.*`／`.new.*`、再 release 鎖、退 128＋N。崩掉留下的 `.tmp.*`／`.new.*`／`.rm.*`：`.` 開頭 memory 看不見；下一個拿到同一個資料夾鎖的 memory_write 順手刪掉超過 10 分鐘的。
- **段名長度**：memory_write 多一條 `PathBad`：段名 > 200 bytes（檔名上限 255，留給 `.md`、`.lock`）。memory 讀不限。

## 鎖協議（使用者裁題 2 的落實）

| 事 | 定法 |
|---|---|
| 鎖什麼 | **要改目錄項的那個資料夾**：`add`／`rm` 鎖父資料夾（升級時鎖祖父，因為動的是 `父.md`）、`edit` 鎖節點所在資料夾（資料夾節點＝它自己）。鎖名牌 `--note "memory_write <op> <path>"` |
| 怎麼鎖 | `aos-lock acquire --wait-ms 3000 --lease-ms 10000 <資料夾>/`（鎖落在 `<資料夾>/.lock/`，`.` 開頭＝memory 看不見；經捷徑的路徑鎖落在**真資料夾**，實測）；寫完 `aos-lock release`（release 失敗只 `warning`，不算錯——鎖資料夾可能被別人的 rm 一起搬走）。**由 Python `subprocess` 直接叫、不經 shell**：aos-lock 的名牌 pid 預設＝叫它的行程，經 `sh -c` 的話 sh 一退鎖就被當死的收走（實測）。aos-lock 在 PATH 上（install.sh 裝的；沒有＝`LaunchFailed`） |
| 拿不到 | 等 3 秒還拿不到＝`LockFailed … held by <holder> (<note>); try again later`，退 1。腦照 `errors`：Failed＝稍後重試一次 |
| 範圍 | 只擋同一個資料夾的目錄項互踩（兩個 add 同名、add 撞 rm）。兩個 agent 改**不同**資料夾互不等；兩回合之間別人改了同一節＝後寫的贏（自擔）。`recursive` rm 前掃一遍子樹有沒有別人的 `.lock/`（活的）＝`LockFailed`，不刪人家正在改的 |
| 讀不鎖 | memory 照舊；rename 保證看到的是整份舊的或整份新的 |
| 人用 vim | 不鎖、自擔；要配合就 `aos-lock acquire 那個資料夾/` 再改 |
| no-pid | memory_write 不碰 pid；`--lease-ms 10000` 讓死鎖就算不看 pid 也 10 秒內能收。aos-lock 要改成純租約或請 daemon 轉接，只動 `memory_fs.with_lock()` 一處 |
