# 邊緣狀況（上）（鐵律 5：挖出來攤給使用者；沒回應＝天然差異或實作時自然解）

標記：**處理**＝設計已接住；**自擔**＝照裁題 2 自行承擔；**待裁**＝在 README 的題裡。

## 併發（多隻 agent 同一個共享資料夾）

| # | 狀況 | 怎麼辦 |
|---|---|---|
| 1 | 兩隻同時 `add` 同名節點 | **處理**：父資料夾鎖串行化，後到的看到 `NodeExists` |
| 2 | 一隻 `rm a`、另一隻正在 `add a/x` | **處理**：同鎖；誰先拿誰先做，後到的得到 `NodeMissing`／`ChildrenExist` |
| 3 | 兩隻各自 `read a/b` → 想一回合 → `edit a/b` | **自擔**：鎖只在單次呼叫內，後寫的贏、前者的改被蓋（lost update）。要避就裁題 2 的 `lock` op（W8），或教腦改前再 read 一次 |
| 4 | 一隻 `rm a recursive`，另一隻正在 `edit a/b/c` | **處理**：rm 先掃子樹有沒有活的 `.lock/`，有＝`LockFailed`；掃完到刪之間還是有空窗（自擔） |
| 5 | 讀的人正好在 rename 那一刻 | **處理**：POSIX rename 原子，看到整份舊或整份新；升級葉→資料夾走「先建好 `.new.*` 再 rename 再 unlink 舊葉」，每一刻 `read 父` 都是完整內容（實測；反過來先 mkdir 會有空窗） |
| 6 | 寫到一半被 kill -9 | **處理**：留 `.tmp.*`（memory 看不見）；鎖靠租約 10 秒／持有者死了被下一個人收；下一個拿到同資料夾鎖的 memory_write 刪 10 分鐘前的殘骸 |
| 7 | 20 隻同時寫同一資料夾 | **自擔／量小**：aos-lock 每 20 ms 輪詢、等 3 秒；超過＝`LockFailed`，腦照 errors「Failed 重試一次」；再不行就回報。知識庫不是信箱，寫入頻率不該高到這裡 |
| 8 | 人用 vim 直接改、不鎖 | **自擔**：使用者原話；要配合就手動 `aos-lock acquire 那個資料夾/` |
| 9 | 鎖的名牌 `holder`＝`$AOS_WS`：兩隻 agent 共用同一個 ws（agents 工具的子預設同父 ws） | 名牌分不出誰，但鎖本身仍互斥（pid 不同）；`--note` 寫 op 與路徑補辨識。no-pid 之後若 aos-lock 不看 pid，兩隻同 holder 會不會被當同一人直接過？**給 no-pid 規劃的人一條** |

## 檔案系統與捷徑

| # | 狀況 | 怎麼辦 |
|---|---|---|
| 10 | 捷徑庫在另一個檔案系統（NFS、另一顆碟） | **處理**：暫存檔寫在真資料夾裡、rename 不跨檔案系統；NFS 的 mkdir 鎖與 rename 語意弱＝自擔 |
| 11 | `rm` 到捷徑 | **處理**：只拆捷徑、不跟進去（`islink` 先判），`recursive` 也不進；拆捷徑＝卸庫，是可逆的檔案操作 |
| 12 | 捷徑斷了（庫搬走） | `read aos`＝`NodeMissing`（isdir 假）；`ls /` 仍列 `aos`？——`children()` 用 `isdir(full)`、斷捷徑＝假、**不列**，腦看不到那庫；人要看就 `ls -la`。可接受 |
| 13 | 捷徑迴圈（kb 裡放一條指回 kb） | **處理**：`grep -R` 會印 warning 跳過（R10 透出 stderr、stdout 不髒）；memory_export 已會印 `not followed`；`read` 走多深都是腦自己給的路徑 |
| 14 | 兩條捷徑指同一庫 | find 命中印兩次（兩路徑都真）；自擔 |
| 15 | 節點名撞：`a.md` 與 `a/` 都在、`a.md` 與 `a.json` 都在 | 讀照舊先資料夾再 `.md`；**`add a` 三者任一在＝`NodeExists`**，不讓腦建一個被遮住的檔 |
| 16 | 檔名超過 255 bytes、磁碟滿、唯讀掛載 | `WriteFailed` 附 errno 原文；腦看代號是 Failed＝不是它的參數錯 |
| 17 | `text` 很大（> 8000） | `TextBad … split into child nodes`；上限跟 read 預設印的一樣，腦寫得進就讀得回 |
| 18 | `text` 開頭不是 `# ` | `TextBad`（目錄會印不出標題）；摘要行不強制、知識庫節 `memory` 教 |
| 19 | 根 README 被 `edit /` | **處理**：`PathBad root is read-only`——根每回合進所有 agent 的 system prompt，一隻改錯全部中毒；人改 |
| 20 | 空資料夾節點（沒 README、沒子） | 合法：文空、`children: (none)`；`add` 子進去正常；`rm` 可刪 |
| 21 | `.lock/`、`.tmp.*`、`.rm.*` 進了 git | 庫若在 git 下，`.gitignore` 加這三個（W1 的 knowledge/README 一句） |
