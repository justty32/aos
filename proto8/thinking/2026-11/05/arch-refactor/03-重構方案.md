```
proto8/
├─ impls/        C／C++ 基礎層與標準庫（13 個專案，名字不動；加頂層 CMakeLists，見 § 3）
├─ cmd/          給人與外部程式用的命令列（Python／sh），一支一夾、夾名＝指令名、執行檔在 <名>/bin/<名>（跟 impls 的 <專案>/bin/<專案> 同形）：
│    aos-agent/（原 extras/agent，含 using-aos-agent.sh、stack.gitignore、docs/）  aos-daemon-ctl/  aos-tools/  aos-tick/
│    aos-eca/（aos-eca-turn、aos-eca-screen 兩支同夾）  aos-mcp/（原 ai_tools）  aos-sandbox/（含 root/、examples/）  aos-grow/
├─ py/           Python 共用模組一處：aos_flags.py、aos_ws.py、cli_session.py（tool_io.py 要不要一起搬，問 die 隊：工具「先找自己資料夾」那條與沙箱唯讀綁定是他們剛做的）
```

- 判準寫進 proto8/README：**impls＝aos-exec 跑得動的基礎與標準庫（C／C++）；cmd＝人在終端打的指令；lib＝腦叫的工具（三件套）；kernel＝掛在 daemon 上的管理元件；templates＝複製出去用的 agent 範本；extras＝還沒定位的嘗試**。
- 替代案（不推薦）：按 C-74 層名 `base/ std/ agent/` 重排——impls 內部本來就跨層（exec 是核心、loop／daemon 基礎層、fsm 標準庫），拆開會把一個 CMake 家族切成三夾，建置更麻煩。
- `impls/aos-json/tools/{json,json_edit}`（B7）：搬進 `lib/base/`、或併進 `json_read`／`json_edit`——等 lib 隊收工再動（他們正在改 lib）。

## 3. impls 建置：頂層一次建、單獨也能建（對 C1～C4；方向題 4）

- 新增 `impls/CMakeLists.txt`：`include(cmake/settings.cmake)`、`project(aos-impls C CXX)`、`option(AOS_IMPLS_ALL "build every bin" ON)`、照依賴序 `add_subdirectory` 13 個；新增 `impls/vcpkg.json`（nlohmann-json＋json-schema-validator 合併）。
