# 11-05 晚 接線（K1～K8、R1）

## 11-05 晚 代定（可翻案）

編號接 [README 代定](README.md#代定fable-照原則定可翻案細節在各分檔) 1～6。

7. **根怎麼進 system prompt＝叫腦之後會叫的同一支工具**：agent-fsm `brain.py --memory NAME`、外部 agent `aos-mcp --memory NAME`（eca 經 `cli.json` 的 `tools_flags`）都是「叫登記名 NAME 的工具 `{"op": "read"}`、印的東西原樣放進去」，不各自讀 `AOS_MEMORY`——腦看到的根跟它自己查的一定是同一個庫。工具清單裡沒有 NAME（這隻拿掉了 memory）＝不帶根。
8. **eca 不做開場白檔**（03 原稿 K3 是 `--prompt knowledge_root.txt`）：改走 K4 的 MCP `instructions`，每次開 CLI 都是當下的根、不用人產檔。codex 不保證讀 `instructions`，靠工具。
9. **根接在 `system.txt` 後面**（03 原稿寫「以根開頭」）：agent 自己的角色先、知識在後，同一則 system 訊息；agent-fsm 的 `system.txt` 改英文（跟知識庫同語言）。CONVENTION 只放草稿（[05-不管落實待決](../../../../docs/CONVENTION/05-不管落實待決.md)），編號等使用者定。
10. **失敗怎麼辦**：brain 叫 memory 失敗＝`agent-fsm: error: MemoryFailed` 停下（定義說要帶根就是要）；aos-mcp 失敗＝不給 `instructions`、只寫 warning（不讓整條 MCP 連線起不來）。
11. **R1 登記格 `env` 的值照字面、不當路徑解**（03 原稿寫「相對路徑相對登記檔」）：env 值不一定是路徑，照 C-56 寫什麼就做什麼；`AOS_MEMORY` 的相對照舊由 memory 自己解（相對 `$AOS_DAEMON`）。範本要便攜就用包裝資料夾＋`_memory.json`。`aos-tools add --env K=V` 寫得進覆蓋層；`aos-agent tools add` 還沒有 `--env`（另一隻工人在改那支，留給隊長）。
12. **包裝資料夾的 `_entry` 不能是捷徑**：實測 aos-exec 會解開 `_entry` 捷徑、`AOS_CD` 變 lib 那格、找不到 `_memory.json`；改成一行單子 `["../../../../lib/agent/memory/_entry"]`（01、knowledge/README、lib/docs/03 已改；`lib/agent/memory/_entry` 開頭註解還寫「三個捷徑」，留給隊長改）。
13. **K1 的範圍**：lib 底下所有有 `_tooldef.json` 的工具都改成英文（含 claude、codex、pyfix、check_inbox、llm_*），參數說明一起改；description ≤ 80 字、列工具自己的代號、只在 self_tools／agents／bash／run_python／llm_http 指節點。
14. **K6 另立 `lib/agent/memory_export`**（印整棵成一份 Markdown），memory 保持純查詢。

## 11-05 晚 結果

- K1、K2、K3、K4、K5、K6、K8、R1 做完；K7 沒做（03 寫明另派 fable 規劃）。
- 假腦（K5，`fake-demo-memory`）：fsm1 先 `memory read me/self_tools`、再 `self_tools add math`、`math 17*23`＝391，照劇本答完。
- 真腦（LM Studio `google/gemma-4-e4b`，掛 daemon 的 agent-fsm）：問「phase stopped 是什麼、該怎麼辦」，腦只叫一次 `memory read status` 就答對（看 reason、修因、人重開）；叫它加 `tools/math`，第一次漏 `name` 看錯誤行自己補上；遇到 `PathBad` 沒有迴圈、回報給人，換成真資料夾後一次加好並算出 391。
- aos-mcp `--memory memory`：initialize 回應帶 `instructions`（根原文），`--memory` 給不存在的名字＝只有 warning。真 Claude Code 讀不讀 `instructions` 沒實跑（要花錢）。
- 實測挖到的邊：工作區裡指向 lib 的相對捷徑被 `self_tools` 判 `PathBad … outside the workspace`（解開後在 lib、照規則該收），訊息會誤導；留給隊長看 self_tools。


## 11-05 晚 邊緣測試

- 登記格 `env` 的值含 NUL（手寫 `"\u0000"`）：`aos-tools call` 吐 ValueError traceback → 驗登記時就 RegistryBad。
- 登記格 `env` 的鍵結尾帶換行（`"X\n"`）被放過（正規式用 `$`）→ 改 `\Z`，RegistryBad／ArgumentsBad。
- `--env K=a=b`（值留 `a=b`）、`--env K=`（空值）、`=x`／`1X=x`（ArgumentsBad）、覆蓋層的 env 整格蓋過定義的、exe 型也帶上：都對，不用改。
- memory_export 碰到指回上層的捷徑：一路往下印到路徑太長（rc 0、內容重複）→ 記住這次印過的上層真實路徑，繞回的節點只印一行 `not followed`。memory 的 find 走 `grep -r`、不跟捷徑，沒事。
- aos-mcp `--memory`：跑起來之後登記檔壞了，initialize 整則回錯（外部 agent 連不上；不帶 `--memory` 時只有 tools/list 回錯）→ 叫 `aos-tools ls` 失敗也只寫 warning、不給 instructions。
- 沒修、列給隊長：agent-fsm `brain.py --memory` 叫 memory 沒有逾時（memory 卡住＝think 格卡住，靠 fsm 那格自己的逾時）。

## 11-05 夜 第二輪邊緣

- **修**（隊長推薦，可翻案）：`brain.py --memory` 叫 memory 加 30 秒逾時（`MEMORY_TIMEOUT_S`，寫死）：逾時整群 TERM→KILL、`agent-fsm: error: MemoryFailed … did not finish in 30 s (killed)`；實測假 memory `sleep 100` 30 秒退 1、沒留孤兒。
- **修**：`_memory.json` 在但不是檔（是資料夾、斷捷徑）原本被當「沒有」、默默改用 `AOS_MEMORY`（沒設就報誤導的「no _memory.json next to the tool」）→ memory、memory_export 改用 `lexists`，一律 `CfgBad`。
- `base` 指不存在、指檔案、指捷徑迴圈：`MemoryMissing … which is not a directory`；`_memory.json` 壞 JSON：`CfgBad`；空資料夾當庫：`node: /` 退 0——都對，不用改。
- 借給 thought 子的 memory 若靠登記格 `env` 配，env 會掉（見 [small-thought 第二輪](../small-thought/README.md#11-05-夜-第二輪邊緣)）；包裝資料夾配的沒事。
