# 層級式記憶工具 `memory`（fable 照原則定的細節，可翻案）

使用者 11-05 下午：「頂層可以是簡介、index目錄之類，並且盡量講簡單……agent有需要的話，再去透過工具……抽取更深一層的知識……層級式記憶工具？現在是查詢需求……這套知識庫還可以給多個agent共享！」。照 [wf/STRUCTURE 分層原則](../../../../../wf/STRUCTURE.md#分層原則)（每層只指向下一層、不存下層細節；README＝入口；膨脹即拆）落成一個 lib 工具。

## 一句話

**知識庫＝一個資料夾樹；每個節點是一段短文（md 或 json）＋它的子節點；工具 `memory` 只做三件事：`read` 一個節點（印它的文＋子節點目錄）、`ls` 列子節點、`find` 用關鍵字找節點。** agent 從根讀起，照目錄往下走，走到夠用為止。這輪只做查詢；增刪改另派 fable 規劃（位置與介面已預留，見末段）。

## 四條設計原則（使用者 11-05 下午定，見 [README 原文](README.md#使用者原文11-05-下午逐字依先後)）

1. **依託現成的檔案系統**：節點＝資料夾／檔，層＝目錄層級，README 慣例；不發明儲存格式、不開資料庫。
2. **查詢＝包現成指令**：`ls`＝`ls`、`read`＝`cat`／`head -c`、`find`＝`grep -ril`（`_entry` 真的叫 `grep`，argv 列表、不走 sh），全部限定在 `AOS_MEMORY` 根之下、唯讀、輸出截斷給小模型；不開放整個 shell。這三支就是記憶工具的基石，之後的增刪改也照這招包 `mkdir`／`mv`／`rm`。
3. **JSON 與檔案系統同像**：物件＝資料夾、key＝名字、值＝檔。節點路徑 `a/b` 跟 aos-json 的 `#/a/b` 指標同形（段名 `[a-z0-9_-]` 沒有 `/`、`~`，不用轉義），之後 `AOS_MEMORY` 指到一份 `.json` 時可以用 aos-json 當後端（體積／效能的另一種取捨；這版不做，留題 4）。
4. **內容格式不限、agent 好讀優先**：節點的文可以是 md、json（這版認這兩種；yaml 之後）；人類可讀性次要——人要看就問 agent，或之後做一支把知識庫（含 json）轉 markdown／html 的工具（[03 步驟](03-接進agent與工具說明.md)）。

## 知識庫在哪、怎麼指它（使用者 11-05 裁：便攜、隨意指定）

使用者裁題 1：「隨著repo出廠，不一定要走環境變數(現在可以先用這個，因為這個最方便)。最主要在於我希望這東西是便攜的，隨意複製，隨意修改，隨意給agent指定、隨意拆卸增添。」

- 任何資料夾都可以當記憶庫的根（使用者：「資料夾、子資料夾、檔案，本來就是一種資料庫、記憶庫」；C-68）；`memory` 指到哪個資料夾，那就是它的庫，**不登記**：複製、改、拆、併都是檔案操作；出廠的在 repo [`proto8/knowledge/`](../../../../knowledge/README.md)。**多隻 agent 共用**＝都指同一個資料夾。
- 工具找知識庫根的**優先序**（都是定義或人配的，腦不能挑——參數裡沒有 `base`，C-52）：
  1. **工具資料夾裡的 `_memory.json`**：`{"base": "<路徑>"}`，相對＝從那個資料夾算（跟 tools.json 的 path 一樣，相對登記它的檔）。「隨意給 agent 指定」就靠這個：定義的 `tools/memory/` 不做捷徑、做成一個小資料夾——`_tooldef.json`／`_metainfo.json` 捷徑指回 `lib/agent/memory/`、`_entry` 是一行單子 `["../../../../lib/agent/memory/_entry"]`，加一個真的 `_memory.json`。工具用 aos-exec 給的 `AOS_CD` 找這個檔〔11-05 晚實測：aos-exec 會解開 `_entry` 捷徑、`AOS_CD` 變成 lib 那格，所以 `_entry` 不能是捷徑、改成單子〕；捷徑整個指到 lib 的沒有設定檔、照舊走 ②。設定檔壞＝`CfgBad`。
  2. **環境變數 `AOS_MEMORY`**：跟 `AOS_LLM_KERNEL` 同一套（N-63 hub 型）：人 export，或寫進 daemon 定義的 `.env`（整台共用）、某隻定義的 `.env`（只它）；相對＝相對 `$AOS_DAEMON`，沒有＝cwd。現在最方便，先用這個。
  3. 都沒有＝`MemoryMissing`。
- **一支 memory 工具＝一個知識庫**（使用者裁題 3：「一個agent他所使用的memory工具，就是只指定一個知識庫。這樣最方便。」）。agent 要接好幾個：現在＝登記好幾支（`tools/memory_aos/`、`tools/memory_proj/` 各自一個 `_memory.json`）；**後續步驟**＝改 memory 讓 `base` 收多個根、假裝頂層還是一個庫（根的目錄把各庫列成子節點，路徑第一段選庫；[03 K7](03-接進agent與工具說明.md)）。
- 覆蓋層那條路（這隻 agent 在 stack 的 tools 覆蓋層裡換知識庫）要 aos-tools 的登記格多認一個 `env` 或 `args` 鍵——**不在本輪領地，寫成給新功能隊的請求**（[03](03-接進agent與工具說明.md#給新功能隊的請求本輪沒動他們的檔)）。
- 第一個知識庫：aos 體系知識 [`proto8/knowledge/aos/`](../../../../knowledge/README.md)（內容見 [02](02-aos知識庫.md)）。

## 節點與定址（代定 2）

| 事 | 定法 |
|---|---|
| 節點路徑 | `agents/spawn` 這種：段用 `/` 接、段名只能 `[a-z0-9_-]+`（C-54 全小寫底線）；`""` 或 `/`＝根。有 `.`、`..`、空段、其他字＝`PathBad` |
| 節點在磁碟上 | **資料夾節點** `<根>/<路徑>/`，它的文在裡面的 `README.md`（沒有＝文是空的，只有子節點）；**葉節點** `<根>/<路徑>.md` 或 `<路徑>.json`（兩個都在＝`.md` 優先；yaml 這版不認）。先找資料夾、再找葉，都沒有＝`NodeMissing`（訊息附父節點有哪些子節點，腦下一步就知道該讀哪個） |
| 子節點 | 資料夾裡的子資料夾＋`*.md`／`*.json`（`README.md` 以外），名字＝資料夾名／檔名去副檔名；`.`、`_` 開頭的不算（留給隱藏檔與之後的 metadata）；照名字排序 |
| 節點的文 | md：**第 1 行 `# 標題`**；**標題後第一個非空行＝一句話摘要**（`ls` 印在目錄裡）；之後才是本文。json：頂層物件的 `title`／`summary` 鍵（沒有＝標題用節點名、摘要空）；`read` 原樣印、不轉換。寫給小模型看：短句、具體指令、一致用詞 |
| 大小 | 一個節點的文以 **≤ 2 KB** 為目標（膨脹即拆成子節點，上層只留摘要＋目錄，STRUCTURE 觸發 A）；`read` 預設最多印 8000 bytes，超過截斷並附 `[truncated: N more bytes]` |

## 三個操作（代定 3）

stdin 一份 JSON（lib 契約規則 1）：`{"op": "read"|"ls"|"find", "path"?: "…", "query"?: "…", "max_bytes"?: N}`。stdout 純文字、英文、第一行一律 `node: <路徑>`（根印 `node: /`）。

| op | 做什麼 | 印什麼 |
|---|---|---|
| `read` | 讀一個節點（`path` 沒給＝根） | `node: 路徑`、空行、節點的文；有子節點再加空行、`children:`、每個子節點一行 `  <名>  <摘要>`（資料夾節點的名字後加 `/`）。腦看完就知道往哪走 |
| `ls` | 只列子節點 | `node: 路徑`、`children:`、同上一行一個；沒有子節點＝`children: (none)` |
| `find` | 在 `path`（沒給＝根）底下所有節點的標題、摘要、本文找 `query`（不分大小寫、子字串） | `node: 路徑`、`matches:`、每個命中的節點一行 `  <節點路徑>  <標題>`（照路徑排序、最多 20 個，再多印 `  … N more`）；沒命中＝`matches: (none)`。`query` 沒給或空＝`ArgumentsBad` |

- 唯讀：不寫任何檔、不碰 `$AOS_WS`（`_metainfo`：`side_effect` false、`idempotent` true、`parallel` true、`interrupt` safe、`resource` cpu、`time_ms` val 50／max 5000）。
- 錯：stderr 與 stdout 各一行 `memory: 代號 原因`、退 1（lib 契約規則 3）：`ArgumentsBad`（stdin 不是 JSON 物件、`op` 沒給、`max_bytes` 不是正整數）、`OpUnknown`、`PathBad`、`MemoryMissing`、`NodeMissing`、`ReadFailed`（檔在但讀不了、不是 UTF-8）。
- `_tooldef.json` 的 description 用英文、只寫增量、用知識庫的詞（[03](03-接進agent與工具說明.md)）：「Look things up in the shared knowledge base. Start with op read and no path (the root); the root tells you what exists. Then read the child you need. find searches by keyword.」。
- 檔案：`proto8/lib/agent/memory/{_entry,_tooldef.json,_metainfo.json}`，python3 純標準庫，照 lib 契約（`_entry` 第二行 `# memory - 一句話`；被 TERM 時直接退，沒有子行程）。放 `lib/agent/`（高層：給 agent 用的工具）；它不懂 aos 的任何東西，知識庫裡寫什麼它都照印——所以也放得進 `lib/base/`，代定放 `agent/`（它的用途是 agent 的記憶）。可翻案。

## 預留給增刪改（這輪不做，另派 fable）

- 同一套定址：`add {path, text}`（建 `.md` 葉；要有子節點時自己升成資料夾＋`README.md`——跟 wf 的四級成長同一招）、`edit {path, text}`、`rm {path}`。
- **鎖協議草稿**（使用者裁題 2：「自行承擔風險。但可以弄個協議，也就是要修改的話就放鎖，也不一定要整個庫一個鎖，搞不好也可以只鎖子庫。也可以善用linux權限」；再補：「嚴格來說，沒有庫、子庫之分，資料夾、子資料夾、檔案，本來就是一種資料庫、記憶庫。上鎖，就是跟大家說，這個資料夾我正在修改。檔案的話就rename原子修改(?)」；只記、不實作）：
  0. **沒有庫／子庫之分**：資料夾、子資料夾、檔案本來就是記憶庫；`memory` 指到哪個資料夾，那個資料夾就是它的根。下面只說「資料夾」「檔案」。
  1. 讀不鎖：`read`／`ls`／`find` 照現在，讀到一半被改＝自擔（跟 N-16 看窗一樣）。
  2. **鎖＝在某個資料夾上宣告「這個資料夾我正在改」**：任一層資料夾都可以鎖，用 `aos-lock`（已有）在 `<那個資料夾>/_lock/` 建鎖，名牌寫誰、何時；改完放掉。`_` 開頭＝不算節點，`ls` 看不到。
  3. 鎖的範圍＝那個資料夾往下；要改上層的檔（例如根的 README）就鎖上層那個資料夾。兩個寫者改不同資料夾互不等；改同一個＝後到的 `aos-lock` 等或 `LockBusy` 自己決定。
  4. **單一檔案不鎖**，改法＝同一個資料夾裡寫暫存檔（`.名字`）再 `rename` 蓋過去（aos-tick 同招）：POSIX 同一檔案系統內 `rename` 是原子的——使用者的問號答案是「對」；跨檔案系統不保證，暫存檔一定寫在同一個資料夾裡。讀的人看到的不是舊的就是新的，沒有半截。
  5. Linux 權限（C-64）當第二層：某個資料夾設成唯讀＝那些 agent 只能查；可寫的 agent 給那個資料夾寫權限。程式不驗身分、沒設權限＝自擔風險（跟 kernel-daemon「唯一能下 ctl」同一套）。
- **節點 metadata**：`_` 開頭保留（例 `_meta.json`：來源、更新時間）；現在不建。
