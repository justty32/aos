# 給你看的說明（ELI5）

## 做出來的是什麼

兩樣東西：

1. **一個記憶工具 `memory`**（[lib/agent/memory](../../../../lib/agent/memory/_entry)）。它只會三招：`read`（翻開一頁）、`ls`（看這頁底下有哪些子頁）、`find`（用關鍵字找頁）。它不知道 aos 是什麼，只是把一個資料夾當成一本有目錄的書，一頁一頁翻給 agent 看。底下真的就是 `ls`、`cat`、`grep`，鎖在知識庫那個資料夾裡，唯讀。
2. **第一本書：aos 體系知識**（[knowledge/aos](../../../../knowledge/aos/README.md)）。英文，給 Haiku、luna 這種小模型讀。

## 書長什麼樣

像 wf/ 的分層樹：**第一頁只講最少的**——aos 是什麼（一句）、八個詞各一行、五條規矩、怎麼往下翻。往下九頁各管一件事：世界觀、我是誰、改自己的工具、生子 agent、問腦、看狀態、讀錯誤、禁忌、給人用的指令表。每頁不到 2 KB，agent 一次只拿第一頁加它需要的那一兩頁，不會把整本塞進 context。

為什麼這樣寫：小模型最常犯的三個錯是「被拒了就一直重試」「改到不該改的檔」「看到錯誤不知道下一步」。所以每一頁講到代號都接「那你該做什麼」，第一頁和禁忌頁都反覆講「被拒是決定、不是 bug」。用詞固定（定義／stack／工作區／daemon／proc／kernel／信／工具），不換說法。

## 怎麼接到 agent

- **第一頁每次都給**：放進 agent 的 system prompt（給的是工具印出來的那頁，含目錄，跟它之後自己翻到的一樣）。
- **其餘靠它自己翻**：`memory` 登記成它的工具之一。
- **三種 agent**：aos 自己的 agent-fsm（brain.py 多讀一頁）、eca（開場白檔放第一頁、MCP 工具裡有 memory）、外面直接接 aos-mcp 的 Claude Code（aos-mcp 在 MCP 握手時把第一頁塞進 `instructions`，用戶端自己會放進 system prompt）。細節與步驟在 [03](03-接進agent與工具說明.md)——**要等新功能隊收工**才動他們的檔，這輪只新建了工具、書、說明。
- **哪本書**：環境變數 `AOS_MEMORY` 指知識庫資料夾，寫進 daemon 定義的 `.env` 就整台共用，跟 `AOS_LLM_KERNEL` 同一招。
- **工具說明瘦身**：各工具的 description 之後只寫「怎麼叫、哪一頁看細節」，不再各自解釋 daemon 是什麼。

## 小模型讀得懂嗎

有實測（[04](04-實測.md)）：九道情境題，Haiku 九題全對、每題翻 1～2 頁、九題合計不到 0.03 美金；luna 見 04。改前改後的差異：一開始 Haiku 照目錄抄 `me/`（尾巴有斜線）會被工具打回，浪費一次；現在工具認得尾巴的斜線。另外兩頁補了一句更直接的「該叫哪個工具」。

## 這只是開頭

你說的「層級式記憶工具」現在只有查詢。之後（另派 fable 規劃）：增刪改、多本書、JSON 當另一種存法（同一套路徑寫法 `a/b` ⇄ `#/a/b`）、把書轉成 markdown／html 給人看的工具。五題你傍晚已裁（便攜不登記、鎖協議只記、一支 memory＝一個庫、JSON 等大了、CONVENTION 先跑接線），結果在 [README 已定](README.md#已定使用者說的)。
