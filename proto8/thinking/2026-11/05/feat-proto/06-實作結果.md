## 代定總表（全部可翻案）

- **留給使用者的六題全照推薦實作**：題 1 撞 `fixed`＝`RequestBad`；題 2 包額度用完不降級、回 `BudgetMissing`；題 3 子 agent 的工作區＝父的 `AOS_WS`；題 4 判官 `max_running` 4（含父）、深度不另限；題 5 範本 agent-fsm 不內建 `self_tools`／`agents`，demo 用 `aos-agent tools add` 當場加；題 6 daemon 子行程自己 `setrlimit`（11-05 晚已做）。
- 01～05 各分檔的「代定」照寫的做，下面是實作時才定的細節：
  - **`$ref` 一包獨立成檔寫 `"packs/x.json"`、不帶 `#/`**（RFC 6901 的 `#/` 是「key 為空字串」）；包的 `budget` 只收 `max_calls`／`max_tokens`，寫 `window`／`spent`＝`CfgBad`（窗同 kernel 的）；`request.model` 只在那包有 `model` 時才擋（`fake` 照收）。
  - `budget.senders` 的 key 相對路徑從 kernel.json 所在算、兩個 key 算出同一人＝`CfgBad`、沒列的不限但照記帳；判序 kernel → 包 → 寄件人。
  - `aos-agent` 的旗標寫在動作前：`aos-agent tools --target fsm1 ls`。`ctl who` 好幾列都包住＝取最深的。
  - `self_tools` 的 `path`：相對從 `$AOS_WS`、絕對限 `proto8/lib/` 底下；`agents` 的 `def`／`path`：相對從 `$AOS_WS`、絕對限 `proto8/lib/`、`proto8/demo/`；`ask` 預設 600 秒、上限 1700（act 格 30 分包得住）；`add` 後面的 `llm set`／`tools add` 失敗＝`ctl rm` 收回。
  - `limits`：key 不認、值不對＝`InterfaceBad`（宣告）／`ArgumentsBad`（`--limits`）；E2 沒到前只驗不送、stderr 一行 `(note: limits … not applied …)`。
  - **範本**：`local-qwen` 併進 `stupid-fast`（舊名不留）；`sol` 的 `body` 改 `fixed`；劇本包裡的路徑寫 `{"$env": "AOS_CD", "$path": "../agent-fsm"}`（kernel 用到那組才解）；件 3 要看得到「在飛」，新增 demo 用的慢假腦 `demo/llm-kernel/fake_slow`（睡 `delay_s` 再交 `llm_fake`）與 `fake-demo-fast`／`fake-demo-slow` 兩包；`budget.senders` 的例子限 `/tmp/aos-demo-sender` 每天 1 次（不影響別的 demo）；判官 `demo/daemon-judge` 的 `allowed` 加 `fsm1`、`kid`、`kid1`～`kid4`，`max_running` 1→4（demo/docs/04 的 `clock2` 例子改說法）。
  - 件 5 的 demo 用 `prlimit --as=2048000000`（＝`ulimit -v 2000000`）起 daemon；吃記憶體的定義要寫成 loop 型（`["aos-loop", "loop.json"]`、`max: 1`），exec 型退非 0 會直接下表、看不到 `reason`。

## 已知限制

- 劇本包與 `fake_slow` 只在**直接跑 repo 裡的** `demo/llm-kernel` 時對（路徑從 `AOS_CD`、從自己的位置找 `lib/`）；`cp` 走的定義用不了這幾包。
- `self_tools`、`agents` 只在 daemon 下的 agent 能用（`ctl who` 要查表）；`aos-exec body.json` 直接跑的回 `DaemonMissing`。
- 父被 `rm` 時它生的子不會跟著走（daemon 不知道父子），人殼 `ctl ls` 看了自己收。
- rlimit 是每個行程各自的上限、不從 daemon 總額扣（天然差異）；`procs` 數的是那個帳號的全部行程。

## 11-05 晚：daemon 那半（E1～E3）

- 照 [05](05-資源份額.md) 的 E1～E3 做：daemon.json 頂層 `limits`＝預設、procs 每列 `limits`；daemon 在 fork 出的子行程自己 setrlimit／換帳號（等同 s6-softlimit／s6-setuidgid，題 6 照推薦）；寫壞＝同 `stack` 三條；做不到＝小格 `stderr.txt` 一行 `LimitBad`、退 1；`procs_state` 每列帶生效的 `limits`；`aos-daemon-ctl add --limits`、`ls --json` 帶出；aos-agent `ctl add` 照宣告轉 `--limits`、提醒行拿掉。細節 [aos-daemon docs/09](../../../../impls/aos-daemon/docs/09-份額.md)。
- 跟規劃不同處：列寫 `{}`＝不限（蓋過 daemon 預設）、`null`＝用預設；`limits` 的 key 不認也算寫壞（`CfgBad`，同 aos-agent 的 `InterfaceBad`）；`user` 的帳號只認本機 `/etc/passwd`、`/etc/group`（靜態連結的 daemon 用 `getpwnam` 查不到名字時實測整台 SIGSEGV，所以不經 NSS）；setgroups／setgid／setuid 取代 initgroups；exec 型做不到照舊下表（原因只在 `stderr.txt`）；aos-agent 的 `--limits '{}'` 也送（蓋過預設）。
- 實測（WSL `/tmp/feat-lim-*`）：`/proc/<pid>/limits` 照列／預設／`{}` 生效；`prlimit --as=2048000000` 起的 daemon 下 `mem_mb: 4096`＝`LimitBad mem_mb 4096 exceeds the daemon's own hard limit`、列 `stopped`＋`reason`；demo/docs/05 件 5 照抄重跑。
- 寄件人額度靠信封 `sender`、不驗身分；要真擋＝Linux 權限分帳號。
- `lib/agent/self_tools/_tooldef.json` 的 `description` 還是中文（給腦看的、算程式輸出，該照 11-05「全都用英文」改；`agents` 的已是英文）。
- 端點函數打到沒開的 LM Studio port，WSL 上要等滿 `timeout_ms`（範本 120 秒）才回 `EndpointFailed`，不是馬上連不上。
