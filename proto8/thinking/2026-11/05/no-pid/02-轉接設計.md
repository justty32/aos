# 轉接設計（照使用者 11-05 晚裁定 (1)～(7)，見 [README](README.md)；細節 fable 代定、可翻案）

## 一句話

**要它做事就寄信、等回信，時限內沒回＝這次呼叫失敗，不去猜它是忙、不認得、還是掛了；想知道原因，讀它上一層 daemon 寫的檔。** daemon 是 Linux 行程跟 aos 之間唯一的橋：pid、`/proc`、訊號只有它碰，它把看到的**寫成檔案**給大家讀（`state.json`、`procs_state.json`）。

## 1. state.json 分成兩件事：`phase` 和「最近一次有反應的時間」（裁定 (3)）

現在的窗已經是檔案；11-02 把心跳拿掉、有變才寫（N-09、N-32），所以 daemon 死了檔停在 `running`，分不出「睡著」跟「死了」——才去對 pid。裁定 (3) 的解法**不是**恢復心跳：

- **多一欄 `responded_at`**（白話「最近一次有反應是什麼時候」；C-54 R6 `<事件>_at`、ISO 8601 UTC 到毫秒；欄名代定）：daemon（和每支 aos-loop）**有反應才寫**——收了信、採用了一份新 ctl、起或收了一個子項、身體跑完一次。睡著沒事做＝不寫，檔案時間照樣不動，**N-09「有變才寫」不破**。
- **只在「應該要有反應」時才判**：有刺激、卻沒反應，才算卡住。刺激＝**ctl 信箱 `new/` 裡有信**（`sent_at` 是刺激的時間）或 **`ctl.json` 的 `seq` 比 `state.json` 的 `ctl_seq` 新**。判法：刺激時間 ＋ N 秒 ＜ 現在，且 `responded_at` ＜ 刺激時間 → **`stuck`**。沒刺激＝不判、不誤判睡著的。N 代定 **10 秒**（daemon 一拍 200 ms、睡著最多 1 秒醒；給慢機器留餘量；寫死不開 key，使用者 11-01「旋鈕能刪就刪」）。
- **誰判**：它的**上一層 daemon**（[05-監管樹](05-監管樹.md)）。呼叫者自己不判——呼叫者只管寄信、等回信（§ 2）。
- **每個 proc 活不活**：表上那列的 `phase` 是 daemon `waitpid` 到才改的，**在那台 daemon 本身沒被上一層標 `stuck` 的前提下可信**。所以不需要新的「查活著」信，讀表就好。
- **daemon 寫自己的上一層**：起來時先把繼承到的 `AOS_DAEMON`（＝管它的那台）記進 `state.json` 與 `procs_state.json` 頂層 **`daemon`** 欄（沒有＝null＝根），再把自己行程的 `AOS_DAEMON` 設成自己（11-05 既有）。想知道「這台 daemon 怎麼了」就順著 `daemon` 欄去讀上一層的表。

## 2. 寄信、等回信：不回＝呼叫失敗（裁定 (5)）

使用者：「寄信收信是我們aos的非同步呼叫的底層機制，寄信不回，等同於呼叫失敗……有可能他在忙，有可能你的要求他不認得，也可能他掛了。」

- **現成的**：daemon 對任何好信有 `reply_to` 就回 `{"applied": true}`（N-28）；`aos-daemon-ctl --reply-to` 已能帶。所以**今天寄 `{}` 加 `--reply-to` 就是一次「問 daemon」**。正式化：`body` `{"ping": true}`（老慣例、R5）、回信 `{"applied": true}`，daemon 認 `ping`＝不改底、只回信、也算一次「有反應」。paused 那圈照 N-28 不認領→不回→**呼叫失敗，正確**（它在忙）；想知道它 paused 讀它的 `state.json`。
- **時限**：純 ping 預設 **3 秒**；`add` 等「列上表」照 aos-agent 既有的 30 秒。逾時＝**失敗**：工具（thought／agents／self_tools）報 `DaemonMissing no reply from the daemon at D within 3s`（沿用既有代號、不造新字：對呼叫者就是「沒有活的 daemon 可用」）；人殼指令（`ctl add`／`rm`…）印一行 note、信照留 `new/`（edge-daemon #7「信照寄、開門照套」保留——非同步呼叫的本性）。
- **判官（`AOS_KERNEL`）也認 ping**：原樣轉寄給 daemon（帶原 `reply_to`）。規則：**問活著寄到跟掛 proc 同一個地方**；判官不在＝沒人轉＝失敗，正好是呼叫者該知道的。`lib/base/judge` 加一個 if。
- **回信信箱**（aos-agent 現在開「暫時信箱、名字帶 pid、清殘留靠 pid」）：照 `aos-llm ask` 先例——**共用一個、靠 `in_reply_to` 認自己的**：`$AOS_STACK/daemon_reply/`（呼叫者自己的 stack；沙箱裡本來就綁 rw）；沒 `AOS_STACK` 的人殼指令用 `$AOS_DAEMON/procs_ctl_mailbox/reply/`。收到自己的就 `done`；沒人領的由下一個來讀的人把 `sent_at` 超過 10 分鐘的收掉（垃圾回收、不是判死活；代定）。

## 3. Python 端：一個模組、三個口（跟大重構 S6 合一）

S6 本來就要把 `aos-daemon-ctl` 改成可 import 模組＋薄殼（arch-refactor 03 § 5 代定 5）。no-pid 就是那個模組長這三個口，**其他 Python 只准 import 它們、不准自己碰 `/proc`**：

| 函式 | 做什麼 | 回什麼 |
|---|---|---|
| `find_daemon(flag=None)` | 照 [03 § 1](03-找daemon與脫鉤.md)：`--daemon` ＞ `$AOS_DAEMON` ＞ `./.stack`；驗是資料夾、有 ctl 信箱；`realpath` | 絕對路徑；找不到＝`DaemonMissing` |
| `state(d)` | 讀 `procs_state.json`（`aos-directive` 解切檔） | `{"daemon": 上一層或 null, "responded_at", "procs": {名字: 列}}`；表還沒寫＝空表 |
| `ask(d, body, timeout_s=3)` | 寄信（`AOS_KERNEL` 有設寄那裡）、在共用回信信箱等 `in_reply_to` | 回信 `body`；逾時＝`None`（呼叫者決定報錯或 note）；`ping(d)`＝`ask(d, {"ping": true})` |

- `ls`／`where`／`state`：讀檔印表；最後一行：有上一層＝讀上一層的表印這台那列的 `phase`（`supervisor <上層>: running`／`stuck`／`stopped`）；根＝`root daemon (no supervisor)`。**不寄信、不等。**
- `add`／`rm`／`stop`／`start`／`sleep`／`wake`：寄信；給 `--reply-to`＝呼叫者等；沒給＝不預判、不印「daemon 沒在跑」（那句連 pid 一起刪；要確認就 `--reply-to`）。
- `pause`／`resume`：照舊直接寫子 loop 的 `ctl.json`、等它 `ctl_seq`（N-10 使用者 10-16 定；是手把與窗、不是 pid）。
