## 代定（可翻案）

1. **模組放 `proto8/py/`**（arch-refactor 03 § 5 原寫 `cmd/aos-daemon-ctl/daemon_ctl.py`）：三支指令都 import 它，照 S5 的分夾判準是「cmd 共用模組」。
2. **`find_daemon` 只驗「是資料夾」＋realpath**；信箱在不在照舊到寄信時報 `MailboxMissing`（03 § 1 寫找的時候驗三件；這樣錯誤行跟原本一樣）。
3. **沒給 `--reply-to` 時看 3 秒信有沒有被認領**：07 驗收要「daemon 不在時 ctl add 印 note 退 0」，02 § 3 又說不預判——折衷成只讀檔、不判死活、只說「信還在」。代價：daemon 活著時每次 add 多等到它下一拍（約 0.1～1 秒）。翻案＝不印、要確認就 `--reply-to`。
4. **加 `aos-daemon-ctl ping` 子命令**（規劃只有模組的口）：給人一條正統的「問 daemon」管道。
5. **`ls` 的上一層看法放 stdout 最後一行、`# ` 開頭**（腳本好略過）；在上一層的表裡找「這台那列」用 realpath(列的 stack)＝realpath(這台)。
6. **`daemon` 欄是相對路徑就不猜**（P2 代定 2 照字面記人殼 export 的相對路徑）：印 `relative path as the daemon inherited it; cannot tell where it is`。根治＝翻 P2 代定 2（daemon 起來時轉絕對），一行 C++，留給 P5b 或使用者。
7. **30 秒一封回信都沒有＝`DaemonMissing`**；回了 `applied: true` 但表還沒變＝照舊 `WaitFailed`。
8. **「有人在跑它」＝表上 phase 是 running／stopping**：daemon 死了、表停在 running 時看不出來，改由 listen 等 10 秒沒被認領提醒一次（暫停中不提，已有暫停那句）；say 不再說「nothing is running」。
9. **共用回信信箱加 `.reply.lock`（flock）**，收信與垃圾回收排隊（codex 實測併發時會重複 `done`）。
10. **aos-agent 叫 screen 入口時把 `AOS_DAEMON` 設成它找到的 daemon**（`--daemon` 給的也傳下去），watch 才讀得到表。
11. `check_limits` 只留一份（用 aos-agent 的字樣）：`aos-daemon-ctl add --limits` 的錯誤字樣跟原本略不同。

## 實測（WSL `/tmp/p3-accept/`；腳本 `accept.sh`、`fsm.sh`、`down.sh`，殺程序只用記下的 pid）

- **ctl 對活的 daemon**：`ping` 62 ms；空表 `ls` 只有 `# root daemon (no supervisor)`；add／ls／ls --json／pause／resume／stop（再 stop＝PhaseBad）／start／sleep／start on sleeping＝PhaseBad／wake／where／rm，輸出與錯誤行照舊。

- **aos-agent 全套 ctl**：add 印 stack、ls、state、pause（ls 顯示 paused）、resume、stop、再 stop＝already、start、sleep、sleeping 的 stop＝PhaseBad、wake、where、say、rm；回信信箱 `<d>/procs_ctl_mailbox/reply/` 用完是空的；設了 `AOS_STACK` 時用 `$AOS_STACK/daemon_reply/`。

- **daemon 死了**（`kill` 記下的 pid）：`ping` 3.0 秒 `DaemonMissing`；`ctl add` 印信件名稱＋3 秒那行提醒、退 0；`aos-agent ctl add` 30.1 秒 `DaemonMissing no reply …`；daemon 再起來，兩封留在信箱的 add 都套上了。

## 新發現的邊緣（沒修，攤出來）

1. **同一個 clone 裡別人的 `git commit` 會帶走你已 stage 的檔**（這次就發生，見開頭）：多人共用工作樹時，stage 跟 commit 要在同一個指令裡做完、或用 `git commit -- <路徑>` 只提交自己的路徑。
2. **daemon 死了、表停在 running**：aos-agent 只能靠 listen 10 秒提醒；say 不再說「nothing is running」。監管樹（P6～P7）做好後，上一層表上那列會變 `stuck`／`stopped`，`ls` 尾行就看得出來。
3. **人殼的回信信箱在 daemon 的 ctl 信箱底下**（`<D>/procs_ctl_mailbox/reply/`）：同帳號沒問題；以後模式 2 把 ctl 信箱鎖給判官帳號時，人殼要另給 `AOS_STACK` 才有地方收回信。
4. **經 `AOS_KERNEL` 寄時，3 秒提醒看的是判官的 `requests/`**：判官是 interval 長的 loop 型時會常印（信其實只是在排隊）。
5. **aos-eca-screen 不是經 aos-agent 叫、殼裡又沒 `AOS_DAEMON`**：找不到 daemon＝看不出來、照等（跟原本「沒宣告 state 窗」一樣）。
6. `daemon_ctl.py` 約 570 行，超過 300 行門檻：S8 拆。
