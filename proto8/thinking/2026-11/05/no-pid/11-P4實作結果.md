# P4 實作結果（11-06）

## 做了什麼

1. **thought 不再碰 pid**（`proto8/lib/agent/thought/_entry`）：
   - **子名每次唯一**：`t-<父名前 32 字>-<UTC 時間到毫秒>-<4 位 hex>`（例 `t-bob-20261106T013358137-8122`）；名字撞表或撞資料夾就重生，5 次都撞＝`MkdirFailed`。原本「從 001 往上數、搶號」整段拿掉，所以 thought 被 `kill -9` 後再叫一次不會卡「子名被佔」。
   - **紀錄改成租約**：`children/<子名>/state` 只剩三種——`running <UTC 時刻>`（＝主人最晚到這時還會用它）、`kept`、`failed`。每次為這隻子叫 aos-agent 之前先續租（這一步的逾時＋5 秒）；被 TERM／Ctrl-C 時把租約收回（寫成現在）。`pid_alive` 與 `running <pid>` 刪掉。
   - **對帳照四格**（照 kernel-daemon 08 代定 1 的精神：表上有沒有那列＋紀錄怎麼寫）：租約沒到＝在飛、不碰；剛建、還沒寫 state＝不碰；表上沒有＝已收尾、忘掉紀錄；表上有——`kept` 不動，租約過了＝主人死在半路，先 `ctl stop`（stack 留著）再記 `failed`，`failed` 照舊只留最新 3 隻。
   - **掛子的信沒回**（aos-agent 30 秒一封回信都沒有＝`DaemonMissing`）：紀錄記 `failed`、不刪；之後信被套上、子上了表，下一次叫 thought 把它當 failed 停掉。
   - **`GoalMissing` 拿掉**：沒給 goal、空字串、全空白都＝`ArgumentsBad`（J1 邊緣 1 的二選一，照推薦）。
2. **`_tooldef.json` 加選填 `env`**（變數名陣列：這支工具要靠哪些 hub 型環境變數找東西）：thought、agents、self_tools、judge＝`["AOS_DAEMON"]`；memory、memory_export＝`["AOS_MEMORY"]`；pyfix＝`["AOS_LLM_KERNEL"]`（codex 盤點多找到的：它的內層 brain 叫 `aos-llm ask`）。模型看不到它（agent-fsm 與 pyfix 的 brain 只取 `description`／`parameters`）。
3. **`tool_io.py`**：`--help` 多印一行 `Environment: AOS_DAEMON (hub variables this tool needs; not set = <Name>Missing)`；`env` 不進參數 schema、不影響旗標（`--env X` 照樣 `FlagUnknown`）；`env` 寫壞（不是字串陣列）＝不印、不提醒。
4. **lib/docs/01 新增規則 11**「找東西靠環境變數或明給、不碰 pid」（[03 § 4](03-找daemon與脫鉤.md) 草稿寫成三小點：位置怎麼拿、不碰行程、列出依賴）；契約表 `_tooldef.json` 那列加 `env`；規則 4 補半句指向規則 11。lib/docs/03 的 thought、self_tools 列照新行為改。
5. **knowledge**（`aos/agents/thought.md`、`aos/me/self_tools.md`、`aos/me/README.md`、`aos/errors/codes.md`、`aos/cli.md`）：`DaemonMissing` 原本只解成「找不到 daemon／你不在 daemon 底下」，現在兩種都講（也可能是 daemon 沒回信：忙、暫停或掛了），並告訴腦：別連著重試、說功能暫時不能用、晚點最多再試一次。
6. small-thought README 加一句結論指到本檔。

## 代定（可翻案）

1. **子名形狀**：規劃寫 `<UTC 奈秒>.<4 位亂數>`；改成保留 `t-<父名>-` 前綴（`ctl ls` 一眼看得出是誰的小念頭）＋人看得懂的 UTC 時間到毫秒＋4 位 hex，用連字號不用點——agents 的名字規則上限 64 字，奈秒＋父名 48 字會超過。
2. **判「主人還在不在」用租約、不用 pid**：子是長住的 agent-fsm，沒有「state.json 收尾」可看；改看主人自己寫的到期時刻。kill -9 的主人沒機會收回，就要等租約到期（最長是 `timeout_s`＋35 秒）才被下一次叫的人停掉。
3. **租約用 UTC 牆鐘、ISO 8601 到秒、`Z` 結尾**（C-54 R6 的時間寫法）；解不出來＝當過期。
4. **TERM 時只改檔、不寄信**：handler 裡寄信要等回信，會拖慢被殺；收回租約後讓下一次對帳去停。
5. **租約過了先 `ctl stop` 再記 failed**（原本主人死了的子只計入 gc、照樣跑著佔 loop）；表上那列已經是 `stopped` 的不再寄 stop（隊長審 diff 時加，省掉每次叫都多三封信）。
6. **掛子的信沒回＝記 failed、不刪**；其他錯（`AddRejected` 等）照舊刪紀錄。
7. **`env` 的尺**：只列「必須靠它」的 hub；不列 aos-exec 的六個、不列只是「有設就改信去向」的 `AOS_KERNEL`、不列 memory 只拿來解相對路徑的 `AOS_DAEMON`。
8. **`--help` 印 `Environment:` 一行**（規劃只說「讓登記的人知道」；json-argv J7 也寫 tool_io 另讀 `env`）：放在 tool_io，各工具不另寫。
9. keep 時先 `ctl stop` 再記 `kept`（stop 期間還在續租）。
10. thought 的 HELP 只改受影響的句子；手寫「Arguments:」段整段刪留給 json-argv J2。json-argv J6 裡「`_tooldef.json` 的 `env` 四支填上」這次已做（填了七支），J6 其餘（`AOS_KERNEL` warning 等）沒動。

## 新發現的邊緣（沒修，攤出來）

1. **掛子的信沒回之後，daemon 還沒恢復就又叫一次 thought**：照四格順序「表上沒有＝忘掉」，那筆 failed 紀錄會被忘掉；之後 daemon 才把信套上，子就沒有紀錄、thought 不會收它（`ctl ls` 看得到 `t-…`，要人 rm）。要解得改「表上沒有就忘」那格（例：failed 紀錄等 10 分鐘才忘），這次沒改。
2. **租約靠牆鐘**：時鐘往前跳會讓別人的租約提早到期、被當死在半路停掉；往後跳則延後收。跟 tick-time 那條「兩鐘規則」同類，等那邊定了再看。
3. **兩個 thought 同時對帳沒有鎖**：同一隻過期子可能被停兩次、或對到別人剛刪的紀錄——結果都是多一封信或一行 warning，不會壞。
4. **kill -9 的主人要等租約到期**：子在那段時間照樣佔一個 loop（最長 `timeout_s`＋35 秒，上限約 29 分鐘）。
5. **真腦小模型會一次發三個呼叫**：thought 本身沒問題，但「A→B→C 串前一步結論」對 1.7b 太難；要測串接得換大一點的模型。
6. 測試時發現：`wsl -e bash -lc` 那條指令一結束，裡面背景起的 daemon 也跟著收掉（codex 也撞到）；驗收的起停要寫在同一支腳本裡。
