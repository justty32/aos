# P2 實作結果（11-06）

只動 `proto8/impls/` 的 aos-loop（`include/aos/loop.hpp`、`src/engine/{window,loop}.cpp`、`engine.hpp`）、aos-daemon（`src/daemon/{daemon,mailbox,windows}.cpp`、`daemon.hpp`）與兩家的 README、docs（aos-loop docs/02；aos-daemon docs/04、05）。`child/` 沒動（少跟家機 S7 分支撞）。

## 做了什麼

1. **aos-loop 的 `state.json` 多一欄 `responded_at`**（最近一次有反應的時間，UTC 到毫秒；起來是 `null`）。有反應才更新：讀到新的一道 ctl 並處理了、身體跑完一次。它算進「有變才寫」，所以**睡著時窗完全不動**，有身體的 loop 每跑完一次寫一份。
2. **aos-daemon 兩扇窗都有 `responded_at` 與頂層 `daemon`**（`procs_state.json` 放在 `procs` 表之前）。daemon 的「有反應」＝上面兩種，再加：這圈收到信、採用了內容不同的新 procs_ctl、表上起了或收了一個子項、自己的身體跑完一次。
3. **`daemon` 欄＝上一層**：起來時先記下繼承到的 `AOS_DAEMON`，再把自己的蓋成自己（順序照 06「不能反」）。沒設＝`null`＝根。
4. **信箱認 `{"ping": true}`**：不改底；有 `reply_to` 照舊回 `{"applied": true}`；收了就算有反應。paused／stopping 那圈本來就不認領信＝不回（呼叫失敗，照裁定）。

## 代定（可翻案）

1. **讀到新的壞 ctl 也算有反應**（規劃寫的是「採用 ctl」）：整份不採用、寫進 `ctl_warning` 的那種也更新 `responded_at`——它確實回應了，只是不採用；不這樣做，P7 判 stuck 會把「有人寫了壞指令」當成卡住。11-07 #15-2 更新：第一道已套用過而略過的指令、檔不見了不算；第一道未套用的好壞指令處理後都算有反應。翻案＝只有照做的才算。
2. **`daemon` 欄照字面記**繼承到的字串（父 daemon 給的是它的 stack、絕對、結尾 `/`）；**例外**：空字串＝`null`；解開後就是自己的 stack（人殼 export 了指自己、再在同一殼起它）＝`null`；解不開（資料夾不在）照字面。翻案＝一律照字面，或一律轉絕對。
3. **`ping` 必須是 JSON `true`**：`false`、`null`、數字、字串都是壞信（`mailbox_warning` 寫 `ping must be true`）、不回；跟其他 key 同一封＝其他照常套。
4. daemon「起子項」含 adopt 接回（所以起來時有接回就已經有 `responded_at`）；「收子項」含 rm 一列 stopped、留成 stopped／sleeping；身體起不來那次也算跑完一次。
5. 欄位位置：`state.json` 的 `responded_at` 在 `pid`／`started_at_ticks`／`boot_id` 之後、`updated_at` 之前，`daemon` 在 `ctl_warning` 之後（經 daemon 的 `info()`）。

## 實測（WSL `/tmp/p2-accept/`；腳本與完整紀錄在 `/tmp/p2-accept/codex-p2/`，殺程序只用記下的 pid，12 支都 TERM 收掉、沒用到 KILL）

- **ping 1 秒內回信**：195 ms（隊長自己另跑一次 119 ms）；回信 `{"applied": true}`、`in_reply_to` 對得上；兩扇窗的 `responded_at` 從 `null` 變成寄信那一刻；表沒變。
- **paused 時收不到**：寫 `{"cmd":"pause"}` 後寄 ping，等 3 秒沒有回信、信留在 `new/`、窗也沒動；`resume` 後那封被收、回信到。
- **睡著 60 秒不動**：空表無身體的 daemon（兩扇窗）、`interval_ms` 600000 的 aos-loop，60 秒前後內容與 mtime 完全一樣。
- **`daemon` 欄**：根（殼裡沒有 `AOS_DAEMON`）兩扇窗都是 `null`；用信 `procs_added` 在根底下掛一台子 daemon（exec 型），子的兩扇窗＝父的 stack（`/tmp/…/root/`，帶結尾 `/`）；指自己、指自己的捷徑、空字串＝`null`；指不存在的路徑＝照字面。
- **aos-loop**：好 ctl、壞 ctl（`{"cmd":"bogus"}`、不是 JSON、ctl 是資料夾）都更新；刪掉 ctl 不更新；身體每跑完一次更新（退 1 也是）。
- **壞 ping**：`{"ping": false}` 不回信、`mailbox_warning` 有原因；`ping` 跟 `procs_removed` 同一封照常套。
- impls 頂層一次建，建得過、沒有 warning。

## 新發現的邊緣（沒修，攤出來）

1. **paused／stopping 的 daemon 信箱裡有信＝`responded_at` 不會動**：P7 照 02 § 1 的判法，10 秒後會把一台只是暫停的 daemon 標成 `stuck`。P7 要先決定：看到子窗 `paused`／`stopping` 就不判，還是算卡住。
2. **paused 中收子項照樣更新 `responded_at`、寫一份窗**（daemon 暫停時照收已在收的、照記自己結束的）——「paused 時窗不動」只在沒有子項起落時成立。無害，記一下。
3. **`daemon` 欄照字面＝人殼 export 相對路徑時記的就是相對的**，讀的人不知道從哪算起（父 daemon 給的永遠是絕對的，所以只出在根 daemon 從人殼繼承的時候）。P3 的 `state()` 讀它時要知道這件事，或翻代定 2 改成一律轉絕對。
4. **同一毫秒裡的幾次反應會共用同一個時間、合成一次寫入**：判法是「`responded_at` 比刺激早」，同毫秒不會誤判，無害。
5. **掛子 daemon 時 exec 目標寫裸名 `aos-daemon` 起不來**（aos-exec 回 `EntryMissing`，它不照 PATH 找）：現在要寫執行檔的絕對路徑；P6 的 daemon 型寫法會蓋過這題。
