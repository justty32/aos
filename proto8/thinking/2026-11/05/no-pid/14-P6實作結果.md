# P6 實作結果（daemon 型 proc，11-06）

## 一句話

**子 daemon 可以寫成第三種 proc `{"daemon": X}` 了**：根收工整棵樹一層層睡、再起一層層醒；`kill -9` 子 daemon，根同一拍（0.16 秒）就重起它，底下的 tick 沒死、被新的子 daemon 接回、接著數。判卡住（`stuck`）沒做，排 P7。

## 做了什麼

1. **寫法**：proc 物件有 `daemon` key＝daemon 型，只收 `daemon`、`stack`、`ws`、`def`、`limits`、`restart_on_stuck`；混 `exec` 或多別的 key＝`CfgBad`。X 是 aos-exec 認得的入口（通常是定義資料夾，`_entry`＝`["aos-daemon", "daemon.json"]`），相對路徑從父的 cwd 轉絕對、不驗在不在。
2. **起法**：父 `aos-exec -- X`，不包 aos-loop、不寫 `loop.json`；`AOS_STACK`＝proc 的 stack、`AOS_DAEMON`＝父的 stack（照舊）。
3. **退了照表重起**：不論退 0、非 0、被訊號打掉、或接回來的拿不到碼，列先留 `sleeping`、同一拍再起（log 那行記 `done`）。連 3 次都在起來 3 秒內退＝列留 `stopped`＋`reason`（例：`failed to start: … EntryMissing entry not found: …; restarted 3 times in a row, each exited within 3s; not restarting again`），要人 `start`。人下的 stop／sleep／rm 不重起。
4. **收工 sleep、開門 wake**：沿用 loop 型那套（daemon 型不是「跑一次」，自然走得到）；父等子 daemon 收工的期限 30 秒（loop 型照舊 10 秒），子先收自己的 procs 才退。
5. **表**：daemon 型的列多 `"daemon": true`、`"restart_on_stuck": <bool>`（只這型寫；`restart_on_stuck` P6 只記，P7 才用）；`exec` 欄記 X。父重開照這欄認型別、不看 `loop.json`。
6. **aos-daemon-ctl／aos-agent 的 stop、sleep**：原本看 stack 裡沒有 `loop.json` 就報 `CtlMissing`（當成 exec 型）。改 `py/daemon_ctl/ctl.py` 的 `need_ctl`：列上 `daemon: true` 就放行；pause／resume 寫子 daemon 自己的 `ctl.json`。
7. 文件：aos-daemon README、docs/02（寫法表第三列、os-impl A7「exec＝oneshot、loop＝longrun、daemon＝bundle」）、docs/03（重起規則；os-impl A15 整樹 sleep 葉先根後、wake 反序、在飛問腦醒來重問）、docs/04（兩個新欄）；cmd/docs/03 一句。
8. 條文加註（原句全留）：N-28「規劃中（P6）」下加已實作、N-17「`stopped` 那半已實作、`stuck` 排 P7」、名詞表 daemon 列、C-16、兩份條號表。

## 代定（可翻案）

1. **X 寫 aos-exec 入口，不是「一份 daemon.json」**：原設計寫「定義資料夾或 daemon.json」。直接給一份沒有 `_entry` 的 daemon.json，父不知道要怎麼起它（拷進小格會把裡面的相對路徑弄壞）；所以 X 照 aos-exec 的規矩：有 `_entry` 的資料夾、帶 `_entry` key 的檔、或 `檔#/指標`。只給 daemon.json＝子行程寫一行 `EntryBad` 進 stderr.txt、3 次後留 `stopped`。
2. **退了先記 `sleeping` 再同一拍起**：這樣父剛好在這時被 `kill -9`，重開看到 `sleeping` 也會 wake，不會漏掉。
3. **「連 3 次失敗」＝連 3 次都在起來 3 秒內退**（3 秒沿用既有 `REVIVE_MS`）；中間有一次撐過 3 秒就重新算。計數只在記憶體，父重開歸零。
4. **父收子 daemon 等 30 秒**才 SIGKILL 整群（子 daemon 自己收它的子項最多 10 秒多，父不搶先）。
5. **stop 子 daemon＝SIGTERM**（不寫 ctl）：子 daemon 自己收工，底下的 procs 留 `sleeping`；`start` 後子起來再 wake 它們。
6. **pause／resume 子 daemon** 寫它自己的 `ctl.json`（daemon 的預設名）、不等 `ctl_seq`；子 daemon 的 daemon.json 若改了 ctl 名，父這邊看不到。
7. **aos-daemon-ctl add 沒有 daemon 型的寫法**：要掛子 daemon 就寫進 daemon.json 的 `procs`，或自己寄 `procs_added` 信（實測就是這樣寄的）。要不要加 `add --daemon` 留給使用者。

## 實測（/tmp/p6-accept，根→子 daemon→tick 三層；腳本 `/tmp/p6-team/accept.sh`）

- 起根：sub `running`（`daemon: true`）、tick `running`；子 daemon 窗的 `daemon` 欄＝根的 stack；tick 每 0.3 秒數一次。
- 根 Ctrl-C：三層都退、行程都不在；子的表 tick `sleeping`（06:19:44.550）先於根的表 sub `sleeping`（.600）＝葉先根後；數字停在 14。
- 再起根：sub、tick 都換新 pid `running`，數字從 14 接著數。
- `kill -9` 子 daemon：根 0.16 秒就換新 pid（根一拍 200 ms）；tick 還是原 pid、新的子 daemon 接回，數字照漲。
- `aos-daemon-ctl stop sub`：sub `stopped`、tick `sleeping`；`start sub`：兩層都回 `running`。
- 寄一封 `procs_added {"bad": {"daemon": "/tmp/p6-accept/nonexist"}}`：4 秒內 `stopped`＋上面那句 reason，stderr.txt 剛好 3 行。
- 舊行為對照：假腦試驗場最短路＋C++ help／錯誤行 119 例（`/tmp/p6-team/cases.sh`），改前改後正規化後 **NODIFF**。

## 新發現的邊緣（沒修，攤出來）

1. **`procs_ctl.json` 一直留著 `procs_started` 那個名字**：3 次失敗留 `stopped` 後，下一圈 stopped 集合又把它拿掉、再試一輪（loop 型出錯留 `stopped` 也是同一個既有語意）。用信箱寄一次 start 不受影響。
2. **子 daemon 的 `daemon.json` 把自己的 state 窗改名或關掉**：父「小格裡已有活著的就接回」那段讀的是預設 `state.json`，認不出來，可能在同一格多起一份——但子 daemon 有 flock，第二份會 `DaemonExists` 退出、3 次後留 `stopped`（不會兩份一起跑）。
3. **父等子 daemon 30 秒、子等孫 10 秒**：三層以上每層都照這個數；哪一層的孫子收得比 30 秒慢，父會先 SIGKILL 整棵（連孫子），那幾列在子的表上會停在 `stopping`／`running`，下次醒來照 adopt 的既有規則處理（接成 `sleeping` 或 `stopped`）。
4. **連敗計數只在記憶體**：父自己也一直 crash 重起的話，子 daemon 的 3 次上限每次都歸零（根 crash 本來就由使用者顧）。
