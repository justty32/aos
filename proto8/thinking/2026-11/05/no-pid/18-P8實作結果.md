## 實測：逐條指令、結果與秒數

全用現有 bin；開始與收尾 `pgrep -a aos-` 無自己的殘留。harness 記自己的 Popen pid，只對本次樹送訊號。PID 屬驗證所在 namespace，不能在別的殼照抄。

**正式試驗場（共 14.403 秒）**：`python3 /tmp/p8-playground-accept/run.py`；完整命令、回應與時間在 `/tmp/p8-playground-accept/events.json`，根輸出 `root-1.log`、`root-2.log`。實際執行順序如下；人手起法為 `cd ~/code/playground && source env.sh && aos-exec root`。

```sh
aos-exec root
aos-daemon-ctl -d /home/lorkhan/code/playground/.stack ls
aos-daemon-ctl -d /home/lorkhan/code/playground/llm_kernel ping
# The following commands run from playground/ws.
aos-daemon-ctl ping
aos-exec ../agents/fsm_ann
aos-agent llm --target fsm_ann set endpoint=fake
aos-agent say --target fsm_ann 'P8 first question: what time is it?'
aos-agent listen --target fsm_ann
kill -9 6
aos-daemon-ctl ping
aos-agent say --target fsm_ann 'P8 after kill: what time is it?'
aos-agent listen --target fsm_ann
kill -INT 3
# Start the root again from playground, then return to ws.
aos-exec root
aos-agent say --target fsm_ann 'P8 after wake: what time is it?'
aos-agent listen --target fsm_ann
aos-agent llm --target fsm_ann reset
kill -INT 287
```

核對領班 pid 6 的 cwd 在 playground/ws、cmdline 為 aos-daemon 才送 KILL；0.060 秒根改成 pid 166，快於一拍 100 ms。再 ping 回 202 ms，第二題 4.041 秒回假腦答案。根 pid 3 收 SIGINT 後 0.113 秒退 130，三層表列全 `sleeping`；重開根 pid 287，0.333 秒三台 ready，第三題 4.240 秒照答。最後 reset 覆蓋層、SIGINT 根，0.114 秒退130，留下 sleeping image；未起 eca_bob。

## 新邊緣、沒做到的與原因

daemon 沒身體時 state.phase 可以是 `waiting`，所以 ready 不可硬等 `running`；表列的 running 與自身窗 phase 是不同層的事。跨重開的 state counter 會重置（正式場 53／31／2 → 1／1／1），不是搬家丟資料；持久 kernel counter 才適合這次驗法。

未實測 scope 的 `memory.max` 與 systemd／s6 端到端監管；沙箱不能連 user bus。跨真主機 boot_id、帳號、真腦端點與在飛外部 CLI 只交付邊界說明。

Git 真索引唯讀，`git add -N` 報 `index.lock: Read-only file system`。以 `/tmp/p8-git-audit/index` 副本納入三個新增程式／範例檔後跑 codemap、wf-lint，真索引未動。隊長之後須先登記新檔再重生，避免漏掉新增檔；環境記在該目錄的 `environment.json`。

待使用者：公司 WSL 的試驗場仍要照食譜換成三層並親手跑一次；家機有 user bus 的殼可另驗 scope 限額。
