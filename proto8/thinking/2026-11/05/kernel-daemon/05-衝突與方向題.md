# 要使用者看的（白話；推薦放第一）

照 [user/03](../../../../../wf/workflows/common/user/03-討論紀錄與規劃.md)：只帶新想法跟既有裁定打架的（衝突）、原則推不出的（方向題）。11-05 早你自己已經裁掉的（kernel 定義、daemon 是最基礎 kernel、兩種模式、問腦掛 daemon、能包盡量包、轉交型算、直接跑不算、`AOS_LLM_KERNEL`、llm 自己一台 daemon、指 stack 不糾結）不列；方向題一題都沒有——「設 daemon 都是指其 stack」那題照你的比喻推得出答案，寫在 [07 § 3](07-llm-daemon佈局.md)，你一句「照建議」就好。

## 衝突 1：10-13 你說「直接當宿主也算 kernel」，11-05 你說「判斷後直接跑 Linux 原生 proc 的不算」

- **哪條**：[10-13 kernel-agent 結論](../../../2026-10/13/kernel-agent/02-結論未決.md)「能操控某些東西被執行的就算 kernel（**直接當宿主**、或寫檔給獨立的 daemon 讀都算）」；C-47 aos 實作定義沒排除自己跑。11-05：「他的 proc 是掛在 linux 底下，而非 daemon 底下。不太好」「直接執行 linux 原生 proc 或是一些函數，那他算 kernel 嗎？我覺得是不算的」。
- **(a) 後裁蓋前裁（推薦）**：C-47 aos 實作定義加一句「被管的 proc 要掛在 daemon 下；判斷後自己 fork 跑 Linux 原生程序或函數的不算；判斷後轉交給有權的 kernel 的算」；10-13 那句加「11-05 改」註。後果：今天的 aos-llm-kernel 在改掛 daemon 之前「嚴格說不算」，文件照實寫；10-15 通用 kernel 設計裡「閘門照舊由 kernel 跑」那段同樣要改成「請 daemon 掛」。
- (b) 兩句並存：「自己跑」算「寬鬆 kernel」、「掛 daemon」算「aos kernel」。後果：一個詞兩義（C-54 R4）、文件每次都要說是哪一種。
- **例子**：agent-fsm 的 act 格判「腦要叫 clock」就直接 `aos-tools call clock`——(a) 不是 kernel；(b) 是寬鬆 kernel。

## 衝突 2：模式 2 要「唯一有權限對 daemon 下 ctl 的 proc」，可是 aos 一路都是「誰能寫誰就能控制、純靠 Linux」

- **哪條**：[11-03 ctl-commands](../../03/ctl-commands/README.md) 決定「不用信箱、誰能寫誰就能控制」；N-54 末「誰能寄：純靠 Linux 檔案權限」；C-64「用檔案是為了借 Linux 權限」；aos-llm-kernel 已知限制「寄信的人是誰 kernel 不驗」。11-05：「kernel 作為一個唯一有權限對 daemon 下 daemon-ctl 指令的 proc」。
- **(a) 照舊純靠 Linux、程式不驗身分（推薦）**：「唯一」＝daemon 的 ctl 信箱只讓 0 號那個帳號寫（`new/`、`tmp/` 755；其他 proc 另一帳號，沙箱 `s6-setuidgid aos-run` 現成），同一帳號裡只是約定（文件寫「這台走 0 號，掛東西寄 `$AOS_KERNEL`」）。後果：零改程式；同帳號擋不住（跟今天「誰能寫誰就能控制」一致）；要真的擋得先把帳號分開（`setup.sh` 那套，WAIT_USER 既有）。
- (b) daemon 認寄件人白名單（daemon.json 一個 key、讀信封 `sender`）。後果：aos 第一次驗身分；`sender` 只是路徑（N-64 ③「身分＝路徑」）、偽造零成本，等於沒擋；多一條規則（C-56）。
- **例子**：同一帳號下人手打 `aos-agent add --name x ../agents/x`——(a) 掛得上（繞過 0 號，自擔）；(b) 被 daemon 丟掉、`mailbox_warning` 一行。

## fable 代定（可翻案；一句一條，細節在 02～07）

1. 掛 proc 只有一條路：往 ctl 信箱寄 `procs_*` 信；kernel＝有判斷地寄這封信的人；daemon＝模式 0。
2. 模式 1＝daemon.json 的 `exec` 身體當判官、轉寄進自己的 ctl 信箱；不給 aos-daemon 加 `procs_judge` 之類的 key。daemon 跑身體那次也設 `AOS_DAEMON`（一行改動）。
3. 模式 2＝同一支判官掛成 loop 型 proc（`demo/procs-kernel`）；`AOS_KERNEL`＝「掛 proc 往哪寄」的 hub，沒設＝daemon 的 ctl 信箱（不報 Missing）；aos-llm-kernel 掛信目的地照這條。
4. llm kernel＝自己一台 daemon 的身體（繼承式第一個實例）；`AOS_LLM_KERNEL`＝llm kernel 的 stack、信箱固定 `<stack>/mailbox/`、kernel.json `mailbox` key 拿掉；人設不自動傳。
5. 問腦 proc 掛成 `max: 1` 的 loop 型、stack＝信資料夾、名字 `llm_<信件名稱>`、單子 `stdin`／`stdout`／`timeout_ms`、不寫 `ws`／`def`；完成看 `state.json`＋`reply.json`，列不見又沒收尾＝重掛一次、第二次失敗；`reply_to`＝kernel 的 `daemon_reply/`。
6. kernel 一拍不再等子行程：收成品→收新信→補位到 `slots`；`RunFailed`、`runner.json`、「一次裡不補位」退場；沒 `AOS_DAEMON`＝`DaemonMissing`。
7. aos-daemon-ctl／aos-agent 第一版不認 `AOS_KERNEL`；通用 kernel（N-42 (2)）照模式 2 的形狀、仍不實作判官腦。
8. 條文：C-47 加嚴（等衝突 1）、N-42 (1) 改寫、附錄1 daemon 列與 N-63 `AOS_DAEMON` 加使用者原話、C-74 表補「aos-llm-kernel 是 kernel 實作」；10-13、think-as-function 05/01 代定 3 加註。
