# 現況對照（11-05 早 `main` `ced4b157`；fable 照使用者定義量的，可翻案）

尺＝使用者 11-05 的三句：**kernel＝管理某 proc 是否可以執行**；**判斷後轉交給有權的 kernel 也算**；**判斷後直接跑 Linux 原生程序或函數的不算**。「掛在 daemon 底下」才算 aos 的 proc；掛在 Linux 底下（自己 fork）的不算。

## 哪些算、哪些不算

| 東西 | 做什麼 | 算不算 | 為什麼 |
|---|---|---|---|
| **aos-daemon** | 收 ctl 信箱／`procs_ctl.json` 的名單、照單把 proc 掛起、停、拔 | **算：最基礎的 kernel**（來者不拒） | 它就是「決定哪些 proc 在跑」的那個；名字不帶 kernel、不改（使用者「別濫用」） |
| **aos-llm-kernel**（今天） | 收請求信、排隊、額度，**自己 fork 子行程用 aos-exec 跑 endpoint 函數**（`serve.cpp` `fork`＋`run_inst`） | **嚴格說不算**（使用者「他的 proc 是掛在 linux 底下」） | 判斷後直接跑函數＝第三句。改成請 daemon 掛（[03](03-問腦改掛daemon.md)）才算；名字照舊 |
| **aos-daemon-ctl**、**aos-agent add／rm／start／stop** | 把人下的指令寫成一封 `procs_*` 信投進 daemon 的 ctl 信箱 | 不算 | 不做判斷、只是語法糖（人殼）；人才是在判斷的那個 |
| **aos-loop**、**aos-fsm** | 一次次跑、照結束碼選下一格 | 不算 | 不決定「掛不掛」；fsm 選格後直接跑函數＝第三句 |
| **agent-fsm 的 act 格**（`aos-tools call`） | 腦說要叫工具就直接跑 | 不算 | 第三句（判斷後直接跑函數） |
| **eca**（claude／codex CLI 當 agent） | 自己跑自己的 | 不算 | 它是被管的 proc |
| **10-15 通用 kernel 的判官設計**（N-42 (2)，現無實作） | 判官 agent 說「跑／不跑」、閘門照舊由 kernel 跑 | 設計方向算、但「kernel 自己跑」要改成請 daemon 掛 | 跟 llm kernel 同一個修法；落成 [02](02-兩種模式.md) 的模式 2 |
| **daemon 底下再掛一個 daemon** | 子 daemon 管自己的 proc | 算（子 daemon 自己是一個 kernel） | 父看它只是一個 proc（portable-flow「上不知下」） |

## 跟哪些條文、裁定衝突或要改

| # | 哪條 | 現在怎麼寫 | 跟 11-05 的關係 | 怎麼辦 |
|---|---|---|---|---|
| 1 | **C-47 aos 實作定義** | 「以 inst／loop／daemon 為基礎，能夠管理某一 inst 是否被執行的，一個正在執行、或是被執行的 inst」 | 相容，但沒說「被管的要掛在 daemon 下」；11-05 第三句把「自己 fork 跑」排除在外 | **收緊一句**：「被管的 proc 掛在 daemon 下才算；判斷後自己 fork 跑 Linux 原生程序或函數的不算；判斷後轉交給有權的 kernel 的算」。要不要收緊見 [05 衝突 1](05-衝突與方向題.md) |
| 2 | **10-13 kernel-agent 結論**（thinking） | 「能操控某些東西被執行的就算 kernel（**直接當宿主**、或寫檔給獨立的 daemon 讀都算）」 | **衝突**：「直接當宿主」＝自己跑＝11-05 說不算 | 後裁蓋前裁：10-13 那句加「11-05 改：直接當宿主的不算」註；見 [05 衝突 1](05-衝突與方向題.md) |
