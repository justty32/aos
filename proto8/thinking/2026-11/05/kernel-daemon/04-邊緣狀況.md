# 邊緣狀況（挖出來的；每條寫代定或現成機制，可翻案）

[think-as-function 04](../../04/think-as-function/04-邊緣狀況.md) 已列的（端點失敗、額度、取消、kernel 不在、沙箱、金鑰…）不重列；這裡只有「問腦改掛 daemon」與兩種模式新帶來的。

| # | 狀況 | 誰看到、怎麼辦 |
|---|---|---|
| 1 | kernel 不在任何 daemon 下（沒 `AOS_DAEMON`） | `DaemonMissing` 退 1、loop 停（P-20）；agent 停在 wait。demo 說明改成先起 llm daemon（[07](07-llm-daemon佈局.md)）。 |
| 2 | daemon 沒開 ctl 信箱（`procs_ctl_mailbox` 寫 `null`） | kernel `MailboxMissing` 退 1。合一的 llm daemon 定義不寫這個 key（預設開）。 |
| 3 | daemon 暫停中 | 掛信堆在 daemon 信箱、不套；kernel 每拍看表沒列、沒 applied＝繼續等，agent 等。daemon resume 那圈才掛。 |
| 4 | daemon 拒掛（壞信；只會是 kernel 自己的 bug） | 不回信、`mailbox_warning` 記那封；kernel 看到 warning 提到自己的掛信名＝`LaunchFailed` 回信、刪。warning 只留最後一封壞信：兩封同時被拒會漏一封→那封一直等；kernel 的 bug、不加機制。 |
| 5 | 掛信名字撞（表上已有 `llm_<id>`） | 同名 add＝設定換掉、已在跑不重起（N-54）：kernel 死掉重起、重掃 `cur/` 時列還在＝照 § 2 當在飛，不會重掛；只有列不在才重掛。 |
| 6 | endpoint 函數不存在、起不來 | aos-exec `EntryMissing` 到 `stderr.txt`、子 loop 退 1→`state.json` code 1→`EndpointFailed`＋stderr 第一行。 |
| 7 | 逾時 | 單子的 `timeout_ms` 由 aos-exec 收整群→code 143→`mounted_at`＋`timeout_ms` 已過＝`EndpointFailed 逾時`。 |
| 8 | llm daemon Ctrl-C 時正在問 | 問腦 loop 睡下（`sleeping`）、開門自動重跑一次→可能多花一次腦（端點收過了、回信沒落地）。使用者口徑「風險自擔」。 |
| 9 | daemon `kill -9`（子項活著） | 問腦 loop 照跑完、寫好 `state.json`／`reply.json`；daemon 再起 adopt：pid 活＝接回、死了＝列不接→kernel 看到 `state.json` 收尾＝完成；若 daemon 把「running 但 pid 死」的列當要起的再起一次＝重跑一次、覆寫成品——窗很窄、自擔。 |
| 10 | 兩次「沒答案」 | 重掛一次後仍沒收尾＝`EndpointFailed 問腦跑了兩次都沒結果`（[03 § 5](03-問腦改掛daemon.md)）。 |
| 11 | 有人對問腦列下 `stop`／`pause` | kernel 等到天荒地老（列在、沒收尾）；`priority.deadline` 已輪到也不管。掛在 daemon 上就看得見、就能被動——自擔。 |
| 12 | 表上多出來的列 | `aos-daemon-ctl ls`／`aos-agent ls` 看到 `llm_<id>`（loop 型、`def` null）：這是「統一管理 endpoint 呼叫」的樣子，不是雜訊；aos-agent 對它做事＝`InterfaceMissing` 一類，天然。 |
| 13 | portable-flow 衝突 3 若裁 (a)「wake 第一圈就退留 `stopped`」 | 問腦列失敗後留在表上（code 1）：kernel 收完成品後多寄一封 `procs_removed`（代定：收尾時列還在就拔，否則不寄）。 |
| 14 | 兩台 kernel（兩個代號表、兩份額度）掛同一台 daemon | 名字含信件名稱、各自 `cur/`，不撞；daemon 表上兩種列並存。 |
| 15 | 多台 agent daemon 共用一台 llm daemon | 請求信都進 `~/llm_kernel/mailbox/new/`，`slots`、`budget` 是全電腦共用的上限（使用者要的「統一管理」）；回信各自寄回各台 agent daemon 底下的 `think/reply/`（跨 stack 寫入＝同一帳號沒事，跨帳號照 WAIT_USER 既有的 `setup.sh --mailbox` 那題）。 |
| 16 | 搬家（portable-flow） | kernel 寄的掛信路徑絕對、由 daemon 存成相對（portable-flow 步 0）；在飛的 `cur/<id>/loop.json` 跟其他小格一樣靠 `{"$env": "AOS_DAEMON"}` 指示詞；`reply_to` 相對信箱根（步 2）；`proc.json` 沒路徑。睡著時搬＝問腦列 `sleeping`、新位置醒來重跑。llm daemon 整個資料夾（含 `def/`）一起搬最省事。 |
| 17 | 金鑰 | `request.json` 跑的期間含解好的金鑰，位置不變（信資料夾）；多了一份 `loop.json`（沒金鑰）。照舊靠 Linux 權限。 |
| 18 | 模式 1 判官身體慢 | daemon 那圈卡住、名單也慢；判官要問腦就改模式 2。aos-llm-kernel 當身體一拍只做收信、寄掛信、收成品，毫秒級。 |
| 19 | 模式 2 下 aos-daemon-ctl／aos-agent add 直達 daemon 信箱 | 同帳號擋不住（約定）；跨帳號 `MailboxBad` 當場退（Linux 權限，[02/01 § 3](02-兩種模式/01-唯一-AOS_KERNEL-命名.md)）。第一版不改它們；[06 步 6](06-實作步驟草稿.md)。 |
| 20 | `AOS_KERNEL` 指錯資料夾 | 掛信默默寄進一個沒人收的資料夾（aos-post 會建 `new/`）→ kernel 一直等。跟 edge-basics 題 1「打錯默默寄」同一題，使用者「自擔」。 |
| 21 | 子 daemon 當 proc、裡面再有 kernel | 子 daemon 的 kernel 掛在子 daemon 上（它的 `AOS_DAEMON`），父不知道（上不知下）；`AOS_LLM_KERNEL` 是人設的、跨層照樣可用。 |
