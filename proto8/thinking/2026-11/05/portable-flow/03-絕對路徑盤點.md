# 絕對路徑盤點：存相對 daemon、讀時從 `AOS_DAEMON` 拼回

使用者 11-05 patch：「用daemon作為相對路徑的一個基準點……以自己頭上最近的那個daemon為準，因為上不知下」；接著裁：不在 daemon 下的不管、指到外面自擔、子 daemon 與父就是 daemon／proc、「最近的上層 daemon」不用找——管我的那個就是。

## 原則（fable 照裁定收斂，可翻案）

1. **只改「存」的格式，不改「給」的格式**：daemon.json、信、`aos-daemon-ctl add` 給的路徑照舊（相對呼叫者 cwd、絕對都行，daemon 照今天先轉絕對）；**寫進 image 的那一刻**（表、小格 `loop.json`、信封）改成相對基準點；**讀出來的那一刻**（adopt、start／wake、`where`、aos-agent 讀表、kernel 回信）拼回絕對。對外介面（argv、環境變數、stdout）不變，`where` 仍印絕對。
2. **基準點＝管我的 daemon 的 stack**（＝那個 daemon 給子項的 `AOS_DAEMON`，結尾 `/`）。推薦理由在 [05 題 1](05-衝突與方向題.md)（三個候選：定義資料夾／stack／ws；image 本體就在 stack、每個 proc 本來就拿到 `AOS_DAEMON`，不多傳任何東西）。
3. **巢狀**：子 daemon 是父的一個 proc，它給自己子項的 `AOS_DAEMON` 是它自己的 stack（今天就是這樣，`dstack_`）→ 子 daemon 的表相對子 daemon 的 stack；父的表只有一列「子 daemon」相對父——「上不知下」自然成立，不用找標記檔、不用多傳變數。
4. **運行時的環境變數仍是絕對**（`AOS_DAEMON`、`AOS_KERNEL`、`AOS_WS`、`AOS_STACK`、`AOS_CF`、`AOS_CD`）：它們是這台「硬體」當下的位址，由起 daemon 那一刻決定、每次搬完重算；N-63「`AOS_DAEMON` 要絕對路徑」不變。只有**落在檔案裡**的才相對。
5. **指到 daemon 外面**（`../../agents/x`、`/home/u/repo/...`）：照寫、能解就解、解不開照今天各自的錯（`EntryMissing`、aos-loop 退 1）；不擋、不提醒（使用者「自行承擔」）。相對寫法會自然把「跟著一起搬的」保住、「沒搬的」斷掉——這就是使用者要的行為。
6. **symlink**：aos-exec 的 `abspath` 只收 `.`／`..`、不解捷徑（N-57 註）；相對化時也不解（用字串算，不 `realpath`），搬家時 symlink 當成普通路徑跟著走。
7. **工具 bin 本身**（aos-exec、aos-loop…）：不在 image 裡，靠 PATH（N-59「PATH 一律不動」照舊）；`lib/base/*` 這種資料夾程式由定義（source）用相對定義資料夾的路徑指，所以**定義要自帶或並排放它們**（[01 步 1](01-旅程對照.md)）。不加 `AOS_LIB` 之類的新變數。

## 用這個 patch 以後，搬家長什麼樣

1. 睡著（Ctrl-C）→ image＝`ws/.stack/`，裡面沒有一個絕對路徑。
2. 把 `agents/`（含 `daemon/`、`kernel/`、`lib/`）跟 `ws/` **保持相對位置**一起搬（或 git pull 下來）。
3. `cd ws && aos-exec ../daemon`：daemon 算出新的 `dstack_`，表上 `procs/fsm_ann`→新位置、`../../agents/fsm_ann`→新位置，wake；子 loop 解 `{"$env":"AOS_DAEMON","$path":…}` 拿到新位置的 `fsm.json`；kernel 回信相對信箱根、落在新位置的 `think/reply/`。
4. 視窗二 `export AOS_DAEMON=$PWD/.stack`（或 source 一行殼檔）→ `aos-agent listen`。

沒一起搬的（定義留在舊台）：醒來 `exec` 解到不存在的檔、子 loop 退 1、今天會下表（[05 衝突 3](05-衝突與方向題.md) 建議留列）。
