# J1 實作結果（11-06）

動了 `proto8/lib/tool_io.py`（73 → 364 行）、六支自己讀 stdin 的工具（`lib/base/{clock,math,llm_http,llm_fake}`、`lib/agent/{agents,pyfix}` 的 `_entry`，各只換讀 stdin 那幾行）與 [lib/docs/01](../../../../lib/docs/01-分層等.md) 規則 1、3、5a、9 和契約表。`cmd/`、`py/`、判官 `lib/aos/judge/`、所有 `_tooldef.json` 沒動。

## 做了什麼

1. **`--help` 多一段「Flags」**，從工具旁邊的 `_tooldef.json` 生：每個參數一行（旗標、型別、必填、預設、可選值、說明），巢狀物件往下縮排列 `--a.b`。工具手寫的說明照印在前面（J2 之前每支都有）。參數表是空的印 `Flags: none`（判官、clock、check_inbox）。
2. **旗標能當參數用**：`aos-exec lib/base/read --path a.txt --max-lines 1` 跟 stdin 給 `{"path":"a.txt","max_lines":1}` 一樣。連字號換底線；整數、數字照型別轉；開關 `--hidden`／`--no-hidden`；陣列重複給；物件給一整段 JSON，或用點路徑 `--set./k/b x` 只改一個鍵。
3. **兩邊都給＝旗標贏**，點路徑只換那一葉（stdin 裡同一個物件的其他鍵照留）；stdin 多的鍵照舊忽略；打錯旗標＝`FlagUnknown`。
4. **終端直接打不會卡**：stdin 是終端就當 `{}`、不讀。
5. **最小型別檢查**：照 `_tooldef.json` 查 `type`、`required`，不合＝`ArgumentsBad`。
6. 新的純函式 `argv_to_json`、`help_from_tooldef`、`tokenize_flags`、`load_tooldef` 可以單獨叫；`tokenize_flags` 是之後 `py/aos_flags.py` 要包的那一份（J5）。

## 代定（隊長；可翻案）

1. **`start()` 只管 `--help` 與訊號，argv 與 stdin 等工具叫 `arguments()` 才解**：判官收一個位置參數、不讀 stdin，只叫 `start`——這樣它一個字不用改。翻案＝`start()` 就解，判官要宣告 `positional` 或改呼叫。
2. **六支自己讀 stdin 的工具改叫 `arguments()`**（J2 的一小塊提前做）：不改的話 `--help` 印了旗標、旗標卻被默默丟掉。
3. **`enum` 不查**（06 原寫 type／required／enum）：規則 3 規定 op 給了不認得＝`OpUnknown`，那是工具自己的錯碼，共用層先擋會變成 `ArgumentsBad`。可選值只印在 `--help`、缺必填時附在錯誤原因後面。
4. **值是 `null` 當沒給**：腦常用 `"offset": null` 表示選填沒填，現況工具都收。
5. **`--help` 在 `--` 之前任何位置都認**（照現況，不照 P-44 的「旗標位置才認」）：少一種舊呼叫變行為。
6. **自由物件**（`object` 或沒型別、沒宣告 `properties`，例 json_edit 的 `set`、agents 的 `llm`）：點路徑之後任何鍵都收，值一律字串（不猜型別，C-56）。要數字、物件就整段 JSON 給 `--set '{"/k":5}'`。
7. **`_tooldef.json` 的退路**：沒有＝旗標全當字串、不報 `FlagUnknown`、不提醒；讀不了／不是 JSON／`parameters` 不是物件＝提醒行一行、同上；欄位缺或怪（`properties` 不是物件、`type` 不認得）＝安靜當沒有／沒型別。
8. 旗標出錯的原因後面加 `(see NAME --help)`；stdin 那邊出錯不加（腦看不到 `--help`）。
9. `tool_io.py` 364 行，超過 300 行門檻但**不拆**：它要能單檔複製進工具資料夾釘版（規則 9），拆了就要複製好幾個檔。

## 實測（WSL `/tmp/j1/`；codex 的完整紀錄在 `/tmp/j1/report.md`、`compat-report.md`）

- **純函式**：06 驗收那組 `["--max-bytes","10","--tag","a","--tag","b","--recursive"]` → `{"max_bytes":10,"tag":["a","b"],"recursive":true}`；`--bogus`＝`FlagUnknown`；`--a.b x` 套到 `{"a":{"c":1},"z":2}` → `{"a":{"b":"x","c":1},"z":2}`；另 27 組邊界斷言都過。
- **26 支用 tool_io 的工具（含判官）`--help` 都退 0、都有 Flags 段**。
- **四種給法一致**（codex 測 read／ls／json_read／一支物件參數的；隊長另跑 read、ls、json_read、json_edit）：只旗標、只 stdin、兩者都給（旗標贏：stdin 給 `b.txt`、旗標給 `a.txt`，讀的是 a）、巢狀（`json_edit --set./k/b x` 跟 stdin 的 `set` 合在一起、兩個鍵都寫進去）。
- **舊的 stdin 呼叫照舊**：27 支工具×4 種呼叫，新舊版逐一 `diff`（108 組）。有效呼叫的 stdout、退出碼全部一樣；差在兩處，都可接受——`--help` 多了 Flags 段；缺必填鍵的錯誤原因換成 `missing KEY (required)`（`op` 類附 `; one of: …`），代號都還是 `ArgumentsBad`、退 1。**唯一換代號的是 thought**：沒給 `goal` 從 `GoalMissing` 變 `ArgumentsBad`（見邊緣 1）。
- **型別檢查擋掉 5 組以前會過的**：都是工具本來就不看的鍵給錯型別（`memory` read 時給 `"query": []`、`llm_fake` 的 `endpoint` 給 `false`／`3`／`[]`／字串）。這些不合自己的 `_tooldef.json`，擋下來算對，照收。
- 終端直接 `ls --path .`：0.03 秒結束。判官：`--help` 退 0；不給參數仍是它自己的 `ArgumentsBad need exactly one argument…`。
- 把 `_tooldef.json` 弄壞五種（沒有、不是 JSON、沒 `parameters`、`properties` 是陣列、`type` 是 `"weird"`）各跑 `--help` 與帶旗標的呼叫：14 次都沒有 traceback，只有提醒行／錯誤行。
- code map 重生、wf-lint broken 0。

## 新發現的邊緣（沒修，攤出來）

1. **thought 的 `GoalMissing` 只剩一半**：沒給 `goal` 現在是 `ArgumentsBad`，給了空字串仍是 `GoalMissing`；它的 `_tooldef.json` 說明還寫著 `GoalMissing`。J2 改接時二選一：拿掉 `GoalMissing`，或把 `goal` 從 `required` 拿掉、讓工具自己判。
2. **過渡期兩種 `--help` 並存**（apply-ideas 04 #22）：手寫的「Arguments:」段跟生成的 Flags 段重複列同一批參數，J2 刪手寫那段就好。
3. **自由物件的值只能是字串**：`--llm.max-tokens 100` 給的是 `"100"`；要數字得整段 JSON。真的常用的話，在 `_tooldef.json` 補那一層的 `properties` 就有型別。
4. **`--help` 在任何位置都認**：`--content --help` 想寫字面 `--help` 進檔會印說明；要寫就走 stdin。
5. **`agent/claude`、`agent/codex` 有 `_tooldef.json` 但沒用 tool_io**（走 `cli_session.py`），所以沒有旗標也沒有 Flags 段——J2 的 E4 那條。
