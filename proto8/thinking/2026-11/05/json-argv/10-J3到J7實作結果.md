## J3 aos-tools 收口

**做了什麼**（`cmd/aos-tools/bin/aos-tools`、README、`cmd/docs/01`、`templates/agent-fsm/act.py`／`brain.py`、`cmd/aos-mcp`、templates／kernel／knowledge 文件各一句）：

1. **exe 工具也走 stdin（A3）**：三種工具（資料夾、JSON、可執行檔）一律 `aos-exec 路徑`、arguments 原樣從 stdin 進；`$AOS_STACK/tool_call.json` 與 `--tool-call` 沒了，exe 的 `StackMissing` 也跟著沒了。
2. **`add --env` 改名 `--envs K=V`（可重複）＋新 `--env-file FILE`（E3）**：舊名不留。
3. **小格由 `aos-tools call` 一處算（E2）**：有父 `AOS_STACK`＝子拿 `<父>/tools/<名>/`；act、brain（memory）、aos-mcp 不再自己算，只傳自己的 stack。
4. `ls --json` 行為不變，docstring 寫明「模型只看 description／parameters 是 brain／aos-mcp 自己挑的」。
5. **`add` 時工具宣告的 hub 變數（`_tooldef.json` 的 `env`）沒設＝提醒行（E5）**：`aos-tools: warning: tool X has unset hub variables: AOS_DAEMON`，照樣登記、退 0。
6. `call` 的 `--help`／錯誤行改回跟其他子命令一樣（拿掉 main 那層的暫時碼）。

**代定（codex 定、隊長審過；可翻案）**：

1. `--env-file` **在 add 當下讀、存內容**（不存路徑），之後改檔要 `add --override` 重登記；讀法照 aos-exec 的 `.env` 子集（24 份範例跟真 aos-exec 比過一樣）。
2. 優先順序分兩段做：add 時 `--envs` ＞ `--env-file`，合成登記格 `env`；call 時登記格 `env` ＞ 繼承的環境。跟 04 的順序同義。
3. 登記格 `env` **不能蓋 `AOS_STACK`**：有父 stack 用父的算小格，沒父就拿掉、交 aos-exec 給預設。
4. 小格要用工具名拼路徑，所以 call 會擋手寫登記檔裡不合法的名字（`../x`、尾端換行）＝`RegistryBad`；add 的名字檢查也改成整串比對。
5. 工具定義的 `env` 不是變數名陣列＝add 時 `ToolDefBad`（ls／get 照舊不驗）。
