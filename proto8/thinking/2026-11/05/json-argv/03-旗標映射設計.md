## 一句話

**`_tooldef.json` 的 `parameters`（JSON Schema）是唯一定義**：同一份生出 ① LLM tool schema（OpenAI function／MCP `inputSchema`，照原形）、② 旗標→stdin JSON 鍵的映射、③ 英文 `--help`、④ 最小型別檢查。純 aos 函數不再手寫旗標表。

## 映射規則（參照 argparse，只取 KISS 子集）

| argv 寫法 | stdin JSON | 說明 |
|---|---|---|
| `--path a.txt`／`--path=a.txt` | `"path": "a.txt"` | 連字號↔底線：`--max-bytes 10` → `"max_bytes": 10`（C-54：key 底線、指令名連字號，同一套） |
| `--limit 10`（schema `integer`／`number`） | `"limit": 10` | 照 schema 型別轉；轉不了＝`ArgumentsBad` |
| `--recursive`（schema `boolean`） | `"recursive": true` | 開關不帶值；`--no-recursive` → `false`；`--recursive=V`＝`ArgumentsBad`（同 P-44） |
| `--tag a --tag b`（schema `array`） | `"tag": ["a","b"]` | 重複＝累加；元素照 `items.type` 轉；非 array 的重複＝最後一個算（同 P-44） |
| `--opts '{"a":1}'`（schema `object`） | `"opts": {"a":1}` | 巢狀只收一整段 JSON 字串、解析失敗＝`ArgumentsBad`；不做 `--opts.a` 點路徑 |
| `--` | — | 結束旗標；之後全是位置參數 |
| 位置參數 | 照 `_tooldef.json` 選填 `"positional": ["path"]` 依序填鍵 | 沒宣告 `positional` 卻給了位置參數＝`ArgumentsBad`。純 aos 函數預設不宣告 |
| 沒有 schema（舊工具／沒 `_tooldef.json`） | 全當字串、無 `--help` 參數段 | 給人勉強用；不報 `FlagUnknown` |

- **不認得的旗標**（schema 裡沒這個 property）＝`FlagUnknown`；schema 有 `required` 卻沒給（旗標、stdin 都沒有）＝`ArgumentsBad`；一律 stderr 一行 `工具名: error: 代號 原因 (usage: …)`、退 1（N-43 續、P-44）。
- **型別只檢查 schema 的 `type`／`required`／`enum`**，不做完整 JSON Schema 驗證（aos-schema 隨 S10 封存；工具自己再驗細節，C-53 (a)）。`type` 是陣列（`["string","null"]`）取第一個非 `null` 的。
- **不做**：短旗標、`--key value1 value2`（nargs）、子命令（純 aos 函數＝一個 method；要子命令的是給人用的程式，走 aos_flags）。

## stdin 與旗標怎麼合併

1. stdin 是終端（`isatty`）＝`{}`，不讀、不卡（P-39「agent 類工具不讀 stdin 會卡」）；不是終端＝讀整段，空＝`{}`，不是 JSON 物件＝`ArgumentsBad`。
2. 旗標／位置參數**蓋**同名的 stdin 鍵（頂層鍵整個換，不深合併）——同 N-58「旗標 ＞ 環境變數 ＞ `.env`」的精神，**不報衝突錯**。
3. 腦叫的路（`aos-tools call`、aos-mcp、act 格）只給 stdin、不給旗標，所以映射對腦是零成本；人要用才打旗標。

## `--help`（英文）從同一份定義生

```
<name> - <description 第一句>
usage: <name> [--help] [--<key> <TYPE>]... [-- <positional>...]
  --path PATH        (string, required)  <property.description>
  --max-bytes N      (integer; default 50000)  ...
  --recursive / --no-recursive  (boolean) ...
  --tag T            (array of string; repeatable) ...
input : JSON object on stdin (same keys); flags override stdin keys
output: stdout, see <tool README>
errors: <name>: error: <Code> <reason>   codes: ArgumentsBad FlagUnknown ...
```
`default` 寫在 schema property 的 `default`（有就印；沒有照說明文字）；`errors:` 行的代號清單來自 `_tooldef.json` 選填 `"errors": ["PathMissing", …]`，沒寫只印兩個通用代號。工具另有人話說明仍可以用 `start(NAME, HELP)` 的 HELP 補一段接在後面。

- 現況是 `start(name, help_text, echo=True)`（`lib/tool_io.py:24`）只認 `--help`、其他 argv 默默不管；`arguments(*required)`（:61）只驗非空字串。改法：`args = tool_io.start("read")`，刪掉自己讀 stdin 與手驗型別的那幾行；`_tooldef.json` 不用改。
- `bin/aos_flags.py`（S5 後 `py/aos_flags.py`）的 `parse(argv, flags, switches=None, multi=None, help=None)` **保留給人用的程式**（旗標表、全字串、有子命令）；它的 tokenizer（`--x V`／`--x=V`／`--`／`--help`／FlagUnknown）跟 `argv_to_json` 是同一段邏輯——`aos_flags` 改成 import 隔壁 `lib/tool_io.py` 的 `tokenize_flags`，刪自己那份（去重；一份錯誤行格式）。`tool_io.py` 自己不 import 任何 aos 模組（釘版複製要能單檔跑，lib 規則 9）。

## C++ 側

- `aos::parse_cli`（`impls/aos-util/include/aos/cli.hpp`）保留：aos-exec／loop／fsm／daemon／post／llm 是給人與基礎設施用的、旗標表驅動，不需要 schema。
- **C++ 現在不做 schema 映射**：impls 裡唯二的「工具」`aos-json/tools/{json,json_edit}` 在 S10 併進 `lib/base/`（Python 殼叫 aos-json），走 Python 的 `tool_io`。將來若有 C++ 寫的工具，才在 aos-util 加 `Json argv_to_json(argv, const Json& schema)`，規則抄本檔、代號相同。
- aos-exec 不參與：它只保證 args 與 stdin 原樣送到入口（P-26、N-58），映射是入口（工具）自己的事（C-52）。

## 同一份定義 → tool schema（呼應 01 的無痛互轉）

- 給腦：`aos-tools ls --json` 已把 `_tooldef.json` 原樣包成 OpenAI function（名字由登記名填）；aos-mcp 把同一份 `parameters` 當 `inputSchema`。**不新增轉換層**，只把「旗標、help、檢查」掛到同一份上。
- 反向（tool 呼叫 → 執行）：`arguments` 原樣 stdin（P-41）；要用 shell 手打就是 `aos-exec <工具> --key v`，兩條路進同一個 dict。
- 給人用的程式（aos-post 等）**不生 tool schema**：agent 走 `bash` 工具叫它們、看 `--help`；要包成 tool 時另做一個資料夾工具（`_entry` 轉接＋`_tooldef.json`），不從旗標表反推 schema（型別資訊不足、也沒必要）。
