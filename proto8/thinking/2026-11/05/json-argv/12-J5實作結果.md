## J5 aos_flags 去重＋SIGPIPE

**做了什麼**（`py/aos_flags.py`、`lib/tool_io.py` 一行、`cmd/aos-agent/bin/aos-agent`、`cmd/aos-sandbox/bin/aos-sandbox`、py／cmd README、cmd/docs/02）：

1. `aos_flags.parse` 刪掉自己的切 token 迴圈，改包 `tool_io.tokenize_flags`（從自己的真位置找 `../lib/tool_io.py`）；短名表、`short=`、`-h`、`--help` 的時機、錯誤字串全部照舊。
2. `tool_io.tokenize_flags` 改一行：單槓 token（`-x=1`）不切 `=`、整個當旗標名（P-44 單槓規則；頂層同意）。lib 工具只差 `-x=1` 的錯誤訊息從 `unknown flag -x` 變 `unknown flag -x=1`，代號、退出碼不變。
3. **stdout 被對面先關（`| head -1`）＝安靜退 141**：`aos_flags.run` 接 BrokenPipeError（含最後那次 flush）。aos-agent 原本沒包 `run`，入口改成 `aos_flags.run(main)`。
4. aos-sandbox 自動綁 `proto8/py` 時也唯讀綁 `proto8/lib/tool_io.py`（不然沙箱裡 aos_flags import 不到）。

**代定（可翻案）**：

1. **不把 SIGPIPE 設回預設**（隊長）：run 包的程式常寫子行程的 stdin，SIG_DFL 會讓它們在子行程先退時被無聲打死；改成接例外。
2. **只有 stdout 真的沒人讀才退 141**（claude 隊員）：用 `poll` 看 stdout（Linux pipe 沒讀的人＝POLLERR）；寫子行程 stdin 撞到的 BrokenPipeError 照舊丟 traceback，不被吞成 141。
3. import 完 tool_io 就把 `lib/` 從 `sys.path` 拿掉（不然 `lib/aos`、`lib/agent` 會被當同名套件搶 import）。

**實測**（`/tmp/d-team/j5/`）：舊版＝HEAD、新版＝同一份只換兩檔；cmd 全部程式 70 層、每層十幾種旗標組合共 **2052 組，stdout／stderr／退出碼 diff 為空**；新舊 `parse` 隨機旗標表＋隨機 argv 20 萬次比對差異 0；lib 工具只差 `-x=1` 那句；`aos-tools ls | head -1`、`aos-agent --help | true` 等舊版 traceback（退 1 或 120）→ 新版安靜退 141；寫子行程 stdin、子行程先退的情境新舊一樣（沒被打死、也沒被誤判成 141）；沙箱裡 `aos-tools --help` 新版能跑。

**新邊緣**：

1. aos_flags 多了一個依賴：`py/` 與 `lib/` 要同層；單獨複製 `aos_flags.py` 出去不能用（py/README 寫了一句）。
2. 同一個行程先 import 了某工具資料夾裡釘版的舊 `tool_io.py`，aos_flags 會拿到那份（目前那條路只用 `die`／`warn`，沒影響）。
3. `poll` 判斷靠 Linux 行為；別的平台查不到就當 stdout 還好、照舊 traceback。
