## 時鐘檔格式

- 現行 `aos-tick FILE`：讀整數 n 寫 n＋1（C-44 實作註）。**不改**：時鐘檔＝一行十進位整數（沒有或空＝0）；寫法照 N-05 先 `.tmp` 再 rename。
- 不在時鐘檔裡放 `interval_ms`、`started_at`：時鐘只是一個數（C-44「不包任務、不保證什麼」）。要默契用 `AOS_TICK_INTERVAL`；sleep 邊緘要的東西列在下面、不在這一版定。
- 讀法：任何 aos 元件要「現在幾點」就 `read $AOS_TICK` 一次拿整數；比較期限＝整數比大小；tick 只增，所以沒有「時鐘倒退」這一類病（edge-round2 aos-lock 的修法可退役）。
- 建議提供 lib 小函數 `now_tick()`（C++ aos-util、Python lib 各一）：讀 `AOS_TICK`，沒設回 `nullopt`／`None`；呼叫端自己決定沒時鐘怎麼辦（下一段）。

## `AOS_TICK`／`AOS_TICK_INTERVAL` 沒設時

| 情況 | 推薦 | 理由 |
|---|---|---|
| `AOS_TICK` 沒設 | **時間不走**：所有 tick 期限視為「永不到」（lease 不過期、deadline 不過期、不判 stuck），每支程式只在 stderr 印一次 `warning: AOS_TICK unset, tick-based deadlines never expire` | 跟「凍住＝時間不走」同一條邏輯；不會偷偷混回牆上時鐘。單人手測不起時鐘也能跑。 |
| `AOS_TICK` 指到不存在的檔 | 當 0、不建檔 | 建檔是 aos-tick 的事；讀的人不寫。 |
| `AOS_TICK` 內容不是整數 | 錯 `TickBad`、退 10 | 跟 aos-json check 同一碼位。 |
| `AOS_TICK_INTERVAL` 沒設 | 預設 `1000`（毫秒） | 只給「人看、對外換算」用；內部邏輯禁止讀它。 |
| 兩者都設，但沒人跑 aos-tick | 同「時間不走」；daemon 的表可多一欄 `tick` 讓人一眼看出沒走 | 誰讓時鐘走是方向題 1。 |

替代（不推薦）：沒 `AOS_TICK` 就用 `AOS_TICK_INTERVAL` 從牆上時鐘反推 tick——凍住時全過期，正是要解的病。

## 跟 no-pid 監管樹、state.json 的關係

- 監管樹（[no-pid](../no-pid/README.md)）每層 daemon 判下層「有刺激沒反應→stuck」：**刺激時間與最近反應時間都記 tick**（state.json 加 `last_input_tick`、`last_react_tick`；`stuck_after_ticks` 在 daemon.json 設、沒設＝不判）。
- 時鐘的 aos-tick 本身就是一個 proc，掛在根 daemon 底下（跟其他 proc 一樣由 daemon.json 列）；它的 state.json 照常寫。它卡住＝整個樹時間停＝沒人會被判 stuck——這是**對的**（時間沒走），但人看不出。所以根 daemon 的表加一欄「tick 現值」，使用者看到不動就知道時鐘停了。
- 誰把 `AOS_TICK` 傳給下層：daemon 起 proc 時照「環境變數是預設管道」把自己的 `AOS_TICK` 原樣傳下去；proc 自己的 `--env-file` 可覆寫（多時鐘＝多個子樹各看自己的，C-37「可看可不看」）。
- daemon 對 Linux proc 的 3 秒／10 秒照舊用牆上時鐘（01 的 4、5），跟 tick 並存不衝突：一個對內一個對外。

## sleep 後重啟的邊緣（列出，不解）

1. aos-tick 寫到一半（`.tmp` 已寫、未 rename）被 sleep：rename 原子，醒來頂多少走一格——可接受，記下。
2. 凍住期間外部寫檔（HTTP 回信、人手改）：這些東西帶的是牆上時間，醒來後 `sent_at` 跟 `sent_tick` 對不上——要不要補 `sent_tick`、誰補。
3. 醒來時「現在幾點」：tick 接著走（推薦，image 語意）vs 按停了多久用 `AOS_TICK_INTERVAL` 補跳——使用者說之後處理。
4. 部分睡：只睡一個子樹，它看的時鐘若在別的子樹照走，醒來期限全過；若子樹有自己的時鐘才真凍。多時鐘的邊界要寫進 NORMS。
5. git 快照拿到的 tick 值與各 state.json 的 tick 不一致（沒全睡就 commit）——fs-image 已列。
6. 時鐘檔被人手改小：tick 倒退；要不要跟 aos-lock 一樣防，或規定「別亂弄」（N-02）。

## 跟 C-44／N-01／N-03 的衝突（要使用者點頭才改條文）

| 條 | 現文 | 新想法 | 衝突在哪 | 後果 |
|---|---|---|---|---|
| **N-01**「大家都要看 tick-tock 時鐘」 | 都要看 | 三類例外（人／外部／Linux proc）明寫允許牆上時鐘 | N-01 沒有例外；01 盤點有 9 處留牆上時鐘，照字面全違規 | 推薦：N-01 補一句「aos 內部互相約時間用 tick；對人、對外、對 Linux proc 用牆上時鐘」。不改＝這 9 處永遠掛衝突。 |
| **C-44**「tick-tock 就是一個時鐘、不保證什麼」 | 不包任務 | `AOS_TICK` 指它、daemon 表顯示它、lock／kernel 拿它比期限 | 不衝突——它仍只是一個數；但「沒時鐘＝時間不走」是新的**約定**，C-44 沒說 | 推薦：寫進 NORMS 當 N-04，不動 C-44。 |
| **C-37**「可看可不看」 | 不看也行 | lock／kernel 內部期限只認 tick | 不看時鐘的元件就沒有期限（永不過期） | 跟「可看可不看」一致，但要在 02 第二段的 warning 明說。 |
| **N-03**「tick 之間可安全打包、由 kernel 做」 | kernel 公告第 N 回合關機 | 打包＝全 sleep（fs-image） | 誰做：kernel 公告 vs 根 daemon 的 sleep 指令；N-03 說 kernel | 推薦：N-03 不改、補註「sleep 是 daemon 的手段、公告是 kernel 的事」；真衝突點是 kernel 要不要能叫 daemon sleep，列明天。 |
| 兩個新環境變數 | json-argv「環境變數是唯一不走 JSON 的、別濫用」 | 加 `AOS_TICK`、`AOS_TICK_INTERVAL` | 使用者自己說「實在很不想再添加」但「太香了」 | 已定，記著就好。 |
