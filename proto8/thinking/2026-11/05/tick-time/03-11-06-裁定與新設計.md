# 11-06 裁定與新設計（fable）

## 使用者裁定（11-06，逐字）

> 都按照推薦。然後每次都要我自己起loop-tick？喔天啊好麻煩，想想看，假如root daemon就是底下的那個硬體板子，在嵌入式中的那個內部晶振，應該也是板子附帶的，所以tick我希望能夠在daemon的設定中自帶(當然，不強制，不與daemon耦合)。沒設AOS_TICK=時間不走？這太粗暴了，在寫韌體的時候發現沒有timer可以參考，當然也還是可以寫啊，只是說你不確定每個函數、每個指令它具體的執行時間。而且我們還有一個逃生口：原生linux提供的實際時間函數。不用訂那麼死的，bruh。AOS_TICK_INTERVAL用一秒？我覺得這個可以再想想...不過現在就先用一秒吧。Q5就隨意。

## 由此定下的

- **Q1 改**：tick 時鐘可以寫在 daemon 的設定裡「自帶」（像板子附的晶振）；**可選、不強制、不與 daemon 耦合**。
- **Q2 改**：沒 `AOS_TICK` **不是**「時間不走」；沒 tick 可參考照樣能跑，只是不知道過了幾個 tick；**逃生口＝Linux 牆上時鐘**；不訂死。
- Q3：`AOS_TICK_INTERVAL` 先用 1000 毫秒，之後再想。
- Q4：照推薦（欄位改名帶 `_tick`／`_ticks`）。
- Q5：隨意 → 代定照推薦（daemon 的 3 秒／10 秒維持牆鐘）。
- 另（apply-ideas D1）：凍住先只有硬凍。

## 新設計一句話

**時鐘是 daemon 設定裡的一個選填 key `tick`，daemon 只做兩件事——把它展開成一個普通的 loop 型子項去跑 `aos-tick`、把時鐘檔路徑用 `AOS_TICK` 傳給底下所有人——自己不讀時鐘；要期限的人寫 tick 數，有 `AOS_TICK` 就比 tick，沒有就用 `AOS_TICK_INTERVAL`（預設 1 秒）換成牆鐘算，記錄裡牆鐘欄一律照寫、tick 欄有時鐘才寫。**

## 一、自帶 tick：daemon.json 的 `tick` key（代定，可翻案）

```json
{"procs": {...}, "tick": true}
{"procs": {...}, "tick": {"file": "clock", "interval_ms": 1000, "name": "_tick"}}
```

- `true`＝全用預設：時鐘檔 `<daemon stack>/tick`、每 `AOS_TICK_INTERVAL`（沒設＝1000）毫秒一格、子項名 `_tick`。物件可改三格；`file` 相對 daemon 的 stack 算（表上照 11-05 存相對 stack 的路徑，搬家跟著走）。沒寫 `tick`＝daemon 完全不管時鐘（現況）。
- **展開**：daemon 讀到 `tick` 就在 `procs` 裡多一列 `"_tick": {"exec": ["aos-tick", "<file>"], "interval_ms": N, "stack": "<stack>/procs/_tick"}`，**之後一切照一般 loop 型子項**：起、停、sleep／wake、表上一列、`ctl ls` 看得到、人可以 `pause`／`stop` 它。daemon 程式裡沒有任何「讀 tick 檔」「等 tick」的碼——這就是「不耦合」。
- **`AOS_TICK` 的來源與傳遞**：daemon 起來時，有 `tick` key → 自己行程的 `AOS_TICK`＝那個檔的絕對路徑（每次開門重算，跟 `AOS_DAEMON` 同法），底下子項照環境變數繼承；沒 `tick` key → `AOS_TICK` 照繼承的（上一層 daemon 的、或人 export 的）、沒有就沒有。**近的贏**：子 daemon 自己寫了 `tick` 就換成自己的時鐘，它底下的子樹全看它（多時鐘＝多子樹，C-37「可看可不看」）。
- **替代（不推薦）**：不加 key，範本 daemon.json 手寫一個 `tick` 子項＋`.env` 寫 `AOS_TICK`——每個 daemon 定義都要抄兩處、路徑要人算絕對；使用者原話「在daemon的設定中自帶」就是要一個 key。
- **為什麼不是 aos-loop 層**：loop 不管子項、沒有「底下所有人」可傳；根 daemon＝板子，晶振在板子上。

## 二、沒 tick 怎麼算：兩鐘規則（代定，可翻案）

| 情況 | 怎麼算 | 說明 |
|---|---|---|
| 期限寫 tick（`lease_ticks`、`deadline_tick`、`stuck_after_ticks`、`timeout_ticks`）、有 `AOS_TICK` | 讀時鐘檔整數比大小 | 凍住＝時鐘不走＝期限不到 |
| 期限寫 tick、**沒** `AOS_TICK`（沒設或檔不在） | **退牆鐘**：`ticks × AOS_TICK_INTERVAL` 毫秒，從「現在」起算（單調鐘） | 逃生口；凍住再醒會過期——沒 tick 就沒有凍住時間的保證，寫明 |
| 期限寫毫秒（`timeout_ms`、`interval_ms`、daemon 3 秒／10 秒） | 永遠牆鐘 | 對外、對 Linux proc、對人那三類 |
| 兩種都寫（`timeout_ms` 與 `timeout_ticks`） | 寫壞 `ArgumentsBad`／`CfgBad` | 擇一，不猜哪個優先 |
| 記錄欄（`sent_at`／`sent_tick`、`acquired_at`／`acquired_tick`、`responded_at`／`responded_tick`）（**11-06 改讀**：使用者 11-06 選「照命名法 (Recommended)」——時間點照 C-54 R6 寫 `<事件>_at_ticks`：`deadline_tick`→`deadline_at_ticks`、`sent_tick`→`sent_at_ticks`、`acquired_tick`→`acquired_at_ticks`、`responded_tick`→`responded_at_ticks`；多久的 `lease_ticks`、`stuck_after_ticks` 不變，[lift-to-norms](../../06/lift-to-norms/README.md)。） | **牆鐘欄一律寫；tick 欄有 `AOS_TICK` 才寫**（沒有就整欄不出現，不寫 null） | 讀的人：有 tick 欄且自己有時鐘＝比 tick；否則＝拿牆鐘欄算 |
| `AOS_TICK` 指的檔內容不是整數 | `TickBad` 退 10 | 同 aos-json check 碼位 |
| `AOS_TICK_INTERVAL` 沒設 | 1000 | 使用者「先用一秒」；內部只在退牆鐘與人看換算時讀它 |

- 提供一個小函數給大家用（T1）：`deadline(ticks)` → 有時鐘回「到第幾 tick」、沒時鐘回「牆鐘到幾點」；`expired(d)` 照型別判。C++ 在 aos-util、Python 在 `lib/tool_io.py`（工具）與 `py/aos_ws.py`（cmd）各一份。
- **不印 warning**：沒 tick 現在是正常狀態（逃生口），不是異常；要看有沒有時鐘看 daemon 表的 `tick` 欄（T7）。推翻 02 的「印一次 warning」。
- 跟 02 相比**變的只有一列**（沒 `AOS_TICK` 那列）；時鐘檔格式、`now_tick()`、欄位改名、三類留牆鐘都照舊。

## 三、混用的坑（規則寫進 N-04）

1. **時鐘檔過舊**（`AOS_TICK` 有設、但 `_tick` 子項死了或被人 stop）：tick 期限永不到、毫秒期限照到——同一台裡兩種期限步調不一致。**不自動退牆鐘**（退了就把「凍住再醒」當成過期，正是要解的病；凍住跟時鐘死在檔案上長得一模一樣）；靠表看（`_tick` 列 `stopped`、頂層 `tick` 欄不動）。要不要自動重起 `_tick` → N1。
2. **寫的人有時鐘、讀的人沒有**（跨樹、沙箱沒綁、人殼）：讀的人拿牆鐘欄算（規則表第 5 列）。**寫的人沒時鐘、讀的人有**：記錄沒 tick 欄＝照牆鐘欄算。所以牆鐘欄不能刪——T2 的 aos-lock 名牌保留 `acquired_at`、再加 `acquired_tick`／`lease_ticks`。
3. **兩棵樹各自的 tick 不能比**：`sent_tick` 只在同一時鐘下有意義；跨樹看 `sent_at`。「同一時鐘」＝`AOS_TICK` 解開後同一個檔；讀的人不去驗，寫進規矩。
4. **`AOS_TICK_INTERVAL` 兩邊設得不一樣**：退牆鐘換算不同。接受，預設 1000、文件寫「別亂設」；真要改一棵樹一起改（放根 daemon 的 `.env`）。
5. **沒 tick 時凍住**：醒來 tick 類期限全過（因為退了牆鐘）——寫一句「要凍住時間就要有 tick；沒 tick 的樹凍住等於一般 sleep」。
6. **人手 export `AOS_TICK` 又在 daemon 寫 `tick`**：daemon 的贏（近的贏）；人殼自己（不在樹裡）看自己 export 的。

## 四、邊緣（新形狀才有的；02 與 apply-ideas 04 列過的不重講）

1. **daemon sleep／wake**：`_tick` 是 loop 型，收工 SIGTERM（aos-tick 一次只寫一格、rename 原子，最多少一格）、表留 `sleeping`，開門 wake 接著數——image 語意自然成立，不用特別做。
2. **daemon 自己 paused**：daemon 暫停不暫停子項，`_tick` 照走、時間照走，只是 daemon 不起停東西；對（daemon 的 pause 是它自己的手把）。
3. **人 `pause _tick`**：時間停、工作照跑——「暫停時間但不暫停世界」，是個現成的新手把（軟凍的另一半）；危險在忘了 resume → 期限永不到（坑 1）。文件寫一句。
4. **起的順序**：daemon 照 `procs` 順序起，`_tick` 排第一（展開時插最前）；第一格要等一個 `interval_ms` 才出現，之前讀檔＝沒有＝當 0——期限從 0 起算、單調，沒事。
5. **`tick` 的 `file` 寫絕對路徑、兩份 daemon.json 複製**：兩台 daemon 寫同一個檔＝兩倍速。預設相對 stack 就不會；寫絕對自擔（portable-flow「指外面自擔」）。
6. **子 daemon 自帶 tick、父 sleep**：子樹整個睡（P6），子的 `_tick` 也睡；醒來子樹看自己的時鐘接著數。父子時鐘值不同本來就不能比（坑 3）。
7. **`_tick` 子項的 log**：`--enable-logs` 時每秒一行洗版（kernel-daemon 08 看過身體 0.3 秒一行）；展開時給它 `logs: false`（若 daemon 有這格）或文件寫「別開」。
8. **`_tick` 名字撞使用者自己的 proc**：`_` 開頭留給 daemon 展開的子項；撞名＝`CfgBad`。
9. **adopt 接回時 `tick` key 變了**（人改了 file）：舊 `_tick` 列照表接回（還在寫舊檔）、新 `AOS_TICK` 指新檔→ 子項看空檔。規矩：改 `tick` 要 sleep 整台再改再 wake（跟改任何 proc 定義一樣）。
10. **T5 inst `timeout_ticks` 誰判**：照兩鐘規則退牆鐘後 aos-exec 本來就有 `timeout_ms` 的路；有時鐘時要 poll 檔——仍傾向由 loop／daemon 這層判，aos-exec 不加（apply-ideas 04 #14）。
11. **P7 stuck 沒 tick 時**：`stuck_after_ticks` 退牆鐘＝原本 no-pid 06「N 秒」的樣子，行為一樣；有 tick 時凍住不誤判。兩種都對。

## 五、新方向題（最多 3 題；推薦放第一）——**11-06 已裁**

> 使用者 11-06（逐字）：「那兩題都按照推薦。」

**由此定下**：N1——自帶（`tick` key 展開）的 `_tick` 照 P6 daemon 型「就是要一直在」的規則重起（退了照表重起、連 3 次失敗留 `stopped`），人下 `stop`／`pause` 的不重起，手寫成普通 proc 的照 N-28 不重起；N2——時鐘檔過舊不自動退牆鐘、不 warning，靠 daemon 表（`_tick` 列、頂層 `tick` 欄）看。原題與選項留著對照。

### N1 `_tick` 子項死了或被停，時間就停：要不要自動重起？（已裁：照推薦）

- **自帶（`tick` key 展開）的 `_tick` 照 P6 daemon 型「就是要一直在」的規則重起（退了照表重起、連 3 次失敗留 `stopped`）；人下 `stop`／`pause` 的不重起；手寫成普通 proc 的照 N-28 不重起 (Recommended)**。後果：晶振是板子附的、壞了板子修；多一條「展開的子項算 daemon 型」的小規則；人停的仍是手把。
- 都不重起，靠表看（`_tick` 列 `stopped`、頂層 `tick` 欄不動）。後果：零規則；但時間默默停、期限永不到，要人發現。
- 都重起（任何 loop 型退了都重起）。後果：改了 N-28 整條，影響所有子項。

### N2 時鐘檔過舊（有 `AOS_TICK`、很久沒動）要不要自動退牆鐘？（已裁：照推薦）

- **不退、也不 warning，只靠表（`_tick` 列、`tick` 欄）看 (Recommended)**。後果：凍住再醒跟時鐘死掉在檔案上一樣，退了就把凍住當過期；N1 照推薦時「死掉」會自己好，剩「人停的」本來就是故意的。
- 超過 N × `AOS_TICK_INTERVAL` 沒動就退牆鐘。後果：凍住 8 小時醒來全過期——回到 11-05 夜要解的病。
- 過舊只印 warning、不退。後果：每個讀的人都要算 mtime，多一段碼、多一條規則，換到的只是提醒。
