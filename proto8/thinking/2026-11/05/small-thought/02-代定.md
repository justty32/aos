# 代定（可翻案）

## 1. 工具的形狀：`lib/agent/thought/`

一個 lib 工具（P-41：stdin 進、stdout 出、退 0／1；lib 契約規則照 `agents`）。**stdin 一份 JSON、沒有 op**（只做一件事）：

| 欄 | 必要 | 意思 |
|---|---|---|
| `goal` | 是 | 要做什麼、**要帶回什麼**（一句到幾句） |
| `context` | 否 | 父給子的背景：字串或字串陣列（前幾步的結論就放這裡）。**不自動複製父的 history**（沿 10-24 定 2：fork 給的是摘要） |
| `tools` | 否 | 子要配的工具 `[{name, path}]`，形狀同 `agents add`；沒給＝只有 `clock`。記憶任務就配 `memory`（想指定知識庫就照 agent-knowledge 的做法給一個小資料夾） |
| `endpoint` | 否 | 子的腦代號；沒給＝同父（題 1 已裁：預設同父） |
| `max_chars` | 否 | 結論上限，預設 600；子超過就截、尾巴加 `[truncated]` |
| `timeout_s` | 否 | 預設 600、上限 1700（跟 `agents ask` 同；act 格 1800 秒包得住） |
| `keep` | 否 | 預設 **false**：做完就 `rm` 子的 stack、不印 `details:`；`true` 才保留供追查（題 2 已裁：「可選。默認刪掉。」） |

stdout（給腦看的，英文）：結論本文；`keep: true` 時多最後一行 `details: agents/<子名>/`（相對管我的 daemon，照 portable-flow 的相對路徑規矩），預設沒有這行。退 0。

## 2. 它是 `agents` 的包裝，不是新機制

`thought` ＝ `agents new`（範本 **demo/agent-fsm**、名字 `t-<父名>-NNN` mkdir 搶號）→ `agents ask`（文字＝system 加一段固定開場：你是一個小念頭，只負責這一件事；做完**只回結論**、不寫過程、≤ max_chars 字；接著 goal、context）→（預設）`agents rm`；`keep: true` 才不刪。三步都走 `aos-agent`，掛在同一台 daemon、同樣過判官 `max_running`；子名記進 `children.json`（跟 `agents` 共用，之後腦要 `agents say` 追問同一隻也行）。**不在 `agents` 裡加 op**：agents 管「長住的子」，thought 管「用完即走的子」，分開兩個工具腦比較不會混。

**fork＝新開乾淨的子**，不複製父的 context：（a）10-24 已這麼定；（b）父的 history 可能很長又帶著別的題；（c）要帶什麼父自己寫進 `context`，正是「主線只剩短短幾句」的對偶。要「帶父最後 N 則」的，日後長一個 `context: {"history_tail": N}` 物件（C-55 純值長成物件、key 不變），這版不做。

## 3. 記憶任務＝一類 goal（使用者補句）

工具不加 `kind` 欄、不做專用模式。文件（`_tooldef.json` 的 description 與 knowledge/aos 的一節）給兩個範例：
- 做事：`{"goal": "Find which files under src/ import foo and list them", "tools": [{"name": "fs", …}]}`
- 凝聚記憶：`{"goal": "From the knowledge base, gather everything about endpoint packs and give me one sentence (<=200 chars) I can reuse", "tools": [{"name": "memory", "path": "…/lib/agent/memory"}], "max_chars": 200}`

「加入自身記憶」這半句：這版結論回到父的 history 就算「加入」（主線 context 就是它的工作記憶）；要**寫進知識庫**＝另一個 goal、子配一個會寫的工具（memory 這版唯讀，先不碰）。

## 4. 串接 A→B→C

腦自己串：第 1 步叫 `thought`，拿結論；第 2 步叫 `thought`，`context: ["Step A concluded: …"]`；以此類推。並行＝一回合裡發多個 tool_calls（act 格本來就會逐個跑；要真並行得等 act 支援多工具同時起，這版不做）。深度上限：thought 把 `AOS_THOUGHT_DEPTH=<父+1>` 放進子的環境（`agents add` 的 limits／env 哪個能帶，實作時看），預設 **2**（子還能再開孫、孫不行）；超過＝`DepthExceeded` 回給腦。

## 5. 錯、逾時、太長、花費

- 子退非 0／逾時／`AnswerMissing`：stdout 與 stderr 各一行 `thought: <代號> <原因>`、退 1；act 把那行回給腦、不停（10-24 定）。逾時時子整群先收（規則 5）。**失敗時 stack 一律留**（不管 keep；好查為什麼壞）、錯誤行尾附 `(details: agents/<子名>/)`——代定，可翻。
- 結論太長：子端 system 已要求上限；父端再截到 `max_chars`、加 `[truncated]`（`keep: true` 時細節仍在 details；預設刪了就只有這截過的）。
- 子再 fork：允許到深度 2；額度不另設整棵樹上限（判官 `max_running` 已擋總數；agent-gus 的 `THOUGHT_MAX_TOTAL` 不復刻）。
- 花費：每個 thought 至少一次 `new`＋一輪 ask；用 `endpoint: "stupid-fast"` 省錢；kernel 寄件人額度（feat-proto 件 5）照寄件人算，子算自己。
- 代號：ArgumentsBad、GoalMissing、DepthExceeded、DaemonMissing、StackMissing、PathBad、LaunchFailed、CommandFailed，以及 aos-agent 原樣轉的（AddRejected、AnswerMissing…）。
