## 一頁結論

- **錢花在哪**：閒著的一拍，真正的判斷只是「看幾個資料夾空不空、幾個檔在不在」。量到的 120～200 ms 幾乎全是 Python 起動加 import。
- **主幹的做法**（推薦，方向由使用者定）：寫一支 C++ 小程式（暫名 `aos-idle`），每拍先由它判斷「確定沒事」。確定沒事就不起 Python；有任何說不準的就照舊起 Python。Python 那幾支不用改寫，行為由它們說了算。
- **等價怎麼保證**：C++ 只擋三種「確定沒事」——信箱空、時間沒到、相關的檔跟 Python 上次看過時一樣。再加一個保底拍（例如每 60 秒照舊起一次 Python）。
- **估計**：閒置輪詢約 4.3 核 → 第 3 刀做完剩約 0.3～0.45 核，第 4 刀做完約 0.15～0.2 核（整棵樹沒人問腦時）。全是照報告的數字估的，每刀做完要實量。
- **順帶發現**：`lib/` 裡 208 支 `.py` 只有 25 支有 `.pyc`，入口又關掉寫 bytecode，所以每次起動都重新編譯原始碼。補上 `.pyc`，`aos-eca-turn` 起動省約 45%、`idle.py` 約 35%、`kernel_llm` 約 45%（[06](06-這次補量的數字.md)）。這不是 C++ 重寫，但半天做得完，忙的時候也省。
- **報告沒算到的一塊**：agent-fsm 在 `wait` 格等腦回信時，一樣每拍起一支 Python（`wait.py`）再加一支 `aos-llm recv`。等一次 30 秒的腦，就是 45～70 拍，每拍一支 Python。這算「忙」不算「閒」，所以沒進 4.3 核，但同一個辦法擋得掉。

## 名詞

- **一拍**：aos-loop 或 aos-daemon 跑一次身體（`exec`）。現在閒著也是每 300 ms 一拍。
- **閘**：身體之前先問一次「這拍要不要跑」的小程式。回 10＝這拍跳過，回 0＝照跑。
- **保底拍**：不管閘怎麼說，隔一段時間照舊跑一次身體。用來接住閘沒想到的情況。
- **記號**：一組檔的「在不在、inode、大小、修改時間」加資料夾裡的名字。兩次記號一樣＝這些檔沒變。

## 使用者的答覆（11-24，逐字）

「1.a 2.收 3.60秒 4.照推薦 5.a。不用調整間隔」

- 1 a：C++ 閘＋小程式（判斷寫成函式庫，之後可升進引擎）；不整支改寫三支 Python。
- 2 收：閒著時的行為差異接受，保底拍 60 秒。
- 3 context_wrap 改 60 秒。
- 4 kernel 先只掛閘，量過再選。
- 5 a：`.pyc` 直接放 `lib/`（第 0 刀；要改「庫的資料夾不留 `__pycache__`」那條慣例）。
- 不做止血（閒著的 agent 的 `interval_ms` 不調）。
- 施工排在 templates 三分切換之後，照 04 的刀序派核心程式位子與範本位子（eca-aos 11-24）。
