# 01 閒著時判斷了什麼

← [入口](README.md)

讀的是 main `519318a2f` 的原始碼。路徑照切換後寫（[入口的對照表](README.md#路徑的寫法)）。「拍」＝身體跑一次。

每一節的表有三欄：

- **做什麼**：Python 現在每拍做的事，照程式的順序。
- **閒著時的結果**：沒事的時候這一步的結果。
- **C++ 怎麼接**：`搬`＝C++ 自己判斷；`記號`＝C++ 不懂內容，只看檔有沒有變；`放行`＝C++ 一看到這個情況就起 Python；`留`＝只在 Python 做。

**為什麼「有信就一律放行」不靠記號**：`--on-busy yield` 時，畫面被人佔著（lock 拿不到、有人接著、`busy.txt` 在），Python 把這批留在 `cur/`、退 0。這時 stack 裡的檔都沒變，但下一拍要再試。畫面空不空不在記號裡，所以只要 `new/`、`cur/` 有信，就照現在每拍起 Python。

**閒著的最小集合（eca）**，照這個順序，第一條成立就停：

1. 這次 loop 起來後還沒放行過 → 放行（接住第 1、2、5、6 步與開場白）。
2. `queue/{tmp,new,cur}` 少一個 → 放行。
3. on_clock 有哪個到了（摘要檔不在、讀不懂、是別次 loop 寫的，也算到了）→ 放行。
4. `cooldown.json` 在而且還沒到 `until` → 跳過。
5. `new/` 或 `cur/` 有信，或 `retry.json` 在 → 放行。
6. 離上次放行超過保底的時間 → 放行。
7. 記號（冷卻三態、`goal.json`、`history.jsonl`、`retry.json`、hook 清單檔）跟上次放行時記的一樣 → 跳過；不一樣 → 放行。

每次放行都把當下的記號記下來（放行**之前**取的），給下次比。

## 4. on_clock 的 hook：`context_wrap`

程式：`py/aos/agentlib/hook_clock.py`（到了沒）、`py/aos/agentlib/hooks.py`（`fire`）、`py/tools/agent/context_wrap/_entry`（handler）。掛在 `templates/agents/agent-fsm/hookeds.json` 與 eca 三份範本的 `hookeds.json`（`templates/agents/` 的 `eca-claude`、`eca-claude-alt`、`eca-pi`），`every_ms` 都是 5000。

on_clock 沒有自己的行程：它是身體（`aos-eca-turn`、fsm 的四格）每拍開頭順手看的。到了才經 `aos-exec` 起 handler。同一份清單上還有 `mail_notify`（60 秒）與 `timer`（300 秒，handler 什麼都不做）。

**「到了沒」那一問**（`hook_clock.clock_tick`，每個 on_clock hook 各做一次）：

1. 讀 hook 清單（定義的幾層加 stack 那份，`null` 是關掉）。
2. 找時鐘檔：沒寫 `clock` 鍵＝`$AOS_CLOCK`；寫路徑＝那個檔；寫名字＝叫 `aos-agent ctl ls --json` 查（查到會記住）。
3. 讀時鐘檔的數字（cycle）。
4. 讀 `$AOS_STACK/hookeds/<名>/on_clock.json`：上次跑的 cycle、哪個時鐘、哪一次 loop。
5. 第一次、換了時鐘、cycle 倒退、換了一次 loop＝立刻跑；否則 `cycle - 上次 >= 間隔` 才跑。
6. 要跑就先寫 `on_clock.json` 再起 handler。

**`context_wrap` handler 自己做的**（每 5 秒一支 Python，約 60～100 ms）：

1. 讀 stdin 的事件 JSON、驗 config（`percent`、`wrap`、`window`）。
2. 讀自己小格的 `state.json`（phase：`idle`／`wrapping`／`compacting`／`compacted`）。
3. `context_use.read(stack)`：讀 agent 最後一輪的 token 讀數。
4. 照 phase 決定：過門檻就寄收尾信；收尾信答完而且 queue 空就寄 `/compact`；壓完記一筆；之後讀到別的一輪、低於門檻才回 `idle`。
5. 有換 phase 才寫 `state.json`。

閒著時的結果：phase 是 `idle` 或 `compacted`，讀數沒變，什麼都不做。

**關鍵觀察**：`context_wrap` 看的東西（token 讀數、信答完了沒、queue 空不空）**只在一輪跑完時才會變**。agent 閒著的時候，每 5 秒跑一次得到的答案一定跟上次一樣。所以它不必照時鐘跑，改法見 [03 第 6 節](03-優化方向.md#6-context_wrap-的頻率)。

**C++ 要接的**：只接「有沒有哪個 on_clock 到了」。做法是 Python 每次 `clock_tick` 完，多寫一個摘要檔（見下），C++ 只讀它跟時鐘檔。hook 清單怎麼疊、時鐘怎麼找、handler 怎麼起，都留在 Python。

### on_clock 的摘要檔

`$AOS_STACK/hookeds/on_clock_next.json`（暫名），`clock_tick` 算完順手寫，內容沒變就不寫：

```json
{"loop": ["<boot_id>", 12345, 678910],
 "clocks": [{"clock": "/…/clock", "cycle": 120}],
 "lists": {"/…/hookeds.json": [inode, size, mtime_ns]}}
```

- `loop`：寫的那次 loop（`state.json` 的三欄）。跟現在這次不一樣＝C++ 當作到了。
- `clocks`：每個時鐘檔，最早哪個 cycle 會有 hook 到。C++ 讀時鐘檔的數字，`>=` 就放行。沒有 on_clock hook＝空陣列。
- `lists`：這次讀到的每份 hook 清單檔的記號。有一份變了（`self_hook add`／`rm` 會改 stack 那份）＝C++ 當作到了，Python 重算。
- 摘要檔不在、讀不懂＝放行。寫不成＝只是每拍都放行，退回現在的行為。

## 5. 報告沒算到的：fsm 的 wait 格（`wait.py`）

報告只算「閒著」。但 agent-fsm 在 `wait` 格有兩種長時間的等，一樣每拍起 `aos-fsm` 加 `wait.py`，成本跟 idle 格差不多（每隻約 0.2 核）：

- **等腦回信**：信寄出去了（`pending` 檔有信名），每拍 `aos-llm recv` 看回信到了沒。
- **冷卻中**：腦失敗後照階梯等 30 秒到 1800 秒（`cooldown.json`），每拍起來看一眼就退 10。

`wait.py` 每拍做的（644 行，這裡只列跟「還要等」有關的；開工前要再逐條對一次）：

| 做什麼 | C++ 怎麼接 |
|---|---|
| `H.clock_tick()` | 同上，讀摘要檔 |
| `pending` 檔不在（還沒寄）：比對 `request.json`、`llm.json`（定義與 stack 兩份）、`history.jsonl` 新舊；`AOS_LLM_KERNEL` 有沒有設；冷卻三態；請求的 `deadline` | 記號：這幾個檔加冷卻三態。冷卻中而且不是「kernel 資料夾剛出現」＝跳過 |
| `pending` 在：`aos-llm recv`，回信箱的 `new/` 有沒有那封 | 搬：回信箱的 `new/` 有東西＝放行 |
| 回信沒到：看 kernel 的 `requests/new/`、`cur/` 還有沒有那封，沒有就重寄 | 搬：那兩個位置都沒有那封＝放行 |
| 等太久的提醒（`slow_step`、`warn_slow`），照等了多久分級 | 這是照時間的。保底拍會跑到，但提醒會晚到最多一個保底時間；或把分級的秒數搬進 C++ |

這一塊放在[第 5 刀](04-分刀與順序.md#第-5-刀wait-格)。

## 6. 順帶：`_clock`

`aos-clock` 每秒一支 Python（70～80 ms），整棵樹只有一隻，約 0.07 核。它做的事是把時鐘檔的數字加一。這是最好改寫的一支（幾十行 C++），但金額小，排在最後。

## 總表：哪些留在 Python

| 東西 | 留在 Python、有事才起 | 搬到 C++ |
|---|---|---|
| 收信、讀信、接進 history、回答配對 | 是 | 只搬「信箱空不空」 |
| hook 清單怎麼疊、handler 怎麼起 | 是 | 只搬「on_clock 到了沒」，而且是讀 Python 寫的摘要 |
| 冷卻的階梯、怎麼記失敗 | 是 | 只搬「現在是沒有／冷卻中／到了」 |
| goal、compact、開場白、`/clear` | 是 | 不搬，只看檔有沒有變 |
| `cli.json`、`kernel.json` 的驗證 | 是 | 不搬，只看檔有沒有變 |
| kernel 的排隊、額度、判決 | 是 | 只搬「`new/`、`cur/`、`held` 都空」 |
