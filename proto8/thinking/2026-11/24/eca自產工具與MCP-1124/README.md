# eca 自產工具與 MCP（發想，2026-11-24）

← 使用者 11-24 原話：「可以的話去幫忙延伸一個想法：假如eca自己透過aos產出了不少工具，是否要再弄一個mcp用於存放這些他自己的工具？」

這份只發想、不定方向。沒改任何程式、範本、知識庫。

## 三句話

1. **這台 MCP 今天就在**：每隻 eca 起 CLI 時都接一台 `aos-mcp`（工具名 `mcp__aos__*`），它讀的是「這隻自己的登記檔」。eca 把工具夾 `self_tools add` 進去，下一則回覆就叫得到，不用重起。所以「每隻 eca 一個私有工具箱，經 MCP 掛回自己」不用再做。
2. **另起第二台 MCP 換不到新東西，還多三個麻煩**：新的一台要重起 CLI 才看得到；多一個會掛的行程；同一支工具可能出現兩個名字。
3. **真正還沒有的是三樣**：工具夾放哪（今天沒有慣例）、多隻 agent 怎麼共用一批（今天只能一隻一隻掛）、共用之後怎麼防改壞（實測有兩個洞，見邊緣狀況）。

## 使用者的答覆（11-24，逐字）

「1.好，不另起。2.不設限，想放哪放哪。3.不設限，隨意處理。4.清單？啥？我是建議agent自己管理工具，反正agent有self_tools，agent就自己找地方維護自己的小筆記，筆記上寫說自己有哪些工具可用，agent就在有需要的時候掛上工具用，不需要的時候自己拿下來，倒是可以做一個self_tools --once的選項，就是一次性，用完就拿掉，或是--twice...。5.不管」

- 1 不另起 MCP，用現有的 `aos-mcp`。2、3 不定慣例。5 不另做回退機制。
- 4：agent 自己管工具——在自己的小筆記記有哪些工具可用，要用才 `self_tools add`、用完自己拿下來；另做一個「用幾次就自己拿掉」的選項（once／twice…），派核心程式位子做（eca-aos 11-24）。
- 使用者接著說（逐字）：「把內建的工具蓋掉？不管，這是一種使用方式。」——共用包同名蓋掉庫存工具不算洞，是一種用法，不修。
