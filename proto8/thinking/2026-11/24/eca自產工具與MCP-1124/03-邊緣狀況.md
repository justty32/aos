# 03 邊緣狀況

← [README](README.md)

「實測」＝在 `~/.aos/scratch/eca-mcp-idea-1124/` 手動對 `aos-mcp` 送 JSON-RPC 看到的（腳本 `t1.sh`）。路徑從 `proto8/` 算。

## 改壞了

**1. 腳本改壞（實測）。** 改 `run.py` 存檔就生效，下一次呼叫就是新的。沒有通知、沒有回退。壞了腦看到的是：

```text
aos-mcp: error: CommandFailed hello exited 1 with empty stdout
```

後面附 stderr 最後 2048 位元組。一隻自己用，這樣很好（改完馬上試）。共用時，甲改壞，乙下一次呼叫就中，乙不知道是誰改的、什麼時候改的。

**2. `_tooldef.json` 改壞（實測）。** 這支工具從清單裡**靜靜消失**。腦再叫它只得到 `no such tool: hello`，沒有原因。原因那行（`tool hello skipped: ...`）只印在 `aos-mcp` 的 stderr，腦看不到。要知道去跑 `self_tools ls` 才會看到 `broken: ...`。

**3. 登記檔壞了、或疊的包檔不在（實測）。這條最重。** 整台全掛：每一支 aos 工具都回 `ToolsBad`，**包含信箱那幾支**。下一次起 CLI 時 `aos-mcp` 直接退 1：

```text
aos-tools: error: PathMissing .../st/tools.json#/$override/1: .../lib/shared.json does not exist
aos-mcp: error: ToolsBad aos-tools ls .../st/tools.json exited 1
```

那隻 eca 就完全沒有 aos 工具，也收不到「為什麼」。起 CLI 前只查登記檔在不在，不查讀不讀得懂（`py/aos/agentlib/cli_mcp.py:253`）。CLI 那一側會不會提醒，沒測。

放到共用包上想：一個人刪掉或寫壞那份包檔，所有疊它的 agent **同時**失去信箱工具，而且沒辦法用信回報。

## 撞名

**4. 同名（實測）。** 三種情況，行為不一樣：

- 自己 `self_tools add` 一個已有的名字：`ToolExists`，擋下。要 `"replace": true` 才蓋。這個安全。
- `"$override"` 疊兩份，兩份有同名：**後面的贏，不出聲**。實測共用包裡放一支叫 `math` 的，庫存的 `math` 就被換掉，清單上看不出來。換成 `mailbox_send` 也一樣。
- 另起第二台 MCP：兩個名字並存（`mcp__aos__x`、`mcp__lib__x`），腦要自己選。知識庫對外部 server 已經寫過「一台只挑一條路」（`knowledge/aos/cli/mcp_import.md` 最後一張表下面）。

## 什麼時候生效

**5. 新工具、新的一台（部分實測）。**

- 經 `self_tools add`：下一則回覆就有（11-10 用 haiku 實測過）。
- 從外面加（eca 用 Bash 跑 `aos-tools add`，或別隻往共用包加一支）：**要等這隻下一次叫任何一支 aos 工具**，通知才送出（實測：加完沒有任何訊息，叫一次 `math` 之後才來 `list_changed`）。整輪都沒叫 aos 工具，就整輪看不到。
- 新的一台 MCP server：`mcp.json` 是起 CLI 時讀的。開著畫面的 eca 是一個長命的 CLI，要關掉畫面重開才有。Claude Code 的 `/mcp` 可以手動重連，但那是人在畫面上按的。

所以「工具加進現有那台」當輪生效，「另起一台」要重起。這是不另起的主要理由。

**6. 工具清單一變，對話開頭的快取就失效**（`knowledge/aos/packs.md:53`）。長對話的 eca 每加一支，整段對話重算一次錢。自己加可以挑時間、一次加完。共用包被別人加一支，所有疊它的 agent 各掉一次快取，時間不是自己挑的。

**7. 每支工具都是固定成本（實測數字）。** 範本 18 支的定義共 13,847 字，每次呼叫都送。自產工具一支約 300～1,200 字（`q146` 是 1,172 位元組）。掛 30 支大約多一倍。Claude Code 有「工具太多就延後載入」的機制，範本限制了內建工具，它會不會啟用沒測。

## 誰能寫

**8. 權限與「防失誤」等級。**

- 全部 agent 同一個 Linux 帳號，誰都改得動任何工具夾。aos 的限制本來就只防失誤、不防故意（`knowledge/aos/rules.md:31`）。
- `aos` 那台是整台預先核准的（`cli_mcp.py:199`）：新工具掛上去，不問就能叫。eca 本來就有 Bash，所以沒有多開洞。但共用之後變成「甲寫的程式，乙不看就會跑」。
- `_metainfo` 的 `side_effect`、`arbitrary_exec` 是寫工具的人自己填的，沒人查。`aos-mcp` 會把 `side_effect: false` 轉成「唯讀」提示交給 CLI（`py/aos/apps/mcp/main.py:142-153`）。填錯就是對 CLI 說錯話。
- 對照：外部 MCP 的工具，aos 選了「凍結，更新要人看過差異」，理由就是怕對方偷換說明（`thinking/2026-11/11/new-tools/03-mcp-client.md:22`）。自產的共用庫今天是即時的，沒有這層。這不一定要補，但等級不一樣，要知道。

**9. 版本與回退。** aos 沒有工具版本。登記檔記的是路徑，同一個路徑內容換了就是換了。回退靠工具夾所在的 git；放在 stack 或 `~/.aos` 底下就沒有。甲要舊版、乙要新版時，只能複製成兩個夾、兩個名字。

## 掛了

**10. MCP 伺服器自己掛了。**

- 現在的樣子：`aos-mcp` 是 CLI 的子行程，一隻一台。掛了只影響那一隻，下次起 CLI 會重起。對話中途掛掉，Claude Code 會不會自己重連沒測。
- 工具本身每次呼叫是新行程，一支掛了不影響櫃台（實測）。逾時會整群收掉。
- 如果做成共用的一台常駐 server（02 的乙三）：一掛全掛，要有人顧它、重起它，還要回答「它算哪個 daemon 底下的 proc」。這是新開的一整塊。

## 兩種腦共用

**11. fsm 與 eca 共用同一支。**

- 名字不一樣：fsm 看到 `q146`，eca 看到 `mcp__aos__q146`。角色卡、系統文字提到工具名時要想好寫哪個。
- 起跑的地方不一樣：經 aos 是從工具夾起跑、帶 `AOS_WS`、`AOS_STACK` 與一個小格；Bash 直接跑是當下的資料夾、什麼都不帶。腳本不要靠 cwd 與 `AOS_*`（ops 的 `run.py` 就是這樣寫的）。
- codex 身起 MCP server 不帶父行程的環境，aos 只明列七個 `AOS_*` 進去（`cli_mcp.py:100-101`）。工具要別的環境變數，在 codex 身上拿不到，要用 `envs` 或 `env_file` 掛。
- 輸出長度：eca 吃得下長輸出，fsm 的小模型不行。共用的工具要照小的那邊設計。

**12. 說明怎麼讓腦讀懂（部分實測）。**

- `self_tools ls` 只給第一句。第一句要自己站得住。
- `tools_def check` 會真的跑說明裡的 `Example: {...} -> 結果` 並比對（`knowledge/aos/tools_def.md`）。這等於說明的測試，自產工具值得都寫。
- 說明改了會通知（實測），但也會掉一次快取（第 6 條）。
- 兩份說明會走樣：`_tooldef.json` 一份、README 清單一份。只留一份當正本比較穩，清單用生成的。
- 語言沒定：`q146` 的說明是中文。小模型讀中文說明準不準，沒測。

**13. Claude Code 的子 agent 用不到自產工具。** 子 agent 那台不帶 `--own`（`cli_mcp.py:216-224`）。eca 把事派給子 agent 時，工具「不見了」，腳本路徑反而能用。這是「腳本加薄包裝」那個做法的另一個好處。

## 搬家與消失

**14. 清單會掉、路徑會斷（部分實測）。**

- `aos-agent tools reset`、換 kit：自己掛的全部退掉，沒有別處記著掛過哪些。
- 工具夾搬位置：變成 `broken`，要 `rm` 再 `add`。
- 登記檔存的是絕對路徑（實測）。家機與公司 WSL 路徑不同（例如 `/mnt/c/...`），而且 stack 不跟 git 走。換一台機器，「同一隻」eca 沒有這些工具，要重掛。`self_tools add` 的 `path_json` 可以寫 `{"$env": ..., "$path": ...}` 避開，但要先有一個指到工具庫的環境變數。
- 開著畫面與 loop 同時 `add` 會不會互相蓋掉，沒測。
