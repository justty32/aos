給使用者的五題：要不要另起 MCP、放哪、怎麼共用、掛進清單的門檻、改壞怎麼回退，每題附推薦與理由。

# 04 題目

← [README](README.md)

大方向是使用者的。下面的推薦只是我照查到的東西排的，哪一題想走別的路都可以。五題都還沒做任何事。

## 第 1 題：要不要另起一台 MCP 放 eca 自己的工具

- a. **不另起，用現有 `aos` 那台**（推薦）
- b. 每隻 eca 另起一台私有的（`mcp__mine__*`）
- c. 一台共用的常駐 server，大家連

**推薦 a。** 理由：

- 「工具夾 → MCP 工具」今天就通，而且當輪生效；另起一台要重起 CLI 才看得到（03 第 5 條）。
- b 多出來的只有名字上的區分，來源欄已經看得到。
- c 要回答「誰在叫」「誰顧它」「掛了怎麼辦」，是新開一整塊，換到的只是少起幾個行程（03 第 10 條）。

什麼時候該改選 c：工具需要**跨呼叫記住東西**（登入狀態、開著的瀏覽器、連線池）。aos 工具每次都是新行程，做不到；那種才值得一台常駐的。今天看到的自產工具（`q146`）不是這種。

## 第 2 題：自產的工具夾放哪

- a. **各自工作區的 `tools/<名>/`，加一份 `tools/_index.json`**（推薦）
- b. 放 stack
- c. 一個機器共用的夾（例如 `~/.aos/tools/`）
- d. 不定，各隻自己決定（現況）

**推薦 a，並寫進知識庫成慣例。** 理由：

- 工作區多半有 git，回退有著落（03 第 9 條）；stack 與 `~/.aos` 沒有。
- 別隻找得到：看那個工作區的 `tools/_index.json` 就知道有哪些（`index_view` 一行一支）。
- 跟 ops 已經在做的一樣（`wf/org/tools/`），只是把位置講定。

a 的代價：工作區不同的 agent 要用絕對路徑去掛別人的工具，換機器會斷（03 第 14 條）。真的要跨工作區共用，是第 3 題。

## 第 3 題：多隻 agent 共用一批工具，怎麼做

- a. **照現在：一隻一隻、一支一支 `self_tools add`**（先這樣，推薦）
- b. 做共用包：一份登記檔，各隻疊進 `"$override"`，往包裡加一支大家都有
- c. 不共用，各做各的

**推薦先 a；符合下面的門檻再做 b，而且 b 之前先補兩個防呆。**

門檻（可以直接照著判斷）：同一批工具有 **3 隻以上** agent 要掛，或這批超過 **5 支**。沒到就 a，掛的次數還數得出來。

b 之前要補的兩個防呆，都是實測到的洞：

1. 共用包裡的名字蓋掉庫存工具時要擋或至少警告（今天不出聲，03 第 4 條）。
2. 包檔不在或壞了，只少那一包，不要整台掛、連信箱都沒了（03 第 3 條）。

不補就做 b 的後果：一個人寫壞一份檔，所有疊它的 agent 同時沒有 aos 工具，而且沒辦法寄信說。

## 第 4 題：什麼樣的工具才掛進工具清單

- a. 做了就掛
- b. **有條件才掛，其他留腳本**（推薦）
- c. 都不掛，eca 一律 Bash（ops 現在的做法）

**推薦 b。** 掛的條件，中一條就掛：

- fsm 也要用（它沒有 Bash，只能走工具）；
- 要讓 aos 的 hook 或呼叫紀錄看得到它被叫；
- 每天都用，怕壓縮後忘記有這支。

其他的留成腳本，在 `tools/_index.json` 寫一行就好。一套多步、要判斷的做法，放 Claude Code 的 skill（平常只佔一句話）。

理由：每掛一支，每次呼叫都多送它的定義（03 第 7 條），每加一次掉一次快取（03 第 6 條）。可以拿一個數字當上限：一隻 eca 自己掛的不超過 **10 支**（大約多 8,000 字、比範本原本的 13,847 字多六成）。超過就該回頭看哪些其實用腳本就好。

不管掛不掛，工具都照「腳本加薄包裝」寫（邏輯一份、包裝三個小檔）。這樣之後要掛、要給 fsm、要給子 agent，都不用重寫。

## 第 5 題：改壞了怎麼辦、要不要做版本

- a. **靠 git 加維護人，aos 不另做版本**（推薦）
- b. 共用的工具比照外部 MCP「凍結」：登記時抄一份定義，更新要有人看過差異才生效
- c. 每支工具夾帶版本號，登記檔記版本

**推薦 a。** 做法：

- 工具夾放在有 git 的地方（第 2 題的 a 已經帶到）。
- 共用的那批指定一個位子維護，別人只回報、不直接改（ops 已經這樣：現場位子維護、ops 核對後 commit）。
- 改完跑一次 `tools_def check`，說明裡的 `Example:` 會被真的執行比對。

理由：b、c 都要新做東西，而今天壞掉的主要原因會是「改腳本改錯」，git 就回得去。b 擋得住的是「說明被偷換」，那是防外人的，自己人之間先不需要。

什麼時候該回頭選 b：共用包真的做了（第 3 題 b），而且往包裡寫的 agent 超過一個位子。那時「甲寫的、乙不看就跑」才成立。

## 不列成題目、順手記的

這些是查的時候看到的小洞，跟方向無關，要不要修由 eca-aos 排：

- `_tooldef.json` 壞掉的工具靜靜消失，腦只得到 `no such tool`（03 第 2 條）。
- `reset`、換 kit 之後，沒有地方記著自己掛過哪些（03 第 14 條）。
- 從外面改了清單，要等下一次叫 aos 工具才通知（03 第 5 條）。
