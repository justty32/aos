## eca 今天拿到哪些 aos 工具

範本 `eca-claude` 給五包、共 18 支：gadgets（`peek_clock`、`peek_now_time`、`math`）、self（只開 `self_tools`、`self_state`）、mailbox、json、index。

- 清單在 `templates/eca-claude/tools.json:1-6`：`"$override"` 疊五個包檔，`tools` 那格關掉五支。
- 檔案與指令不給 aos 的，用 Claude Code 自己的 `Read,Write,Edit,Glob,Grep,Bash`（`templates/eca-claude/cli.json:2`）。
- `tools_def`（做新工具的那支）11-22 起不在範本裡，要用先 `self_tools add`（`knowledge/aos/me/self_tools.md` 的 ToolDefMissing 那條）。

## 怎麼拿到的：一台 aos-mcp

全部經 MCP。Bash 是另一條路，下面講。

1. aos 每次起 Claude Code 前，寫一份 `mcp.json`，裡面一格 `aos`，指令是 `aos-mcp`（`py/aos/agentlib/cli_mcp.py:180-202`、`:262-269`）。
2. 給 `aos-mcp` 的參數帶 `--own <stack>/tools.json`，就是這隻自己的登記檔（`cli_mcp.py:248-259`；哪一份算自己的在 `py/aos/agentlib/cli_cfg.py:124-127`）。
3. 整台一次准：`--allowedTools mcp__aos`（`cli_mcp.py:199`）。這台上任何工具都不會問權限。
4. `aos-mcp` 自己不懂工具。列清單交給 `aos-tools ls --json`，叫一次交給 `aos-tools call`（`py/aos/apps/mcp/main.py:160-189`、`:192-212`）。
5. 清單每次列、每次叫都重讀。叫完發現清單變了，就送 `notifications/tools/list_changed`（`main.py:317-325`）。所以 `self_tools add` 之後同一輪就叫得到。11-10 用 haiku 實測過（`thinking/2026-11/10/tools-def/02-裁定後施工.md:31`）。
6. Claude Code 的子 agent 拿的是另一台 `aos_sub`，只有九支唯讀工具，而且**不帶 `--own`**：eca 自己加的工具不會進子 agent 那台（`cli_mcp.py:216-224`）。
7. 範本另有 `--strict-mcp-config`（`cli.json:2`）：只認 aos 寫的那份 `mcp.json`。這件今天另一隻在修，這裡不碰。

外部的 MCP server 另有兩條路，跟這題有關所以列出來：

- `cli.json` 寫 `mcp_servers`，讓 CLI 自己連（`cli_mcp.py:13-39`；範本沒寫這格）。
- `aos-mcp-import` 把外部 server 的工具「凍結」成 aos 工具（`py/aos/mcp_freeze.py`、`py/aos/mcp_client.py`；說明在 `knowledge/aos/cli/mcp_import.md`）。

## eca 自己做的工具今天放哪

**沒有規定的地方。** 知識庫只說「先把工具檔寫在你的工作區」（`knowledge/aos/me/self_tools.md` 的 rules 段），例子用 `tools/math`、`my_tools/mul`。

實際看到的做法是 ops 那邊（`/mnt/c/code/guanyu/ops-notes/wf/org/tools/`，只讀）：

- 一個工具一個夾（`q146/`）：邏輯在 `run.py`，旁邊三個薄檔 `_entry.json`、`_tooldef.json`、`_metainfo.json`。
- fsm（巡檢）掛成工具 `q146`；eca 用 Bash 直接跑 `run.py`。
- 夾在一個 git repo 裡，有維護人（現場位子），README 有工具清單。

要說清楚的一點：**eca 其實也能把 `q146` 掛成 `mcp__aos__q146`**（`self_tools add` 絕對路徑就行）。ops 選 Bash 是選擇，不是做不到。兩條路的差別：

| | 掛成 aos 工具（經 MCP） | Bash 跑腳本 |
|---|---|---|
| 每次呼叫佔多少 context | 工具定義每次都送。實測範本 18 支共 13,847 字；`q146` 一支 1,172 位元組 | 不佔。要用時才讀 README |
| 腦怎麼知道有這支 | 在工具清單裡，壓縮後也在 | 要有人寫在筆記或 README，壓縮後可能忘 |
| aos 的 hook、呼叫紀錄 | `before_tool`／`after_tool` 看得到；`--enable-logs` 會記 | 看不到（要用 Claude Code 自己的 hook） |
| 參數 | 有參數表（schema），腦照表填 | 命令列字串，自己拼 |
| Claude Code 的子 agent | 用不到（見上面第 6 點） | 用得到 |
| 逾時 | `_metainfo` 的 `timeout_ms`，沒寫是 60 秒 | Bash 自己的上限 |
| fsm、codex、pi | 都能用 | fsm 沒有 Bash 就不能 |

## 別的 agent、下一次的自己怎麼找到

- **下一次的自己**：掛過的工具記在 `<stack>/tools.json`，stack 還在就還在，每次起 CLI 都會列出來。沒掛、只是放在工作區的腳本，靠自己的筆記。
- **別的 agent**：找不到，除非有人告訴它路徑。aos 沒有「機器上有哪些自製工具」的目錄。`self_tools ls` 只列自己的。
- **會掉的時候**：`aos-agent tools reset`、換 kit（`ctl set-def --kit`）會把 `<stack>/tools.json` 整份換掉，自己掛的全部退掉。工具夾的檔還在，但清單沒了，也沒有別處記著「我掛過哪些」（`knowledge/aos/kits.md:20`）。
