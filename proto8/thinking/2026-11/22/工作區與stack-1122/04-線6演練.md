- **腳本做好、演練全過。** 同一支腳本跑了七次全套或退回：成功三次、中途失敗退回三次（一次是真的 bug、兩次是故意的）、清單對不上停在 `check` 一次。每次退回之後，舊樹的八列都醒成 `running`。
- **三個 subagent 可以安全地從外面掛回**，不用等 eca-aos 醒來自己 `rm`／`add`：

- **演練的 eca 沒有開過 claude 對話**：PATH 最前面放一支假 `claude`，被叫到只記一行就一直睡。整場被叫兩次，都是我故意開的畫面；`claude -p` 一次都沒有。

## 演練環境

- 暫存夾 `~/.aos/scratch/ws-stack-1122-home-rehearse/`，裡面的 `home/` 當假家目錄：
  - `home/repo/aos`：HEAD `63e24aaa9` 的 `git archive`，在它的 proto8 跑過 `install.py`。
  - `home/aos-home`：`rehearse-prep` 只讀地抄活樹的 `.stack`、`root`、`perm`、`agents`、`env.sh`、`README.md`、`root.log`，`llm` 用 `rsync --exclude='*.bak-*'`。兩份 `README.md.bak-*` 不抄，放一行占位，讓頂層清單跟活樹一樣。
- 跑腳本時只給 `HM_HOME=<假家目錄>`、`HM_PATH_PREPEND=<假 claude 的夾>`、`HM_GIT_REPO=~/repo/aos`，其他路徑都從 `HM_HOME` 推。
- **抄本要先處理三件事**（`rehearse-prep` 做）：
  - **活樹的絕對路徑換成假家目錄的**：抄來的表上，subagent 的 `as_written.stack` 是 `/home/lorkhan/aos-home/.stack/procs/…`；`exec.json` 的 `AOS_NOTIFY_BOX` 也是。不換的話，演練的舊根會去起活樹的 subagent stack，subagent 也會把通知寄進活樹 eca-aos 的信箱。
  - **開機碼換成全零**：表與 state 窗記著活樹行程的 pid 和開機碼。daemon 本來就會看 `/proc/<pid>/environ` 認出別棵樹的行程、不接回（`adopt.cpp` 的 `same_tree`）；換開機碼是第二道保險。副作用：演練的舊根把五隻 eca 當成「機器重開過」，列成 `stopped`，要手動 `ctl start`。真跑不會這樣，舊根是好好 shutdown 的。
  - **端點只留 `fake*`**，預設端點 `fake`。

## 演練抓到、已修

1. `check` 原本只要 tmux session 在就擋。退回之後，舊根就住在同一個 session 的 `old-root` 視窗，所以改成只擋已經有 `llm`、`root` 視窗的情況。
2. `--stack-json {"$env": "AOS_DAEMON", …}` 是 `aos-agent` 在送信前先在呼叫端解一次（subagent 工具裡本來就有 `AOS_DAEMON`）。從外面掛時沒設就 `DirectiveBad`，所以掛子那一行補 `AOS_DAEMON=<_stack>`。
3. 搬好並開了新樹的畫面之後再 `rollback`，原本不會關那個畫面。那個 claude 會留著，對著一棵停掉又搬走的樹。現在 `rollback` 先關新樹開著的畫面。

## 查到的事（給真跑）

- **外面那個 Claude 的殼帶著十幾個 `CLAUDE_CODE_*`**（含 `CLAUDE_CODE_MESSAGING_SOCKET`），`env.sh` 只清其中三個。所以每個 tmux 視窗的 runner 都會清掉全部 `CLAUDE*` 與 `TMUX`，開畫面、跑 aos 指令前也一樣。
- **還留著舊路徑的只剩執行期檔**：`claude/mcp.json`（每次起 CLI 前重寫，`cli_mcp.py` `mcp_argv`），以及 `hookeds/screen_linger_stop`、`brain_notify` 的上一次 `event.json`。`verify` 只把它們列成 warning。它們都在 `stack.gitignore` 擋的範圍，不會進換機 commit。
- **`cp -a` 帶過去的 `claude/a2a.json`** 指著舊畫面的收件 socket。新的 loop 只在自己這一格（新路徑、新 socket）的畫面開著時才投遞，所以用不到它。新畫面開起來時會重寫。
- **`claude/session.txt` 跟著抄**，工作區又沒變（`~/repo/aos`），新的 eca-aos 應該會 `--resume` 同一段 Claude 對話。演練用的是假 claude，**這一點沒驗到**。
- **我沒有對真位置跑 `check`**：它會 ping 活樹的 daemon、試活樹 `.stack` 的鎖、問開著的畫面 tmux，違反硬規則 1。只用唯讀的 `ls`、`cat`、`/proc` 核對過：清單、帳的舊格式、四格 stack、同一顆碟、`_stack` 與 `.llm-stack` 都還不在，這幾項現在都對。真跑第一步由外面那個 Claude 跑 `check`。
