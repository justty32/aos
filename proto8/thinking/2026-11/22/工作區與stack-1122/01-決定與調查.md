## 決定

| 題 | 定了什麼 |
|---|---|
| A(a) | 根 `.gitignore` 忽略 `_stack`；換機那次強制加，只加該帶走的檔。 |
| B | 工作區（cwd）大家都是 `~/repo/aos`；私有地盤另配 `wf/ws/<agent>/`，subagent 的地盤嵌在上層地盤裡（例 `wf/ws/eca-aos/eca-aos-templates/`）。 |
| C | 私有地盤進 git；任何一層的 `temp/` 都不進；commit 前檢查要進追蹤的檔大小，太大＝agent 不守規矩。 |
| D | `_stack` 取代 `~/aos-home`。 |
| 換台節奏 | 換台前一定 shutdown 再 commit，同一時間只有一台在跑（使用者「1.接受。」）。 |
| git 狀態 | `git status` 永遠是髒的沒關係；commit 只交自己改的；`_stack` 只有換機時才 commit。 |
| 目的 | 私有地盤是未來權限的基礎；現在先讓各 agent 有自己的地盤。 |
| 不列入 | `.claude` 相關的都不管：repo 的 `.claude/`、`~/.claude/`、`~/.claude.json`。 |

沒回答、照規矩不追問的：

- 單檔大小門檻（eca-aos 提議 1 MB）。規劃給一個可調的預設值。
- `wf/` 改名 `_ws/`：使用者第 1 句問過、後來沒再提，B 的分法用的是 `wf/ws/`。這次不改名。

eca-aos 已攤給使用者、使用者沒反對的坑：

1. 對整個 `_stack` 用 `git add -f` 會把鎖、`live.jsonl` 一起加，要一支「換機 commit」小工具只加該帶走的。
2. `_stack` 被忽略後，第一次換機 commit 前，`git clean -fdx` 會刪光它。
3. 大小門檻提議單檔 1 MB，檢查放在 commit-request 交件那一步。
4. 搬家：定義進 repo、在 `_stack` 起新 daemon、重掛 eca-aos 與三個 subagent（`eca-aos-templates`、`eca-aos-kb`、`aos-eca-frontend`）、停 `~/aos-home`。eca-aos 開著畫面，搬時要使用者關掉重開。公司那台也要搬一次並改 kernel_gate 放行範圍。
5. 三個絕對路徑要改程式才換得了台。

### 「只加該帶走的檔」做得到（暫存夾裡試過，試完已刪）

把活樹的 `.stack` 抄一份到暫存的 git repo 當 `_stack`，根 `.gitignore` 寫 `_stack/`，再跑：

```sh
git ls-files -o --exclude-from=<stack.gitignore 那份規則> -- _stack
```

這一行不看根 `.gitignore`、只照 stack 的排除規則列檔：160 個檔裡列出 63 個、合計約 99 KB（最大的是 `history.jsonl` 24 KB）；被排除的是 `claude/` 底下的畫面檔、`hookeds/`、清道夫報告、鎖這些。把這 63 個 `git add -f` 之後：改到已追蹤的檔 `git status` 會顯示、新檔不顯示；**`git stash` 會把追蹤中的 stack 檔倒回去**（試過）。
