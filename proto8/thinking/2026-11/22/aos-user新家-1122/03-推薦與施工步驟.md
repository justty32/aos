## 推薦：甲

把 aos-user 整夾放進 `proto8/frontend/aos-user/`，在 `proto8/frontend/bin/` 放一個連結過去。理由有四個：

1. **換機零步驟。** 程式跟著 git 走；`env.sh` 本來就把 `frontend/bin` 放上 PATH，換台 `git pull` 就有，不用多做一個連結，也不用跑 `install.py`。
2. **前端和測試一行不改。** 我在 scratchpad 原樣擺過：全景頁測試 52 支全過，原本跳過的 7 支都跑了；寄一題假題目，`/api/asks` 讀得到。
3. **不碰活樹。** `frontend/` 存檔就生效，活樹的 `bin/`、`lib/` 不換。
4. **兄弟走過同一條路。** aos-view 從 `ws/tools` 搬到 `proto8/extras`，再搬到 `proto8/frontend`，每一步使用者都點過頭。

代價：名分有點歪（專區工具掛在全景頁底下），全景頁大修、改名時要記得它。哪天想升格成乙，只是把這一夾搬進 `py/aos/apps/` 加一行 `entries.json`，改前端的找法。現在先不做。


| a. 找得到 | `$E bash -c 'command -v aos-user; readlink -f "$(command -v aos-user)"'` | 落在複本的 `frontend/bin/aos-user` → `frontend/aos-user/aos-user` |

| d. 假題目，全景頁讀不讀得到 | 見下面 | `/api/asks` 有那一題 |
| e. 回答與驗證 | 見下面 | 回信進暫存信箱，`aos-user verify` 印 `ok: matches` |

d 和 e 的做法（全部在暫存夾；埠用 18797，避開活的 8767、8768）：

```sh
Z="$E AOS_USER_ZONE=$W/zone"
$Z aos-user init && $Z aos-post init $W/box/mailbox
cat > $W/letter.json <<'EOF'
{"questions": [{"id": "q1", "question": "TEST: can the page see this?", "eli5": "This is a fake question. It checks the new home of aos-user.",
  "options": [{"key": "a", "label": "yes"}, {"key": "b", "label": "no"}], "recommend": "a"}]}
EOF
$Z aos-user send --kind decide --title "TEST aos-user new home" --from aos-user-home-1122 --reply-to $W/box/mailbox $W/letter.json
mkdir -p $W/vhome && echo '{"ui_ports": []}' > $W/vhome/config.json
echo "[{\"name\": \"aos-user-home-1122\", \"state\": \"running\", \"phase\": \"think\", \"ws\": \"$W\"}]" > $W/ls.json
$Z VIEW_LS_FIXTURE=$W/ls.json setsid aos-frontend --port 18797 --home $W/vhome serve > $W/serve.log 2>&1 &
curl -s http://127.0.0.1:18797/api/asks        # 幾秒後再讀；要看到 "TEST aos-user new home"
$Z aos-user answer 1 q1:a                       # 回答
ls $W/box/mailbox/new/                          # 回信進來了
$Z aos-user verify $W/box/mailbox/new/<回信名>   # 要印 ok: matches
kill <serve.log 裡印的 pid>                      # 只收自己記的 pid
```

- `VIEW_LS_FIXTURE` 是全景頁測試用的假 daemon 表。沒有它，暫存的全景頁會因為找不到 daemon 整輪失敗，連 `/api/asks` 都是空的（原型時踩過）。
- `ui_ports` 設成空的，才不會去搶活的 8768。

## 邊緣狀況

1. **抄本是 11-14 的版本。** 活樹那份要是 11-14 到 11-18 之間又被改過，改的東西已經跟舊樹一起刪了，找不回來。目前查不到有人改過。
2. **符號連結。** 要試 `commit-request` 收不收；repo 萬一在 Windows 的檔案系統上 checkout（`core.symlinks=false`），連結會變成一行文字，`aos-user` 跑不起來。兩台都在 Linux 或 WSL 的 ext4 上，現在不會遇到。
3. **全景頁大修、改名時。** `frontend/aos-user/` 要一起考慮，不然改名時可能被當成全景頁的一部分搬走或拆掉。
4. **舊的 systemd 單元。** `~/.config/systemd/user/` 的 `aos-user-tick.*`、`aos-view.service` 還指著 `~/aos-home`，現在是 disabled。有人 enable 的話，會每分鐘失敗一次。沒刪，刪要使用者說。
5. **活的全景頁重起之前，「要決定」欄還是空的。** aos-user 搬好了也一樣，因為舊程式還在找 `~/aos-home/ws/tools`。
6. **兩個網頁都能回同一封信。** 專區自己的網頁（8766）和全景頁（8767、8768）都回得了；先回的算，後回的會 `LetterMissing`。這是本來就有的行為。
7. **`$AOS_WS/tools` 那條找法。** 步驟 5 做之前，要是有人在 repo 根開一個 `tools/aos-user/`，`user_send` 會先用那一支。
8. **專區信數對不上。** HANDOFF 11-18 寫「信箱 3 封」，現在是 0 封，log 裡也沒有 11-16 之後的紀錄。aos-user 回來後，`aos-user ls` 會列出「log 記看過、但 cur 和 done 都沒有」的信（`zone.py` 的 `lost_letters`），到時候就知道是不是被 `aos-mailbox read` 刪了。
9. **專區不跟著換機**（第 3 題選 a 的話）。在家機寄的題目，到公司的全景頁看不到；全景頁只讀本機的專區。
10. **公司那台沒有 `notify-send` 或使用者層的 systemd。** tick 的通知那段會只印警告，檢查和退信照做；整個 tick 不裝也行。
11. **agent-fsm 的 `user_send` 跑在 daemon 起的行程裡。** 它的 PATH 來自起 daemon 的那個殼；殼要是沒有 `source env.sh`，就找不到 `frontend/bin`。家機查過 eca-aos 的 PATH 有，agent-fsm 那邊沒實測。
