# 04 待裁

第 1 題答了才能開工。第 2～4 題晚點答也行：第 2 題只影響步驟 8c，第 3 題現在照 a 的樣子，第 4 題只影響知識庫名片那一句。

## 第 1 題：aos-user 放哪

- **a. 放全景頁的夾 `proto8/frontend/aos-user/`，bin 裡放連結（推薦）**
  - 後果：換台 `git pull` 就有，每台不用多做任何事。
  - 前端和測試不用改，也不用跑 `install.py`。
  - 代價是專區工具掛在全景頁底下，以後全景頁大修、改名時要記得它。
- **b. 放 proto8 本體 `proto8/py/aos/apps/user/`，由 `install.py` 裝進 `bin/`**
  - 後果：名分最正，跟其他 aos 指令同一套。
  - 但要改全景頁找它的程式，還要跑 `install.py`（等於換活樹那份）。
  - 也跟你 11-13 選的「不放 proto8」相反。
- **c. 放 `wf/tools/aos-user/`，每台在 `~/.local/bin` 放連結**
  - 後果：最接近你 11-13 說的「放ws/tools」。
  - 但每台都要自己做一次連結，漏了就靜靜地找不到；全景頁的 systemd 單元也要另外設。

## 第 2 題：每分鐘的 tick 要不要裝回來

tick 是 aos-user 每分鐘跑一次的檢查，會做四件事：壞信退回寄件人、同一個寄件人一小時超過 10 封就擋、桌面通知、到期提醒。它靠 systemd 計時器叫，現在那個計時器停著，而且還指著舊路徑。

- **a. 先不裝（推薦）**
  - 後果：題目照樣寄得進、照樣出現在全景頁，因為 `aos-user send` 寄之前自己會先驗格式，壞信多半寄不出去。
  - 少掉的是：一小時 10 封的上限、到期提醒、壞信退回。桌面通知本來就關著。
  - 等「systemd 規則」那題定了再說。
- **b. 換新路徑裝回 systemd 計時器**
  - 後果：回到 11-13 段 2 的完整樣子。
  - 但要改 `~/.config/systemd/user/`，要你自己下指令或點頭；你 11-15 說過「不要誰都能掛 systemd」。
- **c. 以後改成掛在 daemon 的時鐘 hook 上**
  - 後果：不靠 systemd，daemon 起著才跑。
  - 要寫一點程式，可以跟前端大修一起做。

## 第 3 題：專區的資料跟不跟著換機

專區 `~/.aos/user/` 裡是這台的信、你的回答，還有 `aos-user verify` 用來驗授權的副本和流水帳。

- **a. 每台一份，留在 `~/.aos/user/`（推薦）**
  - 後果：跟現在一樣。
  - 在家寄的題目，到公司的全景頁看不到；換台前把題目答完就好。
- **b. 放進 `_stack`，跟換機 commit 一起走**
  - 後果：題目換台也看得到。
  - 但你的回答、授權憑證、專區網頁的 token 都會進 git。這個 repo 在 GitHub 上是公開的，push 了就公開。
  - 兩台同時寫也要另外處理。

## 第 4 題：跟 wf/user 的關係，與那張不見的名片

另一條線（wf-user-1122-plan）在規劃 `wf/user/`，它建議跟專區「不合併」。兩邊唯一碰得到的地方，是知識庫說的「使用者的名片」`~/aos-home/ws/public/user.json`：上面寫專區在哪、門上公告在哪、用哪支工具。這張名片已經跟舊樹一起刪了。

- **a. 不合併、不對接，知識庫拿掉名片那句（推薦）**
  - 後果：名片上的資訊 `door.json` 都有，打 `aos-user door` 就印得出來，少一張也不缺什麼。
  - 兩邊各管各的：專區是 agent 問你，wf/user 是你留東西。
- **b. 名片改放 `wf/user/`**
  - 後果：進 git，換機跟著走。
  - 但 wf/user 預設 agent 不寫，名片得由你寫或叫 agent 寫；名片上的主機名每台不同，放進 git 反而會錯。
- **c. 合併，專區整個搬進 `wf/user/`**
  - 後果：只剩一個「使用者的地方」。
  - 但專區的信是每台的活資料，會進公開的 repo；agent 寄信等於在你的地盤寫字。不推薦。

## 這次替使用者先做的選擇

1. **把 11-18 的「推」讀成已經同意「放進 repo」。** 所以三個方案都在 repo 裡，放在 repo 外的做法不列。原話是頂層建議「重做 aos-user 並放進 repo」，你回「推，但可能是後天的事情了」。
2. **不重寫，拿 11-14 的抄本當原始碼。** 9 份抄本的 `zone.py` 都一樣，跟現在的 `aos-post` 一起跑測試全過。「重做」我讀成「讓它回來」，不是重新寫一支。
3. **在 scratchpad 擺過一次甲的樣子來驗。** 只在暫存夾：沒有裝、沒有搬，沒碰 repo 的檔、活樹和 `~/.aos/user`。自己起的暫存全景頁（18797 埠）已經收掉。
4. **公司那台不另外問。** 寫成「`git pull` 之後 `aos-user init` 一次，跟線 8 一起做」。你說過公司現有的樹別管，這一步不碰那棵樹，只在家目錄建一個專區。
5. **真專區的假題目驗收（步驟 8b）寫成「你說要才做」。** 那封信會留在 `done/` 一封。
6. **步驟 5 可以延後。** 拿掉 `user_send`、`user_verify` 的舊找法要跑 `install.py`，所以排到下次有人跑 `install.py` 時一起做；不做也不影響功能。
7. **跟 wf/user 的關係當成第 4 題問你。** 沒有去改另一條線的檔，那條線盤點裡一句跟程式對不上的地方，寫在 [01](01-現況盤點.md) 給它參考。
8. **這四題沒有寄進專區。** 因為 aos-user 現在不在，寄不了。由派我來的 eca-aos 決定怎麼問你；搬好之後可以用上面那段 JSON 寄。
