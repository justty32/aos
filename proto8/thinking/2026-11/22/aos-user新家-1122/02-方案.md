## 三案都一樣的地方

- **程式進 git。** 三案都放在 repo 裡，換台 `git pull` 就有程式。11-18 頂層建議「放進 repo」，使用者答「推」。放在 repo 外的做法（例如 `~/.aos/tools/`）換機不會跟著走，違背「可以跨機器搬遷」，所以不列。
- **專區的資料不跟著搬。** `~/.aos/user/` 照舊一台一份，裡面是這台的信、回覆和授權憑證。要不要讓它也跟著換機，是 [04 第 3 題](04-待裁.md#第-3-題專區的資料跟不跟著換機)。
- **原始碼用同一份抄本。** 就是 01 說的 `r5-1115e` 那份，不重寫。
- **三案都要改的文件：**
  - 知識庫兩份：`proto8/knowledge/aos/user_zone.md` 第 30、49 行改成只寫 `aos-user`；第 8 行的名片看 [04 第 4 題](04-待裁.md#第-4-題跟-wfuser-的關係與那張不見的名片)。
  - 中文映照 `proto8/knowledge-zh-md/aos/user_zone.md` 第 46、69 行。
  - `wf/public/user-zone-mail.md:11`。
  - `wf/workflows/dispatch/aos-teams.md:40`，並拿掉第 44 行「家機沒有」那句。
  - 抄本裡寫死的字（01 第 4 節的表）。
  - `wf/progress.json` 的 `workspace-stack-alloc`、`wf/progress/overview-page.md`。

## 甲：放全景頁的夾 `proto8/frontend/aos-user/`

**放哪。** 整夾放 `proto8/frontend/aos-user/`，另外在 `proto8/frontend/bin/` 放一個符號連結 `aos-user`，指向 `../aos-user/aos-user`。

**怎麼進 PATH。** `proto8/env.sh` 本來就會把 `$AOS_HOME/frontend/bin` 放上 PATH（第 22～28 行）。查過：eca-aos 的行程、活的全景頁，PATH 裡都有這一夾。`aos-frontend.service` 也是 `source env.sh` 起的。所以不用另設 `VIEW_TOOLS`；真要設的話，設 `VIEW_TOOLS=proto8/frontend` 也對。

**前端程式不用改。** `find_aos_user()` 從 PATH 找到連結，取 realpath，會落在 `proto8/frontend/aos-user/aos-user`，`zone.py` 就在同一夾。`test_phase1` 推 `TOOLS` 的方法也剛好對。我在 scratchpad 照這個樣子擺過（`git archive` 出來的 proto8，加上抄本和連結），結果：
- 全景頁測試 52 支全過，`test_phase1` 不再跳過。
- 拿掉連結的對照組，跳過 7 支。
- 寄一題假的 decide 進暫存專區，起一個暫存的全景頁，`GET /api/asks` 讀得到那題。

**不用 `install.py`。** `frontend/` 存檔就生效，活樹的 `bin/`、`lib/` 不會被換掉。

**換機跟不跟。** 跟。程式和連結都在 git 裡；換台 `git pull`，殼 `source env.sh`，就有 `aos-user`。

**公司那台 WSL。**
- 殼 source 的如果是 repo 的 `proto8/env.sh`（換機說明書的做法），`git pull` 之後就有 `aos-user`。
- 公司那台照 11-17 的盤點沒有專區，要跑一次 `aos-user init` 建 `~/.aos/user/`。
- 公司如果還在用舊樹自己的 env，那就要等線 8（公司起 `_stack`）一起做。

**要改的檔**（三案共同的那些之外）：
- 新增 `proto8/frontend/aos-user/`（6 個檔加 `tests/`、`systemd/`）和 `proto8/frontend/bin/aos-user`（連結）。
- 只改字：
  - `proto8/frontend/bin/aos-frontend` 第 28、65 行的說明（現在寫「aos-user 不在 proto8」）。
  - `proto8/frontend/systemd/aos-frontend.service:5` 的註解。
  - `proto8/env.sh` 第 22 行講 frontend/bin 的註解。

**好處。** 每台不用多做任何一步；前端和測試一行不改；不碰活樹。它的兄弟 aos-view 走過同一條路：從 `ws/tools` 搬到 `proto8/extras`，再搬到 `proto8/frontend`；11-17 使用者在選項框答「搬進 bin/」。

**代價。**
- 專區是「問使用者」的通道，agent 的 `user_send`、`user_verify` 也靠它，卻掛在全景頁的夾底下，名分有點歪。
- 全景頁要大修、也說過要改名（11-15），到時候這一夾要一起考慮。
- git 裡多一個符號連結：要先試 `commit-request` 收不收；萬一有人在 Windows 的檔案系統上 checkout，連結會變成一個文字檔。

## 乙：放 proto8 本體 `proto8/py/aos/apps/user/`

**放哪。** 程式拆成 `proto8/py/aos/apps/user/`（`zone.py`、`web.py`、入口），`proto8/py/entries.json` 加一行 `"aos-user": "aos.apps.user"`；測試放 `proto8/py/tests/apps/user/`，systemd 範例跟著放進那一夾。

**怎麼進 PATH。** `install.py` 會在 `proto8/bin/` 生一支 `aos-user` 小入口（`install.py` 第 245～276 行），`env.sh` 放上 PATH。

**前端要改程式。** `bin/aos-user` 是生成的小入口，realpath 的旁邊沒有 `zone.py`，所以 `find_aos_user()` 找不到函式庫。要改成去 `$AOS_HOME/lib/aos/apps/user/zone.py` 載，或者直接 `import aos.apps.user.zone`。`test_phase1` 推 `TOOLS` 的方法也要改；`VIEW_TOOLS` 留給測試和示範用。

**要 `install.py`。** 程式要裝進 `lib/` 才會生效。在 repo 跑 `install.py` 等於換掉活樹那份，照硬規則 5 要先回報；公司那台也要跑一次。

**換機跟不跟。** 跟，條件是 `git pull` 之後再 `install.py`（換機說明書本來就有這步）。

**公司那台 WSL。** pull、`install.py`、`aos-user init`。

**要改的檔：**
- 新增 `proto8/py/aos/apps/user/`、`proto8/py/tests/apps/user/`；`proto8/py/entries.json` 加一行。
- 改 `aos-frontend` 的 `find_aos_user()` 和 `load_zone()`，改 `test_phase1.py`。
- 照 proto8 慣例整理：模組名、檔頭一句、輸出英文。`zone.py` 的輸出已經大致是英文，`web.py` 的畫面是中文，跟全景頁一樣。

**好處。** 名分最正：知識庫早就把專區寫成 aos 的一部分，`user_send`、`user_verify`、`user_zone_guard` 也都在 proto8。它會跟其他指令走同一套安裝、測試和 code map，全景頁改名也牽動不到它。

**代價。**
- 改動最大，要動前端程式，要跑 `install.py`。
- 跟使用者 11-13 的選擇方向相反：當時規劃員推薦放 proto8，他選了「放ws/tools」。

## 丙：放 repo 的工具夾 `wf/tools/aos-user/`

**放哪。** 整夾放 `wf/tools/aos-user/`，每台在 `~/.local/bin/` 放連結 `aos-user`。`commit-request` 現在就是這樣裝的。

**怎麼進 PATH。** 靠 `~/.local/bin`。agent 的 PATH 裡有它；但 systemd 使用者單元的 PATH 預設沒有它，`env.sh` 也不加，所以 `aos-frontend.service` 要另外加 `VIEW_TOOLS=%h/repo/aos/wf/tools`（或者把 PATH 補上）。

**前端程式不用改。** 連結的 realpath 會落在 `wf/tools/aos-user/`，`zone.py` 就在旁邊。

**不用 `install.py`。**

**換機跟不跟。** 程式跟，連結不跟：每台要自己 `ln -s` 一次（換機說明書要加一行）。漏做了不會報錯，只會靜靜地找不到，「要決定」欄又變空。

**公司那台 WSL。** pull、`ln -s`、`aos-user init`。

**要改的檔：**
- 新增 `wf/tools/aos-user/`。
- `wf/workflows/dev-env/03-換機.md` 加連結那一步。
- `proto8/frontend/systemd/aos-frontend.service` 加 `VIEW_TOOLS`。
- 前端說明裡的字。

**好處。** 最接近 11-13「放 ws/tools、不放 proto8」的原意：`ws/` 是舊樹的工作區，現在的工作區是 repo，repo 自己的工具就放 `wf/tools/`。

**代價。**
- proto8 的知識庫寫給所有 agent 看，卻要指到 `wf/` 這個 repo 專用的夾。`wf/` 是這個 repo 的工作流，不是 aos 的一部分。
- 每台多一步，systemd 單元也要另外設。
