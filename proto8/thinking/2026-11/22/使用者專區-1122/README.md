同一天他也說過：「這些都只是初步的調查規劃…你也可以大膽想」（eca-aos 轉述）。

## 一句話結論

`wf/user/` 當成**人的地盤**：跟 agent 的 `wf/ws/<名>/` 同一套規矩（進 git、`temp/` 不進、交件查大小、現在不是牆），差別是主人是人，agent 預設只讀、叫了才寫。它跟 `~/.aos/user/`（使用者專區）方向相反、不合併：專區是 agent 寄問題給人，`wf/user` 是人留東西給自己和 agent。

盤點時查到兩件會影響做法的事：

1. **這個 repo 在 GitHub 上是公開的。** 放進 `wf/user` 又 push 的東西，誰都看得到，所以私人素材要有一個不進 git 的位置。
2. **`index_gen` 會往 `wf/user` 裡寫檔。** 這裡的東西超過 15 項，它就會自動生一份 `_index.json`，等於 agent 在人的地盤寫字。要在 `index_gen.json` 把它排除，而且不能用夾名 `user` 排除，因為 `wf/workflows/common/user/` 也叫這個名字。
