# 04 待裁

答法：一題一個字母就好，例如「1a 2b 3c 4b 5a 6a」，或「照推薦」。

## 第 1 題：不想公開的東西放哪？

這個 repo 在 GitHub 上是公開的，wf/user 裡進了 git 又 push 的東西誰都看得到。

- **a. 開 `wf/user/private/`，在根 `.gitignore` 加一行。** 後果：意思清楚（要留、只是不公開）；不進 git，所以換台不會跟著走，要你自己帶。要改一個既有檔。
- **b. 直接用 `wf/user/temp/`。** 後果：今天就能用，不用改任何檔；但照 wf/ws 的規矩，`temp/` 是「換台後不要的東西」，agent 日後清 `temp/` 時可能把它當垃圾。
- **c. 放 repo 外（例如 `~/user-private/`），wf/user 只寫一句「在哪」。** 後果：最不可能誤交進 git；但 agent 的工作區是 repo，要讀得多給一次路徑。
- **d. 不放私人的，wf/user 一律當公開的寫。** 後果：最簡單；私人的東西你自己另外找地方。

**推薦 a。**

## 第 2 題：「你叫它寫」算哪些來源？

README 現在的預設是 agent 只讀、你叫了才寫。問題是哪些話算「你叫的」。

- **a. 只有你當面說**（終端或 Remote Control 裡你親口打的）。後果：最嚴；`eca_main` 轉來的、專區回信都不算。
- **b. 照鐵律 2 的授權鍊**：你當面說、驗過的專區回信，加上 `eca_main` 轉來或派來的普通工作。後果：跟其他地方同一套，agent 不用記兩套規矩；`eca_main` 轉錯話的風險跟其他普通工作一樣。
- **c. b 之外，另開一格 agent 可以自由寫的（例如 `wf/user/回條/`），給 agent 留「我讀了」「我照做了」。** 後果：你在 GitHub app 上一眼看得到誰接了你的交代；但你的抽屜裡就有 agent 的字了，跟「專屬區」的意思打折。

**推薦 b。** 不管選哪個，代寫都要標「（agent 代寫，使用者 MM-DD 口述）」。

## 第 3 題：你自己改的檔，誰交進 git？

你用 VS Code 改了 wf/user 的檔，那份改動要有人交，換台才會跟著走、GitHub 上才看得到。你 11-22 說過「commit的時候只commit自己實際有更改的地方就好」，所以 agent 現在不會交別人的改動。

- **a. 你說了才交。** 後果：最尊重原樣；你忘了說，換台時另一台就看不到。
- **b. eca-aos 收工或換台前自動交，原樣不改一字。** 後果：不會漏；但你寫到一半、或不小心寫了不想公開的，也會被交進去（push 了就是公開）。
- **c. eca-aos 收工或換台前用選項框問你一次「wf/user 有這幾個檔改了，要交嗎」。** 後果：不會漏、也不會誤交；每次收工多一題（有改動才問）。

**推薦 c。**

## 第 4 題：agent 怎麼發現你放了新東西？

- **a. 只靠你說「看一下 wf/user」。** 後果：不用改任何檔；你忘了說，agent 就不知道。
- **b. 開場掃一次，壓縮後也掃一次。** 改 `AGENTS.md` 開場那條（掃信、掃進度之外加掃 wf/user）與 `compact_reload.sh`（只印檔名）。讀到哪記在 agent 自己的地盤。後果：不用你記得說；每次開場多跑一個 `git status`，壓縮後多幾行字。
- **c. b 之外，全景頁加一張「wf/user 改了什麼、誰讀了」的卡。** 後果：回家打開全景頁就知道交代有沒有人接；要改前端，另開一條線做。

**推薦 b。** c 等全景頁那邊有空再說。

## 第 5 題：你在 wf/user 寫的交代，跟 `common/user.md` 誰是正本？

- **a. `common/user.md` 是正本。** agent 把你的交代抄進去，附原話、指回 wf/user 那個檔；wf/user 是原文留底。後果：agent 只要讀一份規矩（壓縮後也會自動貼回）；要多一道抄寫，抄的時候可能漏或抄錯。
- **b. wf/user 是正本，`common/user.md` 只放一句「去看 wf/user/交代.md」。** 後果：不用抄、不會不一致；但壓縮後貼回的就少了這部分，agent 要自己記得去讀；而且你的交代會跟 user.md 現有的規矩各寫各的。
- **c. 分開管：一次性的事（「明天先做 X」）只留在 wf/user；長期的規矩（「以後都要 Y」）抄進 `common/user.md`。** 後果：最貼近實際用法；要 agent 判斷哪條是長期的，判錯就漏抄。

**推薦 c**（判斷不了的當長期，抄進去）。

## 第 6 題：舊的 user-advice 要不要搬進來？

`proto8/thinking/user-advice/` 是你 9 月起手寫的設計意見，agent 一直不碰，性質跟 wf/user 很像。

- **a. 不搬。** wf/user 的 README 指過去；以後寫「對 aos 設計的長篇意見」，放那裡或 wf/user 都行。後果：舊紀錄裡約 20 處路徑不會斷；你的東西分在兩處。
- **b. 整夾搬進 `wf/user/advice/`**（用 `git mv`，歷史留著）。後果：你的東西全在一個地方；舊紀錄的連結照「舊紀錄不回頭改」的規矩不修，會斷約 20 處；設計意見就離開了 proto8 的討論紀錄。
- **c. 舊的不動，以後新寫的設計意見一律放 wf/user。** 後果：不斷連結；但 user-advice 就凍結了，查你的設計意見要看兩處。

**推薦 a。**
