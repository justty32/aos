### wf/ws：agent 的私有地盤（今天新訂）

- 規矩在 `wf/ws/README.md`：路徑照掛的層級嵌套、地盤進 git、任何一層 `temp/` 不進、上層替下層建、**現在只是規矩不是牆**、交件走 commit-request 並查單檔大小。
- 使用者 11-22：「這是未來的權限的基礎。現在就是讓他們有自己的私有地盤這樣」（[01-決定與調查](../工作區與stack-1122/01-決定與調查.md) 第 12 行）。
- 跟 wf/user 的關係：wf/user 就是「人的那一格」。照嵌套的畫法，人是所有頂層 agent 的上層，所以 wf/user 在概念上是整棵地盤樹的根；只是放在 `wf/user/` 而不是 `wf/ws/user/`，因為使用者指定了這個位置，而且這樣 `wf/ws/` 裡就全是 agent，規矩比較單純。

### 三個機制：temp/、大小檢查、index_gen

- **`.gitignore` 的 `temp/`**：根 `.gitignore` 有一行 `temp/`，任何一層叫 `temp` 的夾都不進 git。所以 `wf/user/temp/` **今天就不進 git**，不用改任何檔。
- **大小檢查**：`wf/tools/commit_queue.json` 的 `max_file_bytes` 是 1,048,576（1 MB），`big_ok` 是空的。`--files` 點名的檔有一個超過就整個申請不收。使用者放的照片、PDF、錄音很容易超過。
- **index_gen**：`wf/tools/index_gen.json` 的範圍有 `{"path": "wf", "deep": true}`，所以 `wf/user` 在範圍內。夾裡進 git 的東西超過 15 項（`more_than: 15`），它就會在那個夾生一份 `_index.json`，由 commit 排隊在交件時自動放進 commit（`wf/tools/commit_queue.py:728`）。
  - 這等於 agent 在人的地盤裡寫檔，跟「agent 不主動寫」對不上。
  - `skip_dir_names` 不能加 `user`，因為 `wf/workflows/common/user/` 也會被一起跳過。要用 `skip_dirs` 加 `wf/user`（只在上一層 `wf/_index.json` 留一項）。
  - **附帶影響**：`wf` 頂層現在進 git 的剛好 15 項（`git ls-files wf | cut -d/ -f2 | sort -u`），加了 `user` 變 16 項，超過門檻，所以這次交件會讓 `wf/_index.json` 重新出現（它 11-14 因為過 15 項第一次生、後來掉回 15 項時被收掉）。這是規則本來就會做的事，`AGENTS.md` 也叫人用 `index_view wf`。

### 這個 repo 是公開的

- `gh repo view` 回 `"visibility": "PUBLIC"`（`origin` 是 GitHub 上的 `justty32/aos`）。
- 所以 wf/user 裡任何進了 git 又被 push 的東西，全世界看得到。commit 排隊不掃秘密（`commit_queue.py` 裡沒有 secret 檢查；只有前端的 decide 單會擋 `SecretInPayload`）。
