# 02 規劃

← [README](README.md)｜上一份 [01-現況盤點](01-現況盤點.md)｜下一份 [03-情境](03-情境.md)

## 大白話摘要

- `wf/user` 是你的抽屜。agent 的抽屜在 `wf/ws/`，規矩一樣，只有一點不同：你的抽屜 agent 只看不動，你叫它寫它才寫。
- 你在這裡寫的東西是「原文」；agent 要把它變成規矩時，抄進 `common/user.md` 並附原話，原文不動。
- 問你的題目照舊寄使用者專區、上全景頁，不寫進這裡。這裡是你留給 agent 的，專區是 agent 留給你的。
- repo 是公開的，所以要有一格「不進 git」的私人位置。
- 你在外面時最順的寫法是在 Remote Control 跟 agent 說「記進 wf/user」；看的話是 push 之後用 GitHub app 看。

## 跟既有地方怎麼分工

| 既有地方 | 怎麼辦 | 理由 |
|---|---|---|
| `common/user.md` 與 `user/01～03` | **不動，仍是規矩的正本。** wf/user 裡的交代，agent 照現在的做法抄進去（附原話、日期、出處指回 wf/user 那個檔） | 每個 agent 開場與壓縮後都讀它；要是規矩散在兩處，日後一定不一致 |
| `proto8/thinking/user-advice/` | **推薦不搬**（[04 第 6 題](04-待裁.md#第-6-題舊的-user-advice-要不要搬進來)）。wf/user 的 README 指過去；以後你寫「對 aos 設計的長篇意見」放哪都行 | 它的主題是 aos 本身的設計，跟討論紀錄放在一起；舊紀錄裡約 20 處寫著它的路徑 |
| `~/.aos/user/`（使用者專區） | **不動、不合併。** 兩邊方向相反（見下面「方向」） | 專區要驗回覆、只在本機；wf/user 要進 git、跟著換台 |
| 全景頁 | 不動。之後可以加一張「wf/user 最近改了什麼」的卡（大膽想法，見下面「agent 怎麼發現」第 4 種） | — |
| `wf/ws/` | 不動。wf/user 照它的規矩，主人換成人 | 「私有地盤是未來權限的基礎」，人的那一格也該放進同一套 |
| `wf/progress.json` 裡「等使用者」的條目 | 不動。那是 agent 記的「卡在你身上的事」；你自己的待辦另外寫在 wf/user | 一份是 agent 的帳，一份是你的帳 |

**方向**（一句話分清楚四個地方）：

- `common/user.md`：agent 寫「關於你」的規矩，給 agent 看。
- `wf/user/`：你寫，給你自己和 agent 看。
- `~/.aos/user/`：agent 寫信問你，你回。
- `wf/ws/<名>/`：agent 寫給它自己。

## 你會放什麼（建議的格子）

只是建議，你照自己習慣放也行；agent 讀的時候照 README 的第一行判斷每個檔是什麼。

```
wf/user/
├── README.md       入口（已開）
├── 交代.md          給 agent 的指示：一條一段，最新的放最上面，每條寫日期
├── 待辦.md          你自己要做的事（agent 不幫你勾）
├── 筆記/            想法、隨手記；一個檔一個題目，檔名開頭寫日期
├── 草稿/            寫到一半的東西（agent 不當成定案）
└── temp/  或 private/   不進 git 的私人素材、大檔（見第 1 題）
```

- **交代.md 是最重要的一格**：這是你用 VS Code 改一行就能叫 agent 做事的地方。agent 開場讀它，照做之後在**自己的地盤**記「我讀到哪一條」，不在你的檔上打勾（守住只讀）。
- **筆記和草稿 agent 不主動讀**：你說「看我的筆記 X」它才讀，免得把半成品當成你的決定。
- 圖片、PDF、錄音這類大檔放不進 git 的那一格，或者放 repo 外，只在 wf/user 寫一句「在哪」。

## 誰能讀、誰能寫

### 現在（第一步，只是規矩）

| 動作 | 誰 | 條件 |
|---|---|---|
| 讀 `交代.md`、`待辦.md` | 所有 agent | 開場就讀 |
| 讀筆記、草稿、私人那格 | 所有 agent | 你叫它讀，或做事真的需要 |
| 新增、修改 | agent | **你叫它寫才寫**，只寫你指定的地方；寫的段落標「（agent 代寫，使用者 MM-DD 口述）」 |
| 改名、搬、刪、整理 | agent | 不做。刪檔照鐵律 2 本來就要你本人說 |
| 把你的改動交進 git | agent | 見第 3 題 |
| 引用、轉抄到別處 | agent | 可以，附原話與出處；原檔不動 |

「你叫它寫」算哪些來源，跟鐵律 2 的授權鍊對齊最省事（見第 2 題）：你當面說（終端或 Remote Control）、驗過的專區回信，以及 `eca_main` 轉來的普通工作。agent 之間的信、轉述都不算。

### 第二步（大膽想法：用工具擋，還不是牆）

不用等權限系統，有兩個便宜的做法可以先讓規矩變成「會被提醒」：

- **commit-request 加一道檢查**：交件的檔裡有 `wf/user/` 底下的，msg-file 必須有一行「使用者原話：…」，沒有就不收（跟 1 MB 檢查同一種擋法）。這擋不住手改，但擋得住「順手一起交」。
- **aos 工具這邊照 `user_zone_guard` 再做一支**：agent-fsm 用 aos 工具寫 `wf/user/` 時，`before_tool` hook 擋下來。

Claude Code 自己的權限規則（在 `.claude/settings.json` 寫 `Edit(wf/user/**)` 要先問）看起來也行，但 eca 是用 `--permission-mode dontAsk` 跑的（`proto8/templates/eca-claude/cli.json`），在這個模式下「要先問」會變成「直接拒絕」，而且擋不住 Bash 寫檔。這點沒實測，只記下來。

### 第三步（權限系統來了之後）

`wf/user` 是最適合當第一塊真牆的地方：規則最簡單（人可寫、agent 只讀），而且違規的後果最明確。到時候 wf/ws 的「主人可寫、上層可讀」也可以照同一個樣子做。全部 agent 跟你是同一個 Linux 帳號，這一點跟使用者專區一樣：檔案權限擋不住，要靠 kernel（權限站）或分帳號。

## git、temp/、大小、換台

- **進 git**：README、交代、待辦、筆記、草稿都進。這樣換台會跟著走，push 之後手機上也看得到。
- **記住 repo 是公開的**：進了 git 又 push，就是公開發表。私人的東西要放不進 git 的那一格。
- **不進 git 的那一格**：`wf/user/temp/` 今天就不進（根 `.gitignore` 的 `temp/`），但照 wf/ws 的判準，`temp/` 是「換台之後不要的」。私人素材是「要留、只是不公開」，意思不一樣。所以推薦另開 `wf/user/private/`，在根 `.gitignore` 加一行（第 1 題）。不管選哪個，換台時都不會自動跟著走，要你自己帶（或之後另開一個私人 repo 放）。
- **大小檢查**：1 MB 的門檻照舊。真的要進 git 的大檔，把路徑加進 `wf/tools/commit_queue.json` 的 `big_ok`（要另外交件，git log 看得到誰放行的）。照片、錄音推薦一律放私人那格，不進 git。
- **index_gen**：在 `wf/tools/index_gen.json` 的 `skip_dirs` 加 `wf/user`，它就不會在你的抽屜裡生 `_index.json`，只在 `wf/_index.json` 留一行「wf/user：使用者本人的專屬區」（取 README 第一句）。這次交件 `wf` 頂層變 16 項，`wf/_index.json` 會由排隊重新生出來。
- **換台**：換台前照舊 shutdown 再 commit（使用者 11-22「1.接受。」）。wf/user 裡還沒交的改動要在這一步一起交，不然另一台看不到（第 3 題）。兩台都改了同一個檔又都沒交，就會撞。

## agent 怎麼知道你放了新東西

由便宜到花工，四種，可以疊：

1. **你直接說**（今天就能用）：在終端或 Remote Control 說「看一下 wf/user」。最準，但要你記得說。
2. **開場掃一次**：在 `AGENTS.md` 開場那條「先掃兩軸」加第三軸——跑 `git status --short wf/user` 與 `git log --since=<上次看的時間> -- wf/user`，有改動就讀 `交代.md`。「上次看到哪」記在 agent 自己的地盤（例：`wf/ws/eca-aos/user-seen.json`），不寫在你的抽屜裡。
3. **壓縮後也掃**：`wf/tools/compact_reload.sh` 多印一段「wf/user 有這些檔改了、還沒讀」，只印檔名，不貼全文（不然每次壓縮又多幾 KB）。
4. **全景頁加一張卡**（大膽想法）：前端每次刷新跑一次 `git status wf/user`，顯示「你改了 X，eca-aos 還沒讀」或「已讀」（讀的狀態從各 agent 的 `user-seen.json` 拿）。這樣你回家打開全景頁，就知道你的交代有沒有人接。

推薦 2＋3（第 4 題）。1 本來就一直有效。

## 手機上方不方便

- **看**：全景頁只綁本機，手機看不到。手機能看的是 GitHub app——前提是 push 了。所以 wf/user 進 git、push 之後，你在外面可以用 GitHub app 翻自己的交代、筆記，也能看到 agent 代寫的段落。Markdown 在 GitHub app 上會排版，表格和標題都看得清楚。
- **寫**：
  - **推薦：在 Remote Control 口述，叫 agent 代寫。** 這就是「你叫它寫」，規矩上完全沒問題；agent 寫完回你一句寫在哪、原話是什麼。
  - **不推薦：在 GitHub 網頁上直接改檔。** 那會在遠端的 `main` 上多一個 commit，本機的 `main` 沒有。agent 的規矩裡沒有「先 pull」，commit 排隊下一次推進 `main` 時兩邊就分岔了，要人來收拾。真的要用，回家後先跟 agent 說「我在 GitHub 改過 wf/user，先 pull」。
- **在 Remote Control 裡看檔**：可以叫 agent「把 wf/user/待辦.md 念給我」，它會把內容貼進對話。檔很長時叫它只講重點。

## 邊緣狀況

1. **repo 是公開的。** 你寫進 wf/user 的東西，只要不在私人那格，commit 又 push 就是公開。最容易出事的是你在筆記裡隨手貼了 token、密碼、別人的名字。commit 排隊不掃秘密。
2. **名字撞車。** 你說的「使用者專屬區」跟現有的「使用者專區」（`~/.aos/user/`）只差一個字，agent 和人都容易搞混。文件裡一律寫路徑：`wf/user` 和 `~/.aos/user`。
3. **index_gen 會往你的抽屜寫 `_index.json`**（超過 15 項時），在 `skip_dirs` 排除之前，這是唯一一個「規矩說只讀、程式卻會寫」的地方。現在 wf/user 只有 1 項，離門檻很遠。
4. **這次交件會讓 `wf/_index.json` 重新出現**（`wf` 頂層從 15 項變 16 項）。不是錯，只是 commit 會多一個生成物。
5. **你在 VS Code 改到一半，agent 剛好去交件。** claim 擋不住 VS Code；要是 agent 被叫去交 wf/user 的檔，可能交到你寫到一半的版本。所以「交你的檔」一律先問或等你說（第 3 題）。
6. **兩台各改一份。** 家機改了交代沒交，公司那台又改同一檔，換台時會撞。照「同一時間只有一台在跑」的規矩，換台前交掉就不會發生。
7. **在 GitHub 網頁上改檔**會讓遠端和本機分岔（見上面「手機」）。
8. **代寫和原文分不清。** agent 代寫的段落如果沒標，日後你和別的 agent 都會把它當成你親手寫的、當成原話。每段代寫都要標「（agent 代寫，使用者 MM-DD 口述）」，口述的原話照錄在旁邊。
9. **語音輸入的錯字。** 你口述的原話照錄（跟 thinking 的規矩一樣），旁邊附一句讀法，不改原字。
10. **交代跟 user.md 打架。** 你在交代裡寫了一條，跟 user.md 現有的規矩相反。推薦的裁法：新的、你親手寫的贏；agent 照新的做，並把 user.md 那條改成新原話、舊的收進「已被取代的原話」（第 5 題選 a 的話）。
11. **交代寫得像方向題。** 例如「改用某某架構」。照鐵律 5，大方向是你的，所以這種 agent 照做沒問題；但交代模稜兩可時，agent 不自己猜，寄專區問你一題。
12. **巢狀 `CLAUDE.md`。** Claude Code 讀子資料夾裡的檔時會順便讀那裡的 `CLAUDE.md`（Claude Code 的行為，沒實測）。你若在 wf/user 放 `CLAUDE.md`，任何 agent 讀到你的檔都會被灌進那份。這可以是功能（你的交代自動被看到），也可能是坑（跟「頂層只留兩個入口」的佈局不合、而且讀筆記時也被灌）。推薦先不放。
13. **agent 偷懶把問題寫進 wf/user。** 現在家機沒有 `aos-user`，「寄專區」這條路斷著，agent 可能改把題目寫進 wf/user 或你的待辦。README 已寫明不准；根本解是讓 `aos-user` 有新家（`_stack` 規劃邊緣狀況 32，不在這份範圍）。
14. **大檔。** 照片、錄音超過 1 MB，交件會被整批退（`FAILED RequestBad`）。放私人那格或 repo 外。
15. **刪你的檔。** 你說「把那份草稿刪了」——這是你本人說的，照鐵律 2 可以刪；但 agent 轉述的「使用者說可以刪」不算。
