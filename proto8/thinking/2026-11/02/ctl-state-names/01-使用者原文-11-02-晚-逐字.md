## 使用者原文（11-02 晚，逐字）

> hmmm，就是說，eca本身繼承於daemon，daemon又繼承於loop，他們吃的都是同份ctl/state檔案，就是這份檔案內有額外的key，對於這種控制自己的ctl/state檔案，其實直接用ctl.json/state.json就好，沒必要費心用loop_*，所以改成統一用ctl/state吧，你懂得，就是loop這一系。就是說一個原則：控制自身的ctl/state檔案，那就是ctl/state，不加前綴。至於如果和base class的ctl/state分屬不同格式，那就是把base class的ctl/state增加前綴，畢竟你是末尾，你要負責處理。

頂層問「白天定的 `daemon_ctl.json`／`daemon_state.json` 怎麼辦」，使用者（11-02 晚，逐字）：

> 3.就用我這條，白天那個我還有記憶，晚上的我就是要推翻白天的我。

## 決定（11-02 晚，使用者）

- **原則**：**控制自身的 ctl／state 檔，一律叫 `ctl.json`／`state.json`，不加前綴**。loop 這一系（aos-loop、aos-daemon、eca 範本的子 loop、常駐 bob 的控制器……）全部統一。
- **例外的方向**：末端（derived）的 ctl／state 跟 base 的**格式不同**時，由**末端**負責——把 **base 那份加前綴**（例 `loop_ctl.json`／`loop_state.json`），自己的用 `ctl.json`／`state.json`。
- 本條取代同日的三個說法：
  - [state 窗](../state-window/README.md) 的 daemon 窗 `daemon_ctl.json`／`daemon_state.json` → daemon 自己的窗叫 `ctl.json`／`state.json`。
  - [exec 像繼承 § 結論](../exec-inheritance.md#結論11-02跟使用者討論後)「共用 stack 的常見名字加自己前綴」**在 ctl／state 這件事上**不適用；其他固定名照舊守（方向題 2）。
  - 常駐 bob 的控制器窗用 `ctl.json`／`state.json`；aos-listen `--status` 只認 `state.json`（`lib/aos/aos_ws.py` 不留 `loop_state.json` 備案）。

### 方向題的答案（11-02 晚，使用者逐字）

- **方向題 1**（`loops_ctl`／`loops_state` 留不留名）：「hmmm，是這樣的，剛剛下班通勤的時候有個想法，就是說，exec和loops，其實都屬於proc，所以...改名？可是我又擔心和linux的proc撞名...不過好像撞名也沒差。就是說，exec是基石，loop是另一種基本形式，搞不好以後還會有更多形式。」
  - **11-03 定案**（[11-03 procs](../../03/procs/README.md)）：統稱 proc、名單合一成 `procs`；`loops_ctl`／`loops_state` 改 `procs_ctl`／`procs_state`。通則：**管別人的窗＝`<被管的東西>_ctl`／`_state`**（N-13 的 11-03 補）。
  - **11-03 晚結案**（頂層列開著的事，使用者逐字）：「A2.解決了，以後相關的稱呼/慣例等也要變就是了。」→ 以後相關的稱呼與慣例也跟著改成 proc 這一套（exec／loop 是 proc 的兩種形式，名單、窗、說明一律用 proc 的叫法），遇到舊叫法順手改。
- **方向題 2**：「2.好。」→ 前綴原則對 ctl／state 以外的固定名照舊：只有「控制自身的 ctl／state」是例外，其他固定名（信箱、紀錄檔、`relay_state.json`、`letter_warning.txt` 這類）照 exec 像繼承加前綴或開資料夾。
- **方向題 3**：「3.對。」→ 只有帶 ctl 的才算 ctl／state 對；身體自己的紀錄檔（`relay_state.json`、aos-fsm 的 `state.txt`）不算、照舊。「末端加前綴」的例子（N-13）：一支 `aos-foo` 自己認 `ctl.json` 又在同一個 stack 裡起 aos-loop → `aos-foo` 寫 loop.json 時給 `"ctl": "loop_ctl.json", "state": "loop_state.json"`，自己的照舊 `ctl.json`／`state.json`。

## 結論

### daemon 的 ctl／state 跟 loop 的格式一樣嗎（決定原則怎麼套）

**一樣，而且是同一段程式寫的、沒有多任何 key**（`Daemon` 繼承 `Loop`，兩扇窗由 `Loop::read_ctl`／`Loop::write_state` 讀寫）。daemon 多出來的 key 全在另一對「管別人」的窗（11-02 叫 `loops_ctl`／`loops_state`）。所以照原則，daemon 自己的 `ctl`／`state` 不必加前綴，直接叫 `ctl.json`／`state.json`。
