### 連帶細節（一行一個：定成什麼｜依據）

1. **工具的小格**＝`$AOS_STACK/tools/<名>/`：act、aos-mcp、pyfix 的 act、demo 各 agent 的 act。｜工具名是登記檔／tools 資料夾給的變動名；`tools` 用複數（C-54），跟定義那邊的 `tools/<名>/`（P-25、C-61）同一個字，P-38「stack 樹＝呼叫樹＝tools 資料夾樹」：`act/tools/cathy/act/tools/stamp/` ⇄ `.stack/tools/cathy/tools/stamp/`。
2. **不分 `agents/`、`kernels/`**：被叫的是工具、另一隻 agent、還是 kernel，一律進 `tools/`。｜C-52「上層不該知道下層是什麼」、C-61。
3. **`tools/` 不用誰先 mkdir**：aos-exec 建 stack 是 `mkdir -p`，多一層自動長出來。｜N-59「建 stack 只在 aos-exec 做」。
4. **cli_session 的 attach 找畫面**跟著第 1 條走：`<stack>/tools/<名>`。`lib/agent/claude`、`codex` 兩個工具自己不動（拿到的 `$AOS_STACK` 已經是小格）。
5. **aos-daemon 的子項小格**＝`$AOS_STACK/loops/<名字>/`（11-03 起 `procs/<名字>/`）。｜子項名是名單給的變動名；daemon 自己的固定名（`ctl.json`、`state.json`、管別人的窗、信箱）留頂層。用名單的名字不用 `tools`：daemon 不是在叫工具，C-54「同一主題同一個字」。aos-daemon-ctl 建的 `<WS>/.stack` symlink 跟著指到子項小格；eca-hub 從 state 表讀 `cell` 欄位、不自己拼路徑；`AOS_DAEMON` 仍指 daemon 的 stack 頂層。
6. **eca-turn 的 `<kind>/`**（`claude/`、`codex/`）**留在頂層不動**。｜`kind` 是 aos-eca-turn 自己定的封閉集合，照尺是固定名；`transcripts/`、`eca.json` 同理。以後 kind 若改從設定讀、不再只有兩個，就該搬進複數資料夾（建議名 `clis/<kind>/`）。
7. **eca-hub 不封存**：`eca_archive/` 與 `freeze_transcripts` 拿掉，stop 只從 daemon 拿掉、小格留著，刪小格是 remove（使用者 11-02 晚，見 [eca 14](../../../2026-10/30/eca/14-11-02-晚使用者想法.md#決定11-02-晚使用者)、[15](../../../2026-10/30/eca/15-實作時代定.md)）。
8. **pyfix／agent_tool 的 `runs/NNN/`**：照舊。｜它已經是「變動名收進一個固定資料夾」的形狀。
9. **ask_round 被問的 agent**：沒給 `--ws` 時，工作區＝`$AOS_STACK/tools/<agent 資料夾名>/`，stack 照舊在它底下的 `.stack/`（只改前綴；對齊 P-32 先不管）。
10. act 的 `queue/`、`compact/`、`history_archive/`、`current.txt`、`trace.jsonl` 等程式寫死的固定名：照舊在頂層。aos-mcp 的呼叫紀錄見[決定](01-使用者原文-11-02-逐字.md#決定11-02使用者)（預設不記）。
11. **用詞**：「小格」＝`$AOS_STACK/tools/<名>/`；不新造名詞。daemon 那格照舊叫「子項的小格」。
