## 要使用者看的衝突與方向題

答案在[決定](01-使用者原文-11-02-逐字.md#決定11-02使用者)。留下的結論：

- **衝突 1**：daemon 不再擋子項跟自己的窗同名（子項在自己的小格裡，撞不到）；名字本身的規則（不能空、不能含 `/`、不能 `.` 開頭）照留。
- **衝突 2**：daemon 子項的小格路徑一變，已經在跑的 daemon 要重起才用新路徑，舊小格留在原地不會自動搬。**改小格路徑時要提醒使用者停掉重掛、順手 `rm` 舊小格。**
- **衝突 3**：`tools` 是 stack 頂層保留名——任何格都不能在自己 stack 頂層放叫 `tools` 的固定東西（寫在 P-17 的註）。

## 實作結論（11-02，隊長；代定可翻案）

- **工具小格**：`lib/agent/act`、pyfix 的 act、`cli_session` 的 attach、demo 各 agent 的 act，一律 `$AOS_STACK/tools/<名>/`。`demo/run.sh` 印的樹是 `.stack/tools/cathy/tools/stamp/`。**工具靠 P-17 的擺法找叫它的 agent 的 stack 時，要往上兩層**（agent-kai 的 `recall` 讀 `history.jsonl`）。
- **aos-mcp**：小格 `<stack>/tools/<名>/`；登記檔與呼叫紀錄照[決定](01-使用者原文-11-02-逐字.md#決定11-02使用者)。
- **ask_round**：只改前綴（方向題 1「先不管」）。
- **daemon**：子項小格在 daemon stack 底下的子資料夾（11-02 `loops/<名字>/`；11-03 已改：`procs/<名字>/`，見 [11-03 procs](../../03/procs/README.md)），`make_cell` 建子資料夾與小格兩層（`$AOS_STACK` 不在照舊建不了）；aos-daemon-ctl 的 `.stack` 捷徑、aos-eca-hub、talk 的 quiet.py、daemon-2 的信箱路徑跟著改。
