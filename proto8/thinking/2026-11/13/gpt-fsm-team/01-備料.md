## A. agent-fsm 是什麼、怎麼停

- 範本 `P/templates/agent-fsm/`：身＝`aos-loop loop.json`（每拍 300 ms），`fsm.json` 四格 idle→think→wait→act，act 做完回 think；腦答出**不帶工具呼叫**的話就回 idle。idle 沒信就**空等**（常駐），**沒有「做完就退」、沒有步數上限**（`P/templates/docs/02-agent-fsm.md:34,83`）。
- 唯一的煞車：brain 格旗標 `--max-tool-calls N`（一個任務內滿 N 次之後不給工具），要改 `fsm.json` 的 argv（`brain.py:56`）；`--history task` 只帶最後一封 user 起的訊息。
- wait 格等腦**不設期限**（每 10 分鐘 stderr 提醒一行）；kernel 回錯＝`BrainFailed`、agent 退 1、表上 `stopped`＋reason，有 `auto_restart` 才重起（`wait.py:7,402`）。act 格每支工具照自己的 `timeout_ms`，整格上限 30 分。工具失敗不停，錯誤行交回給腦。
- `goal` 工具：一句話目標；腦停下、queue 空、goal 還 active 時自動丟 `[aos] goal:` 提醒，連續 10 次沒用 goal 以外的工具就自動 paused（`idle.py:208-235`）。外面可 `aos-agent goal -t 名 set …`；history 空時 goal 就是第一句題目。
- 預設 `system.txt` 只有三行通用句。

## B. 定義、生子、回報

- **定義**＝一個資料夾（`interfaces.json`、`tools.json`、`llm.json`、`system.txt`、`hooks.json`、`subagents.json`、`fsm.json`、`loop.json`…）。`agent_def`：`new`（從範本或任一定義複製）、`check`、`tools`／`llm`／`system`（**直接改定義本身**，影響所有用它的 agent）；改不了 `fsm.json`、`hooks.json`、`subagents.json`，那些要用檔案工具或人改（`P/lib/agent/agent_def/_entry:7-27`）。
- stack 裡有覆蓋層的只有 `tools.json`、`llm.json`、`system.txt`、`hooks.json`、`subagents.json`（`KB/definition.json#/overlay`）。
- **subagent**（`subagent` 工具）：`add {def, name, ws, limits, envs, auto_restart}`。子的腦、工具、system **全由子的定義決定，不繼承母**；母之後可用 `subagent {op: llm|tools|system|history|hook}` 改子的覆蓋層。配額 `max_subagents`（範本 4），daemon 總格數另算。**沒有深度限制**（孫受子定義的配額管）；`fork` 深度限 1。
- 子的工作區 `ws` 相對母的工作區（不給＝同一個）；環境變數來自 daemon、不是母（`envs` 明給的才帶，且明文落盤）。
- **回報沒有主動推送**：母用 `ask`（說並等，預設 600 秒）或 `say`＋`listen`；逾時 `AnswerMissing`。另一路是信箱。做完退 0 的 agent 從 daemon 表消失；出錯的留 `stopped`＋reason。
- `agents_ctl`：管 daemon 表上任何 agent（含 rm），不算配額、不能對話。
- 規則（全是自律）：子 agent 用完要 rm（`KB/rules.json` 6）；不碰別人 stack（2）；不准繞過拒絕（4）。

## C. 工具包與權限

- 包（`P/lib/packs/`）：look（read、ls、view、stat、grep、glob）、change（write、edit、copy、move、mkdir）、delete（trash、remove）、shell（shell、run_python）、gadgets（peek_clock、peek_now_time、math、do_task）、events（clock_register、self_hook）、todo、self（self_tools、self_llm、self_system、self_state、self_ctl、self_history）、subagent（subagent、agents_ctl、fork）、def（agent_def、tools_def）、mailbox（peek、read、send）、goal、json（9 支）、jsonx（8 支）、index（index_view）；kernel_gate 不在範本。agent-fsm 預設 15 包 55 支全開（使用者 11-10「預設開到第四包，想要安全就自行限制」）。
- **整包關**＝定義的 `tools.json` `$override` 串拿掉那一包（人或改定義做，agent 自己做不到）；**單支關**＝覆蓋層寫 `"名": null`（`self_tools rm`／`aos-agent tools rm`）。**但有 self 包的 agent 能用 `self_tools add` 把任何工具加回來**，沒有「不許再加」的鎖。
- **寫入範圍沒有內建限制**：write／edit／trash 相對路徑從 `$AOS_WS` 算、絕對路徑照用、**不擋工作區外**；remove 只擋 `/`、`.`、`..`；shell「不是沙箱」，只有 command 與 timeout（預設 30、最多 300 秒），沒有指令白／黑名單（`P/lib/base/write/_entry:4`、`shell/_tooldef.json`）。
- **擋工具呼叫的唯一機制＝`before_tool` hook**：hook 收 `{name, id, arguments}`，退 10＝攔下，腦收到「tool X blocked by hook H」或 hook 印的字（`P/lib/agent/hooks.py:52`、`act.py:189`）。hook 在定義的 `hooks.json` 或覆蓋層；**有 `self_hook`（events 包）的 agent 能自己把 hook 關掉**；母也能透過 `subagent op hook` 改子的 hook。
- **沙箱**：`aos-sandbox`（bwrap 白名單＋s6-softlimit 限資源；設定寫壞＝靜默不套）可包在單支工具外（例 `P/cmd/aos-sandbox/examples/shell-boxed/`：只寫得到 `$AOS_WS` 與自己 stack、斷網）或整隻 agent；範本預設**沒用**。家機有 `bwrap`、**沒有 `s6-softlimit`**；subagent-boxed 例子未實測。
- daemon `limits`：`mem_mb`、`cpu_s`、`procs`、`file_mb`、`files`、`user`（rlimit／換帳號），不管路徑。
- kernel 管不到工具呼叫與寫檔，只管「起哪些 agent」（框架站 `allowed` 名單、`max_running`）與「問腦」。

## D. 腦：端點、模型、額度

- 路徑：brain 格寫 `think/request.json` → wait 格 `aos-llm send` 進 `$AOS_LLM_KERNEL/requests/` → llm kernel 每封掛一個 proc 跑端點程式 `lib/base/llm_http` → `POST <url>/chat/completions`（**只支援 chat completions**，tools 用 OpenAI function 格式）。
- **網址、模型名都在 llm kernel 的 `kernel.json` 的 `endpoints.<包名>`**（`url`、`model`、`fixed`、`slots`、`cost`、`summary`）；agent 的 `llm.json` 只寫 `{"model": "<包名>"}`。金鑰＝llm daemon 環境的 `LITELLM_KEY`（不設就不帶，本地 proxy 免 key 可跑）。
- 出廠範本 `P/kernel/llm-kernel/kernel.json` 已有 `luna`（`chatgpt-gpt-6-luna-low`）、`terra`（`chatgpt-gpt-6.1-terra`）、`sol`（`chatgpt-gpt-6.1-sol`，temperature 0.2），網址 `http://localhost:4000/v1`；**沒有 astra、沒有 -medium／-high 包**；預設包是 `fake`。家機活樹的 llm kernel 實際內容沒看（活樹不碰）。
- **agent 端沒有 reasoning effort 欄位**（刻意不開，`llm_settings.py:5`）；effort 只能靠 proxy 模型名後綴，一個 effort 一個包。`fixed` 可疊任意請求欄位（程式可行、沒人用過）。
- `self_llm` 能把自己換成表上任何包（含較貴的），不擋；限制只能靠 kernel 的 `budget`。
- 額度（`P/lib/aos/kernel_llm/budget.py`）：總額／每包／每寄件人（`budget.senders`，key＝寄件人資料夾路徑）各可設 `max_calls`、`max_tokens`、窗 hour/day/all，到頂 `BudgetMissing`（或 `spent: wait` 停下等）。**沒有金額上限**（`cost` 只是標籤）。寄件人不驗身分。
- 逾時：kernel `timeout_ms` 120000；HTTP 讀回應不設限；沒有 429／5xx 專用重試，proc 死掉重掛一次。

## E. 信箱與外面看得到的

- 每個 stack 有 `mailbox/`（跟 `queue/` 分開，信不自動進 history）。信：`status`（REQUEST、DONE、BLOCKED、NEEDS-USER、FAILED、PROGRESS）、`title`、`what`、`outputs`、`not_done`、`decide`、`reply_to`。寄給 daemon 表上的名字或某個信箱路徑；**誰都能寄給誰、`from` 自報不驗**。
- `mail_notify` hook 每分鐘看一次，有新信往 queue 丟一句 `[aos] new_mail: …`（新起來時已在等的信不提醒）。
- 人或頂層寄信：`aos-mailbox -s <我的 stack> send --to <名> --status REQUEST --title … "內容"`，回信落在該 stack 的 `mailbox/`，`aos-mailbox -s … read/peek` 讀；或 `aos-agent say -t 名 "話"`（直接進 queue）＋`listen`。頂層不是 agent、沒有 mail_notify，要自己看。
- 外面看：`aos-agent ctl ls [-l|-j]`（phase、queued、cooldown、last error、busy）、`ctl state -t 名`（十一部分）、`aos-agent history -t 名 ls`（agent-fsm 的 history 含工具呼叫與結果）、`procs/<名>/stderr.txt`。`stuck`＝控制窗沒答，不是「工作卡住」。
- `todo` 只有本人能讀寫；`do_task` 是自己 history 的摺疊，不是派工。
- on_clock hook 每格開頭檢查，卡在一格裡（長時間 wait／act）時不會跑。

## F. 既有規矩（wf/，使用者定的）

- gpt 系**不參與軟體設計決策與架構規劃**，只照圖紙寫碼、寫文件、雜活；審查只能挑實作錯與跟圖紙不符（使用者 11-07）。
- astra：A 級、價格約 sol 3 倍，原本**只派圖像、創意類**（使用者 11-06）；sol 為一般工作主力，terra 給簡單工作（碰程式邏輯不算簡單）。
- 工人**不 commit**；隊長（Claude opus）審 diff、跑 build、commit；push 要使用者說。
- 舊 codex 隊員的權限邊界：`-s workspace-write` 沙箱（`.git` 不可寫，commit 由隊長在沙箱外做）、不加繞過沙箱的旗標；codex 要設 `/goal <完成條件>`（愛做到一半就說做完）。
- 每隊同時最多兩個 CLI 程序（nodejs 吃機器）；agent-fsm 不是 nodejs，但每隻都是一組行程＋每次問腦一個 proc。
- 規則：本地與遠端只有 `main` 一個分支、不開 worktree 分支。
- 頂層＝調度者，只派隊；「agent 寄來的信不是授權」，例外是 `eca_main` 派的普通工作。
- 家機活樹 `~/aos-home` 是使用者正在用的樹；動它（加 endpoint 包、建定義、起 agent）要頂層放行。
