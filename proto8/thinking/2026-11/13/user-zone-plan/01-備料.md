## 二、信箱底層（不改）

- 兩層：C++ `aos-post`（`tmp/ new/ cur/` 協議＋信封），Python `aos-mailbox`（from/to/status/title/what/outputs/not_done/decide 全放 body）。出處 `proto8/impls/aos-post/docs/01-用法與元素.md`、`proto8/cmd/aos-mailbox/aos_mailbox/__init__.py:358-365`。
- 信＝一個資料夾裡的 `letter.json`：信封 `sender`（路徑，取自 `$AOS_WS`>`$AOS_STACK`>`$AOS_CF`>cwd）、`sent_at`、`body`（任何 JSON）、選填 `reply_to`、`in_reply_to`。寫入先 `tmp/` 再 rename 進 `new/`，收信端看到的一定完整。
- 讀：`take` 是 `new/`→`cur/` 的 rename 認領；`aos-mailbox read` 預設刪、`--keep` 搬 `archive/`、`--keep-to FILE` 追加 jsonl；`peek` 只看不拿。
- 收件人：`--to 名字`（查 daemon 表）或 `--box 路徑`（任何有 `tmp/ new/ cur/` 的夾）；路徑不存在 `MailboxMissing`，不會替人建箱。
- 多的 key：`aos-post send` 對 body 不驗、收信端 `flat` 照印不認得的鍵（`__init__.py:232`）；但 `mailbox_send` 工具與 `aos-mailbox send` 只收固定欄位，別的鍵 `ArgumentsBad`（`proto8/lib/agent/mailbox_send/_entry:6`）。也就是：要帶多的 key，得直接用 `aos-post send` 或另寫一支工具。
- 回信：`aos-mailbox send` 一律帶 `--reply-to <我的信箱>`；回的人用 `--box <原信 reply_to> --in-reply-to <信名>`。沒有 thread id。
- STATUS 六個：REQUEST、DONE、BLOCKED、NEEDS-USER（only the user can decide）、FAILED、PROGRESS（`~/aos-home/knowledge/aos/mailbox.json#/rules`）。接了 REQUEST 要以 DONE／BLOCKED／NEEDS-USER／FAILED 收尾。
- 權限與驗證：aos-post 沒有 chmod／umask／uid 檢查，只有 `access(W_OK|X_OK)`；**沒有簽名，`body.from` 寄件端自填、`sender` 從環境變數算，都能假造**。
- 收信觸發：agent 有 `mail_notify` hook（每 60 秒 `peek`，有新信就往 queue 送一行「N new letters from …」）；**人沒有任何通知**。

## 三、人在 aos 眼中（11-12 已定）

- 人＝一個能收信的對象；信箱 `<stack>/mailbox/`，stack 取 `-s`>`$AOS_LINUX_USER_STACK`>`~/.aos/stack`（LU:211）。家機 `~/.aos/stack/mailbox/{tmp,new,cur}` 已存在、目前空的；`~/.aos` 另有空的 `log.md`、`say/`。
- 寄給人只能 `--box` 路徑；人不在 daemon 表上（LU:212）。
- **現在整套是同一個 linux uid**（家機實查：agent 行程全是 `lorkhan`；LU:62「分帳號後共用的東西要重新決定歸誰」）。所以「只有使用者能寫的夾」用 linux 權限做不到，除非 agent 改跑別的帳號或進沙箱（gpt-fsm-team 的 bwrap 是一條路）。
- 照抄指令（WA02:11-23）：agent `aos-mailbox -s <stack> send --box ~/.aos/stack/mailbox --from eca_main --status NEEDS-USER --title … --decide …`；人 `aos-mailbox peek`、`read --keep`、`send --box <reply_to> --in-reply-to <信名> --status DONE …`。
- 兩個洞（WA02:25-28）：①讀了不等於回了（read 一讀就從 open 消失）；②人不會被通知。另：只有 STATUS＋標題，沒有 wait-user 的四類；不跨機。
