## 段 1：最小可用（指令列）

**做完使用者怎麼用**：終端機打 `aos-user ls` 看到所有在等他的事（急件在上），`aos-user show 3` 看題目與推薦，`aos-user answer 3 q1:a` 回掉；原寄件 agent 一分鐘內被叫醒、收到回信；那封從待辦消失、留在 `done/`。

| 步 | 做什麼 | 檔 |
|---|---|---|
| 1 | 新指令 `aos-user`：`init`、`where`、`send`、`ls`、`show`、`answer`、`reply`、`ok`、`later`、`door`；`--json` 給程式讀；錯誤碼照 aos 慣例（`aos-user: error: 代號 原因`，0／10／1） | `proto8/cmd/aos-user/`（`aos_user/__init__.py` 指令、`aos_user/zone.py` 函式庫、`README.md`、`tests/test_user_zone.py`），檔頭一句話（鐵律 3） |

**驗收**（全部在暫存夾，不碰活樹）：

1. `aos-user init` 兩次：第二次不蓋掉既有的 `door.json`、`log.jsonl`。
2. 假 agent stack 用 `aos-user send` 寄一封 decide（兩題、帶推薦）→ `ls` 看到一列、標 2 題、`show` 後信在 `cur/`。
3. `answer 1 q1:a q2:b*` → 假 agent 的 `mailbox/new/` 多一封：八個標準欄齊、`in_reply_to` 對、`answers` 兩筆、`differs` 第二筆 true；專區那封搬到 `done/2026-11/<信名>/`，有 `reply.json`。
4. 回信對象信箱刪掉再 `answer` → 報 `MailboxMissing`、信留在 `cur/`、答案進 `drafts/`。
5. 用 `mailbox_send` 舊格式寄 NEEDS-USER → `ls` 標「舊」，`reply` 回得出去。
6. 缺 `options` 或 `recommend` 的 decide → `send` 當場拒寄（`SchemaBad`），信箱沒多東西。
7. 同 `dedupe_key` 寄兩封 → `ls` 疊成一列，`answer` 一次兩邊都收到。
8. 測試套件：`python3 -m pytest proto8/cmd/aos-user/tests`（照 dev-env 的跑法）全過。

## 段 2：通知＋收件檢查＋過渡

**做完使用者怎麼用**：有新題桌面跳通知；不合公告的信自動退回寄件人；agent 能驗「這封回信真的是使用者從專區回的」；新題不再寫進 WAIT_USER。

- 通知：使用者沒有 daemon、沒有 `mail_notify`，所以用 `systemd --user` 計時器（家機 linger 開著，LU:17）每分鐘跑 `aos-user tick`：收件檢查（schema、寄件人每小時上限）、不合的搬 `rejected/` 並退信、有新信跳 `notify-send`、到期題提醒。公司 WSL 的 `systemd --user` 與桌面通知待驗（06 第 14、15 條）。
- `aos-user verify <信資料夾>`（L1）：比 `letter_hash`＋log。
- aos 工具 `user_send`（`proto8/lib/agent/user_send/`）給沒 shell 的身；範本預設不掛，誰要誰加（跟 `kernel_gate` 同做法）。
- 守門 hook（eca 身）：aos 工具寫 `~/.aos/user/` 除 `mailbox/` 以外一律擋。只是紀律加一道，不是保證。
- 過渡：WAIT_USER 新題改進專區——**這件屬線遷（`wf/` 走入 aos）**，這裡只交介面：`aos-user ls --json` 的欄位就是 wait-user 的四類（kind＝decide／verify／trial／chore）。
- 驗收：寄 7 題一封、第 8 題被拒；1 小時內第 N+1 封被退；`notify-send` 真的跳（家機）；`verify` 對真回信說 ok、對手改過一個字的說 bad。

## 段 3：桌面網頁

**做完使用者怎麼用**：瀏覽器開 `http://127.0.0.1:8766/`，一題一張卡點選項、寫意見、送出；可存草稿、看已回、切出門模式。

- `aos-user serve`（`aos_user/web.py`＋`web/` 靜態檔）；四頁；POST 帶 token、Host 檢查、只綁本機。
- 看板 8765 的「待你裁」加一條連到 8766 的連結（改 `wf/tools/progress_board/`，要跟線遷對齊）。
- 驗收：用 `curl` 帶錯 Host、沒 token 各被拒；網頁答的跟指令列答的回信只差 `via`；兩個分頁同時答同一封，第二個收到「已回過」。

## 段 4：手機

**做完使用者怎麼用**：出門時手機被叫一聲「3 題等你」，點開就是手機版面，點選項就回掉。

- 照 U3、U4：家機 `tailscale serve` 代理 8766；推播只送「幾題、標題」不送內容；`config.json` 出門模式只推急件，一般的每天彙整一則。
- 備案：`remote_sync.py export` 多推 `snap/zone`，claude.ai 手機看板多一欄；回答經頂層拉回，標 `via: phone-relay`。
- 驗收：手機（tailscale 內）開得到、tailscale 外開不到；推播內容不含題目內文；手機答一半關掉，回家草稿還在。

## 段 5：加強

- L2 簽名（`ssh-keygen -Y sign`、密語鎖、公鑰進 repo）；`aos-user answer --sign`。
- `aos-user import-decide decide_*.json`：decide-page 的大批題變一封 `kind=decide`；答完 `aos-user export-reply` 吐出 decide-page 的一行回覆，接 `decide_page.py parse/apply/land`。
- 專區 agent（若 U8 要）：只做排序、合併重複、補白話、每日「先看這三件」，寫的東西放旁邊一格、標明是它補的。

## 段 6：長期

- L3：agent 改跑別的帳號或進 bwrap，只有 `mailbox/` 寫得進專區（跟分帳號那條線一起做）。
- `done/` 跨機歸檔（私人 git，只增不改）。
