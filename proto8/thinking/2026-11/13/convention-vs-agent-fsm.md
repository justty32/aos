## P-05 入口：條文說入口是一支 shell、裡面直接跑 loop；範本的入口是一張「把自己掛上 daemon」的單子

**1. 條文原句**（`01-保證佈局入口/02-三-入口-loop-fsm.md` 第 5 行）

> - **P-05** 入口 `_entry`（預設 `$AOS_ENTRY`，…）一定帶 shebang（`#!/bin/sh`），下一行 `exec aos-loop loop.json`（設定檔是 aos-loop 唯一的位置參數，…）。也可以讓 loop.json 帶 `_entry`、入口寫 `exec aos-exec loop.json`。（§ 4 原話「#usr/bin/sh aos-loop loop.json」。…範本仍寫 shebang、不靠那條退路；`exec` 少一層行程、訊號直達 loop——本稿定。帶 shebang 的是**可執行檔入口**這一種；入口也可以是沒 `+x` 的 JSON（單子、argv 陣列、`js[$AOS_ENTRY]`，C-73，§ 14），那種入口由 aos-exec 讀、**不寫 shebang、不設 `+x`**（寫法見 P-40）。標準範本 [templates/agent-fsm]… 的 `_entry` 是這種沒 `+x` 的 JSON（單子 `aos-agent ctl add`；`aos-loop loop.json` 寫在 `body.json`，C-73、P-27）；本條改不改由使用者定）

同一條裡，開頭說「一定帶 shebang」「範本仍寫 shebang」，尾巴又說標準範本不是這種。

**2. 範本實際長相**

```
$ ls -la templates/agent-fsm/_entry
-rw-r--r--  …  85  _entry          ← 沒有 +x
```

`_entry`（整份）：

```json
{"argv": ["aos-agent", "ctl", "add", {"$env": "AOS_CD"}], "cwd": {"$env": "AOS_WS"}}
```

`body.json`（整份）：

```json
["aos-loop", "loop.json"]
```

`interfaces.json` 裡 `"entry": "body.json"`。也就是：`aos-exec 這個資料夾` 做的事是「跟 daemon 說：把我掛上去」，然後就回來；真的跑 loop 的是 daemon，它跑的是 `body.json`。

**3. 這條規定當初的用意**

- 入口是 shell 檔＋`aos-loop loop.json`：使用者 10-19 早上（[01-原話](../../2026-10/19/ideas/01-原話.md) § 1）「然後我們所謂的寫程式，就是定義一個資料夾agent-bob/，然後設定入口：一個shell檔案，經過chmod +x，內容是aos-loop loop.json」；§ 4「因為agent-bob/.aos/exec的內容就是#usr/bin/sh aos-loop loop.json，而cwd就是agent-bob/」。
- 「一定帶 shebang、用 `exec`」是條文自己定的（條文標「本稿定」），理由寫在條文裡：少一層行程、訊號直達 loop。
- 入口也可以是 JSON：使用者 10-19 下班前（[03-原話](../../2026-10/19/ideas/03-原話.md) § 14，後來的 [C-73](../../../docs/CONCEPTS/01-設計理念/07-C-73.md)）「要麼自己是可執行檔，要麼是可以被aos-exec的標準實作所執行的檔案(aos-exec _exec)」。
- 範本為什麼變成現在這樣：
  - 11-04 [loop-fsm-agent 設計稿](../04/loop-fsm-agent/01-設計.md) 的 `_entry` 還是 `["aos-loop", "loop.json"]`（已經不是 shell）。
  - 使用者在 [11-03 aos-agent](../03/aos-agent.md) 那份說：「agent不需要佔據workspace。agent本身就是一支aos proc，由daemon管理(對，先暫時忽略直接aos-exec出來的那些)」。
  - 使用者 11-05（[portable-flow](../05/portable-flow/README.md) 題 4）：「aos-agent add。當然，你也可以把_entry寫成aos agent add，這樣我們也可以aos-exec了。」——同一天 commit `6e49aafab` 把 agent-fsm 的 `_entry` 改成呼叫 `aos-agent ctl add`。這句已寫進 [P-43（續）](../../../docs/CONVENTION/02-題目stack停錯腦/03-P-43續-11-04-aos-agent.md)「入口也可用來掛上 daemon」。

**4. 可行的收法**

- **(甲) 條文改成照範本**：P-05 第一句改成「標準範本的入口 `_entry` 是沒 `+x` 的 JSON 單子：`aos-agent ctl add` 把這隻掛上 daemon；身體的入口是 `body.json`＝`["aos-loop", "loop.json"]`，由 `interfaces.json` 的 `entry` 指」。shell 入口（`#!/bin/sh`＋`exec aos-loop loop.json`）降成「也可以這樣寫」的另一種。後果：不動程式；P-35（靠「入口一定是自己的 loop」）、P-29（說 JSON 入口不是範本）要跟著改；10-19 的原話留在括號當沿革。
- **(乙) 條文留著，把兩種入口並列、不說誰是「一定」**：把「一定帶 shebang」改成「入口有兩種：可執行檔（寫法如下）或沒 `+x` 的 JSON（P-40）；標準範本用後者來掛上 daemon」，尾巴那句「本條改不改由使用者定」拿掉。後果：改動最小、不動程式；但條文沒有回答「照抄的人該抄哪種」，P-35 還是懸著。
- **(丙) 範本改回照條文**：`_entry` 改成 shell 檔直接跑 loop。後果：要動範本、測試、`aos-agent`／子 agent 工具的掛法，而且跟使用者 11-05 那句、11-03「agent 是 daemon 管的一支 proc」反著走。

**5. 建議（寫手的，不是定案）**：甲。標準已經裁成 agent-fsm，入口這條是整份慣例的開頭，寫明「入口＝掛上 daemon、身體在 body.json」最不會讓照抄的人抄錯；而且有使用者 11-05 的原話撐著。

**裁定（11-13 第二輪）＝選 A（甲）：條文改成照範本——入口＝掛上 daemon 的 JSON 單子、身體在 `body.json`，shell 入口降成「也可以這樣寫」**（照建議）。使用者回覆原文：「cv-P05:A」。還沒施工。

## P-27 混合寫法：條文說「有真邏輯的格開一個子資料夾、裡面寫 shell」；範本四格都有真邏輯，卻全是「一張單子叫一支 python 檔」

**1. 條文原句**（`03-shell版與inst版.md` 第 5 行；同一個說法也在 `01-保證佈局入口/01-一-aos-保證的與二-佈局.md` 第 9 行、`04-範例三種寫法.md` 第 58 行）

> - **P-27** 標準範本＝**混合寫法**，就是第二節 [templates/agent-fsm]… 的樣子：…**狀態表一律寫在 `fsm.json`**；一行講完的格（跑哪支程式、多久逾時）內嵌單子，直接寫在 `exec`：`"exec": {"argv": ["python3", "brain.py"]}`…——agent-fsm 的四格都是這種，邏輯寫在範本資料夾的 python 檔，沒有資料夾格；有真邏輯的格 `exec` 寫子資料夾名、裡面是 shell。要頻繁改的東西（流程、逾時、誰接誰）全在一份 `fsm.json` 裡；要寫邏輯就開資料夾、用 shell，不用把 shell 塞進 JSON。

01 第 9 行：

> 混合寫法（§ 10 使用者「好主意」）：狀態表一律寫在 `fsm.json`；一行講完的格內嵌單子；有真邏輯的格 `exec` 寫子資料夾名。…四格 idle／think／wait／act 都是單子叫範本裡的 python，沒有資料夾格。

四支 python 的行數：`idle.py` 247、`brain.py` 217、`wait.py` 426、`act.py` 247（都是真邏輯）。範本裡沒有任何子資料夾、沒有任何 shell 檔。

## P-33 工具放哪：條文說工具放在叫它那一格的資料夾裡、用相對路徑叫；範本的工具都登記在一份清單、放在函式庫

**1. 條文原句**（`06-巢狀/01-P-33～P-34.md` 第 8 行）

> - **P-33 工具放在叫它的那一格的資料夾裡：`<格>/tools/<名>/`，格裡寫 `aos-exec tools/<名>`，永遠零個 `..`。** 相對路徑從 cwd 算，而格起跑時 cwd 就是格自己的資料夾（N-59），所以不管這格被埋在第幾層，路徑都一樣長、一樣對。例：bob 的 act 格叫 `tools/cathy`，cathy 的 act 格叫 `tools/stamp`——`<bob 的資料夾>/act/tools/cathy/act/tools/stamp/` 這條路徑就是呼叫鏈本身（P-38）。內嵌單子格（think）的 cwd 是 agent 資料夾，它若要工具就是 agent 根下的 `tools/<名>`，同一條規則。**不給程式根變數**（aos 只訂那幾個變數，§ 4；…）；**不用 PATH**（C-61）。幾格共用一個工具、幾隻 agent 共用一隻 cathy：共用的收進函式庫 `proto8/lib/`（C-61），在自己的 `tools/` 放一條捷徑指過去（…），或登記進 `tools.json`；同名自己的贏；要釘版、要改寫才複製一份（複製＝自己維護，版本＝git；使用者 11-12 裁 Q16「a」）。

（02 夾的 P-25 是同一件事的短版：「工具＝`tools/<名>/` 子資料夾程式，**放在叫它的那一格的資料夾裡**（`act/tools/cathy/`），格裡寫 `aos-exec tools/<名>`」。）

**2. 範本實際長相**

範本沒有格的資料夾，也沒有 `tools/` 夾。`tools.json`（前三行與最後一行，中間同形共 15 包）：

```json
{"$override": [{"$env": "AOS_HOME", "$path": "/lib/packs/look.json"},
               {"$env": "AOS_HOME", "$path": "/lib/packs/change.json"},
               {"$env": "AOS_HOME", "$path": "/lib/packs/delete.json"},

               {"$env": "AOS_HOME", "$path": "/lib/packs/index.json"}]}
```

`act.py` 叫工具的那兩行：

```python
TOOLS = ["aos-tools"] + (["--file", tools_file] if tools_file else [])
```

三件事跟條文不一樣：(1) 工具不在自己資料夾裡，在 `proto8/lib`；(2) 靠 `AOS_HOME` 這個環境變數找到函式庫——它不是 aos 保證的六個變數之一，作用就是條文說不給的「根變數」（只是指的是函式庫的根，不是 agent 的根）；(3) 沒有捷徑，「放捷徑指過去」這個做法範本不用。

## P-35 agent 當工具：條文說被叫的 agent 入口是自己的 loop、跑到沒事才回來；範本的入口是「掛上 daemon」就回來，而且常駐不收工

**1. 條文原句**（`06-巢狀/02-P-35～P-36.md` 第 3～4 行）

> - **P-35 格可以是一整隻 agent，不可以是別人 fsm 的一次；10 只有 idle 退。** 當工具的 agent 入口一定是它自己的 loop（P-05），被叫一次就從現在的 state 跑到它的 idle 退 10 為止才回來；它的 loop 收到 10 退 0，所以呼叫它的格看到的是 0，上層的 loop 不會被誤停——cathy 的 10 到不了 bob。…格叫工具時**工具的非 0 一律當失敗、自己 `exit 1`**（…），不把工具的碼原樣 `exit`——工具若退 10 會被 fsm→loop 當成「停」。

第 4 行的加註：

> - **接住的 10 到不了 loop**（使用者 10-30「都照建議」，…）：「10 只有 idle 退」是字串 `next` 那種表的慣例；物件 `next`（N-36）的表上，任何一格的 10 都可以被接住…。例子是 `templates/agent-fsm`（使用者 11-04 衝突 2 選「think 也退 10，條文加註」，…）：…idle 退 10＝queue 空，範本表上接住＝停著等、改成字串 `next`＝10 到 loop＝收工…。「格叫工具時工具的非 0 一律當失敗、自己 exit 1」不變；agent-fsm 的 act 把工具的非 0 回給腦、自己不退那個碼。

**2. 範本實際長相**

- 入口：見 P-05（`_entry` 是 `aos-agent ctl add`，掛上就回來）。
- `loop.json` 沒有 `max`，`fsm.json` 的 idle 格 `"next": {"0": "think", "10": "idle"}`——idle 退 10 被表接住、留在 idle，loop 永遠收不到 10，所以不會「跑到沒事就回來」，是常駐的。
- `idle.py` 檔頭：`10＝沒信（表上接住＝停著等，改成字串 next＝收工）`。
- `act.py` 檔頭：`工具退非 0 時 stderr 多一行提醒「agent-fsm: warning: tool <名> exit code N (passed back to the brain)」（…不是這格的錯，照樣退 0）`。

所以 P-35 有三句對不上：「入口一定是它自己的 loop」「被叫一次跑到 idle 退 10 才回來」「工具的非 0 一律當失敗、自己 exit 1」（最後一句條文加註裡已經自己承認 agent-fsm 不這樣）。

**3. 這條規定當初的用意**
