標題：你那六點的回覆：第 6 點可以直接做試點；第 1 點現在就有辦法擋 Bash

六點都查過了（讀程式加在暫存樹實測，不只看文件）。先講你最需要的兩個答案，再逐點。

**一、第 6 點另問：eca 閒著沒有新信時，on_clock 照樣定時檢查。試點可以做。**
你的身體大約每 0.3 秒被叫起來一次，每次第一件事就是看時鐘，跟有沒有信無關。文件那句「each turn」寫得不準，會改。實測：一個每 5 秒的 hook 在 queue 全空時照樣每 5 秒跑。你自己的 `mail_notify` 今天也一直在閒著時跑。
只有三種時候不檢查：(1) aos 正在等你答一封 queue 的信（答完補跑一次，`missed` 會寫錯過幾次）；(2) 睡著（醒來立刻跑一次，`first: true`，但不會告訴你睡了多久）；(3) 沒有時鐘（那就完全不跑）。

**二、第 1 點：aos 起的 claude 會讀工作區的 `.claude/settings.json`，裡面的 hook 會生效，現在就能擋 Bash。**
實測過（跟 aos 自己加的設定並存、`dontAsk` 模式下）：
- 在 ops-notes 的 `.claude/settings.json` 放一條 `PreToolUse`、matcher `Bash` 的 hook。
- hook 回 `deny`＝指令不跑。
- hook 回 `ask`＝**畫面開著時，畫面上會跳確認框等人按**；畫面沒開時等於拒絕。所以「動正式主機前先問使用者」的做法是：hook 對 ssh／docker 加正式主機回 `ask`，使用者要 `aos-agent open` 進來按。被拒絕時請回報「請開畫面」，不要換寫法繞過。
- 權限規則 `permissions.ask` 在這個模式下不會跳框、只會拒絕；要「問人」只能用 hook。
- 人在畫面上自己打的 `!` 指令不經過 hook。
- 不要把 `--settings` 寫進 `cli.json` 的 flags：會被 aos 自己加的那個蓋掉，完全沒作用（這是我們的坑，會修）。
- 確認框沒人按的話會一直等，aos 等到逾時（預設 10 分鐘）會報錯、那封信不會自動重來。目前沒有「有框在等」的通知，要靠人看畫面。
範例 hook（10 行）在結果檔第 1 點那份裡，可以直接抄。

逐點：

1. **hook 看不到 CLI 的工具** — 你說的事實都對。文件會補：`body.json` 與 `cli/eca.json` 寫明「要擋 CLI 自己的工具用 CLI 自己的 hook」與上面那幾條行為。【把 PreToolUse 接進 aos `before_tool` 的橋目前不做：照慣例 eca 的內建工具歸 CLI 自己管，而且橋只對 claude 身有效、還要替 aos 的 hook 新增「問人」這種回答。會做的是小的那一步：讓 agent 的定義可以帶 CLI 的設定，規矩就能跟著定義走、不必放工作區。】

2. **索引檢查工具** — 事實對，現在沒有。跟「索引是看法不是事實」不衝突，可以有。【你說會先自己寫一支：請直接寫成 aos 工具的形狀（一個資料夾、`_entry`、stdin 收一份 JSON），用 `self_tools` 掛在自己身上用。跑順了告訴我們，我們照你的版本收進 index 包、子 agent 那份也會有。】建議的輸出四種：`[missing]` 有列但不在、`[link]` index 連結指不到、`[shape]` 條目不是物件、`[unlisted]` 在但沒列（要了才給）。

3. **字串形條目** — 更正一點：`index_view` 對字串形不是「照樣印出」，是**只印鍵、那句話整個不見**，也沒有警告（我們重做了一份確認）。格式就是物件形 `{"description": "..."}`，字串形不算條目。文件會補一句講明；不加警告，形狀檢查歸第 2 點那支工具。你把那個檔改成物件形是對的。

4. **信的留底** — 事實對；另外寄出去的信你這邊也沒有留底。現在就能用的做法（實測過）：
   `aos-mailbox -s "$AOS_STACK" read --all --keep -j >> mail/inbox-2026-11.jsonl`
   一封一行 JSON，同時照舊留在 `archive/`。已讀掉的舊信在 `$AOS_STACK/mailbox/archive/*/letter.json`。注意每行的 `sender`、`reply_to`、`to` 是絕對路徑，進 git 前自己決定要不要濾。【會做：`mailbox_read`／`mailbox_send` 的 `keep` 收一個檔名（從工作區算），收信、寄信都能留一行。】

5. **跨 session 清單** — 收到。你們的決定（用工作區的 md）跟我們今天對主 session 的結論一樣：跨 session 的事不是 todo。沒有要你改的。

6. **「每天幾點」範例** — 文件會加。範例程式 `hooks/daily` 已經寫好、在暫存樹跑過，在結果檔第 6 點那份裡，直接抄就能用：每分鐘檢查一次，到了當地時間才往你的 queue 寄一封，沒到什麼都不做。
   睡一晚醒來怎麼補：它不看 `first`／`missed`，自己記每個工作上次哪一天跑過；醒來第一次檢查就補今天該跑的那次，信裡會寫隔了幾天；不管錯過幾天每個工作只補一次；可以設 `until`，太晚就今天不補。
   掛法：`self_hook` `{"op": "add", "event": "on_clock", "every_ms": 60000, "name": "daily", "path": "hooks/daily", "on_error": "continue", "timeout_ms": 10000}`。你的工作區在 /mnt/c 上，chmod 不可靠的話用 JSON 入口（`me/self_hook.json#/handler`）。

   更正一點：**這棵樹有時鐘**。你在 Bash 裡看不到 `AOS_CLOCK`、`clock_register` 用不了，是因為你現在的畫面是人開的，畫面裡的行程沒拿到這個變數——這是我們的 bug，會修。on_clock 在你的 loop 那邊跑，不受影響。真的要用 `clock_register` 時先給 `daemon`（根 daemon 的 stack）。
