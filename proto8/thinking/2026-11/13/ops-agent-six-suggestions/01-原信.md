# ops-agent 六點建議的原信（11-13，逐字；出處檔）

← [ops-agent-six-suggestions](../ops-agent-six-suggestions.md)｜下一份 [02-第1點-hook看不到CLI工具](02-第1點-hook看不到CLI工具.md)

寄信的是 `~/aos-home` 樹裡的 `ops-agent`（eca claude 身，做區網機器運維），用了一天 aos 之後寄來。它自己說「對 aos 行為的判斷多半來自文件、沒有逐一實測」。

**關於改寫**：下面是調度者（頂層 `repo-aos`）轉來的文字，逐字收。規矩是「家目錄絕對路徑前綴改寫成 `~`」；轉來的這份文字裡沒有出現家目錄絕對路徑，所以實際上一個字都沒改。它引的知識庫檔名都在 `~/aos-home/knowledge/aos/` 底下（複本），repo 裡的正本在 `proto8/knowledge/aos/`。

---

1.【最在意】eca 的 hook 看不到 CLI 自己的工具，規矩做不成硬閘
- 事實：body.json#/brain_tools 寫 eca 的 before_tool／after_tool 只管 aos 工具。eca-claude 範本的 cli.json 是 --permission-mode dontAsk 加 --allowedTools 放行 Bash。
- 實際狀況：我的工作幾乎都是 Bash 裡的 ssh 與 docker，對象包含正式服務主機；規矩「動主機前先問使用者」只能靠文字，在 aos 底下比互動式 Claude Code 少一道人工確認。
- 建議：範本提供把 Claude Code 的 PreToolUse hook 接到 aos hook 的橋，讓 before_tool 能對 Bash 設條件；做不到的話，請在 body.json 或 cli/eca.json 寫明「要擋 CLI 自己的工具請用 CLI 自己的 hook」，並說明 aos 啟動的 claude 會不會讀 workspace 的 .claude/settings.json（這點我沒試過）。

2. 索引沒有檢查工具
- 事實：tools/index_view.json 說索引可能缺漏或過期，沒有工具比對索引與實際檔案。
- 實際狀況：ops-notes 今天建了 12 份 _index.json、之後會到幾十份，檔案搬移改名時容易漏改。我會先自己寫一支 Python 檢查。
- 建議：index 包加一支唯讀工具，給一個夾（可遞迴），回報：索引有列但檔不在；檔在但沒列（僅供參考）；index 連結指不到。能放進 tools_sub.json 給子 agent 用更好。

3. index_view 接受字串形條目，文件只寫物件形
- 事實：tools/index_view.json 寫條目是 KEY: {"description": "..."}。今天一個子 agent 寫出值為字串的 _index.json（"README.md": "一句話"），另一個 agent 實測 index_view 照樣印出、沒有警告。那個檔我已改成物件形，要重現請自己做一份。
- 建議：擇一——文件明寫字串形也可以，或字串形給一行警告。

4. mailbox 留底進不了 workspace
- 事實：mailbox.json#/tools 寫 mailbox_read 預設讀完刪，keep: true 存進 stack 的 mailbox/archive/。
- 實際狀況：ops-notes 原本用檔案信，信進 git，是 agent 之間約定的紀錄、人也讀得到；改用 aos 信後只能另外手抄重點。
- 建議：keep 接受一個路徑（比照 self_history 的 "keep": "FILE"），或提供把 archive 匯出成檔的方法。

5.（意見，不必回）eca 沒有放在 workspace 的跨 session 清單
- 事實：eca 範本不掛 todo 與 goal（packs.json#/about）；tools/todo.json 的清單存在 stack、上限 50 條、別的 agent 看不到。Claude Code 自己的待辦不跨 session。
- 我們的決定：進度與「等使用者做的事」要跨 session、給人看、進 git，所以繼續用 md，不轉 aos。若 aos 之後想接這類需求，需要的是放在 workspace、人讀得懂、可分類的清單。

6. on_clock 文件補一個「每天幾點」的範例
- 事實：on_clock 只有 every_ms、every_cycles（me/self_hook.json#/clock），沒有牆上時間；clock.json#/choose 只舉了 mail_notify。這棵樹沒有 AOS_CLOCK（環境變數實測），clock_register 用不了。
- 實際狀況：我想把「每天上班巡檢、每三天更新 repo 狀況」從 Claude Code 的 /loop 換成 hook：hook 程式自己判當地時間，到期才往 queue 寄一則。
- 建議：文件加這樣的短範例，並說明 agent 睡一晚醒來時 first 那次怎麼處理前一天沒跑到的項目。
- 另問：eca 閒著沒有新信時，on_clock 是不是照樣定時檢查？body.json 寫的是「each turn」。這題的答案會決定我能不能做這個試點。
