aos-home 手冊（公司 WSL）

11-13 早從零搭好：一棵樹、一隻懂 aos 的 opus（eca_main，不設花費上限）。下面每條指令 11-13 都實跑過，沒跑過的會標「沒實跑」。所有指令都在 WSL 終端機裡打。

今天第一次要先做的

1. 信任工作區 要你親手 ：這台的 claude 已經信任過 ~/aos-home/ws（11-13 查過是「已信任」），通常不用做。若開畫面時看到 TrustMissing，在那裡開一次 claude、選信任、打 /exit：

cd ~/aos-home/ws && claude

2. Windows 那份 repo 不用了：公司現在的 repo 是 WSL 的 ~/repo/aos（指令、程式都指它）。

3. 主 session 的 aos MCP：公司 WSL 沒有登記檔（~/.cache/aos-mcp-* 不存在），不用重連。

① 進來、設環境

每開一個視窗先打這行。

cd ~/aos-home && source env.sh

② 起樹

視窗一，前景跑著；Ctrl-C＝整棵停。

cd ~/aos-home && source env.sh && aos-exec root
想放背景跑（11-13 實測用的是這個） 
cd ~/aos-home && source env.sh && (setsid nohup aos-exec root > /tmp/aos-home-root.log 2>&1 < /dev/null &)

③ 確認掛上

cd ~/aos-home && source env.sh && cd ws && aos-agent ctl ls

看到 eca_main running /home/guanyu/aos-home/ws 就對。它已經掛好了，不用再 add；停樹再起，它自己醒、對話還在。

看它有幾支 aos 工具（應該 26 支） 
cd ~/aos-home && source env.sh && cd ws && aos-agent tools --target eca_main ls | wc -l

26 支：json 工具（get／set／ls／search／add／del／len、multi_get／multi_set）、index_view、信箱三支、改自己的 self_*、時間、math 等；讀寫檔、跑指令用 Claude Code 自己的 Read／Write／Edit／Glob／Grep／Bash。它叫子 agent（Agent 工具）時，子 agent 那邊只有唯讀 9 支。開頭會印一行 warning「using the definition's tools.json」，正常。

④ 跟 eca_main 講話

一行一句、等它回；Ctrl-C 離開，樹照跑。

cd ~/aos-home && source env.sh && cd ws && aos-agent chat -t eca_main

先試這句（會花一點 claude 額度）：Use the aos tool index_view on ../knowledge/aos and tell me in one line how many entries it shows.——11-13 它答 20 項、也讀得出 _description.json 的第一句。

看 Claude Code 的互動畫面 沒實跑 
cd ~/aos-home && source env.sh && cd ws && aos-agent open -t eca_main

要真的終端機（11-13 從程式叫沒有畫面可開，所以沒驗）。看到 TrustMissing 就做「今天第一次」第 1 條。

一句話不進 chat 
cd ~/aos-home && source env.sh && cd ws && aos-agent say --target eca_main 'hello' && aos-agent listen --target eca_main --timeout-s 300

⑤ 停樹

aos-daemon-ctl -d ~/aos-home/.stack shutdown

看到 … stopped …; 3 procs asleep, they wake when it starts again。

⑥ 存檔、讀檔

都要先停樹。存檔＝整份抄一份：

mkdir -p ~/aos-saves && cp -a ~/aos-home ~/aos-saves/aos-home-$(date +%m%d-%H%M)

讀檔＝換回來（<存檔名> 換成 ls ~/aos-saves 看到的那個；現在的 aos-home 會被蓋掉）：

rm -rf ~/aos-home && cp -a ~/aos-saves/<存檔名> ~/aos-home

11-13 已有一份 ~/aos-saves/aos-home-1113-0825（剛搭好、問過一句的樣子），讀回來起樹，eca_main 照樣在、對話也在。

⑦ repo 更新之後

拉新的：

cd ~/repo/aos && git -c 'url.git@github.com:.insteadOf=https://github.com/' pull --ff-only

C++ 有改（或不確定）就重 build，再重跑 install：

cd ~/repo/aos/proto8/impls && cmake -B build && cmake --build build -j4
~/repo/aos/proto8/install.sh

指令本來就指回 repo，改了就生效；抄進 aos-home 的 lib、knowledge 不會跟，要重抄（可以不停樹）：

cd ~/aos-home && rm -rf lib && cp -r ~/repo/aos/proto8/lib . && find lib -name __pycache__ -prune -exec rm -rf {} + && find lib -type d -empty -delete
cd ~/aos-home && rm -rf knowledge && cp -r ~/repo/aos/proto8/knowledge . && find knowledge -name __pycache__ -prune -exec rm -rf {} +
py、templates 也有改的話 沒實跑

同一個寫法把 lib 換成 py 或 templates。eca_main 的定義（agents/eca_main）是當初從範本抄的，不會跟範本變；要跟就先停樹、照手冊原稿第 ⑥⑦ 步重做一份。

⑧ 加第二隻 agent

例：eca_two（opus、不設上限、也找得到 knowledge）。樹起著時，在 ws/ 裡打：

cd ~/aos-home && source env.sh && cd ws && cp -r ~/aos-home/templates/eca-claude ~/aos-home/agents/eca_two && echo '{"model": "opus"}' > ~/aos-home/agents/eca_two/llm.json && aos-json set ~/aos-home/agents/eca_two/cli.json#/print_flags '[]' && cp ~/aos-home/agents/eca_main/system.txt ~/aos-home/agents/eca_two/ && aos-agent ctl add ../agents/eca_two
拿掉它（會刪它的對話） 
cd ~/aos-home && source env.sh && cd ws && aos-agent ctl rm --purge -y eca_two && rm -rf ~/aos-home/agents/eca_two

換模型：echo '{"model": "haiku"}' > ~/aos-home/agents/eca_two/llm.json（在 add 之前改）。要設花費上限：aos-json set ~/aos-home/agents/eca_two/cli.json#/print_flags '["--max-budget-usd", "3"]'（管的是一輪）。

常見卡住的

  • TrustMissing：那個工作區 claude 沒信任過 → 「今天第一次」第 1 條。
  • InstanceExists：同名已經掛著，不用再 add。
  • aos-agent 找不到領班：要在 ~/aos-home/ws 裡打（它看目前資料夾的 ./.stack）。
  • install.sh 說 skip、LinkFailed：~/.local/bin 已有同名連結指別份 repo（11-13 撞過）。看 readlink ~/.local/bin/aos-exec，指的不是 ~/repo/aos 就先刪那些舊連結再跑 install。
  • 樹在跑時別整夾重抄 agent 定義：先停樹；lib、knowledge 可以不停。
  • eca 每句話都花錢；別把 hook（例如 on_clock）掛在 eca 上。
這棵樹裡有什麼
  • root/ 根（時鐘、清潔工、領班三列）、daemon/ 領班、agents/eca_main 定義（opus、print_flags []＝不設上限、system.txt 告訴它 knowledge 在 ../knowledge）、ws/ 工作區。
  • lib py templates knowledge 是 11-13 從 ~/repo/aos（2e8eb6736）抄的；env.sh 只設 AOS_HOME＝這棵樹、清掉 CLAUDE 相關變數。
  • 沒有問腦總機（llm kernel）：eca 自己叫 claude，用不到。
