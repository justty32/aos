## 一、kernel 是什麼、請求怎麼走

1. kernel＝「從寄件人看，請求寄去的那個地方」，它決定跑不跑、何時跑；daemon 什麼都不管，是最簡單的 kernel。收請求的 proc 不必知道自己是 kernel；可以多站：agent → 站1 → 站2 → daemon，站間都是 aos-post 信（`KB/kernel.json#/what`）。
2. 手與門：daemon＝手（真的起關行程、死了重起），kernel＝門（唯一有資格叫手做事的）；同一個行程可兼兩者。`aos-daemon-ctl` 直寄 daemon、不經門，是人用的保底（[手與門](../../12/kernel-as-bridge/06-細聊-手與門.md)）。
3. 兩種請求、兩個變數：起／停／睡／醒走 `AOS_KERNEL`（沒設＝`AOS_DAEMON` 的 ctl 信箱）；問腦走 `AOS_LLM_KERNEL`（`KB/kernel.json#/where_to_send`）。`aos-agent ctl`、`subagent` 有 `AOS_KERNEL` 就寄那裡（`P/cmd/aos-agent/aos_agent/ctl/shared.py:93`、`P/lib/agent/subagent/_entry:179`）。活樹 `env.sh` 沒設 `AOS_KERNEL`。
4. 框架站 `P/lib/aos/kernel`：骨架（收信、hook、放／拒／排隊／留著、轉寄）＋包。掛 proc 那包認 `allowed`（名字白名單）、`max_running`（＋`count_daemon`）、`queue`、`next`、`reply_via_me`、`hooks`。下一站三段：`next` → 環境 `AOS_KERNEL`（指自己就跳過）→ `AOS_DAEMON`。`after_verdict` hook 可替單封信指定下一站（`route_ordered`，預設可）（`P/lib/aos/kernel/README.md`）。
5. 問腦總機 Python 版 `P/lib/aos/kernel_llm`：同一副骨架＋問腦那包；有額度（總、每包、每寄件人 `budget.senders`，次數與 token，窗 hour/day/all，`spent: refuse|wait`）、格數、排序、帳 `ledger.jsonl`；三個 hook 時機 `before_verdict`／`after_verdict`／`before_reply`。**問腦那包沒有 `held` 口，hook 回 `hold` 算 hook 自己失敗——現在不能「把腦請求留著等 agent 表態」**（opus 讀 `P/lib/aos/kernel_llm/README.md` hooks 節、`P/lib/aos/kernel/README.md`「包另外提供 held」段）。
6. 隊 kernel 範本 `P/kernel/llm-team/`：問腦站，用 `llm_forward` 把信轉給下一層 llm kernel；寄件方只要把 `AOS_LLM_KERNEL` 指到隊 stack（`P/kernel/llm-team/README.md`）。

## 二、agent 當 kernel：kernel_gate（已進 main、活樹 `H/lib/agent/kernel_gate` 已有）

1. 加法：`self_tools add <AOS_HOME>/lib/agent/kernel_gate`（不在任何範本，使用者裁「預設不掛」）；`kernel_gate {"op":"on"}` 印出收件信箱 `<stack>/hooks/kernel_gate/requests`，寄件人把 `AOS_KERNEL` 設成它（`KB/kernel.json#/gate`）。
2. 跑法：框架站以 `on_clock` hook 掛在 agent 身上，每個時鐘週期跑一輪；**agent 在回合中或睡著時不跑**。規則先判，拒的不問；放行的先留著，agent 收到 `[aos] kernel_hold: N requests held…`；用 `pass`／`refuse` 表態，機器轉寄，下游回信直接回寄件人。pass 後規則再判一次（同上）。
3. 期限屬於寄件人：`aos-agent ctl` 預設 30 秒（`--timeout-s` 可改）；過期＝`SlotMissing`，寄件人撤信失敗（同上）。
4. **kernel_gate 只管掛 proc 那種請求**（起停睡醒），不管腦請求（opus 讀 `P/lib/agent/kernel_gate/_tooldef.json`：「requests to start or change procs」）。
5. eca-as-kernel 撞過的：門正在自己一輪裡時 `on_clock` 不跑、寄件人到期撤信（使用者裁先不補）；agent 判自己發的請求會死鎖；「門死了誰知道」沒有人（[eca-as-kernel](../eca-as-kernel.md) 第五、七節）。
6. 不用工具的第三種寫法：自己寫 `gate/kernel.json`＋`gate/run`，用 `self_hook` 掛 `on_clock`（`KB/kernel.json#/write_your_own`）。

## 三、子 daemon

1. 沒有專用工具：子 daemon 就是父表上的一列 proc，身體是 daemon（`P/kernel/daemon-kernel/`、`llm-kernel/`、`llm-team/` 都是例子），用 `aos-agent ctl add` 或 `aos-daemon-ctl add` 掛（`P/docs/NORMS/04-基礎設施-loop與daemon/02-N-28.md:41`）。
2. 父只看子活著沒（`ctl.json` mtime、`responded_at`），不讀子的表、不管子的 proc（使用者 11-06「子daemon管好自己，父daemon只看他有沒有活着」）；子不帶鐘列就聽外層的鐘；子裡的 agent `AOS_DAEMON` 是子那台（`KB/world.json`、`P/templates/daemon-root/README.md:41`）。
3. `daemon-kernel/` 範本＝一台 daemon，身體本身就是框架站：檢查請求後轉進自己的 ctl 信箱（`KB/kernel.json#/templates`）。
4. 活樹限制：不能起第二台 daemon（G 施工紀錄代定；T33）。sweeper 不往子 daemon 底下走（`P/py/aos_sweep.py:2`）。

## 四、現行做法：astra 用 `subagent` 指揮 sol（11-13 晚 gpt 隊試驗）

1. astra、sol 不是 aos 定義名，是 LiteLLM proxy 的模型：`astra-high`＝`chatgpt-gpt-6-astra-high`、`sol-high`＝`chatgpt-gpt-6.1-sol-high`；定義叫 `gpt-lead`、`gpt-worker`（`H/defs/`）；問腦站 `H/kernels/llm-gpt/`（Python 版 kernel_llm 當 loop proc 掛在 ws daemon，proc 名 `llm-gpt`，這輪已 rm、夾留著）。astra 價約 sol 3 倍（`wf/workflows/dispatch/aos-teams.md:12`）。
2. 流程：隊長（opus）出圖紙、起 astra → astra 寫工單、`subagent add sol-T01`（同一台 daemon）、`say` 交單、`listen` 收 → 自己驗收、`rm`（不 purge）、寄 DONE → 隊長重驗、commit（G「一張圖」、施工紀錄）。
3. 權限：astra 寫入只限隊夾 `H/teams/t1`、shell 在 bwrap 沙箱；`subagent` 只放行 add/say/listen/ls/state/history ls/stop/rm，不准改 sol 的工具／腦／system／hook；沒有 self、def、events 包（`H/defs/gpt-lead/guard.json`、`hooks.json`）。sol 寫 repo 的 proto8、wf，`.git` 唯讀。守門＝`before_tool` hook `H/defs/shared/guard`，`on_error: stop`。`subagents.json` `{"max_subagents": 1}`。
4. 額度：在 `llm-gpt/kernel.json`：寄件人 `teams/t1` 400 次／天、包 astra-high 500、sol-high 1000；格 astra 1、sol 2；逾時 600 秒；沒有金額（T13）。
5. 實績：假工單 2 分鐘（astra 29 次 37.5 萬 token、sol 6 次 4.4 萬）；真工作 7 分鐘（astra 31 次 52 萬、sol 19 次 23 萬）——**astra 花的是 sol 的 2～8 倍**。使用者：「貴不是他的問題，是我的問題…跟astra說，請他盡量把雜事和簡單工作交給sol…之後慢慢調整成medium或轉而讓sol指揮」（G「試驗後的調整」）。
6. `subagent add` 可帶 `envs`（給子 agent 的環境值）與 `limits`（opus 讀 `P/lib/agent/subagent/_tooldef.json`）——**現成就能把 sol 的 `AOS_LLM_KERNEL`／`AOS_KERNEL` 指到別處**。

## 六、一隻 agent 掛在 kernel 底下：生命週期、問腦、權限、卡住

1. 生命週期 op：`add`、`ls`、`ask`（預設等 600 秒）、`say`＋`listen`、`state`、`stop`／`start`、`sleep`／`wake`、`pause`／`resume`、`rm`（`purge` 才刪 stack）；`max_subagents` 預設 4（`KB/agents/subagent.json`、`KB/agents.json#/agents_ctl`）。子的名冊在母 stack `tools/subagent/`。
2. 狀態：daemon 表一列一 proc（name、phase、ws、queue、reason），phase：running、stopped、sleeping、stopping、stuck；stuck＝沒在時限回應控制請求（預設 10 cycle），daemon 只標記，除非 `restart_on_stuck`（`KB/status.json`）。crash＝stopped＋reason，要人 start。
3. 問腦信：`{"endpoint", "request":{messages,tools}, "priority":{level,deadline}}` 寄進 `$AOS_LLM_KERNEL/requests/`；錯誤 `EndpointFailed`、`DeadlineBad`、`LlmKernelMissing`、`BudgetMissing`；用完不自動換包（`KB/brain.json`）。
4. **寄件人身分已改**：線修 `8706d7398`（11-13 21:47）把腦請求的寄件人改成 `$AOS_STACK`（T31／T38），每隻 sol 各自一個 stack＝各自一份額度與帳；但 **C++ 執行檔只在 repo 外編過、活樹沒換，待停樹換**（commit 訊息原文）。巢狀站 `llm_forward` 轉寄時拿掉 `AOS_STACK`（`e56923a97`）。
5. 權限規則：禁手改定義、禁碰別人 stack、禁繞過拒絕（`BudgetMissing`、`AddRejected` 等是決定，不重試、不改名繞白名單、不另起 daemon）、子用完要 rm（`KB/rules.json`）。kernel 層不驗寄件人，`from` 自報（aos-issues #8）。
6. 卡住：`clock_register` 能叫醒自己（gpt 隊兩份定義單加回它，events 包不給）；樹睡著錯過的牆鐘計時器醒來只補一次（[wake-timer](../wake-timer.md)）；on_clock hook 卡在長 wait／act 時不跑（aos-issues #49）。
