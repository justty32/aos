## 2. self_* 一家（C-90：包 `aos-agent X`、目標改自己；改 stack 裡那份，定義不動）
全表 lib/agent/：self_tools、self_llm、self_system、self_history、self_hook、self_state、self_ctl（另 goal、todo 不叫 self_ 但同類）。說明在 knowledge/aos/me/{self_tools,self_llm,self_system,self_history,self_hook,do_task}.json。
| 工具 | 能改什麼 | 實例 | 生效／限制 |
|---|---|---|---|
| self_tools | 自己的工具覆蓋層 | `{"op":"add","path":"tools/math"}`；ls/get/rm（可 rm 出廠工具）/reset；add 選項 name、replace、envs、env_file | 同一輪下一次想就生效；不改定義；不限路徑（11-10「A，拿掉限制」）；壞路徑顯示 broken |
| self_llm | 自己的腦設定 | `{"op":"set","settings":{"model":"smart-high","temperature":"0.2"}}`；ls/rm/reset | 下次 brain call；model 設壞＝停擺等人修；refuse "system" 鍵 |
| self_system | 自己的 system 文字 | `{"op":"set","text":"..."}`；get/reset | 下次 brain call；整份替換；每次改 prompt cache miss 一次；eca 是附加在 CLI prompt 後 |
| self_history | 改自己的對話 | 看/刪段/換成摘要/任意改行 | 當前步動不了；原文搬 history_removed.jsonl；摘要固定 `[aos] summary: …` |
| self_hook | 自己的 hook 清單 | `{"op":"add","event":"before_tool","path":"hooks/guard","condition":"agents_ctl"}` | 事件：before/after_queue、before/after_tool、brain_failed、tool_added、after_start/stop、on_clock；選項 intercept(預設開)/async(預設等)/on_error(預設跟著停)/condition；連鎖不檢測；eca 縮水版 |
| self_state | 唯讀看自己 | `{"parts":["history","mailbox"]}` | 十類：who state tools llm system hooks history mailbox subagents resources time；只給數字、不給建議 |
| self_ctl | stop/pause/sleep/rm 自己 | `{"op":"rm","purge":true}` | 寄出就回；resume 不能自己來 |
| goal | 自己的一句目標 | `{"op":"set","text":"…","limit":10}` / done / pause / resume | 沒叫工具自停時 aos 丟 `[aos] goal: …`；連 10 次無進展暫停；eca 範本不掛 |
- 注意：**「工具清單」「system」「llm」「hook」「歷史」可自改；沒有「自改記憶 index」專用 self_ 工具**（記憶走 memory_write／knowledge 工具）。
- 需 daemon（AOS_DAEMON，靠 aos-agent ctl who 認自己）；aos-exec 直跑的 body 不支援。

## 3. agent 怎麼給自己加新工具（有現成流程）
1. `tools_def {"op":"new","path":"my_tools/mul","description":"…"}`：複製 templates/tool-python（_entry.json＋tool.py＋README）；path 也可 `FILE.json#/POINTER`（腳本放 JSON 旁）。tool.py 只改 DESCRIPTION、PARAMS、META、run：
   ```
   DESCRIPTION = 'Add two numbers and return the sum. Example: {"a": 2, "b": 3} -> 5'
   PARAMS = [ts.param("a","number","the first number"), ts.param("b","number","the second number")]
   META = {"side_effect": False}
   def run(args): return args["a"] + args["b"]
   ts.main(run, DESCRIPTION, PARAMS, META)
   ```
   輔助 lib：lib/tool_spec.py（自動產 _tooldef.json／_metainfo.json）。
2. 用 `edit` 改（不要整檔 write；eca 範本沒有 change 包時改不了檔）。
3. `tools_def {"op":"check","path":"my_tools/mul","sample":{"a":6,"b":7}}`：重產兩份定義、驗 metainfo/tooldef、**照跑 description 裡的 `Example: … -> 結果` 並比對**、試叫一次、末行說 stage；有 bad 退 1 `ToolBad`。
4. `self_tools {"op":"add","path":"my_tools/mul"}` → 同一輪下一次想就能直接以名叫 `mul {"a":6,"b":7}`（42）。
- 分階段 op：add_entry / add_metainfo / add_tooldef（資料夾或 JSON 物件皆可）。
- 寫在哪：path 任意（相對 $AOS_WS 或絕對，權限交 Linux）；誰能用：只有加的那隻（self_tools＝stack 覆蓋層）；要共用就 `agent_def tools add` 寫進定義（其他 agent 下次 brain call 看到）。**不用重啟**。
- 安全：self_tools、bash、run_python 等 `_metainfo` 標 `"arbitrary_exec": true`（thinking/2026-11/07/tool-evolve）；user_zone_guard 是可掛的 before_tool hook（範本預設不掛）。
- 子 agent 亦可：`subagent {"op":"tools","name":"kid","args":{"op":"add","path":"tools/math"}}`。
