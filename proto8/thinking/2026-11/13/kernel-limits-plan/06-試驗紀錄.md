## 試驗（指令→結果→意思）

| # | 做了什麼 | 結果 | 意思 |
|---|---|---|---|
| X1 | `unshare -U --map-auto -r cat /proc/self/uid_map` | `0 1000 1`／`1 100000 65536` | 無特權就能開 user ns，ns 裡 uid 1～65536 對到真的 subuid 100000～165535（`newuidmap` 帶 file cap） |
| X2 | ns 裡 `setpriv --reuid=5` 後 `touch` scratchpad 下 777 的夾 | Permission denied | 祖先夾（`/tmp/claude-1000` 是 700）走不進去：**共用夾的每一層祖先都要給「別人」x**，不然換了 uid 的 proc 什麼都碰不到 |
| X3 | 同上，但先在 mount ns 把夾 bind 到 `/mnt` | touch 成功；外面看擁有者 `100004:100004 644` | 換 uid 是真的：檔案落地就是 subuid 的 |
| X4 | ns 裡 uid 5 讀 lorkhan 的 600 檔 | Permission denied | 不同 uid 真擋得住使用者私檔（對應 issues #7、#10） |
| X5 | lorkhan 在外面對 uid 5 寫的 644 檔 `>>` | permission denied；`rm` 成功（夾是 lorkhan 的） | **使用者改不動 agent 寫的檔**（要進 ns 或靠群組權限），只刪得掉 |
| X6 | ns 裡 uid 5 `kill -0` lorkhan 的 shell | Operation not permitted | agent 殺不到使用者的行程；ns 的 root（＝1000）照殺得到 |
| X7 | `prlimit --cpu=1 sh -c 'while :;do :;done'`（soft＝hard） | 退 137（SIGKILL） | **daemon 現在 soft＝hard，`cpu_s` 到頂表上看到的是 signal 9，跟被 kill 分不出來** |
| X8 | `prlimit --cpu=1:2` 同上 | 退 152（SIGXCPU） | hard 比 soft 多一秒就會先收到 SIGXCPU，表上認得出是 CPU 到頂 |
| X9 | `prlimit --fsize=1024` 寫 4096 位元組 | 退 153（SIGXFSZ） | `file_mb` 到頂認得出 |
| X10 | `prlimit --as=60000000 python3` 配 200MB | `MemoryError`、退 1 | 記憶體到頂只是普通退 1，表上分不出（要靠 stderr 尾巴或 cgroup 的 OOM 計數） |
| X11 | `prlimit --nproc=10`（lorkhan 本來有約 120 個行程） | fork 失敗、退 254 | **同一個 uid 下 `procs` 幾乎不能用**：它數的是整個帳號的行程，不是這一支的 |
| X12 | ns 裡 uid 5 `prlimit --nproc=5` 起 3 個 sleep | 成功 | 換了 uid 之後 `procs` 才是「這隻 agent 自己的」 |
| X13 | `unshare -U -m --map-users=1000,0,1 --map-users=100004,5,1 --map-groups=100004,0,1 --map-groups=1001,5,1`，uid 5、umask 002 寫進 775 的夾 | 檔是 `100004:1001 664`；lorkhan 在外面 `>>` 成功 | ns 裡的 gid 可以對到使用者自己的主群組：擁有者分開、群組共用，使用者改得動 agent 寫的檔（K6） |

沒試的：在委派的 cgroup 下自建子夾（會動 cgroup 樹，留給施工段）；`systemd-run --user --scope`（同上）；Claude Code 在別的 uid 下跑（要搬憑證，留給施工段）；公司 WSL 全部沒查。
