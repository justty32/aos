## 待裁

| # | 題 | 選項 | 推薦（理由一句） |
|---|---|---|---|
| K1 | 請求自帶的 limits 比 kernel 的上限寬 | A 夾到上限並在信上記號／B 拒信 | **A**：agent 不用猜上限，記號讓人看得出被夾 |
| K2 | 列寫 `limits: {}` 的意思 | A 改成「用預設」，要不限只能寫在 daemon.json／B 維持「不限」 | **A**：現在一封信寫 `{}` 就解除全部限制（備料 A、試驗 L1） |
| K3 | 翻 11-05「不做 cgroup」 | A 二期做，只做 memory＋pids，有委派才開／B 照舊不做 | **A**：rlimit 管不到一串子孫的總量，`mem_mb` 對 Claude Code 這類 node 程式又不能用；家機已委派 |
| K4 | 不同 agent 不同 uid 走哪條 | A 無特權 user ns＋subuid（家機可用）／B 真帳號＋root helper／C 只在 bwrap 裡換假 uid／D 這輪不做 uid | **A**：免 root、而且是真的 uid（試驗 X3～X6）；C 什麼都沒擋 |
| K5 | subuid 算不算「一個帳號一整棵樹」裡面 | A 算（subuid 是這個帳號名下的）／B 不算，等於分帳號 | **A**：段是 `/etc/subuid` 發給 lorkhan 的，樹主不用另一個人 |
| K6 | 換了 uid 的 agent 寫出來的檔歸哪個群組 | A 使用者的主群組（使用者改得動；agent 也能寫使用者群組可寫的檔）／B 各自的 subgid（使用者要進 ns 才改得動） | **A**：使用者天天要改 agent 寫的碼（試驗 X13） |
| K7 | eca 身（Claude Code／Codex CLI）換不換 uid | A 先留 1000，只套 rlimit（不含 `mem_mb`）＋二期 cgroup／B 也換，憑證與 `CLAUDE_CONFIG_DIR` 搬給它 | **A**：CLI 要讀寫使用者的憑證，換了 uid 也藏不住它自己的；先做 agent-fsm 身 |
| K8 | 要 root 的包（真帳號、只准換成指定帳號的 helper、sudoers） | A 先不做，`setup.sh` 照舊乾跑／B 現在做 | **A**：沿 11-12「root小daemon先不做」；K4 選 A 就用不到 |
| K9 | uid 分開後，kernel 用信檔擁有者認寄件人 | A 認（擋得住冒名）／B 照舊只信信封 `sender` | **A**：#8 寄件人自報、專區 L3 都靠它；但跟 C-47「aos 不驗寄件人」相衝（衝突 C6） |
| K10 | 段 3 要收緊活樹權限（`~/aos-home` 755、`~/.aos`） | A 段 3 施工時一起收（使用者放行）／B 不收 | **A**：不收的話換了 uid 照樣讀得到別隻的東西，白換 |
| K11 | 沒換 uid 時寫 `procs` | A 警告一行照套／B 直接 `LimitBad`／C 照舊不說 | **A**：試驗 X11 寫了就 fork 不了，至少要說；不擋是照 C-56「寫什麼就做什麼」 |

不在這輪的：aos-sandbox「設定壞了照跑」（T21）fable 建議改拒跑，那題已在 [sandbox-sender-fix](../sandbox-sender-fix.md) 等裁，這裡不重複出題。

## 衝突（哪條、在哪、各自後果）

| # | 舊決定 | 這份的設計 | 後果／讀法 |
|---|---|---|---|
| C1 | 11-05 代定 2「不自動夾成 daemon 的 hard」（[feat-proto 05](../../05/feat-proto/05-資源份額.md)） | kernel 夾（K1） | 不衝：夾在 kernel（政策層），daemon 照舊不夾、超過 `limits_max` 就拒 |
| C2 | 11-05 代定 7「不做 cgroup」 | 二期做 cgroup（K3） | 翻案，要使用者說 |
| C3 | 11-12「一個帳號一整棵樹」「root小daemon先不做」（[linux-user](../../12/linux-user.md)） | subuid 分 agent（K4、K5） | K5 選 A 就不衝；root 的仍不做 |
| C4 | C-64「誰關＝呼叫方，寫在呼叫方 argv 最前面」 | daemon 替 proc 換 uid | 不衝：kernel-as-bridge 已讀成「起 proc 的那層負責套」，daemon 的 `limits.user` 11-05 就有；aos-sandbox 照舊呼叫方包 |
| C5 | C-04「daemon 之上的東西不碰 Linux」 | kernel 站只寫信、不碰 Linux | 不衝：真正 setrlimit／換 uid／cgroup 都在 daemon |
| C6 | C-47「aos 不驗寄件人」「安全的保底是 Linux 本身」 | uid 分開後 kernel 用信檔擁有者認人（K9） | 半衝：靠的正是 Linux 本身，但「不驗」那句要改成「平常不驗、分了 uid 的樹可以驗」 |
| C7 | 11-05 E1「`user` 只認帳號名」、`limits` key 同 aos-sandbox 一套 | 多 `sub:N` 寫法、`limits_max`、`limit_hit` | 擴充，兩邊（daemon、aos-sandbox）一起改，key 仍一套 |
