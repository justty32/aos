# 06 試驗紀錄：規劃中撞到的 aos 問題（一行一條，只記不改）

← [回入口](../wf-into-aos-plan.md)｜上一份：[05-待裁與衝突](05-待裁與衝突.md)

前 16 條是 fable 記的（02 第 10 節），隊長驗過的加註；17 條起是隊長細化時撞到的。施工時續寫在最後。

1. aos hook 沒有 compact 事件；HANDOFF 讀回只能靠 CLI 自己的 SessionStart hook（`proto8/lib/agent/hooks.py:52-65`）。
2. aos hook 沒有「每輪前注入」事件；畫面 hook（`cli_hook.py`）只記帳、不吐文字給模型。
3. eca 的 `before_tool` 看不到 CLI 自己的 Bash／Write，「commit 前跑 `codemap_gen`」沒辦法用 aos 擋。
4. 知識庫 `aos/rules.json` 沒有程式讀進 prompt，全靠 agent 自己去讀。
5. `system.txt` 與 agent 定義在 `~/aos-home`、不進 git，兩台機器會各長各的（家機 `~/aos-home/agents/repo-aos/`、公司 `ws/defs/agent`，連位置都不同）。
6. aos 信箱不跨機器，跟 `wf/inbox` 不互通（`MailboxBad`）。
7. 寄信給使用者還沒有（照 user-zone-plan）；`~/.aos/user/` 單機，WAIT_USER 現在靠 git 跨兩台——這題要 user-zone-plan 答。
8. goal／todo 不給 eca、也不進 git，「跨 session 沒做完的事」在 aos 裡沒有對應，只能留 repo 的 SESSION-LOG。
9. aos 沒有領地／租約機制，CLAIMS 只能留 repo 檔。
10. `index_view` 只讀不生成；aos 沒有 `index_gen`／`index_check` 的對應，repo 只能留自己的。
11. 信讀後不是刪就是 archive，留痕只有 `keep` 追加 JSONL，不像 `wf/inbox/done/` 可以翻。
12. 沒有廣播、topic、團隊信箱、進度板。
13. 家機的 `~/aos-home/ws/public`、`ws/tools`、`ws/temp` 都還沒建（隊長補查：`~/aos-home/ws/` 只有 `.stack`）。
14. 通用版 `knowledge/wf` 缺 HANDOFF、CLAIMS、inbox、data-files、team-model 的對應；也沒有「引用另一個節點、只寫差異」的寫法（隊長驗：沒有，用額外鍵 `base` 當約定，03 第二節）。
15. （隊長驗）`_index.json` 一格的 `index` 只能指另一份 index，不能直接指節點；repo 的 `wf/` 要指知識庫節點只能寫在節點內文。
16. compact 後 repo 的 `.claude/settings.json` hook 在 eca 身裡跑不跑，沒驗過（段 0）。
17. **活樹知識庫抄本落後**：家機 `~/aos-home/knowledge/wf` 比 repo `proto8/knowledge/wf` 少 `skeletons/`、`source/`（第 3、4 塊是在上次抄之後才落檔）；`repo-aos` 的 `system.txt` 指的是抄本那份，讀不到新節點。
18. `$ref` 只能整段換成別處那段，不能「疊在別處那段上再改幾條」——覆蓋式的節點沒有原生寫法。
19. `check_anchors.py` 只查 md 的 `#錨點`；json 的 `#/鍵` 引用沒有任何工具查（index_check 照使用者 11-13 裁定也不查內容引用）。md 轉 json 後斷掉的引用只能靠 `git grep`。
20. index_gen 要手寫的 index 得先登記 `index_gen.json` 的 `hand_indexes`，否則 `--apply` 會把手寫的蓋掉或刪掉。
21. main-session-in-aos 第一題的事實「`.claude/commands/wf-lint.md` CLI 當 skill 用」已過時：11-13 16:32 整支刪了（`70e6d4fd8`），repo 現在 `.claude/` 只有 `settings.json`。
22. git 的最後 commit 時間不能拿來判斷「工作流最後一次被用」：11-13 鋪 index、8 KB 改語氣的整理 commit 碰過每一夾。
23. 盤點時一隻 sonnet 回報 `~/aos-home/ws/` 底下有 `knowledge`、`layers.json`…，隊長實查只有 `.stack`——它多半把 `~/aos-home/knowledge/wf` 看成 ws；子 agent 回報的路徑要抽查。
24. 同時有別的線在 repo 暫存（staged）檔案（`gpt-fsm-team/dryrun/…` 已 `git add`）：commit 一定要 `git commit -- <點名的檔>`，不然會把別線的暫存一起帶走。
