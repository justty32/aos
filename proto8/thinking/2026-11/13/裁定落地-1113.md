### 備註照字面記，讀法不只一種的都列出來（沒有選邊）

**K-F50「可以用unset吧。kernel.json的next感覺有點畫蛇添足。」**（選的是 B：照條文 N-63，總機照舊看 `AOS_KERNEL`）

- 這則備註原本有不只一種讀法（只講總機／連框架站的 `next` 也不要）；頂層當天追問，使用者原話：「Hmmm，好啦，next也可以。只是說，我會覺得AOS_KERNEL他就是在有需要掛一個aos proc的時候，就使用的一個目標，一個通用的，基礎的目標。好比所有C語言程式使用syscall的時候，只要沒有特別指定，不然就是走linux kernel那個記憶體位置。啊如果有需要其他目標...那就自己找方法指定」
- 結論（結案）：框架站設定檔的 `next` 留著；問腦總機照 B，照舊看 `AOS_KERNEL`，問腦的設定不加 `next`。
- 後半段是他對 `AOS_KERNEL` 定位的說法，照字面記：有需要掛一個 aos proc 的時候就用的一個通用的、基礎的目標（像 C 程式用 syscall，沒特別指定就走 linux kernel 那個位置）；需要其他目標的自己找方法指定。
- 備註前半句「可以用unset吧」沒有再談；照字面＝怕繼承到不該用的 `AOS_KERNEL` 時，可以把它 unset 掉。

**C-81「拿掉限制。等以後踩坑再回來處理。」**（選的是 B：不照「讀沒問題，寫限覆蓋層」）

- 讀法一：只改條文。C-81 改回「外人讀寫別人的 stack 沒問題」，把「寫限 `interfaces.json` 宣告的覆蓋層」那半句拿掉。
- 讀法二：連 11-06 選項框選的「宣告過的覆蓋層可寫 (Recommended)」那個裁定也一起翻掉（出題時選項 B 的後果欄寫了「改回就推翻 11-06」）。那麼引用那個裁定的其他條文、`interfaces.json` 的可寫宣告在文件裡的地位，都要跟著看。
- 讀法三：也包括程式——現在若有程式照「沒宣告就不讓外人寫」在擋，也拿掉。有沒有這樣的程式這次沒查。
- 「等以後踩坑再回來處理」照字面＝現在不設限制，出事再補。

**N-17「盡量只讓daemon相關的碰pid，這是原則，推薦遵守。不遵守也沒差。」**（選的是 U：先不選）

- 照字面是一句原則：碰 pid 的事盡量只留給跟 daemon 有關的東西；是推薦、不是硬規定。
- 題目的兩個做法（A 條文列第三個例外「判活」／B 改那兩處程式不讀 /proc）他都沒選，所以這題維持未裁。
- 這句話放在題目上有兩種看法：(一) 那兩處（`aos-daemon-ctl ls`、`aos-agent` 的共用碼）都是「daemon 相關的」，照原則本來就可以碰，條文與程式都不必動，只是 N-17 的說法要從「除兩個例外都不碰」改成這句原則；(二) `aos-agent` 不算 daemon 相關，照原則最好改掉，但「不遵守也沒差」所以不急。兩種都沒被選。
- 「daemon 相關」包不包括 `aos-agent`、清道夫、poke，他沒說。

**C-42「推薦都用json，我們做的東西也盡量以json為主。這是推薦，不遵守也沒差」**（選的是 B：以「純 JSON 樹」為準）

- 選項 B 的字面是「註明現在只做 JSON」；備註的字面是「推薦」「不遵守也沒差」。兩者合起來有兩種寫法：(一) 條文照 B 寫「記憶庫是純 JSON 樹」，備註只是補充態度；(二) 條文的語氣要從「是純 JSON 樹」放成「推薦 JSON、別的格式不禁止」——這就比較接近選項 A 的後果（工具與文件要交代非 JSON 的檔怎麼處理）。
- 「我們做的東西也盡量以json為主」範圍比記憶庫大（aos 自己出的東西），跟 11-12「.json比markdown好」同一個方向；要不要寫成一條通則，他沒說。

**mv-q2「這只是用來參考的概念。」**（選的是 C：兩句都留）

- 照字面：通用／主觀這組分法只是參考用的概念，不必定出一條精確的分界；「放在別處但別人讀得到的看法算哪邊」不用答。
- 「這」指的是通用與主觀的分法，還是整套「客觀／通用觀點／主觀」，他沒說；兩種讀法對條文的結果一樣（都不動）。

**sub-U1「以後再想辦法處理，不急。」**：選丙是現在不管，不是認定丙就是對的；之後還會回來。P-43 要不要現在補一句、還是等以後一起改，他沒說。

**a2a 第 2 題「馬上送，eca他會自己處理。」**（題目的選項：甲 等這一輪講完再送／乙 通知類立刻送、`say` 等講完／丙 全部立刻送）

- 頂層的讀法：丙，全部馬上送。
- 另一種讀法：乙。這句話接在「a2a這個按照建議」後面講的是通知；`say` 馬上送的話，原文件寫了後果「`aos-agent listen`／`subagent ask` 拿到的可能不是針對那句話的回答」，這一點他沒有提到。
- 兩種讀法在「新信通知、時鐘信這類通知馬上送」相同；差在 `say` 要不要也馬上送。

**ms-2「可以。」**：題目是「家機的主 session 要不要也改成樹裡的一隻」，「可以」對到甲（也改）是頂層的讀法；沒有別的原話可對。
