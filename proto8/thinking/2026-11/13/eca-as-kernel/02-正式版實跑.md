## 主流程

對 `kay` 說的話（`aos-agent say -t kay`）：

```text
請做兩件事：(1) 用 self_tools 把工具加上：{"op": "add", "path": "~/code/you-1113/proto8/lib/agent/kernel_gate"}；(2) 叫 kernel_gate，參數 {"op": "on"}，把它印的收件信箱路徑告訴我。之後收到 [aos] kernel_hold 通知時由你自己判：寄件人有寫明要做什麼、而且寫的跟實際要掛的東西對得上就 pass；什麼都沒寫、或對不上就 refuse，原因寫給寄件人看。
```

它的回答：

```text
兩件事都完成了：

1. **工具已加上**：`kernel_gate` 已加入工具箱，路徑是 `~/code/you-1113/proto8/lib/agent/kernel_gate`。
2. **kernel_gate 已開啟**（`{"op": "on"}`）。收件信箱路徑是：

   `~/code/you-1113/tree/stacks/root/procs/kay/hooks/kernel_gate/requests`

   寄件人要把 `AOS_KERNEL` 設成這個路徑。這個站每個時鐘週期在我不處於對話回合時運行一次，會把它允許通過的請求攔下並通知我（`[aos] kernel_hold: ...`）。通過的請求會轉給 `~/code/you-1113/tree/stacks/root/` 的 ctl 信箱。設定檔在 `~/code/you-1113/tree/stacks/root/procs/kay/hooks/kernel_gate/kernel.json`，規則寫在 `aos/kernel.json#/gate`。

- **pass**：寄件人明確寫了要做什麼，而且寫的內容與實際要掛載的東西一致。
- **refuse**：沒寫要做什麼，或寫的內容與實際要掛的東西對不上。我會附上一行原因給寄件人看。
```

## 經 `aos-agent ctl add` 走同一道門

寄件那一側只多設 `AOS_KERNEL=<kay 的收件信箱>`，`--timeout-s 150`（預設只等 30 秒）。`ctl add` 沒有入口可以多帶鍵（使用者 11-13「3乙」：不加），照 `kay` 被交代的標準，沒寫用途的被拒：

```text
aos-agent: warning: routing via AOS_KERNEL=~/code/you-1113/tree/stacks/root/procs/kay/hooks/kernel_gate/requests
aos-agent: error: AddRejected the add letter was refused: HoldRefused No purpose given. Say what the agent kid1 should do and why, then send again.
```

## 寄件人只等 4 秒

請求帶 `"queue_wait_ms": 4000` 與一句對得上的 `desc`。通知上寫「還等 3 秒」；haiku 這一輪從收到通知到叫 `pass` 不到 4 秒，站重判時期限還沒到，照樣放行（回信是 daemon 的 `applied: true`，回信時刻距寄出 3.8 秒）：

```text
01794546825218790729.2303182.1767043
{
  "sender": "~/code/you-1113/tree",
  "sent_at": "2026-11-13T05:13:49.050+00:00",
  "sent_at_cycles": 78,
  "in_reply_to": "01794546825218790729.2303182.1767043",
  "body": {
    "applied": true
  }
}
_clock	running _sweeper	running kay	running logwatch	running logwatch2	running 
```

「期限過了才說 pass」這次沒在真模型上撞到；那個情形由測試蓋住（`lib/aos/kernel/tests/test_kernel_hold.py` 的 `test_04`、`lib/agent/kernel_gate/tests/test_kernel_gate.py` 的 `test_05`：站回 `SlotMissing held N ms, nobody decided in time`、不轉寄，工具回 `LetterRefused`）。

## 收掉

先寄一封 ping 進去（沒人表態），再對 `kay` 說「請叫 kernel_gate，參數 {"op": "off"}，把它印的結果原樣告訴我。」：

```text
原樣如下：

> kernel_gate is off: the station no longer runs. 1 held request was refused (HoldRefused the station was switched off before anyone decided).
> The mailbox ~/code/you-1113/tree/stacks/root/procs/kay/hooks/kernel_gate/requests and kernel.json stay; letters sent there now wait unanswered until op on.

意思是：關閉時還有 1 個請求還沒被決定，所以它被自動拒絕（HoldRefused）。信箱和 kernel.json 都還在，之後如果有人往這個信箱寄信，信會一直等到重新開啟（`op: on`）才會有人處理。
```

之後 `aos-agent hook -t kay ls` 裡已沒有 `kernel_gate`；那封 ping 的寄件人收到 `HoldRefused the station was switched off before anyone decided`。
