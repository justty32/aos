## 邊緣狀況的實跑

**門睡著，寄件人只等 5 秒**（`aos-agent ctl sleep kay` 之後）：

```text
aos-agent: error: DaemonFailed no result from the daemon at ~/code/shen-try-1113/tree/stacks/root within 5 s; letter withdrawn, it will not be applied; letter was sent first to AOS_KERNEL=~/code/shen-try-1113/tree/stacks/root/procs/kay/gate/requests; no reply from there; inspect adjacent ~/code/shen-try-1113/tree/stacks/root/procs/kay/gate/queue.json
exit=1
```

信箱的 `new/` 裡 0 封（已撤回）。接著手寄一封不帶期限的 `kid8`，信留在 `new/`；`aos-agent ctl wake kay` 之後它收到通知、放行，回信 `{"applied": true}`，表上多一列 `kid8 running`。

**門判自己發的請求**（叫 `kay` 用 Bash 跑 `AOS_KERNEL=<自己的信箱> aos-agent ctl add --timeout-s 8 -n kid9 …`），它回報的指令輸出：

```text
aos-agent: warning: routing via AOS_KERNEL=~/code/shen-try-1113/tree/stacks/root/procs/kay/gate/requests
aos-agent: error: DaemonFailed no result from the daemon at ~/code/shen-try-1113/tree/stacks/root within 8 s; letter withdrawn, it will not be applied; …
```

`kid9` 沒有掛上，它也沒有收到這封的通知（信在它那一輪結束前就撤走了）。

**超過寄件人期限才表態**（信帶 `queue_wait_ms: 1000`，2 秒後手叫 `pass`）：

```text
gate: error: LetterLate request 01794544031572875162.2017417.1497950 waited longer than its sender allowed; it was refused with GateTimeout and nothing was passed on
```

寄件人收到 `{"applied": false, "error": {"code": "GateTimeout", "msg": "the gate agent did not decide within 1 s"}}`。

**轉送失敗**（`gate.json` 的 `next` 指到不存在的信箱，手叫 `pass`）：

```text
gate: error: ForwardFailed cannot send 01794544014702664551.2016294.1496389 to ~/code/shen-try-1113/no-such-box (next in gate.json): aos-post: error: MailboxMissing mailbox not found: ~/code/shen-try-1113/no-such-box. The request is still at your gate: pass again later, or refuse it.
```

信還在（`ls` 看得到），之後改叫 `refuse` 成功。對不存在的信名叫 `pass`＝`LetterMissing`。

**一次五封**（名字規則；兩封 `kid` 開頭、三封不是）：一則通知列五封，一輪判完，回信是兩封 `{"applied": true}`、三封 `GateRefused`。

## 對照：身上掛框架站（機器判，零新程式）

三步（用的是人的指令 `aos-agent hook`，等同 agent 自己叫 `self_hook`）：

```sh
# 1. 工作區寫兩個檔
mkdir gate
echo '{"allowed": ["kid"]}' > gate/kernel.json
printf '%s\n' '#!/bin/sh' 'exec aos-exec --stack "$AOS_STACK" "$AOS_HOME/lib/aos/kernel" "$(dirname "$0")/kernel.json"' > gate/run; chmod +x gate/run
# 2. 掛成 on_clock hook
aos-agent hook -t kay add --event on_clock --every-cycles 1 --on-error continue -n gate gate/run
# 3. 信箱在 <kay 的 stack>/hooks/gate/requests；寄件人把 AOS_KERNEL 設成它
```

```text
aos-agent: warning: routing via AOS_KERNEL=~/code/shen-try-1113/tree/stacks/root/procs/kay/hooks/gate/requests
~/code/shen-try-1113/tree/stacks/root/procs/kid
exit=0
aos-agent: error: AddRejected the add letter was refused: NameUnknown evil not in allowed
exit=1
```

## `desc` 經過各種站（實測）

直接寄給 daemon，body 頂層帶 `desc`、或 `procs_added` 那一列裡帶 `desc`：兩封都回 `{"applied": true}`、兩個 proc 都 `running`；daemon 的表裡搜不到 `desc`。

框架站自己選（`station_desc.sh`；A 沒有 hook、B 掛一支剝掉 `desc` 的 `before_verdict` hook、C 掛一支看到 `desc` 就退 10 的）：

```text
A no hook -> next station got: {"procs_added": {"k": {"exec": "/bin/true"}}, "desc": "please let me run this"}   sender got:
B strip   -> next station got: {"procs_added": {"k": {"exec": "/bin/true"}}}   sender got:
kernel: warning: letter 01794544227609748712.2053344.1516842 refused: HookRejected this station takes no desc
C refuse  -> next station got:    sender got: {"applied": false, "error": {"code": "HookRejected", "msg": "this station takes no desc"}}
```
