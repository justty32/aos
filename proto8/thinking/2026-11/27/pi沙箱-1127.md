# pi 沙箱：目標三句與這一串（11-27 早，家機）

← [2026-11-27](README.md)｜前情：[daemon職責-1126](../26/daemon職責-1126.md)、[kernel-1126](../26/kernel-1126.md)、[aospl循址與元介面-1126](../26/aospl循址與元介面-1126.md)

使用者原話逐字在 [9p-proc-1125](../25/9p-proc-1125.md) 第 145～154 段（接著前兩天的編號抄）。這份只留整理後的原意、定了的、還沒定的。

## 目標（第 151～153 段，照原意整理）

1. **做什麼**：一個讓 LLM agent 能安全行動的沙箱。有一個基底（稍微吃資源，就是現在的 daemon；第 150 段「搞不好以後 daemon 會改名叫 vm...先不管」），基底之上可以層層疊疊 kernel，照選配，最輕的就是純粹的檔案遮蔽器。agent 以 pi coding agent 為目標，假設它有 read／write／edit／shell 四種基礎工具。
2. **照什麼做**：Plan 9、aoslua 的概念——在沙箱裡一切都經 Unix 路徑；只從 Plan 9 拿概念，用 Linux 現有輪子，不拿 Plan 9 OS 當依賴（第 147 段）。
3. **核心功能**：選配與介面。功能可裝可不裝，裝了就用介面宣告讓需要的一方看得到；沒時間或懶得管的就漏給底下的 Linux 管（第 148、149 段）。
4. 使用者自述：Linux 系統設計是新手，知道有權限、namespace、pid、cpu、mem、net 可以管，細節大多只聽過（第 151 段）。往後問他的題用「pi 在裡面會怎樣」講。

## 這一串的經過（第 145～150 段）

- **只剩 kernel**（第 145 段）：daemon 更像傳統的容器／沙箱／OS kernel，aos kernel 是攔檔案、轉接到自己指定的檔；往下加 cpu／mem 份額就會越來越像 daemon，不如通通是 kernel、核心功能也可選配；daemon 最核心的是提供 Plan 9／aoslua 的 Unix 路徑統一存取。
- **硬逼出 Plan 9 虛擬機**（第 146 段）：daemon 擋下系統呼叫與網路，逼得底下的 proc 只能用路徑拿東西，kernel 遮得住檔案就管得住一切。
- **只取概念、用 Linux 的輪子**（第 147 段）：要管的主要是權限、cpu、mem、net、IPC，namespace 一定要。
- **介面讓功能可選**（第 148 段）：例 `__meta/__interfaces/aos/perm` 存取得到＝有權限模組；aoslua 路徑一定有、是核心。
- **可用與獨占**（第 149 段）：「管一切」分可用（路徑能用）與獨占（其他路都封了），這也是可選的一項；用可選的方式規劃工作會大減。
- **執行**（第 150 段）：proc 能做的剩讀寫與執行；執行分「納入自己的 stack」與「變成平級的 proc」；管理檔案要不要包括攔 exec 這類系統呼叫——傾向不用，沒裝就漏給 Linux。

## 定了的

1. **原型照甲：pi 整隻放進沙箱，連它的腦也只能經天空裡的一個路徑 `/llm`**（第 154 段「好，照甲做，派去吧」）。`/llm` 由一隻 llm proxy kernel 提供、用介面宣告；不給網路。原型在 `proto9/experiments/pi-sandbox-1127/`（opus 在做）。
2. **`__call` 的定位之後另外規劃**（第 151 段：「我相信等我們討論完，他的定位也就清晰了」）。
3. **元表的夾從 `__meta` 改成 `.aos`，照 Linux「點開頭＝隱藏」的慣例**（第 156、157 段：「我覺得lua只是一個參考概念，或許我們應該遵從linux慣例？」「那就用.aos好了」）。不用 `.meta` 是怕撞名（`.` 開頭那一區很擠）。**夾保留給 aos 之後，裡面的名字不再加 `__`**（「這個簡化也很舒服」）：例 `.aos/index`、`.aos/call`、`.aos/interfaces/aos/llm`。改的是 [aospl循址與元介面-1126](../26/aospl循址與元介面-1126.md) 的寫法（第 5 條「`__` 開頭保留給 aos」改讀成「`.aos` 保留給 aos」），那份原文不改。
4. **一隻 proc 的家目錄＝它自己的 proc 夾**（第 156 段提、第 157 段「12345看起來都不錯」）：天空裡 `$HOME` 設成 `/procs/<自己>`，不另做 `/home/xxx` 連結（要的話天空裡那份很小的 `/etc/passwd` 寫一行）；agent 把自己當成使用者沒關係，它在沙箱裡本來就是一個帳號，亂放也只放在自己家；daemon 寫的事實不能跟程式寫的雜物混在同一個可寫的地方；家目錄實體放外面再掛進來，`forget` 時清不清之後再談（同「persists 誰清」）；`/procs/<別人>/` 預設看不到。
5. **普通程式什麼都不用知道；事實不放進 proc 看得到的家目錄**（第 157 段問「如果這個proc就只是一個普通的程序呢？」，第 158 段「可以，就這樣切」）：
   - 普通程式只看到一片天空和一個 `$HOME`，家目錄裡沒有 `.aos`＝沒宣告任何東西，合法；懂 aos 的程式想宣告自己提供什麼才寫 `$HOME/.aos`。
   - daemon 寫的事實（狀態、天空表、封了哪些路）是給管它的那一方（外面的使用者、init）看的，留在 daemon 目錄的 `procs/<名字>/`；同一隻 proc 兩個視角：外面看＝事實＋家目錄，裡面看＝只有家目錄。
   - proc 要不要讀得到自己的事實做成選配，預設不給；proc 碰不到事實，也就不會拿它說謊。
