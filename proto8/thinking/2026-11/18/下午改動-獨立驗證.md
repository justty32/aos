### 步驟單照抄會卡、或對不上的地方

## 件 2：真 eca 實測

樹是 `cp -r start-eca` 抄到 `$S/eca-tree`；`AOS_HOME` 指件 1 那份 clone；HOME 用真的（claude 的登入在那）。tmux 畫面每隻 agent 有自己的 socket（`/run/user/1000/aos-tty-1000/c2904c74….sock`），只對這一個下 `tmux -S … ls`。`agents/ann/cli.json` 加 `"screen_close_after_s": 20`。**真的叫 claude 只兩句**，加上開畫面 5 次（閒著沒打字）。

| 項目 | 驗了 | 看到什麼 |
|---|---|---|
| 問一句 | ✅ | 「只回一個字 apple」→ 6 秒回 `apple` |
| `ctl stop` 不當場關 | ✅ | 先 `open --detach` 開畫面；stop 後 3、10、18 秒畫面都在，`claude/screen_close.json` 在 |
| 到時間會關 | ✅ | 第 24 秒畫面沒了（socket 不在），`screen_close.json` 也清掉 |
| 期間內又 start 就不關 | ✅ | stop 後第 5 秒 start；15～45 秒畫面一直在；`screen_close.json` start 剛回時還在，稍後就清掉了 |
| `aos-agent close` | ✅ | 印 `closed`，畫面當場沒了 |
| `screen_close_after_s` 設 0 | ✅（加驗） | stop 後 3 秒內畫面就沒了 |
| set-def 跑著的 | ✅ | 開著畫面做；2.5 秒；印 `closed` 與 `…it runs it now`；表上 `def` 換成新的，pid 換新，還是 `running`；history 行數不變；畫面當場關。之後問「之前回了哪個字」→ 回 `apple`，對話接得上 |
| set-def 停著的 | ✅ | 印 `…it stays stopped; ctl start runs it`；還是 `stopped`、def 換了、history 不變、畫面當場關。見發現 1 |
| set-def 睡著的 | ✅ | 印 `…it stays asleep; ctl wake … runs it`；還是 `sleeping`、def 換了、畫面當場關；`ctl wake` 後用新定義跑 |
| daemon 重啟不掉 | ✅ | 根 shutdown 再起，表上 def 還是新的那份 |
| `--restart` | ✅ | 放前、放後都報 `aos-agent: error: FlagUnknown unknown flag --restart …`、退 1 |
| 對自己下 | ✅（模擬） | 在殼裡把 `AOS_STACK` 設成 ann 的 stack 再下：`ArgumentsBad set-def cannot be used by ann on itself …`、退 1。不是 agent 真的自己下 |
| `ctl rm` | ✅ | 開著畫面做：印 `closed` 與 `removed ann; stack … kept`，畫面當場沒了 |

收尾：根 shutdown，`pgrep` 找不到這條線的行程，那個 tmux socket 也不在。

沒驗：走 kernel 排隊時的 set-def、`--envs` 掛的 set-def 被拒、agent 被 SIGKILL 時畫面不排關、`ctl sleep` 本身會不會排關畫面。

## 發現（沒修，攤給你看）

1. **set-def 對停著／睡著的做完，`ctl ls` 那列的工作區欄變成 `-`**（結束碼欄也清掉）。表裡那列的 `ws` 只剩在 `launch` 裡；`start`／`wake` 之後就回來。只是顯示，工作區沒丟。
2. **set-def 對停著的做完，`screen_close.json`（stop 留下的到期單）還在**，畫面其實已被 set-def 關掉；下次 start 才清掉。無害，看檔的人可能會誤會。
3. 步驟單「再起」視窗 B 少 `source env.sh`（件 1 卡點 1）——這條是最可能真的卡住人的。
