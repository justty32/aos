# aos-llm 的歷史：為什麼有它、為什麼是 C++

← [README](README.md)｜上一份：[02-呼叫點清單](02-呼叫點清單.md)｜下一份：[04-方案比較與實測](04-方案比較與實測.md)

## 先講結論

它是 10-24「問腦變成寄信給 kernel」那天生的，當時**整個基礎層都在改 C++**（使用者 10-23「都用C++」），所以寄信端和 kernel 一起寫成 C++。11-13 kernel 那一半為了「骨架只有一份」改回 Python、C++ 版 11-14 刪掉（`726f73952`），**寄信端沒有跟著動**；11-17 改名施工時有人提過「把 `llm` 排進之後改寫成 Python」，使用者選了「不動」。所以它是 C++，**主要是時間順序的結果**，不是因為它需要 C++ 才做得到的事。

## 726f73952 那次的理由，能不能套到 aos-llm

| 那次的理由 | 套到 aos-llm |
|---|---|
| 骨架（收信、排隊、hook 三時機）要只有一份，C++ 留著就兩份 | **部分套得上**：問腦信的格式（priority、body 檢查、回信形狀）現在 C++ 的 `aos/llm.hpp` 一份、Python 的 kernel_llm 一份；寄信端改 Python 就能共用同一份。但寄信端沒有 hook、沒有排隊，「骨架兩份」的痛不在這裡 |
| 對外完全不變，黑箱測試改指新程式就是驗收 | **套得上**：`cpp/aos-llm/tests/` 6 支本來就是 Python 從外面打的 |
| 代價：每輪從 C++ 變成起一次 Python，信多時一輪變慢 | **套得上、要量**：kernel 每 300 ms 一輪本來就起 Python；aos-llm 被 wait 格每拍叫一次，wait 格自己也是 Python（實測見 04） |
| 「已不再使用」 | **套不上**：aos-llm 天天在用，每隻 agent 每次問腦都經過它 |

## 11-17 的裁決要不要算數

11-17 的 X-4 A 是「這次改名施工不順便改寫」，選項 C 寫明「是另一件工，這份沒估」。今天使用者主動問「直接用python寫，其實更好？」，可以看成要那份估價。這份就是那個估價；**要不要推翻 X-4 A 由使用者說**。
