# aos-llm 呼叫點清單：誰真的在叫它、誰只是提到它

← [README](README.md)｜上一份：[01-現況與資料流](01-現況與資料流.md)｜下一份：[03-歷史](03-歷史.md)

## 先講結論

**真的會執行 aos-llm 的程式只有 4 個檔（3 種用法）**：agent-fsm 的 wait 格（範本一份＋start-api 抄好的一份，用 `send`／`recv`）、judge-llm 範本與 llm_forward 工具（各用一次 `ask --full`）。eca 不用它（eca 的身是 claude／codex／pi CLI，不經 llm kernel），aos-agent 的 ask／listen 也不直接叫它（走 queue，再由 fsm 的 wait 格叫）。其餘都是測試、提到錯誤字串的程式、文件。

數量：proto8 裡提到 `aos-llm` 的追蹤檔 **93 個**（`cpp/aos-llm/` 自己 16 個，其餘 77 個），`wf/` 另有 32 個（不含 `aos-llm-kernel` 舊名、不含 thinking／archive）。

## 一、真的會執行它的（程式）

| 類 | 檔 | 用法 |
|---|---|---|
| agent-fsm 範本 | `templates/agent-fsm/wait.py`（412、481 行） | `aos-llm send --reply-to think/reply`（第一拍）、`aos-llm recv --full [--quiet] think/reply 名`（每拍） |
| 起手範本的抄本 | `templates/start-api/agents/ann/wait.py` | 同上（逐字同一份） |
| 範本 | `templates/judge-llm/_entry`（90 行） | `aos-llm ask --full`，失敗報 `BrainFailed aos-llm ask exited N` |
| 工具 | `py/tools/aos/llm_forward/_entry`（68 行） | `aos-llm ask --full`，把一封信轉給下一台 kernel；故意清掉 `AOS_STACK` 讓寄件人算成這台 kernel（30 行註解） |
| 沙箱範例 | `py/aos/apps/sandbox/examples/agent.json` | `commands` 清單列了 `aos-llm`（沙箱裡要看得到這支） |
| 沙箱 root 腳本 | `py/aos/apps/sandbox/root/setup.sh`（68～78 行） | 只是印給人看的檢查指令（`aos-llm ask`） |

**kernel 不叫它**：`py/tools/aos/kernel_llm` 收信、寄回信都用 `aos-post`（`llm_rules.py` 208、234 行），不用 aos-llm。**eca 不叫它**：`py/aos/apps/eca/README.md` 只是一個連結指到「aos-llm 與 eca 入口」那份說明。

## 二、讀它的錯誤字串的（程式）

這幾支不執行 aos-llm，但會把 `aos-llm: error: …`、`aos-llm recv exited 1` 當字串處理或顯示：

| 檔 | 做什麼 |
|---|---|
| `py/aos/apps/agent/hints.py`（136～155 行） | listen 出錯時把 aos-llm 那行原因接到提示裡 |
| `py/aos/apps/agent/ctl/ls.py`（98 行） | `ls -l` 的 LAST ERROR 用下層原話取代「aos-llm recv exited 1」 |
| `py/aos/agentlib/cooldown.py`（15 行） | 註解：冷卻檔的 `error` 欄就是 aos-llm 那行的後半 |

改成 Python 若**保留指令名 `aos-llm` 與 stderr 前綴 `aos-llm:`**，這三支一行都不用動。

## 三、測試

| 檔 | 怎麼用到 |
|---|---|
| `cpp/aos-llm/tests/` 6 支（`test_full`、`test_ls_kernel`、`test_ls_backend`、`test_recv_hint`、`test_send_hint`、`test_sender_stack`） | 黑箱打真 `aos-llm`：改寫時改指新程式就是驗收 |
| `templates/tests/agent-fsm/` 7 支（`test_cells`、`test_cooldown`、`test_hooks`、`test_reply_match`、`test_selfheal`、`test_brain_notify`、`test_hook_retry_later`） | 在 PATH 放一支**假 aos-llm**（Python 小腳本），驗 wait 格怎麼反應 |
| `templates/tests/judge-llm/test_judge.py` | 假 aos-llm shim |
| `py/tools/aos/llm_forward/tests/test_forward.py` | 假 aos-llm shim |
| `py/tools/aos/kernel_llm/tests/test_batch8_live.py`、`test_nesting_live.py` | 打真 aos-llm（端到端） |
| `py/tests/apps/agent/test_listen_brain_failure.py`、`test_ls_health.py` | 只用到錯誤字串 |

注意：agent-fsm 那 7 支是**用假指令頂替**，前提是 wait.py「去 PATH 叫一支叫 aos-llm 的程式」。如果 wait.py 改成 import Python 函式庫（[04 的丁案](04-方案比較與實測.md)），這 7 支的假指令要換成假函式庫或假信箱，是丁案最大的一塊測試改動。
