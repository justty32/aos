# 沙箱隔離實機檢查（不用模型的那一半，公司 WSL，HEAD `71df48e88`）

← [2026-11-18](README.md)｜程式與說明：[aos-sandbox README](../../../py/aos/apps/sandbox/README.md)

使用者 11-18 選「沙箱隔離先驗一半」：不需要模型的部分先做，真開沙箱看得到什麼、寫得到哪、網路通不通；「agent 在沙箱裡跑真模型」明天補。線 `sbx-1118`，只驗不改程式。

**做法**：WSL 暫存夾 `~/.aos/scratch/sbx-1118/` 從 HEAD clone、清 `AOS_*`、`AOS_HOME` 指複本、乾淨 PATH、`install.py`。沙箱靠 **bwrap 0.9.0**（`--unshare-all`＋`--die-with-parent`＋根唯讀）；這台**沒有 s6**（`s6-softlimit` 等）、沒有 `rg`、`jq`，也沒有 root 那半（`aos-run` 帳號、sudoers）。探測腳本只看「在不在、有幾個檔名」，不讀任何檔的內容；環境變數只列名字。假腦樹照[重建步驟單](../17/重建步驟單.md)第 4～6 步起在暫存夾，驗完關掉、行程都確認沒了。

## 落差與嚴重度

**A．嚴重：起手範本的樹，沙箱等於沒關住 daemon。** `templates/start-api` 的根以樹為工作區、`ann` 也用 `-w .`，而根的 stack `.stack/` 與 llm kernel 的 `llms/stacks/llm/` 都在樹裡。實測：一個只綁 `AOS_WS`（＝樹）、斷網的葉沙箱，能 `aos-daemon-ctl ls`、能對 `ann` 說話並收到假腦回答、能往 llm kernel 的 `requests/` 寫檔。README 早有一句「daemon 的 stack 別放在工作區裡」，但照步驟單裝出來的樹剛好就是這個佈局，所以照預設把工具關進沙箱時，隔離在 daemon 這塊是假的。

**B．中：`net:true` 時連得到宿主的 127.0.0.1。** 開網路就是跟主機共用網路，宿主只聽 127.0.0.1 的服務（例 litellm proxy 的 4000 埠、全景頁）沙箱裡都連得到；實測自己起的 127.0.0.1:47118 連上。cli-tool.json 是 `net:true`，所以沙箱裡的 claude／codex 也碰得到 proxy（proxy 有要 key 的話仍會擋）。4000 埠今天沒開，沙箱內外都是逾時（這台是 WSL mirrored 網路，127.0.0.1 會轉到 Windows），連得到與否跟主機一致。

**C．中（功能，不是漏洞）：`net:true` 也查不到 DNS。** 這台 `/etc/resolv.conf` 是指向 `/mnt/wsl/resolv.conf` 的連結，沙箱沒綁 `/mnt/wsl`，所以名字查不到，只能直連 IP。cli-tool.json 照現樣在這台起 claude／codex 會連不上 API。

**D．低：沙箱裡看 daemon 是不是活著會看錯。** 沙箱有自己的行程編號，裡面 `aos-daemon-ctl ls` 印「daemon: not running (pid … is gone)」、`aos-agent listen` 警告「llm kernel … is not running」，其實兩個都活著、信也照收照回。只是訊息誤導。

**E．低：範例在這台多半跑不起來。** shell-boxed、agent.json 寫了上限，沒有 s6 就 `CommandMissing`；shell-boxed 另外列了 `/usr/bin/rg`、`/usr/bin/jq`，這台沒裝會 `PathMissing`。subagent-boxed 的 `ro: ["inner"]` 是從**目前資料夾**算，不是從設定檔的夾算，在別的夾直接叫會 `PathMissing …/inner`（經 aos-exec 從工具夾叫就沒事）。去掉上限的複本照常關住。

**F．提醒（照設計，但後果大）：設定寫壞就整個不關。** 實測 `{"net": "no"}` 只印一行 warning、程式照跑、看得到 `~/.ssh`。這是使用者 11-12 裁的「甲，出事自己負責」，記在這裡是因為明天接真模型時，一個打錯字就等於沒沙箱，要看 stderr 有沒有那行 warning。

另外照設計、沒算落差的：`/etc` 整夾唯讀看得到（`passwd` 讀得到、`shadow` 讀不到）；hostname 跟主機一樣；cli-tool.json 把 `~/.claude`、`~/.claude.json`、`~/.codex` 可寫綁進去（登入檔就在裡面，看得到、改得到）。

## 細節

**1、2、4、5**：設定 `cfg/netoff.json`、`neton.json`（`commands` 列 aos-exec、aos-tools；`rw` 只有 ws 與 stack）。沙箱裡 `id` 是 `uid=1000 … groups=1000,65534(nogroup)`；`/proc` 的 1 號是 bwrap。去掉上限的 agent.json、shell-boxed 複本結果一樣；shell-boxed 連 `id`、`cat` 都沒有，只剩它列的幾支執行檔。

**3**：用 Python 對 `example.com` 做一次名字查詢、對 `1.1.1.1:443` 開一次 TCP、對 127.0.0.1 的 4000 與自己起的 47118 各開一次，不送資料。關網路時連網卡清單都是空的。

**6**：假腦樹在 `~/.aos/scratch/sbx-1118/tree`。subagent-boxed 的 `sandbox.json`（在它自己的夾裡叫）：看不到樹的 `agents/`、llm kernel 的 `requests/`，但對 `ann` 說話收到 `FAKE ANSWER to: hello-from-box`。只綁 ws 的 `netoff.json`：`aos-daemon-ctl` 報 `DaemonMissing`（看不到）。ws 換成樹本身：見 A。

**7**：`AOS_HOME` 指一個空夾＋`commands` 列 aos-exec＝`EnvBad`、退 1；同樣的壞 `AOS_HOME` 但沒列 aos 命令＝照跑、退 0。沒列 aos 命令時家看不到、`aos-exec` 找不到。`AOS_HOME` 沒設時，乾跑看到綁的是命令所在的家。做了一個假的第二個家（`bin/aos-other`＋`lib/aos/__init__.py`）放 PATH 前面：stderr 一行 `warning: aos-other is from the aos home … not AOS_HOME=…; only its folder is bound`，只綁到它的 `bin/`、看不到它的 `lib/`。

**8**：`proto8/py/tools/aos/box_check/tests/test_acceptance.py` 想驗的是：shell-boxed 真的關住（五個探測：私有 `/tmp` 寫得進但主機看不到、連不到 127.0.0.1:4000、列不出家目錄、`/usr/bin` 只剩白名單那幾支、寫不到 stack 上兩層的 `history.jsonl`），沒關的庫 shell 要被判不及格，比對器本身認得缺標記與多出的執行檔。紅的兩支 `test_real_boxed_whitelist_and_writes`、`test_measure_boxed_passes`：原因都是 `CommandMissing s6-softlimit not found on PATH`——測試把 s6 找在 `~/code/try/sandbox/s6-root/bin`（11-15 已刪），shell-boxed 寫了 `mem_mb`、`cpu_s`、`file_mb`；第二支是因為探測根本沒跑起來，所以五個標記全缺。補了 s6 之後下一關是 `PathMissing /usr/bin/rg`（第一支還要 `rg --version` 成功）。另外三支綠。

## 明天接真模型時還要補驗

1. agent.json 那條路：沙箱裡的 agent 只經 `requests/` 信箱問腦，看不到 `kernel.json`、端點與金鑰（今天只用假腦驗了信箱寫得進）。
2. 真 proxy 開著時，`net:false` 的沙箱連不到 4000；`net:true` 的連得到（B），要不要擋請使用者裁。
3. cli-tool.json 在這台要先解 DNS（C）才可能起 claude／codex；起得來後看它寫進 `~/.claude` 等夾的東西。
4. 上限（`mem_mb`、`cpu_s`）與換帳號（`user`、`sub:N`）這台都驗不到：缺 s6、缺 root 那半；要驗得先有人裝。
5. A 的佈局問題：真模型的 agent 若照範本掛在樹裡，關進沙箱的工具仍碰得到 daemon。
