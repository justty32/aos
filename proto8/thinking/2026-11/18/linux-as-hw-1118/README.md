# 「aos 的硬體就是 Linux」調查（11-18）：排程以外，Linux 還給了哪些旋鈕與門鎖，aos 碰了多少

← [2026-11-18](../README.md)

使用者 11-18 晚：「那我們的aos，其硬體就是linux……不只是行程排程，也包括linux的權限/使用者/……我是在想，我們應該還需要考慮如權限/使用者...等的特殊管理。」（全文 [00](00-使用者原話.md)）。線 `linux-as-hw-1118` 做，只調查與發想，沒改程式、沒排實作；讀 repo HEAD `7b29aa17a` 的程式與文件，沒碰活的 daemon 與 `~/aos-home`；家機暫存夾做了兩個不用 daemon 的小實測。

## 先講結論

1. **你的直覺對**：Linux 吃掉了真硬體，但交給一般程式的不只「行程排程」，還有一整排旋鈕和門鎖，大致六塊：**身分**（uid，像員工證）、**看得見什麼**（檔案權限、namespace，像門禁）、**能用多少**（rlimit、cgroup，像電表）、**能做哪些動作**（seccomp、Landlock，像合約）、**怎麼說話**（訊號、socket、檔案，像門鈴與電話）、**看得見發生過什麼**（/proc、journald，像監視器）。對照表在 [01](01-對照表.md)。
2. **「身分」是其他幾塊的鑰匙**：Linux 的門禁、能殺誰、數誰的行程、防火牆、日誌，全都先看 uid。
3. **aos 碰得比想像多**：份額（rlimit＋可選 cgroup）、沙箱布景（bwrap）、換身分工具（`aos-asuser` 的 subuid）、替共用夾開門（`aos-share` 的 ACL）、kernel 站照名字填身分。11-13 的 kernel-limits-plan 已經把「每隻 agent 一個 subuid」整套想完並由你裁了（[02](02-aos現況.md)）。
4. **但最大的空白就在身分**：daemon 那段還不認 `sub:N`，所以**今天每一隻 agent 都跟你同一個 Linux 帳號**；而 aos 自己的身分（信的 `sender`）是自報的——實測一行 `AOS_WS=…/eca_main aos-post send` 就冒名 eca_main（E1）。結果是 aos 內部的每一道門（kernel 拒絕、沙箱、使用者專區驗證）都只擋守規矩的 agent；沙箱碰得到 daemon、專區擋不住會開 shell 的 agent，根是同一個。
5. **別人的作法**（[03](03-別人怎麼做.md)）：蓋在 Linux 上的 Android、systemd、rootless Podman 都是**先一個單位一個 uid**，再一層層加布景、用量、系統呼叫過濾；Plan 9、Fuchsia、微核心走「看不見就碰不到、能寄給誰就是權限」。aos 兩條都沾，缺的是第一條的第一步。
6. **換 uid 會撞的事**（[04](04-邊緣狀況.md)，30 條）：最先撞的是家目錄 700 走不進去（E2 實測），然後是檔案擁有者、git、信箱權限、eca 本體的家與登入資料、tmux、搬家與兩台機器的號碼、公司 WSL 缺套件。
7. **九個樣子**（[05](05-發想.md)）：甲 維持現狀、乙 接完已裁的那一哩（每隻 agent 一個 subuid）、丙 看信夾擁有者驗寄件人、丁 權限＝遞給你的夾、戊 Landlock 自綁、己 整台 aos 一個身分、庚 權限也寄給 kernel 要、辛 root 那半、壬 網路磁碟秘密日誌。**推薦**：現在不開新規劃；要往前就是乙（已裁、免 root，只差 daemon 那段），丙當它的順帶結果記著；庚、壬讓它自然長。**由你拍板。**
8. **要你先說的一題**：你想要的權限管理主要是**防呆**（別手滑弄壞）、**防賊**（prompt 注入、不信任模型）、還是**多人共用**？三種要的東西差很多（05 末節）。**使用者 11-18 晚已答**：都想要，先做防呆，單人使用、模型可信（[06](06-使用者裁定.md)）。
