# 對照表：作業系統替裸機做的事 ↔ Linux 給一般程式的「硬體面」

← [README](README.md)｜上一份：[00-使用者原話](00-使用者原話.md)｜下一份：[02-aos現況](02-aos現況.md)

## 先講結論

- **使用者的直覺是對的**：Linux 把真硬體（中斷、記憶體分頁、磁碟控制器、網卡）全吃掉了，但它**不是**只交給我們一個「行程排程」。它交給一般程式（userspace）的，是另一套「硬體」：一排旋鈕和門鎖。大致分六塊：
  1. **身分**——你是誰（uid／gid、群組、capabilities）。像員工證。
  2. **看得見什麼**——檔案權限、ACL、mount／pid／net namespace。像門禁：哪些房間你的卡刷得開，或乾脆讓你以為那間房不存在。
  3. **能用多少**——rlimit、cgroup。像電表和水表加上總開關。
  4. **能做哪些動作**——seccomp、capabilities、Landlock。像合約上寫「這個人不准碰電閘」。
  5. **怎麼說話、怎麼被叫醒**——訊號、socket、pipe、檔案、inotify、timer。像門鈴、電話、信箱。
  6. **看得見發生過什麼**——/proc、/sys、journald、cgroup 統計、ptrace。像監視器和帳本。
- 其中**第 1 塊「身分」是其他幾塊的鑰匙**：檔案權限、ACL、能殺誰的行程、`RLIMIT_NPROC` 數誰的行程、網路防火牆照誰放行、journald 記誰——Linux 全都是「先看你的 uid 再說」。aos 現在所有 agent 都拿同一張員工證（跟使用者同一個 uid），所以這把鑰匙等於沒用上（見 [02](02-aos現況.md)）。
- 不用 root 能碰到的比想像多：subuid＋user namespace（換身分）、ACL（替別人開門）、bwrap（看得見什麼）、rlimit（每支程式的上限）、Landlock（程式自己綁自己的手）、cgroup（有委派時）。要 root 的主要是：建真帳號、改系統防火牆、磁碟配額、改系統設定。

| **秘密（金鑰）** | 檔案 600、kernel keyring（`keyctl`）、環境變數（同 uid 讀得到 `/proc/<pid>/environ`） | 600＝只有屋主開得了的抽屜；但同一個屋主（同 uid）全都開得了 | 半：沙箱 `env` 白名單擋 API key；`aos-share key` 樣板；LiteLLM proxy 把真金鑰收在 aos 外面 |
| **服務監管** | systemd unit（`Restart=`、`DynamicUser=`、一長串 sandboxing 選項）、s6 | systemd＝大樓物業：誰掛了就重開，還能幫每個服務臨時發一張員工證 | 半：daemon 自己就是一個小 systemd；根 daemon 有 systemd／s6 外管範例（[examples/root](../../../../cpp/aos-daemon/examples/root/README.md)） |

## 「身分」為什麼是鑰匙（用一個比喻講完）

想像一棟辦公大樓。Linux 是物業：門禁、電表、總機、監視器都是它的。物業只認一件事：**你胸前的員工證號碼（uid）**。門禁看號碼決定開不開門；總機看號碼決定轉不轉外線；誰能叫別人下班（kill）看號碼是不是同一人；登記簿每一筆自動蓋上號碼。

aos 現在的狀況是：使用者、eca_main、每一隻 sol、每一個工具，**全部戴同一張證**。所以物業那一整套門禁對「aos 內部誰能碰誰」完全幫不上忙；aos 只好自己在上面再做一層規矩（kernel 拒絕、沙箱布景、使用者專區驗證），而這層規矩**只擋守規矩的人**——會開 shell 的 agent 戴著同一張證，物業眼中它就是使用者本人。

這不是 bug，是 C-64「托底靠 Linux」還沒接上電：托底的那張網在，只是 aos 還沒把不同的人放到網的不同格子裡。
