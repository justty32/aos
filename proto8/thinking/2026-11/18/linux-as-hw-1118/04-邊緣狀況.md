# 邊緣狀況：agent 用不同 Linux 使用者（不同 uid）時會碰到的事

← [README](README.md)｜上一份：[03-別人怎麼做](03-別人怎麼做.md)｜下一份：[05-發想](05-發想.md)

標「實測」的出處：X＝11-13 [kernel-limits-plan 06](../../13/kernel-limits-plan/06-試驗紀錄.md)（家機）、E＝本線 [02 末節](02-aos現況.md)；其他是推的。本線沒建真帳號、沒用 sudo；要實測真帳號那條（R1）得使用者自己 `sudo useradd`。

## 先講結論

- **最先撞到的一定是「路走不到」**：家目錄 700，換了身分的 agent 連 aos 的執行檔都起不來（E2）；aos、樹、工作區只要放在家目錄底下，每一層祖先都要開 `x` 或掛 ACL（X2）。這是第一個要想的，不是最後一個。
- **第二個是「誰擁有檔」**：agent 寫的檔落地就是 subuid 的（X3），使用者改不動、只刪得掉（X5），git 在使用者的 repo 裡直接 fatal（X27），搬到另一台號碼可能對不上。
- **第三個是「信箱」**：今天信箱是一般資料夾、預設權限；換了 uid 後誰寫得進誰的信箱、回信寄不寄得回來，全看權限位與 ACL，寫錯就是信寄不出、或別人讀得到你的信（X23）。
- **大部分都有現成解法**（ACL 樣板、`aos-asuser --fix`、`safe.directory`），kernel-limits-plan 都列過；本份補的是「從 Linux 那邊看」的幾條：sudo、root 才能做的、兩台機器、WSL、eca 本體、清道夫、互相看得見。

## 一、路與家目錄

1. **家目錄 700 進不去**（E2 實測）：`aos-asuser sub:5 -- ~/…/bin/aos-post` 退 127 `Permission denied`。解法三選一：家目錄加 `o+x` 或 `u:sub:N:x` 的 ACL（只給「走過去」、不給「列出來」）；把 aos 與樹放到家目錄外（例 `/srv/aos`，要 root 建一次）；或 agent 在自己的 mount namespace 裡看到 bind 進來的夾（X3，沙箱本來就這樣做）。
2. **每一層祖先都要走得到**（X2）：`~/repo/aos/proto8/lib/…`、`~/aos-home/…`、工作區、`/tmp/claude-1000`（700）都算。少一層就是莫名其妙的 Permission denied。`aos-share` 真做完會逐層檢查並警告。
3. **agent 自己沒有家**：`aos-asuser` 把 `HOME` 設成 `/nonexistent`。claude、codex、git、pip、npm 都想寫 `~/.something`；eca 本體要換 uid 就得替它安排一個家（例 stack 裡的 `home/`），登入資料（`~/.claude`）就得複製或分享過去——**金鑰跟著分出去**。
4. **工具找不到**：PATH 上的指令在使用者家目錄裡（`~/.local/bin`、nvm、pyenv）的，換了 uid 一樣走不到。

## 二、檔案擁有者

5. **使用者改不動 agent 寫的檔**（X5）：只刪得掉（夾是使用者的）。解法：預設 ACL 把使用者加進去（X18），或群組對到使用者的主群組（X13，K6 採的）。
6. **agent 可以把使用者鎖在外面**（X18、L9）：它自己 `chmod 600` 自己的檔，使用者就讀不到，要進 namespace 修（`aos-asuser --fix`，X19）。
7. **git 的 dubious ownership**（X27、L10）：repo 裡有別的 uid 的檔，git 直接拒絕；要 daemon 替它帶 `safe.directory`（`aos-asuser --git-safe` 已有）。
8. **打包、搬家**（C-79 的 image）：`tar` 預設保留數字擁有者。家機 subuid 起點 100000、公司 WSL 也是 100000（教學 10），剛好對得上；但只要某台的段不一樣，搬過去檔案就是別人的。使用者本人的 uid 兩台也不一定一樣（家機 lorkhan＝1000、主群組 1001）。推的解法：打包時不帶擁有者，由新那台的 daemon 照 `users` 表重套（C-83「到新機器由那台的 daemon 重套」）。
9. **刪不掉**：使用者 `rm -rf` 一個 agent 寫的、權限 000 或 sticky 夾裡的東西會失敗；要先 `aos-asuser --fix --recursive`。（本線不刪，只記。）

## 三、信箱與身分

10. **寫不進對方的信箱**：信箱預設是建的人的 uid、umask 022 → 別人寫不進。aos-llm 已經會先檢查「kernel 的 uid 寫不寫得進我的回信箱」（`wait.cpp`），其他寄信處（daemon 回信、kernel 站轉寄、mail_notify）還沒有。
11. **投遞箱沒設預設 ACL＝別人照檔名讀得到你的信**（X23、L8）；要 `aos-share drop`（X24、X33）。
12. **寄件人終於可以驗了**：換 uid 後信夾的擁有者就是寄件人的真身分（X24「信檔擁有者就是寄件人 uid」）。但只有收信方**去看**才有用——今天 kernel 站看的是自報的 `sender`（E1）。
13. **使用者專區**：`~/.aos/user/` 是使用者自己的夾。agent 換了 uid 後要寄信進去得有投遞箱權限；反過來，**agent 再也改不了專區的留底**——鐵律 2 那句「擋不住會開 shell 刻意造假的 agent」就自然擋住了（推的，前提是 eca 本體也換了 uid）。

## 四、sudo、root 與「要 root 才能做的」

14. **sudo**：使用者帳號在 `wheel` 群組（家機實查）。同 uid 的 agent 開 shell 打 `sudo`，若使用者剛輸過密碼、還在 sudo 的快取時間內，**可能不用密碼就成功**（常識，sudo 的 timestamp 預設綁終端，視設定而定）。換了 uid 的 agent 不在 sudoers 裡，這條自然斷。aos-sandbox 的 `sudo -n -k` 已刻意不吃快取。
15. **附屬群組帶不進去**：使用者的 `wheel`、`network`、`docker`（家機有 docker）這類附屬群組對不進 user namespace（X16）。好處：agent 拿不到「docker 群組＝等同 root」；壞處：真要 agent 用 docker 或某設備就做不到。
16. **root 才能做的**（kernel-limits-plan [09](../../13/kernel-limits-plan/09-有root的話.md) R1～R9）：建真帳號（`ps`、`ls` 看得到名字）、照 uid 管網路（nftables `skuid`）、磁碟配額、`chattr +a`、cgroup 委派補齊、加大 subuid 段。全部要使用者親手 `sudo`；subuid 的號碼是真的 uid，所以 R6 網路、R7 配額**也能套在 subuid 上**，只是設規則那一步要 root。
17. **`ps`、`top` 看到的是數字**：subuid 在 `/etc/passwd` 沒名字，`ps` 顯示 `100004`。要認是哪隻 agent，得查 kernel 站的 `users` 表（或 daemon 的表）。

## 五、兩台機器與 WSL

18. **公司 WSL 缺套件**：`uidmap`（aos-asuser）、`acl`（aos-share）、`s6`（沙箱上限）都沒裝（[教學 12](../eca-claude-小試驗教學/12-沙箱asuser-share要裝什麼與WSL限制.md)），要使用者 `sudo apt install uidmap acl`。subuid 段已經有。
19. **公司 WSL 沒有 systemd user**（daemon docs/09「公司 WSL 無 systemd 的環境」）：cgroup 委派、systemd-run 包 CPU 百分比都用不了；cgroup 只能 `off`。
20. **WSL 的檔案系統**：放在 `/mnt/c`（Windows 那邊）的夾，uid／權限位／ACL 是假的或不支援（常識：drvfs 預設把所有檔顯示成同一個擁有者，`metadata` 掛載選項才存權限位）。aos 的樹與工作區若放 `/mnt/c`，換 uid 這整套都不成立。今天的樹在 `~/aos-home`（ext4，支援 ACL，教學 11 實查）。
21. **WSL 的 127.0.0.1 會轉到 Windows**（沙箱檢查 B）：照 uid 擋網路的規則在 Windows 那邊的服務上不一定擋得到。
22. **兩台的 subuid 段一致只是運氣**：都是 `100000:65536`（家機與公司 WSL 實查），將來換新機器不保證。

## 六、aos 自己的零件

23. **daemon 自己是誰**：今天 daemon＝使用者。agent 換了 uid 後，daemon 仍是使用者，所以 daemon 讀寫得到每隻 agent 的 stack（靠 ACL `u:ME`，X25）；反過來 agent 碰不到 daemon 的 stack——**sbx-fix 的九條在不靠沙箱的情況下也擋住**（推的：工作區包住整棵樹時，樹的擁有者是使用者、agent 沒有寫權限）。
24. **清道夫讀 `/proc/<pid>/environ`**：同 uid 才讀得到。agent 換了 uid，使用者身分的清道夫就讀不到 agent 子 loop 的 environ（`/proc/<pid>/environ` 只准擁有者與有 `CAP_SYS_PTRACE` 的讀；推的），認行程那條要改看別的（例 cgroup 格子、pidfd）。
25. **daemon 換身分前沒清環境、沒關 fd**（L5）：金鑰變數照傳給換了身分的子項；換 uid 若不順便清，等於把鑰匙一起交出去。
26. **eca 本體（claude／codex）**：它們才是最常開 shell 的。只把「工具」換 uid、本體不換，那麼最該擋的那個沒擋到；本體換 uid 又撞第 3 條（家與登入資料）。
27. **tmux**：eca 的畫面在使用者的 tmux 伺服器上；換了 uid 的本體接不上使用者的 tmux socket（socket 在 `/tmp/tmux-1000/`，700）。要嘛各 agent 自己一個 tmux 伺服器、要嘛把 socket 分享出去（分享＝它能操作使用者所有 tmux 視窗）。
28. **`procs` 份額終於能用**（X12）：換了 uid 後 `RLIMIT_NPROC` 數的才是這隻自己的。

## 七、不換 uid 也會有的（同 uid 時的邊緣，給「維持現狀」那案看）

29. **prompt 注入**：同 uid 的 agent 被網頁或檔案裡的字騙去 `rm`、改別人的 stack、寄假信，Linux 不會擋。現在唯一的牆是沙箱，而沙箱是選用的、設定寫壞照跑。
30. **兩個人共用一台**：使用者以外的人（或使用者的另一個帳號）想用同一棵樹，今天沒有路；樹的擁有者就是一個人。
