# 發想：aos 在「權限／使用者」與其他非排程資源上可能長成的幾種樣子

← [README](README.md)｜上一份：[04-邊緣狀況](04-邊緣狀況.md)

照 11-14「需求不清時先發想、不急著規劃」：這份是頭腦風暴，不出施工圖、不排階段、不設門檻數字。每案寫好處、代價、跟八個詞與五條規則合不合、是不是「以後自然會長出來」。最後的傾向是推薦，**由使用者拍板**。

八個詞＝定義、stack、工作區、daemon、proc、kernel、信／信箱、工具；五條規則＝①不手改定義、不碰別人的 stack ②用工具不耍 shell ③看錯誤行 ④路徑相對工作區 ⑤被拒是決定不是 bug（[知識庫入口](../../../../knowledge/aos/_description.json)）。

## 先講結論

- **九個樣子**：甲 維持現狀；乙 接完已裁的那一哩（每隻 agent 一個 subuid）；丙 用 Linux 身分驗寄件人；丁 權限＝遞給你的夾（Plan 9／capability 式）；戊 Landlock 自己綁自己；己 整台 aos 一個身分、跟使用者分開；庚 權限也是資源、寄給 kernel 要；辛 root 那半；壬 其他非排程資源（網路、磁碟、秘密、日誌）。
- **最便宜的一步是乙**：使用者 11-13 已經裁完（K1～K18），工具也都做了，只差 daemon 那段 C++。**最值得記住的念頭是丙**：身分是 Linux 一切鎖的鑰匙，乙之後「看信夾擁有者」幾乎免費。**庚、壬多半是以後自然長出來的**，現在不用設計。
- 我的傾向（推薦，使用者拍板）：**現在不開新規劃**；若想往前一步，就是把乙（已裁）接上，並把丙當成乙的順帶結果記著。在那之前，先回答一題方向：你要的「權限管理」主要是**防呆**、**防賊**還是**多人共用**（見末節）。

## 甲：維持現狀（同一個 uid，靠約定＋選用沙箱）

- **是什麼**：全部 agent 跟使用者同一個帳號；規則 1 靠約定；kernel 的拒絕靠大家寄信給它；要牆就自己寫 `sandbox.json`。
- **好處**：零成本；使用者看得到、改得到一切；git、搬家、兩台機器、WSL 都沒煩惱（[02 第三節第 6 條](02-aos現況.md)）。單人、自己的機器、agent 都是自己派的，這其實夠用。
- **代價**：擋不住 prompt 注入或「刻意」的 agent（[04 第 29 條](04-邊緣狀況.md)）；`procs` 份額不能用；kernel 照寄件人的規則都可以被繞過（E1）。
- **合不合**：完全合（現在就是這樣）。C-64「托底靠 Linux」寫了卻沒接上電，算一個「概念有、實作無」的落差，不算衝突。
- **會不會自然長出來**：它不用長，它就是現在。

## 乙：接完最後一哩——每隻 agent 一個 subuid、一台 daemon 一個群組

- **是什麼**：kernel-limits-plan 的段 3 C++：daemon 認 `user: "sub:N"`、多群組、起前替 stack 設 ACL、換身分前關 fd 清環境（L5）。kernel 站照 `users` 表填號碼（已做），daemon 照填的換（未做）。
- **好處**：Android 的第一步、rootless Podman 的做法（[03](03-別人怎麼做.md)）；agent 讀不到使用者私檔、殺不到彼此、改不了 daemon 的 stack（X4、X6、X32、X36）；`procs` 份額變正確（X12）；sbx-fix 的九條不靠沙箱也擋住（[04 第 23 條](04-邊緣狀況.md)）；**免 root**。
- **代價**：04 的第 1～9、10～11、17、23～27 條全部要接住：家目錄與祖先的 `x`、git `safe.directory`、使用者改得動 agent 的檔（預設 ACL）、搬家的數字擁有者、eca 本體的家與登入資料、tmux socket。公司 WSL 要先裝 `uidmap acl`。
- **合不合**：合。身分是寫在 daemon 表上、proc 自己不知道（C-52「偷偷」）；kernel 定政策、daemon 執行（C-47）；規則 1 從約定變成真的鎖。**跟八個詞不衝突，也不多一個詞**——uid 是 Linux 的詞，不是 aos 的。
- **會不會自然長出來**：不會自己長，要有人寫 C++；但已裁，不用再想形狀。

## 丙：用 Linux 的身分驗寄件人

- **是什麼**：收信方（kernel 站、llm kernel、使用者專區）除了看信裡自報的 `sender`，也看**信夾的 Linux 擁有者**（`stat` 的 uid）；對不上就當壞信或拒絕。進一步可以改用 unix socket 收請求，用 `SO_PEERCRED` 看來電號碼（03 的「總機看得到來電號碼」）。
- **好處**：kernel 站的 `allowed`、`by_sender`、llm kernel 照寄件人算額度、使用者專區的驗證，**全部變成造不了假**；astra-kernel-plan 的洞 AK9「門分不出是哪隻 sol 寄的」也順帶解掉。成本很小：多一個 `stat`。
- **代價**：**要先有乙**（同 uid 時擁有者全是 1000，看了也沒用）；kernel 站要有「uid → 誰」的對照表（`users` 表反查就是）；轉寄的信擁有者是轉寄站，鏈上每一站只認得上一站（這跟 C-52「每層只管自己這一層」其實是一致的）。
- **合不合**：合。信的格式不變（不加 key 也行，`stat` 是信夾本身的屬性）；C-48「靠加 key 擴充」若要把驗過的身分寫進轉寄的信，就加一個 key。
- **會不會自然長出來**：**半自然**：乙做完後，第一個被假寄件人坑到的 kernel 自己就會想加這個 `stat`。現在只需要記得「有這一招」。

## 丁：權限＝遞給你的夾（Plan 9／Fuchsia 式）

- **是什麼**：一隻 agent 能碰什麼，不看「它是誰」，看「它的布景裡掛了什麼」。沙箱設定從「agent 定義夾裡自己寫的 `sandbox.json`」變成「**派它的人（父 agent、kernel、daemon 表）遞給它的清單**」；沒遞的夾在它的世界裡不存在。子 agent 只能拿到父 agent 手上有的子集（Fuchsia 的 offer）。
- **好處**：跟 aos「空間就是資料夾、照 Plan 9」（C-05、C-30、C-37）最對味；不用 uid、不用 root、WSL 也行（bwrap 就夠）；權限的來龍去脈是一條看得見的轉手鏈，人讀得懂（C-24「人能不能理解」）。
- **代價**：每隻 agent 都得在 bwrap 裡跑，eca 本體也是（claude 要家、要網路、要登入資料，教學 09 已示範要綁一堆）；布景搭錯就是 sbx-fix 那種「整棵樹都綁進去」；bwrap 布景搭好就不能改，要「中途多給一個夾」得重起或另想辦法。
- **合不合**：大致合：工作區（C-66「影響外部透過指標 `AOS_WS`」）本來就是「遞給它的那個夾」，丁是把這個想法推到底。跟 11-12「設定寫壞照跑、出事自己負責」有張力：丁要求「沒遞＝沒有」，寫壞照跑就等於全給。
- **會不會自然長出來**：部分會：subagent、子 daemon 已經在「遞工作區給下一層」。要不要變成強制，等需求。

## 戊：Landlock——agent 起來時自己綁自己

- **是什麼**：Linux 5.13 起的免 root 機制：程式自己宣告「我和我以後的子行程只碰這幾個夾（後來的版本還能限埠）」，宣告後解不開。[Landlock 文件](https://docs.kernel.org/userspace-api/landlock.html)。aos-exec 或 agent 的 loop 在起身體前呼叫一次，清單＝工作區＋自己的 stack＋唯讀的 `AOS_HOME`。
- **好處**：免 root、免 namespace、免 bwrap；沒有「布景」所以沒有 sbx-fix 那種綁錯整棵樹的問題（它只會縮、不會放大）；家機核心有開（`lsm` 列著 `landlock`）。
- **代價**：只擋檔案和埠，不擋「同 uid 殺行程、讀 environ」；各版本能擋的東西不同，要偵測版本；公司 WSL 的核心有沒有開**未查**；aos 要多一段呼叫系統呼叫的程式（C++ 或 Python ctypes）。
- **合不合**：合；性質像「agent 自己守規則 1 的手銬」，C-52「上層不知道下層」也不破（是下層自己戴的）。跟丁可以疊：丁說「該碰什麼」，戊是「保證碰不到別的」的一種便宜做法。
- **會不會自然長出來**：不會；但它是「如果哪天要牆、又不想搞 uid」時最省的那條，記著就好。

## 己：整台 aos 一個身分，跟使用者分開

- **是什麼**：根 daemon（連同底下所有 agent）用一個 subuid 跑，例 `sub:1`；aos 內部仍同 uid，但 aos 整體跟使用者本人分開。
- **好處**：比乙簡單很多：只換一次、在最外面（C-83「root daemon 是跟 Linux 的接觸面、矛盾集中點」）；agent 碰不到使用者的私檔（`~/.ssh`、`~/.claude`、其他專案）；使用者專區留底也安全。
- **代價**：agent 之間照舊誰都碰得到誰；04 的家目錄、git、eca 登入資料這幾條照樣要處理（只處理一次）；使用者自己的 repo（`~/repo/aos`）要分享給 aos 的身分。
- **合不合**：合；「一台 daemon 一個群組」（11-13 使用者裁）的同一個精神再往外推一層。
- **會不會自然長出來**：不會；它是乙的「先做一半」版本，若乙嫌重可以先這樣。

## 庚：權限也是資源，寄信給 kernel 要

- **是什麼**：C-09「有限就是資源」：一個夾的寫入權、一個網路埠、一把金鑰、一個 subuid 號碼都是有限的。agent 要多一點權限時，寄信給 kernel（「我要讀 `~/data/ref`」），kernel 照規則或轉給使用者專區問，點頭了就用 `aos-share` 開門、或改下一次起身時的沙箱清單。像 Android 的權限申請（[03](03-別人怎麼做.md)）。
- **好處**：完全沿用八個詞（信、kernel、工具），不多新東西；規則 5「被拒是決定」直接適用；使用者專區天生就是「問人要不要給」的地方。
- **代價**：要有乙或丁當底（同 uid、沒布景時，agent 根本不用申請就碰得到）；問人太多會變成「秒選推薦」的疲勞（11-14 頭腦風暴「人少答幾題」那條）。
- **合不合**：很合；這就是 C-47 kernel 的本業延伸到權限。
- **會不會自然長出來**：**會**——11-14 原話「kernel在做判斷的時候，可能會參考各種東西，那時候自然就會有定義出來了」。某個 kernel 第一次被要求「替我開個夾」時就長出來，不用先設計。

## 辛：root 那半（真帳號、照 uid 管網路、磁碟配額、只准追加）

- **是什麼**：kernel-limits-plan [09](../../13/kernel-limits-plan/09-有root的話.md) 的 R1～R9。
- **好處**：`ps` 看得到名字；網路可以細到「只准連 LiteLLM 的埠」；磁碟總量；稽核紀錄只准追加。
- **代價**：要使用者每台 `sudo`；兩台設定要同步；寫錯影響整台；跟 11-12「root小daemon先不做」、11-13「先以沒有root的情況做規劃」方向相反。
- **合不合**：C-83 准 root daemon 綁這台；但使用者已明說先不走。
- **會不會自然長出來**：不會；等使用者自己想要。

## 壬：排程與權限以外的資源（網路、磁碟、秘密、日誌）

| 資源 | 可能的樣子 | 現在要不要想 |
|---|---|---|
| 網路 | 只准連 proxy 一個埠（沙箱外接一個轉送、或 Landlock 埠規則、或辛的 nftables） | 等「agent 連了不該連的」第一次發生 |
| 磁碟 | 每隻 agent 的寫入總量（cgroup 不管、quota 要 root）；或 kernel 定期 `du` 自己的 stack | 等第一次寫滿 |
| 秘密 | 金鑰不進環境變數，改放 `aos-share key` 點名的檔，或只放在 proxy | 半：proxy 已在做；乙之後 `key` 樣板才有意義 |
| 日誌 | daemon 收集各 proc 的事件到一本 agent 改不了的帳（使用者的 uid 擁有、agent 只准追加） | 等乙；同 uid 時誰都改得到 |
| 時間 | 已有 aos 自己的時鐘 | 不用 |
| 設備 | `/dev`、群組 | 沒需求 |

全部屬於「以後自然長出來」：各 kernel 遇到了各自定義（11-14），不用先設計管線。

## 我的傾向（推薦，使用者拍板）

1. **現在不開新規劃**。這一題的答案大部分 11-13 已經想過、裁過（kernel-limits-plan），而 11-14 說「資源不用特別規劃」；庚、壬照這句讓它自然長。
2. **若要往前一步，最小的是乙**：形狀已裁、工具已有，只差 daemon 那段；它是 Android、Podman、systemd 都走過的第一步，而且免 root。乙嫌重就先己（整台一個身分），只換一次。
3. **丙當成乙的順帶結果記著**：身分接上之後，「看信夾擁有者」幾乎免費，卻讓 kernel 的每一個「拒絕」第一次變成真的。
4. **丁、戊留作「想要牆但不想搞 uid」時的備案**；辛照使用者 11-13 的話，先不走。

## 要使用者先說的一題（方向，不是施工）

**你想要的「權限／使用者管理」主要是擋哪一種事？**

- **防呆**：agent 手滑或理解錯，別讓它弄壞使用者的東西、別隻 agent 的東西。→ 己或乙就夠，丙可有可無。
- **防賊**：agent 被網頁、檔案裡的字騙了（prompt 注入），或模型本身不可信。→ 要乙＋丙，eca 本體也得換身分（04 第 26 條），最好再疊丁或戊。
- **多人共用**：使用者以外的人（或不同專案）共用一台、一棵樹。→ 乙＋丙＋庚，可能還要辛的真帳號。
- 或者「現在都還不需要，只是想知道地圖」→ 甲，這份當地圖留著。
