# 邊緣狀況：「Python 寫、編譯成 aos 夾」會撞到的事

← [README](README.md)｜上一份：[03-別人怎麼做](03-別人怎麼做.md)｜下一份：[05-發想](05-發想.md)

照 wf 的通則：這裡挖出來的，使用者沒回應就視為天然差異或實作時自然可解，不追問、不列待辦。除錯（停下來看資源）的邊緣在 [06](06-除錯與停下來看資源.md) 末節。

## 先講結論

- **最先撞的是「生成物 vs 手改」**：aos 的哲學是「程式就是夾，人和 agent 都可以直接改」（C-07、C-51），而所有編譯器都要求「生成物別手改」。兩者正面衝突，第 1～6 條。
- **第二個是「執行期還會長東西」**：定義只是一半，stack 裡有 `self_*` 的差異、kit 疊上的檔、queue、history。編譯器管得到定義，管不到 stack（第 7～11 條）。
- **其餘多半是「實作時自然可解」**：進不進 git、版本、錯誤行號、跨機器、編譯器本身是不是 aos 程式……都有現成先例（`index_gen` 的「生成物進 git、排隊重生」）。

## 一、生成物跟手改

1. **重生會蓋掉手改**。01 的玩具撞到：手加 `loop.json` 後再 build 就 `FileExistsError`。三種處理：拒絕（玩具現在）、整夾覆蓋（手改消失）、只覆蓋自己生的檔（要記得哪些是自己生的——例如每份帶 `_from`，或夾裡放一份清單）。
2. **agent 也會手改**。人至少知道「這是生成的」；agent 用 `write`／`json_set` 改定義夾時不會看註解。aos 規則 1 已經說「不手改定義，用 `self_*`」，所以**正規路上的 agent 不會碰定義**；但 `agent_def tools`／`system` 會改定義本身——編譯出來的定義被 `agent_def` 改了，原始碼就落後了。
3. **JSON 沒有註解**。「本檔由 prog.py 生成，別改」只能寫成一個 key（`_from`、`_generated`）。C-48「不認得的 key 忽略」讓這招免費，但**純文字檔（`system.txt`）和可執行檔要另想**（玩具在 `_entry` 第二行寫註解；`system.txt` 寫進去就會被腦讀到）。
4. **手改了想收回原始碼**（反推）。JSON 的部分可以反推（讀 `_tooldef.json` 印回 `Tool(...)`），**Python 原始碼裡的迴圈、函式、共用變數反推不回來**（03：大家都只做到「匯回資料」）。
5. **部分生成**：一隻 agent 的 `fsm.json`、`tools.json` 用 lib 生，`system.txt` 手寫、格的 Python 抄範本。邊界畫在哪，決定了第 1 條要多細。
6. **`$env` 路徑要「編譯期」還是「執行期」解**？reviewer 的 `tools.json` 寫 `{"$env": "AOS_HOME", "$path": "/lib/tools/base/read"}`，到執行時才知道 `AOS_HOME` 是哪。lib 若在編譯時就把它展開成絕對路徑，生成物就**綁死這台機器**（違反 N-67 可遷移性⑨「環境變數只指樹內或 root 層以上」的精神）；所以 lib 應該**原樣吐出指示詞**，只在預覽時展開。

## 二、執行期才出現的東西

7. **stack 不是編譯出來的**。`ctl add` 時 kit 寫進 stack、`self_tools` 在 stack 寫差異、執行中長出 queue、history、ledger。編譯器只產定義（＝原始碼／映像），stack 是記憶體——**本來就不該由編譯器管**，這是天然差異。
8. **agent 用 `self_*` 改了自己，跟原始碼分岔**。它改的是 stack 裡的副本，定義不動，所以重新編譯不會蓋掉它的改動；但反過來，**你改原始碼重編，那隻已經在跑的 agent 看到的是「新定義＋它舊的差異」疊起來**——差異是對舊定義寫的，疊在新的上面可能不對（例如它刪掉一個工具，新定義把那工具改名了）。現在不靠編譯器也會發生（直接改定義也一樣），屬天然差異。
9. **「把跑出來的好東西收回原始碼」**：agent 自己調好的 system、加的工具（stack 的差異）要變成下一版定義，今天靠 `agent_def new from` 抄一份。lib 若要接這條，就是「反推」再一次（第 4 條）。
10. **lineage**：`agent_def new` 在 `_metainfo.json` 記「從哪抄來」。編譯出來的定義的 lineage 是「哪份原始碼、哪一行、哪個版本」——有地方放（`_metainfo` 的私有 key），要不要放是實作時的事。
11. **daemon 表、kernel 設定是「部署」不是「程式」**。`ctl add` 時給的 `--limits`、`--kit`、`--envs` 寫在 daemon 表上；「一個文字檔描述整個架構」要不要包含「誰掛在哪個 daemon 下、份額多少」？包含＝lib 變成部署工具（像 Pulumi，要對帳），不包含＝只生定義（像 CDK synth）。

## 三、git、版本、重生

12. **生成物進不進 git**？repo 先例：`index_gen` 的 `_index.json` 與 code map **進 git、各線不手改、由排隊重生**（鐵律 3）。lib 的生成物照這個做最省心；但要是生成物很大（agent-fsm 那種 111 KB 抄一份），進 git 會很吵——**reviewer 的「借別人的格」寫法**（`$env` 指到 agent-fsm）讓生成物只有骨架，就不吵。
13. **lib 改版，舊原始碼生出不一樣的夾**。proto8 照「當沒有舊版」，不做相容；但已經掛在 daemon 上的 agent 是用舊夾跑的，重編不會自己換（要 `set-def` 或重掛）。
14. **兩個人（或人和 agent）同時改原始碼與生成物**：git 衝突會出現兩次（原始碼一次、生成物一次）。先例照 `index_gen`：生成物不手解衝突，重生。

## 四、錯誤訊息

15. **錯誤指的是生成物，不是原始碼**（01 實測：traceback 指 `_entry` 第 5 行）。三層錯各自不同：
    - **編譯時錯**（lib 自己查得到：參數型別、fsm 的 `next` 指到不存在的狀態）→ lib 直接報 `prog.py:13`，最好處理。aos-fsm 開跑時本來就會查整張表（N-36「不合＝表壞、退 1」），lib 可以先做同一件事。
    - **aos 的錯**（`aos-exec: error: EntryMissing …`）→ 印的是生成物路徑；要看 `_from` 才知道原始碼哪行。
    - **格／工具自己的錯**（`math: error: ExprBad …`）→ 跟原始碼無關，照常。
16. **C-53「下層的錯不轉述」**：lib 若在 aos 的錯上面加「這是 prog.py:13 生的」，算不算轉述？比較像在錯誤旁邊附一張地圖，不改錯誤本身——但要注意別把 aos-exec 的錯行改寫掉。

## 五、跨機器、跨環境

17. **兩台機器**：生成物不含絕對路徑（第 6 條）就能搬；原始碼裡要是寫了 `os.environ["HOME"]` 之類在編譯時展開的，就搬不了。
18. **公司 WSL 的 Python 版本**：lib 只用標準庫（像 `tool_spec`「純標準庫」）就不怕。
19. **image 搬家**（C-79）：image＝root daemon 的 stack＋ws，**不含原始碼**。搬到別台後只有夾、沒有 prog.py，人在那台只能手改夾——所以**生成物本身必須是完整、能手改的 aos 程式**，不能依賴 lib 才跑得動。

## 六、人與工具

20. **只想用 mkdir 的人**：C-45「aos 給語法糖，不要求一定用」——lib 是語法糖，夾照樣能手寫，兩種寫法生出來的東西要長得一樣（沒有「lib 專用」的格式）。
21. **agent 會不會用這個 lib**？使用者 11-06：「相比跟agent說：這個list就是你，請你修改自己。不如直接把一個資料夾跟幾個python程式和json檔案交給agent」。agent 改夾很順，改「一份 Python 再重編」多一步、還要知道重編指令。**lib 可能主要是給人的**，agent 照舊直接改夾——那就回到第 1、2 條。
22. **編譯器本身是不是 aos 程式**？可以是：一個工具夾 `aos_build`，stdin 吃 `{"src": "prog.py", "out": "defs/x"}`。好處是 agent 也能叫、能進 kernel 的規則；這是「開發函數的函數」又一例，**用多了自然會這樣**，不用先設計。
23. **lib 的「能寫的東西」比 aos 少**：aos 的 JSON 格式族是開放的（私有 key、雙形值、指示詞），任何程式都能加自己的 key。lib 若只認自己定義的類別（`Tool`、`Fsm`），新格式出來就跟不上；**要留一個「原樣吐這份 dict／這個檔」的逃生門**。
24. **資料夾深度與檔數**（11-13 長文「資料夾嵌套可能對linux造成的性能影響」）：lib 讓「生 1000 個夾」變得很容易。11-13 量過活樹 984 檔、走一遍 0.015 秒（[any-resource-os 06](../../13/any-resource-os/06-採納表與改後計劃.md)）；lib 會讓這數字長得更快，但門檻照舊等量測。

## 七、跟今晚另兩份調查的接點

25. **權限**（[linux-as-hw-1118](../linux-as-hw-1118/README.md)，使用者答「先做防呆」）：生成物的擁有者、權限位是 lib 寫檔時決定的；防呆的最小一步是「生成物設唯讀、要改先改原始碼」——這剛好同時解第 1 條的手改問題。只是想法，記著。
26. **預設 stack**（[default-stack-1118](../default-stack-1118/README.md)，丁：stack 裡放路標）：lib 生的是定義，不碰 stack，兩題不相交。
