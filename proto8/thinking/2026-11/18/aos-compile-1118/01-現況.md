# 現況：今天「寫一個 aos 程式」實際要做哪些事、手寫量多少、已經有哪些半自動手段

讀的是 repo HEAD `ce2e875eb` 的 `proto8/`；量測用 `find`／`wc`，不含 README、測試、`__pycache__`。

## 先講結論

1. **寫 aos 程式＝擺一個資料夾**：一個入口 `_entry`（可執行檔、inst 單子、argv 陣列三選一），旁邊放它要讀的 JSON 和程式。aos 本身只認入口與六個環境變數（C-68、C-69、N-57），**其他檔名都是各程式自己的慣例**（工具認 `_tooldef.json`、agent 認 `interfaces.json`……）。
2. **手寫量其實不大，但很「散」**：一隻 agent（reviewer）是 10 個檔、5.6 KB，其中 8 份 JSON 只有 3.1 KB；難的不是字數，是**哪個檔叫什麼、誰指向誰、`$env` 路徑怎麼寫**要記在腦子裡。
3. **「把東西接起來」靠指示詞**：`{"$env": "AOS_HOME", "$path": "/lib/tools/base/read"}`、`$ref`、`$override` 疊工具包——這就是 aos 的 `#include` 與連結器。reviewer 的 8 份 JSON 裡有 16 處指示詞。
4. **已經有好幾個「小編譯器」**，只是各管一塊、沒有串起來：`tool_spec`（一支 Python 宣告 → `_tooldef.json`／`_metainfo.json`，**這就是使用者說的「Python lib 編譯成 json」，在工具這一格已經有了**）、`agent_def new`（抄範本）、kit（蓋在 stack 上的兩份檔）、`install.py`（`py/` → `lib/`＋`bin/` 入口）、`aos-agent ctl add`（把定義掛到 daemon 表）。

## 一、手寫一個 aos 程式要做的事

以「新做一隻 agent，給它一個新工具」為例，今天的步驟：

| 步驟 | 動作 | 寫什麼 |
|---|---|---|
| 1 | `agent_def {"op":"new","template":"agent-fsm","path":"defs/x"}` 或 `cp -r` | 整個範本抄一份（agent-fsm 是 19 檔、111 KB，幾乎全是格的 Python） |
| 2 | 改 `system.txt` | 純文字，給腦看的說明 |
| 3 | 改 `tools.json` | `$override` 列工具包、`tools` 列單個工具的 `path`（`$env` 拼路徑） |
| 4 | 改 `llm.json` | `{"model": ...}` |
| 5 | 做新工具：`tools_def new` → 改 `tool.py` 的 DESCRIPTION／PARAMS／META／run → `tools_def check` | `check` 從 tool.py **重生** `_tooldef.json`、`_metainfo.json` |
| 6 | 把工具接進 agent：`agent_def tools add` 或手改 `tools.json` | 一行 `{"path": ...}` |
| 7 | `aos-agent ctl add defs/x`（可帶 `--kit gather`） | daemon 表上多一列、stack 裡長出執行期的檔 |

用到的「指令格式」只有三種：**資料夾**（有 `_entry`）、**JSON**（單子 `{"argv": [...]}`、或沒有 `argv` 的物件當資料夾一路往下找 `_entry`，C-72）、**可執行檔**。指示詞兩個：`$env`、`$ref`（加修飾 `$path`、`$prefix`，N-45）；工具包的疊法 `$override` 是 aos-tools 自己認的私有 key。

## 二、三個真實例子量一量

| 例子 | 在哪 | 檔數 | 大小（不含 README） | 其中 JSON | 長怎樣 |
|---|---|---|---|---|---|
| 工具 `math` | `py/tools/base/math/` | 3 | 4.0 KB | 2 份 0.8 KB | `_entry`（65 行 Python，前 30 行是「找 aos 套件」的固定開頭）＋`_tooldef.json`（給腦看的說明與參數 schema）＋`_metainfo.json`（副作用、冪等、估時） |
| agent `reviewer` | `templates/reviewer/` | 10 | 5.6 KB | 8 份 3.1 KB | **幾乎全是 JSON**：`_entry`（掛上 daemon 的單子）→`body.json`（`aos-loop loop.json`）→`loop.json`（每拍跑 `fsm.json`）→`fsm.json`（四格 idle／think／wait／act，**格的程式借 agent-fsm 的**，用 `$env AOS_HOME` 指過去）；`interfaces.json` 宣告其他檔叫什麼；`tools.json` 11 處 `$env`；`system.txt` 2.3 KB |
| kit `gather` | `templates/kits/gather/` | 2 | 3.6 KB | 1 份 1.4 KB | `system.txt`＋`tools.json`（`$override` 疊六個工具包），`ctl add --kit gather` 時蓋進新 agent 的 stack |
| （參考）範本 `agent-fsm` | `templates/agent-fsm/` | 19 | 111 KB | 9 份 4.7 KB | 105 KB 是格的 Python（brain、act、idle、wait…）；JSON 只佔 4% |

看得出來：**骨架（資料夾＋JSON）很小，肉（Python）很大**——這正是 11-13 長文說的「在檔案系統內／在 json 內／在程式內各部分的佔比」，目前的實際佔比大約是「夾 10 個、JSON 幾 KB、程式幾十～上百 KB」。reviewer 是最好的例子：**同一套肉（agent-fsm 的格），換一副骨架（幾份 JSON）就是另一隻 agent**。

## 三、已經有的生成器與半自動手段

| 手段 | 在哪 | 做什麼 | 像什麼 |
|---|---|---|---|
| `tool_spec` | `py/aos/tool_spec.py`（291 行） | 一支 `tool.py` 裡寫 `DESCRIPTION`、`PARAMS = [ts.param(...)]`、`META`、`run()`；`--write-defs` 寫出 `_tooldef.json`、`_metainfo.json`，執行時照宣告驗參數。使用者 11-10：「給python一種，順便弄個好用的lib，方便AI弄json schema, metainfo啥的。」 | **已經是「Python lib 編譯成 aos json」，只是單位是一個工具** |
| `tools_def` | `py/tools/agent/tools_def/` | `new` 抄骨架、`check` 從 tool.py 重生兩份 JSON 並試跑、`add_entry`／`add_tooldef` 一步步長 | 編譯＋測試 |
| `agent_def` | `py/tools/agent/agent_def/` | `new` 抄範本或別的定義、`_metainfo.json` 記 `lineage`（從哪抄來）；`check`；`tools`／`llm`／`system` 改定義 | 「抄一份改」型的產生器；lineage 像版本來源 |
| 範本 | `templates/` | agent-fsm、eca-claude、eca-pi、reviewer、judge-llm、kernel、start-api… | 專案骨架（像 `cargo new`） |
| kit | `templates/kits/` | 角色的 system＋工具組，`ctl add --kit` 時寫進 **stack**（不是定義） | 疊在上面的設定層（像 kustomize 的 overlay） |
| 工具包 `$override` | `py/packs/*.json` | 一份 `tools.json` 列幾個包，展開成一串工具 | `#include`／連結 |
| `self_*` 的 overlay | stack 裡的 `tools.json`、`llm.json`、`system.txt` | agent 改自己＝在自己 stack 寫差異，定義不動（[知識庫 definition.json#/overlay](../../../../knowledge/aos/definition.json)） | 執行期打補丁 |
| `install.py` | `proto8/install.py` | 編 C++、`py/` 抄成 `lib/`、照 `py/entries.json` 在 `bin/` 生指令入口 | 真的 build 系統（像 make install） |
| `aos-agent ctl add` | `py/aos/apps/agent/ctl/add.py` | 讀宣告、檢查、寄信給 kernel／daemon 掛上 | 「載入器」：把程式放進記憶體開跑 |
| `index_gen` | `wf/tools/index_gen.py` | 掃樹重生 `_index.json` 與 code map 逐檔表，生成物不手改、由排隊跑 | **repo 裡已有的「生成物進 git、不手改」先例** |

## 四、這次在暫存樹的小實測（玩具，不進 repo 程式區）

在 `~/.aos/scratch/aos-compile-1118/`：`src/` 是 HEAD 的 `git archive`＋`install.py`（15 秒建好），`toy/` 是一支 37 行的玩具 `aosc.py`＋16 行的 `prog.py`。全程沒起 daemon、沒開 tmux，`AOS_HOME` 指暫存樹。

`prog.py`（用 Python 描述一支 aos 程式）：

```python
add = Tool("Add two numbers", {"a": "number", "b": "number"},
           'print(args["a"] + args["b"])')
tick = Tool("Count one step in the stack; exit 10 when the count reaches 3", {},
            'p = os.path.join(os.environ["AOS_STACK"], "n.txt")\n'
            'n = int(open(p).read()) + 1 if os.path.exists(p) else 1\n'
            'open(p, "w").write(str(n)); print("tick", n)\n'
            'sys.exit(10 if n >= 3 else 0)')
done = Tool("Say finished", {}, 'print("finished")')
counter = Fsm("tick", tick=("tick", {"0": "tick", "10": "done"}),
                      done=("done", "done"))
build(sys.argv[1], add=add, tick=tick, done=done, counter=counter)
```

`python3 prog.py out1`（0.02 秒）生出 3 個工具夾（各 `_entry`＋`_tooldef.json`＋`_metainfo.json`）和一份 `counter.json`（aos-fsm 的表，`"_entry": ["aos-fsm", {"$env": "AOS_CF"}]`）。每份 JSON 多一個 `"_from": "prog.py:13"`——C-48「不認得的 key 一律忽略」，所以**這種「出處」欄是免費的**，aos-exec、aos-fsm 都不會抱怨。

<details><summary>玩具本體 aosc.py（37 行）</summary>

```python
"""aosc - 玩具：用 Python 描述 aos 程式（工具、fsm），build() 展開成資料夾＋json；每份生成物記下出自原始碼哪一行。"""
import inspect, json, os

def _where():                                   # 呼叫者在原始碼的哪一行（給錯誤訊息指回去）
    f = inspect.stack()[2]
    return "%s:%d" % (os.path.basename(f.filename), f.lineno)

def _write(path, obj):
    with open(path, "w") as f:
        f.write(json.dumps(obj, ensure_ascii=False, indent=1) + "\n")

class Tool:                                     # 一個工具夾：_entry（Python）＋_tooldef.json＋_metainfo.json
    def __init__(self, desc, params, body):
        self.desc, self.params, self.body, self.src = desc, params, body, _where()
    def emit(self, d):
        os.makedirs(d)
        _write(os.path.join(d, "_tooldef.json"), {"description": self.desc, "_from": self.src,
            "parameters": {"type": "object", "required": list(self.params),
                           "properties": {k: {"type": t} for k, t in self.params.items()}}})
        _write(os.path.join(d, "_metainfo.json"), {"summary": self.desc, "_from": self.src})
        entry = os.path.join(d, "_entry")
        with open(entry, "w") as f:
            f.write("#!/usr/bin/env python3\n# generated by aosc from %s; edit the source, not this file\n"
                    "import json, os, sys\nargs = json.loads(sys.stdin.read() or \"{}\")\n%s\n" % (self.src, self.body))
        os.chmod(entry, 0o755)

class Fsm:                                      # 一張 aos-fsm 的表：狀態名 → (哪一格, 下一步)
    def __init__(self, start, **states):
        self.start, self.states, self.src = start, states, _where()
    def emit(self, path):
        _write(path, {"_entry": ["aos-fsm", {"$env": "AOS_CF"}], "_from": self.src, "start": self.start,
                      "states": {n: {"exec": c, "next": nx} for n, (c, nx) in self.states.items()}})

def build(out, **things):                       # 名字 → 東西；Fsm 變成 <名>.json，其他變成 <名>/ 夾
    os.makedirs(out)
    for name, t in things.items():
        t.emit(os.path.join(out, name + ".json") if isinstance(t, Fsm) else os.path.join(out, name))
```

</details>

實跑結果：

```
$ echo '{"a":2,"b":40}' | aos-exec --ws ws out1/add
42
$ for i in 1 2 3 4 5; do aos-exec --ws ws out1/counter.json; cat ws/.stack/stage.txt; done
tick 1   → stage=tick n=1
tick 2   → stage=tick n=2
tick 3   → stage=done n=3
finished → stage=done
finished → stage=done
```

**每打一次 `aos-exec` 就走一格**，`stage.txt` 就是「程式計數器」、`n.txt` 是「記憶體」——使用者的「aos-exec＝手動推 CPU 走一步」在 fsm 上是字面成立的。手寫一份 `loop.json`（`{"exec": "counter.json", "max": 4}`）與 `body.json`（`{"argv": ["aos-loop", "loop.json"]}`）後 `aos-exec --ws ws2 out1/body.json` 自己跑完四拍、`state.json` 記 `"phase": "done"`。

兩個順便看到的問題（04 細講）：

- **錯誤指不回原始碼**：`{"a":2}` 叫 add，Python 的 traceback 指的是生成出來的 `_entry` 第 5 行，不是 `prog.py` 第 5 行；只有 `_entry` 第二行的註解 `generated by aosc from prog.py:5` 讓人找得回去。
- **重生撞到手改**：手加了 `loop.json`、`body.json` 後再跑 `python3 prog.py out1` → `FileExistsError`；換新夾 `out2` 重生，`diff -r` 只差那兩份手寫檔。玩具選的是「不覆蓋、換夾」，真要做就得決定 04 第一節那幾條。
