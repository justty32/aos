# 04 接法選項、推薦與待裁題

← [03](03-對照表.md)｜[入口](README.md)｜下一份 [05-供應鏈](05-供應鏈.md)

**結論**：推薦**甲（一問一答，照 codex 加第三種身）先做**，要「回答途中收信」再升級成乙（每輪一個 RPC 行程），畫面與外掛（丙）放最後、等使用者真的要開畫面看 pi 再做。理由：甲最小、跟現有 claude／codex 的路一樣（aos 只多一個分岔），做完就能用 `aos-agent say` 叫 pi 答題；乙與丙都能在甲之上疊，不用推倒。

## 三種接法

### 甲：一問一答（`pi --mode json`），照 codex 的樣子

- **做法**：`cli.json` 寫 `"kind": "pi"`；`cli_print` 加 `print_pi`：第一輪 aos 產 uuid，起 `pi --mode json --session-dir <小格>/pi-sessions --session-id <id> [flags] <題目>`，交出去那刻記 `session.txt`；之後同一招續（`--session-id` 用同一個 id 或 `--session <id>`，哪個才是「續」要實測）。讀事件流取最後一則 assistant 的 `message_end`、事件接進 `live.jsonl`（`aos-agent watch` 照看得到）。系統提示用 `--append-system-prompt`、模型用 `--model`。aos 工具先**不接**或用最簡單的方式接（見下「待實測」）。
- **權限**：照 pi 原樣（不問、全開）。必帶 `--no-approve`（不載工作區 `.pi/` 的專案資源，擋 CVE-2026-54325 那類「打開別人的 repo 就跑它的外掛」）；或使用者說要再帶 `-ne`（不載任何外掛）。
- **工作量**：一條線一到兩天。改 `cli_cfg`（kind、保留旗標表：`--mode`、`-p`、`--session*`、`--no-session`、`-c`、`-r`、`--fork` 歸 aos）、`cli_print`、`cli_cell`（帳號資料夾、對話檔位置）、`apps/eca/slash.py`（`/clear`＝刪 `session.txt` 開新的；`/compact` 先回「請開畫面」或實測 json 模式收不收）、說明與 `knowledge/aos/cli/eca.json`、一份 pi 的 `cli.json` 寫法。
- **後果**：沒有畫面、沒有中途收信、失敗一律 `CliFailed` 停下（跟 codex 一樣）。用量讀不到時 `context_wrap` 不作用，靠 pi 自己自動壓縮；aos 的 history 不知道 pi 壓過（history 本來就是 aos 自己記的「信與回答」，不影響續接）。

### 乙：每輪起一個 `pi --mode rpc`（甲的升級）

- **做法**：同甲，但起的是 RPC 行程：送 `{"type":"prompt","message":…}`，讀事件流；等回答時 queue 又來信＝送 `follow_up`（或 `steer`）；看到 `agent_settled` 又沒新信＝關 stdin 讓它收工。`get_state` 拿 `sessionFile`／`sessionId`；aos 寄的 `/compact` 直接送 RPC 的 `compact`（回摘要，可以照 claude 那樣把 history 換成摘要一則）。
- **工作量**：在甲之上再一到兩天。架子跟 `cli_stream.py`（claude 的 `live_mail`）幾乎一樣，可以照抄它的 selector 迴圈；要注意只用 LF 切行。
- **後果**：中途收信、壓縮都是原生的，比 claude 的 `live_mail` 乾淨。代價是多一套協定要跟版本走（RPC 指令名 1.x 之間可能改），出事時比 json 模式難看懂。**不建議做成「一直開著的 RPC 行程」**：aos-eca-turn 一輪一支、loop 管生死，常駐行程要另外管孤兒、重啟、`PR_SET_PDEATHSIG`，不划算。

### 丙：畫面（tmux）＋aos 的 pi 外掛

- **做法**：`cli_screen` 加 pi 分岔：tmux 裡起 `pi --session-dir … --session <id> --tui-mode regular -e <aos 外掛>`；aos 往畫面貼字照舊。外掛（TypeScript，一個檔，約 50～100 行，放 `py/` 旁邊某處、`install.py` 抄進 `lib/`）掛 `agent_start`（寫 `busy.txt`）、`agent_settled`（叫 `cli_session.py hook pi <小格> <JSON>`，帶最後回答與 session id）、`session_compact`（history 跟上）、`session_start`（`/new` 時清 history）。同一支外掛還可以順便掛 `tool_call` 擋危險指令（＝權限白名單），甲乙也能 `-e` 帶它。
- **工作量**：兩到三天，含學 pi 的外掛 API 與實測。aos 第一次放 TypeScript 碼進 repo（慣例是 Python／C++），要使用者點頭。
- **後果**：人能 `aos-agent open` 看 pi 做事；外掛跟 pi 版本綁得更緊（事件名改了就壞）；外掛在 pi 行程裡有使用者全部權限，寫錯就是一個洞。收件 socket（a2a）那套是 Claude Code 專屬，pi 沒有，畫面開著只能貼字。

## 待實測（裝了才知道，列給施工線）

1. `--mode json` 只給 stdin、不給題目參數時行不行；題目很長時怎麼給最穩。
2. `--session-id <同一個 id>` 第二次是「續」還是「開新的」；跟 `--session-dir` 合用時檔名長怎樣。
3. json／print 模式收不收 `/compact`、`/new` 這類 slash。
4. 怎麼讓 pi 這一次起動接上 aos-mcp：`mcp.json` 放哪（帳號資料夾會連 `auth.json` 一起換）、還是外掛 `registerMcpServer()`；aos 工具經 Codemode 叫時 `before_tool` hook 是否照常（應該會，工具還是經 aos-mcp）。
5. 事件裡 usage 欄位（給 `context_wrap`）、失敗時的結束碼與 stderr。
6. 1.0 預設全螢幕下 tmux `capture-pane` 判「畫面穩了」那段還準不準。
