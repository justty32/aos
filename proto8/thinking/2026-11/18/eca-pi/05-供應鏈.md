# 05 pi 的供應鏈：事故、相依、怎麼釘版（這次沒裝任何東西）

← [04](04-接法選項與待裁.md)｜[入口](README.md)

**結論**：沒查到 pi 官方套件本身被下毒；有兩個已修的安全漏洞（都在 1.0 之前修好）、一個名字很像的惡意社群套件。官方套件有 npm 的來源證明（provenance）。要裝就用 npm 釘死 `@earendil-works/pi-coding-agent@1.5.2`、帶 `--ignore-scripts`、不用 `curl | sh`、不裝第三方 pi 外掛。

## 查到的

| 事 | 內容 | 跟我們的關係 |
|---|---|---|
| CVE-2026-54325 | 舊版打開一個 repo 就會載它 `.pi/extensions` 的外掛（沒問信任），等於「進別人的資料夾跑 pi＝跑它的程式」。0.79.0（2026-06-08）修好（現行版本的「專案信任」就是管這件事） | 裝 1.x 就沒這問題；aos 起 pi 仍建議帶 `--no-approve` |
| CVE-2026-54328 | 外掛安裝的暫存路徑可猜，多人共用的 Linux 上能提權（CrowdStrike 回報）。0.78.1 修 | 1.x 已修；我們是單人機 |
| 其他舊 scope 公告 | GitLab 列了 `@mariozechner` 舊名下的幾則：`auth.json` 競態可能漏憑證、HTML 匯出 XSS | 再一個不要留舊版的理由 |
| `pi-exa-mcp`（MAL-2026-3280） | 2026-05-04 起的社群 npm 套件，被標成惡意程式碼，不是官方的 | 不裝第三方 pi 外掛與「pi 套件」（`pi install` 會跑對方的 postinstall、拿你全部權限） |
| 大環境 | 2026 年針對 AI coding 工具鏈的 npm 蠕蟲（Mini Shai-Hulud 等）會改 coding agent 的設定檔當據點；搜尋結果沒列 pi 為受害者 | 裝之前看一下 npm 上的發佈時間與維護者有沒有怪事 |

## 官方套件長怎樣（2026-11-18 讀 npm registry）

- 最新 `1.5.2`（2026-11-10）；1.5.0 是 11-02、1.5.1 是 11-09，**一個月三版**，跳得快。
- 有 SLSA provenance 證明（`dist.attestations`），可以用 `npm audit signatures` 驗是從 GitHub 的建置流程發的。
- 直接相依 22 個，其中 5 個是自家 `@earendil-works/pi-*`（ai、agent-core、tui、mcp、codemode，跟主套件同版號）；外部的有 `undici`、`jiti`（載外掛用）、`chalk`、`yaml`、`diff`、`minimatch`、`cross-spawn`、`highlight.js`、`quickjs-wasi`（Codemode 沙盒）、`@silvia-odwyer/photon-node`（圖片）等，都釘到確切版號。
- `bin` 指的是打包過的 `dist/bundle/cli.js`；要 Node ≥ 22.19。

## 建議的裝法（給之後施工線，這次不做）

> **11-18 使用者裁了不釘版**（「算了，不要釘版吧，太麻煩了」，見 [04 文末](04-接法選項與待裁.md#11-18-使用者裁定)）：aos 用他自己裝的那份 pi。下面這段留著當參考，想釘版時照做。

1. 用 Node 22.19 以上（家機 fnm 的 24.14.1 就夠）。
2. 不用官網 `curl -fsSL https://pi.dev/install.sh | sh`（跑一支當下下載的腳本，跟今天 litellm 那邊的顧慮一樣）。
3. 釘版、關安裝腳本：
   `npm install -g --ignore-scripts @earendil-works/pi-coding-agent@1.5.2`
   更穩的作法：在一個專用資料夾 `npm install --ignore-scripts --save-exact @earendil-works/pi-coding-agent@1.5.2`，留下 `package-lock.json`（每個相依有 `integrity` 雜湊），之後用 `npm ci` 重裝，PATH 指到那裡的 `node_modules/.bin/pi`。
4. 裝完 `npm audit signatures` 看來源證明；`pi --version` 確認。
5. 關掉自動更新（pi 有 `pi update` 與 `--offline`／`PI_OFFLINE=1`；aos 起 pi 時考慮帶 `--offline`，免得它自己連網查更新——**`--offline` 會不會連帶擋掉模型呼叫要實測**）。
6. 不 `pi install` 任何第三方套件；要外掛就自己寫、放 repo 裡。
7. 舊的 `@mariozechner/pi-coding-agent` 要移除（刪檔，要使用者點頭）。
