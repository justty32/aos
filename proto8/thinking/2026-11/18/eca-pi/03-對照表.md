# 03 對照表：aos eca 要的 vs pi 給的 vs claude 現在怎麼給

← [02](02-pi是什麼.md)｜[入口](README.md)｜下一份 [04-接法選項與待裁](04-接法選項與待裁.md)

**結論**：十二項裡「直接對上」六項、「要寫轉接」五項、「對不上」一項（權限白名單）。要寫轉接的都是 aos 這邊多寫幾十行 Python 的量；真正麻煩的是畫面那條路的「講完通知」要寫 pi 外掛、以及權限。

標記：**對上**＝pi 有同一種東西，aos 照 codex 那樣補一支分岔就好；**轉接**＝pi 有，但形狀不同，aos 要多寫一段；**對不上**＝pi 沒有，只能繞。

| # | aos 要的 | pi 給的 | claude 現在怎麼給 | 標記 |
|---|---|---|---|---|
| 1 | 一問一答地起 | `pi --mode json`（跑完就結束、一行一事件）；或 `-p` | `claude -p --output-format stream-json --verbose` | **對上** |
| 2 | 題目怎麼送 | 題目當參數；stdin 也收，但是「接在第一則題目前面」——只給 stdin 不給參數行不行要實測 | stdin | **轉接**（最穩是題目寫進暫存檔、用 `@檔` 或參數給；長題目參數有長度上限） |
| 3 | 答完、拿回答 | 行程結束；最後一則 assistant 的 `message_end`；`agent_settled` 才算真的停 | 最後一行 `result` | **對上**（`print_pi` 讀事件流取最後一則 assistant 文字） |
| 4 | 對話 id 與續接 | `--session-id <id>`（用此 id 開或建）＋`--session <id>` 續；json 第一行 `session.id` | aos 產 id 給 `--session-id`，之後 `--resume` | **對上**（跟 claude 同招：aos 產 id、交出去那刻就記 `session.txt`） |
| 5 | 對話檔在哪 | `--session-dir <夾>` 可指定；預設 `~/.pi/agent/sessions/` 依資料夾分組 | `~/.claude/projects/*/<id>.jsonl`，aos 做 symlink | **對上，還更好**：`--session-dir` 直接指進小格，`transcripts/` 不用找 |
| 6 | 互動畫面 | `pi` TUI，可在 tmux 裡跑（官方有 tmux 頁；1.0 起預設全螢幕，捲動要 `--tui-mode regular`） | tmux 裡起 `claude` | **對上**（貼字那套照用） |
| 7 | 畫面講完一輪叫 aos 的 hook | 沒有「講完叫外部指令」的設定；要寫外掛掛 `agent_settled`，裡面 `pi.exec("python3", [cli_session.py, "hook", "pi", 小格, JSON])` | `--settings` 掛 Stop hook；codex 是 `-c notify=` | **轉接**（要寫、要維護一支 TypeScript 外掛，`-e` 帶進去） |
| 8 | 權限不卡、又有白名單 | 從不問；沒有白名單、沒有沙盒；只能外掛 `tool_call` 擋或關容器 | `dontAsk`＋`--allowedTools Write,Edit,Bash` | **對不上**（「不卡」是白送的，「白名單」要自己做） |
| 9 | 接 aos 工具（aos-mcp） | MCP 內建（1.0 起，經 Codemode），設定在 `mcp.json` 或外掛 `registerMcpServer()`；沒查到單次起動指定設定檔的旗標 | 小格 `mcp.json`＋`--mcp-config` | **轉接**（候選：小格裡放一份專用帳號資料夾的 `mcp.json`——但那會連 `auth.json` 一起換掉；或外掛註冊；待實測） |
| 10 | 附加系統提示 | `--append-system-prompt <字或檔>` | `--append-system-prompt-file`＋snapshot off | **對上** |
| 11 | 換模型 | `--model 供應商/id`（可帶 `:thinking`）、`--provider` | `--model` | **轉接**（小）：`llm.json` 的 `"sonnet"` 是 claude 別名，pi 要寫 `openai/gpt-…` 或 `litellm/<id>` 這種；1.0 起 `--provider` 不帶 `--model` 會報錯 |
| 12 | 壓縮與 slash | `/compact [指示]`；RPC 有 `compact` 指令；會自動壓；json 有 `compaction_start/end`；`/new` 開新對話 | `-p` 認得 `/compact`；hook 看 SessionStart compact | **轉接**：`-p`／json 模式收不收 `/compact` 這種 slash 要實測；RPC 模式最乾淨。aos 的 history 跟上壓縮要讀 pi 的對話檔（樹狀 JSONL，格式另一份文件 `session-format.md`，本線沒讀） |

## 兩樣「好處」

| 項 | pi | claude 現在 | 說明 |
|---|---|---|---|
| 回答途中收信 | RPC 的 `follow_up`（等手上工具做完、沒別的事了才送）與 `steer`（這輪工具做完、下次叫模型前送）；外掛 `sendMessage` 也行 | 畫面走收件 socket、非互動走 `live_mail` | **pi 原生就有**，比 claude 的 `live_mail`（靠 `isReplay` 判斷被取走沒）好接 |
| 暫時錯續做 | 自己會自動重試（`auto_retry_start/end`、RPC `set_auto_retry`） | aos 讀 result 行分 429／5xx，`retry.json` 冷卻 | 第一版照 codex：失敗一律 `CliFailed` 停下；pi 自己的重試先頂著 |

## context_wrap 要的用量

aos 的 `context_wrap` hook 要「上一輪最後一次呼叫的 input token／context 大小」。pi 的 json 事件裡 assistant 訊息應該帶 usage（`message_end` 的 message），RPC 有 `get_session_stats`；具體欄位本線沒讀到，**要實測**。讀不到也不壞：`context_wrap` 對「不給讀數的腦」本來就不管，靠 pi 自己的自動壓縮。

## 帳號資料夾（換台判斷）

aos 的 `.session_home` 記「哪台機器、哪個工作區、哪個帳號資料夾」。pi 的帳號資料夾＝`PI_CODING_AGENT_DIR` 或 `~/.pi/agent`（`cli_cell.account_dir` 補一支）。對話檔若用 `--session-dir` 放進小格，換台時檔跟著小格走，「這段對話是不是這台的」反而簡單：檔在小格裡就是。
