這份教你自己抄一份 eca-claude 定義到樹外、改過、掛成一隻新 agent，再用 set-def 換定義，以及改錯時會看到什麼（試驗 03，11-18 在公司 WSL 用 haiku 實跑過）。

← [目錄](README.md)

使用者原話：「3.試試看自己複製一份template設定到某處，改過之後，掛這個agent上去。」

## 結論

- **定義夾就是一個普通資料夾**，抄到哪裡都能用：`cp -r $AOS_HOME/templates/eca-claude ~/my-defs/bob`。
- **沒有一定要改的檔**，抄來直接掛就會動。常改的是這三個：`llm.json`（模型）、`system.txt`（角色說明，範本沒附這個檔，自己建）、`cli.json`（怎麼叫 claude）。
- 掛上去：`aos-agent -d .stack ctl add -n bob -s ~/bob-stack -w ~/bob-ws --auto-restart ~/my-defs/bob`。它自稱 Bob，模型是 haiku，畫面 30 秒後關，三樣都驗到生效。
- **定義是活的**：agent 跑著的時候改 `system.txt`，下一句就生效，不用重開。
- 要換成**另一個夾**的定義用 `ctl set-def bob ~/my-defs/bob-v2`：約 1 秒，對話紀錄留著。
- **改壞的兩種**：
  - 沒有 `interfaces.json`：掛的當下就被擋，什麼都沒動。
  - `cli.json` 的值錯了：掛的當下**不擋**，agent 起來就倒，倒三次後停住，原因寫在 `stderr.txt`。

## 模型怎麼設成 haiku

範本的 `llm.json` 是 `{"model": "sonnet"}`。改成：

```sh
echo '{"model": "haiku"}' > ~/my-defs/bob/llm.json
```

驗法：問過一句之後，`grep -o '"model":"[^"]*"' ~/bob-stack/claude/live.jsonl | sort -u` 會看到 `"model":"claude-haiku-5-5"`。起手樹的 `~/aos-home/agents/ann/llm.json` 也是同樣改法。

## 一步一步

前提：樹照 [README 的「共同準備」](README.md#共同準備)起好，視窗 A 開著。下面都在視窗 C 的 `~/aos-home` 打。

**1. 抄一份定義、建工作區**

```sh
mkdir -p ~/my-defs ~/bob-ws && cp -r $AOS_HOME/templates/eca-claude ~/my-defs/bob
```

**2. 改模型、寫角色說明**

```sh
echo '{"model": "haiku"}' > ~/my-defs/bob/llm.json
```

```sh
printf 'Your name is Bob. Start every answer with the words: Bob here.\n' > ~/my-defs/bob/system.txt
```

`interfaces.json` 本來就宣告了 `"system": "system.txt"`，aos 會用 `--append-system-prompt-file` 把它**接在** claude 原本的系統提示**後面**。是附加，不是取代。

**3. 改 cli.json 的兩個值**

用編輯器打開 `~/my-defs/bob/cli.json`，改兩處：

- 加一個鍵 `"screen_close_after_s": 30`：停下後 30 秒關畫面，預設是 600 秒。
- 把 `"print_flags"` 裡的 `"0.5"` 改成 `"0.2"`：每一輪最多花 0.2 美元。

**4. 掛上去**

```sh
aos-agent -d .stack ctl add -n bob -s ~/bob-stack -w ~/bob-ws --auto-restart ~/my-defs/bob
```

會印一行它的 stack：`/home/你/bob-stack`。

- `-n` 是表上的名字，不給就用夾名。
- `-s` 是它的 stack，不給就放在 `.stack/procs/bob`。
- `-w` 是它的工作區，不給就是你現在所在的資料夾。

**5. 看表、問一句**

```sh
aos-daemon-ctl -d .stack ls
```

會多一列 `bob	running	…	/home/你/bob-ws`。

```sh
aos-agent -t bob ask --timeout-s 120 "What is your name? One short sentence."
```

會看到 `Bob here. My name is Bob.`（約 8 秒）。

**6. 驗畫面的 30 秒**

```sh
aos-agent -t bob open --detach
```

會印 `screen opened (resumed with --resume if a conversation exists): /run/user/1000/aos-tty-1000/….sock`。`--detach` 的意思是只開、不接進去看。

```sh
aos-agent -t bob ctl stop
```

```
stopped, stack kept (/home/你/bob-stack); say still queues letters meanwhile, aos-agent ctl start --target bob to carry on
```

`cat ~/bob-stack/claude/screen_close.json` 看得到 `"delay_s": 30`。約半分鐘後畫面關掉：`ls /run/user/1000/aos-tty-1000/` 變成空的，畫面的行程也沒了。

**7. 跑著的時候直接改定義**

```sh
aos-daemon-ctl -d .stack start bob
```

```sh
printf 'Your name is Robert. Start every answer with the words: Robert speaking.\n' > ~/my-defs/bob/system.txt
```

```sh
aos-agent -t bob ask --timeout-s 120 "What is your name? One short sentence."
```

會看到 `Robert speaking. My name is Robert.`，**沒重開就生效**。因為每一輪都去讀定義夾的檔，aos 不另外抄一份。

**8. 用 set-def 換到另一個夾**

```sh
cp -r ~/my-defs/bob ~/my-defs/bob-v2 && printf 'Your name is Carol. Start every answer with the words: Carol here.\n' > ~/my-defs/bob-v2/system.txt
```

```sh
aos-agent ctl set-def bob ~/my-defs/bob-v2
```

```
no screen (already closed)
definition of bob is now /home/你/my-defs/bob-v2; it runs it now (stack /home/你/bob-stack kept)
```

約 1.2 秒，換了一個新 pid。再問名字，會看到 `Carol here. My name is Carol.`，它還自己補一句前兩次回答的 Bob、Robert 是錯的。這代表對話紀錄留著。

**9. 收掉**

```sh
aos-agent ctl rm bob
```

```
removed bob; stack /home/你/bob-stack kept (delete it with aos-agent ctl rm --purge, or by hand)
```

## 哪些檔要動、哪些別動

| 檔 | 要不要動 |
|---|---|
| `llm.json` | 常改（模型）。不改就是 sonnet |
| `system.txt` | 選配，範本沒附。要角色說明就自己建 |
| `cli.json` | 選配。`screen_close_after_s`、`print_flags` 的預算、`settings` 的 hook、`live_mail` 這類 |
| `tools.json`、`tools_sub.json`、`hooks.json` | 要增減工具、hook 才動。也可以不動檔，用 `aos-agent tools`／`hook` 改這一隻自己的那份 |
| `interfaces.json`、`_entry`、`loop.json`、`screen/`、`compact_hook`、`_metainfo.json` | 別動。`interfaces.json` 沒了就掛不上（見下） |

## 故意弄壞

**沒有 interfaces.json**：

```sh
aos-agent ctl set-def bob ~/my-defs/broken-noif
```

```
aos-agent: error: InterfaceMissing /home/你/my-defs/broken-noif does not declare the aos-agent interface (/home/你/my-defs/broken-noif has no interfaces.json); put interfaces.json at its top: {"aos-agent": {}}
```

退出碼 1，bob 不受影響。`ctl add` 也做同一個檢查。

**cli.json 的值錯了**，例如 `"screen_close_after_s": "soon"`：

```sh
aos-agent ctl set-def bob ~/my-defs/broken-cli
```

這一步回報成功（退出碼 0）。但過兩秒 `aos-daemon-ctl ls` 會看到：

```
bob	stopped	-	1	…	failed to start: exited within 3s of wake/start (code 1): aos-loop: error: RunFailed run 1: loop.json#/exec failed with exit code 1; restarted 3 times in a row, each exited within 3s; not restarting again
```

真正的原因要看 `tail ~/bob-stack/stderr.txt`：

```
aos-eca-turn: error: CfgBad /home/你/my-defs/broken-cli/cli.json: screen_close_after_s must be a non-negative integer
```

救法：先 `aos-agent ctl set-def bob ~/my-defs/bob-v2`，這時會看到 `it stays stopped; ctl start runs it`。再 `aos-agent ctl start bob`，會看到 `started (same stack); 0 queued letter(s) will be answered next`。

## 發現的問題

1. `set-def`／`add` 只檢查 `interfaces.json`，不檢查 `cli.json`。值錯了也照樣換上去，結果 agent 連倒三次，而表上的原因只寫 `RunFailed`，真正的 `CfgBad` 要自己去翻 `stderr.txt`。
2. 用絕對路徑 add，表上卻記成相對的 `../../bob-stack`，跟 `ctl add --help` 寫的不一樣。見 [01 的發現的問題](01-停daemon複製stack重開.md#發現的問題)。
3. 停著時 set-def 之後，`ls` 那一列的工作區欄顯示 `-`（`bob	stopped	-	-	-	-`），start 後才恢復。這條今天的[下午改動-獨立驗證](../下午改動-獨立驗證.md)也記過。
