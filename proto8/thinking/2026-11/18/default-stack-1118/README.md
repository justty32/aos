# 預設 stack 調查（11-18）：cd 到 agent 的夾裡能不能直接 say

← [2026-11-18](../README.md)

使用者 11-18 晚：「預設stack這個確實，派個標準調查流程去幫我想想。」（下午他說「這種cd過去的感覺挺好的，之後再來規劃吧」，原話全文見 [00](00-使用者原話.md)。）線 `default-stack-1118` 做，只調查與發想，沒改程式、沒排實作；實測在家機 repo 外的暫存樹（HEAD `01458f544`，`git archive` 取的，假腦）。

## 先講結論

1. **現況**：aos-agent 找 daemon 看 `-d` ＞ `AOS_DAEMON` ＞ cwd 的 `./.stack`，找對象看 `-t` ＞ `AOS_AGENT`，**都不看你站在哪隻的夾裡**。所以站在 `.stack/procs/ann/` 要打 `aos-agent -d ../.. -t ann say …`。「掛上時要指定 stack」今天本來就不用：`ctl add` 沒給 `-s` 就放 `<daemon stack>/procs/<名字>/`。
2. **最要緊的三個邊緣狀況**：兩個終端同時對同一隻說，兩句會合成一輪、兩邊拿到同一個回答（實測）；`ctl rm` 留下的、daemon 沒開的 stack，cd 進去看起來跟活的一樣；工具的小格、子 daemon、沙箱都在 agent 的 stack 或樹底下，「看 cwd 推對象」會讓工具對自己說、讓沙箱更容易摸到 daemon。
3. **七個樣子**：甲 維持現狀、乙 只改錯誤訊息、丙 一句「進去」（cd 過去＋設好兩個變數）、丁 stack 裡放一張相對路標（只看 cwd 一層、回表核對）、戊 像 git 一樣往上找、己 站在定義夾裡說、庚 不查表直接寫 `./queue/`。
4. **推薦丙＋乙**（規則一條不動，就是 11-04「命名空間」多一步 cd）；想要完全零設定再看丁。**由使用者拍板。**
5. **要使用者先說的一題**：「cd 過去」是 cd 到 agent 的 **stack**（他下午原話），還是 agent 的**定義夾**（頂層派工的寫法）？
