# 預設 stack 的現況：今天怎麼找 daemon、怎麼找 agent、stack 放哪

← [README](README.md)｜上一份：[00-使用者原話](00-使用者原話.md)｜下一份：[02-邊緣狀況](02-邊緣狀況.md)

## 先講結論

- 要跟一隻 agent 說話，aos-agent 要知道兩件事：**哪台 daemon**、**哪一隻**。兩件各自有固定的找法，**都不看你站在哪個 agent 的夾裡**。
- 哪台 daemon：`-d` ＞ `AOS_DAEMON` ＞ 目前資料夾裡的 `./.stack`（只看這一層、不往上找）。哪一隻：`-t` ＞ `AOS_AGENT`，沒有就報錯。
- 「預設 stack」其實今天有兩個，常被混在一起：
  1. **daemon 的 stack**：`aos-exec` 沒給 `--stack` 時放在工作區的 `.stack/`。起手範本的根就是這樣，所以樹根有 `.stack/`，站在樹根打 aos-agent 可以不帶 `-d`。
  2. **agent 的 stack**：`ctl add` 沒給 `-s` 時放在 `<daemon 的 stack>/procs/<名字>/`。所以「掛上時要指定 stack」今天本來就不用。
- 站在 agent 的 stack（`.stack/procs/ann/`）裡，最短要打 `aos-agent -d ../.. -t ann say …`；站在 agent 的定義夾（`agents/ann/`）裡，最短要打 `aos-agent -d ../../.stack -t ann say …`。這是今天的樣子，不是壞掉。

## 四個東西的關係（拿起手範本那棵樹講）

```
<樹>/                       ← 工作區（ws）；根 daemon 就在這裡起
├── env.sh
├── root/                   ← 根 daemon 的定義
├── agents/ann/             ← ann 的定義（原始碼；不改它）
└── .stack/                 ← 根 daemon 的 stack（daemon 的記憶體；procs_state.json＝那張表）
    └── procs/ann/          ← ann 的 stack（ann 的記憶體：queue/、history.jsonl、state.json…）
```

- 表上 ann 那一列記的是**相對 daemon stack 的路徑**：`"stack": "procs/ann"`、`"ws": ".."`、`"def": "../agents/ann"`（暫存樹實測讀出來的）。所以整棵樹搬家照樣對得上。
- 一份定義可以掛好幾隻：暫存樹裡 `ann` 和 `ann2` 都掛 `agents/ann`，各有自己的 stack。**定義 → agent 是一對多**，agent 的 stack → agent 是一對一。
- `say` 做的事：查表拿到那隻的 stack，往它的 `queue/` 丟一封信。agent 下一輪拿去答，回答寫進 `history.jsonl`。

## 程式在哪

- 找 daemon：`py/aos/daemon_ctl/table.py` 的 `find_daemon`，aos-agent 與 aos-daemon-ctl 共用。註解寫著「11-05 題 3」；N-63 把 `./.stack` 寫成 `AOS_DAEMON` 唯一一條退路、「轉絕對、不往上層找」（[N-63 實例](../../../../docs/NORMS/10-基礎設施-定義與工作區/07-hub-型環境變數與父子交代/02-N-63-實例-AOS_DAEMON與沒有AOS_HUB.md)）。
- 找哪一隻：`--target` ＞ `AOS_AGENT`（[aos-agent README](../../../../py/aos/apps/agent/README.md)「對象」那條）。11-04 設計時寫明「不比工作區（兩隻同工作區就猜不出來）」，要「cd 進去就能說」＝在殼裡 `export AOS_AGENT=bob` 或 `source using-aos-agent.sh bob`（[aos-agent 02](../../04/aos-agent/02-找-agent.md)）。
- 已經有一支「從 stack 反查是哪一隻」的：`aos-agent ctl who --stack S`。它查表、找 `stack` 欄包住 S 的那列（最深的那列）。它是給工具認「叫我的是哪隻」用的，但它**也要先知道 daemon**。
- `using-aos-agent.sh`：`AOS_DAEMON` 沒設就設成 `$PWD/.stack`。
- 定義的 `_entry` 寫成「把自己掛上 daemon」（11-05）：`aos-exec agents/ann`＝`aos-agent ctl add agents/ann`，找 daemon 照樣從 cwd 找。

## 暫存樹實測

在 repo 外 `~/.aos/scratch/default-stack-1118/`：`git archive` 取 HEAD `01458f544` 的 proto8、自己跑 `install.py`（`AOS_HOME` 指這份），抄 `templates/start-api` 成 `tree/`（假腦），起根 daemon 與 llm kernel，`ctl add` 掛 ann。跑完用 `aos-daemon-ctl shutdown` 兩台都關掉、確認行程不在。

| # | 站在哪 | 打什麼 | 結果 |
|---|---|---|---|
| 1 | `.stack/procs/ann/` | `aos-agent say hi` | `TargetMissing`（不知道對誰） |
| 2 | `.stack/procs/ann/` | `aos-agent -t ann say hi` | `DaemonMissing … no .stack folder in the cwd` |
| 3 | `.stack/procs/ann/` | `AOS_STACK=$PWD aos-agent -d ../.. ctl who` | 印 `ann`（給了 daemon，就反查得出是哪隻） |
| 4 | `agents/ann/`（定義夾） | `aos-agent -t ann say hi` | `DaemonMissing`（同 2） |
| 5 | `agents/ann/` | `aos-exec .` | `StateMissing …/agents/ann/.stack is not an aos-daemon stack`：aos-exec 先在 cwd 建了暫時的 `.stack/`，ctl add 找到它就當成 daemon；aos-exec 退出時把空的 `.stack/` 收掉（事後確認不在） |
| 6 | `agents/ann/` | `AOS_DAEMON=<樹>/.stack aos-exec .` | `InstanceExists ann is already on the daemon`（名字＝資料夾名，已經掛過） |
| 7 | 樹根 | 抄一份 `agents/bob`，`aos-exec agents/bob` | 掛上，印 `.stack/procs/bob`；之後 `-t bob ask` 有回答 |
| 8 | `.stack/procs/ann/` | `unset AOS_DAEMON; source using-aos-agent.sh ann; say hi` | `AOS_DAEMON` 被設成 `…/procs/ann/.stack`，`DaemonMissing daemon folder not found`（教學 02 只讀程式推出來的，這次實跑證實） |
| 9 | 樹根 | `ctl rm bob` 後 cd 進 `.stack/procs/bob/`，`-d ../.. -t bob say hi` | stack 還在、表上沒有：`InstanceMissing`；同名 `ctl add` 回來，`listen --last 1` 看得到舊對話 |
| 10 | 樹根 | 兩個殼同時 `ask`（from-A、from-B） | 兩封被同一輪收進去，假腦只答一則，**兩邊印出同一個回答**（見 02 第 1 條） |

另外教學 02 已在公司 WSL 實跑過的不再重跑：`AOS_DAEMON` 有設就不看 `./.stack`、`-d` 贏過 `AOS_DAEMON`、`source env.sh` 會清掉 `AOS_*`、`export AOS_DAEMON=$(realpath ../..) AOS_AGENT=ann` 之後到哪都能說。
