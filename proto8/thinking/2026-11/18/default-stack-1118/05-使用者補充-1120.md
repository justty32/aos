# 預設 stack：使用者 11-20 晚補的想法（逐字）——aos-agent 不指定 -t 時從 cwd 找對象，agent 不記自己在哪個 daemon 底下

← [README](README.md)｜上一份：[04-使用者裁定](04-使用者裁定.md)

## 使用者原話（11-20 晚，家機重建 `~/aos-home`、接上真模型之後；他說「幫我記一筆」）

「我還是想要一個方便的，我直接cd進~/aos-home/.stack/procs/ann，然後可以直接aos-agent say "你好"，也就是我不需要特別指定-d,-t，或許可以是-t沒指定的話，就默認找.stack或.，嘗試將其視爲agent的stack，成功的話，或許可以藉此找到daemon，也就是agent本身會記錄他在哪個daemon底下...如果是這樣的話，那說不定aos-agent的很多子指令都不需要再指定-d了...不對，當初就說最好是要用export AOS_DAEMON自行指定...所以aos-agent他還是不要記錄自己在哪個daemon下好了...所以-t這塊，如果沒有指定AOS_TARGET，那就是找./.stack，找不到，就再找./，看看符不符合目標。」

## 他這段話最後停在哪（照原話整理）

- 對象（`-t`）：沒給 `-t`、也沒設環境變數時，先把 `./.stack` 當成 agent 的 stack 試，不是就再試 `./`，「看看符不符合目標」。
- daemon（`-d`）：agent **不**記錄自己在哪個 daemon 底下；daemon 照舊由使用者 `export AOS_DAEMON` 自己指定。

## 註（記錄者加，不是使用者的話）

- 這跟 [04](04-使用者裁定.md) 11-18 暫定的丁（agent 的 stack 裡加路標、由 daemon 寫）方向相反：這次他說 agent 不要記。丁還算不算數他沒說，沒問。
- 原話寫的變數名是 `AOS_TARGET`；今天程式認的是 `AOS_AGENT`（[README](README.md) 結論 1）。要改名還是口誤，沒問。
- 只記錄，沒派線、沒改程式。
