## 結論

- 編譯線的稿（[04「編譯時怎麼知道事件」](../aos-pylib-plan-1120/04-函數-依賴與互動.md)）說它「只讀一張表，表怎麼來不管；本線改了格式，只要換『拿表』那一行」。**對得上**：本線給一個函式，回的就是它要的那張表，而且比今天多幾格。
- **有三處不一致要對**（最後一節）：表是「照身體」不是「照種類」、兩條線都會改 `agent_spec.py` 寫 loop.json 的那一段、編譯要多寫兩樣東西。都不是方向衝突，是誰先誰後與一個參數的事。
- 兩條線沒有互相等：本線第 1 刀做完，編譯線就能改用新函式；在那之前它照舊讀 `agentlib.hooks.EVENTS`。

## 編譯線能讀的

```python
from aos import hook_point

points = hook_point.read(paths)        # paths＝幾份 hook_points.json 的路徑；回 {點名: 點}；不對丟 hook_point.PointsBad
table  = hook_point.engine_table(points)   # {點名: {"condition": 欄位名或 None, "intercept": (鍵…), "block": bool}}
                                           # ＝今天 agentlib.hooks.EVENTS 的形狀，編譯線現在的三項檢查原樣可用
```

每個點（`points[名]`）多出來能用的格（全表見 [01](01-宣告格式.md)）：

| 格 | 編譯線可以拿來做什麼 |
|---|---|
| `fields`（事件帶的欄位名） | 它稿裡說「選了宣告式＝編譯時多一項能查：函數裡 `event["xxx"]` 的欄位在不在」 |
| `change`（能改的鍵與型別） | 函數回的 dict 若是字面值，鍵在不在可以編譯時就查（它目前寫「不在編譯時查」，可以照舊） |
| `block` | 它已經要用：有 `fn.block(` 而事件不能攔＝`SpecBad` |
| `phase` | 訊息可以寫得更準（「after_tool 是之後的事件，攔不了」） |
| `entry_keys` | `@fn.hook("on_clock", every_cycles=10)` 的額外關鍵字是不是這個事件收的 |
| `when` | `SpecBad` 列出可用事件時附一句說明 |

`on_clock` 專用鍵的值規則（恰好一個 `every_*`、正整數）仍在 `agentlib/hooks.py` 的 `validate_entry`，編譯線照它稿裡寫的「直接叫今天那支」。那支的簽名會多一個參數（要傳表），是唯一的呼叫點改動。

## 「這隻 agent 要讀哪幾份」：照身體，不是照種類

本線的表是聯集，哪幾份取決於身體（[01](01-宣告格式.md)）：

| `defs.Agent(...)` | 編譯時讀的宣告 |
|---|---|
| 有 `fsm=std.fsm()` | `aos-loop`、`agent-fsm` 兩個 `provider` |
| 有自己寫的 `fsm=` | `aos-loop` 那份；寫的人若有自己的宣告檔，用 `interfaces=` 或一個新參數給（留給編譯線定名字） |
| 沒有 `fsm`（eca 身體，只填現成定義） | 現成定義夾 `interfaces.json` 的 `hook_points`（讀得到就用它） |
| 以後的 `defs.Kernel(...)` | `py/tools/aos/kernel/hook_points.json` |

本線另給一個省事的函式，兩邊用同一份邏輯：

```python
hook_point.for_definition(def_folder)   # 讀那一夾 interfaces.json 的 hook_points，回 read() 的結果
```

## 編譯要多寫出的兩樣（屬於編譯線的檔，本線不碰）

| 東西 | 內容 | 不寫的後果 |
|---|---|---|
| `interfaces.json` 的 `hook_points` | 上表那幾份：aos 自己帶的寫 `{"provider": 名字}`，寫的人自己的寫相對路徑（[01](01-宣告格式.md)） | 這隻 agent 一個 hook 都掛不上（`HooksBad`） |
| `loop.json` 的接線 | `on_start`／`on_stop` 改叫 `aos-hook fire`（取代 `agent_spec.py:44` 的 `HOOK_FIRE`）；多 `on_before_run`、`on_after_run` 與兩個 `_if`（[06](06-loop層的點.md)） | 起停事件不發；loop 層的兩個點沒有 |

## 函數 hook 的回話記號

編譯線定的三種（`return None`／`return {鍵: 值}`／`return fn.block("原因")`）跟本線**沒有衝突**：handler 的契約不變，`fn.block` 退 10 在「不能攔」的點會被引擎當成 0（今天就是）——它要在編譯時擋，用 `block` 那一格就夠。

新的 loop 層兩個點對函數 hook 的意思：

```python
@fn.hook("before_run", condition="act")     # 每次要跑 act 這格之前（before_run 才收 condition；after_run 不收）
def quiet_hours(event):
    if night():
        return fn.block("quiet hours")      # 跳過這一圈
```

成本是每圈一支 Python（[06](06-loop層的點.md) 量的 18 毫秒起跳，加函數自己的 15 毫秒）。

## 跟編譯線的稿對過，不一致的三處（帶給頂層）

| # | 編譯線的稿 | 本線 | 怎麼對 |
|---|---|---|---|
| 1 | 每種東西一個類別屬性 `events`（一張表）：「`defs.Agent` 用 agent 那張（今天九種）」 | 表照身體算，同是 `defs.Agent`，有沒有 `fsm` 讀的宣告不同 | `events` 從類別屬性改成一個方法（依這個物件的 `fsm` 決定讀哪幾份）；它的三項檢查不變。**需要編譯線改一句設計**。 |
| 2 | 它的去留表沒提 loop.json 的 on_start／on_stop | 本線第 3、5 刀要改 `agent_spec.py` 寫 loop.json 的那段 | 同一個檔兩條線都動：誰先施工誰改，後到的照著接。建議 `agent_spec.py` 這一段由**後開工的那條線**帶，另一條只在計劃裡記「要接」。 |
| 3 | 它說 D5 選了才「編譯就能警告」 | 本線對 D5 給了設計預設「要」，而且是**擋**（`SpecBad`），不是警告 | 等使用者裁第 5 題（[10](10-待裁題.md)）；在那之前編譯線照它現在的寫法（只查名字在不在表上）不會錯。 |
