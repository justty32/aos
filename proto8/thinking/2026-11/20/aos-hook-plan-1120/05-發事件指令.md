設計之五：讓 C++、shell 寫的子程式也能提供點的那支「發事件」指令 `aos-hook`——參數、stdin／stdout、結束碼、怎麼找宣告與清單、失敗怎麼報；C++ 與 shell 的用法；跟 `hook_fire` 的關係。

← [04](04-小函式.md)｜下一份 [06 loop 層的點](06-loop層的點.md)

指令名與旗標是設計稿，沒寫成程式。

## 結論

- 新指令 **`aos-hook`**（Python，`py/aos/apps/hook/`，包 [04](04-小函式.md) 的小庫）。最常用的是 `aos-hook fire`：**事件資料從 stdin 或旗標進，結果一行 JSON 從 stdout 出，結束碼 0／10／1**。
- 非 Python 的子程式提供一個點＝放一份 `hook_points.json`＋在那個時機起一次 `aos-hook fire`。
- **`hook_fire` 整支拿掉，由 `aos-hook fire` 取代**（不並存：proto8 當成沒有舊版）。六份範本的 `loop.json` 跟著改。已經在跑的定義夾會受影響，是 [07](07-對照與衝突.md) 衝突第 1 條。
- 代價照他選的選項說明：每次發事件多起一個行程，實測約 18 毫秒（Python 起來加 import），有 handler 時再加 handler 自己的（[06](06-loop層的點.md) 的數字）。Python 的提供者不用它，直接 import 小庫，沒有這筆。

## 子指令

| 子指令 | 做什麼 |
|---|---|
| `aos-hook fire [旗標] EVENT` | 發一個事件 |
| `aos-hook points [旗標] [--json]` | 列出有哪些點（名字、之前／之後、欄位、能改什麼、能不能攔）；`aos-agent hook events`、`self_hook` 的 `events` 用同一段程式 |
| `aos-hook check [旗標]` | 只驗：宣告讀不讀得過、清單裡每一格掛的事件在不在、鍵對不對；不跑任何 handler |

## 怎麼找到宣告與清單（三支子指令共用的旗標）

| 旗標 | 意思 |
|---|---|
| `--points FILE`（可重複） | 一份宣告 |
| `--list FILE`（可重複） | 一份清單：有 `hooks` 表的 JSON 檔（agent 的 `hooks.json`、kernel 的 `kernel.json` 都是這個形狀）；後面的蓋前面的，`null`＝關掉 |
| `--agent DEF_DIR` | 一次給齊 agent 的那一套：宣告＝定義夾 `interfaces.json` 的 `hook_points`，清單＝定義那份疊 stack 那份；順便做 agent 一家自己的事（after_start 先清 on_clock 的狀態、驗 on_clock 專用的鍵）。跟 `--points`／`--list` 二選一 |
| `--stack DIR` | handler 的小格放哪（`DIR/hooks/<名>/`）；不給＝`$AOS_STACK`；都沒有＝`StackMissing` |

## `fire` 的進出

| 項 | 規矩 |
|---|---|
| 事件資料 | stdin 給一個 JSON 物件（空的或沒接＝`{}`）；宣告裡寫了 `env` 的欄位：那個環境變數**有設而且不是空字串**才用它（`int` 型別轉成整數，轉不了＝`ArgumentsBad`），否則留 stdin 給的，都沒有＝null；`--field NAME=VALUE`（字串）、`--field-file NAME=PATH`（讀檔、去頭尾空白，檔不在＝null）、`--field-default NAME=VALUE`（前面都沒給出值時才用）。同名時後者蓋前者：stdin → env → 旗標 |
| stdout | 一行 JSON：`{"data": {...}, "changed": [...], "blocked": false, "hook": null, "text": ""}`（就是小庫 `fire` 的回值）；`-q`＝不印（只看結束碼的人用，例 loop.json） |
| 結束碼 | **0**＝照常（沒人掛也是 0）；**10**＝被攔下（只有宣告 `block: true` 的點會）；**1**＝錯 |
| 錯 | stderr 一行 `aos-hook: error: CODE reason`，stdout 不印。`CODE`：`HookFailed`（`on_error: stop` 的 hook 自己失敗）、`HooksBad`（清單壞）、`PointsBad`（宣告壞）、`EventUnknown`（宣告裡沒有這個點）、`ArgumentsBad`、`StackMissing` |
| 警告 | `on_error: continue` 的 hook 失敗＝stderr 一行 `aos-hook: warning: …`，照常退 0 |
| handler 的 stderr | 原樣透出（引擎照舊不攔） |
| `--help` | 英文用法印 stdout、退 0 |

結束碼跟掛 hook 那一方同一套意思（N-43：10＝「不要」，不是錯），所以一支只看結束碼的程式也用得起來。

## 用法示意

shell 寫的子程式（存檔前給人攔、給人改檔名）：

```sh
# hook_points.json 宣告了 before_save：fields {"file": …}，change {"file": "nonempty_string"}，block true
out=$(aos-hook fire --points "$HERE/hook_points.json" --list "$HERE/config.json" --stack "$STATE" \
        --field file="$f" before_save)
case $? in
  0)  f=$(printf '%s' "$out" | jq -r .data.file) ;;            # 改過的值拿回來（解 JSON 用手邊有的工具）
  10) echo "save skipped by a hook" >&2; exit 0 ;;             # 被攔下在我這裡的意思：不存
  *)  exit 1 ;;                                                # 錯誤行 aos-hook 已經印了
esac
```

C++ 寫的子程式（不用 link 任何 hook 的東西，就是起一支程式）：

```cpp
// 用 aos-loop 公開的 run_once 跑一張單子；事件資料走 --field，只看結束碼
aos::loop::Run r = aos::loop::run_once(target({"aos-hook", "fire", "-q", "--points", here + "/hook_points.json",
                                               "--list", cfg_path, "--field", "job=" + job, "before_job"}));
if (r.code == 10) { /* 被攔下：跳過這件工作 */ }
else if (r.code != 0) { /* aos-hook 已印錯誤行；照自己的慣例收尾 */ }
```

只要結果不要改值的最省事：一律 `-q`、只看結束碼。aos-loop 自己連這段都不用寫——它只是照 loop.json 跑被指定的東西（[06](06-loop層的點.md)）。

`loop.json` 裡的寫法（取代現在指到 `hook_fire/_entry` 的兩格）：

```json
"on_start": {"argv": ["aos-hook", "fire", "-q", "--agent", {"$env": "AOS_CD"}, "after_start"]},
"on_stop":  {"argv": ["aos-hook", "fire", "-q", "--agent", {"$env": "AOS_CD"}, "after_stop"]}
```

`code`、`signal`、`cause` 不用寫在 argv：宣告說了它們從 `AOS_LOOP_CODE`、`AOS_LOOP_SIGNAL`、`AOS_LOOP_CAUSE` 取（[02](02-現有的點改寫成宣告.md)）。

## 跟 `hook_fire` 對照

| | `hook_fire`（現在） | `aos-hook fire`（之後） |
|---|---|---|
| 認得的事件 | 寫死 after_start、after_stop | 宣告裡有的都行 |
| 誰能用 | agent 的 loop.json | 任何子程式 |
| 清單 | 只會讀 agent 的 | `--agent`，或 `--list` 任何有 `hooks` 表的檔 |
| after_start 先清 on_clock 狀態 | 有 | 有（`--agent` 時） |
| 失敗 | `hook_fire: error: …` 退 1，aos-loop 當一行 warning | `aos-hook: error: …` 退 1；aos-loop 怎麼看照各格的規矩（[06](06-loop層的點.md)） |
| 位置 | `py/tools/agent/hook_fire/`（工具夾，但不是給腦叫的） | `py/aos/apps/hook/`（指令） |

## 邊緣

- **事件很大**（整份 prompt 那種）：stdin 進一次、寫進 `event.json` 一次、再從 stdin 給 handler 一次。跟現在引擎的做法相同，沒有變好也沒有變壞。
- **`--field` 只能給字串**：要給數字、物件就走 stdin 的 JSON。宣告裡 `type: int` 的欄位，`--field` 給的字串會轉。
- **誰都能發事件**：`aos-hook fire --agent 別人的定義夾 --stack 別人的stack before_tool` 起得來，等於替別的 agent 跑它的 hook。這不是新洞（今天直接 import `agentlib.hooks` 就能做同一件事；全部 agent 同一個 Linux 帳號），只是變得好打。不加擋。
- **handler 裡再叫 `aos-hook fire`**＝連鎖觸發，不檢測，風險自擔（C-90 已定）。
- **宣告與清單對不上**（清單裡掛了宣告沒有的事件）：`fire` 當場 `HooksBad`、退 1，跟現在格程式讀到壞清單時一樣。
