## 先看分法

現在是「agent 一張表九種、kernel 一張表三種」。改成照**發事件的程式**分：

| 檔（放在提供者自己的夾裡） | 提供者 | 點 |
|---|---|---|
| `py/aos/apps/hook/loop_points.json` | 用 aos-loop 跑、而且 loop.json 有接線的任何子程式 | after_start、after_stop（原有）、before_run、after_run（新，見 [06](06-loop層的點.md)） |
| `templates/agent-fsm/hook_points.json` | agent-fsm 的四格 | before_queue、after_queue、before_tool、after_tool、brain_failed、tool_added、on_clock |
| `py/aos/apps/eca/hook_points.json` | aos-eca-turn | before_queue、after_queue、brain_failed、tool_added、on_clock |
| `py/aos/apps/mcp/hook_points.json` | aos-mcp | before_tool、after_tool |
| `py/tools/aos/kernel/hook_points.json` | 通用 kernel 框架 | before_verdict、after_verdict、before_reply |

- 九種照舊九個名字，一個都沒改名、沒拿掉；只是 after_start、after_stop 歸到 loop 那份（它們本來就是 aos-loop 的 `on_start`／`on_stop` 發的）。
- fsm 與 eca **各寫各的 `when` 與欄位**。調查線查到的「同名不同義 5 種」因此各自白紙黑字；要不要進一步統一或分名仍是待裁題（[10](10-待裁題.md) 第 3 題），這份設計不替他選。
- 起手範本裡整夾抄的 agent-fsm（`templates/start-api/agents/ann/`）跟著多一份同樣的檔，照舊由 `templates/tests/test_start.py` 比對。

下面的 JSON 為了一頁放得下，每個點壓成一行；`when`、欄位說明是草稿，施工時逐一對程式核對。

## loop 那份（`loop_points.json`）

```json
{"description": "Hook points of anything run by aos-loop whose loop.json wires them to aos-hook fire.",
 "provider": "aos-loop",
 "points": {
  "after_start": {"when": "the loop started, before the first run", "phase": "after", "fields": {}, "fired_in": []},
  "before_run": {"when": "before each run of the loop body", "phase": "before", "condition": "stage", "subject": "stage", "block": true,
    "if_blocked": "the loop skips this run: the body does not run, the run is not counted, after_run does not fire; the loop asks again after interval_ms",
    "fields": {"counter_runs": {"about": "which run this will be (from 1)", "env": "AOS_LOOP_RUNS", "type": "int"},
               "stage": "fsm bodies only: the state about to run (the table's start state on the first run); null for bodies without states"}},
  "after_run": {"when": "after each run of the loop body, whatever its exit code (not when the body could not start)", "phase": "after",
    "fields": {"counter_runs": {"about": "which run this was", "env": "AOS_LOOP_RUNS", "type": "int"},
               "code": {"about": "the body's exit code", "env": "AOS_LOOP_RUN_CODE", "type": "int"},
               "signal": {"about": "the signal that ended the body, or null", "env": "AOS_LOOP_RUN_SIGNAL", "type": "int"},
               "elapsed_ms": {"about": "how long the body ran", "env": "AOS_LOOP_RUN_MS", "type": "int"},
               "next_stage": "fsm bodies only: the state the table is at now (the next one after a taken step, the same one otherwise); null for bodies without states"}},
  "after_stop": {"when": "the loop is about to exit", "phase": "after",
    "fields": {"code": {"about": "the code the loop exits with", "env": "AOS_LOOP_CODE", "type": "int"},
               "signal": {"about": "the signal it got, or null", "env": "AOS_LOOP_SIGNAL", "type": "int"},
               "cause": {"about": "stop, sleep, remove, shutdown, stuck, signal, max, body_exit or error; null when unknown", "env": "AOS_LOOP_CAUSE", "type": "string"}}}}}
```

## agent-fsm 那份

```json
{"description": "Hook points fired by the agent-fsm cells.", "provider": "agent-fsm",
 "points": {
  "before_queue": {"when": "idle: a good letter is about to enter the conversation (/compact letters do not pass here)", "phase": "before",
    "fields": {"letter": "letter name", "content": "the text that will enter the conversation"},
    "change": {"content": "nonempty_string"}, "block": true, "key": "letter",
    "if_blocked": "the letter is closed and dropped; mailbox_warning.txt says which hook dropped it", "fired_in": ["idle.py"]},
  "after_queue": {"when": "idle: the letter is in history.jsonl and closed", "phase": "after",
    "fields": {"letter": "letter name", "content": "the text that entered"}, "fired_in": ["idle.py"]},
  "before_tool": {"when": "act: before each tool call runs (every tool)", "phase": "before",
    "fields": {"name": "tool name", "id": "tool call id", "arguments": "the JSON object the tool will get"},
    "condition": "name", "subject": "tool", "change": {"arguments": "object"}, "block": true, "key": "id",
    "if_blocked": "the tool does not run; the brain gets the hook's stdout (or a default line) as the tool result", "fired_in": ["act.py"]},
  "after_tool": {"when": "act: a tool finished, before the brain sees its result", "phase": "after",
    "fields": {"name": "tool name", "id": "tool call id", "arguments": "what the tool got", "content": "the result text",
               "code": "the tool's exit code, null when it timed out", "timed_out": "true or false"},
    "condition": "name", "subject": "tool", "change": {"content": "string"}, "fired_in": ["act.py"]},

    "fields": {"name": "error code: LlmKernelMissing, SendFailed, BudgetMissing, BrainFailed or ReplyBad", "reason": "one sentence",
               "error": "the kernel's error object, when there is one", "retry": "optional", "wait_s": "optional", "attempt": "optional"},
    "condition": "name", "subject": "code", "fired_in": ["wait.py"]},
  "tool_added": {"when": "think: a tool name appeared in the tool box since the last request", "phase": "after",
    "fields": {"name": "tool name", "path": "where it is"}, "condition": "name", "subject": "tool", "fired_in": ["brain.py"]},

    "fields": {"clock": "clock file", "cycle": "its number now", "interval_ms": "ms per cycle", "first": "true right after start",
```

## eca 那份與 mcp 那份（只列跟 fsm 不同的地方）

| 點 | 檔 | 跟 fsm 那份不同的字 |
|---|---|---|
| before_queue | eca | `when`: "turn: every good letter, slash letters too; also letters that arrive while waiting for the answer" |
| after_queue | eca | `when`: "the letter was handed to the CLI and joined history; a failing hook is reported only after the answer is in history" |
| brain_failed | eca | `fields.name`: "CliFailed or ReplyMissing"；多 `code`、`retry`、`attempt`、`dropped`、`wait_s`、`status`、`cause`（claude 才有） |
| tool_added | eca | `when`: "turn: before each handoff to the CLI" |
| on_clock | eca | `when`: "start of every turn" |
| before_tool | mcp | `when`: "before an aos tool called through aos-mcp runs (the CLI's own tools do not pass here)"；`if_blocked`: "the tool does not run; the CLI gets the hook's stdout (or a default line) as the result" |
| after_tool | mcp | `when`: "an aos tool called through aos-mcp finished"；`fields.content`: "all text parts joined into one" |

`phase`、`condition`、`change`、`block`、`key` 跟 fsm 那份逐項相同（[01](01-宣告格式.md) 驗證第 5 條要求的）。mcp 的「hook 失敗只算那次工具呼叫錯」是失敗時的報法，不在宣告裡，寫在 [04](04-小函式.md) 的對照表。

## kernel 那份

```json
{"description": "Hook points of the generic kernel framework.", "provider": "kernel",
 "points": {
  "before_verdict": {"when": "a request letter is about to be judged", "phase": "before",
    "fields": {"letter": "letter name", "sender": "who sent it", "sent_at": "when", "reply_to": "where the answer goes", "body": "the request"},
    "change": {"body": "any"}, "block": true, "key": "letter", "if_blocked": "the letter is refused (HookRejected, or BudgetMissing when the hook says so)"},
  "after_verdict": {"when": "the station judged the letter; fired hook by hook", "phase": "after",
    "fields": {"letter": "…", "sender": "…", "sent_at": "…", "reply_to": "…", "body": "…", "verdict": "pass, refuse or hold",
               "error": "the refusal, or null", "decision": "stations that can hold: pass when someone already said so", "next": "stations that forward: the next mailbox, or null"},
    "condition": "verdict", "subject": "verdict", "change": {"verdict": "string", "error": "any", "next": "any"}, "block": true, "key": "letter",
    "if_blocked": "the letter is refused"},
  "before_reply": {"when": "a reply passes this station (only with reply_via_me)", "phase": "before",
    "fields": {"letter": "…", "sender": "…", "reply_to": "…", "reply_sender": "who answered", "body": "the reply"},
    "change": {"body": "any"}, "block": true, "key": "letter", "if_blocked": "the reply is not applied (HookRejected)"}}}
```

`after_verdict` 是「之後」卻能攔，照實寫（判決出來了、還沒照做，所以攔得住）。[01](01-宣告格式.md) 的驗證不擋這種組合；`phase` 只給 gdb 分扣住或暫停用，kernel 沒有 gdb。

## 兩個小地方

- `after_run` 不收 `condition`、欄位叫 `next_stage` 不叫 `stage`：身體跑完時 aos-fsm 已經把格換掉了，拿「下一格」去比掛的人心裡想的「剛跑完那一格」會比錯。要「act 跑完之後」就掛 `before_run` 配下一格，或在 handler 裡自己看 `code`。
- loop 那份的點沒有 `fired_in`（發它們的是 loop.json 的接線，不是哪支原始檔）：測試改成檢查各範本的 loop.json 有接這四個點。
