## 要帶給使用者的衝突

### 1　「proto8 當成沒有舊版」對上「已經在跑的定義夾」

- **已定的**：proto8 一律當成沒有舊版，不寫遷移、不留舊名。
- **衝突在哪**：這份設計拿掉三樣舊東西——`hook_fire` 那支小程式（loop.json 寫死它的路徑）、`agentlib.hooks` 的舊函式（整夾抄走的格程式會叫）、「沒寫 `hook_points` 就當九種」的行為。公司 WSL 活樹與家機裡**已經編譯好、正在用的定義夾**（各 eca、小廝、kernel 底下的 sol）裝了新版之後：
  - loop.json 還指著 `hook_fire`：起停時只多一行 warning，after_start／after_stop 的 hook **靜靜不再觸發**，on_clock 也不再「起來先跑一次」。
  - `interfaces.json` 沒有 `hook_points` 而清單裡有 hook（例 `brain_notify`、`context_wrap`）：第一格就 `HooksBad`、那隻停下。
  - 用 `std.fsm()` 編譯的（格程式執行時指回 `$AOS_HOME/templates/agent-fsm/`）：格程式自動是新的，但 loop.json、interfaces.json 是編譯當時寫的，一樣要重新編譯。
- **各自的後果**：
  - 照規矩不留舊的：裝新版那一刻，所有舊定義要**重新編譯或手改兩個檔**；要先盤點活樹有哪些定義夾，跟 `install.py` 排在同一個時段做。
  - 破例留一段過渡（`hook_fire` 留一個只會轉叫 `aos-hook` 的殼、沒寫 `hook_points` 先當九種）：舊定義不壞，但違反「不留舊名」，而且要另外記得哪天拿掉。

### 2　loop 層的點能「攔」、失敗會「停」，對上 11-11 定的「起停兩格只當 warning」

- **已定的**：11-11 加 `on_start`／`on_stop` 時定的是「退非 0、逾時、起不來＝一行 warning，不改結束碼、不擋起跑」（aos-loop README）；C-52 講 loop 只管自己。
- **衝突在哪**：`on_before_run` 退 10 就跳過這一圈、退其他碼就收工——這是 aos-loop 第一次**照一支旁邊程式的結束碼決定身體跑不跑**。同一層的 after_start 失敗只警告，新的兩個點失敗會停，兩種行為並存。
- **各自的後果**：
  - 照設計（能攔、失敗就停）：符合 C-90「hook 預設能改結果、失敗預設跟著停」；gdb 能扣在任何一格；但一支寫壞的 `before_run` hook 能讓 agent 永遠空轉或停下。
  - 照 11-11 的老規矩（只通知、失敗只警告）：aos-loop 最單純；但 `before_run` 就不是真的「之前」——攔不了、守門的 hook 壞了身體照跑。
  - 兩題都在 [10](10-待裁題.md)（第 1、2 題）。

### 3　宣告把「誰會發哪些事件」定下來，對上「eca 給縮水版」的現況寫法

- **已定的**：C-90 寫「事件清單見 aos-agent docs/06-hook」「eca 給縮水版」；現在 fsm 與 eca 共用一張九種的表。
- **衝突在哪**：照設計，掛到「這隻身體不會發」的事件會**當場被擋**（現在掛得上、永遠不跑、不報錯）。今天 fsm 與 eca 兩種身體算出來的聯集剛好是同樣九個名字，所以**眼前沒有人會被擋**；會被擋的是自己寫格程式的 agent（只剩 loop 那四個點）與以後只加在一種身體的新點。同名的 before_tool 在 fsm 與 mcp 各有一段說明。行為更誠實，但等於用程式把「縮水版」定成「各身體各自一份清單」；C-90 那句「事件清單見…」要不要改指到宣告，是條文的字，要他點頭。
- **各自的後果**：改條文的字＝條文與程式一致；不改＝條文還指著一份手寫的表（那份表仍在、有測試比對，不算錯）。同名不同義要不要更進一步（統一或分名）是 [10](10-待裁題.md) 第 3 題。

### 4　kernel 的表搬成宣告檔，對上「自訂 kernel 先不定，讓它自然長」

- **已定的**：11-19「自訂 kernel 的形式先不定，讓它自然長」；11-14「太早規劃反而會限制到很多可能性」。
- **衝突在哪**：他今天選了「任何子程式，含非 Python」，kernel 當然在內；但把 kernel 三個點寫成一份有固定格式的檔，就是替「kernel 怎麼提供點」定了一個樣子。另外，loop 層的點讓 kernel **不改程式、只改 loop.json** 就有「每輪一次」的時機——昨天 aos-htop 實測卡住的那一點有了路，但走不走是 kernel 那條線的事。
- **各自的後果**：kernel 跟著搬＝全家一種格式，編譯線之後要驗 kernel 的 hook 有對的表可讀；kernel 先不搬＝這份設計的其他部分照做不受影響（kernel 那一刀獨立，[09](09-施工計劃.md)），kernel 繼續自己一張寫死的表。

### 5　「hook不用動」底下的兩個小變化

- **已定的**：11-19「hook不用動」。
- **衝突在哪**：掛的契約沒動，但掛的人**看得見**兩處變化：`self_hook` 的工具說明不再列出九個事件（改成先 `{"op": "events"}` 問），腦多一步才知道有哪些事件；`a.bp.add.<種類>` 的種類從「全體九種」變成「這隻 agent 自己的聯集」（今天 fsm 與 eca 的聯集相同，眼前的差別只有多了 `before_run`、`after_run`；自己寫格程式的 agent 會少）。
- **各自的後果**：照設計＝清單不會再漂移、不會再掛到不會發的事件；要原樣不變＝`self_hook` 的說明繼續手抄（靠測試比對），gdb 種類照舊全體一份。

### 6　零成本的旗標檔，對上 KISS（C-56）

- **已定的**：C-56「不為了邊緣狀況加機制」「寫什麼就做什麼」。
- **衝突在哪**：為了「沒人掛時不多起行程」，loop.json 多兩個 `_if` 鍵、stack 多兩個旗標檔、每個會改清單的指令都要順手對一次旗標。它不是為邊緣狀況（沒人掛是最常見的狀況），但確實是多出來的機制，而且手改清單的人要重起或跑一次 `aos-hook check --agent` 才生效。
- **各自的後果**：要旗標＝沒人掛時零成本；不要＝機制最少，但每隻 agent 每圈固定多約 36 ms（閒著的 agent 每秒約多 6 個行程），等於所有人替少數掛的人付錢。
