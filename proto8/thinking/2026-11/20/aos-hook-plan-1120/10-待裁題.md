## 會擋住施工的

### 第 1 題　`before_run` 的 hook 能不能把這一圈攔下來？（擋第 5 刀）

| 選項 | 後果 |
|---|---|
| 能攔：hook 退 10＝這一圈不跑身體（設計預設） | 可以做「安靜時段」「額度不夠先別跑」；gdb 能扣在任何一格之前。寫壞的 hook 能讓 agent 一直空轉，表上只看得到 waiting |
| 不能攔：只通知 | aos-loop 最單純，跟 11-11 的起停兩格同一種；`before_run` 只能看、不能擋，gdb 仍能扣住（扣住不靠攔） |

### 第 2 題　loop 層的 hook 自己失敗時，agent 停不停？（擋第 5 刀）

| 選項 | 後果 |
|---|---|
| 新的兩個點跟著停，起停兩個照舊只警告（設計預設） | 新點符合「hook 失敗預設跟著停」；同一層兩種行為並存 |
| 四個點都只警告 | 跟 11-11 定的一致；守門用的 `before_run` hook 壞了，身體照跑 |
| 四個點都跟著停 | 全體一致；after_start 的 hook 壞了 agent 就起不來，改了 11-11 定的行為 |

### 第 5 題　掛到「這隻 agent 不會發」的事件上，要怎樣？（擋第 3 刀；調查線的 D5）

| 選項 | 後果 |
|---|---|
| 當場擋下（設計預設） | `hook add`、`self_hook`、編譯都報錯並列出這隻有的事件；eca 掛 fsm 才有的事件不再靜靜不跑 |
| 掛得上，但給一行警告 | 不擋人；警告容易被略過 |
| 照舊不管 | 掛得上、永遠不跑、不報錯 |

### 第 6 題　gdb 怎麼知道一個事件要「扣住」還是「暫停」？（擋第 6 刀；D7）

| 選項 | 後果 |
|---|---|
| 從宣告讀（設計預設） | 新點自動對；斷點種類變成每隻 agent 自己有的那些 |
| 照名字猜（`before_` 開頭＝扣住） | 不用讀宣告；名字取得不照慣例就猜錯 |
| 照舊手改那三處，加一支測試提醒 | 最小改動；靠人記得 |

### 第 10 題　已經編譯好、正在用的舊定義夾怎麼辦？（擋第 3、5 刀；[07](07-對照與衝突.md) 衝突 1）

| 選項 | 後果 |
|---|---|
| 照規矩不留舊的：裝新版時把舊定義一起重新編譯或手改 | 乾淨；要先盤點兩台機器上所有定義夾，跟 `install.py` 排同一個時段，漏掉的那隻會停下或起停事件靜靜不發 |
| 留一段過渡：舊寫法先照樣能跑 | 舊定義不壞；違反「不留舊名」，要另外記得哪天拿掉 |

### 第 11 題　「沒人掛時零成本」要不要用旗標檔做？（擋第 5 刀；衝突 6）

| 選項 | 後果 |
|---|---|
| 要（設計預設） | 沒人掛時每圈約 2 微秒；多兩個 loop.json 的鍵、兩個旗標檔；手改清單的要重起或跑一次 `aos-hook check --agent` 才生效 |
| 不要，每圈都起指令去看 | 機制最少；每隻 agent 每圈固定多約 36 毫秒（閒著時每秒約多 6 個行程） |
| 不要，改成編譯時決定接不接線 | 沒人掛的 agent 完全沒這兩格；執行中用 `self_hook` 新掛的要重起才生效 |

### 第 12 題　loop 層兩個點叫什麼？（擋第 5 刀）

| 選項 | 後果 |
|---|---|
| `before_run`／`after_run`（設計預設） | 跟 aos-loop 自己的用詞一致（`counter_runs`、log 的 run N）；「run」可能被讀成「agent 起來」 |
| `before_loop`／`after_loop` | 貼你早上的話「每次loop」；可能被讀成「整個 loop 開始、結束」 |
| `before_cycle`／`after_cycle` | 白話；但 on_clock 的 `cycle` 指的是時鐘格數，兩個 cycle 不同義 |

### 第 14 題　kernel 的三個點要不要一起搬成宣告檔？（擋第 3 刀的 kernel 那一段；衝突 4）

| 選項 | 後果 |
|---|---|
| 一起搬（設計預設） | 全家一種格式；之後編譯 kernel 時有對的表可驗 |
| kernel 先不動 | kernel 繼續自己一張寫死的表；其他部分照做 |

## 不擋施工的

### 第 3 題　fsm 與 eca 同一個事件名意思不同，要怎樣？（D6）

| 選項 | 後果 |
|---|---|
| 各自寫清楚就好（設計已做到：各身體一份宣告） | 不改行為、不改名 |
| 能統一的統一 | 逐項改 fsm 或 eca（例：`/compact` 信過不過 before_queue）；CLI 自己的工具統一不了。多一刀 |
| 不同的分名（例：eca 的叫 `before_mcp_tool`） | 名字變多；已經掛著的清單要重寫。多一刀 |

### 第 4 題　事件帶哪些欄位，要不要以宣告為唯一來源？（D4）

| 選項 | 後果 |
|---|---|
| 要（設計預設） | `self_hook` 的說明不再列事件，腦先問 `{"op": "events"}`；文件與知識庫有測試比對，不會再各說各的 |
| 宣告照寫，但 `self_hook` 的說明照舊手抄 | 腦不用多問一步；手抄那份靠測試比對防漏 |
| 不要 | 宣告只留三格；欄位照舊各處手寫 |

### 第 7 題　kernel 要不要現在就接上 loop 層的點，得到「每輪一次」的時機？（D8）

| 選項 | 後果 |
|---|---|
| 接：改 procs-kernel 範本的 loop.json | 昨天 aos-htop 卡住的那一點有解，不改 kernel 程式；等於替 kernel 多定了一件事 |
| 先不接，等 kernel 那條線 | 不動；要的人自己在 loop.json 加四行就有 |

### 第 8 題　調查線查到的兩個小問題要不要派線？（D9）

| 選項 | 後果 |
|---|---|
| 派線：補文件漂移＋查證 eca 的 slash 信是不是過兩次 before_queue | 小工作；第二點若屬實再問修不修 |
| 只補文件 | 第 1 刀的測試本來就會逼著補；第二點照舊不確定 |
| 先不管 | 照舊 |

### 第 9 題　每個 hook 都另起行程，要不要現在就想更省的做法？（D10）

| 選項 | 後果 |
|---|---|
| 先不想，照量到的數字走 | 有人掛的點每次約 18 毫秒起跳；慢了再說 |
| 現在一起想（常駐一支、或同行程叫函數） | 跟編譯線的「函數當 hook」併著設計；會動到「handler＝一支程式」的契約 |

### 第 13 題　要不要為「提供 hook 點」立條文、改 C-90 那一句？（擋第 7 刀的條文部分；衝突 3）

| 選項 | 後果 |
|---|---|
| 立一條規範（宣告要寫什麼、之前型才能攔…），C-90 的「事件清單見…」改指宣告 | 條文與程式一致；條文的字要你過目 |
| 不立條文，只寫進程式文件 | 條文不動；規矩只在 `06-hook.md` 與小庫的檔頭 |
