## 結論

- 新增一支最底層的小庫 **`py/aos/hook_point.py`**（跟引擎 `hook_run.py` 同層，只用標準庫＋引擎）：讀宣告、驗、開一個「發事件的把手」。任何 Python 子程式提供點＝**開一次把手，之後每個點一行**。
- **各程式報錯的方式不統一**（fsm 退 1、eca 丟 `Fail`、mcp 回 isError、kernel `ctx.die`）——那是各程式自己的錯誤慣例，本來就該不同。統一的是**寫在哪**：開把手時給一個 `fail=`，之後不用每個呼叫點再包一層 try。
- agent 一家共用的三段（丟信三步、工具被攔的預設字、tool_added 那串）收進 `py/aos/agentlib/hooks.py` 的把手，fsm 與 eca／mcp 叫同一個函式。
- 行為不變：現有的 hook 測試照跑、照綠，是這一刀的驗收條件。

## 全新的 Python 子程式提供一個點：五行

```python
from aos import hook_point
HERE = os.path.dirname(os.path.realpath(__file__))
hooks = hook_point.open(points=[HERE + "/hook_points.json"],   # 我提供哪些點
                        lists=[cfg_path],                       # 誰掛了什麼：有 "hooks" 表的 JSON 檔，後面的蓋前面的、null＝關掉
                        stack=stack, fail=die, warn=warn)       # fail(代號, 一句英文)：照我這支程式的方式報錯，不回來
r = hooks.fire("before_save", {"file": path})                   # 走到那個時機
if r["blocked"]:                                                # 被攔下在我這裡是什麼意思，我自己決定
    return
path = r["data"]["file"]                                        # 改過的值放回我自己的世界
```

加上 `hook_points.json` 裡一段宣告，就是全部。現在同一件事要照 `kernel/hooks.py` 抄約 30 行（表、讀清單、驗、包錯）。

## `aos.hook_point` 給什麼

| 名字 | 做什麼 |
|---|---|
| `read(paths)` | 讀幾份宣告、驗（[01](01-宣告格式.md) 的五條）、合成一張 `{點名: 點}`；不對丟 `PointsBad` |
| `engine_table(points)` | 轉成引擎要的 `{點名: {"condition", "intercept", "block"}}` |
| `open(points, lists=None, entries=None, stack, fail, warn=None, check=None)` | 回把手。`lists`＝每次 `fire` 重讀的檔；`entries`＝呼叫的人已經讀好、解好的清單（kernel 走這條：它的 `hooks` 表在 `kernel.json` 裡，每輪先解過指示詞才用）。`check(event, key, value)` 給「型別以外」的檢查（kernel 的 hold 那種要看執行時狀態的） |
| 把手 `.fire(event, data, only=None)` | 讀清單、驗、交引擎跑；回的形狀跟現在一樣（`data`、`changed`、`blocked`、`hook`、`text`）。`HooksBad`、`HookFailed`、`PointsBad` 一律轉成 `fail(類別名, 句子)` |
| 把手 `.has(event)`、`.names(event, data)`、`.points` | 有沒有人掛這個點；這次會跑的 hook 名（排好；kernel 的 after_verdict 要一個一個發，靠它拿名單再 `fire(…, only=[名])`）；讀好的宣告 |

- 宣告一個行程讀一次；**清單每次 `fire` 重讀**（現在就這樣；長住的 aos-mcp 才看得到中途加的 hook）。
- `change` 的型別檢查由庫做（取代 `agentlib/hooks.py` 裡手寫的「content 要是字串」）：庫把它跟呼叫端給的 `check` 併成一個函式，**交給引擎在每個 hook 跑完的當下驗**（引擎本來就有這個口）。這樣改壞值的那個 hook 才照它自己的 `on_error` 處理，壞值也不會傳給下一個 hook；不是等整串跑完才驗。
- 引擎 `hook_run.py` **不動**。

## agent 一家：`agentlib/hooks.py` 的把手

```python
H = hooks.open(def_folder, stack, fail=die, warn=warn)   # 讀 interfaces.json 的 hook_points 與 hooks；定義那份疊 stack 那份（照舊）
H.fire("after_queue", {"letter": sig, "content": content})
H.clock_tick()                                           # on_clock（照舊的邏輯，搬進把手）
content = H.take_letter(box, sig, content)               # before_queue：被攔＝記 dropped、aos-post done、寫 mailbox_warning.txt，回 None
verdict, value = H.guard_tool(name, cid, args)           # before_tool：("run", 改過的 args) 或 ("blocked", 給腦看的字，空的就補預設那句)
H.announce_tools(tools)                                  # tool_added：有人掛才比名單、一個名字發一次；tools 可以是函式（eca 有人掛才去問 aos-tools）
```

`def_folder` 給 `None`＝空把手（aos-mcp 沒給 `--hooks` 時用，取代它現在自己造的空結果）。

## 邊緣

- **格程式是範本**：整夾抄走改過的 agent 不會自己跟上新寫法；它們的舊格程式 import 的是 `$AOS_HOME/lib` 的 `agentlib.hooks`，舊函式名（`hooks.fire(event, data, def_folder, stack, …)`、`hooks.EVENTS`）拿掉後會直接壞。這是「proto8 當成沒有舊版」的後果，列在 [07](07-對照與衝突.md) 的衝突第 1 條。
- **「行為不變」有一處做不到逐字相同**：丟信三步裡，fsm 會查 `aos-post done` 的結束碼（非 0＝`PostFailed`），eca 不查；收成一份就得選一種。設計預設照 fsm（查），eca 因此多一條會報的錯，施工紀錄要寫明。
- **範本的格程式存檔即生效，庫要 `install.py` 才生效**：借用 `$AOS_HOME/templates/agent-fsm/` 格程式的 agent（`std.fsm()` 編譯的都是）會在庫還沒裝時就跑到新格程式。所以這一刀要分兩步交：先庫（舊函式留著）、裝好、再換格程式（[09](09-施工計劃.md) F1）。
- **`fail` 的兩種寫法**：`fail` 自己丟例外（eca 的 `Fail`、mcp 的 `HookStop`）＝那個例外原樣往外走，庫不接、不包；`fail` 竟然回來了（寫的人忘了退出）＝庫才補丟一個自己的例外，保證不會帶著壞結果往下走。
- 把手的函式若越加越多參數，就表示那件事其實兩邊不同，該搬回呼叫端；上表三個函式目前都不需要「這是 fsm 還是 eca」的參數。
