## 使用者寫起來（四個形狀共用這段，差在編譯後）

```python
@defs.tool                                   # 或 @defs.tool(side_effect=True)＝META
def add(a: float, b: float) -> float:
    """Add two numbers. Example: {"a": 2, "b": 3} -> 5
    Args:
      a: the first number
      b: the second number
    """
    return a + b

@defs.hook("before_tool", condition="write")
def no_secrets(event):
    if "secret" in str(event.get("arguments", "")):
        return defs.BLOCK                    # 攔下＝結束碼 10；回 dict＝改 arguments；回 None＝放行
TOOLS = [std.pack("look"), add]              # 函數直接放進 TOOLS；HOOKS 也一樣
```

**tooldef 從哪來**（四個形狀都一樣）：名字＝函數名；說明＝docstring 第一段（沒寫＝`SpecBad`）；參數＝簽名＋型別註記（`str`／`int`／`float`／`bool`／`list`／`dict` 對到 JSON 的六種）、有預設值＝選填；參數說明＝docstring 的 `Args:` 段（或 `typing.Annotated[str, "說明"]`）；錯誤代號＝照 `tool_spec` 掃 `fail("代號")`。也可以不抽、改成裝飾器明寫（`@defs.tool(description=..., params=[...])`），這是 C 第 B2 題。

## B1 抽出來：編譯時把函數原始碼搬成一支獨立的檔

- **多出的檔**：定義夾裡 `fn/add.py`、`fn/no_secrets.py`（可執行），`tools.json` 登記它們（或登記成 JSON 物件工具，tooldef 跟 `_entry` 寫在一起）；hook 格的 `handler` 指 `fn/no_secrets.py`。抽出的檔可以用 `tool_spec` 包（驗參數、`RunFailed` 帶行號、會答 `--tooldef`），行為跟工具骨架一樣。
- **跟 C 與 .o**：完全合——抽出的檔是產物，可以手改、下次編譯整份蓋；之後跟 `agent.py` 沒關係。
- **`agent.py` 改了沒重編**：照跑舊函數，跟 json 裡的 tooldef 一致。
- **靜態連結**：函數本體被「凍」在產物裡，比 std 工具更靜態（std 工具的程式還是從 `$AOS_HOME` 讀）。
- **邊緣**：
  - 函數用到 `agent.py` 裡的**常數或別的函數**：抽出去就找不到。原型做法是編譯時就報 `SpecBad`（[08](08-B-原型.md)）；也可以把用到的常數照值抄過去，但可變的東西抄了會變兩份。
  - 用到的 **import**：模組可以照搬 `import` 那行；`from x import y` 的 y 要辨認來源。
  - 閉包、lambda、迴圈裡動態做出來的函數、別的裝飾器包過的函數：原始碼拿不到或拿到不對的。
  - `defs.BLOCK` 這類編譯庫的名字被抄進產物：要換成固定值（原型第一次就踩到，見 08）。
  - `defs.load` 衍生：底那支的函數工具，衍生那支拿到的是底那夾的 `fn/` 路徑，要換算或重抽一份。

## B2 回頭跑：產物裡放一格薄殼，執行時再跑一次 agent.py

- **多出的檔**：不多程式檔；`tools.json` 每支寫成 JSON 物件工具：`_tooldef`＋`_entry: ["python3", "agent.py", "--run-fn", "add"]`（cwd＝定義夾，所以 `agent.py` 找得到）。hook 同理。
- **好處**：函數用全域、輔助函式、import 都照常——就是同一支檔。
- **跟 C 與 .o**：**衝突**——產物回頭依賴原始碼，「產出後就跟它沒關係」不成立。這要使用者裁（C 第 B1 題）。
- **`agent.py` 改了沒重編**：函數本體已經是新的、tooldef 還是舊的——名單固定、行為漂移；參數改了名，腦照舊的叫會壞。
- **邊緣**：
  - 每次叫都把整支 `agent.py` 從頭跑一遍：`std.pack` 讀包、`defs.load` 跑底那支都會重來。原型每次約 76 ms，抽出來的約 15 ms（08）。
  - 定義夾一定要帶著 `agent.py`；`cp -r` 漏掉、或 `agent.py` 有語法錯，所有函數工具一起壞。
  - `defs.main` 被叫時要分得出「這次是編譯還是執行某個函數」；今天被 import 時會印 warning。

## B3 另放一支工具模組：函數寫在普通 .py，agent.py 只指到它

```python
TOOLS = [std.pack("look"), defs.py_tools("my_tools.py")]     # my_tools.py 裡每個 @tool 函數各成一支工具
```

- **多出的檔**：`my_tools.py` 本來就在（使用者寫的）；編譯寫出 tooldef 與 `_entry: ["python3", "my_tools.py", "add"]`（或一支薄殼）。
- **跟 C 與 .o**：一半合。`agent.py` 照舊只管編譯；`my_tools.py` 的地位像工具夾裡的 `tool.py`——它本來就是程式，不是 .c。
- **邊緣**：tooldef 在編譯時算、函數在執行時跑，兩者可能漂移（同 B2，但範圍只在這支檔）；工具模組裡別放會在 import 時做事的程式碼。

## B4 同一個行程裡叫（只列出來）

格程式（`act.py`）直接 import 函數來叫，不起行程。最快，但打破「工具＝一個能被 `aos-exec` 叫的程式」（知識庫八個詞的第八個）；hook 的攔下、逾時殺整群、`on_error` 都要另做；函數崩潰會拖垮格程式；eca 身體也用不上。

## 四個形狀都要面對的

| 狀況 | 會怎樣 |
|---|---|
| 函數丟例外 | 工具：一行 `RunFailed`，腦看得到。hook：結束碼 1＝失敗，`on_error: stop`（預設）＝那一格停下 |
| 函數 `print` 除錯 | 工具的 stdout 就是結果，會混進去；hook 的 stdout 要是 JSON，印了就失敗 |
| 相對路徑 | cwd 是工具自己的夾或定義夾，**不是工作區**；要寫 `$AOS_WS` |
| 身分與權限 | 跟 agent 同一個 Linux 帳號、同一套環境；`AOS_STACK` 是 `tools/<名>/` 小格；沒有比手寫工具更多或更少的權限 |
| hook 每圈都跑的成本 | `on_clock` 配 `every_cycles: 1`＝每拍起一支 Python：抽出來約 15 ms、回頭跑約 50～80 ms，loop 一拍 300 ms |
| 第三方套件 | 執行時那個 `python3` 要裝得有 |
| eca 身體（不宣告 FSM） | 工具與 hook 一樣走 `tools.json`／`hooks.json`，四形狀都能用 |
| 同名 | 函數名跟包裡的工具撞：今天 `defs.tool` 同名＝蓋掉包裡那支、兩個包同名不同內容＝`SpecBad`；函數工具算哪一種要定 |
