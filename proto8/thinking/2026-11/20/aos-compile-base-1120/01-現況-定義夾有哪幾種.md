現況盤點之一：aos 今天有哪幾種「定義夾」，各由哪些檔組成、誰讀、何時讀、能不能從 Python 編譯（讀 HEAD 3a9b21d44 的程式與範本）。

← [README](README.md)｜下一份：[02 agent_spec 與 tool_spec](02-現況-agent_spec與tool_spec.md)

## 先講結論

- 能從 Python 編譯的只有兩種：**agent**（`agent.py`）和**工具**（`tool.py`）。kernel、daemon-root、工具包、kit 都還是手寫。
- **loop 和 fsm 在執行期早就是獨立的東西**（`aos-loop` 吃任何一份 `loop.json`、`aos-fsm` 吃任何一份 `fsm.json`），但在編譯期只是 agent 的一部分。
- **hook 不是一種定義夾**，是清單裡的一格；格裡的 handler 是任何一支程式。agent 與 kernel 的 hook 用同一個引擎（`aos/hook_run.py`），事件表不同。
- 大家共通的只有「一夾 json＋`_entry`＋指示詞」這套格式（C-48），沒有共通的編譯程式。

## 讀出來的幾件事

1. **「kernel 的程式」今天已經是 Python 程式庫**：框架站的骨架是 `round.run(pack)`，問腦那包 `kernel_llm` 就是另寫一包交給它（[htop-1119/03](../../19/aos-htop-1119/03-自訂kernel-形式與最小實測.md)）。這是**執行期**的庫；編譯期 kernel 什麼都沒有。
2. **loop 已經被兩種東西共用**：agent 的 loop 跑 `fsm.json`，procs-kernel 的 loop 跑 kernel 程式。執行期它就是一塊積木。
3. **`loop.json` 從 `agent.py` 改不到**：`interval_ms` 寫死 300、檔名寫死；`defs.extern` 只收 SYSTEM／TOOLS／LLM／FSM／HOOKS。手改 `loop.json` 下次編譯就被蓋回去。這是盤點時挖到的邊緣狀況（[09](09-C-待裁題.md) 第 A3 題）。
4. **hook 的「每圈都跑」**：沒有「每圈」這個事件；最接近的是 `on_clock` 配 `every_cycles: 1`（每拍在格程式裡比一次，到了才起 handler 行程）。這跟原話第 1 點有關，那點另有線查。
