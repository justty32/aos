B 題之一：今天一支工具、一支 hook 在執行期是什麼（怎麼被叫、stdin／stdout 的規矩、tooldef 從哪來），所以「agent.py 裡寫一個 Python 函數就是工具或 hook」離現況差哪幾步。

## 先講結論

- **工具與 hook 在執行期都是「一支另外起的程式」**：參數或事件從 stdin 進（JSON），結果從 stdout 出，每次叫都是新行程，經 `aos-exec` 跑。沒有「在同一個行程裡叫一個函數」這回事。
- **`agent.py` 在執行期沒人叫**：它只在編譯時跑。所以「函數寫在 `agent.py` 裡」要嘛編譯時把函數**搬出去**變成一支程式，要嘛執行期**回頭跑** `agent.py`——這就是 [07](07-B-形狀.md) 兩大類形狀的分歧點。
- 差五步：說明與參數從哪來、函數怎麼變成程式、`TOOLS`／`HOOKS` 怎麼收函數、編譯要能寫程式檔、hook 的回話怎麼對應。

## 工具在執行期

| 項 | 今天的樣子 |
|---|---|
| 是什麼 | 三種：資料夾（`_entry`＋`_tooldef.json`）、JSON 物件（`檔.json#/指標`，物件裡有 `_tooldef` 與 `_entry`）、可執行檔（問它 `--tooldef`） |
| 怎麼被叫 | 腦挑工具 → 格程式經 `aos-tools call` → `aos-exec` 起一支新行程 |
| 參數 | stdin 一個 JSON 物件；不認得的鍵＝`ArgumentsBad`（`tool_io` 的規矩） |
| 結果 | stdout 給腦看；錯＝一行 `名: error: 代號 原因`、退 1 |
| 工作目錄 | 資料夾工具＝它自己的夾；JSON 物件工具＝那份 json 的夾；**不是工作區**，工作區要看 `$AOS_WS` |
| stack | `AOS_STACK` 換成叫方 stack 底下的 `tools/<登記名>/` 小格（要寫才建） |
| tooldef 從哪來 | 資料夾：`_tooldef.json`（或 `_metainfo.json` 的 `tooldef` 鍵）；JSON 物件：`_tooldef` 鍵；可執行檔：叫一次 `--tooldef`，快取在 stack、看修改時間 |
| 什麼時候讀 | `aos-tools ls` 拿清單時（格程式每次問腦前） |

`tool.py`（`tool_spec`）就是在這套上加一層：從 `DESCRIPTION`、`PARAMS` 算出 tooldef，執行時照它驗參數、叫 `run(args)`、例外轉 `RunFailed`。

## hook 在執行期

| 項 | 今天的樣子 |
|---|---|
| 是什麼 | `hooks.json` 裡一格：`event`、`handler`（任何程式的路徑）、`condition`、`intercept`、`async`、`on_error`、`timeout_ms`；`on_clock` 另收 `every_cycles`／`every_ms`、`config` |
| 怎麼被叫 | 事件發生時，`hook_run` 把事件寫成 `<stack>/hooks/<名>/event.json`，再 `aos-exec` 起 handler、事件也從 stdin 進 |
| 回話 | 結束碼 0＝好；10＝攔下（能攔的事件才算）；其他＝失敗，照 `on_error` 決定停還是繼續。stdout 可以是一個 JSON 物件，改事件允許的鍵（`before_tool` 改 `arguments`、`after_tool` 改 `content`、`before_queue` 改 `content`） |
| 逾時 | 預設 60 秒，到了整群殺掉 |
| 「每圈」 | 沒有這個事件；`on_clock` 配 `every_cycles: 1` 最接近：格程式每拍在**自己行程裡**比時鐘（不起行程），到了才起 handler |

kernel 的 hook 同一個引擎，事件換成 `before_verdict`、`after_verdict`、`before_reply`。

## 差哪幾步

| 步 | 今天 | 要補的 |
|---|---|---|
| 1. 名字、說明、參數 | `tool.py` 要明寫 `DESCRIPTION`、`PARAMS` | 從函數名、docstring、型別註記抽，或裝飾器明寫 |
| 2. 函數 → 一支能被 `aos-exec` 跑的程式 | `agent.py` 執行期不跑 | 編譯時抽出原始碼成一支檔；或寫一個薄殼回頭跑 `agent.py` |
| 3. `TOOLS`／`HOOKS` 收函數 | `TOOLS` 只收包與 `defs.tool(名, 路徑)`；hook 的 `handler` 是路徑 | 收函數本身（`TOOLS = [std.pack("look"), add]`）或裝飾器自動登記 |
| 4. 編譯會寫程式檔 | `compile()` 只出 json 與文字 | 多出「可執行的檔」（要 `chmod`） |
| 5. hook 的回話 | handler 自己管結束碼與 stdout | 函數回 dict＝改鍵、回某個記號＝攔下（結束碼 10）、回 None＝放行 |

## 跟三個既有性質的互動（細節在 07）

- **「靜態連結只固定名單，程式執行時從 `$AOS_HOME` 讀」**：函數工具的程式不在 `$AOS_HOME`，在定義夾裡（抽出來的那種）或就是 `agent.py`（回頭跑的那種）。前者比 std 工具更「凍住」，後者跟著原始碼走。
- **「編譯產物的 json 照常能手改」**：tooldef 寫進 json 的話照常能改；抽出來的程式檔也能改，下次編譯被蓋。
- **「`agent.py` 改了沒重新編譯」**：抽出來的那種＝照跑舊函數，跟 json 一致；回頭跑的那種＝函數已經是新的、tooldef 還是舊的。
