## 丁：現在不抽，等第三種出現再抽

- **長什麼樣**：今天什麼都不改。哪天真的要編 kernel，先照 `agent_spec` 抄一支 `kernel_spec`，寫法照 `agent.py`；等到第三種（例 daemon-root）也要編，再看三份哪裡真的一樣，抽出共用的。寫程式的人常說「寫到第三次再抽」。
- **要動多少**：現在 0。
- **跟昨天裁的**：都合；也合 11-14「需求不清時先發想」、11-19 kernel 自訂形式「先不定，讓它自然長」。
- **邊緣**：中間有一段時間兩三份重複（今天 agent 與 tool 已經重複約 50 行，見 [02](02-現況-agent_spec與tool_spec.md)）；兩份各改各的，訊息與旗標可能又走散（11-19 才開一刀把 `tool.py` 的旗標對齊 `agent.py`）。

## 戊：底座是「一份中間格式」，前端可以很多種，後端只有一支

```
agent.py ─┐
kernel.py ─┼─► {檔名: 內容}（中間格式） ─► write(夾, 檔們)（唯一後端：暫存檔＋改名、直接蓋）
tool.py ──┤
lisp/lua ─┘   （C-43 原案；AI 直接寫 dict 也算一種前端）
```

```python
files = defs.compile(DESCRIPTION, SYSTEM, TOOLS, LLM, FSM)   # 前端：今天就有，回 {檔名: 內容}
files["kernel.json"] = my_kernel_dict                        # 任何程式都能產生這個 dict
defs.write("defs/x", files)                                  # 後端：今天就有
```

- **長什麼樣**：今天 `defs.compile` 回 `{檔名: 內容}`、`defs.write` 把它寫進夾，這已經是「前端／後端」的切法，只是後端藏在 `agent_spec` 裡。戊把 `write` 抽成全家共用的一支（`tool_spec` 的「寫進 JSON 指標」也收進來），每種東西只寫前端。
- **要動多少**：小。搬一支 `write`（約 40 行）出來，兩邊改用它。
- **跟昨天裁的**：C 與 .o 最直接（後端只會整份蓋）；其他都不碰。
- **邊緣**：
  - 中間格式只是「檔名＋內容」，**不懂內容**；驗法還是各前端自己的，後端擋不住前端給錯的東西。
  - 檔以外的產物（程式檔要可執行、要 `chmod`）中間格式要多帶一個「這份要可執行」的記號——B 題的函數工具會用到（[07](07-B-形狀.md)）。
- **像什麼**：編譯器的前端／後端、LLVM 的中間碼（IR）。

## 另一個太遠的，只記一句

**己：每種定義夾自己帶一份「形狀說明」**（像 `interfaces.json` 已經宣告介面那樣），一支通用編譯器照說明驗與寫。最整齊，但要先替每種東西寫說明，等於先把所有種類定死，跟「讓它自然長」相反。

## 五個形狀一張表

| 形狀 | 使用者寫起來 | 現有程式要動 | 跟昨天裁的（C 與 .o、直接蓋、N-70、資料夾即命名空間、連結選項） | 主要代價 |
|---|---|---|---|---|
| 甲 各一支 spec＋小底座 | `kernel.py` 長得跟 `agent.py` 一樣（大寫常數＋`defs.main`） | 中：抽底座百來行，另寫 kernel_spec | 全合 | 每多一種東西多一支；底座照兩個樣本定形 |
| 乙 底座＋積木 | `b.agent(..., body=b.loop(b.fsm(...)))` 組起來 | 大：拆 `compile()` | 合；命名空間要補「積木單獨編時寫哪夾」 | 組合合不合法要有人查；骨架變長 |
| 丙 整套是程式庫 | 物件＋`.compile(夾)`；也能直接操作活的 | 淺做 0、深做大改 | 合；繼承會有 `defs.load` 與 Python class 兩套 | 原始碼對產物變模糊；import 時碰活樹的風險 |
| 丁 等第三種再抽 | 今天不變 | 0 | 全合 | 期間重複、各自走散 |
| 戊 中間格式＋共用後端 | 今天不變（`defs.compile`／`defs.write`） | 小：搬 `write` | 全合 | 後端不懂內容，驗法仍各寫 |

這幾個不互斥：例如「戊＋丁」（先只共用後端，其他等長出來）、「甲裡面的底座就是戊的後端」、「乙的積木用丙的物件寫法」。要選的其實是**現在做到哪一步**，見 [09](09-C-待裁題.md) A1。
