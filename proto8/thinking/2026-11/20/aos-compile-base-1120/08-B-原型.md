B 題之三：不進 repo 的小原型——「抽出來」與「回頭跑」兩種做法各走一遍，看走不走得通、踩到什麼、每次叫要多久。

## 先講結論

- **兩種都走得通**：函數名、docstring、型別註記抽得出合格的 tooldef；抽出來的檔、回頭跑的薄殼，都照工具的規矩（stdin JSON 進、stdout 出）答對；hook 函數回「攔下」時結束碼是 10。
- **抽出來的那種，邊緣在編譯時就看得到**：函數用到 `agent.py` 裡的常數 `LIMIT`、或另一個函式 `json_text`，編譯當下報一行 `SpecBad`，不會等到執行才炸。
- **每次叫的時間**：空的 `python3` 約 13 ms；抽出來的約 15 ms；回頭跑 `agent.py` 約 76 ms；拿今天的骨架 `agent.py --dry-run`（等於把宣告整個算一遍）約 48 ms。

## 做了什麼

- 位置：`~/.aos/scratch/aos-compile-base-1120/proto/`（公司 WSL；不在 repo）。只用 `python3` 3.12、標準庫；**沒 import aos 套件**（原型自己寫一支 `fnproto.py` 當 `defs`），沒跑 `aos-tools`、`aos-exec`、沒起任何 aos 行程。
- `fnproto.py`（約 180 行，可丟）：`@tool`、`@hook(event, condition=)` 兩個裝飾器把函數登記起來；`tooldef_of(fn)` 從簽名、型別註記、docstring 算 tooldef；`free_globals(fn)` 找函數用到的外部名字；`compile_extract` 把原始碼抄成 `fn/<名>.py`；`compile_shim` 寫 `_entry: ["python3", "agent.py", "--run-fn", 名]`。
- `agent.py` 與 `agent2.py`：兩支函數工具（`add`、`words`，`words` 用到 `re`）、一支函數 hook（`no_secrets`，`before_tool`、`condition: write`）；設 `BAD=1` 時多一支用到模組常數 `LIMIT` 的 `first`。
- 骨架時間那一列是把 `templates/agent-python` 抄進暫存夾、`AOS_HOME` 只在那一行指令裡指到 `~/repo/aos/proto8`、跑 `--dry-run`（只印不寫），跑完刪掉那份抄本。

## 結果

| 試了什麼 | 結果 |
|---|---|
| `agent.py --compile extract`（hook 呼叫了旁邊的函式 `json_text`） | `SpecBad no_secrets uses json_text from agent.py; extract cannot carry them …`、退 1、沒寫檔 |
| `agent2.py`（hook 改成自己寫完）抽出 | 寫出 `fn/add.py`、`fn/words.py`、`fn/no_secrets.py`；`words.py` 自動帶上 `import re` |
| tooldef | `add`＝`{"a": number, "b": number}`、兩個都必填、說明取自 `Args:` 段；`words` 的 `upper` 有預設值＝選填 |
| `{"a":2,"b":3}` 餵 `fn/add.py` | 印 `5`、退 0 |
| `{"text":"hi there","upper":true}` 餵 `fn/words.py` | `["HI", "THERE"]` |
| `{"a":"x"}` 餵 `fn/add.py` | `add: error: RunFailed TypeError: add() missing 1 required positional argument: 'b'`、退 1——**原型沒驗參數**，真做要用 `tool_spec` 包，這裡會先報 `ArgumentsBad` |
| hook 抽出（第一次） | **踩到**：hook 用了 `defs.BLOCK`，抽出的檔多抄了一行 `import fnproto as defs`，執行時 `ModuleNotFoundError`。改成把 `defs` 這個名字跳過、`BLOCK` 換成固定字串後才過 |
| hook：參數含 `secret` | 退 10（攔下）；不含＝退 0 |
| `BAD=1`（用到模組常數 `LIMIT`） | `SpecBad first uses LIMIT from agent.py …`、退 1 |
| `--compile shim` | 每支寫 `_entry: ["python3", "agent2.py", "--run-fn", "add"]`；`--run-fn add` 印 `5`；`--run-fn no_secrets` 退 10 |

每次叫的時間（同一台公司 WSL，各跑 20 次取平均）：

| 叫法 | ms／次 |
|---|---|
| `python3 -c pass`（底） | 13 |
| 抽出來的 `fn/add.py` | 15 |
| 回頭跑 `agent2.py --run-fn add` | 76 |
| 只 import `aos.tool_spec`（抽出來的檔用 `tool_spec` 包時的底） | 23 |
| 骨架 `agent.py --dry-run`（把宣告算一遍） | 48 |

## 沒驗到的

- 沒經 `aos-tools ls`／`call` 與 `aos-exec` 實叫（任務書不起 aos 行程）：「JSON 物件工具的 `_entry` 從那份 json 的夾跑 `python3 fn/add.py`」是照 `aos-tools` README 與程式說明推的。
- 抽出的 hook 沒掛進真的 `hooks.json` 經 `hook_run.fire` 跑；結束碼 10＝攔下是照 `hook_run` 的說明。
- 回頭跑那種的 76 ms 比骨架 dry-run 還慢，原因沒細查（原型的 `fnproto` 載入了 `inspect`、`typing`；真做的話數字會不同）。只能說「回頭跑比抽出來每次多幾十 ms」。
- `functools.wraps` 包過的、類別方法、lambda、迴圈裡做出來的函數，都沒試。
