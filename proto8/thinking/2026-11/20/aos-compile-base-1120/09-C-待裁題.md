## A1. 通用編譯底座，現在做到哪一步？

| 選項 | 後果 |
|---|---|
| a 現在不做，等 kernel 真要編譯再說 | 今天不改；到時先照 `agent.py` 的樣子抄一支，第三種也要編時再抽共用；這段期間 agent 與 tool 兩支約 50 行重複照舊 |
| b 只共用「寫檔」那一支 | 小改：把 `defs.write` 抽成大家共用，`tool.py` 也改用它，產物一字不變；之後任何東西（`kernel.py`、AI 直接產生的檔案內容）都用同一支寫進夾；檢查仍各寫各的 |
| c 抽一個小底座，每種東西各一支 | 中改：例外、旗標、寫檔、`extern`、`load` 共用；`kernel.py` 會長得跟 `agent.py` 一樣（大寫常數＋最後一行 `defs.main`）；每多一種東西多一支 |
| d 往積木走：loop、fsm 能單獨編譯，agent／kernel 用積木組 | 大改 `agent.py` 的編譯程式；要多定一條「一塊積木單獨編時寫進哪一夾」；組合合不合法要有人查 |
| e 往「整套是一個程式庫」走 | 寫定義也變成物件、編譯＝`物件.compile(夾)`；骨架寫法要換；一支腳本可以一次編很多個，也能直接操作活的 agent |

## A3.（盤點挖到的邊緣，不是你問的）`loop.json` 從 `agent.py` 改不到，要處理嗎？

今天 `interval_ms` 寫死 300；手改 `loop.json` 下次編譯就被蓋回去。

| 選項 | 後果 |
|---|---|
| a 加一個 loop 的宣告（例 `LOOP = defs.loop(every_ms=1000)`） | 小改；也是「loop 積木」的第一步 |
| b `defs.extern` 也收 `loop.json` | 要改就整份自己寫，`agent.py` 不碰它 |
| c 維持寫死 | 要改間隔只能改完不再編譯 |

## B1. agent.py 裡的函數變成工具或 hook 之後，產物要不要跟 agent.py 沒關係？

| 選項 | 後果 |
|---|---|
| a 抽出來：編譯時把函數原始碼搬成一支獨立的檔 | 守「C 與 .o」；函數不能用 `agent.py` 裡的常數和別的函式（編譯時就報 `SpecBad`）；每次叫約 15～25 ms |
| b 回頭跑：產物只放說明書，執行時再跑 `agent.py` 的那個函數 | 函數什麼都能用；但產物依賴原始碼——`agent.py` 改了沒重新編譯，函數已經變了、說明書還是舊的；每次叫多幾十 ms；定義夾一定要帶著 `agent.py` |
| c 函數另放一支工具模組檔，`agent.py` 只指到它 | `agent.py` 照舊只管編譯；那支檔像工具夾裡的 `tool.py`，本來就是程式；說明書與函數仍可能不同步，範圍只在那支檔 |

## B2. 函數工具的說明與參數從哪來？

| 選項 | 後果 |
|---|---|
| a 自動抽：docstring＋型別註記 | 寫最少；docstring 要照一個格式寫參數說明，沒寫說明就報錯 |
| b 明寫在裝飾器上，跟 `tool.py` 一樣 | 多打字；跟工具骨架同一套寫法 |
| c 兩種都收，明寫的贏 | 最彈性；要教兩種 |

## B3. 先做工具、先做 hook，還是一起？

| 選項 | 後果 |
|---|---|
| a 一起，同一套寫法 | 一次到位；hook 的回話（攔下、改哪個鍵）要多定一套記號 |
| b 先只做工具 | 小一點；hook 照舊寫一支程式 |
| c 先只做 hook | 小一點；工具照舊寫 `tool.py` |
