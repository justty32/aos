# 你可以怎麼自己試：公司 WSL 的暫存樹已經裝好、收好（睡著），起根、問兩台、拿掉那份 json、寄錯信箱、收樹，幾行指令

← [README](README.md)｜上一份：[05-要他定的題](05-要他定的題.md)

全部在公司 WSL `~/.aos/scratch/aos-kask-proto-1120/`。`mine/proto8` 是裝好原型的乾淨複本（不是 repo、不是活樹）；`t/` 是照 start-api 抄出的暫存樹，`llm`、`perm` 已經掛在根的表上，現在全部睡著。下面這段照抄跑過一次（`try.sh`）。

```sh
S=~/.aos/scratch/aos-kask-proto-1120
. $S/env.sh                       # 清掉 AOS_*、指到原型那份複本（不要在活樹的視窗跑）
cd $S/t && . ./env.sh
setsid aos-exec root > $S/root.log 2>&1 < /dev/null &      # 起根；llm、perm 跟著醒
aos-daemon-ctl -d .stack ls                                # _clock、_sweeper、llm、perm 都是 running

python3 $S/ask.py one .stack/procs/llm/kask  '{"kernel_ask": true}'   # 問 llm kernel：一封回信，內容是 llm/kask.json
python3 $S/ask.py one .stack/procs/perm/kask '{"kernel_ask": true}'   # 問權限站：內容是 perm/kask.json

mv llm/kask.json llm/kask.json.off                         # 不給：下一封回 {"kernel_ask": null, "why": ...}
python3 $S/ask.py one .stack/procs/llm/kask  '{"kernel_ask": true}'
mv llm/kask.json.off llm/kask.json                         # 改內容也是存檔就生效，每封都重讀

python3 $S/ask.py one .stack/procs/perm/requests '{"kernel_ask": true}'   # 寄錯信箱：站回 {"applied": true}
python3 $S/ask.py one .stack/procs/llm/kask '{"kernel_ask": "yes"}'      # 格式不對：AskBad

aos-daemon-ctl -d .stack shutdown                          # 收樹：一句全睡
```

其他量測（`ask.py` 的用法寫在它檔頭）：

```sh
python3 $S/ask.py median .stack/procs/llm/kask '{"kernel_ask": true}' 30      # 連問 30 次的中位數
python3 $S/ask.py burst  .stack/procs/llm/kask 30 .stack/procs/llm/requests \
  '{"endpoint": "fake", "request": {"messages": [{"role": "user", "content": "x"}]}}'   # 灌 30 封＋一封普通請求
cp llm/kernel.hook.json llm/kernel.json      # 掛上試 hook seen（記下看到的信；body 有 "slow": true 就睡 3 秒）
cp llm/kernel.nohook.json llm/kernel.json    # 拔掉
```

整套重跑：`bash $S/run.sh`、`run2.sh`、`run3.sh`（要先起根；`run.sh` 第 9 段會 stop 兩台、第 10 段再 start）。原型的程式：`mine/proto8/py/tools/aos/kernel/kask.py` 與 `round.py`；改了要 `bash $S/install.sh` 才生效。回信堆在 `$S/boxes/` 底下，沒清。
