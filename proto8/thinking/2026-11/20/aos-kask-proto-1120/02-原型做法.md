## 一張圖

```
 問的人 ──{"kernel_ask": true}──► <kernel 的 stack>/kask/        （原型的特殊信箱，跟 requests/ 並排）
                                       │
 骨架一輪（兩種 kernel 都跑這段，每 300 ms 一次）：
   讀 kernel.json → 建 requests/ → 拿 requests/.flock
     →【新】kask.answer_all：kask/ 有信才動；逐封回信、收掉
     → collect → check → order → 逐封 [before_verdict → admit → after_verdict] → 放／拒／排／留
                                       │
 回信：{"kernel_ask": <定義夾的 kask.json>}；沒放那個檔＝{"kernel_ask": null, "why": "..."}；形狀不對＝{"error": {"code": "AskBad", ...}}
```

## 每個選擇（都可以改，列在 05）

| 選擇 | 原型怎麼做 | 別的做法 |
|---|---|---|
| 信箱在哪 | `<stack>/kask/`，跟 `requests/` 並排（[01 甲](01-信箱怎麼有.md)） | `requests/kask/`（乙）、不開信箱只分信（丙）、daemon 認（丁）、宣告檔寫位址（戊） |
| 放在一輪的哪裡 | 拿到鎖之後、`collect` 之前 | 讀 `kernel.json` 之前（設定壞了也答得出來，但那時還不知道定義夾以外的事）；`check` 之後（那就是丙） |
| 排不排隊 | 不排：一輪把信箱裡的全部答完 | 一輪最多答 N 封，其餘下一輪 |
| 過不過三個 hook | 不過 | 過 `before_verdict`（hook 可以擋或改答案；hook 壞了問句也答不了） |
| 進不進帳本 | 不進（llm kernel 的 `ledger.jsonl` 不多一列，實跑） | 記一列「問句」；或另記一本 |
| 那份 json 在哪、何時讀 | 定義夾的 `kask.json`，每封都重讀（改了下一封就照新的） | stack、定義＋stack 蓋；起來時讀一次 |
| 「可選」（kernel 可以不給） | 沒放 `kask.json`＝不給：回 `{"kernel_ask": null, "why": "this kernel gives no declaration"}` | `kernel.json` 一個開關；不給就不建信箱（問的人寄不進＝`MailboxMissing`）；回拒信帶專用代號；不回 |
| 回信長相 | 兩種 kernel 一樣：`{"kernel_ask": …}` 或 `{"error": {…}}` | 跟著各台的形狀（站回 `{"applied": …}`、llm 回 `{"message"}`） |
| 信的格式 | 只認 `{"kernel_ask": true}`；別的鍵不看（問句加真請求寫在同一封＝只答問句，真請求不跑） | 多一格「問什麼」；有別的鍵就拒 |
| 錯的信 | `AskBad` 回信；信封壞＝warning、丟掉 | 不回、照舊丟 |
| 寫錯信箱（問句寄到 `requests/`） | 沒管，照今天（站回假成功、llm 回 `LetterBad`） | `requests/` 也認出問句、回一句「請寄 kask」或直接答 |
