## 甲　現況不動，寫一頁「怎麼加一個 hook 點」

**長什麼樣**：一頁規範＋一張檢查清單（[01](01-A1-加一個點要動哪裡.md) 那 16 處的通用版），寫明提供點的一方要決定的六件事：事件名、時機（之前／之後）、欄位、condition 比什麼、能改什麼／能不能攔、哪種身體觸發。可再加一支**一致性測試**（甲＋）：

```python
# 示意：tests/test_hook_points.py
assert set(tooldef["parameters"]["properties"]["event"]["enum"]) == set(hooks.EVENTS)
assert all(e in doc_06_hook for e in hooks.EVENTS)          # 文件表每種都有一列
assert all(e in knowledge_self_hook for e in hooks.EVENTS)
```

| 項 | 內容 |
|---|---|
| 要動多少 | 一份文件（放哪是題目：`06-hook.md` 加一節，或條文）；甲＋多一支測試。程式 0 行 |
| 合不合 | 「hook不用動」合；「自訂 kernel 先不定、讓它自然長」合（不先定形狀） |
| 解掉的 | 漏改會被測試抓到（甲＋）；新來的人知道要改哪裡 |
| 沒解掉的 | 16 處還是 16 處；HOLD_EVENTS 這種「性質」測不出來；新子程式還是要自己抄 kernel/hooks.py 那約 30 行 |

## 乙　事件表變宣告式

**長什麼樣**：每個提供點的子程式在自己的資料夾放一份宣告，引擎、gdb、self_hook、文件都從它讀：

```json
{"description": "Hook points the agent-fsm body fires.",
 "events": {
  "before_brain": {"when": "think: before request.json is written", "phase": "before", "key": "request",
                   "fields": {"messages": "what will be sent", "tools": "tool names"},
                   "condition": null, "intercept": ["messages"], "block": true,
                   "fired_by": ["templates/agent-fsm/brain.py"]}}}
```

`phase` 給 gdb 分扣住或暫停、`key` 給 gdb 認是哪一次、`fields` 給文件與知識庫、`fired_by`（或由身體在 interfaces.json 宣告「我發哪些」）讓「掛在這隻不會觸發的事件上」能當場說。

| 項 | 內容 |
|---|---|
| 要動多少 | `agentlib/hooks.py`、`kernel/hooks.py` 的表改成讀檔；`gdb/trigger.py:41、67-70`、`gdb/__init__.py:63` 讀宣告；`self_hook/_tooldef.json` 的 enum 要嘛安裝時生、要嘛拿掉改說「看 `aos-agent hook events`」；文件表與知識庫用生成器出或改成指過去。約 8～10 個程式檔＋一支生成器 |
| 合不合 | 「hook不用動」合（handler 規矩不變）；「proto8 當成沒有舊版」：不用寫遷移；「讓它自然長」：**有張力**——等於先定下「提供點長這樣」 |
| 解掉的 | 加一個點＝宣告加一段＋觸發那一行；kernel 也能用同一格式，`agent_spec` 驗 kernel 的 hook 不會再拿錯表（aos-compile-base-1120 [03](../aos-compile-base-1120/03-A-kernel與loop-fsm.md) 第 30 行）；JSON 誰都讀得到，非 Python 也能提供點 |
| 沒解掉的 | 宣告與觸發還是兩處，「宣告了沒叫」要測試抓；呼叫端那 10 份包裝不變 |
| 邊緣 | 宣告放哪：放程式那層（`agentlib/`、`kernel/`）還是身體那層（`templates/agent-fsm/`）；after_start 這種由 loop 發的算誰的；欄位寫多細（只寫名字與一句話，還是 JSON schema） |

## 丙　把呼叫端重複的那幾段收成小函式

**長什麼樣**：`agentlib/hooks.py`（或一支新的小庫）多幾個函式，呼叫端只剩一行：

```python
# 示意
r = hooks.point("after_queue", data, die=die)                 # 包裝＋錯換成自己的報法（die／raise／回 isError 由參數給）
content = hooks.take_letter(stack, box, sig, content, die=die) # before_queue：攔下＝記 dropped、done、warning 一次做完，回 None
act = hooks.guard_tool(name, cid, args, die=die)              # before_tool：回 ("run", args) 或 ("blocked", 給腦看的字)
hooks.announce_tools(stack, listed, die=die)                  # tool_added：has＋tools_added＋逐個 fire
```

| 項 | 內容 |
|---|---|
| 要動多少 | `agentlib/hooks.py` 約加 60 行；呼叫端 fsm 四格＋`cell_common`、eca `hook.py`／`turn.py`、mcp、`hook_fire`，約 9 個檔（起手範本抄本再 5 個）；行為不變，現有測試照跑 |
| 合不合 | 「hook不用動」合；跟乙、戊都能疊 |
| 解掉的 | 10 份包裝與 3 組重抄收成一份；丟信那句字、攔下的預設字只寫一次 |
| 沒解掉的 | 加新點時的「文件、self_hook、gdb」那十幾處不變——**丙主要解耦合，不太解「加點方便」** |
| 邊緣 | fsm 與 eca 本來就不同的地方（after_queue 晚報、mcp 失敗只算那次呼叫）要留成參數，參數多了函式會變一團；格程式是範本，有人抄走改過的不會跟上 |
