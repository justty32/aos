## 丁　loop／狀態機那層加通用的點

**長什麼樣**：照 aos-loop 已有的 `on_start`／`on_stop`，讓 loop（或 aos-fsm）每圈、每格前後也能指一支程式，再由 `hook_fire` 那種小程式照清單發事件：

```json
// 示意：loop.json／fsm.json 多的鍵
{"exec": [...], "on_start": {...hook_fire...}, "on_cycle": {"$env": "AOS_HOME", "$path": "/lib/tools/agent/hook_fire/_entry"}}
// 發出的事件：before_state / after_state  {"state": "act", "code": 0}
```

| 項 | 內容 |
|---|---|
| 貼近 | 你第 1 點「基於loop，每次loop的時候都會觸發。然後在此之上去疊機制」：通用點在 loop 層，九種語意事件疊在上面 |
| 要動多少 | C++ 的 `cpp/aos-loop`（或 `cpp/aos-fsm`）加鍵、`hook_fire` 認新事件、事件表、文件；九種現有的不動 |
| 合不合 | 跟 C-52「loop 只跑被指定的東西」合（同 on_start 的做法）；「hook不用動」合 |
| 解掉的 | 自己寫格程式的 agent（agent.py 自訂 FSM）不用改程式就有點可掛；gdb 能停在任何一格 |
| 沒解掉的 | loop 層只知道格名與結束碼，**不知道信、工具名**，取代不了九種；攔下的意思要另定（退 10＝這格不跑？） |
| 邊緣 | **效能**：aos-loop 不知道有沒有人掛，每圈都得起一支 Python（`hook_fire`）去讀清單才知道——fsm 一圈四格就是四到八個行程；要省就得讓 loop 自己會讀清單（C++ 認得 hook，跟 C-52 有張力） |

## 戊　一支通用的「發事件」指令

**長什麼樣**：把 `hook_fire` 推廣成誰都能 exec 的指令，事件表與清單都用參數給：

```sh
# 示意
aos-hook fire --events hook_events.json --list kernel.json --list "$AOS_STACK/hooks.json" before_x < data.json
# stdout：{"data": {...}, "changed": [...], "blocked": false, "hook": null, "text": ""}；退 0／10（攔下）／1（HookFailed）
```

| 項 | 內容 |
|---|---|
| 要動多少 | 新一支指令（包 `hook_run`）；`hook_fire` 變薄；其他不必動 |
| 合不合 | 跟 NORMS「資料夾程式＋stdin／stdout」的路子合；跟乙最配（`--events` 就是乙的宣告） |
| 解掉的 | C++、shell、別人寫的 loop 都能提供點，不用 import Python |
| 沒解掉的 | Python 的提供方照舊直接叫 `hook_run` 比較快；耦合那半邊不變 |
| 邊緣 | 每次發事件多起一個行程（指令本身＋handler）；事件大時（整份 prompt）走 stdin 兩次 |

## 五個對照

| | 甲 | 乙 | 丙 | 丁 | 戊 |
|---|---|---|---|---|---|
| 主要解 | 漏改（靠清單／測試） | 加點方便、單一來源 | 呼叫端重抄 | 沒有通用點 | 非 Python 提供點 |
| 改程式 | 0（甲＋一支測試） | 約 8～10 檔＋生成器 | 約 9 檔 | C++＋小程式 | 一支新指令 |
| 跟「讓它自然長」 | 合 | 有張力（先定形狀） | 合 | 合 | 合 |
| 能疊 | 都能 | 戊、丙 | 甲、乙 | 甲、乙 | 乙 |

跟另一條線的關係：你第 3 點「整套就是一個程式庫？」若走那條，乙＋丙＋戊可以是那個庫裡的「hook 件」（提供點的人 import 或 exec 它）；第 4 點「python 函數直接當 hook」是**掛的一方**的事，跟這裡**提供點**的介面是兩半，可分開裁（[aos-compile-base-1120](../aos-compile-base-1120/README.md) 的 B 題）。

## 共通的邊緣狀況（哪個形狀都會碰到）

| 狀況 | 今天的樣子 |
|---|---|
| 別人寫的 loop／格程式不叫 hook | 不叫就沒有；gdb 斷點也停不下來，不報錯（只有丁能補一部分） |
| 掛在這種身體不會觸發的事件 | 驗格只看名字，照樣掛得上、永遠不跑（[04](04-B2-誰假設只有這九種.md)） |
| 抄走的範本 | `std.fsm()` 執行時指 `$AOS_HOME/templates/agent-fsm/` 的格程式，裝新版就跟上；但整夾抄走的（起手範本、自己抄的）留舊格程式，不會有新點 |
| 改名、拿掉一種 | proto8 當成沒有舊版：清單裡寫舊名的下次讀就 HooksBad、那隻停下；不留舊名提示 |
| 同名不同義 | fsm 與 eca 同一個名字意思不同（[05](05-B3-fsm與eca差在哪.md)）；要不要分名或標明是題目 |
| 效能 | 每個掛上的 hook 每次都另起行程（`aos-exec`＋handler）；沒掛的不起行程，但每次觸發都重讀 interfaces.json 與兩份 hooks.json |
| 事件很大 | event.json 寫整份資料（before_brain 會是整份 prompt） |
| 連鎖 | hook 又觸發 hook 不檢測，風險自擔（C-90 已定） |
