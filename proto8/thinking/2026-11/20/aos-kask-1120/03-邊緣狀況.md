# 邊緣狀況：十六條，每條一兩句——任務書點名的八條在前，原型跑出來的與順手看到的在後；只列會怎樣，不定怎麼辦

「實跑」＝[04-原型](04-原型.md) 跑出來的；其他是讀程式推的。

## 任務書點名的

1. **kernel 沒放那份 json（他說可選）**：問的人收到什麼有四種可能——回「沒有」（原型：`{"kernel_ask": null, "why": "..."}`，實跑）、回拒信、不回（等到逾時）、照今天的樣子（問腦總機 `LetterBad`、掛 proc 的站 `{"applied": true}`）。後兩種讓問的人分不出「它不給」「它不懂這個協議」「它掛了」。
2. **kernel 忙或掛了，問的人等多久**：等多久是問的人自己定（`state_path.py` 預設 3 秒、逾時撤信，`py/aos/daemon_ctl/state_path.py:15`、`:68`）。掛了＝沒人回、信留在對方 `requests/new/`（實跑）。忙：站一輪把新信一封封做完才下一輪，前面堆著別的信或很慢的 hook 時，問句也跟著等（實跑：30 封問句後的那封要等 12 秒）。agent 當門（`kernel_gate`）時，站只在 agent 兩回合之間跑，agent 回合中問句也不動。
3. **問句信要不要過 hook**：今天它會過 `before_verdict`（新信都過）。過＝別的 hook（像 aos-kres-1120 的資源宣稱 hook）也會被它叫一次，那些 hook 壞掉時（預設 `on_error: stop`）連問句都答不了；不過＝要在 hook 之前攔（[02 甲](02-可能的形狀.md)），hook 也就沒機會改答案或擋問的人。
4. **算不算一次請求、進不進帳本**：做法 A 不算（被拒的信不記帳，`kernel_llm/llm_rules.py:245-247`）；做法 B 算（帳本多一列、算額度、佔格，實跑）。算的話，有每寄件人額度的 kernel 上，問一次會吃掉真請求的份。
5. **跨機、跨帳號**：信今天是同一台機器的資料夾，跨機沒有路（這是前提、不是本題）。跨帳號：kernel 要能寫進問的人的回信箱（`aos-post send` 驗 `W_OK`，`cpp/aos-post/docs/01-用法與元素.md:22`）；答案裡若有本機路徑（像 `procs_state_path`），別台、別帳號拿到也用不上。
6. **請求者不問、直接寄**：照他說的，kernel 自己粗化細化；問句信是可選的路，不問也不會被擋。反過來，kernel 不能假設「寄來的人一定先問過、一定照 schema 寫」。
7. **schema 改版，先前問到的答案過期**：問的人可能記著舊答案（`state_path.py` 就是一次執行只問一次、記在行程內，`:16`）。kernel 改了那份 json 之後，照舊寫的信要嘛被粗化接住、要嘛看不懂；答案裡帶版本號，問的人才有辦法知道自己過期了，但要有人去比。原型讀檔是每問一次重讀，kernel 這邊是立刻生效的。
8. **拿問句信灌爆 kernel**：實跑 30 封，問腦那台 12.6 秒才答完，排在後面的普通請求從約 2.7 秒變 14.4 秒；掛 proc 的站 8.9 秒。問句信不算額度（做法 A），也沒有「每個寄件人最多問幾次」；寄件人又是自報的，換個名字就能繞過按寄件人的限制。
9. **認人靠自報（他說先這樣）在這裡的影響**：答案若對每個寄件人都一樣，冒名沒有好處；若答案按寄件人給（例：「你還剩多少額度」「你能用哪些能力包」），別人冒名就看得到。答案寄到信裡寫的 `reply_to`，所以也能拿問句信叫 kernel 往別人的信箱塞信（今天任何信都一樣）。

## 原型跑出來的

10. **一問兩答**：做法 A 每次兩封（答案＋`HookRejected`），兩封都留在問的人信箱（實跑）。不懂這個協議的人只看第一封或最後一封，會以為被拒。
11. **問句和真請求寫在同一封**：做法 A 整封被拒，真請求沒跑（實跑 b1x、b3）。今天的 `procs_state_path` 是「其他鍵照套」（`mailbox.cpp:14`），兩種習慣不一樣。
12. **寄信工具擋路**：`aos-llm send` 不讓沒有 `request` 的信出門（實跑）。問問腦總機要嘛繞過它、要嘛它要認得問句信。
13. **沒掛的站「假裝聽懂」**：掛 proc 的站把問句轉給 daemon，回 `{"applied": true}`（實跑）。問的人看到 applied 會以為對方收了。

## 順手看到的

14. **鏈上誰回**：問句寄到前站，前站答自己的，還是一路轉到最後一站答？今天的 `procs_state_path` 是一路轉到 daemon 才答，所以答的是最後那台。C-47 說寄出去背後是黑盒子（`docs/CONCEPTS/04-kernel/01-C-47.md`），問的人只看得到第一站；前站若沒掛、只轉寄，答的就是後站，前站自己的規則問的人看不到。
15. **兩種回信形狀**：daemon 與掛 proc 的站回 `{"applied": …}`，問腦總機回 `{"message"}`／`{"error"}`（`kernel_llm/llm_rules.py:27-39`）。問句的回信要嘛跟著各台的形狀、要嘛有自己一種；前者問的人要會讀兩種。
16. **答案多大、要不要整份**：宣告長了（規則多、schema 細），每問一次就是一整份；問的人只想知道一個鍵時，整份是浪費，也讓 kernel 每次都要讀全檔。
