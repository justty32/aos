# 要你定的八題：自動回信放哪、回什麼、那份 json 放哪、interfaces.json 要不要指過去、沒放時回什麼、算不算請求、問句長什麼樣、鏈上誰答；每題都能答「先不定」，不代選、選項順序不代表推薦

← [README](README.md)｜上一份：[04-原型](04-原型.md)

背景在 [02](02-可能的形狀.md)、[03](03-邊緣狀況.md)。名字（問句信的鍵、那份 json 的檔名）本線不取，等你取；這裡不列成題。「schema 誰說了算」你在 aos-kres-1120 已答先不定，不重問。

**第 1 題：「自動回這種信的東西」放在框架的哪一層？**
- 骨架自己攔（在排序之前認出問句、直接回）——所有用骨架的 kernel 都自動有，包不用改；骨架從此認得一種請求，hook 看不到問句。
- hook 多一種回話「這封我答了」，框架附一支用它的標準 hook——掛了才有（可選自然成立）；要改 hook 的回話規則，跟 hook 介面那條線碰在一起。
- 各包的放不放口自己認——最貼今天的寫法；問腦那包、掛 proc 那包各寫一份，新包要自己記得加。
- 分流到另一個答問的小站——站不用改；多一個要起的東西，而且問腦總機沒有分流的口。
- 先不定。

**第 2 題：問句信回的，就是那份「另外一個 json」嗎？**
- 整份原樣回——最簡單；宣告長了每次都是一整份。
- 問的人在信裡指定要哪幾段——回信小；要先定「可以問哪幾段」。
- 整份裡再加上框架算得出來的（例：問腦總機今天就有的能力包清單）——問的人一次拿齊；那份 json 跟回信不再一樣，要說清楚哪些是人寫的。
- 先不定。

**第 3 題：那份「另外一個 json」放哪？**
- kernel 的定義夾——跟著定義走、可以 git，同一份定義起的幾台說一樣的話；kernel 自己（是 agent 時）改它就是改定義。
- kernel 的 stack——kernel 自己改了下一封就生效；換一台要自己抄，跟「經驗存哪」（你答先不定）綁在一起。
- 定義夾一份出廠、stack 有就蓋上去——沿用 agent 那套慣例；要再定整份蓋還是逐鍵蓋。
- 先不定。

**第 4 題：`interfaces.json` 要不要寫一行「那份 json 在哪」？**
- 寫一行——工具有固定地方找，跟今天 `aos-ledger` 同一招；你說 interfaces 是別的用途，這一行算不算佔用它，你判斷。
- 不寫，固定檔名、固定位置——`interfaces.json` 完全不碰；檔名定了就不能隨各台改。
- 先不定。

**第 5 題：kernel 沒放那份 json（你說可選）時，問句信回什麼？**
- 回「沒有」（一封正常的回信，內容說這台不給）——問的人分得出「不給」與「不懂」；不懂這協議的 kernel 還是照舊（拒或假裝收到）。
- 回一封拒信，帶一個專用的錯誤代號——跟其他錯一樣處理；問的人要多認一個代號。
- 不回——最省；問的人只能等到逾時，分不出「不給」「掛了」「忙」。
- 先不定。

**第 6 題：問句信算不算一次請求（過不過 hook、進不進帳、吃不吃額度）？**
- 不算：不過 hook、不記帳、不吃額度——問句最快、跟真請求互不影響；也沒有東西擋得住灌爆（實跑：30 封讓普通請求慢了約 12 秒）。
- 過 hook、但不記帳不吃額度——hook 可以擋或改答案；別的 hook 壞了問句也跟著答不了。
- 當成一般請求：過 hook、記帳、吃額度——灌爆有額度擋；問一次會吃掉真請求的份，還要排隊等格。
- 先不定，各 kernel 自己選。

**第 7 題：問句信長什麼樣？**
- 一個專用的鍵、值是 true（跟今天問表在哪的 `procs_state_path` 同一個樣子）——跟現有的一致；要問別的事就再加一個鍵。
- 一個鍵、值寫「要問什麼」——一封可以只問一段（跟第 2 題第二個選項一起）；要定能問哪些。
- 寫在信封上（aos-post 多一欄）——所有站一眼看得出是問句；要改 aos-post，等於多一條所有站共通的規定。
- 先不定。

（跟著這題的小事：問句跟真請求寫在同一封時，是「問句答了、真請求照跑」，還是「只能單獨問」——今天的 `procs_state_path` 是照跑；原型的做法是整封被拒。）

**第 8 題：信經過好幾站（鏈）時，誰答？**
- 收到的第一站答自己的——問的人看到的就是它的規則，合「背後是黑盒子」；後面幾站的規則問的人看不到。
- 一路轉到最後一站答——跟今天的 `procs_state_path` 一樣；前站自己的規則（例：它的白名單）問的人看不到。
- 每站把自己的加進去一起回——最完整；要定怎麼合、誰先誰後。
- 先不定，各站自己選。
