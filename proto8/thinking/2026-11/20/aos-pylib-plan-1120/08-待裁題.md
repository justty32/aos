## 1. 有了連結版的 extern，「defs.main() 收一個設定檔、在裡面寫哪些產物不要產出」還要不要？

你第一段話要它，第二段話把 extern 改成連結之後沒再提。

| 選項 | 後果 |
|---|---|
| 不要了，用同夾連結頂 | 手寫的檔取別的名字（`system.hand.txt`），`system=defs.extern("system.hand.txt")`；編譯只重做連結、不碰手寫檔。只對 system、tools、llm、hooks、fsm 五欄有用；骨架那幾份（`loop.json`、`_entry`…）保護不到 |
| 要，加設定檔 | `defs.main(agent, "compile.json")`，裡面列不寫的檔名。任何產物都能跳過；多一個檔、多一種格式要教；被跳過的檔不在時定義夾不完整，沒人會提醒 |
| 先不定 | 照第一個選項的現狀走，之後要再加不會弄壞東西 |

## 2.「compile」這個字要照哪一天的意思？（[06 衝突 1](06-對照與衝突.md#要帶給使用者的衝突)）

| 選項 | 後果 |
|---|---|
| 照今天選項框那句：`物件.compile(夾)`＝算完寫進夾，`物件.dry_run()`＝只算 | 跟旗標 `--compile`／`--dry-run` 一對一；昨天的 `defs.compile(...)`（只算）、`defs.write(...)` 拿掉 |
| 照昨天：`物件.compile()`＝只算，`物件.write(夾)`＝寫 | 昨天的字義不變；跟選項框那句、跟旗標 `--compile` 都對不上 |

## 3. 物件的欄位名（也就是 `defs.load` 回來那個東西的欄位）大寫還是小寫？（[06 衝突 2](06-對照與衝突.md#要帶給使用者的衝突)）

| 選項 | 後果 |
|---|---|
| 小寫：`defs.Agent(..., tools=…)`、`base.tools`、`base.hooks` | Python 的慣例；昨天教的 `base.TOOLS` 要改口，`base.tools(prefix=…)` 改叫 `base.pack(prefix=…)` |
| 大寫照舊：`base.TOOLS`、`base.HOOKS` | 昨天的寫法不變；`defs.Agent(...)` 的關鍵字（小寫）跟欄位名（大寫）對不上，或關鍵字也寫大寫 |

## 4. 把函數標成工具／hook 的裝飾器，放在新名字 `fn`，還是掛在 `defs` 底下？（[06 衝突 3](06-對照與衝突.md#要帶給使用者的衝突)）

| 選項 | 後果 |
|---|---|
| `from aos.py import fn`：`@fn.tool`、`@fn.hook(…)`、`fn.block`、`fn.fail` | `agent.py`、`tool.py`、以後 kernel 都同一個名字；抽出來的檔跟手寫的工具檔長得一樣；多一個入口頂層的名字，工具骨架的寫法整個換 |
| 掛在 `defs`：`@defs.tool`、`@defs.hook(…)` | 少一個名字；`defs.tool` 一名兩義；`tool.py` 要另有自己的 `defs`（先碰到第 9 題）；抽出來的檔不能 import `defs`，產物跟原始碼長得不一樣、攔下的記號要另想 |

## 5. 函數想共用 `agent.py` 裡的常數或小函式時，要不要開放？

你選「抽出來」時選項上寫的是「編譯時就報錯」；本稿照這句，連「旁邊另一支自己的模組」也報錯。

| 選項 | 後果 |
|---|---|
| 照舊全部報錯 | 規則一句話：函數只能用標準庫與裝好的套件；要用的常數與小函式得寫進函數裡 |
| 開放旁邊的模組，自己放 | 定義夾放 `helpers.py`，函數裡 import 它；編譯到別的夾、或被別支衍生時，那一夾要自己再放一份（沒放＝編譯報錯） |
| 開放旁邊的模組，編譯時一起寫進 `fn/` | 不用自己搬；那支模組也變成產物（第二份），它再 import 別的旁邊模組時要一路跟 |
| 同檔的普通函式與字面常數跟著抽 | 最好寫；常數在產物裡變第二份；「哪些能跟著抽」多一套規則，會動的值仍要報錯 |

## 6. extern 做成連結後，`agent_def llm set`、`agent_def tools add` 這類指令會順著連結改到那份共用的手寫檔，要怎麼辦？（[06 衝突 4](06-對照與衝突.md#要帶給使用者的衝突)）

| 選項 | 後果 |
|---|---|
| 接受，寫進「別濫用」的說明 | 不動現有指令；有人會不小心改到共用檔 |
| 這幾支指令碰到連結先換成普通檔再改 | 共用檔永遠不會被指令改到，跟 `agent_def system set` 一致；要改 `agent_def` 與 `aos-tools` 的寫檔；下次編譯又變回連結 |
| 碰到連結就拒絕，叫人直接改目標 | 最保守；多一種錯誤訊息 |

## 7. 函數工具／hook 裡的相對路徑從哪算？（原 B4）

抽出來的程式住在定義夾的 `fn/`。

| 選項 | 後果 |
|---|---|
| 照今天工具的規矩：從程式自己那一夾算，工作區要寫 `$AOS_WS` | 跟其他工具一致；起點是 `fn/`，寫函數的人幾乎一定會猜錯 |
| 執行前先切到工作區 | 函數裡 `open("x")` 就是工作區的 x，好寫；跟其他工具不一樣 |
| 執行前先切到定義夾 | 讀定義夾裡的資料檔方便；工作區仍要寫 `$AOS_WS` |

## 8. `loop.json` 從 `agent.py` 改不到（間隔寫死 300 毫秒），要處理嗎？（原 A3）

| 選項 | 後果 |
|---|---|
| 加一個宣告：`defs.Agent(..., loop=defs.loop(every_ms=1000))` | 小改；庫裡那塊內部的 loop 變成公開的 |
| 不加宣告，要改就整份手寫 | 要先有第 1 題的設定檔（連結版 extern 對 `loop.json` 只能指同一夾，而且還沒驗） |
| 維持寫死 | 要改間隔只能改完不再編譯 |

## 9. kernel 以後要編譯時，寫的人從哪裡 import？（原 A2）

| 選項 | 後果 |
|---|---|
| `from aos.py.kernel import defs` | 照你 11-19「defs 不只會在 agent」那句：一種東西一個 `defs` |
| 同一個 `defs`，裡面多 `defs.Kernel(...)` | 只有一個入口；`aos.py.agent.defs` 這個位置就名不副實 |
| 先不定 | 等 kernel 那條線（初始 kernel 八題）有答案再說 |

## 10. `agent_def new` 抄出來的定義，函數工具那一格會指回原來那一夾，要處理嗎？（[06 衝突 6](06-對照與衝突.md#要帶給使用者的衝突)）

| 選項 | 後果 |
|---|---|
| 不動，寫進文件 | 新夾自己那份 `fn/add.py` 沒人用：手改它沒效果；原夾刪了，新夾的函數工具就壞（hook 不受影響） |
| `agent_def new` 對「指在定義夾自己裡面」的相對路徑不改寫 | 新夾用自己那份；改到既有行為——從範本抄出來的定義，夾內的工具也不再指回範本 |
| 只對 `fn/` 開頭的不改寫 | 只影響函數工具；多一條認名字的特例 |
