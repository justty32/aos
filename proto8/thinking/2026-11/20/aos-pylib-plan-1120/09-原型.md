## 結論

- 原型做在 Argon 審之前：檔名用的是 Python 函數名（定稿改成最後登記的名字）、找外面的名字是手寫的（定稿改用 `symtable`），這兩處沒重做。`symtable` 另外單獨試了一個函數（裡面有推導式、`:=`、`with … as`、`except … as`，檔案最上層還有同名的 `item`、`n`）：它回的外面名字是 `LIMIT`、`os`、`re`、`shout` 加幾個內建的，沒把推導式裡的 `item`、`n` 算進來。
- **設計走得通**：抽出的檔保留 `@fn.tool`／`@fn.hook` 那一行、結尾 `fn.main(函數)`，執行時當場從簽名、型別註記、docstring 算說明書，不必載入 `inspect`；工具答對、缺參數報 `ArgumentsBad`、hook 攔下退 10、改鍵印 JSON。
- **「明寫的贏」照一個參數一個參數算**：`add` 的說明與參數 `b` 明寫、`a` 自動抽，`--tooldef` 印出來兩邊各用各的。
- **旁邊模組**（待裁第 5 題的一個選項，預設不開）：函數用 `helpers.twice(...)`，`import helpers` 被帶進產物，把定義夾排進找模組的路徑後執行時找得到。
- **同檔一起抽**（待裁第 5 題的另一個選項）：`first` 用到同檔的 `shout()` 與 `LIMIT = 3`，兩個都被帶進產物，答對。預設（報錯）那種：一行 `SpecBad first uses shout from agent.py; …`。
- **連結**：暫存連結＋改名能換掉普通檔、也能被普通檔換掉，目標都沒被動到；搬動的結果見下表。

## 做了什麼

位置：公司 WSL 的 `~/.aos/scratch/aos-pylib-plan-1120/`（`fn.py` 約 120 行、`extract.py` 約 100 行、`agent.py`、`run.sh`；可丟）。沒 import aos 套件，原型自己的 `fn.py` 當「執行時那一半」。

| 試了什麼 | 結果 |
|---|---|
| 預設（同檔的名字報錯）抽五個函數 | 寫出 `words`、`add`、`no_secrets` 三支；`first`（用到 `shout`、`LIMIT`）、`uses_defs`（用到 `defs`）各報一行 `SpecBad` |
| 同檔一起抽 | `first.py` 帶著 `def shout` 與 `LIMIT = 3` |
| `{"text":"hi there","upper":true}` 餵 `fn/words.py` | `["HI", "THERE"]`、退 0 |
| `{"a":2,"b":3}` 餵 `fn/add.py`（用了 `helpers.twice`） | `5.0`、退 0 |
| `{"a":2}` 餵 `fn/add.py` | `add: error: ArgumentsBad b is required`、退 1 |
| `fn/add.py --tooldef` | 說明是明寫的那句；`b` 是明寫的 `integer`、`a` 是自動抽的 `number` |
| hook：參數含 `secret` | 印原因、退 10 |
| hook：參數含 `pad` | 印 `{"arguments": {"path": "padded"}}`、退 0 |
| hook：其他 | 不印、退 0 |

每次叫（20 次平均，同一台）：空的 `python3` 約 11 毫秒；抽出的 `fn/words.py` 約 20 毫秒（原型的 `fn.py` 很小；真的還要加 aos 驗參數那支，[compile-base 的原型](../aos-compile-base-1120/08-B-原型.md)量到只 import `tool_spec` 約 23 毫秒）。只看量級。

連結：

| 動作 | 結果 |
|---|---|
| 暫存連結改名蓋上去 | `system.txt -> ../../shared/system.txt`，讀得到目標內容 |
| 再用普通檔改名蓋上去 | 變回普通檔；目標那份內容沒變 |
| `cp -r` 到同一層 | 讀得到 |
| `cp -r` 到深一層 | `No such file or directory`（相對連結斷了） |
| `cp -rL` | 變普通檔 |
| `shutil.copytree(symlinks=True)`（`agent_def new` 用的） | 照樣是連結 |
| `git add`、`git archive` 解開 | mode 120000；解開後仍是連結、讀得到 |
| 在 `/mnt/c` 底下建連結（公司 WSL） | 建得起來、讀得到；同一處 `chmod 755` 的檔顯示 `rwxrwxrwx` |

## 沒驗到的

- 沒經 `aos-tools`、`aos-exec`、`hook_run` 實叫（任務書不起 aos 行程）：「相對路徑從 `tools.json`／`hooks.json` 那一夾算」「可執行檔工具要有 x 權限與 `#!`」「`aos-exec` 先切到程式的真實所在夾」是讀程式得的。
- 「函數用到編譯庫要報錯」只驗到它被當成同檔的名字擋下；「它是從編譯庫 import 進來的」那條判斷原型裡的替身沒走到。
- fsm 的連結指到夾外會讓格程式找錯夾：讀程式推的，沒實跑。
- 連結在 `/mnt/c` 從 Windows 那一側看是什麼；git 在 Windows 簽出連結的結果。
- `from __future__ import annotations`、`list[str]`、有 `async` 的 hook 格、被 `defs.load` 載入後再抽。
