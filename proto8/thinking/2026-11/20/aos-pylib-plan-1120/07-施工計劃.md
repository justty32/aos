## 共通的驗收做法與硬規則（每刀都照這節，07b、07c 不重複）

**環境**（[規矩卡「活樹旁九條」](../../../../../wf/workflows/common/rules-card.md)）：

- repo 在 WSL 的 `~/repo/aos`；活樹 `~/aos-home` 不碰。
- **測試在乾淨複本上跑**：`git archive HEAD proto8 | tar -x -C ~/.aos/scratch/<線名-日期>/src`，再把這刀改的檔疊上去（[recipes](../../../../../wf/public/recipes.md)）。
- **暫存樹起在 `~/.aos/scratch/<線名-日期>/`**；收行程只准 shutdown 自己的 stack、kill 自己記的 pid。
- **aos 指令與測試一律經 bash 腳本先清掉所有 `AOS_*`**，再只設這次要的變數。
- **改 `py/` 要 `install.py` 才生效**。裝到暫存的 `AOS_HOME` 沒問題；**在 repo 裡跑 `install.py`＝換掉活樹那份，要先回報**。
- 開工前與收尾各跑一次 `pgrep`／`ls` 核對，對不上就停手回報。

**「骨架一字不差」怎麼比**（第 0、1、2 刀的核心驗收）：

1. 改動前，在複本裡把兩個骨架各編譯一次，輸出留底。
   - `agent.py`：`--compile`、`--dry-run --static`、`--dry-run --dynamic`。
   - `tool.py`：`--compile`、`--dry-run`、`--tooldef`、`--metainfo`，再拿 `{"a":2,"b":3}` 跑一次。
   - stdout、stderr、結束碼都留。
2. 改動後同樣再跑一次。寫出的檔用 `git diff --no-index --exit-code` 跟提交的那份比，留底的輸出用 `cmp` 比。**差一個 byte 就不算過**；那刀明寫要變的例外（例如第 2 刀的 `--help`）。
3. 現成的測試（`Skeleton.test_committed_files_match_agent_py`、`test_skeleton.py`）已比一部分。

**舊寫法 grep**：每刀交件前，在 `proto8/`、`wf/` 跑自己那刀列的 `git grep -nE` 樣式，只排除 `proto8/thinking/`（歷史紀錄）；命中＝沒改完。

**跑哪些測試**：每刀列的，加上這幾支一定跑——`py/tests/test_agent_spec*.py`、`test_tool_spec.py`、`test_aos_py.py`、`templates/tests/tool-python/`、`py/tools/agent/tools_def/tests/`、`py/tools/aos/defs/tests/`、`py/tools/agent/agent_def/tests/`。跑法：`python3 -m unittest discover -s <夾> -p 'test_*.py'`。

**程式的硬規則**（[01-程式碼慣例](../../../../../wf/workflows/common/conventions/01-程式碼慣例.md)）：

- 單檔超過 300 行就拆。**現在就超過的**：`agent_spec.py` 461、`agent_spec_parts.py` 344、`refs_check.py` 304、`tools_def/_entry` 651、`test_agent_spec.py` 1107。各刀怎麼不讓它們再長、或順手拆，寫在 07b、07c（`tools_def/_entry` 不順手拆）。
- 單向分層：`aos/py/`（公開）可以 import `aos/` 其餘的模組（內部），反之不行。
- 程式輸出一律英文；新檔第一行寫一句話。
- 改欄位、改名、改訊息要全域 grep，同一個 commit 改完。
- 不 `git add`、不自己跑 `index_gen`；交件走 `commit-request`；不 push。
- 一刀交一個 commit 為原則；要拆時，每個 commit 也要過上面的測試。

**每刀交件時附的紀錄**：在當天的 `proto8/thinking/` 寫清楚做了什麼、驗收的實際指令與結果、沒驗到的。第 3、4 刀會讓定義夾多出 `fn/` 與連結，紀錄裡寫一句「重新編譯即可、舊的不用刪」。
