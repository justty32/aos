`fn_spec.py` 做三件事：

- **找函數**：只在模組最上層找，用「第一個裝飾器那一行」對 `co_firstlineno`。
- **算用到的外面名字**：用標準庫 `symtable` 問，照 [04 的表](04-函數-依賴與互動.md#函數用到外面的東西) 分成「沒事、搬 import、`SpecBad`」。`fn.block(`／`fn.fail(` 看語法樹的呼叫節點，不找字串。import 只搬用到的名字，一個名字重寫成一行。import 的模組是 `agent.py` 旁邊自己的檔＝`SpecBad`。
- **產生產物的文字**：產物叫 `fn/<最後登記的名字>.py`，工具用經 `name=`、`base.pack(prefix=, rename=)` 之後的名字，hook 用 hook 名；兩格搶同一個檔名＝`SpecBad`。
  - 原檔有 `from __future__ import annotations` 時，這行放在產物最前面。
  - 開頭找 aos 套件只認 `$AOS_HOME/lib`；先比對 `sys.path` 第一格真的是 `fn/`，才把它拿掉。
  - 接著是函數原文，裝飾器那行照搬，最後一行 `fn.main(名)`。

骨架不加函數範例，範例放 README。

**驗收**：

- **實掛**：暫存樹（複本裝到暫存 `AOS_HOME`）加照劇本回話的假腦（`templates/tests/reviewer/endpoint.py` 或 `lib/tools/base/llm_fake`，待確認），掛一隻帶 `add`、`no_secrets` 的 agent：腦叫 `add` 拿到 `5`；含 `secret` 的寫檔被攔，history 有原因；`agent_def check` 回 `{"problems": []}`。
- **04 那張「用到外面的東西」表每一列各一條測試**，另加這幾條：
  - 裝飾器那行、預設值用到同檔常數，各一條；
  - 推導式、`with … as`、`:=` 裡的名字不誤判；
  - import 旁邊模組＝`SpecBad`；
  - `import os, re` 只用到 `re`，產物只寫 `import re`；
  - 叫 `json` 的工具不會害別支產物 import 錯；
  - 字串裡寫了 `fn.block(` 不算。
- **改名與搶檔名**：
  - 底的 `check` 用 `base.pack(prefix="base_")` 改名後，衍生自己的 `check` 兩支都編得出來（`fn/base_check.py`、`fn/check.py`）；
  - 兩格搶同一個檔名＝`SpecBad`。
- **事件**：拼錯事件名、不收條件的事件寫了 `condition=`、`after_tool` 用 `fn.block`，各報 `SpecBad`。
- **互動**（[04 互動表](04-函數-依賴與互動.md#跟已有機制的互動)）：靜態與 `--dynamic`、函數蓋掉包裡同名那支、`defs.drop("add")` 不寫 `fn/add.py`、衍生重抽、eca 版、舊的 `fn/x.py` 不刪，各一條。
- 骨架一字不差。

**文件**：
- `templates/agent-python/README.md` 加「Functions as tools and hooks」一節：相對路徑從 `fn/` 算（工作區用 `$AOS_WS`）、旁邊模組不行、`agent_def new` 會把工具格改指回原夾（第 10 題）；「Linking tool packs」補一句 `fn` 從 `$AOS_HOME/lib` 讀。
- 教學 06-1 加一小節；`py/README.md`。知識庫不加。

**自成一體**：函數工具與 hook 從宣告到實掛整條通；沒用函數的 agent 不受影響。

**邊緣與風險**：
- 掛到「這隻身體不會發」的事件：hook 線第 5 題沒裁。本線只查「在不在 `events()` 的表上」，不在＝`SpecBad`（今天如此）；表照身體給之後就是當場擋。若裁成只警告，是表多給一格、這裡多一個分支，兩種都接得上，不寫死。
- hook 每圈都起一支 Python（D10）。

`SpecBad` 的四種情形：

- 目標不存在。
- 目標是資料夾。
- 繞回自己：比「目標的真實路徑」與「定義夾的真實路徑＋連結檔名」，連結檔名本身不解；這句訊息特別寫。
- fsm 指到夾外：「同一夾」的判法是路徑整理後沒有上一層、也沒有子夾。

**驗收**：

- [05 逐項表](05-extern-symlink.md#逐項) 每列一條測試。
- `--dry-run` 印 `$symlink`。
- **同一支連編兩次，第二次不誤判成繞回自己**。
- `defs.load` 的底連到夾外：衍生那支的連結換算對。底連到夾內：`SpecBad`。
- 手刪目標：`agent_def check` 只報一條 problem。
- 實掛 `system=defs.extern("../shared/system.txt")`：腦收到那份內容；改它不重新編譯，下次問腦就變。
- 骨架一字不差。
- 舊寫法 grep：`git grep -nE 'extern\("system\.txt"\)'` 沒有命中。

**文件**：
骨架 README 的「extern」一節（05 的中文版）；教學 06-2 `:72-117` 的 bob 改用 `defs.extern("system.hand.txt")`（意見 16）；`py/tools/aos/defs/README.md`、`knowledge/aos/agents.json:7`（check 清單加斷鏈）、`py/README.md`。

**自成一體**：新意思從宣告、編譯、`--dry-run`、衍生到 check 整條通；寫穿是已知行為，寫在說明裡（第 6 題）。

**邊緣與風險**：Windows 的 clone 會把連結簽成文字檔（範本不放連結）；`cp -r` 到不同深度，相對連結會斷；guard 照目標的真實位置判；`agent_def system set` 會把連結換成普通檔。
