## 先講結論

```
寫定義（原始碼）                          物件                      編譯產物（一夾檔）
agent.py   defs.Agent(...)        ──►  Agent ─┐
           defs.fsm(...)          ──►  Fsm   ─┼─ .dry_run()      ──► {檔名: 內容}（只算、不寫）
tool.py    @fn.tool def add(...)  ──►  函數  ─┘  .compile(夾)     ──► 寫進夾（直接蓋）
                                              defs.main(物件)／fn.main(函數)＝包一層命令列旗標
```

- **一種東西一個類別，兩個方法**：`.dry_run()` 算出全部產物、不寫；`.compile(夾)` 算完寫進夾。命令列的 `--dry-run`、`--compile` 就是叫這兩個。
- **`agent.py` 最後一行照舊是 `defs.main(...)`**，只是交給它的從「一串大寫常數」變成「一個物件」。旗標一個都沒變。
- **Python 函數的那一半放在新的小模組 `fn`**（`from aos.py import fn`）：`@fn.tool`、`@fn.hook(事件)`；同一個 `fn` 在 `agent.py`、`tool.py`、以後的 kernel 都一樣寫（細節 [03](03-函數當工具與hook.md)）。
- **fsm 現在就能單獨編譯**；loop 在庫裡是內部的一塊，要不要讓人宣告它取決於 A3（[08](08-待裁題.md) 第 4 題）。

## 寫一隻 agent（`agent.py`；含一個函數工具、一個函數 hook、一個 extern）

```python
#!/usr/bin/env python3
"""reviewer - 看工作區的東西、用信回答（python3 agent.py --compile 編譯成這夾的定義檔）。"""
# ---- setup: find the aos package (keep these lines as they are) ----
...（同今天骨架的那十幾行，最後是）
from aos.py import fn
from aos.py.agent import defs
# ---- your agent: change the lines below ----
std = defs.std


@fn.tool
def add(a: float, b: float) -> float:
    """Add two numbers and return the sum. Example: {"a": 2, "b": 3} -> 5

    Args:
      a: the first number
      b: the second number
    """
    return a + b


@fn.hook("before_tool", condition="ws_write")
def no_secrets(event):
    """Stop a write whose arguments mention a secret."""
    if "secret" in str(event.get("arguments", "")):
        return fn.block("the arguments mention a secret")


reviewer = defs.Agent(
    "Look things up in the workspace and answer by mail.",
    system=defs.extern("../shared/system.txt"),      # system.txt 編成一個連結，指到這份手寫檔（別濫用，見 05）
    tools=[std.pack("look"), std.pack("mailbox"), add],
    llm={},
    fsm=std.fsm(),
    hooks=[std.hooks(), no_secrets],
)

defs.main(reviewer)
```

編譯後這一夾多出／換掉的：

| 檔 | 內容 |
|---|---|
| `_entry`、`body.json`、`loop.json`、`interfaces.json`、`fsm.json`、`llm.json`、`_metainfo.json` | 跟今天一樣 |
| `tools.json` | 兩個包的工具照舊；多一格 `"add": {"path": "fn/add.py"}` |
| `hooks.json` | 範本那組照舊；多一格 `"no_secrets": {"event": "before_tool", "condition": "ws_write", "handler": "fn/no_secrets.py"}` |
| `fn/add.py`、`fn/no_secrets.py` | 抽出來的兩支程式（可執行；長相見 [03](03-函數當工具與hook.md)） |
| `system.txt` | 一個連結 → `../shared/system.txt` |

## 寫一支工具（`tool.py`）

```python
#!/usr/bin/env python3
"""add - 把兩個數相加（工具骨架）。"""
# ---- setup: find the aos package (keep these lines as they are) ----
...
from aos.py import fn
# ---- your tool: change the lines below ----

@fn.tool(meta={"side_effect": False})
def add(a: float, b: float) -> float:
    """Add two numbers and return the sum. Example: {"a": 2, "b": 3} -> 5

    Args:
      a: the first number
      b: the second number
    """
    return a + b


fn.main(add)
```

- 旗標照舊：`python3 tool.py --compile [位置]`、`--dry-run`、`--tooldef`、`--metainfo`；沒給旗標＝當工具執行。
- `tool.py` 照舊「又是原始碼又是程式」，不抽。`agent.py` 抽出來的 `fn/add.py` 長得就是一支這樣的檔——**抽出來的產物＝你手寫一支工具檔會寫的樣子**，所以只有一套寫法、一條執行的路。
- 明寫的寫法（兩種都收）：`@fn.tool(description="…", params=[fn.param("a", "number", "the first number"), …])`。

## 一張狀態機單獨編譯；一支腳本編很多個

```python
from aos.py.agent import defs
cells = defs.fsm("idle", [defs.state("idle", ["python3", "idle.py"], {0: "work", 10: "idle"}),
                          defs.state("work", ["python3", "work.py"], "idle")])
cells.compile("machines/counter")              # 只寫 machines/counter/fsm.json；aos-fsm 吃它就能跑
print(cells.dry_run())                         # {"fsm.json": {...}}

for name in ("ann", "bob"):                    # 建置腳本：不叫 defs.main，直接 .compile(夾)
    defs.Agent("Reviewer %s" % name, system=TEXT, tools=[std.pack("look")], llm={}, fsm=cells).compile("defs/" + name)

from aos.py import agent                       # 同一個庫也能操作活的（今天就有）
agent.ctl.add("defs/ann")
```

## 具體是哪些類別與函式

| 名字 | 是什麼 | 備註 |
|---|---|---|
| `defs.Agent(description, system=, tools=, llm=, fsm=None, hooks=None, meta=None, interfaces=None, files=None)` | 一隻 agent 的定義（物件） | 參數就是今天 `defs.main` 那九個；欄位名小寫（`a.tools`、`a.hooks`…）；不給 `fsm`＝只填現成定義夾的內容檔（eca 版），照舊 |
| `物件.dry_run(folder=None, link="static")` | 算出 `{檔名: 內容}`，全部驗完才回，不寫 | 等於 `--dry-run`；有些東西要知道編譯進哪一夾才算得出來（extern 的連結、不宣告 fsm 的 eca 版），那時沒給夾＝`SpecBad` 叫你給，庫不猜 |
| `物件.compile(folder, link="static")` | 算完寫進夾，回「寫了哪些」的字串串列 | 等於 `--compile`；夾一定要明給（物件不知道自己寫在哪支檔裡） |
| `defs.main(物件)` | `agent.py` 最後一行：讀旗標、夾預設＝`agent.py` 那一夾 | 一支 `agent.py` 只交一個物件；被 `defs.load` 載入時只把物件交出去 |
| `defs.fsm(...)`、`defs.state(...)` | 名字不變；`defs.fsm` 回的東西多了 `.compile(夾, name="fsm.json")`、`.dry_run()` | 單獨編譯時寫哪一夾、叫什麼名，都由呼叫的人明寫；寫錯照舊先記著，`.dry_run()`／`.compile()` 才丟 |
| `fn.tool`、`fn.hook(事件, …)`、`fn.param`、`fn.fail`、`fn.block`、`fn.main(函數)` | 函數那一半 | [03](03-函數當工具與hook.md) |
| `defs.extern(目標)` | 這一欄編成一個連結 | [05](05-extern-symlink.md) |

寫錯怎麼報照舊：宣告時不丟，`.dry_run()`／`.compile()` 才丟 `SpecBad`（`defs.main` 把它印成一行、退 1、什麼都不寫）。

**內部（寫定義的人看不到）**：新增一支共用的底 `aos/spec_base.py`——例外類別、從檔名推名字、旗標殼、寫檔後端（暫存檔＋改名；今天只會寫文字與 json，要多會兩種：可執行的程式檔、連結）。`agent_spec` 與 `tool_spec` 都改用它，今天重複的那約 50 行就沒了。

## 邊緣

- **一支腳本編很多個時，「這份產物的原始碼是哪支」會模糊**：`defs.main` 一支只收一個物件、夾預設就是 `agent.py` 那一夾，所以照骨架寫的不受影響；建置腳本是寫的人自己選的。
- **編譯不改物件**：`.dry_run()`／`.compile()` 不動物件裡的串列與表，所以同一張 fsm、同一串工具可以放進好幾個 `defs.Agent`。物件的欄位是普通屬性，拿到之後要改可以改（`defs.load` 回來的也一樣；它裡面的相對路徑在載入時就已經換成從底那一夾算的完整路徑，之後怎麼搬都不會算錯）。
- **物件不拿來做 Python 的 class 繼承**：衍生只有 `defs.load` 一條路（N-70）。`class My(defs.Agent)` 不擋、不教、不保證。
- **寫定義那邊不載入跑指令的東西**：`aos.py` 現有的「用到才 import」照舊，import `defs`、`fn` 不會碰到活的樹。
- **`defs.Agent`（定義）跟 `aos.py.agent` 裡那個把手的類別同名不同物**：一個是寫定義、一個是活的那隻（`agent.attach("ann")` 回的）。寫的人平常碰不到把手的類別名；變數別取名叫 `agent`（會蓋掉 `from aos.py import agent` 那個模組），示意碼用 agent 自己的名字。
- **`fn` 是新名字**，而且放在入口頂層（`from aos.py import fn`）。為什麼不叫 `@defs.tool`：`defs.tool(名, 路徑)` 今天已經是「登記一支現成的工具」；而且 `tool.py` 沒有 `defs`，要「同一套寫法」就得有一個哪裡都能 import 的名字。
