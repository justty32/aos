# 現況盤點（一）：一棵新樹起來時，哪些東西算「kernel」、誰起、掛在哪、不裝會怎樣，並照使用者的二分法歸類

← [README](README.md)｜下一份：[02-可選與開關](02-現況-可選與開關.md)

路徑相對 `proto8/`。只讀程式與文件，沒起樹、沒叫模型。

## 先講結論

- **今天「灌 kernel」實際只灌一件：llm kernel**（替 agent 打電話問模型的總機）。權限／沙箱那一側**沒有任何東西隨「灌 kernel」裝上**；它們散在 daemon 本體、agent 的定義、單獨的指令裡，各自要另外開。
- **「kernel」這個詞今天其實有兩個收件地址**：問腦寄 `AOS_LLM_KERNEL`；開 proc、問「我是誰」寄 `AOS_KERNEL`，沒設就直接寄 daemon（C-47：daemon 自己就是最簡單的 kernel）。這兩個地址剛好對上使用者說的兩塊，但第二個地址今天預設是空的。
- 教學與起手範本擺法不同：教學把 llm kernel 掛成板子上的一列；起手範本與重建步驟單把它當另一台並排的 daemon。兩種都能跑。

## 一件一件列

| 件 | 是什麼 | 誰起、掛哪 | 不裝會怎樣 | 歸哪塊 |
|---|---|---|---|---|
| daemon（根） | 板子本身：表、控制信箱、limits、自動重起 | 使用者 `aos-exec root`（`templates/daemon-root/_entry`） | 什麼都沒有 | 兩塊都不是；它是底 |
| llm kernel | 總機：排隊、格數、額度、帳本、端點 | 起手範本：`llms/def/`，視窗 B `cd llms && aos-exec --stack stacks/llm def`，**另一台 daemon**（`templates/start-api/README.md:19-20`；重建步驟單第 4、6 步 `thinking/2026-11/17/重建步驟單.md:49,51`）。教學：`aos-daemon-ctl -d .stack add --auto-restart llm`，**同板子一列**（`docs/tutorial/03-灌kernel.md:12-17`，並把 `.env` 改成 `${AOS_STACK}/procs/llm`，`02-架daemon.md:13`） | `AOS_LLM_KERNEL` 沒設＝第一次問腦就 `LlmKernelMissing` 停（`templates/agent-fsm/wait.py:459-464`）；設了但沒開＝一直等、每 10 分鐘提醒（`wait.py:157`） | llm |
| `.env` 的 `AOS_LLM_KERNEL` | 指向總機的路標 | 範本寫好（`templates/daemon-root/.env:4`、`templates/start-api/root/.env:4`） | 同上 | llm |
| 端點小程式 | `llm_http`、`endpoints/litellm`（真正打 HTTP） | llm kernel 每封信掛一個 proc | 只能用 `fake` 假腦 | llm |
| llm-team | 隊用的轉發 kernel，有每日額度 | 手動，不在起手範本 | 無 | llm（但額度偏權限） |
| `AOS_KERNEL` 站 | 通用站：`allowed`、`max_running`、`limits` 夾、`users`→`sub:N`、hold（`py/tools/aos/kernel/README.md`） | 範本 `templates/kernel/daemon-kernel`（daemon 身體當站）、`procs-kernel`（一列 proc）；**起手範本都沒用** | 寄信直接到 daemon，誰都不擋 | 權限 |
| kernel_gate | 讓某隻 agent 當門，逐封點頭 | 那隻 agent 自己叫工具 `{"op":"on"}`，站跑在它的 on_clock 裡（`py/tools/agent/kernel_gate/_entry:93-107`）；pack 註明不在任何出廠定義（`py/packs/kernel_gate.json:1`） | 無 | 權限 |
| limits／`sub:N` | rlimit、cgroup、換子帳號 | **寫在 daemon 本體**（`cpp/aos-daemon/docs/09-份額.md`），表上那列寫了才套 | 不限、不換帳號 | 權限（但不在 kernel 裡） |
| aos-sandbox | 把某支工具關進 bwrap＋s6 | 按工具設定，不常駐（`py/aos/apps/sandbox/README.md`） | 工具不關 | 權限（不在 kernel 裡） |
| guard | agent 的 `before_tool` 鉤子，查路徑、信箱、指令 | 定義自己掛；README 寫「under review，先別掛」（`py/tools/agent/guard/README.md:3`），progress `wrapup-1115` 暫停 | 不查 | 權限（在 agent 裡，不在 kernel） |
| user_zone_guard | 擋寫進使用者專區 | 定義自己掛 | 不擋 | 權限（在 agent 裡） |
| 工作區邊界 | `ws_write` 擋區外、`write` 不擋（`py/tools/base/ws_write/_entry:42-59`、`write/_entry:4`） | 每支工具自己 | — | 權限（在工具裡） |
| 身分「我是誰」 | 信封 `sender`＝自己的 `$AOS_STACK`，自報不驗（`cpp/aos-util/src/proc.cpp:80-109`；C-47 續） | 寫死在寄信程式 | — | 兩塊共用的地基 |
| `_clock` | 每秒一拍的鐘 | daemon-root 表上一列（`templates/daemon-root/daemon.json:3`） | 按拍數算的鬧鐘、卡住偵測不走 | 兩塊都不是 |
| `_sweeper` | 清道夫：壓 log、清過期 | 每台 daemon 一列，llm kernel 那台也帶（`templates/kernel/llm-kernel/daemon.json`） | 錯誤記錄無限長 | 兩塊都不是 |
| 信件 | `aos-post`／`aos-mailbox`，只是檔案操作 | 不是行程 | — | 兩塊都不是 |

## 照二分法歸的結果

```
                 ┌──────────── 隨「灌 kernel」裝上 ───────────┐
 llm 那塊        │ llm kernel（llms/def）＋ .env 路標＋端點小程式 │
                 └─────────────────────────────────────────────┘
 權限／沙箱那塊   AOS_KERNEL 站、kernel_gate      ← 在「kernel」位置，但預設不裝
                 limits、sub:N                    ← 在 daemon 本體
                 aos-sandbox                      ← 在工具外面包一層
                 guard、user_zone_guard、ws_write ← 在 agent／工具裡
 歸不進去        daemon 本身、_clock、_sweeper、信件、身分自報
```

邊緣：llm kernel 的**額度與 `budget.senders`** 是「誰能用多少」，性質偏權限，卻長在 llm 那塊裡；**身分**兩塊都靠它、又誰也不擁有它。
