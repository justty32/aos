# 可能的形狀：如果「初始 kernel＝llm 件＋權限沙箱件、都可選」，現有東西怎麼歸，四種切法攤開（不排名、不推薦）

← [README](README.md)｜上一份：[02-可選與開關](02-現況-可選與開關.md)｜下一份：[04-邊緣狀況](04-邊緣狀況.md)

示意指令都是**假想的**，今天不存在。「已定的東西」指：①整塊板子只有 daemon 一個管理員、風險自擔；②同帳號沒有邊界，維持現狀只寫明；③身分照舊自報；④自訂 kernel 先不定、讓它自然長；⑤kernel 之後可能也要編譯（另一條線 [aos-compile-base-1120](../aos-compile-base-1120/) 在查）。

## 先講一個現況裡現成的對應

今天已經有兩個「kernel 地址」：`AOS_LLM_KERNEL`（問腦）與 `AOS_KERNEL`（開 proc、查表）。**llm 件＝前者那台，權限件＝後者那台站**，程式幾乎不用動就對得上。差別只在：後者今天沒人裝、範本沒寫。四種切法都從這裡長出去。

## 甲：就兩件

- **灌 kernel 時**：
  ```sh
  cp -r $AOS_HOME/templates/kernel/llm-kernel llms/def     # llm 件（可不裝）
  cp -r $AOS_HOME/templates/kernel/procs-kernel gate/def   # 權限件（可不裝）
  # root/.env 多一行 AOS_KERNEL=…/gate/…/requests
  ```
- **歸法**：llm 件＝llm kernel（含額度、帳本）。權限件＝一台站（`allowed`、`max_running`、`limits` 夾、`users`→`sub:N`，要的話加 hold）。
- **歸不進去**：guard、sandbox、`ws_write`（在 agent／工具裡，不在 kernel 位置）；daemon 本體的 limits 執行；鐘、清道夫、信件、身分。
- **要動多少**：小。範本與起手範本加一份選裝的站、`.env` 多一行、文件。
- **合不合**：合①②③④。但③讓權限件只是「規矩」：agent 把 `AOS_KERNEL` 拿掉、直接寫 daemon 控制信箱就繞過（見 04 第 7 條）。

## 乙：兩件加一個最小核心

- **灌 kernel 時**：板子買來就帶「核心」（daemon＋身分＋信箱＋鐘＋清道夫），使用者只決定兩個選裝件。
  ```sh
  aos-exec root                    # 核心：一定有
  # 選裝同甲
  ```
- **歸法**：把今天「兩塊都不是」那一堆正式叫「核心」，像 BIOS／開機程式；limits 與 `sub:N` 的**執行**留在核心（因為只有 daemon 能 fork），**策略**（誰拿什麼上限、誰換哪個帳號）放權限件。
- **要動多少**：幾乎不動程式；要改的是文件用詞（C-47「daemon 自己就是最簡單的 kernel」要跟「核心」的說法對齊）。
- **合不合**：合①（核心＝唯一管理員）。邊緣：鐘與清道夫今天可刪，算不算核心要定。

## 丙：一串可選件，llm 與權限只是常見的兩件

- **灌 kernel 時**：像發行版的最小安裝，從清單勾。
  ```json
  {"parts": ["llm", "door", "ledger-view", "clock", "sweeper"]}
  ```
  `door`＝權限站；之後可以長出「記帳件」（[aos-htop-1119](../../19/aos-htop-1119/README.md) 那種）、「團隊轉發件」（今天的 llm-team）、「沙箱預設件」等。
- **歸法**：不硬分兩塊；每件說清楚自己管哪個地址、依賴哪件。
- **要動多少**：要有一個「裝件」的做法（清單＋抄範本），或者乾脆就是文件裡一張表。如果走編譯，清單就是 kernel 的原始碼，接 aos-compile-base-1120。
- **合不合**：最合④（自然長）與⑤；最不像使用者原話的「兩個東西」。

## 丁：權限件分兩半——門在 kernel、手銬在 agent

- **灌 kernel 時**：權限件除了裝站（門），還發一份**預設設定**給之後掛上來的 agent（guard 設定、sandbox 設定、工作夾規則）；agent 的定義編譯時把它掛進去。
  ```sh
  cp -r $AOS_HOME/templates/kernel/door gate/def
  # gate/def/policy/guard.json、sandbox.json ← agent add 時自動帶上
  ```
- **歸法**：把今天散在 agent 那邊的 guard、sandbox、`ws_write` 收進權限件的「發給 agent 的那一半」。
- **要動多少**：最多。guard 還在「先別掛」（progress `wrapup-1115` 暫停），要先過那關；add 時帶設定是新機制。
- **合不合**：跟②③有張力：門加手銬才擋得住「繞過站直接寫 daemon」，但在同一個 Linux 帳號下手銬仍拿得掉（有 `self_hook` 的 agent 能拆）。

## 四種的一張對照

| | 甲 | 乙 | 丙 | 丁 |
|---|---|---|---|---|
| 使用者看到幾件 | 2 | 核心＋2 | 一張清單 | 2（權限件較厚） |
| 鐘、清道夫、身分去哪 | 沒處放 | 核心 | 各自一件或核心 | 沒處放 |
| guard、sandbox 去哪 | 留在 agent | 留在 agent | 一件或留 | 權限件 |
| 程式要動 | 小 | 幾乎不動 | 看要不要裝件機制 | 最多 |
| 跟編譯的關係 | 弱 | 弱 | 強（清單＝原始碼） | 中（發設定給 agent 編譯） |

## 真實世界的類比（點到為止）

- daemon 像 **BIOS／開機程式**：一定有、很小、把其他東西叫起來。
- llm kernel 與站像**微核心的 server**：不在核心裡，靠寄信找到，可以換、可以不裝。
- 權限件像 Linux 的 **LSM**（安全模組，SELinux、AppArmor 那類）與 **cgroup**：可選、掛在同一個核心上；aos 的 limits 已經是 cgroup／rlimit 那一層。
- 丙像**發行版的最小安裝**：先給最少，其他勾選。
