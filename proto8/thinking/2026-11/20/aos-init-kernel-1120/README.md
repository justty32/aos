# 線 aos-init-kernel-1120：「買了板子要灌的初始 kernel＝llm＋權限沙箱、都可選」的調查與發想——現況盤點、可能的切法、待裁題

← [2026-11-20](../README.md)｜原話：[00](00-使用者原話.md)

只查、只寫，沒改程式、沒起樹、沒叫模型。頂層派、線隊長交。

## 結論

```
 買板子 ── daemon（一定有；表、控制信箱、limits／sub:N 的執行、自動重起）
   │        └ 表上兩列：_clock（鐘）、_sweeper（清道夫）  ← 可刪，但有人依賴鐘
   │
 灌 kernel（今天實際只有這一步）
   ├─ llm 件：llm kernel（llms/def）＋ .env 的 AOS_LLM_KERNEL     ← 名義可選，會想的 agent 都要它
   │
   └─ 權限件：今天「沒有隨灌 kernel 裝上的東西」
        ├ 在 kernel 位置、預設不裝：AOS_KERNEL 站（procs-kernel／daemon-kernel）、kernel_gate
        ├ 在 daemon 本體：limits、sub:N（設定寫了才套）
        └ 在 agent／工具裡：guard（暫停、先別掛）、sandbox、ws_write、user_zone_guard

 歸不進兩塊：daemon 本身、鐘、清道夫、信件、身分自報（兩塊都靠它）
 跨界：llm 件裡的額度（誰能問多少）性質偏權限
```

- **二分法跟現況半貼半不貼**：今天剛好有兩個 kernel 地址——問腦寄 `AOS_LLM_KERNEL`、開 proc 寄 `AOS_KERNEL`——正好是 llm 件與權限件；但第二個地址預設是空的，真正在做權限的東西多半不在 kernel 位置，而在 daemon 本體或 agent 自己身上。
- **現在其實不可選的**：daemon；身分自報（寫死）；limits 的執行（寫死在 daemon，只有設定可選）；以及「會想的 agent 一定要 llm 件」（沒有直連模型的模式）。
- **權限件在已定的前提下是規矩不是牆**：寄件人自己決定要不要經過站，同帳號下拿掉 `AOS_KERNEL` 就繞過。
- 四種切法（就兩件／兩件加核心／一串可選件／權限件分門與手銬）攤在 03，八題待裁在 05，都可以答「先不定」。kernel 要不要編譯那半邊由 [aos-compile-base-1120](../aos-compile-base-1120/) 查，這裡只在第 1 題 c 與邊緣第 5 條指過去。
