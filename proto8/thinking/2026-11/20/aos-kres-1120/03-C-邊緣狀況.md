# C. 邊緣狀況十六條：跨體系的排前面；每條「會發生什麼、要不要你管」，挖不解

← [README](README.md)｜上一份：[02-B](02-B-對照現況.md)｜下一份：[04-D-原型](04-D-原型.md)

照通則，沒被你回答的邊緣不追問、留給實作；會改變形狀的才放進 [06 待定題](06-F-待定題.md)，下表最後一欄標「→題」。

## 跨體系（你第二段說這才是它有用的地方）

| # | 狀況 | 會發生什麼 | 要不要管 |
|---|---|---|---|
| 1 | 兩個 kernel 各有各的 schema | 請求者要先知道「這台吃什麼」。沒有統一的問法，就只能看文件或亂寄、讓 kernel 粗化。一個請求經過兩站（隊 kernel→主 kernel）時，兩站可能各粗化一次，第二站看到的是第一站改過的 | 「schema 放哪、怎麼問」會改形狀 →題 5 |
| 2 | 別的體系的請求進來 | 寄件人路徑在別人的樹上、帳號也可能不同；`budget.senders` 這類按路徑的表接不住；今天也沒有把信送進別人 kernel 的路 | 送信的路是前提、不是本題；本題只記 |
| 3 | 誰的宣稱可信 | 宣稱是自報的，可以亂報（報小一點就排前面）。昨天身分你答「照舊自報，風險自擔」。差別：身分亂報是冒充別人，宣稱亂報是自己人也會（不一定惡意，估錯也算）。kernel 有實際帳，可以事後對「說的 vs 實際」，但用不用這個對照是另一回事 | 態度要不要跟身分同一條 →題 6 |
| 4 | schema 改版 | kernel 改了放話內容，舊請求者照舊寫；照你的想法它們就變成「不守的」，靠粗化接住。改版若是收緊（以前收的現在不收），舊請求會被當看不懂 | 留給實作 |

## 頂層先講的五個

| # | 狀況 | 會發生什麼 | 要不要管 |
|---|---|---|---|
| 5 | 每個請求都叫 agent 看 | 每封多一次問腦：慢（秒級）、花 token；agent 在回合中或睡著時站不跑（今天 kernel_gate 就是這樣）。頂層猜的形狀是 agent 寫規則、規則跑、agent 定期回頭改——**你還沒確認** | →題 2 |
| 6 | 看不懂的宣稱 | 三條路：當 0、當滿值、當「沒宣稱」照預設排；或拒。原型裡同一個規則檔換一個開關，例 2 就從「看不懂」變成 0.0075（[04](04-D-原型.md)）。看不懂時怎麼對待直接決定亂寫的人吃虧還是佔便宜 | 留給實作；原型示範了這是一顆開關 |
| 7 | 值是檔案路徑 | kernel 去讀檔＝寄件人叫 kernel 讀任意檔；同帳號下 kernel 讀得到別人讀不到的東西嗎？今天全部同一個 Linux 帳號，沒差；多人多帳號時就是「請 kernel 幫我讀你的檔」。路徑還是寄件人那棵樹的，跨機就不存在 | 留給實作；原型一律不讀 |
| 8 | 公式寫錯餓死某類請求 | 例：某寫法被算成 1.0（滿值），永遠排最後。今天 llm kernel 有等久升級（預設 3 格升一級、不封頂），只要粗化結果最後還是走級數，就不會永遠餓死；若改成直接照 float 排、沒有升級，就會。另一面：寫錯也可能讓某類永遠插隊 | 留給實作 |
| 9 | 改自己改的是什麼、改壞怎麼退 | 改定義＝要重新編譯／重掛；改執行期規則檔＝下一封就生效（今天 kernel.json、規則檔每輪重讀）。改壞：規則檔有 `version`，帳上記「這封是哪一版算的」，就能找出哪段時間算錯、退回上一版；不記就查不出 | →題 3 |

## 其餘

| # | 狀況 | 會發生什麼 | 要不要管 |
|---|---|---|---|
| 10 | 粗化丟掉資訊，帳要記粗的還是原樣 | 只記粗的：之後改公式就沒法重算舊帳、也沒法拿來「改進自己」。原樣＋粗的＋規則版本都記：帳變大（今天 ledger 不記 body，宣稱多大就多大） | 留給實作；原型的帳記三樣 |
| 11 | 細化補出來的值是猜的 | 你已說「這會有問題，但反正agent會自己處理，使用者也會看」。事實：`cost:43` 拆成 token、time，兩個都是猜的；帳上若不標「這是猜的」，之後對帳會把猜的當成請求者說的。原型的產出有 `guessed` 欄 | 不追問 |
| 12 | 「經驗」存在哪、換一隻帶不帶得走 | 存在 agent 的 stack（記憶）：換一隻 kernel 就沒了，也只有它看得懂。存成規則檔：可抄、可給別台、可 git。存在 agent 的定義：要編譯 | →題 3 |
| 13 | 使用者的建議怎麼給 | 寄一封信給那隻 agent（它可以不聽）、直接改規則檔（agent 下次可能又改回來）、或在規則檔裡有「使用者鎖定」的段落 | 留給實作 |
| 14 | 跟「kernel 之後也要編譯」碰 | 若規則檔是 kernel 定義的一部分，agent 改它＝改定義，跟「不手改定義、用 `self_*` 改自己那份」的規矩要對齊；若規則檔在 stack，就是執行期狀態，不進編譯（[aos-compile-base-1120](../aos-compile-base-1120/README.md)） | 隨題 3 |
| 15 | 跟「初始 kernel 由哪些件組成」碰 | 資源基底是灌 kernel 就有，還是另一個可選件？llm 件已經有帳與額度；宣稱欄若只加在 llm 件，起停那站沒有（[aos-init-kernel-1120](../aos-init-kernel-1120/README.md)） | 隨題 1 |
| 16 | 同帳號沒有邊界 | 任何 agent 都能改 kernel 的規則檔、帳本、schema；agent 自己改自己的規則，跟別人改它的規則，檔案層看不出差別。單人時是你承擔的風險；多人時就是另一個人改了你的排程 | 跟 11-19「同帳號沒有邊界」同一條，不另問 |
