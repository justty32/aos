## 先講結論

1. **資源基底的九個零件**（宣稱、kernel 是 agent、只讀想看的 key、放話 schema、粗化、細化、收集資料、改進自己、使用者建議、自己另算記帳）拆在 [01](01-A-拆零件.md)，另列七處有兩種讀法的地方。
2. **今天就做得到的**：請求多寫一個 key 不會被拒（兩種 kernel 都是）；問腦總機的 `before_verdict` hook 讀得到它、可以照規則檔算數；`before_reply` 看得到實際 token；帳本本來就記實際用量。單人版用一支 hook 就成立（[02](02-B-對照現況.md)）。
3. **缺的**：放宣稱的約定位置；帳不收宣稱，對不起「說的 vs 實際」；schema 放哪、怎麼被問到沒有慣例；跨體系送信、認人都沒有。
4. **「kernel 一開始是 agent」**：起停那站今天就能是 agent（`kernel_gate`）；問腦總機不是 agent、也不能扣信等人點頭；agent 要管問腦請求時，自己的問腦信會排進自己的隊而卡住（雞生蛋）。
5. **原型**：你那四種宣稱分別變成 `0.1721`、看不懂（`out` 是路徑，沒讀）、`0.2461`、`0.2`（守 schema）；規則檔只改一個開關（v2），第二種變 `0.0075`；`cost:43` 細化成 token 258、time 1720，兩個都標 guessed。公式是隨手寫的示意（[04](04-D-原型.md)）。
6. 你說價值在多人、多體系：邊緣狀況跨體系的排前面（[03](03-C-邊緣狀況.md)），形狀標了單人就值得的與等多人才有意義的（[05](05-E-形狀.md)）。
7. **排程介面**：你說「就是kernel骨架本來就有的東西」——**一半對**。骨架（兩種 kernel 共用的 `round.py`）有「誰先」的口（包的 `order`）與「放不放」的口；hook 能逐封改判決、扣著不放（扣著只在起停那站）。但誰先的規則兩包各寫一份，只開給寫 Python 包的人；三個 hook 都只看一封，`order` 也在 hook 之前就跑完。另一個事實：**先後只有在有信要等時才有差**，讓信等的是包裡的格數。問腦總機那套搬到骨架會卡三處（[07](07-排程介面.md)）。
8. **九題等你**，每題都可以答先不定（[06](06-F-待定題.md)；1～7 資源基底、8～9 排程介面）。
