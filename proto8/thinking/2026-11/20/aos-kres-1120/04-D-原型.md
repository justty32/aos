# D. 小原型（不進 repo）：你原話的四種宣稱經一份規則檔粗化成 0～1 的數或「看不懂」，再加一個把 cost:43 細化的例子；公式是隨手寫的示意

← [README](README.md)｜上一份：[03-C](03-C-邊緣狀況.md)｜程式全文：[04-D-原型-程式](04-D-原型-程式.md)｜下一份：[05-E-形狀](05-E-形狀.md)

放在公司 WSL 的 `~/.aos/scratch/aos-kres-1120/`，只用 `python3` 標準庫；沒起 aos 行程、沒叫模型、沒裝東西。**規則裡的數字（滿值 1000 token、60 秒，權重 0.7／0.3、細化的拆法）全是隨手寫的示意，不是提案**；你的原話公式是 `token*10+time`，這裡改成除以滿值再加權，只是為了讓結果落在 0～1。

## 夾裡有什麼

| 檔 | 是什麼 | 對到你哪個零件 |
|---|---|---|
| `schema.json` | 對外放話：「我只看 `cost`，0～1 的 float」 | 4 放話 |
| `rules.json` | 粗化規則（資料檔）：去哪找 token、去哪找時間、單位怎麼換、滿值與權重、缺一半時怎麼辦 | 5 粗化；「改進自己」＝改這份、`version` 加 1 |
| `rules_v2.json` | 同一份只改一個開關（缺一半當 0）、版本 2 | 7 改進自己的樣子 |
| `claims.jsonl` | 五個請求的宣稱：你原話四種＋我加的一個 `{"cost":"cheap"}` | 1 宣稱 |
| `coarsen.py` | 讀宣稱、照規則算，看不懂的寫進 `unreadable.jsonl` | — |
| `unreadable.jsonl` | 收集到的看不懂樣本，每筆記是哪一版規則判的 | 7 收集資料 |
| `refine_rules.json`、`refine.py` | 細化：kernel 吃 `cost:{token,time}`，收到粗的就拆開，補出來的標 `guessed` | 6 細化 |

## 跑出來的樣子

```
--- 規則 v1（缺一半就算看不懂）
r1 {"cost":{"token":{"in":123,"out":122}},"time":122,"time_unit":"ms"} -> cost 0.1721  (tokens=245 ms=122)
r2 {"cost":{"token":{"out":"/home/x/ws/out_estimate.json"}},"time_ms":1500} -> 看不懂：cost.token 的 out 不是數字（可能是檔案路徑，沒去讀）
r3 {"cost":{"token":123,"time":"32s"}}                                -> cost 0.2461  (tokens=123 ms=32000)
r4 {"cost":0.2}                                                       -> cost 0.2     (守 schema，直接用)
r5 {"cost":"cheap"}                                                   -> 看不懂：找不到 token、也找不到時間
--- 規則 v2（只改一個開關：缺一半當 0）
r2 ... -> cost 0.0075  (tokens=None ms=1500)      ← 其餘四筆不變
```

例 2 你原話沒給 `time_ms` 的值，這裡填 1500；`out` 的路徑也是我編的。

`unreadable.jsonl`（v1、v2 各跑一次後）：

```
{"id":"r2","rules_version":1,"claim":{…},"why":"cost.token is {\"out\": …}, no reader fits; … (maybe a file path; not opened)"}
{"id":"r5","rules_version":1,"claim":{"cost":"cheap"},"why":"no token field found; no time field found"}
{"id":"r5","rules_version":2,"claim":{"cost":"cheap"},"why":"no token field found; no time field found"}
```

細化（kernel 吃 `cost:{token,time}`）：

```
{"cost":43}                    -> {"token":258,"time":1720}  guessed: token, time   （數字當點數，六四拆）
{"cost":{"token":13,"time":123}} -> 原樣                    guessed: 無
{"cost":{"token":13}}          -> {"token":13,"time":1000}  guessed: time           （缺的補預設值）
{"cost":"a lot"}               -> 看不懂
```

## 從原型看得到的

- **「agent 改進自己」可以小到只改一個鍵**：v1→v2 只改 `missing_part`，例 2 的命運就變了。看不懂樣本帶著規則版本，回頭看得出「改了之後哪些從看不懂變成看得懂」。
- **粗化會丟東西**：r1 的 in／out 分別多少、r3 的「32s」這種原寫法，粗化後只剩一個數；要回算就得在帳上留原樣（[03](03-C-邊緣狀況.md) 第 10 條）。
- **細化補的值一定要標**：`cost:43` 拆出來的兩個數全是規則猜的。
- **讀法是一串「依序試」的讀者**：`cost.token` 是數字就用、是 `{in,out}` 就加總；時間看 `time`＋`time_unit`、`time_ms`、`cost.time`。新寫法出現時就是多加一個讀者——這是 agent 能自己改的那一段。
- 沒做的：沒接進 kernel（沒掛成 hook）；帳本、使用者建議、schema 怎麼被問到都沒做。

## 帳上一列可能長的樣子（只是示意，沒寫成程式）

```json
{"id": "r1", "claim": {"cost": {"token": {"in": 123, "out": 122}}, "time": 122, "time_unit": "ms"},
 "coarse": {"cost": 0.1721}, "rules_version": 1, "guessed": [],
 "actual": {"usage": {"prompt_tokens": 0, "completion_tokens": 0}, "elapsed_ms": 0}}
```

`actual` 那半今天 llm kernel 的 `ledger.jsonl` 已經有；`claim`、`coarse`、`rules_version`、`guessed` 是今天沒有的。
