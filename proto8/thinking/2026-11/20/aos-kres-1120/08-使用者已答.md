## 第 1 題（06-F 第 1 題）：kernel 資源基底，aos 內建要給到哪一層？

當時的選項：

- **只給位置**：請求裡約定一個放資源宣稱的 key，帳上多記原樣宣稱——最小；粗化、schema 全由各 kernel 自己來，別人的 kernel 長什麼樣沒有共通點。
- **再給格式**：schema 放哪、怎麼問到，粗化規則檔與帳一列的格式——不同人的 kernel 與請求者讀得懂彼此；要先定一批格式。
- **連流程都給**：收集樣本、定期回顧、改規則與退版——「agent 改進自己」開箱就有；要多一個回顧的時機，跟 hook 那線的「loop 層通用點」綁在一起。
- **先不定**。

他在 Other 打：

> 給位置和格式。當然，這都是可選的，kernel自己可以選擇不給。

線的解讀：大致是「再給格式」那一格（位置＋格式，不含流程），另外加一條：位置和格式都是 aos 提供的選項，一台 kernel 可以不放話、不收宣稱。「kernel自己可以選擇不給」指的是 kernel 可以不給 schema、不照格式，還是連「位置」都可以不認，線沒有把握，沒追問。

## 第 2 題（06-F 第 2 題）：每封請求進來時，誰來判這份資源宣稱？

當時的選項：

- **agent 寫規則、規則跑**：agent 寫規則、規則每封跑、agent 定期回頭改——平常快、不花 token；規則跟不上新寫法的那段時間會看不懂。
- **agent 每封親自看**：最能接怪寫法；每封一次問腦，慢、花錢，agent 回合中整站不動。
- **使用者寫規則、agent 只建議**：你握著；你不在時新寫法一直看不懂。
- **先不定，各 kernel 自己選**。

他選：「先不定，各 kernel 自己選」

## 第 3 題（06-F 第 3 題）：「agent 改進自己」改的是什麼、經驗存在哪？

當時的選項：

- **stack 裡的一份規則檔**：放在 kernel 的 stack（執行期）——下一封就生效、有版本可退；換一隻 kernel 要自己抄過去。
- **kernel 的定義，改完重新編譯**：規則寫在 kernel 的定義裡，改＝重新編譯——跟 agent 那套一樣整齊、可 git；每改一次要編譯、重掛。
- **留在 agent 的記憶裡**：留在 agent 的記憶（它的 stack 筆記），判斷時參考——最自然；別人看不懂、換一隻就沒了、改壞了沒版本可退。
- **先不定**。

他選：「先不定」

## 第 4 題（06-F 第 7 題）：現在只有你一個使用者，這個資源基底現在要做到哪？

當時的選項：

- **只留紀錄**：只留這份紀錄，等真的有多人、多體系要合作再說。
- **先做最小那層**：先做最小那層（第 1 題 a）：單人也有用，帳上對得起「說的 vs 實際」。
- **把原型接成 hook 試一次**：在乾淨複本上把粗化原型接成問腦總機的一支 hook，跑一次看手感。不改程式，只是試，不留成功能。
- **先不定**。

他選：「把原型接成 hook 試一次」
