# A. 把他的想法拆成九個零件，每個引原話；只拆不改意思，有兩種以上讀法的另列七處

← [README](README.md)｜上一份：[00](00-使用者原話.md)｜下一份：[02-B-對照現況](02-B-對照現況.md)

## 零件

| # | 零件 | 一句白話 | 引他哪一句 |
|---|---|---|---|
| 1 | 資源宣稱 | 請求裡附一塊 json，說「我大概要用多少」，形狀不強制 | 「他一看請求，發現裡面所宣稱的資源需求是{"cost":…}」「多種多樣」 |
| 2 | kernel 一開始是 agent | 收請求、判斷的是一隻會想的 agent | 「比如一個kernel，他一開始是一個agent，然後他開始收請求」 |
| 3 | 只讀想看的 key | 不認得的 key 就當沒看到；也可以寫嚴格 | 「可以只讀自己想看的key，所以agent這邊在寫程式的時候就可以比較舒服，當然，也可以寫得比較嚴格」 |
| 4 | 對外放話的 schema | kernel 公布「我看資源物件裡的 cost，是 0～1 的 float」 | 「agent可以一邊向外放話說，他就是看資源obj中的cost，並且那個cost會是float，也就是提供一個json schema」 |
| 5 | 粗化 | 細的、奇形怪狀的宣稱，用公式壓成 kernel 看得懂的一個數 | 「可以用某公式(token*10+time)，將其粗化成cost:0.2這樣」 |
| 6 | 細化 | 反方向：只給一個數，kernel 拆成自己吃的細形狀；補出來的值會有問題，交給 agent 與使用者看 | 第三段「有人可能只丟一個cost:43，然後kernel他本身吃cost:{token:13,time:123}，他可能會自己把cost:43細化成...」 |
| 7 | 收集資料、改進自己 | 看過一段時間的請求後，改自己的判斷方式 | 「agent會收集一段時間的資料，然後去改進自己，讓自己適應這些東西，這就是agent適應性」「經歷幾次後會有經驗」 |
| 8 | 使用者給建議 | 公式 agent 提，使用者可以出意見 | 「這個公式會是agent自己提的然後使用者可能會給一些建議」 |
| 9 | 自己另算、記帳 | 宣稱只是宣稱；實際跑完 kernel 自己量、記一筆 | 「實際的資源需求，可能kernel之後幫它跑的時候會自己另算，並在自己的本本上記一筆」 |

外加一個**目的**（不是零件）：「方便後續其他使用者規劃排程或管理」，第二段補成「在多使用者、一大堆體系需要合作的時候……就很有用了」。

## 有兩種以上讀法的地方（要拿去問他的在 [06](06-F-待定題.md)）

1. **「一開始是一個agent」的「一開始」**：(a) 起步時是 agent，之後可以慢慢變成不靠腦的規則或程式（呼應 11-07「逐步削減LLM的級別」）；(b) 它本來就是 agent、一直是，「一開始」只是講故事的順序。→ 跟頂層那個「agent 寫規則、規則跑」的猜測綁在一起（06 第 2 題）。
2. **「改進自己」改的是什麼**：(a) 改它自己的定義（像 `self_*` 工具改自己）；(b) 改一份規則檔（原型就是這種）；(c) 只是它記憶裡的經驗（stack 裡的筆記），下次判斷時參考。→ 06 第 3 題。
3. **「基底」提供到哪**：(a) 只提供「請求裡可以放一塊資源 json」＋一本帳；(b) 再提供 schema 怎麼放話、粗化規則怎麼寫的格式；(c) 連「收集、回顧、改進」的流程都提供。他說「規劃這樣一個kernel資源基底框架」，沒說到哪一層。→ 06 第 1 題、[05](05-E-形狀.md)。
4. **`time` 跟 `cost` 是不是同一層**：他第一個例子 `time` 寫在 `cost` 外面、跟 `cost` 同級；第三個例子寫在 `cost` 裡面。他說「同級的key也是可以啦」——讀成 (a) 宣稱的整塊都算資源，`cost` 只是其中一個 key；或 (b) 資源都該在 `cost` 底下，同級的是不守規矩的寫法、要 agent 收。原型照 (a) 去讀，兩者對粗化結果沒差，對「放話的 schema 管多大塊」有差。照通則不追問，留給實作。
5. **值是檔案路徑**（例 2 的 `out`）：(a) 意思是「詳細數字在這個檔裡，自己去讀」；(b) 只是舉例說「值可以是任何怪東西」。原型照 (b) 不去讀檔、當看不懂；(a) 會碰到權限（[03](03-C-邊緣狀況.md) 第 5 條）。
6. **「使用者交代說，你的排程就是看cost值」**：schema 的內容是使用者給 kernel 的交代，kernel 照著放話。讀成 (a) schema 一律由主人定、agent 只負責收不守的；(b) agent 也可以自己改 schema（例如發現大家都寫 token，乾脆改收 token）。→ 06 第 4 題。
7. **宣稱拿來做什麼**：他說「規劃排程或管理」。讀成 (a) 只影響先後（排程）；(b) 也影響放不放、扣多少額度（管理）。今天 llm kernel 的額度是事後照實際用量扣（[02](02-B-對照現況.md)），宣稱若要拿來「先扣」是另一回事。昨天第 1 題「管多深」他答先不定，本題同類，不另問。
