# aospl：通用循址、鴨子型別、元介面（11-26 早，公司）

← [2026-11-26](README.md)｜前情：[daemon當容器-1125](../25/daemon當容器-1125.md)（做減法）、[9p-proc-1125](../25/9p-proc-1125.md)

使用者原話逐字在 [9p-proc-1125](../25/9p-proc-1125.md) 第 40～45 段（接著前一天的編號抄）。這份只留整理後的原意、定了的、還沒定的。

## 使用者說的（照原意整理）

- **aos-exec**：它是一支普通程式。「資料夾裡有 `_entry` 或 `_entry.json`，你就可以被執行」是一份介面；符合的，aos-exec 就能用。先只考慮資料夾，不考慮 JSON。（第 41 段）
- **介面**：核心就一句——你是一個資料夾，或一個能用通用循址字串存取底下東西的檔（例：`aaa.json/yyy/zzz`）；需求者能透過循址字串存取（讀、寫）它要的東西，你就符合它認知中的那份介面。（第 41 段）
- **介面宣告檔**：第一個要定的介面。需求者看這個檔就知道你支援什麼，不用一個一個試。這是軟性的：宣告了做不到也沒關係，風險自己承擔。資料夾裡必須有 `interfaces`，可以是檔或資料夾，先談檔。（第 42 段，訊息斷在「第一版標準規範中，規定」）
- **通用循址字串**：在 Plan 9「萬物皆檔案」上，地址的寫法是 `xxx/yyy/zzz`，也就是 Unix 路徑。用字串不用數字（Lisp 那種「數字/數字/數字」人不好懂）。（第 43 段）
- **參考 Lua**：「把它視作 Lua」是口號，實際是設計特性時參考 Lua 的概念，透過同像性去用。例：介面在 Go 是 interface、在 C++ 是 virtual class，在 Lua 只要 table 裡有這個，你就是那個（鴨子型別）。（第 43 段）
- **aospl**（aos programming language）：以通用循址格式為基礎的 aos 程式語言，不限於檔案系統，存取得到的都算在 table 裡。proc 也能這樣存取，所以循址字串同時承擔記憶體位置與命名。（第 43 段）
- **佈局**：一個能循址存取到的元素的集合；檔是一種元素，存取到 JSON 裡的數字、布林等也算。佈局符合指定格式，你就是那個東西。（第 43 段）

## 使用者整理的一串（第 46 段）

1. Unix 路徑定為 **aos 通用循址格式**。
2. 照 Plan 9 的「一切都是檔案」，在 Linux 上透過掛載或其他手段，任何東西（byte、JSON……）都能弄成通用循址格式存取得到的東西。
3. 在通用循址格式上，所有存取得到的東西都是 **aoslua（aospl）** 的運作基礎：`xxx/` 底下有東西的叫 **table**；`xxx/__meta` 是這個 table 的**元表**，放一些特別的資訊。
4. 這是 aoslua 的看法；有人用別的手段存取，自然可以忽視 `__meta` 這些。

## 定了的

1. **`xxx.json#/yyy` 不用拿掉 `#`。** `xxx/yyy/zzz` 是通用規則，`xxx.json#/yyy` 本身也符合通用規則，只是 aos-exec 用特殊方式解析；不認得的程式會把它當成「名為 `xxx.json#` 的資料夾底下的 `yyy`」，這是自己承擔的風險。（第 44 段）
2. **陣列從 0 數。**（第 44 段）
3. **存在＝存取得到。** Plan 9 的基本檔案操作訪問得到就是存在，訪問不到就是不存在。限時內訪問不到算不算不存在，由需求者各自決定（有人當成只是阻塞、還在；有人嚴格當成不在），都可以。（第 44 段）
4. **「找不到就去別處找」也是一種介面，所以要有元介面，統一放 `xxx/__meta`。** 它是參考用的：普通程式不認得，aos 的程式會看。例：`aos mkdir` 會去看 `xxx/__meta/__newindex`。命名直接拿 Lua 的，連 table 一起抄。（第 45 段；前一步是 eca-aos 講 Lua 的 metatable：`__index` 是表＝疊加、是函式＝現算，`__newindex`＝寫入轉到別處，`rawget`＝跳過轉手看本體）

5. **`__` 開頭的名字保留給 aos**，一般資料不要用。（第 46 段答 eca-aos 的建議「好主意」）
6. **讀 `__meta` 本身不經過轉手**（不走 `__index`），免得繞死。這是規範，之後實作要遵守。（第 46 段）
7. **用 `__call` 取代 `_entry`。** `__meta` 裡大多是參考用的：aos 的標準實作會遵守，其他人遵不遵守沒差。（第 46 段，「之後再說，我建議」）
8. **寫概念時直接拿 table 介紹**，再說明在 aoslua 下背後的意涵。table＝底下有東西能循址存取的（資料夾、JSON 物件、JSON 陣列、活著的 proc 擺出來的目錄）；走到底的一個檔或 JSON 裡的一個值是元素。（第 46 段答「對」）

9. **「單元」改叫元素（element）。**（第 48 段）
10. **`__meta` 先留這九個（參考 Lua 5.4 的 metatable）：** `__index`（找不到時去哪找或叫誰算）、`__newindex`（新建時怎麼辦）、`__call`（怎麼執行，取代 `_entry`）、`__pairs`（列出時看到什麼）、`__name`（是哪一種東西）、`__description`（Lua 的 `__tostring` 改名；一句給人看的說明）、`__metatable`（保護元表）、`__gc`（被刪時的收尾）、`__mode`（裡面的東西隨時可以清掉）。不收：`__len`、`__close`、比較與算術、位元、`__concat`。`__interfaces` 之後再說，會是 aoslua 標準的一部份。（第 47、48 段）

11. **aoslua 的基本操作八個**（參考 Plan 9 的 9P 請求）：走（walk）、列（list）、讀（read）、寫（write）、建（create）、刪（remove）、看屬性（stat）、執行（exec）。改名第 49 段先說算進去，第 50 段改成「用介面宣告」，不算基本操作。九個 `__meta` 大致對上：走到不存在的名字→`__index`、建→`__newindex`、列→`__pairs`、執行→`__call`、刪→`__gc`、看屬性→`__name`／`__description`（之後可以加 `__stat`）、改 `__meta`→`__metatable`；讀寫已經存在的元素跟 Lua 一樣不經 `__meta`。（第 49、50 段）
12. **改名、Linux 比 9P 多的操作（symlink、監看、鎖……）不算基本操作**：碰到 `.json` 這類檔就不好用；要的可以自己提供實作，並在介面裡宣告。（第 49 段）
