# 邊緣狀況：路徑裡的中文與斜線、重名、改字、表格、正本、生成物、8 KB 拆檔、token 量

← [README](README.md)｜上一份：[06-往返與最短解](06-往返與最短解.md)｜下一份：[08-可能的樣子與題](08-可能的樣子與題.md)

標「實跑」的是用原型在暫存夾跑過的；其餘是讀檔或推得的。

## 路徑本身

1. **中文與空白**（實跑）：`md_get edge.md '#/規劃 A/兩個 字 有空白'` 拿得到。JSON 指標本來就收任何字。但同一節在 GitHub 錨點是 `#兩個-字-有空白`——**md 世界已經有一套路徑（錨點），規則跟 JSON 指標不同**，兩套並存時人會混用；在 shell 裡還要記得加引號。
2. **標題裡有 `/`**（實跑）：`## a/b 斜線` 用 `#/規劃 A/a/b 斜線` 拿不到，被切成兩層。要照 JSON 指標寫 `a~1b 斜線`，人不會這樣想。
3. **重複標題**（實跑）：查詢拿到第一個；轉成 json 時第二個要改名（原型改成 `重複 (2)`），GitHub 錨點是加 `-1`。兩邊改名規則不同；而且只要前面那個被刪，後面那個的名字就變了。
4. **標題改字**：路徑斷，**不報錯，只是指不到**。知識庫今天的鍵是 `[a-z0-9_-]` 的短英文（`stack`），文章標題是英文長句（`What is in your stack`），拿標題當鍵等於把路徑換成長句。repo 裡人寫的 md 連結也有同樣問題，STRUCTURE 拆檔時特地留 `<a id>` 保住舊錨。
5. **超過六層**：md 標題只有六級；json 沒有上限。
6. **程式碼區塊裡的 `#`**（實跑）：regex 讀法把 ```` ```sh ```` 裡的 `# 這不是標題` 當成標題，後面全部錯位；`cmark` 讀對。知識庫頁裡大量有 ```` ```json ```` 與 ```` ```text ```` 例子，這條一定會碰到。

## 內容

7. **表格裡換行與直線**（實跑）：換行寫 `<br>`、`|` 寫 `\|`，三份 wf-table 來回列數與內容全對；`self-history-range` 有 3 格含 `|`。但 GitHub 上 `` `a|b` `` 這種行內程式碼裡的 `|` 也要跳脫，人寫時容易漏，漏了那一列就多一欄。
8. **很長的值**：thinking 夾裡最長一格 3,248 字（`decide_20261113_wu-r2`），表格一列 8,379 bytes（[05](05-互轉樣本.md)）。表格不適合，只能卡片。
9. **型別**：md 裡 `3`、`true`、`"3"` 長得一樣，轉回來全是字串。daemon 讀的設定（`loop.json` 這類）有數字與布林，md 化會掉型別。
10. **空物件、空陣列**（實跑）：沒字可寫，轉成 md 就消失（`live-lists.json` 的 `skeleton/open: {}`）。
11. **字串陣列兩種意思**：aos 規矩「全字串陣列＝一段文字」，但 `columns`、標籤清單是名單；轉 md 時兩種該用不同寫法（段落還是清單），光看形狀分不出來。另外 md 裡單一換行在預覽裡會被併成一行，「一行一個元素」的段落渲染出來是一整坨，除非每行後面加兩個空白或空一行。

## 寫的人

12. **AI 寫 md 時不守格式**：多一層標題、欄位清單改用 `：`（全形冒號）、表格少一欄。今天 json 寫錯是「解析失敗」，會報錯；md 寫錯是「結構不一樣」，不會報錯。要嘛另有一支檢查（像 `index_check.py` 對 `_index.json` 那樣），要嘛接受「指不到就是指不到」。
13. **工具往回寫與 AI 同時改**：`aos-json set` 今天只重寫變了的那塊、一次原子寫入；md 往回寫一節通常是整份重印，跟同時在改這份的人更容易撞。

## 兩種格式並存

14. **誰是正本**：`data-files.md` 已有一條「同一份東西不同時存在 md 與資料檔」。若 md 和 json 都放進 repo，就要寫明哪份是生成的，否則人改了生成那份，下次被蓋掉。
15. **生成物進不進 git**：前例是 `_index.json` 與 code map——生成、進 git、只由排隊跑、各線不手改。進 git 的好處是 GitHub 看得到；壞處是每次改都兩份 diff。不進 git 的話，GitHub、手機上就看不到 md。
16. **改了正本忘了重生**：排隊會重跑；但排隊之外（agent 執行期、在樹裡直接改知識庫）不會。知識庫「存檔即生效」，執行期生成物會舊。

## 8 KB 分檔規矩與路徑

17. json 這邊拆檔有 `$ref`：`me.json#/self_tools` 拆走後原位留 `{"$ref": "me/self_tools.json"}`，帶 `follow` 的工具照樣拿得到——**路徑不變**。
18. md 這邊拆檔（STRUCTURE 拆檔做法：按 `##` 拆成 `x/01-….md`）路徑會變：`x.md#/某節` 變成 `x/02-某節.md`。今天靠在原檔留 `<a id>` 讓舊錨跳得過去，但「用標題路徑查」的工具要另外懂這種留路，否則拆一次就斷。
19. [03](03-做法.md) 己（文章一篇一個 .md 檔、名字留在 json）剛好讓 8 KB 規矩落在「一篇」上，拆的時候路徑走 `$ref`，不碰 md。

## token 量（實量 bytes；這台沒有 Claude 的分詞器，只能看大小）

| 檔 | json | 轉成 md | 差 | json 裡的 `\n`、`\"` 跳脫 |
|---|---|---|---|---|
| 知識庫 `aos/brain.json`（註解） | 5,810 | 5,756 | −1% | 62 |
| 知識庫 `aos/me.json`（註解） | 7,924 | 7,912 | 0% | 165 |
| 知識庫 `aos/kernel.json`（註解） | 17,468 | 17,197 | −2% | 289 |
| `逐項表.json`（表格） | 10,105 | 7,245 | −28% | 0 |
| `逐項表.json`（卡片） | 10,105 | 9,428 | −7% | 0 |
| `wf/progress.json`（樹） | 61,752 | 58,429 | −5% | 18 |

- **知識庫改成 md，大小幾乎不變**：它本來就是 md，省的只有跳脫與幾個引號。外面量到的「md 比 json 省一半」是指每列重複鍵名的資料（[04](04-外面現成的.md)），對應這裡的表格那列。
- **agent 讀的量差在「一次讀多少」，不在格式**：今天 agent 走 `index_view` → `json_get` 一個鍵，一次拿 1～3 KB（例 `aos/brain.json#/priority` 2,762 bytes）。改成 md 後如果沒有「拿一節」的工具，就是 `read` 整份 8 KB 左右；有的話一樣。
