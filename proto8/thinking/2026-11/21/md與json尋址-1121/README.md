# md 與 json 尋址（11-21 發想）：做得到，最短的路看他在哪裡看檔；知識庫本來就是 md 包在 json 裡

← [2026-11-21](../README.md)

使用者 11-21 下午問「AI 主要生成 markdown，工具讓 .md 適應 json 尋址；.md 和 .json 能不能互轉」，線 `top-1121-mdjson` 做。**只發想**：讀檔、在暫存夾寫原型實轉、查外面的工具、挖邊緣狀況；沒改程式、範本、知識庫、`wf/`，不替他選。原話見 [00](00-使用者原話.md)。

## 先講結論

1. **做得到。** md 天然有標題、清單、表格，能對到 json 的鍵、陣列、物件陣列；外面也有現成的（`mq` 能用標題路徑查、改、寫回一節；`mdq` 只查；remark／pandoc 要寫程式）。卡點不在「轉不轉得過去」，在**名字從哪來**：拿標題字當鍵好看但改字就斷，另寫一個名字穩但多一行。
2. **知識庫今天已經是「json 外殼、md 內容」**：156 份裡 244 個值本身就是一整篇 md。json 只負責給它一個名字（`aos/me.json#/stack`），難看是因為 md 被壓成一行、換行變 `\n`。
3. **看的程式已經有一支**：`aos-json-view`（11-13）在終端已經把 json 印得像 md。缺的是在編輯器、GitHub 直接打開時好看。所以「我還要特別用程式去看」的最短解，看他平常在哪裡打開檔（題 2），可能只是一個旗標、一份生成的影子 md，或把長文字寫成字串陣列。
4. **互轉**：json → md 好不好看看形狀（「鍵 → 一句」「鍵 → 一篇文章」很好看，寬表長格子用表格很糟、用卡片可以）。md → json 只要 md 裡有明寫的結構就幾乎全回來：知識庫 111 份頁來回，110 份一字不差。
5. **token**：知識庫改成 md，大小只差 0～2%（本來就是 md）；表格那種資料 md 表格少 28%。agent 讀多少，差在有沒有「只拿一節」的工具，不在格式。

## 今天 aos 的尋址

八種，[01](01-現況-aos今天的尋址.md)：統一路徑（JSON 指標）、`$ref`、`$env`、`AOS_CF`／`AOS_CO`、index（`index_view`）、`tabledb.py`、`index_gen.py` 取一句話（**已經會讀 md 的第一個標題**）、md 錨點（人在用）。前六種全要求來源是 JSON；index 能描述一份 .md，但進不了 md 裡面。

## 七種做法各一句（[03](03-做法.md)）

- 甲 讀時轉換：`json_get` 直接吃 `x.md#/標題`，標題＝鍵。
- 乙 md 正本＋排隊生成 json 影子：現有工具一個都不用改。
- 丙 md 裡每段前一行 `<!-- #/鍵 -->`：名字穩，來回實測幾乎一字不差。
- 丁 只做「用標題路徑拿一節」的查詢工具：最小，不往回寫。
- 戊 json 照舊、另產 md 給人看。
- 己 json 留骨架、文章拆成獨立 .md：`$ref` 要學會指 md。
- 庚 不轉，換看的地方（終端已有、編輯器與 GitHub 缺）。

## 這條線替他做的選擇

- 「aos index」讀成 `index_view`＋`_index.json` 那套（找不到叫 `aos-index` 的指令）。
- 原型用三種轉法（樹、卡片、註解），抽的樣本是知識庫 `aos/me.json`、`brain.json`、`kernel.json`，thinking 的 `逐項表.json`、`decide_20261113_wu-r2.json`、當天 `_index.json`，`wf/progress.json`。
