# md → json 能轉回來到什麼程度；「還要特別用程式去看」的最短解可能不是互轉

← [README](README.md)｜上一份：[05-互轉樣本](05-互轉樣本.md)｜下一份：[07-邊緣狀況](07-邊緣狀況.md)

## 來回一趟（json → md → json）實測

| 轉法 | 測了什麼 | 結果 | 掉了什麼 |
|---|---|---|---|
| 註解 | 知識庫 111 份「物件頁」（`_index.json` 除外） | 110 份一字不差 | ① 字串陣列回來變成一個字串（照 aos 規矩兩者等價，但檔案長相變了、git diff 會整段換）；② 空物件 `{}` 沒有東西可寫，回來就不見了（`wf/knowledge/live-lists.json` 的 `skeleton/open`）；③ 字串尾端的換行被吃掉 |
| 樹（表格） | 三份 wf-table：`逐項表`（20 列）、`aos-daemon-env-1121`（36 列）、`self-history-range-1121`（14 列，格子有 `\|`） | 列數、每格內容全對 | 數字、`true` 回來變字串（表格裡看不出型別）；`columns` 那份名單照「字串陣列＝一段」轉成一段字，回來要另外認 |
| 樹（一般） | 自寫的邊緣檔 | 會錯 | 程式碼區塊裡的 `# 註解` 被當成標題（regex 讀法的錯，`cmark` 讀得對）；`- **k**: v` 的值裡剛好有 `**粗體**:` 只認第一個；重複標題要自動改名（原型改成 `重複 (2)`） |

能轉回來的程度，看**md 裡有沒有明寫的結構**：

- 有明寫的名字（註解、欄位清單、表格）→ 幾乎全回來，掉的是型別與「字串還是字串陣列」這類 md 表達不了的差別。
- 只靠自由寫的文章與標題 → 回得來的是「標題樹＋每節一段字」，跟原本的 json 鍵名不一定一樣。
- 人或 AI 直接改 md 之後再轉回去：排版會被正規化（清單符號、空行、跳脫），外面的工具都承認這點（[04](04-外面現成的.md)）。所以「兩邊輪流改」不穩；「一邊是正本、另一邊只生成」才穩。

## 「我還要特別用程式去看」：幾種不靠互轉的小解

他現在打開 json 的地方可能有幾處，每處的解不一樣。下表各寫多小。

| 在哪裡看 | 今天的樣子 | 解法 | 多小 |
|---|---|---|---|
| 終端 | `aos-json-view x.json` 已經把 `\n` 換行、鍵對齊、中文折行（見下） | 已有 | 0 |
| 終端，但想要 md | — | `aos-json-view` 加一個 `--md` 旗標，印 [05](05-互轉樣本.md) 那種 md，再交給 `bat -l md` 或 VS Code 預覽 | 幾十行 |
| 編輯器（VS Code／nvim）打開 .json | 一篇文章是一行，`\n` 到處都是 | ① 長文字改寫成字串陣列（11-13 已允許、推薦，知識庫 `wf/` 那一庫多半已是這樣寫，**`aos/` 那一庫一篇都沒有**；`wf/workflows/inbox.json` 也是這樣寫的，一行一句、編輯器裡直接可讀）；② 編輯器外掛（沒查具體哪支） | ① 不用寫程式，只是重寫檔；② 裝外掛 |
| GitHub 網頁 | json 原樣 | 排隊時生成 `x.json.md` 影子並 commit，GitHub 自動渲染 | 一支生成器＋掛排隊 |
| aos 前端網頁（`aos-frontend`，127.0.0.1:8767） | 全景頁，沒有看檔的頁 | 加一頁「給路徑、印成 md／表格」 | 一頁 |
| 檔案總管、手機 | json 原樣 | 只有影子 md 這條 | 同 GitHub |

## 讀出來的

- 他說的「互轉」有兩個用途，可以分開看：**讓人看**（只要 json → md 一個方向，從來不用轉回去）和**讓 AI 主要寫 md**（才需要 md → json 或 md 直接可尋址）。前者是 [03](03-做法.md) 戊、庚，已經有一半；後者是甲乙丙丁己。
- 「不然我還要特別用程式去看」如果指的是終端，那支程式已經在了；如果指的是編輯器或 GitHub，缺的是影子 md 或字串陣列化。這點從原話推不出來，列在 [08](08-可能的樣子與題.md) 的題裡。
