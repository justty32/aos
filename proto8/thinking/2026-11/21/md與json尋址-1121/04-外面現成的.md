# 外面現成的：md 當成可尋址的資料，別人怎麼做；這台能直接試什麼

← [README](README.md)｜上一份：[03-做法](03-做法.md)｜下一份：[05-互轉樣本](05-互轉樣本.md)

子 agent 開頁讀過，連結附上。`mq`、`mdq` 兩條本線再開一次頁面核對過；其餘照子 agent 的讀法，沒逐頁重開。星數是 11-21 抓的。

## 先講結論

- **定位方式只有兩派**：靠標題字（mdq、mq、remark heading-range、pandoc section、Obsidian `[[筆記#標題]]`、GitHub 錨點），或靠明寫的名字（MyST `(label)=`、Obsidian `^id`、Djot `{#id}`、org-mode `CUSTOM_ID`、mdast-zone 的 `<!--x start-->` 註解）。前一派改標題就斷，後一派穩但要多寫。
- **能「用路徑改 md 再寫回」的現成工具**：命令列只看到 `mq`（`-U` 改符合的節點、`-i` 寫回檔）；寫程式的話是 remark／mdast。
- **沒有一個工具說自己來回轉一字不差**。mdast 的寫回套件直接寫「complete roundtripping is impossible」。

## token 量（外面量的，都不是同儕審查）

- dev.to 一篇用 Anthropic 的 `count_tokens` 量同一份資料：JSON 3,252、YAML 2,208、Markdown 1,514。[來源](https://dev.to/webramos/yaml-vs-markdown-vs-json-vs-toon-which-format-is-most-efficient-for-the-claude-api-4l94)
- OpenAI 論壇用 tiktoken：JSON 13,869、Markdown 11,612（少約 16%）。[來源](https://community.openai.com/t/markdown-is-15-more-token-efficient-than-json/841742)
- 省多少看資料形狀：省的主要是「每列重複的鍵名、引號、括號」。aos 知識庫本來就是 md 包在字串裡，實量差很小（[07](07-邊緣狀況.md)）。

## 這台能直接試的（只查沒裝）

| 有 | 沒有 |
|---|---|
| `cmark` 0.31.2（CommonMark，`-t xml` 印語法樹；**不認 GFM 表格**，表格會變成一段字）、`discount`（`markdown` 指令）、tree-sitter-markdown 函式庫、`jq`、`bat`、`node`／`npx`、VS Code（`code`，內建 md 預覽）、nvim、python 的 `yaml`、`pygments` | `pandoc`、`mdq`、`mq`、`glow`、`mdcat`、`fx`、`jless`、`gron`；python 的 `markdown`、`mistune`、`markdown-it-py`、`mistletoe`、`frontmatter`、`tiktoken` 都沒裝 |

用 `cmark -t xml` 試過：程式碼區塊裡的 `# 註解` 它不會當標題（原型的 regex 會），所以「讀對 md」用 `cmark`＋python 內建的 xml 就做得到，只差表格要自己切。
