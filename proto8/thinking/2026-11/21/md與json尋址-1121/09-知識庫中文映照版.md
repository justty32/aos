# 知識庫中文映照版：156 份 json 各對一份 md，放在這夾的「知識庫映照-zh」，不放知識庫裡面

← [README](README.md)｜原話在 [00](00-使用者原話.md)「第二階段的原話」｜成品：[知識庫映照-zh/](知識庫映照-zh/README.md)

## 先講結論

- **放哪**：`知識庫映照-zh/`（本夾底下），**不是**頂層原本優先的 `proto8/knowledge/aos-zh-md/`。原因：放在知識庫旁邊會被現有的查法撈到（下面「為什麼不放知識庫裡」）。
- **幾份**：156 份 md，一份 json 對一份（`aos/` 110 份翻成中文、`wf/` 46 份原本就是中文照抄），加 13 份子夾 README 與 1 份總 README。來源 commit `fad6bef74`（知識庫更新線交件那一版；到交件時 HEAD 的 `proto8/knowledge/` 跟它一樣）。
- **一對一**：用腳本核過，json 裡 1,103 個葉子（字串、字串陣列、數字、`$ref`…）在 md 裡全都找得到，0 個缺。
- **翻譯**：440 段英文，分 9 批由 opus 子 agent 照同一張用詞表譯；每段自動比對反引號個數、標題行數、程式碼圍欄數跟原文一樣（0 個不合）。

## 轉法（用調查裡最看得下去的那幾種組起來）

- 文章型的值（知識庫大部分）：粗體 `#/鍵` 一行，下面原樣放那篇 md（調查的「註解」法改成看得見的標籤，因為這次要讓人看出對應到哪個鍵）。
- 短值：`#/鍵`：值，一行。
- `_index.json` 與檔內 `_index`：兩欄表格（鍵、一句說明；有 `index` 欄的多一欄）。
- 同一組鍵的小物件陣列（每格短）：排成表，第 i 列＝`#/路徑/i`。
- 名單型的字串陣列（路徑、檔名清單）：一個元素一條 `- `，免得預覽把它們併成一行（調查[邊緣 11](07-邊緣狀況.md#內容)）。
- `$ref`：`→ $ref 原字串`，並連到映照版的那份 md。
- 空物件、空陣列：明寫 `{}`、`[]`（調查裡試出這兩種轉 md 會不見）。

**腳本**（不進 repo）：`~/.aos/scratch/top-1121-mdjson/mirror/mirror.py`（`extract`／`check`／`render`）、`verify.py`（核一對一）、譯文在同夾 `zh/`（每份一個 txt，`<<<< #指標` 分段）、翻譯規則與用詞表 `TRANSLATE.md`、譯者記的拿不準的詞在 `doubts/`。重轉：

```sh
M=~/.aos/scratch/top-1121-mdjson/mirror
python3 $M/mirror.py render 知識庫的根 $M/zh 輸出夾 commit
```

知識庫的 json 改了以後要重跑 `extract` 看哪幾段英文變了、補譯那幾段，再 `render`。

## 為什麼不放知識庫裡（查到的）

1. **agent 的系統文字叫它讀整個 `knowledge/` 夾**：`templates/agent-fsm/system.txt`、`start-api` 的 ann、eca 三份範本都寫「read the knowledge base: the folder knowledge/ under $AOS_HOME」。agent 用 `ls`、`grep`、`glob` 掃 `knowledge/` 時，`aos-zh-md/` 的 156 份中文會跟英文頁一起被撈到。活樹直接讀 repo 這份，存檔即生效。
2. **code map 生成器會收進去**：`wf/tools/index_gen.json` 的 codemap 段 `md_dirs: ["knowledge"]`＝`knowledge/` 底下的 `.md` 要進逐檔表，交件時排隊會在 `wf/knowledge/code-map/proto8/knowledge.json` 多出 156 列。
3. 放 thinking 夾的代價（實測，在乾淨複本跑 `index_gen.py`）：子夾沒有一句話時報 `DescMissing`，所以腳本在每個子夾加一份 README；超過 15 個東西的四個子夾（`aos/`、`aos/cli/`、`aos/tools/`、`wf/workflows/`）排隊會替它們生 `_index.json`。這些都是 thinking 夾的正常規矩，不碰知識庫。

## 轉出來最難看的幾份

- `wf/source/block-4.md`、`block-3.md`、`wf/source.md`：搬遷紀錄的陣列，每筆五個鍵、其中一鍵是字串陣列，排不成表，只好一個鍵一個粗體標籤（block-4 有 113 個標籤），像在看展開的 json。
- `aos/cli/eca.md`：原文 `#/turn` 就是一大段，譯完一行一千多字；這份最長（22.9 KB）。
- `aos/me/self_hook.md`：`#/events` 把三種身體的行為擠在同一段，譯者也說主詞讀不出來。

## 翻譯拿不準的詞

全部 80 條在 `doubts/`，下面是會影響讀懂、或各批譯法不一致的：

| 英文 | 現在的譯法 | 問題 |
|---|---|---|
| directive | 指示詞（directive） | 譯者各寫「指令」「指示」，跟 command 的「指令」撞字；本線統一成 aos 中文文件用的「指示詞」 |
| cell | 有的留 cell、有的「格子」 | 跟 slot（也有人譯「格子」「位子」）撞 |
| overlay | 疊加設定／覆蓋層／照原文 | 三種寫法並存 |
| minimal core | 「最小核心部分」「最小的主體」 | 怕跟 kernel 混，兩批各想一個 |
| brain pack | 腦的包（brain pack） | 原文在 body、talk_settings 用 brain pack，在 brain 用 endpoint pack（端點包），原文自己不一致 |
| station／kernel station | 站／照原文 | 兩種並存 |
| hold／held | 扣住 | 夠不夠白 |
| wall-clock | 牆上時間 | 直譯 |
| registry | 登記表 | 也可「註冊表」 |
| screen | 畫面 | 用詞表沒列 |
| transcript | 對話紀錄 | 跟 history（對話歷史）要分開 |
| body（aos-loop、llm 請求的 body） | 主體／請求內容 | 不是 agent 的身體 |
| window | 窗口 | 不確定指什麼 |
| rearm、fold | 重新上膛、摺 | 比喻譯法 |
| queue、entry、hub、steer | 照原文 | — |

譯者另外指出原文本身讀不懂的地方（照字面譯，沒改）：`aos/cli/agent.json` 開頭 `XXX is the definition folder` 像沒換掉的佔位字；`aos/me/self_hook.json#/screen_linger` 與 `aos/body.json`、`aos/clock.json` 有「in this batch」「before this was fixed」這種開發紀錄口吻；`aos/kernel.json#/what` 說「兩個部分加一個最小核心」但清單對不上；`aos/cli/grow.json` 的 CALLER 在範例裡沒出現。
