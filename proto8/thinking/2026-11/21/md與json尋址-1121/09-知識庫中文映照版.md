## 轉法（用調查裡最看得下去的那幾種組起來）

- 文章型的值（知識庫大部分）：粗體 `#/鍵` 一行，下面原樣放那篇 md（調查的「註解」法改成看得見的標籤，因為這次要讓人看出對應到哪個鍵）。
- 短值：`#/鍵`：值，一行。
- `_index.json` 與檔內 `_index`：兩欄表格（鍵、一句說明；有 `index` 欄的多一欄）。
- 同一組鍵的小物件陣列（每格短）：排成表，第 i 列＝`#/路徑/i`。
- 名單型的字串陣列（路徑、檔名清單）：一個元素一條 `- `，免得預覽把它們併成一行（調查[邊緣 11](07-邊緣狀況.md#內容)）。
- `$ref`：`→ $ref 原字串`，並連到映照版的那份 md。
- 空物件、空陣列：明寫 `{}`、`[]`（調查裡試出這兩種轉 md 會不見）。

**腳本**（不進 repo）：`~/.aos/scratch/top-1121-mdjson/mirror/` 的 `mirror.py`（`extract`／`check`／`render`）、`verify.py`；譯文 `zh/`、用詞表 `TRANSLATE.md`、拿不準的詞 `doubts/`。重轉：

```sh

python3 $M/mirror.py render 知識庫的根 $M/zh 輸出夾 commit
```

知識庫的 json 改了以後要重跑 `extract` 看哪幾段英文變了、補譯那幾段，再 `render`。

## 放在 `knowledge/` 裡面會怎樣（查到的；所以最後搬出來）

1. **agent 的系統文字叫它讀整個 `knowledge/` 夾**：`templates/agent-fsm/system.txt`、`start-api` 的 ann、eca 三份範本都寫「the folder knowledge/ under $AOS_HOME」。agent 用 `ls`、`grep`、`glob` 掃 `knowledge/` 時，`aos-zh-md/` 的 156 份中文會跟英文頁一起被撈到。
2. **code map 會收進去**：`index_gen.json` 的 `md_dirs: ["knowledge"]`，`wf/knowledge/code-map/proto8/knowledge.json` 會多出約 170 列。
3. 知識庫不在 `index_gen` 建 `_index.json` 的範圍（知識庫的 index 是手寫的），所以搬過去後不會生 `_index.json`；放 thinking 夾時排隊替四個子夾生的 `_index.json` 隨搬家移除。每個子夾的 README 照留（腳本加的，說明這夾對知識庫哪一夾）。

## 翻譯拿不準的詞

全部 80 條在 `doubts/`（另有 registry 登記表、screen 畫面、window 窗口、rearm 重新上膛、fold 摺；queue、entry、hub、steer 照原文），下面是會影響讀懂、或各批譯法不一致的：

| 英文 | 現在的譯法 | 問題 |
|---|---|---|
| directive | 指示詞（directive） | 譯者各寫「指令」「指示」，跟 command 的「指令」撞字；本線統一成 aos 中文文件用的「指示詞」 |
| cell | 有的留 cell、有的「格子」 | 跟 slot（也有人譯「格子」「位子」）撞 |
| overlay | 疊加設定／覆蓋層／照原文 | 三種寫法並存 |
| minimal core | 「最小核心部分」「最小的主體」 | 怕跟 kernel 混，兩批各想一個 |
| brain pack | 腦的包（brain pack） | 原文在 body、talk_settings 用 brain pack，在 brain 用 endpoint pack（端點包），原文自己不一致 |
| station／kernel station | 站／照原文 | 兩種並存 |
| hold／held | 扣住 | 夠不夠白 |
| wall-clock | 牆上時間 | 直譯 |
| transcript | 對話紀錄 | 跟 history（對話歷史）要分開 |
| body（aos-loop、llm 請求的 body） | 主體／請求內容 | 不是 agent 的身體 |
| stock template | 內建範本 | 11-22 補：中文版原本混著內建範本（10 處）、現成範本（6）、原廠範本（3，另有「原廠 eca 範本」2）、原裝範本（2）；使用者「都先按照推薦」，推薦是選出現最多的，統一成「內建範本」（`stock eca templates`＝「內建 eca 範本」）。只管 template；stock definition、stock tool 本來就譯「內建定義」「內建工具」，stock hook 的「現成的」沒動 |

譯者另外指出原文本身讀不懂的地方（照字面譯，沒改）：`aos/cli/agent.json` 開頭的 `XXX is the definition folder` 像沒換掉的佔位字；幾處有「in this batch」「before this was fixed」這種開發紀錄口吻。

## 他用 VS Code 打開知識庫：對七種做法的影響（11-21 傍晚補，只寫事實）

他答第 2 題：「我平常就是用vscode打開知識庫這樣。」

- **對「在 VS Code 裡看」有幫助的**：戊（json 旁邊另產 md；現在的 `knowledge-zh-md/` 就是這種，不自動更新）、己（文章拆成真的 .md 檔）、甲乙丙丁（md 當正本，打開就是 md）、庚裡的「長文字寫成字串陣列」（json 在編輯器裡一行一句）。
- **沒幫助的**：庚裡的 `aos-json-view` 和 `--md` 旗標（在終端看，不在 VS Code）；丁的查詢工具本身（是指令，不是看檔）。
- **現在他在 VS Code 裡看得到的**：`proto8/knowledge-zh-md/` 的 156 份中文 md，可以用 VS Code 內建的 md 預覽看（標題、表格、程式碼區塊照常顯示）；旁邊的 json 照舊。兩邊不會自動同步。
