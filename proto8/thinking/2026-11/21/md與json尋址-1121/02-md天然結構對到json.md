# markdown 天然有哪些「可以指到」的結構，各能對到 json 的什麼

← [README](README.md)｜上一份：[01-現況](01-現況-aos今天的尋址.md)｜下一份：[03-做法](03-做法.md)

markdown 沒有「鍵」這個東西，但它有幾種人一眼看得出邊界的結構。下表是每種結構、它最自然對到 json 的哪種形狀、穩不穩。

| md 結構 | 長相 | 最自然對到 | 穩不穩（別人用路徑指它時） |
|---|---|---|---|
| 標題階層 | `#`、`##`…`######` | 物件的鍵；下面那段字＝值 | 改標題字就斷；同一層兩個一樣的標題要另外處理；超過六層沒得表示 |
| 標題下的一段字 | 段落、清單、程式碼混在一起 | 字串（一段 md） | 這就是知識庫今天每個值的形狀 |
| 清單 | `- a`、`1. a` | 陣列（字串陣列） | 第幾項＝號碼，中間插一項後面全變（知識庫規矩 02 就說「要穩定的名字用物件、不用陣列」） |
| 欄位清單 | `- **status**: 等使用者` 或 Dataview 的 `status:: 等使用者` | 小物件（鍵＝粗體字） | 要規定一種寫法；值裡剛好有 `**x**:` 就會誤認 |
| 表格（GFM） | `| a | b |` | 物件陣列（每列一個物件，欄名＝鍵）——就是 `wf-table/1` 的 `rows` | 格子不能換行（要寫 `<br>`）、`|` 要跳脫；欄位一多、格子一長，原始檔就看不下去 |
| 程式碼區塊 | ```` ```json ```` | 任意 json，原樣放 | 最穩：裡面就是 json；但人看到的也還是 json |
| front matter | 檔頭 `---` 到 `---` 之間的 YAML | 整份檔的頂層小物件（標題、狀態、日期） | 只有一層，適合放「這份檔的欄位」，不適合放長文 |
| 連結與錨點 | `[x](a.md#某節)`、`<a id="k"></a>` | 指到別處（像 `$ref`） | `<a id>`、HTML 註解這類「明寫的名字」不隨標題字變 |
| 定義清單 | 標準 md 沒有（pandoc、PHP Markdown Extra 才有 `詞\n: 解釋`） | 物件 | 各家寫法不同，GitHub 不認 |
| HTML 註解 | `<!-- 任何字 -->` | 可以塞一個看不見的鍵或指標 | 畫面上看不見、git diff 看得見；改標題不會斷 |

## 三個從表裡看出來的分岔

1. **「名字從哪來」只有兩條路**：一是拿看得見的字當名字（標題字、粗體欄名），好看、AI 寫起來自然，但改字就斷；二是另外寫一個明寫的名字（`<a id>`、HTML 註解、`{#id}`、front matter 的鍵），穩，但多一樣東西要 AI 記得寫、人要忍受多一行雜訊。外面的工具也分成這兩派（見 [04](04-外面現成的.md)）。
2. **知識庫和資料表是兩種形狀**：知識庫是「名字 → 一篇文章」，用標題或註解就對得上；`wf-table` 是「同一組欄位的很多列」，在 md 裡只有表格或「每列一個小標題＋欄位清單」兩種寫法，前者擠、後者長（樣本在 [05](05-互轉樣本.md)）。
3. **md 文章裡本來就有標題**：知識庫每段都以 `# 標題` 開頭。如果規定「標題＝鍵」，文章自己的標題跟「當鍵用的標題」會撞在一起：`me.json` 轉出來會是 `# stack` 下面緊接一個 `# What is in your stack`（實際轉過，見 [05](05-互轉樣本.md)）。要嘛鍵改用註解標，要嘛文章內的標題要整體降級，要嘛乾脆讓文章自己的標題當鍵（那鍵就變成英文長句）。
