## 使用者原話

頂層問：「gdb 從宣告讀（原本排的第 6 刀）還做不做？現在原則是『宣告只是參考』，引擎也不讀宣告，這一刀的意義少了大半，所以我沒派。」他答：

「4.要做，我覺得可以在gdb啓動時給他選項，跟他說可以參考這份宣告，然後再去做一些事情。」

讀法（頂層的，這條線照做）：`aos-gdb` 啟動時可以帶選項，指給它一份或幾份 hook 宣告檔（新格式 `hooks.json`），gdb 當**參考**用；不給選項照舊能用，給了但對不上也不擋。這條線沒有讀出別的意思。

## 一、盤點：gdb 原本寫死的，與宣告裡拿得到的

| gdb 寫死的 | 在哪 | 新格式宣告裡對應的 | 這次 |
|---|---|---|---|
| 能下斷點的種類（agent 一家的點去掉 on_clock＋壓縮兩點＋loop 四點） | `aos.gdb.EVENTS` | 宣告檔的鍵（點的 id） | 有宣告＝預設的**加上**宣告多的（聯集，見選擇 3） |
| 哪些種類有主詞、主詞參數叫什麼（`tool`／`code`） | `aos.gdb.SUBJECT`、`NAMED` | 自由鍵 `condition`（欄位）、`subject`（說法） | 有宣告照宣告，沒寫的照預設 |
| 主詞拿事件哪個欄位比（一律 `name`） | `trigger.check` | `condition` | trigger.json 多一個 `field`（不是 name 才寫） |
| 扣住還是暫停（before_tool、before_queue 扣住，其他暫停） | `trigger.HOLD_EVENTS`、`how()`，handler 也查 | `phase`、`block` | **沒改**（岔路，見四） |
| 認哪一次（工具呼叫 id、信名） | `trigger.key_of` | `key` | 沒改（跟扣住綁在一起） |
| 停下時怎麼顯示事件（摘要只留 name、id、code、letter、arguments、content 幾鍵） | `trigger.brief`、`_stopped_head` | `input` 的 properties 與各欄 description | 新增 `a.bp.event()` 照 input 排整份事件；摘要多帶主詞欄位 |
| 種類的一句說明 | `_KIND_DOC` | 點的 `description` | 宣告多出來的點用它 |

`output`、`if_blocked`、`fired_in`、`entry_keys`、`environment`、`notes` 對 gdb 沒用，不讀。

## 二、現在怎麼用

```sh
aos-gdb -d .stack --def-hooks ann                       # 讀 ann 定義 interfaces.json 最外層 "hooks"（範本＝loop 四點＋agent-fsm 那份）
aos-gdb -d .stack --hooks my_hooks.json --hooks b.json ann   # 指定檔，可重複；兩種可以一起給
```

REPL 裡多一個名字 `hooks`（`hooks` 列表、`hooks.load(檔)`、`hooks.load_def(a)`、`hooks.clear()`、`hooks.fields(id)`、`hooks.get(id)`），`a.bp` 多一個 `a.bp.event()`。實跑輸出（暫存樹、假腦）貼在 [apps/gdb/README](../../../py/aos/apps/gdb/README.md#hook-宣告當參考--hooks-file--def-hooks)。

宣告被拿來做的事：

1. **列點與欄位**：`hooks` 一張表——點、gdb 會怎麼停（hold／pause／不能下）、宣告寫的 phase／block、主詞、input 欄位。
2. **多出斷點種類**：宣告裡有、gdb 預設沒有的點變成 `a.bp.add.<點>`（tab 補得出），一律暫停。實測：自訂點 `before_save` 宣告 `"condition": "file", "subject": "path"`，`a.bp.add.before_save("a.txt")`，用 `aos-hook fire --def 定義 --stack stack before_save` 發事件，`file` 是 `b.txt` 不停、`a.txt` 停，第一行 `stopped at breakpoint 1 (before_save: a.txt)`。
3. **主詞照宣告**：`condition`＝比哪個欄位，`subject`＝參數名。
4. **對不上只提醒**：點不在宣告裡、`py=` 條件讀了宣告 input 沒有的欄位＝一行 `a.bp.add.X: warning: ... added anyway`，照下。
5. **照 schema 排事件**：`a.bp.event()` 讀觸發器成立時存的整份事件（小格的 `hit.json`），照宣告 input 的順序、帶 description；沒載入宣告也能用（照原本的順序）。
6. `a.bp.add` 打出來的種類表把沒宣告的標 `(not declared)`。

## 三、不帶選項時有沒有改變

- `a.bp` 的種類、主詞、trigger.json、掛 hook 的參數、停的第一行都跟以前一樣（測試 `NoDecl`、`Add.test_without_declaration_same_as_before` 比對；原本 66 支 gdb 測試照綠）。
- 看得到的差別三處：開場那行 `ready:` 多一個 `hooks`；`a.bp` 多一個 `event()` 方法；觸發器成立時多寫一個 `hit.json`（每個觸發器小格一份、蓋掉舊的；寫不了只 warning，不影響停）。

## 四、岔路：扣住還是暫停要不要照宣告（沒做，等使用者）

宣告裡 `phase: before`＋`block: true` 的點有四個：before_tool、before_queue（gdb 本來就扣住）、**before_run、before_compact**（gdb 現在是暫停）。「照宣告」的話這兩個會改成扣住，等於改了 gdb 對它們的用法：

| 選項 | 後果 |
|---|---|
| 甲（現狀）：扣住或暫停照 gdb 自己的表，不看宣告 | 跟以前一樣；`hooks` 表把宣告寫的 phase／block 與 gdb 實際的停法並排列出，對不上一眼看得到。宣告多出來的點一律暫停（事件發生後、那一格做完才停） |
| 乙：有宣告時 `phase: before` 且 `block: true`＝扣住 | `a.bp.add.before_run()` 能停在身體跑之前（11-20 設計稿想要的「扣在任何一格之前」），自訂點也能扣在事情發生前。要改 handler（現在只在 before_tool、before_queue 扣）、`key` 也要照宣告讀；before_run 扣住時 loop 卡在 `aos-hook fire` 裡、表上不是 running；eca 的 before_compact 是經 Claude Code 的 hook 發的，扣太久 CLI 那邊可能自己逾時——都要另外實測。同一個種類有沒有給 `--hooks` 停法不同 |
| 丙：不管有沒有宣告，before_run／before_compact 都改扣住 | 不靠宣告；但改的是 gdb 預設行為，跟這一刀「宣告只是參考」無關，算另一件事 |

這條線停在甲。

## 五、替使用者做的選擇

1. **旗標名** `--hooks FILE`（可重複）：跟 `interfaces.json` 的鍵、宣告檔名 `hooks.json` 同一個字。
2. **自己找宣告是另一個旗標** `--def-hooks`、不是預設：預設就去讀 interfaces.json 會讓「不帶選項」也變了行為（多提醒、多種類）；也不用 `--hooks def` 這種特殊值（KISS「給的值照字面用」）。兩個可以一起給。
3. **種類是聯集**：預設的種類一個不少，宣告多的加在後面；宣告沒寫的點照樣下得了、只多一行 warning（「對不上也不擋」）。宣告沒寫 `condition` 的點也不會因此拿掉預設的主詞。
4. **扣住或暫停不從宣告讀**（四的甲）；宣告多出來的點一律暫停。
5. **主詞參數名**：用 `subject`，當不了 Python 參數名或撞到 `sh`、`py`、`times`… 時用 `condition` 的欄位名；欄位名也撞＝這點沒有主詞。
6. **主詞篩選交給誰**：宣告的點不是 agent 一家自己的（或欄位不是 `name`）時，不把 `--condition` 交給 `aos-agent hook add`（agent 一家以外的發事件程式不篩），由 gdb_trigger 自己比 `field`。
7. **一個 REPL 一份宣告**（`aos.gdb.decl.current`），接好幾隻時不分隻；`hooks.load` 之後下一個 `a.bp` 就照新的。
8. **讀不到的檔**：一行 warning（開場是 `aos-gdb: warning:`，REPL 裡 `hooks.load: warning:`），跳過那一份、其他照讀；同一個 id 兩份都有＝先讀到的算（跟 `aos.hook_point.read` 一樣）。
9. **py 條件猜欄位**：只認 `ev["x"]`、`ev.get("x")` 這兩種最上層讀法（看 bytecode／運算式），猜不到就不提醒；`sh=` 條件不查。
10. **事件整份存 `hit.json`**：成立時寫（不限大小，跟 stack 裡其他檔一樣）；不另外做歷史，只留最近一次。
11. **REPL 指令**：中途載入／查看放在 `hooks` 這個物件上（`load`、`load_def`、`clear`），不另外加 `a.bp.*` 方法。
12. 沒載入宣告時開場不多印一行（只有 `ready:` 那行多一個 `hooks`），載入了才印「hook declarations: N point(s) from M file(s)」。

## 六、沒做的

- 扣住／暫停照宣告（四）、`key` 照宣告。
- tab 補事件欄位名（`ev["` 後面補）：REPL 的補全只認 Python 名字，要自己寫 completer，成本比效益大。
- 補全或檢查**主詞的值**（工具名、錯誤代號不在宣告裡）。
- `output` schema 不用；`sh` 條件不猜欄位。
- 觀察者（`watch`）跟宣告無關，沒動。
- `proto8/docs/` 條文沒改（任務書）。知識庫 [`aos/cli/gdb.json`](../../../knowledge/aos/cli/gdb.json) 加一段。
