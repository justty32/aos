照 hooks 那套類推的三種粗細：甲只搬 hook 兩鍵、乙再加「收什麼請求」與「可挑的 endpoint」、丙每樣一個鍵並包成一格；各附 llm kernel 與一般 kernel 的 `interfaces.json` 與被指到的檔。

樣本都在 [樣本/](樣本/)，是合法 JSON、沒有程式讀。llm kernel 的例子對應 `templates/start-api/llm`，一般 kernel 對應 `templates/start-api/perm`（aos-loop 當身體）。

## 三種共用的寫法（都是從他定的 hook 那套直接搬）

- 鍵的值是**字串或字串陣列，字串就是檔名**；夾內的檔寫相對檔名，別處的寫指示詞。
- 跟著程式走的宣告（三個 hook 點、請求的形狀）指到程式夾：`{"$env": "AOS_HOME", "$path": "/lib/tools/aos/kernel/hooks.json"}`——路徑寫全，看得出哪來，不用 provider 名字。
- 被指到的檔是**一個物件，鍵是 id**，值裡硬性只要 input schema，其餘鍵自由。
- 不把內容直接寫在 `interfaces.json`。
- 甲、乙把鍵放在最外層（照他原話 `"hooks": …` 的字面）；丙包在 `"aos-kernel"` 格裡（照 agent 現況）。**放哪一層跟粗細是兩件事**，可以交叉配，見 [05 第 2 題](05-想問的題.md)。

樣本裡三個名字是我照他的命名往下推的，他沒說過：程式夾那份點宣告叫 `hooks.json`（現在叫 `hook_points.json`）；loop 四個點那份叫 `loop_hooks.json`（現在叫 `loop_points.json`）；loop 的被勾清單叫 `loop_hookeds.json`（現在叫 `loop_hooks.json`——**新舊名字正好撞在一起**，見 [04](04-邊緣狀況.md) 第 9 條）。

## 甲：極簡——只搬 hook 兩鍵

其餘（請求、回信、代號、endpoint、窗、`decisions/`）照舊只在文件與知識庫。

llm kernel（[樣本/甲-llm-interfaces.json](樣本/甲-llm-interfaces.json)）：

```json
{"description": "…",
 "hooks": {"$env": "AOS_HOME", "$path": "/lib/tools/aos/kernel/hooks.json"},
 "hookeds": "hookeds.json",
 "aos-ledger": {"file": "ledger.jsonl"}}
```

一般 kernel（[樣本/甲-perm-interfaces.json](樣本/甲-perm-interfaces.json)）：

```json
{"description": "…",
 "hooks": [{"$env": "AOS_HOME", "$path": "/lib/tools/aos/kernel/hooks.json"},
           {"$env": "AOS_HOME", "$path": "/lib/aos/apps/hook/loop_hooks.json"}],
 "hookeds": ["hookeds.json", "loop_hookeds.json"]}
```

被指到的檔：[樣本/共用-kernel-hooks.json](樣本/共用-kernel-hooks.json)（三個點的新格式）、[樣本/夾內-hookeds.json](樣本/夾內-hookeds.json)。

甲還有一個更省的變體：不拆 `hookeds.json`，寫 `"hookeds": "kernel.json"`（清單就是那份檔裡的 `hooks` 鍵，`aos-hook --list` 本來就收任何有 `hooks` 表的 json）。差別見 [05 第 3 題](05-想問的題.md)。

## 乙：中——再加兩個鍵，都是「id＋input schema」的物件檔

多 `"requests"`（收什麼請求）；llm kernel 再多 `"endpoints"`（可挑的代號）。

llm kernel（[樣本/乙-llm-interfaces.json](樣本/乙-llm-interfaces.json)）：

```json
{"description": "…",
 "hooks": {"$env": "AOS_HOME", "$path": "/lib/tools/aos/kernel/hooks.json"},
 "hookeds": "hookeds.json",
 "requests": {"$env": "AOS_HOME", "$path": "/lib/tools/aos/kernel_llm/requests.json"},
 "endpoints": "endpoints.json",
 "aos-ledger": {"file": "ledger.jsonl"}}
```

一般 kernel（[樣本/乙-perm-interfaces.json](樣本/乙-perm-interfaces.json)）：同甲，多一行

```json
 "requests": {"$env": "AOS_HOME", "$path": "/lib/tools/aos/kernel/requests.json"}
```

### 「收什麼請求」的檔

跟 hook 點同一個樣子：id 當鍵、`input` 是信的 body、`output` 是回信，拒信代號放自由鍵 `errors`。

- llm kernel：[樣本/共用-kernel_llm-requests.json](樣本/共用-kernel_llm-requests.json)，只有一個 id。問腦信的 body 沒有「種類」欄，所以 id（樣本寫 `think`）是憑空取的名字。
- 一般 kernel：[樣本/共用-kernel-requests.json](樣本/共用-kernel-requests.json)，id 用 body 的鍵（`procs_added`、`procs_started`、`procs_woken`——程式會判的三個）。其餘的鍵它原樣轉給下一站，不在表上。

```json
{"description": "…",
 "think": {
  "description": "ask the brain once; the letter goes to <kernel stack>/requests",
  "input": {"type": "object", "required": ["request"], "properties": {
    "endpoint": {"type": "string"}, "reasoning_effort": {"type": "string"},
    "request": {"type": "object", "required": ["messages"]}, "priority": {}}},
  "output": {"oneOf": [{"required": ["message"]}, {"required": ["error"]}]},
  "errors": ["LetterBad", "RequestBad", "EndpointUnknown", "BudgetMissing", "…"]}}
```

一個順帶的好處：`before_verdict` 的 handler 收到的 `body` 就是這份 input。兩支 kernel 程式共用三個 hook 點，差別最大的正是 `body` 的形狀；有了請求檔，hook 點宣告可以寫「`body` 的形狀看這站的請求檔」，不必為了 `body` 把點宣告拆成兩份（[03](03-後果對照.md)「兩支程式共用」那列）。

### 「可挑的 endpoint」的檔

[樣本/夾內-endpoints.json](樣本/夾內-endpoints.json)：id＝代號，其餘鍵自由（`summary`、`speed`、`cost`、`reasoning_efforts`…）。樣本用的落法是**夾裡一份檔同時當清單與設定**：`kernel.json` 寫 `"endpoints": {"$ref": "endpoints.json"}`（整張表拆出去是 llm kernel 現在就支援的寫法），`interfaces.json` 也指它。另外兩種落法（指到 stack 的窗、不宣告）在 [05 第 5 題](05-想問的題.md)。

硬性的 input schema 在這裡可有可無；想寫的話，自然的內容是「挑這個代號時，信的 `request` 能帶什麼」，例如 `sol` 的 `reasoning_effort` 只收五個級別、`temperature` 被釘死不能帶。樣本沒寫。

## 丙：細——每樣一個鍵，包成一格

llm kernel（[樣本/丙-llm-interfaces.json](樣本/丙-llm-interfaces.json)）：

```json
{"description": "…",
 "aos-kernel": {
   "config": "kernel.json",
   "hooks": {"$env": "AOS_HOME", "$path": "/lib/tools/aos/kernel/hooks.json"},
   "hookeds": "hookeds.json",
   "requests": {"$env": "AOS_HOME", "$path": "/lib/tools/aos/kernel_llm/requests.json"},
   "errors": {"$env": "AOS_HOME", "$path": "/lib/tools/aos/kernel_llm/errors.json"},
   "files": [{"$env": "AOS_HOME", "$path": "/lib/tools/aos/kernel/files.json"},
             {"$env": "AOS_HOME", "$path": "/lib/tools/aos/kernel_llm/files.json"}]},
 "aos-llm-kernel": {"endpoints": "endpoints.json"},
 "aos-ledger": {"file": "ledger.jsonl"}}
```

一般 kernel（[樣本/丙-perm-interfaces.json](樣本/丙-perm-interfaces.json)）：只有 `aos-kernel` 一格，`hooks`、`hookeds` 是陣列（多 loop 那兩份）。

比乙多的三個鍵：

- `config`：設定檔叫什麼（現在是固定名，由 `daemon.json`／`loop.json` 的 argv 帶）。
- `errors`：拒信代號表，id＝代號，[樣本/共用-kernel_llm-errors.json](樣本/共用-kernel_llm-errors.json)（只寫三個代號）。代號沒有 input，樣本把那一格叫 `schema`，講錯誤物件多帶哪些欄（`BudgetMissing` 的 `resets_at`…）。
- `files`：stack 裡給外面讀的窗與給外面寫的地方，id＝短名，[樣本/共用-kernel-files.json](樣本/共用-kernel-files.json)（`requests` 信箱、`queue`、`hold`、`decisions`）。路徑從 **stack** 算，不是從定義夾。`kernel_llm/files.json`、`kernel/errors.json` 樣子相同，沒另附樣本。

## 三種並排

| | 甲 | 乙 | 丙 |
|---|---|---|---|
| `interfaces.json` 多幾個鍵 | 2 | 3～4 | 一格裡 6 個，llm 再一格 |
| 程式夾要多幾份宣告檔 | 0（三個點那份已經有，只是換格式） | 2（兩支程式各一份請求檔） | 6 上下 |
| kernel 夾要多幾份檔 | 1～2（`hookeds.json`，或 0：指 `kernel.json`） | 再加 `endpoints.json`（llm） | 同乙 |
| 新發明的約定 | 無 | 請求的 id 怎麼取、endpoint 宣告指哪一份 | 再加：`schema` 這個鍵名、路徑從 stack 算、`aos-kernel` 格 |
| 現在就有讀者的部分 | hook 兩鍵（`aos-hook`、編譯、kernel 自己） | 同甲；請求與 endpoint 沒有 | 同甲；其餘沒有 |
