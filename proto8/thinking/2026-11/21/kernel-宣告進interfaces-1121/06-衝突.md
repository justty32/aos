## 跟他說過的話

1. **「不收」直接寫內容（11-21 第 7 則）對上現有的格。** 他說的是 `"hooks"` 只收檔名。但 `interfaces.json` 現有的 `"aos-ledger": {"file": "ledger.jsonl"}`、`"aos-agent": {…, "llm_keys": […]}` 都是把內容直接寫在裡面的格。「只收檔名」是只管 hook 那兩鍵，還是 kernel 照 hooks 類推的每一格都要（那 `aos-ledger` 這種格算不算例外），沒說過。樣本照前者寫。
2. **`hooks` 這個字在 kernel 這邊是反的。** 他定 `hooks`＝有哪些鉤子、`hookeds`＝被勾著哪些；`kernel.json` 裡的 `hooks` 鍵是被勾清單，`loop_hooks.json` 也是被勾清單。他改名時講的是 agent 那邊的檔名與 `interfaces.json` 的鍵，沒提 `kernel.json` 裡的鍵。不改：同一個字兩個相反的意思；改：`kernel.json` 的鍵名、`defs.Kernel(hooks=…)` 的參數名、知識庫都要跟。
3. **「有宣告就能用」（11-21 早）對上現況。** 四個 kernel 範本沒宣告任何 hook，卻都能掛。這句話若是雙向的，現況就是不合；若只是單向的（宣告了就保證能用），就沒事。
4. **11-20「另外一個json吧。interfaces和hook都是另外的用途。」對上今天「interfaces.json中當然兩者都可以有」。** 前一句是回答「kernel 宣告自己有哪些規則」放哪，他把它放在 `interfaces.json` 外面；今天要把 kernel 的宣告整合進 `interfaces.json`。兩句可以同時成立（`interfaces.json` 可以寫，給別人的另外一份），但 11-20 那份 json 裝的東西（資源宣告、排程規則）現在算不算也該在 `interfaces.json` 有一格，沒說過。
5. **11-14「各種kernel的定義各不相同」「現在就規劃，反而會限制到很多可能性」與 11-20「以後有需求再去定規矩」，對上乙、丙。** 乙的 `requests` 是替「kernel 收什麼」定一個所有 kernel 共用的寫法，丙更是一整套；這是在還沒有讀者的時候先定規矩。甲沒有這個問題（只搬他已經定的 hook）。另外知識庫寫的「收請求的 proc 不需要知道自己是 kernel」「daemon 本身就是最簡單的 kernel」，跟「kernel 要宣告才算數」的方向也相反。

## 跟現有條文

6. **NORMS「宣告介面 `interfaces.json`」寫的是「資料夾宣告自己遵守哪些介面」**（出自他 11-04「宣稱說自己繼承於/遵守於某些介面，比如golang interface」），例子的鍵都是介面名（`aos-agent`、`aos-agent/screen`）。最外層寫 `"hooks"`、`"requests"` 的話，鍵變成「提供的東西的種類」，不是「遵守的介面名」。他 11-20 的定位（「有提供啥界面，就去看」）比較接近後者。兩種讀法並存不會壞，但條文那句與例子要補。
7. **同一條：「其餘檔名由它指定」「檔名只寫在宣告一處」（C-81，給外面寫的覆蓋層）。** agent 的做法是 stack 裡同名的檔蓋定義夾那份，靠的是宣告裡的相對檔名。`hooks` 用指示詞指到 `$AOS_HOME` 之後，那個值不是一個「名字」，stack 沒有對應的同名檔可以蓋；`hookeds` 若也准指到夾外，agent 的 `self_hook` 那種「改 stack 那份」就沒有東西可改。
8. **N-42-1「定義夾 `interfaces.json` 以 `aos-ledger` 宣告」與 N-68 的 `aos-observed`。** 這兩格的檔名是從 **stack** 算的；他定的 `hooks` 字串是從**定義夾**算的。同一份檔兩種起算點（[04](04-邊緣狀況.md) 第 2 條）。條文沒有一句講「哪些格的路徑從哪算」。
9. **附錄 4**：`interfaces.json` 的讀者只列 agent 一家、`ledger.jsonl` 的出處路徑還是舊的 `proto8/kernel/llm-kernel/`、「interfaces.json 沒宣告＝沒有 hook 機制」只對 agent 成立。不管選哪個候選，這幾列都要改。

## 跟現有程式

10. **「`interfaces.json` 必須支援指示詞」對上讀它的程式。** N-45 本來就寫「aos 自己的程式讀的 JSON 一律支援指示詞」，但現在讀 `interfaces.json` 的程式（`declared_files.py`、`hook_point.for_definition`）都是直接讀、不解指示詞；`declared_files.py` 還明文只收「定義夾內的相對檔名」，絕對路徑與 `..` 都擋。條文跟他的話一致，是程式沒跟上。
11. **`aos-hook --agent` 只看 `aos-agent` 那格。** 對 kernel 夾現在是默默給 0 點、不報錯。照任何一種候選，它都要有辦法讀 kernel 的宣告；讀哪一層取決於 [05](05-想問的題.md) 第 2 題。
12. **編譯整份蓋掉 `interfaces.json`，對上「想加啥就加啥」。** `kernel_spec.py` 對 llm kernel 每次重新編譯都寫一份固定的；人手加的格會不見。現在只有一格所以沒人碰到。
