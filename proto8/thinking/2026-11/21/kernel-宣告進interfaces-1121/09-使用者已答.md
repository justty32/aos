使用者 11-21 對 kernel 宣告六題的回答（逐字）與頂層的整理；還沒派施工。

← [README](README.md)

頂層轉述本稿的結論、三種粗細與六題後，他答：

「1.先做甲。2.hooks/hookeds放interfaces.json的頂層。"kernel":...也放頂層。3.把kernel自己提供的hook點位弄成kernel_hooks.json，然後hooks指過去，還有kernel_hookeds.json，同樣hookeds指過去。4.沒宣告的照樣跑，其他的也是，就是說，宣告這東西只是參考。5.模型清單的宣告另外做，這是只有llm kernel特有的，他當然可以在interfaces.json中的頂層添加llm_kernel:{"models":"llm_models.json"}。6.有關聯，之後再來串起來。」

## 整理（頂層的理解，原話以引號內為準）

1. **做到多細**：先做甲（只搬 hook 兩鍵）。
2. **放哪一層**：`hooks`、`hookeds` 放 `interfaces.json` 的最外層；`"kernel": …` 也放最外層。（agent 那邊現在這兩樣包在 `"aos-agent"` 格裡——照這句要搬到最外層，hook 施工那一刀一起做。）
3. **kernel 的檔名**：kernel 自己提供的 hook 點宣告叫 `kernel_hooks.json`，`hooks` 指過去；被勾清單叫 `kernel_hookeds.json`，`hookeds` 指過去（所以被勾清單從 `kernel.json` 拆成獨立的檔）。
4. **沒宣告的**：照樣跑；「其他的也是」——宣告只是參考。
5. **模型清單**：另外做；只有 llm kernel 有，它可以在最外層加 `llm_kernel: {"models": "llm_models.json"}`。
6. **對外另外一份 json** 跟 11-20 寄信問 kernel／public 資料夾：有關聯，之後再串。

## 還沒問的

- 最外層的 `"kernel": …` 裡面放什麼（甲只有 hook 兩鍵與現有的 `aos-ledger`）；現有的 `"aos-agent"`、`"aos-ledger"` 這些格名要不要跟著改成 `"agent"` 之類，沒說。
- 「宣告只是參考」「其他的也是」涵蓋到哪：agent 那邊現在 `ctl add` 要有 `aos-agent` 那格才收、點沒宣告就寫 condition 會報錯；這些要不要也改成不擋，沒問。它跟 11-21 早上那句「hook體系的唯一約定，就是要在interfaces.json中宣告，有宣告就能用」怎麼並存（頂層的讀法：宣告了就能用，沒宣告也不擋），沒確認。
- kernel 的宣告檔 `kernel_hooks.json` 放在定義夾（每個 kernel 夾各一份）還是放在 aos 裝的地方、用指示詞指過去（本稿樣本是後者），他說「hooks指過去」，沒說檔放哪。
- loop 身體的 kernel 那四個 loop 點與它的被勾清單（現在 `loop.json` 指向 `loop_hooks.json`）叫什麼。
- `llm_models.json` 是手寫的清單，還是現在 `kernel.json` 的 `endpoints` 搬過去，沒說（他說「另外做」）。
