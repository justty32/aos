## 一、定案明講拿掉的

- `intercept`、`async`、`on_error` 三個選項（清單裡寫了也不讀）；`aos-agent hook add` 的 `--no-intercept`、`--async`、`--on-error`；`self_hook` 的同名參數。
- 宣告驅動的驗證：宣告的逐鍵檢查、幾份宣告要一致、「點沒宣告卻寫 condition」「掛了 hook 卻沒寫 hook_points」的 HooksBad、`EventUnknown`、`fn.block` 的編譯期檢查、編譯與清單的事件名檢查。
- 旗標檔 `hook_before_run.flag`／`hook_after_run.flag` 與 loop.json 的 `on_*_if`。
- `aos-hook points`、`aos-hook check`、`--points`、`--field`／`--field-file`／`--field-default`、從環境變數取欄位。
- provider 表（`{"provider": "aos-loop"}`）、`hook_points` 鍵。

## 二、保不住的（定案沒明講、但隨之改變）

| # | 以前 | 現在 | 原因 |
|---|---|---|---|
| 1 | 使用者自己 `self_hook add` 的 hook 沒寫 on_error＝失敗時 agent 停 | 只有 before_queue、before_tool 會停；其他點只多一行 warning | 選擇 1 |
| 2 | 出廠 hook（`on_error: continue`）掛在 before_tool 失敗＝warning、工具照跑（例 `user_zone_guard` 說明書教人這樣掛） | 停下（HookFailed） | 同上 |
| 3 | aos-mcp 的 after_tool hook 失敗＝那次工具回 isError | 一行 warning、結果照常回 | 同上 |
| 4 | loop 四點的 hook `on_error: continue` 失敗＝warning、loop 照跑 | 失敗＝loop 收工（on_start 失敗＝agent 起不來）；出廠的 eca `screen_linger_start`／`stop` 改成自己出錯只 warning、退 0，所以這兩支照舊不擋 | 第 7 條：loop.json 那四行帶 `--stop-on-nonzero` |
| 5 | after_run／after_start／after_stop 的 handler 退 10＝當放行 | 退 10＝失敗、loop 收工 | 選擇 3 |
| 6 | loop 事件帶 `code`、`signal`、`cause`、`counter_runs`、`stage`、`next_stage` 欄 | 事件只有 event／hook／stack；值在環境變數 `AOS_LOOP_*` 與 `<stack>/stage.txt` | 第四層拿掉 `--field*` 與環境變數欄位 |
| 7 | before_run 的 condition 可比格名（例「只在 think 之前」） | loop 點沒有 condition；handler 自己讀 stage.txt 判斷 | aos-hook 不比條件 |
| 8 | 執行中 `self_hook add --event before_run` 立刻生效（旗標檔） | 要重新編譯定義並重起；手寫範本要自己在 loop.json 加 `on_before_run` | 第 8 條 |
| 9 | before_compact 多個 hook 串改（後一個看到前一個改的 instructions） | 每個 hook 拿同一份事件，改的值依名字順序後蓋前 | aos-hook fire 不串改 |
| 10 | `aos-agent ctl add` 對沒有 aos-agent 那格的夾＝InterfaceMissing | 照收（入口＝夾本身） | 第 4 條 |
| 11 | kernel.json 的 `hooks` 鍵有作用 | 沒作用（寫了也不讀）；要寫在 `kernel_hookeds.json` | 甲案 |
| 12 | handler 的工作夾 `<stack>/hooks/<名>/`（gdb 觸發器的 trigger.json／count.json、on_clock.json、kernel_gate 的站） | `<stack>/hookeds/<名>/`；舊夾沒人讀 | 使用者「2.對。」 |

## 三、活樹（家機 `~/aos-home`）要做什麼

**在照下面做完之前，活樹不要起**（包括 start、wake、auto_restart、daemon 重起）。理由兩段：
1. 這筆一交進 repo，`templates/agent-fsm/hook_points.json` 就沒了（改名成 `hooks.json`）；活樹的 lib 還是舊的，舊 lib 照 `{"provider": "agent-fsm"}` 去讀那支檔＝ann 的每一格 `PointsBad` 停下。
2. 跑了 `install.py` 換成新 lib 之後，舊定義夾的 `interfaces.json`（hooks 在 aos-agent 格裡）會被當成「沒有 hookeds」＝**安靜地沒有任何 hook**；舊 loop.json 的 `--agent`、`--field-file`、`--points` 是新 aos-hook 不認得的旗標＝on_start 退 1、起不來。

步驟（停樹、換檔、install、搬 stack 的舊清單、再起）：

```sh
cd ~/aos-home && source env.sh
aos-daemon-ctl -d .stack shutdown                          # 1. 先停（全部睡下）
cd "$AOS_HOME" && python3 install.py                       # 2. 換成新 lib（repo 裡跑：這一步會換掉活樹正在用的 bin/ lib/）
cd ~/aos-home
# 3. 定義夾換成新範本的檔（照你的樹是哪個範本抄的；ann 從 start-api 抄、沒改過定義的話）：
for f in interfaces.json loop.json hookeds.json; do cp "$AOS_HOME/templates/start-api/agents/ann/$f" agents/ann/; done
rm agents/ann/hooks.json                                   #    舊的清單（新版的 hooks.json 是宣告，ann 動態連結範本那份，不需要）
#    ann 的定義 hooks.json 若你自己改過：照「01-現在怎麼寫」三的形狀把那幾格搬進 agents/ann/hookeds.json（拿掉 intercept/async/on_error）
#    llm 與 perm（kernel）：
for k in llm perm; do cp "$AOS_HOME/templates/start-api/$k/"{interfaces.json,kernel_hooks.json,kernel_hookeds.json} $k/; done
cp "$AOS_HOME/templates/start-api/perm/loop.json" perm/   #    perm 的舊 loop.json 用 --points／--list（新 aos-hook 不收）
#    eca 定義（start-eca 抄的或 agent_def new 出來的）：interfaces.json、loop.json、compact_hook、hooks.json→hookeds.json 同樣換；
#    agent.py 編譯的定義：python3 agent.py --compile 重新編譯（會寫 hookeds.json，舊的 hooks.json 刪掉）
# 4. 搬 stack 裡 agent 自己加過、關過的 hook（舊檔名 hooks.json → hookeds.json，拿掉外層 hooks 與三個舊選項）：
for st in .stack/procs/*/; do
  [ -f "$st/hooks.json" ] || continue
  python3 - "$st" <<'PY'
import json, os, sys
st = sys.argv[1]; old = json.load(open(os.path.join(st, "hooks.json")))
new = {n: (None if e is None else {k: v for k, v in e.items() if k not in ("intercept", "async", "on_error")})
       for n, e in (old.get("hooks") or {}).items()}
json.dump(new, open(os.path.join(st, "hookeds.json"), "w"), ensure_ascii=False, indent=1)
print(st, "->", sorted(new))
PY
  [ -d "$st/hooks" ] && mv "$st/hooks" "$st/hookeds"       #    handler 的工作夾（on_clock 狀態、gdb 觸發器、kernel_gate 的站）
done
# 5. 驗一次再起：每隻都要看得到原本的 hook
aos-agent -d .stack --target ann hook ls -l
aos-exec root                                              # 起樹（視窗 A）
```

- 第 4 步做完，舊的 `<stack>/hooks.json` 留著也沒人讀；確認 `hook ls -l` 列出原本的之後可以自己刪。
- kernel_gate 開著的 agent：站在 `<stack>/hookeds/kernel_gate/`（第 4 步搬過去了），但站裡還是舊 kernel.json（hooks 在裡面、沒有 interfaces.json）：`kernel_gate` 工具 `op off` 再 `op on` 不會重寫（kernel.json 在就留著）；要把 `kernel.json` 的 `hooks` 搬成同夾的 `kernel_hookeds.json`，再寫一份 `interfaces.json`：`{"hookeds": "kernel_hookeds.json", "kernel": {}}`。
- 這次在 repo 裡沒跑 `install.py`、沒碰 `~/aos-home`。
