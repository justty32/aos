## 一、interfaces.json（agent）

hook 兩鍵在**最外層**，值是檔名字串、指示詞，或它們的陣列（只收檔名，不收直接寫內容）：

```json
{"aos-agent": {"entry": "body.json", "tools": "tools.json", "llm": "llm.json", "history": "history.jsonl", "system": "system.txt"},
 "hooks": [{"$env": "AOS_HOME", "$path": "/lib/aos/apps/hook/loop_hooks.json"}, "hooks.json"],
 "hookeds": "hookeds.json"}
```

- `hooks`＝有哪些鉤子（hook 點的宣告）；`hookeds`＝有哪些被勾著（掛上去的 handler 清單）。
- 字串＝檔名（相對＝從定義夾算）；物件＝指示詞，經 `aos-directive` 解成路徑（`#/` 從 interfaces.json 自己算）。只有物件那項才起 `aos-directive`，普通檔名不起行程。讀的程式：`py/aos/hook_point.py`。
- 宣告只是參考：沒有任何程式因為「沒宣告」而不跑、不給掛；`aos-hook fire` 與引擎從不讀宣告。
- `aos-agent` 那格不再有 `hooks`、`hook_points`。

## 二、宣告檔（hooks.json、loop_hooks.json、kernel_hooks.json）

一個物件，鍵是 hook 點的 id，值裡**硬性只要 `input`**（JSON Schema：handler 收到什麼）；其餘鍵想放什麼放什麼（`description`、`output`、`block`、`phase`、`condition`…）。頂層 `description` 是一句話、不是點。

```json
{"description": "Hook points fired by the agent-fsm cells ...",
 "before_tool": {"description": "act: before each tool call runs (every tool)",
                 "input": {"type": "object", "properties": {"event": {"const": "before_tool"}, "hook": {"type": "string"},
                           "stack": {"type": "string"}, "name": {"description": "tool name"}, "id": {}, "arguments": {}}},
                 "output": {"type": "object", "properties": {"arguments": {}}},
                 "phase": "before", "condition": "name", "block": true}}
```

位置：`templates/agent-fsm/hooks.json`、`py/aos/apps/eca/hooks.json`、`py/aos/apps/mcp/hooks.json`、`py/aos/apps/hook/loop_hooks.json`（aos-loop 四點）、`py/tools/aos/kernel/kernel_hooks.json`（kernel 三點的正本；每個 kernel 定義夾放一份抄本）。舊的 `change` 改寫成 `output`。

## 三、被勾清單（hookeds.json、kernel_hookeds.json、stack 裡的抄本）

一個物件 `{hook 名: 格 或 null}`，頂層 `description` 是一句話（不再包一層 `hooks`）：

```json
{"description": "What is hooked on this agent ...",
 "guard": {"event": "before_tool", "handler": {"$env": "AOS_HOME", "$path": "/lib/tools/agent/guard"},
           "condition": ["ws_write", "shell"], "timeout_ms": 10000},
 "timer": null}
```

- 引擎只看 `event`、`handler`、`timeout_ms`（預設 60000，0＝不限；到了殺整群）；其他鍵是發事件那一家自己的（agent 的 `condition`、on_clock 的 `every_cycles`／`every_ms`／`clock`／`config`），原樣留著。
- `intercept`、`async`、`on_error` 拿掉了（寫了也不讀）。
- 後面的檔同名蓋前面、`null`＝關掉、檔不在＝沒有 hook。agent：定義的 hookeds 疊上 stack 裡同名那份（`<stack>/hookeds.json`）。
- handler 的工作夾：`<stack>/hookeds/<名>/`（以前 `hooks/<名>/`）。

## 四、aos-hook fire

```sh
echo '{"name": "x"}' | aos-hook fire --list hookeds.json --stack "$ST" before_save
# {"event": "before_save", "hooks": [{"hook": "a", "code": 0, "stdout": "...", "error": null}, ...]}   一律退 0
aos-hook fire -q --stop-on-nonzero --def "$AOS_CD" before_run
# 第一個非 0 就停，用它的碼退出（10 不印錯誤行；其他印 aos-hook: error: HookFailed ...；逾時／起不來退 1）
```

- 只剩 `fire` 一個子指令（`points`、`check` 拿掉）。旗標：`--list FILE`（可重複）或 `--def DIR`（interfaces.json 的 hookeds，相對的那幾份疊上 stack 的抄本）、`--stack DIR`、`--stop-on-nonzero`、`-q`。事件資料只有 stdin 的 JSON（`--field`、`--field-file`、`--field-default`、從環境變數取欄位都拿掉；loop 的 handler 自己讀 `AOS_LOOP_*`、`<stack>/stage.txt`）。
- 照名字排、每個 handler 拿同一份事件（不串改）；攔、改、比條件、失敗怎麼算都不管。
- 範本與編譯出的 loop.json：`on_start`／`on_stop` 一律接、帶 `--stop-on-nonzero`；`on_before_run`／`on_after_run` 只在編譯時有 hook 掛那兩點才寫進去（沒有旗標檔了），手寫範本預設不接。

## 五、aos-agent hook add（self_hook 同參數）

```sh
aos-agent hook add --event before_tool --condition ws_write --timeout-ms 5000 ./guard
aos-agent hook add --event on_clock --every-ms 60000 --name ping --path-json '{"$env":"AOS_HOME","$path":"/lib/tools/agent/hook_noop"}'
```

旗標：`--event`、`-n/--name`、`--timeout-ms`、`--replace`、`--path-json`，加 agent 自己留的 `--condition`（只攔某支工具）與 on_clock 的 `--every-cycles`／`--every-ms`／`--clock`／`--config`。`--no-intercept`、`--async`、`--on-error` 拿掉。事件名不驗。掛 `before_run`／`after_run`／`after_start`／`after_stop` 而 loop.json 沒接那條線＝多一行 warning（要重新編譯並重起）。

## 六、各家自己的規矩

**agent 一家**（`py/aos/agentlib/hooks.py` 的 `POINTS`，agent-fsm 四格、aos-eca-turn、aos-mcp 共用）：

| 點 | condition 比 | 退 10 | stdout 能改 |
|---|---|---|---|
| before_queue | — | 攔（丟信） | content（非空字串） |
| after_queue | — | — | — |
| before_tool | name | 攔（工具不跑） | arguments |
| after_tool | name | — | content（字串） |
| brain_failed | name | — | — |
| tool_added | name | — | — |
| on_clock | — | — | — |

hook 失敗（退 0／10 以外、逾時、起不來、stdout 不合）：能攔的點（before_queue、before_tool）＝這個事件停（HookFailed，格程式退 1；aos-mcp 那次工具回 isError）；其他點＝一行 warning、下一個照跑。照名字跑、前一個改的後一個看得到。

**eca 的 compact_hook**（before_compact／after_compact）：經 `aos-hook fire --def` 發，自己讀結果：第一個退 10 的攔下；退 0 的 stdout 物件依名字順序設 instructions／restore（每個 handler 拿同一份事件）；失敗的一行 warning。

**loop 的四個點**：handler 的退出碼經 `--stop-on-nonzero` 原樣給 aos-loop：before_run 退 10＝跳過這圈；其他非 0（四個點都一樣，after_run 退 10 也算）＝loop 收工。

**kernel**（`py/tools/aos/kernel/hooks.py` 的 `POINTS`）：三個點都能攔；after_verdict 的 condition 比 verdict；能改 body／verdict、error、next／body；hook 失敗＝這一輪停（HookFailed）。

**gdb**：觸發器照舊是一個普通 hook；gdb_trigger 自己的錯一律一行 warning、退 0（不靠 on_error）。

## 七、kernel 甲案

```json
{"description": "What this kernel offers ...",
 "hooks": ["kernel_hooks.json", {"$env": "AOS_HOME", "$path": "/lib/aos/apps/hook/loop_hooks.json"}],
 "hookeds": "kernel_hookeds.json",
 "kernel": {}}
```

- `kernel_hooks.json`：kernel 三點的宣告，每個 kernel 定義夾一份（正本在 `py/tools/aos/kernel/`，編譯照抄）；loop 身體多一項指示詞指 aos-loop 的宣告。daemon 身體只寫 `"hooks": "kernel_hooks.json"`。llm kernel 另有 `aos-ledger`。
- `kernel_hookeds.json`：被勾清單，kernel 三點與 loop 四點的格都放這一份；kernel 程式每輪照 `interfaces.json` 的 `hookeds` 讀（kernel.json 的 `hooks` 鍵拿掉；`loop_hooks.json` 這個清單檔沒了）。
- `"kernel": {}` 放最外層，這次裡面沒東西。
- 編譯（`aos.py.kernel.defs`）一律寫 `interfaces.json`、`kernel_hooks.json`、`kernel_hookeds.json`。
- kernel_gate 的站（`<agent stack>/hookeds/kernel_gate/`）`on` 時寫自己的 `interfaces.json`＋`kernel_hookeds.json`（預設那支 hold 在這裡）。
