| # | 題目 | 挑了什麼 | 理由／另一條路 |
|---|---|---|---|
| 1 | 拿掉 `on_error` 之後，agent 一家 hook 失敗怎麼算 | **能攔的點（before_queue、before_tool）＝停**（HookFailed，格程式退 1；aos-mcp 那次工具回 isError）；**其他點＝一行 warning、下一個照跑** | 舊預設是「停」（使用者 11-10「默認跟着停」），但出廠的 hook（timer、mail_notify、context_wrap、brain_notify、screen_linger）與 gdb 全都寫 `on_error: continue`；一律停＝出廠 hook 一壞 agent 就倒，一律放＝擋工具的 guard 一壞工具就跑。分點的寫法讓「會擋人的點壞了就擋住、只是通知的點壞了不影響」。要改成一律停或一律放：`agentlib/hooks.py` 的 `fire` 裡一行 |
| 2 | kernel 的 hook 失敗 | 三個點都能攔，所以一律停（ctx.die HookFailed） | 跟 1 同一條規則；也等於舊預設 |
| 3 | loop 四點（aos-hook fire 發） | 照第 7 條：四行都帶 `--stop-on-nonzero`；handler 退出碼原樣給 aos-loop：before_run 退 10＝跳過這圈；其他非 0（四點都一樣，**after_run 退 10 也算**）＝loop 收工 | 「after 點退 10 的問題照第 7 條的旗標解」的讀法：不再把 10 換成 0，交給 aos-loop 照碼辦。宣告 `loop_hooks.json` 寫明了。另一條路：旗標收一個值（例 `--stop-on-nonzero=before`）讓 after 點的 10 當 0 |
| 4 | 執行中新掛 before_run／after_run | `aos-agent hook add`（self_hook 同）照樣加進清單，但定義的 loop.json 沒接那條線時多印一行 warning（要重新編譯並重起） | 定案「執行中新掛要重新編譯並重起才生效」；不擋、只提醒（宣告只是參考的精神） |
| 5 | 手寫範本的 loop.json | agent-fsm、eca-claude、eca-pi、兩份 ann、procs-kernel、perm：**只接 on_start／on_stop**，before_run／after_run 不接（出廠沒人掛） | 接了＝每圈多起一支 aos-hook（約 36 ms，閒著的 agent 每秒 3 支）；description 寫了怎麼自己加 |
| 6 | `aos-hook` 的子指令與旗標 | 只剩 `fire`；`points`、`check` 拿掉；`--points`、`--field*`、`-j` 拿掉；`--agent` 改名 **`--def`**（kernel 的 loop 身體也用它，不是 agent 專用） | 第四層：宣告不讀、旗標檔沒了，`check` 與 `points` 沒有工作；`--def` 只做「interfaces.json 的 hookeds＋stack 抄本」這件通用的事 |
| 7 | `aos-hook fire` 的輸出 | `{"event", "hooks": [{"hook", "code", "stdout", "error"}]}`；逾時、起不來＝code null＋error（另一行 warning）；`--stop-on-nonzero` 停在非 0：10 不印錯誤行、其他碼印 `HookFailed` 並用 handler 的碼退出；逾時／起不來退 1 | 「交回每個 handler 的輸出與退出碼」照字面 |
| 8 | 事件資料 | 只有 stdin 的 JSON。loop 的事件只剩 event／hook／stack，handler 讀 `AOS_LOOP_*` 環境變數與 `<stack>/stage.txt` | 03b 第 4 層原樣；`--field` 也拿掉（shell 要給欄位就 `echo '{…}' \|`） |
| 9 | aos-hook fire 每個 handler 拿到的資料 | 同一份（不串改） | 引擎不懂「改」；要串改的家（agent、kernel）用 Python 自己一個一個跑 |
| 10 | 宣告檔與清單檔裡的 `description` | 頂層 `description` 是一句話、不是點／不是 hook；`description` 不能當 hook 名 | 兩種檔都要能寫說明；JSON 物件以 id／名字當鍵時只能保留一個字 |
| 11 | 同一個 id 在兩份宣告 | 先寫的算（`hook_point.read`） | 宣告只是參考，不報錯 |
| 12 | 宣告硬性檢查到哪 | 只查：檔是物件、id 只有 a-z0-9_、每點有 `input` 物件。誰會查：只有測試與想讀宣告的程式（`hook_point.read`）；`aos-hook`、引擎、agent、kernel 都不讀宣告 | 「宣告這東西只是參考」 |
| 13 | interfaces.json 的指示詞怎麼解 | 只有物件那項經 `aos-directive` 解（`#/` 從 interfaces.json 自己算、`--at` 給那一格的位置）；普通檔名不起行程 | agent 每格（300 ms）都要讀清單，不能每次起一支 aos-directive |
| 14 | `hookeds` 是陣列時 stack 抄本怎麼算 | 定義的那幾份依序，再疊 stack 裡「相對檔名那幾項」的同名抄本；`aos-agent hook` 寫的是第一個相對檔名的抄本；全是指示詞＝`HooksMissing`（沒地方寫） | 單一字串（出廠都是）跟以前一樣 |
| 15 | agent 留的鍵 | `condition`（只攔某支工具，第 9 條）與 on_clock 的 `every_cycles`／`every_ms`／`clock`／`config` 都留在 hookeds 那格；`aos-agent hook add` 照留這些旗標 | 任務書的旗標清單沒列 on_clock 的，但 on_clock 是「各家自己的規矩」、出廠 context_wrap 的說明教人用 `self_hook add … config`，拿掉就壞了 |
| 16 | condition 寫在不比的點 | 照收、不比、不報錯（以前 `HooksBad: event X takes no condition`） | 「點沒宣告卻寫條件會報錯——改成不擋」 |
| 17 | 事件名 | 任何非空字串都收（`aos-agent hook add`、編譯、清單） | 宣告只是參考；`self_hook` 的 `event` 照舊是列舉（給腦看的） |
| 18 | 「起來後第一次 on_clock 一定跑」 | 以前靠 `aos-hook fire --agent … after_start` 清狀態；現在 hook_clock 自己記「看過哪一次 loop」（`<stack>/state.json` 的 boot_id、pid、started_at_ticks），對不上＝第一次 | aos-hook 不做 agent 專用的事（第 2 層起就要搬家，04 邊緣 9）；不必多掛一支 after_start hook |
| 19 | `aos-agent ctl add`／`set-def` 沒有 aos-agent 那格 | 照收，宣告當 `{}`（入口＝夾本身） | 任務書第 4 條 |
| 20 | gdb 的「斷點壞了不擋 agent」 | 由 gdb_trigger 自己保證：讀不到設定、寫不了檔＝一行 warning、退 0（以前靠 `--on-error continue`）；它 stdout 本來就不印（以前靠 `--no-intercept`） | 各家自己做；gdb 是掛 hook 的一方 |
| 21 | gdb 能下斷點的種類 | 寫在 gdb 裡：agent 一家的點（去掉 on_clock）＋ before_compact、after_compact ＋ loop 四點，順序同以前 | 以前由四份宣告合起來算；「gdb 從宣告讀」這次不做 |
| 22 | eca 的 compact_hook | 自己讀 aos-hook 的原始輸出：第一個退 10 的攔；退 0 的 stdout 物件依名字順序設 instructions／restore；每個 handler 拿同一份事件；失敗一行 warning | 跟 1 的「只是通知的點不擋」一致，而且 compact_hook 本來就「什麼錯都不擋 Claude」 |
| 23 | 編譯：agent.py 的欄位名 | 照舊叫 `hooks=`、`std.hooks()`（讀範本的 `hookeds.json`），寫出的檔名改 `hookeds.json` | 改 Python API 名字會動到使用者寫好的 agent.py；要改名另外說 |
| 24 | 編譯：`interfaces=` 能不能蓋 | 能蓋最外層 `hooks`（宣告，例：eca 那種另一組點）；蓋 `hookeds`＝SpecBad（由 `hooks=` 決定） | 跟以前「aos-agent 的 hooks 由 agent.py 設」同一條 |
| 25 | 編譯：`fn.block` 用在不能攔的點 | 不再擋（以前 SpecBad） | 那是宣告驅動的驗證；不能攔的點收到 10 由發事件的那一家自己看（agent：當放行） |
| 26 | 編譯：hooks 是 `defs.extern(...)` | loop.json 只接起停兩點（不打開連結看有沒有 before_run） | 編譯不讀 extern 的內容 |
| 27 | kernel 編譯 | 一律寫 `interfaces.json`、`kernel_hooks.json`（宣告抄本）、`kernel_hookeds.json`（沒 hook 也寫一份只有 description 的）；`program="kernel"` 以前不寫 interfaces.json | 甲案要每個 kernel 夾都有 |
| 28 | kernel 宣告的正本 | 在 kernel 程式夾 `py/tools/aos/kernel/kernel_hooks.json`，每個 kernel 定義夾一份抄本（測試比對內容一致） | 「放在每個 kernel 的定義夾」＋編譯要有地方抄 |
| 29 | kernel 的被勾清單 | kernel 三點與 loop 四點的格放同一份 `kernel_hookeds.json`；kernel 程式只讀定義夾那份（不疊 stack 抄本）；`aos-hook fire --def` 給 loop 點時會疊 stack 抄本（不在＝沒有） | 一隻 kernel 一份清單最好找；kernel 以前沒有 stack 抄本這回事 |
| 30 | kernel_gate 的站 | `on` 時在站的小格寫 `kernel.json`（`{}`）、`kernel_hookeds.json`（預設 hold）、`interfaces.json`；舊站（`hooks/kernel_gate/`）不搬 | 甲案下 kernel 只照 interfaces.json 找清單 |
| 31 | 出廠範本的 `kernel_hookeds.json` | 每個 kernel 夾都放一份只有 description 的 | 讓人看得到要往哪寫 |
| 32 | `"kernel": {}` | 每個 kernel 夾的 interfaces.json 都寫（含 kernel_gate 的站） | 頂層提過、他沒反對 |
| 34 | 出廠 eca 的 `screen_linger`（掛在 after_start／after_stop） | 當 hook 跑時自己的錯只一行 warning、退 0（reap 用法照舊退 1） | 以前靠 `on_error: continue` 不擋 eca 起來；loop 點失敗現在會讓 loop 收工，所以由它自己保證（同 gdb_trigger） |
| 33 | 一律不留的舊東西 | 舊鍵名、舊檔名、舊旗標、`hook_handle.py`／`hook_flags.py` 的呼叫，全部沒有相容與提示 | proto8 當沒有舊版 |
