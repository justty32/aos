「信封寫的寄件人」怎麼對到「一個 uid」：今天已經存在的兩張表、三種對法，以及怎麼不讓 agent 跟 daemon 綁在一起。

# 乙 2、對照表放哪、誰寫、怎麼不耦合

← [README](README.md)｜上一份：[02](02-信從哪裡進來.md)｜下一份：[04-對不上怎麼辦與誰驗](04-對不上怎麼辦與誰驗.md)

## 今天已經有的兩張表

| 表 | 在哪 | 誰寫 | 內容 | 能不能拿來反查 |
|---|---|---|---|---|
| kernel 站的 `users` | kernel 站自己的 `kernel.json` | 人 | proc **名字樣式** → `sub:N` | 只能答「叫這個名字的 proc 該是哪個 N」；寄件人是路徑，要先從路徑知道它是哪個 proc |
| daemon 表那一列 | daemon 的 `procs_state.json`（每列有名字、stack、ws、生效的 `limits`，含 `user: "sub:N"`） | daemon | 這一列實際用哪個 N 起的 | 能：stack 路徑 → 那一列 → N → 真 uid＝`/etc/subuid` 起點＋N－1 |

兩張表存的都是 **`sub:N`，不是真 uid 號碼**。真號每台現算（家機與公司 WSL 起點都是 100000，只是剛好）。這點對可遷移很重要：資料夾搬到另一台，表照用，號碼在新那台重算。

## 三種對法

| 對法 | 怎麼做 | 要什麼表 | 好處 | 代價 |
|---|---|---|---|---|
| **甲 比對** | 信封 `sender`（路徑）→ 找到它是哪一列 → 那列的 `sub:N` → 真 uid，跟信夾擁有者比 | daemon 表（或 kernel 站自己記的放行紀錄） | 信封格式、各處 key 都不用改；比不上就知道「有人冒名」 | 驗的人要讀得到 daemon 的表；`sender` 是工作區時好幾隻共用一個路徑，對不到唯一一列；同一個 N 給了好幾隻（`users` 寫 `"*"`）時比對沒意義 |
| **乙 取代** | 不比，直接把擁有者換算回 `sub:N`，當成「這封信的身分」；規則（`by_sender`、`budget.senders`）改用 `sub:N` 寫，信封的路徑只當顯示 | 只要 `/etc/subuid`（號碼 ↔ N），不用 daemon 表 | 不讀任何別人的表；跟 daemon 完全不耦合；搬家只要 N 對得上 | 規則的寫法換了一種 key；擁有者是樹主（同帳號）的信都變成同一個身分「樹主」，同帳號的人、eca 本體、沒換身分的 agent 分不開 |
| **丙 只分兩類** | 擁有者是樹主 uid＝「樹主這邊」（照舊信自報）；是名下某個子帳號＝「agent」，再細的照自報 | 只要 `/etc/subuid` | 最小；擋得住「agent 冒充人或冒充 kernel」這一型 | 擋不住 agent 冒充別隻 agent |

這三種是方向，列在 [08 第 3 題](08-待裁題.md)。

## 誰寫對照表

- `sub:N` 照舊**只有一個來源**：kernel 站的 `users` 表（人寫）→ 放行的信 → daemon 照填的換（kernel-limits-plan 已裁，proc 自己不知道，C-52「偷偷」）。
- 驗寄件人**不新增表**：甲用 daemon 已經在寫的那一列；乙、丙只用 `/etc/subuid`。我替使用者選的：**不在任何地方存真 uid 號碼**。

## 「agent 不該和 daemon 耦合」怎麼不違反

他 11-21 的話針對的是「**agent 記自己在哪個 daemon 底下**」：資料夾要能整份複製、換一台 daemon 跑。對照下來：

1. **agent 什麼都不用知道**：寄信的 agent 不寫自己的 uid、不讀 daemon 表；換身分是 daemon 起它時偷偷做的。搬到另一台 daemon，新的 kernel 站照它的 `users` 表給新的 N（或不給），agent 夾一個字都不用改。這條三種對法都成立。
2. **驗的那一方是 kernel**：kernel 站本來就站在 daemon 前面、轉寄進 daemon 的信箱，它知道「我是哪台 daemon 的門」不算 agent 的耦合。甲要 kernel 讀 daemon 表，耦合的是 kernel↔daemon，不是 agent↔daemon。
3. **會違反的寫法**（列出來避開）：讓**一般 agent 的信箱**也照甲去比對——那就要每隻 agent 讀 daemon 表；或在 agent 的 stack 裡記「我的 N」。乙、丙不需要表，一般 agent 也能用；甲最好只放在 kernel。
4. **搬家時**：甲靠 daemon 表，搬到新 daemon 後那一列是新的（新的 N 或沒有），比對自然照新的算；乙、丙只看新那台的 `/etc/subuid`。三種都不用遷移資料。但「搬家那一刻還沒收的信」擁有者會變（[06](06-邊緣狀況.md) 第 1 條）。

## 驗的人自己必須是樹主（實測 T3）

在子帳號的 namespace 裡，使用者的檔顯示 `0`、別的子帳號顯示 `65534`（「沒對到的人」一律顯示成這號）。所以**驗的程式必須在樹主帳號、namespace 外面跑**，不然它看所有別人的信都是 65534、看人的信是 0。kernel 站與 llm kernel 若被 `users` 表的 `"*"` 也換成子帳號，就變成瞎子。這是 [05](05-擋不住的.md) 與切刀時的硬條件：**被驗的是 agent，驗的人不換身分**。
