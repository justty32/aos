# 乙 7、待裁題

只列從他已說的話推不出來的。K9（分了 uid 要不要用擁有者認寄件人）已裁「要」，不重問。

## 第 1 題：擁有者跟信封對不上時，收信的 kernel 怎麼辦？

| 選項 | 後果 |
|---|---|
| A 拒收，退一封錯誤信 | 冒名的當場被擋、看得到錯誤行；邊緣狀況誤傷（人手放的信、複製過的信）時信進拒收處，要人去撿 |
| B 收下，但在交給規則與 hook 的資料裡標「對不上」 | 不丟信；要不要擋由各 kernel 的規則或 hook 自己寫，範本不寫就等於照過 |
| C 收下，只在 kernel 的紀錄寫一行 | 最不打擾；事後查得到，沒人看紀錄就等於沒做 |
| D 每個 kernel 的設定自己選 A／B／C，範本預設不看 | 最有彈性；第一次要用的人得自己想清楚選哪個 |

## 第 2 題：哪些收信處要驗？

| 選項 | 後果 |
|---|---|
| A 只有收請求的 kernel（kernel 站、llm kernel） | 擋在真的照寄件人分人的地方（`by_sender`、額度）；agent 之間的信、使用者專區不驗 |
| B A＋使用者專區的 `verify` | 專區回信多一道「擁有者是你本人」；專區程式要先進 repo；對 eca 本體無效（K7 留你的 uid） |
| C 每個收信方都拿到擁有者這個事實（一般 agent 的 `mailbox_read` 也顯示），只有 kernel 會擋 | agent 自己也看得到「這封信真的是誰的」；一般 agent 只看到號碼或 `sub:N`，不讀 daemon 表 |
| D 先只把事實讀出來，哪裡都不擋 | 只做第 1、6 刀；擋不擋等真的被冒名坑到再說 |

## 第 3 題：「信封寫的寄件人」怎麼對到擁有者？

| 選項 | 後果 |
|---|---|
| A 比對：寄件人路徑 → daemon 表那一列的 `sub:N` → 跟擁有者比 | 信封與規則寫法都不變；驗的 kernel 要讀 daemon 的表（kernel↔daemon，agent 不受牽連）；寄件人寫的是共用工作區時對不到唯一一列 |
| B 取代：不比，擁有者換算成 `sub:N` 就是這封信的身分；`by_sender`、額度改用 `sub:N` 寫 | 不讀任何表、跟 daemon 完全不綁；同帳號的人、eca、沒換身分的 agent 全算同一個「樹主」 |
| C 只分兩類：擁有者是你＝「你這邊」，照舊信自報；是子帳號＝「agent」 | 最小；擋得住 agent 冒充你或冒充 kernel，擋不住 agent 冒充別隻 agent |

## 第 4 題：家機的家目錄（700）怎麼讓子帳號穿過去？

不開這扇門，家機上任何 `sub:N` 的 agent 都起不來（實測 `cannot reach /home/lorkhan`）；公司 WSL 11-19 你已改成 751。

| 選項（你親手跑） | 後果 |
|---|---|
| A `setfacl -m g:160000:x ~` | 只有 aos 換了身分的 proc（預設群組）能穿過去、列不出裡面；這台已有 `setfacl`。daemon 換了 `group` 要多加一行 |
| B `chmod 711 ~`（或跟 WSL 一樣 751） | 最簡單；這台其他帳號也能穿過去，讀得到家目錄裡本來就開放讀的東西（`~/repo`、`~/.aos` 是 755） |
| C 把樹與 repo 搬到家目錄外（要 sudo 建一次夾） | 家目錄不動；兩台路徑都要改，代價最大 |
| D 家機先不開子帳號，只在公司 WSL 驗 | 家機維持 demo；第 3 刀以後的驗收只能在公司做 |

## 可晚點再答

1. **kernel 代寄要不要把驗過的原寄件人帶下去**（加一個 key，下一站只能相信上一站）：今天 daemon 不看寄件人，不帶也不壞。
2. **queue 給好幾個 uid 投時用什麼門**：`drop` 樣板的 sticky 會擋有序投遞（實測 T6）；或 queue 只收你這邊的信。
3. **信裡的附檔要不要也看擁有者**：今天收信方多半只看 `letter.json`。
4. **`users` 表要不要強制一隻一個 `sub:N`**：同一個號碼給好幾隻時，它們彼此冒名擋不住（05 第 6 條）；這是設定習慣，也可以只寫進說明。
5. **同帳號這一群（你的 shell、eca 本體、沒換身分的 agent）要不要互相分得開**：要分只能讓它們也換身分；eca 本體 K7 已裁先留你的 uid，這題等你想動 K7 時再說。

## 這條線替你做的選擇（逐條，不對可以翻）

1. **只存 `sub:N`、不存真 uid 號碼**；真號每台照 `/etc/subuid` 現算（可遷移）。
2. **同帳號時檢查不啟用**：擁有者是你的 uid、推不出身分、或驗的人自己看到 65534，一律照今天的樣子走——demo 狀態自然不受影響。
3. **信夾與 `letter.json` 兩個擁有者都看**，兩個都要對（擋「換掉 `letter.json`」那一型）。
4. **驗的人不換身分**：kernel 站、llm kernel 留在你的 uid、在 namespace 外跑，不然看別人全是 65534。
5. **分層**：aos-post 這類基底工具只讀出擁有者、不判好壞；要不要擋由 kernel 定（C-47「kernel 定政策」的延伸）。
6. **agent 什麼都不記**：寄信的 agent 不寫自己的 uid、不讀 daemon 表；需要表的對法（第 3 題 A）只放在 kernel。
7. **投遞門照 K16 用 `aos-share` 指令開**，不讓 daemon 自動改信箱權限。
8. **搬家時不帶擁有者是正常情形**，不寫任何遷移；搬過來的舊信算「同帳號、不啟用」。
9. **不碰 root、不碰 auditd**（K8）；「最後編輯者」這件事 Linux 不記，這份不設計它。
