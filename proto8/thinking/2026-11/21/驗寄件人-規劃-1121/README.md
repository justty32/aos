# 驗寄件人：規劃（11-21）

← [2026-11-21](../README.md)｜相關：[linux-as-hw-1118](../../18/linux-as-hw-1118/README.md)（丙案）、[kernel-limits-plan](../../13/kernel-limits-plan.md)（K9、K16）、[subuid-1119](../../19/subuid-1119.md)

使用者 11-21 下午：「aos自己的身份是自己報的 <- 應該可以用最後編輯的user來看？有這功能嗎？」「這個還沒做...得去規劃一下，現在就去。」（全文 [00](00-使用者原話.md)）。讀 HEAD `42a50a5f9` 的程式；實測在 `git archive` 的乾淨複本 `~/.aos/scratch/top-1121-ownerplan/`，沒碰 `~/aos-home`、沒用 sudo、沒叫模型。

## 先講結論

1. **Linux 不記「最後編輯的人」，只記「誰建的」**（擁有者，像檔案上的「建檔人」欄）。aos 的信是寄件人自己建的夾，所以「建檔人」剛好就是寄件人——只要寄件人用 aos 的寄信工具、沒人事後去動。
2. **子帳號那一哩比 11-18 寫的前進很多**：11-19 daemon 已經會把 `limits.user: "sub:N"` 的 proc 換成真的子帳號（公司 WSL 真機驗過，檔案歸 100004）。**家機斷在家目錄 700**：實測 daemon 換完身分就報 `cannot reach /home/lorkhan`，起不來。家機其他前置（`/etc/subuid`、`newuidmap`、`setfacl`）都在。
3. **就算起得來，也還寄不出信**：daemon、kernel、llm kernel、別隻 agent 的信箱都沒開投遞門；而且本線實測發現，**收信方收不下子帳號寄的信**（收信要對信夾本身有寫權限），信箱得帶預設 ACL。今天範本裡沒有任何一支 proc 換身分，demo 全同帳號。
4. **擁有者＝寄件人在每個收信處的第一站都成立**（全部寄信都經 aos-post）；轉寄後只認得上一站。今天真的「照寄件人分人」的只有三處：kernel 站 `by_sender`、llm kernel 額度、使用者專區；daemon 根本不看寄件人（[02](02-信從哪裡進來.md)）。
5. **擋得住的**：子帳號 agent 冒充別人、別人冒充子帳號 agent。**擋不住的**：原地改檔（擁有者不變）、同帳號這一群（你的 shell、eca 本體、沒換身分的 agent）互相冒名、root、同一個號碼給了好幾隻；驗的人若自己是子帳號，看別人全是 65534（[05](05-擋不住的.md)）。這剛好對上你說的「只防走規矩的存取」。
6. **七刀**（[07](07-切刀.md)）：0 家目錄（你親手）、1 讀出擁有者（小）、2 號碼換算（小）、3 開投遞門（中）、4 kernel 接政策（小～中）、5 使用者專區（小）、6 條文。**1、2、6 現在就能做**，同帳號時只多一欄「擁有者＝我」，行為不變。
7. **要你拍板四題**（[08](08-待裁題.md)）：對不上怎麼辦、哪些收信處要驗、信封怎麼對到擁有者、家機家目錄怎麼開。另有五題可晚點答、九條我替你定的選擇。
