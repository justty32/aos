看擁有者驗寄件人擋不住的六型：原地改檔、namespace 裡的號碼、同帳號、eca 本體、root、同一個 N 給好幾隻；附實測出處。

# 乙 4、擋不住的

← [README](README.md)｜上一份：[04](04-對不上怎麼辦與誰驗.md)｜下一份：[06-邊緣狀況](06-邊緣狀況.md)

照他今天的原則「只防走規矩的存取，不守規矩的就是要自己承擔風險」，下面每一型都標「守規矩的會不會碰到」。

## 1. 直接改既有檔：看不出誰改的

- Linux 的擁有者是「誰建的」，不是「誰最後改的」。他 11-21 第一句問「最後編輯的 user」——**Linux 沒有這一欄**（mtime 只記時間，不記人）；要記「誰改的」得靠 auditd 之類（要 root，K8 說先不走）。
- 實測 T5：使用者 uid 在帶預設 ACL 的信箱裡**原地覆寫**子帳號寄的 `letter.json`，擁有者仍是 100004、內容已換。
- 誰改得到：凡是那封信夾的 ACL 給了寫權限的 uid。投遞箱樣板（`aos-share drop`）的預設 ACL 只給收信方；小格的預設 ACL 給 agent 自己與 daemon 的 uid。所以**改得到的是收信方自己和樹主 uid**（人、eca 本體、沒換身分的 agent、kernel、daemon 全在這一格）。
- 收信方改自己收到的信沒有意義（它自己就是要讀的人）；**真正的洞是「樹主 uid 的任何程式都能改子帳號寄出、還沒被收的信，而擁有者照舊是子帳號」**。
- 換掉 `letter.json`（寫新檔再改名蓋過去）就看得出：`letter.json` 擁有者變了、信夾沒變。所以我替使用者定了「**信夾與 `letter.json` 兩個都看，兩個都要對**」。
- 守規矩的會不會碰到：不會（沒人該去改別人的信）。

## 2. namespace 裡看到的號碼與外面不同

- 實測 T3：子帳號的 ns 裡，使用者的檔是 `0`、自己是 `N`、別的子帳號是 `65534`。
- 後果：**驗的人必須是樹主、在 ns 外**（[03 末節](03-對照表與耦合.md)）。被 `users` 的 `"*"` 換了身分的 kernel 站，驗不了任何人。
- 另一面：子帳號的 agent 自己 `ls -l` 看到使用者的檔「歸 root」，會以為是系統檔。只影響它的理解，不影響權限（ns 裡的 0 號沒有外面的特權）。
- 推的、沒實測：使用者 uid 擁有且帶 setuid 位的檔，子帳號在它的 ns 裡執行時會變成 ns 的 0 號＝外面的使用者 uid。一般家目錄沒有這種檔；記著。

## 3. 同帳號（人的 shell、沒設 `sub:N` 的 agent、kernel、daemon）

- 這一群全部是樹主 uid，擁有者分不出誰是誰。11-18 E1 那種「人自己的 shell 設 `AOS_WS=…/eca_main` 寄信」擁有者照實是 1000，**跟真的 eca_main 寄的一模一樣**。
- 怎麼算：同帳號＝「沒有證據」，不是「證據對不上」。我替使用者定了：**擁有者是樹主 uid、或對照表裡那個寄件人沒有 `sub:N` 時，檢查不啟用（當成今天的樣子）**。這就是 demo 狀態「自然不啟用」的那條。
- 代價：同帳號這一群之間互相冒名照舊擋不住；要分開只能讓它們也換身分（他說的「多依賴 linux 的權限體系」）。

## 4. eca 本體（claude／codex）

- K7 已裁先留使用者 uid（CLI 要讀寫使用者的登入資料）。所以 eca 本體、它開的 shell、它叫的工具，**擁有者全是使用者本人**。
- 後果：最常開 shell 的那一型，擁有者驗證對它無效；它冒充人、冒充別隻同帳號 agent，看擁有者都看不出。它冒充子帳號 agent 則**看得出**（它建不出子帳號的檔）。
- 不重裁 K7；只記：「看擁有者」真正擋到的是**子帳號 agent 冒充別人**，以及**別人冒充子帳號 agent**。

## 5. root

- root（含 `sudo` 成功的任何程式）可以 `chown` 任何檔成任何擁有者，擁有者驗證對它無效。
- 01 的家機查過：使用者在 `wheel`；11-18 04 第 14 條提過同 uid 的 agent 吃到 sudo 快取的可能。子帳號 agent 不在 sudoers，碰不到這條。
- 照 K8 不往 root 那邊設計。

## 6. 同一個 N 給了好幾隻

- kernel 站的 `users` 表照名字樣式給號碼，README 建議最後寫 `"*"` 兜底。若好幾個樣式（或 `"*"`）給同一個 `sub:N`，那幾隻 agent 擁有者一樣，**彼此冒名照樣擋不住**。
- 另外 `users` 對的是**要起的 proc 的名字**，名字是寄件人自己取的（kernel 站 README 已警告）。一隻 agent 請 kernel 起一支叫 `sol-x` 的 proc，就能拿到給 `sol-*` 的那個 N——之後那支 proc 寄的信，擁有者是「`sol-*` 那個身分」。要擋得靠 `allowed` 限名字。
- 守規矩的會不會碰到：只要設定照「一隻一個 N」寫就不會；這是設定的事，不是程式能擋的。
