## 刀 0：家目錄（使用者親手、不是程式）

家機家目錄 700，daemon 起的子帳號 proc 一律 `cannot reach /home/lorkhan`（01 T1）。選項在 08 第 4 題（跟 11-19 subuid-1119 Q1 同一組；公司 WSL 那台使用者選了 751）。驗收：複本重跑 aos-daemon `test_subuid`，4 條真機條從 skip 變過。

## 刀 1：讀出擁有者

- 新：`py/aos/letter_owner.py`（一句話檔頭；`os.stat` 信夾與 `letter.json`，回兩個 uid）；C++ 在 `cpp/aos-post/include/aos/post.hpp`＋`src/take/take.cpp` 的 `Seen` 多兩欄（`see` 時一起 stat）。命令列 `aos-post see` 印的是 `letter.json` 原文，不往裡面塞欄位。
- 用的地方（只記、不判）：kernel 站 `py/tools/aos/kernel/letters.py`（see 之後）把 uid 放進 hook 事件與 `forwarded.json`；llm kernel `py/tools/aos/kernel_llm/llm_rules.py`（認領後）放進帳本（`ledger.py`）。daemon 的 `mailbox.cpp` 不看寄件人，不用改。
- hook 事件多欄要跟 hook 新格式的宣告一起改（別線在動 `hook_points`，施工時看那時的格式）。
- 驗收：同帳號暫存樹上欄位＝自己的 uid、其餘輸出逐位元組相同；用 T2 的 `unshare` 做法造一封子帳號的信，欄位是 100004（沒有 `newuidmap` 的機器 skip）。

## 刀 2：號碼換算與對照

- `uid → sub:N`：Python 已有兩份 `/etc/subuid` 解析（`py/aos/apps/share/main.py`、`py/aos/apps/asuser/main.py`），收成一份小模組給兩者與驗的人共用；C++ 已有 `cpp/aos-daemon/src/child/subuid.cpp` 的 `sub_range`。規則：樹主 uid＝「樹主」；名下段內＝`sub:N`；其他（含 65534）＝推不出。
- 選甲時多一段：kernel 站從寄件人路徑找 daemon 表那一列（`py/aos/daemon_ctl/table.py` 已會讀表），取那列 `limits.user`。寄件人是工作區、對到多列時＝推不出。
- 驗收：單元測試用假的 subuid 檔（`aos-share` 已有 `AOS_SHARE_SUBUID` 給測試用的先例）。

## 刀 3：收信處開投遞門

- 這一刀其實是 kernel-limits-plan 段 3 剩下的「信箱與共用夾的權限」（K16：用指令，不讓 daemon 自動改）。沒有它，子帳號 agent 寄不出、收信方收不下，**刀 4 沒有信可驗**。
- 要開的：kernel 站與 llm kernel 的 `requests/`、要收子帳號信的 agent `mailbox/`。daemon 的 `procs_requests` 前面有 kernel 站時不開（子帳號直接碰不到 daemon，正是要的）。
- **queue 不能直接套 `drop`**（06 第 18 條、T6）：有序投遞要改寫 `order.json`，sticky 會擋。要嘛 `aos-share` 多一個不帶 sticky 的樣板，要嘛 queue 只收樹主這邊的信；施工時另定，屬細節。
- 改：`py/aos/apps/share/`（若加樣板）、範本 README 寫該下的指令；活樹權限收緊（K10）另放行。
- 驗收（刀 0 後在家機，或在公司 WSL）：一支 `sub:5` 的 proc 寄信給 kernel 站 → 站收得下、擁有者 100004；別的子帳號讀不到它的信。

## 刀 4：接上政策

- kernel 站：`procs_rules.py`（設定驗證）、`letters.py`、`hooks.py`（事件欄）；新設定鍵（名字施工時定），**不寫＝不啟用**。對不上時照第 1 題做（拒＝新錯誤代號、退信；標＝事件多一欄；記＝寫一行）。`by_sender` 的 key 若選乙改用 `sub:N`。
- llm kernel：`llm_rules.py`、`budget.py`（`budget.senders` 的 key 同上）、`slots.py`。
- 共同規則：擁有者是樹主 uid、或推不出身分、或驗的人自己是子帳號（看到 65534）＝不啟用，照今天的樣子走。
- 驗收：同帳號樹上寫了設定也全部照舊；子帳號 proc 用自己的身分寄＝過；設 `AOS_STACK` 冒充別隻＝照第 1 題的樣子被拒、被標或被記；樹主 uid 原地改子帳號的信＝看不出（05 第 1 條，寫進測試當「已知擋不住」）。
