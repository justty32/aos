擁有者跟信封對不上時的四種處理、三個可以驗的位置，各自的後果；這是方向選擇，只攤不選。

# 乙 3、對不上怎麼辦、誰來驗

← [README](README.md)｜上一份：[03](03-對照表與耦合.md)｜下一份：[05-擋不住的](05-擋不住的.md)

「對不上」在三種對法裡意思不同（[03](03-對照表與耦合.md)）：甲是「信封說是 A、擁有者是 B」；乙沒有對不上，只有「身分換成擁有者推出來的那個」；丙是「信封說是樹主這邊，擁有者卻是子帳號」。下面以甲、丙會發生的「對不上」來寫；選乙時第一節只剩「擁有者推不出身分」（例：擁有者是 65534、或不在名下的段）那一種。

## 一、對不上時的四種樣子

| 樣子 | 做法 | 守規矩的 agent 感覺到什麼 | 不守規矩的 | 跟他的話 |
|---|---|---|---|---|
| **A 拒收** | 收信方把信丟到拒收處、照 `reply_to` 回一封錯誤（代號例 `SenderMismatch`），不處理 | 什麼都沒有（它不會對不上）；除非是邊緣狀況誤傷：搬家、複製過的信、人手動放的信（[06](06-邊緣狀況.md)） | 被擋；它看得到錯誤行，知道被抓 | 規則 5「被拒是決定」直接適用；誤傷時信不見了要人去拒收處撿 |
| **B 收但標記** | 照常處理，但收信方在交給規則與 hook 的資料裡多一欄（例：驗過的身分、或 `sender_mismatch: true`），由規則自己決定要不要因此不同 | 沒差 | 照樣過，除非哪條規則看了那一欄 | 符合「kernel 定政策」：事實由底下給、要不要擋由各 kernel 寫；誤傷不丟信 |
| **C 只記一筆** | 照常處理，在 kernel 的紀錄（`forwarded.json`、帳本、log）寫一行 | 沒差 | 照樣過；事後查得到 | 最不打擾；但沒人看紀錄就等於沒做 |
| **D 交給 hook／kernel 決定** | 收信方不定死，把「擁有者、推出的身分、對不對得上」放進 hook 事件（kernel 站已有 `before_verdict` 等點），各 kernel 的 hook 自己決定拒、標、記 | 沒差 | 看各 kernel 怎麼寫 | 最有彈性；範本預設要選一個（A、B、C 其中之一或「不看」），等於把題目往後推一層 |

各樣子的共同點：**同帳號的 demo 都碰不到**（擁有者全是樹主、對照表沒有子帳號，「對不上」不會發生），差別只在換了身分以後。

## 二、誰來驗（三個位置）

| 位置 | 做法 | 好處 | 代價 |
|---|---|---|---|
| **寄信工具落地時**（aos-post `send`） | 寄的時候檢查「我自報的 sender 跟我自己的 uid 合不合」 | 程式最集中 | **沒用**：寄件人自己檢查自己，不守規矩的不用 aos-post 就繞過；守規矩的本來就不會亂寫。只能當「防手滑」（例：忘了清 `AOS_WS` 就寄成別人的名字）的提示 |
| **收信方讀信時**（aos-post `see`／各收信程式） | 讀信時順便讀出信夾與 `letter.json` 的擁有者，交給收信的程式 | 每個收信方都拿得到同一份事實；一般 agent 的 `mailbox_read` 也能顯示 | 收信方是子帳號時看到 65534（[03 末節](03-對照表與耦合.md)）；要比對（甲）就得有表，一般 agent 不該讀 daemon 表 |
| **kernel 站**（含 llm kernel） | 只在收請求的 kernel 驗：這些地方才真的照寄件人分人（`by_sender`、額度） | 擋在要緊的地方；kernel 站本來就跟 daemon 站一起，讀 daemon 表不算 agent 耦合；跟 K9「kernel 用信檔擁有者認寄件人」原文一致 | 一般 agent 之間的信不驗；使用者專區要另外接 |

這三個不是互斥：常見的組合是「**讀信那層給事實、kernel 定要不要擋**」——底下（aos-post 這種基底工具）只說「這封信夾是誰的」，不說好壞；kernel 照自己的設定拒、標或記。我替使用者先定了這個分層（它就是 C-47「kernel 定政策、daemon 執行」與 aos-post「跟 proc 關聯不深的基底工具」的延伸，不是新方向），**要不要擋、在哪裡擋**仍是他的題（[08 第 1、2 題](08-待裁題.md)）。

## 三、使用者專區要另外想的

- 專區的 `verify`（L1）今天比三樣：寄件人是專區、跟專區留底逐欄一樣、專區 log 有同一筆。若專區的程式跑在使用者 uid、agent 換了子帳號，**多比一樣「回信擁有者＝使用者 uid」**，就把鐵律 2 那句「擋不住會開 shell 刻意連留底一起造假的 agent」擋掉一半（另一半是：agent 換了子帳號後本來就改不了專區留底）。
- 但 eca 本體照 K7 留使用者 uid：**eca 寄的回信擁有者跟使用者本人一樣**，這條對 eca 無效。這是 K7 的直接後果，不是這份要重裁的。
- 專區程式不在 repo（在活樹 `~/aos-home/ws/tools/aos-user/`），施工得等它進 repo 或使用者另外放行（[07](07-切刀.md) 第 5 刀）。

## 四、kernel 代寄時要不要把原寄件人帶下去

kernel 站轉寄後，下一站（daemon）看到的是 kernel。今天 daemon 不看寄件人，所以不帶也不壞。若以後 daemon 或下一層 kernel 也要分人，就得在轉出的信上多一個 key（例 `origin_sender`，寫上一站驗過的身分）。這個 key 是上一站寫的，下一站只能選擇相信上一站——**跟 C-52「每層只管自己這一層」一致**，列為可晚點再答。
