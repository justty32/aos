## 結論（先看這段）

1. **今天的 `/compact` 壓完本來就不留工具輸出**：要求之前的對話整段換成一則摘要（沒答的信除外）。所以「清工具輸出」真正的用處有兩個：(a) 讓叫腦寫摘要那次的請求小一半以上；(b) 清完已經夠低時乾脆不叫腦，對話原文照留、只少了舊的工具輸出。
2. **量到的**：四份真模型跑過的 agent-fsm history，工具輸出占 history 的 64%～76%。把「最後 3 則以外」的工具輸出換成一行佔位，history 少 27%～78%；估成 prompt token，skyrim 那三隻是 68,329→約 29,800、62,356→約 27,300、47,880→約 19,000（細節在 [02](02-先清工具輸出.md)）。
3. **建議的預設做法**（細節我照原則定了，理由在 02）：清 `role: tool` 的內容、留最後 3 則與最後一組工具呼叫的結果、短於 300 字的不清；工具呼叫的 arguments 第一版不清；原文照現在的規矩搬進 `history_removed.jsonl`。清只改內容、不刪列，所以工具配對與 do_task 的紀錄點都不會斷。
4. **hook**：開 `before_compact`（能攔、能改給腦的額外指示、能直接給一份摘要＝換掉叫腦）與 `after_compact`（摘要好了、還沒換進 history 時；能改摘要、能交一段「補回」的字，body 把它放成摘要後面的一則 user）。宣告照現行 `hook_points.json` 加進 agent-fsm 那份；預設一個 handler 都不掛。
5. **施工五刀**，第 1 刀（先清再摘要）與第 3 刀（`aos-agent history clear-tools`）不依賴待裁題，可先做（[04](04-施工刀序.md)）。
