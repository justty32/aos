## 一步一步

1. **誰寄 `/compact`**：人寄，或 `context_wrap` hook（`templates/agent-fsm/hooks.json`，`on_clock` 每 5 秒、用量 ≥35% 寄一封只有 `/compact` 的信；handler `py/tools/agent/context_wrap/_entry`）。
2. **idle 收信**（`idle.py:156-217` `take()`）：`/compact` 先挑出來、**不過 `before_queue`／`after_queue`**；同批普通信照常進對話；`/compact` 在批尾合成一次要求。可摺的不到 4 則（`compact.py:9` `MIN_ROWS`）＝不叫腦，回一則 `compact not needed: …`、信記成答完（使用者 11-20「當成正常做完」）。
3. **做到一半來的**（`brain.py:137-160`）：history 尾是 user，或最後一組工具結果都到齊、可摺 ≥4 則，才認領；要求帶 `mid_turn: true`。
4. **加要求**（`compact.py:95-103` `ask`）：history 尾接一則 `[aos] compact: …`（英文長句，要腦只回摘要、列出該寫的項目；`/compact` 後面的字接成「Extra instructions from the sender」）；`compact.json` 記 `phase: asked`。
5. **問腦**（`brain.py:163`、`:178`、`:234`）：這次**送完整 history**（`--history task` 也一樣）、**不帶 tools**。
6. **收摘要**（`wait.py:618-626` → `compact.py:205-260` `fold`）：要求之前的全部換成一則 `[aos] summary: lines 1-N, M messages. 摘要 …` user＋一則 `compact done: …` assistant（`aos.compact: true`），後面接原文留下的列（沒答的信、緊貼要求前的連續 user 提醒），`mid_turn` 的再接一則 `[aos] compact: done. Go on …`。摺掉的原文接進 `history_removed.jsonl`（`op: "compact"`、原行號、原訊息），摘要另接進 `handoff.md`；`compact.json` 記 `phase: done`。
7. **失敗**（`compact.py:173-202` `give_up`）：摘要空、帶 tool_calls、要求列不見、history 壞＝移除要求列、信 drop `failed`、記 warning；腦呼叫本身失敗沿用冷卻規則、保留要求。

## 留什麼、丟什麼

| 東西 | 壓完 |
|---|---|
| 要求之前的 user／assistant／tool 列 | 摺進摘要（原文在 `history_removed.jsonl`） |
| 沒答的信 | 原文照留 |
| 緊貼要求前的連續 user（例：goal 提醒、new_mail） | 照留，舊 summary 除外 |
| 舊的 `[aos] summary:` | 摺掉（新摘要裡要自己寫進去） |
| system 提示 | 本來就不在 history，每次從檔讀（`brain.py` 讀 `system_file`），不需要補回 |
| `goal.json`、todo 清單、`tasks.json` | 不動；todo 照使用者 11-11 T1「不帶，腦自己查」本來就不進 prompt |
| do_task 的紀錄點 | 被摺掉，之後 `do_task end` 回 `MarkerMissing`（摘要要求裡有寫明） |

## 已知毛病

1. **摘要那次送的是全份**：工具輸出占 history 六到七成（[02](02-先清工具輸出.md)），摘要請求就是最貴的那一次。預設 35% 觸發時離滿還遠，超窗的風險小；人在接近滿時手動寄 `/compact`，那次請求本身可能放不下，今天沒有任何保護。
2. **摘要那次拿掉 tools，請求的開頭變了**：照 11-21 session-key 實測，快取靠請求開頭一樣；tools 不在了，這次大概整份不中快取（推測，沒量）。
3. **只有「全摺」一種手段**：哪怕只是幾則大的工具輸出撐上去，也得叫腦把整段對話換成摘要，對話原文一起沒了。
4. **單次工具結果暴衝救不了**（02-agent-fsm「已知限制」原文）：`act.py` 沒有輸出上限；清工具輸出也只清舊的，管不到剛回來那一則。這題不在本規劃範圍，只標出來。
5. **沒有壓前壓後的 hook 點**：`/compact` 連 `before_queue` 都不過（`hook_points.json:6` 寫明）；想在壓完補東西只能另寄信（會多一輪）。
6. **摘要品質全靠模型**：保底是沒答的信原文、`history_removed.jsonl`、`handoff.md`。

## eca 那邊（不在本規劃範圍）

eca 的 `/compact` 交給外面的 CLI 自己做（`py/aos/apps/eca/slash.py`），aos 只把 CLI 的摘要接回 history；清工具輸出與這裡的 hook 點都不適用。新點只宣告在 agent-fsm 那份，掛到 eca 上＝掛得上、不跑、不報錯（06-hook「兩份檔怎麼疊」現行規則）。
