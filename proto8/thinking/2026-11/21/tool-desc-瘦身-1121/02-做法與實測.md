## 五種做法

### A. 只改寫文字，資訊不搬走

刪錯誤列表、刪例子、json 包的 `path` 說明統一成一句。照 byte 估：50,813 → 47,116（−7%，約 −800 token）。風險最低，但省得少；骨架與外殼佔一半，description 裡真正肥的是「整份用法」，不搬走就省不下來。

### B. description 只留一兩句＋「More: 知識庫哪一頁」，細節靠知識庫（原型做了）

- 每支 description 留：做什麼、輸出長怎樣、最常搞錯的那一點、該改用哪支（例 grep ↔ glob）、`More: aos/tools/<名>.json`。參數說明縮成幾個字，**每個參數都留說明**（`tools_def check` 要求）、enum、預設、必填都不動。
- **不用另造地方放細節**：知識庫 `aos/tools/<名>.json`（基本工具）與 `aos/me/…`、`aos/mailbox.json`（self、信箱這幾支）本來就一支一頁，寫著用法、例子、錯誤（11-05「各工具的 description 之後只寫『怎麼叫、哪一頁看細節』」那個方向）。
- **省多少（實測）**：50,813 → 25,198 bytes；`prompt_tokens` 12,553 → 6,185（−51%）。同一題信箱任務 4 次問腦合計：現狀 51,262 → 瘦文字 25,715。
- **要動的檔**：`py/tools/base/*/_tooldef.json` 28 個、`py/tools/agent/*/_tooldef.json` 12 個；知識庫 `aos/packs.json` 的每包字元表；`py/packs/README.md` 一行成本；測試裡比對說明文字的（見 [03](03-施工檔單.md)）。

### C. 起手範本預設少掛幾包，要用再自己加

- 拿掉 json、self 兩包：實測 −37%（原文字）、跟 B 疊起來 −64%。
- **風險**：self 整包拿掉就沒有 self_tools，agent 自己加不回來；所以實際可行的是「self 只留 self_tools、self_state」（估 −33%，跟 B 疊約 −61%）。json 拿掉後改 JSON 要用 read＋edit，容易改壞格式。執行中用 self_tools 加一支會讓對話快取失效一次（py/packs/README 已寫明）。
- **要動的檔**：`templates/agent-fsm/tools.json` 與 `templates/start-api/agents/ann/tools.json`（逐字抄本，`templates/tests/test_start.py` 比對）。
- **這是改 11-14 使用者裁的「tools40: a」**，見 [README 方向題](README.md#要你定的方向題)。

### D. 工具包分級（拆成核心包與進階包）

例：self 拆成 self（self_tools、self_state）與 selfx（其餘四支）；json 拆成讀（get、ls、len、search）與寫。用現成的包機制（`py/packs/*.json` 多幾份、範本的 `$override` 換項），不用新機制。省多少跟 C 的子組合一樣（上表後兩列）。比 C 細、但包變多；跟 C 同一個方向題。

### E. 只給名字和一句、要用時才給全文（延遲載入）

現有體系**沒有**這種機制：模型叫得到的工具都要先在請求裡有完整 schema。`aos-tools ls` 的短版（名字＋第一句）是給人和 `self_tools ls` 看的，不是給模型叫的。要做得新造，這次不建議，只列出來。

## 已有、可以直接用的機制

- 知識庫一支一頁（`knowledge/aos/tools/`、`aos/me/`、`aos/mailbox.json`）——B 的細節去處。
- 包＋`$override`、覆蓋層寫 `"名": null` 關一支——C、D 的做法，原型就是這樣量的。
- kits（`py/kits/`）——按角色替新定義疊工具組；要「某角色多掛幾包」用它，不用改預設。
- `self_tools add`——執行中補一支（一次一支、快取失效一次）。

## 看到的風險

1. **原說明裡「防錯的半句」不能砍**。mailbox_send 原本寫「a letter to yourself = your own name, not self or me」，原型第一版只留「yourself = your own name」，sol 就寫了 `self`。補回「(not self or me)」後跟現狀一樣。這類半句是之前踩過坑才加的，改寫時要逐支保留；03 的文字已補回，施工時照「留防錯句」的原則再過一次。
2. **知識庫在哪，agent 不知道**。系統文字只寫「aos/_description.json in the aos knowledge folder」，沒給路徑，工具也不展開 `$AOS_HOME`；查一頁繞了 5 次才找到。**這是現在就有的缺口**（現狀版要查知識庫一樣找不到），B 讓 agent 更常需要查，所以要一起補：系統文字寫明「知識庫在 `$AOS_HOME/knowledge`，路徑用 shell `echo $AOS_HOME` 取得」之類的一句（[03](03-施工檔單.md) 第 3 項）。
3. **eca 也會跟著變**：eca-claude 透過 aos-mcp 拿同一批說明，B 會讓它的工具說明一起變短。eca 掛的 events、def、jsonx 三包這次沒瘦（原型只動 agent-fsm 預設的 40 支）。
4. **沒測到的**：小模型（LM Studio 那類）只靠短說明能不能用對；self_history、self_llm、self_ctl、do_task、index_view 這幾支這次沒出題。
