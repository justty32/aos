## 先講結論

- **現在這套很大**：專給 hook 的 Python 有 11 支檔、約 2,000 行，另有編譯、kernel、aos-loop（C++）裡約 500 行跟它綁著；專測 hook 的測試約 20 支、約 3,400 行、約 175 個測試函式。做的事盤成 35 件（[01](01-現在做的事.md)、[01b](01b-現在做的事-續.md)）。
- **新格式一換，有一大塊自己就沒了**：provider 表、宣告的逐鍵驗證、幾份宣告同名要一致的檢查、「誰說的」那層記錄，加起來約 200 行；另外有一批東西新格式不影響，但跟「保持極簡」「各家自己的事」對得上，可以另外考慮拿掉（[02](02-新格式會帶走的.md)）。
- **簡化到哪裡，攤了四層**（[03](03-簡化候選.md)、[03b](03b-簡化候選-續.md)）：
  1. 只做新格式本來就要做的清理（少約 200 行，誰都不用多做事）。
  2. 再把三份重複的「讀清單」合成一份、把 agent 專用的動作搬出 `aos-hook`、拿掉幾個沒人用或可以省的機制（少約 450 行，誰都不用多做事，掛錯的少一層事先擋）。
  3. `aos-hook fire` 與引擎不再讀宣告裡任何鍵，能不能攔、能改哪些鍵交給發事件的程式；條件比對改成掛的人自己寫比哪個欄位（少約 550 行、各家多約 60 行）。**這層跟第 7 則「有提供這些 key 就照著做」衝突**。
  4. 最極簡：`aos-hook fire` 只照 `hookeds` 把 handler 叫起來、丟 input、交回輸出與退出碼（hook 這套的核心剩約 300 行）。agent 一家、kernel、aos-loop、gdb 都要自己多做事，C-90 那幾個選項（intercept、async、on_error）會沒有。**跟第 7 則、C-90、旗標檔那題衝突**。
- **我的看法（不是替他選）**：1 與 2 跟「hook 新格式＋檔名對調」那一刀一起做最省（那一刀本來就要整份重寫讀宣告與讀清單的程式）；3、4 牽動他已經說過的話，要他先定。
- **想問他的五題**在 [04](04-邊緣與想問的題.md)：簡化到第幾層、`aos-hook fire` 跟 Python 庫要不要同一套規矩、旗標檔誰對、條件比對放哪、`<stack>/hooks/<名>/` 小格夾跟不跟著改名。跟他說過的話與現有條文的衝突另列在 [05](05-衝突.md)。
- **先後**（[06](06-跟格式刀的先後.md)）：第一題（簡化到第幾層）最好在格式刀之前定，免得格式刀寫出要刪的東西（例如照 output schema 驗型別）。
