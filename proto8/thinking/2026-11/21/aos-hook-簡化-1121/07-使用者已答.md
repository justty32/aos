## 第 1 題：簡化到第幾層

頂層轉述四層候選（各層少多少、代價、第 3、4 層跟他第 7 則「有提供這些key，就照着做」等處的衝突）與五題後，又在 kernel 宣告六題答完時說「還擋著施工的只剩一題：aos-hook 簡化到第幾層（1～4）」，他答：

「簡化到第四層」

整理（頂層的理解）：`aos-hook fire` 只做一件事——照 `hookeds` 清單把 handler 叫起來、把 input 丟給它、把輸出與退出碼交回去；其餘交給發事件的程式。對應他同日說的「發事件的程式自己決定 <- 沒錯，我們提供的hook fire本身會參與這個過程……如果有人不想用我們的aos-hook fire，那就弄他自己的」「總之hook這邊就保持極簡」。本稿 [05](05-衝突.md) 列的衝突（第 7 則、C-90 的 `intercept`／`async`／`on_error`、11-20 待裁第 11 題旗標檔、第 4 題事件欄位以宣告為唯一來源）他是看過轉述後選的。

第 4 層裡的子選擇（4-甲 逾時留不留、4-乙 退出碼怎麼給、4-丙／4-丁 Python 庫要不要也極簡、旗標檔誰維護）頂層接著用選項框問，答案追加在下面。

## 第 4 層的四個子選擇（選項框，選項不標推薦；他選的逐字）

1. 「第四層裡：Python 的 hook 庫（agent-fsm 的格程式、eca、kernel 在用的那套引擎）要不要也跟著極簡？」→ **「庫也極簡」**（引擎整份換成約 300 行，只負責叫 handler；攔、改欄位、條件比對、on_error、async 都改由各家自己做。另一個選項：只有指令極簡。）＝本稿的 4-丁。
2. 「aos-hook fire 叫 handler 時，逾時（timeout_ms，超過就把 handler 整群程序殺掉）要不要留？」→ **「留著」**。
3. 「aos-hook fire 自己的退出碼怎麼給？（aos-loop 是 C++ 程式，只看得懂退出碼、讀不懂 JSON）」→ **「用旗標選」**（預設一律退 0、結果在 JSON；另給一個旗標讓呼叫的人要求「第一個非 0 就停並用它的碼退出」，loop.json 裡那四行帶這個旗標。另兩個選項：第一個非 0 就停／一律退 0。）
4. 「旗標檔（沒人掛 before_run／after_run 時，讓 loop 每圈不必起 aos-hook 的那兩個檔）之後由誰維護？」→ **「編譯時決定」**（定義編譯時有掛才把那兩行寫進 loop.json，沒有旗標檔這個東西；執行中新掛的 before_run／after_run 要重新編譯並重起才生效。另兩個選項：只由 aos-agent hook 維護／拿掉旗標檔。）

## 本稿五題裡還沒答的

- 第 4 題 `condition` 放哪：第 4 層下引擎不做條件比對，各家自己做；agent 一家要不要保留「只攔某支工具」的寫法、放哪，沒問。
- 第 5 題 handler 的工作夾 `<stack>/hooks/<名>/` 要不要改成 `hookeds/`，沒問。
