# 「在 shell 裡下 aos 指令，可以比喻為啥」發想（11-21）：他的直覺對照實際機制、七個候選比喻、十四個邊緣狀況，不選定

← [2026-11-21](../README.md)

使用者 11-21 提出這個問題，線 `top-1121-shellmeta` 做。只發想：讀程式確認機制、攤候選、挖邊緣狀況；沒改程式、範本、文件、條文，沒起樹，沒碰 `~/aos-home`。比喻由使用者自己定，這裡不替他選。

## 他的原話（逐字）

「然後是我的另一個想法：在daemon是板子的比喻體系下，我們在shell輸入aos-agent等指令，感覺有點像是直接強行觸發另一個cpu，讓他跑一個proc (非aos proc，而是底層linux proc)，以此爲起點，去進行其他動作，比如往另一個程序的記憶體內stack塞指令之類，去幫我想想，我現在正嘗試定義"在shell內執行指令，可以比喻爲啥"。」

## 他的直覺對照實際機制

**貼的三處：**

1. **那個行程確實不是 aos 的 proc。** shell 指令行程是終端機 shell 的孩子，不在 daemon 的表上，沒有列、沒有 phase，daemon 的份額、重起、stuck 偵測都管不到它。
2. **「往別人記憶體的 stack 塞東西」幾乎字面成立。** aos 指令沒有一條是連 socket 請 daemon 做事；它們就是往別人的資料夾放信、直接改別人 stack 裡的檔。`say` 是往 agent 的 `queue/` 塞一則訊息，`ctl pause` 是直接寫 agent 的 `ctl.json`，`hook add` 是直接改 agent 的 hooks 清單，這三樣 daemon 完全沒經手。
3. **「強行」也對。** 全部同一個 Linux 帳號，沒有東西擋；人的 shell 經 `env.sh` 後沒有 `AOS_KERNEL`，預設連 kernel 都不經過。

**不貼的四處：**

1. **多半不是「另一顆 cpu 在跑」，是「放下東西就走」。** 指令行程活幾十毫秒到幾秒，放完信、改完檔就結束；被動到的那一方之後在自己的圈裡才發現。例外是 `chat`、`listen --follow`、aos-gdb、`aos-exec root` 這幾條不走的。
2. **塞進去的常常是「請求」不是「指令」。** 寄信給 daemon 或 kernel 的那型可以被拒絕；`say` 塞的是一句話，腦可以不照做。只有寫 ctl 窗和直接改檔這兩型是不問對方的。
3. **它不是 shell 專屬。** agent 的工具（`self_hook`、`self_ctl`、`subagent`）就是包同一支 `aos-agent`。差別只在是誰的後代、帶什麼環境變數、經不經 kernel。
4. **有一條指令方向相反。** `aos-exec root` 不是去動別人，是把 daemon 本身起起來——板子是那個 shell 的後代。

另有一個用詞要他自己說：「cpu」在既有文件已有兩個用法（板子附錄裡指 aos-daemon 這支程式；名詞表裡指 kernel 開來跑某個資料夾的執行單位），這次的「另一個 cpu」是哪個意思，見下面第 1 題。

## 候選短表（詳見 [02](02-候選比喻.md)、[02-續](02-續-候選比喻.md)）

| 候選 | 一句話 | 講得最好 | 講不通 |
|---|---|---|---|
| 甲 另一個匯流排主控 | 不經板上處理器、直接寫板上 RAM 的外來主控（他原話的直讀）| 寫窗、塞 queue、改檔；「強行」| 寄信請 daemon 做的那型；開機；「cpu」撞名 |
| 乙 除錯探針 | shell 是探針另一頭的主機，指令是探針的一次讀、寫、停、放行 | 改檔、讀檔、aos-gdb、凍住時也能改 | 日常的 `say`；agent 自己下指令 |
| 丙 前面板 | shell 是機殼上的面板，指令是按一下鍵 | 開機、關機、看表 | 直接改檔；agent 自己下指令 |
| 丁 板外送來的請求 | 板外設備把東西放進信箱、窗、門鈴，板子照自己的節奏處理 | 寄信、poke、指令死掉、另一台機器 | 直接改檔；開機 |
| 戊 服務處理器 | 主機板上獨立的管理用小處理器，主機關著也在、繞過作業系統 | 板子沒開、開機、繞過 kernel、遠端 | 日常對話；來了就走 |
| 己 使用者是樹外的一顆 PU | 人像畫家一樣是個執行單位，shell 是他的身體，指令是他的工具呼叫 | 人與 agent 是同一支程式；身分看環境；裡面打外面；agent 找人 | 「強行」；開機；離板子畫面較遠 |
| 庚 依型分開講 | shell 是板子外的工作桌，各型指令各用既有的零件（電源、信箱、暫存器、門鈴、探針）| 每一型 | 沒有單一答案 |

## 哪幾個跟他現有體系最不打架（觀察，不是推薦）

- **庚**不打架：既有附錄本來就是逐條指令對的（aos-exec＝bootloader、`aos-daemon-ctl`＝直接敲板子、`aos-agent`＝經作業系統、poke＝門鈴、翻 stack＝JTAG）。照它走，只有「直接改別人 stack 的檔」這一型在既有比喻裡還沒有位置。
- **丁**用的全是既有零件（信箱＝FIFO、窗＝暫存器、門鈴），不用加新詞；但它等於說直接改檔是越界。
- **乙**跟 daemon-board 對照表的 UART／JTAG 那一列、跟 aos-gdb 是同一條線，也接得上「Linux 是硬體」：探針走的是硬體層，板上程式不知情。
- **己**不是硬體比喻，但它用的是既有的兩句話：畫家是一顆 cpu、使用者專區是使用者自己的 stack。
- **會撞到既有東西的**：甲的「cpu」撞名；丙和戊都預設「只有板子外面的人碰得到」，跟「agent 的工具用同一支程式」這個事實衝突。

## 邊緣狀況裡最有料的四條（全部十四條見 [03](03-邊緣狀況.md)）

1. **人從 shell 做，跟 agent 用工具做，是同一支程式。** 五個硬體比喻都把 shell 當板外的特殊東西，一碰到 agent 自己下同樣的指令就要另外解釋。
2. **決定「它是誰」的是環境變數，不是 shell。** 同一個視窗，帶不帶 `AOS_STACK`、`AOS_KERNEL`，走的路和署的名都不同；而且是自報的。
3. **板子關著、整棵樹凍著，shell 照樣改得到 stack。** 凍住準備搬家的 image 其實還能被外面改。
4. **叫 agent 停下的那支指令死了，沒人放行。** aos-gdb 把 agent 暫停後 REPL 死掉，那隻一直停著，表上還顯示 `running`。

## 想先問他的三題

這三題原則推不出答案，而且答了之後候選會自然少掉一半。

1. **「另一個 cpu」的 cpu 指哪個？** (a) Linux 這層硬體自己冒出來的一次執行，板子不知情；(b) 像畫家那樣的外部執行單位，也就是你本人，指令行程是你的手腳；(c) 跟 aos-daemon 這支程式平起平坐的另一顆處理器。
2. **比喻要照「從哪裡來」切，還是照「怎麼碰」切？** 你從 shell 打 `aos-agent hook add`，跟 agent 自己叫 `self_hook`，底下是同一支程式。你想讓這兩件事在比喻裡是同一種東西，還是兩種？
3. **直接改別人 stack 的那幾型，在你心裡算正門還是拆機殼？** 寄信、寫 ctl 窗、按門鈴都有既有比喻；改 hooks、改 history、刪 stack 沒有。它們要跟寄信型用同一個比喻，還是另外一個？
