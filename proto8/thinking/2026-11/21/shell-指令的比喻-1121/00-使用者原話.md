## 11-21 原話（逐字，頂層轉來）

「然後是我的另一個想法：在daemon是板子的比喻體系下，我們在shell輸入aos-agent等指令，感覺有點像是直接強行觸發另一個cpu，讓他跑一個proc (非aos proc，而是底層linux proc)，以此爲起點，去進行其他動作，比如往另一個程序的記憶體內stack塞指令之類，去幫我想想，我現在正嘗試定義"在shell內執行指令，可以比喻爲啥"。」

## 這句話裡的四個零件（照原話拆，不加料）

1. 前提：daemon 是板子（他 11-05、11-06 定的比喻）。
2. 在 shell 打 `aos-agent` 這類指令，像「直接強行觸發另一個 cpu」。
3. 那個 cpu 跑的是一個 proc，而且是底層 Linux 的行程，不是 aos 的 proc。
4. 以那個行程為起點再去做別的事，例子是「往另一個程序的記憶體內 stack 塞指令」。

## 既有比喻體系裡各個東西對到什麼（這題的底圖）

| 實際的東西 | 他已經定的比喻 | 天然差異（已標過的） |
|---|---|---|
| Linux | aos 的「硬體／裸機」 | — |
| root daemon | 板子本體；「使用者顧板子，板子顧底下」 | — |
| aos-daemon 這支程式 | 板子附錄裡叫它 CPU（「晶振……不是 CPU（aos-daemon 程式）的邏輯」） | — |
| aos-loop、aos-fsm、畫家 | PU／cpu：會「算」的執行單位 | 下一步做什麼事前看不到 |
| stack | RAM | 是檔案，斷電不丟 |
| ws | 外接儲存 | — |
| 信箱 | mailbox FIFO | 輪詢；只有 queue 是真 FIFO |
| 窗（ctl.json、state.json） | 記憶體映射暫存器 | 後寫的算、沒有歷史 |
| aos-exec | bootloader | 每一跳都重讀 `.env` |
| poke | 門鈴（唯一的真中斷，只叫醒、不帶內容） | — |
| sleep | 休眠到磁碟＋可插拔存儲 | — |
| `aos-daemon-ctl` | 「指名某塊板子直接敲」 | — |
| `aos-agent` | 「經作業系統」（照 `AOS_KERNEL` 寄） | — |
| `aos-daemon-ctl ls`、翻 stack | UART／JTAG | — |
| 使用者專區 `~/.aos/user/` | 知識庫寫「使用者自己的 stack」 | — |

**注意一個撞名**：「cpu」這個字在既有文件裡已經有兩個用法（aos-daemon 程式；kernel 開來跑某個資料夾的執行單位）。這次他說的「另一個 cpu」是第三個位置，指哪一個要他自己說（[README 想先問的題](README.md#想先問他的三題)）。
