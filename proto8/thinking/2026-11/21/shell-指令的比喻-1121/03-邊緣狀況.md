## 先講結論

- **最會把比喻撐破的是第 2、5 條**：人從 shell 打的指令和 agent 用工具做的事是同一支程式。甲到戊五個硬體比喻都把 shell 講成「板子外面的特殊東西」，一碰到 agent 自己下同樣的指令就得另外解釋。
- **第 4 條說明真正決定「它是誰」的不是 shell，是環境變數**。同一個終端視窗，帶不帶 `AOS_STACK`、`AOS_KERNEL`，同一條指令走的路、署的名都不一樣。
- **第 3、12 條是硬體比喻的共同難處**：板子關著、整棵樹凍著，shell 照樣改得到 stack。這是既有的天然差異「stack 是檔案，斷電不丟」在這一題的延伸。
- **第 7 條裡有一個真的會發生的狀況**：叫 agent 停下的那支指令死了，沒人放行，agent 一直停著。

## 十四條

**1. 好幾個 shell 同時下指令。** 事實：寄信型（一、三）沒事，信是整封落進信箱的；但兩個終端同時對同一隻 `say`，兩句會合成一輪、兩邊拿到同一個回答（[default-stack 實測](../../18/default-stack-1118/02-邊緣狀況.md)）。寫窗型（二）後寫的蓋掉先寫的。直寫型（四）是「讀、改、寫回」沒有鎖，兩個人同時 `hook add` 可能掉一筆（沒驗）。比喻：甲最能說出「需要仲裁但沒有」；丁把信箱那半講得最順（排隊）；乙、丙預設只有一支探針、一塊面板，講不了。

**2. 人從外面做，跟 agent 自己用工具做同一件事。** 事實：`self_hook` 就是把 `aos-agent hook` 的對象換成自己；`self_ctl`、`subagent`、`goal` 同理。差別只有：是 daemon 的後代、帶著 `AOS_STACK`、可能帶 `AOS_KERNEL`。比喻：己最順（都是工具呼叫）；丁也行（都是寄東西的人）；甲勉強（板上周邊也能當主控）；乙、丙、戊都會變成「板上的程式自己拿探針／按面板／用管理通道」。這一條其實在問：比喻要照「從哪裡來」切，還是照「怎麼碰」切。

**3. daemon 沒在跑時還能做的指令。** 事實：三、四、七型照做——`say` 會排進 queue 並提醒「現在沒人在跑」，`hook add`、`history set` 照改。一型直寄 daemon 會回 `DaemonMissing`；寄給 kernel 站的話信放著沒人收，三秒後 `KernelFailed`。比喻：戊最順（主機關著，服務處理器照樣動）；既有比喻的「休眠到磁碟＋可插拔存儲」也說得通：像把記憶卡拔下來拿到別處改。乙不貼（探針要板子有電）；丁只能說「信先丟進信箱，等板子開機」，講不了直寫型。

**4. 指令行程帶著 `AOS_*` 環境，或完全沒有。** 事實：人的 shell 經 `env.sh` 後只剩 `AOS_HOME`，所以不經 kernel、署名是登入名、回信箱借 daemon 的。agent 開的 shell 帶著全套，下同一條指令就被認成那隻 agent。11-13 出過事：agent 的 shell 帶著 `AOS_STACK` 起了 root，root 繼承了它，`env.sh` 因此加了清環境那一行。比喻：己直接成立（環境就是這次工具呼叫的身分）。其他候選都得補一句「這個外來主控／探針／面板，是掛著誰的名牌」，而名牌是自己寫的、沒人驗。

**5. agent 從自己的 proc 裡起 shell 再下 aos 指令（裡面打外面）。** 事實：agent-fsm 的 `shell` 工具、eca 身（claude、codex）自己的 Bash 都能打 `aos-agent`、`aos-daemon-ctl`，連 `aos-exec` 另起一棵樹都行。擋它的只有規矩（知識庫規則 2「用工具，不用 shell 把戲」、`aos/kernel.json`「不要拿 `aos-daemon-ctl` 繞過拒絕」），沒有牆。從裡面起的新樹是那隻 agent 的後代，agent 被收掉時它跟不跟著走，沒驗。比喻：己、丁順；甲可以（板上設備當主控）；乙、丙、戊最怪，因為它們的前提是「只有站在板子外面的人碰得到」。

**6. 權限，以及子帳號接上之後。** 事實：現在全部同一個 Linux 帳號，誰都寫得到誰。`limits.user: "sub:N"` 之後，那支 proc 換成別的 uid：進不了別隻的 stack，也寫不進 daemon、kernel 的信箱（要另外開）；人的 shell 還是本人，照樣全通。這時「人的 shell」和「agent 開的 shell」第一次有了硬差別。另有 `aos-asuser sub:N -- …` 這支，能讓人從 shell 換成某個子帳號跑程式。比喻：乙、丙、戊天生帶著「有實體接觸的人就是全權」，子帳號之後最貼；甲沒談權限；己會變成「兩顆 PU 權限不同」，還是說得通，但對稱性少了一半。

**7. 指令跑到一半死掉。** 事實：信已經落進信箱的，daemon 照做，只是回信沒人收（十分鐘後被清）；正常逾時會撤回還沒被領的信，被 `kill -9` 就不撤。單一的寫檔是「要嘛寫了、要嘛沒寫」。複合指令會停在中間：`ctl rm` 可能表上拿掉了但 stack 沒刪；`set-def` 可能停了沒掛回；aos-gdb 的斷點把 agent `pause` 住之後 REPL 死了，沒人 `resume`，那隻就一直停著（表上還顯示 `running`）。`ask` 死了，問題已經在 queue 裡，agent 照答，沒人聽。起板子的那個視窗被關，daemon 收到訊號會正常收工；被 `kill -9` 則子項留成孤兒。比喻：乙把「停住沒人放行」講得最準（探針線被拔，核心停在原地）；丁把「已經送進去的照樣處理」講得最準；甲只能說「另一個主控當掉」，沒說留下什麼。

**8. 遠端或另一台機器下指令。** 事實：全是檔案，所以「遠端」只有兩種：ssh 進來開 shell（那還是本機的 shell），或在共享資料夾上直接寫檔。後者理論上二、三、四型做得到，五型不行（pid 是本機的，程式會比開機編號擋下），一型看 daemon 輪詢看不看得到；都沒驗。另有既有的天然差異：兩台 daemon 可以指同一份 stack（使用者 11-03「自己承擔」）。比喻：戊天生是遠端管理；丁最乾淨（另一塊板寄信來，跨樹的信已有「期限用毫秒」的規則）；乙要實體線、丙要人站在機器前，都不貼。

**9. 不走的指令。** 事實：`chat`、`listen --follow`、`watch`、aos-gdb 的 REPL、`aos-exec root` 會一直佔著那個視窗。它們是「接著不放」，跟其他「放下就走」的指令不一樣。比喻：乙（探針一直插著）、丙（操作員坐在主控台前）、戊（常駐）貼；丁（一次傳輸）不貼；己的說法是「一次很長的工具呼叫」。

**10. 起板子的那個 shell。** 事實：`aos-exec root` 的 aos-exec 留在視窗裡當監工，aos-daemon 是它的孩子。所以在 Linux 這層，板子是某個終端視窗的後代；視窗關了、按了 Ctrl-C，板子就收工。板子的「電源」其實握在一個 shell 手上。比喻：既有的「aos-exec＝bootloader」加上丙的「開機鍵」或戊最順；甲、乙、丁都預設板子已經在那裡，講不了這條。它也說明 shell 不只是「板子外面來的訪客」，還是「板子站的那張桌子」。

**11. 觀察的指令會不會改到東西。** 事實：`aos-mailbox read` 讀了就把信拿走；`aos-mailbox where` 會建信箱夾；任何等回信的指令會建回信箱並清舊回信；設了 `AOS_KERNEL` 時連「看表」都要先寄一封信。比喻：硬體上有「讀了就清掉」的暫存器，乙、甲都容得下；丙的指示燈講不了；這條主要是提醒「七型純讀」不是一條乾淨的線。

**12. 時間對不上。** 事實：指令行程活在牆鐘上（等三秒、等三十秒），被它動到的東西活在樹的時鐘（cycle）上。時鐘暫停、整棵樹睡著時，shell 照樣把東西塞得進去；凍住準備搬家的 image，其實還能被外面改。比喻：乙最貼（核心停住時探針照樣讀寫，探針有自己的時脈）；戊也貼（帶外）；甲不貼（另一個主控通常同一顆晶振）；己要說「樹外的 PU 不吃這棵樹的鐘」，跟既有「跨樹用毫秒」一致。

**13. 沒有帳。** 事實：寄信型有信封，但寄件人是自己填的；直寫型完全沒痕跡（只有 `history` 改掉的原文會搬到旁邊）。agent 事後發現自己的 hooks 變了，查不出是誰。比喻：甲、乙本來就無痕，貼；丁、己暗示「應該有署名」，會讓現況看起來缺一塊；戊暗示管理通道該有自己的紀錄。

**14. 方向反過來：agent 找人。** 事實：agent 用 `aos-user send`／`user_send` 把信放進使用者專區 `~/.aos/user/mailbox`，人回信，回信進 agent 的信箱。在這個方向上，人完全是「一個有 stack、有信箱、會回信的東西」。比喻：只有己和丁容得下「人也是收信的一方」；甲、乙、丙、戊都只講了「人動板子」這一個方向，反過來時人突然變成另一種東西。
