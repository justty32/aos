## 實測與讀程式

暫存：`git archive HEAD`（`a04eb437c`）解到 `~/.aos/scratch/top-1121-permdoc/src/`、在那裡 `install.py`（退 0）；抄 `templates/start-api` 成 `tree/`、假腦；每支腳本先清所有 `AOS_*`。沒用 sudo、沒建帳號、沒碰 `~/aos-home` 與 LiteLLM。

實測過的（輸出原樣貼在各頁摺疊裡）：

- perm：`allowed: ["worker"]` 擋 `bob`（`NameUnknown`）、放 `worker`；`aos-agent -d .stack ctl add -n bob` 不經站照掛；`limits`＋`users: {"*": "sub:7"}` 時自帶 `user` 被丟、`mem_mb` 99999 夾成 2048、填 `sub:7`；站停時經站的 `ctl ls` 3.06 秒後 `KernelFailed`。
- kernel_gate：以 ann 的環境在殼裡直接跑工具（假腦不叫工具）：on、寄一封、ls、refuse（寄件人收到 `HoldRefused`）、off；假腦的 history 收到 `[aos] kernel_hold` 通知。pass、triage 沒跑。
- guard：proto8 版五個事件（放、擋定義夾、擋家目錄、擋 shell、擋 ctl 信箱）；fsm-guard 從 repo 原地 `python3 -B` 跑：擋 `rm -rf x`、放過 `r\m -rf x`。
- 沙箱：寫工作區可、寫家目錄 Read-only、家目錄看起來是空的、斷網、看不到 `.stack`；`AOS_WS`＝整棵樹時看得到 `.stack`；設定壞照跑並印 warning；`cpu_s: 1` 退 152；`user: "sub:5"` 時 bwrap `Can't find source path … Permission denied`（家目錄 700）。帳號名（sudo）那條沒跑。
- 份額：`cpu_s: 1` 的死迴圈 `limit_hit: cpu_s`；另起一台 daemon 包 `systemd-run --user --scope -p Delegate=yes`、`cgroup: on`，`mem_total_mb: 100` 收掉吃記憶體的行程（137、`limit_hit: mem`），用完 shutdown；`user: "sub:5"` 卡在 `LimitBad user sub:5: cannot reach /home/lorkhan`，但 stack 已有 `user:100004:rwx` 的 ACL。
- bwrap：直接跑一次最小布景（`/home` 不存在、自己是 2 號行程、uid 仍 1000）。
- aos-asuser：`id -u`＝5、uid_map 5→100004、讀不到 `~/.bashrc`、`--dry-run`、在 `/tmp` 寫檔得 100004 擁有、`--fix` 改回 1000:1001。
- aos-share：team、drop（都警告家目錄沒給 x）、check（四行）、reset。
- 寄件人自報：`AOS_STACK=/pretend/eca_main aos-post send` → `sender = /pretend/eca_main`、信夾擁有者 1000。

只讀程式、沒跑的：kernel_gate 的 pass 與 triage、perm 的 max_running／queue／hook、帳號名換身分、`procs` warning、`file_mb`、整樹 scope、aos-share 的 read／key／work／stack、aos-asuser 的 `--group`／`--git-safe`／`--recursive`。

這台的環境（頁面引用）：家目錄 700；`/etc/subuid`、`/etc/subgid` 有 `lorkhan:100000:65536`；bwrap 0.13.0、newuidmap、setfacl、s6（`/usr/local/bin`）都在；系統帳號 `aos-run` 與 `/srv/aos-run` 在；使用者不在 `aos-run` 群組；sudoers 讀不到、沒驗。

## 替使用者做的選擇

1. 檔名用英文（`kernel_gate.html`、`limits.html`…），頁面標題與內容中文，免得雙擊或換機時中文檔名出問題。
2. guard 一頁同時講 proto8 版與 wf 版 fsm-guard，另提一句 `user_zone_guard`（同是 before_tool hook，沒接在範本）。
3. 「份額」頁把 daemon 的 `user`／`sub:N` 換身分也放進去（它就是 `limits` 的一個鍵），aos-asuser 頁再做三種 `sub:N` 對照。
4. 狀態分三格：能用／有但沒接上（含預設關）／沒有；「範本預設」另一欄。
5. kernel_gate 的實測是在殼裡以 ann 的環境直接跑工具，不是讓 agent 自己叫（假腦不叫工具），頁上寫明。
6. cgroup 實測另起一台獨立 daemon（包委派 scope），不動暫存樹的根。
7. 深淺色多一個手動切換（記在瀏覽器 localStorage，讀不到就跟系統）。
