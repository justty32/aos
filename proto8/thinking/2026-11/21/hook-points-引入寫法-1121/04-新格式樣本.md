## 舊鍵怎麼對到新鍵（樣本用的寫法，細處可翻）

| 舊 | 新 | 說明 |
|---|---|---|
| `points` 底下的鍵 | 物件寫法：檔裡的鍵；陣列寫法：每項的 `id` | 他第 5 則：`[...]`、`{...}` 只差 id 放哪 |
| `fields` | `input`（JSON Schema，`{"type": "object", "properties": {…}}`） | 一句話的說明放進每個欄位的 `description`；型別是樣本照程式推的（例 `code` 是 `["integer", "null"]`），舊檔沒有型別 |
| 欄位物件的 `env`、`type` | `input` 裡那個欄位的 `"env": "AOS_LOOP_CODE"` 與 `"type": ["integer", "null"]` | `env` 是 JSON Schema 不認得的關鍵字，照 JSON Schema 的規矩被略過；`aos-hook fire` 照舊讀它 |
| `change`（`{鍵: 四種型別}`） | `output`（JSON Schema，`additionalProperties: false`） | string → `{"type": "string"}`；nonempty_string → 加 `"minLength": 1, "pattern": "\\S"`；object → `{"type": "object"}`；any → `{}` |
| `when` | 點的 `description` | 他第 1 則說「一個 id，配上 description」 |
| `phase`、`condition`、`subject`、`block`、`if_blocked`、`if_failed`、`key`、`entry_keys`、`fired_in` | 照抄，變成自由鍵 | 其中 `block`、`condition`、`entry_keys` 今天有行為（[02](02-各鍵程式讀不讀.md)），讀不讀是 [07](07-要他定的題.md) 第 2 題 |
| 檔頂層的 `provider` | 照抄，自由鍵 | 見 [05](05-一份檔一個provider.md) |
| `interfaces.json` 的 `{"provider": "aos-loop"}` | agent-fsm 那份檔裡的 `"$include": {"$env": "AOS_HOME", "$path": "/lib/aos/apps/hook/loop_points.json"}` | 引入寫在宣告內容裡（他第 4 則） |

handler 實際從 stdin 收到的，除了 `input` 描述的欄位，還有引擎自己加的 `event`、`hook`、`stack` 三鍵（`hook_run.py` 的 `run`）；樣本沒把這三鍵寫進每個 `input`，算引擎的共通約定。

## 物件寫法裡，哪些鍵不是點

物件寫法裡 id 當鍵，`description`、`provider` 這些也是同一層的鍵，名字又剛好合 id 的規則（小寫字母、數字、底線）。樣本用的規則：**值是物件的鍵才是點；`$` 開頭的鍵是讀者自己的（`$include`）；其餘（值是字串、陣列…）是自由鍵**。陣列寫法同理：帶 `id` 的項是點、帶 `$include` 的項是引入、其餘的項是說明。這是 [07](07-要他定的題.md) 第 4 題的一個選項，不是定案。

陣列寫法放在一份檔裡時，沒有地方放檔頭那句 `description`（repo 鐵律 3：新檔第一行一句話；JSON 檔慣例是第一個鍵 `description`），樣本用「第一項只有 `description`」湊。

## ann 的 `interfaces.json` 三種寫法

只列 `aos-agent` 裡的 `hook_points` 那一格，其餘鍵照舊。

字串（指到同夾的宣告檔，檔的內容＝`樣本/agent-fsm-hook_points.json` 那樣）：

```json
"hook_points": "hook_points.json"
```

陣列（直接寫內容，每項帶 id）：

```json
"hook_points": [
  {"$include": {"$env": "AOS_HOME", "$path": "/lib/aos/apps/hook/loop_points.json"}},
  {"id": "before_queue", "description": "idle: a good letter is about to enter the conversation",
   "input": {"type": "object", "properties": {"letter": {"type": "string"}, "content": {"type": "string"}}},
   "output": {"type": "object", "properties": {"content": {"type": "string", "minLength": 1}}, "additionalProperties": false},
   "block": true},
  {"id": "before_tool", "…": "…"}]
```

物件（直接寫內容，id 當鍵）：

```json
"hook_points": {
  "$include": {"$env": "AOS_HOME", "$path": "/lib/aos/apps/hook/loop_points.json"},
  "before_queue": {"description": "…", "input": {…}, "output": {…}, "block": true},
  "before_tool": {"…": "…"}}
```

用 agent.py 編譯出來、借 agent-fsm 格程式的 agent（今天寫 `[{"provider": "aos-loop"}, {"provider": "agent-fsm"}]`），照甲會寫成：

```json
"hook_points": {"$include": {"$env": "AOS_HOME", "$path": "/templates/agent-fsm/hook_points.json"}}
```

agent-fsm 那份自己已經引入 loop 那份，所以一行就夠（引入可以一層層往下，同一份經兩條路進來只算一次）。eca 的三份照樣寫成一個 `$include` 陣列。
