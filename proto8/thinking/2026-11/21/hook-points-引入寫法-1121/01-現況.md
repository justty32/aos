## `{"provider": "aos-loop"}` 怎麼變成一份檔

ann 的 `interfaces.json`（`templates/start-api/agents/ann/interfaces.json`，agent-fsm 範本同）：

```json
"hook_points": [{"provider": "aos-loop"}, "hook_points.json"]
```

1. 讀的人叫 `hook_point.for_definition(定義夾)`（`py/aos/hook_point.py:239-267`）：讀 `interfaces.json` 的 `aos-agent.hook_points`，一項一項看。
2. 字串＝路徑，相對的從定義夾算（`:261-262`）。
3. `{"provider": 名字}`＝查 `PROVIDERS` 表（`:263-264` → `provider_path` `:114-118`）。這張表寫死在 `hook_point.py:91-96`，而且路徑是**從 `hook_point.py` 自己所在的位置**算的：

   | 名字 | 指到 |
   |---|---|
   | `aos-loop` | `<hook_point.py 所在>/apps/hook/loop_points.json`（裝好後＝`$AOS_HOME/lib/aos/apps/hook/loop_points.json`） |
   | `agent-fsm` | `<樹根>/templates/agent-fsm/hook_points.json` |
   | `eca` | `<hook_point.py 所在>/apps/eca/hook_points.json` |
   | `mcp` | `<hook_point.py 所在>/apps/mcp/hook_points.json` |

4. 幾份讀進來後合成一張表（`read` `:209-229`）；同名的點在幾份裡說法要一樣（`CONTRACT` `:100`），不一樣＝`PointsBad`。

### 為什麼看不出來

- `aos-loop` 這個字**只是一張表的鍵**，表在 Python 原始碼裡。宣告上沒有路徑、沒有檔名、沒有提示，要知道它指哪裡，只能去翻 `hook_point.py`。
- 名字跟檔對不起來：`aos-loop` 對到的檔叫 `loop_points.json`、放在 `apps/hook/` 底下，不在 `aos-loop` 的夾（`cpp/aos-loop/`）裡。
- 檔裡自己的 `"provider"`（例如 `loop_points.json` 寫 `"provider": "aos-loop"`）跟表的鍵**沒有人比對**；兩個是各寫各的。
- 非 Python 的程式想讀這張宣告，要自己再抄一份這張表。

這就是他說的「我哪知道這個 aos-loop 是哪來的」。

## 指示詞在這幾份檔裡收不收

- 規範說 aos 自己讀的 JSON 一律支援指示詞、每支只解自己讀的那幾格（[N-45 續](../../../../docs/NORMS/06-基礎設施-命令列與指示詞/02-N-45-ref陣列與aos讀的JSON.md)）。
- 實際上 `hook_point.py` 讀 `interfaces.json` 與宣告檔都是 `json.load` 直讀，**不解指示詞**；11-20 設計稿 01 明寫「這個鍵不收指示詞」，理由是 Python 沒有行程內解指示詞的函式。
- Python 這邊要解指示詞，現成的做法是 `aos/directive_value.resolve`（起一支 `aos-directive`），tools.json 的 `$override`、hook 的 handler（`hook_run.py:118-123`）都這樣用。本機量起一支 `aos-directive` 解一個小物件，100 次平均不到 1 毫秒。
- 指示詞只有 `$env`、`$ref` 兩個（帶 `$path`、`$prefix`）。`$override` **不是指示詞**，是 aos-tools 登記檔自己的鍵（`apps/tools/registry.py:9`、`:60-83`）：值是路徑字串或「解成路徑的指示詞」，由登記檔的讀者自己疊。
- 實測 `aos-directive`（`bin/aos-directive`）：
  - `{"$ref": "loop.json#/points"}` 換成那份檔的內容；`{"$ref": ["a.json#/points", "#/mine"]}` 把幾份物件合成一份（同名後蓋前）。
  - `{"$ref": {"$env": "X", "$path": "/loop.json"}}`、`{"$ref": [{"$env": …}]}` **原封不動**：`$ref` 的值只收字串，不能由環境變數給路徑。所以 `$ref` 要指到 `$AOS_HOME` 底下的檔，只能寫相對路徑或絕對路徑。
  - 不認得的 `$include` 這種鍵原封不動；放在它裡面的 `{"$env": …, "$path": …}` 照樣解成字串（`{"$include": {"$env": "HOME", "$path": "/x"}}` → `{"$include": "/home/…/x"}`）。
