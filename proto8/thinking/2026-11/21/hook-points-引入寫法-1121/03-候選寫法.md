## 前提（他第 4、5 則定的）

`interfaces.json` 的 `hook_points` 收三種值：

| 值 | 意思 |
|---|---|
| `"hook_points.json"` | 字串＝一份宣告檔（相對路徑從定義夾算） |
| `[{"id": "before_tool", …}, …]` | 陣列＝直接寫內容，每項自己帶 `id` |
| `{"before_tool": {…}, …}` | 物件＝直接寫內容，`id` 當鍵 |

宣告檔裡面也是陣列或物件兩種之一（字串在檔裡沒意義）。所以「別家的點（aos-loop 那四個）怎麼進來」要寫在**內容裡**，`interfaces.json` 不再並列 provider。下面每個候選都在這個前提下寫；點本身的寫法照他第 2 則（`id`＋`input` schema＋`output` schema＋自由鍵），完整樣本見 [04](04-新格式樣本.md)，這裡的點只寫一個、其餘用「…」。

## 每個候選都一樣的地方

- **讀的時候才去讀被引入的檔**（動態連結）：loop 那份改了、`install.py` 換了 `lib/`，下一次讀就是新的，不用重新編譯 agent。要靜態連結（編譯時把別家的點抄進來）是另一題，見 [07](07-要他定的題.md) 第 3 題。
- **同一個點出現兩次照舊比對**：今天的「同名的點說法要一樣」（`CONTRACT`）留著，只是比的鍵換成新格式的硬性部分與有行為的鍵；同一份檔經兩條路被引入（菱形）算一次，不算衝突；引入繞圈＝`PointsBad`。
- **誰說的**：今天 `said` 記的是 `provider`＋路徑；之後記路徑就夠，`provider` 變成想寫就寫的說明（見 [05](05-一份檔一個provider.md)）。

## 甲：`$include` 鍵，值是路徑或解成路徑的指示詞（讀者自己解）

照 tools.json 的 `$override` 那條路：`$include` 是 **hook 點宣告的讀者自己認的鍵**，不是指示詞；值是路徑字串、`{"$env": …, "$path": …}` 這種解成路徑的指示詞，或這兩種的陣列。讀者先把值交 `aos-directive` 解成路徑，再自己去讀那份檔、合進來。

ann 的 `interfaces.json`（寫檔名）：

```json
{"aos-agent": {"entry": "body.json", "tools": "tools.json", "llm": "llm.json", "llm_keys": ["model", "reasoning_effort", "temperature", "top_p", "max_tokens", "seed", "presence_penalty", "frequency_penalty", "stop"], "history": "history.jsonl", "hooks": "hooks.json", "hook_points": "hook_points.json", "system": "system.txt"}, "aos-observed": {"file": "observed.jsonl"}}
```

ann 的 `hook_points.json`（物件，`id` 當鍵）：

```json
{"description": "Hook points of an agent-fsm agent: the agent-fsm cells' own points, and the aos-loop points its loop.json wires.",
 "$include": {"$env": "AOS_HOME", "$path": "/lib/aos/apps/hook/loop_points.json"},
 "before_tool": {"description": "act: before each tool call runs (every tool)",
                 "input": {"type": "object", "properties": {"name": {"type": "string"}, "id": {"type": "string"}, "arguments": {}}},
                 "output": {"type": "object", "properties": {"arguments": {}}, "additionalProperties": false},
                 "condition": "name", "block": true},
 "…": "其餘六個點"}
```

直接寫在 `interfaces.json`（陣列，每項帶 `id`；引入是其中一項）：

```json
"hook_points": [
  {"$include": {"$env": "AOS_HOME", "$path": "/lib/aos/apps/hook/loop_points.json"}},
  {"id": "before_tool", "input": {…}, "output": {…}, "condition": "name", "block": true},
  …]
```

直接寫成物件：`"hook_points": {"$include": {…同上…}, "before_tool": {…}, …}`。

- **看不看得出哪來**：看得出。路徑就寫在那裡，跟 procs-kernel `loop.json` 的 `--points {"$env": "AOS_HOME", "$path": "/lib/aos/apps/hook/loop_points.json"}`、tools.json 的 `$override` 長得一模一樣。
- **跟指示詞相不相容**：相容。`$include` 本身不是指示詞，`aos-directive` 會原封不動留著它（實測），只把裡面的 `$env`／`$path` 解成字串；所以拿 `aos-directive` 整份過一遍也不會壞。跟 `$override` 不打架：兩個都是「讀者自己的鍵、值是路徑」，差在合法——`$override` 是補丁式往下合、同名後蓋前；`$include` 是聯集、同名要說法一樣。跟 `$ref` 不打架：`$ref` 換成內容，`$include` 只給路徑。
- **靜態或動態**：動態（每次讀都去讀那份）。
- **搬到別的 daemon、別台機器**：只要那台設了 `AOS_HOME`、那棵樹有這份檔就指得到，讀到的是那台裝的版本；tools.json 本來就靠 `AOS_HOME`，所以 agent 的行程都有它。沒設＝`DirectiveBad`，宣告讀不進來。
- **非 Python 的程式**：要懂兩條規則（`$include` 的值解成路徑後去讀、帶 `id`／物件值的才是點）；或者直接叫 `aos-hook points -j --agent 定義夾`，拿合好的整張表（今天就有）。
- **要動的程式**：`hook_point.py`（讀三種值、`$include`、繞圈與菱形、新格式）；`for_definition` 換成讀字串／陣列／物件；`agent_spec_parts.py:21`、`:204` 寫出 `$include`；`kernel_spec.py:93`、`agentlib/hooks.py:50-55` 不再叫 `provider_path`，改成固定路徑或讀宣告；`PROVIDERS`、`provider_path` 拿掉。C++ 不動。

## 乙：直接用現成的 `$ref` 把內容拉進來（不改任何指示詞）

`$ref` 本來就能把幾份合成一份：都是物件就合鍵、都是陣列就接起來。

ann 的 `interfaces.json`：

```json
"hook_points": {"$ref": ["../../../../lib/aos/apps/hook/loop_points.json", "hook_points.json"]}
```

或檔名寫法，`"hook_points": "hook_points.json"`，而 `hook_points.json` 裡：

```json
{"description": "…",
 "$ref": ["../../../../lib/aos/apps/hook/loop_points.json", "#/own"],
 "own": {"before_tool": {…}, …}}
```

（第二種解得開，但 `$ref` 會把**整個物件**換掉：解完只剩兩份合起來的點，這份檔自己的 `description`、`own` 這層都不見，檔面上看到的形狀跟讀到的不一樣；loop 那份的 `description` 反而會被合進來當一個鍵。）

- **看不看得出哪來**：看得出檔名，但路徑是**相對**的，從寫它的那份檔的夾往上爬到 `lib/`，爬幾層取決於定義放哪；放到 `~/aos-home/agents/ann/` 跟放在 `templates/start-api/agents/ann/` 要寫的不一樣。寫絕對路徑就綁死一台機器。`$ref` 不收 `$env` 給的路徑（實測原封不動）。
- **跟指示詞相不相容**：就是指示詞本身，最相容；但讀者（`hook_point.py`）要先整份交 `aos-directive` 解，今天沒做。
- **合起來就認不出誰說的**：`$ref` 合物件是同名後蓋前、不報錯，loop 跟 agent-fsm 對同一個點說法不一樣也看不出來；合完也不知道哪個點來自哪份檔（`aos-hook points` 印不出「誰說的」）。合物件時兩份的 `description` 也互蓋。陣列寫法接起來不會蓋，重複的點讀者還找得到，但來源一樣丟了。
- **靜態或動態**：動態。
- **搬家**：相對路徑一搬就斷，除非定義跟 `lib/` 的相對位置不變。
- **非 Python 的程式**：叫 `aos-directive --file interfaces.json` 就拿到合好的內容，最省事。
- **要動的程式**：`hook_point.py` 讀之前先過 `aos-directive`；新格式。C++ 不動。
