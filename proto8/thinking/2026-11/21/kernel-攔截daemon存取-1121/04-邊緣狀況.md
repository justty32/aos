## kernel 掛了、不回、很慢

1. **站停著（實測）**：把 perm `stop` 掉後，用 ann 的身分跑：`mailbox_peek`、`mailbox_send`（給名字、給 box 都一樣）、`clock_register add`（給了 box 也一樣）、`goal get`、`agents_ctl ls` 全部約 3.1 秒後 `KernelFailed no reply from AOS_KERNEL=…`。照通的：`todo`、`clock_register ls`、`clock_register rm`（直寫登記表）。起停信：`ctl_wait` 等滿 `--timeout-s`（預設 30 秒）後撤回沒人領的信、報 `DaemonFailed`（讀程式）。
2. **問腦不受影響（讀程式）**：腦走 `AOS_LLM_KERNEL`，是另一個 kernel；ann 的身體本身不跑 ctl who。所以 perm 掛了 ann 照樣想、照樣回話，只是一叫到要認自己的工具就失敗。這次沒有在站停著時叫 ann 回一題。
3. **站很慢**：`kernel_gate` 的站是 agent 自己的 on_clock hook，agent 在一輪裡或睡著時不跑；知識庫 `aos/kernel.json` 已寫，使用者 11-19 選維持現狀只寫明。
4. **開代回會慢一倍（實測）**：`self_state` 3.5 秒 → 7.4 秒。

## kernel 自己

5. **站自己碰 daemon 不經任何 kernel（實測＋讀程式）**：perm 的環境沒有 `AOS_KERNEL`；它放行的信轉給 `AOS_DAEMON` 表上的 `procs_requests`，數 running 時直讀 `count_daemon` 的表。站也是 daemon 表上的一列，但它不靠表認自己（用 `AOS_STACK`）。
6. **站拆下來單獨跑（實測）**：沒有 `next`、沒有 `AOS_DAEMON` 時，連空的一輪都報 `kernel: error: DaemonMissing no next station`；寫了 `next` 就照轉。README 說「空輪不讀表」，但「找下一站」那步在空輪也做。
7. **agent 當 kernel（`kernel_gate`）而自己也帶著指向自己的 `AOS_KERNEL`（讀程式推論）**：它的工具要認自己時寄查詢信給自己的站，站只在它一輪結束後才跑，所以這一輪裡的 ctl who 一定等不到、`KernelFailed`。轉寄那頭有防（指自己就跳過），問表這頭沒有。
8. **llm kernel 也是掛在 daemon 上的一列，而且它自己是一台 daemon（實測：`llm/_entry` 是 `aos-daemon`，起樹後有兩個 aos-daemon 行程）**。它把腦的工作掛成自己那台的列；根的 `.env` 特地不設 `AOS_KERNEL`，避免它的掛信也繞去權限站。

## 人與 agent 的殼

9. **人的殼**：`source env.sh` 清掉 `AOS_KERNEL`，`aos-agent` 一律直寄、直讀；`aos-daemon-ctl` 本來就直寄。要讓人的指令也過站，得在 `source` 之後自己 `export AOS_KERNEL=…`；沒有 `AOS_STACK` 時回信箱在 `$AOS_KERNEL/reply/`。
10. **agent 開 shell 自己 `unset AOS_KERNEL`，或改用 `--daemon`、`aos-daemon-ctl`**：就繞過了。照使用者 11-21 的原則，這是不守規矩的存取，風險自己承擔；要硬防得靠 Linux 權限（kernel 02：daemon 與站用帳號 A、其他 proc 用帳號 B，ctl 信箱不給 B 寫）。知識庫 `aos/rules.json` 與 `kernel.json` 已寫「不要這樣繞過拒絕」。

## 巢狀 daemon

11. **子 daemon 底下的 proc（讀程式）**：daemon 起子行程時只覆蓋 `AOS_STACK`、`AOS_DAEMON`（＝子 daemon 自己）、`AOS_WS`，其餘環境照傳（`child.cpp`）。所以：
    - 上層環境若有 `AOS_KERNEL`，子 daemon 底下的 agent 也帶著它，起停信寄到上層的站；站沒寫 `next` 時轉給**站自己的** `AOS_DAEMON`（上層那台），於是子 daemon 的 agent 要開的子會被掛到上層 daemon 上。根的 `.env` 那句警告講的就是 llm kernel 這個例子。
    - 上層沒設、子 daemon 的 `.env` 或那隻 agent 的 `.env` 設了，才是子 daemon 自己的站。
    - 查詢信同理：問到的表是站那條路最後那台 daemon 的表，不一定是自己那台。
12. **打開 ann 的 `AOS_KERNEL` 那行後，ann 就拆不下來單獨跑（實測）**：那行寫 `${AOS_DAEMON}/procs/perm/requests`，沒有 `AOS_DAEMON` 時 aos-exec 報 `DotenvBad … variable referenced by ${...} is not set`。出廠註解掉時拆得下來（見 [05-切點](../shell-指令的比喻-1121/05-切點.md)）。

## 其他

- 經 kernel 的 `rm`（沒 `--purge`）不關 eca 畫面（知識庫 `aos/kernel.json` 已寫）。
- 起停信帶 `queue_wait_ms`（`set-def` 掛回那封也帶），排隊等不到格就拒 `SlotMissing`，不會晚到才套上（使用者 11-18 裁）。
