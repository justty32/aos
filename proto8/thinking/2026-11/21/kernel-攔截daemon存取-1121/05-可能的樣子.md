## 對照用的五句（使用者原話，出處在 README「使用者原話」）

- ① agent 不該和 daemon 耦合（11-21，可遷移性）
- ② 權限先做防呆，單人使用、模型可信（11-18）
- ③ 宣告只是參考，沒宣告的照樣跑（11-21）
- ④ 只防走規矩的存取，不守規矩的自己承擔，硬防靠 Linux 權限（11-21）
- ⑤ 不是要 kernel 完全替代 daemon，探索「寄信給 kernel、kernel 回位置」（11-21）

## 七種

### 甲 維持今天

- **攔得到**：起停掛拆的信、「表在哪」。
- **代價**：0。已知的：站 3 秒不回，所有要認自己的工具失敗（使用者 11-19 選維持、只寫明）。
- **合不合**：①合（agent 照舊只從環境拿位置）；②④合。

### 乙 只攔起停類，不攔查表

- **攔得到**：起停掛拆的信。查表回到直讀 `AOS_DAEMON`。
- **代價**：要改 `state_path` 的分支；「站掛了連信箱都讀不了」這件事就沒了，因為 14 處認自己不再經站。kernel 也就沒辦法回抄本。
- **合不合**：①：查表要 `AOS_DAEMON`，跟今天沒設 kernel 時一樣。②④合。跟⑤方向相反（拿掉了今天唯一「回位置」的那條）。

### 丙 今天的再補齊：所有查表都問 kernel

- **攔得到**：甲＋ 02 的 b 類 6、7 列（aos-mailbox `--to`、guard、gdb a.bp、aos-llm ls、comm walk、kernel_gate triage）也改問 kernel。`aos-daemon-ctl` 與明給 `--daemon` 是否也改，是另一層（11-07 使用者定直寄）。
- **代價**：六、七處程式改走 `state_path`；站不回時受影響的工具變多（mailbox_send 給名字那半也會掛）。
- **合不合**：①④合；⑤：kernel 回的位置對所有讀表的人都一致。

### 丁 c 類改成「寄信請人代做」

- **攔得到**：pause／resume、塞 queue、改別隻 stack 的設定、刪 stack、時鐘登記，每一件都變成一封信，kernel 看得到內容、能拒能改。
- **代價**：daemon 今天沒有 pause／resume／shutdown／時鐘的信，要嘛 daemon 加，要嘛站代寫檔；每個動作多一趟信與等待；站不回時這些也全停。改自己 stack（self_*）也要寄信的話，等於 agent 碰自己的記憶都要申請。
- **合不合**：②：防呆用不到這麼細。④：合（只對走規矩的）。shell 那份使用者說「放下東西就走」也算塞指令、是非侵入式的方式，這種改法是把非侵入式的直接寫檔改回經手人。

### 戊 kernel 回位置：抄本（⑤的甲）

- **攔得到**：誰問表、給它看哪幾列、每列的 stack 指哪。可以按 sender 給不同的表（但 sender 是自報的 `$AOS_WS`）。
- **代價**：抄本的新鮮度、相對路徑要先轉絕對（實測要做）、每次問都多繞一站（實測慢一倍）。只管得到「問了表才動手」的程式；直讀表的 b 類照樣看到真的（實測 mailbox_send）。拿到 stack 之後的動作照樣看不到。
- **合不合**：①合；④合（走規矩的看到的就是 kernel 給的世界）；③無關。跟 [linux-as-hw-1118/05 丁](../../18/linux-as-hw-1118/05-發想.md)「權限＝遞給你的夾」同一個念頭，不用 bwrap。

### 己 kernel 回位置＋開權限（⑤的乙）

- **攔得到**：同 uid 時跟戊一樣（開權限是空動作）。換 uid（daemon `sub:N`，11-19 起認）之後，沒被開門的那隻真的讀寫不到別隻的 stack。
- **代價**：要「逐次給、到期收、記誰給的」的零件，今天沒有（`aos-share` 是一次性的）；kernel 要認得真寄件人（K9 已裁、沒做）；要換 uid 時，linux-as-hw-1118/04 的三十條代價全部跟著來（家目錄 700、檔案擁有者、git…）。
- **合不合**：②：使用者說先防呆，這一種是防呆用不到的那半。④：「硬防靠 Linux 權限」說的就是這條。跟 [05 庚](../../18/linux-as-hw-1118/05-發想.md)「權限寄給 kernel 要」同一件事，05 寫的「會自然長出來」。

### 庚 連寄信都攔

- **攔得到**：agent 之間的信、塞別隻 queue 的話，都先過 kernel。
- **代價**：信箱今天是「放進對方的夾就算寄到」，不經任何人；改成經 kernel，kernel 掛了全樹沒法說話，而且 kernel 變成看得到所有信的內容。
- **合不合**：⑤說「不是要完全替代 daemon」；寄信本來就不經 daemon，攔它已經超出「daemon 存取」的範圍。

|---|---|---|---|---|---|
| 甲 今天 | 是 | 是（只問位置） | 否 | 無 | 14 處認自己的工具 |
| 乙 只起停 | 是 | 否 | 否 | 小 | 只有起停 |
| 丙 查表補齊 | 是 | 全部 | 否 | 小～中 | 更多 |
