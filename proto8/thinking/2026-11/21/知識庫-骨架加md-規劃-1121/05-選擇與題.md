## 替他做的選擇

他把規劃交給這條線，下面每一條都是實作層級、做錯重跑轉換腳本或改幾行就能換。每條寫「選了什麼／沒選什麼／為什麼」。

1. **指向寫法用 `{"$ref": "me.md#/標題"}`**，沒照他原話字面的純字串 `"xxx":"xxx.md"`。純字串分不出是路徑還是內容，工具沒辦法自動跟，agent 每次多讀一次。
2. **一頁一份 md**，沒用「一個值一份 md」。檔數少（多 102 份而不是兩百多份），在 VS Code 裡一頁就是一份從頭讀到尾的文件。
3. **每頁的 json 留著當骨架，檔名與鍵都不變**。這樣 `aos/me.json#/stack` 這類舊路徑（知識庫裡 321 處、程式與範本 20 處）一處都不用改。整頁只有一篇的頁也留一份一行的 json（31 份）。
4. **`json_get` 這一組自動跟到 md**（指到 md 的 `$ref` 換成文字），指到別份 json 的 `$ref` 照舊原樣印。所以 agent 的查法不用改。
5. **照標題尋的找法**：整份第一個字一樣的標題、不管幾個 `#`；可以多寫一段指明上層；完全一樣優先、不然不分大小寫再試一次；重名拿第一個。照他「大概尋一下就好」定的寬鬆版。
6. **一節＝標題那一行起、到下一個同級或更高級標題前**，含標題行、結尾統一一個換行。代價：10 篇多一個結尾換行。
7. **沒有標題的短文字留在 json**（24 個，主要是 `packs.json` 的 17 段包說明）。搬進 md 就得替它們加標題，那是加東西。結果：`packs.json` 這一頁大半還在 json 裡。
8. **`kernel.json#/what` 照規則切**，舊鍵只拿到前半；沒有為了它另訂特例。後半在 md 裡、沒少字。（題 1）
9. **json 工具不寫 md**：改文章用 `edit`／`write` 直接改 md 檔；`json_set` 指到 md 裡會報錯並說該用哪支。
10. **`wf/` 那一庫這次不換**：它是字串陣列與記錄表，沒有標題可尋，diff 本來就一行一句。
11. **`index_check` 多一條規則**：`X.md` 旁邊有 `X.json` 時不必列進 `_index.json`。不這樣的話 `index_view aos/tools` 會多五十幾行。
12. **`$ref` 指 md 在設定檔那邊（`aos-directive`）也一起通**，不只知識庫的工具。兩支程式對 `$ref` 維持同一套讀法；副作用是設定檔以後也能把長文字放 md（沒有人被迫用）。

另外三個小的：轉換腳本放 `wf/tools/kb_md.py`；Python 與 C++ 兩份讀法跑同一張案例表；今天已經超過 8 KB 的六頁照原樣搬、不順手拆。

## 想請他說的題

從他的話推不出來的。**三題都不擋動工**：不答就照「現在的預設」做，之後改得回來。

**題 1：`kernel.json#/what` 這篇有兩個大標題，舊鍵只拿得到前半，要怎麼辦？**

- a. 不管它，接受（現在的預設；後半直接讀 md 或查 `aos/kernel.md#/The initial kernel`）
- b. 把第二個標題降成 `##`（改了一個字元的內容；舊鍵就拿到全文）
- c. 替後半加一個新鍵（例 `initial`），骨架多一格（內容不改，多一條路徑）

**題 2：`packs.json` 那 17 段沒有標題的包說明，要不要也進 md？**

- a. 留在 json（現在的預設；一字不改）
- b. 進 md，每段前面加一個小標題（標題字用鍵名，例 `## look`；等於替內容加了標題）

**題 3：規範條文 N-45 今天寫 `$ref` 指的是 JSON 檔，這次讓它也能指 md，條文誰改、怎麼寫？**

- a. 先不改條文，等這個樣子用一陣子再說（現在的預設；交件回報裡註明條文與程式有這一處出入）
- b. 他自己改
- c. 這條線起草一句，他看過再放進去
