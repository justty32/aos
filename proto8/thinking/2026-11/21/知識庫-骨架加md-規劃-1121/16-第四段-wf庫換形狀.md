## `wf/` 庫 38 頁換成 md

第三段只搬了「有標題的文章」，`wf/` 庫留了 38 頁 json（工作流節點、空殼、記錄表）。使用者第 23 句要它們也換。這些頁沒有現成的標題，所以這次是**換形狀**：字一個不少，排法變了。新腳本 `wf/tools/kb_md_shape.py`（跟搬文章的 `kb_md.py` 分開）。

| json 裡的 | md 裡變成 | 怎麼讀 |
|---|---|---|
| 頁的 `_description` | 最上面一段，不加標題 | `x.md#/_` |
| 每個鍵 | 一個 `#` 標題，巢狀再深一級 | `x.md#/when` |
| 字串 | 標題底下一段字 | `#/when/_`（`#/when` 含標題行） |
| 字串陣列 | 清單，一個元素一項；元素本來就是 md 的行（有空行、清單記號…）就整段照放 | `#/steps/0`；整段的用 `#/鍵/_` |
| 值都是短字串的物件 | `鍵: 值` 清單 | `#/fields/date` |
| 其他物件 | 每個子鍵一個小標題 | `#/from/repo/_` |
| 物件陣列（記錄） | 每筆一個小標題，標題字是號碼 | `#/which/1/where` |
| `{"$ref": …}` | 一行 `→ 路徑` | |
| `skeleton`（給人照抄的空殼）、數字、空的物件或陣列 | 一個 json 區塊 | `#/skeleton/records` 照 json 往下尋 |

**好處：路徑幾乎不變。** 鍵變成標題、陣列第幾個變成清單第幾項，所以 `wf/workflows/decisions.json#/steps/0` 換完就是 `wf/workflows/decisions.md#/steps/0`。

- **38 頁全部換了，0 頁留 json**。`wf/` 庫現在只剩 `workflows/_index.json` 一份 json（夾的 index）。移除的 38 份 `.json` 各被同名 `.md` 取代。
- **資訊不少的核對**：舊 json 一共 645 個葉值（字串、清單元素、欄位、數字、空殼…），腳本換完逐個從新 md 用尋址讀回來比，**645 個全對、讀不回來的 0**。改完路徑後我再比一次（把路徑字拿掉後比），一樣 0 個不同。
- **退回 json 區塊的只有一處**：`source.json` 的 `blocks`（搬遷記錄，陣列裡還有陣列）。排成小標題時 `#/blocks/1` 會先撞到裡面那層也叫 `1` 的小節，讀回來不對，所以整個 `blocks` 留成一個 json 區塊。
- **誰在讀這些 json**：查了 `proto8/py`、`templates`、`cpp`、`frontend`、`wf/tools`、`install.py`，沒有任何程式讀 `knowledge/wf/` 底下的檔；它們只給 agent 讀。所以沒有「換了會壞」的。
- **路徑改寫**：對照表 861 條（[kb_md_map-wf.json](kb_md_map-wf.json)），知識庫裡 235 處。只改知識庫裡面、而且只改「指到這一庫自己的頁」的路徑；文中講工作區的檔（`wf/progress.json`、`wf/knowledge/decisions.json` 這些不是這一庫的頁）沒動。repo 自己的 `wf/` 沒碰。
- 空殼頁（`wf/skeletons/`）裡 `skeleton` 那一塊保持是 json：工作流叫 agent「照它抄進工作區」，抄的是 json 區塊裡的東西。

**醜的地方**（照實寫）：`source/block-3.md`、`block-4.md` 是搬遷記錄，每筆五個欄位各佔一個小標題，很長（block-4 一萬多字）；單一個數字 `block: 3` 變成一個標題加一個 json 區塊。

## 這一段替使用者定的

1. 換形狀的規則（上表），含「`skeleton`、數字、空的東西留 json 區塊」。
2. 鍵名原樣當標題（英文小寫，如 `# when`），不翻成中文，路徑才不變。
3. 讀不回來的鍵整個退回 json 區塊（這次只有 `source.json` 的 `blocks`）。
4. `$ref` 寫成一行 `→ 路徑`，路徑寫成從庫根算的完整路徑。
5. 路徑只改指到這一庫自己頁的；講工作區檔的不動。
6. 兩份內容是 `{}` 的範本 json 的一句話寫進手寫表，不動檔本身。
