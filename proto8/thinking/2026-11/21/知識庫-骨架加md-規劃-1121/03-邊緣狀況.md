## 沒有 json 骨架之後最要緊的三條

1. **標題就是路徑，改標題字＝別頁指過來的路徑斷掉。** 今天別頁寫 `aos/me.json#/stack`，文章標題隨便改都沒事；換完別頁寫的是 `aos/me.md#/What is in your stack`，標題改一個字就尋不到。會報錯（`PointerMissing`，列出現有標題），不會悄悄拿到別的。防線：新測試 `test_knowledge_paths` 交件前整庫掃。**執行期 agent 自己改知識庫時沒人替它查。** 知識庫裡這種帶位置的引用有 286 處（實量）。
2. **已經在跑的 agent 手上是舊字。** 範本系統文字抄進樹之後就是那隻 agent 自己的；它寫著「Start with knowledge/aos/_description.json」。知識庫一換，這個檔就不在了，舊 agent 照做會讀不到。同理，工具說明結尾的「More: aos/tools/x.json」在重裝之前也是舊的。這一段空窗要頂層在換知識庫那一刻處理（重抄範本或告訴在跑的 agent），這條線不碰活樹。
3. **路徑變長。** `aos/me.json#/stack` → `aos/me.md#/What is in your stack`；最長的標題 110 字。文章裡的引用會變長、agent 要整串照抄。「不分大小寫再試一次」能救打錯大小寫的，救不了少字的。

## 標題

4. **同一份 md 兩個標題一樣**：拿第一個。今天同頁重名 0（實量，102 頁 242 篇）。
5. **「不管幾個 `#`」會撞到小節**：前一篇裡有小節 `Errors`、後面一篇大標題也叫 `Errors`，`x.md#/Errors` 拿到前面那個。今天整庫只有 4 個二級標題、不撞（實量）。
6. **一篇文章自己有兩個一級標題**：整庫一處，今天 `kernel.json#/what` 這個值裡有 `# What a kernel is` 與 `# The initial kernel`。換完它們就是 `kernel.md` 裡前後兩節，各自尋得到；別頁原本指 `aos/kernel.json#/what` 的地方改指第一節，讀的人接著往下讀就是第二節。
7. **標題裡的 `/`** 寫 `~1`（整庫一處 `The [y/N] question`）。手寫容易忘，忘了報尋不到。
8. **中文、空白、標點**照寫；shell 裡要加引號，腦用的工具沒這問題。

## 清單

9. **清單中間插一項，後面的號碼全變。** 跟 json 陣列同一個毛病；會被別人指的東西用標題、不用清單第幾項（知識庫寫頁的說明要寫這句）。
10. **「第一個清單」的邊界**：只看那個標題自己的內文（`_` 那一段），不往小節裡找；小節裡的清單要寫到小節。兩個清單中間只隔一個空行、沒有別的字時，照 markdown 的讀法是同一個清單。
11. **清單項裡的程式碼區塊與續行**：縮排在那一項底下的都算那一項的。縮排沒對齊的續行（AI 常寫歪）可能被切到項外；大概尋得到就好。
12. **數字與 `_` 當標題**：有個標題真的叫 `0` 時，`#/0` 拿到標題，不是清單。有個標題真的叫 `_` 時反過來：`_` 是保留名，拿到的是上一層自己的內文，那個標題尋不到（今天整庫沒有這種標題）。

## 表格、json 區塊、index

18. **表頭算第 0 列**：資料從第 1 列起，容易差一。表格中間插一列，後面的號碼全變（同清單）。
19. **清單與表格搶數字**：清單贏，同一段的表格尋不到（他定的）。
20. **json 區塊「只有它」的判定很脆**：區塊前後多一句說明、或那個標題底下還有小節，就整節變回文字，原本 `#/標題/鍵` 的路徑全部尋不到（會報錯）。區塊裡 json 寫壞也一樣。
21. **文章標題剛好叫 `index`／`description`**：照認（他定的）：`index_view` 把它底下的清單當 index 印，清單項不像「名字: 一句話」的就只印出那一項的字；取一句話時拿 `description` 那節的第一句。不影響尋址。
22. **`_index.md` 與 `_index.json` 同在一夾**：有 json 就完全不看 md（他第 18 句），md 整份被忽略而且不提示，寫的人可能以為它有生效。
25. **index 不必列全之後**：知識庫加了一頁、忘了在 `_index.json` 加一項，沒有任何檢查會提醒；agent 用 `index_view` 看不到那頁，要 `ls` 才看得到。
26. **index 一項是純字串＝一句話**：字串剛好寫成檔名（`"xxx": "xxx.md"`）也只會被當成一句話印出來，不會被跟過去。

23. **清單當字典的誤認**：一句普通的話裡有「: 」（例 `- 注意: 這裡…`）也會被當成鍵 `注意`。只影響「用鍵尋得到什麼」，用號碼尋不受影響。鍵跟子標題同名時標題贏，那一項只能用號碼拿。
24. **`index` 指到的 `.json` 不是索引**：`index_check` 只查它在、讀得出來、最上層是物件；裡面每一項寫得對不對，要等 agent 用 `index_view` 讀它才看到。

## md 本身

13. **程式碼區塊裡的 `#` 與 `- `** 不算標題、不算清單。區塊忘了關＝後面全被吃掉；今天整庫沒有沒關的（實量）。
14. **型別**：md 裡拿到的一律是文字。換成 md 的頁本來就只有文字；有數字、欄位的頁照判準留 json（[06](06-wf庫與路徑盤點.md)）。
15. **結尾換行**：一節統一成結尾一個換行。今天有 13 篇原文結尾沒換行，換完讀出來多一個換行字元，字沒變。

## 讀與改

16. **讀一節幾次、多少**：`json_get aos/me.md#/What is in your stack` 1 次 1.5 KB，跟今天一樣；整頁 1 次 7.5 KB，一樣；eca 自己讀檔 1 次。`grep` 知識庫：今天命中的那一行是整篇文章（幾千字），換完是 md 裡的那一行。
17. **改文章與 git diff**：今天用 `edit` 改 json 裡的文章要處理 `\n`、`\"`（`me.json` 有 165 個）；換完直接改 md。同一次真實修改的 diff，純 json 最長一行 3,577 字、md 507 字（線 `top-1121-mdjson` 原型實量）。只抄 `*.json` 的人會漏掉全部文章；`install.py` 不碰知識庫，測試是整夾抄，不受影響。
