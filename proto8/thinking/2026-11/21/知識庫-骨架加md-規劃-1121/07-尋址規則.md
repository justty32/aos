# 尋址規則：`檔.md#/…` 怎麼照 md 現有的標題、標題自己的內文（保留名 `_`）、清單（號碼或鍵）、表格、json 區塊找到東西

← [README](README.md)｜從 [01-設計](01-設計.md) 分出來｜原話在 [00](00-使用者原話.md) 第 2、4、6、9、10、11、13、14 句

只靠 md 本來就有的東西（他第 4 句：不加東西、大概尋得到就好、尋不到可以）。

**標題**（他說的）：

1. `x.md`（不帶 `#`）＝整份文字。
2. `x.md#/標題字`＝那一節：從標題那一行起，到下一個同級或更高級的標題之前（底下的小節一起算）。拿到一段文字，含標題那一行；尾端空行去掉、結尾一個換行。
3. 找法是「整份裡第一個字一樣的標題」，不管它是幾個 `#`。小節不用把上層寫全。
4. 要指明上層就多寫一段：`x.md#/大節/小節`。
5. 字完全一樣優先；沒有，再試一次不分大小寫；還是沒有＝尋不到（`PointerMissing`，訊息列出這份 md 有哪些標題）。
6. 程式碼區塊裡以 `#` 開頭的行不算標題。只認 `#` 開頭的標題。

**標題自己的內文**（他第 9 句說的：保留名 `_`）：

- `x.md#/標題/_`＝只屬於這個標題的那一段：標題那一行之後、到它底下第一個子標題之前。不含標題那一行、不含各小節。沒有子標題時就是整節去掉標題行。那裡沒有字＝空字串。
- `x.md#/標題`（不加 `_`）照舊是整節，含標題行與所有小節。
- `x.md#/_`＝整份最上面、第一個標題之前的那段（例：頁開頭的一句話簡介）。
- `_` 是保留名，永遠是「自己的內文」；真的有標題叫 `_` 時那個標題尋不到。他說 `_` 或 `-` 都可以，這裡只認 `_`：`-` 在 json 工具裡已經有意思（`/-`＝接在陣列最後）。
- `json_ls` 列一節時，自己的內文有字就多列一行 `_`。

**清單**（他第 6 句說的）：

7. `x.md#/標題/0`＝那個標題**自己的內文**（就是 `_` 那一段）裡**第一個清單**的第 0 項（從 0 數，跟 json 陣列一樣）。拿到那一項的文字，不含前面的 `- ` 或 `1. `；那一項底下縮排的續行與子清單一起算。
8. `x.md#/標題/0/1`＝第 0 項底下的子清單的第 1 項。
9. 一段先當標題找；找不到標題、而它是數字，才當清單的第幾項。小節裡的清單要先寫到那個小節（`#/大節/小節/0`）；`#/標題/_/0` 與 `#/標題/0` 是同一項。`x.md#/0`＝最上面那段（`#/_`）的第一個清單的第 0 項。
10. 那一節的第二個清單尋不到（他說「第一個清單」）。`- `、`* `、`+ `、`1. ` 開頭的都算清單。

**清單當字典**（他第 14 句說的）：

- 清單項寫成 `鍵: 值` 時，可以用鍵尋：`x.md#/標題/鍵` 拿到值。不用整個清單都這樣寫：有冒號的那幾項能用鍵尋，沒冒號的只能用號碼。
- 冒號的認法：項裡第一個「半形冒號後面接空白或行尾」或「全形冒號 `：`」。網址（`http://`，冒號後面不是空白）與反引號裡的冒號不算。鍵外面包著的 `**` 或反引號去掉（`- **status**: open` 的鍵是 `status`）。
- 冒號在行尾（`- 鍵:` 底下縮排接子清單或續行）＝值是底下那一塊，可以再往下尋（`#/標題/鍵/子鍵`、`#/標題/鍵/0`）。
- 順序：同一段先當子標題找，再當號碼，最後才當清單的鍵。所以鍵跟子標題同名時標題贏；鍵本身是數字時號碼贏。鍵重複拿第一個；完全一樣優先、不然不分大小寫再試。
- 用號碼尋照舊能用：`#/標題/0` 拿到整項的字（含「鍵: 」）。`json_ls` 列清單時有鍵的項列鍵。
- `# index` 與 `_index.md` 就是這條規則：鍵＝名字、值＝一句話。表格不做鍵（他說的）。

**表格**（他第 11 句說的）：

11. `x.md#/標題/2/0`＝那個標題自己的內文裡**第一張表**的第 2 列、第 0 欄。先列（從上到下 0～N）再欄（從左到右 0～N），當二維陣列。
12. **表頭那一列算第 0 列**（照他「從上到下」數；`|---|` 那條分隔線不算一列）。所以資料從第 1 列起。
13. `#/標題/2`（只寫列）＝那一列，一個字串陣列。格子裡的字去掉頭尾空白，`\|` 還原成 `|`。格子的值一律是字串，空格子＝空字串（他第 14 句）。
14. 同一段裡既有清單又有表格：**數字只指清單**，那段的表格尋不到（他第 13 句）。只有表格、沒有清單時數字才指表格。

**json 區塊**（他第 11 句說的）：

15. 一個標題底下**只有一個** ```` ```json ```` 區塊、完全沒有別的字（也沒有小節）＝那一節當 json。`x.md#/標題` 拿到的是那份 json 的值（不是文字），`x.md#/標題/鍵/子鍵`、`#/標題/陣列/0` 照 json 的路徑繼續往下尋；數字、布林、物件原樣回來。
16. 區塊裡的字不是合法 json＝當普通文字節（往下尋報 `PointerMissing`，訊息說那個區塊解不開）。區塊外多一個字就不算，整節照文字。
17. `x.md#/標題/_` 在這種節拿到的是原文（含圍欄）。json 工具不往這種區塊裡寫。

**四個有意思的標題名**（他第 11 句說的；怎麼用在 [01](01-設計.md)）：`_index`、`index`、`_description`、`description`。尋址上它們就是普通標題，`x.md#/index` 照樣拿到那一節。

其餘照 `檔#/指標` 本來的寫法：標題裡有 `/` 寫 `~1`；中文、空白照寫；同一份兩個標題一樣拿第一個。`json_ls x.md#/標題` 列出底下的小標題，有清單再加一行說有幾項。md 裡拿到的是文字；例外是表格的一列（字串陣列）與 json 區塊（json 值）。

**沒放進去的**：一般的程式碼區塊（不是「整節只有一個 json 區塊」那種）不能用號碼尋，他沒說要。


## 整份 md 倒成一棵 json 樹（本體的第三個動作，這條線定的樣子）

給人看、給測試對用；平常工具是給路徑拿一格，不走這個。

- 一個標題＝一個鍵。底下沒有小節：值是它自己的內文（文字）；整節只有一個 json 區塊：值是那份 json。
- 底下有小節：值是物件，`_` 放它自己的內文（沒有字就不放），每個小節一個鍵。
- 檔案最上面、第一個標題之前有字：根物件的 `_`。
- 清單、表格留在文字裡不展開（要拿項與格用路徑）。同名的標題只留第一個。
