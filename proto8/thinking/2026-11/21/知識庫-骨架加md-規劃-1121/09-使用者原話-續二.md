# 使用者原話續二（11-21 晚，逐字）：看完第二版之後的第 11～15 句與每句怎麼讀

← [README](README.md)｜前面：[00](00-使用者原話.md)（第 1～5 句）、[08](08-使用者原話-續.md)（第 6～10 句）

## 看完第二版的回話（11-21 晚，逐字）

11.「好，那就只認_。啊，指向寫法這塊，爲何必須要有$ref才能自動跟到.md？_index.md感覺也可以兼容，當然，.md有他的限制在，然後_index.json的優先級較高，_index.md就是補充但不覆蓋。可以有# _description，當然，這個寫法很醜，所以就是說我們認，但建議別這樣寫，# _index也是，除此之外，.md我還想私心加一個機制：認# description, # index，這個就挺舒服了，當然，要不要寫都隨意，通常我們是推薦另外弄一個.json存這份.md的index,description。再來一個我覺得有搞頭的小特性：如果一個#標題下，只有'''json ... '''，完全沒有其他內容，那他就可以當json，這樣就完美相容了。然後表格可以有，一律先y軸再x軸，從上到下0~N，從左到右0~N，當二軸陣列。」

| 這句裡的 | 讀成 | 落在 |
|---|---|---|
| 只認 `_` | 定案 | [07](07-尋址規則.md) |
| 爲何必須要有 `$ref` 才能自動跟 | 問句，不是指示；這條線不替他定，列成題 | [05](05-選擇與題.md) 題 1 |
| `_index.md` 也相容，`_index.json` 優先，md 補充不覆蓋 | 夾裡可以有 `_index.md`；同名項以 json 為準，md 只補 json 沒有的 | [01](01-設計.md)「index 與 description」 |
| 認 `# _description`、`# _index`（醜、不建議），也認 `# description`、`# index` | 四個標題名都認；寫不寫隨意 | 同上 |
| 通常推薦另外弄一個 .json 存這份 md 的 index、description | 拿不準是指夾的 `_index.json` 還是每份 md 配一份 json（跟第 6 句「不要 x.md 旁邊有 x.json」怎麼並存），列成題 | [05](05-選擇與題.md) 題 2 |
| 標題下只有一個 json 區塊就當 json | 那一節的值是 json，可以繼續往下尋。他打的是 `'''json`，頂層與這條線都讀成 markdown 的三個反引號圍欄 | [07](07-尋址規則.md)「json 區塊」 |
| 表格可以有，先 y 再 x，都從 0 數，當二維陣列 | `#/標題/2/0`＝第 2 列第 0 欄 | [07](07-尋址規則.md)「表格」 |

第二版的題 2（`wf/` 庫 68 處路徑）、題 3（N-45 條文）他沒答，照預設，改列在代定（[05](05-選擇與題.md) 選擇 16、17）。一般程式碼區塊他沒說要，不加。他還沒說動工。

## 再回的一句（逐字）

12.「噢噢好吧，那還是乖乖$ref吧。1.對的，就是資料夾的_index.json，然後我記得他不是可以二次導航嗎？{"xxx.md":{"desciption":..., "index":"xxx.index.json"}}這樣，感覺很優雅。2.對的」

（「1」「2」對的是頂層問他的兩處：1＝推薦存 md 的 index、description 的那份 json 是誰；2＝`'''json` 是不是三個反引號圍欄。`desciption` 是他打的字，應為 `description`。）

| 這句裡的 | 讀成 | 落在 |
|---|---|---|
| 還是乖乖 `$ref` | 自動跟到 md 只用 `$ref`，定案；第三版題 1 取消 | [05](05-選擇與題.md) |
| 就是資料夾的 `_index.json` | 推薦存 md 的 index、description 的地方＝夾的 `_index.json`，定案；第三版題 2 取消 | [01](01-設計.md) |
| 他不是可以二次導航嗎？ | 問句，憑記憶。查了程式：**可以，今天就有**（一項的 `index` 欄），細節與一個卡點在 [01](01-設計.md)「二次導航」 | [01](01-設計.md)、[05](05-選擇與題.md) 題 1 |
| 2.對的 | json 區塊＝三個反引號圍欄，確認 | [07](07-尋址規則.md) |

13.「既有清單又有表格，那就只認清單，清單優先級靠前。真有文章標題剛好叫index,description，那就算他倒霉...不是，我是說，就認，反正就讀」

讀成：同一段既有清單又有表格，數字只指清單，那段的表格尋不到；只有表格時數字才指表格。文章標題剛好叫 `index`／`description` 不做特例，照當 index／description 讀，讀到什麼算什麼。表頭算不算第 0 列他沒說，這條線定（算，[05](05-選擇與題.md) 選擇 10）。

## 看完第三版的回話（逐字）

14.「啊？不是，爲何"index":"xxx.index.json"會有問題？然後表格的值一律字串，空的就是空字串。_index.md的樣子，把xxx: yyy當做一個key-value pair，讓清單變成字典...可以，話說這塊其實可以拓展到清單，但表格不行。你問的這題我覺得應該要可以是b，反正就是檔名最後要是.json，解析失敗再說。」

| 這句裡的 | 讀成 | 落在 |
|---|---|---|
| 爲何 `"index":"xxx.index.json"` 會有問題 | 問句。答案：`index_check` 是照他 11-12 自己那句寫的，見 [02](02-工具與測試.md)「`index_check`」 | [02](02-工具與測試.md) |
| 應該要可以是 b，檔名最後要是 .json，解析失敗再說 | `index` 可以指到整份檔，條件只有檔名以 `.json` 結尾；`index_check` 不預先看內容，讀不出索引是讀的時候的事。比第三版列的 b 寬（不限 `.index.json`）。c 沒選，不做 | [02](02-工具與測試.md) |
| 表格的值一律字串，空的就是空字串 | 不轉數字、不給 null | [07](07-尋址規則.md) |
| 把 `xxx: yyy` 當 key-value，清單變字典；可以拓展到清單，表格不行 | 任何清單（不只 index）裡寫成「鍵: 值」的項可以用鍵尋；表格不做 | [07](07-尋址規則.md)「清單當字典」 |

15.「尷尬，index_check這東西在拖後腿...他不能找到某個.json嗎？然後那個.json就是符合index格式的json object」

讀成：問句帶想法，跟第 14 句選的 b 同方向，把樣子講明——`index` 指到任意一份 `.json`，那份檔最上層的物件整個就是 index 表，不必包在 `_index` 鍵底下。答案：能，`index_view` 今天就讀得了，只有 `index_check` 要放寬一條；另外把這支還有哪幾條會卡到這次設計列出來給他審（只列不改），都在 [02](02-工具與測試.md)。
