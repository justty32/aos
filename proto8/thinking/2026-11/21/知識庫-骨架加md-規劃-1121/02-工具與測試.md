# 工具與測試：要改的九處、各改多少、不改的四處、怎麼驗（這次都還沒動，等使用者看過規劃）

← [README](README.md)｜上一份：[01-設計](01-設計.md)｜下一份：[03-邊緣狀況](03-邊緣狀況.md)

原則：proto8 當沒有舊版，定了就整庫換、不留兩套讀法。但工具改完**必須照樣讀得了今天的純 json 知識庫**，因為工具先裝進活樹、知識庫後換（順序見 [04](04-轉換與尋不到的.md)）。新規則只在「檔名以 `.md` 結尾」與「`$ref` 指到 `.md`」時才起作用，純 json 走的路一行都不變，所以這一點自然成立；驗收時用今天的庫再跑一遍確認。

## 不改的（列出來，免得以為漏了）

- `index_view`（`py/aos/index.py`）：只讀 `_index`，都留在 json。驗收時實跑確認輸出逐字不變。
- `jsonx_*`（複雜組）：照舊「照寫的印」；要文字就帶 `resolve: true`（底下是第 1 項，已經會了）。
- `aos-json-view`：照舊，`$ref` 印成 `→ me.md#/…`。他現在用 VS Code 直接開 md，這支不急。
- `test_kits`、`test_daily`、`test_paths_move`：只認 `knowledge` 這個夾名與入口頁的路徑，不讀頁的內容；照跑確認。
- 概念與規範條文（`docs/NORMS` 的 N-45 寫 `$ref` 指的是 JSON）：改寫他的條文不是這條線能代做的，列為題（[05](05-選擇與題.md)）。

## 怎麼驗（第二段動工時）

1. 乾淨複本：`git archive HEAD` 解到 `~/.aos/scratch/top-1121-kbmd/`，疊上改動，在複本裡 `install.py`。
2. 單元測試（unittest）：aos-directive、aos-json、`py/tests`、`templates/tests`、`wf/tools/tests`。
3. **知識庫還是純 json 時**：`json_get`／`json_ls`／`index_view` 對今天的庫抽查，輸出跟改之前逐字一樣。
4. **知識庫換成新樣子後**（在複本裡換）：轉換腳本的 `verify` 全庫比對；再用假腦樹照範本系統文字教的走法查三個不同頁的三條路徑（預定 `aos/me.json#/stack`、`aos/tools/glob.json#/rules`、`aos/rules.json`），結果跟換之前逐字比。
5. `index_gen.py` 檢查、`index_check.py` 0 problems。
