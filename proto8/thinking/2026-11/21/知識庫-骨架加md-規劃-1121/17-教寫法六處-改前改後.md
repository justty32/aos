# 教寫法的六處：改前改後的那一句（第 24 句「新寫的就預設寫.md，然後再去用index json做骨架」）

← [16-第四段](16-第四段-wf庫換形狀.md)

**`knowledge/README.md`**

- 改前：一頁只會是其中一種；
- 改後：一頁只會是其中一種；**新寫的頁預設寫 `.md`、用夾的 `_index.json` 當導航骨架，要用 `.md` 還是 `.json` 都可以**（使用者 11-21 晚「以後我覺得可以是新寫的就預設寫.md，然後再去用index json做骨架，當然，具體要用.md還是.json都可以」；不檢查）；

**`knowledge/docs/01-樹長怎樣與多庫.md`**

- 改前：├─ rules.json             ← 一個檔＝一個 JSON 值（這份是一段文字）
- 改後：├─ rules.json             ← 一個檔＝一個 JSON 值（這份是一段文字）；11-21 起這種文章頁是 rules.md，新寫的頁預設寫 .md（見 03）

**`knowledge/docs/02-寫入與節點怎麼寫.md`**

- 改前：## 節點怎麼寫（給人改內容時看） ⏎ 
- 改後：## 節點怎麼寫（給人改內容時看） ⏎  ⏎ - **新寫的頁預設寫成 `.md`，用夾的 `_index.json` 當導航骨架；要用 `.md` 還是 `.json` 都可以**（使用者 11-21 晚「以後我覺得可以是新寫的就預設寫.md，然後再去用index json做骨架，當然，具體要用.md還是.json都可以」）。這是預設、不是規定，不做檢查：文章、說明、流程寫 md 最順；短欄位、記錄表、要給程式讀的設定寫 json 也行。md 頁怎麼寫、怎麼尋見 [03](03-md頁與尋址.md)；下面幾條講的是 json 頁的寫法。 ⏎ 

**`knowledge/docs/03-md頁與尋址.md`**

- 改前：- **哪些頁用哪種（參考用，不檢查）**：頁裡都是有標題的文章 → md；有沒標題的短文字、欄位、記錄表、數字 → json（例 `aos/packs.json`、`wf/workflows/` 的節點、`wf/skeletons/` 的空殼）。
- 改後：- **新寫的頁預設寫 `.md`**，再用夾的 `_index.json` 當骨架；要用 `.md` 還是 `.json` 都可以（使用者 11-21 晚「以後我覺得可以是新寫的就預設寫.md，然後再去用index json做骨架，當然，具體要用.md還是.json都可以」）。參考用、不檢查：文章與流程寫 md；短欄位、記錄表、給程式讀的設定可以寫 json（現在留 json 的例：`aos/packs.json`）。`wf/` 庫原本是資料形狀的 38 頁 11-21 也換成 md 了：鍵變標題、短字串物件變 `鍵: 值` 清單、字串陣列變清單、記錄陣列變編號小節、只適合當資料的（空殼 `skeleton`、數字）留 ```` ```json ```` 區塊。

**`knowledge/wf/_description.md`**

- 改前：收在工作區的 `wf/` 夾，用 index 與 json 節點組織。這一庫講它的組織原則。
- 改後：收在工作區的 `wf/` 夾，用 index 與節點組織。這一庫講它的組織原則。 ⏎  ⏎ 節點寫成 `.md` 還是 `.json`：新寫的預設寫 `.md`，再用夾的 `_index.json` 當導航骨架；要用哪一種都可以，不檢查（這一庫自己的頁現在都是 md）。本庫各頁裡寫 `<名稱>.json`、「json 節點」的地方講的是 json 形態的寫法；寫成 md 時，原本的鍵就是標題（`#/when`、`#/steps/0` 照樣尋得到），要給人照抄的空殼放在一個 ```` ```json ```` 區塊裡。

**`knowledge/wf/nodes.md`**

- 改前：這裡只寫工作區 `wf/` 多出來的約定。
- 改後：這裡只寫工作區 `wf/` 多出來的約定。新寫的節點預設寫 `.md`（用夾的 `_index.json` 當骨架），要用 `.md` 還是 `.json` 都可以；下面寫 `<名稱>.json` 的地方換成 `<名稱>.md` 一樣成立，鍵就是標題。
