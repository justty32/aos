# 設計：一頁一份 md 放文章、同名 json 留骨架用 `$ref` 指到 md 的標題、`檔.md#/標題` 照標題字尋

## 換完長什麼樣（拿 `aos/me.json` 當例子）

今天 `me.json` 一份 7.9 KB，每個鍵的值是一整篇 md 壓成一行。換完變兩份：

`aos/me.md`（文章，原樣一篇接一篇，中間空一行，**沒有加任何東西**）：

```md
# Who am I

Finding your own name, what is in your stack, …

# What is in your stack

…
```

`aos/me.json`（骨架，約 0.6 KB，鍵跟今天一模一樣）：

```json
{
 "_description": {"$ref": "me.md#/Who am I"},
 "stack": {"$ref": "me.md#/What is in your stack"},
 "self_tools": {"$ref": "me/self_tools.json"},
 "self_state": {"$ref": "me.md#/self_state: what you are right now"}
}
```

骨架讀起來就是一張目錄：鍵 → 哪份 md 的哪個標題。原本就拆出去的 `me/self_tools.json` 照舊留 `$ref`，那一頁自己也變成 `me/self_tools.json`（骨架）＋ `me/self_tools.md`（文章）。

## 骨架怎麼指：`{"$ref": "檔.md#/標題"}`

- 用現成的 `$ref`，不發明新寫法。路徑規則跟今天的 `$ref` 一樣：`#` 左邊是檔（從這份 json 所在的夾算），右邊是檔裡的位置。
- 他原話寫的是 `"xxx":"xxx.md"`（純字串）。沒照字面用純字串的原因：純字串分不出「這是一條路徑」還是「這就是內容」，工具沒辦法自動跟過去，agent 每次都要多讀一次；`$ref` 一看就知道是指向。要換回純字串，重跑轉換腳本就行。
- 整份只有一篇文章的頁（今天整個檔就是一個字串，例 `aos/rules.json`）：文章搬到 `rules.md`，`rules.json` 剩一行 `{"$ref": "rules.md"}`（不帶 `#`＝整份 md）。

## 粒度：一頁一份 md

- 一份 json 頁對一份同名 md，放在同一夾。文章型的值全部搬進去，順序照 json 裡鍵的順序。
- 不採「一個值一份 md」：檔數會從 109 變三百多，在 VS Code 裡一頁要開好幾個分頁；一頁一份時整頁從上讀到下就是一份文件。
- 8 KB 一檔的建議照舊落在 md 上：md 太大就把幾篇搬到另一份 md，骨架那幾個 `$ref` 改指新檔。**經骨架走的路徑（`aos/me.json#/stack`）不會變**，這是留骨架最大的好處。今天已經超過 8 KB 的六頁（`cli/eca` 21 KB、`me/self_hook` 18 KB、`kernel` 17 KB…）這次照原樣搬，不順手拆。

## `#/xxx` 怎麼對到 md：只看標題

照他第 4 句：md 裡不加東西，只靠 `#` 標題，大概尋得到就好。規則六條：

1. `x.md`（不帶 `#`）＝整份文字。
2. `x.md#/標題字`＝那個標題的那一節：從標題那一行起，到下一個**同級或更高級**的標題之前（底下的小節一起算）。拿到的是一段文字，含標題那一行。尾端空行去掉，結尾留一個換行。
3. 找法是「整份裡第一個字一樣的標題」，**不管它是幾個 `#`**。所以小節不用把上層寫全：`x.md#/小節名` 就找得到。
4. 要指明上層就多寫一段：`x.md#/大節/小節`＝先找到大節，再在它裡面找比它深的小節。
5. 字完全一樣優先；沒有完全一樣的，再試一次不分大小寫。還是沒有＝尋不到（報 `PointerMissing`，訊息裡列出這份 md 有哪些標題）。
6. 程式碼區塊（三個反引號或三個波浪號圍起來的）裡以 `#` 開頭的行不算標題。只認 `#` 開頭的標題，不認「底下畫 `===`」那種。

其餘照 `檔#/指標` 本來的寫法：標題裡有 `/` 寫成 `~1`、有 `~` 寫成 `~0`（今天整庫只有一個標題有 `/`：`The [y/N] question`）；中文、空白照寫。同一份 md 兩個標題字一樣＝拿到第一個，不報錯。

列出來（`json_ls x.md`、`json_ls x.md#/大節`）＝那個範圍裡的標題，一行一個。md 裡拿到的東西一律是文字（字串）；數字、布林這類留在 json。

## 從 `aos/me.json#/stack` 一路接到 md

- 腦用的 `json_get`、`json_ls`、`json_len`、`json_search`、`json_multi_get`：**遇到指到 md 的 `$ref` 自動換成那段文字**，不管它在路上、在終點、還是在拿到的值裡面。所以 `json_get aos/me.json#/stack` 跟今天一樣一次拿到文章；`json_get aos/me.json`（整頁）也跟今天一樣拿到每個鍵都是文章的物件。
- 指到別份 json 的 `$ref`（`me.json#/self_tools`）照舊原樣印出 `{"$ref": …}`，agent 自己再去讀那一頁，跟今天一樣。
- 直接查 md 也行：`json_get aos/me.md#/What is in your stack`。
- 自帶讀檔工具的 eca（claude、pi）：讀 `me.json` 看到骨架，再讀 `me.md`；或直接讀 `me.md`。
- `index_view` 完全不變：它讀的 `_index.json`、檔內 `_index` 都留在 json。
- 設定檔的 `$ref`（`aos-directive`）也一起學會指 md：拿到的是那段文字。這是順帶的，知識庫用不到；好處是兩支程式對 `$ref` 的讀法維持同一套。

## 什麼留在 json

| 留在 json 的 | 為什麼 | 數量（`aos/` 庫） |
|---|---|---|
| 每個鍵（骨架） | 舊路徑靠它 | 全部 |
| `_index.json` 與檔內 `_index` | `index_view` 讀的導航表，本來就是短句表格 | 4 份＋`packs.json` 一處 |
| 指到別份 json 的 `$ref` | 照舊 | 10 個 |
| **沒有標題的短文字** | 文章開頭沒有 `#` 標題，搬進 md 就沒有東西可以尋，除非替它加標題（＝加東西、改內容） | 24 個：`packs.json` 的 17 段包說明與它的 `_description`、`clock.json`／`kernel.json` 的 `_description`、四份只有一句話的夾說明 |

判準只有一條：**值是文字、而且第一行是 `# 標題` → 搬 md；其他留 json**。`aos/` 庫 242 篇文章全部符合（每篇都以一級標題開頭，同一頁沒有重名）。

## 寫入

json 工具這次**只讀 md、不寫 md**：`json_set` 指到 md 裡＝報錯，訊息說「用 `edit`／`write` 改那份 md」。AI 改文章就是直接改 md 檔，這正是他說的「AI 改起來比較舒服」。`json_set aos/me.json#/stack` 照舊是改骨架那一格（把 `$ref` 換成別的值）。
