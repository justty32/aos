# 使用者原話續三（11-21 晚，逐字）：看完第四版、對 `index_check` 四條現有規則的裁定與實作順序（第 18 句）

18.「喵的，誰說index格式要列出所有東西了？他喵的，這個規則刪掉。key寫成xxx#/yyy的時候把它當json讀，乾，啊xxx.md#/yyy，他也可以當json讀啊，拜託，實作的時候先實作.md和json的轉換，後面再來處理其他的。每項必須是{description...}這種物件...Hmmm，我希望這邊改一下，也可以是純字串，但這個字串就是等同於description了...如果有需要的話得自己用$ref指向別的地方。整隻只認_index.json...如果沒有_index.json，那才去看_index.md」

| 這句裡的 | 讀成 | 落在 |
|---|---|---|
| 誰說 index 要列出所有東西了，這個規則刪掉 | `index_check` 的 `EntryMissing`（在但沒列）整條刪掉 | [10](10-index_check.md) 第 1 條 |
| `xxx.md#/yyy` 也可以當 json 讀 | 鍵寫成 `檔#/位置` 時，md 照這次的尋址規則讀，讀得到就算在 | [10](10-index_check.md) 第 2 條 |
| 先實作 .md 和 json 的轉換，後面再處理其他的 | 實作順序：先做「把 md 讀成 json」的本體，其他都建在它上面。「轉換」這條線採頂層的讀法（讀成樹的那支核心），不是另做一支檔對檔互轉的工具；理由在 [02](02-工具與測試.md)「順序」 | [02](02-工具與測試.md) |
| 一項也可以是純字串，等同 description；要指到別處自己用 `$ref` | index 的一項可以直接寫一句話。**這改掉他最早那句 `"xxx":"xxx.md"` 的讀法：純字串現在是「一句話」，不是指向** | [10](10-index_check.md) 第 3 條、[01](01-設計.md) |
| 沒有 `_index.json` 才去看 `_index.md` | 有 json 就只用 json；沒有才用 md。**跟第 11 句「json 優先、md 補充不覆蓋」（兩份合併）不一樣**，照最新這句寫，回報裡標出來請他確認 | [10](10-index_check.md) 第 5 條、[01](01-設計.md) |

他仍沒說動工。
