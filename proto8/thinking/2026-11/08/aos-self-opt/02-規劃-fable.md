# aos-self-opt 第一輪規劃（fable，2026-11-08）

## 1. 一句話結論

第一輪只做一件事：在 PG5 離線重播上，用**不含神經網路、不呼叫 LLM 的枚舉式符號迴歸**，從**只有通用原語、零規則**的空基準長出 linker 判決規則（「這個提及指哪個實體／不連／棄權」），以 holdout 任務＋實體替換合成題＋奇偶兩折量學習曲線；過不過，看 holdout 覆蓋能不能從 0 離地而且不背答案。

## 2. 第一輪範圍

**做**：
- 被優化的主功能＝linker 判決本身（規則直接給出實體或不連），不是路由、不是門檻。
- 搜尋空間＝typed 謂詞 AST，原語只有通用的文字／KB 運算（§5 原語集），枚舉到深度 3，行為去重、covered 判定、帳本進退。
- 語料只用 PG5：2,943 題實例去重後的 205 獨特 LLM 題＋368 T0 題（573 題），加合成題。
- 量具：從空基準重放 k＝5 個 pass 的 `curve.jsonl`、面積、達標 pass、兩折差、meta 帳（CPU 時間；LLM token 固定為 0）。
- LLM 輔助通道只開「離線口」：把 PG5 現成的 195 條蒸餾規則當作「LLM 提過的候選」餵進同一套驗證，量 LLM 貢獻的差值。**不發新呼叫**。
- 殘差診斷：第一輪結束時把沒解的題按「缺哪類原語」分類，交第二輪。

**明確不做**：
- 不改生產線、不把任何規則換上 `ws/defs`、不真跑試驗（省錢只量「題數」不量「錢」）。
- 不做演化變異、不做反合一帶槽積木、不做 `$ref` 折疊搜尋（arcagi 已證表示法不加表達力）。
- 不做元層（優化「長樹的過程」）；但 `curve.jsonl` 與 meta 帳就是元層的適應度，第一輪把它定好即是鋪路。
- 不做 arcagi 端接線；只凍資料格式。
- 不碰 `proto8/feedback`（4 列，不夠當試驗場）。

## 3. 「解一題」與指標的最終定義

### 3.1 題

一題＝一個去重後的 LLM 問題實例：`{id, task, 段落 context, 提及 span, 候選實體清單, 真值, 真值等級}`。真值等級：T1／T2 為金，T3（接受的或參考同意的）為銀。

### 3.2 程式與判決

程式＝一個謂詞 AST，輸入題、輸出三者之一：某候選實體、不連、**棄權**。
- 解＝非棄權且與真值一致。
- 錯＝非棄權且與真值不一致。
- 棄權＝這題照原路問 LLM（tier 不變）。
銀真值上的「錯」另記為「爭議」，不計入錯率，報告裡分欄。

### 3.3 背答案的兩種型，分別用兩種檢查抓

| 背法 | 症狀 | 抓它的集 |
|---|---|---|
| 記住「這個名字→這個實體」 | 原題對、換個同類實體名就錯 | **合成題**：拿 KB 同類別實體名換進已知答案的題，連提及、候選清單、真值一起換，不經 LLM；每題造 n＝8 個 |
| 記住這幾個任務的標點、句式 | 訓練任務對、別的任務覆蓋 0（arknights 現況） | **holdout 任務**：既有 `holdout.txt` 4 任務，整任務不進訓練 |

### 3.4 切分

- 任務層：18 訓練任務／4 holdout 任務（沿用）。
- 兩折：訓練 18 任務按奇偶分 A／B 兩折，各在一折長、另一折驗，兩折之差＝雜訊尺。
- 合成題只造在訓練題上，用於適應度與晉升門；holdout 題不造合成，保持純淨。
- 真值：金真值可訓可驗；銀真值只訓不驗。

### 3.5 學習曲線怎麼從空基準重放

空基準＝原語表＋零規則。開跑前兩個自動檢查：（a）`ws/defs` 對空 tag 的 diff 必須乾淨（第五輪踩過兩次）；（b）原語常數白名單（§5）不得含任何語料裡的多字元字串。

一個 pass＝一個 epoch：
1. 枚舉：在訓練折上枚舉深度 ≤3 的 AST，按「訓練題上的輸出向量」去重，算適應度。
2. 晉升：候選先入 shadow，過門（§4）才 live；被既有 live 完全覆蓋者標 covered。
3. 重播：live 規則集對全部 573 題＋合成題跑一遍，得每題 解／棄權／錯，統計訓練／holdout 各自的「仍要問 LLM 題數」、錯數、覆蓋率、各 tier 殘留。
4. 結帳：每解一題收入 1000，80% 按規則分紅，房租 100，連 3 pass 零收入且 covered 者退休；meta 帳記本 pass 的 CPU 時間與枚舉節點數，token＝0。
5. 寫一列 `curve.jsonl`。

k＝5。曲線面積＝5 個 pass「訓練要問 LLM 題數」之和；達標 pass＝第一個達門檻的 pass。整條曲線要跑：空基準、折 A→B、折 B→A、全訓練→holdout 四條。

### 3.6 指標表

| 指標 | 定義 | 第一輪基準 |
|---|---|---|
| 要問 LLM 題數 | 每 pass 棄權題數，訓練／holdout 分列 | 訓練 184（v0）、168（v1） |
| 覆蓋率 | 非棄權題 ÷ 總題 | holdout 0 |
| 錯率 | 錯 ÷ 非棄權，金真值 | — |
| 合成落差 | 原題覆蓋率 − 合成題覆蓋率 | — |
| 主功能佔比 | 被解的題中原本屬 T1 以上者的比例 | — |
| 謂詞寬度 | live 規則中用到非字元類原語者的比例 | arknights 12 條：0 |
| 兩折差 | 同一指標在 A→B 與 B→A 的差 | 第五輪兩折能差 46 分 |
| 確定性 | 同輸入兩次一致率 | 規則＝1，不必量 |
| meta 成本 | CPU 秒、枚舉節點數、LLM token | 223 萬 token／輪（要降到 0） |

## 4. 驗收數字

晉升門（規則層）：shadow→live 須在訓練折上解 ≥3 題、金真值 0 錯，且在自己解的題的合成變體上 0 錯。適應度＝解數 − 5×錯數（錯比漏貴五倍）。

驗收門（第一輪整體，看全訓練→holdout 那條曲線第 5 pass）：

| # | 門檻 | 達到 | 沒達到 |
|---|---|---|---|
| G1 泛化 | holdout 覆蓋 ≥15%，錯率 ≤5% | 謂詞語言有超出標點的表達力，第二輪可加寬詞彙、接真跑 | 見下方分流 |
| G2 不背 | 合成落差 ≤10 個百分點，合成錯率 ≤5% | 不是背名字 | 禁掉能辨識實體身分的原語路徑；合成題納入適應度而非只當門 |
| G3 主功能 | 被解的題中 ≥50% 原本 T1 以上（即 205 獨特 LLM 題至少被解 ~30 題） | 動到的是主功能 | 規則只在吃 T0 題，等於換子功能；回頭看原語集是否只能描述 T0 情境 |
| G4 寬度 | live 規則 ≥50% 含非字元類原語 | 不是 arknights 標點重演 | 字元原語太好記，第二輪要降字元原語的權重或限深 |
| G5 雜訊 | holdout 改善量 ≥2×兩折差 | 數字可信 | 語料太小，先擴 runs 2–4 再下結論，不許加搜尋花樣 |
| G6 成本 | 一條 5-pass 曲線單機 ≤1 小時，LLM token＝0 | 優化器便宜 | 枚舉爆，縮深度或加型別限制，不是加機器 |

G1 沒達到的分流：
- 訓練覆蓋高（≥30%）而 holdout 低 → 背了任務的句式；槓桿是加寬謂詞詞彙，不是多跑 pass（教訓 1）。
- 訓練覆蓋也低（<10%）→ 原語缺；拿殘差診斷清單去定第二輪原語，或承認 252 題「真要 LLM」佔大宗、重定目標題集。

LLM 貢獻（資訊項，無門檻）：195 條舊規則當候選過同一套門後，holdout 覆蓋的差值 Δ。這是「LLM 逐步減少」往後要壓的數字。

第一輪不宣稱省錢；`zeroed_tasks`（整任務清零數）另欄記，預期為 0。

## 5. 元件清單

| 元件 | 一句職責 | 歸屬 |
|---|---|---|
| 題目載入器 | 讀 PG5 `semantic.json`／`request.json`，按 index 拆包、去重成 573 題，接上 `truth.jsonl` 與真值等級 | aos 專屬 |
| 任務集與切分器 | 給題清單出 train／holdout／奇偶折標籤，固定種子 | **共用核心** |
| 合成題介面 | 「給一題造 n 個同分布變體，答案已知」 | 介面共用；實作（KB 實體替換）aos 專屬 |
| 原語集 | typed 原語：左右字類別、鄰近實體類別、段落型別、別名表命中、句型、候選數與類別；常數白名單＝單字元標點類、KB 類別枚舉、小整數 | aos 專屬 |
| 符號迴歸核心 | 吃型別表與適應度回呼，在 AST 空間枚舉、行為去重、算分、covered 判定；不看題內容 | **共用核心** |
| 判決器與積木外殼 | 把 AST 跑成 實體／不連／棄權；包成 `_metainfo.json`＋`_entry`＋規則 AST，status live／shadow／covered／retired | 外殼共用；判決器 aos 專屬 |
| 離線重播器 | live 規則集 × 題集 → 每題 解／棄權／錯、tier 殘留、zeroed_tasks | aos 專屬 |
| 帳本與 meta 帳 | 收入、分紅、房租、退休；meta 帳只記不分 | **共用核心** |
| 學習曲線量具 | 寫 `curve.jsonl`，算面積、達標 pass、兩折差；空基準 diff 檢查 | **共用核心** |
| LLM 輔助接口 | `propose(殘差題) → 候選規則 AST`，結果一律重驗；第一輪實作＝讀 195 條舊規則 | 介面共用；adapter aos 專屬 |
| 殘差診斷 | 把未解題按「缺原語／缺參數來源／真要 LLM」分類 | aos 專屬（分類法可共用） |

**共用邊界（介面上交換什麼）**：核心只收發五種資料，全是 JSON——
1. 題紀錄 `{id, task, payload(不透明), truth, truth_grade, split}`；
2. 型別表 `{原語名, 參數型別, 回傳型別}` 與常數白名單；
3. 程式 AST（積木外殼內的規則）；
4. 評估結果：每題輸出向量、適應度、status；
5. `curve.jsonl` 一列與帳本一列。

核心永遠透過原語回呼碰 payload，自己不解讀；arcagi 換上網格原語與 re-arc 合成即可接。第一輪只凍這五種格式，不交付 arcagi 可執行的程式碼。

## 6. 步驤順序

1. **語料與空基準**——載入器、去重、真值接合、切分、合成題產生器；跑空基準 diff 檢查；重播現成 12 條 live 規則重現「holdout 覆蓋 0」當 sanity。產出：題集、切分檔、合成題集、空基準與 12 條規則各一條 `curve.jsonl`。
2. **原語集＋判決器＋重播器**——手寫 7 類原語與常數白名單；手寫 1 條示範規則跑完全程驗管線。產出：型別表、示範規則的重播報告。
3. **符號迴歸核心 v0**——深度 ≤3 枚舉、行為去重、適應度、covered；A→B、B→A 兩折各跑一次。產出：候選規則集、兩折報告（含假設數，供 G5 判贏家詛咒）。
4. **帳本＋曲線**——包積木、進退場、k＝5 從空重放、全訓練→holdout；對照 §4 六門。產出：四條曲線、驗收報告。
5. **LLM 離線通道＋殘差診斷**——195 條舊規則過同一套門算 Δ；未解題分類；寫第二輪建議（哪些缺口→哪些原語、要不要開真呼叫）。產出：LLM 貢獻數、殘差分類表、第二輪一頁建議。

## 7. 與 aos 原則的衝突，及方向題

### 7.1 衝突

| 原則 | 衝突在哪 | 建議處理 |
|---|---|---|
| C-52 上層不該知道下層是什麼 | 優化器讀全樹的 `semantic.json`、`steps.json`，像在偷看子層 | 優化器不是樹的上層，是「另有機制」：把重播語料定義成明確的匯出介面（記錄匣），優化器是讀匯出的旁路工具；核心更只經原語碰 payload。請隊長確認這解讀合 C-52 原意，若不合，改成由各節點主動吐出題紀錄 |
| C-84 改好的自動換上、gpt 腦改的要 Claude 審 | 演化出的規則要不要審？自動晉升跟「要審」怎麼接 | 第一輪離線、零換上，不觸發。第二輪前提議補一條：**由程式門驗過（holdout＋合成＋兩折）的規則是資料，門就是審；原語、核心、門檻是程式，照 C-84 審**。這是對原則的增補，要使用者點頭 |
| C-56 KISS | 兩折、合成、雙基準、帳本，像在為邊緣狀況加機制 | 這些不是邊緣：教訓 2、4 說少任何一個數字就是假的。KISS 用在另一邊：不做變異、不做反合一、合成只一種方法、切分只一套，枚舉深度 3 封頂 |

### 7.2 原則推不出的方向題

1. **錯判與棄權的代價比**。選項：1：1／5：1／零容忍。推薦 5：1 當適應度、晉升時合成題零錯——錯的確定性判決會沿下游傳且沒人回頭看，棄權只多問一題。
2. **T3 銀真值怎麼用**。選項：全用／只訓不驗／不用。推薦只訓不驗，holdout 報告按真值等級分欄；否則把 sol 的錯學進規則還當作泛化。
3. **第一輪 LLM 通道**。選項：完全不接／離線重放 195 條舊規則當候選／開真呼叫。推薦離線重放：不花 token，又能給出「LLM 貢獻 Δ」這個往後要壓的數。
4. **搜尋方式**。選項：純枚舉／演化變異／兩者。推薦純枚舉——教訓 1 說算力換不到泛化；枚舉解不到的題留給殘差診斷，變成第二輪的原語，而不是第二輪的變異器。
5. **元層第一輪做不做**。選項：不做／最小版（比兩套原語設定的曲線）。推薦不做，但 `curve.jsonl`＋meta 帳即元層適應度，格式第一輪就定死。
6. **共用核心放哪、誰改**。選項：aos 內／arcagi 內／第三處。推薦放 aos 內，arcagi 第一輪不接程式碼只接五種資料格式；格式變更兩邊各留一筆紀錄。路徑由隊長定。

## 8. 風險與對策

1. **語料小、多重比較贏家詛咒**（573 題、holdout 4 任務）。對策：行為去重壓假設數並在報告列出；G5 以兩折差為尺，改善量不到兩倍兩折差就不算；不夠就先擴 runs 2–4，不許加搜尋花樣。
2. **假空基準、原語偷塞題目知識**。對策：步驟 1 自動 diff；常數白名單禁多字元字串；驗收報告印出每條 live 規則用到的全部常數供人眼掃。
3. **離線重播 ≠ 真跑**（一次呼叫包 12～19 題，少一題不少一次呼叫）。對策：第一輪只宣稱題數與覆蓋，不宣稱錢；`zeroed_tasks` 另欄記；真跑留第二輪。
4. **又只換掉子功能**。對策：G3 主功能佔比與 G4 謂詞寬度兩個門直接量這件事；若規則只吃 T0 題即判失敗。
5. **優化器比省下的貴、範圍膨脹**。對策：G6 單機一小時、token 0；不做變異、反合一、`$ref` 搜尋；meta 帳每 pass 記 CPU 與節點數，往後元層就是壓這條。
