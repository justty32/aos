## 2. 五種交換格式（共用邊界，第一輪凍結）

全部是 JSON 或 JSONL，每列帶 `"format": "metaopt-<名>/1"`。

1. **題紀錄** `metaopt-q/1`
   ```json
   {"format":"metaopt-q/1","id":"aerbeita:source#/paras/2:6-14","task":"aerbeita",
    "payload":{...},"truth":"ak/events/xueshanjianglin1101","truth_grade":"gold","split":"train","fold":"A","orig_tier":"T0"}
   ```
   - `truth` 是目標 id 或 `"nolink"`。
   - `truth_grade` 取 gold／silver／none。T1、T2 算 gold，T3 算 silver。
   - `payload` 對核心不透明。aos 這邊的 payload 是 `{context, at, mention, candidates:[{target, name, class}], para_kind, kb_ref}`。
   - 合成題多兩欄：`"synth_of": <原 id>`、`"synth_k": 0..7`。
2. **型別表** `metaopt-types/1`
   ```json
   {"prims":[{"name","args":[型別...],"ret":型別,"cost":1}],"consts":{"型別":[值...]},"root":"Rule"}
   ```
3. **程式 AST** `metaopt-ast/1`：S 式陣列，形如 `["if", <Bool>, <Action>]`。積木的 `_rule.json` 是 `{"format","kind":"rule","ast":...}`。
4. **評估結果** `metaopt-eval/1`：每條規則一列，`{"rule","out":{題id: 判決|null},"solved","wrong","disputed","fitness","status"}`。`out` 只存非棄權的題。
5. **曲線列與帳列**
   - `metaopt-curve/1` 欄位：`{run, pass, asked_all, asked_nonT0, cov_fold, cov_holdout, wrong_gold, disputed, synth_gap, synth_wrong, main_share, width, live, covered, retired, hyp_count, cpu_s, nodes, llm_tok, zeroed_tasks}`。
   - `metaopt-ledger/1` 沿用 node-pool 03 的欄位：`epoch, def, kind, amount, evidence, cost`。

格式要改時，aos 與 arcagi 兩邊各記一筆（代定 D7）。

## 3. 原語、規則形狀、枚舉

### 3.1 規則形狀

規則集是一張有序表，第一條判決非 null 的就採用；全部 null＝棄權。單條規則的形狀：

```
Rule   := ["if", Bool, Action]
Action := ["link_exact"]            ; 候選裡名字跟提及完全相同的那個，沒有就 null
        | ["link_class", Class]     ; 候選裡唯一屬於 Class 的那個，不唯一就 null
        | ["nolink"]
Bool   := 原語 | ["and",B,B] | ["or",B,B] | ["not",B] | ["eq",X,X] | ["ge",Int,Int]
```

深度 ≤3 指的是 Bool 那棵樹。

### 3.2 原語表（`linker/types.json`；全是通用文字或 KB 查表，沒有 arknights 專屬詞）

| 原語 | 型別 | 意思 |
|---|---|---|
| `left_kind k` / `right_kind k` | Int→Kind | 提及左右第 k 字（k∈1..2）的字類 |
| `left_is c` / `right_is c` | Punct→Bool | 左右緊鄰字是某個標點 |
| `mention_len` | →Int | 提及字數 |
| `n_cands` | →Int | 候選數 |
| `has_class c` | Class→Bool | 候選裡有某類 |
| `exact_name` | →Bool | 有候選跟提及完全同名 |
| `inside_longer` | →Bool | 提及落在同段另一個更長的已知名字裡 |
| `neighbor_class d` | Dir→Class | 同段左（右）邊最近的其他已知提及的類，沒有就 `none` |
| `para_kind` | →PKind | 段落型別：heading、list、table、quote、body |
| `wrapped c` | Pair→Bool | 提及被某對括號或引號包住 |

**常數白名單**：

| 型別 | 值 |
|---|---|
| Kind | cjk、latin、digit、punct、space、none |
| Punct | Unicode 類別 P* 的**單一字元**，從固定表取（不從語料取） |
| Pair | 「」、『』、〈〉、《》、()、（）、[]、"" |
| Class | KB 類別名（characters、places、events，由 KB 目錄讀） |
| Dir | left、right |
| Int | 0..4 |

漢字常數一律禁。這一條直接擋掉 arknights「左邊是某字」那種背法。

**KB 的地位**（代定 D1，也是 ask-4）：KB（`PG5/ws/kb-ak2/ak/`）是系統前幾輪自己建的記憶，當作**輸入資料**，不算先驗。空樹的意思是**零規則＋上面這張原語表**。

### 3.3 枚舉與適應度（`aos_metaopt/enum.py` 的介面）

```python
enumerate_rules(types: dict, max_depth: int, eval_fn: Callable[[ast], dict[str, str|None]],
                fitness_fn: Callable[[dict], float], limit_nodes: int) -> list[dict]  # metaopt-eval/1 列
```

- 核心只呼叫 `eval_fn`（由 `linker/judge.py` 提供）拿到輸出向量，按輸出向量去重。
- 適應度：`fitness = solved − 5×wrong_gold`，在訓練折的 gold 題上算，silver 錯記成 `disputed`。
- **晉升門**：訓練折 solved ≥3、wrong_gold＝0、合成變體上 wrong＝0，才從 shadow 升 live。
- **covered**：某規則解的題集合是既有 live 的子集，就標 covered。
- `limit_nodes` 預設 200 萬，報告印實際節點數（`nodes`）與去重後的假設數（`hyp_count`）。

### 3.4 合成題（`linker/synth.py`）

- 只對 truth 是 link、而且 `exact_name` 為真的 train 題造合成。做法：從 KB 同類別隨機抽 8 個其他實體名，換掉 context 裡的提及，重查候選、重算 at，truth 換成新實體。種子固定為 0。
- nolink 題不造合成（代定 D3），G2 只量 link 這一側。
- 換完以後所有原語從新的 payload 重算，不沿用舊值。

## 4. 量法與驗收數字

**一個 pass 的流程**（`bin/run_curve`，照 02 §3.5）：
1. 枚舉；
2. 晉升；
3. 重播全題加合成；
4. 結帳；
5. 寫一列曲線。

第 p 個 pass 只拿得到前 p−1 個 pass 結束時的 live 規則，加上這個 pass 的訓練真值。為了模擬「逐 pass 看到更多真值」，訓練題按 task 分 5 批，第 p 個 pass 累積到第 p 批（代定 D2）。

**每條曲線的量法**：
- `asked_all`、`asked_nonT0`：棄權的題數，訓練與 eval 分開報；
- `cov_fold`：eval 折的非 T0 覆蓋率；
- `main_share`：被解的題裡 orig_tier≠T0 的比例；
- `width`：live 規則裡含非字元類原語（`left_is`、`right_is`、`left_kind`、`right_kind` 以外）的比例；
- `synth_gap`：原題覆蓋率減合成題覆蓋率；
- `cpu_s`：牆鐘 CPU；
- `llm_tok`：第一輪一律是 0。

**驗收**（看 foldAB 與 foldBA 第 5 pass 的平均；full 那條看 holdout）。「改 02」的是 G1、G3、G5：

| # | 門檻 | 沒達到時怎麼辦 |
|---|---|---|
| G0 管線 | `old12` 重現 holdout 覆蓋 0；`empty`（不枚舉、零規則的對照線）每 pass asked_all＝548 | 先修管線，不往下 |
| G1 泛化 | 兩折平均 cov_fold ≥15%，wrong_gold 率 ≤5%；holdout 20 題解 ≥3 題 | 照 02 §4 分流 |
| G2 不背 | synth_gap ≤10 個百分點，合成錯率 ≤5% | 同 02 |
| G3 主功能 | 兩折加起來，被解的非 T0 題 ≥30，而且 main_share ≥30% | 規則只吃 T0 題＝換子功能，回頭看原語 |
| G4 寬度 | width ≥50% | 同 02 |
| G5 雜訊 | 兩折 cov_fold 差 ≤ 兩折平均的一半；報告附 hyp_count | 擴 `~/code/playground-ak/runs/2–4` 再下結論 |
| G6 成本 | 一條 5-pass 曲線 ≤1 小時，llm_tok＝0 | 縮深度、加型別限制 |

G3 從 02 的 ≥50% 降到 30%，是因為空樹下 T0 題（292）比非 T0 多，比例會被它稀釋。絕對數 ≥30 照留。

**資訊項**（沒有門檻）：
- `llm195`：195 條舊規則當候選過同一套門以後，cov_fold 的差 Δ；
- `zeroed_tasks`。
