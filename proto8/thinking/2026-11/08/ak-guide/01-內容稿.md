## 第 2 節　六個名詞，一個比喻就懂

**圖**：六張並排卡片（手機上兩欄三列），每張一個簡單圖示＋名詞＋一句比喻：

| 名詞 | 圖示 | 比喻（卡片上那句） |
|---|---|---|
| 語料 | 書 | 圖書館裡的原書，只看不改 |
| 節點 | 一張卡 | 一張索引卡：一個地點／人物的原文＋它連到誰 |
| 庫 | 卡片櫃 | 放所有卡片的櫃子，每次放卡都用 git 記一筆 |
| 定義 | 食譜 | 一份「這個工人怎麼做事」的食譜（程式＋說明書），放在 `ws/defs/` 一夾一份 |
| 快照 | 正在煮的鍋 | 照食譜做出來、正在跑的那一份（daemon 下的實例），可以停、可以存 |
| 試驗場／kit | 工廠／外帶包 | 試驗場＝工廠本身（`~/code/playground-ak/`）；kit＝把食譜打包帶走，換一個遊戲也能用 |

**結論**：**食譜（定義）是死的、鍋（快照）是活的；工廠用食譜煮出卡片，放進櫃子（庫）。**

**摺疊「術語對照表」**（表格）：
- 節點一張卡有四個檔：`README.md`（原文）、`source.json`（逐段原文＋語料版本）、`links.json`（連到哪些卡）、`tags.json`（標籤）。
- 門牌／slug＝卡片的英文名字（例：婆山鎮 → `poshan`），腳本算、算完就凍結不改。
- prod／full：prod＝真正進庫那次花的 token；full＝prod＋各種檢查與參考也算進去。
- 指標＝(token 進＋出) ÷ (原文 bytes × 2)，使用者訂的尺，只算單個任務（一個地點／人物／事件）。越小越省；1 左右算很省。
- T0／T1／T2／T3：題目分級。T0＝規則直接答（0 token）；T1＝本機 12B 模型；T2＝terra（中階 gpt）；T3＝sol（高階 gpt）。
- hold＝這件停下等人；pending＝這一題先不連、記下來之後裁。
- 審視者 R0／R1／R2：會看報告提意見的 agent；R0 只能列疑點，R2 才能自己開藥方。

## 第 3 節　一個地點的一生（流程圖）

**圖**：橫向六步（手機上改直向），每步一個方塊，顏色照全頁規則：

1. 灰「S1 取門牌」——腳本算英文名
2. 灰「S2 存原文」——從語料指定版本逐字抄
3. 灰「S3 找提及」——掃出文中提到的所有名字
4. 綠＋藍分成上下兩半的方塊「S4 裁連結」：上半綠「四條手寫規則＋學來的規則先答（約 2/3 的題）」，下半藍「剩下的難題問 terra，太難升 sol」
5. 灰「S5 貼標籤」
6. 灰「S6 檢查格式」

S4 和 S6 之後各接一個橘色菱形「閘」：
- S4 後的閘寫「另一個模型（sol）抽查、不同意？」→ 同意：照寫；不同意：那一題丟進橘色小盒「pending（先不連，批末裁判）」，**節點照樣進庫**。
- 「整個地點看起來不對（全拒、舊連結消失）」→ 橘色停止牌「hold：這件停下，工人跑下一件」。
- S6 後 → 綠色勾「git commit 進庫」。

底下一條小字說明：「4 個工人同時跑不同地點；寫櫃子時要先拿鎖，commit 只由一個總管做。」

**結論**：**六步裡五步是腳本、不花錢；只有第四步可能叫 LLM。答不準的題寧可先不連，也不讓錯連進庫。**

**摺疊「每一步用哪個定義」**：S1 `kb_slug`、S2 `kb_store`、S3 `kb_mentions`、S4 `kb_link`（＋`kb_rules`、`linker`）、S5 `kb_tag`、S6 `kb_lint2`；整條由 `place_run` 串；多工人由 `batch_run` 管；批末 `kb_judge` 裁 pending、`kb_truth` 收真值、`kb_rules promote` 讓規則升降級。

**摺疊「四條手寫規則（第四輪加的）」**：①短名嵌在更長名字裡就丟（「耶拉」在「耶拉岡德」裡）；②後面接「語系、人、式…」當修飾語、不連（「伊比利亞語系」）；③是姓氏段 → 強制問模型＋抽查（「佩爾羅契」）；④緊貼另一個名字 → 強制問模型＋抽查（「魔王特蕾西婭」）。

**摺疊「規則怎麼學來（蒸餾）」**：把 LLM 過去答過的題整理成固定規則（例：某字左右是〈〉就不是名字），先「影子跑」（只答不算）；答滿 20 題、5 個任務、對 95% 以上才升上線；最近 50 次錯 2 次就降回影子。目前上線 4 條。使用者的遠期想法：從聰明的 LLM 蒸餾出「智能種子」，最後符號邏輯當主腦、LLM 只當出入口。
