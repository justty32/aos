讀完了。現況核心公式已確認：arcagi 的 `logcost_L` 每題記 log2(到第一解的評估數)、未解記 log2(B)、pass 0 已解題封頂 2 bits，G1 門是留一加 MDL，判準是 CRN 配對 bootstrap；v3 再加 LTO-SCF、ΔAUC_total、priors 位元帳。下面把這些收成一套 ML 語言與一條統一目標函數。

# 錘子的 ML 類比與數學骨架（給 v4）

## 一、ELI5 結論

錘子的「loss」不是答對幾題，而是**每一題要敲幾下才敲出正確程式的位元數**。猴子敲鍵盤是起點，每題都要敲滿預算 B；錘子的全部工作就是把這個數字壓下去，而壓下去的代價是錘子本身變重，重量也用位元算。所以一條式子就夠：**總位元＝錘子的描述長度＋每題搜尋位元之和**，這正是 Levin 複雜度 Kt＝|程式|＋log(時間) 的工程版，也是 Schmidhuber Speed Prior 的精神：不只要短，還要快找到。lv1 造 lv2 的意思是：lv2 在沒看過的題上，總位元更低，而且連造 lv2 花掉的評估數都算進橫軸後仍然划算。

ML 詞彙大多對得上，但有四處類比會騙人，v3 已經各踩過一次：殘差不是梯度，要反合一之後才是；旋鈕不是超參數，實測全平，容量是「長」出來的，不是「調」出來的；確定性系統沒有 seed 雜訊，抽樣單位是題不是 seed；驗證集在 NN 是免費的，在這裡每題都沒有 test 標籤，合成變體在這裡是驗證不是訓練。補法都寫在第四節，並收成 v4 修改清單。

**2. 統一目標函數**

把錘子狀態記為 H，含算子表、積木庫、priors、審查列。對一題 t、預算 B：

```
s_t(H)  = log2( min(到第一個過 G1 的程式所花評估數, B) )    未解 = log2 B
C(T; H) = |H|_bits + Σ_{t∈T} s_t(H)
|H|_bits = lib_bits + ops_bits + priors_bits + gate_bits
```

猴子是 H 為空，C＝|T|·log2 B。每加一個原語付一次 |原語| 位元，換全體題目的 Σs_t 下降。Argon 的「跨題省下位元必須大於 priors 新增位元」、E0 條 7「壓縮與解題分帳」、r08 的 2 bits 封頂，都是這條式子的局部規則。注意兩種位元不能冒名：|H| 是描述長度，Σs_t 是搜尋成本，理論白話 15 說兩者可並列不可相抵，所以帳本要分欄，但目標是和。

我們只看得到 T_seen，要的是 T_future。可操作的近似是兩折：A 折提煉的增量 ΔH 凍結後套到 B 折。

```
Ĵ(ΔH) = |ΔH|_bits − Σ_{t∈B折} [ s_t(H) − s_t(H ∪ ΔH_A) ]      Ĵ < 0 才收
```

LTO-SCF 的幾何平均加速比 ≥1.5 就是 B 折平均 Δs_t ≥0.585 bits，兩者等價，v4 建議直接用位元寫，省去倍率與位元兩套帳。每題 Δs_t 封頂 2 bits 等於 gradient clipping，防單題套利。

最外層是整條學習曲線。令 E 為累計評估數，含本體、元層、鍛造、鑄模與 LLM 稅；N(E) 為盲測解出數。

```
ΔAUC_total = ∫ N dlog10E |_{stage3} − ∫ N dlog10E |_{stage1}
```

C 與 ΔAUC 的關係：H 在未見題上的 C 越低，N(E) 曲線越陡。所以 C 是逐層的局部目標，ΔAUC_total 是唯一的頂層目標，lv2 的定義就是「由樹內節點造出、從同一空種子起跑、ΔAUC_total 為正」。硬約束三條不進目標函數：主線 H24 逐 epoch 不退、計分路徑零 LLM、真值對角矩陣。使用者意見 8 的上上下下，在這個語言裡是 N(E) 允許階梯下跌，只要面積增加；champion 單調、challenger 震盪。

**3. 每一層優化什麼**

| 層 | 自由變數 | 目標 | 讀的真值 | ML 對應 |
|---|---|---|---|---|
| 0 本體 | 一題的程式 | min s_t，受 train 全對＋留一＋MDL | train 對 | forward pass、內迴圈 |
| 1 算子 | `ops.jsonl`、積木庫 | min C(T_seen;H) 且 Ĵ<0 | L∪P 殘差、兩折 | 參數更新，ES 式 |
| 2 審查 | sieve／gate／judge 列 | sieve：min s_t 且解集不變；gate：min 誤放，誤擋≤基線；judge：max 接受對 H24 增益的預測力 | 探針、training 的 test 兩折、校準帳 | 學習型 critic，三個分開算 |
| 3 生長 | route 權重、鍛造分布、預算切分 | max d(省下位元)/dE，含延遲分潤 | 血統帳 | bandit、課程、學習率排程 |
| 4 凍結 | 無 | 無 | H24、purity、判準規則 | test set 與協定 |

層 2 的三個目標不加權：sieve 是純效率，gate 是純正確，judge 是純校準。加權就會被搜到套利路。

**4. 類比失效處與補法**

1. **殘差不是梯度。** NN 的梯度是參數空間裡帶方向與大小的向量，可沿鏈式法則回傳。錘子的殘差是一題的反例集合，沒有方向、沒有大小、不能加總。使用者說「差異收集當梯度」，正確的對應分兩步：單題殘差是 per-sample loss；跨 ≥2 題反合一後的共同簽名才是梯度。方向感來自後向見證：把目標輸出沿可逆算子往回推，這就是 target propagation，也就是 goap_cpp 的後向規劃從目標倒推前置條件。補法：CONCEPTS 寫死這兩個詞的定義，改進節點只准讀反合一後的簽名，不准讀單題殘差直接改表。

2. **更新是 ES 不是 SGD。** 每試一列算子就是一次擾動加回報，CRN seed 是共同隨機數。ES 的樣本複雜度隨維度線性長，而 r06 到 r08 旋鈕全平說明旋鈕軸上地景是平的，再多擾動也是零。補法：把預算從旋鈕軸搬到容量軸，容量移動（comb、decomp、sieve）至少七成，旋鈕移動至多三成且只在 stall 判飽和時開。

3. **超參數不重要，容量是建構出來的。** NN 固定架構調 HP；錘子的能力來自 DSL 表達力與算子數，像 NEAT 或 cascade-correlation 那樣逐步加節點。E0 條 1 與條 24 就是這件事的實測。唯一該當 HP 留著的是學習率類：每 pass 新積木上限 m、`lib_cap`、迭代加深倍率。補法：UCB 的臂全部是容量種類，不是旋鈕。

4. **驗證集在單題層級不存在，增強是驗證不是訓練。** NN 每筆樣本有標籤。ARC 每題只有 2 到 5 對 train，test 標籤看不到。所以留一是題內驗證，synth 同分布變體是「拿增強當驗證」，方向與 NN 相反，絕不能拿變體去訓練本體。鍛造爐的合成題是訓練料，之所以安全是因為生成程式已知，程式對自己的輸出必然正確，這是 SOAR 的 hindsight relabeling，也是崩潰定理裡 α>0 的接地來源。補法：合成題永不進任何判準，v3 已定；再加一條：每個被接受的算子至少帶一筆真題證據，方向題 2 已裁，v4 把它寫成 α 守則並每 epoch 印出 α＝真題證據佔比。

5. **雜訊的抽樣單位是題，不是 seed。** 確定性搜尋下 seed 方差為零，E0 條 8 的 46 分差來自換折。NN 的 SE 來自 minibatch 隨機性，這裡沒有。補法：bootstrap 與兩折都對題重抽，Q4 的兩段判準維持；meta-test 也一樣，stage 3 的錘子要在不同題池上量，CRN seed 不算 meta-test。理論白話 02 的警告直接適用：拿同任務不同 seed 當新任務，是 meta-learning 最常見的洩漏。

6. **MDL 是回溯式，未來題不買帳。** 庫學習的 MDL 壓的是已見語料，Prospective Compression 那篇證明非平穩課程下回溯式壓縮次優，E0 條 4 的 17 倍壓縮只多 1 題是同一現象。補法：兩折 Ĵ 就是前瞻式的最小代理，B 折扮演未來；再要求新原語在 B 折至少出現 2 處，Stitch 效用式 occ×size 在 2 處即為正。

7. **課程會變噪音黑洞，而且可學不等於可遷移。** 對手鍛造按失敗率加權會鎖死無解題，Argon 的 p(1−p) 已修。TAC 的發現再補一刀：局部最可學的領域常不是最可遷移的。補法：鍛造家族各記一張「修補命中對真題殘差簽名的遷移矩陣」，抽樣權重 ∝ p(1−p) × 遷移率，不只看本地命中率。

8. **評審會被學壞。** NN 的 validation 不會被模型改寫；錘子的 judge 是可搜尋列，等於 reward model 進了迴圈，崩潰定理點名學來的 verifier 同樣會崩。補法：紅皇后規則，judge 只在 epoch 邊界換，挑戰者要在凍結真值上勝出；本體與審查不同 epoch 換人，D3 已寫；judge 的接受規則第一段永遠在 `frozen.json`。

9. **信用延遲。** backprop 當步結清；縱拆的見證要兩個 epoch 後才兌現。補法是 D2 的血統帳，對應 eligibility trace 與 bucket brigade，bandit 用延遲回饋的樂觀估計。

10. **開放式與停滯的理論名字。** Van Roy 組把開放式定義為「達到同等報酬所需的新資訊量隨時間線性成長」。翻成錘子：每 epoch 在盲測上省下的位元若連續 k 個 epoch 次線性，系統就不是開放式的，這正是 Q4 的 stop＝缺原語。把這個量印出來，停滯判準就有了理論依據而不是經驗窗。

## 三、建議寫進 v4 的修改

1. **統一目標函數進 `frozen.json#/doc`**：C(T;H)＝|H|_bits＋Σs_t；兩折版 Ĵ<0 為入庫門；ΔAUC_total 為頂層。LTO-SCF 改以位元表述，門檻為 B 折平均 Δs_t ≥0.585 bits，與 1.5 倍等價。
2. **帳本三欄分開、目標取和**：`ledger.jsonl` 每列記 lib_bits、prog_bits、search_bits 與編碼版本；編碼改版後舊列不與新列排名。
3. **CONCEPTS 定義「梯度」**：單題殘差＝per-sample loss；跨 ≥2 題反合一簽名＝梯度；後向見證＝target propagation。改進節點只讀簽名。
4. **預算切分寫死起步比例**：容量移動 ≥70%、旋鈕移動 ≤30%，旋鈕臂只在 stall 判飽和時啟用；UCB 的臂一律是容量種類。
5. **α 守則**：每個轉 live 的算子至少一筆真題證據；每 epoch 印 α＝真題證據佔全部證據的比例，合成題證據永不單獨放行。
6. **meta-test 換題不換 seed**：stage 3 曲線在與 stage 1 不同的題池上量；文件明寫 CRN seed 的 meta-方差為零。
7. **鍛造權重加遷移項**：每個鍛造家族維護對真題殘差簽名的遷移矩陣，權重 ∝ p(1−p) × 遷移率，封頂 5 倍不變。
8. **新原語前瞻門**：B 折出現處 ≥2 且 Ĵ<0，取代「跨 ≥3 題壓縮檢驗」的單一回溯門。
9. **孵化槽騰位用局部競爭**：命中率墊底且行為簽名與既有列重複者才砍 TTL，簽名獨一者不砍；退休前至少 Nmin 次試用，Nmin 起步 20 並印出。
10. **judge 紅皇后規則**：只在 epoch 邊界換版，挑戰者在凍結真值上勝出才換；第一段接受規則永在凍結集；本體與審查不同 epoch 換人。
11. **開放式診斷量**：每 epoch 印盲測省下位元的累計曲線，連續 3 個 epoch 增量趨零即標 `stop`，併入 `stall.json`。
12. **算子巢狀深度 ≤2**：comb 引用 comb 最多兩層，對應層 ≤3 與巢狀技能反噬的實證。
13. **ledger 加 `side` 欄**：旋鈕與預算改動記 run，算子與審查列改動記 learn；lv2 的 `accepted` 只認 learn 側。
14. **「成績上上下下」寫成公式語言**：N(E) 允許階梯下跌，接受判準只看面積；champion 在 H24 單調，challenger 與孵化列可退。
