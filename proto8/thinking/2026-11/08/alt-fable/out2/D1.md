讀完了。重點發現有三個：arcagi 的 `seed/decomp.py` 已有「extra 葉子＋MultiSplit」機制，能直接吃多輸入的子問題；S2 支線留下的 19 題 LLM 回答本身就是逐步 DSL，可以零成本回放成軌跡當預核；文獻裡 ExeDec、Parsel、Stitch 三篇合起來正好是「先給中間狀態、分段合成、失敗段再拆、段程式反合一」的現成配方。以下是設計。

## 一、ELI5 結論

v3 的鑄模廠卡死，是因為把「一整題」當成蠟模的最小單位：一次只鑄一題，卻要三題同型才能反合一，前兩次必然白做；而 LLM 寫的整段 Python 又是一塊黑鐵，沒有縫可以下刀。解法是把最小單位改成「一步」：LLM 解題時必須用檢查點契約把解法寫成一串步驟，廠房只保留每一步前後的格子（軌跡），程式照樣銷毀。枚舉器對每一步單獨擬合，擬得出的那一步立刻變成一條孵化中的算子，不必等第二、第三個蠟模；擬不出的那一步切成「斷裂面微任務」，下次 stop 時鑄的就是這一小段，而不是整題。反合一改在「步驟程式」之間做，不同題型的題常共用同一步（裁切、重上色、鏡射），所以兩個蠟模就夠起跳，三個是加速轉正的門，不是入場門。擬合前還先用鍛造爐變體把 3 對訓練例擴成十幾對，讓每一步的擬合有足夠樣本過留一。所有這些量法都能在開 LLM 之前，先拿 S2 支線留下的 19 題步驟回放一遍，印出「現況能擬合幾步」。

## 二、設計

### 1. 死鎖的真正成因與換單位

| v3 假設 | 問題 | v4 改法 |
|---|---|---|
| 蠟模＝一題的程式軌跡 | 跨題同型少，三個同型要等十幾輪 | 蠟模＝一串步驟，反合一在**步驟程式**之間做 |
| 入庫門＝跨 ≥3 蠟模反合一 | 前兩次 stop 空轉 | 入庫門＝單段擬合過留一即 `incubating`；≥2 來源才算反合一候選；≥3 來源走快車道 |
| 程式本體立即銷毀 | 只有 3 對訓練例，單段擬合過擬合 | 銷毀前先在鍛造變體上跑出**延伸軌跡**，再銷毀 |
| 失敗整題作廢 | 違反意見 3 | 失敗段成微任務，下一次鑄模優先鑄它 |

文獻依據：ExeDec 證明「先預測下一步執行狀態、再對每一步做小 PBE」比直接生碼的組合泛化高 2 到 4 倍；Parsel 證明「分頭實作、組合驗證」把 APPS 從 14.5% 拉到 25.5%，而且瓶頸在分解品質，不在合成器；Stitch 的效用公式 `occ×size − size − k×holes` 在兩個出現處就為正，不需要三個；LiftingTraces 的 Variable Lifting 就是把軌跡裡的常數升成參數。E0 條 20 說 LLM 當求解器準、當積木作者無效，所以 LLM 只負責「切步驟並解出來」，不負責寫 seed 原語。

### 2. 檢查點契約：怎麼逼 LLM 產出可分段的程式

不限定 LLM 用 seed DSL（條 20 已實測 0 解）。LLM 用 Python 或 S2 的舊 DSL 都可以，鑄模廠是髒房，`arcagi.dsl` 可以在這裡跑，只有格子過鎖。契約由 harness 強制，不靠信任：

1. **步驟形式**：`solve(g)` 只能是 `t = Trace(g); t.step(tag, kind, fn); ...; return t.out()`。每個 `fn` 只能讀取先前具名狀態，harness 用深拷貝跑兩次比對來擋掉隱藏狀態。
2. **狀態型別**：每個狀態是 seed 型別的值：`list[list[int]]`、`list[int]`、`int`、`bool`。中間格子允許 0 到 9 以外的整數當標記色，因為 seed 原語是整數泛型。這讓「先抽數值、再套用」的題也能切段，`decomp.py` 的 extra 葉子機制正好吃多輸入子問題。
3. **步驟簽名 `kind`**，封閉集合，harness 便宜驗證：`geom`（格數不變的置換）、`recolor`（形狀不變、存在一致的逐格色映射）、`sub`（輸出是輸入的子格）、`super`（輸入是輸出的子格）、`extract`（輸出非格子）、`apply`（格子加數值得格子）、`local:r`（宣告半徑）、`other`。簽名不是語意，是告訴鎖先試哪個拆法：geom 先試 `conj_*`、recolor 先試 `map`、sub 先試 `take`／`halves`、super 先試 `append`。驗證不過的簽名當場退回。
4. **反套利三條**：每步至少在一對上改動 ≥1 格；狀態不得重現；步數 ≤12。違者退回。
5. **彈回迴圈**：每次 `check` 不只回訓練對通過率，還回**每段的擬合判決** `fit|near(score)|miss`。LLM 必須把 `miss` 段再切，最多 3 輪、總 check ≤8（沿 S2）。輪數用盡仍 `miss` 的段，進斷裂面。
6. **選配提示**：LLM 可對一步附 seed 草圖 `sketch`（帶洞），鎖拿它當模板填洞，命中率另外印出，不命中不影響流程。

人類干預走同一契約：`ctl cast <task>` 手動排鑄模請求，`ctl split <wax> <seg>` 人手切段。

### 3. 延伸軌跡：銷毀之前多榨幾對

N9 改成「程式只活在鑄模廠一次，跑完延伸軌跡即銷毀」。延伸輸入三來源，各自標 `source`：

- `dihedral`：8 個二面體變換；`perm`：非背景色置換。程式在變體上拋例外或步數不同，該變體整條丟棄。
- `rearc`：`vendor/re-arc` 對 training 題有產生器，只取它的**輸入**餵 LLM 程式。re-arc 的輸出只拿來給蠟模標 `forged_pass` 比例，不用來挑程式，不進無菌室計分，守條 17。

每段擬合的樣本數 = 訓練對 + 延伸對，封頂 16。鑄模只對 learn 集題做，holdout 永遠不鑄。

### 4. 無菌鎖的六步與資料格式

**請求** `foundry/requests/<id>.json`：

```json
{"id":"c0031","kind":"task|fracture","task":"3bd67248","seg":null,
 "pairs":[{"in":[[...]],"out":[[...]]}],"residual_hint":"最近殘差 0.83，缺 crop 類","epoch":7}
```

**蠟模** `foundry/wax/<id>.jsonl`，第一行是頭，之後一對一行：

```json
{"schema":"hammer-wax/1","request":"c0031","task":"3bd67248",
 "steps":[{"i":0,"tag":"bbox","kind":"extract","out_type":"list[int]"},
          {"i":1,"tag":"crop","kind":"apply","out_type":"list[list[int]]"},
          {"i":2,"tag":"paint","kind":"recolor","out_type":"list[list[int]]"}],
 "llm":{"model":"opus","tokens":18400,"seconds":47,"checks":5,"bounce_rounds":2},
 "forged":{"n":13,"source":{"dihedral":6,"perm":4,"rearc":3},"forged_pass":0.85}}
{"pair":"t0","states":[S0,S1,S2,S3]}
{"pair":"f3","states":[S0,S1,S2,S3]}
```

鎖的六步：

1. 讀蠟模，第 i 段的規格 = 所有 pair 的 `(states[i], states[i+1])`，含 extra 葉子（前面的具名狀態）。
2. 擬合：`arcbatch --mode seed-sub`，預算 `B0 = 20k` 節點，拆法順序由 `kind` 決定；判決 `fit`（全對且 `pool.loo_ok`）、`near`（`elem_score ≥ 0.9`，附最佳程式）、`miss`。
3. `fit` 段 → **孵化算子**：把程式裡屬於 `task_consts` 而非 `{0,1,-1}` 的整數字面升成洞（≤2 洞，沿 `compress.Params.max_holes`），`infer_sig` 給型別，去掉 size <2、恆等、庫中已有者，寫進 `ops.jsonl`：

```json
{"id":"op_0412","kind":"comb","status":"incubating","by":"foundry",
 "src":{"wax":"c0031","seg":1},"body":["take",["$h0"],["$in"]],"sig":"(int) -> list[list[int]]",
 "holes":1,"mdl_bits":9.5,"pairs_n":16,"loo":true,"evidence":{"uses_new":0,"tasks":[]},
 "ttl":3,"env_hash":"a91c","born":7}
```

   `frozen.json#/priors` 加上 `mdl_bits`。
4. 整條蠟模若每段都 `fit`，額外寫一列 `decomp`：記的是型別鏈與各段程式大小，例如 `grid -extract-> list[int] -apply-> grid, sizes [4,3]`。枚舉器之後對別題停滯時可以照這條鏈「先枚舉 ≤4 節點的 grid→list[int]，再固定它解後半」，這就是 ExeDec 子目標模型的無神經版，也是 Argon 商空間投影的具體形式。
5. `miss` 與 `near` 段 → **斷裂面**寫進 `_witness.jsonl`：

```json
{"kind":"fracture","task":"3bd67248","wax":"c0031","seg":2,"tag":"paint","sig":"recolor",
 "pairs_n":16,"tried":{"nodes":20000,"best_score":0.91,"near_prog":["map",["lam",1,["..."]],["$in"]]},
 "status":"open","born":7}
```

   斷裂面有三條出路，都不需要新 LLM 呼叫就能先走：縱拆路由在下一 epoch 用 4 倍預算重擬；鍛造爐把它當對手題型抽樣；`near_prog` 當枚舉起點。走不通才成為下一次 stop 的鑄模請求，`kind:fracture`，LLM 拿到的只有這一段的 16 對，題目小得多。這就是意見 3 的「繼續拆，拆到夠小就固化」。
6. 跨蠟模：所有蠟模的段程式加上已解題程式一起餵 `compress.candidates`。來源任務數 ≥2 的模板進 `incubating`，≥3 且 `saving` 為正者直接進影子期。

**帳** `ledger.jsonl` 每次鎖一列：`{epoch, event:"lock", wax, k, fit, near, miss, combs, decomps, fractures, fitter_nodes, llm_tax}`。`llm_tax` 沿 Argon 定 10^5 評估／次，連同 `fitter_nodes` 進 N10 的橫軸。

### 5. 量法與門檻

| 量 | 定義 | 門或用途 |
|---|---|---|
| `fit_rate` | 每蠟模 fit 段數 ／ 總段數 | 彈回迴圈的收斂指標；S2 回放預核 |
| `uses_new` | comb 出現在 src 以外任務解路的次數 | 方向題 2 的「解題證據」就是 `uses_new ≥1` |
| `pairs_n` | 段的樣本數 | <3 不擬合；留一在這些對上做 |
| `wax_idle` | 鑄了蠟模但鎖產出 0 列的 epoch 數 | 死鎖偵測，目標恆 0 |
| `fracture_closed` | 斷裂面關閉數 ／ 開啟數，逐 epoch | 意見 3 的進度量 |
| `sketch_hit` | LLM 草圖被填洞成功的比例 | 決定要不要留選配 |
| 轉正 | `uses_new ≥1` 且 `mdl_ok` 且 H24 不退 | 沿 v3，`incubating` TTL 3 epoch 轉 `dormant` |

**預核（條 12）**：S2 的 `aos/llm/responses/` 有 19 題過 train 的逐步 DSL 回答。在開任何新 LLM 呼叫前，用 `arcagi.dsl` 回放成軌跡，套第 4 節的鎖，印出「現況能擬合幾步」與每種 `kind` 的 fit_rate。若整體 `fit_rate` <20%，代表 seed 32 原語對格子段太弱，應先把彈回迴圈的細度上限放寬到 16 步，或允許 `local:r` 段用查表式 comb（表是資料，條 36 裁過）；這個決定要等數字。

**誠實的風險**：r07 資料顯示純枚舉 1M 節點只解 L16 的 2 題，物件概念要 30 多個節點。所以早期斷裂面會多、comb 會少，曲線先不會動。這符合意見 8，但要靠 `fracture_closed` 與 `uses_new` 兩條線看方向對不對，而不是看解題數。

## 三、建議寫進 v4 的修改

1. **§三.1 整段改寫**：蠟模的單位從「題」改成「步」。鎖的三步改成六步（擬合、孵化算子、decomp 鏈、斷裂面、跨蠟模反合一、記帳）。入庫門改為「單段 fit 且留一過即 incubating；≥2 來源反合一候選；≥3 來源快車道」，刪除「跨 ≥3 個蠟模才放行」。
2. **N9 修正**：程式銷毀時點改為「在鑄模廠跑完訓練對與延伸對的軌跡之後」；延伸輸入限 dihedral、色置換、re-arc 輸入，re-arc 輸出只標 `forged_pass`，不進無菌室。
3. **新增 N12 檢查點契約**：步驟形式、seed 型別狀態、八種 `kind` 簽名、反套利三條、彈回迴圈 ≤3 輪 ≤8 check、人手干預同一契約。
4. **§三.5 `ops.jsonl` 加欄**：`src{wax,seg}`、`pairs_n`、`loo`、`evidence{uses_new,tasks}`；`decomp` 列加「型別鏈與段大小」子型。
5. **§三.3 `_witness.jsonl` 加 `kind:fracture`**，欄位照第 4 節第 5 步；斷裂面是縱拆與對手鍛造的合法目標。
6. **§三.6 路由**：鑄模移出 UCB 四臂，只由 `stall=stop` 觸發；鑄模請求佇列順序為「開啟中的斷裂面優先，其次殘差最近的題」。
7. **N10 橫軸**：明寫含 `fitter_nodes` 與 `llm_tax = 10^5` 評估／次。
8. **§四 步 6 驗收改寫**：先做 S2 19 題回放預核並印 `fit_rate`；然後 ≥1 個蠟模產出 ≥1 條 `comb` 或 `fracture`，`wax_idle = 0`；`priors` 位元帳與 `llm_tax` 印出；`solve/` 的 `llm_calls` 仍 0。
9. **方向題 2 的「新解路」定義**固定為 `uses_new ≥1`，單側見證命中不算，與 Argon 建議一致。
10. **CONCEPTS 新增**：檢查點契約、延伸軌跡、孵化算子、斷裂面微任務、decomp 鏈；「蠟模」釋義改為「一題或一段的步驟狀態軌跡」。
11. **§三.7 推廣段補一句**：aos 端 kb_link 的 `observed.jsonl` 已是逐步軌跡，第 2 節契約只需加 `kind` 簽名即可套用，不必另做。
