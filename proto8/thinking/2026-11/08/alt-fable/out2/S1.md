# 錘子架構與設計體系 v1（對照 aos NORMS／CONCEPTS）

## 一、ELI5 結論

錘子不是 aos 之外的另一套系統，它就是一棵合規的 aos 資料夾樹，長在 C-74 分層的最上層（agent／kernel 那一層），用 aos-exec、daemon、信箱這些現成零件組起來。體系只需要講清三件事：**詞**（節點、角色、算子、蠟模、見證……每個詞一個意思，不跟 aos 既有名詞撞）、**層**（鑄模廠與無菌室兩間廠房、無菌室內 A～F 六層，誰能讀誰、誰能寫誰）、**生命週期**（任何東西都走同一條路：出生→孵化→轉正→固化→休眠→退休，人只按退休鍵）。對照 proto8 現有條文，大多是相容的，因為 v3 本來就踩在 C-68「資料夾＝程式」、C-84「系統自己改進函數」、N-68「成本與自報分清」上；真正要裁的衝突有五處，最硬的兩處是「`_metainfo.json` 跑的時候誰都不改」對上 Q1／Q3 想把狀態寫進去，以及「信箱是 Maildir、JSONL 不進標準」對上 `_gradients.jsonl` 當信箱用。另外 v2／v3 的規範編號 N1～N11 跟 aos 的 N-01～N-68 撞號，建議改叫 H-01～，等使用者定了再升格。

## 二、詞彙表

| 詞 | 定義（錘子體系內） | 跟 aos 既有詞的關係 |
|---|---|---|
| 錘子 | 一棵可自我改進的節點樹：本體、審查、改進三種角色都在樹內 | 一個 aos 程式（C-68），掛在 daemon 下當 proc |
| 節點 | 任何函數，資料夾形（重節點）或算子表一列（輕節點）；有契約 `io`、`born`、角色指標 | aos 名詞表的 node＝「loop 服務的資料夾」是子集；本體系用「節點」一律指上述廣義 |
| 角色 | 本體／審查／改進。不是種類，誰被別人的 `review`／`improve` 指到就扮該角色 | 對應 C-84 的「審視者」，但審視者不限 LLM |
| 種類 kind（節點） | `program`／`agent`／`generator`，由入口碰不碰 LLM 決定 | C-13 九軸的「確定性」軸 |
| 算子 | `ops.jsonl` 的一列，`kind ∈ {rewrite, decomp, comb, route, gate, sieve, judge}`，封閉集 | JSON 列＝埋在檔案裡的 table（C-72），長大就變資料夾（C-55） |
| 層 layer | 被改的東西的高度：0 積木、1 旋鈕與拆法、2 審查與改進節點、3 判準與預算政策；≤3，第 4 層只有人 | 與 C-74「分層」（誰依賴誰）是不同軸，條文一律寫 layer 不寫「層」 |
| lv | 錘子的世代：lv2＝ledger 出現 `layer:2`、`by` 為樹內節點、接受項為算子列且 LTO-SCF 過門 | 無對應，新詞 |
| epoch | 錘子根入口被 daemon 叫一次＝一個 pass＝考一次、改卷、改程式、記帳 | 一 tick 一 epoch（N-01 內部 tick）；不是牆鐘 |
| 鑄模廠 foundry | 髒廠房：LLM 與人可進、不計分、產物只有 I/O 軌跡 | 其 LLM 呼叫經 `AOS_LLM_KERNEL`（N-42），不直打 API |
| 蠟模 wax | 一題或一段的步驟狀態軌跡（D1 改為以「步」為單位），程式本體跑完延伸軌跡即銷毀 | 就是 N-68 續的 `observed.jsonl` 那種他見帳 |
| 無菌鎖 | 鑄模廠→無菌室唯一介面：擬合、孵化算子、decomp 鏈、斷裂面、反合一、記帳 | 一條單向的父子交代（N-64）：只有檔進、沒有程式進 |
| 無菌室 hammer/ | 純、計分、零 LLM 的五檔樹 | 計分域（新詞，見 §六 c） |
| 見證 witness | 縱拆時夾出的中間狀態約束（部分網格 `null`＋屬性）；`kind:fracture` 是失敗段切出的微任務 | 無對應 |
| 真值 | 四種：真題 train、盲測 H24、鍛造爐合成、校準帳；誰能讀哪種由隔離矩陣定 | holdout 連 agent 都不准讀（E0 條 9） |
| 鍛造爐 forge | 每 epoch 重抽的合成題與誘餌錯解，供改進器與守門訓練，永不計分 | aos 端＝實體替換造同分布變體 |
| 孵化 incubating | 算子有時間與預算、沒有分數的狀態；TTL 到期轉休眠 | C-84「容忍短暫退步」在錘子裡落在這一態 |
| 血統 lineage | 路線→見證→算子→程式的有向鏈，分紅沿鏈回流；只有引擎可寫 | node-pool 的「先報銷再分紅加房租」同一本帳 |
| 園區 park | 按型別簽章與共用關係自己長出來的節點分群，各有出口表、帳、索引、`C_park` 容量 | ≈ C-47 11-07 註「一個隊伍一個 llm_kernel」的隊伍 |
| 凍結集 frozen.json | 任何層都不可寫的：H24 題組、purity、三判準第一段、layer 上限、priors、truth_matrix、kind 集合 | 類比 C-64：用檔案權限讓它只有人能寫 |
| 帳 ledger | 一處寫的權威紀錄；節點內只放衍生快照 | 對應 node-pool `pool/ledger.jsonl` 只追加 |
| 干預 | 人對樹說話的三招：改活檔、投信、`ctl`；pass 邊界生效、帳留 `by:human` | 信走 N-16 信箱；活檔照 N-05 寫法 |

## 三、分層模型與層間介面

```
鑄模廠 foundry/   ──無菌鎖（唯一跨廠介面，單向）──▶  無菌室 hammer/
                                                     A 身體  B 真值  C 審查算子
                                                     D 算子  E 生長  F 經濟排程
```

| 層 | 管什麼 | 對外介面（檔） | 讀寫方向 | 借用的 aos 機制 |
|---|---|---|---|---|
| A 身體 | 節點身分、入口、契約 | `_metainfo.json`、`_entry`、`interfaces.json`、`state.json` | 被 B～F 讀，自己只寫 `state.json` | C-68 入口、N-57 六環境變數、N-13 窗、C-51 介面宣告 |
| B 真值 | 四種真值、鍛造爐、見證 | `truth/{train,forge,cal}`、`_witness.jsonl` | 只被 C／D 讀；見證只父節點可寫 | 隔離矩陣是 C-64「借 Linux 權限」的用法 |
| C 審查算子 | gate／sieve／judge 三種列 | `frozen.json`、`ops.jsonl` 審查列、`hammer-feat/1` 特徵表 | 裁 D；特徵由審查方抽取，本體不得自報 | N-68「設計者估值與自報分清」同向 |
| D 算子 | 四種本體列、孵化狀態、血統 | `ops.jsonl`、`ledger.jsonl` | 被 C 裁、被 E 排 | C-72 JSON 列＝table |
| E 生長 | epoch、停滯、路線、園區 | `epochs/<n>/`、`stall.json`、`parks/<p>/` | 排 D 何時何處跑 | 一 tick 一 epoch（N-01） |
| F 經濟排程 | 錢、CPU 份額、worker 限額 | `sched/`、`pool/` | 給 E 資源；r10 | 份額＝daemon 列的 `limits`（C-64 11-05 註）；若轉交 daemon 掛 proc 則算 kernel（C-47 加嚴），in-process worker 不算 |

**層間鐵則**：沒有一層能寫上一層的規則；每層只看對方的公開檔（C-52「上層不該知道下層是什麼」在這裡＝只看介面檔、不讀實作）。**身體契約**：`_entry` stdin JSONL 進、stdout JSONL 出，錯退 1、stderr 一行（N-43 只約束 aos 自己的程式，錘子節點**自願**照做，寫進 H 規範而非改 N-43）；in-process 快路徑 import 同一函數，`aos-exec` 單跑任一節點輸出逐位同。

**雙視圖**（Argon 審 v3 B.2）：五檔是權威；每 pass 原子投影 `live/{parks,stalls}/_status.json` 與 `events.jsonl`。前者是窗（N-14：只看最新那份的固定檔，rename 原子），後者是 proc 自訂的串流檔（N-13 名字格式自訂、不進標準）。

## 四、生命週期

一條狀態機，所有東西都走：

```
出生 ──▶ 孵化 ──▶ 轉正 ──▶ 固化
  │        │        │        │
  │        ▼        ▼        ▼
  └────▶ 休眠 ◀────┴────────┘      休眠 ──(人按)──▶ 退休 ──(revive)──▶ 孵化
           ▲
     env_hash 變動時自動回孵化
```

| 態 | 進入條件 | 期間的權利 | 離開 | 帳上一列 |
|---|---|---|---|---|
| 出生 | 由引擎（`by:enum`）、無菌鎖（`by:foundry`）、拆分（`by:<節點路徑>`）或人（`by:human`）產生；`born.by` 由判準程式填，不由提案者自填 | 無 | 立即進孵化 | `born` |
| 孵化 | 過單段留一、或蒸餾簽名 ≥3 次 | 有預算、有影子套用、可進子搜尋；**零分數、零即時現金**；逐次減半，探針簽名獨一者豁免；單一來源配額 ≤50% | 轉正或 TTL 到期休眠 | `incubate` |
| 轉正 live | `uses_new ≥1`（真題新解路）∧ MDL 過 ∧ H24 不退；分支容量不足時與汰出列**成對原子提交**；本體列與審查列不同 epoch 轉正，或採 Argon 的影子伴隨編譯 | 參與計分、領分紅、付房租 | 固化、休眠（二分或容量騰位） | `promote`／`blame` |
| 固化 | 同一引擎換真值：節點 `impl.level` agent→tool→prog；判準是「不變差＋省成本」，不要求顯著進步；進度量 EPC、`llm_share` | 帶 `guard.json` 前提檢查，棄權自動走 `impl.prev` | 棄權率 >20% 或錯率升 5 點自動退一級（`thaw`） | `freeze`／`thaw`／`royalty` |
| 休眠 dormant | TTL 到期、blame 責任 >50%、容量騰位 | 不刪、不計分、不付房租；索引保留 | `env_hash` 變動自動回孵化；人 revive | `dormant` |
| 退休 | 錢包連 `zero_epochs` 為 0 → 只列建議；**人按**才搬 `retired/` | 索引標 `cold` | revive 撥起始金回孵化 | `retire`／`revive_seed` |

**三種節點的差異**只在三處：`program` 全走上表；`agent` 多一個 `queue/`、不進 worker 池、同時 ≤2 隻，產出只寫 `candidate/`；`generator` 的產物另記 `lineage`。**算子列→資料夾**的成長照 C-55 與待定「函數成長」0～5 級：一列裝不下（要帶 `guard.json`、`versions/`、信箱）就長成資料夾，原列變 `_metainfo.json`。**園區**另有四個動作：拆分（live > cap 連 2 epoch）、合併（跨區引用 > 區內 50% 連 3 epoch 或皆 <16）、釘住、凍結；都是 layer-1 動作、過 CRN 判準、`born.by` 記 `improve/zoning`。**蠟模**只有一生：請求→鑄→延伸軌跡→鎖→銷毀，請求佇列「開啟中的斷裂面優先」。

## 五、不變式

1. **I-真值隔離**：`frozen.json#/truth_matrix` 對角線以外的讀取＝違規；盲測任何節點、任何 agent 不可讀；`solved` 永遠＝`test_ok`，守門只影響交卷。
2. **I-無菌**：無菌室 `llm_calls`＝0；LLM 與人的產物只能以 I/O 軌跡進來；進來的先驗位元記 `priors`。
3. **I-全成本**：任何學習曲線橫軸＝本體＋元層＋鍛造爐＋鑄模廠枚舉＋LLM 稅（10⁵ 評估／次）。
4. **I-分帳**：解題帳與壓縮帳不相加，排序解題優先；壓縮每題封頂 2 bits。
5. **I-帳一處寫**：`ledger.jsonl` 唯一權威；`lineage`、`by` 只有引擎可寫；節點內只放衍生快照。
6. **I-凍結**：凍結集任何層不可寫；改了判準的進步一律無效。
7. **I-層間單向**：A 被讀不寫、B 只被 C／D 讀、C 裁 D、E 排 D、F 給 E；沒有一層寫上一層規則。
8. **I-不刪**：狀態只往休眠走，刪除只有人按退休；舊版留 `impl.prev`。
9. **I-干預留痕**：人的三招都在 pass 邊界生效、帳留 `by:human`、不分紅。
10. **I-門檻預核**：任何門上線前印「現況能過幾條、一題影響幾個百分點」。
11. **I-自報不當證據**：本體自報欄位不得當審查特徵；設計者估值與實測他見分開記（N-68）。
12. **I-kind 封閉**：算子 `kind` 集合列在 `frozen.json`；加一種 kind 要走條文，不能由搜尋長出（KISS 最後原則 C-56 的減法鉤子）。

## 六、對應 aos NORMS／CONCEPTS

**相容處**（直接引用，不另立條）：C-68／C-71／C-72 節點＝資料夾＝table，算子列＝JSON 列；C-55 與待定「函數成長」給了列→資料夾的成長規則；C-48 加 `io`、`review`、`improve`、`born` 等 key 合法；C-84 自動換上／退回／容忍短暫退步／審視者層疊／正在跑的不換＝轉正、休眠、孵化、layer ≤3、pass 邊界生效；C-22 能寫死的換程式、專精窄領域＝固化路徑與園區；C-47 11-07 註「成千上萬 agent、同時只亮一小部分」＝園區與排程前提；N-68 成本三維與「自報分清」＝不變式 11；N-68 續 `observed.jsonl`＝蠟模的現成格式；N-16 信箱、queue＝干預通道；N-14 窗＝`_status.json`；N-05 暫存檔改名＝五檔寫法；N-64 父子交代＝管線契約與無菌鎖；C-52 每層只管自己＝層間單向；C-83／N-67 可遷移性＝位址相對 `ws`、`env_hash` 不含絕對路徑；node-pool 03 的報銷、分紅、房租、人按退休＝血統帳與退休態。

**衝突處**（要裁）：

|---|---|---|---|---|

| c | C-84：審視者權限一步步放到「自己寫程式」 | N9 無菌鎖：LLM 與人的程式銷毀、只留軌跡 | 範圍衝突 | 新概念「計分域」：無菌室是計分域守 N9；aos 一般 agent 樹非計分域照 C-84。兩條各管一域，條文互引 |

## 七、建議寫進 v4 的修改

1. **§三.0 改寫為本篇 §三的六層表**，每層加「借用的 aos 機制」欄；規範編號 N1～N11 全部改 **H-01～H-11**，v4 起不再用 N 字頭，免與 N-01～N-68 撞。
2. **新增 §三.0b 詞彙表**（本篇 §二）與 **§三.0c 生命週期狀態機**（本篇 §四），`ops.jsonl` 的 `status` 擴成 `incubating|live|dormant|retired`，節點 `impl.level` 併入同一張圖。
3. **H-12 計分域**：「無菌室是計分域；計分域內 H-09 無菌鎖優先於 C-84 的審視者寫程式權限；計分域外照 C-84。」
4. **H-13 宣告與狀態分離**（解衝突 a）：「`_metainfo.json` 只放設計者宣告；`status`、`impl`、`lineage`、`env_hash` 等跑動狀態放節點 `state.json` 或 ops 列。」Q1 的 JSON 範例同步改。
