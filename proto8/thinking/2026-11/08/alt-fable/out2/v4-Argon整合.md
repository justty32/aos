# 錘子設計圖 v4（整合定稿）

## 一、ELI5 結論

v3 把廠房切成「髒鑄模廠」與「純無菌室」，解開了破冰與純度的死結，但留下一把**不會長大的固定鐵錘**：蠟模一次鑄整題卻要湊三題才放行（死鎖）、審查與改進寫死在 Python 裡不會演化、扁平算子表一旦擴張就撐爆搜尋分支、還拿盲測集 `H24` 每輪守門造成隱性洩漏。

v4 把整套系統收斂成一棵**自相似的活資料夾樹**：解題積木、園區夾具／守門（審查）、樹差修補器（改進）全都是同一種帶 `(body, review, improve)` 契約的函數節點；輕量時住算子表一列，發熱或帶 LLM 時自動長成實體資料夾（可 `cd` 巡檢、可投 `inbox/` 干預）。全樹流通單一反向貨幣——**反合一殘差簽名**（符號系統的梯度）：同一支暴力枚舉＋反合一母機，吃網格殘差就長 2D 算子、吃錯解特徵就長審查門、吃歷史修補軌跡就長改進器，真正做到「Lv1 錘子敲出 Lv2 錘子」。卡住時看殘差熵自動雙向生長：職責混雜就**往下拆細並固化成純程式**（`agent → tool → prog`）；節點已極簡卻修不動就**往上長二階改進器**。計分採**園區條件 Levin 位元帳**與**三池隔離**（`train` 學習、輪替 `canary` 搭棘輪包絡線容忍短期重構震盪、`H24` 絕對盲測零回流）。

## 三、完整設計

### 0. 往上收斂與往外發散

- **往上收斂（一個單元、一種梯度、一條公式）**：
  1. **同構三指針節點**：本體、審查、改進皆為 `(In -> Out)` 純契約函數，附 `(review_ref, improve_ref)` 與成本層級 `tier ∈ {agent, tool, prog}`。
  2. **結構化殘差梯度**：單題誤差只是 loss；跨 ≥2 例對差異做反合一後的簽名 `diff_sig` 才是梯度。同一支枚舉＋反合一引擎對網格殘差長 `comb`、對特徵殘差長 `sieve/gate`、對 `(near_ast, diff_sig) -> fit_ast` 歷史帳長 `xform` 改進器。
  3. **園區條件 Levin 目標函數**：令錘子 $H = \{H_p\}$ 按園區分群，單題條件成本與雙折前瞻判準為：
     $$c_t(H) = r_t(x_t \to p) + |prog_t|_{H_p} + s_t(t \mid H_p), \quad C(T; H) = \sum_p |H_p|_{\text{bits}} + \sum_{t \in T} c_t(H)$$
     $$\hat{J}(\Delta H) = |\Delta H|_{\text{bits}} - \sum_{t \in B\text{折}} \text{clip}\big(c_t(H) - c_t(H \cup \Delta H_A)\big) < 0$$
     其中 $s_t = \log_2 \min(\text{evals}_t, B)$。**雙段封頂 `clip`**：基線淺題（$s_t < 6$）封頂 $2\text{ bits}$ 防刷淺題；深題與新解超時題（$s_t \ge 10$）放寬至 $0.5\log_2 B$，保護攻克難題的深層算子。頂層唯一指標為全等效成本面積增益（計入 $E_{\text{eff}} = E_{\text{solve}} + E_{\text{meta}} + E_{\text{forge}} + E_{\text{foundry}} + 10^5 N_{\text{llm}}$）：
     $$\Delta\text{AUC}_{\text{total}} = \int N_{\text{H24}}\, d\log_{10} E_{\text{eff}}\Big|_{\text{stage3}} - \int N_{\text{H24}}\, d\log_{10} E_{\text{eff}}\Big|_{\text{stage1}}$$
     當節點沿 `agent → tool → prog` 固化，即使解題數 $N$ 不變，$E_{\text{eff}}$ 驟降仍直接推升 $\Delta\text{AUC}_{\text{total}}$。

- **往外發散（三個跨模組湧現閉環）**：
  1. **廢熱三聯產（Cogeneration）**：搜尋期的半對錯解經 SOAR 重標記免費變成鍛造爐合成題；合成題上「過 train 卻錯隱藏對」的破損程式免費變成 `gate` 的**零成本標記誘餌**（徹底解決 195 題僅 20 題誤放的小樣本飢餓）；而 `gate` 挖出的守恆規律 `break_L` 又直接前移成展開前的 O(1) 園區夾具 `jig`！
  2. **跨縫商空間雙向會師（Quotient Seam Meet-in-the-Middle）**：對蠟模斷裂縫 `(S_{i-1} -> [S_i] -> S_{i+1})`，不硬對齊 LLM 隨手編碼的像素格 `S_i`，改對齊其商空間投影 $\pi(S_i) = (\text{shape}, \text{fg\_mask}, \text{obj\_cnt})$，自動繞過 Python 扭曲標記色，免重叫 LLM。
  3. **元軌跡自舉編譯（Meta-Trace Compilation）**：把錘子自己的 `ledger.jsonl` 與 `_residuals.jsonl` 當作 PBE 真值表——用慢速枚舉或鑄模曾修好的 `(錯AST, diff_sig) -> 對AST` 訓練出毫秒級確定性修補列 `xform`，用歷史成功掛載紀錄訓練出園區門房 `gate(pre)`，讓「錘子造錘子」落地為同一引擎的自我編譯。

### 1. 鑄模廠、無菌鎖與白箱結晶槽（意見 3）

1. **觸發與請求佇列**：移出常規 bandit 臂。僅當園區雙向分岔皆無進展時開啟，優先鑄 `_witness.jsonl` 中開啟的 `fracture` 微任務，其次按殘差指紋聚類鑄同型未解 `train` 題（≤2 並行，經 `AOS_LLM_KERNEL`）。
2. **零儀式步驟與共變延伸**：LLM 在髒房寫 `t.step(tag, fn)`，過全部 train 對且通過本地反套利（每步改 ≥1 格、無狀態重現、步數 ≤12）即收，**不手填 `kind`、不彈回燒稅**。銷毀前先跑**共變性守門**：僅對在 train 對滿足 $P(g\cdot x)=\phi_g(y)$ 的合法變換子群 $G_{\text{valid}}$（及型別合法的 `re-arc` 輸入）展開延伸軌跡，封頂 16 對，隨即銷毀 Python 本體。
3. **無菌鎖六步與雙軌白箱結晶**：
   - 鎖內 1ms 探針標記 `auto_kinds` 決定拆法順序，以 `seed-sub`（$B_0=2\times 10^4$）逐段擬合：前序具名狀態優先綁資料流葉子 `$e0`，其餘任務常數升洞（≤2 洞）。
   - `fit` 且過留一 → 單段直接入 `ops.jsonl` `status:incubating`，記 `priors` 位元；整鏈 `fit` 另寫一列型別鏈 `decomp`。
   - `near/miss` 段 → 連同前一段組**跨縫視窗 `seam`** 寫入 `_witness.jsonl`（`kind:fracture`、`info_bits >= 8`），交無菌室縱拆與商空間會師續攻。
   - **白箱結晶槽**：非計分域的 `agent/tool` 執行自動錄入 `crystal_buf.jsonl`，背景跑符號回歸結晶為帶 `guard.json` 的 `prog`（棄權率 >20% 自動 `thaw` 退回上一級）；若鑄模廠直接提交僅含 `frozen.json#/dsl_primitives` 的純白箱 AST，須全額扣繳 $\text{Bits}_{\text{AST}}$ 先驗稅且過雙折 $\hat{J}<0$ 方准孵化。計分模式物理斷開 `AOS_LLM_KERNEL`，只跑 `prog`。

### 2. 真值與金髮女孩鍛造爐（廢熱三聯產）

每輪產出三源合成料（永不計分、每輪重抽）：① **單步破損**（餵重寫與 `xform`，其中過全 train 但錯隱藏對者自動轉存為守門**誘餌錯解**）；② **橋接挖空**（過輸出熵 $\ge 4\text{ bits}$ 且跨對非常數之非退化門，餵縱拆與 `decomp`）；③ **SOAR 錯解重標記**（wake 期枚舉出的高分錯解對自身輸出必然正確，零成本轉合成題）。
- **課程抽樣權重**：$w_k \propto \hat{p}_k(1-\hat{p}_k) \times \text{Jaccard}(\text{ForgeSig}_k, \text{UnsolvedTrainSig})$，封頂 5 倍——自動鎖定「瀕臨突破且殘差簽名貼近真題」的金髮女孩區，避開不可解黑洞與稀疏矩陣雜訊。

### 3. 同構算子、指紋桶與商空間園區（意見 1、6）

- **算子表與八種 `kind`**：r09 維持 7 種（`comb`［含 `compose` 與高頻槽 `specialize`］、`decomp`、`rewrite`、`route`、`sieve`、`gate`［分 `stage:"pre|post"`］、`judge`）；r10 解鎖第 8 種 `xform`（樹差反合一合成之特定替換改進器）。造詞採 **Stitch 式 top-down 上界剪枝**，巢狀深度受控。
- **32 探針 `uint64` 觀測指紋桶**：以 32 張微型標準網格求值雜湊撞桶，毫秒級自動挖掘等價律（寫入 `sieve`）並在 `enum.py` 展開時零評估剪除 70%+ 冗餘分支，免引入重型多步 e-graph。
- **商空間投影與園區分流**：任何算子誕生時自動標記對 `(proj_shape, proj_palette, proj_fg_mask)` 的同態不變性；縱拆先在二值骨架商空間搜幾何前半 $H$，再固定 $H$ 搜填色後半 $G$。園區入口由 `gate(stage:"pre")`（r10 升為園區 `jig`）計算 <0.1ms 輸入不變量，只掛載 Top-2 相容園區算子，壓住分支因子（目標 `park_selectivity < 0.2`）。

### 4. 進化審查與防串通（意見 2、6）

- **三階分工**：① `sieve`（探針零反例＋10% 題目影子抽查 **0 掉題**，遇反例即休眠記 `refuted_by`）；② 前置夾具 `gate(pre)`（真值＝歷史成功解路與固定預算 $B$ 下淨解題增益 $\Delta\text{Solved}@B \ge +1$）；③ 終檢守門 `gate(post)`（只讀審查方自抽之 `hammer-feat/1` 與規律破壞特徵 `break_L`，禁讀本體自報欄；在 `train` 雙折＋誘餌集上最大化 $\Delta U = \Delta\text{BlockedWrong} - 3\Delta\text{BlockedRight} \ge +2$）。
- **防 Goodhart 四鎖**：① `truth_matrix` 對角隔離，`solved` 永遠等於 `test_ok`，守門只影響交卷；② 廢除奇偶輪裸奔鎖，改**影子伴隨編譯＋`tx_bundle` 同輪成對原子切換**；③ 誘餌錯解防放水；④ 上線前 `witness.py` 與評審器必過 metamorphic 等價／破壞變形自測。

### 5. 血統帳、殘差棘輪託管與差集軟節流

- **反事實分紅與固化退稅**：真題新解付價沿 `lineage` 回流，算子權重按拿掉該列後搜尋倍增對數 $w_i = \min(4, \log_2(\text{evals}_{-i}/\text{evals}))$ 計算（恆等包裝 $w_i=0$）。元節點 $M$ 將高成本節點 $A$ 固化為純程式 $B$ 時，領取省成本比例之**固化退稅 Royalty**，跨固化邊界傳導率 `0.9`。解題帳與位元帳嚴格分立，排序解題優先。
- **殘差棘輪託管（Ratchet Escrow）**：每道未解題維護留一驗證下歷史最低殘差位元 $D_q^*$；壓低水位即發一次性託管積分 $\text{escrow}=(D_q^*-D_q')/D_{q,0}$ 並單調鎖死新 $D_q^*$。常規三臂（縱拆、橫拆、睡眠造詞）各領 20% 底薪，餘 40% 按 `solve_div + 0.3 * live_escrow` 加探索項撥款。孵化槽採逐次減半，觸發域探針簽名獨一者豁免。
- **容量門與軟節流**：活表設分支容量上限（r09 全域 `C_evals=25%`，r10 改分園區 `C_park`），超額須與最低淨值列成對騰位。退步時先查單列邊際帳 `marginal`，直接調高拖累列展開成本先驗 $\Delta c_i$ 平滑節流；單列惡化佔退幅 >50% 才留一轉 `dormant`。

### 6. 停滯雙向分岔與重構債券（意見 4、8）

節點或園區連 3 輪 $\Delta D_q^* = 0$（或有 `escrow` 無真解）時，讀取 `_residuals.jsonl` 計算殘差分群熵 $H_{\text{cid}}$ 與**分岔指數** $\text{BDI} = H_{\text{cid}} \cdot \log_2(1 + |\text{AST}|)$：
- **往下拆（`SPLIT_DOWN`，$\text{BDI} > \theta$）**：殘差多峰或 AST 肥大 → 依雙峰 `diff_sig` 分裂（高勝率子集直接固化為純程式並掛專屬 `gate(pre)`），或沿商空間見證縱拆為子節點。
- **往上長（`SPAWN_UP`，$\text{BDI} \le \theta$）**：節點已精簡而殘差單峰卡死 → 拉出二階節點對歷史修補軌跡跑**樹編輯反合一**合成新 `xform` 改進器；仍無解才送鑄模廠破冰。
- **棘輪包絡線與重構債券**：分離歷史最佳快照 `BEST` 與工作頭 `head`。當拆分或重構大幅降低描述長度（$\Delta\text{MDL} < -B$），簽發 `bond` 容許 `head` 在 `canary` 池透支小幅退步達 $W=3$ 輪；到期淨值創新高即鎖定新錨點，逾期未還清則按 `bond_id` 整包原子回滾至 `BEST`。

## 六、要使用者裁的方向題（最多 5 題）

1. **`H24` 改「0-bit 絕對盲測金庫」並切 `canary` 折配 3-epoch 棘輪守門，還是維持 v3「`H24` 逐輪不退硬門檻」？**
   - **推薦**：改 `H24` 純盲測＋`canary` 棘輪守門。
   - **後果**：徹底堵住每輪拿 `H24` 篩算子造成的 1-bit 適應性洩漏，且允許主線「先蹲後跳」完成拆解重構；代價是 `train` 池少 24 題（約 6%），且與 v3 裁定 5 字面不同需拍板換軌。若維持原制，`H24` 實質退化為驗證集，且 U 型結構升級會被單題（4.17%）波動卡死。
2. **無菌鎖是否允許鑄模廠／結晶槽提交「繳清全額 AST MDL 先驗稅的純白箱 seed AST」，還是只准過純 I/O 軌跡？**
   - **推薦**：允許繳清全額先驗稅且過雙折 $\hat{J}<0$ 的純 `seed` AST 進孵化（仍禁任何 Python 與任務常數）。
   - **後果**：真正打通意見 3「`agent → tool → prog` 漸進拆小固化」，免去交了 $10^5$ LLM 稅還要在 >20 節點處瞎猜重湊；若只准過純 I/O 軌跡，純度說法最極端簡單，但逾 15 節點的複合步驟在 $B_0=2\times 10^4$ 下幾乎必進斷裂面，固化速度慢數倍。
3. **園區前置夾具 `gate(pre)/jig` 要採「同預算淨解題增益 $\Delta\text{Solved}@B \ge +1$」，還是比照 `sieve` 強制 0 掉題？**
   - **推薦**：採同預算淨增益 $\ge +1$（純代數等價 `sieve` 仍嚴守 0 掉題）。
   - **後果**：允許剪掉 80% 無關分支以換取深層多解 3～4 道新題（落實意見 1、8），個別漏網舊題由園區回退兜底；若強制前置路由也 0 掉題，任何條件剪枝都會被單一怪題一票否決，節點破百後搜尋必退化。
4. **S1 衝突 b（`_gradients.jsonl` 命名）與人類 `inbox/` 干預如何記帳？**
   - **推薦**：改名 `_grad_log.jsonl`（不改格式），互動干預全走 Maildir `inbox/`；人類提示按 AST 長度計入 `priors` 的 `human_prior_bits`（不分紅），跑 lv2 自舉考核時設 `inbox_lock=true`。
   - **後果**：完全合規 `N-16` 信箱標準，平時方便你 `cd` 進去隨時指點，考核時又能切出無爭議的零干預自舉曲線；代價是 `node-pool` 既有文件需改一處檔名。
