fable 抓出 `seed/decomp.py` 的 `extra` 葉子機制與「S2 支線 19 題零成本回放預核」非常精準，將蠟模最小單位從「整題」改為「單步」也確實解開了 v3 的冷啟動死鎖。但作為共同設計者，對照使用者 8 條原話，D1 目前只設計了**「切碎鐵劍的流水線」**，還沒畫出**「錘子造錘子」的母機結構**。

## (A) 審查：盲點、原意偏離、過保守與過複雜

### 1. 與使用者原意的三大偏離
* **只往下拆「劍片」，沒往上鑄「錘頭」（偏離意見 4、5、6）**：使用者明確要求 Lv1 錘子造 Lv2 錘子，停滯時除了往下拆，還能**往上長出「改進這個改進程式的程式」**，並用暴力模式匹配優化「審查、改進與本體全部節點」。D1 只往下產出領域算子（`ops.jsonl` 劍片），而負責擬合、拆法排序、留一審查與路由的「無菌鎖」全是寫死的 Python harness——錘子本身不會演化。
* **缺「產業園區」分流，必撞枚舉分支爆炸（偏離意見 1）**：單段過留一就進全域 `ops.jsonl` 與 `priors`，當孵化算子破百時，每次 `seed-sub` 的 `B0 = 20k` 預算會被無關算子嚴重稀釋，搜尋深度反而倒退。使用者已預警「節點池會膨脹」，解法是分園區掛載，而非平坦入庫。
* **活體 `aos` 樹退化成靜態批次檔（偏離意見 1、7）**：使用者要的是「非 LLM 函數本身就是活節點」，可 `cd` 進目錄看運作、發訊息干預；D1 只給了離線 JSONL 與 `ctl cast/split` 兩支 CLI，沒有活樹執行期結構。

### 2. 三個技術盲點
* **延伸軌跡的「偽合法毒樣本」**：§2.3 規定 `dihedral` 與 `perm` 變體只要「不拋例外且步數相同」就收錄。但含**重力方向、讀序或特定語意色**的題目，旋轉或換色後跑原 Python 程式**常不會拋錯且步數相同，卻產出違反題意的假軌跡**（例如旋轉後重力仍往下拉、寫死 `c==2` 變空轉），直接污染 16 對樣本，害正確步驟假性 `miss`。
* **斷裂面的「壞介面焊死」**：第 $i$ 段 `miss` 常不是該段太難，而是第 $i-1$ 段選了對 Python 順手、對 `seed` 極扭曲的中間態 $S_i$（如隨意編碼標記色）。把 `(S_i, S_{i+1})` 鎖死成微任務等於焊死壞邊界，再往下拆也無解。
* **常數升洞與資料流混線**：把 `task_consts` 一律升成自由洞 `$h0`，每多一洞就乘開一層常數搜尋；若該常數其實對應前序 `extract` 的輸出，應優先綁定型別葉子 `$e0`（資料流連線）而非開盲洞。

### 3. 過度複雜與過度保守
* **過度複雜——事前 `kind` 填表與彈回稅**：`geom`、`recolor`、`sub`、`super`、`extract` 全是 `(S_i, S_{i+1})` 軌跡的**後驗可判定性質**，鎖花 1ms 就能算完。逼 LLM 手填封閉 `kind` 並彈回重跑 3 輪 8 次 check，既違反條 20（干擾 LLM 專心解題），又白燒 `llm_tax`（$10^5$ 評估／次）。
* **過度保守——`H24 不退` 硬門檻**：轉正要求單輪 `H24 不退` 直接違背**意見 8**（上下震盪正常，重點是趨勢）。固定預算下新算子加入必會擠壓邊際題配額，短期掉 1 題卻打開新題型很常見，硬門檻會錯殺關鍵基建。

## (B) Argon 共同提案：母機園區、雙向鬆弛與具體落地

**核心類比**：D1 像翻砂鑄造「零件毛坯（`comb`）」，我們要補上**「晶圓廠製程園區（Fab Bays）＋ 自演化工具機母機（Gates & Tactics）」**——讓審查器、改進器與解題算子共用同一套節點結構，全都能被暴力模式匹配優化並固化成純程式。

### 1. 往上長：用暴力模式匹配鑄造「審查門」與「修補錘」（落實意見 2、3、4、6）
把元優化對象變成同樣可做小 PBE 的資料節點，與 `op` 算子並存：
* **`gate`（低成本審查／園區守門程式）**：檢查過去 $N$ 次呼叫命中率（意見 2），並對 `(in, out)` 計算 <0.1ms 的廉價不變量向量（維度比、色集合差、連通塊差、對稱群），決定該段是否載入本園區算子。直接對歷史成功解路跑小型布林決策樹枚舉，即可自動更新守門規則。
* **`tactic`（低成本特定替換改進程式）**：收集 epoch 內的差異對 `(near_prog, residual_grid) -> fit_prog`，在 AST 重寫空間跑暴力模式匹配，合成無 LLM 的局部修補程式（如「殘差集中在邊框 1px → 自動包 border mask」）。當某類殘差停滯且符號枚舉擬不出 `tactic` 時，才**往上拉一層**請 LLM 觀察 5 組殘差寫修補器，再拆小固化為純規則（意見 3、4）。

### 2. 三項替代機制（修補 D1 盲點與複雜度）
* **零儀式軌跡＋後驗自動分型**：廢除手寫 `kind` 與彈回。LLM 只寫純函數步驟鏈 `@step`，過 train 即收；鎖內建決定論探針自動標記多標籤 `auto_kinds`，省下彈回的 `llm_tax`。
* **延伸軌跡「共變性守門（Equivariance Gate）」**：變換 $g \in \text{Dihedral} \times \text{Perm}$ 必須先在訓練對通過共變檢驗 $P(g \cdot x_{\text{train}}) = \phi_g(y_{\text{train}})$，確認程式與題意對 $g$ 具真對稱性後，才用合法子群 $G_{\text{valid}}$ 生成延伸軌跡，根絕重力與語意色毒樣本。
* **跨縫滑動窗（Seam Window）**：當第 $i$ 段 `miss` 而第 $i-1$ 段已 `fit`，斷裂面額外記錄跨兩段的 `(S_{i-1}, S_{i+1})` 並將 `S_i` 降為軟提示（距離獎勵而非硬邊界），允許枚舉器或微任務微調出對 `seed` 友善的中間態 $S'_i$。

### 3. 資料格式落地：活體 `aos` 園區樹與升級契約
廢除單一平坦 `ops.jsonl`，改為活目錄樹 `aos/parks/<park>/nodes/<id>/`（支援上千個無 LLM 函數節點併發，使用者隨時 `cd` 進去 `cat node.json` 或寫入 `inbox` 干預，落實意見 1、7）：

```json
// aos/parks/recolor/nodes/nd_0412/node.json（統一表示 op | gate | tactic）
{"id":"nd_0412","role":"op|gate|tactic","park":"recolor","status":"incubating",
 "gate_pred":["and",["shape_eq"],["<=",["new_colors"],1]],
 "body":["map",["lam",1,["..."]],["$in"],["$e0"]],
 "stats":{"window_10":[1,0,1,1,0,0,1,0,1,0],"uses_new":2,"ema_util":1350.0},
 "inbox":["hint: bind $e0 before const hole"]}
```

蠟模頭 `wax/<id>.jsonl` 與斷裂面 `_witness.jsonl` 增修欄位：

```json

{"verified_sym":{"dihedral":["id","flip_h"],"perm_orbits":[[1,4,7]]},
 "auto_kinds":[["extract","int"],["sub"],["recolor","sparse"]]}

{"kind":"fracture","wax":"c0031","seg":2,"pairs_n":12,
 "seam":{"prev_seg":1,"prev_prog":["take",["$e0"],["$in"]],"s_prev":"states[1]"}}
```

### 4. 四個具體量法
1. **`park_selectivity`（園區選擇率）**：$\text{單段實際掛載算子數} / \text{全庫活躍算子數}$（目標 $<0.15$），監控節點池膨脹時單次枚舉分支是否受控（意見 1）。
2. **`solidification_rate`（無 LLM 固化率）**：$\text{當輪由無 LLM 節點（枚舉＋tactic 修補）關閉之斷裂面數} / \text{總關閉數}$，直接量測「agent → tool → 程式」的脫 LLM 進度（意見 2、3）。
3. **`hammer_gain`（錘子升級倍率）**：固定總評估帳（`fitter_nodes + tactic_nodes + llm_tax`）下，比較新一批 `gate/tactic` 啟用前後每 $10^6$ 次評估關閉的斷裂面數比值，量測 Lv1→Lv2 母機增效（意見 5、6）。
4. **`ema_net_utility`（滑動淨效用，取代 `H24 不退`）**：計算跨 5 個 epoch 的 $\text{EMA}_5(\Delta \text{solved}\cdot B_0 - \text{marginal\_nodes})$；單輪 H24 退 1～2 題僅轉 `shadow` 觀察而不淘汰，只要 5 輪趨勢為正且 `uses_new ≥ 1` 即轉正（落實意見 8）。
