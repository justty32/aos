讀完了。現況要點：守門 `guard.py` 五道門、三道預設、常數手定；拆法在 `decomp.py` 用固定清單、預算均分（`SPLIT=0.6/len`）；r08 meta 帳裡 `halves` 讓 AUC 12→18 卻被 CRN 判準擋下；linker 的 kb_link 是唯一花 token 的節點，規則晉升門已經是程式。以下是 Q3 的答案。

# Q3 固化路徑：agent → tool → 程式

## ELI5 結論

一塊工作「可以固化」的意思不是 agent 自己說它穩，而是**有一支程式能重現它最近的輸入輸出**。所以固化不靠判斷，靠搜尋：把節點最近 N 次的 (input, output) 當 ground truth，用現成的枚舉器（arcagi 的 `seed.enum`、aos 的 `aos_metaopt.enum`）去找一支能重現的程式；找得到就固化，找不到就拆成更小的塊再找。固化後的程式一定帶「前提檢查」，不在前提內就棄權、自動退回舊版 agent，所以固化永遠可逆。整條路的進度用一個數字量：這個節點的 **LLM 份額**（`llm_share`＝問腦花的分數 ÷ 總分數）有沒有逐 epoch 降到 0。拆出一堆腳本但 `llm_share` 不降，就是使用者擔心的「只固化了無關痛癢的部分」，記成失敗。

## 設計

### 1. 節點的實作等級

每個節點 `_metainfo.json` 加一格 `impl`（不認得照 C-48 忽略）：

```json
"impl": {"level": "agent|tool|prog", "llm_share": 0.83, "prev": "versions/3",
         "guard": "guard.json", "since_epoch": 12}
```

- `agent`：每次呼叫都問腦。`tool`：程式先判，判不了才問腦（部分固化）。`prog`：純程式，`llm_share`＝0。
- `llm_share` 不是自報，從 `observed.jsonl` 的 `think` 行與 `tool` 行用 node-pool 的 `cost` 公式算出來。

### 2. 「夠小、夠穩」的量法（全部機械，不問 LLM）

| 項 | 怎麼量 | 起步門檻 |
|---|---|---|
| 小（契約封閉） | 最近 N＝20 次的 `in_bytes` p95；呼叫期間讀過的檔是否只在自己資料夾與輸入 | p95 ≤ 8 KB；外讀 0 |
| 穩（可重現） | 20 次 I/O 當 ground truth，枚舉器找程式；留一驗證 | 留一正確 ≥ 95%，錯 0（棄權不算錯） |
| 不背答案 | 找到的程式大小 vs 樣本數；合成變體（aos-self-opt 的 `synth.py`、arcagi 的 S5 pair）也要對 | 程式節點數 ≤ 樣本數 ÷ 2；合成錯 0 |
| 值得 | 固化成本（枚舉 CPU 秒換成分數）vs 省下的 `llm_share × 預期呼叫數` | 10 個 epoch 內回本 |

四項全過＝固化候選；固化成本從節點自己的錢包報銷（接 node-pool `ledger` 新 `kind: freeze`）。

### 3. 拆分演算法（整塊找不到程式時）

依序試三種拆法，每一種都把「子塊能否被程式重現」當成功判準：

1. **按 trace 拆**：讀 `observed.jsonl`，以 `think` 行當切點，切出連續的純 `tool`／`cmd` 區段，各成子節點。問腦的部分留在 agent。這是最便宜的拆法，但只拆出確定性區段，`llm_share` 常常不降。
2. **按殘差拆**：對枚舉器沒重現的 case，用 `residual.py` 那套按輸出特徵分類（棄權、錯類別、長輸入等）；每一類單獨再枚舉，找得到的類固化成子節點並加前提檢查，agent 只接剩下的類。這一步才會真的降 `llm_share`。
3. **按見證拆**：arcagi `witness_splits` 的 map／take／append 拆法直接搬來用在 JSON 輸出：輸出物件各 key 獨立求解（等於 map over keys）、輸出是輸入的延伸就只解增量。

停止條件：子塊樣本數 < 5、拆深 ≥ 2，或一輪拆分後 `llm_share` 降幅 < 5 個百分點（記成「只拆出腳本」的失敗拆法，寫進 meta 帳）。

### 4. 固化後怎麼回退

- **前提檢查必備**：枚舉時順手產生 `guard.json`（看過的輸入長度範圍、key 集合、常數集合）；固化程式跑之前先查，不在範圍內回 `Abstain`，由叫用層自動走 `impl.prev` 指的舊版，記一行 `fallback`。這跟 r07 守門「不確定就放棄」是同一個思想。
- **影子期**：固化版先以影子跟 agent 版並跑 K＝10 次，一致率 ≥ 95% 才換上（C-84 自動換上）。
- **自動退回**：滑動 20 次內棄權率 > 20%，或錯誤率比舊版高 5 個百分點，自動把 `impl.level` 降一級、`prev` 換回，寫 meta 帳 `kind: thaw`。舊版照想法 21 標 `covered`、不刪。
- **判準方向**：固化只要求「不變差＋省成本」，不要求顯著進步。r08 的 `halves` 讓 AUC 12→18 卻因 `mean_drop 20.3 < 2×SE 25.8` 被拒，就是用了「要顯著進步」的判準擋掉了便宜的固化；兩種判準要分開。

### 5. 三個例子

**(a) arcagi 守門。** 現況：r07 線 C 由 agent 離線讀 r06 artifacts 選門，結果寫死在 `guard.py` 的 `DEFAULT_GATES` 與 `TABLE_MIN_ROWS=4`、`ROW_SUPPORT=2`。這是「agent 手固化」，沒有回退路。r09 動作：新節點 `aos/gate/select/`，輸入每題候選帳 `candidates.jsonl`（`origin, support, table rows/thin, synth_ok, shape_law, train_ok, test_ok`），輸出 `gates.json`；搜尋空間＝五門開關 × 常數 {2,3,4,5}；適應度＝training 上「放棄的錯答 − 5 × 誤擋對答」（與 linker 的 `fitness` 同形）；只用 training，evaluation 收輪審計。固化判準：連續 5 個 epoch 選出同一組 → 寫成常數版 `prog`，選門節點退為影子每輪重跑比對；收輪若 evaluation 誤擋 > 0，退回前版 `gates.json`。

**(b) 拆法選擇。** 現況：`decomp.py` 把 `SPLIT=0.6` 的預算均分給所有適用拆法，順序寫死；加減拆法靠 agent 改碼。r09 動作：新節點 `aos/split/select/`，輸入題目特徵（`same_len, const_out_len, is_prefix, len_ratio`，這些 `witness` 本來就算出來）、輸出每拆法預算份額；資料來源是每題每拆法子搜尋的 `eval_steps` 與解出與否（已計費，只要多寫一列）。先當 `tool`：查表「特徵 → 各拆法成功率」，表不足時回均分；表累積 ≥ 20 題且留一正確 ≥ 80% 後固化成決策表常數；回退＝回均分。這也化解 halves 案例：不開全局開關，只在特徵命中時給它預算。

**(c) aos linker 規則。** 現況：kb_link 是 agent（20 地 170.5k token，整棵樹唯一花 token 的節點），`judge.py` 規則集是 tool，晉升門（solved ≥ 3、wrong_gold＝0、合成錯 0）已經是程式。第二輪動作：把 kb_link 改成 `tool` 級——規則先判、棄權才問腦；每批結束把問腦的 (payload, 答案) 當 ground truth 餵 `enum.py` 長新規則；`asked_nonT0` 逐 pass 下降就是 `llm_share` 下降。拆分走殘差分類（`residual.json` 每類一個子節點）。回退靠規則 `covered` 不刪、`distill uncompress`、C-84 三個 case 門。門檻：第二輪結束 `asked_nonT0` 比起點降 ≥ 30%，`wrong_gold` ≤ 5%。

### 6. 活的樹（意見 7）

固化狀態必須能 cd 進去看：節點資料夾裡有 `_metainfo.json#/impl`、`guard.json`、`shadow.jsonl`、`versions/`。干預走現成的梯度信箱：`pool grad` 加兩種 `case`——`freeze`（立刻試固化）、`thaw`（立刻退回），節點每次被叫之前讀 `_gradients.jsonl` 裡 `handled: null` 的信。強制走某版用 `aos-exec --ws <ws> <node> --impl agent`。arcagi 這邊第一步只讓 `grow` 迴圈改經 `aos-exec` 叫 `aos/gate/select` 與 `aos/split/select` 兩個節點，其餘照舊 in-process；aos 這邊在 `playground-so1` 把 kb_link 子樹跑起來。

## 風險與不做的事

- **只固化無關痛癢的部分**（想法 13）：用 `llm_share` 降幅當拆法成敗，不用「固化了幾個節點」。
- **枚舉找到的是背答案的表**：留一、合成變體、程式大小上限三道同時守；守門 `table` 門的思想直接複用。
- **前提檢查太緊導致棄權過多**：棄權有自動 fallback，不會錯答，只是省不到錢；棄權率寫進曲線。
- **顯著性判準誤殺便宜固化**：固化用「不變差」判準，與元優化的「顯著進步」判準分開記帳。
- 不做：不固化審視者本身（留給 Q4 的往上長）；不讓 LLM 判「穩不穩」；不在 r09 把整棵 arcagi 樹活化，只兩個節點；不動 aos-exec 等基礎層。
