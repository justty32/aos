## (A) 審查：v2 體檢報告

### 1. 上一版的意見是否真的解決？
* **已實質解決（3 項）**：
  * **踏腳石保護**：引入 `incubator.jsonl`（給預算不給分、TTL 3、MDL 門），解決單步貪婪門誤殺半成品的問題，也防住刷半成品騙分。
  * **結構優化取代調參**：`params.json` 降回第 1 層墊底；新增縱拆 `pipe:[H,G]` 與條件 AST 重寫 `rewrites.jsonl`，第 2 層終於碰觸程式結構。
  * **底層修補水源**：鍛造爐 `truth/forge/` 讓重寫器在第 0 輪就有「破損→修補」對可練，緩解空種子無米可炊。
* **表面解決、實則未解（2 項）**：
  * **詞彙水源依然斷絕**：鍛造爐只拿**現有原語**組 2～3 步，**長不出新原語（詞彙表封閉）**；而方向題 15 仍把 LLM 鎖在 `stop` 才 `propose` 一次，探索期依舊缺乏高階破冰水源。
  * **單體迴圈披資料夾皮**：步 1「根 `_entry` 包 `grow.curve` 單 pass、邊界重讀活檔」，本質仍是單體 Python 迴圈定期讀設定檔，並非函數本身即獨立可組合節點。

### 2. v2 新引入的 4 個致命問題
* **鍛造爐的「單步溫室偏置」**：正向組 2～3 步再「刪改 1 步」，殘差永遠離正解僅 1 步編輯距離。真題卡住多半差在**缺中間表示或差 4～5 步複合變換**；拿單步破損訓練「改進器改改進器（第三種病人）」，只會篩出局部修補匠（peephole fixer），造成元層對合成雜訊過擬合。
* **縱拆見證的「一對多爆炸與空交集」**：
  1. 逆運算多為**一對多（非單射）**（如裁切↔貼回、drop↔任意前綴、塗色↔反查），逆推 1 步的狀態集 $B$ 有上萬種可能，`_witness.jsonl` 若存具體陣列必記憶體爆炸。
  2. 前向 1～2 步與後向 1 步要求直接相等對齊，等於假設總長 $\le 3$ 步；遇 5 步題交集必為空。
* **「改進器改改進器」樣本飢餓**：r09 初期 `rewrites.jsonl` 僅個位數列，在此規模上跑 AST 變異改自己，統計功效趨近於零，搜尋空間卻平方膨脹。
* **孵化槽 `covered` 永久毒化**：到期未轉正標 `covered` 不刪；但若失敗是因**當時缺某個下游原語**，幾輪後新原語長出，該優質前半拆法卻被永久跳過。應綁定「當時原語庫雜湊 `env_hash`」，環境變動即解凍。

### 3. 哪裡偏離使用者原意？
* **偏離意見 3（agent → tool → 程式）**：原意是先用高成本通用 agent 解通，再一路拆小固化成純程式；v2 在 arcagi 仍因純度潔癖封殺探索期 LLM，未打通「髒破冰→純固化」管線。
* **偏離意見 4 頂層註（往哪長可元優化）**：§三.5 把「縱拆→橫拆→up-expr→up-params」寫死成固定優先序，沒讓錘子學習根據殘差決定生長方向。
* **偏離意見 8（看趨勢容許震盪）**：主線仍鎖死單步 `J-不退`；自舉三階測試看「接受項簽名重合率」，忽略演化路徑依賴與「不同 AST 但語義等價」的殊途同歸。

### 4. 最小可落地版（MVP）真的最小嗎？
* **仍膨脹約 2 倍。** 六層體系、9 種 schema、r09 八大步外加雙專案同步，戰線太長。r09 應果斷**砍掉 5 項**：
  1. **第三種病人（改進器改改進器）**：r09 先讓重寫器改好本體與拆解，r10 再改自己。
  2. **`up-params`**：明知預期 $\Delta=0$ 還給 1/4 預算純屬浪費。
  3. **影子錢制與自建 `sched/`**：OS 級 `nice`＋process pool 限 12 workers 即夠，會計帳對 r09 決策貢獻為 0。
  4. **守門搜尋（步 4）降為選配**：守門只省常數倍評估費（lv1.5），人力應優先打穿「鍛造爐＋孵化槽＋縱拆＋重寫器」。
  5. **雙專案強綁**：先在 `arcagi` 單戰場跑通閉環，收輪再抽 `aos_metaopt` 給 `playground-so1`。

### 5. 量法能否分辨真進步？
* **有三個漏洞必須補**：
  * **lv2 門的合成集後門**：§三.3 寫「SCF ≥1.5 **或** H24＋**合成保留集**淨增 ≥2」。合成保留集與鍛造爐同分布，極易靠刷合成題 +2 繞過 SCF 拿假 lv2（直接違背方向題 1 初衷），**必須剔除合成保留集**。
  * **SCF 的「砍空間刷倍率」陷阱**：重寫規則若把搜尋空間砍 90%，在簡單題上枚舉量暴降（SCF 極高），卻可能悄悄剪掉難題所需的分支。SCF 必須改算**跨題遷移（Leave-Task-Out）**且綁定解題集不縮水。
  * **簽名重合率看錯指標**：Stage3 重跑應考核「單位算力累積解題曲線下面積（AUC）是否優於 Stage1」，而非強求長出同一條 AST 簽名。

## (B) Argon 共同設計提案：我們該怎麼造這把錘子？

### 1. 三個新機制與核心類比（補齊 fable 沒想到的拼圖）

* **類比一：失蠟鑄造法（Lost-Wax Casting）——解開「意見 3 破冰水源 vs 無先驗純度」死結**
  * 分離**鑄模廠（Foundry）**與**無菌室（Clean-Room）**。在鑄模廠放開限制：卡住時允許 LLM Agent（或人類干預）寫粗糙 Python／混合 tool 先解出真題當「蠟模」，產生中間 I/O 軌跡；接著用 `enum.py` 逐段暴力擬合固化，並對多題解法做**反合一（Anti-unification，抽最大帶洞公共子樹 `λx. ...`）**提煉出**無題目常數的通用組合子或拆解規則**。
  * **無菌鎖**：蠟模程式碼與單題特解一律銷毀；只有通過跨 ≥3 題壓縮檢驗、計入 `frozen.json` 先驗位元帳的純 DSL 算子才能進無菌室，最後在零 LLM 無菌室從頭重播計分。這讓 arcagi 與 aos-self-opt 徹底統一在意見 3 下，且絕不污染純度。
* **類比二：最弱前置條件（Dijkstra's WP / 雙向透鏡）——用「部分遮罩與屬性約束」取代具體見證**
  * 縱拆逆推不要存上萬個具體網格，改存**約束見證（Partial Grid with `?` + Property Sketch）**。例如末步是 `overlay(A, B)`，逆推只寫一條帶 `null`（don't-care）的遮罩；末步是色盤映射，逆推只寫「尺寸同輸出、連通塊同構」的屬性約束。
  * 子節點查表計分時，`null` 格誤差記 0，只算違反約束的位元數。這瞬間化解逆運算一對多爆炸，且就算中間隔 3 步，也能先在「尺寸約束」對齊縱拆，再對「顏色約束」二次縱拆（商空間逐步收斂）。
* **類比三：醒睡壓縮＋多步橋接鍛造（DreamCoder Sleep + Bridge Forge）**
  * **睡眠造詞**：每 epoch 掃描主線與孵化槽程式樹，只要某個帶洞子樹跨題省下的總 MDL 位元大於自身定義長度，自動升格為新原語 `parks/lib/comb_k`——**空種子不靠 LLM 也能長出新詞彙**。
  * **橋接鍛造**：隨機抽兩題已解程式 $P_1, P_2$ 串成 4～6 步合成程式，**挖空中間連續 2～3 步**考縱拆器與重寫器，消滅單步擾動的溫室偏置。
* **動態生長路由（落實意見 4、6）**：廢除寫死的四步順序，改由一張可演化的 `dispatch.jsonl` 讀取殘差指紋（尺寸是否已合、色盤 IoU、漢明距離熵），用 UCB 按各動作歷史「每千次評估壓縮位元率 $\Delta L / 10^3\text{evals}$」動態分配預算（縱拆／橫拆／睡眠造詞／鑄模破冰）。

### 2. 我會怎麼設計這把錘子：極簡「三件套＋Unix 管線樹」
砍掉九種格式與雙軌包袱，整棵樹只有一種身體（標準 stdin/stdout 讀寫 JSONL 的可執行資料夾，`pipe:[H,G]` 直接對應 Unix 管線與中間見證檔）與**三種核心資料檔**：
1. **見證檔 `hammer-witness/2`（`_witness.jsonl`）**：支援部分網格與屬性約束
   ```json
   {"task":"0d3d703e","pair":0,"dir":"bwd","op":"wp_overlay",
    "mask_grid":[[2,null,2],[null,0,null]],
    "props":{"shape":[2,3],"n_colors_le":3},"base_bits":48.0}
   ```
2. **統一算子檔 `hammer-op/1`（`ops.jsonl`，合併重寫、拆解、新組合子與孵化狀態）**：
   ```json
   {"id":"op_07","kind":"decomp|rewrite|comb","status":"incubating|live|dormant",
    "when_res":{"shape_eq":true,"color_iou_lt":0.8},
    "lhs":"(map ?f ?x)","rhs":"(overlay (keep_color ?c ?x) ?slot1)",
    "free_slots":{"?c":"Palette(x)","?slot1":"Expr(d<=2)"},
    "mdl_bits":18.5,"ttl":3,"env_hash":"8f2a","lto_scf":2.1}
   ```
   *(註：`status` 直接內建孵化狀態，連 `incubator.jsonl` 都可合併；`env_hash` 隨原語庫新增自動喚醒 `dormant` 踏腳石；人類干預 `ctl say` 就是直接往 `ops.jsonl` 塞一列 `status:"incubating", by:"human"`，零阻抗！再加一個 `_view.sh` 把殘差印成彩色終端色塊方便人眼巡檢。)*
3. **單一權威帳 `ledger.jsonl`**：每 epoch 記每顆節點的 `evals_spent`（含元層自身搜尋耗費）、`mdl_bits_saved`、`solved_train`。

### 3. 硬核防弊量法（2 條公式定真偽）
* **跨題遷移壓縮倍率 $\text{LTO-SCF}$（驗單一算子品質）**：將訓練池對半切 $A, B$。在 $A$ 提煉的 layer-2 算子集 $R_A$ 凍結套入 $B$，僅在「未丟失任何原已解題」前提下計算幾何平均加速比：
  $$\text{LTO-SCF}(R_A) = \exp\left(\frac{1}{|S_B|}\sum_{t\in S_B}\ln\frac{\text{evals}_{\text{base}}(t)}{\text{evals}_{+R_A}(t)}\right) \ge 1.5$$
* **全成本自舉曲線面積增益 $\Delta\text{AUC}_{\text{total}}$（驗錘子真升級，內化 50% 元開銷）**：
  Stage1（原錘子）與 Stage3（套入 layer-2 算子的新錘子）從同一空種子起跑，**橫軸直接取「本體＋元層＋鍛造爐的總評估次數 $\log_{10}(\text{TotalEvals})$」**，縱軸取盲測／保留真題解出數。若元層瞎忙耗超過省下的算力，曲線自動右移導致 $\Delta\text{AUC}_{\text{total}} \le 0$——用一條物理定律同時驗出「學習斜率、方向正確（容許局部震盪）與元層經濟學」。

### 4. 對 v2 五道方向題的明確建議
1. **鍛造爐不進計分**：**同意**，且必須同步把 §三.3 lv2 門裡的「合成保留集淨增 ≥2」後門刪掉。
2. **SCF 先量基線**：**同意暫定 1.5**，但必須改為跨題遷移 **LTO-SCF**。
3. **逆運算庫列先驗**：**同意**，並建議改寫為 4～6 個基礎原語的「最弱前置條件（遮罩／屬性逆推器）」。
4. **r09 園區只做快取匯流排**：**同意**，連影子錢制與 `up-params` 也一併砍到 r10 後。
5. **自舉三階 r09 先報、r10 成硬門**：**同意**，但指標從「簽名重合率」改為 **$\Delta\text{AUC}_{\text{total}} > 0$**。
