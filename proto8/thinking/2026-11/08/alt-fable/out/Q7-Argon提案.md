# Argon 共同設計提案：母機鍛造、契約反傳與踏腳石錘子（Hammer v1-Argon）

## 一、核心診斷與新類比：別造「官僚審批樹」，要造「工具機母機＋編譯器管線」

Fable v1 把 Q1～Q6 整得很乾淨，但架構骨子裡是一棵**「單步貪婪的官僚審批樹」**——每步改動都必須立刻通過終端嚴格不退門檻（`J-進步`／`J-不退`），否則淘汰。這直接埋下三個死結：
1. **違背意見 8（允許震盪）並鎖死「往下拆」**：把大問題拆成兩半時，前半段就算切對了，在後半段長出來前，終端解題數必為 0 甚至因開銷略退。貪婪門檻會把所有「結構踏腳石」當場槍斃（所以 `halves` 在 v1 得靠 `whitebox:true` 開特例後門）。
2. **把「題目分流」誤當「程式拆解」**：v1 的 `sub/<sig>/` 只是按殘差簽章把題目分群（橫向路由），沒有把複合函數 $f(x)=g(h(x))$ 縱向切開；子節點沒有局部真值，暴力搜內部節點仍得重跑全樹。
3. **假同構（換湯不換藥）**：調 `params.json` 浮點門檻只是轉溫控器，不是錘子造錘子（E0 已知參數層 Δ=0）。

**我的設計類比：「車床造車床（工具機母機）＋ LLVM 編譯器 IR 管線」**
* **母機同構**：車床能車出下一代車床的齒輪，是因為「產品（ARC 解法）」與「母機零件（改進器／拆解器）」都是**同構的狀態重寫規則（State-Rewrite Pass）**，吃同一套暴力枚舉引擎（意見 6）。
* **產業園區（意見 1）的真義**：科學園區不是為了設 `cap 64` 收 `×1.2` 過路費，而是提供**公共水電檢測台（園區級共用特徵快取）**與**上下游半成品交易（中間件黑板）**，讓上百個小程式零重複計算地拼裝。

## 二、Fable v1 沒想到的四個核心機制

### 1. 自舉鍛造爐（Synthetic Forge）：零成本破解「空樹餓死 vs 舊樹污染」
不必在方向題 1 糾結雙軌。拿空樹現有的種子原語，隨機正向組合 2～3 步作用在訓練輸入網格上，每輪自動合成 1,000 道**「已知真實拆法」的合成題**；再故意刪改其中一步，直接產出 `(破損 AST, 殘差特徵) → 正確修補動作` 的元訓練對。
* **效果**：完全不碰舊樹 474 個手寫節點、零 LLM token，空樹第 0 輪就有滿滿的真值可餵飽梯子、守門搜尋與改進器。

### 2. 雙向夾擊與「契約反傳（Witness Backprop）」：離散版神經網路反傳（意見 4）
離散程式沒有連續梯度，它的梯度是**中間目標見證（Intermediate I/O Witness）**。當節點停滯需要「往下拆」（或意見 3 的 agent 拆小固化）時：
* 從 `Input` 正向枚舉深 1～2 步得前向狀態集 $F$，從 `GroundTruth` 逆向反推 1 步（逆裁切、色表反查、差異遮罩分離）得需求前狀態集 $B$。
* 若某對 $(F_i, B_j)$ 在多數訓練對上對齊或殘差驟降，立刻在交會處切開成串聯子節點 `pipe: [H, G]`，並把 `(Input → F_i)` 與 `(F_i → Output)` 寫入各自的 `_witness.jsonl`。此後兩個子節點與固化枚舉器都能**查表單獨暴力搜（$O(1)$ 局部評分）**，不必重跑整棵樹。

### 3. 「主線＋踏腳石孵化槽（Incubator）」雙軌制：制度化落實意見 8
每個目標除 `champion`（主線，守嚴格門檻）外，旁掛容量上限 8、壽命 `TTL=3 epochs` 的**孵化槽**。結構拆分或半成品節點即使終端新解題數 $\Delta=0$（甚至微退），只要**大幅壓縮殘差描述長度**就准入駐孵化槽，給下游 3 輪時間補完最後一哩路；到期未轉正自動回收。`halves` 直接成為此機制的標準產物，無須特例旗標。

### 4. 真・產業園區匯流排與條件樹重寫（意見 1、2、6）
* **園區匯流排（Park Bus）**：`parks/grid2d/` 入口每 epoch 統一算一次連通物件、對稱軸、色盤差等基礎特徵寫入共用快取；節點產出的高價值中間網格（如去背物件、遮罩）依雜湊去重掛上園區黑板，供全園區節點當積木引用。
* **改進器即重寫規則**：將 `improve` 節點從「調參數腳本」改為與解題器同引擎的**條件樹重寫器（Conditional AST Rewriter）**——依殘差標籤觸發，只挖空局部 AST 槽位（`free_slots`）交給 `enum.py` 暴力填空，把 $10^6$ 搜尋空間壓到 $10^2$。

## 三、具體資料格式與活樹結構

在 v1 的 `ws/hammer/` 基礎上，新增／替換三個核心格式（皆為單行 JSONL，支援 `cd` 檢視與信箱干預）：

1. **局部真值契約 `_witness.jsonl`（`hammer-witness/1`，放子節點內）**
```json
{"v":"hammer-witness/1","task":"00d62c1b","pair":0,"in_sha":"a1b2","target_sha":"f9c0","src":"meet_mid","ttl":3}
```
2. **統一重寫規則 `rewrites.jsonl`（`hammer-rewrite/1`，本體與 layer-2 改進器共用）**
```json
{"v":"hammer-rewrite/1","park":"ast_edit","when_res":["bbox_ok_color_off"],"lhs":"(paint ?g ?c)","rhs":"(paint_mask ?g ?m ?c)","free_slots":["?m"],"gain_scf":3.4}
```
3. **孵化槽 `hammer/incubator.jsonl`（`hammer-incubator/1`）與園區宣告 `parks/<name>/_park.json`**
```json
{"v":"hammer-incubator/1","node":"parks/grid2d/sub_07","born":4,"ttl":3,"solved_delta":0,"mdl_drop_bits":38.2,"witness_pass":"15/18"}
```
* **活樹干預（意見 7）**：使用者 `cd ws/hammer/parks/grid2d` 可直接 `cat ../../incubator.jsonl` 看哪些半成品差臨門一腳，並用 `pool grad --def sub_07 --case rewrite_hint --say "試對稱遮罩"` 投遞局部提示。

## 四、具體量法與真・lv2 門檻

1. **搜尋壓縮倍率 $\text{SCF}$（Search Compression Factor）—— 真・lv2 門檻（對應意見 5 效率工程）**
   * **廢除「改動 `params.json` 即算 lv2」**：`layer:2` 接受項必須是樹內枚舉出的結構（`hammer-rewrite/1`、拆解器規則或 `judge.json` AST）。
   * **硬指標**：在空樹曲線與盲測 H24 不退前提下，同題集達標所需的**總枚舉評估次數下降 $\ge 2.0\times$（$\text{SCF} \ge 2.0$）**，或**同等算力預算下 H24／合成保留集淨增 $\ge 2$ 題**，且元層自身算力開銷 $\le$ 省下算力的 $50\%$。
2. **防背答案的殘差壓縮門檻 $\Delta\text{MDL}_{\text{res}}$（孵化槽守門）**
   * 定義 $L(y^* \mid y)$ 為將輸出 $y$ 修補成真值 $y^*$ 所需的壓縮位元數。入駐孵化槽須滿足跨 $\ge 3$ 題平均 $\Delta L \ge 25\%$，**且嚴格滿足 $|\text{程式位元長}| + L(y^* \mid y) < L(y^* \mid x)$**（防止把殘差硬編碼進樹裡騙分）。
3. **固化有效覆蓋率 $\text{EPC}$（意見 3）與園區複用率 $\text{IRR}$（意見 1）**
   * $\text{EPC} = \text{純 prog 節點獨立走完且正確的任務佔比}$（防 `guard.json` 靠棄權刷低 `llm_share`）；園區 $\text{IRR} = \text{命中園區快取或半成品黑板的評估佔比}$，低於 $15\%$ 則自動合併園區。

## 五、作為共同設計者對 v1 方向題的裁決建議

* **題 1（病人）**：改選 **「空樹＋自舉鍛造爐」**，既解決 r08 餓死，又守住 100% 從零長出的純度，省下雙軌三成維護工。
* **題 2（判準與 halves）**：主線守嚴格兩段判準，但加掛 **`incubator.jsonl`（TTL=3）**，用 $\Delta\text{MDL}_{\text{res}}$ 正大光明收留 `halves` 等拆解踏腳石。
* **題 3 & 4（LLM 與錢制）**：贊成 v1（`stop` 時才准 `propose` 寫候選；錢制先跑影子帳，改用算力配額與孵化槽 TTL 控管資源）。
