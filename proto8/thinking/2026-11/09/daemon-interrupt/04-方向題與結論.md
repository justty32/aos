## 方向題（4 題，原則推不出、要使用者拍板）

**題 1：三條路先做哪一條？**
推薦：**②Unix socket 先做，當預設鈴；①只用在 daemon 叫自己的子項（不給外人用）；③排後**，等「proc 連函式庫都不要、只寫一個路徑」的需求真的出現再做。理由：②是唯一同時做到不碰 pid、沙箱可用、跨帳號可用、改動中等的；①外人用會撞 no-pid、沙箱不通；③最像 plan9 但最重，有全員卡住與殭屍掛載兩個硬坑。
判準：預期有任何寄件人跑在 bwrap 裡或別的帳號 → ①不給外人用；要求「寄件人就是寫一個路徑」→ 只有③；能接受的改動 ≤500 行 C++ → ②，③至少 1000 行＋新的建置依賴。

**題 2：鈴還是通道？**（socket／FUSE 上要不要載指令、同步回結果）
推薦：**鈴**。指令照舊寫 ctl／信箱，socket 只收一行 `ring`、回一個 byte「聽到了」，結果仍從 state 或回信讀；守住 N-06、使用者 11-03、C-07、C-48。
判準：只有出現某種指令**必須在 50 毫秒內拿到同步回應、又沒法寫成「寫檔＋回信」**時，才值得開通道。現有的 pause／resume／stop／名單增減／ping 全寫得成 → 鈴。

**題 3：響鈴預設開，還是寄件人明說 `--urgent`？**
推薦：**明說**（Python `urgent=True`），預設不響——前提「super loop 第一優先、緊急才走這套」的直譯。
判準：用一個月後，若 ≥50% 的 ctl 寫入／寄信都帶 `--urgent`，就反轉預設；≤10% 維持。某個子命令（例 `aos-daemon-ctl stop`）若體感上一定要快，可以只對它預設響。

**題 4：開關關著時，要不要順手擋掉 SIGUSR1／SIGUSR2？**（現在一來就死、子項孤兒）
推薦：**擋**（用擋住、不用忽略；子行程解開）。P-36 本來就要求先收好子項再走，只是以前沒人送這兩個訊號。這是全案**唯一**讓「關著時行為」跟現在不同的地方：差別只有收到 SIGUSR1／2 不再死。
判準：使用者若把「沒開時行為與現在完全一樣」讀成字面上零改動 → 不擋，記成已知坑；查得到有工具依賴「送 SIGUSR1 讓 daemon 死」→ 不擋（目前查不到）。

## 照原則定的細節（不必再問）

1. 鈴不帶內容、檔是唯一真相；鈴不提早跑身體，只提早看檔。
2. 開關＝daemon.json／loop.json 頂層 `interrupt`：沒寫／`null`／`false`＝關；`true`＝預設種類（照題 1 推薦＝socket，`interrupt.sock` 放自己的 stack）；物件 `{"kind": "socket"|"signal"|"mount", "path"?, "signal"?}` 細調；壞值＝`CfgBad`。
3. 開了在 state 窗寫 `interrupt` 欄；關著不寫。寄件人只看這欄決定響不響、怎麼響；沒宣告就不響。（另一隊正把 state 拆出常變的回音窗；`interrupt` 是穩定欄、留在 state。）
4. 寄件人三個口（`aos-daemon-ctl`、`aos-post send`、`py/daemon_ctl`）各加 `--urgent`；永遠先寫檔（N-05）再響鈴；響失敗一律靜默跳過，不改逾時、不改錯誤碼（N-17）。
5. 用訊號時：預設 SIGUSR1、可設 SIGRTMIN+n；外人送之前三欄（pid、`started_at_ticks`、`boot_id`）對 /proc，對不上不送；鈴號全程擋著，`folder.cpp` 與 `child.cpp` 的子行程都解開；不當收工訊號；不轉給身體。
6. socket：AF_UNIX、stream、非阻塞、backlog 128、權限 0660；每次醒全收、一行最多 64 bytes、回 1 byte、關；起來先 flock 再刪殘留；關著時 nap 照舊 `sigtimedwait`。路徑超過 108 字元或檔案系統不支援＝warning、不宣告、退回 super loop（opus 補）。
7. 搶占第一版只做 `run_folder`；loop 插播只有 `stop` 立刻生效（SIGTERM 給身體），其他等身體跑完；daemon 插播跑小 tend、跳過自己的身體。`run_inline` 只喚醒，文件寫明。
8. 監管樹不自動往下傳；daemon `halt` 寫子的 ctl stop 後，子 state 有宣告鈴才響——子項停下來從「≤1 秒＋身體時間」縮到「幾毫秒＋grace」。
9. 不另設節流。
10. `interrupt.sock`、`live/` 掛載點不進 image（列進不進 image 清單）；新機由 daemon 重建，設定跟 daemon.json 走。
11. ③若做：FUSE 低階 API、fd 進同一個 poll、不開執行緒；一次 open→release＝一道指令；寫穿真檔；起來先卸殭屍；沒 `/dev/fuse` 就 warning、當關著；跨帳號要 `user_allow_other`，C-78 多一步要標。
12. 驗收數字：interval 200 帶 `--urgent` 寫 pause → state 反映 **<10 毫秒**（現況約 130）；暫停中 resume **<10 毫秒**（現況 700）；身體 `sleep 30` 時鈴聲 stop → 身體 **<100 毫秒**收到 SIGTERM（現況等 30 秒）；關著時 strace 比對通過。

## 裁完之後的順序（建議）

題 1～4 裁完 → ②喚醒（nap 的 poll 版、socket 模組、state 宣告、函式庫 `--urgent`）→ ②搶占（插播、小 tend）→ daemon 叫子項（①或②，看題 1）→ 條文加註（N-06、N-17、C-78、附錄1 daemon 條）→ 量上面四個數字。①外人用、③留在本檔當已規劃未做。等另一隊 state 拆分做完再開工，避免同時改 aos-loop 的 window.cpp／loop.cpp。
