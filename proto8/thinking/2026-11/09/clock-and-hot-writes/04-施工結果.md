## 第一段：省寫檔（想法 2，五題照推薦）

### 做了什麼

- `responded_at` 不再因身體跑完一次更新（aos-loop 的身體、aos-daemon 自己的身體都一樣），只在處理新 ctl、收到信、起或收子項時更新；父判卡住（`stuck.cpp`）沒動。
- loop／daemon 的 state.json、llm kernel 的 queue.json 拿掉 `counter_runs`。新開關 **`--enable-counters`**（aos-loop、aos-daemon、aos-llm-kernel 同名，預設不寫）：loop／daemon 寫在 state 窗同資料夾的 `counter_runs.txt`（這個行程起來後第幾輪，跟原本 state 的 `counter_runs` 同一個數），kernel 寫 `$AOS_STACK/counter_kernel_runs.txt`（跨次累加）。都照 N-05 先寫暫存再改名。
- daemon 的 `procs_state.json` 拿掉頂層 `tick` 觀察值；看時鐘讀鐘檔或看 `_tick` 列。
- `queue.json`、aos-fsm 的 `stage.txt` 內容沒變就不寫。
- 條文：N-09 新增「11-09 補」寫原則（兩條判準、一個計數器一個 .txt、`--enable-counters`、有人讀的不搬）；N-17、細則 N-32 的 P5b 註、N-65 ②、N-28 T7 註、C-48 註、C-54 例子、附錄 1～3 照實改；各 impls 說明、`impls/docs/03`（`CounterBad`）、`04`（旗標）、cmd 說明、`stack.gitignore`（`**/counter_*.txt` 不進 image）。

### 代定（可翻案）

1. **旗標名 `--enable-counters`**，寫進 [N-09 的 11-09 補](../../../../docs/NORMS/05-基礎設施-窗/02-N-09～N-11.md)與 impls/docs/04：全家同名，新程式有這類計數器就用它。
2. **kernel 的計數檔叫 `counter_kernel_runs.txt`**，不叫 `counter_runs.txt`：kernel 跟管它的 daemon 共用同一個 stack，同名會互蓋（隊員施工時發現）。
3. kernel 計數檔在但內容不是非負整數＝新代號 **`CounterBad`**（叫人刪掉重來）。
4. 計數器 `.txt` **不進 image**（照 11-07 #20-1「只給人看的紀錄只留原機器」）；所以 git 搬家後 kernel 計數從 0 起，`cp -a` 搬才接著數。
5. loop／daemon 的計數照舊在「開跑那一輪」就加（daemon 數的是圈數，不是身體次數），跟原本 state 的 `counter_runs` 同義。

## 加量：`responded_at` 跟 state 其他欄的變動頻率比較（使用者 11-09「看看他的更動頻率，和state其他東西的變動頻率的比較」）

| 情境 | 重寫次數 | 只因 `responded_at` 變 | `responded_at` 變幾次 | 其他欄變幾次 |

## 第二段：tick→clock 大改（單位 cycle）

### 代定（隊長定的名字，可翻案）

使用者裁的是「clock＋單位 cycle」；下面這些細名是隊長照「指時鐘本身＝clock、指格數／單位＝cycle」定的：

| 舊 | 新 |
|---|---|
| `_tick`、daemon.json `"tick"`、鐘檔預設名 `tick` | `_clock`、`"clock"`、`clock` |
| `AOS_TICK`、`AOS_TICK_INTERVAL` | `AOS_CLOCK`、`AOS_CLOCK_INTERVAL` |
| `aos-tick`（`cmd/aos-tick/`）、`cmd/docs/02-aos-tick與已定值.md` | `aos-clock`、`02-aos-clock與已定值.md` |
| aos-util `tick.hpp`／`tick.cpp` | `clock.hpp`／`clock.cpp` |
| `now_tick`、`at_tick`、`old_tick` | `now_cycle`、`at_cycle`、`old_cycle`（值是第幾格） |
| `tick_interval_ms`、`on_tick`、`warn_missing_tick`、`expand_tick`、`tick_timed_out` | `clock_interval_ms`、`on_clock`、`warn_missing_clock`、`expand_clock`、`clock_timed_out` |
| `*_ticks`、`--timeout-ticks`、`--lease-ticks`、`ASK_MAX_TICKS` | `*_cycles`、`--timeout-cycles`、`--lease-cycles`、`ASK_MAX_CYCLES` |
| `TickBad` | 併進 `ClockBad`（盤點推薦） |
| 腦的工具 `lib/base/clock`、範例 proc 名 `clock`／`clock2` | `lib/base/wall_clock`、`wall_clock`／`wall_clock2`（盤點推薦） |

不改：`started_at_ticks` 一族（Linux `/proc` 第 22 欄）、`progress_board` 的 `SC_CLK_TCK`、C-05 原話（只加 11-09 註）、歷史（thinking、session_logs、archive、user-advice、`wf/workflows/refactor/reports/` 審查報告）、指到 thinking 的路徑（`tick-time/`）、封存的 `/wf-tick`。

施工時多定的（可翻案）：測試與範例裡存某一格值的區域變數 `tick`／`ticks`→`cycle`／`cycles`；Lua 範例鐘檔 `tick.txt`→`clock.txt`；aos-clock 說明的 `round(s)`→`cycle(s)`；aos-daemon docs/09 份額範例裡名叫 `tick` 的普通 proc 改叫 `clock`；名詞表新增「cycle（時鐘的一格）」列，跟原有指資源格的「格」並存。
