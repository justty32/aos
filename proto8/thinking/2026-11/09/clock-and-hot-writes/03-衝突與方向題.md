# 03 想法 2 的衝突與方向題（11-09）

← [README](README.md)｜上一份 [02](02-想法2-熱寫檔實測.md)

使用者的原則：**很頻繁變動的欄從 json 拉出來，改用 .txt 寫，argv 旗標決定寫不寫**。

## 一、碰到的條文

| 條 | 衝突在哪 | 照原則改的後果 | 照條文不改的後果 |
|---|---|---|---|
| **N-09 11-02 補**（state 有變才寫，`counter_runs` 不算變動，窗裡是快照） | 不算衝突，是往前推一步：使用者 11-02 已經讓 `counter_runs` 不觸發寫，現在連快照都不放 | `counter_runs` 搬出 state，N-09 那句改寫；看跑了幾次要開旗標 | 維持現狀，但 `counter_runs` 本來就不是重寫的原因，留著不多花寫檔 |
| **NORMS 05 窗細則 11-06 註（no-pid P5b）**：`responded_at`「身體跑完一次都更新」，算進有變才寫 | **這條就是每跑一次重寫的原因**。原則想省的寫檔，要碰這條才省得到 | 拿掉「身體跑完一次」這個觸發：閒置 loop 的 state 不再動；P7 要回歸 | 每跑一次都重寫一份 state；把 runs 搬去 .txt 也一次不會少 |
| **N-17**（判死活不設心跳、內容沒變就不碰檔、睡著時窗不動） | 不是使用者原則跟條文衝突，而是 P5b 跟 N-17 本來就有一點打架：`responded_at` 每跑一次就更新，實際上就是心跳 | 照原則改，等於把 N-17 的精神找回來 | 留著一個沒寫明的心跳 |
| **N-65 ②＋T7＋N2 裁定**（「看 daemon 表的 `_tick` 列與 `tick` 欄」） | `tick` 觀察值讓每台開了時鐘的 daemon 表每格重寫一次；要省就得拿掉或放到旗標後面，這會改到使用者 N2 裁定指定的「看哪裡」 | 表每格不動；想看時鐘就 `cat` 鐘檔，或看 `_clock` 列 | 每台每秒重寫一次表（三層樹就是每秒 3 次，加上身體觸發的） |
| **P7 使用者 11-06 晚裁**（父只看活著、只看公開 ctl／state 窗、不加宣告欄） | `responded_at` 是父判卡住唯一讀的欄（`stuck.cpp` 拿它跟 ctl 的 mtime 比），**不能搬去 .txt、也不能用旗標關掉** | — | 照留在 state.json；只能改它「什麼時候更新」（方向題 2） |
| **C-48 JSON 格式族**（除非必要不新增格式） | 每個計數器一個 .txt，算是新格式 | 輕微：N-13 本來就允許外顯檔自訂名字和格式（`stage.txt` 是先例），C-54 也定了純文字帶 `.txt` | — |
| **N-05**（給別人讀的檔先寫暫存再改名） | 換成 .txt 不會比較便宜：只要有人會讀，一樣要寫暫存再改名，一次寫的成本跟 json 差不多 | 省的是旗標關著時「不寫」，不是換格式本身。要不要讓計數器原地覆寫，是方向題 5 | — |
| **11-06 git-image**（`stack.gitignore` 留 state.json、procs_state.json、queue.json、stage.txt；11-07 #20-1 只給人看的紀錄只留原機器） | 熱欄讓 image 每次 commit 都有雜訊 diff；新的 .txt 計數器要不要進 image 得定 | 計數器只給人看，照 #20-1 排除 | — |
| **N-13**（state／ctl＝程式內部狀態的外顯，像 Plan 9） | 旗標預設關的話，跑了幾次預設就看不到 | debug 時要記得開旗標 | — |

不衝突、也支持這個原則的有：json-argv「argv＝method」、11-04「不該在 json 指定檔名，應該用旗標」、`--enable-logs` 預設關的先例、C-54 `.txt` 命名、「不寫遷移」（llm kernel 讀 `queue.json` 時缺 `counter_runs` 會報 `QueueBad`，直接改掉就好，不做相容）。**鐵律 6 wf-table** 管的是 wf 文件的條列，不管程式狀態，沒有衝突。**少用 sh** 也沒碰到。

## 二、不用新原則就能省的（照現有條文直接修）

- **`stage.txt` 有變才寫**：閒置時每秒 3 次都寫同樣的 `idle`。N-09 的精神已經涵蓋，可以直接做；判準是閒置的 fsm agent 這個檔每秒 3 次降到 0。
- **`queue.json` 的 `counter_runs`**：除了它自己沒人讀，是唯一讓它重寫的欄；搬出去（方向題 1）以後，閒置時每秒 3.3 次降到 0（`seen_at_*` 有信進出才變）。

## 三、方向題（推薦放第一）

### 題 1　什麼算「很頻繁」、要搬出 json？

**使用者 11-09 裁：照推薦。**

- **（推薦）判準兩條都要符合：①只因為時間過去或每跑一次就變（不是有事件才變）；②除了寫它的程式自己以外，沒有程式讀它。**符合的搬出去寫 `.txt`、放旗標後面。現在符合的有：loop／daemon state 的 `counter_runs`、llm kernel `queue.json` 的 `counter_runs`。有程式在讀的（`responded_at`、`tick`、`phase`）不搬，改它們「什麼時候寫」（題 2、3）。後果：原則有清楚的邊，P7 不受影響。
- 只要變得頻繁就搬，不管有沒有人讀。後果：`responded_at` 也得搬，P7 就壞了，違反 11-06 晚「父只看公開窗」的裁定。

### 題 2　`responded_at` 在身體每跑一次時更新，要不要拿掉？（這才是 state.json 每跑一次重寫的原因）

**使用者 11-09 裁：照推薦。**

- **（推薦）拿掉「身體跑完一次」這個觸發，只留 ctl 處理、收到信、起或收子項。**父判卡住只拿 `responded_at` 跟 ctl 的 mtime 比（讀過 `aos-daemon/src/daemon/stuck.cpp` 確認），而 loop 每圈都是先讀 ctl 再跑身體，所以有沒有身體觸發都不影響判斷。可執行判準：改完以後閒置 fsm agent 的 state.json 從每秒 3 次降到 0、總機 state.json 從每秒 3.3 次降到 0，而且 no-pid P9 的卡住相關實測列全部通過。後果：人不能再用 `responded_at` 看「最近還有沒有在跑」，要看就開題 4 的旗標。要改的是 P5b 那句條文。
- 照留。後果：每跑一次寫一份 state，原則在 state.json 上省不到東西。

### 題 3　daemon 表的 `tick` 觀察值

**使用者 11-09 裁：照推薦。**

- **（推薦）從 `procs_state.json` 拿掉，想看時鐘就讀鐘檔本身（`cat "$AOS_CLOCK"`）或看 `_clock` 列有沒有在跑。**後果：開了時鐘的 daemon 表從每格重寫一次變成不動；要把 N-65 ② 和 T7 那句「看 `tick` 欄」改掉，因為那是使用者 N2 裁定「靠表看」的落實。可執行判準：三層試驗場閒置時，根和領班的表從每秒 1 次降到 0。
- 留著，但只在旗標開著時才寫。後果：預設省下來，要看時多一個旗標。
- 照留。後果：每台開時鐘的 daemon 每秒多寫一次表。

### 題 4　旗標預設開還是關、叫什麼

**使用者 11-09 裁：照推薦。**

- **（推薦）預設不寫**，照 `--enable-logs` 的先例，各程式用同一個名字（例如 `--enable-counters`），走共用介面 `parse_cli`／`aos_flags`；寫的位置是 stack 裡的 `counter_runs.txt` 一類檔（一個計數器一個檔，名字照 C-54）。後果：沒人讀的東西預設不花寫檔；debug 時要記得開。
- 預設寫、旗標用來關。後果：行為跟現在最像，但省寫檔要每個定義都去加旗標，等於沒有原則。

### 題 5　.txt 計數器要不要照 N-05 先寫暫存再改名

**使用者 11-09 裁：照推薦。**

- **（推薦）照 N-05**，因為人可能正在 `cat` 它。省寫檔靠的是題 4「預設不寫」，不是換格式。
- 原地覆寫（N-05 只管給別人讀的檔，計數器只給人看，讀到半行可以接受）。後果：一次少一個 rename，但多一條「哪些檔不照 N-05」的例外。
