## 使用者拍板（10-16）

五件（稿裡「三分鐘看懂」那五件）使用者的回覆照錄。落成見 [CONCEPTS C-62](../docs/CONCEPTS/05-agent.md)、[NORMS N-53](../docs/NORMS/10-基礎設施-定義與工作區.md)、[N-54](../docs/NORMS/04-基礎設施-loop與daemon.md)。

1. **daemon 指令資料夾（N-10）留不留**——使用者：「不留」。→ N-10 整套刪；daemon 的子項由它 ctl 的 `children` 宣告「我要表上有誰」（N-54；`children` 進 ctl 算 N-11 的例外）；暫停某個子 loop＝直接寫它的 ctl；看它＝讀它的 state。（表 3.1、3.15）
2. **daemon 重起要不要接回子 loop**——使用者：「給選項，默認留」。→ 開關 `adopt`（布林，預設 `true`＝接回；旗標 `--adopt`）；心跳照留；table 窗併進 daemon 自己的 state 窗（N-28）。（表 3.3）
3. **loop 被 SIGTERM 退 0 還是 1**——使用者：「退0。應該說，SIGTERM之後，loop會做一些事情，然後再自己結束，也就是優雅收工。重點在於"把該做的事情做一做後，才結束"，不管有沒有事情要做，總之就是這樣。這塊也可以當原則」。→ 現行：N-52 作廢（10-19 使用者「都按照建議」，[ideas § 11](2026-10-19-ideas.md)），照 CONVENTION P-36「被外層逾時殺掉＝那格失敗」；「先收好子程式再結束」寫在 P-36。（表 3.10）
4. **agent 定義要不要含 loop、腦連錯要不要數**——使用者：「agent的定義就是一個狀態機，至於這個狀態機怎麼跑、由誰跑，都無所謂。這是概念。但是我們的規範會說，為了讓agent方便審視自己，所以agent就是一個被人驅動的狀態機，需要外面有人用loop驅動他。這是我們的aos agent，至於我們常見的claude code，他們就是一個process持續執行，那是他們愛的。」頂層確認「腦出錯那一拍退 1、phase 不動（同 N-38），重試幾次看外面 loop 的 times，agent 自己不數」——使用者：「可以。」→ 概念 C-62（agent 的定義＝一台狀態機，怎麼跑、由誰跑不管）；規範 N-53（aos 的 agent 是被外面驅動的狀態機，每次被叫走一拍、由外面的 loop 驅動；定義不含 loop；連錯不數）。（表 4.5）
5. **兩種 kernel 併不併**——使用者：「兩隻kernel不併成一支。」→ 維持 N-42 兩種兩支；彙整 5.1 撤回。（表 5.1）
