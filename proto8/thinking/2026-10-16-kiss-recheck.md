## 三分鐘看懂

把昨天那份大掃除清單用今天的尺重看了一遍。批次 2 幾乎全被「食譜＋廚房」取代；批次 3～6 裡有十幾項是在推翻你親手定的、而且刪了需求就沒人接，我把它們撤回了。**真正要你拍板的只有五件**，其他都標「照推薦、之後再看」，現在不用看。

1. **daemon 的指令資料夾（丟一個檔＝一條指令、回一個 `.done`）留不留？** 昨天推薦整套刪、改成在 ctl.json 寫「我要表上有誰」。我推薦**留，但瘦成只剩 add／remove 兩條**。理由：ctl.json 是整份蓋過去、兩個人同時寫會互相蓋掉，一檔一指令才能多人同時丟；其他指令只是替你寫子 loop 的 ctl，你直接寫就好。（這是你 10-12 定的 N-10。）**→ 使用者拍板：不留**（N-10 整套刪，見末尾）。
2. **daemon 死了重起，要不要接回舊的子 loop？** 昨天推薦接回、心跳、表窗整套刪。我推薦**接回與心跳留**（你說過審設計要考慮當機復原），只把表窗併進 daemon 自己的 state 窗、少一扇窗。**→ 使用者拍板：做成選項、預設接回**（見末尾）。
3. **loop 被 SIGTERM 停掉，退 0 還是退 1？** 現在 loop 退 1、daemon 退 0。但你定的 N-07 說「當場停＝送訊號」，照你對「正常退出」的定義（文件寫明的路）它該退 0。推薦**兩個都退 0**，哪個訊號照記在 state 窗。（翻你 10-15 晚「loop 退 1」。）**→ 使用者拍板：退 0，而且升成原則——收到 SIGTERM＝優雅收工**（見末尾）。
4. **agent 的定義裡要不要含 loop？腦連錯要不要數？** 推薦**不含 loop**、**不數連錯**（`halt_after`／`halt_state` 刪）。（翻你 10-15「連錯 3 次停住」。）**→ 使用者拍板：agent 的定義就是一台狀態機，怎麼跑、由誰跑概念上不管；aos 的 agent 是被外面驅動的狀態機，每次被叫走一拍、由外面的 loop 驅動；腦出錯那一拍退 1、phase 不動，重試幾次看外面 loop 的 `times`，agent 自己不數**（見末尾）。原推薦裡「`aos agent -` 自己一拍一拍跑到 end」不採用。
5. **兩種 kernel 併成一支？** 推薦**併**：通用 kernel 沒寫判官時就是「管 LLM 的那種」，「兩種」是兩種用途、不是兩支程式。（翻你 10-15「先做兩種」。）**→ 使用者拍板：不併，維持兩支**（見末尾）。

## 使用者拍板（10-16）

頂層把「三分鐘看懂」五件逐件白話講給使用者聽，他這樣回（原話照錄）。落成見 [CONCEPTS C-62](../CONCEPTS/05-agent.md)、[NORMS N-52](../NORMS/01-總則.md)、[N-53](../NORMS/10-基礎設施-定義與工作區.md)、[N-54](../NORMS/04-基礎設施-loop與daemon.md)；全部草稿、程式未改。

1. **daemon 指令資料夾（N-10）留不留**——使用者：「不留」。→ N-10 整套刪；daemon 的子項由它 ctl 的 `children` 宣告「我要表上有誰」（照彙整 3.1 原推薦，N-54）；暫停某個子 loop＝直接寫它的 ctl；看它＝讀它的 state。（表 3.1、3.15）
2. **daemon 重起要不要接回子 loop**——使用者：「給選項，默認留」。→ 開關 `adopt`（布林，預設 `true`＝接回；旗標 `--adopt`），取代原 `load`；心跳照留；table 窗併進 daemon 自己的 state 窗（N-28 改字）。（表 3.3）
3. **loop 被 SIGTERM 退 0 還是 1**——使用者：「退0。應該說，SIGTERM之後，loop會做一些事情，然後再自己結束，也就是優雅收工。重點在於"把該做的事情做一做後，才結束"，不管有沒有事情要做，總之就是這樣。這塊也可以當原則」。→ 總則 N-52：收到 SIGTERM＝優雅收工，先把該做的事做完、再自己結束、退 0，不管有沒有事要做都走這條路；翻 10-15 晚「loop、閘門、tasks 被訊號停掉退 1」（N-43 改）。（表 3.10）
4. **agent 定義要不要含 loop、腦連錯要不要數**——使用者：「agent的定義就是一個狀態機，至於這個狀態機怎麼跑、由誰跑，都無所謂。這是概念。但是我們的規範會說，為了讓agent方便審視自己，所以agent就是一個被人驅動的狀態機，需要外面有人用loop驅動他。這是我們的aos agent，至於我們常見的claude code，他們就是一個process持續執行，那是他們愛的。」頂層確認「腦出錯那一拍退 1、phase 不動（同 N-38），重試幾次看外面 loop 的 times，agent 自己不數」——使用者：「可以。」→ 概念 C-62（agent 的定義＝一台狀態機，怎麼跑、由誰跑不管）；規範 N-53（aos 的 agent 是被外面驅動的狀態機，每次被叫走一拍、由外面的 loop 驅動；定義不含 loop；連錯不數）。本稿原推薦的「`aos agent -` 自己一拍一拍跑到 end」不採用。（表 4.5）
5. **兩種 kernel 併不併**——使用者：「兩隻kernel不併成一支。」→ 維持 N-42 兩種兩支；彙整 5.1 撤回。（表 5.1）
