> 規矩：程式只准做日記裡出現過的事。日記裡沒有的，不做。

早上開電腦，systemd 把 aos daemon 起好。它只做一件事：每 5 秒對 `~/world` tick 一次。

```sh
$ ls ~/world
.aos  human  llm  painter-a  painter-b  scheduler
$ cat ~/world/.aos/tick.json
{"round": 1832, "at": "2026-10-12T08:01:05"}
```

我想要一張風景畫。寫一個檔丟給 painter-a：

```sh
$ echo '{"want": "風景", "style": "現代"}' > ~/world/painter-a/in/1832-1.json
```

接下來三個 tick，我什麼都不用做：

- 1833：scheduler 跑，看到 painter-a 的 `in/` 有 1 件、painter-b 0 件、llm 空著，寫 `.aos/order.json`：`["scheduler", "painter-a", "llm"]`。tick 照順序起 painter-a；它讀到我的檔，把要問模型的話寫到 `~/world/llm/in/1833-1.json`，然後退出。
- 1834：llm 跑，一次只處理一件（它 capacity 1），問完把回覆寫到 `llm/out/1834-1.json`，順手在 `llm/out/usage.json` 加一行 token 數。
- 1835：painter-a 讀到回覆，寫 `painter-a/out/1835-1.md`，退出。

```sh
$ cat ~/world/painter-a/out/1835-1.md
（一張風景畫的文字描述）
```

中午看了覺得 painter-a 風景畫得爛。它本來就擅長人物。我改它的標籤：

```sh
$ cat ~/world/painter-a/task.json
{"argv": ["python3", "run.py"],
 "axes": {...},
 "traits": {"good_at": ["人物"], "bad_at": ["風景"]}}
```

下午再丟一張風景需求進來——這次我丟到 `~/world/in/`？不，沒有這種地方。我丟給 scheduler：

```sh
$ echo '{"want": "風景"}' > ~/world/scheduler/in/1900-1.json
```

scheduler 看標籤，painter-a 說自己不擅長風景，painter-b 沒說，就把這件搬到 `painter-b/in/`。我沒寫這條規則，是 scheduler 的 `run.py` 裡本來就有一條「照 traits 分」。

傍晚 llm 太貴了。我開第二個資源：

```sh
$ cp -r ~/world/llm ~/world/llm-local
$ vim ~/world/llm-local/task.json     # model 改成本地的、capacity 改 2
```

下一個 tick 它就在了，不用登記、不用重啟。scheduler 看到兩個 `needs: llm` 能用的資源，便宜的優先——這條規則它也本來就有。

晚上我想知道 painter-a 這一步為什麼要問模型。看它的步驟：

```sh
$ cat ~/world/painter-a/steps.json
[{"llm": "prompts/understand.md"},
 {"llm": "prompts/draw.md"},
 {"argv": ["python3", "save.py"]}]
```

第一步「理解需求」其實用程式就能做（就是把 JSON 的 `want` 和 `style` 抄進提示）。我把它換掉：

```sh
$ vim ~/world/painter-a/steps.json
[{"argv": ["python3", "understand.py"]},
 {"llm": "prompts/draw.md"},
 {"argv": ["python3", "save.py"]}]
```

三個節點，現在只剩一個是模型。明天它畫得怎樣，我比較好猜。

睡前我想把今天這個世界留一份：

```sh
$ touch ~/world/.aos/snapshot        # 跟 tick 說：下回合停下來打包
$ ls ~/world/.aos/snapshots/
1832.zip  1990.zip
```

整天我只用了 `ls`、`cat`、`echo`、`cp`、`vim`。沒有一個 aos 指令。
