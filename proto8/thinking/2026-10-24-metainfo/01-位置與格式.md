<a id="1-放哪三處同一個名字"></a>
## 1. 放哪：三處同一個名字

| 函數長什麼樣 | `_metainfo` 放哪 |
|---|---|
| 資料夾程式 `X/` | `X/_metainfo`（跟 `X/_entry` 並列的檔，內容是 JSON） |
| JSON 物件（沒 `argv`、當資料夾，N-61） | `js["_metainfo"]`，跟 `js["_entry"]` 並列 |
| 單子（有 `argv`，含 loop／fsm `exec` 裡內嵌的） | 單子裡的 `_metainfo` key（10-13 D5 原本那處） |

- 資料夾那處沒有副檔名，跟 `_entry` 一樣只佔一層、跟 JSON 的一個 key 對上（C-71、C-72；使用者 10-19 § 17「還是_exec就夠了」不帶 `.json`）。**也收 `X/_metainfo.json`**，找法同入口（N-61：`XXX/$AOS_ENTRY` 沒有再找 `.json`）；兩個都在＝`_metainfo` 贏。
- 可執行檔入口（`_entry` 是 shell／python 腳本）自己沒地方放 JSON，就靠它所在資料夾的 `_metainfo`。

<a id="2-怎麼找跟找入口同一條路"></a>
## 2. 怎麼找：跟找入口同一條路

讀的人（kernel、閘門、工具）拿到 `aos-exec XXX` 的那個 XXX，照 N-61 找入口的同一條路往下走，**沿路遇到的第一份 `_metainfo` 就是這個函數的**，之後不再往下：

1. XXX 是資料夾 → 看 `X/_metainfo`、`X/_metainfo.json`；沒有 → 照 `$AOS_ENTRY` 走進入口。
2. 走到 JSON 物件（沒 `argv`）→ 看 `js["_metainfo"]`；沒有 → 取 `js[$AOS_ENTRY]` 繼續。
3. 走到單子 → 看它的 `_metainfo` key；沒有就是**沒說**。
4. 走到可執行檔 → 沒說（內容不讀，同 N-61）。
5. 字串轉向 → 接著走轉向的目標（同找入口）；`檔#/指標` → 從那個位置開始。

- **外層贏**：呼叫者叫的是 X，X 的作者寫的就是 X 對外的特性（C-52：呼叫者只看得到 X）；裡面各格自己的 `_metainfo` 是給叫那一格的人看的（例 fsm 的 think 格，見範例 3）。
- **名字固定 `_metainfo`**，不開 `AOS_METAINFO` 環境變數（C-69：aos 只訂那六個）。
- **`.env` 的限制**：`X/.env` 可以改 `AOS_ENTRY`，不是 aos-exec 的讀者通常不讀 `.env`，走到的入口可能跟真的不一樣。讀者第一版只照預設 `_entry` 走；要精準就用 aos-exec 的同一套程式（見 [02 § 5](02-誰讀與kernel接法.md#5-給-llm-kernel-實作者的接法)）。

<a id="3-內容通用-key全選填"></a>
## 3. 內容：通用 key（全選填）

**沒有必填**（D5 格式自由）；沒寫＝**沒說**，不等於「安全」「便宜」。下面這組是通用規範要規定的「大家常用的」，名字照 C-54（小寫底線、單位放字尾）；其餘 key 自由加，讀的人不認得就忽略（C-48）。

**數量類的雙形**（C-48 值的雙形、C-55）：寫數字＝典型值；寫物件＝`{"val": 典型值, "max": 上限}`，原值固定在 `val`，其他子 key（`min`、`p90`…）自由。

時間與資源：

| key | 值 | 意思 |
|---|---|---|
| `summary` | 字串 | 一句話說它做什麼（10-15 通用 kernel 第 1 題） |
| `time_ms` | 數量 | 跑一次多久（牆上時間） |
| `resource` | 字串或字串陣列 | 要佔哪幾種格：`llm`／`gpu`／`cpu`／`disk`／`net`／`human`（10-15），可自訂 |
| `mem_mb`、`gpu_mem_mb` | 數量 | 記憶體、顯示記憶體峰值 |
| `llm_calls`、`llm_tokens` | 數量 | 跑一次問幾次腦、總共多少 token |
| `lock` | 字串陣列 | 獨佔資源名：名字相同的函數同時只跑一個（例 `"ws:/home/me/proj"`） |
| `cost` | 數量 | 相對成本，越小越便宜，單位由 kernel 定 |

行為（九軸裡 kernel 用得上的幾軸）：

| key | 值 | 意思 |
|---|---|---|
| `side_effect` | 布林 | 會不會動到自己 stack 以外的東西（工作區、別的檔、外部服務） |
| `idempotent` | 布林 | 同樣的輸入重跑一次，結果跟跑一次一樣 |
| `deterministic` | 布林 | 同樣的輸入每次輸出一樣（問腦的通常 `false`） |
| `interrupt` | 字串 | 被殺掉會怎樣：`safe`／`unsafe`／`resumable` |
| `parallel` | 布林 | 同一個函數可不可以同時跑好幾份 |

- **`priority` 不放這裡**（M5）：`priority` 跟著請求、由呼叫者（閘門）填（10-15 的分工），`_metainfo` 從不蓋過 `level`。
- 九軸其餘幾軸（I/O 型態、生命週期、組合模式、環境模式）先不列通用 key，要用的人自己加；kernel 用到了再收進來。錯誤路徑評估（NORMS 待定）同理。

<a id="4-三個完整範例"></a>
## 4. 三個完整範例

**範例 1：python 小工具** `tools/pyfmt/`（`_entry` 是 python 腳本，`tool.json` 給模型看）——`tools/pyfmt/_metainfo`：

```json
{"summary": "把一個 .py 檔照 PEP8 排版，原地改寫",
 "time_ms": {"val": 300, "max": 5000},
 "resource": "cpu",
 "mem_mb": 50,
 "side_effect": true,
 "idempotent": true,
 "deterministic": true,
 "interrupt": "unsafe",
 "parallel": true}
```

**範例 2：agent-dan** 整個資料夾——`agent-dan/_metainfo`（外層贏：叫 `aos-exec agent-dan` 的人看到的就是這份）：

```json
{"summary": "回答工作區 new/ 裡的題目；會問腦、叫 clock 與 math",
 "time_ms": {"val": 30000, "max": 600000},
 "resource": ["llm", "cpu"],
 "llm_calls": {"val": 3, "max": 40},
 "llm_tokens": {"val": 6000, "max": 80000},
 "side_effect": true,
 "idempotent": false,
 "deterministic": false,
 "interrupt": "resumable",
 "parallel": true,
 "lock": [{"$env": "AOS_WS", "$prefix": "ws:"}]}
```

`llm_calls.max` 40＝loop.json 的 `max`；`resumable`＝狀態都落在 stack，殺掉再叫會接著做；同一個工作區只能有一份在跑，用 `lock` 說（不同工作區可以並行，所以 `parallel` 是 `true`）。

**範例 3：問腦的單子**——agent-dan 的 `fsm.json` 裡 think 格內嵌的單子：

```json
"think": {"exec": {"argv": ["python3", "brain.py"], "timeout_ms": 120000,
                   "_metainfo": {"summary": "問腦一次",
                                 "time_ms": {"val": 4000, "max": 120000},
                                 "resource": "llm",
                                 "llm_calls": 1,
                                 "llm_tokens": {"val": 2000, "max": 8000},
                                 "side_effect": false,
                                 "idempotent": false,
                                 "deterministic": false,
                                 "interrupt": "safe"}},
          "next": "act"}
```

`idempotent: false`：重跑會在 `history.jsonl` 多接一則。這份不會被叫 `aos-exec agent-dan` 的人看到（外層有寫）；要排進 LLM kernel 時，`_metainfo` 要寫在**閘門寄出去的那張單子**裡（kernel 看的是信裡的單子，見 [02 § 5](02-誰讀與kernel接法.md#5-給-llm-kernel-實作者的接法)）。

<a id="5-版本演進"></a>
## 5. 版本、指示詞、共用

- **版本演進**：不加 `ver`、`_type`、`_version` 之類的 key。只加 key；要改一個 key 的意思就取新名字，舊的照樣讀得懂。
- **指示詞**：`_metainfo` 裡可以用 `$env`／`$ref`（N-45：aos 讀的 JSON 都解），由**讀它的那支程式**解（每支程式只解自己讀的格），aos-exec 不解（它不讀）。`$env` 能用但少用：特性是定義的固定屬性，跟著環境變就不好比對（範例 2 的 `lock` 是少數合理的用法）。
- **共用**：可以整份 `$ref`，也可以用 `$ref` 陣列「底稿＋自己的」（10-23：物件合 key、後面蓋前面），例 `"_metainfo": {"$ref": ["../meta/llm-call.json", "think-meta.json"]}`；相對檔名從寫著它的那份檔所在的資料夾算。
