## A. N-36 分岔的格式（結論）

1. **`next` 兩種寫法，舊的照舊**：字串＝原本的意思（格退 0 才走過去，其他碼 state 不動、fsm 以那個碼退出）；**物件 `{結束碼: 狀態名, …}`**＝照格的結束碼查表走。key 是十進位整數的字串（`"0"`、`"10"`、`"1"`、`"143"`）或 **`"*"`**（其餘全部；照 Unix `case` 的 `*)` 老慣例，C-54 查過就用）；值是表上的狀態名，規則同字串 `next`（非空、頭尾沒空白、沒換行、要在表上）。例：

   ```json
   "idle": {"exec": ["idle", {"$env": "ROUND_AGENT"}], "next": {"0": "think", "10": "idle"}}
   ```

   這是 C-55「純值不夠用就長成物件、key 不變」的一次套用：`next` 這個 key 不變，值從一個名字長成一張小表。不另開 `on_code`、`branches` 之類的新 key（C-56）。
2. **查得到＝這一步正常**：格退 c，表上有 `"c"`（或沒有 `"c"` 但有 `"*"`）→ 把那個狀態名寫進 state（N-05 先寫暫存再改名）、**fsm 以 0 結束**；**查不到＝跟現在一樣**：state 不動、fsm 以 c 結束（loop 看到 10 就停、看到其他非 0 就失敗停下，P-19／P-20 原樣）。理由：N-43「每層只說自己」——表上寫了那個碼怎麼走，fsm 就是照表走了一步，對外面的 loop 來說這一步是正常的；沒寫的，fsm 不知道怎麼辦，照舊透明轉交。「透明轉交」這個例外從「一律」改成「表上沒接住的才轉交」。
3. **跟 N-43 現有的碼怎麼對**：不加新碼、不改 10 的意思。`0`＝這一步好了；`10`＝「正常，但這一步到此為止／沒事可做」（agent-round § 3 早就把 10 統一成這個意思）；其他非 0＝錯。分岔只是讓「10 之後往哪走」「錯了往哪走」可以寫在表上。aos-round 的範本表**只用 0 與 10**（見 B），不發明 11、12——照使用者 10-15「結束碼不要太依賴」。把錯誤碼（`"1"`、`"143"`）寫進表、導回自己或導到善後格，**不禁止、風險自擔**（N-38 ⑥：無窮轉移只有 loop 的 `max` 擋；N-18 使用者自行承擔）——這是 P-20「預設停」的門從表上打開，見衝突 3。
4. **物件至少要有 `"0"` 或 `"*"`**（開跑時查整張表，N-36 既有的規矩）：少了＝表壞、退 1、不跑格。理由：退 0 查不到就會「state 不動、fsm 退 0、loop 下一次又跑同一格」——等於偷渡乙案「成功但留在原地」，使用者已說不走，表上不准寫得出來。
5. **跟 P-36 巢狀、逾時殺整群怎麼對**：不變。被外層 `timeout_ms` 收掉的格碼是 128＋訊號，表上**沒寫**它就照 P-36＝失敗、state 不動、上面停；表上寫了 `"143"` 或 `"*"` 就會接住——條文寫明「`*` 也接得住 128＋N，要不要接是你的事」，範本表不接。fsm **自己**收到 SIGINT／SIGTERM／SIGHUP 的例外照 N-38：那格跑完照表寫 state（含分岔）、然後以 128＋N 結束、不以 0 結束。
6. **trace 怎麼記分岔**：trace 每行**加一個 `next`**＝這次寫進 state 的狀態名，沒換狀態＝`null`。欄位變成 `{"started_at","state","code","signal","elapsed_ms","next"}`，字串 `next` 的格也記（0 → 名字、其他 → null），一致。理由：P-38 看樹就看 trace；有分岔後光看 `code` 推不出走到哪（表會改），一個欄位省掉對表。名字照表的 key（C-54 一詞一義）。頂層代定、可翻案（N-39 字面要加註，見衝突 5）。
7. **aos-loop 不改**。loop 看到的仍是 fsm 的碼：0 繼續、10 停（退 0）、其他停（退那個碼）。ctl 的 `paused`／`stopped` 每格之間都看一次（loop 本來就一次一格）。

## B. aos-round 長什麼樣（結論）

**一句話（C-54 R1）**：`aos-round <agent 資料夾>` ＝ 把 agent 的「一輪」跑一格：拿 `lib/agent/round/` 裡的那張 fsm 表交給 aos-fsm，表上的每一格是薄薄一支程式、只叫 agent 自己登記的器官（queue／history／endpoint／act／hook）。外面照舊由 agent 的 `loop.json`（aos-loop）一次一次叫它、開 ctl／state 窗。

1. **形狀＝一支小程式 ＋ lib 裡兩張 fsm 表 ＋ 五個薄格**。
   - **`proto8/bin/aos-round`**（跟 aos-parts、aos-tools 同一層；Python）：收一個參數 agent 資料夾（存在的絕對路徑，`AgentBad`）；用 `aos-parts --file <agent>/parts.json which --json round` 拿 `round` 槽的 `env`（`ROUND_ON_EMPTY`，預設 `stop`；`MAX_RETRIES` 照舊）；設 `ROUND_AGENT=<agent>`；`exec` 成 `aos-fsm <lib>/round/fsm-stop.json` 或 `fsm-idle.json`。沒有旗標（N-11 新程式盡量不收旗標）、不開窗、不寫檔；自己的錯一行 `aos-round: 代號 原因`、退 1。aos-fsm 的碼就是它的碼（exec 成它，透明）。
   - **兩張表**（`lib/agent/round/fsm-stop.json`、`fsm-idle.json`），只差 idle 那格接不接 10：

     ```json
     {"start": "idle",
      "states": {
        "idle":   {"exec": ["idle",   {"$env": "ROUND_AGENT"}], "next": {"0": "think"}},
        "think":  {"exec": ["think",  {"$env": "ROUND_AGENT"}], "next": {"0": "act", "10": "finish"}},
        "act":    {"exec": ["act",    {"$env": "ROUND_AGENT"}], "next": {"0": "think", "10": "more"}},
        "more":   {"exec": ["more",   {"$env": "ROUND_AGENT"}], "next": {"0": "act", "10": "act"}},
        "finish": {"exec": ["finish", {"$env": "ROUND_AGENT"}], "next": "idle"}}}
     ```

     `fsm-idle.json` 的 idle 是 `{"0": "think", "10": "idle"}`。`exec` 陣列的第一個是格的相對路徑，從表所在的資料夾算（N-36：`exec` 的相對路徑從 cwd 算、aos-exec 表檔時 cwd＝表的資料夾；aos-round exec aos-fsm 前先 cd 到 `lib/agent/round/`）；`{"$env": "ROUND_AGENT"}` 是 N-45 的指示詞、argv 陣列裡本來就能放（P-40）。agent 資料夾照 10-28 衝突 1 仍是每格的第一個參數，只是從表上經環境變數帶進去（P-39「往下只流環境變數、別的都明給」——明給的就是這個參數，變數只是表寫得出來的辦法）。
   - **五個薄格**（`lib/agent/round/{idle,think,act,more,finish}/_entry`，Python；現有 `_entry` 的函數搬成同資料夾的 `roundlib.py` 共用，叫格的方式、trace 以外的代定 28～38 照舊）：

     | 格 | 做什麼（都是叫 agent 的器官） | 退 0 | 退 10 | 其他 |
     |---|---|---|---|---|
     | `idle` | `cur/` 有信＝補認領（`queue claim`，不叫 `pre_round`）；沒有＝`hook/pre_round` → `queue claim` | 認到了 | queue 空 | 格的錯 |
     | `think` | `hook/pre_think`（有掛就重讀 history）→ `endpoint/<目前>` → 失敗問 `hook/on_error`（retry／switch 在格內數，`MAX_RETRIES`）→ `hook/post_think` → `history append` → `queue emit` | 那則 assistant 有 `tool_calls` | 沒 `tool_calls`（該交卷了） | `EndpointFailed` 等 |
     | `act` | 最後一則 assistant 還有沒回的 `tool_calls` 才叫 `act`，吐的 tool 訊息逐則 `history append`；沒有要跑的＝什麼都不做退 0 | 跑完（或沒事） | act 退 10＝插話（`on_interrupt` 說打斷） | 格的錯 |
     | `more` | `queue claim --more`（把插進來的那封接進 history） | 接到了 | 沒信（搶輸了） | 格的錯 |
     | `finish` | `queue finish`（stdin＝那則 content）→ `hook/post_round` | 收掉了 | — | 格的錯 |

2. **round 的順序怎麼對成格與分岔**：一輪＝idle → think → (act → think)* → finish → idle，跟 agent-round § 2 的順序一樣，只是「下一步是什麼」從 round 的 `where()` 搬到了表上，「現在在哪」從重算改成讀 `$AOS_STACK/state.txt`（fsm 的，N-39）。**每格對 state 與資料不一致要能自保**（N-38「半成品由格自己看自己的檔判斷」）：state 說 act、history 最後一則卻沒待回的 `tool_calls`＝act 退 0 直接去 think；state 說 finish、`current.txt` 空＝finish 退 0（沒東西可收）；state 說 idle、`cur/` 有信＝補認領。這樣 P-20「人修好再跑一次、從 state.txt 接著做同一格」直接成立，不用另一套判斷。
3. **五個難點各怎麼靠分岔解**：
   - **idle 等（不阻塞）**：idle 格 queue 空退 10。`fsm-idle.json` 接住 `"10": "idle"` → fsm 退 0 → loop 隔 `interval_ms` 再叫一次（反應時間＝`interval_ms`，agent-lifecycle 衝突 6 已定）；`fsm-stop.json` 不接 → fsm 退 10 → loop 退 0、停。`ROUND_ON_EMPTY` 的兩個值就是這兩張表。
   - **插話**：act 格裡 `act` 器官退 10（它在兩批工具之間看了 `queue/new/`、`hook/on_interrupt` 說打斷）→ act 格退 10 → `more` 接進那封 → 回 act 把剩下的工具跑完 → think。act 的 10 不再到 loop 手上（隊長難點 2 的「包一層轉碼、加一格和記號檔」只剩表上一行）。
   - **答完一題就停**：`fsm-stop.json`＝答到 queue 空就停。`ask_round` 用自己的小工作區、一次放一題，所以「queue 空」就是「答完這一題」，兩者在它身上等價；`ROUND_ON_EMPTY=stop` 的常駐 agent 收到連續幾題會一口氣答完才停，這跟現在 round 的行為一樣。「不管 queue 還有沒有、嚴格一題一停」沒有人需要，不加（C-56）——見方向題 2。
   - **retry／switch**：留在 think 格**裡面**（一次問腦最多重來 `MAX_RETRIES` 次，計數在行程記憶體、用完 `EndpointFailed` 退 1），跟現在 round 一樣、不落檔。理由：N-38 允許「想優雅處理的格自己接錯」，這是格內的事；不把重試寫成表上的 `"1": "think"`（那是沒上限的自動重試，只有 loop 的 `max` 擋，跟 N-53「agent 自己不數連錯」的精神打架，見衝突 3）。think 退 1 → 表上沒接 → fsm 退 1 → loop 停下等人（P-20 預設）。
   - **trace 撞檔**：**格不寫 trace，fsm 的一格一行就是 aos-round 的 trace**（加了 `next` 欄之後一行看得出走到哪）。round 現在的 `{"unit"}` 行退場；端點換到哪看 `endpoint.txt`、用量看 `usage.jsonl`、工具呼叫看各工具小格的 trace（P-38 stack 樹）。一個 stack 一種 trace 形狀，`find … | sort` 照舊（見衝突 5）。
4. **退場的東西**：`hook/pause`（它的工作「一輪中途讓出、好讓 loop 看 ctl」現在每格之間 loop 本來就看）、`round --step`（fsm 一次一格就是 step）、round 的 `unit` trace、`where()`。`hook/pre_round`、`pre_think`、`post_think`、`post_round`、`on_error`、`on_interrupt`、`pre_tool`、`post_tool` 都照舊（在對應的格或 act 器官裡）。

## D. 「拆散放進每一格」那條路（一段話）

就是 agent-dan-q 現在的長法：agent 資料夾裡自己寫一張 `fsm.json`、每格是自己的程式（認領、問腦、跑工具各寫一支或合寫），不經 aos-round、不一定有 `parts.json`，round 的順序與判斷散在各格裡。**什麼時候用**：這隻 agent 的「一輪」跟範本不同形（多一格審稿、腦不是 OpenAI 訊息、沒有 history、要在兩格之間插自己的狀態），aos-round 那張表擺不下的時候；代價是每隻自己維護一份順序，aos-round 改了它不跟。有了分岔之後，這種 agent 也能用物件 `next` 接 10、寫善後格，不必像以前只能排成一直線。不做範本、不寫條文，demo/agent-dan-q 就是例子。

3. **表上可以把「錯」導回同一格，等於從表上開了一扇自動重試的門。** P-20、N-53 說 agent 失敗就停下等人、自己不數連錯、重試幾次看外面。分岔讓人可以寫 `"1": "think"`——錯了就再問一次，而且沒有上限（只有 loop 的 `max` 擋）。**各選項後果**：(甲) 條文只准接 0 與 10、錯誤碼不准寫進表——乾淨，但你說的是「依據不同結束碼導向不同分支」，自己又把一半的碼關掉，而且善後格（錯了去清東西再停）也寫不出來。(乙) 准寫、風險自擔——跟 N-38「想優雅處理的格自己接錯」同一個精神，只是從格內搬到表上；範本不這樣寫，所以預設行為沒變；想無限重試的人要自己知道 `max` 是唯一的煞車。**建議：乙**，P-20 加註「表上沒接住時才是預設停」。 **已定：照建議（使用者 10-30「都照建議」）。**
4. **round 本來故意不設狀態檔，現在「我在哪」變成 fsm 的 `state.txt` 說了算。** 10-28 代定 29、30 是「看 `cur/` 跟 history 最後一則就知道接著做什麼，不另設狀態檔」；搬進 fsm 後 `state.txt` 多了一份真相，兩邊可能對不上（例如 state 說 act、history 卻沒有待回的工具）。**後果**：沿用舊做法＝fsm 的 state 只是擺設、每格還是重算，那就不是薄殼；改成 state 為準＝每格要對「state 跟資料對不上」自保（沒事做就退 0 往下走），這正是 N-38「半成品由格自己看自己的檔判斷」原本就要求的；好處是 P-20「人修好再跑、從 state.txt 接著做」對 round 也成立，跟 agent-dan 一個樣。**建議：state 為準、格自保**（B 第 2 點）。 **已定：照建議（使用者 10-30「都照建議」）。**
5. **trace 從「每叫一個器官一行」變成「每格一行」，而且 fsm 的 trace 多一個欄位。** 現在 round 的 trace 看得到 `queue claim`、`endpoint/litellm`、`hook/post_think` 一行一行；換成 fsm 之後一格一行（`idle`、`think`…），器官層的細節沒了；N-39 定的 fsm trace 五個欄位也要加 `next`，`test_fsm` 與看 trace 的工具（nvim 外掛、demo 的 run.sh）要跟著看。**各選項後果**：(甲) 只留 fsm 的行——一個 stack 一種 trace 形狀，`sort` 照舊，想看哪個端點看 `endpoint.txt`、用量看 `usage.jsonl`；(乙) 格也寫自己的 `unit` 行到同一個檔——細節都在，但同一個檔兩種形狀、兩種時間格式（現在就是 `Z` 對 `+00:00`），讀的人要分。**建議：甲**，`next` 欄加上。 **已定：照建議（使用者 10-30「都照建議」）。**
6. **`hook/pause` 與 `round --step` 退場，10-28 的掛勾表與代定 27 要劃掉。** 它們的工作（讓 loop 有機會看 ctl、一次只做一步）在「loop 一次叫一格」的形狀下是天生的。**後果**：留著＝多兩個沒人用的開關；拿掉＝agent-round § 3 的表少一列、代定 27 作廢，現有範本沒有人掛 pause、`--step` 只有測試在用。**建議：退場**。 **已定：照建議（使用者 10-30「都照建議」）。**
7. **`timeout_ms` 從「管一輪」變成「管一格」。** agent-nia 的 `loop.json` 寫 600 秒本來是一整輪的上限，現在同一個數字只管一格（think 那格含問腦）。**後果**：數字不改＝每格最多 600 秒、一輪沒有上限（一輪的長短由腦決定，本來就不太能定）；要整輪上限得在外面再包一層（P-36 外層包內層）。範本照舊寫 600 秒、README 講清楚它管的是一格。**建議：照舊數字、改說明**。 **已定：照建議（使用者 10-30「都照建議」）。**

## 方向題（原則推不出的，附背景例子）

1. **agent 要不要能自帶一張 round 的表。** 背景：aos-round 固定用 `lib/agent/round/` 的兩張表；某隻 agent 想在 think 跟 act 之間多一格「審稿」（例如叫另一個腦看一眼再放行工具），現在只能走 D「拆散」自己寫整張 `fsm.json`、每格自己維護。另一條路是 `parts.json` 多一個槽 `round/fsm` 指自己的表、格仍用 lib 的五個——只改表、不重寫格。**兩條路**：(甲) 現在不開，要客製就走 D，aos-round 保持只有兩張表；(乙) 開這個槽，aos-round 多讀一個 key。**建議：甲**，等真有一隻 agent 需要再開（C-56 不為還沒發生的事加機制）；寫在這裡是因為「要不要留這個口」是產品範圍、不是原則能推的。 **已定：照建議（使用者 10-30「都照建議」）。**
2. **要不要「不管 queue 還有沒有、答完一題就停」這個嚴格版。** 背景：`ROUND_ON_EMPTY=stop` 是「答到 queue 空才停」；ask_round 一次只放一題，兩者等價。但如果有人往一隻 stop 模式的 agent 一次塞三題再 `aos-exec` 它，它會三題都答完才回來，不是答一題回來一次。要嚴格版得在表上多一格或讓 finish 退 10、再被 loop 停（但那樣 state 會停在 finish 而不是 idle，違反 P-34「正常結束 stack 要停在起點」），都不乾淨。**建議：不做**；真要「一次只處理一題」的人用 loop 的 `max` 或一次只塞一題。 **已定：照建議（使用者 10-30「都照建議」）。**
3. **舊 round 骨架要不要留一陣子並存。** 背景：C 的建議是六步內換完、最後一步刪掉 `aos-parts run round` 這個叫法；期間（第 2～5 步）新舊都跑得動。另一條是刪掉的那步不做、留著當「不用 fsm 的對照版」。**後果**：留＝兩套各自長、改器官介面要改兩邊（C-52 一件事寫一處）；刪＝要回頭看舊版去 git log。**建議：換完就刪**。 **已定：照建議（使用者 10-30「都照建議」）。**
