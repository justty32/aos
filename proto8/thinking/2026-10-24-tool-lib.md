**重複**：讀檔、寫檔、改檔三處（pyfix 子工具、pi-tools、file-tools 的 view）；列資料夾兩處（pyfix `list_files`、file-tools `ls`；pi 靠 bash）；改 JSON 三處（file-tools `json_edit`、aos-json 的 `json`／`json_edit`、ai_tools 的 `edit` 接口）；跑 python 三處（pyfix、gus 的 `run_python`、self-improve 的 `try_run`）；`math`、`clock` 複製四份；「放題、等答案」兩處（human、aos-ai）。

**不一致**：參數名（`old`／`new` 對 `edits[{old_text, new_text}]`；`timeout` 對 `timeout_s` 對 cli.json 的 `timeout_ms`）；錯誤怎麼回（只 stderr／stderr＋stdout 同一行／stdout `{"error"}`／stdout「錯誤：…」退 0／`{"ok": false}` 退 0）；**模型給錯參數算不算工具失敗**（pi、dan：退 1；eve 子工具、meg、talk、gus、ai_tools：退 0 讓腦自己改）；根（`$AOS_WS`／`$PYFIX_DIR`／`$AOS_AI_ROOT`／`$AOS_HEAP`／stack）；輸出（文字對 JSON）；共用程式碼（自成一格／`common.py` 經 sys.path／`../../cli_session.py`）；引用方式（整個 `tools` 一條捷徑／一條捷徑一個工具／複製）；逾時預設（10／30／60 秒）與上限（60／120／300）；截斷（100 KB／2000 行 50 KB／20000 字／8000 字）；只有 10-24 `_metainfo` 規劃之後的工具才有特性。

**缺口**：沒有一處索引列出所有工具；沒有形狀檢查（tool.json 寫錯只有腦叫下去才知道）；沒有「工具＝函數」的契約文件（P-41 只定了介面那一句）；沒有版本與覆寫的說法；repo 外的 agent 怎麼掛庫。

## 設計（用 aos 自己的話講）

- **agent＝函數**（C-46、C-68：一個資料夾，呼叫時不變）；**工具＝它內部呼叫的外部函數**（C-42「被引用的標頭檔」、C-61 工具是資料夾程式放 `tools/<名>/`）；**函式庫＝這些外部函數收成一份、被引用而不是被複製**（C-40「引用一個設好的資料夾，不複製，執行環境在引用者這邊」）。
- **一個工具＝一個 aos 函數＝一個資料夾**，三個檔：`_entry`（aos-exec 跑）、`tool.json`（給模型，P-41）、`_metainfo`（給 kernel 與人，M1 資料夾那處、M10 跟 tool.json 分開）。照[函數成長](2026-10-24-fn-grow.md)它們是第 4 級（資料夾、不只入口）；裡面長出 loop／fsm、各格是子函數＝第 5 級，那就是高層（agent 層）的工具。
- **分層（每層只依賴下層）**：

  ```
  demo/agent-*/              最上層：agent（函數）
    tools/<名> ─捷徑─▶ lib/<層>/<名>/
  lib/agent/                 高層：裡面是一整隻 agent 的工具（pyfix、thought、claude／codex）［還沒收］
  lib/aos/                   中層：動 aos 自己東西的工具（heap 記憶、寄信、say／listen、spawn／ask／status）［還沒收］
  lib/base/                  底層原語：檔案、資料夾、JSON、行程（bash）——只靠 Linux＋Python 標準庫、只碰 $AOS_WS
  impls/                     基礎層與標準庫（C-74）：aos-exec、loop、fsm、daemon
  ```

  層名＝資料夾名（`base`、`aos`、`agent`），不進工具名；只建有東西的層。跟 C-74 的關係：C-74 是 aos 本身的分層（誰依賴誰），lib 整個在它的最上層（agent）那一格裡，lib 自己再分三層。
- **統一契約**（全文在 [lib/README](../lib/README.md)）：stdin 一份 JSON 物件、key 小寫底線、單位放字尾；stdout 整段是結果（文字或一行 JSON）；錯＝stderr 一行 `工具名: 代號 原因`＋stdout 同一行、退 1，代號照 C-54 四種；**參數給錯也退 1——停下還是回給腦由叫它的 agent 決定**（dan 停、pip 回給腦），工具不替它決定（C-52、C-53 入口檢查）；被跑的指令退非 0 是結果不是錯；沙盒只有 `$AOS_WS`（要別的根＝呼叫者 `aos-exec --ws`，C-66）；會跑東西的一定有 `timeout_s`、整群收；寫檔先暫存再改名（N-05）、全有或全無；上限 2000 行／50 KB、500 項、4 MB，超過就說怎麼接著拿；base 層不用 stack；一個工具自成一格、不 import 隔壁。
- **怎麼引用——比較後選「一條相對捷徑一個工具」**：

  | 做法 | 好 | 壞 | 結果 |
  |---|---|---|---|
  | 整個 `tools/` 一條捷徑指庫（agent-pip 10-24） | 一行 | 不能挑、不能混自己的工具、不能覆寫 | 不選 |
  | **`tools/<名>` 一條捷徑指 `lib/<層>/<名>`**（agent-kai 10-24 已這樣掛 read） | agent 的 brain／act 一個字不改（照舊讀 `tools/*/tool.json`、`aos-exec tools/<名>`，P-25、P-33 地址零個 `..`）；aos-exec 走進真資料夾（N-57、N-59，實測 cwd、`AOS_CD` 是庫的位置）；要哪些掛哪些、自己的（真資料夾）與庫的並存、同名自己的贏＝覆寫；agent 不知道是庫的（C-52）；C-61 本來就允許「相對捷徑、兩份一起搬也不斷」 | 只有 Linux（10-19 使用者「先只考慮在linux上」）；repo 外要絕對路徑；複製 agent 要 `cp -a` | **選** |
  | `tools.json` 清單（名→路徑） | 不靠檔案系統、可寫在大 JSON 裡 | 要改範本的 brain、act 兩支，每個照抄 dan 的 agent 都要跟；地址帶 `..` | 不選（KISS：現有機制夠） |
  | `tools/<名>/_entry` 寫 JSON 字串轉向（N-61） | aos-exec 原生支援 | `tool.json` 還是得複製一份、`_metainfo` 也是；等於半複製 | 不選 |
  | PATH | — | C-61 已否決 | 不選 |
  | `$ref` | — | 是拆檔用的內容引用，不是位置（C-48） | 不選 |

  **版本與覆寫**：版本＝git（庫改了，掛著的 agent 下次跑就是新的）；要釘住某版＝複製進自己的 `tools/`（＝覆寫＝自己維護）。不另做版本號（M9 同理：不加 `ver`）。
- **跟既有原則對照**：沒有硬衝突。擦邊兩處——P-25「demo 之間不跨 agent 互指、各複製一份」是 10-19 為了 demo 寫的；庫就是為了不複製，捷徑是 C-61、P-33 本來列的第二條路。P-33「不給程式根變數」照守：捷徑不需要知道 agent 的根。
- **命名**（C-54）：`lib`（abbr.json 已有）、層 `base`／`aos`／`agent`；工具名一個動詞（`read`、`ls`）或主題在前（`json_read`、`json_edit`）；pi 的四個照原名（模型本來就認得，C-54 例外「工具自己的慣例照工具」）；eve 子工具的 `read_file`、`write_file`、`edit_file`、`list_files` 在庫裡就是 `read`、`write`、`edit`、`ls`；參數 `timeout` → `timeout_s`（R6 單位放字尾）；代號新加 `PointerBad`、`PointerMissing`（JSON 指標）。

### 代定清單（照推薦定、可翻案）

1. 位置 `proto8/lib/<層>/<名>/`，層名 `base`／`aos`／`agent`；只建有東西的層。翻案判準：第二層收進第一個工具時覺得名字拗口就改，那時連結還少。
2. 一個工具固定三個檔（`_entry`、`tool.json`、`_metainfo`），形狀由 `test_lib.py` 守。
3. 參數 stdin JSON 物件、小寫底線、單位字尾（`timeout_s`）。
4. 錯一律退 1＋stdout 同一行；代號 C-54；停或回給腦是 agent 的事（不在工具）。翻案後果：改成「模型的錯退 0」就得在每個工具裡分「誰的錯」，而且 dan 式的 agent 會把錯當結果交出去。
5. 沙盒只認 `$AOS_WS`；換根用 `aos-exec --ws`。
6. 逾時 `timeout_s`、預設與上限各工具自訂寫進 `tool.json`；整群 TERM→KILL。
7. 上限 2000 行／50 KB（read、bash）、500 項（ls）、4 MB（json）；超過就說怎麼接著拿。
8. 引用＝一條相對捷徑一個工具；同名自己的贏；版本＝git、釘版＝複製。
9. 自成一格、不 import 隔壁；共用庫等到第三份一樣的大段再抽（STRUCTURE 膨脹即拆）。
10. base 不用 stack（純函數）；中層以上才用小格留東西。
11. 命名：工具名一個動詞或主題_動詞；pi 四個照原名；eve 式的 `read_file` 改 `read`。
12. 跟函數成長一致：庫裡的工具是第 4 級；長出 loop／fsm 就是第 5 級、歸 agent 層。縮回不自動。
13. 示範 agent 叫 `agent-liv`；只掛庫、不改範本程式。
14. file-tools、aos-json 做好後**換實作不換介面**：`ls`、`json_read`、`json_edit` 的 `tool.json` 不變，`_entry` 可換成叫 `aos-json`（C++）。

## 邊緣狀況（攤出來，不擋）

- **捷徑只有 Linux**；repo 在別的檔案系統 checkout 會變成普通檔，agent 叫工具時 aos-exec 讀到一個不是 JSON 的小檔＝`EntryBad`。10-19 使用者「先只考慮在linux上」。
- **複製 agent 時捷徑會被解開**：`cp -r`、`shutil.copytree(symlinks=False)`（aos-ai 的 `spawn` 用的）會把庫的工具複製成真資料夾——行為一樣，但那隻就不再跟著庫更新；要保留捷徑用 `cp -a`／`symlinks=True`。
- **庫一改全部的 agent 立刻變**（沒有版本釘），好處與風險同一件事；要釘住的複製一份。
- **工具的 `AOS_CD` 是庫的位置**（aos-exec 解開捷徑）：工具若想找「掛它的那隻 agent 的檔」找不到——本來就不該（C-52）。
- **bash 擋不住出工作區**、**stack 在工作區裡時腦改得到自己的 history**（pi-tools 紀錄已列）；要隔離靠容器、或把 `AOS_STACK` 放工作區外。
- **json_edit 會換排版**（縮排 1 格）；`set` 到不存在的中間層會建**物件**（`/zz/0` 建出 `{"zz": {"0": 1}}`，不是陣列）；aos-json 做好後換成只重寫有變的那塊。
- **錯誤行在 stdout 與 stderr 各一份**：被 dan 式「退非 0 就停」的 act 叫時 stdout 那行沒人看，無害。
- **同一個檔兩隻 agent 同時 edit**：沒有鎖，後寫的贏（N-15 鎖現無實作）。
- **形狀檢查只看 `lib/`**：demo 裡各 agent 自己的工具不在檢查範圍，想一起守就把 `test_lib.py` 的 `lib_tools()` 擴到 `demo/*/tools/`。

## 留給之後的選項（現在照推薦做了，翻案時看這裡）

1. 錯誤要不要分「模型的錯退 0」：現在一律退 1、由 agent 決定。
2. 共用程式庫：現在每個工具自帶十幾行開頭；第三份一樣時抽 `lib/base/_tool.py` 之類（名字再定），用 realpath 找（file-tools 的做法）。
3. 引用方式：現在捷徑；之後若 brain／act 範本要改版，可順便收 `tools.json` 清單當第二種寫法（兩種並存＝多一條規則，KISS 先不要）。
4. 層名 `aos`、`agent` 在收第一個工具時再定案。
5. 要不要把 demo 裡各 agent 的工具也納入形狀檢查。
6. 給人用的命令列（say／listen、aos-ai、aos-grow）算不算函式庫的一部分、放哪。
