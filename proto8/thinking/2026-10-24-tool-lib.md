## 設計（用 aos 自己的話講）

- **agent＝函數**（C-46、C-68：一個資料夾，呼叫時不變）；**工具＝它內部呼叫的外部函數**（C-42「被引用的標頭檔」、C-61 工具是資料夾程式放 `tools/<名>/`）；**函式庫＝這些外部函數收成一份、被引用而不是被複製**（C-40「引用一個設好的資料夾，不複製，執行環境在引用者這邊」）。
- **一個工具＝一個 aos 函數＝一個資料夾**，三個檔：`_entry`（aos-exec 跑）、`tool.json`（給模型，P-41）、`_metainfo`（給 kernel 與人，M1 資料夾那處、M10 跟 tool.json 分開）。照[函數成長](2026-10-24-fn-grow.md)它們是第 4 級（資料夾、不只入口）；裡面長出 loop／fsm、各格是子函數＝第 5 級，那就是高層（agent 層）的工具。
- **分層（每層只依賴下層）**：

  ```
  demo/agent-*/              最上層：agent（函數）
    tools/<名> ─捷徑─▶ lib/<層>/<名>/
  lib/agent/                 高層：裡面是一整隻 agent 的工具（pyfix、claude／codex）
  lib/aos/                   中層：動 aos 自己東西的工具（heap 記憶、寄信、spawn／ask／status、try_run）
  lib/base/                  底層原語：檔案、資料夾、JSON、行程（bash）——只靠 Linux＋Python 標準庫、只碰 $AOS_WS
  impls/                     基礎層與標準庫（C-74）：aos-exec、loop、fsm、daemon
  ```

  層名＝資料夾名（`base`、`aos`、`agent`），不進工具名；只建有東西的層。跟 C-74 的關係：C-74 是 aos 本身的分層（誰依賴誰），lib 整個在它的最上層（agent）那一格裡，lib 自己再分三層。
- **統一契約**（全文在 [lib/README](../lib/README.md)）：stdin 一份 JSON 物件、key 小寫底線、單位放字尾；stdout 整段是結果（文字或一行 JSON）；錯＝stderr 一行 `工具名: 代號 原因`＋stdout 同一行、退 1，代號照 C-54 四種；**參數給錯也退 1——停下還是回給腦由叫它的 agent 決定**（dan 停、pip 回給腦），工具不替它決定（C-52、C-53 入口檢查）；被跑的指令退非 0 是結果不是錯；沙盒只有 `$AOS_WS`（要別的根＝呼叫者 `aos-exec --ws`，C-66）；會跑東西的一定有 `timeout_s`、整群收；寫檔先暫存再改名（N-05）、全有或全無；上限 2000 行／50 KB、500 項、4 MB，超過就說怎麼接著拿；base 層不用 stack；一個工具自成一格、不 import 隔壁。
- **怎麼引用：`tools/<名>` 一條相對捷徑指 `lib/<層>/<名>`**。agent 的 brain／act 一個字不改（照舊讀 `tools/*/tool.json`、`aos-exec tools/<名>`，P-25、P-33 地址零個 `..`）；aos-exec 走進真資料夾（N-57、N-59，cwd、`AOS_CD` 是庫的位置）；要哪些掛哪些、自己的（真資料夾）與庫的並存、同名自己的贏＝覆寫；agent 不知道是庫的（C-52）；C-61 允許「相對捷徑、兩份一起搬也不斷」。只有 Linux（10-19 使用者「先只考慮在linux上」）；repo 外要絕對路徑；複製 agent 要 `cp -a`。
  不用：整個 `tools/` 一條捷徑（不能挑、不能混自己的、不能覆寫）、`tools.json` 清單、`tools/<名>/_entry` 寫 JSON 字串轉向（N-61；`tool.json`、`_metainfo` 還得複製）、PATH（C-61 已否決）、`$ref`（拆檔用的內容引用，不是位置，C-48）。

  **版本與覆寫**：版本＝git（庫改了，掛著的 agent 下次跑就是新的）；要釘住某版＝複製進自己的 `tools/`（＝覆寫＝自己維護）。不另做版本號（M9 同理：不加 `ver`）。
- **跟既有原則對照**：沒有硬衝突。擦邊兩處——P-25「demo 之間不跨 agent 互指、各複製一份」是 10-19 為了 demo 寫的；庫就是為了不複製，捷徑是 C-61、P-33 本來列的第二條路。P-33「不給程式根變數」照守：捷徑不需要知道 agent 的根。
- **命名**（C-54）：`lib`（abbr.json 已有）、層 `base`／`aos`／`agent`；工具名一個動詞（`read`、`ls`）或主題在前（`json_read`、`json_edit`）；pi 的四個照原名（模型本來就認得，C-54 例外「工具自己的慣例照工具」）；eve 子工具的 `read_file`、`write_file`、`edit_file`、`list_files` 在庫裡就是 `read`、`write`、`edit`、`ls`；參數 `timeout_s`（R6 單位放字尾）；代號新加 `PointerBad`、`PointerMissing`（JSON 指標）。

## 做了什麼（10-24，照推薦定、可翻案）

- **`proto8/lib/`**：[README](../lib/README.md)（入口＋索引＋契約，小資料夾 README／INDEX 合一）；每個工具都有 `_entry`、`tool.json`、`_metainfo`。
- **示範 agent `demo/agent-liv`**（人名接 ann、bob、cathy、dan、eve、fay、gus、ivy、kai、meg、pip）：照抄 agent-dan，`tools/` 裡相對捷徑 `../../../lib/base/<名>` 加一個自己的 `clock/`（示範「同名自己的贏」）；`_metainfo` 照 `_metainfo` 規劃的範例 2；假腦叫庫的 `ls` 一次、拿 `total` 答。act 照 agent-pip：庫的工具出錯回給腦、不停（10-24 真腦實測，照「都按照建議」代定、可翻案；真腦叫 `edit` 抄錯原文時，停下重跑會卡在同一個呼叫）。
- **測試 `tests/test_lib.py`**：形狀檢查跑過 `lib/` 每個工具（三個檔、`+x`、shebang、第二行 `# 名 - 一句話`、`tool.json` 的 description／parameters 與參數名合 C-54、`_metainfo` 八個通用 key、壞 stdin→`ArgumentsBad` 一行且 stdout 同一行、直接叫沒 `AOS_WS`→`WsMissing`）；各工具的行為（截斷與接著讀、權限留住、全有或全無、bash 結束碼與逾時整群停、ls 分頁與隱藏檔與連結、json_read 摺疊與指標錯、json_edit 一處不合整份不寫、出不了工作區含連結與絕對路徑）；agent-liv 捷徑是相對的且指到 lib、假腦經捷徑用 `ls` 跑完一題。

### 代定清單（照推薦定、可翻案）

1. 位置 `proto8/lib/<層>/<名>/`，層名 `base`／`aos`／`agent`；只建有東西的層。翻案判準：第二層收進第一個工具時覺得名字拗口就改，那時連結還少。
2. 一個工具固定三個檔（`_entry`、`tool.json`、`_metainfo`），形狀由 `test_lib.py` 守。
3. 參數 stdin JSON 物件、小寫底線、單位字尾（`timeout_s`）。
4. 錯一律退 1＋stdout 同一行；代號 C-54；停或回給腦是 agent 的事（不在工具）。
5. 沙盒只認 `$AOS_WS`；換根用 `aos-exec --ws`。
6. 逾時 `timeout_s`、預設與上限各工具自訂寫進 `tool.json`；整群 TERM→KILL。
7. 上限 2000 行／50 KB（read、bash）、500 項（ls）、4 MB（json）；超過就說怎麼接著拿。
8. 引用＝一條相對捷徑一個工具；同名自己的贏；版本＝git、釘版＝複製。
9. 自成一格、不 import 隔壁；共用庫等到第三份一樣的大段再抽（STRUCTURE 膨脹即拆）。
10. base 不用 stack（純函數）；中層以上才用小格留東西。
11. 命名：工具名一個動詞或主題_動詞；pi 四個照原名；eve 式的 `read_file` 改 `read`。
12. 跟函數成長一致：庫裡的工具是第 4 級；長出 loop／fsm 就是第 5 級、歸 agent 層。縮回不自動。
13. 示範 agent 叫 `agent-liv`；只掛庫、不改範本程式。
14. **換實作不換介面**：`ls`、`json_read`、`json_edit` 的 `tool.json` 不變，`_entry` 可換成叫 `aos-json`（C++）。

**lib 現在的樹**（索引在 [lib/README](../lib/README.md)）：

- `base/` 15 個：read、write、edit、bash、ls、stat、view、json_read、json_edit、mkdir、move、copy、trash、math、clock、run_python。
- `aos/` 10 個＋共用模組 `aos_ws.py`：memory（連 heap.py）、send_message、check_inbox、spawn_agent、ask_agent、agent_status、make_json、make_tool、explain_aos、try_run。

**逐項**：

1. demo/pi-tools、demo/file-tools 收進 base 後刪掉：ls 只有一份（含 file-tools 的 `children`、`aos` 記號、`exec`、JSON 頂層 key）；file-tools 的 `common.py` 攤回各工具、錯一律 stdout 同一行（不用 `{"error"}`）；agent-pip、agent-kai 的 read、self-improve 改進者的 read／write／edit、sandbox 的 bash-boxed 都指 base（bash-boxed 用 `timeout_s`）。

3. math、clock 在 base（照契約：錯也印 stdout、壞 stdin＝`ArgumentsBad`；clock 是 python3 才能驗 stdin）；hal、kai、talk 掛捷徑。**agent-dan 自己那份留著**：它是 aos-ai spawn 的預設範本、也是 artifact 的對象；agent-liv 的 clock 也留著，示範「同名自己的贏」。
4. 錯誤要停 vs 回給腦（lib/README「工具只報錯、停不停由 agent 決定」）：所有庫工具「模型的錯」也退 1、一行錯；靠腦自己改的 agent（agent-meg、talk 的 member、agent-gus、pyfix-agent）act 是「工具退非 0 回給腦、不停」（同 agent-pip）。talk 自動回信寄不成寫在答案後面、環境壞了才停。
5. run_python 在 base（不是 agent 層：它是行程原語）：逾時算 `CommandFailed`、整群 TERM→KILL；程式寫在自己的小格（規則 8 的例外）。try_run 在 aos（跑一個 aos 函數的暫時複本）：參數 `timeout_s`、逾時算錯。
6. memory、send_message／check_inbox、ai_tools 六個在 aos；`$AOS_HEAP`、`$AOS_ROSTER`、`$AOS_AI_ROOT` 照原樣留（規則 4 的例外，寫進 README）。ai 六個的錯代號照 aos-ai 的（`NameBad`…）。`aos-ai spawn --tool` 從 lib/aos 拿。

**沒搬的**：agent-gus 的小念頭 `thought.json`／`thought.py`（見下 10-25）；aos-json 自帶的 `tools/json`、`tools/json_edit`（小念頭式兩步改）留在 impls、跟它的測試在一起。agent-bob 的 `cathy`、`stamp` 是非腦的工具（格直接叫），不在範圍。

## 邊緣狀況（攤出來，不擋）

- **捷徑只有 Linux**；repo 在別的檔案系統 checkout 會變成普通檔，agent 叫工具時 aos-exec 讀到一個不是 JSON 的小檔＝`EntryBad`。10-19 使用者「先只考慮在linux上」。
- **複製 agent 時捷徑會被解開或斷掉**：`cp -r` 會把庫的工具複製成真資料夾——行為一樣，但那隻就不再跟著庫更新；`shutil.copytree(symlinks=True)` 留捷徑，但相對捷徑複製到別處會斷（aos-ai spawn 改成絕對捷徑）。要保留捷徑用 `cp -a`。
- **庫一改全部的 agent 立刻變**（沒有版本釘）；要釘住的複製一份。
- **工具的 `AOS_CD` 是庫的位置**（aos-exec 解開捷徑）：工具若想找「掛它的那隻 agent 的檔」找不到——本來就不該（C-52）。
- **bash 擋不住出工作區**、**stack 在工作區裡時腦改得到自己的 history**（pi-tools 紀錄已列）；要隔離靠容器、或把 `AOS_STACK` 放工作區外。
- **json_edit**：`set` 到不存在的中間層會建**物件**（`/zz/0` 建出 `{"zz": {"0": 1}}`，不是陣列）。
- **錯誤行在 stdout 與 stderr 各一份**：被 dan 式「退非 0 就停」的 act 叫時 stdout 那行沒人看，無害。
- **同一個檔兩隻 agent 同時 edit**：沒有鎖，後寫的贏（N-15 鎖現無實作）。
- **形狀檢查只看 `lib/`**：demo 裡各 agent 自己的工具不在檢查範圍，想一起守就把 `test_lib.py` 的 `lib_tools()` 擴到 `demo/*/tools/`。

## 留給之後的選項（現在照推薦做了，翻案時看這裡）

1. 錯誤要不要分「模型的錯退 0」：現在一律退 1、由 agent 決定。
2. 共用程式庫：現在每個工具自帶十幾行開頭；第三份一樣時抽 `lib/base/_tool.py` 之類（名字再定），用 realpath 找（file-tools 的做法）。
3. 引用方式：現在捷徑；之後若 brain／act 範本要改版，可順便收 `tools.json` 清單當第二種寫法（兩種並存＝多一條規則，KISS 先不要）。
4. 層名 `aos`、`agent` 在收第一個工具時再定案。
5. 要不要把 demo 裡各 agent 的工具也納入形狀檢查。
6. 給人用的命令列（say／listen、aos-ai、aos-grow）算不算函式庫的一部分、放哪。
7. repo 外的 agent 怎麼掛庫（相對捷徑不通，要絕對路徑）。

## 10-25：agent-gus 的小念頭不搬（頂層代定，可翻案）

使用者 10-25：「可以直接派人做的就去做」。`thought` **不搬，留在 `demo/agent-gus/`**：`thought.json` 不是給腦叫的工具（沒有 `tool.json`、stdin 是一步 `{goal, context, needs}`、錯只寫 stderr），是 agent-gus 對外的第二個入口；小念頭＝起 agent-gus 自己（`shared.launch` 以本資料夾為入口跑），要進庫就得整隻 gus（plan、fork、brain、act、shared、測試）一起搬；只把 `thought` 放進 `lib/` 會讓庫倒過來依賴 demo（庫只該被 demo 引用）。

翻案：哪天有別的 agent 要把小念頭當腦的工具用（[intent-context](2026-10-24-intent-context.md) 說的接法、[aos-json](2026-10-24-aos-json.md) json_edit 兩步的第二步），就照 pyfix 的做法——整隻 gus 搬進 `lib/agent/thought/agent/`，外面一個 `_entry`＋`tool.json`＋`_metainfo` 轉接到 `thought.json`，錯照庫的契約兩邊各印一行。
