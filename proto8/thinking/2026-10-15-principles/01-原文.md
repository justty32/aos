## 原文（10-15，照貼）

「都按照推薦。我這邊的原則是：盡量保持簡單，要考慮到在巢狀的情況下，進行乾淨的切分，也就是只管自己這一層，因爲後續複雜起來的時候，巢狀會很容易出現，我會希望當多層巢狀出現的時候，我可以用單一原則，或是單一概念，只去拿最上層的進行處理，下層的東西會被很乾淨的切割，在我處理上層的時候可以盡量不管下層的事情，或是要管的時候，心理有一把尺，有一個可以參照的原則，我可以相信這個原則會貫穿和在整個巢狀重複。然後一樣，關於錯誤處理那塊也是按照先前的標準，各功能單元僅處理自己的錯誤，對於別人的錯誤，我們可以分爲：你丟給我的時候就應該是正常的（之後可以延伸爲我不管(默認正常)，或是我會在入口處檢查並處理輸入），或是我交出去的時候我會保証不出錯，或是提前把可能的錯誤列出來。相關錯誤路徑處理也是盡量濃縮成少數幾個，讓整個程式的行爲(這裏說的和程式本身的功能有關，但更多是關於"在程式執行該功能時出了問題後"的行爲)複雜度減少，這塊後續也可以納入kernel評估中」

## 決定

- 兩條寫成設計理念 **C-52**（巢狀：只管自己這一層）、**C-53**（錯誤：只處理自己的錯；對別人的錯三種姿態；錯誤路徑濃縮）。
- 「先前的標準」＝proto7 設計原則 9、10：KISS、錯誤分類同類走同一分支（＝濃縮錯誤路徑）、很多東西默認正常、誤用不歸組件管、先定義組件功能（要求呼叫者保證什麼＝入口、它保證什麼＝出口、明確不管）。C-53 接著它寫，不另起爐灶；proto8 已有的 N-18（錯誤歸類）、N-20、N-29、N-43、N-38、「卡死不防護」都是它的實例，條文不動、只補指向。
- 盤點第 1、3、8、9 條照推薦（「都同意。」）：
  - **1** 每層只退 0／非 0 說自己，下層的碼只放 stdout／stderr 的 JSON，不沿用下層的結束碼：loop、daemon 自己的錯（設定錯、窗缺、最後一次 inst 出錯等）一律退 1，stderr 一份自己的錯誤。寫進 N-43。
  - **3** 判官錯濃縮成一條「判官這拍沒給合法答案＝這拍用規則」：不數連錯、不設「等人歸零」，連錯計數是判官格自己的事；`judge_error` 只記原因（答對清掉）；補位（backfill）不是錯誤路徑，照留。
  - **8** think 連錯時自己寫好要交的錯：think 第 halt_after 次自己寫 cwd 的 `ret.json`＝`{"error"}`、回 `next: halted`；`halted` 不在各表的 `states`、只在 `end`（N-40：next 不在表裡、在 end 裡＝fsm 結束），不經 done；done 只寫 `{"reply": 最後一句}`，不讀 think 的連錯檔。
  - **9** halted 時 loop 退 0 維持：照 C-52，loop 只說自己這一層（它照設計拍完、正常結束），agent 的錯在 `ret.json`；agent 說明寫明「看 ret.json」。halted 那拍 think 寫 `ret.json` 的錯、退 0、不寫 stderr，符合「正常退出」的定義。
- 「正常退出」的定義寫進 N-43：照設計、文檔走正常那條路、是預料到的狀況；簡化判準＝不在 stderr 噴東西。反向不成立：退非 0 時錯誤可以寫到別處（文件說好的地方）。
- 「納入 kernel 評估」記成待定（[NORMS 待定 【kernel】](../../docs/NORMS/08-待定.md)）。
- 「正常退出」盤點 S1～S5 照推薦（「都按照推薦。」）：
  - **S1 警告不開例外**：stderr 不放警告（N-29）。讀 ctl 窗出問題（壞檔、不見、讀不了）、daemon 策略格或重起失敗、寫不了子項 ctl、信箱回信寫不進去 → 記在自己 state 窗的 `last_warning`（讀到好的清掉；N-08）；沒窗的小工具 → 寫在輸出、退 0；多給輸入 → 入口錯、退非 0；**state 窗本身寫不了**（沒地方記）→ 是錯：loop／daemon 收工、stderr 一份、退 1（同 N-19 窗缺）。
  - **S2** loop 不把 inst 的 stderr 轉到自己的 stderr，只記 state 窗 `last_error`；daemon 的子 loop stderr 落 `work_dir/N/err.json`。
  - **S3** 閘門透明：轉交 target 的 stderr 與碼（N-43 寫明）。
  - **S4** `stderr_inherit` 維持：寫單子的人自選，那時 stderr 是子程式的（N-26、N-43 寫明）。
  - **S5** 述詞（`aos-not`、`aos-if` 的條件）是 N-43 的 Unix 式例外（同 `test`／`false`／`grep`），N-34、N-43 寫明。
- 新的待定 A～C 照推薦（「按照推薦」）：
  - **結束碼只剩 0／1**（N-43：「0 正常、非 0 有錯，沒了」）：aos 的程式說自己的錯一律 1，不再用數字分種類，是哪種錯看 stderr 的 `code`。
  - **被訊號停掉**：使用者另加一條：不用 128＋N、一律退 1；現行照 [CONVENTION P-36](../../docs/CONVENTION/06-巢狀.md)（先收好子程式、寫好狀態再結束，loop／fsm 以 128＋N 結束）。
  - **例外只有兩種，寫進 N-43**：透明轉交別人的碼（閘門＝target 的碼；tasks 的 seq／par／if 回子程式的碼，同 sh 的 `&&`）、述詞。inst 結果的 `code`（被訊號停掉的子程式是 128＋N）是子程式的碼、是資料，不是退出碼（N-30 寫明）。
  - B（state 窗寫不了就收工）、C（`last_warning` 只留最近一件）維持。
