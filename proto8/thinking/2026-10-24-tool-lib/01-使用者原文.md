## 使用者原文（10-24，逐字）

> 就，我們在做工具集，這其實挺像是在做函式庫。因爲agent是函數，我們給他的工具就是他在內部自己跑的時候會呼叫的外部函數。既然是這樣，那我們就要把抽象做好，把函數庫做好

同日前文（這一批嘗試通用）：

> 我隨便說，你隨便做，反正只是嘗試　／　我現在沒空管這些小事，都按建議做

所以下面的代定一律**照推薦定、可翻案**（使用者 10-24「都按建議做」），不另留待使用者項。

## 設計（用 aos 自己的話講）

- **agent＝函數**（C-46、C-68：一個資料夾，呼叫時不變）；**工具＝它內部呼叫的外部函數**（C-42「被引用的標頭檔」、C-61 工具是資料夾程式放 `tools/<名>/`）；**函式庫＝這些外部函數收成一份、被引用而不是被複製**（C-40「引用一個設好的資料夾，不複製，執行環境在引用者這邊」）。
- **一個工具＝一個 aos 函數＝一個資料夾**，三個檔：`_entry`（aos-exec 跑）、`tool.json`（給模型，P-41）、`_metainfo`（給 kernel 與人，M1 資料夾那處、M10 跟 tool.json 分開）。照[函數成長](../2026-10-24-fn-grow.md)它們是第 4 級（資料夾、不只入口）；裡面長出 loop／fsm、各格是子函數＝第 5 級，那就是高層（agent 層）的工具。
- **分層（每層只依賴下層）**：

  ```
  demo/agent-*/              最上層：agent（函數）
    tools/<名> ─捷徑─▶ lib/<層>/<名>/
  lib/agent/                 高層：裡面是一整隻 agent 的工具（pyfix、claude／codex）
  lib/aos/                   中層：動 aos 自己東西的工具（heap 記憶、寄信、spawn／ask／status、try_run）
  lib/base/                  底層原語：檔案、資料夾、JSON、行程（bash）——只靠 Linux＋Python 標準庫、只碰 $AOS_WS
  impls/                     基礎層與標準庫（C-74）：aos-exec、loop、fsm、daemon
  ```

  層名＝資料夾名（`base`、`aos`、`agent`），不進工具名；只建有東西的層。跟 C-74 的關係：C-74 是 aos 本身的分層（誰依賴誰），lib 整個在它的最上層（agent）那一格裡，lib 自己再分三層。
- **統一契約**（全文在 [lib/README](../../lib/README.md)）：stdin 一份 JSON 物件、key 小寫底線、單位放字尾；stdout 整段是結果（文字或一行 JSON）；錯＝stderr 一行 `工具名: 代號 原因`＋stdout 同一行、退 1，代號照 C-54 四種；**參數給錯也退 1——停下還是回給腦由叫它的 agent 決定**（dan 停、pip 回給腦），工具不替它決定（C-52、C-53 入口檢查）；被跑的指令退非 0 是結果不是錯；沙盒只有 `$AOS_WS`（要別的根＝呼叫者 `aos-exec --ws`，C-66）；會跑東西的一定有 `timeout_s`、整群收；寫檔先暫存再改名（N-05）、全有或全無；上限 2000 行／50 KB、500 項、4 MB，超過就說怎麼接著拿；base 層不用 stack；一個工具自成一格、不 import 隔壁。
- **怎麼引用：`tools/<名>` 一條相對捷徑指 `lib/<層>/<名>`**。agent 的 brain／act 一個字不改（照舊讀 `tools/*/tool.json`、`aos-exec tools/<名>`，P-25、P-33 地址零個 `..`）；aos-exec 走進真資料夾（N-57、N-59，cwd、`AOS_CD` 是庫的位置）；要哪些掛哪些、自己的（真資料夾）與庫的並存、同名自己的贏＝覆寫；agent 不知道是庫的（C-52）；C-61 允許「相對捷徑、兩份一起搬也不斷」。只有 Linux（10-19 使用者「先只考慮在linux上」）；repo 外要絕對路徑；複製 agent 要 `cp -a`。
  不用：整個 `tools/` 一條捷徑（不能挑、不能混自己的、不能覆寫）、`tools.json` 清單、`tools/<名>/_entry` 寫 JSON 字串轉向（N-61；`tool.json`、`_metainfo` 還得複製）、PATH（C-61 已否決）、`$ref`（拆檔用的內容引用，不是位置，C-48）。

  **版本與覆寫**：版本＝git（庫改了，掛著的 agent 下次跑就是新的）；要釘住某版＝複製進自己的 `tools/`（＝覆寫＝自己維護）。不另做版本號（M9 同理：不加 `ver`）。
- **跟既有原則對照**：沒有硬衝突。擦邊兩處——P-25「demo 之間不跨 agent 互指、各複製一份」是 10-19 為了 demo 寫的；庫就是為了不複製，捷徑是 C-61、P-33 本來列的第二條路。P-33「不給程式根變數」照守：捷徑不需要知道 agent 的根。
- **命名**（C-54）：`lib`（abbr.json 已有）、層 `base`／`aos`／`agent`；工具名一個動詞（`read`、`ls`）或主題在前（`json_read`、`json_edit`）；pi 的四個照原名（模型本來就認得，C-54 例外「工具自己的慣例照工具」）；eve 子工具的 `read_file`、`write_file`、`edit_file`、`list_files` 在庫裡就是 `read`、`write`、`edit`、`ls`；參數 `timeout_s`（R6 單位放字尾）；代號新加 `PointerBad`、`PointerMissing`（JSON 指標）。
