## 留給之後的選項（現在照推薦做了，翻案時看這裡）

1. 錯誤要不要分「模型的錯退 0」：現在一律退 1、由 agent 決定。
2. 共用程式庫：現在每個工具自帶十幾行開頭；第三份一樣時抽 `lib/base/_tool.py` 之類（名字再定），用 realpath 找（file-tools 的做法）。
3. 引用方式：現在捷徑；之後若 brain／act 範本要改版，可順便收 `tools.json` 清單當第二種寫法（兩種並存＝多一條規則，KISS 先不要）。
4. 層名 `aos`、`agent` 在收第一個工具時再定案。
5. 要不要把 demo 裡各 agent 的工具也納入形狀檢查。
6. 給人用的命令列（say／listen、aos-ai、aos-grow）算不算函式庫的一部分、放哪。
7. repo 外的 agent 怎麼掛庫（相對捷徑不通，要絕對路徑）。

## 10-25：agent-gus 的小念頭不搬（頂層代定，可翻案）

使用者 10-25：「可以直接派人做的就去做」。`thought` **不搬，留在 `demo/agent-gus/`**：`thought.json` 不是給腦叫的工具（沒有 `tool.json`、stdin 是一步 `{goal, context, needs}`、錯只寫 stderr），是 agent-gus 對外的第二個入口；小念頭＝起 agent-gus 自己（`shared.launch` 以本資料夾為入口跑），要進庫就得整隻 gus（plan、fork、brain、act、shared、測試）一起搬；只把 `thought` 放進 `lib/` 會讓庫倒過來依賴 demo（庫只該被 demo 引用）。

翻案：哪天有別的 agent 要把小念頭當腦的工具用（[intent-context](../2026-10-24-intent-context.md) 說的接法、[aos-json](../2026-10-24-aos-json.md) json_edit 兩步的第二步），就照 pyfix 的做法——整隻 gus 搬進 `lib/agent/thought/agent/`，外面一個 `_entry`＋`tool.json`＋`_metainfo` 轉接到 `thought.json`，錯照庫的契約兩邊各印一行。
