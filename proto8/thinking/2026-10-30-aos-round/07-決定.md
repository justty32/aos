## 決定（10-30）

使用者 10-30 看完衝突七條與方向題三條：「都照建議」。

1. **衝突 1**：名字用 `aos-round`；C-54 R13 補一句「標準庫層級、全域只有一個意思的單字程式可以不帶領域」（同 aos-loop、aos-fsm）。
2. **衝突 2**：N-43、P-35 加註「10 是對直接收到它的那層說的，表上接住就不往上」，碼的意思不動、不加新碼。
3. **衝突 3**：錯誤碼與 `"*"` 准寫進表、風險自擔（`max` 是唯一煞車）；P-20 加註「表上沒接住時才是預設停」，範本表只接 0 與 10。
4. **衝突 4**：「現在在哪」以 fsm 的 `state.txt` 為準，每格對 state 與資料對不上要自保（沒事做就退 0 往下走）。
5. **衝突 5**：trace 只留 fsm 的一格一行、加 `next` 欄；round 的 `unit` 行退場。
6. **衝突 6**：`hook/pause` 與 `round --step` 退場，agent-round 掛勾表那列與代定 27 劃掉。
7. **衝突 7**：`timeout_ms` 數字照舊 600 秒、說明改成「管一格」；要整輪上限在外面再包一層。
8. **方向題 1**：agent 不自帶 round 表，要客製走 D「拆散」；等真有需要再開槽。
9. **方向題 2**：不做「嚴格答一題就停」；要一次一題用 loop 的 `max` 或一次只塞一題。
10. **方向題 3**：舊 round 骨架換完就刪，不並存。

## 實作時代定（10-30，隊長與工人照原則定的細節，可翻案）

- **第 1 步**：物件 `next` 的 key 只收 `"0"`～`"255"` 的標準十進位寫法（沒有正負號、空白、前導 0）或 `"*"`，其他＝CfgBad（`"010"`、`"256"` 永遠查不到，當表壞比默默不生效安全）；值不是字串也是 CfgBad；trace 的 `next` 欄在 main 組那一行時加，`append_trace` 介面不變。
- **要使用者裁（第 1 步發現）**：`lib/aos/aos_ws.py` 判 trace 那一行算不算失敗是「非 0、非 10，或被訊號停掉」；有了分岔，被 `"*"` 或 `"1"` 接住的錯碼 fsm 其實退 0 照表走了一步，這條規則仍會標成失敗。沒改（範本表只接 0 與 10，眼前不會遇到），寫進 WAIT_USER。
- **留到第 7 步一起改**：trace 範例還寫五欄的文件——`proto8/demo/README.md` 的範例行、`proto8/extras/ai_tools/claude_skill/aos/concepts.md`、`proto8/docs/CONVENTION.md` 入口。
- **第 2 步**：五個格的錯誤行名字是 `round/<格>`（例 `round/think: EndpointFailed …`）；格開頭一行 `roundlib.main("<格>", 函數)`（解 argv、要 `AOS_STACK`、設模組變數、抓錯印一行）；roundlib 不讀 `ROUND_ON_EMPTY`（空了停不停由兩張表定），`MAX_RETRIES` 只有 think 讀。格的自保多兩條：think 看到最後一則 assistant 還有沒回的 tool_calls（工具只接進一部分就斷了）＝不問腦、退 0 去 act 補完；最後一則的 role 不是 user／tool／assistant＝`HistoryBad`。finish 看到最後一則不是「沒 tool_calls 的 assistant」＝不收信、退 0（回 idle → think 接著答，不丟題）。idle 補認領或 `queue claim` 退 10 之後一律看 `cur/` 有沒有信決定退 0 或 10。
- **第 3 步**：`aos-round` 讀 round 槽：`aos-parts which` 退 10（沒登記也沒同名資料夾）＝用預設、不算錯；env 整份在 exec 時交給 aos-fsm（`os.execvpe`），不改自己的環境；相對 `AOS_STACK`／`AOS_WS` 轉絕對時保留結尾 `/`；aos-fsm 起不來＝`CommandMissing`（沿用 aos-tools／aos-parts 的代號）。實測單子逾時殺在 think：trace 最後一行 `think` 碼 143、state 停在 think、loop 退 143，跟規劃書一致。
- **第 4 步**：agent-nia 的 loop.json `max` 照舊 40，但現在數的是格（一題約 6 格，一次最多答 6 題左右，demo README 寫明）；test_nia 原本「數 trace 的 `hook/pre_think` 行」驗 compact 掛著的那條拿掉（fsm trace 看不到器官層），改驗 parts.json 的 `hook/pre_think` 指到 compact。aos-ai、aos_ws、aos_human 本來就兩種 trace 都看得懂，只改測試斷言（`fsm_state` 答完是 `idle`、listen 說「停在 think 那格」）。
- **第 5 步**：ask_round 判「答完了」只看 `queue pop --timeout-s 0 <信號>`（信不見了＝finish 那格已收信、state 回到 idle），不讀 state.txt、不靠 aos-round 的 10——被問的 agent 的 round 槽若設 `ROUND_ON_EMPTY=idle`（parts.json 的 env 壓過環境）也不會卡住；aos-round 退 10 只用在「queue 空了信卻還在」＝`AnswerMissing`。
- **第 6 步**：aos_ws、aos_human、aos-listen 讀 trace 的 `unit` 行相容讀留著（舊 stack 還有；eca 的 turn 現在也寫 `unit` 行），只改註解；aos-parts 說明的例子從 `run round` 換成 eca-claude 的 `run turn`。
- **第 7 步**：C-54 R13 照決定 1 補一句（規劃書 C 段原寫「CONCEPTS 不動」，以決定為準）；N-39 加註順手註明 `at` 10-23 起改名 `started_at`（正文的欄位名舊了，沒改正文）。
- **收尾後補（10-30 晚）**：round 的 `letter_warning`（agent-lifecycle Q-4 留下的）沒有落在 idle 格，是由 queue 格在丟壞信時寫 `$AOS_STACK/letter_warning.txt`。idle、more 兩格叫 `queue claim` 時就一起記到，格一行都不用改。理由與細節見 [agent-lifecycle 實作時代定 Q-17](../2026-10-30-agent-lifecycle/07-衝突.md#實作時代定10-30隊長與工人照原則定的細節可翻案)。
- **10-30 晚真腦實測發現 1**：`aos-round` 找不到 aos-fsm 時，原本靠 `os.execvpe` 的錯，它只報 PATH 最後一格試的路徑（像 `/home/lorkhan/bin/aos-fsm`），看起來像寫死。改成先自己照 exec 時的 PATH 找（`shutil.which`），找不到就說「PATH 上找不到可執行的 aos-fsm」、找到卻起不來才印那個路徑；代號照舊 `CommandMissing`。`aos-parts run`、`aos-tools call` 叫 aos-exec 有同樣寫法，一起改。測試：`test_round` 的 `AosRound.test_fsm_not_on_path`、`test_aos_parts`、`test_aos_tools` 各一案。
- **10-30 晚真腦實測發現 2**：`aos-say` 之後拿舊協議的 agent（agent-dan 讀工作區的 `new/*.txt`、不收 queue）跑，退 0、信原封留在 queue，`aos-listen` 原本只說「沒有程式在跑」然後一直等。代定最小做法：listen 等一封時，**信還在 `queue/new/`、沒人在跑、而且 stack 的 `trace.jsonl` 比這封信新**（＝它寄出之後有程式跑過這個 stack、停了、卻沒認領它），就印一行 `aos-listen: LetterUnclaimed …沒人認領…可能還是舊協議…或 loop 的 max 先到了。不等了`、退 1（新代號；listen 的錯一律退 1）。只看「沒人在跑＋信在 new/」不夠：先 say、先開 listen、再開 agent 是正常用法（`test_waits_while_agent_runs_later`），那時還沒人跑過、trace 不比信新，照舊提醒一次、繼續等。判「有人跑過」用 trace.jsonl 的 mtime，是因為舊協議的 fsm 範本、aos-round、eca 的 turn 都把 trace 寫在同一個 stack；退之前再看一次信是不是還在 new/，剛好被認領走就不算。aos-chat 替你跑完 agent 後信還在 new/ 沒被認領，原本那句「還有 N 封沒答」多帶同一個提示（chat 是互動的、不退）；chat 不帶 agent 等別人跑時的提醒也換成這句。測試：`test_human` 的 `test_old_protocol_agent_unclaimed`、`test_old_protocol_agent_hint`。
