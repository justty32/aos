## 衝突（跟既有原則、實作對不上的；寫給使用者看）

1. **名字：你說 `aos-round`，你剛定的命名慣例說程式要叫「aos-領域-功能」。** C-54 R13（10-30 夜才落正文）要程式名寫成 `aos-<領域>-<功能>`，像 aos-llm-kernel、aos-eca-hub；round 不是一個領域，照字面該叫 `aos-agent-round`。**各選項後果**：(甲) `aos-round`——跟 aos-loop、aos-fsm、aos-exec、aos-post 這些「標準庫裡一個字的程式」同一族，短、好打；R13 補一句「標準庫層級、全域只有一個意思的單字程式可以不帶領域」。(乙) `aos-agent-round`——照 R13 字面，但 aos-loop、aos-fsm 也得跟著改才一致，不然規矩自己打自己。**建議：甲**，R13 補那一句。 **已定：照建議（使用者 10-30「都照建議」）。**
2. **「10 是叫外面的 loop 別再跑了」這句話，中間隔了 fsm 就不再字面成立。** N-43 寫 10＝要求外面的 loop 別再跑；P-35 寫「10 只有 idle 退」。有了分岔，think 退 10 是「該交卷了」、act 退 10 是「有人插話」，fsm 表接住後 loop 根本看不到那個 10。**後果**：不改字面＝條文跟範本行為對不上，看條文的人會以為 think 退 10 整隻會停；改口＝N-43、P-35 各加一句「10 的意思是對直接收到它的那層說的，表上接住就不往上」，碼的意思本身不動、不加新碼。**建議：加註**（上面草稿）。 **已定：照建議（使用者 10-30「都照建議」）。**
3. **表上可以把「錯」導回同一格，等於從表上開了一扇自動重試的門。** P-20、N-53 說 agent 失敗就停下等人、自己不數連錯、重試幾次看外面。分岔讓人可以寫 `"1": "think"`——錯了就再問一次，而且沒有上限（只有 loop 的 `max` 擋）。**各選項後果**：(甲) 條文只准接 0 與 10、錯誤碼不准寫進表——乾淨，但你說的是「依據不同結束碼導向不同分支」，自己又把一半的碼關掉，而且善後格（錯了去清東西再停）也寫不出來。(乙) 准寫、風險自擔——跟 N-38「想優雅處理的格自己接錯」同一個精神，只是從格內搬到表上；範本不這樣寫，所以預設行為沒變；想無限重試的人要自己知道 `max` 是唯一的煞車。**建議：乙**，P-20 加註「表上沒接住時才是預設停」。 **已定：照建議（使用者 10-30「都照建議」）。**
4. **round 本來故意不設狀態檔，現在「我在哪」變成 fsm 的 `state.txt` 說了算。** 10-28 代定 29、30 是「看 `cur/` 跟 history 最後一則就知道接著做什麼，不另設狀態檔」；搬進 fsm 後 `state.txt` 多了一份真相，兩邊可能對不上（例如 state 說 act、history 卻沒有待回的工具）。**後果**：沿用舊做法＝fsm 的 state 只是擺設、每格還是重算，那就不是薄殼；改成 state 為準＝每格要對「state 跟資料對不上」自保（沒事做就退 0 往下走），這正是 N-38「半成品由格自己看自己的檔判斷」原本就要求的；好處是 P-20「人修好再跑、從 state.txt 接著做」對 round 也成立，跟 agent-dan 一個樣。**建議：state 為準、格自保**（B 第 2 點）。 **已定：照建議（使用者 10-30「都照建議」）。**
5. **trace 從「每叫一個器官一行」變成「每格一行」，而且 fsm 的 trace 多一個欄位。** 現在 round 的 trace 看得到 `queue claim`、`endpoint/litellm`、`hook/post_think` 一行一行；換成 fsm 之後一格一行（`idle`、`think`…），器官層的細節沒了；N-39 定的 fsm trace 五個欄位也要加 `next`，`test_fsm` 與看 trace 的工具（nvim 外掛、demo 的 run.sh）要跟著看。**各選項後果**：(甲) 只留 fsm 的行——一個 stack 一種 trace 形狀，`sort` 照舊，想看哪個端點看 `endpoint.txt`、用量看 `usage.jsonl`；(乙) 格也寫自己的 `unit` 行到同一個檔——細節都在，但同一個檔兩種形狀、兩種時間格式（現在就是 `Z` 對 `+00:00`），讀的人要分。**建議：甲**，`next` 欄加上。 **已定：照建議（使用者 10-30「都照建議」）。**
6. **`hook/pause` 與 `round --step` 退場，10-28 的掛勾表與代定 27 要劃掉。** 它們的工作（讓 loop 有機會看 ctl、一次只做一步）在「loop 一次叫一格」的形狀下是天生的。**後果**：留著＝多兩個沒人用的開關；拿掉＝agent-round § 3 的表少一列、代定 27 作廢，現有範本沒有人掛 pause、`--step` 只有測試在用。**建議：退場**。 **已定：照建議（使用者 10-30「都照建議」）。**
7. **`timeout_ms` 從「管一輪」變成「管一格」。** agent-nia 的 `loop.json` 寫 600 秒本來是一整輪的上限，現在同一個數字只管一格（think 那格含問腦）。**後果**：數字不改＝每格最多 600 秒、一輪沒有上限（一輪的長短由腦決定，本來就不太能定）；要整輪上限得在外面再包一層（P-36 外層包內層）。範本照舊寫 600 秒、README 講清楚它管的是一格。**建議：照舊數字、改說明**。 **已定：照建議（使用者 10-30「都照建議」）。**

## 方向題（原則推不出的，附背景例子）

1. **agent 要不要能自帶一張 round 的表。** 背景：aos-round 固定用 `lib/agent/round/` 的兩張表；某隻 agent 想在 think 跟 act 之間多一格「審稿」（例如叫另一個腦看一眼再放行工具），現在只能走 D「拆散」自己寫整張 `fsm.json`、每格自己維護。另一條路是 `parts.json` 多一個槽 `round/fsm` 指自己的表、格仍用 lib 的五個——只改表、不重寫格。**兩條路**：(甲) 現在不開，要客製就走 D，aos-round 保持只有兩張表；(乙) 開這個槽，aos-round 多讀一個 key。**建議：甲**，等真有一隻 agent 需要再開（C-56 不為還沒發生的事加機制）；寫在這裡是因為「要不要留這個口」是產品範圍、不是原則能推的。 **已定：照建議（使用者 10-30「都照建議」）。**
2. **要不要「不管 queue 還有沒有、答完一題就停」這個嚴格版。** 背景：`ROUND_ON_EMPTY=stop` 是「答到 queue 空才停」；ask_round 一次只放一題，兩者等價。但如果有人往一隻 stop 模式的 agent 一次塞三題再 `aos-exec` 它，它會三題都答完才回來，不是答一題回來一次。要嚴格版得在表上多一格或讓 finish 退 10、再被 loop 停（但那樣 state 會停在 finish 而不是 idle，違反 P-34「正常結束 stack 要停在起點」），都不乾淨。**建議：不做**；真要「一次只處理一題」的人用 loop 的 `max` 或一次只塞一題。 **已定：照建議（使用者 10-30「都照建議」）。**
3. **舊 round 骨架要不要留一陣子並存。** 背景：C 的建議是六步內換完、最後一步刪掉 `aos-parts run round` 這個叫法；期間（第 2～5 步）新舊都跑得動。另一條是刪掉的那步不做、留著當「不用 fsm 的對照版」。**後果**：留＝兩套各自長、改器官介面要改兩邊（C-52 一件事寫一處）；刪＝要回頭看舊版去 git log。**建議：換完就刪**。 **已定：照建議（使用者 10-30「都照建議」）。**
