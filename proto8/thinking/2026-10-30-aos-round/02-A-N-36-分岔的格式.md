## A. N-36 分岔的格式（結論）

1. **`next` 兩種寫法，舊的照舊**：字串＝原本的意思（格退 0 才走過去，其他碼 state 不動、fsm 以那個碼退出）；**物件 `{結束碼: 狀態名, …}`**＝照格的結束碼查表走。key 是十進位整數的字串（`"0"`、`"10"`、`"1"`、`"143"`）或 **`"*"`**（其餘全部；照 Unix `case` 的 `*)` 老慣例，C-54 查過就用）；值是表上的狀態名，規則同字串 `next`（非空、頭尾沒空白、沒換行、要在表上）。例：

   ```json
   "idle": {"exec": ["idle", {"$env": "ROUND_AGENT"}], "next": {"0": "think", "10": "idle"}}
   ```

   這是 C-55「純值不夠用就長成物件、key 不變」的一次套用：`next` 這個 key 不變，值從一個名字長成一張小表。不另開 `on_code`、`branches` 之類的新 key（C-56）。
2. **查得到＝這一步正常**：格退 c，表上有 `"c"`（或沒有 `"c"` 但有 `"*"`）→ 把那個狀態名寫進 state（N-05 先寫暫存再改名）、**fsm 以 0 結束**；**查不到＝跟現在一樣**：state 不動、fsm 以 c 結束（loop 看到 10 就停、看到其他非 0 就失敗停下，P-19／P-20 原樣）。理由：N-43「每層只說自己」——表上寫了那個碼怎麼走，fsm 就是照表走了一步，對外面的 loop 來說這一步是正常的；沒寫的，fsm 不知道怎麼辦，照舊透明轉交。「透明轉交」這個例外從「一律」改成「表上沒接住的才轉交」。
3. **跟 N-43 現有的碼怎麼對**：不加新碼、不改 10 的意思。`0`＝這一步好了；`10`＝「正常，但這一步到此為止／沒事可做」（agent-round § 3 早就把 10 統一成這個意思）；其他非 0＝錯。分岔只是讓「10 之後往哪走」「錯了往哪走」可以寫在表上。aos-round 的範本表**只用 0 與 10**（見 B），不發明 11、12——照使用者 10-15「結束碼不要太依賴」。把錯誤碼（`"1"`、`"143"`）寫進表、導回自己或導到善後格，**不禁止、風險自擔**（N-38 ⑥：無窮轉移只有 loop 的 `max` 擋；N-18 使用者自行承擔）——這是 P-20「預設停」的門從表上打開，見衝突 3。
4. **物件至少要有 `"0"` 或 `"*"`**（開跑時查整張表，N-36 既有的規矩）：少了＝表壞、退 1、不跑格。理由：退 0 查不到就會「state 不動、fsm 退 0、loop 下一次又跑同一格」——等於偷渡乙案「成功但留在原地」，使用者已說不走，表上不准寫得出來。
5. **跟 P-36 巢狀、逾時殺整群怎麼對**：不變。被外層 `timeout_ms` 收掉的格碼是 128＋訊號，表上**沒寫**它就照 P-36＝失敗、state 不動、上面停；表上寫了 `"143"` 或 `"*"` 就會接住——條文寫明「`*` 也接得住 128＋N，要不要接是你的事」，範本表不接。fsm **自己**收到 SIGINT／SIGTERM／SIGHUP 的例外照 N-38：那格跑完照表寫 state（含分岔）、然後以 128＋N 結束、不以 0 結束。
6. **trace 怎麼記分岔**：trace 每行**加一個 `next`**＝這次寫進 state 的狀態名，沒換狀態＝`null`。欄位變成 `{"started_at","state","code","signal","elapsed_ms","next"}`，字串 `next` 的格也記（0 → 名字、其他 → null），一致。理由：P-38 看樹就看 trace；有分岔後光看 `code` 推不出走到哪（表會改），一個欄位省掉對表。名字照表的 key（C-54 一詞一義）。頂層代定、可翻案（N-39 字面要加註，見衝突 5）。
7. **aos-loop 不改**。loop 看到的仍是 fsm 的碼：0 繼續、10 停（退 0）、其他停（退那個碼）。ctl 的 `paused`／`stopped` 每格之間都看一次（loop 本來就一次一格）。
