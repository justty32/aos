## C. 換過去的路（結論）

- **agent-nia**：`loop.json` 的 `exec` 換成 `aos-round`；`parts.json` 的 `round` 槽留著（aos-round 從這裡讀 `ROUND_ON_EMPTY`、`MAX_RETRIES`；路徑仍指 `lib/agent/round`，只是那資料夾不再有 `_entry` 骨架而是表＋格）。`system.txt`、`tools.json`、其他槽不動。**aos-ai**（spawn 複製範本、run＝aos-exec）只跟著範本走，不改程式；agent-ops／aos-ai 的文件裡「round」一詞改口。
- **eca-claude／eca-codex 的 `turn`**：**不動**。turn 一格就是一整輪（認領 → 問 CLI → 接回 → 收信），放進 aos-round 的表只會變成一張只有一格的表，什麼都沒多（C-56）；P-43 才剛落正文、外部 agent 的形狀以它為準。之後若要外部 agent 也有「插話」「被打斷接著做」，再把 turn 拆成 idle／ask／finish 三格、腦換成 cli_session，走同一張表——留在 eca § 之後再改那一節的旁邊，不排。
- **ask_round**（`lib/aos/ask_round`）：現在「重叫 round 直到有答案」（代定 46）改成「**重叫 `aos-round` 直到 state 回到 `idle` 且 history 最新的 assistant 比題目新**」——每叫一次＝一格，`ASK_MAX_ROUNDS` 改名 `ASK_MAX_STEPS`、預設放大到 200（一題大約 4～8 格，含工具呼叫更多）；`timeout_s` 照舊；退 10／其他碼的判斷照代定 46 對應（fsm 退 10＝queue 空卻沒答案＝`AnswerMissing`，其他＝`RoundFailed`）。不用 `aos-exec <agent>` 整隻叫：那會照 agent 自己的 `ROUND_ON_EMPTY`，idle 模式的 agent 永遠不回來，而 parts.json 的 env 又壓過環境變數（代定 31 那條）。
- **舊 round 骨架**：**不並存、照步驟換掉**——第 2 步先把函數搬成 `roundlib.py`、長出五格與兩張表，舊 `_entry` 一直跑得動；第 3～5 步把 agent-nia、ask_round、測試換到 aos-round；最後一步刪 `_entry`、`--step`、`hook/pause`、`unit` trace。期間 `aos-parts run round <agent>` 照舊能跑（方便對照），換完就沒有這個叫法。理由：「下一步是什麼」只能寫在一處（C-52），兩套留著會各自長歪。見方向題 3。
- **測試怎麼對**：`test_fsm.py` 加分岔；`test_round.py` 的 `Round` 類改用 `aos-round`／`aos-loop`＋tmp agent 跑、驗 trace 的 `state`／`next` 序列（像 `test_dan_q` 驗 `state` 那樣）而不是 `unit` 序列，案例一對一搬（on_error switch、retry 上限、插話、`ON_EMPTY idle`、補認領、loop＋ctl paused、crash 後從 state.txt 接著做）；`test_round_queue.py`（queue／history／compact 三格）不動；`test_nia.py` 跟著 loop.json 與 ask_round 改；`test_dan.py`／`test_dan_q.py` 不動（字串 `next` 照舊）；`test_eca_turn.py` 不動。
- **條文**：N-36 改口、N-43／N-39／P-20／P-35 加註（草稿在下）；agent-round § 2、§ 3、代定 27 加一行「10-30 起由 aos-round 取代」；CONVENTION 06 的 P-36 不用改。

## D. 「拆散放進每一格」那條路（一段話）

就是 agent-dan-q 現在的長法：agent 資料夾裡自己寫一張 `fsm.json`、每格是自己的程式（認領、問腦、跑工具各寫一支或合寫），不經 aos-round、不一定有 `parts.json`，round 的順序與判斷散在各格裡。**什麼時候用**：這隻 agent 的「一輪」跟範本不同形（多一格審稿、腦不是 OpenAI 訊息、沒有 history、要在兩格之間插自己的狀態），aos-round 那張表擺不下的時候；代價是每隻自己維護一份順序，aos-round 改了它不跟。有了分岔之後，這種 agent 也能用物件 `next` 接 10、寫善後格，不必像以前只能排成一直線。不做範本、不寫條文，demo/agent-dan-q 就是例子。

## 條文草稿（草稿、待使用者看；不改 NORMS／CONVENTION 正文）

### NORMS 組合子 N-36 改口（`next` 兩種寫法）

> **N-36 10-30 改口（使用者 10-30「fsm 的 next 可以按照結束碼分岔……依據不同結束碼導向不同分支」，選甲；細節 fable 代定、可翻案，[thinking 10-30 aos-round](02-A-N-36-分岔的格式.md#a-n-36-分岔的格式結論)）**：每格的 `next` 收兩種——**字串**＝一個狀態名，意思照舊（格退 0 才把它寫進 state，其他碼 state 不動、fsm 以那個碼退出）；**物件** `{結束碼: 狀態名, …}`＝照格的結束碼查表：key 是十進位整數的字串（`"0"`、`"10"`、`"143"`）或 `"*"`（其餘全部，含 128＋訊號），值是表上的狀態名（規則同字串 `next`）。格退 c：表上有 `"c"`（沒有 `"c"` 但有 `"*"` 也算）＝把那個狀態名寫進 state、**fsm 以 0 結束**（這一步照表走了，每層只說自己，N-43）；查不到＝state 不動、以 c 結束（透明轉交，照舊）。物件**至少要有 `"0"` 或 `"*"`**，開跑時查整張表（跟 `start`、`exec` 一起），少了＝表壞、退 1、不跑格——退 0 不准查不到，免得變成「成功但留在原地」。fsm 自己收到訊號的例外照 N-38：那格跑完照表寫 state（含分岔），再以 128＋N 結束。把錯誤碼或 `"*"` 寫進表、導回同一格或善後格，fsm 不擋、不數（無窮轉移只有 loop 的 `max` 擋，本檔開頭 ⑥）、風險自擔；範本 `lib/agent/round/` 的表只接 0 與 10。

### NORMS 組合子 N-39 加註（trace 加 `next`）

> **10-30 加註**：trace 每行多一個 `next`＝這次寫進 state 的狀態名、沒換狀態＝`null`；字串 `next` 的格也記（退 0 是名字、其他是 null）。欄位序 `{"started_at","state","code","signal","elapsed_ms","next"}`。（P-38 看樹就看 trace；有分岔後光看 `code` 推不出走到哪。頂層代定、可翻案）

### NORMS 總則 N-43 加註

> **10-30 加註**：「`10`＝要求外面的 loop 別再跑了」是對**直接收到它的那一層**說的；中間隔著 fsm、表上接住了 10（N-36 的物件 `next`），fsm 就以 0 結束、loop 不會看到 10。同理「其他非 0＝有錯」是對沒接住它的那層說的。結束碼本身的意思不變，不加新碼。

### CONVENTION P-20、P-35 加註

> **P-20 10-30 加註**：用 aos-round（或自己寫物件 `next`）的 agent，「任一格失敗＝停下等人」是**表上沒接住那個碼時**的預設；表上接了就照表走。範本表不接錯誤碼，所以範本仍是失敗就停；endpoint 的 retry／switch 照 10-28 在 think 格內問 `hook/on_error`、數 `MAX_RETRIES`，不寫在表上。
>
> **P-35 10-30 加註**：「10 只有 idle 退」是字串 `next` 那種表的慣例；物件 `next` 的表上，任何一格的 10 都可以被接住（aos-round 的 think 退 10＝該交卷、act 退 10＝插話），接住的 10 到不了 loop。「格叫工具時工具的非 0 一律當失敗、自己 exit 1」那半句不變。
