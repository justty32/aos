## 決定（11-03，使用者）

- **統稱 `proc`**：daemon 管的子項，不論是包在 aos-loop 裡一直跑的（loop 型）還是 aos-exec 跑一次的（exec 型），都是 proc；exec 是基石、loop 是另一種基本形式、以後可能更多。跟 Linux 的 proc 撞名「沒差」。
- **名單合一**：`loops`＋`execs` 兩份名單合成一份 **`procs`**。手把、狀態窗、信箱、小格資料夾全部跟著統稱改名。
- **沒有 `kind`**（「kind這東西沒用吧，刪掉」）：daemon.json 的每項、手把、信、狀態窗的列、log 行都**不帶** `kind`；一項怎麼起（包成 loop 還是 aos-exec 一次）**看它自己的寫法**——就像 `aos-daemon-ctl add` 今天已經在做的自動識別（有 `loop.json` 的資料夾＝loop 型、其他＝exec 型）。規則在[規劃 § 2](#2-看寫法決定怎麼起代定)。
- **舊 key 當沒看到**（「1. 當沒看到。」）：daemon.json、`procs_ctl.json`、信裡出現 `loops`、`execs`、`loops_ctl`、`loops_state`、`loops_ctl_mailbox`、`loops_added`……一律照 C-48 當不認得的 key、忽略；不報錯、不提醒、不做過渡期。

### 2. 看寫法決定怎麼起（代定）

今天兩份名單裡的寫法，攤開來只有三種，合成一份之後規則是：

1. **字串、陣列**（`"../tick"`、`["/bin/sleep", "2"]`）＝**aos-exec 一次**（exec 型）。這跟全體系「字串＝aos-exec 的目標」（C-55、N-28）同一個意思——一個 proc 寫成「要跑什麼」，就是跑它；使用者說的基石。（今天 `loops` 裡的字串會被包成子 loop，這一點改掉。）
2. **物件，而且 key 只有 `exec`、或 `exec`＋`ws`**（`{"exec": 單子}`、`{"exec": [目標, 參數], "ws": "…"}`）＝**aos-exec 一次**。這正是今天 `execs` 物件的全部寫法（10-30 `ws`、11-02 晚「6.要」的內嵌單子），一字不改。
3. **其他物件**（多了任何一個 key：`max`、`interval_ms`、`ctl`、`state`、`body`、`envs`……）＝**loop 設定、包成子 aos-loop**。這也是今天 `loops` 物件的處理：daemon 只解它認得的幾格，其餘原樣交給子 loop、不驗。所以「多了 key」不必列清單——只要不是第 2 種那個最小形狀，就是給 aos-loop 的。
4. **沒有 `exec` 的物件**（`{}`、`{"ws": …}`、`{"max": 3}`）＝第 3 種，原樣交給子 loop、由它退 1「沒有東西可跑」（今天 `loops` 就這樣；N-28「daemon 收子項只看它自己需要的」）。
5. **同一個名字改寫法**（ctl 或信把 `bob` 從 `{"exec": X}` 改成 `{"exec": X, "interval_ms": 500}`）：**已在跑的不重起**——照 N-54「名字已在表上的不看設定變了沒」，寫法是設定的一部分；等它結束或被 `procs_removed` 再放回才照新寫法起。取代 10-30「種類不一樣＝收掉舊的、下一次起新的」（那條是兩份名單時代的產物；沒有種類欄之後 adopt 也無從比對）。
6. **`aos-daemon-ctl add` 的 loop 型**：送出去的 loop 設定**一定帶 `ctl`／`state`**（沒寫就補 `"ctl": "ctl.json"`、`"state": "state.json"`——跟 daemon 替子 loop 補的一模一樣、語意零改變），這樣就算那份 `loop.json` 只有 `{"exec": …}`（例 `demo/self-improve/loop.json`）也不會被當成第 2 種跑一次。exec 型照舊送目標本身。
7. **狀態窗、`ls`、log 不標哪種**：使用者「kind 沒用」。要分，看小格：loop 型的 `procs/<名字>/loop.json` 是 daemon 寫的，exec 型沒有這個檔（單子型有 `exec.json`）。`Child::once` 留在記憶體裡（起的時候照 1～3 判），adopt 接回來的不知道、也不需要知道（收法一樣：SIGTERM 那個 pid、10 秒 SIGKILL 整群；第 5 條之後也不再拿它比對）。
8. **名字唯一**：`procs` 是一個 JSON 物件，同名本來就只剩一個（`$ref` 陣列合檔時後面的蓋前面的）；`check_apart` 退場。**exec 型跑完**照 11-02 的規矩不變——`done` 印 log 一行、從表上拿掉、記 `ended_`（只記名字）、本次執行不再起；同名再 `procs_added`（信）或名單有一圈沒有它（ctl）＝重新起。loop 型同理。
9. **真正的坑只有一個**：直接在 daemon.json 寫 `"x": {"exec": "fsm.json"}` 想要一支不停跑的 loop，會變成跑一次。要 loop 就寫一個 loop 的 key（`"interval_ms": 0` 或 `"ctl": "ctl.json"`），N-28 補一句例子。沒有別的坑：有 `max`／`interval_ms`／`ctl`／`state` 的一定是 loop，有 `ws` 沒別的一定是 exec。

跟原則對過：這是 C-55「雙形都收」與 N-28 既有「字串包成 loop、物件原樣交出」同一種讀法，只是把「字串」跟「最小物件」劃給 aos-exec；沒有暗值（C-56 管的是「同一個 key 的某個特定值偷偷換行為」，這裡是形狀決定交給誰，跟 `exec` 字串＝目標、物件＝單子一樣）。**沒有跟原則打架的地方，不列衝突。**
