## pi 的調查結論（2026-10-24 查，`badlogic/pi-mono` 主線 commit `136b87e8`，2026-10-23）

來源：[coding-agent/src/core/tools/](https://github.com/badlogic/pi-mono/tree/main/packages/coding-agent/src/core/tools)（read.ts、write.ts、edit.ts、edit-diff.ts、bash.ts、truncate.ts、path-utils.ts、index.ts）、[system-prompt.ts](https://github.com/badlogic/pi-mono/blob/main/packages/coding-agent/src/core/system-prompt.ts)、[coding-agent README](https://github.com/badlogic/pi-mono/tree/main/packages/coding-agent)、作者文章 [What I learned building an opinionated and minimal coding agent](https://mariozechner.at/posts/2025-11-30-pi-coding-agent/)（Mario Zechner，2025-11-30）。

- **預設只開四個**：`read`、`bash`、`edit`、`write`（`createCodingTools`）。另有 `grep`、`find`、`ls`（唯讀組）與 `powershell`，預設不開。
- **作者的理由**：「if I don't need it, it won't be built」；「these four tools are all you need for an effective coding agent」——模型本來就會 bash，也被訓練過類似的讀／寫／改格式。system prompt 加工具說明不到 1000 token（模型已被 RL 訓練成懂 coding agent，不需要上萬 token 的 prompt）。不做 MCP（工具說明一開場就塞滿 context；寧可給 CLI＋README，讓 agent 要用時才讀）、不做子 agent、不做 plan mode。預設 YOLO：不問權限、檔案系統與指令全開——作者說別家的防護「mostly security theater」，能寫能跑程式的 agent 本來就擋不住外洩；怕就跑在容器裡。
- **read**：`{path, offset?, limit?}`。輸出最多 2000 行或 50KB（先到先算），從頭截，截了就在尾巴寫「Showing lines a-b of N. Use offset=… to continue.」；`limit` 停在檔尾前也提示；第一行就超過 50KB 時叫你改用 `bash: sed -n 'Np' … | head -c …`。**不加行號**。圖片（jpg/png/gif/webp/bmp）當附件送給模型。
- **write**：`{path, content}`。沒有就建、有就蓋、上層資料夾自動建；回「Successfully wrote to path」。
- **edit**：`{path, edits: [{oldText, newText}]}`（也收舊的單一 `oldText`／`newText`、收被模型寫成字串的 `edits`）。每個 `oldText` 都對**原檔**比、要剛好出現一次、彼此不重疊、不能空；改完跟原本一樣算錯。先精確比，找不到再模糊比（NFKC、行尾空白、彎引號、各種破折號與空白）。照 LF 比、寫回時還原 CRLF 與 BOM。回「Successfully replaced N block(s) in path.」（diff 只給畫面看）。
- **bash**：`{command, timeout?}`（秒，**沒有預設逾時**）。cwd＝工作資料夾，stdout＋stderr 合在一起，**從尾巴截**（最後 2000 行或 50KB），截了就把全文存暫存檔、告訴模型路徑。指令退非 0：輸出加「Command exited with code N」、標成錯。逾時／中止：整個行程樹殺掉，回「Command timed out after N seconds」。
- **路徑**：相對路徑從 cwd 算、可以給絕對路徑、`~` 展開；**不擋出 cwd**。
- **錯怎麼回**：工具丟例外 → 當成錯誤結果回給模型（模型看得到原因、自己改），agent 不停。
- **system prompt 開頭**：「You are an expert coding assistant operating inside pi … You help users by reading files, executing commands, editing code, and writing new files.」接著列工具一行說明、幾條規矩（用 read 不要 cat、write 只用在新檔或整份重寫、edit 的 oldText 要精確且盡量短、多處合成一次 edit、回答簡短、路徑寫清楚）。

## 決定（使用者 10-24「都按建議做」，照推薦定、可翻案）

1. **工具組放 `proto8/demo/pi-tools/`**：`read/`、`write/`、`edit/`、`bash/` 四個資料夾程式，各一份 `tool.json`（P-41 形狀）＋`_entry`（python3 純標準庫，照 agent-dan 的 math 慣例）。只做 pi 預設的四個，唯讀組（grep、find、ls）不做——bash 就能做（同 pi 只開四個的理由）。
2. **參數名照我們的命名**（C-54 小寫底線）：edit 是 `edits: [{old_text, new_text}]`；其餘同 pi（`path`、`offset`、`limit`、`content`、`command`、`timeout`）。不收 pi 為了相容舊模型的那些變形寫法。
3. **長度上限照 pi**：2000 行或 50KB。read 從頭截、提示 offset；bash 從尾巴截、只寫「只留最後幾行」，**不存全文暫存檔**（存了模型也讀不到：在工作資料夾外）。
4. **限制在工作資料夾＝`$AOS_WS`**（跟 pi 不同）：read／write／edit 的路徑從 `$AOS_WS` 算，解開 `..` 與符號連結後必須還在裡面（`PathBad`）；裡面的絕對路徑可以。bash 的 cwd 是 `$AOS_WS`，但指令本身擋不住（同 pi 的看法：能跑程式就擋不住），要真隔離就把整隻 agent 放進容器。
5. **bash 一定有逾時**：預設 30 秒、上限 300 秒（pi 沒預設）。逾時＝整群先 TERM、2 秒後 KILL，算工具的錯 `CommandFailed`，逾時前的輸出照給。指令自己退非 0 **不算**工具的錯，結果尾巴寫「[結束碼 N]」；被訊號停寫「[被訊號 N 停掉]」。工具被外面 TERM（act 格逾時）時先停掉指令那一群再走，不留孤兒。stdin 是 /dev/null。
6. **edit 規則照 pi**（對原檔比、唯一、不重疊、不空、改完一樣算錯、全有或全無、CRLF 還原），**不做模糊比對**、不管 BOM（KISS；之後模型常撞再加）。read 不加行號、不讀圖片（拒絕二進位檔，`FileBad`）。
7. **錯誤照現行慣例**：stderr 一行「工具名: 代號 原因」、退 1；代號照 C-54：`ArgumentsBad`、`WsMissing`、`PathBad`、`FileMissing`、`FileBad`、`ReadFailed`、`WriteFailed`、`MkdirFailed`、`TextMissing`（edit 找不到）、`TextBad`（edit 不唯一／重疊／空／改完一樣）、`CommandFailed`（bash 逾時）、`LaunchFailed`。**同一行也印在 stdout**——stdout 是給腦看的結果，腦才知道錯在哪。
8. **掛上這套的 coding agent＝`demo/agent-pip`**（人名接 demo 慣例；ann、bob、cathy、dan、eve、fay 已有人用）：從 agent-dan 照抄，`tools` 是指到 `../pi-tools` 的符號連結（act 叫的地址仍是 `tools/<名>`、零個 `..`）。`system.txt` 照 pi 的精神寫短版。loop `max` 200、think 逾時 180 秒、act 900 秒。
9. **agent-pip 跟 agent-dan 不同的一條：這一次叫工具出的問題回給腦、不停**（10-24 晚起 agent-dan 也這樣，[tool-calls 文末](2026-10-23-tool-calls.md#10-24-定叫工具與小念頭的失敗回給腦)）。工具退非 0（stdout 照收、尾巴加「(工具 X 結束碼 N)」）、叫了沒有的工具（`act: ToolUnknown …`，附能叫的清單）、`arguments` 不是 JSON（`act: ArgumentsBad …`）都接成一則 tool 訊息讓腦自己改。act 不讀工具的 stderr（C-52、C-53：腦看到的是工具自己放進 stdout 的那行）。理由：寫程式時 edit 找不到原文是常事；照 agent-dan 停下的話，人重跑會再叫同一個呼叫、永遠卡在同一格。這也回答了 10-23 留的「叫了不存在的工具停下還是回給腦」——**agent-pip 回給腦、agent-dan 照舊停下**（範本各自選）。
10. 試驗場 `~/code/try/pi-tools/`。

## 邊緣狀況（攤出來，不擋）

- **stack 放在工作區裡時，腦碰得到自己的對話**：`AOS_STACK` 預設 `$AOS_WS/.stack/`，write／edit／bash 都能改 `history.jsonl`、`state.txt`。工具不知道呼叫者的 stack 在哪（C-52），擋不了；真跑時把 `AOS_STACK` 放在工作區外（試驗場就是這樣跑）。
- **bash 擋不住出工作資料夾**（`cat /etc/passwd`、`rm -rf ~`、連網）：路徑檢查只管 read／write／edit。要隔離得靠容器或另一層沙箱。
- **錯誤那行在 stdout 與 stderr 各一份**：工具被 agent-dan 那種「退非 0 就停」的 act 叫時，stdout 那行沒人看，無害。
- **對話越來越長**：read 一次最多 50KB、bash 也是，幾輪就很大；history 不設上限（10-23 第 6 點），之後撞到模型的 context 上限會 `BrainFailed`（HTTP 400），沒有自動壓縮。
- **同一題卡死在腦一直重試**：錯誤回給腦之後，腦可能一直叫同一個錯的呼叫；只有 loop 的 `max`（200 次≈66 輪）擋著，到了 loop 停、題目留在 `cur/`。
- **bash 的指令自己開背景行程、脫離行程群**（`setsid`、`nohup … &` 再 `disown`）：逾時整群停不到它。
- **edit 不做模糊比對**：模型把彎引號、全形空白、行尾空白抄錯時就是 `TextMissing`，靠腦重讀再改。
- **符號連結指向工作區外**：read／write／edit 一律當 `PathBad`（含工作區裡本來就有的連結，例如 agent-pip 自己的 `tools` 連結不在工作區、不受影響）。
- **跟 agent-as-tool 那條重疊**：那邊的子 agent 也要讀檔／寫檔／跑 python 的工具，之後可以直接掛這套（`tools` 連結或複製），不再各寫一份。

## 10-24 稍晚：資料夾與檔案的工具要特別設計（file-tools）

### 使用者原文

> 因爲很多東西都是靠資料夾和檔案。所以資料夾修改和檔案這兩個工具我需要特別設計。比如ls工具，返回一個陣列，AI可以在去看特定檔案的屬性和內容

（前文，JSON 工具那條：「agent說想要看某些json，那就是給他json頂層，他說想看特定key，再逐一給他看細節」——同一個「漸進展開」的精神。）

> 修改檔案這塊，json檔案修改起來，其實對AI很友好，一方面AI熟這些，AI生成json幾乎不會有問題，另一方面因爲是分層的，所以AI可以只去看他想看的東西。

### 決定（使用者 10-24「都按建議做」，照推薦定、可翻案）

1. **另開一套 `proto8/demo/file-tools/`**，當 pi-tools 的延伸：`ls`、`stat`、`view`、`json_edit`、`mkdir`、`move`、`copy`、`trash` 八個資料夾程式，各一份 `tool.json`；共用的路徑限制、輸出、錯誤放 `file-tools/common.py`（各 `_entry` 照自己的真實位置找它，用符號連結掛進 agent 也找得到）。**跟 pi 的差異**：pi 只有四個、讀檔回純文字；這套多出「先看結構、再看屬性、再展開內容」的一層層工具，**輸出一律 JSON**（錯時是 `{"error": "工具名: 代號 原因"}`，stderr 照慣例一行、退 1）。
2. **ls** 回 `{path, total, items: [...], next_offset?, hidden?}`；每項 `name`、`type`（file／dir／link）、`mtime`；檔多 `size`、`exec`；`.json` 檔多 `keys`（頂層 key，最多 12 個，多的寫 `keys_more`）；資料夾多 `children`（子項數）與 `aos`（裡面有 `_entry`、`_entry.json`、`_metainfo`、`_metainfo.json`、`.env`、`tool.json`、`loop.json`、`fsm.json` 的哪幾個）；連結多 `link_to`。`.` 開頭的預設不列（數目放 `hidden`，`hidden: true` 才列）。資料夾在前、照名字排；一次預設 100 項、上限 500，分頁用 `offset`。
3. **stat** 看單一個：`type`、`mtime`、`mode`；檔多 `size`、`exec`、`text`、`lines`、`format`（json／python／markdown／shell／text），JSON 檔多 `top`（頂層摘要）；資料夾多 `children`、`aos`；連結多 `link_to`（斷的標 `broken`）。
4. **view 漸進看內容**：**JSON 檔走分層**——`pointer`（RFC 6901，空字串＝整份）一次看一層，序列化後 ≤ 1000 字直接給 `value`，大的給 `children`（每個子項的型別與大小：物件幾個 key、陣列幾項、長字串幾字），要看哪個就把 key 接到 pointer 後面再叫。內容解得開就算 JSON（含沒副檔名的 `_entry`）。**文字檔**：≤ 200 行且 ≤ 8KB 整份給；大的先給大綱（Python 的 class／def 與行號範圍、Markdown 的標題與行號、其他給前 40 行），再用 `start`／`end`（行號）看那段；一次最多 2000 行或 50KB（同 read）。JSON 檔給 `start`／`end` 就當文字看。
5. **json_edit 照指標改 JSON**：`{path, set: {指標: 值}, del: [指標]}`；先自己檢查全部指得到（`PointerMissing` 就都不改），再交給 **aos-json**（`proto8/impls/aos-json`，另一條線做的 JSON 工具集）寫：set 一次 `aos-json batch --parents`（全有或全無、原子寫入、排版照留），del 每個一次 `aos-json del`。aos-json 照 PATH 找（同 aos-exec，由呼叫者放好），它的 stderr 原樣往上、這裡不讀（C-53），失敗只說 `WriteFailed aos-json … 結束碼 N`。讀用 view 自己做（aos-json 的 peek 輸出是文字，這套要 JSON）。不穿 `$ref`。新的 JSON 檔用 pi-tools 的 write 整份寫。
6. **資料夾修改**：`mkdir`（上層一起建、已有＝`created: false`）、`move`（搬移／改名，`to` 上層自動建，`to` 已有東西就不搬——要蓋先 trash）、`copy`（檔或整個資料夾，連結照連結複製、不跟進去；先複製到 `.` 開頭的暫存再改名）、`trash`（**刪除＝搬進 `$AOS_WS/.trash/<時間>/<原路徑>`**，同一秒再丟加 `-1`、`-2`；垃圾桶裡的不再丟；要救用 move 搬回來；真的清掉垃圾桶是人的事）。原子寫入照 pi-tools 的 write（N-05）。
7. **限制在工作資料夾**同 pi-tools（`PathBad`；move／copy／trash 的最後一節是連結時動連結本身、不跟進去）。新代號：`PointerMissing`、`MoveFailed`、`CopyFailed`。
8. **agent-pip 兩套一起掛**：`tools/` 改成真資料夾，裡面十二個相對連結（`../../pi-tools/<名>`、`../../file-tools/<名>`）；`system.txt` 加「先 ls 看結構、JSON 用 view 的 pointer 與 json_edit、其他文字檔大的先看大綱、刪東西用 trash」。

### 實跑（10-24）

LiteLLM 還是連不上，用假腦劇本（`~/code/try/pi-tools/explore/`）：題目「工作資料夾裡有一隻 aos agent。找出它的 act 那一格逾時是多少，改成 5 分鐘」——`ls` 看到 `agent-dan` 帶 `aos: [_entry, .env, loop.json, fsm.json]` → `ls agent-dan` → `view fsm.json#/states/act`（直接給 value：`timeout_ms: 60000`）→ `json_edit set /states/act/exec/timeout_ms 300000` → `view` 那個指標確認 → 答。結束碼 0，`fsm.json` 只動那一行、其他排版照留。

### 邊緣狀況

- **json_edit 同時給 set 與 del**：set 那批是一次原子寫入，del 是一個一個寫；del 中途失敗時 set 已經寫進去了（先檢查過指標，正常不會發生）。
- **aos-json 還在另一條線開發中**（10-24 還沒進 git）：它的命令列改了，json_edit 要跟著改；測試在 aos-json 沒建好時 skip。
- **ls 會列出 agent 自己的題目資料夾**（`new/`、`cur/`）與 `.trash`（hidden）：腦可能動到自己的題目；同 pi-tools 的 stack 那條，要隔離就把題目與 stack 放工作區外。
- **垃圾桶只進不出**：沒有自動清；工作區越用越大。
- **view 判斷 JSON 是「解得開就算」**：一個剛好是合法 JSON 的文字檔（例如只有一個數字）會被當 JSON 看；要看原文給 `start`／`end`。
- **大 JSON 陣列**：children 最多列 200 個（多的寫 `children_more`），沒有分頁；要看後面的直接指標到那一項。
