# 2026-10-15 命名：proto8 現況盤點

← [命名](../2026-10-15-naming.md)｜規則：[C-54](../../CONCEPTS/01-設計理念.md#命名10-15-使用者說原文)｜縮寫表：[abbr.json](../../CONCEPTS/abbr.json)

## 未決（AI 只讀盤點，附推薦；程式另一個 agent 在改，這裡都沒動）

依重要性排：

1. **兩種 kernel 的名字分不出誰是誰**：LLM kernel＝`aos_gate_kernel.py`＋說明 `kernel.md`＋demo `kernel/`；通用 kernel＝`aos_kernel.py`＋`kernel2.md`＋demo `kernel2/`。「2」不說是什麼，`aos_kernel.py` 反而不是第一種。推薦（主題在前）：`aos_kernel_llm.py`、`aos_kernel_general.py`（判官 `aos_kernel_judge.py` 已合）；說明 `kernel_llm.md`、`kernel_general.md`；demo `kernel/llm/`、`kernel/general/`；子命令 `aos kernel llm|general`。
2. **`control_dir`**（daemon.json）：使用者自己舉的例子正是 `ctl_dir`，全體系也都叫 ctl。推薦改 `ctl_dir`；說明寫清楚它是「指令式控制資料夾」，跟 `ctl`（宣告式 ctl 窗）是兩樣東西。
3. **同一個字兩個意思：env**：inst 的 `envs`、指示詞 `$env`＝環境變數；frame 的 `env.json`＝`{"parent": 定義資料夾}`（Lisp 的環境）。違反「記一次全體系通用」。推薦 frame 那份改名（例 `parent.json`，內容就是 parent），env 只留給環境變數。
4. **同一個東西兩個字：kids／children**：`aos_tree` 的節點用 `kids`，daemon 用 `children`。推薦統一 `children`。
5. **格的資料夾叫 `cells/`、表裡叫 `states`**（fsm.json `states` → `cells/x.json`）：名詞「格」已在 lib 用開，可接受；推薦在 lib fsm.md 的資料夾圖上標一句「states 的每格放 cells/」就好，不改。
6. **frame 裡三種分隔符混用**：`fsm-state.json`、`loop-state.json`（連字號）、`args.taken.json`（點）、`work/think-fails.json`、`steps.jsonl`。推薦用資料夾減分隔符：`state/fsm.json`、`state/loop.json`（主題 state 在前），`args.taken.json` 可保留（點＝同一份的另一個角色）。
7. **demo/kernel2 平鋪的前綴檔**：`gate-cpu.json`／`gate-human.json`／`gate-llm.json`、`judge-agent.json`／`judge-broken.json`／`judge-rules.json`／`judge.schema.json`，旁邊還有 `judge/`（agent 定義資料夾）。推薦照 `./insts/a.json`：`gates/cpu.json`…；三種判官設定放 `judges/agent.json`、`judges/broken.json`、`judges/rules.json`，agent 定義資料夾移成 `judges/agent/`（或保留 `judge/` 由使用者挑）。demo/kernel 的 `gate.json`／`gate-fake.json` 同理。
8. **lib 說明頁（連字號）跟程式檔（底線）對不上**：`ctl-state.md` ⇄ `aos_ctl_state.py`、`agent-lib.md` ⇄ `aos_agent_lib.py`、`agent-frame.md` ⇄ `aos_frame.py`（主題也不同）。推薦說明頁名＝模組名去掉 `aos_`：`ctl_state.md`、`agent_lib.md`、`frame.md`（或程式改 `aos_agent_frame.py`）。
9. **`lib/judge_rules.py` 少了 `aos_` 前綴、主題不在前**：其他 lib 檔都是 `aos_<主題>_<子類>`。推薦 `aos_kernel_judge_rules.py`（或歸到 demo，它是假判官）。
10. **錯誤代號的詞序不一**（JSON 值，CamelCase）：主詞在前的 `CtlBad`、`CtlMissing`、`StateBad`、`CwdMissing`、`ResourceUnknown`、`ReferenceCycle`、`TreeCycle`；形容詞在前的 `BadArguments`、`BadCommand`、`BadDirname`、`BadLetter`、`BadNext`、`BadReply`、`BadResponse`、`UnknownDirective`／`Flag`／`Next`／`Op`／`State`／`Tool`、`NoApiKey`／`NoConfig`／`NoFsm`／`NoHistory`／`NoResult`。推薦照「主題在前」統一成主詞在前（`ArgumentsBad`、`FlagUnknown`、`ApiKeyMissing`），同主題的錯排在一起、好搜；保留 CamelCase（它在程式裡像類別名，照程式那套）。改代號會動測試，量不小，使用者定要不要動。
11. **同名類別兩處**：`KernelError` 在 `aos_kernel.py` 和 `aos_gate_kernel.py` 各一個。推薦跟第 1 條一起改成 `KernelLlmError`／`KernelGeneralError`，類別名 ⇄ 檔名固定對應。
12. **看名字看不懂的檔**：`demo/fsm/brain/ollama146.json`、`qwen146.json`（146＝主機 IP 尾碼，名字裡看不出；兩份都是 ollama，差在模型）。推薦 `brain/ollama/gemma3_1b.json`、`brain/ollama/qwen2_5_14b.json`（主機寫在檔內 `--base-url`）。`paint/brain/fake-alt.json` → `brain/fake/alt.json` 或 `fake_alt.json`。
13. **`aos_` 前綴每個 lib 檔都有**：照「靠資料夾減底線」可以變成 Python 套件 `lib/aos/daemon/table.py`（`import aos.daemon.table`）。推薦**先不動**：現在平鋪＋前綴在 sys.path 上不撞名、`bin/aos` 對應簡單，等程式穩了再一次搬。
14. **大寫檔名**：`README.md`、`INDEX.md`、`CONCEPTS.md`、`NORMS.md`、`PLAN.md` 與 `CONCEPTS/`、`NORMS/`、`PLAN/` 資料夾。README 全大寫本身也是 Unix 老慣例（`README`、`INSTALL`、`Makefile`，`ls` 時排在前面）。推薦當「入口檔」例外保留，寫進 C-54 的例外；其他一律小寫。
15. **`last_code`／`last_error`／`last_state`、`max_fails`**：修飾詞在前，跟「主題在前」看起來相反。推薦**不改**：`last_` 本身就是一個可搜尋的群組（state 窗裡「上一次的」排在一起），`max_` 是大家都知道的慣例；寫進 C-54 當說明的例子即可。

**複數資料夾**（決定的第 3 條）：

16. **一堆腦放單數資料夾 `brain/`**：`demo/fsm/brain/`（litellm、lmstudio、ollama146、openai、qwen146 五份＋`fake.py`）、`demo/paint/brain/`。推薦改 `brains/`；旁邊的 `brain.json`（這個 agent 用的那一顆）是單一檔案、維持單數。
17. **平鋪的同類前綴檔**：第 7 條的 `gate-*.json`、`judge-*.json`（→ `gates/`、`judges/`）與第 12 條的 `fake-alt.json` 都屬這類。
18. **`lib/`、`bin/`、`demo/` 單數卻裝很多個**：`lib`、`bin` 是 Unix 慣例名（`/usr/lib`、`/usr/bin`）。推薦這兩個列為例外不改；`demo/` 照規則應是 `demos/`，推薦改（連結與 `aos-demo` 的路徑要跟著動），或也列例外，使用者定。
19. **`lib/tests/test_*.py` 檔名重複類別**：pytest 靠 `test_` 前綴找測試，推薦當工具慣例例外保留。另：frame 的 `steps.jsonl` 是單一檔案卻用複數——一個檔裝很多筆（串流、日誌）推薦允許複數，使用者定；`work/think-fails.json` 只存一個計數 `{"n", "error"}`，推薦併進第 6 條一起改（例 `state/think.json`）。

**縮寫表收不進去的**（不認得或有歧義，表裡沒收）：

20. **`sig`**：kernel2 state 的 `last_sig`＝排隊情況的指紋（signature，「信沒變就不問判官」用），但 loop／inst 結果裡的 `signal` 讓人會讀成訊號。推薦改 `last_signature`（不縮）或 `queue_fingerprint`；`sig` 不進表。
21. **單字母 key `n`**：`work/think-fails.json` 的 `{"n"}`。推薦 `fails`。
22. **`metainfo`**：`_metainfo` 不是常見字（常見的是 metadata／meta）。表裡收了 `meta`；`_metainfo` 已寫進很多條規範（C-48、N-42…），推薦不改、在表裡註明。
23. **外部 API 照抄的名字**：`num_ctx`、`keep_alive`（ollama 的參數名）。推薦照外部原名、不進表（不是 aos 自己取的）。

已合的（不用動）：所有 JSON key 都是小寫加底線；帶單位的後綴（`timeout_ms`、`interval_ms`、`aging_ticks`）、主題在前的 `stdout_append`、`exit_mkdir`、`envs_clear`、`judge_fails`、`cell_error`、`ctl_seq`、`ctl_poll_ms`；lib 的 `aos_daemon_table.py`／`aos_daemon_folder.py`、`aos_brain_openai.py`／`aos_brain_ollama.py`；環境變數 `AOS_DIRNAME`、`AOS_PRIORITY`、`AOS_KERNEL`。
