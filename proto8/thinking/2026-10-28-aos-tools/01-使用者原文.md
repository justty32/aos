## 決定（10-28，使用者提的構想與回答，照實記）

1. **aos-tools 維護一份 JSON 註冊檔**（使用者回答裡叫 `tools.json`），記有哪些工具；這份檔「可以被指示詞分開」（什麼意思實作時就知道，見未決）。
2. **指令四個**：`aos-tools add XXX`、`rm XXX`、`ls`、`get XXX`；XXX 是檔案或資料夾。
3. **三種登記對象，各自怎麼給工具定義**：
   - **JSON 檔**：走 aos-exec 的格式（aos-exec 跑得動的那種 JSON），裡面要有 `_tooldef` 這個 key，放工具定義。
   - **python 或其他可執行檔**：要支援 `--tooldef` 旗標（帶這個旗標跑它，它吐出工具定義）。
   - **資料夾**：裡面要有 `_tooldef` 或 `_tooldef.json` 這個檔。
4. **XXX 不符合要求就報錯**：不是「JSON＋`_tooldef`」、不是「支援 `--tooldef` 的可執行檔」、也不是「有 `_tooldef`／`_tooldef.json` 的資料夾」，`aos-tools` 直接報錯——不猜、不跳過。
5. **aos agent 直接吃這份註冊檔當 tools**。
6. **claude code cli、pi coding agent 之類**：啟動它們時經 **aos-mcp** 轉接吃這份註冊檔（aos-mcp＝跑在 aos-tools 上的小包裝，接 10-27 筆記）。
7. 現行 aos-mcp 掃 `tool.json` 的做法要換掉（使用者「太土太粗暴，不夠靈活」）。
8. **註冊檔每個 agent 資料夾一份**（回答 ②）。
9. **路徑**（回答 ③）：指令收絕對或相對路徑都行；相對路徑以**執行 aos-tools 時的 cwd** 解析；註冊檔裡**一律存絕對路徑**。
10. **`--tooldef` 的結果可以快取**（回答 ④）。
11. **工具撞名＝報錯**；加 `--override` 可以蓋掉（回答 ⑤）。
12. **python／可執行檔除了 `--tooldef`，還要支援 `--tool-call XXX`**：XXX 是它要讀的任務（回答 ⑥）。XXX 是檔案路徑還是內容字串，原文沒說死，實作時定。
13. **註冊檔變了，開著的 claude 要不要即時更新：實作者自由選**（回答 ⑦「隨意」）。
14. **現有的 `tool.json` 改成新格式**（`_tooldef`／`_tooldef.json`），實作時一起改（回答 ⑧）；這次只記、程式沒改。
