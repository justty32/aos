## 結論（10-28 實作，照原則代定、可翻案）

使用者 10-28 授權：「好了之後可以開始做aos-tools」「hub也可以開始做。aos-mcp也可以做」。做法：

1. **`proto8/bin/aos-tools`**（Python 標準庫，放 proto8/bin，測試與 demo 的 PATH 本來就有）：`add [--override] [--name N] XXX`、`rm XXX`、`ls [--json]`、`get XXX`，加一個 **`call 名`**（stdin＝arguments，結束碼是工具的）——aos agent 與 aos-mcp 都要「叫一次」，三種登記對象怎麼叫只寫在這一處（C-52）。註冊檔＝`--file` ＞ `./tools.json`，長 `{"tools": {名: {"path": 絕對路徑}}}`；沒有這份檔＝沒有工具（固定名字＋`--file` 覆寫；10-31 使用者給了「固定名字 vs 間接」判準 → [eca § 10-31 原則](../2026-10-30-eca/10-10-31-使用者原文-turn-的定義檔只認固.md#10-31-使用者原則固定名字可以但限縮範圍判準)）。`rm`／`get` 的 XXX 先當工具名、不是就當路徑。工具名預設檔名去副檔名（資料夾名），`--name` 另取，只收 `[A-Za-z0-9_-]`、最多 64 字（OpenAI／MCP 的限制）。
2. **指示詞分開＝`$ref`**（未決第一題；從 N-45「aos 讀的 JSON 都解」推）：註冊檔有 `$ref`／`$env` 就交給 aos-json 解（`get --follow --resolve`）；`{"tools": {"$ref": ["base.json", "mine.json"]}}` 就是拆成兩份，`add` 經 `aos-json set --follow` 寫進最後一份、`rm` 經 `del --follow` 從它所在那份拿掉。`_tooldef`／`_metainfo` 有指示詞也一樣解。
3. **`--tool-call XXX` 的 XXX＝任務檔的路徑**（未決第二題）：使用者說 XXX 是「需要讀取的任務」；用檔不碰命令列長度與跳脫，也不碰 C-42b「schema 怎麼轉 argv」。aos-tools 把 arguments 原樣寫成 `$AOS_STACK/tool_call.json`（沒設 AOS_STACK＝暫存檔、用完刪），再 `aos-exec 檔 --tool-call 那個檔`、stdin 不給。
4. **種類照 aos-exec 的認法**（N-61）：資料夾；檔有 `+x`＝可執行檔；檔沒 `+x`＝JSON。資料夾先找 `_tooldef` 再找 `_tooldef.json`（同 `_entry` 的找法，化解對照第 5 點）。資料夾、JSON 檔叫＝`aos-exec 路徑`、arguments 從 stdin（P-41 照舊）；只有可執行檔走 `--tool-call`（化解第 8 點：兩套照種類分，不並存在同一個工具上）。`--tooldef` 直接跑（cwd＝檔的資料夾、10 秒），不經 aos-exec（不在 cwd 留 `.stack/`）。`_metainfo`：資料夾的檔、JSON 的 key 有就一起給；可執行檔沒有。
5. **快取不違反 P-15**（化解第 7 點）：`add` 是設定時寫；`--tooldef` 的結果在 `add` 時存進註冊檔（`cache`：`stamp`＝mtime＋大小、`tooldef`），讀的時候 stamp 一樣就用快取、不一樣就重跑但**不寫回**——跑起來的時候不寫定義資料夾。
6. **絕對路徑與搬家**（第 9 點）：`add` 一律寫絕對路徑（決定 9）；**手寫的相對路徑從註冊檔所在資料夾算**（同 `$ref` 的相對規則，N-45），所以 git 裡的範本 `tools.json` 寫 `tools/clock` 這種相對路徑、複製搬家不斷；`add` 寫進去的絕對路徑搬家、換機器會斷，要重新 add（使用者自己選的代價）。
7. **報錯不猜**（決定 4）：不是三種之一、沒定義、定義不是物件（`description` 要字串、`parameters` 要物件）、`--tooldef` 失敗都報錯；`ls`／`get` 碰到登記了但壞掉的工具也整個報錯（訊息帶工具名）——所以 aos agent 的 brain 這時停下（`ToolsBad`，P-20 人修好再跑）。以前讀不懂的 `tool.json` 當作沒有，這點行為變了。
8. **aos agent 直接吃**（決定 5）：demo 的 agent-dan、eve、fay、gus、hal、kai、liv、meg、pip、self-improve/improver、talk/member、lib/agent/pyfix/agent，brain 改成 `aos-tools ls --json` 組 tools、act 改成 `aos-tools call 名`；每個範本加一份手寫 `tools.json`（相對路徑，列原本 `tools/` 底下有說明檔的）。`aos-ai spawn --tool`、`make tool` 複製或建好工具後順手 `aos-tools add`。**topdown 的 agent 先不換**（它們的自我優化流程直接建工具資料夾），照舊掃 `tools/*/_tooldef.json`。**10-29 換了**：兩隊七隻 agent（甲隊 writer〔writer-sol、optkit/shell 共用它的 brain／act〕、grader、train/weigh；乙隊 draft/tools/writer、lib/selfopt/host）改讀 `tools.json`（手寫、相對路徑 `tools/<名>`，捷徑照留）；自我優化抽新工具（甲隊 `optkit/opt_extract`、乙隊 `lib/selfopt/extract_tool`）時直接在 `tools.json` 追加一筆相對路徑，**不用 `aos-tools add`**——add 寫絕對路徑，甲隊在拷貝樹裡抽、accept 搬回原樹後會指到拷貝；也不經甲隊的白名單。
9. **現有 `tool.json` 改名 `_tooldef.json`**（決定 14）：58 份，內容不動；讀它的程式、產生器、測試、README 一起改。選帶 `.json` 的那個名字（C-54 JSON 檔帶 `.json`，也最不容易漏改）。
10. **aos-mcp 包在 aos-tools 上**（決定 6、7）：`aos-mcp [--ws WS] [--stack DIR] [--timeout-s N] AGENT_DIR...`，讀每個 `AGENT_DIR/tools.json`（`aos-tools ls --json`），叫＝`aos-tools call`；**介面改了**（以前給工具資料夾）。註冊檔變了（決定 13「隨意」）：**每次 `tools/list`、`tools/call` 都重讀**，開著的 claude 下次列清單就看得到；不主動送 listChanged 通知。
11. 對照「對不上」第 1～3 點（工具一律資料夾、放在自己那格零個 `..`、10-24 不用清單檔）是使用者 10-28 的新方向直接取代，條文加註（[C-61](../../docs/CONCEPTS/05-agent.md)、[P-41](../../docs/CONVENTION/02-題目stack停錯腦.md)、[NORMS 待定](../../docs/NORMS/08-待定.md)）；舊規則留給沒經 `tools.json` 的叫法。第 4 點照決定 14 改了；第 6 點（新的命令列約定）是使用者定的。

實跑（WSL，試驗場 `~/code/try/aos-tools/`，不在 git）：一個 agent 資料夾 `aos-tools add` 三種各一個（lib/base/clock 資料夾、echo.json、add.py），agent-dan 複本接假的 OpenAI 相容腦叫到三個（答案 `tools=['add', 'clock', 'echo'] results=['…Z', '{"text": "hi"}', '42']`）；claude（haiku）經 aos-mcp 叫到三個（5 回合，$0.0026）。
