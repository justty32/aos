## 跟原則的對照（10-28，只列不裁定）

對照 CONCEPTS／NORMS／CONVENTION 與 10-24 工具＝函式庫的定案。

### 對得上的

- **C-52 只管自己這層**：agent 只看到工具清單（名字、說明、參數），註冊檔正好就是這份清單，工具裡面是什麼照舊不管。
- **C-48 私有 key、不認得的忽略**：JSON 裡多一個 `_tooldef` key，aos-exec 跟其他程式不認得就忽略，不壞既有格式。
- **C-72／`_metainfo` 的找法**：資料夾放 `_tooldef` 檔、JSON 放 `_tooldef` key，跟 `_entry`、`_metainfo`「資料夾一個檔、JSON 一個 key、同一套找法」是同一個樣子。
- **C-73／N-59 aos-exec 跑得動檔也跑得動資料夾**：登記對象可以是檔，aos-exec 本來就能直接跑 JSON 檔、可執行檔。
- **N-27／C-61 參數怎麼進由工具自己定**：`--tool-call` 是一種「工具自己定」的方式。
- **N-45 aos 讀的 JSON 都解指示詞**：如果「指示詞分開」是用 `$ref` 拆檔，註冊檔本來就該支援。
- **少用 sh**（[user/03](../../../wf/workflows/common/user/03-討論紀錄與規劃.md#少用-sh2026-10-15-定)）：python 或任何可執行檔直接登記，不用 `sh -c` 包。
- **報錯不猜**（決定 4）：跟 10-28 hub「`AOS_HUB` 沒設＝報錯」（[決定 10](../2026-10-28-hub-kernel.md#決定10-28)）同調。

### 對不上、要使用者看的

1. **「工具一律做成資料夾程式」**（C-61、P-25）：現在規定工具一定是資料夾；新構想讓單一個 JSON 檔、python 檔、可執行檔也能直接當工具。
2. **工具放哪：「放在叫它的那一格的 `tools/<名>/` 裡、永遠零個 `..`、不靠 PATH」**（C-61、N-50、P-25、P-33）：現在工具的位置就是呼叫鏈本身；新構想改成註冊檔記一個路徑，工具可以在任何地方，路徑可能有 `..` 或是絕對路徑。
3. **10-24 工具＝函式庫明白不用「`tools.json` 清單」**（[tool-lib](../2026-10-24-tool-lib.md)）：當時選「`tools/<名>` 一條相對捷徑指到庫」、刻意不用清單檔；新構想正是一份清單檔。
4. **工具說明檔叫 `tool.json`**（P-41：`tools/<名>/tool.json`＝給模型看的說明，沒有它的資料夾不算工具；10-24 一個工具＝`_entry`＋`tool.json`＋`_metainfo`）：新構想改叫 `_tooldef`／`_tooldef.json`，現有 lib 的工具、agent-dan、aos-mcp、aos-ai `make tool` 都認 `tool.json`——使用者已說「改吧」（決定 14），實作時一起改；P-41 與 10-24 的條文也要跟著改。
5. **一個名字兩種寫法**：資料夾裡 `_tooldef` 或 `_tooldef.json` 都行；但 `_entry`、`_metainfo` 都只有一個不帶副檔名的名字，命名規矩（C-54）又說 JSON 檔帶 `.json`——兩邊都有前例，兩個都認時同時存在要看哪個也沒定。
6. **`--tooldef`、`--tool-call` 是新的命令列約定**：規範裡沒有「帶某個旗標跑程式就吐出自己的說明／照這個任務做」這種東西；要先跑一次陌生程式才知道它是什麼（結果可快取，決定 10），跟現在「讀一個檔就知道」不同。
7. **註冊檔放每個 agent 資料夾 vs P-15「定義資料夾不被寫」**：定了每個 agent 資料夾一份（決定 8），所以 `aos-tools add` 會寫進定義資料夾——是設定時寫、不是執行中寫，P-15 管的是執行中，算不算違反要使用者看；`--tooldef` 的快取（決定 10）要是也放這裡，同一題。
8. **參數怎麼進：P-41 與 10-24 lib 契約是「`arguments` 從 stdin 進」**；可執行檔改走 `--tool-call XXX`（決定 12），兩套並存或改掉哪一套要看。C-42b「schema 怎麼轉成 argv 沒定」——XXX 要是內容字串，也會碰到這條。
9. **註冊檔存絕對路徑**（決定 9）：跟 P-33「地址零個 `..`、兩份定義一起搬也不斷」相反——絕對路徑在整個資料夾搬家、換機器（例 Windows 與 WSL）時會斷。

## 現行 aos-mcp 跟新方向的差異（之後要改的）

| 項目 | 現在（10-27） | 新方向（10-28） |
|---|---|---|
| 工具從哪來 | 命令列給一串資料夾，掃 `tool.json`（或 `tools/*/tool.json`） | 讀 aos-tools 的註冊檔 |
| 工具說明 | 資料夾裡的 `tool.json` | JSON 的 `_tooldef` key、可執行檔 `--tooldef`、資料夾的 `_tooldef`／`_tooldef.json` |
| 能登記什麼 | 只有資料夾 | 資料夾、JSON 檔、python／可執行檔 |
| 管理 | 沒有；改啟動參數 | `aos-tools add／rm／ls／get`，不符合就報錯 |
| aos agent | agent-dan 讀 `tools/*/tool.json` | 直接吃自己資料夾裡的註冊檔 |
| 叫可執行檔 | `aos-exec` 跑、`arguments` 從 stdin 進 | 可執行檔支援 `--tool-call XXX` |
| 撞名 | 資料夾名就是工具名，不會撞 | 報錯，`--override` 蓋掉 |
