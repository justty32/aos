## 前提（使用者 10-15 深夜追加的兩條，本稿每一條都要過這兩關）

1. **KISS 納進最高原則**——徹底的純淨簡潔。（另一個 agent 正在把它寫進 principles 稿與 NORMS，本稿不碰那些檔。）
2. **層要徹底切割**：「agent他就是看到自己的工具，工具在幹嘛他就不管，拜託，乾淨，完全切割，徹底切割，不得有任何殘留。」「想要看子層的東西請另外透過其他機制，沒機制就別碰。」所以 agent lib **不能知道某個工具是 agent**；工具就是一張 inst，裡面怎麼叫 bob 是工具自己的事（第二版 E「tool 步驟認資料夾、開 work/、寫 frame.json」違反這條，作廢）。

這兩條對本稿的意思：aos-exec 不知道 agent（只組 inst）；aos-inst 不知道 aos-exec（只讀 stdin）；agent 的格只看自己的 stdin 與 cwd；工具是一張黑箱 inst。下面每處有「殘留」的都標出來並拿掉。

## 已定（使用者拍板，第二版照抄，不重開）

1. `$ref` 的相對檔名從**那個指示詞所在的檔**的資料夾算（`dirname(abspath(檔))`，**不解 symlink**）；stdin 那份＝當成 cwd 裡放了一份 inst.json，基準＝cwd；Python 傳 dict 基準＝呼叫者 cwd；取回來的東西裡再有 `$ref`，從被取的那份檔算。
2. inst 的 `cwd`、`stdin`／`stdout`／`stderr`／`exit` 一律從 aos-inst 自己的 cwd 算；`cwd` 只決定子程式在哪跑。沒寫 `cwd`＝子程式在呼叫者站的地方跑。
3. **aos-inst 拿掉 TARGET，設定只從 stdin 來**（N-12 標準用法；命令列空出來）。
4. **`aos-exec TARGET` 是語法糖**，給人用。
5. **TARGET 全拿掉**：命令列的（inst／loop／daemon／fsm／gate）與 JSON 裡寫的 TARGET 字串（daemon `children`、閘門 `target`、kernel 的 gates／judges、fsm 的格、tasks 的 argv）。替代＝**內嵌 inst 物件**（同像性，`(daemon (fsm b c))`）；要拆成小檔就 `$ref`，那是拆檔便利、不是機制。
6. 刪 aos_tree；`$abs_path` 不做；呼叫機制不靠指示詞、不靠環境變數。

## 從規範推出來的 aos-exec（結論）

三條規範把它的形狀定死了：

- **N-12**：可呼叫的程式 stdin＝參數。所以 aos-inst 只讀 stdin、命令列零引數。
- **N-21～N-24、N-35**：TARGET、`檔#/位置`、資料夾找 inst.json、鏡射旗標、`--`——全是「人手打」的方便（N-22 自己說「不是硬規則」）。這些便利**只有人用的那一層才有**，整包搬進 aos-exec。
- **C-52 每層只管自己**：aos-exec 是 inst 這一層的語法糖，它**不知道 agent、frame、loop 是什麼**，也**不寫任何檔**。它唯一做的事：把「檔（或資料夾）＋旗標＋argv」組成**一張 inst**，灌給 aos-inst。

```
aos-exec TARGET [--key 值 ...] [-- argv...]
```

等價於這條 shell（差別只在三點：資料夾找 inst.json、`#/位置`、`$ref` 從檔所在算）：

```
aos-exec x.json --timeout-ms 3000 -- sh -c 'ls'   ≈   cat x.json | aos-inst   （再蓋上旗標與 argv）
```

**aos-exec 的全部步驟**：

1. TARGET 切 `檔#/位置`（N-35 的切法不變）。檔是資料夾＝找 `<資料夾>/$AOS_DIRNAME/inst.json`，沒有再找 `<資料夾>/inst.json`（規矩從 N-35「TARGET」名下搬到 aos-exec 名下）。
2. 讀那份 JSON，解指示詞——基準＝那份檔所在的資料夾（已定 1），`#/位置` 指到的那格仍是整份檔的視窗（`../` 摸得到旁邊，現況不變）。
3. 旗標蓋 key（N-22 鏡射，N-23 旗標＞檔）、`--` 蓋 `argv`（N-24）。
4. 得到的那張 inst 交給 aos-inst 跑；結果（N-30）與錯誤（N-29）原樣就是 aos-exec 的 stdout／stderr、退出碼照 N-43（aos-exec 自己只多三種錯：`ArgumentsBad`、`InstMissing`、指示詞的錯）。

**不做的**：不 cd（`cwd` 沒寫就在使用者站的地方跑，已定 2、3）、不寫檔、不讀自己的 stdin 當設定（設定在命令列上；自己的 stdin 留給子程式，見未決 B）、不認得 agent。

## 分層（這次的核心判斷）

```
aos-inst   跑一張 inst；設定只從 stdin。                      ←規範（N-12）
aos-exec   人用的糖：檔／資料夾＋旗標＋argv → 一張 inst → aos-inst。   ←語法糖（C-45）
agent      定義資料夾怎麼在別的 cwd 跑起來，是 agent 自己（lib、慣例）的事。  ←實作慣例，不是規範
工具       一張 inst，黑箱；agent 只看它的 _tool 說明、只給它 args.json、只拿它的 stdout。  ←前提 2
```

第二版把第三層的事（寫 frame.json、args.json）塞進第二層，所以醜。**bob 那條要在 agent 這層解**，而且在這套規則下只剩一條路：

**定義隨 inst 走（程式＝資料）**。aos-exec 讀 bob/inst.json 時 `$ref` 全部照 bob/ 解開，所以交到 aos-inst 手上的那張 inst 已經**自帶整份定義**（loop 表、fsm 表、每格的腦與工具），跑在哪都一樣。這正是 C-48 說的「自己的檔案可以透過指示詞拆成小檔」——機制是「內嵌」，`$ref` 只是把它拆回資料夾；整份寫成一個 inst.json 也成立，零指示詞。需要的只有一件事：**inst 的 `stdin` 可以寫內嵌 JSON**（未決 D）。

```
cd /home/a/workspace
echo '{"question": "幾點？"}' > args.json     # 引數＝frame 裡的 args.json（C-46 原本就這樣）
aos-exec ../agents/bob                         # 一行；不碰環境變數、不寫 frame.json
cat ret.json
```

bob 長這樣（跟今天的定義資料夾幾乎一樣，差在三個 `$ref` 與格的 stdin）：

```jsonc
// bob/inst.json
{"argv": ["aos", "loop"], "stdin": {"$ref": "loop.json"}}
// bob/loop.json
{"inst": {"argv": ["aos", "fsm"], "stdin": {"$ref": "fsm.json"}}, "times": 20, "stop_on_end": true,
 "ctl": "loop/ctl.json", "state": "loop/state.json"}
// bob/fsm.json（格只收內嵌，已定 5；拆檔用 $ref）
{"start": "intake", "state": "fsm/state.json", "end": ["done", "halted"], "states": {
   "intake": {"val": {"$ref": "cells/intake.json"}, "next": "thinking"},
   "thinking": {"val": {"$ref": "cells/think.json"}, "next": "route"}, …}}
// bob/cells/think.json（格要什麼寫自己的 stdin，N-37；$ref 從 cells/ 算）
{"argv": ["aos", "agent", "think"], "timeout_ms": 200000,
 "stdin": {"brain": {"$ref": "../brain.json"}, "system": {"$ref": "../system.json"},
           "tools": {"clock": {"$ref": "../tools/clock.json"}}}}
```

- 跑起來：aos-inst 在 workspace 起 `aos loop`，loop 設定從它的 stdin 來（aos-inst 把內嵌的 JSON 落成 `.` 開頭暫存檔餵進去）；loop 每拍起 `aos fsm`、fsm 起每格——全部在 workspace，窗（`loop/`、`fsm/`）、`history.json`、`work/`、`ret.json` 都落在 workspace。同一個 bob、兩個 workspace 同時叫互不相干。
- **frame.json 與 `parent` 鏈退場**：它存在的唯一理由是「在別的 cwd 找回定義」，定義隨 inst 走之後沒事可做。frame 就只是 cwd（C-46 的 stack 比喻不變：引數 `args.json`、回傳 `ret.json`、綁定＝放同名檔，都還在）。`aos agent fsm`（照 frame 找 fsm.json 的包裝）跟著退場，直接 `aos fsm` 從 stdin 讀表。
- **綁定**：C-46 說 bob/ 裡的腦與工具「只是預設值」，所以格找東西的順序＝**cwd 的檔 ＞ stdin 那份定義**（今天是 stdin 優先，要翻過來，未決 F）。要換腦＝在 workspace 放 `brain.json`；追加工具＝`tools/x.json`。
- **工具叫 agent**（painter 叫 brush）：照前提 2，painter 的 tool 格對**每一張**工具 inst 都做同一件事——開 `work/<n>/`、把模型給的 arguments 落成那裡的 `args.json`、在那裡跑它、拿 stdout 當結果（N-27，今天就這樣）；它不知道也不問這張工具裡面是不是另一個 agent。brush 怎麼被叫，全寫在工具那張 inst 裡，用同一招（定義隨 inst 走）解今天唯一卡住的「定義在哪」：

```jsonc
// painter/tools/brush.json（$ref 從 painter/tools/ 算；brush 自己的 $ref 再從 brush/ 算，已定 1）
{"argv": ["sh", "-c", "aos loop >/dev/null; cat ret.json"],
 "stdin": {"$ref": "../../brush/loop.json"}, "timeout_ms": 500000,
 "_tool": {"description": "叫畫筆備顏料", "parameters": {…}}}
```

  `sh -c` 的 stdin 就是那張 inst 的 `stdin`（內嵌的 brush loop 設定），`aos loop` 接過去跑，`cat ret.json` 就是工具結果。零絕對路徑、零環境變數、零 frame.json；`aos-demo` 的 `AOS_DEMO` 那一半退場（`.py` 轉指令名那一半照留，C-50）。

## 未決（附推薦；每條一個推薦＋一句為什麼不選另一個）

- **A. TARGET 可以省略嗎**（`aos-exec --timeout-ms 3 -- ls`）→ **推薦可以**，省略＝從 `{}` 起（今天 aos-inst 的手感搬過來）。不選「必填」：試東西少了一行寫法，而且判斷零成本（TARGET 不會以 `-` 開頭）。
- **B. aos-exec 另起 aos-inst 行程，還是同行程 `aos_inst.run(dict)`** → **推薦同行程**（fsm 跑格也是這樣）。好處：aos-exec 自己的 stdin 沒被設定用掉，inst 寫 `stdin_inherit` 就能接到終端機或管線（`echo hi | aos-exec x.json -- cat`），N-26 的 Conflict 只在設定真的從 stdin 來時才發生。不選另起行程：多一個行程、`stdin_inherit` 死掉，什麼都沒換到。
- **C. 結果的 `id`** → **推薦 aos-exec 代填**：inst 沒寫 `id`、也沒給 `--id` 時填 `abspath#/位置`（同今天 TARGET 的 id 形狀，realpath 改 abspath，跟已定 1「捷徑＝一份懶得 copy 的副本」同一把尺；N-30、N-35 改字）。這只是替人打一個 `--id`，不是寫檔。不選「不填」：人跑 `aos-exec x.json` 結果裡 id 是 null，退步。
- **D. inst 的 `stdin` 收內嵌 JSON** → **推薦做，這版的必要件**：字串＝檔路徑（從 aos-inst 的 cwd 算，已定 2）；物件＝一份 JSON；陣列＝多份（串流當省略外層 `[]` 的陣列，N-12；要傳一份陣列就 `[[…]]`）。aos-inst 落成 `.` 開頭暫存檔餵子程式、跑完刪；跟 `stdin_inherit` 同時寫＝Conflict。這是 C-48 值的雙形，不是新格式。不選「不做」：定義就沒辦法隨 inst 走，bob 那行回到要寫 frame.json。
- **E. frame.json／`parent` 鏈退場** → **推薦退場**（C-46 的「找名字往上找」那句拿掉，frame＝cwd）；`aos_frame.py` 的 `chain()` 退場，`lookup()` 只剩「cwd 的檔 → stdin 那份」。不選「留著、人自己寫 frame.json」：兩套機制做同一件事（stdin 自帶定義 vs parent 找定義），而且 `cd workspace && aos-exec ../agents/bob` 變兩行，正是使用者不要的。
- **F. 格找東西的順序** → **推薦 cwd 的檔 ＞ stdin 那份定義**（定義＝預設值，frame 放檔＝綁定蓋過，照 C-46 原意）。不選「stdin 優先」（現況）：那樣放 `brain.json` 到 workspace 換不了腦。
- **G. agent 當工具的寫法** → **推薦 `sh -c 'aos loop >/dev/null; cat ret.json'` ＋ `stdin: {"$ref": "…/loop.json"}`**（上面那張）；不另寫 `aos agent call` 之類的程式（意見 3「不要用程式去實作」）。不選「tool 格認資料夾、自己去開」（第二版 E）：lib 就知道了工具裡面是 agent，違反前提 2。
- **H. JSON 裡 TARGET 字串的替代**（已定 5 的落法，各一行）→ daemon `children` 每項內嵌 loop 設定、**`id` 必填**（缺＝`IdMissing`；不選「照位置編號」：表一改號碼就跑掉）；閘門 `target` 只收內嵌 inst；kernel 設定的 gates／judges 內嵌（判官＝一張 inst，它的 loop 設定用 `$ref` 拆）；fsm 的格純值形＝內嵌 inst、展開形＝`{"val": <inst>, "next"}`，N-36「格從表所在資料夾算」那句刪；tasks（seq／par／if／not）從 stdin 收：seq／par＝串流一份一張 inst 照順序、if＝一份 `{"cond", "then", "else"}`、not＝一張；loop 的 `inst` 已經是內嵌，不動。
- **I. 旗標與 `--` 只在 aos-exec** → **推薦**：aos-inst／loop／daemon／fsm／gate 命令列零引數（多給＝`ArgumentsBad`）；`-` 與「都沒給＝`{}`」退場。人要從檔起 loop／daemon／fsm：`aos loop < loop.json`（`$ref` 從 cwd 算，站在那個資料夾就對）；不站在那裡就包一張 inst 給 aos-exec（`{"argv": ["aos", "loop"], "stdin": {"$ref": "loop.json"}}`）。不選「loop 等也各留一個 exec」：四個糖做同一件事。
- **J. Python 的 `run(x)`（N-25）** → **推薦 `aos_inst.run(dict)` 只收 dict**（基準＝呼叫者 cwd）；路徑形改 `aos_exec.run(target, flags=None, argv=None)`。
- **K. 閘門的信把呼叫者 stdin 寫成旁檔 `reply/<名>.stdin`** → 有了 D 可以直接內嵌進信的 `stdin`，少一個旁檔；**推薦這輪不動**，等 kernel 那條線再收。
- **L. `_schema`、`_tool` 等私有 key 裡的路徑** → 只是資料，不進規範；要程式幫忙就 `{"$ref": "schema.json"}`。

## 第二版為什麼作廢（結論，兩句）

它把 agent 那層的事（寫 frame.json、把 stdin 落成 args.json）塞進 aos-exec，一支「執行」糖變成會寫檔、懂 C-46 的東西，違反 C-52 每層只管自己；命令列形狀也寫反（旗標在前）。重推之後 aos-exec 只剩「讀檔→組一張 inst→灌 aos-inst」，agent 的「定義在哪」靠定義隨 inst 走（程式＝資料）解，frame.json 不再需要。
