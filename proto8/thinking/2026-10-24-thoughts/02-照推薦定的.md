## 照推薦定的（使用者 10-24「都按建議做」，可翻案）

1. **fork＝再跑一次自己這個資料夾**：`aos-exec --ws <小格>/ws .`（cwd 是 agent 資料夾；`.` 不是 `..`，P-25 沒破）。小念頭就是同一隻 agent，所以它自己也能規劃、再 fork——使用者「fork出去的東西，又可以繼續steps」不用另寫東西。fork 不經 `tools/`，所以不受「工具放在 `tools/` 底下自己叫不到自己」限制。
2. **fork 給的是摘要，不是母體的 history**：小念頭的題目＝plan 時腦寫的 `context`（給小念頭的背景摘要）＋它 needs 的那幾步的結論＋自己的 `goal`＋一句「做完只回結論，不寫過程，N 字以內」。小念頭的 history 從空的開始（像 eve 的「每次新的」）。
   - **選項（沒做）：複製母體 history**（像 Claude Code 的 fork 繼承 context）：母體 history 有 H 字、拆 k 步、每個小念頭平均問腦 c 次，就多送約 k×c×H；母體是一段長對話時 H 可能上萬字。換到的是小念頭看得到前因後果、不靠腦寫的摘要。
3. **回來只帶結論**：結論＝小念頭最後的答案（它 `out/` 裡那段），超過 `THOUGHT_MAX_CHARS`（預設 1500 字）截斷、註明全文在哪。過程（工具來回、讀到的東西、它自己的子念頭）全留在小格，不進母體 history。
4. **結論怎麼進母體 history**：全部到齊後依規劃順序一次接，一步一則 `{"role": "user", "content": "小念頭 sN 的結論（目標：…）：\n…"}`。腦的規劃回覆本身不進 history（只記在 steps.json），所以母體 history 只有「題目＋各步與結論＋回答」。用 user 而不是 tool 訊息：tool 訊息前面要有 assistant 的 tool_calls，規劃不是工具呼叫。
5. **步之間的依賴：`needs` 表＋「齊了就起」**：每步列出要先拿到哪幾步的結論；fork 一邊跑一邊看，某步的 needs 都有結論了、而且同時跑的不到 `THOUGHT_PARALLEL`（預設 3）個，就起它，它的題目帶上那幾步的結論。plan 時就擋掉 needs 指錯、繞圈。
   - 選項（沒做）：(甲) 全部獨立、只並行，要接力就靠母體最後彙整；(乙) 全部依序，每步都帶前面所有的結論；(丙) 每跑完一批讓母體的腦重新規劃下一批。
6. **並行：fork 格自己起多個行程**（不經 aos-daemon）：小念頭跟 fork 同生同死，fork 格的 `timeout_ms`（1 小時）一到整個收掉。每個小念頭自成一個行程群組，fork 被收（SIGTERM／Ctrl-C）時先把它們整群收掉再走。選項（沒做）：交給 aos-daemon 管，fork 格只登記、下一次再來收結論（要多一套「還在跑」的狀態）。
7. **深度上限**：`THOUGHT_DEPTH`（fork 往下帶，母體 0）到了 `THOUGHT_MAX_DEPTH`（預設 2）就**不問腦、直接做**（省一次規劃）。
8. **整棵樹的額度**：`THOUGHT_MAX_TOTAL`（預設 10）＝一道題最多 fork 幾個小念頭（不含母體）。母體在 `$AOS_STACK/budgets/<plan_id>/` 開一份，`THOUGHT_BUDGET` 往下帶；plan 拿到規劃後拿鎖（flock）數一數，夠才佔（一步一個檔），**不夠就不拆、自己做**（不報錯）。剩不到 2 個時連問都不問。每道題一份額度、互不影響。
9. **一次規劃最多 `THOUGHT_MAX_STEPS`（預設 4）步**，跟剩下的額度取小的，寫在規劃提示裡；腦回的超過＝`PlanBad`。只拆一步＝當不拆（白 fork 一次）。
10. **錯**：規劃寫錯（steps 不是陣列、id、超過步數、needs 指錯或繞圈）＝`PlanBad` 照 P-20 停（steps.json 不寫，重跑再問一次腦，題目不重接）。**小念頭失敗回給母體的腦、不停**（使用者 10-24「都隨意」，代定可翻案，[tool-calls 文末](../2026-10-23-tool-calls/02-結論.md#10-24-定叫工具與小念頭的失敗回給腦)）：小念頭退非 0、逾時（`THOUGHT_TIMEOUT_S`，預設 900 秒，整群 SIGTERM、5 秒後 SIGKILL）、沒交答案，那一步的結論就是「小念頭 sN 失敗了（目標：…）：原因」，同一批其他的照樣跑完，全部依規劃順序接進 history；needs 它的步不起，結論寫「沒起：要先拿到 sN 的結論，但它失敗了」；stderr 留一行 `agent-gus: ThoughtFailed sN …（當結論回給腦）` 給人看；母體的 system.txt 多一句「失敗了的步能自己用工具補做就補做，做不到就照實說」。fork 自己被殺（步還是 running）時重跑，那幾步在原本的小格裡接著跑。翻案：fork.py 有失敗的步就 `die("ThoughtFailed", …)`。其他代號同 agent-dan；`StepBad` 是 thought.json 的 stdin 不對（thought.json 自己失敗是 `ThoughtFailed` 退 1，停不停由叫它的決定）。
   - **腦回的不是規劃＝當不拆、自己做**（10-24 真腦實測定，使用者「我開litellm了。其他都按照建議」，代定、可翻案）：解不出帶 `steps` 的 JSON 物件（直接回答了、說做不到、散文裡夾著 `{i: i …}`）＝當不拆（steps.json 的 `direct` 記 `"prose"`），think 帶 tools 再問一次，不是 `PlanBad`。規劃那次不送 tools，真模型的小念頭常回「沒有工具可用」的散文；在規劃提示裡列出工具名與說明擋不住。翻案：`plan.py` 的 `parse()` 在 `plan is None` 時 `die("PlanBad", …)`；代價是小念頭每個多一次腦（規劃那次白問）。
11. **token 看得到**：plan、think 問腦時，回覆的 `usage` 和送出的字數記一行在 `$AOS_STACK/usage.jsonl`。
12. **名字**（C-54）：`agent-gus`（demo 用人名，接 dan、eve、fay 之後）；格 `plan`、`fork`；`steps.json`、`thoughts/<id>/`（複數資料夾裝同類）、`plans/`、`budgets/`、`usage.jsonl`；環境變數 `THOUGHT_*`（主詞在前）；代號 `PlanBad`、`ThoughtFailed`、`StepBad`。
