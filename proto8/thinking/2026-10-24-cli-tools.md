## 實查兩個 CLI（10-24，`--help` 實查；Claude Code 2.1.310、codex-cli 0.163.0）

- **claude**：`-p` 非互動（題目可從 stdin 進，`--output-format json` 回 `{"result", "session_id", "is_error"}`）；`--session-id <uuid>` 指定新對話的 id、`--resume <id>` 接著某段對話（互動、非互動都行）；`--tools` 限制可用的內建工具、`--permission-mode dontAsk`（不問，沒預先允許的一律拒）、`--strict-mcp-config`（不給 MCP）、`--max-budget-usd`（只對 `-p`）；`--settings <json>` 可以帶 hooks。另有自家的 `--bg`／`claude attach <id>`（背景 session、附回終端），但 agent 沒辦法往裡面送字，沒採用。
- **codex**：`codex exec [PROMPT|-]` 非互動（`-` 從 stdin 讀；`--json` 印事件，第一個是 `{"type": "thread.started", "thread_id"}`；`-o 檔` 寫最後一則回答）；`codex exec resume <id> -` 接著某段對話（**resume 沒有 `-s`、`-C`**，沙盒改用 `-c sandbox_mode="read-only"`、工作資料夾用 cwd）；互動 `codex resume <id>`；`-c notify=[…]`＝每講完一輪叫一支程式、最後一個參數是 JSON（`type: agent-turn-complete`、`thread-id`、`last-assistant-message`）。另有 `codex queue --thread`（往現有 session 排一句話），沒採用。
- 系統有 `tmux` 3.7c，沒有 dtach、abduco、screen；`script` 有。

## 結論（照推薦定、可翻案）

### 1. 選的做法：兩條路並用——平常非互動續同一段對話；人接進去時開真的互動畫面（tmux），跳出後畫面留著、agent 改從畫面送字

| 情況 | agent 叫工具時怎麼做 |
|---|---|
| 畫面沒開（平常） | 非互動：claude `-p --resume <id>`（第一次 `--session-id <新 uuid>`）；codex `exec resume <id> -`（第一次 `exec -`、從 `thread.started` 拿 id）。回答從 JSON／`-o` 檔拿 |
| 畫面開著、沒人接著 | 從 pty 送字：`tmux paste-buffer -p`（bracketed paste，多行不會半路送出）＋Enter；回答**不解析畫面**，等 CLI 自己的 hook 在小格的 `turns.jsonl` 接一行（claude 用 `Stop` hook、codex 用 `notify`） |
| 有人接在畫面上、或 claude 正在跑一輪 | 不送，`SessionBad`（agent 停下，P-20；人跳出後再跑一次） |

同一段對話只有一個 id（`session.txt`），兩條路都接它，所以人在畫面上看得到 agent 之前問過的每一句，agent 之後也接得上人講過的話。

### 2. 接入／跳出

- 指令：agent 資料夾裡的 **`attach`**（`attach claude`、`attach codex`；`attach -d <名>` 只開不接；`attach` 不帶名字＝列出各工具的狀態與對話 id）。名字照 C-54：單一動詞、跟 `claude attach`、`tmux attach` 同字。
- 在**工作區**打（或 `--ws <工作區>`），不是在 agent 資料夾裡：畫面與對話屬於某一次跑的 stack（`$AOS_WS/.stack/<工具名>/`），同一個 agent 資料夾可以同時跑在好幾個工作區（N-55、C-65）。使用者原話「cd 到 agent-bob/」照這條改成 cd 到工作區、用 agent 資料夾裡的 `attach`。
- 畫面沒開就先開（有對話就 `--resume`／`resume` 接著那段），然後 `tmux -S <小格>/tty.sock attach`——**「接入某個檔」就是這個 socket 檔**。
- **跳出＝Ctrl-\\**（dtach 的習慣；tmux 不用 prefix，Ctrl-b 留給 Claude Code 自己用）；畫面底下狀態列寫著。在畫面裡 `/exit`（claude）或 `/quit`（codex）＝真的結束 CLI，畫面關掉，之後 agent 回到非互動那條路、接同一段對話。
- **只有人開畫面**（`attach`），agent 從不自己開：開畫面可能撞到信任資料夾、權限之類要人回答的提問，人在場才開。

### 3. 保守的權限（寫在各工具的 `cli.json`，要放寬就改那份）

- claude：`--tools Read,Glob,Grep`（只能讀；沒有 Bash、沒有開子 agent 的 Task，所以不會遞迴開 agent）、`--permission-mode dontAsk`（不跳權限提問，沒允許的直接拒，畫面不會卡在提問上）、`--strict-mcp-config`（不載任何 MCP server）、`--model sonnet`（省額度）；非互動另加 `--max-budget-usd 0.5`。互動畫面用同一組旗標——人接進去看到的也是唯讀的 Claude。
- codex：`-c sandbox_mode="read-only"`、`-c approval_policy="never"`（exec、resume、互動畫面都帶）；非 git 資料夾要 `--skip-git-repo-check`（程式自己加）。
- CLI 的工作資料夾＝`$AOS_WS`（工作區）。

### 4. 小格（工具自己的 stack，`$AOS_STACK/<工具名>/`）

`session.txt`（對話 id）、`tty.sock`（tmux socket）、`tmux.conf`（開畫面時寫）、`turns.jsonl`（hook 接的每一輪 `{"at", "text"}`，人在畫面上講的也進來）、`busy.txt`（claude 的 `UserPromptSubmit` hook 寫、`Stop` 刪）、`lock`（flock：agent 的一次呼叫、attach 開畫面互斥）、`last.txt`（codex `-o`）。

### 5. 錯（stderr 一行 `cli_session: 代號 原因`、退 1 → agent-fay 的 act 把那行回給腦，10-24 晚起）

`PromptBad`（stdin 不是 `{"prompt": 非空字串}`）、`CliMissing`（PATH 上沒有 claude／codex）、`CliFailed`（結束碼非 0、`is_error`、逾時、畫面在講完前關掉）、`ReplyMissing`（畫面開著、送出後等到 `timeout_ms` 還沒有 hook 回來）、`SessionBad`（有人接著、正在跑一輪、這段對話有人在用）、`CfgMissing`／`CfgBad`（`cli.json`）、`StackMissing`；attach 另有 `ToolUnknown`、`TmuxMissing`、`WsMissing`、`ArgumentsBad`、`FlagUnknown`。

### 6. 名字（C-54）

| 名字 | 一句白話 |
|---|---|
| `agent-fay` | 腦有 claude、codex 兩個 CLI 工具、人可以接進去的問答 agent（demo 的 agent 用人名，接 eve；本來叫 agent-eve，撞到同時在做的「agent 當工具」，改 fay） |
| `attach` | 接進某個 CLI 工具的互動畫面 |
| `cli_session.py` | 把 CLI 的一段對話接成工具（兩條路、hook、開畫面） |
| `tools/<名>/cli.json` | 這個工具怎麼叫 CLI：`kind`（claude／codex）、`flags`（兩條路都帶）、`print_flags`（只有非互動帶）、`timeout_ms` |
| `session.txt`、`tty.sock`、`turns.jsonl`、`busy.txt` | 見第 4 點 |

## 其他做法（沒選，留作選項）

- **甲、畫面一直開著，agent 只從畫面送字、解析畫面拿答案**：最像使用者說的「stdin/out 接到檔」，但 TUI 輸出是一堆跳脫碼與重畫，答案怎麼切、何時講完都靠猜；開機的信任提問、更新通知也會擋在前面。這次用 hook 拿答案、畫面只拿來送字，等於取了甲的好處。
- **乙、只用非互動，attach＝前景開 `claude --resume <id>`，退出才回到 agent**：最簡單、沒有 tmux；但「跳出後 CLI 在背景活著」做不到（人一退出程式就結束），人接著時 agent 也只能等。現在的做法在畫面沒開時就是乙。
- **丙、用 CLI 自家的背景機制**：claude `--bg`＋`claude attach`、codex 的 app-server 與 `codex queue`。兩家各一套、agent 那邊要分別對接；claude 那套沒有「往背景 session 送一句、拿回答」的指令。之後兩家若都有穩定的 API，可以改走這條。
- **丁、自己寫最小 pty 中繼（Python `pty`）取代 tmux**：不依賴 tmux，但跳出、重接、改視窗大小、多人看都要自己做；tmux 現成。

## 實跑（10-24，`~/code/try/cli-tools/`；LiteLLM 沒開，腦用假腦——題目原樣交給 claude 工具）

1. 整隻 agent，claude 非互動：題目「列出這個資料夾的檔案並回一句話。」→ act 6.8 秒 → 答「這個資料夾有 `README.txt`、`cur/q1.txt`，以及 `.stack/` 底下的 …」；trace `idle think act idle think act idle(10)`。
2. codex 非互動（直接叫工具）：同一題 → 8.5 秒 →「這個資料夾包含檔案 `README.txt`，以及子資料夾 `.stack/`、`cur/`、`done/`、`new/`、`out/`。」，`session.txt` 記下 thread id。
3. `attach -d claude`：Claude Code 開在 tmux 裡、`--resume` 接上第 1 步那段（畫面上看得到之前的問答）；agent 再叫一次「剛才你列了幾個檔案？只回一個數字。」→ 從畫面送字、`Stop` hook 回「6」，2.4 秒。
4. 模擬人（`attach_sim.py`：pty 裡跑 `attach claude`、打「只回一個字：好」、Enter、Ctrl-\\）：畫面回「好」、`turns.jsonl` 多一行、attach 結束碼 0、跳出後畫面還開著。
5. `attach -d codex`＋agent 叫「剛才那個資料夾有幾個子資料夾？只回一個數字。」→ 從畫面送字、`notify` 回「5」，3.1 秒。
6. 真 CLI 共花：claude 3 次、codex 2 次（測試寫壞時另誤叫真 claude 一次「hi」，已修：測試的 PATH 只留系統資料夾＋假 CLI）。

## 邊緣狀況（實跑撞到的，與想到的）

- **在 Claude Code 裡面跑 agent**：環境有 `CLAUDECODE` 等變數，巢狀的 claude 可能被擋或混到；實跑時用 `env.sh` 先拿掉。agent 平常不在 Claude Code 裡跑，程式不替你清。
- **開機時間**：codex 的「Resuming session…」會停 2 秒以上不動，太早貼字會被吃掉；開畫面後等「畫面連續 3 秒沒變、且不是停在 Resuming」才放行（原 1.5 秒不夠）。只有 attach 開畫面時才等；之後換版本畫面不同可能又不夠。
- **人打到一半就跳出**：輸入框裡留著半句，agent 貼上的字會接在後面一起送出。沒處理（要清輸入框得送 Ctrl-U 之類，各家按鍵不同）。
- **codex 沒有「開始跑一輪」的通知**：人在畫面上送出、還沒講完就跳出，agent 這時送字會插進去；claude 有 `busy.txt` 擋，codex 沒有。
- **人在畫面上講的話**也會進 `turns.jsonl`，但不會進 agent 的 history：agent 的腦不知道人跟 CLI 講過什麼（CLI 自己的對話記得）。
- **畫面開著時 hook 沒回**（卡在信任或權限提問、CLI 當掉）：等到 `timeout_ms`（10 分鐘）才 `ReplyMissing`；act 那格逾時 15 分鐘。
- **socket 路徑上限**：unix socket 路徑最長約 108 字元，stack 疊很多層（工具裡的 agent 裡的工具…）會超過，tmux 開不起來。
- **非互動第一次就失敗**：不記 id，下次用新 id 重來；claude 那邊可能留一段半截的對話。
- **人在畫面上 `/exit` 掉之後**：下次 agent 叫走非互動 `--resume`，同一段對話照接；人再 `attach` 會用 `--resume` 開新畫面。
- **Claude 提示 tmux 的 `focus-events`**：已在 `tmux.conf` 打開。codex 畫面右下有「3 warnings」，沒細看（不影響送字與 notify）。
- **花額度**：每次 agent 叫工具就是一次真的 CLI 呼叫；claude 非互動有 `--max-budget-usd 0.5`，互動畫面與 codex 沒有上限。
