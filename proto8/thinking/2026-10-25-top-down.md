## 乙隊：galtxt（galtxt-b）

### 使用者原文（10-25，逐字）

- 途中直接給乙隊的提示：「在進行的過程中，可以適當將一些經驗留存下來。」「因爲我們目前都還是依賴claude code來操控，來制作這套程式。以後我們也會用aos體系，制作用來制作這套程式的程式」「到時候就會需要這些經驗。」「可以先想想，假如想要弄成mcp，那該怎麼做」「這是支線任務」

### 結論

**範圍**：單一性格單一場景——宮澤柚葉（傲嬌）、梅雨傍晚河鹿堂、進新書日；題目只動「誰先開口」×「第二組必提詞」兩個開關。

**拆法**：根是 loop→fsm 一圈六格（idle／brief／draft／check／judge／deliver），是 galtxt「查表→寫→檢→評→交」的直譯；貴而不確定的節點（寫、評）各自獨立一塊，「寫」前面加一個可驗的程式節點（beat 表＋文法校驗），把大 LLM 步拆成「規劃→校驗→填句」。fsm 沒有條件轉移，用 stack 檔決定誰做事。刻意不拆：要人審的蒸餾表工廠、沒校準的 overgenerate-and-rank、翻 repo 外語料的工具。

**`_metainfo`**：只看表就指得出優化順序（錢在 writer、時間在 director）；宣告值是沒跑過時估的，要「跑一次就回填」。格式缺口：每次／每題要 `unit`、prompt 與 completion 分開、品質欄、量測方法、樣本數。壓平成一張表的收表程式只當除錯工具。

**反向收攏**：先問要不要檔案系統特性（可執行入口、捷徑、腦要叫的 `tools/<名>/`、權限、多寫者或單獨追蹤、>8 KB、自己的 stack、被 ≥2 處叫），撞到就不動；**收攏不急，只併真的空殼**。沒有葉片縮成 JSON（撞到的全是上述特性）。`tools/` 單工具中間層撞慣例 P-33，留給使用者。

**節點生命週期**：agent → script（查表、查不到才問腦）→ pure（只查表），前版留在節點內 `versions/`，呼叫方不變。確定性的提升主要來自固化成表；抽出的純程式工具（trim）的價值是「保證」不是「改善」，叫它的那趟來回才是成本——該固定走的步驟寫進程式，不留給腦決定。

**接不住的輸入（照 ML）**：降級照產（通用 default 表）＋難例寫自己的小格 → 下一輪拿節點自己的前一階版本（舊的腦版）當老師示範一次、校驗後蒸餾進表。換人物要短名對照表。

**梯度＝與 `_metainfo` 同形的 diff**：數值給 `delta`、非數值給 `from/to`、集合給 `added/removed`、文字進 `notes`；只算被動到的節點與往上一路。分攤：有貢獻按 |貢獻| 比例，沒有就分給這一步動到的工具；貢獻目前只有 ablation 量得出。**比較小改動要加樣本或改用確定性高的指標**（單次雜訊比多數改動大一個量級）。像反向傳播的是誤差沿樹往上記、往下分；不像的是沒有可微量，判斷輕重靠另一棵樹。

**三棵樹**：台詞樹被優化器改；優化器從 `_metainfo` 推候選；判斷器（critic 形的單發腦函數）只判二選一、判夠次數後權重固化成表、只在平手時問腦，自己的帳記在自己的 `_metainfo`。三者都走同一條 agent→表的固化路；錨只進分數與核對，不被任何樹改。

**自我優化**：一包可掛到任何節點的工具（讀自己、讀先前結果、白名單內改自己且寫前存 `versions/`、抽工具、由凍結的檢查與評分跑自測、記筆記、叫 claude code）。越界由程式擋（只寫自己資料夾、凍結節點與 `_metainfo`／測試／量尺一律拒、預算上限），不靠 prompt。自我優化看得到自己的細節、一步改到位；風險是改壞自己（拿掉安全步驟）與作弊（改測試、改量尺）。所以：**改動要外部重跑 ≥2 次、分數掉就自動退回**（未做）；拿掉保證型步驟前要先有 ablation 證據。工具包成熟前 claude code 當主力（使用者原話），台詞樹本身的腦仍是 gpt。

**結構化場景**：人物卡、地點卡、事件節拍、稱呼規則、禁詞拆成一格一事實，仍是 JSON、不長成資料夾（沒有任何一格要單獨權限、單獨被寫或單獨追蹤）；brief 照版面組回，給腦的稿紙逐字不變。粒度判準：拆到「程式會單獨查／改／歸因」為止；風格示範、一條 canon 內的子句不該拆。

**樹中有樹**：每個節點的 `_metainfo.rollup` 每輪由下往上算（子樹 token、最不固化的階、確定性、難例數、節點數）；捷徑子樹照抄目標的 rollup，重用時帶著走。生命週期往下走一階，資料夾就更「實」（腦殼→表→純函數）。

**錨與漂移**：有錨的是規則寫死的 lint 護欄、雜訊 σ、降級旗標；沒錨的是 critic 的語意維與判斷器權重（分數的大半）。漂移看得見、擋不住，真擋要人評或人手寫的正解。

**塔**：做到第二層（判斷器、優化器各有 `_metainfo` 與固化路）就停；第 N 層成本是下一層每步驗證的倍數、雜訊一路疊，第三層在現在的樣本量下量不出東西。

**代定（照推薦先做，使用者可翻）**：① apply 的改動只進訓練場、不自動畢業回 repo 樹；② 結構化場景的題目檔（凍結）仍是散文；③ lint 標 frozen 但加 `cell` 輸出欄（分數不變）；④ claude_code 不用 bwrap，靠限工具＋事後整樹比對還原；⑤ 「實測誰較好」：總分差 ≥0.5 高者勝，否則根 token 少 ≥5% 勝，否則平手。

**對 fable 的評估**：系統設計（切哪、什麼該凍結、往哪個方向固化、怎麼記帳）拆得好，每輪把跟原則衝突的點單列、不硬拍板；有序清單＋驗收＋預算的規劃最好用。估不到 agent 節點的**行為成本**（來回次數），數字預期要靠跑一次回填，仍是人／隊長要補的一環；規劃文件容易越寫越長。

## 甲隊：galtxt（galtxt-a）

原型 proto8/topdown/galtxt-a/；fable 規劃在 plan/，經驗在 lessons。使用者「跟甲隊說差不多可以收尾了，我抓到了一些問題點」後收尾。

### 使用者原文（10-25，逐字；頂部那段以外、直接給甲隊或甲隊依據的）

- 「差不多30%的時候就該換手了其實」「我人在外面，不方便評」

### 結論

**範圍**：一個角色×一個場景——宮澤柚葉（傲嬌）× 文化祭收攤的教室；舊題留著當回歸。

**拆法**：
```
galtxt-a/            根＝五格內嵌單子 brief→write→check→judge→pick（不要腦的都是單子）
├─ writer/           agent 節點；stage.json 記 agent→semi→program
├─ grader/           評審 agent；尺，不固化
├─ tools/lint/       純程式護欄，輸出 hits（指到格 id）
├─ data/             人寫的表，拆成有 id 的格
├─ train/            verify→train→rate→optimize 迴圈；weigh/（判斷器樹）、optimize/（優化器樹）
├─ optkit/           自我優化工具包（任何節點可掛；含叫 claude code 的工具）
├─ meta/             metatable、collapse、rollup
└─ human/ plan/ idle/
```
- 第一層切在「要不要腦」與資料形狀變化處：要腦的（寫手、評審）各是 agent 資料夾，其他全是根 fsm 的內嵌單子。
- 刻意不拆：pick／check／brief 不給資料夾；lint 不拆維度（一次掃完便宜）；評審不分成三個 agent（三倍 token）。
- 三棵樹：台詞樹被改（只改參數表、`stage.json`、模板）；優化器只讀根 rollup 挑一棵子樹；判斷器只讀兩份 diff＋人寫優先序表、不改任何東西。

**反向收攏**：併「一格一夾」的 glue 與重複的 idle、縮薄中間層。不縮的判準＝`fs_needs`（自己的 stack、tool json、隔離、要單檔 diff、別的行程寫）＋伴隨檔 ≥2＋共用真身；有旁檔（ratings／stage／grad／rollup）的子樹不縮。

**`_metainfo`**：只看表指得出**該優化什麼**，指不出**該優化多少**（要實測欄）；表最大的洞是資料流（`reads`／`writes`／狀態 key）。缺的 key：`measured`、prompt／completion 分開、`cache`、`timeout_ms` 與資源上限分開、`max_rounds`、`max_children`、`parallel_safe`／`max_parallel`、`entry_kind`、`callers`、`llm_model`、`role`、`derived`、`steps`、`opt_writes`、旁檔 `$ref`。metatable 只當人看的索引；決策讀**樹中有樹**的 rollup——每棵子樹的 `rollup.json` 只彙總直接子樹、一層層往上算，搬到別棵樹也帶著走。

**拆格**：id＝JSON key 路徑（`cast.yuzu.tic.03`），檔長成資料夾 id 不變（C-72）；給腦的散文只在 brief 最後一步從格渲染。停止條件：再拆一格要答得出「有程式只讀這格嗎／控制變量只動這格嗎／梯度或規則會單指這格嗎」，三個都否就不拆；真腦後仍 0 引用的格併回陣列。

**自我優化**：優化器不親自改節點，挑子樹（照 rollup）→ 寫一句「請優化 X」＋附先前結果 → 叫節點自己做（agent 節點多掛 `opt_*` 工具；純程式節點臨時配殼；或叫 claude code）→ `accept` 判 → 不收就回滾。工具包：describe、history、read／edit／write（白名單內）、extract、try、test、note（改 `_metainfo` 只寫建議，不直接改）。防作弊全靠程式：在整棵樹的拷貝裡改，`accept` 檢白名單、錨的 sha256、契約測試；背正解、讀絕對路徑擋不住、只能事後抓。分工（預測）：自優化改**內容**（抽工具、蒸餾模板、改 prompt）；外部優化器翻**開關**（stage、switch、hints）並當收貨人；連兩次被拒退回外部動作。
