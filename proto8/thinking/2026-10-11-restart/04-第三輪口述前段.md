## 3g. 使用者第三輪口述：實作上的想法（10-11 晚，照原意整理）

### 3g.1 最終要達到的效果

- 最終會有一個**很方便的、類似程式設計師在用的東西**——一些 library、一些庫。
- 用它寫出來的東西，**最終編譯成基於 aos 體系的一個類似 LISP 的程式**。
- 這個程式**把 aos 體系當作作業系統**，在上面跑東西。
- 這一塊**會很適合 agent**。

### 3g.2 inst 的實作

- 最基礎的早就做過了（原話「install 過了」，照上下文記為「實作過了」）。這邊只是自己再描述一遍：
- inst **吃一些 JSON，有固定的幾個 key**。
- 它會先**按照指示庫（指示集）把它組成一個 JSON**。照指示庫組的時候，**相對路徑會長怎麼樣**是個點：可以透過 **argv 選擇**找目錄是從 **cwd** 來、還是從執行處來——反正就這一塊，哪樣都可以。
- 吃 JSON key 的時候，**它吃它想要的；其他不認識的 key 沒關係**（忽略）。
- 指示庫：使用者本想說最終可以只留兩三個，後來說「算了算了，**都留都留**」。
- 解完之後它就跑。

### 3g.3 loop 與 daemon 的實作

- **loop**：不管它，它會**變成一個 library，整個進 daemon**。
- **daemon**：各種 **Linux 許可權有的沒的，全部都在它身上跑**。它也可以**吃一點控制**（接受一些控制輸入）。
- 這些早就想過了，其實都已經很完善；最終可能再調整一下，重新把控一下狀況——使用者會**去 survey 一下 code**。
- 使用者的判斷：除去一些必要的庫、必要的樣本程式碼（處理比較複雜的那塊、Linux 那塊的東西），**daemon 會是非常非常非常簡短的東西**。

### 3g.4 tick-tock 的實作（使用者講到一半說「這塊我掌握的不夠全」）

- tick-tock 其實早就定下來了，就長那個樣子。這裡只是重新複述：
- **丟給 daemon 跑的都是一個資料夾。** 跟 daemon 說「我要跑這個資料夾」。inst 本身可以跑 daemon、也可以跑資料夾；daemon 當然也能跑一些指定指令，**但那不在正式的使用範圍承諾內**。
- 跟 daemon 說要跑這個資料夾時，可以說：**只跑一次／跑好幾次／無限跑，每次跑間隔多少**——daemon 收這些指令。
- tick-tock 通常是這樣：丟一個資料夾給 daemon，說「這個資料夾的 inst 每五秒跑一次」。這個 inst 指向的是 **aos task（跑多工的那個指令）**；任務表中**最前面是 tick、最後面是 tock**——「不一定不一定，它可能就是兩個連在一起，都可以再想想」。tick-tock 連起來，中間任務跑一跑。
- 講到「其中有些任務它是……」時使用者停下：「**不對，我發現這塊我掌握的不夠全。**」→ 到此為止，不補。

### 3g.5 回頭講 tick-tock：可以跟 node 的狀態變化完全脫鉤；它是一個抬頭看的時鐘

- 使用者發現：現在做的 tick-tock 是跟 node 的狀態變化掛在一起的（原話「所打勾的」，照上下文記為「掛鉤」）。**其實 tick-tock 本身可以脫鉤，完全脫鉤。**
- 樣子：**一個 daemon 底下跑一個 tick-tock，loop 持續跑 tick-tock**。被 daemon 管理的其他 node，**有些會訂閱 tick-tock 的通知**，大家就知道現在第幾回合。**它就是一個可以抬頭看的時鐘，就這樣。**
- 要不要給 tick-tock 一個更好的定義：**保證在 tick-tock 之間（或 tick 之後到下個 tick 之間），可以安全地把資料夾壓縮、打包帶走**——時間之間的穩定狀況。
  - 比如 tick 就是起任務（原話「啟用人物」，照上下文記為「啟用任務」）、通知大家第幾回合開始；再通知大家這回合結束、「麻煩把狀態穩定儲存，因為這回合結束了」；之後下個回合會不會來也不知道。
- 這是很重要的特性，**但要不要做成標準配備，不一定**：搞不好是 kernel 的配備；搞不好也不是 kernel 的、也不在 tick-tock 裡——「隨便，反正就是**可選項、但很重要**的東西」。

### 3g.6 脫鉤之後：協議變簡單；kernel 的參照物是時間（tick-tock）與空間（資料夾）

- tick-tock 脫鉤之後「就解放了」：**協議不用那麼麻煩，拆開之後大家都變簡單**。訂閱搞不好也可以更簡單；tick-tock「隨便啊」，後續很容易寫出來，再說。
- tick-tock 和 task 都有了，接下來 kernel 這邊也差不多了。kernel 就是先前說的那個任務包。使用者「簡單隨便說一下」：
- **tick-tock 對 kernel 是一個重要參照物。** 現有 Linux kernel 以**時間、空間、消耗資源**（原話「小號資源」，照上下文記）作為重要的規劃目標；aos 體系裡**時間和空間被 tick-tock 和資料夾壟斷了**，所以 kernel 的參照物就是這兩個。例子：
  - 「我希望你**三回合之內**搞定這一切，不然我就換個人做。」（時間）
  - 「我希望你**只動這三個資料夾**」「只用這幾個檔案」「每個檔案不得超過幾 KB」。（空間）
  - 就這麼簡單——**kernel 只是一個排程**（語音原話「最技術的排程」，使用者校正為「只是一個排程」）。
- 排程這一塊：早前一直卡在「PU 這塊如何實作任務請求、如何處理」。使用者：**這就各資料夾各家各做各的，那只是一個概念，你想怎麼做都可以。** 例子：
  - 跟大家說「你把檔案寫在這邊」——有許可權的就是有許可權，沒許可權的再說。
  - 搞不好再多寫一個檔案說「你的優先多高」。
  - 搞不好另一個人說「你寫下來，OK，我再處理一下」。
  - 「都可以都可以。」
