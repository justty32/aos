## A. 兩塊比較：aos agent vs 外部 coding agent

把「射後有理」拆成七件事，兩邊各自現在是怎麼做（或做不到）的對照。「外部 agent」拿 claude code 當代表（codex 同形、pi 的 rpc 模式更順，見 hub-adapter 適配表）。

| 事 | aos agent（已做，P-42） | 外部 coding agent（黑盒子） | 共同點 → 通用介面怎麼對上 |
|---|---|---|---|
| **跑起來** | `aos-exec --ws WS <定義>`；`_entry` 是 aos-loop、每次叫 round | `claude -p`（一答就退）或互動式 `claude`（停著）；都是別人的程式、旗標在它那邊 | 都是「一個資料夾程式跑在一個工作區」。外部 agent 要能 `aos-exec`，就得有一個**定義資料夾**包著它（下面 B） |
| **輸入（塞 prompt）** | `$AOS_STACK/queue/`（N-16 有序投遞），agent 自己的 queue 格認領、接進 history | 非互動：只有啟動那一句（stdin／argv）；要「再說一句」只能再跑一次 `claude -p --resume <id>`。互動式：往畫面打字（tmux paste）。跑到一半不能插（pi rpc 的 `steer` 例外） | 兩邊都是「一則一則、有先後的訊息」。差別只在**誰去 queue 拿**：aos agent 自己拿；外部 agent 不會看資料夾，要**有人替它拿**——那個人就是 adapter（下面叫 `turn` 格）。aos-say 不用改：一律寄進 `<stack>/queue/` |
| **回答（看 reply）** | `$AOS_STACK/history.jsonl` 最新那則 assistant | 非互動：stdout（stream-json）；互動：畫面，另有 `Stop` hook 給最後一句；完整對話在它自己的 session 檔 `~/.claude/projects/<cwd 編碼>/<id>.jsonl` | 兩邊都有「只附加的對話紀錄」。aos 這邊**一律看 history**：外部 agent 的回答由 adapter 抄一則進 history（user 那則認領時抄、assistant 那則答完抄）；它自己的 session 檔用 symlink 掛在小格（決定 35、agent-lifecycle C-15～17）。aos-listen 不用改 |
| **一輪的邊界** | round：認領一則 → 問腦 → 跑工具 → 交卷；格與格之間有 trace | 一輪＝「一句進去、到它不再叫工具、吐出最後一句」（使用者 10-27 筆記）；中間它自己跑工具，外面看不到格 | 兩邊都有「一輪」。aos agent 的一輪拆得開（格），外部 agent 的一輪是一整塊——這是決定 12 說的差別，也是「暫停」粒度不同的根 |
| **停著等** | aos-loop 提供：`ROUND_ON_EMPTY=idle`＋`interval_ms`，queue 空就退 0 等下一次 | `claude -p` 自己不會等（退了）；互動式 `claude` 會等，但等的是鍵盤、不是 queue | 「停著等 queue」兩邊都**不是腦本身的事**：aos agent 交給 aos-loop；外部 agent 的 adapter 也交給 aos-loop（一次＝替它答一則），不自己寫循環（agent-bob 的教訓、agent-lifecycle 衝突 6） |
| **暫停／停** | 寫 `$AOS_STACK/ctl.json` 的 `paused`／`stopped`（N-07），停在輪與輪之間；fsm agent 還能停在格與格之間 | 沒有暫停這回事；只能不給它下一句（互動式畫面開著也一樣）。「停」＝殺行程、關畫面；對話靠 `--resume` 接回 | **`paused` 對外部 agent＝不餵下一則**（新信留在 `queue/new/`、手上那則答完）；**`stopped`＝這則答完 loop 收工**，畫面另外用 hub 的 `close`／`stop` 管。粒度只到「一則訊息」，停不進它的工具呼叫中間——這是黑盒子的天然差異，不補 |
| **誰在管生命週期** | 直接 aos-exec＝Linux 管；掛 daemon＝`loops`／`execs`（N-28 10-30 補） | 同左（決定 34）；多出來的只有**畫面**（tmux、Ctrl-]、信任提問）和**它自己的 session 檔** | 生命週期兩邊**同一套**（aos-exec、aos-daemon、aos-daemon-ctl）。外部 agent 多的那兩樣（畫面、session 檔）就是 aos-eca-hub 要做的全部（下面 C） |

**一句話結論**：兩塊的共同點是「有序的訊息進、只附加的紀錄出、一輪一輪、輪與輪之間才停得下來」——這正好就是 P-42 的三樣（queue、history、ctl／state）。差別只有一個：aos agent 自己去 queue 拿、自己寫 history；外部 agent 不會，**要一個 adapter 替它做，而這個 adapter 跑在 aos-loop 底下就跟一隻 aos agent 一模一樣**。所以通用介面不用新發明：aos-say／listen 照 P-42 一行不改；外部 agent 的 queue 由 adapter 收、history 由 adapter 寫、`paused` 由包著 adapter 的 aos-loop 認。

## 各題結論（每條標照哪條原則／決定）

### B. 外部 agent 跟 aos agent 平級，怎麼落到佈局

1. **一隻外部 coding agent 的「定義」＝一個資料夾程式，形狀跟 aos agent 範本一樣**（map-review 第 3 點平級；C-68 資料夾＝程式；N-53 入口帶 loop；P-15 定義不被寫）。`demo/eca-claude/`（範本名照 `aos-<領域>-<功能>` 的精神用 `eca-<CLI 名>`）：
   - `_entry`＝`["aos-loop", "loop.json"]`（跟 agent-nia 同一行）。
   - `loop.json`＝`{"exec": {"argv": ["aos-parts", "run", "turn", {"$env": "AOS_CD"}], "timeout_ms": 900000}, "interval_ms": 300, "ctl": "ctl.json", "state": "state.json"}`——停著等版；射後不理版加 `"max": N` 或讓 `turn` 空了退 10。
   - `parts.json`＝`{"parts": {"turn": {"path": "../../lib/eca/turn", "env": {"ECA_ON_EMPTY": "idle"}}}}`——只有一格，叫 **turn**（外部 agent 的「一輪」；cli_session 本來就叫它 turn，`turns.jsonl`）。沒有 think／act／endpoint：**腦不是 claude，整隻 agent 才是 claude**（第 3 點「不是腦」）。
   - `cli.json`＝現有工具資料夾那份（`kind: claude|codex`、`flags`、`print_flags`、`timeout_ms`；[cli-tools 結論 3、6](2026-10-24-cli-tools.md)），放在定義頂層，turn 讀它。**不另造 `agent.json`**：`kind` 已經在 `cli.json` 裡（C-56 不多造格式）。
   - 選填 `prompt.txt`＝開場白（射後不理那種：history 空、queue 也空時，turn 把它當第一則 user 投進 queue 再答——agent-bob-1 的作法搬過來；playground-queue 結論 1「初始 prompt 寫在定義裡」）。
   - **實例＝定義 × 工作區**，跟 aos agent 一樣（P-15、C-65）：`aos-exec --ws ~/code/myproj demo/eca-claude`；工作區＝claude 的 cwd（使用者的程式專案）；stack 預設 `~/code/myproj/.stack/`，裡面長 `queue/`、`history.jsonl`、`ctl.json`、`state.json`、`trace.jsonl` 與 cli_session 的小格 `claude/`（`session.txt`、`tty.sock`、`transcripts/`…）。10-28 使用者「放Stack比較好」照舊成立，而且**不再是 hub 的特例**，就是 P-42。
2. **turn 格（`lib/eca/turn/`，Python）做的事**，照 queue 格與 round 的順序，只是「問腦」換成「叫 CLI」：① `cur/` 有沒答完的先接，否則 `aos-post claim` 一封（Q-1 的順序：先 claim、接進 history、寫 `current.txt`）；② `body` 不是 `{"role": "user", …}`＝壞信，`aos-post finish` 丟掉、trace 記一行（衝突 5、Q-4）；③ `content` 交給 cli_session（畫面開著＝貼進 pty 等 `Stop` hook；沒開＝`claude -p --resume <id>`，第一次 `--session-id <新 uuid>`——兩條路照 10-24，一行不改）；④ 回答接成一則 assistant 進 history、才 `aos-post finish`；⑤ queue 空：`ECA_ON_EMPTY=stop`＝退 10（loop 收工＝射後不理）、`idle`＝退 0（loop 隔 `interval_ms` 再來＝射後有理）；⑥ 每則在 `trace.jsonl` 寫一行 `{"unit": "turn", "question": 信號, "code", "elapsed_ms", "error"?}`，aos-listen 的 Q-13 判法照舊看得懂；⑦ 拿到 session id 那刻在小格建 `transcripts/<kind>-<id>.jsonl` → CLI 自己對話檔的 symlink（C-15～17，`wip/hub-step6` 裡 cli_session 那段可以直接收）。**人在畫面上自己打的話不進 history**（它沒經 queue；決定 26 紀錄 aos 不管；完整對話在 transcripts）；`SessionBad`（有人接在畫面上）＝這次退 0 不動、信留 `cur/`，下一次再試（hub 現行 5 秒再試的意思，改由 `interval_ms` 給）。
3. **`aos-exec <外部定義>` 要能跑**——能，而且這就是射後有理的開法（上面 1）。父子交代那層（C-75 第三種）跟 aos agent 一樣：argv、環境變數進，結束碼出。
4. **掛 daemon 用同一支 aos-daemon-ctl**（第 6 點已定）：`aos-daemon-ctl add --ws ~/code/myproj --name myproj demo/eca-claude`——有 `loop.json`、認成 loop 子項（D-12），daemon 的子 loop 直接跑 turn，**只有一層 loop**（不是 `max: 1` 那種包兩層）。這裡要補一個現在沒有的東西：**子項的工作區**（`--ws` → 子項設定的 `ws` key → daemon 起子項時設 `AOS_WS`），不然掛上去的任何 agent（aos 的也一樣）都只能繼承 daemon 的 `AOS_WS`。原則上這是 N-55「工作區由呼叫方設 `AOS_WS`」的直接要求（daemon 是呼叫方），但要動 N-28、N-54 與 D-2「其他 key 忽略」→ [衝突 1](#衝突跟既有原則實作對不上的寫給使用者看)。掛上去之後 stack＝daemon 的小格 `$AOS_DAEMON/myproj/`，不是 `myproj/.stack/`——這是 C-67「stack 放哪由呼叫方自由決定」，但 10-27 筆記「cd 過去打指令就接上」就得有辦法找到它 → [衝突 3](#衝突跟既有原則實作對不上的寫給使用者看)。
5. **「claude／codex 當 tool」（agent-fay）跟「當平級 agent」：同一份程式、兩種叫法，不是兩套**（C-52：工具裡是不是另一個 agent，呼叫的格不知道；10-24 agent-as-tool：agent 可以當工具）。
   - **當平級**＝整個定義 `aos-exec`（`_entry` → aos-loop → turn），停著等、有 queue／history／ctl。
   - **當工具**＝只叫一次 turn 的「問一句」形：`lib/agent/claude`、`codex` 現在就是這個（stdin `{"prompt"}` → stdout 回答，P-41 工具契約），接下來改成薄薄一層叫 `lib/eca/turn --one`（或 turn 提供 `call_main`），cli_session 共用。差別只在**對話記在哪**：工具形的對話在呼叫它那格的小格（`$AOS_STACK/<工具名>/session.txt`），平級形的在定義自己的 stack；兩種都留 transcripts symlink（方向題 3 已定）。
   - 所以 agent-fay 不改、`attach` 不改；`aos-eca-hub open` 跟 `attach` 做的是同一件事（開小格的畫面），實作共用 cli_session，見 C。
6. **外部 agent 的 queue 誰收、history 誰寫、paused 是什麼**（A 表的三個問號，收成一句）：**queue 由 turn 收、history 由 turn 寫、paused 由包著 turn 的 aos-loop 認（＝不餵下一則）**。aos-say／listen／chat、`lib/aos/aos_ws.py`、ask_round 全部一行不改。

### C. aos-eca-hub：daemon ＋ 什麼

7. **aos-eca-hub＝aos-daemon（通用層，使用者定）＋三件 daemon 做不到、只有外部 CLI 才需要的事**：① **畫面**（tmux 開／接／關、Ctrl-] 只跳出、信任提問要人回答）；② **對話接回**（`--resume`／`exec resume`、session id 在小格 `session.txt`）；③ **它自己的 session 檔**（transcripts symlink、stop 時換複製）。其他 10-27 筆記裡的事都歸 daemon：「記哪個資料夾有實例在跑」＝`loops_state.json`；「給使用者查詢」＝`aos-daemon-ctl ls`；「閒太久就關掉」＝`close --idle`（照舊用 aos-loop 跑 `reap.json`）；「限制同時數量」＝使用者 10-28「實作時再說」，仍不做。

## 實作時代定（10-30，隊長與工人照原則定的細節，可翻案）
