## 已知限制

- **挑錯意圖、漏掉關鍵上下文**：字面比對對同義詞無力（「房間號碼」對「房號」、「小動物」對「貓」）；目錄每行截字，關鍵資訊在句尾就看不到。沒有 recall 就答錯；有 recall 也要腦「知道自己不知道」。
- **摘要失真**：結論只是回答原文，回答沒寫的就不在主線；結論本身寫錯，之後每次被展開都在傳播錯誤。
- **指代**：「前天說的那個」「你一開始講的」這種跨很遠、又沒字面線索的，只剩目錄與 recall。「它」「這個」很常見，常常白白多展開一題。「第 N 題」的 N 是整個 stack 從頭數，換 stack 就重編。
- **成本可能反而變高**：短對話（固定開銷，靠 `KAI_FULL_UNDER` 擋）；要用舊過程細節的題（要 recall／重讀）；**供應商的 prompt cache**——kai 每次組的前綴不同，幾乎吃不到快取，dan 只在尾巴加、命中率高。
- **目錄自己也會長**：一題一行，50 題約 3K token；題目很多時目錄本身就是新的「太長」。
- **題沒答完就失敗**：照 dan，題目留在 `cur/`；重跑時「這題」的範圍仍從最後一則 user 算。手動往 history 塞了不成對的訊息會被當成「這題」的一部分。
- **記憶庫與目錄重複**：同一件事各出現一次，白花 token；兩者衝突時腦要自己判斷。
- **recall 看得到整份紀錄**：包括當時工具讀過的檔內容；工具輸出裡有不該再給腦看的東西（密碼之類）時，recall 會再拿出來。

## 未決（選項，沒做，要的話再說）

- **只靠程式挑**（拿掉 recall）：最省，但漏了就是錯、腦沒有補救的路。
- **只靠腦要**：只給目錄、不自動展開任何舊題，全部由腦 recall；幾乎每個回頭引用的題都多一次呼叫。
- **先叫一次（小）模型判斷意圖**：每題多一次呼叫，挑得比字面準（同義詞、跨很遠的指代）。
- **答完時讓腦順手寫一行摘要**（或另叫小模型摘要）：目錄行與結論都換成摘要；摘要可能失真。
- **舊題的工具輸出改存成「小念頭的結論」**：讀檔這種大輸出當下就交給小念頭讀、只回要用的那幾句；之後要別的段落得再讀一次。
- **跟 prompt cache 配合**：前綴固定（system＋目錄只在換題時更新、展開的舊題放在最後）。
