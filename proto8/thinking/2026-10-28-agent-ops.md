## 決定（10-28）

1. **各種單位都要是 aos 函數**，也就是 aos-exec 能跑的東西：queue 的各種操作、endpoint、tools、迴圈裡各個時間點的掛勾，乃至一輪本身——**包括 endpoint**（使用者「各種單位都要跟aos函數對上，也就是aos-exec可以跑的單位目標。包括endpoint」）。目標是用在 aos agent 體系。
2. 頂層的第一份回答（提案一）**記下來**（使用者「記下來」）；記下來不等於逐條採納，內容仍是提案。
3. **跟規範衝突時照新做法走**（endpoint 是 aos 函數、各單位都是 aos 函數）：**P-23**（endpoint 由環境變數 `AOS_BRAIN_URL` 等給）改成 endpoint 是 aos 函數；**P-41**（腦寫在 think 格裡的程式）的 brain 拆成 endpoint 資料夾（使用者「跟規範不一樣...就是要這樣，我覺得我們現在這樣比較先進。」）。**NORMS／CONVENTION 條文這次不改，待實作時改**（待辦記在 [SESSION-LOG](../../wf/SESSION-LOG.md)）。
4. **迴圈上的固定時間點都是插座**，每個點都能掛 aos 函數；tools 何時生效＝掛在哪個點（使用者「好主意」）。
5. **history 是一個單位**，摘要、刪舊是 aos 函數（例 history/compact）、掛在問腦前（使用者「對的對的」）。
6. **endpoint 介面要講清楚**：輸入輸出格式、串流、錯誤分類（429 重試、401 停）、usage 回報，這些要處理（使用者「要，這個確實需要處理」）。
7. **引用共用零件用 symlink**（使用者「在aos體系下，引用，可以用symlink」）；agent 只寫自己要換的格。
8. **多個工具平行或依序，交給一個 aos 函數決定**（使用者「對的」）。
9. **不考慮跟 kernel 的關係**：我們就是呼叫函數，函數背後有沒有被 kernel 管，呼叫者不知道；之後再說（使用者「不需要考慮跟kernel的關係……那是後續了」）。
10. **symlink 引用共用零件跟 P-25、C-61「零個 `..`」衝突時，照新做法走**（使用者「撞到就撞到。反正我是覺得我們這個比較先進」）——跟決定 3 同一個精神；條文一樣先不改、待實作時改（待辦在 SESSION-LOG）。

決定 4～9 的細節設計（掛勾點的名字與語意、stack 的檔、history 與 endpoint 的介面、引用怎麼寫、工具平行、queue 對信箱、外部指令對應、落地步驟）照原則代定，全在 [agent-round](2026-10-28-agent-round.md)。

## 提案一：常用操作（提案，未定）

### queue 對到既有信箱（提案，未定）

- 對應：`new/`＝排隊中、`cur/`＝處理中、`done/`＋`out/`＝處理過、`history.jsonl`＝副產物（P-11～P-13、P-41）。
- 操作：say（push）、listen（pop）、看排隊、看當前（`current.txt`）、看處理過、跟著看 history、撤回（刪 `new/` 裡那題）、插隊（改檔名，靠 P-12 照檔名排序取題）、改題目。
- **「認領」（搬進 `cur/`）是界線**：認領前可以改、可以撤回；認領後只能看。

### endpoint 中途換（提案，未定）

- 環境變數在行程跑起來後改不到，所以要改成**每次問腦前去讀一個東西**。操作：get、set、候選名單。
- 跟原則的衝突：**P-23**（endpoint 由環境變數 `AOS_BRAIN_URL` 給）；**P-20**（出錯就停、不自動重試）——所以「失敗了重試」「失敗了換下一個 endpoint」算各 agent 自己的設定，範本預設照樣停。

### tools（提案，未定）

- 增刪改查已有 [aos-tools](2026-10-28-aos-tools.md)。
- 生效時間點三種：一輪開頭拍快照、每次問腦前重讀、跑工具中途被刪（這種已定：`ToolUnknown` 回給腦，P-41）。
- 代價：中途改工具清單，模型的 prompt cache 會失效，所以**時間點也交給 agent 自己設定**。
- 延伸：題目資料夾自帶工具（P-13 的資料夾題），只對那一題有效。

### 阻塞（提案，未定）

| 操作 | 預設 | 可選 |
|---|---|---|
| say | 不等 | `--wait` 等到答案 |
| listen | 等 | 設逾時；或不等、沒有就回一個結束碼 |
| 查看（排隊、當前、處理過） | 永遠不等 | — |
| 改設定（endpoint、tools） | 寫完就走 | 等到 agent 真的用上（要 trace 記這輪用的是哪一版） |
| pause | 等到下一個安全點 | — |

多人同時寫同一份東西，要先寫暫存再改名。

### 黑盒子（claude code、codex）（提案，未定）

- queue 和看過程做得到（hub 已經代它們收題，[hub-adapter](2026-10-28-hub-adapter.md)）。
- 中途換 endpoint 大概只能重開。
- 中途改 tools 要靠 MCP 的 `list_changed` 通知——**未查證**。

## 提案二：照決定 1 重寫的 pseudo code（提案，未定）

原樣收錄：

```python
# aos(X, ...) = AOS_STACK=<小格> aos-exec X ...；stdin／stdout／結束碼就是介面
# 迴圈裡的變數一律是 $AOS_STACK 裡的檔，所以每一步都能是獨立的行程

def round():                                   # 一輪本身也是 aos 函數：aos-exec round
    if not aos("queue/claim"):                 # new/ 最前面一題搬進 cur/；沒題目就退 10
        return 10
    while True:
        ep    = aos("endpoint/pick")           # stdout：這次要用的 endpoint 路徑
        tdefs = aos("tools/defs")              # = aos-tools ls；何時重讀由這格自己決定
        r = aos(ep, stdin=history() + tdefs)   # endpoint 本身是 aos 函數：messages 進，一則 assistant 出
        if r.code != 0:
            what = aos("hook/on_error", stdin=r.stderr)    # 印 retry／switch／stop；範本預設 stop（P-20）
            if what == "retry":  continue
            if what == "switch": aos("endpoint/next"); continue
            return r.code                      # 停下等人；狀態都在 stack，修好再跑一次接著做
        aos("history/append", stdin=r.out)
        aos("queue/emit", stdin=r.out)         # 吐給外面（out/ 或串流）
        if not r.tool_calls:
            aos("queue/finish")                # 答案寫 out/，題目 cur/ → done/
            return 0
        for call in r.tool_calls:
            if aos("queue/peek").has_new and aos("hook/on_interrupt") == "打斷":
                aos("history/append", stdin=aos("queue/claim_extra"))
                break
            out = aos("tools/call", call.name, stdin=call.arguments)   # = aos-tools call
            aos("history/append", stdin=out)
            if aos("hook/should_pause"):
                return 0                       # yield 在 aos 裡就是「結束並把狀態留在 stack」，下次從這接

def agent():                                   # 外層 = aos loop／fsm 反覆跑 round
    while (code := aos("round")) == 0: pass
```

### 外面的人用的操作（提案，未定）

也是 aos 函數，而且跟上面迴圈動的是同一批檔：

| 操作 | 對到 |
|---|---|
| say | `queue/push` |
| listen | `queue/pop` |
| 看排隊 | `queue/peek` |
| 看處理過 | `queue/done-ls` |
| endpoint set／ls | 改 endpoint 註冊檔（形狀可比照 tools.json） |
| tools 增刪改查 | aos-tools |

### 附帶結論（提案，未定）

- endpoint 變成資料夾程式之後，假腦、LiteLLM、直連 OpenAI 都只是不同的 endpoint 資料夾。
- 黑盒子 agent（claude code、codex）等於把整個 `round` 換成一個由 hub 包起來的 aos 函數。
- 每一步都開行程很慢。決定 1 是「**可以是** aos 函數」，不是「**必須拆成**行程」，實作可以合併。

## 跟原則對不上的（提案，未定）

P-23、P-41 的衝突已定（決定 3）、P-25／C-61 的 `..` 已定（決定 10），不在這裡；細節設計撞到的（P-33 程式根、兩套引用、N-53 一次一格、P-41 只附加、N-43 錯誤分類）列在 [agent-round 文末](2026-10-28-agent-round.md#要使用者看的只這一節)。剩下：

- **P-20**（出錯就停、不自動重試、不數連錯）：pseudo code 的 `hook/on_error` 能印 retry／switch；範本預設 stop 就不違反，但 agent 自己設成 retry 時，P-20 要改寫成「預設」而不是「一律」。
- P-23 改了之後，`AOS_BRAIN_URL` 等環境變數頂多是某個 endpoint 資料夾自己的設定。
