## 前提（引用哪些決定）

- **map-review 第 3 點**（使用者 10-30）：claude code cli 這類外部 agent「本質上是可以用來代替 aos agent 的，兩者是平級的關係」，不是 aos agent 的腦；「射後有理」「訊息 queue」分成 aos agent 體系、外部 agent 兩塊看與比較，找出共同點，**以 aos agent 為主**，做成通用介面（aos-say／listen）。
- **map-review 第 5 點＋決定**：aos-hub 通用的那層就是 aos-daemon；**不做 aos-hub，現有的 aos-hub 改名 aos-eca-hub**（extern coding agent hub）；`aos-hub` 這個名字保留以後用；「除此之外還有 aos-eca XXX 這類的指令」。
- **map-review 第 6、10 點＋決定**：要一個把 proc 掛到 daemon 的指令（已做：`aos-daemon-ctl add`，自動認 loop、不是就 `execs`、`--kind max1` 是底線）；用哪個 daemon 靠環境變數＋argv（已做：`--daemon` ＞ `$AOS_DAEMON`，N-63 的 10-30 補）。
- **map-review 第 9、11 點**：命名慣例 `aos-<領域>-<功能>`（aos-llm-kernel、aos-llm-send 已改）；要不要寫成條文開著。
- **agent-bob 決定 33～35**：agent 這層叫 queue、不叫信箱；**aos-loop 是 aos agent 這支程式的內部組件**，外部 coding agent 內部是黑盒子、生命週期在外面包（含掛 daemon；`max: 1` 可以、daemon 原生掛更好）；對話簿放 stack；hub 的 pause 改名收起；**claude code cli 這類自己存 session 的，aos 要弄一份 symlink 或複製一份過來管理**。
- **agent-lifecycle 決定（10-30）**：衝突 1～6 與方向題 1～3 都照建議，其中跟這份直接相關的——queue 放 `$AOS_STACK/queue/`、一則訊息＝一則 OpenAI message、回答＝history 最新 assistant、停著等不阻塞（反應時間＝`interval_ms`）、daemon 原生 `execs`、舊 fsm 範本不搬、session 檔活著 symlink／stop 換複製、**工具叫的 claude／codex 也留 symlink**。
- **10-28 hub-kernel 決定**：1 名字（這份改口成 aos-eca-hub）、3 kernel 掛了指令報錯、5 pause／stop 兩種、6 歸檔放工作區的 stack、7 Ctrl-]＝只跳出、8 以 kernel 記的為準、9 hub 是 kernel 的一種、11 prompt＝stdin／stdout 當 queue、12 現成 agent 跟 aos agent 的差別在底層握不握在手上、13 插話等或打斷不訂死、14 kernel 要不要建在 daemon 上「沒差」。
- **10-28 medium 決定**：1 要納管就透過介質、直接 aos-exec＝Linux 管；2 aos-loop＝「常駐＋暴露狀態＋控制手把」套在 aos 函數上的包裝；17 hub 型環境變數薄標準（N-63）；22 身分＝路徑；26 紀錄 aos 不管；28 三種基本概念投遞、窗、父子交代（C-75）。
- **10-24 cli-tools**：claude／codex 當 agent 的工具（lib/agent/claude、codex，共用 `cli_session.py`）、`attach` 接畫面、tmux、Ctrl-\。**10-28 hub-adapter 結論三**：每種 CLI 一張適配表（claude、codex 實測；pi 建議走 rpc 模式）。
- **playground-queue 結論 1、2**：兩個場景——射後不理（`aos-exec agent-bob` 跑完結束、初始 prompt 寫在定義裡）、射後有理（跑著時塞 prompt、看 reply；aos agent 還能暫停狀態機）；**跑完要不要結束寫死在定義裡**，是停著等的腦才在外面包一層管生命週期。
- **實作現況（這次翻過）**：aos agent 那邊第 1～5 步做完——`lib/agent/queue` 走 `$AOS_STACK/queue/`（底下叫 aos-post）、round 有 `ROUND_ON_EMPTY=stop|idle`、agent-nia 範本 `_entry: ["aos-loop", "loop.json"]`、aos-say／listen／chat 只碰 stack 三樣（say＝`aos-post send --ordered`、listen 等信不見後讀 history、`--status` 看 aos-loop 的 `phase`）。daemon 那邊第 7、8 步做完——`execs`、`aos-daemon-ctl add|rm|ls`（投信進 `loops_mailbox/`）。**daemon 的子項拿不到自己的工作區**：daemon.json 的子項只有 `exec`（loop 型連 loop.json 的 key 一起），沒有給工作區的 key，`AOS_WS` 一律繼承 daemon 的；demo/daemon 的作法是把子 loop 的 exec 寫成單子 `argv: ["aos-exec", "--ws", …, "../agent-bob"]`。aos-hub 那邊：`aos-hub-kernel`（常駐、`$AOS_HUB/kernel.sock`、狀態只在記憶體）替代答實例收 `<資料夾>/.stack/new/` 的題、交 cli_session 答、寫 `out/`；`wip/hub-step6` 是「kernel 改收 queue、答案接 history、pause→close、cli_session 建 transcripts symlink、stop 換複製」的半成品。
