### E. agent-lifecycle 留的 WAIT_USER 六題

12. **① `wip/hub-step6` 的 kernel 改 queue 要不要合進 main**：**不合**，kernel 要刪；邏輯搬進 `lib/eca/turn`、cli_session 的 transcripts 那段收進 main（上面 9）。
13. **② loops_ctl 要不要認整份的 `execs`**：**不認，維持**。整份的 `loops` 是 N-54 10-16 的原型（ctl 整份期望，N-06），`execs` 10-30 才有、從一開始就只有增減（N-54 的 10-30 補已寫明）；要對稱就得連信箱模式也收整份，多一條規則換不到新能力（C-56）。
14. **③ aos-daemon-ctl 把 loop.json 搬成子項設定、`.env` 與指示詞不處理、非信箱模式不支援**：**維持**，但加 `--ws`（上面 4、衝突 1）。`.env` 不處理的代價是「定義裡用 `.env` 給的環境變數掛 daemon 時拿不到」，eca 範本因此把能設的都寫在 `parts.json` 的 `env`（aos-parts run 會套）、不靠 `.env`。
15. **④ aos-ai 舊 fsm 範本只剩 `run`**：**維持**（衝突 4 已定舊協議不遷）。
16. **⑤ 三處舊說法（NORMS/08 第 7 行、P-19「idle 看 `new/` 空了」、P-41「題目還在 `cur/`」）**：**補一句「舊協議；走 queue 的 agent 看 `$AOS_STACK/queue/`」**，不改原文。理由：P-11 已標舊協議，三處不補讀者會以為兩套並行；一句話的事（T-4 說「多半屬於舊協議」，這裡定成都補）。進條文步驟。
17. **⑥ round 放不放進 aos-loop＋fsm**：原則推不出（要改 N-36 或 N-43 其中一條），**留方向題**，附建議 → [方向題 1](09-方向題.md#方向題原則推不出的附背景例子)。

### F. 順帶

18. **P-42 ④ `server.txt`：刪掉、不落正文**。它是 hub-kernel 當服務者時的權宜（`/proc` 猜不到常駐的 Python）；turn 跑在 aos-loop 下，aos-loop 的環境有 `AOS_STACK`、`state.json` 有 `phase`，aos-listen 現有的兩招就夠。aos_human.py 讀 `server.txt` 的那段跟著刪（KISS 最後一步）。
19. **P-42 暫緩的那句**改口成：「aos-say／aos-listen 不分後面是 aos agent 還是外部 coding agent，都只碰這三樣；外部 coding agent 由它定義裡的 turn 格（`lib/eca/turn`）替它收 queue、寫 history，停著等與 `paused` 同樣由 aos-loop 提供（P-43）」。
20. **`AOS_HUB` 不改名、直接退場**（上面 8）；`aos-hub` 名字保留，之後真有「通用 hub」再用。
21. **命名慣例 `aos-<領域>-<功能>` 寫不寫成條文**（map-review 第 9 點開著）：這是頂層從使用者兩次改名推出來的，寫成 C-54 命名方法的一條規則最省（R13：「程式名＝`aos-<領域>-<功能>`，領域在前、功能在後；只有一個功能的領域可以省功能」），eca-hub、llm-kernel、llm-send、daemon-ctl 都對得上。要不要寫是條文的事、不是方向 → 列在條文草稿，使用者看到不反對就落。
