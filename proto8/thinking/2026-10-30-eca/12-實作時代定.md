## 實作時代定（10-30，隊長與工人照原則定的細節，可翻案）

- **daemon `ws`（第 1 步）**：列上沒設 `ws` 就不寫這欄（舊讀者與測試不受影響）；`null`＝沒寫、空字串或其他型別照該處既有的壞值規則（daemon.json CfgBad、loops_ctl 整份不採用、信算壞信）；`ws` 的指示詞照解（N-45）；相對路徑從 daemon 的 cwd 用 abspath 轉（daemon 不 chdir）；不驗資料夾在不在（aos-exec 報 `WsMissing`）；改了 `ws` 照 N-54 不重起；只有物件子項能寫；adopt 保留舊列的 `ws`。
- **aos-daemon-ctl（第 2、6 步）**：`--ws` 由 ctl 從呼叫當下的 cwd 轉絕對、必須是現有資料夾（`PathMissing`）；`.stack` 捷徑在信送出成功後才建、建不成只印「注意」照樣退 0；**`.stack` 已在（例如直接 aos-exec 跑過的真資料夾）＝不建，印「注意 工作區已有 .stack…，沒建捷徑…；要接上請先搬開（或用 --stack …）」、退 0**（10-30：照它既有「注意」一行、退 0 的慣例，不另設 `StackExists` 退 1——add 的信已經送出，退 1 會讓人以為沒掛上）；`rm` 只拿掉「指到這個小格」的捷徑；**搬 loop.json 進小格時，exec 裡剛好等於 `{"$env": "AOS_CD"}` 的值換成定義的絕對路徑**（`pin_cd`；不然掛 daemon 時 `AOS_CD`＝小格、turn／round 找不到定義，agent-nia 掛 daemon 也有同一個洞；跟既有的「相對目標轉絕對、單子 cwd 定死在定義」是同一類改寫）。
- **cli_session（第 3、5 步）**：`register` 送 kernel 那段刪，寫 `tool.txt`／`ws.txt` 那段留下改名 `note_cell`（叫回畫面要用）；`wip/hub-step6` 的 `transcript_note` 沒收（沒人叫）；`freeze_transcripts` 拷到一半來源被清掉也不報錯；抽出共用 `ask()`（note_cell → lock → 畫面／非互動 → transcripts），錯走 `die`（turn 換成丟例外）。
- **turn（第 4 步）**：定義資料夾由 argv[1] 傳（`{"$env": "AOS_CD"}`，同 round）；turn 自己叫 aos-post、自己附加 history，不經 aos-parts 找 queue／history 格（parts.json 只有一格）；小格＝`$AOS_STACK/<kind>/`；好信＝`{"role": "user", "content": 非空字串}`；`SessionBad` 與 queue 空都不寫 trace（免得洗版，Q-9）；壞信 trace 一行 code 0 帶 `letter_warning`；CLI 失敗退 1、信留 `cur/`（P-20）；queue 沒有就 `aos-post init`；`prompt.txt` 只在 history 空且 `new/`、`cur/` 都空時投；`eca.json` 有變才寫；`ECA_ON_EMPTY` 沒設＝stop、值不對＝`SettingBad`；沒用到 `Letter*`／`PartMissing`。
- **範本（第 5 步）**：`lib/agent/claude`、`codex` 的 `_entry` 沒改成叫 `turn --one`（它們本來就叫 `call_main`＝工具形，問 CLI 那段已共用 `ask`；改了多一層行程，而且工具被整個複製進 agent 的 `tools/` 時找不到 `lib/eca/`）；射後不理在 aos-loop 外面看是退 0（內層退 10＝loop 以 0 收工）；要射後不理就複製一份改 `parts.json` 的 env（註冊檔的 env 蓋過環境變數）；範本 `cli.json` 沿用 lib 工具的保守旗標、不放 `prompt.txt`。
- **aos-eca-hub（第 6 步）**：歸檔放 `$AOS_DAEMON/eca_archive/<名字>-<UTC>/`（10-30 使用者「A」改；原本放 `<工作區>/.stack/eca_archive/`、rm 拿掉捷徑後建真資料夾，「`.stack` 指進小格裡面就退到 daemon 底下」那條特例跟著消失）；`.stack` 捷徑還指著小格或小格裡面（ctl 沒拿掉）就先拿掉，工作區不留東西；用 `shutil.move`（可能跨檔案系統）；`close` 出錯停了的實例＝先 rm、等那列不見才 add（同一圈先刪後加 daemon 不重起 done 那列）；用 loops_state 的心跳判 daemon 活不活；等 daemon 收掉最多 30 秒（`Timeout`）；不另做 `aos-post init`。
- **human（第 7 步）**：aos-listen「trace 有 question＋error」的判斷保留，只改註解（turn 失敗也這樣寫）。
- **agent-dan-q（第 8 步）**：**不改 agent-dan，另開 `demo/agent-dan-q`**（agent-dan 被 7 個測試與 janet／lua 範例逐檔比對，搬了要改一大片；方向題 1「哪隻真要用才搬那隻」的意思照樣達到）；**只做射後不理**（fsm 要「成功但留在原地」才能停著等，正是方向題 1 的洞，不繞；要停著等用 agent-nia 或 eca 範本）；tools 指 `lib/base`、idle 寫成 `idle.py` 單子、壞信丟掉接著認領下一封。
- **條文（第 9 步）**：N-63 的 `AOS_HUB` 直接刪字、② 的例子 `HubMissing` 換 `DaemonMissing`；P-43 照實作多寫幾件（`letter_warning`、`eca.json`、CLI 錯照 P-20）；舊協議半句直接接在原句後面、原文不改。
- **還留著的 `AOS_HUB` 字樣**：`cli_session.py`、`lib/README.md` 的歷史說明，`test_eca`／`test_eca_turn`／`test_fay` 清環境的名單（無害）。
- **已裁（10-30，使用者「A」）**：原本 `aos-eca-hub stop` 照 hub-kernel 決定 6 把歸檔放工作區，留下真的 `.stack/`、再 add 就接不上；改放 `$AOS_DAEMON/eca_archive/`，見 [§ 決定](09-方向題.md#決定10-30) 第 10 條。直接 `aos-exec` 跑過的工作區照舊要人先搬開（試驗場 README 用 `mv .stack .stack-direct`），add 現在會印警告講明。
