## 方向題（原則推不出的，附背景例子）

1. **round 要不要搬進 aos-loop＋fsm 的框架**（你 10-30 第 2 點問的、WAIT_USER ⑥）。背景：round 是「看資料決定下一格」的一支程式（認領 → 問腦 → 跑工具 → 交卷），aos-loop 只負責一次次叫它；agent-dan 那種是 aos-loop 跑 aos-fsm、一次一格。隊長查過：fsm 每格只有一條「下一格」、只有退 0 才前進，round 要的「分岔」「成功但留在原地」「答完一題就停」fsm 都沒有，硬拼會把 round 散到每一格裡、每格自己再判一次。要乾淨只有兩條路，都要改規範：(甲) fsm 的 `next` 可以照結束碼分岔（改 N-36「每格一個 next」）；(乙) 多一個「成功但留在原地」的結束碼（改 N-43「結束碼只有三種」）。**建議：都不走，round 留著當骨架**——它是零件庫的語法糖（你 10-28 說的）、不是 aos 指令，留著不違反任何原則；等真有第二個東西需要「分岔」再改 fsm。這題跟 eca 無關，只是一起收。 **已定：照建議（使用者 10-30「都照建議」）。**
2. **人在 claude 畫面上自己打的話，要不要抄進 aos 的 history。** 背景：你 `aos-eca-hub open` 進畫面跟 claude 講了三句、Ctrl-] 跳出，之後 `aos-say` 的第四句 claude 記得前三句（它自己的 session 有），但 `aos-listen --last` 看不到那三句（沒經 queue、history 沒抄）。完整的對話在小格 `transcripts/` 的 symlink 裡看得到。claude 有 hook 可以在人送出每句時通知（`UserPromptSubmit`），技術上抄得進去。**兩條路**：(甲) 不抄——history 只記「經 aos 進出的」，簡單、跟決定 26「紀錄 aos 不管」同調，想看全貌去 transcripts；(乙) 抄——hook 把人打的那句接成 user、`Stop` 把回答接成 assistant，history 就是完整對話，但 codex 沒有同等的 hook（只有講完的 notify）、pi 要另看，三種 CLI 會不一樣。**建議：甲**，這份先照甲寫（結論 2）；你覺得 listen 看不到會困擾再換乙。 **已定：照建議（使用者 10-30「都照建議」）。**
3. **`aos-eca-hub add` 的預設定義放哪、叫什麼。** 背景：`add --kind claude 專案` 要有一份現成的定義拿來用；這份放 `demo/eca-claude`（跟 agent-nia 同一層）。但 demo 是「範例」，拿範例當正式預設有點怪；放 `lib/eca/claude/` 又跟「lib 是零件、不是整隻」的分法打架；放 `extras/eca_hub/templates/` 最貼（hub 自己的東西）但 agent-fay 那種「拿去改一份」的用法要多知道一個地方。**建議：`demo/eca-claude`、`demo/eca-codex`**，跟所有 agent 範本一個地方；eca-hub 預設指過去，`--template` 可換。小題，寫這裡是因為「demo 當預設」是個分類上的選擇、原則沒說。 **已定：照建議（使用者 10-30「都照建議」）。**

## 決定（10-30）

使用者 10-30 看完衝突六條與方向題三條：「都照建議」。

1. **衝突 1**：daemon 的 `loops`／`execs` 子項多一個選填 `ws` key，daemon 起子項時設 `AOS_WS`；aos-daemon-ctl 多 `--ws`（N-28、N-54 各補一句）。
2. **衝突 2**：aos-eca-hub 不設自己的常駐 kernel，常駐的是 aos-daemon、以 `loops_state.json` 為準；hub-kernel 決定 2、3、8、9 改口，`aos-hub-kernel` 與 `kernel.sock` 刪。
3. **衝突 3**：`aos-eca-hub add`（與 `aos-daemon-ctl add --ws`）在專案建一個 `.stack` symlink 指到 daemon 的小格；專案本來就有 `.stack` 就不建、報一句。
4. **衝突 4**：`AOS_HUB` 退場、不改名，aos-eca-hub 用 `AOS_DAEMON`；N-63 實例拿掉 `AOS_HUB`，`aos-hub` 名字留給以後。
5. **衝突 5**：外部 agent 用 aos-loop 包 turn（claude 仍是黑盒子），決定 34 不改字。
6. **衝突 6**：`server.txt` 與「只登記的實例」都刪；要看 agent 的工具呼叫去看那隻 agent 的 trace。
7. **方向題 1**：round 不搬進 aos-loop＋fsm，留著當骨架；N-36、N-43 不改。
8. **方向題 2**：人在畫面上自己打的話不抄進 history，全貌看 `transcripts/`。
9. **方向題 3**：預設定義放 `demo/eca-claude`、`demo/eca-codex`，aos-eca-hub 預設指過去、`--template` 可換。
10. **stop 的歸檔放哪**（使用者 10-30 看完 WAIT_USER 那題，原文「A」）：改放 daemon 小格那邊 `$AOS_DAEMON/eca_archive/<名字>-<UTC>/`，工作區永遠只有 `.stack` 捷徑、stop 時把捷徑拿掉就好、不在工作區建真的 `.stack/`——翻掉 10-28 [hub-kernel 決定 6](../2026-10-28-hub-kernel.md)「歸檔放工作區的 stack」。直接 `aos-exec` 跑過留下真 `.stack/` 的工作區是另一種情況：add 照舊不建捷徑，但印一行警告要人先搬開（[§ 實作時代定](12-實作時代定.md#實作時代定10-30隊長與工人照原則定的細節可翻案)）。

## 之後再改：停著時改 history 再繼續（10-30，使用者先記下）

使用者原文（10-30）：

> eca這塊，history只能出...假如我關掉了session，然後找到這個session的history，給他刪去一些東西，然後繼續session，這樣可以嗎
> 先記下來吧，之後再改。

跟 AI 討論後的結論：

- **aos agent：可以，本來就這樣。** history 是它的記憶，每輪從 history 重建上下文；「只附加」是跑著時的規矩，停著時改幾行、下一輪就照改過的繼續（射後有理場景二；compact 做的也是同一件事）。
- **外部 agent（claude code 等）：改 aos 的 `history.jsonl` 沒用。** 真正的狀態在廠商自己的 session 檔，aos 的 history 只是 turn 抄的鏡子，`--resume` 不會看。兩條路：
  1. 直接改廠商 session 檔——格式沒保證，不當標準做法。
  2. **turn 支援「history 被改過就重開 session」**：turn 發現 history 跟它上次寫的對不上（或使用者明說 reseed），就不 `--resume`、開新 session、把改過的 history 整份當開場餵進去；代價是對方 cache 掉、session id 換。頂層建議走這條。

狀態：**開著、之後再改**（使用者「先記下來吧，之後再改。」）；落點是 `lib/eca/turn`（實作第 4 步）。
