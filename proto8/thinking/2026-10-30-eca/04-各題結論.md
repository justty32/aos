### C. aos-eca-hub：daemon ＋ 什麼

7. **aos-eca-hub＝aos-daemon（通用層，使用者定）＋三件 daemon 做不到、只有外部 CLI 才需要的事**：① **畫面**（tmux 開／接／關、Ctrl-] 只跳出、信任提問要人回答）；② **對話接回**（`--resume`／`exec resume`、session id 在小格 `session.txt`）；③ **它自己的 session 檔**（transcripts symlink、stop 時換複製）。其他 10-27 筆記裡的事都歸 daemon：「記哪個資料夾有實例在跑」＝`loops_state.json`；「給使用者查詢」＝`aos-daemon-ctl ls`；「閒太久就關掉」＝`close --idle`（照舊用 aos-loop 跑 `reap.json`）；「限制同時數量」＝使用者 10-28「實作時再說」，仍不做。
8. **它是另一支程式掛在 daemon 上，不是 daemon 加 kind**（C-52 daemon 只管自己這層、不知道子項是什麼；N-42 kernel 基於 daemon；hub-kernel 決定 14「要不要建在 daemon 上沒差」→ 這次定建在 daemon 上）。aos-daemon（C++）**一個字不加 eca**；aos-eca-hub 是 Python 命令列，每個子命令都是「叫 aos-daemon-ctl ＋ 動小格裡 cli_session 的東西」：

   | `aos-eca-hub …` | 做什麼 | 底下是 |
   |---|---|---|
   | `add [--kind claude\|codex \| --template 定義] [--name N] 資料夾` | 把「某個定義 × 這個資料夾」掛到 daemon，開始替它收 queue | `aos-daemon-ctl add --ws 資料夾 --name N <定義>`（預設定義 `demo/eca-<kind>`，`--kind` 沒給＝claude）；小格沒有 `queue/` 就 `aos-post init`；資料夾沒有 `.stack` 就建一個 symlink 指到小格（[衝突 3](08-衝突.md#衝突跟既有原則實作對不上的寫給使用者看)） |
   | `ls [--json]` | 列納管的外部 agent：名字、daemon 的 `phase`、CLI 種類、工作區、對話 id 前 8 碼、畫面開沒開 | `aos-daemon-ctl ls` 再只留小格裡有 `cli.json` 種類記號（turn 寫一份 `eca.json`：`kind`、`ws`、`template`）的那些；畫面＝小格 `tty.sock` 活不活 |
   | `state [資料夾\|名字]` | 這裡是不是納管的外部 agent | 讀同一張表；不是＝`InstanceMissing` |
   | `open [-d] [資料夾\|名字]` | 接進畫面；沒開就開（有對話就 `--resume`）；還沒 add 就先 add | cli_session 的 attach（agent-fay 的 `attach` 同一段程式）；只有人開畫面，turn 從不自己開 |
   | `close [資料夾\|名字]`／`close --idle 分` | 收起：關畫面、對話留著、turn 照樣用 `--resume` 答 | `tmux kill-server`；出錯的實例 close 一次＝清掉錯、再收 |
   | `stop [資料夾\|名字]` | 結束：關畫面、從 daemon 拿掉、小格搬到 `$AOS_DAEMON/eca_archive/<名字>-<UTC>/`（10-30 使用者「A」改；原寫 `<工作區>/.stack/eca_archive/`）、transcripts symlink 換成真的複製 | `aos-daemon-ctl rm N` → 等 `done`／`stopped` → 搬小格、`freeze_transcripts`（`wip/hub-step6` 那段） |
   | `watch [資料夾\|名字]` | 跟著看非互動那次在做什麼 | 讀小格 `live.jsonl`（照舊） |

   - **沒有常駐的 hub kernel、沒有 `kernel.sock`**：決定 8「以 kernel 記的為準」改讀成「以 daemon 的 `loops_state.json` 為準」（同一個精神：有一個常駐的東西記著、指令只讀它）；決定 3「kernel 掛了指令報錯」＝daemon 沒跑或 `AOS_DAEMON` 沒設＝`DaemonMissing`（N-63）；決定 9「hub 是 kernel 的一種」＝aos-eca-hub 建在 daemon（aos 的通用管理者）上。hub-kernel 這三條要改口 → [衝突 2](08-衝突.md#衝突跟既有原則實作對不上的寫給使用者看)。
   - **`AOS_HUB` 退場**（名字保留給以後的 aos-hub，使用者 10-30）：aos-eca-hub 用哪個 daemon就照 aos-daemon-ctl 的 `--daemon` ＞ `$AOS_DAEMON`，不另設變數（N-63 一個 hub 一個變數，這裡的 hub 就是 daemon）。N-63 列的實例 `AOS_HUB` 拿掉 → [衝突 4](08-衝突.md#衝突跟既有原則實作對不上的寫給使用者看)。
   - **「暫停」只有一種**：N-07 的 `paused`（寫實例小格的 `ctl.json`，不餵下一則）；hub 的 `pause` 改名 `close`（決定 35 收起），aos-eca-hub 不另做 pause。要「先別動」就寫 ctl 或別 say。
9. **現有 aos-hub 的東西哪些改名、哪些併進 daemon、哪些刪**：

   | 現在 | 處置 | 理由 |
   |---|---|---|
   | `extras/cli_hub/` 資料夾 | 改名 `extras/eca_hub/` | 名字跟程式一致（C-54）；`cli_hub` 是 10-27 的舊名 |
   | `bin/aos-hub` | 改寫成 `bin/aos-eca-hub`（上表七個子命令） | 使用者定的名字 |
   | `bin/aos-hub-kernel` | **刪**。收題的那段（claim → history → 工具 → history → finish；`wip/hub-step6` 已改成 queue 版）搬進 `lib/eca/turn`；register／ls／state 的那段由 daemon 的表取代 | 通用層＝daemon（使用者定）；一個實例一個 aos-loop 比一個 kernel 輪詢全部更貼 C-52（每個實例只管自己） |
   | `bin/hub_ipc.py`（`kernel.sock`） | **刪** | 沒有 kernel 就沒有 IPC |
   | `reap.json` | 改成 `aos-eca-hub close --idle 30` | 照舊，只換指令 |
   | `AOS_HUB` | **退場**，改用 `AOS_DAEMON` | 上面 8 |
   | cli_session 的 `register`（送一行給 kernel） | **刪**；「只登記的實例」這個分類消失——工具叫的 claude／codex 不是實例，`ls` 不列；它們的 transcripts symlink照方向題 3 留 | 沒有 kernel；工具呼叫是那隻 agent 的事（C-52） |
   | cli_session 的 transcripts symlink、`freeze_transcripts`（`wip/hub-step6`） | **收**，進 main | 決定 35、C-15～17 已定，跟 hub 怎麼切無關 |
   | `wip/hub-step6` 的 kernel 改 queue、pause→close、test_hub 改寫 | kernel 那份**不合進 main**（kernel 要刪），邏輯搬進 turn 時當參考；test_hub 的「say／listen 經 queue」四案改寫成 test_eca（對 `aos-exec demo/eca-claude` 跑假 CLI）；分支做完這輪後刪（刪分支要使用者點頭，列 WAIT_USER） | WAIT_USER ① 的答案：不合、改搬 |
   | say／listen／human README 裡的 hub 用語、`server.txt` | **刪**：turn 跑在 aos-loop 下，`/proc` 掃 `AOS_STACK` 就找得到服務者、`state.json` 就有 `phase`；P-42 ④ 不需要了 | KISS 最後一步減法（C-56）；F 題一起解 |
   | N-63 實例 `AOS_HUB` | 拿掉，`AOS_DAEMON` 已在 | 上面 8 |
   | thinking hub-kernel／hub-adapter 的標題與正文 | **不改字**（歷史紀錄）；各加一行「10-30 起 aos-hub 改做 aos-eca-hub，見本檔」；hub-kernel 決定 2、3、8、9 標改口 | R-3 的做法：舊紀錄只補指標 |
   | code map `06-周邊工具-3`、`09-lib`、`proto8.md` | 跟著改名、加 `lib/eca/` | 鐵律 3 |

10. **`aos-eca XXX` 要哪幾支**：**現在只要一支 `aos-eca-hub`**。使用者提的「aos-eca XXX 這類的指令」照 `aos-<領域>-<功能>` 看，eca 這個領域底下現在能想到的功能只有「管實例」（hub）；「說話、聽、停」是 aos-say／listen／ctl 的事、不分領域；「接畫面」是 hub 的 `open`。以後要再加（例如 `aos-eca-import` 把一個已經在跑的 claude 收進來）照同一個慣例取名就好，現在不預先建。
