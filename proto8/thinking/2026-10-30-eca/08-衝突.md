## 衝突（跟既有原則、實作對不上的；寫給使用者看）

1. **掛在 daemon 底下的 agent，拿不到自己的工作區。** 現在 daemon 起子項時，子項的「工作區在哪」（`AOS_WS`）只能繼承 daemon 自己的，daemon.json 的子項沒有一格可以寫「這隻的工作區是哪個資料夾」；demo 是把子 loop 的指令寫成「`aos-exec --ws 某資料夾 …`」繞過去。你要的「cd 到專案、把 claude 掛上去」一定要每隻有自己的工作區。**跟哪條對不上**：N-28 子項設定只有 `exec`（loop 型連 loop.json 的 key），N-54 的增減同；實作代定 D-2「物件裡其他 key 忽略」。**各選項後果**：(甲) 子項多一個 `ws` key、daemon 起它時設 `AOS_WS`——N-28、N-54 各補一句、daemon 改幾十行、aos-daemon-ctl 多 `--ws`；以後所有掛 daemon 的 agent（aos 的也是）都能各有工作區。(乙) 不加，照 demo 的寫法把 `aos-exec --ws` 塞進子項的指令裡——條文不動，但 `aos-daemon-ctl add XXX` 認出 loop 時就得改寫人家 loop.json 的指令（替人家插旗標，等於藏一條規則，C-56「不藏規則」不喜歡），而且 `execs` 型完全沒地方塞。(丙) 一個 daemon 一個工作區，要不同工作區就開不同 daemon——最省，但「一個 daemon 管我所有專案的 claude」就做不到。**建議：甲**。原則上本來就是 N-55「工作區由呼叫方設」，daemon 是呼叫方，只是 10-30 補 `execs` 時漏了。 **已定：照建議（使用者 10-30「都照建議」）。**
2. **aos-eca-hub 沒有自己的常駐 kernel，跟 10-28 hub-kernel 的三條決定字面相反。** 10-28 你定：`AOS_HUB` 指的資料夾裡跑一個常駐 kernel（決定 2）、狀態以 kernel 記的為準（8）、hub 是 kernel 的一種（9）。這份把「常駐、記著誰在跑」交給 aos-daemon（你 10-30 說通用層就是 daemon），aos-eca-hub 只剩沒有狀態的命令列。**後果**：照 10-28 字面＝留一個 hub kernel，跟 daemon 做同一件事（兩套記名單，決定 8 要選一邊）；照這份＝三條改口成「常駐的是 daemon、以 `loops_state.json` 為準、eca-hub 建在 daemon 上」，kernel 與它的 socket 刪掉、約 400 行程式不要了，`wip/hub-step6` 的 kernel 部分作廢。另外「kernel 重開清單清空」這個已知限制也隨之消失（daemon 有 `adopt`）。**建議：照這份改口**。三條的精神（有一個常駐的東西記著、指令只讀它、它掛了就報錯）一條沒丟，只是那個東西從 hub 自己的 kernel 換成 daemon——正是你 10-30 說的「摘出來就是 daemon」。 **已定：照建議（使用者 10-30「都照建議」）。**
3. **掛了 daemon 之後，「cd 到專案、直接 aos-say」找不到它的 queue。** 你 10-27 的用法是 cd 到專案資料夾就能接上那隻 claude；10-28 定信箱放專案的 `.stack/`。但掛在 daemon 底下時，實例的 stack 是 daemon 給的小格（`$AOS_DAEMON/<名字>/`），不在專案裡——這是 C-67「stack 放哪由呼叫方決定」的正常結果，aos-say 預設找 `<專案>/.stack/`（N-57）就找不到。**各選項後果**：(甲) `aos-eca-hub add` 在專案裡建一個 `.stack` **捷徑（symlink）**指到小格——cd 進去 aos-say 就通，專案頂層只多一個隱藏的捷徑（跟 10-28 的 `.stack/` 長得一樣）；專案本來就有 `.stack`（例如有 aos agent 在用）就不建、報一句，要人用 `--stack`。(乙) 不建捷徑，每次 `aos-say --stack $AOS_DAEMON/<名字>`——規則最少，但 10-27 的順手就沒了。(丙) 掛 daemon 時硬把小格設成 `<專案>/.stack/`——要 daemon 多一個「小格放哪」的設定，動 N-28 的小格規則，為一個用法改通則。**建議：甲**（跟 session 檔用 symlink 是同一招、你 10-30 已接受 symlink）。 **已定：照建議（使用者 10-30「都照建議」）。**
4. **`AOS_HUB` 退場，N-63 列它當實例。** N-63 的三個實例是 `AOS_STACK`、`AOS_KERNEL`、`AOS_HUB`（10-30 又補 `AOS_DAEMON`）；這份讓 aos-eca-hub 直接用 `AOS_DAEMON`、不另設變數。**後果**：留 `AOS_HUB`（改成指 eca-hub 用哪個 daemon）＝同一個 daemon 兩個名字（`AOS_DAEMON`、`AOS_HUB` 指同一個資料夾），一詞一義（C-54）出問題；退場＝N-63 拿掉一個實例、程式裡 24 處 `AOS_HUB` 跟著刪，`aos-hub` 這個名字乾乾淨淨留給以後。**建議：退場**。 **已定：照建議（使用者 10-30「都照建議」）。**
5. **外部 agent 包在 aos-loop 裡，跟決定 34「aos-loop 是 aos agent 的內部組件」字面有點緊。** 你說 aos-loop 是 aos agent 這支程式裡的零件，其他 coding agent 內部是黑盒子、在外面包東西。這份「外面包的東西」正好是 aos-loop（包著 turn，turn 再叫 claude）。**後果**：照字面不用 aos-loop＝得另寫一個停著等的循環（agent-bob-2 那條路，衝突 6 已否、暫停與狀態要重做一遍）；用 aos-loop＝claude 仍是黑盒子（aos-loop 包的是 turn、不是 claude），只是「包在外面的那層」拿現成的（medium 決定 2：aos-loop 就是「常駐＋狀態＋手把」的標準包裝）。**建議：用 aos-loop**，決定 34 不改字；這份只是把「外面包什麼」具體成「aos-loop＋turn」。 **已定：照建議（使用者 10-30「都照建議」）。**
6. **`server.txt` 與「只登記的實例」兩樣東西要刪，跟 hub-adapter 的代定 1、3 相反。** 10-28 hub 加了 `server.txt`（讓 listen 知道常駐 Python 在服務）和「只登記」實例（agent 叫工具時的格也列在 hub 的 ls 裡）。這份兩樣都不要：turn 在 aos-loop 下 `/proc` 就看得到；工具呼叫的格是那隻 agent 的事、不算實例。**後果**：留＝多一個檔、多一個分類，listen 多一招；刪＝`aos-eca-hub ls` 看不到「某隻 agent 正在用 claude 工具」。**建議：刪**（要看 agent 的工具呼叫去看那隻 agent 的 trace，C-52）。 **已定：照建議（使用者 10-30「都照建議」）。**
