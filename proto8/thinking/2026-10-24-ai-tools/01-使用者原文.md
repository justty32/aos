## 結論

**範圍**：只做「用 aos 指令與資料夾」這一層——起 agent（從範本產生資料夾）、丟題、`aos-exec` 跑一次、看 state／trace、經 daemon 的 ctl 加減子項、停、讀結果與錯誤一行；加上生成 JSON 與骨架（`make`）、概念速成（`explain`）。JSON 修改交給 aos-json，`aos-ai edit` 只是接口（交給 `$AOS_AI_JSON_EDITOR`）。

**兩種 AI、一個核心**：一支命令列 `aos-ai`（Python、只用標準庫），每次 stdout 一行 JSON；兩種 AI 都轉叫它——

- ① 外部 coding agent（Claude Code、Codex）：一份 Claude Code **skill**（`ai_tools/claude_skill/aos/SKILL.md`，同資料夾帶 `.claude-plugin/plugin.json` 所以也是 plugin）。不做 MCP server；Codex 讀 SKILL.md 就是一份精簡說明。
- ② 我們自己的 agent-dan 的腦：掛得上去的工具 `dan_tools/{spawn_agent, ask_agent, agent_status, make_json, make_tool, explain_aos}`（P-41 的形狀：`tool.json`＋`_entry`，arguments 從 stdin 進、stdout 一行 JSON）。

## 決定（使用者 10-24「都按建議做」，照推薦定、可翻案）

1. **形狀**：核心是 CLI＋JSON 輸出；① 給 skill（也是 plugin），不做 MCP；② 給 agent-dan 工具。
2. **名字**：資料夾 `proto8/ai_tools/`（C-54 資料夾小寫底線），指令 `aos-ai`；子資料夾 `bin/`、`dan_tools/`、`claude_skill/aos/`；工具名照 OpenAI function 慣例用底線（`ask_agent`）。
3. **工作資料夾（root）**：`--root` ＞ `$AOS_AI_ROOT` ＞ cwd；只寫 root 底下，`--ws`、`edit` 的檔都檢查；名字只收 `[a-z0-9][a-z0-9_-]*`。不刪任何東西、不碰 git。
4. **root 的佈局**：`agents/<名>/agent/`（範本複本）、`agents/<名>/ws/`（工作區，stack 在 `ws/.stack/`）、`agents/<名>/runs.jsonl`（aos-ai 每次 run 一行）、`daemon/`（一個 root 一個 aos-daemon）。
5. **範本**：`--from` 收 `proto8/demo/` 底下的名字或路徑，預設 `agent-dan`；`spawn` 是整份複製（不是連結），之後改這隻不影響範本。
6. **前景 run**：`aos-exec --ws ws agent`，`AOS_STACK` 明寫成 `ws/.stack/`（被別的 aos 程式叫時外面的 `AOS_STACK` 不漏進來）；預設 300 秒逾時，到了 SIGTERM 整群、10 秒後 SIGKILL。
7. **結果與錯**：agent 跑失敗是資料（aos-ai 退 0、JSON `ok: false`、`code`、`errors`、`hint`）；aos-ai 自己的錯照 C-54：stderr 一行 `aos-ai: 代號 原因（下一步：…）`、退 1。下層的 `程式名: 代號 原因` 拆成 `{prog, code, reason}`。
8. **背景**：用 aos-daemon，一隻 agent＝一個子 loop，`exec` 是單子 `{"argv": ["aos-exec", "--ws", ws, agent], "envs": {"AOS_STACK": ws/.stack/}}`、`interval_ms` 預設 2000；加減寫 ctl 的 `loops_added`（N-54），每次 `seq`＋1、等 state 的 `ctl_seq` 回音才回。子 loop 結束（agent 失敗）不會自己重起，`start` 時看到表上是 done／stopped 就先拿掉、等它下表、再放回。`daemon up` 會拿掉上次留下的 `stopped`，`loops_added` 照留（上次在背景的照起）。
9. **② 的工具**：子 agent 放 `$AOS_AI_ROOT`（沒設＝老闆的 `$AOS_WS`）的 `agents/<名>/`；錯照 lib 契約 stderr＋stdout 一行、退 1，由叫它的 agent 回給腦、腦自己改——agent-dan 範本本身就把工具錯回給腦（[tool-calls 文末](../2026-10-23-tool-calls/02-結論.md#10-24-定叫工具與小念頭的失敗回給腦)，使用者 10-24「都隨意」），`aos-ai spawn` 原樣複製範本；`ask_agent` 前景跑、上限 50 秒（`$AOS_AI_ASK_TIMEOUT`，要小於 act 格的 60 秒）。
10. **skill 的裝法**：放在 repo 裡（`proto8/ai_tools/claude_skill/aos/`），不改 repo 根的 `.claude/`；要用時 `--plugin-dir`、或 symlink 到 `~/.claude/skills/aos`、或 repo 的 `.claude/skills/aos`。
11. **只生成、不改**：既有 JSON 的修改交給 aos-json（`proto8/impls/aos-json`）。aos-ai 在 PATH 上找得到 aos-json 時：`--out` 寫完跑 `aos-json check`、`make cell` 用 `aos-json set` 改 fsm.json；找不到才自己讀－改－原子寫（只做簡單指標）。
12. **`make` 生成什麼**：JSON——inst 單子、loop.json、fsm.json、daemon.json、`_metainfo`、tool.json——先驗形狀再輸出，`--out` 原子寫入；骨架——agent 的新工具（tool.json＋`_entry`，可加 `_metainfo`）、fsm 新格（可起格資料夾）、函數資料夾（`_entry`＋`_metainfo`）。**形狀檢查只看 aos 讀的格**（exec 三種寫法、單子的 10 個 key、fsm 每格要有 `next` 且在表上、daemon 子項名字、`_metainfo` 通用 key 的型別、`priority` 不准放 `_metainfo`、tool.json 的 description／parameters）；其他 key 照 C-48 不管。
13. **loop／fsm／daemon 預設帶 `_entry`**（`["aos-loop"|"aos-fsm"|"aos-daemon", {"$env": "AOS_CF"}]`），生成的檔直接 `aos-exec` 得動；`--entry no` 不帶。
14. **fsm 的格**：`--cell 名=exec` 照順序，`next` 沒給＝下一格、最後一格回 `start`（接成環，同三態範本）；`--next 名=下一格` 改。
15. **欄位說明預設附上**（`notes`：每個欄位一句、指到 `explain` 的節），`--no-notes` 關掉。
16. **工具骨架預設 Python**（照 agent-dan 的 math；`--lang sh` 照 clock），骨架照 P-41：stdin 收 arguments、stdout 印結果、錯一行「工具名: 代號 原因」。
17. **函數資料夾的 `_metainfo` 是檔**（跟 `_entry` 並列，M1），內容照 M3 的通用 key。
18. **概念速成一份兩用**：`claude_skill/aos/concepts.md`，skill 讀它、`aos-ai explain` 印它；每節一句白話、最小範例、常見錯、條號，照 CONCEPTS／NORMS／CONVENTION 寫，不自創規則。
19. **`explain --here` 是模擬、不跑**：照 N-58、N-59、N-61、N-62 模擬「現在 aos-exec 它」——讀了哪些 `.env`（哪幾個名字因為已設而跳過）、挑到哪個入口、哪一種、入口看到的六個變數；輸出明寫「以 aos-exec 為準」。沒模擬的：字串轉向後的下一跳、`$AOS_ENTRY` 多段路徑、捷徑、繞圈；`.env` 只粗讀。
