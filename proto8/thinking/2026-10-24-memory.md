## 考古結論（以前講過的、做過的）

- **使用者自己的話**：agent＝腦＋**記憶（核心人格＝system、近期記憶＝上下文）**＋手腳（10-11 河堤 2.17，C-19）；「定義這個 agent 就是某一個資料夾，裡面已經放好相關的 skills／技能、memory／記憶、有的沒的、還有相關的工具」（10-11 第三輪 3g.10）；「只要符合機器人的三樣模型——記憶、思考中心、工具」（10-13）。
- **heap 這個名字早就留好了**：10-16 夜 frame 改名 stack 時，使用者問「能不能換成stack(或heap)?」，定下 stack＝這次執行用的、**heap 保留給以後跨呼叫共用的記憶，目前沒有機制**（名詞表、C-65 用詞）。記憶庫就是這個 heap。
- **proto7-2（10-09，使用者 14:40 三目標之二「做出現有 coding agent 常見的東西——compact、memory、skill 等」）**：記憶＝node 上的檔、不是模型視窗；跨信記憶 M1——每件做完存全文 `notes/done/<id>.md`、INDEX 一行一件（滿 50 行輪替）、**每回合固定附 INDEX、提到前件才附那一份全文**、AI 可回「要檔案：<id>」、**不用向量檢索**；skill＝SKILL.md 資料夾＋一行索引給模型挑（本機關鍵字、敢說 none）；compact＝舊段封存再換摘要、open 項不丟。真 AI 驗收：11 號信答出 01 號週報第 5 節，token 只多 0.9%。
- **proto5（09-24 第 4 隊）**：`note` 工具（add 同 key 更新／find 關鍵字＋標籤／get／rm），存 `wf-table/1` 的 `notes.json`、flock 防並行寫；`recall` 找被壓縮掉的原文；正式員工有長期記憶、臨時工（像工具一樣被叫）沒記憶。
- **wf 本身**：分層樹、索引只指下一層、膨脹即拆、條列走 `wf-table/1` 資料檔；使用者 09-30「Claude Code 的自動記憶是垃圾，wf 才是結構化的記憶」——要分類、要分層、要人看得懂、能清。

沿用的方法：記憶在檔不在模型（proto7-2）、每題固定附一小段＋有關的才附全文（proto7-2 M1）、關鍵字不用向量（proto7-2、proto5）、同 key 覆蓋＋flock（proto5 note）、`wf-table/1` 索引與分層（wf）。

## 結論：agent-meg 的記憶庫（使用者 10-24「都按建議做」，照推薦定、可翻案）

### 1. 長什麼樣

```
$AOS_HEAP/                 記憶庫（heap）；沒設＝$AOS_WS/.heap/（跟 .stack/ 並排）
  index.json               頂層索引（wf-table/1）：有東西的類各一列——類名、一句說明、幾筆、指向 <類>/index.json
  prefs/                   使用者偏好
    index.json             這類的索引（wf-table/1）：id、標題、標籤、摘要、建立／更新時間、狀態、檔案、忘記理由
    001.md                 一筆一檔（第一行 # 標題）
  facts/                   事實（專案、環境、人、東西在哪）
  outcomes/                做過的事的結論
  gotchas/                 踩過的坑與解法
  snippets/                檔案、片段、指令
  skills/                  可重用的做法（步驟、prompt）
  archive/<類>/            forget 掉的搬來這裡（不刪；索引那列 status=forgotten、留理由）
  .lock                    寫入時 flock
```

- id＝`<類>/<三位數>`（例 `facts/001`），就是檔案路徑去掉 `.md`；號碼只增不重用。
- 分層照 wf：頂層只指六類的索引，類的索引才指一筆一檔。一類太多時再拆是以後的事（見邊緣狀況）。

### 2. 放哪、私有還是共用

- **位置由叫它的人給**，跟 stack 一樣（C-67）：環境變數 `AOS_HEAP`（範本慣例，同 `AOS_BRAIN_*`，不是 aos 保證的那六個）。兩隻 agent 指同一個＝共用；各指各的＝私有；不給＝跟著工作區走（`$AOS_WS/.heap/`）。
- **不放在 agent 資料夾裡**：agent 資料夾是定義、呼叫時不變（C-46）；記憶是跑出來的東西。
- 哪幾類適合共用：prefs、facts（同一個使用者、同一個專案，各 agent 都該知道）；outcomes、gotchas 看工作範圍；skills 跟那隻 agent 的工具綁在一起，通常私有。這次不在程式裡分，靠「指哪個資料夾」決定。

### 3. 腦怎麼用

- **一個工具 `tools/memory/`**，`op` 四種：`save`（同類同標題＝覆蓋那一筆，回舊內容讓腦看到衝突）、`search`（關鍵字；query 空＝最近的）、`read`（一筆全文）、`forget`（搬去 archive、留理由）。不拆成四個工具：程式庫要放在工具自己的資料夾、工具之間不互指（P-25 零個 `..`），一個工具帶 `op` 是 proto5 `note` 的做法。
- **每題開頭範本自動注入**（不是等腦主動查）：think 每次問腦前，把「偏好全部（上限 1500 字）＋其他類照題目找最像的 5 筆（上限 2400 字）＋一句『不夠就 search／read，衝突以現在說的為準』」接在 system 後面；**不進 history**，所以剛存的下一輪就看得到、換 stack 也還在。庫是空的就不附。腦仍可以自己 search／read 找更多。
- 找法：英數一個字一詞、中文兩字一詞；標題命中 3 分、標籤 2 分、內文 1 分；不用向量、不用外部服務。
- 寫入：一次寫一筆（`save` 限標題 80 字、內容 4000 字、標籤 10 個），持 `.lock`；檔案與索引都先寫 `.` 開頭暫存檔再改名（N-05）。
- 錯：模型的錯（op／kind 不對、id 找不到、太長）照實回給模型、工具退 0；**記憶庫本身壞了**（索引不是 JSON）工具 `memory: HeapBad`、退 1（act 當 `ToolFailed` 停下）；think 注入時讀到壞索引＝`agent-meg: HeapBad`、退 1。
- system.txt 教腦：偏好、事實、結論、坑要存；只存使用者明說或確認過的；一件事一筆、寫成以後沒這段對話也看得懂的句子；衝突以現在說的為準並更新。

### 4. 過時與清理

- 每筆帶 `updated`，注入時印日期讓腦自己判斷。
- 過時或記錯＝腦 `forget`（或再 `save` 同標題覆蓋）；人要清就照樣叫這個工具（stdin 一行 JSON），或直接動檔——都是普通的檔與 `wf-table/1`。
- 不自動清、不自動摘要（proto7-2 的 compact 那套等真的太多再接）。

## 邊緣狀況（記著，不擋）

- **記憶衝突**：同標題覆蓋時把舊內容回給腦；不同標題講同一件事（「縮排 4 格」「Python 風格」）兩筆都會附上、可能互相矛盾——現在靠 system 那句「以現在說的為準」與日期。
- **記錯**：腦把猜的存成事實，下次還會被自動附上、越用越像真的。現在只靠 system.txt 叫它別存猜測；要追是誰哪題存的，目前沒記來源（工具不知道呼叫它的是哪題，C-52）。
- **越積越多**：注入有上限（偏好 1500 字、其他 2400 字），超過的偏好不附、說「用 search 找」；索引是整份讀，一類幾百筆後該拆（例：按年或按標籤拆成 `$ref` 陣列，照 10-23 daemon-ctl-ref 的做法）。
- **私有 vs 共用**：`AOS_HEAP` 會被子程式繼承——meg 把另一隻 agent 當工具叫時，那隻也會寫進同一個庫（等於自動共用）；要分開得在那個工具的 `_entry` 裡改 `AOS_HEAP`。
- **並行寫入**：同一個庫多個行程同時 save 有 flock，不互蓋（已測 20 個）；但兩隻 agent 同時覆蓋同一標題＝後寫的贏，前一個的內容只剩在回傳裡。讀沒鎖，可能讀到剛改名前的舊索引（只差一輪）。
- 中文兩字一詞：一個字的關鍵字（「貓」）只在整段就是一個字時才算詞，可能找不到。

## 可翻案的地方（照推薦定的）

1. 自動注入 vs 腦主動查：現在**自動注入＋可主動查**；另一條是只給工具不注入（省 token、但腦常忘了查）。
2. 一個工具帶 `op` vs 四個工具：現在一個；要四個就得讓工具共用程式庫（違反 P-25 或複製四份）。
3. 位置：現在 `AOS_HEAP`、預設 `$AOS_WS/.heap/`；另一條是預設放 stack 旁邊、或一律要叫的人給。
4. 共用：現在「指同一個資料夾＝共用」；另一條是分兩層（自己的可寫＋共用的唯讀，例 `AOS_HEAP_SHARED`）。
5. 六類的名字與分法（prefs、facts、outcomes、gotchas、snippets、skills）。
6. 找法：關鍵字；以後要向量檢索就換 `search` 的實作，介面不變。
