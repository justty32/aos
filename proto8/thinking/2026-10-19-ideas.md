### 14. entry 的定義（10-19 下班前口述）

> 好，首先是關於entry，entry這東西我給他一個定義：要麼自己是可執行檔，要麼是可以被aos-exec的標準實作所執行的檔案(aos-exec _exec)。aos-exec的標準實作，支援inst json格式，也支援json array(視為argv[])，也支援shebang、可執行檔。然後按照"json等同於單檔內的微型檔案系統"的定義，js["_exec"]，也是可以被aos-exec執行的，具體來說就是js["_exec"]的value必須是inst json格式或json array(argv)。

→ 整理：entry＝(a) 本身是可執行檔，或 (b) aos-exec 標準實作跑得動的檔。標準實作認四種：inst JSON、JSON array（當 argv）、shebang、可執行檔。單檔 JSON 照 C-72 也是入口：`js["_exec"]` 的值必須是 inst JSON 或 JSON array（argv）。（口述記錄，尚未寫進 CONCEPTS／NORMS、程式未改；現行 aos-exec 只認可執行的 `_exec` 與旁邊的 `_exec.json` 單子，見 N-57。）

### 15. aos-exec 怎麼找入口（10-19 下班前口述）

> 然後aos-exec XXX，這個XXX可以是資料夾，如果是資料夾的話就是後面接AOS_ENTRY。AOS_ENTRY必須指向檔案。如果找到了檔案，但該檔案的json格式並非inst json，那就去找這個json檔案的js["_exec"]，也就是AOS_ENTRY。

→ 整理：`aos-exec XXX` 的 XXX 可以是資料夾（也可以直接是檔）。是資料夾就接上 `AOS_ENTRY`，得到 `XXX/$AOS_ENTRY`，它必須是檔案。找到的檔若是 JSON、但不是 inst JSON，就往檔內找 `js["_exec"]`——也就是在 JSON 裡用同一個 `AOS_ENTRY` 再找一次（資料夾與 JSON 同一套尋址，C-72）；那個值照 § 14 須是 inst JSON 或 argv 陣列。（口述記錄，條文與程式未改。）
