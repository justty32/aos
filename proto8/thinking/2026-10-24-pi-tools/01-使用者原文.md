## pi 怎麼做（2026-10-24 查，`badlogic/pi-mono` 主線 commit `136b87e8`）

來源：[coding-agent/src/core/tools/](https://github.com/badlogic/pi-mono/tree/main/packages/coding-agent/src/core/tools)、[system-prompt.ts](https://github.com/badlogic/pi-mono/blob/main/packages/coding-agent/src/core/system-prompt.ts)、作者文章 [What I learned building an opinionated and minimal coding agent](https://mariozechner.at/posts/2025-11-30-pi-coding-agent/)。

- 預設只開四個：`read`、`bash`、`edit`、`write`；system prompt 短（工具說明不到 1000 token）；不做 MCP、子 agent、plan mode；不擋權限（怕就跑在容器裡）。
- read 最多 2000 行或 50KB、從頭截、不加行號；bash 從尾巴截、沒有預設逾時；edit 每個 `oldText` 對原檔比、唯一、不重疊、不空；路徑不擋出 cwd；工具的錯當結果回給模型、agent 不停。

## 決定（使用者 10-24「都按建議做」，照推薦定、可翻案）

1. **工具組四個**：`read`、`write`、`edit`、`bash`，各是資料夾程式、一份 `tool.json`（P-41 形狀）＋`_entry`（python3 純標準庫）。唯讀組（grep、find、ls）不另做——bash 就能做。
2. **參數名照我們的命名**（C-54 小寫底線）：edit 是 `edits: [{old_text, new_text}]`。不收 pi 為了相容舊模型的那些變形寫法。
3. **長度上限照 pi**：2000 行或 50KB。read 從頭截、提示 offset；bash 從尾巴截、只寫「只留最後幾行」，**不存全文暫存檔**（存了模型也讀不到：在工作資料夾外）。
4. **限制在工作資料夾＝`$AOS_WS`**（跟 pi 不同）：read／write／edit 的路徑從 `$AOS_WS` 算，解開 `..` 與符號連結後必須還在裡面（`PathBad`）；裡面的絕對路徑可以。bash 的 cwd 是 `$AOS_WS`，但指令本身擋不住，要真隔離就把整隻 agent 放進容器或沙箱（[sandbox](../2026-10-24-sandbox.md)）。
5. **bash 一定有逾時**：預設 30 秒、上限 300 秒。逾時＝整群先 TERM、2 秒後 KILL，算工具的錯 `CommandFailed`，逾時前的輸出照給。指令自己退非 0 **不算**工具的錯，結果尾巴寫「[結束碼 N]」；被訊號停寫「[被訊號 N 停掉]」。工具被外面 TERM（act 格逾時）時先停掉指令那一群再走，不留孤兒。stdin 是 /dev/null。
6. **edit 規則照 pi**（對原檔比、唯一、不重疊、不空、改完一樣算錯、全有或全無、CRLF 還原），**不做模糊比對**、不管 BOM（KISS；之後模型常撞再加）。read 不加行號、不讀圖片（拒絕二進位檔，`FileBad`）。
7. **錯誤照現行慣例**：stderr 一行「工具名: 代號 原因」、退 1；代號照 C-54：`ArgumentsBad`、`WsMissing`、`PathBad`、`FileMissing`、`FileBad`、`ReadFailed`、`WriteFailed`、`MkdirFailed`、`TextMissing`（edit 找不到）、`TextBad`（edit 不唯一／重疊／空／改完一樣）、`CommandFailed`（bash 逾時）、`LaunchFailed`。**同一行也印在 stdout**——stdout 是給腦看的結果，腦才知道錯在哪。
8. **掛上這套的 coding agent＝`demo/agent-pip`**：從 agent-dan 照抄，`tools/` 裡一條捷徑掛一個庫的工具（act 叫的地址仍是 `tools/<名>`）。`system.txt` 照 pi 的精神寫短版。loop `max` 200、think 逾時 180 秒、act 900 秒。
9. **叫工具出的問題回給腦、不停**（agent-dan 也一樣，[tool-calls 文末](../2026-10-23-tool-calls/02-結論.md#10-24-定叫工具與小念頭的失敗回給腦)）：工具退非 0（stdout 照收、尾巴加「(工具 X 結束碼 N)」）、叫了沒有的工具（`act: ToolUnknown …`，附能叫的清單）、`arguments` 不是 JSON（`act: ArgumentsBad …`）都接成一則 tool 訊息讓腦自己改。act 不讀工具的 stderr（C-52、C-53：腦看到的是工具自己放進 stdout 的那行）。
10. 試驗場 `~/code/try/pi-tools/`；真模型那一跑還沒做。

## 邊緣狀況（攤出來，不擋）

- **stack 放在工作區裡時，腦碰得到自己的對話**：`AOS_STACK` 預設 `$AOS_WS/.stack/`，write／edit／bash 都能改 `history.jsonl`、`state.txt`。工具不知道呼叫者的 stack 在哪（C-52），擋不了；真跑時把 `AOS_STACK` 放在工作區外。
- **bash 擋不住出工作資料夾**（`cat /etc/passwd`、`rm -rf ~`、連網）：路徑檢查只管 read／write／edit。要隔離得靠容器或另一層沙箱。
- **錯誤那行在 stdout 與 stderr 各一份**：工具被「退非 0 就停」的 act 叫時，stdout 那行沒人看，無害。
- **對話越來越長**：read 一次最多 50KB、bash 也是，幾輪就很大；history 不設上限（10-23 第 6 點），撞到模型的 context 上限會 `BrainFailed`（HTTP 400），沒有自動壓縮。
- **同一題卡死在腦一直重試**：錯誤回給腦之後，腦可能一直叫同一個錯的呼叫；只有 loop 的 `max`（200 次≈66 輪）擋著，到了 loop 停、題目留在 `cur/`。
- **bash 的指令自己開背景行程、脫離行程群**（`setsid`、`nohup … &` 再 `disown`）：逾時整群停不到它。
- **edit 不做模糊比對**：模型把彎引號、全形空白、行尾空白抄錯時就是 `TextMissing`，靠腦重讀再改。
- **符號連結指向工作區外**：read／write／edit 一律當 `PathBad`（含工作區裡本來就有的連結；agent-pip 自己的 `tools` 連結不在工作區、不受影響）。
