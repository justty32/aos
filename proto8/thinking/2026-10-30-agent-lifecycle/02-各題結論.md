### A. agent 層的 queue

1. **queue＝有順序投遞（N-16）在 agent 層的名字**；它是 N-16 有序信箱的一個實例，這一層叫它 queue、裡面一封信叫「一則訊息」。（決定 33「這一層是訊息的 queue」；C-54 一詞一義：queue＝一場對話的輸入、順序是意思的一部分；信箱＝獨立的請求。）
2. **位置：`$AOS_STACK/queue/`**，不在工作區。佈局照 N-16 有序信箱：`queue/tmp/`、`queue/new/`、`queue/cur/`、`queue/order.lock/`、`queue/order.json`；`done/` 選用（agent 想留才有，預設處理完就刪）。對話是這次執行的狀態；aos-say／listen 要摸的東西（queue、history、ctl／state）全在一個 stack 裡，hub 的「信箱放 `.stack/`」（使用者 10-28）跟 aos agent 同一條規則；工作區只剩使用者的檔與成品（使用者 10-16「我不喜歡 /ws 底下出現一個 work/」）。C-65 例子改口見[決定](07-衝突.md#決定10-30)衝突 1。
3. **一則訊息＝一封 N-16 的信**，`letter.json` 照信封（`kind: "letter"`、`sender`、`sent_at`、選填 `reply_to`／`in_reply_to`），**`body`＝一則 OpenAI message 物件**（`{"role": "user", "content": "…"}`，有需要也可以是 `system` 或帶 `name`），agent 收到就把 `body` 原樣接進 `history.jsonl`——queue 的一則＝history 的一行（P-41；C-56）。不是物件、沒有 `role`＝壞信，照 N-16 丟掉、記 `letter_warning`（agent 有 state 窗才記；aos-loop 開了窗就有）。
4. **queue 只收有序的信**：寄＝`aos-post send --ordered $AOS_STACK/queue`；非有序的信進來＝壞信。
5. **認領與處理完**：`claim`＝`aos-post claim`（rename 進 `cur/`）＋把 `body` 經 history 格 `append`；**信留在 `cur/` 直到這題答完**；`finish`＝assistant 那則已在 history 之後才 `aos-post finish`（預設刪、`--keep` 進 `done/`）。「信還在 `new/` 或 `cur/`」＝還沒答，「信不見了」＝答案已在 history。失敗（P-20）＝信留 `cur/`、人修好重跑接著做。插話（`claim --more`）：`cur/` 裡幾封就幾封一起算答完。
6. **回答不另開通道，答案就是 history 最新那則 assistant**（決定 11、26、C-56）。queue 是一場對話，不是一問一答；想要一問一答的人用 N-16 的 `reply_to` 自己做，標準不保證一題配一答。
7. **aos-say**：`aos-say [--ws WS] [--stack STACK] [話...]`＝`aos-post send --ordered <stack>/queue`，stdout 印信號；stack＝`--stack` ＞ `$AOS_STACK` ＞ `<WS>/.stack/`（N-57）。沒有 `queue/` 就建（`aos-post init`），可以先說再跑 agent；沒有 `--name`（信號由 aos-post 給）。
8. **aos-listen 只看 stack**（N-14 窗、N-13 stack 裡的檔）：
   - `aos-listen <信號>`：信還在 `queue/new/` 或 `queue/cur/` 就等；不見了就印 history 最新那則沒有 `tool_calls` 的 assistant 的 `content`；四處都沒這封、history 也沒新 assistant＝`QuestionUnknown`；服務者 trace 說失敗就講出來。
   - `--follow`／`--last N`：直接跟 history（只印 assistant，`--trace` 連 tool 一起）。
   - `--status`：誰在服務（`/proc` 掃 `AOS_WS`／`AOS_STACK`、或 stack 的 `server.txt`）、aos-loop 的 `state.json` 的 `phase`、queue 四格各幾封、history 幾則。
9. **P-11 題目信箱退場**：lib `queue` 格、round、`ask_round`、hub-kernel、aos-say／listen／chat、`lib/aos/aos_ws.py`、試驗場 bob 都改走 `$AOS_STACK/queue/`（底下叫 aos-post）。**舊的 fsm 範本（agent-bob／ann／dan、topdown）不改**，P-11 留給它們、標「舊協議」；say／listen 不再認它們（[決定](07-衝突.md#決定10-30)衝突 4、方向題 1）。
10. **「agent 之間的請求投遞」叫信箱**，不叫 queue：請求是一封封獨立的信（可能要回信、可以不照順序、處理者可能好幾個）；queue 專指對話那條（C-54）。資料夾名慣例 `inbox/`，位置照 N-16 由擁有者定、別人靠 hub 型變數或明給找到（N-63）。agent 自己去看信箱照決定 32 以後放 tools。
