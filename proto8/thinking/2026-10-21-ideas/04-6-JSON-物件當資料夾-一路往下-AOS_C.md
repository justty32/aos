## 6. JSON 物件當資料夾、一路往下、`AOS_CO`（10-21 晚）

規範：[N-57、N-59 第 4 件、N-61、N-62](../../docs/NORMS/10-基礎設施-定義與工作區.md)、[N-11](../../docs/NORMS/05-基礎設施-窗.md)、[N-28](../../docs/NORMS/04-基礎設施-loop與daemon.md)、[N-18](../../docs/NORMS/01-總則.md)、[P-39](../../docs/CONVENTION/06-巢狀.md)；測試 `proto8/tests/test_exec_env.py`。

### 6.1 原話

1. 頂層解釋 JSON 入口四種（陣列、有 argv 的單子、沒 argv 的物件取 `[$AOS_ENTRY]`、字串轉向）。使用者：
   > json裡面是否也會有.env？啊不對，inst json本來就支援。我是在想，因為沒有argv的物件，我們就把他當資料夾看待
2. 頂層提兩題：(1) 物件裡放 `.env` key，值是物件 `{"名字":"值"}`，`${}` 規則同 `.env` 檔；真資料夾的 `.env` 先讀、物件的 `.env` 後讀（後讀的贏），然後才照 `AOS_ENTRY` 挑 key。(2) 物件裡挑到的又是沒 argv 的物件：(a) 維持一層 (b) 一路往下、每層用當下的 `AOS_ENTRY`（同一個 `AOS_ENTRY` 值會一路用下去，除非子物件自己的 `.env` 改它）。使用者：
   > 1. OK，那就這樣。2.b，我們就是這樣規定的，具體風險由使用者自己承擔
3. 頂層問真資料夾要不要比照：(a) 兩邊都每層讀——`AOS_ENTRY` 挑到的是子資料夾就走進去、cd、讀它的 `.env`、再用 `AOS_ENTRY` 往下挑，`sub/run` 這種沿路資料夾的 `.env` 都讀；(b) 兩邊不同。使用者：
   > a
4. 兩個細節：
   > .env內的不是字串(在解完指示詞後)，那就靜默忽略。AOS_ENTRY等於.env時，那就將照做，就等於沒辦法另外設.env了。
5. 指標位置要不要反映在環境變數：
   > AOS_CF不動。但是我們再加上AOS_CO

   > aos current obj
6. 收尾的幾件（換腦、`.env` 改 `AOS_WS` 時 `AOS_STACK` 不跟著搬、「新程式不收旗標」、要不要做極簡基礎版）：
   > 換腦這塊不管，也不用待定，之後做到那邊的時候會改。.env改AOS_WS後AOS_STACK不跟著搬，這個真的OK，風險自己承擔。新程式不收旗標...沒關係的，那是軟性，應該改成"盡量不收"。極簡基礎版不用做

### 6.2 決定

- **J1 沒 `argv` 的 JSON 物件＝資料夾**（第 1、2 句）：進去先套它的 `.env` key（`{"名字": 值}`，`${名字}` 規則同 `.env` 檔）、旗標蓋回，再照當下的 `$AOS_ENTRY` 取那格。真資料夾的 `.env` 先、物件的 `.env` key 後。
- **J2 一路往下**（第 2 句「2.b」）：取到的又是沒 `argv` 的物件就再當資料夾走進去，每層用當下的 `$AOS_ENTRY`。風險使用者自擔。
- **J3 真資料夾也每層讀**（第 3 句「a」）：`$AOS_ENTRY` 挑到資料夾就走進去、cd、讀它的 `.env`、旗標蓋回、照當下的 `$AOS_ENTRY` 再挑，一路往下；`sub/run` 這種多段路徑沿路每個資料夾的 `.env` 都讀（由外到內）。
- **J4 JSON `.env` key 的值**（第 4 句）：可以放指示詞（同單子那套），解完不是字串的那一項靜默忽略——只有 JSON `.env` key 這樣，`.env` 檔格式錯照舊是錯。
- **J5 `AOS_ENTRY` 是 `.env`**（第 4 句）：照做，`.env` 那格當入口、不當環境設定，這時那個物件沒辦法另外設 `.env`。看的是進入物件那一刻、還沒套它的 `.env` 之前的值。
- **J6 `AOS_CO`**（第 5 句）：`AOS_CF` 不動（實際的檔，往下走進 JSON 物件時不變）；`AOS_CO`（aos current obj）＝實際入口在那份 JSON 檔裡的位置，JSON 指標、不帶 `#`（例 `/dev/sub`），最後跑到的那格；`檔#/指標` 也算在內（`x.json#/a` 再挑 `_exec`＝`/a/_exec`）；整份檔就是入口、或入口不是 JSON＝空字串；每一跳 export、覆寫；key 照 JSON 指標跳脫 `~0`、`~1`；`.env` 也能改它。aos 訂的環境變數是六個。（定義是頂層擬的，使用者回「aos current obj」確認。）
- **J7 換腦**（第 6 句）：不管、不列待定，之後做到那邊時再改。
- **J8 `.env` 改 `AOS_WS` 時 `AOS_STACK` 不跟著搬**（第 6 句）：風險使用者自己承擔。
- **J9「新程式不收旗標」是軟性**（第 6 句）：N-11、N-28 寫「盡量不收旗標」。
- **J10 極簡基礎版不用做**（第 6 句）。

### 6.3 頂層代定的細節（使用者可翻案）

翻案就改 [N-59 第 4 件、N-61](../../docs/NORMS/10-基礎設施-定義與工作區.md) 與 aos-exec 的 `hop()`、`find()`、`json_env()`。

1. JSON `.env` key：指示詞的 `$ref` 從那份 JSON 檔所在的資料夾算；指示詞解不開（`$env` 沒設、`$ref` 讀不到…）＝`.env 壞`；字串值的名字不合規則、`${名字}` 沒設＝`.env 壞`（同 `.env` 檔）；`.env` 這個 key 解完整個不是物件＝整個跳過、不算錯（比照 J4 的寬容）。錯誤訊息只印「檔#指標 的 .env」和原因，不印名字和值。
2. 有 `argv` 的物件（單子）裡就算有 `.env` key 也不套（單子自己有 `envs`）；只有沒 `argv` 的物件才當資料夾。
3. 真資料夾也比照 J5：走進資料夾那一刻 `$AOS_ENTRY` 是 `.env`＝那份 `.env` 檔不讀成環境，直接拿它當入口檔挑。
4. 物件自己的 `.env` key 把 `AOS_ENTRY` 改成 `.env`：先套（進去那一刻還不是 `.env`），再去挑 `.env` 那格——那格就是剛套的物件，通常是「入口壞」。
5. `AOS_CO` 的指標照實際走的路組：`檔#/指標` 照原樣（不重新正規化跳脫），之後每挑一格接 `/` 加跳脫過的 key；`AOS_ENTRY` 帶 `/`（例 `a/b`）在 JSON 裡是一個 key，指標裡寫成 `/a~1b`。
6. 每走進一層資料夾 `AOS_CO` 先設成空字串（所以資料夾裡的 `.env` 看到的是空）；挑完入口才設最後的值。最後讀的那份 `.env`（檔或 JSON `.env` key）自己設了 `AOS_CO` 就不蓋（同 § 5.3 第 2 點）。
7. 真資料夾一路往下走回走過的資料夾（例 `AOS_ENTRY=.`、捷徑繞回上層）＝`入口壞：資料夾繞圈`；`sub/run` 這種多段路徑裡的 `.`（`./run`）不算走進新資料夾、不重讀 `.env`。JSON 一路往下時挑的時候不解 `$ref`，走的是那份檔的樹，不會無限，所以不另做繞圈偵測（字串轉向的繞圈偵測照舊）。
8. 寫著「新程式不收旗標」的一般原則只有 N-11、N-28 兩處，寫「盡量不收」；講 aos-exec 以前行為的歷史敘述不動。
