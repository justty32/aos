# 2. 看得出的幾件事

1. **沒有「標準 `.env`」**。同一行 `X="a b"`：compose、dotenv 去掉引號；docker run 文件沒說（一般認為照字面留著，沒實測）。`${}` 有的展開、有的不展開，展開的語法也各不同；要相容外面的格式就得選邊。
2. **只有名字的一行，三家三種意思**：docker run＝從外面帶進來、python-dotenv＝不設、systemd＝跳過。沒有一家當成「拿掉」。
3. **拿掉變數，在「一份檔」的格式裡幾乎沒人做**。做的是 envdir 那一族（空檔）、systemd（另開一個設定）、bash／direnv（本來就是 shell）。dotenv 那一族都沒有。
4. **多行值都綁在引號上**：要多行就先要有引號，有引號就要有跳脫（`\"`、`\\`、`\n`），有跳脫就要回答「反斜線後面接別的字元怎麼辦」——systemd 為這件事在文件裡寫了一整段。唯一不靠引號的多行是 GitHub 的 heredoc，以及 envdir 的「整份檔就是值」。
5. **優先順序**：python-dotenv 與 node dotenv 預設**外面已經有的贏**（要 `override` 才蓋）；aos 同（預設不蓋、`--dotenv-override` 才蓋，N-58）。
6. **最寬的是 dotenvx**：連 `$(指令)` 都跑。這是「引號＋展開」一路長下去的終點，跟 aos「寫什麼就做什麼」正相反。
