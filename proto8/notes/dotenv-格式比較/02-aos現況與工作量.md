# 1. aos 現況（N-59 第 4 件、N-60、`proto8/bin/aos-exec` 的 `load_env`／`set_env`／`json_env`）

**收的**：一行 `名字=值`；去行尾 `\r`、去前導 ASCII 空白；空行與行首 `#` 跳過；`=` 只切第一個；值照字面（頭尾空白、引號、反斜線、行中的 `#` 都原樣）；只展開 `${名字}`（逐行，後面看得到前面設的）；孤零零的 `$` 原樣；同名後者贏。JSON 沒 `argv` 的物件另有 `.env` key：`{"名字": 值}`，值可放指示詞，解完不是字串的**靜默跳過**。

**判壞**（退 1、`.env 壞`、只印檔名和行號）：沒有 `=`、名字不合（含 `export X=1`、`X =1`、全形空白開頭）、`${` 後面不是 `名字}`、`${名字}` 沒設、值有 NUL、不是 UTF-8、帶 BOM。讀不到（權限、是資料夾、壞捷徑）＝`.env 讀不到`。測試在 `proto8/tests/test_exec_env.py`（`test_bad_lines_never_print_value`、`test_unset_reference_is_error`、`test_env_bom_is_bad`、`test_leading_whitespace_ascii_only` 等）。

**不判壞但跟別家不同的**（安靜地照字面）：`X="a b"`＝值含引號；`X=a # 註解`＝值含 ` # 註解`；`X=C:\a\n`＝反斜線照字面。這三種從別的工具抄過來時**不會報錯、會靜靜拿到不一樣的值**——這是現況最大的坑，跟要不要補功能無關。

# 2. 三項的工作量

估的基準：bin 版 `load_env` 現在約 25 行、`set_env` 約 20 行；impls（C++，這台沒有）照 [code map](../../../wf/workflows/common/code-map/proto8/01-impls與舊lib.md) 是 `aos-exec/src/env/dotenv.cpp` 的 `load_env`／`json_env`／`set_env`，結構跟 bin 一樣，所以改法對得上；10-21 晚兩版 19 種寫法逐案比過，改完要再比一次。

## 2.1 拿掉變數（unset）——**小**

改法有兩種形狀（[aos-exec-s6-runit 03 § 2](../aos-exec-s6-runit/03-借形狀.md) 已提），可以只做一種：

| 形狀 | bin 版 | 測試 | C++ |
|---|---|---|---|
| (U1) JSON `.env` key 的值 `null`＝拿掉 | `json_env` 加約 3 行（`None` 就 `os.environ.pop`） | 2～3 個（拿掉、拿掉後 `${X}`＝沒設＝錯、拿掉沒設過的＝沒事） | `json_env` 同樣幾行＋同數測試 |
| (U2) `.env` 檔只有名字的一行＝拿掉 | `load_env` 把 `bad("沒有 =")` 換成驗名字＋`pop`，約 4 行 | 同上，再加「名字不合照舊是錯」 | 同 |

**要動的條文**：N-59 第 4 件「`.env` 的值」那點與「沒 `argv` 的 JSON 物件」那點（現在寫「解完不是字串靜默跳過」）、N-60 錯誤清單（U2 拿掉「沒有 =」）、bin/README 的 `.env` 格式句；決定本身記進當天的 thinking ideas。

**要先定的細縫**：拿掉 `AOS_CF`／`AOS_CD`／`AOS_CO` 算不算「自己設了、挑完不蓋」（N-59 第 4 件「挑完重設」）；拿掉 `AOS_WS`／`AOS_STACK` 後，插進去的 `aos-exec` 會重算預設值（等於換到 cwd 的工作區）。

**風險**：U2 把現在的「打錯字＝報錯」變成「打錯字＝靜靜拿掉一個變數」；而且只有名字的一行在 docker run 是「從外面帶進來」，意思正好相反（[01 § 2](01-各家做法.md)）。U1 把現在的「`null` 靜默跳過」改成有作用，但 `null` 在 JSON 本來就是「沒有」，最接近 envdir 的「空檔＝拿掉」。跟「寫什麼就做什麼」不衝突：寫了拿掉就拿掉。

## 2.2 多行值——**中**（不碰引號的前提下）

| 形狀 | bin 版 | 測試 | 風險 |
|---|---|---|---|
| (M1) heredoc：`名字<<記號` 到單獨一行 `記號`（GitHub 那種） | `load_env` 從「逐行」改成要記狀態，約 12～15 行；沒收尾＝錯、錯誤行號要報開頭那行 | 4～5 個（一般、內容有 `=`／`#`、沒收尾、記號名不合、內容裡的 `${}` 展不展開） | 新語法；`名字<<` 現在是名字不合＝錯，所以不會悄悄改到現有檔。要再定內容展不展開 `${}` |
| (M2) 值裡的 `\n` 跳脫 | 約 5 行 | 3 個 | **改到現有的值**：今天 `X=C:\new` 是照字面，加了就變換行；接著得有 `\\`，就進了跳脫字元那條路 |
| (M3) 引號內可跨行（dotenv 那種） | 要先有引號，見 2.3 | — | 同 2.3 |

**要動的條文**：N-59 第 4 件格式句、N-60（新的錯：沒收尾）、bin/README。C++ 的 `load_env` 同樣要從逐行改成有狀態。

**其實現在已經寫得出多行**：JSON `.env` key 的字串本來就能有 `\n`，也能 `{"$ref": "secrets.json#/key"}` 從別的 JSON 拿（見 [03 § 1](03-替代方案與建議.md)）。

## 2.3 引號——**大**（真的做到跟別家相容的話）

| 形狀 | bin 版 | 測試 | 風險 |
|---|---|---|---|
| (Q1) 只拿掉頭尾一對同樣的引號、裡面照字面、沒有跳脫 | 約 4 行 | 3 個 | 值本來就要以引號開頭結尾時寫不出來 → 很快就會要 `\"` → 進 Q2 |
| (Q2) 照 dotenv／compose：單引號照字面、雙引號有跳脫、引號內可跨行、引號外 `#` 是註解 | 要換成一支小解析器（逐字元、有狀態），幾十行起跳；python-dotenv 為此單獨有一個 parser 模組 | 十幾個（每種跳脫、沒收尾、引號後的雜字、單雙引號內 `${}` 展不展開…） | 跳脫字元的無底洞：哪些字元要跳、未知的跳脫怎麼辦、`$` 在哪種引號裡展開。各家答案都不一樣（[01 § 1](01-各家做法.md)），選了一家就跟其他家不相容 |
| (Q0) 不支援，但值以 `"`／`'` 開頭＝`.env 壞` | 約 2 行 | 1～2 個 | 只是把 1. 說的坑變成報錯；值真的要以引號開頭的人要改用 JSON `.env` key |

**要動的條文**：N-59 第 4 件格式句（現寫「不支援引號」）、N-60、bin/README；Q2 還要另寫一段格式規格（光是規則本身就會比現在整段 `.env` 條文長）。C++ 同樣要一支解析器，兩版一致性要逐案比。

**跟原則的關係**：Q1、Q2 都是「讓一個字元偷偷變成另一種意思」，跟 C-56「寫什麼就做什麼、照字面」正面衝突；也是 C-56「沒人需要就不加」——使用者 10-21 定 `.env` 時講的用途是 PATH 與 API key，兩者都不需要引號（值照字面、頭尾空白也原樣，本來就不必用引號保護）。
