# 1. 不改 `.env` 的替代做法（都是現行規則，不用改一行）

**先分清楚**：方向題 a 定的是 **aos-exec 本身只用標準庫、不叫外部程式替自己做事**（例如不 exec 成 `envfile` 替自己讀 `.env`）。**使用者自己在入口的 argv 裡接外部工具**是另一回事——那是入口的內容，aos-exec 照字面跑，a 不管（[aos-exec-s6-runit 01](../aos-exec-s6-runit/01-直接呼叫-環境與鎖.md) 的三種接法）。下面都是後者。

| 要的 | 做法 | 例子 | 代價 |
|---|---|---|---|
| 拿掉變數 | 入口寫成 argv 陣列，前面接 `env -u` | `"_exec": ["env", "-u", "OPENAI_API_KEY", "aos-loop", "loop.json"]` | `-u` 不是 POSIX（GNU、BSD、busybox 都有）；要拿掉的名字寫在入口裡，不在 `.env` |
| 拿掉變數 | 前面接 `s6-envdir`／`chpst -e`，放一個空檔 | `["s6-envdir", "unset", "aos-loop", "loop.json"]`，`unset/OPENAI_API_KEY` 是空檔 | 要裝 s6 或 runit（agent 資料夾多一個依賴，方向題 d） |
| 拿掉變數 | 只留白名單：`env -i`（POSIX） | `["env", "-i", "PATH=/usr/bin:/bin", "HOME=/x", "prog"]` | 整個清空，`AOS_*` 也要自己帶回來，很囉嗦 |
| 多行值 | JSON 物件的 `.env` key，字串裡 `\n` | `{".env": {"KEY": "line1\nline2"}, "_exec": [...]}` | 入口要改寫成 JSON；跳脫規則是 JSON 自己的，不是 aos 新發明 |
| 多行值 | `.env` key 用 `$ref` 從別的 JSON 拿 | `{".env": {"KEY": {"$ref": "secrets.json#/key"}}, ...}` | 同上；祕密檔可以自己 `chmod 600`（C-64） |
| 多行值 | 只傳檔名，程式自己讀（docker 官方映像的 `*_FILE` 慣例） | `.env`：`KEY_FILE=${AOS_CD}/key.pem` | 程式要配合讀檔 |
| 多行值／祕密 | envdir 一族（一個變數一個檔，s6 `-f` 整份檔就是值） | `["s6-envdir", "-f", "secrets", "prog"]` | 要裝 s6；也順便解了「一份 `.env` 沒法分權限」 |
| 引號 | 不寫引號：值照字面，頭尾空白也原樣，本來就不需要 | `GREETING=  hi there ` | 從別家抄來的檔要手動去引號（見 [02 § 1](02-aos現況與工作量.md) 的坑） |

`.env` 檔本身沒辦法接這些：它只設變數，不是一條鏈。所以替代做法都落在入口（`_exec`）那一層。

# 2. 最小可行建議（**只是建議，由使用者定**，鐵律 5）

**如果只做一項：做拿掉變數，而且先只做 (U1) JSON `.env` key 的 `null`＝拿掉。**

- 理由一：工作量最小（bin 約 3 行、測試 2～3 個、C++ 對稱），也不改 `.env` 檔的文法，現有的 `.env` 檔一個字都不受影響。
- 理由二：它補的是一個**現在完全做不到**的事——上層設了的變數（例如外面帶進來的 API key），一路往下每層疊、後讀的贏，誰都拿不掉；多行與引號則都已經有路（JSON `.env` key、照字面）。
- 理由三：`null`＝「沒有」是 JSON 本來的意思，最接近 envdir「空檔＝拿掉」，不用發明新記號；不會碰到 docker「只有名字＝帶進來」那個相反的意思。
- 要的話再加 (U2) 讓 `.env` 檔也能拿掉；那時要接受「打錯字變成靜靜拿掉」。

**順帶一個便宜的選項**（不是補功能，是補坑）：(Q0) 值以引號開頭＝`.env 壞`，約 2 行。它不讓 aos 支援引號，只是讓從別家抄來的 `X="..."` 報錯，而不是靜靜拿到帶引號的值。代價是值真要以引號開頭時得改寫在 JSON `.env` key。要不要做也是使用者定。

**不建議做的**：Q1、Q2（引號）與 M2（`\n` 跳脫）——會改到現有值的意思，也跟「照字面」衝突；做了就得一路回答跳脫字元的問題。M1（heredoc）不衝突、也不改現有檔，但現在沒有實際需要，照 C-56 先不加。

# 3. 全都不做的後果

- 拿掉變數：只能在入口的 argv 前面接 `env -u` 或 envdir 空檔（上面 § 1）。不影響現有任何東西；只是「把外面的祕密擋在某一格之外」要寫在入口、不能寫在 `.env`。
- 多行：寫在 JSON `.env` key 或改傳檔名，今天就能做。
- 引號：照字面，aos 一直如此。唯一的實際損失是**跟別家 `.env` 不相容**、而且抄錯不會報錯（[02 § 1](02-aos現況與工作量.md)）。如果 aos 的 `.env` 不打算跟 docker／dotenv 共用同一份檔，這個損失不大；打算共用的話，引號只是其中一項，`${}` 的展開規則本來就對不上（[01 § 2](01-各家做法.md)）。
