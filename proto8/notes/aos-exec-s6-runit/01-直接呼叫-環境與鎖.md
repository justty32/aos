**接法只有三種，先講清楚**（都是現行規則，不改 aos）：

- **A. argv 陣列入口**（C-73、N-61）：`_exec` 是沒 `+x` 的 JSON 陣列，aos-exec 做完 N-59 那幾件後 `exec` 它。`argv[0]` 沒 `/` 照 PATH 找（N-61「就是要有 / 才算路徑」），所以 `["s6-envdir", "secrets", "aos-loop", "loop.json"]` 直接成立；元素可放 `$env` 指示詞（N-45）。起跑 cwd＝`AOS_CD`（N-59），相對路徑從定義資料夾算。
- **B. 單子的 `argv`**（N-04、N-61）：格或 loop 的 `body` 裡 `"argv": ["s6-softlimit", "-m", "…", "python3", "brain.py"]`，由 aos-exec 行程內跑（10-22 起 inst 是 lib、沒有命令列，跟 impls 一樣），逾時與訊號照舊打整群。
- **C. 放在 aos-exec 外面**：`s6-envdir secrets aos-exec agent-x`——環境變數自然往下傳（N-55 同一個道理），`.env` 的 `${名字}` 還讀得到它設的值。換使用者**只能**用這種（見 [02 § 3](02-直接呼叫-資源fd使用者.md)）。

這些工具是「葉子程式」，C-61「資料夾程式之間互指不靠 PATH」講的是 agent 的工具，葉子程式照舊用指令名（`date` 那類），不衝突。N-59「PATH 不動」只是 aos 不替你加，裝在 `/usr/bin` 的本來就在 PATH 上；execline 那套在 Debian 不在 PATH，見 § 3。

# 1. envdir 一族：一個變數一個檔（放 API key）

**對方怎麼做。** [s6-envdir](https://skarnet.org/software/s6/s6-envdir.html) `[-I|-i] [-n] [-f] [-L] dir prog...`：`dir` 裡每個檔＝一個變數，檔名＝名字、第一行＝值（去行尾空白；NUL 變換行；只讀前 4096 bytes，`-L` 不限）；**空檔＝把這個變數拿掉**；`.` 開頭、帶 `=` 的檔名跳過；值照字面、不展開；`-i`（預設）dir 不在退 111，`-I` 不在就照跑；`-f` 整份檔當值（可多行）。runit 的 [chpst](https://smarden.org/runit/chpst.8) `-e dir` 與 daemontools 的 [envdir](https://manpages.debian.org/bookworm/daemontools/envdir.8.en.html) 規則相同（envdir 出錯退 111、否則結束碼＝子程式的）。三個都做完就 exec 成後面的 argv。

**aos 接法（A）。** 定義資料夾裡放 `secrets/`，一個 key 一個檔、各自 `chmod 600`（定義資料夾不被寫，唯讀正好）：

```
agent-x/
  _exec                 ← 沒 +x 的 JSON：["s6-envdir", "secrets", "aos-loop", "loop.json"]
  secrets/OPENAI_API_KEY   （chmod 600；內容一行）
  loop.json  fsm.json  brain.py …
```

`aos-exec agent-x` → cd 進去、讀 `.env`（若有）、exec `s6-envdir` → 設好變數 → exec `aos-loop loop.json`；pid 不變，aos-daemon 的 `adopt` 照樣認得。runit 版 `["chpst", "-e", "secrets", "aos-loop", "loop.json"]`，daemontools 版 `["envdir", "secrets", …]`。要容忍沒有 `secrets/` 就寫 `s6-envdir -I`。

**對應原則。** C-64（用檔案是為了借 Linux 權限：一個祕密一個檔、一個權限）、C-04（Linux 那邊的事交給下面那層）、C-56（不往 aos-exec 加 key）。使用者 10-21 要 `.env` 的兩個理由是 PATH 與 API key；PATH 用 `.env`（要 `${PATH}` 接舊值，envdir 不會展開），API key 用 envdir，兩邊各取所長。**現在就能用。**

**接法 C 也行**：`s6-envdir /etc/aos/secrets aos-exec --ws ws agent-x`——祕密放在定義資料夾外面、由呼叫者決定，agent 自己不知道。

# 2. setlock 一族：一個工作區同時只跑一隻

**對方怎麼做。** [s6-setlock](https://skarnet.org/software/s6/s6-setlock.html) `[-n|-N] [-t ms] [-d fd] [-r|-w] file prog...`：建檔、開寫、上鎖（預設獨占、阻塞），再 exec；`-n` 拿不到立刻退 1、`-t` 等幾毫秒；**鎖的 fd 留在 prog 裡**，prog 結束（所有拿著這個開檔的行程都關掉）鎖才放。chpst `-l`（等）／`-L`（不等）、daemontools [setlock](https://manpages.debian.org/bookworm/daemontools/setlock.8.en.html) `-n`／`-N` 同一回事。

**aos 接法（A）。** aos 沒有鎖：P-18「兩隻共用 stack 同時跑會互寫」、aos-tick「同一個 FILE 兩個人同時 tick 不管」、daemon 靠 `adopt` 認回而不是靠鎖。鎖檔要放 **stack**（每個工作區各自的），不能放定義資料夾（cwd 就是定義資料夾，`"lock"` 這樣寫會寫進去、兩個工作區跑同一個 agent 也會互相擋）：

```json
["s6-setlock", "-n", {"$env": "AOS_STACK", "$path": "lock"}, "aos-loop", "loop.json"]
```

第二隻起來時 s6-setlock 退 1 → aos-exec 是 exec 的、結束碼就是 1（N-43 透明轉交）→ 上面的 loop 看到非 0 當失敗、daemon 記 `exited`／`code: 1`。鎖的 fd 跟著 aos-loop 活；loop 起的每拍 aos-exec 是 subprocess（Python 預設 close_fds），孫子不繼承、不會把鎖帶走——鎖就是「這隻 loop 還活著」。runit：`["chpst", "-L", {"$env": …}, …]`。

**對應原則。** C-64、C-67（stack 放哪是呼叫方的自由，鎖跟著 stack 走剛好）、C-52（鎖是鏈上那支的事，aos-exec 不知道）。**現在就能用。** 要不要 aos 自己有鎖，是方向題（[04](04-不適合-衝突-方向題-套件.md)）。

# 3. execlineb 當入口檔：不用 sh 的 shell 檔

**對方怎麼做。** [execlineb](https://skarnet.org/software/execline/execlineb.html) 把整份腳本 parse 成**一條 argv** 然後 exec 它，自己不常駐；`-P` 不處理位置參數（run 腳本慣用，shebang `#!/usr/bin/execlineb -P`）；語法錯退 100。沒有變數展開，要用環境變數得 [importas](https://skarnet.org/software/execline/importas.html)（`importas -i VAR ENVVAR prog...`，把後面 argv 裡的 `${VAR}` 換掉，`-i` 沒設就退 100）。Debian／Ubuntu 的 execline 套件只把 `execlineb` 放 `/usr/bin`，其餘 52 支（`cd`、`exec`、`umask`、`envfile`、`fdmove`、`redirfd`、`importas`、`foreground`、`if`、`pipeline`、`trap`…）在 **`/usr/lib/execline/bin/`**，不在 PATH（[Debian 檔案清單](https://packages.debian.org/bookworm/amd64/execline/filelist)；execlineb 腳本裡怎麼找到它們看套件的 README.Debian，我沒裝、沒驗）。從 aos 的 argv 陣列直接叫，要寫全路徑 `/usr/lib/execline/bin/redirfd`（argv[0] 帶 `/` 且 `+x`＝直接 exec，N-61），或 `.env` 加一行 `PATH=/usr/lib/execline/bin:${PATH}`——這正是 `.env` 設計時要的用法。

**aos 接法。** 現在 demo 的 `_exec` 是 `#!/bin/sh` + `exec aos-loop loop.json`（使用者 10-19「入口與格可以是 shell 檔；不用 sh -c 拼字串的精神照舊」）。同一件事用 execlineb 寫，整份就是一條鏈、沒有 shell 在中間：

```
#!/usr/bin/execlineb -P
importas -i STACK AOS_STACK
s6-envdir -I secrets
s6-setlock -n ${STACK}/lock
aos-loop loop.json
```

（`+x`，shebang 由 kernel 處理，N-61「可執行檔內容不讀」。）

**什麼時候值得。** 只排一條直線的鏈，**argv 陣列入口已經夠了、不用裝任何東西**（上面 § 1、§ 2 的寫法）；要 `foreground { … }`、`if`、`pipeline`、`backtick` 這種有分支或管道的，才需要 execlineb。對應「少用 sh」（user 03）與 C-07（POSIX 是模型天生會的；execline 不是）。**現在就能用，但是方向題**：agent 資料夾可不可以依賴 execline（[04](04-不適合-衝突-方向題-套件.md)）。
