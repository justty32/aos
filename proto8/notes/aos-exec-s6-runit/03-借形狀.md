「借形狀」＝不裝對方、不依賴對方，aos 自己照那個樣子做（或決定不做）。每點標對應原則與「現在就能用／要改規範／方向題」。

# 1. 加旗標前的判準（chain loading 的分工）

**對方的形狀。** execline／s6／runit 每支程式只做一件事：讀自己要的幾個參數、改一下行程狀態、exec 成 argv 剩下的部分（[grammar](https://skarnet.org/software/execline/grammar.html)）。「要做什麼」寫在 argv 上、順序一目了然；沒有哪支是「什麼都會」的。

**aos 現況。** aos-exec 做 N-59 那幾件（定工作區與 stack、找入口、export 六個 `AOS_*`、cd、讀 `.env`、exec 或行程內跑單子），旗標表只有 `--ws`，N-58 說「以後可能會加新的旗標」。

**借法。** 一個判準：**新旗標若只是「改行程狀態再 exec」（換使用者、上限、鎖、umask、nice、關 fd、chroot），就不該是旗標，交給鏈上那支小程式（接法 A／B／C）；aos-exec 的旗標只留「找入口、定工作區」要用的**（`--ws`、也許將來的 `--entry`、`--stack`——它們跟六個環境變數一一對應，旗標蓋環境變數，N-58 已定的形狀）。這是 opus 對照「別把 aos-exec 養肥」的具體判準。**對應**：C-56 KISS、N-58、N-59。**方向題**（使用者定旗標表的邊界；現在沒有待加的旗標，不急）。

# 2. envdir 的「空檔＝拿掉變數」

**對方的形狀。** envdir 一族：空檔＝unset（[s6-envdir](https://skarnet.org/software/s6/s6-envdir.html)、[envdir](https://manpages.debian.org/bookworm/daemontools/envdir.8.en.html)）。execline 的 [envfile](https://skarnet.org/software/execline/envfile.html) 則「不能拿掉變數，要排除就註解掉」。

**aos 現況。** `.env` 只有「設」：`X=` 是設成空字串；一路往下每層疊上去、後讀的贏（N-59 第 4 件），上層設了下層拿不掉；`AOS_*` 也能設、風險自擔。

**借法。** 要補的話，形狀有兩種：`.env` 一行只有名字沒有 `=`（現在是錯：「沒有 =」）改成＝拿掉；或 JSON `.env` key 的值 `null`＝拿掉（現在「解完不是字串的靜默跳過」）。兩種都是**改規範**（N-59 第 4 件、N-60 的錯誤清單）。不改也有路：需要 unset 時在鏈上接 `s6-envdir`，空檔就拿掉（接法 A）。**對應**：C-56（沒人需要就不加；使用者 10-21 定 `.env` 格式時沒提 unset）。**方向題**。

# 3. envfile vs `.env`：兩份幾乎一樣的東西

**對方的形狀。** execline [envfile](https://skarnet.org/software/execline/envfile.html) `[-i|-I] file prog...`：`key = value`（等號兩邊可有空白）、`#` 註解、雙引號保留空白、C 跳脫、`\` 接下一行、**空值＝設成空字串**、**不展開變數**、大致相容 systemd 的 EnvironmentFile；語法錯退 1、檔不在退 111（`-I` 照跑）。nosh 的 `read-conf` 讀 BSD `rc.conf` 格式，同一類。

**aos 現況。** `.env`：`名字=值`、`#` 註解、不支援引號／`export `／多行、**只展開 `${名字}`**（沒設＝錯）、同名後者贏、錯只印檔名與行號不印值（N-59 第 4 件、N-60）。差別只有兩處：aos 會展開 `${}`（為了 `PATH=${AOS_CD}/bin:${PATH}`，使用者 10-21 的主因）、不收引號與跳脫。

**借法。** 不用借——aos 的版本已經是「envfile 加 `${}`」，而且比它少規則。值得記的只有：(a) 如果哪天想讓 `.env` 跟外面的工具共用（systemd EnvironmentFile、docker `--env-file`、python-dotenv），aos 的 `${}` 語意跟它們各不相同（dotenv 展開、EnvironmentFile 不展開），要選邊；(b) **aos-exec 不該 exec 成 `envfile` 替自己讀 `.env`**：會丟掉 `${}`、多一個外部依賴、讀 `.env` 的順序（旗標蓋回、一路往下每層讀）也搬不過去——跟 N-59 第 4 件衝突，見 [04 § 2](04-不適合-衝突-方向題-套件.md)。**對應**：N-59、C-56、N-18（bin 版是標準實作、純標準庫）。**方向題**（要不要相容外面的格式）。

# 4. 鎖與資源上限當單子的 key

**對方的形狀。** chpst 把鎖與上限做成旗標（`-l`／`-L`、`-m -d -o -p -f -c -t`），s6 做成兩支獨立程式。

**aos 現況。** 單子的 key：`argv`、`cwd`、`envs`、`stdin`、`stdout`、`stderr`、`*_append`、`timeout_ms`、`grace_ms`（N-04）。沒有鎖、沒有記憶體上限。

**借法。** 若要長，C-55 的成長方向是加 key：`"limits": {"mem": 1073741824, "cpu_s": 300}`、`"lock": "路徑"`——key 名照 C-54（主題在前、單位後綴）。這是**改規範**（N-04 的 key 清單、兩版實作）。但 [02 § 1](02-直接呼叫-資源fd使用者.md)、[01 § 2](01-直接呼叫-環境與鎖.md) 已示範不加 key 也做得到；C-56 最後一步減法會問「多這個 key 換到什麼」——答案是少裝一個套件、JSON 裡看得到上限。**方向題**，現在偏「不加」。

# 5. 結束碼 100／111／126／127 與「P 照 C 的碼退」

**對方的形狀。** skarnet 全家：0 成功（很少見，因為成功就 exec 走了）、**100 用法錯、111 系統呼叫失敗、126 exec 不了（非 ENOENT）、127 找不到程式**；被訊號殺＝128＋N；「P 照 C 的碼退，C ≥ 128 則 P 退 128」讓鏈可以巢狀（[exitcodes](https://skarnet.org/software/execline/exitcodes.html)）。chpst 100／111、daemontools 111。

**aos 現況。** N-43：0 正常、10 要求停、其他非 0 有錯；**aos 的程式說自己的錯一律退 1**，不另用 125～127（使用者 10-15「結束碼不要太依賴」）；透明轉交（exec 之後碼就是入口的）；128＋N。10-22 起錯誤一行加代號（`aos-exec: EntryMissing 原因`），種類寫在 stderr 的字裡、不寫在碼裡。

**借法。** 兩邊「鏈可以巢狀、碼透明往上」是同一個形狀，aos 已經有。aos 刻意不分 100／111／126／127：種類在 stderr 的代號裡（C-54 CamelCase），碼只分 0／10／其他。唯一要知道的：鏈上的 s6／runit 工具在 exec 之前失敗，aos-loop 看到的是 100／111／127 這種「其他非 0」＝失敗、loop 以那個碼結束——合 N-43、C-53（下層的錯不轉述）；不會被誤認成 10。**不借；現況即可。**

# 6. servicedir：「一個 key 一個檔」的資料夾

**對方的形狀。** s6 的 [servicedir](https://skarnet.org/software/s6/servicedir.html)：`run`、`finish`、`notification-fd`（一個數字）、`down`（存在＝預設不起）、`down-signal`、`timeout-kill`、`timeout-finish`、`lock-fd`、`nosetsid`、`log/`——每個設定是一個小檔、檔名＝key、內容＝值、存在與否也是值；runit 的 servicedir、daemontools 一樣。execline 的腳本同樣「一個檔＝一條 argv」。

**aos 現況。** 資料夾＝程式（C-68）、資料夾與 JSON 互通（C-51：資料夾＝object、檔名＝key）、入口 `_exec` 一層、`.env` 一檔、其餘設定塞 JSON（loop.json、fsm.json、單子）。

**借法。** 形狀已經一樣，只是 s6 把「所有 key 都是檔」做到底、aos 把大部分 key 放進 JSON。值得記的是：單子或 loop 的 key 日後要長（§ 4 的 `limits`、`lock`，或 opus 對照提的 `down-signal`／`timeout-kill`），**都有「資料夾裡一個檔」這個選項**，而且那樣就能各自設 Linux 權限（C-64）——例如 `secrets/` 本來就是這個形狀。使用者 10-15 說互通「建議不要濫用」（C-51），所以只記著、不建議現在改。**對應**：C-51、C-68、C-72。**方向題**。
