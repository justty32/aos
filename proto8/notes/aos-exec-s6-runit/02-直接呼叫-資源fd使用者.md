# 1. softlimit 一族：記憶體、CPU、檔案數上限

**對方怎麼做。** [s6-softlimit](https://skarnet.org/software/s6/s6-softlimit.html) `[-H|-h] [-a allmem] [-c core] [-d data] [-f fsize] [-l lock] [-m mem] [-o ofiles] [-P prio] [-p proc] [-r res] [-s stack] [-t cpusecs] prog...`：設軟限制（setrlimit）再 exec；`-m` 一次設所有記憶體類；`=` 表示設成硬限制；`-H` 連硬限制一起改（要 root）。chpst 的 `-m -d -o -p -f -c -t` 同一組（超過 CPU 時間收到 SIGXCPU）；daemontools `softlimit` 是原版。

**aos 接法（B）。** 單子只有 `timeout_ms`（牆上時間）與 `grace_ms`，沒有記憶體上限；think 格叫 LLM、act 格跑工具，吃爆記憶體的是這兩種。放在格的 `argv` 前面，兩種上限並存（`timeout_ms` 牆上秒、`-t` CPU 秒）：

```json
"think": {"val": "fsm.json#/states/think/body",
          "body": {"argv": ["s6-softlimit", "-m", "1073741824", "-t", "300", "python3", "brain.py"],
                   "stdout": {"$env": "AOS_STACK", "$path": "plan"},
                   "timeout_ms": 120000},
          "next": "act"}
```

aos-exec 行程內跑這張單子、開一個新行程群組、exec `s6-softlimit` → 它 exec `python3`；逾時 killpg 照樣打到（同一群，softlimit 不換群）。**對應原則**：C-56（不加 `limits` key）、C-04。**現在就能用。** 要不要讓單子自己長出 `limits`（C-55 值的雙形）是「要改規範」，見 [03 § 4](03-借形狀.md)。

# 2. redirfd、fdmove、fdclose、umask、cd：動 fd 與行程狀態

**對方怎麼做。** execline：[redirfd](https://skarnet.org/software/execline/redirfd.html) `-r|-w|-u|-a|-x [-n] [-b] fd file prog...`（`-a` 附加、`-x` 不存在才建）；[fdmove](https://skarnet.org/software/execline/fdmove.html) `[-c] fdto fdfrom prog...`（搬或複製 fd）；`fdclose fd`；[umask](https://skarnet.org/software/execline/umask.html) `mask prog...`；[cd](https://skarnet.org/software/execline/execline-cd.html) `dir prog...`。chpst 有 `-0 -1 -2`（關掉 stdin／stdout／stderr）、`-C pwd`、`-/ root`（chroot）、`-n nice`、`-b argv0`。

**aos 接法。** 單子已經有 `stdin`／`stdout`／`stderr`／`*_append`／`cwd`（N-04），這些**不需要**。缺口在兩處：
- **argv 陣列入口**（沒有單子那些 key）要重導：`["/usr/lib/execline/bin/redirfd", "-a", "1", {"$env": "AOS_STACK", "$path": "out.log"}, "python3", "act.py"]`；比起把入口改寫成單子，多一支程式、少一層 JSON，兩種都合規、看哪個順手。
- **fd 3 以上、關掉一個串流、umask、nice**：單子表達不了「關掉 stdin」（`/dev/null` 可以、關掉不行；「沒寫的串流就是接呼叫者的」，C-56 寫什麼就做什麼）；要關就 `fdclose 0 …` 或 `chpst -0`。`umask 077` 讓 stack 裡的檔預設只有自己讀得到——跟 C-64 同路。

**對應原則**：C-56、N-04（單子不認的 key 別人可讀，但這裡連 key 都不用加）。**現在就能用**（execline 要全路徑或 `.env` 加 PATH，[01 § 3](01-直接呼叫-環境與鎖.md)）。

# 3. setuidgid 一族：換使用者——要放在 aos-exec 外面

**對方怎麼做。** [s6-setuidgid](https://skarnet.org/software/s6/s6-setuidgid.html) `account prog...`（只有 root 能用；`uid:gid` 或帳號名；設 uid、gid、補充群組，帳號不存在退 1）；[s6-applyuidgid](https://skarnet.org/software/s6/s6-applyuidgid.html) `-u -g -G -U -z`（`-U` 從 `UID`／`GID`／`GIDLIST` 環境變數拿）配 [s6-envuidgid](https://skarnet.org/software/s6/s6-envuidgid.html)（只查帳號、把三個變數設進環境，不換身分）；chpst `-u [:]user[:group]`（`-U` 是 envuidgid）；daemontools `setuidgid`、`envuidgid`。

**aos 接法——順序是坑。** 直覺寫法 `_exec = ["s6-setuidgid", "agent", "aos-loop", "loop.json"]` 以 root 跑 `aos-exec agent-x` 會壞：aos-exec **第 1 件事**就用當下的身分（root）建好 `$AOS_STACK`（N-59 第 1 件），然後才 exec 入口換成 `agent`；之後 loop／fsm 寫 `state`、`trace.jsonl` 進 stack 全部 EACCES。**解法是接法 C，換身分在 aos-exec 之前**：

```
s6-setuidgid agent aos-exec --ws /srv/ws/x agent-x        # 整條鏈都是 agent
```

daemon 要「一個子項一個使用者」也一樣：子項的 `body.argv` 寫 `["s6-setuidgid", "bob", "aos-exec", "--ws", {"$env": "AOS_WS", "$path": "bob"}, "../agent-bob"]`，daemon 本身以 root 跑。`s6-envuidgid` 那種「只設變數不換身分」的可以在任何位置。

**對應原則**：C-64（使用者 10-16 原話「讓kernel成為某daemon的ctl/清單的唯一可讀寫者」——真要做到就是每隻 agent 一個 Linux 使用者，這條鏈是最短路）、C-04、C-52（aos-exec 不知道上面換過身分）。**現在就能用**，但「要不要走這條路（整棵樹由 root 起）」是**方向題**（[04](04-不適合-衝突-方向題-套件.md)）。

# 4. setsid、pgrphack、fghack：只能在最外層

**對方怎麼做。** [s6-setsid](https://skarnet.org/software/s6/s6-setsid.html) `[-s|-b|-f|-g] [-i|-I|-q] prog...`（`-s` 新 session、`-b` 新行程群組；失敗預設警告照跑）；chpst `-P`、daemontools `pgrphack`＝新行程群組；`fghack`／`s6-fghack` 是讓會自己 fork 到背景的程式留在前台的 hack。

**aos 接法。** aos 的逾時與訊號都靠行程群組：單子由 aos-exec 開新群、逾時 killpg（P-36）；daemon 收子項 SIGTERM／SIGKILL 整群；N-41「格自己不 setsid／fork 背景行程」。**在格或單子裡接 `s6-setsid`／`chpst -P` 會讓子程式逃出那一群**——逾時與訊號打不到、孫程式變孤兒，這是跟 N-41、P-36 直接衝突。只有一個地方能用：最外層、上面沒有任何 aos 的 loop／fsm／daemon 時，例如從終端機手動 `s6-setsid aos-exec agent-x` 讓它脫離終端機。**只可參考、別放進格裡。** `fghack` 對 aos 沒用（aos 的格本來就該前台跑完）。

# 5. chpst 一支抵全部（runit）

[chpst](https://smarden.org/runit/chpst.8) `[-vVP012] [-u user] [-U user] [-b argv0] [-e dir] [-/ root] [-C pwd] [-n inc] [-l|-L lock] [-m bytes] [-d bytes] [-o n] [-p n] [-f bytes] [-c bytes] [-t seconds] prog`：上面 § 1～§ 4 的事一支做完，自己的錯退 100（用法）／111（改不了狀態），否則結束碼＝prog 的；以 `envdir`、`setuidgid`、`setlock`、`softlimit`、`pgrphack`、`envuidgid` 這些名字呼叫時模擬 daemontools 原版（Debian 的 runit 套件沒裝那些別名）。一行示範（接法 A）：

```json
["chpst", "-e", "secrets", "-L", {"$env": "AOS_STACK", "$path": "lock"}, "-m", "1073741824", "aos-loop", "loop.json"]
```

**s6 vs runit 怎麼選**：s6 一件事一支、名字都帶 `s6-` 不撞名、文件最細、`-I`／`-t` 這類選項多；runit 只要記 chpst 一支、裝一個套件；daemontools 原版最老（公共領域）、功能最少。三個在 Debian／Ubuntu 都在 universe／main，見 [04 § 4](04-不適合-衝突-方向題-套件.md)。
