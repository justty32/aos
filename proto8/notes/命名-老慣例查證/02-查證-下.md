# 查證：頂層憑記憶講的八條（下）

每條：頂層講的（標題）→ 查證結果（【對】／【部分對】／【錯】）→ 原文（逐字）與出處 → 對使用者方法的哪一步。R 編號見 [C-54 命名方法](../../docs/CONCEPTS/01-設計理念/C-54-命名方法.md)；「問 N」是 artifact 拍板題的編號，10-23 晚都已定（見 [thinking](../../thinking/2026-10-23-naming-method.md)）。

### 單位後綴（`timeout_ms`、`_us`、`_ns`；systemd `TimeoutStartUSec`）
- 【對】
- > Properties exposing time values are usually encoded in microseconds (μs) on the bus, even if their corresponding settings in the unit files are in seconds.
（介面列有 `readonly t TimeoutStartUSec`）（[org.freedesktop.systemd1(5)](https://www.freedesktop.org/software/systemd/man/latest/org.freedesktop.systemd1.html)）

  > The former typically are suffixed with "…Sec" to indicate the default unit of seconds, the latter are typically suffixed with "…USec" to indicate the underlying low-level time unit
（[systemd.time(7)](https://www.freedesktop.org/software/systemd/man/latest/systemd.time.html)）

  > Quantities with a clear unit of measurement (such as bytes, miles, and so on) must include the unit of measurement as the suffix.
／
  > abbreviations should not be pluralized (for example, distance_km rather than distance_kilometers)
（[Google AIP-141](https://google.aip.dev/141)）

  kernel 的 `udelay(unsigned long usec)`、`ndelay(unsigned long nsec)` 也是（（[kernel timers](https://www.kernel.org/doc/html/latest/timers/delay_sleep_functions.html)））。最明文的其實是 Google 的 API 規範 AIP-141／142，不是 kernel。
- ＝5c「單位後綴」（R6）。`_ms`、`_ticks` 完全合。

### kernel 計數用 `nr_`（`nr_pages`），index 用 `idx`／`i`
- 【部分對】（沒有明文，只有原始碼）
- `#define NR_CPUS CONFIG_NR_CPUS`（（[threads.h](https://github.com/torvalds/linux/blob/master/include/linux/threads.h)））、`int nr_threads;`（（[fork.c](https://github.com/torvalds/linux/blob/master/kernel/fork.c)））、`unsigned long nr_pages`（（[mm.h](https://github.com/torvalds/linux/blob/master/include/linux/mm.h)））；Linux 0.01（1991）就有 `#define NR_TASKS 64`。

  記錯的：kernel 文件**沒有明文**規定 `nr_`；它也不是 Unix V6／V7 傳下來的（V7 用 `NPROC`、`NINODE` 這種 `N` 前綴），比較像從 MINIX 來的，但沒查到一手證據。Google AIP-141 反過來規定用 `_count` 後綴、不用 `num_` 前綴。
- 你定了：不用 `nr_`（「現在這東西不太常見了」），留「被數的東西加 s」。〔10-25 你再改：「計數這塊，幫我改成counter_*」——計數改叫 `counter_<被數的東西>`〕`i`／`idx` 是區域變數的短名，見問 3。

### Unix 時間傳統是 epoch 秒（`time_t`）；`created_at`／`updated_at` 是 Rails 帶起來的
- 【對】（Rails 是「普及」不是「起源」）
- > time() returns the time as the number of seconds since the Epoch, 1970-01-01 00:00:00 +0000 (UTC).
（[time(2)](https://man7.org/linux/man-pages/man2/time.2.html)）

  > created_at - Automatically gets set to the current date and time when the record is first created.
（[Rails Guides](https://guides.rubyonrails.org/active_record_basics.html)）

  > Active Record automatically timestamps create and update operations if the table has fields named created_at/created_on or updated_at/updated_on.
（[Rails API](https://api.rubyonrails.org/classes/ActiveRecord/Timestamp.html)）

  補一點：現代 `struct stat` 的欄位是 `st_mtim`（timespec），`st_mtime` 是巨集展開成 `st_mtim.tv_sec`。「起源於 Rails」找不到出處，只能說 Rails 普及了它。
- ＝5c「啥時候」。ISO 跟 epoch 是正面衝突，見問 7；`_at` 後綴見問 1。

### Ken Thompson：重來一次會「把 creat 補上那個 e」
- 【對】（場合記錯）
- > It was a question I asked him, while Brian Kernighan and I were writing the Unix Programming Environment. His actual response was pithier (as one would expect): "I'd spell creat with an 'e'".
（[Rob Pike，TUHS 郵件列表 2020-02-08](https://www.tuhs.org/pipermail/tuhs/2020-February/020337.html)）

  > open, create, close – open a file for reading or writing, create file
（[Plan 9 open(2)](https://9p.io/magic/man2html/2/open)）（Plan 9 真的補上了 e）

  > Whatever regret Ken has for quirky contractions like creat and cron is fully compensated by grep
（[McIlroy，;login: 2016](https://www.usenix.net/system/files/login/articles/login_spring16_05_mcilroy.pdf)）

  記錯的：不是「公開訪談」，是 Pike 寫《The UNIX Programming Environment》（1984）時親口問的。
- R5 縮寫門檻的反面教材：刪母音式縮寫省一個字母、被講四十年。
