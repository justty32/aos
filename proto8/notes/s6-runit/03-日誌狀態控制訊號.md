# 6. 日誌

**s6／runit 怎麼做。** 服務資料夾裡放一個 `log/` 子服務，服務的 stdout 經管道接到 logger 的 stdin；管道由上層（s6-svscan／runsv）拿著，所以服務或 logger 任一邊重起都不掉 log（[s6-svscan](https://skarnet.org/software/s6/s6-svscan.html)、[runsv(8)](https://smarden.org/runit/runsv.8)）。logger（s6-log、svlogd）把一行行寫進 `current`，到大小就改名成 `@時間戳.s`、開新的 `current`，只留 n 份舊的（預設 10）；svlogd 在磁碟滿時刪到剩 N 份讓寫入繼續（[s6-log](https://skarnet.org/software/s6/s6-log.html)、[svlogd(8)](https://smarden.org/runit/svlogd.8)）。

**aos 怎麼做。** aos-daemon 丟掉子 loop 的 stdout、stderr 附加到小格的 `stderr` 檔，不輪替（[bin README](../../bin/README.md)）。N-28 的條文寫的是「子 loop 的輸出檔不無限長」「stderr 只在出錯時 append」，輪替列為完整實作（10-22 前叫標準實作）待補（N-28 已自註 bin 版還沒做）。〔10-22 註：N-28 已照程式改寫成「aos 不保證子項輸出不無限長、使用者自己承擔」，見 [NORMS/04](../../NORMS/04-基礎設施-loop與daemon.md)。10-22 使用者再改：輪替、選填路徑、清舊小格從規範拿掉、不是待補，要的話自己接 s6-log／svlogd 等工具；下面「要補輪替時」只當接工具時的參考。〕

**可借鏡。** 要補輪替時，s6-log／svlogd 的形狀可以直接抄：`current` 一份、滿了改名成帶時間的舊檔、留 n 份——全是「先寫再改名」的檔案操作，跟 N-05 同路。另一條路是不自己寫：讓小格的 stderr 交給一支現成 logger，但那要 daemon 多拿一條管道，機制變多。

**aos 刻意不同的地方。** s6 用管道＋常駐 logger；aos 直接 append 到檔（C-64），服務重起時不會有「管道斷了掉 log」的問題，代價是檔會一直長。

# 7. 狀態檔

**s6／runit 怎麼做。** s6：`supervise/status`（二進位），用 `s6-svstat` 讀；狀態變化經 `event/` fifodir 通知，想等的人不用輪詢（[servicedir](https://skarnet.org/software/s6/servicedir.html)）。runit：`supervise/status`（二進位，相容 daemontools）、外加給人看的 `stat`、`pid` 兩個純文字檔（[runsv(8)](https://smarden.org/runit/runsv.8)）。

**aos 怎麼做。** state 窗是 JSON，先寫 `.` 開頭暫存檔再改名（N-05）：`state`、`lap`、`max`、`paused`、`ctl_seq`、`last_warning`、`pid`、`started`（/proc 的啟動時間）、`boot_id`、`beat`；daemon 多 `children`；fsm 另有 `trace.jsonl` 一拍一行（[bin README](../../bin/README.md)、N-32）。

**可借鏡。** runit 的 `pid`、`stat` 是「`cat` 一下就懂」；aos 的 JSON 給 AI 讀（C-07）也已經夠直白。真正少的是「等狀態變化不輪詢」——目前讀 state 只能定時看；需要時再說。

**aos 刻意不同的地方。** aos 存 `started`＋`boot_id`，pid 被重用、開機過都認得出來，比 s6／runit 只存 pid 多一層保險——這是 `adopt` 要用的。

# 8. 控制

**s6／runit 怎麼做。** 指令式：往 `supervise/control` 這條具名管道寫一個字母＝一個指令（`u` 起、`d` 停、`o` 跑一次、`x` 監工結束、`p`／`c` 暫停繼續、其餘字母送對應的訊號）（[s6-svc](https://skarnet.org/software/s6/s6-svc.html)、[runsv(8)](https://smarden.org/runit/runsv.8)）。runit 還能放 `control/<字母>` 腳本，自訂「收到這個字母怎麼做」。s6 另有 `down-signal`（停服務用哪個訊號，預設 TERM）、`timeout-kill`（停不下來多久後 SIGKILL，預設永不）兩個小檔（[servicedir](https://skarnet.org/software/s6/servicedir.html)）。

**aos 怎麼做。** 期望式：ctl.json 寫「我要的整份樣子」（N-06），loop 每圈讀一次，認 `paused`、`stop`、`max`、`interval_ms`、`seq`，daemon 多認 `children`；讀到壞的維持上一份好的、寫進 `last_warning`；`seq` 會回音成 state 的 `ctl_seq`，寫的人可以看它知道生效了沒。daemon 收子項固定 SIGTERM、等 10 秒、SIGKILL 整群。

**可借鏡。** ①**停子項用哪個訊號、等多久**：aos-daemon 是寫死的；s6 用兩個小檔讓每個服務自己說。如果將來有子項要 SIGINT 才收得乾淨，這是現成的形狀（在 aos 會是子項 loop 設定裡的兩個 key）。②aos 的 `seq`／`ctl_seq` 對上 `s6-svc -w…`「送了指令、等到生效」——aos 已經有，而且是用檔案做到的。

**aos 刻意不同的地方。** aos 原本也有指令式（N-10，放 `名字.json` 一問一答），使用者 10-16 刪掉、改成期望式。期望式重送無害、當掉重起後還在；代價是要輪詢，生效最多慢一圈（暫停時每秒看一次）。

# 9. 訊號

**s6／runit 怎麼做。** s6-supervise：TERM＝把服務停掉再自己結束；INT＝轉給服務的行程群組後自己立刻結束；**QUIT＝自己結束、服務不動**（[s6-supervise](https://skarnet.org/software/s6/s6-supervise.html)）。runsv：TERM＝當作收到 `x`（[runsv(8)](https://smarden.org/runit/runsv.8)）。s6-svscan：TERM 收掉整棵樹、等 logger 寫完才走（不掉 log）。

**aos 怎麼做。** aos-loop／aos-fsm：INT／TERM／HUP 都轉給正在跑的那拍、等它結束、以 128＋N 結束（P-36、N-43）；aos-daemon：先收掉所有子項、寫好 state，再 128＋N。

**可借鏡。** s6 的「QUIT＝只有監工走、服務留著」對上 aos 的 `adopt`：現在 aos-daemon 只有被 SIGKILL、當掉時才留得下子項給下一個 daemon 接回；想「換 daemon 版本而不停子 loop」的話，s6 的做法是一個訊號的差別。要不要這樣用是方向題，留給使用者。

**aos 刻意不同的地方。** aos 三個訊號一視同仁、一律收乾淨再 128＋N（使用者 10-19「SIGINT 比照 SIGTERM」），比 s6 少分幾種情況，合 C-56。
