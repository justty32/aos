## 定了的（續）：10-14 夜動工時的細則（原待定 h）

10-14 夜重做 inst／loop／daemon 時，代理人遇到規範沒寫清楚的地方，照 N-18 挑最簡單的先做、記成待定 h1～h16；**使用者 10-14 深夜拍板「全照建議」**（[thinking 14](../thinking/2026-10-14-json-entry/14-h拍板.md)）。跨程式的約定落成下面的條文；只跟 daemon 實作有關的（h10～h14）寫在 [lib daemon.md](../lib/daemon.md) 當實作說明；h9 補進 [N-28](05-命令列與daemon-N21至N28.md)；h1、h2 補進 N-21、N-22。全部是**草稿**。

- **N-29**（原 h3，草稿）stderr 的 JSON 形狀：錯誤一份 `{"error": {"code", "msg"}}`（同 N-10 回覆的 error），警告一份 `{"warning": {"code", "msg"}}`，一份一行。stdin 有多份 JSON 而程式只要一份時，只看第一份、警告 `ExtraInput`。（10-14 深夜）
- **N-30**（原 h4、h5，草稿）aos-inst 的結果（stdout 那一份）帶 `id`、`code`、`signal`：`code`＝子程式的碼，被訊號停掉＝128＋N（同 exit 檔），訊號號碼另放 `signal`。`id` 沒寫＝TARGET 的 `realpath#/位置`；設定從 stdin 來又沒寫才是 null。**`exit` 是選填**（exit 檔只是與舊時代的橋樑，暫定 e）：要子程式的碼，讀這份結果的 `code`。（10-14 深夜）
- **N-31**（原 h6，草稿）loop／daemon 的 stdout：每真的跑了一次 inst 吐一份 `{run, code, ms}`（daemon 沒 inst 就不吐），結束時吐一份總結，`end`＝最後狀態字串（`"done"`／`"stopped"`）。（10-14 深夜）
- **N-32**（原 h7，補 N-17，草稿）心跳間隔 1 秒（不開 key）；state 加 `started`（Linux＝/proc/<pid>/stat 第 22 欄）、`boot_id`、`beat`（寫的那一刻，epoch 秒），非 Linux 是 null。（10-14 深夜）
- **N-33**（原 h8，補 N-14 的 seq，草稿）ctl 的 `seq`：寫 ctl 的人自己帶，選填非負整數；沒帶＝state 的 `ctl_seq` 是 null；舊的 `ctl_mtime` 回音拿掉。daemon 寫子 loop 的 ctl 時把 seq 加一。（10-14 深夜）
- **N-34**（原 h16，草稿）tasks（proto8-1 的 aos-seq／par／if／not）：起子 aos-inst 時接它的 stdout，讀那份結果的 `code` 當子程式的碼，不靠 exit 檔，所以 inst 不必寫 `exit`；子 aos-inst 的結果不漏進 tasks 自己的 stdout。tasks 與 aos-tick 自己的 stdout 不吐東西（空的 JSON 串流，結果就是退出碼，N-12「不強制」最簡單的合規），自己的錯誤照 N-29 吐 JSON。（10-14 深夜，使用者把原 h16「讀 exit 檔」改成讀 stdout）
