# 基礎設施／指示詞

（10-19 整份重寫：舊命令列的語法糖〔TARGET、旗標、`--`〕新程式沒有，條號作廢；aos 的命令列只有 [N-58](10-基礎設施-定義與工作區.md) 的 `aos-exec [旗標...] XXX [args...]`（10-21 改：aos-exec 收旗標、`--` 結束旗標，目前只有 `--ws`，原 `aos-exec XXX [WS [args...]]`，[ideas 10-21](../thinking/2026-10-21-ideas.md)）——`proto8/bin` 版另有 `aos-inst FILE [args...]`，impls 線不提供 aos-inst 命令列（使用者 10-19 晚，[ideas § 20](../thinking/2026-10-19-ideas.md)）。10-22 使用者改：bin 版的 `aos-inst` 也刪了（[ideas 10-22](../thinking/2026-10-22-ideas.md)），兩版都只有 aos-exec 這條〔10-23 起只剩 impls 一版〕。舊的 `檔#/位置` 10-19 下班前以 `#/` 尋址的樣子回來了，只用在 aos-exec 的入口路徑，見 [N-62](10-基礎設施-定義與工作區.md)。）

- **N-45**（10-15 深夜定，10-16 夜改，10-19 改，10-19 晚改，10-20 改，10-21 傍晚改，10-23 改，草稿；[CONVENTION P-31](../CONVENTION.md)）**指示詞有兩個：`$env` 與 `$ref`，都可帶修飾欄 `$path`、`$prefix`**（10-20 改，原「`$env`（可帶 `path`）與 `$ref`」）（10-19 晚使用者定保留 `$ref`：「impls這塊，指示詞是OK的」，[ideas § 22](../thinking/2026-10-19-ideas.md)）。指示詞＝單子裡任何位置、帶 `$ref` 或 `$env` key 的物件，**整個物件換成它指到的值**；一個物件同時寫了 `$ref` 與 `$env` 只看 `$ref`，物件裡其餘 key 忽略。10-20 改（原「帶 `$` 開頭 key 的物件」「不認得的 `$xxx`＝錯」）：使用者「在解析json時，他會嘗試找到所有$ref/$env，並進行相應替換，替換失敗就原封不動放著。關於找到$ref/$env後，他們所在的那個obj value，就會被替換，至於那個obj value裡面的其他東西，就不管。」「一些該報錯的還是要報錯：環境變數沒設、讀不到檔、指不到、繞圈。主要是json格式這塊，指示詞機制很寬容」（[ideas](../thinking/2026-10-20-ideas.md) D12～D15）。所以錯分兩類：
  - **真的解不開＝錯**：環境變數沒設、`$ref` 的檔讀不到（不是 JSON 也算）、指標指不到、繞圈——解單子那一層自己的錯，退 1（bin 版是 aos-inst 的錯〔10-22 使用者改：aos-inst 命令列刪了，bin 版也是 aos-exec 行程內解單子時的錯，原因開頭 `單子跑不起來`〕；impls 是 aos-exec 行程內解單子時的錯，代號 `DirectiveBad`；10-23 起 bin 也帶同一個代號〔之後 bin 版刪了，只剩 impls〕）。
  - **寫法（格式）寬容、不報錯**：不認得的 `$xxx`（含還沒定的 `$fmt`）與其餘 key 不管；`$path`、`$prefix` 不是字串（也不是 `null`）＝當沒寫〔原另有「`$at` 不合＝當沒寫」，10-23 刪 `$at`〕；`$ref`／`$env` 的值不是字串或空字串、`#` 後不是 `/`、只有 `#/…` 沒檔名＝換不了，**整個物件原封不動留著**（有 `$ref` 時不改試 `$env`；頂層自定，待使用者確認）。留下來的物件若在 argv 裡，解完不是字串，照 argv 的規則算單子壞／入口壞——那是 argv 的規則，不是指示詞的錯。
  - **`$path`、`$prefix`**（10-20 使用者：「我希望那個path可以換成$path，然後添加$prefix」「兩種都能用。如果換出來的不是字串，那也不報錯，就靜默失效。」，[ideas](../thinking/2026-10-20-ideas.md) D9～D11）：換出來的值是字串時，先照 `$path` 接上去，再在前面加 `$prefix`：`{"$env": "AOS_WS", "$path": "a.txt", "$prefix": "--file="}` → `"--file=/ws/a.txt"`。**`$path` 是字串拼接**（10-21 傍晚改，原「`os.path.join`；`$path` 寫絕對路徑就是絕對路徑」；使用者「$path/$prefix就只是單純的字串拼接，頂多處理一下/，所以$path也可以透過$path:"#/loops/a"，來取代$at？」→ 頂層給 (a) 留 `$path`、`#` 開頭直接接、其他中間補剛好一個 `/`，(b) `$prefix`／`$suffix` 純拼接 → 「a」，[ideas 10-21 § 9](../thinking/2026-10-21-ideas.md#9-設定檔是唯一的位置參數path-改字串拼接10-21-傍晚) H6）：`$path` 以 `#` 開頭＝直接接在後面（`{"$env": "AOS_CF", "$path": "#/loops/a"}` → `"/x/big.json#/loops/a"`，大 JSON 裡的設定指回自己那一格就這樣寫）；其他＝去掉基底結尾的 `/`、去掉 `$path` 開頭的 `/`，中間剛好一個 `/`（`a.txt`、`/a.txt` 都是 `/ws/a.txt`；**寫絕對路徑不再整個取代**）；`$path` 是空字串、不帶或 `null`＝不接；基底是空字串或 `/`＝接成 `/a`（頂層自定，ideas 10-21 § 9.3 第 8 點）。`$at` 不做（`$path: "#/…"` 取代）〔10-23 統合（[thinking](../thinking/2026-10-23-naming.md)）：這句說的是 `$env` 不另開取位置的 `$at`、照舊用 `$path: "#/…"` 拼指標；`$ref` 原本的 `at` 改名 `$at`（修飾詞都帶 `$`），只給 `$ref` 用〕〔10-23 晚 `$ref` 的 `$at` 也刪了（使用者「把$at刪掉，就都只認#/。」），兩者不再重疊；下面這句原話照留〕。使用者留意：`$path` 與 `$ref` 的 `$at` 日後可能統一成一個名字，現在先這樣（「只是哪天搞不好我又會覺得$path和$at的功能有所重疊，然後統一成一個名字。不過現在先這樣」）——兩者不同：`$at` 是「取那份檔裡那段內容換進來」，`$path: "#/…"` 只是「拼出指標字串」。`$env`、`$ref` 都能帶；換出來不是字串，兩欄靜默不作用、值原樣換進來。**舊寫法 `path` 不再有作用**（改名後是普通 key，照上面「其餘 key 不管」）。`$fmt` 使用者「先等等，fmt先不動」，未定。
  - **`$env`**：`{"$env": 名, "$path": 子路徑}` 換成該環境變數底下的路徑（照上面 `$path` 的字串拼接接上去，10-21 傍晚改，原「照 `os.path.join` 接；`$path` 寫絕對路徑就是絕對路徑」；不帶 `$path`（或 `null`）就是整個變數值；10-20 改：原寫 `path`，「`path` 不是字串＝錯」改成當沒寫，見上）。`$env` 讀的是**執行當下的環境**，像 shell 的 `$HOME`——同一份單子在不同環境下指到不同地方，所以可以當正式機制。變數沒設＝解單子那一層自己的錯，退 1（同上「真的解不開」；10-20 照舊）。`$env` 在 aos-exec 設好六個環境變數（10-21 晚加 `AOS_CO`）之後才解，所以單子裡讀得到 `AOS_STACK`、`AOS_CF`、`AOS_CD`（N-57）。
  - **`$ref`**（語意原照 impls 的 aos-directive 庫，`proto8/impls/aos-directive/README.md`；impls 是使用者的檔、10-23 起進 git。10-20 起 bin 版先做了 `#/`、`$at`、`$path`、`$prefix` 與寫法寬容，**現行以 bin 版為準**，impls 10-21 已對齊〔10-23 起 bin 版刪了，現行就是 impls 的 aos-directive〕）：`{"$ref": "檔"}` 換成**那份 JSON 檔的整份內容**，換進來的值**接著解**（裡面的 `$ref`／`$env` 也解）。相對檔名從**寫著這個 `$ref` 的那份檔所在的資料夾**算：單子本身是入口時＝入口檔所在的資料夾（`AOS_CD`）；被 `$ref` 進來的檔若是捷徑，解開捷徑、從它實際指向的檔所在的資料夾算（使用者 10-17 定）；loop／fsm 設定裡內嵌的單子＝那份設定檔所在的資料夾。**可以取檔內的位置，只認 `#/`**（10-20 改，原「只收整份檔、不收 `#`（`檔#/位置` ＝錯；跟入口路徑的 `#/` 尋址 N-62 是兩套、規則不同）」；10-23 改，原「兩種寫法都收」——另一種是修飾詞 `$at`〔10-23 前叫 `at`〕，兩個都寫時 `$at` 接在 `#/` 的指標後面，10-20 使用者，見 [ideas](../thinking/2026-10-20-ideas.md) D1、D7；10-23 頂層問 `$ref` 陣列遇到 `$at` 怎麼接時，使用者「把$at刪掉，就都只認#/。」）：`{"$ref": "x.json#/a/b"}` 換成 `x.json` 裡 `/a/b` 那個值（JSON pointer，寫法同 N-62：第一個 `#` 就切、`#` 後面一定要 `/`）。寫了 `$at` 是不認得的 `$xxx`、不管（`{"$ref": "x.json", "$at": "/a/b"}` 換成整份 `x.json`）。指標取的是那份檔的原文（不穿過檔裡的 `$ref`），取到的值再接著解。`$ref` 指回正在解的鏈上的同一個位置（檔＋指標，繞圈）、檔讀不到（**指到資料夾也算讀不到**：不走進去找入口、不把資料夾組成物件；10-21 傍晚使用者「對了，$ref如果指向的是資料夾？」「那還是維持報錯吧」，[ideas 10-21 § 9](../thinking/2026-10-21-ideas.md#9-設定檔是唯一的位置參數path-改字串拼接10-21-傍晚) H8）、不是 JSON、指不到＝錯，一樣是解單子那一層自己的錯、退 1；`#` 後不是 `/`、值不是字串或空字串、只有 `#/…` 沒寫檔名＝物件原封不動留著（10-20 改，原這幾種也＝錯，見上「寫法寬容」）。物件有 `$ref` 就只看 `$ref`、`$path`、`$prefix`，其餘 key（含 `$env`、`$at`、舊的 `path`、不認得的 `$xxx`）不管（10-20 改，原「只看 `$ref` 與 `at`……不認得的 `$xxx`＝錯」〔10-23 統合改名：`at` → `$at`，[thinking](../thinking/2026-10-23-naming.md)；同日再刪 `$at`〕）。
  - **`$ref` 可以寫成陣列＝幾份照順序合成一份**（10-23 使用者；只改 C++ 版 `proto8/impls` 的 aos-directive）：頂層問 daemon 的 `loops` 要拆成好幾份檔怎麼寫時，使用者：「等一下，我記得可以這樣啊："$ref":["a.json", "b.json#/c/d]"」（頂層查過，條文、thinking、程式原本都沒有這種寫法）；使用者接著選「**`$ref` 可以寫成陣列＝把幾份照順序合成一份：都是物件就合 key，都是陣列就接起來，種類混在一起＝解不開**」與「**合物件時同名 key：後面的蓋前面的**」（淺層合併，不往下層合）。例：`{"$ref": ["a.json", "b.json#/c/d"]}`。細則（頂層照上面兩類錯的規則推）：
    - **每個元素**就是原本的 `$ref` 字串（`檔`、`檔#/位置`），相對路徑照原規則從寫著它的那份檔所在的資料夾算；每一份各自取原文、各自接著解（裡面的相對 `$ref` 從那份檔自己的資料夾算），解完再合。合物件時同名 key 的位置留在第一次出現的地方、值換成後面的。
    - **只有一份**＝就是它本身（不限種類，跟寫成字串一樣）；**兩份以上**卻不是全物件或全陣列（混在一起，或都是字串、數字、布林、`null`）＝合不起來＝`DirectiveBad`。〔頂層推的：使用者只說了物件、陣列與混在一起；兩份字串沒有「合」的意思，當成解不開。10-23 使用者確認：「好。」〕
    - **位置只認 `#/`**：每個元素各自寫 `檔#/位置`；寫了 `$at` 不管（同上）。（頂層原推「`$at` 接在每一份的指標後面」、另一種讀法是對合好的結果再取位置，問使用者時 10-23：使用者「把$at刪掉，就都只認#/。」）
    - **`$path`、`$prefix`** 作用在合好的那一份：是字串才接（只會發生在只有一份時），不是字串靜默不作用（同上）。
    - **寫法寬容**：空陣列（同空字串）、有任何一個元素不是合格的字串（不是字串、空字串、`#` 後不是 `/`、只有 `#/…` 沒檔名）＝換不了，**整個物件原封不動留著**，不會只合其中幾份。
    - **真的解不開**：有一份讀不到、指不到＝`DirectiveBad`，整個都不換；**繞圈**看的是往上那幾層（某一份指回正在解的鏈上同一個位置）；同一個陣列裡寫兩次同一份不算繞圈（物件合起來一樣、陣列接兩次）。
    - 只換一格的讀法（`resolve_shallow`，見下「aos 讀的 JSON 都解」）：合出來的每個 key／元素記著它來自哪份檔，讀的人往下解那一格時從那份檔的資料夾算。
  - **argv 陣列裡也能放**（10-20 使用者，見 [ideas](../thinking/2026-10-20-ideas.md) D2、D8）：入口的 argv 陣列（C-73、N-61）原本「全是字串」、不能放指示詞，10-20 起元素可以寫 `$env` 或 `$ref`（`["echo", {"$env": "AOS_WS"}]`、`[{"$ref": "cmd.json#/0"}, "x"]`；`$path`、`$prefix` 同樣適用）；aos-exec 在六個環境變數設好之後解，相對檔名從陣列所在的檔的資料夾（＝`AOS_CD`）算；解完每個元素都要是字串，不是（或解不開）＝入口壞、aos-exec 退 1，不會把解出來的陣列攤開（10-20：寫法不合而原封不動留下的物件也不是字串，同樣＝入口壞）。
  - **aos 讀的 JSON 都解**（10-23 晚，只改 C++ 版 `proto8/impls`；使用者「對了，各種json應該都支援指示詞吧」，頂層說明當時只有單子與 argv 陣列會解，使用者選「aos 讀的 JSON 全部支援」，[thinking 10-23 ctl 與 $ref](../thinking/2026-10-23-daemon-ctl-ref.md)）。分兩層：**規範**＝aos 自己的程式讀的 JSON 一律支援指示詞；**事實**＝別人做的程式不一定支援（使用者：「其他地方預設不支援指示詞...這不應該是規範，這是在陳述事實，因爲其他人做的程式未必會想支援這個」）。細則（頂層照原則定）：
    - **每支程式只解自己讀的那幾格**（C-52）：整份、以及它一層層讀進去的那幾層先換掉（只換那一格，不往裡面走）；它讀的 key 的值整個解；**它不讀的 key（`body`、`_entry`…）原封不動**，留給讀它的人——`loop.json#/body` 由跑那次的 aos-exec 照上面的規則自己解，所以 body 裡的 `$env` 沒設照舊是那次 aos-exec 的錯、不擋 loop 起來。aos-loop：loop.json 整份、`run`、`max`、`interval_ms`、`ctl`、`state`；ctl 整份、`paused`、`stopped`、`max`、`interval_ms`、`seq`。aos-daemon 再加 daemon.json 的 `loops`、`adopt`，ctl 的 `loops`、`loops_added`、`loops_removed`（子項怎麼解見 [N-28](04-基礎設施-loop與daemon.md) 10-23 晚 ②）。aos-fsm：fsm.json 整份、`start`、`states`、每一格、格的 `val`、`next`。
    - **相對 `$ref` 從寫著它的那份檔所在的資料夾算**（同上 `$ref`）：設定檔＝設定檔的資料夾（`檔#/指標` 取的是那份檔）、ctl＝ctl 的資料夾、換進來的檔＝它解開捷徑後的資料夾。
    - **解不開**：設定檔＝程式自己的錯，退 1、一行 `程式名: DirectiveBad 原因`；ctl＝整份不採用、維持上一份好的、原因進 `ctl_warning`（N-08）。寫法不合的照上面原封不動，再照那一格自己的規則判（例 `max` 留成物件＝`CfgBad`）。
