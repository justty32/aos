# 基礎設施／指示詞

（10-19 整份重寫：舊命令列的語法糖〔TARGET、旗標、`--`〕新程式沒有，條號作廢；aos 的命令列只有 [N-58](10-基礎設施-定義與工作區.md) 的 `aos-exec [旗標...] XXX [args...]`（10-21 改：aos-exec 收旗標、`--` 結束旗標，目前只有 `--ws`，原 `aos-exec XXX [WS [args...]]`，[ideas 10-21](../thinking/2026-10-21-ideas.md)）——`proto8/bin` 版另有 `aos-inst FILE [args...]`，impls 線不提供 aos-inst 命令列（使用者 10-19 晚，[ideas § 20](../thinking/2026-10-19-ideas.md)）。舊的 `檔#/位置` 10-19 下班前以 `#/` 尋址的樣子回來了，只用在 aos-exec 的入口路徑，見 [N-62](10-基礎設施-定義與工作區.md)。）

- **N-45**（10-15 深夜定，10-16 夜改，10-19 改，10-19 晚改，10-20 改，草稿；[CONVENTION P-31](../CONVENTION.md)）**指示詞有兩個：`$env` 與 `$ref`，都可帶修飾欄 `$path`、`$prefix`**（10-20 改，原「`$env`（可帶 `path`）與 `$ref`」）（10-19 晚使用者定保留 `$ref`：「impls這塊，指示詞是OK的」，[ideas § 22](../thinking/2026-10-19-ideas.md)）。指示詞＝單子裡任何位置、帶 `$ref` 或 `$env` key 的物件，**整個物件換成它指到的值**；一個物件同時寫了 `$ref` 與 `$env` 只看 `$ref`，物件裡其餘 key 忽略。10-20 改（原「帶 `$` 開頭 key 的物件」「不認得的 `$xxx`＝錯」）：使用者「在解析json時，他會嘗試找到所有$ref/$env，並進行相應替換，替換失敗就原封不動放著。關於找到$ref/$env後，他們所在的那個obj value，就會被替換，至於那個obj value裡面的其他東西，就不管。」「一些該報錯的還是要報錯：環境變數沒設、讀不到檔、指不到、繞圈。主要是json格式這塊，指示詞機制很寬容」（[ideas](../thinking/2026-10-20-ideas.md) D12～D15）。所以錯分兩類：
  - **真的解不開＝錯**：環境變數沒設、`$ref` 的檔讀不到（不是 JSON 也算）、指標指不到、繞圈——解單子那一層自己的錯，退 1（bin 版是 aos-inst 的錯；impls 是 aos-exec 行程內解單子時的錯，代號 `DirectiveBad`）。
  - **寫法（格式）寬容、不報錯**：不認得的 `$xxx`（含還沒定的 `$fmt`）與其餘 key 不管；`$path`、`$prefix` 不是字串（也不是 `null`）、`at` 不合＝當沒寫；`$ref`／`$env` 的值不是字串或空字串、`#` 後不是 `/`、只有 `#/…` 沒檔名＝換不了，**整個物件原封不動留著**（有 `$ref` 時不改試 `$env`；頂層自定，待使用者確認）。留下來的物件若在 argv 裡，解完不是字串，照 argv 的規則算單子壞／入口壞——那是 argv 的規則，不是指示詞的錯。
  - **`$path`、`$prefix`**（10-20 使用者：「我希望那個path可以換成$path，然後添加$prefix」「兩種都能用。如果換出來的不是字串，那也不報錯，就靜默失效。」，[ideas](../thinking/2026-10-20-ideas.md) D9～D11）：換出來的值是字串時，先照 `$path` 接路徑（`os.path.join`；`$path` 寫絕對路徑就是絕對路徑；不帶或 `null`＝不接），再在前面加 `$prefix`：`{"$env": "AOS_WS", "$path": "a.txt", "$prefix": "--file="}` → `"--file=/ws/a.txt"`。`$env`、`$ref` 都能帶；換出來不是字串，兩欄靜默不作用、值原樣換進來。**舊寫法 `path` 不再有作用**（改名後是普通 key，照上面「其餘 key 不管」）。`$fmt` 使用者「先等等，fmt先不動」，未定。
  - **`$env`**：`{"$env": 名, "$path": 子路徑}` 換成該環境變數底下的路徑（照 `os.path.join` 接；`$path` 寫絕對路徑就是絕對路徑；不帶 `$path`（或 `null`）就是整個變數值；10-20 改：原寫 `path`，「`path` 不是字串＝錯」改成當沒寫，見上）。`$env` 讀的是**執行當下的環境**，像 shell 的 `$HOME`——同一份單子在不同環境下指到不同地方，所以可以當正式機制。變數沒設＝解單子那一層自己的錯，退 1（同上「真的解不開」；10-20 照舊）。`$env` 在 aos-exec 設好六個環境變數（10-21 晚加 `AOS_CO`）之後才解，所以單子裡讀得到 `AOS_STACK`、`AOS_CF`、`AOS_CD`（N-57）。
  - **`$ref`**（語意原照 impls 的 aos-directive 庫，`proto8/impls/aos-directive/README.md`；impls 是使用者的檔、git 未追蹤。10-20 起 bin 版先做了 `#/`、`at`、`$path`、`$prefix` 與寫法寬容，**現行以 bin 版為準**，impls 10-21 已對齊）：`{"$ref": "檔"}` 換成**那份 JSON 檔的整份內容**，換進來的值**接著解**（裡面的 `$ref`／`$env` 也解）。相對檔名從**寫著這個 `$ref` 的那份檔所在的資料夾**算：單子本身是入口時＝入口檔所在的資料夾（`AOS_CD`）；被 `$ref` 進來的檔若是捷徑，解開捷徑、從它實際指向的檔所在的資料夾算（使用者 10-17 定）；loop／fsm 設定裡內嵌的單子＝那份設定檔所在的資料夾。**可以取檔內的位置，兩種寫法都收**（10-20 改，原「只收整份檔、不收 `#`（`檔#/位置` ＝錯；跟入口路徑的 `#/` 尋址 N-62 是兩套、規則不同）」）：`{"$ref": "x.json#/a/b"}` 與 `{"$ref": "x.json", "at": "/a/b"}`，換成 `x.json` 裡 `/a/b` 那個值（JSON pointer，寫法同 N-62：第一個 `#` 就切、`#` 後面一定要 `/`）；**兩個都寫時 `at` 接在 `#/` 的指標後面**，`{"$ref": "x.json#/a", "at": "/b"}` 取 `/a/b`（10-20 使用者，見 [ideas](../thinking/2026-10-20-ideas.md) D1、D7）。`at` 要是空字串（＝不再往下）或 `/` 開頭；指標取的是那份檔的原文（不穿過檔裡的 `$ref`），取到的值再接著解。`$ref` 指回正在解的鏈上的同一個位置（檔＋指標，繞圈）、檔讀不到、不是 JSON、指不到＝錯，一樣是解單子那一層自己的錯、退 1；`#` 後不是 `/`、值不是字串或空字串、只有 `#/…` 沒寫檔名＝物件原封不動留著，`at` 不合＝當沒寫（10-20 改，原這幾種也＝錯，見上「寫法寬容」）。物件有 `$ref` 就只看 `$ref`、`at`、`$path`、`$prefix`，其餘 key（含 `$env`、舊的 `path`、不認得的 `$xxx`）不管（10-20 改，原「只看 `$ref` 與 `at`……不認得的 `$xxx`＝錯」）。
  - **argv 陣列裡也能放**（10-20 使用者，見 [ideas](../thinking/2026-10-20-ideas.md) D2、D8）：入口的 argv 陣列（C-73、N-61）原本「全是字串」、不能放指示詞，10-20 起元素可以寫 `$env` 或 `$ref`（`["echo", {"$env": "AOS_WS"}]`、`[{"$ref": "cmd.json#/0"}, "x"]`；`$path`、`$prefix` 同樣適用）；aos-exec 在六個環境變數設好之後解，相對檔名從陣列所在的檔的資料夾（＝`AOS_CD`）算；解完每個元素都要是字串，不是（或解不開）＝入口壞、aos-exec 退 1，不會把解出來的陣列攤開（10-20：寫法不合而原封不動留下的物件也不是字串，同樣＝入口壞）。
  - 寫什麼就做什麼（C-56）：值寫的就是「讀這個環境變數」「換成那份檔」，不做字串內插（`"$AOS_STACK/plan"` 那種是把規則埋進字串的暗規則）。單子本來就能內嵌，**JSON 大不是問題**，慣例範本不用 `$ref` 拆檔（P-27、P-31）；`$ref` 是給要拆的人用的。
  - **實作差異**（列在 [NORMS/10 開頭](10-基礎設施-定義與工作區.md)、[CONVENTION § 十](../CONVENTION.md)）：原「目前只有 impls 有 `$ref`……`proto8/bin` 的 `aos_inst.py` 只有 `$env`，沒有 `$ref`」10-20 改。**bin 版 10-20 做、impls 10-21 對齊**：`proto8/bin` 的 `aos_inst.py` 兩個指示詞都解（含 `#/`、`at`、`$path`、`$prefix`、寫法寬容），aos-exec 的 argv 陣列也解（10-20 使用者，見 [ideas](../thinking/2026-10-20-ideas.md) D1、D2、D7～D15）；impls 的 aos-directive 10-21 照 bin 版重寫，`#/`、`at`、argv 陣列裡的指示詞、`$path`／`$prefix`、寫法寬容都有，真的解不開才是 `DirectiveBad`（argv 陣列裡的＝`EntryBad`）。
