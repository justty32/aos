# 基礎設施／指示詞

（10-19 整份重寫：舊命令列的語法糖〔TARGET、旗標、`--`〕新程式沒有，條號作廢；aos 的命令列只有 [N-58](10-基礎設施-定義與工作區.md) 的 `aos-exec XXX [WS [args...]]`——`proto8/bin` 版另有 `aos-inst FILE [args...]`，impls 線不提供 aos-inst 命令列（使用者 10-19 晚，[ideas § 20](../thinking/2026-10-19-ideas.md)）。舊的 `檔#/位置` 10-19 下班前以 `#/` 尋址的樣子回來了，只用在 aos-exec 的入口路徑，見 [N-62](10-基礎設施-定義與工作區.md)。）

- **N-45**（10-15 深夜定，10-16 夜改，10-19 改，10-19 晚改，草稿；[CONVENTION P-31](../CONVENTION.md)）**指示詞有兩個：`$env`（可帶 `path`）與 `$ref`**（10-19 晚使用者定保留 `$ref`：「impls這塊，指示詞是OK的」，[ideas § 22](../thinking/2026-10-19-ideas.md)）。指示詞＝單子裡任何位置、帶 `$` 開頭 key 的物件，**整個物件換成它指到的值**；一個物件同時寫了 `$ref` 與 `$env` 只看 `$ref`，物件裡其餘 key 忽略；不認得的 `$xxx`＝錯。
  - **`$env`**：`{"$env": 名, "path": 子路徑}` 換成該環境變數底下的路徑（照 `os.path.join` 接；`path` 寫絕對路徑就是絕對路徑；不帶 `path`（或 `null`）就是整個變數值；`path` 不是字串＝錯）。`$env` 讀的是**執行當下的環境**，像 shell 的 `$HOME`——同一份單子在不同環境下指到不同地方，所以可以當正式機制。變數沒設＝解單子那一層自己的錯，退 1（bin 版是 aos-inst 的錯；impls 是 aos-exec 行程內解單子時的錯，代號 `DirectiveBad`）。`$env` 在 aos-exec 設好五個環境變數之後才解，所以單子裡讀得到 `AOS_STACK`、`AOS_CF`、`AOS_CD`（N-57）。
  - **`$ref`**（語意照 impls 的 aos-directive 庫，`proto8/impls/aos-directive/README.md`；impls 是使用者的檔、git 未追蹤）：`{"$ref": "檔"}` 換成**那份 JSON 檔的整份內容**，換進來的值**接著解**（裡面的 `$ref`／`$env` 也解）。相對檔名從**寫著這個 `$ref` 的那份檔所在的資料夾**算：單子本身是入口時＝入口檔所在的資料夾（`AOS_CD`）；被 `$ref` 進來的檔若是捷徑，解開捷徑、從它實際指向的檔所在的資料夾算（使用者 10-17 定）。**只收整份檔、不收 `#`**（`檔#/位置` ＝錯；跟入口路徑的 `#/` 尋址 N-62 是兩套、規則不同）。`$ref` 指回正在解的鏈上的檔（繞圈）、檔讀不到、不是 JSON、值不是字串或空字串＝錯，一樣是解單子那一層自己的錯、退 1。
  - 寫什麼就做什麼（C-56）：值寫的就是「讀這個環境變數」「換成那份檔」，不做字串內插（`"$AOS_STACK/plan"` 那種是把規則埋進字串的暗規則）。單子本來就能內嵌，**JSON 大不是問題**，慣例範本不用 `$ref` 拆檔（P-27、P-31）；`$ref` 是給要拆的人用的。
  - **實作差異**（列在 [NORMS/10 開頭](10-基礎設施-定義與工作區.md)、[CONVENTION § 十](../CONVENTION.md)）：目前只有 impls 有 `$ref`——aos-directive 庫解、aos-exec 行程內跑單子時連它，兩個指示詞都解得開；`proto8/bin` 的 `aos_inst.py` 只有 `$env`，**沒有 `$ref`**（寫了 `$ref` 會被當普通物件、在欄位型別那關退 1），bin 的 aos-exec、aos-loop、aos-fsm 行程內跑單子都走它。
