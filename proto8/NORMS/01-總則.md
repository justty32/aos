# 總則

- **N-05** 給別人讀的檔，先寫 `.` 開頭的暫存檔再改名蓋過去；讀的人不讀 `.` 開頭的檔。這是 N-02 的細則之一；ctl.json、state 檔、`.done`、save 檔、時鐘檔都照這條。（10-12）
- **N-12**（10-14 定，草稿）可供呼叫的程式回歸 POSIX 原始本意：stdin＝參數，stdout／stderr＝結果，exit＝輔助。在 aos 規範中三者都是 JSON 串流（放寬：一串 JSON 值接著一串，每份可單行或跨行；只有一份就是普通 JSON）。stdin 有多份時，整串是一次呼叫，意思由程式自己解讀、寫在它的說明裡，規範只管格式。跑完的判定：以 stdout 吐出結果並且行程結束為準；有寫 exit 檔的話，exit 檔出現也算（10-14 深夜使用者改，原為「exit 檔出現」，見 [thinking 14 §41](../thinking/2026-10-14-json-entry/14-h拍板.md#41-結論與未決)）。**半份不算**（10-14 深夜，[thinking 15](../thinking/2026-10-14-json-entry/15-ret與半份JSON.md)）：讀的人只認完整、能解析的 JSON；被殺時最後一份只寫一半、解析不了就忽略，因此找不到結果＝沒有結果（例：tasks 報 `ResultUnreadable`、loop 記 `code` null）。JSON 串流視為省略最外層 `[]` 的陣列，`檔#/位置` 照陣列索引指。inst.json 格式不變（作為與舊時代的橋樑）；規範管的是 inst 所呼叫的 argv[0] 程式。以函數來看：stdin＝args，exit＋stdout＝返回值，stderr＝途中拋出的錯誤與警告；stdout 可一份一份吐出（像 yield），不強制。aos-inst／loop／daemon 已照本條重做（10-14 使用者定；10-14 夜動工，基礎實作，命令列細則見 [N-21～N-27](../NORMS.md)）。（10-14）
- **N-18**（10-14 夜定，草稿）規範延伸出來的實作分兩級。**基礎實作**：最精簡，只確保符合概念與規範的要求。**標準實作**：考慮到邊緣狀況、經過一定程度精修。目前先做基礎實作；邊緣狀況能顧就顧，但不為了邊緣狀況把實作弄肥。錯誤歸類慣例：規範沒說的邊緣狀況，在基礎實作中預設不應出現，出問題算使用者的事。（10-14）
- **N-29**（原 h3，草稿）stderr 的 JSON 形狀：錯誤一份 `{"error": {"code", "msg"}}`（同 N-10 回覆的 error），警告一份 `{"warning": {"code", "msg"}}`，一份一行。stdin 有多份 JSON 而程式只要一份時，只看第一份、警告 `ExtraInput`。（10-14 深夜）
- **N-35**（10-15 定，草稿）路徑寫法 `檔#/位置`：凡是收「一份 JSON 設定」的地方（aos-inst／loop／daemon 的 TARGET、`$ref`、daemon 指令裡的 id、fsm 的格），都可以在檔名或資料夾後面接 `#/位置` 指到裡面的一塊。遇到第一個 `#` 就切（檔名含 `#` 的不支援），`#` 後面只認 `/` 開頭（`檔#x`＝錯）；位置照檔案系統寫法（D1a）：`#` 或 `#/`＝整份，結尾 `/` 與空段落忽略，代價是名字是空字串的 key 指不到；JSON 串流當省略最外層 `[]` 的陣列、照索引指（N-12）。指到的是一塊視窗不是切下來：裡面的 `$ref` 可以用 `../` 摸到旁邊的東西。TARGET 是資料夾時先照現有規矩找 inst.json 再套位置。當設定用時指到的值不是物件＝錯。身分（id）＝`realpath#/位置`，沒位置或 `#/` 就是純 realpath（同一份檔兩個位置＝兩個 id）。一份 JSON 放好幾個 inst 可以（agent.json 或資料夾都行）。（10-15）
