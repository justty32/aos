# 總則

- **N-05** 給別人讀的檔，先寫 `.` 開頭的暫存檔再改名蓋過去；讀的人不讀 `.` 開頭的檔。這是 N-02 的細則之一；ctl.json、state 檔、`.done`、save 檔、時鐘檔都照這條。（10-12）
- **N-43**（10-15 收工後定，草稿；10-19 改，[CONVENTION P-19、P-21](../CONVENTION.md)、[N-60](10-基礎設施-定義與工作區.md)）結束碼：**`0`＝正常、`10`＝正常停（要求外面的 loop 別再圈了）、其他非 0＝有錯**。**aos 的程式說自己的錯一律退 1**，stderr 一行「程式名: 原因」（P-21），不另用 125～127 等數字分種類；被訊號停掉的結束碼是 128＋訊號（shell 慣例），在行程內呼叫 aos-inst 的人另拿到 `signal`、`timed_out`（N-30）。**每層只說自己**（C-52；10-15 晚使用者「都同意。」，[盤點](../thinking/2026-10-15-principles.md)第 1 條）：loop 收到子程式的 10 以 0 結束、收到其他非 0 以那個碼結束，自己的錯退 1；不把下層的錯誤內容往上轉述，下層的錯寫在下層自己的 stderr 或 stack 的檔裡。**例外只有一種**（10-15 晚使用者「都按照推薦。」）：**透明轉交**別人的碼——aos-inst 命令列的結束碼＝子程式的碼（資料，N-30）、aos-exec `exec` 入口之後結束碼就是入口的碼，這時碼是下層的、不是自己的。loop 跑滿 `max` 圈以 0 結束、**不寫 stderr**（要知道有沒有跑滿看 `trace.jsonl` 行數）。被外層 `timeout_ms` 殺掉的那格＝失敗，碼 128＋訊號（P-36）。（停止碼 10：使用者 10-19 拍板點 1「agent-bob 現在的形狀就是標準」，並裁定走今天的，[ideas § 8、§ 9](../thinking/2026-10-19-ideas.md)；使用者 10-15 收工後：「結束碼不要太依賴，我已經決定規範中只定下：0就是通用正常，非0就是有錯，沒了。」）**「正常退出」的定義**（10-15 晚補，盡量靠近 Unix 傳統）：該功能單元的行為照當初的設計構想、功能介紹、文檔走（走的是定義中正常退出那條路），而且是考慮過的狀況（被預料到、而且是正常的）。簡化判準：**正常退出不會在 stderr 噴東西**——寫了 stderr 就不算正常退出、不該退 0。反過來不成立：沒寫 stderr 不代表一定退 0，錯誤可以寫到別處（例 stack 裡的 `trace.jsonl`），只要寫在文件說好的地方。（使用者 10-15 晚：「喔剛剛那個我補一句：結束碼0代表正常退出，我這邊的定義(我希望盡量靠近unix傳統)，關於"正常退出"的定義，就是該功能單元中，其行爲有如當初的設計構想、功能介紹、文檔走(當然，走的是定義中正常退出的那條路)，並且是考慮過的狀況的一部分(有被預料到，且是正常的)，一個更簡單一些的定義是不會在stderr噴東西。」「當然，不在stderr噴東西，不代表結束碼就必須爲0。你當然可以把錯誤輸出到別的地方。」；與 C-53 錯誤路徑濃縮同一件事，[thinking 原則](../thinking/2026-10-15-principles.md)）
- **N-18**（10-14 夜定，草稿）規範延伸出來的實作分兩級。**基礎實作**：最精簡，只確保符合概念與規範的要求。**標準實作**：考慮到邊緣狀況、經過一定程度精修。目前先做基礎實作；邊緣狀況能顧就顧，但不為了邊緣狀況把實作弄肥。錯誤歸類慣例：規範沒說的邊緣狀況，在基礎實作中預設不應出現，出問題算使用者的事（這是 [C-53](../CONCEPTS/01-設計理念.md) 的姿態 (a)「入口默認正常」）。（10-14）
