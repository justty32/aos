# 基礎設施／組合子（tasks、fsm）

使用者 10-15：tasks 組合子歸基礎設施，「**地位等同於 C 語言的 stdlib**」；同日又定「把 fsm 也跟 tasks 放一起」——fsm 同為 stdlib 地位。[agent](../CONCEPTS/05-agent.md) 是用 fsm 組出來的（一個資料夾程式＝入口＋表＋各格，C-50），agent 主題連過來。

> **分層**（10-22，[C-74](../CONCEPTS/01-設計理念.md#分層10-22-使用者定)）：fsm、tasks 屬**標準庫**，建在基礎層（核心 aos-exec＋loop、daemon）之上；本檔主題名「基礎設施」是照內容分的，不是層。

> **fsm 不管、使用者自行承擔的事**（10-22 使用者「其餘算使用者自己承擔，條文定稿」，[ideas 10-22 § 7](../thinking/2026-10-22-ideas.md#7-fsm10-22)）：① 每格**沒有時間上限**：格最後 exec 成可執行檔或 argv 陣列時，不理 SIGTERM 就一直等（格是 inst 單子且寫了 `timeout_ms` 時，由 aos-exec 到時 SIGTERM、過 `grace_ms` 補 SIGKILL；沒寫 `timeout_ms` 一樣不限）——要上限自己加，例如在 `val` 指的單子或 argv 檔裡 argv 前面接 `timeout -k 5 60`（不加 `-k` 遇到不理 SIGTERM 的照樣等），或用單子的 `timeout_ms`；`val` 陣列的第一個是 aos-exec 的目標，不能直接寫 `timeout`。② 兩隻 fsm **共用同一個 stack**（同一份 `state.txt`，本來就違反 N-09「一個 state 檔只有被控制的那個東西自己寫」）：寫的時間撞上時搶同一個暫存檔 `.state.txt`、後到的當掉，沒撞上也會互相蓋掉狀態、`trace.jsonl` 兩邊交錯——自己避免，或在外面接 s6-setlock 之類的鎖（N-39：同時兩隻跑同一份交給拍它的 loop）。③ **state／trace 寫不了**（stack 資料夾不見、沒權限…）時，格已經跑完，fsm 直接當掉、stderr 吐 Python traceback、結束碼 1（這拍收到了訊號也不以 128＋N 結束），算 P-21「自己的錯 stderr 一行」的例外，接受；state 沒換，下一拍照舊跑同一格（stack 資料夾不見時讀不到 state，從 `start` 起），重跑的冪等性不保證（N-20）。④ `trace.jsonl` **不設上限**、每拍附加一行，要控制大小自己處理（fsm 每拍重新以附加模式打開，外面用 logrotate 之類搬走或截斷都接得上）。⑤ 拍它的 loop 或 fsm 自己被 **SIGKILL**（轉不了訊號）時，正在跑的格變孤兒、繼續跑到完；這時重開，新的一拍可能跟還沒跑完的舊格重疊（同一格跑兩份、搶同一份 state）——自己避免，例如重開前先確認舊格結束。⑥ **無窮轉移**（格一直退 0、狀態轉個不停）只有拍它的 loop 的 `max` 擋，fsm 自己不數（N-38）。⑦ `val` 的**相對路徑從 cwd 算**（fsm 不轉，F2）：經 `aos-exec fsm.json` 跑時 cwd 是 fsm.json 所在的資料夾；直接叫 `aos-fsm` 時是從哪裡叫就從哪裡算。⑧ **`.env` 外層贏**：aos-exec 預設不蓋已有的環境變數（N-59 第 4 件），所以格的資料夾的 `.env` 跟外層同名時，格看到的是外層的值；`val` 陣列是 `aos-exec -- 目標 參數...`，寫成 `["--dotenv-override", "act"]` 會把旗標當成目標、傳不了——要蓋就把那格寫成 body 單子，例 `{"val": "fsm.json#/states/act/body", "body": {"argv": ["aos-exec", "--dotenv-override", "act"]}, "next": "idle"}`。

## fsm

- **N-20**（10-14 夜定；10-22 定稿，原標「草稿」，[ideas 10-22 § 7](../thinking/2026-10-22-ideas.md#7-fsm10-22)）巢狀 fsm 出口當掉後重跑時，各格的冪等性**不保證，不在規範範圍內**（照 N-18 的錯誤歸類：各格自己顧，出問題算使用者的事）。（10-14）（10-22 對照 bin 程式：fsm 不記格跑到哪、不做重跑保護，上一拍被殺一半就是下一拍重跑同一格，見 N-38。）
- **N-36**（10-15 定；10-19 改；10-22 定稿，原標「草稿」，[ideas 10-22 § 7](../thinking/2026-10-22-ideas.md#7-fsm10-22)；[CONVENTION P-07](../CONVENTION.md)）aos-fsm 只管一件事：**現在是 A 狀態，就跑 A 那格**；狀態內部、格內部的事 fsm 都不管（10-15 收工後使用者意見 1，[意見 1～4](../thinking/2026-10-15-opinions-1-4.md)）。表：`{"start": 起始狀態名, "states": {狀態名: {"val": 格, "next": 下一個狀態名}}}`（`val` 照 C-55）。每格的 `val`＝**字串＝aos-exec 的目標（子資料夾、檔或 `檔#/指標`；`aos-exec -- 它`，相對路徑從 cwd 算，cwd＝agent 資料夾，N-59；直接叫 `aos-fsm` 時是叫它的地方，見本檔開頭⑦）；要內嵌單子就寫 `"val": "fsm.json#/states/<名>/body"`、單子放在同一格的 `body`，由 aos-exec 行程內跑**（10-21 起 `val` 只收字串、物件＝表壞，跟 loop 的 `val` 同一個規矩；[計畫 10-21](../thinking/2026-10-21-plan.md) F2，使用者不在時代定。原本物件＝一張單子、fsm 行程內 `aos_inst.run()`）。`val` 也可以是陣列 `[目標, 參數...]`（每拍 `aos-exec -- 目標 參數...`，元素都要是字串；比照 loop 的 `val`，10-21 傍晚，[ideas 10-21 § 9](../thinking/2026-10-21-ideas.md#9-設定檔是唯一的位置參數path-改字串拼接10-21-傍晚) H3）。命令列 `aos-fsm [旗標] fsm.json`：設定檔是唯一的位置參數，可寫 `檔#/指標`，目前沒有旗標（10-21 傍晚改，原 `aos-fsm --cfg fsm.json`、沒有位置參數〔F1〕，H1）；表裡不認得的 key 忽略（C-48），所以 fsm.json 可以帶 `"_entry": ["aos-fsm", {"$env": "AOS_CF"}]`，`aos-exec fsm.json` 就是一拍（F6；10-21 傍晚改，原 `["aos-fsm", "--cfg", "fsm.json"]`）。表一定明寫、`next` 只在表上，不靠慣例檔名；查不到那格＝錯（N-38）。**開跑時（讀表後、跑格前）查整張表**（10-22 使用者「b、c 開跑時查整張表」）：`start` 要在表上；每一格要是 `{"val", "next"}`、`val` 是 aos-exec 的目標（字串或非空字串陣列）、`next` 是表上的狀態名、不能是空字串；哪一格不合都＝表壞、退 1、不跑格（原本只查這拍那一格：`next` 不在表上要到下一拍才擋、`next` 是空字串則下一拍靜靜回 `start`，10-22 改）。`next` 頭尾也不能有空白、不能有換行（state 檔是純文字一行、讀回來會去頭尾空白，寫進去要讀得回同一個名字），連同別格的 `val` 一起查，是 10-22 實作時代定的。一拍只跑一格：讀 `$AOS_STACK/state.txt`（10-23 起帶 `.txt`，原 `state`；沒有檔＝從 `start` 起；純文字一行，N-13；讀的時候去頭尾空白，內容是空的也＝`start`；**檔在但讀不了**〔沒權限、是資料夾、不是 UTF-8…〕＝fsm 自己的錯、退 1、不跑格，10-22 使用者「a state 讀不了就退 1」，原本沒權限、是資料夾都當沒有檔從 `start` 起、不是 UTF-8 吐 traceback；裡面的狀態不在表上＝查不到那格、退 1，照舊）、跑那格、**格的碼是 0 才**把 `next` 寫進 state（N-05 先寫暫存再改名）、然後以格的碼退出（收到訊號的例外見 N-38）。（10-15；10-16 使用者同意「喔喔，好」：格的路徑一律從 cwd 算）
- **N-38**（10-15 定；10-19 改；10-22 定稿，原標「草稿」，[ideas 10-22 § 7](../thinking/2026-10-22-ideas.md#7-fsm10-22)；[CONVENTION P-20、P-21](../CONVENTION.md)）fsm 出錯：那格結束碼非 0（含被訊號殺、逾時）、查不到那格、表壞（含 `val` 不是字串，10-21）〔10-22 改：原寫「`val` 不是字串」，10-21 傍晚起 `val` 也收陣列，照程式改成「`val` 不是 aos-exec 的目標（字串或非空字串陣列）」；表壞 10-22 起開跑時查整張表、哪一格壞都算，見 N-36〕、state 檔在但讀不了（10-22，見 N-36）＝錯；格指到的單子壞是 aos-exec 的錯（它退 1、自己說），對 fsm 來說就是那格非 0（10-21 起；原本「單子壞」是 fsm 自己的錯）。出錯時 **state 不動**（下一拍重跑同一格）、fsm 以那格的碼退出（fsm 自己的錯退 1，stderr 一行 `aos-fsm: 原因`，N-43；自己的錯一律不跑格、不記 trace）；**格的 stderr fsm 不讀、不轉**（C-52 切乾淨：格的錯是格自己的；想看子層靠自己寫的檔，沒機制就不碰；10-15 深夜使用者「不能接受，拜託切乾淨」）；之後怎麼辦交給外層（拍它的 loop）或人。不特別的 `error` 格：想優雅處理的格自己接錯、改寫狀態；連錯幾次要停住，也是格自己數——**agent 的格不數**（10-16，[N-53](10-基礎設施-定義與工作區.md)：重試幾次看外面 loop，agent 自己不數）。上一拍被殺一半（格跑了、state 沒寫）＝下一拍重跑同一格，半成品由格自己看自己的檔判斷；重跑的冪等性不保證（N-20）。拍數上限由拍它的 loop 的 `max` 管。**例外（10-19 晚，[ideas § 24](../thinking/2026-10-19-ideas.md)）**：fsm 自己收到 SIGINT／SIGTERM／SIGHUP 時，先轉給那格、等格跑完，trace 與 state 照常寫（格退 0 照樣換狀態），再以 128＋N 結束、不以格的碼結束；跑格之前就收到＝不跑、直接 128＋N（CONVENTION P-36）。（10-15 收工後依意見 1～4 Q1、Q4 改，[意見 1～4](../thinking/2026-10-15-opinions-1-4.md)；格出錯 fsm 退非 0，使用者 10-15 收工後定）
- **N-39**（10-15 定；10-19 改；10-22 定稿，原標「草稿」，[ideas 10-22 § 7](../thinking/2026-10-22-ideas.md#7-fsm10-22)；[CONVENTION P-07、P-37、P-38](../CONVENTION.md)）fsm 的 state 檔在 `$AOS_STACK/state.txt`，只記現在狀態名（純文字一行），只有 fsm 自己寫（N-09）。fsm 不開 ctl、lock：暫停、停止、同時兩隻跑同一份，交給拍它的 loop（共用同一個 stack 會撞暫存檔，使用者自行承擔，見本檔開頭②）。心跳：fsm 是單次程式、壽命一拍，不適用 N-17／N-32 的每秒心跳。**每拍在 `$AOS_STACK/trace.jsonl` 追加一行** `{"at","state","code","signal","elapsed_ms"}`（`at`＝這拍開始的 UTC 時間，ISO 8601 到毫秒〔10-23 統合：原 `ms`、`at` 到秒，[thinking](../thinking/2026-10-23-naming.md)〕；10-15 待定「標準實作要不要每拍記時間」〔今稱完整實作，N-18〕10-19 結案：要，P-38）。10-21 拿掉 `timed_out`（[計畫 10-21](../thinking/2026-10-21-plan.md) F4）：fsm 看不到格裡有沒有逾時（C-52），被逾時收掉的格看 `code`（128＋15）就知道。（10-22 對照 bin 程式補：被逾時收掉的單子格 `signal` 是 null——格是 aos-exec 子行程，它收掉單子後以子程式的碼正常結束；`signal` 只在拍的那個行程（aos-exec，或它 exec 成的程式）本身被訊號殺掉時有值，例如 exec 成的 shell 腳本被轉來的 SIGTERM 殺掉、外面 SIGKILL 它。每拍先寫 trace、再寫 state；trace 不設上限、state／trace 寫不了是 traceback，見本檔開頭③④。）表裡的格指回自己（遞迴、同一份同時被拍兩次）fsm 不擋，卡死不防護（10-15 收工後使用者「好」；P-37）。（10-15 收工後依意見 1～4 改，[意見 1～4](../thinking/2026-10-15-opinions-1-4.md)）
- **N-41**（10-15 定；10-19 改；10-22 定稿，原標「草稿」，[ideas 10-22 § 7](../thinking/2026-10-22-ideas.md#7-fsm10-22)；[CONVENTION P-09、P-22、P-36](../CONVENTION.md)）一格怎麼跑是那格的事，規範中立：例如 think 格可以起來就等 LLM 回覆、處理完才結束（同步），也可以把請求寫進某個地方就結束，下一拍再看回覆到了沒（非同步），兩種都合規，換一格即可；最小實作先做同步版。格自己不 setsid／fork 背景行程——格是單子（`fsm.json#/states/<名>/body`）時由 aos-exec 行程內跑、給格一個新的行程群組、逾時打整群、把 fsm 轉來的訊號轉給整群（P-36、N-59 第 5 件；bin 版經 `aos_inst.run()`，impls 線由 inst 的 C lib `new_session` 開群組；10-21 起 fsm 自己不跑單子），格自己不另起。格裡放 loop 不禁止也不鼓勵，會阻塞一拍，靠那一格單子的 `timeout_ms` 守。（10-15）（10-22 對照 bin 程式補：格不是單子〔`val` 指到可執行檔或 argv 陣列檔〕，或是單子但沒寫 `timeout_ms` 時，沒有時間上限，見本檔開頭①。）
