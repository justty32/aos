# 基礎設施／組合子（tasks、fsm）

使用者 10-15：tasks 組合子歸基礎設施，「**地位等同於 C 語言的 stdlib**」；同日又定「把 fsm 也跟 tasks 放一起」——fsm 同為 stdlib 地位。[agent](../CONCEPTS/05-agent.md) 是用 fsm 組出來的（例：一份 agent.json），agent 主題連過來。

## tasks（seq／par／if／not）

- **N-34**（原 h16，草稿）tasks（proto8-1 的 aos-seq／par／if／not）：起子 aos-inst 時接它的 stdout，讀那份結果的 `code` 當子程式的碼，不靠 exit 檔，所以 inst 不必寫 `exit`；子 aos-inst 的結果不漏進 tasks 自己的 stdout。tasks 與 aos-tick 自己的 stdout 不吐東西（空的 JSON 串流，結果就是退出碼，N-12「不強制」最簡單的合規），自己的錯誤照 N-29 吐 JSON。（10-14 深夜，使用者把原 h16「讀 exit 檔」改成讀 stdout）

## fsm

- **N-20**（10-14 夜定，草稿）巢狀 fsm 出口當掉後重跑時，各格的冪等性**不保證，不在規範範圍內**（照 N-18 的錯誤歸類：各格自己顧，出問題算使用者的事）。（10-14）
- **N-36**（10-15 定，草稿）aos-fsm 的方法表：設定有 `start`（起始狀態名）與 `states`（狀態名 → 格）。每格的值＝一個 aos-inst TARGET（檔、資料夾、可接 `#/位置`，或內嵌一張 inst），也可寫成 `{"target": …, "next": "<狀態名>"}` 帶表上靜態 next。表一定明寫，不靠慣例檔名；查不到那格＝錯（照 N-38）。一拍只跑一格：fsm 讀回現在狀態、跑那格、換狀態、退出。第一拍：state 窗位置有、檔還沒有＝從 `start` 起。（10-15）
- **N-37**（10-15 定，草稿）下一狀態：fsm 讀那格 stdout 的最後一份完整 JSON（N-12，半份不算），有 `next` 就照它；沒有就看表上靜態 next；兩邊都沒有就留原狀態。那份的 `data` 由 fsm 存進 state 窗，下一拍當 `prev` 給下一格。`next` 不在表裡＝錯（N-38）；有 `end` 的內層見 N-40。（以結束碼決定下一狀態概念上也正當，但 aos-fsm 採 stdout。）（10-15）
- **N-38**（10-15 定，草稿）fsm 出錯：那格結束碼非 0、查不到那格、或走到 `max_steps`（暫定 a）＝錯。表上有 `error` 格就跳去：phase 改成 `error`，下一拍才跑（一拍一格），原狀態與錯誤放進 `prev`；沒有就留原狀態並在 state 窗記 `last_error`。`error` 格自己出錯不再跳，留在 `error`＋`last_error` 等人。`step` 計數在回到 `start` 或進 `error` 格時歸零（`max_steps` 自上次回 `start` 起算）。上一拍沒留下結果（被殺一半；含格跑完、ret 落了、state 還沒寫就被殺）＝重進同狀態重跑、不撿舊 ret，`prev.interrupted: true`，接著怎麼做由那格自己決定；重跑的冪等性不保證（N-20）。fsm 起格前先把 `step` 寫進 state 窗，好判得出上一拍沒留結果。fsm 的結束碼只在 fsm 自己出錯（設定錯、窗缺、拿不到鎖）才非 0；格出錯由表處理、fsm 退 0——所以內層沒 `error` 格時外層不知情，要外層接手就讓內層 `error` 格回 `end` 名單裡的 `next`（N-40）。（10-15）
- **N-39**（10-15 定，草稿）fsm 的窗：state 窗必填（N-19），記 `phase`（現在狀態名）、`data`、`step`、`last_error`，只有 fsm 自己寫（N-09）；ctl 窗選填，認 paused／stop、帶 seq（N-33），`paused`／`stop` 對單次程式都＝這拍不起格就退出；lock 窗選填（N-14），擋同時兩隻 fsm 跑同一份，也擋表裡指回自己資料夾的遞迴，拿不到＝fsm 自己出錯、不碰 state。心跳：fsm 是單次程式、壽命一拍，不適用 N-17／N-32 的每秒心跳，生死看拍它的 loop 的 state 窗；基礎實作 fsm 的 state 不寫時間、不帶 pid／started／boot_id（標準實作要不要每拍記時間未定，見[待定](08-待定.md)）。（10-15）
- **N-40**（10-15 定，草稿）fsm 巢狀：某格本身可以是另一個 aos-fsm（像階層式狀態機），內層每拍也只跑一步。內層設定明寫 `end` 出口名單：格回的 `next` 不在自己表裡、但在 `end` 裡＝交給外層——內層把那份結果原樣當自己這拍 stdout 的最後一份，子 phase 歸位到 `start`；不在表裡也不在 `end` 裡＝錯。內層沒到終點時 stdout 最後一份不帶 `next`，外層留在原格（巢狀格不宜寫表上靜態 next；寫了照 N-37 會被帶走，自己負責）。內層有自己的 state 窗（必填），鎖與 ctl 不另開（沿用外層）；內層從自己的 TARGET 拿設定、不讀外層給的 stdin，要外層的東西就 `$ref`。（10-15）
- **N-41**（10-15 定，草稿）一格怎麼跑是那格的事，規範中立：例如 think 格可以起來就等 LLM 回覆、處理完才結束（同步），也可以把請求寫進某個請求資料夾就結束、回 `{"next":"waiting"}`，下一拍再看回覆到了沒（非同步），兩種都合規，換一格即可；基礎實作先做同步版。兩種都不自己 setsid／fork 背景行程（限 fsm 的格；argv[0] 程式的通則另議，見[待定](08-待定.md)）。格裡放 loop／daemon 不禁止也不鼓勵，會阻塞一拍，靠那張 inst 的 `timeout_ms` 守。（10-15）
