# 基礎設施／組合子（tasks、fsm）

使用者 10-15：tasks 組合子歸基礎設施，「**地位等同於 C 語言的 stdlib**」；同日又定「把 fsm 也跟 tasks 放一起」——fsm 同為 stdlib 地位。[agent](../CONCEPTS/05-agent.md) 是用 fsm 組出來的（10-15 收工後：一個定義資料夾＝表＋每格一張 inst，C-50），agent 主題連過來。

## tasks（seq／par／if）

- **N-34**（原 h16，草稿）tasks（`aos seq`／`par`／`if`，在 proto8/lib）：起子 aos-inst 時接它的 stdout，讀那份結果的 `code` 當子程式的碼（沒有 exit 檔）；子 aos-inst 的結果不漏進 tasks 自己的 stdout。tasks 與 aos-tick 自己的 stdout 不吐東西（空的 JSON 串流，結果就是退出碼，N-12「不強制」最簡單的合規），自己的錯誤照 N-29 吐 JSON、退 1（含 aos-inst 起不來、結果讀不到；原本「收到訊號＝stderr 一份 `Signaled`」，10-16 起收到 SIGTERM＝優雅收工、收好子程式退 0（[N-52](01-總則.md)），實作待改）；seq／par／if 回子程式的碼是透明轉交（N-43 例外）。（10-14 深夜，使用者把原 h16「讀 exit 檔」改成讀 stdout。10-15 深夜 KISS 批次 1：`aos-not` 刪——要反過來寫 `aos if X 失敗格 成功格`；跟著刪的「述詞例外」原是 10-15 晚使用者「都按照推薦」定的（[盤點](../thinking/2026-10-15-principles.md) S5），`aos-if` 的條件本來就是子程式的碼、不是 aos-if 自己的退出碼，不算例外，見 [KISS 彙整](../thinking/2026-10-15-kiss/README.md) 1.17）

## fsm

- **N-20**（10-14 夜定，草稿）巢狀 fsm 出口當掉後重跑時，各格的冪等性**不保證，不在規範範圍內**（照 N-18 的錯誤歸類：各格自己顧，出問題算使用者的事）。（10-14）
- **N-36**（10-15 定，草稿）aos-fsm 只管一件事：**現在是 A 狀態，就跑 A 那格的 inst**；狀態內部、inst 內部的事 fsm 都不管（10-15 收工後使用者意見 1，[意見 1～4](../thinking/2026-10-15-opinions-1-4.md)）。方法表：設定有 `start`（起始狀態名）與 `states`（狀態名 → 格），選填 `end`（N-40）。每格的值＝一個 aos-inst TARGET（檔、資料夾、可接 `#/位置`，或內嵌一張 inst），也可寫成 `{"val": …, "next": "<狀態名>"}` 帶表上靜態 next（原值 key 照 C-55 統一叫 `val`，原本 `target`；10-15 使用者「都按照推薦」）。表一定明寫，不靠慣例檔名；查不到那格＝錯（照 N-38）。**格的路徑一律從 stack（cwd；10-16 夜改名，原叫工作區）算**，窗與格要讀寫的資料也照 cwd 算——跟 [C-59](../CONCEPTS/03-基礎設施.md#資料夾程式工作區與-stack10-19)／[N-46～N-51](10-基礎設施-定義與工作區.md)「只有一種路徑規則」一致；定義裡的格寫 `.aos/x`（N-48）。（10-16 改：原本「格的名字從 fsm 設定檔所在的資料夾算；設定從 stdin 或 dict 來的，從呼叫者的 cwd 算」，前半句刪掉；使用者同意頂層推薦「喔喔，好」。實作待改：`aos_fsm` 目前照舊從設定檔所在資料夾算。）一拍只跑一格：fsm 讀回現在狀態、跑那格、換狀態、退出。第一拍：state 窗位置有、檔還沒有＝從 `start` 起。（10-15）
- **N-37**（10-15 定，草稿）下一狀態：fsm 讀那格 stdout 的最後一份完整 JSON（N-12，半份不算），有 `next` 就照它：字串＝那個狀態名，**`null`＝留原狀態**（格說「我還沒完」，表上寫了靜態 next 也不走；10-15 深夜依 C-52 補）；沒有 `next` 這個 key（含格什麼都沒吐）就看表上靜態 next；兩邊都沒有就留原狀態（格什麼都沒吐又沒寫表上 next＝錯，N-38）。`next` 在表裡＝進入那個狀態；在 `end` 的情形見 N-40；不在表裡也不在 `end`＝錯（N-38）。**fsm 不碰格的 stdin**：格要什麼設定、參數，寫在那張 inst 自己的 `stdin`（N-27）；fsm 只另外接一份 stdout 來看 `next`。格之間要傳的東西由格自己寫成檔（例 cwd 裡的 history.json），fsm 不存 `data`。（10-15 收工後依意見 1～4 Q2、Q3 改，[意見 1～4](../thinking/2026-10-15-opinions-1-4.md)；原為「fsm 設定本身＋`fsm_state` 當 stdin、`data` 存進 state 窗」）（以結束碼決定下一狀態概念上也正當，但 aos-fsm 採 stdout。）（10-15）
- **N-38**（10-15 定，草稿）fsm 出錯：那格結束碼非 0、stdout 吐了東西卻沒有一份完整 JSON 物件、沒輸出又沒寫表上 next、查不到那格、或 `next` 不在表裡也不在 `end`＝錯。**格沒輸出**（結束碼 0、stdout 空的）而表上寫了 `next`＝照表上 `next` 走，不算錯（10-15 使用者「按照建議」）。出錯時 **phase 不動**（下一拍重跑同一格），fsm 把那格的結果（N-30）原樣放進這拍 stdout 往外報，`error` 只說「格 X 結束碼 N」；**格的 stderr fsm 不讀、不轉**（C-52 切乾淨：格的錯是格自己的，要留就在那張 inst 寫 `stderr` 檔，N-26；想看子層靠那種機制，沒機制就不碰；10-15 深夜使用者「不能接受，拜託切乾淨」，原本把格 stderr 最後一份 N-29 錯誤放進 `error.msg` 已拿掉）；之後怎麼辦交給外層（拍它的 loop、上一層 fsm）或格自己。`error` 不再是特別的格：想優雅處理的格自己接錯、回 `{"next": "error"}`（或任何狀態名）；連錯幾次要停住，也是格自己數、自己回一個停住用的狀態（例 `halted`）——**agent 的格不數**（10-16，[N-53](10-基礎設施-定義與工作區.md)：重試幾次看外面 loop 的 `times`）。上一拍被殺一半（格跑了、phase 沒寫）＝下一拍重跑同一格，半成品由格自己看自己的檔判斷；重跑的冪等性不保證（N-20）。拍數上限由拍它的 loop 的 `times` 管，fsm 不計 `step`。fsm 的結束碼照 N-43：這拍正常＝0；格出錯、或 fsm 自己出錯（設定錯、窗缺、state 讀寫不了）＝非 0（10-15 收工後使用者定，原為「格出錯 fsm 退 0」）。（10-15 收工後依意見 1～4 Q1、Q4 改，[意見 1～4](../thinking/2026-10-15-opinions-1-4.md)；原有的 `error` 格跳轉、`error_from`、`last_error`、`running`、`step`／`max_steps`、`fails`／`max_fails`／`halted` 與「人改 state 窗接手」的 N-09 例外全部拿掉）（10-15）
- **N-39**（10-15 定，草稿）fsm 的窗：state 窗必填（N-19），只記 `phase`（現在狀態名），只有 fsm 自己寫（N-09）。fsm 不開 ctl、lock：暫停、停止、同時兩隻跑同一份，交給拍它的 loop（loop 的 ctl、串行拍）；一次呼叫一個新的 cwd 也擋得住重疊（意見 1～4 Q5、Q13）。心跳：fsm 是單次程式、壽命一拍，不適用 N-17／N-32 的每秒心跳，生死看拍它的 loop 的 state 窗；fsm 的 state 不寫時間、不帶 pid／started／boot_id（標準實作要不要每拍記時間未定，見[待定](08-待定.md)）。表裡的格指回自己（遞迴、同一份同時被拍兩次）fsm 不擋，卡死不防護（10-15 收工後使用者「好」）。（10-15 收工後依意見 1～4 改，[意見 1～4](../thinking/2026-10-15-opinions-1-4.md)；原本還記 `data`、`step`、`running`、`last_error`、`error_from`、`ctl_seq`、`fails`、`halted`，並有選填 ctl、lock 窗）（10-15）
- **N-40**（10-15 定，草稿）fsm 的 `end` 與巢狀：`end` 是名字的陣列，可以多個；名字可以在表裡、也可以不在。某格跑完回的 `next`：(a) 在表裡、不在 `end`＝照常進入；(b) 在表裡、也在 `end`＝進入，下一拍跑完那格的 inst，然後這個 fsm 結束；(c) 不在表裡、在 `end`＝直接結束，結果＝剛跑完那格的結果；(d) 不在表裡也不在 `end`＝錯（N-38）。**結束**＝這拍那行多 `"end": true`（拍它的 loop 寫了 `stop_on_end` 就看它停，N-44），把那格的結果原樣當自己這拍 stdout 的最後一份交出去（那格沒輸出就不交），phase 歸位到 `start`（10-15 收工後使用者定：「如果進入這個state，那就執行完該state的inst之後就退出，並且可以多選」「如果表裏面沒有這個狀態也可以……如果不在表裏而在end裏，那就是退出」，[意見 1～4](../thinking/2026-10-15-opinions-1-4.md)；原本只有 (a)(c)(d)，同名兩邊都放永遠不會結束）。巢狀：某格本身可以是另一個 aos-fsm（像階層式狀態機），內層每拍也只跑一步；**外層不需要、也不該知道那格是個 fsm**（C-52；10-15 深夜使用者「fsm就是他那一層」）——內層沒結束時 stdout 最後一份（它自己那行）帶 `"next": null`，外層照 N-37 留在原格，表上寫不寫靜態 next 都一樣；結束時交出去的是那格的結果，帶的 `next` 由外層照 N-37 看（那格沒輸出＝只交那行、不帶 next，外層看自己表上的 next）。原「巢狀格不宜寫表上靜態 next」拿掉。內層有自己的 state 窗（必填），從自己的 TARGET 拿設定，**不繼承外層的設定**（原「外層 cfg 當預設」與它對 N-21 的例外，10-15 收工後依 Q6 拿掉）。（10-15）
- **N-41**（10-15 定，草稿）一格怎麼跑是那格的事，規範中立：例如 think 格可以起來就等 LLM 回覆、處理完才結束（同步），也可以把請求寫進某個請求資料夾就結束、回 `{"next":"waiting"}`，下一拍再看回覆到了沒（非同步），兩種都合規，換一格即可；基礎實作先做同步版。兩種都不自己 setsid／fork 背景行程（限 fsm 的格；argv[0] 程式的通則另議，見[待定](08-待定.md)）。格裡放 loop／daemon 不禁止也不鼓勵，會阻塞一拍，靠那張 inst 的 `timeout_ms` 守。（10-15）
