## 待定（AI 整理的候選，使用者還沒定）

- **daemon 底下 loop 的 ret／err 檔在 `times: null` 時無限增長**：daemon 起的 loop 落 `work_dir/N/ret.json`、`err.json`（10-14 第 6 題），不限次數的 loop 會一直長。（10-14 下午）

- **aos-fsm 還沒寫成 N 條文**：方法表（`start`＋`states`，每格＝aos-inst TARGET）、`next` 走 stdout 最後一份、`error` 格、state 窗記 `phase`＋`data`（**state 窗必填**，已定＝N-19 擴到 fsm，10-14 夜）、可嵌套（出口 `end`）——目前只記在 [thinking 06～08](../thinking/2026-10-14-json-entry/06-fsm.md)，等動工時決定哪些進規範、哪些只是 aos-fsm 的程式說明。（10-14 傍晚）已定的方向（10-14 夜，[thinking 12](../thinking/2026-10-14-json-entry/12-七題回覆.md)）：規範只說「走到 think 狀態就跑那格 inst」，那格阻塞等 LLM 回覆或丟請求下一拍再看，**規範中立**，基礎實作先做阻塞版；「繼承」只是形容、不進規範；寫 agent 用一份 agent.json 或建資料夾都可以（inst TARGET 本來就兩種都收）。巢狀重跑的冪等已定＝N-20。

- **a～f 暫定預設**（使用者 10-14 夜說「先隨意」，AI 照 N-18 基礎實作精神各挑最簡單的一個；**全部暫定、可改**，出處 [thinking 12 §33](../thinking/2026-10-14-json-entry/12-七題回覆.md)）：
  - a. fsm 走到 `max_steps`＝當成那格出錯，走既有出錯規則（有 `error` 格跳去、沒有就留原狀態＋`last_error`）；不另發明 `failed`。
  - b. loop／daemon 自身 state 七態與 daemon 子項六態的 `starting`／`stopping` 撞名：不改名；兩套各在自己的窗（state 窗 vs `table.json` 子項），不會混。
  - c. ctl 改流水號後 state 回報欄位名＝`ctl_seq`。
  - d. daemon 的 save 檔與 `table.json` 窗合一：table 窗就是 save 檔，`--load` 讀 table 接回；不留第二份。
  - e. 「inst 的 exit 檔＝state」舊說法作廢：inst 不開窗；exit 檔只是與舊時代的橋樑（N-12）。
  - f. `policies.child_exit` 策略格＝一個 aos-inst TARGET（寫法同 fsm 格）；`children` 每項＝一個 aos-loop 設定的 TARGET（路徑、`檔#/位置` 或內嵌物件）。

- **h. 10-14 夜動工時代理人自定**（重做 inst／loop／daemon 遇到規範沒寫清楚的點，照 N-18 挑最簡單的；**全部暫定、可改**；D-1～D-6 已成 N-21～N-27、候選 g 已成 N-28）：
  1. 命令列沒給 TARGET 也沒給 `-`＝設定從 `{}` 起（只靠旗標與 `--`），不自動讀 stdin。
  2. 旗標每個都要帶一個值；值先當 JSON 解（`3`、`null`、`true`），解不了當字串；布林寫 `--cwd-mkdir true`。只認純量 key，其他＝UnknownFlag。
  3. stderr 的 JSON 形狀：錯誤 `{"error": {"code", "msg"}}`（同 N-10 的 error）、警告 `{"warning": {"code", "msg"}}`，一份一行。stdin 多份＝只看第一份、警告 `ExtraInput`。
  4. inst 的結果多帶 `id`；`code` 被訊號停掉＝128＋N（同 exit 檔），訊號號碼另放 `signal`。
  5. `id` 沒寫＝TARGET 的 realpath#/位置（不是 null）；從 stdin 來又沒寫才是 null。
  6. loop／daemon 結束總結的 `end`＝最後狀態字串（`"done"`／`"stopped"`）；每拍那份 `{run, code, ms}` 只在真的跑了 inst 時吐，daemon 沒 inst 就不吐、只吐結束總結（10-14 深夜改：原本沒 inst 也每拍吐一份 `code` null 的，200 毫秒一份太吵）。
  7. 心跳（N-17）：間隔 1 秒（不開 key）；state 加 `started`（/proc/<pid>/stat 第 22 欄）、`boot_id`、`beat`（寫的那一刻，epoch 秒），非 Linux 是 null。
  8. ctl 的 `seq`：寫的人自己帶，選填非負整數；沒帶＝`ctl_seq` null；舊的 `ctl_mtime` 回音拿掉。daemon 寫子 loop 的 ctl 時把 seq 加一。
  9. daemon 的 `times` 預設 null（loop 是 1）、`interval_ms` 預設 200（loop 是 0）：同名同義，但預設值不同，所以「沒寫 times 的 loop.json」丟給 daemon 會一直跑。
  10. daemon 的 `work_dir` 預設改成 state 窗旁的 `loops/`（control_dir 變選填了）；每個子項都有一格 `work_dir/N/`。
  11. table 窗的 key 叫 `table`（選填），`load` 改成布林（讀 table 窗接回）；`save` key 與 `save`／`load` 指令拿掉（暫定 d 的落實）。收工時表與 `work_dir/N` 留著，`remove` 才刪那格；沒 load 重起會用新的格子，舊格子不清。
  12. 策略格怎麼拿 stdin／stdout：daemon 把 `{id, code, exits, last_state}` 寫成 `work_dir/N/policy.in.json`、蓋過那格 inst 的 `stdin`／`stdout`（stdout 指到 `policy.out.json`），起 aos-inst 阻塞跑完、讀最後一份。出錯＝leave、警告 `PolicyFailed`。
  13. `children` 內嵌物件的 id＝它的 `id` key，沒有＝`daemon 的 id#/children/i`；相對路徑從 daemon 的 cwd 算。
  14. 接回孤兒只比 pid＋啟動時間（沒看心跳）；認領的孤兒沒有 Popen，結束靠 /proc 輪詢發現、拿不到結束碼（`last_code` null）。
  15. 子 loop 起不來的錯（例如 inst 寫錯）不在 add 當下報，落在 `work_dir/N/err.json`，子 loop 退出後照「子項結束」走策略格。
  16. tasks（proto8-1 的 aos-seq／par／if／not）的三扇門（10-14 深夜補）：起子 aos_inst 時它 stdout 那份結果接 /dev/null 丟掉（子程式的碼照舊讀 exit 檔）；tasks 自己的 stdout 不吐東西＝空的 JSON 串流，結果就是退出碼（N-12「stdout 可一份一份吐出、不強制」，最簡單的合規）；自己的錯誤用 aos_cli 的 `error()` 吐 `{"error": {"code", "msg"}}`。aos-tick 一樣：stdout 空、錯誤吐 JSON。

- **資料夾別亂弄的細則**：能不能動別人的資料夾、哪些檔是誰的。（「寫檔要不要先寫暫存再改名」已定＝N-05。）
- **argv[0] 程式的規矩**（10-12 做 tasks 時試出來，使用者同意「規範比實作重要」這個方向，細則沒定）：
  - 結束碼：0＝成功；自己的失敗用 1～123；124 以上有慣例意思（124 timeout、125～127 包裝程式自己出錯／不能執行／找不到、128＋N 訊號）。（10-12 夜使用者定：只有 0／非 0 是確定的，其他數字只供參考。aos_inst、aos_loop 的退出碼只說自己有沒有出錯，子程式的碼寫進 inst.json 的 exit 檔，10-14 夜重做後也放在 aos_inst 的 stdout 結果；125～127、128＋N 只是參考用的慣例。）
  - 收到 SIGTERM：收好自己起的子程式再退出。
  - 不自己 setsid 跑出行程群組（不然 daemon 整群收收不到）。
  - 錯誤寫 stderr。
- **kernel 公告**：公告欄在哪、格式、看到的人要做什麼、「逾時不候」之後 kernel 怎麼處理沒存好的。
- **時鐘**：回合數怎麼讀（aos-tick 的檔＝十進位＋換行）算不算規範，還是只是 aos-tick 這個語法糖的格式。
- **路徑寫法 `檔#/位置`**（JSON pointer）要不要列成大家都遵守的規範——出處 [thinking 10-13](../thinking/2026-10-13-json-path.md) §3、§3.2。
- **`_metainfo`**：inst.json 裡給 kernel 參考的抽屜（九軸、資源特性），inst 格式的可選 key（地位同 `argv`）、inst 與標準實作忽略；裡面格式自由，通用的寫法（含資源）之後規定——出處 [thinking 10-13 §3](../thinking/2026-10-13-json-path.md)。
