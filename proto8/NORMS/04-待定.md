- **a～f 暫定預設**（使用者 10-14 夜說「先隨意」，AI 照 N-18 基礎實作精神各挑最簡單的一個；**全部暫定、可改**，出處 [thinking 12 §33](../thinking/2026-10-14-json-entry/12-七題回覆.md)）：
  - a. fsm 走到 `max_steps`＝當成那格出錯，走既有出錯規則（有 `error` 格跳去、沒有就留原狀態＋`last_error`）；不另發明 `failed`。
  - b. loop／daemon 自身 state 七態與 daemon 子項六態的 `starting`／`stopping` 撞名：不改名；兩套各在自己的窗（state 窗 vs `table.json` 子項），不會混。
  - c. ctl 改流水號後 state 回報欄位名＝`ctl_seq`。
  - d. daemon 的 save 檔與 `table.json` 窗合一：table 窗就是 save 檔，`--load` 讀 table 接回；不留第二份。
  - e. 「inst 的 exit 檔＝state」舊說法作廢：inst 不開窗；exit 檔只是與舊時代的橋樑（N-12）。
  - f. `policies.child_exit` 策略格＝一個 aos-inst TARGET（寫法同 fsm 格）；`children` 每項＝一個 aos-loop 設定的 TARGET（路徑、`檔#/位置` 或內嵌物件）。

- **g. daemon.json＝loop.json 的超集、`inst`＝daemon 每拍的身體**（候選，使用者 10-14 夜末問「daemon.json 應該可以放 inst 吧」；出處 [thinking 13 §37](../thinking/2026-10-14-json-entry/13-動工前拍板.md)；**等拍板**）：
  - **現況**：loop.json＝外層 key（節奏 `times`／`interval_ms`／`interval_mode`、窗 `ctl`／`ctl_poll_ms`／`state`、收尾 `grace_ms`／`error_wait_ms`）＋ **`inst`（必填）＝身體**，每拍跑一次、阻塞到它結束。daemon.json＝同一組外層 key＋ `control_dir`／`load`／`save`／`work_dir`，**沒有 `inst`**（10-12 定：身體內建＝掃控制資料夾）；10-14 再加 `children`、`policies`、`table.json` 窗（暫定 d、f）。
  - **建議**：daemon.json 改成 loop.json 的**嚴格超集**——同名 key 同義；多 `children`（並行的長壽子 loop，暫定 f 不動）、`policies`、`control_dir`、`work_dir`；**`inst`＝daemon 自己每拍串行跑一次的身體**，選填（純監工不需要）。每拍＝收屍 → 掃 control_dir → 套策略格 → 跑 `inst`（有的話，阻塞；超時用它自己的 `timeout_ms`，跟 loop 一樣記 `last_code`／`last_error`）。`runs`、`times` 照舊數拍；`error_wait_ms` 跟著進 daemon。這就是「daemon 本身也是一個 loop」（C-36）的字面落實，kernel 也順：kernel＝daemon，`inst`＝每拍的 tick／tasks 身體，`children`＝agent 們的 loop。
  - **不採**：`inst`＝子項的預設／範本（children 已是 loop TARGET，要共用寫 `$ref` 即可）；`inst` 取代掃資料夾（N-10 要留）。
  - **連帶**：(1) 10-12 loop／daemon §2 那句「沒有 inst」改掉；lib `daemon.md`、`ctl-state.md` 的 key 分組把 `inst` 列進 daemon 的身體類（N-11：不能從 ctl 改）。(2) `control_dir` 建議改**選填**（指令資料夾是一種窗，沒給照 N-13 不開；這樣一份合法的 loop.json 丟給 aos-daemon 也能跑）——不改也行，只是超集不嚴格。(3) 子項放 inst.json（今天 `add` 已收、包成 `times: 1` 的 loop）與本題無關，`children` 可沿用同一個形狀判斷。(4) 基礎實作最簡做法：daemon 直接重用 loop 的拍引擎，每拍多做收屍／掃／策略，`inst` 空就跳過；沒拍板前先留縫、不做。

- **daemon 的 save 檔與 table 窗合一**：今天 save 存 `[{loop, ctl}]`，10-14 拍板的 `table.json` 窗（子項六態）會與它漂移；建議合成一份（table 窗就是 save 檔、load 就是接回）。出處 [thinking 09](../thinking/2026-10-14-json-entry/09-daemon套fsm.md)。（10-14 夜）→ 暫定採合一（上面 d 項），可改。

- **資料夾別亂弄的細則**：能不能動別人的資料夾、哪些檔是誰的。（「寫檔要不要先寫暫存再改名」已定＝N-05。）
- **argv[0] 程式的規矩**（10-12 做 tasks 時試出來，使用者同意「規範比實作重要」這個方向，細則沒定）：
  - 結束碼：0＝成功；自己的失敗用 1～123；124 以上有慣例意思（124 timeout、125～127 包裝程式自己出錯／不能執行／找不到、128＋N 訊號）。（10-12 夜使用者定：只有 0／非 0 是確定的，其他數字只供參考。aos_inst、aos_loop 的退出碼只說自己有沒有出錯，子程式的碼只寫進 inst.json 的 exit 檔；125～127、128＋N 只是參考用的慣例。）
  - 收到 SIGTERM：收好自己起的子程式再退出。
  - 不自己 setsid 跑出行程群組（不然 daemon 整群收收不到）。
  - 錯誤寫 stderr。
- **kernel 公告**：公告欄在哪、格式、看到的人要做什麼、「逾時不候」之後 kernel 怎麼處理沒存好的。
- **時鐘**：回合數怎麼讀（aos-tick 的檔＝十進位＋換行）算不算規範，還是只是 aos-tick 這個語法糖的格式。

- **`_metainfo`**：inst.json 裡給 kernel 參考的抽屜（九軸、資源特性），inst 格式的可選 key（地位同 `argv`）、inst 與標準實作忽略；裡面格式自由，通用的寫法（含資源）之後規定——出處 [thinking 10-13 §3](../thinking/2026-10-13-json-path.md)。
