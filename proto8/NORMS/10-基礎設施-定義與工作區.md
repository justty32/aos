# 基礎設施／定義與工作區

用詞（C-54）：**定義**＝「食譜」（一個 `.aos/` 資料夾）；**工作區**＝「廚房」（跑的時候的 cwd，命令列寫 `WD`）；**門房**＝`aos exec`。食譜、廚房是比喻，條文用正式名詞。

全部出自使用者 10-16 的決定（[稿 § 四](../thinking/2026-10-16-agent-inherit.md#四使用者決定10-16)），都是**草稿**；**程式還沒照改**，各條寫了「實作待改」的地方就是現況跟條文不合處。細節裡 AI 提了、使用者沒點頭的放在[待定](08-待定.md)。

- **N-46**（10-16 定，草稿）**正規參數入口是 stdin**（N-12）。`aos exec WD TARGET`、`aos agent 路徑`、TARGET 引數、鏡射旗標、`--` 這類 argv 寫法都是**語法糖**：方便人打，但規範與機制以「stdin 一份 JSON」那條為準，不得有只能靠 argv 才做得到的事。（使用者：「argv:[aos,agent,agents/brush]，其實，我一直覺得argv這塊的用法...就像我早期說的，正規參數入口就是stdin，像是aos-exec WD TARGET這個用法是語法糖...」）實作待改：現在 aos-inst／loop／daemon 還收 TARGET 與旗標（N-21～N-24），本條把它們歸成語法糖，程式先不動。
- **N-47**（10-16 定，草稿）**「定義＋這次在哪做」一律 `aos exec 工作區 定義`**（門房）：站進工作區；工作區還沒有 `.aos` 就把定義掛成工作區的 `.aos`（N-48）；然後跑 `.aos/inst.json`（照 N-46，把它灌給 `aos inst` 的 stdin）。適用所有東西：一支工作（inst）、一條 tasks 流水線、一個 loop、daemon 的子項、kernel 的判官、agent、工具（N-50）。（使用者：「前兩項我都OK」——「食譜 `.aos/`＋廚房 cwd」一律 `aos exec 廚房 食譜`，推廣到所有東西。）`.aos` 已存在且指別處、捷徑斷了、工作區要不要先存在等邊緣怎麼報錯，見[待定](08-待定.md)。實作待改：`aos exec` 還不存在（KISS 彙整批次 2 的 `aos-exec TARGET` 也沒做）。
- **N-48**（10-16 定，草稿）**定義與工作區用捷徑接**：定義是一個 `.aos/` 資料夾，入口是 `.aos/inst.json`；工作區裡放一條叫 `.aos` 的捷徑（symlink）指向它；**一個工作區一份定義**（要兩份就開兩個工作區）。**定義裡的檔互相指，一律寫 `.aos/x`，從工作區（cwd）算——跟 inst 現行「路徑從 cwd 算」同一條，沒有第二種路徑規則**；不靠 `$ref`（N-45）、不寫絕對路徑。在定義自己的資料夾裡跑也成立（那裡本來就有 `.aos/`，不用掛）。（使用者選捷徑：「捷徑。這塊細說」→「太優雅，太美了，這就是我要的。」）實作待改：現在找 inst.json 照 N-35 的 `$AOS_DIRNAME`；N-36 原本「fsm 格的路徑從設定檔所在資料夾算」那半句 10-16 已刪，fsm 格也一律從 cwd 算（實作待改，`aos_fsm` 還照舊）。
- **N-49**（10-16 定，草稿）**agent 的 stdin 只放一份，這份是定義**；**「這次的話」放在工作區裡**，使用時指定工作區的位置（以後可以有 `aos-agent-say`、`aos-agent-init` 這類語法糖）。agent 當函數是概念上的：定義（JSON＋資料夾）就是函數、工作區就是它的環境，**不造 `args.json`／`ret.json`／`frame.json`**（C-46）。（使用者：「stdin只放一份，這份要食譜。」「放在廚房裡，然後使用的時候指定廚房的位置。」）話在工作區裡叫什麼檔、什麼形狀、回答放哪，見[待定](08-待定.md)。實作待改：現在 agent 讀 frame 的 `args.json`、寫 `ret.json`、照 `frame.json` 的 `parent` 找名字（lib agent.md、frame.md）。
- **N-50**（10-16 定，草稿）**工具一律是定義資料夾，地址寫在呼叫者的定義裡、不用 PATH**：工具 `<名>` 的地址＝呼叫者定義裡的一條相對捷徑 `.aos/tools/<名>`（指向那個工具的 `.aos/`；`date` 這種一般指令也包成 `.aos/tools/date/`）。工具格對每一個工具做同一件事：**站在自己的工作區，開 `work/<n>/`，叫門房 `aos exec work/<n> .aos/tools/<名>`**；它不知道工具裡是不是另一個 agent（C-52）。**工具參數分兩層**：參數走門房（`aos exec`）的 stdin，由 stub／旗標明寫把它放進工具的工作區；裡面 agent 程式那層的 stdin 仍只放定義（N-49）；一般工具照 N-27（參數走 stdin）。（使用者：「可以不使用PATH嗎？」→「好!」；兩層：「還是不太懂，但感覺OK，就先這樣吧，以後再來搞懂。」）旗標叫什麼、做哪幾件事見[待定](08-待定.md)。實作待改：現在工具是 `tools` 裡的內嵌 inst、agent 當工具是三張 `sh -c` 工具 inst（lib agent.md）。
- **N-51**（10-16 定，草稿）**定義可以帶一個 shebang stub**：定義的 `.aos/` 裡放一個小檔，第一行寫「用 `aos exec` 在這裡跑我」（`#!/usr/bin/env -S aos exec …`），人就能在終端把定義當指令打（另在自己的 PATH 放一條捷徑指到它）。**體系內部不靠 PATH**（N-50）；PATH 只留給人。（使用者同意「食譜裡放 shebang stub＋捷徑」，之後再定「不用 PATH」，PATH 只留給人在終端用。）stub 上的旗標與 `env -S` 的版本要求見[待定](08-待定.md)。實作待改：還沒有 stub。
