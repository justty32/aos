# 基礎設施／資料夾程式與執行

（10-19 整份重寫；檔名沿用「定義與工作區」不改，連結多。）用詞（C-54）：**資料夾程式**（定義）＝一個資料夾；**入口**＝`$AOS_ENTRY` 指的可執行檔；**stack**＝被叫的程式自己的 `$AOS_STACK`（執行中狀態）；**小格**＝叫別的資料夾程式時給它的 stack；**工作區**＝使用者的檔與成品所在的資料夾（`ws`，C-65）。見[名詞表](../CONCEPTS/附錄1-名詞.md)。

N-57～N-60 是 aos 保證的底，使用者 10-19 的原話在 [ideas § 1～§ 5](../thinking/2026-10-19-ideas.md)；從 [CONVENTION](../CONVENTION.md) 原第一節（P-01～P-04）升上來。N-50、N-53、N-55 是 10-16 定、10-19 改字後留下的。其餘全是慣例（P-05～P-39，在 CONVENTION），不是大家都要守的。都是**草稿**。

- **N-57**（10-19 定，草稿）**aos 只訂三個環境變數**：`AOS_ENTRY`＝入口在資料夾裡的相對位置，預設 `.aos/exec`，**是可執行檔，或旁邊的 `$AOS_ENTRY.json` 單子**（可執行檔優先；兩隻 demo 都用可執行檔）；`AOS_WS`＝工作區（使用者的檔與成品在哪，N-55）；`AOS_STACK`＝被叫的程式自己執行中狀態放哪，預設 `$AOS_WS/.aos/`，**它的子程式的 stack 由它自己訂**，aos 不管巢狀（C-70）。（使用者 10-19：「純粹把資料夾作為lisp的list或lua的table，然後有一個entry……環境變數定義：AOS_ENTRY=.aos/inst，這個定義的目標必須是可執行檔。就這樣，非常簡單。」「首先，.aos/inst幫我改成.aos/exec，然後執行狀態這塊由agent-bob自己訂……所以我們再設定一個AOS_STACK=ws/.aos/。」「那就AOS_WS。」；[ideas § 1～§ 3](../thinking/2026-10-19-ideas.md)；`$AOS_ENTRY.json` 見 § 7 的 B；CONVENTION P-01）
- **N-58**（10-19 定，草稿）**`aos-exec DIR [WS [args...]]`＝「在 WS 這個工作區，執行 DIR 這個程式」**。WS 省略＝`-`；`-`＝沿用現有 `$AOS_WS`，沒設才用 `.`（呼叫當下的 cwd）；給路徑就用那個。慣例用法：`cd workspace && aos-exec ../agent-bob`。（使用者 10-19：「WS不寫的話預設是-，只是說當WS是-，但環境變數又沒有AOS_WS的時候，才會退回到.」；[ideas § 4、§ 5](../thinking/2026-10-19-ideas.md)；CONVENTION P-02）
- **N-59**（10-19 定，草稿）**aos-exec 只做五件事**：把 WS 轉絕對路徑設成 `AOS_WS`；`AOS_STACK` 沒設就設預設值、建資料夾，有設就沿用；把自己的 `bin/` 加進 PATH（入口才找得到 `aos-loop`、`aos-exec` 這些 aos 的指令）；`cd DIR`；`exec` 入口（可執行檔，或沒有它時交給 aos-inst 跑 `$AOS_ENTRY.json`），多的 args 與 stdin 原樣交給它。**起跑時 cwd＝DIR**；之後程式愛 cd 去哪、「這次要做啥」怎麼收，都是它自己的事（C-69）。（使用者 10-19：「entry這塊，『這次要做啥』，其實就隨意。……我們就是訂下一些環境變數，就這樣。」；CONVENTION P-03）
- **N-60**（10-19 定，草稿）**aos-exec 自己的錯一律退 1**：DIR 或 WS 不存在、入口缺或不可執行 → 非 0 結束（1）、stderr 一行原因（「aos-exec: 原因」）。（N-43；CONVENTION P-04）
- **N-50**（10-16 定，10-19 改，草稿）**工具＝資料夾程式，放在呼叫它的那一格的資料夾裡、不用 PATH**：工具 `<名>` 的地址＝`<格>/tools/<名>/`，格裡寫 `aos-exec tools/<名>`——從自己 cwd 算的相對路徑、永遠零個 `..`（N-59 起跑 cwd＝格自己的資料夾，所以埋在第幾層路徑都一樣長）。呼叫每個工具都做同一件事：給它一個**小格**（它自己的 stack，`AOS_STACK=$AOS_STACK/<名>/ aos-exec tools/<名>`）；不知道工具裡是不是另一個 agent（C-52）。工具要不要碰工作區、怎麼碰是工具自己的事，要碰就用 `$AOS_WS`（N-55）。工具的參數怎麼進（args、stdin、或 stack 裡的檔）由工具自己的說明定（N-27）。aos 自己的指令（`aos-exec`、`aos-loop`、`aos-fsm`、`aos-inst`）由 aos-exec 放進 PATH、入口裡直接寫指令名，那是 aos 的指令，不是工具；PATH 其餘的只留給人。（使用者 10-16 夜：「可以不使用PATH嗎？」→「好!」；10-19 改：捷徑、門房、參數兩層作廢，CONVENTION P-17、P-25、P-33）
- **N-53**（10-16 定，10-19 改，草稿）**aos 的 agent 是被外面驅動的狀態機**：agent 每次被叫只走一拍（跑現在那格、換狀態、退出），由外面的 loop 一拍一拍驅動——為的是讓 agent 方便審視自己（每拍之間狀態都落在 stack、看得到）。反覆幾次、隔多久是 loop 的事；idle 看沒題了退 10，loop 收到 10 就停（N-43、P-19）；agent 資料夾可以**帶 loop 當入口**（`aos-loop loop.json`，P-05、P-06；使用者 10-19 §1，[ideas § 9](../thinking/2026-10-19-ideas.md) 第 5 條裁定走今天的）。**某格出錯那一拍退非 0、state 不動**（同 N-38，下一拍重跑同一格）；**重試幾次由人或外面決定，agent 自己不數連錯**（P-20）。概念上 agent 只是一台狀態機、怎麼跑由誰跑都行（C-62）；本條只管 aos 自己的 agent。（使用者 10-16：「但是我們的規範會說，為了讓agent方便審視自己，所以agent就是一個被人驅動的狀態機，需要外面有人用loop驅動他。這是我們的aos agent」；頂層確認「腦出錯那一拍退 1、phase 不動，重試幾次看外面 loop，agent 自己不數」→「可以。」，[KISS 重審拍板 4](../thinking/2026-10-16-kiss-recheck.md#使用者拍板10-16)）**不採用**：AI 稿裡「`aos agent -` 自己一拍一拍跑到 end 才結束」。

## stack 與工作區（10-16 夜）

出自使用者 10-16 夜的決定（[稿 § 四](../thinking/2026-10-16-agent-inherit.md#四使用者決定10-16)；看完稿 § 八「三分鐘看懂（五）」：「我覺得不錯。不過是不是可以採用環境變數？所以cwd: WS? 具體命名幫我想想。」→ 頂層提 `AOS_WS` →「可以用$env啊」→ N-45 選 A：「A」）。概念 C-65～C-67。

- **N-55**（10-16 夜定，10-19 起 aos-exec 照做，草稿）**工作區的位置由環境變數 `AOS_WS` 給**（`ws`＝workspace，進[縮寫表](../CONCEPTS/abbr.json)）：呼叫方設，照 Linux 環境變數本來的樣子自然往下傳給所有子行程，巢狀多深都指同一個工作區、沒有人需要知道深度。資料夾程式跑的時候起跑 cwd 是自己的資料夾（N-59），**工作區保持乾淨**——執行時的東西（狀態、草稿、紀錄、小格）都放 stack，不放工作區（C-65；呼叫方自己把 stack 指到工作區是它的自由，C-67；`AOS_STACK` 的預設就是工作區裡的隱藏資料夾 `.aos/`，N-57）。單子裡讀它用 `$env`（N-45）。（使用者 10-16 夜：「除此之外，C語言函數想要影響外部變數，那也是透過指標」；「風險就設計者自己管控」）
