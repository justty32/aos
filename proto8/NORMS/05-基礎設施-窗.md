# 基礎設施／窗

## 控制：ctl 與 state

- **N-06** 控制一個會反覆跑的東西（loop、daemon）＝改它的 ctl.json。ctl.json 寫的是「我要它現在怎樣」，不是一條條指令：整份就是全部的期望，寫幾次都一樣；沒寫的欄位＝回它起來時那份檔（loop.json／daemon.json）的初始值，不是維持上一版；讀的人只讀不寫；誰都可以寫，後寫的算。（10-12）旗子通用：任何開了 ctl 窗的程式都認 `paused`／`stop`；`times` 等節奏 key 只有反覆跑的程式認（10-14 下午）。
- **N-07** ctl.json 認兩個旗子——`paused`（不再起新的一次）、`stop`（這次跑完就結束）——各寫成 `{"val": 布林, "now": 布林}`，`now` 為 true＝不等這次跑完、當場收掉；只寫布林＝只給 `val`；`stop` 壓過 `paused`。加上能蓋過 loop.json 外層執行方式的那幾個 key（`times`、`interval_ms`、`interval_mode`）。不認的 key 照 N-04。這兩個旗子不限 loop／daemon，開了 ctl 窗的程式都認；`times`、`interval_ms`、`interval_mode` 只有反覆跑的程式認（10-14 下午）。（10-12）
- **N-08** 讀 ctl.json 的人定期看；讀到壞的、型別不對、檔不見了，整份不採用、維持上一次的好狀態、印一次、不退出。（10-12）
- **N-09** 要回報狀態，寫到另一個檔（state），不碰 ctl.json；一個 state 檔只有被控制的那個東西自己寫；選填；沒給就不開、也不提醒（N-13；10-14 稍晚推翻了下午「提醒不是錯」的寫法）。例外：loop／daemon 的 state／ctl、fsm 的 state 必填，見 [N-19](05-基礎設施-窗.md)。（10-12）
- **N-11** 設定檔、ctl、state 是同一條線：「設定檔」＝程式啟動時合成、只讀一次的那份設定，不管來自檔（inst.json／loop.json／daemon.json）、stdin 還是 argv 旗標（10-14 下午改此定義）；它整份只在起來時讀一次（含 loop.json 裡的 `inst`），跑的途中要改只能走 ctl.json，ctl 蓋過設定檔，state 回報實際生效的值。三者裡節奏類的 key（跑幾次、隔多久、間隔怎麼算）同名；ctl 能蓋的只有這一類，位置、身體、收尾類的 key（`ctl`、`state`、`inst`、`grace_ms`…）不能從 ctl 改，要改就停了重起。state 的欄位、狀態值是慣例，見 [lib README](../lib/README.md#ctl-與-state-的慣例)。（使用者 10-12 夜）

## 內部狀態的外顯與窗的族譜

- **N-13**（10-14 定，草稿）state／ctl＝程式內部狀態的外顯（程式願意分享給大家的，像 Plan 9／FUSE），跟 stdin／stdout／stderr 完全無關。外顯位置由 stdin 參數指定；名字統一為 `state`、`ctl`；參數沒指定（沒這個 key 或明寫 `null`）＝不外顯，安靜不開、不提醒（10-14 稍晚：原「stderr 提醒」整條拿掉；10-14 夜再定 loop／daemon 的 state／ctl 與 fsm 的 state 例外——必填、否則報錯不執行，見 [N-19](05-基礎設施-窗.md)）。外顯後程式自己每隔固定時間同步（讀 ctl、寫 state）。ctl／state 的格式與語意照 N-05～N-11，本條只補位置與命名。FUSE 可選、以後再說；daemon 的控制資料夾（N-10）先不管。窗擴成一族（鎖、信箱、心跳…）見 [N-14～N-17](05-基礎設施-窗.md)。（10-14）
- **N-14**（10-14 定，草稿）窗一族總則：除了 state／ctl，鎖、號誌、信箱、公告、一問一答…都是窗，每種一條規範。共通：位置由 stdin 參數用攤平的 key 指定（例 `{"state": "s.json", "ctl": "c.json", "lock": "brain.lock/"}`），沒給照 N-13（不開、不提醒；loop／daemon 的 state／ctl、fsm 的 state 例外，必填，[N-19](05-基礎設施-窗.md)）；窗內自述種類（`kind`）；內容是 JSON；原子性只靠三種——rename（照 N-05）、mkdir／O_EXCL、flock；fsync 不強制；判斷變化比內容或序號，不比 stat；回音以序號 seq 為準（例：ctl 加 seq，state 回報 `ctl_seq`＝讀到第幾號；10-14 夜重做時已落實）；等變化輪詢保底、inotify 加速（/mnt/c 上 inotify 會靜默失效）。號誌、公告、一問一答的細節待實作時定，見 [IPC 研究頁](https://claude.ai/artifact/7QcbQjrK2h7U9LPcApwpvH)（AI 建議，未拍板）。FUSE 等效能很糟時再說。（10-14）
- **N-15**（10-14 定，草稿）鎖：鎖窗是一個資料夾，mkdir 建成功的人拿到鎖，在裡面寫名牌 `holder.json`（租約）；flock 只當同機加速。收屍看 pid（＋啟動時間）與租約：確認持有者已死或租約過期，搶的人可以自己收，帶序號防兩人同時收。（10-14）
- **N-16**（10-14 定，草稿）信箱：兩種都收——資料夾式（Maildir：tmp／new／cur，認領靠改名）＝一封封信；JSONL 追加檔（照 N-12 的 JSON 串流）＝一條流。（10-14）
- **N-17**（10-14 定，草稿）心跳：state 帶 pid、啟動時間、開機 id；內容沒變也每隔一段碰一下；超過 3 倍間隔沒動靜算疑似死亡（確定要看 pid＋啟動時間，N-15）。間隔預設值未定。loop／daemon 自身 state 的 `state` 欄是七態（`starting`／`waiting`／`running`／`paused`／`done`／`stopping`／`stopped`，各程式取子集）；daemon 的 table 窗子項另有六態 `phase`（`starting`／`running`／`exited`／`backoff`／`stopping`／`removed`）。`starting`／`stopping` 兩套撞名，**不改名**：兩套各在自己的窗（state 窗 vs table 窗子項），不會混（原暫定 b，10-15 使用者『全定』）。（10-14）

## 必填與細則

- **N-19**（10-14 夜定，草稿）loop／daemon（會反覆跑的程式）的窗位置 `state`、`ctl` 必須提供：缺 key 或明寫 `null` 都是錯，報錯、不執行。**aos-fsm 的 `state` 窗同樣必填**（10-14 夜使用者再定：fsm 每拍重起、靠 state 窗接上一拍，沒窗就不成 fsm；缺 key 或 `null` 一樣報錯不執行；巢狀的內層 fsm 也要有自己的 state 窗）。fsm 的 `ctl` 仍選填——巢狀內層不另開 ctl（[thinking 07 §12.4](../thinking/2026-10-14-json-entry/07-fsm樹與一拍.md)），不能強制。這是 N-09「選填」與 N-13「沒給就安靜不開」的例外，兩條只剩單次程式（inst、aos-llm、fsm 的方法程式等）適用。推翻 10-14 下午 Q9「沒給就不開、不提醒」對 loop／daemon／fsm 的部分。（10-14）
- **N-32**（原 h7，補 N-17，草稿）心跳間隔 1 秒（不開 key）；state 加 `started`（Linux＝/proc/<pid>/stat 第 22 欄）、`boot_id`、`beat`（寫的那一刻，epoch 秒），非 Linux 是 null。（10-14 深夜）
- **N-33**（原 h8，補 N-14 的 seq，草稿）ctl 的 `seq`：寫 ctl 的人自己帶，選填非負整數；沒帶＝state 的 `ctl_seq` 是 null；舊的 `ctl_mtime` 回音拿掉。state 回報的欄位名定為 `ctl_seq`（原暫定 c，10-15 使用者『全定』）。daemon 寫子 loop 的 ctl 時把 seq 加一。（10-14 深夜）
