# 基礎設施／窗

> 10-19：窗這一族（ctl、state、鎖、信箱、心跳）是給「反覆跑的東西」（daemon、kernel）用的，**現無實作**（舊實作在 git 歷史 aa2fec1f），照「資料夾＝程式」重寫 daemon 時再對。（10-20：ctl、state 兩扇已做，`proto8/bin` 的 aos-loop、aos-daemon。）agent 這層沒有 ctl：停＝退 10 或送訊號（P-19），內部狀態就是 `$AOS_STACK` 裡的檔（N-13、P-16）。

## 控制：ctl 與 state

- **N-06** 控制一個會反覆跑的東西（loop、daemon）＝改它的 ctl.json。ctl.json 寫的是「我要它現在怎樣」，不是一條條指令：整份就是全部的期望，寫幾次都一樣；沒寫的欄位＝回它起來時那份檔（loop.json／daemon.json）的初始值，不是維持上一版；讀的人只讀不寫；誰都可以寫，後寫的算。（10-12）旗子通用：任何開了 ctl 窗的程式都認 `paused`／`stop`；`max` 等節奏 key 只有反覆跑的程式認（10-14 下午）。（節奏 key 原叫 `times`，10-19 晚使用者定改用現行 loop.json 的 `max`，[ideas § 22](../thinking/2026-10-19-ideas.md)；`interval_ms` 日後當 loop 的選填 key 長出來，未實作。窗現無實作，等 daemon 照新做法重寫時用。10-20：兩件都已做，`proto8/bin`。）
- **N-07** ctl.json 認兩個旗子——`paused`（不再起新的一次）、`stop`（這次跑完就結束）——只收布林；`stop` 壓過 `paused`。要當場收掉正在跑的那次＝對它送訊號（原 `{"val", "now"}` 雙形、`now`＝當場收掉，10-12 定；10-15 深夜 KISS 批次 1 拿掉，見 [KISS 彙整批次 1](../thinking/2026-10-15-kiss/README.md#批次-1純刪彼此不相依不碰第四版的形狀已做10-15-深夜四個-commit自定點見-10-15-session-log) 1.4）。加上能蓋過 loop.json 外層執行方式的那幾個 key（`max`、`interval_ms`；`interval_mode` 隨 fixed 節奏一起拿掉，1.3）。不認的 key 照 N-04。這兩個旗子不限 loop／daemon，開了 ctl 窗的程式都認；`max`、`interval_ms` 只有反覆跑的程式認（10-14 下午）。（10-12；`times` 改 `max`，10-19 晚，ideas § 22）
- **N-08** 讀 ctl.json 的人定期看；讀到壞的、型別不對、檔不見了，整份不採用、維持上一次的好狀態、不退出，原因記進自己 state 窗的 `last_warning`（讀到好的就清掉）。（10-12；10-15 晚改：原為「印一次」（stderr 警告），照 N-43 正常退出不寫 stderr，使用者「都按照推薦。」，[盤點](../thinking/2026-10-15-principles.md) S1）
- **N-09** 要回報狀態，寫到另一個檔（state），不碰 ctl.json；一個 state 檔只有被控制的那個東西自己寫；選填；沒給就不開、也不提醒（N-13；10-14 稍晚推翻了下午「提醒不是錯」的寫法）。（10-12；fsm 的 state 見 N-13）
- **N-11** 設定檔、ctl、state 是同一條線：「設定檔」＝程式啟動時只讀一次的那份 JSON 檔（loop.json／daemon.json／fsm.json，命令列唯一的位置參數，像 `aos-loop loop.json`，可寫 `檔#/指標`＝那份檔裡那個位置的物件——10-21 傍晚改，原 `aos-loop --cfg loop.json`，[ideas 10-21 § 9](../thinking/2026-10-21-ideas.md#9-設定檔是唯一的位置參數path-改字串拼接10-21-傍晚)；新程式盡量不收旗標、不從 stdin 讀設定——10-19 晚使用者定「捨棄舊的」，[ideas § 22](../thinking/2026-10-19-ideas.md)；10-21 註：原「新程式不收旗標」，使用者 10-21 晚「新程式不收旗標...沒關係的，那是軟性，應該改成"盡量不收"」，[ideas 10-21 § 6](../thinking/2026-10-21-ideas.md#6-json-物件當資料夾一路往下aos_co10-21-晚)）；它整份只在起來時讀一次（含 loop.json 裡的 `run`），跑的途中要改只能走 ctl.json，ctl 蓋過設定檔，state 回報實際生效的值。三者裡節奏類的 key（跑幾次、隔多久）同名；ctl 能蓋的只有這一類，位置、身體類的 key（`ctl`、`state`、`run`…）不能從 ctl 改，要改就停了重起（例外：daemon 的 ctl 認 `children`，10-16 [N-54](04-基礎設施-loop與daemon.md)）。（使用者 10-12 夜）**10-21 下午**（使用者「loop.json還是需要的，至少我比較喜歡這個，寫好一次設定後就可以多次使用。然後旗標放前面確實比較好。」，[ideas 10-21 § 8](../thinking/2026-10-21-ideas.md#8-aos-loop10-21-下午)）：aos-loop、aos-daemon 收旗標——`程式 [--max N] [--interval-ms N] [--ctl 檔] [--state 檔] 設定檔`，旗標放設定檔前面、規則同 aos-exec（N-58）；旗標鏡射設定檔的 key（旗標名＝key 名底線換連字號），起跑時 旗標 ＞ 設定檔 ＞ 預設。**10-21 傍晚改**（使用者「--cfg是否可以簡化？比如aos-loop --cfg loop.json foo.json，簡化成aos-loop loop.json，然後loop.json內就包含各種東西？」，[ideas 10-21 § 9](../thinking/2026-10-21-ideas.md#9-設定檔是唯一的位置參數path-改字串拼接10-21-傍晚) H1～H3）：拿掉 `--cfg` 與命令列 XXX（原 `程式 [--cfg 設定檔] … [XXX [args...]]`、命令列 XXX 蓋過 `run`）——設定檔是唯一的位置參數，必給、只能一個，多給＝usage 錯；要跑什麼、帶什麼參數都寫在設定檔（`run` 可以是陣列 `[目標, 參數...]`）。aos-fsm 同規則（目前沒有旗標）。設定檔仍是起來時讀一次的那份 JSON；跑的途中仍只能走 ctl，ctl 蓋過前面三者（每圈讀一次、後到先贏），state 回報實際生效的值。

## 內部狀態的外顯與窗的族譜

- **N-13**（10-14 定，草稿；10-19 改，P-15、P-16）state／ctl＝程式內部狀態的外顯（程式願意分享給大家的，像 Plan 9／FUSE），跟 stdin／stdout／stderr 完全無關。外顯的檔落在 `$AOS_STACK` 底下，**名字與格式由程式自訂**（agent-bob 的 `state` 是純文字一行、另有 `trace.jsonl`）；需要 stack 的程式沒設 `AOS_STACK` 就退 1、stderr 一行原因（例 aos-fsm，N-38、N-39）；不外顯的就安靜不開、不提醒（10-14 稍晚：原「stderr 提醒」整條拿掉）。外顯後程式自己每隔固定時間同步（讀 ctl、寫 state）時，格式與語意照 N-05～N-11（現無實作）。FUSE 可選、以後再說。窗擴成一族（鎖、信箱、心跳…）見 [N-14～N-17](05-基礎設施-窗.md)。（10-14）
- **N-14**（10-14 定，草稿）窗一族總則：除了 state／ctl，鎖、號誌、信箱、公告、一問一答…都是窗，每種一條規範。共通：位置落在 `$AOS_STACK` 底下、名字由程式自訂（N-13）；窗內自述種類（`kind`）；內容是 JSON；原子性只靠三種——rename（照 N-05）、mkdir／O_EXCL、flock；fsync 不強制；判斷變化比內容或序號，不比 stat；回音以序號 seq 為準（例：ctl 加 seq，state 回報 `ctl_seq`＝讀到第幾號；10-14 夜重做時已落實）；等變化輪詢保底、inotify 加速（/mnt/c 上 inotify 會靜默失效）。號誌、公告、一問一答的細節待實作時定，見 [IPC 研究頁](https://claude.ai/artifact/7QcbQjrK2h7U9LPcApwpvH)（AI 建議，未拍板）。FUSE 等效能很糟時再說。（10-14）
- **N-15**（10-14 定，草稿）鎖：鎖窗是一個資料夾，mkdir 建成功的人拿到鎖，在裡面寫名牌 `holder.json`（租約）；flock 只當同機加速。收屍看 pid（＋啟動時間）與租約：確認持有者已死或租約過期，搶的人可以自己收，帶序號防兩人同時收。（10-14）
- **N-16**（10-14 定，草稿）信箱：兩種都收——資料夾式（Maildir：tmp／new／cur，認領靠改名）＝一封封信；JSONL 追加檔（一份份 JSON 接著寫）＝一條流。（10-14）
- **N-17**（10-14 定，草稿）心跳：state 帶 pid、啟動時間、開機 id；內容沒變也每隔一段碰一下；超過 3 倍間隔沒動靜算疑似死亡（確定要看 pid＋啟動時間，N-15）。間隔預設值未定。loop／daemon 自身 state 的 `state` 欄是七態（`starting`／`waiting`／`running`／`paused`／`done`／`stopping`／`stopped`，各程式取子集）；daemon 的子項另有六態 `phase`（`starting`／`running`／`exited`／`backoff`／`stopping`／`removed`）。`starting`／`stopping` 兩套撞名，**不改名**：兩套在不同的 key，不會混（原暫定 b，10-15 使用者『全定』；原寫「各在自己的窗（state 窗 vs table 窗子項）」，10-16 table 窗併進 daemon 的 state 窗（[N-28](04-基礎設施-loop與daemon.md)），七態在 state 窗頂層的 `state`、六態在 `children` 各項的 `phase`）。（10-14）**10-20 使用者「照預設」**（[ideas § 25](../thinking/2026-10-19-ideas.md)）：**心跳只在兩拍之間跳**——state 在拍與拍之間寫（每圈一次、睡著時每秒一次），拍正在跑時不另外碰；拍很長時 `beat` 會停在拍開始那一刻，確定死活照上一句看 pid＋啟動時間。

## 細則

- **N-32**（原 h7，補 N-17，草稿）心跳間隔 1 秒（不開 key）；state 加 `started`（Linux＝/proc/<pid>/stat 第 22 欄）、`boot_id`、`beat`（寫的那一刻，epoch 秒），非 Linux 是 null。（10-14 深夜）
- **N-33**（原 h8，補 N-14 的 seq，草稿）ctl 的 `seq`：寫 ctl 的人自己帶，選填非負整數；沒帶＝state 的 `ctl_seq` 是 null；舊的 `ctl_mtime` 回音拿掉。state 回報的欄位名定為 `ctl_seq`（原暫定 c，10-15 使用者『全定』）。daemon 寫子 loop 的 ctl 時把 seq 加一。（10-14 深夜）**10-20 使用者「照預設」保留這個回音**（[ideas § 25](../thinking/2026-10-19-ideas.md)；原列待定）：aos-loop、aos-daemon 已做；這版 daemon 收子項用訊號、不寫子 loop 的 ctl，「加一」那句暫時用不到。
