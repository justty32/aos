## daemon

> **daemon 兩義**：①[C-04](../CONCEPTS/01-設計理念.md) 說的 daemon＝aos 與 Linux 之間的借階層（Linux 那邊的事全在這層）；②這裡的 daemon＝管一群 loop 的程式（`aos-daemon`，C-36）。[名詞表](../CONCEPTS/附錄1-名詞.md)兩列都留。

- **N-10**（10-12 定；**10-16 使用者刪**）原「指令式控制資料夾」（往資料夾放 `名字.json`＝一條指令、回 `名字.json.done` 一問一答）整套刪。daemon 表上有誰改由 ctl 宣告（N-54）；暫停、停掉某個子 loop＝直接寫它的 ctl（N-06）；看它＝讀它的 state 窗。（使用者 10-16：「不留」，[KISS 重審拍板 1](../thinking/2026-10-16-kiss-recheck.md#使用者拍板10-16)）
- **N-28**（候選 g，10-14 夜末使用者拍板，草稿）**daemon.json 是 loop.json 的嚴格超集**：同名 key 同義（節奏、窗、收尾、`id`）。`run`＝daemon 自己每拍串行跑一次的身體（字串＝aos-exec 的目標，`aos-exec` 它；同 P-06。10-21 起只收字串，物件＝自己的錯，要內嵌單子寫 `daemon.json#/body`），跑法跟 loop 一樣（阻塞到它結束），在 daemon 裡**選填**（純監工不需要），在 loop 裡維持必填。daemon 多的是 `children`（並行、長壽的子 loop）、`policies`、`work_dir`、`adopt`。（原有 `ctl_dir`＝N-10 指令資料夾，10-16 隨 N-10 刪；table 窗 10-16 併進 state 窗，見下。）一份合法的 loop.json 直接丟給 aos-daemon 也要能跑。daemon 與 loop 同名 key 語義相同，預設值可不同（daemon `max` 預設不限、`interval_ms` 200；loop `max` 沒寫＝不限〔10-21 起；原 10〕、`interval_ms` 0）。（原 h9，10-14 深夜定：「沒寫 `max` 的 loop.json 丟給 daemon 會一直跑」；10-21 起 loop 自己也不限，兩者只差 `interval_ms` 的預設。）（key 名原為 `times`／`inst`，10-19 晚使用者定改用現行 loop.json 的 `max`／`run`，[ideas § 22](../thinking/2026-10-19-ideas.md)；`interval_ms` 等 daemon 才有的選填 key 日後當 loop 的選填 key 長出來，未實作。）`policies.child_exit` 是一張 inst 單子（寫法同 fsm 的格；子項結束時問它怎麼辦），`children` 每項是一份 loop 設定——路徑或內嵌物件，形狀同現行 loop.json（`{"run", "max", …}`）（原暫定 f，10-15 使用者『全定』）。**daemon 收子項只看它自己需要的**（C-52；10-15 深夜使用者「不留」）：是物件、沒 `run` 有 `argv` 就包成跑一次（當一張單子、`max` 1）、是資料夾程式就包成 `{"run": 它}`、ctl／state 沒寫就自己放；裡面的 loop key 與單子一概不驗、原樣灌給子 loop，寫錯了子 loop 自己退 1、錯在它的 stderr，daemon 只看到它結束（原 h15「add 先驗 inst」拿掉）。daemon 不另留 save 檔：**子項表寫在 daemon 自己的 state 窗**（`children` 一列一項：id、pid、啟動時間、`phase`…；10-16 改，原本另開一扇 `table` 窗，KISS 重審 3.3 照 Fable 推薦併進 state 窗），state 窗就是 save 檔。**`adopt`**（布林，**預設 `true`**；寫在 daemon.json 裡，新程式盡量不收旗標，N-11；10-21 註：原「新程式不收旗標」，使用者 10-21 晚「新程式不收旗標...沒關係的，那是軟性，應該改成"盡量不收"」）：daemon 重起時讀自己上次的 state 窗、把還活著的子 loop 接回（pid＋啟動時間對得上才認，N-17），不重起它們；寫 `false`＝不接回。第一次起來沒有舊的 state 就沒東西可接。心跳照 N-17／N-32 留。**子 loop 的輸出檔不無限長**（10-14 深夜使用者「隨你」、採方案 B）：基礎實作丟掉子 loop 的 stdout（結果一律從 state 窗讀），stderr 只在出錯時 append 到 `work_dir/N/err.json`；標準實作才做 stdout／stderr 選填路徑＋上限輪替、以及不接回時清掉表上沒列到的舊格子（[thinking 15](../thinking/2026-10-14-json-entry/15-ret與半份JSON.md)）。（10-21 註：N-18 10-21 改了說法，`proto8/bin` 的 aos-exec 算標準實作；這裡「標準實作才做」的幾件是標準實作待補，bin 版 aos-daemon 還沒做。）（使用者 10-16：「給選項，默認留」，[KISS 重審拍板 2](../thinking/2026-10-16-kiss-recheck.md#使用者拍板10-16)；key 名 `adopt` 是頂層照 C-54 挑的——說的是「認領活著的子 loop」，表窗併掉後已沒有一份「save 檔」可 load；取代原 `load`（預設 false，原暫定 d，10-15 使用者『全定』）。）推翻 10-12「daemon 沒有 inst、身體內建＝掃資料夾」。（10-14）10-19：子項若是資料夾程式，用 `aos-exec` 跑（[N-58](10-基礎設施-定義與工作區.md)）。現無實作，daemon 照「資料夾＝程式」重寫時再對。**10-20 落實**（`proto8/bin/aos-daemon`；使用者 10-20「照預設」，[ideas § 25](../thinking/2026-10-19-ideas.md)）：① `children` 寫成 `{名字: loop 設定}`——名字就是子項的 `id` 與小格 `$AOS_STACK/<名字>/`（P-17，取代 `work_dir`，stderr 落在小格的 `stderr`）；字串＝資料夾程式，包成 `{"run": 它}`；物件＝loop 設定，原樣交給子 loop。「路徑」與「沒 `run` 有 `argv` 就包成跑一次」這版沒做。② **子 loop 結束後不自動重起**：`phase` 停在 `exited`，要再起就從 ctl 的 `children` 拿掉再放回、或重起 daemon；所以 `policies.child_exit` 與六態裡的 `backoff` 這版沒做。③ 心跳只在兩拍之間跳（N-17）。收工照 P-36：不論為什麼結束都先收掉子項、寫好 state，收到訊號以 128＋N 結束（非 0）。**10-21 落實**（[ideas 10-21 § 8](../thinking/2026-10-21-ideas.md#8-aos-loop10-21-下午)、[計畫 10-21](../thinking/2026-10-21-plan.md) D1～D4）：命令列同 aos-loop（共用；`--cfg`、`--max`、`--interval-ms`、`--ctl`、`--state`，XXX＝daemon 自己的 `run`；`children`、`adopt` 只在 daemon.json）；起子 loop 改成 `aos-loop --cfg 小格/loop.json`；子項設定的 `run` 跟 loop 一樣只收字串（aos-exec 的目標，相對路徑從 daemon 的 cwd 算），內嵌單子寫 `{"run": "daemon.json#/children/<名字>/body", "body": 單子}`；寫成物件照樣原樣交出去，由子 loop 自己退 1、錯在小格的 `stderr`。字串子項＝aos-exec 的目標（不限資料夾，也可以是 `daemon.json#/…` 指進一張單子），包成 `{"run": 它}`。收工時「最後一圈之後才自己結束」的子項也標 `exited`、記 `code`，最後那份 state 不留 `running`（計畫 D7，第 2 段）。
- **N-54**（10-16 定，草稿）**daemon 表上有誰，寫在 daemon 的 ctl 窗**：daemon 的 ctl 多認一個 `children`＝「我要表上有誰」，每項寫法同 N-28 的 `children`；照 N-06 是整份期望——ctl 有 `children` 就照它（多出來的起、少掉的收掉移除），沒寫＝回 daemon.json 的 `children`。要暫停、停掉、改某個子 loop 的節奏＝直接寫它的 ctl（誰都可以寫，N-06），要看它＝讀它的 state 窗；daemon 回報實際的表在自己的 state 窗（N-28）。這是 N-11「ctl 只能蓋節奏類 key」的例外（頂層判斷：刪了 N-10 之後，增減子項只剩這條路）。（使用者 10-16 對 N-10：「不留」，照 [KISS 彙整 3.1](../thinking/2026-10-15-kiss/README.md) 原推薦；[KISS 重審拍板 1](../thinking/2026-10-16-kiss-recheck.md#使用者拍板10-16)）兩個人同時改 ctl 會互相蓋掉（後寫的算）：靠 Linux 檔案權限讓它只有一個寫的人（例 kernel 當這份 ctl 的唯一寫者），不另加機制（10-16 使用者，[C-64](../CONCEPTS/01-設計理念.md#檔案權限10-16-使用者定)）。現無實作，daemon 照「資料夾＝程式」重寫時再對（10-19）。10-20 已照做（`proto8/bin/aos-daemon`）：ctl 的 `children` 有寫就照它增減，名字已在表上的不看設定變了沒。**10-21**：每項寫法跟著 N-28 的「10-21 落實」（字串＝aos-exec 的目標、物件的 `run` 只收字串）；ctl 半路加進來的子項沒有檔可以指 `#/…/body`，要內嵌單子只能用字串目標指到別的檔、或寫絕對路徑指進 ctl.json（[計畫](../thinking/2026-10-21-plan.md) § 1.2 第 4 題）。
