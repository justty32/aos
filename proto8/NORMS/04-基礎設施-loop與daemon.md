# 基礎設施／loop、daemon

> 10-19：loop 現行做法是 `aos-loop loop.json`（`{"run", "max"}`，子程式退 10 就停，P-06、P-19），沒有 times／interval_ms／stop_on_end／ctl／state 窗。下面 daemon 的條文（管一群 loop 的程式）**現無實作**，舊版在 git 歷史 aa2fec1f；照「資料夾＝程式」重寫時再對。state／ctl 窗在[窗](05-基礎設施-窗.md)。

## daemon

> **daemon 兩義**：①[C-04](../CONCEPTS/01-設計理念.md) 說的 daemon＝aos 與 Linux 之間的借階層（Linux 那邊的事全在這層）；②這裡的 daemon＝管一群 loop 的程式（`aos-daemon`，C-36）。[名詞表](../CONCEPTS/附錄1-名詞.md)兩列都留。

- **N-10**（10-12 定；**10-16 使用者刪**）原「指令式控制資料夾」（往資料夾放 `名字.json`＝一條指令、回 `名字.json.done` 一問一答）整套刪。daemon 表上有誰改由 ctl 宣告（N-54）；暫停、停掉某個子 loop＝直接寫它的 ctl（N-06）；看它＝讀它的 state 窗。（使用者 10-16：「不留」，[KISS 重審拍板 1](../thinking/2026-10-16-kiss-recheck.md#使用者拍板10-16)）
- **N-28**（候選 g，10-14 夜末使用者拍板，草稿）**daemon.json 是 loop.json 的嚴格超集**：同名 key 同義（節奏、窗、收尾、`id`）。`inst`＝daemon 自己每拍串行跑一次的身體，跑法跟 loop 一樣（阻塞到它結束），在 daemon 裡**選填**（純監工不需要），在 loop 裡維持必填。daemon 多的是 `children`（並行、長壽的子 loop）、`policies`、`work_dir`、`adopt`。（原有 `ctl_dir`＝N-10 指令資料夾，10-16 隨 N-10 刪；table 窗 10-16 併進 state 窗，見下。）一份合法的 loop.json 直接丟給 aos-daemon 也要能跑。daemon 與 loop 同名 key 語義相同，預設值可不同（daemon `times` 預設不限、`interval_ms` 200；loop `times` 1、`interval_ms` 0），所以沒寫 times 的 loop.json 丟給 daemon 會一直跑（原 h9，10-14 深夜定）。（這裡的 `times`／`interval_ms` 是 daemon 與它管的子 loop 用的 key；現行 aos-loop 的 loop.json 只有 `max`（P-06），daemon 重寫時再對。10-19 補）`policies.child_exit` 是一張 aos-inst 單子（寫法同 fsm 的格；子項結束時問它怎麼辦），`children` 每項是一份 aos-loop 設定（路徑或內嵌物件）（原暫定 f，10-15 使用者『全定』）。**daemon 收子項只看它自己需要的**（C-52；10-15 深夜使用者「不留」）：是物件、沒 `inst` 有 `argv` 就包成跑一次、ctl／state 沒寫就自己放；裡面的 loop key 與 inst 一概不驗、原樣灌給子 loop，寫錯了子 loop 自己退 1、錯在它的 stderr，daemon 只看到它結束（原 h15「add 先驗 inst」拿掉）。daemon 不另留 save 檔：**子項表寫在 daemon 自己的 state 窗**（`children` 一列一項：id、pid、啟動時間、`phase`…；10-16 改，原本另開一扇 `table` 窗，KISS 重審 3.3 照 Fable 推薦併進 state 窗），state 窗就是 save 檔。**`adopt`**（布林，**預設 `true`**；旗標 `--adopt`）：daemon 重起時讀自己上次的 state 窗、把還活著的子 loop 接回（pid＋啟動時間對得上才認，N-17），不重起它們；寫 `false`＝不接回。第一次起來沒有舊的 state 就沒東西可接。心跳照 N-17／N-32 留。**子 loop 的輸出檔不無限長**（10-14 深夜使用者「隨你」、採方案 B）：基礎實作丟掉子 loop 的 stdout（結果一律從 state 窗讀），stderr 只在出錯時 append 到 `work_dir/N/err.json`；標準實作才做 stdout／stderr 選填路徑＋上限輪替、以及不接回時清掉表上沒列到的舊格子（[thinking 15](../thinking/2026-10-14-json-entry/15-ret與半份JSON.md)）。（使用者 10-16：「給選項，默認留」，[KISS 重審拍板 2](../thinking/2026-10-16-kiss-recheck.md#使用者拍板10-16)；key 名 `adopt` 是頂層照 C-54 挑的——說的是「認領活著的子 loop」，表窗併掉後已沒有一份「save 檔」可 load；取代原 `load`（預設 false，原暫定 d，10-15 使用者『全定』）。）推翻 10-12「daemon 沒有 inst、身體內建＝掃資料夾」。（10-14）10-19：子項若是資料夾程式，用 `aos-exec` 跑（[N-58](10-基礎設施-定義與工作區.md)）。現無實作，daemon 照「資料夾＝程式」重寫時再對。
- **N-54**（10-16 定，草稿）**daemon 表上有誰，寫在 daemon 的 ctl 窗**：daemon 的 ctl 多認一個 `children`＝「我要表上有誰」，每項寫法同 N-28 的 `children`；照 N-06 是整份期望——ctl 有 `children` 就照它（多出來的起、少掉的收掉移除），沒寫＝回 daemon.json 的 `children`。要暫停、停掉、改某個子 loop 的節奏＝直接寫它的 ctl（誰都可以寫，N-06），要看它＝讀它的 state 窗；daemon 回報實際的表在自己的 state 窗（N-28）。這是 N-11「ctl 只能蓋節奏類 key」的例外（頂層判斷：刪了 N-10 之後，增減子項只剩這條路）。（使用者 10-16 對 N-10：「不留」，照 [KISS 彙整 3.1](../thinking/2026-10-15-kiss/README.md) 原推薦；[KISS 重審拍板 1](../thinking/2026-10-16-kiss-recheck.md#使用者拍板10-16)）兩個人同時改 ctl 會互相蓋掉（後寫的算）：靠 Linux 檔案權限讓它只有一個寫的人（例 kernel 當這份 ctl 的唯一寫者），不另加機制（10-16 使用者，[C-64](../CONCEPTS/01-設計理念.md#檔案權限10-16-使用者定)）。現無實作，daemon 照「資料夾＝程式」重寫時再對（10-19）。
