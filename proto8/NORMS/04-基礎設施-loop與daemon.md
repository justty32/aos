# 基礎設施／loop、daemon

> 10-19：loop 現行做法是 `aos-loop loop.json`（`{"run", "max"}`，子程式退 10 就停，P-06、P-19；10-21 下午起寫成 `aos-loop --cfg loop.json`、也收旗標與 XXX；10-21 傍晚拿掉 `--cfg` 與 XXX，回到 `aos-loop [旗標] loop.json`、設定檔是唯一的位置參數，N-11）。**key 名以現行 loop.json 為準**（10-19 晚使用者定：「那就用到最新的吧」，[ideas § 22](../thinking/2026-10-19-ideas.md)）：身體叫 `run`、跑幾拍叫 `max`〔10-23 統合改名：`run` → `val`，[thinking](../thinking/2026-10-23-naming.md)〕，daemon 與窗的條文（N-06、N-07、N-11、N-28）都改用這兩個字；`interval_ms`、`ctl`、`state` 這些 daemon 才有的選填 key，日後當 loop 的選填 key 長出來（[rewrite-order ④](../thinking/2026-10-19-rewrite-order.md)）——10-20 已長出來，見下。下面 daemon 的條文（管一群 loop 的程式）10-19 時沒有實作（舊版在 git 歷史 5546be29），說好照「資料夾＝程式」重寫時再對；**現在 N-28、N-54 都有實作**（`proto8/bin/aos-daemon`；10-21 收旗標、D7，見 N-28、N-54 末的落實段）。**10-20**：daemon 照新做法重寫完（`proto8/bin/aos-daemon`，使用者對計畫的五點說「照預設」，[ideas § 25](../thinking/2026-10-19-ideas.md)），`interval_ms`、`ctl`、`state` 也已長成 aos-loop 的選填 key；跟下面條文不同的地方寫在 N-28 末的「10-20 落實」。state／ctl 窗在[窗](05-基礎設施-窗.md)。**10-22**：N-28、N-54 照 bin 程式核對後定稿（拿掉「草稿」，使用者「條文草稿那邊要去解決」，[ideas 10-22 § 5](../thinking/2026-10-22-ideas.md#5-loop10-22)）。

> **loop／daemon 不管、使用者自行承擔的事**（10-22 使用者，[ideas 10-22 § 5](../thinking/2026-10-22-ideas.md#5-loop10-22)）：① 每拍**沒有時間上限**：拍最後 exec 成可執行檔或 argv 陣列時，不理 SIGTERM 就一直等（拍是 inst 單子時由 aos-exec 照單子的 `grace_ms` 補 SIGKILL）——要上限自己加，例如在 `val` 指的單子或 argv 檔裡 argv 前面接 `timeout -k 5 60`（不加 `-k` 遇到不理 SIGTERM 的照樣等），或用單子的 `timeout_ms`；`val` 陣列的第一個是 aos-exec 的目標，不能直接寫 `timeout`。② 兩個 loop／daemon **共用同一份 state 檔**（本來就違反 N-09「一個 state 檔只有被控制的那個東西自己寫」）：寫的時間撞上時搶同一個暫存檔名、後到的當掉，沒撞上也會互相蓋掉內容——自己避免，或在外面接 s6-setlock 之類的鎖。③ **state 寫不了**（資料夾不見、沒權限…）時程式直接當掉、stderr 吐 Python traceback、結束碼 1，算 P-21「自己的錯 stderr 一行」的例外，接受；daemon 這時不收子項（不跑收尾），子 loop 留著跑，下次起來 state 讀得到就照 `adopt` 接回。④ loop 跑途中改 `.env`，因為 aos-exec 預設不蓋已有的環境變數（N-59 第 4 件），改過的值不生效，loop 也不會替每拍加 `--dotenv-override`——要蓋就自己在 `val` 指的單子 argv 寫旗標，旗標只管那次 aos-exec 走進的地方的 `.env`，所以要指回同一層（例 `{"val": "loop.json#/body", "body": {"argv": ["aos-exec", "--dotenv-override", "loop.json#/real"]}, "real": {"argv": ["aos-fsm", "fsm.json"]}}`），或重開 loop。
