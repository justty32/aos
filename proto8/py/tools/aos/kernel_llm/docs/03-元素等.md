## 元素

```
 _entry ──▶ 參數（--enable-counters、一個設定檔）──▶ round.run（骨架 ../kernel/round.py）
   讀設定：要 AOS_STACK → packs.read_cfg → hooks.load → llm_rules.find_host（AOS_DAEMON、掛信信箱）
   建信箱、鎖 requests/.flock
   collect：read_queue → count_run（有旗標）→ read_used → runner.read_table → write_window → cur/ 每封 runner.settle → deliver（ledger.append、add_used、before_reply、寄回信、撤回、整封刪）
   sweep → check（LetterBad 先回）→ 骨架排先後（row 驗不過的最前、其餘 rank＝order.sort）→ 逐封 before_verdict → admit（期限、額度、slots.room）→ after_verdict
   dispatch：認領進 cur/、寫 request.json、runner.mount（寄掛信、寫 proc.json）；refuse：回 {"error"}、整封刪
   finish：write_queue
```

每個口在 `llm_rules.py`（`collect`、`sweep`、`check`、`row`、`rank`、`admit`、`dispatch`、`refuse`、`finish`）；設定與能力包在 `packs.py`，排隊與 `queue.json` 在 `order.py`，格數在 `slots.py`，額度與 `used.json` 在 `budget.py`，逐封帳在 `ledger.py`；掛 proc、看表、重掛、逾時是框架的通用零件 [`../kernel/runner.py`](../../kernel/README.md)。各檔頭一句話說它負責什麼（README 的「零件」表）。

## 做法

- **一次跑完就結束、不常駐**：節奏、暫停、收工交給拍它的 daemon（C-47、C-38「它只是一個排程」）；一般就是那台 daemon 的身體（[kernel/llm-kernel](../../../../../templates/kernel/docs/01-llm-kernel.md)）。
- **問腦請 daemon 掛、kernel 不等**（使用者 11-05「問腦，他本身也可以包裝成一個aos函數，掛成proc去跑」「能包盡量包啦」）：一封＝一列 `llm_<信件名稱>`，`aos-daemon-ctl ls` 看得到；kernel 只寄信、讀窗（C-52）。
- **kernel 不懂腦**：端點、模型是 `endpoints` 裡的資料，原樣交給 endpoint 函數；金鑰由端點小定義的 `--key-env NAME` 指定，小 proc 自己讀環境，kernel 不讀、不寫、不轉交。kernel 只看結束碼與回信形狀（C-52）。要換家（Anthropic 原生、llama.cpp）＝再寫一個 endpoint 函數、`exec` 換指。
- **high 保留格只管補位、不搶占**：頂層 `reserved.high` 限制宣告 level 低於 high 的信只能補到總在飛數 `slots-reserved.high`；aging 只改排序、不改保留格資格。不能補的低級信跳過，繼續找後面的 high；端點包原有的 `slots` 與 backend 的 `slots`／`max_packs` 上限仍照算。
- **信箱用改名認領、flock 擋第二個 kernel**（N-14：只靠 rename、mkdir、flock）。寄信的撤信（`new/` → `tmp/`）跟 kernel 認領（`new/` → `cur/`）只有一個改得成。

後端狀態與黏著排序在 `order.py`，backend 歸屬與窗在 `packs.py`；三層格數的補位檢查在 `slots.py`，首次換包記帳在 `llm_rules.dispatch`，重掛不重算 switched。

## 錯誤代號

自己出錯：stderr 一行 **`kernel_llm: error: 代號 原因`**、退 1（N-60）。**一封信的錯不是 kernel 的錯**：寫進那封的回信，aos-llm 印成它自己的一行。

| 代號 | 誰 | 什麼時候 |
|---|---|---|
| `ArgumentsBad`、`FlagUnknown`（共用） | kernel | 沒給／多給設定檔、不認得的旗標 |
| `StackMissing`（共用） | kernel | 沒設 `AOS_STACK` |
| `DaemonMissing` | kernel | 沒設 `AOS_DAEMON`、指的不是資料夾（kernel 要住在 daemon 底下） |
| `MailboxMissing`（共用） | kernel | 沒設 `AOS_KERNEL`、而 `$AOS_DAEMON` 那台沒開 ctl 信箱（`procs_requests` 是 null） |
| `CfgMissing`、`CfgBad`、`DirectiveBad`（共用） | kernel | kernel.json 不在、指不到；不是物件、`slots`／`aging_cycles` 不是正整數、頂層 `reserved` 不是只含 `high` 的物件或 `high` 不是小於 `slots` 的非負整數、`backends` 不是物件、後端 slots／max_packs 不是正整數、`budget` 形狀不對（含 `senders` 不是物件、一格不是 `{"max_calls", "max_tokens"}`、兩個 key 算出同一個寄件人）、`exec` 沒寫或不是非空字串、`endpoints` 沒寫或不是非空物件、`endpoint` 不在表裡、`timeout_ms` 不是非負整數、被勾清單（同夾 `interfaces.json` 的 `hookeds`）寫壞；指示詞解不開 |
| `WriteFailed`（共用） | kernel | `queue.json`、`endpoints.json`、`used.json`、`counter_kernel_runs.txt`（開了 `--enable-counters`）、`proc.json` 寫不了、改名不了 |
| `CommandMissing`、`PostFailed` | kernel | `aos-post`、`aos-directive` 不在 PATH；信箱三格建不了、認領或收信的 `aos-post` 失敗（骨架） |
| `StateBad` | kernel | 骨架自己的檔（`bodies/` 等）讀寫不了 |
| `HookFailed` | kernel | hook 自己失敗（這輪退 1，見 [README](../README.md#hooks)） |
| `LockFailed` | kernel | 信箱被另一個 kernel 鎖著 |
| `ClockBad`（`tool_io`） | kernel | `AOS_CLOCK` 鐘檔讀不了（不存在時提醒並當 0 除外）或內容不是有效格數；沒有樹時鐘而需計算排隊格數時 `AOS_CLOCK_INTERVAL` 無效 |
| `QueueBad` | kernel | `queue.json` 在但讀不懂，含 backends 記錄型別不合 |
| `UsedBad` | kernel | `used.json` 在但讀不懂，而且 `ledger.jsonl` 不在或讀不了（重算不了）；或壞檔改名留底失敗 |
| `CounterBad` | kernel | 給了 `--enable-counters`，`counter_kernel_runs.txt` 在但內容不是非負整數（訊息叫人刪掉重來） |
| `LetterBad` | 回信 | `letter.json` 讀不懂、`body` 不是物件、沒有 `body.request`、`body.endpoint` 不是字串、priority 壞 |
| `RequestBad` | 回信 | `body.request` 不是物件、`messages` 不是陣列、`stream` 寫真；request 寫了那組 `fixed` 裡的 key、或那組有 `model` 而 request 寫了 `model`（`temperature is fixed by endpoint smart-high …`） |
| `EndpointMissing` | 回信 | 信沒寫 `endpoint`、kernel.json 也沒寫預設 |
| `EndpointUnknown` | 回信 | 信寫的代號不在 `endpoints` 表裡 |
| `DirectiveBad`、`CfgBad` | 回信 | 那組的指示詞解不開（環境變數沒設、檔讀不到）；那組不是物件、那組的 `exec` 不是非空字串、`slots` 不是正整數、`budget` 不是 `{"max_calls", "max_tokens"}`（寫了 `window`／`spent` 也算）、`speed` 不是 `fast`／`normal`／`slow`、`fixed` 不是物件 |
| `DeadlineBad` | 回信 | 輪到之前時限已過，沒跑 |
| `BudgetMissing` | 回信 | 這一窗的額度用完了（`spent` 是 `refuse`），沒跑；那包的 `budget` 到頂＝msg 開頭 `endpoint <代號>: max_calls N reached …`（不降級換包）；寄件人的到頂＝`budget.senders key "<key>" (sender <寄件人>): max_calls N reached …`。`msg` 之外 `error` 另帶 `scope`（`total`／`endpoint`／`sender`）、`window`、`since`、`resets_at`（`all` 為 null）、`limit`（`max_calls`／`max_tokens`）、`max`，endpoint 層多 `endpoint`、sender 層多 `key`；只有 `spent: "refuse"` 才回 |
| `LaunchFailed`（共用） | 回信 | 掛不上 daemon：掛信寄不進（含重掛時）、或 daemon 的 `state_flux.json` 中 `mailbox_warning` 說不收這封掛信 |
| `EndpointFailed` | 回信 | endpoint 函數退非 0 且 stdout 不是合格單行 error 物件（msg 帶 `reply.json` 或 `stderr.txt` 的第一行）、逾時、問腦跑了兩次都沒結果（被收掉或死在半路） |
| `ReplyBad` | 回信 | endpoint 函數退 0 但 stdout 不是 `{"message": 物件, …}` |
| `HookRejected` | 回信 | hook 退 10 攔下（`before_verdict` 拒信、`before_reply` 擋回信） |

## 建置與測試

Python，不用建置；`aos-exec` 跑這夾的 `_entry`，要 `aos-post`、`aos-directive`（設定裡有指示詞時）在 PATH 上。測試在 `tests/`：

```sh
cd proto8/py/tools/aos/kernel_llm/tests && python3 -m unittest test_ledger test_backends test_nesting test_stopped_slot test_two_machines test_hooks
```

`test_batch8_live`、`test_nesting_live` 要真的 daemon 與模型，平常不跑。
