aos 自己的幾家發事件的程式各有哪些 hook 點、各自的規矩（能不能攔、能改什麼、失敗停不停），一張表看完。

使用者 11-21：「發事件的程式自己決定」。下面每一家的規矩都寫在那一家的程式裡，宣告只是抄給人看（[02](02-宣告格式.md)）。

## 總表

| 家 | 點 | 誰發 | 能攔（退 10） | 能改（退 0 的 stdout） | hook 失敗 |
|---|---|---|---|---|---|
| **agent 一家**（規矩：[`agentlib/hooks.py`](../../../agentlib/hooks.py) 的 `POINTS`） | `before_queue` | agent-fsm 的 idle、aos-eca-turn | 丟掉這封信 | `content`（非空字串） | **停**（HookFailed，agent 停下） |
| | `after_queue` | 同上 | — | — | 一行 warning，下一個照跑 |
| | `before_tool` | agent-fsm 的 act、aos-mcp | 工具不跑，腦看到 stdout | `arguments` | **停**（aos-mcp：那次工具回 isError，agent 不停） |
| | `after_tool` | 同上 | — | `content`（字串） | 一行 warning |
| | `brain_failed` | agent-fsm 的 wait、aos-eca-turn | — | — | 一行 warning |
| | `tool_added` | agent-fsm 的 think、aos-eca-turn | — | — | 一行 warning |
| | `on_clock` | 每格（eca：每輪）開頭的 `clock_tick` | — | — | 一行 warning |
| **aos-loop 四點**（規矩：aos-loop 本身；loop.json 經 `aos-hook fire -q --stop-on-nonzero --def $AOS_CD` 發） | `after_start` | loop 起來、第一次跑身體之前 | — | — | loop 收工（起不來） |
| | `after_stop` | loop 要退時 | — | — | 本來要退 0＝改退 hook 的碼；本來就非 0＝一行 warning |
| | `before_run` | 每跑一次身體之前（有接線才發） | **跳過這一圈** | — | loop 收工 |
| | `after_run` | 每跑一次身體之後（有接線才發） | 退 10 也算失敗 | — | loop 收工（身體自己結束 loop 時只 warning） |
| **eca 的壓縮兩點**（規矩：eca-claude 範本的 `compact_hook`，經 `aos-hook fire --def $AOS_CLI_DEF` 發、自己讀結果） | `before_compact` | Claude Code 要壓縮對話前（`PreCompact`） | 不壓（第一個退 10 的） | `instructions`、`restore`（依名字順序，後蓋前） | 一行 warning，照沒有這個 hook |
| | `after_compact` | 壓完（`PostCompact`） | — | — | 一行 warning |
| **kernel 三點**（規矩：[`tools/aos/kernel/hooks.py`](../../../../tools/aos/kernel/hooks.py) 的 `POINTS`） | `before_verdict` | 新信在內建規則之前 | 拒信（HookRejected，或 stdout 說 BudgetMissing） | `body` | **停**這一輪（HookFailed），下一輪重來 |
| | `after_verdict` | 判完一次 | 拒信 | `verdict`、`error`、`next` | **停**這一輪 |
| | `before_reply` | 代回下游的回信之前 | 改代回 HookRejected | `body` | **停**這一輪 |

一句話記：**能攔的點失敗就停，只是通知的點失敗只 warning；loop 四點失敗 loop 收工。**（agent 一家的分法是施工線替使用者挑的，[施工 02 第 1 條](../../../../../thinking/2026-11/21/hook-新格式施工-1121/02-替使用者做的選擇.md)：以前預設一律停、出廠 hook 卻全寫 `on_error: continue`。）

## 各家細節

**agent 一家**（agent-fsm 四格、aos-eca-turn、aos-mcp 共用一份規矩與遙控器 [`agent_hooks.py`](../../../agentlib/agent_hooks.py)）

- 照名字跑，前一個改的後一個看得到；被攔就不往下。`condition` 只在 `before_tool`／`after_tool`／`tool_added`／`brain_failed` 比（[04](04-掛hook.md#只攔某支工具condition)）。
- 不能攔的點收到 10＝當 0。能改的點 stdout 不是 JSON 物件、或改的值型別不對＝失敗。
- 每個事件的欄位、on_clock 的時鐘規矩：[apps/agent/docs/06-hook](../../agent/docs/06-hook.md)。

**eca 跟 agent-fsm 不一樣的地方**（細節 [06-hook「eca（縮水版）」](../../agent/docs/06-hook.md#eca縮水版)、[templates/docs/01](../../../../../templates/docs/01-eca-claude.md)）

- `before_tool`／`after_tool` 只看得到經 aos-mcp 叫的 aos 工具；CLI 自帶的工具（Bash、Read…）與人在畫面上打的字 aos 看不到（要擋 CLI 自己的工具用 CLI 自己的 hook，知識庫 `aos/cli/eca.json#/cli_hooks`）。
- `before_queue` 連 slash 信也過；`on_clock` 每輪看一次。
- `before_compact`／`after_compact` 只有 claude 身、`cli.json` 掛了範本的 `compact_hook` 才發；pi、codex 不發。`restore`（壓完要補回對話的一段字）只能在 `before_compact` 交（實測 Claude Code 的 SessionStart 比 PostCompact 早跑）。每個 handler 拿同一份事件（不串改）。

**aos-loop 四點**（宣告 [loop_hooks.json](../loop_hooks.json)）

- 事件 JSON 只有 `event`、`hook`、`stack`；loop 知道的東西在 handler 的環境變數：`AOS_LOOP_CODE`／`AOS_LOOP_SIGNAL`／`AOS_LOOP_CAUSE`（after_stop）、`AOS_LOOP_RUNS`（before_run／after_run）、`AOS_LOOP_RUN_CODE`／`AOS_LOOP_RUN_SIGNAL`／`AOS_LOOP_RUN_MS`（after_run）；fsm 身體的格在 `<stack>/stage.txt`。
- 每個 handler 拿同一份事件；第一個非 0 就停，碼原樣交給 aos-loop。
- `before_run`／`after_run` 只在 `loop.json` 有 `on_before_run`／`on_after_run` 時發（編譯時決定，[04](04-掛hook.md#loop-的點before_runafter_run-要重新編譯並重起)）。agent 的一次＝agent-fsm 一格、eca 一輪；kernel 的一次＝一輪。
- kill -9 不跑 `after_stop`；pause 不算停下。aos-daemon 自己的 `on_start`／`on_stop` 失敗也收工，但它不收 before_run／after_run。

**kernel 三點**（宣告 `kernel_hooks.json`，正本在 [tools/aos/kernel](../../../../tools/aos/kernel/kernel_hooks.json)、每個 kernel 定義夾一份抄本）

- 被勾清單：定義夾 `interfaces.json` 的 `hookeds`（範本與編譯都寫 `kernel_hookeds.json`）；kernel 三點與 loop 四點的格放同一份。`kernel.json` 不再有 `hooks`。
- 照名字跑，前一個改的後一個看得到；`after_verdict` 的 `condition` 比 `verdict`。
- 沒有「只 warning」的選項：失敗＝印 `kernel: error: HookFailed …`、這輪退 1，信留著下輪重來。
- llm kernel（`kernel_llm`）同一套三點。細節：[kernel README「hooks」](../../../../tools/aos/kernel/README.md#hooks)；agent 自己當一站：知識庫 `aos/kernel.json#/gate`。

**gdb**（掛 hook 的一方，不是發事件的一方）

- 觸發型斷點＝agent 身上一個普通 hook（`gdb_0003` 這種名字，handler `lib/tools/agent/gdb_trigger`）。它自己壞了只印一行 warning、退 0，stdout 不印，所以不會讓 agent 停。
- 能下斷點的種類寫在 gdb 程式裡：agent 一家的點（去掉 on_clock）＋ `before_compact`／`after_compact` ＋ loop 四點（「從宣告讀」還沒做，[07](07-限制與還沒做的.md)）。細節：[apps/gdb/README](../../gdb/README.md)。

**出廠的 hook**：agent-fsm 範本帶 `timer`、`mail_notify`、`context_wrap`（on_clock）、`brain_notify`（brain_failed）；eca-claude 同樣四格，另帶 `screen_linger_start`／`screen_linger_stop`（after_start／after_stop，自己出錯只 warning、退 0，所以不會擋 eca 起停）；eca-pi 只有 `timer`、`mail_notify` 與那兩格 screen_linger。都掛在不能攔的點上。
