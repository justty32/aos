自己做一個會發事件的程式：用 aos-hook fire（兩種退出碼模式）、直接叫 Python 引擎、或完全自己來；非 Python 的程式怎麼用。

使用者 11-21：「發事件的程式自己決定 <- 沒錯，我們提供的hook fire本身會參與這個過程，所以也算在其中。如果有人不想用我們的aos-hook fire，那就弄他自己的。」；11-20「任何子程式，含非Python」。

## 三條路

| 路 | 適合 | 你要做的 |
|---|---|---|
| **`aos-hook fire`** | 任何語言（shell、C++、Go…），能起一支程式就行 | 在那個時刻起一次 `aos-hook fire`，自己讀結果 |
| **Python 直接叫引擎** | Python 寫的程式，不想每次多起一支行程（約 36 毫秒） | `aos.hook_lists.load(paths)` 讀清單、`aos.hook_run.fire(event, data, entries, stack)` 跑 |
| **完全自己來** | 不想用 aos 的清單格式或引擎 | 自己讀自己的清單、自己起 handler；aos 不管 |

不管哪條路，**宣告都是選的**：寫一份 `hooks.json` 讓人知道你會發哪些點、handler 收到什麼（[02](02-宣告格式.md)）；不寫照樣跑、照樣有人能掛。

## 用 aos-hook fire

掛 hook 的人寫一份被勾清單（跟 agent 的 `hookeds.json` 同一種格）：

```json
{"description": "What is hooked on before_save.",
 "a_deny": {"event": "before_save", "handler": "a_deny", "timeout_ms": 5000},
 "b_rename": {"event": "before_save", "handler": "b_rename"}}
```

你的程式在那個時刻：

```sh
out=$(printf '{"file": "%s"}' "$f" | aos-hook fire --list "$HERE/hookeds.json" --stack "$STATE" before_save)
```

**兩種退出碼模式**：

| 模式 | 結束碼 | stdout | 適合 |
|---|---|---|---|
| 預設 | 一律 0（handler 退什麼都一樣；沒人掛也 0） | 一行 JSON：`{"event", "hooks": [{"hook", "code", "stdout", "error"}, …]}`，每個 handler 都跑 | 讀得懂 JSON、要自己定規矩（誰退 10 算攔、拿誰的 stdout 改） |
| `--stop-on-nonzero`（常配 `-q`） | 第一個非 0 的 handler 的碼（10 不印錯誤行；其他碼印 `aos-hook: error: HookFailed …`；逾時／起不來＝1） | 同上（`-q` 不印） | 只看得懂結束碼的程式（aos-loop 就是這樣用） |

兩種模式下 `aos-hook` 自己出錯都是退 1、stderr 一行 `aos-hook: error: CODE reason`（`ArgumentsBad`、`HooksBad`、`InterfaceBad`、`StackMissing`…），所以 `--stop-on-nonzero` 時 handler 退 1 跟 `aos-hook` 出錯分不出來，要分就用預設模式讀 JSON。

清單從哪來二選一：`--list FILE`（可重複，後蓋前、`null` 關、檔不在＝沒有 hook）或 `--def DIR`（`DIR/interfaces.json` 最外層的 `hookeds`，相對的那幾份再疊上 stack 裡同名那份）。`--stack DIR` 是 handler 工作夾的上層（`DIR/hookeds/<名>/`），沒給用 `$AOS_STACK`。

自己讀結果的例子（誰退 10 就當攔下、退 0 的 stdout 拿來改）與 C++ 的寫法、實跑輸出：[../README.md](../README.md)。

要注意：

- 事件資料只走 stdin（JSON 物件）。從別的程式起 `aos-hook` 時 stdin 要嘛給 JSON、要嘛接 `/dev/null`：接著一條不關的管子它會一直等。
- 每個 handler 拿同一份資料（不串改）；要「前一個改的後一個看得到」，用 Python 自己一個一個跑（agent 一家、kernel 就是這樣）。
- 發事件時沒人掛＝`"hooks": []`、退 0；事件名不驗。

## Python 直接叫引擎

```python
import os
from aos import hook_lists, hook_run
entries = hook_lists.load([os.path.join(here, "hookeds.json")])      # {名: 格}，壞＝HooksBad
for r in hook_run.fire("before_save", {"file": name}, entries, state_dir):
    if r["code"] == hook_run.BLOCK: ...                               # 你的規矩
```

- `hook_run.run(name, entry, event, data, stack)` 跑一個（要串改就自己迴圈、每次把改過的 data 傳下去）；`hook_run.names(entries, event)` 給排好序的名字。
- 要讀 `interfaces.json` 的 `hookeds`：`aos.hook_point.layers(def_dir, stack)` 給要讀的清單路徑（定義的、再疊 stack 的）。
- `load(paths, check)` 的 `check(entry)` 可以加你自己的鍵檢查（agent 一家用它驗 `condition` 與 on_clock 的鍵）。
- 介面寫在三支的檔頭：[hook_run.py](../../../hook_run.py)、[hook_lists.py](../../../hook_lists.py)、[hook_point.py](../../../hook_point.py)。

## 非 Python 的程式

- **發事件**：起 `aos-hook fire`（上面）。C++ 不用 link 任何 hook 的東西；aos-loop 本身就是這樣接 loop 四點的（loop.json 的 `on_start` 等四鍵寫成 `aos-hook fire -q --stop-on-nonzero --def …`）。
- **當 handler**：任何 aos-exec 跑得動的程式（[03](03-寫handler.md#handler-是什麼)）。stdin 一行 JSON，用 `jq` 或 `read -r` 讀就行；`$AOS_STACK` 是它的工作夾。
- **掛 hook**：寫 JSON（被勾清單）或叫 `aos-agent hook add`，都不用 Python。

## 要讓別人知道你的點

在你的程式的 `interfaces.json` 最外層寫 `"hooks": "hooks.json"`、`"hookeds": "hookeds.json"`，旁邊放這兩份；用 `--def` 發的話別人掛在 `hookeds.json`（或 stack 裡同名那份）就生效。`aos-agent hook` 是給 agent 用的（要指一隻 agent），你的程式的清單由人直接編，或你自己做一個指令改。
