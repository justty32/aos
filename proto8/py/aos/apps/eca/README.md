# aos-eca — 外部 coding agent（claude／codex／pi）的兩支指令

← [cmd](../../../docs/05-commands.md)｜範本：[templates/eca-claude](../../../../templates/docs/01-eca-claude.md)、[templates/eca-pi](../../../../templates/docs/03-eca-pi.md)

- `bin/aos-eca-turn`：答一輪——從 stack 的 queue 認領一批、交給 CLI 就收信、回答接進 history。說明在 [05-commands/01](../../../docs/05-commands/01-逐支說明.md#逐支說明)。
  **畫面開著的 claude 身改走收件口**（[eca-a2a-notify](../../../../thinking/2026-11/13/eca-a2a-notify.md)，使用者 11-13「1.a2a這個按照建議。馬上送，eca他會自己處理。say/chat被當成不是使用者打的，我覺得可以，真的有要的話，就自己open進去說。」）：一批信不貼字，改往 Claude Code 這個 session 自己的收件口（cross-session messaging 的 Unix socket）寫，一封一個署名信封，畫面顯示「› Message from @名字: …」、CLI 自己告訴模型這則不是它的使用者打的。署名＝信 body 的 `name`（`aos-agent say`／`chat` 對 eca 寄時填，見 [aos-agent](../agent/README.md)），沒有＝`aos通知中心`（新信通知、時鐘信、goal 提醒、開場白、換台前情提要）；`name` 不接進 history。這條路不看 `--on-busy`：有人接在畫面上、正在跑一輪都照投（CLI 手上那步工具做完就讀到）；等回答時 queue 又來信也一封一封馬上投（`aos_eca/midturn.py`，slash 指令、hook 或 aos-post 出錯、投不出去、冷卻剛到那輪除外，那封留到下一輪）。socket 位置與有沒有收到靠畫面 hook 記在小格的 `a2a.json`、`a2a_acks.jsonl`（`py/aos/agentlib/cli_a2a.py`）；沒記到、投不出去、投了 30 秒沒回執＝退回貼字（後者這個畫面之後都貼，到下一次 SessionStart）。接線前開的畫面要關掉重開才換新路。關掉：定義的 `cli.json` 寫 `"a2a": false`。畫面沒開、codex 身、slash 指令、工具形照舊。
  **history 被改過＝下一輪開新 claude 對話**（self-family ⑩）：靠小格的 `.history_sum` 認出來，帶改過的紀錄過去；畫面開著不換。細節同上。
  **turn 死了外部 CLI 跟著收**（坑-52，Linux）：非互動起的 claude／codex 設了 `PR_SET_PDEATHSIG`＝SIGTERM，aos-eca-turn 被 `kill -9`／OOM（或它的 aos-loop 被殺、經 aos-inst 的 PDEATHSIG 連帶）時 CLI 收 SIGTERM，不留孤兒跟下一輪的 `--resume` 寫同一段對話；tmux 畫面裡的 CLI 不在此列（`cli_print.parent_death_term`）。
  **hook（eca 縮水版）**（[hook 圖紙 § 6](../../../../thinking/2026-11/10/self-family/hook/01-圖紙.md#6-eca-縮水版)）：定義的 interfaces.json 最外層寫了 `hookeds`（被勾清單）時，這支跑 `before_queue`／`after_queue`／`brain_failed`／`tool_added`，`before_tool`／`after_tool` 在 aos-mcp，`before_compact`／`after_compact` 由 eca-claude 範本的 `compact_hook`（Claude Code 自己的壓縮 hook）經 `aos-hook fire` 發（11-21）；有哪些、沒有哪些見 [templates/docs/01](../../../../templates/docs/01-eca-claude.md)。
  **slash 指令**（[eca-slash](../../../../thinking/2026-11/12/eca-slash.md)，⑭）：`aos-agent say／chat` 送一封剛好是 `/clear`、`/compact`、`/status`、`/usage`、`/exit` 的信＝aos 這層做（claude -p 認得的 `/compact`、`/usage` 交給 claude），回一則 `[aos] slash: …`，listen 照拿；`/clear` 連 history 一起清、claude 的 `/compact` 把 history 換成它的摘要（原文都搬到 `history_removed.jsonl`）；畫面開著時這兩個打進畫面。`/goal …`（以它開頭就算，含 `/goal clear`）是 CLI 自己的 goal：畫面開著打進去、沒開交給 claude（codex 回一句請開畫面），跟 aos 的 goal.json 不同步；codex 已有 goal 時跳的「Replace goal?」aos 自動選 1（Replace current goal），認不得就不按。畫面上打的由畫面 hook 跟上（`cli_hook.follow_session`／`clear_history`／`compact_history`；codex 換到剛開的 thread＝清、同一段 thread 被壓過＝history 換成它壓縮後留下的對話）。沒畫面時交給 claude 的 `/goal …`、`/compact` 跟一般一輪一樣：交出去就收信、user 接進 history，claude 失敗＝這封掉了、fire `brain_failed`、記冷卻。
  **暫時 API 錯誤續做（只限 claude print 形）**：交出去之後，result 行標成暫時 API 錯（429、408、409、5xx、overloaded、connection failed 或 CLI 自己的 api_retry 用盡）時，這輪退 0、不停 loop；一般信仍欠回答，記在 `$AOS_STACK/retry.json`，冷卻後只送一則 `[aos] retry: ...`、同段對話續做，不重送原文、不拿新信。成功的回答配給原信，再清欠帳與冷卻；對話檔不在則開新對話帶 history 前情。同一筆欠帳連續第 10 次暫時錯（`retry.py` 的 `MAX_FAILURES`）就當永久錯：丟信、刪 `retry.json`、退 1。slash 遇暫時錯也退 0，但該信照舊 failed、不重做、不動既有欠帳。其他失敗仍停下，codex 全照舊；claude 非文字 result 一律 `CliFailed`。claude 的 `brain_failed` 多帶 `code`、`retry`、`attempt`、`dropped`，暫時錯有 `wait_s`，有資料才帶 `status`、`cause`（codex 仍只有 `name`、`reason`）。
  **pi 身**（[eca-pi](../../../../thinking/2026-11/18/eca-pi/README.md)，使用者 11-18「1.做成第三種。」、傍晚「pi coding agent要做畫面」「接著做乙丙吧」）：`cli.json` 寫 `"kind": "pi"`＝每批起一次 `pi --mode rpc`（題目一則 `prompt`、回答途中又來的信一封一則 `steer`、對話檔在小格的 `pi-sessions/`、aos 工具經小格生成的一行外掛 `pi-aos-mcp.mjs`），`/compact` 另起一次 rpc 送 `compact`；**有畫面**：`aos-agent open` 在 tmux 起互動的 pi，多帶一支 aos 的 pi 外掛 `pi_aos_screen.mjs`（講完一輪回報 aos、畫面開著時 aos 的信經小格的 `pi_inbox/` 送進對話）；失敗同 codex。本體 `py/aos/agentlib/cli_pi.py`、`cli_pi_rpc.py`，寫法、實測與已知限制見 [templates/docs/03](../../../../templates/docs/03-eca-pi.md)。
  **外部 MCP server**（[external-mcp](../../../../thinking/2026-11/12/external-mcp/README.md)）：定義的 `cli.json` 列 `mcp_servers`（server 檔路徑），cli_session 起 CLI 時讓 claude／codex 自己接（http 帶 Bearer 與自簽 CA、stdio 經 `aos-mcp-launch`）；金鑰檔起 CLI 那一刻才讀、只進 CLI（或 server）行程。寫法見 [templates/docs/01](../../../../templates/docs/01-eca-claude.md#接外部-mcp-server11-12-external-mcp)。另一條路是同一份 server 檔先用 [aos-mcp-import](../mcp_import/README.md) 凍結、疊進 `tools.json`，經 aos-mcp 給 CLI（`mcp__aos__<server>_<工具>`，`before_tool` hook 攔得到）；一台選一條，差別表在同一節。
  **子 agent 與 skill**（[eca-task-subagent](../../../../thinking/2026-11/12/eca-task-subagent.md)）：claude 身的範本開 CLI 自己的 `Agent`（子 agent）與 `Skill`；`cli.json` 的 `tools_sub`＝子 agent 那台 aos 登記檔（內建 general-purpose 子 agent 只拿到 `mcp__aos_sub__*`，其他類型叫 `mcp__aos__*` 會被擋）。寫法見 [templates/docs/01](../../../../templates/docs/01-eca-claude.md#子-agent-與-skill11-12-晚-eca-task-subagent)。
  **程式放哪**：`main_turn.py` 只留說明（檔頭中文 docstring）與跑 main，本體在同夾的套件（一輪的流程、交給 CLI 的前後（handoff，一般一輪與 slash 共用）、history、hook、認領信、等回答時又來的信（midturn）、slash、開場白各一檔，逐檔一句話見 code map）；入口 `bin/aos-eca-turn` 由 `install.py` 照 `py/entries.json` 生，跑的是 `lib/aos/apps/eca/main_turn.py`。
**畫面延後關（C′ 主體）**：eca 範本的 `screen_linger_stop`（after_stop）在 `<stack>/<kind>/screen_close.json` 原子寫到期單，由畫面自己的 tmux 排程，daemon 關掉也照走。定義 `cli.json` 的 `screen_close_after_s` 是非負整數秒（預設 600，0＝當場 reap）；`screen_linger_start`（after_start）撤單。到期核 token、tmux 身分與本機 loop 身分，新的 loop 已起來就不關，不讀 daemon 表。有人接著看也照關；鎖忙每 30 秒再試，最多 10 次。兩格設 null 可停用；舊定義要另外補 hook。SIGKILL／OOM、停著才開畫面沒有 hook，第一批不處理；沒有 sweeper 後援。`aos-agent ctl stop` 不再當場關畫面（B 包），全靠這兩格；`ctl rm`、`ctl set-def` 照舊當場關；`ctl set-def` 拔掉之後、掛回之前刪掉 stack 小格裡留著的到期單（11-18 cooldown-1118：以前 set-def 關了畫面、到期單還在，計時跟著 tmux 一起沒了、單子沒人收；使用者 11-18 裁「清單只限 set-def」，所以 `aos-eca-screen close`、`ctl rm`、`aos-agent close` 不刪）。

- `bin/aos-eca-screen`：eca 的 screen 子介面身體（open／close／watch），人經 `aos-agent` 叫。說明在 [05-commands/05](../../../docs/05-commands/05-aos-llm與eca入口.md)。
