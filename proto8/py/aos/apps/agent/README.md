**ctl：掛上與管理**（使用者 11-05「我希望掛上和管理這塊，能夠放到aos-agent ctl這個子命令下。」）

aos-agent [--daemon D] ctl rm [--purge [--yes]] [--timeout-s 秒] 名字                       拔掉、stack 留著（cli-sweep Q3，使用者「兩支都留 stack，要刪另外說」；印 `removed X; stack S kept (…)`，同名同 `--stack` 再 `ctl add` 接著用；**改名**＝`ctl rm 舊名`（stack 留著）再 `ctl add -n 新名 -s <舊 stack> [-w <ws>] [--auto-restart] <定義>`，stack 資料夾不搬（路徑還是舊名，沒關係），中間寄給舊名的信會被退，用 `--envs` 掛的要把 `--envs` 再給一次）。`--purge` 才連 stack 一起刪（名字要明講；先關畫面，正在答＝SessionBad、什麼都不動；stack 是工作區、定義、daemon 資料夾、目前資料夾、家目錄、表上別隻的 stack 或在它們上層的不刪；終端裡先問 [y/N]）；`-y` 沒配 `--purge`＝`ArgumentsBad`；工作區（表上那列的 `ws`）已經不在不擋 `ctl rm`、`ctl set-def`：stderr 一行 `aos-agent: warning: the workspace of X is gone (…); closing its screen from its stack instead`，畫面改從 stack 關
aos-agent [--daemon D] ctl set-def [--kit KIT] [--timeout-s 秒] 名字 新定義               換定義＝停（等這一輪跑完）→拔（關畫面、stack 留著）→用同一個名字、stack、工作區、limits、auto_restart 掛回新定義（history、queue、信箱、自己那份覆蓋層都在 stack 裡）；表上馬上是新的、daemon 重啟也不掉；在跑的掛回就用新定義起（pid 換新），停著的還是停著、睡著的還是睡著；中間有一小段不在表上，這時寄給它的信會被退；停那步失敗或逾時＝什麼都沒拔，拔了之後掛回失敗＝錯誤行後面接手動接回的 `aos-agent -d <daemon> ctl add …` 指令（帶 `-d`＝直寄 daemon，`AOS_KERNEL` 設著照抄也不再經那一站；setdef-night-1118）；走 kernel 時掛回那封信帶 `queue_wait_ms`＝`--timeout-s`（同 add 的 `--on-queued fail`），站的格滿排隊、期限一到站就拒（`SlotMissing`），不會之後才套上、蓋掉手動接回的（使用者 11-18 裁「信帶等待期限」）；對自己（`$AOS_STACK` 就是那隻的 stack）＝`ArgumentsBad`；`--envs` 掛的不收（先 rm 再 add `-s 舊 stack`）；stack 裡自己那份 tools 還疊在舊定義上＝提醒一行、不改寫
aos-agent [--daemon D] ctl ls [--json] [--long] [--deep]                    列 daemon 表上全部：名字 狀態 工作區 queue 幾封（-l 多印健康欄，--deep 整棵樹，見下「ctl ls 看狀況」）
aos-agent [--daemon D] ctl start|stop|sleep|wake [名字|--target 名字] [--timeout-s 秒]   stop／sleep 另收 --no-wait；add／start／wake 另收 --on-queued fail|ok；stop 不關畫面（C′ B 包：eca 定義的 after_stop hook `screen_linger_stop` 照 `cli.json` 的 `screen_close_after_s` 延後關，預設 600 秒、0＝當場；期間又起來就不關；要馬上關用 `aos-agent close`）

**ctl state：看一隻的十一類事實**（[self-family 02](../../../../thinking/2026-11/10/self-family/02-self_state與self_ctl.md)，使用者「點菜…也可以點總覽」「只給數字」「擴充原有的吧」）：類別＝`who`（名字、定義、工作區、stack）、`state`（phase、reason、queue 幾封、最近回答）、`tools`（轉叫 `tools ls`，加自己那份的增減）、`llm`（轉叫 `llm ls`，哪些鍵是這隻改的）、`system`（轉叫 `system get --json`：來源、幾 byte、第一行；細節多全文、超過 2000 字截）、`hooks`（轉叫 `hook ls`）、`history`（轉叫 `history ls`：幾則、幾 byte、各角色幾則、搬走留底幾則；細節多最後 5 則、一行最多 200 字）、`mailbox`（轉叫 `aos-mailbox -s <stack> peek`）、`subagents`（subagent 的帳 `<stack>/tools/subagent/subagents.json` 對上表；配額 `max_subagents` 讀定義與 stack 的 `subagents.json`、預設 4）、`resources`（表上的 limits；行程樹的記憶體、cpu 秒數、幾個行程，讀 `/proc`）、`time`（現在、活了多久）。不給類別＝每類一行的總覽；給類別＝那幾類的細節（`== 類別` 分段）；`all`＝全部；`-j`＝一個 JSON 物件 `{類別: {...}}`。只給數字與事實、不給建議。某類拿不到（例：沒宣告 hooks）＝那一類印 `not available (原因)`（JSON：`{"available": false, "reason"}`），其他照印、退 0。不認得的類別＝`ArgumentsBad`。agent 自己看用工具 `self_state`。

**`--no-wait`：給對自己下指令用**（self-family 02，使用者 self_ctl「3.可以」）：`ctl stop --no-wait` 只等 daemon 收下（不等停好、不關畫面）；`ctl pause --no-wait` 寫了 ctl 就回（不等套用）；`ctl sleep --no-wait`、`ctl rm --no-wait` 寄出就回、不等回信（daemon 會連下指令的這支一起收掉）。`rm --no-wait --purge` 另起一個脫離的小行程，等那列不在了再刪 stack（同樣的保護；活不過那隻的話 stack 留著）。agent 自己用工具 `self_ctl`。

**history：看、刪、摘要、改對話紀錄**（[self-family](../../../../thinking/2026-11/10/self-family/README.md)）：檔在哪由定義的 `interfaces.json` 裡 `aos-agent.history` 宣告（相對 stack；兩個範本都寫 `history.jsonl`）。RANGE＝`N`、`A-B`、`A-`；最後 K 則用旗標 `-n K`／`--last K`（K、-K 都收：`ls -n 3`＝`ls -n -3`，ls／rm／summarize 都有；使用者 11-21「-N 3, -N -2」「-N "-3"」「-N "2"，都可以」，線 histrange-1121），行號＝第幾則訊息、從 1 數、空行不算。`ls` 一則一行 `行號 TAB 角色 TAB 內容`（換行印成 `\n`、工具呼叫印成 `-> 名(參數)`、讀不懂的行角色印 `?`；內容預設截 200 字、結尾 `…`，`-l` 印全文；使用者「幫我改成默認都短板吧」）；預設只印最後 20 則，前面還有就先印一行 `(N earlier messages not shown: lines 1-N; -a shows all, or give a RANGE)`，`-a/--all` 全印、給 RANGE 照 RANGE（`-a` 跟 RANGE 擇一）——使用者「4.好」；`-j` 印 `[{"line","message"|"raw"}]`，一律全部（或 RANGE）、不截。`rm` 刪一段；`summarize` 把一段換成一則（`--role` 預設 `user`，TEXT 寫 `-` 讀 stdin；內容固定是 `[aos] summary: lines A-B, N messages. TEXT`，讀的人分得出不是使用者講的——使用者「self_history的摘要這塊，身份可以是user，只是內容這塊希望能符合特定格式，比如我們現有的error那樣，就aos:...。」，形狀代定，[tonight-rulings](../../../../thinking/2026-11/10/tonight-rulings/README.md)）；`set` 把一行整則換掉（JSON 要是物件，`-` 讀 stdin）。**原文不丟**：預設接在旁邊的 `history_removed.jsonl`（一則一行 `{"removed_at","op","line","message"|"raw"}`）；`--keep F` 換位置（相對目前資料夾）；`--no-keep` 不留，終端上先問、`-y` 不問。結果行說原文在哪時不印絕對路徑（self_history／do_task 會把這行接進 history，history 進 git）：預設那份印相對 stack 的位置（`the originals are in history_removed.jsonl in the stack of bob`），`--keep` 照給的字面印。寫法是整份寫暫存檔再改名，寫前比 size／mtime，被別人動過就重做、最多 3 次。**改正在跑的**：建議先 `ctl pause`；agent-fsm 寄信前看到 history 比 request 新會重組；eca 下一輪認出改過、開新對話帶改過的紀錄過去。錯誤代號：`HistoryMissing`（沒宣告）、`InterfaceBad`（宣告寫壞）、`RangeBad`（超出、倒過來、寫壞、history 是空的）、`MessageBad`（JSON 不是物件）、`WriteFailed`（一直被別人動）、`ArgumentsBad`（`--keep` 配 `--no-keep`、`-y` 沒配 `--no-keep`）。agent 自己改用工具 `self_history`（[py/tools/agent/self_history](../../../tools/agent/self_history/)）。

- **短名與確認**（human-cli H4、H11，使用者裁「開幾個常用短名」「終端問、非終端不問」「幫我加上--yes跳過」）：長旗標照樣能用；短名是全 aos 共用一張表裡的，同名同義——這支用到 `-h`（`--help`，全部）、`-d`（`--daemon`）、`-t`（`--target`）、`-j`（`--json`：`ctl ls`、`ctl who`、`tools ls`）、`-n -w -s`（`--name --ws --stack`：只在 `ctl add`）、`-f`（`listen --follow`）、`-y`（`--yes`：`ctl rm --purge`、`tools reset`、`llm reset`）。一個槓一個名字，不黏值、不併：`-tann`、`-jf` 都是 `FlagUnknown`。刪了別處沒副本的三個子命令（`ctl rm --purge`、`tools reset`、`llm reset`；不帶 `--purge` 的 `ctl rm` 不刪東西、不問）**stdin 是終端**時先在 stderr 問一句 `[y/N]`，只有 `y`／`yes` 才做；其他字、空行、Ctrl-D＝印 `aos-agent: warning: nothing done`、退 0（問的時候按 Ctrl-C＝退 130）；`-y` 不問；stdin 不是終端（管線、腳本、agent、`</dev/null`）不問、照做。`tools reset`／`llm reset` 沒東西可刪就不問。例子在 [docs/01](docs/01-用法例子.md#短名與確認11-06)。
- **旗標寫在哪**（[cli-sweep 10d](../../../../thinking/2026-11/10/cli-sweep/10d-施工結果-Q1旗標位置.md)，使用者「1.收。2.收。3.好。」，條文 [P-44 續](../../../../docs/CONVENTION/02-題目stack停錯腦/07-P-44續-11-10-旗標位置.md)）：每一層（aos-agent、子命令、動作）的旗標寫在那一層名字之後任何位置都算——`aos-agent ctl stop ann -d D`＝`aos-agent -d D ctl stop ann`、`tools add XXX --name n`＝`tools add --name n XXX`。`ctl start／stop／sleep／wake／pause／resume／where` 也收名字放最後（跟 `-t` 不同＝`ArgumentsBad`）；`ctl add／rm／ls／who` 後面寫 `-t`＝`FlagUnknown`。`say` 的 WORDS、`history summarize` 的 TEXT、`history set` 的 JSON 起全是內容，旗標寫在前面（代定）；`--` 後都不是旗標。

- **哪個 daemon**：`--daemon D` ＞ `$AOS_DAEMON`（那個 daemon 的 `$AOS_STACK`，絕對路徑）＞ **cwd 認得出的 agent stack 往上兩層**（使用者 11-21「那也幫我把-d省略也做一下吧，弄成往上兩層去找，因爲默認是.stack/procs/ann這樣」）：`./.stack` 先、再 `./`，有 `stderr.txt` 的第一個夾往上兩層要有 `procs_state.json`、而且表上有這個 stack，不成＝`DaemonMissing`（訊息寫試過哪裡）。站在 `<daemon stack>/procs/ann/` 裡就什麼都不用給；`-s` 掛在別處的 stack（例如 `ws/.stack`）往上兩層不是 daemon，照樣要 `-d`。給了 `-t`／`AOS_AGENT` 也一樣用 cwd 找 daemon（站在 ann 的 stack 裡 `-t bob` 就是同一台的 bob）。樹根的 `./.stack` 本身不當 daemon（11-05 portable-flow 題 3 那條退路 11-21 在 aos-agent 拿掉，使用者當時說「-d不能省略」；`aos-daemon-ctl` 等別的指令照舊）。設了 `AOS_KERNEL` 照舊問 kernel、不往上找。D 一律轉真實路徑（realpath）。D 已存在但沒有 `procs_state.json`＝立刻 `StateMissing`。不預判 daemon 活不活：`ctl ls`／`state`／`where` 照表印；`ctl add`／`rm`／`start`／`stop`／`sleep`／`wake` 照寄、等回信，`--timeout-s S`（預設 30 秒）內一封都沒有＝`DaemonFailed`（下面「等回信」）；`say` 照寄。
- **表上的路徑**：沒走 kernel 時，daemon 把每列的 `stack`／`ws`／`def` 存成相對 daemon stack（整份搬家照樣對得上），`aos-daemon-ctl ls --json` 拼回絕對再給這支；`ctl ls`／`state`／`where` 印的都是絕對。列上的 `reason`（出錯結束〔任意 proc 退非 0〕留成 `stopped` 的列，daemon 寫的原因；修好後 `llm reset`／`tools reset` 再 `ctl start`，不要了 `ctl rm`）`ctl ls` 印在最後一欄、`ctl state` 多一行 `reason`。
- **ctl ls 看狀況**（two-machines，使用者裁「aos image...拿掉吧」）：`-l`／`--long` 在每列後面多四欄 `QUEUE`（`queue/new/` 還沒收的封數，`.` 開頭不算；沒 queue/＝`-`）、`RESTARTS`（`cooldown.json` 的 `failures`，沒有＝0）、`COOLDOWN`（`until 10:41 (4)`＝冷卻到本地時間幾點、第幾次；過了＝`due (4)`；沒有＝`-`）、`LAST ERROR`（冷卻的代號＋原因、截到 60 字；冷卻有 `error` 欄＝代號＋下層的代號與原話，例 `BrainFailed EndpointFailed HTTP 400 …`；沒冷卻＝表上的 reason）；不帶 `-l` 一個字不變。`--json` 每列多 `auto_restart`（布林）、`queue`、`cooldown`（`null` 或 `{failures, until, code, reason, dropped, state: cooling|due}`，檔裡有 `retry`、`error` 就照帶）、`busy`（`think`＝有 `think/pending.txt`、`act`＝`stage.txt` 是 act、`cli`＝eca 小格〔stack 本身或 `tools/<名>/`〕有 `busy.txt`、否則 `null`）。冷卻檔只經 [py/cooldown](../../agentlib/cooldown.py) 讀，壞了當沒有。
- **ctl retry**（11-24，使用者看過 core 報告後定：「做一個立刻重試的動作，但不要做成工具，並盡可能納入現有指令，成為子指令」）：外面的服務失敗後（agent-fsm 的 BrainFailed／SendFailed／BudgetMissing、eca 的 CliFailed／ReplyMissing）agent 照 `cooldown.json` 等 30 秒～30 分鐘；`ctl retry` 刪掉那隻 stack 的 `cooldown.json`（`py/aos/agentlib/cooldown.py` 的 `clear`，eca 與 fsm 同一張），fsm 下一拍就重寄同一份請求、eca 下一拍就重跑 CLI。印一行清之前的狀態：`cleared ann's cooldown: 4 failures in a row, it was waiting until 10:41:07; last error: BrainFailed EndpointFailed …; it tries again on its next round`（時間是本地；已過＝`it was already due`；有下層的錯就印下層的代號與原話）；沒有冷卻＝`ann has no cooldown (…); nothing to clear`、退 0。stopped／sleeping／paused 的不替它起，那行最後說要 `ctl start`／`wake`／`resume`（起來後也不用再等）。走 kernel 時照 ctl ls 問表在哪；刪檔是本機的事，不寄信給 daemon。刪不掉＝`WriteFailed`。
- **ctl ls --deep**（11-24，eca_main 要的欄）：照 [aos.comm.walk](../../comm/walk.py)（`aos-comm board ls --deep` 同一支）往下走——頂層＝這次讀的表（`--daemon`／`AOS_DAEMON`／`AOS_KERNEL` 照舊），表上哪一列的 stack 有 `procs_state.json` 就再列它那張（直接讀檔，不經 kernel），廣度優先、最深 5 層、最多 500 隻；下層表讀不到＝stderr 一行 warning、照走別的，超過上限也一行 warning。一列 `PATH STATE PID STAGE QUEUED LAST-ACTIVE REASON`（再帶 `-l` 的四欄）：`PATH`＝上層名/…/名；`PID`＝表上的 pid 加 `alive`／`dead`／`exited`（殭屍）／`reused`（pid 換人了，對 `started_at_ticks`），沒 pid＝`-`；`STAGE`＝stack 的 `stage.txt` 第一行（agent-fsm），沒有＝`busy`（eca 是 `cli`），都沒有＝`-`；`LAST-ACTIVE`＝stack 本身與直接底下檔案的最新 mtime（跟 `aos-daemon-ctl prune` 同一套），本地 `MM-DD HH:MM`。`--deep --json` 每列多 `path`、`depth`、`table`（那張表的 daemon stack）、`pid`、`pid_state`、`stage`、`last_active`（UTC ISO 或 null）。不帶 `--deep` 一個字不變。
- **ctl sleep／wake**（[portable-flow 衝突 1](../../../../thinking/2026-11/05/portable-flow/05-衝突與方向題.md)，使用者選「嚴格分」）：`sleep`＝現在就睡（daemon SIGTERM、列 `sleeping`、stack 留；daemon 開門自己醒，或 `wake`）；`stop`＝等這輪做完、要 `start` 才回來。`start` 只起 `stopped`、`wake` 只醒 `sleeping`；跨著用（sleeping 的 `start`／`stop`、stopped 的 `wake`／`sleep`）＝`aos-daemon-ctl` 的 `PhaseBad` 原樣轉（`X is sleeping; use wake …` 之類）；同一狀態再叫（stopped 的 stop、running 的 start、sleeping 的 sleep、running 的 wake）＝印 `already …`、退 0。sleep 不關畫面（跟 daemon 收工一樣）；沒走 kernel 時 `stop`、`ctl rm` 先關畫面（正在答＝`SessionBad`、不往下做）。
- **三扇門**（[stdio-unify](../../../../thinking/2026-11/05/stdio-unify/README.md) R1、R3、R15）：stdout 只放結果；提醒是 stderr 一行 `aos-agent: warning: 句子`；`chat` 的提示符 `> ` 在 stderr（D5）。`ctl ls` 一行 `名字 TAB 狀態 TAB 工作區 TAB queue 幾封 TAB reason`（沒有＝`-`）。`--help`／`-h`＝**那一層**的英文 help 到 stdout、退 0（頂層一屏總覽、`ctl --help` 列動作、`ctl rm --help` 只講 rm；`tools ls --help` 這種不用先有 target）；不給子命令＝`ArgumentsBad` 退 1；子命令前不認得的旗標＝`FlagUnknown`、子命令不認得＝`CommandUnknown`。錯誤行括號裡只指**那個子命令**（H10）：缺參數、參數不對＝`(usage: 那個子命令的 usage 行)`；子命令後不認得的旗標＝`(see aos-agent ctl rm --help)` 這樣指回它自己那份；子命令前的 `FlagUnknown` 指回頂層 `(see aos-agent --help)`。Ctrl-C 退 130（`listen --follow` 用 Ctrl-C 離開是正常離開、退 0）。
- **daemon_ctl 模組的錯**：`ctl` 系列 import `daemon_ctl`（不叫 aos-daemon-ctl 行程、不讀誰的 stderr），模組報的錯換成這支的名字與代號再印（`ProcMissing`→`InstanceMissing`，其他代號照用）。
- **錯**：stderr 一行 `aos-agent: error: 代號 原因`、退 1；`--timeout-s S`（預設 30 秒）內一封回信都沒有＝`DaemonFailed`；回了 `applied: true` 但表上等滿 S 秒還沒變成結果＝`WaitFailed`；`ctl add` 的信被 daemon 拒收（名字像 `a/b`、`..`，或設定不合格；daemon 寫在 `state_flux.json` 的 `mailbox_warning`）＝立刻 `AddRejected`、原因原樣轉，不等滿 S 秒；判官不掛（回信 `applied: false`）＝立刻 `AddRejected`（`add`）／`CtlRejected`（其他 ctl），訊息帶判官的代號與原因（下一條）；daemon 自己收到壞信（回 `applied: false`，代號 `BodyBad`）同樣立刻 `AddRejected`／`CtlRejected`，不等到逾時。子介面入口（screen）與 aos-tools、aos-json 自己報的錯原樣轉。
- **daemon 沒在跑就馬上說**（cli-sweep 甲6；沒走 kernel 時）：`ctl` 底下會寄信等結果的（add、rm、start、stop、sleep、wake）寄信前先核 daemon 的 state 窗＋/proc（同 `aos-daemon-ctl ls` 的 `# daemon:` 那行）；確定不在＝馬上 `DaemonMissing no aos-daemon running at D (...); nothing was sent. Start it first: aos-exec --stack D <its definition folder>`，不寄信、不乾等 `--timeout-s`。state 窗關著或讀壞＝寄信等；自己在子 pid 命名空間裡（aos-sandbox）看不到 daemon 的 pid＝不核、寄信等。
- **錯誤代號一覽**：`ArgumentsBad`、`FlagUnknown`、`CommandUnknown`、`CommandMissing`（叫不到要的指令，例 `aos-exec`／`aos-json` 不在 PATH）、`DaemonMissing`、`DaemonFailed`、`KernelFailed`、`StateMissing`、`InstanceMissing`、`InstanceExists`、`PathMissing`、`SessionBad`、`SendFailed`、`PostFailed`、`QuestionUnknown`、`AnswerMissing`、`WaitFailed`、`AddRejected`、`CtlRejected`、`TargetMissing`、`WsMissing`、`StackMissing`、`InterfaceMissing`、`InterfaceBad`、`PhaseBad`、`ScreenMissing`、`ScreenBad`、`ToolsMissing`、`LlmMissing`、`LlmBad`、`SystemMissing`、`SystemBad`；子介面與共用工具另有自己的代號（見上一條）。
- **`AOS_KERNEL`**：非空＝ctl 信照路由寄那個信箱，stderr 印 `aos-agent: warning: routing via AOS_KERNEL=<路徑>`。不從信箱位置辨識 kernel 身份、不查它是否 running、不自動直接寄 daemon；即使對象就是收件者本身也一樣。判官本身睡著或停著＝設計系統的人要管的風險（使用者 11-07），手動用 `aos-daemon-ctl wake NAME`（停著用 `start`）叫醒：aos-daemon-ctl 一律直寄 daemon、不看 `AOS_KERNEL`（使用者「aos-daemon-ctl 永遠直寄」；aos-agent＝經 kernel，人平常用這個；aos-daemon-ctl＝指名 daemon 的工具，有 Linux 權限就能用）。
- **等回信**（[edge-agent 題 2](../../../../thinking/2026-11/05/edge-agent/README.md)，使用者選「加 --reply-to 等回信」）：`ctl add`／`rm`／`start`／`stop`／`sleep`／`wake` 每封信都帶回信信箱（`reply_to`）寄，最多等 `--timeout-s S`（預設 30 秒）。六個動詞都支援這個旗標，S 必須是有限且大於 0 的秒數，沒有短名；設計見 [寄信者自設逾時](../../../../thinking/2026-11/06/os-impl/05-寄信者自設逾時.md)。回信信箱是**共用的**（[no-pid](../../../../thinking/2026-11/05/no-pid/README.md) P3）：有 `$AOS_STACK`＝`$AOS_STACK/daemon_reply/`；沒有（人殼）且走 kernel＝`$AOS_KERNEL/reply/`，否則＝`<daemon stack>/procs_requests/reply/`；大家共用、靠回信的 `in_reply_to` 認自己那封，沒人領的 10 分鐘後由下一個來拿信箱的人收掉（垃圾回收，不是判死活）。判官不掛＝回信 `applied: false` 一到就退：`aos-agent: error: AddRejected AOS_KERNEL refused the add letter: NameUnknown evil not in allowed`（滿額是 `SlotMissing`；wake／start 超過 `max_running` 是 `CtlRejected`）。走 kernel 的只看回信指令收到 `applied: true` 就成功；沒走 kernel＝daemon 回 `applied: true`，等表上變成結果（表先變、回信還沒到＝最多再等 1 秒讓它落地）；回了但表等滿 S 秒沒變＝`WaitFailed`。**S 秒內一封回信都沒有**時按下面的排隊／撤信規則處理，不從 daemon 或判官身份猜原因。被 TERM 退 143、HUP 退 129。
- **排隊與等滿**：add／start／wake 收 `--on-queued fail|ok`，預設 `fail`（set-def 掛回那封固定照 `fail`）。`fail` 把 `queue_wait_ms=S×1000` 放進 body；判官按信封 `sent_at`＋毫秒牆鐘到期，回拒信後確定不再轉寄。`ok` 不帶期限；等滿 S 秒，只在公開 `queue.json` 確認自己那封仍在排時印 `queued NAME at position N (letter L; applied when a slot frees)`、退 0，意思是已排隊，尚未掛上。其他沒回信的情況仍失敗。`fail` 在隊裡等滿時多等 1 秒收最後拒信：收到就以拒信為準（add＝`AddRejected`、start／wake＝`CtlRejected`，帶 `SlotMissing`）；仍沒回才是 `DaemonFailed`。未開 queue＝格滿立即拒；有回信一律以回信為準。逾時失敗時盡力 `aos-post regret` 撤仍在原收信箱 `new/` 的信；判官已領進 cur 的由信內期限擋晚套，已轉寄到 daemon ctl 或 daemon 已領走就不能保證取消，可能之後才套。詳見 [已知限制](docs/02-已知限制.md)。

## 介面 `aos-agent`：ctl add 只看宣告

一個資料夾能被 `ctl add`，只看它頂層 `interfaces.json` 有沒有 `aos-agent` 這個 key（沒有＝`InterfaceMissing`、不送信；讀不懂＝`InterfaceBad`）；不驗 `cli.json`、`fsm.json`（宣告了卻沒做到，第一圈就出錯結束、表上留 `stopped`＋原因）。介面六條（資料夾程式、只吃 aos 的環境變數、常駐有窗、`queue/` 收 user message、`history.jsonl` 寫回答、錯在 stderr 一行）與選配子介面見 [03](../../../../thinking/2026-11/04/aos-agent/03-種類與契約.md)：

```json
{"aos-agent": {"entry": "body.json", "screen": "screen", "tools": "tools.json", "llm": "llm.json", "history": "history.jsonl"}}
```

- `entry`（選填，[portable-flow 題 4](../../../../thinking/2026-11/05/portable-flow/05-衝突與方向題.md)）＝定義裡**身體的入口**（相對路徑，可帶 `#/指標`；不在或寫成絕對／`..`＝`InterfaceBad`）。宣告了＝`ctl add` 掛的是 `<定義>/<entry>`（`aos-daemon-ctl add --def <定義> <定義>/<entry>`，表上的 `def` 照樣是定義資料夾）；沒宣告＝掛定義資料夾本身（照它的 `_entry` 判型）。用處：定義的 `_entry` 空出來寫成「**把自己掛上 daemon**」，`aos-exec 那個資料夾`＝`aos-agent ctl add 那個資料夾`（使用者「介面維持 aos-agent add」、不加 `aos-exec --daemon`；add 在 `ctl` 底下）。範例在 [templates/agent-fsm](../../../../templates/docs/02-agent-fsm.md)：
  `_entry`＝`{"argv": ["aos-agent", "ctl", "add", {"$env": "AOS_CD"}], "cwd": {"$env": "AOS_WS"}}`、`body.json`＝`["aos-loop", "loop.json"]`。aos-exec 跑 `_entry` 時已經 cd 進定義資料夾，所以單子用 `cwd` 換回工作區（`AOS_WS`＝`--ws` ＞ 外面的 `$AOS_WS` ＞ 呼叫當下的 cwd，轉絕對）：`ctl add` 沒給 `--ws` 就沿用這個 `$AOS_WS`，未設或空才用 cwd；daemon 只從 `$AOS_DAEMON` 來（11-21 起不看 cwd 的 `./.stack`，人在殼裡要先 export）；`AOS_CD`＝定義資料夾的絕對路徑；名字＝資料夾名。不走 `sh -c`。`export AOS_DAEMON=$PWD/ws/.stack; cd ws && aos-exec ../agents/bob` 就把 bob 掛上 `ws/.stack` 的 daemon；要換名字、換 ws 以外的設定就直接打 `aos-agent ctl add …`（`aos-exec 資料夾 參數` 的參數會接在 argv 尾巴、ctl add 不收）。

- `screen`＝定義裡一個資料夾程式，它自己的 `interfaces.json` 宣告 `{"aos-agent/screen": {}}`（沒宣告＝`ScreenBad`）。aos-agent 從 daemon 表那一列的 `def` 欄找回定義（aos-daemon-ctl add 送、daemon 記；使用者 11-04「那就b。」；沒這欄＝`InterfaceMissing`，`ctl rm` 再 `ctl add` 一次），叫 `aos-exec --ws <ws> --stack <stack> <定義>/<入口> 動作…`。沒宣告＝`ScreenMissing`（看回答改用 `listen --follow`）。
- `tools`＝定義裡登記檔的相對路徑（不可絕對、不可含 `..`、不可指資料夾），也決定**這一隻的覆蓋層**位置：`<stack>/<同一相對路徑>`。例如宣告 `"tools": "cfg/my_tools.json"`，就讀 `<定義>/cfg/my_tools.json`、只改 `<stack>/cfg/my_tools.json`（K-6）；`aos-agent tools` 只寫這個宣告的覆蓋層（只存差異；形狀＝`{"$override": 定義那份, "tools": {名: 登記, 不要的: null}}（null 那格不算工具）`、不整份複製定義；身體每次讀這份（疊法歸 aos-tools）、定義改了照疊；`reset` 刪覆蓋層）——存什麼、怎麼合併、定義改了怎麼辦見 **[docs/03 tools 覆蓋層](docs/03-tools覆蓋層.md#tools-覆蓋層)**。改定義用 `aos-tools --file <定義>/<宣告的 tools 路徑> …`。同一份定義掛了好幾隻時，改這隻的會在 stderr 提醒一行 `aos-agent: warning: this definition (/agents/shared) is also used by bob; only ann's own copy (in its stack) changed, theirs did not (to change them all, edit the definition: aos-tools / aos-json)`（例：ann、bob 共用 `/agents/shared`）。
- `llm`＝定義裡那份**腦設定檔**的相對路徑（跟 `tools` 同一種寫法；[think-as-function 03 § 4](../../../../thinking/2026-11/04/think-as-function/03-呼叫端.md)：`aos-llm` 是寄請求給 llm kernel 的基礎工具，aos-agent 的 `llm` 只是 aos-json 的語法糖）。這隻改過的鍵＝stack 裡同一個相對路徑（例 `<stack>/llm.json`），**只放改過的鍵**、其他照定義：`ls`＝定義那份（沒有＝`{}`）疊改過的、一行一個 `鍵=值`；`ls -l` 多一欄來源（`definition`，或 `agent`＝這隻改過的，蓋掉定義的再接 `definition: 原值`）；`ls --json`＝`[{"key","value","from","definition"?}]`；`set 鍵=值…`＝`aos-json set --str <stack 那份>#/鍵 值`（不在先建 `{}`；值一律字串）；`rm 鍵…`＝拿掉這隻改過的那幾鍵、回到定義的值（沒改過＝`KeyMissing`；拿光了刪檔）；`reset`＝刪掉。鍵由那隻身體認：定義的 `interfaces.json` 在 `aos-agent` 裡寫 `llm_keys`（鍵名陣列）時，`set` 不在單子上的鍵＝照存、stderr 一行 warning（使用者「1.跳warinig就好」；沒寫 `llm_keys`＝不提醒）。agent-fsm 認 `model`（kernel 的 endpoint 包代號）與與快取無關的調整鍵 `temperature`、`top_p`、`max_tokens`、`seed`、`presence_penalty`、`frequency_penalty`、`stop`；eca 認 `model` 與 `reasoning_effort`（思考程度：claude 身補成 `--effort`、pi 身補成 `--thinking`，只收那支 CLI 認得的級別，見 [templates/docs/01](../../../../templates/docs/01-eca-claude.md)；11-21 線 top-1121-ecaeffort）。身體每題重讀、有的鍵蓋過定義。改定義＝人直接 `aos-json set --str <定義>/llm.json#/model sol`。沒宣告＝`LlmMissing`；宣告的是資料夾或讀不懂＝`LlmBad`。
- `history`（self-family）＝這隻對話紀錄在 stack 裡的相對路徑（跟 `tools` 同一種寫法）；`aos-agent history` 只認這個宣告。沒宣告＝`HistoryMissing`；寫壞＝`InterfaceBad`。身體的程式寫死 `history.jsonl`，宣告是給外面的工具找檔用的。
- `system`（[thinking self-system](../../../../thinking/2026-11/11/self-system/README.md)，使用者「然後我們現在的工具沒辦法讓agent修改自身的system prompt……」）＝定義裡 system 文字檔的相對路徑（跟 `tools` 同一種寫法）；這隻自己那份＝`<stack>/<同一相對路徑>`，**在就整份用它**（不疊、不合併），定義那份不在＝空文字。`aos-agent system get|set|reset` 只寫自己那份；身體怎麼用（agent-fsm 取代、eca 附加）、何時生效見 **[docs/07 system](docs/07-system.md)**。沒宣告＝`SystemMissing`；宣告的不是定義內相對檔名＝`SystemBad`。`llm set system=…`＝`ArgumentsBad`、不存、錯誤行指到這個（使用者「報錯並指路」）。
- hook 不在 `aos-agent` 這格裡（11-21 起）：`interfaces.json` **最外層**的 `hookeds`（[self-family/hook](../../../../thinking/2026-11/10/self-family/hook/README.md)）＝被勾清單，值是檔名、指示詞或它們的陣列（相對＝從定義夾算）；這隻自己那份＝`<stack>/<同一相對檔名>`，形狀一樣 `{"description": "一句話", 名: 格 或 null}`，疊在定義那份上（同名蓋過、null 關掉）。最外層的 `hooks` 是 hook 點的宣告，只是參考，沒有程式照它擋人。`aos-agent hook` 只寫自己那份。事件、回話協定（0 放行／10 攔下）、選項、例子見 **[docs/06 hook](docs/06-hook.md)**（整套 hook 的總說明：[apps/hook/docs](../hook/docs/README.md)）。沒宣告＝`HooksMissing`；清單壞＝`HooksBad`。

## agent 對話協議（P-42；併自 extras/human）

- **stdin／stdout**（使用者 11-05「aos-say,aos-listen，我希望能支援stdin/out。」）：`say` 沒給話（或只給 `-`）＝整份 stdin 是**一則**訊息（照 UTF-8 原樣讀、不看 locale，去掉尾端一個換行〔`aos_ws.put` 本來就再把結尾的換行全去掉〕）；stdin 是終端又沒給話＝`ArgumentsBad`、立刻退，不卡著等；要寄一個字的 `-` 就 `echo - | aos-agent say`。`listen` 的 stdout **只有回答本文**，提醒、狀態一律 stderr，所以 `echo 題 | aos-agent say && aos-agent listen > 答.txt`、`cat 長題.md | aos-agent say && aos-agent listen | 下一支` 都行（say 的 stdout 是信件名稱，要丟掉就 `> /dev/null`）。`--last N`／`--follow` 一則一段（代定）：一行 `== #序號`、問的那幾行前面加 `> `、然後回答本文；要純回答就用不帶旗標的 `listen`（一次一則）。例子在 [docs/01](docs/01-用法例子.md#stdin-與-stdout11-05)。
- **say 的腦提示**：寄出成功、agent 沒停也沒暫停時，若問腦記錄顯示 llm kernel 沒在跑，stderr 印一行提示，信仍照寄。
- **listen 的腦提示**：等最新回答時若 llm kernel 沒在跑，stderr 只提醒一次；逾時的 `AnswerMissing` 也附上當下提示，`--last`／`--follow` 不變。
- **listen／ask 的問腦失敗**（small-1118，使用者 11-18 小題一包「listen 出錯時把理由帶出來」）：信交出去還沒答時，每秒看一次 stack 的 `cooldown.json`（問腦沒成就記、成功一次就刪）。有＝stderr 提醒一次「最後一次問腦失敗」，帶 stderr 檔（`stderr.txt`）最後一行錯誤行原話（例 `aos-llm: error: EndpointFailed timed out connecting …`）、第幾次、冷卻到幾點，照等（會自己重送的：`retry` true、`BudgetMissing`）；**身體停在這個錯上**（stderr 裡最後一行 `名: error: <冷卻的代號> …` 之後，同一支沒再印 warning〔別支的 `aos-loop: error: RunFailed …`、`brain_notify: warning: …` 不算〕、沒有 `think/pending.txt`＝沒在問腦；例：端點回 400，fsm 記冷卻後退 1）＝馬上結束，錯誤行帶那行往上連著的錯誤行（例 `aos-llm: error: EndpointFailed HTTP 400 … / agent-fsm: error: BrainFailed …`），`AnswerMissing … stopped on an error before answering: <錯誤行>…`，後面接下一步（表上 `auto_restart`＝daemon 會重起、冷卻完重寄同一份；沒有＝修好再 `ctl start`）與 `listen --letter` 怎麼之後再看。逾時的 `AnswerMissing` 也接上 `X's last brain call failed: …`。只讀，檔不在或壞了當沒有；成功的路不變。以前（11-18 litellm 實測）是等滿逾時只說 `… was handed over and is not answered yet`。
- **說**：`aos-agent say 話`＝`aos-post send --ordered <stack>/queue`，一封信的 body＝`{"role": "user", "content": 話}`（當 queue 用的信箱：寄的都帶 --ordered（C-54 R14）；queue 還沒有就先建，可以先說、再跑）。印的信件名稱就是 `new/` 裡那封的名字（`<12 位序號>.<尾名>`）。沒人在跑時照表上的 phase 提醒：`stopped`＝`aos-agent ctl start --target 名字`（有 `reason` 一起印）；`sleeping`＝`wake it: aos-agent ctl wake --target 名字 (if the daemon itself is down, restarting it wakes 名字 too: …)`（不判 daemon 在不在跑，兩條路都給）。「有沒有人在跑它」只看表上那列 `phase` 是 `running`／`stopping`。
- **寄件人**（[eca-a2a-notify](../../../../thinking/2026-11/13/eca-a2a-notify.md)，使用者 11-13「say/chat被當成不是使用者打的，我覺得可以，真的有要的話，就自己open進去說。」）：`say`／`chat` 對 eca（定義有 `cli.json`）寄的信，body 多一個 `name`＝寄件人；畫面開著的 claude 身把它當信封署名（畫面顯示「Message from @名字」，CLI 告訴模型這則不是它的使用者打的），`name` 不接進 history。誰算寄件人：`--from 誰` ＞ `$AOS_STACK` 落在 daemon 表上哪一隻的 stack 裡＝那隻的名字（agent 的工具或它的 CLI 下的指令，例如 subagent 工具的 say／ask）＞ 登入名。名字要一行、最多 64 字、不含 `" < > &` 與控制字元，`--from` 不合＝`ArgumentsBad`。目標不是 eca＝信不帶 `name`，跟以前一樣。要當成使用者親口說的，自己 `aos-agent open` 進畫面打。
- **聽**：`aos-agent listen --letter 信名`（信名＝say 印的那個）等**那封的回答**：`aos_ws.answer_for` 照 queue → history → `history_removed.jsonl` → `letters.json` 找，回答的 `aos.answer_to` 含這封就印；`letters.json` 的 `dropped` 有它＝`LetterDropped`（帶原因）；身體還沒升級（查無紀錄、history 裡有不帶 `aos` 的新信列）＝stderr 提醒一句、退回下面的舊配法（[reply-match-1114](../../../../thinking/2026-11/14/reply-match-1114.md)）。不給信名＝等**最新那封**＝queue 的 `new/`、`cur/` 裡照處理順序排最後的（`aos_ws.letter_key`）：還在就等；queue 空了、`letters.json` 的 `pending` 有信＝等 pending 最後那封；都沒有＝印 history 最新那則沒有 `tool_calls` 的 assistant（先 say 後 listen 不會漏）。交出去還在答（eca 交給 CLI 就收信、fsm 答的途中；history 最後一則 user 在最後一則回答之後也算——前一題的回答在等的途中才到，不會被當成這封的）照等；都空、history 也沒回答＝`QuestionUnknown`；信不見了、沒回答、也沒人在跑＝`AnswerMissing`；沒人在跑＝提醒一次、繼續等。等的那封滿 10 秒還在 `queue/new/`、表上又是 `running`＝提醒一次 `SIG has not been taken from queue/new/ after 10 s; X may be busy, or its daemon may be down: aos-daemon-ctl --daemon D ls (the last line shows what the daemon's supervisor sees)`，之後照等（no-pid P3）。`--timeout-s` 秒數到了＝`AnswerMissing`。也可用 `--timeout-cycles N`（signed 64-bit 範圍的正十進位整數），與 `--timeout-s` 擇一；兩者並給或搭 `--last`／`--follow`＝`ArgumentsBad`。時鐘期限用 `aos_ws.deadline_after`／`expired`：有 `AOS_CLOCK` 就只看時鐘、停鐘照等；未設就按 `AOS_CLOCK_INTERVAL`（預設 1000 毫秒）退牆鐘。未給期限＝無上限；`--timeout-s` 照牆鐘秒數算、不看時鐘。暫停中＝提醒一次「要 resume」照等；答到一半被 stop／sleep、或出錯結束（表上 stopped／sleeping；出錯的帶原因）＝提醒一次（附 `ctl start`／`ctl wake` 怎麼叫回）照等；等到一半那隻下了表（退 0）＝`AnswerMissing` 說它最後的輸出在哪、同名 `ctl add` 接著用；被 `ctl rm --purge`（stack 刪了）＝`InstanceMissing`（不帶 `--purge` 的 `ctl rm` 留 stack，照上一條「下了表」走）（edge-agent）。`--last N` 印最後 N 段就走；單用 `--follow` 從目前歷史尾端追新回答，搭 `--last N` 則先印最後 N 段再追。數字旗標（E1）：`--timeout-s` 要有限、不小於 0 的秒數（不設上限＝不給這個旗標），`--last` 要不小於 0 的整數；`inf`、`nan`、`1e999`、`1.5`、`-1`、`abc`、空字串都是 `ArgumentsBad` 一行、退 1。
- **ask**：say＋`listen --letter` 一次做完（subagent 的 op ask 就是跑它），stdout 只有回答；等的是自己那封信的回答，同時有別人問同一隻也各拿各的，一則回答回好幾封時每個問的人都拿到同一則全文；`chat` 每句也一樣。寄之前先記 history 的列數與回答數，身體還沒升級時退回「等最新那則」並在 stderr 說一句。Ctrl-C＝退 130，stderr 印 `listen --target X --letter 信名` 讓你之後再拿（見 [docs/02](docs/02-已知限制.md)）。
- **chat**：say＋listen 的迴圈；提示符 `> ` 在 stderr、stdout 只有回答（`chat < 問題.txt > 答案.txt` 也行）；不印信件名稱。等答案時 Ctrl-C＝退 130，那封已寄出、agent 照答，之後用 `listen` 看；stdin 結束退 0；途中 `AnswerMissing` 印一行錯誤行、不退出（stdin 結束時印過錯誤行＝退 1）；每句寄之前重查表，聊到一半被 `ctl rm`＝`InstanceMissing` 退 1（edge-agent）。**讀一行**（[chat-utf8](../../../../thinking/2026-11/12/chat-utf8.md)，在 `aos_agent/read_line.py`）：stdin 與 stdout 都是終端機＝Python `input()` 配 GNU readline 做行編輯——Backspace 按字刪中文、方向鍵移游標、上鍵叫回前幾句、一行沒有 4096 bytes 上限、貼上多行＝一則訊息，這時提示符由 readline 畫在終端機上（stdout 那邊）；其他情況按行讀 bytes、提示符在 stderr，stdin 是終端機時先替它開 `iutf8`、結束時還原。還是讀到不是 UTF-8 的一行＝錯誤行 `ArgumentsBad this line is not UTF-8, not sent; type it again (…stty iutf8)`、不寄、回提示符。
- **看**：`aos-agent ctl state`（狀態、工作區、定義、stack、queue 幾封、最新回答前 60 字、`mailbox_warning.txt` 那一行）。
- **停**（都在 `ctl` 下）：`pause`／`resume`＝`aos-daemon-ctl pause／resume`（寫它的 ctl.json、等它套用最多 5 秒才回；停在哪是身體的事：eca 一批信、fsm 一格）；暫停中被 stop／sleep 的，`ctl start`／`wake` 起來照它的 state 先暫停，那行輸出尾巴會說 `it was paused when it went down, so it comes back paused: aos-agent ctl resume …`；`ctl state` 的 paused＝表上那列 `running` 且它自己 state 窗的 `phase` 是 `paused`（[listen paused bug](../../../../thinking/2026-11/05/portable-flow/07-listen-paused-bug.md)；不比 pid）；`stop`／`start`＝表上留成 `stopped`、stack 留著、信照收不答；`sleep`／`wake`＝現在就睡、表上留成 `sleeping`、daemon 開門自己醒（搬家前用）。
- 直接 `aos-exec --ws W <agent>` 跑、沒掛 daemon 的，aos-agent 不管：`aos-post send --ordered W/.stack/queue` 寫信、看 `W/.stack/history.jsonl`。

## 搬家

整份 `ws/`（連 `.stack`）和定義保持相對位置 `cp -r` 或 git 來回，到新位置 `aos-exec ../daemon` 就接著跑。要點：**先 Ctrl-C 讓 daemon 睡著再存**；`pid`、`boot_id` 那幾欄是上一台的、只有 daemon 自己看；eca 的 claude session 綁那台的 `~/.claude`；git 掉的空資料夾第一圈自己建回；只在 Linux 檔案系統 checkout、別在 Windows checkout 上跑；範本 `cp stack.gitignore ws/.stack/.gitignore`、`cp stack.gitattributes <repo 根>/.gitattributes`。全文與實測在 [docs/04-搬家](docs/04-搬家.md#搬家)。

## 已知限制

併自 extras/eca 的那段，在 [docs/02-已知限制](docs/02-已知限制.md)；tools 覆蓋層的邊在 [docs/03](docs/03-tools覆蓋層.md#已知的邊)。

**裁定 B**：body.json 是陣列或 argv 物件都原樣經 aos-exec 起，不辨認 aos-loop 來改掛法。任何 body 都可 stop／sleep；stop 寫公開 ctl 並等自行退（不讀 ctl 的就等它自己結束），sleep 送 SIGTERM；stop 中的 stopping 列也能 sleep，退後保留 stopped 與 launch，用 ctl start 再起。非 0 留 stopped＋reason、修好 ctl start；退 0 才下表（adopt 拿不到碼另算），收工時 running 的睡下（sleeping），stop 途中的留 stopped，sleep 途中的睡下，rm 途中的拿掉；收工途中被 kill -9，重開時照表上的 `stop_mode` 做，結果一樣。睡下的開門自動 wake。
