## 已知限制（併自 extras/eca）

- **kernel 查表不能繞過**：設了 `AOS_KERNEL` 且沒給 `--daemon` 時，`ctl ls`／`who`／`where`／`state` 先寄 `procs_state_path` 查詢信再讀那份檔；`--timeout-s S` 預設 3 秒，問不到＝`KernelFailed`，不退回讀 `AOS_DAEMON`。只會掛 proc、不答查詢信的 kernel 仍能處理 `add`、不帶 `--purge` 的 `rm`、`stop`／`start`／`sleep`／`wake`（只看自己的回信，不先讀表、不核活、不等表）；但 `rm --purge`、`set-def`、`pause`／`resume` 要先問到表。明給 `--daemon` 才指名直讀那台。
- **`ctl stop` 不關畫面**（C′ B 包）：走不走 kernel 都一樣，畫面交給 eca 定義的 after_stop hook `screen_linger_stop`，照 `cli.json` 的 `screen_close_after_s` 延後關（預設 600 秒、0＝當場），期間又起來就不關；stack 的 hookeds.json 把那兩格設 null（或缺了）＝停下後畫面一直開著，要關就 `aos-agent close --target N`。沒宣告這兩格的別種身體同理。`ctl rm`、`ctl set-def` 照舊自己先關。
- **走 kernel 時的畫面**（批 5b）：設了 `AOS_KERNEL` 且沒給 `--daemon` 時，不帶 `--purge` 的 `ctl rm` 不自動關 eca 畫面，`rm` 要在 rm **之前**先 close（刪減表缺 def 時也可能無法用 close）。一般 `rm --purge` 先讀列、寄 rm 等成功，再用存下的列關畫面、刪 stack；被拒不關不刪。列缺 def 時印 warning，仍照常 purge。`--no-wait` 照舊不關畫面。已 rm 而查不到列時，用 `tmux -S <socket> kill-server`：socket 為 `$XDG_RUNTIME_DIR/aos-tty-<uid>/<hash>.sock`，hash 是小格 realpath（`<stack>/<kind>`，claude 身為 `<stack>/claude`）的 SHA-256 前 16 個十六進位字元；`XDG_RUNTIME_DIR` 未設、非絕對路徑、不存在、不可寫或路徑太長時用 `/tmp/aos-tty-<uid>/`。找既有 socket 時也會檢查 `/tmp` 候選與舊位置 `<stack>/<kind>/tty.sock`，刪 stack 不會刪掉外面的 socket。
- **畫面入口與 watch 的表**：走 kernel 時 `run_entry` 保留呼叫者的 `AOS_KERNEL`／`AOS_DAEMON`，不把表檔所在夾冒充 daemon；直連時指定 `AOS_DAEMON` 並拿掉 `AOS_KERNEL`。watch 每隔至少 5 秒重問表檔（每次等回信最多 1 秒），空表、找不到自己或明確非 running 就結束；讀不到、表未給 stack 或自己那列未給 phase 都繼續等。open 不改：小格 `env.json` 有效時，CLI 用 agent 自己記的環境；檔案不在或壞掉則沿用開畫面那個殼的值。
- **`AOS_DAEMON` 要給絕對路徑**，相對路徑 cd 之後就對不上（使用者 11-02 晚選「3」：維持、只寫清楚）。沒走 kernel、`-d` 與 `AOS_DAEMON` 都沒有時，只從 cwd 認出的 agent stack 往上兩層找 daemon（11-21 起；樹根的 `./.stack` 本身不當 daemon，見 README「哪個 daemon」）；`-s` 掛在別處的 stack 往上兩層不是 daemon，照樣要給。
- **從 cwd 找對象只認 stack 本身**：要 cd 進 agent 的 stack（或 `.stack` 就是它 stack 的那一夾）；站在 stack 的子夾（`think/`、`tools/<名>/`）、或定義夾裡找不到（定義一份可掛好幾隻，認不出是哪隻），照樣給 `-t`。認的檔是 `stderr.txt`：daemon 起過那隻一次才有（`ctl add` 之後馬上就起，平常碰不到）；有人刪了它就認不出來，給 `-t`。
- **短時間多封信＝一批**（eca）：aos-eca-turn 一次把 queue 的信全部、照順序丟進一次 CLI；人接在畫面上時信排著等人跳出；`listen` 不給信名時等的是最新那封，前面的用 `--letter 信名` 等、或 `--last N` 看。
- **`ask`／`chat`／`listen --letter` 配信名，但身體要升級過**（[reply-match-1114](../../../../../thinking/2026-11/14/reply-match-1114.md)，取代 11-14 ok-pilot 的「ask 不配對信名」）：agent 的身體收信時在 history 那列記 `aos.letter`、最終回答記 `aos.answer_to`，stack 裡另有 `letters.json`（`pending`／`dropped`）；讀的一方照 queue → history → `history_removed.jsonl` → `letters.json` 查那封信，所以兩人同時問同一隻各拿各的，一批多封拿到同一則全文，被丟的信（壞信、被 hook 擋、交出去後失敗）立刻報 `LetterDropped`。**還沒升級的身體**（換樹空窗裡還在跑舊 `templates/`、`lib/` 的 agent，沒有 `aos.letter`）：信離開 queue 後查無紀錄、寄之後多了不帶 `aos` 的信列，就退回舊配法——等最新那則回答，stderr 說一句「body is not upgraded yet」，這時同時有別人對同一隻說話仍可能拿錯；查無紀錄又沒有那種列＝等到逾時報 `AnswerMissing`（說明可能是身體還沒升級或信名寫錯）。`listen` 不給信名＝等 queue 最新那封，queue 空就等 `letters.json` 的 pending 最後那封，都沒有才照舊印最新回答；舊身體走的就是最後這條，不另說。
- **執行 aos-agent 的 PATH**：一定要找得到 `aos-post`、`aos-exec`；`llm set` 另要 `aos-json`。叫不到＝`CommandMissing`。`tools` 不看 PATH：照 aos-agent 自己的位置找同一份 repo 的 `proto8/py/aos/apps/tools/main.py`，用跑 aos-agent 的那個 Python（`sys.executable`）跑它（坑-65）。
- **daemon 的 PATH**：子 loop 用 daemon 啟動時的環境叫 claude／codex、aos-eca-turn、aos-post、aos-exec；接了工具還要 `proto8/py/aos/apps/mcp`（aos-mcp）與 `proto8/py/aos/apps/tools`（aos-tools）。
- **新資料夾第一次開畫面，claude 會先問「信任這個資料夾嗎」**：`open` 接進去，用方向鍵移到「Yes」再按 Enter（直接 Enter 是「No, exit」）。
- **出錯結束的（CLI 出錯、fsm 腦失敗，任意 proc 退非 0）留在表上 `stopped`＋`reason`**（11-05 使用者裁「留表標 stopped (Recommended)」）：`ctl ls` 最後一欄 reason、`ctl state` 多一行 `reason`；修好後 `aos-agent llm reset`／`tools reset`（或直接改 stack 裡那份）再 `aos-agent ctl start`；不要了 `ctl rm`。**做完的（退 0：跑滿、身體退 10、直接寫它 `ctl.json` 的 stop）在 daemon 表上沒有**：`ctl ls` 不列、`ctl state`／`ctl rm`＝`InstanceMissing`；stack 留著（自己 `rm -r`），要接著用就同名再 `ctl add`（用自訂 `--stack` 的要記得當初給的 S）。
- **回信信箱要讓 daemon、判官寫得進去**（edge-agent 題 2；[no-pid](../../../../../thinking/2026-11/05/no-pid/README.md) P3 共用信箱）：回信寄到 `$AOS_STACK/daemon_reply/`（人殼走 kernel＝`$AOS_KERNEL/reply/`，否則＝`<daemon stack>/procs_requests/reply/`）。照 [kernel/docs/02](../../../../../templates/kernel/docs/02-kernel-modes.md)「Linux 權限」那級把 daemon／判官放別的帳號時，它們寫不進去＝回信寄不出去（判官 stderr 一行 `ReplyFailed`），aos-agent 等滿 `--timeout-s S`（預設 30 秒）一封都沒收到＝`DaemonFailed no reply …`，就算表上其實已經變了；這種佈置要讓那個信箱給 daemon／判官的帳號寫。沙箱裡的 aos-agent 也一樣：回信信箱在自己的 stack，要綁 rw。
- **逾時不等於保證取消**：逾時失敗會盡力用 `aos-post regret` 撤原收信箱 `new/` 裡的信；成功撤掉才不會晚套。`--on-queued fail` 的信帶 `queue_wait_ms`，判官領進 cur 的也按 `sent_at` 牆鐘期限到期拒絕，包含睡醒後首次見到的過期信。但信已轉寄進 daemon ctl、或已被 daemon 領走進 cur 就撤不回；可能失敗後仍掛上，需查表處理。`--on-queued ok` 成功排隊會保留請求，之後有格照掛；它的成功只表示排隊。晚到回信留共用信箱，10 分鐘後由下一個開箱者收掉。`kill -9` 等待者不能保證跑撤信；直接 ctl／繞過判官也不能靠判官期限擋晚套。
- **收件者睡著**：`AOS_KERNEL` 只是信箱路由，不辨識 kernel 身份或預判其狀態；判官睡著是設計系統的人要管的風險（使用者 11-07）：手動 `aos-daemon-ctl wake NAME`（一律直寄 daemon、不看 `AOS_KERNEL`）叫醒，否則信照樣留它的箱裡等它回來；程式不自動叫醒、不自動繞過。
- **信交給 CLI 就算答了，中途掛掉的那批不重答**（eca 20）：要重答就再 `say` 一次。`ctl sleep` 剛好在答的時候也一樣（daemon SIGTERM 掉 CLI，wake 之後那句不會有回答；edge-agent 實測，`ctl sleep` 會先提醒一聲）；`ctl stop` 會等這輪答完，不會丟。
- **`limits` 已生效**（feat-proto 件 5）：`ctl add` 驗過就轉給 `aos-daemon-ctl add --limits`，daemon 在子行程 setrlimit／換帳號。是**每個行程各自**的上限（rlimit），不從 daemon 的總額扣；比 daemon 自己的 hard 寬不會自動夾、那隻起不來（`LimitBad`）。
- `watch` 只讀非互動那條路的 `live.jsonl`；收起畫面＝`tmux kill-server`，人打到一半沒送出的字會丟。
- `llm` 改過的鍵不跟定義（只放改過的鍵，其他照定義；`llm ls -l` 列哪些是改過的），要回去就 `reset`。`tools` 是覆蓋層、定義改了照疊（[03](03-tools覆蓋層.md)）。
