## 1. 一句話

proto8 ＝ **一個資料夾（世界），裡面每個子資料夾是一個計算任務：一份 `task.json`。有 `argv` 的會被跑；有 `capacity` 的是資源；有 `needs` 的要排到某個資源的格才跑。tick 每 N 秒照排序器寫的順序表起行程；排序器自己也是一個任務。** 任何人（含模型）用 `ls`、`cat`、改 JSON 就能看懂、操作整個世界。

跟第一版差在：排序的是「任務→資源的格」不是「先起哪個資料夾」；核心不認 `in/`／`out/`、不讀九軸、不等任務、不殺行程；需求也是一個資料夾；`belief.json`、`steps.json`、`priority` 從核心階段拿掉。

## 2. 世界長什麼樣（候選，§5 (a)(b) 答了才定）

```
world/
├── .aos/
│   ├── tick.json          {"round": 1832, "at": "…"}            核心寫
│   ├── order.json         排序器寫（形狀見 §3）；誰都能手寫一份
│   ├── rounds.jsonl       一回合一行：起了誰、誰退出、退出碼    核心寫
│   └── snapshots/1850.zip
├── scheduler/task.json    {"argv": ["python3", "run.py"]}        排序器：普通任務
├── scheduler/goal.md      7 行白話：這個世界照什麼排
├── painter-a/task.json    {"serves": "paint", "capacity": 4, "traits": {"good_at": ["人物"], "bad_at": ["風景"]}}
├── painter-b/task.json    {"serves": "paint", "capacity": 1, "traits": {"good_at": ["風景"]}}
├── brain/task.json        {"serves": "llm", "capacity": 1, "traits": {"model": "luna"}}
├── human/task.json        {"serves": "human", "capacity": 1}      你的座位
├── req-01/task.json       {"needs": "paint", "argv": ["python3", "../painter-a/draw.py"], "traits": {"want": "人物"}}
└── req-02/task.json       {"needs": "paint", "traits": {"want": "風景"}}
```

**核心只認四個鍵**：`argv`、`needs`、`serves`、`capacity`。其他（`traits`、九軸）核心一個字都不讀。
**狀態不存欄位、用檔案推**（另一條路的做法）：資料夾裡沒 `run.json`＝排隊；有 `run.json` 沒 `exit`＝跑著；有 `exit`＝做完。`ls` 一眼看出。

**九軸怎麼放**：`task.json` 可以有 `axes` 一段（`life`、`determinism`、`rerun`、`kill`、`state`、`io`、`reach`；見 九軸報告 §1（已刪：AI 產出，使用者 10-12 夜要求刪除）），**第一版沒有任何程式讀它**，寫了只是給人和模型看。`needs`／`serves`／`capacity` 就是第 4 軸（資源）的需求側與供給側。

## 3. 核心只做一件事：tick

```
每 N 秒（固定，不等任何人）：
  round += 1
  讀 .aos/order.json；它的 round 不是上一回合 → 當沒有
  有表：照表，每個資源的格有空就起排在前面的任務（cwd＝任務資料夾，環境 AOS_ROOT、AOS_ROUND、AOS_SLOT）
  沒表：有 argv 又沒 needs 的全起（排序器因此永遠會被起、漏了自己也復活）
  已經在跑的不重起；退出的記一行 rounds.jsonl
  看到 .aos/snapshot 旗標：這回合不起任何人、zip（排除 snapshots/）、刪旗標
  寫 tick.json
```

一支檔、純標準庫、**≤150 行**。不等、不殺、不讀軸、不認 `in/`／`out/`、stdout／stderr 繼承（任務要留日誌自己導）。
起行程 `start_new_session`；寫檔 → fsync → rename；暫存名 `.` 開頭、掃資料夾忽略 `.` 開頭（打撈 b-1、b-6、b-7）。

`order.json`（排序器實驗的形狀＋找洞的 `round`）：
```json
{"round": 1833,
 "assign": {"painter-a": ["req-03", "req-01"], "painter-b": ["req-02"], "brain": [], "human": []},
 "wait": ["req-04"]}
```

**任務之間怎麼講話**：核心沒有協定。寫檔、看檔，就這樣；慣例（檔名帶自己的名字、先寫 `.tmp` 再 rename、讀完就刪）寫在 README 給任務作者看，核心不管。

## 5. 要你拍板的五個設計題（都是你 §4 留白的，附預設）

> **使用者 10-11 回覆**：(a) **格數**。(b)～(e)「有點偏離我的想法，之後再說」——**沒有定、不照預設做**。所以 §2 的 `req-*/`、§3 的 `order.json` 形狀、§4 第 1 步的排序器實驗都還不能動；(b)～(e) **題目本身就問錯了**（使用者 10-11 確認「問的題目不對」），不是預設答錯；整個 §5 (b)～(e) 連同它們撐著的 §2、§3、§4 第 1 步作廢，等使用者講他的想法再重寫。

**(a) 資源是「格數」還是「會收件的行程」？**
格數＝`capacity: 1`，要用它的任務排到格就**自己跑**（問模型的任務＝argv 是 `aos-llm`、`needs: llm`）；沒有 `in/`、沒有協定。
會收件的行程＝資源自己有 argv 常駐，別人把東西丟給它（你 2.8 的原話是這個）。
預設：**第一版格數**。理由：信箱協定整個消失、核心最小；資源真要變常駐行程時，它就是一個 `life: service` 的任務佔自己的格，核心不用改。綜合 §3(a)（已刪：AI 產出，使用者 10-12 夜要求刪除）

**(b) 誰算任務：掃一層資料夾，還是登記？**
你 10-04 說「不該掃，要登記」，打撈 c-1 有實證（兩個 daemon 同時 tick 一個資料夾）。
預設：**第一版掃一層**（只認有 `task.json` 的直接子資料夾；一個世界一個 tick）。理由：單機單 tick 沒那個問題；但這是你明說過的，請你定。

**(c) 需求是「一件一個資料夾」嗎？做完的誰清？**
一件一夾最合「一切都是計算任務」，排序器只讀一種檔；但你罰過「每回合產資料夾」。
預設：**需求一件一夾；agent 內部的步不開夾**（那是 agent 的事，後面再說）；做完的夾第一版不清、README 一句「`rm -r` 就是清」，等真礙事再寫 `aos gc`。

**(d) 排序器是「一個管全部資源」還是「每個資源一個」？**
一個：讀全世界 `*/task.json`，寫整張 `order.json`。每個資源一個：資源的 task.json 指一個排序 argv，tick 替每個資源叫（另一條路）。
預設：**一個**。理由：第 1 步的實驗就是這樣做的、答案唯一可 `diff`；要分也只是排序器自己再 fork。

**(e) 「生成排序程式的程式」第一版要不要進世界？**
你 2.10 說它是一個會呼叫模型的程式。第 1 步是我在外面 `curl` 模型，不是世界裡的任務。
預設：**第一版在外面做**，但 PLAN 寫明「生成器任務化是以後的事、位子空著不用改核心」（它就是一個 `needs: llm` 的任務，輸出寫進 `scheduler/run.py`）。

## 7. 限制與失敗行為（astra 要我把「不做」改寫成這樣）

| 事 | 第一版的行為 | 不是 |
|---|---|---|
| 任務跑超過一回合 | 下回合不重起，`run.json` 留著，排序器看得見它佔格 | 不殺、不設期限 |
| tick 被殺重起 | 讀 `tick.json` 接續回合數；舊子行程變孤兒照跑；**同一任務可能被起第二份**——寫進 README | 不做 pid 驗身、不做恢復 |
| argv 起不來／task.json 壞 | stderr 一行＋`rounds.jsonl` 一行，跳過，不寫任何東西進那個資料夾 | 不做退出碼契約 |
| `order.json` 壞／round 過期／指到不存在的任務 | 當沒有表：只起沒 `needs` 的；stderr 一行 | 不猜、不修 |
| 兩個任務同回合寫同一處 | 核心不管；README 慣例：檔名帶自己名字、`.tmp`→rename | 不上鎖 |
| 模型呼叫中途被殺 | 那是 `aos-llm` 任務的事：它自己寫「在途」檔、設上限；第 4 步會碰到（打撈 b-5） | 核心不做 once／grant／帳本 |
| 花費 | `aos-llm` 每次呼叫在自己資料夾寫一行 | 不做帳本包 |
| 權限、身份、掛載 | 全在一個 Linux 使用者底下 | daemon 層以後接 |
| 信箱、技能、記性、選單、壓縮、監督者 | 都是任務自己的事或排序器的一條規則 | 不做包 |
