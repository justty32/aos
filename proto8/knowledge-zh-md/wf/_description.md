# wf：工作區的工作文檔怎麼組織

一個專案（工作區）裡給 agent 用的工作文檔——做事的流程、查得到的知識與記錄、還沒完的事——收在工作區的 `wf/` 夾，用 index 與節點組織。這一庫講它的組織原則。

節點寫成 `.md` 還是 `.json`：新寫的預設寫 `.md`，再用夾的 `_index.json` 當導航骨架；要用哪一種都可以，不檢查（這一庫自己的頁現在都是 md）。本庫各頁裡寫 `<名稱>.json`、「json 節點」的地方講的是 json 形態的寫法；寫成 md 時，原本的鍵就是標題（`#/when`、`#/steps/0` 照樣尋得到），要給人照抄的空殼放在一個 ```` ```json ```` 區塊裡。

注意兩種路徑：本庫自己的節點寫 `wf/layers.md` 這種（從 knowledge 這層算）；講到「工作區的 `wf/…`」時，指的是專案工作區裡的那個夾，不是本庫。

樹本身怎麼寫——`_index.json`／`_index`、`_description`、統一路徑、`$ref`、一段文字寫字串還是字串陣列、大小建議、名字用字——是整個 knowledge 共用的規則，出處是 knowledge 的 `docs/01-樹長怎樣與多庫.md`、`docs/02-寫入與節點怎麼寫.md`，本庫不重講。

- `wf/layers.md`：東西該放哪一層、流程與知識怎麼分、私有 index、日誌寫法。
- `wf/nodes.md`：檔名、index 的說明怎麼寫、工作流節點的固定形式、一個工作流怎麼長大。
- `wf/tidying.md`：什麼時候該拆、怎麼拆、過時的怎麼封存。
- `wf/workflows/`：出廠的工作流節點（kernel 的記決定、規劃、記踩坑、記偏好、文件整理；開發類的功能開發、測試、重構、搬檔、分析、調查、環境、patch），那夾的 `_index.json` 就是派發表。
- `wf/knowledge/`：工作流會指過來查的出廠知識（工作流節點的骨架、內容精簡的判準、整理踩過的坑、活清單寫法、鐵律、開發類的派發分辨、code map 規則、綠燈不等於有檢查）。
- `wf/skeletons/`：專案自己要填的記錄的空殼（決策、想法、踩坑、偏好、驗證表、環境、code map、慣例、筆記、分析產物），工作流叫你建檔時照它抄進工作區。
- `wf/source.md`：這些內容從哪裡來、哪些沒帶進來。
