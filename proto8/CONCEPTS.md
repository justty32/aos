## 2. 規則（使用者說過「一定是這樣」的）

- **C-01** 一切都是計算任務：排序是、資源分配是、資源本身也是。核心沒有第二種東西。（2.8）
- **C-02** 計算任務＝POSIX 行程。在它之上可以分種類，但其實不用分。（2.7）
- **C-03** 資源＝有限的處理能力，由任務的需求反推出來（任務要 scanf，人類輸入就是資源）。（2.7）
- **C-04** 資源的容量是格數。（3b(a)）
- **C-05** 四層由下往上：Linux → daemon → 時空（資料夾＋tick）→ 排程與資源分配 → agent。上層只透過下層。（2.5、10-03 S-02）
- **C-06** 空間＝資料夾、時間＝tick。這一塊已經定好，不用再說。（2.5）
- **C-07** tick 是時間格，不是「等誰做完」。停下來時正在跑的任務可以不停，agent 看到的狀況裡可以含「這件事正在跑」。（2.11）
- **C-08** 一切用檔案系統、POSIX、JSON，因為大模型天生會，所以對這套體系有自省能力。（2.6）
- **C-09** 每個計算任務都有九軸的基礎特性，加上人隨意附加的特性；特性多到只能靠 LLM 處理。（2.9）
- **C-10** 排序規則可以任意設計；可以有一個程式呼叫模型來生成排序程式。（2.10）
- **C-11** agent 是狀態機、是函式、是計算任務；它叫的模型也是計算任務。（2.13、2.14）
- **C-12** agent 的簽名＝腦＋核心人格＋近期記憶＋手腳。（2.17）
- **C-13** agent 自己的迴圈便宜；貴的是它叫的模型和工具。排程的對象是「誰先用腦」「它何時該跑」。（2.18、2.19）
- **C-14** 確定性是任務的屬性；可預測性是觀察者的認識，有主體性。（2.14、2.15）
- **C-15** 提高 agent 可預測性＝把它當 S 表示式拆，能寫死的節點換成程式，降低走進不可預測節點的機率。（2.16）
- **C-16** 要最佳化的不是時間空間，是金錢、可預測性、人能不能理解。（9/1，ideas 01；2.1 重申「可用性、人類可理解性」）
- **C-17** agent 內部怎麼設計是後面的事；先把底打好。（2.20）
- **C-18** 大操作（問模型、跑久的工具）丟到另一個資料夾讓另一個行程處理，agent 自己每次 eval 短促。（9/19）
- **C-19** 沒輸入就每 tick 沒事。（9/23）

## 3. 概念層的空白（AI 的觀察，不出題、不給答案）

讀完上面，有幾個概念之間的關係還沒說，但不說就沒法往下想。只是列出來；要不要補、怎麼補是使用者的。

1. 一個計算任務同時需要兩個資源時，「分配」是什麼意思。
2. 「格」什麼時候算被占、什麼時候算放掉——跟 tick 是什麼關係。
3. 人既是資源（人類輸入）也是 agent（老闆）；同一個東西在兩個位置。
4. 「一次計算」什麼時候算結束：行程退出？還是別的。
5. 資源「也是計算任務」（C-01）和資源「是格數」（C-04）怎麼同時成立——格數是誰在數。
6. 排序器是誰起的、什麼時候跑：它自己也是任務，那誰排它。
7. tick 的間隔是哪一層的概念。
8. 九軸裡「持續性」那一軸和「tick 是時間格」怎麼接：跑好幾回合的任務在時間上長什麼樣。
9. 「停下來打包」的那個「停」，停的是時間還是行程。
10. 可預測性既然有主體性，那在這套系統裡「觀察者」是個概念嗎，還是只是人在看。
