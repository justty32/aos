N-43 接續（上一份的子項到這裡繼續）：

  - **10-28 補：錯誤分類靠 stderr 代號，結束碼仍一律 1**（使用者 10-28「照新做法」，[thinking 10-28 agent-ops 決定 11](../../../thinking/2026-10/28/agent-ops/02-決定.md#決定10-28)；細節照原則代定、可翻案，[agent-round § 4 endpoint 的錯](../../../thinking/2026-10/28/agent-round/02-2-round-一輪本身.md#4-單位介面)）：要讓別人分種類的錯，寫在 stderr 那一行的代號裡（`名: 代號 原因`〔11-05 起 `名: error: 代號 原因`〕，代號照 C-54；例 endpoint 的 `BrainFailed`、`KeyBad`、`ModelUnknown`、`RequestBad`、`ReplyBad`，要分 429 跟 503 看原因裡的數字），不另用結束碼分。例：round 把 endpoint 的 stderr 那一行交給 `hook/on_error` 決定停或換（CONVENTION P-20 的 10-28 加註）。 **11-04 加註**（round 已刪後的條文整理，使用者 11-04「照建議」，[收斂報告 § round 刪掉後](../../../../wf/workflows/tidy/reports/2026-11-03-收斂/03-round刪掉後的條文之一.md#round-刪掉後沒實作撐的條文11-04給使用者裁)）：末句「round 把 endpoint 的 stderr 那一行交給 `hook/on_error`」的例子出自已刪的 round（`hook/`、endpoint 格都已刪，它指的 CONVENTION P-20 的 10-28 加註也 11-04 刪了）；「錯誤分類靠 stderr 代號、結束碼仍一律 1」本身照舊（例 endpoint 函數 `lib/base/llm_http` 退 `EndpointFailed`、`ReplyBad`，`aos-llm` 退 `KernelMissing`〔11-05 改名 `LlmKernelMissing`，N-63〕、`RequestBad`；11-04 晚前的例子是 demo 各隻 `brain.py` 退 `BrainFailed`，問腦改寄信給 llm kernel 後那支不再打端點，[think-as-function](../../../thinking/2026-11/04/think-as-function/README.md)）。
  - **11-05 補：stderr 只有兩種行**（使用者 11-05，問「退 0 時提醒能不能印 stderr」答：「可以，固定格式："error:", "warning:"後面接你那個」；[thinking 11-05 stdio-unify](../../../thinking/2026-11/05/stdio-unify/README.md) R1）：aos 自己的程式寫 stderr 只有兩種行——
    - **錯誤行** `程式: error: 代號 原因`（例 `aos-post: error: MailboxMissing no mailbox at /x`）：代號＝`error: ` 後第一個字（C-54），解析代號的地方都照這個拆；要附用法放在原因後面 `(usage: …)`（CONVENTION P-44）；開頭可以是 agent 名（P-21）。
    - **提醒行** `程式: warning: 句子`（不帶代號）：長駐程式的 log、給人看的狀態句（attaching、watching…）、「沒出錯但該讓人知道」的事都寫成這種；互動提示符（aos-agent chat 的 `> `）不算一行（代定 D5）。
    - 退 0 可以有提醒行；**有錯誤行就不准退 0**。其他雜訊（括號句、`note:`、不帶前綴的 log）改成提醒行或拿掉。透明轉交（exec 交棒、照下層碼結束）不受影響：那時的 stderr 是下層的。
  - **11-05 補：10 的兩種讀法**（照盤點推薦，[thinking 11-05 stdio-unify](../../../thinking/2026-11/05/stdio-unify/README.md) R9）：(a) 基礎工具（aos-post、aos-lock、`aos-llm recv`、`aos-json check`…）的 10＝「**查了，沒有**」（沒信、沒鎖、還沒回、驗不過有問題〔aos-json check，代定 D1〕），不是錯、不寫錯誤行；(b) fsm 格的**分岔碼**（照物件 `next` 查表的碼，例 templates/agent-fsm wait 格的 10「還沒回」、11「回 think 重組」）是給那張 fsm 表看的，被表接住就不算錯（同上一份的 10-30 加註）。
  - **11-05 補：轉交的碼**（照盤點推薦，[thinking 11-05 stdio-unify](../../../thinking/2026-11/05/stdio-unify/README.md) R8）：轉交的碼不改數字、不另用數字分種類；分得出誰錯靠 stderr——**退非 0 時 stderr 有 `我的名字: error:` 這一行＝我自己錯；沒有＝下層的碼**。會轉交碼的程式（aos-exec、`aos-tools call`、aos-sandbox、aos-loop、aos-fsm、kernel/llm-kernel 的 fake_slow…）各自 README 寫這一句。aos-loop 身體退非 0 時照樣寫一行 `aos-loop: error: RunFailed run N: X failed with exit code C` 再以那個碼結束（代定 D4）：這行說的是「第幾次、誰、碼幾」（P-21），碼仍是身體的。
  - **11-05 補：訊號**（照盤點推薦，[thinking 11-05 stdio-unify](../../../thinking/2026-11/05/stdio-unify/README.md) R12）：子程式被訊號殺、而我照轉交碼結束時，一律換算成 128＋N（不把 Python 的負數 returncode 直接當碼）；Python 寫的程式被 Ctrl-C 不吐 traceback、退 130（＝128＋2）；被 TERM 照現狀（有接的退 128＋15）。
