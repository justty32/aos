## 設定檔 `loop.json`、`fsm.json`、`daemon.json` 與 `exec`

「要跑什麼」一律叫 `exec` 見 [命名](../命名.md)「要跑什麼＝`exec`」（含原話），規範在 [N-28](../04-基礎設施-loop與daemon/02-N-28.md)、[N-36](../07-基礎設施-組合子.md)；這裡只放概念那邊搬來的檔名句子。

- loop＝`aos-loop [FLAGS...] loop.json`（`{"exec", "max"}`）；設定檔是唯一的位置參數（[ideas 10-21 § 9](../../../thinking/2026-10/21/ideas/05-7-審後的五個細縫與修正.md#9-設定檔是唯一的位置參數path-改字串拼接10-21-傍晚)）；`exec` 收 aos-exec 的目標（字串或陣列，每次 `aos-exec` 它；`loop.json#/body` 也是目標），也可以直接放單子物件、行程內跑（[thinking 10-24](../../../thinking/2026-10/24/exec-relative/01-使用者原文.md#10-24-exec-直接放單子)、[ideas 10-21 § 8](../../../thinking/2026-10/21/ideas/05-7-審後的五個細縫與修正.md#8-aos-loop10-21-下午)）；子程式退 10 就停（P-06、P-19）。
- 一次一格的 fsm＝`aos-fsm fsm.json`（P-07）；設定檔是唯一的位置參數；格的 `exec` 收 aos-exec 的目標（每次 `aos-exec` 它；`fsm.json#/states/<名>/body` 也是目標），也可以直接放單子物件、行程內跑（[計畫 10-21](../../../thinking/2026-10/21/plan/README.md) F1、F2）。
- `exec` 用在：loop.json、daemon.json 與子項、daemon 寫進小格的 loop.json、fsm 的每一格（C-55）。
- agent 資料夾可以帶 loop 當入口（`aos-loop loop.json`，P-05、P-06；使用者 10-19，[ideas § 1](../../../thinking/2026-10/19/ideas/README.md)）。

例：kernel 的繼承式擺法＝`daemon.json` 的 `exec` 身體當判官、判完轉寄進自己的 ctl 信箱（範例擺法之一，C-47）；時鐘是根 `daemon.json` 裡一列普通 proc（見下「時鐘」）。

（無條號，從 [C-36](../../CONCEPTS/03-基礎設施/01-inst至fsm.md)、[C-55](../../CONCEPTS/01-設計理念/05-布局成長與檔案權限.md)、[C-50](../../CONCEPTS/05-agent/01-腦-工具-可預測性與agent函數binding.md)、[C-47](../../CONCEPTS/04-kernel/01-C-47.md) 搬來；規範旁：N-28、N-36。）

## 份額 `limits` 與沙箱 `aos-sandbox`

`limits` 的 key 與預設規範在 [N-28（Linux 管、份額、時鐘）](../04-基礎設施-loop與daemon/02-N-28/09-Linux管-份額-時鐘.md)；這裡只放概念搬來的句子。

- 份額＝daemon 表那列的 `limits`（`mem_mb`／`cpu_s`／`procs`／`file_mb`／`files`／`user`，同 aos-sandbox 的 key），daemon 在子行程裡 `setrlimit`／`setuid`、proc 不知道；daemon 自己被限＝起它的人包（rlimit 繼承）。`aos-daemon-ctl add --limits` 帶、aos-agent 照宣告送，llm kernel 另有包與寄件人額度（[aos-daemon docs/09](../../../cpp/aos-daemon/docs/09-份額.md)）。
- 遠期、沒排（C-64：以後一個 Linux 帳號一整棵樹，用帳號設權限）：跟 aos-sandbox 的 `s6-setuidgid`、上面 `limits` 的 `user` 同一條線。這次不做、不預留 key。
- 沙箱做成一支不常駐的 [`aos-sandbox 設定 prog...`](../../../py/aos/apps/sandbox/README.md)：排好這條鏈就 exec 走，結束碼與串流都是 prog 的。設定是白名單：沒列到的路徑看不到、`net` 預設 false、環境只帶一份預設清單、金鑰不帶。
- 能不能用 llm kernel＝看不看得到它的信箱（`rw` 綁 `$AOS_LLM_KERNEL/requests`），不另設開關；kernel 只跑自己 `kernel.json` 的 endpoint、金鑰在它那邊，沙箱裡的 agent 看不到。
- 管 agent 的工具（`subagent`、`agents_ctl`、`self_tools`）在沙箱裡照樣能用：設定裡 `rw` 綁 daemon（`$AOS_DAEMON`），程式不改。daemon 給 proc 的份額 `limits` 用同一套 key，是另一條路（daemon 在子行程裡設）。
- 函數在 `_metainfo` 宣告 `sandbox` 那一格見 [01 `_metainfo`](01-入口-metainfo-介面-血緣.md#_metainfo節點描述自己的抽屜)。

例：身分＝`s6-setuidgid` 換帳號（要 root、要先有帳號）；命名空間＝bwrap（免 root）；上限用 `s6-softlimit`。

（無條號，從 [C-64](../../CONCEPTS/01-設計理念/05-布局成長與檔案權限.md) 搬來；規範旁：N-28、[N-41](../07-基礎設施-組合子/02-N-38～N-41.md)、N-69。）
