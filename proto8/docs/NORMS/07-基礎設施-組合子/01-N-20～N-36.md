## tasks（seq／par／if）

## fsm

- **N-20**（定稿，[ideas 10-22 § 7](../../../thinking/2026-10/22/ideas/03-5-loop.md#7-fsm10-22)）巢狀 fsm 出口當掉後重跑時，各格的冪等性**不保證，不在規範範圍內**（照 N-18 的錯誤歸類：各格自己顧，出問題算使用者的事）。fsm 不記格跑到哪、不做重跑保護，上一次被殺一半就是下一次重跑同一格，見 N-38。
- **N-36**（定稿，[ideas 10-22 § 7](../../../thinking/2026-10/22/ideas/03-5-loop.md#7-fsm10-22)；[CONVENTION P-07](../../CONVENTION.md)）aos-fsm 只管一件事：**現在是 A 狀態，就跑 A 那格**；狀態內部、格內部的事 fsm 都不管（使用者意見 1，[意見 1～4](../../../thinking/2026-10/15/opinions-1-4.md)）。表：`{"start": 起始狀態名, "states": {狀態名: {"exec": 格, "next": 下一個狀態名}}}`（`exec`＝交給 aos-exec 跑的目標，照 C-55；key 名照使用者「fsm.json，現在是用val，幫我改成exec」，[thinking](../../../thinking/2026-10/23/naming.md)）。每格的 `exec` 收三種：
  - **字串＝aos-exec 的目標**（子資料夾、檔或 `檔#/指標`；`aos-exec -- 它`，相對路徑從 cwd 算，cwd＝agent 資料夾，N-59；直接叫 `aos-fsm` 時是叫它的地方，見本檔開頭⑦）。單子放在同一格的 `body`、寫 `"exec": "fsm.json#/states/<名>/body"` 也行（就是普通的 aos-exec 目標，由 aos-exec 行程內跑）。
  - **陣列 `[目標, 參數...]`**（每次 `aos-exec -- 目標 參數...`，元素都要是字串；比照 loop 的 `exec`，[ideas 10-21 § 9](../../../thinking/2026-10/21/ideas/05-7-審後的五個細縫與修正.md#9-設定檔是唯一的位置參數path-改字串拼接10-21-傍晚) H3）。
  - **單子物件**（使用者 10-24「不過exec本來就應該要可以直接放內嵌單子吧」「好，就這樣做」，[thinking 10-24](../../../thinking/2026-10/24/exec-relative/01-使用者原文.md#10-24-exec-直接放單子)）：loop／fsm／daemon 拿到物件時在自己行程內用 aos-exec 跑單子的同一套（`run_inst`、inst 的 C lib；`timeout_ms`、訊號、結束碼都一樣）跑，跑的期間 `AOS_CF`＝寫著它的設定檔、`AOS_CD`＝那份檔的資料夾（也是相對路徑的基準）、`AOS_CO`＝它在檔裡的位置（`/exec`、`/states/<名>/exec`）；單子壞＝那支程式自己的錯、退 1。
  命令列 `aos-fsm [FLAGS] fsm.json`：設定檔是唯一的位置參數，可寫 `檔#/指標`，目前沒有旗標（H1）；表裡不認得的 key 忽略（C-48），所以 fsm.json 可以帶 `"_entry": ["aos-fsm", {"$env": "AOS_CF"}]`，`aos-exec fsm.json` 就是一次（F6）。表一定明寫、`next` 只在表上，不靠慣例檔名；查不到那格＝錯（N-38）。**開跑時（讀表後、跑格前）查整張表**（使用者「b、c 開跑時查整張表」）：`start` 要在表上；每一格要是 `{"exec", "next"}`、`exec` 是 aos-exec 的目標（字串或非空字串陣列）或單子物件（單子裡面開跑時不查，跑那格時才驗，壞了＝fsm 自己的錯、退 1、state 不動）、`next` 是表上的狀態名、不能是空字串；哪一格不合都＝表壞、退 1、不跑格。`next` 頭尾也不能有空白、不能有換行（state 檔是純文字一行、讀回來會去頭尾空白，寫進去要讀得回同一個名字），連同別格的 `exec` 一起查（代定）。一次只跑一格：讀 `$AOS_STACK/stage.txt`（使用者題 10「fsm改名，嘗試用同義詞」，[four-elements 07](../../../thinking/2026-11/04/four-elements/07-實作步驟.md) 步 3；fsm.json 的 `start`／`states` 不改）（沒有檔＝從 `start` 起；純文字一行，N-13；讀的時候去頭尾空白，內容是空的也＝`start`；**檔在但讀不了**〔沒權限、是資料夾、不是 UTF-8…〕＝fsm 自己的錯、退 1、不跑格，使用者「a state 讀不了就退 1」；裡面的狀態不在表上＝查不到那格、退 1）、跑那格、**格的碼是 0 才**把 `next` 寫進 state（N-05 先寫暫存再改名）、然後以格的碼退出（收到訊號的例外見 N-38）。（使用者同意「喔喔，好」：格的路徑一律從 cwd 算）
  - **`next` 兩種寫法、照結束碼分岔**（使用者 10-30「fsm 的 next 可以按照結束碼分岔……依據不同結束碼導向不同分支」，選甲；看完衝突與方向題回「都照建議」；細節 fable 代定、可翻案，[thinking 10-30 aos-round](../../../thinking/2026-10/30/aos-round/02-A-N-36-分岔的格式.md#a-n-36-分岔的格式結論)）：每格的 `next` 收兩種——**字串**＝一個狀態名（格退 0 才把它寫進 state，其他碼 state 不動、fsm 以那個碼退出）；**物件** `{結束碼: 狀態名, …}`＝照格的結束碼查表：key 是十進位整數的字串（`"0"`～`"255"`，沒有正負號、空白、前導 0）或 `"*"`（其餘全部，含 128＋訊號），值是表上的狀態名（規則同字串 `next`）。格退 c：表上有 `"c"`（沒有 `"c"` 但有 `"*"` 也算）＝把那個狀態名寫進 state、**fsm 以 0 結束**（這一步照表走了，每層只說自己，N-43）；查不到＝state 不動、以 c 結束（透明轉交）。物件**至少要有 `"0"` 或 `"*"`**，開跑時查整張表（跟 `start`、`exec` 一起），少了＝表壞、退 1、不跑格——退 0 不准查不到，免得變成「成功但留在原地」。fsm 自己收到訊號的例外照 N-38：那格跑完照表寫 state（含分岔），再以 128＋N 結束。把錯誤碼或 `"*"` 寫進表、導回同一格或善後格，fsm 不擋、不數（無窮轉移只有 loop 的 `max` 擋，本檔開頭⑥）、風險自擔。現役範本 `templates/agent-fsm/fsm.json` 的 idle、think、wait、act 四格都用物件 `next`。
