- **N-38**（10-15 定；10-22 定稿，[ideas 10-22 § 7](../../../thinking/2026-10/22/ideas/03-5-loop.md#7-fsm10-22)；[CONVENTION P-20、P-21](../../CONVENTION.md)）fsm 出錯：那格結束碼非 0（含被訊號殺、逾時）、查不到那格、表壞（含 `exec` 不合；開跑時查整張表、哪一格壞都算，見 N-36）、state 檔在但讀不了（見 N-36）＝錯；格指到的單子壞是 aos-exec 的錯（它退 1、自己說），對 fsm 來說就是那格非 0。出錯時 **state 不動**（下一次重跑同一格）、fsm 以那格的碼退出（fsm 自己的錯退 1，stderr 一行 `aos-fsm: 原因`，N-43；自己的錯一律不跑格）；**格的 stderr fsm 不讀、不轉**（C-52 切乾淨：格的錯是格自己的；想看子層靠自己寫的檔，沒機制就不碰；10-15 深夜使用者「不能接受，拜託切乾淨」）；之後怎麼辦交給外層（跑它的 loop）或人。不特別的 `error` 格：想優雅處理的格自己接錯、改寫狀態；連錯幾次要停住，也是格自己數——**agent 的格不數**（10-16，[N-53](../10-基礎設施-定義與工作區/06-N-50～N-53.md)：重試幾次看外面 loop，agent 自己不數）。上一次被殺一半（格跑了、state 沒寫）＝下一次重跑同一格，半成品由格自己看自己的檔判斷；重跑的冪等性不保證（N-20）。次數上限由跑它的 loop 的 `max` 管。**例外（10-19 晚，[ideas § 24](../../../thinking/2026-10/19/ideas/README.md)）**：fsm 自己收到 SIGINT／SIGTERM／SIGHUP 時，先轉給那格、等格跑完，state 照常寫（格退 0 照樣換狀態），再以 128＋N 結束、不以格的碼結束；跑格之前就收到＝不跑、直接 128＋N（CONVENTION P-36）。（[意見 1～4](../../../thinking/2026-10/15/opinions-1-4.md) Q1、Q4；格出錯 fsm 退非 0，使用者 10-15 收工後定）
- **N-39**（10-15 定；10-22 定稿，[ideas 10-22 § 7](../../../thinking/2026-10/22/ideas/03-5-loop.md#7-fsm10-22)；[CONVENTION P-07、P-37、P-38](../../CONVENTION.md)）fsm 的 state 檔在 `$AOS_STACK/state.txt`，只記現在狀態名（純文字一行），只有 fsm 自己寫（N-09）。fsm 不開 ctl、lock：暫停、停止、同時兩隻跑同一份，交給跑它的 loop（共用同一個 stack 會撞暫存檔，使用者自行承擔，見本檔開頭②）。心跳：fsm 是單次程式、壽命一次，不適用 N-17／N-32 的每秒心跳。**fsm 不寫 `$AOS_STACK/trace.jsonl`，每次只動 `state.txt`〔11-04 加註：fsm 的這個檔改名 `stage.txt`（使用者題 10「fsm改名，嘗試用同義詞」，[four-elements 07](../../../thinking/2026-11/04/four-elements/07-實作步驟.md) 步 3；fsm.json 的 `start`／`states` 不改）〕**（使用者 11-03「trace.jsonl會無限累加...老實說我覺得這個檔案沒啥必要。」「整個拿掉。」，[thinking 11-03 trace](../../../thinking/2026-11/03/trace.md)；頂層代定、可翻案）：aos-eca-turn 也不寫 trace，讀它的 `aos-listen --status`／`--trace` 也沒有；要看跑到哪看 `state.txt`，要時間軸由外層（例如 loop 的 log `--enable-logs`）或使用者自己包。state 寫不了是 `WriteFailed` 一行、退 1，見本檔開頭③。表裡的格指回自己（遞迴、同一份同時被跑兩次）fsm 不擋，卡死不防護（10-15 收工後使用者「好」；P-37）。（[意見 1～4](../../../thinking/2026-10/15/opinions-1-4.md)）
- **N-41**（10-15 定；10-22 定稿，[ideas 10-22 § 7](../../../thinking/2026-10/22/ideas/03-5-loop.md#7-fsm10-22)；[CONVENTION P-09、P-22、P-36](../../CONVENTION.md)）一格怎麼跑是那格的事，規範中立：例如 think 格可以起來就等 LLM 回覆、處理完才結束（同步），也可以把請求寫進某個地方就結束，下一次再看回覆到了沒（非同步），兩種都合規，換一格即可；最小實作先做同步版。格自己不 setsid／fork 背景行程——格是單子時，由跑單子的那方（`fsm.json#/states/<名>/body` 這種目標＝aos-exec 行程內跑；`exec` 是單子物件＝fsm 自己行程內 `run_inst`，N-36）給格一個新的行程群組（inst 的 C lib `new_session`）、逾時打整群、把 fsm 轉來的訊號轉給整群（P-36、N-59 第 5 件），格自己不另起。格裡放 loop 不禁止也不鼓勵，會阻塞一次，靠那一格單子的 `timeout_ms` 守。（10-15）格不是單子（`exec` 指到可執行檔或 argv 陣列檔），或是單子但沒寫 `timeout_ms` 時，沒有時間上限，見本檔開頭①。
