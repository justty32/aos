# 基礎設施／組合子（tasks、fsm）

使用者 10-15：tasks 組合子歸基礎設施，「**地位等同於 C 語言的 stdlib**」；同日又定「把 fsm 也跟 tasks 放一起」——fsm 同為 stdlib 地位。[agent](../CONCEPTS/05-agent.md) 是用 fsm 組出來的（一個資料夾程式＝入口＋表＋各格，C-50），agent 主題連過來。

> **分層**（[C-74](../CONCEPTS/01-設計理念/02-C-51.md#分層10-22-使用者定)）：fsm、tasks 屬**標準庫**，建在基礎層（核心 aos-exec＋loop、daemon）之上；本檔主題名「基礎設施」是照內容分的，不是層。

> **fsm 不管、使用者自行承擔的事**（10-22 使用者「其餘算使用者自己承擔，條文定稿」，[ideas 10-22 § 7](../../thinking/2026-10/22/ideas/03-5-loop.md#7-fsm10-22)）：① 每格**沒有時間上限**：格最後 exec 成可執行檔或 argv 陣列時，不理 SIGTERM 就一直等（格是 inst 單子且寫了 `timeout_ms` 時，由 aos-exec 到時 SIGTERM、過 `grace_ms` 補 SIGKILL；沒寫 `timeout_ms` 一樣不限）——要上限自己加，例如在 `exec` 指的單子或 argv 檔裡 argv 前面接 `timeout -k 5 60`（不加 `-k` 遇到不理 SIGTERM 的照樣等），或用單子的 `timeout_ms`；`exec` 陣列的第一個是 aos-exec 的目標，不能直接寫 `timeout`。② 兩隻 fsm **共用同一個 stack**（同一份 `stage.txt`，本來就違反 N-09「一個 state 檔只有被控制的那個東西自己寫」）：寫的時間撞上時搶同一個暫存檔 `.stage.txt`、後到的當掉，沒撞上也會互相蓋掉狀態——自己避免，或在外面接 s6-setlock 之類的鎖（N-39：同時兩隻跑同一份交給跑它的 loop）。③ **state 寫不了**（stack 資料夾不見、沒權限…）時，格已經跑完，fsm stderr 一行 `aos-fsm: error: WriteFailed cannot write <檔>: <原因>`（N-43）、結束碼 1（這次收到了訊號也不以 128＋N 結束），跟其他自己的錯一樣（P-21；10-23 使用者：照 C++ 版）。state 沒換，下一次照舊跑同一格（stack 資料夾不見時讀不到 state，從 `start` 起），重跑的冪等性不保證（N-20）。④（空號。）⑤ 跑它的 loop 或 fsm 自己被 **SIGKILL**（轉不了訊號）時，正在跑的格變孤兒、繼續跑到完；這時重開，新的一次可能跟還沒跑完的舊格重疊（同一格跑兩份、搶同一份 state）——自己避免，例如重開前先確認舊格結束。⑥ **無窮轉移**（格一直退 0、狀態轉個不停）只有跑它的 loop 的 `max` 擋，fsm 自己不數（N-38）。⑦ `exec` 的**相對路徑從 cwd 算**（fsm 不轉，F2）：經 `aos-exec fsm.json` 跑時 cwd 是 fsm.json 所在的資料夾；直接叫 `aos-fsm` 時是從哪裡叫就從哪裡算。⑧ **`.env` 外層贏**：aos-exec 預設不蓋已有的環境變數（N-59 第 4 件），所以格的資料夾的 `.env` 跟外層同名時，格看到的是外層的值；`exec` 陣列是 `aos-exec -- 目標 參數...`，寫成 `["--dotenv-override", "act"]` 會把旗標當成目標、傳不了——要蓋就把那格寫成 body 單子，例 `{"exec": "fsm.json#/states/act/body", "body": {"argv": ["aos-exec", "--dotenv-override", "act"]}, "next": "idle"}`。
