# 基礎設施／組合子（tasks、fsm）

使用者 10-15：tasks 組合子歸基礎設施，「**地位等同於 C 語言的 stdlib**」；同日又定「把 fsm 也跟 tasks 放一起」——fsm 同為 stdlib 地位。[agent](../CONCEPTS/05-agent.md) 是用 fsm 組出來的（一個資料夾程式＝入口＋表＋各格，C-50），agent 主題連過來。

> **分層**（10-22，[C-74](../CONCEPTS/01-設計理念.md#分層10-22-使用者定)）：fsm、tasks 屬**標準庫**，建在基礎層（核心 aos-exec＋loop、daemon）之上；本檔主題名「基礎設施」是照內容分的，不是層。

> **fsm 不管、使用者自行承擔的事**（10-22 使用者「其餘算使用者自己承擔，條文定稿」，[ideas 10-22 § 7](../../thinking/2026-10-22-ideas.md#7-fsm10-22)）：① 每格**沒有時間上限**：格最後 exec 成可執行檔或 argv 陣列時，不理 SIGTERM 就一直等（格是 inst 單子且寫了 `timeout_ms` 時，由 aos-exec 到時 SIGTERM、過 `grace_ms` 補 SIGKILL；沒寫 `timeout_ms` 一樣不限）——要上限自己加，例如在 `exec` 指的單子或 argv 檔裡 argv 前面接 `timeout -k 5 60`（不加 `-k` 遇到不理 SIGTERM 的照樣等），或用單子的 `timeout_ms`；`exec` 陣列的第一個是 aos-exec 的目標，不能直接寫 `timeout`。② 兩隻 fsm **共用同一個 stack**（同一份 `state.txt`，本來就違反 N-09「一個 state 檔只有被控制的那個東西自己寫」）：寫的時間撞上時搶同一個暫存檔 `.state.txt`、後到的當掉，沒撞上也會互相蓋掉狀態、`trace.jsonl` 兩邊交錯——自己避免，或在外面接 s6-setlock 之類的鎖（N-39：同時兩隻跑同一份交給跑它的 loop）。③ **state／trace 寫不了**（stack 資料夾不見、沒權限…）時，格已經跑完，fsm stderr 一行 `aos-fsm: WriteFailed 寫不了 <檔>：<原因>`、結束碼 1（這次收到了訊號也不以 128＋N 結束），跟其他自己的錯一樣（P-21；10-23 使用者：照 C++ 版）。先寫 trace 再寫 state：trace 寫不了就不寫 state；trace 寫得了、state 寫不了（例如 `trace.jsonl` 早就在、可寫，只是資料夾不能新建暫存檔 `.state.txt`）時，trace 多一行、state 沒換。state 沒換，下一次照舊跑同一格（stack 資料夾不見時讀不到 state，從 `start` 起），重跑的冪等性不保證（N-20）。④ `trace.jsonl` **不設上限**、每次附加一行，要控制大小自己處理（fsm 每次重新以附加模式打開，外面用 logrotate 之類搬走或截斷都接得上）。⑤ 跑它的 loop 或 fsm 自己被 **SIGKILL**（轉不了訊號）時，正在跑的格變孤兒、繼續跑到完；這時重開，新的一次可能跟還沒跑完的舊格重疊（同一格跑兩份、搶同一份 state）——自己避免，例如重開前先確認舊格結束。⑥ **無窮轉移**（格一直退 0、狀態轉個不停）只有跑它的 loop 的 `max` 擋，fsm 自己不數（N-38）。⑦ `exec` 的**相對路徑從 cwd 算**（fsm 不轉，F2）：經 `aos-exec fsm.json` 跑時 cwd 是 fsm.json 所在的資料夾；直接叫 `aos-fsm` 時是從哪裡叫就從哪裡算。⑧ **`.env` 外層贏**：aos-exec 預設不蓋已有的環境變數（N-59 第 4 件），所以格的資料夾的 `.env` 跟外層同名時，格看到的是外層的值；`exec` 陣列是 `aos-exec -- 目標 參數...`，寫成 `["--dotenv-override", "act"]` 會把旗標當成目標、傳不了——要蓋就把那格寫成 body 單子，例 `{"exec": "fsm.json#/states/act/body", "body": {"argv": ["aos-exec", "--dotenv-override", "act"]}, "next": "idle"}`。

## tasks（seq／par／if）

- **N-34**（原 h16，草稿）tasks（`seq`／`par`／`if`）**現無實作**，待重寫成資料夾程式。規範：起子程式後**看它的結束碼**決定往哪走（10-19 起結束碼是正式訊號）；自己的錯退 1、stderr 一行原因；seq／par／if 回子程式的碼是透明轉交（N-43 例外）。沒有 `aos-not`：要反過來寫 `aos if X 失敗格 成功格`（[KISS 彙整](../../thinking/2026-10-15-kiss/README.md) 1.17）。（10-14 深夜）

## fsm

- **N-20**（10-14 夜定；10-22 定稿，[ideas 10-22 § 7](../../thinking/2026-10-22-ideas.md#7-fsm10-22)）巢狀 fsm 出口當掉後重跑時，各格的冪等性**不保證，不在規範範圍內**（照 N-18 的錯誤歸類：各格自己顧，出問題算使用者的事）。fsm 不記格跑到哪、不做重跑保護，上一次被殺一半就是下一次重跑同一格，見 N-38。（10-14）
- **N-36**（10-15 定；10-22 定稿，[ideas 10-22 § 7](../../thinking/2026-10-22-ideas.md#7-fsm10-22)；[CONVENTION P-07](../CONVENTION.md)）aos-fsm 只管一件事：**現在是 A 狀態，就跑 A 那格**；狀態內部、格內部的事 fsm 都不管（10-15 收工後使用者意見 1，[意見 1～4](../../thinking/2026-10-15-opinions-1-4.md)）。表：`{"start": 起始狀態名, "states": {狀態名: {"exec": 格, "next": 下一個狀態名}}}`（`exec`＝交給 aos-exec 跑的目標，照 C-55；key 名照使用者「fsm.json，現在是用val，幫我改成exec」，[thinking](../../thinking/2026-10-23-naming.md)）。每格的 `exec` 收三種：
  - **字串＝aos-exec 的目標**（子資料夾、檔或 `檔#/指標`；`aos-exec -- 它`，相對路徑從 cwd 算，cwd＝agent 資料夾，N-59；直接叫 `aos-fsm` 時是叫它的地方，見本檔開頭⑦）。單子放在同一格的 `body`、寫 `"exec": "fsm.json#/states/<名>/body"` 也行（就是普通的 aos-exec 目標，由 aos-exec 行程內跑）。
  - **陣列 `[目標, 參數...]`**（每次 `aos-exec -- 目標 參數...`，元素都要是字串；比照 loop 的 `exec`，[ideas 10-21 § 9](../../thinking/2026-10-21-ideas.md#9-設定檔是唯一的位置參數path-改字串拼接10-21-傍晚) H3）。
  - **單子物件**（使用者 10-24「不過exec本來就應該要可以直接放內嵌單子吧」「好，就這樣做」，[thinking 10-24](../../thinking/2026-10-24-exec-relative.md#10-24-exec-直接放單子)）：loop／fsm／daemon 拿到物件時在自己行程內用 aos-exec 跑單子的同一套（`run_inst`、inst 的 C lib；`timeout_ms`、訊號、結束碼都一樣）跑，跑的期間 `AOS_CF`＝寫著它的設定檔、`AOS_CD`＝那份檔的資料夾（也是相對路徑的基準）、`AOS_CO`＝它在檔裡的位置（`/exec`、`/states/<名>/exec`）；單子壞＝那支程式自己的錯、退 1。
  命令列 `aos-fsm [旗標] fsm.json`：設定檔是唯一的位置參數，可寫 `檔#/指標`，目前沒有旗標（H1）；表裡不認得的 key 忽略（C-48），所以 fsm.json 可以帶 `"_entry": ["aos-fsm", {"$env": "AOS_CF"}]`，`aos-exec fsm.json` 就是一次（F6）。表一定明寫、`next` 只在表上，不靠慣例檔名；查不到那格＝錯（N-38）。**開跑時（讀表後、跑格前）查整張表**（10-22 使用者「b、c 開跑時查整張表」）：`start` 要在表上；每一格要是 `{"exec", "next"}`、`exec` 是 aos-exec 的目標（字串或非空字串陣列）或單子物件（單子裡面開跑時不查，跑那格時才驗，壞了＝fsm 自己的錯、退 1、不寫 trace、state 不動）、`next` 是表上的狀態名、不能是空字串；哪一格不合都＝表壞、退 1、不跑格。`next` 頭尾也不能有空白、不能有換行（state 檔是純文字一行、讀回來會去頭尾空白，寫進去要讀得回同一個名字），連同別格的 `exec` 一起查（10-22 實作時代定）。一次只跑一格：讀 `$AOS_STACK/state.txt`（沒有檔＝從 `start` 起；純文字一行，N-13；讀的時候去頭尾空白，內容是空的也＝`start`；**檔在但讀不了**〔沒權限、是資料夾、不是 UTF-8…〕＝fsm 自己的錯、退 1、不跑格，10-22 使用者「a state 讀不了就退 1」；裡面的狀態不在表上＝查不到那格、退 1）、跑那格、**格的碼是 0 才**把 `next` 寫進 state（N-05 先寫暫存再改名）、然後以格的碼退出（收到訊號的例外見 N-38）。（10-15；10-16 使用者同意「喔喔，好」：格的路徑一律從 cwd 算）
  - **10-30 改口：`next` 兩種寫法、照結束碼分岔**（使用者 10-30「fsm 的 next 可以按照結束碼分岔……依據不同結束碼導向不同分支」，選甲；看完衝突與方向題回「都照建議」；細節 fable 代定、可翻案，[thinking 10-30 aos-round](../../thinking/2026-10-30-aos-round.md#a-n-36-分岔的格式結論)）：每格的 `next` 收兩種——**字串**＝一個狀態名，意思照舊（格退 0 才把它寫進 state，其他碼 state 不動、fsm 以那個碼退出）；**物件** `{結束碼: 狀態名, …}`＝照格的結束碼查表：key 是十進位整數的字串（`"0"`～`"255"`，沒有正負號、空白、前導 0）或 `"*"`（其餘全部，含 128＋訊號），值是表上的狀態名（規則同字串 `next`）。格退 c：表上有 `"c"`（沒有 `"c"` 但有 `"*"` 也算）＝把那個狀態名寫進 state、**fsm 以 0 結束**（這一步照表走了，每層只說自己，N-43）；查不到＝state 不動、以 c 結束（透明轉交，照舊）。物件**至少要有 `"0"` 或 `"*"`**，開跑時查整張表（跟 `start`、`exec` 一起），少了＝表壞、退 1、不跑格——退 0 不准查不到，免得變成「成功但留在原地」。fsm 自己收到訊號的例外照 N-38：那格跑完照表寫 state（含分岔），再以 128＋N 結束。把錯誤碼或 `"*"` 寫進表、導回同一格或善後格，fsm 不擋、不數（無窮轉移只有 loop 的 `max` 擋，本檔開頭⑥）、風險自擔；範本 `lib/agent/round/` 的表只接 0 與 10（aos-round）。
- **N-38**（10-15 定；10-22 定稿，[ideas 10-22 § 7](../../thinking/2026-10-22-ideas.md#7-fsm10-22)；[CONVENTION P-20、P-21](../CONVENTION.md)）fsm 出錯：那格結束碼非 0（含被訊號殺、逾時）、查不到那格、表壞（含 `exec` 不合；開跑時查整張表、哪一格壞都算，見 N-36）、state 檔在但讀不了（見 N-36）＝錯；格指到的單子壞是 aos-exec 的錯（它退 1、自己說），對 fsm 來說就是那格非 0。出錯時 **state 不動**（下一次重跑同一格）、fsm 以那格的碼退出（fsm 自己的錯退 1，stderr 一行 `aos-fsm: 原因`，N-43；自己的錯一律不跑格、不記 trace）；**格的 stderr fsm 不讀、不轉**（C-52 切乾淨：格的錯是格自己的；想看子層靠自己寫的檔，沒機制就不碰；10-15 深夜使用者「不能接受，拜託切乾淨」）；之後怎麼辦交給外層（跑它的 loop）或人。不特別的 `error` 格：想優雅處理的格自己接錯、改寫狀態；連錯幾次要停住，也是格自己數——**agent 的格不數**（10-16，[N-53](10-基礎設施-定義與工作區.md)：重試幾次看外面 loop，agent 自己不數）。上一次被殺一半（格跑了、state 沒寫）＝下一次重跑同一格，半成品由格自己看自己的檔判斷；重跑的冪等性不保證（N-20）。次數上限由跑它的 loop 的 `max` 管。**例外（10-19 晚，[ideas § 24](../../thinking/2026-10-19-ideas.md)）**：fsm 自己收到 SIGINT／SIGTERM／SIGHUP 時，先轉給那格、等格跑完，trace 與 state 照常寫（格退 0 照樣換狀態），再以 128＋N 結束、不以格的碼結束；跑格之前就收到＝不跑、直接 128＋N（CONVENTION P-36）。（[意見 1～4](../../thinking/2026-10-15-opinions-1-4.md) Q1、Q4；格出錯 fsm 退非 0，使用者 10-15 收工後定）
- **N-39**（10-15 定；10-22 定稿，[ideas 10-22 § 7](../../thinking/2026-10-22-ideas.md#7-fsm10-22)；[CONVENTION P-07、P-37、P-38](../CONVENTION.md)）fsm 的 state 檔在 `$AOS_STACK/state.txt`，只記現在狀態名（純文字一行），只有 fsm 自己寫（N-09）。fsm 不開 ctl、lock：暫停、停止、同時兩隻跑同一份，交給跑它的 loop（共用同一個 stack 會撞暫存檔，使用者自行承擔，見本檔開頭②）。心跳：fsm 是單次程式、壽命一次，不適用 N-17／N-32 的每秒心跳。**每次在 `$AOS_STACK/trace.jsonl` 追加一行** `{"at","state","code","signal","elapsed_ms"}`（`at`＝這次開始的 UTC 時間，ISO 8601 到毫秒；每次都記時間，10-19 定，P-38）。trace 沒有 `timed_out`（[計畫 10-21](../../thinking/2026-10-21-plan.md) F4）：fsm 看不到格裡有沒有逾時（C-52），被逾時收掉的格看 `code`（128＋15）就知道。被逾時收掉的單子格 `signal` 是 null——格是 aos-exec 子行程，它收掉單子後以子程式的碼正常結束；`signal` 只在那次的那個行程（aos-exec，或它 exec 成的程式）本身被訊號殺掉時有值，例如 exec 成的 shell 腳本被轉來的 SIGTERM 殺掉、外面 SIGKILL 它。每次先寫 trace、再寫 state；trace 不設上限、state／trace 寫不了是 `WriteFailed` 一行、退 1，見本檔開頭③④。表裡的格指回自己（遞迴、同一份同時被跑兩次）fsm 不擋，卡死不防護（10-15 收工後使用者「好」；P-37）。（[意見 1～4](../../thinking/2026-10-15-opinions-1-4.md)）
  - **10-30 加註：trace 加 `next`**（頂層代定、可翻案，[thinking 10-30 aos-round](../../thinking/2026-10-30-aos-round.md#a-n-36-分岔的格式結論) 第 6 點、決定 5）：trace 每行多一個 `next`＝這次寫進 state 的狀態名、沒換狀態＝`null`；字串 `next` 的格也記（退 0 是名字、其他是 null）。欄位序 `{"started_at","state","code","signal","elapsed_ms","next"}`（`at` 10-23 起改名 `started_at`，C-54 R6）。P-38 看樹就看 trace；有分岔後光看 `code` 推不出走到哪。
- **N-41**（10-15 定；10-22 定稿，[ideas 10-22 § 7](../../thinking/2026-10-22-ideas.md#7-fsm10-22)；[CONVENTION P-09、P-22、P-36](../CONVENTION.md)）一格怎麼跑是那格的事，規範中立：例如 think 格可以起來就等 LLM 回覆、處理完才結束（同步），也可以把請求寫進某個地方就結束，下一次再看回覆到了沒（非同步），兩種都合規，換一格即可；最小實作先做同步版。格自己不 setsid／fork 背景行程——格是單子時，由跑單子的那方（`fsm.json#/states/<名>/body` 這種目標＝aos-exec 行程內跑；`exec` 是單子物件＝fsm 自己行程內 `run_inst`，N-36）給格一個新的行程群組（inst 的 C lib `new_session`）、逾時打整群、把 fsm 轉來的訊號轉給整群（P-36、N-59 第 5 件），格自己不另起。格裡放 loop 不禁止也不鼓勵，會阻塞一次，靠那一格單子的 `timeout_ms` 守。（10-15）格不是單子（`exec` 指到可執行檔或 argv 陣列檔），或是單子但沒寫 `timeout_ms` 時，沒有時間上限，見本檔開頭①。
