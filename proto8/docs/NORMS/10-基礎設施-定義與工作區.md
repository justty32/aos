# 基礎設施／資料夾程式與執行

（檔名沿用「定義與工作區」。）用詞（C-54）：**資料夾程式**（定義）＝一個資料夾；**入口**＝`$AOS_ENTRY` 指的檔（可執行檔，或 aos-exec 完整實作（N-18）跑得動的檔——inst 單子、argv 陣列、`js[$AOS_ENTRY]`，C-73；[ideas § 14](../../thinking/2026-10-19-ideas.md)）；**stack**＝被叫的程式自己的 `$AOS_STACK`（執行中狀態）；**小格**＝叫別的資料夾程式時給它的 stack；**工作區**＝使用者的檔與成品所在的資料夾（`ws`，C-65）。見[名詞表](../CONCEPTS/附錄1-名詞.md)。

N-57～N-62 是 aos 保證的底，使用者 10-19 的原話在 [ideas § 1～§ 5、§ 14～§ 21](../../thinking/2026-10-19-ideas.md)（N-57～N-60 對應 [CONVENTION](../CONVENTION.md) P-01～P-04）。N-50、N-53、N-55 是 10-16 定的。其餘全是慣例（P-05～P-40，在 CONVENTION），不是大家都要守的。都是**草稿**。

> **實作**：這些條文講的是「aos-exec 這個角色」，不分實作。現在的實作是 `proto8/impls`（C++，使用者寫的參考實作；使用者 10-23「python版本可以刪掉了。aos-exec/loop/daemon都用C++」，fsm 也改 C++、tick 先留 Python）：命令列有 `aos-exec`、`aos-loop`、`aos-fsm`、`aos-daemon` 四支；inst 是 C lib、不提供 `aos-inst` 命令列（§ 20；使用者 10-22「對於python版，aos-inst指令可以刪掉了，跟C++版一樣做成lib就好。」，[ideas 10-22](../../thinking/2026-10-22-ideas.md)），單子由 aos-exec 在行程內交給 C lib 跑；錯誤一行是 `aos-exec: 代號 原因`（10-22 使用者「錯誤訊息多代號也遵循」）；loop／daemon 的 `exec`、fsm 格的 `exec` 見 N-11、N-36（key 名：使用者「fsm.json，現在是用val，幫我改成exec」「exec，loop／daemon 的 run 也一起改 exec」，[thinking](../../thinking/2026-10-23-naming.md)）。實作上要知道的：impls 沒有 `aos-tick`（`proto8/bin` 的 Python 版；10-22 使用者定 C++ 先不補）；impls 的 loop／fsm 每次、daemon 起子 loop 不叫 PATH 上的 aos-exec，而是 fork 後在子行程裡呼叫 aos-exec 的公開 API `run_cli`（效果等同；argv 陣列裡插進去的 aos-exec、daemon 要的 aos-loop 照樣照 PATH 找）——**使用者 10-22 接受**（「Python 版照舊去 PATH 找 aos-exec 就好，只是 C++ 版這樣做我接受」，理由「因為以後可能會變成一個aos指令，後面接子指令。比如aos exec, aos loop這樣」）；可執行檔入口拿到的 `argv[0]` 是 `./檔名`；讀設定檔會跳過第一行 `#!`、`.env` 去前導空白只認 ASCII 空白（使用者「C++版比較寬鬆這塊，希望python也遵循」）；`.env` 格式與 `--dotenv-override` 見 [ideas 10-22 § 3](../../thinking/2026-10-22-ideas/02-3-env-基礎子集與---dotenv-ove.md#3-env-基礎子集與---dotenv-override10-22)、N-58、N-59 第 4 件、N-60。

- **N-57**（10-19 定，草稿；[ideas § 14、§ 19](../../thinking/2026-10-19-ideas.md)）**aos 只訂環境變數，現在六個**（使用者 10-19 下班前：「然後我想要再加上兩個環境變數：AOS_CF, AOS_CD，也就是current file，current dir。」→ 定義由 fable 擬、使用者「同意做」；10-21 晚使用者「AOS_CF不動。但是我們再加上AOS_CO」「aos current obj」，[ideas 10-21 § 6](../../thinking/2026-10-21-ideas/04-6-JSON-物件當資料夾-一路往下-AOS_C.md#6-json-物件當資料夾一路往下aos_co10-21-晚)）：
  - `AOS_ENTRY`＝入口在資料夾裡的相對位置，預設 `_entry`（使用者 10-19 晚「然後其實我有點想要把AOS_ENTRY的默認值換成_exec。也就是js["_exec"]。」「換。AOS_ENTRY 預設改成 _exec，工作區的 .aos/ stack 照舊；派人改程式、demo、測試和文件。」；不帶 `.json`：「啊shit，那還是不要用_exec.json好了。還是_exec就夠了。」；原話裡的 `_exec`、`.aos/` 現在叫 `_entry`、`.stack/`，[thinking](../../thinking/2026-10-23-naming.md)）——入口只佔資料夾一層，跟 table 的一個 key 對上（C-71、C-72）；工作區的 `.stack/` 是 stack 的預設位置，跟入口無關；[ideas § 13](../../thinking/2026-10-19-ideas.md)。入口有四種：可執行檔（含 shebang 檔）、inst 單子、argv 陣列、`js[$AOS_ENTRY]` 的值（單子、陣列、或字串路徑，§ 17）——定義在 C-73，找法在 N-61。同一個名字資料夾裡與 JSON 裡都用（`agent-bob/_entry` ⇄ `js["_entry"]`）。
  - `AOS_WS`＝工作區（使用者的檔與成品在哪，N-55）。
  - `AOS_STACK`＝被叫的程式自己執行中狀態放哪，預設 `$AOS_WS/.stack/`（跟 `AOS_STACK` 同字；使用者 10-23 選），**它的子程式的 stack 由它自己訂**，aos 不管巢狀（C-70）。
  - `AOS_CF`（current file）＝**實際被執行的那個檔**的絕對路徑（解開捷徑；不帶 `#/…`；字串轉向後＝最後那個檔）。
  - `AOS_CD`（current dir）＝**`AOS_CF` 所在的資料夾**＝aos-exec cd 進去的地方。
  - `AOS_CO`（current obj）＝**實際入口在那份 JSON 檔裡的位置**，JSON 指標、不帶 `#`（例 `/dev/sub`）：最後跑到的那格；`檔#/指標` 也算在內（`x.json#/a` 再挑 `_entry`＝`/a/_entry`）；key 照 JSON 指標跳脫（`~0`、`~1`）；整份檔就是入口、或入口不是 JSON（可執行檔）＝空字串。往下走進 JSON 物件時 `AOS_CF`、`AOS_CD` 不變，只有 `AOS_CO` 跟著變（定義是頂層擬、使用者確認「aos current obj」）。
  `AOS_CF`／`AOS_CD`／`AOS_CO` 都由 aos-exec **每次呼叫覆寫**，每層看到的是自己的。loop／fsm／daemon 的 `exec` 是內嵌單子（物件）時，它們在自己行程內跑單子，跑的那段把這三個設成單子的位置（`AOS_CF`＝寫著它的設定檔、解開捷徑，`AOS_CD`＝它的資料夾，`AOS_CO`＝`/exec` 或 `/states/<名>/exec`，設定檔寫 `檔#/指標` 時接在指標後面），跑完還原成原本的；值就是 aos-exec 跑 `loop.json#/exec` 時會設的那三個（使用者 10-24「不過exec本來就應該要可以直接放內嵌單子吧」，頂層照本條推的代定，[exec-relative § 10-24 exec 直接放單子](../../thinking/2026-10-24-exec-relative/01-使用者原文.md#10-24-exec-直接放單子)、[審後修正](../../thinking/2026-10-24-exec-relative/01-使用者原文.md#10-24-審後修正)）。`AOS_CD` 裡的 `.env` 可以再改這幾個的任何一個，不限制、風險自擔（N-59 第 4 件；使用者「2.可以，全都可以，不限制，風險自己擔。」）——這幾個在讀 `.env` 前已設好，要那一跳加 `--dotenv-override` 才改得了（N-58）；`.env` 設的 `AOS_ENTRY` 對這一層挑入口就有作用（讀完 `.env` 才挑入口檔，N-59 第 4 件、[ideas 10-21 § 5](../../thinking/2026-10-21-ideas/03-5-標準實作與-AOS_ENTRY-的順序.md#5-標準實作與-aos_entry-的順序10-21-晚)）。用處是程式 cd 走之後還能找回自己的東西（例 `cd "$AOS_WS" && … && aos-exec "$AOS_CD/tools/stamp"`）。三類分法（繼承／每層覆寫／叫別人時明給）在 CONVENTION P-39。（使用者 10-19：「純粹把資料夾作為lisp的list或lua的table，然後有一個entry……環境變數定義：AOS_ENTRY=.aos/inst，這個定義的目標必須是可執行檔。就這樣，非常簡單。」「首先，.aos/inst幫我改成.aos/exec，然後執行狀態這塊由agent-bob自己訂……所以我們再設定一個AOS_STACK=ws/.aos/。」「那就AOS_WS。」；[ideas § 1～§ 3](../../thinking/2026-10-19-ideas.md)；CONVENTION P-01）

  - **argv[0] 怎麼跑**（10-20 使用者，見 [ideas](../../thinking/2026-10-20-ideas.md) D3～D5）：適用所有跑 argv 的地方——入口的 argv 陣列、單子的 `argv`（aos-exec 跑的、loop／fsm 內嵌的）。**沒 `/` 一律照 PATH 找**（D4：「就是要有/才算路徑」）。**有 `/`**：是 `+x` 的一般檔就照舊直接 exec（不 cd、不設 `AOS_CF`，現有寫法行為不變）；**exec 不了的——資料夾、沒 `+x` 的檔、不在、或帶 `#/`——等同在前面插 `aos-exec`**，由 inst 叫 PATH 上的 `aos-exec`（D3：「分層衝突沒關係，就是要inst依賴PATH中的aos-exec」）；相對路徑照子程式的 cwd 算。D5：`["tools/stamp", "a"]`＝`["aos-exec", "tools/stamp", "a"]`；第二個元素起都是 args（工作區由 `--ws` 給，N-58）。PATH 上沒有 `aos-exec`＝起不來（單子：程式找不到）。工具的小格（stack）、算不算暗規則，使用者沒回，照通則不追問（D6，ideas § 2 的 (4)、(5)）：插進去的 `aos-exec` 沿用現有的 `AOS_WS`／`AOS_STACK`，跟手寫 `aos-exec` 一樣。
- **N-62**（10-19 下班前定，草稿，[ideas § 19](../../thinking/2026-10-19-ideas.md)）**路徑支援 JSON 尋址 `檔#/指標`**：`cfg.json#/tools/stamp`＝cfg.json 裡 `/tools/stamp` 那個值，寫法是 JSON pointer（RFC 6901：`#/` 開頭、一層一個 `/`，`~0`＝`~`、`~1`＝`/`），指到的值照 N-61 的種類判斷（單子、argv 陣列、字串轉向、或沒 `argv` 的物件再取 `js[$AOS_ENTRY]`）。**第一個 `#` 就切、不支援檔名含 `#`**（照舊 N-35 的做法）；`#` 後面一定要 `/`；資料夾或可執行檔帶 `#/`＝入口壞；指不到＝找不到。只用在 aos-exec 的入口路徑（XXX 與字串轉向），單子裡的 `$env` 路徑不認 `#`。另兩處也認 `#/`（10-20 使用者，見 [ideas](../../thinking/2026-10-20-ideas.md) D1、D3）：`$ref` 的檔名（N-45，同一套寫法）、argv[0]（帶 `#/`＝交給 aos-exec，N-61）。`AOS_CF` 不帶 `#/…`（指標位置在 `AOS_CO`，N-57）。（使用者：「並且支援json尋址，也就是loop.json#_exec」→ 頂層提 `#a/b` 或 `#/a/b` →「#/。」「尋址一定值得。」）
- **N-50**（10-16 定，草稿）**工具＝資料夾程式，放在呼叫它的那一格的資料夾裡、不用 PATH**：工具 `<名>` 的地址＝`<格>/tools/<名>/`，格裡寫 `aos-exec tools/<名>`——從自己 cwd 算的相對路徑、永遠零個 `..`（N-59 起跑 cwd＝格自己的資料夾，所以埋在第幾層路徑都一樣長）。呼叫每個工具都做同一件事：給它一個**小格**（它自己的 stack，`AOS_STACK=$AOS_STACK/<名>/ aos-exec tools/<名>`）；不知道工具裡是不是另一個 agent（C-52）。工具要不要碰工作區、怎麼碰是工具自己的事，要碰就用 `$AOS_WS`（N-55）。工具的參數怎麼進（args、stdin、或 stack 裡的檔）由工具自己的說明定（N-27）。aos 自己的指令（`aos-exec`、`aos-loop`、`aos-fsm`、`aos-daemon` 四支；沒有 `aos-inst`，§ 20）入口裡直接寫指令名、由呼叫者放進 PATH（aos 的程式都不動 PATH，[ideas § 24](../../thinking/2026-10-19-ideas.md)、N-59），那是 aos 的指令，不是工具；PATH 其餘的只留給人。（使用者 10-16 夜：「可以不使用PATH嗎？」→「好!」；CONVENTION P-17、P-25、P-33）
- **N-53**（10-16 定，草稿）**aos 的 agent 是被外面驅動的狀態機**：agent 每次被叫只走一次（跑現在那格、換狀態、退出），由外面的 loop 一次一次驅動——為的是讓 agent 方便審視自己（每次之間狀態都落在 stack、看得到）。反覆幾次、隔多久是 loop 的事；idle 看沒題了退 10，loop 收到 10 就停（N-43、P-19）；agent 資料夾可以**帶 loop 當入口**（`aos-loop loop.json`，P-05、P-06；使用者 10-19 §1，[ideas § 9](../../thinking/2026-10-19-ideas.md) 第 5 條裁定走今天的）。**某格出錯那一次退非 0、state 不動**（同 N-38，下一次重跑同一格）；**重試幾次由人或外面決定，agent 自己不數連錯**（P-20）。概念上 agent 只是一台狀態機、怎麼跑由誰跑都行（C-62）；本條只管 aos 自己的 agent。（使用者 10-16：「但是我們的規範會說，為了讓agent方便審視自己，所以agent就是一個被人驅動的狀態機，需要外面有人用loop驅動他。這是我們的aos agent」；頂層確認「腦出錯那一次退 1、phase 不動，重試幾次看外面 loop，agent 自己不數」→「可以。」，[KISS 重審拍板 4](../../thinking/2026-10-16-kiss-recheck.md#使用者拍板10-16)）
  - **10-28 補：一格一次用 aos-loop、一輪用 round，看 `_entry`**（使用者 10-28「一個行程跑完一整輪...是這樣的，aos agent他是基於loop/fsm，所以我們可以用aos-loop直接讓他一格一格跑。也可以用aos-round，讓他跑一整輪。aos-exec他的時候要跑哪個，那就看_entry是設定要哪個。」「喔不，還是零件庫吧。只是說，aos-round他是一個語法糖，沒有他，我們也可以用aos-loop加上一些東西去實現。」，[thinking 10-28 agent-ops 決定 12、13](../../thinking/2026-10-28-agent-ops.md#決定10-28)；細節照原則代定、可翻案，[agent-round § 2](../../thinking/2026-10-28-agent-round/02-2-round-一輪本身.md#2-round一輪本身)）：照 round 拆成格的 agent，格只有一套。`_entry` 寫 aos-loop、每次只做下一格＝本條的「每次被叫只走一次」照舊；`_entry` 叫 round＝一個行程跑完一輪（認領一題到答案寫進 `out/`；中途可掛 `hook/pause` yield）。round 是零件庫 `lib/agent/round/` 的語法糖（aos-loop 加「這一輪結束就停」），不是 aos 指令。從哪接著做看 `cur/` 跟 `history.jsonl` 最後一則，不另設狀態檔；格出錯那一次退非 0、狀態不動、人修好再跑，照本條。endpoint 的失敗可以經 `hook/on_error` 選 retry／switch（CONVENTION P-20 的 10-28 加註）；沒掛 `on_error` 的 agent 照本條「agent 自己不數連錯」。

## hub 型環境變數（10-28）

- **N-63**（10-28 定，草稿；使用者 10-28「hub 照你的建議定薄標準。」，[thinking 10-28 medium](../../thinking/2026-10-28-medium.md) 決定 17）**hub（類 singleton、全樹共用的那一個東西）用環境變數指，只定三件事，其他不管**：
  ① **命名 `AOS_<名字>`，值是一個資料夾的路徑**；
  ② **沒設定＝報錯、說缺什麼**：代號 `<名字>Missing`（C-54，例 `StackMissing`、`DaemonMissing`），不自己猜一個位置；
  ③ **子 process 預設繼承**（照 Linux 環境變數本來的樣子往下傳）。
  資料夾裡放什麼、誰建、怎麼跟它講話，各 hub 自己定。現有的實例：`AOS_STACK`（執行中狀態放哪，N-57）、`AOS_KERNEL`（kernel 的信箱資料夾，N-16、[aos-llm-send](../../impls/aos-llm-send/README.md)）。
  - **跟實作對不上的**（只列、程式沒改）：
    - `AOS_STACK` 沒設時 **aos-exec 自己退回預設** `$AOS_WS/.stack/`（N-57、C-69，impls aos-exec `setup_ws_stack`），跟 ② 不合；aos-loop（開了窗才要）、aos-fsm、aos-daemon、aos-llm-kernel 沒設就報 `StackMissing`，合。
    - `AOS_KERNEL` 沒設時 aos-llm-send 報錯、不猜位置，合 ②；但代號是 `MailboxMissing`、不是 `KernelMissing`（impls aos-llm-send `send.cpp`）。kernel 那一邊（aos-llm-kernel）不讀 `AOS_KERNEL`，信箱位置讀 kernel.json 的 `mailbox`（demo/llm-kernel 的 `_entry` 再把同一個路徑設給 `AOS_KERNEL`）。
  - **10-30 補：實例 `AOS_DAEMON`**（使用者 10-30「關於那個aos-daemon-ctl，他應該是要吃環境變數+argv來確定daemon home在哪裡的(要用哪個daemon)。」，[thinking 10-30 map-review](../../thinking/2026-10-30-map-review.md#決定10-30) 第 10 點，變數名與優先順序是實作代定、可翻案）：[aos-daemon-ctl](../../bin/README.md) 找「掛到哪個 daemon」用 `--daemon` ＞ `$AOS_DAEMON`，值＝那個 daemon 的 `$AOS_STACK` 資料夾；都沒有或不是資料夾＝`DaemonMissing`；子 process 照常繼承——三件都合。
    - ③ 跟 [CONVENTION P-39](../CONVENTION/06-巢狀.md) 的寫法不同：P-39 把 `AOS_STACK` 歸「叫別人時明給」（每層開小格、重設），不是一路繼承；繼承是預設，P-39 是 agent 範本在叫別人時的做法。
  - **10-30 夜改：實例拿掉 `AOS_HUB`**（使用者 10-30「都照建議」，[thinking 10-30 eca](../../thinking/2026-10-30-eca/09-方向題.md#決定10-30) 衝突 2、4、條文草稿；[10-30 map-review](../../thinking/2026-10-30-map-review.md#決定10-30) 第 5 點）：10-30 起 aos-hub 改做 **aos-eca-hub**（[extras/eca_hub](../../extras/eca_hub/README.md)），建在 aos-daemon 上、不設自己的常駐 kernel，用哪個 daemon 照 `--daemon` ＞ `$AOS_DAEMON`（上面 10-30 補），不另設變數（一個 hub 一個變數，這裡的 hub 就是 daemon；留著＝同一個資料夾兩個名字，C-54 一詞一義）。所以上面實例清單原有的「`AOS_HUB`（放常駐 aos-hub-kernel 的資料夾，[thinking 10-28 hub-kernel](../../thinking/2026-10-28-hub-kernel.md) 決定 2、10）」與「跟實作對不上的」底下「`AOS_HUB` 三件都合」那條拿掉，② 的例子 `HubMissing` 換成 `DaemonMissing`。`aos-hub` 這個名字保留，以後真有通用的 hub 再用（使用者 10-30）。

## 父子交代（10-29）

- **N-64**（10-29 定；使用者 10-29「父子交代...可以算基本概念，用不用都可以，用了的話我們也提供一些aos標準供人遵守」，看完衝突與方向題回「都照建議」，[thinking 10-29 medium-plan](../../thinking/2026-10-29-medium-plan.md) § 六、條文草稿；[10-28 medium](../../thinking/2026-10-28-medium.md) 決定 22、23、28；概念 [C-75](../CONCEPTS/03-基礎設施.md#proc-之間的交流10-29)）**父子交代（選用）**：上一代生下一代時給的、下一代結束時留下的，只在上下兩代之間。
  ① **上一代給下一代的**＝args、stdin、aos-exec 保證的六個環境變數（N-57）與 hub 型變數（N-63）；參數怎麼進由下一代自己說（[N-27](03-基礎設施-inst.md)）。
  ② **下一代留給上一代的**＝結束碼（[N-43](01-總則.md)）、stdout、stack 裡的檔（[N-13](05-基礎設施-窗.md)）。
  ③ 下一代要自報身分就報 `$AOS_WS`：上一代給的工作區就是它的名字。
  ④ 上一代要讓下一代找到自己的信箱或窗，用 hub 型變數（N-63）或 args 明給，不另加新的環境變數（C-69 aos 只訂那幾個）。
  這一條只是把散在 N-27、N-43、N-13、N-57、N-63 的東西集中點名；用不用都可以。daemon 起子 loop 就是一個實例（寫小格 `loop.json`、`AOS_STACK`＝小格、起 `aos-exec 小格/loop.json#/_entry`，N-28）。
