# 基礎設施／指示詞

（命令列語法糖〔TARGET、旗標、`--`〕那幾條的條號作廢。aos 的命令列只有 [N-58](10-基礎設施-定義與工作區/02-N-58.md) 的 `aos-exec [FLAGS...] XXX [args...]`（`--` 結束旗標，[ideas 10-21](../../thinking/2026-10/21/ideas/README.md)）——規範層只定 aos-exec 的命令列，其他程式的形狀是慣例 [P-44](../CONVENTION/02-題目stack停錯腦/07-P-44.md)（使用者 11-04 題 7「只進 CONVENTION 當慣例」）；沒有 `aos-inst` 命令列（使用者 10-19 晚，[ideas § 20](../../thinking/2026-10/19/ideas/README.md)；[ideas 10-22](../../thinking/2026-10/22/ideas/README.md)）。`檔#/指標` 是全系統唯一的「指」法，誰認它由各個讀者自己宣告（aos-exec 的入口路徑與 argv[0]、`$ref` 的檔名；`$ref` 只寫 `#/…`＝寫著它的那份檔），見 [N-62](10-基礎設施-定義與工作區/05-N-61～N-62.md)。）

- **N-45**（10-15 深夜定，草稿；[CONVENTION P-31](../CONVENTION.md)）**指示詞有兩個：`$env` 與 `$ref`，都可帶修飾欄 `$path`、`$prefix`**（10-19 晚使用者定保留 `$ref`：「impls這塊，指示詞是OK的」，[ideas § 22](../../thinking/2026-10/19/ideas/README.md)）。指示詞＝單子裡任何位置、帶 `$ref` 或 `$env` key 的物件，**整個物件換成它指到的值**；一個物件同時寫了 `$ref` 與 `$env` 只看 `$ref`，物件裡其餘 key 忽略。使用者 10-20：「在解析json時，他會嘗試找到所有$ref/$env，並進行相應替換，替換失敗就原封不動放著。關於找到$ref/$env後，他們所在的那個obj value，就會被替換，至於那個obj value裡面的其他東西，就不管。」「一些該報錯的還是要報錯：環境變數沒設、讀不到檔、指不到、繞圈。主要是json格式這塊，指示詞機制很寬容」（[ideas](../../thinking/2026-10/20/ideas.md) D12～D15）。錯分兩類：
  - **真的解不開＝錯**：環境變數沒設、`$ref` 的檔讀不到（不是 JSON 也算）、指標指不到、繞圈——解單子那一層自己的錯，退 1（aos-exec 行程內解單子時的錯，代號 `DirectiveBad`）。
  - **寫法（格式）寬容、不報錯**：不認得的 `$xxx`（含還沒定的 `$fmt`）與其餘 key 不管；`$path`、`$prefix` 不是字串（也不是 `null`）＝當沒寫；`$ref`／`$env` 的值不是字串或空字串、只有 `#/…` 卻不知道寫著它的是哪份檔＝換不了，**整個物件原封不動留著**（有 `$ref` 時不改試 `$env`；頂層自定，待使用者確認）。留下來的物件若在 argv 裡，解完不是字串，照 argv 的規則算單子壞／入口壞——那是 argv 的規則，不是指示詞的錯。
