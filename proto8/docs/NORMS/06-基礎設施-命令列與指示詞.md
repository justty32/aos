# 基礎設施／指示詞

（舊命令列的語法糖〔TARGET、旗標、`--`〕那幾條，條號 10-19 作廢。aos 的命令列只有 [N-58](10-基礎設施-定義與工作區.md) 的 `aos-exec [旗標...] XXX [args...]`（`--` 結束旗標，[ideas 10-21](../../thinking/2026-10-21-ideas.md)）；沒有 `aos-inst` 命令列（使用者 10-19 晚，[ideas § 20](../../thinking/2026-10-19-ideas.md)；[ideas 10-22](../../thinking/2026-10-22-ideas.md)）。`檔#/位置` 以 `#/` 尋址，用在 aos-exec 的入口路徑，見 [N-62](10-基礎設施-定義與工作區.md)。）

- **N-45**（10-15 深夜定，草稿；[CONVENTION P-31](../CONVENTION.md)）**指示詞有兩個：`$env` 與 `$ref`，都可帶修飾欄 `$path`、`$prefix`**（10-19 晚使用者定保留 `$ref`：「impls這塊，指示詞是OK的」，[ideas § 22](../../thinking/2026-10-19-ideas.md)）。指示詞＝單子裡任何位置、帶 `$ref` 或 `$env` key 的物件，**整個物件換成它指到的值**；一個物件同時寫了 `$ref` 與 `$env` 只看 `$ref`，物件裡其餘 key 忽略。使用者 10-20：「在解析json時，他會嘗試找到所有$ref/$env，並進行相應替換，替換失敗就原封不動放著。關於找到$ref/$env後，他們所在的那個obj value，就會被替換，至於那個obj value裡面的其他東西，就不管。」「一些該報錯的還是要報錯：環境變數沒設、讀不到檔、指不到、繞圈。主要是json格式這塊，指示詞機制很寬容」（[ideas](../../thinking/2026-10-20-ideas.md) D12～D15）。所以錯分兩類：
  - **真的解不開＝錯**：環境變數沒設、`$ref` 的檔讀不到（不是 JSON 也算）、指標指不到、繞圈——解單子那一層自己的錯，退 1（aos-exec 行程內解單子時的錯，代號 `DirectiveBad`）。
  - **寫法（格式）寬容、不報錯**：不認得的 `$xxx`（含還沒定的 `$fmt`）與其餘 key 不管；`$path`、`$prefix` 不是字串（也不是 `null`）＝當沒寫；`$ref`／`$env` 的值不是字串或空字串、`#` 後不是 `/`、只有 `#/…` 沒檔名＝換不了，**整個物件原封不動留著**（有 `$ref` 時不改試 `$env`；頂層自定，待使用者確認）。留下來的物件若在 argv 裡，解完不是字串，照 argv 的規則算單子壞／入口壞——那是 argv 的規則，不是指示詞的錯。
  - **`$path`、`$prefix`**（10-20 使用者：「我希望那個path可以換成$path，然後添加$prefix」「兩種都能用。如果換出來的不是字串，那也不報錯，就靜默失效。」，[ideas](../../thinking/2026-10-20-ideas.md) D9～D11）：換出來的值是字串時，先照 `$path` 接上去，再在前面加 `$prefix`：`{"$env": "AOS_WS", "$path": "a.txt", "$prefix": "--file="}` → `"--file=/ws/a.txt"`。**`$path` 是字串拼接**（10-21 傍晚使用者「$path/$prefix就只是單純的字串拼接，頂多處理一下/，所以$path也可以透過$path:"#/loops/a"，來取代$at？」→ 頂層給 (a) 留 `$path`、`#` 開頭直接接、其他中間補剛好一個 `/`，(b) `$prefix`／`$suffix` 純拼接 → 「a」，[ideas 10-21 § 9](../../thinking/2026-10-21-ideas/05-7-審後的五個細縫與修正.md#9-設定檔是唯一的位置參數path-改字串拼接10-21-傍晚) H6）：`$path` 以 `#` 開頭＝直接接在後面（`{"$env": "AOS_CF", "$path": "#/loops/a"}` → `"/x/big.json#/loops/a"`，大 JSON 裡的設定指回自己那一格就這樣寫）；其他＝去掉基底結尾的 `/`、去掉 `$path` 開頭的 `/`，中間剛好一個 `/`（`a.txt`、`/a.txt` 都是 `/ws/a.txt`；**寫絕對路徑也是接上去、不整個取代**）；`$path` 是空字串、不帶或 `null`＝不接；基底是空字串或 `/`＝接成 `/a`（頂層自定，ideas 10-21 § 9.3 第 8 點）。`$path: "#/…"` 只是「拼出指標字串」，不取那份檔裡的內容。`$env`、`$ref` 都能帶；換出來不是字串，兩欄靜默不作用、值原樣換進來。不帶 `$` 的 `path` 是普通 key，照上面「其餘 key 不管」。`$fmt` 使用者「先等等，fmt先不動」，未定。
  - **`$env`**：`{"$env": 名, "$path": 子路徑}` 換成該環境變數底下的路徑（照上面 `$path` 的字串拼接接上去；不帶 `$path`（或 `null`）就是整個變數值；`$path` 不是字串＝當沒寫，見上）。`$env` 讀的是**執行當下的環境**，像 shell 的 `$HOME`——同一份單子在不同環境下指到不同地方，所以可以當正式機制。變數沒設＝解單子那一層自己的錯，退 1（同上「真的解不開」）。`$env` 在 aos-exec 設好六個環境變數之後才解，所以單子裡讀得到 `AOS_STACK`、`AOS_CF`、`AOS_CD`（N-57）。
  - **`$ref`**（語意照 impls 的 aos-directive 庫，`proto8/impls/aos-directive/README.md`；impls 是使用者的檔）：`{"$ref": "檔"}` 換成**那份 JSON 檔的整份內容**，換進來的值**接著解**（裡面的 `$ref`／`$env` 也解）。相對檔名從**寫著這個 `$ref` 的那份檔所在的資料夾**算：單子本身是入口時＝入口檔所在的資料夾（`AOS_CD`）；被 `$ref` 進來的檔若是捷徑，解開捷徑、從它實際指向的檔所在的資料夾算（使用者 10-17 定）；loop／fsm 設定裡內嵌的單子＝那份設定檔所在的資料夾。**可以取檔內的位置，只認 `#/`**（[ideas](../../thinking/2026-10-20-ideas.md) D1、D7；10-23 使用者「把$at刪掉，就都只認#/。」）：`{"$ref": "x.json#/a/b"}` 換成 `x.json` 裡 `/a/b` 那個值（JSON pointer，寫法同 N-62：第一個 `#` 就切、`#` 後面一定要 `/`）。寫了 `$at` 是不認得的 `$xxx`、不管（`{"$ref": "x.json", "$at": "/a/b"}` 換成整份 `x.json`）。指標取的是那份檔的原文（不穿過檔裡的 `$ref`），取到的值再接著解。`$ref` 指回正在解的鏈上的同一個位置（檔＋指標，繞圈）、檔讀不到（**指到資料夾也算讀不到**：不走進去找入口、不把資料夾組成物件；10-21 傍晚使用者「對了，$ref如果指向的是資料夾？」「那還是維持報錯吧」，[ideas 10-21 § 9](../../thinking/2026-10-21-ideas/05-7-審後的五個細縫與修正.md#9-設定檔是唯一的位置參數path-改字串拼接10-21-傍晚) H8）、不是 JSON、指不到＝錯，一樣是解單子那一層自己的錯、退 1；`#` 後不是 `/`、值不是字串或空字串、只有 `#/…` 沒寫檔名＝物件原封不動留著（見上「寫法寬容」）。物件有 `$ref` 就只看 `$ref`、`$path`、`$prefix`，其餘 key（含 `$env`、`$at`、不帶 `$` 的 `path`、不認得的 `$xxx`）不管。
  - **`$ref` 可以寫成陣列＝幾份照順序合成一份**（10-23 使用者）：頂層問 daemon 的 `loops` 要拆成好幾份檔怎麼寫時，使用者：「等一下，我記得可以這樣啊："$ref":["a.json", "b.json#/c/d]"」；使用者接著選「**`$ref` 可以寫成陣列＝把幾份照順序合成一份：都是物件就合 key，都是陣列就接起來，種類混在一起＝解不開**」與「**合物件時同名 key：後面的蓋前面的**」（淺層合併，不往下層合）。例：`{"$ref": ["a.json", "b.json#/c/d"]}`。細則（頂層照上面兩類錯的規則推）：
    - **每個元素**就是一個 `$ref` 字串（`檔`、`檔#/位置`），相對路徑照原規則從寫著它的那份檔所在的資料夾算；每一份各自取原文、各自接著解（裡面的相對 `$ref` 從那份檔自己的資料夾算），解完再合。合物件時同名 key 的位置留在第一次出現的地方、值換成後面的。
    - **只有一份**＝就是它本身（不限種類，跟寫成字串一樣）；**兩份以上**卻不是全物件或全陣列（混在一起，或都是字串、數字、布林、`null`）＝合不起來＝`DirectiveBad`（頂層推的，10-23 使用者確認：「好。」）。
    - **位置只認 `#/`**：每個元素各自寫 `檔#/位置`；寫了 `$at` 不管（同上；使用者「把$at刪掉，就都只認#/。」）。
    - **`$path`、`$prefix`** 作用在合好的那一份：是字串才接（只會發生在只有一份時），不是字串靜默不作用（同上）。
    - **寫法寬容**：空陣列（同空字串）、有任何一個元素不是合格的字串（不是字串、空字串、`#` 後不是 `/`、只有 `#/…` 沒檔名）＝換不了，**整個物件原封不動留著**，不會只合其中幾份。
    - **真的解不開**：有一份讀不到、指不到＝`DirectiveBad`，整個都不換；**繞圈**看的是往上那幾層（某一份指回正在解的鏈上同一個位置）；同一個陣列裡寫兩次同一份不算繞圈（物件合起來一樣、陣列接兩次）。
    - 只換一格的讀法（`resolve_shallow`，見下「aos 讀的 JSON 都解」）：合出來的每個 key／元素記著它來自哪份檔，讀的人往下解那一格時從那份檔的資料夾算。
  - **argv 陣列裡也能放**（10-20 使用者，見 [ideas](../../thinking/2026-10-20-ideas.md) D2、D8）：入口的 argv 陣列（C-73、N-61）元素可以寫 `$env` 或 `$ref`（`["echo", {"$env": "AOS_WS"}]`、`[{"$ref": "cmd.json#/0"}, "x"]`；`$path`、`$prefix` 同樣適用）；aos-exec 在六個環境變數設好之後解，相對檔名從陣列所在的檔的資料夾（＝`AOS_CD`）算；解完每個元素都要是字串，不是（或解不開；寫法不合而原封不動留下的物件也不是字串）＝入口壞（代號 `EntryBad`）、aos-exec 退 1，不會把解出來的陣列攤開。
  - **aos 讀的 JSON 都解**（10-23 晚；使用者「對了，各種json應該都支援指示詞吧」，使用者選「aos 讀的 JSON 全部支援」，[thinking 10-23 ctl 與 $ref](../../thinking/2026-10-23-daemon-ctl-ref.md)）。分兩層：**規範**＝aos 自己的程式讀的 JSON 一律支援指示詞；**事實**＝別人做的程式不一定支援（使用者：「其他地方預設不支援指示詞...這不應該是規範，這是在陳述事實，因爲其他人做的程式未必會想支援這個」）。細則（頂層照原則定）：
    - **每支程式只解自己讀的那幾格**（C-52）：整份、以及它一層層讀進去的那幾層先換掉（只換那一格，不往裡面走）；它讀的 key 的值整個解；**它不讀的 key（`body`、`_entry`…）原封不動**，留給讀它的人——`loop.json#/body` 由跑那次的 aos-exec 照上面的規則自己解，所以 body 裡的 `$env` 沒設照舊是那次 aos-exec 的錯、不擋 loop 起來。`exec` 直接放單子物件時（[thinking 10-24](../../thinking/2026-10-24-exec-relative/01-使用者原文.md#10-24-exec-直接放單子)），loop／fsm／daemon 讀設定只把 `exec` 換一層、單子裡面不解，留到每次跑的時候（`AOS_CF`／`AOS_CO` 設好）由 `run_inst` 解；解不開＝那支程式自己的錯（`DirectiveBad`）。aos-loop：loop.json 整份、`exec`、`max`、`interval_ms`、`ctl`、`state`；ctl 整份、`paused`、`stopped`、`max`、`interval_ms`、`seq`。aos-daemon 再加 daemon.json 的 `loops`、`adopt`，ctl 的 `loops`、`loops_added`、`loops_removed`（子項怎麼解見 [N-28](04-基礎設施-loop與daemon.md) 10-23 晚 ②）。aos-fsm：fsm.json 整份、`start`、`states`、每一格、格的 `exec`、`next`（key 名：使用者「fsm.json，現在是用val，幫我改成exec」「exec，loop／daemon 的 run 也一起改 exec」，[thinking](../../thinking/2026-10-23-naming.md)）。
    - **相對 `$ref` 從寫著它的那份檔所在的資料夾算**（同上 `$ref`）：設定檔＝設定檔的資料夾（`檔#/指標` 取的是那份檔）、ctl＝ctl 的資料夾、換進來的檔＝它解開捷徑後的資料夾。
    - **解不開**：設定檔＝程式自己的錯，退 1、一行 `程式名: DirectiveBad 原因`；ctl＝整份不採用、維持上一份好的、原因進 `ctl_warning`（N-08）。寫法不合的照上面原封不動，再照那一格自己的規則判（例 `max` 留成物件＝`CfgBad`）。
    - **state 窗是程式自己寫的**：只有 daemon 的 `loops` 表太長時用 `$ref` 陣列切檔（N-28 10-23 晚 ③）；讀 state 的人自己用同一個庫（aos-directive）解，拿回完整的 `loops` 物件。
  - 寫什麼就做什麼（C-56）：值寫的就是「讀這個環境變數」「換成那份檔」，不做字串內插（`"$AOS_STACK/plan.txt"` 那種是把規則埋進字串的暗規則）。單子本來就能內嵌，**JSON 大不是問題**，慣例範本不用 `$ref` 拆檔（P-27、P-31）；`$ref` 是給要拆的人用的。
  （使用者 10-15 深夜：「我記得有說過吧，在概念或規範那邊，有說過指示詞的用法」「啊...好啦，規範那邊說一下，後續就是都默認沒有指示詞能用，但是不用擔心json太大」；出處 [thinking inst-exec 第四版](../../thinking/2026-10-15-inst-exec-v4.md)。「後續就是都默認沒有指示詞能用」那句使用者 10-23 晚澄清：「這不應該是規範，這是在陳述事實，因爲其他人做的程式未必會想支援這個」——規範是 aos 自己的程式讀的 JSON 一律支援，見上「aos 讀的 JSON 都解」。10-16 夜使用者：「可以用$env啊」，再選「A」：`$ref` 是拆檔便利、`$env` 讀執行當下的環境可當正式機制，[稿 § 四](../../thinking/2026-10-16-agent-inherit/02-四-使用者決定.md#四使用者決定10-16)。）
