- **N-11** 設定檔、ctl、state 是同一條線：「設定檔」＝程式啟動時只讀一次的那份 JSON 檔（loop.json／daemon.json／fsm.json），是命令列唯一的位置參數，像 `aos-loop loop.json`，可寫 `檔#/指標`＝那份檔裡那個位置的物件；新程式盡量不收旗標、不從 stdin 讀設定（使用者 10-19 晚「捨棄舊的」，[ideas § 22](../../../../thinking/2026-10/19/ideas/README.md)；使用者 10-21 晚「新程式不收旗標...沒關係的，那是軟性，應該改成"盡量不收"」，[ideas 10-21 § 6](../../../../thinking/2026-10/21/ideas/04-6-JSON-物件當資料夾-一路往下-AOS_C.md#6-json-物件當資料夾一路往下aos_co10-21-晚)）。它整份只在起來時讀一次（含 loop.json 裡的 `exec`），跑的途中要改只能走 ctl.json，ctl 蓋過設定檔，state 回報實際生效的值。三者裡節奏類的 key（跑幾次、隔多久）同名；ctl 只能蓋節奏類 key（`max`／`interval_ms`；ctl 的動作 `cmd` 見 N-07），位置、身體類的 key（`ctl`、`state`、`exec`…）不能從 ctl 改，要改就停了重起（例外：daemon 的管轄手把 `procs_ctl.json` 認 `procs`、`procs_added`、`procs_removed`、`procs_stopped`、`procs_started`、`procs_slept`、`procs_woken`（後兩個：新舊打架，11-17「新的覆蓋舊的」，N-28 11-05 較晚），[N-54](../../04-基礎設施-loop與daemon/03-N-54.md)；[thinking ctl-commands](../../../../thinking/2026-11/03/ctl-commands/README.md) § 6）。（使用者 10-12 夜）
  - loop.json 的 `ctl`／`state`／`state_flux` 沒寫＝`ctl.json`／`state.json`／`state_flux.json`、寫 `null`＝不開；要開卻沒設 `AOS_STACK`＝`StackMissing`（使用者題 5「留 key、沒寫時預設就是這兩個名」，[four-elements 06](../../../../thinking/2026-11/04/four-elements/06-要使用者裁的題.md)）。
  - **旗標**（使用者 10-21 下午「loop.json還是需要的，至少我比較喜歡這個，寫好一次設定後就可以多次使用。然後旗標放前面確實比較好。」，[ideas 10-21 § 8](../../../../thinking/2026-10/21/ideas/05-7-審後的五個細縫與修正.md#8-aos-loop10-21-下午)）：aos-loop、aos-daemon 收旗標——`程式 [--max N] [--interval-ms N] [--ctl 檔] [--state 檔] [--state-flux 檔] 設定檔`，旗標放設定檔前面、規則同 aos-exec（N-58）；旗標鏡射設定檔的 key（旗標名＝key 名底線換連字號），起跑時 旗標 ＞ 設定檔 ＞ 預設。
  - **設定檔是唯一的位置參數**（使用者 10-21 傍晚「--cfg是否可以簡化？比如aos-loop --cfg loop.json foo.json，簡化成aos-loop loop.json，然後loop.json內就包含各種東西？」，[ideas 10-21 § 9](../../../../thinking/2026-10/21/ideas/05-7-審後的五個細縫與修正.md#9-設定檔是唯一的位置參數path-改字串拼接10-21-傍晚) H1～H3）：必給、只能一個，多給＝參數錯（代號 `ArgumentsBad`）；沒有 `--cfg`。要跑什麼寫在設定檔的 `exec`（可以是陣列 `[目標, 參數...]`；key 名照使用者「exec，loop／daemon 的 run 也一起改 exec」，[thinking](../../../../thinking/2026-10/23/naming.md)），附加參數也可以從 `--` 後面帶（下一點）。aos-fsm 同規則（目前沒有旗標）。跑的途中仍只能走 ctl，ctl 蓋過前面三者（每跑一次讀一次、後到先贏），state 回報實際生效的值。
  - **`設定檔 -- 參數...`、`--enable-logs`**（使用者 11-02 晚「aos-loop XXX -- ...應該是可以這樣用的，代表後面的argv轉給裡面的exec？這樣可以嗎？」，接著「1. 是的，就應該這樣，也就是aos-XXX ... ... -- ...，第一個...就是aos-XXX本身的旗標，大多都是--aaa bbb或-c，第二個...就是目標檔案，或是目標字串陣列，後面就是純參數。」；log 是 11-02「要給argv讓使用者選擇是否要印出」、11-02 晚「aos-loop和aos-daemon他們印出的log感覺都沒啥用，應該要改成默認不印。」，[thinking 11-02 state 窗](../../../../thinking/2026-11/02/state-window/01-使用者原文-11-02-逐字.md#決定11-02-晚使用者實作中陸續裁的)；照實作寫，[impls/aos-loop](../../../../impls/aos-loop/README.md)「用法」「log」）：命令列是 `程式 [旗標...] 設定檔 [-- 參數...]`。設定檔之後接 `--`＝後面全是附加參數（那個 `--` 剝掉），**每次**接在 `exec` 後面（字串目標＝`[目標, 參數...]`、陣列＝接在最後、內嵌單子＝接在單子 `argv` 的最後）；aos-daemon 只接在 daemon 自己的 `exec`、不影響子項；ctl 改不了它們。使用者說的通則（`aos-XXX [FLAGS] 目標 -- 參數`）只記原文，其他程式不跟著改。旗標多一個不帶值的開關 `--enable-logs`：給了才把 log 印到 stdout（預設不印，不寫 log 檔；內容見 [N-28](../../04-基礎設施-loop與daemon/02-N-28.md)「log」），log 跟身體的 stdout 混在一起由使用者自己處理（使用者 11-02 晚「aos體系下，stdin/out/err都可以任意指定，混在一起就是使用者自己要處理的，不用管太多。」）。
