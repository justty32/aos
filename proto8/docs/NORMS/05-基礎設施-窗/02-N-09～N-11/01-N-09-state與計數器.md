- **N-09** 要回報狀態，寫到另一個檔（state），不碰 ctl.json；一個 state 檔只有被控制的那個東西自己寫；選填；沒給就不開、也不提醒（N-13；fsm 的 state 見 N-13）。aos-loop（與繼承它的 aos-daemon）的 `ctl`／`state` 沒寫＝預設名 `ctl.json`／`state.json`、寫 `null`＝不開（使用者題 5「留 key、沒寫時預設就是這兩個名」，[four-elements 06](../../../../thinking/2026-11/04/four-elements/06-要使用者裁的題.md)）。被 SIGKILL 的程式（例 daemon 收不掉、滿 10 秒 SIGKILL 的子 loop）留下的 state 停在最後一份，別人（daemon）不替它補；死活照 N-17；daemon 的 log 那一行寫 `stopped`、`signal` 9，表上留不留那一列照 [N-28](../../04-基礎設施-loop與daemon/02-N-28.md)。
  - **state 有變才寫**（使用者 11-02「state.json就是初始的時候寫下，有變動的時候更新」「kind沒人在用，那就拿掉」、方向題 2「對」、方向題 3「收掉」，11-02 晚「running/waiting確實不該算變動」，[thinking 11-02 state 窗](../../../../thinking/2026-11/02/state-window/01-使用者原文-11-02-逐字.md#決定11-02使用者)；照實作寫，[cpp/aos-loop](../../../../cpp/aos-loop/README.md)「窗」）：aos-loop、aos-daemon 的 state 啟動後第一份一定寫、結束那份（帶 `code`）一定寫，之間跟上一份寫出去的比，**有變才寫**；`phase` 在 `running`／`waiting` 之間換不算。state 沒有 `kind`、`recorded_at`、`counter_runs`（計數器見下）；最後一欄 `updated_at`＝這份寫出去的那一刻（ISO 8601 UTC 到毫秒），只有 state／procs_state 有，state_flux 沒有（它每次寫都伴隨 `responded_at` 更新，再加一欄是重複）。
  - **名詞表**（見 N-06）：state 的 `phase` 照名詞表、不改字；「現在暫停中」記在 state 的 `paused`／`phase`（[ctl-commands § 4](../../../../thinking/2026-11/03/ctl-commands/02-2-loop-怎麼知道這道是新的-沒有信.md#4-現在暫停中記在哪再起時怎麼辦代定)）。state 只有自己寫：想讓一支 loop 一起來就暫停，正路是起來後寫 `{"cmd": "pause"}`，不是替它寫 state.json。daemon 的名單窗叫 `procs_state.json`（N-28「兩個手把、兩扇狀態窗」）。
  - **計數器：只因時間或每跑一次就變、又沒人讀的欄，不放 json、改寫 `.txt`、放旗標後面**（使用者 11-09「一些 json 檔案變動得太頻繁，如 loop 的 runs 之類，像這類非常頻繁變動的，我覺得可以從 json 中拉出來，改成用 .txt 寫，然後要有 argv 做旗標選擇是否要寫。這應該是原則，不然這種固定的寫檔開銷實在不好。」，五題「都照推薦」，[thinking clock-and-hot-writes](../../../../thinking/2026-11/09/clock-and-hot-writes/README.md)）：
    - **判準兩條都要符合**：①只因時間過去或每跑一次就變（不是有事件才變）；②除了寫它的程式自己，沒有程式讀它。符合的才搬。
    - **怎麼寫**：一個計數器一個 `.txt`（名字照 C-54，例 `counter_runs.txt`），內容是十進位整數＋換行；照 N-05 先寫暫存（`.counter_runs.txt.<pid>.tmp`）再改名，因為人可能正在 `cat` 它。
    - **旗標**：預設不寫；各程式統一用不帶值的開關 `--enable-counters`，走共用介面（C++ `parse_cli`、Python `aos_flags`），不各自取名。
    - **兩層原則**：常變的欄分兩層處理——①**沒人讀＋只因時間或每跑一次就變**→旗標後面的 `.txt` 計數器（本條上兩點）；②**有人讀＋隨便有人敲一下就變**（寄信、寫 ctl、ping、壞信，使用者 11-09「容易變動...就是隨便有人敲一下就變動，或是有風吹草動就變動」）→同資料夾的公開窗 `state_flux`（下一點），不放旗標後面。兩層都不符的（`phase`、時鐘）不搬，管的是「什麼時候寫」。
    - **落點**：aos-loop、aos-daemon 開了 `--enable-counters` 而且有 state 窗時，每跑一次把這個行程起來後跑過幾次寫進 state 窗同資料夾的 `counter_runs.txt`；llm kernel（`py/tools/aos/kernel_llm`）的 `queue.json` 沒有 `counter_runs`，開了旗標才讀寫 `$AOS_STACK/counter_kernel_runs.txt`（跨次累加；名字帶 `kernel` 是因為 kernel 跟管它的 daemon 共用同一個 stack，daemon 的 `counter_runs.txt` 也在那裡，代定）。「什麼時候寫」：`responded_at` 不因身體跑完一次而更新（細則 N-32）、aos-daemon 的 `procs_state.json` 沒有頂層時鐘觀察值（[N-28](../../04-基礎設施-loop與daemon/02-N-28.md)）、`queue.json` 與 aos-fsm 的 `stage.txt` 內容沒變就不重寫。`--enable-logs` 的 log 行裡照樣有 `counter_runs`。
