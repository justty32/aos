- **N-17**（10-14 定；10-22 定稿，[ideas 10-22 § 5](../../../thinking/2026-10/22/ideas/03-5-loop.md#5-loop10-22)）心跳：state 帶 pid、啟動時間、開機 id；內容沒變也每隔一段碰一下；超過 3 倍間隔沒動靜算疑似死亡（確定要看 pid＋啟動時間，N-15）。間隔＝1 秒、不開 key（N-32）。
  - **狀態只有一個 key `phase`、一套值**（10-23 使用者「都先幫我統合」，[thinking](../../../thinking/2026-10/23/naming.md)）：loop／daemon 自身 state 頂層的 `phase`、daemon 子項表（`loops`；10-29 起在 `loops_state.json`，N-28）各列的 `phase` 都從 `waiting`／`running`／`paused`／`stopping`／`done`／`stopped` 取。aos-loop 用 `waiting`／`running`／`paused`／`done`／`stopped`。daemon 頂層用 `waiting`／`running`（有 `exec` 時）／`paused`／`stopping`／`done`／`stopped`；沒有 `exec` 的 daemon 不寫 `running`（一圈一份 `waiting`）。daemon 子項用 `running`／`stopping`／`done`／`stopped`：子 loop 自己結束＝`done`、daemon 收掉它＝`stopped`、送了 SIGTERM 還沒退＝`stopping`。沒有 `starting`、`backoff`、`removed`：子項起來就算 `running`、`backoff` 隨「不自動重起」不做（[N-28](../04-基礎設施-loop與daemon/02-N-28.md)）、移除的直接從表上拿掉。11-03 起 daemon 子項表的值是 `running`／`stopping`／`stopped`（N-28「`procs_state.json` 就是 save 檔」），11-03 晚多 **`sleeping`**（daemon 收工時還在跑的 loop 型，再開自動 wake；N-28「收工時 sleep、開門時 wake」、[thinking 11-03 procs § 8](../../../thinking/2026-11/03/procs/10-實作時代定-11-03-實作者照原則定的.md#8-收工時改寫成休息中sleepwake11-03-晚)）；log 行同。
  - **心跳只在兩次之間跳**（10-20 使用者「照預設」，[ideas § 25](../../../thinking/2026-10/19/ideas/README.md)）：state 在兩次之間寫（每次跑之前寫一次、睡著時每秒一次），正在跑時不另外碰；一次跑很久時 `recorded_at` 會停在那次開始那一刻，確定死活照上面看 pid＋啟動時間。
  - **daemon 收子項**（[thinking 10-23 daemon 壓測](../../../thinking/2026-10/23/daemon-bench.md)，[N-28](../04-基礎設施-loop與daemon/02-N-28.md)）：不原地等，送 SIGTERM 後照常巡、照寫 state——子項那一列送了 SIGTERM、還沒退時是 `stopping`；daemon 收工等子項退的那段，頂層 `phase` 是 `stopping`、每秒寫一份。
  - 被 SIGKILL 的程式來不及寫最後一份，它的 state 會停在 `running` 之類：**讀的人一律照 pid＋`started_at_ticks` 判死活**，`phase` 不算數。
  - **11-02 改口：心跳拿掉**（使用者 11-02「心跳這塊就直接看pid就好，從檔案判斷...檔案的更新本來就會受到多方面因素影響，這其實不太好，應該說，要看一個proc是否還活著，除去linux底層proc機制外，我們的aos-daemon-ctl問詢也是一個方式，兩者並存。」，答 [thinking 11-02 state 窗](../../../thinking/2026-11/02/state-window/01-使用者原文-11-02-逐字.md#決定11-02使用者) 衝突 1；照實作寫）：state 照舊帶 pid、`started_at_ticks`、`boot_id`，但**內容沒變就不碰檔**（N-09 的 11-02 補），睡著時窗不動。判活著＝pid＋`started_at_ticks`＋`boot_id` 對 Linux 的 /proc；另外 [aos-daemon-ctl](../../../bin/README.md) 的 `ls` 也會照這三欄對 /proc、對不上說一句「daemon 沒在跑」——兩者並存。**不從檔案的更新時間判**（`updated_at` 新不新也不算）。本條開頭「內容沒變也每隔一段碰一下；超過 3 倍間隔沒動靜算疑似死亡」「間隔＝1 秒」與「心跳只在兩次之間跳」那段不再成立；「daemon 收子項」那段的「每秒寫一份」改讀成「先寫一份 `stopping`、之後每退一批寫一次 `loops_state`」；「沒有 `exec` 的 daemon（一圈一份 `waiting`）」改讀成最多一份、有變才寫。daemon 子項的 `done`／`stopped` 11-02 起只出現在 daemon 的 log 那一行（子項結束就從表上拿掉，[N-28](../04-基礎設施-loop與daemon/02-N-28.md)「子項結束後不自動重起、不留名單」），表上看得到的只有 `running`／`stopping`。
