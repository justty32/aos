  - **11-09 例外（poke）**：「其他人不碰 pid」唯一的例外是 [`aos-daemon-ctl poke`](../../../cmd/docs/03-aos-daemon-ctl.md)——門鈴，不帶內容、不判死活，只叫 daemon 立刻看一次檔（指令照舊寫 ctl.json／procs_ctl.json／信箱）。寄件人讀 daemon 自己 state 的 `pid`、`started_at_ticks`、`boot_id` 與穩定欄 `poke`（宣告三個訊號號碼；沒這欄＝`PokeFailed`），先開 pidfd、三欄都對上 `/proc/<pid>/stat` 的 starttime 與 `/proc/sys/kernel/random/boot_id` 才用 pidfd 送；對不上或行程不在報 `DaemonMissing`；跨帳號／沙箱送不出去（EPERM 等）報 `PokeFailed`、不改走別的路。pid 被別的程式重用的殘餘風險由使用者承擔——使用者 11-09：「pid被別的程式重用...這是使用者自己要承擔的風險，但我們確實也會做一些護欄，就是你說的這些。」送得出去不代表 daemon 活著、叫得動，**不拿送不送得出去來判死活，也不縮短任何逾時**；判死活照上面的改讀。只有 aos-daemon 與這支指令懂訊號，proc 與其他 aos 程式照舊只寫檔（[thinking daemon-interrupt](../../../thinking/2026-11/09/daemon-interrupt/README.md)）。（11-10 prefix-fixes open-11：aos-daemon-ctl shutdown 照同一套核 pid 再寫 daemon 自己的 ctl）
