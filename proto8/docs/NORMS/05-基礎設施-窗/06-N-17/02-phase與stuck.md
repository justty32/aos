N-17 接續（上一份的子項到這裡繼續）：

  - **狀態只有一個 key `phase`、一套值**（10-23 使用者「都先幫我統合」，[thinking](../../../../thinking/2026-10/23/naming.md)）：loop／daemon 自身 state 頂層的 `phase`、daemon 子項表（`procs_state.json` 的 `procs`，N-28）各列的 `phase` 與 daemon 的 log 行都從 `waiting`／`running`／`paused`／`stopping`／`done`／`stopped`／`sleeping`／`stuck` 取。
    - aos-loop 用 `waiting`／`running`／`paused`／`done`／`stopped`。
    - daemon 頂層用 `waiting`／`running`（有 `exec` 時）／`paused`／`stopping`／`done`／`stopped`；沒有 `exec` 的 daemon 不寫 `running`（一圈最多一份 `waiting`、有變才寫）。
    - daemon 子項表的列用 `running`／`stopping`（送了 SIGTERM 或寫了 stop、還沒退）／`stopped`（daemon 下的 stop 退了；或已知非 0 結束，帶 `reason`、`code`）／`sleeping`（daemon 收工時還活著的 proc，再開自動 wake；N-28「收工時 sleep、開門時 wake」、[thinking 11-03 procs § 8](../../../../thinking/2026-11/03/procs/10-實作時代定-11-03-實作者照原則定的.md#8-收工時改寫成休息中sleepwake11-03-晚)）／`stuck`（下一點）。退 0 或 `adopt` 拿不到碼的自然結束從表上拿掉，結束的值只出現在 daemon 的 log 那一行：子 loop 自己結束＝`done`、daemon 收掉它＝`stopped`。出錯結束（已知非 0）留表見 N-28「出錯結束一律留表」；`auto_restart` 見下面「被 SIGKILL」（使用者裁定 B，sol 審查）。
    - **`stuck`＝該有反應卻沒反應**：只出現在父 daemon 的表；刺激只有一種——新的 ctl 沒被採用：子 `ctl.json` 的 mtime（刺激時間，使用者裁定 sol 審查 #15-1 接受）晚於起／接回基準，而子 state_flux 的 `responded_at` 沒跟上，才按每列 `stuck_after_cycles`（預設 10，門檻是代定；兩鐘）或 `stuck_after_ms`（牆鐘毫秒，兩者擇一）起算；表上標 `stuck`＋英文原因，回應後回 `running`。對任何有公開 ctl／state_flux 窗的 proc 都判；父讀的是子 ctl 與子 state_flux，不讀子 state、不看子信箱（使用者 11-06 晚：「子daemon管好自己，父daemon只看他有沒有活着，子daemon的其他東西父daemon別碰。盡量解耦合。」，[17 § 使用者裁定](../../../../thinking/2026-11/05/no-pid/17-P7實作結果.md#使用者裁定11-06-晚家機)）。**要判卡住就要開 state_flux**：子的 `state_flux` 設 `null`、檔不在或不是物件＝這列不判；為了省檔關掉它就丟了監看。手寫 ctl 要換 `seq`（同內容再寫一次＝子不回應，會被標）。不改寄 ping（使用者 11-06「照原設計」）。預設只標、等人處理（`ctl rm` 或 `ctl start`）；列上選填 `restart_on_stuck: true` 才由上一層 SIGTERM→SIGKILL 整群、照表重起——第一次卡住也計入，第三次連續未回應又卡住收完留 `stopped`（最多重起兩次）；父 paused 只標；只有上一層動 pid。使用者 11-05「你的想法很好，我也是這麼想的！，剩下都沒問題！」（[監管樹](../../../../thinking/2026-11/05/no-pid/05-監管樹.md)、[11-06 裁定](../../../../thinking/2026-11/05/no-pid/12-P5b條文結果.md)、[16](../../../../thinking/2026-11/05/no-pid/16-P7重設計.md)、[17](../../../../thinking/2026-11/05/no-pid/17-P7實作結果.md)）。
    - **接回時讀子 `phase`**：loop 型子項被接回時，父 daemon 讀子 state 的 `phase == done`（已經跑完的不再接回），算「看它有沒有活著」裡的「是否已結束」，不算碰子的其他東西（使用者裁定，出處 [wf/workflows/refactor/reports/2026-11-07-sol審查/11-使用者裁定.md](../../../../../wf/workflows/refactor/reports/2026-11-07-sol審查/11-使用者裁定.md) #34-5）。
    - 沒有 `starting`、`backoff`、`removed`：子項起來就算 `running`、不做 backoff、移除的直接從表上拿掉。
  - **daemon 收子項**（[thinking 10-23 daemon 壓測](../../../../thinking/2026-10/23/daemon-bench.md)，[N-28](../../04-基礎設施-loop與daemon/02-N-28.md)）：不原地等，送 SIGTERM 後照常巡、照讀 ctl、state 照規則寫（有變才寫）——子項那一列送了 SIGTERM、還沒退時是 `stopping`；daemon 收工等子項退的那段，頂層 `phase` 是 `stopping`：先寫一份 `stopping`、之後每退一批寫一次 `procs_state`。
  - **被 SIGKILL**：被 SIGKILL 的程式來不及寫最後一份，它的 state 會停在 `running` 之類：daemon 自己照 pid＋`started_at_ticks`＋`boot_id` 判死活，`phase` 不算數；其他人照上面讀上一層表或寄信。被 `kill -9` 的 daemon 自己的窗會停在 `running` 等最後狀態，別人從它自己的窗看不出死活，寄信沒回＝這次呼叫失敗（[P3 新發現的邊緣 2](../../../../thinking/2026-11/05/no-pid/10-P3實作結果.md#新發現的邊緣沒修攤出來)）。子 daemon 掛成普通 proc（使用者 11-06「不要耦合」），那列寫了通用的 `auto_restart: true` 時，被 `kill -9` 或自己退了，上一層同一拍照表重起；連 3 次都在起來 3 秒內就退，上一層才在自己的表把那列標 `stopped`＋`reason`（[no-pid 15](../../../../thinking/2026-11/05/no-pid/15-P6去耦合.md)）；叫不動的標 `stuck`（上面）。

時鐘停住時判卡住、以 cycle 計的鎖租約與逾時一起停，`stuck_after_ms` 的列例外：見 [時空](../../02-設計理念-時空.md) 末段。
