- **N-17**（[ideas 10-22 § 5](../../../../thinking/2026-10/22/ideas/03-5-loop.md#5-loop10-22)）判死活（不設心跳）：state 帶 pid、`started_at_ticks`（啟動時間）、`boot_id`（開機 id），**內容沒變就不碰檔**（N-09），閒著跑身體、睡著時窗都不動（`responded_at` 只在 ctl、信、子項起落時更新，在 state_flux，見細則 N-32）。**不從檔案的更新時間判死活**（`updated_at` 新不新也不算）。（使用者 11-02「心跳這塊就直接看pid就好，從檔案判斷...檔案的更新本來就會受到多方面因素影響，這其實不太好，應該說，要看一個proc是否還活著，除去linux底層proc機制外，我們的aos-daemon-ctl問詢也是一個方式，兩者並存。」，[thinking 11-02 state 窗](../../../../thinking/2026-11/02/state-window/01-使用者原文-11-02-逐字.md#決定11-02使用者) 衝突 1）
  - **誰對 `/proc` 判活**：只剩 daemon 自己（`adopt` 接回、起 loop 型前看小格；`adopt` 另比表頂層 `boot_id`，看小格只比 pid＋ticks），照 pid＋`started_at_ticks`＋`boot_id` 對 Linux 的 /proc。其他人不碰 pid：讀上一層 daemon 寫的 `procs_state.json` 那一列的 `phase`（`aos-daemon-ctl ls` 尾行以 `# ` 開頭印上一層的看法），或寄信等回信（`aos-daemon-ctl ping`、帶 `reply_to` 的信）——「兩者並存」的問詢就是寄信問、讀上一層的表。時限內沒回＝這次呼叫失敗：`ping` 沒回報 `DaemonFailed`，aos-agent ctl 等滿、沒回且表上結果未成立時也報 `DaemonFailed`（結果先成立則另等 1 秒後可成功，詳 N-63）；`DaemonMissing` 只用於沒設／daemon 資料夾不在（使用者裁定 sol 審查 #28）。人殼 `--reply-to` 只寄、由呼叫者等信；沒帶則只看一小段時間（預設 3 秒）有沒有被認領、未領是提醒並退 0。出處是使用者 11-05 晚「所有牽涉到linux原生行程的機制，都以daemon爲界面」「寄信不回，等同於呼叫失敗」（[原文](../../../../thinking/2026-11/05/no-pid/README.md)、[P3 結果](../../../../thinking/2026-11/05/no-pid/10-P3實作結果.md)）。
  - **時限由寄信者自己設定、判官輔助**（使用者 11-06「由寄信者自己設定。然後30秒？這不該是固定值，同樣該由寄信者自己設定。判官會輔助。」，[os-impl 05](../../../../thinking/2026-11/06/os-impl/05-寄信者自設逾時.md)、[寫死的等待盤點](../../../../thinking/2026-11/06/os-impl/05-續2-寫死的等待盤點.md)）：寄信者給旗標與 body `queue_wait_ms`，預設值不變（aos-agent ctl 30 秒、人殼看認領 3 秒等，`--timeout-s` 可改）；aos-daemon-ctl 一律直寄 daemon、不帶 `queue_wait_ms`。
  - **例外一：poke**——「其他人不碰 pid」的例外之一是 [`aos-daemon-ctl poke`](../../../../cmd/docs/03-aos-daemon-ctl.md)：門鈴，不帶內容、不判死活，只叫 daemon 立刻看一次檔（指令照舊寫 ctl.json／procs_ctl.json／信箱）。寄件人讀 daemon 自己 state 的 `pid`、`started_at_ticks`、`boot_id` 與穩定欄 `poke`（宣告三個訊號號碼；沒這欄＝`PokeFailed`），先開 pidfd、三欄都對上 `/proc/<pid>/stat` 的 starttime 與 `/proc/sys/kernel/random/boot_id` 才用 pidfd 送；對不上或行程不在報 `DaemonMissing`；跨帳號／沙箱送不出去（EPERM 等）報 `PokeFailed`、不改走別的路。pid 被別的程式重用的殘餘風險由使用者承擔——使用者 11-09：「pid被別的程式重用...這是使用者自己要承擔的風險，但我們確實也會做一些護欄，就是你說的這些。」送得出去不代表 daemon 活著、叫得動，**不拿送不送得出去來判死活，也不縮短任何逾時**；判死活照上一點。只有 aos-daemon 與這支指令懂訊號，proc 與其他 aos 程式只寫檔（[thinking daemon-interrupt](../../../../thinking/2026-11/09/daemon-interrupt/README.md)）。aos-daemon-ctl shutdown 照同一套核 pid 再寫 daemon 自己的 ctl。
  - **例外二：清道夫**（`aos-sweeper` 一輪、`aos-daemon-ctl sweep`；[thinking sweeper](../../../../thinking/2026-11/10/sweeper/README.md)）是 daemon 底下的一列 proc，卻會讀 `/proc`、送訊號，範圍只有一類：這台 daemon 自己活著（照 poke 的核法）、預設小格 `D/procs/<名>/` 不在表上、它自己的 state 窗 pid＋`started_at_ticks`＋`boot_id`（必須有、等於本機這次開機）對得上 `/proc`、`/proc/<pid>/environ` 的 `AOS_STACK`＝這格且 `AOS_DAEMON`＝這台、活了 60 秒以上。先寫它的 ctl stop（只寫檔，不算例外），之後的輪、離寫 stop 超過寬限還是同一支，才用 pidfd 核身分後 SIGTERM 它的行程群與底下自成一群的、10 秒後 SIGKILL。daemon 不在＝一個行程都不碰；zombie、別帳號（EPERM）、環境對不上、別次開機或別台寫的窗只報。使用者 11-10「也會看到那些殭屍行程，會幫忙清掉」、題 2 選 A「只收有十足把握的那類」。不拿這套判死活給別人用。
