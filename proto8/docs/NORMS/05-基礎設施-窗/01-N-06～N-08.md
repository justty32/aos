## 控制：ctl 與 state

- **N-06** 控制一個會反覆跑的東西（loop、daemon）＝改它的 ctl.json。ctl.json 寫的是「我要它現在怎樣」，不是一條條指令：整份就是全部的期望，寫幾次都一樣；沒寫的欄位＝回它起來時那份檔（loop.json／daemon.json）的初始值，不是維持上一版；讀的人只讀不寫；誰都可以寫，後寫的算。（10-12）旗子通用：任何開了 ctl 窗的程式都認 `paused`／`stopped`（[thinking](../../../thinking/2026-10/23/naming-method/README.md)）；`max` 等節奏 key 只有反覆跑的程式認（10-14 下午；節奏 key 用 loop.json 的 `max`，10-19 晚使用者定，[ideas § 22](../../../thinking/2026-10/19/ideas/README.md)）。daemon 的 ctl 可以只寫變動的名單（`loops_added`／`loops_removed`，10-23 晚使用者選「維持宣告式，但可以只寫變動的」）——仍是宣告：期望表只由這一份 ctl 與 daemon.json 算出來，拿掉那兩個 key 就回 daemon.json 的名單（[N-54](../04-基礎設施-loop與daemon/03-N-54.md)；10-29 起名單這幾個 key 搬到管轄手把 `loops_ctl.json`，見 N-54）。
  - **11-03 改口：loop 這一系控制自身的 ctl.json 改成一道指令**（使用者 11-03「還是用指令吧，不然大家不好理解。但是loop就不要用mailbox那套，就是誰能寫ctl.json就能控制。」；[thinking 11-03 ctl-commands](../../../thinking/2026-11/03/ctl-commands/README.md) § 1～2、§ 4）：上面前半（寫的是期望、不是指令；整份就是全部的期望；沒寫的欄位回初始值）改讀成：ctl.json＝**一個 JSON 物件＝一道指令**——`cmd`（`pause`／`resume`／`stop`）、`max`／`interval_ms`（寫了才動、`null`＝回設定檔的值、沒寫＝不動）、`seq`（回音，並供首次讀取時與舊 state 去重（代定（11-07 落實時，可翻案）））。**新舊比內容**：跟上一次讀到的不一樣才算新指令、照做一次，一樣＝不重做。loop 起來首次讀 ctl，比對上一份 state.json 的 `ctl_seq`：兩邊都是有效數字 seq 且相同＝已做、不重做；不同、舊 state 不存在或缺欄＝照一般指令做並更新 `responded_at` 回音（代定（11-07 落實時，可翻案）），因此未做過的舊 pause／stop 也會立即生效。（11-07 使用者裁定 sol 審查 #15-2）**後寫的蓋前寫的，被蓋的就沒了**；不用信箱那套。「讀的人只讀不寫」「誰都可以寫，後寫的算」照舊（loop 不刪、不改 ctl.json）。暫停中記在 loop 自己的 state（`paused`／`phase`）；起來時自己舊的 state.json `paused` 是 true 就先暫停（代定）。**daemon 管別人的 `procs_ctl.json` 照舊是宣告的名單**（[N-54](../04-基礎設施-loop與daemon/03-N-54.md) 的 11-03 改口）。
  - **11-03 名詞表**（使用者 11-03「名詞表我們先設計好，實際狀況中可能是同一種狀況能符合多個名詞，那就挑一個統一用這塊就好。不過實際狀況各有不同，至少我們現在遇到的是這樣。pause-paused,resume-running」；[thinking 11-03 procs § 0](../../../thinking/2026-11/03/procs/03-規劃-fable-照原則定的細節-可翻案.md#0-名詞表代定)，代定）：動作 `add`／`rm`／`start`／`stop`／`pause`／`resume`，帶到的狀態 `running`／`paused`／`stopped`（＋proc 自己走到的 `waiting`、`done`）。ctl 的動作字就是動作欄的 `pause`／`resume`／`stop`；aos-loop state 的五個 `phase`（`running`、`waiting`、`paused`、`done`、`stopped`）不改字。
    - **11-06 註**：使用者 11-03「還記得嗎？我們有start/stop, sleep/wake, pause/resume，我們缺了sleep/wake」；動作除 `add`／`rm` 外，三對是 `start`／`stop`（停到 `stopped`）、`sleep`／`wake`（睡到 `sleeping`）、`pause`／`resume`（`paused`／`running`）。11-05「sleep/wake就開放吧」，已開放成指令（[11-03 原話與 11-05 補註](../../../thinking/2026-11/03/procs/10-實作時代定-11-03-實作者照原則定的.md)）。
- **N-07** ctl.json 認兩個旗子——`paused`（不再起新的一次）、`stopped`（這次跑完就結束）——只收布林；`stopped` 壓過 `paused`。要當場收掉正在跑的那次＝對它送訊號（10-28 改口：送什麼訊號、怎麼收照 Unix 慣例，訊號不是 aos 標準，使用者 10-28「照你的建議，留著改口，JSONL 那半條刪掉」，[thinking 10-28 medium](../../../thinking/2026-10/28/medium/README.md)）。加上能蓋過 loop.json 外層執行方式的那幾個 key（`max`、`interval_ms`）。不認的 key 照 N-04。這兩個旗子不限 loop／daemon，開了 ctl 窗的程式都認；`max`、`interval_ms` 只有反覆跑的程式認（10-14 下午）。（10-12）
  - **10-29 補：daemon 的 `paused`＝整圈暫停**（使用者 10-29「都照建議」，[thinking 10-29 medium-plan](../../../thinking/2026-10/29/medium-plan/README.md) § 四 2、條文草稿）：不起自己的 `exec`、也不調表（名單的變動等解除暫停那圈才生效）；照寫 state、照讀 ctl、照收已送 SIGTERM 的子項。daemon 的「一次」就是調整管轄的那一圈（[10-28 medium](../../../thinking/2026-10/28/medium/README.md) 決定 2），暫停 loop 面向＝暫停那一圈。兩個手把見 [N-54](../04-基礎設施-loop與daemon/03-N-54.md) 的 10-29 改口。
  - **11-03 改口：兩個旗子改成 `cmd` 的三個動詞**（原文見 N-06 的 11-03 改口；[thinking 11-03 ctl-commands](../../../thinking/2026-11/03/ctl-commands/README.md) § 1、§ 3）：`paused`／`stopped` 兩個布林改成 `cmd`＝`pause`（這次跑完不起下一次）／`resume`（解除暫停）／`stop`（這次跑完退 0、phase `stopped`）；三個都冪等（已在那個狀態＝不動）。`max`／`interval_ms` 改成寫了才動、`null` 回初始、沒寫不動；`max` 改到比 `counter_runs` 小＝這次跑完 `done`。`stop` 壓過同一道裡的其他東西照舊；當場收掉照舊送訊號。10-29 補的 daemon「`paused`＝整圈暫停」照舊，字換成 `{"cmd": "pause"}`。名詞表（N-06 的 11-03）：子項的暫停是子 loop 自己的 ctl（aos-daemon-ctl `pause` 直接寫它）；stop 是 daemon 的手把 `procs_stopped`＋daemon 替子 loop 寫的 `{"cmd": "stop"}`（[procs § 2c](../../../thinking/2026-11/03/procs/05-2c-起-停-暫停-代定.md#2c-起停暫停代定)），兩層各管各的。
- **N-08** 讀 ctl.json 的人定期看；讀到壞的、型別不對、檔不見了，整份不採用、維持上一次的好狀態、不退出，原因記進自己 state 窗的 `ctl_warning`（讀到好的就清掉），不寫 stderr（照 N-43 正常退出不寫 stderr，使用者「都按照推薦。」，[盤點](../../../thinking/2026-10/15/principles/README.md) S1；欄位名見 [thinking](../../../thinking/2026-10/23/naming-method/README.md)）。ctl 裡的指示詞解不開（環境變數沒設、`$ref` 讀不到、指不到、繞圈）也算讀到壞的，照本條整份不採用（[N-45](../06-基礎設施-命令列與指示詞.md)；設定檔解不開則是程式自己的錯、退 1）。（10-12）
  - **11-03 加註**（[thinking 11-03 ctl-commands](../../../thinking/2026-11/03/ctl-commands/README.md) § 1）：ctl 改成指令後，整份不採用的多一種——`cmd` 不認得（不是 `pause`／`resume`／`stop`）；其餘一字不改。

**首次讀取的去重限制**：未開 state 窗、舊 state 缺有效 `ctl_seq`（含 `null`），或新 ctl 沒給 `seq`，都無法判已做，首次照一般指令處理並回音；新 ctl 的 `seq` 若為 `null` 則仍屬型別不合，照 N-08 整份不採用。（11-07 使用者裁定 sol 審查 #15-2）
