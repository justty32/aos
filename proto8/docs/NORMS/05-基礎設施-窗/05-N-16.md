- **N-16**（10-14 定；10-29 定案；使用者 10-28「通常會有一個資料夾，大家就將請求投遞過去」、10-29「窗可以跟投遞並列」，看完衝突與方向題回「都照建議」，[thinking 10-29 medium-plan](../../../thinking/2026-10/29/medium-plan/README.md) § 二、§ 三、決定 1～3、8、9、條文草稿；[10-28 medium](../../../thinking/2026-10/28/medium/README.md) 決定 4、7、9、18、19、21、22、25、27；11-04 aos-post 改版：使用者 11-03 晚看完 aos-post 的用法、環境變數、佈局、json 後提的想法，頂層讀不準的六點附建議，使用者「都照建議。in_reply_to那個是我誤會了，按照你的來。」，三題衝突與方向題使用者 11-03 晚「aos-post這塊都按照建議。」，[thinking 11-03 aos-post](../../../thinking/2026-11/03/aos-post/README.md) 決定 1～8、規劃 § 1～6；照實作寫，[impls/aos-post](../../../impls/aos-post/README.md)）信箱：資料夾式（Maildir：tmp／new／cur，認領靠改名）＝一封封信；信箱是**投遞**用的，不是窗（N-14）。檔案串流（JSONL 追加檔）不寫進 aos 標準、要用由 proc 自己定（使用者 10-28「照你的建議，留著改口，JSONL 那半條刪掉」，[thinking 10-28 medium](../../../thinking/2026-10/28/medium/README.md)）。**aos-post＝IPC 的語法糖、基底工具**，跟 aos proc 的關聯不深，proc 自己拿它組出想要的效果。
  - **信箱**＝一個資料夾，底下 `tmp/`、`new/`、`cur/`，歸檔格 **`archive/`** 選用（處理者想留紀錄才有，`done --keep` 才建），各格在同一個檔案系統。`send` 時檢查 `tmp/`、`new/` 是資料夾而且對自己可寫（不過＝`MailboxBad`），`cur/` 由認領的人發現沒有就建。**位置由擁有者定、不強制在 `$AOS_STACK`**（衝突 1）；別人靠 hub 型變數（[N-63](../10-基礎設施-定義與工作區.md)，例 `AOS_KERNEL`）或叫它時明給找到。
  - **一封信**＝一個資料夾，名字叫**信件名稱**（避開 signal）。`send` 可以自己給（不空、不含 `/`、不以 `.` 開頭，而且不得像有序名 `^[0-9]{12}\.`；撞名＝`LetterExists`，C-54 的 11-04 加註）；不給＝自動生成 `<UTC 奈秒 20 位>.<pid>.<started_at_ticks>`（只保證同機不撞名，撞名換一個）。必有 `letter.json`：`sender`（寄信人身分＝路徑：`AOS_WS` ＞ `AOS_STACK` ＞ `AOS_CF` ＞ cwd，空字串算沒設、相對的照 cwd 轉絕對；程式與人同一條，決定 9；N-15 ③）、`sent_at`（ISO 8601 UTC 到毫秒）、`body`（形狀由收信程式定，信封不管內容）；選填 `reply_to`（要回信就寫一個信箱的路徑，照 `send` 的驗法驗；回信也是一封信；沒寫＝不回）、`in_reply_to`（回信時寫原信的信件名稱，不是資料夾，不驗那封還在不在）（決定 8）。信封不帶 `kind`；不認得的 key 忽略（C-48，舊信帶著 `kind` 也是）；其他檔隨意。
  - **動詞**：**寄**（`send`）＝`mkdir tmp/<信件名稱>` → 在裡面寫 → `rename` 進 `new/`；**認領**（`take`、`take-all`）＝`rename` 進 `cur/`，成功的那個人才算；**讀**（`see`）；**撤回**（`regret`）＝`rename` 回 `tmp/` 再刪，進了 `cur/` 就撤不了，名稱必給；**處理完**（`done`）預設刪（先 rename 回 `tmp/` 再刪）、要留紀錄就 rename 進 `archive/`；有 `reply_to` 的，把回信（`in_reply_to` 填原信件名稱）照同一套投進去。`see`、`done` 可不給信件名稱＝`cur/` 裡照處理順序排第一的那封。舊動詞名（`claim`、`claim-all`、`check`、`finish`、`withdraw`）不認、不留相容。
  - **壞信**（`letter.json` 不是 JSON、缺必填、`body` 不合收信程式的形狀）丟掉、原因記自己 state 的 `mailbox_warning`，不通知寄信人（10-28 決定 27）；名字不是有序的不算壞信。欄名叫 `mailbox_warning`（使用者 11-02 晚「letter_warning改成mailbox_warning」；頂層問「要不要統一成 mailbox_warning？」，使用者「要」，[thinking 11-02 state 窗](../../../thinking/2026-11/02/state-window/01-使用者原文-11-02-逐字.md#通稱統一-mailbox_warning11-02-晚使用者)），舊名 `letter_warning` 不留別名、不讀舊檔名。aos agent 的 queue 處理者（aos-eca-turn、demo agent-fsm 的 idle 格）記在 `$AOS_STACK/mailbox_warning.txt`——它的 state 窗是 aos-loop 的、一個窗一個寫者（N-09），所以另放一個同名的檔（[aos-round 實作時代定](../../../thinking/2026-10/30/aos-round/07-決定.md#實作時代定10-30隊長與工人照原則定的細節可翻案)；aos-round 已刪，使用者 11-01 晚「aos round這東西還沒刪掉嗎」「這應該整個都不需要吧」，看完牽連範圍回「刪掉」，[thinking 11-01 playground-bob 03](../../../thinking/2026-11/01/playground-bob/03-旋鈕改-argv-與檔-實作.md)）。一個信箱預設一個處理者；`tmp/` 殘骸處理者不碰。
  - **有順序的投遞**（使用者 10-28「另外設置一個檔案或資料夾，有鎖的，大家要投遞就去取鎖，取得順序」）：信箱多 `order.lock/`（N-15 的鎖）與 `order.json`（`{"counter_letters": N}`）；寄信人先照上面在 `tmp/` 寫好信 → 拿鎖 → 讀 N（沒有 `order.json`＝0）→ `order.json` 先寫 N+1（N-05）→ rename 進 `new/<N+1 零填 12 位>.<尾名>` → 放鎖。鎖握到 rename 完，所以到達 `new/` 的順序＝取號順序。**先寫計數再 rename**：死在兩步之間只會缺一個號、不會有兩封同號（使用者 10-29「都按照建議」照實作，[medium-plan 實作時代定](../../../thinking/2026-10/29/medium-plan/07-實作時代定.md#實作時代定10-29隊長與工人照原則定的細節可翻案) 第 10 條）。
  - **有序、無序同箱**：`send` 帶不帶 `--ordered` 都收。處理順序（`take`、`take-all`、`see`／`done` 的預設都用同一套）：有序的全部在前、照序號；無序的在後、照名字（預設名時間開頭＝寄出先後）；無序的被有序的一直插隊也接受。有序缺號不等、直接拿下一號，照名字排好從頭拿、不逐號探（使用者「有序的人缺號時，我怕下一個號碼是幾百號之後，實作的時候要小心，不要每號都確認。」）。
  - **queue**（使用者 10-30「這一層更接近訊息的queue概念，請求的投遞倒是可以用信箱概念，但也可以用queue概念」、看完規劃回「都照建議」，[10-29 agent-bob](../../../thinking/2026-10/29/agent-bob/04-頂層對八題的再想.md#決定10-30) 決定 33、36，[thinking 10-30 agent-lifecycle](../../../thinking/2026-10/30/agent-lifecycle/07-衝突.md#決定10-30) 條文草稿、A-1、A-10）：agent 層把自己的輸入叫 **queue**，它就是本條的有順序投遞（同箱也收無序的，照上面排在後面），資料夾叫 `queue/`、位置在那隻 agent 的 `$AOS_STACK`（[CONVENTION P-11、P-42](../../CONVENTION/02-題目stack停錯腦.md)）；「信箱」這個詞留給 agent 之間的請求投遞（一封封獨立的信，可能要回信、可以不照順序）。
  - **aos-llm-kernel 自己的信箱**（[aos-llm-kernel](../../../impls/aos-llm-kernel/README.md)、[aos-llm](../../../impls/aos-llm/README.md)，[thinking 2026-10-24-llm-kernel](../../../thinking/2026-10/24/llm-kernel/README.md)；衝突 3；方向題 3，等 kernel 下一次大改再一起收）：位置是 kernel 自己選的（kernel.json 的 `mailbox`），寄信的人由 `AOS_KERNEL` 得知；kernel 用 flock 鎖整個信箱；歸檔格照舊叫 `done/`，`done/`＋`reply.json` 是它自己的回信方式（10-28 決定 9 允許）、當 kernel 的紀錄、也給沒寫 `reply_to` 的信；它 flock 用的檔見 N-15「名字分清」。請求信由 `aos-llm` 寄：body＝`{"endpoint"?, "request", "priority"?}`，信封 `reply_to` 必有——`aos-llm send --reply-to BOX` 寫寄信人自己的信箱（非同步），`aos-llm ask` 寫 `<kernel 的信箱>/reply/`（同步、共用，靠 `in_reply_to` 認自己的）；kernel 照本條寄回信（`in_reply_to`＝原信件名稱、`body`＝`{"message", "usage", "model"}` 或 `{"error"}`，`done/<信>/reply.json` 留同一份）（[medium-plan](../../../thinking/2026-10/29/medium-plan/README.md) 實作第 6 步後半、決定 3；[實作時代定](../../../thinking/2026-10/29/medium-plan/07-實作時代定.md#實作時代定10-29隊長與工人照原則定的細節可翻案) 第 14 條；N-42 (1)）。**11-04 晚已改**（使用者 11-04 晚「llm呼叫這塊，我希望是把請求丟到llm kernel(一個loop)，處理好後收回信」「然後aos llm,tool這兩個，我希望他們的定位是跟aos post一樣，作為基礎工具」，[thinking 11-04 think-as-function](../../../thinking/2026-11/04/think-as-function/README.md)；細節 fable 代定、可翻案）：原本閘門 aos-llm-send 寄的信帶單子與整份環境（`inst`／`env`／`priority` 過渡期在頂層、沒包進 `body`），回信 `body`＝`{"code","signal"}`、stdout／stderr 附在信裡，閘門從 `<kernel 的信箱>/reply/` 拿；現在 aos-llm-send 改名 `aos-llm`，信只帶請求、全部在 `body`，頂層 `inst`／`env` 的舊信＝`LetterBad`。題目信箱（[CONVENTION P-11](../../CONVENTION/02-題目stack停錯腦/01-P-11～P-14.md)）不算標準投遞（衝突 2）。**11-04 夜再改**（使用者「很多都是自己要承擔的風險。舊信根本不用留，就是刪」，[think-as-function 08 題 3](../../../thinking/2026-11/04/think-as-function/08-邊緣狀況實測.md#留給你的題白話推薦放第一)）：kernel 不再有 `done/`，信寄完回信就整封刪掉（沒寫 `reply_to`、回信寄不進＝回信沒人收，信照刪）；上面「歸檔格照舊叫 `done/`」「`done/<信>/reply.json` 留同一份」作廢。**11-05 再改**（使用者選「也刪」）：每封一行的 `served.jsonl` 也不寫了，kernel 不留任何一封的紀錄。
