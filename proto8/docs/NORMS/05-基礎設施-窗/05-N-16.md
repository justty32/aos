- **N-16**（10-14 定；10-29 改口＋補、已定，見本條下的 10-29 改口）信箱：資料夾式（Maildir：tmp／new／cur，認領靠改名）＝一封封信。（10-14；原本還收「JSONL 追加檔＝一條流」，沒有實作、也沒人依賴，10-28 刪掉——檔案串流不寫進 aos 標準、要用由 proc 自己定，使用者 10-28「照你的建議，留著改口，JSONL 那半條刪掉」，[thinking 10-28 medium](../../../thinking/2026-10/28/medium.md)）資料夾式的實作是 LLM kernel 的信箱（[aos-llm-kernel](../../../impls/aos-llm-kernel/README.md)、[aos-llm-send](../../../impls/aos-llm-send/README.md)，[thinking 2026-10-24-llm-kernel](../../../thinking/2026-10/24/llm-kernel/README.md)）：`tmp/`、`new/`、`cur/` 照這條，另加 `done/` 放回信；一封信一個資料夾、認領與撤信都靠改名、kernel 用 flock 鎖整個信箱（N-14 三招）；位置照 N-14 落在 kernel 的 `$AOS_STACK` 底下（kernel.json 的 `mailbox`），寄信的人由 `AOS_KERNEL` 得知。
  - **10-29 改口＋補：投遞與信箱**（使用者 10-28「通常會有一個資料夾，大家就將請求投遞過去」、10-29「窗可以跟投遞並列」；看完衝突與方向題回「都照建議」，[thinking 10-29 medium-plan](../../../thinking/2026-10/29/medium-plan/README.md) § 二、§ 三、決定 1～3、8、9、條文草稿；[10-28 medium](../../../thinking/2026-10/28/medium.md) 決定 4、7、9、18、19、21、22、25、27）：信箱是**投遞**用的，不是窗（N-14 的 10-29 改口）。
    - **信箱**＝一個資料夾，四格 `tmp/`、`new/`、`cur/`（`done/` 選用，處理者想留紀錄才有），四格在同一個檔案系統。**位置由擁有者定、不強制在 `$AOS_STACK`**（衝突 1；上面「位置照 N-14 落在 kernel 的 `$AOS_STACK` 底下」改讀成 kernel 自己的選擇）；別人靠 hub 型變數（[N-63](../10-基礎設施-定義與工作區.md)，例 `AOS_KERNEL`）或叫它時明給找到。
    - **一封信**＝一個資料夾，名字叫信號 `<UTC 奈秒 20 位>.<pid>.<started_at_ticks>`（只保證同機不撞名，按名字排序不保證順序）；必有 `letter.json`：`kind: "letter"`、`sender`（寄信人身分＝路徑：`$AOS_WS`，沒設才 `~/`，程式與人同一條，決定 9）、`sent_at`（ISO 8601 UTC 到毫秒）、`body`（形狀由收信程式定，信封不管內容）；選填 `reply_to`（要回信就寫一個信箱的路徑，回信也是一封信；沒寫＝不回）、`in_reply_to`（回信時寫原信的信號）（決定 8）。不認得的 key 忽略（C-48）；其他檔隨意。
    - **寄**＝`mkdir tmp/<信號>`（撞名換一個）→ 在裡面寫 → `rename` 進 `new/`；**認領**＝`rename` 進 `cur/`，成功的那個人才算；**撤回**＝`rename` 回 `tmp/` 再刪，進了 `cur/` 就撤不了；**處理完**預設刪（先 rename 回 `tmp/` 再刪）、要留紀錄就 rename 進 `done/`；有 `reply_to` 的，把回信（`in_reply_to` 填原信號）照同一套投進去。
    - **壞信**（`letter.json` 不是 JSON、缺必填、`body` 不合收信程式的形狀）丟掉、原因記自己 state 的 `mailbox_warning`（11-02 晚改名，原 `letter_warning`；使用者「要」），不通知寄信人（10-28 決定 27）。（10-30 實作：aos agent 的 queue 記在 `$AOS_STACK/mailbox_warning.txt`（11-02 晚原 `letter_warning.txt`）——它的 state 窗是 aos-loop 的、一個窗一個寫者（N-09），所以另放一個同名的檔；eca 的 turn 記在 trace 那行，P-43〔11-03 起改記 `$AOS_STACK/mailbox_warning.txt`、同 queue 格〕；[aos-round 實作時代定](../../../thinking/2026-10/30/aos-round/07-決定.md#實作時代定10-30隊長與工人照原則定的細節可翻案)。）一個信箱預設一個處理者；`tmp/` 殘骸處理者不碰。 **11-01 加註**（使用者 11-01 晚「aos round這東西還沒刪掉嗎」「這應該整個都不需要吧」，看完牽連範圍回「刪掉」，[thinking 11-01 playground-bob 03](../../../thinking/2026-11/01/playground-bob/03-旋鈕改-argv-與檔-實作.md)）：`aos-round` 已刪；agent 的 loop.json 直接叫 `aos-fsm`、指 lib/agent/round 的 `fsm-stop.json` 或 `fsm-idle.json`（stop／idle＝指哪張表，`--on-empty` 跟著沒了），五格從 `AOS_CD` 拿 agent 資料夾（`AOS_ROUND_AGENT` 拿掉）。本條提到 aos-round 的地方照這個讀，條文改不改由使用者定。 **11-02 加註**（使用者 11-02 晚「letter_warning改成mailbox_warning」，[thinking 11-02 state 窗](../../../thinking/2026-11/02/state-window.md#決定11-02-晚使用者實作中陸續裁的)）：aos-daemon 的 `loops_state.json` 這一欄改叫 `mailbox_warning`。**11-02 晚再改**（頂層問「要不要統一成 mailbox_warning？」，使用者「要」，[thinking 11-02 state 窗](../../../thinking/2026-11/02/state-window.md#通稱統一-mailbox_warning11-02-晚使用者)）：本條通稱改 `mailbox_warning`，agent queue 的 `.txt`、aos-eca-turn trace 那欄跟著改；舊名不留別名、不讀舊檔名。
    - **有順序的投遞**（使用者 10-28「另外設置一個檔案或資料夾，有鎖的，大家要投遞就去取鎖，取得順序」）：信箱多 `order.lock/`（N-15 的鎖）與 `order.json`（`{"counter_letters": N}`）；寄信人先照上面在 `tmp/` 寫好信 → 拿鎖 → 讀 N（沒有 `order.json`＝0）→ `order.json` 先寫 N+1（N-05）→ rename 進 `new/<N+1 零填 12 位>.<信號>` → 放鎖。鎖握到 rename 完，所以到達 `new/` 的順序＝取號順序，處理者照名字排序就是有順序的。**先寫計數再 rename**：死在兩步之間只會缺一個號、不會有兩封同號（10-29 實作時對調，原寫先 rename 再寫計數；使用者 10-29「都按照建議」照實作改，[medium-plan 實作時代定](../../../thinking/2026-10/29/medium-plan/07-實作時代定.md#實作時代定10-29隊長與工人照原則定的細節可翻案) 第 10 條）。一個有序信箱只收有序的信。
    - **過渡**（衝突 3）：aos-llm-kernel 現行的回信（`done/`＋`reply.json`）是它自己的回信方式（10-28 決定 9 允許），過渡期照舊；它 flock 用的檔改名見 N-15 的 10-29 補。**10-30 實作補**（[medium-plan](../../../thinking/2026-10/29/medium-plan/README.md) 實作第 6 步後半、決定 3「有空再改」；[實作時代定](../../../thinking/2026-10/29/medium-plan/07-實作時代定.md#實作時代定10-29隊長與工人照原則定的細節可翻案) 第 14 條）：aos-llm-send 的信封寫 `reply_to`（回信信箱 `<kernel 的信箱>/reply/`），kernel 照本條寄回信（`in_reply_to`＝原信號、`body`＝原本 `reply.json` 那份、stdout／stderr 附在信裡），閘門從回信信箱拿；`done/`＋`reply.json` 留著當 kernel 的紀錄、也給沒寫 `reply_to` 的信。題目信箱（[CONVENTION P-11](../../CONVENTION/02-題目stack停錯腦.md)）不算標準投遞（衝突 2）。
  - **11-04 改口：aos-post 改版**（使用者 11-03 晚看完 aos-post 的用法、環境變數、佈局、json 後提的想法，頂層讀不準的六點附建議，使用者「都照建議。in_reply_to那個是我誤會了，按照你的來。」；三題衝突與方向題，使用者 11-03 晚「aos-post這塊都按照建議。」；[thinking 11-03 aos-post](../../../thinking/2026-11/03/aos-post.md) 決定 1～8、規劃 § 1～6；照實作寫，[impls/aos-post](../../../impls/aos-post/README.md)）：**aos-post＝IPC 的語法糖、基底工具**，跟 aos proc 的關聯不深，proc 自己拿它組出想要的效果。上面 10-29 改口那幾段照下面讀：
    - **用詞**：「信號」改叫**信件名稱**（避開 signal）。
    - **信箱**＝一個資料夾；`send` 時檢查 `tmp/`、`new/` 是資料夾而且對自己可寫（不過＝`MailboxBad`），`cur/` 由認領的人發現沒有就建。歸檔格 `done/` 改叫 **`archive/`**（避開 `done` 指令；`done --keep` 才建），上面「`done/` 選用」照 `archive/` 讀。aos-llm-kernel 自己信箱的 `done/` 不動（方向題 3，等 kernel 下一次大改再一起收），「過渡」那段照舊。
    - **動詞改名**：`claim`→`take`、`claim-all`→`take-all`、`check`→`see`、`finish`→`done`、`withdraw`→`regret`；舊名直接退場、不留相容。`see`、`done` 可不給信件名稱＝`cur/` 裡照處理順序排第一的那封；`regret` 的名稱必給。
    - **信件名稱可以自己給**：`send` 給了就用（不空、不含 `/`、不以 `.` 開頭，而且不得像有序名 `^[0-9]{12}\.`；撞名＝`LetterExists`，C-54 的 11-04 加註），不給＝照舊自動生成；上面「撞名換一個」只對自動生成的名字。
    - **信封**：拿掉 `kind`（舊信帶著也只是不認得的 key、忽略，C-48 的 11-03 加註）；`sender` 順序改成 `AOS_WS` ＞ `AOS_STACK` ＞ `AOS_CF` ＞ cwd（拿掉 `HOME`；N-15 的 11-04 加註）；`reply_to`＝一個信箱，照 `send` 的驗法驗；`in_reply_to`＝原信的信件名稱（不是資料夾，不驗那封還在不在）。名字不是有序的不再算壞信。
    - **有序、無序同箱**：上面「一個有序信箱只收有序的信」不再成立，`send` 帶不帶 `--ordered` 都收。處理順序（`take`、`take-all`、`see`／`done` 的預設都用同一套）：有序的全部在前、照序號；無序的在後、照名字（預設名時間開頭＝寄出先後）；無序的被有序的一直插隊也接受。有序缺號不等、直接拿下一號，照名字排好從頭拿、不逐號探（使用者「有序的人缺號時，我怕下一個號碼是幾百號之後，實作的時候要小心，不要每號都確認。」）。
  - **10-30 加註：queue**（使用者 10-30「這一層更接近訊息的queue概念，請求的投遞倒是可以用信箱概念，但也可以用queue概念」、看完規劃回「都照建議」，[10-29 agent-bob](../../../thinking/2026-10/29/agent-bob/04-頂層對八題的再想.md#決定10-30) 決定 33、36，[thinking 10-30 agent-lifecycle](../../../thinking/2026-10/30/agent-lifecycle/07-衝突.md#決定10-30) 條文草稿、A-1、A-10）：agent 層把自己的輸入叫 **queue**，它就是本條的有順序投遞，資料夾叫 `queue/`、位置在那隻 agent 的 `$AOS_STACK`（[CONVENTION P-11 的 10-30 改口、P-42](../../CONVENTION/02-題目stack停錯腦.md)）；「信箱」這個詞留給 agent 之間的請求投遞（一封封獨立的信，可能要回信、可以不照順序）。本條內容不變。
