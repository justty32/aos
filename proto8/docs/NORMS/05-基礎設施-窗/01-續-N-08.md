- **N-08** 讀 ctl.json 的人定期看；讀到壞的、型別不對、檔不見了，整份不採用、維持上一次的好狀態、不退出，原因記進自己 state 窗的 `ctl_warning`（讀到好的就清掉），不寫 stderr（照 N-43 正常退出不寫 stderr，使用者「都按照推薦。」，[盤點](../../../thinking/2026-10/15/principles/README.md) S1；欄位名見 [thinking](../../../thinking/2026-10/23/naming-method/README.md)）。ctl 裡的指示詞解不開（環境變數沒設、`$ref` 讀不到、指不到、繞圈）也算讀到壞的，照本條整份不採用（[N-45](../06-基礎設施-命令列與指示詞.md)；設定檔解不開則是程式自己的錯、退 1）。（10-12）
  - **11-03 加註**（[thinking 11-03 ctl-commands](../../../thinking/2026-11/03/ctl-commands/README.md) § 1）：ctl 改成指令後，整份不採用的多一種——`cmd` 不認得（不是 `pause`／`resume`／`stop`）；其餘一字不改。

**首次讀取的去重限制**：未開 state 窗、舊 state 缺有效 `ctl_seq`（含 `null`），或新 ctl 沒給 `seq`，都無法判已做，首次照一般指令處理並回音；新 ctl 的 `seq` 若為 `null` 則仍屬型別不合，照 N-08 整份不採用。（11-07 使用者裁定 sol 審查 #15-2）
