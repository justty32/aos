- **N-16**（使用者 10-28「通常會有一個資料夾，大家就將請求投遞過去」、10-29「窗可以跟投遞並列」，看完衝突與方向題回「都照建議」，[thinking 10-29 medium-plan](../../../../thinking/2026-10/29/medium-plan/README.md) § 二、§ 三、決定 1～3、8、9、條文草稿；[10-28 medium](../../../../thinking/2026-10/28/medium/README.md) 決定 4、7、9、18、19、21、22、25、27；aos-post 的用法、環境變數、佈局、json：使用者 11-03 晚「都照建議。in_reply_to那個是我誤會了，按照你的來。」，三題衝突與方向題「aos-post這塊都按照建議。」，[thinking 11-03 aos-post](../../../../thinking/2026-11/03/aos-post/README.md) 決定 1～8、規劃 § 1～6；照實作寫，[cpp/aos-post](../../../../cpp/aos-post/README.md)）信箱：資料夾式（Maildir：tmp／new／cur，認領靠改名）＝一封封信；信箱是**投遞**用的，不是窗（N-14）。檔案串流（JSONL 追加檔）不寫進 aos 標準、要用由 proc 自己定（使用者 10-28「照你的建議，留著改口，JSONL 那半條刪掉」，[thinking 10-28 medium](../../../../thinking/2026-10/28/medium/README.md)）。**aos-post＝IPC 的語法糖、基底工具**，跟 aos proc 的關聯不深，proc 自己拿它組出想要的效果。
  - **信箱**＝一個資料夾，底下 `tmp/`、`new/`、`cur/`，歸檔格 **`archive/`** 選用（處理者想留紀錄才有，`done --keep` 才建），各格在同一個檔案系統；不改成全部放一個資料夾、用 rename 標狀態（使用者比較後裁「不換」，[aos-post-one-dir](../../../../thinking/2026-11/04/aos-post-one-dir.md)）。`send` 時檢查 `tmp/`、`new/` 是資料夾而且對自己可寫（不過＝`MailboxBad`），`cur/` 由認領的人發現沒有就建。**位置由擁有者定、不強制在 `$AOS_STACK`**（衝突 1）；別人靠 hub 型變數（[N-63](../../10-基礎設施-定義與工作區.md)，例 `AOS_LLM_KERNEL`）或叫它時明給找到。`archive/` 會跟著 image 搬家，見 N-67（[../10-基礎設施-定義與工作區/09-續-N-67.md](../../10-基礎設施-定義與工作區/09-續-N-67.md)）⑩（使用者裁定，出處 [wf/workflows/refactor/reports/2026-11-07-sol審查/11-使用者裁定.md](../../../../../wf/workflows/refactor/reports/2026-11-07-sol審查/11-使用者裁定.md) #20-2）。
  - **一封信**＝一個資料夾，名字叫**信件名稱**（避開 signal）。`send` 可以自己給（不空、不含 `/`、不以 `.` 開頭，而且不得像有序名 `^[0-9]{12}\.`；撞名＝`LetterExists`，C-54）；不給＝自動生成 `<UTC 奈秒 20 位>.<pid>.<started_at_ticks>`（只保證同機不撞名，撞名換一個）。必有 `letter.json`：`sender`（寄信人身分＝路徑：`AOS_WS` ＞ `AOS_STACK` ＞ `AOS_CF` ＞ cwd，空字串算沒設、相對的照 cwd 轉絕對；程式與人同一條，決定 9；N-15 ③）、`sent_at`（ISO 8601 UTC 到毫秒）、`body`（形狀由收信程式定，信封不管內容）；選填 `reply_to`（要回信就寫一個信箱的路徑，照 `send` 的驗法驗；回信也是一封信；沒寫＝不回）、`in_reply_to`（回信時寫原信的信件名稱，不是資料夾，不驗那封還在不在）（決定 8）。信封不帶 `kind`；不認得的 key 忽略（C-48）；其他檔隨意。
    - **三層分開**（使用者 11-05「信件是IPC手段，然後我們的"非同步呼叫aos函數"又是基於這個手段的。」、11-06「所以不要去與aos-post耦合太深。」，[fs-image](../../../../thinking/2026-11/05/fs-image/README.md)、[body-protocol 原文](../../../../thinking/2026-11/06/body-protocol/README.md)）：信封 `sender`、`sent_at`、`reply_to`、`in_reply_to` 與投遞＝IPC；非同步呼叫建在信上（[N-66](../08-N-66.md)）；body 的格式與處理歸定那個函數的人，aos-post 不看、不驗。
  - **動詞**：**寄**（`send`）＝`mkdir tmp/<信件名稱>` → 在裡面寫 → `rename` 進 `new/`；**認領**（`take`、`take-all`）＝`rename` 進 `cur/`，成功的那個人才算；**讀**（`see`）；**撤回**（`regret`）＝`rename` 回 `tmp/` 再刪，進了 `cur/` 就撤不了，名稱必給；**處理完**（`done`）預設刪（先 rename 回 `tmp/` 再刪）、要留紀錄就 rename 進 `archive/`；有 `reply_to` 的，把回信（`in_reply_to` 填原信件名稱）照同一套投進去。`see`、`done` 可不給信件名稱＝`cur/` 裡照處理順序排第一的那封。
  - **壞信**＝信封壞（`letter.json` 不是 JSON、缺必填）：丟掉、原因記自己 state_flux 的 `mailbox_warning`，不通知寄信人（10-28 決定 27）；名字不是有序的不算壞信。信封好但 body 不合收信程式的形狀是呼叫層的事，照 [N-66](../08-N-66.md)：有 `reply_to` 就回錯誤信（使用者 11-06「四題都按照推薦」，[body-protocol](../../../../thinking/2026-11/06/body-protocol/04-方向題與aos-post可改.md)）；llm kernel、判官、daemon ctl 信箱都已這樣做（daemon 回 `{"applied": false, "error": {"code": "BodyBad", …}}`，[N-28](../../04-基礎設施-loop與daemon/02-N-28.md)）（使用者 11-14 專區答「fixok:ok」，reply cee70afc742361ba）。N-16 只管信封與投遞。
    - 欄名叫 `mailbox_warning`（使用者 11-02 晚「letter_warning改成mailbox_warning」；頂層問「要不要統一成 mailbox_warning？」，使用者「要」，[thinking 11-02 state 窗](../../../../thinking/2026-11/02/state-window/01-使用者原文-11-02-逐字.md#通稱統一-mailbox_warning11-02-晚使用者)）。aos agent 的 queue 處理者（aos-eca-turn、templates/agents/agent-fsm 的 idle 格）記在 `$AOS_STACK/mailbox_warning.txt`——它的 state／state_flux 窗是 aos-loop 的、一個窗一個寫者（N-09），所以另放一個同名的檔（[aos-round 實作時代定](../../../../thinking/2026-10/30/aos-round/07-決定.md#實作時代定10-30隊長與工人照原則定的細節可翻案)）。一個信箱預設一個處理者；`tmp/` 殘骸處理者不碰。
