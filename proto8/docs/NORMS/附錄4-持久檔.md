## 持久檔與暫時檔

proto8 哪些檔與資料夾會跨版本長期活著（持久）、哪些用完就丟（暫時），各由誰寫、誰讀、進不進 image、壞了現在怎麼反應。以後要加格式版本（format-versioning 選項 B）或寫升級腳本，管的範圍就是標「持久」的列；改到這些檔的格式時要寫一句「要重建什麼」，見 [conventions 程式碼慣例](../../../wf/workflows/common/conventions.md#程式碼慣例)。

出處：format-versioning 種子 S1，使用者 11-09「剩下都OK」＝照推薦現在做（[format-versioning README「使用者 11-09 裁定」第 2 題](../../thinking/2026-11/09/format-versioning/README.md#使用者-11-09-裁定)、[03 S1](../../thinking/2026-11/09/format-versioning/03-正式版機制與種子.md)）。這張表只是盤點，不代表要做相容（11-05「proto8 當沒有舊版」）。

### 正式版與格式版本

- **什麼時候算正式版**：使用者親自主持的一次大型精心審查與大修（可能手寫程式碼）結束之後才轉正；資料活過改版、第二台機器之類不算轉正條件。使用者 11-09：「啥時候能算正式版：我之後會有一次大型的精心審查和大修，會放很多心力，甚至手寫程式碼，結束之後才能轉正。」（[format-versioning 裁定第 1 題](../../thinking/2026-11/09/format-versioning/README.md#使用者-11-09-裁定)）。轉正之前照「proto8 當沒有舊版」。
- **正式版當天起**（使用者 11-09「剩下都OK」＝照推薦，同上第 3 題與「建議」）：本表標「持久」的檔加 `format` 版本標記（一種持久檔一個 `format` 名；程式寫的狀態檔一定帶，人寫的配置檔可以不帶），沒標記或不對＝拒讀＋英文提示；之後要改持久格式，寫獨立的升級腳本（先備份），不在程式裡內建讀舊版；舊 key 照舊忽略（C-48），只靠版本標記擋。

### 欄位

- `path`：檔或資料夾的相對位置，用代號開頭（`$AOS_STACK/…`、`<定義資料夾>/…`、`<信箱>/…`）。
- `lifetime`：`持久`＝跨版本活著、丟了要重建；`暫時`＝寫到一半的暫存、只給人看的紀錄、醒來會重寫的。
- `writer`／`reader`：寫它、讀它的程式（grep 程式核對）；「人手寫」＝使用者自己編。
- `image`：進不進 git image（[C-79](../CONCEPTS/02-設計理念-時空.md)、[N-67 ⑩](10-基礎設施-定義與工作區/09-續-N-67.md)、`cmd/aos-agent/stack.gitignore`）。定義資料夾是原始碼、不算 image，所以定義類寫「看情況」。
- `on_bad`：檔不在、不是 JSON、形狀不對時，程式現在怎麼反應。
- `note`：備註（跟條文對不上、01 盤點沒列等）。
- `evidence`：出處，寫 `檔路徑（函式名、…）`，多個用 `、` 隔開；沒函式可指就只寫路徑。不寫行號（一改碼就失效）。
