N-54 接續（上一份的子項到這裡繼續）：

  - **起、停、暫停**（loop 的 ctl 改指令：使用者 11-03「還是用指令吧，不然大家不好理解。但是loop就不要用mailbox那套，就是誰能寫ctl.json就能控制。」，[11-03 ctl-commands](../../../../thinking/2026-11/03/ctl-commands/README.md) § 5）。**daemon 不分類**：任何列（不分 loop 型、exec 型，寫沒寫 `auto_restart`）都可 stop／start／sleep／wake（使用者 11-07：「等等，不過有個問題：argv:[aos-loop loop.json]，我用aos-exec執行，這等同於我變成了aos-loop，然後去跑loop.json設定。在變成loop之前，我確實就是一次性程式沒錯」，選 **B：daemon 不分類**，[arknights-kb 07](../../../../thinking/2026-11/07/arknights-kb/07-停不下與消失.md)）；`auto_restart` 只管自然結束後重起，與 stop／sleep 能否採用無關。
    - **stop**：daemon 往子項的公開 ctl 寫一道 `{"cmd": "stop", "seq": N}`——小格父寫的 loop 設定有非空 `ctl` 就用它，否則 `ctl.json`——然後等它自己退，不送 SIGTERM；寫不了只 warning、照等。子 loop 跑完這一次自己退 0；等的途中列是 `stopping`，退了**列留在表上**、`phase` `stopped`、stack 不碰。
    - **start**：用列上的 `stack` 再起，**不用先清 ctl**：首次讀 ctl 比對舊 `state_flux.json` 的 `ctl_seq`，兩邊都是有效數字 seq 且相同＝已做、不重做；不同、舊 state_flux 不存在或缺欄＝照一般指令做並以 `responded_at` 回音（代定、可翻案），未做過的 stop 會立即生效（sol 審查 #15-2 使用者裁定）；起來是跑還是暫停看它自己 state.json 的 `paused`（代定，ctl-commands § 4）。只有指令叫起：信來、手把別的 key 變、同名 `procs_added` 都不把 stopped 的拉起來。
    - **sleep 的 stopping 例外**（11-07 晚審第 3 題，使用者選 A）：`stopping` 的列也准許 sleep，改送 SIGTERM；stop 途中的列退後留 `stopped`，保留入口與 stack，之後用 start 再起。其他 sleep 仍留 `sleeping`、用 wake 醒。
    - **pause／resume、改節奏**不經 daemon：直接寫子 loop 的 `ctl.json`（誰都可以寫，N-06；[aos-daemon-ctl](../../../../py/docs/05-commands.md) 的 `pause`／`resume` 就是寫 `{"cmd": "pause"}`／`{"cmd": "resume"}`），要看它＝讀它的 state 窗；daemon 不轉述 paused（不讀子項的 state，C-52）。daemon 回報實際的表在 `procs_state.json`（N-28）。
    - **pause／resume 的 PhaseBad**：aos-daemon-ctl 對 `stopped`／`sleeping` 子項不准寫 pause／resume；理由是該狀態沒有正在讀 ctl 的執行個體，應先 start／wake，並非首次讀 ctl 不執行。（代定、可翻案）
    - **停掉要走 daemon**：掛在 daemon 下的子 loop，要停就走 daemon（上面的 stop）。繞過 daemon、自己往子 loop 的 ctl 寫 `{"cmd": "stop"}`：子項退了，從表上拿掉（N-28「子項結束後不自動重起；自然退 0 就下表」；＝對 daemon 不存在，叫不回）。（新舊打架，11-17「新的覆蓋舊的」：本條 11-03 較晚；N-10「暫停、停掉某個子 loop＝直接寫它的 ctl」現行見本條。）
  - **工作區不放子項的 stack**（使用者 11-03「那其實.stack根本不需要放到ws那邊」，看完四題建議回「那四題照建議，只是say/listen這塊之後還要再改。」；[thinking 11-03 stack-where](../../../../thinking/2026-11/03/stack-where.md)）：daemon 像硬體，子項的 stack 像 CPU 的暫存器、歸 daemon 管（`<daemon 的 AOS_STACK>/procs/<名字>/` 或列上的 `stack`），`ws`／`AOS_WS` 只是交給子項的一個位址。所以 aos-daemon-ctl 的 `add --ws` 不在 `<WS>/.stack` 建捷徑、`rm` 不拆；要找某個子項的 stack 用 `aos-daemon-ctl where --stack 名字`——**只認 daemon 表上的**（含 `stopped` 的列；使用者「一個proc在daemon中的狀態，包括運行中、暫停中，除此之外就是不存在於daemon了」「拿下名單後，對於daemon來說他就不存在了，自然找不到」），表上沒有＝`ProcMissing`。對它說話＝`aos-agent say --target 名字 …`（工具的事、不算規範；[aos-agent](../../../../py/aos/apps/agent/README.md)）。
