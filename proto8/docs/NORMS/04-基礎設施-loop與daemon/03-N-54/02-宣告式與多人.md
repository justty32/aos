N-54 接續（上一份的子項到這裡繼續）：

  - **宣告式，可以只寫變動的**（使用者 10-23「ctl這塊我會想要是"啓動XXX loop/刪除XXX loop"，而不是每次都讓他讀全部」；使用者選「維持宣告式，但可以只寫變動的」，[thinking 10-23 ctl 與 $ref](../../../../thinking/2026-10/23/daemon-ctl-ref/README.md)）：`procs_ctl.json` 是宣告的名單，不跟 loop 的 ctl 一起改成指令。`procs_added`＝名單上要多這些（寫法同 `procs`，要拆檔同 N-28 用 `$ref` 陣列）、`procs_removed`＝名單上要少這些（名字的陣列）；key 名照 C-54 R4「ctl 的 key 用狀態詞」（同 `stop` → `stopped`）。
    - **期望表＝（`procs_ctl` 的 `procs`，沒寫＝底的）＋`procs_added`－`procs_removed`**，先加後減：同一個名字兩邊都寫＝不要；`procs_removed` 寫了名單上沒有的名字＝不管；名單上已有的名字寫進 `procs_added`＝設定換成這份、已在跑的不重起；名字已在表上的不看設定變了沒。**底**：只開 `procs_ctl` 時就是 daemon.json 的 `procs`，也開了信箱時再加 adopt 接回的與信改過的（N-28「信箱」）。
    - **要停的名字（stopped 集合）同一套**：`procs_stopped` 加、`procs_started` 減，同名兩邊都寫＝起。**要睡的名字（slept 集合）也同一套**：`procs_slept` 加、`procs_woken` 減，同名兩邊都寫＝醒；開門 wake 見 N-28。
    - 只看這一份 `procs_ctl` 與底，讀幾次結果都一樣；照 N-06「沒寫＝回初始值」，**拿掉 `procs_added`＝加進來的那些收掉**、拿掉 `procs_removed`＝減掉的照底重新起、手把拿掉 `procs_stopped` 的名字＝起；要一直加著、停著就一直寫著。
    - 寫壞（不是 JSON 物件、`seq` 不是非負整數、`procs_removed`／`procs_stopped`／`procs_started`／`procs_slept`／`procs_woken` 不是字串陣列、`procs`／`procs_added` 寫法或名字不合、指示詞解不開）＝整份不採用、記 `state_flux.json` 的 `procs_ctl_warning`（N-08、N-09）。
    - **指示詞**照 N-45：`procs`、`procs_added`、`procs_removed` 也解，相對 `$ref` 從 `procs_ctl` 的資料夾（`$AOS_STACK` 底下那份）算。
      - 例：`{"procs_added": {"$ref": ["more.json", "more2.json"]}}`。
  - **多人要改名單**：兩個人同時改 `procs_ctl` 會互相蓋掉（後寫的算）：靠 Linux 檔案權限讓它只有一個寫的人（例 kernel 當這份手把的唯一寫者），不另加機制（10-16 使用者，[C-64](../../../CONCEPTS/01-設計理念/05-布局成長與檔案權限.md#檔案權限10-16-使用者定)）；或用名單的信箱 `procs_requests`（N-28「信箱」），跟 `procs_ctl` 可以同時開（使用者 11-02 晚「我希望信箱和loops_ctl共存，或者說兩者都可以在daemon.json中設定」，[thinking 11-02 state 窗](../../../../thinking/2026-11/02/state-window/01-使用者原文-11-02-逐字.md#決定11-02-晚使用者實作中陸續裁的)）。信箱沒寫＝開在 `procs_requests/`、`null`＝不開；名字回報在 `procs_state.json` 的同名欄，aos-daemon-ctl 從那裡找信箱（[thinking 11-04 four-elements](../../../../thinking/2026-11/04/four-elements/06-要使用者裁的題.md#使用者裁定11-04選項原文或他的話逐字) 題 5；N-28「兩個手把、兩扇狀態窗」「小格裡三個檔名可設」）。信的 `body` 是 `procs_added`／`procs_removed`／`procs_stopped`／`procs_started`／`procs_slept`／`procs_woken` 片段（沒有整份的 `procs`），每圈全部認領、照順序套用；壞信不套、記 `state_flux.json` 的 `mailbox_warning`；誰能寄同樣靠 Linux 檔案權限。
