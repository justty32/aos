N-28 接續（上一份的子項到這裡繼續）：

  - **`adopt`**（布林，**預設 `true`**；使用者 10-16：「給選項，默認留」，[KISS 重審拍板 2](../../../../thinking/2026-10/16/kiss-recheck.md#使用者拍板10-16)；key 名 `adopt` 是頂層照 C-54 挑的——說的是「認領活著的子 loop」）：daemon 重起時讀自己上次的 `procs_state.json`，把還活著的子項接回（pid＋啟動時間對得上才認，N-17），不重起它們；`phase: stopped` 的列接回成 `stopped`（不起、不判活）；`sleeping` 的列接回後 wake（見「收工時 sleep、開門時 wake」）；接回的列 `ws` 保留。adopt 與 start 照列上的 `stack`。寫 `false`＝不接回。第一次起來沒有舊的 state 就沒東西可接。
    - **讀不了要說話**：檔不在＝第一次，安靜；檔在但讀不了（不是 JSON、不是物件、缺 `procs` 或解不開、`procs` 不是物件）＝主檔改名留證 `procs_state.json.bad-<UTC 時間>`、印英文 `warning:`、從空表開始（daemon.json 的列照起）；只有幾列不是物件＝複製主檔留證、跳過壞列、好列照接。原因同時進 log 與 `state_flux.json` 的 `adopt_warning`（沒事＝null）。不是 C-48 的「當沒看到」：daemon 自己寫的狀態檔讀不了要看得出壞了（format-versioning 必修 1，使用者「先修必修」，[thinking format-versioning](../../../../thinking/2026-11/09/format-versioning/README.md)）。其他窗（state、state_flux，主人與旁觀者）見 [N-09](../../05-基礎設施-窗/02-N-09～N-11.md)。
    - 另比表頂層 `boot_id`：跟這次開機不同＝表上的行程都當不在、照名單另起；表沒寫 `boot_id`＝當作別次開機；這台讀不到 `boot_id`＝不比，照舊 pid＋ticks（[P1 結果](../../../../thinking/2026-11/05/no-pid/08-P1實作結果.md)）。
  - **子項結束後不自動重起；自然退 0 就下表**（使用者 10-20「照預設」，[ideas § 25](../../../../thinking/2026-10/19/ideas/README.md)；使用者 11-02 晚「改成子項結束後不留名單」，[thinking 11-02 state 窗](../../../../thinking/2026-11/02/state-window/01-使用者原文-11-02-逐字.md#決定11-02使用者)；11-03「照舊拿掉」）：不分寫法，子項自己退 0（`done`）印完 log 那行就從表上拿掉，小格留著；表上看不到結束的，結束碼看 log 那一行。留在表上的：已知非 0（含被訊號打掉、起不來）＝`stopped`＋`reason`（下一點）；stop 途中退的＝`stopped`、sleep 途中退的＝`sleeping`（N-54）；daemon 收工時睡下的＝`sleeping`。adopt 接回時還活著、之後在這個 daemon 底下才退的拿不到結束碼，退了照樣下表；daemon 不在的期間就死了的留 `stopped`（下一點，11-19 起）。寫了 `auto_restart` 的先照它的重起規則（使用者 11-07 選 B「daemon 不分類」，[arknights-kb 07](../../../../thinking/2026-11/07/arknights-kb/07-停不下與消失.md)）。
    - **出錯結束一律留表**（使用者裁 [edge-agent 題 1](../../../../thinking/2026-11/05/edge-agent/README.md)「留表標 stopped (Recommended)」、[edge-daemon 題 2](../../../../thinking/2026-11/05/edge-daemon/README.md)「一起改成留表 (Recommended)」；[portable-flow](../../../../thinking/2026-11/05/portable-flow/README.md) 衝突 3「留成stopped，並寫原因」；不分寫法）：子項自己退了、結束碼非 0（含被訊號打掉、起不來）＝列留成 `stopped`＋`reason`（英文）、要 `start` 才再起；wake／start／add 起來 3 秒內退的原因字樣是 `failed to start…`，其他是 `failed while running…`。退 0（做完）下表；adopt 接回時還活著、之後才退的（拿不到結束碼）下表（代定）；**daemon 不在的期間死掉的**（daemon 被殺、斷電、重開機的期間結束，拿不到結束碼）、沒寫 `auto_restart` 的＝列留 `stopped`＋`reason`、要人 `start`，不再整列下表（同一次開機＝`ended while the daemon was not running (exit code unknown); start it to run it again`，表上 `boot_id` 跟這次開機不同＝`the machine restarted while it was running (exit code unknown); start it to run it again`；stderr 一列一行 warning）；`procs_ctl` 宣告的、信或 `ctl add` 加的都一樣留 `stopped`，只有 daemon.json 寫的列照宣告再起（使用者 11-19 下午選項框選「斷電後 agent 從表上消失」，說明：「改成留在表上並標明死了。」，`36602ed9b`；`procs_ctl` 宣告的要不要也自動再起，同日選「維持，留 stopped (Recommended)」；條文 11-19 跟上，[修補紀錄](../../../../thinking/2026-11/19/aos-base-fix.md#使用者裁定11-19-下午選項框線-aos-n28-1119-補記)）；寫了 `auto_restart` 的先照它重起。
    - 自己結束（`done`）的**本次執行不再起**——某一圈算出的期望表裡沒有它了才放掉（之後名單再有它就照常起）；開了信箱再從底拿掉，之後再有信同名 `procs_added`＝重新起。要再起：`procs_ctl` 從名單拿掉（daemon 看過一圈）再放回、再寄一封同名的信、或重起 daemon。
    - 「不自動重起」管的是 **daemon 開著的時候**；daemon 重開＝重新開始，照名單起表上缺的——含 daemon 停機期間（例如被 SIGKILL）死掉的子項；還活著、pid＋啟動時間對得上的照 `adopt` 接回、不重起（使用者 10-22「1 daemon 重開時照表起，算重新開始、不算自動重起」）。
    - 沒有 `policies.child_exit`、沒有 `backoff` 設定（10-22 使用者；`auto_restart` 連著重起越等越久是寫死在程式裡的、不開設定，見下一點），只有每個 proc 自己寫的布林 `auto_restart`（下一點）；其他「結束了怎麼辦」自己在鏈上接工具，例如子項的 `exec` 指到自己寫的監工、或外面用 s6／runit 管。
    - **`auto_restart`**（布林，任何 proc 都能寫；使用者 11-06 選項框選「通用 restart: true (Recommended)」、名字定 `auto_restart`：「因為單restart，你不知道他想表達的意思。」，[no-pid 15](../../../../thinking/2026-11/05/no-pid/15-P6去耦合.md)）：自己退了（退 0、非 0、被訊號打掉都算）照表重起，**連著重起越等越久**：第 1 次同一拍起、第 2 次等 1 秒、之後每次加倍（2、4、8…秒）、最多等 60 秒；有一輩子撐過 60 秒才退＝重新算，下一次又是同一拍起（「連著」＝每一輩子都沒撐過 60 秒）。這幾個數寫死在程式裡、不開設定。等的期間列是 `sleeping`、`reason` 寫第幾次、要等幾秒、連著幾次（`auto_restart: restart <N> in <秒>s (<連著幾次> in a row; last: <上一次怎麼退>)`）；起來後 `running` 的列 `reason` 寫重起過幾次，列多一欄 `counter_restarts`——表上看得到次數。次數只在記憶體，人 `start`／`add`、daemon 重開都歸 0（使用者 11-19 下午選項框選「會死的 proc 無限重起」，說明：「改成越重起等越久，並在表上看得到次數。」，`0b23509a1`；要不要開成可設定，同日選「寫死就好 (Recommended)」；條文 11-19 跟上，[修補紀錄](../../../../thinking/2026-11/19/aos-base-fix.md#使用者裁定11-19-下午選項框線-aos-n28-1119-補記)）。連 3 次都在起來 3 秒內就退＝留 `stopped`＋`reason`、要人 `start`；寫了它的算常駐，可 stop／sleep、收工留 `sleeping`、開門 wake；人下 stop／sleep／rm 的不重起；沒寫照本條不重起。人從命令列開它用 `aos-agent ctl add --auto-restart`（或 `aos-daemon-ctl add --auto-restart`），就是替那列寫 `auto_restart: true`；腦或外面的服務暫時失敗時那封信掉掉、agent 自動重起（使用者選定，[two-machines](../../../../thinking/2026-11/10/two-machines/README.md#使用者裁定11-10-上午選項框快裁大修時可重看) 裁定 5、6）。暫時失敗後冷卻、只拿一封試（使用者選定，同上），冷卻是 agent 身體自己做的（[P-20](../../../CONVENTION/02-題目stack停錯腦/04-五-stack與六-停與錯.md)），不是 daemon 的退避；daemon 的等待只有上面寫死的那一段，照舊沒有 `backoff` 設定。
    - **子 daemon 不另成一型**（使用者 11-06「對於daemon來說，子daemon對他來說就只是一個普通的proc。不要耦合」）：沒有 `{"daemon": …}` 寫法，子 daemon 用普通 exec 型掛（`{"exec": "../sub"}`），父不知道它是 daemon；整棵樹一層層睡醒是每層 daemon 自己收工、自己醒的結果（[aos-daemon docs/03](../../../../cpp/aos-daemon/docs/03-起-停-暫停.md#auto_restart常駐11-06)）。
    - 時鐘是 `procs` 裡一列普通 proc（範本慣例名 `_clock`，不是保留字），寫了 `auto_restart: true` 就照 `auto_restart` 的規則重起（連 3 次失敗留 `stopped`）；人下 `stop`／`pause` 的不重起。daemon 沒有時鐘專屬規則（見「時鐘」那段）。
    - 清道夫 `_sweeper` 同樣是範本慣例名的一列普通 loop 型 proc（不是保留字，daemon 不認它）；跟鐘不同，每台 daemon 自己帶一列、只管自己表上的列（使用者 11-10「每個daemon要掛就自己掛，只管自己」，[thinking sweeper](../../../../thinking/2026-11/10/sweeper/README.md)）。
