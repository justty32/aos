N-28 接續（上一份的子項到這裡繼續）：

  - **名單 `procs`**＝`{名字: proc}`（使用者 11-03「exec和loops，其實都屬於proc」「連名單也合一」）。名字就是子項的 `id`，沒寫 `stack` 時也是小格 `$AOS_STACK/procs/<名字>/` 的名字（P-17；子項名字是名單給的，跟 daemon 自己的固定名分開，[thinking 11-02 stack-tools](../../../../thinking/2026-11/02/stack-tools/README.md) 細節 5）。名字不能空、不能含 `/`、不能 `.` 開頭、不能帶 `#`（`#` 是頂層自定，ideas 10-21 § 9.3 第 5～7 點）；跟 daemon 自己的窗同名不擋（使用者 11-02「那兩題中的1.，可以」）。**daemon 收子項只看它自己需要的**（C-52；10-15 深夜使用者「不留」）。每項**看寫法決定怎麼起**，沒有 `kind`（使用者 11-03「2.kind這東西沒用吧，刪掉」）：
    - **型別怎麼判**（使用者題 3「不動，文件寫清楚」，[thinking 11-04 four-elements](../../../../thinking/2026-11/04/four-elements/06-要使用者裁的題.md#使用者裁定11-04選項原文或他的話逐字)）：字串、陣列 `[目標, 參數...]`、或含 `exec` 且其餘 key 只在 `ws`、`stack`、`def`、`limits`、`limits_clamped`、`auto_restart`、`restart_on_stuck`、`stuck_after_cycles`、`stuck_after_ms` 之中的物件＝**exec 型**：aos-exec 跑一次。其他物件（例如多任何一個 loop 的 key `max`、`interval_ms`、`ctl`、`state`）＝**loop 型**：一份 loop 設定、包成子 aos-loop（10-15 使用者『全定』）。**要一直跑最少寫 `"interval_ms": 0`**；aos-daemon-ctl add 的 loop.json 只有 `exec` 時替它補 `"interval_ms": 0` 就是為了這條。
    - 例：`"a": "../job"`＝跑一次；`"b": {"exec": "fsm.json", "ws": "/w"}`＝跑一次；`"c": {"exec": "fsm.json", "interval_ms": 0}`＝一直跑。坑：寫 `{"exec": "fsm.json"}` 想要一直跑的 loop 會變成跑一次，要 loop 就多寫一個 loop 的 key（例 `"interval_ms": 0`）。
    - 型別只決定怎麼起；起來之後一視同仁，不用 `interval_ms` 決定管理動作（使用者 11-07：「等等，不過有個問題：argv:[aos-loop loop.json]，我用aos-exec執行，這等同於我變成了aos-loop，然後去跑loop.json設定。在變成loop之前，我確實就是一次性程式沒錯」，選 **B：daemon 不分類**，[arknights-kb 07](../../../../thinking/2026-11/07/arknights-kb/07-停不下與消失.md)）。
    - loop 型物件裡的 loop key 與單子 daemon 一概不驗、原樣灌給子 loop，寫錯了子 loop 自己退 1、錯在它的 stderr，daemon 只看到它結束；沒 `exec` 的物件一樣原樣交給子 loop，由它退 1（「沒有東西可跑」）。要用 loop 型跑單子，寫 `{"exec": "daemon.json#/procs/<名字>/body", "body": 單子}`（只跑一次再加 `"max": 1`）。
    - 要一次跑完的東西也可以寫成 `{"exec": 它, "max": 1}` 的 loop（使用者 10-30「包成max:1也是可以」），差別只在多一層 aos-loop 與它的窗——小格裡外層 loop 的 `ctl.json`／`state.json` 會跟掛進去的 aos agent 自己的 loop 窗撞同一個檔（[入口](../../04-基礎設施-loop與daemon.md)開頭 ②），純黑盒子沒這問題。
    - 同名改寫法（loop 型與 exec 型互換、改了 `ws`、`stack`…）照 N-54「名字已在表上的不看設定變了沒」不重起，下一次起它才用新的。
  - **起 loop 型**（經 aos-exec，使用者「5.要」）：daemon 把子項設定拿掉 `ws`、`stack`，一律蓋上 `"_entry": ["aos-loop", {"$env": "AOS_CF"}]` 寫成小格的 `loop.json`，起 `aos-exec -- 小格/loop.json#/_entry`（指到 `_entry` 不受 `$AOS_ENTRY` 影響）。**不補 `ctl`／`state`**：aos-loop 自己沒寫＝`ctl.json`／`state.json`；daemon 停子 loop 時它的 loop.json 沒寫 `ctl`＝當 `ctl.json`。相對路徑從 daemon 的 cwd 算：aos-exec 會 cd 進小格，所以 daemon 寫小格時把子項 `exec` 的目標（字串，或陣列的第一個元素）照 daemon 的 cwd 轉成絕對路徑；`exec` 是單子時由子 loop 在自己行程內跑（`AOS_CF`＝小格的 `loop.json`、`AOS_CO`＝`/exec`），單子沒寫 `cwd`＝補上 daemon 的 cwd、相對的 `cwd` 接在 daemon 的 cwd 後面（是指示詞就不動），單子裡相對的 `$ref` 檔名照它來自的那份檔轉成絕對、不解；`procs_ctl` 加的子項同一套（頂層代定，[thinking 10-24](../../../../thinking/2026-10/24/exec-relative/01-使用者原文.md#10-24-exec-直接放單子)）。其他 key 不驗、不動。子項若是資料夾程式，用 `aos-exec` 跑（[N-58](../../10-基礎設施-定義與工作區/02-N-58.md)）。
  - **起 exec 型**（使用者 10-30「不過可以的話，我也覺得讓daemon可以掛aos-exec，也是不錯的」、看完規劃回「都照建議」，[thinking 10-30 agent-lifecycle](../../../../thinking/2026-10/30/agent-lifecycle/07-衝突.md#決定10-30)；[impls/aos-daemon](../../../../impls/aos-daemon/README.md)）：daemon 對它直接 `aos-exec` 一次，**不包 aos-loop、不寫小格的 `loop.json`、不補 `ctl`／`state`**，表上的 pid 就是那支程式。目標是字串或陣列＝`aos-exec -- 目標 參數...`；`{"exec": 單子}`＝daemon 把它寫成小格的 `exec.json`（`{"exec": 單子}`，單子的 `cwd` 照 loop 型的單子那樣補），跑 `aos-exec -- 小格/exec.json#/exec` 一次（`AOS_CF`＝小格的 `exec.json`、`AOS_CO`＝`/exec`；單子沒寫 stdin／stdout＝接 `/dev/null`、stderr 附加到小格的 `stderr.txt`，寫了就照它）（使用者 11-02 回「daemon 的 execs 要不要也收內嵌單子」：「6.要。」）。
  - **兩型共通**：`AOS_STACK`＝小格（或那一項的 `stack`）；stdin／stdout 接 `/dev/null`、stderr 附加到小格的 `stderr.txt`（exec 型的單子寫了 stdin／stdout 就照它，見上）；自成 session 群組；cwd＝daemon 的 cwd。子項的環境除了 `AOS_STACK`（與寫了 `ws` 時的 `AOS_WS`），一律多設 `AOS_DAEMON`＝daemon 自己的 stack（絕對、結尾 `/`），只設這一個（使用者 11-02 對常駐 bob 的衝突與方向題回「照建議走」，thinking 11-02 resident-bob（已封存） 衝突 2；條文在 [N-63](../../10-基礎設施-定義與工作區.md)「daemon 起子項時把 `AOS_DAEMON` 設給它」，父子交代的例子在 N-64 ④）。
