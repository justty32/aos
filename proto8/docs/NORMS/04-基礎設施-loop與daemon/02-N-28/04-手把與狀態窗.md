N-28 接續（上一份的子項到這裡繼續）：

  - **兩個手把、兩扇狀態窗**（使用者 10-28「一個控制loop面向和自身屬性，一個控制管轄的aos函數」、10-29「ctl和投遞信箱並存，那就是程式設計者自己決定哪個負責哪個，這就是兩套模式」；看完衝突與方向題回「都照建議」，[thinking 10-29 medium-plan](../../../../thinking/2026-10/29/medium-plan/README.md) § 四）：
    - `ctl`、`state` 管 loop 面向與自身屬性，跟 aos-loop 同一套（嚴格超集）；慣用名 `ctl.json`、`state.json`（使用者 11-02 晚「控制自身的 ctl/state 檔案，那就是 ctl/state，不加前綴」，[thinking 11-02 ctl-state-names](../../../../thinking/2026-11/02/ctl-state-names/README.md)），沒寫＝預設 `ctl.json`／`state.json`、寫 `null`＝不開（N-09）。另一扇 `state_flux`（預設 `state_flux.json`、`null`＝不開；使用者 11-09 裁 state_flux，[thinking clock-and-hot-writes 05](../../../../thinking/2026-11/09/clock-and-hot-writes/05-state拆分規劃.md)）放 daemon 所有的回音——loop 面向的 `responded_at`、`ctl_seq`、`ctl_warning`，管轄手把的 `procs_ctl_seq`、`procs_ctl_warning`，信箱的 `mailbox_warning`，與 `adopt_warning`（一個程式一份，不另開 `procs_state_flux.json`；見 N-09）。
    - `procs_ctl`、`procs_state` 管轄的名單（手把怎麼寫見 N-54）與它的狀態窗：路徑，相對 `$AOS_STACK`；沒寫＝`procs_ctl.json`、`procs_state.json`。
    - `procs_requests`＝名單的信箱（名字見 [C-54 R14](../../../CONCEPTS/01-設計理念/C-54-命名方法/03-R14.md)；路徑；沒寫＝開在 `procs_requests/`、`null`＝不開，跟 `procs_ctl` 同形；使用者 11-04 題 5 後半「留 key、沒寫時預設就是這兩個名」，[four-elements](../../../../thinking/2026-11/04/four-elements/06-要使用者裁的題.md#使用者裁定11-04選項原文或他的話逐字)）。跟 `procs_ctl` 可以同時開、只開一個、都不開（都不開＝名單只看 daemon.json）（使用者 11-02 晚「我希望信箱和loops_ctl共存，或者說兩者都可以在daemon.json中設定」「loops_mailbox改名為loops_ctl_mailbox。寫null就是不開窗，ctl/ctl_mailbox可以一起不開」）。
    - `ctl`、`state`、`state_flux`、`procs_ctl`、`procs_state`、`procs_requests` 寫 `null`＝不開（使用者 11-02 晚「daemon.json中的ctl/state，如果指定null，那就是不開窗」「寫null就是不開窗」）。
  - **`procs_state.json` 就是 save 檔**（daemon 不另留 save 檔；KISS 重審 3.3）：頂層是 `procs_loop`、`procs_exec`、`procs_stderr`、`procs_requests`、`daemon`、`procs` 表（一項一列：`pid`、`started_at_ticks`、`phase`、`code`、`signal`、`stack`…）、`pid`、`started_at_ticks`、`boot_id`，最後一欄 `updated_at`。回音欄不在這裡——`procs_ctl_seq`、`procs_ctl_warning`、`mailbox_warning`（N-16；使用者 11-02 晚「letter_warning改成mailbox_warning」）、`adopt_warning` 都在 daemon 的 `state_flux.json`（[thinking clock-and-hot-writes 05](../../../../thinking/2026-11/09/clock-and-hot-writes/05-state拆分規劃.md)）。
    - **每列的欄**：每列都寫 `stack`（預設小格也寫）；起它時給了 `ws` 才多一欄 `ws`（起的那一刻的值）；`exec`＝起它時的目標（字串目標、陣列的第一個、物件的 `exec`，`檔#/…` 片段照留；內嵌單子＝`null`；使用者 11-04 晚「daemon表多一欄記下來」，[thinking 11-04 aos-agent 06/02](../../../../thinking/2026-11/04/aos-agent/06-衝突與方向題/02-新題-11-04-晚.md#使用者裁定11-04-晚選項原文) 方向題 1）；`def`＝proc 物件的 `def`（定義資料夾；沒給＝`null`；daemon 不驗、只記，aos-daemon-ctl add 一律送 XXX），aos-agent 從 `def` 找定義（使用者 11-04「那就b。」，[thinking 11-04 aos-agent 05/03 第 2 條](../../../../thinking/2026-11/04/aos-agent/05-實作步驟/03-實作時改的設計.md#實作時改的設計)）。adopt 接回的列照舊表帶過來。列的 `phase` 只有 `running`／`stopping`／`stopped`／`sleeping`；留 `stopped` 的列多一欄 `reason`（見「出錯結束一律留表」）。
    - **表上的路徑相對 daemon 的 stack**（使用者裁 [portable-flow](../../../../thinking/2026-11/05/portable-flow/README.md) 題 1「daemon 的 stack」；使用者「實現無痛遷移」）：`stack`、`ws`、`exec`、`def` 存相對、讀時從現在的 stack 拼回；小格 `loop.json` 的 `exec` 寫 `{"$env": "AOS_DAEMON", "$path": …}`；運行時環境變數照舊絕對。基準點就是管我的、最近的上一層 daemon（使用者原話「以自己頭上最近的那個daemon為準，因為上不知下」）。
      - **指到外面的路徑三種寫法都收**：相對、絕對、`{"$env": …}`，用到時才解，兩台各設各的（使用者 11-10「要用相對位置、絕對位置、環境變數指定都可」「兩台各自設一次...不要限制只設一次」，[two-machines](../../../../thinking/2026-11/10/two-machines/README.md#午後方向改變逐字)）。列上另存選填的 `as_written`＝使用者寫的原形：`ws`、`stack`、`def`、`exec` 寫成指示詞的，每次起照 daemon 當下的環境再解（解不開＝留 `stopped`＋`reason`，不退回舊值）；使用者在命令列打成絕對路徑的原樣存、每次起照它（使用者 11-10「add xxx 會換算(除了絕對路徑)」，[two-machines 16](../../../../thinking/2026-11/10/two-machines/16-B01後半施工結果.md)）；相對路徑照上面換算成相對 daemon 的 stack。程式自己組的絕對路徑不算使用者寫的、照舊換算；原樣存的絕對路徑在這台不在＝改用表上相對 daemon stack 那份、stderr 一行（這兩點代定、可翻案，[two-machines 16](../../../../thinking/2026-11/10/two-machines/16-B01後半施工結果.md)）。
    - 頂層 `daemon` 在 `procs_requests` 後、`procs` 表前，有變才寫的比對也算它（[P2 結果](../../../../thinking/2026-11/05/no-pid/09-P2實作結果.md)）；`responded_at` 只在 `state_flux.json`，定義與欄位順序見 [N-32](../../05-基礎設施-窗/07-細則.md)。
