N-28 接續（上一份的子項到這裡繼續）：

  - **小格裡三個檔名可設**（使用者題 6「是否能在json中設置？但默認用這些名」，[thinking 11-04 four-elements](../../../../thinking/2026-11/04/four-elements/06-要使用者裁的題.md#使用者裁定11-04選項原文或他的話逐字)；[aos-daemon](../../../../impls/aos-daemon/docs/01-用法.md)）：daemon.json 頂層 `procs_loop`（預設 `loop.json`）、`procs_exec`（`exec.json`）、`procs_stderr`（`stderr.txt`），暫存檔＝`.`＋名字；daemon 在 `procs_state.json` 頂層回報同名欄（連同 `procs_requests`，沒開＝`null`），讀小格的人（aos-daemon-ctl、aos-agent、adopt）從窗拿名字、不寫死。本條講 `loop.json`、`exec.json`、`stderr.txt` 的地方照這條讀。
  - **每項選填 `stack`**（使用者 11-03「那就記錄在名單上。我是希望盡量不要用捷徑啦。」）：非空字串，相對路徑從 daemon 的 cwd 算、轉絕對；`null`＝當沒寫；沒寫＝小格 `procs/<名字>/`。不在就建（`mkdir -p`，建不了＝`MkdirFailed`）；裡面有什麼、兩項同一個 stack，都不查不擋、使用者自己承擔；不建捷徑；不灌進 `loop.json`。
  - **每項選填 `ws`**（這一隻的工作區；使用者 10-30「都照建議」，[thinking 10-30 eca](../../../../thinking/2026-10/30/eca/09-方向題.md#決定10-30) 衝突 1；[impls/aos-daemon](../../../../impls/aos-daemon/README.md)）：只有物件寫得了（字串或陣列寫法沒地方寫，要 `ws` 就寫成物件）。值是非空字串（指示詞照解），**相對路徑從 daemon 的 cwd 算**、轉成絕對存進期望表；`null`＝當沒寫；其他型別或空字串＝壞（daemon.json＝`CfgBad` 退 1、`procs_ctl` 整份不採用、信＝壞信）；在不在不驗（不在的話子項經 aos-exec 報 `WsMissing`）。daemon 起那個子項時把 `AOS_WS` 設成它；**沒寫＝繼承 daemon 的環境**。`ws` 不寫進小格的 `loop.json`（它不是 loop 的 key），只進環境；小格不因 `ws` 搬家。改了 `ws`，下一次起它才用新的（同名改寫法）。`ws`、`stack` 是 daemon 拿走的 key：exec 型物件可用的額外 key 見判型清單，loop 型物件交給子 loop 前也會拿走 daemon 自己用的 key。原則：[N-55](../../10-基礎設施-定義與工作區.md) 工作區由呼叫方設 `AOS_WS`，daemon 是呼叫方。
  - **子項的輸出：aos 不保證子項的輸出不無限長**（使用者 10-22「小地方那些我都OK」、四個實際問題都由使用者自己承擔，[ideas 10-22 § 5](../../../../thinking/2026-10/22/ideas/03-5-loop.md#5-loop10-22)；使用者 10-22「3 N-28 未做的從規範拿掉、改寫自己接工具」，[ideas 10-22 § 6](../../../../thinking/2026-10/22/ideas/03-5-loop.md#6-daemon10-22)）。aos-daemon 丟掉子項的 stdout（結果一律從 state 窗讀），子項自己與它每次的 stderr 全部附加到小格的 `stderr.txt`（daemon 自己開的檔，不只出錯時、不輪替、不設上限）；選填路徑、輪替、清舊格子都不做。要控制大小的人自己處理，風險使用者自己承擔；aos-loop 自己的那幾行仍會進小格。
    - 例：外面用 logrotate 的 copytruncate 截（檔是附加模式開的），或讓那次的單子用 `stderr` key 把輸出導到自己的檔、在那次裡把輸出接給 s6-log、svlogd（見 [notes/s6-runit](../../../notes/s6-runit.md)）。
  - **daemon 不清小格**（使用者確認：自己承擔）：表上沒列到的舊小格留著，同名子項再起時沿用那格、`stderr.txt` 接著附加，小格裡舊的 `ctl.json`、`state.json` 也留著，再起時怎麼讀照 [N-06](../../05-基礎設施-窗/01-N-06～N-08.md)。要清自己在起 daemon 前刪。
  - **`$AOS_STACK` daemon 起來時自己建；小格只建 `procs/` 與小格兩層**：設定驗過之後、上鎖與 adopt 之前，`$AOS_STACK` 有設但不在就 `mkdir -p`（aos-loop 的 `make_stack`），建不了＝`MkdirFailed` `cannot create AOS_STACK: …`、退 1，設定壞的不建（使用者 11-11「stack只能在aos-exec建<-這個規則刪除」，稍晚在選項框選「也自己建」：跟 loop／fsm 一致，[thinking tool-cells-lazy](../../../../thinking/2026-11/11/tool-cells-lazy.md#線-h-裁定daemon-也自己建11-11)；aos-loop、aos-fsm 同樣自建，見 [N-59 第 1 件](../../10-基礎設施-定義與工作區/03-N-59.md)）。跑的途中 `$AOS_STACK` 被刪、或在但不是資料夾＝state、state_flux 或 procs_state 窗開了任一扇就 `WriteFailed`、都沒開才 `MkdirFailed`，都退 1、stderr 一行。寫了 `stack` 的見上（不在就建）。
  - **同一個 stack 已有 daemon 在跑＝`DaemonExists` 退 1**（「有就沿用」；使用者 11-06 選「繼續擋 (Recommended)」）；不同 stack 起兩個 daemon 不擋（[procs 11](../../../../thinking/2026-11/03/procs/11-實作時代定-11-03-晚-實作者照原則.md)、[lift-to-norms](../../../../thinking/2026-11/06/lift-to-norms/README.md)）。細節 [aos-daemon 搬家相關](../../../../impls/aos-daemon/docs/03-起-停-暫停.md#11-05-搬家相關)。
    - 判「同一個 stack 已有 daemon」只靠 flock；daemon fork 出的子行程（proc 與身體）第一件事關掉這把鎖（`pthread_atfork`），daemon 被 `kill -9` 後立刻再起起得來。鎖不到時只看 `state.json` 的 `phase`（`stopping`＝收工途中），訊息不帶 pid。邊緣，沒修：單子身體在舊 daemon 被 `kill -9` 後變孤兒照跑，新 daemon 另跑自己的身體，有一陣子兩份身體同時跑（[P1 結果與邊緣 1](../../../../thinking/2026-11/05/no-pid/08-P1實作結果.md)）。
