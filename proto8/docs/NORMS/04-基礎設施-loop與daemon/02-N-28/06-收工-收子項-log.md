N-28 接續（上一份的子項到這裡繼續）：

  - **收工時 sleep、開門時 wake**（使用者 11-03「改寫成休息中」「還記得嗎？我們有start/stop, sleep/wake, pause/resume，我們缺了sleep/wake」；[thinking 11-03 procs § 8](../../../../thinking/2026-11/03/procs/10-實作時代定-11-03-實作者照原則定的.md#8-收工時改寫成休息中sleepwake11-03-晚)）：daemon 收工（P-36，不論為什麼）時還活著的列一律送 SIGTERM 收掉，退了留成 `sleeping`（行程不在、stack 留著）；adopt 接回 `sleeping` 的列、不進 stopped 集合，第一圈用列上的 `stack` 自動再起（wake）。收工前已 `stopped` 的留 `stopped`；`kill -9` 的 daemon 沒走收工，不睡。
    - **sleep／wake 也是指令**（使用者裁 [portable-flow](../../../../thinking/2026-11/05/portable-flow/README.md) 衝突 1 選「嚴格分」）：信／`procs_ctl` 認 `procs_slept`、`procs_woken`（名字陣列；N-54 的 key 清單）；sleep＝現在就睡（送 SIGTERM，同收工那套，列 `sleeping`；不寫 ctl，協定沒有 sleep 指令），wake 或 daemon 開門才醒；stop＝等這輪做完、要 start。任何 running 列都能 sleep、任何 sleeping 列都能 wake，不分寫法；stopping 列也能 sleep（11-07 晚審第 3 題使用者選 A）：stop 途中的列改送 SIGTERM，退後仍留 stopped、用 start 再起（N-54）。其他用錯（start 一隻 sleeping 的…）＝aos-daemon-ctl 回 `PhaseBad`。
    - 一次性程式（沒讀 ctl、沒自己的 state 的那種）收工時還在跑，也一樣留 `sleeping`；開門 wake＝照列上記的入口與參數從頭再跑一次，不是接著跑。有副作用、不能重做的一次性工作，要寫的人自己讓它做得起兩次，或收工前先 rm。（這半句代定）（11-07 使用者裁定，出處 [proto8/thinking/2026-11/07/arknights-kb/07-停不下與消失.md](../../../../thinking/2026-11/07/arknights-kb/07-停不下與消失.md)）
  - **daemon 停子 loop**＝往它的 `ctl.json` 寫一道 `{"cmd": "stop"}`（[thinking 11-03 ctl-commands](../../../../thinking/2026-11/03/ctl-commands/README.md) § 5、[N-06](../../05-基礎設施-窗/01-N-06～N-08.md)；stop 的完整流程見 N-54「起、停、暫停」）。
  - **收子項不阻塞**（使用者「都修都處理」，[thinking 10-23 daemon 壓測](../../../../thinking/2026-10/23/daemon-bench.md)）：表上多出來的送 SIGTERM 就往下巡（state 一樣寫、ctl 一樣讀、別的子項一樣起），之後每次巡時看一眼，退了從表上拿掉，滿 10 秒還在才 SIGKILL 整群；收的途中那一列的 `phase` 是 `stopping`（N-17）。exec 型一樣收，SIGTERM 直接打那支程式。收的途中名單又把同名的放回來＝等舊的退了、下一次才起新的（同一個小格）。
    - **收工**照 P-36：不論為什麼結束都先收掉子項、寫好 state，收到訊號以 128＋N 結束（非 0）。收法是全部先送 SIGTERM、等它們退：先寫一份頂層 `phase` `stopping` 的 state、之後每退一批寫一次 `procs_state`，滿 10 秒還在的 SIGKILL；名單早就要拿掉、收工時才退的一樣拿掉；最後一次之後才自己結束的子項，log 那一行記 `done`、`code`，列從表上拿掉（[計畫 10-21](../../../../thinking/2026-10/21/plan/README.md) D7）。
    - **被 SIGKILL 的子 loop 自己的 state 會停在最後寫的那份**（多半是 `running`）：daemon 不去改它（N-09 一個 state 檔只有它自己寫）。讀子 loop 的 state 時死活照 N-17 看 pid＋`started_at_ticks`；daemon 的 log 那一行是準的——daemon 收掉的寫 `stopped`，被 SIGKILL 的 `signal` 9、`code` 137。
  - **什麼時候寫 state**（兩扇狀態窗都有變才寫，N-09）：`procs_state.json` 跟上一份寫出去的比（四個名字欄 `procs_loop`／`procs_exec`／`procs_stderr`／`procs_requests`、`daemon`、`procs` 表），一樣就不碰檔、分檔也不碰；回音欄由 `state_flux.json` 整份比、有變才寫，寫序是 state／procs_state 先、state_flux 後（N-09；[thinking clock-and-hot-writes 05](../../../../thinking/2026-11/09/clock-and-hot-writes/05-state拆分規劃.md)），所以寄 ping、寫壞 ctl、壞信都不動 `procs_state.json`。沒有 `exec` 的 daemon 一圈只讀一次 ctl、只對一次表、最多寫一份 state（`waiting`，不寫 `running`），睡著時兩扇窗都不動；表用雜湊找名字。起子項之前先寫一份 `procs_state`、之後每起一個寫一次。
  - **log**（使用者 11-02「daemon和loop他們就是把log輸出到stdout」，11-02 晚「aos-loop和aos-daemon他們印出的log感覺都沒啥用，應該要改成默認不印。」，[thinking 11-02 loop-stdio](../../../../thinking/2026-11/02/loop-stdio.md#決定)）：命令列給 `--enable-logs` 才印到 stdout（N-11），不寫 log 檔。aos-loop（與有 `exec` 的 daemon）每跑完一次一行 `{"started_at", "counter_runs", "code", "signal", "elapsed_ms"}`（欄位名同 N-39、P-38），沒有 `exec` 不印每圈的行；daemon 的子項起來一行、結束一行 `{"at", "name", "phase", "pid", "code", "signal"}`（起它時給了 `ws` 再多一欄 `ws`；adopt 接回的也印一行 `running`）。子項的 stdout 接 `/dev/null`；daemon 自己的身體跟 log 同一條 stdout，混在一起由使用者自己處理（使用者 11-02 晚「aos體系下，stdin/out/err都可以任意指定，混在一起就是使用者自己要處理的，不用管太多。」）。
