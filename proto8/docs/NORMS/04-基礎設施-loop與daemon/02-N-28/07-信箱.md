N-28 接續（上一份的子項到這裡繼續）：

  - **信箱**（`procs_requests`）：daemon 建好 `tmp/`、`new/`、`cur/` 三格、每圈照 [N-16](../../05-基礎設施-窗/05-N-16.md) 認領全部的信、照名字順序套用，信預設刪；信的 `body` 是名單的增減片段（認哪些 key 見 N-54），沒有整份的 `procs`。
    - 信改的是「底」：daemon.json 的 `procs`＋開了信箱時 adopt 接回、不在上面的＋依序套用的信；`procs_ctl` 每圈疊在底上（N-54）；同一圈先套完信、再疊 `procs_ctl`、再對一次表（合併規則照實作，隊長代定）。**接回的子項留在名單上，直到有信把它 `procs_removed`、或它結束**（方向題 1）。
    - 寫了 `reply_to` 的好信，對完表才回一封 `body: {"applied": true}`；**壞信不套用、原因記 `state_flux.json` 的 `mailbox_warning`**（N-09；[10-28 medium](../../../../thinking/2026-10/28/medium/README.md) 決定 27；使用者 10-29「都按照建議」，[medium-plan 實作時代定](../../../../thinking/2026-10/29/medium-plan/07-實作時代定.md#實作時代定10-29隊長與工人照原則定的細節可翻案) 第 11 條）。**信封讀得懂、有 `reply_to`、body 壞的**（body 不是物件、`ping` 或 `procs_state_path` 不是 `true`、名單類欄位不合格、指示詞解不開），daemon 回 `{"applied": false, "error": {"code": "BodyBad", "msg": "<原因>"}}`，`msg` 跟 `mailbox_warning` 冒號後同一句；信封壞、沒 `reply_to` 不回；回信寄不出去不管（決定 27）（使用者 11-12「kernel那邊，小而獨立的可以做」，[kernel-small-fixes](../../../../thinking/2026-11/12/kernel-small-fixes.md) ②；代號一律 `BodyBad` 是代定、可翻案）。要知道結果的標準做法是讀 `procs_state.json`。
    - 信多認 `{"ping": true}`，不改底；有 `reply_to` 照舊對完表回 `{"applied": true}`，收了算有反應。`ping` 不是 JSON `true`＝整封壞信，`mailbox_warning` 寫 `ping must be true`、不套其他 key，有 `reply_to` 照上一點回 `BodyBad`（[kernel-small-fixes](../../../../thinking/2026-11/12/kernel-small-fixes.md) ②）；有效 `ping: true` 跟其他 key 同一封，其他照常套。暫停、收工那圈本來就不認領信＝不回＝等信的呼叫者當失敗（使用者「寄信不回，等同於呼叫失敗」）。人用 `aos-daemon-ctl ping`：回信到＝`replied in N ms`，沒回＝`DaemonFailed`（`DaemonMissing` 只留沒設／daemon 資料夾不在）（sol 審查 #28 使用者裁定）；`ls`、`listen` 讀檔、不寄 ping。經判官（`AOS_KERNEL`）時，判官照 C-48 原樣轉寄 ping（[P2](../../../../thinking/2026-11/05/no-pid/09-P2實作結果.md)、[P3](../../../../thinking/2026-11/05/no-pid/10-P3實作結果.md)）。
    - 信也認「表在哪」查詢信 `{"procs_state_path": true}`（使用者 11-11「…或許可以折衷？寄信問，取得狀態位址這樣。」、選項框「kernel 給一個狀態位址」，C-47 ①，[kernel-framework 03](../../../../thinking/2026-11/12/kernel-framework/03-狀態查詢信.md)；[aos-daemon 信箱](../../../../cpp/aos-daemon/docs/05-信箱.md)）：不改底；有 `reply_to` 的，對完表回 `{"applied": true, "procs_state_path": "<自己那份 procs_state.json 的絕對路徑>"}`，沒開 `procs_state` 窗＝值寫 `null`；沒問的信回信不多帶這個 key。值不是 JSON `true`＝整封壞信（`mailbox_warning` 寫 `procs_state_path must be true`、不套其他 key、有 `reply_to` 回 `BodyBad`，回信不帶這個 key）；有效的 `procs_state_path: true` 跟其他 key 同一封，其他照常套。不動持久格式。一般 proc 不直接寄 daemon，而是寄 `AOS_KERNEL`；中間的框架站不認得這個 key、照樣轉（要給刪減表的站在 `before_reply` 換掉路徑，是圖紙的做法）；問的那一邊怎麼用見 [N-63 的 `ctl who`](../../10-基礎設施-定義與工作區/07-hub-型環境變數與父子交代/02-N-63-實例-AOS_DAEMON與沒有AOS_HUB.md)。
      - 例：整棵鏈劇本第 3 段驗過——只設 `AOS_KERNEL` 的 agent 經站 A 的 `before_reply` 拿到只有自己與它的子的表（批 7b）。
