  - **認哪些 key**：`procs`＝「我要表上有誰」（整份名單）、`procs_added`、`procs_removed`、`procs_stopped`、`procs_started`、`seq`（回音在 `state_flux.json` 的 `procs_ctl_seq`；**11-09 補**（使用者裁 state_flux，[thinking clock-and-hot-writes 05](../../../thinking/2026-11/09/clock-and-hot-writes/05-state拆分規劃.md)））。daemon.json 不認後四個（起來的名單就是 `procs`）。daemon 自己的 `ctl.json` 只認 loop 那幾個（`cmd`、`max`、`interval_ms`、`seq`），名單的 key 寫在那裡＝不認得的 key、忽略（C-48），不提醒（使用者 11-03「當沒看到」，[thinking 11-03 procs § 4](../../../thinking/2026-11/03/procs/07-4-舊名怎麼辦-遷移-當沒看到.md)）。每圈先讀 `ctl.json`、再讀 `procs_ctl.json`，各自採用或不採用，一份壞不影響另一份；daemon 暫停中，名單變動等解除暫停那圈才生效（[N-07](../05-基礎設施-窗/01-N-06～N-08.md)）。
    - **11-06 註（no-pid P5b）**：信箱的信另認 `ping`（見 [N-28「信箱」的 ping 那點](02-N-28.md)、[P2 結果](../../../thinking/2026-11/05/no-pid/09-P2實作結果.md)）。`procs_ctl.json` 裡的 `ping` 是不認得的 key，不驗它是不是 `true`、不做 ping、不回信；其他認得的 key 照常處理。不過程式採用時保留整份內容作比較，所以只改這個不認得的 key，也會使內容不同、更新 `responded_at`。
  - **每項寫法**跟著 N-28（「名單 `procs`」「起 loop 型」）：字串、陣列＝aos-exec 的目標；物件照 N-28 看寫法決定型，它的 `exec` 可以是字串目標，也可以直接放單子物件（由子 loop 在自己行程內跑；`cwd` 與相對 `$ref` 照 N-28 同一套補成 daemon 的 cwd、轉成絕對）（使用者 10-24「不過exec本來就應該要可以直接放內嵌單子吧」「好，就這樣做」，[thinking 10-24](../../../thinking/2026-10/24/exec-relative/01-使用者原文.md#10-24-exec-直接放單子)；使用者 10-26「規範那邊N-54改成可放單子物件。」）。每項同樣可以帶 `ws`（子項的工作區，語意同 N-28「每項選填 `ws`」；使用者 10-30「都照建議」，[thinking 10-30 eca](../../../thinking/2026-10/30/eca/09-方向題.md#決定10-30) 衝突 1、3）；從外面掛上的命令列 [aos-daemon-ctl](../../../cmd/README.md) 的 `add --ws WS` 就是寫這個 key（WS 從呼叫當下的 cwd 轉絕對）。
  - **宣告式，可以只寫變動的**（使用者 10-23「ctl這塊我會想要是"啓動XXX loop/刪除XXX loop"，而不是每次都讓他讀全部」；使用者選「維持宣告式，但可以只寫變動的」，[thinking 10-23 ctl 與 $ref](../../../thinking/2026-10/23/daemon-ctl-ref/README.md)）：`procs_ctl.json` 是宣告的名單，不跟 loop 的 ctl 一起改成指令。`procs_added`＝名單上要多這些（寫法同 `procs`，要拆檔同 N-28 用 `$ref` 陣列）、`procs_removed`＝名單上要少這些（名字的陣列）；key 名照 C-54 R4「ctl 的 key 用狀態詞」（同 `stop` → `stopped`）。
    - **期望表＝（`procs_ctl` 的 `procs`，沒寫＝底的）＋`procs_added`－`procs_removed`**，先加後減：同一個名字兩邊都寫＝不要；`procs_removed` 寫了名單上沒有的名字＝不管；名單上已有的名字寫進 `procs_added`＝設定換成這份、已在跑的不重起；名字已在表上的不看設定變了沒。**底**：只開 `procs_ctl` 時就是 daemon.json 的 `procs`，也開了信箱時再加 adopt 接回的與信改過的（N-28「信箱」）。
    - **要停的名字（stopped 集合）同一套**：`procs_stopped` 加、`procs_started` 減，同名兩邊都寫＝起。

  - **多人要改名單**：兩個人同時改 `procs_ctl` 會互相蓋掉（後寫的算）：靠 Linux 檔案權限讓它只有一個寫的人（例 kernel 當這份手把的唯一寫者），不另加機制（10-16 使用者，[C-64](../../CONCEPTS/01-設計理念/05-布局成長與檔案權限.md#檔案權限10-16-使用者定)）；或用名單的信箱 `procs_requests`（N-28「信箱」），跟 `procs_ctl` 可以同時開（使用者 11-02 晚「我希望信箱和loops_ctl共存，或者說兩者都可以在daemon.json中設定」，[thinking 11-02 state 窗](../../../thinking/2026-11/02/state-window/01-使用者原文-11-02-逐字.md#決定11-02-晚使用者實作中陸續裁的)）。信箱沒寫＝開在 `procs_requests/`、`null`＝不開；名字回報在 `procs_state.json` 的同名欄，aos-daemon-ctl 從那裡找信箱（[thinking 11-04 four-elements](../../../thinking/2026-11/04/four-elements/06-要使用者裁的題.md#使用者裁定11-04選項原文或他的話逐字) 題 5；N-28 11-04 ②）。信的 `body` 是 `procs_added`／`procs_removed`／`procs_stopped`／`procs_started`／`procs_slept`／`procs_woken` 片段（11-10 prefix-fixes 坑-12：對齊源碼）（沒有整份的 `procs`），每圈全部認領、照順序套用；壞信不套、記 `state_flux.json` 的 `mailbox_warning`（11-10 prefix-fixes 坑-12：對齊源碼）；誰能寄同樣靠 Linux 檔案權限。
  - **起、停、暫停**（loop 的 ctl 改指令：使用者 11-03「還是用指令吧，不然大家不好理解。但是loop就不要用mailbox那套，就是誰能寫ctl.json就能控制。」，[11-03 ctl-commands](../../../thinking/2026-11/03/ctl-commands/README.md) § 5）：
    - **stop**（loop 型；**11-07 使用者裁定 B（11-07 使用者確認翻案（B 落實時））**：此範圍已翻，現為任何 proc）：daemon 往子 loop 的 `ctl.json` 寫一道 `{"cmd": "stop", "seq": N}`，子 loop 跑完這一次自己退 0；等的途中列是 `stopping`，退了**列留在表上**、`phase` `stopped`、stack 不碰。
    - **start**：用列上的 `stack` 再起，**不用先清 ctl**（首次讀 ctl 比對舊 state_flux.json 的 `ctl_seq`（11-09 起，N-09 的 11-09 補），兩邊都是有效數字 seq 且相同＝已做、不重做；不同、舊 state_flux 不存在或缺欄＝照一般指令做並以 `responded_at` 回音（代定（11-07 落實時，可翻案）），未做過的 stop 會立即生效）。（11-07 使用者裁定 sol 審查 #15-2）；起來是跑還是暫停看它自己 state.json 的 `paused`（代定，ctl-commands § 4）。只有指令叫起：信來、手把別的 key 變、同名 `procs_added` 都不把 stopped 的拉起來。
    - **pause／resume、改節奏**不經 daemon：直接寫子 loop 的 `ctl.json`（誰都可以寫，N-06；[aos-daemon-ctl](../../../cmd/README.md) 的 `pause`／`resume` 就是寫 `{"cmd": "pause"}`／`{"cmd": "resume"}`），要看它＝讀它的 state 窗；daemon 不轉述 paused（不讀子項的 state，C-52）。daemon 回報實際的表在 `procs_state.json`（N-28）。
    - **exec 型只有跑和拔**（使用者「他停下來就是沒了，新開的就是新的CPU了」）：`procs_stopped`／`procs_started` 寫到 exec 型的名字＝手把整份不採用、記 `procs_ctl_warning`；信＝壞信。
      - **11-07 使用者裁定 B（11-07 使用者確認翻案（B 落實時））**：上列舊句已翻。使用者原話：「hmmm，果然不可以用陣列形或物件形來分，還是得去看關鍵的interval_ms，看有沒有這個key」；接著：「等等，不過有個問題：argv:[aos-loop loop.json]，我用aos-exec執行，這等同於我變成了aos-loop，然後去跑loop.json設定。在變成loop之前，我確實就是一次性程式沒錯」。最後**選 B：daemon 不分類**；前句看 interval_ms 的想法未採用。任何列可 stop／start／sleep／wake；stop 寫公開 ctl 並等自行退，不送 SIGTERM；小格父寫的 loop 設定有非空 ctl 就用它，否則 ctl.json。寫不了只 warning、照等。
      - **11-06 改讀（no-pid P6）**：這句管的是**沒寫 `auto_restart` 的** exec 型；寫了 `auto_restart: true` 的算常駐，可以 stop／start／sleep／wake（沒有 ctl＝daemon 送 SIGTERM）。使用者 11-06 選項框「通用 restart: true (Recommended)」（[no-pid 15](../../../thinking/2026-11/05/no-pid/15-P6去耦合.md)）。
        - **11-07 使用者裁定 B（11-07 使用者確認翻案（B 落實時））**：上列「只放行 auto_restart」與「沒有 ctl 就送 SIGTERM」已翻；auto_restart 只管自然結束後重起，與 stop／sleep 能否採用無關。
    - 繞過 daemon、自己往子 loop 的 ctl 寫 `{"cmd": "stop"}`：子項退了，從表上拿掉（N-28「子項結束後不自動重起、不留名單」；＝對 daemon 不存在，叫不回）；掛在 daemon 下要停就走 daemon。
  - **工作區不放子項的 stack**（使用者 11-03「那其實.stack根本不需要放到ws那邊」，看完四題建議回「那四題照建議，只是say/listen這塊之後還要再改。」；[thinking 11-03 stack-where](../../../thinking/2026-11/03/stack-where.md)；照實作寫）：daemon 像硬體，子項的 stack 像 CPU 的暫存器、歸 daemon 管（`<daemon 的 AOS_STACK>/procs/<名字>/` 或列上的 `stack`），`ws`／`AOS_WS` 只是交給子項的一個位址。所以 aos-daemon-ctl 的 `add --ws` 不在 `<WS>/.stack` 建捷徑、`rm` 不拆；要找某個子項的 stack 用 `aos-daemon-ctl where --stack 名字`——**只認 daemon 表上的**（含 `stopped` 的列；使用者「一個proc在daemon中的狀態，包括運行中、暫停中，除此之外就是不存在於daemon了」「拿下名單後，對於daemon來說他就不存在了，自然找不到」），表上沒有＝`ProcMissing`。對它說話＝`aos-agent say --target 名字 …`（工具的事、不算規範；[aos-agent](../../../cmd/aos-agent/README.md)）。

**sleep 的 stopping 例外**（11-07 晚審第 3 題，使用者選 A）：`stopping` 的列也准許 sleep，改送 SIGTERM；原本 stop 途中的列退後留 `stopped`，保留入口與 stack，之後用 start 再起。其他 sleep 仍留 `sleeping`、用 wake 醒。

**pause／resume 的 PhaseBad**：aos-daemon-ctl 對 `stopped`／`sleeping` 子項仍不准寫 pause／resume；理由是該狀態沒有正在讀 ctl 的執行個體，應先 start／wake，並非首次讀 ctl 不執行。（代定（11-07 落實時，可翻案））
