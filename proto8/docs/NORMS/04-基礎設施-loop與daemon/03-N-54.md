- **N-54**（10-16 定；10-22 定稿，[ideas 10-22 § 5](../../../thinking/2026-10/22/ideas/03-5-loop.md#5-loop10-22)）**daemon 表上有誰，寫在 daemon 的 ctl 窗**：daemon 的 ctl 多認一個 `loops`＝「我要表上有誰」，每項寫法同 N-28 的 `loops`；照 N-06 是整份期望——ctl 有 `loops` 就照它（多出來的起、少掉的收掉移除），沒寫＝回 daemon.json 的 `loops`。要暫停、停掉、改某個子 loop 的節奏＝直接寫它的 ctl（誰都可以寫，N-06），要看它＝讀它的 state 窗；daemon 回報實際的表在自己的 state 窗（N-28）。這是 N-11「ctl 只能蓋節奏類 key」的例外。（使用者 10-16 設定，它的 `exec` 可以是字串目標，也可以直接放單子物件（由子 loop 在自己行程內跑；`cwd` 與相對 `$ref` 照 N-28 同一套補成 daemon 的 cwd、轉成絕對）（使用者 10-24「不過exec本來就應該要可以直接放內嵌單子吧」「好，就這樣做」，[thinking 陣列）、`loops_removed`＝名單上要少這些（名字的陣列）；key 名照 C-54 R4「ctl 的 key 用狀態詞」（同 `stop` → `stopped`）。**期望表＝（ctl 的 `loops`，沒寫＝daemon.json 的 `loops`）＋`loops_added`－`loops_removed`**，先加後減：同一個名字兩邊都寫＝不要；`loops_removed`   - **10-29 改口：daemon 表上有誰，寫在 daemon 的管轄手把 `loops_ctl.json`**（使用者 10-28「一個控制loop面向和自身屬性，一個控制管轄的aos函數」、10-29「ctl和投遞信箱並存，那就是程式設計者自己決定哪個負責哪個，這就是兩套模式」；看完衝突與方向題回「都照建議」，[thinking 10-29 medium-plan](../../../thinking/2026-10/29/medium-plan/README.md) § 四、決定 5、條文草稿）：上面說的「daemon 的 ctl」改讀成 `loops_ctl.json`（路徑見 N-28「兩個手把、兩扇狀態窗」）——`loops`、`loops_added`、`loops_removed`、`seq` 的語意一字不改（宣告式、先加後減、整份壞就不採用、記進 `loops_state.json` 的 `ctl_warning`）；`ctl.json` 只認 loop 那幾個（`paused`、`stopped`、`max`、`interval_ms`、`seq`），**不再認這三個**（寫了＝不認得的 key、忽略，C-48；過渡期在 `state.json` 的 `ctl_warning` 提醒已搬到 `loops_ctl.json`、之後拿掉，衝突 5）。每圈先讀 `ctl.json`、再讀 `loops_ctl.json`，各自採用或不採用，一份壞不影響另一份；`paused` 時名單變動等解除暫停那圈才生效（[N-07](../05-基礎設施-窗/01-N-06～N-08.md) 的 10-29 補）。末句補：多人要改名單，除了靠 Linux 權限讓一人寫手把，也可以改開信箱模式（`loops_mailbox`，N-28「信箱」）——信的 `body` 是 `loops_added`／`loops_removed` 片段，每圈全部認領、照順序套用，誰能寄同樣靠 Linux 檔案權限。
  - **10-30 補：`execs_added`／`execs_removed`**（exec 型子項，N-28「起 exec 型」；使用者 10-30「都照建議」，[thinking 10-30 agent-lifecycle](../../../thinking/2026-10/30/agent-lifecycle/07-衝突.md#決定10-30) 條文草稿、衝突 3；照實作寫，[impls/aos-daemon](../../../impls/aos-daemon/README.md)）：`loops_ctl.json` 與信箱模式的信多認 `execs_added`／`execs_removed`，語意同 `loops_added`／`loops_removed`（先加後減、整份壞就不採用）。`loops_ctl.json` **沒有整份的 `execs`**：`execs` 那半的期望表＝daemon.json 的 `execs`＋`execs_added`－`execs_removed`。合出來 `loops` 與 `execs` 同名＝整份不採用、記 `ctl_warning`；信箱模式的信套完同名＝壞信、不套、記 `letter_warning`。
  - **10-30 夜補：`*_added` 帶 `ws`**（子項的工作區，N-28「每項選填 `ws`」；使用者 10-30「都照建議」，[thinking 10-30 eca](../../../thinking/2026-10/30/eca/09-方向題.md#決定10-30) 衝突 1、3、條文草稿；照實作寫）：`loops_ctl.json` 的整份 `loops`、`loops_added`／`execs_added`、信箱模式的信，每項同樣可以帶 `ws`，語意同 N-28。從外面掛上的命令列 [aos-daemon-ctl](../../../bin/README.md) 的 `--ws WS` 就是寫這個 key（WS 從呼叫當下的 cwd 轉絕對）；10-30～11-02 它順手在 `<WS>/.stack` 不在時建一個 symlink 指到 daemon 給那一隻的小格，cd 到 WS 打 aos-say 就接上（衝突 3；工具的事、不算規範）——**11-03 拿掉**，見下一條。
  - **11-03 補：工作區不放子項的 stack**（使用者 11-03「那其實.stack根本不需要放到ws那邊」，看完四題建議回「那四題照建議，只是say/listen這塊之後還要再改。」；[thinking 11-03 stack-where](../../../thinking/2026-11/03/stack-where.md)；照實作寫）：daemon 像硬體，子項的 stack 像 CPU 的暫存器、歸 daemon 管（`<daemon 的 AOS_STACK>/loops/<名字>/`），`ws`／`AOS_WS` 只是交給子項的一個位址。所以 [aos-daemon-ctl](../../../bin/README.md) 的 `add --ws` 不再在 `<WS>/.stack` 建捷徑、`rm` 不再拆；要找某個子項的 stack 用 `aos-daemon-ctl where --stack 名字`——**只認 daemon 表上的**（使用者「一個proc在daemon中的狀態，包括運行中、暫停中，除此之外就是不存在於daemon了」「拿下名單後，對於daemon來說他就不存在了，自然找不到」），表上沒有＝`ProcMissing`。對它說話＝`aos-say --stack $(aos-daemon-ctl where --stack 名字) …`（工具的事、不算規範；say／listen 使用者之後重做）。
  - **11-02 改口：`loops_ctl` 認整份 `execs`、跟信箱共存**（使用者 11-02 晚「loops這塊...也弄個execs吧」「我希望信箱和loops_ctl共存，或者說兩者都可以在daemon.json中設定」，[thinking 11-02 state 窗](../../../thinking/2026-11/02/state-window/01-使用者原文-11-02-逐字.md#決定11-02-晚使用者實作中陸續裁的)；照實作寫，[impls/aos-daemon](../../../impls/aos-daemon/README.md)「loops_ctl 只寫變動」「信箱」）：`loops_ctl.json` 多認整份的 **`execs`**（跟 `loops` 對稱，寫了就取代底的 `execs`；驗法同 `execs_added`，壞了整份不採用）；上面 10-30 補「`loops_ctl.json` **沒有整份的 `execs`**」不再成立。期望表裡說的 daemon.json 的 `loops`、`execs` 改讀成「底」：只開 `loops_ctl` 時底就是 daemon.json，也開了信箱時底再加 adopt 接回的與信改過的（N-28「信箱」）——**期望表＝（`loops_ctl` 的 `loops`，沒寫＝底的）＋`loops_added`－`loops_removed`**，`execs` 同理。10-29 改口末句「也可以改開信箱模式」（`loops_mailbox`）改讀成「另開信箱 `loops_ctl_mailbox`、可以跟 `loops_ctl` 同時開」；10-30 補的「記 `letter_warning`」改讀成 `mailbox_warning`。信的 `body` 不變（還是只有 `*_added`／`*_removed`，沒有整份的 `loops`／`execs`）。
  - **11-03 改口：手把與信改 `procs_*`，多了 stop／start**（使用者 11-03「所以相關指令就是start/stop/add/rm/pause/resume」「所以add/rm是動作，相關的狀態就是started/stopped」「只有指令叫醒。然後loop就是原生支援暫停和休眠的，exec就是只有執行中和拔掉」「照舊拿掉」；loop 的 ctl 改指令：「還是用指令吧，不然大家不好理解。但是loop就不要用mailbox那套，就是誰能寫ctl.json就能控制。」；[thinking 11-03 procs](../../../thinking/2026-11/03/procs/README.md) § 0、§ 2c，[11-03 ctl-commands](../../../thinking/2026-11/03/ctl-commands/README.md) § 5）：
    - **手把 `procs_ctl.json`** 認 `procs`、`procs_added`、`procs_removed`、`procs_stopped`、`procs_started`、`seq`；信箱 `procs_ctl_mailbox/` 的信認後四個。手把仍是宣告的名單，不跟 loop 的 ctl 一起改成指令。期望表算法照舊；要停的名字（stopped 集合）同一套：`procs_stopped` 加、`procs_started` 減，同名兩邊都寫＝起；照 N-06 沒寫＝回初始值，手把拿掉名字＝起。
    - **stop**（loop 型）：daemon 往子 loop 的 `ctl.json` 寫一道 `{"cmd": "stop", "seq": N}`（上面「要暫停、停掉某個子 loop＝直接寫它的 ctl」就是這條），子 loop 跑完這一次自己退 0；等的途中列是 `stopping`，退了**列留在表上**、`phase` `stopped`、stack 不碰。
    - **start**：用列上的 `stack` 再起，**不用先清 ctl**（loop 起來第一次讀到的 ctl 當基準線、不執行，殘留的 `{"cmd": "stop"}` 沒事）；起來是跑還是暫停看它自己 state.json 的 `paused`（代定，ctl-commands § 4）。只有指令叫起：信來、手把別的 key 變、同名 `procs_added` 都不把 stopped 的拉起來。
    - **pause／resume** 不經 daemon：[aos-daemon-ctl](../../../bin/README.md) 往子 loop 的 `ctl.json` 寫 `{"cmd": "pause"}`／`{"cmd": "resume"}`；daemon 不轉述 paused（不讀子項的 state，C-52）。
    - **exec 型只有跑和拔**（使用者「他停下來就是沒了，新開的就是新的CPU了」）：`procs_stopped`／`procs_started` 寫到 exec 型的名字＝手把整份不採用、記 `ctl_warning`；信＝壞信。
    - 繞過 daemon、自己往子 loop 的 ctl 寫 `{"cmd": "stop"}`：子項退了，照 11-02 從表上拿掉（＝對 daemon 不存在，叫不回）；掛在 daemon 下要停就走 daemon。
    - 上面 11-03 補（工作區不放子項的 stack）的 `<daemon 的 AOS_STACK>/loops/<名字>/` 讀成 `procs/<名字>/` 或列上的 `stack`；`where` 只認表上的（含 `stopped` 的列）。
