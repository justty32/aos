- **N-28**（候選 g，10-14 夜末使用者拍板；10-22 定稿，[ideas 10-22 § 5](../../../thinking/2026-10/22/ideas/03-5-loop.md#5-loop10-22)）**daemon.json 是 loop.json 的嚴格超集**：同名 key 同義（節奏、窗、收尾、`id`；`id` 現行沒有），預設值可以不同（daemon `max` 預設不限、`interval_ms` 200；loop `max` 沒寫＝不限、`interval_ms` 0；10-14 深夜定：「沒寫 `max` 的 loop.json 丟給 daemon 會一直跑」）。一份合法的 loop.json 直接丟給 aos-daemon 也要能跑。daemon.json 多的 key 只有 `procs`、`adopt`、`procs_ctl`、`procs_state`、`procs_ctl_mailbox`；`procs`、`adopt` 只寫在 daemon.json（新程式盡量不收旗標，N-11；使用者 10-21 晚「新程式不收旗標...沒關係的，那是軟性，應該改成"盡量不收"」）。認不得的 key（含改名前的 `loops`、`execs`、`loops_*`）照 C-48 當沒看到：不報錯、不提醒、不過渡（使用者 11-03「1. 當沒看到。」，[thinking 11-03 procs](../../../thinking/2026-11/03/procs/README.md)）。
  - **命令列**同 aos-loop（共用）：`aos-daemon [FLAGS] daemon.json [-- ARGS...]`；設定檔是唯一的位置參數，可寫 `檔#/指標`；旗標 `--max`、`--interval-ms`、`--ctl`、`--state`、`--enable-logs`（[ideas 10-21 § 8](../../../thinking/2026-10/21/ideas/05-7-審後的五個細縫與修正.md#8-aos-loop10-21-下午)、[計畫 10-21](../../../thinking/2026-10/21/plan/README.md) D1～D4；[ideas 10-21 § 9](../../../thinking/2026-10/21/ideas/05-7-審後的五個細縫與修正.md#9-設定檔是唯一的位置參數path-改字串拼接10-21-傍晚)）。`-- 參數...` 只接在 daemon 自己的 `exec` 後面、每次都帶，不影響子項；沒有 `exec` 卻給了＝`ArgumentsBad`（代定）。
  - **`exec`**＝daemon 自己每次串行跑一次的身體；跑法跟 loop 一樣（阻塞到它結束）；在 daemon 裡**選填**（純監工不需要），在 loop 裡必填。字串＝aos-exec 的目標（`aos-exec` 它；同 P-06；`daemon.json#/body` 這類 `檔#/…` 就是普通的 aos-exec 目標）；陣列＝`[目標, 參數...]`；也可以直接放單子物件（使用者 10-24「不過exec本來就應該要可以直接放內嵌單子吧」「好，就這樣做」，[thinking 10-24](../../../thinking/2026-10/24/exec-relative/01-使用者原文.md#10-24-exec-直接放單子)）——loop／fsm／daemon 拿到物件時在自己行程內用 aos-exec 跑單子的同一套（`run_inst`、inst 的 C lib；`timeout_ms`、訊號、結束碼都一樣）跑，跑的期間 `AOS_CF`＝寫著它的設定檔、`AOS_CD`＝那份檔的資料夾（也是相對路徑的基準）、`AOS_CO`＝它在檔裡的位置（`/exec`、`/states/<名>/exec`）；單子壞＝那支程式自己的錯、退 1。daemon 自己的 `exec` 那次繼承同一個 `$AOS_STACK`。
  - **名單 `procs`**＝`{名字: proc}`（使用者 11-03「exec和loops，其實都屬於proc」「連名單也合一」）。名字就是子項的 `id`，沒寫 `stack` 時也是小格 `$AOS_STACK/procs/<名字>/` 的名字（P-17；子項名字是名單給的，跟 daemon 自己的固定名分開，[thinking 11-02 stack-tools](../../../thinking/2026-11/02/stack-tools/README.md) 細節 5）。名字不能空、不能含 `/`、不能 `.` 開頭、不能帶 `#`（`#` 是頂層自定，ideas 10-21 § 9.3 第 5～7 點）；跟 daemon 自己的窗同名不擋（使用者 11-02「那兩題中的1.，可以」）。**daemon 收子項只看它自己需要的**（C-52；10-15 深夜使用者「不留」）。每項**看寫法決定怎麼起**，沒有 `kind`（使用者 11-03「2.kind這東西沒用吧，刪掉」）：
    - 字串、陣列 `[目標, 參數...]`、或 key 只有 `exec`（可再加 `ws`、`stack`）的物件＝**exec 型**：aos-exec 跑一次。
    - 其他物件＝**loop 型**：一份 loop 設定、包成子 aos-loop（10-15 使用者『全定』）。裡面的 loop key 與單子 daemon 一概不驗、原樣灌給子 loop，寫錯了子 loop 自己退 1、錯在它的 stderr，daemon 只看到它結束；沒 `exec` 的物件一樣原樣交給子 loop，由它退 1（「沒有東西可跑」）。要用 loop 型跑單子，寫 `{"exec": "daemon.json#/procs/<名字>/body", "body": 單子}`（只跑一次再加 `"max": 1`）。
    - 坑：寫 `{"exec": "fsm.json"}` 想要一直跑的 loop 會變成跑一次，要 loop 就多寫一個 loop 的 key（例 `"interval_ms": 0`）。
    - 要一次跑完的東西也可以寫成 `{"exec": 它, "max": 1}` 的 loop（使用者 10-30「包成max:1也是可以」），差別只在多一層 aos-loop 與它的窗——小格裡外層 loop 的 `ctl.json`／`state.json` 會跟掛進去的 aos agent 自己的 loop 窗撞同一個檔（本檔開頭 ②），純黑盒子沒這問題。
    - 同名改寫法（loop 型與 exec 型互換、改了 `ws`、`stack`…）照 N-54「名字已在表上的不看設定變了沒」不重起，下一次起它才用新的。
  - **起 loop 型**（經 aos-exec，使用者「5.要」）：daemon 把子項設定補上 `ctl`／`state`（沒寫才補 `ctl.json`／`state.json`）、拿掉 `ws`、`stack`，一律蓋上 `"_entry": ["aos-loop", {"$env": "AOS_CF"}]` 寫成小格的 `loop.json`，起 `aos-exec -- 小格/loop.json#/_entry`（指到 `_entry` 不受 `$AOS_ENTRY` 影響）。相對路徑從 daemon 的 cwd 算：aos-exec 會 cd 進小格，所以 daemon 寫小格時把子項 `exec` 的目標（字串，或陣列的第一個元素）照 daemon 的 cwd 轉成絕對路徑；`exec` 是單子時由子 loop 在自己行程內跑（`AOS_CF`＝小格的 `loop.json`、`AOS_CO`＝`/exec`），單子沒寫 `cwd`＝補上 daemon 的 cwd、相對的 `cwd` 接在 daemon 的 cwd 後面（是指示詞就不動），單子裡相對的 `$ref` 檔名照它來自的那份檔轉成絕對、不解；`procs_ctl` 加的子項同一套（頂層代定，[thinking 10-24](../../../thinking/2026-10/24/exec-relative/01-使用者原文.md#10-24-exec-直接放單子)）。其他 key 不驗、不動。子項若是資料夾程式，用 `aos-exec` 跑（[N-58](../10-基礎設施-定義與工作區/02-N-58.md)）。
  - **起 exec 型**（使用者 10-30「不過可以的話，我也覺得讓daemon可以掛aos-exec，也是不錯的」、看完規劃回「都照建議」，[thinking 10-30 agent-lifecycle](../../../thinking/2026-10/30/agent-lifecycle/07-衝突.md#決定10-30)；照實作寫，[impls/aos-daemon](../../../impls/aos-daemon/README.md)）：daemon 對它直接 `aos-exec` 一次，**不包 aos-loop、不寫小格的 `loop.json`、不補 `ctl`／`state`**，表上的 pid 就是那支程式。目標是字串或陣列＝`aos-exec -- 目標 參數...`；`{"exec": 單子}`＝daemon 把它寫成小格的 `exec.json`（`{"exec": 單子}`，單子的 `cwd` 照 loop 型的單子那樣補），跑 `aos-exec -- 小格/exec.json#/exec` 一次（`AOS_CF`＝小格的 `exec.json`、`AOS_CO`＝`/exec`；單子沒寫 stdin／stdout＝接 `/dev/null`、stderr 附加到小格的 `stderr.txt`，寫了就照它）（使用者 11-02 回「daemon 的 execs 要不要也收內嵌單子」：「6.要。」）。
  - **兩型共通**：`AOS_STACK`＝小格（或那一項的 `stack`）；stdin／stdout 接 `/dev/null`、stderr 附加到小格的 `stderr.txt`（exec 型的單子寫了 stdin／stdout 就照它，見上）；自成 session 群組；cwd＝daemon 的 cwd。子項的環境除了 `AOS_STACK`（與寫了 `ws` 時的 `AOS_WS`），一律多設 `AOS_DAEMON`＝daemon 自己的 stack（絕對、結尾 `/`），只設這一個（舊名見[附錄3](../附錄3-舊名對照.md)；使用者 11-02 對常駐 bob 的衝突與方向題回「照建議走」，thinking 11-02 resident-bob（已封存） 衝突 2；條文在 [N-63](../10-基礎設施-定義與工作區.md)「daemon 起子項時把 `AOS_DAEMON` 設給它」，父子交代的例子在 N-64 ④）。
  - **每項選填 `stack`**（使用者 11-03「那就記錄在名單上。我是希望盡量不要用捷徑啦。」）：非空字串，相對路徑從 daemon 的 cwd 算、轉絕對；`null`＝當沒寫；沒寫＝小格 `procs/<名字>/`。不在就建（`mkdir -p`，建不了＝`MkdirFailed`）；裡面有什麼、兩項同一個 stack，都不查不擋、使用者自己承擔；不建捷徑；不灌進 `loop.json`。
  - **每項選填 `ws`**（這一隻的工作區；使用者 10-30「都照建議」，[thinking 10-30 eca](../../../thinking/2026-10/30/eca/09-方向題.md#決定10-30) 衝突 1；照實作寫，[impls/aos-daemon](../../../impls/aos-daemon/README.md)）：只有物件寫得了（字串或陣列寫法沒地方寫，要 `ws` 就寫成物件）。值是非空字串（指示詞照解），**相對路徑從 daemon 的 cwd 算**、轉成絕對存進期望表；`null`＝當沒寫；其他型別或空字串＝壞（daemon.json＝`CfgBad` 退 1、`procs_ctl` 整份不採用、信＝壞信）；在不在不驗（不在的話子項經 aos-exec 報 `WsMissing`）。daemon 起那個子項時把 `AOS_WS` 設成它；**沒寫＝繼承 daemon 的環境**。`ws` 不寫進小格的 `loop.json`（它不是 loop 的 key），只進環境；小格不因 `ws` 搬家。改了 `ws`，下一次起它才用新的（同名改寫法，見上）。`ws`、`stack` 是 daemon 拿走的 key：exec 型物件除了 `exec` 只認這兩個，loop 型物件除了這兩個原樣交給子 loop。原則：[N-55](../10-基礎設施-定義與工作區.md) 工作區由呼叫方設 `AOS_WS`，daemon 是呼叫方。
  - **子項的輸出：aos 不保證子項的輸出不無限長**（使用者 10-22「小地方那些我都OK」、四個實際問題都由使用者自己承擔，[ideas 10-22 § 5](../../../thinking/2026-10/22/ideas/03-5-loop.md#5-loop10-22)；使用者 10-22「3 N-28 未做的從規範拿掉、改寫自己接工具」，[ideas 10-22 § 6](../../../thinking/2026-10/22/ideas/03-5-loop.md#6-daemon10-22)）。aos-daemon 丟掉子項的 stdout（結果一律從 state 窗讀），子項自己與它每次的 stderr 全部附加到小格的 `stderr.txt`（daemon 自己開的檔，不只出錯時、不輪替、不設上限）；選填路徑、輪替、清舊格子都不做。要控制大小的人自己處理，風險使用者自己承擔：例如外面用 logrotate 的 copytruncate 截（檔是附加模式開的），或讓那次的單子用 `stderr` key 把輸出導到自己的檔、在那次裡把輸出接給 s6-log、svlogd（見 [notes/s6-runit](../../../notes/s6-runit.md)）——aos-loop 自己的那幾行仍會進小格。
  - **daemon 不清小格**（10-22 使用者確認：自己承擔）：表上沒列到的舊小格留著，同名子項再起時沿用那格、`stderr.txt` 接著附加，小格裡舊的 `ctl.json`、`state.json` 也留著，再起時怎麼讀照 [N-06](../05-基礎設施-窗/01-N-06～N-08.md)。要清自己在起 daemon 前刪。
  - **小格只建 `procs/` 與小格兩層**，不順手建出 `$AOS_STACK`：`$AOS_STACK` 不在＝state 或 procs_state 窗開了任一扇就 `WriteFailed`、兩扇都沒開才 `MkdirFailed`，都退 1、stderr 一行（建 stack 只在 aos-exec 做，N-59 第 1 件；直接跑 aos-loop 也一樣不建，見本檔開頭 ③）。寫了 `stack` 的見上（不在就建）。
  - **兩個手把、兩扇狀態窗**（使用者 10-28「一個控制loop面向和自身屬性，一個控制管轄的aos函數」、10-29「ctl和投遞信箱並存，那就是程式設計者自己決定哪個負責哪個，這就是兩套模式」；看完衝突與方向題回「都照建議」，[thinking 10-29 medium-plan](../../../thinking/2026-10/29/medium-plan/README.md) § 四）：
    - `ctl`、`state` 管 loop 面向與自身屬性，跟 aos-loop 同一套（上面「嚴格超集」）；慣用名 `ctl.json`、`state.json`（使用者 11-02 晚「控制自身的 ctl/state 檔案，那就是 ctl/state，不加前綴」，[thinking 11-02 ctl-state-names](../../../thinking/2026-11/02/ctl-state-names/README.md)），程式沒有預設名（沒寫＝不開，N-09）。
    - `procs_ctl`、`procs_state` 管轄的名單（手把怎麼寫見 N-54）與它的狀態窗：路徑，相對 `$AOS_STACK`；沒寫＝`procs_ctl.json`、`procs_state.json`。
    - `procs_ctl_mailbox`＝名單的信箱（路徑；沒寫＝不開；慣用名 `procs_ctl_mailbox`）。跟 `procs_ctl` 可以同時開、只開一個、都不開（都不開＝名單只看 daemon.json）（使用者 11-02 晚「我希望信箱和loops_ctl共存，或者說兩者都可以在daemon.json中設定」「loops_mailbox改名為loops_ctl_mailbox。寫null就是不開窗，ctl/ctl_mailbox可以一起不開」）。
    - `ctl`、`state`、`procs_ctl`、`procs_state`、`procs_ctl_mailbox` 寫 `null`＝不開（使用者 11-02 晚「daemon.json中的ctl/state，如果指定null，那就是不開窗」「寫null就是不開窗」）。
  - **`procs_state.json` 就是 save 檔**（daemon 不另留 save 檔；KISS 重審 3.3）：帶 `procs` 表（一項一列：`pid`、`started_at_ticks`、`phase`、`code`、`signal`、`stack`…）、`ctl_seq`（回的是 `procs_ctl.json` 的 `seq`）、`ctl_warning`（壞的 `procs_ctl`）、`mailbox_warning`（壞信，N-16；使用者 11-02 晚「letter_warning改成mailbox_warning」）、`pid`、`started_at_ticks`、`boot_id`，最後一欄 `updated_at`。每列的 `stack` 是絕對路徑（預設小格也寫）；起它時給了 `ws` 才多一欄 `ws`（起的那一刻的值）。**11-04 註**：每列多一欄 `exec`＝起它時的目標（字串目標、陣列的第一個、物件的 `exec`，照 daemon 的 cwd 轉絕對，`檔#/…` 片段照留；內嵌單子＝`null`），adopt 接回的照舊表帶過來（使用者 11-04 晚「daemon表多一欄記下來」，[thinking 11-04 aos-agent 06/02](../../../thinking/2026-11/04/aos-agent/06-衝突與方向題/02-新題-11-04-晚.md#使用者裁定11-04-晚選項原文) 方向題 1；aos-agent 從它找回定義資料夾）。**11-04 再註**：每列再多一欄 `def`＝proc 物件的 `def`（定義資料夾，絕對；沒給＝`null`；daemon 不驗、只記，aos-daemon-ctl add 一律送 XXX），aos-agent 改從 `def` 找定義、不再從 `exec` 推（使用者 11-04「那就b。」，[thinking 11-04 aos-agent 05/03 第 2 條](../../../thinking/2026-11/04/aos-agent/05-實作步驟/03-實作時改的設計.md#實作時改的設計)）。列的 `phase` 只有 `running`／`stopping`／`stopped`／`sleeping`。
    - **11-06 註（no-pid P5b）**：頂層多 `daemon`、`responded_at`，在 `procs_ctl_mailbox` 後、`procs` 表前；兩扇窗都有，定義與 state 的欄位順序見 [N-32 的 11-06 註](../05-基礎設施-窗/07-細則.md)。有變才寫的比對也算這兩欄（[P2 結果](../../../thinking/2026-11/05/no-pid/09-P2實作結果.md)）。
  - **`adopt`**（布林，**預設 `true`**；使用者 10-16：「給選項，默認留」，[KISS 重審拍板 2](../../../thinking/2026-10/16/kiss-recheck.md#使用者拍板10-16)；key 名 `adopt` 是頂層照 C-54 挑的——說的是「認領活著的子 loop」）：daemon 重起時讀自己上次的 `procs_state.json`，把還活著的子項接回（pid＋啟動時間對得上才認，N-17），不重起它們；`phase: stopped` 的列接回成 `stopped`（不起、不判活）；`sleeping` 的列接回後 wake（見下）；接回的列 `ws` 保留。adopt 與 start 照列上的 `stack`。寫 `false`＝不接回。第一次起來沒有舊的 state 就沒東西可接。
    - **11-06 註（no-pid P5b）**：P1 起另比表頂層 `boot_id`，跟這次開機不同＝表上的行程都當不在、照名單另起；表沒寫 `boot_id`＝當作別次開機；這台讀不到 `boot_id`＝不比，照舊 pid＋ticks（[P1 結果](../../../thinking/2026-11/05/no-pid/08-P1實作結果.md)）。
  - **子項結束後不自動重起、不留名單**（使用者 10-20「照預設」，[ideas § 25](../../../thinking/2026-10/19/ideas/README.md)；使用者 11-02 晚「改成子項結束後不留名單」，[thinking 11-02 state 窗](../../../thinking/2026-11/02/state-window/01-使用者原文-11-02-逐字.md#決定11-02使用者)；11-03「照舊拿掉」）：loop 型、exec 型都一樣，子項退了（`done`／`stopped`）印完 log 那行就從表上拿掉，小格留著；表上看不到結束的，結束碼看 log 那一行。只有兩個例外會留在表上：daemon 自己下的 stop（N-54）退了的列留成 `stopped`；daemon 收工時睡下的列留成 `sleeping`（下一條）。**11-05 晚加第三個例外**：loop 型出錯結束（退非 0）留成 `stopped`＋`reason`（見本條最後「11-05 晚補」⑤）。
    - 自己結束（`done`）的**本次執行不再起**——某一圈算出的期望表裡沒有它了才放掉（之後名單再有它就照常起）；開了信箱再從底拿掉，之後再有信同名 `procs_added`＝重新起。要再起：`procs_ctl` 從名單拿掉（daemon 看過一圈）再放回、再寄一封同名的信、或重起 daemon。

    ⑥ **daemon 的身體失敗＝記一行、下一圈再跑**（edge-daemon 題 1「記一行、下一圈再跑 (Recommended)」）：上面 `exec` 那條「跑法跟 loop 一樣」的例外——身體退 10 以外的非 0、或起不來，daemon **不收工**：stderr 一行（碼或錯變了才印；11-05 起是提醒行 `aos-daemon: warning: …`，好了那行也是——不退出就不寫錯誤行，N-43「stderr 只有兩種行」，代定 D4，[thinking 11-05 stdio-unify](../../../thinking/2026-11/05/stdio-unify/README.md)）、`state.json` 的 `body_code` 記最後一次的碼、`interval_ms` 後再跑；退 10 照舊收工。要整台停用 ctl 的 stop 或 Ctrl-C。aos-loop 本身照 P-20（那次非 0＝退）。細節 [aos-daemon docs/06](../../../impls/aos-daemon/docs/06-結束碼等.md#結束碼)。
