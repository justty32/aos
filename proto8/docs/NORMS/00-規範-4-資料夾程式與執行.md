## 資料夾程式與執行

**[基礎設施／資料夾程式與執行](10-基礎設施-定義與工作區.md)**（[N-57](10-基礎設施-定義與工作區/01-N-57.md)、[N-58](10-基礎設施-定義與工作區/02-N-58.md)、[N-59](10-基礎設施-定義與工作區/03-N-59.md)、[N-60](10-基礎設施-定義與工作區/04-N-60.md)、[N-61、N-62](10-基礎設施-定義與工作區/05-N-61～N-62.md)、[N-50、N-53、N-55](10-基礎設施-定義與工作區/06-N-50～N-53.md)）
- （無條號）用詞：資料夾程式（定義）＝一個資料夾；入口＝`$AOS_ENTRY` 指的檔；stack＝被叫的程式自己的 `$AOS_STACK`；小格＝叫別的資料夾程式時給它的 stack；工作區＝使用者的檔與成品所在的資料夾。N-57～N-62 是 aos 保證的底，N-50、N-53、N-55 是 10-16 定的，其餘全是慣例（在 CONVENTION）；條文講的是「aos-exec 這個角色」，不分實作。
- **N-57**（草稿）aos 只訂環境變數，共六個：`AOS_ENTRY`（入口在資料夾裡的相對位置，預設 `_entry`、不帶 `.json`）、`AOS_WS`（工作區）、`AOS_STACK`（自己執行中狀態放哪，預設 `$AOS_WS/.stack/`，子程式的由它自己訂）、`AOS_CF`（實際被執行的檔的絕對路徑）、`AOS_CD`（它所在的資料夾）、`AOS_CO`（入口在那份 JSON 裡的位置，不帶 `#`）；入口有四種：可執行檔、inst 單子、argv 陣列、`js[$AOS_ENTRY]` 的值。
- **N-58**（草稿）`aos-exec [FLAGS...] XXX [args...]`＝在工作區執行 XXX：前面是自己的旗標（`--dotenv-override`、`--ws`、`--stack`、`--stack-lazy` 四個），之後原樣傳下去，`--` 結束旗標；優先順序預設 旗標 ＞ 原本就有的環境變數 ＞ `.env` ＞ 預設，加 `--dotenv-override`＝旗標 ＞ `.env` ＞ 原本的 ＞ 預設；旗標只管這一次。
- **N-59**（草稿）aos-exec 只做這幾件事：1 定工作區與 stack（工作區在不在、轉絕對只在這裡做；`AOS_STACK` 沒設就設預設、建資料夾，`--stack-lazy` 那一跳不建）；2 照 N-61 認出 XXX；3 export `AOS_CF`／`AOS_CD`／`AOS_CO`；4 走進去（cd）、讀那裡的 `.env`（預設不蓋）、讀完才照當下的 `$AOS_ENTRY` 挑入口，沒 `argv` 的 JSON 物件當資料夾一路往下；5 開跑：可執行檔與 argv 陣列＝exec 入口，inst 單子＝行程內跑、以子程式的碼結束；`+x` 沒 `#!` 的檔三處（可執行檔入口、argv 陣列入口、單子 `argv[0]`）用 `/bin/sh` 跑。
- **N-60**（草稿）aos-exec 自己的錯一律退 1、stderr 一行 `aos-exec: error: 代號 原因`：命令列不合、`.env` 讀不到或壞（訊息絕不印值，頂層代定）、WS 不是資料夾、入口找不到、入口壞、exec 失敗；沒 `+x` 不是錯，當 JSON 讀。
- **N-61**（草稿）找入口：資料夾→`XXX/$AOS_ENTRY`，沒有再找 `.json`（同名資料夾贏）；XXX 不是資料夾、沒有副檔名、又找不到＝找 `XXX.json`；JSON 不是單子就找 `js[$AOS_ENTRY]`；種類看內容（`+x` 且像程式＝可執行檔，其餘當 JSON 讀，有 `argv`＝單子）；值是字串＝路徑轉向（全新的一跳）；繞圈由 aos-exec 偵測；`argv[0]` 沒 `/` 照 PATH 找，有 `/` 又 exec 不了＝前面插 `aos-exec`。
- **N-62**（草稿）路徑支援 JSON 尋址 `檔#/指標`（RFC 6901）；第一個 `#` 就切、`#` 後面一定要 `/`；資料夾或可執行檔帶 `#/`＝入口壞。
- **N-50**（草稿）工具＝資料夾程式，放在呼叫它的那一格的 `tools/<名>/`、不用 PATH；叫工具時給它小格 `$AOS_STACK/tools/<名>/`；參數怎麼進由工具自己的說明定；aos 自己的指令由呼叫者放進 PATH。
- **N-53**（草稿）aos 的 agent 是被外面驅動的狀態機：每次被叫只走一次，由外面的 loop 驅動，idle 沒題退 10；某格出錯那一次退非 0、state 不動，重試幾次由人或外面決定，agent 自己不數連錯。
- **N-55**（草稿）工作區的位置由環境變數 `AOS_WS` 給，自然往下傳給所有子行程；工作區保持乾淨，執行時的東西都放 stack。

**[hub 型環境變數](10-基礎設施-定義與工作區/07-hub-型環境變數與父子交代.md)**（[父子交代 N-64](10-基礎設施-定義與工作區/08-父子交代.md)）
- **N-63**（草稿）hub（全樹共用的那一個東西）用環境變數指，只定三件事：① 命名 `AOS_<名字>`，值是一個資料夾的路徑；② 沒設定＝報錯 `<名字>Missing`、不自己猜（或在四種性質表那一列寫明唯一一條退路）；③ 子 process 預設繼承。實例 `AOS_STACK`（只有 aos-exec 給預設）、`AOS_LLM_KERNEL`、`AOS_KERNEL`（沒設＝`$AOS_DAEMON` 的 ctl 信箱）、`AOS_DAEMON`（daemon 起子項時設給它；沒設找 cwd 的 `./.stack`）、`AOS_CLOCK`（值是檔；沒設＝退回牆鐘）；`AOS_AGENT` 是例外、不是 hub；沒有 `AOS_HUB`。
- **N-64** 父子交代（選用）：上一代給 args、stdin、六個環境變數與 hub 型變數；下一代留結束碼、stdout、stack 裡的檔；要自報身分就報 `$AOS_WS`；要讓下一代找到信箱或窗，用 hub 型變數或 args 明給，不另加環境變數。

**[可遷移性檢查單](10-基礎設施-定義與工作區/09-N-67.md)**（[⑩](10-基礎設施-定義與工作區/09-續-N-67.md)）
- **N-67** ① image 裡的位址一律相對 daemon 的 stack；② 期限用 cycle、跨樹用毫秒；③ 原生機制：表列設定（`limits` 等）由 daemon 起子行程時套用；④ 行程狀態（pid、`started_at_ticks`、`boot_id`、鎖）不是真相；⑤ root 例外：root daemon 的這台綁定不進 image，搬家＝照食譜重建 root；⑥ 檢驗法：睡著→搬→另一台醒來接著跑；⑦ 環境變數的值不落檔；⑧ 密鑰只走環境、不落檔；⑨ 環境變數只指樹內或 root 層以上；⑩ 只會往後加的 log 不進 image。

**[函數的 `_metainfo`](10-基礎設施-定義與工作區/10-N-68.md)**（[N-68 續](10-基礎設施-定義與工作區/10-續-N-68.md)、[N-69](10-基礎設施-定義與工作區/11-N-69.md)）
- **N-68** `_metainfo.json` 裡估的成本放 `cost`（`token`、`counter_calls`、`time_ms`，值照 C-48 雙形），估時 `cost.time_ms` 跟頂層的逾時 `timeout_ms` 分開；設計者寫的估值與 agent 自報的分清；metainfo 不強迫；實測記在叫的人自己 stack 的 `observed.jsonl`。
- **N-69** `_metainfo` 是函數的那排屬性：資料夾的 `_metainfo.json` 或 JSON 的 `_metainfo` key，讀的人看手上那一處、不順著入口往下追；通用 key 全選填；全是觀點、參考用，壞了＝當沒寫；實測不回寫；`tooldef`／`index` 也可以寫在裡面，推薦裡外都讀、外面贏；模型看不到特性。
