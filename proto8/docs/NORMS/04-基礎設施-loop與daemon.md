# 基礎設施／loop、daemon

> loop 是 `aos-loop [旗標] loop.json`（`{"exec", "max"}`，子程式退 10 就停，P-06、P-19；設定檔是唯一的位置參數，N-11）。**key 名以現行 loop.json 為準**（10-19 晚使用者定：「那就用到最新的吧」，[ideas § 22](../../thinking/2026-10-19-ideas.md)）：身體叫 `exec`、跑幾次叫 `max`，daemon 與窗的條文（N-06、N-07、N-11、N-28）都用這兩個字；`interval_ms`、`ctl`、`state` 也是 aos-loop 的選填 key。N-28、N-54 都有實作（[impls/aos-daemon](../../impls/aos-daemon/README.md)；daemon 照「資料夾＝程式」重寫，使用者對計畫的五點說「照預設」，[ideas § 25](../../thinking/2026-10-19-ideas.md)），照程式核對後定稿（10-22，使用者「條文草稿那邊要去解決」，[ideas 10-22 § 5](../../thinking/2026-10-22-ideas/03-5-loop.md#5-loop10-22)）。state／ctl 窗在[窗](05-基礎設施-窗.md)。

> **loop／daemon 不管、使用者自行承擔的事**（10-22 使用者，[ideas 10-22 § 5](../../thinking/2026-10-22-ideas/03-5-loop.md#5-loop10-22)）：① 每次**沒有時間上限**：那次最後 exec 成可執行檔或 argv 陣列時，不理 SIGTERM 就一直等（那次是 inst 單子時由 aos-exec 照單子的 `grace_ms` 補 SIGKILL）——要上限自己加，例如在 `exec` 指的單子或 argv 檔裡 argv 前面接 `timeout -k 5 60`（不加 `-k` 遇到不理 SIGTERM 的照樣等），或用單子的 `timeout_ms`；`exec` 陣列的第一個是 aos-exec 的目標，不能直接寫 `timeout`。② 兩個 loop／daemon **共用同一份 state 檔**（本來就違反 N-09「一個 state 檔只有被控制的那個東西自己寫」）：寫的時間撞上時搶同一個暫存檔名、後到的當掉，沒撞上也會互相蓋掉內容——自己避免，或在外面接 s6-setlock 之類的鎖。③ **state 寫不了**（資料夾不見、沒權限…）時，stderr 一行 `aos-loop: WriteFailed 寫不了 <檔>：<原因>`（daemon 開頭是 `aos-daemon:`）、結束碼 1，跟其他自己的錯一樣（P-21）；這時就算收到了訊號也不以 128＋N 結束。state 是在兩次之間寫的，所以發現時那次已經跑完、下一次不起（一開始就寫不了＝一次也沒跑）；檔裡的 state 停在最後寫成的那份（多半是 `running`），要看死活照 N-17 看 pid＋`started_at_ticks`。**daemon 照樣先收掉子項才結束**（P-36）：全部送 SIGTERM、等它們退，滿 10 秒還在的 SIGKILL 整群（同 N-28「收子項不阻塞」），不留孤兒；等的這段 state 照樣寫不了、不寫。一開始就寫不了時，起子項之前那份 state 就寫不了，子項一個都沒起。直接跑 aos-loop 時 `$AOS_STACK` 資料夾不在也算這種，aos-loop 不自己建——建 stack 只在 aos-exec 做（N-59 第 1 件），經 aos-exec 跑就沒事（[thinking 10-23 daemon 壓測](../../thinking/2026-10-23-daemon-bench.md)）。④ loop 跑途中改 `.env`，因為 aos-exec 預設不蓋已有的環境變數（N-59 第 4 件），改過的值不生效，loop 也不會替每次加 `--dotenv-override`——要蓋就自己在 `exec` 指的單子 argv 寫旗標，旗標只管那次 aos-exec 走進的地方的 `.env`，所以要指回同一層（例 `{"exec": "loop.json#/body", "body": {"argv": ["aos-exec", "--dotenv-override", "loop.json#/real"]}, "real": {"argv": ["aos-fsm", "fsm.json"]}}`），或重開 loop。

## daemon

> **daemon 兩義**：①[C-04](../CONCEPTS/01-設計理念.md) 說的 daemon＝aos 與 Linux 之間的借階層（Linux 那邊的事全在這層）；②這裡的 daemon＝管一群 loop 的程式（`aos-daemon`，C-36）。[名詞表](../CONCEPTS/附錄1-名詞.md)兩列都留。

> **11-03 起統稱 `procs`**（[thinking 11-03 procs](../../thinking/2026-11-03-procs.md)）：本段 11-02 以前寫的 `loops`＋`execs`、`loops_ctl`、`loops_state`、`loops_ctl_mailbox`、`loops_state_loops/`、小格 `loops/<名字>/`，11-03 起依序讀成 `procs`、`procs_ctl`、`procs_state`、`procs_ctl_mailbox`、`procs_state_procs/`、`procs/<名字>/`（或那一項的 `stack`）；細節見 N-28、N-54 的 11-03 改口（N-28 已摺成現行條文、全用新名）。

- **N-10**（10-12 定；**10-16 使用者刪**）原「指令式控制資料夾」（往資料夾放 `名字.json`＝一條指令、回 `名字.json.done` 一問一答）整套刪。daemon 表上有誰改由 ctl 宣告（N-54）；暫停、停掉某個子 loop＝直接寫它的 ctl（N-06）；看它＝讀它的 state 窗。（使用者 10-16：「不留」，[KISS 重審拍板 1](../../thinking/2026-10-16-kiss-recheck.md#使用者拍板10-16)）
- **N-28**（候選 g，10-14 夜末使用者拍板；10-22 定稿，[ideas 10-22 § 5](../../thinking/2026-10-22-ideas/03-5-loop.md#5-loop10-22)）**daemon.json 是 loop.json 的嚴格超集**：同名 key 同義（節奏、窗、收尾、`id`；`id` 現行沒有），預設值可以不同（daemon `max` 預設不限、`interval_ms` 200；loop `max` 沒寫＝不限、`interval_ms` 0；10-14 深夜定：「沒寫 `max` 的 loop.json 丟給 daemon 會一直跑」）。一份合法的 loop.json 直接丟給 aos-daemon 也要能跑。daemon.json 多的 key 只有 `procs`、`adopt`、`procs_ctl`、`procs_state`、`procs_ctl_mailbox`；`procs`、`adopt` 只寫在 daemon.json（新程式盡量不收旗標，N-11；使用者 10-21 晚「新程式不收旗標...沒關係的，那是軟性，應該改成"盡量不收"」）。認不得的 key（含改名前的 `loops`、`execs`、`loops_*`）照 C-48 當沒看到：不報錯、不提醒、不過渡（使用者 11-03「1. 當沒看到。」，[thinking 11-03 procs](../../thinking/2026-11-03-procs.md)）。
  - **命令列**同 aos-loop（共用）：`aos-daemon [旗標] daemon.json [-- 參數...]`；設定檔是唯一的位置參數，可寫 `檔#/指標`；旗標 `--max`、`--interval-ms`、`--ctl`、`--state`、`--enable-logs`（[ideas 10-21 § 8](../../thinking/2026-10-21-ideas/05-7-審後的五個細縫與修正.md#8-aos-loop10-21-下午)、[計畫 10-21](../../thinking/2026-10-21-plan.md) D1～D4；[ideas 10-21 § 9](../../thinking/2026-10-21-ideas/05-7-審後的五個細縫與修正.md#9-設定檔是唯一的位置參數path-改字串拼接10-21-傍晚)）。`-- 參數...` 只接在 daemon 自己的 `exec` 後面、每次都帶，不影響子項；沒有 `exec` 卻給了＝`ArgumentsBad`（代定）。
  - **`exec`**＝daemon 自己每次串行跑一次的身體；跑法跟 loop 一樣（阻塞到它結束）；在 daemon 裡**選填**（純監工不需要），在 loop 裡必填。字串＝aos-exec 的目標（`aos-exec` 它；同 P-06；`daemon.json#/body` 這類 `檔#/…` 就是普通的 aos-exec 目標）；陣列＝`[目標, 參數...]`；也可以直接放單子物件（使用者 10-24「不過exec本來就應該要可以直接放內嵌單子吧」「好，就這樣做」，[thinking 10-24](../../thinking/2026-10-24-exec-relative/01-使用者原文.md#10-24-exec-直接放單子)）——loop／fsm／daemon 拿到物件時在自己行程內用 aos-exec 跑單子的同一套（`run_inst`、inst 的 C lib；`timeout_ms`、訊號、結束碼都一樣）跑，跑的期間 `AOS_CF`＝寫著它的設定檔、`AOS_CD`＝那份檔的資料夾（也是相對路徑的基準）、`AOS_CO`＝它在檔裡的位置（`/exec`、`/states/<名>/exec`）；單子壞＝那支程式自己的錯、退 1。daemon 自己的 `exec` 那次繼承同一個 `$AOS_STACK`。
  - **名單 `procs`**＝`{名字: proc}`（使用者 11-03「exec和loops，其實都屬於proc」「連名單也合一」）。名字就是子項的 `id`，沒寫 `stack` 時也是小格 `$AOS_STACK/procs/<名字>/` 的名字（P-17；子項名字是名單給的，跟 daemon 自己的固定名分開，[thinking 11-02 stack-tools](../../thinking/2026-11-02-stack-tools.md) 細節 5）。名字不能空、不能含 `/`、不能 `.` 開頭、不能帶 `#`（`#` 是頂層自定，ideas 10-21 § 9.3 第 5～7 點）；跟 daemon 自己的窗同名不擋（使用者 11-02「那兩題中的1.，可以」）。**daemon 收子項只看它自己需要的**（C-52；10-15 深夜使用者「不留」）。每項**看寫法決定怎麼起**，沒有 `kind`（使用者 11-03「2.kind這東西沒用吧，刪掉」）：
    - 字串、陣列 `[目標, 參數...]`、或 key 只有 `exec`（可再加 `ws`、`stack`）的物件＝**exec 型**：aos-exec 跑一次。
    - 其他物件＝**loop 型**：一份 loop 設定、包成子 aos-loop（10-15 使用者『全定』）。裡面的 loop key 與單子 daemon 一概不驗、原樣灌給子 loop，寫錯了子 loop 自己退 1、錯在它的 stderr，daemon 只看到它結束；沒 `exec` 的物件一樣原樣交給子 loop，由它退 1（「沒有東西可跑」）。要用 loop 型跑單子，寫 `{"exec": "daemon.json#/procs/<名字>/body", "body": 單子}`（只跑一次再加 `"max": 1`）。
    - 坑：寫 `{"exec": "fsm.json"}` 想要一直跑的 loop 會變成跑一次，要 loop 就多寫一個 loop 的 key（例 `"interval_ms": 0`）。
    - 要一次跑完的東西也可以寫成 `{"exec": 它, "max": 1}` 的 loop（使用者 10-30「包成max:1也是可以」），差別只在多一層 aos-loop 與它的窗——小格裡外層 loop 的 `ctl.json`／`state.json` 會跟掛進去的 aos agent 自己的 loop 窗撞同一個檔（本檔開頭 ②），純黑盒子沒這問題。
    - 同名改寫法（loop 型與 exec 型互換、改了 `ws`、`stack`…）照 N-54「名字已在表上的不看設定變了沒」不重起，下一次起它才用新的。
  - **起 loop 型**（經 aos-exec，使用者「5.要」）：daemon 把子項設定補上 `ctl`／`state`（沒寫才補 `ctl.json`／`state.json`）、拿掉 `ws`、`stack`，一律蓋上 `"_entry": ["aos-loop", {"$env": "AOS_CF"}]` 寫成小格的 `loop.json`，起 `aos-exec -- 小格/loop.json#/_entry`（指到 `_entry` 不受 `$AOS_ENTRY` 影響）。相對路徑從 daemon 的 cwd 算：aos-exec 會 cd 進小格，所以 daemon 寫小格時把子項 `exec` 的目標（字串，或陣列的第一個元素）照 daemon 的 cwd 轉成絕對路徑；`exec` 是單子時由子 loop 在自己行程內跑（`AOS_CF`＝小格的 `loop.json`、`AOS_CO`＝`/exec`），單子沒寫 `cwd`＝補上 daemon 的 cwd、相對的 `cwd` 接在 daemon 的 cwd 後面（是指示詞就不動），單子裡相對的 `$ref` 檔名照它來自的那份檔轉成絕對、不解；`procs_ctl` 加的子項同一套（頂層代定，[thinking 10-24](../../thinking/2026-10-24-exec-relative/01-使用者原文.md#10-24-exec-直接放單子)）。其他 key 不驗、不動。子項若是資料夾程式，用 `aos-exec` 跑（[N-58](10-基礎設施-定義與工作區.md)）。
  - **起 exec 型**（使用者 10-30「不過可以的話，我也覺得讓daemon可以掛aos-exec，也是不錯的」、看完規劃回「都照建議」，[thinking 10-30 agent-lifecycle](../../thinking/2026-10-30-agent-lifecycle/07-衝突.md#決定10-30)；照實作寫，[impls/aos-daemon](../../impls/aos-daemon/README.md)）：daemon 對它直接 `aos-exec` 一次，**不包 aos-loop、不寫小格的 `loop.json`、不補 `ctl`／`state`**，表上的 pid 就是那支程式。目標是字串或陣列＝`aos-exec -- 目標 參數...`；`{"exec": 單子}`＝daemon 把它寫成小格的 `exec.json`（`{"exec": 單子}`，單子的 `cwd` 照 loop 型的單子那樣補），跑 `aos-exec -- 小格/exec.json#/exec` 一次（`AOS_CF`＝小格的 `exec.json`、`AOS_CO`＝`/exec`；單子沒寫 stdin／stdout＝接 `/dev/null`、stderr 附加到小格的 `stderr.txt`，寫了就照它）（使用者 11-02 回「daemon 的 execs 要不要也收內嵌單子」：「6.要。」）。
  - **兩型共通**：`AOS_STACK`＝小格（或那一項的 `stack`）；stdin／stdout 接 `/dev/null`、stderr 附加到小格的 `stderr.txt`（exec 型的單子寫了 stdin／stdout 就照它，見上）；自成 session 群組；cwd＝daemon 的 cwd。子項的環境除了 `AOS_STACK`（與寫了 `ws` 時的 `AOS_WS`），一律多設 `AOS_DAEMON_STACK`＝daemon 自己的 stack（絕對、結尾 `/`），只設這一個（使用者 11-02 對常駐 bob 的衝突與方向題回「照建議走」，[thinking 11-02 resident-bob](../../thinking/2026-11-02-resident-bob.md#衝突與方向題的裁定11-02-晚使用者) 衝突 2；條文在 [N-63 的 11-02 補](10-基礎設施-定義與工作區.md)，父子交代的例子在 N-64 ④）。
  - **每項選填 `stack`**（使用者 11-03「那就記錄在名單上。我是希望盡量不要用捷徑啦。」）：非空字串，相對路徑從 daemon 的 cwd 算、轉絕對；`null`＝當沒寫；沒寫＝小格 `procs/<名字>/`。不在就建（`mkdir -p`，建不了＝`MkdirFailed`）；裡面有什麼、兩項同一個 stack，都不查不擋、使用者自己承擔；不建捷徑；不灌進 `loop.json`。
  - **每項選填 `ws`**（這一隻的工作區；使用者 10-30「都照建議」，[thinking 10-30 eca](../../thinking/2026-10-30-eca/09-方向題.md#決定10-30) 衝突 1；照實作寫，[impls/aos-daemon](../../impls/aos-daemon/README.md)）：只有物件寫得了（字串或陣列寫法沒地方寫，要 `ws` 就寫成物件）。值是非空字串（指示詞照解），**相對路徑從 daemon 的 cwd 算**、轉成絕對存進期望表；`null`＝當沒寫；其他型別或空字串＝壞（daemon.json＝`CfgBad` 退 1、`procs_ctl` 整份不採用、信＝壞信）；在不在不驗（不在的話子項經 aos-exec 報 `WsMissing`）。daemon 起那個子項時把 `AOS_WS` 設成它；**沒寫＝繼承 daemon 的環境**。`ws` 不寫進小格的 `loop.json`（它不是 loop 的 key），只進環境；小格不因 `ws` 搬家。改了 `ws`，下一次起它才用新的（同名改寫法，見上）。`ws`、`stack` 是 daemon 拿走的 key：exec 型物件除了 `exec` 只認這兩個，loop 型物件除了這兩個原樣交給子 loop。原則：[N-55](10-基礎設施-定義與工作區.md) 工作區由呼叫方設 `AOS_WS`，daemon 是呼叫方。
  - **子項的輸出：aos 不保證子項的輸出不無限長**（使用者 10-22「小地方那些我都OK」、四個實際問題都由使用者自己承擔，[ideas 10-22 § 5](../../thinking/2026-10-22-ideas/03-5-loop.md#5-loop10-22)；使用者 10-22「3 N-28 未做的從規範拿掉、改寫自己接工具」，[ideas 10-22 § 6](../../thinking/2026-10-22-ideas/03-5-loop.md#6-daemon10-22)）。aos-daemon 丟掉子項的 stdout（結果一律從 state 窗讀），子項自己與它每次的 stderr 全部附加到小格的 `stderr.txt`（daemon 自己開的檔，不只出錯時、不輪替、不設上限）；選填路徑、輪替、清舊格子都不做。要控制大小的人自己處理，風險使用者自己承擔：例如外面用 logrotate 的 copytruncate 截（檔是附加模式開的），或讓那次的單子用 `stderr` key 把輸出導到自己的檔、在那次裡把輸出接給 s6-log、svlogd（見 [notes/s6-runit](../../notes/s6-runit.md)）——aos-loop 自己的那幾行仍會進小格。
  - **daemon 不清小格**（10-22 使用者確認：自己承擔）：表上沒列到的舊小格留著，同名子項再起時沿用那格、`stderr.txt` 接著附加，小格裡舊的 `ctl.json`、`state.json` 也留著，再起時怎麼讀照 [N-06](05-基礎設施-窗.md)。要清自己在起 daemon 前刪。
  - **小格只建 `procs/` 與小格兩層**，不順手建出 `$AOS_STACK`：`$AOS_STACK` 不在＝state 或 procs_state 窗開了任一扇就 `WriteFailed`、兩扇都沒開才 `MkdirFailed`，都退 1、stderr 一行（建 stack 只在 aos-exec 做，N-59 第 1 件；直接跑 aos-loop 也一樣不建，見本檔開頭 ③）。寫了 `stack` 的見上（不在就建）。
  - **兩個手把、兩扇狀態窗**（使用者 10-28「一個控制loop面向和自身屬性，一個控制管轄的aos函數」、10-29「ctl和投遞信箱並存，那就是程式設計者自己決定哪個負責哪個，這就是兩套模式」；看完衝突與方向題回「都照建議」，[thinking 10-29 medium-plan](../../thinking/2026-10-29-medium-plan.md) § 四）：
    - `ctl`、`state` 管 loop 面向與自身屬性，跟 aos-loop 同一套（上面「嚴格超集」）；慣用名 `ctl.json`、`state.json`（使用者 11-02 晚「控制自身的 ctl/state 檔案，那就是 ctl/state，不加前綴」，[thinking 11-02 ctl-state-names](../../thinking/2026-11-02-ctl-state-names.md)），程式沒有預設名（沒寫＝不開，N-09）。
