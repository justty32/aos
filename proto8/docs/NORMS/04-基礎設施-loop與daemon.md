# 基礎設施／loop、daemon

> loop 是 `aos-loop [旗標] loop.json`（`{"exec", "max"}`，子程式退 10 就停，P-06、P-19；設定檔是唯一的位置參數，N-11）。**key 名以現行 loop.json 為準**（10-19 晚使用者定：「那就用到最新的吧」，[ideas § 22](../../thinking/2026-10-19-ideas.md)）：身體叫 `exec`、跑幾次叫 `max`，daemon 與窗的條文（N-06、N-07、N-11、N-28）都用這兩個字；`interval_ms`、`ctl`、`state` 也是 aos-loop 的選填 key。N-28、N-54 都有實作（[impls/aos-daemon](../../impls/aos-daemon/README.md)；daemon 照「資料夾＝程式」重寫，使用者對計畫的五點說「照預設」，[ideas § 25](../../thinking/2026-10-19-ideas.md)），照程式核對後定稿（10-22，使用者「條文草稿那邊要去解決」，[ideas 10-22 § 5](../../thinking/2026-10-22-ideas.md#5-loop10-22)）。state／ctl 窗在[窗](05-基礎設施-窗.md)。

> **loop／daemon 不管、使用者自行承擔的事**（10-22 使用者，[ideas 10-22 § 5](../../thinking/2026-10-22-ideas.md#5-loop10-22)）：① 每次**沒有時間上限**：那次最後 exec 成可執行檔或 argv 陣列時，不理 SIGTERM 就一直等（那次是 inst 單子時由 aos-exec 照單子的 `grace_ms` 補 SIGKILL）——要上限自己加，例如在 `exec` 指的單子或 argv 檔裡 argv 前面接 `timeout -k 5 60`（不加 `-k` 遇到不理 SIGTERM 的照樣等），或用單子的 `timeout_ms`；`exec` 陣列的第一個是 aos-exec 的目標，不能直接寫 `timeout`。② 兩個 loop／daemon **共用同一份 state 檔**（本來就違反 N-09「一個 state 檔只有被控制的那個東西自己寫」）：寫的時間撞上時搶同一個暫存檔名、後到的當掉，沒撞上也會互相蓋掉內容——自己避免，或在外面接 s6-setlock 之類的鎖。③ **state 寫不了**（資料夾不見、沒權限…）時，stderr 一行 `aos-loop: WriteFailed 寫不了 <檔>：<原因>`（daemon 開頭是 `aos-daemon:`）、結束碼 1，跟其他自己的錯一樣（P-21）；這時就算收到了訊號也不以 128＋N 結束。state 是在兩次之間寫的，所以發現時那次已經跑完、下一次不起（一開始就寫不了＝一次也沒跑）；檔裡的 state 停在最後寫成的那份（多半是 `running`），要看死活照 N-17 看 pid＋`started_at_ticks`。**daemon 照樣先收掉子項才結束**（P-36）：全部送 SIGTERM、等它們退，滿 10 秒還在的 SIGKILL 整群（同下「10-23 壓測後」①），不留孤兒；等的這段 state 照樣寫不了、不寫。一開始就寫不了時，起子項之前那份 state 就寫不了，子項一個都沒起。直接跑 aos-loop 時 `$AOS_STACK` 資料夾不在也算這種，aos-loop 不自己建——建 stack 只在 aos-exec 做（N-59 第 1 件），經 aos-exec 跑就沒事（[thinking 10-23 daemon 壓測](../../thinking/2026-10-23-daemon-bench.md)）。④ loop 跑途中改 `.env`，因為 aos-exec 預設不蓋已有的環境變數（N-59 第 4 件），改過的值不生效，loop 也不會替每次加 `--dotenv-override`——要蓋就自己在 `exec` 指的單子 argv 寫旗標，旗標只管那次 aos-exec 走進的地方的 `.env`，所以要指回同一層（例 `{"exec": "loop.json#/body", "body": {"argv": ["aos-exec", "--dotenv-override", "loop.json#/real"]}, "real": {"argv": ["aos-fsm", "fsm.json"]}}`），或重開 loop。

## daemon

> **daemon 兩義**：①[C-04](../CONCEPTS/01-設計理念.md) 說的 daemon＝aos 與 Linux 之間的借階層（Linux 那邊的事全在這層）；②這裡的 daemon＝管一群 loop 的程式（`aos-daemon`，C-36）。[名詞表](../CONCEPTS/附錄1-名詞.md)兩列都留。

- **N-10**（10-12 定；**10-16 使用者刪**）原「指令式控制資料夾」（往資料夾放 `名字.json`＝一條指令、回 `名字.json.done` 一問一答）整套刪。daemon 表上有誰改由 ctl 宣告（N-54）；暫停、停掉某個子 loop＝直接寫它的 ctl（N-06）；看它＝讀它的 state 窗。（使用者 10-16：「不留」，[KISS 重審拍板 1](../../thinking/2026-10-16-kiss-recheck.md#使用者拍板10-16)）
- **N-28**（候選 g，10-14 夜末使用者拍板；10-22 定稿，[ideas 10-22 § 5](../../thinking/2026-10-22-ideas.md#5-loop10-22)）**daemon.json 是 loop.json 的嚴格超集**：同名 key 同義（節奏、窗、收尾、`id`；`id` 現行沒有）。`exec`＝daemon 自己每次串行跑一次的身體（字串＝aos-exec 的目標，`aos-exec` 它；同 P-06；`daemon.json#/body` 這類 `檔#/…` 就是普通的 aos-exec 目標）；`exec` 也可以直接放單子物件（使用者 10-24「不過exec本來就應該要可以直接放內嵌單子吧」「好，就這樣做」，[thinking 10-24](../../thinking/2026-10-24-exec-relative.md#10-24-exec-直接放單子)）——loop／fsm／daemon 拿到物件時在自己行程內用 aos-exec 跑單子的同一套（`run_inst`、inst 的 C lib；`timeout_ms`、訊號、結束碼都一樣）跑，跑的期間 `AOS_CF`＝寫著它的設定檔、`AOS_CD`＝那份檔的資料夾（也是相對路徑的基準）、`AOS_CO`＝它在檔裡的位置（`/exec`、`/states/<名>/exec`）；單子壞＝那支程式自己的錯、退 1。跑法跟 loop 一樣（阻塞到它結束），在 daemon 裡**選填**（純監工不需要），在 loop 裡維持必填。daemon 多的只有 `loops`（並行、長壽的子 loop）、`adopt`（`policies` 不做、從規範拿掉，見下；`work_dir` 由小格 `$AOS_STACK/<名字>/` 取代）。一份合法的 loop.json 直接丟給 aos-daemon 也要能跑。daemon 與 loop 同名 key 語義相同，預設值可不同（daemon `max` 預設不限、`interval_ms` 200；loop `max` 沒寫＝不限、`interval_ms` 0）。（原 h9，10-14 深夜定：「沒寫 `max` 的 loop.json 丟給 daemon 會一直跑」；兩者只差 `interval_ms` 的預設。）`loops` 每項是一份 loop 設定——路徑或內嵌物件，形狀同現行 loop.json（`{"exec", "max", …}`）（原暫定 f，10-15 使用者『全定』；寫法見下「10-20 落實」①）。`policies.child_exit` 不做、從規範拿掉（10-22 使用者）：子項結束後不自動重起（見下「10-20 落實」②），沒有要問它的事；要「結束了怎麼辦」自己在鏈上接工具，例如子項的 `exec` 指到自己寫的監工、或外面用 s6／runit 管。**daemon 收子項只看它自己需要的**（C-52；10-15 深夜使用者「不留」）：是資料夾程式就包成 `{"exec": 它}`、ctl／state 沒寫就自己放；沒 `exec` 的物件照樣原樣交給子 loop，由它退 1（「沒有東西可跑」），要跑一次單子就寫 `{"exec": "daemon.json#/loops/<名字>/body", "body": 單子, "max": 1}`；裡面的 loop key 與單子一概不驗、原樣灌給子 loop，寫錯了子 loop 自己退 1、錯在它的 stderr，daemon 只看到它結束。daemon 不另留 save 檔：**子項表寫在 daemon 自己的 state 窗**（`loops` 一列一項：id、pid、啟動時間、`phase`…；KISS 重審 3.3），state 窗就是 save 檔。**`adopt`**（布林，**預設 `true`**；寫在 daemon.json 裡，新程式盡量不收旗標，N-11；使用者 10-21 晚「新程式不收旗標...沒關係的，那是軟性，應該改成"盡量不收"」）：daemon 重起時讀自己上次的 state 窗、把還活著的子 loop 接回（pid＋啟動時間對得上才認，N-17），不重起它們；寫 `false`＝不接回。第一次起來沒有舊的 state 就沒東西可接。（使用者 10-16：「給選項，默認留」，[KISS 重審拍板 2](../../thinking/2026-10-16-kiss-recheck.md#使用者拍板10-16)；key 名 `adopt` 是頂層照 C-54 挑的——說的是「認領活著的子 loop」。）心跳照 N-17／N-32 留。**子 loop 的輸出：aos 不保證子項的輸出不無限長**（使用者 10-22「小地方那些我都OK」、四個實際問題都由使用者自己承擔，[ideas 10-22 § 5](../../thinking/2026-10-22-ideas.md#5-loop10-22)；使用者 10-22「3 N-28 未做的從規範拿掉、改寫自己接工具」，[ideas 10-22 § 6](../../thinking/2026-10-22-ideas.md#6-daemon10-22)；取代 10-14 深夜使用者「隨你」採的方案 B，[thinking 15](../../thinking/2026-10-14-json-entry/15-ret與半份JSON.md)）。aos-daemon 丟掉子 loop 的 stdout（結果一律從 state 窗讀），子 loop 自己與它每次的 stderr 全部附加到小格的 `stderr.txt`（daemon 自己開的檔，不只出錯時、不輪替、不設上限）；選填路徑、輪替、清舊格子都不做。要控制大小的人自己處理，風險使用者自己承擔：例如外面用 logrotate 的 copytruncate 截（檔是附加模式開的），或讓那次的單子用 `stderr` key 把輸出導到自己的檔、在那次裡把輸出接給 s6-log、svlogd（見 [notes/s6-runit](../../notes/s6-runit.md)）——aos-loop 自己的那幾行仍會進小格。daemon 不清小格（表上沒列到的舊小格留著，同名子項再起時沿用那格、`stderr.txt` 接著附加，小格裡舊的 `ctl.json`、`state.json` 也留著——用 ctl 停過或暫停過的子項，再起時新的子 loop 第一次就讀到舊 ctl、照樣停或暫停），要清自己在起 daemon 前刪，或再起前先刪那格的 `ctl.json`（10-22 使用者確認：自己承擔）。（10-14；推翻 10-12「daemon 沒有 inst、身體內建＝掃資料夾」）子項若是資料夾程式，用 `aos-exec` 跑（[N-58](10-基礎設施-定義與工作區.md)）。**10-20 落實**（使用者 10-20「照預設」，[ideas § 25](../../thinking/2026-10-19-ideas.md)）：① `loops` 寫成 `{名字: loop 設定}`——名字就是子項的 `id` 與小格 `$AOS_STACK/<名字>/`（P-17，stderr 落在小格的 `stderr.txt`）；字串＝aos-exec 的目標，包成 `{"exec": 它}`；物件＝loop 設定，原樣交給子 loop。② **子 loop 結束後不自動重起**：`phase` 停在 `done`，要再起就從 ctl 的 `loops` 拿掉再放回、或重起 daemon；`policies.child_exit` 與六態裡的 `backoff` 不做、從規範拿掉。「不自動重起」管的是 **daemon 開著的時候**；daemon 重開＝重新開始，照名單起表上缺的——含 daemon 停機期間（例如被 SIGKILL）死掉的子項；還活著、pid＋啟動時間對得上的照 `adopt` 接回、不重起（使用者 10-22「1 daemon 重開時照表起，算重新開始、不算自動重起」）。③ 心跳只在兩次之間跳（N-17）。收工照 P-36：不論為什麼結束都先收掉子項、寫好 state，收到訊號以 128＋N 結束（非 0）。**10-21 落實**（[ideas 10-21 § 8](../../thinking/2026-10-21-ideas/05-7-審後的五個細縫與修正.md#8-aos-loop10-21-下午)、[計畫 10-21](../../thinking/2026-10-21-plan.md) D1～D4）：命令列同 aos-loop（共用；旗標 `--max`、`--interval-ms`、`--ctl`、`--state`）；`loops`、`adopt` 只在 daemon.json；子項設定的 `exec` 跟 loop 一樣：字串＝aos-exec 的目標，相對路徑從 daemon 的 cwd 算；也可以是單子物件，由子 loop 行程內跑，`AOS_CF`＝小格的 `loop.json`、`AOS_CO`＝`/exec`。為了相對路徑照舊從 daemon 的 cwd 算，daemon 寫小格時單子沒寫 `cwd`＝補上 daemon 的 cwd、相對的 `cwd` 接在 daemon 的 cwd 後面（是指示詞就不動），單子裡相對的 `$ref` 檔名照它來自的那份檔轉成絕對、不解；ctl 加的子項同一套（頂層代定，[thinking 10-24](../../thinking/2026-10-24-exec-relative.md#10-24-exec-直接放單子)）。內嵌單子也可以寫 `{"exec": "daemon.json#/loops/<名字>/body", "body": 單子}`；寫成物件照樣原樣交出去（daemon 不驗），壞了由子 loop 自己退 1、錯在小格的 `stderr.txt`。字串子項＝aos-exec 的目標（不限資料夾，也可以是 `daemon.json#/…` 指進一張單子），包成 `{"exec": 它}`。收工時「最後一次之後才自己結束」的子項也標 `done`、記 `code`，最後那份 state 不留 `running`（計畫 D7，第 2 段）。**10-21 傍晚**（[ideas 10-21 § 9](../../thinking/2026-10-21-ideas/05-7-審後的五個細縫與修正.md#9-設定檔是唯一的位置參數path-改字串拼接10-21-傍晚) H1、H3、H5）：命令列是 `aos-daemon [旗標] daemon.json`（設定檔可寫 `檔#/指標`）；`exec` 與子項可以是陣列 `[目標, 參數...]`；**起子 loop 經 aos-exec**（使用者「5.要」）：daemon 把子項設定補上 `ctl`／`state`（沒寫才補）、一律蓋上 `"_entry": ["aos-loop", {"$env": "AOS_CF"}]` 寫成小格的 `loop.json`，起 `aos-exec -- 小格/loop.json#/_entry`（指到 `_entry` 不受 `$AOS_ENTRY` 影響）；aos-exec cd 進小格，所以 daemon 寫小格時把子項 `exec` 的目標（陣列的第一個元素）照 daemon 的 cwd 轉成絕對路徑——「相對路徑從 daemon 的 cwd 算」照舊成立，其他 key 照舊不驗、不動；子項名字不能帶 `#`（頂層自定，ideas 10-21 § 9.3 第 5～7 點）。**10-22 落實**（使用者 10-22「2 子項名字擋掉跟 ctl／state 同名」，[ideas 10-22 § 6](../../thinking/2026-10-22-ideas.md#6-daemon10-22)）：子項名字不能跟 daemon 自己的 ctl、state 撞名——它們落在 `$AOS_STACK` 底下時，相對路徑的第一段就是會撞的名字（`state.json`、`ctl.json`、`"w/c.json"` 的 `w`；落在 `$AOS_STACK` 外面的、沒開的不算；撞名取第一段是頂層照程式定的）。起來時撞＝自己的錯，退 1、stderr 一行；ctl 的 `loops` 撞＝那份 ctl 整份不採用、維持上一份好的、原因進 state 的 `ctl_warning`（同 N-08）。daemon 在 `$AOS_STACK` 底下另外只寫 `.` 開頭的暫存檔，名字本來就不能 `.` 開頭。daemon 自己的 `exec` 那次繼承同一個 `$AOS_STACK`，它寫在那裡的檔（例如 exec 是 fsm 時的 `state.txt`、`trace.jsonl`）不擋，子項名字別取一樣的，使用者自己避免。**10-23 壓測後**（使用者「都修都處理」、修到一半「python版本可以刪掉了。aos-exec/loop/daemon都用C++」，[thinking 10-23 daemon 壓測](../../thinking/2026-10-23-daemon-bench.md)）：① **收子項不阻塞**：表上多出來的送 SIGTERM 就往下巡（state 照寫、ctl 照讀、別的子項照起），之後每次巡時看一眼，退了標 `stopped`、從表上拿掉，滿 10 秒還在才 SIGKILL 整群；收的途中那一列的 `phase` 是 `stopping`（N-17）。收的途中 ctl 又把同名的放回來＝等舊的退了、下一次才起新的（同一個小格）。daemon 收工時（不論為什麼）也是全部先送 SIGTERM、等它們退，等的這段每秒寫一份 state、頂層 `phase` 是 `stopping`，滿 10 秒還在的 SIGKILL；ctl 早就要拿掉、收工時才退的照樣拿掉。② **被 SIGKILL 的子 loop 自己的 state 會停在最後寫的那份**（多半是 `running`）：daemon 不去改它（N-09 一個 state 檔只有它自己寫）。讀子 loop 的 state 時死活照 N-17 看 pid＋`started_at_ticks`；daemon 自己 state 的那一列是準的——daemon 收掉的寫 `stopped`，被 SIGKILL 的 `signal` 9、`code` 137。③ 沒有 `exec` 的 daemon 一圈只讀一次 ctl、只對一次表、只寫一份 state（`waiting`，不寫 `running`），`recorded_at` 的間隔＝`interval_ms`＋那一圈對表的時間；表用雜湊找名字。④ 起子項之前先寫一份 state，一大批起很久時每秒一份（心跳，N-32）。⑤ 小格只建一層（不順手建出 `$AOS_STACK`）：`$AOS_STACK` 不在＝開了 state 窗就 `WriteFailed`、沒開就 `MkdirFailed`，都退 1、stderr 一行（建 stack 只在 aos-exec 做，N-59 第 1 件；直接跑 aos-loop 也一樣不建，見本檔開頭 ③）。**10-23 晚**（使用者「當loop太多的時候，json超大，我會希望他會自動用$ref切，每個檔案一百個」、切檔三處都選、「aos 讀的 JSON 全部支援」，[thinking 10-23 ctl 與 $ref](../../thinking/2026-10-23-daemon-ctl-ref.md)）：① **`loops` 拆成好幾份檔＝`$ref` 陣列**（使用者「等一下，我記得可以這樣啊："$ref":["a.json", "b.json#/c/d]"」：`$ref` 可以寫成陣列、幾份照順序合成一份，見 [N-45](06-基礎設施-命令列與指示詞.md)）：`loops` 一律是物件 `{名字: 子項}`，要拆就寫 `"loops": {"$ref": ["loops-1.json", "loops-2.json"]}`——都是物件就合 key、同名後面的蓋前面的；不拆也能整份 `"loops": {"$ref": "loops.json"}`。daemon.json、ctl 的
