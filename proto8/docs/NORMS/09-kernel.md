# kernel 規範

- **N-42**（10-15 定，草稿）先做兩種 kernel，都基於 daemon：(1) 管 LLM 呼叫的 kernel；(2) 通用管理的 kernel（以 agent 作判斷）。兩支不併成一支（使用者 10-16：「兩隻kernel不併成一支。」，[KISS 重審拍板 5](../../thinking/2026-10-16-kiss-recheck.md#使用者拍板10-16)）。出自 C-47。閘門／信箱草案在 [thinking 10-15 kernel 截流](../../thinking/2026-10-15-kernel-intercept.md)；六題 10-15 使用者「隨意」、照建議預設定案，見 [LLM kernel](../../thinking/2026-10-15-llm-kernel.md)。
  - **(1) LLM kernel**（使用者 10-24「LLM kernel，也就是把brain這塊弄成一個請求，而不是直接打API，請求會被丟到某個地方，由kernel排隊跑」；照 [10-15 LLM kernel](../../thinking/2026-10-15-llm-kernel.md) 已定的六條與 [kernel 截流](../../thinking/2026-10-15-kernel-intercept.md) 的閘門／信箱，細節照推薦定、可翻案，見 [thinking 2026-10-24-llm-kernel](../../thinking/2026-10-24-llm-kernel.md)）：基於 daemon（kernel 是 daemon 或 loop 一次次拍的一張單子，C-47）；agent 那格跑閘門 `aos-llm-send`，閘門把「問腦」那張單子寫成一封信丟進信箱（`$AOS_KERNEL`，N-16 資料夾式）、等回信、原樣交回；kernel `aos-llm-kernel` 一次挑最該跑的（級數＋aging → 時限 → 單子 `_metainfo.time_ms` 短的先 → 等得久 → 先寄）、同時跑 `slots` 封、回信。kernel 跑信時給 `AOS_KERNEL_REPORT`、腦願意就寫 `usage`；kernel.json 的 `budget` 設 `calls`／`tokens` 每窗上限，到頂回 `BudgetMissing`（或設成等下一窗），見 [thinking](../../thinking/2026-10-24-llm-kernel.md#token-回報與額度10-24-下午)。
  - **(2) 通用 kernel**：具體機制再規劃，現無實作。
