# kernel 規範

- **N-42**（10-15 定，草稿）先做兩種 kernel，都基於 daemon：(1) 管 LLM 呼叫的 kernel；(2) 通用管理的 kernel（以 agent 作判斷）。具體機制再規劃（[thinking 10-15 kernel 截流](../../thinking/2026-10-15-kernel-intercept.md)有閘門／信箱草案；六題未決 10-15 使用者「隨意」、照建議預設定案，見 [LLM kernel](../../thinking/2026-10-15-llm-kernel.md)）。兩種現在都無實作（10-19 刪舊版進 git，待照新做法重寫）。出自 C-47。**10-16 維持兩支**：KISS 重審曾推薦「兩支併成一支、沒寫判官＝管 LLM 的那種」，使用者：「兩隻kernel不併成一支。」（[KISS 重審拍板 5](../../thinking/2026-10-16-kiss-recheck.md#使用者拍板10-16)），彙整 5.1 撤回。**10-24 使用者「LLM kernel，也就是把brain這塊弄成一個請求，而不是直接打API，請求會被丟到某個地方，由kernel排隊跑」**：(1) 有實作了（照 [10-15 LLM kernel](../../thinking/2026-10-15-llm-kernel.md) 已定的六條與 [kernel 截流](../../thinking/2026-10-15-kernel-intercept.md) 的閘門／信箱；細節照推薦定、可翻案，見 [thinking 2026-10-24-llm-kernel](../../thinking/2026-10-24-llm-kernel.md)）：基於 daemon（kernel 是 daemon 或 loop 一次次拍的一張單子，C-47）；agent 那格跑閘門 `aos-gate`，閘門把「問腦」那張單子寫成一封信丟進信箱（`$AOS_KERNEL`，N-16 資料夾式）、等回信、原樣交回；kernel `aos-kernel-llm` 一次挑最該跑的（級數＋aging → 時限 → 單子 `_metainfo.time_ms` 短的先 → 等得久 → 先寄）、同時跑 `slots` 封、回信。token 額度這版沒做、只算次數（回報通道 `AOS_KERNEL_REPORT` 10-24 照推薦定了要開）。〔10-24 下午註：回報通道與額度做了——kernel 跑信時給 `AOS_KERNEL_REPORT`、腦願意就寫 `usage`；kernel.json 的 `budget` 設 `calls`／`tokens` 每窗上限，到頂回 `BudgetMissing`（或設成等下一窗），見 [thinking](../../thinking/2026-10-24-llm-kernel.md#token-回報與額度10-24-下午)〕(2) 通用 kernel 仍無。
