# kernel 規範

- **N-42**（10-15 定，草稿）先做兩種 kernel，都基於 daemon：(1) 管 LLM 呼叫的 kernel；(2) 通用管理的 kernel（以 agent 作判斷）。兩支不併成一支（使用者 10-16：「兩隻kernel不併成一支。」，[KISS 重審拍板 5](../../thinking/2026-10/16/kiss-recheck.md#使用者拍板10-16)）。出自 C-47。
  - **(1) LLM kernel**（使用者 10-24「LLM kernel，也就是把brain這塊弄成一個請求，而不是直接打API，請求會被丟到某個地方，由kernel排隊跑」；照 [10-15 LLM kernel](../../thinking/2026-10/15/llm-kernel.md) 已定的六條〔10-15 使用者「隨意」、照建議預設定案〕與 [kernel 截流](../../thinking/2026-10/15/kernel-intercept.md) 的閘門／信箱草案，細節照推薦定、可翻案，見 [thinking 2026-10-24-llm-kernel](../../thinking/2026-10/24/llm-kernel/README.md)；11-04 晚使用者「llm呼叫這塊，我希望是把請求丟到llm kernel(一個loop)，處理好後收回信」「也可以是一個daemon，實際endpoint呼叫就是aos exec」「包起來的」「我是希望走2」「各種llm設定也可以包裝，這樣寄信的時候只要寫簡單的代號就可以」，細節 fable 照原則代定、可翻案，[thinking 11-04 think-as-function](../../thinking/2026-11/04/think-as-function/README.md)）：基於 daemon（kernel 是 daemon 或 loop 一次次拍的一張單子，C-47；範本 `demo/llm-kernel`＝aos-loop 每 300 ms 拍一次 `aos-llm-kernel kernel.json`，可 `aos-daemon-ctl add` 掛成 daemon 的 proc）。對外只有**信箱＋`aos-llm`**（「包起來的」＝裡面怎麼跑呼叫端不知道，C-52）：
    - **信帶請求、不帶單子**：請求信（N-16）的 body＝`{"endpoint"?: 代號, "request": OpenAI chat completions body 去掉端點, "priority"?}`，信封 `reply_to` 必有；回信 body＝`{"message", "usage", "model"}` 或 `{"error": {"code", "msg"}}`，`in_reply_to`＝請求信的名稱。`request` 寫 `stream`＝`RequestBad`（串流不做）。
    - **kernel 跑自己的 endpoint 函數**：`kernel.json`＝`mailbox`、`slots`、`budget`、`timeout_ms`（跑一封的上限，選填）、`exec`（預設 endpoint 函數＝aos-exec 目標，範本 `lib/base/llm_http`：stdin `{"endpoint", "request"}` → POST `{url}/chat/completions` → stdout `{"message", "usage", "model"}`）、`endpoints`（代號 → 一組設定，一組可自帶 `exec`，例 `fake`→`lib/base/llm_fake`；其他鍵原樣交給 endpoint 函數，指示詞照 N-45 解，金鑰寫 `{"$env"}`／`{"$ref"}`）、`endpoint`（預設代號）。kernel 用 aos-exec 跑那組的 `exec`（環境是 kernel 自己的、stack＝那封信的資料夾），stdout 當回信照 `reply_to` 寄回。代號錯：信沒寫、kernel 也沒預設＝`EndpointMissing`；信寫的表裡沒有＝`EndpointUnknown`；endpoint 函數退非 0＝`EndpointFailed`；body 不合形狀＝`RequestBad`。
    - **非同步 `aos-llm send`／`recv`**：`send [--priority P] --reply-to BOX`（stdin＝整份 body）寄完印信件名稱、馬上回，不建 `sender.flock`——沒鎖檔＝kernel 不判寄信人存活、照跑；`recv BOX 名` 到 BOX 找那封的回信（0 到／10 沒到／1 錯）；**同步 `ask`**＝寄（回信信箱 `$AOS_KERNEL/reply/`、建 `sender.flock`）＋等＋印 `message`；`regret` 撤回還沒被認領的請求。
    - kernel 一次挑最該跑的（級數＋aging → 時限 → 等得久 → 先寄）、同時跑 `slots` 封；用量從回信的 `usage` 記；`budget` 設 `max_calls`／`max_tokens` 每窗上限，到頂回 `BudgetMissing`（或設成等下一窗），見 [thinking](../../thinking/2026-10/24/llm-kernel/02-邊緣狀況.md#token-回報與額度10-24-下午)。
    - **11-04 晚已改**：原本 agent 那格跑閘門 `aos-llm-send`，閘門把「問腦」那張單子＋寄信那一刻的整份環境寫成信、站著等回信、原樣交回；kernel 照單子跑（排序多一條單子 `_metainfo.time_ms` 短的先）；kernel 跑信時給 `AOS_KERNEL_REPORT`、腦願意就寫 `usage`；`kernel.json` 的 `accept` 只跑名單裡的單子。現在信裡沒單子：`aos-llm-send` 改名 `aos-llm`、長出 `send`／`recv`／`ask`／`regret`（使用者 11-04 晚「然後aos llm,tool這兩個，我希望他們的定位是跟aos post一樣，作為基礎工具」「並且可以的話，考慮非同步呼叫，也就是正在跑的loop不停。」）；`_metainfo` 兩個排序依據、`AOS_KERNEL_REPORT`、`accept` 拿掉；舊閘門的信（頂層 `inst`／`env`）＝`LetterBad`。非同步沒鎖檔＝不判存活是衝突 2 照推薦 (a)，隊長先實作、可翻案（[05](../../thinking/2026-11/04/think-as-function/05-衝突與方向題.md)）。
  - **(2) 通用 kernel**：具體機制再規劃，現無實作。
