# kernel 規範

- **N-42**（草稿）先做兩種 kernel，都基於 daemon：(1) 管 LLM 呼叫的 kernel；(2) 通用管理的 kernel（以 agent 作判斷）。出自 C-47。兩種收進同一份通用 kernel 框架：框架一份，llm kernel＝框架＋問腦專屬那包（能力包、額度、帳），判官也收進框架（見 (2)）（使用者 11-11「在我的規劃中，我們會有一個通用的kernel框架，在這個框架下，我們去擴充更多功能如llm之類」、11-12「問腦總機要收進框架」，[kernel-framework](../../thinking/2026-11/12/kernel-framework/README.md#已裁問腦總機收進框架)）。**現況**：框架的骨架、掛 proc 那一包（原判官已收進來）與 hook 三個時機在 [`py/tools/aos/kernel`](../../py/tools/aos/kernel/README.md)；llm kernel 在 [`py/tools/aos/kernel_llm`](../../py/tools/aos/kernel_llm/README.md)（範本 `kernel/llm-kernel`、`kernel/llm-team` 的身體是它）；狀態查詢信由 `aos-agent ctl who` 先問再讀（新舊打架，11-17「新的覆蓋舊的」：11-14 的現況較晚）。開工的原話：使用者 11-12「kernel先這樣就好，開工等假日。我自己也要思考一下」、11-13「kernel框架現在就可以開工了。只是說我們現在只有eca能用。」。圖紙的零件、鍵名、做法是代定，在 kernel-framework 圖紙，不進條文。`AOS_LLM_KERNEL` 與 `AOS_KERNEL` 維持兩個變數（選項框「維持兩個變數」）。
  - **(1) LLM kernel**：全文在分檔 [09-kernel/01-N-42-1-LLM-kernel](09-kernel/01-N-42-1-LLM-kernel.md)；能力包、排程、每寄件人額度、嵌套在 [02-N-42-1-能力包與份額](09-kernel/02-N-42-1-能力包與份額.md)。
  - **(2) 通用 kernel**：普通的掛 proc 請求去它那（C-47「多種 syscall」）；框架站、以 agent 作判斷、下一站三段、`count_daemon`、hook、排隊、有序、停／收／睡／醒、`aos-daemon-ctl` 直寄、ping 全文在分檔 [09-kernel/03-N-42-2-通用kernel](09-kernel/03-N-42-2-通用kernel.md)。
