- **N-50**（10-16 定，草稿）**工具＝資料夾程式，放在呼叫它的那一格的資料夾裡、不用 PATH**：工具 `<名>` 的地址＝`<格>/tools/<名>/`，格裡寫 `aos-exec tools/<名>`——從自己 cwd 算的相對路徑、永遠零個 `..`（N-59 起跑 cwd＝格自己的資料夾，所以埋在第幾層路徑都一樣長）。呼叫每個工具都做同一件事：給它一個**小格**（它自己的 stack，`AOS_STACK=$AOS_STACK/tools/<名>/ aos-exec tools/<名>`，見 [P-17](../../CONVENTION/02-題目stack停錯腦.md)、[thinking 11-02 stack-tools](../../../thinking/2026-11/02/stack-tools/README.md)）；不知道工具裡是不是另一個 agent（C-52）。工具要不要碰工作區、怎麼碰是工具自己的事，要碰就用 `$AOS_WS`（N-55）。工具的參數怎麼進（args、stdin、或 stack 裡的檔）由工具自己的說明定（N-27）。aos 自己的指令（`aos-exec`、`aos-loop`、`aos-fsm`、`aos-daemon` 四支；沒有 `aos-inst`，§ 20）入口裡直接寫指令名、由呼叫者放進 PATH（aos 的程式都不動 PATH，[ideas § 24](../../../thinking/2026-10/19/ideas/README.md)、N-59），那是 aos 的指令，不是工具；PATH 其餘的只留給人。（使用者 10-16 夜：「可以不使用PATH嗎？」→「好!」；CONVENTION P-17、P-25、P-33）
- **N-53**（10-16 定，草稿）**aos 的 agent 是被外面驅動的狀態機**：agent 每次被叫只走一次（跑現在那格、換狀態、退出），由外面的 loop 一次一次驅動——為的是讓 agent 方便審視自己（每次之間狀態都落在 stack、看得到）。反覆幾次、隔多久是 loop 的事；idle 看沒題了退 10，loop 收到 10 就停（N-43、P-19）；agent 資料夾可以**帶 loop 當入口**（`aos-loop loop.json`，P-05、P-06；使用者 10-19，[ideas § 9](../../../thinking/2026-10/19/ideas/README.md) 第 5 條）。**某格出錯那一次退非 0、state 不動**（同 N-38，下一次重跑同一格）；**重試幾次由人或外面決定，agent 自己不數連錯**（P-20）。概念上 agent 只是一台狀態機、怎麼跑由誰跑都行（C-62）；本條只管 aos 自己的 agent。（使用者 10-16：「但是我們的規範會說，為了讓agent方便審視自己，所以agent就是一個被人驅動的狀態機，需要外面有人用loop驅動他。這是我們的aos agent」；頂層確認「腦出錯那一次退 1、phase 不動，重試幾次看外面 loop，agent 自己不數」→「可以。」，[KISS 重審拍板 4](../../../thinking/2026-10/16/kiss-recheck.md#使用者拍板10-16)）

## stack 與工作區（10-16 夜）

出自使用者 10-16 夜的決定（[稿 § 四](../../../thinking/2026-10/16/agent-inherit/02-四-使用者決定.md#四使用者決定10-16)；使用者「我覺得不錯。不過是不是可以採用環境變數？所以cwd: WS? 具體命名幫我想想。」名字是 `AOS_WS`，單子裡讀它：「可以用$env啊」，選「A」，N-45）。概念 C-65～C-67。

- **N-55**（10-16 夜定，aos-exec 照做，草稿）**工作區的位置由環境變數 `AOS_WS` 給**（`ws`＝workspace，進[縮寫表](../../CONCEPTS/abbr.json)）：呼叫方設，照 Linux 環境變數本來的樣子自然往下傳給所有子行程，巢狀多深都指同一個工作區、沒有人需要知道深度。資料夾程式跑的時候起跑 cwd 是自己的資料夾（N-59），**工作區保持乾淨**——執行時的東西（狀態、草稿、紀錄、小格）都放 stack，不放工作區（C-65；呼叫方自己把 stack 指到工作區是它的自由，C-67；`AOS_STACK` 的預設就是工作區裡的隱藏資料夾 `.stack/`，N-57）。單子裡讀它用 `$env`（N-45）。（使用者 10-16 夜：「除此之外，C語言函數想要影響外部變數，那也是透過指標」；「風險就設計者自己管控」）
