- **N-57**（10-19 定，草稿；[ideas § 14、§ 19](../../../thinking/2026-10/19/ideas/README.md)）**aos 只訂環境變數，共六個**（使用者「然後我想要再加上兩個環境變數：AOS_CF, AOS_CD，也就是current file，current dir。」「AOS_CF不動。但是我們再加上AOS_CO」「aos current obj」；`AOS_CF`／`AOS_CD` 的定義由 fable 擬、使用者「同意做」，[ideas 10-21 § 6](../../../thinking/2026-10/21/ideas/04-6-JSON-物件當資料夾-一路往下-AOS_C.md#6-json-物件當資料夾一路往下aos_co10-21-晚)）：
  - `AOS_ENTRY`＝入口在資料夾裡的相對位置，預設 `_entry`、不帶 `.json`（使用者「啊shit，那還是不要用_exec.json好了。還是_exec就夠了。」，原話的 `_exec` 即現在的 `_entry`，名字見 [thinking](../../../thinking/2026-10/23/naming.md)）——入口只佔資料夾一層，跟 table 的一個 key 對上（C-71、C-72）；工作區的 `.stack/` 是 stack 的預設位置，跟入口無關；[ideas § 13](../../../thinking/2026-10/19/ideas/README.md)。入口有四種：可執行檔（含 shebang 檔）、inst 單子、argv 陣列、`js[$AOS_ENTRY]` 的值（單子、陣列、或字串路徑，§ 17）——定義在 C-73，找法在 N-61。同一個名字資料夾裡與 JSON 裡都用（`agent-bob/_entry` ⇄ `js["_entry"]`）。
  - `AOS_WS`＝工作區（使用者的檔與成品在哪，N-55）。
  - `AOS_STACK`＝被叫的程式自己執行中狀態放哪，預設 `$AOS_WS/.stack/`（跟 `AOS_STACK` 同字；使用者 10-23 選），**它的子程式的 stack 由它自己訂**，aos 不管巢狀（C-70）。
  - `AOS_CF`（current file）＝**實際被執行的那個檔**的絕對路徑（解開捷徑；不帶 `#/…`；字串轉向後＝最後那個檔）。
  - `AOS_CD`（current dir）＝**`AOS_CF` 所在的資料夾**＝aos-exec cd 進去的地方。
  - `AOS_CO`（current obj）＝**實際入口在那份 JSON 檔裡的位置**，JSON 指標、不帶 `#`（例 `/dev/sub`）：最後跑到的那格；`檔#/指標` 也算在內（`x.json#/a` 再挑 `_entry`＝`/a/_entry`）；key 照 JSON 指標跳脫（`~0`、`~1`）；整份檔就是入口、或入口不是 JSON（可執行檔）＝空字串。往下走進 JSON 物件時 `AOS_CF`、`AOS_CD` 不變，只有 `AOS_CO` 跟著變（定義是頂層擬、使用者確認「aos current obj」）。
  `AOS_CF`／`AOS_CD`／`AOS_CO` 都由 aos-exec **每次呼叫覆寫**，每層看到的是自己的。loop／fsm／daemon 的 `exec` 是內嵌單子（物件）時，它們在自己行程內跑單子，跑的那段把這三個設成單子的位置（`AOS_CF`＝寫著它的設定檔、解開捷徑，`AOS_CD`＝它的資料夾，`AOS_CO`＝`/exec` 或 `/states/<名>/exec`，設定檔寫 `檔#/指標` 時接在指標後面），跑完還原成原本的；值就是 aos-exec 跑 `loop.json#/exec` 時會設的那三個（使用者 10-24「不過exec本來就應該要可以直接放內嵌單子吧」，頂層照本條推的代定，[exec-relative § 10-24 exec 直接放單子](../../../thinking/2026-10/24/exec-relative/01-使用者原文.md#10-24-exec-直接放單子)、[審後修正](../../../thinking/2026-10/24/exec-relative/01-使用者原文.md#10-24-審後修正)）。`AOS_CD` 裡的 `.env` 可以再改這幾個的任何一個，不限制、風險自擔（N-59 第 4 件；使用者「2.可以，全都可以，不限制，風險自己擔。」）——這幾個在讀 `.env` 前已設好，要那一跳加 `--dotenv-override` 才改得了（N-58）；`.env` 設的 `AOS_ENTRY` 對這一層挑入口就有作用（讀完 `.env` 才挑入口檔，N-59 第 4 件、[ideas 10-21 § 5](../../../thinking/2026-10/21/ideas/03-5-標準實作與-AOS_ENTRY-的順序.md#5-標準實作與-aos_entry-的順序10-21-晚)）。用處是程式 cd 走之後還能找回自己的東西（例 `cd "$AOS_WS" && … && aos-exec "$AOS_CD/tools/stamp"`）。三類分法（繼承／每層覆寫／叫別人時明給）在 CONVENTION P-39。（使用者 10-19：「純粹把資料夾作為lisp的list或lua的table，然後有一個entry……」「然後執行狀態這塊由agent-bob自己訂……」「那就AOS_WS。」；[ideas § 1～§ 3](../../../thinking/2026-10/19/ideas/README.md)；CONVENTION P-01）
