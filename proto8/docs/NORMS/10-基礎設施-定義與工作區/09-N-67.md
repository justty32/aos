## 可遷移性檢查單（11-06）

- **N-67 可遷移性檢查單**（使用者 11-06 題 4 選「概念＋檢查單 (Recommended)」，[os-concepts 使用者裁定](../../../thinking/2026-11/06/os-concepts/README.md#使用者裁定11-06選項框)；形狀照 [os-concepts 10 規範層草稿](../../../thinking/2026-11/06/os-concepts/10-可遷移性原則草稿與root例外.md#原則草稿只草稿條號由-lift-to-norms-隊定不改條文)；概念 [C-83](../../CONCEPTS/01-設計理念/09-C-83.md)）：把散在各處的已裁事項收成一條檢查單；image 範圍與整樹凍住搬家定義統一見 [C-79](../../CONCEPTS/02-設計理念-時空.md)（使用者裁定 sol 審查 #19），逐項對：
  ① **image 裡的位址一律相對 daemon 的 stack**（[N-28](../04-基礎設施-loop與daemon/02-N-28.md)：表上的 `stack`、`ws`、`exec`、`def` 存相對、讀時從現在的 stack 拼回，基準是最近的上一層 daemon）。已實作。
  ② **期限用 cycle、跨樹用毫秒**（[N-65](../02-設計理念-時空.md) 兩鐘規則；daemon-board 題 1）：這裡的毫秒指跨樹採牆鐘語意、不數 cycle；格式不限，既有秒數／ISO 格式照舊，不要求改成 epoch 毫秒（使用者裁定 sol 審查 #11）。內部時鐘已實作（[tick-time 04](../../../thinking/2026-11/05/tick-time/04-T線實作結果.md)、[05](../../../thinking/2026-11/05/tick-time/05-T5T6T8與試驗場.md)），這不表示跨樹信件已改成毫秒格式。
  ③ **原生機制**：表列設定（`limits` 等）由 daemon 起子行程時套用（N-28 的 `limits`）。不經 daemon 直接用的程式在自己 README 寫明「搬不走什麼」（[os-concepts 09-續 偏離表](../../../thinking/2026-11/06/os-concepts/09-續-偏離建議的地方與方向題.md)），各程式 README 照偏離表逐支補（還沒排步）。
  `nice`、CPU 釘核這類「建議」先不進 daemon 的 `limits`；要用就在那一列的 `exec` 前面自己包 `nice`／`taskset`，代價是表上看不到、核號只對這台有效。等壓測出現「daemon 被餓」才考慮加 `limits.nice`。（使用者裁定，出處 [wf/workflows/refactor/reports/2026-11-07-sol審查/11-使用者裁定.md](../../../../wf/workflows/refactor/reports/2026-11-07-sol審查/11-使用者裁定.md) #34-4）
  ④ **行程狀態（pid、`started_at_ticks`、`boot_id`、鎖）不是真相**：只給上一層 daemon 判活（[N-17](../05-基礎設施-窗/06-N-17.md)），搬過去對不上＝全當死＝正確。已實作，aos-lock 用檔案鎖（[N-15](../05-基礎設施-窗/04-N-15.md)）。使用者 11-06 題 5 選「不放寬 (Recommended)」，這一項不跟著「經 daemon 降成建議」放寬（理由見 C-83）。
  ⑤ **root 例外**：root daemon 的這台綁定（systemd／s6、`prlimit`／scope、帳號、sudo 規則、人 export 的絕對變數、ctl 信箱擁有者）不進 image；搬家＝照食譜重建 root（使用者「在使用者作為保底的情況下，實作上可以稍微拉扯一下」，[os-concepts 10](../../../thinking/2026-11/06/os-concepts/10-可遷移性原則草稿與root例外.md)）；食譜是 no-pid P8（[實作步驟](../../../thinking/2026-11/05/no-pid/07-實作步驟.md)）。root 可以放寬哪些、邊界與重建四步見 [os-concepts 10 § root 可放寬](../../../thinking/2026-11/06/os-concepts/10-可遷移性原則草稿與root例外.md#root-daemon-可以放寬的直接用綁這台)（細節是 fable 代定、P8 食譜的料，不是條文）。
  ⑥ **檢驗法**：睡著 → `cp -a`／git → 另一台 `aos-exec` 醒來接著跑；no-pid P8 試驗場就是這條的測試。
  ⑦⑧⑨ 依據使用者 11-05「aos體系下，唯一與json無關的，就是環境變數」——值一旦寫進 JSON，就把唯一不是 JSON 的東西偷渡進 image（使用者 11-06 選項框「加進條文 (Recommended)」；草稿與盤點見 [env-portability](../../../thinking/2026-11/06/env-portability/README.md)、[04 規範草稿](../../../thinking/2026-11/06/env-portability/04-規範草稿.md)）：
  ⑦ **環境變數的值不落檔**：程式不把從環境讀到的值（路徑、密鑰、任何字串）寫進 stack 或定義；要記就記名字（`{"$env": X}`）或相對 stack／定義的路徑，到用的那一跳才從當下的環境解。例外：每次起來都重寫、沒人讀回的回顯欄（例 daemon 表的 `daemon` 欄），寫的程式在自己文件標「回顯、不讀回」。daemon 表、`subagents.json`、kernel 額度鍵（相對 kernel stack）、eca 小格 `ws.txt`／`stack.txt` 都照這條。aos-tools 登記檔把 env 字面與絕對 path 存下、登記檔贏過外面——使用者 11-06 選項框「C 照現況」，是已知代價、不修（[env-portability 05](../../../thinking/2026-11/06/env-portability/05-衝突與方向題.md) Q2＋Q3），搬家時照 P8 食譜檢查各工具的登記檔、必要時重新 `aos-tools add`；llm kernel 在飛的 `proc.json`／`loop.json` 存 endpoint 函數絕對路徑，沒排步、P8 實搬時驗。
  ⑧ **密鑰只走環境、不落檔**：定義裡的密鑰只准寫成 `{"$env": X}` 或指向樹外的 `$ref`；解開的值只活在行程的記憶體與 pipe 裡，不寫進信、信資料夾、窗、登記檔；凍住的 image 裡 grep 不到任何密鑰。llm kernel 的金鑰歸端點小 proc（使用者「金鑰應該由那個小proc自己保管，我們在定義那個小proc的時候就要跟他說讀哪個環境變數當金鑰了」）：kernel 連指示詞都不經手，每個要金鑰的端點有自己的小定義資料夾（`_entry` 寫 `llm_http --key-env 變數名`），kernel.json 那包只指 `exec`、沒有 `key`（[env-portability 06](../../../thinking/2026-11/06/env-portability/06-E1改-金鑰歸小proc.md)）。`aos-tools add --envs` 存明文那半跟 ⑦ 同題、使用者選照現況（已知代價；密鑰別用 `--envs`、用 export）。
  ⑨ **環境變數只指兩種地方**：樹內（daemon 或 aos-exec 每次醒來重設的，或從 `$AOS_CD` 算出來的）、或 root 層以上（人 export、root 的 `env.sh`）；定義的 `.env` 不寫絕對路徑，跨樹的 hub（`AOS_LLM_KERNEL` 等）只在 root 層設。
  **檢驗法併 ⑥**：睡著 → `cp -a` 到別的路徑 → `grep -rIl` 舊根路徑與每個密鑰值應為零（回顯欄除外）→ 醒來接著跑。

③「搬不走什麼」、⑤ root 重建、⑥ 三層睡醒搬家驗法，以及 ⑦⑨ 的工具登記檔／外接 hub 檢查收在程式文件與 P8 食譜；文件落點、實跑範圍與未覆蓋項見 [18-P8實作結果](../../../thinking/2026-11/05/no-pid/18-P8實作結果.md)。
