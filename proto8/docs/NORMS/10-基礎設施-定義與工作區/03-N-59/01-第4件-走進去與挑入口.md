# N-59 第 4 件：走進一層、挑入口、挑完重設

  4. **走進去、讀 `.env`、挑入口**（別處引用的「N-59 第 4 件」就是這段）：
     - **走進一層**＝**cd 到那個資料夾**（XXX 是資料夾且 `AOS_ENTRY` 預設 `_entry` 時＝`cd DIR`；XXX 是檔時 cd 到它所在的資料夾——§ 18 ③ 使用者「按照建議」）→ **讀那裡的 `.env` 套進環境**（使用者：「而.env，他就是cd過去後，"設好環境變數"這一段，的功能，他是互補的。」，[ideas 10-21 § 4](../../../../thinking/2026-10/21/ideas/02-4-aos-exec-支援-env.md#4-aos-exec-支援-env10-21)）→ 旗標蓋回（N-58）。沒有 `.env`＝什麼都不做。**預設不蓋**：開始讀這份 `.env` 那一刻環境裡已有的名字，那一行跳過（格式照驗、壞了照報錯）；同一份檔裡同名照樣後者贏；這一跳加了 `--dotenv-override` 才蓋（N-58，[ideas 10-22 § 3](../../../../thinking/2026-10/22/ideas/02-3-env-基礎子集與---dotenv-ove.md#3-env-基礎子集與---dotenv-override10-22)）。所以不蓋時多層 `.env` 是**外層（先讀的）贏**，蓋的那一跳內層贏外層。走進那一刻 `$AOS_ENTRY` 就是 `.env`＝那份 `.env` 是入口、不讀成環境（頂層代定，ideas 10-21 § 6.3）。
     - **讀完才照當下的 `$AOS_ENTRY` 挑入口**（可能被 `.env` 改過；[ideas 10-21 § 5](../../../../thinking/2026-10/21/ideas/03-5-標準實作與-AOS_ENTRY-的順序.md#5-標準實作與-aos_entry-的順序10-21-晚)：使用者講的順序是「cd過去→設環境變數→跑檔案」，挑檔屬於跑檔案那一步，所以 `.env` 設的 `AOS_ENTRY` 要有用）。XXX 是資料夾：`$AOS_ENTRY` 一段段走，`sub/run` 這種多段路徑**沿路經過的每個資料夾都走進去、`.env` 都讀**（由外到內）；**挑到的是資料夾就走進去**（cd、讀它的 `.env`、旗標蓋回，再照當下的 `$AOS_ENTRY` 挑，一路往下）（10-21 晚使用者「a」：真資料夾與 JSON 物件都每層讀，[ideas 10-21 § 6](../../../../thinking/2026-10/21/ideas/04-6-JSON-物件當資料夾-一路往下-AOS_C.md#6-json-物件當資料夾一路往下aos_co10-21-晚)）。走回走過的資料夾＝入口壞（多段路徑中間經過的也算，例 `sub/../sub/run`；`.` 不算走進新資料夾；空的段不算一段，`_entry/`＝`_entry`——頂層代定，[ideas 10-21 § 7](../../../../thinking/2026-10/21/ideas/05-7-審後的五個細縫與修正.md#7-審後的五個細縫與修正10-21-晚)）。XXX 是檔（含 `檔#/指標`、補 `.json`）：已經走進它的資料夾、讀過 `.env`，之後 JSON 沒 `argv` 的物件取 `js[$AOS_ENTRY]` 用讀完 `.env` 之後的值。
     - **沒 `argv` 的 JSON 物件＝資料夾**（[ideas 10-21 § 6](../../../../thinking/2026-10/21/ideas/04-6-JSON-物件當資料夾-一路往下-AOS_C.md#6-json-物件當資料夾一路往下aos_co10-21-晚)）：先套它的 `.env` key（`{"名字": 值}`，值可以放指示詞、同單子那套；解完不是字串的那一項**靜默跳過**——只有 JSON 的 `.env` key 這樣，`.env` 檔格式錯照舊是錯；字串照 `.env` 檔的規則展開 `${名字}`），旗標蓋回，再照當下的 `$AOS_ENTRY` 取那格，又是沒 `argv` 的物件就一路往下；真資料夾的 `.env` 先讀、物件的 `.env` key 後讀（預設不蓋＝先讀的贏，這一跳加 `--dotenv-override` 才是後讀的贏）。**`.env` key 裡的指示詞（`$env`…）只看進入物件之前的環境**，看不到同一個物件裡前面的 key；同物件裡互相引用用 `${名字}`（逐項展開、看得到前面設的；10-21 晚使用者「全照建議」，ideas 10-21 § 7）。**進入物件那一刻（還沒套它的 `.env` 之前）`$AOS_ENTRY` 就是 `.env`＝照做**：`.env` 那格當入口、不當環境設定，所以這時那個物件沒辦法另外設 `.env`（使用者「AOS_ENTRY等於.env時，那就將照做，就等於沒辦法另外設.env了。」）。
     - **挑完重設**：`AOS_CF`＝實際的檔、`AOS_CD`＝它所在的資料夾、`AOS_CO`＝入口在檔裡的指標；入口檔是指到別處的捷徑就 cd 到實際的資料夾，那邊的 `.env` 不讀。**最後讀的那一份** `.env`（檔或 JSON 的 `.env` key）自己設了 `AOS_CF`／`AOS_CD`／`AOS_CO` 時就不蓋（這三個讀 `.env` 前已設，只有加 `--dotenv-override` 時 `.env` 設得了，這句才用得上）；更早讀的那幾份設的不算（頂層代定 ideas 10-21 § 5.3、§ 6.3；「只看最後一份」10-21 晚使用者「全照建議」，§ 7）。
