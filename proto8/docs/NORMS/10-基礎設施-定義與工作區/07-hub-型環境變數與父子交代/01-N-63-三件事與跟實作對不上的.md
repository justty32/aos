## hub 型環境變數（10-28）

- **N-63**（10-28 定，草稿；使用者 10-28「hub 照你的建議定薄標準。」，[thinking 10-28 medium](../../../../thinking/2026-10/28/medium/README.md) 決定 17）**hub（類 singleton、全樹共用的那一個東西）用環境變數指，只定三件事，其他不管**：
  ① **命名 `AOS_<名字>`，值是一個資料夾的路徑**；
  ② **沒設定＝報錯、說缺什麼**：代號 `<名字>Missing`（C-54，例 `StackMissing`、`DaemonMissing`），不自己猜一個位置；
  ③ **子 process 預設繼承**（照 Linux 環境變數本來的樣子往下傳）。
  資料夾裡放什麼、誰建、怎麼跟它講話，各 hub 自己定。現有的實例：`AOS_STACK`（執行中狀態放哪，N-57）、`AOS_LLM_KERNEL`（llm kernel 的信箱資料夾，N-16、N-42、[aos-llm](../../../../impls/aos-llm/README.md)；11-05 前叫 `AOS_KERNEL`，見下「舊名退場」；**11-05 改**：值改成 llm kernel 的 **stack**，見下）、`AOS_DAEMON`（見下）、`AOS_KERNEL`（11-05 起＝「要掛 proc 往哪寄」的信箱資料夾，見下）。
  - **跟實作對不上的**（只列、程式沒改）：
    - `AOS_STACK` 沒設時 **aos-exec 自己退回預設** `$AOS_WS/.stack/`（N-57、C-69，impls aos-exec `setup_ws_stack`），跟 ② 不合；aos-loop（開了窗才要）、aos-fsm、aos-daemon、aos-llm-kernel 沒設就報 `StackMissing`，合。 **11-04 定**（使用者 11-04 題 1「只有 aos-exec 給」，[four-elements 06](../../../../thinking/2026-11/04/four-elements/06-要使用者裁的題.md#使用者裁定11-04選項原文或他的話逐字)）：`AOS_STACK` **只有 aos-exec 給預設**（它負責建），其他程式沒設＝`StackMissing`（aos-tools `call` 可執行檔工具 11-04 起也是，不再偷用暫存資料夾）；替人下 aos-exec 的人殼指令算成那一跳、照 aos-exec 的預設。
    - `AOS_LLM_KERNEL` 沒設時 aos-llm（11-04 晚前叫 aos-llm-send）報 `KernelMissing`、不猜位置，合 ②（**11-04 已改**：原本代號是 `MailboxMissing`，四元素審查；**11-05 改**：代號改名 `LlmKernelMissing`，見下「舊名退場」）。kernel 那一邊（aos-llm-kernel）不讀 `AOS_LLM_KERNEL`，信箱位置讀 kernel.json 的 `mailbox`（**11-05 改**：`mailbox` key 拿掉，kernel 讀自己的 `$AOS_STACK/mailbox/`，N-42 (1)）；範本 `kernel/llm-kernel` 的信箱在它的 `$AOS_STACK` 底下，由人把那個路徑 export 成 `AOS_LLM_KERNEL`（掛 daemon 時＝`$AOS_DAEMON/procs/<名>/mailbox/`）（**11-05 改**：`AOS_LLM_KERNEL` 的值＝llm kernel 的 **stack**〔合一時＝那台 llm daemon 的 stack，例 `~/llm_kernel`〕，信箱固定 `<stack>/mailbox/`、`ask` 的回信信箱 `<stack>/mailbox/reply/`；kernel 那邊照舊不讀它、讀自己的 `$AOS_STACK/mailbox/`。使用者 11-05「我先在把定義複製到~/llm_kernel/def，然後cd ~/llm_kernel && aos-exec def，把llm的daemon+kernel叫起來。…叫起來之前要先設AOS_LLM_KERNEL=~/llm_kernel/.stack。」「啊不對，應該說aos-exec --stack . def，直接讓他把~/llm_kernel作為stack就好」，[kernel-daemon 07](../../../../thinking/2026-11/05/kernel-daemon/07-llm-daemon佈局.md)）；**daemon 不代設**（使用者 11-05「用人設吧，你得自己指定。AOS_KERNEL這個命名我感覺他是通用於所有proc的，像是llm請求這塊，感覺要用AOS_LLM_KERNEL，代表llm這個子領域下的，管理呼叫的kernel。」（[thinking 11-05 portable-flow 05 方向題 5](../../../../thinking/2026-11/05/portable-flow/05-衝突與方向題.md)））。
    - **舊名退場**（11-05，照 11-04 `AOS_DAEMON_STACK` 的做法）：`AOS_KERNEL` 改名 `AOS_LLM_KERNEL`、不留別名——只設了 `AOS_KERNEL`、沒設 `AOS_LLM_KERNEL`＝aos-llm 報 `KernelMissing`，訊息提示改設 `AOS_LLM_KERNEL`。`AOS_KERNEL` 這個名字留給以後「通用於所有 proc 的 kernel」（使用者同句）；代號 `KernelMissing` 沒跟著改名（實作代定、可翻案）。**11-05 改**（隊長代定、可翻案）：代號 `KernelMissing` 改名 **`LlmKernelMissing`**——照 C-54 主詞在前、R4 一詞一義，`Kernel` 留給通用 kernel；舊代號不留別名（[附錄3 舊名對照](../../附錄3-舊名對照.md)）。
    - **實例 `AOS_KERNEL`**（11-05；使用者 11-05「AOS_KERNEL這個命名我感覺他是通用於所有proc的」；第二種模式「kernel作為一個唯一有權限對daemon下daemon-ctl指令的proc，其他人要掛proc，就是要改將請求丟給這個kernel proc」；fable 代定 3、可翻案，[thinking 11-05 kernel-daemon](../../../../thinking/2026-11/05/kernel-daemon/README.md) [02/01 § 4](../../../../thinking/2026-11/05/kernel-daemon/02-兩種模式/01-唯一-AOS_KERNEL-命名.md)）：值＝「要掛 proc 往哪寄」的信箱資料夾（收 `procs_*` 信，形狀同 daemon 的 ctl 信箱；走 0 號 proc 式時＝那個 kernel proc 的收件信箱）。**沒設＝寄 `$AOS_DAEMON` 的 ctl 信箱、不報 Missing**（daemon 就是最基礎的 kernel）——跟 ② 不合，是刻意的例外。人設，或寫進 daemon 的 `.env`；aos-llm-kernel（寄問腦的掛信）、aos-daemon-ctl（aos-agent 經它）認。`aos-daemon-ctl --reply-to` 帶的信寄到這裡、判官不掛＝回 `applied: false`（帶 `error` 的 `code`／`msg`；放行＝照帶 `reply_to` 轉給 daemon、由 daemon 回，11-05）。
    - ③ 跟 [CONVENTION P-39](../../../CONVENTION/06-巢狀/03-P-37～P-40.md) 的寫法不同：P-39 把 `AOS_STACK` 歸「叫別人時明給」（每層開小格、重設），不是一路繼承；繼承是預設，P-39 是 agent 範本在叫別人時的做法。
