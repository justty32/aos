## hub 型環境變數（10-28）

- **N-63**（10-28 定，草稿；使用者 10-28「hub 照你的建議定薄標準。」，[thinking 10-28 medium](../../../../thinking/2026-10/28/medium/README.md) 決定 17）**hub（類 singleton、全樹共用的那一個東西）用環境變數指，只定三件事，其他不管**：
  ① **命名 `AOS_<名字>`，值是一個資料夾的路徑**；
  ② **沒設定＝報錯、說缺什麼**：代號 `<名字>Missing`（C-54，例 `StackMissing`、`DaemonMissing`），不自己猜一個位置；或在[四種性質表](03-AOS_-變數的四種性質.md#退路)那一列寫明唯一一條退路；
  ③ **子 process 預設繼承**（照 Linux 環境變數本來的樣子往下傳）。
  資料夾裡放什麼、誰建、怎麼跟它講話，各 hub 自己定。現有的實例：`AOS_STACK`（執行中狀態放哪，N-57）、`AOS_LLM_KERNEL`（llm kernel 的 **stack**，N-16、N-42、[aos-llm](../../../../impls/aos-llm/README.md)，見下）、`AOS_DAEMON`（見 [02](02-N-63-實例-AOS_DAEMON與沒有AOS_HUB.md)）、`AOS_KERNEL`（一般 proc 送 syscall 請求的信箱資料夾，C-47；見下）、`AOS_CLOCK`（見 [03](03-AOS_-變數的四種性質.md)）。舊名對照在 [附錄3](../../附錄3-舊名對照.md)，舊名一律不留別名。
  - **各實例跟 ①～③ 的細節**：
    - `AOS_STACK` **只有 aos-exec 給預設** `$AOS_WS/.stack/`（它負責建；N-57、C-69，impls aos-exec `setup_ws_stack`；使用者 11-04 題 1「只有 aos-exec 給」，[four-elements 06](../../../../thinking/2026-11/04/four-elements/06-要使用者裁的題.md#使用者裁定11-04選項原文或他的話逐字)），是 ② 的例外；其他程式沒設＝`StackMissing`：aos-loop（開了窗才要）、aos-fsm、aos-daemon、aos-llm-kernel、aos-tools `call` 的可執行檔工具（不偷用暫存資料夾）。替人下 aos-exec 的人殼指令算成那一跳、照 aos-exec 的預設。
    - `AOS_LLM_KERNEL` 的值＝llm kernel 的 **stack**（合一時＝那台 llm daemon 的 stack，例 `~/llm_kernel`）；信箱固定 `<stack>/requests/`（跟判官的收件箱同名，C-54 R14；使用者 11-06 選項框「現在統一 requests/」，[mailbox-naming](../../../../thinking/2026-11/06/mailbox-naming/README.md)），`ask` 的共用回信信箱是 `<stack>/requests/reply/`。沒設時 aos-llm 報 `LlmKernelMissing`（隊長代定、可翻案）、不猜位置，合 ②。kernel 那一邊（aos-llm-kernel）不讀 `AOS_LLM_KERNEL`，讀自己的 `$AOS_STACK/requests/`（N-42 (1)）。用法例：使用者 11-05「啊不對，應該說aos-exec --stack . def，直接讓他把~/llm_kernel作為stack就好」（[kernel-daemon 07](../../../../thinking/2026-11/05/kernel-daemon/07-llm-daemon佈局.md)）。**由人設、daemon 不代設**（使用者 11-05「用人設吧，你得自己指定。AOS_KERNEL這個命名我感覺他是通用於所有proc的，像是llm請求這塊，感覺要用AOS_LLM_KERNEL，代表llm這個子領域下的，管理呼叫的kernel。」（[portable-flow 05 方向題 5](../../../../thinking/2026-11/05/portable-flow/05-衝突與方向題.md)））。
    - **實例 `AOS_KERNEL`**（使用者 11-05「AOS_KERNEL這個命名我感覺他是通用於所有proc的」；第二種模式「kernel作為一個唯一有權限對daemon下daemon-ctl指令的proc，其他人要掛proc，就是要改將請求丟給這個kernel proc」；fable 代定 3、可翻案，[kernel-daemon 02/01 § 4](../../../../thinking/2026-11/05/kernel-daemon/02-兩種模式/01-唯一-AOS_KERNEL-命名.md)）：值＝一般 proc 送 syscall 請求的地方，指到一個信箱資料夾；一般 proc 一律寄這裡（使用者 11-11「我的想法是一律寄到AOS_KERNEL」，C-47）。寄件人只寄這裡、不管背後信會去哪；收件那邊對寄件人就是 kernel。現在收的是掛 proc 的 `procs_*` 信，形狀同 daemon 的 ctl 信箱（例：0 號 proc 式擺法時＝那個 kernel proc 的收件信箱）。**沒設＝寄 `$AOS_DAEMON` 的 ctl 信箱、不報 Missing**（daemon 就是最基礎的 kernel；這是表上寫明的退路，見 [03](03-AOS_-變數的四種性質.md#退路)）；`AOS_DAEMON` 也沒設時見 [02 的 `./.stack`](02-N-63-實例-AOS_DAEMON與沒有AOS_HUB.md)。人設，或寫進 daemon 的 `.env`；daemon 不自動設（11-11：「沒設就退回 daemon」留著）。判官不掛＝回 `applied: false`（帶 `error` 的 `code`／`msg`）；放行＝照帶 `reply_to` 轉給 daemon、由 daemon 回。
      - **誰認**：**認 `AOS_KERNEL` 的是 aos-llm-kernel（寄問腦的掛信）與 aos-agent**（aos-agent import 共用套件 `py/daemon_ctl`、照它寄）；aos-daemon-ctl 不看 `AOS_KERNEL`、一律直寄 daemon 的 ctl 信箱——它是指名要碰某台 daemon 的工具，有 Linux 權限就能用（使用者 11-07 選項框「aos-daemon-ctl 永遠直寄」、11-11 選項框「維持直寄，它就是『指名 daemon』的工具」，[os-impl 08](../../../../thinking/2026-11/06/os-impl/08-aos-daemon-ctl永遠直寄實作結果.md)；人平常用的 `aos-agent ctl` 走 kernel，C-47「安全的保底是 Linux 本身」）。判官睡著＝設計系統的人要管的風險，手動 `aos-daemon-ctl wake 名字`。
    - ③ 跟 [CONVENTION P-39](../../../CONVENTION/06-巢狀/03-P-37～P-40.md) 的寫法不同：P-39 把 `AOS_STACK` 歸「叫別人時明給」（每層開小格、重設），不是一路繼承；繼承是預設，P-39 是 agent 範本在叫別人時的做法。
    - **② 的「給」與 `DaemonFailed`**：② 管的是「沒給就報錯、不猜」；`--daemon`、argv、設定檔、信裡帶路徑都算「給」。使用者 11-05 晚：「只靠環境變數找DAEMON，只是因爲這最方便，誰也限制不了你透過其他方式傳遞daemon位置」。不准的是拿 Linux 行程資訊（掃 `/proc` 的 argv／environ、讀 pid）去猜位置；aos 函數默認吃得到 aos-exec 的六個（見 [lib 規則 11](../../../../lib/docs/01-分層等.md)）。②「沒設定＝`<名字>Missing`」照字面成立，`DaemonMissing` 只留給沒設／daemon 資料夾不在；**`DaemonFailed`**＝找到 daemon 的資料夾了，但這次呼叫沒等到回信（aos-agent 的 ctl 等滿時限、仍沒回且表上結果未成立時；表上結果先成立的，另留 1 秒等回信後可先成功；`aos-daemon-ctl ping` 同理）（11-07 使用者裁定 sol 審查 #28；見 [no-pid 03](../../../../thinking/2026-11/05/no-pid/03-找daemon與脫鉤.md)、[10 P3](../../../../thinking/2026-11/05/no-pid/10-P3實作結果.md)、[11 P4](../../../../thinking/2026-11/05/no-pid/11-P4實作結果.md)）。**時限由寄信者自己設定、判官輔助**（使用者 11-06「由寄信者自己設定。然後30秒？這不該是固定值，同樣該由寄信者自己設定。判官會輔助。」）：aos-agent ctl 用 `--timeout-s`（預設 30 秒），並帶進信 body 的 `queue_wait_ms` 給判官排隊用；`aos-daemon-ctl ping` 用 `--timeout-s`（預設 3 秒），直寄 daemon、不帶 `queue_wait_ms`（[os-impl 05](../../../../thinking/2026-11/06/os-impl/05-寄信者自設逾時.md)、[寫死的等待盤點](../../../../thinking/2026-11/06/os-impl/05-續2-寫死的等待盤點.md)）。

  - **跨樹 hub**：hub 型變數指到別棵樹的（`AOS_LLM_KERNEL` 等）算外接，搬家後由人在新機器重設；在飛的跨樹請求作廢重寄。使用者 11-06「兩題都按照推薦。」（[daemon-board 遷移題 1](../../../../thinking/2026-11/06/daemon-board/04-凍住後要能遷移-續.md)）；食譜見 [18-P8實作結果](../../../../thinking/2026-11/05/no-pid/18-P8實作結果.md)。
  - aos-sandbox 預設帶 hub 型變數，含 `AOS_KERNEL`、`AOS_CLOCK`（使用者 11-06 選項框，[README](../../../../cmd/aos-sandbox/README.md)）。
