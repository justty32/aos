- **N-61**（10-19 下班前定，草稿，[ideas § 15、§ 17、§ 18](../../../thinking/2026-10/19/ideas/README.md)）**aos-exec 怎麼從 XXX 找到入口、怎麼判斷種類**：
  - **路徑**：XXX 是資料夾 → `XXX/$AOS_ENTRY`（`$AOS_ENTRY` 是讀完 `XXX/.env` 之後的值，N-59 第 4 件）；沒有再找 `XXX/$AOS_ENTRY.json`；**`$AOS_ENTRY` 指到資料夾＝走進去**（cd、讀它的 `.env`、照當下的 `$AOS_ENTRY` 再挑、一路往下，N-59 第 4 件、[ideas 10-21 § 6](../../../thinking/2026-10/21/ideas/04-6-JSON-物件當資料夾-一路往下-AOS_C.md#6-json-物件當資料夾一路往下aos_co10-21-晚) J3）——所以同名的資料夾與 `.json` 都在時**資料夾贏**（`XXX/$AOS_ENTRY` 是資料夾就走進去，不看旁邊的 `$AOS_ENTRY.json`）。XXX 不是資料夾、沒有副檔名、又找不到 → 順道找 `XXX.json`。（使用者：「如果是資料夾，那就去找XXX/AOS_ENTRY，更進一步就是XXX/AOS_ENTRY.json」「如果aos-exec XXX，那個XXX非資料夾、後面沒有副檔名，然後又找不到這個XXX在哪，那aos-exec就會順道去找XXX.json」）
  - **JSON 內不補**：找到的檔若是 JSON、但不是單子，就往檔內找 `js[$AOS_ENTRY]`（預設 `js["_entry"]`）——資料夾與 JSON 同一套尋址（C-72）；不會再試 `js["_entry.json"]`。（使用者 § 15：「如果找到了檔案，但該檔案的json格式並非inst json，那就去找這個json檔案的js["_exec"]，也就是AOS_ENTRY。」§ 17：「至於json內部，就沒有這個特例了，就乖乖找AOS_ENTRY」）**一路往下**：取出來的值又是沒 `argv` 的物件，就當資料夾再走進去（套它的 `.env` key、照當下的 `$AOS_ENTRY` 再取），直到不是沒 `argv` 的物件為止（使用者「2.b，我們就是這樣規定的，具體風險由使用者自己承擔」，[ideas 10-21 § 6](../../../thinking/2026-10/21/ideas/04-6-JSON-物件當資料夾-一路往下-AOS_C.md#6-json-物件當資料夾一路往下aos_co10-21-晚)）。挑的時候不解 `$ref`，走的是那份 JSON 的樹、不會無限。
  - **種類**：有 `+x` 而且內容像程式（開頭 `#!` 或 ELF〔`\x7fELF`〕，或整份不是 JSON）＝可執行檔，直接 exec（shebang 由 kernel 處理；沒 `#!` 的改用 `/bin/sh` 跑，N-59 第 5 件）；其餘（沒 `+x`，或 `+x` 但整份是 JSON）就當 JSON 讀（第一行 `#!` 跳過）〔11-10 two-machines（使用者准「1.可以」）：/mnt/c（drvfs 沒 metadata）每個檔都是 0777，只看 `+x` 會把 JSON 入口當程式跑；`+x` 只是能 exec 的條件、種類看內容，ext4 上結果不變〕，**有 `argv` 這個 key＝inst 單子**（§ 18 ② 使用者「2.好。」）、非空陣列＝argv（元素可以是字串或 `$env`／`$ref` 指示詞，開跑前解、解完要全是字串，不是＝入口壞；10-20 使用者，見 [ideas](../../../thinking/2026-10/20/ideas.md) D2、D8，N-45）、字串＝路徑轉向、沒 `argv` 的物件＝當資料夾、取 `js[$AOS_ENTRY]` 一路往下（見上一點）；其餘判斷順序由實作照 KISS 定。
  - **字串＝路徑轉向**：`js[$AOS_ENTRY]` 的值是字串時（例 `"_entry": "tool"`），等同 `aos-exec 那個路徑`、整套規則從頭再來（＝**交給下一層、全新的一次 aos-exec**：這次命令的旗標不帶過去、XXX 後的 args 照接，下一層自己 cd、讀它那裡的 `.env`，N-58、N-59 第 4 件，[ideas 10-21 § 4](../../../thinking/2026-10/21/ideas/02-4-aos-exec-支援-env.md#4-aos-exec-支援-env10-21)）；相對路徑以 aos-exec 執行它時的 cwd 為準＝寫著它的那個檔所在的資料夾（aos-exec 跑它之前已 cd 進去，§ 17 頂層補充）。（使用者：「不過js[AOS_ENTRY]的值可以是字串，也就是js["_exec"]:"loop.json"，相對路徑的話是參照於aos-exec在執行他的時候的cwd，loop.json可以是資料夾或檔案，這等同於aos-exec loop.json，等於是複用那個規則」；§ 18 ①：`loop.json` 是 loop 的設定、不是入口，aos-exec 不認 loop／fsm 設定，要寫就寫 `"_entry": ["aos-loop", "loop.json"]`）
  - **繞圈由 aos-exec 自己偵測**：字串轉向走回走過的位置（`a → b → a`）＝入口壞、退 1；不設深度上限（P-37）。（§ 18 ④ 使用者：「4.aos-exec自己要做偵測。」）**這是「每層只管自己」（C-52）的唯一例外**：字串轉向每一跳都是全新的一次 aos-exec（N-58、N-59 第 4 件），照理不記得上一跳；繞圈偵測仍沿用同一條走過的鏈，當安全網（10-21 晚使用者「全照建議」，[ideas 10-21 § 7](../../../thinking/2026-10/21/ideas/05-7-審後的五個細縫與修正.md#7-審後的五個細縫與修正10-21-晚)）。
    **11-06 改讀**（[special-cases](../../../thinking/2026-11/06/special-cases/05-衝突與方向題.md) 盤出的矛盾）：「唯一例外」改讀成「aos-exec 這一層的例外」——C-52 另有 10-28 round 參數與准讀下層 stderr 的判準（[C-52 續](../../CONCEPTS/01-設計理念/03-續-C-52-例外.md)）。
  - **argv[0] 怎麼跑**（10-20 使用者，見 [ideas](../../../thinking/2026-10/20/ideas.md) D3～D5）：適用所有跑 argv 的地方——入口的 argv 陣列、單子的 `argv`（aos-exec 跑的、loop／fsm 內嵌的）。**沒 `/` 一律照 PATH 找**（D4：「就是要有/才算路徑」）。**有 `/`**：是上一點認成可執行檔的一般檔（`+x` 且內容像程式）就照舊直接 exec（不 cd、不設 `AOS_CF`，現有寫法行為不變）；**exec 不了的——資料夾、沒 `+x` 的檔、`+x` 但是 JSON 的檔（11-10）、不在、或帶 `#/`——等同在前面插 `aos-exec`**，由 inst 叫 PATH 上的 `aos-exec`（D3：「分層衝突沒關係，就是要inst依賴PATH中的aos-exec」）；相對路徑照子程式的 cwd 算。D5：`["tools/stamp", "a"]`＝`["aos-exec", "tools/stamp", "a"]`；第二個元素起都是 args（工作區由 `--ws` 給，N-58）。PATH 上沒有 `aos-exec`＝起不來（單子：程式找不到）。工具的小格（stack）、算不算暗規則，使用者沒回，照通則不追問（D6，ideas § 2 的 (4)、(5)）：插進去的 `aos-exec` 沿用現有的 `AOS_WS`／`AOS_STACK`，跟手寫 `aos-exec` 一樣。
- **N-62**（10-19 下班前定，草稿，[ideas § 19](../../../thinking/2026-10/19/ideas/README.md)）**路徑支援 JSON 尋址 `檔#/指標`**：`cfg.json#/tools/stamp`＝cfg.json 裡 `/tools/stamp` 那個值，寫法是 JSON pointer（RFC 6901：`#/` 開頭、一層一個 `/`，`~0`＝`~`、`~1`＝`/`），指到的值照 N-61 的種類判斷（單子、argv 陣列、字串轉向、或沒 `argv` 的物件再取 `js[$AOS_ENTRY]`）。**第一個 `#` 就切、不支援檔名含 `#`**（照舊 N-35 的做法）；`#` 後面一定要 `/`；資料夾或可執行檔帶 `#/`＝入口壞；指不到＝找不到。只用在 aos-exec 的入口路徑（XXX 與字串轉向），單子裡的 `$env` 路徑不認 `#`。另兩處也認 `#/`（10-20 使用者，見 [ideas](../../../thinking/2026-10/20/ideas.md) D1、D3）：`$ref` 的檔名（N-45，同一套寫法）、argv[0]（帶 `#/`＝交給 aos-exec，N-61）。`AOS_CF` 不帶 `#/…`（指標位置在 `AOS_CO`，N-57）。（使用者：「並且支援json尋址，也就是loop.json#_exec」→ 頂層提 `#a/b` 或 `#/a/b` →「#/。」「尋址一定值得。」）
