## 函數的 _metainfo：放哪、怎麼找、誰讀（10-24）

- **N-69**（使用者 10-24「一個函數是用_entry去跑。其特性我想要將其寫到_metainfo，裏面可以存放該函數要跑多久，要喫多少資源這種東西。相關的.json格式也要規劃。然後kernel也可以透過這個，來做參考」，規劃後「我現在沒空管這些小事，都按建議做」；[thinking 10-24 `_metainfo`](../../../thinking/2026-10/24/metainfo/README.md) M1～M10；11-12 使用者裁 Q16「a」照現況落條文）**`_metainfo` 是函數的那排屬性**——檔案有 `ls -l` 那排，函數沒有。給 kernel、審視者與人參考，**模型看不到**（給模型看的是 `_tooldef`，P-41）。
  - **放哪**：同一個名字、兩種寫法。資料夾裡跟 `_entry` 並列的檔 `_metainfo.json`（11-04 起帶 `.json`，不帶的不認）；JSON 定義裡的 `_metainfo` key——JSON 檔的頂層，或 `檔.json#/指標` 那個物件裡（單子裡也可以寫，地位同 `argv`）。
  - **怎麼找**：讀的人看它手上那個位置的那一處：資料夾看 `_metainfo.json`，JSON 檔或 `檔.json#/指標` 看那個物件的 `_metainfo` key（共用讀法 `lib/metainfo.py` 的 `read`；aos-tools 登記的工具 `ls --json`／`get` 一起帶出來）。不順著入口往下追：資料夾裡 `_entry` 單子的 `_metainfo` key 沒有人讀（函數長大時的情形見 [C-55 的 10-24 補](../../CONCEPTS/01-設計理念/05-續-C-55-函數成長.md)）。可執行檔工具沒有這一處。
  - **內容**：沒有必填、不強迫寫（N-68）；通用 key 全選填，沒寫＝沒說，其餘自由（C-14），不認得的忽略（C-48）。現在用到的通用 key：`summary`（一句話）、`cost` 與 `timeout_ms`、`comfort`（三個見 N-68）、`resource`、`side_effect`、`idempotent`、`deterministic`、`interrupt`、`parallel`、`arbitrary_exec`、`sandbox`（[C-64 的 10-24 補](../../CONCEPTS/01-設計理念/05-布局成長與檔案權限.md#檔案權限10-16-使用者定)）。數量類照 C-48 的雙形。不加版本 key：只加 key，要改意思就換新名字（C-48）。
  - **誰讀、讀了做什麼**：aos-exec、inst 與指示詞都不讀（C-48、N-04、N-45 只解自己讀的格）。act 格與 aos-mcp 照 `timeout_ms` 殺工具（N-68）；aos-mcp 把 `side_effect`／`idempotent`／`resource` 換成 MCP 的提示；shell 帳（`shell_report`）看 `arbitrary_exec` 與有沒有 `sandbox`；審視工具 `metainfo_check` 讀 `cost`；定義樹的檢查（`defs`、`agent_def check`）要定義的 `_metainfo.json` 有 `summary`；`tools_def` 與 `lib/tool_spec.py` 產新工具時寫一份（沒給的補保守預設）。kernel 現在不讀（11-04 起 llm kernel 的信裡沒有單子）。寫壞了怎麼辦由讀的人自己定：現在 `lib/metainfo.py` 讀到壞的 `timeout_ms`／`cost` 報 `FileBad`／`CalBad`，act 照這個停、aos-mcp 報 `ToolsBad`。
  - **實測不回寫**：跑的時候誰都不改 `_metainfo`；量到的寫在量的人自己那邊（他見的帳 `observed.jsonl`，[N-68 續](10-續-N-68.md)）。
  - 11-12 使用者有後續整合想法，見 [thinking 11-12 index](../../../thinking/2026-11/12/index.md)。
