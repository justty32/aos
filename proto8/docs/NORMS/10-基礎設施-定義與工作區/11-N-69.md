## 函數的 _metainfo：放哪、怎麼找、誰讀（10-24）

- **N-69**（使用者 10-24「一個函數是用_entry去跑。其特性我想要將其寫到_metainfo，裏面可以存放該函數要跑多久，要喫多少資源這種東西。相關的.json格式也要規劃。然後kernel也可以透過這個，來做參考」，規劃後「我現在沒空管這些小事，都按建議做」；[thinking 10-24 `_metainfo`](../../../thinking/2026-10/24/metainfo/README.md) M1～M10；使用者 11-12 裁 Q16「a」照現況寫成條文）**`_metainfo` 是函數的那排屬性**——檔案有 `ls -l` 那排，函數沒有。給 kernel、審視者與人參考，**模型看不到**（給模型看的是 `_tooldef`，P-41）。
  - **放哪**：同一個名字、兩種寫法。資料夾裡跟 `_entry` 並列的檔 `_metainfo.json`（不帶 `.json` 的不認）；JSON 定義裡的 `_metainfo` key——JSON 檔的頂層，或 `檔.json#/指標` 那個物件裡（單子裡也可以寫，地位同 `argv`）。
  - **怎麼找**：讀的人看它手上那個位置的那一處：資料夾看 `_metainfo.json`，JSON 檔或 `檔.json#/指標` 看那個物件的 `_metainfo` key（共用讀法 `lib/metainfo.py` 的 `read`；aos-tools 登記的工具 `ls --json`／`get` 一起帶出來）。不順著入口往下追：資料夾裡 `_entry` 單子的 `_metainfo` key 沒有人讀（函數長大時的情形見 [C-55 的 10-24 補](../../CONCEPTS/01-設計理念/05-續-C-55-函數成長.md)）。可執行檔工具沒有這一處。
  - **內容**：沒有必填、不強迫寫（N-68）；通用 key 全選填，沒寫＝沒說，其餘自由（C-14），不認得的忽略（C-48）。現在用到的通用 key：`summary`（一句話）、`cost` 與 `timeout_ms`、`comfort`（三個見 N-68）、`resource`、`side_effect`、`idempotent`、`deterministic`、`interrupt`、`parallel`、`arbitrary_exec`、`sandbox`（[C-64 的 10-24 補](../../CONCEPTS/01-設計理念/05-布局成長與檔案權限.md#檔案權限10-16-使用者定)）。數量類照 C-48 的雙形。不加版本 key：只加 key，要改意思就換新名字（C-48）。
  - **誰讀、讀了做什麼**：aos-exec、inst 與指示詞都不讀（C-48、N-04、N-45 只解自己讀的格）。act 格與 aos-mcp 照 `timeout_ms` 殺工具（N-68）；aos-mcp 把 `side_effect`／`idempotent`／`resource` 換成 MCP 的提示；shell 帳（`shell_report`）看 `arbitrary_exec` 與有沒有 `sandbox`；審視工具 `metainfo_check` 讀 `cost`；定義樹的檢查（`defs`、`agent_def check`）要定義的 `_metainfo.json` 有 `summary`；`tools_def` 與 `lib/tool_spec.py` 產新工具時寫一份（沒給的補保守預設）。kernel 不讀（llm kernel 的信裡沒有單子）。寫壞了怎麼辦由讀的人自己定：`lib/metainfo.py` 讀到壞的 `timeout_ms`／`cost` 報 `FileBad`／`CalBad`，act 照這個停、aos-mcp 報 `ToolsBad`。
  - **實測不回寫**：跑的時候誰都不改 `_metainfo`；量到的寫在量的人自己那邊（他見的帳 `observed.jsonl`，[N-68 續](10-續-N-68.md)）。
  - **`_metainfo` 也是口子**（[thinking 11-12 metainfo](../../../thinking/2026-11/12/metainfo/README.md)）。使用者 11-12：「…或許可以這樣說，_metainfo就是一個天然的，蒐集那些同節點下散落的(aos體系中的)各種_*」；「_tooldef要不要搬進去，我覺得是可選的，就是說，我希望我們吃_tooldef的工具，都能支援_metainfo(不強制啦)，支援的方式就是他可以指定一個節點，然後他先看看有沒有_metainfo，有的話就先讀，然後再看看有沒有獨立出來的_tooldef，有的話就再讀。如果_metainfo內有tooldef，外面也有獨立出來的_tooldef，那就兩者合併，外面獨立出來的會覆蓋掉_metainfo內的。當然，這是不強制的啦，後續其他程式自己想怎麼做都可以，反正我們就是推薦這樣。」；「_metainfo這東西，他就是只活在概念與規範中，我們目前是不做單一程式去處理的，我們就是定下來，啊其他工具要不要支援，就看他們自己」；「index_view也要認_metainfo。」；「description 寫進 _metainfo <- 先不寫入。只有{}的_metainfo.json也算agent定義。」
    - **兩格**：除了上面的特性，節點的 `tooldef`、`index` **可以**寫在 `_metainfo` 裡（名字＝外面那個去掉 `_`，使用者「_index進去後就是index，去掉_」），跟特性平鋪並排；也可以照舊獨立放在外面（資料夾的 `_tooldef.json`、`_index.json`，JSON 物件的 `_tooldef`、`_index` 鍵）。現有的獨立檔不搬、不刪；要用不用都可以。兩格的值跟外面那份一樣：`tooldef`＝P-41 的工具說明物件；`index`＝`{名: {"description": …, "index": …}}`（`index` 選填，指到另一份 index 的路徑；檔內 `_index` 本身也可以是這種路徑字串），天然位置在被描述的節點上一層（寫法與門檻目前只寫在 [knowledge/docs/01](../../../knowledge/docs/01-樹長怎樣與多庫.md)，這裡不另開條）。節點自己的正文 `_description.json`／`_description` 只放外面，不寫進 `_metainfo`。
    - **推薦讀法**：給一個節點，先看 `_metainfo` 有沒有、有就讀那一格，再看獨立的那份、有就讀，兩者合併，**獨立那份蓋過 `_metainfo` 裡的**。合併只有一層：`tooldef` 是頂層鍵淺合併（同名頂層鍵整鍵以外面為準，`parameters` 整鍵換、不往下合 schema）；`index` 是逐項整項覆蓋（同名項整項以外面為準）。兩處都沒有＝照那支工具原本「沒有」的處理。`_metainfo` 那處壞了（讀不了、不是物件、那一格形狀不對）只略過那處、提醒一句，照用獨立那份（使用者 11-12 「_metainfo.json 壞掉時，index_view 對那個資料夾不該直接報錯。」；tooldef 的工具比照）；只有壞掉的那處、拿不到可用的＝照那支工具原本「壞掉」的代號，句子指明哪一處；獨立那份壞了照它原本的處理。這是推薦、不強制，其他程式想怎麼讀都可以。
    - **不做專門處理 `_metainfo` 的程式**，也不做共用讀取模組；各工具要不要支援看它自己，要支援的在自己的程式裡加幾行。寫的一方不變（`tool_spec`、`tools_def` 照舊寫獨立的 `_tooldef.json`／`_tooldef`）。**照推薦讀法支援的**：`aos-tools`（登記與 `ls`／`get`／`call`：資料夾、JSON 檔、`檔.json#/指標` 都認 `_metainfo` 的 `tooldef`）、`lib/tool_io.py`（工具啟動時讀自己夾的定義：argv 旗標轉型、`--help`）、`tools_def`（`check` 與分階段把裡面的 `tooldef` 也算「有」，兩處都有時多印一行 note）、`index_view`（`lib/aos_index.py`：天然那份＝`_metainfo` 裡的 `index` 為底、疊上獨立的 `_index`，再給 `index` 參數就是三層，後面蓋前面）。定義樹（`defs`）不把「沒有 `_entry`、`_metainfo.json` 非空而且只有 `tooldef`／`index`」的夾當成定義；`{}` 或有其他任何鍵的 `_metainfo.json` 照舊算定義。
    - **不進 `_metainfo` 的**：`_entry`（與 `_entry.json`）、`.env`——aos-exec 跑的時候要用（使用者「_entry確實不能搬進去」）；`_description`（使用者「description 寫進 _metainfo <- 先不寫入。」）；C++ 基礎層照舊不讀 `_metainfo`。可執行檔工具只有 `--tooldef`。**裝不下的節點**（陣列、別人的 json、可執行檔）只有 `index` 延伸：寫在最近一個裝得下的上層節點的 index 裡，鍵寫相對路徑（`list/0`、`other.json#/key`）。
    - **模型看到的**：特性照舊看不到；模型看到的只有 tooldef，支援的工具給的是合併後的那份。工具不藏 `_metainfo`（`ls`、`json_ls` 照實列，C-48）。
