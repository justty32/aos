## 函數的 _metainfo：放哪、怎麼找、誰讀（10-24）

- **N-69**（[thinking 10-24 `_metainfo`](../../../thinking/2026-10/24/metainfo/README.md) M1～M10；使用者 11-12 裁 Q16「a」照現況寫成條文）**`_metainfo` 是函數的那排屬性**——檔案有 `ls -l` 那排，函數沒有。現行給審視者與人參考，kernel 現在不讀（見下「誰讀」；新舊打架，11-17「新的覆蓋舊的」：11-12 照現況較晚）；**模型看不到**（給模型看的是 `_tooldef`，P-41）。用意是使用者 10-24「一個函數是用_entry去跑。其特性我想要將其寫到_metainfo，裏面可以存放該函數要跑多久，要喫多少資源這種東西。相關的.json格式也要規劃。然後kernel也可以透過這個，來做參考」，規劃後「我現在沒空管這些小事，都按建議做」（kernel 讀不讀，現行見同條「誰讀」）。它是節點描述自己的一個子節點，可以放任何東西來描述自己；index 是其中一種、所以也能放進去，`_metainfo` 本身不算 index（使用者 11-12 晚「_metainfo不算index，_metainfo他是描述自身節點的一個子節點，可以塞任何東西來描述自身，因爲index也是一種描述自身的東西，所以也可以塞入其中。」，[metainfo-views](../../../thinking/2026-11/12/metainfo-views.md)）。
  - **放哪**：同一個名字、兩種寫法。資料夾裡跟 `_entry` 並列的檔 `_metainfo.json`（不帶 `.json` 的不認）；JSON 定義裡的 `_metainfo` key——JSON 檔的頂層，或 `檔.json#/指標` 那個物件裡（單子裡也可以寫，地位同 `argv`）。
  - **怎麼找**：讀的人看它手上那個位置的那一處：資料夾看 `_metainfo.json`，JSON 檔或 `檔.json#/指標` 看那個物件的 `_metainfo` key（共用讀法 `lib/metainfo.py` 的 `read`；aos-tools 登記的工具 `ls --json`／`get` 一起帶出來）。不順著入口往下追：資料夾裡 `_entry` 單子的 `_metainfo` key 沒有人讀（函數長大時見 [C-55 續](../../CONCEPTS/01-設計理念/05-續-C-55-函數成長.md)）。可執行檔工具沒有這一處。
  - **內容**：沒有必填、不強迫寫（N-68）；通用 key 全選填，沒寫＝沒說，其餘自由（C-14），不認得的忽略（C-48）。現在用到的通用 key：`summary`（一句話）、`cost` 與 `timeout_ms`、`comfort`（三個見 N-68）、`resource`、`side_effect`、`idempotent`、`deterministic`、`interrupt`、`parallel`、`arbitrary_exec`、`sandbox`（[C-64](../../CONCEPTS/01-設計理念/05-布局成長與檔案權限.md#檔案權限10-16-使用者定)）。數量類照 C-48 的雙形。不加版本 key：只加 key，要改意思就換新名字（C-48）。
  - **誰讀、讀了做什麼**：aos-exec、inst 與指示詞都不讀（C-48、N-04、N-45 只解自己讀的格）。act 格與 aos-mcp 照 `timeout_ms` 殺工具（N-68）；aos-mcp 把 `side_effect`／`idempotent`／`resource` 換成 MCP 的提示；shell 帳（`shell_report`）看 `arbitrary_exec` 與有沒有 `sandbox`；審視工具 `metainfo_check` 讀 `cost`；定義樹的檢查（`defs`、`agent_def check`）要定義的 `_metainfo.json` 有 `summary`；`tools_def` 與 `lib/tool_spec.py` 產新工具時寫一份（沒給的補保守預設）。kernel 不讀（llm kernel 的信裡沒有單子）。
  - **全是觀點、參考用**（使用者 11-12 晚「當然，全都是觀點，全都是參考用，出事了自行負責。」）：每一格——`timeout_ms`、`sandbox`、`side_effect`、`cost` 也一樣——都是觀點，不是規則。定義旁那份是設計者公開給別人的聲稱（通用視角）；agent 私有的看法是主觀，放哪不規定（使用者「主觀的metainfo的位置也不規定。」），沒有程式會自己去找主觀那份。執行的程式（act、aos-mcp）拿定義旁那份當參考值照著用；它不是保證、不是安全邊界：寫錯、寫壞、被有權限的人改掉，後果自負；真要擋靠別層（Linux 權限與資源上限、起 proc 那層套的沙箱，C-64）。
    - **壞了＝當沒寫**：讀不了、不是物件，或某一格的值壞了，讀的人略過那一處、提醒一句、不擋（使用者 11-12 晚：「對，略過，出事自己負責」）。`lib/metainfo.py`（`read`、`timeout_ms`、`eval_cost`）遇到壞的回「沒有」、把略過了什麼交給呼叫者提醒。略過之後：act 不設上限（同沒寫 `timeout_ms`）；aos-mcp 用自己的預設逾時（60 秒或 `--timeout-s`）；`mcp_tool` 用預設 60000 毫秒；`metainfo_check` 當沒宣稱、在 `notes` 寫明。`sandbox` 也一樣（使用者 11-12 晚，甲＝也略過、不關沙箱照跑：「甲，出事自己負責」）：aos-sandbox 讀到壞的設定＝不套沙箱、直接跑，stderr 一行 `sandbox config ignored, running unsandboxed`；設定不在（檔不在、`#/` 指不到）與環境做不到（路徑不在、bwrap／s6 不在、不是 root）照它自己的錯報（代定、可翻案）。
  - **實測不回寫**：跑的時候誰都不改 `_metainfo`；量到的寫在量的人自己那邊（`observed.jsonl`，[N-68 續](10-續-N-68.md)）。
  - **`_metainfo` 也是口子**（tooldef／index 兩格、推薦讀法、支援的工具、不進的、模型看到的）：全文在 [11-續-N-69](11-續-N-69.md)。
