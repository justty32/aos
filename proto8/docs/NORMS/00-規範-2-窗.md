**[基礎設施／窗](05-基礎設施-窗.md)**
- （無條號）這一族（ctl、state、鎖、信箱、判死活）給反覆跑的東西（daemon、kernel）用；agent 這層沒有 ctl，停＝退 10 或送訊號，內部狀態就是 `$AOS_STACK` 裡的檔。

**[控制：ctl 與 state](05-基礎設施-窗/01-N-06～N-08.md)**（[N-09、N-11](05-基礎設施-窗/02-N-09～N-11.md)）
- **N-06** 控制一個會反覆跑的東西（loop、daemon）＝改它的 ctl.json；loop 這一系的 ctl＝一個 JSON 物件＝一道指令（`cmd`、`max`／`interval_ms`、`seq`）；跟上一次讀到的內容不一樣才算新指令，後寫的蓋前寫的；讀的人只讀不寫。daemon 管別人的 `procs_ctl.json` 是宣告的名單、不是指令。
- **N-07** `cmd` 認 `pause`、`resume`、`stop` 三個動詞（都冪等，`stop` 壓過同一道裡的其他東西），開了 ctl 窗的程式都認；`max`、`interval_ms` 寫了才動、`null` 回初始、沒寫不動，只有反覆跑的程式認；daemon 的 pause＝整圈暫停；要當場收掉正在跑的那次＝送訊號。
- **N-08** 讀 ctl 的人定期看；檔不見＝沒有新指令、維持原狀；讀到壞的或型別不對（含解不開的指示詞）＝整份不採用、維持上一次的好狀態、不退出，原因記進自己 state_flux 的 `ctl_warning`（讀到好的就清掉），不寫 stderr。
- **N-09** 要回報狀態寫到另一個檔（state），不碰 ctl；一個 state 檔只有被控制的那個東西自己寫；選填，沒給就不開、也不提醒（aos-loop／aos-daemon 的 `ctl`／`state` 沒寫＝`ctl.json`／`state.json`、`null`＝不開）；有變才寫，最後一欄 `updated_at`。
- **N-09** state 拆兩扇：`state.json`（穩定）＋`state_flux.json`（回音：`responded_at`、`ctl_seq`、`ctl_warning`…，一個程式一份），先寫 state 再寫 state_flux；只因時間或每跑一次就變、又沒人讀的欄改寫 `.txt` 計數器、放 `--enable-counters` 後面；主人（自己寫、起來時自己讀回的窗：aos-loop 與繼承它的 aos-daemon 的 `state`、`state_flux`）讀不了＝改名 `.bad-*` 留證、stderr 印 warning、當沒有，旁觀者（讀別人的窗）讀不了＝stderr 印 warning、當沒有。
- **N-11** 設定檔（loop.json／daemon.json／fsm.json）是命令列唯一的位置參數、起來時只讀一次；跑途中只能走 ctl，ctl 只能蓋節奏類 key（例外 `procs_ctl.json` 的名單 key）；aos-loop、aos-daemon 的命令列 `程式 [旗標...] 設定檔 [-- 參數...]`，旗標鏡射 key（旗標 ＞ 設定檔 ＞ 預設），`--enable-logs` 給了才把 log 印到 stdout（其他程式不跟著改）；新程式盡量不收旗標、不從 stdin 讀設定。

**[內部狀態的外顯與窗的族譜](05-基礎設施-窗/03-N-13～N-14.md)**（[N-15](05-基礎設施-窗/04-N-15.md)、[N-16](05-基礎設施-窗/05-N-16.md)、[N-17](05-基礎設施-窗/06-N-17.md)、[細則 N-32、N-33](05-基礎設施-窗/07-細則.md)）
- **N-13** state／ctl＝程式內部狀態的外顯，跟 stdin／stdout／stderr 完全無關；落在 `$AOS_STACK` 底下，名字由程式自訂、窗的內容照 N-14 是 JSON（新舊打架，N-14 10-29 較晚；fsm 的 `stage.txt` 是 state 檔、不算窗）；需要 stack 的程式沒設 `AOS_STACK` 就退 1；控制自身的一組慣用名 `ctl.json`／`state.json`／`state_flux.json`，管別人的叫 `<被管的東西>_ctl`／`_state`。
- **N-14** 窗＝只看最新那份的固定檔（state、state_flux、ctl、公告）；鎖、信箱不算窗；強制落在 `$AOS_STACK` 的只有窗；內容是 JSON、原子性只靠 rename、判變化比內容或序號不比 stat、回音以 `seq` 為準；窗不自述種類（不帶 `kind`）。
- **N-15** 鎖是一個資料夾，`mkdir` 成功的人拿到（`<資料夾>/.lock/`、`<檔>.lock/`），裡面寫名牌 `holder.json`；只有一種獨佔鎖；flock 判持鎖人還在不在、選填租約 `lease_cycles` 照兩鐘到期，主人死了或過期就替它收；放鎖先改名再刪；是約定、不必擋得住。
- **N-16** 信箱＝資料夾式（`tmp/`、`new/`、`cur/`，`archive/` 選用），位置由擁有者定；一封信＝一個資料夾，必有 `letter.json`（`sender`、`sent_at`、`body`；選填 `reply_to`、`in_reply_to`）；寄＝在 `tmp/` 寫好再 rename 進 `new/`，認領＝rename 進 `cur/`；信封壞＝丟掉、記 `mailbox_warning`；有序投遞靠 `order.lock/`＋`order.json` 取號，有序的排在無序的前面；agent 層的輸入叫 queue。
- **N-17** 判死活不設心跳、不從檔案的更新時間判：只有 daemon 自己照 pid＋`started_at_ticks`＋`boot_id` 對 `/proc`；其他人不碰 pid（例外 poke、清道夫，都不拿它替別人判死活），讀上一層的 `procs_state.json` 或寄信問、時限內沒回＝這次呼叫失敗；狀態只有一個 key `phase`、一套值；`stuck`＝新的 ctl 沒被採用，只在父 daemon 的表上標。
- **N-32** state 帶 `started_at_ticks`、`boot_id`（非 Linux 是 null），最後一欄 `updated_at`；沒有心跳、沒有 `recorded_at`；`responded_at` 只在 state_flux、有反應才改，身體跑完一次不更新；`interval_ms`＝上一次結束到下一次開始至少隔幾毫秒。
- **N-33** ctl 的 `seq` 由寫的人自己帶（選填非負整數），state_flux 的 `ctl_seq` 回報最後一份採用的 ctl 的 `seq`；daemon 的 `procs_ctl.json` 同樣回音到 `procs_ctl_seq`。

**[非同步呼叫](05-基礎設施-窗/08-N-66.md)**
- **N-66** 非同步呼叫建在 N-16 的信封與投遞之上，aos-post 只收發信、不管 body；一箱一函數，body＝那函數的 stdin JSON；成功的回信 body＝函數 stdout 原樣，失敗＝頂層 `error`（`code`、`msg`），body 不合且有 `reply_to` 就回錯誤信；進度先不另定，要看就讀信資料夾裡的窗；等不到回信＝這次呼叫失敗，時限由寄信者自己設（選 `--on-queued ok` 時，判官的 `queue.json` 證明還在排也算成功）。
