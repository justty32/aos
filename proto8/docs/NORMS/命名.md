**命名**（規則在 [C-54 命名方法](../CONCEPTS/01-設計理念/C-54-命名方法.md)；只換名字、不改原意，不留舊名；舊名在歷史敘述裡照留。**舊名 → 現名**一張表在[附錄3 舊名對照](附錄3-舊名對照.md)）：

- **10-23 命名統合**（[thinking 2026-10-23-naming](../../thinking/2026-10/23/naming.md)，使用者「都先幫我統合。統合好後更新文件和artifact，我等一下重看」）：純文字檔帶 `.txt`、指示詞的位置只認 `#/`、錯誤代號照 C-54 的寫法；N-17「兩套撞名不改名」與 C-54「代號照舊沿用」不再成立。
- **要跑什麼＝`exec`**（「beats 改 runs」原話見 [naming-method 02](../../thinking/2026-10/23/naming-method/02-照規則改的名字.md)；11-10 prefix-fixes 坑-57：出處核對。10-23 晚使用者：「改，beats改runs，然後val寫要跑啥，通常不會用val，應該用run。」，衝突時選「只有 loop、daemon 用 run」；10-23 深夜：「fsm.json，現在是用val，幫我改成exec」，問到 loop／daemon 時：「exec，loop／daemon 的 run 也一起改 exec」）：「要跑什麼」那一格全體系一律叫 `exec`——fsm 格、loop／daemon（含子項、小格 loop.json）；`val` 只留給 C-55 的雙形；條文說「次」不說「拍」。
- **10-23 晚入口改名**（[thinking 2026-10-23-naming](../../thinking/2026-10/23/naming.md)，使用者「改。然後_開頭=附註這個概念刪掉。」「不認得的key就是忽略」）：入口預設名是 `_entry`（`AOS_ENTRY` 預設值、入口檔、JSON 的 key；使用者原話裡的 `_exec` 照留）；不認得的 key 一律忽略（C-48），`_` 開頭沒有特別意思。
- **計數一律 `counter_*`**（使用者 10-25「計數這塊，幫我改成counter_*」）：計數一律 `counter_<被數的東西>`（[C-54 命名方法 R6](../CONCEPTS/01-設計理念/C-54-命名方法.md)；規範層 N-17、N-32）。
- **時間點一律 `<發生了什麼>_at`、上限一律 `max_*`**（使用者 10-25 已選 `recorded_at`，頂層問兩題（時間點規則要不要跟著改、上限要不要照 R6 改 `max_*`），使用者回「都好」；頂層代定（可翻案））：時間點＝`<發生了什麼>_at`，沒有單獨的 `at`；上限一律 `max_*`（[C-54 命名方法 R3、R6](../CONCEPTS/01-設計理念/C-54-命名方法.md)）。
- **控制自身的窗叫 ctl／state，管子項的叫 `procs_*`**（[thinking 2026-11-02-ctl-state-names](../../thinking/2026-11/02/ctl-state-names/README.md)，使用者「控制自身的 ctl/state 檔案，那就是 ctl/state，不加前綴」，方向題 2「好。」、3「對。」；[thinking 2026-11-03-procs](../../thinking/2026-11/03/procs/README.md)）：loop 這一系控制自身的窗統一 `ctl.json`／`state.json`（aos-daemon 自己也是；N-13、N-28）；daemon 管子項的窗叫 `procs_ctl`／`procs_state`、信箱 `procs_ctl_mailbox`，子項統稱 proc（N-28、N-54）；名詞表（動作 add／rm／start／stop／pause／resume）見 [procs § 0](../../thinking/2026-11/03/procs/03-規劃-fable-照原則定的細節-可翻案.md#0-名詞表代定)。
