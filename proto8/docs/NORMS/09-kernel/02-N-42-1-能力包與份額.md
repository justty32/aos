# kernel 規範：N-42 (1) 11-05 午加

接 [01](01-N-42-1-LLM-kernel.md) 的 (1) LLM kernel 各項之後。

- **N-42** (1) 續：
    - **11-05 午加**（使用者 11-05 午「把endpoint打包成smart-high, stupid-fast, ...這類，並且附上各種屬性(各種temperature也固定)，讓kernel能根據信件中額外附送的priority之類資訊做排程」「啊，還有，會想要限制特定aos proc所占用的資源。以及daemon/kernel自己本身被限制占用資源，並且會分配份額給proc」；細節 fable 照原則代定、可翻案，[thinking 11-05 feat-proto 02、03、05](../../../thinking/2026-11/05/feat-proto/README.md)、[實作結果](../../../thinking/2026-11/05/feat-proto/06-實作結果.md)）：`endpoints` 的一組＝**能力包**（代號就是能力名，例 `smart-high`、`stupid-fast`）：kernel 自己看 `exec`、`slots`（這包同時幾封在飛）、`budget`（這包每窗的 `max_calls`／`max_tokens`，窗與 `spent` 同 kernel 的）、`speed`（`fast`／`normal`／`slow`），拿掉後其餘原樣交給 endpoint 函數；上面那組的 `body`（預設、信可蓋）改名 **`fixed`（釘死）**——信的 `request` 寫了 `fixed` 裡的 key、或那包有 `model` 而信寫了 `model`＝`RequestBad`（換參數、換模型＝換代號）。包的屬性表（`speed`、`cost`、`context`、`slots`、`summary`）每拍寫成窗 `$AOS_STACK/endpoints.json`，`aos-llm ls` 印它。上面「一次挑最該跑的」的順序改成**級數＋aging → 時限 → 包的 `speed`（fast 先）→ 等得久 → 先寄**；補位時那封的包在飛數到了它的 `slots`＝跳過、看下一封（kernel 總 `slots` 到了才停）；包的 `budget` 到頂＝那封 `BudgetMissing`，不替人降級換包（`spent: wait` 時那封留著、別包照跑）。`budget` 多一格**每個寄件人的額度** `senders: {信封 sender: {max_calls, max_tokens}}`（key 相對的從 kernel.json 所在算；沒列的不限；寄件人不驗，10-15「先信任」）；判序 kernel → 包 → 寄件人；`used.json` 多 `packs`、`senders`，`proc.json` 記代號與寄件人。實作：[aos-llm-kernel](../../../impls/aos-llm-kernel/README.md)、`aos-llm ls`、範本與劇本 [demo/docs/05](../../../demo/docs/05-feat-proto.md)。
