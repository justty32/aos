# kernel 規範：N-42 (1) 能力包與份額

接 [01](01-N-42-1-LLM-kernel.md) 的 (1) LLM kernel 各項之後。

- **N-42** (1) 續：
    - **能力包、排程、每寄件人額度**（使用者 11-05 午「把endpoint打包成smart-high, stupid-fast, ...這類，並且附上各種屬性(各種temperature也固定)，讓kernel能根據信件中額外附送的priority之類資訊做排程」「啊，還有，會想要限制特定aos proc所占用的資源。以及daemon/kernel自己本身被限制占用資源，並且會分配份額給proc」；細節 fable 照原則代定、可翻案，[thinking 11-05 feat-proto 02、03、05](../../../thinking/2026-11/05/feat-proto/README.md)、[實作結果](../../../thinking/2026-11/05/feat-proto/06-實作結果.md)）：`endpoints` 的一組＝**能力包**（代號就是能力名，例 `smart-high`、`stupid-fast`）：kernel 自己看 `exec`、`slots`（這包同時幾封在飛）、`budget`（這包每窗的 `max_calls`／`max_tokens`，窗與 `spent` 同 kernel 的）、`speed`（`fast`／`normal`／`slow`）、`backend`（見下），拿掉後其餘原樣交給 endpoint 函數；那組的 **`fixed`（釘死）**——信的 `request` 寫了 `fixed` 裡的 key、或那包有 `model` 而信寫了 `model`＝`RequestBad`（換參數、換模型＝換代號）。包的屬性表（`speed`、`cost`、`context`、`slots`、`summary`）每拍寫成窗 `$AOS_STACK/endpoints.json`，`aos-llm ls` 印它。補位時那封的包在飛數到了它的 `slots`＝跳過、看下一封（kernel 總 `slots` 到了才停）；包的 `budget` 到頂＝那封 `BudgetMissing`，不替人降級換包（`spent: wait` 時那封留著、別包照跑）。`budget` 多一格**每個寄件人的額度** `senders: {信封 sender: {max_calls, max_tokens}}`（key 寫相對的從 kernel.json 所在算；記帳時 `used.json` 的 `senders` 與 `budget.senders` 兩邊的 key 都是寄件人相對 kernel stack 的路徑，搬家跟著走，使用者 11-05 夜「剩下都照推薦」，[portable-flow 07](../../../thinking/2026-11/05/portable-flow/07-listen-paused-bug.md)；沒列的不限；寄件人不驗，10-15「先信任」）；判序 kernel → 包 → 寄件人；`used.json` 多 `packs`、`senders`，`proc.json` 記代號與寄件人。實作：[aos-llm-kernel](../../../impls/aos-llm-kernel/README.md)、`aos-llm ls`、範本與劇本 [kernel/docs/03](../../../kernel/docs/03-feat-proto.md)。
      - **已裁、不算代定的兩項**：撞 `fixed` 或包已指定的 `model` 回 `RequestBad`，以及包的額度到頂回 `BudgetMissing`、不替人降級，是使用者 11-05 裁的（選項原文「回 RequestBad (Recommended)」「不降級，回 BudgetMissing (Recommended)」，[feat-proto 已定六題](../../../thinking/2026-11/05/feat-proto/README.md)）。
    - **kernel 嵌套**（使用者 11-07 傍晚 kn-2～kn-6 選★，[kernel-nest](../../../thinking/2026-11/07/kernel-nest/README.md)，實作 [impl-plan 批 7、8](../../../thinking/2026-11/07/impl-plan/README.md)）：
      - **endpoint 函數契約**：stdin 多頂層 `priority`＝`{"level": 信宣告的級數（沒寫＝normal；aging 升的不寫）, "deadline"?: epoch 秒＝min(信的期限, 本層掛上時刻＋timeout_ms)}`，兩者都沒有就不放 `deadline`；重掛沿用第一次的。stdout 成功形多一個選填 `child`＝`{"kernel", "letter"}`（下一本帳在哪），kernel 記進本層 ledger、回信拿掉（上層只知一層）。退非 0 而 stdout 整份是一行合格錯誤物件 `{"error": {"code": 字串, "msg": 字串}}`＝**原樣當回信**（透明轉交，見 C-52 例外表 ③ 註）；否則 `EndpointFailed`＋第一行。退 0 而 stdout 是錯誤物件＝`ReplyBad`。
      - **包的 `backend`**、`kernel.json` 頂層選填 `backends: {名: {slots, max_packs?}}`：同 backend 的包在飛總數 ≤ 那格 `slots`，在飛的不同包數 ≤ `max_packs`（擋住的信跳過、看下一封）。LM Studio 一次一模型＝`{"slots": 1, "max_packs": 1}`。`queue.json` 記各 backend 目前載著哪包；換包後第一封的 ledger 行 `switched: true`（沒記錄時第一封也算）。
      - **排序**（一次挑最該跑的）：級數＋aging → 時限 → **同 backend 上跟目前載著的包相同的先（黏著，只在同級同期限時起作用）** → 包的 `speed` → 等得久 → 先寄。推得的期限讓轉交來的信同級時排在沒寫期限的信前面，接受（上層真的只等這麼久）。
      - **ledger**（逐封帳：每層 kernel 在自己 stack 追加 `ledger.jsonl`，[aos-llm-kernel docs 02](../../../impls/aos-llm-kernel/docs/02-token-回報與額度.md)；使用者 11-07 裁定「留，明寫是翻案（推薦）」；定義夾 `interfaces.json` 以 `aos-ledger` 宣告）每行有 `seen_at`、`code`（成功 null、失敗＝回給寄件人的代號）、`child`、`switched`。同一筆 usage 在每層各記一次，**加總只加一層**（要全鏈只加葉子行，`child` 為 null 的）；讀的人跳過壞行、用 `id` 去重；kernel 不輪替，人或審視者清。
      - **往下一層寫在包裡**：轉交函數 [`lib/aos/llm_forward`](../../../lib/README.md) 從包讀 `to`、`kernel`，只對自己的子行程設 `AOS_LLM_KERNEL`；hub 整棵樹仍一個值（P-39 註）。下層看寄件人＝一隊一格（kn-4 使用者裁 A）。
      - **部署規則**：指向同一台 LM Studio 的包只放在一台 kernel（兩台都放＝互斥失效，自擔）；kernel 只知道自己最後掛的是哪包，人手換模型或剛重起時 `switched` 可能記錯（[已知限制](../../../impls/aos-llm-kernel/docs/04-已知限制.md)）。
