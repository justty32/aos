# 基礎設施／inst

> **argv[0] 帶 `/` 又 exec 不了＝前面插 `aos-exec`**（10-20 使用者，見 [ideas](../../thinking/2026-10-20-ideas.md) D3～D5；規則在 [N-61](10-基礎設施-定義與工作區.md)）：單子的 `argv[0]` 是資料夾、沒 `+x` 的檔、不在、或帶 `#/` 時，inst 改跑 `aos-exec argv...`，`aos-exec` 照 PATH 找（「分層衝突沒關係，就是要inst依賴PATH中的aos-exec」）；`+x` 的檔直接跑、沒 `/` 照 PATH 找。loop／fsm 內嵌的單子也經 inst，一樣。這段放在 aos-exec 的 `run_inst`（C 的 inst 庫不知道 aos-exec）。

- **N-04** inst 單子裡可以多放東西，inst 不認的別人可以讀（aos-exec 的 `run_inst` 只驗 10 個 key，其他 key 忽略）。（3g.13b）
- **N-25**（D-4，草稿；10-19 改）程式內呼叫：`aos_inst.run(x)` 收路徑或一份單子（dict），回 `{"code","signal","timed_out","pid","elapsed_ms"}`〔現在對應的是 impls aos-exec 的 `run_inst`（`run_inst(單子, 基準資料夾, args, ref_base)`，回 `Result`：`code`、`signal`、`timed_out`、`pid`、`ms`、`received`；C++ 欄位名是 `ms`、不是 `elapsed_ms`，`received`＝跑的期間轉給子程式的第一個訊號；單子壞、指示詞壞、起不來是丟錯（`EntryBad`、`DirectiveBad`、`LaunchFailed`），見 [impls/aos-exec](../../impls/aos-exec/README.md)）〕。呼叫者：aos-exec，與 aos-loop、aos-fsm、aos-daemon——loop 的 `exec`、fsm 格的 `exec` 是字串＝aos-exec 的目標，內嵌單子可以寫 `檔#/…/body`、由 aos-exec 行程內跑（[計畫 10-21](../../thinking/2026-10-21-plan.md) L3、F2）；`exec` 是單子物件時在自己行程內呼叫 `run_inst(單子, 設定檔的資料夾, {}, exec 那格來自的檔的資料夾)`，跑的期間 `AOS_CF`／`AOS_CD`／`AOS_CO` 設成單子的位置（使用者 10-24「不過exec本來就應該要可以直接放內嵌單子吧」「好，就這樣做」，[thinking 10-24](../../thinking/2026-10-24-exec-relative/01-使用者原文.md#10-24-exec-直接放單子)）。`ref_base`＝單子裡 `$ref` 的起點（寫著單子的檔所在的資料夾；給路徑時自動取）（N-45；10-20 使用者，見 [ideas](../../thinking/2026-10-20-ideas.md) D1）。（10-14）loop／daemon「可以隨意使用指示詞,json schema，還有aos-exec的公開api」（使用者 10-19 晚，[ideas § 20](../../thinking/2026-10-19-ideas.md)）。
- **N-27**（D-6，草稿；10-19 改，[CONVENTION P-26](../CONVENTION.md)）子程式的參數：aos-exec 把多的 args 與 stdin 原樣送到入口，怎麼進（args、stdin、或 stack 裡的檔）由工具自己的說明定；單子裡 `stdin: "params.json"` 照舊可以把一個檔交給子程式當 stdin，不加新 key。（10-14；10-16 起 agent 的工具見 [N-50](10-基礎設施-定義與工作區.md)）
- **N-30**（原 h4、h5，草稿；10-19 改）aos-inst 的結果 `{"code","signal","timed_out","pid","elapsed_ms"}` 回給行程內的呼叫者〔現在是 impls aos-exec 的 `run_inst`，回的欄位見 N-25 與 [impls/aos-exec](../../impls/aos-exec/README.md)〕（aos-exec 只拿 `code` 當自己的結束碼；fsm 的 `trace.jsonl` 沒有 `timed_out`，N-39）：`code`＝子程式的碼（照實轉交的資料，不是 aos-inst 的退出碼；被訊號停掉時是 128＋N，N-43）、訊號號碼另放 `signal`、被逾時殺掉的 `timed_out: true`。命令列上 aos-inst 的結束碼＝子程式的碼（透明轉交，N-43 例外），不另吐結果 JSON；aos-inst 自己出錯一律退 1、stderr 一行 `aos-inst: 原因`（這句現無實作：沒有 aos-inst 命令列）。inst 自己不開窗（沒有 state／ctl）。（10-14 深夜；10-19 改，P-21、P-30）單子當入口時由 aos-exec 行程內跑、aos-exec 以子程式的碼結束（同樣是透明轉交，N-59 第 5 件）；單子壞＝aos-exec 自己的錯退 1（§ 20）、stderr 一行 `aos-exec: 代號 單子跑不起來：原因`。
