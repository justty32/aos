# 基礎設施／inst

> **argv[0] 帶 `/` 又 exec 不了＝前面插 `aos-exec`**（10-20 使用者，見 [ideas](../../thinking/2026-10/20/ideas.md) D3～D5；規則在 [N-61](10-基礎設施-定義與工作區/05-N-61～N-62.md)）：單子的 `argv[0]` 是資料夾、沒 `+x` 的檔、`+x` 但是 JSON 的檔（N-61 種類看內容）、不在、或帶 `#/` 時，inst 改跑 `aos-exec argv...`，`aos-exec` 照 PATH 找（「分層衝突沒關係，就是要inst依賴PATH中的aos-exec」）；`+x` 的檔直接跑、沒 `/` 照 PATH 找。loop／fsm 內嵌的單子也經 inst，一樣。這段放在 aos-exec 的 `run_inst`（C 的 inst 庫不知道 aos-exec）。

- **N-04** inst 單子裡可以多放東西，inst 不認的別人可以讀：aos-exec 的 `run_inst` 認 17 個 key（`id` 是標籤、收下不驗；含 `id`、`envs_clear`、`cwd_mkdir`、`stdout_mkdir`、`stderr_mkdir`、`stderr_merge`、`timeout_cycles`，使用者 11-04 題 9「aos-exec 補認那 7 個」，[four-elements 06](../../thinking/2026-11/04/four-elements/06-要使用者裁的題.md)），其他 key 忽略。（3g.13b）aos-exec 認的 key 表（[impls/aos-exec 03](../../impls/aos-exec/docs/03-環境變數.md)）＝完整實作的欄位；`envs_clear` 清掉之後 aos-exec 的六個 `AOS_*` 照設（N-57 不受影響）。
- **N-25**（D-4，草稿）程式內呼叫：aos-exec 公開 API 的 `run_inst(單子, 基準資料夾, args, ref_base)`，回 `Result`：`code`、`signal`、`timed_out`、`pid`、`ms`、`received`（`received`＝跑的期間轉給子程式的第一個訊號）；單子壞、指示詞壞、起不來是丟錯（`EntryBad`、`DirectiveBad`、`LaunchFailed`），見 [impls/aos-exec](../../impls/aos-exec/README.md)。呼叫者：aos-exec，與 aos-loop、aos-fsm、aos-daemon——loop 的 `exec`、fsm 格的 `exec` 是字串＝aos-exec 的目標，內嵌單子可以寫 `檔#/…/body`、由 aos-exec 行程內跑（[計畫 10-21](../../thinking/2026-10/21/plan/README.md) L3、F2）；`exec` 是單子物件時在自己行程內呼叫 `run_inst(單子, 設定檔的資料夾, {}, exec 那格來自的檔的資料夾)`，跑的期間 `AOS_CF`／`AOS_CD`／`AOS_CO` 設成單子的位置（使用者 10-24「不過exec本來就應該要可以直接放內嵌單子吧」「好，就這樣做」，[thinking 10-24](../../thinking/2026-10/24/exec-relative/01-使用者原文.md#10-24-exec-直接放單子)）。`ref_base`＝單子裡 `$ref` 的起點（寫著單子的檔所在的資料夾）（N-45；10-20 使用者，見 [ideas](../../thinking/2026-10/20/ideas.md) D1）。loop／daemon「可以隨意使用指示詞,json schema，還有aos-exec的公開api」（使用者 10-19 晚，[ideas § 20](../../thinking/2026-10/19/ideas/README.md)）。
- **N-27**（D-6，草稿；[CONVENTION P-26](../CONVENTION.md)）子程式的參數：aos-exec 把多的 args 與 stdin 原樣送到入口，怎麼進（args、stdin、或 stack 裡的檔）由工具自己的說明定；單子裡 `stdin: "params.json"` 可以把一個檔交給子程式當 stdin，不加新 key。（agent 的工具見 [N-50](10-基礎設施-定義與工作區/06-N-50～N-53.md)）
- **N-30**（原 h4、h5，草稿）單子的結果回給行程內的呼叫者（aos-exec 的 `run_inst`，欄位見 N-25）：`code`＝子程式的碼（照實轉交的資料；被訊號停掉時是 128＋N，N-43）、訊號號碼另放 `signal`、被逾時殺掉的 `timed_out: true`；aos-exec 只拿 `code` 當自己的結束碼。inst 自己不開窗（沒有 state／ctl）（P-21、P-30）。單子當入口時由 aos-exec 行程內跑、aos-exec 以子程式的碼結束（透明轉交，N-43 例外，N-59 第 5 件）；單子壞＝aos-exec 自己的錯退 1（§ 20）、stderr 一行 `aos-exec: error: 代號 inst cannot run: 原因`。
