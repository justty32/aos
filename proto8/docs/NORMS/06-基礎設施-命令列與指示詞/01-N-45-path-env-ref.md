# N-45（續）：`$path`、`$prefix`、`$env`、`$ref`

- **`$path`、`$prefix`**（10-20 使用者：「我希望那個path可以換成$path，然後添加$prefix」「兩種都能用。如果換出來的不是字串，那也不報錯，就靜默失效。」，[ideas](../../../thinking/2026-10/20/ideas.md) D9～D11）：換出來的值是字串時，先照 `$path` 接上去，再在前面加 `$prefix`。**`$path` 是字串拼接**（10-21 傍晚使用者選「a」：留 `$path`、`#` 開頭直接接、其他中間補剛好一個 `/`，[ideas 10-21 § 9](../../../thinking/2026-10/21/ideas/05-7-審後的五個細縫與修正.md#9-設定檔是唯一的位置參數path-改字串拼接10-21-傍晚) H6）：`$path` 以 `#` 開頭＝直接接在後面；其他＝去掉基底結尾的 `/`、去掉 `$path` 開頭的 `/`，中間剛好一個 `/`（**寫絕對路徑也是接上去、不整個取代**）；`$path` 是空字串、不帶或 `null`＝不接；基底是空字串或 `/`＝接成 `/a`（頂層自定，ideas 10-21 § 9.3 第 8 點）。`$path: "#/…"` 只是「拼出指標字串」，不取那份檔裡的內容。`$env`、`$ref` 都能帶；換出來不是字串，兩欄靜默不作用、值原樣換進來。不帶 `$` 的 `path` 是普通 key，照「其餘 key 不管」。`$fmt` 使用者「先等等，fmt先不動」，未定。
- **`$env`**：`{"$env": 名, "$path": 子路徑}` 換成該環境變數底下的路徑（照 `$path` 的字串拼接；不帶 `$path`（或 `null`）就是整個變數值；`$path` 不是字串＝當沒寫）。`$env` 讀的是**執行當下的環境**，像 shell 的 `$HOME`——同一份單子在不同環境下指到不同地方，所以可以當正式機制。變數沒設＝解單子那一層自己的錯，退 1。`$env` 在 aos-exec 設好六個環境變數之後才解，所以單子裡讀得到 `AOS_STACK`、`AOS_CF`、`AOS_CD`（N-57）。
- **`$ref`**（語意照 impls 的 aos-directive 庫，`proto8/cpp/aos-directive/README.md`；impls 是使用者的檔）：`{"$ref": "檔"}` 換成**那份 JSON 檔的整份內容**，換進來的值**接著解**（裡面的 `$ref`／`$env` 也解）。
  - **相對檔名**（可以寫 `./`、`../`）從**寫著這個 `$ref` 的那份檔所在的資料夾**算：單子本身是入口時＝入口檔所在的資料夾（`AOS_CD`）；被 `$ref` 進來的檔若是捷徑，解開捷徑、從它實際指向的檔所在的資料夾算（使用者 10-17 定）；loop／fsm 設定裡內嵌的單子＝那份設定檔所在的資料夾。
  - **取檔內的位置**：接在檔名後面寫 `#/指標`（[ideas](../../../thinking/2026-10/20/ideas.md) D1、D7），換成那份檔裡那個位置的值。指標取的是那份檔的原文（不穿過檔裡的 `$ref`），取到的值再接著解。**只寫 `#/…`（沒檔名）＝寫著這個 `$ref` 的那份檔自己**（11-12 使用者：「話說ref應該支援#/開頭吧」）；「那份檔」跟相對檔名的起點是同一份——被 `$ref` 換進來的檔裡寫的 `#/x` 指那份被換進來的檔，入口檔、設定檔、ctl 裡寫的指它自己（用 `檔#/指標` 指到的設定或單子也從那份檔的根算）；取原文、接著解、繞圈、指不到同 `檔#/位置`。不知道寫著它的是哪份檔（stdin、信、行程內給的 JSON）＝`#/…` 原封不動留著（見入口「寫法寬容」）。
  - **`#` 左邊一律檔案系統、右邊一律 json 內部**（11-13 晚使用者：「#作爲json內部尋址的標示」「$ref和index路徑的規則要相同」，[ref-path-rules](../../../thinking/2026-11/13/ref-path-rules.md)；`$ref` 與 index 路徑同一套規則、同一支解析器）：左邊是檔案系統路徑（`x.json`、`./`、`../`、絕對路徑；不帶 `#` 就是整份）；右邊：`#/a/b`＝本檔根起算（RFC 6901，`..` 不特別、是 key 名）、`#./b`＝所在物件起算、`#../c`＝所在物件上一層起算（可連用，超出根報錯）、`#` 與 `#/`＝整份；帶檔名的 `y.json#/k`、`y.json#`、`y.json#/` 可（`y.json` 的 `/k`、整份、整份）。**所在物件**＝這個 `$ref` 物件整個所佔的那一格的上一層（`$ref` 陣列裡的元素同；整份檔就是一個指示詞時沒有所在物件，`#./`、`#../` 報錯）。`#aaa`、`y.json#aaa`、`y.json#./b`、`y.json#../b` 寫法不合＝`DirectiveBad`。
  - **錯**：算出來是資料夾＝讀不到；`$ref` 指回正在解的鏈上的同一個位置（檔＋指標，繞圈）、檔讀不到（**指到資料夾也算讀不到**：不走進去找入口、不把資料夾組成物件；10-21 傍晚使用者「對了，$ref如果指向的是資料夾？」「那還是維持報錯吧」，[ideas 10-21 § 9](../../../thinking/2026-10/21/ideas/05-7-審後的五個細縫與修正.md#9-設定檔是唯一的位置參數path-改字串拼接10-21-傍晚) H8）、不是 JSON、指不到＝錯，解單子那一層自己的錯、退 1。物件有 `$ref` 就只看 `$ref`、`$path`、`$prefix`，其餘 key（含 `$env`、不帶 `$` 的 `path`、不認得的 `$xxx`）不管。
  - **`$ref` 是最底層的組裝**：先用 `$ref` 把整份組好，讀它的程式拿到的就是一整份、不分哪段是接進來的；所以接進來那段裡的一般路徑值（不是 `$ref` 的檔名）照讀它的程式的規則算，跟直接寫在那份檔裡一樣（使用者 11-11「喔不對，$ref是最底層機制，都是先用$ref弄好後，最後產出的那個檔，再拿去使用。最後產出的這個檔案就是不管$ref啥的了，就當作這是整份」，[two-machines 17](../../../thinking/2026-11/10/two-machines/17-B07到B10施工結果.md) 11-11 續記題 1）。

## 例子

- `$path`、`$prefix`：`{"$env": "AOS_WS", "$path": "a.txt", "$prefix": "--file="}` → `"--file=/ws/a.txt"`；`a.txt`、`/a.txt` 都是 `/ws/a.txt`；`{"$env": "AOS_CF", "$path": "#/loops/a"}` → `"/x/big.json#/loops/a"`（大 JSON 裡的設定指回自己那一格就這樣寫）。
- `$ref` 取位置：`{"$ref": "x.json#/a/b"}` 換成 `x.json` 裡 `/a/b` 那個值；`{"$ref": "#/defs/cmd"}` 換成這份檔裡 `/defs/cmd` 的值。
- `loop.json` 是 `{"defs": {"argv": ["echo", "hi"]}, "exec": {"argv": {"$ref": "#/defs/argv"}}}`，跑的是 `["echo", "hi"]`。
- 所在物件：`{"a": {"b": {"$ref": "#./x"}}}` 的 `#./x`＝`/a/x`。
- 最底層的組裝：接進 daemon.json 的 `procs` 列，相對路徑照舊從 daemon 的 cwd 算。
