# 設計理念／時空

- **N-01** 大家都要看時鐘：aos 內部互相約的時間看時鐘（使用者 11-05「推薦大家用tick回合數來算」，[fs-image 原話](../../thinking/2026-11/05/fs-image/README.md)）；對人（使用者體驗）、對外、對 Linux proc（daemon）用牆上時鐘。
  - 現行數 cycle 的期限：共用函數（aos-util `clock.hpp`、`lib/tool_io.py`、`py/aos_ws.py`）、llm kernel aging 數 cycle（[tick-time 04](../../thinking/2026-11/05/tick-time/04-T線實作結果.md)）；inst 單子選填 `timeout_cycles`（跟 `timeout_ms` 擇一，aos-exec 判）、agents `ask` 的 `timeout_cycles`（跟 `timeout_s` 擇一）、`aos-agent listen --timeout-cycles`、`daemon_ctl.ask()`／`ping()` 的 `timeout_cycles`；人打的指令（aos-daemon-ctl、aos-agent ctl 的 `--timeout-s`）用秒——對人用牆鐘（[tick-time 05](../../thinking/2026-11/05/tick-time/05-T5T6T8與試驗場.md)）。
  - **時鐘到點寄信、不跑任意 aos 函數**（使用者 11-10「時鐘這塊幫我改成寄信好了，不要用跑任意aos函數。」「指令是aos-clock-register嗎？」，[clock-letters](../../thinking/2026-11/10/clock-letters/README.md)）：時鐘檔旁一張登記表，每格寫「每幾個 cycle、寄到哪個信箱、寄什麼字」；時鐘走到的新數字除得盡的格各寄一封（對齊整數倍，不從登記那刻起算）。人用 `aos-clock-register` 登記。腦用 `clock_register` 登記；寫得到登記表就能改；寄不到、表壞＝一行提醒，時鐘照走、不被拖垮；沒有登記表＝不寄（代定、可翻案，[clock-letters 代定](../../thinking/2026-11/10/clock-letters/README.md#代定可翻案)）。登記的人走了由時鐘自己清（使用者「時鐘本身會每隔一定的cycle檢查自身。」）：每隔一段 cycle 把信箱資料夾已經不在的格拿掉（間隔與「不在」的判法代定、可翻案，[clock-letters 02](../../thinking/2026-11/10/clock-letters/02-自我檢查與-d.md)）。用法見 [cmd/aos-clock-register](../../cmd/aos-clock-register/README.md)。
- **N-02** 資料夾別亂弄。
- **N-03** 「格（cycle）與格之間可以安全打包」是大家要遵守的規範，不強制；打包由 kernel 做。例：kernel 在公告欄說「大家，咱們第 1021 回合準備關機下線，在那之前所有人把狀態保存到檔案，逾時不候」。
  - 現行的打包＝daemon sleep 的硬凍（使用者 11-06 裁「D1：先只有硬凍（推薦）」，[apply-ideas D1](../../thinking/2026-11/06/apply-ideas/03-方向題.md)）；例子裡 kernel 公告第 N 回合的軟凍現在沒有。

- **N-65 兩鐘規則**（已定；[tick-time 03 使用者裁定與 N1／N2](../../thinking/2026-11/05/tick-time/03-11-06-裁定與新設計.md)、[daemon-board 四題裁定](../../thinking/2026-11/06/daemon-board/README.md)）：
  ① **期限寫 cycle 時，有 `AOS_CLOCK` 就讀它指的時鐘檔、比 cycle；沒有就退牆上時鐘**，以 `cycles × AOS_CLOCK_INTERVAL` 換成毫秒。使用者稱原生 Linux 實際時間函數為「逃生口」；沒時鐘的樹沒有凍住時間的保證（[tick-time 03](../../thinking/2026-11/05/tick-time/03-11-06-裁定與新設計.md)）。
  ② **有 `AOS_CLOCK` 就只認時鐘，時鐘停了期限就不到，不因時鐘檔過舊自動退牆鐘、也不 warning**；看 daemon 表上跑鐘那列（範本叫 `_clock`，通常只在根）是不是 `running`——鐘列要寫 `stuck_after_ms` 才判得出鐘自己卡住（被 SIGSTOP、卡 I/O 時時鐘不走，用 cycle 的期限永遠不到）（使用者裁「照用鐘，只有鐘那列用牆鐘」，[thinking clock-decouple](../../thinking/2026-11/09/clock-decouple/README.md)）——或讀鐘檔本身（`cat "$AOS_CLOCK"`；daemon 表頂層沒有時鐘觀察值（使用者裁「都照推薦」），[thinking clock-and-hot-writes 03 題 3](../../thinking/2026-11/09/clock-and-hot-writes/03-衝突與方向題.md)）。使用者 11-06「那兩題都按照推薦。」裁定 N2（[tick-time 03](../../thinking/2026-11/05/tick-time/03-11-06-裁定與新設計.md)）。
  ③ **跨樹的信裡期限用毫秒**，使用者原話「信裡用毫秒」；kernel 內部計時才用自己樹的鐘（[daemon-board 題 1](../../thinking/2026-11/06/daemon-board/README.md)）。這裡的「毫秒」指跨樹用牆鐘的語意、不數 cycle；格式不限，既有的 ISO 8601／秒數格式照舊，不要求改成 epoch 毫秒整數（同 N-67（[10-基礎設施-定義與工作區/09-N-67.md](10-基礎設施-定義與工作區/09-N-67.md)） ②；使用者裁定，出處 [wf/workflows/refactor/reports/2026-11-07-sol審查/11-使用者裁定.md](../../../wf/workflows/refactor/reports/2026-11-07-sol審查/11-使用者裁定.md) #11）。
     **判官排隊期限用牆鐘**：判官排隊的期限（信 body 的 `queue_wait_ms`）從信封 `sent_at` 起按牆鐘算，不數 cycle。凍住期間牆鐘照走，所以醒來第一輪，已經過期的排隊信會一起被拒；要跨過凍住繼續排，就用 `--on-queued ok`（不帶期限，見 N-66（[05-基礎設施-窗/08-N-66.md](05-基礎設施-窗/08-N-66.md)））。這是 N-01「aos 內部互相約的時間看時鐘」的例外，使用者知道後果後選了維持（使用者裁定，出處同上 #6）。
  ④ **`AOS_CLOCK_INTERVAL` 是標稱頻率的默契，只會慢，先不補成固定週期**；使用者原話「先不補」（[daemon-board 題 4](../../thinking/2026-11/06/daemon-board/README.md)）。沒設先用 1000 毫秒，**暫定：使用者說可再想**，原話「AOS_TICK_INTERVAL用一秒？我覺得這個可以再想想...不過現在就先用一秒吧。」（[tick-time 03](../../thinking/2026-11/05/tick-time/03-11-06-裁定與新設計.md)）。

**時鐘停住時，判卡住、鎖租約與以 cycle 計的逾時一起停、永不到期；要它們繼續走，就讓時鐘 resume。**（使用者裁定 sol 審查 #12）例外：寫了 `stuck_after_ms` 的列判卡住用牆鐘、不隨時鐘停；範本只給跑鐘那列寫（[thinking clock-decouple](../../thinking/2026-11/09/clock-decouple/README.md)）。
