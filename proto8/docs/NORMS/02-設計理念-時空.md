- **N-01** 大家都要看 tick-tock 時鐘。（10-12）
  - **11-06 註／改讀**：使用者 11-05「推薦大家用tick回合數來算」；aos 內部互相約的時間看時鐘，對人（使用者體驗）、對外、對 Linux proc（daemon）用牆上時鐘。已定（11-05，[fs-image 原話](../../thinking/2026-11/05/fs-image/README.md)）；內部期限改用時鐘的實作排在 T1～T6。**11-06 註（實作）**：T1 共用函數（aos-util `clock.hpp`、`lib/tool_io.py`、`py/aos_ws.py`）與 T4（llm kernel aging 數 cycle）已實作（[tick-time 04](../../thinking/2026-11/05/tick-time/04-T線實作結果.md)）。**11-06 晚註（實作）**：T5 inst 單子選填 `timeout_cycles`（跟 `timeout_ms` 擇一，aos-exec 判）已實作（[tick-time 05](../../thinking/2026-11/05/tick-time/05-T5T6T8與試驗場.md)）。T6 thought／agents `ask` 的 `timeout_cycles`（跟 `timeout_s` 擇一）、`aos-agent listen --timeout-cycles`、`daemon_ctl.ask()`／`ping()` 的 `timeout_cycles` 已實作；人打的指令（aos-daemon-ctl、aos-agent ctl 的 `--timeout-s`）照舊用秒——對人用牆鐘（[tick-time 05](../../thinking/2026-11/05/tick-time/05-T5T6T8與試驗場.md)）。
- **N-02** 資料夾別亂弄。（10-12）
- **N-03** 「tick 之間可以安全打包」是大家要遵守的規範，不強制；打包由 kernel 做。例：kernel 在公告欄說「大家，咱們第 1021 回合準備關機下線，在那之前所有人把狀態保存到檔案，逾時不候」。（10-12）

  - **11-06 註／改讀**：「打包由 kernel 做」的現況是 daemon 的 sleep；使用者 11-06 裁「D1：先只有硬凍（推薦）」，現行的停＝daemon sleep 的硬凍，N-03 例子裡 kernel 公告第 N 回合的軟凍現在沒有（[apply-ideas D1](../../thinking/2026-11/06/apply-ideas/03-方向題.md)）。

- **N-65 兩鐘規則**（11-06 新；**已定（11-06）；實作排在 T1～T7**（11-06 註：T1～T4、T7 已實作，[tick-time 04](../../thinking/2026-11/05/tick-time/04-T線實作結果.md)；11-06 晚 T5、T6 已實作，[tick-time 05](../../thinking/2026-11/05/tick-time/05-T5T6T8與試驗場.md)）；[tick-time 03 使用者裁定與 N1／N2](../../thinking/2026-11/05/tick-time/03-11-06-裁定與新設計.md)、[daemon-board 四題裁定](../../thinking/2026-11/06/daemon-board/README.md)）：
  ① **期限寫 cycle 時，有 `AOS_CLOCK` 就讀它指的時鐘檔、比 cycle；沒有就退牆上時鐘**，以 `cycles × AOS_CLOCK_INTERVAL` 換成毫秒。使用者稱原生 Linux 實際時間函數為「逃生口」；沒時鐘的樹沒有凍住時間的保證（[tick-time 03](../../thinking/2026-11/05/tick-time/03-11-06-裁定與新設計.md)）。
  ② **有 `AOS_CLOCK` 就只認時鐘，時鐘停了期限就不到，不因時鐘檔過舊自動退牆鐘、也不 warning**；看 daemon 表的 `_clock` 列是不是 `running`，或讀鐘檔本身（`cat "$AOS_CLOCK"`；表頂層的時鐘觀察值 11-09 拿掉，使用者裁「都照推薦」，[thinking clock-and-hot-writes 03 題 3](../../thinking/2026-11/09/clock-and-hot-writes/03-衝突與方向題.md)）。使用者 11-06「那兩題都按照推薦。」裁定 N2（[tick-time 03](../../thinking/2026-11/05/tick-time/03-11-06-裁定與新設計.md)）。
  ③ **跨樹的信裡期限用毫秒**，使用者原話「信裡用毫秒」；kernel 內部計時才用自己樹的鐘（[daemon-board 題 1](../../thinking/2026-11/06/daemon-board/README.md)）。

  **11-07 註（判官排隊期限用牆鐘）**：判官排隊的期限（信 body 的 `queue_wait_ms`）從信封 `sent_at` 起按牆鐘算，不數 cycle。凍住期間牆鐘照走，所以醒來第一輪，已經過期的排隊信會一起被拒；要跨過凍住繼續排，就用 `--on-queued ok`（不帶期限，見 N-66（[05-基礎設施-窗/08-N-66.md](05-基礎設施-窗/08-N-66.md)） 11-07 註）。這是 N-01 改讀「aos 內部互相約的時間看時鐘」的例外，使用者知道後果後選了維持。已實作。（11-07 使用者裁定，出處 [wf/workflows/refactor/reports/2026-11-07-sol審查/11-使用者裁定.md](../../../wf/workflows/refactor/reports/2026-11-07-sol審查/11-使用者裁定.md) #6）

  **11-07 註**：這裡的「毫秒」指跨樹用牆鐘的語意、不數 cycle；格式不限，既有的 ISO 8601／秒數格式照舊，不要求改成 epoch 毫秒整數（同 N-67（[10-基礎設施-定義與工作區/09-N-67.md](10-基礎設施-定義與工作區/09-N-67.md)） ②）。（11-07 使用者裁定，出處 [wf/workflows/refactor/reports/2026-11-07-sol審查/11-使用者裁定.md](../../../wf/workflows/refactor/reports/2026-11-07-sol審查/11-使用者裁定.md) #11）
  ④ **`AOS_CLOCK_INTERVAL` 是標稱頻率的默契，只會慢，先不補成固定週期**；使用者原話「先不補」（[daemon-board 題 4](../../thinking/2026-11/06/daemon-board/README.md)）。沒設先用 1000 毫秒，**暫定：使用者說可再想**，原話「AOS_TICK_INTERVAL用一秒？我覺得這個可以再想想...不過現在就先用一秒吧。」（[tick-time 03](../../thinking/2026-11/05/tick-time/03-11-06-裁定與新設計.md)）。

**時鐘停住時，判卡住、鎖租約與以 cycle 計的逾時一起停、永不到期；要它們繼續走，就讓時鐘 resume。**（11-07 使用者裁定 sol 審查 #12）
