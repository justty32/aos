# 設計理念／時空

- **N-01** 大家都要看 tick-tock 時鐘。（10-12）
  - **11-06 註／改讀**：使用者 11-05「推薦大家用tick回合數來算」；aos 內部互相約的時間看 tick，對人（使用者體驗）、對外、對 Linux proc（daemon）用牆上時鐘。已定（11-05，[fs-image 原話](../../thinking/2026-11/05/fs-image/README.md)）；內部期限改 tick 的實作排在 T1～T6。**11-06 註（實作）**：T1 共用函數（aos-util `tick.hpp`、`lib/tool_io.py`、`py/aos_ws.py`）與 T4（llm kernel aging 數 tick）已實作（[tick-time 04](../../thinking/2026-11/05/tick-time/04-T線實作結果.md)）。
- **N-02** 資料夾別亂弄。（10-12）
- **N-03** 「tick 之間可以安全打包」是大家要遵守的規範，不強制；打包由 kernel 做。例：kernel 在公告欄說「大家，咱們第 1021 回合準備關機下線，在那之前所有人把狀態保存到檔案，逾時不候」。（10-12）

  - **11-06 註／改讀**：「打包由 kernel 做」的現況是 daemon 的 sleep；使用者 11-06 裁「D1：先只有硬凍（推薦）」，現行的停＝daemon sleep 的硬凍，N-03 例子裡 kernel 公告第 N 回合的軟凍現在沒有（[apply-ideas D1](../../thinking/2026-11/06/apply-ideas/03-方向題.md)）。

- **N-65 兩鐘規則**（11-06 新；**已定（11-06）；實作排在 T1～T7**（11-06 註：T1～T4、T7 已實作，[tick-time 04](../../thinking/2026-11/05/tick-time/04-T線實作結果.md)）；[tick-time 03 使用者裁定與 N1／N2](../../thinking/2026-11/05/tick-time/03-11-06-裁定與新設計.md)、[daemon-board 四題裁定](../../thinking/2026-11/06/daemon-board/README.md)）：
  ① **期限寫 tick 時，有 `AOS_TICK` 就讀它指的時鐘檔、比 tick；沒有就退牆上時鐘**，以 `ticks × AOS_TICK_INTERVAL` 換成毫秒。使用者稱原生 Linux 實際時間函數為「逃生口」；沒 tick 的樹沒有凍住時間的保證（[tick-time 03](../../thinking/2026-11/05/tick-time/03-11-06-裁定與新設計.md)）。
  ② **有 `AOS_TICK` 就只認時鐘，時鐘停了期限就不到，不因時鐘檔過舊自動退牆鐘、也不 warning**；看 daemon 表的 `_tick` 列與 `tick` 欄。使用者 11-06「那兩題都按照推薦。」裁定 N2（[tick-time 03](../../thinking/2026-11/05/tick-time/03-11-06-裁定與新設計.md)）。
  ③ **跨樹的信裡期限用毫秒**，使用者原話「信裡用毫秒」；kernel 內部計時才用自己樹的鐘（[daemon-board 題 1](../../thinking/2026-11/06/daemon-board/README.md)）。
  ④ **`AOS_TICK_INTERVAL` 是標稱頻率的默契，只會慢，先不補成固定週期**；使用者原話「先不補」（[daemon-board 題 4](../../thinking/2026-11/06/daemon-board/README.md)）。沒設先用 1000 毫秒，**暫定：使用者說可再想**，原話「AOS_TICK_INTERVAL用一秒？我覺得這個可以再想想...不過現在就先用一秒吧。」（[tick-time 03](../../thinking/2026-11/05/tick-time/03-11-06-裁定與新設計.md)）。
