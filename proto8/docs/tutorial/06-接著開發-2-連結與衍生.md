# 06 接著開發（二）：別的庫、靜態／動態連結、從另一隻衍生

## 6.3 別的庫：`defs.lib("名", 路徑)`

**結論**：庫就是一個固定形狀的資料夾（`packs/<包>.json`＋`tools/<工具>/`）。資料夾＝命名空間：`std` 的工具用短名，別的庫的工具編譯時自動帶 `庫名_`，撞名在編譯時就報錯。

做一個小庫 `mylib`，裡面放 shout：

```sh
mkdir -p mylib/packs mylib/tools
cp -r tools/shout mylib/tools/shout
```

寫 `mylib/packs/fun.json`：

```json
{"description": "Fun tools: shout.",
 "tools": {"shout": {"path": "../tools/shout"}}}
```

`agents/ann/agent.py` 在 `std = defs.std` 下面加一行、`tools=[...]` 那一串尾巴加一包：

```python
my = defs.lib("my", defs.env("AOS_WS", "/mylib"))
```

```python
    tools=[std.pack("look"), std.pack("mailbox"), std.tool("base/peek_now_time"),
           defs.tool("shout", defs.env("AOS_WS", "/tools/shout")),
           my.pack("fun")],
```

```sh
python3 agents/ann/agent.py --compile
AOS_WS=$PWD python3 agents/ann/agent.py --compile | tail -1
python3 -c 'import json; print(json.load(open("agents/ann/tools.json"))["tools"]["my_shout"])'
```

```
ann: error: SpecBad defs.lib('my') reads $AOS_WS/mylib, but AOS_WS is not set (set it when you run agent.py) (fix the declaration in agent.py)
agents that use this definition see the change from their next brain call (state machine and loop changes: from their next tick or restart)
{'path': {'$env': 'AOS_WS', '$path': '/mylib/tools/shout'}}
```

第一次失敗是故意的：編譯時要真的去讀庫，庫根寫成 `$AOS_WS/…` 就得在編譯那一刻給 `AOS_WS`（`env.sh` 會把它清掉）。之後凡是用到 `mylib` 的編譯都帶 `AOS_WS=$PWD`。`tools.json` 裡只有完整路徑，不記庫名。

## 6.4 靜態連結、動態連結（編譯選項）

**結論**：預設**靜態連結**＝把包裡的工具一支支複製進 `tools.json`，包之後加了工具要重新編譯才看得到；`--dynamic`＝**動態連結**，`tools.json` 只寫「去讀哪個包」，agent 每次問腦前才讀（不用重起）。像 `gcc -static` 和 `.so`，但 aos 的靜態連結只固定**名單**，不像 `gcc -static` 把程式本身抄進來（見本節最後一點）。

```sh
export AOS_WS=$PWD
python3 -c 'import json; t=json.load(open("agents/ann/tools.json")); print(t.get("$override"), t["tools"]["read"])'
python3 agents/ann/agent.py --compile --dynamic | head -2
python3 -c 'import json; t=json.load(open("agents/ann/tools.json")); print(t.get("$override")); print(sorted(t["tools"]))'
python3 agents/ann/agent.py --compile | tail -1
```

```
None {'path': {'$env': 'AOS_HOME', '$path': '/lib/tools/base/read'}}
ann: warning: my.pack('fun') is linked statically: its tools are renamed (a prefix or rename=), which only static linking can do
wrote ~/code/aos-tut/agents/ann/_entry
[{'$env': 'AOS_HOME', '$path': '/lib/packs/look.json'}, {'$env': 'AOS_HOME', '$path': '/lib/packs/mailbox.json'}]
['my_shout', 'peek_now_time', 'shout']
agents that use this definition see the change from their next brain call (state machine and loop changes: from their next tick or restart)
```

- 靜態時 `read` 直接寫在表裡；動態時 `look`、`mailbox` 兩包變成 `$override` 兩行，表裡只剩單支的工具。
- `my.pack("fun")` 動態不了：工具要改名成 `my_shout`，只有編譯時複製才改得了名，所以它照樣靜態、印一行 warning。`defs.load` 來的工具也一樣只能靜態。
- 只讓某一包動態：`std.pack("look", link="dynamic")`。最後那行又編回預設的靜態，下面接著用。
- **靜態連結只固定工具名單**：「有哪些工具、各在哪條路徑」寫死在 `tools.json`；工具程式本身、它的 `_tooldef.json`（腦看到的說明）、狀態格的程式，仍是 agent 跑的時候從 `$AOS_HOME`（或庫根，例如上面的 `$AOS_WS/mylib`）讀。所以庫一升級（`git pull`＋`install.py`），已經編譯好的 agent 下一次問腦就換成新的說明；庫拿掉一支工具，清單就少一支；拿掉一格程式，用它的 agent 一起來就停。靜態連結不是「之後庫怎麼改都不影響這隻」（使用者 11-19 選維持現狀、只寫清楚，[aos-vs-c-1119](../../thinking/2026-11/19/aos-vs-c-1119/README.md#使用者已答11-19-下午選項框) G2）。

## 6.5 從另一隻衍生：`defs.load`、`defs.drop`、`defs.extern`

**結論**：新的 `agent.py` 先 `defs.load("../ann")` 拿到 ann 那隻（ann 的 `agent.py` 交給 `defs.main` 的那個 `defs.Agent`），用 `base.tools`、`base.llm` 這些欄位，只寫差異。衍生只發生在編譯那一刻；編出來的是完整的一夾，不記得 ann。

```sh
mkdir -p agents/bob
cp $AOS_HOME/templates/agents/agent-python/agent.py agents/bob/agent.py
echo "You are bob. Answer every letter with mailbox_send." > agents/bob/system.hand.txt
```

`agents/bob/agent.py` 的 `# ---- your agent` 以下換成：

```python
base = defs.load("../ann")              # run ann's agent.py and take the agent it hands to defs.main

bob = defs.Agent(
    "Like ann, without grep, with a system text written by hand.",
    system=defs.extern("system.hand.txt"),   # system.txt becomes a link to the file written by hand; compiling never touches it
    tools=[base.tools, defs.drop("grep")],   # every tool of ann but grep
    llm=base.llm,
    fsm=base.fsm,
)

defs.main(bob)
```

```sh
AOS_WS=$PWD python3 agents/bob/agent.py --compile
readlink agents/bob/system.txt
cat agents/bob/system.txt
python3 -c 'import json; print(sorted(json.load(open("agents/bob/tools.json"))["tools"]))'
aos-agent -d .stack ctl add --auto-restart -w . agents/bob
aos-agent -d .stack --target bob say "please shout"
aos-agent -d .stack --target bob listen --timeout-s 20
```

```
wrote ~/code/aos-tut/agents/bob/_entry
…
wrote ~/code/aos-tut/agents/bob/_metainfo.json
wrote ~/code/aos-tut/agents/bob/README.md
wrote ~/code/aos-tut/agents/bob/system.txt -> system.hand.txt
agents that use this definition see the change from their next brain call (state machine and loop changes: from their next tick or restart)
system.hand.txt
You are bob. Answer every letter with mailbox_send.
['glob', 'ls', 'mailbox_peek', 'mailbox_read', 'mailbox_send', 'my_shout', 'peek_now_time', 'read', 'shout', 'stat', 'view']
~/code/aos-tut/.stack/procs/bob
FAKE ANSWER to: please shout (tool said: HELLO)
```

- `system.txt` 是一個連結（symlink：一個指到別的檔的小檔，讀它等於讀它指的那份），指到你手寫的 `system.hand.txt`：`defs.extern(路徑)`＝「這一欄編成連結」，編譯只重做連結、永遠不碰手寫那份；改 `system.hand.txt` 不用重新編譯，下次問腦就生效（11-20 編譯程式庫第 4 刀；使用者：「創建一個symlink…編譯的時候就是只生成symlink」）。
- **別濫用**：連結讓定義夾靠著夾外（或另一個名字）的檔。整夾搬走、`agent_def new` 抄到不同深度，相對的連結會斷，斷了 agent 是靜靜地沒有 system 文字，只有 `agent_def check` 會報；`agent_def llm`／`tools` 這類指令會順著連結改到那份手寫檔（連到它的定義一起變），`agent_def system` 則把連結換成普通檔。只是想在編譯時讀一份檔的字，用 Python 讀進來就好：`system=open("system.hand.txt").read()`。細節（連到別夾、`fsm` 只能連同一夾、`defs.load` 的底有連結時）在 `templates/agents/agent-python/README.md` 的「extern」。
- `grep` 不見了，其餘跟 ann 一樣（`llm` 也是 `fake-shout`，所以照樣叫 shout）。
- ann 的 `agent.py` 之後改了，bob 要**重新編譯**才跟上；`defs.load` 跑的是 ann 的 `agent.py`，不是 ann 那夾 json。

<details><summary>衍生還能做的</summary>

- 改一支 hook 的一個欄位：`hooks=[base.hooks, {"timer": {**base.hooks["timer"], "every_ms": 60000}}]`。底要真的有那支 hook：ann 是 `hooks={}`，`base.hooks["timer"]` 會是 `KeyError`；底寫的是 `hooks=std.hooks()` 才有 `timer`。
- 改狀態機的一格：`fsm=defs.fsm(base.fsm, [defs.state("think", [...])])`；`drop=["act"]` 再拿掉一格，但整張表會重驗，別的格還指著它就是 `SpecBad`（拿 ann 的四格直接 drop `act`：`state wait: next state 'act' is not one of the states (idle, think, wait)`，`wait` 的 `next` 也要一起改）。
- 底的工具換名字：`base.pack(prefix="a_")`（跟 `std.pack` 一樣收 `prefix=`、`rename=`、`exclude=`）。
- 兩個底（菱形）同名工具不一樣＝`SpecBad`，用 `defs.tool(名, …)` 或 `defs.drop(名)` 說清楚要哪個。
- 細節在 `templates/agents/agent-python/README.md` 的「Build on another agent.py」。
</details>
