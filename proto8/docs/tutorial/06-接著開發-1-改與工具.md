# 06 接著開發（一）：改了重新編譯、自己寫一支工具

## 6.1 改了 agent.py 就重新編譯，跑著的會立刻讀到

**結論**：改 `agent.py` → `--compile` 重新編譯 → 跑著的 agent **不用重起**，下一次問腦就用新的定義。這是特性：定義夾是它每次都去讀的那份，不是開機時拷一份走。

把 `defs.Agent(...)` 裡 `system=` 的第一行改成 `You are ann, a polite clock. When a letter comes, …`，然後：

```sh
python3 agents/ann/agent.py --compile | tail -1
aos-agent -d .stack ctl state --target ann system
aos-daemon-ctl -d .stack ls | grep ann
```

```
agents that use this definition see the change from their next brain call (state machine and loop changes: from their next tick or restart)
== system
from   definition (~/code/aos-tut/agents/ann/system.txt)
bytes  146
You are ann, a polite clock. When a letter comes, look at the clock with peek_now_time,
then answer the letter with mailbox_send to its reply_to.
ann	running	804813	-	~/code/aos-tut	-
```

pid 沒變＝沒重起，新的 system 已經生效。要注意的：

- **一份定義，所有用它的 agent 一起變**。只想改一隻，就另外抄一夾（或 6.5 的衍生）。
- **agent 自己改過的那塊不跟著變**：agent 用 `self_*` 工具改自己時，改動記在它的 stack 裡、蓋在定義上面（`ctl state` 的 `no own changes`＝沒有）。
- **狀態機別在跑的時候改名或刪格**：它正停在那一格的話，下一步會找不到格、報 `StateUnknown`（骨架 README 的說法，教學沒實測）。
- 編不過（`SpecBad`）就什麼都不寫，跑著的照舊；所以改到一半存檔不會弄壞它。

## 6.2 標準庫的工具包、自己寫一支工具

**結論**：工具包先從 `std` 挑；沒有的就抄 `tool-python` 骨架寫一支，`tool.py --compile` 編譯，再在 `agent.py` 的 `tools=[…]` 加一項。

標準庫有哪些包：

```sh
ls $AOS_HOME/lib/packs
```

```
README.md
change.json
comm.json
def.json
…
look.json
mailbox.json
self.json
shell.json
subagent.json
todo.json
ws-write.json
```

`tools=[…]` 裡的寫法：`std.pack("shell")`＝整包；`std.tool("base/read")`＝一支；`defs.drop("grep")`＝從包裡拿掉一支。

### 抄骨架、寫工具

```sh
mkdir -p tools
cp -r $AOS_HOME/templates/tools/tool-python tools/shout
ls tools/shout
```

```
README.md
_entry.json
_metainfo.json
_tooldef.json
tool.py
```

打開 `tools/shout/tool.py`，上面 setup 那幾行不動，`# ---- your tool` 以下換成：

```python
@fn.tool
def shout(text: str) -> str:
    """Say the text back in capital letters. Example: {"text": "hi"} -> HI

    Args:
      text: the text to shout
    """
    return text.upper()


fn.main(shout)
```

工具就是一個 Python 函數加上 `@fn.tool`：說明寫在 docstring（`Args:` 那行之前），每個參數要有型別（`str`、`int`、`float`、`bool`、`list`、`dict`）和 `Args:` 底下一行說明；少了哪樣，`--compile` 會報一行 `SpecBad` 說要補什麼。也可以改用明寫的 `@fn.tool(description=..., params=[fn.param(...)])`，明寫的贏（11-20 起的寫法，使用者選「新名字 fn」）。

```sh
python3 tools/shout/tool.py --compile
echo '{"text": "hello"}' | aos-exec tools/shout
echo '{}' | aos-exec tools/shout
```

```
wrote ~/code/aos-tut/tools/shout/_tooldef.json
wrote ~/code/aos-tut/tools/shout/_metainfo.json
HELLO
shout: error: ArgumentsBad missing text (required)
shout: error: ArgumentsBad missing text (required)
```

工具就是「給一份 JSON、印出答案」的資料夾。錯誤印兩次是因為 stdout、stderr 各一行（給腦看和給人看），在終端機上就疊在一起。

### 接進 agent，讓腦真的叫它

`agents/ann/agent.py` 的 `defs.Agent(...)` 裡改兩個欄位（`tools=` 尾巴加一支、`llm=` 換代號）：

```python
    tools=[std.pack("look"), std.pack("mailbox"), std.tool("base/peek_now_time"),
           defs.tool("shout", defs.env("AOS_WS", "/tools/shout"))],
    llm={"model": "fake-shout"},
```

`defs.env("AOS_WS", "/tools/shout")`＝「這隻的工作區底下的 tools/shout」；路徑這樣寫，整夾搬到哪都對（別寫 `../`）。

預設假腦只會叫 `peek_now_time`。要它叫 `shout`，給 llm kernel 加一個**劇本假腦**：打開 `llm/kernel.json`，在 `"endpoints": {` 裡加一包（llm kernel 每一輪都重讀這檔，不用重起）：

```json
"fake-shout": {"exec": {"$env": "AOS_HOME", "$path": "/lib/tools/base/llm_fake"}, "speed": "fast", "cost": "free", "tool": "peek_now_time",
               "script": [{"when": "shout", "tool_calls": [{"name": "shout", "arguments": {"text": "hello"}}]}],
               "summary": "fake brain: a letter with the word shout makes it call shout"},
```

```sh
python3 agents/ann/agent.py --compile | tail -1
aos-agent -d .stack ctl state --target ann tools | grep -E '^(==|shout|peek)'
aos-agent -d .stack --target ann say "please shout"
aos-agent -d .stack --target ann listen --timeout-s 20
AOS_LLM_KERNEL=$PWD/.stack/procs/llm aos-llm ls | grep shout
```

```
agents that use this definition see the change from their next brain call (state machine and loop changes: from their next tick or restart)
== tools
peek_now_time	Get the current time.
shout	Say the text back in capital letters.
FAKE ANSWER to: please shout (tool said: HELLO)
fake-shout	fast	free	-	-	-	fake brain: a letter with the word shout makes it call shout
```

（`say` 印的信名省略。）信裡有 shout 這個字，劇本假腦就叫 `shout`，括號裡是你那支工具的回答。

`aos-llm ls` 放在最後：它列的是 llm kernel 上一次接信時寫下的那張表，不是直接讀 `kernel.json`。剛改完 `kernel.json`、還沒有人問過腦，就列不出 `fake-shout`（11-20 實跑：改完馬上 `ls` 沒有這一行，`say` 一封之後就有了）。

### 工具或 hook 也能直接寫在 agent.py 裡

**結論**：同一套 `@fn.tool` 寫法的函數直接寫在 `agent.py`、放進 `tools=[…]`；`@fn.hook("事件")` 的函數放進 `hooks=[…]`。編譯時每個函數各「抽出來」成定義夾裡的一支程式 `fn/<名>.py`，`tools.json`／`hookeds.json` 那格指到它（11-20 起；使用者選「抽出來」「一起，同一套寫法」）。

```python
from aos.py import fn


@fn.tool
def shout(text: str) -> str:
    """Say the text back in capital letters. Example: {"text": "hi"} -> HI

    Args:
      text: the text to shout
    """
    return text.upper()


@fn.hook("before_tool", condition="ws_write")
def no_secrets(event):
    """Stop a ws_write that mentions a secret."""
    if "secret" in str(event.get("arguments")):
        return fn.block("the arguments mention a secret")
```

```python
    tools=[std.pack("look"), std.pack("mailbox"), std.pack("ws-write"), std.tool("base/peek_now_time"), shout],
    hooks=[no_secrets],
```

`python3 agents/ann/agent.py --compile` 之後，夾裡多 `fn/shout.py`、`fn/no_secrets.py`（可執行），`tools.json` 是 `"shout": {"path": "fn/shout.py"}`。要注意的：

- **函數只能用**：Python 內建的、自己的參數與變數、`fn`、`agent.py` 最上面 `import` 進來的模組（只搬用到的那個名字）。用到 `agent.py` 自己的常數、函式、`defs`／`std`、放在 `agent.py` 旁邊的模組（`import helpers`），編譯時都報一行 `SpecBad`，說怎麼改（通常是「搬進函數裡」）。
- **函數裡的相對路徑從 `fn/` 算**（程式自己那一夾，跟所有工具一樣）；要工作區寫 `os.environ["AOS_WS"]`。
- hook 函數回 `None`＝放行、回 dict＝改那些鍵、回 `fn.block("原因")`＝攔下；`after_tool` 這種攔不下的事件裡寫 `fn.block` 會報 `SpecBad`。
- 抽出來的程式之後跟 `agent.py` 無關，能手改，下次編譯整份蓋；拿掉的函數留下的舊檔不刪。細節在骨架 README 的「Functions as tools and hooks」。

<details><summary>工具骨架的旗標</summary>
