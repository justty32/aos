# 04 寫一份原始碼（agent.py）

**結論**：抄 `agent-python` 骨架，只改 `agent.py` 裡 `# ---- your agent` 以下那段，`python3 agent.py --compile` 就把整夾 json 編譯出來。好比 C 原始碼和 `.o`：編譯完，aos 只跑那些 json，跟 `agent.py` 沒關係了。

## 抄骨架

```sh
mkdir -p agents
cp -r $AOS_HOME/templates/agent-python agents/ann
ls agents/ann
```

```
README.md
_entry
_metainfo.json
agent.py
body.json
fsm.json
hookeds.json
interfaces.json
llm.json
loop.json
system.txt
tools.json
```

除了 `agent.py` 和 `README.md`，其他都是編譯產物。

## 改原始碼

用編輯器打開 `agents/ann/agent.py`。最上面 `# ---- setup` 那幾行（找 aos 套件、`from aos.py.agent import defs`）**不要動**；把 `# ---- your agent` 以下換成：

```python
std = defs.std

ann = defs.Agent(
    "Tell the time and answer by mail.",
    system="""You are ann. When a letter comes, look at the clock with peek_now_time,
then answer the letter with mailbox_send to its reply_to.
""",
    tools=[std.pack("look"), std.pack("mailbox"), std.tool("base/peek_now_time")],
    llm={"model": "fake"},
    fsm=std.fsm(),
    hooks={},               # no hooks yet, but declared, so aos-gdb can set breakpoints
)

defs.main(ann)
```

整隻 agent 寫成一個 `defs.Agent(...)`：第一個是說明，其他欄位都寫「名字=值」，名字全小寫。寫錯的欄位（例如 `tools` 給的不是串列）編譯時才報一行 `SpecBad`。

| 欄位 | 是什麼 | 編譯成 |
|---|---|---|
| 說明（第一個，不寫名字） | 一句英文：這隻做什麼 | `_metainfo.json` 的 `summary` |
| `system` | 給腦看的開場說明（system prompt） | `system.txt` |
| `tools` | 腦能叫的工具。`std.pack("look")`＝標準庫的一包（唯讀看檔）；`std.tool("base/peek_now_time")`＝標準庫的一支 | `tools.json` |
| `llm` | 腦的設定。`model` 寫上一章 `aos-llm ls` 的代號；`{}`＝llm kernel 的預設 | `llm.json` |
| `fsm` | 狀態機（這隻一格一格怎麼走）。`std.fsm()`＝用標準的四格：閒著 idle → 想 think → 等腦 wait → 做 act | `fsm.json` |
| `hooks` | 事件發生時順手跑的小程式（hook，像 git hook）。骨架已經帶了 `hooks={}`：一個都沒有，但宣告了，第 06 章的斷點才掛得上去；**別刪** | `hookeds.json`（被勾著的 hook 清單；`interfaces.json` 的 `hookeds` 指它） |
| `defs.main(ann)` | 最後一行，把這隻交給命令列（`--compile`、`--dry-run`）；保留 | — |

`std` 是隨 aos 發的**標準庫**，像 C 的 libc：工具包在 `$AOS_HOME/lib/packs/`，工具在 `$AOS_HOME/lib/tools/`。

## 檢查這夾定義

```sh
echo '{"op": "check", "path": "agents/ann"}' | AOS_WS=$PWD aos-exec $AOS_HOME/lib/tools/agent/agent_def
```

```
{"problems": []}
```

空的 `problems`＝合格。`agent_def` 本來是給 agent 用的工具，所以要用「給工具一份 JSON」的方式叫它；`AOS_WS` 告訴它相對路徑從哪算。

**check 才會查叫的東西存不存在**：寫錯的工具路徑、狀態格／loop／hook 指到的程式不在、`llm` 的值型別錯（例 `"temperature": "hot"`），`--compile` 都不管、照樣編過，只有 check 會報（使用者 11-19 選「只放進檢查指令」）。所以每次編譯完都跑一次 check。這台機器上查不了的（例如某個環境變數這裡沒設）它照實放進 `"warnings"`，不算不合格；`model` 的名字對不對它不查（要問 kernel 才知道）。

<details><summary>編譯前一定要知道的三件事（骨架 README 原文的重點）</summary>

1. `--compile` 每次把宣告到的檔**整份蓋掉、不問**。在一夾手寫的定義裡跑，手寫的就沒了；先 `--dry-run` 看，或先 commit。
2. 直接改編譯產物（編輯器、`agent_def tools`…）的改動，下次重新編譯就沒了。要留就寫進 `agent.py`。
3. 不動的：`_metainfo.json` 裡 `agent.py` 沒設的鍵、已經在的 `README.md`、其他檔。舊版 `agent.py` 寫過、新版不再宣告的檔不會被刪，要自己刪。
</details>
