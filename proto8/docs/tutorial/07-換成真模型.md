# 07 換成真模型（**整章未實跑**）

**結論**：agent 這邊只換一個代號（`agent.py` 裡寫 `llm={"model": "luna"}`，重新編譯）；代號背後連哪裡、用哪個模型，寫在 llm kernel 的 `llm/kernel.json`；金鑰放在開板子那個視窗的環境變數裡，不寫進任何檔。

這章只寫怎麼設：寫教學時沒有叫真模型，下面的指令與檔案位置是照範本與說明寫的，**沒有實跑**。

## 1. llm kernel 那邊：代號 → 模型

`llm/kernel.json` 的 `endpoints` 出廠就登記了幾個真模型的代號（`aos-llm ls` 也列得出）：

| 代號 | 連哪 | 模型（`model` 欄） |
|---|---|---|
| `luna`、`terra`、`sol` | LiteLLM proxy `http://localhost:4000/v1` | `chatgpt-gpt-6-luna-low`、`chatgpt-gpt-6.1-terra`、`chatgpt-gpt-6.1-sol` |
| `smart-high`、`judge` | 同上 | `claude-haiku` |
| `stupid-fast` | LM Studio `http://localhost:1234/v1` | `qwen3-1.7b` |

一包長這樣（`luna`）：

```json
"luna": {"exec": "endpoints/litellm", "url": "http://localhost:4000/v1", "model": "chatgpt-gpt-6-luna-low", "cost": "high", "context": 272000,
              "summary": "LiteLLM gpt-6 luna, low effort"},
```

- `url`、`model` 換成你那台真的有的（`curl localhost:4000/v1/models` 看名字）。
- `exec: "endpoints/litellm"` 指 `llm/endpoints/litellm/_entry`，裡面寫了 `--key-env LITELLM_KEY`＝「金鑰從環境變數 `LITELLM_KEY` 讀」。只寫**變數名**，不寫值。
- 要加自己的一包就照這個形狀多寫一個代號；`fixed` 裡的設定（例如溫度）是釘死的，agent 改不了，要換就換代號。

## 2. 金鑰：放在開板子的視窗

kernel 掛在板子上，所以它的環境是從板子繼承來的。在**視窗 A 開板子之前**：

```sh
export LITELLM_KEY=…        # 值自己填；proxy 沒開金鑰驗證就不用設
aos-exec root
```

板子已經開著的話：先 `aos-daemon-ctl -d .stack shutdown`，在視窗 A 設好再 `aos-exec root`（上面睡著的都會醒）。

## 3. agent 這邊：換代號、重新編譯

`agents/ann/agent.py` 裡 `llm=` 那行改成：

```python
    llm={"model": "luna"},
```

```sh
AOS_WS=$PWD python3 agents/ann/agent.py --compile | tail -1
aos-agent -d .stack --target ann say hello
aos-agent -d .stack --target ann listen --timeout-s 120
```

跟第 06 章一樣，跑著的 ann 下一次問腦就換成 luna，不用重起。真模型會自己決定叫哪個工具、回什麼，不再是 `FAKE ANSWER`。

<details><summary>出錯時大概長怎樣（照 llm kernel 說明，未實跑）</summary>

- 金鑰沒設而 proxy 要金鑰：`EndpointFailed HTTP 401 (the endpoint refused the request and may need a key: environment variable LITELLM_KEY (--key-env) is not set): …`
- 信裡改了包釘死的設定：`RequestBad temperature is fixed by endpoint smart-high …`
- proxy 沒開：問腦那一封卡住或失敗，其他照跑。WSL 裡連沒人聽的本機埠可能卡上兩分鐘左右才回錯，先 `curl` 確認 proxy 在。
</details>
