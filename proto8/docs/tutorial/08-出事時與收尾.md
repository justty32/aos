# 08 出事時看哪裡、收尾

## 先看三個地方

**結論**：先看表（狀態和原因欄），再看那隻的 `stderr.txt`，再看視窗 A 印的狀態變化。aos 的錯誤一律是一行 `誰: error: 代號 原因`，代號（CamelCase 一個字）就是線索。

| 看哪 | 指令 | 看什麼 |
|---|---|---|
| 表 | `aos-daemon-ctl -d .stack ls` | 第二欄狀態（`running`、`stopped`、`sleeping`…）、第四欄退出碼、最後一欄原因 |
| 全身 | `aos-agent -d .stack ctl state --target ann` | 在不在跑、幾封信在等、上一句回答、工具、腦設定 |
| 錯誤記錄 | `tail .stack/procs/ann/stderr.txt` | 工具失敗、腦叫不到之類的 warning 與 error |
| 板子的流水帳 | 視窗 A | 誰什麼時候變成什麼狀態、退出碼 |
| 停在哪一格 | `cat .stack/procs/ann/stage.txt`，或 aos-gdb 裡 `a.look.where()` | idle／think／wait／act |

## 常見的錯誤行

下面每一行都是實跑出來的。

```sh
(unset AOS_HOME; python3 agents/ann/agent.py --compile)
```
```
ann: error: HomeMissing AOS_HOME is not set (set it, or copy the aos package folder next to agent.py)
```
→ 這個視窗沒設 `AOS_HOME`：`export AOS_HOME=~/repo/aos/proto8; source $AOS_HOME/env.sh`。

狀態機裡把 `wait` 打成 `wiat`，編譯：
```
typo: error: SpecBad state idle: next state 'wiat' is not one of the states (idle) (fix the declaration in agent.py)
```
→ `SpecBad`＝`agent.py` 宣告寫錯，照句子改；這時**什麼檔都沒寫**（那夾只有 `agent.py`）。

```sh
aos-agent -d .stack --target nobody say hi
```
```
aos-agent: error: InstanceMissing nobody is not on the daemon table (removed with rm, exited 0, …)
```
→ 名字打錯，或那隻已經 `rm`；`aos-daemon-ctl -d .stack ls` 看表上有誰。

kernel 沒在跑時問話（先 `aos-daemon-ctl -d .stack stop llm` 模擬）：

```sh
aos-agent -d .stack --target ann say "anyone there"
aos-agent -d .stack --target ann listen --timeout-s 3; echo "exit=$?"
```
```
aos-agent: warning: ann is waiting for its brain, but the llm kernel at ~/code/aos-tut/.stack/procs/llm is not running (the llm daemon is not running (state.json phase stopped)); start that llm kernel, or if AOS_LLM_KERNEL points to the wrong place, add ann again with the right one. Still waiting, Ctrl-C to leave
aos-agent: error: AnswerMissing waited 3 s; 000000000005.… was handed over and is not answered yet; ann is waiting for its brain, but the llm kernel … is not running …
exit=1
```
→ 信沒丟。`aos-daemon-ctl -d .stack start llm` 之後再 `listen`，就收到 `FAKE ANSWER to: anyone there (…)`。`stderr.txt` 同時記了一行 `aos-llm: warning: … llm daemon is not running …`。

其他會碰到的：

| 錯誤代號 | 意思 | 怎麼辦 |
|---|---|---|
| `DaemonMissing` | 那塊板子沒開（例：關機後再 `shutdown`） | 視窗 A `aos-exec root` |
| `HooksMissing`（aos-gdb 下斷點時） | 那隻沒宣告 hook（骨架那行 `HOOKS = {}` 被刪了，或像 bob 衍生時沒寫 `HOOKS`） | 照錯誤行後面那句：`agent.py` 加 `HOOKS = {}`、`hooks=HOOKS`，重新編譯（06 之三） |
| `SpecBad … AOS_WS is not set` | 用了 `$AOS_WS` 下的庫，編譯時沒給 | `AOS_WS=$PWD python3 …/agent.py --compile` |
| `ArgumentsBad`（工具） | 工具收到的參數不對 | 看那支工具的 `_tooldef.json` |
| `LlmKernelMissing` | agent 不知道總機在哪（**未實跑**） | 檢查 `root/.env` 的 `AOS_LLM_KERNEL`，改完重開板子 |
| `DotenvBad … .env line N`（起板子時，**未實跑**） | `.env` 那行要的變數沒設（多半是 `AOS_HOME`） | 先 `export AOS_HOME=…` |

更多代號：`$AOS_HOME/knowledge/aos/errors.json`。

## 收尾：全部關掉、清掉

```sh
aos-daemon-ctl -d .stack shutdown
aos-daemon-ctl -d .stack ls
aos-daemon-ctl -d .stack/procs/llm ls
```

```
daemon at ~/code/aos-tut/.stack stopped (ctl seq 2); 5 procs asleep, they wake when it starts again
_clock	sleeping	-	143	-	-
_sweeper	sleeping	-	143	-	-
llm	sleeping	-	143	-	-
ann	sleeping	-	143	~/code/aos-tut	-
bob	sleeping	-	143	~/code/aos-tut	-
# daemon: not running (pid 803028 is gone); the table above is what it left
# root daemon (no supervisor)
_sweeper	sleeping	-	143	-	-
# daemon: not running (pid 809562 is gone); the table above is what it left
# supervisor ~/code/aos-tut/.stack/: sleeping
```

kernel 掛在板子上，所以一句全關；明天視窗 A 再 `aos-exec root`，五個全醒、記憶都在。不要了就整夾刪掉：

```sh
cd ~ && rm -rf ~/code/aos-tut
```

板子先關再刪：板子開著時刪，跑著的行程會找不到自己的檔。
