- **P-35 格可以是一整隻 agent，不可以是別人 fsm 的一次；10 只有 idle 退。** 當工具的 agent 入口一定是它自己的 loop（P-05），被叫一次就從現在的 state 跑到它的 idle 退 10 為止才回來；它的 loop 收到 10 退 0，所以呼叫它的格看到的是 0，上層的 loop 不會被誤停——cathy 的 10 到不了 bob。**不要**把另一隻 agent 的 `fsm.json` 直接拿來當自己的一格（`{"argv": ["aos-fsm", "tools/cathy/fsm.json"]}`）：那一次她退 0 只代表「她走了一格」，你的 fsm 卻會換狀態、她還沒做完；她退 10 又會把你的 loop 停掉。fsm 只看結束碼，沒有「內層還沒完」的回報（不做階層式 fsm）——要巢狀就整隻叫。格叫工具時**工具的非 0 一律當失敗、自己 `exit 1`**（`|| { echo "act: cathy 失敗" >&2; exit 1; }`），不把工具的碼原樣 `exit`——工具若退 10 會被 fsm→loop 當成「停」。（P-19；P-21 誰的錯誰講；C-52 上層不知道下層是 fsm；N-53 整隻 agent 由自己的 loop 驅動；ideas § 9 第 4 條）
  - **10-30 加註：接住的 10 到不了 loop**（使用者 10-30「都照建議」，[thinking 10-30 aos-round](../../../thinking/2026-10/30/aos-round/07-決定.md#決定10-30) 衝突 2）：「10 只有 idle 退」是字串 `next` 那種表的慣例；物件 `next`（N-36）的表上，任何一格的 10 都可以被接住（aos-round 的 think 退 10＝該交卷、act 退 10＝插話），接住的 10 到不了 loop。「格叫工具時工具的非 0 一律當失敗、自己 exit 1」那半句不變。 **11-01 加註**（使用者 11-01 晚「aos round這東西還沒刪掉嗎」「這應該整個都不需要吧」，看完牽連範圍回「刪掉」，[thinking 11-01 playground-bob 03](../../../thinking/2026-11/01/playground-bob/03-旋鈕改-argv-與檔-實作.md)）：`aos-round` 已刪；agent 的 loop.json 直接叫 `aos-fsm`、指 lib/agent/round 的 `fsm-stop.json` 或 `fsm-idle.json`（stop／idle＝指哪張表，`--on-empty` 跟著沒了），五格從 `AOS_CD` 拿 agent 資料夾（`AOS_ROUND_AGENT` 拿掉）。本條提到 aos-round 的地方照這個讀，條文改不改由使用者定。 **11-04 加註**（round 已刪後的條文整理，使用者 11-04「照建議」，[收斂報告 § round 刪掉後](../../../../wf/workflows/tidy/reports/2026-11-03-收斂/03-round刪掉後的條文之一.md#round-刪掉後沒實作撐的條文11-04給使用者裁)）：例子「think 退 10＝該交卷、act 退 10＝插話」出自已刪的 aos-round；「接住的 10 到不了 loop」本身仍由 aos-fsm 的物件 `next` 撐著（同 N-43 的 10-30 加註）。 **11-04 加註**（loop／fsm agent，使用者 11-04 衝突 2 選「think 也退 10，條文加註」，[thinking 11-04 loop-fsm-agent](../../../thinking/2026-11/04/loop-fsm-agent/04-衝突與方向題.md#決定11-04使用者)）：現行的例子是 `demo/agent-fsm`：think 答完（腦沒叫工具）退 10＝沒東西了，表上 `"10": "idle"` 接住回 idle 等信；idle 退 10＝queue 空，範本表上接住＝停著等、改成字串 `next`＝10 到 loop＝收工（P-19 的 11-04 加註）。「格叫工具時工具的非 0 一律當失敗」照舊（agent-fsm 的 act 把工具的非 0 回給腦、自己不退那個碼）。
- **P-36 逾時打整棵子樹；外層包內層。** 單子起的程式自成一個行程群組（inst 的 C lib `new_session`，實作只有 impls 的 C++ 版，使用者「python版本可以刪掉了。aos-exec/loop/daemon都用C++」；aos-exec 行程內跑單子時當監工轉訊號，§ 20 預設「逾時整群殺」），逾時與轉來的 SIGINT／SIGTERM／SIGHUP 都打整個群組（`killpg`），grace 到了 SIGKILL 整個群組。只殺直接起的那一個不夠：格是 `#!/bin/sh` 時 sh 收到 SIGTERM 直接死、不轉給前景子程式，sh 底下的 `aos-exec tools/cathy`→cathy 的 loop→她的格會變孤兒繼續跑。中間沒隔單子的那幾層（sh 格、它起的 aos-exec）跟起它們的程式同一個群組，所以一刀下去整棵子樹一起收，下一層單子再轉給它自己的群組，層層往下。被殺的那格＝**失敗**（碼 128＋訊號；`trace.jsonl` 沒有 `timed_out`——fsm 看不到格裡有沒有逾時，C-52，看碼就知道，[計畫 10-21](../../../thinking/2026-10/21/plan/README.md) F4），上面照 P-20 停下來等人，不當正常收工。N-52「SIGTERM 退 0」作廢（使用者 10-19「都按照建議」，[ideas § 9、§ 11](../../../thinking/2026-10/19/ideas/README.md)）；它的後半句留作慣例：**收到 SIGTERM 的程式先收好自己起的子程式、寫好狀態再結束，但結束碼是非 0**（被殺就是失敗；使用者 10-16 原話：「重點在於"把該做的事情做一做後，才結束"」）。**loop／fsm 自己收到 SIGINT／SIGTERM／SIGHUP**（10-19 晚使用者「1.好。」，[ideas § 24](../../../thinking/2026-10/19/ideas/README.md)）：先轉給正在跑的那一次（字串 `exec`〔使用者：「exec，loop／daemon 的 run 也一起改
