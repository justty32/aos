- **P-36 逾時打整棵子樹；外層包內層。** 單子起的程式自成一個行程群組（inst 的 C lib `new_session`，實作只有 impls 的 C++ 版，使用者「python版本可以刪掉了。aos-exec/loop/daemon都用C++」；aos-exec 行程內跑單子時當監工轉訊號，§ 20 預設「逾時整群殺」），逾時與轉來的 SIGINT／SIGTERM／SIGHUP 都打整個群組（`killpg`），grace 到了 SIGKILL 整個群組。只殺直接起的那一個不夠：格是 `#!/bin/sh` 時 sh 收到 SIGTERM 直接死、不轉給前景子程式，sh 底下的 `aos-exec tools/cathy`→cathy 的 loop→她的格會變孤兒繼續跑。中間沒隔單子的那幾層（sh 格、它起的 aos-exec）跟起它們的程式同一個群組，所以一刀下去整棵子樹一起收，下一層單子再轉給它自己的群組，層層往下。被殺的那格＝**失敗**（碼 128＋訊號；fsm 看不到格裡有沒有逾時，C-52，看碼就知道，[計畫 10-21](../../../thinking/2026-10/21/plan/README.md) F4），上面照 P-20 停下來等人，不當正常收工。N-52「SIGTERM 退 0」作廢（使用者 10-19「都按照建議」，[ideas § 9、§ 11](../../../thinking/2026-10/19/ideas/README.md)）；它的後半句留作慣例：**收到 SIGTERM 的程式先收好自己起的子程式、寫好狀態再結束，但結束碼是非 0**（被殺就是失敗；使用者 10-16 原話：「重點在於"把該做的事情做一做後，才結束"」）。**loop／fsm 自己收到 SIGINT／SIGTERM／SIGHUP**（10-19 晚使用者「1.好。」，[ideas § 24](../../../thinking/2026-10/19/ideas/README.md)）：先轉給正在跑的那一次（字串 `exec`〔使用者：「exec，loop／daemon 的 run 也一起改 exec」「fsm.json，現在是用val，幫我改成exec」〕是那個 aos-exec 子行程；那次是單子時再轉給整群、過 `grace_ms` SIGKILL 整群；`exec` 直接放單子時 loop／fsm 在自己行程內照同一套跑，P-06），等它收好，**不起下一次**，以 128＋N（N＝第一個收到的訊號）結束；兩次之間收到＝不起下一次、直接 128＋N；fsm 被中斷時那格跑完**照常寫 state**（格退 0 就照樣換狀態），再以 128＋N 結束——就是上一句「先收好、寫好狀態、結束碼非 0」落在 loop／fsm 身上。SIGINT（人按 Ctrl-C）跟 SIGTERM 同一種處理（[NORMS 待定](../../NORMS/08-待定.md)「SIGINT 比照 SIGTERM」已結案）。寫法：逾時寫在最靠近會卡的那格（think 問腦 120 秒）；要包住整隻子 agent，呼叫它的格在 `fsm.json` 寫成 `{"exec": {"argv": ["aos-exec", "act"], "timeout_ms": …}, "next": …}`（或 `"exec": "fsm.json#/states/act/body"`、單子放 `body`，P-29）；**外層 ≥ 內層一圈各格逾時之和 × 內層 `max`**，不然外層會先殺人；`grace_ms` 外 ≥ 內（巢狀 grace 使用者 10-12 夜定「只當慣例、不進規範」：建議值也是程式預設——inst 2000、daemon 10000（收子 loop 時 SIGTERM 後等 10 秒才 SIGKILL）；外層宜大於內層；設錯自己負責）。aos 不替人算這個。代價：新群組沒有控制終端，格裡的程式不能去讀終端（agent 本來就不該，N-41）。（N-41 靠 `timeout_ms` 守；P-22；P-30 逾時收尾不留孫程式；C-52 每層只管自己直接起的；「巢狀 grace：外層宜大於內層」；N-52 作廢，見上）本條的訊號轉交、整群殺、128＋N 是 aos-exec、aos-loop、aos-fsm、aos-daemon 這幾支自己的行為，照 Unix 慣例；訊號不寫進 aos 標準，別的 aos 函數要怎麼處理訊號自己定（使用者 10-28「照你的建議，留著改口，JSONL 那半條刪掉」，[thinking 10-28 medium](../../../thinking/2026-10/28/medium/README.md)，見 N-43「適用範圍」）。**11-05 註（例外：daemon 的狀態窗寫不了）**：使用者裁 [edge-round2 題 warning: …`：不退出就不寫錯誤行，比照 stdio-unify 代定 D4〕、下一圈再寫、proc 照顧著（同身體失敗）；收工那份寫不了也照常結束。aos-loop、aos-fsm 照舊。
