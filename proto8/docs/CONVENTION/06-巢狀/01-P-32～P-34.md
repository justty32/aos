## 十二、巢狀：層層疊疊（10-19 第二輪）

使用者 § 10：「以後會是巢狀嵌入，層層疊疊，act 中所使用的工具可能又是另一個 agent-cathy，一層一層這樣。」底下每條都照同一把尺：**每一層只管自己這一層、同一條規則在每層重複**（C-52）。aos 本身仍然只管那幾個環境變數（§ 4；六個，§ 19），這一節全是慣例。

- **P-32 被叫者的工作區在呼叫方的小格裡。** 叫另一隻 agent 當工具，跟叫工具一樣先開小格 `sub=$AOS_STACK/tools/<名>/`（P-17）；它若需要自己的工作區（它自己的說明會說，例如 cathy 認 `new/` 一題一檔），工作區就是 **`$sub/ws/`**：呼叫方照它的說明在那裡備好題目、叫它、再從那裡拿答案。一行寫完：`AOS_STACK=$sub aos-exec --ws "$sub/ws" tools/<名>`（N-58）——**stack 與工作區兩個都明給**（`AOS_STACK` 已經有值，aos-exec 不會替巢狀給預設；只給工作區不給 stack，被叫者會把 `stage.txt`／`current.txt` 寫進呼叫方的 stack，把呼叫方的狀態機弄壞）。不需要工作區的工具（stamp 這種吃 stdin 吐 stdout 的）不給 `--ws`（沿用），只給 stack。被叫者沿用呼叫方的 `AOS_WS` 只有一種情況正當：它的說明說它就是要動呼叫方的工作區（C-66 工具拿指標改外部變數）。使用者的工作區因此只多出 bob 自己的 `out/`、`done/`，cathy 的題目與答案全在 `.stack/tools/cathy/ws/` 裡。**這不是「agent 之間走 inbox」的規則**：bob 寫 cathy 的 `new/` 是因為 cathy 的說明這樣寫（P-26 參數怎麼進由工具說明定）；換一隻吃 stdin 的 agent 就照它的。（§ 10；§ 9「inbox 先不管」；C-65 工作區只放使用者的東西、stack 放「叫工具時開的小格」；C-66；C-67 stack 放哪由呼叫方決定；C-52 被叫者不知道上面有誰；P-14 工作區其他東西不碰；P-17）
- **P-33 工具放在叫它的那一格的資料夾裡：`<格>/tools/<名>/`，格裡寫 `aos-exec tools/<名>`，永遠零個 `..`。** 相對路徑從 cwd 算，而格起跑時 cwd 就是格自己的資料夾（N-59），所以不管這格被埋在第幾層，路徑都一樣長、一樣對。bob 的 act 叫 `tools/cathy`，cathy 的 act 叫 `tools/stamp`——`agent-bob/act/tools/cathy/act/tools/stamp/` 這條路徑就是呼叫鏈本身（P-38）。內嵌單子格（think）的 cwd 是 agent 資料夾，它若要工具就是 agent 根下的 `tools/<名>`，同一條規則。**不給程式根變數**（aos 只訂那幾個變數，§ 4；而且 aos-exec 對每一格都是「一個資料夾程式」，不知道哪一層算「agent 的根」。`AOS_CD` 不是程式根：它是**這一格**自己的資料夾、每層覆寫，bob 的 act 格看到的是 `act/`，用途是 cd 走之後找回自己，例 `cd "$AOS_WS" && … && aos-exec "$AOS_CD/tools/stamp"`）；**不用 PATH**（C-61）。幾格共用一個工具、幾隻 agent 共用一隻 cathy：複製一份（demo 的做法，P-25 不跨 agent 互指），或在自己的 `tools/` 放一條捷徑指過去（C-61「相對捷徑、兩份一起搬也不斷」；Linux 才有，§ 9 先只考慮 Linux。本 repo 在 Windows checkout，所以 demo 不 commit 捷徑）。（C-61 地址在自己資料夾裡、不用 PATH；N-50；C-56 KISS；§ 4）
  - **10-28 例外：round 與每一格拿 agent 資料夾的絕對路徑當第一個參數**（使用者 10-28「照新做法」，[thinking 10-28 agent-ops 決定 11](../../../thinking/2026-10/28/agent-ops/02-決定.md#決定10-28)；細節照原則代定、可翻案，[agent-round § 1 佈局](../../../thinking/2026-10/28/agent-round/01-白話版.md#1-佈局)）：照 round 拆成格的 agent，`loop.json` 用 `{"$env": "AOS_CD"}` 把 agent 資料夾給 round，round 再原樣當第一個參數給每一格與掛勾（`aos-exec <格> <agent 資料夾> [子命令]`）。理由：aos-exec 解開捷徑後 cwd 是共用件（庫）那邊，共用件靠 cwd 找不到引用它的 agent 的其他格，所以用參數明給。這跟 `aos-fsm fsm.json`「設定檔是唯一的位置參數」、`"_entry": ["aos-fsm", {"$env": "AOS_CF"}]` 同一種——**是參數、不是環境變數**，aos 保證的變數照舊只有那六個。沒照 round 拆格的 agent 照本條「不給程式根變數」。 **11-04 加註**（round 已刪後的條文整理，使用者 11-04「照建議」，[收斂報告 § round 刪掉後](../../../../wf/workflows/tidy/reports/2026-11-03-收斂/03-round刪掉後的條文之一.md#round-刪掉後沒實作撐的條文11-04給使用者裁)）：round 那套（round 與它叫的各格、掛勾）已刪，本條字面講的已無實作；同一手法（`loop.json` 用 `{"$env": "AOS_CD"}` 把 agent 資料夾當參數明給）aos-eca-turn 在用（templates/eca-claude 的 loop.json），本條不改寫成一般說法。
- **P-34 小格不收、不清，連叫也用同一個；要全新就換名。** 第二題再叫 cathy 時，她的小格裡還有上一題的 `current.txt`、`plan.txt`、`ws/done/`——這是正常的：標準範本正常結束時 state 停在 `idle`（P-08），所以她從頭開始，`current.txt`／`plan.txt` 被新題蓋掉、`done/` 累積給人看。她若上次**失敗**停在半路（state＝`act`），呼叫方修好後再叫，她正是從那格接著做——這就是 P-20 要的。所以呼叫方**不在開工前 `rm`**（那會把 P-20 的接續抹掉）、**不用題名開新小格**（小格會跟著題目長、stack 樹不再等於呼叫樹）。真要全新：呼叫方給另一個小格名或自己 `rm`（C-67 呼叫方的自由）。被叫者的義務只有一條：**正常結束時自己的 stack 要停在起點**。（P-17 叫完不自動收；P-20 失敗停下、修好接著做；P-08；C-65「續聊＝同一個 stack 再跑，要忘記＝換一個」；C-67；拍板點 3 人來看）
