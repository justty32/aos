- **P-37 不設深度上限、沒有人管遞迴。** 照 P-33 工具在呼叫者自己的資料夾裡、不用捷徑時，「cathy 又叫 bob」根本寫不出來（bob 不在 cathy 底下）；寫得出來的只有捷徑或絕對路徑，那是設計者自己選的。真遞迴下去，每層小格路徑多一段，撞到路徑長度上限時 `mkdir` 失敗、aos-exec 退 1、一路失敗往上停；或被最外層的 `timeout_ms` 一刀收掉（P-36）。不加深度計數、不加環境變數數層。（N-39「表裡的格指回自己（遞迴）fsm 不擋，卡死不防護」；C-53 誤用不歸組件管；C-56 不為邊緣狀況加機制）
- **P-38 stack 樹＝呼叫樹＝tools 資料夾樹；看全貌就看那棵樹。** 每層照 P-17 在 `tools/` 底下用工具名開小格，所以 `$AOS_STACK` 底下長出來的就是這次誰叫了誰：`.stack/{stage.txt,tools/cathy/{stage.txt,ws/,tools/stamp/runs.txt}}`。看法：`tree -a "$AOS_STACK"`。不另做彙整工具。（拍板點 3 人來看；C-54 結構本身就是說明；C-56；fsm 不寫 trace：使用者 11-03「整個拿掉」，[thinking 11-03 trace](../../../thinking/2026-11/03/trace.md)，N-39）
- **P-39 往下只流環境變數，別的都明給。** 六個變數分三類（§ 19 使用者「同意做」，分類是 fable 擬的）：**叫別人時明給**——`AOS_WS`、`AOS_STACK` 每次叫別人都明寫（P-32）；**一路繼承**——`AOS_ENTRY`、`AOS_BRAIN_*` 整棵樹一致，所以**巢狀裡的 agent 不改 `AOS_ENTRY`**（上面改了名，底下每一格都要跟著有那個檔），demo 全用預設 `_entry`，腦要換端點就在叫它那一行覆寫；**每層覆寫**——`AOS_CF`、`AOS_CD`、`AOS_CO` 由 aos-exec 每次呼叫重設（N-57），每層看到自己的、不用管也不該改，要往下傳自己的位置就拿它的值明給（例 `aos-exec "$AOS_CD/tools/stamp"`）。stdin 一路繼承到最底層，所以**agent 類工具不讀 stdin**（會卡在終端上），要餵東西就 `<` 明給（stamp 那種）。stderr 一路繼承，每層出錯只說自己一行（P-21），三層就是三行、由下往上，人看得出是哪層。`PATH`：**aos 的程式（aos-exec、aos-loop、aos-fsm）一律不動 PATH，原樣傳下去**；入口、格、`exec`（loop.json 的那格）裡要叫 `aos-exec`、`aos-fsm` 這些，由呼叫者自己讓它們在 PATH 上（10-19 晚使用者對 loop／fsm 說「2.不要主動加」、對 aos-exec 說「也套用，都不動path吧」，[ideas § 24](../../../thinking/2026-10/19/ideas/README.md)、N-59）。**`.env`**（[N-59](../../NORMS/10-基礎設施-定義與工作區/03-N-59.md) 第 4 件，[ideas 10-21 § 4](../../../thinking/2026-10/21/ideas/02-4-aos-exec-支援-env.md#4-aos-exec-支援-env10-21)）：aos-exec cd 進入口資料夾後讀那裡的 `.env`；預設不蓋，優先順序 旗標 ＞ 原本的環境變數 ＞ `.env` ＞ 預設，繼承來的與 aos-exec 剛設的都改不了；被叫的那一跳加 `--dotenv-override` 時是 旗標 ＞ `.env` ＞ 原本的 ＞ 預設，上面三類每一類都可能被被叫者自己的 `.env` 改掉（[N-58](../../NORMS/10-基礎設施-定義與工作區/02-N-58.md)、[ideas 10-22 § 3](../../../thinking/2026-10/22/ideas/02-3-env-基礎子集與---dotenv-ove.md#3-env-基礎子集與---dotenv-override10-22)；什麼都能設、風險自擔，使用者「2.可以，全都可以，不限制，風險自己擔。」）；`.env` 裡設的 PATH 是使用者自己寫的，aos 的程式仍不主動加 PATH。叫它那一行設的換腦變數會被 `.env` 蓋掉，使用者「先不管」、10-21 晚「換腦這塊不管，也不用待定，之後做到那邊的時候會改。」（不列待定）。（§ 4 aos 只訂環境變數；§ 19；N-55 環境變數自然往下傳；P-21；C-53）
- **P-40 JSON 入口怎麼寫（aos-exec 適用）**：單子或 argv 陣列當入口時，寫成**沒 `+x` 的 JSON 檔**（`_entry.json`，或資料夾裡沒 `+x` 的 `_entry`、或 JSON 裡的 `js["_entry"]`），**不寫 shebang、不設 `+x`**（aos-exec 看到 `+x` 就 exec、不讀內容——`+x` 的 JSON 檔沒 `#!` 會被交給 `/bin/sh` 跑、當然跑不動，§ 22；沒 `+x` 才當 JSON 讀，第一行 `#!` 只是被跳過、留著會誤導人）。**不要**寫成 `#!/usr/bin/env aos-exec` 再 `chmod +x`：`+x` 的檔 aos-exec 會再 exec 它、kernel 再叫 aos-exec……原地無限 exec，aos-exec 照 P-37 不讀 `+x` 檔的內容去擋。`js[$AOS_ENTRY]` 寫字串時指的是**另一個入口**（資料夾、檔、`檔#/指標`），不是 loop／fsm 的設定（§ 18 ① 使用者「確實要改寫例子」：要跑 loop 就寫 `"_entry": ["aos-loop", "loop.json"]`）。單子只認 [aos-exec 的 inst 單子](../../../impls/aos-exec/docs/03-環境變數.md#inst-單子) 列的 key、其他忽略（§ 20 預設）；單子沒寫的串流接呼叫者的。**argv 陣列裡可以放 `$env`、`$ref`**（N-45）；**argv[0] 寫別的資料夾程式**（資料夾、JSON 檔、`檔#/指標`）＝等同前面插 `aos-exec`，第二個元素起都是 args；要換工作區寫 `["aos-exec", "--ws", WS, "tools/stamp", "a"]`（N-58）（N-61；10-20 使用者，見 [ideas](../../../thinking/2026-10/20/ideas.md) D2、D3、D5、D8）。（§ 14、§ 17、§ 18、§ 20；C-73、N-61；計畫 v2 衝突 6 的預設，使用者沒異議）
