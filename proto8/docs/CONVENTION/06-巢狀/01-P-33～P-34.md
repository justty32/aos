## 十二、巢狀：層層疊疊（10-19 第二輪）

使用者 § 10：「以後會是巢狀嵌入，層層疊疊，act 中所使用的工具可能又是另一個 agent-cathy，一層一層這樣。」底下每條都照同一把尺：**每一層只管自己這一層、同一條規則在每層重複**（C-52）。aos 本身仍然只管那幾個環境變數（§ 4；六個，§ 19），這一節全是慣例。

- **P-32 已移除**（使用者 11-06「移除P-32」：被叫者沒給工作區就沿用呼叫方的 `AOS_WS`，跟 C-42 一致；編號不回收。記錄處：[special-cases 裁定](../../../thinking/2026-11/06/special-cases/README.md#使用者裁定11-06選項框)）。
- **P-33** 本條講的是**沒經 `tools.json`** 的叫法（C-61）；標準範本 agent-fsm 的工具走登記檔，見 P-41（使用者 11-13「cv-P33:B」，[convention-vs-agent-fsm](../../../thinking/2026-11/13/convention-vs-agent-fsm.md)）。**工具放在叫它的那一格的資料夾裡：`<格>/tools/<名>/`，格裡寫 `aos-exec tools/<名>`，永遠零個 `..`。** 相對路徑從 cwd 算，而格起跑時 cwd 就是格自己的資料夾（N-59），所以不管這格被埋在第幾層，路徑都一樣長、一樣對。內嵌單子格（think）的 cwd 是 agent 資料夾，它若要工具就是 agent 根下的 `tools/<名>`，同一條規則。**不給程式根變數**（aos 只訂那幾個變數，§ 4；而且 aos-exec 對每一格都是「一個資料夾程式」，不知道哪一層算「agent 的根」。`AOS_CD` 不是程式根：它是**這一格**自己的資料夾、每層覆寫，bob 的 act 格看到的是 `act/`，用途是 cd 走之後找回自己，例 `cd "$AOS_WS" && … && aos-exec "$AOS_CD/tools/stamp"`）；**不用 PATH**（C-61）。幾格共用一個工具、幾隻 agent 共用一隻 cathy：共用的收進函式庫 `proto8/lib/`（C-61），在自己的 `tools/` 放一條捷徑指過去（C-61「相對捷徑、兩份一起搬也不斷」；Linux 才有，§ 9 先只考慮 Linux），或登記進 `tools.json`；同名自己的贏；要釘版、要改寫才複製一份（複製＝自己維護，版本＝git；使用者 11-12 裁 Q16「a」）。（C-61 地址在自己資料夾裡、不用 PATH；N-50；C-56 KISS；§ 4）
  - **例外：共用件拿 agent 資料夾的絕對路徑當參數**（[thinking 10-28 agent-ops 決定 11](../../../thinking/2026-10/28/agent-ops/02-決定.md#決定10-28)）：格或指令收在共用處（庫、命令列）時，aos-exec 解開捷徑後 cwd 在共用件那邊，靠 cwd 找不到引用它的 agent，所以 `loop.json` 用 `{"$env": "AOS_CD"}` 把 agent 資料夾當參數明給（例 templates/agents/eca-claude 的 `loop.json` 給 `aos-eca-turn`）。這跟 `aos-fsm fsm.json`「設定檔是唯一的位置參數」、`"_entry": ["aos-fsm", {"$env": "AOS_CF"}]` 同一種——**是參數、不是環境變數**，aos 保證的變數照舊只有那六個。其餘照本條「不給程式根變數」。（使用者 11-14 專區答「P33:clear」，reply cee70afc742361ba；取代 11-04「round 那批條文原字不動」）

  例（P-33）：bob 的 act 格叫 `tools/cathy`，cathy 的 act 格叫 `tools/stamp`——`<bob 的資料夾>/act/tools/cathy/act/tools/stamp/` 這條路徑就是呼叫鏈本身（P-38）。

- **P-34** 本條講的是**跑完就退**的 agent（同 P-35 的界定）；標準範本 agent-fsm 是常駐的，把它當工具的做法見 P-41（使用者 11-13 收工待裁頁 W23「三件都對齊」）。**小格不收、不清，連叫也用同一個；要全新就換名。** 第二題再叫 cathy（照 agent-fsm 範本做、idle 的 `next` 改成字串的那種，P-35）時，她的小格裡還有上一題的 `stage.txt`、`history.jsonl`、`think/request.json`——這是正常的：標準範本正常結束時 state 停在 `idle`（P-08；agent-fsm 的表上 think、act 退 10 都回 `idle`），所以她從頭開始收新信，`think/request.json` 被新請求蓋掉、`history.jsonl` 接著往下長給人看。她若上次**失敗**停在半路（state＝`act`），呼叫方修好後再叫，她正是從那格接著做——這就是 P-20 要的。所以呼叫方**不在開工前 `rm`**（那會把 P-20 的接續抹掉）、**不用題名開新小格**（小格會跟著題目長、stack 樹不再等於呼叫樹）。真要全新：呼叫方給另一個小格名或自己 `rm`（C-67 呼叫方的自由）。被叫者的義務只有一條：**正常結束時自己的 stack 要停在起點**。（P-17 叫完不自動收；P-20 失敗停下、修好接著做；P-08；C-65「續聊＝同一個 stack 再跑，要忘記＝換一個」；C-67；拍板點 3 人來看）
