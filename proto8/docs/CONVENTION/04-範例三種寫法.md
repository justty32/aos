### 範例：同一隻 agent 的三種寫法

**標準寫法（[templates/agent-fsm](../../templates/README.md#agent-fsm) 的 `fsm.json`，整份照抄）**——表一份、四格都是單子，各指範本資料夾裡的一支 python；零子資料夾：

```json
{"_entry": ["aos-fsm", {"$env": "AOS_CF"}],
 "start": "idle",
 "states": {
   "idle":  {"exec": {"argv": ["python3", "idle.py"]},
             "next": {"0": "think", "10": "idle"}},
   "think": {"exec": {"argv": ["python3", "brain.py"]},
             "next": {"0": "wait", "10": "idle"}},
   "wait":  {"exec": {"argv": ["python3", "wait.py"]},
             "next": {"0": "act", "10": "wait", "11": "think"}},
   "act":   {"exec": {"argv": ["python3", "act.py"], "timeout_ms": 1800000},
             "next": {"0": "think", "10": "idle"}}}}
```

格寫成 `{"exec", "next"}` 照 N-36（使用者：「fsm.json，現在是用val，幫我改成exec」，[thinking](../../thinking/2026-10/23/naming.md)）；四格的單子直接放在 `exec`（P-07，[thinking 10-24](../../thinking/2026-10/24/exec-relative/01-使用者原文.md#10-24-exec-直接放單子)），fsm 在自己行程內跑，所以格這一層零 `aos-exec`。`next` 是照結束碼分岔的物件（N-36、P-35）：idle 沒信退 10＝留在 idle 等；think、act 退 10＝沒事做、回 idle；wait 退 10＝回信還沒到、留在 wait，退 11＝回 think 重組請求。`_entry` 讓 fsm.json 本身成為 aos-exec 的入口，所以 `loop.json` 寫 `"exec": "fsm.json"` 就好（fsm 讀表時不理 `_entry`、`body`，C-48）。同一夾的另外三個入口檔：

```json
{"argv": ["aos-agent", "ctl", "add", {"$env": "AOS_CD"}], "cwd": {"$env": "AOS_WS"}}
```

（`_entry`，沒 `+x`：`aos-exec` 這個資料夾＝把這隻掛上 daemon）

```json
["aos-loop", "loop.json"]
```

（`body.json`：掛上去之後 daemon 跑的身體）

```json
{"exec": "fsm.json", "interval_ms": 300, "ctl": "ctl.json", "state": "state.json", "state_flux": "state_flux.json", "on_start": …, "on_stop": …}
```

（`loop.json` 節錄：省掉 `description` 與 `on_start`／`on_stop` 的單子；沒寫 `max`）

收信、組請求、寄與收、跑工具這種動態的事由 `idle.py`、`brain.py`、`wait.py`、`act.py` 做，單子是靜態資料，只負責「跑誰、多久逾時」（只有 act 那格寫了 `timeout_ms`）。不經 daemon、手動一拍一拍跑也行，每次 `aos-exec fsm.json` 走一格（空工作區、`AOS_HOME` 指到 proto8、沒有時鐘；第一拍 stderr 另有兩行 `agent-fsm: warning: hook … is not checked: AOS_CLOCK is not set …`）：

```
$ aos-exec --ws ws --stack stack/ $AOS_HOME/templates/agent-fsm/fsm.json; cat stack/stage.txt
idle
$ echo '{"role": "user", "content": "hello"}' | aos-post send stack/queue
01794536865892524833.641708.805623
$ aos-exec --ws ws --stack stack/ $AOS_HOME/templates/agent-fsm/fsm.json; cat stack/stage.txt
think
$ aos-exec --ws ws --stack stack/ $AOS_HOME/templates/agent-fsm/fsm.json; cat stack/stage.txt
wait
$ cat stack/history.jsonl
{"role": "user", "content": "hello"}
```

三拍都退 0：第一拍 queue 空，idle 退 10 被表接住、留在 `idle`；第二拍 idle 把信收進 `history.jsonl`；第三拍 think 寫好 `stack/think/request.json`。再下一拍 wait 才會寄給 llm kernel。

**加資料夾格（混合）**——某一格要用 shell 寫邏輯時，那格的 `exec` 改寫子資料夾名（`"exec": "act"`，身體是 `act/_entry`），其他格照舊是單子、表還是那一份（P-27、P-09）。agent-fsm 沒有這種格。

**全 shell（對照）**——`loop.json` 是 `{"exec": "fsm"}`（使用者：「exec，loop／daemon 的 run 也一起改 exec」，[thinking](../../thinking/2026-10/23/naming.md)），`fsm/_entry` 自己讀 state、`aos-exec "$state"`、`case` 換狀態，每格是 `fsm/<格>/_entry`。沒有逾時；表藏在 `case` 裡。想完全不碰 JSON 時可以這樣寫，state 檔同格式、跟 aos-fsm 可互換（P-07）。下面這份的表跟上面 agent-fsm 的 `fsm.json` 同一張（沒有現成範本；拿四個只退指定碼的假格跑過，換狀態與結束碼都跟表一樣）：

```sh
#!/bin/sh
# fsm/_entry：一次跑一格，照格的結束碼換狀態
state=$(cat "$AOS_STACK/stage.txt" 2>/dev/null || echo idle)
aos-exec "$state"; code=$?
case $state:$code in
  idle:0) next=think;; think:0) next=wait;; wait:0) next=act;; act:0) next=think;;
  idle:10|think:10|act:10) next=idle;; wait:10) next=wait;; wait:11) next=think;;
  *) exit $code;;
esac
echo $next > "$AOS_STACK/stage.txt"
```

三種的 stack 長相一樣（`stage.txt`、格自己寫的檔），人看的地方不變。範本各格的程式每隻 agent 複製一份，不跨 agent 互指（P-27、P-33）。
