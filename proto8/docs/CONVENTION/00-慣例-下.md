## 停與錯

**[六、停與錯](02-題目stack停錯腦/04-五-stack與六-停與錯.md)**（[P-21、P-22](02-題目stack停錯腦/04-六-停與錯續-P-21～P-22.md)）
- **P-19** 結束碼三種：`0`＝這次好了、下一次；`10`＝正常停、沒東西了；表上明寫接住的碼（如 wait 的 11）＝分岔；沒列在表上的其他非 0 才是失敗。物件 `next` 的表上別格也能退 10、由表接住；loop 收到 10 以 0 結束、其他非 0 以那個碼結束，跑滿 `max` 以 0 結束。
- **P-20** 任一格失敗＝整隻停下等人（fsm 不換狀態、loop 以那個碼結束），修好再跑就從 `stage.txt` 接著做同一格、同一題；不自動重試，開了 `--auto-restart` 的才照失敗後冷卻重試。這是表上沒接住那個碼時的預設；例外：daemon 的身體失敗記一行、下一圈再跑，kernel 不在＝等它、不停，等回信沒有期限。
- **P-21** 誰的錯誰自己講：格的錯寫在格自己的 stderr，fsm 不轉述，loop 只說「第幾次、誰、結束碼幾」；那一行是錯誤行 `程式: error: 代號 原因` 或提醒行 `程式: warning: 句子`。這是範本、lib、aos-loop／fsm 自己的約定，不是 aos 函數都要守。
- **P-22** shell 版的格沒人管逾時；要逾時就把那格換成 inst 單子、寫 `timeout_ms`，由 fsm 或 aos-exec 當監工收整群。

## 腦與工具

**[七、腦與工具](02-題目stack停錯腦/05-P-23～P-26.md)**
- **P-23** 腦＝寄一封請求信給 llm kernel、之後收回信（非同步，用基礎工具 `aos-llm`），問腦只走 kernel。端點、模型只在 kernel 的 `kernel.json`，agent 只知道能力包代號（定義 `llm.json` 的 `model`），換模型＝換代號；只取回覆的 `content`（與 `tool_calls`），想的內容不收，usage 不進 history。
- **P-24** 想跟做分開：think 問腦、只決定要做什麼；act 照 plan 動手、不問腦；能寫死的步驟放在程式格。
- **P-25** 工具＝子資料夾程式；沒經 `tools.json` 叫的放在叫它那格的資料夾 `tools/<名>/`、零個 `..`、不靠 PATH（P-33）；共用的收在 `proto8/lib/`、不各自複製；腦能叫的走登記檔 `tools.json`。
- **P-26** 工具的參數怎麼進由工具自己的說明定；aos-exec 保證 args 與 stdin 原樣送到，入口是單子時也成立。

**[P-41](02-題目stack停錯腦/06-P-41.md)、[P-47](02-題目stack停錯腦/09-P-47.md)**
- **P-41** 腦的工具呼叫：腦能叫的工具＝登記檔 `tools.json`，給模型看的說明在工具的 `_tooldef.json`；`arguments` 從 stdin 進、stdout 整段是結果，錯是一行錯誤行。對話是 `$AOS_STACK/history.jsonl`（一行一則 OpenAI message、只附加）；四格 idle 收信 → think 組請求 → wait 寄與收 → act 叫工具或交答案；給腦看的文字用英文。
- **P-47** 外部 MCP server 一台一份 server 檔，兩條路寫在哪走哪條、一台選一條：經 aos（`aos-mcp-import` 凍結成普通的 aos 工具）或 CLI 自己接（只有 eca，`cli.json` 的 `mcp_servers`）；金鑰只放使用者自己的 env 檔。

## shell 版與 inst 版

**[八、shell 版與 inst 版](03-shell版與inst版.md)**（[範例：三種寫法](04-範例三種寫法.md)）
- **P-27** 標準寫法就是 agent-fsm：狀態表一律寫在 `fsm.json`，每一格是一張單子、叫範本資料夾裡的一支程式檔（另一種可用寫法是資料夾格）；各格的程式每隻 agent 複製一份自己改，有第三份一樣的才抽進 lib。
- **P-28** inst 單子是可選的升級，可在同一個 agent 混用：(1) shebang 小殼叫 `aos-exec _entry.json`；(2) loop／fsm 的設定裡內嵌單子；(B) 任何沒 `+x` 的 JSON 檔都能當入口。(A) `#!/usr/bin/env aos-inst` 不能用（inst 是 C lib、沒有命令列）；單子只認 inst 單子列的 key，其他忽略。
- **P-29** 範本用 (2) 和 (B)；(1) 仍能用、不是範本。資料夾格要逾時，就在 `fsm.json` 把那格寫成帶 `timeout_ms` 的單子。
- **P-30** 用 inst 換到四樣：argv 是陣列；`timeout_ms` 逾時收尾、不留孫程式；結果是結構化的；單子是資料、可內嵌。
- **P-31** 單子要指到某個環境變數底下的檔，寫 `{"$env": 變數, "$path": 路徑}`（可加 `$prefix`），指函式庫用 `AOS_HOME`；範本的單子只用 `$env`、不寫 `$ref`；不用字串內插。

## 巢狀

**[十二、巢狀](06-巢狀/01-P-33～P-34.md)**（[P-35](06-巢狀/02-P-35～P-36.md)、[P-36](06-巢狀/02-P-36.md)、[P-37～P-40](06-巢狀/03-P-37～P-40.md)）
- **P-33** （沒經 `tools.json` 的叫法）工具放在叫它那格的資料夾 `<格>/tools/<名>/`、零個 `..`，路徑就是呼叫鏈；不給程式根變數、不用 PATH，共用的收進 `proto8/lib/`。例外：共用件要找引用它的 agent，由 `loop.json` 把 `{"$env": "AOS_CD"}` 當參數明給。
- **P-34** （跑完就退的 agent）小格不收、不清，連叫也用同一個，要全新就換名；被叫者正常結束時 stack 要停在起點；失敗停在半路的修好再叫就接著做。
- **P-35** （跑完就退的 agent）格可以是一整隻 agent、不可以是別人 fsm 的一次，10 只有 idle 退；格叫工具時工具的非 0 一律當失敗、自己 `exit 1`。物件 `next` 的表上任何格的 10 都能被接住、到不了 loop。
- **P-36** 逾時打整棵子樹、外層包內層：單子起的程式自成行程群組，逾時與訊號打整群，被殺的那格＝失敗；收到 SIGTERM 先收好子程式、寫好狀態再以非 0 結束（loop／fsm 不起下一次、以 128＋N）。外層逾時 ≥ 內層一圈各格逾時之和 × 內層 `max`（內層跑完就退時）、`grace_ms` 外 ≥ 內，aos 不替人算。
- **P-37** （沒經 `tools.json` 的叫法）不設深度上限、沒有人管遞迴；撞到路徑長度上限或最外層的 `timeout_ms` 自然停。
- **P-38** stack 樹＝呼叫樹（小格名＝登記名）；看全貌用 `tree -a "$AOS_STACK"`，不另做彙整工具。
- **P-39** 往下只流環境變數，別的都明給：`AOS_STACK` 每次叫別人都明給，`AOS_WS` 沒給就沿用呼叫方的；`AOS_ENTRY`、`AOS_LLM_KERNEL` 一路繼承；`AOS_CF`／`AOS_CD`／`AOS_CO` 每層覆寫。不讀繼承來的 stdin；aos 的程式不動 PATH；`.env` 預設不蓋原本的環境變數（`--dotenv-override` 才蓋）。
- **P-40** JSON 入口寫成沒 `+x` 的 JSON 檔，不寫 shebang（`#!/usr/bin/env aos-exec` 加 `+x` 會無限 exec）；`js[$AOS_ENTRY]` 寫字串＝指另一個入口；argv[0] 寫別的資料夾程式＝等同前面插 `aos-exec`。

## 命令列

**[十三、命令列：P-44](02-題目stack停錯腦/07-P-44.md)**（[旗標寫在哪](02-題目stack停錯腦/07-P-44續-11-10-旗標位置.md)、[P-45](02-題目stack停錯腦/08-P-45.md)）
- **P-44** 我們自己寫的程式照同一個命令列形狀（不要求別人守）：旗標寫在它那一層名字之後的任何位置，重複給＝最後一個算；錯是 `FlagUnknown`／`CommandUnknown`／`ArgumentsBad` 一行；每支都認 `--help`（英文、stdout、退 0）。給人用的指令照 unix 習慣：TAB 分欄、`--json`、列表預設短版、不可逆的問 `[y/N]`、有 `--yes`。
- **P-45** 純 aos 函數大多輸入走 stdin JSON，旗標只是補充：`--xxx yyy` → `"xxx":"yyy"`（`--a.b x` 巢狀），同鍵優先 旗標 ＞ stdin ＞ 環境變數；stdin 裡 schema 沒宣告的鍵＝`ArgumentsBad`。
