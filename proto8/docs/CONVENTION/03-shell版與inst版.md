## 八、shell 版與 inst 版

- **P-27** 標準範本的寫法，就是第二節 [templates/agent-fsm](../../templates/README.md#agent-fsm) 的樣子：入口 `_entry` 是沒 `+x` 的 JSON 單子（`aos-agent ctl add`，把這隻掛上 daemon，P-05），身體的入口 `body.json` 寫 `["aos-loop", "loop.json"]`；`loop.json` 寫 `"exec": "fsm.json"`（沒寫 `max`）、fsm.json 帶 `"_entry": ["aos-fsm", {"$env": "AOS_CF"}]`，每次就是 `aos-exec -- fsm.json`（[ideas 10-21 § 9](../../thinking/2026-10/21/ideas/05-7-審後的五個細縫與修正.md#9-設定檔是唯一的位置參數path-改字串拼接10-21-傍晚)；[計畫 10-21](../../thinking/2026-10/21/plan/README.md) F6）；**狀態表一律寫在 `fsm.json`**；**每一格是一張單子，叫範本資料夾裡的一支程式檔**（agent-fsm 是 python），單子直接寫在 `exec`：`"exec": {"argv": ["python3", "brain.py"]}`（[thinking 10-24](../../thinking/2026-10/24/exec-relative/01-使用者原文.md#10-24-exec-直接放單子)）——跑哪支程式、多久逾時寫在單子，邏輯寫在那支程式檔；agent-fsm 的四格都是這樣，沒有資料夾格。要頻繁改的東西（流程、逾時、誰接誰）全在一份 `fsm.json` 裡。另一種可用寫法是資料夾格：那格的 `exec` 寫子資料夾名、邏輯寫在子資料夾裡（例如 shell），不用把 shell 塞進 JSON。（§ 10 使用者「好主意」；格的寫法照範本＝使用者 11-13「cv-P27:A」，[convention-vs-agent-fsm](../../thinking/2026-11/13/convention-vs-agent-fsm.md)；拍板點 1；§ 7「想要簡單直接，那就上 shell 指令」「單子是資料……在不希望資料夾佈局太複雜的時候很好用」；`exec` 這個名字：使用者「exec，loop／daemon 的 run 也一起改 exec」「fsm.json，現在是用val，幫我改成exec」，[thinking](../../thinking/2026-10/23/naming.md)）agent-fsm 走 queue（P-11）（使用者 11-04「接下來是弄aos loop/fsm agent了」、看完規劃四題都選建議並說「記完就實作」，[thinking 11-04 loop-fsm-agent](../../thinking/2026-11/04/loop-fsm-agent/02-跟-eca-對照.md#條文要加的註實作時一起11-04-註條文原字不動)）。範本各格的程式（agent-fsm 的 idle.py、brain.py、wait.py、act.py）放在範本資料夾，每隻 agent 複製一份、自己改；有第三份一樣的才抽進 lib、範本改捷徑（使用者 11-04 選「放範本裡，每隻複製」，[loop-fsm-agent 裁定](../../thinking/2026-11/04/loop-fsm-agent/04-衝突與方向題.md#決定11-04使用者)）。
- **P-28** inst 單子（`{"argv", "cwd", "stdin", "stdout", "timeout_ms", …}`，key 表見 [aos-exec 的 inst 單子](../../impls/aos-exec/docs/03-環境變數.md#inst-單子)）是可選的升級，下面能用的寫法可以在同一個 agent 裡混用：
  - (1) `_entry` 是 shebang 小殼、讀旁邊的 `_entry.json`：`#!/bin/sh`＋`exec aos-exec _entry.json "$@"`。
  - (2) loop／fsm 的設定裡直接內嵌單子：`exec` 直接放單子物件，loop／fsm／daemon 在自己行程內用 aos-exec 跑單子的同一套跑（P-06、P-07；使用者「不過exec本來就應該要可以直接放內嵌單子吧」「好，就這樣做」，[thinking 10-24](../../thinking/2026-10/24/exec-relative/01-使用者原文.md#10-24-exec-直接放單子)）；或 `exec` 指到 `檔#/…/body`、單子放 `body`，由 aos-exec 跑。
  - (B) **任何沒 `+x` 的 JSON 檔**都能當入口（§ 14）：`_entry.json`（`$AOS_ENTRY.json`）、`aos-exec tool.json`、`aos-exec tool`（補找 `tool.json`，N-61）、`cfg.json#/tools/stamp`（N-62）、JSON 裡的 `js[$AOS_ENTRY]`（單子、argv 陣列、字串路徑，C-73）；第一行 `#!` 會被跳過。
  - (A) `_entry` 第一行 `#!/usr/bin/env aos-inst`、後面接 JSON 的 `+x` 入口**不能用**：沒有 `aos-inst` 命令列，inst 是 C lib（使用者：「aos-inst可以不用，inst和inst json格式，他就是一個C lib，也不提供cli」；10-22「對於python版，aos-inst指令可以刪掉了，跟C++版一樣做成lib就好。」；10-23「python版本可以刪掉了。aos-exec/loop/daemon都用C++」，[ideas 10-22](../../thinking/2026-10/22/ideas/README.md)）。同一個檔拿掉 `+x` 就是 (B)。

  單子只認 aos-exec 的 inst 單子列的 key（16 個，含 `id`、`envs_clear`、`cwd_mkdir`、`stdout_mkdir`、`stderr_mkdir`、`stderr_merge`：`cwd_mkdir` 先 `mkdir -p` cwd、`stderr_merge` 把 stderr 併進 stdout；使用者 11-04 題 9「aos-exec 補認那 7 個」，[four-elements 06](../../thinking/2026-11/04/four-elements/06-要使用者裁的題.md)、N-04），其他一律忽略、不報錯（§ 20 預設）。`+x` 但沒 `#!` 的檔，單子裡的 `argv[0]`、aos-exec 的可執行檔入口、argv 陣列入口三處一致，都改用 `/bin/sh` 跑（§ 21 使用者「不擋」〔單子那處〕；§ 22 使用者選「乙」〔三處都放〕，N-59 第 5 件）。（§ 7「1 跟 2 都要」「接法 3 感覺也是 OK 的」「AB 都可以」；§ 17、§ 20、§ 21）
- **P-29** 範本給的是 (2)：`fsm.json` 裡內嵌單子（agent-fsm 的四格，直接寫在 `exec`，[thinking 10-24](../../thinking/2026-10/24/exec-relative/01-使用者原文.md#10-24-exec-直接放單子)）（見下面範例）。(1)、(B) 仍都能用——一個資料夾格自己想用單子寫入口時用 (B)（把單子寫成沒 `+x` 的 `_entry.json`，P-40）——但不是範本。資料夾格要逾時，更直接的寫法是在 `fsm.json` 把那格寫成 `{"exec": {"argv": ["aos-exec", "act"], "timeout_ms": 600000}, "next": …}`，或 `{"exec": "fsm.json#/states/act/body", "body": {"argv": ["aos-exec", "act"], "timeout_ms": 600000}, "next": …}`（P-36）。（§ 10；§ 7「AB 都可以」；這是原討論稿拍板點 5 的答案）
- **P-30** 用 inst 換到的是四樣：argv 是陣列、不靠 sh 拼字串；`timeout_ms` 逾時收尾、不留孫程式；結果是結構化的（結束碼、訊號、有沒有逾時、毫秒）；單子是資料、可內嵌進別的 JSON。（§ 7 使用者「都還好。主要是單子是資料這塊……結果是結構化的這塊也很舒服」）impls 的 aos-exec 是 C++、單子在行程內交給 C lib 跑；`exec` 直接放單子時 loop／fsm／daemon 也在自己行程內跑（`run_inst`），省掉一層 aos-exec 子程式（[thinking 10-24](../../thinking/2026-10/24/exec-relative/01-使用者原文.md#10-24-exec-直接放單子)）。
- **P-31** 單子要指到 stack 或工作區底下的檔，寫 `{"$env": "AOS_STACK", "$path": "history.jsonl"}`：意思是「那個環境變數指的資料夾底下的 `history.jsonl`」，字串拼接、中間剛好一個 `/`（`AOS_STACK` 結尾有 `/`、`AOS_WS` 沒有，兩種都對；`$path` 寫絕對路徑也是接上去，`#` 開頭直接接，N-45、[ideas 10-21 § 9](../../thinking/2026-10/21/ideas/05-7-審後的五個細縫與修正.md#9-設定檔是唯一的位置參數path-改字串拼接10-21-傍晚)）。不帶 `$path` 就是整個變數值。`$prefix` 接在結果前面，`{"$env": "AOS_WS", "$path": "a.txt", "$prefix": "--file="}` → `--file=/ws/a.txt`；`$env`、`$ref` 都能帶，換出來不是字串就靜默不作用；不帶 `$` 的 `path` 沒有作用；指示詞的寫法寬容、不報錯（使用者「我希望那個path可以換成$path，然後添加$prefix」，N-45、[ideas](../../thinking/2026-10/20/ideas.md) D9～D15）。**範本只用 `$env`**；規範另有 `$ref`（`{"$ref": "檔"}`＝換成那份檔的整份內容，語意在 N-45；能取檔內位置 `{"$ref": "x.json#/a"}`；argv 陣列裡也能放 `$env`、`$ref`；[ideas](../../thinking/2026-10/20/ideas.md) D1、D2、D7、D8），但單子本來就能內嵌、不必拆檔，所以範本與 demo 不寫 `$ref`。變數沒設＝解單子那一層自己的錯、退 1。`$env` 在六個環境變數設好之後才解，所以單子裡也讀得到 `AOS_CF`、`AOS_CD`（N-45）。不用字串內插（`"$AOS_STACK/history.jsonl"`）：那是把規則埋進字串的暗規則。（本稿定；C-48／C-55 值長成物件、同層加屬性；C-56 寫什麼就做什麼；N-45 `$env` 是正式機制；`$ref` 保留＝使用者 10-19 晚「impls這塊，指示詞是OK的」，[ideas § 22](../../thinking/2026-10/19/ideas/README.md)）
