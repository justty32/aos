- **aos-eca-turn 一次替它答一批**（一批幾封無上限：使用者 11-03「每次aos-eca-turn就是把所有信一起丟進去(當然，是有順序的)」「一批幾封無上限」，[eca 17](../../../../thinking/2026-10/30/eca/17-11-03-批次-status.md)）：`queue/cur/` 裡認領了還沒交出去的，加上 `new/` 全部（`aos-post take-all`），照處理順序；無序的信排在這批最後、照樣答（N-16；使用者 11-03 晚「aos-post這塊都按照建議。」，[thinking 11-03 aos-post](../../../../thinking/2026-11/03/aos-post/README.md)）。`body` 不是 `{"role": "user", "content": 非空字串}`＝壞信，收掉（`aos-post done`）、`$AOS_STACK/mailbox_warning.txt` 記一行（名字 11-02 晚使用者「要」）；`body` 可以多帶選填的 `name`＝寄件人（`aos-agent say`／`chat` 對 eca 說話時填：`--from` ＞ 下指令的那隻 agent ＞ 登入名），只當投收件口時的署名、不接進 history。好信照順序交給 CLI（畫面開著：claude 身投進 CLI 的收件口、投不進去才貼進畫面，codex 身貼進畫面；沒開就 `--resume`），**交給 CLI 就算完成**：題目交給 CLI 的那一刻（非互動＝CLI 起來、題目寫進去；畫面＝寫進收件口成功，或貼上按 Enter）、等回答之前，把這批每封各接一則 user 進 history、收信（`aos-post done`），CLI 答完才接一則 assistant；不寫 `current.txt`。CLI 中途掛掉（`CliFailed`、`ReplyMissing`、被殺）是邊緣狀況，信已經收了、不自動重答，要重答由人再 say（P-12 在 eca 的例外）；還沒交出去的（`--on-busy yield` 退讓、CLI 起不來）信留 `cur/`、history 不動，下一輪照答。CLI 找不到原本那段對話（換台、換工作區、被重起）＝開新對話，開場用 aos 自己記的 history 整理成一段帶進去，換台本身不掉信（使用者 11-10 選項框裁定 4，[two-machines](../../../../thinking/2026-11/10/two-machines/README.md#使用者裁定11-10-上午選項框快裁大修時可重看) 裁定 4）。（使用者 11-03「對於eca來說，他收到信後，丟給claude之類的，然後這封信就算是完成了」「中途掛掉就是邊緣狀況，不要讓邊緣狀況影響他的原本意思」，[eca 20](../../../../thinking/2026-10/30/eca/20-11-03-交出去就收.md)）
- **queue 空與開場白**：queue 空照 argv `--on-empty stop|idle`（沒給＝`stop`）退 10 或 0（P-42「跑完要不要結束寫在定義裡」；使用者 10-31「然後那個信箱空了怎麼辦那個環境變數和我希望可以改成argv」，是 C-51「再靈活一些，可以用上環境變數或argv指定」的應用）。開場白檔由 `loop.json` 叫 aos-eca-turn 時的旗標 `--prompt FILE` 給（相對路徑從定義資料夾算；指的不是檔＝`PromptMissing`）；沒給＝沒有開場白，不找 `prompt.txt`，`cli.json` 不指開場白。history 與 queue 都空、有開場白＝先把它當第一則 user 投進 queue 再答（射後不理的開法）。（使用者 11-04 先問「他仍然是吃固定的prompt.txt對吧，能改嗎？可以的話就改吧。」、同天「那我覺得不該在json中指定檔案名稱，應該改成用旗標指定，或是吃stdin，你覺得呢」「按你建議。」，[eca 21](../../../../thinking/2026-10/30/eca/21-11-04-開場白檔可指定.md)）
