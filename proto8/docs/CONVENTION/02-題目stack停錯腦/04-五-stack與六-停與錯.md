## 五、stack

- **P-15** 執行中的一切（狀態、草稿、紀錄、小格）只寫 `$AOS_STACK`，**定義資料夾不被寫**；所以同一個 agent 可以同時被兩個工作區跑。`aos-agent tools`／`llm` 改的是那一隻 stack 裡的副本（`$AOS_STACK/tools.json`、`$AOS_STACK/llm.json`；之後不跟定義變，`reset` 刪副本），定義照樣不被寫；改定義是人有意的事、不是執行中寫：工具用 `aos-tools`，腦設定直接 `aos-json set <定義>/llm.json#/鍵 值`（`aos-agent llm show／set／reset` 是讀定義 `llm.json` 疊 `<stack>/llm.json`、`aos-json set` 寫副本、刪副本的語法糖，P-43（續））。**11-04 晚已改**（使用者 11-04 晚「然後aos llm,tool這兩個，我希望他們的定位是跟aos post一樣，作為基礎工具」，[thinking 11-04 think-as-function](../../../thinking/2026-11/04/think-as-function/README.md) 衝突 1 照推薦 (a)，隊長先實作、可翻案）：原本改定義裡的腦用 Python 的 `aos-llm`（經每隻的 `llm/` 入口程式）；現在 `aos-llm` 是寄信收信的基礎工具（P-23），Python 那支刪了。（C-65；§ 2；原型測試已驗；副本：使用者 11-04 晚「改副本。改定義那塊用aos-tools」「aos-agent llm改正在跑著的，aos-llm改定義」「不跟。風險自行處理。但我們可以給reset。」，[thinking 11-04 aos-agent 03/01](../../../thinking/2026-11/04/aos-agent/03-種類與契約/01-tools-llm-與兩個範本要改什麼.md)）
- **P-16** agent 自己的格（idle／think／act）共用同一個 `$AOS_STACK`——它們是同一台狀態機。stack 裡放什麼、叫什麼，agent 自訂；agent-bob〔11-04 已刪，例子照留〕的 `stage.txt`、`current.txt`、`plan.txt` 是例子不是規範。（拍板點 1「stack 內部自由」；§ 2「剩下的你自己想」；§ 3）
- **P-17** 叫**別的**資料夾程式（工具、另一個 agent）時，給它自己的 stack（**小格**）：`sub=$AOS_STACK/tools/<名>/`、`AOS_STACK=$sub aos-exec tools/<名>`（例：cathy 的 act 用 `AOS_STACK=$sub aos-exec tools/stamp`，工具的 `runs.txt` 落在 `$AOS_STACK/tools/stamp/`）。小格名＝工具資料夾名（P-38 靠這點）。小格放在 `tools/` 底下，呼叫方給的名字跟格自己的固定名分開命名空間；`tools` 是 stack 頂層的保留名（格自己不能在 stack 頂層放叫 `tools` 的固定東西）（使用者 11-02「未來，搞不好會出現agent+kernel的變體，.stack底下會有一大堆東西。擋名字會擋不過來。所以我覺得最好還是tools/<name>更好」，[thinking 11-02 stack-tools](../../../thinking/2026-11/02/stack-tools/README.md)）。被叫的只看到自己的 stack、不知道上面有誰。叫完不自動收——留著給人看；要收由呼叫方自己 `rm`。巢狀時小格怎麼給、被叫者的工作區放哪，見第十二節 P-32。（§ 3「子程式的 stack 由 agent-bob 自己訂，有可能他會是 AOS_STACK/think, /act」；C-52 子 agent 只看自己的 stack；C-65 stack＝「叫工具時開的小格」；C-67 stack 放哪由呼叫方決定；拍板點 3「人來看」。這是原討論稿拍板點 4 的答案）
- **P-18** 一個工作區同時跑兩個 agent 時，呼叫方給不同的 `AOS_STACK`（例 `$AOS_WS/.stack/bob/`）；預設值只保證「一個工作區一個 agent」不撞。（C-67；C-53 入口默認正常、誤用不歸組件管）

## 六、停與錯

- **P-19** 結束碼三種：`0`＝這次好了、下一次；`10`＝正常停、沒東西了（idle 看 `$AOS_STACK/queue/` 空了；舊協議看 `new/`，P-11）；其他非 0＝失敗。字串 `next` 的表上只有 idle 退 10；物件 `next`（N-36）的表上，別的格也可以退 10、意思仍是 N-43 的「沒東西」——`demo/agent-fsm` 的 think 在腦給了最後答案（沒有 `tool_calls`）時退 10，表上 `"10": "idle"` 接住、到不了 loop（P-35）。loop 收到 10 以 0 結束；收到其他非 0 以那個碼結束；跑滿 `max` 以 0 結束、stderr 不寫（N-43 正常退出不噴 stderr；要知道有沒有跑滿看 loop 的 state 窗或 log）；loop 自己收到 SIGINT／SIGTERM／SIGHUP 時收完那次以 128＋N 結束（P-36）。（拍板點 1；原型現狀。跟 C-63 相撞處使用者 10-19 定照用、C-63 作廢，[ideas § 9](../../../thinking/2026-10/19/ideas/README.md)；N-43；think 也退 10：使用者 11-04 衝突 2 選「think 也退 10，條文加註」，[thinking 11-04 loop-fsm-agent](../../../thinking/2026-11/04/loop-fsm-agent/04-衝突與方向題.md#決定11-04使用者)）
- **P-20** 任一格失敗＝整個 agent 停下來等人：fsm 不換狀態、loop 以那個碼結束；人修好後再 `aos-exec` 一次，從 `$AOS_STACK/state.txt`〔11-04 起叫 `stage.txt`（[four-elements 07 步 3](../../../thinking/2026-11/04/four-elements/07-實作步驟.md#步-3fsm-的-statetxt-換同義詞題-10)）；11-04 夜使用者選「加一句改名註 (Recommended)」，原字不動，[收斂報告 05 第 5 題](../../../../wf/workflows/tidy/reports/2026-11-03-收斂/05-11-04晚-P2-P3-P4續.md#留給使用者看的)〕 接著做同一格、同一題。不自動重試、不數連錯。（拍板點 3；N-53 腦出錯那次 phase 不動；N-38）
  - **10-30 加註：表上沒接住時才是預設停**（使用者 10-30「都照建議」，[thinking 10-30 aos-round](../../../thinking/2026-10/30/aos-round/07-決定.md#決定10-30) 衝突 3）：用 aos-round（或自己寫物件 `next`，N-36）的 agent，「任一格失敗＝停下等人」是**表上沒接住那個碼時**的預設；表上接了就照表走（風險自擔，loop 的 `max` 是唯一的煞車）。範本表不接錯誤碼，所以範本仍是失敗就停；endpoint 的 retry／switch 照 10-28 在 think 格內問 `hook/on_error`、數 `AOS_ROUND_MAX_RETRIES`，不寫在表上。 **11-01 加註**（使用者 11-01 晚「3.這就是濫用...除非真的有必要的，否則不要用。」「明明現有的機制組合一下就能搞定，偏偏在那邊亂搞一通」，[thinking 11-01 playground-bob 03](../../../thinking/2026-11/01/playground-bob/03-旋鈕改-argv-與檔-實作.md)）：格自己的旋鈕不再走環境變數——能刪的寫死成常數，刪不掉的改 argv 或格／stack 裡的檔；本條提到的 `AOS_ROUND_MAX_RETRIES` 已刪（think 寫死重來 3 次）。條文原意改不改由使用者定。 **11-04 加註**（round 已刪後的條文整理，使用者 11-04「照建議」，[收斂報告 § round 刪掉後](../../../../wf/workflows/tidy/reports/2026-11-03-收斂/03-round刪掉後的條文之一.md#round-刪掉後沒實作撐的條文11-04給使用者裁)）：後半「endpoint 的 retry／switch 照 10-28 在 think 格內問 `hook/on_error`、數 `AOS_ROUND_MAX_RETRIES`」已無實作（round、endpoint 格、`hook/` 都已刪，那條 10-28 加註 11-04 也刪了）；前半「表上沒接住時才是預設停」照舊，由 aos-fsm 的物件 `next`（N-36）撐著。
  - **11-05 註：daemon 的身體例外**（使用者 11-05 裁 edge-daemon 題 1，選項原話「記一行、下一圈再跑 (Recommended)」）：aos-daemon 的身體（判官、llm kernel）失敗不照本條停——失敗記一行、下一圈再跑（stderr 一行〔11-05 起是提醒行 `aos-daemon: warning: …`：不退出就不寫錯誤行，代定 D4，[thinking 11-05 stdio-unify](../../../thinking/2026-11/05/stdio-unify/README.md)〕、`state.json` 記 `body_code`；[N-28 ⑥](../../NORMS/04-基礎設施-loop與daemon/02-N-28.md)）。agent 自己（aos-loop、aos-fsm）照本條停；掛在 daemon 下停了的列留 `stopped`＋`reason`（N-28 ⑤）。
