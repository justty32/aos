## 五、stack

<a id="p-15"></a>

P-15 全文見 [04-五-stack續-P-15](04-五-stack續-P-15.md)。

- **P-16** agent 自己的格（idle／think／wait／act）共用同一個 `$AOS_STACK`——它們是同一台狀態機。stack 裡放什麼、叫什麼，agent 自訂；`templates/agent-fsm` 的 `think/pending.txt`、`think/request.json` 是例子不是規範。（拍板點 1「stack 內部自由」；§ 2「剩下的你自己想」；§ 3）
- **P-17** 叫**別的**資料夾程式（工具、另一個 agent）時，給它自己的 stack（**小格**）：`sub=$AOS_STACK/tools/<名>/`、`AOS_STACK=$sub aos-exec tools/<名>`（例：agent-fsm 的 act 經 `aos-tools call` 叫工具，工具的小格是 `$AOS_STACK/tools/<登記名>/`）。小格名＝工具資料夾名（P-38 靠這點）。小格放在 `tools/` 底下，呼叫方給的名字跟格自己的固定名分開命名空間；`tools` 是 stack 頂層的保留名（格自己不能在 stack 頂層放叫 `tools` 的固定東西）（使用者 11-02「未來，搞不好會出現agent+kernel的變體，.stack底下會有一大堆東西。擋名字會擋不過來。所以我覺得最好還是tools/<name>更好」，[thinking 11-02 stack-tools](../../../thinking/2026-11/02/stack-tools/README.md)）。被叫的只看到自己的 stack、不知道上面有誰。叫完不自動收——留著給人看；要收由呼叫方自己 `rm`。巢狀時被叫者的工作區：沒給就沿用呼叫方的 `AOS_WS`，要換就明給 `--ws`（N-58）。（§ 3「子程式的 stack 由 agent-bob 自己訂，有可能他會是 AOS_STACK/think, /act」；C-52 子 agent 只看自己的 stack；C-65 stack＝「叫工具時開的小格」；C-67 stack 放哪由呼叫方決定；拍板點 3「人來看」。這是原討論稿拍板點 4 的答案）
  - **小格不先建**（使用者 11-11「我確實想改成工具真的寫東西時才建資料夾」，[thinking tool-cells-lazy](../../../thinking/2026-11/11/tool-cells-lazy.md)）：`aos-tools call` 只把 `AOS_STACK` 設成 `<父 stack>/tools/<名>/`、交 `aos-exec --stack-lazy`，不先建資料夾；工具真的要往小格寫東西才自己 `mkdir -p`，讀的時候小格不在＝空的。所以只有寫過東西的工具才留下小格，「叫完不自動收」照舊。
- **P-18** 一個工作區同時跑兩個 agent 時，呼叫方給不同的 `AOS_STACK`（例 `$AOS_WS/.stack/bob/`）；預設值只保證「一個工作區一個 agent」不撞。（C-67；C-53 入口默認正常、誤用不歸組件管）

## 六、停與錯

- **P-19** 結束碼三種：`0`＝這次好了、下一次；`10`＝正常停、沒東西了（idle 看 `$AOS_STACK/queue/` 空了，P-11）；表上明寫接住的碼（如 wait 的 11）＝分岔、不是失敗；沒列在表上的其他非 0 才是失敗。（使用者裁定 sol 審查 #29）字串 `next` 的表上只有 idle 退 10；物件 `next`（N-36）的表上，別的格也可以退 10、意思仍是 N-43 的「沒東西」、由表接住——`templates/agent-fsm`（四格 idle → think → wait → act）在腦給了最後答案（沒有 `tool_calls`）時 act 退 10、think 在 history 尾巴沒有要答的時退 10，表上 `"10": "idle"` 接住、到不了 loop（P-35、P-41、[四格呼叫端](../../../thinking/2026-11/04/think-as-function/03-呼叫端.md)）。loop 收到 10 以 0 結束；收到其他非 0 以那個碼結束；跑滿 `max` 以 0 結束、stderr 不寫（N-43 正常退出不噴 stderr；要知道有沒有跑滿看 loop 的 state 窗或 log）；loop 自己收到 SIGINT／SIGTERM／SIGHUP 時收完那次以 128＋N 結束（P-36）。（拍板點 1；原型現狀。跟 C-63 相撞處使用者 10-19 定照用、C-63 作廢，[ideas § 9](../../../thinking/2026-10/19/ideas/README.md)；N-43；think 也退 10：使用者 11-04 衝突 2 選「think 也退 10，條文加註」，[thinking 11-04 loop-fsm-agent](../../../thinking/2026-11/04/loop-fsm-agent/04-衝突與方向題.md#決定11-04使用者)）
- **P-20** 任一格失敗＝整個 agent 停下來等人：fsm 不換狀態、loop 以那個碼結束；人修好後再 `aos-exec` 一次，從 `$AOS_STACK/stage.txt`（[four-elements 07 步 3](../../../thinking/2026-11/04/four-elements/07-實作步驟.md#步-3fsm-的-statetxt-換同義詞題-10)）接著做同一格、同一題。不自動重試、不數連錯；只有開了 `--auto-restart`（`aos-agent ctl add`）的，照下面「失敗後冷卻」重試。（拍板點 3；N-53 腦出錯那次 phase 不動；N-38）
  - **表上沒接住時才是預設停**（使用者 10-30「都照建議」，[thinking 10-30 aos-round](../../../thinking/2026-10/30/aos-round/07-決定.md#決定10-30) 衝突 3；使用者 11-04「照建議」，[收斂報告 § round 刪掉後](../../../../wf/workflows/tidy/reports/2026-11-03-收斂/03-round刪掉後的條文之一.md#round-刪掉後沒實作撐的條文11-04給使用者裁)）：自己寫物件 `next`（N-36）的 agent，「任一格失敗＝停下等人」是**表上沒接住那個碼時**的預設；表上接了就照表走（風險自擔，loop 的 `max` 是唯一的煞車）。範本表不接錯誤碼，所以範本仍是失敗就停。格自己的旋鈕不走環境變數——能刪的寫死成常數，刪不掉的改 argv 或格／stack 裡的檔（使用者 11-01 晚「3.這就是濫用...除非真的有必要的，否則不要用。」「明明現有的機制組合一下就能搞定，偏偏在那邊亂搞一通」，[thinking 11-01 playground-bob 03](../../../thinking/2026-11/01/playground-bob/03-旋鈕改-argv-與檔-實作.md)）。
  - **daemon 的身體例外**（使用者 11-05 裁 edge-daemon 題 1，選項原話「記一行、下一圈再跑 (Recommended)」）：aos-daemon 的身體（判官、llm kernel）失敗不照本條停——失敗記一行、下一圈再跑（stderr 一行提醒行 `aos-daemon: warning: …`〔不退出就不寫錯誤行，代定 D4，[thinking 11-05 stdio-unify](../../../thinking/2026-11/05/stdio-unify/README.md)〕、`state.json` 記 `body_code`；[N-28「daemon 的身體失敗」](../../NORMS/04-基礎設施-loop與daemon/02-N-28.md)）。agent 自己（aos-loop、aos-fsm）照本條停；掛在 daemon 下停了的列留 `stopped`＋`reason`（N-28「出錯結束一律留表」）。
  - **kernel 不在＝等它來，不停**（使用者 11-10「如果llms那邊我沒開aos daemon，那就是我自己的問題，但我也希望他不要搞壞」，[thinking two-machines](../../../thinking/2026-11/10/two-machines/README.md#午後方向改變逐字)）：`templates/agent-fsm` 的 wait 格寄不出去（`AOS_LLM_KERNEL` 不是資料夾）或 kernel 沒在跑時，印 warning、原地等、下一拍再試，有沒有 `--auto-restart` 都不停；kernel 回錯（端點壞、額度到頂）照本條停（開了 `--auto-restart` 的由冷卻接手重試）。
  - **等回信沒有期限**（使用者 11-10「2.等腦回信沒前線...理論上這是要自己承擔的風險。但是確實也可以如你這樣所說，就是自己當monitor，過一段時間沒收到，那就印提醒，或是直接失敗。」）：wait 寄出後沒收到回信不判失敗、照樣等，每滿 10 分鐘印一行 warning（選印提醒、間隔 10 分鐘是代定、可翻案，[prefix-fixes](../../../thinking/2026-11/10/prefix-fixes/README.md#使用者裁定11-10-快裁大修時可重看) q-wait）。
  - **失敗後冷卻**（使用者 11-10 選項框裁定 5「掉那一封、但自動重起」、裁定 6 加 `aos-agent ctl add --auto-restart`，額度窗選「失敗後冷卻，只拿一封試 (Recommended)」，[two-machines](../../../thinking/2026-11/10/two-machines/README.md#使用者裁定11-10-上午選項框快裁大修時可重看)）：開了 `--auto-restart` 的 agent 退了由 daemon 重起；外面服務（腦、Claude）的錯記一筆冷卻（`$AOS_STACK/cooldown.json`），冷卻中不送，冷卻到了再試——eca 只拿一封試、交出去失敗的那封掉掉，agent-fsm 重寄同一份請求、不掉信；成功一次歸零。間隔 30 秒、1、2、4、8、15、30 分鐘，之後固定 30 分鐘（代定、可翻案，[two-machines 06](../../../thinking/2026-11/10/two-machines/06-長跑自動重起.md#補的東西失敗後冷卻python兩個地方不動-daemon)）。
