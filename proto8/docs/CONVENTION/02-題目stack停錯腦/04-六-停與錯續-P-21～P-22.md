## 六、停與錯（續）

- **P-21** 誰的錯誰自己講：格的錯寫在格自己的 stderr；fsm 什麼都不轉述；loop 只說「第幾次、誰、結束碼幾」。錯寫 stderr 是 agent 範本與 lib 的格、aos-loop／aos-fsm 這幾支自己的約定，照 Unix 慣例，不是 aos 函數都要守的標準（stderr 只是每個 proc 都有的檔案；見 N-43「適用範圍」）。（C-53；N-43 每層只說自己；使用者 10-28「照你的建議，留著改口，JSONL 那半條刪掉」，[thinking 10-28 medium](../../../thinking/2026-10/28/medium/README.md)）
  - **11-05 註：那一行的形狀**（使用者 11-05「可以，固定格式："error:", "warning:"後面接你那個」，[thinking 11-05 stdio-unify](../../../thinking/2026-11/05/stdio-unify/README.md) R1、R15）：說自己的錯是**錯誤行** `程式: error: 代號 原因`；不是錯、只要讓人知道的是**提醒行** `程式: warning: 句子`（[N-43 續](../../NORMS/01-總則/02-N-43續-11-05-兩種行與碼.md)）。開頭的「程式」**可以是 agent 名**（照盤點推薦 R15：templates/agent-fsm 四格照舊都用 `agent-fsm:`，不換成各格名）。loop 那句「第幾次、誰、結束碼幾」寫成錯誤行 `aos-loop: error: RunFailed run N: X failed with exit code C`、接著以那個碼結束（代定 D4）。給人看的表（`ls` 類）一律 TAB 分欄（R15）。
- **P-22** 逾時：shell 版沒人管——某格卡住（模型沒載入、網路不通）loop 只會等，也殺不到孫程式。要逾時就把那格換成 inst 版、寫 `timeout_ms`（P-29）：直接寫 `"exec": {"argv": …, "timeout_ms": …}`，fsm 行程內當監工收整群（[thinking 10-24](../../../thinking/2026-10/24/exec-relative/01-使用者原文.md#10-24-exec-直接放單子)）；或寫 `"exec": "fsm.json#/states/<名>/body"`、單子放 `body`，由 aos-exec 當監工收整群（P-07）。（N-41「靠那張 inst 的 timeout_ms 守」；inst 討論的結論）
