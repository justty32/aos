- **P-41 腦的工具呼叫（`tool_calls`）**（範本 `templates/agent-fsm`；[thinking 2026-10-23-tool-calls](../../../thinking/2026-10/23/tool-calls/README.md)；走 queue 的做法：使用者 11-04「接下來是弄aos loop/fsm agent了」、看完規劃四題都選建議並說「記完就實作」，[thinking 11-04 loop-fsm-agent](../../../thinking/2026-11/04/loop-fsm-agent/02-跟-eca-對照.md#條文要加的註實作時一起11-04-註條文原字不動)）：
  - **工具登記與說明**：腦能叫哪些工具＝**登記檔 `tools.json`**（[aos-tools](../../../cmd/README.md) 管，`add／rm／ls／get`；brain.py／act.py 的 `--tools`，預設範本的 `tools.json`；使用者 10-28「像現在這樣掃tool.json，實在太土太粗暴，不夠靈活」「現有的...改吧」，[thinking 10-28 aos-tools](../../../thinking/2026-10/28/aos-tools/README.md)）。brain 跑 `aos-tools ls --json` 組 `tools`、act 跑 `aos-tools call 名` 叫。給模型看的說明在工具資料夾的 `_tooldef.json`（JSON 檔工具用 `_tooldef` key；可執行檔用 `--tooldef`），內容就是 OpenAI tool 的 function 物件去掉 `name`（`{"description": …, "parameters": {JSON Schema}}`，外部 API 欄位名照原名）；裡面其他 key 忽略（C-48）。資料夾裡只認 `_tooldef.json`、`_metainfo.json`，不帶副檔名的不認；沒有 `_tooldef.json` 的資料夾登記不了（`ToolDefMissing`）（使用者 11-04 題 8「留 _、加 .json」，[four-elements 06](../../../thinking/2026-11/04/four-elements/06-要使用者裁的題.md#使用者裁定11-04選項原文或他的話逐字)）。tooldef 也可以寫在 `_metainfo` 裡——資料夾 `_metainfo.json` 的 `tooldef` 鍵、JSON 物件的 `_metainfo.tooldef`；aos-tools 兩處都認，先讀裡面、再讀獨立那份、頂層鍵淺合併、獨立那份贏，兩處都沒有才 `ToolDefMissing`；工具自己啟動時的 `tool_io` 與 `tools_def` 也照這樣讀。推薦讀法與目前支援名單見 [N-69](../../NORMS/10-基礎設施-定義與工作區/11-N-69.md)。**工具名＝登記名**（預設資料夾名），組 `tools` 陣列時由程式填。登記檔本身壞（不是 JSON、形狀不對、`$override` 指不到、指示詞解不開、登記格形狀不對）＝brain／act 自己這層的錯 `ToolsBad`（整隻停、人修好再跑）；登記了但其中一支壞掉（路徑不在、定義缺或壞）＝`aos-tools ls` 略過那支、提醒一行，清單少那一支、照跑（使用者 11-12「可以改條文」，[tool-path-broken](../../../thinking/2026-11/12/tool-path-broken.md)）。
  - **工具＝函式庫裡的一個函數**（[tool-lib](../../../thinking/2026-10/24/tool-lib/README.md)，C-61；使用者 11-12 裁 Q16「a」照現況落）：一個工具＝`_entry`＋`_tooldef.json`＋選填 `_metainfo.json`（JSON 檔工具是同一份檔裡的 `_tooldef`／`_metainfo` 兩個 key；可執行檔用 `--tooldef`、沒有 metainfo）。給腦用的工具一律照 [lib 的統一契約](../../../lib/docs/01-分層等.md)（使用者 11-05「統一 lib 契約 (Recommended)」，[stdio-unify](../../../thinking/2026-11/05/stdio-unify/README.md) R2、R10）：stdin 一份 JSON、stdout 整段是結果；錯＝`工具名: error: 代號 原因` 一行、stderr 與 stdout 都印、退 1（N-43、P-21）；被跑的指令自己退非 0 不算工具的錯（`shell`、`run_python` 的 stdout 最後一行寫 `[exit code N]`）；下層的 stderr 原樣透到工具的 stderr，下層壞了 stdout 只有工具自己那一行錯誤行（把下層代號接進自己那行的工具，各自寫在說明裡）。逾時、上限、寫檔、stack 等細則在契約裡。
  - **給腦看的文字用英文**：system、persona、開場白、工具說明（`_tooldef`）這些給 LLM 看的內容一律英文（使用者裁定 sol 審查 #34-2，出處 [wf/workflows/refactor/reports/2026-11-07-sol審查/11-使用者裁定.md](../../../../wf/workflows/refactor/reports/2026-11-07-sol審查/11-使用者裁定.md)）。
  - **介面**：模型給的 `arguments`（JSON 字串）原樣從 stdin 餵進去，工具的 stdout 整段就是結果（像 stamp）；arguments 裡有 schema 沒宣告的鍵＝`ArgumentsBad`（tool_io 集中擋；schema 寫 `additionalProperties: true` 的照收；使用者 11-10「那就報錯」，[self-tools 04](../../../thinking/2026-11/10/self-tools/04-不認得的鍵報錯.md)）；用 argv 陣列叫、不經 `sh -c`；exe 也從 stdin 收 arguments，沒有 `tool_call.json`／`--tool-call`。模型只取 `_tooldef` 的 `description`／`parameters`；工具側另讀選填的 `positional`／`errors`／`env`（[J1](../../../thinking/2026-11/05/json-argv/08-J1實作結果.md)、[J2](../../../thinking/2026-11/05/json-argv/09-J2實作結果.md)）。每個工具一個小格：`AOS_STACK=$AOS_STACK/tools/<名>/`（見 P-17），由 `aos-tools call` 一處算。要把另一隻 agent 給腦當工具，轉接寫在那個工具資料夾自己的 `_entry`，範本不管（C-52）。
  - **對話**：`$AOS_STACK/history.jsonl`，一行一則 OpenAI message（照 API 原形），只附加、不改寫；system 訊息不存、每格重讀：brain.py 帶 `--system FILE` 就讀那份；範本不帶，由 interfaces.json 宣告 `"system": "system.txt"`——`$AOS_STACK/system.txt` 在就整份用它（`aos-agent system set`／`self_system`）、否則用定義那份，同一題下一格生效；eca 則附加給 CLI（[thinking self-system](../../../thinking/2026-11/11/self-system/README.md)）；模型想的內容不收（P-23）。
  - **四格 idle → think → wait → act**（P-08；腦的決定仍是 plan，P-24）：idle 收 queue；think 只組請求（system＋history＋`aos-tools ls --json` 的工具清單＋`llm.json` 的代號）寫 `$AOS_STACK/think/request.json`、不碰網路；wait 沒寄過就 `aos-llm send --reply-to $AOS_STACK/think/reply`、信件名稱記 `think/pending.txt`、退 10，寄過就 `aos-llm recv`（沒到退 10 停在 wait、loop 照跑；到了把 `message` 接進 history、退 0 到 act）；沒 pending 且 `think/request.json` 不在、或腦設定改過與現有請求對不上＝退 11 回 think，從 history＋定義重組再寄（git-image 裁定；對不上那半是代定、可翻案，使用者裁定 sol 審查 #29）——11 是 fsm 表接住的分岔、不是失敗（P-19）；有 pending 則直接收原回信，不依賴 request；act 看最後一則 assistant：沒有 `tool_calls`＝答完、退 10 回 idle（P-19），答案就是 history 那則 assistant、沒有 `out/`／`done/`；有＝逐個跑工具、結果接回 history、退 0 回 think 再問。等回信期間不收新信、答完回 idle 再收（使用者 11-04 晚方向題 1 選「不收」）。「要不要叫工具」由 act 判（P-23；[thinking 11-04 think-as-function 03](../../../thinking/2026-11/04/think-as-function/03-呼叫端.md)；細節 fable 代定，見 [四題裁定](../../../thinking/2026-11/04/think-as-function/05-衝突與方向題.md)）。
  - **錯**：問腦的錯在 kernel 的回信裡（端點連不上或 HTTP 非 2xx＝`EndpointFailed`、回覆不是 OpenAI 的形狀＝`ReplyBad`，代號表見 N-42 (1)），`aos-llm recv` 退 1、wait 格照樣停；叫工具時 aos-tools 起不來＝`ToolFailed`（範本另有 `StackMissing`、`HistoryBad`〔history.jsonl 有一行不是 JSON、或沒有 assistant 可照做〕）。這些一律 stderr 一行 `<agent 名>: error: 代號 原因`（P-21；範本是 `agent-fsm:`）、退 1、stage 不動、history 不接那一則；人修好再 `aos-exec` 一次從同一格接著做（P-20）。叫了沒登記的工具（`ToolUnknown`）、`arguments` 不是 JSON（`ArgumentsBad`）、工具退非 0（含 10，P-35）這三種不停：接成一則 tool 訊息回給腦（act 格沒失敗，工具的錯是那次呼叫的結果；P-20 不變；使用者 10-24「都隨意」，代定可翻案，[thinking tool-calls 文末](../../../thinking/2026-10/23/tool-calls/02-結論.md#10-24-定叫工具與小念頭的失敗回給腦)）。逾時：act 是自己單子的 `timeout_ms`（P-22）；act 叫每支工具另按那支的 `_metainfo.timeout_ms`（純數或 `{"val": N}`，經共用 `lib/metainfo.py` 讀；未寫不限；估時在 `cost.time_ms`，見 [N-68](../../NORMS/10-基礎設施-定義與工作區/10-N-68.md)；使用者 11-07 裁定，[evolve-design](../../../thinking/2026-11/07/evolve-design/README.md)），退非 0／逾時的 tool 訊息附 stderr 尾 2048 bytes（C-52 例外；[J3／J4](../../../thinking/2026-11/05/json-argv/10-J3到J7實作結果.md)）；問腦由 kernel.json 的 `timeout_ms` 守（wait 自己不設）。history 不設上限，要忘記＝換 stack。
