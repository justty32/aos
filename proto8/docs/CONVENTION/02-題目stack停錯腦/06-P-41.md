- **P-41 腦的工具呼叫（`tool_calls`）**（範本 `templates/agent-fsm`；[thinking 2026-10-23-tool-calls](../../../thinking/2026-10/23/tool-calls/README.md)；走 queue 的做法：使用者 11-04「接下來是弄aos loop/fsm agent了」、看完規劃四題都選建議並說「記完就實作」，[thinking 11-04 loop-fsm-agent](../../../thinking/2026-11/04/loop-fsm-agent/02-跟-eca-對照.md#條文要加的註實作時一起11-04-註條文原字不動)）：
  - **工具登記與說明**：腦能叫哪些工具＝**登記檔 `tools.json`**（[aos-tools](../../../cmd/README.md) 管，`add／rm／ls／get`；brain.py／act.py 的 `--tools`，預設範本的 `tools.json`；使用者 10-28「像現在這樣掃tool.json，實在太土太粗暴，不夠靈活」「現有的...改吧」，[thinking 10-28 aos-tools](../../../thinking/2026-10/28/aos-tools/README.md)）。brain 跑 `aos-tools ls --json` 組 `tools`、act 跑 `aos-tools call 名` 叫。給模型看的說明在工具資料夾的 `_tooldef.json`（JSON 檔工具用 `_tooldef` key；可執行檔用 `--tooldef`），內容就是 OpenAI tool 的 function 物件去掉 `name`（`{"description": …, "parameters": {JSON Schema}}`，外部 API 欄位名照原名）；裡面其他 key 忽略（C-48）。資料夾裡只認 `_tooldef.json`、`_metainfo.json`，不帶副檔名的不認；沒有 `_tooldef.json` 的資料夾登記不了（`ToolDefMissing`）（使用者 11-04 題 8「留 _、加 .json」，[four-elements 06](../../../thinking/2026-11/04/four-elements/06-要使用者裁的題.md#使用者裁定11-04選項原文或他的話逐字)）。**工具名＝登記名**（預設資料夾名），組 `tools` 陣列時由程式填。登記了但壞掉的工具＝brain／act 自己這層的錯 `ToolsBad`（停、人修好再跑）。
  - **介面**：模型給的 `arguments`（JSON 字串）原樣從 stdin 餵進去，工具的 stdout 整段就是結果（像 stamp）；用 argv 陣列叫、不經 `sh -c`。每個工具一個小格：`AOS_STACK=$AOS_STACK/tools/<名>/`（見 P-17）。要把另一隻 agent 給腦當工具，轉接寫在那個工具資料夾自己的 `_entry`，範本不管（C-52）。
  - **對話**：`$AOS_STACK/history.jsonl`，一行一則 OpenAI message（照 API 原形），只附加、不改寫；system 訊息每次從 brain.py `--system FILE` 指的檔讀（範本是 `system.txt`）、不存；模型想的內容不收（P-23）。
  - **四格 idle → think → wait → act**（11-04 晚，P-08 的加註；腦的決定仍是 plan，P-24）：idle 收 queue；think 只組請求（system＋history＋`aos-tools ls --json` 的工具清單＋`llm.json` 的代號）寫 `$AOS_STACK/think/request.json`、不碰網路；wait 沒寄過就 `aos-llm send --reply-to $AOS_STACK/think/reply`、信件名稱記 `think/pending.txt`、退 10，寄過就 `aos-llm recv`（沒到退 10 停在 wait、loop 照跑；到了把 `message` 接進 history、退 0 到 act）；沒 pending 且 `think/request.json` 不在＝退 11 回 think，從 history＋定義重組再寄（11-06 git-image 裁定）；有 pending 則直接收原回信，不依賴 request；act 看最後一則 assistant：沒有 `tool_calls`＝答完、退 10 回 idle（P-19），答案就是 history 那則 assistant、沒有 `out/`／`done/`；有＝逐個跑工具、結果接回 history、退 0 回 think 再問。等回信期間不收新信、答完回 idle 再收。「要不要叫工具」由 act 判（P-23；[thinking 11-04 think-as-function 03](../../../thinking/2026-11/04/think-as-function/03-呼叫端.md)；方向題 1 照推薦 (a)，可翻案（11-06 註：使用者 11-04 晚選「不收」、已定案；細節仍是 fable 代定，見 [四題裁定](../../../thinking/2026-11/04/think-as-function/05-衝突與方向題.md)））。
    **11-04 晚已改**（使用者 11-04 晚「並且可以的話，考慮非同步呼叫，也就是正在跑的loop不停。」「llm呼叫這塊，我希望是把請求丟到llm kernel(一個loop)，處理好後收回信」，[thinking 11-04 think-as-function](../../../thinking/2026-11/04/think-as-function/README.md)）：原本三態 idle → think → act，think 自己問腦、回覆接一行：有 `tool_calls` 退 0 到 act、沒有退 10 回 idle。舊協議（P-11）的範本是 act 判：有 `tool_calls` 跑完退 0 回 idle、題目還在 `cur/`，think 帶 history 再問（P-12）；沒有 `tool_calls` 才把 `content` 寫成答案、題目搬 `done/`。
  - **錯**：問腦的錯在 kernel 的回信裡（端點連不上或 HTTP 非 2xx＝`EndpointFailed`、回覆不是 OpenAI 的形狀＝`ReplyBad`，代號表見 N-42 (1)），`aos-llm recv` 退 1、wait 格照樣停〔11-04 晚已改：原本 think 自己打端點，報 `BrainFailed`／`ReplyBad`〕；叫工具時 aos-tools 起不來＝`ToolFailed`（範本另有 `StackMissing`、`HistoryBad`〔history.jsonl 有一行不是 JSON、或沒有 assistant 可照做〕；舊協議另有 `QuestionMissing`〔new/ 與 cur/ 都空〕）。這些一律 stderr 一行 `<agent 名>: error: 代號 原因`〔11-05 加 `error:`，P-21〕（範本是 `agent-fsm:`）、退 1、stage 不動、history 不接那一則；人修好再 `aos-exec` 一次從同一格接著做（P-20）。叫了沒登記的工具（`ToolUnknown`）、`arguments` 不是 JSON（`ArgumentsBad`）、工具退非 0（含 10，P-35）這三種不停：接成一則 tool 訊息回給腦（act 格沒失敗，工具的錯是那次呼叫的結果；P-20 不變；使用者 10-24「都隨意」，代定可翻案，[thinking tool-calls 文末](../../../thinking/2026-10/23/tool-calls/02-結論.md#10-24-定叫工具與小念頭的失敗回給腦)）。逾時：act 是自己單子的 `timeout_ms`（P-22）；問腦由 kernel.json 的 `timeout_ms` 守（wait 自己不設，11-04 晚起；原本 think 單子也有 `timeout_ms`）。history 不設上限，要忘記＝換 stack。
