- **P-43（續）：範本的 aos-agent 介面**（使用者 11-03「aos_ws,aos-say/listen,aos-ai這些之後都會整合進aos-agent」、11-04 晚「幫我弄個aos-agent chat指令，ctrl-c退出」「aos-agent add --name bob ../agents/bob這樣」，[thinking 11-04 aos-agent](../../../thinking/2026-11/04/aos-agent/README.md)、[03/01 兩個範本要改什麼](../../../thinking/2026-11/04/aos-agent/03-種類與契約/01-tools-llm-與兩個範本要改什麼.md)）：
  - **範本多三樣**：定義頂層 `interfaces.json`（`{"aos-agent": {"screen": "screen", "tools": "tools.json", "llm": "llm.json"}}`，宣告遵守 aos-agent 介面；`aos-agent ctl add` 只看它）、`screen/`（`_entry`＝`["aos-eca-screen", "--eca", ".."]`；隊長代定 D6：aos-exec 把動作接在 argv 最後，eca 資料夾用子命令前的旗標 `--eca` 給，[stdio-unify R6](../../../thinking/2026-11/05/stdio-unify/README.md)）、腦設定檔 `llm.json`（eca：`{"model": "sonnet"}`，cli_session 組旗標時補 `--model`；agent-fsm：`model`＝kernel 的代號，P-23；使用者 11-10 晚「3.把fsm認的endpoint這個key，也改名爲model吧...麻煩的話就算了。」，[self-tools 05](../../../thinking/2026-11/10/self-tools/05-llm設定改名與ls.md)）。`tools`、`llm` 的值都是定義裡那份檔的相對路徑，副本＝stack 裡同一個相對路徑：`aos-agent tools` 改 `$AOS_STACK/tools.json`（只存差異的覆蓋層，[aos-agent docs/03](../../../cmd/aos-agent/docs/03-tools覆蓋層.md#tools-覆蓋層)；P-15），cli_session 怎麼用它見 P-43「工具」；`aos-agent llm ls` 讀定義 `llm.json`（沒有＝`{}`）疊 `$AOS_STACK/llm.json` 印 `鍵=值`（`-l` 標出哪些是自己改的）、`set 鍵=值` 是 `aos-json set` 寫副本、`rm 鍵` 拿掉改過的鍵、`reset` 刪副本（使用者 11-10 晚「5.那就來個ls?」，問 show 換掉還是留：「換」，[self-tools 05](../../../thinking/2026-11/10/self-tools/05-llm設定改名與ls.md)、[tonight-rulings](../../../thinking/2026-11/10/tonight-rulings/README.md) 第 8 題）——`llm` 宣告的是腦設定檔、沒有入口程式，aos-agent 不懂鍵（不認的鍵由身體照 C-48 忽略）；eca 的 `--model` 寫在 `llm.json`、不在 `cli.json`（使用者 11-04 晚「然後aos llm,tool這兩個，我希望他們的定位是跟aos post一樣，作為基礎工具」，[thinking 11-04 think-as-function 03 § 4](../../../thinking/2026-11/04/think-as-function/03-呼叫端.md)；fable 代定、衝突 1 照推薦 (a)，可翻案）。沒宣告 `llm`＝`LlmMissing`；宣告值不是檔（例如資料夾）＝`LlmBad`。宣告還有 `system`（定義裡 system 文字檔的相對路徑）；`aos-agent system get|set|reset` 寫 stack 同一相對路徑那份（整份、在就蓋過定義那份），腦用 `self_system`（[thinking self-system](../../../thinking/2026-11/11/self-system/README.md)，使用者選項框裁「單獨一支工具」「self_system」「fsm 取代、eca 附加」「只給 reset、不擋」）。
  - eca 那幾條決定（[eca](../../../thinking/2026-10/30/eca/README.md) 14、18、19、20、eca-tools、21）由 [cmd/aos-agent](../../../cmd/aos-agent/README.md) 引用。

  - **入口也可用來掛上 daemon**：使用者 11-05「當然，你也可以把_entry寫成aos agent add，這樣我們也可以aos-exec了。」掛上 daemon 的介面是 `aos-agent ctl add`；定義的 `_entry` 可呼叫它，`aos-exec 那個資料夾` 就是掛上 daemon；`aos-exec` 不加 `--daemon`（N-59 只做幾件事），見 [portable-flow](../../../thinking/2026-11/05/portable-flow/README.md)。
