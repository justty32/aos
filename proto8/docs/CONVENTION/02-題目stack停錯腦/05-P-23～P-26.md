## 七、腦與工具

- **P-23** 腦＝OpenAI 相容的 chat completions 端點，由環境變數 `AOS_BRAIN_URL`、`AOS_BRAIN_MODEL`、`AOS_BRAIN_KEY` 指定；`AOS_BRAIN_URL` 沒設＝假腦（demo 預設）。只取回覆的 `content`（有工具時加 `tool_calls`），模型想的內容不收、不存。這台電腦不跑本機模型。（原型現狀；使用者 10-15「維持 openai 格式」「模型想的內容丟掉」（[thinking 10-15 topics/02](../../../thinking/2026-10/15/topics/02-agent工具與試146.md)）；§ 6；變數名照 C-54 全大寫底線）。腦的模型名放範本的 `.env`（`AOS_BRAIN_MODEL`；`.env` 不蓋外面已設的），端點 `AOS_BRAIN_URL` 由叫它的人給；家機走 LiteLLM `http://localhost:4000/v1`（不用 key），範本預設 `chatgpt-gpt-6-luna-low`（使用者 10-23「盡量都用gpt的」）。範本 agent-eve（11-04 隨 proto8/tests 刪了）（11-02 晚 agent-dan 刪除，原本指 agent-dan，eve 是它的複本）、P-41。經 LLM kernel 跑時（閘門 `aos-llm-send`），環境裡有 `AOS_KERNEL_REPORT`＝kernel 給的回報檔；腦願意就把 API 回覆的 `usage` 物件原樣寫進去（先寫暫存再改名），kernel 拿它記 token、算額度；不寫＝kernel 只算次數。usage 不進 history。範本 agent-eve 的 `brain.py` 有寫（約五行；11-02 晚 agent-dan 刪除，原本寫 agent-dan）；使用者 10-24「都按建議做」＝照 [rewrite-order 第 3 題](../../../thinking/2026-10/19/rewrite-order.md)推薦，見 [thinking 10-24 llm-kernel](../../../thinking/2026-10/24/llm-kernel/02-邊緣狀況.md#token-回報與額度10-24-下午)。 **11-04 加註**（aos-agent 的 llm 子介面，使用者 11-04 晚「aos-agent llm改正在跑著的，aos-llm改定義」，[thinking 11-04 aos-agent 03/02](../../../thinking/2026-11/04/aos-agent/03-種類與契約/02-子介面規格.md)）：宣告了 `llm` 子介面的 agent，讀腦設定先看 `$AOS_STACK/llm.json`（`aos-agent llm set` 寫的副本，只放改過的鍵），有的鍵蓋過上面的環境變數與 `.env`；沒有副本＝照本條。範本 `demo/agent-fsm` 的 brain.py 每格先讀它；eca 換的是 CLI 的 `--model`（`lib/agent/cli_session.py`）。改定義裡的腦用 `aos-llm`。
- **P-24** 想跟做分開：think 問腦、只把「要做什麼」寫進 `$AOS_STACK/plan.txt`；act 照 plan 動手、不問腦。能寫死的步驟（搬檔、寫檔）放在 act 這種程式格，不交給模型。agent-eve 這類範本（11-02 晚 agent-dan 刪除，原本舉 agent-dan）沒有 `plan.txt`——腦的決定（`$AOS_STACK/history.jsonl` 最後一則 assistant）就是 plan，act 照它叫工具或交答案、不問腦（P-41）。（C-22 能寫死的節點換成程式；C-25）
- **P-25** 工具＝`tools/<名>/` 子資料夾程式，**放在叫它的那一格的資料夾裡**（`act/tools/cathy/`），格裡寫 `aos-exec tools/<名>`：地址是從自己 cwd 起算的相對路徑、永遠零個 `..`、不靠 PATH；`AOS_WS` 自然傳下去（要換工作區見 P-32）；工具要不要碰工作區、怎麼碰，是工具自己的事、風險設計者自管；工具裡是不是另一個 agent，呼叫者不知道也不管。stack 照 P-17。細節與理由見 P-33。（C-61 不用 PATH、地址在自己資料夾裡；N-55；C-66；C-52）
  - **10-28 補：格也走註冊檔**（使用者 10-28「全部走註冊檔好了，捷徑就是方便使用」「註冊檔案中沒寫的，那就是走固定名字」「撞到就撞到。反正我是覺得我們這個比較先進」，[thinking 10-28 agent-ops 決定 10、16](../../../thinking/2026-10/28/agent-ops/02-決定.md#決定10-28)；細節照原則代定、可翻案，[agent-round § 格怎麼找](../../../thinking/2026-10/28/agent-round/01-白話版.md#格怎麼找註冊檔--固定名字--預設決定-16)）：腦能叫的工具走 `tools.json`（aos-tools，P-41 的 10-28 加註）；照 round 拆成格的 agent，自己的格（`round`、`queue`、`history`、`act`、`endpoint/<名>`、`hook/<點>`）也走註冊檔——agent 資料夾裡**另一份** `parts.json`，**是 aos-exec 格式的約定**（11-01 使用者裁，[C-74](../../CONCEPTS/01-設計理念/02-C-51.md#分層10-22-使用者定)；槽值＝路徑字串或 `{".env", "_entry"}`、`endpoint`／`hook` 巢狀；沒有管理指令，手寫或用 `aos-json set／del`，器官共用 `lib/agent/parts.py` 找格——`aos-parts` 11-01 已刪），手寫的相對路徑從註冊檔所在資料夾算（`aos-ai spawn` 複製範本時把指出範本的改成絕對）。註冊檔與固定名字共存（11-01 使用者「2.兩者可以共存的。」）：叫一格的查找順序＝**註冊檔 → agent 資料夾裡的固定名字（捷徑、真的資料夾或檔都行）→ 沒有**（掛勾＝沒掛；必要的格＝`PartMissing`）。`..` 只出現在方便用的捷徑與手寫的相對路徑裡。本條「放在叫它的那一格的資料夾裡、零個 `..`」留給沒經 `tools.json`／`parts.json` 的叫法（例 topdown 的 agent、bob 的 `act/tools/cathy`）。 **11-04 加註**（round 已刪後的條文整理，使用者 11-04「照建議」，[收斂報告 § round 刪掉後](../../../../wf/workflows/tidy/reports/2026-11-03-收斂/03-round刪掉後的條文之一.md#round-刪掉後沒實作撐的條文11-04給使用者裁)）：`parts.json` 那半（照 round 拆成格的 agent 自己的格走另一份 `parts.json`、查找順序、`PartMissing`）已無實作：round 那套已刪，現有程式沒有讀 `parts.json` 的；腦能叫的工具走 `tools.json`（aos-tools）照舊。
- **P-26** 工具的參數怎麼進（args、stdin、或 stack 裡的檔）由工具自己的說明定；aos-exec 保證 args 與 stdin 原樣送到。（§ 4）入口是單子時也成立：args 接在單子 `argv` 的尾巴，單子沒寫 `stdin` 就接呼叫者的（§ 20 使用者沒異議、照預設「串流沒寫＝接呼叫者的」）；單子自己寫了 `stdin: 檔` 是它自己選的，不算 aos-exec 沒送到。
