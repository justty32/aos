## 七、腦與工具

- **P-23** 腦＝**寄一封請求信給 llm kernel、之後收回信**（使用者 11-04 晚「brain url那塊我不喜歡，我希望llm呼叫，或者說思考，這本身也是用aos函數」「llm呼叫這塊，我希望是把請求丟到llm kernel(一個loop)，處理好後收回信」「也可以是一個daemon，實際endpoint呼叫就是aos exec」「包起來的」「我是希望走2」，[thinking 11-04 think-as-function](../../../thinking/2026-11/04/think-as-function/README.md)）。agent 把 OpenAI chat completions 形狀的請求寫成信，body＝`{"endpoint"?, "request", "priority"?}`，寄進 `$AOS_KERNEL`（hub，沒設＝`KernelMissing`，N-63 ②）；回信 body＝`{"message", "usage", "model"}` 或 `{"error": {"code", "msg"}}`（N-42 (1)、N-16）。寄信收信用基礎工具 [aos-llm](../../../impls/aos-llm/README.md)：`send [--priority P] --reply-to BOX`（stdin＝整份 body，印信件名稱、馬上回）、`recv BOX 名`（0 到／10 沒到／1 錯）、同步 `ask`、撤回 `regret`。**非同步**：寄完那格就退、loop 照跑，下一格再收（使用者 11-04 晚「並且可以的話，考慮非同步呼叫，也就是正在跑的loop不停。」）。
  **端點、模型、金鑰只在 kernel 的 `kernel.json`**：`endpoints` 代號表（一組＝`url`／`model`／`key`／`body`，或自己的 `exec`）、預設代號 `endpoint`；**agent 只知道代號**（使用者 11-04 晚「各種llm設定也可以包裝，這樣寄信的時候只要寫簡單的代號就可以」）。代號與選填 `model`（臨時換模型）放定義的 `llm.json`（`interfaces.json` 宣告 `"llm": "llm.json"`，P-43（續））；`$AOS_STACK/llm.json`（`aos-agent llm set` 寫的副本，只放改過的鍵，P-15）有的鍵蓋過定義，每題重讀；都沒寫＝信不寫 `endpoint`、kernel 用預設那組。信改不了 `url`／`key`。假腦＝kernel 的一組代號（範本 `fake`，exec 指 `lib/base/llm_fake`）。只取回覆的 `content`（有工具時加 `tool_calls`），模型想的內容不收、不存（由 endpoint 函數剪）。這台電腦不跑本機模型。（使用者 10-15「維持 openai 格式」「模型想的內容丟掉」（[thinking 10-15 topics/02](../../../thinking/2026-10/15/topics/02-agent工具與試146.md)）；§ 6）。用量在回信的 `usage` 裡，kernel 拿它記 token、算額度；usage 不進 history。agent-fsm 的 think 組請求、wait 寄＋收（P-41）；kernel 範本 [demo/llm-kernel](../../../demo/docs/03-llm-kernel.md)：預設代號 `fake`，家機 `luna`／`sol` 走 LiteLLM `http://localhost:4000/v1`（不用 key），`luna`＝`chatgpt-gpt-6-luna-low`（使用者 10-23「盡量都用gpt的」）。eca 不經 kernel（腦是 CLI）：模型放定義 `llm.json` 的 `model`、副本照上面蓋，`lib/agent/cli_session.py` 組旗標時補 `--model`。
  **11-04 晚已改**（細節 fable 照原則代定、四題照推薦 (a) 先實作，可翻案，[05 衝突與方向題](../../../thinking/2026-11/04/think-as-function/05-衝突與方向題.md)）：原本腦＝OpenAI 相容端點，由環境變數 `AOS_BRAIN_URL`／`_MODEL`／`_KEY` 指定（URL 沒設＝假腦；模型名放範本 `.env`），think 格自己打端點、同步卡住那一格；經閘門 `aos-llm-send` 時，腦把 `usage` 寫進 kernel 給的 `AOS_KERNEL_REPORT`（使用者 10-24「都按建議做」＝照 [rewrite-order 第 3 題](../../../thinking/2026-10/19/rewrite-order.md)推薦，見 [thinking 10-24 llm-kernel](../../../thinking/2026-10/24/llm-kernel/02-邊緣狀況.md#token-回報與額度10-24-下午)）；改定義裡的腦用 Python 的 `bin/aos-llm`（使用者 11-04 晚「aos-agent llm改正在跑著的，aos-llm改定義」，[thinking 11-04 aos-agent 03/02](../../../thinking/2026-11/04/aos-agent/03-種類與契約/02-子介面規格.md)）。現在 `AOS_BRAIN_*` 退場、`AOS_KERNEL_REPORT` 換成回信的 `usage`、`aos-llm` 是寄信收信那支（使用者 11-04 晚「然後aos llm,tool這兩個，我希望他們的定位是跟aos post一樣，作為基礎工具」）；改定義裡的腦＝人直接 `aos-json set <定義>/llm.json#/endpoint sol`。
- **P-24** 想跟做分開：think 問腦、只把「要做什麼」寫進 `$AOS_STACK/plan.txt`；act 照 plan 動手、不問腦。能寫死的步驟（搬檔、寫檔）放在 act 這種程式格，不交給模型。agent-eve 這類範本（已刪）沒有 `plan.txt`——腦的決定（`$AOS_STACK/history.jsonl` 最後一則 assistant）就是 plan，act 照它叫工具或交答案、不問腦（P-41）。（C-22 能寫死的節點換成程式；C-25）
- **P-25** 工具＝`tools/<名>/` 子資料夾程式，**放在叫它的那一格的資料夾裡**（`act/tools/cathy/`），格裡寫 `aos-exec tools/<名>`：地址是從自己 cwd 起算的相對路徑、永遠零個 `..`、不靠 PATH；`AOS_WS` 自然傳下去（要換工作區見 P-32）；工具要不要碰工作區、怎麼碰，是工具自己的事、風險設計者自管；工具裡是不是另一個 agent，呼叫者不知道也不管。stack 照 P-17。細節與理由見 P-33。（C-61 不用 PATH、地址在自己資料夾裡；N-55；C-66；C-52）
  - **10-28 補：格也走註冊檔**（使用者 10-28「全部走註冊檔好了，捷徑就是方便使用」「註冊檔案中沒寫的，那就是走固定名字」「撞到就撞到。反正我是覺得我們這個比較先進」，[thinking 10-28 agent-ops 決定 10、16](../../../thinking/2026-10/28/agent-ops/02-決定.md#決定10-28)；細節照原則代定、可翻案，[agent-round § 格怎麼找](../../../thinking/2026-10/28/agent-round/01-白話版.md#格怎麼找註冊檔--固定名字--預設決定-16)）：腦能叫的工具走 `tools.json`（aos-tools，P-41 的 10-28 加註）；照 round 拆成格的 agent，自己的格（`round`、`queue`、`history`、`act`、`endpoint/<名>`、`hook/<點>`）也走註冊檔——agent 資料夾裡**另一份** `parts.json`，**是 aos-exec 格式的約定**（11-01 使用者裁，[C-74](../../CONCEPTS/01-設計理念/02-C-51.md#分層10-22-使用者定)；槽值＝路徑字串或 `{".env", "_entry"}`、`endpoint`／`hook` 巢狀；沒有管理指令，手寫或用 `aos-json set／del`，器官共用 `lib/agent/parts.py` 找格——`aos-parts` 11-01 已刪），手寫的相對路徑從註冊檔所在資料夾算（`aos-ai spawn` 複製範本時把指出範本的改成絕對）。註冊檔與固定名字共存（11-01 使用者「2.兩者可以共存的。」）：叫一格的查找順序＝**註冊檔 → agent 資料夾裡的固定名字（捷徑、真的資料夾或檔都行）→ 沒有**（掛勾＝沒掛；必要的格＝`PartMissing`）。`..` 只出現在方便用的捷徑與手寫的相對路徑裡。本條「放在叫它的那一格的資料夾裡、零個 `..`」留給沒經 `tools.json`／`parts.json` 的叫法（例 topdown 的 agent、bob 的 `act/tools/cathy`）。 **11-04 加註**（round 已刪後的條文整理，使用者 11-04「照建議」，[收斂報告 § round 刪掉後](../../../../wf/workflows/tidy/reports/2026-11-03-收斂/03-round刪掉後的條文之一.md#round-刪掉後沒實作撐的條文11-04給使用者裁)）：`parts.json` 那半（照 round 拆成格的 agent 自己的格走另一份 `parts.json`、查找順序、`PartMissing`）已無實作：round 那套已刪，現有程式沒有讀 `parts.json` 的；腦能叫的工具走 `tools.json`（aos-tools）照舊。
- **P-26** 工具的參數怎麼進（args、stdin、或 stack 裡的檔）由工具自己的說明定；aos-exec 保證 args 與 stdin 原樣送到。（§ 4）入口是單子時也成立：args 接在單子 `argv` 的尾巴，單子沒寫 `stdin` 就接呼叫者的（§ 20 使用者沒異議、照預設「串流沒寫＝接呼叫者的」）；單子自己寫了 `stdin: 檔` 是它自己選的，不算 aos-exec 沒送到。
