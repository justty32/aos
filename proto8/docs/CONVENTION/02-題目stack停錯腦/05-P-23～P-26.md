## 七、腦與工具

- **P-23** 腦＝**寄一封請求信給 llm kernel、之後收回信**（使用者 11-04 晚「brain url那塊我不喜歡，我希望llm呼叫，或者說思考，這本身也是用aos函數」「llm呼叫這塊，我希望是把請求丟到llm kernel(一個loop)，處理好後收回信」「也可以是一個daemon，實際endpoint呼叫就是aos exec」「包起來的」「我是希望走2」，[thinking 11-04 think-as-function](../../../thinking/2026-11/04/think-as-function/README.md)；細節 fable 代定、可翻案，四題使用者選推薦，[05 衝突與方向題](../../../thinking/2026-11/04/think-as-function/05-衝突與方向題.md)）。agent 把 OpenAI chat completions 形狀的請求寫成信，body＝`{"endpoint"?, "request", "priority"?}`，寄進 llm kernel 的信箱 `$AOS_LLM_KERNEL/requests/`（`AOS_LLM_KERNEL`＝llm kernel 的 stack，N-63 ②；沒設＝`LlmKernelMissing`；信箱名跟判官的收件箱同名，C-54 R14，使用者 11-06 選項框「現在統一 requests/」，[mailbox-naming](../../../thinking/2026-11/06/mailbox-naming/README.md)）；回信 body＝`{"message", "usage", "model"}` 或 `{"error": {"code", "msg"}}`（N-42 (1)、N-16）。寄信收信用基礎工具 [aos-llm](../../../impls/aos-llm/README.md)（使用者 11-04 晚「然後aos llm,tool這兩個，我希望他們的定位是跟aos post一樣，作為基礎工具」，選「aos-llm＝寄收信工具」）：`send [--priority P] --reply-to BOX`（stdin＝整份 body，印信件名稱、馬上回）、`recv BOX 名`（0 到／10 沒到／1 錯）、同步 `ask`（共用回信信箱 `<stack>/requests/reply/`）、撤回 `regret`、列能力包 `ls`。**非同步**：寄完那格就退、loop 照跑，下一格再收（使用者 11-04 晚「並且可以的話，考慮非同步呼叫，也就是正在跑的loop不停。」）。agent 問腦只走 llm kernel：範本不另把 `llm_http` 登記成工具直連端點，沒有 kernel 就問不了腦（使用者選「只走 kernel」，[四題裁定](../../../thinking/2026-11/04/think-as-function/05-衝突與方向題.md)）。
  **端點、模型、金鑰只在 kernel 的 `kernel.json`**：`endpoints` 代號表、預設代號 `endpoint`；**agent 只知道代號**（使用者 11-04 晚「各種llm設定也可以包裝，這樣寄信的時候只要寫簡單的代號就可以」）。一組代號是一個**能力包**（使用者 11-05 午「把endpoint打包成smart-high, stupid-fast, ...這類，並且附上各種屬性(各種temperature也固定)」，細節 fable 代定、可翻案，[feat-proto 02](../../../thinking/2026-11/05/feat-proto/02-endpoint-packs.md) 代定 2～4）：`url`／`model`／`key`／**`fixed`**，或自己的 `exec`；`fixed` 是釘死的（`llm_http`：request 先、`fixed` 蓋上、`model` 用包的；信寫了被釘的 key，或那包有 `model` 時信寫 `model`＝kernel 回 `RequestBad`，N-42 (1)）；信改不了 `url`／`key`。**換模型＝換代號**（多登記一包），brain 不寫 `request.model`；有哪些包＝`aos-llm ls`。範本代號 `smart-high`、`stupid-fast`、`luna`、`sol`、`fake`，劇本假腦 `fake-demo-*`；預設代號 `fake`；`luna`／`sol` 走家機 LiteLLM `http://localhost:4000/v1`（不用 key），`luna`＝`chatgpt-gpt-6-luna-low`（使用者 10-23「盡量都用gpt的」）；kernel 範本 [kernel/llm-kernel](../../../kernel/docs/01-llm-kernel.md)。假腦＝kernel 的一組代號（`fake`，exec 指 `lib/base/llm_fake`）。
  agent-fsm 用哪包寫在定義的 `llm.json` 的鍵 `model`（值是能力包代號；`interfaces.json` 宣告 `"llm": "llm.json"`，P-43（續）；使用者 11-10 晚「3.把fsm認的endpoint這個key，也改名爲model吧...麻煩的話就算了。」，[self-tools 05](../../../thinking/2026-11/10/self-tools/05-llm設定改名與ls.md)），brain 把它填進請求信 body 的 `endpoint`（請求信與 `kernel.json` 的鍵仍叫 `endpoint`）；`$AOS_STACK/llm.json`（`aos-agent llm set` 寫的副本，只放改過的鍵，P-15）有的鍵蓋過定義，每題重讀；都沒寫＝信不寫 `endpoint`、kernel 用預設那包。改定義裡的腦＝人直接 `aos-json set <定義>/llm.json#/model sol`。
  只取回覆的 `content`（有工具時加 `tool_calls`），模型想的內容不收、不存（由 endpoint 函數剪）（使用者 10-15「維持 openai 格式」「模型想的內容丟掉」（[thinking 10-15 topics/02](../../../thinking/2026-10/15/topics/02-agent工具與試146.md)）；§ 6）。用量在回信的 `usage` 裡，kernel 拿它記 token、算額度；usage 不進 history。agent-fsm 的 think 組請求、wait 寄＋收（P-41）。eca 不經 kernel（腦是 CLI）：模型放定義 `llm.json` 的 `model`、副本照上面蓋，[lib/agent/cli_session.py](../../../lib/agent/cli_session.py) 組旗標時補 `--model`。
- **P-24** 想跟做分開：think 問腦、只把「要做什麼」寫進 `$AOS_STACK/plan.txt`；act 照 plan 動手、不問腦。能寫死的步驟（搬檔、寫檔）放在 act 這種程式格，不交給模型。agent-eve 這類範本（已刪）沒有 `plan.txt`——腦的決定（`$AOS_STACK/history.jsonl` 最後一則 assistant）就是 plan，act 照它叫工具或交答案、不問腦（P-41）。（C-22 能寫死的節點換成程式；C-25）
- **P-25** 工具＝`tools/<名>/` 子資料夾程式，**放在叫它的那一格的資料夾裡**（`act/tools/cathy/`），格裡寫 `aos-exec tools/<名>`：地址是從自己 cwd 起算的相對路徑、永遠零個 `..`、不靠 PATH；`AOS_WS` 自然傳下去（要換工作區就明給 `--ws`，N-58）；工具要不要碰工作區、怎麼碰，是工具自己的事、風險設計者自管；工具裡是不是另一個 agent，呼叫者不知道也不管。stack 照 P-17。共用的工具不各自複製：收在函式庫 `proto8/lib/`、掛捷徑或登記引用（C-61）。細節與理由見 P-33。（C-61 不用 PATH、地址在自己資料夾裡；N-55；C-66；C-52）
  腦能叫的工具走登記檔 `tools.json`（aos-tools，P-41）；`..` 只出現在方便用的捷徑與手寫的相對路徑裡；本條「放在叫它的那一格的資料夾裡、零個 `..`」管的是沒經 `tools.json` 的叫法（例 bob 的 `act/tools/cathy`）。
- **P-26** 工具的參數怎麼進（args、stdin、或 stack 裡的檔）由工具自己的說明定；aos-exec 保證 args 與 stdin 原樣送到。（§ 4）入口是單子時也成立：args 接在單子 `argv` 的尾巴，單子沒寫 `stdin` 就接呼叫者的（§ 20 使用者沒異議、照預設「串流沒寫＝接呼叫者的」）；單子自己寫了 `stdin: 檔` 是它自己選的，不算 aos-exec 沒送到。
