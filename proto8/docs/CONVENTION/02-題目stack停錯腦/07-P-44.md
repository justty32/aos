## 十三、命令列

- **P-44 aos 自己程式的命令列形狀**（11-04；使用者 11-04 題 7「只進 CONVENTION 當慣例」，[four-elements 06](../../../thinking/2026-11/04/four-elements/06-要使用者裁的題.md)、實作步驟 [07](../../../thinking/2026-11/04/four-elements/07-實作步驟.md) 步 2）：規範層只定 aos-exec 的命令列（[N-58](../../NORMS/10-基礎設施-定義與工作區/02-N-58.md)）；我們自己寫的其他程式（impls 的 aos-loop／fsm／daemon／schema／directive，`bin/` 的 aos-tick／aos-tools／aos-daemon-ctl，extras 的 aos-mcp／aos-grow／aos-sandbox／aos-janet…）照同一個形狀，**不要求別人守**：
  - `程式 [旗標...] 位置參數...`：**旗標在位置參數前面**，第一個不是旗標的參數（不以 `-` 開頭，或就是 `-`）起都是位置參數、不再解析旗標；`--` 結束旗標（位置參數可以 `-` 開頭）。有子命令的（aos-tools、aos-daemon-ctl、aos-grow）＝`程式 [旗標...] 子命令 [子命令的旗標...] 位置參數...`。
  - 只有長旗標：帶值的寫 `--x V` 或 `--x=V`，重複給＝最後一個算（明說可重複收的例外，例 aos-grow 的 `--take`）；開關不帶值、寫 `--x=V`＝錯。沒有短旗標。
  - 時間旗標帶單位後綴：`--interval-ms`、`--timeout-s`。
  - 錯：不認得的旗標＝`FlagUnknown`；缺值、開關帶值、位置參數不對＝`ArgumentsBad`；stderr 一行 `程式名: 代號 原因`，原因裡附 usage。**不做 `--help`**（用法寫在各程式的 README 與檔頭）。
  - 實作用同一套：C++ 是 aos-util 的 `aos::parse_cli`（`aos/cli.hpp`），Python 是 [`proto8/bin/aos_flags.py`](../../../bin/aos_flags.py) 的 `parse`；不各自手寫解析器。
