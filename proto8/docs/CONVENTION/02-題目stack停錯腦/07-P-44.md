## 十三、命令列

- **P-44 aos 自己程式的命令列形狀**（11-04；使用者 11-04 題 7「只進 CONVENTION 當慣例」，[four-elements 06](../../../thinking/2026-11/04/four-elements/06-要使用者裁的題.md)、實作步驟 [07](../../../thinking/2026-11/04/four-elements/07-實作步驟.md) 步 2）：規範層只定 aos-exec 的命令列（[N-58](../../NORMS/10-基礎設施-定義與工作區/02-N-58.md)）；我們自己寫的其他程式（impls 的 aos-loop／fsm／daemon／schema／directive，`cmd/` 的 aos-clock／aos-tools／aos-daemon-ctl／aos-mcp／aos-grow／aos-sandbox，extras 的 aos-janet…）照同一個形狀，**不要求別人守**：
  - `程式 [旗標...] 位置參數...`：**旗標在位置參數前面**，第一個不是旗標的參數（不以 `-` 開頭，或就是 `-`）起都是位置參數、不再解析旗標；`--` 結束旗標（位置參數可以 `-` 開頭）。有子命令的（aos-tools、aos-daemon-ctl、aos-grow）＝`程式 [旗標...] 子命令 [子命令的旗標...] 位置參數...`（11-05：aos-eca-screen 也改成這個形狀 `aos-eca-screen open [--detach] ECA_DIR`，照盤點推薦，[thinking 11-05 stdio-unify](../../../thinking/2026-11/05/stdio-unify/README.md) R6）。
  - 長旗標帶值的寫 `--x V` 或 `--x=V`，重複給＝最後一個算（明說可重複收的例外，例 aos-grow 的 `--take`）；開關不帶值、寫 `--x=V`＝錯。短旗標由每支「給人用的指令」各自定，同一短名在不同指令可不同義（11-07 使用者裁定 sol 審查 #22）；共用模組的常用表只是預設，不限制表外短名。（代定（11-07 落實時，可翻案））
  - 時間旗標帶單位後綴：`--interval-ms`、`--timeout-s`。
  - 錯：不認得的旗標＝`FlagUnknown`；缺值、開關帶值、位置參數不對＝`ArgumentsBad`；stderr 一行 `程式名: 代號 原因`，原因裡附 usage。~~**不做 `--help`**（用法寫在各程式的 README 與檔頭）。~~（11-05 作廢，見下面 `--help`）
    **11-05 改**（[thinking 11-05 stdio-unify](../../../thinking/2026-11/05/stdio-unify/README.md) R4、R5）：錯誤行是 `程式名: error: 代號 原因`（[N-43 續](../../NORMS/01-總則/02-N-43續-11-05-兩種行與碼.md)）；usage 放在**原因後面**、括號包起來（照盤點推薦 R5）：`aos-fsm: error: ArgumentsBad missing CONFIG (usage: aos-fsm [FLAGS] CONFIG.json)`，出錯訊息也可以說 `see 程式 --help`。有子命令的：**子命令前**不認得的旗標＝`FlagUnknown`、子命令本身不認得＝`CommandUnknown`（使用者 11-05「FlagUnknown (Recommended)」，R4）。
  - **`--help`**（使用者 11-05「全都有」，並補「--help要輸出英文」，[thinking 11-05 stdio-unify](../../../thinking/2026-11/05/stdio-unify/README.md) R3）：**每支都認 `--help`**——英文用法、印 stdout、退 0；放在旗標的位置就認，子命令後也認（`程式 子命令 --help`）；前一個帶值旗標的值（如 `tool --text --help`）、第一個位置參數後、`--` 後的 `--help` 都是普通值，不印說明。（11-07 使用者裁定 sol 審查 #34-1）**不給參數**照常解析：該有參數卻沒給＝`ArgumentsBad` 退 1、不印說明；說明只在 `--help`。用法仍寫在各程式的 README 與檔頭。
  - 實作用同一套：C++ 是 aos-util 的 `aos::parse_cli`（`aos/util/cli.hpp`），Python 是 [`proto8/py/aos_flags.py`](../../../py/aos_flags.py) 的 `parse`；不各自手寫解析器。（**11-06 改讀**：Python 旗標解析改由 `lib/tool_io.py`，`py/aos_flags.py` 包它的 `tokenize_flags`，仍共用一套；使用者「P-44改吧」，已定（11-05，[json-argv 07](../../../thinking/2026-11/05/json-argv/07-使用者回覆-11-05晚.md)）；11-06 J5 已實作（`92717ee3`）：`aos_flags.parse` 包 `tool_io.tokenize_flags`，短名與 help 時機照舊，見 [J5 結果](../../../thinking/2026-11/05/json-argv/10-J3到J7實作結果.md#j5-aos_flags-去重sigpipe)。）

### 給人用的指令（11-06 註）

給人（或用 shell 工具的 agent）操作的指令，照 unix／linux 習慣、以人為主、要有 `--help`，見 [C-82](../../CONCEPTS/05-agent/02-agent-的工具與agent-就是一台狀態機.md)；使用者原話與裁定見 [human-cli](../../../thinking/2026-11/06/human-cli/README.md)。純 aos 函數的補充旗標見 [P-45](08-P-45.md)。

- **短旗標各支自定**：每支定自己的短名，可不同義（11-07 使用者裁定 sol 審查 #22）；`aos_flags.SHORT` 與 aos-util 常用表只是預設，呼叫端可傳自己的對照表。（代定（11-07 落實時，可翻案））help 旗標行寫成 `-j, --json`。
- **不手寫 man**：`--help` 是一屏版、README 是長版；真要 man 就從 `--help` 生成。已定（11-06，[方向題 3](../../../thinking/2026-11/06/human-cli/06-方向題.md)）；現況沒有手寫 man，生成等需要才做。
- **不可逆子命令**：stdin 是終端才問 `[y/N]`，非終端不問、照做；一律提供 `--yes`／`-y` 跳過，答 No 退 0、加提醒行 `程式: warning: nothing done`。清單只有 `aos-agent ctl rm`、`aos-agent tools reset`、`aos-agent llm reset`；判準是「刪掉的東西別處沒有副本、而且沒有 `--dry-run`」，不含 aos-tools rm、aos-json del。已定（11-06，使用者「不可逆動作那塊，幫我加上--yes跳過」，[裁定](../../../thinking/2026-11/06/human-cli/README.md)、[新題 1](../../../thinking/2026-11/06/human-cli/06-方向題.md)）；答 No 的細節是 fable 代定，見 [H11](../../../thinking/2026-11/06/human-cli/03-慣例草案-續.md)；11-06 已實作（S8-0 `confirm` `8d400c74`、S8-b 三個子命令 `f6578378`）。

- **先不做的**：`--version`、`--quiet`／`--verbose`、顏色、進度條都不做。（11-07 使用者裁定，出處 [wf/workflows/refactor/reports/2026-11-07-sol審查/11-使用者裁定.md](../../../../wf/workflows/refactor/reports/2026-11-07-sol審查/11-使用者裁定.md) #34-3）
