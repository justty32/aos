## 十三、命令列

- **P-44 aos 自己程式的命令列形狀**（使用者 11-04 題 7「只進 CONVENTION 當慣例」，[four-elements 06](../../../thinking/2026-11/04/four-elements/06-要使用者裁的題.md)、實作步驟 [07](../../../thinking/2026-11/04/four-elements/07-實作步驟.md) 步 2）：規範層只定 aos-exec 的命令列（[N-58](../../NORMS/10-基礎設施-定義與工作區/02-N-58.md)）；我們自己寫的其他程式（impls 的 aos-loop／fsm／daemon／directive，`cmd/` 的 aos-clock／aos-tools／aos-daemon-ctl／aos-mcp／aos-grow／aos-sandbox，extras 的 aos-janet…）照同一個形狀，**不要求別人守**：
  - **旗標寫在它那一層名字之後的任何位置**（使用者「1.收。2.收。3.好。」）；規則、停止解析的位置與例外見 [續](07-P-44續-11-10-旗標位置.md)。
  - 長旗標帶值的寫 `--x V` 或 `--x=V`，重複給＝最後一個算（明說可重複收的例外，例 aos-grow 的 `--take`）；開關不帶值、寫 `--x=V`＝錯。短旗標由每支「給人用的指令」各自定，同一短名在不同指令可不同義（使用者裁定 sol 審查 #22）；共用模組的常用表只是預設，不限制表外短名（代定、可翻案）。
  - 時間旗標帶單位後綴：`--interval-ms`、`--timeout-s`。
  - 錯：不認得的旗標（有子命令的，含子命令前的）＝`FlagUnknown`（使用者 11-05「FlagUnknown (Recommended)」，[thinking 11-05 stdio-unify](../../../thinking/2026-11/05/stdio-unify/README.md) R4）；子命令本身不認得＝`CommandUnknown`；缺值、開關帶值、位置參數不對＝`ArgumentsBad`。stderr 一行 `程式名: error: 代號 原因`（[N-43 續](../../NORMS/01-總則/02-N-43續-11-05-兩種行與碼.md)）；usage 放在**原因後面**、括號包起來（照盤點推薦 R5）：`aos-fsm: error: ArgumentsBad missing CONFIG (usage: aos-fsm [FLAGS] CONFIG.json)`，出錯訊息也可以說 `see 程式 --help`。
  - **`--help`**（使用者 11-05「全都有」，並補「--help要輸出英文」，[thinking 11-05 stdio-unify](../../../thinking/2026-11/05/stdio-unify/README.md) R3）：**每支都認 `--help`**——英文用法、印 stdout、退 0；放在旗標的位置就認，子命令後、動作的位置參數後也認（`程式 子命令 --help`，見續）；前一個帶值旗標的值（如 `tool --text --help`）、`--` 後、以及停止解析的位置之後（續的「之後停止解析」與照舊規則的那幾處）的 `--help` 都是普通值，不印說明（使用者裁定 sol 審查 #34-1）。**不給參數**照常解析：該有參數卻沒給＝`ArgumentsBad` 退 1、不印說明；說明只在 `--help`。用法仍寫在各程式的 README 與檔頭。
  - 實作用同一套：C++ 是 aos-util 的 `aos::parse_cli`（`aos/util/cli.hpp`），Python 是 [`proto8/py/aos_flags.py`](../../../py/aos_flags.py) 的 `parse`，它切 token 包 `lib/tool_io.py` 的 `tokenize_flags`（使用者「P-44改吧」，[json-argv 07](../../../thinking/2026-11/05/json-argv/07-使用者回覆-11-05晚.md)、[J5](../../../thinking/2026-11/05/json-argv/10-J3到J7實作結果.md#j5-aos_flags-去重sigpipe)）；不各自手寫解析器。
  - **替別人帶環境變數**：`--env-file FILE`（`.env` 格式）與可重複的 `--envs K=V` 並存，不收 `--env K=V`；值不給腦看（使用者「或者改成--env-file xxx搭配--envs K=V...也不錯，兩者並存吧。」，[no-pid 03](../../../thinking/2026-11/05/no-pid/03-找daemon與脫鉤.md)）。aos-tools add 與 `aos-agent tools add` 收同一組旗標（`--name`、`--envs`、`--env-file`、`--path-json`、`--replace`、`--no-cache`，[cli-sweep](../../../thinking/2026-11/10/cli-sweep/README.md) Q8「改」）。`--envs K=V` 記值進登記格 `env`；`--env-file` 只記檔案位置（登記格 `env_file`），每次 `call` 才讀、檔不在報錯不跑（使用者 Q1「只記位置」、N4「報錯不跑」，[aos-tools-cli](../../../thinking/2026-11/10/aos-tools-cli/README.md)）。call 時後面的贏：繼承環境 ＜ `env_file` ＜ `env` ＜ `AOS_STACK`——`AOS_STACK` 只由父 stack 算小格、無父時交 aos-exec 給預設，登記格不得覆蓋。
  - tool_io 的 schema `array` 旗標可重複，每次收一個元素；同一旗標的各次值累加、覆蓋 stdin 的同鍵陣列（[J1](../../../thinking/2026-11/05/json-argv/08-J1實作結果.md)）。

### 給人用的指令

給人（或用 shell 工具的 agent）操作的指令，照 unix／linux 習慣、以人為主、要有 `--help`，見 [C-82](../../CONCEPTS/05-agent/02-agent-的工具與agent-就是一台狀態機.md)；使用者原話與裁定見 [human-cli](../../../thinking/2026-11/06/human-cli/README.md)。純 aos 函數的補充旗標見 [P-45](08-P-45.md)。

- **短旗標各支自定**：每支定自己的短名，可不同義（使用者裁定 sol 審查 #22）；`aos_flags.SHORT` 與 aos-util 常用表只是預設，呼叫端可傳自己的對照表（代定、可翻案）。help 旗標行寫成 `-j, --json`。
- **`--help` 分層**：每個子命令一份自己的英文 `--help`——頂層一屏、子命令一屏、長篇規則放 README；錯誤行後面只接**那個子命令**的 usage 或 `see 程式 子命令 --help`（代定、可翻案，[human-cli 03 H6](../../../thinking/2026-11/06/human-cli/03-慣例草案.md#h6---help-的形狀英文中文與長篇進-readme)）。
- **人看的輸出與 `--json`**：會列資料的子命令都有 `-j`／`--json`；人看的輸出一列一筆、TAB 分欄、沒有表頭（欄名寫在 `--help`）；清單空＝stdout 空、退 0（代定、可翻案，[human-cli 03 H8](../../../thinking/2026-11/06/human-cli/03-慣例草案.md#h8-人看的輸出-vs---json)）。
- **列表預設短版**：有短版、長版之分的列表（指令與給腦的工具都算），預設都是短版；`-l`／`"long"` 是長版、`--json`／`"json"` 是全份（使用者 11-10「其他我記得還有一些地方也是有短版長版之分的，也幫我改成默認都短板吧。」，[tonight-rulings](../../../thinking/2026-11/10/tonight-rulings/README.md#項-b有短版長版之分的預設都是短版)）。`aos-agent history ls` 預設只印最後 20 則、先一行講省略了幾則（使用者答「1.好。2.好。3.好。3.好。」，第二個 3 讀成這第 4 題；20 則是代定、可翻案，[同上 第四批](../../../thinking/2026-11/10/tonight-rulings/README.md#第四批11-10-深夜最後一輪)）。
- **不手寫 man**：`--help` 是一屏版、README 是長版；真要 man 就從 `--help` 生成，等需要才做（[方向題 3](../../../thinking/2026-11/06/human-cli/06-方向題.md)）。
- **不可逆子命令**：stdin 是終端才問 `[y/N]`，非終端不問、照做；一律提供 `--yes`／`-y` 跳過，答 No 退 0、加提醒行 `程式: warning: nothing done`。清單：`aos-agent` 的 `ctl rm --purge`、`tools reset`、`llm reset`、`system reset`、`hook reset`、`goal clear`、`history rm`／`summarize`／`set` 的 `--no-keep`，以及 `aos-daemon-ctl sweep --purge`；`aos-agent ctl rm` 預設留 stack、不問，加 `--purge` 才刪 stack（使用者 11-10「兩支都留 stack，要刪另外說」，[cli-sweep](../../../thinking/2026-11/10/cli-sweep/README.md#使用者已答的11-10頂層轉達都只記裁定還沒施工) Q3）；清單就是程式裡會問 `[y/N]` 的那些，新子命令要問就加進來，不含 aos-tools rm、aos-json del（使用者「不可逆動作那塊，幫我加上--yes跳過」，[裁定](../../../thinking/2026-11/06/human-cli/README.md)、[新題 1](../../../thinking/2026-11/06/human-cli/06-方向題.md)）；答 No 的細節是 fable 代定，見 [H11](../../../thinking/2026-11/06/human-cli/03-慣例草案-續.md)；共用確認在 `aos_flags` 的 `confirm`。

- **先不做的**：`--version`、`--quiet`／`--verbose`、顏色、進度條都不做（使用者裁定，出處 [wf/workflows/refactor/reports/2026-11-07-sol審查/11-使用者裁定.md](../../../../wf/workflows/refactor/reports/2026-11-07-sol審查/11-使用者裁定.md) #34-3）。
