## 十三、命令列

- **P-44 aos 自己程式的命令列形狀**（11-04；使用者 11-04 題 7「只進 CONVENTION 當慣例」，[four-elements 06](../../../thinking/2026-11/04/four-elements/06-要使用者裁的題.md)、實作步驟 [07](../../../thinking/2026-11/04/four-elements/07-實作步驟.md) 步 2）：規範層只定 aos-exec 的命令列（[N-58](../../NORMS/10-基礎設施-定義與工作區/02-N-58.md)）；我們自己寫的其他程式（impls 的 aos-loop／fsm／daemon／schema／directive，`cmd/` 的 aos-tick／aos-tools／aos-daemon-ctl／aos-mcp／aos-grow／aos-sandbox，extras 的 aos-janet…）照同一個形狀，**不要求別人守**：
  - `程式 [旗標...] 位置參數...`：**旗標在位置參數前面**，第一個不是旗標的參數（不以 `-` 開頭，或就是 `-`）起都是位置參數、不再解析旗標；`--` 結束旗標（位置參數可以 `-` 開頭）。有子命令的（aos-tools、aos-daemon-ctl、aos-grow）＝`程式 [旗標...] 子命令 [子命令的旗標...] 位置參數...`（11-05：aos-eca-screen 也改成這個形狀 `aos-eca-screen open [--detach] ECA_DIR`，照盤點推薦，[thinking 11-05 stdio-unify](../../../thinking/2026-11/05/stdio-unify/README.md) R6）。
  - 只有長旗標：帶值的寫 `--x V` 或 `--x=V`，重複給＝最後一個算（明說可重複收的例外，例 aos-grow 的 `--take`）；開關不帶值、寫 `--x=V`＝錯。沒有短旗標。
  - 時間旗標帶單位後綴：`--interval-ms`、`--timeout-s`。
  - 錯：不認得的旗標＝`FlagUnknown`；缺值、開關帶值、位置參數不對＝`ArgumentsBad`；stderr 一行 `程式名: 代號 原因`，原因裡附 usage。~~**不做 `--help`**（用法寫在各程式的 README 與檔頭）。~~（11-05 作廢，見下面 `--help`）
    **11-05 改**（[thinking 11-05 stdio-unify](../../../thinking/2026-11/05/stdio-unify/README.md) R4、R5）：錯誤行是 `程式名: error: 代號 原因`（[N-43 續](../../NORMS/01-總則/02-N-43續-11-05-兩種行與碼.md)）；usage 放在**原因後面**、括號包起來（照盤點推薦 R5）：`aos-fsm: error: ArgumentsBad missing CONFIG (usage: aos-fsm [FLAGS] CONFIG.json)`，出錯訊息也可以說 `see 程式 --help`。有子命令的：**子命令前**不認得的旗標＝`FlagUnknown`、子命令本身不認得＝`CommandUnknown`（使用者 11-05「FlagUnknown (Recommended)」，R4）。
  - **`--help`**（使用者 11-05「全都有」，並補「--help要輸出英文」，[thinking 11-05 stdio-unify](../../../thinking/2026-11/05/stdio-unify/README.md) R3）：**每支都認 `--help`**——英文用法、印 stdout、退 0；放在旗標的位置就認，子命令後也認（`程式 子命令 --help`）。**不給參數**照常解析：該有參數卻沒給＝`ArgumentsBad` 退 1、不印說明；說明只在 `--help`。用法仍寫在各程式的 README 與檔頭。
  - 實作用同一套：C++ 是 aos-util 的 `aos::parse_cli`（`aos/cli.hpp`），Python 是 [`proto8/py/aos_flags.py`](../../../py/aos_flags.py) 的 `parse`；不各自手寫解析器。
