## P-44 續：旗標寫在哪（11-10）

**原條文（11-04，11-10 被下面翻掉，逐字留存）**：~~`程式 [旗標...] 位置參數...`：**旗標在位置參數前面**，第一個不是旗標的參數（不以 `-` 開頭，或就是 `-`）起都是位置參數、不再解析旗標；`--` 結束旗標（位置參數可以 `-` 開頭）。有子命令的（aos-tools、aos-daemon-ctl、aos-grow）＝`程式 [旗標...] 子命令 [子命令的旗標...] 位置參數...`（11-05：aos-eca-screen 也改成這個形狀 `aos-eca-screen open [--detach] ECA_DIR`，照盤點推薦，[thinking 11-05 stdio-unify](../../../thinking/2026-11/05/stdio-unify/README.md) R6）。~~

**11-10 改**（[cli-sweep 10d](../../../thinking/2026-11/10/cli-sweep/10d-施工結果-Q1旗標位置.md)）。使用者白天說：「旗標也可以寫在子命令前面，但這樣就等同於aos-yyy zzz [flags] XXX [flags] QQQ。因為zzz有個意義：aos-yyy-zzz和aos-yyy zzz相等。所以其實都可以。」三題答「1.收。2.收。3.好。」：

- **規則**：指令的每一層（程式、子命令、動作）是一個節點。屬於某一層的旗標，可以寫在那一層名字之後的任何位置：緊接著寫，或隔了下一層的名字、位置參數再寫，都算。例：`aos-agent ctl stop ann -d D` ＝ `aos-agent -d D ctl stop ann`；`aos-tools add tools/clock --name now` ＝ `aos-tools add --name now tools/clock`。舊寫法全部照樣能用。
- **名字放最後**（題 2）：`aos-agent ctl` 裡只對一隻做事的動作（start、stop、sleep、wake、pause、resume、where）收 `-t NAME`，也收最後一個位置參數 NAME；兩個都給又不同＝`ArgumentsBad`。say、listen、tools、llm、history、hook 只用 `-t`。
- **之後停止解析**（題 3）：`--` 之後都不是旗標。要原樣交給別人的那類位置參數，從它起也不解析：`aos-daemon-ctl add XXX -- ARGS`、`aos-exec XXX args`。（代定）訊息與內容也算這一類：`aos-agent say` 的 WORDS、`history summarize` 的 TEXT、`history set` 的 JSON、`aos-mailbox send` 的 WHAT、`aos-clock-register add` 的 TEXT。旗標要寫在它們前面。
- **同名**：下層有同名旗標時算下層的（例：`aos-agent say -t` 是 say 自己的 `-t`）。重複給照舊＝最後一個算；有「前後給了不同值＝ArgumentsBad」規則的（aos-agent 的 `-t`、aos-tools 的 `--file`、aos-mailbox 的 `-s`、aos-clock-register 的 `-c`）照舊。
- **錯**：位置參數後寫了不認得的旗標＝`FlagUnknown`。例外：（代定）位置參數後像負數（`-3`、`-.5`）或含空白（`"- 一條摘要"`）的字，照舊當位置參數。`--help` 寫在動作的位置參數後也印說明。
- **已照新規則的**：aos-agent、aos-daemon-ctl、aos-grow、aos-tools、aos-mailbox、aos-clock-register（Python `aos_flags.parse` 的 `sub="root"`／`sub=True`／`keep`）。**還是舊規則**（第一個位置參數起不再解析）：aos-mcp、aos-sandbox、aos-clock、aos-sweeper、aos-feedback、aos-eca-turn／aos-eca-screen，以及 C++ 的 `aos::parse_cli`（impls）。之後要不要一起改，沒裁。
  - **11-11 已裁**：使用者選項框選「全部改」（[11-11 carry-over](../../../thinking/2026-11/11/carry-over.md) 待裁 1）。施工：Python 那幾支換成同一套共用解析（只有一層的程式 `aos_flags.parse(..., anywhere=True)`；aos-eca-screen、aos-feedback 照子命令程式 `sub="root"`），C++ 只改 aos-util 的 `parse_cli` 一處（旗標寫在位置參數前後都收、像負數或含空白的字照舊當位置參數、`--` 在位置參數後連它原樣交出、`keep`＝第 N 個位置參數起原樣），零件全家跟著。**照舊規則的**（語意衝突、不硬套）：子命令程式的頂層（aos-post、aos-lock、aos-json、aos-llm 解到子命令名為止，子命令那層才收）；`aos-exec XXX ARGS`（XXX 起原樣交給它）；`aos-json set／append／merge`（值什麼字都可以，`--str` 時 `-x`、`--check` 也是合法值，FILE 後再認旗標會把值吃掉，所以旗標照舊寫在 FILE 前）；`aos-sandbox CONFIG PROG ARGS` 的 PROG 起原樣；訊息與內容那類（上面「之後停止解析」）不變。agent-fsm 範本的四格（idle、brain、act、wait）是 loop 叫的、argv 固定，這次沒動。
- **aos-eca-screen**：原條文那句寫 `aos-eca-screen open [--detach] ECA_DIR`，已過時。現在是 `aos-eca-screen --eca ECA_DIR SUBCOMMAND [FLAGS...]`，指令本身這次不動。
