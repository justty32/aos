- **P-43 外部 coding agent（eca）的定義**（使用者 10-30「都照建議」，[thinking 10-30 eca](../../../thinking/2026-10/30/eca/09-方向題.md#決定10-30) B 結論 1、2、5、條文草稿、衝突 5、方向題 2、3；[10-29 agent-bob](../../../thinking/2026-10/29/agent-bob/04-頂層對八題的再想.md#決定10-30) 決定 33～35；照實作寫，[bin/aos-eca-turn](../../../py/aos/apps/eca/README.md)）：claude code、codex 這類外部 coding agent 要進 aos，**包成一個資料夾程式**：`_entry` 是 aos-loop（`["aos-loop", "loop.json"]`）、`loop.json` 開 ctl／state 窗、`loop.json` 直接叫 PATH 上的 `aos-eca-turn`（`proto8/py/aos/apps/eca/`）：`["aos-eca-turn", "--on-empty", "idle", "--on-busy", "yield", {"$env": "AOS_CD"}]`；頂層 `cli.json` 寫 `kind`（`claude`／`codex`）與旗標；範本是 `templates/agents/eca-claude`（方向題 3；codex 版只差 cli.json 的 kind 與旗標，沒有另放範本），範本多的 `interfaces.json`、`screen/`、`llm.json` 見 [P-43（續）](03-P-43續-11-04-aos-agent.md)。它不是 aos agent 的腦，是**平級的另一隻 agent**（使用者 10-30）；它內部是黑盒子，aos 只碰它的 stack 三樣（P-42）與它自己的 session 檔（拿到 session id 就在小格建 `transcripts/<kind>-<id>.jsonl` symlink，決定 35）。（map-review 第 3、5 點；決定 33～35；C-52、C-56、C-65、C-75；N-53、N-63；P-15、P-20、P-41、P-42）
  - **跟 aos 自己的範本 `templates/agents/agent-fsm` 比，照實際寫**（待裁網頁 條文-5 選 A）：一樣的是 `loop.json` 開 ctl／state／state_flux 三個窗、`on_start`／`on_stop` 掛 `py/tools/agent/hook_fire`，stack 裡對外的三樣 queue／history／ctl・state（P-42），定義裡有 `tools.json`、`llm.json`、`hooks.json`、`interfaces.json`。入口不一樣：eca 的 `_entry` 直接是 aos-loop；agent-fsm 的 `_entry` 是 `aos-agent ctl add`（掛上 daemon），身體的入口另放 `body.json`（P-05）。身體也不一樣：eca 的 `loop.json` 叫 aos-eca-turn、多 `cli.json` 與 `screen/`；agent-fsm 的叫 `fsm.json` 四格。其他不一樣的地方記在[對照表](../../../thinking/2026-11/04/loop-fsm-agent/02-跟-eca-對照.md#條文要加的註實作時一起11-04-註條文原字不動)（使用者 11-04「接下來是弄aos loop/fsm agent了」、看完規劃四題都選建議並說「記完就實作」）。
