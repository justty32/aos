- **P-11** 題目＝`$AOS_WS/new/<題名>`，純文字、一題一檔；開始做時把題目搬到 `$AOS_WS/cur/<題名>`（認領）；答案＝`$AOS_WS/out/<題名>`，跟題目同名；做完把題目從 `cur/` 搬到 `$AOS_WS/done/<題名>`。階段名照 Maildir：`new/`＝還沒做、`cur/`＝已認領處理中、`done/`＝做完；`out/` 是產出放的地方、不是階段名（使用者 10-23 選「改成一致的階段名」）。**結果＝工作區內容，沒有別的結果通道。**（拍板點 2；C-65 工作區只放交辦的東西與成果；C-34 求值＝空間狀態的變化。這是 agent-bob 的做法；「agent 之間傳題目走 inbox」當共同形狀，inbox 先不管〔使用者 10-19；現行資料夾名是 `new/`〕，不當規則）**10-29 加註**：題目信箱（`$AOS_WS/new cur out done`，一題一檔）是 agent 慣例自己的簡化信箱，**不算** [N-16](../../NORMS/05-基礎設施-窗/05-N-16.md) 的標準投遞（沒有 `tmp/`、沒有 `letter.json` 信封，答案另放 `out/`）；照舊用，新東西才走標準（使用者 10-29「都照建議」，[thinking 10-29 medium-plan](../../../thinking/2026-10/29/medium-plan/README.md) 決定 2）。
  - **10-30 改口：aos agent 的輸入是 queue**（使用者 10-30「這一層更接近訊息的queue概念」、看完規劃回「都照建議」，[10-29 agent-bob](../../../thinking/2026-10/29/agent-bob/04-頂層對八題的再想.md#決定10-30) 決定 33、35、36，[thinking 10-30 agent-lifecycle](../../../thinking/2026-10/30/agent-lifecycle/07-衝突.md#決定10-30) 條文草稿、衝突 1、4、5、方向題 1）：上面「題目＝`$AOS_WS/new/<題名>`……答案＝`$AOS_WS/out/<題名>`」整段改讀成——**aos agent 的輸入是 queue**：`$AOS_STACK/queue/`，一個 [N-16](../../NORMS/05-基礎設施-窗/05-N-16.md) 的**有順序信箱**（N-16 的 10-30 加註），一封信＝一則訊息（`body` 是一則 OpenAI message 物件，照 P-41 history 的一行；不是 message 物件＝壞信，人一律經 aos-say〔11-04 併進 aos-agent：`aos-agent say`，P-42 的 11-04 註〕，衝突 5）；agent 認領（rename 進 `cur/`）就把 `body` 接進 `history.jsonl`，答完（assistant 那則已進 history）才把信收掉（預設刪、要留紀錄進 `done/`）。**回答就是 history 最新那則 assistant，沒有別的回答通道**；檔案成品照舊落在工作區（「結果＝工作區內容」那句只管檔案）。原本的 `new/`、`cur/`、`out/`、`done/` 四格留給 10-30 前的 fsm 範本（agent-bob／ann／dan、topdown），標**舊協議**，新東西不用；aos-say／aos-listen〔11-04 併進 aos-agent〕不再認它（衝突 4；哪隻舊範本真要再用才只搬那隻，方向題 1）。誰說、誰看、誰停見 P-42。（決定 33、35；N-16；C-65 執行中的東西落 stack〔C-65 的 10-30 改口〕；C-56） **11-04 加註**（aos-post 改版，使用者 11-03 晚「aos-post這塊都按照建議。」，[thinking 11-03 aos-post](../../../thinking/2026-11/03/aos-post/README.md)）：「要留紀錄進 `done/`」照 `archive/` 讀（aos-post 的歸檔格改名，N-16 的 11-04 改口）；queue 同一個信箱也收無序的信，排在有序的後面（同上）。 **11-04 加註**（loop／fsm agent，使用者 11-04 衝突 1 選「接進對話紀錄就收」，[thinking 11-04 loop-fsm-agent](../../../thinking/2026-11/04/loop-fsm-agent/04-衝突與方向題.md#決定11-04使用者)）：走 queue 的 agent，「答完（assistant 那則已進 history）才把信收掉」改讀成**接進 `history.jsonl` 那刻就收掉**（`aos-post done`）——跟外部 coding agent「交給 CLI 就算完成」（P-12、P-43 的 11-03 註）同一個做法；信的內容已在 history，`cur/` 不再留一份。沒答完的那題看 history 尾巴是不是 user（加上 `state.txt` 停在哪格），不看 `cur/`；`cur/` 只剩認領了還沒接進 history 的（例：idle 在兩步之間被殺）。範本 `demo/agent-fsm`。
