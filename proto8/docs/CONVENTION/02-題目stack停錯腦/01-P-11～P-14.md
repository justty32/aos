## 四、題目與答案

- **P-11** **aos agent 的輸入是 queue**：`$AOS_STACK/queue/`，一個 [N-16](../../NORMS/05-基礎設施-窗/05-N-16.md) 的**有順序信箱**（同一個信箱也收無序的信，排在有序的後面），一封信＝一則訊息（`body` 是一則 OpenAI message 物件，照 P-41 history 的一行；不是 message 物件＝壞信，人一律經 `aos-agent say`〔P-42〕，衝突 5）。agent 認領（rename 進 `cur/`）、把 `body` 接進 `history.jsonl`，**接進那刻就把信收掉**（`aos-post done`；預設刪、要留紀錄進 `archive/`）——跟外部 coding agent「交給 CLI 就算完成」（P-12、P-43）同一個做法；信的內容已在 history，`cur/` 不再留一份。沒答完的那題看 history 尾巴是不是 user（加上 `stage.txt` 停在哪格），不看 `cur/`；`cur/` 只剩認領了還沒接進 history 的（例：idle 在兩步之間被殺）。**回答就是 history 最新那則 assistant，沒有別的回答通道**；檔案成品落在工作區（下面「結果＝工作區內容」那句只管檔案）。誰說、誰看、誰停見 P-42。範本 `templates/agent-fsm`。（使用者 10-30「這一層更接近訊息的queue概念」、看完規劃回「都照建議」，[10-29 agent-bob](../../../thinking/2026-10/29/agent-bob/04-頂層對八題的再想.md#決定10-30) 決定 33、35、36，[thinking 10-30 agent-lifecycle](../../../thinking/2026-10/30/agent-lifecycle/07-衝突.md#決定10-30) 條文草稿、衝突 1、4、5、方向題 1；接進就收：使用者 11-04 衝突 1 選「接進對話紀錄就收」，[thinking 11-04 loop-fsm-agent](../../../thinking/2026-11/04/loop-fsm-agent/04-衝突與方向題.md#決定11-04使用者)；`archive/`、無序的信：使用者 11-03 晚「aos-post這塊都按照建議。」，[thinking 11-03 aos-post](../../../thinking/2026-11/03/aos-post/README.md)；N-16；C-65 執行中的東西落 stack；C-56）
  - **舊協議：題目資料夾**（現在沒有範本用它；新東西不用，`aos-agent say`／`listen` 不認它，方向題 1）：題目＝`$AOS_WS/new/<題名>`，純文字、一題一檔；開始做時把題目搬到 `$AOS_WS/cur/<題名>`（認領）；答案＝`$AOS_WS/out/<題名>`，跟題目同名；做完把題目從 `cur/` 搬到 `$AOS_WS/done/<題名>`。階段名照 Maildir：`new/`＝還沒做、`cur/`＝已認領處理中、`done/`＝做完；`out/` 是產出放的地方、不是階段名（使用者 10-23 選「改成一致的階段名」）。**結果＝工作區內容，沒有別的結果通道。**（拍板點 2；C-65 工作區只放交辦的東西與成果；C-34 求值＝空間狀態的變化。「agent 之間傳題目走 inbox」當共同形狀，inbox 先不管〔使用者 10-19；現行資料夾名是 `new/`〕，不當規則）題目信箱（`$AOS_WS/new cur out done`，一題一檔）是 agent 慣例自己的簡化信箱，**不算** N-16 的標準投遞（沒有 `tmp/`、沒有 `letter.json` 信封，答案另放 `out/`）；新東西走標準（使用者 10-29「都照建議」，[thinking 10-29 medium-plan](../../../thinking/2026-10/29/medium-plan/README.md) 決定 2）。
- **P-12** 一次做一題：取 `new/` 裡檔名排序最前面的那個、搬到 `cur/`，題名寫進 `$AOS_STACK/current.txt`；`cur/` 裡已經有認領了沒做完的（例如 think 的腦失敗、人修好重跑），先接著做那題、不從 `new/` 拿新的，idle 也把 `cur/` 算成還有題目（所以 P-20 的「接著做同一題」對 think 失敗也成立）。走 queue 的 agent，「一次做一題、`cur/` 有沒做完的先接」照舊，資料夾是 `$AOS_STACK/queue/` 的 `new/`、`cur/`；範本 `templates/agent-fsm` 一次收一批（queue 裡全部、照處理順序，think 一次答整批）、`cur/` 有的先接、不寫 `current.txt`，信接進 history 就收（P-11）。外部 coding agent（P-43）是例外：信交給 CLI 就算完成、當場收掉，CLI 中途掛掉的那批不接著做、不自動重答，要重答由人再 say；`cur/` 只留認領了還沒交出去的（見 P-43）。（原型現狀；拍板點 1；queue：[thinking 10-30 agent-lifecycle](../../../thinking/2026-10/30/agent-lifecycle/07-衝突.md#決定10-30) 條文草稿；一次收一批：使用者 11-04「接下來是弄aos loop/fsm agent了」、看完規劃四題都選建議並說「記完就實作」，[thinking 11-04 loop-fsm-agent](../../../thinking/2026-11/04/loop-fsm-agent/02-跟-eca-對照.md#條文要加的註實作時一起11-04-註條文原字不動)）
- **P-13** 需要附檔時升級成資料夾：`new/<題名>/` 裡題文叫 `prompt.txt`、其餘檔是附檔；答案 `out/<題名>/` 也是資料夾、主答案叫 `answer.txt`。一個 agent 認哪種形狀寫在它自己的說明。走 queue 的 agent，附檔＝信資料夾裡的其他檔（N-16「其他檔隨意」），不用 `prompt.txt`／`answer.txt`（題文在 `body`、答案在 history）。（拍板點 2「需要附檔再升級成資料夾」；檔名本稿定，照 C-54 小寫單數；queue：[thinking 10-30 agent-lifecycle](../../../thinking/2026-10/30/agent-lifecycle/07-衝突.md#決定10-30) 條文草稿）
- **P-14** agent 只動 `$AOS_STACK` 與工作區裡它說明寫明的檔（queue 在 `$AOS_STACK` 裡），工作區其他東西不碰；走舊協議的就是只動 `new/`、`cur/`、`out/`、`done/` 與 `$AOS_STACK`。`done/` 只進不出，清理是人的事。（C-65 工作區保持乾淨；C-56 不為清理加機制；queue：[thinking 10-30 agent-lifecycle](../../../thinking/2026-10/30/agent-lifecycle/07-衝突.md#決定10-30) 條文草稿）
