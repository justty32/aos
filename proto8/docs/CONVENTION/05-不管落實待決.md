## 十、程式對這份的落實（10-23 起只有 impls 的 C++ 版，aos-tick 例外）

C++ 的 [impls](../../impls/README.md) 是唯一實作（使用者「python版本可以刪掉了。aos-exec/loop/daemon都用C++」；頂層問 fsm、tick，使用者選 fsm 也改 C++、tick 先留 Python），`proto8/bin` 只剩 `aos-tick`。這份慣例（含 § 14～§ 24、N-57～N-62、C-73、P-40）都已落實，沒有程式落後的地方。aos-fsm／brain.py 寫檔先暫存再改名（N-05）、aos-loop 跑滿 max 不寫 stderr（N-43）。

- 命令列：`aos-exec`、`aos-loop`、`aos-fsm`、`aos-daemon` 四支（loop／fsm 照 [ideas § 23](../../thinking/2026-10-19-ideas.md)「重寫吧，fsm一起做」）；inst 是 C lib、沒有 `aos-inst` 命令列（§ 20；使用者 10-22「aos-inst指令可以刪掉了，跟C++版一樣做成lib就好」），所以 P-28 的 (A) 不能用、(1) 小殼叫 aos-exec。
- 字串的 `exec`（loop 的、fsm 格的；`aos-exec 那個資料夾`；名字照使用者「fsm.json，現在是用val，幫我改成exec」「exec，loop／daemon 的 run 也一起改 exec」）：loop／fsm 不叫命令列，在子行程裡走 aos-exec 的公開 API（找入口、備環境變數、cd、開跑），錯誤照 aos-exec 的格式說；`exec` 直接放單子時在自己行程內交給 `run_inst`（P-06）。
- `aos-daemon`：子 loop 是 fork 後在子行程呼叫 aos-exec 的公開 API `run_cli`，exec 成 PATH 上的 aos-loop。這個「子行程直接呼叫、不叫 PATH 上的 aos-exec」的做法使用者 10-22 接受（[ideas 10-22](../../thinking/2026-10-22-ideas.md)）。
- 訊號與 PATH（[ideas § 24](../../thinking/2026-10-19-ideas.md)）：loop／fsm 收到 SIGINT／SIGTERM／SIGHUP 先轉給正在跑的那次、收完以 128＋N 結束（P-36）；aos-exec、aos-loop、aos-fsm 都不動 PATH、原樣傳下去（P-39、N-59），demo 與測試由呼叫端自己放 PATH。
- 單子當入口：aos-exec 留在行程裡當監工、交給 C lib 跑，以子程式的碼結束。
- 錯誤一行：`程式名: 代號 原因`（例 `aos-exec: 代號 原因`），N-60（使用者 10-22「錯誤訊息多代號也遵循」）。
- 指示詞：單子（aos-exec 的入口、loop／fsm 內嵌的）都解 `$env` 與 `$ref`（aos-directive 庫；使用者 10-19 晚定保留 `$ref`，[ideas § 22](../../thinking/2026-10-19-ideas.md)；N-45），含 `$ref` 的 `#/`、argv 陣列裡的 `$env`／`$ref`、argv[0] 帶 `/` 又 exec 不了＝交給 PATH 上的 aos-exec（N-45、N-61；[ideas](../../thinking/2026-10-20-ideas.md) D1～D8）；`$env` 用 `$path`、加 `$prefix`、寫法寬容（N-45；使用者「我希望那個path可以換成$path，然後添加$prefix」「主要是json格式這塊，指示詞機制很寬容」，[ideas](../../thinking/2026-10-20-ideas.md) D9～D15）。範本與 demo 只用 `$env`（P-31）。
- demo 兩隻 agent 的入口都是可執行檔、單子都內嵌在 fsm.json。

## 十一、要使用者決定的

第一輪六條與第二輪的 N-52 ↔ P-36 都已由使用者裁定，裁定寫在 [ideas § 9](../../thinking/2026-10-19-ideas.md)；方向問題（agent 當工具時題目怎麼交）照預設 (a)「各看各的說明」，記在 [NORMS 待定](../NORMS/08-待定.md)。

**入口檔不在資料夾頂層時 cd 到哪**：一律 cd 到入口檔（解開捷徑後）所在的資料夾＝`AOS_CD`，一條規則管資料夾與檔兩種 XXX（N-59 第 4 件）。`AOS_ENTRY` 預設 `_entry` 時沒差；有人把 `AOS_ENTRY` 設成 `.aos/exec` 這種帶子資料夾的值、或入口是捷徑時，「`cd DIR`」跟 § 18 ③「XXX 是檔就 cd 到它所在的資料夾」會分岔（前者 cd 到 `agent-bob/`，後者 cd 到 `agent-bob/.aos/`、或捷徑指到的實際資料夾），照這條走後者。這是照預設定的（使用者 § 21 對這題的回覆是「cd這個...啥」，頂層白話重講後說不用回、照預設走；他若改判再改）。
