## 三、入口、loop、fsm

- **P-05** 入口 `_entry`（預設 `$AOS_ENTRY`，[ideas § 13](../../../thinking/2026-10/19/ideas/README.md)）一定帶 shebang（`#!/bin/sh`），下一行 `exec aos-loop loop.json`（設定檔是 aos-loop 唯一的位置參數，N-11、[ideas 10-21 § 9](../../../thinking/2026-10/21/ideas/05-7-審後的五個細縫與修正.md#9-設定檔是唯一的位置參數path-改字串拼接10-21-傍晚)）。也可以讓 loop.json 帶 `_entry`、入口寫 `exec aos-exec loop.json`（demo 的 agent-ann）。（§ 4 原話「#usr/bin/sh aos-loop loop.json」。沒有 `#!` 的檔 Linux 本身跑不起來，aos-exec 與單子遇到會改用 `/bin/sh` 跑（§ 22 使用者「乙」，N-59 第 5 件），範本仍寫 shebang、不靠那條退路；`exec` 少一層行程、訊號直達 loop——本稿定。帶 shebang 的是**可執行檔入口**這一種；入口也可以是沒 `+x` 的 JSON（單子、argv 陣列、`js[$AOS_ENTRY]`，C-73，§ 14），那種入口由 aos-exec 讀、**不寫 shebang、不設 `+x`**（寫法見 P-40）。範本 agent-bob 的 `_entry` 是 shebang 小殼）
- **P-06** `loop.json` 的欄位：aos-loop 認的 key 照 [impls/aos-loop](../../../impls/aos-loop/README.md) 共五個：`exec`、`max`，加選填的 `interval_ms`〔上一次結束到下一次開始至少隔幾毫秒，沒寫＝0，N-32〕、`ctl`、`state`〔窗的檔名，在 `$AOS_STACK` 底下；11-04 加註：沒寫＝`ctl.json`／`state.json`、寫 `null`＝不開（使用者題 5「留 key、沒寫時預設就是這兩個名」）〕；其他 key 如 `body`、`_entry` loop 不看，是給 aos-exec 用的（[ideas 10-22 § 5](../../../thinking/2026-10/22/ideas/03-5-loop.md#5-loop10-22)）。`exec`＝每次跑誰，三種寫法：
  - 字串＝aos-exec 的目標（子資料夾、檔、`檔#/指標`；每次 `aos-exec -- <exec>`）。相對路徑照 cwd 算、loop 不轉（慣例下 cwd＝loop.json 所在的資料夾）。單子放在同一份的 `body`、寫 `"exec": "loop.json#/body"` 也行（aos-exec 從 loop.json 的資料夾跑它），就是普通的 aos-exec 目標。
  - 陣列 `[目標, 參數...]`（每次 `aos-exec -- 目標 參數...`）。
  - 單子物件（使用者「不過exec本來就應該要可以直接放內嵌單子吧」「好，就這樣做」，[thinking 10-24](../../../thinking/2026-10/24/exec-relative/01-使用者原文.md#10-24-exec-直接放單子)）：loop／fsm／daemon 拿到物件時在自己行程內用 aos-exec 跑單子的同一套（`run_inst`、inst 的 C lib；`timeout_ms`、訊號、結束碼都一樣）跑，跑的期間 `AOS_CF`＝寫著它的設定檔、`AOS_CD`＝那份檔的資料夾（也是相對路徑的基準）、`AOS_CO`＝它在檔裡的位置（`/exec`、`/states/<名>/exec`）；單子壞＝那支程式自己的錯、退 1。

  `max`＝最多幾次（沒寫＝不限）。loop.json 帶 `"_entry": ["aos-loop", {"$env": "AOS_CF"}]`（放在大 JSON 裡就寫 `{"$env": "AOS_CF", "$path": "#/loops/a"}`（`loops` 只是 JSON 指標的例子；daemon 的名單 11-03 起叫 `procs`，[thinking 11-03 procs](../../../thinking/2026-11/03/procs/README.md)），N-45）時，`aos-exec loop.json` 就能把 loop 跑起來（沒 `argv` 的物件當資料夾，N-61；使用者 10-21 下午「你說的這兩個可以刪的，確實跟我想的一樣，都可以做。」，[ideas 10-21 § 8](../../../thinking/2026-10/21/ideas/05-7-審後的五個細縫與修正.md#8-aos-loop10-21-下午)）。loop 每次起一個 `exec`，看它的結束碼決定下一步（P-19）。（§ 1；拍板點 1；欄位名為原型自訂，daemon／窗的條文也用這兩個名字，[ideas § 22](../../../thinking/2026-10/19/ideas/README.md)、N-28；`exec` 這個名字：使用者「exec，loop／daemon 的 run 也一起改 exec」，[thinking](../../../thinking/2026-10/23/naming.md)）
- **P-07**（**11-03 加註**：下文「每次在 `$AOS_STACK/trace.jsonl` 追加一行」作廢，fsm 不寫 trace 了，[thinking 11-03 trace](../../../thinking/2026-11/03/trace.md)，N-39）fsm 一次只跑一格：讀 `$AOS_STACK/state.txt〔11-04 加註：fsm 的這個檔改名 `stage.txt`（使用者題 10「fsm改名，嘗試用同義詞」，[four-elements 07](../../../thinking/2026-11/04/four-elements/07-實作步驟.md) 步 3；fsm.json 的 `start`／`states` 不改）〕`（沒有＝`start`），跑那格；那格 0 才寫下一個狀態、退 0；非 0 就不換狀態、以原碼退。每次之間狀態都落在 stack，人看得到。**標準＝`aos-fsm fsm.json`**（[impls/aos-fsm](../../../impls/aos-fsm/README.md)；§ 10；設定檔是唯一的位置參數，[ideas 10-21 § 9](../../../thinking/2026-10/21/ideas/05-7-審後的五個細縫與修正.md#9-設定檔是唯一的位置參數path-改字串拼接10-21-傍晚)）：表長 `{"start","states":{名:{"exec","next"}}}`（使用者：「fsm.json，現在是用val，幫我改成exec」，[thinking](../../../thinking/2026-10/23/naming.md)）。`exec` 跟 P-06 同三種：字串＝`aos-exec -- 它`（子資料夾、檔、`檔#/指標`；相對 cwd＝agent 資料夾；單子放同一格的 `body`、寫 `"exec": "fsm.json#/states/<名>/body"` 也行）；陣列；單子物件＝fsm 在自己行程內跑（`AOS_CO`＝`/states/<名>/exec`，[thinking 10-24](../../../thinking/2026-10/24/exec-relative/01-使用者原文.md#10-24-exec-直接放單子)）。fsm.json 可帶 `"_entry": ["aos-fsm", {"$env": "AOS_CF"}]`，`aos-exec fsm.json` 就是一次（F6）；每次在 `$AOS_STACK/trace.jsonl` 追加一行 `{"started_at","state","code","signal","elapsed_ms"}`（`started_at`＝這次開始的 UTC 時間，ISO 8601 到毫秒；時間點一律 `<發生了什麼>_at`，C-54 命名方法 R6；使用者 10-25 回頂層兩題「都好」，頂層代定、可翻案；P-38）。shell 版 fsm（自己讀 state、`case` 換狀態，見第八節範例「全 shell」）是對照寫法，state 檔同一個檔、同一格式，兩種可互換。（C-62、N-53 agent 是被外面 loop 一次一次驅動的狀態機；N-36 一次一格、表一定明寫）
- **P-08** 標準三態 `idle → think → act → idle`。要加狀態＝`fsm.json` 加一格（資料夾格就再加一個子資料夾）；表一定明寫、不靠慣例檔名。`idle` 既是起點也是終點：`new/` 空了退 10 時 state 停在 `idle`，所以跑完的 agent 再被叫一次是從頭開始（P-34 靠這點）。腦的工具呼叫不加第四格——「叫工具還是交答案」由腦決定、act 照做，照樣三態（P-41；[thinking 2026-10-23-tool-calls](../../../thinking/2026-10/23/tool-calls/README.md) 第 4 點）。（拍板點 1；N-36 表一定明寫）
- **P-09** 每一格都是資料夾程式：`exec` 是字串時經 aos-exec 跑，內嵌在 `fsm.json` 的 `檔#/…/body` 單子格也是經 aos-exec 跑的一個入口（P-07）；`exec` 直接放單子物件時由 fsm 行程內跑，那格不是資料夾程式（[thinking 10-24](../../../thinking/2026-10/24/exec-relative/01-使用者原文.md#10-24-exec-直接放單子)）。fsm 只看格的結束碼，不讀格的 stderr、不管格裡面怎麼做（同步等腦、或丟請求下一次再看，都行）。（C-52、N-38、N-41）
- **P-10** 格之間要傳的東西寫成 stack 裡的檔（agent-bob：`current.txt`＝正在做哪題、`plan.txt`＝腦的草稿），不走 stdout。（N-36 `next` 只在表上、格之間要傳的東西由格自己寫成檔；§ 2）
