## 腦、工具、可預測性（續）：C-22

- **C-22** 提高 agent 可預測性的方法：當 S 表示式拆開，能寫死的節點換成程式，降低走進不可預測節點的機率。（2.16）
  **優化目標是確定性**（使用者 11-07，開 arknights 收庫線時說，[arknights-kb](../../../thinking/2026-11/07/arknights-kb/README.md)）：「優化目標就是確定性，我這邊給幾個建議：shell工具一開始可以隨意開放，後面改成謹慎，最後改成全部都有專屬工具。git是很好的東西與重要概念。讓agent專精特定領域，領域越是狹小，能夠變成工具的地方就越多，所需的llm model就越是不用那麼高級，token也能省下來。」白話：改進 agent 時，要往「更多步驟寫死」的方向走。工具權限分三段收：一開始 shell 隨便用，接著謹慎用，最後每件事都有專屬工具。agent 只管一塊窄領域，領域越窄，能寫成工具的部分越多，剩下要動腦的部分用便宜一點的模型就夠，token 也省。版本與回退靠 git。這是方向，不是門檻。
  **三段怎麼認、怎麼走**（使用者 11-07 傍晚 te-1～te-6 都選推薦，[tool-evolve](../../../thinking/2026-11/07/tool-evolve/README.md)）：
  - **階段不另存欄位，從有效工具清單推出來**：有「任意執行工具」又沒宣告沙箱＝`open`（一開始）；都宣告了沙箱＝`boxed`（謹慎）；沒有＝`none`（全是專屬工具）。agent 的階段＝它最鬆的那支工具。任意執行工具＝呼叫者給什麼就跑什麼的工具（shell、run_python，以及能把呼叫者寫的東西登記成工具或子 agent 的那幾支），在 `_metainfo` 宣告 `arbitrary_exec`，是 C-14 的附加特性、不是第十軸。
  - **機器只往緊收**：審視者只有三招——把一種 shell 用法做成專屬工具（extract）、`open`→`boxed`（box）、`boxed`→`none`（unshell）；放寬只能人做，或自動退回時恢復前版。同一形狀連續 2 個 case 出現才算數。三招現在只開處方、不自動做。
  - **確定性＝自洽**：同一份定義、同一個 case 重跑幾次，樣本彼此比；分腳本步、LLM 步、整體三層，分開報、不合成一個分數。跟參考答案比叫「一致」，那是門，不叫確定性。需要時評估可以加「人類可理解性」一項，由使用者本人評分（te-5 備註原話在 [C-84](03-C-84.md) 末段）。
  - 這些階段、門檻與報法本身也能再改（[C-84](03-C-84.md) 末段）。
