## 腦、工具、可預測性（續）：C-22

- **C-22** 提高 agent 可預測性的方法：當 S 表示式拆開，能寫死的節點換成程式，降低走進不可預測節點的機率。（2.16）
  **11-07 加註**（使用者 11-07 上午，開 arknights 收庫線時說）：「優化目標就是確定性，我這邊給幾個建議：shell工具一開始可以隨意開放，後面改成謹慎，最後改成全部都有專屬工具。git是很好的東西與重要概念。讓agent專精特定領域，領域越是狹小，能夠變成工具的地方就越多，所需的llm model就越是不用那麼高級，token也能省下來。」白話：改進 agent 時，要往「更多步驟寫死」的方向走。工具權限分三段收：一開始 shell 隨便用，接著謹慎用，最後每件事都有專屬工具。agent 只管一塊窄領域，領域越窄，能寫成工具的部分越多，剩下要動腦的部分用便宜一點的模型就夠，token 也省。版本與回退靠 git。這是方向，不是門檻；三段各在什麼時候切換沒定（排在 tool-evolve）。（11-07 使用者原話，出處 [proto8/thinking/2026-11/07/arknights-kb/README.md](../../../thinking/2026-11/07/arknights-kb/README.md)）
