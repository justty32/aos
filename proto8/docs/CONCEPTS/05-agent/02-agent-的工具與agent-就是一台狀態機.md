## agent 的工具（10-16 使用者定，10-19 改）

出處：[稿 § 四](../../../thinking/2026-10/16/agent-inherit/02-四-使用者決定.md#四使用者決定10-16)、[ideas § 4、§ 10](../../../thinking/2026-10/19/ideas/README.md)。名詞：資料夾程式、stack、小格、工作區，見 [CONCEPTS 基礎設施 § 資料夾程式、工作區與 stack](../03-基礎設施/02-資料夾程式-工作區與-stack.md#資料夾程式工作區與-stack10-19)。規範 N-50、N-53；慣例 P-11（題目與答案）、P-17（小格）、P-25、P-32、P-33（工具）。

- **C-61** **工具的地址不用 PATH**：工具是資料夾程式，放在呼叫它的那一格自己的資料夾裡（例 `act/tools/cathy/`），格裡寫 `aos-exec tools/<名>`——從自己 cwd 算的相對路徑、永遠零個 `..`（P-25、P-33），兩份定義一起搬也不斷；**工具一律做成資料夾程式**（`date` 這種也是），所以叫每個工具都做同一件事：給它一個小格（它自己的 stack，P-17）、`aos-exec` 它。工具裡是不是另一個 agent，呼叫的格不知道（C-52）。**工具的參數怎麼進（args、stdin、或 stack 裡的檔）由工具自己的說明定**，aos-exec 保證 args 與 stdin 原樣送到（P-26）。例外：aos 自己的指令（`aos-exec`、`aos-loop`、`aos-fsm`；沒有 `aos-inst`，[ideas § 20](../../../thinking/2026-10/19/ideas/README.md)）入口裡直接寫指令名（N-59、P-39）——那是 aos 的指令，不是工具；**aos 的程式都不動 PATH**（使用者「也套用，都不動path吧」，[ideas § 24](../../../thinking/2026-10/19/ideas/README.md)），這些指令由呼叫者自己放進 PATH。PATH 其餘的只留給人在終端打指令。（使用者 10-16 夜：「可以不使用PATH嗎？」→ 看完提案：「好!」）〔腦可以叫的工具另有 `tool.json`（給模型看的說明），`arguments` 從 stdin 進、stdout 出，P-41〕
  - **10-28 補**（使用者 10-28 aos-tools，[thinking](../../../thinking/2026-10/28/aos-tools/README.md)）：agent 的工具改由自己資料夾的 `tools.json` 登記（`aos-tools add`），登記對象可以是資料夾、JSON 檔或可執行檔、可以放在任何地方（註冊檔存絕對路徑）；這條「放在那一格自己的資料夾、零個 `..`、一律資料夾」留給沒經 tools.json 的叫法（例 topdown 的 agent、bob 的 `act/tools/cathy`）。範本裡手寫的 `tools.json` 用相對路徑（從註冊檔的資料夾算），兩份定義一起搬照樣不斷。
  - **10-28 再補：格也走註冊檔**（使用者 10-28「全部走註冊檔好了，捷徑就是方便使用」「註冊檔案中沒寫的，那就是走固定名字」，[thinking 10-28 agent-ops 決定 10、16](../../../thinking/2026-10/28/agent-ops/02-決定.md#決定10-28)；[agent-round § 格怎麼找](../../../thinking/2026-10/28/agent-round/01-白話版.md#格怎麼找註冊檔--固定名字--預設決定-16)）：照 round 拆成格的 agent，自己的格（round、queue、history、act、endpoint、掛勾）登記在 agent 資料夾的 `parts.json`——一份 aos-exec 格式的約定（11-01 改口；沒有管理指令，`aos-parts` 11-01 已刪），同上一條 tools.json 的加註：可以放在任何地方（多半是共用件 `lib/agent/<名>/`、`lib/endpoint/<名>/`）；註冊檔與固定名字共存（11-01 使用者「2.兩者可以共存的。」）：註冊檔有寫的優先，沒寫的格走固定名字（捷徑、真的資料夾或檔都行）。`..` 只出現在方便用的捷徑與手寫的相對路徑裡（使用者「撞到就撞到」）。本條「零個 `..`」照樣留給沒經 tools.json／parts.json 的叫法。parts 是 agent 慣例層的約定、不歸標準庫，見 [C-74](../01-設計理念.md#分層10-22-使用者定)（11-01 使用者裁）。

## agent 就是一台狀態機（10-16 使用者定）

- **C-62** **agent 的定義就是一台狀態機；這台狀態機怎麼跑、由誰跑，概念上都不管**（接 C-18、C-39）。aos 自己的 agent 怎麼跑是規範的事（[N-53](../../NORMS/10-基礎設施-定義與工作區/06-N-50～N-53.md)：被外面的 loop 一次一次驅動）；別家的 agent（例 Claude Code）是一個行程持續跑，概念上同樣是 agent。（使用者 10-16：「agent的定義就是一個狀態機，至於這個狀態機怎麼跑、由誰跑，都無所謂。這是概念。但是我們的規範會說，為了讓agent方便審視自己，所以agent就是一個被人驅動的狀態機，需要外面有人用loop驅動他。這是我們的aos agent，至於我們常見的claude code，他們就是一個process持續執行，那是他們愛的。」，[KISS 重審拍板 4](../../../thinking/2026-10/16/kiss-recheck.md#使用者拍板10-16)）
