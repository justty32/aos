## 記憶與 index

<a id="c-88"></a>
- **C-88** **整個檔案系統＋json 就是 agent 的記憶，缺的只是 index**（使用者 11-12：「就是說，整個檔案系統+json，本來就可以作為agent的memory了，有需要啥就去讀啥，天然的分層。缺的是啥？」自答「description, index」，[thinking index](../../../thinking/2026-11/12/index.md)）。記憶不另做工具或機制：讀寫用一般的檔案工具、json 工具與 shell。沒有 knowledge 工具（「knowledge沒用了，可以拿掉。」）；出廠的知識庫是一般的資料夾＋json，agent 怎麼知道它在哪不管（「4.不管。」，[knowledge-removal](../../../thinking/2026-11/12/knowledge-removal.md)）。index 的名字、格式與路徑寫法是規範（[檔名見 NORMS 命名續](../../NORMS/命名-續-概念搬來的檔名.md)）。
  - **一條路徑尋址**：檔案系統與 json 用同一條路徑，`#` 左邊是檔案系統、右邊是 json 內部（使用者原話四：「我們用一條路徑來統一檔案系統與json的尋址，如aaa.json#/xxx/yyy，檔案系統的根目錄是/，.json檔案的根(也就是整份檔案)則是#/。」）。寫法照標準（RFC 6901，[N-45](../../NORMS/06-基礎設施-命令列與指示詞.md)、[N-62](../../NORMS/10-基礎設施-定義與工作區/05-N-61～N-62.md)；使用者「原來$ref用的是標準寫法。那我們還是按照標準寫法好了。」）。
  - **description 與 index 合一，叫 index**：描述節點的 index＝agent 自己對這個節點的理解，一項一個物件，以後不只放 description（使用者「description和index是可以合起來的，或者說，本來就該合起來，統一叫_index.json/_index，也就是agent自己對這個節點的理解。格式就是{xxx:{description:...}, yyy:{...}}。」）。一項裡還想放什麼都可以，後果自負（使用者 11-12 晚「_index的obj內要不要再多塞東西...可以，想塞啥塞啥，出事了自己負責。」）；`index_view` 只讀 description 與 index 兩格，其他鍵不讀、不檢查、不印。
  - **index 是視角，不是事實**：「index的用途，我用白話說，就是一個透鏡，agent可以透過他看到自己想看到的東西」；要真正客觀就用 `ls`／`json_ls`（使用者「如果想要真正客觀，那就乖乖用shell ls或是aos json ls。」）。客觀的東西怎麼描述都描述不全，所以被記下來而且非私有的，一律是通用視角（公用視角）＝自己公開給別人的聲稱；私有的是主觀（使用者 11-12 晚「客觀那個你不管怎麼描述無法描述全，所以能被我們記錄下來的，非私有的，全都是通用視角(公用視角)(自己公開給別人的聲稱)。」，[thinking metainfo-views](../../../thinking/2026-11/12/metainfo-views.md)）。
  - **天然位置＝被描述節點的上一層**：沒指定位置時，想了解某節點就看它上一層的 index。天然那份是各 agent 共用的通用視角（公用視角）；agent 自己私有的是主觀視角，放哪不規定；cache 不做（使用者「agent的cache這個機制先不用做，反正我們就是訂下index是這樣，客觀index是這樣，agent自己要記錄自己的主觀的東西，就自己想想要放哪，我們不規定。」）。最頂層沒有上一層的 index；index 沒列到的節點不管（「最頂層本來就沒有...。沒列到的就不管」）。塞不進節點裡的（陣列、別人的 json 檔），index 寫在外面、用路徑指（「2,3的確如此」）。
  - **只給太大的補**：「如果有些東西太大，那就補index.json/_index。如果夠小，那其實也不用做看法了，直接讀就是了。」「太大」的門檻（現在是資料夾超過 15 個東西、json 檔超過 8000 bytes 或頂層鍵超過 10 個）是代定、可翻案（[knowledge-removal](../../../thinking/2026-11/12/knowledge-removal.md)）。
  - **看與改**：看用 `index_view`，只做「透過視角看節點」——沒指定＝天然那份；指定一份就疊在天然那份上，同名項以指定那份為準（使用者「path和index可以同時給，指定的那一份有的，會覆蓋掉天然那份。」，[index-tools](../../../thinking/2026-11/12/index-tools/README.md)）。改 index 直接用 json 工具（「index工具那塊，主要做視角就好，修改這塊應該不用做，因為他就是json，直接用json工具就好」）；改通用視角有權限就能改、不用明講（「改通用視角這塊就是有權限就能改，不用明講，風險自己承擔。」）。index 也可以寫進節點描述自己的抽屜（[N-69](../../NORMS/10-基礎設施-定義與工作區/11-N-69.md)）：那個抽屜什麼都能放，index 是其中一種；抽屜本身不算 index。
  - **index 可以指到下一份 index**（使用者 11-12 晚，[index-link](../../../thinking/2026-11/12/index-link.md)）：一項可以指到另一份 index，工具只顯示、不跟著往下走（「json object內的_index這個key，現在他的值是只能json obj，我希望能支援字串，同樣也是路徑，必須指向另一個_index, _index.json。　　不跟着往下走。路徑相對...以_index, _index.json的位置爲準。」）。index 裡的路徑跟 `$ref` 用同一套規則（11-13 晚使用者「$ref和index路徑的規則要相同」，[ref-path-rules](../../../thinking/2026-11/13/ref-path-rules.md)）；細則在規範（[檔名見 NORMS 命名續](../../NORMS/命名-續-概念搬來的檔名.md)），定細則時的原話：「也跟進吧」「算數。」「3.甲」。這條同像只管 index 的路徑；`$ref` 的相對檔名仍從寫著它的檔所在的資料夾算（使用者「3.甲」，N-45）。
  - 格式細節（資料夾與檔內兩種寫法、正文描述與 index 的分別）見 [knowledge/docs/01](../../../knowledge/docs/01-樹長怎樣與多庫.md)。
