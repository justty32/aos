## 腦、工具、可預測性（續）

- **C-42** 工具＝被引用的標頭檔；agent 也可以是工具；aos 體系的每一樣（daemon、tick、task、inst、kernel）都基於 inst、都是 shell 指令，所以都是 agent 的工具——自我迴圈改進的閉環。（3g.12、3g.13）**11-05 午落實**（使用者 11-05 午「讓agent給自己改tool」「讓agent利用aos指令產出另一個agent」，[feat-proto 01、04](../../../thinking/2026-11/05/feat-proto/README.md)）：兩個腦可以叫的工具——`lib/agent/self_tools`（改**自己這隻的**工具覆蓋層：add／rm／ls，定義不動、下一格起生效）、`lib/agent/agents`（在管我的那台 daemon 上生、叫、收別隻 agent：add／say／ask／rm／ls，不繼承腦與工具、上限交給判官 `max_running`）；兩個都只轉手 `aos-agent`，沒有新協定。**11-05 晚落實**（[agent-knowledge](../../../thinking/2026-11/05/agent-knowledge/README.md)，使用者 11-05「層級式記憶工具」）：`lib/agent/memory`（層級式記憶：知識庫＝資料夾樹，`read`／`ls`／`find` 唯讀查）；三種 agent 的 system prompt 都帶它的根（agent-fsm `brain.py --memory`、eca 與外部 agent 經 `aos-mcp --memory` 的 `instructions`），工具說明只寫增量、細節指節點。
  **11-06 註：知識庫、thought、agents**（使用者 11-05 原話；沒標排程的都已實作）：
  - **知識庫便攜、多隻共享**（[agent-knowledge](../../../thinking/2026-11/05/agent-knowledge/README.md)）：「隨著repo出廠，不一定要走環境變數(現在可以先用這個，因為這個最方便)。最主要在於我希望這東西是便攜的，隨意複製，隨意修改，隨意給agent指定、隨意拆卸增添。」「並且這套知識庫還可以給多個agent共享！」——知識庫是普通資料夾，現在用 `AOS_MEMORY` 指（定義裡的 `_memory.json` 蓋過它）；多隻指同一個資料夾就是共享。
  - **分層**：「頂層可以是簡介、index目錄之類，並且盡量講簡單(ELI5風格？)，然後agent有需要的話，再去透過工具，或是一些其他東西去抽取更深一層的知識(或者是當初在規劃該agent用途的時候，就考慮到它需要這個，然後在定義那邊就給他配上)。」
  - **依託檔案系統**（只限記憶工具這件事，不升成總原則）：「現有的資料夾、檔案系統，本身就是一個很好用的東西，盡量依託於這塊。」**格式不限**：「markdown, json, yaml之類的格式都可以。"人類可讀性"可以是次要考慮選項」。
  - **多庫假裝一庫**（規劃中）：「後續可以修改這個memory工具，讓他可以接多個庫，只是假裝頂層還是一個庫。」現在一支 memory 只指一個庫；多庫＝一個資料夾放幾條捷徑各指一庫。**寫入另一支 `memory_write`**（`add`／`edit`／`rm`），`memory` 維持唯讀查；出廠 `knowledge/aos` 不配給 agent 寫、agent 寫自己的庫。這兩項已定（11-05 夜，使用者「知識庫這塊都按照推薦」，[knowledge-write](../../../thinking/2026-11/05/knowledge-write/README.md)；細節 fable 代定、可翻案）；實作排在 W1～W10。
  - **thought 做成工具、不做成 agent 機制**（[small-thought](../../../thinking/2026-11/05/small-thought/README.md)）：「我也不建議把這做為agent機制，我更推薦將其作為工具。」「其實記憶這項，他本身也算是任務」——`lib/agent/thought` 派一件事給乾淨的子 agent、主線只拿回短結論。
  - **生子 agent 兩種、工作區不固定**（[feat-proto](../../../thinking/2026-11/05/feat-proto/README.md)）：「生子agent有分兩種，一種是產出新agent定義，另一種是用現有定義生(可能會稍微改一些設定)。我希望兩種都有」——`agents` 的 `new`（產出新定義）與 `add`（現有定義＋覆蓋）；工作區「不要固定，因為各有不同需求。」——`new`／`add` 收 `ws`（沒給＝沿用父的 `$AOS_WS`；使用者 11-06 已定：被問到這條跟 P-32「被叫者不沿用呼叫方 `AOS_WS`」照哪邊，答「移除P-32」，[special-cases 05 第 3 處](../../../thinking/2026-11/06/special-cases/05-衝突與方向題.md#條文裡已經互相矛盾的不用問給條文隊)）。
  - **11-06 改讀「上限交給判官 `max_running`」**（原句保留）：「工具自己有紀錄，會看到說超過四個，直接回error」——上限是兩道關、各數各的：工具自己數這隻父生了幾隻（`max_children`，超過回 `ChildSlotMissing`、不寄信），判官管整台總量。
