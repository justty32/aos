- **C-42** 工具＝被引用的標頭檔；agent 也可以是工具；aos 體系的每一樣（daemon、clock、task、inst、kernel）都基於 inst、都是 shell 指令，所以都是 agent 的工具——自我迴圈改進的閉環。（3g.12、3g.13）**11-05 午落實**（使用者 11-05 午「讓agent給自己改tool」「讓agent利用aos指令產出另一個agent」，[feat-proto 01、04](../../../thinking/2026-11/05/feat-proto/README.md)）：腦可以叫的工具——`lib/agent/self_tools`（改**自己這隻的**工具覆蓋層：add／rm／ls，定義不動、下一格起生效），和管別隻 agent 的三支（11-10 晚分成三塊，使用者「首先是我希望拆成幾大塊：掌管子agent的管理與生滅，掌管agent定義的創造修改，掌管與其他agent的交流」「agent_def」，[agents-split](../../../thinking/2026-11/10/agents-split/README.md)；`subagent` 這個名字是 11-11 定的，[subagent-rename](../../../thinking/2026-11/11/subagent-rename.md)）：`lib/agent/subagent`（生、叫、收**自己生的**子 agent：add／rm／ls／state／stop／start／sleep／wake／pause／resume／say／listen／ask，出生後還能調子的 tools／llm／history／hook／system；工具自己記帳、數配額）、`lib/agent/agents_ctl`（`aos-agent ctl` 的純包裝，對象是 daemon 表上任何一隻，不記帳、不算配額，成不成看權限）、`lib/agent/agent_def`（new＝把範本整夾複製成新定義、check＝轉叫 `lib/aos/defs` 看一份定義合不合格；tools／llm／system＝把工具、腦設定、system 文字直接寫進某份定義，`args` 形狀照 self_*，new 時在新定義的 `_metainfo.json` 記 `lineage`〔11-12，[agent-def-fine-lineage](../../../thinking/2026-11/12/agent-def-fine-lineage.md)〕）。都不繼承腦與工具，只轉手下層（`aos-agent`；agent_def 轉手 `lib/aos/defs`、`aos-tools`、`aos-json`），沒有新協定；整台的總量交給判官 `max_running`。

  **11-07 註**：thought（11-11 改名 `do_task`，[do-task-rename](../../../thinking/2026-11/11/do-task-rename.md)；**11-11 再註**：這支開小幫手的工具拿掉了，`do_task` 這個名字改給 save／load 版〔在自己的 history 留紀錄點、結束時換成總結〕，複製自己去做另成工具 `fork`，[fork-and-do-task](../../../thinking/2026-11/11/fork-and-do-task/README.md)） 的子 stack 照 11-05 裁定默認刪掉；刪之前只把子的帳檔（`observed.jsonl` 等）抄進 thought 自己的小格，`subagent` 工具在 `ask`／`listen` 回來與 `rm` 前同理，帳才能沿呼叫樹往上收。已定；實作排在 evolve-design。（11-07 使用者裁定，傍晚選項框 ltn-5 選推薦，[lift-to-norms](../../../thinking/2026-11/07/lift-to-norms/README.md)）

  - **生子 agent 兩種、工作區不固定**（[feat-proto](../../../thinking/2026-11/05/feat-proto/README.md)）：「生子agent有分兩種，一種是產出新agent定義，另一種是用現有定義生(可能會稍微改一些設定)。我希望兩種都有」——「產出新定義」是 `agent_def` 的 `new`（只把範本整夾複製成新定義，不掛上；改內容用 `agent_def` 的 tools／llm／system 或一般檔案工具），「用現有定義生」是 `subagent` 的 `add`（記帳的子）或 `agents_ctl` 的 `add`（不記帳），要改的設定照 `aos-agent ctl add` 的旗標給；工作區「不要固定，因為各有不同需求。」——這兩支的 `add` 收 `ws`（沒給＝沿用父的 `$AOS_WS`；使用者 11-06 已定：被問到這條跟 P-32「被叫者不沿用呼叫方 `AOS_WS`」照哪邊，答「移除P-32」，[special-cases 05 第 3 處](../../../thinking/2026-11/06/special-cases/05-衝突與方向題.md#條文裡已經互相矛盾的不用問給條文隊)）。出處 [agents-split](../../../thinking/2026-11/10/agents-split/README.md)。

  - **知識庫存什麼、給人看什麼**（使用者 11-07 午，收 arknights 語料時裁）：「節點名確實建議英文，剩下隨意。內部內容建議按照語料原文，這樣能最大程度保持原意。這是儲存方面，至於使用者想看的時候，可以透過其他界面，比如做一份附屬知識庫，其中是翻譯過的白話，或是直接準備一個agent幫忙解答問題。類似RAG。」白話：節點名（路徑上那一段）用英文，其他像標題怎麼寫都隨意。從外部語料收進來的知識庫，節點內文照語料原文逐字存，不翻譯、不改寫，這樣原意最完整。這是**存**的那一層；人要看時走另一層：另做一份翻成白話的附屬知識庫，或者準備一隻問答 agent 回答問題（類似 RAG）。兩層分開，存的那層不為了好讀而改原文。（「人類可讀性可以是次要考慮」見上面「依託檔案系統」那條。）已定；問答 agent 原型在試驗場（arknights-kb 06），附屬白話庫還沒做。（11-07 使用者裁定，出處 [proto8/thinking/2026-11/07/arknights-kb/README.md](../../../thinking/2026-11/07/arknights-kb/README.md)） 原文要讓連結指到「第幾段」時，可以把原文存成逐段陣列：內容仍逐字，只是容器從一整段字串變成陣列，連結就能用 `節點#/paras/N` 這種 JSON 指標指進去（使用者 11-07 午後選「可以，存成逐段陣列」）。怎麼切（現在是照換行切、`"\n".join` 要跟原文逐 byte 相同）是試驗場的代定，不是規則。已定；試驗場已照做（arknights-kb 10-第二輪設計）。（11-07 使用者裁定，出處 [proto8/thinking/2026-11/07/kb-ideas/README.md](../../../thinking/2026-11/07/kb-ideas/README.md)）
