1. **R1 先寫一行 NAME：`名字 - 一句話`**。每支程式、每份檔、每扇窗，動手前先寫「它做什麼」一句話（使用者：「我在寫程式的時候，會先用簡短的介紹描述自己要做的東西，比如aos-loop，我會這樣說：以指定設定，定期執行某個aos-exec目標」）。格式照 man page 第一行：名字、空格、連字號、空格、一句話；英文小寫開頭、不加句號。放檔頭或 README 第一行；之後所有名字都要能從這行推回來。要加功能也一樣：先一句話說那個功能，再照句子加 key（C-48）（使用者：「然後我會給這些額外的功能添加更多說明……然後就按照這句話開始實作」）。
   例：`aos-loop - 以指定設定，定期執行一個 aos-exec 目標`、`state.json - loop 自己回報的現況，每跑一次寫一次`
2. **R2 每一格一句白話，先不想名字**（使用者：「把這些資訊寫出來後，在去將其命名」）。例：「跑到第幾次」「最多跑幾次」「兩次之間隔多久」「ctl 窗最近一次讀到壞的，原因是什麼」。
3. **R3 先查固定格，有就直接用**：原值 `val`（C-55）、上限 `max`、種類 `kind`、結束碼 `code`、訊號 `signal`、流水號 `seq`、階段 `phase`、行程號 `pid`。時間點沒有單獨的固定格 `at`，一律 `<發生了什麼>_at`（見 R6「啥時候」那列；使用者 10-25 回頂層兩題「都好」，頂層代定、可翻案）。這一步在挑字之前。`val` 只給「值的展開形」裡原值那一格（C-55）；**具名欄位不是展開形，照白話取名**——「要跑什麼」全體系一律叫 `exec`（loop.json、daemon.json 與子項、fsm 的每一格；`exec`＝交給 aos-exec 跑的目標），不叫 `val`（10-23 晚使用者：「val寫要跑啥，通常不會用val，應該用run。」；深夜使用者「fsm.json，現在是用val，幫我改成exec」，頂層指出 loop／daemon 叫 `run`、不同名違反 R4 一詞一義，使用者選「exec，loop／daemon 的 run 也一起改 exec」）。
4. **R4 主題字從白話的主詞來，全體系一詞一義；巢狀已經說了的，不再重複**。一句白話的主詞就是主題字（「ctl 窗讀到壞的」→ `ctl`）；同一個詞在 aos 各處只一個意思（C-54「一次記住、全體系通用」：`state` 是窗，所以窗裡的「現在在幹嘛」叫 `phase`）；外層已經說了的主題，裡層不重複（`loops.bob.pid`，不寫 `loop_pid`）。ctl 是宣告（N-06），key 一律用狀態詞；state 裡有對應的格時，用同一個字：`paused`、`stopped`（10-23 晚使用者選「改成 stopped」）；state 裡沒有同名的格時照樣用狀態詞（例 daemon ctl 的 `loops_added`／`loops_removed`，N-54）〔頂層代定（使用者「都隨意」）〕。 **11-03 加註**（使用者 11-03「還是用指令吧，不然大家不好理解。」；[thinking 11-03 ctl-commands](../../../../thinking/2026-11/03/ctl-commands.md) § 6、[11-03 procs § 0 名詞表](../../../../thinking/2026-11/03/procs.md#0-名詞表代定)）：loop 這一系控制自身的 ctl 改成一道指令，key 是 `cmd`、值是動詞（名詞表動作欄的 `pause`／`resume`／`stop`），不再用狀態詞；state 的 `phase`、`paused` 照舊用狀態詞。daemon 管別人的 `procs_ctl.json` 仍是宣告、照舊用狀態詞（`procs_added`、`procs_removed`、`procs_stopped`、`procs_started`）；上面的例 `loops_added`／`loops_removed` 11-03 起是 `procs_added`／`procs_removed`。
5. **R5 縮寫只用縮寫表；新縮寫進表的門檻是「一眼還原得了」**（使用者：「也要看他是否有簡寫(容易認，少寫幾個字母)」）：要嘛是 Unix／POSIX 老慣例大家本來就認得（`pid`、`cwd`、`argv`、`ms`、`tmp`），要嘛看一眼就還原得了全字（`ctl`、`cfg`、`seq`）；「刪母音」式、光看還原不了的不收（`crt`、`umnt`）。**表上已有的不追溯**：`AOS_CF`／`AOS_CD`／`AOS_CO` 留著（10-23 晚使用者選「留著」）。門檻也寫在 [abbr.json](../../abbr.json) 的 `note`。
6. **R6 修飾成分照表貼**：

   | 白話裡出現 | 貼什麼 | 例 |
   |---|---|---|
   | 最多、上限 | `max`（單獨，或前綴 `max_`） | `max`、`max_runs`、`max_calls`（llm-kernel）、`max_lines`（lib 的 read） |
   | 幾個（計數） | **前綴 `counter_`＋被數的東西**：`counter_<被數的東西>`（10-25 使用者「計數這塊，幫我改成counter_*」）；**不用 `nr_`**（使用者：「nr_這東西還是建議不要用，現在這東西不太常見了」）；撞名時照 R9「撞名就換角度」，得到的名字不一定是「`counter_` 加名詞」。只管「次數、個數」：一串東西本身（陣列、清單，例 `steps`、`tools`）照「複數只加 s」，不加 `counter_`；上限（`max`／`max_`）、時長（單位當後綴）、第幾個（`seq`、`idx`）照各自那一列〔10-25 頂層代定〕 | `counter_runs`（loop／daemon 的 state.json：跑過幾次；使用者「beats改runs」、10-25「state.json中，runs改counter，at改成recorded_at」，再照本列）、`counter_tokens`（llm-kernel）、`counter_hops`（信） |
   | 多久、單位 | 單位當後綴 | `interval_ms`、`elapsed_ms` |
   | 啥時候（這筆紀錄） | 跟下一列同一條：**`<發生了什麼>_at`**，值 ISO 8601 UTC 到毫秒（10-23 晚使用者選「留 ISO」）——「這筆紀錄的時間」也照白話說出是什麼事的時間（寫下這份 state＝`recorded_at`、這格開始跑＝`started_at`、信寄出＝`sent_at`、kernel 處理這封信＝`served_at`），不用單獨的 `at`（使用者 10-25 選 `recorded_at`〔「state.json中，runs改counter，at改成recorded_at」〕；回頂層兩題「都好」，頂層代定、可翻案） | `recorded_at`、`started_at` |
   | 啥時候（某件事） | `<事件>_at`，值同上（10-23 晚使用者選「補」） | `started_at` |
   | 某件事的時間點、用別的單位記 | `<事件>_at_<單位>`（使用者：「後面接參照與單位(兩者可以合一)：started_at_ticks」；10-23 晚選「改成 started_at_ticks」） | `started_at_ticks` |
   | 上一次 | 前綴 `last_` | （現在沒有這種格；「上一次的結果」`last_code` 10-23 晚使用者選「先不加」） |
   | 在一排裡第幾個 | 不進縮寫表；真要用時寫 `idx`（使用者原本提 `_i`：「這可能不太好，要再想想」；10-23 晚選「`_i` 不進表，真要用時用 `idx`」） | — |

7. **R7 排字序：主題在前、由大到小，單位一律在最後**（C-54「可搜尋的標籤／主題放前面」）。同主題的 key 排在一起（`ctl_seq`、`ctl_warning`）；`max_`、`last_` 這種修飾詞在前是 C-54 已寫的例外〔計數的 `counter_` 同理（使用者「計數這塊，幫我改成counter_*」）〕。 **11-03 例**（[thinking 11-03 procs](../../../../thinking/2026-11/03/procs.md) § 1）：daemon 管 procs 的手把、窗、信箱叫 `procs_ctl`、`procs_state`、`procs_ctl_mailbox`——主題 `procs` 在前。
