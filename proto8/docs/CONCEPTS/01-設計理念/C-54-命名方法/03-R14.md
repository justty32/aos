14. **R14 信箱叫 mailbox、queue，還是照裝的東西取名**（11-06；使用者 11-06 選項框「寫進 C-54 (Recommended)」，原問「關於現在的_mailbox命名，如果那個mailbox是有序的話，是否應該都改名為_queue？」；草稿與盤點 [thinking 11-06 mailbox-naming](../../../../thinking/2026-11/06/mailbox-naming/README.md)）：
    1. **「信箱」是機制名，不是用途名。** 凡是 N-16 那種資料夾（`tmp/`、`new/`、`cur/`、選用 `archive/`，信＝資料夾＋`letter.json`）都叫信箱；講機制的名字一律用 mailbox：aos-post 的型別與函式、錯誤代號 `MailboxMissing`／`MailboxBad`、壞信欄 `mailbox_warning`（使用者 11-02 定的通稱，不分這箱拿來做什麼）、收「任何一個信箱」的參數（`--reply-to BOX`、aos-sandbox 的 `--mailbox`）。
    2. **資料夾、設定 key、窗裡回報箱名的欄位，照「這箱拿來做什麼」取名**（R2 的一句白話），分三種：
       - **queue**＝寄的人全帶序號（`--ordered`）、一個讀者、照順序一封封消費、順序錯了結果就錯。**四條都成立才叫 queue。** 例：agent 的 `$AOS_STACK/queue/`（N-16 10-30、P-11）。
       - **`<主題>_mailbox`**＝收件箱：很多人寄、一封封各自獨立、可以要回信、讀的人可以整批拿。例：daemon 的名單信箱（**11-10 註**：這個例子 11-10 改名 `procs_requests/`，歸下一種「照裝的東西取名」；新開的箱照本條末 11-10 註先找裝的東西）。
       - **照裝的東西取名**＝收的東西有固定名字時用那個名詞的複數：`requests/`（判官、llm kernel 收的請求）、`reply/`、`daemon_reply/`（回信）。這也是收件箱，名字講裝什麼。
    3. **讀的人另有排法（優先序、期限、配額），信箱名不叫 queue。** 排法寫在讀的程式的說明與排序函式，不靠名字暗示。例：llm kernel 照級數＋aging 挑信，它的箱叫 `requests/`。
    4. **記錄排隊狀況的檔不是箱**（N-14：鎖、信箱都不算窗）：一個寫者、只看最新那份的照 N-14 開窗；名字可以叫 `queue.json`（「現在誰在排」），不受 2 的「四條都成立」限制，但寫它的程式的檔頭註解與說明要有一句寫明排法（先來先掛／優先序）。使用者 11-06 選項框「不算、檔頭寫明 (Recommended)」：這不算 R4 的一詞兩義。例：llm kernel `queue.json`（kernel 自己的排隊帳，優先序）、判官 `queue.json`（窗，先來先掛；已定、實作排在 P9 後（11-07 註：已實作，見 [N-66 11-07 註](../../../NORMS/05-基礎設施-窗/08-N-66.md)；代定））。
    5. **「有序」只說信，不說箱。** 文件寫「有序的信」「帶序號寄」；要講箱就寫「當 queue 用的信箱」，不寫「有序信箱」——11-04 aos-post 改版（有序、無序同箱，N-16）起箱沒有這個屬性。
       **11-07 確認**：R14 標題那個原問題（「如果那個mailbox是有序的話，是否應該都改名為_queue？」），使用者確認不改名：現有的 `_mailbox` 照舊。（11-07 使用者裁定，出處 [wf/workflows/refactor/reports/2026-11-07-sol審查/11-使用者裁定.md](../../../../../wf/workflows/refactor/reports/2026-11-07-sol審查/11-使用者裁定.md) #31-2）
    6. **以後新開的箱**：寄的人程式裡全帶 `--ordered`、讀的人照順序消費、順序錯了結果就錯 → 叫 queue；任一條不成立 → 收件箱（2 的後兩種）。只因「順序有一點影響」（例 daemon 同一圈 add 又 rm）不升格成 queue。

    **11-07 確認**：使用者 10-30 說過請求投遞也可以叫 queue（[agent-bob 04 決定 33](../../../../thinking/2026-10/29/agent-bob/04-頂層對八題的再想.md#決定10-30)）；本條仍保留「四條都成立才叫 queue」的嚴讀法。（11-07 使用者裁定 sol 審查 #31-1）

    **11-10 註**（daemon 名單信箱改名 `procs_requests`；使用者 11-10「對了，就是說，有一個我想要改名的地方：procs_ctl_mailbox，這太長了，有點奇怪。我覺得可以將其改為procs_ctls。」「或是procs_requests」，選項「1.requests。2.不用。」——2＝其他名字帶 mailbox 的不跟著改）：使用者講的原則逐字是「mailbox，他是底層的aos post機制。但我們是將其作為其他機制的承載者，我們不該直接拿mailbox做命名。應該是用承載的機制作命名」。照這句讀 2：資料夾、設定 key、回報箱名的欄位先照「這箱承載的機制」取名（`requests/`、`procs_requests/`、`reply/`），`<主題>_mailbox` 不再當新開箱的取名法；1 講的機制名（aos-post、`MailboxMissing`／`MailboxBad`、`mailbox_warning`、`--mailbox`）照舊。現有其他帶 mailbox 的名字使用者裁「不用」改；agent 的 `queue/` 不動。
