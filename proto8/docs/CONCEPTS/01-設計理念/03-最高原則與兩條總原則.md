## 最高原則（10-15 深夜使用者定，[原文](../../../thinking/2026-10/15/principles/02-結論-已有的實例.md#10-15-深夜使用者拍板切乾淨kiss)）

- **C-56** **KISS 是最高原則，也是最後原則**：「我要的是徹底的純淨簡潔，KISS。把KISS納進最高原則。」（10-15 深夜）「KISS是最高原則，但也是最後原則，本質上是希望提出的設計在滿足各類需求和原則後，最後能回頭思考，把一些多餘的東西清掉。」（10-16，[原文](../../../thinking/2026-10/16/kiss-last.md)）接 proto7 設計原則 第 9 條（核心〔proto7 用語，＝名詞表的「系統本體」，不是 C-74 分層的核心〕只做最基礎的保護、錯誤同類走同一分支、很多東西默認正常、誤用不歸組件管）。其他原則都在它底下，下面兩條（C-52 巢狀切乾淨、C-53 錯誤只處理自己的）是它在巢狀與錯誤上的樣子；但 KISS 是**最後一步的減法**：設計先滿足各類需求與其他原則，再回頭把多餘的清掉——不為了方便偷看一層、不為了邊緣狀況加機制；也**不拿「最乾淨、規則最少」當抄近路的理由**（使用者：「“最乾淨、規則最少”很容易導致一些問題，也就是抄近路反而導致繞遠路」），清的時候不能違反其他原則。**寫什麼就做什麼**（10-16 補）：給的值照字面意思用，不讓某些特定值偷偷變成另一種行為；不拿「要人記的暗規則」換少一個 key——減法清掉的是多餘的東西，不是把規則藏進值裡（使用者：「不要用這種方式添加規則，不直觀，這等同於埋雷，大家都預期“我給啥檔案，他就是往這個檔案塞東西”，你還要人家記“如果給的是這個檔案，那他會幹別的事情”，這太糟糕了。」）。例：inst 的 `stdout` 寫 `/dev/stdout` 就只是照字面打開那個路徑，不特判成直接繼承 fd；沒寫的串流就是接呼叫者的，不需要旗子（[aos-exec](../../../impls/aos-exec/README.md)；[原文](../../../thinking/2026-10/16/kiss-last.md#原文寫什麼就做什麼10-16)）。

## 兩條總原則（10-15 使用者定，[原文](../../../thinking/2026-10/15/principles/README.md)；10-15 深夜加嚴）

- **C-52** 巢狀：**只管自己這一層，徹底切割、不得有任何殘留**。盡量保持簡單；之後一複雜，巢狀一定常見，所以每一層只管自己，處理上層時下層被乾淨切開、可以不管；真要管時心裡有一把尺——同一個原則在每一層重複、貫穿整個巢狀，只看最上層就能處理。10-15 深夜使用者加嚴：**想看子層的東西要另外透過其他機制，沒機制就別碰**（不偷讀下層的 stderr、不替下層驗它的東西）；**上層不需要、也不該知道下層是什麼**（fsm 不知道某格是不是另一個 fsm，agent 只看到自己的工具清單、不知道工具裡是不是另一個 agent，什麼都不往下傳、不繼承）。已有的例子：fsm 只管「格→結束碼」（C-49、N-36）、格的 stderr fsm 不讀（N-38）、inst 的結果只說子程式（N-30）、暫停與次數交給跑它的 loop（N-39）、agent 不知道工具內部、子 agent 只看自己的 stack（C-46；P-17 給被叫者自己的小格）、巢狀時 aos 只訂被叫者自己的 `AOS_STACK`、子程式的 stack 由它自己訂（C-70）、整隻 agent 叫、不拿別人 fsm 的一次（P-35）、被外層逾時殺掉就是那格失敗、不為內層說話（P-36）、每層出錯只說自己一行（P-21）、結束碼只說自己這一層（N-43）。（[CONVENTION](../../CONVENTION.md)）
  - **10-28 例外：round 與每一格拿 agent 資料夾當第一個參數**（使用者 10-28「照新做法」，[thinking 10-28 agent-ops 決定 11](../../../thinking/2026-10/28/agent-ops/02-決定.md#決定10-28)；[agent-round § 1 佈局](../../../thinking/2026-10/28/agent-round/01-白話版.md#1-佈局)）：照 round 拆成格的 aos agent，round 把 agent 資料夾的絕對路徑原樣當第一個參數給每一格，格靠它找同一隻 agent 的其他格（P-33 的 10-28 例外）。這是明給的參數、跟 fsm 拿 fsm.json 同一種，不是環境變數。理由：aos-exec 解開捷徑後 cwd 在共用件那邊，共用件靠 cwd 找不到引用它的 agent。其餘照本條。
  - **11-05 例外：aos-mcp 失敗時把工具 stderr 的最後一段附給外部 agent**（使用者 11-05 選「附 stderr 尾巴（推薦）」，[edge-basics 題 1](../../../thinking/2026-11/04/edge-basics/README.md#題-1工具失敗時外部-agentclaude-code-等看不到原因)；[aos-mcp](../../../cmd/aos-mcp/README.md)）：aos-mcp 的出口是給 Claude Code 等外部 agent 看的，它們看不到 MCP 用戶端的 log，只看 stdout 就不知道失敗的原因。所以工具（含 aos-tools、aos-exec）退非 0 或逾時時，aos-mcp 接住那次 stderr，最後 2 KB 另附一段回給外部 agent；成功時不附，stderr 照樣轉印到自己的 stderr。也是 C-53「下層的錯不轉述」的例外。只限 aos-mcp 這個對外出口，aos 內部的上下層照本條。
  - **11-05：准讀下層 stderr 的明文例外表**（照盤點推薦，[thinking 11-05 stdio-unify](../../../thinking/2026-11/05/stdio-unify/README.md) R10）：本條「不偷讀下層的 stderr」只有下面三處例外，出口都是給人或外部 agent 看的——① **aos-mcp** 工具失敗時附 stderr 尾巴給外部 agent（上一項）；② **aos-agent** 把 aos-daemon-ctl 的錯換成自己的名字與代號（例 `ProcMissing`→`InstanceMissing`），出口給人（**11-06 改讀（no-pid P5b）**：② 作廢——aos-agent 已直接 import `py/daemon_ctl/`、不再叫 aos-daemon-ctl，沒有它的 stderr 可讀；例外剩 ①、③，見 [P3 結果](../../../thinking/2026-11/05/no-pid/10-P3實作結果.md)）；③ **aos-llm-kernel** 的 endpoint 函數退非 0 時，拿它 `stderr.txt` 的第一行當回信 `EndpointFailed` 的原因，出口給寄信的那方。**其他一律**（aos-eca-turn、demo idle.py 讀 aos-post 的 stderr、cli_session 讀 CLI 的 stderr 尾巴、memory（11-10 改名 knowledge_read）／self_tools 的末行…都照這個改）：下層的 stderr 原樣透出、不攔，自己只多寫一行自己的錯誤行；給腦用的工具透出的下層 stderr 只到工具的 stderr，stdout 只有自己那一行（代定 D2：腦只看 stdout，不被下層雜訊淹）。
  - **11-06 註（J4 已實作，`2eb02ea4`；使用者 11-06 選項框選「保留 (Recommended)」，已定）**：准讀下層 stderr 的例外加 ④ **agent-fsm 的 act 格**：工具退非 0 或逾時，把那次 stderr 最後 2 KB 附進回給腦的 tool 訊息；成功不附，全文照樣轉印到 act 的 stderr。這也是 C-53 的例外；上文「只限 aos-mcp」「出口都是給人或外部 agent」隨此擴及 act 給內部腦的出口，現行清單為 ①、③、④。見 [json-argv J4 結果](../../../thinking/2026-11/05/json-argv/10-J3到J7實作結果.md)。
  - **11-06 註（使用者 11-06 選項框，已定）**：例外清單再加 ⑤ 轉接下層最後一行的代號與原因（agents、self_tools、aos_json、json_rewrite）；全文見 [續：C-52 例外 ⑤](03-續-C-52-例外.md)。
