## 命名（10-15 使用者說，[原文](../../../thinking/2026-10/15/naming/README.md)）

- **C-54** 命名：**好懂、快速理解、快速記住**。資料夾布局、程式碼、JSON 格式最好一看就懂七七八八——先排結構，結構與名字本身就是說明；說明只要少量簡介，再直接甩出 pseudo code／JSON／資料夾。
  - **一次記住、全體系通用**：同一個詞在 aos 各處同義。縮寫只用大家本來就知道的，而且**新縮寫要先進 [aos 認可縮寫表](../abbr.json) 才能用**（10-15 使用者「要，縮寫表照推薦做」；表的欄位：縮寫、全稱、意思、例子）。
  - **難懂才加前後綴**，表特性（`dir`、`path`、單位 `ms`）或子類時用；不用匈牙利命名法那種型別前綴。**可搜尋的標籤／主題放前面、由大到小**，排序、搜尋時同類排在一起。
  - **資料夾、檔名、JSON key：全小寫加底線**；**對外的指令名＝同一個名字把底線換成連字號**；環境變數全大寫加底線（10-15 使用者「指令名就是底線換連字號。」）。
    - **夾名推薦底線、不強制**（使用者 11-14 專區 U2 選 allow：「夾名不改，規則補一句『範本、kernel、定義夾名可跟指令名一樣用連字號』」；備註原文「夾名這塊，改成推薦用底線，實際上愛怎麼用怎麼用。」，專區回覆 reply_id `64cd11aaf4131c02`，ok-pilot 經手）：資料夾名推薦全小寫加底線；用連字號也可以，範本、kernel、定義的夾名可以跟指令名一樣用連字號，現有夾名不改。定義夾名的檢查照舊收 `[a-z0-9_-]+`。檔名、JSON key 照上一句。
  - **程式碼照該語言規範**（Python 照 PEP8），並跟檔名固定對上；程式裡可混大小寫表層級。
  - **靠資料夾布局少用底線，複數資料夾裝同類**：裝同一類多個東西的資料夾用複數名，裡面的檔名不再重複類別。複數一律只加 `s`（縮寫也是），不用不規則變化；本身已是複數或不可數的照原樣；單一檔案用單數（10-15 使用者「對了，還有複數形式，比如./inst-a.json, ./insts/a.json」，細節「都按照推薦」）。daemon 管的子項都是 proc，名單叫 `procs`（不叫 `children`）（使用者 11-03「連名單也合一」，[thinking 11-03 procs](../../../thinking/2026-11/03/procs/README.md)）。
  - **錯誤若帶代號，照 CamelCase、主詞在前**（錯是 stderr 一行 `程式名: error: 代號 原因`，代號＝`error: ` 後第一個字，N-43、P-21），同主題的錯排在一起。
    - **結尾是推薦**（使用者 11-11：「Hmmm，錯誤代號本身就千變萬化。concept內應該只是列出幾項基礎的、很通用大眾的，跟大家說類似的就盡量遵循這個。但其他的也可以自己隨意定。就是說偏向於推薦啦。」，[knowledge-fix 03](../../../thinking/2026-11/11/knowledge-fix/03-六題裁定與施工.md)）：下面幾個基礎、通用的結尾，遇到類似的情況盡量照用；其他情況可以自己定。
      - 「沒有某物」`…Missing`、「不認得」`…Unknown`、「壞了／不合」`…Bad`（10-15 晚使用者「都按照推薦」，盤點 P7）。
      - 「動作做不成」動作＋`…Failed`（可以再試一次）；`Internal`＝照理不會發生的錯（10-23 使用者逐條認可）。
      - `…Exists`＝已經有同名的（11-03 晚使用者「aos-post這塊都按照建議。」，[aos-post 原話與衝突 1](../../../thinking/2026-11/03/aos-post/01-使用者原文-11-03-晚-看完頂層整理.md)）。
      - `…Rejected`＝守門的說不，**這是決定、別重試**——要嘛改請求、要嘛回報；跟 `…Failed` 分開（使用者 11-06 選項框選「C-54 補第六種 (Recommended)」，[arch-refactor 06](../../../thinking/2026-11/05/arch-refactor/06-工作量與排程.md) S9 列；選項逐字原話的出處待核）。
    - **基礎層共用的代號**統合過一次，清單見[命名統合原話](04-續-命名統合原話.md)。
  - **例外**（10-15 盤點後定，使用者「其他直接改」）：入口檔照 Unix 老慣例全大寫（`ls` 時排前面）；`bin/` 是 Unix 慣例名、單數照留；工具自己的慣例照工具；外部 API 的參數名照原名、不進縮寫表；一個檔裝很多筆的串流／日誌檔可以用複數。`last_`／`max_` 這種修飾詞在前不算違反「主題在前」〔計數的 `counter_` 同理，使用者 10-25「計數這塊，幫我改成counter_*」〕——`last_` 本身就是一個可搜尋的群組（state 窗裡「上一次的」排在一起），`max_` 是大家都知道的慣例。
  - **副檔名、時間、計數、上限**（[thinking](../../../thinking/2026-10/23/naming.md)；使用者 10-23 逐條選過，副檔名選「純文字也帶 .txt」）：JSON 帶 `.json`、JSON Lines 帶 `.jsonl`、純文字帶 `.txt`（入口檔是程式不是資料、不帶；設環境變數的那份照 dotenv 生態、不帶）；時間點一律 `<發生了什麼>_at`，不用單獨的 `at`（使用者 10-25「state.json中，runs改counter，at改成recorded_at」，回頂層兩題「都好」，頂層代定、可翻案），值一律 ISO 8601 UTC 到毫秒，時長與其他單位照後綴；計數一律 `counter_<被數的東西>`，一串東西本身（陣列）不算計數、照「複數一律只加 s」；上限叫 `max` 或前綴 `max_`；細則見 [C-54 命名方法 R6](C-54-命名方法.md)。
  - **命名方法（10-23 晚，[thinking](../../../thinking/2026-10/23/naming-method/README.md)）**：取名照 R1～R14 走，細則逐條在 [C-54 命名方法](C-54-命名方法.md)：先寫一行 NAME `名字 - 一句話` → 每格一句白話 → 先查固定格 → 主題字從主詞來 → 修飾成分照表貼 → 排字序 → 名字長度跟要被認多遠成正比 → 簡化到同檔同主題仍唯一（撞名就換一個角度，用白話重新描述它的功能與特性再取名）→ 最後回頭清、每個名字都推得回那一句。同一個時間點用別的單位記就把單位接在後面（使用者原例「started_at_ticks」）。「要跑什麼」全體系一律叫 `exec`（見 C-55、R3）；條文與訊息裡說「次」，不說「拍」（使用者：「"拍"，其實我們人類不常用這個來說，我們都是說"次"。」）。

## 例子

- 一詞一義：`inst`、`ctl`、`state`…。前後綴：`ctl_dir`；主題在前：`path_insert`、`path_query_sql`。
- 底線換連字號：`node_path` ⇄ `node-path`；環境變數 `AOS_ENTRY`；用連字號的夾名 `agent-fsm`、`eca-claude`、`opus-kernel`；程式的 `NodePath` ⇄ 檔名 `node_path`、`NodePath_SQL_Query`。
- 複數：`insts/`、`cells/`、`tools/`；`insts/a.json`，不寫 `inst_a.json`、`insts/inst_a.json`；`insts`、`cfgs`、`msgs`；照原樣的 `args`、`data`、`history`；單數 `brain.json`、`ret.json`。
- 錯誤代號：`ArgumentsBad`、`FlagUnknown`、`ApiKeyMissing`、`StateBad`；`LaunchFailed`、`MkdirFailed`、`WriteFailed`、`OpenFailed`；aos-post 自己給的信件名稱撞名＝`LetterExists`，跟既有的 `InstanceExists`、`FileExists`、`ToolExists` 一致；守門的是判官、daemon 不收，既有的 `AddRejected`、`CtlRejected` 照用；`DepthExceeded`、`SubagentQueued`、`ChildrenExist` 照用、不改名。
- 例外：`README.md`、`INDEX.md`、`CONCEPTS.md`、`NORMS.md`；pytest 的 `tests/test_*.py`；外部 API 的 `num_ctx`、`keep_alive`；串流檔 `steps.jsonl`。
- 副檔名與時間：fsm 的 `stage.txt`、`stderr.txt`、`current.txt`；入口檔 `_entry`、`.env` 不帶副檔名；`recorded_at`、`started_at`、`sent_at`、`served_at`；`_ms`、`_cycles`；計數 `counter_runs`（不放 state.json、寫成旗標後面的 `counter_runs.txt`，N-09）；上限 llm-kernel 的 `max_calls`／`max_tokens`。
