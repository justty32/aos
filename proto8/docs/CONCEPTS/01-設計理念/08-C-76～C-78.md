## 預設介質、開銷與啟動（11-05 使用者說）

- **C-76** **JSON 是 aos 的預設介質，但不定死**（使用者 11-05 晚，[thinking 11-05 json-argv](../../../thinking/2026-11/05/json-argv/README.md)）：使用者列的好處——「爲何要json？我看重他的好處在於幾個點：1. 就算不憑藉任何工具，人類也能理解…… 2. 大語言模型生成起來幾乎不會出錯，就算是笨模型也是。 3. tool呼叫就是用json格式。 4. 與檔案系統的同像性。 5. 大部份程式語言都原生支援。」問到要不要寫成規範：「看起來是的，但我沒有定死，就只是把優點擺出來，之後實際工程上大家就依據需求斟酌使用。」手改不便（不能註解、尾逗號）：「是的，但我們也有各種工具，不管是jq，或是寫一個小程式將其抽象化/自動轉換，或是把一些重要的東西抽出來成簡單json，讓人簡單改。」白話：預設用 JSON、優點擺著，工程上照需要斟酌，不寫成硬規。（格式族與「不認得的 key 忽略」見 C-48；JSON＝埋在檔案裡的 table 見 C-72。）
- **C-77** **開銷不算啥，能包成 aos 函數的盡量包**（使用者 11-05 早，[thinking 11-05 kernel-daemon](../../../thinking/2026-11/05/kernel-daemon/README.md)）：「啊不過老實說，我們的核心思想就是開銷不算啥，因為LLM本身就是最消耗時間的。所以...還是都包成aos函數吧」「能包盡量包啦」。白話：LLM 本身最花時間，包成 aos 函數多出的開銷不必算。（例：問腦也包成 aos 函數、掛在 daemon 下，見 N-42；轉交型可帶 kernel 字、別濫用那句在 C-47。）
- **C-78** **啟動的判準：盡量快，四步**（使用者 11-05 早，[thinking 11-05 portable-flow](../../../thinking/2026-11/05/portable-flow/README.md)）：「主要就：啟動盡量快，就是複製過去、起daemon、(設好環境變數)(盡量少)、aos-exec開跑。」又補「起daemon...對啦，也可以不起，那就是沿用」。白話：①複製過去 ②起 daemon（已有就沿用）③設環境變數（盡量少）④aos-exec 開跑；新東西若讓啟動多出一步，要標出來（portable-flow 的實作步驟都照這四步量）。
