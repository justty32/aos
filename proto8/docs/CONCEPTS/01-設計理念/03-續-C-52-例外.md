## 使用者裁定（11-06，選項框）：C-52 的讀法、准讀下層 stderr 改成判準＋現行表

出處 [special-cases 使用者裁定](../../../thinking/2026-11/06/special-cases/README.md#使用者裁定11-06選項框)。上文與主檔原句全留，照下面改讀。

- **讀法：不認身份、可認公開介面**（選項「不認身份、可認公開介面 (Recommended)」）：本條「上層不需要、也不該知道下層是什麼」讀成——上層可以依賴下層**公開宣告**的介面（對外標頭、schema、`interfaces.json`），**不准**認對方的程式名、內部檔名、錯誤字句來分支。例：daemon 的 loop 型可以用 aos-loop 公開的 `ctl`／`state`／`state_flux` 窗，但不准認 aos-loop 錯誤行的字句。**11-06 K-2 已實作**：daemon 不認 aos-loop 錯誤字句，`ctl`／`state`／`state_flux`（11-09 加）格式與預設名由 aos-loop 公開標頭一處定義。現況不合的幾處（llm kernel 讀 daemon 表的字句、手拼掛 proc 的信；lib 工具認範本）實作排在 [apply-ideas 02 § special-cases](../../../thinking/2026-11/06/apply-ideas/02-排程.md#11-06-special-cases-排程k-隊)。（11-07 使用者裁定 sol 審查 #25）
  **11-07 註**：例句的「daemon 的 loop 型」照 daemon 不分類改讀成「daemon 對任何列」：stop 寫的是那列的公開 ctl（小格父寫的 loop 設定有 `ctl` 就照它、否則 `ctl.json`），daemon 不翻身體的 loop 設定判型。使用者原話：「argv:[aos-loop loop.json]，我用aos-exec執行，這等同於我變成了aos-loop……在變成loop之前，我確實就是一次性程式沒錯」。（11-07 使用者裁定，出處 [proto8/thinking/2026-11/07/arknights-kb/07-停不下與消失.md](../../../thinking/2026-11/07/arknights-kb/07-停不下與消失.md)）
- **准讀下層 stderr：一條判準**（選項「改成判準＋現行表 (Recommended)」）：一層的出口讀者看不到下層的 stderr（外部 agent、腦、回信的收件人、看表的人）時，這一層**失敗時**可以把下層錯誤行的「代號與原因」接進自己那一行，或附下層 stderr 最後 2 KB；成功時不附；下層 stderr 照樣原樣透出。aos 內部上下層之間（讀者是程式）不適用。照判準推得出來的不必再逐項裁；透出的程式在自己的 README 寫一行「透出：哪種、給誰」。主檔的「三處」「只限 aos-mcp」「出口都是給人或外部 agent」與編號 ①～⑤ 改讀成下表。

## 特例怎麼處理：升格門檻（11-06）

原出處為使用者 11-06 選項框「第 3 次升格 (Recommended)」（[special-cases 04](../../../thinking/2026-11/06/special-cases/04-升格建議與慣例草稿.md)）；11-07 更新為下方判準。不只 C-52，條文與程式裡所有「一般規則＋例外」都照這幾條：（範圍句是 agent 補的，使用者沒裁過，可翻）

1. **認名型第一次就消**：例外要成立得讓 A 寫死認得 B 的程式名、內部檔名、格式或錯誤字句 → 改成「B 宣告、A 照宣告」或任何人都能寫的通用欄位（例：P6 → `auto_restart`）。
2. **同型特例再出現時問一次**：同一句「一般規則＋例外理由」再出現時，問「往後會更多嗎、好處遠大於壞處嗎」；依這個判準決定是否升格為一條判準，取代逐項清單。同型第 3 次只提醒重看，不是自動升格開關。（11-07 使用者裁定 sol 審查 #23）
3. **清單 5 項或 3 天 2 項只提醒**：可記「同型第 N 次」作提醒；一份例外清單到 5 項，或 3 天內加了 2 項，提醒照第 2 條重看；不因數字自動改寫。決定升格後才改成「判準＋現行表」（現行表只列現在有效的；原句照舊留在原處）。（11-07 使用者裁定 sol 審查 #23）
4. **「先不做」要寫等什麼**：範圍限縮型的例外寫一句「等 X 才動」，X 發生了照 1～3 重審。（agent 補，使用者沒裁過，可翻）

**11-06 已實作註（no-pid P7）**：P7 已照本條讀法完成：父只認公開 ctl／state／state_flux 窗（**11-09 補**（使用者裁 state_flux，[thinking clock-and-hot-writes 05](../../../thinking/2026-11/09/clock-and-hot-writes/05-state拆分規劃.md)）：state_flux 跟 ctl／state 同在 aos-loop 公開標頭 `aos/loop.hpp` 定義、任何程式照寫，屬「可認公開介面」；判卡住時父碰的子檔從 ctl＋state 變成 ctl＋state_flux；接回時看子 state 的 `phase == done` 照舊，N-17 的 11-07 確認），不讀子信箱、不認 daemon 身份。 見 [16](../../../thinking/2026-11/05/no-pid/16-P7重設計.md)、[17](../../../thinking/2026-11/05/no-pid/17-P7實作結果.md)。
