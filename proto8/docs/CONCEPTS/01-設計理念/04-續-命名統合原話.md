## 命名統合的使用者原話

細則都在 [C-54](04-C-54.md#命名10-15-使用者說原文) 與 [C-54 命名方法](C-54-命名方法.md)；這裡留原話、出處與統合出的基礎層共用錯誤代號。不留舊名。

- **命名統合**（[thinking 2026-10-23-naming](../../../thinking/2026-10/23/naming.md)）：使用者「都先幫我統合。統合好後更新文件和artifact，我等一下重看」；逐條看過頂層的統合，其餘認可，三條改選：純文字也帶 `.txt`、stack 預設位置 `.stack/`（C-65）、題目資料夾 `new/`＋照 Maildir 認領 `cur/`（C-65）。錯誤代號結尾是推薦的六種結尾＋`Internal`（[C-54](04-C-54.md#命名10-15-使用者說原文)）；[縮寫表](../abbr.json)有 `co`、`dotenv`。
- **基礎層共用的錯誤代號**（10-23 使用者「都先幫我統合」，[thinking](../../../thinking/2026-10/23/naming.md)）：用法不對 `ArgumentsBad`、不認得的旗標 `FlagUnknown`；設定檔不在或 `#/` 指不到 `CfgMissing`，讀不了、JSON 語法錯、欄位型別錯、互相衝突 `CfgBad`；fsm 的 state 讀不了 `StateBad`；工作區不在 `WsMissing`；`.env` 讀不了或壞 `DotenvBad`；要跑的指令找不到 `CommandMissing`、不能執行 `CommandBad`；直接叫庫跑單子檔時，檔本身不在 `EntryMissing`、讀不了或語法錯 `EntryBad`；aos-clock 也帶代號（`ArgumentsBad`、`FlagUnknown`、`ClockBad`、`WriteFailed`）。
- **「要跑什麼」＝`exec`**：使用者「fsm.json，現在是用val，幫我改成exec」，再選「exec，loop／daemon 的 run 也一起改 exec」——「要跑什麼」全體系一律叫 `exec`（loop／daemon、fsm 的每一格），C-55 的 `val` 只留給值的展開形；條文與訊息裡說「次」，不說「拍」。
- **入口與 `_` 開頭的 key**（[thinking 2026-10-23-naming](../../../thinking/2026-10/23/naming.md)）：使用者問「換_entry，有好處嗎」，聽完利弊後「改。然後_開頭=附註這個概念刪掉。」，又補「不認得的key就是忽略」——入口預設名 `_entry`（`AOS_ENTRY` 預設值、入口檔、JSON 的 key；使用者原話裡的 `_exec` 照留）；C-48 是通則「不認得的 key 一律忽略、不報錯」，沒有 `_notes` 慣例。
- **命名方法**（[thinking 2026-10-23-naming-method](../../../thinking/2026-10/23/naming-method/README.md)）：使用者「先試試看，不要急着寫進去」，查過 Unix／Linux 老慣例、八題選完後「寫進去吧」——C-54 的「命名方法」一點，R1～R12 細則在 [C-54 命名方法](C-54-命名方法.md)。
- **計數、時間點、上限**：使用者「state.json中，runs改counter，at改成recorded_at」、「計數這塊，幫我改成counter_*」；頂層問兩題（時間點規則要不要跟著改、上限要不要照 R6 改 `max_*`），使用者回「都好」（頂層代定、可翻案）——計數一律 `counter_<被數的東西>`（例 aos-loop 開旗標才寫的 `counter_runs.txt`，[N-09](../../NORMS/05-基礎設施-窗/02-N-09～N-11.md)）、時間點一律 `<發生了什麼>_at`（例 `started_at`）、上限一律 `max` 或 `max_*`（[C-54 命名方法 R3、R6](C-54-命名方法.md)）。
- **程式名**（[thinking 2026-10-30-eca](../../../thinking/2026-10/30/eca/09-方向題.md#決定10-30) F-21、[10-30 map-review](../../../thinking/2026-10/30/map-review/01-使用者原文.md#決定10-30) 第 9、11 點）：使用者「我其實更prefer前者，因為以後會有一大堆領域，而kernel作為基底，他就是算...lib？」（講的是 llm kernel 的程式名），再要 aos-gate 換名字；頂層推成「程式名＝`aos-<領域>-<功能>`」寫進條文草稿，使用者「都照建議」——[C-54 命名方法](C-54-命名方法.md) R13（頂層推論、可翻案）。
