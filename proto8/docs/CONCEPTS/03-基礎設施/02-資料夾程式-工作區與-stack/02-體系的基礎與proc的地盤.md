### 體系的基礎與 proc 的地盤（11-04 晚、11-05 使用者說）

- **C-80** **不在任何 daemon 下的不管；體系的基礎是 daemon／loop／exec 三者合一**（使用者 11-05 早，[thinking 11-05 portable-flow](../../../../thinking/2026-11/05/portable-flow/README.md)）：「不在任何daemon下的，我們不管，我們這套體系的基礎就是daemon/loop/exec三者合一。指到daemon外面就是自行承擔風險。」又說「在這套系統下，我們不管不在daemon下的proc，所以所有proc都有daemon管...那就是那個daemon。」白話：每個 proc 都有一台管它的 daemon；路徑指到 daemon 外面，風險自擔。
- **C-81** **stack 是 proc 自己的地盤；對外介面四類**（使用者 11-04 晚，[thinking 11-04 aos-agent 06](../../../../thinking/2026-11/04/aos-agent/06-衝突與方向題.md#使用者原文11-04-晚逐字介面與-stack)）：「一個proc，你在stack中放啥都可以，因為那是你的地盤，頂多你要考慮到繼承於你的傢伙，在設計他自己的stack的時候是否會容易命名衝突，導致你可能要把一些路徑放在.json中去設定(比如eca他固定吃cli.json...)。但是你對外的各種介面都必須在遵守原則的情況下保持靈活。基本就三類：命令行參數、吃/設的環境變數、stdin/out/err/exit、信箱內容格式。」現行是四類（原話說「基本就三類」、列了四樣；待裁網頁 條文-10-C81 選 A）：命令列參數、吃／設的環境變數、stdin／stdout／stderr／結束碼、信箱內容格式。stack 裡放什麼自訂；外人讀寫它 stack 裡的檔沒問題（使用者 11-13「拿掉限制。等以後踩坑再回來處理。」，再選「rd-C81:A」＝只改本條，[裁定落地-1113](../../../../thinking/2026-11/13/裁定落地-1113.md)）。對方宣告過的覆蓋層照舊是給外面寫的地方，檔名只寫在宣告一處（使用者 11-06 選項框「宣告過的覆蓋層可寫 (Recommended)」；[apply-ideas 02](../../../../thinking/2026-11/06/apply-ideas/02-排程.md#11-06-special-cases-排程k-隊)；宣告檔的名字見 [NORMS 命名續](../../../NORMS/命名-續-概念搬來的檔名.md)）。proc 可以像 Go interface 那樣宣告自己遵守哪些約定（見名詞表「介面」）。
