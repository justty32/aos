## 資料夾程式、工作區與 stack（10-19）

規範：[NORMS 資料夾程式與執行](../../NORMS/10-基礎設施-定義與工作區.md)（N-57～N-62、N-53、N-55）；慣例：[CONVENTION](../../CONVENTION.md)；實作：[aos-exec](../../../impls/aos-exec/README.md)、[templates](../../../templates/README.md)。資料夾＝程式、入口、環境變數是 [C-68～C-70](../01-設計理念/06-C-68～C-72.md#資料夾程式與環境變數10-19-使用者定)。

> 用詞（C-54）：**定義**＝一個資料夾（程式）；**入口**＝`$AOS_ENTRY` 指的檔（四種：可執行檔、inst 單子、argv 陣列、`js[$AOS_ENTRY]`，C-73）；**stack**＝被叫的那個程式自己的 `$AOS_STACK`（執行中狀態）；**小格**＝叫別的資料夾程式時給它的 stack（`$AOS_STACK/tools/<名>/`，見 [P-17](../../CONVENTION/02-題目stack停錯腦.md)）；**工作區**＝使用者的檔與成品所在的資料夾（`$AOS_WS`，C-65）；**heap** 保留給以後跨呼叫共用的記憶，目前沒有機制。見[名詞表](../附錄1-名詞.md)。

### stack 與工作區分開（10-16 夜，10-19 改）

出處：[稿 § 四](../../../thinking/2026-10/16/agent-inherit/02-四-使用者決定.md#四使用者決定10-16)（決定與原話）、[稿 § 八](../../../thinking/2026-10/16/agent-inherit/03-五-自然組合的機制.md#八工作區與-frame-分開10-16-夜重想ai-提案指標捷徑工具可直接-cwd-ws風險設計者自管已定)；環境變數那半見 [ideas § 2、§ 3、§ 9](../../../thinking/2026-10/19/ideas/README.md)。規範 [N-55](../../NORMS/10-基礎設施-定義與工作區.md)、慣例 P-14～P-18。

- **C-65** **stack 與工作區是兩個東西**（使用者 10-16 夜原話：「我記得先前還有一個叫做frame的概念，也就是agent當函數，函數運行時候的heap(還是stack?反正就是運行時才會往其中放資料的)，可以指定某個資料夾當heap。用捷徑也不錯。然後我不喜歡/ws底下出現一個work/，這太突兀了，工作區會變得不乾淨。」——「用捷徑」那半由環境變數做；名字：使用者「不過frame那塊能不能換成stack(或heap)?。」→ 頂層推薦 stack、heap 留給以後跨呼叫共用的記憶 →「好！」）：**stack**＝被叫的程式執行時才往裡放東西的地方——狀態、草稿、紀錄（例 fsm 的 `stage.txt`、對話的 `history.jsonl`）、叫別的程式時開的小格；像函數跑起來的呼叫堆疊：每叫一次別的資料夾程式就給它一個小格（續聊＝同一個 stack 再跑，要忘記＝換一個）。**工作區**＝使用者的檔、成品要留的地方（`$AOS_WS`），像 C 的外部變數。程式起跑時 cwd 是它自己的資料夾（N-59）；**工作區只放交辦的東西與成果**——使用者的檔、agent 寫出的成品檔；執行時的東西落在 stack，對話（queue、history）也是這次執行的狀態、落在 stack（使用者 10-30「都照建議」，[thinking 10-30 agent-lifecycle](../../../thinking/2026-10/30/agent-lifecycle/07-衝突.md#決定10-30) 衝突 1；[10-29 agent-bob](../../../thinking/2026-10/29/agent-bob/04-頂層對八題的再想.md#決定10-30) 決定 35、36；[CONVENTION P-11、P-41、P-42](../../CONVENTION/02-題目stack停錯腦.md)）。題目資料夾那四格（`new/`、`cur/`、`done/`、`out/`，P-11、P-14；使用者 10-23 選「改成一致的階段名」：題目照 Maildir 原意 `new/`＝還沒做、`cur/`＝已認領處理中、`done/`＝做完，答案放 `out/`，[thinking 10-23 naming](../../../thinking/2026-10/23/naming.md)）是舊協議，只有舊範本在用。`AOS_STACK` 這個環境變數出自使用者 10-19：「所以我們再設定一個AOS_STACK=ws/.aos/」（[ideas § 9](../../../thinking/2026-10/19/ideas/README.md)）；預設值是 `$AOS_WS/.stack/`（隱藏資料夾，跟 `AOS_STACK` 同字，使用者 10-23 選，[thinking 10-23 naming](../../../thinking/2026-10/23/naming.md)）。
- **C-66** **影響外部＝透過指標，指標＝環境變數 `AOS_WS`**：像 C 函數要改外部變數得拿到指標，工具要動呼叫者的工作區，也是拿到一個指向工作區的東西，不是自己伸手出去；在 aos 裡這個指標就是環境變數 `AOS_WS`（N-55）。能不能寫由 Linux 權限管（C-64），風險由工具的設計者自己管控。（使用者 10-16 夜：「除此之外，C語言函數想要影響外部變數，那也是透過指標」；「對，我覺得這樣會更方便。風險就設計者自己管控」）起跑 cwd 一律是程式自己的資料夾（N-59），要碰工作區就用 `$AOS_WS`。
- **C-67** **stack 放哪由呼叫方自由決定**：被叫的 agent 不知道也不必知道（C-52）；「stack 在哪」只是環境變數 `AOS_STACK` 的值，改值就得到不同效果，程式不動、規則一條都不用加——這是刻意保留的自由度。例（[稿 § 八 3b](../../../thinking/2026-10/16/agent-inherit/03-五-自然組合的機制.md#3b-frame-指到哪是呼叫方的自由概念層的一句)）：stack 指到工作區＝就地辦公（代價：執行時的東西全落進工作區、可能跟使用者的檔撞名）；兩個 agent 共用一個 stack＝共享記憶、接力（同時跑會互寫，P-18）；stack 放暫存目錄＝用完即丟（當機就沒了）；stack 長期保留＝下次接著聊（小格會一直堆）；stack 放在別人唯讀可看的地方＝旁人能審視、改不了（C-64）。代價都是呼叫方自己的選擇。（使用者 10-16 夜：「只是我們可以偷偷把它的frame設成ws」「我們可以自由管控他的frame要在哪裡，從而達到各種神奇效果」）
- **C-87** **往下「變成」另一套＝共用同一個 stack（像繼承）；「叫」另一個程式＝給它小格（像組合，P-17）**（使用者 11-02，[exec-inheritance](../../../thinking/2026-11/02/exec-inheritance.md#結論11-02跟使用者討論後)）：「就是說，我們現在的aos體系，就是aos-exec一環套一環，用aos-exec跑一個資料夾，他可能會先執行一套，這一套在執行過程中又可能變成另一套，然後大家全都共用一個stack。這其實有點類似繼承，你要考慮你的base class做了啥，用了啥，並且斟酌決定是否要覆蓋，或是避開」。共用 stack 撞名，aos 不做隱性的命名空間（不像 C++ 自動各自分開）：各自管好，常見的名字加自己的前綴（例 daemon 管別人的那對窗叫 `procs_ctl.json`、`procs_state.json`），或自己開資料夾放（使用者：「我們不做這樣的隱性操作，大家就是各自管好自己的手」「或是自己開個資料夾放」）；控制自身的那對窗不加前綴，就叫 `ctl.json`／`state.json`（使用者「好。」，[ctl-state-names](../../../thinking/2026-11/02/ctl-state-names/README.md)）。契約或機制現在不做（使用者「當然，未來可以考慮弄一些契約或機制，但那是以後的事情。」）。繼承的比喻只用在宣告時的撞名；呼叫沒有 base／derived 之分——同一組檔可以從起點一路往下叫，也可以從另一端開始一路叫回來，誰叫誰看入口從哪進（使用者：「所以在呼叫這塊，其實沒有base class, deriative class之分。」）。

### 體系的基礎與 proc 的地盤（11-04 晚、11-05 使用者說）

- **C-80** **不在任何 daemon 下的不管；體系的基礎是 daemon／loop／exec 三者合一**（使用者 11-05 早，[thinking 11-05 portable-flow](../../../thinking/2026-11/05/portable-flow/README.md)）：「不在任何daemon下的，我們不管，我們這套體系的基礎就是daemon/loop/exec三者合一。指到daemon外面就是自行承擔風險。」又說「在這套系統下，我們不管不在daemon下的proc，所以所有proc都有daemon管...那就是那個daemon。」白話：每個 proc 都有一台管它的 daemon；路徑指到 daemon 外面，風險自擔。
- **C-81** **stack 是 proc 自己的地盤；對外介面（原話三類、列四樣）**（使用者 11-04 晚，[thinking 11-04 aos-agent 06](../../../thinking/2026-11/04/aos-agent/06-衝突與方向題.md#使用者原文11-04-晚逐字介面與-stack)）：「一個proc，你在stack中放啥都可以，因為那是你的地盤，頂多你要考慮到繼承於你的傢伙，在設計他自己的stack的時候是否會容易命名衝突，導致你可能要把一些路徑放在.json中去設定(比如eca他固定吃cli.json...)。但是你對外的各種介面都必須在遵守原則的情況下保持靈活。基本就三類：命令行參數、吃/設的環境變數、stdin/out/err/exit、信箱內容格式。」白話：stack 裡放什麼自訂；對外介面就這四類（原話說三類、列了四樣，照四樣）——命令列參數、吃／設的環境變數、stdin／stdout／stderr／結束碼、信箱內容格式。三類還是四類待使用者確認（四樣都列了，實作沒差）。外人讀它 stack 裡的檔沒問題；外人寫別人 stack 的檔，限對方在 `interfaces.json` 宣告可從外面寫的（覆蓋層），其他經信箱或 ctl（使用者 11-06 選項框「宣告過的覆蓋層可寫 (Recommended)」；[apply-ideas 02](../../../thinking/2026-11/06/apply-ideas/02-排程.md#11-06-special-cases-排程k-隊)）；覆蓋層檔名只寫在宣告一處。proc 可以像 Go interface 那樣宣告自己遵守哪些約定（見名詞表「介面」）。
