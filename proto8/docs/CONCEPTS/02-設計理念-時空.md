# 設計理念／時空

- **C-05** 空間就是資料夾，時間就是 tick；這一塊已定，不再討論。（2.5、2.12）
- **C-06** tick 之間，所有與外部有關的狀態一致。（9/24）
- **C-16** tick-tock 的本質是定義時間、讓時間能停；停下來後 agent 看到的就是那個時間點的空間，可直接打包。（2.11）〔以 C-44 為準：tick-tock 就是時鐘、不保證什麼；打包是規範、由 kernel 做。〕
  **11-06 註**（使用者 11-05 夜，[fs-image](../../thinking/2026-11/05/fs-image/README.md)）：「我們只要把daemon以及一切都停下來(sleep)，那麼整個資料夾都停下來了(當然，除了一些外部的東西會寫檔)，這類似lisp的image，只是說他這個是更好理解的，畢竟人和AI可以翻資料夾。這除了可以用git之外，這種非同步呼叫也是，可以去看看說目前是哪些信。」——全部 sleep＝整個資料夾凍住，像 image，人與 AI 能翻、能 git。**暫停的目的是遷移**（使用者 11-06，[daemon-board 04](../../thinking/2026-11/06/daemon-board/04-凍住後要能遷移.md)）：「我知道linux有原生暫停，但我想要的是暫停後能遷移。」所以不用 Linux 原生暫停（SIGSTOP，行程與記憶體搬不走）；aos 的 sleep＝休眠到磁碟＋可插拔存儲（狀態全在檔案、行程不在）。遷移的單位＝一棵樹一個 image，跨樹的連線算外接（使用者 11-06「兩題都按照推薦。」，[daemon-board 04-續](../../thinking/2026-11/06/daemon-board/04-凍住後要能遷移-續.md)）。現況：單台 daemon sleep 已凍得住，11-05 `cp -a`／git 搬家實測過；整樹一次睡已定（11-05，[no-pid 05 監管樹](../../thinking/2026-11/05/no-pid/05-監管樹.md)）；實作排在 no-pid P6。
- **C-17** 停下來時正在跑的任務可以不被迫停止；那個時間點的空間裡可以含「這件事正在跑」。（2.11）
  **11-06 改讀**（使用者 11-06 裁 D1「先只有硬凍」，[apply-ideas 03](../../thinking/2026-11/06/apply-ideas/03-方向題.md)）：現在只有硬凍——loop 型收 SIGTERM、單子跑完或被收；「正在跑的任務可以不被迫停止」靠 stack／state.json 醒來接著做實現，不是行程不停（原句保留）。軟凍（kernel 公告第 N 回合、大家在那之前存檔）現在沒有。
- **C-79** **image 模型：daemon＝硬體、stack＝記憶體、ws＝外置記憶體、定義＝source code**（使用者 11-05 早，[portable-flow](../../thinking/2026-11/05/portable-flow/README.md)、[02 image 模型](../../thinking/2026-11/05/portable-flow/02-image-模型.md)）：「想想看，lisp可以做image，直接在程式執行中把狀態保存起來。在我們這邊，daemon就像是硬體，各stack就是各程序所佔據的記憶體空間。ws則是外置記憶體。各種定義資料夾則是類似source code，跑起來之後就是看其實例了(daemon下的stack)」；搬家：「搬家這塊，我預期可能會搬到另一個電腦，乃至於透過git管理，我到另一台電腦做git pull」。白話：搬家＝把 image 存起來、到別台載回來接著跑，跟 C-16 的暫停時間是同一個 image（11-05 `cp -a`、git clone 實測醒來續答）。各零件的板子比喻見 [附錄1 續 板子比喻](附錄1-續-板子比喻.md)。
- **C-26** 沒輸入就每 tick 沒事。（9/23）
- **C-27** tock 的時機（任務都結束就提前 vs 固定間隔）應該是可選的。（10-04 user-advice）
- **C-30** 空間的定義可以擴到外部設備：資料庫、硬碟、快取、記憶體、雲端都能納入空間，像 Plan 9。（3d）
- **C-31** 行程本身也是掛在空間裡的一個東西。資源、設備、PU、行程，全是空間裡掛著的節點。（3e）
- **C-32** 空間就是存放狀態的地方。（3h）
- **C-33** 處理單元／處理（process）＝過一段時間後造成的變化，變化指的是空間上的變化。（3h）
- **C-35** Linux 檔案系統就是一個 LISP；資料夾＝list，list 裡有 list。（3f.1、9/19）比喻用 table（[C-71](01-設計理念/06-C-68～C-72.md#資料夾程式與環境變數10-19-使用者定)）：資料夾＝table、table 裡有 table；本質不變——用 index＋巢狀分資料，只是 index 格式不同。
- **C-37** 時空固定：空間照 Plan 9；時間是 tick-tock，一個可看可不看的時鐘；要先有時間後面才不會亂。tick-tock 可以跟 node 的狀態變化完全脫鉤，node 要看就訂閱。（3f.5、3g.5）
- **C-44** tick-tock 就是一個時鐘（「甲」）：不包任務、不保證什麼；「tick 之間可以安全打包」是後續大家要遵守的規範，不強制；打包這塊在後續 kernel 那邊做。（10-12） 〔實作：時鐘＝`proto8/cmd/aos-tick/bin/aos-tick FILE`，讀 n 寫 n＋1（照 10-12 使用者「做吧」的規格，[tasks-ticktock](../../thinking/2026-10/12/tasks-ticktock.md)）；節奏、停、只走 N 回合交給跑它的 loop，例子在 tick（11-04 隨 proto8/tests 刪了）。〕 **11-06 註**（使用者 11-05 夜，[fs-image](../../thinking/2026-11/05/fs-image/README.md)）：「至於aos-tick跑在哪，那其實也不重要了。」——大家只認 `AOS_TICK` 指的那個時鐘檔（兩鐘規則見 [N-65](../NORMS/02-設計理念-時空.md)）；已定（11-05，[fs-image](../../thinking/2026-11/05/fs-image/README.md)）；實作排在 T1、T7。
