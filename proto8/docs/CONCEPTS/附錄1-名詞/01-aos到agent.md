## 1. 名詞（一）：aos、時空、資源、kernel、agent

| 詞 | 使用者的意思 | 出處 |
|---|---|---|
| aos | 蓋在 Linux 上、為「任意目標」最佳化、要讓大語言模型方便用的作業系統 | 2.1、2.5 |
| 目標 | 排程要最佳化的東西；AI 時代目標變多（可用性、人類可理解性……）而且任意 | 2.1、2.4 |
| 計算任務 | 一個照 POSIX 方式被叫起來的行程，不是 thread | 2.7 |
| 資源 | 處理計算任務時會用到、而且有限的東西；它自己也當行程看 | 2.7、2.8 |
| 格 | 資源的「有限」用幾個數來講：一個資源有幾格 | 3b |
| 排序演算法 | 決定哪個任務先給哪個資源處理；它自己也是計算任務 | 2.7、2.8 |
| 排程／資源分配 | 把任務分給擅長它的資源，有限時排優先級；使用者把這兩詞和「排序」幾乎互換用 | 2.2、2.3 |
| 優先級 | 有限資源下「誰先」的那個先後 | 2.2 |
| 空間 | 東西存在的地方＝資料夾體系；**就是存放狀態的地方**；資料庫、硬碟、快取、記憶體、雲端這類外部設備也可以納入空間（像 Plan 9） | 2.5、9/24、3d、3h |
| 時間／clock（時鐘） | 取得下一個時間點的狀態；格與格之間所有對外狀態一致（使用者叫這「時空法則」） | 2.5、9/24 |
| cycle（格） | 時鐘的一格，時鐘走一步就多一格；用時鐘計的欄位帶 `_cycles` 單位（`timeout_cycles`、`sent_at_cycles`，C-54 R6） | 11-09 |
| 凍住 | 時鐘讓時間能停下來；正常結束時 agent 看到的資料夾就是那個時間點的狀況；可以打包（C-16、C-17） | 2.11 |
| 變換 | 符合 POSIX 的呼叫（和時間、空間並列的第三樣） | 9/24 |
| daemon | aos 與 Linux 之間的借階層；Linux 那邊的事（許可權、身分、記憶體、硬碟、行程）全在這層；有了它 aos 就有了「硬體」。也是**最基礎的 kernel（來者不拒：收到掛的請求就掛）；它的 stack 就是它本身**。照 C-47 從寄件人看：請求直接寄給 daemon 的人（例：沒設 `AOS_KERNEL` 時），daemon 對他就是 kernel（使用者 11-05「daemon是硬體，他是比較特殊的存在，他的stack就是自己本身，所以才說AOS_DAEMON，而非AOS_DAEMON_STACK」「從這個來看，其實daemon也算是一種kernel，只是他就是來者不拒，可以說是一種最基礎的kernel實作」，[thinking 11-05 kernel-daemon](../../../thinking/2026-11/05/kernel-daemon/README.md)；C-47）。daemon 是 Linux 行程與 aos 之間的**橋梁**（使用者 11-05 晚「所有牽涉到linux原生行程的機制，都以daemon爲界面，而daemon所擔任的，就是橋梁，並且盡量將各類東西暴露爲檔案」，[no-pid 入口](../../../thinking/2026-11/05/no-pid/README.md)）：只有 daemon 碰 pid，其他人讀它寫的檔、往它的信箱寄信（寄信不回＝呼叫失敗）；例外是 `aos-daemon-ctl poke`（門鈴，不帶內容、不判死活）照 daemon 自己 state 的 pid 三欄對過 /proc 才送訊號，叫它立刻看一次檔（[N-17 的例外](../../NORMS/05-基礎設施-窗/06-N-17.md)）。**監管樹**：每台 daemon 都是某台 daemon 底下的 proc，問誰的死活問它的上一層；子 daemon 對上一層就是普通 proc、上一層不認它的 daemon 身分（使用者 11-06「對於daemon來說，子daemon對他來說就只是一個普通的proc。不要耦合」，[no-pid 15](../../../thinking/2026-11/05/no-pid/15-P6去耦合.md)）：要 crash 了重起就在那列寫任何 proc 都能寫的 `auto_restart: true`（連 3 次起不來才留 `stopped`）；判卡住只看公開窗，預設標 `stuck`，選填 `restart_on_stuck` 才重起（[16](../../../thinking/2026-11/05/no-pid/16-P7重設計.md)、[17](../../../thinking/2026-11/05/no-pid/17-P7實作結果.md)）；整棵樹一層層睡醒是每層自己收工、自己醒的結果；窗的 `daemon` 欄記上一層，`aos-daemon-ctl ls` 尾行印上一層的看法。**根 daemon** 就是普通 daemon，只是頭上沒人，由使用者顧（使用者 11-05「他就是一個普通daemon，只是說因爲他頭上沒daemon了，所以使用者要保証他能正常運行」「但也可以就只是一個普通的linux user proc，壞了就壞了」，[no-pid 05 監管樹](../../../thinking/2026-11/05/no-pid/05-監管樹.md)）——要一直在就自己交 systemd／s6，也可以就是普通使用者行程；aos 不做根的根 | 2.5 |
| kernel | 管理正在跑的程式、分配 cpu、粗放式（Linux 是細粒度）、要讓 agent 能自省的那一層。aos 的說法是「資源管理＋排程」，而且是從外面看進去的身分——請求寄到哪，那裡對寄件人就是 kernel；收件的 proc 不必知道自己是 kernel（C-47） | 9/19、9/23、11-11 |
| cpu（使用者的用法） | kernel 開來跑某個資料夾的一個執行單位；畫家也是一顆 cpu | 9/23、2.3 |
| 核心（aos 作業系統核心） | 到「排序程式可由模型生成」為止這一整塊；在它之上才是 agent。使用者原話是「aos 作業系統核心」。C-74 分層裡的「核心」指 aos-exec（見「核心（分層）」列），同詞兩義、照上下文分（使用者 11-17 選項框「改回「核心」」；待裁網頁 條文-1a 選 B） | 2.10 |
| agent | 一個狀態機（想→做→循環）、一個函式、一個複合型計算任務 | 2.13、2.14、2.18 |
| 函式／黑箱 | 給東西、跑一跑、停下來；strcpy 和 LLM agent 對我們都是黑箱，差在使用方式與計算特性 | 2.14、9/19 |
| 腦 | agent 裡負責思考的大語言模型 | 2.17 |
| 核心人格 | system prompt | 2.17 |
| 近期記憶 | 一般上下文 | 2.17 |
| 手腳 | agent 可用的工具 | 2.17 |
| 九軸 | 每個計算任務固有的計算性特性：副作用、冪等、碰外部檔案、持續性、有無 entry、確定性…… | 2.9 |
| 附加特性 | 九軸之外、人隨意加的特性（例：「繪畫上偏現代」）；會多到只能靠模型處理 | 2.9 |
| 確定性 | 任務自己的屬性：有沒有機率問題；跑 LLM 的任務不確定 | 2.9、2.14 |
| 可預測性 | 觀察者對任務的認識，有主體性（對誰可預測）；確定性高不等於可預測 | 2.14、2.15 |
| S 表示式／節點 | 把流程看成一棵樹，有些節點我們知道、有些不知道；呼叫模型的節點是不知道的那種 | 2.16 |
| list／eval | 檔案系統看成 list；eval＝求某關卡之後的狀態，list 自己就是被跑的程式，其餘是環境。「list」用 table 比喻（C-71），意思不變 | 9/19 |
| 生成排序程式的程式 | 叫大語言模型幫忙定義資源、寫排序的那個程式 | 2.10 |
| 快取／靈感 | 資源手邊現成的東西；沒有就要去找，找的時間算進處理時間 | 2.3 |
| PU（處理單元） | 會「算」的東西：普通 CPU 跑一般任務；畫師、GPU、NPU 是另一種 PU，屬外部設備——工作丟給它、它用自己的方式算、算完收回 | 3d |
| 求值 | 放開讓它算，過一段時間看它狀態變化的結果；求值＝空間狀態的變化。對資料夾求值＝執行這個資料夾（inst） | 3h、3f.1 |
| 外部設備 | 系統外面但能掛進來用的東西：PU（畫師、GPU、NPU）與儲存（資料庫、硬碟、快取、記憶體、雲端） | 3d |
| 間接抽象化 | 沒法直接變成 POSIX 呼叫的事（人手畫），拆成幾個 POSIX 任務包起來：寄信給畫家、收信、畫歸檔 | 3c |
