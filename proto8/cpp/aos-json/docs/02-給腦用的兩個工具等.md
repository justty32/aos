## 給腦用的工具（在 lib）

給腦掛的工具都在 lib，照 lib 的契約走（`tool_io`、`_tooldef.json`、沒設 `AOS_WS`＝`WsMissing`）；它們叫 PATH 上的 `aos-json`。說明在 lib 的索引：

- **json 工具一族**（[thinking json-tools](../../../thinking/2026-11/12/json-tools/README.md)）：程式一份 [`py/aos/json.py`](../../../py/aos/json.py)（一次多格的兩支在 [`aos_json_multi.py`](../../../py/aos/json_multi.py)），十四個資料夾只是殼；路徑一律一整串 `檔#/指標`。
  - 簡單組 `py/tools/base/json_get`、`json_ls`、`json_search`、`json_len`、`json_set`、`json_add`、`json_del`，加 `json_multi_get`、`json_multi_set`（逐格做、一格一行、不回滾；包 `py/packs/json.json`）：值照字面；讀叫 `aos-json get／ls／search`，寫叫 `aos-json set／append／add／del --raw`（路上的 `$ref`／`$env` 當普通物件）；ls／search／add 的邏輯在 aos-json 裡，Python 只管參數、上限與把訊息說成參數名。說明在 [py/docs/02 索引：base](../../../py/docs/02-索引-base與索引-aos.md#索引base)。
  - 複雜組 `py/tools/aos/jsonx_get`、`jsonx_ls`、`jsonx_search`、`jsonx_set`、`jsonx_add`、`jsonx_del`，加 `jsonx_multi_get`、`jsonx_multi_set`（包 `py/packs/jsonx.json`，agent-fsm、eca-claude 範本都掛）：腦明講才帶 `--follow`、`--resolve`、`--check`，值可從 `text`（當 JSON 解）或 `from`（另一格）來。說明在 [py/docs/02 索引：aos](../../../py/docs/02-索引-base與索引-aos.md#索引aos)。
  - aos-json 退 1 時接它錯誤行的代號與原因（C-52 例外 ⑤），例 `json_set: error: PointerMissing no such pointer: cfg.json#/a/b (the root has no a; give "parents": true to create objects along the way)`。

## 跟 aos-directive 的分工

`get --resolve` 與 `peek --follow` 指到的 `$ref` 直接交給 aos-directive（`resolve`、`resolve_shallow`），跟 aos-loop、aos-fsm 讀設定檔同一套；最外層的相對 `$ref` 從給的檔所在的資料夾算（沒解開捷徑，同 aos-loop 的 `load_cfg`），`#/…` 取的是值所在的那份檔（交給它 `RefBase{資料夾, 檔}`）。
但改檔要的是「這個值在哪份檔的哪個位置」，aos-directive 的 `resolve` 只回值，所以 `src/follow/` 自己往下走（語意見 [NORMS 指示詞 N-45](../../../docs/NORMS/06-基礎設施-命令列與指示詞.md)）：`$ref` 的字串→位置交給 aos-directive 的 `aos::ref_spot`（`#/…` 沒檔名＝寫著它的那份檔、`#./`、`#../` 都在裡面）；讀檔跳 `#!`、指標取原文、繞圈＝同一個檔＋指標又出現、陣列同名後蓋前仍在 `src/follow/kind.cpp`、`locate.cpp`，aos-directive 改了這幾樣要跟著改。

## 也讀 .md

11-21 晚（[thinking 知識庫-骨架加md-規劃-1121](../../../thinking/2026-11/21/知識庫-骨架加md-規劃-1121/README.md)，規則全文在 07-尋址規則.md）：實際的檔（解開捷徑後）以 `.md` 結尾＝不當 JSON 讀，`#/…` 照 md 的標題、`_`（自己的內文）、清單（號碼或 `鍵: 值`）、表格、整節只有一個 ```` ```json ```` 區塊找（aos-directive 的 `md_get`；Python 那份 `py/aos/mdpath.py`，同一張案例表）。

- `get x.md`＝整份文字（一個 JSON 字串）；`get x.md#/標題`＝那一節；`--str` 照舊（值是字串才印字面）；`get --tree x.md`＝整份倒成一棵 json（只收整份 md，不配 `--follow`、`--resolve`）。
- `ls`：md 文字底下的名字（`md_ls`）當 key 列，第一行印 `object, N keys`，`--long` 的型別與大小用各自 `md_get` 取到的值算；底下沒有名字的文字照字串印一行；json 區塊的值、表格的一列照 json 列。`--depth`、`--offset`、`--limit` 照舊。
- `peek`、`search`：整份 md（沒 `#/`）作用在 `md_tree` 的結果上（`search` 印的 `x.md#/標題/…` 可以直接拿去 `get`）；帶 `#/` 時作用在 `md_get` 取到的那一格。`search --up` 不收 md（`ArgumentsBad`）。
- `--follow`：路上或終點穿到指著 md 的 `$ref`，剩下的路接在 md 裡的位置後面一起交給 `md_get`；`where` 停在 md 那一站。md 取到的值不再穿、不再解指示詞（`--resolve` 也不解，同 aos-directive）。
- `check`：指著 md 的 `$ref` 指得到算對（md 裡面不往下驗）、指不到照舊 `DirectiveBad`。
- 指不到：`PointerMissing no such pointer: <spec> (<md 那邊的原因>)`，原因同 mdpath（`/A has no C (it has: B, …)`）；檔不在照舊 `FileMissing`。
- **不寫 md**：`set`、`add`、`del`、`append`、`merge`、`batch`、`env`、`ref`（含 `--move` 的目標）直接給 md、或 `--follow` 穿到 md，一律退 1：`aos-json: error: TargetBad <檔> is markdown: the json tools only read it; change it with a file tool (edit, write)`（建新的 `.md` 也不收）。

## 元素

逐檔「哪個檔負責什麼」從檔頭一句話生成，在 code map 的 [逐檔表 cpp.json](../../../../wf/knowledge/code-map/proto8/cpp.json)（`#/tree/aos-json`）；改說明去改檔頭。

## 建置與測試

```sh
python3 install.py                                    # 在 proto8 跑，編全家、裝進 proto8/bin
make -C proto8/cpp -j8 BINDIR=$AOS_HOME/bin aos-json  # 開發時只重編這支
```

依賴 aos-util、aos-directive（頂層 Makefile 一起編）。
**共用建置**：`aos-json` 列在頂層 `cpp/Makefile` 的 `LIBS`、`BINS` 裡（依賴寫在 `DEPS_json`），一次建全部的寫法見 `wf/workflows/testing.md`。
