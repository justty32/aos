## 用法

```
aos-loop [--max N] [--interval-ms N] [--ctl FILE] [--state FILE] [--state-flux FILE] [--enable-logs] [--enable-counters] CONFIG.json [-- ARGS...]
```

- **命令列**（`loop_cli`，aos-daemon 共用）：**唯一的位置參數就是設定檔**——必給、只能一個；可寫 `檔#/指標`＝讀那份檔裡那個位置的物件（aos-util 的 `load_cfg`）。
  旗標放設定檔前面、規則同 aos-exec（`--x V`／`--x=V`、重複給最後一個算、`--` 結束旗標；aos-util 的 `parse_cli`）；旗標名＝loop.json 的 key 名底線換連字號。
  不認得的旗標（含 `--cfg`）＝`FlagUnknown`；沒給、多給設定檔、旗標缺值＝`ArgumentsBad`（原因 `reason (usage: aos-loop [--max N] [--interval-ms N] [--ctl FILE] [--state FILE] [--state-flux FILE] [--enable-logs] [--enable-counters] CONFIG.json [-- ARGS...])`）；`--help`＝英文說明印 stdout、退 0；
  `--max`／`--interval-ms` 要是非負整數（只收 `[0-9]+`），不是＝`ArgumentsBad`（命令列用錯）。
  `--enable-logs` 是不帶值的開關（寫 `--enable-logs=V`＝`ArgumentsBad`）：印 log（見下面「log」）。`--enable-counters` 也是不帶值的開關（全家同名，[N-09「計數器」](../../../docs/NORMS/05-基礎設施-窗/02-N-09～N-11.md)）：有 state 窗時每跑一次寫 `counter_runs.txt`（見 [02 窗](02-窗.md)）；沒開 state 窗就什麼都不寫。
- **`設定檔 -- 參數...`**（使用者「aos-XXX ... ... -- ...，第一個...就是aos-XXX本身的旗標……第二個...就是目標檔案……後面就是純參數」）：
  設定檔之後接 `--`＝後面全是附加參數（那個 `--` 剝掉），**每次**接在 exec 後面：字串目標＝`[目標, 參數...]`、陣列＝接在最後、內嵌單子＝接在單子 `argv` 的最後
  （`argv` 要直接寫成陣列；是指示詞或沒寫＝`CfgBad`）；ctl 改不了它們。設定檔之後接的不是 `--`＝`ArgumentsBad`；設定檔之前的 `--` 是「旗標結束」（`aos-loop -- -odd.json -- 參數`）。
  跟 aos-exec 的差異：`aos-exec XXX args...` 的 XXX 後面全部原樣交給入口（`--` 也原樣、不剝）；所以 `aos-exec <loop 資料夾> -- 題` 會變成 `aos-loop <AOS_CF> -- 題`，aos-loop 在這裡剝掉 `--`、把「題」接到身體。
- **起跑時 旗標 ＞ 設定檔 ＞ 預設**（ctl 窗在跑的途中還能再蓋，見下面「窗」）。
- **loop.json**：`{"exec": aos-exec 的目標, "max": 最多幾次}`（使用者「exec，loop／daemon 的 run 也一起改 exec」，跟 fsm 格同名），選填 `interval_ms`、`ctl`、`state`、`state_flux`（下面「窗」），其他 key 忽略（`body`、`_entry`…）。
  - `exec`（`parse_target`）＝**字串**（每次 `aos-exec -- <exec>`；`--` 讓 `-` 開頭的目標不被當旗標）或**陣列 `[目標, 參數...]`**（每次 `aos-exec -- 目標 參數...`；元素都要是字串、不能空）。
    相對路徑照 cwd 算、loop 不 cd 不轉；loop 不驗目標存不存在，那是那次 aos-exec 的錯。WS、`AOS_STACK` 由那次的 aos-exec 照它的規則定（沿用 `$AOS_WS`，沒設用 cwd）。每次重找入口，入口換了下一次就生效。
  - `exec` 寫成**物件＝單子**：每次在 aos-loop 自己行程內交給 aos-exec 的 `run_inst`（同 aos-exec 跑單子：先解指示詞、驗 17 個 key、aos-inst 起、`timeout_ms`／`timeout_cycles` 擇一與 `grace_ms`、訊號轉給整群）。`timeout_cycles` 有時鐘比格數，沒時鐘以 `AOS_CLOCK_INTERVAL` 毫秒換算（預設 1000）；時鐘停了就不到期。
    跑的期間 `AOS_CF`＝設定檔的實際路徑、`AOS_CD`＝它的資料夾、`AOS_CO`＝`/exec`（設定檔寫 `檔#/指標` 時＝那個指標＋`/exec`），跑完還原；相對路徑（`cwd`、串流、`argv[0]`）從設定檔的資料夾算，
    單子裡的 `$ref` 從 `exec` 那格來自的檔的資料夾算；`AOS_WS`／`AOS_STACK` 照 loop 自己的，相對路徑以 loop 的 cwd 轉成絕對（`AOS_STACK` 結尾補 `/`，同 aos-exec；跑完還原；不驗、不建），不讀 `.env`。單子壞＝自己的錯一行（`EntryBad`／`DirectiveBad`／`LaunchFailed`，原因開頭 `inst cannot run: `）、退 1。
    被逾時收掉＝那次 143（失敗那行的「誰」＝`loop.json#/exec`）。`{"exec": "loop.json#/body", "body": 單子}` 照樣能用（字串目標，由那次的 aos-exec 跑）。沒有 `exec`＝`CfgBad`「nothing to run」。
  - `max` 非負整數，**沒寫＝不限**；0＝一次都不跑、退 0（負的、`null`＝`CfgBad`）。
  - `interval_ms` 非負整數，沒寫＝0：一次結束到下一次開始至少隔幾毫秒。
- **`on_start`／`on_stop`**（選填，寫法同 `exec`；`null`＝沒有）：`on_start` 在讀完舊 state、第一次之前跑一次；`on_stop` 在要退的那一刻跑一次（`finish` 之後、最後一份 state 之前），不論為什麼退：stop、跑滿、身體 10、身體失敗、訊號、自己的錯（設定讀不了的那種在 loop 起來之前，兩格都不跑）。SIGKILL 跑不到。
  - `on_stop` 的環境多 `AOS_LOOP_CODE`＝loop 要退的碼、`AOS_LOOP_SIGNAL`＝收到的訊號號碼（SIGTERM＝`15`；沒有＝空字串）、`AOS_LOOP_CAUSE`＝為什麼收工（下一條），跑完還原。
  - **`AOS_LOOP_CAUSE`**（11-14 B7；名字與值表照 ok-devt [定稿 2.2～2.4](../../../thinking/2026-11/14/ok-devt-1114/05-定稿.md)）：「為什麼結束」的代號，`[a-z_]{1,32}`，可以拿來比對。只在 `on_stop` 期間才設：aos-loop 一起來就 `unsetenv`，外層帶進來的 `on_start`、身體都看不到。agent 範本的 `aos-hook fire --agent … after_stop` 照宣告（`py/aos/apps/hook/loop_points.json`）把它放進 after_stop 事件的 `cause` 欄。

    | 值 | 情況 | 誰判定 |
    |---|---|---|
    | `stop` | ctl stop（ctl 窗的 `{"cmd": "stop"}`） | loop |
    | `sleep` | ctl sleep | daemon（原因檔） |
    | `remove` | ctl rm，或 daemon.json 裡沒有它了 | daemon（原因檔） |
    | `shutdown` | daemon 收工 | daemon（原因檔） |
    | `stuck` | 卡住被重起 | daemon（原因檔） |
    | `signal` | 收到訊號但沒有有效的原因檔（人手 kill、SIGINT、舊檔） | loop |
    | `max` | 跑滿 max 次 | loop |
    | `body_exit` | 身體以 10 結束 | loop |
    | `error` | 身體以其他非 0 結束、身體被訊號殺、loop 自己出錯 | loop |
    | null | 舊版 loop 沒給（`aos-hook fire` 把空的、沒設的當 null） | — |

    - `stop`、`sleep`、`remove` 跟 daemon 表上的 `stop_mode` 同名；`stop_mode` 是這張表的子集，兩邊加值要一起看。
    - `error` 只是停止的分類，不是錯誤結構，也不是錯誤代號。
    - **第一個原因不覆寫，唯一的例外**：同一次啟動（`boot_id`、`started_at_ticks` 都對得上）daemon 只寫一次原因檔——sleep 中又收工仍是 `sleep`，接回（adopt）重送、daemon 收工、卡住一律不覆寫；只有原因檔已經是 `sleep`（或 `stop`：stop 不寫檔，之後第一次寫的就是 `remove`），收的途中使用者明下 rm，daemon 才改寫成 `remove`（sleep 是「會再醒」、remove 是「不回來」）。細節見 [aos-daemon 03](../../aos-daemon/docs/03-起-停-暫停.md)。
    - 撞限額沒有獨立的值：依撞的是誰、被什麼訊號收掉，可能是 `error`、`signal`，或根本沒有 on_stop（SIGKILL）。要知道是不是撞限額，看表上的 `limit_hit`。名字 `limit` 保留。
    - `cause` 跟 daemon 表上的 `reason` 不同：`reason` 是給人看的一句話（上一次出錯的原因），不拿來比對；`cause` 是代號。
    - **判斷順序**（第一條成立就停）：① 收到 SIGTERM 而且原因檔有效＝檔裡的值（不管 ctl 窗的 stop、身體之後怎麼退）；② 收到任何訊號＝ctl 窗 stop 中是 `stop`，否則 `signal`（SIGINT、SIGHUP 不讀檔）；③ ctl 窗 stop＝`stop`；④ 跑滿＝`max`；⑤ 身體退 10＝`body_exit`；⑥ 其他＝`error`。
    - **原因檔 `$AOS_STACK/stop_cause.json`**：daemon 送 SIGTERM 之前寫（[aos-daemon 03](../../aos-daemon/docs/03-起-停-暫停.md)），`{"cause", "pid", "started_at_ticks"（表上那個值）, "at_ticks"（寫的那刻，CLOCK_BOOTTIME 換成 clock ticks）, "boot_id"}`。loop 只讀不寫、誰都不刪。有效＝`boot_id` 跟自己的一樣，而且 `started_at_ticks` 等於自己的啟動 ticks（`/proc/<pid>/stat` 第 22 欄，daemon 起的就是 loop），或 `started_at_ticks` < 自己的啟動 ticks <= `at_ticks`（daemon 起的是外殼 sudo、bwrap、aos-exec，檔在 loop 起來之後才寫）。`cause` 符合 `[a-z_]{1,32}` 就照抄（daemon 以後加新值，舊 loop 照傳）。
    - 檔不在＝靜默；讀不了、壞 JSON、少欄位、`cause` 格式不對＝一行 `aos-loop: warning: stop cause file unusable: ...`，照判斷順序往下；別次啟動、別人的檔＝靜默不用。已知漏洞（不修）：外殼的情況下 daemon 在 loop 本身 exec 之前就寫了檔，會回 `signal`。
  - 期限 `on_timeout_ms`（非負整數，0＝不限，沒寫＝5000；負的、非整數＝`CfgBad`）：目標（字串、陣列）自成一個行程群組，到時間 SIGTERM 整群、1 秒後還在就 SIGKILL；這個值大於 0 且單子自己沒寫 `timeout_ms`／`timeout_cycles` 才補上；單子明寫 `timeout_ms: 0`＝不限，不補期限。跑的期間收到的訊號轉給它（整群），之後照常收工。
  - **退非 0、逾時、起不來＝收工**（11-20 使用者「四個點都跟著停」；原本 11-11 定的是只一行 warning）：`on_start` 失敗＝stderr 一行 `aos-loop: error: PointFailed on_start <誰> exited N`（或 `did not finish in N ms and was killed`、`cannot run: 代號 原因`）、身體一次都不跑、以它的碼收工（逾時是那次的碼，起不來＝1），`on_stop` 照跑（`AOS_LOOP_CAUSE`＝`error`）。`on_stop` 失敗＝本來要退 0 才改以它的碼退（錯誤行 `PointFailed on_stop …`），本來就退非 0＝一行 `aos-loop: warning: on_stop …`、碼不變。跑的期間 loop 收到訊號＝照收到訊號收工，不算失敗。
  - 單子的 `AOS_CO`＝`/on_start`、`/on_stop`。aos-daemon 繼承 Loop，daemon.json 寫了也照跑，**失敗一樣收工**（11-21 使用者「daemon 也停」；原本 11-20 是只一行 warning）：`on_start` 失敗＝daemon 起不來，錯誤行的程式名是 `aos-daemon`。`Defaults::run_points` 只管收不收 `on_before_run`／`on_after_run` 與兩個 `_if`。
- **`on_before_run`／`on_after_run`**（11-20 hook 第 5 刀，[設計 06](../../../thinking/2026-11/20/aos-hook-plan-1120/06-loop層的點.md)；選填，寫法同 `exec`；`null`＝沒有）：身體每跑一次的前、後各跑一次。不吃 `on_timeout_ms`（要限時就在單子裡寫 `timeout_ms`：被扣在這裡等人是正常的）。單子的 `AOS_CO`＝`/on_before_run`、`/on_after_run`。一圈的順序：

  ```
  讀 ctl → tend → 停不停 → 暫停中、還沒到時間：睡，回頂端（兩個點都不跑）
         → on_before_run_if 的檔在嗎（沒寫當作在）→ 跑 on_before_run（這段期間 state 仍是 waiting）
              跑的期間收到訊號＝照收到訊號收工（不算失敗），身體不跑
              10＝跳過這一圈：不跑身體、不算一次（max 不算它）、不發 after；下一次＝現在加 interval_ms，回頂端
              其他非 0、逾時、起不來＝錯誤行 PointFailed run N: on_before_run …、以它的碼收工（on_stop 照跑）
              0＝再讀一次 ctl：這時下了 stop／pause 就照它（回頂端），身體不跑；已跑滿也回頂端
         → 次數加一、state 寫 running → 跑身體（身體起不來＝照舊收工，不跑 after）
         → 印 log；身體退非 0 不是 10＝印 RunFailed 那行
         → 這一圈沒收到訊號、而且 on_after_run_if 的檔在 → 跑 on_after_run
              跑的期間收到訊號＝照收到訊號收工
              非 0：身體是 0＝錯誤行 PointFailed run N: on_after_run …、以它的碼收工；身體本來就要收工（10 或失敗）＝一行 warning、照身體的結果
         → 照身體的結果往下（0＝下一次、10＝正常停、其他＝以那個碼停）
  ```

  - 環境（跑完還原，身體與 `on_stop` 看不到）：兩格都有 `AOS_LOOP_RUNS`（before＝這一次會是第幾次＝已跑次數加一，after＝同一個數）；`on_after_run` 另有 `AOS_LOOP_RUN_CODE`（身體的碼）、`AOS_LOOP_RUN_SIGNAL`（停掉身體的訊號號碼，沒有＝空字串）、`AOS_LOOP_RUN_MS`（毫秒），同 log 那一行的 `code`、`signal`、`elapsed_ms`。名字在 `aos/loop.hpp` 定一次（`runs_env` 等）。
  - **`on_before_run_if`／`on_after_run_if`**（選填，非空字串＝一個檔的路徑，相對＝照 cwd；可寫指示詞，例 `{"$env": "AOS_STACK", "$path": "/hook_before_run.flag"}`，`$path` 是直接接在後面）：寫了＝那個檔在才跑對應的點，每圈只看一次在不在（約 1 微秒）；沒寫＝每圈都跑。寫了卻沒寫對應的點＝`CfgBad`。誰建、誰刪旗標檔 loop 不管（使用者 11-20 選「用旗標檔」：有人掛那個點時才存在，由改 hook 清單的指令對）。
  - aos-daemon 不收這四個鍵：daemon.json 寫了（含 `null`）＝`CfgBad … is not taken by aos-daemon`（不讓任何東西跳過或拖住管理員的一圈）。
  - 今天沒有範本接這兩格：agent 的 loop.json 要接 `aos-hook fire --agent …` 得等 agent 讀自己的 `hook_points` 宣告（hook 介面第 3 刀）。
  - 被 daemon 接回（daemon 被 kill -9 後 adopt）的 loop 沒有重起，`on_start` 不會再跑；auto_restart 重起、開門 wake 是新的一支，會再跑。
- loop.json 帶 `"_entry": ["aos-loop", {"$env": "AOS_CF"}]` 時，`aos-exec loop.json` 就把 loop 跑起來（PATH 上要有 aos-loop 與 aos-exec；`_entry` 裡也可以放旗標）。
- 不讀 stdin；stdout 只印 log（下面「log」，沒給 `--enable-logs` 就不寫 stdout）。那次的 stdin／stdout／stderr 接 aos-loop 的。逾時交給單子的 `timeout_ms` 或 `timeout_cycles`（擇一），由共用 `run_inst` 判。

### log

使用者 11-02「daemon和loop他們就是把log輸出到stdout」「要給argv讓使用者選擇是否要印出」，11-02 晚「aos-loop和aos-daemon他們印出的log感覺都沒啥用，應該要改成默認不印」（[thinking 11-02 state 窗](../../../thinking/2026-11/02/state-window/README.md)）：

- **每跑完一次在 stdout 印一行 JSON**（不論那次怎麼結束：0、10、失敗、被訊號停掉）：`{"started_at": 這次開始（ISO 8601 UTC 到毫秒）, "counter_runs": 第幾次, "code": 結束碼, "signal": 訊號或 null, "elapsed_ms": 毫秒}`。結束不另印；`exec` 起不來（單子壞、fork 失敗）那次沒有結果、不印。沒有 `exec`（aos-daemon 純監工）不印每圈的行。
- **預設不印，`--enable-logs` 才印**。不寫任何 log 檔（loop.json 沒有 `log` key）；要存檔就在外面接（`aos-loop loop.json >> log.jsonl`）。
- 身體的 stdout 跟 log 同一條（那次繼承 aos-loop 的 stdout）；混在一起由使用者自己處理（11-02 晚使用者「stdin/out/err都可以任意指定」）。
- 一行一次 `write`（不經 stdio 緩衝）。印不了（stdout 是關掉的管子 EPIPE…）＝之後都不印、照跑、不退出：寫的那一下用 `pthread_sigmask` 擋著 SIGPIPE，寫失敗就把排著的 SIGPIPE 吃掉（零逾時的 `sigtimedwait`）再還原遮罩——**不改 SIGPIPE 的處置**（改成忽略會被 exec 的那次繼承，改了身體的行為）。stdout 是滿了的管子（讀的人不讀）時會卡在那一下，同一般程式寫 stdout。

### 指示詞

使用者「aos 讀的 JSON 全部支援」（N-45）：loop.json 與 ctl 裡也能寫 `$ref`／`$env`（寫法同 [aos-directive](../../aos-directive/README.md)）。**只解 loop 自己讀的格**（C-52；`resolve_keys`）：

- loop.json：整份先換一層（整份是 `{"$ref": "real.json"}` 也行），再把 `exec`、`max`、`interval_ms`、`ctl`、`state`、`state_flux`（還有 `on_timeout_ms`、`on_before_run_if`、`on_after_run_if`；`on_start`、`on_stop`、`on_before_run`、`on_after_run` 同 `exec`）整個解（`exec` 換一層後是物件＝單子，裡面不解，留到每次跑的時候 `run_inst` 解，`resolve_exec`）；相對 `$ref` 從設定檔所在的資料夾算（整份換過的從那份檔的；設定檔是捷徑＝實際的資料夾，同 aos-exec 與內嵌單子的 `AOS_CD`，`config_file`）。
  其他 key（`body`、`_entry`…）不碰：`loop.json#/body` 由那次的 aos-exec 自己解，body 裡的 `$env` 沒設是那次的錯。
- ctl：整份先換一層，再把 `cmd`、`max`、`interval_ms`、`seq` 整個解；相對 `$ref` 從 ctl 所在的資料夾算。
- 解不開（變數沒設、讀不到、指不到、繞圈）：設定檔＝自己的錯 `DirectiveBad`、退 1；ctl＝整份不採用、原因進 state_flux 的 `ctl_warning`。

```json
{"exec": [{"$env": "AGENT"}, "題"], "max": {"$ref": "common.json#/max"}, "state": "state.json"}
```
