### 命令列：設定、旗標、三扇門、指示詞

> **aos-exec、aos-loop、aos-fsm、aos-daemon 的命令列不照這一節**：不讀 stdin 設定，設定只認設定檔（loop.json、fsm.json、daemon.json 是唯一的位置參數，可寫 `檔#/指標`），
> 不寫結果 JSON（結果＝結束碼），錯誤一行「程式名: 代號 原因」。**旗標**：旗標寫在位置參數前後都收（11-11 P-44 續；位置參數後像負數或含空白的字照舊當位置參數），`--x V` 或 `--x=V`、重複給最後一個算、`--` 結束旗標（在位置參數後＝連它原樣交出）、
> 呼叫者給 `keep`＝第 N 個位置參數起原樣（子命令程式的頂層、aos-exec 的 XXX、aos-json set／append／merge 給 1＝舊規則）；不認得＝`FlagUnknown`、缺值＝`ArgumentsBad`。規則在 aos-util 的 `aos/util/cli.hpp`（`parse_cli`、`load_cfg`）：
> aos-exec 有 `--ws`、`--stack` 與不帶值的 `--dotenv-override`；aos-loop、aos-daemon 有 `--max`、`--interval-ms`、`--ctl`、`--state`、`--state-flux`（11-09，[N-09「state 與 state_flux」](../../docs/NORMS/05-基礎設施-窗/02-N-09～N-11.md)：回音窗 `state_flux.json` 的位置，鏡射設定 key `state_flux`）與不帶值的 `--enable-logs`、`--enable-counters`（旗標 ＞ 設定檔 ＞ 預設）；問腦總機（`py/tools/aos/kernel_llm`，不在 cpp）也只有 `--enable-counters`；aos-fsm 沒有旗標。**`--enable-counters` 是全家同名的開關**（11-09，[N-09「計數器」](../../docs/NORMS/05-基礎設施-窗/02-N-09～N-11.md)）：只因時間或每跑一次就變、又沒別的程式讀的計數器，一個一個 `.txt`（例 `counter_runs.txt`）放在這個旗標後面，**預設不寫**；新程式有這類計數器就用同一個名字，走 `parse_cli`／`aos_flags`，不各自取名。
> 下面是較早那代（aos-directive 的 bin；aos-schema 11-06 封存）的規矩。

- **設定只從 stdin 讀一份 JSON**（`aos::read_stdin`）：空的＝`{}`、多份＝`InputBad`、解不出來＝`InputBad`、壞掉的尾巴丟掉。
  沒有 TARGET、沒有 `-`：任何位置參數＝`ArgumentsBad`。
- **旗標**：較早那代的 `aos::parse_flags`（旗標＝key 原名）沒人叫，11-04 已刪；現行旗標一律走 `aos/util/cli.hpp` 的 `parse_cli`。
- **指示詞**（aos-directive）：stdin 與每個旗標值裡的 `{"$ref": 檔}`、`{"$env": 變數}` 先解開再驗欄位。語意見 [N-45](../../docs/NORMS/06-基礎設施-命令列與指示詞.md)。
- **結果 stdout 一行 JSON、退出 0**（`aos::emit`，排版同 Python `json.dumps`，key 照原順序）；**出錯 stderr 一行、退出 1**。
  子程式回非 0 不算錯（那是結果）。

### 目錄（照 dcap，三處偏離）

```
<專案>/
  include/aos/...   公開標頭（有要給別人用的才有；install.py 抄進 proto8/include/）
  src/              除 main.cpp 全進函式庫；一個元素一個資料夾
  tests/            測試（到 proto8/bin/ 找執行檔）
```

專案夾裡沒有建置檔：11-17 起全家由 `cpp/` 頂層一份 [`Makefile`](../Makefile) 編（不用 CMake、vcpkg），產物全在 `cpp/build/`（不進 git），執行檔由 install.py 裝到 `proto8/bin/`。

跟 dcap 不同的三點（使用者拍板）：函式庫 **STATIC**（不是 SHARED）、執行檔 **`-static-pie` 全靜態**（啟動不必動態載入 libstdc++；代價是執行檔較大、glibc 有安全更新要重建）、**兄弟專案一起編**（頂層 Makefile 一次編全家，建 aos-fsm 會連帶編它要的 aos-loop、aos-exec 等庫）。

### 建置

11-17 起不用 CMake、vcpkg（使用者裁定外部依賴 D-1「單檔收進 repo」、D-2「換頂層 Makefile」）。

**一次建全家（平常用這個）**：在 proto8 跑

```sh
python3 install.py
```

只用標準庫、Python ≥ 3.11。先查相依（必需 g++ ≥ 10、gcc、make、ar；選配工具只列表、不擋），再叫 `make -C cpp` 編全家（11 個庫、9 支執行檔），清空再填 `proto8/bin/`（9 支執行檔）與 `proto8/include/`（公開標頭，從 `cpp/aos-*/include` 抄）。中間檔與 `.a`／`.so` 在 `cpp/build/`，log 在 `cpp/build/build.log`；`bin/`、`include/`、`cpp/build/` 都不進 git。`--check` 只查相依。重跑＝跟全新安裝一樣，C++ 沒改時幾秒。

**開發時只重編一支**：

```sh
make -C proto8/cpp -j8 BINDIR=$AOS_HOME/bin aos-exec
```

目標名就是執行檔名，會連帶重編它要的庫；不給 `BINDIR` 時執行檔在 `cpp/build/bin/`。也可以直接重跑 install.py。

- 頂層 [`Makefile`](../Makefile)：每個專案 `aos-X` 的 `src/**/*.cpp`（除 `src/main.cpp`）編成 `libaos-X.a`，`src/main.cpp` 加庫連成 `aos-X`；aos-inst 是 C，出 `libaos-inst.a` 與 `libaos-inst.so`（預設 hidden，只匯出 `AOS_API` 的符號）。
- nlohmann json 是收進 repo 的單檔 [`third_party/nlohmann/json.hpp`](../third_party/nlohmann/json.hpp)（官方 v3.12.0，附 `LICENSE.MIT`），用 `-isystem third_party` 找到；不用 vcpkg、不用 find_package。
- C++ 標準全家一個：C++20（`-std=c++20`）；aos-inst 是 C11。執行檔預設 `-static-pie`、`-O3 -DNDEBUG`。
- 依賴：Makefile 裡每個專案一行 `DEPS_<短名>`（連結順序：庫排在它用的庫前面）；`LIBS`、`BINS` 兩張表列全家。依賴順序：aos-inst → aos-util → aos-directive → aos-exec → aos-loop → aos-fsm、aos-daemon → aos-llm；aos-json 連 aos-util、aos-directive；aos-lock 只連 aos-util、aos-post 連 aos-lock、aos-daemon 連 aos-post（信箱模式）。
- Sanitizer：`make -C proto8/cpp STATIC= CXXFLAGS="-O1 -g -fsanitize=address"`（sanitizer 不能全靜態，`STATIC=` 拿掉 `-static-pie`）。**改 CXXFLAGS 要先 `make clean`**：旗標變了 Makefile 不會自己重編，建完正常版也一樣要先 clean。
- clangd 看 install.py 產的 `cpp/compile_commands.json`。
- 測試到 `proto8/bin/` 找執行檔，跑測試前要先 `python3 install.py`。

## 新專案照這張清單

1. 資料夾 `aos-<短名>`（`src/`，要給別人用的標頭放 `include/aos/`）；在頂層 [`Makefile`](../Makefile) 加一行 `DEPS_<短名>`、把短名加進 `LIBS`（有執行檔的也加進 `BINS`）。不用寫各專案的建置檔。
2. namespace `aos::<短名>`；`src/common/common.hpp` 放 `using aos::Error; using aos::Json;` 與自己的 `code`（`using namespace aos::code;` ＋獨有的）。
3. 先用一句話說清楚這支程式是什麼，從那句話裡的元素拆 `src/<元素>/`，每個元素一個同名 `.hpp` 列「幾塊 → 哪個檔」；跨元素共用的進 `common/`；
   全家都要的進 aos-util。`main.cpp` 只串。
4. 命令列：`aos::parse_cli` ＋ `aos::read_stdin` ＋ `aos::resolve` ＋ 欄位表；結果 `aos::emit`、錯誤 `aos::fail(程式名, e)`（錯誤行 `程式: error: 代號 原因`）、提醒 `aos::warn`；`parse_cli` 最後一個參數給英文 `--help` 說明。
5. README 照上面的章節順序；只講自己，共通的連回這一頁，規範的語意連回 [NORMS](../../docs/NORMS.md)。
6. 每個檔開頭一段白話（哪個元素的哪一塊）；寫法照「寫法（不要太難）」。
