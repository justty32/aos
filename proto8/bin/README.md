## 逐支說明

- `aos-exec [--ws WS] XXX [args...]`（Python）：在工作區執行 XXX 這個程式。
  - **命令列**（10-21）：XXX 前面是 aos-exec 自己的旗標，第一個不是旗標的參數（不以 `-` 開頭，或就是 `-`）就是 XXX，之後全部原樣當 args（XXX 之後不再解析旗標）；`--` 結束旗標（XXX 可以 `-` 開頭：`aos-exec -- -p`）。旗標都帶一個值，`--x V` 或 `--x=V`，重複給＝最後一個算；旗標蓋過對應的環境變數。不認得的旗標、旗標缺值、沒有 XXX＝退 1、stderr 一行 `aos-exec: usage: aos-exec [--ws WS] XXX [args...]（原因）`。
  - **`--ws WS`**（目前唯一的旗標）沒給／`-`／空＝沿用現有 `AOS_WS`，沒設才用 `.`（呼叫當下的 cwd）；給路徑就用那個；轉絕對路徑設成 `AOS_WS`。`AOS_STACK` 沒設就用 `$AOS_WS/.aos/`，有設就沿用（相對路徑照呼叫當下的 cwd），都建好、轉絕對、結尾 `/`。
  - **找入口**（N-61、N-62）：XXX 先在第一個 `#` 切開（後面一定要 `/`，JSON pointer、`~1`＝`/`、`~0`＝`~`）。資料夾 → `XXX/$AOS_ENTRY`，沒有再找 `XXX/$AOS_ENTRY.json`（`$AOS_ENTRY` 是資料夾＝找不到、不往下補）；檔 → 就用它；不在、basename 沒有 `.` → 補找 `XXX.json`。解開捷徑得到實際的檔。
  - **種類**：有 `+x` ＝可執行檔，`exec` 它、內容不讀（沒 `#!`、exec 得到 ENOEXEC 時同 glibc `execvp` 改用 `/bin/sh 那個檔 args...` 跑；使用者 [ideas § 22](../thinking/2026-10-19-ideas.md)「乙」）；沒 `+x` 當 JSON 讀（第一行 `#!` 跳過，有 `#/` 就照指標取值）：非空陣列＝argv（元素可放 `$env`／`$ref`，開跑前解、`$ref` 從 `AOS_CD` 算，解完不是全字串或解不開＝`入口壞`；10-20），`exec`（`argv[0]` 帶 `/` 又不是 `+x` 的一般檔或帶 `#/`＝前面插 `aos-exec`，10-20；`argv[0]` 沒 `/` 時自己照 PATH 一段段 `execv`、找不到或沒 `+x` 換下一段；檔 `+x` 沒 `#!` 同樣改用 `/bin/sh` 跑，跟 `execvp` 一樣，§ 22）；有 `argv` 的物件＝inst 單子，行程內 `aos_inst.run()`、以子程式的碼結束（被訊號停掉＝128＋N）；沒 `argv` 的物件＝取 `[$AOS_ENTRY]` 再判一次（只往下一層）；字串＝路徑轉向，等同 `aos-exec 那個路徑`、相對路徑從寫著它的檔所在的資料夾算，走回走過的位置（檔＋指標）＝入口壞、訊息列出 `a → b → a`。
  - **開跑前**：export `AOS_WS`、`AOS_STACK`、`AOS_CF`（實際的檔）、`AOS_CD`（它所在的資料夾）；**PATH 不動、原樣傳下去**（ideas § 24，使用者「也套用，都不動path吧」；入口裡要叫 `aos-exec`、`aos-loop`、`aos-fsm`，由呼叫者事先把 `bin/` 放進 PATH；沒設 PATH 時照 `/bin:/usr/bin` 找 argv[0]，但不 export）；**cd 到 `AOS_CD`**；SIGPIPE 還原成預設再 exec（Python 預設忽略、會被入口繼承）。args 接在入口後面（單子／陣列：接在 `argv` 尾），stdin 不讀、原樣給入口。
  - **自己的錯**退 1、stderr 一行 `aos-exec: 原因`，原因開頭固定：`工作區不存在`、`入口不存在`（資料夾／檔／補 `.json` 都沒有、`#/` 指不到）、`入口壞`（沒 `+x` 又不是 JSON、種類不對、`#` 後不是 `/`、資料夾或可執行檔帶 `#/`、轉向繞圈、argv 陣列的指示詞解不開或解完不是字串）、`起不來`（exec 失敗）、`單子跑不起來`（aos_inst 的錯：欄位型別、`$env` 沒設、程式找不到、cwd 不在、串流開不了）、`建不了 AOS_STACK`、`usage: …`。
- `aos-inst FILE [args...]`（`aos_inst.py`，純標準庫）：讀一張單子，第一行是 `#!` 就丟掉，其餘當 JSON，跑一次。所以 `_exec` 第一行寫 `#!/usr/bin/env aos-inst`、下面接 JSON、`chmod +x` 就是入口（P-28 (A)）。認得的 key：`argv`（必填，args 接在後面）、`cwd`、`envs`、`stdin`、`stdout`、`stderr`、`stdout_append`、`stderr_append`、`timeout_ms`、`grace_ms`（沒寫 2000；逾時先 SIGTERM、過 grace 再 SIGKILL）；其他 key 忽略。子程式自成一個行程群組，逾時與轉來的訊號打整個群組（killpg），孫程式一起收掉（P-36）。單子裡任何位置的 `{"$env": 名, "path": 子路徑}` 換成該環境變數底下的路徑（P-31）；`{"$ref": "檔"}` 換成那份 JSON 檔的整份內容、`"檔#/指標"` 或 `"at": "/指標"` 取檔內位置（兩個都寫＝`at` 接在後面），換進來的值接著解；相對檔名從寫著它的檔所在的資料夾算（單子檔＝它解開捷徑後的資料夾；行程內給 dict 時＝`ref_base` 參數，沒給＝cwd；loop／fsm 傳設定檔的資料夾）；繞圈（同一個檔＋指標）、讀不到、指不到、`#` 後不是 `/`、`at` 不是空字串或 `/` 開頭、同物件不認得的 `$xxx`＝單子的錯（N-45，10-20）。`argv[0]` 帶 `/` 又不是 `+x` 的一般檔（資料夾、沒 `+x`、不在）或帶 `#/` → 改跑 `aos-exec argv...`（`aos-exec` 照子程式的 PATH 找，找不到＝`找不到要跑的程式 aos-exec`；N-61，10-20）。`argv[0]` 是 `+x` 但沒 `#!` 的檔（ENOEXEC）時照 execvp 的做法改用 `/bin/sh 那個檔 args...` 再起一次（使用者 § 21「不擋」，跟 impls 經 glibc `execvp` 一樣；§ 22 起 aos-exec 的可執行檔與 argv 陣列入口也一樣）。沒寫的串流接呼叫者的；命令列結束碼＝子程式的碼（不另吐結果 JSON），aos-inst 自己的錯退 1、stderr 一行 `aos-inst: 原因`。行程內用 `aos_inst.run(單子或檔)` 回 `{"code","signal","timed_out","pid","ms","received"}`（`received`＝跑的期間收到、轉給子程式的第一個訊號，沒有＝`null`；§ 24 加，給 loop／fsm 用）。（**impls 線沒有這支**：inst 是 C lib、不提供命令列，單子當入口時由 aos-exec 行程內跑、aos-exec 以子程式的碼結束；行程內的函數是 aos-exec 公開 API 的 `run_inst`。所以 `#!/usr/bin/env aos-inst` 與 `exec aos-inst _exec.json` 兩種寫法只在這版能用；同一個檔拿掉 `+x` 就是兩版 aos-exec 都認的 JSON 入口，P-40。使用者 10-19 晚，[ideas § 20](../thinking/2026-10-19-ideas.md)）**這版的 aos-exec 不叫 aos-inst 命令列**（行程內 import `aos_inst`）。
- `aos-loop loop.json`（Python）：`{"run": 子資料夾 或 一張單子, "max": 最多幾圈}`，每圈 `aos-exec <run>`（`run` 是物件＝單子，行程內 `aos_inst.run()`，取它的 `code`）；檔讀不到／不是 JSON／`run` 不對／單子壞 → 退 1、stderr 一行 `aos-loop: 原因`。子程式結束碼 0＝下一圈、**10＝要求停（loop 以 0 結束）**、其他非 0＝失敗（loop 以原碼結束）；跑滿 max 圈也以 0 結束、stderr 不寫（N-43 正常退出；有沒有跑滿看 `trace.jsonl` 行數）。**訊號**（§ 24，同 impls）：整支程式的壽命都接著 SIGINT／SIGTERM／SIGHUP——那拍跑到一半收到就轉給它（字串 run＝`os.kill` 給那個 `aos-exec` 子行程，同一個行程群組、不另設 SIGKILL 期限；單子＝`aos_inst.run()` 轉整群、過 `grace_ms` SIGKILL），等它結束、不起下一拍，以 128＋第一個收到的訊號結束、stderr 不寫；拍與拍之間收到就直接 128＋N。終端機 Ctrl-C：字串 run 那拍同群組，會收到兩次（直接一次、轉的一次）。**選填 key**（10-20，daemon 重寫時照 [rewrite-order ④](../thinking/2026-10-19-rewrite-order.md) 長出來；沒寫＝跟以前一樣）：`interval_ms`（一拍結束到下一拍開始至少隔幾毫秒，沒寫＝0）、`ctl`、`state`（窗的檔名，放在 `$AOS_STACK` 底下；寫了卻沒設 `AOS_STACK`＝退 1；沒寫＝不開、不提醒，N-09）。ctl 每圈讀一次，認 `paused`（不起下一拍、每秒再看）、`stop`（不起下一拍、以 0 結束）、`max`、`interval_ms`（蓋過 loop.json 的）、`seq`（state 回音 `ctl_seq`）；讀到壞的不採用、維持上一份好的、原因寫進 state 的 `last_warning`（N-08）；檔不在＝還沒人寫、不算問題。state 只在拍與拍之間寫（心跳只在兩拍之間跳，使用者 10-20「照預設」）：`{"kind": "state", "state": running／waiting／paused／done／stopped, "lap", "max", "interval_ms", "paused", "ctl_seq", "last_warning", "pid", "started", "boot_id", "beat"}`，結束時多 `code`（`done`＝自己跑完或失敗、`stopped`＝ctl 叫停或收到訊號）。骨架在 `aos_loop.py`。
- `aos-daemon DAEMON.json`（Python，10-20，`aos_loop.Loop` 的子類別）：管一群長壽的子 loop（C-36、N-28）。daemon.json＝loop.json 的超集：`run`、`max`、`interval_ms`、`ctl`、`state` 同 aos-loop，但 `run` 選填（純監工不寫）、`max` 沒寫＝不限、`interval_ms` 沒寫＝200；多兩個 key——`children`＝`{名字: loop 設定}`（字串＝子資料夾，包成 `{"run": 它}`；物件＝一份 loop.json 的內容，不驗、原樣交給子 loop，寫錯了子 loop 自己退 1）、`adopt`（布林，沒寫＝true）。要 `$AOS_STACK`（沒設＝退 1）。每個子項的小格是 `$AOS_STACK/<名字>/`（P-17）：daemon 把設定補上 `"ctl": "ctl.json"`、`"state": "state.json"`（沒寫才補）寫成小格裡的 `loop.json`，以 `AOS_STACK=小格` 起 `aos-loop 小格/loop.json`（cwd＝daemon 的 cwd、自成一個行程群組、stdin 接 /dev/null）；子 loop 的 stdout 丟掉、stderr 附加到小格的 `stderr`（N-28 方案 B）。每圈：讀 ctl（多認 `children`＝我要表上有誰，N-54；沒寫＝回 daemon.json 的）→ 表上多出來的收掉（SIGTERM、等 10 秒、再 SIGKILL 整群）並移除、看誰結束了（`phase` 改 `exited`、記 `code`／`signal`）、表上少掉的起來 → 跑 `run`（有寫才跑）→ 寫 state（多一欄 `children`：`{名字: {"pid", "started", "phase", "code", "signal"}}`）。**子 loop 結束後不自動重起**（使用者 10-20「照預設」）：停在表上 `exited`；要再起就從 ctl 的 `children` 拿掉再放回，或重起 daemon。**不論為什麼結束**（拍滿 `max`、ctl `stop`、`run` 退 10 或失敗、收到訊號、自己的錯）都先收掉所有子 loop、寫好 state 再結束；收到 SIGINT／SIGTERM／SIGHUP 以 128＋N 結束（非 0，P-36）。**接回**（`adopt`）：起來時讀自己上次的 state，`phase` 是 `running`、pid＋啟動時間對得上的子 loop 直接放回表上、不重起（N-17）；其他的照表重起。所以只有 daemon 被 SIGKILL、當掉時才有東西可接。自己的錯退 1、stderr 一行 `aos-daemon: 原因`。PATH 不動：子項要用的 `aos-loop`、`aos-exec` 由呼叫者放進 PATH。
- `aos_loop.py`（10-20，aos-loop、aos-daemon 共用）：`Loop`＝讀設定、每圈讀 ctl → `tend()` → stop／拍滿就結束 → paused 或還沒到時間就睡（最多 1 秒、每 50 毫秒看一次訊號）→ 跑一拍（`aos_beat.run`）；`finish()` 在結束前呼叫、`info()` 給 state 多的欄位；`cli(類別, argv)` 是兩支命令列共用的入口。
- `aos_window.py`（10-20）：ctl／state 窗。`Ctl(路徑, extra).read()`（extra＝這支程式多認的 key 與驗證）、`write(路徑, dict)`（先寫 `.` 開頭的暫存檔再改名，N-05）、`beat()`（`pid`、`started`＝/proc/<pid>/stat 第 22 欄、`boot_id`、`beat`＝epoch 秒；非 Linux 是 null，N-32）、`started(pid)`。
- `aos-fsm FSM.json`（Python，import `aos_inst`）：一拍只跑一格。`{"start": "idle", "states": {名: {"val": 子資料夾名或單子, "next": 下一個狀態}}}`；讀 `$AOS_STACK/state`（沒有＝start；純文字一行；寫的時候先寫 `.state` 再改名，N-05），`val` 字串＝`aos-exec` 它（相對路徑從 cwd 算）、物件＝行程內 `aos_inst.run()`；每拍在 `$AOS_STACK/trace.jsonl` 追加一行 `{"at","state","code","signal","timed_out","ms"}`（`at`＝這拍開始的 UTC 時間，P-38）；格的碼 0 才把 next 寫進 state，然後以格的碼退出（10 與其他非 0 原樣往上、state 不動）。只看結束碼、不讀格的 stdout、不轉述格的 stderr。沒設 `AOS_STACK`／表壞／查不到格／單子壞 → 退 1、stderr 一行 `aos-fsm: 原因`。**訊號**（§ 24，同 impls）：跑格期間收到就轉給那格（同 aos-loop），等格結束、**trace 與 state 照常寫完**（格收好自己退 0 就照樣換狀態），再以 128＋N 結束；跑格之前就收到＝不跑、直接 128＋N。
- `aos_beat.py`（§ 24，aos-loop、aos-fsm、aos-daemon 共用）：`block()` 接住三個訊號、`take()` 取拍外收到的、`run(字串或單子)` 跑一拍回 `{"code","signal","timed_out","ms","received"}`（字串＝子行程 `aos-exec <它>`、轉訊號給它；單子＝`aos_inst.run()`）。對齊 impls aos-loop 的 `block_signals`／`take_signal`／`run_beat`。

執行中狀態（`state`、`trace.jsonl`、`plan`、`current`）在 `$AOS_STACK`（預設 `$AOS_WS/.aos/`）；工作區只放交辦的東西與成果（`inbox/`、`out/`、`done/`）；定義資料夾不被寫，所以同一個 agent 可同時被兩個工作區跑。結果＝工作區內容；沒有別的結果通道。
