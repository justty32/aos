**2026-10-19 從 proto8-2 併進來。** 資料夾＝程式；入口＝資料夾裡 `$AOS_ENTRY`（預設 `_exec`；10-19 晚改，原 `.aos/exec`）指的檔。純標準庫 Python，在 WSL／Linux 跑。**aos 只訂環境變數**（`AOS_ENTRY`、`AOS_WS`、`AOS_STACK`、`AOS_CF`、`AOS_CD`、`AOS_CO`），入口拿到之後「這次要做啥」怎麼收、怎麼用是入口自己的事（使用者 10-19，[ideas § 4](../thinking/2026-10-19-ideas.md)）；aos-exec 只是把多的 args／stdin 原樣交給它。

> **10-19 晚照下班前的新規則改完**（使用者 § 21「舊版一起改」；[ideas § 14～§ 20](../thinking/2026-10-19-ideas.md)；條文 [N-57～N-62](../NORMS/10-基礎設施-定義與工作區.md)、C-73、P-40）：`aos-exec` 從 sh 改寫成 Python，行為對齊 `proto8/impls/aos-exec`（C++ 參考實作）——入口四種、`aos-exec XXX`（XXX 可為資料夾、檔、`檔#/指標`、補找 `XXX.json`）、五個環境變數、字串轉向與繞圈偵測、cd 到入口檔所在的資料夾。跟 impls 版不同的只有：錯誤一行沒有代號（N-60 兩種都合）；inst 單子在行程內交給 `aos_inst.run()`（Python），不是 C lib。`aos-inst` 命令列留著（`#!/usr/bin/env aos-inst` 與小殼 `exec aos-inst _exec.json` 兩種寫法只在這版能用），但 aos-exec 不再依賴它。

## 逐支說明

- `aos-exec [--ws WS] XXX [args...]`（Python）：在工作區執行 XXX 這個程式。
  - **命令列**（10-21）：XXX 前面是 aos-exec 自己的旗標，第一個不是旗標的參數（不以 `-` 開頭，或就是 `-`）就是 XXX，之後全部原樣當 args（XXX 之後不再解析旗標）；`--` 結束旗標（XXX 可以 `-` 開頭：`aos-exec -- -p`）。旗標都帶一個值，`--x V` 或 `--x=V`，重複給＝最後一個算；旗標蓋過對應的環境變數。不認得的旗標、旗標缺值、沒有 XXX＝退 1、stderr 一行 `aos-exec: usage: aos-exec [--ws WS] XXX [args...]（原因）`。
  - **`--ws WS`**（目前唯一的旗標）沒給／`-`／空＝沿用現有 `AOS_WS`，沒設才用 `.`（呼叫當下的 cwd）；給路徑就用那個；轉絕對路徑設成 `AOS_WS`。`AOS_STACK` 沒設就用 `$AOS_WS/.aos/`，有設就沿用（相對路徑照呼叫當下的 cwd），都建好、轉絕對、結尾 `/`。只有這裡算出來的會建、會轉絕對：之後 `.env` 設的 `AOS_*` 照字面用——`AOS_WS` 不存在或相對也照傳、`AOS_STACK` 不建、不轉絕對（使用者「全都可以，不限制，風險自己擔」）。
  - **找入口**（N-61、N-62）：XXX 先在第一個 `#` 切開（後面一定要 `/`，JSON pointer、`~1`＝`/`、`~0`＝`~`）。資料夾 → `XXX/$AOS_ENTRY`，沒有再找 `XXX/$AOS_ENTRY.json`（`$AOS_ENTRY` 是資料夾＝走進去、一路往下，見下面 `.env` 那點；同名的資料夾與 `.json` 都在時資料夾贏）；檔 → 就用它；不在、basename 沒有 `.` → 補找 `XXX.json`。解開捷徑得到實際的檔。
