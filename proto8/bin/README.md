## 逐支說明

> **分層（[C-74](../docs/CONCEPTS/01-設計理念.md#分層10-22-使用者定)）**：`aos-tick` 擱置中、不歸層。（基礎層、標準庫那幾支只有 C++ 版，見 [impls](../impls/README.md)。）

- **`aos-tools - 一個 agent 資料夾一份工具註冊檔（tools.json），登記這隻 agent 能叫哪些工具`**（決定與代定 [thinking 10-28 aos-tools](../thinking/2026-10-28-aos-tools.md)）
  用法 `aos-tools [--file F] add [--override] [--name N] [--no-cache] XXX｜rm XXX｜ls [--json]｜get XXX｜call 名`，註冊檔＝`--file`＞`./tools.json`（沒有＝沒登記任何工具）。
  **三種登記對象**（種類照 aos-exec 的認法，N-61）：資料夾（裡面 `_tooldef`，沒有再找 `_tooldef.json`）、沒 `+x` 的 JSON 檔（頂層 `_tooldef` key）、有 `+x` 的 python／可執行檔（`XXX --tooldef` 在 stdout 吐定義，結果依檔的 mtime＋大小快取在註冊檔；`add --no-cache` 那一項記 `"cache": false`、不存快取，之後 ls／get 每次重跑 `--tooldef`，手寫或 `aos-json set …#/tools/名/cache false` 也行；`--override` 沒帶 `--no-cache`＝回到有快取；dir／json 給 `--no-cache`＝`ArgumentsBad`、手寫 `false`＝`RegistryBad`，[thinking § 11-03](../thinking/2026-10-28-aos-tools/04-11-03-no-cache.md)）；不符合就報錯。工具定義＝OpenAI function 物件去掉 `name`。工具名＝`--name`＞檔名去副檔名（資料夾名），只收 `[A-Za-z0-9_-]`；撞名 `ToolExists`，`--override` 蓋掉。
  **存法**：`{"tools": {名: {"path": 絕對路徑, "cache"?: {...}｜false}}}`；add 的相對路徑從 cwd 算、一律存絕對；手寫的相對路徑從註冊檔的資料夾算（範本用這個，搬家不斷）。有 `$ref`／`$env` 就交給 aos-json 解與改（`$ref` 陣列＝拆成好幾份，add 寫進最後一份）。
  **叫**：`call 名`——資料夾、JSON＝`aos-exec 路徑`，arguments 原樣從 stdin 進（P-41）；可執行檔＝arguments 寫成 `$AOS_STACK/tool_call.json`（沒設＝暫存檔、用完刪），`aos-exec 檔 --tool-call 那個檔`。結束碼是工具的。
  **錯**：stderr 一行 `aos-tools: 代號 原因`、退 1（`ArgumentsBad`、`FlagUnknown`、`CommandUnknown`、`RegistryBad`、`PathMissing`、`ToolDefMissing`、`ToolDefBad`、`NameBad`、`ToolExists`、`ToolMissing`、`DirectiveBad`、`CommandMissing`、`WriteFailed`）；ls／get 碰到登記了但壞掉的工具也報錯。要 PATH 上有 aos-exec、aos-json。測試 `proto8/tests/test_aos_tools.py`。

- **`aos-round` 不在了**（使用者「aos round這東西還沒刪掉嗎」「刪掉」）：agent 的 `loop.json` 直接叫 aos-fsm；它跑的 `lib/agent/round/` 那套格 11-03 也刪了（概念在 proto8/archive/agent-round-concepts/）。

- **`aos-eca-turn - 外部 coding agent（claude／codex）的一輪：從 stack 的 queue 認領一批、交給 CLI 就收信、回答接進 history`**（使用者「aos eca turn」、C-54 R13 `aos-<領域>-<功能>`；設計 [thinking 10-30 eca](../thinking/2026-10-30-eca.md)）
  用法 `aos-eca-turn [--one] [--on-empty stop|idle] [--on-busy yield|answer] [--prompt FILE] <定義資料夾絕對路徑>`（旗標在位置參數前）。定義＝`demo/eca-claude` 那種（頂層 `cli.json`、選填 `tools.json`〔aos-tools 登記檔，`cli.json` 的 `tools` 可改指；cli_session 接上 aos-mcp，`--ws $AOS_WS --stack $AOS_STACK`〕），定義不被寫、寫的都在 `$AOS_STACK`。一次答一批（使用者 11-03「每次aos-eca-turn就是把所有信一起丟進去(當然，是有順序的)」「一批幾封無上限」）：`queue/cur/` 與 `new/` 的信全部、照處理順序（`new/` 用 `aos-post take-all`，沒有上限；跑的期間才來的留給下一輪；順序照 `lib/aos/aos_ws.py` 的 `letter_key`：有序在前照名字、無序在後照名字，11-03 aos-post 改版起名字不是有序的也照樣答）→ 各封 content 用一個空行接成一段，經 `lib/agent/cli_session.py` 的 `ask` 交給 CLI（畫面開著貼字、沒開 `--resume`）→ **交出去那一刻**每封一則 user 接進 `history.jsonl`、收信（使用者「對於eca來說，他收到信後，丟給claude之類的，然後這封信就算是完成了」，[eca 20](../thinking/2026-10-30-eca/20-11-03-交出去就收.md)）→ 答完 assistant 接進 history；CLI 中途掛掉＝邊緣狀況，那批不自動重答（要重答再 say），沒有 `current.txt`；讀信 `aos-post see`、收信 `aos-post done`；壞信丟掉、記進 `$AOS_STACK/mailbox_warning.txt`；`$AOS_STACK/eca.json` 記 kind、ws、template。
  **`--on-empty`**：queue 空時 `stop`（沒給；退 10＝loop 收工）｜`idle`（退 0＝loop 隔 `interval_ms` 再來）；壞值、跟 `--one` 一起給＝`ArgumentsBad`；不讀環境變數。**`--on-busy`**：`yield`（沒給）＝lock 拿不到、有人接在 tmux 畫面上、`busy.txt` 在＝還沒交出去：這輪退 0、信留 `cur/`、history 不動（`--one` 照錯退 1）｜`answer`＝照常答不退讓（lock 等、有人接著照樣貼、`busy.txt` 等它消失，共用 `timeout_ms` 期限，逾時 `ReplyMissing`）。`--one`＝工具形（stdin `{"prompt"}` → stdout，同 `lib/agent/claude` 的 `call_main`）。**`--prompt FILE`**＝開場白檔（history 與 queue 都空時當第一則 user 投進 queue）：相對路徑從定義資料夾算；給了但不是檔＝`PromptMissing`、空字串或跟 `--one` 一起給＝`ArgumentsBad`；**沒給＝沒有開場白**（不找 `prompt.txt`；`cli.json` 寫了 `prompt` 不看）。使用者 11-04「不該在json中指定檔案名稱，應該改成用旗標指定」，[eca 21 § 翻案](../thinking/2026-10-30-eca/21-11-04-開場白檔可指定.md#11-04-翻案開場白改成-aos-eca-turn-的旗標)。定義的 `loop.json` 這樣叫：`{"exec": {"argv": ["aos-eca-turn", "--on-empty", "idle", "--on-busy", "yield", {"$env": "AOS_CD"}], "timeout_ms": 900000}}`。
  **錯**：stderr 一行 `aos-eca-turn: 代號 原因`、退 1（`ArgumentsBad`、`FlagUnknown`、`AgentBad`、`StackMissing`、`PromptMissing`〔`--prompt` 給的開場白檔不在〕、`HistoryBad`、`PostFailed`、`WriteFailed`，加 cli_session 的 `CfgMissing`、`CfgBad`、`ToolsMissing`、`CliMissing`〔含 aos-mcp 不在 PATH〕、`CliFailed`、`ReplyMissing`）。要 PATH 上有 aos-post（接了工具還要 aos-mcp、aos-tools）。測試 `proto8/tests/test_eca_turn.py`（範本 `test_eca.py`）。

- **`aos-tick - 把時鐘檔的回合數往前走一格`**（NAME，C-54 R1）
  用法 `aos-tick [旗標] FILE`（Python）：時鐘往前走一格（C-44：只是時鐘，不包任務、不保證什麼）。FILE 裡是回合數（十進位＋換行），讀出 n、寫回 n＋1 就退 0；FILE 不在＝0（第一次寫 1）；寫進 n＋1＝第 n 回合結束、第 n＋1 回合開始，mtime＝這回合從什麼時候開始。先寫同資料夾的 `.名字` 再改名蓋過去（N-05），不 fsync，stdout 不吐東西。**命令列**：唯一的位置參數就是 FILE（必給、只能一個、相對路徑從 cwd 算）；FILE 照字面用，`#` 不切指標（它是時鐘檔不是設定檔）；目前沒有旗標（旗標表是空的、走 `aos_flags`，`--` 結束旗標）。**自己的錯**退 1、stderr 一行 `aos-tick: 代號 原因`、FILE 不動：`ArgumentsBad usage: aos-tick [旗標] FILE（原因）`（跟 aos-loop、aos-fsm 同一個寫法）（沒給、多給；不認得的旗標是 `FlagUnknown usage: …`）、`ClockBad 時鐘檔讀不到：`（例：它是資料夾）、`ClockBad 時鐘檔壞：`（內容不是 `[0-9]+` 加可有可無的一個 `\n`；空檔、`\r\n`、空白、負號、全形數字都算壞）、`WriteFailed 時鐘檔寫不了：`（資料夾不在或沒寫入權限；不替人建資料夾，暫存檔會清掉）。節奏、停、只走 N 回合交給 loop（`max`、`interval_ms`、ctl 的 `pause`）；同一個 FILE 兩個人同時 tick 不管。

- `aos_flags.py`：命令列旗標解析 `parse(argv, 旗標表)` 回 `(opts, [XXX, args...])`（`--x V`／`--x=V`、重複給最後一個算、`--` 結束旗標、第一個不是旗標的參數起原樣；不認得＝`FlagUnknown`、缺值＝`ArgumentsBad`）。aos-tick、aos-tools、aos-eca-turn 用。

執行中狀態（`state.txt`、`plan.txt`、`current.txt`）在 `$AOS_STACK`（預設 `$AOS_WS/.stack/`）；工作區只放交辦的東西與成果（題目 `new/` → 認領 `cur/` → `done/`，答案 `out/`）；定義資料夾不被寫，所以同一個 agent 可同時被兩個工作區跑。結果＝工作區內容；沒有別的結果通道。

## aos-daemon-ctl

**`aos-daemon-ctl - 把 proc 掛到一個 aos-daemon 上、起停、暫停（往它的信箱投 procs_added／procs_removed／procs_stopped／procs_started）`**（使用者「我們現在跑aos-exec XXX，等同於把這個proc掛到linux這個原生proc管理器上。假如我們想要掛在daemon上呢？或許是aos-daemon-ctl add XXX這樣，然後會自動識別XXX是否為loop，不是的話就max:1這樣？」；[thinking 10-30 agent-lifecycle](../thinking/2026-10-30-agent-lifecycle.md)、[thinking 11-03 procs](../thinking/2026-11-03-procs.md)；例子 demo/daemon-3 11-04 隨 demo 刪了）

用法 `aos-daemon-ctl [--daemon-stack D] add [--name N] [--ws WS] [--stack S] XXX [-- 參數...]｜rm 名字｜stop 名字｜start 名字｜pause 名字｜resume 名字｜ls [--json]｜where --stack 名字`。名詞照 [procs § 0](../thinking/2026-11-03-procs.md#0-名詞表代定)：add／rm＝插拔、start／stop＝起停（stack 留著）、pause／resume＝暫停。表上的 `phase` 只有 `running`、`stopping`、`stopped`、`sleeping`（daemon 收工時還在跑的 loop 型、再開自動 wake，見 [aos-daemon](../impls/aos-daemon/README.md)；sleep／wake 不開放成子命令）；暫停中是子 loop 自己 state.json 的事，表上不轉述。沒有 `--kind`（給了＝`FlagUnknown`）；ls 只看得到還在跑的（使用者「把--kind刪掉，XXX後面可以接-- ... 也就是附加argv參數。改成子項結束後不留名單」）。

- **哪個 daemon**（N-63 hub 型變數）：`--daemon-stack` ＞ `$AOS_DAEMON_STACK`（使用者「就AOS_DAEMON_STACK吧」「最好明講，也就是--daemon-stack」；給 `--daemon`＝`FlagUnknown`，只設舊名 `$AOS_DAEMON`＝`DaemonMissing`、訊息提示改設新名），值＝那個 daemon 的 `$AOS_STACK`（它的窗用預設名字：信箱 `procs_ctl_mailbox/`、`procs_state.json`）；都沒有或不是資料夾＝`DaemonMissing`；子 proc 照常繼承。`AOS_DAEMON_STACK` 要給絕對路徑，相對路徑 cd 之後就對不上（從別的資料夾叫＝`DaemonMissing`；使用者「3」：維持、只寫清楚）。掛在 daemon 底下的子項不用自己設：daemon 起它時就把 `AOS_DAEMON_STACK` 設成自己的 stack（[aos-daemon「子項的 AOS_DAEMON_STACK」](../impls/aos-daemon/README.md#子項的-aos_daemon_stack11-02thinking-11-02-resident-bob-衝突-2)），子項裡叫 aos-daemon-ctl 直接接到它的 daemon。
- **add／rm＝投信**（信箱模式，N-28、N-54）：daemon.json 要寫 `"procs_ctl_mailbox": "procs_ctl_mailbox"`（可以跟 `procs_ctl` 同時開），沒有 `new/`＝`MailboxMissing`；stdout 印 aos-post 的信件名稱；daemon 下一圈才套，結果看 ls（壞信在 procs_state 的 `mailbox_warning`）。rm＝`{"procs_removed": [名字]}`；先停再拿掉，stack 不清。
- **做完的同名再 add＝重新起**：信箱模式下子項做完（done）daemon 就從期望表拿掉，再投一封同名的 add 就再跑一次，不用先 rm。
- **自動識別**：XXX 是有 `loop.json` 的資料夾＝loop 子項，設定＝它的 loop.json（去掉 `_entry`；相對 exec 照 XXX 轉絕對；exec 是內嵌單子＝換成 `<XXX>/loop.json#/exec`，子 loop 每次 aos-exec 指回原檔那張單子，`AOS_CD`＝XXX、相對的 cwd／argv 照原地算——eca 定義的 `aos-eca-turn … {"$env": "AOS_CD"}` 靠這條掛得上 daemon）——子 loop 直接跑它的 loop，ctl／state 落在它的 stack；**一定帶 `ctl`／`state`**（沒寫補 `"ctl.json"`／`"state.json"`，寫了的照原樣；daemon 看寫法決定怎麼起，只有 `{"exec": …}` 的物件＝跑一次，補了才不會把只寫 exec 的 loop.json 當成跑一次）；其他＝exec 型（XXX 的絕對路徑，跑一次）。名字＝`--name` ＞ XXX 的資料夾名。XXX 的 `.env`、loop.json 裡的指示詞不處理。
- **`-- 參數...`**：`--` 之後全當附加 argv，原樣不轉路徑；exec 型＝`procs_added {名字: [XXX 絕對路徑, 參數...]}`（daemon 起它＝`aos-exec XXX 參數...`；沒參數是字串），有 `--ws`／`--stack`＝`{"exec": [XXX, 參數...], "ws"?: WS, "stack"?: S}`。**loop 型帶參數＝`ArgumentsBad`**（代定：要參數寫進 loop.json 的 `exec`）。XXX 後面接的不是 `--`＝`ArgumentsBad`（add 只收一個 XXX）。例：`aos-daemon-ctl add ../../agents/bob -- "在 env:AOS_WS 寫一首詩，詠桃花，檔名 peach.txt。"`。
- **`--ws WS`**（使用者「都照建議」）：這一隻的工作區。WS 從呼叫當下的 cwd 轉絕對（不是資料夾＝`PathMissing`、空＝`ArgumentsBad`），寫進子項物件的 `ws`（loop＝子項設定多一個 `ws`；exec＝`{"exec": XXX 或 [XXX, 參數...], "ws": WS}`），daemon 起它時設 `AOS_WS`（[aos-daemon「子項的工作區 ws」](../impls/aos-daemon/README.md)）。
- **`--stack S`**（使用者「那就記錄在名單上。我是希望盡量不要用捷徑啦。然後S裡面有別的東西的話，使用者要自己承擔風險。」）：這一隻的 stack，沒給＝daemon 的預設小格 `<D>/procs/<名字>/`。S 從呼叫當下的 cwd 轉絕對（同 `--ws`）、**不驗在不在**（daemon 起它時 `mkdir -p`）；空（`--stack ""`、`--stack=`）＝`ArgumentsBad`；寫進子項物件的 `stack`（loop 型多一個 key、exec 型寫成 `{"exec", "stack"}`）。
- **不碰 `<WS>/.stack`**（使用者「那其實.stack根本不需要放到ws那邊」，[thinking 11-03 stack-where](../thinking/2026-11-03-stack-where.md)）：add／rm 不建也不拆指到小格的 symlink；子項的 stack 歸 daemon 管，`AOS_WS` 只是一個位址。工作區原本有什麼都不動、不說話。要對它說話：`aos-say --stack $(aos-daemon-ctl where --stack 名字) 你好 && aos-listen --stack $(aos-daemon-ctl where --stack 名字)`。
- **stop／start**：`stop 名字`＝`{"procs_stopped": [名字]}`（loop 型跑完這次自己退 0、列留成 `stopped`、stack 留著、where 照找得到）；`start 名字`＝`{"procs_started": [名字]}`（stopped 的用列上的 stack 再起；起來是跑還是暫停看它自己的 state.json）；stdout 印信件名稱。
- **pause／resume**（[ctl-commands § 5](../thinking/2026-11-03-ctl-commands.md)）：不經 daemon，直接往它的 ctl（stack 裡 daemon 寫的 `loop.json` 的 `ctl` 那格，慣用 `ctl.json`）寫一道 `{"cmd": "pause"|"resume", "seq": N}`（先寫 `.ctl.json` 暫存再改名，N-05；N＝ctl 裡現有的 `seq`＋1，沒有＝1，內容一定跟上一道不同），stdout 印 N（它 state.json 的 `ctl_seq` 追上 N＝看到了）。誰都不清 ctl。要看暫停了沒：看它 stack 裡的 `state.json`（`cat $(aos-daemon-ctl where --stack 名字)/state.json`，`phase` 是 `paused`）。
- **exec 型只有跑和拔**（使用者「exec就是只有執行中和拔掉」）：stop、pause、resume 先看它的 stack 裡有沒有 daemon 寫的 `loop.json`，沒有＝`CtlMissing`「X 沒有 ctl（exec 型只有跑和拔）」、退 1、不送信不寫檔；`loop.json` 的 `ctl` 是 null＝也是 `CtlMissing`。start 的那列已是 `stopped`／`sleeping` 就不看（只有 loop 型會被停或睡；同一圈 add＋stop 的 stack 還沒建），其他照看。daemon 自己再驗一次。表上沒有＝`ProcMissing`。
- **where --stack 名字**：印這個子項的 stack＝procs_state 那一列的 `stack`（預設小格 `<D>/procs/<名字>`、或 add `--stack` 給的；絕對路徑一行、結尾不帶 `/`；拿 stack 只在 `cell_of` 一處）。**只認 daemon 表上的**（`running`、`stopping`、`stopped`、`sleeping` 都算；使用者「一個proc在daemon中的狀態，包括運行中、暫停中，除此之外就是不存在於daemon了」「拿下名單後，對於daemon來說他就不存在了，自然找不到」）：表上沒有＝`ProcMissing`、退 1，小格資料夾還在也一樣。`procs_state.json` 不在＝`StateMissing`；daemon 沒在跑＝同 ls 那句注意、照表印。只收 `--stack`（沒給、多給位置參數＝`ArgumentsBad`）。
- **ls**：讀 `procs_state.json` 的一張表 `procs`（切檔的 `$ref` 合回來），一行「名字 TAB phase TAB pid TAB code TAB ws」（pid、code、ws 沒有＝`-`，stopped、sleeping 的 pid 是 `-`）；`--json`＝一行 `{"procs": 表}`（列照 procs_state 原樣：`pid`、`started_at_ticks`、`phase`、`code`、`signal`、`stack`、有給 ws 的帶 `ws`）。**自己結束的不在表上**（表上是 `running`、收的途中 `stopping`、daemon 停掉的 `stopped`、收工時還在跑的 `sleeping`）：子項自己結束（`done`、訊號、別人直接寫它 ctl 的 stop）daemon 就拿掉，**結束碼看 daemon 的 log**（`aos-daemon --enable-logs` 時 stdout 每個子項起來一行、結束一行 JSON，`{"at","name","phase","pid","code","signal"(,"ws")}`），所以 code 那欄平常是 `-`。
- **ls 另判 daemon 活著**（使用者「要看一個proc是否還活著，除去linux底層proc機制外，我們的aos-daemon-ctl問詢也是一個方式，兩者並存」）：procs_state 頂層的 `pid`＋`started_at_ticks`（＋`boot_id`）對 /proc（N-17 的確定法），對不上＝stderr 一句「`aos-daemon-ctl: 注意 daemon 沒在跑（pid N）；表是它最後寫的`」，照樣列、退 0（`--json` 也一樣，輸出不加欄）。不看 `updated_at` 或檔案新不新（state 窗有變才寫、沒心跳）。
- **錯**：stderr 一行 `aos-daemon-ctl: 代號 原因`、退 1（`ArgumentsBad`、`FlagUnknown`、`CommandUnknown`、`DaemonMissing`、`MailboxMissing`、`PathMissing`、`LoopBad`、`StateMissing`、`StateBad`、`ProcMissing`、`CtlMissing`、`WriteFailed`（pause／resume 寫不了 ctl）、`CommandMissing`、`SendFailed`）。要 PATH 上有 aos-post。測試 `proto8/tests/test_aos_daemon_ctl.py`。

例：`aos-daemon-ctl add --stack /tmp/c --name c ../agents/clock`、`aos-daemon-ctl pause c`、`cat /tmp/c/state.json`、`aos-daemon-ctl resume c`、`aos-daemon-ctl stop c`（`ls` 見 `c TAB stopped TAB - TAB 0 TAB -`）、`aos-daemon-ctl start c`、`aos-daemon-ctl rm c`（`/tmp/c` 留著）。
