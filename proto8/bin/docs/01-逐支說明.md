## 逐支說明

> **分層（[C-74](../../docs/CONCEPTS/01-設計理念/02-C-51.md#分層10-22-使用者定)）**：`aos-tick` 擱置中、不歸層。（基礎層、標準庫那幾支只有 C++ 版，見 [impls](../../impls/README.md)。）

- **`aos-tools - 一個 agent 資料夾一份工具註冊檔（tools.json），登記這隻 agent 能叫哪些工具`**（決定與代定 [thinking 10-28 aos-tools](../../thinking/2026-10/28/aos-tools/README.md)）
  用法 `aos-tools [--file F] [--overlay O] add [--override] [--name N] [--no-cache] XXX｜rm XXX｜ls [--json]｜get XXX｜call NAME`，註冊檔＝`--file`＞`./tools.json`（沒有＝沒登記任何工具）。
  **`--overlay O`**（11-05 portable-flow 步 4）：F 疊一層覆蓋層 O 再用——O＝`{"add": {名: {"path": 相對 O 所在資料夾}}, "rm": [名]}`，疊法＝F 先拿掉 rm 的名字（F 沒有的忽略）、再放上 add 的（同名蓋過 F）；有 `--overlay` 時 add／rm 只寫 O、不碰 F。aos-agent `tools` 與 agent-fsm 的身體用它，說明在 [aos-agent docs/03「tools 覆蓋層」](../../extras/agent/docs/03-tools覆蓋層.md#tools-覆蓋層)。
  **三種登記對象**（種類照 aos-exec 的認法，N-61）：資料夾（裡面 `_tooldef.json`、有 `_metainfo.json` 一起給；11-04 起不帶副檔名的 `_tooldef`／`_metainfo` 不認）、沒 `+x` 的 JSON 檔（頂層 `_tooldef` key）、有 `+x` 的 python／可執行檔（`XXX --tooldef` 在 stdout 吐定義，結果依檔的 mtime＋大小快取在註冊檔；`add --no-cache` 那一項記 `"cache": false`、不存快取，之後 ls／get 每次重跑 `--tooldef`，手寫或 `aos-json set …#/tools/名/cache false` 也行；`--override` 沒帶 `--no-cache`＝回到有快取；dir／json 給 `--no-cache`＝`ArgumentsBad`、手寫 `false`＝`RegistryBad`，[thinking § 11-03](../../thinking/2026-10/28/aos-tools/04-11-03-no-cache.md)）；不符合就報錯。工具定義＝OpenAI function 物件去掉 `name`。工具名＝`--name`＞檔名去副檔名（資料夾名），只收 `[A-Za-z0-9_-]`；撞名 `ToolExists`，`--override` 蓋掉。
  **存法**：`{"tools": {名: {"path": 絕對路徑, "cache"?: {...}｜false}}}`；add 的相對路徑從 cwd 算、一律存絕對；手寫的相對路徑從註冊檔的資料夾算（範本用這個，搬家不斷）。有 `$ref`／`$env` 就交給 aos-json 解與改（`$ref` 陣列＝拆成好幾份，add 寫進最後一份）。
  **叫**：`call 名`——資料夾、JSON＝`aos-exec 路徑`，arguments 原樣從 stdin 進（P-41）；可執行檔＝arguments 寫成 `$AOS_STACK/tool_call.json`（沒設＝`StackMissing`，11-04 起不再用暫存檔），`aos-exec 檔 --tool-call 那個檔`。結束碼是工具的。
  **錯**：stderr 一行 `aos-tools: 代號 原因`、退 1（`ArgumentsBad`、`FlagUnknown`、`CommandUnknown`、`RegistryBad`、`PathMissing`、`ToolDefMissing`、`ToolDefBad`、`NameBad`、`ToolExists`、`ToolMissing`、`DirectiveBad`、`CommandMissing`、`WriteFailed`）；ls／get 碰到登記了但壞掉的工具也報錯。要 PATH 上有 aos-exec、aos-json。

- **`aos-round` 不在了**（使用者「aos round這東西還沒刪掉嗎」「刪掉」）：agent 的 `loop.json` 直接叫 aos-fsm；它跑的 `lib/agent/round/` 那套格 11-03 也刪了（概念在 proto8/archive/agent-round-concepts/）。

- **`aos-eca-turn - 外部 coding agent（claude／codex）的一輪：從 stack 的 queue 認領一批、交給 CLI 就收信、回答接進 history`**（使用者「aos eca turn」、C-54 R13 `aos-<領域>-<功能>`；設計 [thinking 10-30 eca](../../thinking/2026-10/30/eca/README.md)）
  用法 `aos-eca-turn [--one] [--on-empty stop|idle] [--on-busy yield|answer] [--prompt FILE] <absolute definition dir>`（旗標在位置參數前）。定義＝`demo/eca-claude` 那種（頂層 `cli.json`、選填 `tools.json`〔aos-tools 登記檔，`cli.json` 的 `tools` 可改指；cli_session 接上 aos-mcp，`--ws $AOS_WS --stack $AOS_STACK`〕），定義不被寫、寫的都在 `$AOS_STACK`。一次答一批（使用者 11-03「每次aos-eca-turn就是把所有信一起丟進去(當然，是有順序的)」「一批幾封無上限」）：`queue/cur/` 與 `new/` 的信全部、照處理順序（`new/` 用 `aos-post take-all`，沒有上限；跑的期間才來的留給下一輪；順序照 `lib/aos/aos_ws.py` 的 `letter_key`：有序在前照名字、無序在後照名字，11-03 aos-post 改版起名字不是有序的也照樣答）→ 各封 content 用一個空行接成一段，經 `lib/agent/cli_session.py` 的 `ask` 交給 CLI（畫面開著貼字、沒開 `--resume`）→ **交出去那一刻**每封一則 user 接進 `history.jsonl`、收信（使用者「對於eca來說，他收到信後，丟給claude之類的，然後這封信就算是完成了」，[eca 20](../../thinking/2026-10/30/eca/20-11-03-交出去就收.md)）→ 答完 assistant 接進 history；CLI 中途掛掉＝邊緣狀況，那批不自動重答（要重答再 say），沒有 `current.txt`；讀信 `aos-post see`、收信 `aos-post done`；壞信丟掉、記進 `$AOS_STACK/mailbox_warning.txt`；`$AOS_STACK/eca.json` 記 kind、ws、template。
  **`--on-empty`**：queue 空時 `stop`（沒給；退 10＝loop 收工）｜`idle`（退 0＝loop 隔 `interval_ms` 再來）；壞值、跟 `--one` 一起給＝`ArgumentsBad`；不讀環境變數。**`--on-busy`**：`yield`（沒給）＝lock 拿不到、有人接在 tmux 畫面上、`busy.txt` 在＝還沒交出去：這輪退 0、信留 `cur/`、history 不動（`--one` 照錯退 1）｜`answer`＝照常答不退讓（lock 等、有人接著照樣貼、`busy.txt` 等它消失，共用 `timeout_ms` 期限，逾時 `ReplyMissing`）。`--one`＝工具形（stdin `{"prompt"}` → stdout，同 `lib/agent/claude` 的 `call_main`）。**`--prompt FILE`**＝開場白檔（history 與 queue 都空時當第一則 user 投進 queue）：相對路徑從定義資料夾算；給了但不是檔＝`PromptMissing`、空字串或跟 `--one` 一起給＝`ArgumentsBad`；**沒給＝沒有開場白**（不找 `prompt.txt`；`cli.json` 寫了 `prompt` 不看）。使用者 11-04「不該在json中指定檔案名稱，應該改成用旗標指定」，[eca 21 § 翻案](../../thinking/2026-10/30/eca/21-11-04-開場白檔可指定.md#11-04-翻案開場白改成-aos-eca-turn-的旗標)。定義的 `loop.json` 這樣叫：`{"exec": {"argv": ["aos-eca-turn", "--on-empty", "idle", "--on-busy", "yield", {"$env": "AOS_CD"}], "timeout_ms": 900000}}`。
  **錯**：stderr 一行 `aos-eca-turn: 代號 原因`、退 1（`ArgumentsBad`、`FlagUnknown`、`AgentBad`、`StackMissing`、`PromptMissing`〔`--prompt` 給的開場白檔不在〕、`HistoryBad`、`PostFailed`、`WriteFailed`，加 cli_session 的 `CfgMissing`、`CfgBad`、`ToolsMissing`、`CliMissing`〔含 aos-mcp 不在 PATH〕、`CliFailed`、`ReplyMissing`）。要 PATH 上有 aos-post（接了工具還要 aos-mcp、aos-tools）。
