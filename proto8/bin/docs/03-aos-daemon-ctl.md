## aos-daemon-ctl

**`aos-daemon-ctl - 把 proc 掛到一個 aos-daemon 上、起停、暫停（往它的信箱投 procs_added／procs_removed／procs_stopped／procs_started／procs_slept／procs_woken）`**（使用者「我們現在跑aos-exec XXX，等同於把這個proc掛到linux這個原生proc管理器上。假如我們想要掛在daemon上呢？或許是aos-daemon-ctl add XXX這樣，然後會自動識別XXX是否為loop，不是的話就max:1這樣？」；[thinking 10-30 agent-lifecycle](../../thinking/2026-10/30/agent-lifecycle/README.md)、[thinking 11-03 procs](../../thinking/2026-11/03/procs/README.md)；例子 demo/daemon-3 11-04 隨 demo 刪了）

用法 `aos-daemon-ctl [--daemon D] add [--name N] [--ws WS] [--stack S] [--def DEF] XXX [-- 參數...]｜rm 名字｜stop 名字｜start 名字｜sleep 名字｜wake 名字｜pause 名字｜resume 名字｜ls [--json]｜where --stack 名字`（`-h`／`--help`＝印檔頭說明）。名詞照 [procs § 0](../../thinking/2026-11/03/procs/03-規劃-fable-照原則定的細節-可翻案.md#0-名詞表代定)：add／rm＝插拔、start／stop＝起停（stack 留著）、sleep／wake＝睡醒（stack 留著；11-05 開放）、pause／resume＝暫停。表上的 `phase` 只有 `running`、`stopping`、`stopped`、`sleeping`（daemon 收工時還在跑的 loop 型、或 `sleep 名字` 睡下的，再開自動 wake，見 [aos-daemon](../../impls/aos-daemon/README.md)）；暫停中是子 loop 自己 state.json 的事，表上不轉述。沒有 `--kind`（給了＝`FlagUnknown`）；ls 只看得到還在跑的（使用者「把--kind刪掉，XXX後面可以接-- ... 也就是附加argv參數。改成子項結束後不留名單」）。

- **哪個 daemon**（N-63 hub 型變數）：`--daemon` ＞ `$AOS_DAEMON` ＞ **呼叫當下 cwd 的 `./.stack`**（11-05 [portable-flow 題 3](../../thinking/2026-11/05/portable-flow/05-衝突與方向題.md)，使用者選「沒設找 `./.stack`」：在 ws 裡起的 daemon，stack 就是 `ws/.stack`，`cd ws` 之後不設變數也找得到；轉絕對、不往上層找、不是資料夾＝`DaemonMissing`）（使用者 11-04 晚「AOS_DAEMON_STACK實在太醜，還是直接簡化成AOS_DAEMON就好了」），值＝那個 daemon 的 `$AOS_STACK`（它的窗用預設名字：信箱 `procs_ctl_mailbox/`、`procs_state.json`）；都沒有或不是資料夾＝`DaemonMissing`；子 proc 照常繼承。`AOS_DAEMON` 要給絕對路徑，相對路徑 cd 之後就對不上（從別的資料夾叫＝`DaemonMissing`；使用者「3」：維持、只寫清楚）。掛在 daemon 底下的子項不用自己設：daemon 起它時就把 `AOS_DAEMON` 設成自己的 stack（[aos-daemon「子項的 AOS_DAEMON」](../../impls/aos-daemon/docs/05-信箱.md#子項的-aos_daemon_stack11-02thinking-11-02-resident-bob-衝突-2)），子項裡叫 aos-daemon-ctl 直接接到它的 daemon。
- **掛信寄哪**（11-05 [kernel-daemon 06 步 6](../../thinking/2026-11/05/kernel-daemon/06-實作步驟草稿.md)、N-63 `AOS_KERNEL`）：`add`／`rm`／`stop`／`start`／`sleep`／`wake` 的 `procs_*` 信，有設 `$AOS_KERNEL` 就寄那裡（「要掛 proc 往哪寄」：模式 1＝daemon 的 `requests/`、模式 2＝0 號 proc 的 `requests/`，判官判完才轉寄進 daemon 的 ctl 信箱，見 [demo/docs/04](../../demo/docs/04-kernel-modes.md)）；沒設＝直接寄 daemon 的 ctl 信箱（daemon 就是 kernel）。表照樣從 D 讀。`AOS_KERNEL` 沒有 `new/`＝`MailboxMissing`。實測：`AOS_KERNEL=/tmp/dj/requests aos-daemon-ctl --daemon /tmp/dj add --name clock sl` → 判官放行、`ls` 出現 `clock running`；名字不在白名單的被判官拒、表上沒有。
- **add／rm＝投信**（信箱模式，N-28、N-54）：信箱名照 daemon 在 `procs_state.json` 回報的 `procs_ctl_mailbox`（11-04 起 daemon.json 沒寫也開、預設 `procs_ctl_mailbox`；回報 `null`＝沒開＝`MailboxMissing`），沒有 `new/`＝`MailboxMissing`；stdout 印 aos-post 的信件名稱；daemon 下一圈才套，結果看 ls（壞信在 procs_state 的 `mailbox_warning`）。rm＝`{"procs_removed": [名字]}`；先停再拿掉，stack 不清。
- **做完的同名再 add＝重新起**：信箱模式下子項做完（done）daemon 就從期望表拿掉，再投一封同名的 add 就再跑一次，不用先 rm。
- **自動識別**（11-04 改，使用者「拿掉，不應該看特定檔案。add這塊，就是看最終指向的json的內部結構。」，[four-elements 08 步 7](../../thinking/2026-11/04/four-elements/08-實作步驟-等aos-agent後.md)）：照 aos-exec 的找法走到入口（資料夾＝`XXX/$AOS_ENTRY`，預設 `_entry`、沒有再找 `.json`；可執行檔＝exec 型；JSON 陣列 `["aos-loop", 設定檔]`＝讀那份設定檔；字串＝轉向再走；有 `argv` 的物件＝單子＝exec 型；沒 `argv`、有 `exec` 的物件＝loop 設定；沒 `argv` 沒 `exec`＝取 `js[$AOS_ENTRY]` 再走），走到 loop 設定＝loop 子項，其他＝exec 型（XXX 的絕對路徑，跑一次）；不看檔名，繞圈＝`EntryBad`，`.env` 不讀、指示詞不解。loop 子項的設定＝那份 loop 設定（去掉 `_entry`；相對 exec 照它的資料夾轉絕對；exec 是內嵌單子＝換成 `<那份檔>#<指標>/exec`，例 `<XXX>/loop.json#/exec`，子 loop 每次 aos-exec 指回原檔那張單子，`AOS_CD`、相對的 cwd／argv 照原地算——eca 定義的 `aos-eca-turn … {"$env": "AOS_CD"}` 靠這條掛得上 daemon）；**11-04 起不補 `ctl`／`state`**（aos-loop 沒寫＝`ctl.json`／`state.json`）；設定只有 `exec`＝補 `"interval_ms": 0`（aos-loop 的預設本來是 0；daemon 看寫法決定怎麼起，只有 `{"exec": …}` 的物件＝跑一次，補了才不會被當成跑一次）。名字＝`--name` ＞ XXX 的資料夾名。
- **`-- 參數...`**：`--` 之後全當附加 argv，原樣不轉路徑；exec 型＝`procs_added {名字: [XXX 絕對路徑, 參數...]}`（daemon 起它＝`aos-exec XXX 參數...`；沒參數是字串），實際送的是物件 `{"exec": [XXX, 參數...], "def": XXX, "ws"?: WS, "stack"?: S}`（`def` 見下）。**loop 型帶參數＝`ArgumentsBad`**（代定：要參數寫進 loop.json 的 `exec`）。XXX 後面接的不是 `--`＝`ArgumentsBad`（add 只收一個 XXX）。例：`aos-daemon-ctl add ../../agents/bob -- "在 env:AOS_WS 寫一首詩，詠桃花，檔名 peach.txt。"`。
- **`--ws WS`**（使用者「都照建議」）：這一隻的工作區。WS 從呼叫當下的 cwd 轉絕對（不是資料夾＝`PathMissing`、空＝`ArgumentsBad`），寫進子項物件的 `ws`（loop＝子項設定多一個 `ws`；exec＝`{"exec": XXX 或 [XXX, 參數...], "ws": WS}`），daemon 起它時設 `AOS_WS`（[aos-daemon「子項的工作區 ws」](../../impls/aos-daemon/README.md)）。
- **`--stack S`**（使用者「那就記錄在名單上。我是希望盡量不要用捷徑啦。然後S裡面有別的東西的話，使用者要自己承擔風險。」）：這一隻的 stack，沒給＝daemon 的預設小格 `<D>/procs/<名字>/`。S 從呼叫當下的 cwd 轉絕對（同 `--ws`）、**不驗在不在**（daemon 起它時 `mkdir -p`）；空（`--stack ""`、`--stack=`）＝`ArgumentsBad`；寫進子項物件的 `stack`（loop 型多一個 key、exec 型寫成 `{"exec", "stack"}`）。
- **不碰 `<WS>/.stack`**（使用者「那其實.stack根本不需要放到ws那邊」，[thinking 11-03 stack-where](../../thinking/2026-11/03/stack-where.md)）：add／rm 不建也不拆指到小格的 symlink；子項的 stack 歸 daemon 管，`AOS_WS` 只是一個位址。工作區原本有什麼都不動、不說話。要對它說話：`aos-agent say --target 名字 你好 && aos-agent listen --target 名字`（[aos-agent](../../extras/agent/README.md)，11-04 起取代 aos-say／aos-listen；它掛 agent 也是叫本程式）。
- **stop／start**：`stop 名字`＝`{"procs_stopped": [名字]}`（loop 型跑完這次自己退 0、列留成 `stopped`、stack 留著、where 照找得到）；`start 名字`＝`{"procs_started": [名字]}`（stopped 的用列上的 stack 再起；起來是跑還是暫停看它自己的 state.json）；stdout 印信件名稱。
- **sleep／wake**（11-05 [portable-flow 衝突 1](../../thinking/2026-11/05/portable-flow/05-衝突與方向題.md)，使用者選「嚴格分」）：`sleep 名字`＝`{"procs_slept": [名字]}`（daemon **現在就**對它 SIGTERM〔10 秒 KILL〕、列留成 `sleeping`、stack 留著；daemon 開門自己醒，或 `wake` 叫醒）；`wake 名字`＝`{"procs_woken": [名字]}`（sleeping 的用列上的 stack 再起）；stdout 印信件名稱。一句話分：**stop 等它做完這輪、要人 start 才回來；sleep 現在就睡、daemon 開門自己醒**。搬家前先 sleep（或直接 Ctrl-C daemon）再複製。
- **用錯 phase＝`PhaseBad`**（11-05 嚴格分；照表檢查、退 1、不送信，daemon 再驗一次）：`stop`、`sleep` 只收 `running`；`start` 只收 `stopped`；`wake` 只收 `sleeping`。提示照表上的 phase 給下一步，例 sleeping 的 `start`＝「X 是 sleeping，要 wake」、sleeping 的 `stop`＝「要先 wake 再 stop，或直接 rm」、stopped 的 `wake`＝「要 start」。11-05 前 `start` 也收 sleeping，收回了。daemon 沒在跑時 `wake`／`start`／`rm` 照樣寄（daemon 再開先套信）。
- **pause／resume**（[ctl-commands § 5](../../thinking/2026-11/03/ctl-commands/README.md)）：不經 daemon，直接往它的 ctl（stack 裡 daemon 寫的 `loop.json` 的 `ctl` 那格，慣用 `ctl.json`）寫一道 `{"cmd": "pause"|"resume", "seq": N}`（先寫 `.ctl.json` 暫存再改名，N-05；N＝ctl 裡現有的 `seq`＋1，沒有＝1，內容一定跟上一道不同），stdout 印 N（它 state.json 的 `ctl_seq` 追上 N＝看到了）。誰都不清 ctl。要看暫停了沒：看它 stack 裡的 `state.json`（`cat $(aos-daemon-ctl where --stack 名字)/state.json`，`phase` 是 `paused`）。
- **表上的路徑存相對、印絕對**（11-05 [portable-flow 03](../../thinking/2026-11/05/portable-flow/03-絕對路徑盤點.md)，使用者「可以用daemon作為相對路徑的一個基準點」）：daemon 寫 `procs_state.json` 時每列的 `stack`／`ws`／`exec`／`def` 存成**相對 daemon 的 stack**（＝D；例 `procs/bob`、`..`、`../../agents/bob/loop.json#/exec`），整份 `ws/` 搬走或 git pull 到別台照樣對得上。本程式讀表時一律 `normpath(join(D, 值))`（`exec` 的 `#` 片段照留；字串算、不 realpath），**ls、ls --json、where 印的都是絕對**。add 送給 daemon 的照舊是絕對（「只改存的格式，不改給的格式」）。
- **`ls --json`**（11-04 晚）：列照 procs_state 原樣（路徑欄拼回絕對，上條），每列多一欄 `exec`＝daemon 記的起它時的目標（絕對；loop 型多是 `<XXX>/loop.json#/exec`、exec 型是 XXX；內嵌單子＝`null`；[aos-daemon](../../impls/aos-daemon/docs/02-看寫法決定怎麼起.md)），再一欄 `def`＝add 送的定義資料夾（下條）；文字的 ls 不加欄。
- **`def`**（11-04，使用者 11-04「那就b。」，[aos-agent 05/03 第 2 條](../../thinking/2026-11/04/aos-agent/05-實作步驟/03-實作時改的設計.md#實作時改的設計)）：add 的子項物件一律多帶 `"def"`＝XXX 的絕對路徑（`#` 後面不帶；11-05 起 `--def DEF` 可另給，aos-agent 的定義宣告了 `entry`、XXX 是定義裡那個入口時用），loop 型、exec 型都送——所以 exec 型一律送物件 `{"exec": XXX 或 [XXX, 參數...], "def": XXX, "ws"?, "stack"?}`，不再送裸字串；daemon 只記進表的 `def` 欄，aos-agent 靠它找定義。
- **exec 型只有跑和拔**（使用者「exec就是只有執行中和拔掉」）：stop、sleep、pause、resume 先看它的 stack 裡有沒有 daemon 寫的 `loop.json`（名字照窗上的 `procs_loop`，11-04；它的 `ctl` 沒寫＝`ctl.json`），沒有＝`CtlMissing`「X 沒有 ctl（exec 型只有跑和拔）」、退 1、不送信不寫檔；`loop.json` 的 `ctl` 是 null＝也是 `CtlMissing`。start、wake 不看（只收 `stopped`／`sleeping` 的列，只有 loop 型會被停或睡；同一圈 add＋stop 的 stack 還沒建）。daemon 自己再驗一次。表上沒有＝`ProcMissing`。
