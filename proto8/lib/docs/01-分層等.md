## 分層（每層只依賴下層）

```
<agent>/                   最上層：agent 本身（也是函數；例 demo/agent-fsm）
  tools/<名> ─捷徑─▶ lib/<層>/<名>/        引用，不複製（見下「怎麼引用」）
lib/agent/                 高層：裡面是一整隻 agent（或外部 agent CLI）的工具（pyfix、claude、codex）＋共用模組 agent_tool.py、cli_session.py
lib/aos/                   中層：動 aos 自己東西的工具（記憶 heap、寄信）＋共用模組 aos_ws.py
lib/base/                  底層原語：檔案、資料夾、JSON、行程（bash）、小工具——Linux＋Python 標準庫（json_edit 另叫 aos-json）、只碰 $AOS_WS
lib/tool_io.py             最底：每個工具共用的開頭（--help、Ctrl-C、錯誤行／提醒行、讀 stdin、查工作區）——不是工具，是共用模組（11-05 晚）
impls/                     基礎層與標準庫（C-74）：aos-exec 把工具叫起來，loop／fsm 跑 agent
```

層名只是資料夾名，不進工具名；還沒有工具的層不先建空資料夾（STRUCTURE：不預先建空檔）。

## 一個工具長什麼樣（契約）

一個工具＝一個資料夾程式（C-61、N-50），裡面固定三個檔：

| 檔 | 給誰看 | 內容 |
|---|---|---|
| `_entry` | aos-exec | 可執行檔（python3 純標準庫，或 sh）；第一行 shebang，第二行 `# <名> - 一句話`（C-54 R1） |
| `_tooldef.json` | 模型 | `{"description", "parameters"}`（P-41，OpenAI function 物件去掉 name；工具名＝登記進 agent 的 `tools.json` 時取的名字，預設＝資料夾名） |
| `_metainfo.json` | kernel 與人 | JSON（11-04 起檔名帶 `.json`，原 `_metainfo`；JSON 檔與單子裡的 key 仍叫 `_metainfo`），通用 key 照 [`_metainfo` 規劃](../../thinking/2026-10/24/metainfo/01-位置與格式.md)：`summary`、`time_ms`、`resource`、`side_effect`、`idempotent`、`deterministic`、`interrupt`、`parallel`；模型看不到（M10） |

規則：

1. **參數**：stdin 一份 JSON 物件（模型的 `arguments` 原樣，P-41）；空 stdin 當 `{}`。key 全小寫底線、單位放字尾（`timeout_s`、`max_bytes`，C-54）；選填的寫預設值在 `_tooldef.json` 的說明裡。
2. **結果**：stdout 整段就是結果（P-41）。文字工具印文字；結構工具（`ls`、`json_*`）印一行 JSON。工具起的程式的 stderr **原樣透到工具的 stderr**，不攔、不塞進自己的錯（C-52；11-05 [stdio-unify](../../thinking/2026-11/05/stdio-unify/README.md) R10）——下層壞了，工具只多寫自己一行錯誤行，stdout 也只有那一行（D2：腦只看 stdout，不被下層的話淹）。例外照寫在各工具：`agents`、`self_tools`、aos-json 的 `json`／`json_edit` 把下層錯誤行的代號與原因接在自己的錯誤行裡（例 `self_tools: error: ToolExists …`）——這是**給腦用的工具把下層錯翻成自己的錯**：腦只看 stdout，光一句 `CommandFailed` 它不知道該改哪裡（腦要知道哪裡寫錯，stdio-unify C 線代定；`self_tools` 11-05 E 線補上）。
3. **錯**（寫法在 `tool_io.die`／`warn`，規則 9）：一律 stderr 一行 `工具名: error: 代號 原因`、退 1（P-21；11-05 stdio-unify R1、R2 起中間多 `error: `，例 `read: error: FileMissing a.txt`），**同一行也印在 stdout**——stdout 是給腦看的，腦才知道錯在哪。不算錯、只是要人知道的事寫提醒行 `工具名: warning: 句子`（只在 stderr、不帶代號；例 judge 拒信）；有錯誤行就不退 0。stdin 不是 JSON＝`ArgumentsBad stdin is not JSON`（不帶 Python 的例外原文，R11）；有 `op` 的工具：沒給 op＝`ArgumentsBad`、給了不認得＝`OpUnknown`。代號照 C-54 四種結尾（`ArgumentsBad`、`WsMissing`、`PathBad`、`FileMissing`、`FileBad`、`ReadFailed`、`WriteFailed`、`MkdirFailed`、`TextMissing`、`TextBad`、`PointerBad`、`PointerMissing`、`CommandFailed`、`LaunchFailed`）。**參數給錯對工具來說也是錯、照樣退 1**；停下等人還是把那行回給腦，是叫它的 agent 自己的決定（agent-eve 等範本都回給腦，[thinking](../../thinking/2026-10/23/tool-calls/README.md#10-24-定叫工具與小念頭的失敗回給腦)），工具不替它決定（C-52、C-53 入口檢查）。被跑的指令自己退非 0 **不是**工具的錯（那是結果）：`bash`、`run_python` 的結果**最後一行一律是 `[exit code N]`**（退 0 也寫；被訊號殺＝128＋N），工具照樣退 0。
4. **沙盒＝`$AOS_WS`**：路徑一律從工作區算，解開 `..` 與捷徑後必須還在裡面（`PathBad`）；沒設或不是資料夾＝`WsMissing`。要動別的資料夾，是叫它的人 `aos-exec --ws 那裡 tools/<名>`（C-66 指標＝`AOS_WS`），工具不另收根的參數或環境變數。`bash` 擋不住指令本身跑出去，說明裡寫明。例外：`agents` 讀的路徑（`def`、`from`、`tools` 的 `path`）與子 agent 的 `ws` 收絕對路徑（定義放哪都行，[portable-flow](../../thinking/2026-11/05/portable-flow/README.md)；使用者 11-05 子 agent 工作區「不要固定」），它寫的（`new` 的 `path`、`files`）照樣只在工作區裡。
5. **逾時與訊號**：會跑東西的工具一定有逾時（`timeout_s`，預設與上限寫在 `_tooldef.json`），到時整群先 TERM 再 KILL、算 `CommandFailed`；工具自己被外面 TERM（act 格逾時）時先收掉自己起的那一群再走，不留孤兒（P-36）。Ctrl-C（SIGINT）＝不吐 traceback、退 130（有子行程的同 TERM，先收那一群；R12）。
5a. **`--help`**（11-05 stdio-unify R3，使用者「全都有」「--help要輸出英文」）：argv 有 `--help`＝英文用法（參數、結果、錯誤行的形狀）印 stdout、退 0；其他 argv 照舊不看。說明是給人看的，模型看的是 `_tooldef.json`。
6. **寫檔**：先寫 `.` 開頭的暫存檔再改名（N-05）、留住原檔權限；幾處一起改的全有或全無。
7. **上限與漸進展開**：讀最多 2000 行或 50KB、列最多 500 項、JSON 檔最多 4MB；超過就截，並在結果裡說怎麼接著拿（`offset`、`next_offset`、`pointer` 往下一層）。
8. **stack**：工具的 stack＝呼叫者給的小格 `$AOS_STACK/tools/<名>/`（P-17）；base 層是純函數、不用 stack，要跨呼叫留東西的工具（中層以上）才寫那裡。
9. **共用開頭收在 `lib/tool_io.py`**（使用者 11-05 裁「收成共用模組」；原則「統一成單一介面，這樣只需要改介面」，[stdio-unify](../../thinking/2026-11/05/stdio-unify/README.md#剩下的)）：錯誤行、提醒行、`--help`、Ctrl-C、讀 stdin 參數、查工作區的寫法只在 `tool_io.py` 一份，工具 `tool_io.start(NAME, HELP)` 之後用 `tool_io.die`／`warn`／`arguments`／`workspace`，不自己拼錯誤行。工具找它的順序：**先找工具自己的資料夾、再找 `lib/`**（工具資料夾往上兩層；用 realpath，所以被捷徑掛到哪都找得到），**最後找 PATH 上 `aos-tools` 所屬那份 proto8 的 `lib/`**（`install.sh` 的捷徑指回 `proto8/bin/`；11-05 晚試驗場回報：定義 `cp -r` 出 repo 就找不到）；三處都沒有＝`ModuleMissing` 錯誤行（給腦用的兩邊印、judge 只 stderr）、退 1。其餘仍只靠自己：不 `import` 隔壁工具的檔；同一層的共用模組（`agent_tool.py`、`cli_session.py`、`aos_ws.py`）照舊。
   - **複製出 lib**（釘版、改寫）：PATH 上有 aos-tools 就照樣找得到；要連 tool_io 一起釘版，把 `tool_io.py` 複製進工具資料夾（自己資料夾最先找）。
   - **沙箱**：工具在 aos-sandbox 裡跑時 `tool_io.py` 也要看得到——設定的 `ro` 加上它（例 [bash-boxed](../../extras/sandbox/examples/bash-boxed/sandbox.json) 的 `"../../../../lib/tool_io.py"`）；沒綁＝工具起不來（印 `工具名: error: ModuleMissing tool_io.py not found …` 一行、退 1，11-05 晚）。
   - 不收的：`judge` 不是給腦用的（`start(..., echo=False)`：錯誤行只到 stderr）；`cli_session.py` 也給 proto8/bin 的 aos-eca-turn 用，維持自己的 `die`／`warn`；pyfix 子 agent 的格（`pyfix/agent/act.py`、`brain.py`）是 agent 的格、不是工具，照舊。
10. **命名**：工具名＝資料夾名，一個動詞（`read`、`ls`）或「主題_動詞」（`json_read`、`json_edit`，C-54 主題在前）；縮寫照 [abbr.json](../../docs/CONCEPTS/abbr.json)；錯誤代號主詞在前。

## 怎麼引用（不複製）

agent 的 `tools/` 裡放**一條相對捷徑指到庫裡那個工具**，一個工具一條：

```sh
cd <agent>/tools && ln -s <proto8>/lib/base/read read   # 11-04 前的例子是 demo/agent-liv/tools（demo 刪了）
```

- 捷徑建好再**登記進 agent 的 `tools.json`**（範本手寫相對路徑 `"read": {"path": "tools/read"}`，或 `aos-tools --file ../tools.json add read` 寫絕對路徑）；沒登記＝腦看不到。
- agent 的程式**一個字不用改**：act 照舊 `aos-tools call read`（→ `aos-exec <agent>/tools/read`，P-25、P-33）；aos-exec 走進捷徑指到的真資料夾（cwd、`AOS_CF`、`AOS_CD` 都是庫裡的位置，N-57、N-59），brain 照舊從 `tools.json`（`aos-tools ls --json`）組 tools 陣列。agent 不知道、也不必知道這個工具是庫的（C-52）。
- **要哪些掛哪些**，自己的工具（真資料夾）跟庫的並存在同一個 `tools/`；同名時自己的贏（一個名字只能有一個東西），這就是覆寫。
- **版本＝git**：庫改了，掛著的 agent 下次跑就是新的；要釘住某一版就複製那個資料夾進自己的 `tools/`（複製＝覆寫＝自己維護；`lib/tool_io.py` 一起複製進那個資料夾，規則 9）。
- 代價：只有 Linux 有捷徑（使用者 10-19「先只考慮在linux上」）；repo 外的 agent 要寫絕對路徑；複製 agent 資料夾時要保留捷徑（`cp -a`，不要 `cp -r`／跟著捷徑複製，不然就變成複本）。
