## 一個工具長什麼樣（契約）

一個工具＝一個資料夾程式（C-61、N-50），裡面固定三個檔：

| 檔 | 給誰看 | 內容 |
|---|---|---|
| `_entry` | aos-exec | 可執行檔（python3 純標準庫，或 sh）；第一行 shebang，第二行 `# <名> - 一句話`（C-54 R1） |
| `_tooldef.json` | 模型（`tool_io` 也讀） | `{"description", "parameters"}`（P-41，OpenAI function 物件去掉 name；工具名＝登記進 agent 的 `tools.json` 時取的名字，預設＝資料夾名）。工具側（`tool_io`）另讀的選填 key：`positional`（位置參數依序填哪些鍵）、`errors`（`--help` 印成一行 `Error codes:` 的錯誤代號陣列：這支工具錯誤行可能出的代號，`ArgumentsBad` 先、其餘照程式出現順序，叫 `workspace()` 的含 `WsMissing`；每支共通的 `FlagUnknown`、`ModuleMissing` 不列；把下層代號照接的工具〔`agents`、`self_tools`、`thought`〕只列自己會出的；11-06 json-argv J2）、`env`（這支工具要靠哪些 hub 型環境變數找東西，變數名陣列，例 `["AOS_DAEMON"]`；`--help` 照它印一行 `Environment:`；列哪些看規則 11；11-06 no-pid P4，[thinking](../../../thinking/2026-11/05/no-pid/README.md)）；property 的 `default` 會印進 `--help`；模型只看 `description`、`parameters`。沒有這個檔＝旗標全當字串；壞了（讀不了、不是 JSON、`parameters` 不是物件）＝提醒行一行、當沒有照樣跑（11-06 json-argv J1，[thinking](../../../thinking/2026-11/05/json-argv/README.md)） |
| `_metainfo.json` | kernel 與人 | JSON（11-04 起檔名帶 `.json`，原 `_metainfo`；JSON 檔與單子裡的 key 仍叫 `_metainfo`），通用 key 照 [N-68](../../../docs/NORMS/10-基礎設施-定義與工作區/10-N-68.md)：`summary`、`cost`（`time_ms`／`token`／`counter_calls`）、`timeout_ms`、`resource`、`side_effect`、`idempotent`、`deterministic`、`interrupt`、`parallel`；模型看不到（M10） |

規則：

1. **參數**：stdin 一份 JSON 物件（模型的 `arguments` 原樣，P-41）；空 stdin 當 `{}`；stdin 是終端（tty）＝當 `{}`、不讀（人在終端直接打旗標不會卡；11-06 json-argv J1，[thinking](../../../thinking/2026-11/05/json-argv/README.md)）。key 全小寫底線、單位放字尾（`timeout_s`、`max_bytes`，C-54）；選填的預設值一律寫成 `_tooldef.json` 該 property 的 `default`（值跟程式實際用的一樣，會印進 `--help`；說明文字裡原本寫的照留，那是模型看的；11-06 json-argv J2，[thinking](../../../thinking/2026-11/05/json-argv/README.md)）。
   - **旗標**（11-06 json-argv J1，[thinking](../../../thinking/2026-11/05/json-argv/README.md)；使用者 11-05 晚「旗標我覺得只是一種補充手段」）：人可以用旗標給參數——`--key V`（或 `--key=V`）對到 stdin JSON 的同名鍵，連字號換底線（`--max-bytes 10` → `"max_bytes": 10`）。兩邊都給＝**旗標 ＞ stdin**、不報錯；巢狀 `--a.b V` 只換那一葉，`a` 的其他鍵照留；stdin 多的鍵工具不認得就忽略（只吃想吃的）；不認得的旗標＝`FlagUnknown`（旗標是人打的，打錯要知道）。型別怎麼轉、開關、陣列、位置參數等映射細節看 `lib/tool_io.py` 檔頭與 thinking json-argv [03](../../../thinking/2026-11/05/json-argv/03-旗標映射設計.md)／[07](../../../thinking/2026-11/05/json-argv/07-使用者回覆-11-05晚.md)，這裡不重抄。
2. **結果**：stdout 整段就是結果（P-41）。文字工具印文字；結構工具（`ls`、`json_*`）印一行 JSON。工具起的程式的 stderr **原樣透到工具的 stderr**，不攔、不塞進自己的錯（C-52；11-05 [stdio-unify](../../../thinking/2026-11/05/stdio-unify/README.md) R10）——下層壞了，工具只多寫自己一行錯誤行，stdout 也只有那一行（D2：腦只看 stdout，不被下層的話淹）。例外照寫在各工具：`agents`、`self_tools`、`aos_json`／`json_rewrite` 把下層錯誤行的代號與原因接在自己的錯誤行裡（例 `self_tools: error: ToolExists …`）——這是**給腦用的工具把下層錯翻成自己的錯**：腦只看 stdout，光一句 `CommandFailed` 它不知道該改哪裡（腦要知道哪裡寫錯，stdio-unify C 線代定；`self_tools` 11-05 E 線補上）。
3. **錯**（寫法在 `tool_io.die`／`warn`，規則 9）：一律 stderr 一行 `工具名: error: 代號 原因`、退 1（P-21；11-05 stdio-unify R1、R2 起中間多 `error: `，例 `read: error: FileMissing a.txt`），**同一行也印在 stdout**——stdout 是給腦看的，腦才知道錯在哪。不算錯、只是要人知道的事寫提醒行 `工具名: warning: 句子`（只在 stderr、不帶代號；例 judge 拒信）；有錯誤行就不退 0。stdin 不是 JSON＝`ArgumentsBad stdin is not JSON`（不帶 Python 的例外原文，R11）；有 `op` 的工具：沒給 op＝`ArgumentsBad`、給了不認得＝`OpUnknown`。代號照 C-54 六種結尾（`ArgumentsBad`、`FlagUnknown`（旗標，規則 1）、`WsMissing`、`PathBad`、`FileMissing`、`FileBad`、`ReadFailed`、`WriteFailed`、`MkdirFailed`、`TextMissing`、`TextBad`、`PointerBad`、`PointerMissing`、`CommandFailed`、`LaunchFailed`）。**參數給錯對工具來說也是錯、照樣退 1**；停下等人還是把那行回給腦，是叫它的 agent 自己的決定（agent-eve 等範本都回給腦，[thinking](../../../thinking/2026-10/23/tool-calls/README.md#10-24-定叫工具與小念頭的失敗回給腦)），工具不替它決定（C-52、C-53 入口檢查）。被跑的指令自己退非 0 **不是**工具的錯（那是結果）：`bash`、`run_python` 的結果**最後一行一律是 `[exit code N]`**（退 0 也寫；被訊號殺＝128＋N），工具照樣退 0。
   - **11-06 註**：共通代號也包含 `StackMissing`（需要 stack 的工具缺執行狀態）與 `ModuleMissing`（規則 9 的共用模組找不到）；原清單其餘代號照舊。見 json-argv [J2 實作結果](../../../thinking/2026-11/05/json-argv/09-J2實作結果.md#新發現的邊緣沒修攤出來)。
4. **沙盒＝`$AOS_WS`**：路徑一律從工作區算，解開 `..` 與捷徑後必須還在裡面（`PathBad`）；沒設或不是資料夾＝`WsMissing`（一律走 `tool_io.workspace()`，沒有工具把沒設當成 `.`；`claude`、`codex` 原本預設 `.`，11-06 json-argv J2 起同樣 `WsMissing`）。要動別的資料夾，是叫它的人 `aos-exec --ws 那裡 tools/<名>`（C-66 指標＝`AOS_WS`），工具不另收根的參數或環境變數（找 daemon、知識庫這類別處服務的位置是另一回事，見規則 11）。`bash` 擋不住指令本身跑出去，說明裡寫明。例外：`agents` 讀的路徑（`def`、`from`、`tools` 的 `path`）與子 agent 的 `ws` 收絕對路徑（定義放哪都行，[portable-flow](../../../thinking/2026-11/05/portable-flow/README.md)；使用者 11-05 子 agent 工作區「不要固定」），它寫的（`new` 的 `path`、`files`）照樣只在工作區裡。
   - **`memory_write` 的例外**（使用者 11-05 夜裁定）：沙盒＝定義的 `_memory.json` 或人配的 `AOS_MEMORY` 所指知識庫根；腦只能給節點路徑，不能另挑根。庫內捷徑是人配的掛載，寫入經捷徑落在真資料夾；根節點本身不給改、刪，能否寫由工具清單與 Linux 權限決定。
5. **逾時與訊號**：會跑東西的工具一定有逾時（`timeout_s`，預設與上限寫在 `_tooldef.json`），到時整群先 TERM 再 KILL、算 `CommandFailed`；工具自己被外面 TERM（act 格逾時）時先收掉自己起的那一群再走，不留孤兒（P-36）。Ctrl-C（SIGINT）＝不吐 traceback、退 130（有子行程的同 TERM，先收那一群；R12）。
