5a. **`--help`**（stdio-unify R3，使用者「全都有」「--help要輸出英文」）：argv 在旗標位置有 `--help`（前個帶值旗標的值、第一個位置參數後與 `--` 之後都不算；使用者裁定 sol 審查 #34-1）＝英文用法（參數、結果、錯誤行的形狀）印 stdout、退 0。旗標段從 `_tooldef.json` 生（參數、`default`、`errors` 的錯誤代號、`env` 都從那裡來），接在工具手寫的說明後面；手寫的只剩用法行、做什麼、結果與錯誤行的形狀，**工具不手寫參數段**——參數的事只寫在 `_tooldef.json` 一份，`_tooldef.json` 的 description 沒講到的語意寫成手寫說明裡的一句話（json-argv J2，[thinking](../../../thinking/2026-11/05/json-argv/README.md)）；其他 argv 由 `tool_io.arguments()` 解成旗標（規則 1），工具不叫 `arguments()` 的（例 judge）argv 自己解（json-argv J1，[thinking](../../../thinking/2026-11/05/json-argv/README.md)）。說明是給人看的，模型看的是 `_tooldef.json`。
6. **寫檔**：先寫 `.` 開頭的暫存檔再改名（N-05）、留住原檔權限；幾處一起改的全有或全無。
7. **上限與漸進展開**：讀最多 2000 行或 50KB、列最多 500 項、JSON 檔最多 4MB；超過就截，並在結果裡說怎麼接著拿（`offset`、`next_offset`、`pointer` 往下一層）。
8. **stack**：工具的 stack＝呼叫者給的小格 `$AOS_STACK/tools/<名>/`（P-17）；base 層是純函數、不用 stack，要跨呼叫留東西的工具（中層以上）才寫那裡。 小格由 `aos-tools call` 一處算，呼叫者只傳自己的 stack（J3 `a6d8cd9a`，[結果](../../../thinking/2026-11/05/json-argv/10-J3到J7實作結果.md)）。
9. **共用開頭收在 `lib/tool_io.py`**（使用者 11-05 裁「收成共用模組」；原則「統一成單一介面，這樣只需要改介面」，[stdio-unify](../../../thinking/2026-11/05/stdio-unify/README.md#剩下的)）：錯誤行、提醒行、`--help`、Ctrl-C、讀 stdin 參數、查工作區的寫法只在 `tool_io.py` 一份，工具 `tool_io.start(NAME, HELP)` 之後用 `tool_io.die`／`warn`／`arguments`／`workspace`，不自己拼錯誤行。`arguments()` 也合併旗標（規則 1），並照 `_tooldef.json` 做最小型別檢查：只查 `type`／`required`（不合＝`ArgumentsBad`）；`enum` 不查——規則 3 的 `OpUnknown` 是工具自己的錯碼，tool_io 先擋會變成 `ArgumentsBad`；值是 `null` 當沒給（json-argv J1，[thinking](../../../thinking/2026-11/05/json-argv/README.md)；`arguments()` 驗完型別（sol 審查 #13）就把 schema 寫了 `type` 的 null 鍵拿掉，工具拿到的就是「沒給」、預設照補（不拿掉的話 `null` 會蓋掉預設、或跟互斥的鍵撞）；沒寫 `type` 的鍵（例 json_set 的 `value`）null 照字面留著）。工具找共用模組的順序：**自己的資料夾 → 從自己 `realpath(__file__)` 往上找 repo 的 `lib/` → 標準 `sys.path`**（K-5）。最後一段可由 `install.sh` 寫的 user site `aos-proto8.pth` 或明給的 `PYTHONPATH` 提供；不從 PATH 上 `aos-tools` 的真位置推庫在哪。都沒有＝`ModuleMissing` 錯誤行（給腦用的兩邊印、judge 只 stderr）、退 1。不 `import` 隔壁工具的檔；共用的 `agent_tool.py`、`cli_session.py` 與 `cli_*.py`、`agent_files.py` 都在 `lib/agent/`，`lib` 不 import 上層 `py`。
   - **`tool_spec.py`**（[tools-def](../../../thinking/2026-11/10/tools-def/README.md)）：給 AI 寫新工具的輔助，同層 import `tool_io`。骨架 `templates/tool-python/tool.py` 的開頭找它的順序：自己的資料夾 → 祖先資料夾底下的 `lib/` → `$AOS_HOME/lib` → 標準 `sys.path`；所以骨架抄到哪都行，只要設了 `AOS_HOME`，或把 `tool_spec.py`、`tool_io.py` 一起抄到 `tool.py` 旁邊。這是骨架自己的找法，lib 裡現有工具不加 `$AOS_HOME`。
   - **複製出 lib**（釘版、改寫）：先跑過 `install.sh`，或讓 `PYTHONPATH` 包含 repo 的 `lib` 絕對路徑，就能經標準 `sys.path` 找共用模組；要連 tool_io 一起釘版，把 `tool_io.py` 複製進工具資料夾（自己的資料夾最先找）。
   - **沙箱**：工具在 aos-sandbox 裡跑時 `tool_io.py` 也要看得到——設定的 `ro` 加上它（例 [shell-boxed](../../../cmd/aos-sandbox/examples/shell-boxed/sandbox.json) 的 `"../../../../lib/tool_io.py"`）；沒綁＝工具起不來（印 `工具名: error: ModuleMissing tool_io.py not found …` 一行、退 1）。repo 外的工具若靠 `.pth` 或 `PYTHONPATH`，相關路徑也要在沙箱裡可見。
   - **輸出也共用**：`judge` 不是給腦用的，`start(..., echo=False)` 讓錯誤行只到 stderr；`cli_base.py` 的 `die`／`warn` 同樣走 `tool_io`，工具形 `call_main` 兩邊印、cmd／畫面形只印 stderr。`claude`、`codex` 的開頭走 `agent_tool.ask_cli`（`start`、`workspace`、`arguments`），再叫 `cli_ask.ask`；`call_main` 只給 aos-eca-turn `--one` 用。
10. **命名**：工具名＝資料夾名，一個動詞（`read`、`ls`）或「主題_動詞」（`json_get`、`json_set`，C-54 主題在前）；縮寫照 [abbr.json](../../../docs/CONCEPTS/abbr.json)；錯誤代號主詞在前。
11. **找東西靠環境變數或明給、不碰 pid**（no-pid P4，[thinking](../../../thinking/2026-11/05/no-pid/README.md)；使用者 11-05 晚「所有牽涉到linux原生行程的機制，都以daemon爲界面」「只要是aos函數，我們都默認他能吃aos-exec所提供的那幾個環境變數」）：工具要找別處的東西，只從環境變數或呼叫的人直接指定的位置拿；牽涉 Linux 行程的事一律交給 daemon。
    - **位置怎麼拿**：工具是 aos 函數，aos-exec 給的六個環境變數（`AOS_WS`、`AOS_STACK`、`AOS_CF`、`AOS_CD`、`AOS_CO`、`AOS_ENTRY`）當作一定在。指向別處服務的 hub 型變數（`AOS_DAEMON`、`AOS_LLM_KERNEL`…）不一定在——工具被借給別的 agent、進沙箱、搬家時都可能掉——所以工具從 `AOS_<名字>`，或呼叫的人直接指定的 argv／設定拿位置；都沒有＝`<名字>Missing`、不猜。
    - **不碰行程**：不讀 pid（行程編號）、不掃 `/proc`、不送訊號給不是自己起的行程（自己起的子行程整群收拾不算，規則 5）。要知道 daemon 或某個 proc 活不活，讀 daemon 寫的檔（`state.json`、`procs_state.json`）；要它做事，寄信等回信，時限內沒回＝這次呼叫失敗，不管它是忙、暫停還是掛了。
    - **列出依賴**：設計工具時先把它依賴的 hub 變數列進 `_tooldef.json` 的 `env`（契約表），讓用它的人知道它要靠哪些、少了會報什麼。登記格的 `env`（aos-tools 登記檔那一格）補的是工具自己的 hub（`AOS_LLM_KERNEL`…），不補 aos-exec 的六個、也不補 `AOS_DAEMON`——`AOS_DAEMON` 由 daemon 給子、人殼 export 或 `--daemon` 指定，寫死在登記格會讓工具借到別台 daemon 底下時指錯台（[no-pid 03 § 3](../../../thinking/2026-11/05/no-pid/03-找daemon與脫鉤.md)）。
    - **端點金鑰**：endpoint 函數的金鑰變數名寫在端點小定義的 `--key-env NAME`，小 proc 自己讀環境；不從 stdin 拿金鑰，也不把值寫進定義或 stack（[env-portability E1](../../../thinking/2026-11/06/env-portability/06-E1改-金鑰歸小proc.md)）。

## 怎麼引用（不複製）

agent 的 `tools/` 裡放**一條相對捷徑指到庫裡那個工具**，一個工具一條：

```sh
cd <agent>/tools && ln -s <proto8>/lib/base/read read
```

- 捷徑建好再**登記進 agent 的 `tools.json`**（範本手寫相對路徑 `"read": {"path": "tools/read"}`，或 `aos-tools --file ../tools.json add read` 寫絕對路徑）；沒登記＝腦看不到。
- agent 的程式**一個字不用改**：act 照舊 `aos-tools call read`（→ `aos-exec <agent>/tools/read`，P-25、P-33）；aos-exec 走進捷徑指到的真資料夾（cwd、`AOS_CF`、`AOS_CD` 都是庫裡的位置，N-57、N-59），brain 照舊從 `tools.json`（`aos-tools ls --json`）組 tools 陣列。agent 不知道、也不必知道這個工具是庫的（C-52）。
- **要哪些掛哪些**，自己的工具（真資料夾）跟庫的並存在同一個 `tools/`；同名時自己的贏（一個名字只能有一個東西），這就是覆寫。
- **版本＝git**：庫改了，掛著的 agent 下次跑就是新的；要釘住某一版就複製那個資料夾進自己的 `tools/`（複製＝覆寫＝自己維護；`lib/tool_io.py` 一起複製進那個資料夾，規則 9）。
- 代價：只有 Linux 有捷徑（使用者 10-19「先只考慮在linux上」）；repo 外的 agent 要寫絕對路徑；複製 agent 資料夾時要保留捷徑（`cp -a`，不要 `cp -r`／跟著捷徑複製，不然就變成複本）。
