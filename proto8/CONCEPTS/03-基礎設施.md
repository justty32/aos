# 基礎設施

子主題：inst、loop、daemon、窗、命令列、指示詞與路徑、組合子（tasks、fsm）、資料夾程式、工作區與 stack（10-19）。窗、命令列、指示詞與路徑沒有專屬的概念條，只有規範（見上）。

> 10-22 註：「基礎設施」是主題名（照內容分），不是層。分層（[C-74](01-設計理念.md#分層10-22-使用者定)）裡組合子 tasks、fsm 屬**標準庫**，其餘子主題（inst、loop、daemon、窗、命令列、指示詞與路徑、資料夾程式、工作區與 stack）屬**基礎層**（aos-exec 是其中的核心）。repo 根 [`core/README`](../../core/README.md) 說的「基礎設施」（`common/`、`app/`、`cmake/`）是舊一代 C++ 版的建置目錄，跟這裡無關。

## inst

實作：[inst](../impls/inst/README.md)〔10-23 註：原指 `proto8/bin` 版的 aos_inst 庫（10-22 起跟 impls 一樣不提供命令列），10-23 Python 版刪了〕；impls 線 inst 是 C lib、不提供命令列，單子由 aos-exec 行程內跑（[ideas § 20](../thinking/2026-10-19-ideas.md)）。C-36 的層層遞進從 inst 起，條文放在下面 loop 與 daemon。

- **C-08** 計算任務＝一個 POSIX 行程，不是 thread；不必再往下分種類。（2.7）
- **C-34** 求值＝放開讓它算、過一段時間看狀態變化的結果；求值的定義就是空間狀態的變化。對資料夾求值＝執行這個資料夾；求值還回來的是一個正在變動的資料夾，不是一個值。（3h、3f.1、3f.3）
- **C-42b** inst 的 JSON 裡可以多放東西：九軸特性、traits、資源標籤、優先順序標籤、工具……inst 不認的別人可以讀。工具用 JSON schema 限制引數；schema 怎麼轉成 argv——走 schema→argv 這條路，或先定義一些通用的東西，沒定。（3g.13b）10-13：這個抽屜定名 `_metainfo`，見 [thinking 10-13 §3](../thinking/2026-10-13-json-path.md)。

## loop 與 daemon

實作：loop＝[aos-loop](../impls/aos-loop/README.md)；daemon＝[aos-daemon](../impls/aos-daemon/README.md)（10-20 照「資料夾＝程式」重寫，當時是 `proto8/bin` 版；10-23 Python 版刪了，現在只有 impls 的 C++ 版）。

> **daemon 兩義**：①[C-04](01-設計理念.md) 說的 daemon＝aos 與 Linux 之間的借階層（Linux 那邊的事全在這層）；②這裡的 daemon＝管一群 loop 的程式（`aos-daemon`，C-36）。[名詞表](附錄1-名詞.md)兩列都留。

- **C-36** 層層遞進：inst（求值一次）→ loop（持續求值）→ node（loop 服務的資料夾）→ daemon（統管 loop）；daemon 跑的 inst 可以是另一個 daemon。（3f.2）**10-19 落實**：inst＝`aos-inst FILE` 把一張單子跑一次（`proto8/bin` 版，10-22 刪；impls 線沒有 aos-inst 命令列，10-22 起兩版都是：單子＝入口的一種、由 aos-exec 行程內跑，C-73、N-59）；loop＝`aos-loop loop.json`（`{"run", "max"}`：每次 `aos-exec` 一個子資料夾或跑一張單子，子程式退 10 就停，P-06、P-19；10-21 下午改：`aos-loop [--cfg loop.json] [旗標...] [XXX [args...]]`；10-21 傍晚再改：`aos-loop [旗標...] loop.json`，設定檔是唯一的位置參數、`run` 可以是陣列，[ideas 10-21 § 9](../thinking/2026-10-21-ideas.md#9-設定檔是唯一的位置參數path-改字串拼接10-21-傍晚)；`run` 只收 aos-exec 的目標、每次 `aos-exec` 它〔10-23 統合一度改名 `val`，同晚使用者改回 `run`（「只有 loop、daemon 用 run」），[thinking](../thinking/2026-10-23-naming.md)〕，內嵌單子寫 `loop.json#/body`，[ideas 10-21 § 8](../thinking/2026-10-21-ideas.md#8-aos-loop10-21-下午)）；一次一格的 fsm＝`aos-fsm`（P-07；10-21 改：`aos-fsm --cfg fsm.json`，10-21 傍晚再改回 `aos-fsm fsm.json`（設定檔是唯一的位置參數）；格的 `val` 只收 aos-exec 的目標、每次 `aos-exec` 它，內嵌單子寫 `fsm.json#/states/<名>/body`，[計畫 10-21](../thinking/2026-10-21-plan.md) F1、F2）；node＝被 loop 反覆跑的那個資料夾程式。daemon（管一群 loop）10-20 照新做法重寫（`proto8/bin` 版 `aos-daemon`，impls 10-21 對齊；loop、fsm、daemon 10-21 下午與傍晚的改動 impls 10-21 晚也對齊；[N-28、N-54](../NORMS/04-基礎設施-loop與daemon.md)）。〔10-23 註：Python 版刪了（使用者「python版本可以刪掉了。aos-exec/loop/daemon都用C++」，fsm 也改 C++），現在只有 impls 的 C++ 版；本條講 bin 版的是當時的樣子〕

## tasks 組合子

實作：現無實作（舊的 `aos seq`／`par`／`if` 在 git 歷史 5546be29，10-19 刪），待照新做法重寫成資料夾程式。使用者 10-15：tasks 組合子「**地位等同於 C 語言的 stdlib**」。

- **C-41** 巢狀：list 的元素也是 list，求值時先對元素求值（畫家裡的畫筆 agent 先算）。（3g.11）比喻字眼 10-19 改用 table（C-71）：table 的元素也是 table。**10-19 晚使用者裁：元素要不要先求值，由 entry 決定**——原話「算元素？由entry指定，你看，lisp的quote就是那個功能。」像 lisp 的 quote：元素預設只是資料、不求值，entry 要算才算、要叫誰自己叫。所以「求值時先對元素求值」不是規則，是 entry 可以選的一種做法；跟 C-70（aos 不管巢狀、入口自己決定）、C-52（只管自己這一層）一致。（[ideas § 12](../thinking/2026-10-19-ideas.md)）

## fsm

使用者 10-15：「把 fsm 也跟 tasks 放一起」——fsm 是組合子、同為 stdlib 地位；[agent](05-agent.md) 是用 fsm 組出來的（一個定義資料夾，C-50）。規範：[NORMS 組合子 § fsm](../NORMS/07-基礎設施-組合子.md#fsm)（N-20、N-36、N-38、N-39、N-41）；慣例：[CONVENTION](../CONVENTION.md) P-07～P-10；實作：[aos-fsm](../impls/aos-fsm/README.md)。

- **C-18** agent 是狀態機、是函式、也是計算任務；直接接進核心，不特別處理。（2.13、2.14）〔10-22 註：這裡的「核心」＝名詞表的「系統本體」，不是 C-74 分層裡的核心 aos-exec〕
- **C-25** 大操作（問模型、跑久的工具）丟到另一個資料夾讓另一個行程處理；agent 自己每次 eval 短促。（9/19）10-16：aos 的 agent 每次被叫只走一次、由外面的 loop 驅動（C-62、[N-53](../NORMS/10-基礎設施-定義與工作區.md)；10-19 的做法是 P-07 一次一格）。
- **C-39** agent 是一個資料夾、一個 node、一條很長的 list（模型、context、工具、記憶……各占一個元素），持續被求值。最普通的 agent＝狀態機，在等待、思考、行動之間切換，需要思考就丟 LLM。（3f.7、3g.8、3g.9）「list」10-19 改用 table 比喻（[C-71](01-設計理念.md#資料夾程式與環境變數10-19-使用者定)）：各占一個元素、靠名字找，意思不變。
- **C-49** fsm 要很單純：「當現在是A狀態的時候，執行指定inst，就這樣，那個狀態內部、inst內部的東西，fsm不該管。」所以 fsm 只留表與記現在狀態的 state 檔；錯誤處理、計數、暫停、格之間傳資料都歸格自己或跑它的 loop。（10-15 收工後，[thinking 意見 1～4](../thinking/2026-10-15-opinions-1-4.md)；規範 N-36、N-38、N-39、N-41；慣例 P-07～P-10）

### stack 與工作區分開（10-16 夜，10-19 改）

出處：[稿 § 四](../thinking/2026-10-16-agent-inherit.md#四使用者決定10-16)（決定與原話）、[稿 § 八](../thinking/2026-10-16-agent-inherit.md#八工作區與-frame-分開10-16-夜重想ai-提案指標捷徑工具可直接-cwd-ws風險設計者自管已定)；10-19 在 [ideas § 2、§ 3、§ 9](../thinking/2026-10-19-ideas.md) 改成環境變數。規範 [N-55](../NORMS/10-基礎設施-定義與工作區.md)、慣例 P-14～P-18。

- **C-65** **stack 與工作區是兩個東西**：**stack**＝被叫的程式執行時才往裡放東西的地方——狀態、草稿、紀錄（`trace.jsonl`）、叫別的程式時開的小格；像函數跑起來的呼叫堆疊：每叫一次別的資料夾程式就給它一個小格（續聊＝同一個 stack 再跑，要忘記＝換一個）。**工作區**＝使用者的檔、成品要留的地方（`$AOS_WS`），像 C 的外部變數。程式起跑時 cwd 是它自己的資料夾（N-59）；**工作區只放交辦的東西與成果**（`new/`、`cur/`、`done/`、`out/` 這類，P-11、P-14；10-23 使用者選「改成一致的階段名」→ `new / cur / done`，原 `inbox/`；題目照 Maildir 原意 `new/`＝還沒做、`cur/`＝已認領處理中、`done/`＝做完，答案照舊放 `out/`），執行時的東西落在 stack。`AOS_STACK` 預設 `$AOS_WS/.stack/`（隱藏資料夾；使用者 10-19：「所以我們再設定一個AOS_STACK=ws/.aos/」，並裁定走今天的，[ideas § 9](../thinking/2026-10-19-ideas.md)；10-23 改名 `.stack/`，跟 `AOS_STACK` 同字，使用者 10-23 選）。（10-16 夜當晚先叫 frame，後改名 stack：使用者「不過frame那塊能不能換成stack(或heap)?。」→ 頂層推薦 stack、heap 留給以後跨呼叫共用的記憶 →「好！」使用者 10-16 夜原話：「我記得先前還有一個叫做frame的概念，也就是agent當函數，函數運行時候的heap(還是stack?反正就是運行時才會往其中放資料的)，可以指定某個資料夾當heap。用捷徑也不錯。然後我不喜歡/ws底下出現一個work/，這太突兀了，工作區會變得不乾淨。」——「用捷徑」那半 10-19 改成環境變數）
- **C-66** **影響外部＝透過指標，指標＝環境變數 `AOS_WS`**：像 C 函數要改外部變數得拿到指標，工具要動呼叫者的工作區，也是拿到一個指向工作區的東西，不是自己伸手出去；在 aos 裡這個指標就是環境變數 `AOS_WS`（N-55）。能不能寫由 Linux 權限管（C-64），風險由工具的設計者自己管控。（使用者 10-16 夜：「除此之外，C語言函數想要影響外部變數，那也是透過指標」；「對，我覺得這樣會更方便。風險就設計者自己管控」——當時的指標是捷徑、工具預設站工作區，10-19 改成環境變數 `AOS_WS`、起跑 cwd＝自己的資料夾）起跑 cwd 一律是程式自己的資料夾（N-59），要碰工作區就用 `$AOS_WS`。
- **C-67** **stack 放哪由呼叫方自由決定**：被叫的 agent 不知道也不必知道（C-52）；「stack 在哪」只是環境變數 `AOS_STACK` 的值，改值就得到不同效果，程式不動、規則一條都不用加——這是刻意保留的自由度。例（[稿 § 八 3b](../thinking/2026-10-16-agent-inherit.md#3b-frame-指到哪是呼叫方的自由概念層的一句)）：stack 指到工作區＝就地辦公（代價：執行時的東西全落進工作區、可能跟使用者的檔撞名）；兩個 agent 共用一個 stack＝共享記憶、接力（同時跑會互寫，P-18）；stack 放暫存目錄＝用完即丟（當機就沒了）；stack 長期保留＝下次接著聊（小格會一直堆）；stack 放在別人唯讀可看的地方＝旁人能審視、改不了（C-64）。代價都是呼叫方自己的選擇。（使用者 10-16 夜：「只是我們可以偷偷把它的frame設成ws」「我們可以自由管控他的frame要在哪裡，從而達到各種神奇效果」）
