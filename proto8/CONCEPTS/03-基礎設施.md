# 基礎設施

子主題：inst、loop、daemon、窗、命令列、指示詞與路徑、組合子（tasks、fsm）、定義與工作區（食譜與廚房，10-16）。窗、命令列、指示詞與路徑沒有專屬的概念條，只有規範（見上）。

## inst

實作：[lib inst.md](../lib/inst.md)。C-36 的層層遞進從 inst 起，條文放在下面 loop 與 daemon。

- **C-08** 計算任務＝一個 POSIX 行程，不是 thread；不必再往下分種類。（2.7）
- **C-34** 求值＝放開讓它算、過一段時間看狀態變化的結果；求值的定義就是空間狀態的變化。對資料夾求值＝執行這個資料夾；求值還回來的是一個正在變動的資料夾，不是一個值。（3h、3f.1、3f.3）
- **C-42b** inst 的 JSON 裡可以多放東西：九軸特性、traits、資源標籤、優先順序標籤、工具……inst 不認的別人可以讀。工具用 JSON schema 限制引數；schema 怎麼轉成 argv——走 schema→argv 這條路，或先定義一些通用的東西，沒定。（3g.13b）10-13：這個抽屜定名 `_metainfo`，見 [thinking 10-13 §3](../thinking/2026-10-13-json-path.md)。

## loop 與 daemon

實作：[lib loop.md](../lib/loop.md)、[lib daemon.md](../lib/daemon.md)。

> **daemon 兩義**：①[C-04](01-設計理念.md) 說的 daemon＝aos 與 Linux 之間的借階層（Linux 那邊的事全在這層）；②這裡的 daemon＝管一群 loop 的程式（`aos-daemon`，C-36）。[名詞表](附錄1-名詞.md)兩列都留。

- **C-36** 層層遞進：inst（求值一次）→ loop（持續求值）→ node（loop 服務的資料夾）→ daemon（統管 loop）；daemon 跑的 inst 可以是另一個 daemon。（3f.2）10-12 夜落實：inst＝`aos_inst.py x.json` 跑一次；loop＝`aos_loop.py x.json` 包一個 inst、跑 times 次後退出，用一個 ctl.json 控制（N-06～N-08）；daemon＝`aos_daemon.py x.json`，表上每個 loop 是子程序、用控制資料夾下指令（N-10），自己也是一個 loop。**10-16 改**：控制資料夾（N-10）整套刪，daemon 表上有誰改由它 ctl 的 `children` 宣告（[N-54](../NORMS/04-基礎設施-loop與daemon.md)，使用者「不留」，實作待改）。

## tasks 組合子

實作：[lib README](../lib/README.md)（`aos seq`／`par`／`if`；10-15 深夜從 proto8-1 併進 proto8/lib，aos-not 刪）。使用者 10-15：tasks 組合子「**地位等同於 C 語言的 stdlib**」。

- **C-41** 巢狀：list 的元素也是 list，求值時先對元素求值（畫家裡的畫筆 agent 先算）。（3g.11）

## fsm

使用者 10-15：「把 fsm 也跟 tasks 放一起」——fsm 是組合子、同為 stdlib 地位；[agent](05-agent.md) 是用 fsm 組出來的（一個定義資料夾，C-50）。規範：[NORMS 組合子 § fsm](../NORMS/07-基礎設施-組合子.md#fsm)（N-20、N-36～N-41）；實作：[lib fsm.md](../lib/fsm.md)（10-15 基礎實作）。

- **C-18** agent 是狀態機、是函式、也是計算任務；直接接進核心，不特別處理。（2.13、2.14）
- **C-25** 大操作（問模型、跑久的工具）丟到另一個資料夾讓另一個行程處理；agent 自己每次 eval 短促。（9/19）10-16：aos 的 agent 每次被叫只走一拍、由外面的 loop 驅動（C-62、[N-53](../NORMS/10-基礎設施-定義與工作區.md)）。
- **C-39** agent 是一個資料夾、一個 node、一條很長的 list（模型、context、工具、記憶……各占一個元素），持續被求值。最普通的 agent＝狀態機，在等待、思考、行動之間切換，需要思考就丟 LLM。（3f.7、3g.8、3g.9）
- **C-49** fsm 要很單純：「當現在是A狀態的時候，執行指定inst，就這樣，那個狀態內部、inst內部的東西，fsm不該管。」所以 fsm 只留表、`end` 與記現在狀態的 state 窗；錯誤處理、計數、暫停、格之間傳資料都歸格自己或拍它的 loop。（10-15 收工後，[thinking 意見 1～4](../thinking/2026-10-15-opinions-1-4.md)；規範 N-36～N-40）

## 定義與工作區（食譜與廚房，10-16）

規範：[NORMS 定義與工作區](../NORMS/10-基礎設施-定義與工作區.md)（N-46～N-51，草稿）；實作：**程式還沒改**（現在沒有 `aos exec`、沒有 `.aos` 捷徑，agent 還是 frame＋args.json／ret.json，見 [lib agent.md](../lib/agent.md)）。

> 用詞（C-54）：「食譜」「廚房」是討論時的比喻；正式名詞是**定義**（食譜，一個 `.aos/` 資料夾）與**工作區**（廚房，跑的時候的 cwd；命令列寫 `WD`）。「門房」＝`aos exec`。見[名詞表](附錄1-名詞.md)。

- **C-57** **正規參數入口是 stdin**；`aos agent 路徑`、`aos exec WD TARGET` 這類 argv 寫法都是**語法糖**（接 N-12：stdin＝參數）。（使用者 10-16：「argv:[aos,agent,agents/brush]，其實，我一直覺得argv這塊的用法...就像我早期說的，正規參數入口就是stdin，像是aos-exec WD TARGET這個用法是語法糖...」，[稿 § 四](../thinking/2026-10-16-agent-inherit.md#四使用者決定10-16)）
- **C-59** **定義與工作區的接法＝捷徑**：定義（食譜）是一個 `.aos/` 資料夾；工作區（廚房）裡放一條叫 `.aos` 的捷徑（symlink）指向那個 `.aos/`；定義裡的檔互相指一律寫 `.aos/x`——從工作區（cwd）算，**沒有第二種路徑規則**，誰站在工作區誰就找得到。不靠 `$ref`、不寫絕對路徑、不編譯、不藏暗規則，靠檔案系統本來就有的捷徑自然組合（像 Plan 9 的 bind，C-30）。工作區就是那個 node（C-36、C-39），`.aos/` 是它的定義。（使用者 10-16 夜：「哇，可是我不想用 `$ref`……我也不想用絕對路徑。我也不想要用小工具編譯，我想要依靠機制自然組合。我也不想用暗規則……」→ 選捷徑：「捷徑。這塊細說」→「太優雅，太美了，這就是我要的。」，[稿 § 四](../thinking/2026-10-16-agent-inherit.md#四使用者決定10-16)）
- **C-60** **推廣到所有東西**：任何「可重複用的定義＋這次在哪做」——一支工作（inst）、一條 tasks 流水線、一個 loop、daemon 的子項、kernel 的判官、agent——都是「定義 `.aos/`＋工作區 cwd」，一律 **`aos exec 工作區 定義`**（門房：站進工作區、沒掛就把定義掛成工作區的 `.aos`、跑 `.aos/inst.json`）。定義裡可以放一個 shebang stub（第一行寫「用 `aos exec` 跑我」），讓人在終端把定義當指令打；**體系內部不靠 PATH**（C-61），PATH 只留給人。（使用者 10-16 夜：「何等美麗的閉環，這就像是lisp的repl，/ws就是那個啥...」「前兩項我都OK」，[稿 § 四](../thinking/2026-10-16-agent-inherit.md#四使用者決定10-16)）
