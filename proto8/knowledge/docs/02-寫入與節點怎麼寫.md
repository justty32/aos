## 節點怎麼寫（給人改內容時看）

- 一段文字＝一個 JSON 字串（Markdown 也是字串，`\n` 是換行）；放成一份 `x.json`，或放成某個物件的一個鍵。幾段相關的併成一份物件檔，自己帶 `_index`；大一點的就開資料夾、帶 `_index.json`。
- 每新增一個節點，就在它上一層的 index 加一格 `"名字": {"description": "…"}`，description 寫**英文一句話**；資料夾的 `_index.json` 要列出夾裡每一個東西（`_description.json`、`README.md`、`docs` 也列）。資料夾自己的正文放同夾的 `_description.json`、物件自己的正文放它的 `_description` 鍵。名字只用 `[a-z0-9_-]`（檔名加 `.json`）；`.`、`_` 開頭的保留（`_index.json`、`_index`、`_description.json`、`_description` 例外）。
- 寫給小模型：短句、具體的呼叫例子、一致用詞、**建議一段文字（一個字串值）約 1 KB、一個檔約 8 KB**（11-11 使用者改：「這個"不超過2kb"我沒說過，拿掉。不過也可以用，我的建議是改成一個檔案不超過8kb，一段不超過1kb。」「那個知識庫上限，只是推薦，不要訂死。」）；撐大就拆成物件的幾個鍵或幾個檔、上層只留說明。陣列只讀（`#/items/0`），要穩定的名字就用物件。拆檔搬走時要留路，在原位放 `{"$ref": "新檔.json"}` 指過去（`aos-json ref --move` 一步做完）。
- 內容語言英文（AI 讀）；本說明（knowledge 的 README 與 docs）與各庫的人用說明繁中。**11-07 改讀**：「內容語言英文」管的是出廠的 `knowledge/aos`；從外部語料收進來的庫，節點名英文、內文照語料原文存（見 [CONCEPTS C-42 續「知識庫存什麼、給人看什麼」](../../docs/CONCEPTS/05-agent/01-續-C-42.md)）。（11-07 使用者裁定，傍晚選項框 ltn-7 選推薦，[lift-to-norms](../../thinking/2026-11/07/lift-to-norms/README.md)）
