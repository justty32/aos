## 寫入

要讓 agent 寫自己的庫，另配 [knowledge_write](../../lib/agent/knowledge_write/)；它沿用同一套找根，另外多收呼叫參數 `root`（排在 `--root` 之後、`_knowledge.json` 之前；相對從工作區 `$AOS_WS` 算；11-11）：`add` 新增（帶 `value` 與 `description`，內容與表裡那格一次寫好；路徑以 `/` 結尾＝開資料夾；不給 `value`＝只替已在的檔或 key 補表裡那格、內容不動，不在＝`NodeMissing`、帶 `"create": true` 才建空的〔使用者 11-10 深夜〕）、`set` 換內容（可一起換說明）、`rm` 刪掉並拔掉表裡那格（不空的資料夾要 `recursive: true`；根＝`PathBad`）。agent 不自己改 `_index.json`。**寫入不限範圍**：`../`、絕對路徑、捷徑、掛進來的別庫，指到哪就寫到哪，作業系統不讓寫＝`WriteFailed`（使用者 11-10「寫入這個沒差，想怎麽寫就怎麼寫，有權限就能動」）。自己的簡介（資料夾的 `_description.json`、物件的 `_description` key）就當普通路徑用 `add`／`set`／`rm` 寫：`value` 是一個字串、不給 `description`、不進表；`add` 資料夾時給的 `description` 寫進上一層的表，不自動建 `_description.json`。兩份 agent 範本預設登記 `knowledge_read` 與 `knowledge_write`（11-10 深夜 tool-packs）；`knowledge_read` 那格 `env.AOS_KNOWLEDGE` 指 `{"$env": "AOS_HOME", "$path": "/knowledge"}`＝出廠的這一層（使用者「指knowledge/」）。原本 `knowledge_write` 那格也指這裡（照範本跑的 agent 寫了就改到 repo 的 `knowledge/`）；**11-11 拿掉**（使用者「不給預設，要自己透過旗標指定或環境變數設定，或是工具呼叫內給。如果都沒有，那就報錯。」）：寫的庫要嘛腦在呼叫裡給 `root`，要嘛人替那格配 `env.AOS_KNOWLEDGE`（相對、絕對或 `{"$env": "MY_KNOWLEDGE"}`；在定義的 `tools.json` 補一格 `"knowledge_write": {"env": {"AOS_KNOWLEDGE": …}}`，或對跑著的那隻 `aos-agent tools add --replace -n knowledge_write --envs AOS_KNOWLEDGE=/x/kb "$AOS_HOME/lib/agent/knowledge_write"`），都沒有＝`KnowledgeMissing`。寫入指引在 `aos/knowledge.json`。

**沒有鎖**：兩邊同時寫同一份檔＝後寫的蓋掉先寫的（使用者 11-10「不管，自行承擔風險」）。剩下的保證只有 aos-json 的：每份檔暫存成 `.名字.<pid>.tmp` 再原子 rename，不會寫出半份檔（非 `.json` 檔由 knowledge_write 暫存成 `.tmp.*` 再換）。新增要動兩份檔（內容＋表），中途死掉＝留下一個沒登記的檔，ls 的 `not in index:` 看得到。

**掛出廠庫要由人設成唯讀**（11-07 晚審裁定 7 選推薦，[晚審 04](../../../wf/workflows/refactor/reports/2026-11-07-晚審/04b-要使用者裁定-續.md)）：跑 agent 的通常就是 repo 主人，「沒權限＝唯讀」不成立；`knowledge_write` 的庫若直接就是 `knowledge/aos`，會真的改到 repo、污染每隻 agent 的 system prompt。所以要給 agent 寫的庫不要指到 `knowledge/aos`，要共用就由人先設唯讀（`chmod -R a-w` 那份，或掛一份唯讀副本）。（11-10 深夜註：使用者改定範本預設就指 `knowledge/`、讀寫同一處，見上段；要擋就照這段由人設唯讀，或改指自己的資料夾。11-11 註：範本的 `knowledge_write` 不再指出廠庫，見上段；人自己替它配到出廠庫時這段照舊適用。）

庫在 git 下時，`.gitignore` 加 `.*.tmp`、`.tmp.*`，不要把暫存檔當知識提交。

## 節點怎麼寫（給人改內容時看）

- 一段文字＝一個 JSON 字串（Markdown 也是字串，`\n` 是換行）；放成一份 `x.json`，或放成某個物件的一個 key。幾段相關的併成一份物件檔，自己帶 `_index`；大一點的就開資料夾、帶 `_index.json`。
- 每新增一個位置，就在它所在那張表加一格，`_description` 寫**一句話**（ls／read 的目錄印這句）；資料夾自己的簡介放同資料夾的 `_description.json`、物件自己的簡介放它的 `_description` key。名字只用 `[a-z0-9_-]`（檔名加 `.json`）；`.`、`_` 開頭的保留（`_description.json`、`_description` 例外）。
- 寫給小模型：短句、具體的呼叫例子、一致用詞、**建議一段文字（一個字串值）約 1 KB、一個檔約 8 KB**（11-11 使用者改：「這個"不超過2kb"我沒說過，拿掉。不過也可以用，我的建議是改成一個檔案不超過8kb，一段不超過1kb。」「那個知識庫上限，只是推薦，不要訂死。」）；撐大就拆成物件的幾個 key 或幾個檔、上層只留說明。陣列只讀（`#/items/0`），要穩定的名字就用物件。拆檔搬走時要留路，在原位放一格 `$ref` 指過去。
- 內容語言英文（AI 讀）；本說明（knowledge 的 README 與 docs）與各庫的人用說明繁中。**11-07 改讀**：「內容語言英文」管的是出廠的 `knowledge/aos`；從外部語料收進來的庫，節點名英文、內文照語料原文存（見 [CONCEPTS C-42 續「知識庫存什麼、給人看什麼」](../../docs/CONCEPTS/05-agent/01-續-C-42.md)）。（11-07 使用者裁定，傍晚選項框 ltn-7 選推薦，[lift-to-norms](../../thinking/2026-11/07/lift-to-norms/README.md)）
