## 11-21 起：長文章的頁是 `.md`，短資料的頁留 `.json`

使用者 11-21 晚：「仍然以.md爲主體，然後index做導航骨架，這樣git diff也比較舒服，AI改起來，或許也會比較舒服」「x.md旁邊有x.json？……不要這樣，就是一個x.md就好了」「如果是短文字，那就留json沒關係，.md和.json各有各的優勢」「判準這塊不用定的太死，就參考用」。規劃、原話全文與施工紀錄在 [thinking 11-21 知識庫-骨架加md-規劃](../../thinking/2026-11/21/知識庫-骨架加md-規劃-1121/README.md)。[01](01-樹長怎樣與多庫.md)、[02](02-寫入與節點怎麼寫.md) 裡以 json 為例的段落講的規矩照舊適用在留 json 的頁；跟本檔對不上的地方以本檔為準。

- **一頁只會是一種**：`me.md` 或 `me.json`，不會兩份並排。文章一篇接一篇放在同一份 md，每篇用自己的 `#` 標題開頭，**不加任何標記**。
- **新寫的頁預設寫 `.md`**，再用夾的 `_index.json` 當骨架；要用 `.md` 還是 `.json` 都可以（使用者 11-21 晚「以後我覺得可以是新寫的就預設寫.md，然後再去用index json做骨架，當然，具體要用.md還是.json都可以」）。參考用、不檢查：文章與流程寫 md；短欄位、記錄表、給程式讀的設定可以寫 json（現在留 json 的例：`aos/packs.md`）。`wf/` 庫原本是資料形狀的 38 頁 11-21 也換成 md 了：鍵變標題、短字串物件變 `鍵: 值` 清單、字串陣列變清單、記錄陣列變編號小節、只適合當資料的（空殼 `skeleton`、數字）留 ```` ```json ```` 區塊。
- **導航骨架是夾的 `_index.json`**，鍵是檔名（`"me.md": {"description": "…"}`）。一份 md 裡有哪幾節不必另外寫表：`json_ls aos/me.md` 列出它的標題。

## `檔.md#/…` 怎麼尋（只靠 md 本來就有的東西；`json_get`、`json_ls`、`aos-json` 都吃）

| 寫法 | 拿到 |
|---|---|
| `x.md` | 整份文字 |
| `x.md#/標題字` | 那一節：標題那一行、它的字、底下的小節。整份第一個同字的標題，不管幾個 `#`；完全一樣優先，不然不分大小寫（只對英文字母） |
| `x.md#/大節/小節` | 指明上層 |
| `x.md#/標題/_`、`x.md#/_` | 只屬於那個標題的字（不含標題行與小節）；檔案最上面、第一個標題之前的字 |
| `x.md#/標題/0`、`/0/1` | 那個標題自己的字裡第一個清單的第 0 項；子清單的第 1 項 |
| `x.md#/標題/鍵` | 清單項寫成 `鍵: 值` 時用鍵拿值 |
| `x.md#/標題/2/0` | 沒有清單時，第一張表的第 2 列第 0 欄（表頭是第 0 列；格子一律字串） |
| `x.md#/標題/鍵/0` | 那個標題底下只有一個 ```` ```json ```` 區塊時，那一節就是那份 json，照 json 往下尋 |

同一段的找法順序：`_` › 標題 › 數字 › 清單的鍵。標題裡的 `/` 寫 `~1`。json 工具只讀 md、不寫 md：改文章用 `edit`／`write`。給 agent 看的英文版在 `aos/tools/json_get.md#/JSON tools: reading markdown`。

## 寫 md 頁的人要知道的

- **標題就是路徑**。改一個標題字，別頁寫的 「某頁.md#/舊標題」這種路徑 就尋不到（會報錯，訊息列出現有標題）。改標題前先 `grep` 誰指過來；`proto8/py/tests/test_knowledge_paths.py` 會掃整庫。
- 要穩定的名字用標題，不要用清單第幾項（中間插一項，後面的號碼全變）。
- 同一份 md 兩個標題一樣只尋得到第一個；叫 `_` 的標題尋不到（保留名）。
- 一句話的頁簡介放在最上面、第一個標題之前。
- 建議大小照舊：一份約 8 KB、一篇約 1 KB，撐大就把幾篇搬到另一份 md。

## index 的新寫法（11-21）

- **不必列出夾裡每一個東西**（使用者：「誰說index格式要列出所有東西了？……這個規則刪掉」）；index 是視角，可以只列一部分。
- 一項可以是 `{"description": "…"}`，也可以直接是一句話的純字串（等同 description）；要指到別處用 `{"$ref": "路徑"}`。
- 二次導航：一項的 `index` 欄可以是任何一條 `檔#/路徑`，只要最後讀出來是 index 格式（一個 json 物件；指進 md 也行：只有 json 區塊的節，或 `名字: 一句話` 的清單）。例：`{"me.md": {"description": "…", "index": "me.index.json"}}`。
- 夾的 `_index.json` 是骨架；某一項的 description 太長時，可以把長的說明寫在 `_index.md`（或別的 md）裡，在 `_index.json` 那一項用 `{"$ref": "路徑"}` 指過去（使用者 11-21 晚：「如果是description太大段，那可以用_index.md做補充，用ref指過去」）。
- 夾**沒有** `_index.json` 時才看 `_index.md`（整份一個清單，一項 `名字: 一句話`）。
- 一份 md 自己的 index：標題 `# index`（或 `# _index`，兩個都有時後者贏）底下一個同樣的清單；自己的一句話可以放 `# description`（或 `# _description`）。寫不寫都隨意，小的頁不用寫。
- `$ref` 可以指到 md（`{"$ref": "x.md#/標題"}`）；知識庫自己不用，設定檔可以用。

檢查：`python3 wf/tools/index_check.py proto8/knowledge`（查什麼見 thinking 那夾的 `10-index_check.md`）。
