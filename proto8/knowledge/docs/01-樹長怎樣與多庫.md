## 樹長怎樣

根是 `knowledge/` 這一層：`aos/`（先讀）、`_description.json`、給人看的 `README.md` 與 `docs/`，所以路徑寫 `aos/rules.json`、`aos/errors.json#/codes`。下面是 `aos/` 裡面的樣子：

```text
knowledge/aos/
├─ _index.json            ← 這個資料夾的 index（整個檔就是表，列出夾裡每一個東西；夾裡東西多才有）
├─ _description.json      ← 這個資料夾自己的正文（一個 JSON 字串，或字串陣列）
├─ rules.json             ← 一個檔＝一個 JSON 值（這份是一段文字）
├─ errors.json            ← 一個物件：_description（正文）與幾段內容；夠小，沒有 _index
├─ packs.json             ← 一個物件，頂層鍵多，所以有 _index（index）
└─ cli/
   ├─ _index.json
   ├─ _description.json
   └─ flags.json
```

- **統一路徑**＝`資料夾/檔.json#/JSON Pointer`（RFC 6901：`/` 分段、`~1`＝`/`、`~0`＝`~`），檔名**帶副檔名**：`aos/rules.json`、`aos/errors.json#/codes`、`aos/cli/flags.json`（使用者 11-10「可以用xxx/xxx.json#/xxx/xxx，這個單一路徑取得東西」）。`aos-json get` 直接吃這種路徑；腦用的 `json_get`／`json_ls` 也吃同一串（`path`＝`檔#/指標`）。
- **資料夾的 index＝`_index.json`**：`{"rules.json": {"description": "…"}, "cli": {"description": "…"}}`，鍵是夾裡的名字（子資料夾不帶尾斜線），列出每一個檔與子資料夾，`_index.json` 自己除外。**JSON 物件的 index＝`_index` 鍵**：`{"_index": {"codes": {"description": "…"}}, "codes": "# Code endings …"}`，鍵是同一個物件的其他鍵。index 也可以寫在 `_metainfo` 裡（資料夾 `_metainfo.json` 的 `index` 鍵、JSON 物件的 `_metainfo.index`）：`index_view` 先讀它、再疊上獨立的 `_index.json`／`_index`，同名項以獨立那份為準；這棵樹現有的都放外面、不搬（[N-69](../../docs/NORMS/10-基礎設施-定義與工作區/11-N-69.md) 11-12 補）。
- **只給太大的補**（使用者 11-12「如果有些東西太大，那就補index.json/_index。如果夠小，那其實也不用做看法了，直接讀就是了。」）：資料夾裡超過 15 個東西才放 `_index.json`（現在是 `aos/`、`aos/cli/`、`aos/tools/`）；一個 json 檔超過 8000 bytes（`json_get` 預設上限）或頂層內容鍵超過 10 個才放 `_index`（現在只有 `aos/packs.json`）。放進檔內會弄壞讀它的程式時，改放同夾的 `_index.json`、鍵寫 `檔名#/鍵`。
- 每一格有 `description`：英文一句話，說那個節點是什麼（字串；寫成字串陣列 `index_view` 也認，接成一行印）；一格裡想再放別的鍵都可以（使用者 11-12 晚「_index的obj內要不要再多塞東西...可以，想塞啥塞啥，出事了自己負責。」；`index_view` 只讀 `description` 與 `index`，其他鍵不讀、不印）；可以再放 **`index`**（選填）：值必須是字串、必須是路徑，指向另一份 `_index.json` 或檔內的 `_index`（寫法同統一路徑：`cli/_index.json`、`packs.json#/_index`）。**JSON 物件的 `_index` 鍵本身也可以是這種路徑字串**（不寫表、指到別處那份）；資料夾的 `_index.json` 整份仍是表。兩種路徑的相對路徑都**從裝著那份 index 的容器算**：`_index.json` 從它所在的資料夾；檔內 `_index` 從裝著它的那個 JSON 物件，把物件當成資料夾——名字＝往下一個 key、`..`＝外層物件，根物件就是這個檔、它的 `..`＝檔案所在的資料夾；要進別的檔得先走回檔案系統那邊再寫 `檔#/指標`。`#/` 開頭不算相對：從這份 index 所在的那個 json 檔的根算起，跟寫在多深無關（`_index.json`、`_metainfo.json` 本身就是那個檔；同 N-45 `{"$ref": "#/a/b"}`；使用者 11-12 晚「也跟進吧」）；`#` 之後的算法跟 `$ref` 同一套，`..` 往外一層、走出根物件就是檔所在的資料夾（`#/../x.json#/_index`）。例：`aos/packs.json` 根物件的 `_index` 裡寫 `look/_index`＝`aos/packs.json#/look/_index`、寫 `../cli/_index.json`＝`aos/cli/_index.json`；絕對路徑照用；`index_view` 只顯示這條路徑、不跟著往下讀（使用者 11-12 晚「除了description之外，還可以放index，值必須是字串，必須是路徑，指向另一個_index或_index.json。」「json object內的_index這個key……我希望能支援字串，同樣也是路徑，必須指向另一個_index, _index.json。　　不跟着往下走。路徑相對...以_index, _index.json的位置爲準。」「這個要用json與檔案系統的同像性去想。如果是在json物件內的，某key的_index，那他就從這個json物件開始算(把這個json物件當成資料夾)。然後如果這個json物件是這個.json檔案的根，那他就等同於這個檔案。」，[thinking index-link](../../thinking/2026-11/12/index-link.md)）。想了解某個節點，就看它上一層的 index（使用者 11-12「在沒有指定位置的時候，agent如果想要了解某個節點的狀況，就會去看其上方節點的index」）；上一層沒有 index＝夠小，直接讀。沒列到的節點就不管。這裡放的都是天然位置的 index，是通用視角（公用視角）（使用者 11-12 晚「客觀那個你不管怎麼描述無法描述全，所以能被我們記錄下來的，非私有的，全都是通用視角(公用視角)(自己公開給別人的聲稱)。」）；agent 自己私有的看法（主觀、cache）放哪不規定。
- **節點自己的正文**：資料夾＝同夾的 `_description.json`（一個 JSON 字串）；JSON 物件＝它的 `_description` 鍵（字串，跟 `_index` 並排）。兩處都是一段文字，也可以寫成字串陣列（一行一個元素；多行長文字推薦、不強制，見 [02](02-寫入與節點怎麼寫.md)；使用者 11-13）；這棵樹現有的都是一個字串、不改。它是節點本身的內容，不是 index；只放外面，不寫進 `_metainfo`（[N-69](../../docs/NORMS/10-基礎設施-定義與工作區/11-N-69.md)）；`aos/_description.json` 就是「aos in one page」。
- **`$ref`**：大段內容拆到別檔時，原位放 `{"$ref": "me/self_tools.json"}`（相對路徑從所在檔的資料夾算；只寫 `#/指標`＝所在檔自己的那個位置；`#` 後的 `..` 往外一層，走出根物件就是檔所在的資料夾：`#/../other.json`＝隔壁那份檔；再加 `"$at": "a/b"`＝從指到的地方接著往下走，`$at` 裡不能寫 `#`；N-45）。`aos-json get` 預設不跟、要加 `--follow`；`json_get` 照實印出 `{"$ref": …}`，要再自己去讀那個檔。

```sh
# 從 proto8/
aos-json get knowledge/aos/me.json#/self_tools                       # {"$ref": "me/self_tools.json"}
aos-json get --follow --str knowledge/aos/me.json#/self_tools/add    # self_tools 檔裡 add 那一段文字
```

## 多庫

多庫＝多棵資料夾樹。要另一棵就複製一份或另開一個資料夾，把路徑告訴 agent 即可；不登記、沒有掛載設定（使用者 11-05「隨意複製，隨意修改，隨意給agent指定、隨意拆卸增添」）。
