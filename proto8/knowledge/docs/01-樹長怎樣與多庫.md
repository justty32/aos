## 樹長怎樣

根是 `knowledge/` 這一層：`knowledge/_index.json` 列 `aos`（先讀）、`_description.json` 與給人看的 `README.md`、`docs`，所以路徑寫 `aos/rules.json`、`aos/errors.json#/codes`。下面是 `aos/` 裡面的樣子：

```text
knowledge/aos/
├─ _index.json            ← 這個資料夾的 index（整個檔就是表，列出夾裡每一個東西）
├─ _description.json      ← 這個資料夾自己的正文（一個 JSON 字串）
├─ rules.json             ← 一個檔＝一個 JSON 值（這份是一段文字）
├─ errors.json            ← 一個物件，裡面有 _index（index）與 _description（正文）兩個鍵
└─ cli/
   ├─ _index.json
   ├─ _description.json
   └─ flags.json
```

- **統一路徑**＝`資料夾/檔.json#/JSON Pointer`（RFC 6901：`/` 分段、`~1`＝`/`、`~0`＝`~`），檔名**帶副檔名**：`aos/rules.json`、`aos/errors.json#/codes`、`aos/cli/flags.json`（使用者 11-10「可以用xxx/xxx.json#/xxx/xxx，這個單一路徑取得東西」）。`aos-json get` 直接吃這種路徑；腦用的 `json_get`／`json_ls` 也吃同一串（`path`＝`檔#/指標`）。
- **資料夾的 index＝`_index.json`**：`{"rules.json": {"description": "…"}, "cli": {"description": "…"}}`，鍵是夾裡的名字（子資料夾不帶尾斜線），列出每一個檔與子資料夾，`_index.json` 自己除外。**JSON 物件的 index＝`_index` 鍵**：`{"_index": {"codes": {"description": "…"}}, "codes": "# Code endings …"}`，鍵是同一個物件的其他鍵。
- 每一格目前只有 `description`：英文一句話，說那個節點是什麼。想了解某個節點，就看它上一層的 index（使用者 11-12「在沒有指定位置的時候，agent如果想要了解某個節點的狀況，就會去看其上方節點的index」）。最頂層沒有上一層的 index；沒列到的節點就不管。這裡放的都是客觀 index（使用者 11-12「放在天然位置的index，其實會是所謂的客觀index，而agent自己存的則是主觀」）；主觀 index 放哪、格裡還要加什麼，之後再定。
- **節點自己的正文**：資料夾＝同夾的 `_description.json`（一個 JSON 字串）；JSON 物件＝它的 `_description` 鍵（字串，跟 `_index` 並排）。它是節點本身的內容，不是 index；`aos/_description.json` 就是「aos in one page」。
- **`$ref`**：大段內容拆到別檔時，原位放 `{"$ref": "me/self_tools.json"}`（相對路徑從所在檔的資料夾算）。`aos-json get` 預設不跟、要加 `--follow`；`json_get` 照實印出 `{"$ref": …}`，要再自己去讀那個檔。

```sh
# 從 proto8/
aos-json get knowledge/aos/me.json#/self_tools                       # {"$ref": "me/self_tools.json"}
aos-json get --follow knowledge/aos/me.json#/self_tools/_index/add   # {"description": "self_tools add: every option ..."}
```

## 多庫

多庫＝多棵資料夾樹。要另一棵就複製一份或另開一個資料夾，把路徑告訴 agent 即可；不登記、沒有掛載設定（使用者 11-05「隨意複製，隨意修改，隨意給agent指定、隨意拆卸增添」）。
