# 排程與資源 module

← [node 樹與資源](README.md)

## S-201．ready／due 的權威與讀取

〔使用者方向 2026-09-29〕每個 kernel 用自己的狀態檔保存直接成員的必要摘要：是否有事可做（ready）、下次到期時間（due）。收件檔與狀態檔是依據，由 kernel 的 tick 更新摘要並決定叫醒誰；上層只看下層 `.aos/summary/` 提供的摘要，不讀它的成員內容。

冷成員沒有新事件或到期工作就不反覆開空 tick。等待工具／LLM 結果也不占住 tick；有結果再叫醒。run 是軟性原則，不以「目前 run 還沒結束」一律排除新訊息。收到新件與本格轉 idle 交錯時，下一次核對仍須看見尚未處理的收件，不能拿舊摘要蓋掉新件。

驗收：等待結果時不反覆空跑；轉 idle 同時到件，通知或 S-202 補查仍能讓它再前進。

## S-202．通知與補查

〔使用者方向 2026-09-29〕通知只是提示；即使通知丟失，收件檔仍在，所屬 kernel 可補查。投件權限、發布與去重依 [傳遞](../base/transport.md)，收件消費依 [tick](../tick.md)。

〔建議預設，未拍板〕正常只處理被通知及已到期的成員；啟動、通知溢出或發現不一致時，分批核對自己的登記、收件與成員摘要。另做低頻補查，避免遺失通知使工作永遠睡著；例如每 60 秒一批、每批最多 64 個成員，數值可調，不要求每輪全掃或解碼所有 history。daemon 只負責登記與開程序，不代做內容補查。

驗收：收件後丟掉通知，補查仍會找到工作；無事成員不因補查而全部啟動。

## S-203．逐層分配與資源 module

〔使用者方向 2026-09-29〕資源由父 kernel 分給子層，子層只能在已分得的範圍內再分。CPU、記憶體、pids、LLM、磁碟記帳及網路以相同方式註冊成資源 module；裝哪些由各 kernel 決定，沒有所有部署必填的一組全域上限。**沒裝 module，就不在該層另記／另限；已生效的父層限制照舊。**

CPU、記憶體與 pids 等 OS 限制由已啟用 module 配合 cgroup 落實，cgroup 子樹對上 node 的資源分配層級；磁碟額度可選且只記帳，見 [身分與 OS 資源](../base/identity-resources.md)。LLM module 的份額與池端限制見 [LLM](llm.md)。同一 node 的 tick 互斥依 [tick](../tick.md)，不是可關掉的資源 module。

〔建議預設，未拍板〕kernel 可依已裝 module 的可用量決定並行數與等候工作；只需保存本層分配及使用的必要摘要，不做全樹一次占齊各種資源的交易。程序還沒清乾淨，就不能因標成 unknown 而把實際占用當作已釋放；遠端用量不明依 [S-304](llm.md) 保留。

〔使用者方向 2026-09-29 晚〕LLM 的預算首版只算 token，算錢的價格表是可選的人手維護檔，見 [S-302](llm.md)。〔使用者方向 2026-09-29 晚，第十五批〕token 預算先不做。

已啟用額度不足時，可等待或留下待處理事項，不忙跑、不丟結果；取消入口保持可用。若採用 run，可取消收尾；修好或加額後 resume 重新驗證是可選出口，依 [S-102](runs.md)。容量不足而不能接件時要明確回報，不能先說已接收再靜默丟掉；滿碟處理依 [儲存](../base/storage.md)。

驗收：下層未裝某 module，不新增該層限制，但不能越過父層已施加的上限；父層份額用完時等待，尚存活的 unknown 工作仍算實際占用。

## S-204．可預測的簡單公平

〔使用者方向 2026-09-29〕排隊先後用所屬 kernel 配發的持久遞增序號，放在狀態檔或檔名；重啟不倒退，不靠牆鐘，也不要求全樹共用一個序號。到期時間與等待時長不拿來替代序號排序，時間規則見 [共用契約](../contracts.md)。

〔建議預設，未拍板〕各 kernel 可選自己的公平政策，例如成員輪流、每輪一件，或設一般／互動優先級並在等候 60 秒後提高機會。額度不足者先略過，但保留排隊位置，不阻擋其他可跑的工作。調低額度不等於取消已有工作；等使用量回落再派，調高仍受父層限制。

驗收：牆鐘跳動不改變同一 kernel 的排隊先後；一個成員缺額度，其他有額度的成員仍可前進。
