# 可選的任務輪次與重試

← [node 樹與資源](README.md)｜[共用契約](../contracts.md)

〔使用者方向 2026-09-29〕run 是替一輪任務分組的軟性原則，不是 kernel 必須採用的工作模型。任務途中新訊息歸哪一輪仍未定案。狀態放在所屬 node 的普通檔案，提交與恢復統一依 [tick](../tick.md)。

## S-101．接件與輪次

〔建議預設，未拍板〕若 agent 要用 run，可以「一則輸入一個 run，按序號先來先做，普通新訊息排後面」作起點；這是可替換例子。

〔使用者方向 2026-09-29〕node 不必先建立人可見的 run 才能做事；註冊任務使用工具與 LLM 的送出、收結果順序見 [tick](../tick.md)。設定何時生效與怎麼修改，統一見 [A-102](../agent/configuration.md)。

驗收：不用 run 的 kernel 仍能收件、派工與收結果。

## S-102．Run 合法轉移

〔建議預設，未拍板〕若採用 run，暫停、取消與恢復只需留下必要的本地狀態，隨 group commit：

- 暫停：停止替該 run 派新工作；已送出的結果仍接收，不能把暫停當成已殺掉程序。
- 取消：保存取消要求、停止派新工作並要求收尾。取消 once 的核權與做法以 [B-203](../base/execution.md) 為正本，收尾見 [B-604](../daemon.md)；程序尚未清空，不能宣稱取消完成。結果不明依 [S-401](operations.md) 放著。
- 恢復：接著已保存的進度做，不重做已確認完成的副作用；不自動清除取消要求，也不把 unknown 當成可重試。

已提交的暫停或取消要求不因重啟消失。程序是否清空依 [daemon](../daemon.md) 與 runner 的事實判斷；agent 閒著或 tick 結束，都不是任務成功的證據。

〔使用者方向 2026-09-29〕設定錯誤、資料缺失、容量或已啟用額度不足等問題修好後，**resume 重新驗證是可選出口**。提供時，須先確認阻擋原因已消除，才接續保存的進度；未解除就保持待處理。也可只提供取消，明說不支援 resume。unknown 與未解除的取消要求不能走這個出口。重要設定的編輯與恢復依 [A-102](../agent/configuration.md)，不要把暫停 run 誤當成暫停該 node 的 tick。

驗收：工具未停只顯示取消中，重啟仍保留要求；額度補足後驗證才續做，未實作 resume 仍可取消。

## S-104．Job、attempt 與 retry

〔使用者方向 2026-09-29；第十八批重排〕工作識別見 [T-03](../terms.md)，固定材料與結果見 [B-101](../base/work.md)、[B-103](../base/work.md)，交接順序依 [tick](../tick.md)；結果不明就是 unknown、不自動重做，正本是 [S-401](operations.md)。

〔建議預設，未拍板〕重試政策是各 kernel 自己定的；以下是預設 kernel 範本的規則（[T-06](../terms.md)）。每次實際重試用新的嘗試 ID，用請求、結果與必要的狀態檔就足夠。自動重試只限確定失敗且明確可安全重做的工作，次數有限、間隔有退避，暫停或取消後不再派出；預設只試一次，LLM 的限流例外依 [S-303](llm.md)。

晚到結果及結果／用量不重複採計依 [C-03](../contracts.md)。

驗收：第一次送出後失去結果，不自動出現第二次；unknown 保持原樣，隨定期清理清掉。
