# 整理區名詞：tick 核心、四類程式與 daemon 用語

← [整理區](README.md)｜[通用 tick](tick.md)｜[daemon](daemon.md)｜其餘名詞：[名詞與責任](../terms.md)

本篇收 tick 與 daemon 基礎用到的名詞（T-07、T-09、T-10），條號不變；其餘名詞（來源標記、node 與角色、工作識別、投件權等）仍在[名詞與責任](../terms.md)。這裡只講詞義，規則以各詞後面連的正本為準。

## T-07．tick 核心

**tick 是一個定期被執行的程式**，怎麼被執行不管：daemon、cron、人手都行；人手或 cron 直接跑的風險自己承擔。tick 的真正核心，本質上是加了一些功能的 aos-exec（跑一份 [inst](../base/inst.md)）。

### 核心只做四件事

1. **互斥**：同一資料夾同時只跑一格（[B-602](tick.md)）。
2. **照表跑**：照任務表的陣列順序一項一項跑，每項是 inst 的超集（[B-620](tick.md)）。
3. **上下層判定**：預設看資料夾包含，可登記覆蓋（[B-628](tick.md)）。
4. **每項結束碼紀錄**：本格每一項怎麼結束，寫成一份檔讓後面的任務讀得到（[B-633](tick.md)）。

這四件事不靠 daemon、git、cgroup、helper，也不靠任何系統級任務。

照表跑時，核心另外只認兩件事：

- **停格檔**：任務要停掉本格剩下的項，就建立約定的檔案；核心每跑完一項檢查它，存在就不跑後面的項。**不靠結束碼**，任務回什麼碼都只是一般的成功或失敗。停格檔只在任務層面、只擋本格；要擋住之後的格用**擋板檔**，有它時 daemon 不開格。
- **任務的 `user`**：跟 tick 的帳號不同時，那一項回 125、不切帳號；要切帳號就在 argv 包 `aos-as`（T-10）。

檔名、誰清除與整格結束碼以 [B-620](tick.md) 為正本。

原本算在 tick 裡的其餘事，都拆出去了（界線以 [B-626](tick.md) 為正本）：

- 收件（回 -32601、刪收件原件）、投件與鬧鐘、發布摘要、清理，以及下一步納入的 git 開格與收尾——都是**系統級任務**。
- needs 的「前置沒成功就跳過」、切換帳號，以及下一步納入的每項任務一框——都是**普通程式**（`aos-needs`、`aos-as`、`aos-cg`）。
- 一格結束後殺殘留，歸 daemon（T-10）。

### tick 是 aos 的衡量基準

整個 aos 體系都基於 tick：

- **以格計**：排程以 tick 為基本單位，例如「這個任務要花十個 tick」。一格的標準長度由那個 tick 的週期 `interval_ms` 決定，「10 格」大約等於 10 個週期；「花幾格」算**安排它的上層**的格，上下層週期不同造成的落差不管。時間欄位怎麼寫見 [C-01](../contracts.md)。
- **排程也在任務表上**：aos 的排程行為就是一個掛在任務表上、只在每次 tick 時執行的程式（[scheduling](../scheduling/README.md)）。
- **唯一的逃生口是 tick–daemon 通道**：除了通道上的事（登記、掛行程、叫醒、傳訊，[B-612～614](daemon.md)），其他所有事都必須在某一格 tick 裡做，不准有別的背景程序或常駐服務繞過 tick。
- **反應速度就是一格**：「立刻處理」最快是下一格；只有走通道的急件叫醒例外（[B-614](daemon.md)）。

### 其他

- CLI 或工具在 tick 之外自己取鎖改檔，當成外部世界，aos 不管。
- tick 不跟其他計算單位（once、LLM 嘗試、agent 一輪等）放進同一個外殼；kernel、agent、custom 類任務的外殼、逾時與取消延後（P-008）。

依據：第十八批（外殼）；第十九批（定期被執行的程式）；第二十批（四件事、衡量基準、系統級任務與普通程式）、疑點裁定 1（改：停格靠檔案）、6（任務的 `user`）、8（tick 外的寫入者）。

## T-09．收尾、排空停機、熱重載、逃生口

幾個容易混的詞。這四樣都屬 daemon，不在任務表上。

| 詞 | 意思 | 正本 |
|---|---|---|
| 收尾 | 對範圍內每個程序群組送 SIGTERM，等 `shutdown_grace_ms`，再送 SIGKILL，確認全空（下一步納入 cgroup 後改對框用 `cgroup.kill`）。重啟、停機、解除登記、取消在跑的工作都用這一套 | [B-604](daemon.md) |
| 排空停機 | daemon 停收新工作，等在途的做完再停；可設上限時間 | [B-604](daemon.md) |
| 熱重載 | 不重開 daemon，重讀設定並套用「免重開」的部分 | [B-608](daemon.md) |
| 逃生口 | node 在自己框下另開子框、刻意留住的常駐程序。〔暫定，第二十批疑-13〕跟「通道是唯一逃生口」（T-07）衝突，不再提供；要常駐就經通道用 `node.mount` 掛 | [B-605](daemon.md)、[B-613](daemon.md) |

- 「排空」只指停機；解除登記那套 TERM→寬限→kill 叫「收尾」。
- 表中的「逃生口」指 node 自開的子框，跟 T-07「唯一的逃生口是通道」不是同一件事。

依據：第十八批（詞義）；第二十批（歸 daemon，詞義不變）。

## T-10．tick 核心、系統級任務、普通程式與其他任務

**管轄區**：tick 執行時的目前目錄（cwd）就是它的管轄區。

- aos 體系裡的慣例是兩個 tick 的管轄區**不重疊、但可以包含**，被包含的那個從屬於包含它的（上下層）；真的重疊了風險自負。
- tick 對管轄區內的東西有最高裁量權。這是 aos 體系裡的約定，**不是 tick 運作的前提**：Linux 權限上碰不到的東西，tick 照樣完成職責。

### 四類

取代第十九批的「核心／標準配備／其他掛載」三層。每類有什麼、怎麼掛，以 [B-626](tick.md) 為正本。

| 類 | 一句話 | 正本 |
|---|---|---|
| tick 核心 | `aos-tick` 本身：互斥鎖、照表跑、上下層判定、每項結束碼紀錄（T-07） | [B-602](tick.md)、[B-620](tick.md)、[B-628](tick.md)、[B-633](tick.md) |
| 系統級任務 | 從核心拆出、掛在任務表上的獨立程式，`kind:"system"` 標記，寫在表上才跑：收件、投件、發摘要、清理（下一步納入：git 開格與收尾） | [B-626](tick.md)、[B-629](tick.md)；git 見 [B-630](tick.md)（下一步納入） |
| 普通程式 | 任務會用到的工具，要的任務自己在 argv 包：`aos-as`、`aos-needs`（下一步納入：`aos-cg`）；不是系統級任務 | [B-303](helper.md)、[B-621](tick.md)；`aos-cg` 見 [B-202](../base/execution.md)（下一步納入） |
| 其他任務 | kernel、agent、clock、自訂任務 | [scheduling](../scheduling/README.md)、[agent](../agent/README.md) |

- **daemon 不在任務表上**：一格結束後殺殘留、重啟清空、排空停機、helper 都歸 daemon（[B-603～605](daemon.md)），本輪以程序群組管；node 框與資源上限下一步納入 cgroup 時也歸 daemon。daemon 跟 tick 之間只有通道這一條路（T-07）；daemon 不看 tick 的結束碼、不因停格檔暫停 node，只看擋板檔決定開不開格（[B-607](daemon.md)）。
- **範本只是預設**：任務表可以拿掉任何一項系統級任務，拿掉了那一項的保證就沒有（[T-01](../terms.md)）。第十九批的「標準配備必須全掛、不能拆、跟核心同一支 `aos-tick`」「全掛檢查與 y／n」「有備援仍算全掛」都撤了。
- 〔第十九批疑點裁定 11 記錄者歸類〕沒 helper、沒通道（不是 daemon 開的格）只算功能受限：要它們的那幾樣（例如 `aos-as`）用不了，其他照常；不另設替代路。

### 幾個詞

詞義如下；檔名、欄位與碼值以正本為準。

| 詞 | 意思 | 正本 |
|---|---|---|
| 掛載 | 把一個程式寫進任務表，讓 tick 每格跑它 | [B-620](tick.md) |
| 系統級任務 | 從 tick 核心拆出、掛在任務表上的程式，以 `kind:"system"` 標記 | [B-626](tick.md) |
| 標準任務表範本 | 預設的一組系統級任務加原本的 kernel／agent 任務；本輪順序是收件 → 使用者任務 → 投件 → 發摘要 → 清理 | [B-629](tick.md) |
| 每項結束碼紀錄 | 核心每格寫的一份檔，記本格各項怎麼結束，後面的任務讀得到；它直接取代第十九批的日誌，git 與無 git 合成同一種模式（第二十批疑點裁定 5） | [B-633](tick.md)、[B-632](tick.md) |
| 格數 | 本 node 第幾格，記在結束碼紀錄裡；aos 內部的時長與起算點都用它數 | [B-633](tick.md)、[C-01](../contracts.md) |
| 停格檔 | 任務建它，核心跑完那一項就不開本格後面的項；只管本格，daemon 不看它 | [B-620](tick.md) |
| 擋板檔 | 擋住之後的格：有它時 daemon 不開格，直接跑的核心也一項不跑；由任務或人手建、只由人手刪 | [B-620](tick.md)、[B-607](daemon.md) |
| 任務環境變數 | 整格共用的叫 `AOS_TICK_*`，這一項專屬的叫 `AOS_TASK_*`；清單見正本 | [B-620](tick.md)、[P-203](protocol/node.md) |
| 包裝 | 先做一件事、再跑原指令、照原指令的結果結束的普通程式，例如 `aos-needs a -- 原指令` | [B-202](../base/execution.md)、[B-303](helper.md)、[B-621](tick.md) |
| 有效上層 | 有登記覆蓋就是覆蓋指定的那個，否則是資料夾推得的上層；覆蓋只改管理關係（誰分資源、誰叫醒、誰能解除），檔案上的管轄權仍跟著資料夾 | [B-628](tick.md)、[B-606](daemon.md) |
| 通道 | daemon 開的 tick 跟 daemon 之間的 IPC，也是唯一逃生口；不是 daemon 開的 tick 沒有通道 | [B-612](daemon.md) |
| 憑證 | daemon 開 tick 時發的一次性憑證，tick 與它的任務在通道上出示它，證明自己是誰；每格一張、這格內有效 | [B-612](daemon.md) |
| 急件 | 走通道送到時要叫醒收件 tick 的訊息 | [B-614](daemon.md) |
| 以指定帳號開程序 | 任務要用別的帳號跑時，在 argv 包 `aos-as <帳號> -- 原指令`：它帶本格憑證經通道請 helper 用那個帳號開（`spawn_as`），交出繼承的鎖 fd，等那個程序結束才照它的結果結束。核心不切帳號 | [B-303](helper.md)、[B-609](daemon.md)、[B-620](tick.md) |

依據：第十九批（管轄區）；第二十批（四類與詞義）。

驗收：見 [B-626](tick.md) 與 [B-620](tick.md) 的驗收句（拿掉一切只跑 `true`、停格檔、任務回任何碼都是一般失敗、帶不同 `user` 回 125）。
