## B-645：訊息模組與 `aos-mq`〔使用者 2026-10-01 第十二批；2026-10-02 第二十五批改成多扇門〕

**daemon 開幾扇「門」（各一個 unix socket），每一項自己挑訂哪幾扇；從某扇門寄進來的信，放進訂了那扇門的每一項的信箱、叫醒它們。任務用 `aos-mq send <門> <JSON>` 寄、`aos-mq take <門>` 取自己的信、`aos-mq peek <門>` 只看不取。** 它是 daemon 的一個模組（[B-640](../core.md)「模組」），設定檔寫了 `modules.mq` 才有。

〔使用者 2026-10-02 第二十五批：「我覺得daemon config中，應該是modules.mq:{"socket-1":"...", "socket-2":"..."}，也就是隨意指定各socket」「inst可以指定說自己想要訂閱哪個socket，然後daemon如果從那個socket收到訊息，就把訂閱了該socket的inst叫醒。這樣就不用topic了」〕這一批取代了第十二批「一個 socket、寄給指名的項」、第十四、十五批的 `--from` 篩選、第二十一批的 `--socket`／`from_socket`、第二十二批的 `--all`／`--channel`／`subscribe`／信的 `to`，以及 `--urgent`。依據：[第二十五批裁定紀錄](../../../../notes/verdicts/11-tick-as-unit/26-1002-第二十五批.md#2026-10-02-第二十五批訊息多扇門)。

### 門

```json
"modules": {"mq": {"SOCKET_1": "./mq-1.sock", "ALERTS": "/srv/aos/doors/alerts/s"}},
"insts": {"inst-1": {"mq": ["SOCKET_1", "ALERTS"]}, "inst-2": {}}
```

- `modules.mq` 是「門名 → socket 路徑」：每個值就是路徑字串，相對路徑以起點為準。daemon 開起來時每扇門開一個 socket。
- 門名只能用英數與底線（要拿來當環境變數名的一段），大小寫照原樣。至少一扇（AI 隊定）。兩扇門算成同一個絕對路徑、或跟控制 socket 同一個路徑＝設定錯（AI 隊定：同一個檔不能開兩次）。
- 舊寫法 `{"socket": "<路徑>"}` 照新規則會被讀成「一扇叫 `socket` 的門」，不是錯；但沒人訂它就收不到信。

### 訂閱

- 每一項的 `mq` 是門名陣列＝這一項訂哪幾扇門；沒寫或空陣列＝不訂。
- 寫了 `modules.mq` 裡沒有的門名＝設定錯（開起來回 1、重讀照 [B-642](../reload.md) 整份不套用）；同一個門名寫兩次照一次算（AI 隊定：重複無害）。
- 沒掛訊息模組時每一項的 `mq` 照不認得的鍵忽略。
- 沒有頻道、沒有收件人地址：**門就是收件地址**，訂了誰就給誰。

### 寄：放進信箱並叫醒

- 從某扇門收到一封寄件：**信＝寄的那個 JSON 原樣**，daemon 不加 `from`、門名或任何欄位。
- 放進**訂了那扇門的每一項**的信箱（每個信箱各一份）。寄件人自己若也訂了，自己也收到、也被叫醒（使用者：不做排除）；任務要避免自己叫醒自己的迴圈，自己處理。
- 沒人訂的門照收、回成功，信直接丟掉（AI 隊定：沒有信箱可放；跟舊「沒人收也算成功」一致）。
- **每封都叫醒收件的項，但叫醒會合併**：照控制模組 `wake`（不帶選項）／舊急件的規則——還沒開跑前連來幾封只跑一次；正在跑時來信，跑完只補跑一次；暫停中跑一次、跑完照樣暫停；被 `stop_on_nonzero` 停掉的不跑（信照收、回成功）。不用掛控制模組也做得到；以後 `wake` 的規則改了，這裡跟著改。不再有 `--urgent`（使用者嫌每封都叫醒太浪費，靠合併叫醒解）。

### 信箱

- **每一項一個信箱，放 daemon 記憶體、先進先出。** daemon 重開就丟，不保證送達。不管信從哪扇門來，都進同一個信箱。
- daemon 不看信的內容；要知道是誰寄的、要怎麼回，寫在信裡，由任務自己約定。
- **`take`／`peek` 連這個 daemon 的任何一扇門都行**，取／看那一項**全部**的信（沒有篩選）；`take` 取走、`peek` 不取。
- 「只能取／看自己的」只在 `aos-mq` 這一側做（它只用 `AOS_DAEMON_INST`、不收 inst 參數）；**daemon 不驗身分**，直接連門送 `{"take":"<別項>"}` 照樣取得到（使用者：「就a，可以報別項的名字」；照 POC「能連就能做」）。誰能連哪扇門，靠下面的資料夾權限管。
- 指名不在 `insts` 的項取／看：回 `unknown_inst`。
- 不設上限（每箱幾封、單封多大）、不去重、不確認送達、不重送。

### 跨 daemon

`aos-mq send` 的路徑寫對方 daemon 的門就是寄給對方（訂了那扇門的項收到），不需要特別的欄位；daemon 不轉送、也不知道信從哪個 daemon 來。要人回信，就在信裡寫回信用的門的路徑。

### socket 與檔案權限（控制、訊息都一樣）

- 每扇門的協議照控制模組：一連線一請求、一行 JSON 來、一行 JSON 回（[B-641](../control.md)）；壞請求、對面先關、逾時只影響那一條連線；收到 SIGINT／SIGTERM 退出前刪掉所有門的 socket 檔。
- 訊息與控制各開各的 socket、互不依賴（使用者 m3n 裁定 5）。
- <a id="socket-權限"></a>**權限原則**〔第二十五批：「保持這樣的json格式，但是socket檔案權限另外精心設計」〕：daemon 建的 socket 檔（控制的一個、訊息的每一扇門）**一律 chmod 666**，不管有沒有掛帳號模組（取代第十二批「掛了帳號模組才先 666」）。**誰能連，由 socket 所在的資料夾決定**（連 unix socket 要對路徑上每一層資料夾有 x 權）：資料夾的擁有者、群組、權限由管理者事先建好，daemon 不建、不改（資料夾不在就照 POC 讓開 socket 自然出錯）。例子：
  - 公告門只准某群組：`/srv/aos/doors/alerts/` 屬 `root:ops`、`0750`，門放裡面 → 只有 ops 群組的人寄得到、取得到。
  - 私人收件匣：`/home/alice/aos/inbox/` 屬 `alice`、`0700` → 只有 alice（與 root）連得到。
  - 小組：`/srv/aos/doors/team-a/` 屬 `root:team-a`、`0770` → team-a 的成員都能寄、能取。
  - 控制 socket 放在只有管理者進得去的資料夾 → 只有管理者能 pause／kill。

### 給任務的環境變數

掛了之後每次開 `aos-exec` 多放：

- `AOS_DAEMON_MQ_<門名>`：**每一扇門**的絕對路徑（不管這一項有沒有訂）。例如門名 `SOCKET_1` → `AOS_DAEMON_MQ_SOCKET_1`。舊的 `AOS_DAEMON_MQ_SOCKET` 拿掉（除非剛好有一扇門叫 `SOCKET`）。
- `AOS_DAEMON_INST`：這一項的 inst 字面值。**掛了控制或訊息任何一個就放**（使用者同意 M2），兩個都掛也是同一個值。
