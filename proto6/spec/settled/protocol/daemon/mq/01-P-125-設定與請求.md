## P-125．訊息 socket、環境變數與 aos-mq〔使用者 2026-10-01 第十二批；2026-10-02 第二十五批改成多扇門；欄位名照現行程式〕

〔[第二十五批](../../../../../notes/verdicts/11-tick-as-unit/26-1002-第二十五批.md#2026-10-02-第二十五批訊息多扇門)〕本篇整份照第二十五批重寫：舊的單一 `modules.mq.socket`、每項 `mq.subscribe`、請求的 `msg`／`from`／`from_socket`／`urgent`／`broadcast`／`channel`、`take`／`peek` 的 `from`／`to` 篩選、回應的 `delivered`、信的 `from`／`from_socket`／`to` 都拿掉了（第十二、十四、十五、二十一、二十二批的寫法被取代）。

### 設定

daemon 設定檔（[P-120](../core.md)）頂層 `modules` 裡寫門，每一項的 `mq` 寫訂哪幾扇：

```json
{
  "modules": {"mq": {"SOCKET_1": "./mq-1.sock", "ALERTS": "/srv/aos/doors/alerts/s"}},
  "insts": {"inst-1": {"mq": ["SOCKET_1", "ALERTS"]}, "inst-2": {}}
}
```

| 位置 | 型別 | 意思 |
|---|---|---|
| `modules.mq` | 物件，至少一個鍵 | 鍵＝門名，只能是 `[A-Za-z0-9_]+`（大小寫照原樣）；值＝那扇門的 socket 路徑，非空字串，相對以起點為準，daemon 算成絕對路徑 |
| 每一項的 `mq` | 字串陣列，可省 | 這一項訂哪幾扇門；省了或 `[]`＝不訂；同一個門名寫兩次照一次算 |

設定錯（開起來回 1、stderr `aos-daemon: config: <說明>`；重讀時照 [P-122](../reload.md) 整份不套用）：`modules.mq` 不是物件或是空的、門名不合、值不是非空字串、兩扇門算成同一個絕對路徑、某扇門跟控制 socket（[P-121](../control.md)）同一個路徑、某項的 `mq` 不是字串陣列、寫了 `modules.mq` 沒有的門名。重讀時每項的 `mq` 照**開起來時的門**核（`modules.mq` 本身改了不套用，只印 `reload: need restart: modules`）。沒掛訊息模組時每項的 `mq` 照不認得的鍵忽略。舊寫法 `{"socket": "<路徑>"}` 會被讀成一扇叫 `socket` 的門。

範例：[兩扇門＋控制](../../../../protocol/examples/daemon/core-config.mq.valid.json)、[訂閱（含空陣列、重複門名）](../../../../protocol/examples/daemon/core-config.mq-subscribe.valid.json)；反例：[沒有門](../../../../protocol/examples/daemon/core-config.mq-empty.invalid.json)、[門的值寫成物件](../../../../protocol/examples/daemon/core-config.mq-door-object.invalid.json)、[門名有 `-`](../../../../protocol/examples/daemon/core-config.mq-door-name-dash.invalid.json)、[項的 `mq` 是字串](../../../../protocol/examples/daemon/core-config.mq-subscribe-string.invalid.json)、[項的 `mq` 是舊的 `subscribe` 物件](../../../../protocol/examples/daemon/core-config.mq-item-object.invalid.json)、[訂了沒有的門](../../../../protocol/examples/daemon/core-config.mq-unknown-door.invalid.json)（這條 schema 驗不到，`validate.py` 另查）。

### socket 上的一來一回

**每扇門都一樣**，跟控制 socket 一樣（[P-121](../control.md)「socket 上的一來一回」）：Unix stream socket、一條連線只問一次、一行 JSON（UTF-8、LF 結尾）來回、每條連線 1 秒內要送完那一行、一條出錯不影響下一條、不驗身分。socket 檔的開與刪照 P-121；開好後一律 chmod 666，誰能連看所在資料夾的權限（[B-645「socket 與檔案權限」](../../../daemon/mq/01-B-645-信箱與socket.md#socket-權限)）。

### 請求

```json
{"send":{"hi":1}}
{"send":null}
{"take":"b.json"}
{"peek":"b.json"}
```

| 欄位 | 型別 | 意思 |
|---|---|---|
| `send`／`take`／`peek` | 見右 | 三個裡剛好出現一個 |
| `send` | 任何 JSON 值（含 `null`） | **信本身**。放進訂了「這扇門」（收到請求的那個 socket）的每一項的信箱，原樣、不加欄位，並照 [B-645](../../../daemon/mq.md)「寄：放進信箱並叫醒」叫醒它們 |
| `take`／`peek` | 字串＝inst 字面值 | 取走／看這一項**全部**的信，跟設定檔 `insts` 的鍵逐字比對；連哪一扇門都一樣 |

不認得的欄位照收不理（同 P-121），所以舊格式 `{"send":"b.json","msg":…,"urgent":true}` 會被當成「信＝`"b.json"`」寄出去。socket 不驗身分：`take`、`peek` 指名任何一項都取得到（「只能取／看自己」是 `aos-mq` 那一側做的，[B-645](../../../daemon/mq.md)；使用者第二十五批：「就a，可以報別項的名字」）。跨 daemon 寄信就是直接連對方 daemon 的門送 `send`，格式一樣；daemon 不轉送。
