# 方案取捨：agent 在 tick／daemon 上是什麼

← [提案入口](README.md)｜上一份：[歷史與零件](01-歷史與零件.md)｜下一份：[agent 的長相](03-agent長相.md)

四個方案，前兩個都是「agent＝一個 tick 工作資料夾」，差在一格裡怎麼切；後兩個是另一種實體。

## A：tick 資料夾，一步拆成幾個小任務（推薦）

agent＝一個有 `.aos/tasks.json` 的資料夾。表上四五項：收信、組 context、呼叫 LLM、做工具、寫記憶，各是一支小程式。一格＝agent 的一步。daemon 的一項 inst 定期叫 `aos-tick` 跑它。

- 好：每一段在紀錄裡各有結束碼；kernel 可以用 `before_kind.llm` 這種 hook 擋住 LLM 那一項（按格計費、查預算），不用改 agent 程式；每支程式都小、好測、好換（例如換掉 LLM 那支）。
- 壞：一步要開四五個程序，一格多幾十毫秒；步與步之間靠 `work/` 裡的檔接力，格式要定。

## B：tick 資料夾，一步就是一支 `aos-agent` 程式

表上只有一項 `aos-agent step`。

- 好：最快能跑起來；接力格式不用公開。
- 壞：LLM 與工具混在一支程式裡，kernel 看不到也擋不了「這一步要打 LLM」；要讀程式才知道一步做了什麼；跟「程式即 spec、每格可量」的方向反。

## C：daemon 直接跑一支常駐的 agent 程式（不經 tick）

inst 的 argv 直接是 `aos-agent --loop`，永不結束。

- 好：反應最快、沒有格的開銷。
- 壞：違反「不准有背景程序繞過 tick」（T-07）；沒有 `seq`、沒有每項結束碼、hooks 用不上；一萬個 agent 就一萬支程序。**不推薦**。

## D：每個 agent 自己一個 daemon

- 好：每個 agent 的門、帳號、重讀設定都獨立；上下層就是 daemon 跑 daemon。
- 壞：一萬個 agent 一萬個 daemon，記憶體與 socket 數都受不了；proto5 試過「每個 agent 一個 tick-daemon」，使用者自己撤回。**只給團隊用**（一個主管 agent 開一個子 daemon 管它的成員），不給每個 agent 用。

## 取捨表

| | A 拆任務 | B 一支程式 | C 常駐 | D 一人一 daemon |
|---|---|---|---|---|
| 符合「一格一單位」 | 是 | 是 | 否 | 是 |
| kernel 能按格擋 LLM | hook 就行 | 要改程式 | 不能 | hook 就行 |
| 新造程式 | 5 支小的 | 1 支大的 | 1 支大的 | 同 A 或 B |
| 一萬個閒置 agent | 不開程序，但 daemon 每項一條執行緒＋一個信箱 | 同 A | 一萬程序 | 一萬 daemon |
| 最早能跑 | 第二階段 | 第一階段 | 第一階段 | 第四階段 |

## 推薦與理由

**推 A，上下層用 D 補。** 理由三個：

1. 一步拆開才對得上 T-06「分配的單位是一次計算（一次 LLM 呼叫）」——LLM 呼叫自己是表上一項，有結束碼、有 kind，kernel 用現有 hooks 就管得到。
2. 現有零件已經夠組：收信＝`aos-mq take`、睡＝一直暫停、醒＝寄信（含 grant）或 `wake`、壓住＝不寄 grant 或寫 `tasks-blocked`、停＝擋板檔、身分＝資料夾＋帳號模組。新造的只剩「呼叫 LLM」與「接線」。
3. 符合「程式即 spec」：看 `tasks.json` 就知道這個 agent 一步做哪幾件事，不用讀程式。

**要付的代價**：接力檔格式（`work/request.json`、`work/response.json`、`work/tools/<id>/`）要在提案裡定清楚（見 [一格做什麼](04-一格做什麼.md)）。

## 睡覺的三種做法（A 之內的小取捨）

| 做法 | 怎麼睡 | 怎麼醒 | 代價 |
|---|---|---|---|
| **一直暫停（推薦，對齊 kernel 提案）** | daemon 狀態模組預置 `paused:true`；格做完就結束、照樣暫停 | 有人往它訂的門寄信（grant 也是信）或 `aos-ctl wake`：暫停中仍跑一格 | 要掛狀態＋訊息模組；`pause` 不能再當「壓住」用（它本來就是暫停的） |
| 長週期不自醒 | `interval_ms` 設很長 | 到點、寄信、`wake` | 到點仍會跑空格；daemon 開起來每項先跑一次 |
| 擋板檔 | 自己放 `tick-blocked` | 只有人能刪 | 這是「停」不是「睡」 |

`pause` 現行語意：只停週期排程，來信與 `wake` 仍跑一次，正在跑的不殺。所以它適合當「睡」，不適合當「壓住」。
