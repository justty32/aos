# 八、外部先例：別人在「一個工作一個程序」與「常駐 thread」之間怎麼選

← [入口](README.md)｜上一份：[實驗](07-實驗.md)｜下一份：[分層視角](09-分層視角.md)

由一位助手整理（有查到的附來源，其餘標憑記憶）。只留跟本題有關的。

## 共同規律

1. **隔離單位留在程序，併發單位才往 thread 移。** Apache prefork → worker → event、nginx master＋worker、PHP-FPM、gunicorn，每一代都是這樣。從程序走向 thread 的理由只有三個：記憶體、連線數、啟動成本；付的代價是當掉隔離、thread-safety、熱重載。〔Apache MPM 文件：https://httpd.apache.org/docs/2.4/mpm.html；其餘憑記憶〕
2. **跑「別人寫的碼」的系統，一律程序。** cron、systemd timer、inetd、Airflow（task 永遠是獨立程序，LocalExecutor 預先 fork 一批 worker）、Luigi、Kubernetes Job、CI runner（Jenkins、GitHub Actions、Buildkite）。理由相同：使用者腳本不可信、要能 kill、log 要獨立、任意語言。〔Airflow：https://airflow.apache.org/docs/apache-airflow/stable/core-concepts/executor/local.html；其餘憑記憶〕
3. **監督者（daemontools、runit、s6、supervisord）從不把被監督者當 thread。** 監督者是最後一道防線，自己不能因被監督者而死；「重啟」＝kill＋exec，thread 做不到。監督者只知三件事：怎麼啟動（`./run`）、怎麼知道 ready（s6 的 `notification-fd`）、怎麼停（訊號）。〔s6：https://skarnet.org/software/s6/notifywhenup.html；其餘憑記憶〕
4. **啟動成本用「預熱＋fork」解，不用 thread 解。** Android zygote、Chromium zygote（省每程序約 6 MB 與 60 ms/GHz 的 loader 成本，且避免執行中升級後版本不合）、Python `multiprocessing` forkserver（3.14 起 POSIX 預設，官方理由：「保留效能但避開多 thread 程序的相容問題」）。〔Chromium：https://chromium.googlesource.com/chromium/src/+/main/docs/linux/zygote.md；Python：https://docs.python.org/3/library/multiprocessing.html#contexts-and-start-methods〕
5. **「可殺」的前提是狀態不共享。** Go goroutine 只能合作式取消（`context`）、Java `Thread.stop` 已廢、Python／Rust thread 殺不掉；Erlang 能 `exit(Pid, kill)` 是因為每個 process 獨立 heap。OS 程序與 BEAM process 滿足，thread 不滿足。〔Go：https://pkg.go.dev/context；Erlang：https://www.erlang.org/doc/system/ref_man_processes.html；其餘憑記憶〕
6. **「同時支援兩種」的做法都一樣：launcher 可插拔、工作契約固定。** Apache MPM、gunicorn worker class、Airflow executor、`multiprocessing` start method。上層只選「怎麼生」，不改「做什麼」。〔同上〕

## 跟本題直接相關的事實

| 事實 | 影響 | 來源 |
|---|---|---|
| glibc 2.24 起 `posix_spawn` 用 `clone(CLONE_VM\|CLONE_VFORK)`，不複製頁表 | 程序啟動的大頭不在 spawn，在直譯器啟動與 import | https://man7.org/linux/man-pages/man3/posix_spawn.3.html |
| CPython `subprocess` 只在 `close_fds=False`、`cwd=None`、無 `start_new_session` 等條件下走 posix_spawn；否則走 `_posixsubprocess` 的 vfork 路徑（3.10 起），3.12 起 vfork 等待期間釋放 GIL | 現行 `Popen(cwd=…, start_new_session=True)` 走 vfork，已經很便宜；多 thread 下 Popen 不互卡 | https://raw.githubusercontent.com/python/cpython/3.12/Lib/subprocess.py、Modules/_posixsubprocess.c 第 811～816 行 |
| Python signal handler 只能在主 thread 裝、只在主 thread 跑 | tick 若有任何訊號邏輯，變 thread 後要由 daemon 主 thread 代管 | https://docs.python.org/3/library/signal.html |
| 3.12 起多 thread 程序呼叫 `os.fork()` 發 `DeprecationWarning`；`subprocess` 不受影響 | fork server 路線（[05 E](05-其他路線.md)）必須在開 thread 前先 fork 出 zygote | https://docs.python.org/3/library/os.html#os.fork |
| libfuse `fuse_context.pid` 註解：「calling **thread** 的 pid」；核心 `fs/fuse/req.c` 第 13 行 `pid_nr_ns(task_pid(current), …)`，是 tid 不是 tgid | FUSE 分得出同一程序的不同 thread；要對回程序讀 `/proc/<tid>/status` 的 `Tgid`；writeback 路徑 pid 為 0，write handler 別信 pid | https://raw.githubusercontent.com/libfuse/libfuse/master/include/fuse.h、https://raw.githubusercontent.com/torvalds/linux/master/fs/fuse/req.c |
| cgroup v2：寫 pid 進 `cgroup.procs`，整個程序的 thread 一起搬 | thread 版 tick 不能單獨框 | https://man7.org/linux/man-pages/man7/cgroups.7.html |
| Plan 9 `rfork(flags)` 逐項選要不要共享 fd 表、環境、namespace、記憶體 | thread vs process 不是二選一；問題是「哪些東西要各自一份」 | https://9p.io/magic/man2html/2/fork |

## 對 aos 的一句話

外部先例幾乎一致：跑任意語言任務的排程器把隔離單位留在程序，啟動成本用 zygote、預熱或小二進位解決。真正從程序走向 thread 的（Apache worker、gunicorn gthread、Nailgun）都付了隔離與可殺的代價，而且前提是「被跑的碼受信任且 thread-safe」。aos 的 tick 本身是我們自己的碼（受信任），所以 B 不是不行；但它跑的任務不受信任，而任務層本來就不受 B 影響，所以 B 換到的只剩啟動成本與記憶體。
