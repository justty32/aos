**讀法**：一格程序的成本幾乎全是 Python 直譯器與 import；spawn 機制（posix_spawn 或 vfork）只佔 0.12 ms。現行鏈 daemon → aos-exec → aos-tick 每格付 25＋17＝42 ms，其中 aos-exec 那 25 ms 不做任何事，只是轉一手。C／C++ 程式的程序成本 0.07～0.43 ms，thread 的速度優勢在 C++ 時代消失。

## 二、同時 N 格：thread vs process

重現：`for N in 1 10 100 1000; do for m in a b c; do python3 timev.py python3 bench2.py $m $N; done; done`。每格一個工作資料夾、一項 `/bin/true`。

- (a) 一次 Popen N 支真 aos-tick。
- (b) N 條 thread，每條 `Popen(任務).wait()`。這是 B 的代理，因為真的多 thread 呼叫 `run_tick` 會互踩（見下）。
- (c) N 條 thread，各 Popen 一支 aos-tick 再 wait（現行 daemon 的形狀）。

| N | a 牆鐘 | b 牆鐘 | c 牆鐘 | a 子樹 CPU | b 子樹 CPU | c 子樹 CPU | b daemon RSS |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 1 | 22.0 | 0.4 | 17.6 | 22 | 0 | 17 | 14.9 MB |
| 10 | 25.0 | 1.2 | 25.5 | 203 | 2 | 205 | 15.0 MB |
| 100 | 184.5 | 7.2 | 188.4 | 2658 | 15 | 2681 | 16.4 MB |
| 1000 | 1802.8 | 66.6 | 2126.9 | 26629 | 141 | 30170 | 33.5 MB |

- 同時活著的 aos-tick 每支約 13～16 MB；N＝100 時系統合計 390～460 MB。
- N＝1000 時每支 aos-tick 要 27～30 ms CPU（16 緒搶 8 核）。
- **c 不比 a 快**；thread 只省 daemon 的程式結構，不省每格的程序成本。
- 1000 沒撞 ulimit（`-u` 246988）。

**真的多 thread 呼叫 `run_tick`（b_naive）**：N＝10 有 1 格、N＝100 有 16 格印 `busy:`，有紀錄的資料夾只有 9/10、84/100，沒有任何例外。原因：thread A `chdir(dirA)` 後 thread B `chdir(dirB)`，A 再開相對路徑 `.aos/tick.lock` 拿到的是 B 的鎖。**現行 tick 在同程序並行會悄悄跑錯資料夾，不會報錯。**

## 三、鎖

重現：`python3 bench3_locks.py`

| 情境 | 結果 |
|---|---|
| 同程序兩 thread 各自 open、`flock(LOCK_EX\|LOCK_NB)` | 第二個 **EWOULDBLOCK**：flock 綁 open file description，thread 間互斥 |
| 同上改 `lockf` | 第二個 **成功**（不互斥）；且程序內任一 fd 關掉就全放 |
| 同一 fd 兩 thread flock | 都成功（同一 description 重複上鎖＝轉換） |
| 父 flock → `Popen(sleep 5, pass_fds=[fd])` → 父退出 → 第三方試 | **EWOULDBLOCK，鎖還在**；殺掉 sleep 後第三方成功 |
| 現行實作 | tick（`aos_tick.py` 第 199 行）與 daemon（`aos_daemon.py` 第 127 行）都是 flock；tick 鎖 fd 不可繼承＋close_fds，任務帶不走 |

讀法：B 下 flock 照樣互斥，鎖不必改；「鎖跟著任務活」（[01](01-POSIX優勢拆解.md) 第 13 項的補法）實測可行。

## 四、FUSE 認身分

pyfuse3 沒裝，用 60 行 C 寫最小 FUSE（write handler 印 `fuse_get_context()->pid`）。重現：`gcc ctxfs.c -o ctxfs $(pkg-config --cflags --libs fuse3); ./ctxfs -f mnt & python3 bench4_fuse.py mnt`

```text
WRITE ctx.pid=130243  Tgid=130243  data=main-thread
WRITE ctx.pid=130245  Tgid=130243  data=thread-0
WRITE ctx.pid=130246  Tgid=130243  data=thread-1
WRITE ctx.pid=130248  Tgid=130248  data=child
```

**已實測**：`fuse_context.pid` 是呼叫 thread 的 tid。同程序不同 thread 分得出來；要還原程序 pid 讀 `/proc/<tid>/status` 的 `Tgid`。限制：tid 結束後可重用，而且 tid 對不到 cgroup／session 這類核心邊界。

## 五、thread 殺不掉

重現：`python3 bench5_kill.py`。`Thread` 沒有 `kill`／`terminate`；`PyThreadState_SetAsyncExc` 對 `sleep` 中的 thread 無效（0.5 s 後仍活著），只對忙迴圈有效，且是 ctypes 偏方。對照 `Popen.terminate()` 0.11 ms、`kill()` 0.16 ms 立刻結束。
