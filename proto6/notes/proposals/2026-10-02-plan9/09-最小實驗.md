## 三個實驗

範圍先縮成「單帳號、固定路徑、假 LLM」。每個實驗只驗一件事，驗到就停。

**實驗 A（半天）：bwrap 給回聲 agent 一個視野。** 拿 agent 提案第 0 階段的回聲 agent（零新程式）。daemon 把 inst 當**路徑**交給 `aos-exec`，不能在 daemon 設定裡直接寫 argv 陣列，所以是改回聲 agent 的 `.aos/inst.json`：`argv` 寫成上面那串 bwrap（結尾 `aos-tick`），kernel 門 bind 到 `/aos/kernel`、控制 socket bind 到 `/aos/ctl`，`--setenv` 補身分與路徑變數。驗兩件事：`ls /aos` 只看到該看到的兩個檔；在裡面 `aos-mq send /aos/kernel …` 通，把別人的門路徑硬寫進去 → `connect` 錯（`ENOENT`，路徑不存在）。再開第二個回聲 agent，證明兩棵樹互不可見。**注意這只驗「看不到」，不驗「不能控制」**——連得到 `/aos/ctl` 的仍能對任何項下指令。這一步不改任何 aos 程式。

**實驗 B（一天）：`/llm/clone` 的 FUSE 玩具。** pyfuse3（用 asyncio 層）寫一個小 FUSE：`clone` 讀回號碼（client 要保住那個 fd，全關才回收）、`N/request` 以 close 當收完、`N/response` blocking read 回 `fake:` 劇本（先不打真 API）、`N/usage` 一行。先只驗三件：兩個視野（一個 bind 了 `/llm`、一個沒有）、一個假回應、shell 能完成一次呼叫。Ctrl-C 中斷、拔掉 FUSE 的錯誤、`think` 寫 `tasks-blocked` 這些是第二輪。這一輪驗的是**檔案介面**，不是額度強制——次數與 token 的管理要另寫在服務裡，不算這輪已證明的收益。

**實驗 C（可選，半天）：信落檔。** daemon mq 模組加一個選項，把每封信落成**每一項自己的** `insts/<項>/mail/<n>.json`（現行每位訂戶各有一份，共用一份會被第一個取走的人刪掉），`aos-mq take`＝`ls`＋`cat`＋`rm` 只動自己的目錄。這是檔位 0 裡有真收益的一條，但不列第一輪必做。

三個實驗都在 scratchpad 或 `proto6/notes/probes/` 玩，不碰 spec、不碰 `src/py`（實驗 C 除外，可用 `--opt` 開關）。玩完照 aos-teams 慣例派人試玩打分。
