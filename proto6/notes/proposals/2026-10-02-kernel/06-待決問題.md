# 六、待使用者決定的問題（每題附建議）

← [提案入口](README.md)｜上一份：[分階段落地](05-分階段落地.md)

都是方向題，我不代裁。沒回答的照建議寫進 POC，條文標「暫定」。

## 1. kernel 是角色，不是程式？

kernel＝一個工作資料夾（tasks.json 放政策）＋它擁有的一份 daemon 設定。沒有 `aos-kernel` 常駐程式。
**建議：是。** 這是 09-29 原意，也是現行零件自然組出來的形狀。

## 2. 一個 kernel 一個 daemon？

A：每個 kernel 自己一份 daemon 設定，成員是它的 `insts`；多層＝daemon 跑 daemon。B：全機一個 daemon，kernel 只管其中一組項。
**建議：A。** 一份設定就是一個隔離單位，pause／kill／cgroup 都能整組套；B 要在 daemon 裡多一層「哪些項歸誰」，又回到 node。

## 3. 成員狀況靠 push 還是 pull？

push：成員 `after_all` 寄 summary。pull：kernel 讀成員資料夾的 `.aos/tick/last/`。
**建議：push。** 不用跨資料夾讀檔、不用知道成員路徑、順便叫醒 kernel。pull 留給除錯用。

## 4. kernel 怎麼 SIGHUP 自己的 daemon？

改名單、改上限要重讀設定，但 reload 只收 SIGHUP、控制 socket 故意不收 reload，而且現在拿不到 daemon 的 pid。選項：a 加環境變數 `AOS_DAEMON_PID`；b 鎖檔裡寫 pid；c 控制 socket 加 `reload`。
**建議：a。** 最小、登在 C-10 一行就好；c 推翻先前裁定。前提：kernel 那一項跟 daemon 同帳號（不然訊號送不到）。第 4 階段才需要，前三階段名單靜態。

## 5. LLM 額度要不要強制？

grant 是建議，agent 自律。要強制得走「池代發」（舊三檔的第二檔）：agent 把請求寄給池那一項，池替它打 HTTP。
**建議：POC 先自律。** 使用者 09-30 已接受直連 key 藏不住；強制留到玩過再說。

## 6. grant 用信還是用檔？

信：kernel 每格寄到 MEMBERS 門，agent 開跑先 take。檔：kernel 寫 `public/grants/<成員>.json`，agent 自己讀。
**建議：信。** 不用跨資料夾寫檔、不用約定路徑、叫醒免費。代價是重開會丟，kernel 下一格重寄就好。

## 7. 下層 kernel 怎麼知道上層的門？

a 寫死在下層 `policy.json`；b 下層 daemon.json 的 kernel 項 `envs` 用 `{"$env":"AOS_DAEMON_MQ_KERNEL"}` 接住繼承來的上層門路徑。
**建議：a 先、b 當進階寫法。** a 一眼看懂；b 少寫一份路徑但要懂展開時機。

## 8. 額度的窗口用誰的格？

**建議：kernel 的格**（C-01：算安排它的那一層）。grant 帶 `kernel_seq` 與 `window_ticks`，agent 不用換算。

## 9. 任務的 `kind` 要不要訂 `"kernel"`？

**建議：要，但只是標籤**（第二十四批：kind 隨便寫）。好處是 kernel 範本能用 `before_kind.kernel` 掛 git 之類的 hooks。

## 10. 名字：還叫 kernel 嗎？

使用者預感 node 會消失；kernel 這詞要不要保留。
**建議：保留 kernel，不用 node。** 「成員」「工作資料夾」「項」三個詞夠用；kernel 一詞在 T-06、T-10 都還在。

## 11. kernel 的格壞了要不要救？

**建議：不救**（默認一切正常）。成員照上次設定跑；人看 daemon stdout 的 `exit=1` 行自己處理。

## 12. 成員資料夾要不要放在 kernel 資料夾底下？

**建議：不要求。** 成員是誰只看 daemon.json，跟路徑無關（上下層照包含關係算已在暫緩區）。範本把成員放 `agents/` 底下只是整齊。

## 13. 要不要留「成員彼此講話」給 kernel 轉？

**建議：不要。** kernel 不轉信；成員要講話直接寄到對方訂的門（第二十一、二十二批已有廣播與頻道）。

## 14. 隨機性當排程依據（T-06 第 6 條）

**建議：先不做**，只在 summary 的 `usage` 預留位置（例如 `retries`），等有數據再想怎麼量。

## 15. 第 0 階段做完要不要停在方案 D？

若兩個成員靠共用額度檔自律就夠，可以不蓋 kernel。
**建議：不停。** 多層與摘要往上是使用者反覆講的方向；但第 0 階段的結果是這題的實測依據，看完再拍。
