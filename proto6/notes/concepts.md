# proto6 的三大概念：基底、agent、任務與排程

← [筆記索引](README.md)

2026-09-28，使用者已接受這個責任分區，作為接下來理解與建造 proto6 的入口。這是概念劃分，不代表實作已完成，也不是要求拆成三個程序或先訂一套固定 schema。

## 1．基底：讓工作確實執行、交接與收尾

基底提供一般工作的執行機制，不需要理解人格、bot 或對話的意義。後續細分為工作描述、執行器、身分與資源、儲存與持久狀態、通訊與交接、生命週期管理；逐塊意義與例子見[基底](base.md)，細分仍是待討論的規劃草案。

daemon 現有的大部分底層管理機制歸在這裡。它可以依指示執行某個 agent 的 tick，但不需要知道那個 agent 的人格或為什麼選這個工具。

## 2．agent：理解任務，決定下一步

agent 的資料夾是持久本體，tick 是推進狀態的步驟；不必把 agent 等同於一個永遠存活的程序。

這一層管理設定、人格、模型與工作原則；管理對話 history、notes 及記憶整理；管理能力與工具登記、呼叫；維護 idle／think／act／wait 等狀態。

agent 決定放哪些內容進 context、如何理解 LLM 回覆、接下來呼叫哪個工具。選好之後交給基底執行，再用結果推進自己的狀態。單次 LLM API client 可以獨立存在，不必因此把整個 agent 的判斷邏輯放進 client 或基底。

設定、輸入、記憶、能力與狀態推進的細分草案見 [agent](agent.md)。

## 3．任務與排程：決定誰先做、能用多少

這一層從較長的工作範圍看事情：一輪任務何時開始、暫停、完成；不同 agent 的工作如何安排優先次序；LLM 共享額度與 token 預算如何分配；人的互動與背景工作如何兼顧公平、可理解與可預測；以及較粗的資源分配。

它決定執行機會與額度，基底負責把決定落實。例如排程決定某件工作現在可以開始，基底才以正確身分和資源限制啟動它；agent 再根據執行結果決定下一步。

這是 kernel 後續可能承擔的責任方向。kernel 最後是一個程序、幾個部分，或集中／分散安排，仍未決定；一輪任務的完整語意也不因這份概念圖就自動定案。

任務輪次、准入、公平、LLM 額度、預算與人工控制的細分草案見[任務與排程](scheduling.md)。

## 與先前五大概念的關係

先前的[人格、記憶、能力、環境權限、執行底座](2026-09-28-human-architecture.md)，是人操作與理解一個 agent 的視角。這次三分法是建造系統時的責任視角，兩者不衝突：人格、記憶、能力主要落在 agent；環境與資源由基底提供機制，任務與排程決定如何分配；執行底座則對應基底。

接下來先看**基底的工作描述與執行，再看通訊與生命週期**，這個接續順序已獲使用者同意。之後建議再看 agent 本身與更細的任務排程；這是閱讀與規劃順序，不要求先把整個基底做完才可以驗證一個 agent。

後續已繼續拆成 [spec 規格草案](../spec/README.md)：各末端條款定義責任、資料、前置條件、狀態、持久交接與驗收。概念分區仍保留，具體schema與政策是可替換的建議預設，尚未實作。
