## 第三批：tick 改成註冊式（同日）

使用者方向：tick 承擔的事愈來愈多，改成註冊式。loop 只做「跑一次 inst」，inst 要跑的程式就是 `aos-tick`；`aos-tick` 依註冊表順序跑各項任務：系統性任務（權限、掛載等基底）→ agent 任務（吃訊息、處理工具等）→ 自訂任務（例如收信）。支援 **group**（組內全成功才把結果納入變動）與 **needs**（前置任務成功才執行）。取代 A-506 前後掛勾。

| 題 | 裁定 |
|---|---|
| 要 root 的系統性任務 | **固定在 root helper**，不進註冊表；註冊表的系統任務用控制側專用帳號跑、不是 root（守裁定 5） |
| 任務用 LLM／跑工具 | **先送出去、下次 tick 收結果**（同 proto5 丟資料夾；tick 保持短） |
| group 失敗撤回到哪 | **只撤回交給帳本的結果**；任務自己直接改的檔案不管、不回滾（工具就是工具） |

狀態：spec 與協議篇的 tick／checkpoint／掛勾段落待依此重寫；協議篇五份初稿（依舊 tick 模型寫成）先收錄當材料。

## 第四批：kernel 樹（同日）

使用者指出 proto6 把 proto5 的 kernel／daemon 改成單一控制端＋總帳本，偏離原意。原意與補充 → [kernel 樹與註冊式 tick](../2026-09-29-kernel-tree.md)：
- kernel 也是靠 tick 推進的資料夾；團隊可以有自己的 kernel，只管自己的排程與資源，又是上層 kernel 的一件工作。
- **LLM 也化作資源**，由 kernel 分配與排程。
- **最頂層 kernel 只是多了一些高級系統權限（例如可用 root helper），此外和其他 kernel 沒有不同。**
- **LLM endpoint 通常由最頂層掌管，其他 kernel 也可以有自己的 endpoint 池。**

## 第五批：拿掉帳本、資源模組化（同日）

- **帳本沒必要**。使用者原以為帳本是「原子操作紀錄」：先記下後果，條件滿足才套用。這個用途只管資料夾內的變動，**用 git 做**，不想管的用 `.gitignore`；工具的不可逆外部後果不管。除此之外不需要帳本。→ 取代第三批「group 失敗只撤回交給帳本的結果」：改為 git 追蹤範圍一起還原。
- **kernel 管的資源要能靈活增減**：做成可插拔 module；某團隊不想管網路消耗，它的 kernel 就不裝網路 module。
- 細節草案見 [kernel 樹與註冊式 tick](../2026-09-29-kernel-tree.md)第二、五節。
- 確認：收件區 `.gitignore`、吃訊息＝搬進追蹤區；資源 module 走 kernel 註冊表；**不用 sqlite**；帳本其他用途靠檔案，但要精簡。
- **daemon**：記憶體裡一張註冊表，資料夾路徑就是 id；依設定定期跑各資料夾的 inst（tick）；其他程式用 IPC 註冊／解除註冊、叫醒（提前 tick）。**agent 也註冊給 daemon**，由所屬 kernel 決定何時叫醒；**重啟後設定檔只列頂層，其餘由各 kernel 的 tick 重新註冊補回**。
