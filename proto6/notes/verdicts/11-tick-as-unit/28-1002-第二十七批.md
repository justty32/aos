## 2026-10-02 第二十七批：settled 佔據 spec、舊設計封存

〔使用者裁定 2026-10-02〕使用者原話：「舊的設計spec可以開agent去做整理封存。舊的連結也封存。現在我們的settled要成為唯一事實，佔據spec。」兩件事：

1. **舊設計整批封存。** `proto6/spec/` 裡 settled 以外的舊篇（agent、base、cli、conformance、scheduling、readme、舊協議篇、`contracts.md`、`terms.md`、`cli.md`、`conformance.md`、`check_ids.py`）用 `git mv` 原樣搬到 [notes/archive/spec-2026-10-02/](../../archive/spec-2026-10-02/README.md)，結構照舊、內容不改。舊 schema 與範例（agent、kernel、llm、work、msg、ops、res、outbox 那一批，詳見下）跟著搬。`check_ids.py` 檢查的是舊條號體系，spec 只剩一小撮條號、notes 又大量引用已封存的條號，沒用了，一起封存。
2. **settled 提升成 spec。** `spec/settled/` 這層消失：README、conventions、terms、tick.md、tick/、daemon/、deferred/ 搬到 `spec/` 根，`settled/protocol/` 的篇併進 `spec/protocol/`。`spec/README.md` 改寫成「spec 就是唯一事實；程式、測試、schema 是行為與格式正本；spec 只留程式看不出的原則」，拿掉「整理區」說法與「對外依賴」「還開著的」兩節。

### 對外依賴收進來

原本 settled 靠區外的幾篇，逐一看現行程式還有沒有用：

| 原依賴 | 處理 |
|---|---|

| C-01 時間以 tick 為基準、C-07 版本與陌生欄位 | 收進 [conventions.md](../../../spec/conventions.md)；舊篇的 `aos migrate`、永遠禁止鍵（`api_key`、attention `argv`）是舊設計，不寫 |
| inst（`base/inst.md`） | 新寫 [inst.md](../../../spec/inst.md)：形狀、找目標（檔或資料夾、`AOS_DIRNAME`）、指示詞交給 `aos_directives`、怎麼跑（125／126／127、128+N、逾時）、指向 `aos_inst.py`、`aos_exec*.py` 與測試 |

| 儲存 B-404（滿碟、保留、`aos-clean`） | 現行程式沒有 `aos-clean`，也沒有針對滿碟的處理，不寫，留在封存 |
| 驗收入口（`conformance.md`） | 現行驗收就是測試加 `validate.py`；README 只留「怎麼驗」三個指令，場景表留在封存 |

### schema 與範例

`spec/protocol/schemas` 與 `examples` 留在原位。只搬現行程式與測試都不用的：`agent-*`、`kernel-*`、`llm-*`、`work-*`、`msg-*`（含 `msg-outbox`）、`ops-*`、`res-*` 共 46 份 schema；範例目錄 `agent-tasks`、`kernel-tasks`、`ops`、`resources`、`work` 與 `messages/` 全部 JSON（含 `outbox.*`）。留下 16 份 schema（`common`、`inst`、`tick-*`、`daemon-*`）與 `daemon`、`tick` 兩批範例。`messages/validate.py` 留在原處（指令不變），拿掉舊分組的對照與舊範本的跨欄位檢查。舊 daemon 的 `daemon-config`、`daemon-state`、`daemon-rpc`、`daemon-helper`、`daemon-provision`、`daemon-registration`、`daemon-runner-report`、`daemon-launch-error` 現行程式沒用，但暫緩區的舊協議篇還連著它們，所以先留。

### 連結與註解

- 全 repo 指向 `spec/settled/…` 的連結改指新路徑；指向被封存舊篇的改指封存路徑，新 spec 有對應篇的（舊 terms、舊協議通則、`contracts.md#c-01`／`#c-07`、`inst.md`）改指新篇。用腳本逐條對照搬移前後的目標，約 900 條、涉及一百多份檔。封存資料夾內的連結不維護。
- 入口檔：`settled/daemon.md`（原路徑保留的入口）刪掉，`spec/protocol/daemon.md` 封存，指向它們的連結改指 `daemon/README.md`、`protocol/daemon/README.md`。暫緩區各分檔入口的「原路徑保留當入口」說明改成「本檔只留前言與目錄」，入口檔本身留著（它們還是那個主題的前言與目錄）。
- 程式註解：`aos_inst.py`、`aos_directives.py`、`aos_exec.py`、`aos_exec_run.py`、四份 `test_inst_*.py` 的 docstring 裡指向不存在的 `spec/inst-posix/`、`spec/directives/`、`spec/aos-exec/`、`spec/base/inst.md` 改指 `proto6/spec/inst.md`（指示詞機制說明指向 proto5）。只改註解，行為沒動。
- `proto6/README.md` 的 spec 描述改寫。
