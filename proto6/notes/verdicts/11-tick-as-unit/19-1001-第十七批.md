## 2026-10-01 第十七批：hook 新掛點與 git

〔使用者裁定 2026-10-01 晚〕使用者原話依序：「那確實是需要AOS_TASK_EXIT」「"hooks":{"after_task":{"a":..., "b":...}}，然後是after_every_task。」「都照你說的，排給agent做。git這塊先不要進範本。」

定下來的：

- **`hooks.before_all`**：inst 陣列；開格後、第一項任務（含 tasks-blocked 的檢查）之前跑一次。擋板檔、鎖被佔、任務表壞（整格沒開）時不跑。給 `AOS_HOOK_*`，不給 `AOS_TASK_*`。
- **`hooks.after_every_task`**：inst 陣列；每一項任務跑完都跑。
- **`hooks.after_task`**：物件，鍵＝任務 id（沒寫 id 的任務 id 是位置字串，所以位置也能當鍵），值＝inst 陣列（只有一個也寫陣列）；只有那一項跑完才跑。寫了不存在的 id＝永遠不跑、tick 不報錯。
- 兩個都有時：先 `after_task.<id>`、再 `after_every_task`。
- 這兩個跟任務有關的掛點：`AOS_HOOK_POINT`、`AOS_HOOK_INDEX`（在它自己那個陣列裡的位置，`after_task` 每個 id 各自從 0 數）、`AOS_HOOK_ID`，加上剛跑完那一項的 `AOS_TASK_ID`、`AOS_TASK_INDEX`、**`AOS_TASK_EXIT`**（結束碼；被訊號 N 殺＝128+N）。不看 tasks-blocked；被 tasks-blocked 擋下、沒跑的任務不觸發。
- **`AOS_TASK_EXIT` 只有這兩個掛點有**；一般任務、`before_all`、`after_all` 都不給。跑每一項前跟其他 `AOS_TASK_*`／`AOS_HOOK_*` 一樣先從繼承的環境拿掉（第十批那條規則多一個變數）。
- hook 的結束碼照 `after_all`：只記不是 0 的，不影響 tick 結束碼。
- **`aos-git` 整套搬暫緩區**（原 `tick/git.md` 的 B-630、B-622、B-632 整篇，P-205）：用 hooks 加普通 git 指令取代（`before_all` 當機還原、`after_task`／`after_every_task` 成功 commit、失敗還原那一項），這個用法寫成 B-635 的範例說明。**範本（B-629）不放 git**：「有 git 版範本」搬暫緩區，範本只留沒有 git 的那份。git 的固定排除、`AOS_DIRNAME` 空字串時提交整個資料夾等規則跟著暫緩。plan `m2-system-tasks.md` 的待問 1～12 標成隨 `aos-git` 擱置。

**AI 隊定的細節**（使用者可改）：

1. 紀錄 `hook-exits.json` 擴充成各掛點各一個陣列（照 `before_all`、`after_task`、`after_every_task`、`after_all` 的順序，任務表寫了哪幾個就有哪幾個鍵）；`after_task` 各任務 id 的筆混在同一個陣列、照跑的順序。`after_task`、`after_every_task` 的每筆另帶 **`task_index`**＝觸發它的那一項任務的位置。
2. 因為 hooks 在格中也會跑，`hook-exits.json` 改成**開格就建**、`record.json` 開格就帶 `hooks` 的 `$ref`（原本收尾才建）。schema `tick-record` 拿掉「`ended:false` 不得有 `hooks`」，原本兩個「沒收場卻有 hooks」反例改成正例 `hooks-running`；validate.py 補查 `task_index` 不遞減、都小於 `ran`。
3. `exec_failed` 的標籤：`before_all/<id>`、`after_task/<任務 id>/<id>`、`after_every_task/<id>`、`after_all/<id>`。
4. `after_task` 的鍵比字串（任務 id 不是字串時 `str()` 後比）。展開時機比照 `after_all`（`after_task` 多一層：每個任務 id 的陣列各解一層）。
5. `hooks` 裡其他還沒開的鍵（例如 `before_task`）照收不理；原本拿 `before_all` 當「不認得的掛點」的兩條測試改用 `before_task`。
6. B-635 的 git 範例用 `python3` 讀上一格 `record.json` 的 `ended` 判斷要不要還原、`git checkout -- . && git clean -fdq -e .aos` 還原；只是說明，aos 不提供腳本。
