## 2026-10-02 第二十四批：kind 拿來掛 hooks、擋停格，值隨便寫

〔使用者裁定 2026-10-02，公司〕頂層問「kind 你想拿來做什麼？」，使用者勾了三項：「hooks 按 kind 掛」「停格按 kind 擋」「值改成隨便寫」；之後說「kind可以開agent先讓他去做了」。

**頂層建議、使用者放行**（使用者沒反對，照做）：

1. **值**：`kind` 是任意非空字串，拿掉 `system`／`kernel`／`agent`／`custom` 與「類別.名稱」那份清單（schema、P-202 欄位表都改），`system.x` 不再是反例；不寫＝沒有類別。tick 核心照舊不驗 kind 的值（極簡檢查不變）。
2. **hooks 新掛點** `before_kind.<kind>`、`after_kind.<kind>`：掛在那一類**每一個**任務的前後，寫法比照 `after_task.<id>`（物件：鍵＝kind，值＝inst 陣列）；`AOS_HOOK_POINT` 等照現有規則，`after_kind` 比照 `after_task` 給 `AOS_TASK_EXIT`。比對用展開後的 kind；沒有 kind 的任務不觸發任何 `*_kind`。
3. **停格按 kind 擋**：`tick/tasks-blocked` 內容是 JSON 物件、有 `"kinds": [字串…]` 時，只擋 kind 在清單內的任務，其他照跑（沒有 kind 的不擋）；不是這種形狀（空檔、非 JSON、沒 `kinds`）＝照舊全部擋。這改了[第十八批](20-1001-第十八批.md)「tasks-blocked 內容 tick 不讀」——tick 現在只讀 `kinds` 這一個鍵，其他內容照舊留給模組 insts 讀。被擋的任務，它相關的 hooks 照現在的規則不跑；`before_all`／`after_all` 照舊。

**AI 隊定的細節**（挑最簡單一致的；使用者可改）：

1. **比對只認字串**：展開後的 kind 不是字串（數字、物件…）就當沒有類別——不觸發 `*_kind`、不會被 `kinds` 擋；核心照舊不報錯。只看任務自己的 kind（頂層的 kind 照舊不是預設）；hook 項、tasks-blocked 模組 insts 裡寫的 kind 沒作用。理由：鍵與清單都是字串，非字串硬轉容易誤中（`5` 對上 `"5"`）。
2. **讀表檢查比照 `after_task`**：`before_kind`／`after_kind` 要是物件、每個值是陣列、每項合併預設後有 `argv`，不合＝`bad_table`；寫了沒有任務用的 kind＝永遠不跑、不報錯；指示詞展開時機也一樣。
3. **一項任務的順序**：tasks-blocked 檢查（含 B-636 模組）→ `before_kind.<kind>` → 任務 → `after_task.<id>` → `after_kind.<kind>` → `after_every_task`。理由：由專到泛（id 最專、kind 次之、every 最泛）。`before_kind` 排在檢查之後，所以被擋的任務不會觸發它；它寫的 tasks-blocked 擋不到自己這一項（已經檢查過），擋的是下一項——跟「hook 寫的 tasks-blocked 只擋下一項任務」一致。
4. **環境變數**：`before_kind` 給 `AOS_HOOK_POINT=before_kind`、`AOS_HOOK_INDEX`、`AOS_HOOK_ID`、`AOS_TASK_ID`、`AOS_TASK_INDEX`，**不給** `AOS_TASK_EXIT`（還沒跑）；`after_kind` 再加 `AOS_TASK_EXIT`。不另加 `AOS_TASK_KIND`（hook 掛在哪個 kind 自己知道；要再加）。
5. **hooks 紀錄**：`hook-exits.json` 多 `before_kind`、`after_kind` 兩個鍵（任務表有寫才有），鍵順序 `before_all`、`before_kind`、`after_task`、`after_kind`、`after_every_task`、`after_all`；每筆帶 `task_index`，`index` 是它在那個 kind 的陣列裡的位置（每個 kind 各自從 0 數）。開不起來印 `exec_failed: before_kind/<kind>/<id>: …`（`after_kind` 同）。
6. **「這種形狀」**＝讀得到的一般檔、合法 JSON、頂層物件、有 `kinds`、`kinds` 是陣列而且每個元素都是字串。其他一律照舊全部擋（含資料夾、讀不到、壞 symlink、空檔、非 JSON、`kinds` 不是陣列或混了非字串）——讀不到不丟錯。`"kinds": []` 照字面＝一個都不擋。
7. **每一項之前都重讀**：格中檔可能被改；某項之前是 kinds 形狀就只看這一項的 kind，之後變成全擋形狀就從那一項起全部擋（照舊停下、記 `blocked_before`）。
8. **部分擋的紀錄**：被 kinds 擋掉的任務不算 `ran`、不進 `tasks`；`record.json` 收尾時多 **`skipped`**：`[{"id","index"}…]`，照順序，只有被 kinds 擋過才有，跟 `blocked_before` 一樣只在 `ended:true` 時可有（中途 hook 讀 `current/` 看不到）。`blocked_before` 只在全部擋時記。補查改成：`tasks` 的 `index`、hook 的 `task_index` 都小於 `ran`＋`skipped` 筆數；`skipped` 的 `index` 嚴格遞增。理由：不改 `ran` 的意思、record.json 照舊只在開格與收尾各寫一次。
9. **跟 tasks-blocked 模組（B-636）**：每一項「本來要被擋」時（不管哪種形狀）都先跑那一串、再重讀一次決定這一項；kinds 形狀時一格可能跑好幾次（每個要被擋的項一次），kind 不在清單、本來就不擋的項不觸發。跑完仍擋：全擋形狀＝這一項與後面都不跑；kinds 形狀＝只跳過這一項。模組把檔刪了或把清單改掉都算放行。
10. **其他不變**：整格最後照舊刪 tasks-blocked（不管內容哪種形狀）；擋板檔 `tick-blocked` 照舊不讀內容；`before_all`／`after_all` 照舊。
