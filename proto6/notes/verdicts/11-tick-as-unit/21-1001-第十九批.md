## 2026-10-01 第十九批：daemon 上下層用到的三件事

〔使用者裁定 2026-10-01 晚〕討論「daemon 的上下層」：上層 daemon 把下層 daemon 當成一項跑（inst 的 argv 是 `aos-daemon --config …`）。使用者要的上下層權限是 **a 監督**（下層掛了上層重開，現在就有）、**b 權限分層**（root 上層掛帳號模組開出各帳號的下層，帳號模組就有）、**c 停掉重開**、**d 跟上層講話**。給各 inst 做上下層使用者說沒必要（「現有的aos-mq就夠了」）。

使用者原話依序：
- 「1. 對，就是這樣，我們不管這塊。 2. 這是要自己承擔的風險，我記得我們會在stdout跳警告對吧？ 3. 那就要有這個指令。 4.這得做...   我想要的權限：abcd」（2＝同一份設定開兩個 daemon；當時 AI 隊更正：其實沒有任何警告，而且第二個會先刪掉第一個的 socket 檔再重建）
- 「然後堆在上層的記憶體這件事，上層這邊要做記憶體上限，超過就丟棄早的。然後用socket檔案作爲daemon是否正在運行的依據，感覺不太好，換成另一檔案吧，畢竟socket以後會有多個，且權限管理複雜。 3.按照你的建議。 4. daemon之間的交流，我希望和tick之間的交流是另一套體系...還是說可以共用？這得好好思考。」
- 追加改兩點：「上限必須共用，然後每項不覆蓋」「拿不到鎖就報錯退出」。

定案（已做）：

1. **輸出上限**：頂層 `exec_output_max_bytes`（預設 1048576），**各項共用、每項不能覆蓋**（寫在某一項裡照不認得的鍵忽略）。每一次、每條串流（stdout、stderr 各算）最多留這麼多，**邊讀邊丟最早的**；寫出時標頭多 `dropped=<bytes>`。沒寫 `exec_out_path`／`exec_err_path` 的那條接 `/dev/null`，不收。正本 [B-640](../../../spec/settled/daemon/core.md)「輸出」、[P-120](../../../spec/settled/protocol/daemon/core.md)。
2. **鎖檔**：daemon 開起來對 `<設定檔>.lock`（頂層 `lock_path` 可改，相對以設定檔資料夾為準）取非阻塞 flock；**拿不到就 stderr `aos-daemon: lock: another aos-daemon holds <鎖檔>`、回 1**，在開 socket、建 cgroup、開 root 端之前。不靠 socket 檔判斷。正本 [B-640](../../../spec/settled/daemon/core.md)「同一份設定只能開一個」。
3. **控制模組 `kill`、`restart`**（照建議）：kill＝先 SIGTERM，`modules.control.kill_grace_ms`（預設 5000）內還沒結束就 SIGKILL，掛 cgroup 再 `cgroup.kill` 整個框；沒在跑回 ok、不做事。restart＝有在跑就照 kill、結束後馬上再跑一次；沒在跑＝wake。正本 [B-641](../../../spec/settled/daemon/control.md)「kill 與 restart」、[P-121](../../../spec/settled/protocol/daemon/control.md)。
4. **d（下層的任務跟上層講話）這次不做**：使用者在想 daemon 之間的交流要不要跟 tick 那套分開。

**AI 隊定的細節**（使用者可改）：

1. 輸出上限 0＝全部丟、只寫標頭（`dropped=` 有數字、內容是空的一行）；上限算 bytes，丟的地方可能在一行或一個 UTF-8 字的中間。重讀設定改了上限：照套，下一次起用。
2. 鎖檔不存在就建、不刪；fd 握到程序結束、不傳給子程序。鎖檔路徑在重讀時變了：只警告 `reload: need restart: lock_path`。兩份不同的設定檔開兩個 daemon 照樣可以（各鎖各的），它們若指同一個 socket 路徑，後開的照舊先刪再開。
3. **kill 送給誰**：aos-exec 把任務開在另一個 session，只送 aos-exec 的程序群組會讓任務變孤兒，所以從 /proc 找 aos-exec 所有後代的程序群組。SIGTERM 只送後代的群組、**不送 aos-exec 自己**——任務收到 TERM 自己收尾、結束，aos-exec 照常回任務的碼（例如任務 trap 後 `exit 7`，`exit=7`）；aos-exec 底下還沒有程序時才送它自己。SIGKILL 送後代的群組加 aos-exec 自己（碼 137）。已經跳出親子樹的（setsid＋double fork 被收養）找不到，只有掛 cgroup 時靠 `cgroup.kill` 清。
4. kill 殺掉的那次非 0，`stop_on_nonzero` 照算（會停掉）；**restart 殺掉的那次不算**（不然 restart 會把 stop_on_nonzero 的項停掉、重開不了）。被 stop_on_nonzero 停掉的項 restart 回 `stopped`（同 wake），要救用 resume。
5. 指令送出 SIGTERM 就回 ok，不等那一次結束（跟其他指令一樣）；寬限與 SIGKILL 在另一條執行緒做。
6. **帳號模組底下別的帳號的項**：降權後的主程式送不到別的帳號的程序，所以請 root 端送——root 端加一種封包 `{"signal": <請求 id>, "final": false|true}`，照同一套規則（root 端另寫一份 `targets()`，不 import aos 其他模組）；不回應。掛 cgroup 時最後的 `cgroup.kill` 照樣由主程式寫（框已 chown 給預設帳號）。
7. `kill_grace_ms` 可以是小數、要非負；`exec_output_max_bytes` 要非負整數；`lock_path` 要非空字串；不合都是設定錯（stderr `aos-daemon: config: <說明>`、回 1）。
