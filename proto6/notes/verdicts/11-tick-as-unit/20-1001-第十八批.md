## 2026-10-01 第十八批：範本清空、ended 時機

〔使用者裁定 2026-10-01 晚〕使用者原話：「1. 都按你建議 2.好 3.對，我就不想了。」對應三題：

1. **範本（B-629）裡剩的系統級任務都搬暫緩區**：`aos-mq get`（B-623）、`aos-mq post`（B-624 剩下那部分）要靠暫緩區的 daemon 通道，用途已被 daemon 訊息模組（B-645，`aos-mq send`／`take`）取代；`aos-clean`（B-404 的系統級任務那部分）現在沒東西可清。三樣搬走後範本只剩使用者任務，**B-629 整條搬暫緩區**。現行**沒有系統級任務**，全部在暫緩區。
2. **所有 hooks（含 `after_all`）跑完之後才寫 `ended:true`**：tick 在跑 hook 時被殺，下一格的 `last/record.json` 是 `ended:false`，`before_all` 的當機還原看得到。
3. **tasks-blocked 的內容定案**：tick 只看存不存在、永遠不讀內容；內容給 `modules.tasks_blocked` 的 insts 自己讀。

**AI 隊定的細節**（使用者可改）：

1. 寫法跟 `aos-git`（第十七批）一致：`tick/mq.md`（B-623、B-624）、`tick/template.md`（B-629）**整篇搬進暫緩區**（`deferred/mq.md`、`deferred/template.md`），第十七批放在 tick 暫緩區的「有 git 版範本」併到 `deferred/template.md` 篇末；P-206 搬進 tick 協議暫緩區。`aos-clean` 在 `base/storage.md`（不在整理區）就地標暫緩、不搬家。範例 `tasks.template*.json` 照留（照樣過 schema），P-202 的範例清單標成舊範本的紀錄。
2. tick 子篇入口改名「hooks、tick 模組與普通程式」；B-626 的系統級任務那列寫明「現行沒有，全部在暫緩區」；類別本身的規定（`kind:"system"`、只靠檔案交接）照留給之後回來的系統級任務。
3. `ended` 改時機之後：hook 跑的時候讀到的本格紀錄是 `ended:false`、還沒有 `exit`、`blocked_before`（`blocked_before` 照舊只在收尾寫，沒有另外提早寫）；要知道這格被擋下，hook 看 tasks-blocked 在不在（整格最後才刪）或比 `ran` 與任務數。hook 展開失敗時「tick 回 1、紀錄卻寫 `exit:0`」的對不上（第八批記的「先不管」）隨之消失。
4. 測試：`test_hook_sees_ended_record` 改成 `test_hook_sees_record_not_yet_ended`；新 `test_killed_during_hook_leaves_not_ended`（hook 裡 `kill -9 $PPID`，下一格的 `before_all` 讀到 `last` 是 `ended:false`）；`test_hook_exits_file` 跟著改。
