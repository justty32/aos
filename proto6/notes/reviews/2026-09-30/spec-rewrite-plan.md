**名詞**：

- **正本**：一條規則只在一個地方寫完整，其他地方只放連結指過去。
- **熱重載**：不重開 daemon，直接重讀設定檔並套用。
- **排空停機**：先不收新工作，等手上的做完再停。
- **收尾**：送 SIGTERM，等一段寬限，再 `cgroup.kill`，最後確認都清空了。這次會把 unregister 原本叫「排空」的那套動作統一改叫「收尾」，免得跟排空停機搞混。

## 一、正本重排（裁定第 15 條）

**現況**：spec 裡約有 24 個主題，同一條規則在兩處以上都寫了完整內容，其中 9 處已經寫得不一樣了。例如：

- 取消在跑的工作，一處說會殺掉，另一處說「排空、不殺」（必-3）。
- helper 停程序時的寬限寫死 2 秒，沒跟著設定值走。
- tick 篇和 CLI 篇的任務表都漏了 `methods` 欄。
- B-501 寫「對發件者開放」，跟 P-202 的說法不一致。
- 同一個指令，kernel 回 2、agent 回 1。

另外還有三個結構問題：

- B-504 在兩個檔裡各有一個標題，條號重複。
- P-100～116 的索引表有三份。
- P-001 自稱「本篇只定編碼」，但近幾批的新行為大多是先寫進協議篇的。

每個主題的出現處、差異和處置，都在 map 檔 `kind=重複` 的 24 列。

**三種做法**：

| 方案 | 做法 | 好處 | 壞處 | 搬動量 |
|---|---|---|---|---|
| A | 主規格管行為；協議篇只管格式、method、argv、結束碼 | 符合現在 README 的說法 | 約 20 條只寫在協議篇的行為（鬧鐘、methods、task-*、取消…）要往上搬 | 最大 |
| B | 協議篇當正本；主規格縮成導讀（方向、不變的規則、驗收、連結） | 實作的人只要讀一處；schema 本來就綁在協議篇 | 主規格約 35 條要縮；協議單檔會超過 20 KB，要再拆 | 大 |
| **C（推薦）** | 按主題各指定一個正本，選目前寫得最細的那一處；另一邊只留一句話加條號。正本清單寫進 V-01，當成正式的「正本表」 | 搬得最少，只要把約 45 處刪成引用，真正搬家的約 5 處；9 處不一致都能靠「指定正本、另一邊改引用」解決 | 要查表才知道正本在哪，所以正本表一定要維護 | 小 |

**推薦 C 的理由**：

1. 這次大改的重點是架構：多層多 kernel、各 kernel 自訂。如果先大搬文字，改架構時還得再搬一次。
2. 現有的不一致全部都能用 C 解掉，不需要換掉整套分工。
3. C 大致會形成這樣的分法：基底（daemon、tick、inst、cgroup）的正本留在主規格，各 kernel 可以自訂的東西（任務範本、LLM 池、資源政策）以協議篇為正本。之後要往 B 走，也很順。

**這只是建議，由你決定（Q1）。**

**條號**：一律保留舊號，不重新編號。notes 裡約 113 處、審稿紀錄裡還有更多，都引用了現在的條號。內容搬走的條號留一句殘根，寫「第十八批：併入 P-xxx」。新主題用新號段，例如 T-06。

`check_ids.py` 順便補三項檢查：同一條號有兩個標題就報錯；只剩索引列、沒有正文就報錯；V- 開頭的條號也納入檢查。

## 三、daemon 設定與操作表（裁定第 6 條）

原則照你說的：**只有重大或危險的操作才要重開，其餘盡量即時改。**

現況是 spec 把所有設定都寫成「改了要重開」（P-101、P-104），原型也只在啟動時讀一次設定。下表「建議」欄是我的初判，請逐項看；標 ★ 的連到疑點。

### 設定項

| 設定 | 白話 | 建議 | 理由 |
|---|---|---|---|
| `version` | 設定檔格式版本 | 重載時照樣檢查 | 不是可以改的值；版本不同就整份不收 |
| `common_user` | 沒 helper 時整棵樹共用的帳號；用 sudo 開時，daemon 會降權成這個帳號 | **要重開** | daemon 已經永久變成這個帳號，換帳號就等於換一個 daemon。socket、state_dir、cgroup 的擁有者全部跟著變，降過權的程序做不到 |
| `socket_path` | 大家連 daemon 的位置 | **要重開** | 所有連線會斷；各 kernel 記的位置都要改；防止兩個 daemon 同時跑的鎖放在 socket 目錄，換位置就等於換鎖，可能讓兩個 daemon 同時活著 |
| `state_dir` | 存 state.json、daemon 自己的事項、PID 檔的地方 | **要重開** | 恢復資料都在舊位置，換掉就等於換一個 daemon |
| `cgroup_root` | 交給 daemon 管的那棵 cgroup 子樹 | **要重開** | 所有正在跑的程序都要跨子樹搬家，這需要 root，daemon 早就沒有 root 了；上限要重寫，用量也會歸零 |
| `create_cgroup` | 子樹不存在時由 daemon 自己建 | 只在啟動時有用，重載時忽略 | 子樹一旦建好，這項就沒有意義了 |
| `pause_save_interval_ms` | pause 狀態多久批次存一次檔 | 即時改 | 下一次存檔就用新值 |
| `shutdown_grace_ms` | 送 SIGTERM 後，等多久才強殺 | 即時改 | 只影響之後才開始的收尾；已經在收尾的照舊值走完 |
| `disable` | 強制關掉可選功能（目前只有 quota） | 即時改 ★Q13 | 只影響之後的 quota 動作，已經設好的歸屬不收回；重新打開時要再偵測一次能不能用 |
| roots：加一棵頂層 | 多一棵樹 | 即時改 ★Q7、Q12 | 等於一次沒有父層的登記加一次 wake；需要 helper 的部分見 Q7 |
| roots：刪一棵 | 移除整棵樹 | 即時改 | 走 unregister 收尾；清不空就一直擋著，並寫事項 |
| roots：頂層身分額度擴大 | 頂層可用的帳號變多 | 即時改 ★Q7 | 這正是第 6 條要解決的事 |
| roots：頂層身分額度縮小 | 頂層可用的帳號變少 | 即時改 ★Q8 | 已經往下授出去的，會超出新的範圍 |
| roots：`interval_ms` | 頂層多久跑一格 | 即時改 | 從下一次到期開始算 |
| roots：佈建權擴大或縮小 | 頂層能做哪些固定動作、能碰哪些路徑 | 即時改 ★Q8 | 已經做完的動作不回滾 |
| roots：`node_id` 改名 | 頂層換路徑 | 當成「刪一棵＋加一棵」 | 舊的那棵要收尾 |
| 頂層身分額度改用前綴或範圍 | 例如 `aos-` 開頭的帳號，或一段 UID | 即時改（新語法）★Q9 | 格式見第四節 |
| 新增：`drain_timeout_ms` | 排空停機最多等多久 | 即時改 | 下一次停機才用到 |
| 新增：once 診斷的容量或保留期 | daemon 記憶體裡最多留幾筆 once 結果、留多久 | 即時改 ★Q32 | 下一輪淘汰就用新值 |
| 有沒有 helper（用不用 sudo 開） | 要不要能切換到其他帳號 | **要重開** | 由啟動方式決定；拉起 helper 需要 root |

寫死、不開放成設定的：IPC 封包上限 256 KiB、`node.ls` 每頁 64 筆、socket 權限預設值、最低版本（git 從 2.35 改成 2.36）。版本檢查只在啟動時做。

### 操作

| 操作 | 做什麼 | 建議 | 說明 |
|---|---|---|---|
| 啟動 `aos daemon` | 前景開 daemon | — | 自我檢查、準備 cgroup、清掉舊程序，都只在這時做 |
| 短寬限停機（Ctrl-C／SIGTERM） | 停止開新格，TERM → 寬限 → 強殺 | 保留 | 第 7 條要求保留 |
| **排空停機**（新） | 不收新工作，等在途的做完，到上限才強停 | 新增 ★Q14～Q16 | 見第四節 |
| **熱重載**（新） | 重讀設定、算出差異，只套用可以即時改的 | 新增 ★Q5、Q6 | 見第四節 |
| `daemon.info` | 查這次啟動的 ID | 即時 | 不變 |
| `node.register`（新登記） | 登記一個成員 | 即時 | 不變；額度可以寫前綴或範圍 |
| `node.register`（同一 node、內容不同） | 改週期、額度、佈建權 | 即時 | 現在要求「整棵暫停且全空」才能改。建議改成：週期、擴大額度即時生效；縮小則照 Q8 處理 |
| **帶新上層重新登記**（換父，新） | 把 node 搬到另一個父層下 | 即時，但被搬的那棵要先停 ★Q10 | cgroup 框必須在父框底下，換父就要拆掉舊框、在新父下重建，上限重寫、用量歸零。不必重開 daemon，只影響被搬的那棵 |
| `node.unregister` | 收尾後解除，連子樹一起 | 即時 | 不變；確認全空後刪掉 node 框（設-10） |
| `node.wake` | 要求現在跑一格 | 即時 | 人手「立刻跑一格」就用它，CLI 再等格次序號前進（第 16 條） |
| `node.pause`／`resume` | 關或開這個 node 的開格閘門 | 即時 ★Q11 | 要不要加「連子樹一起」的選項 |
| `node.show`／`ls` | 查登記與最近一格 | 即時 | 最近一格的資料加上格次序號（新必-2） |
| **once 診斷清除**（新） | 手動清掉已結束 once 的診斷紀錄 | 即時 | 見第四節 |
| `node.provision`：改 cgroup 上限 | 寫 CPU、記憶體、程序數上限 | 即時 | 第 8 條：拿掉「整棵全空才改」；調低時由 Linux 處理超用，aos 記一筆（★Q17） |
| `node.provision`：建帳號、chown、建框、quota | 原本的固定動作 | 即時 | 不變 |
| `node.provision`：helper 新動作（新） | 交出框、群組…… | 即時 ★Q21 | 見第四節 |
| `daemon.attention.*` | 看 daemon 自己的事項、標成完成 | 即時 | 不變 |
| helper 被 kill 之後恢復 | 讓特權操作能再做 | **要重開** | 需要 root 才拉得起來；daemon 已經降權了。這是現有規則，不變 |

**要重開的只有 6 項**：common_user、socket_path、state_dir、cgroup_root、有沒有 helper、helper 被 kill 後恢復。共同原因是：這幾項一改，就等於換了 daemon 的身分、它的恢復資料，或整棵資源樹，而且大多需要 root 才做得到。其餘項目最多只要求被動到的那一棵先停下，不影響別的樹。

## 四、新增的東西：最小規格草稿

以下只定骨架：欄位、指令、錯誤碼的方向。細節等疑點定了再寫。

1. **helper 新增的固定動作**（P-107；裁定 3）。仍然只做固定清單上的事，每次只做一件，不收任意路徑以外的參數。
   - `cgroup_delegate`：不帶參數。把本 node 的 `n-<h>` 資料夾，以及其中 `cgroup.procs`、`cgroup.subtree_control`、`cgroup.threads` 三個檔，交給這個 node 的執行帳號。上限檔不動。
   - `group_create`：參數 `group`，要寫確切名稱。建一個系統群組。
   - `group_add_member`：參數 `group`、`user`。只對之後新開的程序生效。
   - `chgrp`：參數 `path`、`group`。只改一個路徑，不遞迴、不跟隨 symlink，路徑必須在已授權的範圍內。
   - 候選（★Q21）：改群組時遞迴、chmod／setgid、刪殘留框 `cgroup_remove`。
   - 錯誤沿用 P-111，另加 `group_not_granted`。schema 要改 daemon-provision、daemon-registration、daemon-helper 三份。
2. **排空停機**（B-604／P-114；裁定 7）。
   - 新設定 `drain_timeout_ms`，可省略，預設值由 Q16 定。
   - 流程：停止收新工作（範圍見 Q15）→ 等在途的 tick 與 once 自然結束 → 全部結束就存檔、回 0；到了上限就照 Q16 處理。
   - 觸發方式見 Q14。短寬限停機保留不變。
3. **熱重載**（P-101 新增小節；裁定 6）。
   - 觸發方式與權限見 Q5。
   - 流程：讀取新設定並驗證整份 → 跟目前的設定比對差異 → 依第三節的表套用。
   - 回應：`{boot_id, applied:[欄位…], restart_required:[欄位…]}`。
   - 錯誤：`config_invalid`，表示新設定讀不進來，舊設定繼續用；`restart_required`，是否整份拒收見 Q6。
   - helper 的安全問題見 Q7。
4. **帳號前綴與範圍**（P-104、daemon-config；裁定 6，推翻第十一批）。
   - 身分額度的每一項可以是以下其中一種：確切名稱、UID 整數、`{"prefix":"aos-"}`、`{"uid_min":N,"uid_max":M}`。
   - 「子額度必須在父額度內」改成判斷集合是否被包含：前綴包前綴、範圍包範圍、確切值落在規則裡。
   - 一律排除 UID 0。比名稱還是比 UID、要不要排除系統帳號、要不要保留「帳號第一次建立後就綁定 UID」，見 Q9。
5. **帶新上層重新登記**（P-104；裁定 6）。
   - 用同一個 `node.register`，帶不同的 `parent_id`，就視為搬家。
