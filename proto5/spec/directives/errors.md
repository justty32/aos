# 5. 循環

`$ref` 沿著一條鏈記身分：**(檔案的 realpath，解出來的絕對位置)**，任何深度都記；同一條鏈裡
再撞到同一個身分＝`ReferenceCycle`。例如 `{"$ref":"", "$at":"."}`——指到「目前文件、目前
位置」自己——直接算循環。

**這條鏈是「每個值的位置各自算一條」，不是整份文件共用一條**：宿主每解一格（每個欄位、
`argv` 的每個元素、`envs` 的每個值）都從空鏈開始；但宿主若是拿著 `$ref` 取回來的容器**繼續往裡面解**
（lib 的 `resolve_located`），鏈要跟著帶進去，不然走進取回來的容器再繞回自己會無限遞迴。所以同一份
`$ref` 目標，只要不是在同一條解析路徑上遞迴繞回自己，被兩個不同的欄位各自引用一次是完全
合法的，不會被誤判成循環。

# 6. 錯誤代號

| 代號 | 什麼時候 |
|---|---|
| `UnknownDirective` | 物件有 `$` 開頭的 key，但沒有一個是 `$opt`／`$ref`／`$fmt`／`$env`（其他不是 `$` 開頭的 key 一律忽略，不影響判定） |
| `DirectiveValueTypeMismatch` | `$env`／`$ref` 的值不是字串；`$at` 有寫但不是字串；`$fmt` 的值不是物件；`$fmt` 的 `$val` 或任一變數解完不是字串 |
| `FormatVariableInvalid` | `$fmt` 變數表裡，`$val` 以外的變數名 `$` 開頭、是空字串、或含 `{`、`}` |
| `UnknownOption` | `$opt` 不是這個位置認得的選項；或這個位置根本不吃 `$opt`——**由宿主的選項表決定**（選項物件裡 `$opt`／`$val` 以外的 key 一律忽略，不影響判定） |
| `OptionConflict` | 該帶 `$val` 沒帶、不該帶卻帶了、或選了互斥的選項組合——**由宿主的選項表決定** |
| `EnvironmentVariableMissing` | `$env` 指的變數不存在 |
| `UnknownFormatVariable` | `$fmt` 模板裡的 `${name}` 不在變數表裡 |
| `ReferenceReadFailed` | `$ref` 指的檔讀不到 |
| `ReferenceJsonInvalid` | `$ref` 指的檔不是合法 JSON |
| `ReferencePointerInvalid` | `$at` 語法錯（不是 `/`、`.`、`..` 開頭）、相對寫法（`.`／`..`）爬過所在文件的根、或在文件裡走不到 |
| `ReferenceCycle` | `$ref` 鏈繞回同一個身分 |

`FieldTypeMismatch`（解完之後型別不對）不在這張表——那是「那一格該是什麼型別」的判斷，
屬於宿主規範，不是指示詞機制的錯誤。

# 7. 容易踩的

- 一般物件的 key **不能 `$` 開頭**：只要出現就會讓整個物件被當成指示詞看，不會被當成一般
  巢狀資料。這是這套機制天生的限制，沒有跳脫寫法。
- 指示詞**只能拿來產生「值」，不能拿來產生「key」**——JSON 的 key 本來就只能是字面字串。
- **可以混寫**：一個物件裡出現不只一個 `$` 開頭的指示詞 key，**不會報錯**——照優先順序
  （`$opt`＞`$ref`＞`$fmt`＞`$env`）只跑排最前面的那一個，其餘（包括不是 `$` 開頭的 key）
  一律忽略。例：`{"$ref":"e.json","X":"1"}` 會跑 `$ref`，`X` 忽略；`{"$ref":"a.json","$fmt":{...}}`
  也只跑 `$ref`。
