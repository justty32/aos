# 1. 什麼算指示詞

一個 JSON 物件（dict）**只要有 `$` 開頭的 key，就當指示詞看**——不會被當成一般的巢狀物件。
這代表：一般物件的 key **不能** `$` 開頭，不然會被誤認成指示詞（見第 7 節）。

物件裡除了指示詞的 key，**可以有任何其他 key，一律忽略**（例如 `_note`、`x` 之類的說明用
key）。如果同一個物件裡同時出現不只一個指示詞 key（`$opt`／`$ref`／`$fmt`／`$env`），
只跑**優先順序最高**的那一個，其餘全部忽略——優先順序是：

    $opt  >  $ref  >  $fmt  >  $env

例：`{"$ref": "a.json", "$fmt": {...}}` 只跑 `$ref`，`$fmt` 不看；`{"$ref": "a.json", "_note": "說明"}`
也只跑 `$ref`，`_note` 忽略。

有 `$` 開頭的 key、但四個都不是（例如只有 `{"$xyz": 1}`）——仍然是 `UnknownDirective`。

指示詞分兩類：

- **取值指示詞**（`$env`／`$fmt`／`$ref`）：`$env`／`$ref` 的值是字串，`$fmt` 的值是物件。
  它會被「解」成另一個值，解出來的東西當成本來就寫在那一格。
- **選項物件**（`$opt`，可選 `$val`）：這一類**不取值**，是「幫這一格加選項」（例如：附加寫入、
  先建目錄、繼承標準輸入）。真正要放進這一格的值是 `$val`（沒有 `$val` 就是這格保持原本的
  預設值，只是加了選項）。判定指示詞時，含 `$opt` 的物件照優先順序最先跑；其他 `$` 開頭的
  key（含 `$ref`／`$fmt`／`$env`）一律忽略，不會被讀取也不會報錯。

# 2. 先解、再驗；巢狀

解析永遠是**先把指示詞展開，展開完再驗型別**，不是邊解邊驗：

1. 看這一格的值是不是指示詞。
2. 是的話，解開一層，換成解出來的值。
3. 解出來的東西**還是指示詞就繼續解**（巢狀），直到不是指示詞為止。
4. 最後才照「那一格本來該有的型別」去驗——這一步是**宿主規範的事**，不是指示詞機制管的。

`$val` 的值一樣可以再是指示詞（`$env`／`$fmt`／`$ref`），一樣照上面的流程解到底、再驗。

指示詞機制不知道、也不管某一格「應該」是字串還是陣列還是物件；它只負責把指示詞換成值，
換完之後型別驗不驗得過，是那一格自己（宿主規範）的判斷。
