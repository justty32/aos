# 指示詞：讓 JSON 的值「從別處來」

← [proto5 README](../README.md)｜實作在 [proto4-3/aos_inst_resolve.py](../../proto4-3/aos_inst_resolve.py)

這份文件講的是**指示詞這套機制本身**，不是某一種 JSON 文件（例如 inst.json）該有哪些欄位。
內容照現在的程式碼寫，不是照想像；程式碼跟本文對不上的地方，以程式碼為準、回來改本文——


一句話：**指示詞**是 JSON 文件裡「這一格的值不是字面寫死的，是從別處取來的」的統一寫法——
從解析者自己的環境變數取、拼一段字串、或去讀另一份 JSON 檔的某個位置。哪份文件用這套機制
（例如 inst.json）是那份文件自己的規範（「宿主規範」）決定的；本文只管機制本身怎麼運作。

## 1. 什麼算指示詞

一個 JSON 物件（dict）**只要有 `$` 開頭的 key，就當指示詞看**——不會被當成一般的巢狀物件。
這代表：一般物件的 key **不能** `$` 開頭，不然會被誤認成指示詞（見第 7 節）。

物件裡除了指示詞的 key，**可以有任何其他 key，一律忽略**（例如 `_note`、`x` 之類的說明用
key）。如果同一個物件裡同時出現不只一個指示詞 key（`$opt`／`$ref`／`$fmt`／`$env`），
只跑**優先順序最高**的那一個，其餘全部忽略——優先順序是：

    $opt  >  $ref  >  $fmt  >  $env

例：`{"$ref": "a.json", "$fmt": {...}}` 只跑 `$ref`，`$fmt` 不看；`{"$ref": "a.json", "_note": "說明"}`
也只跑 `$ref`，`_note` 忽略。

有 `$` 開頭的 key、但四個都不是（例如只有 `{"$xyz": 1}`）——仍然是 `UnknownDirective`。

指示詞分兩類：

- **取值指示詞**（`$env`／`$fmt`／`$ref`）：`$env`／`$ref` 的值是字串，`$fmt` 的值是物件。
  它會被「解」成另一個值，解出來的東西當成本來就寫在那一格。
- **選項物件**（`$opt`，可選 `$val`）：這一類**不取值**，是「幫這一格加選項」（例如：附加寫入、
  先建目錄、繼承標準輸入）。真正要放進這一格的值是 `$val`（沒有 `$val` 就是這格保持原本的
  預設值，只是加了選項）。判定指示詞時，含 `$opt` 的物件照優先順序最先跑；其他 `$` 開頭的
  key（含 `$ref`／`$fmt`／`$env`、舊的 `$envs`）一律忽略，不會被讀取也不會報錯。

## 2. 先解、再驗；巢狀

解析永遠是**先把指示詞展開，展開完再驗型別**，不是邊解邊驗：

1. 看這一格的值是不是指示詞。
2. 是的話，解開一層，換成解出來的值。
3. 解出來的東西**還是指示詞就繼續解**（巢狀），直到不是指示詞為止。
4. 最後才照「那一格本來該有的型別」去驗——這一步是**宿主規範的事**，不是指示詞機制管的。

`$val` 的值一樣可以再是指示詞（`$env`／`$fmt`／`$ref`），一樣照上面的流程解到底、再驗。

指示詞機制不知道、也不管某一格「應該」是字串還是陣列還是物件；它只負責把指示詞換成值，
換完之後型別驗不驗得過，是那一格自己（宿主規範）的判斷。

## 3. 三種取值指示詞

| 指示詞 | 解出來是 | 意思 |
|---|---|---|
| `{"$env":"NAME"}` | 字串 | 讀**解析者自己的**環境變數 `NAME`。不存在＝錯誤；存在但是空字串＝解出空字串（這是兩件不同的事） |
| `{"$fmt":{"$val":"模板", "變數名":值, …}}` | 字串 | 字串模板代換：值是物件，`$val` 是模板、其餘 key 是本地變數表，見 3.1 |
| `{"$ref":"file.json#/a/b"}` | 任何 JSON | 讀另一份 JSON 檔的一部分，見 3.2 |

### 3.1 `$fmt`：字串模板

外形像 repo 既有那一套（[data-files-fmt](../../wf/workflows/common/data-files-fmt.md)），但這裡
**沒有 namespace**。只有一種寫法：值是物件，`$val` 是模板，其餘 key 是「本地變數表」：

    {"$fmt": {"$val": "aaa${xxx}, bbb${zzz}", "xxx": {"$env":"yyy"}, "zzz": "haha"}}

要用環境變數，就在變數表裡放一個 `$env`：

    {"$fmt": {"$val": "${p}:/opt/bin", "p": {"$env": "PATH"}}}

**模板本身怎麼展開：**

- 只有 `${…}` 會被代換；單獨的 `$`、或 `$NAME`（沒有大括號）都是**字面**，不展開、不用跳脫。
- `${name}` **只查本地變數表**，沒有任何 namespace、沒有任何特例；表裡沒有這個名字 →
  `UnknownFormatVariable`，不會用猜的。
- **展開一次、不再掃結果**：代換進來的變數值裡如果又出現 `${…}`，就當字面，不會再展開。

**變數表的規則：**

- `$val` **必填**：這是模板本身；它自己可以再是指示詞（`$env`／`$ref`／`$fmt`…），解完
  必須是字串，不是字串 → `DirectiveValueTypeMismatch`。
- `$val` 以外的每個 key 都是**本地變數名**，值可以是字串，也可以是任何指示詞
  （`$env`／`$ref`／`$fmt`…），解完必須是字串，不是字串 → `DirectiveValueTypeMismatch`。
  變數的值跟這份 `$fmt` 用同一個中心路徑／同一條 `$ref` 鏈解，怎麼定中心路徑是宿主規範的事
  （見第 3.2 節、第 5 節）。
- 變數名不能 `$` 開頭、不能是空字串、不能含 `{`、`}` → `FormatVariableInvalid`（新代號）。
- 定義了但模板沒用到的變數沒關係，不算錯。

`$fmt` 的值不是物件 → `DirectiveValueTypeMismatch`（舊的字串寫法不再認得）。

### 3.2 `$ref`：讀另一份 JSON

`{"$ref":"file.json#/a/b"}`：

- 相對路徑相對於**「中心路徑」**去找檔案；中心路徑是什麼由**宿主規範決定**（例如 inst 是
  解出來的 `cwd`，不是這份指示詞所在的檔案）。絕對路徑照字面用。
- `#` 後面是 RFC 6901 JSON Pointer：`~1` 還原成 `/`、`~0` 還原成 `~`；物件用 key、陣列用
  十進位索引。**沒有 `#`** 就是取整份檔案。
- 取回來的值**原樣**放進那一格——字串、陣列、物件都可能，型別由那一格自己驗（第 2 節）。
- 取回來的東西如果又是指示詞，照第 2 節繼續解。

## 4. 選項物件：`$opt` / `$val`

形狀固定三種寫法：

```json
{"$opt": "名字"}
{"$opt": "名字", "$val": 值}
{"$opt": ["名字1", "名字2"], "$val": 值}
```

- `$opt` 的值是**字串**或**非空字串陣列**；別的型別＝`DirectiveValueTypeMismatch`。陣列裡
  同一個名字重複＝`UnknownOption`。
- 選項物件只**讀 `$opt`、`$val`** 這兩個 key，其他 key（含 `$ref`／`$fmt`／`$env`、舊的
  `$envs`）**一律忽略**，不會報錯。**這是個容易踩的坑**：舊寫法
  `{"$opt":"clear","$envs":{…}}` 不會報錯，但 `$envs` 被忽略，等於只剩 `{"$opt":"clear"}`——
  結果是清成**空環境**，不是 `$envs` 裡那些值（詳見第 7 節）。
- 選項名字全部**小寫**、區分大小寫。
- 「這個位置認得哪些選項名、哪些選項要求一定要帶 `$val`、哪些不准帶 `$val`、哪些選項彼此
  互斥」——**全部由宿主規範決定**，本文不定義任何實際的選項名字。宿主規範也決定「這個位置
  根本不准用 `$opt`」的位置（例如 inst 的 `argv` 元素）回 `UnknownOption`——「這格沒有任何選項可用」。
- 不認得的選項名＝`UnknownOption`；帶了不該帶的 `$val`、漏了必帶的 `$val`、或選了互斥的
  選項組合＝`OptionConflict`。


## 5. 循環

`$ref` 沿著一條鏈記「檔案 realpath ＋ pointer」這個身分，任何深度都記；同一條鏈裡再撞到
同一個身分＝`ReferenceCycle`。頂層直接寫 `{"$ref":"自己"}` 也擋得到。

**這條鏈是「每個值的位置各自算一條」，不是整份文件共用一條**（讀程式碼確認：每個欄位、
`argv` 的每個元素、`envs` 的每個值，呼叫解析時都是從一個全新的空鏈 `[]` 開始）。所以同一份
`$ref` 目標，只要不是在同一條解析路徑上遞迴繞回自己，被兩個不同的欄位各自引用一次是完全
合法的，不會被誤判成循環。

## 6. 錯誤代號

| 代號 | 什麼時候 |
|---|---|
| `UnknownDirective` | 物件有 `$` 開頭的 key，但沒有一個是 `$opt`／`$ref`／`$fmt`／`$env`（其他不是 `$` 開頭的 key 一律忽略，不影響判定） |
| `DirectiveValueTypeMismatch` | `$env`／`$ref` 的值不是字串；`$fmt` 的值不是物件；`$fmt` 的 `$val` 或任一變數解完不是字串；或 `$opt` 的值不是字串也不是非空字串陣列 |
| `FormatVariableInvalid` | `$fmt` 變數表裡，`$val` 以外的變數名 `$` 開頭、是空字串、或含 `{`、`}` |
| `UnknownOption` | `$opt` 的值不是這個位置認得的選項名；陣列裡同一個名字重複；或這個位置根本不吃 `$opt`（選項物件裡其他 key 一律忽略，不影響判定） |
| `OptionConflict` | 該帶 `$val` 沒帶、不該帶卻帶了、或選了互斥的選項組合 |
| `EnvironmentVariableMissing` | `$env` 指的變數不存在 |
| `UnknownFormatVariable` | `$fmt` 模板裡的 `${name}` 不在變數表裡 |
| `ReferenceReadFailed` | `$ref` 指的檔讀不到 |
| `ReferenceJsonInvalid` | `$ref` 指的檔不是合法 JSON |
| `ReferencePointerInvalid` | `#` 後面的 pointer 語法錯，或在文件裡走不到 |
| `ReferenceCycle` | `$ref` 鏈繞回同一個身分 |

`FieldTypeMismatch`（解完之後型別不對）不在這張表——那是「那一格該是什麼型別」的判斷，
屬於宿主規範，不是指示詞機制的錯誤。

## 7. 容易踩的

- 一般物件的 key **不能 `$` 開頭**：只要出現就會讓整個物件被當成指示詞看，不會被當成一般
  巢狀資料。這是這套機制天生的限制，沒有跳脫寫法。
- 指示詞**只能拿來產生「值」，不能拿來產生「key」**——JSON 的 key 本來就只能是字面字串。
- **可以混寫**：一個物件裡出現不只一個 `$` 開頭的指示詞 key，**不會報錯**——照優先順序
  （`$opt`＞`$ref`＞`$fmt`＞`$env`）只跑排最前面的那一個，其餘（包括不是 `$` 開頭的 key）
  一律忽略。例：`{"$ref":"e.json","X":"1"}` 會跑 `$ref`，`X` 忽略；`{"$ref":"a.json","$fmt":{...}}`
  也只跑 `$ref`。
- **`$envs` 的坑**：選項物件只認 `$opt`／`$val`，舊寫法
  `{"$opt":"clear","$envs":{"LANG":"C"}}` 裡的 `$envs` 會被忽略，不會報錯——結果等於
  `{"$opt":"clear"}`，清成**空環境**，不是 `$envs` 裡那些值。遷移舊寫法時要把 `$envs`
  改成 `$val`，不能只是留著。

## 8. 誰用這套

目前唯一的使用者是 [inst-posix.md](./inst-posix.md)：它定義了 `stdin`／`stdout`／`stderr`／
`exit`／`cwd`／`envs` 每個位置認得哪些 `$opt` 選項名、中心路徑（`$ref` 的 base）是解出來的
`cwd`。以後如果有別種 JSON 文件也想用指示詞，一樣是宿主規範自己定義「這個位置認得哪些
選項名」，機制本身（第 1～6 節）不用重寫。
