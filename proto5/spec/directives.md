# 指示詞：讓 JSON 的值「從別處來」

← [proto5 README](../README.md)｜實作：[proto5/lib/aos_directives.py](../lib/aos_directives.py)（[lib README](../lib/README.md)）；proto4-3 的 `aos_inst_resolve.py` 是凍結的舊版參考

這份文件講的是**指示詞這套機制本身**，不是某一種 JSON 文件（例如 inst.json）該有哪些欄位。
規範先行：程式照本文做；程式跟本文對不上、又不是本文寫錯的地方，回來改本文。

一句話：**指示詞**是 JSON 文件裡「這一格的值不是字面寫死的，是從別處取來的」的統一寫法——
從解析者自己的環境變數取、拼一段字串、或去讀另一份 JSON 檔的某個位置。哪份文件用這套機制
（例如 inst.json）是那份文件自己的規範（「宿主規範」）決定的；本文只管機制本身怎麼運作。

## 1. 什麼算指示詞

一個 JSON 物件（dict）**只要有 `$` 開頭的 key，就當指示詞看**——不會被當成一般的巢狀物件。
這代表：一般物件的 key **不能** `$` 開頭，不然會被誤認成指示詞（見第 7 節）。

物件裡除了指示詞的 key，**可以有任何其他 key，一律忽略**（例如 `_note`、`x` 之類的說明用
key）。如果同一個物件裡同時出現不只一個指示詞 key（`$opt`／`$ref`／`$fmt`／`$env`），
只跑**優先順序最高**的那一個，其餘全部忽略——優先順序是：

    $opt  >  $ref  >  $fmt  >  $env

例：`{"$ref": "a.json", "$fmt": {...}}` 只跑 `$ref`，`$fmt` 不看；`{"$ref": "a.json", "_note": "說明"}`
也只跑 `$ref`，`_note` 忽略。

有 `$` 開頭的 key、但四個都不是（例如只有 `{"$xyz": 1}`）——仍然是 `UnknownDirective`。

指示詞分兩類：

- **取值指示詞**（`$env`／`$fmt`／`$ref`）：`$env`／`$ref` 的值是字串，`$fmt` 的值是物件。
  它會被「解」成另一個值，解出來的東西當成本來就寫在那一格。
- **選項物件**（`$opt`，可選 `$val`）：這一類**不取值**，是「幫這一格加選項」（例如：附加寫入、
  先建目錄、繼承標準輸入）。真正要放進這一格的值是 `$val`（沒有 `$val` 就是這格保持原本的
  預設值，只是加了選項）。判定指示詞時，含 `$opt` 的物件照優先順序最先跑；其他 `$` 開頭的
  key（含 `$ref`／`$fmt`／`$env`）一律忽略，不會被讀取也不會報錯。

## 2. 先解、再驗；巢狀

解析永遠是**先把指示詞展開，展開完再驗型別**，不是邊解邊驗：

1. 看這一格的值是不是指示詞。
2. 是的話，解開一層，換成解出來的值。
3. 解出來的東西**還是指示詞就繼續解**（巢狀），直到不是指示詞為止。
4. 最後才照「那一格本來該有的型別」去驗——這一步是**宿主規範的事**，不是指示詞機制管的。

`$val` 的值一樣可以再是指示詞（`$env`／`$fmt`／`$ref`），一樣照上面的流程解到底、再驗。

指示詞機制不知道、也不管某一格「應該」是字串還是陣列還是物件；它只負責把指示詞換成值，
換完之後型別驗不驗得過，是那一格自己（宿主規範）的判斷。

## 3. 三種取值指示詞

| 指示詞 | 解出來是 | 意思 |
|---|---|---|
| `{"$env":"NAME"}` | 字串 | 讀**解析者自己的**環境變數 `NAME`。不存在＝錯誤；存在但是空字串＝解出空字串（這是兩件不同的事） |
| `{"$fmt":{"$val":"模板", "變數名":值, …}}` | 字串 | 字串模板代換：值是物件，`$val` 是模板、其餘 key 是本地變數表，見 3.1 |
| `{"$ref":"file.json"}`（可選 `"$at":"/a/b"`） | 任何 JSON | 讀另一份 JSON 檔（或目前文件）的某個位置，見 3.2 |

### 3.1 `$fmt`：字串模板

外形像 repo 既有那一套（[data-files-fmt](../../wf/workflows/common/data-files-fmt.md)），但這裡
**沒有 namespace**。只有一種寫法：值是物件，`$val` 是模板，其餘 key 是「本地變數表」：

    {"$fmt": {"$val": "aaa${xxx}, bbb${zzz}", "xxx": {"$env":"yyy"}, "zzz": "haha"}}

要用環境變數，就在變數表裡放一個 `$env`：

    {"$fmt": {"$val": "${p}:/opt/bin", "p": {"$env": "PATH"}}}

**模板本身怎麼展開：**

- 只有 `${…}` 會被代換；單獨的 `$`、或 `$NAME`（沒有大括號）都是**字面**，不展開、不用跳脫。
- `${name}` **只查本地變數表**，沒有任何 namespace、沒有任何特例；表裡沒有這個名字 →
  `UnknownFormatVariable`，不會用猜的。
- **展開一次、不再掃結果**：代換進來的變數值裡如果又出現 `${…}`，就當字面，不會再展開。

**變數表的規則：**

- `$val` **必填**：這是模板本身；它自己可以再是指示詞（`$env`／`$ref`／`$fmt`…），解完
  必須是字串，不是字串 → `DirectiveValueTypeMismatch`。
- `$val` 以外的每個 key 都是**本地變數名**，值可以是字串，也可以是任何指示詞
  （`$env`／`$ref`／`$fmt`…），解完必須是字串，不是字串 → `DirectiveValueTypeMismatch`。
  變數的值跟這份 `$fmt` 用同一個中心路徑／同一條 `$ref` 鏈解，怎麼定中心路徑是宿主規範的事
  （見第 3.2 節、第 5 節）。
- 變數名不能 `$` 開頭、不能是空字串、不能含 `{`、`}` → `FormatVariableInvalid`。
- 定義了但模板沒用到的變數沒關係，不算錯。

`$fmt` 的值不是物件 → `DirectiveValueTypeMismatch`（舊的字串寫法不再認得）。

### 3.2 `$ref` + `$at`：讀另一份 JSON 的某個位置

`$ref` 決定讀**哪份檔案**（或不讀檔案，就用目前這份），`$at` 決定要文件裡的**哪個位置**：

```json
{"$ref": "a.json"}                       整份 a.json
{"$ref": "a.json", "$at": "/x/y/0"}      a.json 裡的 /x/y/0（開頭 / ＝從那份文件的根算）
{"$ref": "",       "$at": "/envs/PATH"}  $ref 空字串＝「這個值所在的那份檔案」自己
{"$ref": "",       "$at": "./a", "a": true}   ./ ＝這個指示詞物件自己的位置 → 它的 key a → true
{"$ref": "",       "$at": "../GREET"}    ../ ＝往上一層（兄弟 key）
```

**`$ref`：找哪份檔案**

- `$ref` 的值一定是字串（不是 → `DirectiveValueTypeMismatch`）。
- 非空字串：當**檔名**看。相對路徑相對於**「中心路徑」**去找檔案；中心路徑是什麼由**宿主
  規範決定**（例如 inst 是解出來的 `cwd`，不是這份指示詞所在的檔案）。絕對路徑照字面用。
- **空字串 `""`**：特指「**目前正在解析的這份文件**」——可能是頂層 inst.json 本身，也可能是
  透過某個 `$ref` 取進來、這個值目前所在的那份檔（見「目前文件／目前位置」）。
- **`$ref` 字串也可以自己帶 `#位置`**，等同另外寫一個 `$at`：

  ```json
  {"$ref": "main.json#/a/b"}        ＝ {"$ref": "main.json", "$at": "/a/b"}
  {"$ref": "main.json#./a/b"}       別的檔的「目前位置」＝它的根，所以 ＝ /a/b
  {"$ref": "#../GREET"}             檔案空＝目前文件，從目前位置往上
  {"$ref": "", "$at": "../GREET"}   同上
  ```

  `$ref` 字串以**第一個 `#`** 切開：前面當檔案（空字串＝目前文件），後面當位置字串，語法
  跟 `$at` 完全一樣；沒有 `#` ＝整份文件。代價：檔名裡真的含 `#` 的檔沒辦法用 `$ref` 指到。
  `$at` key 跟字串裡的 `#位置` **同時出現時，`$at` 贏**，字串裡 `#` 後面那段整段忽略。

**`$at`：文件裡的哪個位置**

- `$at` 可省——省了＝整份文件；有寫必須是字串（不是 → `DirectiveValueTypeMismatch`）。
- 用 `/` 分段解讀：
  - 整個 `$at` 以 `/` 開頭 ＝**絕對**，從「`$ref` 指到的那份文件」的根算起（例如 `/x/y/0`）。
  - 整個 `$at` 第一段是 `.` 或 `..`（也就是以 `./` 或 `../` 開頭，或整串就是 `.`／`..`）＝
    **相對於「目前位置」**，不分 `$ref` 指的是目前文件還是別的檔，統一這樣算：
    - `$ref` 指**目前文件**（`$ref:""`）——目前位置＝這個指示詞物件自己在文件裡的位置；
    - `$ref` 指**別的檔**（非空字串）——目前位置＝那份檔的**根**（`/`）。
    所以 `x.json#./a` ＝ `/a`；`x.json#../a` 從根再往上爬，爬過根 → `ReferencePointerInvalid`。
  - 之後每一段：`.` 段＝略過（留在原地）、`..` 段＝往上一層（回到父層，也就是兄弟 key／元素
    那一層），爬過文件的根 → `ReferencePointerInvalid`。
  - 其餘段是實際要走的 key 或索引：`~1` 還原成 `/`、`~0` 還原成 `~`；物件用 key 對應、陣列用
    十進位索引；走不到 → `ReferencePointerInvalid`。
  - 不是以 `/`、`.`、`..` 開頭的 `$at`（例如 `"x/y"`）→ `ReferencePointerInvalid`。
  - 單獨一個 `.`（$at 整串就是 `"."`）＝目前位置本身，不移動——常拿來測循環，見第 5 節。

**目前文件／目前位置，以及取值後怎麼繼續解**

- 頂層 inst.json（或任何宿主文件）一開始，「目前文件」就是它自己、「目前位置」是根 `/`。
- **「位置」一律是原始 JSON 裡的實體路徑**，連 `$fmt`、`$val`、`$opt` 這些指示詞自己的 key
  都算一段，不會被跳過：`argv` 第一個元素是 `/argv/0`；`envs.PATH` 若是一般字串就是
  `/envs/PATH`，若是 `$fmt` 物件，變數 `p` 的位置是 `/envs/PATH/$fmt/p`、模板本身
  （`$val`）的位置是 `/envs/PATH/$fmt/$val`；一個選項物件的值位置是（例如）`/stdout/$val`。
  這樣 `$fmt` 的變數之間才能互相指來指去，例如 `"b": {"$ref": "", "$at": "../a"}` 從
  `/envs/PATH/$fmt/b` 往上一層就到 `/envs/PATH/$fmt/a`。
- `$at` 的空段（例如整段 `"/"`、或 `./` 結尾留下的那個空字串）照 RFC 6901 當 key `""`，
  不會被略過。
- 取回來的值**原樣**放進那一格——字串、陣列、物件都可能，型別由那一格自己驗（第 2 節）。
- 取回來的東西如果又是指示詞，繼續解時「目前文件」換成剛剛被 `$ref` 指到的那份檔、「目前
  位置」換成剛剛取到的位置。所以解析器要一路帶著「(目前文件的 realpath，目前文件的根物件，
  目前位置的 pointer)」這三樣往下傳，`$ref:""`／相對 `$at` 才有東西可以比對。

## 4. 選項物件：`$opt` / `$val`

形狀固定：

```json
{"$opt": 任何值}
{"$opt": 任何值, "$val": 值}
```

- `$opt` 的值**什麼型別都可以**（字串、數字、物件、陣列、`null`……）——機制本身**不解讀、
  不驗型別、也不解裡面的指示詞**，原樣交給宿主規範去判斷。「`$opt` 該是什麼形狀」是宿主
  規範自己定義的事，不是指示詞機制管的。
- `$val` 是「本來要直接寫在那一格的值」，型別照那一格的規則驗；`$val` 本身**可以再是
  指示詞**（`$env`／`$fmt`／`$ref`），解完再驗。
- 選項物件只**讀 `$opt`、`$val`** 這兩個 key，其他 key（含 `$ref`／`$fmt`／`$env`）**一律忽略**，不會報錯。
- 「這個位置認得哪些選項、`$opt` 該是什麼形狀、哪些選項要求一定要帶 `$val`、哪些不准帶
  `$val`、哪些選項彼此互斥」——**全部由宿主規範決定**，本文不定義任何實際的選項名字或
  型別規則。宿主規範也決定「這個位置根本不准用 `$opt`」的位置怎麼算錯。
  - 舉例：inst 規範（見 [inst-posix.md](./inst-posix.md) 3.3）自己約定 `$opt` 是「選項名
    字串」或「非空選項名字串陣列」，陣列裡名字重複算錯、選項名區分大小寫只認小寫——這是
    inst 這個宿主自訂的慣例，不是機制本身的規定，別的宿主可以用別的形狀。
- 不認得的選項＝`UnknownOption`（由宿主的選項表決定認不認得）；帶了不該帶的 `$val`、漏了
  必帶的 `$val`、或選了互斥的選項組合＝`OptionConflict`（同樣由宿主的選項表決定）。


## 5. 循環

`$ref` 沿著一條鏈記身分：**(檔案的 realpath，解出來的絕對位置)**，任何深度都記；同一條鏈裡
再撞到同一個身分＝`ReferenceCycle`。例如 `{"$ref":"", "$at":"."}`——指到「目前文件、目前
位置」自己——直接算循環。

**這條鏈是「每個值的位置各自算一條」，不是整份文件共用一條**：宿主每解一格（每個欄位、
`argv` 的每個元素、`envs` 的每個值）都從空鏈開始；但宿主若是拿著 `$ref` 取回來的容器**繼續往裡面解**
（lib 的 `resolve_located`），鏈要跟著帶進去，不然走進取回來的容器再繞回自己會無限遞迴。所以同一份
`$ref` 目標，只要不是在同一條解析路徑上遞迴繞回自己，被兩個不同的欄位各自引用一次是完全
合法的，不會被誤判成循環。

## 6. 錯誤代號

| 代號 | 什麼時候 |
|---|---|
| `UnknownDirective` | 物件有 `$` 開頭的 key，但沒有一個是 `$opt`／`$ref`／`$fmt`／`$env`（其他不是 `$` 開頭的 key 一律忽略，不影響判定） |
| `DirectiveValueTypeMismatch` | `$env`／`$ref` 的值不是字串；`$at` 有寫但不是字串；`$fmt` 的值不是物件；`$fmt` 的 `$val` 或任一變數解完不是字串 |
| `FormatVariableInvalid` | `$fmt` 變數表裡，`$val` 以外的變數名 `$` 開頭、是空字串、或含 `{`、`}` |
| `UnknownOption` | `$opt` 不是這個位置認得的選項；或這個位置根本不吃 `$opt`——**由宿主的選項表決定**（選項物件裡 `$opt`／`$val` 以外的 key 一律忽略，不影響判定） |
| `OptionConflict` | 該帶 `$val` 沒帶、不該帶卻帶了、或選了互斥的選項組合——**由宿主的選項表決定** |
| `EnvironmentVariableMissing` | `$env` 指的變數不存在 |
| `UnknownFormatVariable` | `$fmt` 模板裡的 `${name}` 不在變數表裡 |
| `ReferenceReadFailed` | `$ref` 指的檔讀不到 |
| `ReferenceJsonInvalid` | `$ref` 指的檔不是合法 JSON |
| `ReferencePointerInvalid` | `$at` 語法錯（不是 `/`、`.`、`..` 開頭）、相對寫法（`.`／`..`）爬過所在文件的根、或在文件裡走不到 |
| `ReferenceCycle` | `$ref` 鏈繞回同一個身分 |

`FieldTypeMismatch`（解完之後型別不對）不在這張表——那是「那一格該是什麼型別」的判斷，
屬於宿主規範，不是指示詞機制的錯誤。

## 7. 容易踩的

- 一般物件的 key **不能 `$` 開頭**：只要出現就會讓整個物件被當成指示詞看，不會被當成一般
  巢狀資料。這是這套機制天生的限制，沒有跳脫寫法。
- 指示詞**只能拿來產生「值」，不能拿來產生「key」**——JSON 的 key 本來就只能是字面字串。
- **可以混寫**：一個物件裡出現不只一個 `$` 開頭的指示詞 key，**不會報錯**——照優先順序
  （`$opt`＞`$ref`＞`$fmt`＞`$env`）只跑排最前面的那一個，其餘（包括不是 `$` 開頭的 key）
  一律忽略。例：`{"$ref":"e.json","X":"1"}` 會跑 `$ref`，`X` 忽略；`{"$ref":"a.json","$fmt":{...}}`
  也只跑 `$ref`。

## 8. 誰用這套

目前唯一的使用者是 [inst-posix.md](./inst-posix.md)：它定義了 `stdin`／`stdout`／`stderr`／
`exit`／`cwd`／`envs` 每個位置認得哪些 `$opt` 選項名、中心路徑（`$ref` 的 base）是解出來的
`cwd`。以後如果有別種 JSON 文件也想用指示詞，一樣是宿主規範自己定義「這個位置認得哪些
選項名」，機制本身（第 1～6 節）不用重寫。
