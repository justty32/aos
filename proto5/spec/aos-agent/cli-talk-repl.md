# 1.9 `talk`：來回對話（09-24 talk 補）

```
aos-agent talk [--target DIR] [--wait 秒] [--show-calls]
```

使用者定的（09-24）：極簡版的來回 `say`／`listen`，像 REPL；不求 Claude Code 那種體驗，Ctrl-C 就退出。
（`cli-talk.md` 已是 §1.2／§1.5，這份另取名。）

讀一行 → 照 §1.2 投進 `input` 第一條 → 等這一句的回話、印出 → 再讀一行。純標準庫：`input()`，有 `readline` 就載（方向鍵、上一句）。不要 `AOS_KERNEL_HOME`（有設就拿來看登記狀態，同 `status`）。

## 旗標

| 旗標 | 意思 |
|---|---|
| `--target DIR` | 家；省略＝目前資料夾（§1） |
| `--wait 秒` | 每句最多等幾秒；省略＝**120**（比 `say --wait` 的 300 短：人在前面等）；`0`＝不等，送出就回提示符。秒數規則同 §1（0～604800、可帶小數），不帶數字、不是數字＝用法錯 2 |
| `--show-calls` | 也印工具呼叫與結果的簡化行（下面〈印什麼〉）；預設不印 |

`--json` 不收（用法錯 2）。家不是 agent 家、info 讀驗錯＝進入前就 `NotAnAgent`／§12 的代號、退 1。

## 進入

stderr 印一行 `talk <家>  health <§1.3 health 那句>（/help 看指令，Ctrl-C 或 Ctrl-D 離開）`。health 是 `沒登記`、kernel 家有問題、手動暫停、連敗暫停、`bad`、家的設定讀不到這幾種不會自己好的，下面多一行「照這樣說話會先投進去、等修好才處理」——**不擋**，照樣進提示符（可以先 `/continue`）。
stdin 是 tty 才印提示符 `> `（stdout 不是終端時提示符寫 stderr，`talk > 紀錄.txt` 不混進 `> `）；stdin 不是 tty（管線餵行）不印提示符，其他一樣。

## 一句話怎麼等（不能漏、不能重印）

- **送出之前**記下記憶長度 H0，再投檔；判「這一句回完了」跟 `say --wait` 同一個條件（§1.2）：投的檔已不在、`idle`、沒 `batch`、沒 `intake`、最後一則是 assistant、H0 以後有一則 `content` 等於這句的 user 在它前面。
  所以回話就算在開始等之前就寫進記憶，也算數（不踩 `listen --wait`「開始聽之後才算」的坑）。
  （astra 審查補）「投的檔已不在」認的是**我投的那份**（記下投出去的 inode；原路徑上是別人新投的同名檔也算不在）；而且每輪**先看檔、再讀 state、最後讀記憶**——照 §8 的順序，
  檔已被收、之後 state 又是 `idle`＋沒 `intake`，就代表這句已接進記憶、那一輪走完，同樣的字連送兩次也不會拿前一句的回話充數。記憶讀不到（寫到一半）時下面的停止原因照看。
- talk 另外記一個「印到哪」的位置（進入時＝當下記憶長度，之前的不重印）。每 200 ms 讀一次記憶，這個位置之後的新訊息**邊到邊印**、印完就往後挪，所以同一則不會印兩次。
- 等的時候照 §1.2 的先後看「不會自己好」的（kernel 家有問題、沒登記、手動暫停、連敗暫停、`bad`）：stderr 印 `aos-agent: <代號>: <原因>` 和一行「已投入，不要再說一次；修好後 /wait 等回話，或按 Enter 看到了沒」，回提示符（**不退出**、不印整段 `status`）。
- 逾時：stderr 一行 `（還在想：等了 N 秒。/wait 再等；按 Enter 看到了沒；離開後 aos-agent listen --last --target <家> 也看得到）`，回提示符。
  （不叫人用 `listen --wait`：它只等開始聽之後才到的，回話若已經到了會乾等。）
- **晚到的回話**：每次顯示提示符之前、以及打空行時，先看一次「印到哪」之後有沒有新的，有就印；逾時那一句這一輪走完了就不再算「在等」。
- 等待提示：stdin 與 stderr 都是 tty 時在同一行印 `（等回話 N 秒… Ctrl-C 離開）`，回話要印之前先清掉；否則不印。

## 印什麼

- 回話（stdout）：assistant 的 `content` 原樣；中途叫工具時附的那句（例如「讓我查查」）到了就先印。自己打的 user 不回印；別人從別處投的 user 也不印。
- `--show-calls`（stdout）：每個工具呼叫一行 `[呼叫 <名> k=v …]`（參數是 JSON 物件就攤成 `k=v`，字串原樣、其他照 JSON；不是物件就原樣；換行寫成 `\n`；整段超過 80 字截斷加 `…`），每個結果一行
  `[結果 ok N 行]`（空＝`[結果 ok 空]`）；結果開頭是 §6.2 那幾種 `工具 <名> 逾時／失敗／無法執行／沒跑…` 的字串＝`[結果 失敗 <第一行原樣>]`（只看字串開頭，不靠前面的呼叫），是「結果不明」那個固定字串＝`[結果 不明：工具可能跑了也可能沒有]`。
  格式跟 `listen --show-calls` 儘量對齊。
- 提示、錯誤、逾時、卡住的原因一律 stderr；stdout 只有回話與 slash 指令的輸出（拿 stdout 當對話紀錄不會吃到雜訊）。

## slash 指令

提示符打 `/` 開頭＝指令，**不送給模型**。要把 `/` 開頭的字送出去就打兩個：`//status 是什麼` 送出 `/status 是什麼`。空行（含只有空白）不送。送出的字去掉頭尾空白。

| 指令 | 一句話 |
|---|---|
| `/status [-v]` | 一行：`health <…>  state <…>  batch <kind 收回／總數 或 ->  input <N 個沒收 或 ->`，還在等上一句就加 `還在等上一句`；state 讀不到＝`state ?  batch ?`；`-v` 印整段 `status -v` |
| `/context [N]` | 現在每次問模型會送的東西（aos-llm §4：人格＋整份記憶＋工具）：模型代號與池、system 幾字、history 幾則幾字（user／assistant／tool 各幾則；字數算 `content` 與工具參數）、工具幾個幾字與名字、合計，最後列最近 N 則（預設 3，一則一行、整行 80 字截斷）；＝[`context`](cli-memory.md) |
| `/history [N]` | 記憶最後 N 則（預設 10）：`user: …`、`assistant: …`（全文，帶 `[呼叫 …]`）、工具結果印成 `[結果 …]` 那種短行 |
| `/tools` | 工具一行一個：`<名>  <description 第一行>` |
| `/wait [秒]` | 上一句逾時還沒回：照原來那句再等（秒數省略＝`--wait` 的值）；沒有在等的＝先補印晚到的、再印「（沒有在等的話）」 |
| `/pause` | 同 `aos-agent pause`（§1.6） |
| `/continue` | 同 `aos-agent continue`（§1.4，只解這個家） |
| `/help` | 印這張表和上面那兩條規矩 |
| `/quit`（`/exit`） | 離開，同 Ctrl-D |

不認得的 `/xxx`＝stderr `沒有這個指令，/help 看清單（要把 / 開頭的字送給模型就打兩個 //）`，不送、不退出。指令的參數錯（例如 `/history 0`、`/wait abc`；`/tools`、`/pause`、`/continue`、`/help`、`/quit` 帶任何參數也算）＝stderr 一行 `aos-agent: Usage: …`，不執行、不退出。

## 離開

Ctrl-C（任何時候，包括剛進入、等回話中）、Ctrl-D／stdin 讀到 EOF、`/quit` 都**退 0**，不留半截狀態：talk 自己不寫 `state.json`、不拿 tick 鎖，只投檔（投檔是原子的，§1.2）。
投檔＋記下「在等這句」、`/pause`、`/continue` 這三段是一組做完的：中途按 Ctrl-C 先記著，做完才離開（不會投了卻沒提醒、不會留半截暫停檔或只解一半）。
離開前再看一次（晚到的回話先補印）；還有一句沒回（逾時或卡住那種），stderr 多一行「上一句還沒回；話已投入，回話會進記憶，之後 `aos-agent listen --last --target <家>` 看」——回話照常由 tick 寫進記憶，不會因為 talk 走了就丟。
一句話投檔失敗（例如單一檔的 `InputBusy`）＝stderr `aos-agent: <代號>: …`，回提示符。

## 保證外

- 同一個家開兩個 talk、或 talk 開著時另有人 `say`：各自的回話判法不受影響，但「印到哪」之後的 assistant 都會印，所以可能看到別人那句的回話。
- 人在 talk 開著時把記憶改短：從新的長度重新算，改掉的那段不補印；短到比那句送出時還短，就不再追那句，stderr 說「記憶被改短了，追不到剛才那句」。
