## 必修

- `proto5/lib/aos_market.py:296、493`：撥款與市場紀錄不是同一筆交易，崩在逐家撥款途中會重撥，合併崩在「A 加款、B 扣款」之間更會憑空增加額度。修法：先持久化操作 ID 與計畫，帳戶支援依 ID 去重，轉帳以同一筆交易完成，重啟接續未完成操作。

- `proto5/lib/aos_market.py:364、499`：公司搬進 archive 後才儲存市場狀態，這個窗口崩潰會留下「營業中但原目錄消失」，合併重跑也找不到來源。修法：封存前持久化目的地與關閉階段，恢復時同時辨認原目錄及 archive，再完成狀態提交。

- `proto5/lib/aos_market.py:277、311、443`：市場沒有涵蓋讀取、檢查與修改的鎖，並行撥款可突破總池，並行合併可各自使用同一批正式名額，名冊寫入也未使用既有 `roster_lock`。修法：市場操作持有交易鎖，合併依固定順序鎖名冊並重新計算人頭後才提交。

- `proto5/lib/aos_market.py:344、488`；`proto5/lib/aos_company.py:818`：回收／轉移餘額取自停機前快照，且停機失敗仍被忽略，可能把仍在花費的額度與仍占用的 CPU 名額重新發出去。修法：先停止接單、確認工作停止且費用入帳，再結算回收；停機失敗不得封存或釋放名額。

- `proto5/lib/aos_market.py:136`：開戶未拒絕相同或互相包含的公司路徑，不同帳戶可重複認列同一筆消費，重用已封存公司的原路徑也會污染舊帳戶。修法：檢查既有帳戶根目錄的重疊與重用，或讓消費歸屬不可重用的公司世代 ID。

- `proto5/lib/aos_company.py:435、495`：有填但配不到的 `reply_to` 仍會套用單一窗口單的 fallback，而明確配到單號時又允許非窗口成員將 desk 單結案，造成抄錯人或誤結案。修法：fallback 僅限未填 `reply_to`，desk 結案另核對指定窗口身分。

- `proto5/lib/aos_company.py:476、548`：總機單先寫入、之後才把單號存回 seen，中間崩潰會留下孤兒單並重開另一張；董事單在派送前崩潰則沒有恢復入口。修法：先持久化固定單號及派送意圖，讓 relay 接續所有尚未完成派送的訂單。

- `proto5/lib/aos_company.py:391`：門房工具先執行、最後才儲存結果，崩潰重跑會再次執行具有副作用的工具，違反總機冪等保證。修法：工具接受持久化操作 ID 並去重，無此能力的工具不得自動重試不確定是否完成的執行。

- `proto5/lib/aos_market.py:234、299`：grant 後仍沿用上一輪的品質、秒數與結單數，下一輪沒做事也能繼續取得品質及速度分。修法：分數綁定輪次，rank 只接受本輪紀錄，grant 後開啟新的評分輪次。

- `proto5/lib/aos_market.py:189`：規格按「本輪結單」計算，實作卻用下單時間篩選，跨輪完成的工作會永久漏算，且時間直接比較字串。修法：保存明確結案時間，解析為帶時區時間後按輪次區間篩選。

## 建議

- `proto5/lib/aos_market.py:79、212`：市場參數與手動分數缺少型別、範圍及有限值驗證，負秒數、超過 100 的品質或 NaN 都能進入排名／帳戶計算。修法：統一驗證參數與 CLI 輸入，拒絕非有限數及不合法範圍。

- `proto5/lib/aos_company.py:175、364`：兼任部門開著但宿主部門關閉時，`host_dept` 仍回傳宿主，dispatch 隨後因團隊不存在而拋 `KeyError`，中斷整輪總機。修法：驗證宿主實際開放且有團隊，否則正常退信並繼續處理其他信。

- `proto5/lib/aos_company.py:416、564`：董事直接下單命中 tool 時，結果只存在訂單內，既不寄董事信也不由 `mail` 列出。修法：以固定 ID 產生董事可見的結果，或讓 `mail` 納入這類訂單結果。

- `proto5/lib/aos_market.py:462、485`：合併只保留部分成員設定，會遺失 `spawn`／`commons` 覆寫，也沒有替新名字接上公司人格。修法：明確保留可攜設定並轉換路徑，啟動前補齊公司人格及專案規則。

- `proto5/lib/test/test_company.py:339`：唯一崩潰測試只涵蓋「seen 已寫、動作尚未開始」，沒有覆蓋孤兒訂單、工具執行後崩潰、錯誤 reply_to 或非窗口結案。修法：補逐持久化窗口的故障注入，並加入真郵差消費寄件檔後的恢復測試。

- `proto5/lib/test/test_market.py:180、234`：市場測試未覆蓋美元縮額、跨輪評分、並行操作、停機失敗及合併中斷，合併成功測試也沒有實際 kernel。修法：補上述失敗案例及「額度守恆、名額不超限、重試不重撥」斷言，再驗 slots→down/up 的整合路徑。
