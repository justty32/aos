# 互相反駁

## 保留派反駁合併派

**我認的**：
1. **root daemon 更危險**：全認。誰能往 `D/requests/` 丟檔就能拿到 root，daemon 永遠不該是 root。我的 memo 本來就沒選 root，第 5 題改成跟對方同一句：「daemon 永遠不用 root」。
2. **「崩了只丟一格」靠的是每格單獨開一次，不是靠兩支**：認。對方的「縮」有保留這一點，這格我先前沒想到，是好主意。
3. **K2、一個 daemon 管多家**：輕，認。
4. **kernel cpu 和開機交接是真成本**：認。拿掉它是「縮」真正的收益，不只是少一條指令。

**我不認的**：
1. **「一個家」撞 cpu 範式**：範式是「一個家一個主人行程」（[cpu 範式](../../spec/cpu/README.md)）。孩子表由長命爸爸寫，帳本由每格 tick 寫，同一個家就有兩個寫的人。對方說「cpu 範式不動」，這兩句對不上。要嘛帳本另開一個家（那就還是兩個家），要嘛放寬範式（那是要使用者拍的，不是順手改）。
2. **爸爸開始看 `K/requests/`**：那是任何人（包括沒關牢的工具）都能丟檔的收件匣。爸爸只看「有沒有新檔」就還好；一旦要讀內容來決定開不開下一格，握「能拉行程」的那支就在讀不受信的輸入。規範要寫死：**爸爸只看檔在不在，不讀內容**。
3. **延遲不必靠縮**：[idle-wait](../../../proto5-2/notes/2026-09-24-idle-wait/README.md) 的「停車＋有新件就叫醒」在 kernel 裡多 50～80 行就做得到，不用動 daemon。
4. **30～50 行偏樂觀**：爸爸要多管「同時只准一格」「tick 卡住怎麼辦」「tick 連敗要不要停」。現在這些由 kernel cpu 的主人管，搬過來就要重寫這一段，連崩潰測試一起重寫。

**折衷（我願意接受）**：**開機合一、家不合一。** 一條 `aos up`；爸爸有新件或時間到就開一格 tick、拿掉 kernel cpu 與交接；但 `D/` 與 `K/` 仍分兩個家，K 的主人＝「同時只准一格」的 tick（用鎖）。爸爸只看檔在不在、不讀內容，不用 root。這樣對方要的（一條開機、沒交接、崩潰隔離）都拿到，範式和權限分離也都沒破。什麼時候做照對方：proto5-2 重寫 kernel 時順路。

## 合併派反駁保留派

**我認的**：root 那條一致劃掉；現在不動；權限只走 bwrap 牢；真要切使用者走 subuid，開 namespace 的只能是一支一直活著的小行程（第 2 條）；切使用者時 ②④ 出局（否決條件）；「daemon 不常改」還沒被時間證明（第 5 條）。

**逐點回**：
- **第 3 條（崩只丟一格、改了不用重開）**：你也說這來自「每格單獨開一次」。「縮」不是 ②④，tick 照舊每格開一次，這條擋不到縮版。
- **第 4 條（有人收屍）**：縮版的爸爸不跑排程，排程 bug 在 tick 那個孩子身上崩，拖不垮收屍。「爸爸被 KILL，孩子不跟著死」現在的 daemon 一樣有，跟合不合無關。
- **第 1、2 條（握權力的不該讀不受信的單子）**：現在的 daemon 本來就照 `D/requests/` 裡任何人丟的單子拉程式，分兩支並沒做到這點。你反駁裡的規矩「爸爸只看檔在不在、不讀內容」我全接受。
- **「留一扇門幾乎不花錢」**：不是零。kernel cpu、開機交接、r5 的順序陷阱每天在付，換的是你自己說「需求還沒到」的切使用者。
- **`aos up` 包掉兩步**：現在夠用，我認；但沒拿掉交接和 kernel cpu，是延後不是解掉。

**對你的折衷**：接受「**開機合一、家不合一**」。你說得對：一個家兩個寫的人（爸爸寫孩子表、tick 寫帳本）撞 cpu 範式，我 memo 裡「範式不動」那句寫錯了。30～50 行也偏樂觀，「同時只准一格、卡住、連敗」要搬過來，改估 80～150 行，連崩潰測試。延遲 idle-wait 也能解，我收回「縮才能縮小延遲」。

**合起來的建議**：現在不動；proto5-2 重寫 kernel 時做這個折衷：一條 `aos up`，拿掉 kernel cpu 與交接，`D/`、`K/` 兩個家，爸爸只看檔在不在，不用 root。
