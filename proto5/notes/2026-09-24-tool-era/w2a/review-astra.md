有必修項目，最嚴重的是：**關牢測試仍可能透過案例檔寫到主機外部路徑，以及 `--force` 發布失敗會刪掉舊包。**

只審指定差異，未改檔、未啟動模型或服務。四份測試共 95 條：21 條通過、1 條跳過、73 條因唯讀環境無法建立暫存目錄而出錯，**不能視為整套驗證通過**。以下部分問題另用不落地的記憶體驗證重現。

**必修**

- **M1｜案例檔可繞過牢，寫到 workspace 外。**  
  檔：`proto5/lib/aos_agent_tools_dev.py`，`_suite()`，1053–1056 行。前一個工具只要在 workspace 建立指向主機路徑的符號連結，後面的 `cases.json.files` 就會由**牢外測試器**沿連結寫入。`load_cases()` 只擋絕對路徑與 `..`，擋不住這種方式。建議用 workspace 的目錄 fd 逐層開啟、拒絕符號連結，最後寫檔也加 `O_NOFOLLOW`；不能只在寫前做一次 `realpath`。

- **M2｜`--force` 發布失敗會把舊包一起刪掉。**  
  檔：同上，`publish()`，73–83 行。舊包改名成功後，若 `os.rename(tmp, dest)` 失敗，`finally` 仍刪掉 `old`，新舊兩包都沒了；已用 mock 重現。建議只有新包就位才刪備份，失敗則還原或保留備份。硬中止時也可能留下 `.new-*`／`.old-*`，目前沒有恢復程序。

- **M3｜合法包名會撞掉必要檔案。**  
  檔：同上，`new_files()`、`wrap_py()`，172–176、699–702 行。`new config`、`new cases` 都接受，卻用設定／案例 JSON 蓋掉工具描述；`wrap-py wrap.py` 預設包名 `wrap`，工具描述也會被 `wrap.json` 蓋掉。建議建檔清單前檢查保留名稱與重複路徑，不能讓 dict 靜默覆蓋。

- **M4｜30 秒不是完整上限，巨大輸出也沒有上限。**  
  檔：同上，`Runner.run()`，795–807 行。`communicate()` 把 stdout／stderr 全收進記憶體；大量輸出可耗盡記憶體。逾時後第二次 `communicate()` 沒期限；不關牢時，子程序另開 session 並持有 pipe，或 kill 失敗，就可能一直卡住，也到不了暫存家清理。建議限制輸出量、逾時後限時收尾並關閉 pipe，且清楚回報未能終止的程序。

- **M5｜「沒關牢」是在工具執行完才告知。**  
  檔：同上，`_single()`、`_suite()`，1002、1064 行。兩條路徑都先跑任意程式才印提示；工具卡住或測試器崩潰時，使用者完全看不到。建議在第一次執行前向 stderr 印原因並 flush，JSON 結果仍保留 `jail_note`。教程 08 的「關在牢裡跑」也應補上自動退回的條件。

- **M6｜條件區塊內的函式會被誤收。**  
  檔：同上，`_Finder`、`analyze()`，367 行起。`if False: def never(x: int): ...` 仍列「收」；實際 import 後根本沒有這支函式。同名函式分布在不同分支時，也可能記到錯的簽名。建議只接收直接位於 `Module.body` 的函式，條件式／迴圈／try 裡的定義列拒收。

- **M7｜函式拋 `KeyboardInterrupt` 仍會噴 Traceback。**  
  檔：同上，產生的 `WRAP_RUN.main()`，590 行。只接 `Exception`、`SystemExit`；外層 `_common.run()` 也不接 `KeyboardInterrupt`。已在記憶體重現漏接，違反「例外轉錯誤 JSON、不噴 Traceback」。建議在呼叫使用者函式的邊界完整處理 `BaseException`，並明訂中斷的回傳方式。

- **M8｜刪範例會連後面的正式小節一起刪。**  
  檔：`proto5/tools/wf/_fill.py`，`drop_examples()`，239–248 行。例如 `## 區` 下依序放「下面是範例」、`### 範例`、`### 正式資料`，程式會一直刪到下一個 `##`；已重現正式資料消失。README 寫「下一個同級以上標題」，實作卻用父標題層級。建議用明確的範例起訖標記；不能確定多個小節都屬範例就保留並回報。

- **M9｜「整格是一個佔位」的判斷不成立。**  
  檔：同上，`is_template_row()`，156–161 行。`PH.fullmatch()` 會把 `{{甲}} {{乙}}` 整串當一個匹配，因此 `| {{甲}} {{乙}} | 真資料 |` 也被認為範本列，開 `drop_template_rows` 就整列刪除。建議確認第一格只有一個佔位，且其外沒有其他文字。

- **M10｜名字對應沒有完全遵守公布的規則。**  
  檔：同上，`match()`、`fill_file.repl()`，75–90、283 行起。有兩個已重現的問題：`{{甲}}` 配 `{"甲":"正確"}` 仍不填，因為兩字限制連完全相等也擋掉；`| 時間 | {{日期}} |` 配開始日期、結束日期、時間三條事實時，日期明明歧義，卻繼續用第一格填入時間。建議兩字限制只用於包含比對，歧義則立即停止該佔位的替代比對。此外 `wf.json` 描述稱「only exact matches」，也須改成實際的三層規則。

- **M11｜`mail` 與 `score` 的起點挑法不同。**  
  檔：`proto5/lib/aos_team_mail.py`，`fallthrough_letter()`，55–77 行。mail 排除有 `reply_to` 的人寫 REQUEST，score 沒排除；已重現同一時間窗各選不同信。另外 mail 沒確認開單者真是 lead，也沒沿用 score 的開單歷史時間備援。建議抽成共用選信函式，讓兩者與規範使用同一套判準。

- **M12｜混用有／無時區時間會讓 `mail --task` 出錯。**  
  檔：同上，`fallthrough_letter()`，71、76 行。直接比較 `parse_iso()` 結果，遇到無時區信件與有時區單子會拋 `TypeError`；已重現。帶不同 UTC offset 的時間彼此比較沒問題。建議統一沿用 score 的時間正規化；目前 `_at()` 又把無時區當 UTC，與 score 當本機時間不同，也應統一。

**建議**

- **S1｜sha256 目前只是紀錄。** `WRAP_RUN.load()` 沒核對副本雜湊，改了副本仍照跑。現行規範只要求「記 sha256」，所以不算違約；建議執行前核對，避免簽名與副本脫節。這也不等於能驗證一份同時遭修改的 manifest。
- **S2｜包含比對仍可能填錯。** 例如只有「程式語言」事實時，`{{語言}}` 可能被填成 Python，而原意是回覆語言。這符合目前公布的包含規則；建議只讓明確同義詞自動填，包含命中列為候選。表格解析也宜處理跳脫的 `\|`。
- **S3｜`mail --follow` 看不到題目後續答案。** `seen` 只記 `(kind, id)`，同題從 open 變 answered 不會再印；重新執行 mail 才看得到。建議把題目狀態／答案變更納入更新判斷。
- **S4｜補上 mail JSON 契約。** 信件列保持原樣，新增題目列使用 `kind: ask`、`question/answer/state`，沒有 `text`。repo 內未找到因此壞掉的正式消費程式，但外部讀取者不能保證；規範應列出形狀並要求依 `kind` 分派。

**確認沒問題的**

- **靜態讀不執行原檔。** 字串註解重新 `ast.parse(..., mode="eval")`，不是 Python `eval()`；預設值用 `ast.literal_eval()`。使用者原檔只在產出的工具執行時 import。
- 一般的沒註解、`*args`／`**kwargs`、positional-only、自訂類別、async、decorator、函式／類別內巢狀函式都有拒收；條件區塊例外見 M6。
- runtime 排除 bool 當 int／float，遞迴驗 list／dict，Literal 比值也比型別，混型 Literal 靜態拒收。Optional 預設 null、多給參數的處理符合現行規範；一般例外、import 失敗及常見非 JSON 回傳都有結構化錯誤。
- bwrap 可用時確實隔離：workspace 可寫掛到 `/work/ws`、cwd 同處、網路關閉、程式目錄唯讀，另有系統唯讀掛載與暫存 `/tmp`。正常結束會清掉假家；例外邊界見 M1、M4。
- 包名擋住 `/`、`..` 與絕對路徑；現有目的地符號連結即使 `--force` 也拒絕。`--out` 可指定任意既存目錄，也會跟隨父路徑連結；`--force` 替換的是**整個同名資料夾**。
- `wf_fill` 掃描只處理 `.md`，正常靜態目錄下不跟隨符號連結，與 `wf_init` 共用目錄鎖，每檔原子替換。facts 使用共用 `resolve()` 圍籬：不關牢是工作根，關牢是整個 `/work`，不僅 `/work/ws`。有效時區的「今天」換算正確；無效時區會靜默退回本機。
- `route try` 路徑只讀規則、比對及列印，沒有跑工具、開單、寄信或寫 route.log。
- importer 確實列出 10 支工具；mail 分派、郵差／心跳標籤、交接驗收提示及教程的 route try 段落與程式一致。
