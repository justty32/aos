## 一頁摘要

**六軸**：ai_core 的九軸是「函式怎麼跑」的描述，不是打分；講好壞的是它的治理原則「LLM 預設不准進來，證明非它不可又夠穩才放行」。
評分表＝使用者的五句（LLM 少、穩、省資源、快、人易懂）＋我補的「邊界」（碰得到什麼、壞了收不收得回），每軸 1～5，不加總、只看最低兩軸。穩定軸跑滿 10 次才給分。

**workflows 變團隊**：workflows 是一套以 Markdown 為主、給 agent 照做的手冊（派發表、信箱、SESSION-LOG／WAIT_USER、心跳、Done when），**本身沒有執行引擎**——aos 正好補上。
團隊＝**三種會想的 agent**（領隊：拆派收；工人：照工作流做事；審查：只判要人判斷的驗收條目）＋**四個不會想的機械員**（門房：前濾網，命中就不叫模型；郵差兼書記：搬信、開單、改任務狀態、記帳、報停滯；驗收員：跑固定檢查器；心跳：routines／schedule 到期就派）。不是每件事都要三種 agent 都上。
交流全用現有的「投檔進 `input/`」：agent 寄信只寫團隊資料夾裡自己的 `outbox/`，郵差搬、每封留投遞紀錄兼去重；agent 只在閒著時收信；沒有「等回信」工具（proto2 教訓：模型會自己等自己）。

**工具**：30 個，**工具本身**會叫模型的只有 1 個（`wrap-cli`，第三波）。「讀一個 python 檔納入工具」＝`tools wrap-py`，用 `ast` 讀型別與 docstring 生 JSON Schema，不 import、不叫模型，不支援的寫法拒收並說原因。`/compact` 預設是機械的（保留最後幾輪、工具輸出換成一行、原文封存、有 token 上限、崩了不丟記憶），叫模型寫摘要是第三波的選項。

**三波**：
- 第一波（**4 隊並行＋收尾 1 隊**，前面先由隊 1 用半天把共用格式定下來合進 main）：骨架（`aos-team`、模板、門房、任務單）、郵差（寄信、郵差＋書記、驗收員、心跳）、檔案＋workflows 工具包（`json_edit`、`md_section`、`wf_*`、`aos-directives`）、記憶與紀錄（事件紀錄、`context`、`compact`、`note`）。
  **第一波不另開新的逃生口，但整體不安全**：工人的 base `bash` 本來就關不住，所以它是信任環境裡的功能原型（拋棄式專案、LiteLLM deepseek）。驗收：真跑「導入 heartbeat 包」「落穿給領隊＋審查」兩個例子（心跳例子可選），看功能過關線；六軸先打一次。
- 第二波（牆合進 main 後，3 隊）：造工具（`tools new／test／wrap-py`）、把第一波全部放進牢並正式重驗六軸（跑滿 10 次）、申請類（碰資料夾、改人格都是「提案，人批」）。
- 第三波（挑著開）：模型生成員、模型寫工具、固化建議（把領隊老在派的句型變成門房規則的候選）等「讓模型做更多」的。

## 審查改了什麼

astra（gpt-6-astra）唯讀審查：必修 15 條、建議 7 條，**全部改進**（[review-astra.md](review-astra.md)）。主要的：

- **M1 第一波不是「沒牆也安全」**：改成「不另開新逃生口、但整體是信任環境的功能原型」；驗收員只跑工具包自帶的固定檢查器、不執行專案裡的檔；`json_edit` 認信任資料看實際設定解出的路徑、不看檔名。
- **M2／M3 郵差**：一封一份投遞紀錄兼去重憑據，投遞前查收件人的 `input/`、`done/`、`intake`；崩在三個窗口都不重投不漏做，測試要讓收件人在窗口裡把信收走。寫明 agent 只在閒著時收信、一次可能多封、同批照檔名不照時間、第一版沒有插話取消。
- **M4 任務狀態機**：單有 `rev`／`attempt`，只認目前負責人對得上版本的回報；驗收不過寄「修正」而不是 FAILED（workflows 的 FAILED＝終止）；`handoff` 一步建單＋派送；`judge` 開審查子任務逐條回。
- **M5 停滯與鎖**：看事件紀錄與健康，不看 idle；只報「觀察到停滯」、同次只報一次；鎖只有持有者放、確認沒在途工具才回收。
- **M6／M7 workflows 包與例子**：帶整棵固定版本快照（`wf-init.sh` 需要 `template/`、`flavors/`）、加 `wf_doc` 讀手冊、`wf_init` 先在 staging 做；例子給固定事實表、加內容檢查、殘留用專門檢查器（`grep -c` 零命中退 1），寫明例子只驗導入這條路，另加落穿＋審查例子。
- **M8 心跳**：`routines.json` 唯一來源、每次到期有 id、在途不重派、每天幾點、漏跑只補一次、只有人登記的列會自動跑。
- **M9 量測**：新增 T-events（每批起訖、成敗、`aos-llm call` 記 usage），歸記憶隊最早做；`ms` 是經過時間不是 cpu 秒；score 只彙整。
- **M10 壓縮**：先寫 archive 再原子替換 history、有 token 上限、沒做完的任務不縮、自動壓縮在 tick 同一把鎖裡做。
- **M11 牆接線**：outbox 從一開始就放團隊資料夾（家是信任資料）；契約是有表就全關，不逐支繞過。
- **M12 並行**：共用格式先行；`aos_agent_cli.py`、tick、共用 README 各指定唯一改動者；交件改 rebase 不 reset。
- **M13 wrap-py**：寫明支援的型別與拒收條件；驗收改用固定 fixture（`find_big_lists.py` 沒註解會全被拒）。
- **M14 門檻**：分數區間補齊互斥；功能過關線與六軸評分分開；資源看實測增量成本；冪等只要求同一請求重試不多做。
- **M15 六軸推論**：刪掉混用兩套編號的推導，改成「這次沒搜到」。
- 建議：workflows 描述改「以 Markdown 為主」、routines 做完改日期不刪、三層是改編（S1）；角色按需上、驗收不在郵差裡同步跑（S2）；門房多重命中與否定詞落穿、規則帶正反例句（S3）；「叫不叫模型」分工具本身與整條流程（S4）；補 `board`、`review_result`、`wait ls`、任務取消與重派、工具骨架改第二波（S5）；一份資料一個寫的人＋`expect_sha`（S6）；重來要重置全部、紀錄保留期、模型扮新手只是代理（S7）。
