# 幾種做法比一比

使用者 09-24 定調：**這些都是「工具存取的別名／映射」，用指示詞表達**。所以下面把「指示詞寫映射」當底，
比較的是「映射寫好之後，**誰來保證**工具真的只碰得到映射裡的東西」。

## 0. 只有指示詞（映射寫在一份表，工具 `_meta` 用 `$ref` 取）

指示詞只決定「工具從哪裡開始、帶什麼環境、參數是什麼」。它**不會攔**任何事——工具程式拿到 cwd 之後想去哪就去哪。

- 做得到：workspace 別名（cwd／根目錄從表裡取，改一行就換）、共用工具檔（`tools` 直接列路徑）、每支工具的環境變數（`clear`）。
- 做不到：擋 bash 的 `cd ../amy`、絕對路徑、符號連結；模型從 `pwd`、錯誤訊息看到真路徑；工具改名（要新選項，見 README §3）。

## (a) 工具層檢查：每支工具解開路徑後比對白名單

base 工具包（read／write／edit／grep／find／ls）**已經這樣做**：`realpath` 後不在根目錄內＝`OutsideRoot`。

- 擋得住：`../`、絕對路徑、符號連結指出去（實驗 2 全擋）。
- 擋不住：**bash**（它什麼都能跑）；檢查完到打開之間被換掉的路徑（base 開檔後用 `/proc/self/fd` 再驗一次，縮小了但沒根除）；別人寫的工具沒照做。
- 模型看到：`{"ok": false, "error": "OutsideRoot", "message": "… is outside the project directory <真路徑>"}`——**真路徑會漏**，要改成印別名。
- 改設定：一個檔（base 的 `config.json` 或指示詞表）。每支工具都要自己實作檢查。

## (b) 執行環境層

### (b1) 只 chdir＋清環境變數＋不給家路徑

- 擋得住：模型「不小心」走出去的大多數情況（它不知道家在哪）；金鑰、`AOS_KERNEL_HOME` 不在環境裡。
- 擋不住：`cd ..; ls` 一看就知道；`pwd` 印真路徑；絕對路徑照走。**不算邊界**。

### (b2) bwrap（bubblewrap）開一個只掛指定資料夾的小世界

每次跑工具：新的 mount namespace，只把 `/usr`（唯讀）、工具程式（唯讀）、映射表裡的資料夾掛進 `/work/<別名>`，其他（真的家目錄、agent 家、K、D、`/tmp`）都**不存在**。

- 掛什麼：只掛表裡的資料夾＋固定執行環境（`/usr` 唯讀、新的 `/proc`、最小 `/dev`、空 `/tmp`；`/etc` 只掛必要的幾個檔，實驗裡整份掛 `/etc` 是偷懶，不照做）。
- 這台（Manjaro）：`/usr/bin/bwrap` 0.12.0 已裝，一般使用者可用，一次 1.3 ms（[實驗](experiment.md)）。`unshare` 也在，但 bwrap 是給一般使用者用的包裝、參數好寫。
- 擋得住：`cd ../amy`、絕對路徑、符號連結指出去（連結懸空）、K 後門、環境變數（`--clearenv`）；`--unshare-pid` 看不到別的行程；`--die-with-parent`＋`--new-session` 工具被砍時整群收掉。
- 擋不住／要另外想：
  - **網路**：`--unshare-all` 會連網路一起關（`curl localhost:4000` 失敗）；coding agent 常要裝套件，要網路就加 `--share-net`，但 localhost 上的 LiteLLM（免 key）也就連得到——等於工具能自己叫模型。
  - 掛成**可寫**的資料夾若含工具檔、工具程式、映射表或它 `$ref` 的檔：下一批由牢外的 aos-agent 讀到被改過的版本＝自己給自己加權限、甚至把 bwrap 從 argv 拿掉；共用的還會下毒給別的 agent。所以這些「信任資料」一律不准跟可寫映射重疊（contract §3）。
  - 開放 `self`：預設整個家唯讀（contract §4）。實驗 3 證明單檔唯讀蓋得上，但黑名單蓋不完、蓋不住之後新建的檔，不採用。
  - 牢裡寫出來的東西之後被**人**在牢外執行（`.git/hooks`、Makefile）——超出這條線，只提醒。
  - 非 Linux、或 user namespace 被關的機器：bwrap 跑不起來。
- 模型看到：`No such file or directory`（不是 permission denied；它根本看不到外面）；`pwd`＝`/work/ws`。工具路徑是穩定的別名：換 ws-A→ws-B，工具看到的路徑一個字都不變（但檔案內容、`/proc/self/fd` 仍可能帶出真路徑）。
- 改設定：一個檔（映射表）；aos-agent 每送一批解一次，下一批生效。

## (c) 混合：指示詞寫映射 ＋ bwrap 當牆 ＋ 工具層檢查當「好看的錯誤訊息」

牢裡 read／write 仍檢查根目錄，給模型一行清楚的 `OutsideRoot`（路徑印別名）；真正的牆是 bwrap。

| 逃逸路徑 | 0 指示詞 | (a) 工具層 | (b1) chdir | (b2) bwrap | (c) 混合 |
|---|---|---|---|---|---|
| read 工具 `../amy/x` | 漏 | 擋 | 漏 | 擋 | 擋（好訊息） |
| bash `cd ../amy` | 漏 | 漏 | 漏 | 擋 | 擋 |
| bash 絕對路徑 | 漏 | 漏 | 漏 | 擋 | 擋 |
| 符號連結指出去（ws 裡本來就有、或 bash 自己建） | 漏 | read 擋、bash 漏 | 漏 | 擋（懸空） | 擋 |
| 硬連結（有人**事先**在 ws 裡建了指向 amy 檔的硬連結；牢裡建不出新的，因為看不到原檔） | 漏 | 漏 | 漏 | **漏**（同一個檔） | 漏——明列為限制 |
| `$AOS_KERNEL_HOME` → 往 K 丟工作 | 漏 | 漏 | 擋變數、猜得到路徑 | 擋（K 不存在） | 擋 |
| 環境裡的金鑰 | 看有沒有 clear | 漏 | 擋 | 擋 | 擋 |
| 工具路徑是穩定別名 | 否 | 否（錯誤訊息印真路徑） | 否（`pwd`） | 是 | 是 |
| `setsid`／`nohup` 背景行程活過工具 | 漏 | 漏 | 漏 | `--die-with-parent`＋pid namespace 收掉 | 同左 |
| 網路（含免 key 的本機 LiteLLM） | 通 | 通 | 通 | 預設不通，開了就通 | 看設定 |

**選 (c)**：指示詞負責「映射」（使用者要的），bwrap 負責「牆」，工具層負責「講人話」。**bwrap 不在就拒跑**（不退回 (a)＋(b1)：那等於 bash 回到完整權限，設定形同虛設），`aos-agent check` 標 bad。牢裡確切看得到什麼、哪些東西永遠不能掛成可寫，見 [contract.md](contract.md)。

表裡的「擋」只講「碰不碰得到映射以外的資料夾」。不包括：映射資料夾裡的 Unix socket（能請牢外服務代做事）、受控串流的 fd、同批工具互蓋同一個檔、資源上限——見 contract §2、§6。
