# advice-r1 A 隊：`aos-agent check` 與好看的 `aos-kernel ls`（2026-09-24）

← [notes 索引](README.md)｜審查：[任務書](2026-09-24-advice-r1-review-task.md)、[astra 原文](2026-09-24-advice-r1-review-astra.md)

使用者今天的兩條建議（原話）：

1. 「`aos-kernel check --agent xxx` 這個指令不應該放在 aos-kernel 下面。應該改成 `aos-agent check`，然後遵循 `--target xxx`、默認 xxx 為 `.` 的原則。」
2. 「`aos-kernel ls` 的時候列印出來的東西，希望能好看一些。然後可以的話加上 `aos-kernel ls --json`，用 json 方式印出來。」

## 做了什麼

**(1) `aos-agent check [--target DIR] [--probe]`**
- 整段接手原本的 `aos-kernel check --agent`：先跑一遍跟 `aos-kernel check` 一樣的 kernel 檢查，再查這個 agent 家（池、模型代號、工具找不找得到）；`--probe` 用同一套。
- `--target` 省略＝目前資料夾。K 不用給：先看 `AOS_KERNEL_HOME`，沒設就用家裡 `tick.json` 記的（上次 start 寫的）。第一行講用了哪個 K、從哪來。
- `AOS_KERNEL_HOME` 跟 `tick.json` 對不上、或 `tick.json` 壞了，就印一行 `bad`，判法跟 `start` 一樣（start 會拒絕的，check 就先說）。
- daemon 家：`AOS_DAEMON_HOME`，沒設就用 K 的 info 記的 `daemon`（boot 寫的），再沒有才是目前資料夾。
- `aos-kernel check` 拿掉 `--agent`。舊寫法一律退 2，錯誤訊息指到新指令：
  `aos-kernel: Usage: --agent 搬走了：agent 的檢查改用 aos-agent check --target <DIR> [--probe]（K 由 AOS_KERNEL_HOME 或 agent 家的 tick.json 找）`；`-h` 不列 `--agent`。

**(2) `aos-kernel ls`**
- 第一行 `health …` 一個字都沒動，判定順序也沒動。
- 下面改成：kernel 一行加 kernel cpu 一行、cpu 表按池分組、proc 表、bad 行程的「壞了，看 …」、queue 一行。欄位對齊（中文算 2 格），狀態用短字。
- 長名字砍中間（留頭留尾）。K、D、chain、target 這類長路徑只在新加的 `-v` 印。
- `--json` 改成欄位穩定的物件 `aos_kernel_ls` 第 1 版：health、kernel（含 settings）、cpus、procs、queue、counts。stdout 只有一個 JSON 加換行，錯誤走 stderr，退出碼跟文字版一樣。**不再原樣吐帳本**，要原始帳本就直接讀 `K/state.json`。
- `aos-agent status --json` 本來就有（`collect()` 的 dict），這輪沒動它的 schema，也沒寫穩定承諾（原因見最後「沒做的」）。

## astra 審查：必修 6 條，全修

1. `tick.json` 壞了或缺 K 時，check 說 ok，但 start 會拒絕 → 改成跟 start 同判；沒設環境變數時也分開講「壞了」和「沒 start 過」。
2. proc 缺鍵或值是 null 時，JSON 會原樣吐出來，跟規範的型別不合 → 改成正規化：`status` 變 `"unknown"`、`runs`／`fails` 變 0、`pool`／`target` 變 null，規範也寫明。
3. `status: null` 和 `"null"` 在 `counts` 裡撞成兩個同名鍵 → 正規化後就不會撞。
4. 沒有字面 `stderr` 時，`look` 印的是「<target> 的 stderr 設定」 → 改成直接指 target（舊測試一起改）。
5. health 已經判 `broken` 了，ls 還是退 0 → 改成退 1、stdout 空。
6. 池名空字串、字面 `-`、info 裡沒有這顆，三種會被併成同一組 → 改用原值分組，顯示成 `""`、`-`、`?`。

建議共 6 條，採了 3 條：`settings` 固定五個鍵、規範寫明 `counts.procs.status` 是資料映射、`lib/README.md` 裡舊的 `--json` 說明。「舊旗標遇上其他用法錯時先報哪個」只在規範寫明現況，沒改程式。沒採的：`_cut` 在寬度 0 的邊界（呼叫端固定 24）、沒 boot 時 kernel 池的 cpu 被算成閒著的工作 cpu（照「帳本的 kcpu」字面定義，留給使用者判斷）、其他補測清單。

## 沒做的與原因

- **`aos-agent status --json` 的穩定 schema**：本來就有 `--json`，但它是 `collect()` 的內部 dict，要穩定得先挑欄位、定型別，工作量跟 ls 差不多。任務說不強求，這輪就沒動，也沒寫進規範。
- **`aos-agent check` 沒有 `--daemon-target`**：任務只要 `--target`／`--probe`，daemon 改成自己從環境變數和 K 的 info 找。之後要加很容易。
- **一次查多個 agent**：沒做，一個家跑一次。
