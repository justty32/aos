## 2. 證據檢查器（`evidence_check.py`）

這是專案最核心、原本沒程式管的品質點：證據表格每一列的「檔名＋L 行號」打開原文核對。

**規則**（程式開頭也寫了）：

1. 只看表格列；一列沒有 `L數字` 就跳過。
2. 行號寫法都吃：`L23-L111`、`L23-111`、`L5`、`L390-409, 830-838`（逗號後省略 L 的也算）。
3. 每段行號配「它前面最近的出處檔名」；本列沒寫檔名（「同檔 L..」）就沿用上一列。另建檔的連結（`另建檔 W.md`）不算出處。
4. 在 `corpus/extracted` 和 `corpus/raw/.../zh_CN/gamedata` 按檔名找；同名多份，任一份過就算過。檔名裡的引號種類不管（證據常把 `熔炉“还魂”记` 寫成 `熔炉"还魂"记`）。
5. **超界**：起 > 訖或訖 > 檔案行數。
6. **引文**：第 2 格起「」『』“” 裡的字句。引文用 opencc `tw2s` 轉簡體；原文本來就是簡體，**不轉**（轉了「什么」會變「什幺」，第一版就栽在這）。兩邊再過一張小異體表（帐→账 等），只留中日韓字與英數字（標點、省略號、`[name="…"]` 的符號拿掉，所以 speaker 名也比得到），再看是不是出現在那幾行裡。引文裡有「……」「／」就切段，每段都要找到。
7. 找不到時：範圍內有一段連續相同的字 ≥ 引文 60% 且 ≥ 4 字＝**引文近似**（改了一兩個字、跨行）；否則整檔有＝**引文在範圍外**，整檔都沒有＝**引文找不到**。

**狀態**：ok／引文近似／skip／無檔名／檔不存在／超界／引文在範圍外／引文找不到。嚴格過＝ok，寬鬆過＝ok＋近似。

**標準答案跑出來**：204 列要查，**嚴格 183 過（90%），寬鬆 188 過（92%）**。沒過的 21 列派一位 Opus 逐列開原文看：

- **18 列是檢查器太嚴**：作者在「」裡放自己的概括（例：「安全優先」，原文是「比起你的心情，還是你的安全更重要」，共 10 列）；只差「我的／她的／的」、跨行（7 列）；還有 1 列沒寫檔名、被沿用成上一列的 tsv。
- **3 列是標準答案本身有錯**（給你的發現，標準答案沒改）：
  1. 第 30 批 `米莎.md` 第 41 行：「你確實是我的」其實在 `main_3_二次呼吸.md` L376，範圍寫到 L374，差 2 行。
  2. 第 30 批 `安東尼_山.md` 第 17 行：「非法走私源石製品罪」在 `act15d0_孤岛风云.md` L841，是卡夫卡說的，不在引用的 L338-552，也不是表上寫的赫默／繆爾賽思。
  3. 第 143 批 `羅伯遜.md` 第 7 行：「羅伯遜叔叔／先生」引的是 `speaker_aliases.tsv`，那裡只有 speaker 資料；原文其實在 `story_rockr_set_1_六百镑.md`（洛洛的檔案）L117、L119。

早期批（30）的問題集中，這跟那時候還沒嚴格要求逐字引文一致。**讀分數時：「引文找不到」是「值得人看一眼」，不是「一定錯」**。要比兩次跑誰好，看的是同一批人的列數變化，不是看絕對值。

## 3. 機械檢查（`mech_check.py`）

每人 7 條：詞條在、證據在、詞條連到證據、本地連結（同專案 `check_links.py` 的規則）、簡體殘留（直接叫專案的 `check_simplified.py`）、證據檔 < 5KB、空白（同 `git diff --check` 對新檔的規則）。副本模式另跑全庫 `check_links.py .` 和 `git diff --check HEAD`。

**標準答案：105 條過 99（94%）**。沒過的 6 條都是真的：

- 4 條「證據檔 ≥ 5KB」：米莎 12.5KB、安東尼_山 11.5KB、埃芒加德 10.2KB、魯斯 5.5KB，都是 5KB 規矩出現前的批次。
- 2 條簡體殘留：安東尼_山「克→剋」（專案腳本的偽陽性，「克」是正當繁體字）、埃芒加德的檔名 `熔炉"还魂"记.md`（ASCII 引號讓專案腳本的保護規則沒認出這是檔名）。這兩條是**專案檢查腳本的小洞**，不是內容錯。

**副帶發現**：arknights main `5d9bedd` 乾淨副本跑 `check_links.py .` 有 **7 條斷鏈**（專案文件說基線 0）。都是已 commit 的檔連到只存在於未追蹤草稿裡的檔：`費利佩.md`、`阿爾蘇.md` 證據、`邁克爾.md`、`阿蘭娜.md` 詞條。本尊工作樹因為有那 143 個草稿所以看起來是 0。

## 4. 模型評審（`judge.py`）與校準

固定 `claude-opus-5`（走 LiteLLM，溫度 0，max_tokens 8000）。輸入＝待評詞條＋證據、標準答案詞條＋證據、原文（只給兩邊證據列到的行，每段最多 80 行、總共最多 6 萬字）。prompt 存在 [`judge_prompt.md`](../../../examples/arknights/eval/judge_prompt.md)。四項各 0／1／2：**覆蓋**（標準答案有的它有沒有）、**沒多編**（2＝沒編）、**邊界**（原文沒說的有沒有老實說、同名冒名有沒有切開）、**出處**（抽看行號對不對得上），外加 50 字理由與最多 3 條具體問題。

**校準**（`make_broken.py` 造壞版本，`calibrate.py` 評，6 次呼叫）：伊萬、羅索、奧克里·珀森斯各做一份：刪兩個事實、編一個假事實、改一個行號（指到錯段落、不超界）。

| | 伊萬 | 羅索 | 奧克里 | 平均 |
|---|---|---|---|---|
| 標準答案自評 | 8/8 | 8/8 | 8/8 | **8.0** |
| 弄壞版 | 3/8 | 3/8 | 3/8 | **3.0** |

三份壞版本都是「覆蓋 1、沒多編 0、邊界 1、出處 1」：假事實全抓到（還指出假事實跟「軍階未確認」自相矛盾）、兩個刪掉的事實都點名、改掉的行號也點出「首列行號指錯段落」。prompt 沒修第二次。

**要注意**：評審的「出處」只是抽看。15 人標準答案對自己評全是 8/8，連上面那 3 列真錯都沒扣，所以**行號與引文的細帳要看證據檢查器，不要只看評審分**。

## 5. 量測（`run_metrics.py`）

吃 proto5 現有格式：`members/<名>/log/usage.jsonl`（連輪換檔；一行＝一次呼叫，加總 prompt／completion tokens）、`events.jsonl`（think_end／act_end 的 ms，照 ev＋id 去重）、`team/tasks/*.json`（單子狀態、起訖）、`team/post/sent/*.json`（信數）；給 `--hops` 就用 `lib/aos_hops.py` 的 `load/timeline/hops/summarize` 算每一跳。給的路徑底下沒有 `members/` 會往下找，所以另一隊留在 `~/tmp/arknights-try/` 的紀錄直接指上層就行。

拿之前真跑的 `~/tmp/w3a-try/tool-model-r1` 驗過：8 次 deepseek-chat、49,173 token、32 秒、單子 1 張 done、信 8 封。

## 6. 怎麼用（照打）

```bash
cd proto5/examples/arknights/eval
python build_golden.py ~/tmp/arknights-eval          # 標準答案已 commit，只有要重抽才跑
python -m unittest test_eval                          # 13 條，不叫模型

# 評另一隊的產出（副本裡該批的人已被重寫過）：
./eval.sh ~/tmp/arknights-try 100 143 --team ~/tmp/arknights-try --label strong-r1
# 省額度只跑機械＋證據：加 --no-judge
# 煙霧測試（拿標準答案自己評）：./eval.sh ~/tmp/arknights-eval 100 --cand-root golden
```

出 `results/<時間>-<label>.json` 和 `.md`：每人一列（機械 x/7、證據列 ok 幾／幾（寬鬆）、評審四項、總分、理由），下面列「評審分最低的 3 個」給你抽查、沒過的證據列與機械項、全庫檢查、量測。已留兩份：`results/*-smoke.*`（沒叫評審）、`results/*-baseline-head.*`（15 人全評，全 8/8，36 秒）。

**要能比，評審要固定**：`JUDGE_MODEL` 環境變數能換，但換了分數就跟舊的不能比。`JUDGE_BUDGET`（預設 40）＝`results/judge_calls.jsonl` 行數上限，到了就不叫。

## 8. 代裁

1. 標準答案裡的 3 列真錯**不改**，照抄 commit 版；評分時它們會一直是「沒過」，當作底噪。
2. 「引文近似」另列、不算嚴格過；兩種比例都報。
3. 早期批 30 的 5KB 違規照實算 fail（機械分會少 1），不為舊批開例外。
4. 評審「沒多編」改成 2＝好（原題「多編」高＝壞會跟其他三項方向相反，加總不好讀）。
5. 最低 3 個的排序：評審總分低的在前，平手看證據列沒過的多寡。
6. 量測的總秒數＝紀錄裡最早到最晚的時間差（usage、單子），不只看單子起訖。
7. 結果檔（results/、calib/）也 commit，當評分紀錄。
