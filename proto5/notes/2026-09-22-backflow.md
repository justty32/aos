# proto5.1 規範回流 proto5（2026-09-22）

使用者定的順序：proto5.1 照 [23 題拍板](2026-09-22-decisions.md) 改（第 4 段）→ fable 重審（[review-fable](../../proto5.1/notes/review-fable.md)）→ 照重審修（第 5 段）→ **只把規範與筆記收回 proto5，程式先不動**。這份記錄搬了什麼。

## 搬了什麼

`proto5.1/spec/` 的 15 份原樣複製到 `proto5/spec/`，每份開頭加一行「proto5 的程式還沒照這份實作」；指向 proto5 沒有的程式檔的連結改指 proto5.1。`directives.md`／`inst-posix.md`／`exec.md` 三份 proto5.1 沒動過，不用搬。

## 跟 proto5 舊規範差在哪（三份改的）

- **agent.md**：`engine` 只剩 `cpu`（必填）／`model`（代號）／`params`；`errors` 欄；`waits` 由 aos-agent 自己也會加。
- **aos-agent.md**：`think` 不再同步問，改交 llm cpu、`waits` 等 `ask-result.json`；`act` 分同步工具與 `_run: cpu` 工具，後者交 tool cpu、等 `tool-results/<i>.json`；工具 `_timeout_ms` 預設 60 秒；連敗 3 次加 consume 的 `continue.json` 門；結果不明看 `code == "Reaped"`，回固定文字、不重試；同一批 cpu 工具不保證執行順序。
- **aos-llm-ask.md**：同步 HTTP 路徑拿掉，只剩組 body 與給 cpu 用的 `call`。

## 程式也搬回來了（同日下午）

使用者說「可以開始把 proto5 的程式丟上規範了」，於是 `proto5.1/lib`（十二支模組＋十三份測試）、`proto5.1/cli`（九個入口）、`lib/README.md` 整套複製進 proto5，覆蓋掉早上的六支版本；規範開頭的「程式還沒照這份實作」那行拿掉、指向 proto5.1 程式的連結改回 `../lib/`。程式碼跟 proto5.1 一字不差，只有兩處不同：`spec/exec.md` 在 proto5 叫 `aos-exec.md`（連結跟著改）、`lib/README.md` 的標題與測試指令換成 proto5 路徑。findings 仍留在 proto5.1，規範裡指過去的連結不動。

搬過來撞到一個坑：`test_kernel.py` 的 setUp 要求 `<proto>/.build` 先存在，proto5.1 有那個資料夾、proto5 沒有，34 條 kernel 測試在 setUp 就倒。改成測試自己 `mkdir(exist_ok=True)`（proto5.1 同步改），並補 `proto5/.gitignore` 擋 `.build/`。

驗證：802 條全綠；LM Studio（`qwen/qwen3-1.7b`）真跑 [proto5.1 的 stage5-demo](../../proto5.1/notes/stage5-demo.py) 改指 proto5 的 cli，daemon＋三顆 kernel cpu 跑 agent／llm cpu／tool cpu，問時間→now 工具→回話 16.2 秒，stop 後 `pgrep -f aos-` 空。
