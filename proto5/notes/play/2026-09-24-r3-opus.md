## 做了什麼

1. **README 從頭照抄**：第 1～6 段與「附：手動 amy」全部照抄一次過。`say --wait` 約 14 秒回「現在是…12 點 31 分 40 秒」，`add` 工具回 `5555`，amy 20 秒後 `last` 有回話、`done/` 有封存檔。唯一自己加的：daemon 用 `nohup … &`（我的 shell 每段就退出）。
2. **早上開機**：`init` 三個家（poet 五言絕句＋`wc` 工具、sys 管家＋`uptime`／`df`、calc 計算機＋`calc` 工具），改 `system.json`、放 `tools/*.json`，`check --agent` 全 ok，`start` 三個。輪流 `say` 各三句，混用 `--wait` 與不等後 `status`／`last`，全部拿到回話（計算、詩、字數、磁碟都對）。
   - **連敗暫停**：把 llm.json 的 port 改成 1 後 `say sys … --wait`，12 秒退 101、stderr `stuck: …修好後 aos-agent continue`，附的 status `wait` 行寫「連敗暫停」。改回、`continue` → 20 秒內答完。重按 `continue` 說「已經 touch 過」／「沒有在暫停」。**看得出來、救得回來**。
3. **故意弄壞**：
   - `say` 給沒 start 的 agent：照樣 `said ->`、退 0；`--wait` 等到逾時退 101。
   - `init` 已有家：`AlreadyExists … 已經是 agent 家（拒絕覆蓋）`、退 1，清楚。
   - `status /tmp`：`NotAnAgent: … 沒有 info.json`、退 1。
   - `kill -9` llm cpu（閒時、think 批送出後各一次）：daemon 自己重拉，回話照常。
   - `rm -rf K/requests`：**全體靜默卡住**。見卡住第 4 條。`aos-kernel check` 抓得到、提示 `mkdir -p` 補上，補完不用重 boot 就自己走下去。
4. **自己寫工具**：`tools/bin/listdir`（Python，收 `{"path"}`、印「種類 大小 名字」）＋`tools/listdir.json`，下一格生效，模型叫得到、看得到結果。拿掉執行位 `check --agent` 馬上 `bad … 找不到可執行的 tools/bin/listdir`。
5. 停機三層都印 `stopped`（agent `stop` 不用 `AOS_K`）。

## 卡住的地方

1. **aos-agent.md §1.3／`status` 的 error 行**：救回之後 `status` 還是印 `error  aos-agent: stuck: 問模型連敗 3 次…`。我以為它還卡著；實際已經 `idle`、回話也出來了，那只是 agent.err 的最後一行。
2. **同上，暫停中**：`error` 行只有 `stuck: …touch … 繼續`，**看不到為什麼**（Connection refused 在上一行）；`state` 行還寫 `errors 0`。我以為 errors 會是 3；實際要自己 `tail log/agent.err` 才知道是 endpoint 壞了。
3. **README 第 4 段／§1.2 `say`**：給沒 `start` 的 agent `say` 照樣 `said ->` 退 0，`--wait` 預設要等 300 秒；逾時附的 status 在沒 export `AOS_K` 時寫 `kernel （沒設 AOS_K）`，不是「沒登記」。我以為是 AOS_K 的問題；實際是沒 start（有設 AOS_K 時才印 `沒登記（aos-agent start）`）。
4. **kernel 家的 `requests/` 被刪**：`aos-kernel ls` 仍 `phase running  daemon alive`、三個 agent `queued`；`status` 的 `error -`；`say --wait` 逾時。我以為模型慢；實際 kernel 整個停住，只有 `aos-kernel check` 會說 `bad dirs: 缺 …/requests/`。README「掛了」只講 daemon，沒講「全 queued 不動先跑 check」。
5. **README 第 4 段「一個檔＝一則話」**：連投兩則給 calc（「2^64−1」「再除以 3」）還沒收時，被合成同一輪兩則 user、只回了一個答案。我以為會一問一答；實際一格收走所有等著的檔。規範裡找不到這句白話。
6. **`NotAnAgent: … 沒有 info.json`**：在 W 底下打 `aos-agent say "hi"`（忘了 dir）得到這句，沒提示「要給 dir 或 cd 進家」「新家用 init」。小事但第一次會愣一下。

## 改了會更順的清單（痛度由高到低）

1. `status` 的 `error` 行改成「這次卡住的原因」：暫停時印導致暫停的那個 engine 錯（endpoint＋Connection refused），不是 stuck 那行；恢復後不再印舊錯（或標「歷史」＋時間）。
2. kernel 自己壞（`requests/` 缺、帳本壞）時 `aos-kernel ls` 第一行要喊出來，`aos-agent status` 的 `kernel` 行也帶一句「kernel 家壞了，跑 aos-kernel check」。
3. `say` 到沒登記的家：stdout 照樣投，但 stderr 一行 warn「沒登記，沒人會收；aos-agent start」（有 tick.json 或 AOS_K 可查時）；`--wait` 遇到沒登記就立刻退，不要等 300 秒。
4. `status` 沒設 AOS_K 又沒 tick.json 時，直接說「從沒 start 過（沒 tick.json）」，別只說沒設 AOS_K。
5. 暫停中 `state` 行的 `errors` 保留 3（或另寫「連敗 3 次暫停中」），不要歸 0。
6. README 第 4 段補一句：還沒收的多則話會**合成一輪**一起問模型。
7. README 第 1 段註一句：非互動 shell（腳本、每段開新 shell 的工具）請用 `nohup` 或 `setsid` 放背景。
8. README「掛了」擴成三行小表：daemon 掛了／kernel 家壞了／agent 暫停，各一個指令。
9. `NotAnAgent` 附提示：「給 agent 家路徑，或 `aos-agent init <dir>` 生一個」。
10. `start` 沒設 `AOS_K` 時錯誤訊息附 `export AOS_K=<絕對路徑>` 範例。
