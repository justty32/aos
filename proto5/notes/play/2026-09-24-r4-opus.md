## 卡住的地方

1. README 第 3 段／`aos-kernel boot`：我以為會印 `booted` 之類的字，實際上成功時什麼都不印（rc=0）。不確定有沒有成功，只好再跑 `ls`。
2. README「每天重開機」／模擬斷電（`kill -9` daemon 和 cpu）：斷電後 `ls` 第一行正確說「daemon 沒在跑」，但下面 cpu 那幾行還印 `running`，前後矛盾。
3. 同一節：重開後 `aos-agent start` 印 `AlreadyExists: 行程已存在` 並退 1。README 有寫這代表已登記、不用管，但它看起來像錯誤、退出碼也是錯誤；寫成腳本的話 `set -e` 會停在這裡。
4. aos-agent.md 的「連敗暫停」：我以為 `llm.json` 是每個 agent 各一份，實際上所有 agent 共用 kernel 的那一份。port 一改壞，所有正在說話的 agent 一起倒（alice 也跟著暫停了），任務書「只弄壞一個」做不到，每個 agent 都得各自 `continue`。
5. 連敗還沒滿 3 次時（alice `errors 2`），`status` 第一行照樣 `health ok`，只有 error 欄寫「已連敗 2 次（3 次會暫停）」。第一行其實應該說「正在重試」。
6. `continue` 救回之後：README 說舊錯會另起一行、標「已恢復」。實際那一行叫 `last-error`，「（已恢復）」接在一條超長的 touch 路徑後面，我用 `cut` 一截就看不到了，還以為沒標。
7. 在沒 `start` 的 agent 上 `say --wait`：確實立刻退 101，但那則話**還是投進去了**。使用者會以為沒送出，照著提示 `start` 再說一次，結果同一句話進了記憶兩次（carl 的 history 裡「第三句：1+1？」出現兩則）。
8. `init` 在已經有東西的非 agent 資料夾（裡面有 a.txt）：一聲不吭就把檔案生進去了。在 agent 家上 `init` 會被正確拒絕，這點沒問題。
9. 對 kernel 家下 `aos-agent status`：印「NotAnAgent: _metainfo._type 只認 llm_agent」，沒說「這是 kernel 家」。
10. `requests/` 被搬走之後：`ls` 和 `status` 第一行都講對了，但 `say --wait` 還是乾等 20 秒才退。`check` 的提示「手建的家請 mkdir -p 補上（aos-kernel init 會建）」，括號那句會讓人想去重跑 init。照 mkdir 補上就好了，不用 boot。
11. README 第 6 段：說工具壞了「`log/agent.err` 有詳情」。實測拿掉執行位後，模型看得到 exit 126，但 agent.err 裡沒有對應的一行。`check --agent` 則正確抓到了。
12. `last` 取到的是中間步驟（`(tool_calls: add)`，或者「讓我看看書架…」），卻沒有「還沒講完」的警告。這時門已經關上了，但真正的回話還沒出來，使用者會以為這就是答案。
13. 4 個 agent 共用 2 顆一般 cpu，每走一格都要占一顆 cpu。`ls` 常常看到兩顆都被 tick 占著，工具只能排隊。README 沒說 agent 多了要加 cpu。

## 改了會更順的清單（最痛的排前面）

1. `say --wait` 發現沒登記時，不要把話投進去（或者投了就明說「已投入，start 後會處理，別再說一次」），避免同一句重複。
2. `say --wait` 開始等之前先看一次 health：K 家壞了、daemon 死了、連敗暫停，都立刻退，不要乾等 5 分鐘。
3. 讓一次 `continue` 能救回所有 agent（例如 `aos-agent continue --all`，或 `aos-kernel ls` 列出正在暫停的 agent）。llm.json 是共用的，一壞就是一片。
4. `aos-kernel check` 加一項實際打一次 endpoint（或提供 `--probe`），port 錯了在開機時就抓得到。
5. 舊錯那一行把「（已恢復）」移到最前面；舊錯訊息裡的 `touch …json` 改寫成 `aos-agent continue`。
6. 連敗未滿 3 次時，`health` 寫「重試中（連敗 N/3）」，不要寫 ok。
7. `boot` 成功時印一行（例：`booted 4 cpus`）。
8. daemon 沒在跑時，`ls` 的 cpu 行不要再印 `running`。
9. `start` 遇到已登記時改成印 `already started`、退 0。
10. `status` 指到 kernel 家或 daemon 家時直接說「這是 kernel 家，不是 agent 家」。
11. `last` 取到中間步驟時，在 stderr 加一行「還在處理中」。
12. README 第 4 段補一句：「agent 多了，`init` 時多給幾顆 `--cpu`」。

## 第 4 項：自己寫工具

給 alice（圖書館員人格）寫了一支 `list_dir`：stdin 收 `{"path"}`，stdout 印出檔名和大小。照第 6 段放進 `tools/`，不用重新 start 就生效，`check --agent` 顯示 ok。模型照著回答了：書架上 4 本 0 bytes 的名著加一份 13 bytes 的借書單，也答對「哪個檔最大」，每次都照人格附一句五言詩。拿掉執行位後 `check` 會標 bad，模型也會跟使用者說工具沒有執行權限。

另外兩個 agent 也各三句說完：carl（會計師）每一題都叫 add 工具，答出 13021、13798、2；dora（海盜船長）照人格粗魯地報時、講格言、講笑話。README 裡的手動家 amy 也照抄就過。
