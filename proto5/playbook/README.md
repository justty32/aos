# proto5/playbook — 邊做邊沉澱

← [proto5 README](../README.md)

使用者要的是「一邊做、一邊產出經驗，還有 agent 團隊組織架構、agent 工作流架構、可複用的工具，持續迭代、一邊開發一邊測試、同時持續變好」。這裡就是那個固定的家，從 2026-09-25 起每一隊**收尾**都要往這裡沉澱四樣東西：

| 樣 | 放哪 | 是什麼 |
|---|---|---|
| 經驗 | [lessons.md](lessons.md) | 一條一段的教訓：做過才知道的規則、踩過的坑、下次怎麼做 |
| 團隊組織架構 | [teams/](teams/README.md) | 可重複套用的團隊編制（名冊模板、角色分工、誰管誰） |
| 工作流架構 | [workflows/](workflows/README.md) | 可重複套用的做事流程（強模型→找重複→換笨模型→換程式 這種降級路線、階段拆法） |
| 可複用工具 | [`proto5/tools/`](../tools/README.md) | 這裡不重放工具本體，工具包已經有自己的家；本檔只負責在下面索引表提一句「這個工具從哪隊長出來、適合什麼活」 |

整件事也可以當做開一間公司在看：業務、製造、品管、研發、HR、圖書館、財務……各部門做什麼、現在對應 proto5 哪些東西、缺什麼，見 [company.md](company.md)。`lessons.md` 每條標的「部門」就是照這份的部門名。

## 誰來放、怎麼放

**誰**：每一隊收尾（寫收尾報告的那一刻）都要回頭看一眼——這次做的事裡，有沒有「別隊也用得到」的東西？有就往這裡加，沒有就不用勉強湊數。

**怎麼放**，每一條、每一個項目都要交代三件事：

1. **從哪段抽的**——連到來源報告（`notes/<日期>-<主題>/.../README.md` 的章節），讓人查得到原始脈絡。
2. **適合什麼活**——講清楚適用場景，不是每件事都套得上。
3. **哪裡可再用**——下次遇到類似情況，去哪個檔案／哪個工具、怎麼動手接上。

不要把來源報告整篇搬過來抄一遍：這裡只留「抽出來的教訓」，細節留在原報告，用連結指過去就好。
