# 一輪市場：打分 → 排名 → 倒閉 → 撥款 → 合併

← [workflows](README.md)｜規則：[spec/team/market.md](../../spec/team/market.md)｜來源：[notes/2026-09-25-company](../../notes/2026-09-25-company/README.md)

**適合什麼活**：同一種活交給幾支一樣的隊（公司）做，用表現決定資源往哪裡流。經理人（aos 外）拿機械指令做決定，參數可調、可覆寫。

1. 各家做同一批單（每家自己的專案副本）。**換一批新的人名之前先查各部門 `cmd_ok` 白名單有沒有照人名寫死**（lessons 34；樣板 09-25 起用 `"pattern": true` 的 `{name}`，舊實例要自己改）；五家同跑 09-25 用「一輪 3 張、五家同一秒下、依序、單張 12 分鐘沒結案記失敗」可行，一輪 12～35 分鐘。
2. `market.py score 名 --eval 結果.json`：品質（機械 40％＋證據 40％＋評審 20％；證據檔的「A L30」代號先展開再算）；成功張數、董事等的秒數從董事的單與總裁結案信自動算。成功＝總裁寄了 DONE 結案信＋品管報告檔（`qa-reports/X.md`）結論合格（找不到報告才看結案信的字面）。**`score` 要等這一輪的單都過了逾時才跑**：還沒結案的算逾時失敗（`timeout`），被財務擋的單會有 FAILED 結案信、自然算失敗。
3. `market.py rank`：品質 0.6、快 0.25、省 0.15（都是參數）。這輪沒成功的全項 0；快＝董事等了幾秒；省＝這一輪花的 token（不是累計），只在成功的之間比；只剩一家成功會註明「無對照」。
4. `market.py bankrupt [--dry-run]`：**先倒閉再撥款**（market.md §3，astra 09-25）——花光的停、封存；剩的配額與名額回總池；`close 名` 是經理人主動裁撤（剩多少收多少）。順序反過來，撥款會把該倒的公司救活（花光的現在一律拿 0、覆寫也擋 `Broke`）。
5. `market.py grant [--dry-run]`：照名次分這一輪的總額（同分均分）；總池不夠就照比例縮。這輪一家都沒 `score` 會拒絕（「本輪無分數」）。撥完這一輪就結束，下一輪的 `score` 要重記（分數綁輪次）。
6. 剩兩家：`market.py merge --dry-run` 看計畫（經理只留一個、名額滿了改臨時工）→ `merge`。

- **在哪停下來看**：先 `--dry-run`；排名第一但品質低於門檻的（快又省但做壞了）要設 `min_quality`。
- **打分後看 `score` 印的「說明」**：證據代號展開不了會寫原因（證據那項算 0），這時再看 evidence_check 的 `by_status`（lessons 29；09-25 研發部已讓 `--eval` 自動展開「A 檔 L30」代號）。單子 FAILED 的公司 09-25 起自動全項 0、撥 0，不用再手動覆寫（lessons 30）。
- **`grant --dry-run` 後對一次「成功／失敗」欄跟董事收件匣**：DONE 又品管合格的卻記失敗＝判定出錯，停在 dry-run（lessons 33；09-25 五家真跑抓到「結論為：合格」不算，已修）。
- **`grant` 拒絕「本輪無分數」是好事**：代表上一輪撥完還沒人打分，別用覆寫硬發（lessons 31，09-25 已修成拒絕）。
- **注意**：並行的單照單算 token 會變成整隊的（品管部 09-25），市場用整家一輪的總數就沒這問題。
