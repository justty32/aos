# 記帳 → 查帳 → 擋預算（財務部的三步）

← [workflows](README.md)｜來源：[notes/2026-09-25-finance/README.md](../../notes/2026-09-25-finance/README.md)｜規格 [spec/team/cost.md](../../spec/team/cost.md)

**適合什麼活**：任何「有一筆會被重複消耗的資源（token、錢、cpu、外部 API 次數），要知道誰用了多少、超了要停」的事。三步**全是機械**，不用模型。

## 三步

| 步 | 做什麼 | 在哪 | 機械？ | 失敗了怎樣 |
|---|---|---|---|---|
| 1 記帳 | 在**唯一的漏斗口**（所有呼叫都經過的那個函式）拿到用量，追加一行到一本帳 | `aos_llm_call.call`、`aos_llm_ask.ask` → `aos_team_cost.record` | 純機械 | **吞掉**：記帳壞了絕不擋正事 |
| 2 查帳 | 讀整本帳、篩時間、照某欄分組加總；錢用**現在的**價格表重算 | `aos-team cost [--by …]` | 純機械 | 缺價的只記 token、印警告 |
| 3 擋預算 | 在**派新工作的那一個點**問「超了沒」，超了就不派新的、通知人；已在做的不砍 | 郵差 `budget_hold`、`aos-team ls` 第一行 | 純機械 | 預算檔壞了**不擋**，只在 ls 報 |

## 照抄時的四個判斷

1. **漏斗口在哪**：先找所有呼叫都經過的那一層（這裡是 `_post`，上面只有兩個入口）。掛在入口而不是最底層，才拿得到「誰在叫」（agent 家、環境標籤）。
2. **一本還是多本**：資源是誰出錢就歸誰——董事一個錢包＝一台機器一本；要看某隊就篩欄位，不要分本（分了就加不出總數）。
3. **擋在哪**：擋「開新工作」的那一個點，不擋「做到一半」的。擋的方式是「先不處理、留原檔」而不是退件，這樣調高預算後自己會繼續，不用人重送。
4. **預設開還是關**：記帳要環境變數明確打開（`AOS_COST_HOME`），不然測試的假呼叫會污染真帳本。代價是「忘了接線就沒記到」——所以 `ls` 第一行要讓人看得出有沒有在記。

## 哪裡可再用

- 別的資源（cpu 秒、外部 API 次數）：照 `aos_team_cost.py` 的 `record`／`summarize`／`usage_against`／`budget_hold` 四塊換欄位。
- 回填舊紀錄：`aos-team cost import` 的「每行帶來源 sha 當 key、帳上已有同一次的即時紀錄就跳過」這個去重法，任何「事後補帳」都適用。
