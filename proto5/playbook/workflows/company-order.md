# 董事一句話 → 總裁 → 製造 → 品管 → 回報

← [workflows](README.md)｜真東西：[examples/company/](../../examples/company/README.md)｜來源：[notes/2026-09-25-company §3](../../notes/2026-09-25-company/README.md)

**適合什麼活**：一件貨要經過「做」與「獨立驗」兩個部門，董事只想下一句話、收一封結案信。

```text
董事 company.py order "補人物 X"
  → 總裁辦門房（沒命中）→ 總裁：team_say human「〔給 mfg〕補人物 X（只寫詞條）」
  → 總機 → 製造門房命中 → 寫手做 → 驗收（機械）→ 審查（judge）→ 郵差 DONE／FAILED
  → 總機抄回總裁 → 總裁「〔給 qa〕驗貨 X」→ 品管門房命中 → 檢驗員抽查 → 郵差 DONE
  → 總機抄回總裁 → 總裁寄給董事（不帶〔給〕）
```

- 09-25 真跑：成功那次 3 分 26 秒、34 次模型、89 萬 token（製造佔 87%）；失敗那次是製造審查兩次都沒過，總裁照 SOP 直接報董事。
- **在哪停下來看**：製造的一次過率（attempt=1 的 done）低於一半，先補寫手人格或換模型，不要讓總裁重派硬撐；品管合格但機械工具抓到小毛病（行尾空白）＝驗收條件漏了，補進門房的 `done_when`。
- **可以降級的地方**：總裁的 SOP 是固定三步，下一步可以寫成總機規則（製造 DONE 自動派品管），總裁只留給門房接不住的話。
