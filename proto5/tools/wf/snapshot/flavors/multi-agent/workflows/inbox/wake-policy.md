## 為什麼要分層

所有訊息都灌進同一條大流時，頂層會被每一則工人回報吵醒，真正該由領導處理的細節反而沒人第一時間看。醒鐘策略就是把「誰該被吵醒」寫死。

## 策略表

| 層 | 誰的信進我這格 | 哪些 STATUS 我要醒 | 其餘怎麼辦 |
|---|---|---|---|
| 頂層（`new/` ＋ `mail/dispatcher/`） | 領導、不在任何團隊的線 | `NEEDS-USER`、`FAILED`、**領導的 `DONE`**（整團隊收工）、資源／鎖請求 | 領導的 `PROGRESS`／`BLOCKED` 不另設醒鐘，下次使用者輸入時順帶看到 |
| 領導（`mail/<領導>/` ＋ `teams/<團隊>/`） | 自己團隊的工人 | **五種全醒**，用 `--wait` 當醒鐘 | 自己判斷要不要上呈，只有自己解不了的才往上送 |
| 工人（`mail/<我>/` ＋ 團隊格 ＋ `orders/`） | 領導、隊友 | 沒有醒鐘，**每完成一個工作步驟 `--once`** | 延遲上限就是一個工作步驟 |

## `--wait` 怎麼當醒鐘

```bash
inbox_poll.sh <我> --wait [--timeout N] [--interval N]
```

阻塞到個人信箱、團隊信箱、`orders/` 任一有未讀才印出並 `exit 0`；逾時 `exit 3` 且不印任何東西；沒給 `--timeout` 就永不逾時。

- **領導**：丟進背景跑（例：`--timeout 1800`），**行程結束就是被喚醒**，不必自己輪詢；醒來先讀那幾行，再決定要不要進團隊格看正文。
- **頂層**：`dispatcher` 這個名字會**額外掃 `new/`**，所以沒有使用者輸入的時段也能被外部 agent 叫醒。
- **收線前務必確認沒有殘留的背景輪詢**（`--wait`／`--watch` 都是長駐）。

## 領導轉發的三條規矩

1. **重寫標題**——頂層看到的一句話要是「你的判斷」，不是工人原話。
2. **附上你已經排除的可能**，否則頂層只能重跑一次你剛做過的判斷。
3. **標明你要什麼**——要裁決、要資源、還是只是報備，寫在標題裡。
