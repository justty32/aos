# quality-gates — 互動課程的品質關卡

[study-site](README.md)｜[WORKFLOWS](../../WORKFLOWS.md)

交付前逐關驗，結果寫進該課的 `驗收紀錄.md`。**沒有證據的項目不得標為通過**；驗收者不採信建置者的自報，全部重驗一次。

## 1. 內容正確性

- 每個核心概念、公式、預設值與診斷結論都能回指本地來源。
- 簡化模型明確標示假設與適用範圍，不把教學近似講成工程保證。
- 術語與來源材料一致，首次出現已依語言契約展開（見 [plain-explain](../plain-explain.md)）。
- 互動回饋說明「為什麼」，不只顯示對錯。
- **抽章重算**：挑至少一章，對照來源親手重算數值。規格本身的算術錯會被建置者忠實照抄進產品，只有重算抓得到。
- **字元級錯字掃描**：機械掃描抓不到形近錯字與混入的異體字；用高頻術語逐一 grep 比對。

## 2. 學習有效性

- 每個模組有可觀察的學習成果。
- 至少各有一次：取捨判斷、參數實驗、故障診斷、跨層整合。
- 控制值一改，數值、結果與 why 說明立刻跟著變。
- 可以重設單元重來；進度只作輔助，不阻擋自由瀏覽。

## 3. 介面與可及性

- 第一個 viewport 就是學習工作台，不是 landing page。
- 桌面與手機都沒有文字截斷、控制項位移、內容重疊或**橫向溢出**。
- 互動可用鍵盤操作、有可見 focus、表單有 label，狀態不只靠顏色表達。
- 尊重 `prefers-reduced-motion`；不用閃爍與無意義背景動畫。控制列與圖表尺寸穩定，狀態切換不造成版面跳動。

## 4. 離線與節流

- HTML、CSS、JavaScript 與必要資產全在課程目錄內。
- 沒有外部字型、圖片、分析碼、CDN、遠端 API 或第三方執行期依賴。
- 開發與測試不新增套件鎖檔；環境已有的工具直接用既有版本。
- 瀏覽器開發者工具的 Network 只有本機請求。

## 5. 技術驗證

依環境可用能力由上而下做，**不為了測試而下載新工具**：

1. 語法檢查（例：`node --check <script>`）。
2. 相對連結與檔案存在性檢查、pager 串接無孤兒頁。
3. 起本機靜態 HTTP server，驗證各模組、重設與本地儲存。
4. 環境已有無頭瀏覽器就跑：console error、桌面 `1440×900`、手機 `390×844` 首屏。
5. 確認頁面沒有外部請求；每個公式用獨立數值人工交叉驗算至少一組。

> 〔模板說明〕`1440×900` 與 `390×844` 是常見的桌面／手機驗收尺寸，換成你自己的目標裝置即可，但要**寫死成數字**——沒有數字的「手機看起來還好」不算通過。

## 可複製的驗收片段

```sh
d="<課程目錄>"
# 1) 互動程式依賴的所有 id 仍存在於頁面（輸出應為空）
ids=$(grep -ohE 'getElementById\("[^"]+"\)' "$d"/*.js | grep -oE '"[^"]+"' | tr -d '"' | sort -u)
for id in $ids; do grep -qF "id=\"$id\"" "$d"/*.html || echo "MISSING id: $id"; done
# 2) 無外部資源（只允許回自家主站的連結；輸出應為空）
grep -ohiE '(src|href)="https?://[^"]+"' "$d"/*.html | grep -viE '{{自家網域，如 example.github.io}}'
# 3) 無 LaTeX 殘留（沒有數學渲染器時；輸出應為空）
grep -lE '\\\(|\\\)|\\\[|\\\]|\$\$' "$d"/*.html
# 4) 嚴格 UTF-8、無 BOM、無替換字元（輸出應為空）
for f in "$d"/*.html "$d"/*.js "$d"/*.css; do iconv -f UTF-8 -t UTF-8 "$f" >/dev/null || echo "BAD ENCODING: $f"; done
grep -lP '\xEF\xBB\xBF|\xEF\xBF\xBD' "$d"/* 2>/dev/null
# 5) 相對連結目標存在（輸出應為空）
grep -ohE 'href="[^"#:]+\.html' "$d"/*.html | sed 's/href="//' | sort -u |
  while read -r p; do [ -e "$d/$p" ] || echo "BROKEN LINK: $p"; done
# 6) 語法與規模
for f in "$d"/*.js; do node --check "$f"; done
wc -l "$d"/*.html "$d"/*.js
```

> 〔導入判斷〕課程頁面**有**數學渲染器（自帶或允許的依賴）→ 刪掉片段第 3 項並在 `BUILD-SPEC.md` 寫明用哪一種語法。同步：`workflows/study-site/enrich-existing.md` 的紅線第 6 條與其驗收片段。

## 零基礎加驗（套 foundations-first 時全數適用）

- 沒有未解釋的英文或縮寫債；術語首次出現有繁中、英文全名與必要縮寫。
- 名詞與概念**分開**驗：名詞有位置／功能／機制／邊界；概念有角色／狀態或資料流／因果／結果／可觀察證據。
- 基線薄弱時有明確 `00` 零基礎入口；術語跨頁反覆或約 15 個以上時有可搜尋字典，且不要求背完才准瀏覽。
- 超過單一概念群或約 6 個主要章節時已拆頁；每頁單一教學責任、DOM 契約獨立或安全共用。
- 首頁、章節導覽、上一頁／下一頁齊全，沒有孤兒頁。
- `PROJECT-BRIEF.md` 記得住讀者基線與 prerequisite gap，課程 README 記得住頁面地圖——[foundations-first](foundations-first.md) 的可延續性五問全部答得出來。

## 驗收紀錄

每門課在自己的 `驗收紀錄.md` 記：測試日期、環境、通過項、失敗項、已知限制、是否允許交付。跑不了的關卡（實機觸控、真人視覺）不是「通過」，是**待人工**——同時在 [WAIT_USER](../../WAIT_USER.md) 開一行。
