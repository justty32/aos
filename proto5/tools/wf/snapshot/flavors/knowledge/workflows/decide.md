# decide — 結構化決策（在幾個選項間選一個）

[WORKFLOWS](../WORKFLOWS.md)｜[INDEX](../INDEX.md)

把「選哪個」攤成選項、準則、評估，給出結論與**未選原因**。這裡管**決策過程**；結論的長期存放在 kernel 的 [decisions](decisions.md)。

**何時用**：兩個以上可行選項、決定不好回頭、或使用者說「幫我比一比再決定」。
**何時不用**：只有一條路，或改了隨時可回頭的小事。已經決定好、只是要留理由 → 直接去 [decisions](decisions.md) 加一列。問的是「要不要做 / 何時做」而不是「選哪個」 → kernel 的 [planning](planning.md)。

## Done when

- 下方「選項與評估」表每列每欄填滿，不確定處標 `?` 而不是留空。
- 決策檔有「結論 / 主要理由 / 未選原因 / 前提」四段。
- [decisions](decisions.md) 表多一列，且該列「未選方案與原因」與「前提」非空。

## 流程

1. 列出**真實可行**的選項，含「不做」這一項。
2. 定準則與相對重要性——準則來自**使用者的實際約束**（預算、時間、風險承受），優先於一般最佳解。
3. 逐選項對每個準則評估；不確定的標出來，不假裝確定。
4. 給明確結論與主要理由，不要列完優缺點就把球丟回去。
5. 寫下為什麼不選其他、以及結論建立在什麼前提上（前提變了要重看）。

## 交接

- **完成後 → 結論落到 kernel 的 [decisions](decisions.md)** 一列；本檔的過程記錄留著或歸檔皆可。
- **要執行 → 接 [plan-a-thing](plan-a-thing.md)**；產出是程式碼 → 開發 flavor 的 plan。
- 等使用者拍板 → [WAIT_USER](../WAIT_USER.md) 一行。
