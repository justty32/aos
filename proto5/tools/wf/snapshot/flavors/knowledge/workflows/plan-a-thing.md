# plan-a-thing — 規劃一件非開發的事

[WORKFLOWS](../WORKFLOWS.md)｜[INDEX](../INDEX.md)

把活動、旅行、搬家、流程改造這類**產出不是程式碼**的事，規劃成一份可執行、可追蹤的計畫。

**何時用**：使用者說「規劃一下這件事」「幫我排這個活動 / 行程」，而且產出不是程式碼。
**何時不用**：三兩步的小事直接做。還只是「以後可能要做」的想法 → kernel 的 [planning](planning.md) 記一列。產出是程式碼 → 開發 flavor 的 spec / plan。要先在選項間抉擇 → [decide](decide.md)。

## Done when

- 計畫檔存在，含「目標 / 不做什麼 / 步驟表 / 收尾」四段。
- 下方步驟表每列的「時間點」與「誰做」兩欄非空。
- 要使用者親自做的每一項，在 [WAIT_USER](../WAIT_USER.md) 有對應一行。

## 流程

1. **釐清目標與成功樣貌**：做完長什麼樣、怎麼算成功。
2. **定範圍**：一開始就寫「不做什麼」，範圍才不會無限膨脹。
3. **拆步驟與依賴**：誰卡誰、哪一步不做就全停。
4. **標時間點與負責人**，填進步驟表。
5. **執行 / 追蹤**：進行中的狀態記 [SESSION-LOG](../SESSION-LOG.md) 一行，不只留在聊天裡。
6. **收尾與回顧**：計畫執行完移進 `archive/`（規則見 [STRUCTURE](../STRUCTURE.md)）。

## 交接

- 中途要選方案 → [decide](decide.md)，結論回來繼續。
- 要產出對外文字（邀請函、公告、說明）→ [write](write.md)。
- 等使用者付錢 / 決定 / 親自出面 → [WAIT_USER](../WAIT_USER.md) 一行；訂位、報名、寄信這類對外動作守鐵律 2（授權來源）。

> 〔模板說明〕同時追多個計畫、或單一計畫長出子計畫時，照 [STRUCTURE](../STRUCTURE.md) 四級成長升級成 `plan-a-thing/` 資料夾，一計畫一檔。
