# proto3-1 設計：世界是 list，求值走 eval

← [proto3](../../proto3/README.md)（上一版：世界是 table、走元素叫 :func-tick）

使用者原話（09-08）：「開 proto3-1，這次試試看把 list 作為世界，求值走 eval。同樣兩套都做。」

## 一句話

**一個世界＝一個 list（form）＋一個環境（folder）。跑一格＝在那個環境裡 eval 那個 list。**
proto2 的 `.aos/inst` 是「一句 shell，跑完可以把下一句寫回去」；這裡 inst 就是 list、
寫回去就是 `(next 新form)`。狀態機不再是 `case`，而是 **form 改寫**：idle 的 form 求值後
換成 think 的 form，think 換成等待的 form……

## 兩套都要一樣的東西

### 世界
- `(make name form & kvs)` 建世界，回傳「環境」（folder）。環境裡放：`:path`（身分＝父 path/名字）、
  `:form`（現在的 list）、`:now`（走了幾格）、`:inbox`／`:outbox`、`:kids`、`:ticks` 會計、
  `:frozen`。**path 就是身分**，`all`／`at` 用 path 找世界（同 proto3）。
- `(dotick env)`：frozen 就記 frozen；否則 `:now` +1、**eval `:form`**，求值期間若叫過 `(next f)` 就把
  `:form` 換成 f；回傳這格做了什麼（form 的回傳值是 `:busy`／`:wait`／`:idle` 就照記，其他算 busy）；
  借鐘的小孩在父求值時跟著求值一格。
- **狀態要跨格留在環境裡**：Janet 用 `(make-env root-env)`，form 裡 `(def x …)` 下一格看得到——
  binding 就是資料夾裡的檔案。CL 沒有一等環境，用動態變數 `*me*` 綁目前世界的 hash table，
  form 裡用 `(var 'x)`／`(setvar 'x v)` 讀寫（老實記下這個差別，不要硬模擬）。

### form 裡可以用的原語（綁在環境裡／透過 *me*）
`me`（自己的環境）、`(now)`、`(next form)`、`(say x)`、`(send to-path x)`、`(mail &opt pred)` 拿信、
`(kid "name" form)` 子世界＝巢狀 list：第一次求值時建立（path＝父/名字、`:clock :shared`），之後每次
父求值它就跟著求值一格；`(kid "name" :own form)` 只建立、不跟著走，要另外向 kernel 登記。
`(kill path)`。

### 時鐘（kernel）— 同 proto3
`register`／`unregister`／`pause`／`continue`（CL 叫 `resume`）／`ls`／`step-all`／`run`／`start`／`stop-all`。
同步模式 interval＝每幾格動一次；非同步 Janet 一鐘一 fiber、CL 一鐘一 thread（求值加全域鎖）。

### LLM 世界 — 同 proto3，但它的 form 是 `(llm-step)`
佇列、`ask` 不等、每格處理 max-per-tick 筆、三態 pending→running→done/failed、結果以信
`{:kind :llm-result :id :reply :error}` 寄回請求者、`usage` 按請求者計數。`echo-engine`、`script-engine`。

### agent — 只勾輪廓，但**狀態機用 form 改寫**
`(agent/make name llm & kvs)` 的初始 form 是 `(agent-idle)`：
- `(agent-idle)`：有非 llm-result 的信 → 記進 history、記 asker、`(next '(agent-think))`、回 :busy；沒信回 :idle。
- `(agent-think)`：`ask` LLM，然後 `(wait-for until then timeout)`——這是 helper，效果是
  `(next '(agent-wait …))`，把「等到什麼算數／等到了做什麼／幾格放棄」帶在 form 裡。
- `(agent-wait …)`：until 有東西 → 叫 then（then 自己決定 `next` 成 act 或 idle）；逾時 → `(next '(agent-idle))`；否則回 :wait。
- `(agent-act)`：回覆進 history、`say`、回信給 asker、`(next '(agent-idle))`。
- 模型出錯先簡單回 idle 並記 `:last-error`（同 proto3）。

### 範例（main）與 proto3 同一個劇情
報時世界、echo LLM、agent-1（system「你是 agent-1」）底下 shared-kid 與 own-kid（interval 2）、
user 世界寄「你好，agent-1」、observer 印狀態變化（狀態＝現在的 form 的第一個符號）。
同步 `8` 格／`async 5` 秒兩種跑法，結尾印 agent-1 說了什麼、user 收到什麼、會計、鐘。

### 測試：proto3 的 36 條精神照搬，再加 eval 特有的
- 狀態跨格留在環境裡（Janet：form 裡 `(def x …)`；CL：`setvar`）。
- `next` 改寫：一個 form 求值後換成另一個，下一格跑的是新的。
- 沒叫 `next` 就維持原 form（每格重跑同一句）。
- kid 巢狀 list：第一次求值建立、之後跟著走；`:own` 不跟著走。
- observer 看得到 agent 的 form 從 agent-idle → agent-think → agent-wait → agent-act → agent-idle。
