# toolsmith 試玩記錄

## 做的時候的坑

- 規格草稿原本把 `pack` 寫成打開既有包。任務書要求它直接寫一份自己家的骨架，所以這輪照任務書。
- `Ctx` 沒有文字檔寫入把手。pack 骨架用自己的 `open()` 寫，沒有改共用接點。
- 這一格已載入的工具清單不會變。`tool_try` 必須自己再讀一次 `tools.json`，才能當格試跑。
- 假 LLM 的測試劇本不能解析巢狀 JSON。整合測試的 `tool_add` 省略 `parameters`，另用直接測試驗 schema 補齊。

## 玩的紀錄

- 使用者：幫自己造一個工具叫 today，印今天日期，然後用它
- agent → `tool_add`：`{"name":"today","description":"印出今天日期","command":"date +%Y-%m-%d"}`
- tool_add：工具加好了；現在用 tool_try 試跑，正式清單下一格生效
- agent → `tool_try`：`{"name":"today"}`
- tool_try：`{"exit":0,"stdout":"2026-09-06\n","stderr":""}`
- agent：工具 today 造好了，一跑就印出「2026-09-06」✅

## 玩的時候的坑

- 試玩複本的 `llm.json.dir` 第一遍被我算成相對 home。這欄其實相對世界，請求因此落到沒鐘的資料夾，等 60 格才回白話逾時。修正後重送就成功。
- 模型把「然後用它」做成 `tool_try`，沒有再等下一格呼叫正式的 `today`。這符合包的 prompt；下一格正式可呼叫另有自動測試驗過。

## 缺什麼接點

- 沒缺。寫 pack 骨架可直接用 Python 標準函式庫。

## 介面簡不簡潔（我自己的評分與哪裡可以更簡）

9/10。四個工具名直接對應新增、查看、移除、試跑。

`tool_add` 同時做 shell 工具和 pack 骨架，是唯一稍微混合的地方。
任務已指定用同一個入口，所以沒有再拆工具。

## 內部機理簡不簡單

9/10。只有一個 Python 檔。
shell 工具仍是 `tools.json` 加一句 command。
試跑只用 `subprocess.run`。
pack 骨架只是普通 `.py`。

## 效能與邊緣狀況（留給使用者看）

- 每次操作都整份讀寫 `tools.json`。工具很多時會慢。
- `tool_list` 每次走過所有已載入的包與工具。現在數量小，不處理索引。
- 沒有檔案鎖。兩個同時寫會互相蓋掉。
- shell 沒有逾時。卡住會卡住這一格。
- 沒有沙箱、路徑限制或危險指令審批。
- 自製工具撞到包裡的同名工具時，包裡的會贏。
- pack 骨架已存在時不覆寫，也不會只幫它重新啟用。
- 關 pack 只改清單，不刪骨架檔。
