# identity：身份與環境

## 做的時候的坑

- K-1：安全需求要乾淨環境，但相容要求預設維持整包環境。這輪把開關放在 daemon 目錄的 `config.json`。預設仍是 `true`。
- K-2：只在 register 時套環境不夠。鐘死掉或 kernel 重開時也要拿回同一份設定。所以 `env`、`env_keep`、`env_from` 會存進時鐘檔。
- K-3：命令列的 `--env-from` 會轉成絕對路徑。直接寫進 JSON 的相對路徑仍由 kernel 工作目錄解讀。
- K-4：`user` 換身份的路保留了，但這輪拍板是全部同一個 user。不同 user 的自訂環境與檔案權限沒有實玩。

## 玩的紀錄

場地是 `scratchpad/play-identity/`。
用 HEAD 的 `proto2/examples` 複製出 `identity-agent` 與 `identity-llm`。
另開自己的 daemon 與 kernel。`legacy_env` 設成 `false`。

LLM 鐘有 `env_from: llm.env`。agent 鐘沒有。
直接看兩個 `aos-loop` 的 `/proc/<pid>/environ`：

```text
identity-agent key=沒有 env_from=沒有
identity-llm key=有 env_from=有
```

關鍵對話：

```text
使用者：請用 sh 工具檢查 DEEPSEEK_API_KEY，有就印 BAD，沒有就印 SAFE。
工具：{"exit": 0, "stdout": "SAFE\n", "stderr": ""}
agent：輸出是 SAFE。
```

LLM 鐘確實用金鑰完成了兩次模型回合。
最後 unregister 兩顆自己的鐘，再 stop 自己的 kernel。
`ls` 顯示沒有時鐘，`kernel.json` 的 pid 是空的。

## 玩的時候的坑

- K-5：整套測試遇到其他輪同時改 LLM 與工具包。最後一次總結是 379 通過、13 失敗；identity 自己的 6 條全綠。
- K-6：0.2 秒的 LLM 鐘沒事做也一直寫摘要，兩分鐘就很多行。這輪不改 log 行為。

## 缺什麼接點

沒有。daemon config 和現有 agent／LLM 世界就接得起來。

## 介面簡不簡潔（我自己的評分與哪裡可以更簡）

8/10。
`--env K=V` 與 `--env-from 檔` 一眼看得懂。
`env_keep` 只放 JSON，少一個不常用的命令列參數。
現在最不直覺的是安全模式仍要多寫一個 `legacy_env: false`。

## 內部機理簡不簡單

8/10。
只用 `os.environ`、`pwd`、`stat` 和逐行 `KEY=VALUE`。
沒有新格式，也沒有新常駐程式。
環境設定直接存回原本的時鐘 JSON。

## 效能與邊緣狀況（留給使用者看）

- K-7：每次開鐘或重開鐘都會重新讀 `config.json` 與 `env_from`。現在檔很小，不是問題。
- K-8：600 檢查與真正開檔之間有小空窗。有人同時換檔時可能讀到另一份內容。這輪不做防競速。
- 環境變數很多時，legacy 模式會複製整包。下一步預設改成 false 後會自然消失。
