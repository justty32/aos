# 簡化輪實玩（二）

## 介面前後

- 以前：`ctx.send(..., timeout_steps=120)`，pending 記 `since_step`／`timeout_steps`。
- 現在：`ctx.send(..., timeout_s=600)`，pending 只記 `since_ts`／`timeout_s`；沒有保留格數版參數。
- 以前：每題每格都加一，睡著等旁線也會吃掉 60 格上限。
- 現在：睡著且該格沒做事只加 `question_steps.sleeping`；醒來後才續加動作格。
- 缺鐘不再假裝成 timeout，`kind_of_error` 是 `no_clock`。

## 刪除與行數

- 刪掉 `SIDE_TIMEOUT_STEPS`、`timeout_steps`、`since_step` 與 think 的 `wait_steps`。
- 本輪程式 8,460 → 8,463 行，多 3 行（不含同時出現的 `aos-user` 6 行）；工具仍是 74 個。
- README 加 docs 1,607 → 1,608 行，多 1 行。

## 假 server／假 pending 實玩

- 用測試 helper 的世界放一筆永遠不回的 pending，連推三格：動作格保持 3，睡眠格變 3。
- 等 2.1 秒再推一格：請求以 timeout 醒來，動作格才變 4。
- 另用假 LLM server 跑原本的 60 格硬上限鏈；回「繼續」後仍從原題格數接著走。
- 牆鐘短逾時與取消都落 `side/` 並回聊天錯誤；目標沒鐘則立刻回 `no_clock`。

## 還沒簡化到

- 主線 LLM 的等待仍是 `LLM_WAIT_TICKS=60`，不是牆上時間；這輪只改旁線。
- `branch` 若供應商回空內容，模型仍可能自行補一次 think。
- pending 與 state 仍沒有鎖；多個時鐘同推一個 agent 可能互蓋。
