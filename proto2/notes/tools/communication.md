# 工具包：跟別的 agent 講話（comm）

一句話：讓一個 agent 把信寫進**別人的** `inbox/`，並且知道自己認識誰。

現在的 `mailbox` 包只會讀自己的信。這一包負責寄。兩包分開，不合併。

## 工具清單

### `mail_send`

- 參數：`to`（對方的名字）、`content`（要說的話）。
- 回：`{"ok": true, "to": "helper", "id": "20260906-140311-004221.json"}`；找不到人就 `{"ok": false, "error": "通訊錄裡沒有這個人：xxx"}`。
- 什麼時候用：你想主動跟某個 agent 說一件事。名字不確定就先 `mail_who`。信寄出去對方不會馬上看到，是它下一格自己去撿的。

### `mail_reply`

- 參數：`source`（那封信是哪個來源來的）、`id`（那封信的檔名）、`content`。
- 回：跟 `mail_send` 一樣，多一個 `reply_to`。
- 什麼時候用：你剛用 `inbox_read` 讀完一封信、要回它。用這個而不是 `mail_send`，對方才看得出你在回哪一封。

### `mail_broadcast`

- 參數：`content`、`to`（選填，一串名字；不給＝你的家人：父 ＋ 你所有的小孩）。
- 回：`{"ok": true, "sent": ["parent", "helper", "writer"], "failed": []}`。
- 什麼時候用：同一句話要講給一群人聽（交代進度、喊停）。不要拿它當閒聊，每個人都會被叫醒一格。

### `mail_who`

- 參數：`alive_only`（選填，只列現在真的有資料夾在的）。
- 回：一列一個人：`{"name": "helper", "relation": "kid", "dir": "…/kids/helper", "exists": true}`。
- 什麼時候用：想寄信但不確定名字怎麼拼、或想知道自己認識誰。

### `mail_wait`

- 參數：`id`（你剛寄出那封信的 id）、`note`（選填，一句話提醒自己在等什麼）。
- 回：`{"ok": true, "waiting": 1}` — **馬上回，不會卡住這一格**。
- 什麼時候用：你寄了信要等回覆才能繼續。登記完就把這一輪講完、去做別的；回信到的時候狀態機會多跟你說一句「你等的那封回來了」。**沒有阻塞的等法**，這個世界一格就是一格。

登記寫在 `<home>/waiting.json`，就是一串 `{"id","note","time"}`。回信（`reply_to` 對得上）進來時那筆被劃掉。

## 使用者的特殊地位

使用者也是一個 agent，但有三點不一樣，而且**故意不對稱**：

1. **他的信直接進 prompt。** 來源 `user` 的信不用工具去讀，`idle` 那格就直接接進記憶（前面加 `[user] `），檔案當場搬進 `read/`。這是現在就有的行為，保留。
2. **不能被忽略。** 別人的信只會被通知一句「你有新信」，模型不去讀就算了；使用者的信是直接塞進去的，模型看得到就一定得面對。
3. **優先級最高。** 同一格裡有 user 的信也有別人的信，user 的先進記憶，其他的只提一句。

使用者自己的資料夾（`AOS_USER_DIR`，例如 `~/.aos/me`）長得跟別的 agent 一樣：

```
~/.aos/me/inbox/<誰>/*.json     別的 agent 寄給我的（未讀）
~/.aos/me/inbox/<誰>/read/      我看過的
~/.aos/me/outbox/<四位數>.json  我說過的話的存底
```

差別是它**沒有 `.aos/inst`、沒有時鐘、沒有 LLM**——人自己就是那個時鐘。agent 寄信給 `user`，就是往這個資料夾的 `inbox/<agent 名字>/` 寫檔。

`aos-user` 之後就改名叫 `aos-me`，動作對應過來：`say` ＝ 幫我寄一封信（順手落一份到我的 outbox）、`listen` ＝ 盯**我自己的** inbox（不是盯對方的 outbox）、`talk` ＝ 兩個合起來、`status`／`spawn` 不變。這個轉換等寄信這包做完再做，不急。

## 一封信長怎樣

```json
{
  "from": "planner",
  "to": "helper",
  "time": "2026-09-06T14:03:11",
  "content": "先把 README 那段改完再叫我",
  "reply_to": "20260906-140033-991020.json",
  "thread": "20260906-140033-991020"
}
```

- **必填只有 `content`。** 其他讀的人讀不到就自己補預設（`from` 補成資料夾名、`time` 補空字串）。
- `from`／`to`／`time` 由寄信工具自己填，模型不用管。
- `reply_to`：回哪一封（就是對方那封信的檔名）。只有 `mail_reply` 會填。
- `thread`：一串對話的 id ＝ 這串第一封信的檔名去掉 `.json`。沒有 `reply_to` 就是自己開一串。
- 檔名還是時間戳到微秒，跟現在一樣。多帶別的鍵沒關係，沒人管。

## 跟現有東西怎麼接

- **寄信 ＝ 往對方的 `<home>/inbox/<我的名字>/` 寫一個 JSON 檔。** 就這樣。已經有 `put_mail(home, source, text, sender)` 了，多塞 `to`／`reply_to`／`thread` 就夠。
- **對方的 home 怎麼算**：通訊錄存的是**世界資料夾**路徑，再用現成的 `resolve_home()` 從它的 `.aos/inst` 撈 `--home`。
- **通訊錄從哪來**：`<home>/contacts.json`，`{"名字": {"dir": "...", "relation": "..."}}`。三種來源自動填：
  - `user` — 一開始就有，指到 `AOS_USER_DIR`。
  - 小孩 — `spawn` 的時候父在自己的 contacts 加一筆 `kid`，同時在小孩的 contacts 加一筆 `parent` 指回來。
  - 手動 — 人自己去編那個檔。**沒有自動探索、沒有註冊中心。**
- **誰有權寫**：檔案系統權限就是權限。同一個使用者跑的時鐘互相寫得到，寫不進去就回一句錯誤。daemon 換身份跑的鐘會寫不進去，撞到再說。
- **`outbox` 不動**：它還是「這個 agent 說出口的話」的存底，誰想看自己去看。寄信是另一件事。
- 跨機器：不管。

## 現在故意不做

- 冒名（`from` 誰都能亂寫，沒有驗證）
- 送達確認、讀取回條、退信
- 信箱上限、過期清理、`read/` 永遠長大
- 等回信的逾時（登記了就一直等）
- 廣播打回來的迴圈（A 廣播 B、B 又廣播 A）
- 同一微秒兩封信撞檔名
- 鎖、寫到一半被讀（`put_mail` 還不是原子寫）
- 群組／團隊的成員管理（只有「家人」一種）
- 附件、大檔、加密、封鎖某人
- 對方資料夾在跑但不是標準 agent

## 要拍板的（5 條）

1. **定址用名字還是路徑？** 建議名字，靠 `contacts.json` 轉路徑——路徑太長、模型會抄錯。
2. **agent 回話要不要也變成「寄一封信給 user」？** 建議要，但 `outbox` 存底保留，兩邊都寫。
3. **廣播預設寄給誰？** 建議「家人」＝父 ＋ 所有小孩，不另外定義團隊這個概念。
4. **孫子輩認不認識爺爺？** 建議不認識，contacts 只有直接的父跟直接的小孩，要通訊自己轉手。
5. **`mail_send` 給一個不存在的人，是回錯誤還是靜靜丟掉？** 建議回錯誤，模型才知道要改。
