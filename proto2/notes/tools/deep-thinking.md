# deep-thinking 工具包

一句話：讓平常用快模型的 agent，遇到難題時借一台更會想的模型，分幾格慢慢想完，再拿回短結論。

平常那一輪 LLM 是決定下一步。深度思考是工具工作。
它可以排隊，可以跨很多格，也有自己的預算。
agent 不必停住整個時鐘。每格仍然只做丟請求、看結果、存一小段其中一件事。

## 工具

### `think(question, budget?)`

- 參數：`question` 是要想清楚的問題。`budget` 可改 token、格數和金額上限。
- 回：完成後回短結論、最多三個理由、仍不確定的地方、`thought_id` 和實際用量。
- 怎麼跑：這格只寫一個 `think-<id>.json` 到 LLM 的 `requests/`。不等網路，也不先塞假的工具結果。
- 預設 prompt：事情牽涉多步判斷、代價很大，或你連續兩次都沒有進展時才用。簡單查詢和可直接試的小事不要用。

`aos-agent` 把原本的工具呼叫編號記住，接著進現有的 `wait`。
結果出現後，`wait` 把答案包成那次工具呼叫的結果，再走 `collect`。
請求仍走同一個 LLM 資料夾，只換 thinker engine、較低優先級和 `think-` 檔名前綴。

### `think_steps(question, budget?)`

- 參數：`question`，以及可選的 `budget`。第一版固定最多三步。
- 回：全部完成後回 `thought_id`、一句摘要和「可以呼叫 `conclude`」。
- 怎麼跑：第一步看原問題。之後每一步只看原問題和上一步的短結論，不重送更早內容。
- 預設 prompt：問題可以明確拆成幾個判斷時用。每一步只解一件事，先寫本步結論，再決定下一步。

中間內容放在 `<home>/thoughts/<id>/`。
`meta.json` 記問題、狀態、預算和用量。
`01.json`、`02.json`、`03.json` 各放一個步驟的短結論。
`conclusion.md` 放最後結論。
收到一個步驟的結果後先落檔，再送下一個請求，仍留在 `wait`。
中間內容不進 `prompts.json`。

### `critique(draft, budget?)`

- 參數：`draft` 是要檢查的答案或計畫。`budget` 可選。
- 回：最多三條。每條只有漏洞或反例、為什麼重要、最小修法，另附用量。
- 怎麼跑：也是一個非阻塞的 thinker 請求。結果回來才接成工具結果。
- 預設 prompt：答案要交付、改動難回頭，或你對自己的結論太有把握時用一次。不要為普通措辭反覆批評。

### `conclude(thought_id)`

- 參數：`thought_id`。
- 回：`conclusion.md` 的短結論、採取動作、主要風險和總用量。
- 預設 prompt：多步思考完成後一定用它收尾。只把結論帶回對話，不把逐步內容抄回來。

這個工具的回傳才進日常對話與記憶。
原問題、中間步驟和原始結果繼續留在 `thoughts/`。

### `thoughts_list()`

- 參數：無。
- 回：最近的思考編號、題目短句、狀態、步數、用量和完成時間。
- 預設 prompt：你記得以前想過相近問題，但不知道編號時先用。平常不要每輪檢查。

### `thought_read(id)`

- 參數：`id`。
- 回：題目、每一步的短結論、最後結論和用量。內容太長就截斷。
- 預設 prompt：只有真的需要重查理由或接續未完成思考時才用。只要答案時改用 `conclude`。

## 何時該用

這三句直接放進 `PROMPT`：

1. 要同時權衡三件以上的事、錯了很難回頭，或一般作法試了兩次仍卡住，才深度思考。
2. 能查到、能算出、能用一次小實驗驗證的事，先直接做，不要深度思考。
3. 一個問題最多開一份思考；開始後等它完成，不要重複送同一題。

## 預算

一次思考預設最多 6000 個輸出 token、三個步驟、等待 120 格、估計 0.10 美元。
`budget` 可以往下改，不能超過這組預設上限。
每個請求都帶 `params.max_tokens`。多步時按剩餘步數分配剩餘 token。
送下一步前，先用 `engines.json` 的單價估錢。估計會超過就不送。
token、步數或等待格數用完，就保存已有內容，回 `budget_exceeded` 和目前最好的短結論。
已經送出的請求不能把錢收回。實際金額若超過估計，照實記帳並立刻停止後續步驟。

每次結果都附 LLM 回的完整用量、思考 token 和估計金額。
帳本照工具成本的做法記在 `think`、`think_steps` 或 `critique` 名下。

## thinker engine

建議在 `engines.json` 的引擎上加 `"role": "thinker"`。
能力是引擎自己的資料，不放進每個 agent 的 `llm.json`。
工具固定選第一台 `role` 是 `thinker` 的引擎。

本機只有小模型時，就再登記一個指向同一個 endpoint 和 model 的 `local-thinker`。
它的 `params` 開啟該模型支援的思考模式，並給較大的 `max_tokens`。
這仍是同一台機器，只是用另一組跑法。

## 跟現有狀態機怎麼接

- 新增 `packs/think.py`，內含六個工具、預設 prompt、請求建立和思考檔案讀寫。
- 非阻塞工具回一個內部等待記號。`aos-agent` 看到後不寫普通工具結果，改進 `wait`。
- `state.json` 沿用 `request`，再加 `request_kind`、`tool_call_id`、`thought_id`、`thought_step`、`thought_budget` 和 `thought_started_step`。
- `request_kind` 是 `normal`、`think`、`think_steps` 或 `critique`。`wait` 靠它分流，不靠檔名前綴猜。
- 普通 LLM 結果仍接成 assistant 訊息。深思結果接成原工具呼叫的 tool 訊息，或只落進思考檔案。
- `think_steps` 的中間結果只落檔。最後回一個完成通知，等模型呼叫 `conclude`。
- `<home>/thoughts/` 加進 `.gitignore`。它是執行中的私有資料，不進版本庫。

## 不找別人一起想

第一版不生小孩，也不寄信問別的 agent。
深度思考只是同一個 agent 借更會想的 engine，題目和責任都還在自己身上。
`kids` 適合把工作交給一個有自己記憶、工具和時鐘的小孩。
communication 適合詢問已存在、可能知道別件事的 agent。
把這三種路混在一起會多出權限、等待、失聯和費用歸屬，先不做。

## 現在故意不做

- 同時開兩份思考，或一輪同時叫深思工具和其他工具。
- 取消已送出的請求，以及清掉逾時後晚到的結果。
- thinker 掛掉後自動換另一台、重試或續跑。
- 多個進程同時改同一份思考，現在不上鎖。
- 自動清理很舊的 `thoughts/`。
- 不同供應商的思考開關自動翻譯。
- 精準保證金額上限。送出前只能估，送出後只能照實記。
- 把模型沒有回傳的隱藏思考內容硬挖出來。

- T-41：一次上限用 6000 輸出 token、三步、等待 120 格、0.10 美元？建議先這樣。
- T-42：深思沿用 `wait`，靠 `request_kind` 分流，不新增第六個狀態？建議是。
- T-43：多步思考只把原問題和上一步短結論送進下一步？建議是。
- T-44：只有 `conclude` 把結論放進記憶，整個 `thoughts/` 不進 git？建議是。
