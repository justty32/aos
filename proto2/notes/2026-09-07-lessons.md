# 跑一間 LLM 工作室前要知道的事

← [play/README](play/README.md)｜過程與時間軸 [studio-journey](2026-09-07-studio-journey.md)｜設計說明 [studio-efficiency](2026-09-07-studio-efficiency.md)

2026-09-07 一天實玩四局（qwen → haiku／sonnet）換來的。順序就是動手的順序：**先堵死路 → 再量 → 再固化 → 再換模型 → 最後才調預算**。前面沒做完就跳到後面，錢一定白燒。

## 一、先堵死路（沒有人再叫醒它 ＝ 整局結束）

1. 看到任何 `return "idle"` 都先問一句：**「誰會再叫醒它？」** 沒答案就是死路。前三局全死在這裡，修法只有幾行。→ `aos-agent`
2. 信通知過但沒讀成，要再提醒。→ `aos-agent` 未讀信閒滿 30 格重提醒（睡著的人也叫醒）
3. 模型回錯之後不能就這樣回 idle。→ `aos-agent` `llm_errors` 20 格重送、連錯 5 次才放著、新信來重來
4. 安全網：閒著而對話尾巴是「沒人回的話」就不准放著。→ `aos-agent` `dangling_turn()`（泛用 stuck 狀態還在做）
5. 做到一半停下來也是死路。→ `packs/studio.py` `on_idle`：手上有任務卻閒著，45 格後提醒自己，三次沒動改寄主管「我卡住了」
6. 互等死結（A 等 B 回信、B 等 A 撥錢）：睡著的人也要被信叫醒。→ `aos_agent.py` `scan_inbox`
7. 等的格不算「每題動作格」，不然還沒等到就撞上限停下來問人。→ `aos-agent` `LLM_WAIT_TICKS_ALIVE`
8. 每格都可以改程式（一格一個進程），坑當場修當場生效，不必重開實玩。這是修得動二十幾條的前提。

## 二、再量（不量就會修錯地方）

9. 量之前先確認**真的量到了**。我從 `proto2/` 裡跑 `test.sh` 看到「全部通過」就信了，其實一條包測試都沒跑。→ `test.sh` 以腳本位置定根目錄、找不到包測試就紅
10. 量了才知道：**prompt 占 96% 的 token**，其中一半以上是根本用不到的工具表。→ `tools.json` 的 `only` 白名單（PM schema 13,439→2,827 字）
11. PM 26 輪裡 16 輪只在讀信等信；讀一封信 2～3 輪 ≈ 20k。→ `inline_mail`：信整封直接進 prompt
12. 撥一次額度 4 輪 ≈ 35k，而且小模型常把 grant 寫成文字沒真的做。→ `team.json` 的 `auto_grant`：閘門自己撥、不叫模型
13. 用 `team why`／`team tail` 看局，不要再拼 state.json＋monitor.log＋inbox。→ `aos-user`

## 三、再固化（LLM 只做要判斷的事）

14. 能寫死就寫死：接單、派工、撥錢、回報、驗收、交付都是「搬東西」，一個工具一次做完一串。→ `packs/studio.py` 九個工具
15. 剩給模型的只有三件：拆任務、寫程式、判過不過。其他都不該讓它動腦。
16. **規則放工具，不放人格。** 人格寫的它會忘，工具擋的它繞不過。
17. 小模型的毛病很固定，一條一條擋：
    - 自己編單號 → `order_accept` 給錯單號就接最新那張
    - 工具呼叫寫成文字（`<tool_call>`、純 JSON、```plaintext 裡「工具名: {參數}」）→ `aos-agent` 認得的救回來、救不回來同題重送
    - 測試紅字視而不見報「全過」→ `packs/studio.py` `task_report` 的 `test_cmd` 沒過就退回，任務不算完成
    - 空泛提醒只回一段計畫 → 提醒直接寫「現在就 read → write 整檔 → run_checks → task_report」
    - qa 又寫又驗 → 不能派任務給 qa；沒有一筆 exit 0 的測試紀錄不能判過
18. 共用檔一定要鎖。8 進程各撥 20 次，有鎖 160 筆不掉、沒鎖只剩 23 筆還把 budget.json 寫壞。→ `aos_agent.py` `team_lock()` flock
19. 好資產比好 prompt 便宜：骨架、標準檢查一次生成。→ `packs/pyshop.py` `scaffold`／`run_checks`

## 四、再換模型（流程穩了才有意義）

20. **不要跟模型的習慣打架，順著它然後在系統端收口。** 想讓模型「用 JSON 描述工具呼叫」是跟本能作對——會用工具的模型看到工具名就直接叫。→ `aos-llm` claude-cli 改走 MCP：`aos-mcp-tools` 只登記不執行、`--max-turns 1` 第一輪就停
21. 換引擎的坑幾乎都在接口層，不在流程層（4d 六條全是）。分層對了，換引擎就是一小時的事。→ `aos-llm`、`aos-loop`
22. 借別人的 CLI 當引擎要把它的身份整個換掉：`--system-prompt` 不是 `--append-`（省下 Claude Code 那兩萬 token，30k→2.6k、五輪→兩輪）；`--safe-mode` 會連 MCP 一起關，改用 `--setting-sources "" --disable-slash-commands`。
23. **qwen 跟 haiku 是兩種病**：qwen 是「做不出來」（`edit` 對不上原文、繞二十輪），解法是換模型；haiku 是「做得出來但貴」（對話史帶整檔，一輪 10k→20k），解法是管記憶。別把兩件事混著想。

## 五、最後才調預算

24. 天花板就是煞車，要留著，但要跟引擎配：`max_per_member` 100k 對 qwen 剛好、對 claude-cli 太低（4d 手動抬到 250k）。→ `presets/studio/team.json`
25. 凍住之後不能等 300 格才再試。→ `aos-agent` `AUTO_GRANT_RETRY_TICKS`＝每 10 格重試自動撥款
26. **帳面不等於成本**：claude-cli／anthropic 的 `prompt_tokens` 把 `cache_read` 也算進去（真實約 1/10），4d 帳面 841k 一半以上是 cache。要不要打折還沒決定。→ [WAIT_USER 11](../../wf/WAIT_USER.md)
27. 池子乾了要有人開口問甲方，不能全隊安靜凍死。→ 閘門撥不出來時替 sales 對甲方喊追加

## 派工與自己操作

28. 開 agent 並行真的快，但**規格要先寫死、各管各的檔**（事先講好誰不能碰哪個檔，兩批各四個都沒撞到）。
29. opus 給的回報有量測、會主動說「我沒驗到什麼」；sonnet 做得對但會停下來等背景、還同時開三份全套。**給 sonnet 要寫死：前景跑、不要等通知、不要平行開測試。**
30. 我自己兩個失誤是同一種：明知有東西在跑還去動它（看到「全部通過」就信；明知 agent 在跑測試還 `git stash`）。
