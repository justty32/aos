## 一、三分鐘看懂（我們聽到的）

一個資料夾就是一個程式，像 lisp 的 list、lua 的 table。資料夾裡要有一個**入口**，入口放哪由環境變數 `AOS_ENTRY` 說（例：`.aos/inst`），入口**必須是可執行檔**。規矩就這一條。

**寫程式**＝建一個資料夾 `agent-bob/`，在 `agent-bob/.aos/inst` 放一個 shell 檔、`chmod +x`，內容一行 `aos-loop loop.json`；`loop.json` 放在 `agent-bob/` 裡。慣例：跑的時候 cwd 就是 `agent-bob/`，所以 `loop.json` 用相對路徑直接找得到。

**使用**＝三步：設環境變數 `WS=workspace/`、`cd agent-bob`、跑入口。三步縮成一句 `aos-exec workspace agent-bob`，意思是「在 workspace 這個資料夾，執行 agent-bob 這個程式」。

**aos-exec 不管裡面**：agent-bob 怎麼用 cwd、怎麼讀寫 workspace，是 agent-bob 自己的事。

**拿掉的**：inst.json 的 key 規矩、stdin 放定義、門房掛 `.aos` 捷徑——這些都嫌麻煩。aos-exec 只做「設環境變數、cd、跑入口」。

## 二、字面上要確認的小地方

1. 原話寫「跑`./aos/inst`」，前面寫 `AOS_ENTRY=.aos/inst`，差一個點。猜是 `./.aos/inst` 的筆誤。
2. 原話的 `WS` 與週五定的 `AOS_WS`（N-55）是同一個東西嗎？`AOS_ENTRY` 有 `AOS_` 前綴、`WS` 沒有，是順手簡寫還是真想改短？
3. 「cwd 是 agent-bob/，這會是慣例」和「agent-bob 如何處理 cwd 是它自己的事」怎麼並存？我們的解讀：**起跑時** cwd＝agent-bob/ 是 aos-exec 保證的；起跑**之後** agent-bob 愛 cd 去哪是它的事。對嗎？
4. `AOS_ENTRY` 是整套 aos 固定成 `.aos/inst`（環境變數只是放這個常數的地方），還是呼叫方可以換（例 `AOS_ENTRY=.aos/test` 跑另一個入口）？
5. `loop.json` 的位置「是 agent-bob」：是 `agent-bob/loop.json`（頂層），還是 `agent-bob/.aos/loop.json`？`.aos/` 裡只放入口、其他都放頂層嗎？

## 三、邊緣狀況（會撞到的）

1. **入口不存在、或存在但沒 `+x`**。aos-exec 怎麼說？可能的選項：只報錯退 1（照 N-43）；或自動 `chmod +x`；或退回去找 `inst.json`。
2. **入口不是 shell 而是二進位或 python**。`exec` 本來不管是什麼，OS 認 shebang 就跑。可能的選項：規範只寫「可執行」，不管種類。
3. **巢狀**：agent-bob 裡的 `tools/brush/` 也有自己的 `.aos/inst`。agent-bob 叫它時寫 `aos-exec ？ tools/brush`——第一個參數給誰？`tools/brush` 從哪算（cwd＝agent-bob/，應該自然）。可能的選項：WS 照環境變數本來的樣子往下傳、第一個參數可省＝繼承；或第一個參數必填、要同一個 workspace 就自己寫一次。
4. **相對路徑**：`aos-exec workspace agent-bob` 兩個參數都相對於打指令的地方；但 cd 進 agent-bob 之後，`WS=workspace/` 這個相對路徑就指錯地方了。可能的選項：aos-exec 一律把 WS 轉成絕對路徑再設。
5. **WS 沒設**：不經 aos-exec、直接 `./.aos/inst` 時 WS 是空的。可能的選項：aos-exec 必填不給預設（跟待定裡「WD 必填、不設預設 `.`」同向）；直跑時 agent-bob 自己負責（C-53：誤用不歸組件管）。
6. **「這次要做什麼」放哪**：stdin 規矩拿掉後，話／參數進得去的門只剩環境變數、workspace 裡的檔、aos-exec 多餘的參數、stdin 原樣透傳。可能的選項：aos-exec 不管，stdin 與多餘 argv 原樣透傳給入口（像 `exec`）；或規定放 workspace 裡某個檔。對照 C-58「話放 stack」。
7. **結果與結束碼去哪**：aos-exec 是像 `exec()` 把自己換成入口（stdout、結束碼全透傳），還是自己包一層、只退 0／1？對照 C-63「結束碼只是參考」。可能的選項：直接 `exec()` 取代自己，最省。
8. **同一個 agent-bob 被兩個 workspace 同時跑**。cwd＝agent-bob/，aos-loop 的窗、history、fsm 狀態若寫在 cwd，兩份會互寫。這直接撞到週五的 C-65（執行時的東西放 stack、定義不動）：新想法裡「定義資料夾＝cwd」，程式與執行狀態同一處。可能的選項：(a) 就這樣，狀態寫哪 agent-bob 自己管（例寫進 WS）；(b) 規定執行狀態一律寫 WS；(c) 保留 stack 當第三個東西，aos-exec 多一個參數。
9. **定義資料夾唯讀**（共用的 lib、git 管的、唯讀掛載）：狀態寫 cwd 就寫不進去。同第 8 條。
10. **Windows／symlink**：`chmod +x`、shell 入口、環境變數繼承都是 POSIX 的事；proto8 本來就 POSIX-only（C-08），不新增問題。symlink 反而不需要了（不掛 `.aos` 捷徑）；只剩「agent-bob 本身是捷徑時 cd 進去 cwd 是哪」——照 shell 慣例就好。可能的選項：維持 POSIX-only。
11. **workspace 不存在**：建還是報錯？可能的選項：報錯（不偷做事，C-56）；或 `mkdir -p`。

## 四、跟 proto8 對照（只列、不下結論）

**會被取代或改掉的：**

- **N-47／C-60 門房 `aos exec stack 定義`**（站進 stack、掛 `.aos` 捷徑、跑 `.aos/inst.json`）→ `aos-exec workspace 程式`（設 WS、cd 進程式資料夾、跑可執行入口）。參數順序一樣「哪裡做、做什麼」，但第一個參數的意思變了：proto8 第一個是 stack＝cwd；新想法 cwd＝程式資料夾、第一個參數變成環境變數。
- **N-48／C-59 `.aos` 捷徑、`.aos/x` 從 stack 算**：新想法不掛捷徑，入口就在程式資料夾自己的 `.aos/` 裡、從 cwd 算。週五「太優雅」的那套捷徑不需要了。
- **N-46／C-57 stdin 是正規入口、argv 是糖**：aos-exec 這層不再定 stdin。
- **N-49／C-58 agent 的 stdin 只放定義、話放 stack**：定義就是資料夾本身、不再從 stdin 進；「話放哪」原話沒說（邊緣 6）。
- **C-65～C-67 stack 與工作區分開、站在 stack**：新想法站在定義資料夾，沒有獨立的 stack；工作區（WS）保留。衝突最大的一條（邊緣 8）。
- **N-56 一般工具入口寫 `"cwd": {"$env": "AOS_WS"}`**：入口若是 shell 就是 `cd "$WS"`，意思同、寫法變。
- **inst.json 當入口（N-04、N-24～N-27 的 key）**：最外層入口不必是 inst.json；入口裡面的 aos-loop、fsm、tasks 內部仍可以用 inst。

**同方向的：**

- **N-55 工作區＝環境變數、自然往下傳**：WS 就是這個。
- **C-67 stack 放哪由呼叫方自由決定**、**C-52 只管自己這層**：「agent-bob 怎麼處理 cwd 是它自己的事」同一精神。
- **C-61／N-50 不用 PATH、地址＝資料夾**：入口寫在資料夾裡，同向。但入口內容 `aos-loop loop.json` 本身走 PATH 找 `aos-loop`——N-50 說體系內部不靠 PATH，小衝突。
- **N-51 shebang stub**：新想法的入口就是 stub 再往前一步——直接可執行、不轉手。
- **C-62／N-53 agent 被外面的 loop 驅動、定義不含 loop**：入口是 `aos-loop loop.json`，剛好是外面的 loop 包 agent，同向。
- **C-56 KISS**：這想法就是為了這條。
- **10-15「少用 sh」**（user.md）：入口是 shell 檔。不是 `sh -c` 串東西，但確實是 sh；要確認他覺得 OK。

**可能還是需要的：**

- 窗（N-06～N-19）、aos-loop／daemon 的規矩：是入口裡面的事，不受影響。
- N-43 結束碼、N-29 stderr 形狀：aos-exec 自己的錯（入口不存在、workspace 不存在）怎麼報。
- fsm、tasks 的格仍用 inst.json：只有最外層入口變。

## 五、拍板點（最先該答的排前面，一句話回答就好）

1. **cwd＝agent-bob/（定義資料夾）定了嗎？** 這跟週五 C-65「執行狀態放 stack、定義不動」相撞：兩個 workspace 同時跑同一個 agent-bob 會互寫。(a) 就這樣，狀態寫哪 agent-bob 自管；(b) 執行狀態一律寫進 WS；(c) 保留 stack 當第三個參數。
2. **`WS` 跟 `AOS_WS` 是同一個嗎？名字用哪個？**
3. **`AOS_ENTRY` 是 aos 固定的 `.aos/inst`，還是呼叫方可以換？**
4. **「這次要做什麼」從哪進去？** aos-exec 不管、stdin 與多餘 argv 原樣透傳給入口；或規定放 WS 裡某個檔。
5. **`aos-exec` 第一個參數省略時**：報錯，還是繼承現有的 WS（巢狀時會常用）？
6. **入口是 shell 檔，跟 10-15「少用 sh」怎麼相處？** OK 嗎？
