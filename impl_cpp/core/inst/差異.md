這份對照搬進來的 v1 執行器（impl_cpp/core/inst）跟現行 aos-inst（proto8，含 aos-exec 讀單子那層）在行為與介面上差在哪，給你決定要不要補。

**結論**：最大的差別有五個。① v1 是 C++ 一次跑一批、把輸出讀回記憶體；現行是 C 庫一次跑一條，輸出接到檔、/dev/null 或直通。② v1 起不來不算錯，子程式直接退 127／126；現行回錯誤代號，aos-exec 印一行 `error: LaunchFailed …` 退 1。③ 逾時 v1 直接對整群 SIGKILL（signal 9）；現行先 SIGTERM，過 grace 才 KILL（碼 143／137）。④ 單子 JSON v1 只認 6 個 key，`stdin` 是內容；現行 17 個 key，`stdin` 是路徑，另外還有 `$env`／`$ref`。⑤ v1 exec 前不還原訊號、不清 fd、`+x` 沒 `#!` 的腳本會退 127；這三件現行都有處理。

| 項目 | v1（impl_cpp/core/inst） | 現行 aos-inst（proto8） | 補的話動哪 |
|---|---|---|---|
| 介面形狀 | C++ struct `Spawn`→`Running`→`Result`；`start_all`／`wait_all` 一次一批 | C ABI 平結構＋`aos_inst_start`／`wait`／`exec`／`strerror`，一次一條 | `include/aos/exec.hpp`；要 C ABI 得另包一層 `extern "C"` |
| 回條 | `exit`、`signal`（二擇一）、`stdout_text`／`stderr_text`、`started_at`／`ended_at`（ISO 字串）、`pid`、`error` | `code`（被訊號停＝128＋N）、`signal`、`timed_out`、`pid`、`ms` | `Result`＋`wait_all.cpp` `decode_status` |
| 錯誤怎麼報 | 英文 `error` 字串（只有 fork／mkstemp／setpgid／waitpid 失敗才填） | 10 個代號（InputBad…KillFailed）；aos-exec 印一行 `aos-exec: error: LaunchFailed inst cannot run: 代號 原因`、退 1 | `start.cpp`、`Running/Result::error` 改成代號 |
| 找不到程式／沒權限 | 不算錯：子程式 `_exit(127)`／`_exit(126)`，呼叫端看到的是 exit 127／126（`spawn_prep.cpp` `resolve_executable`） | `CommandMissing`／`CommandBad`（子程式透過 CLOEXEC pipe 把 errno 回報給父） | `start.cpp` `run_child`＋父那側讀 pipe |
| `+x` 但沒 `#!` | 用 `execve`，ENOEXEC→退 127 | 用 `execvp`，glibc 改交給 sh 跑→印 hi、碼 0（驗收 A nosb） | `run_child` 改 `execvp` 或自己補 sh 退路 |
| 單子 JSON key | `id`(字串)、`argv`、`env`、`cwd`、`stdin`、`timeout_ms`；不認得的 key 不管 | 17 個：`envs`（不叫 `env`）、`stdout`／`stderr`、`*_append`、`*_mkdir`、`cwd_mkdir`、`stderr_merge`、`grace_ms`、`timeout_cycles`、`envs_clear`；`id` 型別不限 | `src/wire/inst.cpp` `parse_inst`、`wire.hpp` `Inst` |
| JSON 錯 | 回 nullopt＋`field 'x' must be …` | `EntryBad`（型別錯）、`DirectiveBad`（指示詞錯） | `parse_inst` |
| `timeout_ms` 型別 | 非負整數，0＝不限 | 正整數或 `null`；跟 `timeout_cycles` 只能擇一 | `parse_inst` |
| stdout／stderr | 一律 mkstemp 開暫存檔，跑完整份讀回記憶體再 unlink；大小沒上限 | 寫到給的路徑（截斷或附加），NULL＝/dev/null，`inherits` 直通呼叫者的 fd，`merge` 合流；不收進記憶體 | `start.cpp` `prepare_temp_files`、`wait_all.cpp` `collect_files` |
| stdin | 單子裡的字串先寫進暫存檔再接上；沒給＝空檔 | 填的是路徑，NULL＝/dev/null；aos-exec 預設直通 fd 0 | 同上 |
| 逾時 | 整群直接 `kill(-pid,SIGKILL)` → `signal 9` | 先 SIGTERM，等 `grace_ms` 再 SIGKILL（庫的預設 0，aos-exec 的預設 2000）；`timed_out` 會設真 | `wait_all.cpp` 逾時那段 |
| 行程群組 | 一律 `setpgid(0,0)` 自成一群（同一個 session，終端還在） | 預設跟呼叫者同群、只收直接子程式；`new_session` 才 `setsid` 整群收（aos-exec 一律開） | `run_child`、`start_all` |
| 訊號轉送 | `interrupt_running(sig)`：全域 256 格表、只呼叫 kill，可以在 handler 裡叫；表滿就默默不登記 | 庫完全不碰訊號；轉送歸 aos-exec（INT／TERM／HUP 轉給整群，過 grace 再 KILL） | `interrupt.cpp` |
| 子程式訊號狀態 | exec 前**沒**還原訊號處置、也沒清遮罩，呼叫者忽略的訊號會一路傳下去 | 還原成預設、遮罩清空 | `run_child` 加 sigaction／sigprocmask |
| fd 外漏 | 3 以上的 fd 沒標 CLOEXEC；0～2 被關掉時也沒先把 fd 搬開 | `close_range` 把 3 以上標 CLOEXEC；`inst_lift_fd` 把 fd 搬到 3 以上 | `run_child`、`tempfile.cpp` |
| 怎麼等 | `waitpid(WNOHANG)` 輪詢，間隔指數退避，最長 50 ms | pidfd＋poll；拿不到 pidfd 才退回每 1 ms 看一次 | `wait_all.cpp`、`wait.cpp` |
| 殭屍 | `Running` 沒 wait 就丟→留殭屍＋暫存檔 | 同一條規則：start 成功就一定要 wait 一次 | 沒差 |
| 環境變數 | 疊在呼叫者的環境上（只加不減）；key 空或含 `=`→退 126 | 庫：`envs` 給的就是**完整**環境；aos-exec：`envs` 疊上去，`envs_clear` 全部清掉 | `spawn_prep.cpp` `merge_environment` |
| 單個 unset | 不行 | 也不行（只有 `envs_clear` 全清） | 沒差 |
| cwd | 可以給相對路徑（算呼叫者的 cwd）；不存在→子程式退 126，不算錯 | 庫只收絕對路徑，先檢查→`CwdMissing`；aos-exec 從入口所在資料夾轉成絕對；可以 `cwd_mkdir` | `spawn_prep.cpp` `child_directory`、`start.cpp` |
| 找程式 | 父行程 fork 前先照 PATH（沒設就用 confstr 預設）stat＋access 找好 | 交給子行程的 `execvp` 找，PATH 看子程式那份環境 | `resolve_executable` |
| `$env`／`$ref` | 沒有 | 有（aos-exec＋aos-directive，可帶 `$path`／`$prefix`） | 新寫一層，在 `parse_inst` 前面解 |
| fork 後安全界線 | 守住了：子行程只做 setpgid／dup2／close／chdir／execve／_exit，argv、envp 都在 fork 前備好 | 守住了，外加 sigaction／sigprocmask／fcntl／write | 大致沒差 |
| 執行緒 | 有全域 pid 表（atomic）；同時跑幾個 `wait_all` 沒驗過→待查 | 沒有全域狀態，可多條執行緒同時呼叫；也可以 start 跟 wait 分在不同執行緒 | `interrupt.cpp` |
| 序列化 | `to_json_text(Inst)` | 沒看到對應的→待查 | — |
| 退 10 | 不適用（那是 loop／fsm 的慣例，跟 inst 無關） | 不適用 | — |

<details><summary>驗收卡（aos-大修材料/50-驗收/aos-inst.md）逐條拿 v1 來看</summary>

- A code3 → 3：v1 的 exit 也是 3，沒差。
- A slow → 143：v1 拿到的是 signal 9，對不上。
- A missing → `LaunchFailed … CommandMissing`、退 1：v1 是 exit 127、`error` 空。
- A cwd → `CwdMissing`：v1 是 exit 126。
- A nosb → 印 hi、0：v1 是 127，而且 hi 只會出現在 `stdout_text` 裡，不會直接印出來。
- A sig → 143：v1 是 signal 15（要換成碼得自己算 128＋N）。
- 小測試裡的 PathConflict／PathNotAbsolute／OpenFailed／`new_session` 有沒有開兩種情況：v1 沒有這些欄位。
- 小測試「在別條執行緒 wait」：v1 的 `wait_all` 收的是整批，別條執行緒能不能叫→待查。
- C 同一個檔互蓋、C 接 FIFO：v1 沒有輸出路徑可給，不適用。
- C 孫程式背景跑：v1 正常結束時也不收孫程式（只有逾時才整群 KILL），跟現行一樣。
- B「grep 不到 `signal(`」：v1 本來就沒裝 handler，但 `interrupt_running` 是給呼叫者在 handler 裡叫的。

</details>
